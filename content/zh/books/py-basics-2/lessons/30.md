# 实战：把一坨代码重构成一组函数

> 这是第 6 章的收尾课。前面五课学的函数技巧，这一课全部用上：**把之前写过的通讯录小工具，从"一坨代码"重构成"一组各司其职的函数"**。
>
> 重点不是"代码变短了"，而是**每一块代码都有自己的名字和职责**。

## 一、重构前的"一坨代码"

假设这是一个极简通讯录，用列表存字典：

```python
# 一坨代码版本
book = []

print("添加张三")
book.append({"name": "张三", "phone": "13800138000"})
print("添加李四")
book.append({"name": "李四", "phone": "13900139000"})

print("查找张三")
found = None
for c in book:
    if c["name"] == "张三":
        found = c
        break
if found:
    print(found["phone"])
else:
    print("没找到")

print("所有联系人")
for c in book:
    print(c["name"], c["phone"])
```

能跑，但**问题一大堆**：逻辑全混在一起、想加功能得改中间、找人那套逻辑没法复用、读起来像流水账。

## 二、重构第一步：切分出"动作"

通讯录本质上是四种操作：**加、查、列、删**。每种操作包成一个函数：

```python
def add_contact(book, name, phone):
    book.append({"name": name, "phone": phone})

def find_contact(book, name):
    for c in book:
        if c["name"] == name:
            return c
    return None

def list_contacts(book):
    for c in book:
        print(c["name"], c["phone"])

def remove_contact(book, name):
    for i, c in enumerate(book):
        if c["name"] == name:
            book.pop(i)
            return True
    return False
```

每个函数**只做一件事**：`add_contact` 只管加、`find_contact` 只管找、`list_contacts` 只管列、`remove_contact` 只管删。这就是**单一职责原则**。

⚠️ **翻车：一个函数身兼数职。**

```python
def manage(book, name, phone, action):      # ❌ 一个函数干四件事
    if action == "add":
        book.append(...)
    elif action == "find":
        ...
    elif action == "list":
        ...
    elif action == "remove":
        ...
```

用 `action` 字符串分流的"万能函数"，本质上是把四个函数塞进一个函数里。**改其中一个逻辑，就要在这个大函数里翻找、还要担心改坏别的**。拆开才是正道。

## 三、重构后的主流程

主流程变得**像读说明一样清楚**：

```python
def main():
    book = []

    add_contact(book, "张三", "13800138000")
    add_contact(book, "李四", "13900139000")

    print("查找张三:")
    result = find_contact(book, "张三")
    if result:
        print(result["phone"])
    else:
        print("没找到")

    print("所有联系人:")
    list_contacts(book)

    remove_contact(book, "张三")
    print("删除后:")
    list_contacts(book)

main()
```

主函数 `main()` 里**看不到任何实现细节**，只能看到"做了什么"。这才是重构的核心价值。

## 四、完整代码

```python
def add_contact(book, name, phone):
    """添加联系人"""
    book.append({"name": name, "phone": phone})

def find_contact(book, name):
    """查找联系人，找到返回字典，找不到返回 None"""
    for c in book:
        if c["name"] == name:
            return c
    return None

def list_contacts(book):
    """列出所有联系人"""
    for c in book:
        print(f"{c['name']}: {c['phone']}")

def remove_contact(book, name):
    """删除联系人，成功返回 True，没找到返回 False"""
    for i, c in enumerate(book):
        if c["name"] == name:
            book.pop(i)
            return True
    return False

def main():
    book = []
    add_contact(book, "张三", "13800138000")
    add_contact(book, "李四", "13900139000")

    print("查找张三:")
    result = find_contact(book, "张三")
    print(result["phone"] if result else "没找到")

    print("\n所有联系人:")
    list_contacts(book)

    print("\n删除张三后:")
    remove_contact(book, "张三")
    list_contacts(book)

main()
```

输出：

```
查找张三:
13800138000

所有联系人:
张三: 13800138000
李四: 13900139000

删除张三后:
李四: 13900139000
```

⚠️ **翻车：函数之间靠全局变量 `book` 传状态。**

```python
book = []           # 全局

def add_contact(name, phone):       # ❌ 依赖全局 book
    book.append({"name": name, "phone": phone})
```

这能跑，但 `add_contact` 的正确性**依赖外部有个叫 `book` 的变量**。测试时、多个通讯录并存时就崩了。**把 book 作为参数传进去，函数才能独立、可复用**。

## 五、怎么切分：三条经验

**1. 找"动词"。** "添加联系人""查找联系人""删除联系人"——句子里的动词，往往就是一个函数。通讯录 = add / find / list / remove，成绩管理 = add_score / average / top_student / fail_list。

**2. 每个函数只做一件事。** 判断标准是：**你能不能给它起一个准确的动词名字**。起不出来，说明它干了不止一件事，该拆。

**3. 数据当参数传，结果用 return 交回。** 别用全局变量当传声筒。

⚠️ **翻车：函数名起得含糊，说明职责不清。**

```python
def process_data(book, name):       # "process" 啥也没说
    ...

def handle_user(x):                 # "handle" 太空泛
    ...
```

这种名字出现时，通常意味着函数里塞了太多东西。**能说清"做什么"，才是好名字**。

## 六、重构的收益：测试

重构后，每个函数都能**单独测试**：

```python
# 测试 find_contact
book = [{"name": "张三", "phone": "138"}]
assert find_contact(book, "张三")["phone"] == "138"
assert find_contact(book, "李四") is None

# 测试 remove_contact
book = [{"name": "张三"}]
assert remove_contact(book, "张三") is True
assert remove_contact(book, "李四") is False
```

**一坨代码做不到这点**——你没法只测"查找"那一段，因为那段代码和环境死死绑在一起。函数化之后，**输入输出清晰，测试自然就写得出**。

⚠️ **翻车：重构时改了行为却没察觉。**

```python
# 原来：找不到返回 "没找到"
# 重构后：找不到返回 None
```

行为变了，但代码能跑。这就是测试的意义——**重构只改结构、不改行为**，测试能帮你守住这条底线。

## 七、把函数"当对象"用：菜单分发

上一章学的"函数字典"，在这里正好派上用场：

```python
MENU = {
    "1": ("添加", add_contact),
    "2": ("查找", find_contact),
    "3": ("列出", list_contacts),
    "4": ("删除", remove_contact),
}

def show_menu():
    for key, (label, _) in MENU.items():
        print(f"{key}. {label}")

show_menu()
```

把"操作名"和"对应函数"绑在一起，**加新功能只要在 MENU 里加一行**，主循环完全不用动。这就是"开闭原则"——对扩展开放、对修改关闭。

## 小结

- 重构的目标不是"变短"，而是**每块代码各司其职、见名知义**
- 切分方法：找动词、每个函数只做一件事、数据当参数传、结果 return 交回
- 一个函数干四件事的"万能函数"，是反模式
- 别用全局变量传状态，让函数能独立、可测试
- 重构只改结构、不改行为，测试守住底线
- 函数字典做菜单分发，是函数作为对象的最实用落地
