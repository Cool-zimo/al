# 字符串是不可变的

> 第 3 课学过"按位置改元素"：`nums[0] = 99`。你可能会想，字符串也是一串字符，能不能 `s[0] = 'X'`？
>
> 这一课讲字符串的**不可变**特性，以及由此带来的一系列常用方法。

## 一、"改"字符串，其实是新建

先试一下直接改：

```python
s = "hello"
s[0] = "H"          # ✗ TypeError: 'str' object does not support item assignment
```

报错说得很清楚 —— 字符串**不支持按位置赋值**。

那为什么下面这行看起来"改成功了"？

```python
s = "hello"
s = "H" + s[1:]
print(s)            # Hello
```

因为这里**没有改原来的 "hello"**。发生的事情是：

1. 算出 `"H" + s[1:]`，得到新字符串 `"Hello"`
2. 让变量 `s` 指向这个新字符串
3. 旧的 `"hello"` 没人用了，被 Python 回收

**字符串一旦创建就不可变。** 变量能重新指向别处，但字符串对象本身动不了。

这个性质和元组一样，和列表相反：

| 类型 | 能按位置改吗 | 举例 |
|---|---|---|
| 列表 `list` | 能 | `nums[0] = 99` |
| 元组 `tuple` | 不能 | `t[0] = 1` → 报错 |
| 字符串 `str` | 不能 | `s[0] = 'H'` → 报错 |

⚠️ **翻车：想当然地以为 `replace` 会改原字符串。**

```python
msg = "我喜欢吃苹果"
msg.replace("苹果", "香蕉")
print(msg)          # 我喜欢吃苹果 —— 原字符串没变！
```

`replace` **返回一个新的字符串**，不会动原来的。你得把结果接住：

```python
msg = "我喜欢吃苹果"
msg = msg.replace("苹果", "香蕉")
print(msg)          # 我喜欢吃香蕉
```

这个"方法返回新对象、不改原对象"的特点，字符串的几乎所有方法都遵循。写的时候记住：**字符串的方法调用永远是"算出一个新字符串"，原串不变。**

## 二、最常用的一组方法

| 方法 | 干什么 | 示例 |
|---|---|---|
| `split(分隔符)` | 按分隔符切成列表 | `"a,b,c".split(",")` → `['a','b','c']` |
| `"分隔符".join(列表)` | 把列表粘成一个字符串 | `",".join(['a','b'])` → `"a,b"` |
| `strip()` | 去掉两端空白 | `"  hi  ".strip()` → `"hi"` |
| `replace(a, b)` | 把 a 全换成 b | `"aa".replace("a","b")` → `"bb"` |
| `find(x)` | 找 x 的位置，找不到返回 -1 | `"abc".find("b")` → `1` |
| `startswith(x)` | 是否以 x 开头 | `"2026-09-29".startswith("2026")` → `True` |

### split：把一串拆开

```python
line = "张三,13800138000,北京"
parts = line.split(",")
print(parts)        # ['张三', '13800138000', '北京']
print(parts[0])     # 张三
```

`split` 返回一个**列表**。不传参数时按"任意空白"切：

```python
s = "a  b\tc\nd"
print(s.split())    # ['a', 'b', 'c', 'd']
```

⚠️ **翻车：`split` 找不到分隔符会怎样？**

```python
s = "helloworld"
print(s.split(","))      # ['helloworld'] —— 不报错，返回只有一整个元素的列表
```

切不动就整段原样返回，包在列表里。这个特性经常用来"试探性解析" —— 但别指望它告诉你"没切动"。

### strip：清空白

```python
name = "   张三   "
print(name.strip())      # "张三"
```

`strip()` 不带参数清两端**所有空白**（空格、换行、制表符）。还可以指定清哪些字符：

```python
s = "###重要通知###"
print(s.strip("#"))      # 重要通知
```

⚠️ **翻车：`strip` 不是"去掉开头结尾的那一串"，而是"去掉其中任意字符"。**

```python
s = "abcFOOcab"
print(s.strip("abc"))    # FOO
```

它从两端反复剥掉**属于给定集合的任意字符**，直到碰到不属于集合的为止。所以结果不一定是"去掉了某个固定前缀"。

### find 和 startswith：找东西

```python
url = "https://example.com"
print(url.startswith("https"))     # True
print(url.find("example"))        # 8
print(url.find("github"))         # -1 —— 找不到返回 -1
```

`find` 找不到时返回 `-1`，而不是报错，也不返回 `None`。这点和列表的 `index` 方法不同：

```python
"abc".index("z")        # ✗ ValueError: substring not found
```

**需要判断"有没有"时用 `in` 或 `find`，需要知道位置时用 `find`，确定一定有时用 `index`。**

## 三、join：把列表粘回去

`join` 是 `split` 的反向操作：

```python
parts = ["张三", "13800138000", "北京"]
line = ",".join(parts)
print(line)             # 张三,13800138000,北京
```

注意写法有点"反直觉"：**是分隔符在调用 `join`，列表作为参数传进去。**

```python
",".join(parts)      # 正确
parts.join(",")      # ✗ AttributeError: 'list' object has no attribute 'join'
```

为什么这么设计？因为"用什么粘"是字符串的活，列表只负责提供元素。念一遍就顺了："逗号，把 parts 粘起来"。

## 四、join 比 += 好在哪

假设要把一堆词拼成一个句子：

```python
words = ["我", "爱", "写", "Python"]
```

**用 += 的写法：**

```python
s = ""
for w in words:
    s += w
print(s)          # 我爱写Python
```

**用 join 的写法：**

```python
s = "".join(words)
print(s)          # 我爱写Python
```

结果一样，但 `join` 明显更短。更重要的是**效率上的差别**：

字符串是不可变的，所以 `s += w` 的每一步都在**新建一个字符串**，把之前的内容复制一遍再接上新的。词越多，重复复制的量越大 —— 1000 个词时，复制的总量大约是原来的一千倍。

而 `join` 知道总共有多少个词，**一次性**分配好足够的内存，一趟就拼完。

⚠️ **翻车：用 += 拼了很多次才发现问题。**

这不是会报错的错误，而是一个**性能隐患**。循环里用 `+=` 拼字符串，在数据量大时会明显变慢；循环里用 `join`（或先把片段装进列表，最后 `join`）则稳定。

一个实用的判断：循环里要拼字符串，**先装进列表，循环结束 `join`**。

```python
lines = []
for name in ["张三", "李四", "王五"]:
    lines.append(f"你好，{name}")
text = "\n".join(lines)
print(text)
```

## 小结

- 字符串不可变，不能 `s[0]='X'`；看起来"改了"其实是变量指向了新字符串
- 字符串的方法都**返回新字符串**，不会改原串 —— `s = s.replace(...)` 才是正确用法
- `split` 切出列表，`join` 粘回字符串；`join` 由分隔符调用
- `strip` 剥掉的是"字符集合"不是"固定前缀"；`find` 找不到返回 -1
- 循环里拼字符串用列表 + `join`，别用 `+=`
