# 字典的坑：键必须可哈希、顺序别依赖

> 字典用起来很顺手，但它有三个"坑"是几乎每个人都会踩的。这一课把这三个坑一次性讲透，让你以后少掉头发。

## 坑一：键必须是"可哈希的"

先说结论：**字典的键必须是不可变对象**。字符串、数字、元组可以当键；列表、字典不行。

```python
d = {}
d["北京"] = "首都"          # 字符串当键，可以
d[42] = "生命答案"          # 数字当键，可以
d[(116, 39)] = "坐标"       # 元组当键，可以
```

```python
d[["北京", "上海"]] = "城市对"      # ✗ TypeError: unhashable type: 'list'
```

报错信息里的关键词是 **unhashable（不可哈希）**。它其实就是说："这个东西会变，我不能拿它当索引。"

### 为什么"会变"的东西不能当键

字典能按键快速查值，靠的是**哈希表**：Python 给每个键算一个"哈希值"，用来决定这个值存在哪。如果键能变，它的哈希值就会变，那它存进去时算一次、找的时候算一次，两次不一样，就找不到了。

所以 Python 干脆**不让可变对象当键** —— 从语法层面杜绝这个隐患。

⚠️ **翻车：以为"元组就一定能当键"。**

元组本身不可变，但如果它里面装了可变对象，照样不行：

```python
d = {([1, 2], 3): "value"}        # ✗ TypeError: unhashable type: 'list'
```

因为元组的第一个元素是个列表。判断标准是**键对象本身以及它包含的一切都不可变**。

### 一个实用的判断

> 对象能不能放进集合 `set()`，它就能不能当字典的键 —— 两者用的是同一套规则。

```python
{ [1, 2] }          # ✗ 报错，列表不可哈希
{ (1, 2) }          # ✓ 元组可以
```

### 常见可哈希 vs 不可哈希

| 可哈希（能当键） | 不可哈希（不能当键） |
|---|---|
| 字符串 `str` | 列表 `list` |
| 整数、浮点数 | 字典 `dict` |
| 元组 `tuple`（元素也可哈希） | 集合 `set` |
| `True` / `False` / `None` | 字节数组 `bytearray` |

⚠️ **翻车：把字典当键。**

```python
d = {{"a": 1}: "value"}      # ✗ TypeError: unhashable type: 'dict'
```

字典自己也不能当键 —— 因为字典是可变的。

## 坑二：不存在的键会 KeyError

第 12 课讲过 `get`，但日常代码里还是经常看到中括号取值：

```python
scores = {"张三": 92}
print(scores["李四"])        # ✗ KeyError: '李四'
```

**KeyError 是字典最常见的运行时错误之一。** 遇到它只有三条路：

1. **确定一定存在**：直接用中括号，崩了说明数据有问题，让它崩
2. **可能不存在、给个备胎**：用 `get(键, 默认值)`
3. **先检查再取**：`if 键 in 字典:`

```python
# 用 get 是最省心的
age = info.get("age", 0)
```

⚠️ **翻车：用 `get` 之后忘记处理"没取到"的情况。**

```python
value = d.get("key")
print(value.upper())         # ✗ AttributeError: 'NoneType' object has no attribute 'upper'
```

如果键不存在、`get` 又没给默认值，返回的就是 `None`。拿 `None` 当字符串用就崩。所以要么给默认值，要么取值后先判空。

## 坑三：字典"有序"，但别依赖顺序

Python 3.7 起，字典**会保留插入顺序**：

```python
d = {}
d["北京"] = 1
d["上海"] = 2
d["广州"] = 3
print(list(d.keys()))        # ['北京', '上海', '广州']
```

看起来是"有序的"。但请注意：**这是实现细节提升成的保证，逻辑上你不该指望它排序。**

什么意思？意思是：字典的顺序是"你插入的先后"，**不是按大小排、不是按字母排**。

⚠️ **翻车：以为字典会自动排序。**

```python
d = {"banana": 3, "apple": 1, "cherry": 2}
print(list(d.keys()))        # ['banana', 'apple', 'cherry'] —— 按插入顺序，不是字母序
```

它**不会**按字母排序。想排序就得显式 `sorted`：

```python
for k in sorted(d):
    print(k, d[k])
```

```
apple 1
banana 3
cherry 2
```

⚠️ **翻车：把"顺序一致"当成"字典相等"。**

```python
a = {"x": 1, "y": 2}
b = {"y": 2, "x": 1}
print(a == b)           # True
```

字典的相等比较**只看键值对是否相同**，不看顺序。所以"顺序"虽然被保留，却不影响逻辑上的相等判断 —— 别把顺序当成字典的核心特性。

## 小结

- 字典的键必须可哈希：字符串、数字、元组可以；列表、字典、集合不行
- 元组当键的前提是它里面**所有元素**也都可哈希
- 不存在的键会 KeyError；用 `get` 或先 `in` 判断来避免
- 字典保留插入顺序，但**不会自动排序**；要排序显式用 `sorted`
- 字典的相等比较不关心顺序，只关心键值对是否一致
