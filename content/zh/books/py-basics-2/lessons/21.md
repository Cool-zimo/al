# 为什么要有函数：别再复制粘贴了

> 前四章写代码都是"从头写到尾一条龙"。代码一多，你很快会遇到三种痛苦：**重复**、**难改**、**看不懂**。
>
> 这一章讲**函数（function）** —— 它是把"一段会重复用到的代码"打包、起个名字、随时喊它来干活的工具。学会函数，才算真正入门"写程序"。

## 一、一个真实的问题：复制粘贴的代价

假设你在写一个"班级成绩小工具"，要判断每个同学的成绩等级：

```python
score1 = 92
if score1 >= 90:
    print("优秀")
elif score1 >= 60:
    print("及格")
else:
    print("不及格")

score2 = 55
if score2 >= 90:
    print("优秀")
elif score2 >= 60:
    print("及格")
else:
    print("不及格")

score3 = 78
if score3 >= 90:
    print("优秀")
elif score3 >= 60:
    print("及格")
else:
    print("不及格")
```

三份几乎一样的代码。如果需求变了 —— 比如要改成"优秀 / 良好 / 及格 / 不及格"四级 —— 你就得**改三处**，改到第三处时手一抖改错了，bug 就来了。

这就是复制粘贴最大的代价：**逻辑只写在一个地方最好，写三份就埋了三颗雷**。

## 二、给一段代码"起个名字"

函数的想法朴素到有点土：**把这段逻辑包起来，起个名字，以后喊名字就行**。

```python
def judge(score):
    if score >= 90:
        print("优秀")
    elif score >= 60:
        print("及格")
    else:
        print("不及格")

judge(92)        # 优秀
judge(55)        # 不及格
judge(78)        # 及格
```

三份重复的代码，现在只有**一份**。`def` 是"定义"，`judge` 是这段代码的名字，`score` 是"喂给它的东西"。喊一声 `judge(92)`，它就去执行那段逻辑。

⚠️ **翻车：想用函数但忘了定义，直接喊名字。**

```python
greet("张三")          # ✗ NameError: name 'greet' is not defined

def greet(name):
    print("你好", name)
```

Python 是按顺序执行的。`greet("张三")` 写在定义**前面**，解释器还没见过 `greet` 这个名，就报 `NameError`。**先定义、再调用**，顺序不能反。

## 三、函数把"做"和"用"分开

不写函数时，代码是"边做边用"；写了函数，变成"**先定义好做什么，再在需要的地方喊它**"。

```python
# 先定义：这段逻辑是干嘛的
def calc_tax(price):
    return price * 0.13

# 再使用：在需要的地方喊它
total = 100 + calc_tax(100)
print("应付:", total)        # 应付: 113.0
```

好处是：**看调用的人只关心"它算了个税"**，不用看那行公式怎么写。这就是"封装"——把细节藏起来，只暴露一个名字。

⚠️ **翻车：把"定义"和"使用"混在一个文件里，分不清哪段是给谁用的。**

```python
print("开始")
def f1():
    print("A")
def f2():
    print("B")
f1()
f2()
print("结束")
```

这段代码能跑，但全是定义和调用交错。**约定俗成的写法是：把 `def` 都集中在文件上半部分，调用集中在下半部分**，或者更进一步——主逻辑包进一个 `main()`。这不算语法要求，但能救命。

## 四、复制粘贴 vs 函数：一个真实对照

看同一个需求："给购物车里每个商品算打折价"。

**复制粘贴版：**

```python
p1 = 100
if p1 >= 200:
    p1 *= 0.8
else:
    p1 *= 0.9
print(p1)

p2 = 300
if p2 >= 200:
    p2 *= 0.8
else:
    p2 *= 0.9
print(p2)
```

**函数版：**

```python
def discount(price):
    if price >= 200:
        return price * 0.8
    return price * 0.9

print(discount(100))        # 90.0
print(discount(300))        # 240.0
```

以后老板说"满 300 打 7 折"，**复制粘贴版要改两处（还容易改漏），函数版只改 `discount` 里一处**。这就是函数的全部意义——**一处定义，到处使用**。

⚠️ **翻车：把打折规则写了三遍，改的时候只改了两遍。**

```python
p1 = 100
if p1 >= 200:
    p1 *= 0.8
else:
    p1 *= 0.9

p2 = 300
if p2 >= 200:
    p2 *= 0.8
else:
    p2 *= 0.9       # 这里改成了 0.7

p3 = 500
if p3 >= 200:
    p3 *= 0.8       # 这里忘了改！
else:
    p3 *= 0.9
```

三份代码总有一份会被你漏掉。这不是"粗心"能解释的——**是人就会漏，所以要让重复根本不存在**。

## 五、函数不只省事，还让代码"读得懂"

好的函数名本身就在说话：

```python
def is_vip(user):
    return user.get("level", 0) >= 3

if is_vip(zhangsan):
    print("送优惠券")
```

对比不写函数：

```python
if zhangsan.get("level", 0) >= 3:
    print("送优惠券")
```

两行差不多，但 `is_vip(zhangsan)` 读起来像人话：**"张三是不是 VIP"**。半年后你回来改代码，第一个版本一眼就懂，第二个版本还得再想一遍那行逻辑在判断什么。

**函数名的价值**：让代码读起来像一段说明，而不是一堆操作。

## 小结

- 复制粘贴三份相同逻辑 = 埋三颗雷，改一处要改十处
- 函数用 `def 名字(参数):` 定义，之后用 `名字(参数)` 调用
- **必须先定义、再调用**，顺序反了就 `NameError`
- 函数把"做什么"和"在哪用"分开，逻辑只写一份
- 好函数名本身就是注释，让代码读起来像人话

```quiz
type: code
q: 把下面这段重复三次的"判断成绩等级"代码，改写成一个函数 `grade(score)`：90 及以上返回 "优秀"，60 及以上返回 "及格"，否则返回 "不及格"。然后用它分别判断 92、55、78 并打印结果
starter: |
  def grade(score):
      # 在这里写判断逻辑，并返回字符串

  print(grade(92))
  print(grade(55))
  print(grade(78))
tests:
- assert "优秀" in __out
- assert "不及格" in __out
- assert "及格" in __out
hint: 用 if/elif/else 三分支，每层返回一个字符串。注意返回的是字符串，不是 print。
explain: 答案：def grade(score):\n    if score >= 90: return "优秀"\n    elif score >= 60: return "及格"\n    else: return "不及格"。这是把"重复逻辑包成函数"的第一步 —— 三处判断变成一次定义、三次调用。
```
