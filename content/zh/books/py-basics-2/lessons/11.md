# 为什么要有字典：用"名字"取，不用"位置"取

> 前面学的列表、元组，取值都得靠**位置**：`scores[0]` 是第 1 个，`scores[1]` 是第 2 个。
>
> 但现实里更多情况是：**你知道名字，想知道对应的值** —— 张三的成绩、北京的区号、这个商品的单价。靠位置取，就得一个个翻。
>
> 这一课讲**字典（dict）**：它用"名字"取东西，速度快、读起来也清楚。

## 一、一个真实的问题

假设要存几个人的成绩，用列表：

```python
scores = [92, 78, 100, 65]
```

请问"张三的成绩是多少"？你**不知道**。因为列表只记得"第几个"，不记得"谁是谁"。要找张三，得再维护一个平行的名单：

```python
names = ["张三", "李四", "王五", "赵六"]
scores = [92, 78, 100, 65]

# 找张三的成绩
i = names.index("张三")
print(scores[i])        # 92
```

麻烦，而且两份数据必须**严丝合缝地对齐**，错一个就全乱了。

**字典把"名字"和"成绩"绑在一起存：**

```python
scores = {
    "张三": 92,
    "李四": 78,
    "王五": 100,
    "赵六": 65,
}

print(scores["张三"])        # 92
```

`"张三"` 是**键（key）**，`92` 是它对应的**值（value）**。键值成对出现，中间用冒号 `:` 隔开。整个字典用花括号 `{ }` 包起来。

要找张三的成绩，直接 `scores["张三"]`，**不用知道他在第几个**。

## 二、字典的字面量与 `dict()`

最常见的写法是**字面量**，也就是直接把键值对写出来：

```python
phone = {
    "张三": "13800138000",
    "李四": "13900139000",
}
print(phone["张三"])        # 13800138000
```

也可以先用空字典，再往里加（第 12 课细讲）：

```python
phone = {}
phone["张三"] = "13800138000"
```

用 `dict()` 构造函数也能创建，参数用"键=值"的形式（键必须是合法标识符、不能是中文）：

```python
d = dict(a=1, b=2)
print(d)        # {'a': 1, 'b': 2}
```

⚠️ **翻车：键用中文时不能用 `dict(键=值)` 的写法。**

```python
d = dict(张三=92)        # ✗ SyntaxError: keyword can't be an expression
```

`dict(键=值)` 的键部分要求像变量名一样合法，中文不行。要用中文键，就老老实实写字面量 `{"张三": 92}`。

## 三、现实中的对应关系

字典就是一张**映射表**：给定一个键，得到对应的值。生活里到处都是这种关系：

| 场景 | 键 | 值 |
|---|---|---|
| 通讯录 | 姓名 | 电话号码 |
| 商品价格表 | 商品名 | 单价 |
| 城市区号 | 城市名 | 区号 |
| 配置项 | 配置名 | 配置值 |
| 统计词频 | 单词 | 出现次数 |

```python
prices = {
    "苹果": 5.5,
    "牛奶": 8.0,
    "面包": 3.5,
}
print(prices["苹果"])        # 5.5
```

读起来非常自然：`prices["苹果"]` 就是"苹果的单价"。

## 四、键和值可以是各种类型

字典的值可以是任何东西 —— 数字、字符串、列表、甚至另一个字典：

```python
student = {
    "姓名": "张三",
    "年龄": 20,
    "成绩": [92, 78, 100],
    "地址": {
        "城市": "北京",
        "区": "海淀",
    },
}

print(student["成绩"][0])            # 92
print(student["地址"]["城市"])       # 北京
```

**键**的要求更严：必须是**不可变的**（字符串、数字、元组都可以；列表不行）。为什么后面第 14 课会讲透。

常见的是用**字符串当键**：

```python
config = {
    "host": "localhost",
    "port": 3306,
    "debug": True,
}
```

⚠️ **翻车：把键写成了列表。**

```python
d = {["北京", "上海"]: "城市"}      # ✗ TypeError: unhashable type: 'list'
```

列表不能当键。想用"多个东西"当键，得用元组：

```python
d = {("北京", "上海"): "城市对"}
print(d[("北京", "上海")])      # 城市对
```

## 五、字典 vs 列表：什么时候该用谁

给一个简单判断：

| 你想做的事 | 用哪个 | 例子 |
|---|---|---|
| "按名字查信息" | 字典 | 张三的成绩、商品价格 |
| "按顺序存一批东西" | 列表 | 所有成绩、购物车商品 |
| "键值都要、还能改" | 字典 | 用户信息表 |
| "只存值、按位置取" | 列表 | 一串分数 |

```python
# 用列表：只是"一批成绩"，顺序有意义
scores = [92, 78, 100]

# 用字典：成绩要和人对上号
scores_by_name = {"张三": 92, "李四": 78, "王五": 100}
```

**一句话**：如果取值时你的第一反应是"那个叫什么什么的"，就用字典；如果第一反应是"第几个"，就用列表。

⚠️ **翻车：该用字典却用了列表，靠 index 去对齐。**

```python
names = ["张三", "李四", "王五"]
scores = [92, 78, 100]
# 想改张三的成绩
i = names.index("张三")
scores[i] = 95           # 能用，但脆弱
```

只要哪天插入或删除时两边没对齐，数据就错了。这种"两份平行列表"的写法，是字典最该出场的地方 —— 换成字典，名字和成绩就天然绑在一起，不用担心对齐。

## 小结

- 字典用 `{键: 值}` 存储，**按键取**而不是按位置取
- 字典存的是"映射关系"：姓名→电话、商品→价格、城市→区号
- 值可以是任意类型，包括列表和字典；键必须是不可变的（字符串最常用）
- 该用字典的信号：你总在想"那个叫某某的"
- 列表当键会报错；用元组可以
