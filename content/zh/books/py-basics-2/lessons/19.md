# 四种容器怎么选：list、tuple、dict、set

> 学完了四种内置容器，最实际的问题是：**拿到一个需求，该用哪个？**
>
> 这一课给一份"决策表"，把四种容器的脾气对比清楚，再配上真实场景的选型判断。

## 一、四种容器一览

| 类型 | 字面量 | 有序？ | 可改？ | 元素能否重复 | 取值方式 | 典型用途 |
|---|---|---|---|---|---|---|
| `list` 列表 | `[1, 2, 3]` | 有顺序 | 能改 | 能 | 下标 `[i]` | 一批同类数据 |
| `tuple` 元组 | `(1, 2, 3)` | 有顺序 | 不能改 | 能 | 下标 `[i]` | 固定字段、当键 |
| `dict` 字典 | `{"a": 1}` | 保插入序 | 能改 | 键不重 | 键 `d[k]` | 键值映射 |
| `set` 集合 | `{1, 2, 3}` | 无顺序 | 能增删 | 不能 | 只能 `in` | 去重、判断存在 |

逐行对比：

- **有序 vs 无序**：列表、元组、字典都"有顺序感"；集合完全无序，不能按下标取
- **可变 vs 不可变**：列表、字典、集合都能改；元组不能改
- **能否重复**：列表、元组、字典（键）允许重复值；集合的元素天生唯一
- **取值方式**：列表元组靠位置，字典靠键，集合靠"在不在"

⚠️ **翻车：以为字典和集合都"没有顺序"。**

Python 3.7+ 的字典是**保留插入顺序**的。只有集合是无序的。两者别混为一谈。

## 二、决策表：按需求选

问自己四个问题，按顺序判断：

### 问题 1：我存的是"键值对"吗？

如果是 —— **用字典**。比如"姓名→电话""商品→价格""配置名→配置值"。

```python
phone = {"张三": "13800138000", "李四": "13900139000"}
```

如果不是键值对，继续往下问。

### 问题 2：需要频繁判断"在不在"或去重吗？

如果是 —— **用集合**。比如黑名单、独立访客、找共同好友。

```python
vip = {"张三", "李四", "王五"}
```

否则继续。

### 问题 3：这一组数据**不该被改**吗？（字段固定、要当键）

如果是 —— **用元组**。比如坐标 `(x, y)`、数据库一条记录、函数返回多个值。

```python
point = (116.46, 39.92)
```

否则就用列表。

### 问题 4：就是一批东西，要增删、要排序

—— **用列表**。这是默认选择，最灵活。

```python
scores = [87, 92, 78, 65, 100]
```

⚠️ **翻车：一上来就用列表，没想过别的。**

列表最灵活，但也"最没特色"。当你发现自己在列表上频繁做 `in` 判断、或者一直在维护"两份平行列表"，就该想想字典或集合了。

## 三、真实场景选型

### 场景 1：购物车

需求：能加商品、能删、能算总价，允许同一个商品多次出现（买 3 个苹果）。

→ **列表**。允许重复、需要增删、顺序有意义。

```python
cart = ["苹果", "牛奶", "苹果", "面包"]
cart.append("苹果")        # 又加一个苹果
```

如果需求变成"统计每种商品买了几个"，就用**字典**：

```python
cart_count = {"苹果": 3, "牛奶": 1, "面包": 1}
```

### 场景 2：通讯录

需求：按名字查电话，名字不会重复。

→ **字典**。按键（名字）取值，天然一对一。

```python
contacts = {"张三": "13800138000", "李四": "13900139000"}
print(contacts["张三"])
```

### 场景 3：班级点名册

需求：就一串名字，按顺序，偶尔加人。

→ **列表**。顺序有意义，允许重复（重名的处理另说）。

```python
roster = ["张三", "李四", "王五"]
roster.append("赵六")
```

### 场景 4：已登录用户

需求：判断某个用户登没登录，用户不重复。

→ **集合**。去重、判断存在飞快。

```python
logged_in = {"张三", "李四"}
if "张三" in logged_in:
    print("已登录")
```

### 场景 5：一条订单记录

需求：订单号、用户、金额，三个字段绑定在一起，不该被改。

→ **元组**（或更常见的：具名元组 / 类，那是后面学的东西）。

```python
order = ("ORD001", "张三", 128.50)
```

### 场景 6：词频统计

需求：一堆文本，统计每个词出现几次。

→ **字典**。`{词: 次数}` 的计数套路。

```python
text = ["我", "爱", "Python", "我", "爱", "编程"]
count = {}
for w in text:
    count[w] = count.get(w, 0) + 1
print(count)      # {'我': 2, '爱': 2, 'Python': 1, '编程': 1}
```

### 场景 7：找出两段文字的共有词汇

需求：取交集。

→ **集合**。`set(words1) & set(words2)`。

```python
words1 = {"Python", "Java", "Go"}
words2 = {"Go", "Rust", "Python"}
print(words1 & words2)        # {'Python', 'Go'}
```

⚠️ **翻车：该用集合做交集，却用列表推导式写嵌套循环。**

```python
# 能跑，但啰嗦且慢
common = [w for w in words1 if w in words2]
```

元素多时，`in` 列表是慢的。转成集合一行搞定，又快又清楚。

## 四、组合使用：容器的嵌套

现实数据往往是"套娃"的。四种容器可以任意嵌套：

```python
# 字典的值可以是列表：一个班级里每个学生有多门成绩
class_scores = {
    "张三": [92, 78, 88],
    "李四": [85, 90, 77],
}

# 列表里装元组：固定结构的记录集合
students = [("张三", 92), ("李四", 78)]

# 字典的值是集合：每个人会的技能
skills = {
    "张三": {"Python", "SQL"},
    "李四": {"Java", "Python", "Go"},
}
```

嵌套时的选型原则不变，只是**从外到内逐层选**：

1. 外层"按名字查"→ 字典
2. 内层"一组成绩，有序可增删"→ 列表
3. 内层"技能标签，去重、判断会不会"→ 集合

⚠️ **翻车：嵌套后忘记每层容器的操作限制。**

```python
data = {"tags": {"python", "java"}}   # 值是集合
data["tags"].append("go")             # ✗ AttributeError: 'set' object has no attribute 'append'
```

集合没有 `append`，得用 `add`。嵌套越深，越要清楚**每一层到底是什么类型**。

## 小结

- 存键值对 → 字典；判断存在/去重 → 集合；字段固定/要当键 → 元组；否则 → 列表
- 列表默认选择，但别"什么都是列表"
- 真实场景里四种容器常常**嵌套组合**使用
- 嵌套时要清楚每一层的类型，别把集合当列表用
