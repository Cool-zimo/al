# 参数详解：位置、默认、关键字和顺序

> 上一课讲了"def 怎么写"。这一课把**参数**讲透：位置参数、默认参数、关键字参数，以及它们**必须出现的顺序**。
>
> 这一课有两个坑特别阴：**默认参数用了可变对象**、**默认参数"记住了上次的修改"**。

## 一、位置参数：按位置一一对应

最常见的写法，实参按位置对上形参：

```python
def greet(city, name):
    return f"{city}的{name}，你好"

print(greet("北京", "张三"))        # 北京的三，你好
```

第一个实参 "北京" 给 `city`，第二个 "张三" 给 `name`，靠**位置**对齐。

⚠️ **翻车：位置传反了，结果说反话。**

```python
def greet(city, name):
    return f"{city}的{name}，你好"

print(greet("张三", "北京"))        # 张三的北京，你好 —— 逻辑错了，但没报错
```

这不会报错，但语义完全错乱。这种"参数类型是同一个（都是字符串）"的函数，传反了很难发现。**参数名起得好，能让这种错误在代码审查时被看出来**。

## 二、默认参数：给参数一个"默认值"

很多参数大多数时候都是同一个值，这时候可以给它设默认值：

```python
def make_url(host, scheme="https"):
    return f"{scheme}://{host}"

print(make_url("example.com"))              # https://example.com
print(make_url("example.com", "http"))      # http://example.com
```

`scheme="https"` 就是默认参数。**调用时不传，就用默认值；传了，就用你传的**。

⚠️ **翻车：默认参数写在位置参数前面。**

```python
def make_url(scheme="https", host):     # ✗ SyntaxError
    return f"{scheme}://{host}"
```

Python 规定：**默认参数必须放在位置参数后面**。原因是"先按位置对上，剩下的才用默认值"，如果顺序反了，解释器无法确定哪个位置对应哪个参数。铁律：**位置参数在前，默认参数在后**。

## 三、关键字参数：指名道姓地传

调用时可以写明"这个值是给哪个参数的"：

```python
def connect(host, port, timeout):
    print(f"连接 {host}:{port}，超时 {timeout} 秒")

connect(host="localhost", port=3306, timeout=5)
connect(port=3306, host="localhost", timeout=5)     # 顺序无所谓
```

用"参数名="的方式传，**顺序就可以乱**，读起来也更清楚。

⚠️ **翻车：位置参数写在关键字参数后面。**

```python
connect("localhost", port=3306, 5)      # ✗ SyntaxError: positional argument follows keyword argument
```

规则是：**位置参数在前，关键字参数在后**。一旦你用了关键字，后面就不能再回到位置传法。

⚠️ **翻车：同一个参数传了两遍。**

```python
connect(host="localhost", port=3306, host="127.0.0.1")
# ✗ SyntaxError: keyword argument repeated: host
```

同一个参数不能既用位置传又用关键字传，也不能用关键字传两次。

## 四、经典坑：默认参数用了可变对象

这是 Python 里**最著名、最阴**的坑，几乎每个人都会踩一次。

```python
def add_item(item, bag=[]):        # ❌ 默认值是可变对象！
    bag.append(item)
    return bag

print(add_item("苹果"))        # ['苹果']
print(add_item("香蕉"))        # ['苹果', '香蕉']  ← 不是 ['香蕉']！
```

第二次调用时，`bag` 里**还留着上次的"苹果"**。为什么会这样？

**原因**：默认参数的值（那个 `[]`）**在函数定义时就被创建、且只创建一次**，然后被所有调用共享。列表是可变的，你往里 append，就污染了所有人的"默认背包"。

⚠️ **翻车现场：写了个"友好的默认参数"，结果成了 bug 工厂。**

```python
def register(name, scores=[]):
    scores.append(0)           # 想给新用户初始化一个 0 分
    print(name, scores)

register("张三")               # 张三 [0]
register("李四")               # 李四 [0, 0]  ← 李四凭什么带着张三的 0？
```

`[]` 在函数定义时只生成一次，之后所有调用共享同一个列表。张三的 0 留在了里面，李四一来就被 append 上了。

**正确写法：用 `None` 占位，函数体内再创建。**

```python
def add_item(item, bag=None):
    if bag is None:
        bag = []               # 每次调用都新建一个
    bag.append(item)
    return bag

print(add_item("苹果"))        # ['苹果']
print(add_item("香蕉"))        # ['香蕉']  ← 干净了
```

`None` 是不可变的，不会"记住"任何东西。每次调用时再 `bag = []`，每次都是一张白纸。

⚠️ **翻车：把"默认值是可变对象"理解成"默认参数不能用列表"——其实是"不能用可变对象的默认实例"。**

```python
def get_config(key, default=None):      # ✅ 用 None 当默认值，没问题
    return default

def get_config(key, default=[]):       # ❌ 用列表当默认值，坑
    return default
```

不是"列表不能当参数"，而是"默认参数的值必须是不可变的"。`None`、数字、字符串、元组都可以；列表、字典、集合都不行。

## 五、四种参数的混合顺序

把前面学的全用上：

```python
def order(a, b, c=3, d=4):
    return (a, b, c, d)

print(order(1, 2))              # (1, 2, 3, 4)        —— 用默认值
print(order(1, 2, 30))          # (1, 2, 30, 4)       —— c 用传的，d 默认
print(order(1, 2, d=40))        # (1, 2, 3, 40)       —— 指名传 d
print(order(1, 2, 30, 40))      # (1, 2, 30, 40)
```

**铁律顺序**：位置参数 → 默认参数 →（后面第 26 课还有 `*args`、`**kwargs`）。记不住就先写位置、后写默认值。

## 六、一个实用例子：连接数据库

```python
def connect_db(host, port=3306, user="root", charset="utf8mb4"):
    return f"mysql://{user}@{host}:{port}?charset={charset}"

print(connect_db("localhost"))
# mysql://root@localhost:3306?charset=utf8mb4

print(connect_db("10.0.0.1", port=5432, user="app"))
# mysql://app@10.0.0.1:5432?charset=utf8mb4
```

`host` 必须传（没默认值），其余都有合理默认值。这种"一个必填 + 多个可选"的结构，是默认参数的主战场。

⚠️ **翻车：默认参数的"可变对象"坑出现在真实项目里，症状极隐蔽。**

```python
def fetch_users(ids, cache={}):
    uncached = [i for i in ids if i not in cache]
    for i in uncached:
        cache[i] = f"用户{i}"        # 模拟查库
    return [cache[i] for i in ids]

fetch_users([1, 2])
fetch_users([2, 3])        # 2 命中缓存（确实对了），但 cache 会越涨越大
```

`cache` 在函数定义时创建、跨调用存活。一开始你以为"省了一次重复查询"，后来发现**缓存永远不失效、内存只涨不降**。真实项目里这种写法就是内存泄漏。**缓存应该是调用者传进来的对象，或者模块级变量，而不是默认参数**。

## 小结

- 位置参数按位置一一对应，类型相同时传反了不会报错但语义错乱
- 默认参数：调用时可省略，省略就用默认值
- 关键字参数：`参数名=值`，顺序无所谓，可读性好
- 参数顺序铁律：位置参数 → 默认参数；调用时：位置参数 → 关键字参数
- **默认参数不能用可变对象（列表、字典、集合）**，用 `None` 占位、函数体内再创建
- 默认参数的值在函数定义时创建一次并共享，这是最阴的坑
