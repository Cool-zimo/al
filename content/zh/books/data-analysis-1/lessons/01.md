# 为什么列表不够用

> 你已经会 Python 列表了。那为什么还要学 NumPy？
> 这一课不教你写代码，只回答一个问题：**列表到底哪里不行**。

## 先看一件很普通的事

把两个列表"对应位置相加"：

```python
a = [1, 2, 3, 4, 5]
b = [10, 20, 30, 40, 50]

# 你想要 [11, 22, 33, 44, 55]
print(a + b)
```

结果不是你想要的：

```
[1, 2, 3, 4, 5, 10, 20, 30, 40, 50]
```

**列表的 `+` 是"拼接"，不是"相加"。** 这是列表的第一个尴尬之处——它是个"容器"，不是"数学对象"。

要真正相加，你得写循环：

```python
result = []
for i in range(len(a)):
    result.append(a[i] + b[i])
print(result)      # [11, 22, 33, 44, 55]
```

五行代码，只为做一个加法。

## NumPy 的写法

```python
import numpy as np

a = np.array([1, 2, 3, 4, 5])
b = np.array([10, 20, 30, 40, 50])
print(a + b)       # [11 22 33 44 55]
```

一行。`+` 就是数学上的加。

**这就是 NumPy 的核心主张**：把"一堆数字"当成一个整体来运算，而不是一个一个去处理。

## 列表的三个短板

### 短板一：写法啰嗦

上面已经看到了。列表做数学运算，几乎总要配一个 `for`。

### 短板二：慢

这个差距大得惊人。我们来实测一下——把 100 万个数字各自平方：

```python
import numpy as np
import time

data = list(range(1_000_000))
arr = np.array(data)

# 列表：循环
t0 = time.time()
result_list = [x ** 2 for x in data]
t1 = time.time()

# 数组：向量化
result_arr = arr ** 2
t2 = time.time()

print(f"列表：{(t1 - t0) * 1000:.1f} 毫秒")
print(f"数组：{(t2 - t1) * 1000:.1f} 毫秒")
```

典型的输出（你的机器上数字会不同，但比例差不多）：

```
列表：78.3 毫秒
数组：2.1 毫秒
```

**快了几十倍。** 数据越大，差距越明显。

### 短板三：内存吃得多

列表里存的不是数字本身，而是**指向数字对象的引用**。每个 Python 整数对象还要附带类型信息、引用计数等额外数据。

数组存的是**原始数字**，一个挨着一个，紧密排列。

```python
import numpy as np
import sys

data = list(range(1000))
arr = np.array(data)

print(sys.getsizeof(data[0]))   # 28  ← 一个 int 对象就 28 字节
print(arr.itemsize)             # 8   ← 数组里每个元素只占 8 字节
```

1000 个数字，列表要存 1000 个引用 + 1000 个对象；数组只要 1000 × 8 字节的连续空间。

## 为什么数组这么快

两个原因，都值得知道：

**1. 连续内存。** 数组元素在内存里紧挨着，CPU 可以一次性读取一大块（缓存友好）。列表的元素散落在内存各处，每次都要"跳过去找"。

**2. 批量运算在底层完成。** `arr ** 2` 这个操作，NumPy 内部是用 C 语言写的循环跑完的，不经过 Python 解释器逐条执行。Python 的 `for` 循环每转一圈都要做一次类型检查、一次边界检查——这些开销在 100 万次循环里被放大了。

> 💡 术语：**向量化（vectorization）**。意思是"把对单个元素的操作，变成对整个数组的一次操作"。这是 NumPy 最重要的思维方式，第 2 章整章都在讲它。

## 那列表就该被淘汰吗

不是。列表依然有它的地盘：

| 场景 | 用谁 | 原因 |
|---|---|---|
| 存不同类型的东西 | **列表** | 数组要求所有元素同类型 |
| 频繁增删元素 | **列表** | 数组长度固定，改大小要重建 |
| 大规模数值计算 | **数组** | 快、省、写法简洁 |
| 小规模、就几个数 | **列表** | 数组有创建开销，数据量小反而亏 |

判断标准很简单：**如果你要拿这些数据做数学运算，用数组；如果只是"存着"，用列表。**

## NumPy 的规矩：所有元素必须同类型

这是数组能快的前提，也是它最大的限制。

```python
import numpy as np

# 混着放会怎样？
arr = np.array([1, 2.5, 3])
print(arr)        # [1.  2.5 3. ]
print(arr.dtype)  # float64  ← 整数被自动升级成浮点
```

Python 不会报错，而是**把大家统一成同一种类型**（这里是都变成 float）。

再看字符串混数字：

```python
arr = np.array([1, 2, "three"])
print(arr)        # ['1' '2' 'three']  ← 全都变成字符串了
print(arr.dtype)  # <U21
```

数字变成了字符串，这是**静默发生**的，不会报错。以后排查"为什么算不出来"的 bug 时，`dtype` 是第一个该看的东西。
