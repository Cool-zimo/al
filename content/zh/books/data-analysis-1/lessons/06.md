# 向量化思维

> 这一课是整个 NumPy 的灵魂：**学会不用循环思考问题**。

## 两种写法，同一个结果

给一批商品打八折：

```python
import numpy as np

prices = np.array([100, 250, 80, 300, 45])

# 写法一：循环（列表思维）
result = []
for p in prices:
    result.append(p * 0.8)

# 写法二：向量化（数组思维）
result2 = prices * 0.8
```

**第二种不是"写得短一点"，而是一种不同的思维方式。**

- 循环思维：我有一堆数，我一个个拿过来处理
- 向量化思维：我有一个数组，我对它整体做一个操作

当你开始习惯后者，你会发现原本需要十几行的代码往往一行就能写完，而且跑得更快。

## 实测一次差距

```python
import numpy as np
import time

n = 2_000_000
arr = np.random.random(n)

t0 = time.time()
doubled = np.array([x * 2 for x in arr])   # 逐元素循环
t1 = time.time()
doubled2 = arr * 2                          # 向量化
t2 = time.time()

print(f"循环：{(t1 - t0) * 1000:.0f} 毫秒")
print(f"向量化：{(t2 - t1) * 1000:.0f} 毫秒")
```

两百万个数，循环要几百毫秒，向量化通常只要几毫秒。

## 条件判断也能向量化：np.where

这是最"救命"的一个函数。

**需求**：成绩低于 60 的记为 0，否则保留原分。

循环写法：

```python
scores = np.array([45, 78, 92, 55, 61])
result = []
for s in scores:
    if s < 60:
        result.append(0)
    else:
        result.append(s)
```

向量化写法：

```python
result = np.where(scores < 60, 0, scores)
print(result)      # [ 0 78 92  0 61]
```

**`np.where(条件, 满足时取的值, 不满足时取的值)`** —— 三个参数，一行搞定。

它做的是"逐元素三元运算"，等价于对每个元素问一次：条件成立吗？成立取第二个，否则取第三个。

**也可以只给条件**，`np.where` 会返回满足条件的**下标**：

```python
print(np.where(scores < 60))     # (array([0, 3]),)  ← 第 0 个和第 3 个
print(scores[np.where(scores < 60)])   # [45 55]
```

（第 3 章会讲更简洁的布尔索引写法。）

## 一个真实的改造案例

**需求**：计算一组坐标到原点的距离。

```python
import numpy as np

points = np.array([[1, 2], [3, 4], [5, 12], [8, 6]])
```

**循环写法**：

```python
dists = []
for x, y in points:
    dists.append((x ** 2 + y ** 2) ** 0.5)
```

**向量化写法**：

```python
xs = points[:, 0]        # 所有行的第 0 列 → [1 3 5 8]
ys = points[:, 1]        # 所有行的第 1 列 → [2 4 12 6]
dists = (xs ** 2 + ys ** 2) ** 0.5
print(dists)             # [ 2.236  5.  13.  10.]
```

甚至可以更短：

```python
dists = np.sqrt((points ** 2).sum(axis=1))
```

**注意这里发生了什么**：我们没有"遍历每个点"，而是把"所有 x"和"所有 y"各自取出来，当成两个整体来算。这就是向量化的核心动作——**把逐元素的处理，变成对整列的操作**。

## 什么时候循环不可替代

别走极端。以下场景循环（或部分循环）仍然合理：

**1. 前后有依赖。** 当前值依赖上一步的结果，比如"累加到某个阈值就停"：

```python
# 这类"滚动依赖"没法直接向量化
total = 0
for x in data:
    total += x
    if total > 1000:
        break
```

（严格说 `np.cumsum()` 能算前缀和，但"提前 break"这种短路逻辑不好向量化。）

**2. 每个元素的处理逻辑不一样。** 向量化要求"所有元素做同一件事"。

**3. 数据量很小。** 几千个元素以下，循环和向量化的差距你可能根本感觉不到，那就不必为了向量化把代码写得难懂。

> 💡 判断标准：**先看能不能向量化，不能再用循环**。而不是反过来。

## 向量化的三个常用套路

| 想做的事 | 向量化写法 |
|---|---|
| 条件二选一 | `np.where(cond, a, b)` |
| 逐元素函数 | `np.sqrt(arr)`、`np.exp(arr)` |
| 按条件统计 | `np.sum(arr > 5)` |
| 整体替换某段 | `arr[arr < 0] = 0` |
| 一次算一堆的均值 | `arr.mean(axis=1)` |

```quiz

  scores = np.array([45, 78, 92, 55, 61])

  print("在这里改")
tests:
- assert "[60 78 92 60 61]" in __out
hint: print(np.where(scores < 60, 60, scores))。三个参数依次是：条件、条件成立时的值、不成立时的值。
```

```quiz
q: 关于向量化，下面哪个说法正确？

- 向量化只是"代码写得短"，运行速度其实一样
- 向量化把逐元素操作变成对整个数组的操作，通常在底层批量执行，因此更快
- 任何循环都能改写成向量化，而且一定更快
- 向量化只适用于一维数组
answer: 1
```
