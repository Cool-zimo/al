# 列表与数组的取舍

> 两个都能装一堆数，怎么选？这一课给出可操作的判断标准，并做一次真实的性能实测。

## 互相转换

```python
import numpy as np

# 列表 → 数组
lst = [1, 2, 3, 4, 5]
arr = np.array(lst)
print(arr, type(arr))     # [1 2 3 4 5] <class 'numpy.ndarray'>

# 数组 → 列表
back = arr.tolist()
print(back, type(back))   # [1, 2, 3, 4, 5] <class 'list'>
```

**`tolist()` 是递归的**——多维数组会变成嵌套列表：

```python
m = np.array([[1, 2], [3, 4]])
print(m.tolist())     # [[1, 2], [3, 4]]
```

**什么时候需要转回列表？**

- 要 `append` / `insert` 频繁增删时
- 要存进 JSON 时（NumPy 数组不能直接序列化）
- 要交给只认列表的第三方库时

## 性能实测：别听我说，自己跑

课上给一个可复现的对比。这段代码你可以直接在下面的运行框里跑：

```python
import numpy as np
import time

n = 500_000
data = list(range(n))
arr = np.array(data)

# 列表：循环求和
t0 = time.time()
s1 = 0
for x in data:
    s1 += x
t1 = time.time()

# 数组：向量化求和
s2 = np.sum(arr)
t2 = time.time()

print(f"结果一致：{s1 == s2}")
print(f"列表循环：{(t1 - t0) * 1000:.2f} 毫秒")
print(f"数组求和：{(t2 - t1) * 1000:.2f} 毫秒")
```

你会发现数组快一个数量级。

**但请注意**：这个差距只体现在"大量数据的批量运算"上。

## 反例：数组也会输

试试往里面塞元素：

```python
import numpy as np
import time

n = 50_000

t0 = time.time()
lst = []
for i in range(n):
    lst.append(i)
t1 = time.time()

arr = np.array([])
for i in range(n):
    arr = np.append(arr, i)
t2 = time.time()

print(f"列表 append：{(t1 - t0) * 1000:.1f} 毫秒")
print(f"数组 append：{(t2 - t1) * 1000:.1f} 毫秒")
```

数组会慢得多，可能是几十倍。

**为什么？** 因为 `np.append` 不是"在末尾加一个格子"，而是**新建一个更大的数组，把旧内容全拷过去，再加新元素**。做了 5 万次，等于反复重建 5 万次。

> 💡 记住：**数组适合"一次建好，反复算"，不适合"边跑边长"。** 需要动态增长时，用列表收集，最后一次性 `np.array()` 转换。

```python
# 正确做法
rows = []
for i in range(1000):
    rows.append(compute(i))     # 先用列表收集
arr = np.array(rows)            # 最后一次性转换
```

## 决策表

| 你的需求 | 选谁 |
|---|---|
| 做数学运算（加减乘除、统计） | **数组** |
| 数据量大（万级以上） | **数组** |
| 需要频繁增删元素 | **列表** |
| 存不同类型的东西 | **列表** |
| 就几个数，随手用 | **列表** |
| 要存 JSON / 交给别的库 | **列表** |
| 要做矩阵运算、画图 | **数组** |

一句话总结：**算用数组，存用列表。**

## 数组也有"容器"用法

数组支持大部分列表的操作：

```python
arr = np.array([10, 20, 30, 40, 50])

print(arr[0])          # 10      下标
print(arr[-1])         # 50      负索引
print(arr[1:3])        # [20 30] 切片
print(len(arr))        # 5       长度
print(30 in arr)       # True    包含
```

但有两个重要区别：

**1. 切片是"视图"，不是副本。**

```python
arr = np.array([1, 2, 3, 4, 5])
part = arr[1:3]
part[0] = 99
print(arr)      # [1 99 3 4 5]  ← 原数组被改了！
```

列表的切片会复制一份，数组的切片只是"开了个窗口"。这是 NumPy 最重要的陷阱之一，第 3 章会专门讲。

**2. 数组没有 append。**

前面说过了，用 `np.append` 是新建+复制，代价高。

## 内存对比

直观感受一下：

```python
import numpy as np
import sys

n = 100_000
lst = list(range(n))
arr = np.arange(n)

# 列表：容器本身 + 所有 int 对象
list_bytes = sys.getsizeof(lst) + sum(sys.getsizeof(x) for x in lst)
arr_bytes = arr.nbytes

print(f"列表：{list_bytes / 1024 / 1024:.1f} MB")
print(f"数组：{arr_bytes / 1024 / 1024:.1f} MB")
```

通常列表要占数组的好几倍。

**`arr.nbytes`** 是数组占的字节数，排查内存问题时很有用。

## 一个实战场景

假设你要处理一份 10 万行的销售数据：

```python
import numpy as np

np.random.seed(0)
prices = np.random.uniform(10, 500, 100_000)   # 10 万个价格
quantities = np.random.randint(1, 10, 100_000) # 10 万个数量

# 总额：一行搞定
total = prices * quantities

print(f"总销售额：{np.sum(total):,.0f}")
print(f"平均单价：{np.mean(prices):.1f}")
print(f"最贵的一笔：{np.max(total):,.0f}")
print(f"超过 1000 的笔数：{np.sum(total > 1000)}")
```

用列表写这段，需要 4 个循环。

## 随堂练习

把"先用列表收集，最后一次性转换"这个模式写一遍。

```quiz
type: code
q: 先用列表收集 0~4 的平方，最后转成数组并求和（答案 30）
starter: |
  import numpy as np
  
  # 用列表收集 0~4 的平方
  squares = []
  for i in range(5):
      squares.append(i ** 2)
  
  # 最后一次性转成数组，再求和
  # 提示：np.array(squares).sum()
  
  print("在这里改")
tests:
- assert "30" in __out
hint: arr = np.array(squares) 然后 print(arr.sum())。0+1+4+9+16 = 30。
explain: 这是处理"动态数据"的标准姿势：列表负责收集和增长，转换只做一次。反过来如果每来一个数据就 np.append 一次，会反复重建数组，慢上几十倍。
```
