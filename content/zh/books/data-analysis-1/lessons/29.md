# 性能：避开常见慢写法

> 这一段不教新 API，只做一件事：**用实测数据告诉你哪些写法慢、慢多少**。

## 先建立测量方法

```python
import numpy as np
import time

def timeit(fn, *args):
    fn(*args)                       # 预热一次（首次调用有额外开销）
    t0 = time.perf_counter()
    r = fn(*args)
    return (time.perf_counter() - t0) * 1000    # 毫秒
```

**预热很重要**——第一次调用往往包含初始化开销，测进去会失真。

## 对比一：循环 vs 向量化

```python
n = 200_000
a = np.arange(n, dtype=float)

def by_loop(x):
    total = 0.0
    for v in x:
        total += v * v
    return total

def by_vector(x):
    return (x ** 2).sum()

print(f"循环：{timeit(by_loop, a):.1f} ms")
print(f"向量化：{timeit(by_vector, a):.1f} ms")
```

典型结果（20 万个数）：

```
循环：12.4 ms
向量化：0.4 ms
```

**约 30 倍差距**。而且数据量越大，差距越大。

**原因**：Python 循环每次迭代都要做类型检查、边界检查；NumPy 的向量化是一次性把 20 万个数交给底层 C 循环处理。

## 对比二：np.append vs 预分配

**这是新手最常踩的坑**：

```python
n = 20_000

def by_append(n):
    arr = np.array([])
    for i in range(n):
        arr = np.append(arr, i)      # 每次都创建新数组！
    return arr

def by_prealloc(n):
    arr = np.empty(n)
    for i in range(n):
        arr[i] = i
    return arr

print(f"np.append：{timeit(by_append, n):.1f} ms")
print(f"预分配：{timeit(by_prealloc, n):.1f} ms")
```

**`np.append` 不是"往数组里加东西"**——它每次都**新建一个更大的数组、把旧内容复制过去**。做 n 次就是 n 次完整复制，复杂度 O(n²)。

> 💡 **绝对不要在循环里用 np.append**。要么预分配 `np.empty(n)`，要么先把值收进 Python 列表、最后一次 `np.array(list)`。

## 对比三：花式索引 vs 布尔索引

```python
n = 500_000
a = np.random.rand(n)
idx = np.arange(0, n, 2)              # 偶数下标

t0 = time.perf_counter(); x = a[idx]; t1 = time.perf_counter()
mask = a > 0.5
t2 = time.perf_counter(); y = a[mask]; t3 = time.perf_counter()

print(f"花式索引：{(t1-t0)*1000:.2f} ms")
print(f"布尔索引：{(t3-t2)*1000:.2f} ms")
```

两者都会**复制数据**（不是视图）。如果只读不写，且需要多次访问，考虑一次性取出。

## 对比四：view vs copy

```python
big = np.random.rand(3000, 3000)      # 约 72 MB

# view：几乎瞬间
t0 = time.perf_counter(); v = big[:1500]; t1 = time.perf_counter()
# copy：要真搬 36 MB
t2 = time.perf_counter(); c = big[:1500].copy(); t3 = time.perf_counter()

print(f"切片（view）：{(t1-t0)*1000:.3f} ms")
print(f"复制（copy）：{(t3-t2)*1000:.1f} ms")
```

**切片是瞬间的，copy 要真搬内存**。处理大图、大矩阵时，能不 copy 就不 copy。

## 对比五：axis 方向也会影响速度

```python
m = np.random.rand(2000, 2000)

def sum_rows(x):  return x.sum(axis=0)    # 跨行（沿第 0 维压）
def sum_cols(x):  return x.sum(axis=1)    # 跨列（沿第 1 维压）

print(f"axis=0：{timeit(sum_rows, m):.1f} ms")
print(f"axis=1：{timeit(sum_cols, m):.1f} ms")
```

**`axis=0` 通常更快**，因为 NumPy 数组默认**按行存储（C 序）**——同一列的元素在内存中不连续，跨行读取要跳跃。

数据量小的时候无所谓，几百万级的时候能差 2~5 倍。

## 慢写法清单

| ❌ 慢 | ✅ 快 | 原因 |
|---|---|---|
| `for` 循环逐元素算 | 向量化表达式 | Python 循环开销 |
| 循环里 `np.append` | 预分配 / 先收列表 | append 是 O(n²) |
| 不必要的 `.copy()` | 用 view | 避免搬内存 |
| `np.concatenate` 逐个拼 | 一次性 `concatenate([...])` | 减少中间数组 |
| 反复 `np.array(list)` | 一次转换 | 减少转换次数 |
| 小数组上的复杂表达式 | 直接算 | 小数据时函数调用开销占比高 |

## 什么时候不用优化

**过早优化是万恶之源**。以下情况不值得优化：

- 数据量小于 1 万（差距在毫秒级，人感觉不到）
- 这段代码只跑一次（优化花的时间比省下的多）
- 代码清晰度会明显下降（可读性优先）

**原则**：**先写对，再测，发现慢了再优化**。用 `timeit` 找到真正的瓶颈，而不是凭感觉。

## 测量工具

```python
import timeit

# 更严谨的做法：跑很多次取平均
t = timeit.timeit(lambda: (a ** 2).sum(), number=100)
print(f"100 次共 {t*1000:.1f} ms，单次 {t*1000/100:.3f} ms")
```

`timeit` 模块会自动多次运行取平均，比手写 `time.perf_counter()` 更可靠。
