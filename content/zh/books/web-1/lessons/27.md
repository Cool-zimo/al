# 搭 HTML 骨架：语义化标签组织简历

> 这一节把上一课的设计落地成 HTML。重点是**标签选对**——每个区块用最合适的标签，让结构本身就是文档。

## 简历页的完整骨架

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>张三 - 前端工程师</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header class="site-header">
    <h1>张三</h1>
    <p class="title">前端工程师</p>
    <nav class="social">
      <a href="mailto:zhangsan@example.com">邮箱</a>
      <a href="https://github.com">GitHub</a>
      <a href="https://juejin.cn">掘金</a>
    </nav>
  </header>

  <main>
    <section class="about">
      <h2>关于我</h2>
      <p>5 年 Web 开发经验，专注于前端工程化与用户体验优化……</p>
    </section>

    <section class="skills">
      <h2>技能</h2>
      <ul>
        <li>JavaScript / TypeScript</li>
        <li>React / Vue</li>
        <li>Node.js</li>
      </ul>
    </section>

    <section class="experience">
      <h2>工作经历</h2>
      <article class="job">
        <h3>高级前端工程师 · 某科技公司</h3>
        <time>2022.03 - 至今</time>
        <p>负责公司核心产品的前端架构与开发……</p>
      </article>
    </section>

    <section class="projects">
      <h2>项目经验</h2>
      <article class="project-card">
        <h3>电商后台管理系统</h3>
        <p>基于 Vue 3 + Element Plus 的管理平台……</p>
      </article>
    </section>
  </main>

  <footer class="site-footer">
    <p>© 2026 张三 · 用 ❤️ 制作</p>
  </footer>
</body>
</html>
```

## 标签选择的思考

**为什么 `<main>` 包裹主体内容？**

`<main>` 表示页面的主要内容，一个页面只能有一个。它帮助读屏用户快速跳过导航、直达正文。

**为什么 `<article>` 包工作经历和项目？**

`<article>` 表示一段**独立、可分发**的内容。一份工作描述、一张项目卡片，理论上可以独立存在（比如被引用到其他页面），所以用 article 最合适。

**为什么时间用 `<time>`？**

```html
<time datetime="2022-03">2022.03 - 至今</time>
```

`<time>` 的 `datetime` 属性提供机器可读的时间格式，搜索引擎和浏览器可以解析。展示给用户的是更友好的"2022.03 - 至今"。

翻车现场一：整个页面都是 div。

```html
<div class="header">
  <div class="title">张三</div>
</div>
<div class="main">
  <div class="section">
    <div class="section-title">关于我</div>
    <div class="text">...</div>
  </div>
</div>
```

后果：能渲染，但语义全无。SEO 差、可访问性差、维护时难以理解结构。一个 div 走天下是新手最常见的写法。

## 区块之间的层级关系

注意 `<section>` 里可以包含 `<article>`，`<article>` 里也可以有自己的 `<h3>` 和小节：

```
<body>
  <header>          ← 头部
  <main>            ← 主体
    <section>       ← 区块：关于我
    <section>       ← 区块：技能
    <section>       ← 区块：经历
      <article>     ← 独立的经历条目
    <section>       ← 区块：项目
      <article>     ← 独立的项目卡片
  <footer>          ← 底部
```

h1 → h2 → h3 的层级也对应这个结构。标题层级不能跳（h1 直接跳 h3），否则读屏用户会困惑。

## 小结

- 简历骨架用 header / main / section / article / footer 构建。
- 标签选择的原则是"语义最匹配"，不是"哪个能渲染"。
- main 唯一、article 表示独立可分发内容、time 提供机器可读时间。
- 标题层级 h1→h2→h3 不跳跃，反映内容嵌套关系。

## 随堂练习

```quiz
type: html
q: 写一个 section（class="projects"），里面放一个 h2（内容"项目经验"）和两个 article，每个 article 里放一个 h3（项目名）和一个 p（描述）。项目名分别为"在线商城"和"数据可视化平台"，描述分别为"基于 React 的电商前端"和"基于 ECharts 的数据大屏"。
starter: |
  <section class="projects">
  </section>
checks:
- document.querySelector('.projects h2').textContent.trim() === '项目经验'
- document.querySelectorAll('.projects article').length === 2
- document.querySelectorAll('.projects article h3').length === 2
- document.querySelectorAll('.projects article')[0].querySelector('h3').textContent.trim() === '在线商城'
- document.querySelectorAll('.projects article')[0].querySelector('p').textContent.trim() === '基于 React 的电商前端'
- document.querySelectorAll('.projects article')[1].querySelector('h3').textContent.trim() === '数据可视化平台'
- document.querySelectorAll('.projects article')[1].querySelector('p').textContent.trim() === '基于 ECharts 的数据大屏'
hint: section 内含 h2 和两个 article，每个 article 内含 h3 + p。
explain: section 作为项目区块，article 表示每个独立的项目卡片，结构清晰。
```

## 本节测验

```quiz
type: choice
exam: true
q: 关于 `<article>` 和 `<section>` 的使用，下列说法正确的是？
options:
- article 和 section 完全一样，随便用
- article 表示独立可分发的内容，section 表示主题性的内容分组
- section 只能放在 article 里面
- article 不能包含标题
answer: 1
explain: article 用于独立、可单独分发的内容（如一篇博客、一张卡片）；section 用于对相关内容进行主题性分组。两者可嵌套，article 内部可有自己的标题。
```
