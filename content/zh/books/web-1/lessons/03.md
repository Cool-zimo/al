# 标题与段落：h1~h6 的语义

> 这一节解决"标题用什么标签"的问题。核心认知：**h1 是"这是一级标题"，不是"这是大号字"**。

## 标题是层级，不是字号

HTML 有六级标题：`<h1>` 到 `<h6>`。它们表达的是**内容的层级关系**，像一本书的"章—节—小节"。

```html
<h1>张三的简历</h1>
<h2>教育经历</h2>
<h3>本科</h3>
<p>北京大学，计算机科学与技术，2018—2022</p>
<h3>硕士</h3>
<p>清华大学，软件工程，2022—2024</p>
<h2>工作经历</h2>
```

这棵标题树，浏览器能读懂，搜索引擎能读懂，屏幕阅读器也能读懂。视障用户用读屏软件可以按标题跳转，快速定位到"工作经历"那段——**这才是标题标签的价值**。

翻车现场一：用字号大小"假装"标题。

```html
<p style="font-size: 32px; font-weight: bold;">工作经历</p>
<p>张三，前端工程师……</p>
```

后果：字是大了、粗了，看着像标题。但对机器来说，这就是两个普通段落。读屏用户听不到任何"这里是一个章节开始"的信号，搜索结果里也不会把"工作经历"当作结构标记。多写几个 `style`，代码也越来越脏。

## 一个页面只有一个 h1

h1 是"页面主标题"，整个页面应该只有一个。它是给搜索引擎和辅助工具看的"这一页在讲什么"。副标题用 h2，更细的用 h3，逐级往下。

```html
<h1>张三的个人网站</h1>
<h2>关于我</h2>
<p>……</p>
<h2>我的项目</h2>
<h3>项目一</h3>
<p>……</p>
<h3>项目二</h3>
<p>……</p>
```

如果张三的简历页把"教育经历""工作经历""技能"都写成 h1，搜索引擎会认为这一页有三个同等重要的主标题，页面的主题就模糊了。

## 段落：p 标签

```html
<p>张三是一名前端开发工程师，目前就职于北京的一家互联网公司。</p>
<p>他喜欢写清晰、可维护的代码。</p>
```

`<p>` 表示一段完整的内容。浏览器会自动在段落前后加空白（margin），所以**你不需要手动加空行**。

翻车现场二：用 br 堆间距。

```html
<p>第一段内容</p>
<br><br><br>
<p>第二段内容</p>
```

后果：`<br>` 的本意是"在一段之内换行"（比如地址、诗歌）。用三个 br 来制造段落间距，等于用内容元素去做布局的事。间距该由 CSS 的 margin 控制。这么写还有个麻烦：以后想统一调间距，得一个个 br 去删，而用 CSS 只要改一行。

## br 与 hr

`<br>` 是强制换行，只用在确实需要在段内换行的场合：

```html
<p>
  北京市朝阳区<br>
  望京街 1 号<br>
  邮编 100102
</p>
```

`<hr>` 是分隔线，表示话题的转换：

```html
<h2>第一部分</h2>
<p>……</p>
<hr>
<h2>第二部分</h2>
<p>……</p>
```

现代网页里 hr 用得不多，大多数分隔效果用 CSS 的 border 实现。知道它存在即可。

## 小结

- h1~h6 表示**层级**，不是字号；一个页面只有一个 h1。
- 标题树是给机器读的，关系到可访问性和 SEO。
- 段落用 `<p>`，别用 `<br>` 堆间距——那是 CSS 的活。
- `<br>` 只在段内换行时用，`<hr>` 表示话题转换。

## 随堂练习

```quiz
type: html
q: 写一个 h1，内容是"我的主页"，再写一个 h2，内容是"关于我"，最后写一个 p，内容是"我喜欢编程"。三个元素顺序写出即可。
starter: |
  <h1>我的主页</h1>
checks:
- document.querySelectorAll('h1').length === 1
- document.querySelectorAll('h2').length === 1
- document.querySelectorAll('p').length === 1
- document.querySelector('h1').textContent.trim() === '我的主页'
- document.querySelector('h2').textContent.trim() === '关于我'
hint: 三个标签直接并列，按顺序写。
explain: h1、h2、p 各自独立，内容分别在各自的标签内。
```
