# float 与清除浮动：被绕开的文档流

> 这一节解决"图片旁边想绕排文字"和"两个 div 并排却让父容器塌了"的问题。float 是 CSS 里一个历史包袱很重的属性，搞懂它，才能理解为什么现在更推荐 Flex。

## float 原本是干什么的

`float` 最初的设计目的只有一件：**让文字环绕图片**，像报纸排版那样。

```html
<img src="cat.jpg" class="float-left">
<p>这是一段很长的文字，会围绕在图片的右侧排列。浮动元素脱离正常文档流，但文字不会覆盖它，而是主动绕开，形成经典的图文绕排效果……</p>
```

```css
.float-left {
  float: left;
  margin-right: 15px;
  margin-bottom: 10px;
}
```

`float: left` 让元素贴到父容器的左侧，右侧内容（这里是文字）会环绕它。`float: right` 则贴到右侧。

后来有人发现"诶，float 能让元素并排"，于是整个 Web 1.0 时代的布局都靠它。但这个用法带来了著名的副作用——**高度塌陷**。

## 高度塌陷：float 的千古之坑

当一个父元素里的子元素全部浮动时，父元素会"感知不到"子元素的高度，高度塌缩为 0。

```html
<div class="parent">
  <div class="child">块 A</div>
  <div class="child">块 B</div>
</div>
<p class="after">我是后面的内容</p>
```

```css
.parent {
  border: 2px solid red;
  background: #ffe0e0;
}
.child {
  float: left;
  width: 150px;
  height: 100px;
  background: #4a90d9;
  margin-right: 10px;
}
```

后果：`.parent` 的红边框紧紧贴在一条线上，高度几乎为 0。两个蓝色的 child 仿佛"飞"了出去，后面的 `<p>` 也会直接挤上来，盖在浮动元素下面。

翻车现场一：以为给父元素设 `overflow: hidden` 会裁掉子元素。

```css
.parent {
  overflow: hidden;
}
```

实际效果：父元素反而"恢复"了高度，包裹住了浮动的子元素。这是因为 `overflow` 不为 `visible` 时会触发 BFC（块级格式化上下文），强制父元素计算浮动子元素的高度。所以 `overflow: hidden` 恰好是一种清除浮动的方法，虽然它本意是裁切溢出。

## 清除浮动的三种方法

**方法一：clear 属性**

`clear: both` 表示"我的左侧和右侧不允许有浮动元素"，常用于在浮动元素后面放一个清除元素。

```css
.clear {
  clear: both;
}
```

```html
<div class="parent">
  <div class="child">块 A</div>
  <div class="child">块 B</div>
  <div class="clear"></div>
</div>
```

**方法二：clearfix 伪元素（推荐）**

不需要在 HTML 里多写一个空 div，用伪元素 `::after` 代替。

```css
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
```

```html
<div class="parent clearfix">
  <div class="child">块 A</div>
  <div class="child">块 B</div>
</div>
```

`.parent` 会自动包裹住浮动子元素，HTML 结构保持干净。

**方法三：overflow 触发 BFC**

```css
.parent {
  overflow: hidden; /* 或 auto */
}
```

简单粗暴，但要注意：如果子元素有超出父元素的内容（比如下拉菜单），会被裁掉。

翻车现场二：只给父元素设 `height` 硬撑。

```css
.parent {
  height: 100px;
}
```

后果：父元素看起来"包住了"，但如果以后子元素变多或变高，父元素的固定高度就不够用了，内容溢出。这是治标不治本，遇到动态内容就会翻车。

## 现代布局还需要 float 吗

答案是：**并排布局不需要，图文绕排仍然需要**。

现在做导航、卡片、网格，统一用 Flex（第 19、20 课）或 Grid（第 24 课），它们不会出现高度塌陷的问题。但如果你要让一段文字优雅地绕在一张图片旁边，float 依然是唯一选择。

```css
.article img {
  float: left;
  width: 200px;
  margin-right: 16px;
  margin-bottom: 8px;
}
```

## 小结

- float 最初用于图文绕排，后来被滥用于布局。
- 浮动元素脱离文档流，导致父元素高度塌陷为 0。
- 清除浮动三种方法：clear 属性、clearfix 伪元素、overflow 触发 BFC。
- clearfix 是最干净、最通用的方案，不污染 HTML 也不裁切内容。
- 并排布局用 Flex/Grid 替代 float，绕排场景仍用 float。

type: css
