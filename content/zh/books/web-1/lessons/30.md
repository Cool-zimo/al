# 收官：检查清单与部署上线

> 这一节解决"怎么确认页面写好了"和"怎么让别人也能访问"的问题。一份上线前的检查清单，加上 GitHub Pages 的部署流程。

## 上线前检查清单

### 语义化

- [ ] 每个页面有且只有一个 `<main>`
- [ ] 标题层级 h1 → h2 → h3 不跳跃
- [ ] 图片有 `alt` 属性
- [ ] 链接文字有描述性（不是"点击这里"）
- [ ] 列表用 `<ul>` / `<ol>` / `<li>`，导航用 `<nav>`

### 响应式

- [ ] 有 viewport meta 标签
- [ ] 在 320px（小屏手机）下无横向滚动
- [ ] 在 1920px（大屏桌面）下不拉伸失控
- [ ] 字体在手机上不小于 14px
- [ ] 图片有 `max-width: 100%; height: auto`

### 可访问性

- [ ] 颜色对比度足够（正文至少 4.5:1）
- [ ] 表单有 `<label>` 关联
- [ ] 按钮有可理解的文字（不用空 div 做按钮）
- [ ] 可以用 Tab 键遍历所有可交互元素
- [ ] 鼠标 hover 的效果在键盘 focus 时也能体现

```css
/* focus 和 hover 保持一致 */
a:hover,
a:focus {
  color: var(--color-accent);
  text-decoration: underline;
}
```

### 性能

- [ ] 图片经过压缩（不传 5MB 的原图）
- [ ] CSS 写在外部文件（可缓存）
- [ ] 动画只用 transform 和 opacity
- [ ] 没有 console.log 留在生产代码里

## 部署到 GitHub Pages

GitHub Pages 是 GitHub 提供的免费静态站点托管服务。你的简历页是纯 HTML/CSS/JS，完全符合。

**步骤：**

1. **创建仓库**：在 GitHub 上新建一个仓库，名字叫 `你的用户名.github.io`（比如 `zhangsan.github.io`）。

2. **上传代码**：把 `index.html`、`style.css`、`app.js` 上传到仓库根目录。

```bash
git init
git add .
git commit -m "简历页初版"
git branch -M main
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git push -u origin main
```

3. **开启 Pages**：仓库 → Settings → Pages → Source 选 `main` 分支 → Save。

4. **访问**：等待约 1 分钟，打开 `https://你的用户名.github.io` 就能看到你的简历页了。

翻车现场一：仓库名不合规。

后果：如果仓库名不是 `用户名.github.io` 的格式，Pages 的地址会是 `用户名.github.io/仓库名`。虽然也能访问，但 URL 多了一层。

翻车现场二：页面显示 404。

后果：可能原因——HTML 文件名不是 `index.html`（GitHub Pages 默认找 index.html），或者还没选对分支/目录。检查仓库根目录是否有 index.html，Pages 设置里分支是否选对。

```quiz
type: html
q: 检查以下 HTML 片段的可访问性：给 img 加 alt 属性（内容"张三的个人头像"），给 a 加有意义的链接文字（"查看张三的 GitHub 主页"），给 button 加 type 属性（值 submit）。

  <img src="avatar.jpg">
  <a href="https://github.com/zhangsan"></a>
  <button>提交简历</button>
checks:
- document.querySelector('img').getAttribute('alt') === '张三的个人头像'

- document.querySelector('button').getAttribute('type') === 'submit'
hint: img 加 alt，a 加描述性文字，button 加 type="submit"。
explain: alt 让读屏用户知道图片内容，描述性链接文字比"点击这里"更有意义，button 的 type 属性明确语义。
```
