# 语义化标签：header、nav、main、section、article、footer

> 这一节解决"满屏都是 div，机器读不懂我的页面在讲什么"的问题。语义化标签让结构自己会说话。

## 一堆 div 的问题

```html
<div class="header">页头</div>
<div class="nav">导航</div>
<div class="main">
  <div class="section">
    <div class="article">正文</div>
  </div>
</div>
<div class="footer">页脚</div>
```

这一堆 div 在浏览器里渲染出来没问题，但**没有任何一个标签告诉机器"这里是导航""那里是主内容"**。对机器来说，这就是六个长相不同的盒子。

## 语义化标签：给结构起对名字

```html
<header>页头</header>
<nav>导航</nav>
<main>
  <section>
    <article>正文</article>
  </section>
</main>
<footer>页脚</footer>
```

| 标签 | 用途 |
|---|---|
| `<header>` | 页头或区块的头部（标题、logo、导航） |
| `<nav>` | 导航链接的集合 |
| `<main>` | 页面的主要内容，**每个页面只有一个** |
| `<section>` | 一个主题性的内容区块，通常带标题 |
| `<article>` | 一段独立完整、可单独分发的内容（博客、评论） |
| `<footer>` | 页脚或区块的尾部（版权、联系方式） |

## main 只能有一个

`<main>` 表示页面的**主要内容**。一个页面应该只有一个 `<main>`。读屏用户有个快捷键"跳到主内容"，跳到的就是这个 main。如果张三写了两个 main，读屏就不知道该跳到哪个了。

## header 和 footer 不是只能用一次

它们可以嵌套在任意区块里：

```html
<article>
  <header>
    <h3>文章标题</h3>
    <p>发布于 2026 年 9 月</p>
  </header>
  <p>正文……</p>
  <footer>
    <p>标签：前端、HTML</p>
  </footer>
</article>
```

这里的 header 是这篇文章的头部，不是整个页面的头部。语义是"在某个容器内作为头部"，不限次数。

## section 与 article 的差别

判断方法：**内容能不能脱离上下文独立存在？**

- 能独立存在（博客文章、新闻条目、评论）→ `<article>`
- 只是主题相关的一段内容（"关于我们"板块、"技能"板块）→ `<section>`

```html
<main>
  <section>
    <h2>我的项目</h2>
    <article>
      <h3>项目一</h3>
      <p>一个用 Python 写的爬虫工具。</p>
    </article>
    <article>
      <h3>项目二</h3>
      <p>一个用 Vue 写的待办应用。</p>
    </article>
  </section>
</main>
```

翻车现场一：section 里没有标题。

```html
<section>
  <p>一些内容</p>
</section>
```

后果：section 的本意是"有主题的内容区"，按规范应该有一个标题（h2~h6）说明主题。没有标题的 section，语义就不成立——这时改用 div 反而更准确。

翻车现场二：article 包 article，把 section 当万能容器。

```html
<article>
  <article>嵌套内容</article>
</article>
```

后果：article 表示"一份完整独立的内容"，一份完整内容里再套一份完整内容，语义矛盾。嵌套关系要按实际内容层级设计。

## 为什么比一堆 div 好

1. **可访问性**：读屏用户可以按"地标"（landmark）跳转——直接跳到 nav、跳到 main。
2. **SEO**：搜索引擎更容易理解页面结构，判断哪些内容是主体、哪些是导航。
3. **可维护性**：半年后回来看代码，`<main>` 一眼就知道是主内容区，`.main` 这个 class 名字每个人可能起得不一样。

## 小结

- header、nav、main、section、article、footer 各有明确语义。
- main 每页只能有一个，header/footer 可以多处使用。
- 能独立存在的内容用 article，主题区块用 section，无主题的容器才用 div。
- 语义化提升可访问性、SEO 和代码可读性。

## 随堂练习

```quiz
type: html
q: 写一个 main，里面放一个 section，section 里放一个 article，article 里放一个 h2（内容"我的项目"）和一个 p（内容"介绍"）。
starter: |
  <main>
  </main>
checks:
- document.querySelectorAll('main').length === 1
- document.querySelector('main > section') !== null
- document.querySelector('section > article') !== null
- document.querySelector('article > h2') !== null
- document.querySelector('article > h2').textContent.trim() === '我的项目'
hint: main 直接包含 section，section 直接包含 article，article 内含 h2 与 p。
explain: 语义化结构要求三层嵌套关系正确，内容在对应标签内。
```
