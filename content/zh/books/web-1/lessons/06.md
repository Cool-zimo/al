# 三种写 CSS 的方式

> 这一节解决"CSS 写在哪儿"的问题。三种方式都能生效，但维护成本差得远。

## 方式一：内联样式

```html
<p style="color: red; font-size: 16px;">一段红色文字</p>
```

直接写在标签的 `style` 属性里。优先级最高，能盖掉其他方式。但问题也最明显：样式和标签绑死了，想改十个地方就得改十处。

## 方式二：style 标签（内部样式表）

```html
<head>
  <style>
    p {
      color: #333;
      line-height: 1.6;
    }
    .intro {
      font-size: 18px;
    }
  </style>
</head>
```

写在 `<head>` 里的 `<style>` 中。一次可以定义很多规则，对单个页面够用。但如果站里有二十个页面，想统一改标题颜色，得打开二十个文件改。

## 方式三：外链样式表

```html
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

另建一个 `style.css` 文件：

```css
body {
  font-family: "PingFang SC", sans-serif;
  color: #333;
}
h1 {
  color: #2c7a7b;
}
```

这是**推荐**的方式。原因：

1. **一处修改，全站生效**。改一个文件，所有页面一起更新。
2. **缓存**。浏览器下载一次 `style.css` 后会缓存，之后访问其他页面不用再下载，加载更快。
3. **结构与样式分离**。HTML 管结构，CSS 管样式，各司其职，代码更好读。

张三做简历页，把所有样式写进 `style.css`，后来想换个主色调，只改一行就全站更新了。如果他当初写在 style 标签里，就得逐文件找。

## 三种方式的优先级

当三种方式同时作用于同一个元素时，**越具体、越靠近元素的胜出**：

内联 `style` > 内部 `<style>` ≈ 外链 `<link>` > 浏览器默认样式

后两者的优先级取决于它们在 HTML 里的先后顺序：后出现的覆盖先出现的。

翻车现场一：用内联样式"快速改一下"。

```html
<h1 style="color: red;">标题</h1>
<h1 style="color: red;">副标题</h1>
<h1 style="color: red;">又一个</h1>
```

后果：三个 h1 都红了。后来张三想改成青色，得改三处。如果当初写 `.title { color: red; }` 再给三个 h1 加 `class="title"`，改一处就够了。

翻车现场二：外链路径写错。

```html
<link rel="stylesheet" href="css/style.css">
```

后果：文件实际在 `styles/main.css`，路径错了，样式完全不生效，页面变成"裸奔"的默认样式。打开浏览器开发者工具的 Network 面板，会看到这个 CSS 文件 404。

## 第一个样式

```css
h1 {
  color: #2c7a7b;
  font-size: 32px;
}
```

这个结构叫**规则**：`h1` 是选择器（选哪些元素），大括号里是**声明块**，每个声明是"属性: 值"。

## 小结

- 三种方式：内联、内部、外链，外链最推荐。
- 外链样式表的优势：一处修改全站生效、可被缓存、结构与样式分离。
- 优先级：内联 > 内部 ≈ 外链 > 浏览器默认。
- 选择器 + 声明块构成一条 CSS 规则。

## 随堂练习

```quiz
type: css
q: 让页面里所有 p 的文字颜色变成深灰色 rgb(51, 51, 51)。
html: |
  <p>第一段</p>
  <p>第二段</p>
starter: |
  p {
  }
checks:
- getComputedStyle(document.querySelectorAll('p')[0]).color === 'rgb(51, 51, 51)'
- getComputedStyle(document.querySelectorAll('p')[1]).color === 'rgb(51, 51, 51)'
hint: 用 color 属性，值写成 rgb 形式。
explain: 标签选择器 p 选中所有段落，color 设置文字颜色。
```
