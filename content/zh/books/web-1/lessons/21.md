# 为什么要有响应式

> 这一节解决"同一份代码怎么在手机和电脑上都好看"的问题。响应式不是加分项，而是 2026 年的基本要求——手机流量早就是主流。

## 一个现实问题

你写了一个网页，在电脑上打开，三栏布局，完美。用手机打开，发现字小得看不清，内容横向溢出，要左右拖动才能看完一行。

这不是用户的问题，是你的代码问题。

```html
<div class="container">
  <aside class="sidebar">侧边栏</aside>
  <main class="content">主内容</main>
  <aside class="ads">广告</aside>
</div>
```

```css
.container { width: 1200px; }
.sidebar { width: 200px; float: left; }
.content { width: 800px; float: left; }
.ads { width: 200px; float: left; }
```

这段 CSS 在 1200px 以上的屏幕没问题。但在 375px 宽的 iPhone 上，`.container` 的 1200px 远超屏幕，整个页面横向溢出，用户必须左右滑动。

## 响应式的核心思想

**一套代码，多种呈现。** 不是写两个网站（手机版 + 电脑版），而是让同一份 HTML/CSS 根据屏幕宽度自动调整布局。

```css
/* 默认：手机优先 */
.container {
  display: flex;
  flex-direction: column;
}

/* 屏幕变宽后：改成三栏 */
@media (min-width: 768px) {
  .container {
    flex-direction: row;
  }
}
```

手机上 `.container` 纵向排列，768px 以上的屏幕变成横向三栏。同一个 HTML，两种布局。

## 三个关键要素

响应式设计依赖三件事：

1. **流式布局**：用百分比、flex、grid 代替固定像素。
2. **弹性图片**：图片随容器缩放，不溢出。
3. **媒体查询**：根据断点切换样式。

翻车现场一：只写固定宽度，不做任何适配。

```css
.page {
  width: 1000px;
}
```

后果：手机上横向溢出，用户要左右滑动。这在 2010 年之前是常态，现在会被用户直接关掉。

翻车现场二：给手机写死了一套尺寸，却忘了电脑上会拉伸变形。

```css
.card {
  width: 90vw;  /* 手机上 90% 视口宽度，大约 340px */
  font-size: 14px;
}
```

后果：在 27 寸显示器上，card 宽度接近 2400px，一行文字横跨大半个屏幕，阅读体验极差。

## 手机优先 vs 桌面优先

有两种思路：

**手机优先（推荐）**：先写手机样式（默认），再用 `min-width` 媒体查询逐步增强。

```css
.card {
  width: 100%;
  padding: 12px;
}
@media (min-width: 768px) {
  .card {
    width: 50%;
    padding: 24px;
  }
}
```

**桌面优先**：先写桌面样式，再用 `max-width` 逐步缩减。

```css
.card {
  width: 33.33%;
  float: left;
}
@media (max-width: 767px) {
  .card {
    width: 100%;
    float: none;
  }
}
```

手机优先更符合渐进增强的理念，也是目前的主流做法。

## 小结

- 响应式 = 同一份代码在不同屏幕上呈现不同效果。
- 三大要素：流式布局、弹性图片、媒体查询。
- 手机优先是推荐策略，用 min-width 逐步增强。
- 写死固定宽度是响应式的最大敌人。
