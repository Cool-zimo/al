# concat：把两张表上下拼起来

> merge 负责"左右拼"，concat 负责"上下拼"。先把这件事搞清，后面才不会用错工具。

## 从一个场景开始

张三负责北京分公司的销售记录，李四负责上海分公司。月底要把两份数据合成一张总表：

```python
import pandas as pd

bj = pd.DataFrame({
    '日期': ['2026-09-01', '2026-09-02'],
    '城市': ['北京', '北京'],
    '销售额': [1200, 1500]
})

sh = pd.DataFrame({
    '日期': ['2026-09-01', '2026-09-02'],
    '城市': ['上海', '上海'],
    '销售额': [900, 2100]
})
```

两张表**列名完全一样**，只是行不同。这种"上下叠"的操作，用 `concat`：

```python
total = pd.concat([bj, sh])
print(total)
```

```
         日期  城市   销售额
0  2026-09-01  北京  1200
1  2026-09-02  北京  1500
0  2026-09-01  上海   900
1  2026-09-02  上海  2100
```

**四行**，正是 2 + 2。这就是 concat 的本事：只管把行摞起来。

## 语法：传一个列表

```python
pd.concat([表1, 表2, 表3])
```

**关键：第一个参数是列表**，不是两个并列的位置参数。

```python
# WRONG
pd.concat(bj, sh)
```

```
TypeError: concat() got multiple values for argument 'objs'
```

## axis 决定方向

```python
df1 = pd.DataFrame({'A': [1, 2], 'B': [3, 4]})
df2 = pd.DataFrame({'A': [5, 6], 'C': [7, 8]})
```

**默认 `axis=0`，纵向堆叠**：

```python
print(pd.concat([df1, df2]))
```

```
   A    B    C
0  1  3.0  NaN
1  2  4.0  NaN
0  5  NaN  7.0
1  6  NaN  8.0
```

两张表没有共同列名时会补 NaN。**`axis=1` 变成横向对齐（按索引对齐）**：

```python
print(pd.concat([df1, df2], axis=1))
```

```
   A  B  A  C
0  1  3  5  7
1  2  4  6  8
```

列重复也没关系，pandas 不会帮你改名——**这正是 merge 的地盘，不要拿 concat 硬凑**。

## ignore_index 让索引连续

上面纵向拼接的结果索引是 `0,1,0,1`，看起来很怪。加 `ignore_index=True`：

```python
print(pd.concat([bj, sh], ignore_index=True))
```

```
         日期  城市   销售额
0  2026-09-01  北京  1200
1  2026-09-02  北京  1500
2  2026-09-01  上海   900
3  2026-09-02  上海  2100
```

**索引从 0 重新编号**。后续要按位置取行时这个参数很实用。

## 键不在同一张表？用 keys 标记来源

```python
g = pd.concat([bj, sh], keys=['北京', '上海'])
print(g)
```

```
            日期  城市   销售额
北京 0  2026-09-01  北京  1200
    1  2026-09-02  北京  1500
上海 0  2026-09-01  上海   900
    1  2026-09-02  上海  2100
```

结果变成**两层索引（MultiIndex）**，第一层是来源标记。想知道哪些行来自北京：`g.loc['北京']`。

**这是"保留了出处"的拼接**——做审计、做溯源时比 ignore_index 更有用。

## append 已弃用，别再用了

老教程里常见的 `df1.append(df2)` 在 pandas 2.0 里已经彻底移除：

```python
# WRONG
total = bj.append(sh)
```

```
AttributeError: 'DataFrame' object has no attribute 'append'
```

**现在统一用 `pd.concat([df1, df2])`**。

## 翻车现场：列数不一致时 NaN 悄无声息

```python
# 张三的表多加了一列"渠道"
bj2 = pd.DataFrame({
    '日期': ['2026-09-01'],
    '城市': ['北京'],
    '销售额': [1200],
    '渠道': ['线上']
})

print(pd.concat([bj2, sh], ignore_index=True))
```

```
         日期  城市   销售额   渠道
0  2026-09-01  北京  1200.0   线上
1  2026-09-01  上海   900.0  NaN
2  2026-09-02  上海  2100.0  NaN
```

**没有报错，但上海的"渠道"全是 NaN**。这类问题最危险：代码跑通了，结论却歪了。拼接前务必 `print(df.columns)` 对一下列名。

## 翻车现场：axis=1 时索引对不齐

```python
a = pd.DataFrame({'销售额': [100, 200]}, index=['北京', '上海'])
b = pd.DataFrame({'成本': [60, 120]}, index=['上海', '广州'])

print(pd.concat([a, b], axis=1))
```

```
     销售额   成本
北京  100.0   NaN
上海  200.0  60.0
广州    NaN  120.0
```

**两边索引没有交集的部分都变成 NaN**。这不是 bug，是 concat 的"按索引对齐"机制。真要左右拼，用 merge。

## 小结

- **concat 干一件事：把多张表摞起来**，默认纵向 `axis=0`
- **第一个参数必须是列表**：`pd.concat([a, b])`
- **`ignore_index=True`** 让索引连续；**`keys=[...]`** 保留来源标记
- **列名不一致不报错**，缺失处补 NaN，务必先对列名
- **`append` 已弃用**，统一用 concat
