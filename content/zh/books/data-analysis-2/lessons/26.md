# 时间序列基础：从字符串到 DatetimeIndex

> 把"2026-09-01"存成字符串，就只能排序、不能按周聚合。转成时间类型后，pandas 的时间魔法才真正生效。

## 为什么必须转成时间类型

```python
import pandas as pd

df = pd.DataFrame({
    '日期': ['2026-09-01', '2026-09-02', '2026-09-03'],
    '销售额': [1200, 1500, 900]
})

print(df.dtypes)
```

```
日期    object
销售额     int64
dtype: object
```

**日期是 object（字符串）**。你没法按"每周""每月"聚合，也没法算出"这是第几周"。

## pd.to_datetime：转换入口

```python
df['日期'] = pd.to_datetime(df['日期'])
print(df.dtypes)
```

```
日期    datetime64[ns]
销售额             int64
dtype: object
```

**`datetime64[ns]` 才是真正的时间类型**。

支持多种格式，pandas 能自动识别：

```python
print(pd.to_datetime(['2026/9/1', '20260902', 'Sep-03-2026']))
```

```
DatetimeIndex(['2026-09-01', '2026-09-02', '2026-09-03'], dtype='datetime64[ns]', freq=None)
```

**混着写也能识别**。但真实项目里格式统一更稳妥——依赖自动推断迟早踩坑。

## 转失败怎么办：errors 参数

```python
# WRONG
pd.to_datetime(['2026-09-01', '不是日期', '2026-09-03'])
```

```
ParserError: Unknown string format
```

**一个脏数据就让整行报错**。加 `errors='coerce'` 把解析不了的变成 NaT：

```python
s = pd.to_datetime(['2026-09-01', '不是日期', '2026-09-03'], errors='coerce')
print(s)
```

```
DatetimeIndex(['2026-09-01', 'NaT', '2026-09-03'], dtype='datetime64[ns]', freq=None)
```

**NaT 是时间版的 NaN**，可以接着用 `isna()` 筛掉。

## 设为索引：时间切片的前提

```python
df['日期'] = pd.to_datetime(df['日期'])
df = df.set_index('日期')
print(df.index)
```

```
DatetimeIndex(['2026-09-01', '2026-09-02', '2026-09-03'], dtype='datetime64[ns]', name='日期', freq=None)
```

**索引变成 DatetimeIndex 后，切片才按时间语义工作**。

## 字符串切片：为什么能用

```python
df.loc['2026-09-02']
```

```
销售额    1500
Name: 2026-09-02 00:00:00, dtype: int64
```

**用字符串就能取到具体某一天**——因为索引是 DatetimeIndex，pandas 会帮你解析。

取一段时间：

```python
print(df.loc['2026-09-01':'2026-09-02'])
```

```
            销售额
日期
2026-09-01  1200
2026-09-02  1500
```

**支持"年""年-月"这样的部分字符串**：

```python
# 取 9 月整月
print(df.loc['2026-09'])
```

## dt 访问器：从时间列里拆字段

```python
df2 = pd.DataFrame({
    '时间': pd.to_datetime(['2026-09-01 10:30', '2026-12-25 18:00'])
})

print(df2['时间'].dt.year)      # 2026, 2026
print(df2['时间'].dt.month)     # 9, 12
print(df2['时间'].dt.day)       # 1, 25
print(df2['时间'].dt.hour)      # 10, 18
print(df2['时间'].dt.dayofweek) # 1(周二), 4(周五)
```

**`dt` 访问器把时间拆成年、月、日、时、星期几**。这是按"季度""星期"分组的前提。

```python
df2['季度'] = df2['时间'].dt.quarter
print(df2['季度'])   # 0    3, 1    4
```

## 翻车现场：时区问题

```python
a = pd.Timestamp('2026-09-01 08:00')
b = pd.Timestamp('2026-09-01 08:00', tz='Asia/Shanghai')
print(a == b)
```

```
False
```

**一个有时区、一个没有，永远不等**。跨国业务里这是高频坑。

统一处理：

```python
print(a.tz_localize('Asia/Shanghai') == b)   # True
```

## 翻车现场：转成日期后 dtype 没变

```python
df3 = pd.DataFrame({'日期': ['2026-09-01']})
df3['日期'].astype(str)   # 这是错的思路
```

**以为转了，其实没转**。检查 `dtypes` 是唯一可靠的办法：

```python
df3['日期'] = pd.to_datetime(df3['日期'])
print(df3['日期'].dtype)   # datetime64[ns]
```

## 小结

- **`pd.to_datetime()`** 把字符串列变成时间类型
- **解析失败用 `errors='coerce'`** 转成 NaT，别让脏数据打断流程
- **设为索引后才能用字符串切片**
- **`dt.year / month / day / hour`** 拆出时间字段
- **时区要统一**，tz-aware 与 naive 永远不等
