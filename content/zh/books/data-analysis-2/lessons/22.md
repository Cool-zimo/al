# merge：左右拼表的四种方式

> 真实数据从来不在一张表里。员工信息在 A 表、工资在 B 表、部门在 C 表——merge 就是把这些表按"键"拼起来的工具。

## 从一个场景开始

员工表 `emp` 只有姓名和部门号，部门表 `dept` 才有部门名。要得到"张三→技术部"：

```python
import pandas as pd

emp = pd.DataFrame({
    '姓名': ['张三', '李四', '王五'],
    '部门号': [10, 20, 10]
})

dept = pd.DataFrame({
    '部门号': [10, 20, 30],
    '部门名': ['技术部', '市场部', '财务部']
})
```

```python
result = emp.merge(dept, on='部门号')
print(result)
```

```
   姓名  部门号  部门名
0  张三   10  技术部
1  王五   10  技术部
2  李四   20  市场部
```

**两表按"部门号"对齐，部门名被带过来了**。这就是 merge 的本质：按键匹配。

## 语法

```python
左表.merge(右表, on='键', how='连接方式')
```

三个要素：**左表、右表、用哪个键连**。

## 四种连接方式

| how | 含义 |
|---|---|
| `inner` | 只保留两边都有的键（默认） |
| `left` | 保留左表全部键，右表没有就补 NaN |
| `right` | 保留右表全部键 |
| `outer` | 两边所有键都保留 |

用具体数据看区别：

```python
left = pd.DataFrame({'k': ['a', 'b', 'c'], 'v': [1, 2, 3]})
right = pd.DataFrame({'k': ['b', 'c', 'd'], 'w': [4, 5, 6]})
```

```python
print(left.merge(right, on='k', how='inner'))
```

```
   k  v  w
0  b  2  4
1  c  3  5
```

**只有 b、c 两表都有**，a 和 d 都被丢掉了。这是默认值。

```python
print(left.merge(right, on='k', how='left'))
```

```
   k  v    w
0  a  1  NaN
1  b  2  4.0
2  c  3  5.0
```

**左表 a、b、c 全留**，a 在右表没有匹配，w 列补 NaN。

```python
print(left.merge(right, on='k', how='outer'))
```

```
   k    v    w
0  a  1.0  NaN
1  b  2.0  4.0
2  c  3.0  5.0
3  d  NaN  6.0
```

**全部键都出现**，缺失处补 NaN。

## 键名不同：left_on / right_on

```python
emp2 = pd.DataFrame({'姓名': ['张三', '李四'], 'dept_id': [10, 20]})
dept2 = pd.DataFrame({'部门号': [10, 20], '部门名': ['技术部', '市场部']})
```

键名不一样时不能写 `on=`，要分开指定：

```python
print(emp2.merge(dept2, left_on='dept_id', right_on='部门号'))
```

```
   姓名  dept_id  部门号  部门名
0  张三       10    10  技术部
1  李四       20    20  市场部
```

**结果里会同时出现 `dept_id` 和 `部门号` 两列**。通常用完就删一列：

```python
r = emp2.merge(dept2, left_on='dept_id', right_on='部门号').drop(columns='部门号')
```

## 翻车现场：一对多连接导致行数变多

```python
订单 = pd.DataFrame({'订单号': ['A001', 'A002'], '客户': ['张三', '李四']})
明细 = pd.DataFrame({'订单号': ['A001', 'A001', 'A002'], '商品': ['键盘', '鼠标', '显示器']})
```

一个订单对应多行明细，是"一对多"关系：

```python
print(订单.merge(明细, on='订单号'))
```

```
   订单号  客户  商品
0  A001  张三  键盘
1  A001  张三  鼠标
2  A002  李四  显示器
```

**3 行！** 左表明明只有 2 行，结果变 3 行。张三出现了两次，因为他的订单有两行明细。

**这不是 bug，是 merge 的正确行为**——每一对匹配都会生成一行。做聚合前如果没意识到这点，求和就会翻倍。务必先 `len()` 看一眼。

## 翻车现场：重复键让行数爆炸

```python
a = pd.DataFrame({'k': ['x', 'x'], 'v': [1, 2]})
b = pd.DataFrame({'k': ['x', 'x'], 'w': [3, 4]})

print(a.merge(b, on='k'))
```

```
   k  v  w
0  x  1  3
1  x  1  4
2  x  2  3
3  x  2  4
```

**2 行 × 2 行 = 4 行，笛卡尔积**。键不是唯一时，merge 会把所有组合都展开。

**用 `indicator=True` 能看清每行是怎么来的**：

```python
r = a.merge(b, on='k', indicator=True)
print(r['_merge'].value_counts())
```

```
   both          4
   left_only     0
   right_only    0
   Name: _merge, dtype: int64
```

新增的 `_merge` 列标着 `left_only` / `right_only` / `both`。**排查连接问题时先看这一列**，一眼就能看出哪些行没匹配上。

## 小结

- **merge 按键匹配**：`左.merge(右, on=键, how=方式)`
- **inner 只留共有键，left/right 保单边，outer 全保留**
- **键名不同用 `left_on` / `right_on`**，结果会留两列键
- **一对多会让行数变多**，先 len() 再聚合
- **重复键产生笛卡尔积**，用 `indicator=True` 排查
