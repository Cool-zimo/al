# rolling：滚动窗口与移动平均

> 原始数据抖得太厉害，看不出趋势。滚动窗口能把"最近 N 天"的数据抹平——这就是移动平均的本质。

## 七天的移动平均

```python
import pandas as pd

idx = pd.date_range('2026-09-01', periods=10, freq='D')
销售额 = pd.Series([100, 120, 90, 130, 110, 150, 140, 160, 170, 180], index=idx)
```

每天的数值起伏很大。算"7 天均值"：

```python
ma7 = 销售额.rolling(7).mean()
print(ma7)
```

```
2026-09-01      NaN
2026-09-02      NaN
2026-09-03      NaN
2026-09-04      NaN
2026-09-05      NaN
2026-09-06      NaN
2026-09-07    111.428571
2026-09-08    128.571429
2026-09-09    135.714286
2026-09-10    145.714286
Freq: D, dtype: float64
```

**前 6 个值是 NaN**，因为凑不够 7 个数据点。从第 7 天开始才有结果。

## 语法

```python
series.rolling(窗口大小).聚合函数()
```

**窗口大小是"包含当前行在内的前 N 行"**。

## min_periods：放宽要求

```python
ma3 = 销售额.rolling(3, min_periods=1).mean()
print(ma3)
```

```
2026-09-01    100.0
2026-09-02    110.0
2026-09-03    103.333333
2026-09-04    113.333333
2026-09-05    110.0
2026-09-06    130.0
2026-09-07    133.333333
2026-09-08    150.0
2026-09-09    156.666667
2026-09-10    169.0
Freq: D, dtype: float64
```

**`min_periods=1` 表示"哪怕只有 1 个数据也算"**。第 1 天的值就是它自己。

**对比默认（min_periods=窗口大小）**：前 6 个 NaN vs 全程有值。看趋势时常用 min_periods=1，做严格分析时保留默认。

## 翻车现场：窗口算出来全是 NaN

```python
短 = pd.Series([10, 20, 30])
print(短.rolling(7).mean())
```

```
0   NaN
1   NaN
2   NaN
dtype: float64
```

**窗口 7，数据只有 3 行，永远凑不够，全是 NaN**。这是最常见的"算出来是空的"原因。

**用 `min_periods=1` 或缩小窗口**：

```python
print(短.rolling(7, min_periods=1).mean())
```

```
0    10.0
1    15.0
2    20.0
dtype: float64
```

## 时间窗口：按"几天"而不是按"几行"

```python
idx2 = pd.to_datetime(['2026-09-01', '2026-09-02', '2026-09-05', '2026-09-10'])
s2 = pd.Series([10, 20, 30, 40], index=idx2)
```

数据是**不规则间隔**（缺了几天）。用 `window='3D'` 按"3 天内"聚合：

```python
print(s2.rolling('3D').mean())
```

```
2026-09-01    10.0
2026-09-02    15.0
2026-09-05    30.0
2026-09-10    40.0
```

**按日历时间算窗口**，而不是按行数。要求索引是 DatetimeIndex。

## 其他聚合

```python
r = 销售额.rolling(3)
print(r.sum())     # 3 天累计
print(r.max())     # 3 天最高
print(r.std())     # 3 天波动
print(r.count())   # 窗口内有效个数
```

## expanding：从起点开始的累积窗口

```python
print(销售额.expanding().mean())
```

```
2026-09-01    100.0
2026-09-02    110.0
2026-09-03    103.333333
2026-09-04    110.0
2026-09-05    110.0
...
```

**expanding 窗口从第一行开始，越往后越大**。等价于 `cumsum()/cumcount()`，但能接任意聚合。

**对比 rolling 与 expanding**：

| | 窗口大小 | 典型用途 |
|---|---|---|
| `rolling(7)` | 固定 7 行 | 7 天移动平均 |
| `expanding()` | 从起点累积 | 历史累计均值 |

## 翻车现场：rolling 后忘了跟聚合函数

```python
# WRONG
销售额.rolling(7)
```

```
Rolling 对象（不是结果！）
```

**rolling 本身只是定义窗口**，必须接 `.mean()` / `.sum()` 等才出结果。和 groupby、resample 一样是"两段式"。

## 翻车现场：移动平均"偷看未来"

```python
# 默认是"回望"（center=False）
回望 = 销售额.rolling(3, min_periods=1).mean()
print(回望.iloc[0])   # 100.0，只用到了第 0 天自己
```

**默认窗口在"当前行及之前"**，这是做预测时的正确行为（不会用到未来数据）。

如果想要"以当前行为中心"的对称窗口：

```python
居中 = 销售额.rolling(3, center=True, min_periods=1).mean()
print(居中)
```

**`center=True` 让窗口以当前行为中心**。做平滑展示图时用得多，做时序预测时千万别用——那等于用未来数据预测当前。

## 小结

- **`rolling(N)` 是"包含当前行的往前 N 行"窗口**，要跟聚合函数
- **前 N-1 行默认是 NaN**，用 `min_periods=1` 可放宽
- **`window='3D'` 按日历时间开窗**，要求 DatetimeIndex
- **expanding 从起点累积**，窗口越来越大
- **`center=True` 会用到未来数据**，预测场景要避开
