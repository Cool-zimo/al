# 实战：一份完整的数据分析报告

> 前面五章的工具你都见过了。这一课把它们串成一条流水线——从脏数据到一张结论图，中间不跳过任何环节。

## 要回答的问题

张三在北京开了三家奶茶店（中关村店、国贸店、望京店），2026 年 1-9 月的销售数据散落在三份表里，还有一份 9 月促销活动表。他想回答：

1. 哪家店卖得最好？月均销售额多少？
2. 整体增长还是下滑？环比、同比如何？
3. 哪个月做活动最划算？活动期的提升能不能算出来？

这就是一份真实报告该做的事——**不是跑几个函数，而是从问题出发，一步步推到结论**。

## 第一步：构造数据

实战的第一步是"有数据可跑"。我们用确定性的方式造一份"脏数据"，把真实数据里常见的问题都埋进去。

```python
import pandas as pd
import numpy as np

# 三家门店 2026-01 ~ 2026-09 的日销售记录
门店 = ['中关村店', '国贸店', '望京店']
记录 = []
for 店 in 门店:
    for 月 in range(1, 10):
        天数 = 28
        for d in range(1, 天数 + 1):
            日期 = pd.Timestamp(f'2026-{月:02d}-{d:02d}')
            销售额 = round(2000 + hash((店, 月, d)) % 3000, 2)
            记录.append({'门店': 店, '日期': 日期, '销售额': 销售额})

销售 = pd.DataFrame(记录)
print(销售.shape)        # (756, 3)
print(销售.head())
```

**756 行 = 3 家店 × 9 个月 × 28 天**。注意我们故意没有用 30/31 天，让数据天然"不完整"，后面再看怎么处理。

再造一份促销表，只有 9 月的活动记录：

```python
促销 = pd.DataFrame({
    '门店': ['中关村店', '国贸店', '望京店', '中关村店'],
    '月份': ['2026-09', '2026-09', '2026-09', '2026-08'],
    '活动名': ['开学季', '白领节', '社区团购', '暑期返场'],
    '投入费用': [3000, 5000, 2000, 1500]
})
print(促销)
```

**两份表的粒度不一样**：销售表是"门店 × 日期"，促销表是"门店 × 月份"。这意味着连接后必然是一对多。

## 第二步：清洗（第 3 章复习）

假设销售表里混进了几个脏值。真实场景下你会遇到：

```python
# 模拟几个脏值
销售.loc[0, '销售额'] = '缺失'
销售.loc[5, '销售额'] = None

print(销售['销售额'].dtype)   # object（被字符串污染）
```

**dtype 变成 object 是脏数据最典型的信号**。三步清理：

```python
销售['销售额'] = pd.to_numeric(销售['销售额'], errors='coerce')
销售 = 销售.dropna(subset=['销售额'])
销售['月份'] = 销售['日期'].dt.to_period('M')
销售 = 销售.sort_values(['门店', '日期']).reset_index(drop=True)

print(销售.dtypes)
print(销售.shape)
```

| 操作 | 作用 |
|---|---|
| `to_numeric(errors='coerce')` | 非数字转 NaN |
| `dropna(subset=[...])` | 丢掉关键列缺失的行 |
| `dt.to_period('M')` | 提取月份，用于月度汇总 |
| `sort_values + reset_index` | 排序并重置索引 |

**清理后数据干净、有序、带月份字段**，后续所有操作才站得住脚。

## 第三步：连接（第 5 章复习）

把促销信息合到销售表上，用 merge：

```python
促销['月份'] = pd.to_datetime(促销['月份']).dt.to_period('M')
merged = 销售.merge(促销, on=['门店', '月份'], how='left')
print(merged.shape)          # (756, 5)
print(merged['活动名'].notna().sum())   # 只有 9 月的记录匹配上
```

**左连接保证销售表的每一行都留下来**，促销信息匹配不上的填 NaN。这是最安全的连接方式——不会丢原始数据。

注意这里**没有一对多膨胀**：因为销售表的最小粒度是"天"，促销表是"月"，按"门店+月份"合并时，一个月里所有天都对应同一条促销记录，行数不变（756）。

如果反过来按"门店"单键合并，9 月促销表有 4 条（中关村出现两次），就会产生一对多膨胀。

## 第四步：分组聚合（第 4 章复习）

```python
月度 = (销售.groupby(['门店', '月份'], observed=True)['销售额']
             .agg(['sum', 'mean', 'count'])
             .round(2))
月度.columns = ['销售额合计', '日均值', '天数']
print(月度)
```

| 门店 | 月份 | 销售额合计 | 日均值 | 天数 |
|---|---|---|---|---|
| 中关村店 | 2026-01 | 61384.31 | 2192.30 | 28 |
| 国贸店 | 2026-01 | 71884.04 | 2567.29 | 28 |
| 望京店 | 2026-01 | 61086.68 | 2181.67 | 28 |

**agg 一次出多个指标**，比分三次 groupby 快得多。这也是真实报告的标准写法。

要回答"哪家店卖得最好"：

```python
总榜 = (销售.groupby('门店')['销售额'].sum()
             .sort_values(ascending=False))
print(总榜)
```

## 第五步：时间序列（第 6 章复习）

把所有门店按天汇总，看整体走势：

```python
日汇总 = (销售.groupby('日期')['销售额'].sum()
               .asfreq('D'))    # 保证日频，缺的日期留空

日均值7 = 日汇总.rolling(7, min_periods=1).mean()
```

**`asfreq('D')` 补齐缺失日期**，否则 resample 可能跳过没有数据的那天。`rolling(7)` 抹平日内波动。

算环比和同比（第 29 课）：

```python
日汇总['环比'] = 日汇总.pct_change()
日汇总['同比'] = 日汇总 / 日汇总.shift(28) - 1   # 28 天前（同一批日期的上月同日）
```

**这里 shift(28) 是因为我们造的数据每月都是 28 天**，真实数据要用 `DateOffset(months=1)` 按日历对齐。

## 第六步：得出结论

```python
# 活动期（9 月）vs 非活动期（1-8 月）的对比
非活动 = 销售[销售['月份'].astype(str) < '2026-09']['销售额'].mean()
活动期 = 销售[销售['月份'].astype(str) == '2026-09']['销售额'].mean()
提升 = (活动期 / 非活动 - 1) * 100

print(f'非活动期日均：{非活动:.0f} 元')
print(f'活动期日均：{活动期:.0f} 元')
print(f'活动带来提升：{提升:.1f}%')
```

**结论不是"算出来了"，而是"说清楚了"**：把对比的口径、基期、幅度写明白。这才是报告真正交付的东西。

## 完整流水线一览

```python
def 生成报告(销售表, 促销表):
    # 1. 清洗
    销售表['销售额'] = pd.to_numeric(销售表['销售额'], errors='coerce')
    销售表 = 销售表.dropna(subset=['销售额']).copy()
    销售表['月份'] = 销售表['日期'].dt.to_period('M')

    # 2. 连接
    促销表 = 促销表.copy()
    促销表['月份'] = pd.to_datetime(促销表['月份']).dt.to_period('M')
    合并 = 销售表.merge(促销表, on=['门店', '月份'], how='left')

    # 3. 聚合
    月度 = 销售表.groupby(['门店', '月份'], observed=True)['销售额'].sum()

    # 4. 时序
    日 = 销售表.groupby('日期')['销售额'].sum().asfreq('D')
    日_ma7 = 日.rolling(7, min_periods=1).mean()

    # 5. 结论
    结果 = {
        '门店总榜': 销售表.groupby('门店')['销售额'].sum()
                        .sort_values(ascending=False).to_dict(),
        '月度走势_7日均': 日_ma7.round(0).to_dict(),
        '促销覆盖天数': int(合并['活动名'].notna().sum()),
    }
    return 结果
```

**五个环节一环扣一环**：脏数据进不来第 2 步，连接不上第 3 步就无从聚合，缺日期第 4 步就会错位。**任何一步偷懒，后面全错**。

## 翻车现场：merge 键的类型不一致，匹配结果为空

```python
# WRONG
销售表['月份'] = '2026-01'          # 字符串
促销表['月份'] = pd.to_datetime('2026-01')   # Timestamp
合并 = 销售表.merge(促销表, on='月份')   # 0 行！
print(len(合并))
```

**两边类型不同，pandas 不会自动帮你转**，结果是 0 行空表。连接前务必 `print(df.dtypes)` 确认键的类型一致。

## 翻车现场：先聚合再连接，丢失粒度

```python
# WRONG
月度汇总 = 销售表.groupby(['门店', '月份']).sum().reset_index()
月度汇总.merge(促销表, on='月份')   # 门店信息已丢，只剩月份
```

**先聚合会丢掉行级细节**（比如具体哪天做活动）。正确顺序是：先连接（保留明细），再聚合。需要明细和汇总时，用 `.copy()` 分两条路处理。

## 翻车现场：pct_change 没处理 NaN，报告里出现空值

```python
# WRONG
报告 = 销售表.groupby('日期')['销售额'].sum().pct_change()
print(报告.iloc[0])    # NaN
```

**第一个值是 NaN，直接写进报告会被渲染成空白**。用 `.fillna(0)` 或 `.dropna()` 处理后再输出，并在报告脚注明"首日无环比"。

## 小结

- **真实报告是流水线**：构造 → 清洗 → 连接 → 聚合 → 时序 → 结论，顺序不能乱
- **`errors='coerce'` + `dropna` 是清洗标配**
- **左连接保原始数据，键的类型必须一致**
- **agg 一次出多指标，比多次 groupby 高效**
- **`asfreq('D')` 补日期，`rolling(7)` 看趋势**
- **结论要说清口径、基期、幅度**，数字只是论据
