# shift 与差分：环比、同比与增长率

> 昨天卖了多少？去年今天呢？想知道"变了多少、涨了几个点"，靠的不是重算，而是把数据挪一挪再相减。

## shift：把数据挪一挪

```python
import pandas as pd

idx = pd.date_range('2026-09-01', periods=6, freq='D')
销售额 = pd.Series([100, 120, 90, 130, 110, 150], index=idx)
```

`shift(1)` 把整个序列**往下挪一行**：原来第 2 天的值跑到第 3 天去，最上面空出来的那格填 NaN。

```python
昨天 = 销售额.shift(1)
print(昨天)
```

```
2026-09-01      NaN
2026-09-02    100.0
2026-09-03    120.0
2026-09-04     90.0
2026-09-05    130.0
2026-09-06    110.0
Freq: D, dtype: float64
```

**`shift(1)` 的意思是"取上一行的值"**。所以第 2 行显示 100，就是第 1 天的销售额。

## 环比：今天减昨天

环比 = 今天 - 昨天。用 `销售额 - 销售额.shift(1)`：

```python
环比增减 = 销售额 - 销售额.shift(1)
print(环比增减)
```

```
2026-09-01      NaN
2026-09-02     20.0
2026-09-03    -30.0
2026-09-04     40.0
2026-09-05    -20.0
2026-09-06     40.0
Freq: D, dtype: float64
```

**第 1 天是 NaN**，因为它没有"昨天"可减。第 2 天 +20，说明比昨天多卖了 20。

要算"涨了百分之几"，除以昨天即可：

```python
环比增长率 = 销售额 / 销售额.shift(1) - 1
print(环比增长率)
```

```
2026-09-01         NaN
2026-09-02    0.200000
2026-09-03   -0.250000
2026-09-04    0.444444
2026-09-05   -0.153846
2026-09-06    0.363636
Freq: D, dtype: float64
```

第 2 天 0.2 = 涨了 20%。

## periods 参数：一次挪多行

`shift(1)` 挪一格，`shift(7)` 挪七格——正好是"上周同一天"。

```python
上周 = 销售额.shift(7)
print(上周)
```

```
2026-09-01    NaN
2026-09-02    NaN
2026-09-03    NaN
2026-09-04    NaN
2026-09-05    NaN
2026-09-06    NaN
Freq: D, dtype: float64
```

这里数据只有 6 天，挪 7 格全空。**`periods` 是挪动的行数**，正负决定方向：正数往下挪（取过去），负数往上挪（取未来）。

## diff()：一步到位的差分

`diff()` 等价于 `x - x.shift(1)`，少写一层。

```python
print(销售额.diff())
print(销售额.diff(1))      # 同上
print(销售额.diff(2))      # 隔一行相减：今天 - 前天
```

```
2026-09-01      NaN
2026-09-02     20.0
2026-09-03    -30.0
2026-09-04     40.0
2026-09-05    -20.0
2026-09-06     40.0
Freq: D, dtype: float64
```

`diff(2)` 的结果是 [NaN, NaN, -10, 10, 20, 60]，因为第 3 天用第 1 天来减（120-100=20…实际 90-100=-10）。

## pct_change()：一步到位的增长率

`pct_change()` 等价于 `x / x.shift(1) - 1`。

```python
print(销售额.pct_change())
```

```
2026-09-01         NaN
2026-09-02    0.200000
2026-09-03   -0.250000
2026-09-04    0.444444
2026-09-05   -0.153846
2026-09-06    0.363636
Freq: D, dtype: float64
```

**`diff()` 算绝对差，`pct_change()` 算相对差（百分比）**，两者最常配对使用：一个看金额，一个看幅度。

## 同比：今年 vs 去年今日

数据跨年的时候，环比看昨天，同比看去年同一天。挪动 365 格：

```python
天数 = 365
idx_y = pd.date_range('2025-01-01', periods=400, freq='D')
去年 = pd.Series(range(100, 500), index=idx_y)
今年第1天 = 去年.shift(-365)     # 负数往上挪 = 取未来那一行
```

更稳的写法是**用日期索引自己对齐**，而不是硬挪行数：

```python
s = pd.Series([120, 150, 90, 200],
              index=pd.to_datetime(['2026-01-01','2026-07-01','2027-01-01','2027-07-01']))
去年同天 = s.index - pd.DateOffset(years=1)
同比 = s / s.reindex(去年同天).values - 1
```

**按日期对齐不依赖行数**，闰年、缺日期都不出错。硬挪行数只在同一天不缺数据时才安全。

## 翻车现场：shift 后第一行是 NaN，后面跟着全 NaN

```python
# WRONG
销售 = pd.Series([100, 120, 130])
后一天 = 销售.shift(-1)
结果 = 后一天 / 销售
print(结果)
```

```
0    NaN
1    1.0
2    NaN
dtype: float64
```

最后一行是 NaN（往下挪没数据），**但更隐蔽的是：NaN 参与任何运算都会传染**。如果你接着算 `结果.sum()`，得到 NaN 而不是你以为的 1.0。

**用 `dropna()` 或 `fillna()` 先处理**：

```python
后一天 = 销售.shift(-1).fillna(0)
结果 = 后一天 / 销售
print(结果.sum())   # 1.0
```

或者只保留两边都有值的行：`销售.shift(-1).dropna()`。

## 翻车现场：periods 写反方向，算成"未来增长率"

```python
# WRONG
挪 = 销售额.shift(-1)         # 往上挪 = 取明天的数
增长率 = 销售额 / 挪 - 1       # 用今天除明天
print(增长率)
```

```
2026-09-01   -0.166667
2026-09-02    0.333333
2026-09-03   -0.307692
2026-09-04    0.181818
2026-09-05   -0.266667
2026-09-06         NaN
dtype: float64
```

**正数 shift 才是"取过去"**。写反了不算报错，结果却完全反了——这类 bug 不报错但结论错，最危险。

记忆口诀：**想看"昨天"，用正数（往回看）；想看"明天"，用负数（往前看）**。

## 翻车现场：diff 对字符串列调用

```python
# WRONG
df = pd.DataFrame({'城市': ['北京','上海','广州'], '销量': [100, 200, 150]})
df['销量'].diff()      # OK
df['城市'].diff()      # TypeError
```

```
TypeError: unsupported operand type(s) for -: 'str' and 'str'
```

**`diff()` 和 `pct_change()` 只对数值列有意义**。对字符串、日期列调用会直接报错。日期差用 `dt.days`：

```python
间隔 = (df['日期'] - df['日期'].shift(1)).dt.days
```

## 小结

- **`shift(1)` 取上一行，`shift(-1)` 取下一行**，正数往回看
- **`diff()` = 当前减上一行**，`pct_change()` = 当前除上一行减 1
- **环比看昨天，同比看去年今日**，跨年数据按日期对齐更稳
- **NaN 会传染**，shift 后务必 `dropna()` 或 `fillna()`
- **`periods` 方向写反不报错但结论全反**，一定要复核首末几个值
