## 第一部分 · 选择题

检验这章的概念有没有真正记住。

```quiz
type: choice
q: 下面这段代码的运行结果是什么？
  print("苹果", "香蕉", sep="-")
options:
- 苹果-香蕉
- 苹果 香蕉
- 苹果-香蕉-
- 报错
answer: 0
explain: sep 参数控制"多个内容之间用什么隔开"。这里指定用 -，所以输出 苹果-香蕉。如果不写 sep，默认用空格隔开。
```

```quiz
type: choice
q: 为什么 print(你好) 会报错，而 print("你好") 不会？
options:
- 因为中文不能直接打印
- 因为不加引号时，Python 会把"你好"当成一个变量名去找它，找不到就报 NameError
- 因为 print 函数规定必须加引号
- 因为引号能让文字显示得更清楚
answer: 1
explain: 引号的作用是划界：引号里面是"数据"（纯文字），外面是"代码"（命令或名字）。不加引号，Python 就以为你在说一个叫"你好"的变量。
```

```quiz
type: choice
q: 关于注释，下面哪种做法是「好注释」？
options:
- print("你好")  # 打印"你好"
- # 这里必须用 0.1，因为上游接口只认浮点数
- 每一行代码后面都加一句解释它在干嘛
- 把不想执行的代码删掉，而不是注释掉
answer: 1
explain: 代码本身已经说明了"做了什么"，注释应该补充代码里写不出来的"为什么"。复述代码的注释是废话；而"删掉"是不可逆的，调试时注释掉更好。
```

```quiz
type: choice
q: 看到一段报错，最有效率的阅读顺序是？
options:
- 从上往下逐行读，一个字不能漏
- 先读最后一行（错误类型），再找 line N（出错位置）
- 只看红色的字
- 复制到翻译软件里翻译一遍
answer: 1
explain: 最后一行告诉你"是什么错"，line N 告诉你"在哪一行"。这两条信息组合起来，90% 的报错都能在 30 秒内定位。
```

```quiz
type: choice
q: 代码 print（"你好"） 报错的最可能原因是？
options:
- print 拼错了
- 用了中文的全角括号 （ ） 而不是英文括号 ( )
- 引号用错了
- Python 不支持打印中文
answer: 1
explain: 中文全角括号和英文括号长得极像，但 Python 只认英文的那个。写代码时保持输入法在英文状态，能避开这个几乎人人踩过的坑。
```

## 第二部分 · 算法题

不只是"会用"，还要"想得明白"。这两道题**都由机器判分** —— 一道检查程序输出，一道直接调用你写的函数、比对返回值。

```quiz
type: function
q: 补全 make_card()：把姓名和爱好拼成一行名片文字，用 return 交回来
func: make_card
starter: |
  def make_card(name, hobby):
      # 把 name 和 hobby 拼成 "姓名：xxx · 爱好：xxx" 这样的格式
      # 关键：用 return 把结果交回来，而不是 print 出去
      return ""
cases: |
  "张三", "编程" -> "姓名：张三 · 爱好：编程"
  "李四", "爬山" -> "姓名：李四 · 爱好：爬山"
  "王五", "画画" -> "姓名：王五 · 爱好：画画"
hint: 用 + 把几段文字接起来：return "姓名：" + name + " · 爱好：" + hobby。return 后面不要再加引号。
explain: 这是本测验里唯一一道"真调用你的函数"的题 —— 网页会真的执行 make_card("张三", "编程")，把返回值和预期逐个比对。函数的关键是 return：print 是把内容显示在屏幕上，return 是把结果交给调用者，两者完全不同。
```

```quiz
type: code
q: 找出这段代码的 3 个错误并改对，让它正常打印 4 行
starter: |
  # 这段程序有 3 个错误，逐个找出来
  print("姓名：张三"
  print(爱好：编程)
  # print("城市：杭州"
  print("座右铭：每天进步一点")
tests:
- assert "姓名：张三" in __out
- assert "爱好：编程" in __out
- assert "城市：杭州" in __out
hint: 三个错误分别是：第 2 行少一个右括号、第 3 行"爱好：编程"没加引号、第 4 行整行被注释掉了。
explain: 这三个错误正好对上第一章的三大经典坑：括号没配对（SyntaxError）、字符串没加引号（NameError）、整行被注释掉（代码根本没执行）。能一次全找出来，说明这章是真的吸收了。
```

## 第三部分 · 小项目

把这一章的东西做成一件"拿得出手"的完整作品。

```quiz
type: project
q: 制作一张「我的个人名片」—— 用 print 在屏幕上输出一张有边框的卡片
checklist:
- 至少输出 5 行（含边框）
- 用了 ─ │ ╭ ╮ ╰ ╯ 或 * = - 之类的字符做出边框，卡片有"形状"
- 卡片内容是真实的你自己（昵称、在学什么、一句签名等）
- 每行都从最左边开始，没有多余的缩进（否则会 IndentationError）
- 代码里至少写了 1 行注释，说明你为什么这么排版
- 点过「运行」，确认真的能跑出你想要的图案
hint: 先在纸上画出卡片的样子，再照着用 print 一行一行"画"出来。边框只是字符串，别想复杂了。
explain: 这个项目考察的是"把想法翻译成代码"的完整流程 —— 先在脑子里（或纸上）想清楚成品长什么样，再拆解成一行行的输出。这就是编程的真实工作方式。
```

## 这一章，你学会了什么

- ✅ 编程的本质：把事情拆成**无歧义的有序步骤**
- ✅ Python 是**解释型**语言，需要一个解释器才能跑
- ✅ `print` 的用法：`sep`、`end`、`\n` 转义
- ✅ 引号的作用是**划界**：里面是数据，外面是代码
- ✅ 注释写**"为什么"**，而不是复述"做了什么"
- ✅ 读报错先看**最后一行**，再找**行号**

**下一章**，我们开始讲"数据" —— 程序处理的原料：数字、字符串、布尔值。那才是真正开始有"计算"感觉的地方。
