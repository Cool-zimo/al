# 一直运行：while True 与 break

> 上一课的 `while` 有个前提：**你得提前知道条件什么时候不成立。**
>
> 但有一大类需求根本说不清次数 —— 一个菜单程序，你不知道用户会选几次才退出；一个登录框，你不知道用户会输错几次。
>
> 这类需求的共同点是：**一直运行，直到用户说"够了"。**
>
> 这一课学两个关键字，它们专门解决这件事：`while True` 和 `break`。

## 一、它解决的是什么问题

想想 ATM 机。你插卡、查余额、取钱、再查一次、再取一次…… 机器不会在你操作完一次之后就把卡吐出来。

它做的是：

> **一直显示菜单，直到你点了"退卡"。**

用上一课的知识能写出来吗？很难。因为你没法提前知道用户要操作几次，写不出 `while count <= ?` 里那个问号。

于是一种新写法出现了：**把条件直接写成"永远成立"，然后在想停的地方自己跳出去。**

## 二、while True 长什么样

```python
while True:
    print("程序正在运行")
```

`True` 是一个固定的布尔值，它**永远为真**。所以这个循环的条件永远不会不成立 —— 按上一课的标准看，这就是个死循环。

它确实不会自己停。**但它给了你一个全新的能力：循环体内部的"紧急出口"。**

## 三、break：从循环里跳出去

看一个真正有用的例子 —— 一直问密码，直到输对：

```python
password = "123456"      # 正确的密码
tries = 0

while True:
    guess = "123456"     # 真实场景里这里应该是 input()
    tries = tries + 1

    if guess == password:
        print("密码正确，欢迎回来")
        break           # ← 跳出去

    print("第", tries, "次错误")

print("程序结束")
```

运行：

```
密码正确，欢迎回来
程序结束
```

**`break` 的意思就一个字：停。**

程序执行到 `break`，立刻**跳出整个循环**，直接跳到循环后面那一行继续。

### break 为什么几乎总是和 if 在一起？

注意上面代码的结构：`break` 被包在 `if` 里面。

这不是巧合 —— **`break` 单独出现是没有意义的**。如果每次都 break，循环只跑一轮，那写循环干什么？

所以标准形态永远是：

```python
while True:
    做点什么
    if 某个条件:
        break        # 满足条件才停
```

**"一直做，直到满足某个条件才停。"** 这句话就是 `while True` + `break` 的全部含义。

对比一下两种写法的适用场景：

| 写法 | 适用场景 | 例子 |
|---|---|---|
| `while 条件:` | 一开始就能判断要不要做 | 从 1 数到 100 |
| `while True:` + `break` | 得**先做一次**才知道要不要停 | 猜数字、菜单、登录 |

**判断口诀：需要先做再判断的，用 `while True`。**

猜数字就是典型 —— 你得先让人猜一次，才知道猜没猜中。

## 四、continue：跳过这一轮

`continue` 和 `break` 长得像，但做的事完全不同：

| | 含义 | 之后去哪 |
|---|---|---|
| `break` | 整个循环结束 | 跳到循环**外面** |
| `continue` | **跳过本轮剩下的部分** | 回到循环**开头**，开始下一轮 |

看个例子：打印 1 到 5，但跳过 3。

```python
count = 0

while count < 5:
    count = count + 1

    if count == 3:
        continue          # ← 跳过这一轮剩下的 print

    print(count)
```

运行：

```
1
2
4
5
```

3 不见了。因为它碰到 `continue` 时，**立刻回到循环开头**，后面的 `print` 根本没机会执行。

> ⚠️ 注意上面代码里 `count = count + 1` 被放在了 `continue` **之前**。
> 如果放在后面，`count` 等于 3 时会被 continue 跳过，永远不会 +1 —— **死循环**。
> 这跟上一课"自增不能写进 if 里"是同一个陷阱，只是换了个马甲。

## 五、做一个能一直用的菜单

现在把第 4 章的 `if`、`elif` 和这一课的 `while True`、`break` 组合起来 —— 这是本册到目前为止**最像"真程序"的一段代码**：

```python
running = True

while running:
    print("")
    print("===== 计算器 =====")
    print("1. 加法")
    print("2. 减法")
    print("3. 退出")

    choice = "1"        # 真实场景里是 input()

    if choice == "1":
        print("10 + 5 =", 10 + 5)
    elif choice == "2":
        print("10 - 5 =", 10 - 5)
    elif choice == "3":
        print("再见")
        running = False    # ← 让循环的条件不成立
    else:
        print("没有这个选项")
```

运行会看到菜单，选 1 出结果，然后**菜单又出现一次** —— 这正是"工具"和"脚本"的区别。

注意这里用了另一种停止方式：**改一个标志变量**（`running = False`），而不是 `break`。

两种都能停，区别是：

- `break` —— 立刻跳走，后面的代码不执行
- `running = False` —— 条件变假，但**本轮还会继续跑完**，下一轮才停

初学者推荐先用 `break`，更直观。等你写更复杂的程序，标志变量会更灵活。

## 六、while True 的三个坑

### 1. 忘记 break → 真死循环

```python
while True:
    print("停不下来")
```

这是货真价实的死循环。写 `while True` 时，**第一件事就是先写 break 的位置**。

### 2. break 只跳出一层

后面你会学到"循环里套循环"。`break` 只跳**最里面那一层**，外层继续跑。这是新手困惑的经典来源，先记住有这回事。

### 3. 别在 break 后面写代码

```python
while True:
    break
    print("这行永远不会执行")    # 死代码
```

不报错，但永远不会跑。看到就能删掉。
