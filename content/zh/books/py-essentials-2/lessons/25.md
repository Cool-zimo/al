## 三十秒速览

```python
# 数据长这样：每人一门或多门成绩
students = [
    {"name": "张三", "scores": {"语文": 88, "数学": 92, "英语": 76}},
    {"name": "李四", "scores": {"语文": 95, "数学": 87, "英语": 90}},
]

# 常用统计套路
avg = sum(s["scores"].values()) / len(s["scores"])   # 个人平均分
total = sum(s["scores"].values())                     # 个人总分
ranked = sorted(students, key=lambda s: total, reverse=True)  # 按总分排名
```

成绩系统比通讯录难的地方在于：**每人有多门成绩，要算总分、平均分、排名、单科最高分、全班统计**。也就是说，你得同时用上字典嵌套、推导式、`sorted` 的 `key`、函数封装——这一章前面所有课的东西在这里汇合。

## 最容易错的三件事

### 一、排名用"下标 + 1"算，却忘了处理并列

```python
# WRONG
ranked = sorted(students, key=lambda s: sum(s["scores"].values()), reverse=True)
for i, s in enumerate(ranked):
    print(i + 1, s["name"])      # 两人同分却排 1、2
```

张三和李四如果总分都是 260，用户期望看到两个第 1 名、下一个是第 3 名，而不是 1、2。

```python
# RIGHT：遇到同分保持同排名，跳号
def rank_students(students):
    totals = [(sum(s["scores"].values()), s["name"], s) for s in students]
    totals.sort(reverse=True, key=lambda t: t[0])
    result = []
    rank = 1
    for i, (total, name, s) in enumerate(totals):
        if i > 0 and total != totals[i - 1][0]:
            rank = i + 1          # 分数变了才更新排名
        result.append((rank, s))
    return result
```

这就是"真正的排名"和"只是排个序"的区别。很多新手以为 `enumerate` 加 1 就是排名，交出去的产品在并列场景下立刻露馅。

### 二、平均分算错：科目不齐时 `len()` 取错了分母

```python
# WRONG
def average(scores_dict):
    return sum(scores_dict.values()) / len(scores_dict)   # 科目数
```

看着没问题，但如果某个学生缺考了一门（字典里没这门成绩），分母就少了。更隐蔽的是**全班的某门课平均分**：

```python
# WRONG：直接取所有成绩再除
all_math = [s["scores"]["数学"] for s in students]        # KeyError 如果有人缺考
avg_math = sum(all_math) / len(all_math)
```

```python
# RIGHT：只统计实际有这门成绩的人
def subject_average(students, subject):
    scores = [s["scores"][subject] for s in students if subject in s["scores"]]
    if not scores:                    # 空列表要判，否则 ZeroDivisionError
        return 0.0
    return sum(scores) / len(scores)
```

**`if not scores` 这个判断一定要写**——否则全员缺考时程序崩溃，而不是给出"0.0"。这跟第 21 课的 `all([])` 是同一类问题：空集要单独处理。

### 三、把统计结果和打印格式混在一起

```python
# WRONG
def report(students):
    for s in students:
        total = sum(s["scores"].values())
        avg = total / len(s["scores"])
        print(f"{s['name']}: 总分{total} 平均{avg:.1f}")
        if avg >= 90:
            print("  等级：优秀")
        elif avg >= 60:
            print("  等级：及格")
        else:
            print("  等级：不及格")
```

这函数**只能打印**，想把它变成网页表格、变成 Excel、变成发给学生的短信，就得重写一遍统计逻辑。

```python
# RIGHT：先算，后渲染
def compute_stats(students):
    """纯函数：返回结构化数据，不打印。"""
    return [{
        "name": s["name"],
        "total": sum(s["scores"].values()),
        "average": sum(s["scores"].values()) / len(s["scores"]),
        "level": level_of(sum(s["scores"].values()) / len(s["scores"])),
    } for s in students]

def level_of(avg):
    if avg >= 90: return "优秀"
    if avg >= 60: return "及格"
    return "不及格"

def render_text(stats):
    """只负责把结构化数据变成字符串。"""
    for st in stats:
        print(f"{st['name']}  总分{st['total']}  平均{st['average']:.1f}  {st['level']}")
```

**算和显示分开，是这个项目最该带走的经验。** 它让你的统计逻辑可以复用，也让测试变得简单——断言一个字典，比解析一行打印输出可靠一百倍。

## 翻车现场：等级判定的边界值

```python
# WRONG
def level(avg):
    if avg > 90:
        return "优秀"
    elif avg > 60:
        return "及格"
    else:
        return "不及格"
```

考了正好 90 分的学生，得到的是"及格"——用户会投诉。这种**边界偏差（off-by-one in condition）**是新手最常见、也最容易被用户抓出来的 bug。

```python
# RIGHT
def level(avg):
    if avg >= 90:     # 注意是 >=
        return "优秀"
    if avg >= 60:
        return "及格"
    return "不及格"
```

测试边界值时，要**专门测 89.9、90、60 这三个数**：

```python
assert level(89.9) == "及格"
assert level(90) == "优秀"      # 这里 WRONG 版会挂
assert level(60) == "及格"
assert level(59.9) == "不及格"
```

这个习惯叫**边界值测试**，是测试里性价比最高的一类。凡是写着 `>= 90` 的地方，就测 89、90、91 三个点。你的程序经得起这种测试，才算真正写对了。

## 小结

- 多科目成绩用字典嵌套：`{"name": ..., "scores": {"语文": 88, ...}}`
- 排名要处理并列：分数变化时才更新名次，跳过并列的序号
- 统计前先想清楚**分母是科目数还是人数**，空集要单独返回 0.0
- 等级判定用 `>=` 并**专门测试 89/90/60 这三个边界**
- 算和显示分开：纯函数返回结构化数据，渲染函数单独写
- 做完这个项目，你就已经能写"能用的程序"了

## 附录：下一步走哪条路

走到这里，你已经掌握了 Python 这门语言的**全部基础语法**。接下来往哪走，取决于你想用它做什么。四条路，各自的第一步：

**一、数据分析**
学 `pandas`（DataFrame 的筛选、分组、聚合）+ `matplotlib` / `seaborn`（画图）。第一步：下载一份 Kaggle 上的真实数据集，用它回答三个自己关心的问题。这一路通向运营分析、商业分析、数据科学。

**二、算法与竞赛**
刷 LeetCode 简单到中等题，重点练**数组、哈希表、双指针、滑动窗口、树和图**。同时学复杂度分析（时间/空间）。第一步：每天一题，做完必须看题解里最优的解法。这一路通向后端、算法岗、面试。

**三、桌面与可视化**
学 `tkinter`（标准库自带）或 `PySide6` 做窗口程序，配合前面做的成绩系统，给它加一个图形界面。第一步：把第 24 课的通讯录做成有按钮和表格的窗口程序。这一路通向工具开发、内部系统。

**四、工程化**
学 `git` + GitHub、单元测试（`pytest`）、虚拟环境、类型注解、代码规范（`ruff` / `black`）、打包发布（`pyproject.toml`）。第一步：给自己前面写的通讯录建一个 Git 仓库，写一份 README，补上单元测试。这一路通向软件工程师、开源贡献者。

不管走哪条路，**保持写代码的频率**比选哪条路更重要。语法你已经够了，剩下的全是"做项目"。
