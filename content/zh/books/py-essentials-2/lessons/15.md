# 集合巩固

> 这一课不重新讲概念。它做三件事：**用三十秒回顾要点、纠正最容易犯的三个错、用题目检验你是不是真的会了**。
> 这一课对应《学习篇》第 15 课。如果你发现回顾部分有任何一句看着陌生，先回去看《学习篇》第 15 课，再回来做题。

## 三十秒速览

```python
s = {1, 2, 3, 2, 1}
print(s)         # {1, 2, 3}   自动去重

s.add(4)         # {1, 2, 3, 4}
s.remove(2)      # {1, 3, 4}   没有就 KeyError
s.discard(9)     # 没有也不报错，更安全

a = {1, 2, 3}
b = {3, 4, 5}
print(a & b)     # {3}         交集
print(a | b)     # {1, 2, 3, 4, 5}   并集
print(a - b)     # {1, 2}      差集：在 a 不在 b
print(a ^ b)     # {1, 2, 4, 5}   对称差：只在一个里
```

| 运算 | 符号 | 方法 |
|---|---|---|
| 交集 | `a & b` | `a.intersection(b)` |
| 并集 | `a | b` | `a.union(b)` |
| 差集 | `a - b` | `a.difference(b)` |

集合里的元素必须可哈希，所以**列表不能放进集合**。`in` 判断是 O(1)。

## 最容易错的三件事

### 一、空集合不能写 `{}`

```python
a = {}
print(type(a))      # <class 'dict'>   这是空字典

b = set()
print(type(b))      # <class 'set'>    这才是空集合
```

`{}` 在 Python 里被字典占了。`set()` 才表示空集合。有元素时 `{1, 2, 3}` 没问题，因为字典必须带冒号。

### 二、集合是无序的，别指望它有顺序

```python
print({3, 1, 2})    # {1, 2, 3}   顺序不定，不同版本/运行可能不同
```

集合为了 O(1) 的查找效率，内部用哈希表，**不记录插入顺序**。所以：

- 想"去重且保持顺序"：用列表 + 集合辅助（见随堂练习）
- 想"去重但不在乎顺序"：直接 `set()`
- Python 3.7+ 的字典才保序，**集合始终不保序**

### 三、`remove()` 找不到就报错，`discard()` 不会

```python
s = {1, 2, 3}
s.remove(9)     # KeyError: 9
s.discard(9)    # 什么也不做，不报错
```

**不确定元素在不在，就用 `discard`**；只有确定它一定存在时才用 `remove`。

## 翻车现场：把列表当集合用

```python
# WRONG：想知道哪些城市在两个名单里都有
a = ["北京", "上海", "广州"]
b = ["广州", "深圳", "北京"]
print(a & b)      # TypeError: unsupported operand type(s) for &: 'list' and 'list'
```

`&`、`|`、`-` 是集合的运算符，列表不认。很多人脑子里已经把"交集"想成了 `&`，手上却还写着列表，于是撞上 `TypeError`。

正确写法：先转集合再运算。

```python
a = ["北京", "上海", "广州"]
b = ["广州", "深圳", "北京"]
common = set(a) & set(b)
print(common)             # {'广州', '北京'}   无序
print(sorted(common))     # ['北京', '广州']   想要顺序就再 sorted 一下
```

**集合转回列表要 `sorted()`，别直接 `list()`**——后者顺序是随机的。

列表 `in` 还是慢的问题，规模一大就更明显：

```python
# 慢
cities = ["北京", "上海", "广州", "深圳", "杭州"] * 2000   # 一万个城市
for _ in range(10000):
    if "拉萨" in cities:      # 每次都要从头比一遍，O(n)
        pass
```

```
# 没有报错，但跑得慢
# 一万个元素的列表，in 判断要平均扫 5000 次
```

列表的 `in` 是线性扫描 O(n)。**要判断"有没有"，集合是 O(1)**——哈希一下直接定位。

```python
cities = ["北京", "上海", "广州", "深圳", "杭州"] * 2000
city_set = set(cities)        # 转成集合，一次 O(n)
for _ in range(10000):
    if "拉萨" in city_set:    # O(1)
        pass
```

转集合只要扫一遍，之后每次查询都是常数级。数据量越大，差距越夸张：**一万个元素的列表查一万次，和同规模集合查一万次，可能差出上百倍**。

记住这条经验：**查重、去重、判存在，第一反应是集合**。

## 小结

- 空集合写 `set()`，别写 `{}`（那是字典）
- 集合无序，要保序去重得自己用列表 + 集合辅助
- 元素必须可哈希：列表不能进集合
- 不确定在不在用 `discard()`，确定在才用 `remove()`
- **判存在用集合（O(1)），不要用列表（O(n)）**

## 随堂练习

```quiz
type: code
q: 输入一行用空格分隔的若干个整数，输出去重后保持原顺序的列表。例如输入 "3 1 2 1 3 2 4" 输出 "[3, 1, 2, 4]"。注意：直接转 set 会打乱顺序，要自己用列表加集合辅助
starter: |
  nums = [int(x) for x in input().split()]
  seen = set()
  result = []
  # 遍历 nums，没见过的加入 result 并登记
  print(result)
tests:
- assert __out.strip() == "[3, 1, 2, 4]"
- assert __out.strip() == "[1, 2, 3]"
hint: for n in nums: if n not in seen: seen.add(n); result.append(n)。集合负责 O(1) 判重，列表负责保序。
explain: 这题是集合最典型的用法：用一个 set 记录"已经出现过的"，用列表记录"最终顺序"。两者配合，既有 O(1) 的判重效率，又保住了首次出现的顺序。单纯 set() 做不到保序。
```
