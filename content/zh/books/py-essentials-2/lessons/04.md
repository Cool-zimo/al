# 报错阅读巩固

> 这一课不重新讲概念。它做三件事：**用三十秒回顾要点、纠正最容易犯的三个错、用题目检验你是不是真的会了**。
> 如果你发现回顾部分有任何一句看着陌生，先回去看《学习篇》第 5 课，再回来做题。

## 三十秒速览

```python
# 故意写一段会报错的代码
def greet(name):
    print("你好" + nam)   # 少打了一个 e

greet("张三")
```

运行后 Python 会打印一长段红字，这就是 **Traceback（回溯）**。它的阅读顺序是**从下往上**：

```
Traceback (most recent call last):
  File "<stdin>", line 5, in <module>
    greet("张三")
  File "<stdin>", line 2, in greet
    print("你好" + nam)
NameError: name 'nam' is not found
```

| 看哪 | 得到什么 |
|---|---|
| **最下面一行** | 错误类型 + 一句话原因（`NameError: name 'nam' is not found`） |
| **中间箭头处** | 出错的那一行代码 |
| **再往上看** | 是谁调用到这里的（调用栈） |

**最下面的那一行就是全部答案**：错误类型告诉你"哪一类错"，引号里的内容告诉你"错在哪"。

## 最容易错的三件事

### 一、看到红字就慌，其实最后一行才是重点

新手常犯的错是盯着整屏红字发呆。其实只要读两处：

```python
# 例 1：SyntaxError
 if x = 3:
     print(x)
```

```
  File "<stdin>", line 1
    if x = 3:
       ^^^^
SyntaxError: cannot assign to expression here
```

`SyntaxError` 是**语法错误**——代码根本没通过"编译"这一关，程序一行都没执行。箭头 `^^^^` 直接指到 `x = 3`，告诉你"这里不该写赋值"。常见原因：把 `=` 写成 `==` 的反面、少了冒号、少了引号。

### 二、`NameError` 和 `TypeError` 都跟"名字"有关，但含义完全不同

```python
# NameError：这个名字根本不存在
print(nam)                  # NameError: name 'nam' is not defined

# TypeError：名字存在，但用法不对
print("3" + 3)              # TypeError: can only concatenate str to str
```

`NameError` 说"我找不到这个变量"，十有八九是**拼写错了**或**忘了定义**。`TypeError` 说"变量是有的，但你这样用不行"，通常是**类型不对**——比如拿字符串和数字做加法，或者调用函数时传了错误数量的参数。

```python
len(123)                    # TypeError: object of type 'int' has no len()
```

### 三、`IndexError` 和 `ValueError` 一个越界、一个格式错

```python
s = "abc"
s[5]            # IndexError: string index out of range —— 下标超了

int("abc")      # ValueError: invalid literal for int() with base 10: 'abc'
```

`IndexError` 是"你访问的位置不存在"。`ValueError` 是"这个值本身没法按你要的方式用"——`int()` 可以转换 `"123"`，但转换不了 `"abc"`，尽管 `"abc"` 是个完全合法的字符串。

四个错误类型的对照表：

| 错误 | 含义 | 典型场景 |
|---|---|---|
| `SyntaxError` | 语法不对，代码没跑起来 | 少冒号、少引号、`=` 当 `==` |
| `NameError` | 用了没定义/拼错的名字 | `nam` 写成 `name` |
| `TypeError` | 类型用错了 | `"3" + 3`、参数个数不对 |
| `IndexError` | 下标越界 | `s[100]`、`lst[-5]` 但只有 3 个 |
| `ValueError` | 值的内容不合法 | `int("abc")`、`float("十二")` |

## 翻车现场：Traceback 里的行号指的不是"你以为的那行"

```python
# WRONG：只盯着第一行报错，以为问题在定义
def get_first(s):
    return s[10]          # 你以为错在这里

name = "张三"
print(get_first(name))
```

```
Traceback (most recent call last):
  File "demo.py", line 6, in <module>
    print(get_first(name))
  File "demo.py", line 2, in get_first
    return s[10]
IndexError: string index out of range
```

很多人看到"line 6"就回去改 `print` 那行。其实**箭头和错误类型才是指引**：箭头指到 `return s[10]`，错误是 `IndexError`。问题不是 `print` 调用错了，而是 `"张三"` 只有 2 个字符，`s[10]` 越界了。

正确的处理顺序：**先看最下面一行错误类型和原因 → 再看箭头指的那行代码 → 最后才看上面的调用栈**。如果报错出现在函数内部，调用栈会告诉你"是谁传了个奇怪的值进来"，这时候就要往上看。

顺带一提，**`SyntaxError` 是唯一没有 Traceback 的**：因为它是语法检查阶段就被拦下的，程序还没开始执行，谈不上"调用栈"。

## 小结

- 读报错从**下往上看**，最后一行 = 错误类型 + 原因
- 箭头 `^^^^` 指的位置 = 真正出问题的那行
- `SyntaxError` 最特殊：没有 Traceback，箭头直接指语法错误处
- `NameError` 是"没这变量"，`TypeError` 是"类型不对"，`IndexError` 是"越界"，`ValueError` 是"值不合法"
- 五个错误类型各管一段，能对号入座就能秒修 bug

## 随堂练习

```quiz
type: code
q: 读入一个字符串和一个整数下标，输出该下标对应的字符。如果下标越界，输出 "越界"。系统会输入 "python" 和 "8"
starter: |
  s = input()
  i = int(input())
  # 用 len(s) 判断下标是否合法
  print("TODO：把这行改成你要打印的结果")
stdin: |
  python
  8
tests:
- assert "越界" in __out
hint: 合法下标范围是 0 到 len(s)-1。用 if i < len(s) 判断，否则输出"越界"。
explain: 这题练习"防越界"的防御性写法。IndexError 的本质就是下标超出 [0, len(s)-1]，只要访问前先判断就能避免。用 len() 而不是硬编码数字 5，代码对更长更短的字符串都适用。
```

```quiz
type: choice
exam: true
q: 运行下面代码会报什么错？
code: |
  x = "123"
  y = x + 4
  print(y)
options:
- SyntaxError
- NameError
- TypeError
- ValueError
answer: 2
explain: x 是字符串 "123"，4 是整数。Python 不允许字符串和整数相加，报 TypeError: can only concatenate str to str。注意不是 ValueError：ValueError 是"值的内容没法转换"（如 int("abc")），这里是"两种类型根本不能这么运算"。
```

```quiz
type: function
exam: true
q: 写 safe_divide(a, b)，返回 a / b 的结果（保留两位小数，用 round 处理）。如果 b 为 0，返回字符串 "除数不能为0"。提示：0 不能作为除数，会触发 ZeroDivisionError
func: safe_divide
starter: |
  def safe_divide(a, b):
      # 先判断 b 是否为 0，否则做除法并 round(..., 2)
      return 0
cases: |
  (10, 3) -> 3.33
  (7, 2) -> 3.5
  (5, 0) -> "除数不能为0"
hint: 用 if b == 0 提前处理，否则 return round(a / b, 2)。注意 round 的第二个参数是保留小数位数。
explain: 这是"防御性编程"的基本功：先把不合法的情况拦下来，再处理正常逻辑。ZeroDivisionError 属于运行时异常，不会在语法检查阶段被发现，所以必须用 if 预判。若反例写成直接除而不判断，b=0 时会抛异常而非返回提示字符串。
```
