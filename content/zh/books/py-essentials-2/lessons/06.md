# if / elif / else 巩固

> 这一课不重新讲概念。它做三件事：**用三十秒回顾要点、纠正最容易犯的三个错、用题目检验你是不是真的会了**。
> 如果你发现回顾部分有任何一句看着陌生，先回去看《学习篇》第 6 课，再回来做题。

## 三十秒速览

```python
score = 85

if score >= 90:
    level = "优秀"
elif score >= 60:        # elif = else if，前面不满足才进这里
    level = "及格"
else:                    # 所有上面都不满足
    level = "不及格"

print(level)             # 及格
```

比较运算符：`==`（等于）、`!=`（不等于）、`>`、`<`、`>=`、`<=`。

判断的核心规则只有两条：

1. **条件从上往下逐个判断，命中一个就执行它，剩下的全跳过**。`elif` 是按顺序匹配，不是"所有满足条件的都执行"。
2. **缩进决定归属**。同一个缩进层级属于同一个分支，缩进错了，逻辑就错了。

```python
if score >= 60:
    print("能毕业")      # 缩进 4 个空格，属于 if 块
print("这里总会执行")     # 顶格，和 if 无关
```

## 最容易错的三件事

### 一、条件顺序写反：宽泛条件挡在前面

这是 `elif` 里最经典的坑，没有之一。

```python
# WRONG：把最宽的条件写在第一个
score = 85

if score >= 60:                  # 85 满足这个条件
    print("及格")                # 命中，执行
elif score >= 90:                # 永远不会走到这里
    print("优秀")
```

一旦 `score >= 60` 命中，下面的 `elif` 就**直接作废**。85 明明也算"优秀"？不算，程序已经走了第一个分支。

正确顺序是从**严到宽**，把范围最小的放最前：

```python
score = 85

if score >= 90:                  # 先问最严的
    print("优秀")
elif score >= 60:                # 再问宽松的
    print("及格")
else:
    print("不及格")
```

判断顺序像漏斗：**先窄后宽**。写 `elif` 时养成习惯，从最严格的条件往下排。

### 二、用 `=` 而不是 `==` 做判断

```python
# WRONG
if x = 18:          # SyntaxError: invalid syntax
    print("等于18")
```

`=` 是赋值，`==` 才是比较。Python 在这里比较友好，会直接报 `SyntaxError` 拦住你。但在 `while` 条件里这个错误更隐蔽，后面第 8 课会再讲。

```python
x = 18
if x == 18:         # True
    print("等于18")
```

注意 `if x = 18:` 和 `if x == 18:` 只差一个等号，但完全不是一回事。

### 三、缩进不一致：混用空格和 Tab

```python
# WRONG：有的行 4 空格，有的行 1 个 Tab
if score >= 60:
    print("及格")
	print("能毕业")      # IndentationError: unindent does not match
```

Python 看到缩进不一致就直接报错，连运行都进不去。更坑的是**看起来对齐、实际没对齐**的情况——全角空格、混用 Tab 和空格，肉眼很难分辨。

正确做法：整份代码统一用 **4 个空格**。编辑器里把 Tab 键设成自动转成 4 个空格，从此不用再想这件事。

```python
if score >= 60:
    print("及格")        # 4 空格
    if score >= 90:
        print("优秀")    # 再缩进 4 空格，共 8 个
```

## 翻车现场：一个分支永远走不到

```python
# WRONG：给成绩打等级，结果 95 分被判定成"及格"
score = 95

if score >= 60:
    level = "及格"
elif score >= 80:
    level = "良好"
elif score >= 90:
    level = "优秀"
else:
    level = "不及格"

print(level)        # 及格  ← 95 分只拿到"及格"
```

问题一目了然：最宽的条件 `>= 60` 排在了最前，95 一进来就被"及格"截走，`>= 80` 和 `>= 90` 这两行成了**死代码**——逻辑上永远执行不到。

修法：**从严到宽重新排列**。

```python
score = 95

if score >= 90:
    level = "优秀"
elif score >= 80:
    level = "良好"
elif score >= 60:
    level = "及格"
else:
    level = "不及格"

print(level)        # 优秀
```

这类 bug 的可怕之处在于**不报错**：程序正常运行，只是结果错。要发现它，得靠自己测边界值（60、79、80、89、90），而不是等用户反馈。

## 小结

- `elif` 是按顺序匹配的，命中一个就跳过其余，不是"所有满足的都执行"
- 写 `elif` 顺序从**严到宽**，最严格的条件放最前
- `=` 是赋值，`==` 才是比较，混用会 `SyntaxError`
- 缩进统一用 4 个空格，别混用 Tab
- 条件分支的 bug 往往不报错，用边界值（60、90）自己验一遍
