# 模块与包巩固

> 这一课不重新讲概念。它做三件事：**用三十秒回顾要点、纠正最容易犯的三个错、用题目检验你是不是真的会了**。
> 如果你发现回顾部分有任何一句看着陌生，先回去看《学习篇》第 22 课，再回来做题。

## 三十秒速览

```python
import math                  # 用法：math.sqrt(2)
import os.path as osp        # 起别名，避免名字太长
from random import choice    # 只导入一个名字，直接用 choice([1,2,3])
from collections import *    # 导入所有公开名字（不推荐在正式代码里用）
```

| 写法 | 导入的东西 | 调用方式 |
|---|---|---|
| `import math` | 整个模块 | `math.sqrt(2)` |
| `import math as m` | 整个模块，别名 `m` | `m.sqrt(2)` |
| `from math import sqrt` | 只导入 `sqrt` 一个名字 | `sqrt(2)` |
| `from math import *` | 所有公开名字 | `sqrt(2)`（污染命名空间） |

模块就是**一个 `.py` 文件**。包就是**一个带 `__init__.py` 的文件夹**（Python 3.3+ 命名空间包可省略，但写上更清晰）。

## 最容易错的三件事

### 一、`from x import *` 把你的变量覆盖了

```python
# WRONG
from math import *
sqrt = 3.14            # 你想给"圆周率"起个名字
print(sqrt(9))         # TypeError: 'float' object is not callable
```

`from math import *` 把 `sqrt`、`sin`、`cos`、`pi` 等几十个名字全部倒进当前命名空间。之后你再用 `sqrt` 当变量名，就悄悄覆盖了那个函数——而且 Python 不会给任何警告。

`import *` 还有两个硬伤：读代码时看不到名字从哪来；工具无法静态分析哪些名字被用了。

```python
# RIGHT
import math
sqrt = 3.14
print(math.sqrt(9))    # 4.0   —— 模块名充当命名空间，互不干扰
```

交互式探索时用 `from x import *` 图省事可以，写文件时必须用 `import x`。

### 二、`if __name__ == "__main__":` 不是装饰，是"能不能被复用"的分水岭

```python
# tools.py
def double(x):
    return x * 2

print(double(10))      # 调试时写的
```

另一个文件 `main.py`：

```python
import tools           # 一导入就打印 20，污染了 main.py 的输出
print(tools.double(5))
```

```python
# tools.py 的正确写法
def double(x):
    return x * 2

if __name__ == "__main__":
    print(double(10))  # 只有直接运行 python tools.py 才执行
```

`__name__` 是这个模块的"名字"。**直接运行时它被设为 `"__main__"`，被导入时则设为文件名**（`"tools"`）。这行判断的含义是："只有在被当作程序入口时才跑这段，被别人 import 时只提供函数，不执行副作用。"

### 三、模块只会被导入一次，改了代码也不会重新加载

```python
# config.py
TIMEOUT = 30
```

```python
import config
print(config.TIMEOUT)   # 30
# 此时你用编辑器把 config.py 改成 TIMEOUT = 60 并保存
print(config.TIMEOUT)   # 还是 30！
```

Python 在第一次 `import` 时执行模块顶层代码，把结果缓存在 `sys.modules`。之后所有 `import` 都直接从缓存取，**不再读文件**。这是有意的——重复执行模块顶层代码既慢又危险。

想强制重载：

```python
import importlib
import config
importlib.reload(config)   # 仅调试时用，生产环境不要用
```

真正的解决方式是**重启解释器**。这也是为什么 IDE 的"运行"按钮总会启动一个新进程。

## 翻车现场：# WRONG `__pycache__` 看起来像垃圾，但不是

```bash
$ python main.py
$ ls
main.py  utils.py  __pycache__/
$ ls __pycache__/
utils.cpython-311.pyc
```

```python
# 删掉 __pycache__ 再运行，程序照样跑
# 但删掉 utils.py 后……
$ python main.py
ModuleNotFoundError: No module named 'utils'
```

`__pycache__` 里放的是 `.pyc` 文件——Python 把编译好的字节码缓存下来，**下次启动就跳过编译，直接加载**，能省下几十毫秒。它完全由 Python 自动管理，可以删、可以重建，不是你需要手动维护的东西。

真正的坑是**循环导入**：

```python
# a.py
import b
def fa():
    return b.gb() + 1

# b.py
import a                 # 此时 a 还没加载完，a.fa 还不存在
def gb():
    return a.fa() - 1    # AttributeError: module 'a' has no attribute 'fa'
```

导入 `a` 时执行 `a.py`，遇到 `import b` 转去执行 `b.py`；`b.py` 又要 `import a`，而此时 `a` 还在半途——结果 `b` 拿到的是一个**尚未完成的 `a` 模块对象**，`a.fa` 根本不存在。

解决办法：把导入推迟到函数内部（延迟导入），或者重构代码把公共部分抽到第三个模块。这也是为什么"在文件顶部放所有 import"这条惯例，遇到循环依赖时就得破例。

## 小结

- 四种 `import` 写法各有权衡，写文件时优先 `import x`，别用 `from x import *`
- `from x import *` 会污染命名空间，覆盖同名变量且毫无警告
- `if __name__ == "__main__"` 让文件"既能当脚本又能被导入"，是可复用性的分水岭
- 模块只加载一次，缓存于 `sys.modules`，改源码要重启解释器
- `__pycache__` 是字节码缓存，可删可重建；循环导入才是真问题

## 随堂练习

```quiz
type: code
q: 你正在写一个工具模块。请在下方代码里用 `if __name__ == "__main__":` 包裹测试代码，使得这个文件被 import 时不打印任何东西，但直接运行时打印 greet("张三") 和 greet("李四") 的结果。系统运行的是直接执行本文件
starter: |
  def greet(name):
      return f"你好，{name}！"

  # 在这里加守卫，让下面的测试只在直接运行时执行
  print(greet("张三"))
  print(greet("李四"))
stdin: |

tests:
- assert "你好，张三！" in __out
- assert "你好，李四！" in __out
hint: 把两个 print 缩进到 if __name__ == "__main__": 下面。
explain: 这题考察的就是那行守卫的写法。没有它，任何 import 这个模块的文件都会在导入瞬间打印两句问候——生产代码里这种"隐式副作用"是最难排查的 bug 之一。
```

## 本节测验

```quiz
type: choice
exam: true
q: 关于下面两种写法，下列说法正确的是？
code: |
  # 写法 A
  from math import sqrt, pi

  # 写法 B
  import math
options:
- 两种写法完全等价，只是 A 打字更少
- A 会导入 math 里所有函数，B 只导入两个
- A 把 sqrt 和 pi 直接放进当前命名空间，B 需要 math.sqrt 访问；A 不会影响 math 模块本身的名字
- B 会把 math 里所有函数都执行一遍并占用大量内存
answer: 2
explain: from ... import 只是把指定名字绑定到当前作用域，名字来源依然是 math 模块。两种写法都不会"导入全部函数然后挑两个"——import 的最小单位是一个模块。差别在于命名空间的污染程度。
```

```quiz
type: function
exam: true
q: 写 make_greeter(greeting)，返回一个闭包函数。返回的函数接受一个名字 name，返回 greeting 和 name 拼接后的字符串。要求：不使用任何 import，不访问全局变量，纯靠参数和返回值实现。这个练习考察的是"模块思维"——把一个可复用单元封装成函数，而不是依赖外部状态
func: make_greeter
starter: |
  def make_greeter(greeting):
      # 返回一个函数，该函数记住了 greeting
      def inner(name):
          return ""
      return inner
cases: |
  make_greeter("你好")(("张三",)) -> "你好，张三"
  make_greeter("Hello")(("Alice",)) -> "Hello, Alice"
  make_greeter("早上好")(("李四",)) -> "早上好，李四"
hint: inner 函数定义在 make_greeter 内部，自然能捕获外层参数 greeting，这就是闭包。直接 return f"{greeting}，{name}" 即可。
explain: 模块的本质是"封装 + 复用"。这道题用闭包模拟了模块级的封装：greeting 相当于模块里的配置常量，inner 相当于模块里的函数。理解了这一点，"为什么要把代码放进模块"就不再是一个语法问题，而是一个设计问题。
```
