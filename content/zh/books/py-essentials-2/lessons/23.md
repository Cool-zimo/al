# 推导式与内置函数巩固

> 这一课不重新讲概念。它做三件事：**用三十秒回顾要点、纠正最容易犯的三个错、用题目检验你是不是真的会了**。
> 如果你发现回顾部分有任何一句看着陌生，先回去看《学习篇》第 23 课，再回来做题。

## 三十秒速览

```python
# 列表推导式
squares = [x**2 for x in range(10)]            # [0, 1, 4, ..., 81]
evens = [x for x in range(20) if x % 2 == 0]   # 带条件

# 字典 / 集合推导式
d = {x: x**2 for x in range(5)}                # {0:0, 1:1, 2:4, 3:9, 4:16}
s = {len(w) for w in ["a", "bb", "ccc"]}       # {1, 2, 3}  自动去重

# 内置函数
sorted([3, 1, 2], reverse=True)                # [3, 2, 1]
sorted(people, key=lambda p: p["age"])         # 按 age 排序
zip([1, 2], ["a", "b"])                        # 两两配对
any([False, True, False])                      # True
all([1, 2, 3])                                 # True —— 所有元素都为真
sum([1, 2, 3])                                 # 6
```

推导式就是"**把 for 循环写成一行表达式**"。`key` 参数接受一个函数，告诉排序/最值"按什么比较"。

## 最容易错的三件事

### 一、把推导式写成了三层的嵌套地狱

```python
# WRONG
matrix = [[[x * y * z for x in range(3)] for y in range(3)] for z in range(3)]
```

这行代码能跑，但谁也读不懂。`[[... for x in ...] for y in ...]` 这种**推导式里套推导式**的写法，可读性断崖式下降——执行顺序是"从外到内"，但阅读顺序和直觉相反。

**推导式超过两层就该写成普通 for 循环**：

```python
result = []
for z in range(3):
    layer = []
    for y in range(3):
        row = [x * y * z for x in range(3)]   # 最内层才用推导式
        layer.append(row)
    result.append(layer)
```

判断标准很简单：**能在一秒内看懂在干什么，就留着推导式；看不懂，就拆。** Python 之禅里那句"可读性很重要"说的就是这种取舍。

### 二、`sorted()` 不改变原列表，`list.sort()` 才改

```python
nums = [3, 1, 2]
sorted(nums)          # 返回一个新列表 [1, 2, 3]
print(nums)           # [3, 1, 2]   —— 原列表没动！

nums.sort()           # 原地排序，返回 None
print(nums)           # [1, 2, 3]
```

| 写法 | 是否产生新列表 | 返回值 | 适用对象 |
|---|---|---|---|
| `sorted(x)` | 是 | 新列表 | 任何可迭代对象（含元组、字符串） |
| `x.sort()` | 否，原地改 | `None` | 只有列表有这个方法 |

这个区别在链式调用里会咬人：

```python
# WRONG
result = nums.sort(reverse=True) * 2   # TypeError: NoneType 不支持乘法
```

`sort()` 返回 `None`，`None * 2` 直接报错。要链式就得用 `sorted()`。

顺带一提，`max`/`min` 也能接 `key`：

```python
words = ["python", "is", "awesome"]
print(max(words, key=len))     # "awesome"  —— 最长的
```

### 三、`all()` 和 `any()` 对空序列的结果反直觉

```python
print(all([]))    # True   —— "所有元素都满足"在空集合上为真
print(any([]))    # False  —— "存在元素满足"在空集合上为假
```

这叫"真空真"（vacuous truth）。`all` 的逻辑等价于"不存在反例"，空集里没有反例，所以为真；`any` 的逻辑是"存在正例"，空集里没有正例，所以为假。

实战里最常见的翻车：

```python
scores = []                       # 还没人交卷
if all(s >= 60 for s in scores):  # True！空列表全员及格
    print("全班及格")              # 错误结论
```

```python
# RIGHT：先判非空
if scores and all(s >= 60 for s in scores):
    print("全班及格")
```

`and` 短路了空列表的 `False` 值，顺序必须是"先 `scores` 再 `all(...)`"。

## 翻车现场：`zip` 的长度由最短的那个决定

```python
names = ["张三", "李四", "王五"]
cities = ["北京", "上海"]

for n, c in zip(names, cities):
    print(f"{n}住在{c}")
```

```
张三住在北京
李四住在上海
```

`王五` 就这么消失了。`zip` 在**任意一个**可迭代对象耗尽时立即停止，多出来的部分被静默丢弃。要保留全部数据得用 `itertools.zip_longest`：

```python
from itertools import zip_longest
for n, c in zip_longest(names, cities, fillvalue="未知"):
    print(f"{n}住在{c}")
```

```
张三住在北京
李四住在上海
王五住在未知
```

更隐蔽的坑是 `dict` 的 `zip` 构造法：

```python
keys = ["name", "age", "city"]
values = ["张三", 18]                    # 少了一项
user = dict(zip(keys, values))
print(user)                             # {'name': '张三', 'age': 18} —— 丢了 city
```

少传一个值，字典就少一个键，**不报错**。这在处理外部数据时尤其危险，因为数据缺失往往不会以异常的形式暴露。

## 小结

- 推导式是好东西，但**超过两层就该拆成 for 循环**
- `sorted()` 返回新列表不改原对象；`list.sort()` 原地改、返回 `None`
- `all([])` 为 `True`、`any([])` 为 `False`，处理可能为空的数据时先判空
- `zip` 以最短为准，多余元素静默丢弃；要保全会用 `zip_longest`
- `max`/`min`/`sorted` 都能接 `key` 参数，别在比较前手动转换
