# 饼图的争议与替代

> 饼图几乎是每个新手最先学会的图，也是数据可视化专家最不推荐的一张。这一节讲清它为什么坑，以及该用什么替代。

## 饼图能画，但很挑场景

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

channels = ['线上商城', '门店直营', '经销商', '直播带货']
share = [42, 28, 18, 12]

fig, ax = plt.subplots(figsize=(7, 7))
ax.pie(share, labels=channels, autopct='%1.1f%%', startangle=90)
ax.set_title('销售额渠道占比')
fig.savefig('pie_basic.png')
print('saved')
```

`autopct='%1.1f%%'` 显示百分比，`startangle=90` 让第一块从 90° 开始。**饼图只适合"整体是 100%"的场景**——占比、构成、份额。

## 为什么专家不推荐饼图

**人眼不擅长比较角度。** 这是饼图的根本缺陷。

```python
# 两个扇区，哪个大？
a, b = 27, 32
```

输出：27% 和 32% 的扇区**看起来几乎一样大**，但你问"哪个大"，很多人答错。相比之下，两根柱子的长短差异一眼就能看出来。

**实验结论**：人对**长度**的判断误差约 5%，对**角度/面积**的判断误差高达 20% 以上。饼图用的是角度，天生不精确。

## 翻车现场 1：类别太多

```python
cats = ['线上商城', '门店直营', '经销商', '直播带货', '团购', '分销',
        '代购', '企业采购', '海外']
vals = [25, 20, 15, 12, 8, 7, 6, 5, 2]

fig, ax = plt.subplots(figsize=(7, 7))
ax.pie(vals, labels=cats, autopct='%1.1f%%')
fig.savefig('pie_many.png')
```

输出：**扇区细得像牙签**，标签挤成一团甚至跑到图外面。饼图超过 5–6 块就基本不可读。

## 翻车现场 2：差 1% 画成差不多大

```python
vals = [26, 27, 25, 22]      # 四个数几乎相等
ax.pie(vals, labels=['A','B','C','D'], autopct='%1.0f%%')
```

输出：四块扇区**看起来几乎一样大**，但数字差了 5 个百分点。这种"看似平等"的视觉误导，是饼图最常见的坑。

## 替代一：条形图（最稳）

**任何饼图都能换成条形图，而且通常更好。**

```python
fig, ax = plt.subplots(figsize=(8, 5))
bars = ax.barh(channels, share, color='#377eb8')
ax.set_xlabel('占比（%）')
ax.set_title('销售额渠道占比')

# 给每根柱子标数值
for bar, v in zip(bars, share):
    ax.text(v, bar.get_y() + bar.get_height()/2, f'{v}%',
            va='center', ha='left', fontsize=10)
fig.savefig('bar_alt.png')
```

横向条形图的优势：**长度差异一目了然**，5% 和 32% 一眼分得清；还能放 10 个以上类别；标签永远不挤。

## 翻车现场 3：不按大小排序

```python
ax.barh(channels, share)        # 按原始顺序，杂乱
```

输出：高低交错，看不出谁是主力。**饼图和条形图的扇区/柱子都应该从大到小排**：

```python
order = np.argsort(share)              # 从小到大排序
ax.barh(np.array(channels)[order], np.array(share)[order])
```

排好序后"主力渠道一眼就在最上面"，信息密度大幅提升。

## 替代二：堆叠水平条（100% 堆叠）

想强调"构成 100%"这个事实，又不想用饼图：

```python
fig, ax = plt.subplots(figsize=(9, 3))
left = 0
colors = ['#e41a1c', '#377eb8', '#4daf4a', '#984ea3']
for cat, v, c in zip(channels, share, colors):
    ax.barh(['占比'], [v], left=left, label=cat, color=c)
    ax.text(left + v/2, 0, cat, ha='center', va='center', color='white', fontsize=10)
    left += v
ax.set_xlim(0, 100)
ax.set_xlabel('占比（%）')
ax.set_title('销售额渠道占比（100% 堆叠条）')
ax.legend(loc='upper center', ncol=4, bbox_to_anchor=(0.5, 1.15))
fig.savefig('stacked100.png')
```

100% 堆叠条保留了"整体是 100%"的语义，同时用**长度**而不是角度来比较。

## 什么时候饼图是可以用的

饼图不是"绝对不能用"，有严格的前提：

- **类别 ≤ 5 个**
- **想强调"这是整体的 100%"**（构成、份额）
- **各类别差异明显**（最大的比最小的大 2 倍以上）
- **读者只需要大致印象**，不要求精确比较

业务周报、PPT 首页、给非技术读者看时，饼图依然好用——**它的优势是"一眼知道是个构成"**，这个语义饼图像传达得最直白。但涉及精确比较，一律换条形。

## donut（环形图）也没救

```python
ax.pie(share, labels=channels, autopct='%1.1f%%', wedgeprops={'width': 0.5})
```

环形图只是把中间挖空，本质还是角度比较，**缺点一个没少**。中间那块空白唯一的作用是放个总数——如果真要放，至少有点价值；不放就是纯装饰。

## 小结

- 饼图的根本缺陷：**人眼不擅长比较角度**（误差 20%+，而长度只有 5%）
- 超过 5–6 块扇区就不可读，类别多一律换条形
- 差异小时（26% vs 27%）饼图会画成"看起来一样大"，最危险
- 替代方案：横向条形图（最稳）、100% 堆叠条（保留构成语义）
- 排序很重要：饼图扇区、条形图柱子都该从大到小
- 饼图唯一不可替代的价值：**最直白地传达"这是整体的 100%"**
