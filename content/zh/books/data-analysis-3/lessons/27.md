# 清洗与特征：从脏数据到可用数据

> 上一节定好了清洗清单，这一节动手做：把字符串变成数字、把缺失填上或删掉、把异常值揪出来、再顺手派生出新字段——清洗不是整理卫生，而是在给模型准备"能吃的饭"。

## 第一步：类型转换，脏数据的第一道关口

读进来的数字常常是字符串，`1000` 和 `'1000'` 在 pandas 眼里完全不是一回事。想做加减乘除，必须先转换。

```python
import matplotlib
matplotlib.use('Agg')
import pandas as pd
import numpy as np

df = pd.DataFrame({
    '门店': ['北京', '上海', '北京', '上海', '广州'],
    '日期': ['2025-01-01', '2025-01-02', '2025-01-03', '2025-01-04', '2025-01-05'],
    '销售额': ['1000', '1,200', '980', '1,500', '3200元'],
    '客流量': [120, 130, '无记录', 150, 90],
    '是否会员': ['是', '否', '是', '是', '否'],
    '备注': ['正常', None, '退货', '正常', '正常'],
})

print(df.dtypes)
# 销售额    object
# 客流量    object   ← 混入了"无记录"，整数列被抬成 object
```

转换的主力是 `pd.to_numeric`：

```python
df['销售额_元'] = pd.to_numeric(
    df['销售额'].str.replace('[元,]', '', regex=True),
    errors='coerce'
)
print(df['销售额_元'])
# 0    1000.0
# 1    1200.0
# 2     980.0
# 3    1500.0
# 4    3200.0
```

`errors='coerce'` 把转不动的值变成 `NaN`，让程序继续跑下去，而不是当场崩溃。`str.replace` 里的正则去掉了 `,` 和 `元`，这是处理"混入单位"的标准动作。

**翻车现场 1：忘了 `errors='coerce`，整列报错。**

```python
# WRONG：含"1,200""3200元"的列直接转，遇到非数字就崩
pd.to_numeric(df['销售额'])
# ValueError: Unable to parse string "1,200" at position 1
```

报错信息说得很直白：position 1 的 `"1,200"` 解析不了。**默认 `errors='raise'`，遇到一个非数字就全盘终止**。真实数据里几乎一定有脏值，所以日常写代码时 `errors='coerce'` 才是默认值心态。反过来说，`errors='ignore'` 会原样返回原列（连类型都不改），是三个选项里最"看起来没报错、实际上什么都没干"的一个陷阱。

| 参数值 | 遇到脏值时的行为 | 适用场景 |
|---|---|---|
| `raise` | 抛异常终止 | 你确信数据必须全干净 |
| `coerce` | 变 NaN 继续 | 日常清洗，最常用 |
| `ignore` | 保留原值不动 | 只想试转、不想要 NaN |

## 第二步：缺失值，填还是删

缺失不是脏，是"信息不完整"。处理思路就两条：删掉这行，或者填上一个值。选哪个，取决于缺失是否随机、占比多大。

```python
print('缺失情况:')
print(df.isna().sum())
# 销售额      0
# 客流量      0   ← 注意："无记录"是字符串，不算缺失
# 备注        1

# 先处理客流量里的"无记录"——它现在被当成合法字符串
df['客流量'] = pd.to_numeric(df['客流量'], errors='coerce')
print(df['客流量'].isna().sum())   # 1
```

数值列的常见填法：

```python
# 均值填充（对销售额）——适合近似正态分布
df['销售额_均值填'] = df['销售额_元'].fillna(df['销售额_元'].mean())

# 中位数填充——存在极端值时比均值稳
df['销售额_中位填'] = df['销售额_元'].fillna(df['销售额_元'].median())

# 类别列填众数或"未知"
df['备注'] = df['备注'].fillna('正常')

# 直接删除缺失行
df_dropped = df.dropna(subset=['销售额_元'])
```

均值和中位数的取舍是关键：**列里有异常大值（比如某天卖了 100 万）时，均值会被拉高，用均值填充会把"普通的一天"填成偏高的数字**，这时中位数更可信。删行则是双刃剑——缺失集中在某一家门店时，删掉会让这家门店彻底从样本里消失，分析结论会系统性地偏向其他门店。

**翻车现场 2：NaN 不能直接转 int。**

```python
# WRONG：含 NaN 的整数列转 int 必然失败
df['客流量_int'] = df['客流量'].astype(int)
# ValueError: cannot convert float NaN to integer
```

pandas 的整数类型不能表达缺失，于是 NaN（本质是 float）和 int 互不相容。**思路是先填再转**：`df['客流量'].fillna(0).astype(int)`。或者干脆保留 float——在很多业务场景里，`客流量=0` 和 `客流量=未知` 是两码事，把未知硬填成 0 是另一种失真。pandas 的 `Int64`（大写）是可空整数类型，能同时表达整数和缺失，是新版本里的推荐写法：`df['客流量'].astype('Int64')`。

## 第三步：异常值，先定性再动手

异常值不一定错。北京某门店双十一当天卖了 10 万，是异常，但真实。清洗的任务是**识别出来**，而不是无脑删除。

```python
sales = pd.Series([980, 1000, 1200, 1300, 1500, 3200, 8800, 1050, 1100, 1250])
q1, q3 = sales.quantile(0.25), sales.quantile(0.75)
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr
print(f'Q1={q1}, Q3={q3}, IQR={iqr}')
print(f'上下界: [{lower}, {upper}]')
# Q1=1050.0, Q3=1350.0, IQR=300.0
# 上下界: [600.0, 1800.0]

mask = (sales < lower) | (sales > upper)
print('异常值:', sales[mask].tolist())   # [3200, 8800]
```

这套方法叫 **IQR（四分位距）法**：低于 Q1−1.5×IQR 或高于 Q3+1.5×IQR 的点被视为异常。它不依赖均值和方差，所以对偏态分布天然友好——这是它比"均值±3 倍标准差"更常用的原因。

**翻车现场 3：IQR 上下界算错。**

```python
# WRONG：把减法顺序写反，得到负的下界再取 abs
lower_wrong = abs(q1 - 1.5 * iqr)      # 很多人直觉写 abs
print(lower_wrong)                      # 350.0  ← 完全错了
```

`abs(q1 - 1.5*iqr)` 算出来是 350，而不是 −300 再自然变成下界的问题。**方向错了，后面所有判断都反了**：本该被抓出来的低点全放过了，还可能把正常值判成异常。正确写法就是 `q1 - 1.5*iqr` 和 `q3 + 1.5*iqr`，别加 `abs`，别减反。如果你的数据确实全是正数、想保证下界不为负，那是业务层面的截断（`max(0, lower)`），不是算法本身。

## 第四步：派生字段，把信息榨出来

类型、缺失、异常都处理完，下一步是造字段。好的派生字段能把隐藏的信息抬到模型面前。

```python
df['日期_dt'] = pd.to_datetime(df['日期'], errors='coerce')
df['月份'] = df['日期_dt'].dt.month
df['星期'] = df['日期_dt'].dt.dayofweek          # 0=周一
df['是否周末'] = df['星期'].isin([5, 6]).astype(int)
df['客单价'] = (df['销售额_元'] / df['客流量']).round(2)

# 门店维度的聚合派生
city_avg = df.groupby('门店')['销售额_元'].transform('mean')
df['相对门店均值'] = (df['销售额_元'] - city_avg).round(2)

print(df[['门店', '月份', '是否周末', '客单价', '相对门店均值']])
```

`dt` 访问器能拆出年月日、星期、季度；`transform('mean')` 配合 groupby 能把"该门店的平均销售额"按原行广播回来，减一减就是"比门店均值高还是低"——这是零售分析里高频使用的相对指标。

派生字段有三层价值：一是**降低模型理解成本**（星期几比原始日期字符串好用），二是**创造可解释特征**（客单价直接反映经营效率），三是**做群体对比**（相对门店均值看出哪家门店拖了后腿）。

但别造过头。两个高度相关的字段（`销售额` 和 `销售额_元`）留在同一张表里，会让线性回归的系数解释变得混乱；把目标变量泄露进特征（比如用"总销售额"去预测"日销售额"）则是更隐蔽的错误。

## 清洗流水线：一步接一步，别跳步

```python
def clean_store(df):
    out = df.copy()
    # 1. 类型转换
    out['销售额_元'] = pd.to_numeric(
        out['销售额'].str.replace('[元,]', '', regex=True), errors='coerce')
    out['客流量'] = pd.to_numeric(out['客流量'], errors='coerce')
    # 2. 缺失：数值填中位数，类别填"未知"
    out['客流量'] = out['客流量'].fillna(out['客流量'].median())
    out['备注'] = out['备注'].fillna('正常')
    # 3. 异常：用 IQR 上下界截断到边界（而非删除）
    q1, q3 = out['销售额_元'].quantile([.25, .75])
    lo, hi = q1 - 1.5*(q3-q1), q3 + 1.5*(q3-q1)
    out['销售额_元'] = out['销售额_元'].clip(lo, hi)
    # 4. 派生
    out['日期_dt'] = pd.to_datetime(out['日期'], errors='coerce')
    out['月份'] = out['日期_dt'].dt.month
    out['客单价'] = (out['销售额_元'] / out['客流量']).round(2)
    return out

print(clean_store(df))
```

这条流水线体现了清洗的顺序原则：**先转类型，再补缺失，再处理异常，最后派生**。顺序反了会有麻烦——在含 `,` 的字符串上算中位数毫无意义；在缺失还没处理时算 IQR，中位数本身就已经被 NaN 污染了；派生客单价时若客流量还是字符串，会直接报错。每一步都依赖前一步的输出，这就是不能跳步的原因。

## 小结

- `pd.to_numeric(errors='coerce')` 是日常转换的默认选择，脏值变 NaN 而非崩溃
- 混入单位先 `str.replace` 去符号，再转换
- 缺失值：均值填充适合近似正态，中位数填充抗异常值；删行会让缺失集中的门店从样本消失
- NaN 不能直接 `astype(int)`，先 `fillna` 或用可空整数 `Int64`
- 异常值用 IQR 法：Q1−1.5×IQR 和 Q3+1.5×IQR 为界，别写反也别加 `abs`
- 派生字段的价值在降低理解成本、创造可解释特征、做群体对比
- 清洗顺序固定：转类型 → 补缺失 → 处理异常 → 派生
