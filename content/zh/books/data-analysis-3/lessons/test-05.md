## 第一部分 · 选择题

---

```quiz
type: choice
exam: true
q: 从业务问题到最终出图，正确的第一步是？
options:
- 打开 Excel 把数据做成柱状图
- 明确"这张图要回答什么问题"——先有结论方向，再选图表类型
- 把数据库里所有表都导出来再说
- 选一个好看的配色方案
answer: 1
explain: 画图之前必须先明确"我要回答什么问题"。是看趋势、看分布、还是比较分类？问题决定了图表类型：趋势用折线，分布用直方图/箱线，比较用柱状/散点。没有问题的图只是装饰，不是分析。
```

```quiz
type: choice
exam: true
q: 一份完整的 EDA（探索性数据分析）流程，正确的顺序是？
options:
- 清洗缺失值 → 画图 → 分组聚合 → 写结论
- 了解数据（shape/head/describe/类型）→ 清洗（缺失、重复、类型）→ 单变量分布 → 多变量关系 → 分组洞察 → 结论
- 分组聚合 → 画热力图 → 删掉不需要的列 → 导出
- 导入库 → 写标题 → 画图 → 提交
answer: 1
explain: 标准 EDA 流程是从宏观到微观、从数据质量到业务洞察的递进：先了解数据全貌（shape、head、dtypes、describe），再做清洗（缺失值、重复值、异常值、类型转换），然后看单变量分布，再看变量间关系，最后做分组聚合找差异并提炼结论。跳步容易得出错误结论。
```

```quiz
type: choice
exam: true
q: 下面哪种做法最可能"骗人"？
options:
- 把 Y 轴从 0 截断，让微小差异看起来像巨大差距
- 在柱状图上标注具体数值
- 用对数刻度并在标题注明"log scale"
- 在折线图横轴标注完整日期范围
answer: 0
explain: 截断 Y 轴是最常见的视觉误导手段：把纵轴起点设为接近最小值而非 0，会让两个接近的柱子看起来差了好几倍。反之，标注数值、注明对数刻度、标注完整日期范围都是增强可读性和诚实性的好做法。
```

```quiz
type: choice
exam: true
q: 双 Y 轴图（左右各一个纵轴）的主要风险是？
options:
- 会让图变得太大
- 两条刻度尺的视觉基准不同，容易误导读者把高度差解读为数量关系
- 配色会冲突
- 运行速度变慢
answer: 1
explain: 双 Y 轴最大的问题是：左轴量纲（如销售额）和右轴量纲（如客流量）完全不同，但读者会不自觉地用柱子的"视觉高度"做比较，得出"销售额和客流量差不多"之类的错误结论。如果必须画，建议拆成两张图或使用标准化后的指数。
```

```quiz
type: choice
exam: true
q: 某门店 A 转化率 5%（样本 2000 人），门店 B 转化率 7%（样本 50 人）。只看百分比谁更好，问题在哪？
options:
- 门店 B 的颜色不好看
- 门店 B 样本量仅 50 人，7% 可能是随机波动，样本太小导致结论不可靠
- 5% 比 7% 差距太小，不值得画
- 应该把两个门店合并统计
answer: 1
explain: 小样本的高百分比往往不稳定。门店 B 只有 50 个样本，3.5 个转化和 2.5 个转化的差距在统计上并不显著——多一两个转化，百分比就跳好几个点。画图时必须同时呈现样本量（用气泡大小、标注 n 值、或并排画置信区间），否则容易被小样本的噪声误导。
```

```quiz
type: function
exam: true
q: 写一个函数 sample_size_warning，接收两个门店的转化数据（各自的总人数和转化人数），返回提示信息。如果任一门店样本量小于 100，返回字符串"样本量不足，结论不可靠"；否则计算两店转化率差值的百分点，返回形如"门店A转化率X.X%，门店B转化率Y.Y%，差距Z.Z个百分点"的字符串。
func: sample_size_warning
starter: |
  def sample_size_warning(a_total, a_conv, b_total, b_conv):
      return ""
cases: |
  (2000, 100, 50, 4) -> "样本量不足，结论不可靠"
  (2000, 100, 2000, 140) -> "门店A转化率5.0%，门店B转化率7.0%，差距2.0个百分点"
  (100, 5, 150, 9) -> "样本量不足，结论不可靠"
  (500, 25, 500, 35) -> "门店A转化率5.0%，门店B转化率7.0%，差距2.0个百分点"
hint: if min(a_total,b_total)<100: return "样本量不足，结论不可靠"; ra,rb=a_conv/a_total*100,b_conv/b_total*100; return f"门店A转化率{ra:.1f}%，门店B转化率{rb:.1f}%，差距{abs(ra-rb):.1f}个百分点"
explain: 样本量检查是数据故事化的基本功。先判断数据是否"够格"得出结论，再计算差异。返回格式化字符串而非画图，便于在报告脚本中直接使用。
```
