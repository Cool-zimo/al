# 嵌套结构怎么取：多层 dict 与 list 的取值

> 这一课解决"JSON 读进来后，怎么安全地一层层取到深处的值"。你会学会 `get` 链式取值，避免 KeyError 让你的脚本整段崩掉。

## JSON 的数据结构本质就是 dict 和 list 的嵌套

真实接口返回的 JSON 从不会是扁平的。比如查一个用户的订单详情：

```python
import json

raw = '''
{
    "code": 0,
    "msg": "ok",
    "data": {
        "user": {
            "id": 10086,
            "name": "张三",
            "address": {
                "city": "北京",
                "district": "海淀区"
            }
        },
        "orders": [
            {"id": "DD001", "total": 199.0, "status": "paid"},
            {"id": "DD002", "total": 59.0, "status": "pending"}
        ]
    }
}
'''

resp = json.loads(raw)
```

这里面：`resp` 是字典，取 `"data"` 得到字典，取 `"user"` 得到字典，取 `"address"` 得到字典；取 `"orders"` 得到列表，列表里又是字典。

**取值的基本动作就是反复用 `[]`**：

```python
city = resp["data"]["user"]["address"]["city"]
print(city)                # 北京

first_order_id = resp["data"]["orders"][0]["id"]
print(first_order_id)      # DD001
```

## 翻车现场：一层取不到就 KeyError 全崩

线上接口最常出问题的就是：某个字段**可能不存在**。比如用户没填地址：

```python
import json

raw = '''
{
    "code": 0,
    "data": {
        "user": {
            "name": "张三"
        }
    }
}
'''

resp = json.loads(raw)
district = resp["data"]["user"]["address"]["district"]
print(district)
```

报错：

```
KeyError: 'address'
```

只要某一层缺键，整条取值链就断掉，后面的逻辑全不执行。对一个"可能不完整的外部数据"用 `[]` 硬取，是极不稳健的。

## 用 get 做安全取值

字典的 `get` 方法允许你指定"取不到时返回什么"：

```python
d = {"name": "张三"}
print(d.get("age"))            # None（不存在的键，默认返回 None）
print(d.get("age", 18))        # 18（指定默认值）
```

**嵌套取值时，把每一层都换成 get**：

```python
resp = json.loads(raw)

city = resp.get("data", {}).get("user", {}).get("address", {}).get("city", "未知")
print(city)                    # 未知（因为这份数据里没有 address）
```

链式写法 `resp.get("data", {}).get(...)` 为什么安全？因为：

- 如果 `"data"` 不存在，`resp.get("data", {})` 返回 `{}`
- 对空字典 `{}` 再 `.get("user", {})`，还是返回 `{}`
- 一路返回 `{}`，最后 `.get("city", "未知")` 返回 `"未知"`

**关键在于每一层 get 的默认值都是一个空字典 `{}`**，这样下一层还能继续 `.get` 下去，不会 `None.get(...)` 报错。

## 翻车现场：默认值用 None 导致链式崩溃

```python
# WRONG：默认值是 None，下一层 .get 就崩了
city = resp.get("data", None).get("user", None).get("city", "未知")
```

报错：

```
AttributeError: 'NoneType' object has no attribute 'get'
```

**记住**：链式中每一层的默认值必须是"同种空容器"——字典就用 `{}`，列表就用 `[]`，这样才能继续往下取。

## 列表的安全取值：先判长度

列表索引不存在时会报 `IndexError`：

```python
orders = resp["data"]["orders"]

# WRONG
first = orders[0]          # 如果 orders 是空列表，就 IndexError

# 正确：先判长度
if orders:
    print(orders[0]["id"])
else:
    print("没有订单")
```

或者用 `next` + 默认值（Python 小技巧）：

```python
first = next(iter(orders), None)
print(first)                # 第一个元素或 None
```

## 实战：从真实接口里提取信息

下面这段代码模拟处理一份订单接口响应，安全地把各字段取出来：

```python
import json

def extract_order_info(raw):
    """从接口响应里提取订单概要，缺失字段用默认值补齐"""
    resp = json.loads(raw)

    # 安全取值链
    user_name = resp.get("data", {}).get("user", {}).get("name", "匿名用户")
    city = resp.get("data", {}).get("user", {}).get("address", {}).get("city", "未知")

    orders = resp.get("data", {}).get("orders", [])
    paid_count = sum(1 for o in orders if o.get("status") == "paid")
    total_amount = sum(o.get("total", 0) for o in orders)

    return {
        "user": user_name,
        "city": city,
        "order_count": len(orders),
        "paid_count": paid_count,
        "total_amount": round(total_amount, 2)
    }

raw = '''
{
    "code": 0,
    "data": {
        "user": {"name": "张三", "address": {"city": "北京"}},
        "orders": [
            {"id": "DD001", "total": 199.0, "status": "paid"},
            {"id": "DD002", "total": 59.0, "status": "pending"},
            {"id": "DD003", "total": 320.0, "status": "paid"}
        ]
    }
}
'''

info = extract_order_info(raw)
print(f"用户：{info['user']}，城市：{info['city']}")
print(f"订单数：{info['order_count']}，已付款：{info['paid_count']}，合计：¥{info['total_amount']}")
```

输出：

```
用户：张三，城市：北京
订单数：3，已付款：2，合计：¥578.0
```

把 `raw` 里的 `address` 整段删掉再跑一次，结果会是 `城市：未知`，但**程序不会崩**。

## 翻车现场：用 try/except 包裹整段取值，掩盖真问题

有人图省事：

```python
# 不太推荐
try:
    city = resp["data"]["user"]["address"]["city"]
except (KeyError, TypeError):
    city = "未知"
```

这种写法能用，但有两个问题：

1. `TypeError` 会掩盖"某一层不是字典"的真正 bug（比如接口返回了字符串）
2. 大段 `try` 块让定位问题变难

**`get` 链式取值更清晰、更精确**，是处理不确定结构数据的首选。

## 一个更简洁的写法：自定义取值函数

如果你经常要写深层取值，可以封装一个工具：

```python
def dig(obj, *keys, default=None):
    """沿 keys 一路往下取，取不到返回 default"""
    cur = obj
    for k in keys:
        if isinstance(cur, dict):
            cur = cur.get(k)
        elif isinstance(cur, list) and isinstance(k, int):
            try:
                cur = cur[k]
            except IndexError:
                return default
        else:
            return default
        if cur is None:
            return default
    return cur

resp = json.loads(raw)
print(dig(resp, "data", "user", "address", "city", default="未知"))  # 北京
print(dig(resp, "data", "orders", 0, "id", default="无"))            # DD001
```

`dig(obj, "a", "b", "c")` 等价于 `obj["a"]["b"]["c"]`，但全程安全。这种写法在配置读取、接口解析里非常常见。

## 小结

- JSON 就是 `dict` + `list` 的嵌套组合，取值靠反复 `[]`
- 对外部数据用 `[]` 硬取会 KeyError 全崩
- **链式安全取值**：`resp.get("a", {}).get("b", {}).get("c", default)`
- 每一层的默认值必须是**同种空容器**（`{}`/`[]`），否则下一层 `.get` 崩
- 列表先判长度或用 `next(iter(x), None)` 避免 IndexError
- 频繁深层取值可封装 `dig` 工具函数
- `try/except` 包裹整段取值能工作，但不如 `get` 精确清晰
