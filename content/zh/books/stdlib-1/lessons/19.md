# base64：把二进制塞进只认文本的地方

> 这一课解决"图片、签名、压缩包怎么塞进 JSON / 邮件 / URL"。二进制字节不能裸放在文本协议里，base64 就是那段"翻译层"——它把 3 字节变成 4 个可打印字符。

## 问题：二进制不能裸放在文本协议里

想象你在做一个接口，要往 JSON 里塞一张用户头像：

```python
import json

avatar = b"\x89PNG\r\n\x1a\n\x00..."   # 一张 PNG 的字节
payload = {"user": "张三", "avatar": avatar}

# WRONG
json.dumps(payload)
```

报错：

```
TypeError: Object of type bytes is not JSON serializable
```

JSON 只认识字符串（而且是 Unicode），不认识 `bytes`。你也不能直接把字节"当字符串"拼进去——`\x89` 这类高位字节在不少传输链路上会被改写、截断、或被判成非法 UTF-8。

**解法：先把字节编成 ASCII 字符，再放进去。base64 干的就是这件事。**

## 最小可用：b64encode / b64decode

```python
import base64

data = b"\x89PNG\r\n\x1a\n"          # 任意二进制
encoded = base64.b64encode(data)     # 返回 bytes
text = encoded.decode("ascii")       # 转成字符串就能进 JSON 了

print("编码后:", text)
print("长度: ", len(text), "字符")

# 还原
back = base64.b64decode(text)
print("还原后:", back, "相等:", back == data)
```

输出：

```
编码后: iVBORw0KGgo=
长度:  12 字符
还原后: b'\x89PNG\r\n\x1a\n' 相等: True
```

注意三点：

1. `b64encode` 吃 `bytes`，吐 `bytes`——所以还要 `.decode("ascii")` 才拿到字符串。
2. 输出只含 `A-Z a-z 0-9 + /` 和填充符 `=`，**全是 ASCII 可打印字符**，塞进 JSON、邮件、XML 都不会出问题。
3. 体积膨胀约 **4/3 倍**（3 字节变 4 字符），加上填充可能到 1.37 倍。传大文件用它等于白白多传 33% 流量，别这么干。

## 把图片塞进 JSON：完整流程

这才是 base64 的主战场——接口里附带小体积二进制。

```python
import json
import base64

def wrap_file(name, raw_bytes):
    return {
        "name": name,
        "size": len(raw_bytes),
        "data_b64": base64.b64encode(raw_bytes).decode("ascii"),
    }

png_header = b"\x89PNG\r\n\x1a\n" + b"\x00" * 10
msg = wrap_file("logo.png", png_header)
print(json.dumps(msg, ensure_ascii=False, indent=2))
```

输出：

```
{
  "name": "logo.png",
  "size": 14,
  "data_b64": "iVBORw0KGgoAAAAAAgAAAAA="
}
```

反向解析：

```python
import json
import base64

doc = json.loads('{"name":"logo.png","size":14,"data_b64":"iVBORw0KGgoAAAAAAgAAAAA="}')
raw = base64.b64decode(doc["data_b64"])
print(raw == png_header)        # True
```

这就是"文件上传/下载接口里带缩略图"的标准实现方式。

## urlsafe_b64encode：让结果能安全进 URL

标准 base64 用了 `+` 和 `/`，这两个字符在 URL 里有特殊含义（`+` 会被当成空格、`/` 是路径分隔符）。把标准 base64 直接拼进链接会出错。

```python
import base64

raw = b"hello+/world"

std = base64.b64encode(raw).decode()
url = base64.urlsafe_b64encode(raw).decode()

print("标准: ", std)     # aGVsbG8rL3dvcmxk
print("URL安全:", url)    # aGVsbG8rL3dvcmxk
```

这例子碰巧一样，因为没触发差异。差异点在 `+ /`：URL 安全版把 `+` 换成 `-`、`/` 换成 `_`，这样结果里**一个特殊字符都没有**，可以直接拼进查询参数。

```python
import base64

raw = b"\xff\xfe\xfd\xfc"          # 高位字节，容易触发 / 和 +
std = base64.b64encode(raw).decode()
url = base64.urlsafe_b64encode(raw).decode()
print("标准: ", std)
print("URL安全:", url)

# 拼进 URL 毫无压力
link = "https://example.com/token=" + url
print(link)
```

输出：

```
标准:  //7//A==
URL安全: __7__A==
https://example.com/token=__7__A==
```

**凡是要进 URL、文件名、HTTP header 的值，一律用 `urlsafe_b64encode`**，养成肌肉记忆。

## 翻车现场一：编码字符串而不是字节

```python
import base64

# WRONG
base64.b64encode("张三")       # 想编码一个字符串
```

报错：

```
TypeError: a bytes-like object is required, not 'str'
```

`b64encode` 只认 `bytes`。想编码文本，先按某种编码转成字节：

```python
text = "张三"
encoded = base64.b64encode(text.encode("utf-8")).decode("ascii")
print(encoded)                          # 5a2Z5LiJ

decoded = base64.b64decode(encoded).decode("utf-8")
print(decoded)                          # 张三
```

**编码和解码必须成对：b64encode 处理 bytes、输出 bytes；要当字符串用就 decode 成 ascii；还原时先 b64decode 再按原编码 decode 回文本。**

## 翻车现场二：base64 不是加密

这是最常被误解的一点。base64 是**编码**，不是加密——任何人拿到字符串，一秒就能解码回原文。

```python
import base64

secret = "password123"
encoded = base64.b64encode(secret.encode()).decode()
print("看起来很乱:", encoded)            # cGFzc3dvcmQxMjM=

# 但谁都能解开
print(base64.b64decode(encoded).decode())  # password123
```

**base64 的目的是"安全传输"，不是"保密"。** 要保密请用 `secrets`/`hashlib`/`cryptography`，别拿 base64 糊弄。第 20 课会讲摘要和"为什么不能存明文密码"。

## 翻车现场三：等号 `=` 被 URL 处理吃掉

标准 base64 用 `=` 做填充。某些老旧 HTTP 库或日志系统会把行尾的 `=` 当"参数结束符"丢掉。如果解码端收到缺填充的字符串，`b64decode` 会报错：

```python
import base64

try:
    base64.b64decode("iVBOR")      # 缺了最后两个 =
except Exception as e:
    print(type(e).__name__, e)
```

输出：

```
binascii.Error Incorrect padding
```

两个对策：URL 场景一律 `urlsafe_b64encode`（它本身不解决填充问题，但字符集安全）；遇到缺填充的字符串，先补 `=` 再解：

```python
import base64

def safe_b64decode(text):
    pad = 4 - len(text) % 4
    if pad != 4:
        text = text + "=" * pad
    return base64.b64decode(text)

print(safe_b64decode("iVBOR"))          # b'\x89PNG'
print(safe_b64decode("iVBORw0K"))       # b'\x89PNG\xd0\xd0'
```

## 小结

- base64 把 3 字节二进制变成 4 个 ASCII 字符，用来把 bytes **塞进只认文本的地方**（JSON、邮件、XML、URL）
- `b64encode` 吃 `bytes` 吐 `bytes`，要当字符串用得再 `.decode("ascii")`
- **凡是要进 URL，用 `urlsafe_b64encode`**（把 `+`/`/` 换成 `-`/`_`）
- 代价是体积膨胀约 1.33 倍，**只适合小数据**（缩略图、令牌、签名、小附件）
- base64 是编码不是加密，**别拿它当保密手段**
- 解码前记得处理 `=` 填充
