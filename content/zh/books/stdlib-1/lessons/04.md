# 读写文件：dump、load 与那三个关键参数

> 这一课讲怎么把 JSON 真正存到磁盘、再从磁盘读回来。你会学到 `ensure_ascii`、`indent`、`sort_keys` 三个让文件"既好用又好看"的参数。

## dump：把对象直接写进文件

前面学过 `dumps` 返回字符串。如果最终目的是存文件，`dump` 一步到位：

```python
import json

config = {
    "app_name": "订单管理系统",
    "version": "1.2.0",
    "debug": False,
    "max_workers": 8
}

with open("config.json", "w") as f:
    json.dump(config, f)
```

`dump(obj, f)` 接收两个参数：要序列化的对象和**已经打开的文件对象**。它内部帮你 `write`，你不用再调一次。

读取同理，用 `load(f)`：

```python
with open("config.json") as f:
    cfg = json.load(f)

print(cfg["app_name"])      # 订单管理系统
print(cfg["max_workers"])   # 8
```

**`dump`/`load` 与 `dumps`/`loads` 的区别只有一件事：要不要自己管文件**。要存盘用 `dump`，要在内存里处理用 `dumps`。

## ensure_ascii=False：让中文正常显示

这是新手问得最多的问题。先看默认行为：

```python
import json

data = {"city": "北京", "slogan": "我爱编程"}

print(json.dumps(data))
# {"city": "\u5317\u4eac", "slogan": "\u6211\u7231\u7f16\u7a0b"}
```

中文全变成了 `\u5317\u4eac` 这种**转义序列**。

这不是 bug，是 `json.dumps` 的默认策略：为了"在任何编码环境下都绝对安全"，它把所有非 ASCII 字符都转成 `\uXXXX`。数据没丢、解析也正常，就是**人看不懂**。

解决办法：加 `ensure_ascii=False`：

```python
print(json.dumps(data, ensure_ascii=False))
# {"city": "北京", "slogan": "我爱编程"}
```

写文件时同样适用：

```python
with open("city.json", "w") as f:
    json.dump(data, f, ensure_ascii=False)
```

现在打开 `city.json`，中文清清楚楚。

**结论**：只要你的数据里有中文，几乎永远应该写 `ensure_ascii=False`。唯一例外是你明确要兼容只认 ASCII 的老旧系统。

## indent：让文件有层次

默认输出的 JSON 是**一行挤在一起**的，机器读没问题，人维护起来要命。

```python
import json

users = {
    "users": [
        {"name": "张三", "age": 20, "city": "北京"},
        {"name": "李四", "age": 25, "city": "上海"}
    ],
    "count": 2
}

print(json.dumps(users))
# {"users": [{"name": "张三", "age": 20, "city": "北京"}, {"name": "李四", "age": 25, "city": "上海"}], "count": 2}
```

加 `indent=2`：

```python
print(json.dumps(users, indent=2, ensure_ascii=False))
```

输出：

```json
{
  "users": [
    {
      "name": "张三",
      "age": 20,
      "city": "北京"
    },
    {
      "name": "李四",
      "age": 25,
      "city": "上海"
    }
  ],
  "count": 2
}
```

`indent=2` 表示每层缩进 2 个空格。**配置文件、日志文件强烈建议加 indent**，因为你可能要手动改、要 diff、要排查问题。

## sort_keys：键按字母排序

```python
import json

profile = {"name": "张三", "age": 20, "city": "北京"}

print(json.dumps(profile, sort_keys=True))
# {"age": 20, "city": "北京", "name": "张三"}
```

键被按字母顺序排了。什么时候需要它？

- **要做版本对比（diff）**：排序后两个文件只要内容一致，diff 就是空，不会被顺序干扰
- **调试**：顺序固定，一眼能找到某个字段
- **写测试快照**：序列化结果稳定可预测

不需要的场景（追求性能、字段顺序本身有意义）就别开，因为排序本身有开销。

## 翻车现场：忘记加 encoding，中文文件在 Windows 上变乱码

```python
import json

data = {"msg": "你好世界"}

# WRONG：在 Windows 上默认可能是 gbk 编码打开
with open("hello.json", "w") as f:
    json.dump(data, f, ensure_ascii=False)
```

在 Windows 中文系统上，`open()` 默认用 GBK 编码。你以为写的是 UTF-8，实际写的是 GBK。换到别的程序（或 Linux 服务器）读，就会乱码。

**正确做法**：明确指定 `encoding="utf-8"`：

```python
with open("hello.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False)

# 读取时同样指定
with open("hello.json", encoding="utf-8") as f:
    obj = json.load(f)
```

> 关于编码的细节，第 05 课会专门展开。

## 三个参数怎么组合用

实际项目里最常见的写法就这一条：

```python
import json

def save_json(obj, path):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(obj, f, ensure_ascii=False, indent=2)

def load_json(path):
    with open(path, encoding="utf-8") as f:
        return json.load(f)
```

四个保证：`ensure_ascii=False` 中文可读、`indent=2` 格式清晰、`encoding="utf-8"` 跨平台不乱码、`with` 语句自动关文件。

## 实战：保存并读取一份成绩单

```python
import json

report = {
    "class": "高三(1)班",
    "exam": "2026 年 9 月月考",
    "students": [
        {"name": "张三", "chinese": 118, "math": 135, "english": 122},
        {"name": "李四", "chinese": 105, "math": 142, "english": 130},
        {"name": "王五", "chinese": 128, "math": 98, "english": 115}
    ]
}

# 保存
with open("report.json", "w", encoding="utf-8") as f:
    json.dump(report, f, ensure_ascii=False, indent=2, sort_keys=False)

# 读取并统计
with open("report.json", encoding="utf-8") as f:
    data = json.load(f)

print(f"班级：{data['class']}  考试：{data['exam']}")
print("-" * 30)
for s in data["students"]:
    avg = round((s["chinese"] + s["math"] + s["english"]) / 3, 1)
    print(f"{s['name']}  总分：{s['chinese']+s['math']+s['english']}  均分：{avg}")
```

输出：

```
班级：高三(1)班  考试：2026 年 9 月月考
------------------------------
张三  总分：375  均分：125.0
李四  总分：377  均分：125.7
王五  总分：341  均分：113.7
```

打开 `report.json`，你会看到一份排版整齐、中文清晰、随时可手改的 JSON 文件。这就是 `indent` 和 `ensure_ascii` 的价值。

## 小结

- `dump(obj, f)` 写文件，`load(f)` 读文件；`dumps`/`loads` 只处理字符串
- **中文必加 `ensure_ascii=False`**，否则变 `\uXXXX` 转义
- **配置文件必加 `indent=2`**，人能看懂、能 diff
- **需要对比/快照时加 `sort_keys=True`**，序列化结果稳定
- 读写文件**都显式指定 `encoding="utf-8"`**，避免 Windows 默认 GBK 的坑
- 推荐封装 `save_json` / `load_json` 两个工具函数统一使用
