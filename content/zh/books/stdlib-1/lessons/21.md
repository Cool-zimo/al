# decimal：为什么 ¥0.1 + ¥0.2 不等于 ¥0.3

> 这一课彻底解决"金额为什么不能用 float"的问题。你会在课上亲眼看到 `0.1 + 0.2` 的坑，并学会用 `decimal.Decimal` 把它做对——**构造时用字符串，不是 float**。

## 浮点经典坑：0.1 + 0.2 ≠ 0.3

先回忆（第 03 课提过，这里讲透）。

```python
a = 0.1 + 0.2
print(a)              # 0.30000000000000004
print(a == 0.3)       # False
```

为什么？因为计算机用二进制存小数，`0.1` 在二进制里是**无限循环小数**，存进 64 位 float 时必然被截断。十次加法下来，误差足以让你对账失败。

**坑在哪**：错误不是一开始就出现，而是**累积到一定量级才暴露**——可能上线三个月、跑了几百万笔账之后才报。所以"我试了几个数都对"根本不算验证。

## Decimal：用十进制做精确计算

`decimal` 模块用**十进制**而不是二进制存小数，位数想多长就多长，不会出现二进制截断。

```python
from decimal import Decimal

a = Decimal("0.1") + Decimal("0.2")
print(a)              # 0.3
print(a == Decimal("0.3"))   # True
```

输出：

```
0.3
True
```

干净利落。

## 翻车现场一：Decimal(0.1) 是错的

这是最容易踩、也最隐蔽的错。`Decimal(0.1)` 会**先保留 float 的误差，再把那个误差包装成 Decimal**——垃圾进、垃圾出。

```python
from decimal import Decimal

print(Decimal(0.1))          # 0.1000000000000000055511151231257827021181583404541015625
print(Decimal("0.1"))        # 0.1
```

输出：

```
0.1000000000000000055511151231257827021181583404541015625
0.1
```

**规则记住：从外部进来的金额，一律用字符串构造 `Decimal("19.90")`；只有你确信是整数的场景（比如"分"作单位）才用 `Decimal(1990)`。**

```python
from decimal import Decimal

# 正确
price = Decimal("19.90")
qty = 3
total = price * qty
print(total)          # 59.70

# 也正确：金额一律用"分"作整数存
cents = Decimal(1990) * Decimal(3) / Decimal(100)
print(cents)          # 59.70
```

## 翻车现场二：除法会爆出无限小数，精度不够就报错

```python
from decimal import Decimal

# WRONG：默认精度下除不尽
Decimal(1) / Decimal(3)
```

输出：

```
Decimal('0.3333333333333333333333333333')
```

看起来没事，但你算 `1 / 3 * 3` 就想当然以为能还原成 1，而且**如果上下文精度被调小**，会抛 `DivisionByZero` 或 `InvalidOperation`。更重要的是：**除法的位数如果不设上限，结果可能无限长**。

```python
from decimal import Decimal, getcontext

getcontext().prec = 4          # 临时把精度调成 4 位
try:
    print(Decimal(1) / Decimal(3))
except Exception as e:
    print(type(e).__name__, e)

# 恢复默认精度
getcontext().prec = 28
```

输出：

```
DivisionByZero [<class 'decimal.DivisionImpossible'>]
```

（具体异常取决于精度和 rounding 模式，核心是"精度不够就报错"。）

## quantize：把结果"四舍五入到分"

金额算完必须"落到分"——不能出现 `59.7000001` 或无限位。用 `quantize` 指定精度：

```python
from decimal import Decimal

price = Decimal("19.876")
qty = Decimal("3")
total = price * qty
print("原始:", total)                 # 59.628

rounded = total.quantize(Decimal("0.01"))   # 精确到分
print("精确到分:", rounded)                  # 59.63
```

`Decimal("0.01")` 这个参数就是"我想精确到几位"的模板——写 `"0.1"` 是角、`"0.01"` 是分、`"0.0001"` 是万分之一。

## 翻车现场三：round 用的是"银行家舍入"

Python 的 `round` 用的是**银行家舍入**（四舍六入五成双）：5 会向最近的偶数靠拢，目的是在大量统计中减少累计偏差。但银行家舍入**不等于"四舍五入"**：

```python
from decimal import Decimal, ROUND_HALF_UP

print(round(Decimal("1.25"), 1))   # 1.2  ← 银行家舍入：.25 向偶数 1.2 靠拢
print(round(Decimal("1.35"), 1))   # 1.4  ← .35 向偶数 1.4 靠拢

# 想要真正的小数"四舍五入"，显式指定
print(Decimal("1.25").quantize(Decimal("0.1"), rounding=ROUND_HALF_UP))   # 1.3
print(Decimal("1.35").quantize(Decimal("0.1"), rounding=ROUND_HALF_UP))   # 1.4
```

输出：

```
1.2
1.4
1.3
1.4
```

**业务里"四舍五入"请用 `quantize(..., rounding=ROUND_HALF_UP)`**，别指望 `round`。

## 负数舍入的坑

舍入规则对负数有时反直觉：

```python
from decimal import Decimal, ROUND_HALF_UP, ROUND_HALF_EVEN

print(Decimal("-1.5").quantize(Decimal("1."), rounding=ROUND_HALF_UP))    # -1.5 → -2
print(Decimal("-1.5").quantize(Decimal("1."), rounding=ROUND_HALF_EVEN))  # -1.5 → -2
```

`ROUND_HALF_UP` 是"远离零"的方向，`ROUND_HALF_EVEN` 是向偶数。处理退款、负余额时确认你用的是哪一套会计规则。

## 实战：算一笔订单的含税总价

```python
from decimal import Decimal, ROUND_HALF_UP

def order_total(unit_price, qty, tax_rate):
    """含税金额，精确到分，采用四舍五入。"""
    price = Decimal(unit_price)
    subtotal = price * qty
    tax = subtotal * Decimal(tax_rate)
    total = subtotal + tax
    return total.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

print(order_total("19.90", 3, "0.13"))    # 单价19.90 数量3 税率13%
print(order_total("9.99", 7, "0.06"))
```

输出：

```
67.40
74.03
```

## 小结

- 浮点用二进制存小数，`0.1+0.2` 会有截断误差，金额场景绝不能碰 float
- **Decimal 一律用字符串构造**：`Decimal("0.1")` 对，`Decimal(0.1)` 错
- `quantize(Decimal("0.01"))` 把结果精确到分；`"0.1"` 是角、`"0.01"` 是分
- `round` 用银行家舍入，**业务"四舍五入"用 `ROUND_HALF_UP`**
- 除法可能无限长，记得先 `quantize` 再落地；涉及负数时确认会计规则
