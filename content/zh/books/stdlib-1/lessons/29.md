# 第 29 课 · 数据管道：输出与日志

> 输出层负责把清洗好的数据写出去，日志负责告诉开发者程序内部发生了什么。

## 输出到 JSON

通过的记录要写回文件。先转成可序列化格式：

```python
import json
from decimal import Decimal
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"

def record_to_dict(rec):
    """把标准 dict 转成可 JSON 序列化的 dict"""
    return {
        "id": rec["id"],
        "amount": str(rec["amount"]),       # Decimal → str
        "status": rec["status"],            # 已经是字符串
        "qty": int(rec["qty"]),
    }

def dump_json(records, filepath):
    data = [record_to_dict(r) for r in records]
    with open(filepath, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

**`record_to_dict` 负责类型转换**：Decimal 转 str、Enum 取 value。这是第 25 课就强调过的——`json.dump` 不认识自定义类型。

## 输出到 CSV

```python
import csv

def dump_csv(records, filepath):
    fieldnames = ["id", "amount", "status", "qty"]
    with open(filepath, "w", encoding="utf-8", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        for rec in records:
            writer.writerow(record_to_dict(rec))
```

`csv.DictWriter` 需要 `fieldnames` 参数。每行调用 `writeheader()` 写表头，然后逐条 `writerow`。

## 按扩展名分派输出

和读取层对称，输出层也按扩展名分派：

```python
def dump(records, filepath):
    if filepath.endswith(".json"):
        dump_json(records, filepath)
    elif filepath.endswith(".csv"):
        dump_csv(records, filepath)
    else:
        raise ValueError(f"不支持的输出格式: {filepath}")
```

**输入和输出格式可以不同**——比如读 JSON、写 CSV。这正是管道的灵活性所在。

## 为什么 print 不够用

管道跑起来后，你会在终端看到各种信息：

- 读取了几个文件
- 每条记录的校验结果
- 最终通过/失败统计
- 出错时的详细堆栈

如果全用 `print`，你会得到一坨分不清层次的东西。**你需要的是有级别、有格式、可以开关的日志系统**——这就是 `logging`。

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s [%(levelname)s] %(message)s",
    datefmt="%H:%M:%S",
)
logging.info("开始处理数据")
logging.warning("发现 3 条记录格式异常")
logging.error("无法打开文件 data.json")
```

输出：

```
14:30:05 [INFO] 开始处理数据
14:30:05 [WARNING] 发现 3 条记录格式异常
14:30:05 [ERROR] 无法打开文件 data.json
```

**带时间戳、带级别、带格式**——这就是 `print` 做不到的。

## 五个日志级别

| 级别 | 数值 | 用途 |
|------|------|------|
| `DEBUG` | 10 | 开发调试细节，默认不显示 |
| `INFO` | 20 | 正常流程信息 |
| `WARNING` | 30 | 不致命但需注意的问题 |
| `ERROR` | 40 | 出错了但程序还能跑 |
| `CRITICAL` | 50 | 致命错误，程序即将崩溃 |

```python
import logging

logging.debug("正在解析第 3 行")       # 默认看不到
logging.info("读取了 100 条记录")     # 能看到
logging.warning("金额字段缺失")       # 能看到
logging.error("JSON 解析失败")        # 能看到
```

**`basicConfig(level=...)` 控制最低显示级别**。设 `INFO` 时 `DEBUG` 被过滤掉，设 `DEBUG` 时全部显示。

## basicConfig 常用参数

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,                    # 最低显示级别
    format="%(asctime)s %(levelname)s %(name)s - %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S",           # 时间格式
    filename="pipeline.log",               # 输出到文件而非终端
    filemode="a",                          # 追加模式
)
```

| 参数 | 作用 |
|------|------|
| `level` | 最低显示级别 |
| `format` | 日志格式字符串 |
| `datefmt` | 时间格式 |
| `filename` | 输出到文件（不指定则输出到终端） |
| `filemode` | 文件模式，`w` 覆盖/`a` 追加 |

## 给用户看的 vs 给开发者看的

**这是日志设计的核心原则**：

- 给**用户**看的信息 → 用 `print()` 或专门的输出函数，简洁明了
- 给**开发者**看的信息 → 用 `logging`，带级别带上下文

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

def process_with_log(records):
    logging.info(f"开始处理 {len(records)} 条记录")
    passed, failed = check_all(records)  # 假设已有
    logging.info(f"处理完成: 通过 {len(passed)} 条")
    if failed:
        logging.warning(f"{len(failed)} 条记录校验失败")
    # 给用户看的报告
    print("✓ 处理完成")
    return passed, failed
```

**日志是"旁白"，输出是"台词"**。旁白给幕后人员看，台词给观众看，两者不能混。

## 小结

- 输出层用 `record_to_dict` 做类型转换（Decimal→str）
- JSON 用 `json.dump`，CSV 用 `csv.DictWriter`
- 输出也按扩展名分派，输入输出格式可以不同
- `logging` 提供有级别、有格式、可开关的日志
- 五个级别：DEBUG < INFO < WARNING < ERROR < CRITICAL
- `basicConfig` 配置级别、格式、输出目标
- 日志给开发者看，print 给用户看，不要混用

## 翻车现场一：CSV 忘记 newline=""

```python
import csv

# WRONG
# with open("out.csv", "w") as f:
#     writer = csv.writer(f)
#     writer.writerows(data)
# 在 Windows 上每行之间会出现空行

# 正确
with open("out.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerows([["id", "amount"], ["T001", "19.90"]])
```

**`csv` 模块要求打开文件时 `newline=""`**，否则 Windows 上写出的 CSV 会每行之间多出空行。

## 翻车现场二：basicConfig 重复调用不生效

```python
import logging

logging.basicConfig(level=logging.WARNING, format="%(levelname)s: %(message)s")
logging.warning("第一条")  # 显示

# WRONG：以为第二次调用会改级别
logging.basicConfig(level=logging.DEBUG, format="%(levelname)s: %(message)s")
logging.debug("第二条")   # 不显示！级别还是 WARNING

# 正确做法：用 logger 对象
logger = logging.getLogger("myapp")
logger.setLevel(logging.DEBUG)
logger.debug("第二条")    # 显示
```

**`basicConfig` 只在第一次调用时生效**，之后调用会被忽略。要动态调整级别，需要用 `getLogger()` 拿到 logger 对象再 `setLevel()`。
