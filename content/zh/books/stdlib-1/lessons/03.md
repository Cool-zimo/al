# 类型映射表：哪些能转，哪些会翻车

> 这一课把 Python 和 JSON 之间的类型转换规则讲清楚。记不住就会出 bug：`(1, 2)` 存进去再读出来变成了 `[1, 2]`。

## 一张表看懂双向映射

JSON 只有六种数据类型，Python 的类型远不止六种。所以转换不是"一一对应"，而是**能映射的映射、不能映射的报错**。

| Python → JSON | JSON → Python |
|---|---|
| `dict` | `object` → `dict` |
| `list` | `array` → `list` |
| `str` | `string` → `str` |
| `int`、`float` | `number` → `int`（无小数）/`float`（有小数） |
| `True` / `False` | `true` / `false` → `True` / `False` |
| `None` | `null` → `None` |

也就是说，JSON 里的 `number` 回来时可能是 `int` 也可能是 `float`，取决于有没有小数点。这对业务的影响很小，但如果你用 `type()` 严格判断，就要留个心。

## 翻车现场：元组会变成列表

这是最经典的一处"有损转换"：

```python
import json

t = (1, 2, 3)
print("原类型：", type(t))          # <class 'tuple'>

text = json.dumps(t)
print("序列化结果：", text)          # [1, 2, 3]

back = json.loads(text)
print("还原后类型：", type(back))    # <class 'list'>
print("还原后值：", back)            # [1, 2, 3]
```

**元组在 JSON 里没有对应类型**，它只能被当成数组，于是以列表 `[1, 2, 3]` 的形式出去，回来时自然就成了 `list`。

如果你的代码依赖"这是个元组不能改"，经过一次 JSON 往返后这个保证就没了：

```python
point = (3, 4)
data = json.loads(json.dumps(point))
data.append(5)          # 居然成功了！元组本该不可变
print(data)             # [3, 4, 5]
```

**怎么规避**：在序列化和反序列化之间手动转回元组，或者干脆在业务里只用列表。

```python
def tuple_roundtrip(t):
    return tuple(json.loads(json.dumps(t)))

print(tuple_roundtrip((3, 4)))      # (3, 4)，还是元组
```

## 翻车现场：字典的键必须是整数或字符串

JSON 规定对象的键**只能是字符串**。Python 字典的键可以是整数、浮点数、甚至元组，但一旦 `dumps`，非字符串键就会出问题：

```python
import json

# 整数键：会被强制转成字符串
d = {1: "一", 2: "二"}
text = json.dumps(d)
print(text)              # {"1": "一", "2": "二"}

back = json.loads(text)
print(back)              # {'1': '一', '2': '二'}  ← 键变成了字符串 "1"
print(back[1])           # KeyError: 1（你想要整数 1，实际是字符串 "1"）
```

**整数键会被悄悄转成字符串**，回来后你用整数去取就 KeyError。这个 bug 非常隐蔽，因为代码不报错，只是取不到值。

```python
# 元组做键：直接报错，根本 dumbs 不出来
d2 = {(1, 2): "坐标"}
json.dumps(d2)
```

报错：

```
TypeError: keys must be str, int, float, bool or None, not tuple
```

## 翻车现场：布尔值和 None 的大小写

Python 是 `True`/`False`/`None`，JSON 是 `true`/`false`/`null`，全小写：

```python
import json

# WRONG：自己拼 JSON 字符串时用了 Python 的写法
raw = '{"paid": True, "note": None}'
json.loads(raw)
```

报错：

```
JSONDecodeError: Expecting value: line 1 column 9 (char 8)
```

解析器在 `True` 的位置期待的是一个 JSON 值（`true`/`false`/`null`/字符串/数字），遇到大写的 `T` 就懵了。

**正确做法依然是交给库**：`json.dumps({"paid": True, "note": None})` 会输出 `{"paid": true, "note": null}`。

## 哪些类型 JSON 压根不支持

Python 里这些常见类型，**直接 `dumps` 会报错**：

| Python 类型 | 报错 |
|---|---|
| `set`（集合） | `TypeError: Object of type set is not JSON serializable` |
| `datetime.date` / `datetime.datetime` | 同上 |
| 自定义类的实例 | 同上 |
| `bytes`（字节串） | 同上 |
| 含循环引用的结构 | `ValueError: Circular reference detected` |

```python
import json

tags = {"python", "json", "教程"}
json.dumps(tags)
```

报错：

```
TypeError: Object of type set is not JSON serializable
```

怎么办？**转成它能处理的类型**。集合可以转列表：

```python
tags = {"python", "json", "教程"}
print(json.dumps(list(tags)))       # ["json", "教程", "python"] 顺序不定
```

> 日期和自定义对象的序列化，第 07 课会专门讲 `default=` 参数来解决。

## 数字：精度与边界的坑

```python
import json

# 浮点精度问题照样存在
d = {"pi": 0.1 + 0.2}
print(json.dumps(d))        # {"pi": 0.30000000000000004}

# JSON 标准里 number 没有大小限制，但 JS 的 number 是双精度浮点
big = 10 ** 20
print(json.dumps(big))      # 100000000000000000000（整数没问题）
```

**注意**：Python 的 `int` 是任意精度，但 JSON 里的大整数如果被 JavaScript 读取，超过 2^53 会丢精度。需要精确大整数（比如订单号、雪花 ID）时，建议当字符串传：

```python
order = {"order_id": "79228162514264337593543950336"}   # 字符串最安全
print(json.dumps(order))
```

## 实战：分析一次往返前后的类型变化

```python
import json

data = {
    "name": "张三",
    "scores": (88, 92, 95),          # 元组
    "tags": {"vip", "new"},          # 集合
    "info": {"age": 20}              # 嵌套字典
}

# 不能直接 dumps，tags 是集合，会报错
# 预处理：把集合转列表
data["tags"] = list(data["tags"])

text = json.dumps(data)
print("出去的字符串：", text)

back = json.loads(text)
print("回来后 scores 的类型：", type(back["scores"]))   # list，不再是 tuple
print("回来后 tags 的类型：", type(back["tags"]))       # list
print("回来后 info 的类型：", type(back["info"]))       # dict，正常
```

输出：

```
出去的字符串： {"name": "张三", "scores": [88, 92, 95], "tags": ["new", "vip", "教程"], "info": {"age": 20}}
回来后 scores 的类型： <class 'list'>
回来后 tags 的类型： <class 'list'>
回来后 info 的类型： <class 'dict'>
```

**结论**：JSON 往返是**有损**的。元组、集合这类"没有对应类型"的结构，回来时都变成了列表。设计数据结构时要心里有数。

## 小结

- JSON 六种类型：object、array、string、number、true/false、null
- **元组 → 列表**，往返后不可变保证消失
- **整数键 → 字符串键**，回来后用整数取会 KeyError
- **元组/集合/日期/自定义对象/循环引用** 直接 `dumps` 会报错
- 大整数（订单号等）建议当字符串传，避免 JS 端丢精度
- JSON 往返是**有损**转换，设计数据结构要留神
- 自己拼 JSON 字符串几乎一定会出错，永远交给 `json` 模块
