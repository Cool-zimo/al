# 第 27 课 · 数据管道：读取多种格式

> 读取层的目标是——不管来什么格式，出去都是 `list[dict]`。

## 按扩展名分派

读取层的核心逻辑：先看文件后缀，再决定用哪种解析器。这就是**分派（dispatch）**模式：

```python
def load(filepath):
    if filepath.endswith(".json"):
        return load_json(filepath)
    elif filepath.endswith(".csv"):
        return load_csv(filepath)
    elif filepath.endswith(".ini"):
        return load_ini(filepath)
    else:
        raise ValueError(f"不支持的格式: {filepath}")
```

**一行 `if-elif` 搞定分派**。为什么不用更复杂的设计模式？因为三个分支就够用了，过度抽象反而难读。等你将来真的遇到十种格式，再考虑策略模式不迟。

## 三种解析器

### JSON 读取

```python
import json

def load_json(filepath):
    with open(filepath, encoding="utf-8") as f:
        data = json.load(f)
    # 统一转成 list[dict]
    if isinstance(data, dict):
        data = [data]
    return data
```

JSON 可能是单个对象也可能是数组，用 `isinstance` 判断一下兜底。

### CSV 读取

```python
import csv

def load_csv(filepath):
    with open(filepath, encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        return list(reader)
```

`csv.DictReader` 直接给你 dict 列表，key 就是表头。注意 `newline=""`——这是 `csv` 模块的硬性要求，漏了在 Windows 上会出现空行。

### INI 读取

```python
import configparser

def load_ini(filepath):
    cp = configparser.ConfigParser()
    cp.read(filepath, encoding="utf-8")
    records = []
    for section in cp.sections():
        d = dict(cp[section])
        # INI 没有顶层 id，用 section 名当 id
        d["id"] = section
        records.append(d)
    return records
```

INI 的 section 天然对应一条记录，`cp[section]` 可以当 dict 用，直接 `dict()` 转出来。

## 完整读取层

把三层解析器封装进一个模块：

```python
import json
import csv
import configparser

def load_json(filepath):
    with open(filepath, encoding="utf-8") as f:
        data = json.load(f)
    return data if isinstance(data, list) else [data]

def load_csv(filepath):
    with open(filepath, encoding="utf-8", newline="") as f:
        return list(csv.DictReader(f))

def load_ini(filepath):
    cp = configparser.ConfigParser()
    cp.read(filepath, encoding="utf-8")
    records = []
    for section in cp.sections():
        d = dict(cp[section])
        d["id"] = section
        records.append(d)
    return records

def load(filepath):
    if filepath.endswith(".json"):
        return load_json(filepath)
    elif filepath.endswith(".csv"):
        return load_csv(filepath)
    elif filepath.endswith(".ini"):
        return load_ini(filepath)
    else:
        raise ValueError(f"不支持的格式: {filepath}")
```

**调用方只需要知道 `load()`**，不需要关心内部是哪种格式。这就是分层的价值。

## 标准化：把不同 key 统一

读取层出来的是"各格式原生 dict"，字段名不统一。比如 CSV 表头是 `订单号`，INI 里是 `id`。这一步在转换层做：

```python
def normalize(raw_list):
    """把原生 dict 列表转成标准 Record dict 列表"""
    result = []
    for raw in raw_list:
        # 处理不同的 key 名
        id_val = raw.get("id") or raw.get("订单号") or raw.get("编号")
        amount = raw.get("amount") or raw.get("金额")
        status = raw.get("status") or raw.get("状态")
        qty = raw.get("qty") or raw.get("数量")
        result.append({
            "id": id_val,
            "amount": str(amount),
            "status": status,
            "qty": int(qty) if qty else 0,
        })
    return result
```

`raw.get("id") or raw.get("订单号")`——先用标准名取，取不到再试中文别名。**这就是"翻译"逻辑**，把五花八门的输入字段名映射成统一的标准名。

## 为什么返回 list[dict] 而不是直接转 Record

你可能会问：为什么不直接返回 `list[Record]`？因为**读取层不应该知道业务模型的存在**。

读取层只负责"把文件变成 dict"，转换层才负责"把 dict 变成 Record"。这样如果将来 Record 结构变了（多加一个字段），读取层完全不用动。

这是**单一职责原则**在管道里的体现。

## 小结

- 读取层用 `if-elif` 按扩展名分派到三个解析器
- JSON 用 `json.load`，CSV 用 `csv.DictReader`，INI 用 `configparser`
- `csv` 打开必须加 `newline=""`
- 标准化层负责把不同字段名（中文/英文）映射到统一 key
- 读取层只输出 `list[dict]`，不碰业务模型
- 调用方只调 `load()`，屏蔽格式差异

## 翻车现场一：INI 读出来的值全是字符串

```python
import configparser

cp = configparser.ConfigParser()
# cp.read(...) 省略
# WRONG：以为 INI 会保留类型
# amount = cp["T001"]["amount"]  # 这是 str，不是 int 也不是 float
```

**INI 格式天生只存字符串**。所有值都需要手动转换类型，这是 INI 的固有限制，也是为什么转换层要做类型转换。

## 翻车现场二：JSON 顶层是对象不是数组

```python
import json

# WRONG：假设一定是列表
# data = json.load(f)
# for item in data: ...   # 如果顶层是 {} 就崩了

# 正确：判断类型
data = {"id": "T001", "amount": "19.90"}
if isinstance(data, dict):
    data = [data]
for item in data:
    print(item)
```

**永远不要假设 JSON 顶层结构**。接口返回可能是单个对象也可能是数组，用 `isinstance` 兜底。
