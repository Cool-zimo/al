# dumps 与 loads：四个函数记住两对

> 这一课把 `json` 模块最常用的四个函数讲透。你只需要记两对：**字符串**用 `dumps`/`loads`，**文件**用 `dump`/`load`。

## json 模块只有四件兵器

打开 Python 交互环境，import 进来看看它提供了什么：

```python
import json

print([x for x in dir(json) if not x.startswith("_")])
```

最常用的就是这四个：

| 函数 | 作用 | 输入 | 输出 |
|---|---|---|---|
| `json.dumps(obj)` | 序列化（编码） | Python 对象 | **字符串** str |
| `json.loads(s)` | 反序列化（解码） | JSON 字符串 | **Python 对象** |
| `json.dump(obj, f)` | 序列化到文件 | Python 对象 + 文件对象 | 无（直接写文件） |
| `json.load(f)` | 从文件反序列化 | 文件对象 | Python 对象 |

记忆口诀：**带 `s` 的是字符串（string）版本，不带 `s` 的是文件版本**。

- `dumps` = dump + string，结果是一串字符串
- `loads` = load + string，从字符串读取
- `dump` / `load` 直接操作文件对象

## dumps：把对象变成字符串

```python
import json

config = {
    "host": "api.example.com",
    "port": 443,
    "timeout": 30,
    "debug": False,
    "retry": None
}

text = json.dumps(config)
print(text)
print(type(text))      # <class 'str'>
```

输出：

```
{"host": "api.example.com", "port": 443, "timeout": 30, "debug": false, "retry": null}
<class 'str'>
```

注意几个"翻译"点：`False` → `false`，`None` → `null`。返回值是 `str` 类型，可以直接存数据库、发网络、写日志。

**这是"对外输出"的格式**：你的程序内部用字典方便，要交给外界就得先 `dumps` 成字符串。

## loads：把字符串变回对象

```python
import json

raw = '{"host": "api.example.com", "port": 443, "debug": false}'

obj = json.loads(raw)
print(obj)
print(type(obj))       # <class 'dict'>
print(obj["host"])     # api.example.com
```

`loads` 是 `dumps` 的逆操作。输入必须是一段**合法的 JSON 字符串**，返回值是字典或列表。

## 翻车现场：dumps 的结果再用 dump，等于写字符串进了字符串

这是新手最容易混淆的一件事：`dumps` 已经给了你字符串，如果你还拿去 `dump`，会发生什么？

```python
import json

config = {"host": "localhost", "port": 8080}

# WRONG：dumps 已经得到字符串，再用 dump 去写文件
text = json.dumps(config)
with open("/tmp/wrong.json", "w") as f:
    json.dump(text, f)      # 把字符串又当成对象序列化了一次
```

打开 `/tmp/wrong.json`，你看到的是：

```
"{\"host\": \"localhost\", \"port\": 8080}"
```

整段内容被**加了双引号、反斜杠转义**——因为字符串本身被当成了一个 JSON 字符串值来序列化。正确的做法二选一：

```python
# 正确写法一：dump 直接写对象
with open("/tmp/right1.json", "w") as f:
    json.dump(config, f)

# 正确写法二：dumps 拿到字符串后，自己 write
with open("/tmp/right2.json", "w") as f:
    f.write(json.dumps(config))
```

## 翻车现场：loads 传了文件对象而不是字符串

```python
import json

# WRONG
with open("/tmp/right1.json") as f:
    obj = json.loads(f)     # 传了文件对象
```

报错：

```
TypeError: the JSON object must be str, bytes or bytearray, not TextIOWrapper
```

`loads` 只要字符串。想直接读文件，用 `load`（没有 s）：

```python
with open("/tmp/right1.json") as f:
    obj = json.load(f)      # 正确：load 接收文件对象
print(obj)                  # {'host': 'localhost', 'port': 8080}
```

**一句话记住**：要不要自己管文件，取决于函数名里**有没有 s**。`dump/load` 帮你打开读写，`dumps/loads` 只管字符串，文件你自己负责。

## 四函数的使用场景对照

| 场景 | 用什么 |
|---|---|
| 把配置存进数据库、发到网络 | `dumps` → 得到字符串 |
| 从网络响应、消息队列里拿到文本要解析 | `loads` → 得到对象 |
| 直接把配置写到 `config.json` 文件 | `dump` |
| 直接读取 `data.json` 文件 | `load` |
| 想在内存里快速序列化再反序列化 | `dumps` + `loads` 组合 |

## 实战：模拟一次"发请求—收响应"

下面这段代码模拟了真实开发中"把数据打包发出去，再把回包解开"的完整过程：

```python
import json

# —— 客户端：打包请求 ——
request = {
    "action": "query_order",
    "order_id": "DD20260927001",
    "fields": ["buyer", "total", "items"]
}
body = json.dumps(request)          # 变成字符串，准备通过网络发送
print("发送：", body)

# —— 假装网络传输，body 就是那串字符串 ——

# —— 服务端：解开请求，构造响应 ——
received = json.loads(body)         # 服务端拿到字符串，还原成对象
resp = {
    "code": 0,
    "msg": "ok",
    "data": {
        "buyer": "张三",
        "total": 537,
        "items": [{"name": "机械键盘", "price": 459, "qty": 1}]
    }
}
resp_body = json.dumps(resp)

# —— 客户端：解开响应 ——
result = json.loads(resp_body)
print(f"响应码：{result['code']}，买家：{result['data']['buyer']}，合计：¥{result['data']['total']}")
```

输出：

```
发送： {"action": "query_order", "order_id": "DD20260927001", "fields": ["buyer", "total", "items"]}
响应码：0，买家：张三，合计：¥537
```

你看，整个通信过程就是 `dumps` 和 `loads` 各用两次。这就是 90% 的接口调用在底层做的事。

## 小结

- `json` 模块核心四函数：`dumps`/`loads`（字符串）、`dump`/`load`（文件）
- 口诀：**带 s 的字符串版，不带 s 的文件版**
- `dumps` 输出 `str`，`loads` 输出 `dict`/`list`
- 最易混错：`dumps` 完再 `dump`（双重序列化，出现转义），`loads` 误传文件对象
- 对外发数据用 `dumps`，从外部收数据用 `loads`；直接读写文件用 `dump`/`load`
- 网络请求/响应就是 `dumps`+`loads` 的组合使用
