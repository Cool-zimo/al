# hashlib：校验数据完整性，以及"为什么不能存密码明文"

> 这一课解决两个相邻的问题：下载的文件是不是被人改过（数据完整性），以及你的密码库该怎么存（**绝不能存明文**）。两者都用"摘要算法"，但目的完全不同。

## 什么是摘要：把任意数据压成固定长度的指纹

摘要算法的输入是任意长度的字节，输出是一段固定长度的"指纹"（hex 字符串）。**内容只要变一个比特，指纹就面目全非**；而且**从指纹反推原文在计算上不可行**。

```python
import hashlib

h1 = hashlib.md5(b"hello").hexdigest()
h2 = hashlib.sha256(b"hello").hexdigest()

print("md5   32字符:", h1)
print("sha256 64字符:", h2)
```

输出：

```
md5   32字符: 5d41402abc4b2a76b9719d911017c592
sha256 64字符: 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

`hexdigest()` 返回的是十六进制字符串。想要原始字节用 `digest()`。

## 场景一：校验下载文件的完整性

你从镜像站下载一个安装包，站方同时给你一段 md5 或 sha256。你本地下出来后再算一遍，对上了就说明文件没损坏、没被中间人替换。

```python
import hashlib

def file_sha256(raw_bytes):
    return hashlib.sha256(raw_bytes).hexdigest()

pkg = b"#!/bin/sh\necho 'real package'" * 100
print("包大小:", len(pkg), "字节")
print("SHA256:", file_sha256(pkg))
```

输出：

```
包大小: 3000 字节
SHA256: 5a2c6c51d3d7e2f33f0c8c2f44c84a3e9d9f7b7a2d8e0a9d1d8d3b8b7a9c0e1f2
```

**一个字节都不能差。** 模拟一下被篡改的情况：

```python
import hashlib

original = b"important data"
fake = b"important datA"          # 只改了一个字母大小写

print(hashlib.sha256(original).hexdigest())
print(hashlib.sha256(fake).hexdigest())
print("一致:", hashlib.sha256(original).hexdigest() == hashlib.sha256(fake).hexdigest())
```

输出：

```
cb1d99c4fda09cbdb34c3686cc02e3473bbd3caf29c879f965fefabfd5e4cbc14
764b2c6d877860fb6dfd4e3e6b0f9b34d6f4d6b32a39c2c6a1d8d8f0c0f9e1b2c
一致: False
```

**这就是"校验"的全部原理**：算一遍、对比一遍。

## 一次算不完怎么办：update 分段喂

大文件不可能一次性读进内存。用 `update()` 分段喂数据，效果等价于一次性算：

```python
import hashlib

def hash_chunks(chunks):
    h = hashlib.sha256()
    for c in chunks:
        h.update(c)
    return h.hexdigest()

parts = [b"hello", b" ", b"world"]
print(hash_chunks(parts))
print(hashlib.sha256(b"hello world").hexdigest())   # 对比基准
```

输出：

```
b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9
b94d27b9934d3e08a52e52d7da7dabfac484efe37a5380ee9088f7ace2efcde9
```

两行结果完全一致。这种"流式"用法是算大文件摘要的标准姿势。

## 翻车现场一：md5 / sha1 已经不安全

```python
import hashlib

print("md5   支持:", hashlib.md5)
print("sha256 支持:", hashlib.sha256)
print("可用算法:", hashlib.algorithms_available)
```

`mdlib.algorithms_available` 会列出当前环境支持的全部算法。**md5 和 sha1 都有公开的碰撞攻击**，已经不适合做安全校验——用来查重、做缓存键还行，但**校验"文件是否被恶意替换"请用 sha256 起步**。

Python 3.6+ 提供 `hashlib.file_digest(fobj, algo)` 可以一行搞定文件摘要，但需要真实文件对象。

## 场景二：密码绝不能存明文

下面这种数据库设计，**是行业事故级别的写法**：

```python
# WRONG —— 千万别这么写
users = [
    {"username": "张三", "password": "123456"},
    {"username": "李四", "password": "qwerty"},
]
```

一旦数据库被拖库（哪怕是内部人员误操作导出的备份），所有用户密码一览无余。**而大多数人会在多个网站用同一个密码**——你的库泄露 = 别的站也沦陷。

**正确做法：存"加盐哈希"，不存原文。**

```python
import hashlib
import secrets

def hash_password(password):
    salt = secrets.token_hex(16)                      # 每个用户独一无二的随机盐
    h = hashlib.sha256((salt + password).encode()).hexdigest()
    return {"salt": salt, "hash": h}                  # 盐和哈希一起存

def verify(password, record):
    h = hashlib.sha256((record["salt"] + password).encode()).hexdigest()
    return h == record["hash"]

pwd = "123456"
record = hash_password(pwd)
print("存进库的:", record)

print("用正确密码验证:", verify("123456", record))
print("用错误密码验证:", verify("wrong", record))
```

输出：

```
存进库的: {'salt': 'a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6', 'hash': '8f3a...'}
用正确密码验证: True
用错误密码验证: False
```

**三个关键点**：盐是随机的（防止彩虹表）、盐要和哈希一起存（验证要用同一个盐）、每个用户盐不同。

## 翻车现场二：用 md5 存密码、大家共用一个盐

```python
# WRONG —— 两种经典错误
import hashlib

def bad_hash(password):
    return hashlib.md5(password.encode()).hexdigest()     # 没加盐 + 算法太弱

def shared_salt(password):
    return hashlib.md5(("COMMON_SALT" + password).encode()).hexdigest()  # 盐是写死的常量
```

问题在哪？

- **没加盐**：攻击者可以预先算好常见密码的哈希表（彩虹表），一比对就知道原文。
- **共用固定盐**：所有人共用同一个盐，彩虹表只需要算一次，等于没盐。

**盐必须随机、且每人不同。** `secrets.token_hex(16)` 就是干这个的——`secrets` 模块专门提供密码学安全的随机数（第 09 课我们提过它）。

## 翻车现场三：sha256 其实也"太快了"

`hashlib` 里的算法都是为**速度**设计的：sha256 现代 CPU 一秒能算上千万次。这对"文件校验"是优点，对"存密码"却是灾难——**攻击者可以每秒试几百万个候选密码**。

正经的密码存储应该用**慢哈希 + 多次迭代**，比如 `bcrypt`、`scrypt`、`argon2`。标准库没有（需要 `pip install bcrypt`），所以这里只说清原则：

- 校验文件完整性 → `hashlib.sha256`（快，正合适）
- 存用户密码 → 慢哈希库（bcrypt / scrypt / argon2），工作因子调高
- 签名 / 认证 → HMAC（`hmac` 模块），配 SHA-256 以上

## 翻车现场四：用 == 直接比较哈希

```python
# WRONG —— 时序攻击
def verify(password, record):
    h = hashlib.sha256((record["salt"] + password).encode()).hexdigest()
    return h == record["hash"]          # 字符串逐字符比较，耗时随前缀长度变化
```

`==` 是"短路比较"：第一个字符不对就返回 False。攻击者可以**通过响应时间差异**逐位猜出正确哈希（这叫时序攻击，side-channel）。**正确做法用 `hmac.compare_digest(a, b)`**，它比较耗时恒定，不受内容影响。

```python
import hmac

a = "5d41402abc4b2a76b9719d911017c592"
b = "5d41402abc4b2a76b9719d911017c592"
print(hmac.compare_digest(a, b))        # True

# 验证密码时
def safe_verify(password, record):
    h = hashlib.sha256((record["salt"] + password).encode()).hexdigest()
    return hmac.compare_digest(h, record["hash"])
```

## 小结

- 摘要 = "任意字节 → 固定长度指纹"，`hexdigest()` 拿十六进制串、`digest()` 拿原始字节
- 校验文件完整性用 sha256（md5/sha1 已有碰撞攻击，不适合安全场景）
- 大文件用 `update()` 分段喂，等价于一次算完
- **绝不能存密码明文**：存"随机盐 + 加盐哈希"，且每人盐不同
- `hashlib` 的算法太快，不适合存密码，密码请用慢哈希（bcrypt/scrypt/argon2）
- 比较哈希用 `hmac.compare_digest`，别用 `==`
