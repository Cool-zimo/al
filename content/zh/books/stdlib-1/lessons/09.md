# 什么时候 JSON 不够用

> 这一课给你一张"边界清单"：日期、二进制、循环引用、元组/集合——这些 JSON 表达不了。学会识别它们，才知道什么时候该换方案。

## JSON 能表达的只有六种类型

回顾一下：JSON 只有 object、array、string、number、true/false、null。这六种东西能组合出非常复杂的结构，但**有硬边界**。

当你试图序列化下面这些东西时，会直接报错：

```python
import json

# 日期
import datetime
json.dumps(datetime.date(2026, 9, 27))
# TypeError: Object of type date is not JSON serializable

# 时间
json.dumps(datetime.datetime.now())
# TypeError

# 二进制
json.dumps(b"\xe4\xbd\xa0")
# TypeError

# 集合
json.dumps({1, 2, 3})
# TypeError

# 自定义对象（没有 default）
class User: pass
json.dumps(User())
# TypeError
```

这些报错都说同一件事：**JSON 没有对应的数据类型**。

## 日期时间：必须自己约定格式

日期是业务里最常见的东西，也是最容易被 JSON 坑的。常见的"序列化约定"有三种：

```python
import json
import datetime

d = datetime.datetime(2026, 9, 27, 14, 30, 0)

# 方案 A：ISO 8601 字符串（最推荐）
s1 = d.isoformat()
print(s1)                      # 2026-09-27T14:30:00

# 方案 B：时间戳（秒/毫秒）
s2 = d.timestamp()             # 浮点秒数
print(s2)

# 方案 C：拆成年月日的字典
s3 = {"year": 2026, "month": 9, "day": 27}
print(s3)
```

**ISO 8601 是事实标准**：`2026-09-27T14:30:00`，带 `T` 分隔日期和时间。它的优势是**人能读、程序能解析、带时区也能表达**。

反序列化回来时：

```python
text = "2026-09-27T14:30:00"
back = datetime.datetime.fromisoformat(text)
print(back.year, back.month, back.day)      # 2026 9 27
```

## 翻车现场：把日期当字符串拼接，解析时格式对不上

张三自己定了个格式 `"2026年9月27日"`，存进了 JSON：

```python
# WRONG
raw = '{"date": "2026年9月27日"}'
# 解析端怎么还原成 datetime？只能靠一堆字符串切分
```

这种"自创格式"的最大问题是**谁都不知道该怎么解析**。一旦换了个人接手代码，就要重新猜。

**正确做法**：统一用 ISO 8601，全世界都认。

```python
import json
import datetime

def datetime_default(o):
    if isinstance(o, (datetime.datetime, datetime.date)):
        return o.isoformat()
    raise TypeError(f"不支持: {type(o)}")

data = {"event": "开学", "date": datetime.date(2026, 9, 1)}
text = json.dumps(data, default=datetime_default)
print(text)            # {"event": "开学", "date": "2026-09-01"}
```

## 二进制数据：base64 是标准答案

图片、压缩包、加密后的内容都是 `bytes`。JSON 是文本格式，**装不下字节**。

```python
import json

signature = b"\x00\x01\x02\xff\xfe\xfd"
json.dumps({"sig": signature})
# TypeError
```

**标准做法：base64 编码**，把字节转成纯 ASCII 字符串：

```python
import base64
import json

raw_bytes = b"\x00\x01\x02\xff\xfe\xfd"

encoded = base64.b64encode(raw_bytes).decode("ascii")
print(encoded)                      # AAA=//79

text = json.dumps({"sig": encoded})
print(text)                         # {"sig": "AAA=//79"}

# 读回来
back = json.loads(text)
decoded = base64.b64decode(back["sig"])
print(decoded)                       # b'\x00\x01\x02\xff\xfe\xfd'
```

`base64.b64encode` 返回 bytes，所以要 `.decode("ascii")` 变成字符串才能进 JSON。读取时 `b64decode` 还原。

**代价**：base64 会让体积膨胀约 1.37 倍。所以二进制数据量大时，更好的方案是直接存文件、JSON 里只放文件路径。

## 循环引用：JSON 根本写不出来

```python
import json

a = []
a.append(a)              # a 里包含 a 自己

json.dumps(a)
```

报错：

```
ValueError: Circular reference detected
```

这不是 bug，是**逻辑上写不出来**：`a` 是 `[...]`，它的第一个元素是它自己，要写出 `[[[[...` 无限层。

**现实里的循环引用**通常是对象互相引用：

```python
class Node:
    def __init__(self, name):
        self.name = name
        self.parent = None

root = Node("root")
child = Node("child")
child.parent = root       # 反向引用
```

这种结构无法直接 `dumps`。**解决思路**：序列化时**只存 id，不存引用**，或者约定"父子关系只存一个方向"。

## 元组和集合：信息会丢

```python
import json

t = (1, 2, 3)            # 元组：不可变
s = {1, 2, 3}            # 集合：无序、去重

text = json.dumps([t, list(s)])     # 集合要先手动转 list
print(text)                          # [[1, 2, 3], [1, 2, 3]]

back = json.loads(text)
print(type(back[0]))                 # <class 'list'>  不是 tuple！
```

**元组**会变成列表，回来后不再是元组；**集合**得手动转列表，回来后也成了列表，且**顺序不保证**。

如果你的业务真的需要"不可变序列"或"去重集合"，JSON 本身表达不了，需要在 `object_hook` 里按约定还原（见第 07 课的类型标记技巧）。

## 翻车现场：把 JSON 当数据库用，遇到超大数据量就崩

```python
import json

# 假装有一个 100 万条记录的列表
big = [{"id": i, "name": f"用户{i}"} for i in range(1_000_000)]

# 全部序列化到内存
text = json.dumps(big)           # 可能占用几百 MB 内存
```

**JSON 是"全量加载"格式**：`json.load` 会一次性把整个文件读进内存变成对象。当数据上百万条、几个 GB 时，这会直接 OOM（内存溢出）。

**什么时候该换方案**：

| 需求 | JSON 够不够 | 更好的选择 |
|---|---|---|
| 配置文件（几 KB~几 MB） | 够 | JSON / YAML / TOML |
| 接口数据传输 | 够 | JSON |
| 几百万条记录、需要查询 | 不够 | 数据库（SQLite/MySQL） |
| 大数据流式处理 | 不够 | 逐行 JSONL / CSV / Parquet |
| 二进制大文件（图片/视频） | 不够 | 直接存文件 + 路径索引 |
| 对象间复杂引用关系 | 不够 | 数据库或图数据库 |

## JSONL：一行一条 JSON 的流式替代

如果你的数据是一大堆**相互独立的记录**，又想用 JSON，可以用 JSONL（JSON Lines）格式：每行一条 JSON，而不是一个大数组。

```python
import json

records = [
    {"id": 1, "name": "张三"},
    {"id": 2, "name": "李四"},
    {"id": 3, "name": "王五"}
]

# 写成 JSONL：每行一条
with open("users.jsonl", "w", encoding="utf-8") as f:
    for r in records:
        f.write(json.dumps(r, ensure_ascii=False) + "\n")

# 读取时可以一行行读，不占全量内存
with open("users.jsonl", encoding="utf-8") as f:
    for line in f:
        obj = json.loads(line)
        print(obj["name"])
```

输出：

```
张三
李四
王五
```

**优势**：可以逐行处理，内存占用极低；可以追加写（不用读整个文件再写回）；适合日志、导出文件。

**代价**：不能直接看成一个大数组，需要工具支持。

## 小结

- JSON 只有六种类型，**日期、二进制、循环引用、元组/集合都表达不了**
- 日期用 **ISO 8601**（`2026-09-27T14:30:00`），人能读、程序能解析
- 二进制用 **base64** 编码成字符串，代价是体积膨胀约 1.37 倍
- 循环引用无法序列化，需改存 id 或单向引用
- 元组、集合往返后会变成列表，信息丢失
- JSON 是**全量加载**格式，上百万条记录时考虑数据库或 JSONL
- **JSONL** 是一行一条 JSON 的流式格式，适合日志和大批量导出
