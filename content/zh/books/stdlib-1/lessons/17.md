# pickle：把任意 Python 对象存成字节串

> 这一课解决"JSON 存不了的东西怎么存"。自定义类实例、带循环引用的结构、集合、复数——`pickle` 全部照单全收。代价是：它产出的东西只有 Python 能读。

## JSON 做不到的事，pickle 能做

回想第 03、09 课：JSON 只认识六种类型。下面这个对象，`json.dumps` 直接报 `TypeError`。

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
json.dumps(p)        # TypeError: Object of type Point is not JSON serializable
```

换成 `pickle`：

```python
import pickle

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
data = pickle.dumps(p)         # 字节串
print(type(data).__name__, len(data), "字节")

p2 = pickle.loads(data)
print(type(p2).__name__, p2.x, p2.y)
```

输出：

```
bytes 57 字节
Point 3 4
```

对象完整地回来了。这叫**序列化**（把内存对象变成可传输的字节串）和**反序列化**（还原）。

## dumps / loads：操作字节串

`pickle` 的命名和 `json` 一模一样，对应关系很好记：

| 用途 | pickle | json |
|---|---|---|
| 对象 → 字符串/字节 | `dumps(obj)` | `dumps(obj)` |
| 字节/字符串 → 对象 | `loads(data)` | `loads(data)` |
| 对象 → 文件 | `dump(obj, f)` | `dump(obj, f)` |
| 文件 → 对象 | `load(f)` | `load(f)` |

唯一的差别：`pickle` 的 `dumps` 返回的是**字节串**（`bytes`），不是字符串。所以用 `io.BytesIO` 而不是 `io.StringIO` 做"内存文件"。

```python
import pickle
import io

buf = io.BytesIO()
pickle.dump([1, 2, {"a": 3}], buf)
print("写入了", buf.tell(), "字节")

buf.seek(0)
obj = pickle.load(buf)
print(obj)
```

输出：

```
写入了 43 字节
[1, 2, {'a': 3}]
```

## pickle 能做而 JSON 做不到的三件事

**一、存自定义类的实例。** 上面已经演示过。

**二、存循环引用。** 一个对象引用了自己（或相互引用），JSON 会无限递归直到栈溢出，pickle 用"对象备忘录"机制正确处理：

```python
import pickle

a = {"name": "张三"}
a["self"] = a            # 循环引用：字典里引用自己

data = pickle.dumps(a)
a2 = pickle.loads(data)

print(a2["name"])        # 张三
print(a2["self"] is a2)  # True —— 还原后还是同一个对象
```

`a2["self"] is a2` 为 `True`，说明循环结构被忠实地重建了。这是 pickle 相对 JSON 的杀手级能力。

**三、存 JSON 根本没类型的东西。**

```python
import pickle

stuff = {
    "set": {1, 2, 3},
    "complex": 3 + 4j,
    "frozenset": frozenset([9, 9, 8]),
    "bytes": b"\x00\x01\x02",
}
data = pickle.dumps(stuff)
back = pickle.loads(data)
print(type(back["set"]).__name__, back["set"])
print(back["complex"], back["frozenset"], back["bytes"])
```

输出：

```
set {1, 2, 3}
(3+4j) frozenset({8, 9}) b'\x00\x01\x02'
```

集合、复数、frozenset、bytes——JSON 一个都不认识，pickle 全部保留原类型。

## 翻车现场一：dumps 返回的是字节，不是字符串

```python
import pickle

data = pickle.dumps([1, 2, 3])
# WRONG
print("序列化结果：" + data)
```

报错：

```
TypeError: can only concatenate str (not "bytes") to str
```

`data` 是 `bytes`。想看内容必须先解码，或者干脆打印它的 repr：

```python
data = pickle.dumps([1, 2, 3])
print(repr(data))                    # b'\x80\x04\x95\x0b...'
print(data.decode("latin-1"))        # 能解码但内容是乱码，不推荐
```

**记住：凡是要当文本处理的东西用 JSON；凡是要当字节处理的东西用 pickle。**

## 翻车现场二：跨版本、跨 Python 读不出来

pickle 有协议版本号（protocol）。高版本 Python 生成的字节串，低版本可能读不了。可以用 `protocol=` 显式指定旧版本做兼容：

```python
import pickle

obj = [1, 2, 3]
print("默认协议:", pickle.DEFAULT_PROTOCOL)
print("最高协议:", pickle.HIGHEST_PROTOCOL)

b5 = pickle.dumps(obj, protocol=pickle.HIGHEST_PROTOCOL)
b0 = pickle.dumps(obj, protocol=0)   # 最早的文本协议，体积最大
print("协议5:", len(b5), "字节")
print("协议0:", len(b0), "字节")
```

输出：

```
默认协议: 4
最高协议: 5
协议5: 22 字节
协议0: 18 字节
```

协议版本还会影响体积。更关键的是**Python 2 的 pickle 和 Python 3 的 pickle 互通性极差**，如果数据要长期归档，pickle 不是好选择——下一节会讲为什么，以及该怎么选。

## 翻车现场三：类定义变了，旧数据读不回来

pickle 存的是"重建指令"，指令里写的是类名（比如 `__main__.Point`）。如果类名或构造参数变了，反序列化会失败：

```python
import pickle

class Old:
    def __init__(self, x):
        self.x = x

obj = Old(1)
data = pickle.dumps(obj)
del Old                        # 类定义被删了

# WRONG：反序列化时找不到类
try:
    pickle.loads(data)
except AttributeError as e:
    print("AttributeError:", e)
```

输出：

```
AttributeError: Can't get attribute 'Old' on <module '__main__'>
```

**所以 pickle 数据不要跨版本长期存档，也别指望换个程序就能读。** 它是"同语言、同代码版本下临时落盘"的工具，不是交换格式。

## 小结

- `pickle.dumps` 返回 `bytes`，用 `pickle.loads` 还原；文件操作用 `dump/load` + `io.BytesIO`
- pickle 能存自定义类实例、循环引用、集合、复数——JSON 全部不支持
- 代价：产物是字节串、强依赖 Python 版本和类定义、完全不可跨语言
- 适合场景：缓存、进程间临时传对象、会话状态；不适合：长期归档、对外接口、跨语言交换
- 下一课会讲最重要的一条：**绝不能 unpickle 来源不明的数据**
