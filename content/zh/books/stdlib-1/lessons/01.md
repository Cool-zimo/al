# 为什么要有数据格式

> 这一课解决"两个程序之间怎么把数据原样交出去"。你会明白 `print` 打出来的字符串是给人看的，`json.dumps` 出来的字符串才是给程序看的。

## 程序之间的对话不能靠 print

假设你写了一个脚本，从数据库里查出今天的订单，想交给另一个同事写的程序继续算账。最直接的想法：打印出来不就行了？

```python
orders = [{"id": 1, "total": 99.5}, {"id": 2, "total": 128.0}]

print(orders)
```

输出：

```
[{'id': 1, 'total': 99.5}, {'id': 2, 'total': 128.0}]
```

这串东西只有**看得懂 Python 的人**能处理。换成一个 Java 程序、一个前端网页、一个 Excel 插件，它们看到 `"'id'"` 里的单引号就会一脸问号——这不是它们认识的语言。

更要命的是，这串输出是**给人调试看的**，不是"结构化数据"。想从中取出第二个订单的总价，你得自己写一堆字符串切分逻辑。

**数据格式的作用**，就是给这种对话定一个"世界语"：两边约定好——所有字符串用双引号、所有数组用方括号、所有键都是字符串。谁都能生成，谁都能解析，互不关心对方用什么语言写的。

## JSON 就是这个"世界语"

JSON（JavaScript Object Notation）原本是 JavaScript 的对象写法，但因为足够简单，现在几乎成了互联网数据交换的事实标准。你在网上购物、刷短视频、看天气，手机 App 和服务器之间传的就是 JSON。

它的语法只有几条：

| JSON 里的样子 | 含义 | 对应 Python |
|---|---|---|
| `123` | 数字 | `int` / `float` |
| `"你好"` | 字符串（必须双引号） | `str` |
| `true` / `false` | 布尔值 | `True` / `False` |
| `null` | 空值 | `None` |
| `[1, 2, 3]` | 数组（有序列表） | `list` |
| `{"name": "张三"}` | 对象（键值表） | `dict` |

注意**两处必须记住的死规定**：

1. **字符串只能用双引号** `"`，单引号 `'` 是错的。
2. **键也必须用双引号**，写 `{"name": 1}` 可以，写 `{name: 1}` 不行。

## 翻车现场：用 print 传数据，逗号一变就崩

张三写了个脚本处理订单备注，用 print 输出给李四：

```python
# WRONG
note = "客户要求: 加急, 周末送到"
print(note)
```

李四按"逗号"切分这串字符串，结果备注里的逗号让切分错位了。真正靠谱的做法是让程序自己序列化，不要手写。

```python
import json

order = {
    "id": "DD20260927001",
    "buyer": "张三",
    "total": 99.5,
    "items": [
        {"name": "机械键盘", "price": 459, "qty": 1},
        {"name": "鼠标垫", "price": 39, "qty": 2}
    ],
    "note": "加急, 周末送到",
    "paid": True
}

text = json.dumps(order)
print(text)
```

输出是一行连续的字符串（这里为了看清做了换行展示）：

```
{"id": "DD20260927001", "buyer": "张三", "total": 99.5,
 "items": [{"name": "机械键盘", "price": 459, "qty": 1},
           {"name": "鼠标垫", "price": 39, "qty": 2}],
 "note": "加急, 周末送到", "paid": true}
```

注意 `paid` 字段：Python 的 `True` 变成了 JSON 的 `true`，首字母小写。`None` 会变成 `null`。这就是"翻译"的过程。

## 翻车现场：单引号和尾随逗号，JSON 一律不认

```python
import json

# WRONG：Python 的 repr 风格字符串，不是合法 JSON
data = "{'name': '张三'}"
json.loads(data)
```

报错：

```
JSONDecodeError: Expecting property name enclosed in double quotes
```

JSON 规范里**没有单引号**这种写法，也没有尾随逗号（`[1, 2,]` 后面那个多余逗号）。这些在 Python 里合法，在 JSON 里一律报错。

**正确做法**：永远用 `json.dumps` 生成、用 `json.loads` 解析，让库帮你处理引号转换，不要自己拼字符串。

## 一个简单的端到端例子

下面这段代码模拟了一个真实场景：服务器返回一串 JSON 文本，你的程序拿到后要从中取出订单总额。

```python
import json

# 假设这串文本是从网络/文件里读到的（这里是字符串，假装是外部输入）
raw = '''
{
    "order_id": "DD20260927001",
    "buyer": "张三",
    "items": [
        {"name": "机械键盘", "price": 459, "qty": 1},
        {"name": "鼠标垫", "price": 39, "qty": 2}
    ],
    "paid": true
}
'''

order = json.loads(raw)          # 字符串 -> Python 对象
total = sum(it["price"] * it["qty"] for it in order["items"])
print(f"买家：{order['buyer']}，应付合计：¥{total}")
```

输出：

```
买家：张三，应付合计：¥537
```

这一步的关键：`json.loads` 把外面的字符串"还原"成了 Python 的字典和列表，之后你就可以用熟悉的 `[]` 和循环去处理了。**这就是"数据格式"的全部价值：把外部文本变成内部对象。**

## 标准库意味着"开箱即用"

`json` 是 Python 标准库的一部分。所谓标准库，就是装好 Python 就自带、不用 `pip install` 的库。和它同级别的还有 `csv`（处理表格）、`os`（操作系统交互）、`datetime`（日期时间）等，都会在这本书里讲到。

```python
import json        # 标准库，直接 import 就能用
import csv
import os
```

**为什么标准库值得单独学一章**：它们覆盖了日常脚本 80% 的"脏活累活"。自己写字符串解析、自己处理文件编码、自己拼分隔符，都是容易出错且没必要的重复劳动。

## 小结

- 程序之间交换数据要用**约定好的数据格式**，不能靠 `print` 随便打字符串
- JSON 是当前最通用的数据交换格式：双引号字符串、数组用 `[]`、对象用 `{}`
- 字符串只能用双引号，键也要双引号；`true`/`false`/`null` 是 JSON 的写法
- `json.dumps(obj)` 把 Python 对象变成 JSON 字符串；`json.loads(text)` 把字符串还原成对象
- JSON 里**没有单引号、没有尾随逗号**，这些 Python 语法在这里都报错
- `json` 是标准库，无需安装，直接 `import`
