# 中文与编码：为什么文件会变成乱码

> 这一课把"文件读写为什么乱码"讲透。你不会再说"我就随便 open 了一下"，而是能准确说出问题出在 UTF-8、GBK 还是 BOM。

## 字符串、字节、编码：三个概念先分清

Python 里有两种"文本相关的东西"：

```python
s = "你好"            # str，字符串，是"字符"的序列
b = b"\xe4\xbd\xa0\xe5\xa5\xbd"   # bytes，字节串，是"字节"的序列
```

`str` 是给人看的，`bytes` 是给计算机存的。两者之间的转换叫**编码（encode）**和**解码（decode）**：

```python
s = "你好"
b = s.encode("utf-8")       # str -> bytes
print(b)                    # b'\xe4\xbd\xa0\xe5\xa5\xbd'

back = b.decode("utf-8")    # bytes -> str
print(back)                 # 你好
```

**文件在磁盘上存的永远是 bytes**。当你 `open()` 一个文本文件时，Python 要帮你把 bytes 解码成 str——这个"怎么解码"就是编码问题。

## open 的默认编码：一个跨平台的地雷

```python
# Windows 上可能出问题
open("data.txt", "w").write("你好")
```

在 Linux / macOS 上，`open()` 默认用 UTF-8；在**中文 Windows 上，默认是 GBK**。

```python
import sys
print(sys.platform)         # win32 / linux / darwin
# Windows 上：open 默认 encoding 是 'cp936'（即 GBK）
```

后果是：你在 Windows 上写了个 UTF-8 的文件，却用 GBK 去解释，打开就是乱码——"浣犲ソ""����"之类的东西。

**解决办法：永远显式指定 encoding**：

```python
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("你好")

with open("data.txt", encoding="utf-8") as f:
    print(f.read())         # 你好
```

`json.dump` 和 `json.load` 也一样——它们是建立在 `open` 之上的，编码由你传给 `open` 的参数决定。

## 翻车现场：GBK 文件在 Linux 上读成乱码

张三在 Windows 记事本里保存了一份 `users.json`，内容是 `{"name": "张三"}`。记事本默认用 GBK 编码保存。李四在 Linux 服务器上用默认 UTF-8 去读：

```python
import json

# 假设 content 是按 GBK 读进来的字节（模拟 Windows 记事本保存的文件）
raw_gbk = "{\"name\": \"张三\"}".encode("gbk")

# WRONG：当 UTF-8 去解码
s = raw_gbk.decode("utf-8")
print(s)
```

报错：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd5 in position ...: invalid continuation byte
```

**怎么修**：用对编码解码，或者干脆重新以 UTF-8 保存。

```python
# 正确：按实际编码解码
s = raw_gbk.decode("gbk")
data = json.loads(s)
print(data)                 # {'name': '张三'}

# 或者：读取时指定 errors 处理策略（容错但不推荐，会丢字符）
s2 = raw_gbk.decode("utf-8", errors="replace")
print(s2)                   # {"name": "??"}  乱码被替换成 ?
```

## 翻车现场：BOM 让第一个键莫名其妙读不出

BOM（Byte Order Mark，`\ufeff`）是某些编辑器（尤其是 Windows 记事本"另存为 UTF-8"）在文件**开头偷偷加的三个字节**，用来标记"这是 UTF-8 文件"。

```python
# 模拟一个带 BOM 的文件内容
bom_json = "\ufeff{\"name\": \"张三\"}"

import json
data = json.loads(bom_json)
print(data)                 # 其实能读出来，键是正常的

# 但如果是按行读、或者自己做字符串处理：
first_char = bom_json[0]
print(repr(first_char))     # '\ufeff'  看不见的字符
print(first_char == "{")    # False
```

BOM 最坑的场景是**你自己做解析**时，开头多了一个看不见的 `\ufeff`，导致判断、切片全部错位。

```python
# WRONG：直接用带 BOM 的文件做 key 匹配
line = "\ufeffadmin: 1"
if line.startswith("admin"):
    print("是管理员")
else:
    print("不是")            # 走到这里，因为开头是 \ufeff
```

**怎么修**：`open()` 时用 `encoding="utf-8-sig"`，它会自动吃掉 BOM：

```python
with open("with_bom.json", "w", encoding="utf-8-sig") as f:
    f.write("\ufeff")        # 模拟 BOM 已存在
    f.write('{"name": "张三"}')

with open("with_bom.json", encoding="utf-8-sig") as f:
    data = json.load(f)      # 自动跳过 BOM
print(data)                  # {'name': '张三'}
```

## ensure_ascii 与编码的关系

回顾一下：`ensure_ascii=False` 决定的是**字符串要不要转义**，编码决定的是**这些字符最终按什么字节存**。

```python
import json

data = {"city": "北京"}

# 方案 A：ensure_ascii=True（默认）+ UTF-8 存盘
t1 = json.dumps(data)                        # '{"city": "\\u5317\\u4eac"}'
t1.encode("utf-8")                           # 纯 ASCII 字节，任何系统都能读

# 方案 B：ensure_ascii=False + UTF-8 存盘（推荐）
t2 = json.dumps(data, ensure_ascii=False)    # '{"city": "北京"}'
t2.encode("utf-8")                           # 含中文字节，需以 UTF-8 解码
```

**两种方案都正确、都能被任何 JSON 解析器读懂**（JSON 标准规定必须以 Unicode 解读）。差别在于：

- 方案 A：文件全 ASCII，兼容性好，但人看不懂
- 方案 B：中文清晰，但读的人必须知道是 UTF-8

只要**写和读用同一个编码**（都用 UTF-8），方案 B 就是最优解。

## 翻车现场：errors 参数误用导致数据静默损坏

```python
# WRONG：用 errors="ignore" 吞掉无法解码的字节
with open("data.txt", "rb") as f:
    raw = f.read()
text = raw.decode("utf-8", errors="ignore")   # 坏字节直接丢弃
print(text)        # 可能缺字，你却不知道
```

`errors="ignore"` 和 `errors="replace"` 都是"容错"手段，但它们**会静默损坏数据**。调试阶段千万别用，会让问题更难查。

```python
# 宁可让它报错
text = raw.decode("utf-8")   # 解码失败就报错，早暴露早修
```

## 实战：写一个跨平台的 JSON 读写工具

```python
import json
import os

def read_json(path, default=None):
    """读 JSON。文件不存在返回 default；BOM 自动处理；编码用 UTF-8。"""
    if not os.path.exists(path):
        return default
    with open(path, encoding="utf-8-sig") as f:
        return json.load(f)

def write_json(obj, path):
    """写 JSON。中文可读、带缩进、UTF-8 无 BOM。"""
    with open(path, "w", encoding="utf-8") as f:
        json.dump(obj, f, ensure_ascii=False, indent=2)

# 使用
profile = {"name": "张三", "city": "北京", "hobbies": ["编程", "篮球"]}
write_json(profile, "profile.json")

loaded = read_json("profile.json")
print(loaded["name"], "来自", loaded["city"])
```

输出：

```
张三 来自 北京
```

这个工具函数涵盖了本章全部要点：`utf-8-sig` 处理 BOM、`ensure_ascii=False` 中文可读、`indent=2` 格式清晰、`encoding="utf-8"` 跨平台一致。

## 小结

- `str` 是字符，`bytes` 是字节；`encode` 编码、`decode` 解码
- **磁盘上永远是 bytes**，用什么编码写、就用什么编码读
- Windows 默认 GBK、Linux/macOS 默认 UTF-8，跨平台务必显式 `encoding="utf-8"`
- **BOM** 是文件开头看不见的 `\ufeff`，用 `encoding="utf-8-sig"` 自动跳过
- `ensure_ascii=False` 管"要不要转义"，编码管"按什么字节存"，两者正交
- `errors="ignore"/"replace"` 会静默丢数据，调试阶段不要用
- 封装 `read_json`/`write_json` 统一处理编码和 BOM 是项目级最佳实践
