# 事务与连接管理

> 这一课收尾数据层：commit 和 rollback 到底管什么、连接该什么时候打开、什么时候关。把这两件事做对，你的程序才不会"数据神秘丢失"或"文件被锁死"。

## 事务：一组操作要么全成要么全败

**事务（transaction）是数据库的核心概念。** 它保证一组操作"要么全部生效，要么全部作废"，不会停在中间状态。

**举个记账场景**：用户想把一笔 100 元的"餐饮"改成"交通"，同时新增一条备注。这两步应该绑定在一起——如果第一步成功、第二步失败，数据库就处于不一致状态。

```python
try:
    cur.execute("UPDATE records SET category='交通' WHERE id=?", (1,))
    cur.execute("UPDATE records SET note='已更正' WHERE id=?", (1,))
    conn.commit()        # 两步都成功才提交
except Exception:
    conn.rollback()      # 任何一步失败就回滚，回到原样
    raise
```

**没有事务的世界**：网络抖动、程序崩溃、磁盘满了，都可能让一组操作只做了一半。有了事务，出任何问题都能 `rollback()` 回到操作前的状态。

## 自动提交模式

**默认情况下，SQLite 是"延迟提交"：INSERT/UPDATE/DELETE 后必须显式 commit。**

**但你可以打开"自动提交"模式**：每条语句执行完立刻提交，不用手动 commit。在桌面小程序里这能少写几行代码，代价是**失去事务的原子性**——多条语句没法绑定在一起了。

**本项目保持手动提交**，因为"添加一条记录"看似简单，但后续你可能要在同一个事务里"插入记录 + 更新统计缓存 + 写日志"，保留事务能力更灵活。

## with 上下文管理连接

**`sqlite3.connect()` 返回的连接对象支持 `with`，但很多人用错（第 6 课提过一次，这里讲透）：**

```python
with sqlite3.connect("ledger.db") as conn:
    cur = conn.cursor()
    cur.execute("INSERT INTO records(amount) VALUES (38.5)")
    # 没异常 → 离开 with 时自动 commit
# 异常 → 离开 with 时自动 rollback
```

**关键：with 结束的是事务，不是连接。** 离开 with 块后，连接对象仍然有效，你还能继续用——只是那个事务已经提交了。

**这是反直觉的重点**：with 不是"连接的生命周期管理器"，而是"事务的边界"。想管理连接生命周期，得自己写：

```python
conn = sqlite3.connect("ledger.db")
try:
    with conn:                      # 只管这一组操作的事务
        cur = conn.cursor()
        cur.execute("INSERT INTO records(amount) VALUES (38.5)")
    # 这里 conn 还开着，还能继续别的
finally:
    conn.close()                    # 真正关闭连接
```

## 连接什么时候关

**桌面应用的标准做法：程序启动时开一个全局连接，程序退出时关。**

```python
# main.py
import tkinter as tk
import sqlite3
import db

def on_close():
    db.close_conn()     # 在关闭窗口前关数据库
    root.destroy()

root = tk.Tk()
db.init_global_conn("ledger.db")
root.protocol("WM_DELETE_WINDOW", on_close)
root.mainloop()
```

**为什么要挂 `WM_DELETE_WINDOW`？** 因为用户点右上角关闭，tkinter 默认直接杀进程，你的 `conn.close()` 可能来不及执行。挂上这个协议，点关闭时会先跑你的清理逻辑。

**如果不关会怎样？** 通常 SQLite 会在进程退出时自动回滚未提交事务并关闭文件，但**未提交的数据可能丢失**，且文件锁释放不及时，下次启动可能短暂报"database is locked"。

## 短连接 vs 长连接

**两种风格对比：**

| 风格 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 短连接 | 每个函数内 connect + close | 简单、不怕忘记关 | 频繁开关有开销 |
| 长连接 | 全局一个，全程复用 | 快、能保持事务 | 要小心单线程 |

**tkinter 程序是单线程事件循环**，天然适合长连接。多连接并发写同一个 db 还会触发 `database is locked`，所以本项目一律长连接。

## 翻车现场一：异常跳过 commit，数据丢失

```python
cur.execute("INSERT INTO records(amount) VALUES (38.5)")
1/0                        # 故意制造异常
conn.commit()              # 永远执行不到
```

**症状**：没报错（异常向上传播被顶层捕获），但数据没存进去，查不到。

**原因**：commit 在异常之后，没机会执行。异常离开作用域时，SQLite 自动回滚了未提交事务。

**解决**：写操作包 try/except，或者在 with 块里做——with 会在异常时自动 rollback，至少不会留半截状态。

## 翻车现场二：with 之后还用游标

```python
with sqlite3.connect("ledger.db") as conn:
    cur = conn.cursor()
    cur.execute("SELECT * FROM records")

rows = cur.fetchall()      # 有时能跑，有时报 "Cannot operate on a closed database"
```

**症状**：偶发的 `sqlite3.ProgrammingError: Cannot operate on a closed database`。

**原因**：离开 with 块时，SQLite 不仅提交了事务，在某些情况下还会把底层连接标记为不可用。**更隐蔽的问题是：你在 with 外还持有那个游标，游标的生命周期绑定在连接上。**

**解决**：查询和取结果都在 with 块内完成，把结果存进变量再出来：

```python
with sqlite3.connect("ledger.db") as conn:
    cur = conn.cursor()
    cur.execute("SELECT * FROM records")
    rows = cur.fetchall()     # 在块内取完
# 这里用 rows，不用 cur
```

## 翻车现场三：忘了关连接，文件被锁

**症状**：程序异常退出后，再次启动时 `connect()` 报 `database is locked`，要等几十秒甚至重启电脑才恢复。

**原因**：上次进程没正常关闭连接，文件锁残留。Windows 上尤其常见。

**解决**：始终挂 `WM_DELETE_WINDOW` 做清理；开发时如果用 Ctrl+C 强杀进程，手动删掉同目录的 `-journal` 或 `-wal` 临时文件（SQLite 用它做崩溃恢复）。

## 小结

- 事务保证一组操作原子性：全成或全败
- 默认延迟提交，写操作要手动 commit；出错 rollback
- with 管事务边界，不管连接生命周期
- 桌面程序用全局长连接，退出时挂 WM_DELETE_WINDOW 关闭
- 查询和取结果都要在 with 块内完成
- 异常退出会留文件锁，开发时可能要清理 wal/journal 文件

## 随堂练习

```quiz
type: local
q: 在 db.py 里实现全局连接管理：init_global_conn(path) 打开连接并存到模块变量，close_conn() 关闭它，get_conn() 返回它。main.py 里挂 WM_DELETE_WINDOW 在窗口关闭时调 close_conn()。注意：sqlite3 本地运行，网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  # db.py
  _CONN = None

  def init_global_conn(path):
      global _CONN
      _CONN = sqlite3.connect(path)
      _CONN.row_factory = sqlite3.Row

  def get_conn():
      return _CONN

  def close_conn():
      global _CONN
      if _CONN is not None:
          _CONN.close()
          _CONN = None

  # main.py
  import tkinter as tk
  import db
  root = tk.Tk()
  db.init_global_conn("ledger.db")
  # 挂 WM_DELETE_WINDOW
  root.mainloop()
checklist:
- init_global_conn 打开了连接
- get_conn 返回全局连接
- close_conn 会关闭且置 None
- main.py 挂了 WM_DELETE_WINDOW 在关闭时关闭数据库
```
