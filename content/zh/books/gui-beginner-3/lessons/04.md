# 原型草图：先画界面再写代码

> 代码分层定好了，动手前最后一件事：把界面长什么样画出来。不是用设计软件，是用 ASCII 字符在纸上画。先想清楚"用户眼睛看到什么、手点哪里"，再决定"代码里放几个控件"。

## 为什么先画草图

**跳起草图直接写代码的人，往往会写出"控件打架"的界面**：录入区的按钮挡住表格最后一行，日期框挤不下 10 个字符，分类下拉框宽到离谱。

**草图的价值在于用最低成本试错。** 画错了擦掉重写，只要十秒；代码写完了发现布局不对，改起来要翻好几个文件。

## 我们要的界面：上中下三层

**对着需求 F1（记一笔）和 F2（看列表），界面自然分成三块：**

```
┌─────────────────────────────────────────┐
│  记账本 Ledger                  📊统计  │  ← 顶部：标题 + 统计按钮
├─────────────────────────────────────────┤
│  日期        金额     分类     备注      │
│  2026-09-27  38.5    餐饮     午餐      │  ← 中间：记录列表
│  2026-09-26  120     交通     打车      │
│  2026-09-25  8000    工资     发薪      │
│  ...                                    │
├─────────────────────────────────────────┤
│ 日期 [____] 金额 [____] 分类 [下拉▼]    │
│ 备注 [________________]   [+ 记一笔]    │  ← 底部：录入表单
└─────────────────────────────────────────┘
```

**三块各司其职**：顶部是全局操作（切换页面、看统计），中间是数据的"主角"——表格，底部是录入区，所有输入控件一行排开，最右边是"记一笔"按钮。

## 每个控件对应哪个需求

**草图不是随便摆控件，每个控件都要能指回一条需求：**

| 控件 | 对应的需求 |
|---|---|
| 中间表格 Treeview | F2 看列表 |
| 底部"记一笔"按钮 | F1 记一笔 |
| 底部日期/金额/分类/备注输入框 | F1 记一笔 |
| 顶部"📊统计"按钮 | F3 按分类统计 |
| 数据库文件 ledger.db | F4 存下来 |

**练习：对着你的草图，给每个控件标注它服务哪条需求。** 标不出来的控件，多半是多余的。

## 字段摆放的小心思

**录入区几个控件怎么排，是有讲究的：**

- **日期放最左**：用户从左到右填，日期是第一个要填的；
- **金额紧跟**：金额是核心，放显眼位置，宽一点；
- **分类用下拉框 Combobox**：不能让用户自由输入，否则分类名会五花八门（"餐饮""吃饭""饭"全算不同的），统计就废了；
- **备注放一行长条**：备注通常长，单行 Entry 够用；
- **按钮放最右**：用户填完最后一项，手自然落在右下角。

## 翻车现场一：录入控件用 Entry 让自由输入分类

```python
cat_entry = tk.Entry(form_frame)   # 错误：自由输入
```

**症状**：用户今天填"餐饮"、明天填"吃饭"、后天填"饭"，数据库里出现三个"不同的分类"，统计时三笔被算成三份。

**原因**：分类应该是固定选项，而不是自由文本。

**解决**：用 `ttk.Combobox` 加 `values=("餐饮","交通","购物","工资",...)`，必要时允许 `state="readonly"` 强制只能选。

## 翻车现场二：把录入区放顶部、列表放底部

**有些新手照"先输入后展示"的思路，把表单放顶部、表格放底部。**

**症状**：录了 20 条记录以后，想看刚录的那条，得把滚动条拖到最底——新记录通常要排在顶部（时间倒序），这就矛盾了。

**原因**：把"操作顺序"和"信息优先级"混为一谈。用户最常看的是历史列表，它应该占最大面积、在最顺眼的中间位置。

**解决**：录入区放底部（一次录一条，占一行就够了），列表占中间主力区域。

## 尺寸怎么定

**不用纠结像素，先用"比例"想布局。** 这个界面用 `pack` 三刀切就够了：

- 顶部工具栏 `side="top"`、固定高度；
- 底部录入区 `side="bottom"`、固定高度；
- 中间表格 `side="top"`、加 `fill="both", expand=True` 让它吃满剩余空间。

**中间表格要能伸缩**：`expand=True` 保证窗口放大时表格跟着变大，用户在大屏上不会看到一大片空白。

## 小结

- 动手前用 ASCII 画草图，最低成本试错
- 界面上中下三层：工具栏 / 表格 / 录入区
- 每个控件都要能指回一条需求，指不出的多半多余
- 分类用 Combobox 固定选项，别让自由输入毁了统计
- 列表占主力区、录入区放底部，符合"信息优先级"
