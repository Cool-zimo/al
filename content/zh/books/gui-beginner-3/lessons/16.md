# 把数据接进界面：加载数据到 Treeview

> 前三课把界面骨架搭好了，这一课做第一次"打通"：让程序启动时自动从数据库读数据、填进表格。虽然还没有录入功能，但你能看到真实数据出现在界面上。

## 启动流程

**一个桌面应用的标准启动顺序：**

1. 创建根窗口；
2. 初始化数据层（建表）；
3. 搭建界面；
4. **首次刷新表格**（把数据库现有数据加载进来）；
5. 进入主循环。

**第 4 步是关键，漏了它你会发现：数据库里有数据，但界面一片空白。**

```python
import tkinter as tk
import db, logic, ui

def main():
    root = tk.Tk()
    root.title("记账本 Ledger")
    root.geometry("800x600")
    root.minsize(640, 480)

    db.init_global_conn("ledger.db")
    db.ensure_schema()

    app = ui.build(root)                 # app 是个字典，装着 tree 等控件引用
    ui.refresh_table(app["tree"], app["empty_label"], db.get_conn())

    def on_close():
        db.close_conn()
        root.destroy()
    root.protocol("WM_DELETE_WINDOW", on_close)

    root.mainloop()

if __name__ == "__main__":
    main()
```

**`ui.build` 返回控件引用字典**，是因为 main 需要拿到 tree 去调刷新，而其他函数（录入回调）也需要它。把控件引用存起来比用全局变量干净。

## 用真实数据填充

**先往数据库塞几条测试数据（一次性脚本，跑完就删）：**

```python
# seed.py（用完即弃的脚本）
import sqlite3
from datetime import datetime

conn = sqlite3.connect("ledger.db")
cur = conn.cursor()
cur.execute("""CREATE TABLE IF NOT EXISTS records(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    amount REAL NOT NULL, category TEXT NOT NULL,
    date TEXT NOT NULL, note TEXT, type TEXT NOT NULL DEFAULT '支出',
    created_at TEXT NOT NULL)""")

samples = [
    (38.5, "餐饮", "2026-09-27", "午餐", "支出"),
    (120.0, "交通", "2026-09-26", "打车", "支出"),
    (8000.0, "工资", "2026-09-25", "发薪", "收入"),
    (256.0, "购物", "2026-09-24", "买书", "支出"),
    (65.0, "餐饮", "2026-09-22", "晚餐", "支出"),
]
cur.executemany("INSERT INTO records(amount,category,date,note,type,created_at) VALUES(?,?,?,?,?,?)",
                [(a, c, d, n, t, datetime.now().isoformat()) for (a, c, d, n, t) in samples])

```

**`executemany` 是批量插入利器**，第二个参数是元组列表，一次搞定。开发阶段用它造测试数据，比一条条 insert 省事得多。

## refresh_table 的完整实现

**把第 12 课的刷新逻辑加上格式化、加上空状态：**

```python
def refresh_table(tree, empty_label, conn):
    rows = db.get_all(conn)                       # 列表，元素为 sqlite3.Row
    if not rows:
        tree.pack_forget()
        empty_label.pack(fill="both", expand=True, pady=80)
        return

    empty_label.pack_forget()
    tree.pack(fill="both", expand=True)

    for iid in tree.get_children():
        tree.delete(iid)

    for r in rows:
        tree.insert("", "end", iid=str(r["id"]), values=(
            r["date"].replace("-", "/"),
            f"{r['amount']:,.2f}",
            r["category"],
            r["note"] or "",
            r["type"],
        ))
```

**这里的 `r` 是 `sqlite3.Row` 对象**，所以能用 `r["amount"]` 按列名取值——这正是第 6 课设置 `row_factory` 的回报。

## 让列可排序

**点击列标题排序，是桌面软件的常见交互。** 实现思路：给每个 heading 绑一个点击回调，记录排序方向，重查并重填。

```python
_sort_state = {"col": "date", "desc": True}

def _on_heading_click(tree, col):
    if _sort_state["col"] == col:
        _sort_state["desc"] = not _sort_state["desc"]   # 再点一次反向
    else:
        _sort_state["col"] = col
        _sort_state["desc"] = True
    # 重查
    conn = db.get_conn()
    rows = db.get_all_sorted(conn, col, _sort_state["desc"])
    _refill(tree, rows)

def _refill(tree, rows):
    for iid in tree.get_children():
        tree.delete(iid)
    for r in rows:
        tree.insert("", "end", iid=str(r["id"]), values=(...))
```

**`db.get_all_sorted(conn, col, desc)` 是一个新函数，用白名单校验列名后拼 SQL：**

```python
VALID = {"date", "amount", "category", "type"}

def get_all_sorted(conn, col, desc):
    if col not in VALID:
        col = "date"
    order = "DESC" if desc else "ASC"
    cur = conn.cursor()
    cur.execute(f"SELECT ... FROM records ORDER BY {col} {order}, id DESC")
    return cur.fetchall()
```

**列名用 f-string 拼接，所以必须白名单校验**——这是第 9 课讲的规则。列名不能占位符，只能拼 + 白名单。

## 翻车现场一：启动后表格空白，但数据库有数据

**症状**：明明 seed 了数据，`print(len(db.get_all(conn)))` 也显示 5 条，但界面空空。

**原因**：`ui.build` 里只创建了 Treeview，没有调用 `refresh_table`。界面画好了，但没人往里灌数据。

**解决**：build 之后立刻调一次 `refresh_table`。养成习惯：任何可能改变显示的函数末尾都刷新。

## 翻车现场二：executemany 参数结构错了

```python
samples = [(38.5, "餐饮", ...), (120, "交通", ...)]
cur.executemany("INSERT INTO records(amount,category) VALUES(?,?)", samples)
# 报错：Incorrect number of bindings supplied. Current statement uses 2, and there are 3 supplied.
```

**症状**：`sqlite3.ProgrammingError: Incorrect number of bindings supplied`。

**原因**：SQL 里 `?` 是 2 个，但元组里有 3 个元素（samples 的每个元组是 `(a,c,d,n,t)` 五个元素）。`executemany` 要求每个元组的长度严格等于 `?` 数量。

**解决**：要么把元组截成对应长度，要么写个生成器把缺的字段补上默认值。

## 翻车现场三：排序时列名没做白名单，埋下注入隐患

```python
col = tree.heading(col)["text"]         # 用户点的是"金额"
cur.execute(f"SELECT * FROM records ORDER BY {col}")   # 直接拼
```

**症状**：功能正常，但 `col` 来自界面，理论上可被篡改（如果是动态列）。

**解决**：永远只把界面列名映射到白名单里的字段名。`VALID` 集合一查，不在里面就 fallback 到 `date`。

## 小结

- 启动顺序：建窗口 → 初始化数据层 → 搭界面 → 首次刷新 → 主循环
- ui.build 返回控件引用字典，避免全局变量
- 开发期用 executemany 批量造测试数据
- refresh_table 先判空（空状态）再格式化填充
- 排序靠点击 heading + 白名单拼列名 + 反向切换
- 启动后界面空白，第一反应：是不是忘了调 refresh_table
