# 添加一条记录：从表单到数据库再回到表格

> 这一课完成第一个完整闭环：用户在表单里填数据 → 点"记一笔" → 数据进数据库 → 表格自动出现新行。这是整个应用最核心的一次打通。

## 完整链路

**一次添加操作要走过四层：**

1. 界面层：从 Entry/Combobox 取值；
2. 逻辑层：校验；
3. 数据层：INSERT；
4. 界面层：刷新表格 + 清空表单。

**回调只负责串起这条链，自己不写业务逻辑：**

```python
def on_add():
    date = app["date_var"].get().strip()
    amt = app["amt_var"].get().strip()
    cat = app["cat_var"].get().strip()
    note = app["note_var"].get().strip()
    rtype = app["type_var"].get()          # "支出" 或 "收入"

    ok, msg = logic.validate(date, amt, cat)
    if not ok:
        mb.showerror("输入有误", msg)
        return

    conn = db.get_conn()
    rid = db.add_record(conn, float(amt), cat, date, note, rtype)
    app["status_var"].set(f"已保存 · 新记录 #{rid}")
    root.after(3000, lambda: app["status_var"].set("就绪"))

    refresh_table(app["tree"], app["empty_label"], conn)
    _clear_form()
```

**`db.add_record` 返回新记录的 id**（第 8 课用 `cur.lastrowid`），状态栏直接显示 `#{rid}`，用户能确认"存进去了、是第几条"。

## 清空表单

**录入成功后清空输入框，让用户继续录下一条：**

```python
def _clear_form():
    app["date_var"].set(date.today().isoformat())   # 日期恢复今天
    app["amt_var"].set("")
    app["note_var"].set("")
    # cat_var 保留上次选择，减少重复操作
```

**日期恢复成今天、分类保留上次选择**——这是产品决策，目的都是减少重复输入。录入记账本的操作频率很高，每少一次按键都是体验提升。

## 录入区的完整实现

**把第 13 课的表单控件存进 app 字典，方便回调取用：**

```python
def build(root):
    app = {}

    # ---- 底部录入区（grid）----
    form = tk.Frame(root, padx=8, pady=8)
    form.pack(side="bottom", fill="x")

    app["date_var"] = tk.StringVar(value=date.today().isoformat())
    app["amt_var"] = tk.StringVar()
    app["cat_var"] = tk.StringVar(value="餐饮")
    app["note_var"] = tk.StringVar()
    app["type_var"] = tk.StringVar(value="支出")

    tk.Label(form, text="类型").grid(row=0, column=0, sticky="w")
    tk.Radiobutton(form, text="支出", variable=app["type_var"], value="支出").grid(row=1, column=0)
    tk.Radiobutton(form, text="收入", variable=app["type_var"], value="收入").grid(row=1, column=1)

    tk.Label(form, text="日期").grid(row=0, column=2, sticky="w")
    tk.Entry(form, textvariable=app["date_var"], width=12).grid(row=1, column=2, padx=4)

    tk.Label(form, text="金额").grid(row=0, column=3, sticky="w")
    tk.Entry(form, textvariable=app["amt_var"], width=10).grid(row=1, column=3, padx=4)

    tk.Label(form, text="分类").grid(row=0, column=4, sticky="w")
    ttk.Combobox(form, textvariable=app["cat_var"], width=9,
                 values=("餐饮","交通","购物","居住","工资","其他"),
                 state="readonly").grid(row=1, column=4, padx=4)

    tk.Label(form, text="备注").grid(row=0, column=5, sticky="w")
    tk.Entry(form, textvariable=app["note_var"], width=24).grid(row=1, column=5, padx=4)

    tk.Button(form, text="+ 记一笔", command=on_add).grid(row=1, column=6, padx=8)

    # ---- 中间列表区 ----
    list_container = tk.Frame(root)
    list_container.pack(side="top", fill="both", expand=True)

    cols = ("date","amount","category","note","type")
    app["tree"] = ttk.Treeview(list_container, columns=cols, show="headings")
    for c in cols:
        app["tree"].heading(c, text=c)
        app["tree"].column(c, width=120 if c=="note" else 90,
                           anchor="center" if c!="note" else "w")
    app["tree"].pack(fill="both", expand=True)

    app["empty_label"] = tk.Label(list_container,
        text="还没有任何记录\n\n记录你的第一笔收支吧", justify="center", fg="#999", font=("",12))

    # ---- 状态栏 ----
    app["status_var"] = tk.StringVar(value="就绪")
    tk.Label(root, textvariable=app["status_var"], anchor="w", relief="sunken")\
        .pack(side="bottom", fill="x")

    return app
```

**所有控件引用集中放在 `app` 字典里**，回调通过闭包或传参拿到它。这是 tkinter 项目里避免全局变量的常用手法。

## 为什么要用变量字典而不是全局变量

**新手常写一堆全局变量：**

```python
global tree, date_var, amt_var, cat_var, note_var   # 满屏 global
```

**问题在于**：一旦你有多个窗口（比如统计窗口），全局变量就不够用了，变量名冲突、状态混乱。

**用字典或对象封装状态**：`app["tree"]`、`app["date_var"]`，逻辑清晰，还能把 app 传给其他模块。

## 翻车现场一：录入后表格没更新，用户以为没存上

**症状**：弹窗"已保存"，但表格里看不到新行，用户反复点，存了一堆重复。

**原因**：INSERT 成功了，但没调 `refresh_table`。

**解决**：每次写操作后必须刷新。这一课我们先手动调，第 19 课会用观察者模式自动化。

## 翻车现场二：金额没转 float 就存

```python
db.add_record(conn, amt, cat, date, note, rtype)   # amt 是字符串 "38.5"
```

**症状**：不报错，但 `amount` 列存的是字符串（如果你的建表语句写错了类型，比如写成 TEXT），统计时 `SUM` 出问题。

**原因**：Entry 的 `get()` 返回字符串，没转数字就直接传。即使表字段是 REAL，SQLite 会隐式转，但带着单位（"38.5元"）就会错。

**解决**：校验通过后 `float(amt)` 再传。校验逻辑已经保证了能转，这里直接转即可。

## 翻车现场三：清空表单时把日期也清空了

```python
def _clear_form():
    app["date_var"].set("")
    app["amt_var"].set("")
    ...
```

**症状**：用户录完一笔，日期框变空，录下一条还得手动填日期。

**原因**：清空逻辑一刀切。

**解决**：日期恢复成今天 `date.today().isoformat()`，分类保留上次选择。这是减少重复输入的细节打磨。

## 小结

- 添加 = 界面取值 → 逻辑校验 → 数据 INSERT → 刷新表格 → 清空表单
- add_record 返回新 id，状态栏显示 #id 给用户反馈
- 控件引用集中放字典，避免满屏 global
- 日期恢复今天、分类保留上次，减少重复输入
- 每次写操作后都要刷新表格，否则用户看不到变化
- 金额必须 float 转换后传入
