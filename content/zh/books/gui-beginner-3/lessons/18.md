# 删除与修改：选中行 → 确认 → 操作 → 刷新

> 录入做完了，这一课补上两个必备操作：删除和修改。它们的共同点是都要"先选中一行"——所以重点讲 Treeview 的选中机制，以及为什么 iid 要用数据库 id。

## 选中一行：selection

**Treeview 的 `selection()` 返回当前选中行的 iid 元组（可能多选）：**

```python
sel = tree.selection()
if not sel:
    mb.showwarning("提示", "请先选中一条记录")
    return
rid = int(sel[0])          # iid 就是我们设的数据库 id
```

**三个前提，一个都不能少：**

1. **插入时 `iid=str(r["id"])`**（第 12 课强调过）；
2. **只允许单选**：创建 Treeview 时 `selectmode="browse"`（默认就是 browse，一选一）；
3. **没选中要给提示**，否则下面 `int(sel[0])` 直接 IndexError。

**`selectmode` 的三个取值：**

| 取值 | 行为 |
|---|---|
| `"browse"` | 单选（默认），最常用 |
| `"extended"` | 多选（Ctrl/Shift 选多行） |
| `"none"` | 禁止选中 |

## 删除：确认后 DELETE + 刷新

**完整流程：**

```python
def on_delete():
    sel = app["tree"].selection()
    if not sel:
        mb.showwarning("提示", "请先选中一条记录")
        return
    rid = int(sel[0])

    ok = mb.askyesno("确认删除",
                     "确定要删除这条记录吗？\n此操作不可恢复。")
    if not ok:
        return

    conn = db.get_conn()
    n = db.delete_record(conn, rid)
    if n == 0:
        mb.showerror("删除失败", f"找不到 id 为 {rid} 的记录，可能已被删除")
        return

    app["status_var"].set("已删除一条记录")
    root.after(3000, lambda: app["status_var"].set("就绪"))
    refresh_table(app["tree"], app["empty_label"], conn)
```

**`askyesno` 是"确认对话框"**，返回 True/False。删除、清空、重置这类不可逆操作都必须加。

**`delete_record` 返回 `rowcount`**，为 0 说明没删到东西——可能是并发下被别人删了，或者 id 对不上。这时候刷新一下表格最稳妥。

## 修改：双击或点按钮弹出编辑窗口

**修改比删除复杂一点：要先把选中行的值回填进表单，改完再 UPDATE。**

**有两种交互设计：**

1. **点按钮"编辑"，把值回填到底部录入区，把"+ 记一笔"临时变成"保存修改"**——改动小、不弹窗，适合记账本这种简单场景；
2. **双击行弹出 Toplevel 编辑窗口**——更"专业"，但要处理模态、焦点。

**本项目用第一种（更轻量）。实现思路：用一个标志位区分"新增"和"编辑"模式：**

```python
app["editing_id"] = None          # None 表示当前是新增模式

def on_edit():
    sel = app["tree"].selection()
    if not sel:
        mb.showwarning("提示", "请先选中一条记录")
        return
    rid = int(sel[0])
    conn = db.get_conn()
    r = db.get_by_id(conn, rid)   # SELECT ... WHERE id=?
    if r is None:
        mb.showerror("错误", "记录不存在")
        return
    # 回填到表单
    app["date_var"].set(r["date"])
    app["amt_var"].set(str(r["amount"]))
    app["cat_var"].set(r["category"])
    app["note_var"].set(r["note"] or "")
    app["type_var"].set(r["type"])
    app["editing_id"] = rid
    app["submit_btn"].config(text="保存修改")

def on_submit():                  # 原本的 on_add，改名复用
    # ... 取值、校验 ...
    conn = db.get_conn()
    if app["editing_id"] is not None:
        rid = app["editing_id"]
        db.update_record(conn, rid, float(amt), cat, date, note, rtype)
        app["status_var"].set(f"已修改 · 记录 #{rid}")
        app["editing_id"] = None
        app["submit_btn"].config(text="+ 记一笔")
    else:
        db.add_record(conn, float(amt), cat, date, note, rtype)
        app["status_var"].set("已保存")
    refresh_table(...)
    _clear_form()
```

**用 `editing_id` 这个标志位区分两种模式**，按钮文字随之变化，用户很清楚自己在"新增"还是"修改"。

## 双击行也能编辑

**更顺手的做法：双击表格行直接进入编辑模式：**

```python
app["tree"].bind("<Double-1>", lambda e: on_edit())
```

**`<Double-1>` 是"双击左键"的事件。** 绑上去后用户双击任意一行就能编辑，不用先选中再点按钮。

## 翻车现场一：忘了设 iid，selection 拿到的是乱码

```python
tree.insert("", "end", values=(...))    # 没传 iid
sel = tree.selection()
rid = int(sel[0])                        # ValueError: invalid literal for int()
```

**症状**：`ValueError: invalid literal for int() with base 10: 'I001'`。

**原因**：没设 iid，Treeview 自动生成 `"I001"` 这种内部编号，转 int 失败。

**解决**：插入时 `iid=str(r["id"])`。

## 翻车现场二：没选中就点删除，IndexError

```python
def on_delete():
    sel = tree.selection()
    rid = int(sel[0])        # IndexError: tuple index out of range
```

**症状**：`IndexError`，因为 `sel` 是空元组 `()`。

**原因**：没判断空就直接取下标。

**解决**：`if not sel: mb.showwarning(...); return`。

## 翻车现场三：编辑完忘了把按钮文字改回来

**症状**：用户编辑了一条，按钮还是显示"保存修改"。之后想新增，点了按钮却变成了"修改刚才那条"——因为 `editing_id` 还留着。

**原因**：操作结束后没重置状态。

**解决**：每次提交完成、或用户点"取消编辑"时，重置 `editing_id = None`、按钮文字改回"+ 记一笔"、表单清空。建议加一个"取消"按钮专门做这件事。

## 小结

- 删除/修改前用 tree.selection() 拿选中行 iid，必须判断非空
- iid 要用数据库 id，否则无法定位记录
- 删除是不可逆操作，必须 askyesno 二次确认
- 用 editing_id 标志位区分新增/编辑模式，按钮文字随之变化
- 双击行进入编辑：tree.bind("<Double-1>", ...)
- 操作结束要重置状态（editing_id、按钮文字、表单）
