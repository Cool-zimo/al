# 打包：把记账本变成一个双击就能跑的 exe

> 代码写完了，你妈想用你的记账本。你总不能让她先装个 Python、再装 tkinter、matplotlib、再 `git clone` 你的仓库吧。这一课讲怎么把整个项目打成单个可执行文件，以及为什么事情没你想的那么简单。

## 需求：从源码到可分发产物

**打包要解决的是"交付最后一公里"的问题：**

| 目标 | 说明 |
|---|---|
| 单一文件 | 用户拿到一个 `.exe`（或 macOS 的 app、Linux 的可执行文件），双击就跑 |
| 不要求装 Python | 目标机器上没有解释器也能运行 |
| 带上依赖 | sqlite3、matplotlib、tkinter 这些全打进去 |
| 带上资源 | 图标、默认数据文件、中文字体 |
| 干净卸载 | 不留垃圾，最好就是删一个文件/一个文件夹 |

**PyInstaller 是目前最省心的选择**：纯 Python、跨平台、对 tkinter 支持开箱即用。另一个常见选择是 `cx_Freeze`，但配置更啰嗦；Nuitka 会把 Python 编译成 C 再编译，体积小、启动快，但编译慢、排错痛苦。新手无脑选 PyInstaller。

**安装：**

```
pip install pyinstaller
pyinstaller --version
```

**确保你在项目的虚拟环境里装、打包**。全局装一份、项目用另一套依赖，最容易踩坑。

## 基本命令：一条命令打出来

**最简单的用法，在项目根目录运行：**

```
pyinstaller main.py
```

**这条命令会做这些事：**
1. 分析 `main.py` 的 import，递归收集所有依赖；
2. 在 `build/` 目录里生成中间文件；
3. 在 `dist/main/` 目录里输出一堆文件——这就是你的程序，双击 `main.exe`（Windows）或 `main`（macOS/Linux）就能跑。

**`--onefile`：打包成单个文件**

```
pyinstaller --onefile main.py
```

出来的 `dist/main.exe` 就是单独一个文件，分发最方便。

**`--name`：指定输出文件名**

```
pyinstaller --onefile --name Ledger main.py
```

## `--onefile` vs `--onedir`：最经典的取舍

**这两个选项决定了产物长什么样，也决定了用户体感：**

| 维度 | `--onefile`（单文件） | `--onedir`（文件夹，默认） |
|---|---|---|
| 产物形态 | 一个 exe | 一个文件夹，里面有 exe + 一堆 dll/pyd |
| 分发体验 | 极简，一个文件发过去 | 得打包成 zip 或安装包 |
| 启动速度 | 慢，每次都要解压到临时目录 | 快，直接加载 |
| 体积 | 单文件较大（解压后一样） | 体积分散，无差别 |
| 调试难度 | 高，报错的路径是临时目录 | 低，文件都在手边 |
| 适用场景 | 交付给普通用户 | 内部工具、开发阶段调试 |

**核心机制差异**：`--onefile` 启动时会先把整个运行时解压到系统的临时目录（`%TEMP%/_MEIxxxxxx`），然后再跑。这步解压就是你感觉"怎么双击半天没反应"的根源。程序一退出，临时目录清理掉。**如果程序里反复启动子进程，这个解压会被反复执行，非常慢。**

**`--onedir` 没有解压这一步，exe 直接加载旁边已经躺好的 `python3x.dll` 和各个 `.pyd`，启动是秒开。**

**实战建议：开发期用 `--onedir` 快速验证打包是否成功；正式交付换 `--onefile`。** 记账本这种偶尔开一次的桌面应用，多等一两秒换来的"一个文件发过去"是值得的。但如果你做的是要常驻托盘、频繁启动的工具，`--onedir` 更合适。

## 图标：让你的 exe 有张脸

**Windows 用 `.ico`，macOS 用 `.icns`，Linux 用 `.png`：**

```
pyinstaller --onefile --icon=ledger.ico main.py
```

**macOS 应用图标：**

```
pyinstaller --onefile --windowed --icon=ledger.icns main.py
```

**常见坑**：图标文件必须是真正的 `.ico` 格式，不能直接把 `.png` 改名。ico 里最好塞进 16×16、32×32、48×48、256×256 多套尺寸，资源管理器和任务栏会按需要挑。

## 隐藏控制台：别让用户看到黑窗口

**tkinter 程序是 GUI 应用，默认打包出来双击会带一个黑色控制台窗口。**

**`--windowed`（Windows/macOS 也可用 `--noconsole`）：**

```
pyinstaller --onefile --windowed main.py
```

**这个标志做了什么**：告诉操作系统"这是个 GUI 子系统程序，不要分配控制台"。效果是：双击 exe，只有你的 tkinter 窗口出现，没有黑框。

**什么时候不该加 `--windowed`**：开发调试阶段。**加了 `--windowed` 之后，你在代码里 `print()` 的东西会全部消失**，一旦崩溃，你连报错信息都看不到。所以调试期务必先不打 `--windowed`，让控制台把 traceback 暴露出来，确认没问题再切换。

**`--console` 是默认行为**，显式写出来只是为了提醒自己。

## 常用参数速查

| 参数 | 作用 |
|---|---|
| `--onefile` | 单文件模式 |
| `--onedir` | 文件夹模式（默认） |
| `--windowed` | 无控制台窗口 |
| `--name NAME` | 指定产物名称 |
| `--icon=FILE.ico` | 设置图标 |
| `--add-data "SRC;DST"` | 附带资源文件（Windows 用 `;` 分隔，macOS/Linux 用 `:`） |
| `--exclude-module NAME` | 排除某个模块不打包 |
| `--clean` | 打包前清理缓存 |
| `--hidden-import NAME` | 强制包含某个 PyInstaller 没自动发现的模块 |

**`--add-data` 是打包 tkinter 程序最常用但最容易忘的参数**：你的程序里 `open("data/default.db")` 这种相对路径，打包后就找不到了。下一课讲怎么用 `sys._MEIPASS` 正确定位打包后的资源。

## 翻车现场一：开发机跑得好好的，用户机器上双击没反应

**症状**：你自己电脑上 `dist/main.exe` 双击完美运行。发给同事，双击后什么也不发生，进程管理器里一闪而过。

**原因**：目标机器缺少 Visual C++ 运行库，或者你的代码里有一个只在你机器上存在的隐式依赖（比如某个动态链接库）。还有一种常见情况：`main.py` 启动时报错被 `--windowed` 吞掉了，你看不到任何提示。

**排查步骤：**

```
# 1. 先不加 --windowed 重新打包，让控制台把错误吐出来
pyinstaller --onefile main.py

# 2. 在目标机器上打开 cmd，手动运行 exe，观察报错
dist\main.exe
```

**如果你看到 `Failed to execute script main` 配一段 traceback，那就是你代码的问题；如果连这个都没有、直接退出，多半是 VC++ 运行库缺失。**

**最坑的是这种：你的代码在 `import` 阶段就崩了，但 traceback 里出现的是 `_MEIxxxxx` 这种临时路径，让人摸不着头脑。**

## 翻车现场二：图标加不上，`--icon` 参数明明写了

**症状**：

```
pyinstaller --onefile --icon=ledger.png main.py
```

打包成功，但 exe 图标还是默认的羽毛图标。

**原因**：`ledger.png` 根本不是 `.ico` 文件，只是把 png 改了个扩展名。Windows 的 exe 图标必须读取 ICO 格式里内嵌的位图资源，png 改名骗不过去。

**报错信息往往也不明显，PyInstaller 可能直接忽略无效的图标文件，不报错但也不生效。**

**正确做法：**

```
# 用 pillow 把 png 转成真正的 ico
python -c "from PIL import Image; Image.open('ledger.png').save('ledger.ico')"

pyinstaller --onefile --icon=ledger.ico main.py
```

**转之前确认 png 是正方形（推荐 256×256 或 512×512）**，否则缩到 16×16 会变形。

**macOS 同理，icns 要用专门的工具生成（如 `iconutil`），不能直接改扩展名。**

## 翻车现场三：`--onefile` 启动要等三四秒，用户以为没点上

**症状**：双击 exe，等了 3 秒才弹出窗口，用户连点三次，弹出三个窗口。

**原因**：`--onefile` 的解压开销。你的程序带 matplotlib 时尤其明显，解压体积可能上百 MB，SSD 上也要一两秒，机械硬盘上能到 5 秒以上。

**解决办法按优先级：**

1. **换成 `--onedir`**：启动秒开，代价是分发时要打包成 zip 或做成安装包；
2. **加启动画面（splash screen）**：用 `--splash splash.png` 在解压期间显示一张图片，让用户知道程序在跑。这是 PyInstaller 5.3+ 的功能：

```
pyinstaller --onefile --splash splash.png main.py
```

3. **优化体积**（下一课重点）：解压的东西少了，自然就快了。

## 翻车现场四：`--windowed` 之后程序崩溃全无声

**症状**：加了 `--windowed` 打包，双击后窗口一闪就没了，没有任何错误提示。

**原因**：GUI 子系统程序没有控制台，`print` 和未捕获异常都无处可去。

**正确做法——用 `logging` 写文件：**

```
import logging
import sys
from pathlib import Path

log_path = Path(sys.executable).parent / "ledger_error.log"
logging.basicConfig(
    filename=str(log_path),
    level=logging.ERROR,
    format="%(asctime)s %(levelname)s %(message)s",
)

def main():
    # 你的主程序
    ...

if __name__ == "__main__":
    try:
        main()
    except Exception:
        logging.exception("未捕获的异常")
        raise
```

**发布版本务必加上全局异常兜底**，否则用户只能告诉你"打不开"，你什么都诊断不出来。

## 小结

- PyInstaller 是 tkinter 项目打包的首选工具
- `--onefile` 单文件方便分发但启动慢（要解压），`--onedir` 反之
- `--windowed` 去掉黑控制台，但调试期别加，否则看不到报错
- `--icon` 要用真正的 ico/icns，不能改扩展名
- 开发机能跑 ≠ 用户机能跑，务必在干净机器上测试
- 发布版要写日志文件，别让崩溃无声无息
