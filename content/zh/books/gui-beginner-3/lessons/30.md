# 发布与收官：把记账本交付出去，然后走向 Qt

> 代码写完了、打包成功了、体积压到 30MB 了。现在你要面对的是"交付"这件事本身——一个没有 README、没有版本号、没有许可证的 exe，和一个没有文档的文件夹，在用户眼里没有任何区别。这一课讲发布清单，然后回头看看这一路你到底走完了什么，以及下一步该往哪走。

## 发布清单：一个能交付的项目长什么样

**以下是记账本发布前的检查表：**

| 项目 | 说明 |
|---|---|
| README.md | 项目说明、安装方式、运行方式、截图 |
| LICENSE | 许可证文件（MIT/Apache 2.0/GPL 等） |
| 版本号 | 明确的 `v1.0.0`，写在 README 和关于页 |
| 发布产物 | dist 目录打包成 zip，命名含版本号 |
| 依赖清单 | `requirements.txt` 或 `pyproject.toml` |
| 截图 | 至少 2-3 张主界面截图 |
| 已知问题 | 记录已发现但未修复的缺陷 |
| 更新日志 | CHANGELOG.md，记录版本变更 |
| 构建说明 | 怎么从源码打包（`pyinstaller --onefile ...`） |
| 图标与资源 | ico/png 原文件保留在仓库 |

**README 的最小骨架：**

**版本号用语义化版本（SemVer）**：`主版本.次版本.修订号`。改了不兼容的数据库结构 → 主版本+1；加了新功能 → 次版本+1；修了 bug → 修订号+1。第 1 章定的"v1.0.0"就是这个。

**许可证别漏。** 哪怕是自娱自乐的项目，放上 `LICENSE` 文件（MIT 是最宽松的）也是好习惯。没有许可证的代码在法律上是"保留所有权利"，别人不敢用。

## 六章回顾：你到底走完了什么

**第 1 章 想清楚再做**：需求清单、数据模型（四张表、字段、主键）、三层架构（数据层/逻辑层/界面层）、原型草图、为什么选 SQLite。**结论**：动手前想清楚，是这一整本书最重要的一课。

**第 2 章 数据层**：`sqlite3` 连接与游标、`CREATE TABLE`、CRUD 四条语句、**参数化查询防 SQL 注入**、`commit/rollback`、`with` 上下文管理。你写出了 `db.py`，一个能被任何界面调用的干净数据层。

**第 3 章 界面骨架**：三层布局（顶部筛选、中部表格、底部表单）、`Treeview` 列定义与插入、`Combobox` 表单、输入校验、空状态提示。你搭出了"能看不能动"的界面。

**第 4 章 打通**：`refresh_list` 加载数据、添加/删除/修改走逻辑层、用 observer 模式解耦界面与数据、理解全量刷新 vs 增量更新的取舍。你的界面活了。

**第 5 章 统计图表**：SQL `GROUP BY` 汇总、用 `FigureCanvasTkAgg` 嵌入 matplotlib 画布（不能用 `plt.show()`）、饼图与柱状图、中文字体设置、`fig.clear()` 防内存泄漏。你的记账本有了"洞察"。

**第 6 章 打包交付**：全局异常处理与配置、PyInstaller `--onefile`/`--onedir`/`--windowed`/`--icon`、体积优化到 30MB 左右、发布清单。**结论**：一个完整桌面项目从 0 到 1 走完了。

**回头看第 1 章那张原型草图——现在它已经是一个能双击运行的程序了。**

## 下一步：为什么 tkinter 之后要学 Qt

**tkinter 教会了你 GUI 编程的核心概念：事件循环、布局、控件、数据绑定、MVC 分层。** 这些是通用的，换任何 GUI 框架都不用重学。但 tkinter 的局限也很明显：

| 维度 | tkinter | Qt（PySide6 / PyQt6） |
|---|---|---|
| 颜值 | 原生系统控件，难定制 | 支持 QSS 样式表，能做出现代化界面 |
| 控件丰富度 | 基础控件够用，复杂控件缺 | 表格、树、图形视图、OpenGL、多媒体、网络全有 |
| 布局系统 | pack/grid/place，够简单但死板 | 布局嵌套灵活，支持动画与响应式 |
| 高 DPI 支持 | 差，4K 屏模糊 | 原生支持，自动缩放 |
| 自定义绘制 | Canvas 能用但费劲 | QPainter 专业级 2D 绘图 |
| 商业使用 | 免费 | PySide6 是 LGPL，可商用；PyQt6 是 GPL/商业授权 |
| 学习曲线 | 平缓 | 陡峭，概念多（信号槽、元对象系统） |
| 打包体积 | 小（~10MB） | 大（~30-60MB 起步） |
| 生态与就业 | 小众 | 工业软件、汽车、医疗领域大量使用 |

**最关键的区别是信号槽（signal/slot）机制。** tkinter 用 `command=` 回调，函数多了就变成一团乱麻；Qt 的 `signal` 可以带任意参数、可以连接多个槽、可以跨线程安全触发，天生适合大型项目。你第 4 章写的 observer 模式，在 Qt 里是内置的。

**选择建议：**

- **想做"能用的小工具"** → tkinter 完全够，你现在就会；
- **想做"好看、能商用、能进简历"的桌面软件** → 学 Qt；
- **想做跨平台移动端/Web** → 考虑别的路（Kivy、Electron、Flutter）。

**Qt 学习路径建议：**

1. **先学 PySide6**（LGPL，商用友好；PyQt6 要买商业授权或用 GPL 开源）；
2. 从"把记账本用 Qt 重写一遍"开始——复用你第 2 章的数据层，只换界面层，这是最高效的练习；
3. 重点掌握：QMainWindow 与 QWidgets、QVBoxLayout/QHBoxLayout/QGridLayout、QTableView + QAbstractTableModel（比 tkinter 的 Treeview 强一个量级）、信号槽、QSS 美化；
4. 进阶：QThreadPool 多线程、QNetworkAccessManager 网络请求、QML 做炫酷界面。

**你现在已经具备了学 Qt 的全部前置知识**：知道怎么分层、怎么把数据和界面解耦、怎么打包。剩下的只是学一套新 API。

## 翻车现场一：发布 exe 没带依赖的 data 文件，用户打开就崩

**症状**：你的程序里写了 `with open("data/default_categories.json")` 读取默认分类。自己电脑上正常，用户那边一打开就崩：

```
FileNotFoundError: [Errno 2] No such file or directory: 'data/default_categories.json'
```

**原因**：源码运行时，相对路径是相对于 `main.py` 的；**打包后程序运行在临时解压目录 `_MEIxxxxxx` 里**，`data/default_categories.json` 根本没被打包进去。

**正确做法：用 `sys._MEIPASS` 定位资源：**

```
import sys
from pathlib import Path

def resource_path(rel):
    base = getattr(sys, "_MEIPASS", Path(__file__).parent)
    return Path(base) / rel

# 使用
categories = json.load(open(resource_path("data/default_categories.json"), encoding="utf-8"))
```

**打包时显式附带：**

```
pyinstaller --onefile --add-data "data;data" main.py    # Windows 用 ;
# pyinstaller --onefile --add-data "data:data" main.py  # macOS/Linux 用 :
```

**错误写法：**

```
json.load(open("data/default_categories.json"))  # 打包后必崩
```

## 翻车现场二：README 写"双击 exe"但没说清首次运行会建库

**症状**：用户第一次打开程序，弹了个"正在初始化数据库"的提示，用户以为卡住了，关掉重开，结果提示数据库已存在、又报错。

**原因**：第 2 章你写的 `init_db()` 会在首次运行时建表。这个行为对用户应该是透明的，但缺乏引导就会引发恐慌。

**正确做法：首次启动给明确反馈。**

```
def ensure_database():
    if not DB_PATH.exists():
        init_db()
        show_info("欢迎使用记账本", "已为您创建账本数据库，开始记录吧！")
    else:
        # 正常启动，什么都不说
        pass
```

**README 里也写明："首次运行会在您的文档目录创建 ledger.db，这是正常现象。"**

## 翻车现场三：版本号只写在 README 里，关于页不显示

**症状**：用户报了个 bug，你问"你用的哪个版本"，用户答不上来——关于页上没写版本。

**原因**：版本号只在 README 里维护，代码里是硬编码的 `"1.0"`。用户看不到代码。

**正确做法：单一来源（Single Source of Truth）。** 建一个 `_version.py`：

```
VERSION = "1.0.0"
```

**README、关于页、PyInstaller 打包都引用它：**

```
# about.py
from _version import VERSION
ttk.Label(root, text=f"记账本 v{VERSION}").pack()
```

**打包命令也可以参数化：`--name "Ledger-{VERSION}"`。**

## 翻车现场四：把 .db 文件也打进了安装包

**症状**：用户安装后打开，发现里面已经有一个预置的账本数据库，里面还有别人的测试数据。

**原因**：你在打包前运行过程序，`ledger.db` 被生成在源码目录里，PyInstaller 顺手把它打进了 exe（因为 `--add-data` 配了整个目录）。

**正确做法：打包前清理开发期产生的数据文件，并把数据库文件加入 `.gitignore`：**

```
# .gitignore
*.db
__pycache__/
build/
dist/
*.spec
config.ini
```

**并在 README 里说明：程序首次运行会自动建库。**
