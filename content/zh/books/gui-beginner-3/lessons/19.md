# 用 observer 解耦：数据变了怎么通知界面刷新

> 前三课我们每次写操作后都手动调 `refresh_table`。漏一次就出 bug，写三遍就冗余。这一课用观察者模式把"刷新"自动化——数据一变，界面自动更新，再也不用记住调刷新。

## 问题：刷新散落在各处

**回顾我们的代码，刷新出现在三个地方：**

```python
def on_add():
    db.add_record(...)
    refresh_table(...)        # 这里一次

def on_delete():
    db.delete_record(...)
    refresh_table(...)        # 这里一次

def on_edit():
    db.update_record(...)
    refresh_table(...)        # 这里一次
```

**代价**：加一个操作（比如"批量导入"）就要记着加一行刷新；改刷新逻辑（比如加动画）要改三处。漏一处就是 bug。

## 观察者模式的核心思想

**观察者模式的口号是："别问，去订阅。"**

- 界面层**订阅**一个事件（比如 `"records_changed"`）；
- 数据层在**任何写入发生时发出这个事件**；
- 订阅者收到事件就自动刷新。

**界面层从此不再需要知道"什么时候该刷新"，只管"收到通知就刷新"。**

## 最简实现：一个回调列表

**Python 里观察者可以简单到几行代码：**

```python
# observer.py
_listeners = []

def subscribe(fn):
    _listeners.append(fn)

def notify(*args, **kwargs):
    for fn in _listeners:
        fn(*args, **kwargs)
```

**就这么短。** 数据层写完就 `notify()`，界面层启动时 `subscribe(refresh_table)`。

## 数据层发出通知

**改 `db.py`，在每个写操作末尾加 notify：**

```python
import observer

def add_record(conn, amount, category, date, note="", rtype="支出"):
    cur = conn.cursor()
    cur.execute("""INSERT INTO records(amount,category,date,note,type,created_at)
                   VALUES (?,?,?,?,?,?)""",
                (amount, category, date, note, rtype, datetime.now().isoformat(timespec="seconds")))
    conn.commit()
    observer.notify("add", cur.lastrowid)      # 通知！
    return cur.lastrowid

def delete_record(conn, rid):
    cur = conn.cursor()
    cur.execute("DELETE FROM records WHERE id=?", (rid,))
    conn.commit()
    observer.notify("delete", rid)

def update_record(conn, rid, ...):
    ...
    conn.commit()
    observer.notify("update", rid)
```

**注意 notify 传了动作名和 id**，订阅者可以据此决定"是全量刷新还是增量更新"（第 20 课用得上）。

## 界面层订阅

**在 `ui.build` 末尾订阅一次：**

```python
import observer

def build(root):
    app = {}
    # ... 搭建界面 ...
    app["tree"] = ttk.Treeview(...)

    def _on_data_changed(action, rid):
        refresh_table(app["tree"], app["empty_label"], db.get_conn())
        app["status_var"].set(f"数据已更新（{action}）")
        root.after(3000, lambda: app["status_var"].set("就绪"))

    observer.subscribe(_on_data_changed)
    return app
```

**回调闭包捕获了 `app`、`tree`、`status_var`、`root`**，所以它知道该刷新哪个表格、该更新哪个状态栏。

## 现在 on_add 变干净了

**回调不再需要记得刷新：**

```python
def on_add():
    # ... 取值、校验 ...
    db.add_record(conn, float(amt), cat, date, note, rtype)
    # 不用写 refresh_table，observer 会自动调
```

**数据层和界面层彻底解耦了**：数据层完全不知道有窗口存在，界面层只管"接到通知就刷新"。以后加图表页、导出功能，只要它们也订阅同一个事件，数据一变就自动同步。

## 翻车现场一：订阅了两次，刷新两次

**症状**：每次添加，表格先闪一下旧数据、再闪一下新数据，或者状态栏提示跳两次。

**原因**：`observer.subscribe` 被调了两次（比如 build 调了一次，某处又调了一次）。同一个回调进了列表两遍，`notify` 就跑两遍。

**解决**：要么保证 subscribe 只调一次，要么做去重：

```python
def subscribe(fn):
    if fn not in _listeners:
        _listeners.append(fn)
```

**或者在测试时打印 `_listeners` 的长度，确认是 1 不是 2。**

## 翻车现场二：在通知回调里又触发通知，死循环

```python
def _on_data_changed(action, rid):
    # 不小心在刷新里又做了写操作
    db.update_record(conn, rid, ...)    # 这又 notify → 再调自己 → 无限递归
    refresh_table(...)
```

**症状**：`RecursionError: maximum recursion depth exceeded`，程序瞬间卡死。

**原因**：通知回调里触发了新的通知，新通知又调回调，无限递归。

**解决**：刷新操作（refresh_table）是只读的，绝不在回调里做任何写操作。若确实需要联动写，加一个"是否正在通知"的锁标志位防重入。

## 翻车现场三：忘记订阅，界面又不动了

**症状**：写入后数据库有数据，但界面不刷新。你排查一圈发现……忘了 subscribe。

**原因**：重构时把 subscribe 那行删了或挪错了地方。

**解决**：把 subscribe 放在 build 的最后、返回之前，作为一个明确的"启动钩子"固定下来。团队项目里这行很容易在 code review 时被注意到。

## 小结

- 观察者模式 = 订阅事件 + 数据层 notify + 界面层自动刷新
- 核心是"别问，去订阅"，界面不再需要知道何时刷新
- Python 里用回调列表就能实现，几行代码
- 数据层写完就 notify，传动作名+id 供后续增量更新
- 防重复订阅：subscribe 时去重
- 防递归：回调里绝不触发新的写操作

```quiz
type: local
exam: true
q: 扩展 observer 支持"按事件名订阅"：改成支持 observer.subscribe("records_changed", fn) 和 observer.notify("records_changed", action, rid)，只有订阅了该事件名的回调才被触发。演示：订阅 "records_changed" 和 "theme_changed" 两个事件，分别 notify，验证只有对应订阅者被调用。注意：网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  # observer.py
  _channels = {}   # {"records_changed": [fn1, fn2], "theme_changed": [fn3]}

  def subscribe(event, fn):
      _channels.setdefault(event, [])
      if fn not in _channels[event]:
          _channels[event].append(fn)

  def notify(event, *args, **kwargs):
      for fn in _channels.get(event, []):
          fn(*args, **kwargs)

  # 演示
  def on_record(action, rid):
      print("记录变了:", action, rid)
  def on_theme(name):
      print("主题变了:", name)

  subscribe("records_changed", on_record)
  subscribe("theme_changed", on_theme)
  notify("records_changed", "add", 1)
  notify("theme_changed", "dark")

- 只触发了对应的订阅者
- 演示打印结果正确
```
