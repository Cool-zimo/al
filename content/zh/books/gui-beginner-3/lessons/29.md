# 瘦身：把一个 60MB 的 exe 压到 30MB

> 一个只显示"Hello World"的 tkinter 程序，PyInstaller 打出来有 10MB 左右。加上 matplotlib 画两张图，直接飙到 60MB 以上。这一课讲清楚体积都去哪了，以及怎么用 `--exclude-module` 和精细排查把它砍下来。

## 一个 tkinter hello world 凭什么有 10MB

**先给个实测数量级，让你心里有数：**

| 程序内容 | 打包体积（--onefile，Windows 10，Python 3.11） |
|---|---|
| `print("hi")` 纯控制台 | ~6 MB |
| tkinter 显示一个 Label | ~10 MB |
| 上面再加 matplotlib 画一张图 | ~60 MB |
| 用 `--exclude-module` 精简后 | ~30 MB |

**10MB 去哪了？** PyInstaller 打包的不是"你写的代码"，而是整个 Python 运行时 + 你 import 链路上所有能追到的东西：

- `python311.dll`：约 4 MB，解释器本体，去不掉；
- `tkinter` 本身：约 2 MB（含 Tcl/Tk 运行时 `tcl86t.dll`、`tk86t.dll`）；
- **标准库里被"连带"打进来的大块头**：`encodings`（各种字符编码表，几 MB）、`ssl`、`sqlite3`、`_ssl`、`hashlib` 及其底层依赖——tkinter 间接依赖它们，PyInstaller 不敢漏；
- `numpy`、`matplotlib` 进来后：`numpy` 一个就有 30+ MB，`matplotlib` 的字体库、后端、样例数据又占十几 MB。

**关键认知：体积大头不是你的代码，是依赖。** 你那几百行业务代码压缩后不到 100KB，可以忽略不计。

## 怎么看打进去了什么：`--exclude-module` 与对照实验

**`--exclude-module` 是最直接的体积手术刀：**

```
pyinstaller --onefile --exclude-module matplotlib main.py
```

**它告诉 PyInstaller："不要收集这个模块及其子模块"。** 前提是你的代码确实用不到它——如果用了，运行时会报 `ModuleNotFoundError`。

**正确排查思路，一次只动一个变量：**

```
# 基准：全量打包
pyinstaller --onefile --clean main.py
# 记下 dist/main.exe 大小

# 逐步排除大块头，每次重新打包、重新记录
pyinstaller --onefile --clean --exclude-module matplotlib main.py
pyinstaller --onefile --clean --exclude-module numpy main.py
pyinstaller --onefile --clean --exclude-module PIL main.py
```

**把每次体积记下来，你就得到了这张表：**

| 排除项 | 体积变化 | 结论 |
|---|---|---|
| 无（全量） | 62 MB | 基准 |
| 排除 matplotlib | 30 MB | matplotlib 占 32 MB |
| 再排除 numpy | 22 MB | numpy 占 8 MB |
| 再排除 PIL | 18 MB | PIL 占 4 MB |

**这一步的价值在于：它告诉你哪些是真的"必要成本"，哪些是"随手 import 的奢侈消费"。**

## 为什么 matplotlib 这么胖：它的字体库

**matplotlib 体积爆炸的头号原因是字体。** 它把整套 DejaVu 字体、各种数学符号字体、中文字体打包进来，光 `matplotlib/mpl-data/fonts/ttf/` 就有 10MB 以上。

**如果你只在程序里用到了其中一两种字体，其余的全是浪费。**

**进一步精修：直接在 spec 文件里删字体目录里的多余文件。** 但这属于进阶操作，新手先用 `--exclude-module` 控制到 30MB 左右，性价比最高。

**实测结论：记账本项目原本 62MB，排除 matplotlib 后落到 30MB 左右，体积直接砍半。** 如果你的统计页是可选的、且用户群体能接受"不装也能用基础功能"，甚至可以把 matplotlib 做成可选依赖。

## 排查冗余：看清打包分析过程

**PyInstaller 生成的 `build/main/warn-main.txt` 和 `build/main/xref-main.html` 是你的诊断工具：**

- `warn-main.txt`：列出所有"找不到"或"没收集到"的模块警告；
- `xref-main.html`：完整的模块引用关系图，可以看到某个模块是被谁 import 带进来的。

**操作步骤：**

```
pyinstaller --onefile --clean main.py
# 打开 build/main/xref-main.html，搜索大模块名，沿引用链往上追
```

**你可能会发现：某个模块是你代码里 `import` 了、但实际只有一条分支用到、而这条分支用户几乎走不到。** 这时候要么重构代码做惰性导入，要么接受这个成本。

**惰性导入示例（用到了才 import）：**

```
def draw_chart(self):
    import matplotlib
    matplotlib.use("Agg")
    from matplotlib.backends.backend_tkagg import FigureCanvasTkAgg
    # ... 画图
```

**这样做的好处：如果 `draw_chart` 从未被调用，PyInstaller 分析时这个 import 就不在静态 import 图上，模块不会被收进去。** 但注意：`--onefile` 下惰性导入仍可能被收集（因为 PyInstaller 会扫描字节码），真正的"按需"要靠 `--exclude-module` 配合运行时动态加载。

## 翻车现场一：排除模块后运行报 ModuleNotFoundError

**症状**：加了 `--exclude-module matplotlib` 打包成功，双击运行，程序崩了：

```
Traceback (most recent call last):
  File "main.py", line 5, in <module>
    import matplotlib.pyplot as plt
ModuleNotFoundError: No module named 'matplotlib'
```

**原因**：你代码里确实 import 了它，排除是排除不掉的——排除只是告诉 PyInstaller 别收集，运行时要用的模块没了，自然报错。

**解决办法（二选一）：**

1. **别排除，接受体积成本**——最稳；
2. **做条件导入 + 优雅降级**：

```
try:
    import matplotlib
    HAS_MPL = True
except ImportError:
    HAS_MPL = False

# 界面上：
if not HAS_MPL:
    chart_tab_label.config(text="统计（当前环境未安装图表库）")
```

**错误写法（不该这么写）：**

```
pyinstaller --onefile --exclude-module matplotlib main.py
# 但 main.py 顶部就是 import matplotlib.pyplot as plt
```

**这种自相矛盾，PyInstaller 不会提醒你，它只在运行时给你一记闷棍。**

## 翻车现场二：看大小看错了文件，以为优化没生效

**症状**：你兴冲冲加了 `--exclude-module matplotlib`，打包完去 `dist/` 一看，文件还是 62MB，以为没生效。

**原因**：你看的是 `--onefile` 的产物。**单文件 exe 内部是压缩过的自解压包**，压缩比很高，但显示的文件大小仍然是解压后的体积。真正该比的是**解压后的目录体积**，或者换 `--onedir` 看 `dist/main/` 整个文件夹的大小。

**错误判断：**

```
# 只看这一个文件的大小，容易误判
ls -lh dist/main.exe
# -rwxr-xr-x  1 user  staff  62M  dist/main.exe   <- 还那么大
```

**正确做法：用 `--onedir` 对比文件夹总大小，或者看 `dist/main.exe` 在相同排除参数下的相对变化。** 更靠谱的是写个脚本自动记录：

```
#!/usr/bin/env python3
# measure.py
import os, subprocess, re

excludes = ["", "matplotlib", "matplotlib,numpy", "matplotlib,numpy,PIL"]
for ex in excludes:
    name = "ledger_" + (ex.replace(",", "_") or "full")
    cmd = f"pyinstaller --onefile --clean --name {name}"
    if ex:
        for m in ex.split(","):
            cmd += f" --exclude-module {m}"
    cmd += " main.py"
    subprocess.run(cmd, shell=True)
    # 统计解压后体积
    dist_path = f"dist/{name}"
    total = sum(
        os.path.getsize(os.path.join(dirpath, f))
        for dirpath, _, files in os.walk(dist_path)
        for f in files
    )
    print(f"{name:30s} {total/1024/1024:6.1f} MB")
```

**输出类似：**

```
ledger_full                    62.3 MB
ledger_matplotlib              30.1 MB
ledger_matplotlib_numpy        22.4 MB
ledger_matplotlib_numpy_PIL    18.2 MB
```

**这才是科学的对比方式。**

## 翻车现场三：`--upx-dir` 压不动，甚至 UPX 把 exe 压坏了

**症状**：听人说 UPX 能进一步压缩，加了 `--upx-dir`，体积确实小了，但 exe 双击报"不是有效的 Win32 应用程序"。

**原因**：UPX 对某些版本的 Python DLL 压缩后会破坏其数字签名或重定位信息，杀毒软件也可能误报。

**PyInstaller 从 4.x 开始默认**不再自动用 UPX，原因就是这个不稳定性。**新手不要为了那 10%~20% 的体积去赌兼容性。**

## 翻车现场四：以为优化就是"排除越多越好"

**症状**：你一口气排除了十几个模块，体积降到 8MB，美滋滋。发给用户，用户报告"录入页空白""统计页打不开"。

**原因**：排除是全局的，没有"只排除这一个函数用到的那部分"这种细粒度。**你排除的可能是某个被 tkinter 或你的代码在异常分支、插件机制里用到的模块。**

**正确心态：排除只针对你明确知道"整个程序完全用不到"的模块。** 有疑问就留着。30MB 对一个桌面应用来说完全可接受，8MB 的代价是随时可能崩。

## 小结

- tkinter hello world 约 10MB，加 matplotlib 飙到 60MB+，体积大头是依赖不是你的代码
- 用 `--exclude-module` 做对照实验，找出真正的体积大户
- matplotlib 胖在字体库；记账本排除后可压到 30MB 左右
- `build/main/warn-main.txt` 和 `xref-main.html` 用来追冗余来源
- 排除前确认代码确实用不到，否则运行时 ModuleNotFoundError
- 别用 UPX，别贪心排除太多，稳定性优先于体积
