# 数据模型怎么定：一条记录有哪些字段

> 上一课定下了"要做成什么样"，这一课定"数据长什么样"。数据模型是整个项目的地基——它一旦定下来，数据库表结构、界面字段、统计维度都跟着它走。

## 一条记账记录里有什么

**对着需求 F1（记一笔）想：要记下一笔账，最少需要哪些信息？**

| 字段 | 说明 | 例子 |
|---|---|---|
| 金额 | 这笔钱是多少 | 38.5 |
| 分类 | 花在/赚在哪儿 | 餐饮、工资 |
| 日期 | 什么时候发生的 | 2026-09-27 |
| 备注 | 补充说明 | 和同事午餐 |
| 类型 | 收入还是支出 | 支出 |

**再加两个"系统字段"，不是用户填的，但必须有：**

| 字段 | 说明 |
|---|---|
| id | 每条记录的唯一编号（主键） |
| 创建时间 | 这条记录是何时录入系统的 |

## 为什么必须有主键 id

**"日期+金额+备注"能不能当主键？** 不行。因为你可能在同一天花同样一笔钱吃同样的饭，录入两次——这两行除了 id 之外所有字段都一样，没有 id 就没法区分它们，也就没法单独删掉其中一条。

**主键的作用是唯一标识一行。** SQLite 里常用 `INTEGER PRIMARY KEY AUTOINCREMENT`：你插入时不用管它，数据库自动给一个递增的整数。

## 日期怎么存

**这是新手最容易踩的坑。** 日期有三种存法，先看结论：

| 存法 | 例子 | 评价 |
|---|---|---|
| 存字符串 "2026-09-27" | 人能直接读 | ✅ 推荐，方便排序和按年月分组 |
| 存时间戳 1780000000 | 一个整数 | 排序快，但人看不懂，要转换 |
| 存成三列 年/月/日 | 分开三个字段 | 麻烦，不推荐 |

**我们用字符串 `YYYY-MM-DD` 格式存。** 它既能直接被 SQLite 排序（`"2026-10-01" > "2026-09-27"` 成立），又能方便地按前 7 位做"按月汇总"（取子串 `"2026-09"`）。

**翻车现场**：如果你存成 `"9月27日"` 或 `"27/09/2026"`，字符串排序会乱套——`"10/01"` 会排在 `"09/27"` 前面，因为 `'1' < '0'`。**一律用 `YYYY-MM-DD` 这种"大单位在前"的格式。**

## 金额怎么存

**金额必须存成数字（整数或浮点），绝不能存成字符串。** 原因有两个：

1. 统计时要做加法，`SUM()` 只对数字列生效；
2. 字符串 `"38.5"` 和 `"100"` 相加会报错或得到无意义结果。

**用 `REAL`（浮点）存金额的常见顾虑是精度。** 钱确实要求精确，但个人记账本分位到角就够了，浮点的精度误差（约 1e-15）在这种量级下可以接受。如果你要做"一分钱都不能差"的财务软件，就该用整数分（`3850` 表示 38.50 元）或 `DECIMAL` 类型——但 SQLite 没有 DECIMAL，整数分是最稳妥的替代方案。

**本项目用 `REAL` 存元，分位到角。** 录入时校验输入是合法数字即可。

## 分类要不要单独建表

**分类（餐饮、交通、工资…）是固定的几个选项。** 你可以把分类名直接写进每条记录里，也可以单独建一张 `categories` 表，用分类 id 关联。

**本项目用最简单的做法：分类作为记录表里的一个文本字段 `category TEXT`。** 理由：分类很少、也不会频繁增删，没必要为了规范化多建一张表。等分类要支持"每个分类配一个图标、一种颜色"时，才需要单独建表。

## 翻车现场：金额存成字符串

```sql
-- 错误：amount 是 TEXT
CREATE TABLE records (amount TEXT, category TEXT, ...);

-- 统计时
SELECT SUM(amount) FROM records;
-- 结果可能是 0 或者报错，因为 SQLite 会做隐式转换，
-- 碰到 "12.5元" 这种带单位的字符串就转成 0
```

**症状**：`SUM(amount)` 返回的结果莫名其妙，比预期小很多，或者干脆是 0。

**原因**：`"12.5元"` 这种字符串 SQLite 无法完整转换成数字，转一半就丢了。

**解决**：金额列用 `REAL`，录入时只接受纯数字，单位（元）只在界面显示时加。

## 翻车现场：用自造编号当主键

```sql
-- 错误：用"日期+序号"当主键
INSERT INTO records VALUES ('20260927-001', 38.5, '餐饮');
-- 同一天录第二笔怎么办？-002？那删除中间的会留洞
```

**症状**：插入时报 `UNIQUE constraint failed`，或者编号出现空洞。

**原因**：自己管理编号就要自己处理并发和重复，容易出错。

**解决**：交给数据库，`id INTEGER PRIMARY KEY AUTOINCREMENT`，插入时把 id 留空。

## 小结

- 一条记录 = 金额(REAL) + 分类(TEXT) + 日期(TEXT) + 备注(TEXT) + 类型(TEXT) + 主键 id
- 主键用 `AUTOINCREMENT` 自增整数，别自己造编号
- 日期一律 `YYYY-MM-DD` 字符串，方便排序和按月分组
- 金额存成 `REAL` 数字，绝不用字符串
- 分类直接存在记录表里，先不建单独表
