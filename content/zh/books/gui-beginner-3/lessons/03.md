# 模块怎么切：三层架构

> 需求有了，数据模型有了，现在要写代码。第一件事不是建窗口，而是先把代码分成三层：数据层、界面层、逻辑层。这一课讲为什么要分开、怎么分。

## 为什么要把代码切开

**新手最容易写出"一锅粥"式的代码**：数据库操作写在按钮的回调函数里，SQL 语句和 `tree.insert(...)` 挤在同一个函数里，改一个字段要翻遍整个文件。

**这种写法的代价在项目变大时集中爆发：**

- 想换个数据库（比如从 SQLite 换成文件），界面代码得全改；
- 想加单元测试，但测试代码必须启动窗口；
- 想复用"算分类总额"的逻辑给图表和导出用，只能复制粘贴。

**把代码按"职责"分层，就是为了把变动关在局部。** 数据库换掉只改数据层，界面重做只改界面层，业务逻辑不动。

## 三层各自负责什么

| 层 | 职责 | 能 import 谁 | 不能做什么 |
|---|---|---|---|
| 数据层 `db.py` | 连接数据库、建表、增删改查 | 只 import sqlite3 | 不知道有窗口、有按钮 |
| 界面层 `ui.py` | 画窗口、表格、表单，处理点击 | 数据层、逻辑层 | 不写 SQL |
| 逻辑层 `logic.py` | 校验输入、算统计、转换格式 | 数据层 | 不创建控件 |

**关键规则：依赖单向。** 数据层在最底下，谁都不依赖；界面层依赖数据层；逻辑层也依赖数据层。反向的依赖不允许——数据层绝不能 `import ui`。

## 目录结构

```
ledger/
├── main.py        # 入口：只做一件事——创建 App 并启动主循环
├── db.py          # 数据层
├── logic.py       # 逻辑层
├── ui.py          # 界面层
└── ledger.db      # 运行时生成的数据库文件（不用手写，程序自动建）
```

**每个文件只负责一件事。** `main.py` 里不要出现 SQL，也不要出现一大堆 `Label`；它只负责把各层串起来。

## 用例子感受分层

**假设用户点"添加"，录入一笔 38.5 元的餐饮支出。三层的分工是：**

1. 界面层 `ui.py`：从 Entry 里读出字符串 `"38.5"` 和 `"餐饮"`，交给逻辑层；
2. 逻辑层 `logic.py`：校验 `"38.5"` 能转成数字、分类非空，然后调数据层存；
3. 数据层 `db.py`：执行 `INSERT INTO records ...`。

**反向流程（刷新列表）：**

1. 界面层调用逻辑层"取所有记录"；
2. 逻辑层调数据层查询；
3. 数据层返回 Python 列表，界面层塞进 Treeview。

**每层只跟相邻层说话，不越级。** 界面层不会直接拼 SQL，数据层也不会直接读 Entry 的值。

## 翻车现场一：在按钮回调里写 SQL

```python
def on_add():
    conn = sqlite3.connect("ledger.db")
    c = conn.cursor()
    c.execute("INSERT INTO records(amount,category) VALUES(?,?)",
              (amt_entry.get(), cat_entry.get()))
    conn.commit()
    conn.close()
    # 还要手动刷新表格……
    for row in tree.get_children():
        tree.delete(row)
    for r in load_all():
        tree.insert("", "end", values=r)
```

**症状**：同样的"刷新表格"代码在添加、删除、修改三个地方各写了一遍，改一处忘改另外两处，bug 反复出现。

**原因**：把数据操作和界面刷新混在一起，职责不清。

**解决**：把"加载并刷新表格"抽成 `ui.py` 里的一个独立函数 `refresh_table()`，添加、删除、修改都只调它。更进一步，用观察者模式（第 19 课讲）让数据层一变更就自动通知界面。

## 翻车现场二：数据层 import 了界面层

```python
# db.py
from ui import tree   # 错误！数据层依赖了界面层

def add_record(r):
    # ...insert...
    for row in tree.get_children():   # 数据层里操作控件
        tree.delete(row)
```

**症状**：循环依赖报错 `ImportError: cannot import name 'tree'`，或者改界面主题时把数据库代码一起拖下水。

**原因**：违反了"依赖单向"。数据层是最底层，不该知道上面有窗口。

**解决**：数据层只返回数据（列表、字典），刷新控件的事交给界面层自己。

## 逻辑层到底放什么

**逻辑层是"不画界面、不碰数据库语句、但懂业务规则"的那一层。** 典型内容：

- 校验：金额是不是合法数字、日期是不是 `YYYY-MM-DD`、分类是不是空；
- 转换：数据库查出来的 `(id, amount, category, date)` 元组，转成界面好用的字典；
- 统计：按分类汇总、按月求和、算结余。

**把这些放逻辑层，而不是界面层的回调函数里，是为了复用和测试。** 统计函数可以被图表、导出、界面三处调用；写测试时不用启动窗口，直接喂数据测函数。

## 小结

- 三层：数据层(db.py)、界面层(ui.py)、逻辑层(logic.py)，入口 main.py
- 依赖单向：界面/逻辑 → 数据，绝不允许反向
- 数据层只管 SQL 和连接，界面层只管控件，逻辑层管校验和统计
- 分层的收益：换数据库只改一层、逻辑能复用、能写测试
- 界面层的回调要短，立刻交给逻辑层，自己不写 SQL
