# 刷新策略：全量刷新 vs 增量更新

> 上一课我们做到了"数据一变就自动刷新"。这一课回答一个性能问题：刷新时是清空整张表重画，还是只改那一行？两种策略各有适用场景，搞混了要么卡、要么显示错。

## 两种策略

**全量刷新（我们一直在用）：**

```python
def refresh_table(tree, empty_label, conn):
    rows = db.get_all(conn)
    if not rows:
        tree.pack_forget(); empty_label.pack(); return
    empty_label.pack_forget(); tree.pack(fill="both", expand=True)
    for iid in tree.get_children():
        tree.delete(iid)
    for r in rows:
        tree.insert("", "end", iid=str(r["id"]), values=(...))
```

**特点**：简单、一定对。代价是每次都删全部、插全部。

**增量更新（只改变化的那一行）：**

```python
def update_row(tree, rid, r):
    # 先删旧行，再插新行
    tree.delete(str(rid))
    tree.insert("", "end", iid=str(rid), values=(...))
```

**特点**：精准、快。代价是逻辑复杂，要考虑插入位置、排序顺序。

## 什么时候该用全量

**全量刷新适合这些情况：**

- **数据量小**（几千条以内）：删插几千行在 tkinter 里是毫秒级，用户无感；
- **顺序可能变**：改了日期或金额，排序位置会变，只改值不动位置会显示错乱；
- **有筛选/排序**：改完之后这一行可能要跑到别的页或别的位置；
- **刚启动 / 刚切换页面**：本来就要重建整个视图。

**我们的记账本属于前两条**：数据量小、用户常按日期排序。所以**默认用全量，没问题。**

## 什么时候该用增量

**数据量大（上万条）或操作频繁时，全量会卡。增量只动一行，代价是你要维护好位置。**

**难点在"插到哪儿"**：表格按日期倒序，你改了一笔的日期从 9-27 到 9-01，这一行应该移到最底下。增量更新如果只是 `delete + insert` 插到末尾，位置就错了。

**解决：要么重新排序后插入，要么干脆退回全量。** 对于排序视图，全量反而更稳妥——你不用维护位置，重查一次就对了。

## 混合方案：按动作类型决定

**利用第 19 课 notify 传的动作名，给不同动作不同策略：**

```python
def _on_data_changed(action, rid):
    conn = db.get_conn()
    if action in ("delete",):                     # 删除：可以增量
        app["tree"].delete(str(rid))
        if not db.count_records(conn):
            app["tree"].pack_forget()
            app["empty_label"].pack(fill="both", expand=True, pady=80)
    elif action == "update":                      # 更新：位置可能变，全量
        refresh_table(app["tree"], app["empty_label"], conn)
    else:                                         # add：追加到末尾即可
        r = db.get_by_id(conn, rid)
        app["tree"].pack_forget()
        app["empty_label"].pack_forget()
        app["tree"].pack(fill="both", expand=True)
        app["tree"].insert("", "end", iid=str(rid), values=_fmt(r))
    app["status_var"].set(f"数据已更新（{action}）")
    root.after(3000, lambda: app["status_var"].set("就绪"))
```

**删除用增量**（删掉那行就行，位置不会变），**更新用全量**（位置可能变），**新增在末尾追加**（前提是当前视图是"按 id 倒序"——如果是按日期排序，新增可能要插到中间，此时也要全量）。

**这就是策略选择的本质：你得多想一步"这次操作会不会改变顺序"。**

## 分页：大数据量的终极方案

**如果记录真的上十万条，连全量刷新都会卡。** 这时候要分页：

```python
def load_page(tree, page, page_size=100):
    offset = page * page_size
    rows = db.get_page(conn, offset, page_size)   # LIMIT ? OFFSET ?
    # 清空并插入这一页
```

**数据库里用 `LIMIT 100 OFFSET 0` 只取前 100 条**，Treeview 只装 100 行，永远不卡。

**记账本基本用不上分页**——个人记账一年也就几百条。但了解这个概念，以后做"用户量大"的项目能派上用场。

## 翻车现场一：增量更新只改值不改位置，显示错乱

```python
def update_row(tree, rid, r):
    # 直接改值
    tree.item(str(rid), values=_fmt(r))    # 值变了，但位置没动
```

**症状**：金额从 38.5 改成 1200，显示值是对的，但它还待在原来的位置——而按金额排序的视图里，它应该跑到前面去。

**原因**：`tree.item()` 只改内容，不改顺序。

**解决**：排序视图下直接全量刷新；或者 `delete + insert` 到正确位置（要先算位置）。

## 翻车现场二：大数据量全量刷新，界面卡死

**症状**：导入了 50000 条记录后，每次添加都卡 2 秒，界面"未响应"。

**原因**：`refresh_table` 删 50000 行、插 50000 行，GUI 线程被占满。

**解决**：要么分页，要么增量。记账本场景不会出现这个问题，但批量导入时要记得——导入完再刷新一次即可，别在循环里每次 insert 都刷新。

## 翻车现场三：删到最后一条时忘记切到空状态

```python
def _on_data_changed(action, rid):
    if action == "delete":
        tree.delete(str(rid))
        # 忘了检查：现在是不是 0 条了？
```

**症状**：删掉最后一条后，界面显示一个空表格（有列标题、没数据），而不是"还没有记录"的友好提示。

**原因**：只做了 delete，没判断剩余行数，没切换空状态。

**解决**：删除后检查 `count_records`，为 0 就 `pack_forget(tree)` + `empty_label.pack()`。

## 小结

- 全量刷新：简单、一定对，适合数据量小或顺序会变的操作
- 增量更新：只改一行，快，但要处理插入位置
- 排序视图下增量容易出错，通常直接全量更稳妥
- 混合策略：按动作类型选——删除可增量、更新常全量、新增末尾追加
- 数据量上万要分页（LIMIT/OFFSET），记账本用不上
- 删到最后一条要检查并切换空状态

## 随堂练习

```quiz
type: local
q: 实现一个"智能刷新"函数 smart_refresh(action, rid)：删除时只 delete 那一行并检查空状态；新增时如果当前排序是"按 id 倒序"则末尾追加一行，否则全量刷新；更新时一律全量刷新。要求用 observer 订阅 "records_changed" 事件，传 (action, rid)。演示三种动作各触发一次，观察表格变化。注意：窗口程序网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  import tkinter as tk
  import tkinter.ttk as ttk
  import db, ui, observer

  def smart_refresh(action, rid):
      conn = db.get_conn()
      tree = app["tree"]
      if action == "delete":
          tree.delete(str(rid))
          if db.count_records(conn) == 0:
              tree.pack_forget()
              app["empty_label"].pack(fill="both", expand=True, pady=80)
      elif action == "add":
          r = db.get_by_id(conn, rid)
          app["empty_label"].pack_forget()
          tree.pack(fill="both", expand=True)
          tree.insert("", "end", iid=str(rid), values=_fmt(r))
      elif action == "update":
          ui.refresh_table(tree, app["empty_label"], conn)

  observer.subscribe(smart_refresh)
checklist:
- 删除只删那一行
- 删除到最后一条能切换空状态
- 新增能末尾追加一行
- 更新走全量刷新
- 通过 observer 触发
```

```quiz
type: local
exam: true
q: 实现一个分页加载函数 load_page(tree, page, page_size)，用 LIMIT/OFFSET 从数据库取一页数据并填充表格。界面上加"上一页""下一页"两个按钮，显示当前页码和总页数（总条数/page_size 向上取整）。演示：库里有 250 条数据，每页 100 条，点下一页能翻到第 2 页。注意：窗口程序网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  import tkinter as tk
  import tkinter.ttk as ttk
  import math
  import db, ui

  app = {"page": [0]}

  def load_page(page, page_size=100):
      offset = page * page_size
      rows = db.get_page(db.get_conn(), offset, page_size)
      ui._refill(app["tree"], rows)          # 只清空+插入，不做排序
      total = db.count_records(db.get_conn())
      pages = math.ceil(total / page_size)
      app["page_label"].config(text=f"{page+1} / {pages}")

  def next_page():
      app["page"][0] += 1
      load_page(app["page"][0])

  def prev_page():
      if app["page"][0] > 0:
          app["page"][0] -= 1
          load_page(app["page"][0])
checklist:
- load_page 用 LIMIT/OFFSET 取数据
- 上一页/下一页按钮能翻页
- 显示当前页码和总页数
- 边界处理（第一页不能往前）
- 表格内容随页码正确变化
```
