# 录入表单：Label + Entry + Combobox + Button

> 表格会画了，这一课搭底部的录入区：日期、金额、分类、备注四个输入控件，加一个"记一笔"按钮。表单是用户和软件打交道最频繁的界面，做得顺不顺手直接决定体验。

## 表单布局用 grid

**底部录入区是"一行多列"的对齐结构，用 grid 最合适：**

```python
form = tk.Frame(root, padx=8, pady=8)

tk.Label(form, text="日期").grid(row=0, column=0, sticky="w")
tk.Label(form, text="金额").grid(row=0, column=2, sticky="w")
tk.Label(form, text="分类").grid(row=0, column=4, sticky="w")
tk.Label(form, text="备注").grid(row=0, column=6, sticky="w")

date_var = tk.StringVar(value="2026-09-27")
amt_var = tk.StringVar()
cat_var = tk.StringVar()
note_var = tk.StringVar()

tk.Entry(form, textvariable=date_var, width=12).grid(row=1, column=0, padx=4)
tk.Entry(form, textvariable=amt_var, width=10).grid(row=1, column=2, padx=4)

cat_cb = ttk.Combobox(form, textvariable=cat_var, width=9,
                      values=("餐饮","交通","购物","居住","工资","其他"),
                      state="readonly")
cat_cb.grid(row=1, column=4, padx=4)
cat_cb.set("餐饮")                      # 默认选中

tk.Entry(form, textvariable=note_var, width=24).grid(row=1, column=6, padx=4)

tk.Button(form, text="+ 记一笔", command=on_add).grid(row=1, column=8, padx=8)

form.pack(side="bottom", fill="x")
```

**grid 的两行分工**：第 0 行放标签、第 1 行放控件，上下对齐。`sticky="w"` 让标签左对齐贴单元格左边。

## 为什么用 StringVar

**`textvariable` 把控件的值绑定到一个变量，好处是"想读就直接读"：**

```python
amt_var.get()      # 读取 Entry 当前内容，返回字符串
amt_var.set("0")   # 清空或预填
```

**也可以不用 StringVar，直接 `entry.get()`。** 用 StringVar 的优势是：多个控件/多个地方要同步同一个值时，改一处全局生效；且清空表单 `amt_var.set("")` 一行搞定，不用 `entry.delete(0, "end")`。

**本项目用 StringVar**，因为录入后要清空所有框，用变量集中管理更省事。

## Combobox 的 state="readonly"

**分类用下拉框，但要让用户只能选、不能自由输入：**

```python
cat_cb = ttk.Combobox(form, textvariable=cat_var, state="readonly", ...)
```

**为什么要 readonly？** 因为如果允许自由输入，用户会填出"餐饮""吃饭""饭"三个不同分类，统计直接废掉（第 4 课草图时就强调过）。

**代价**：readonly 下不能预设"提示文字"让用户看到"请选择分类"。解决办法是默认 `cat_cb.set("餐饮")`，或者自己接管 focus 事件做占位提示。

## 按钮回调：先取值再处理

**`+ 记一笔` 的回调要做三件事：**

```python
def on_add():
    date = date_var.get().strip()
    amt = amt_var.get().strip()
    cat = cat_var.get().strip()
    note = note_var.get().strip()

    # 1. 交给逻辑层校验
    ok, msg = logic.validate(date, amt, cat)
    if not ok:
        mb.showerror("输入有误", msg)
        return

    # 2. 交给数据层存储
    rtype = "支出"                       # 简化：默认支出，后续可加单选
    db.add_record(conn, float(amt), cat, date, note, rtype)

    # 3. 刷新表格 + 清空表单
    ui.refresh_table(tree, conn)
    date_var.set("")                      # 保留日期？看产品决策
    amt_var.set("")
    note_var.set("")
    # cat_var 保留上次选择，减少重复操作
```

**回调要短**——取值、调逻辑层、调数据层、刷新。业务逻辑写在 logic.py 里，不在回调里堆代码。

## 预填今天的日期

**日期框默认填今天，能减少用户操作：**

```python
from datetime import date
date_var = tk.StringVar(value=date.today().isoformat())   # "2026-09-27"
```

**`date.today().isoformat()` 正好返回 `YYYY-MM-DD`**，和我们数据库存的格式一致，省得用户手动敲。

## 翻车现场一：grid 和 pack 混用在同一个父容器

```python
tk.Label(form, text="日期").grid(row=0, column=0)
tk.Entry(form, textvariable=date_var).pack()    # 混用！
```

**症状**：控件要么显示不出来，要么布局错乱，还可能报 `cannot use geometry manager grid inside ... which already has slaves managed by pack`。

**原因**：同一个父容器（form）里同时用了两种布局管理器，tkinter 不知道听谁的。

**解决**：一个父容器只选一种。外层 frame 用 pack 切块，内层 form 用 grid 对齐，界限划清。

## 翻车现场二：Combobox 能自由输入，分类被污染

```python
cat_cb = ttk.Combobox(form, textvariable=cat_var, values=(...))  # 缺 state
cat_cb.set("")   # 用户能往里打字
```

**症状**：数据库里出现大量近似分类，"餐饮""吃饭""饭"全算不同项，饼图被切成一堆碎块。

**原因**：默认 `state="normal"`，允许编辑。

**解决**：`state="readonly"` 强制只能选。需要允许用户新增分类时，单独做一个"管理分类"功能，而不是在录入框里随手写。

## 翻车现场三：录入后不刷新，用户以为没存上

```python
def on_add():
    db.add_record(conn, float(amt), cat, date, note, "支出")
    # 忘记 refresh_table
    mb.showinfo("已保存", "保存成功")   # 用户看到提示，但表格没更新
```

**症状**：弹窗说"保存成功"，但表格里看不到新记录。用户会反复点"记一笔"，存进一堆重复数据。

**原因**：没调刷新，表格和数据脱节。

**解决**：每次写操作后都刷新表格。第 19 课会用观察者模式自动化这件事，现在先手动调 `refresh_table`。

## 小结

- 录入区用 grid：第 0 行标签、第 1 行控件，上下对齐
- StringVar 统一管理输入值，清空用 .set("") 一行搞定
- Combobox 用 state="readonly"，防止分类被自由输入污染
- 按钮回调要短：取值 → 校验 → 存 → 刷新
- 日期框预填今天，减少用户操作
- 同父容器只用一种布局管理器，别 grid/pack 混用
