# SQLite 与连接：sqlite3 标准库

> 从这一课开始进入数据层。SQLite 是这一册的数据心脏——你写的所有记录、做的所有统计，最终都要经过它。第一课先把"怎么连上它"讲透。

## sqlite3 是标准库

**Python 自带 `sqlite3` 模块，装好 Python 就能用，不用 pip：**

```python
import sqlite3

conn = sqlite3.connect("ledger.db")
print(conn)
# <sqlite3.Connection object at 0x...>
```

**`connect("ledger.db")` 做两件事：**

1. 如果当前目录没有 `ledger.db`，**自动创建**这个文件；
2. 打开一个到这个文件的数据库连接，返回 `Connection` 对象。

**这就是 SQLite "单文件数据库"的含义**：整个数据库就是一个 `.db` 文件，你可以用文件管理器看到它、复制它、备份它。

## 连接与游标

**拿到连接后，还要拿一个"游标"（cursor）才能执行 SQL：**

```python
conn = sqlite3.connect("ledger.db")
cur = conn.cursor()

cur.execute("CREATE TABLE IF NOT EXISTS t(x INT)")
cur.execute("INSERT INTO t VALUES (1)")

conn.commit()      # 增删改必须 commit，否则不生效
conn.close()
```

**两个对象的分工：**

| 对象 | 干什么 |
|---|---|
| `Connection` | 管连接、事务（commit/rollback）、关闭 |
| `Cursor` | 执行 SQL、取查询结果 |

**记住：增删改要 `commit()`，查询不用。** 这是 SQLite 的事务机制：改动先在内存里，commit 才真正写进文件。

## 连接放哪儿、开几个

**一个桌面应用通常只需要一个全局连接**，程序启动时打开，退出时关闭。把它放在 `db.py` 里：

```python
import sqlite3

_conn = None

def get_conn():
    global _conn
    if _conn is None:
        _conn = sqlite3.connect("ledger.db")
    return _conn
```

**为什么不每次操作都开一个连接？** 因为打开连接是有开销的，频繁开关会让界面卡顿（虽然 SQLite 很快，但积少成多）。**保持一个长连接、全程复用**，是桌面应用的标准做法。

## 让查询结果更好用：row_factory

**默认 `cur.fetchall()` 返回的是元组列表，你得靠下标取值：**

```python
cur.execute("SELECT id, amount, category FROM records")
rows = cur.fetchall()
for r in rows:
    print(r[0], r[1], r[2])   # 下标 0 1 2，难记
```

**改成"按列名取值"**：设置 `row_factory`：

```python
conn = sqlite3.connect("ledger.db")
conn.row_factory = sqlite3.Row

cur = conn.cursor()
cur.execute("SELECT id, amount, category FROM records")
rows = cur.fetchall()
for r in rows:
    print(r["id"], r["amount"], r["category"])   # 按名字取，清楚
```

**一旦用了 `Row`，返回的对象既可以用名字 `r["id"]`，也可以当元组 `r[0]`。** 推荐在数据层里统一设置，界面层读起来舒服很多。

## 翻车现场一：忘了 commit，数据没存进去

```python
conn = sqlite3.connect("ledger.db")
cur = conn.cursor()
cur.execute("INSERT INTO records(amount) VALUES (38.5)")
# 忘记 conn.commit()
conn.close()
```

**症状**：程序不报错，看起来一切正常。但下次打开软件，这条记录不见了。

**原因**：SQLite 默认是"延迟提交"模式，INSERT/UPDATE/DELETE 后必须显式 `commit()`，改动才会写进文件。关连接时如果还有未提交的事务，SQLite 会**回滚**（丢掉）。

**解决**：养成习惯——每个写操作（增删改）后面紧跟 `commit()`。更好的做法是把写操作包在 `try/except` 里，出错时 `rollback()`。

## 翻车现场二：同时开两个连接往同一个 db 写

```python
# 线程 A
conn1 = sqlite3.connect("ledger.db")
# 线程 B
conn2 = sqlite3.connect("ledger.db")
```

**症状**：第二个连接写的时候报 `database is locked`，或者数据互相覆盖。

**原因**：SQLite 是文件级锁，同一时刻只允许一个写者。多线程各开连接会撞车。

**解决**：本项目是单线程 tkinter 程序，**全局只保持一个连接**就不会撞。真有多线程需求，要加锁或改用支持并发的数据库。

## 翻车现场三：程序崩了没关连接

**症状**：异常发生时 `conn.close()` 没被执行，连接泄漏。轻则下次 `connect` 报"数据库被占用"，重则文件锁残留。

**解决**：用 `try/finally` 保证关闭，或者用上下文管理。但注意——**`Connection` 本身支持上下文管理，只是它管的是"事务"，不是"连接关闭"**：

```python
with sqlite3.connect("ledger.db") as conn:    # with 结束时会 commit 或 rollback
    cur = conn.cursor()
    cur.execute("INSERT INTO records(amount) VALUES (38.5)")
# 离开 with 块：如果没异常就 commit，有异常就 rollback
# 注意：连接本身并未关闭！仍需 conn.close()
```

**这一点很反直觉，务必记住：`with conn` 管事务，不管关闭。**

## 小结

- `sqlite3` 是标准库，`connect()` 不存在就自动建文件
- 连接管事务、游标管执行；增删改要 commit
- 桌面应用全局一个连接、全程复用，别频繁开关
- 设 `row_factory = sqlite3.Row` 后能用列名取值
- 忘了 commit 是最常见的"数据神秘消失"原因
- `with conn` 只管事务提交/回滚，连接还得自己关
