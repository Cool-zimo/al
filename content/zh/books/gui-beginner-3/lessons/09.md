# 参数化查询：为什么不能拼接 SQL

> 上一课你看到的所有 SQL 都用 `?` 占位符。这一课讲清楚为什么——因为字符串拼接 SQL 是致命的安全漏洞，即使你的软件"只是自己用"也值得养成好习惯。

## 用 f-string 拼接的"看起来方便"

**新手最爱这么写：**

```python
category = "餐饮"
cur.execute(f"SELECT * FROM records WHERE category = '{category}'")
```

**这行代码确实能跑，看起来也没毛病。** 但一旦这个 `category` 的来源不是你手写的常量，而是用户的输入框，灾难就来了。

## SQL 注入演示

**假设分类输入框里用户填了这么一段（看起来像乱码，其实是精心构造的攻击）：**

```python
category = "餐饮'; DROP TABLE records; --"
cur.execute(f"SELECT * FROM records WHERE category = '{category}'")
```

**拼出来后实际发给数据库的 SQL 是：**

```sql
SELECT * FROM records WHERE category = '餐饮'; DROP TABLE records; --'
```

**三条语句被一次性执行：**

1. 正常查询；
2. `DROP TABLE records;` 把你的表删了；
3. `--` 把后面残留的 `'` 注释掉，语法合法。

**你的记账本，连同所有数据，在一瞬间消失。** 这就是 SQL 注入。

## 即使"自己用"也不能侥幸

**你可能会说："这软件就我自己用，谁会填这种东西？"**

**现实中的来源不止用户：**

- 从 CSV 导入数据时，数据文件里可能有恶意内容；
- 复制粘贴一条带引号的备注；
- 将来软件要联网、要接别人，隐患早就埋下了。

**更实际的理由：拼接 SQL 会先崩在你自己手上。** 看下一条翻车现场。

## 占位符的写法

**把"会变的部分"用 `?` 代替，把值单独作为参数传进去：**

```python
cur.execute("SELECT * FROM records WHERE category = ? AND date LIKE ?",
            ("餐饮", "2026-09%"))
```

**SQLite 会做三件事：**

1. 把参数里的引号**转义**，让它不可能被当成 SQL 语法；
2. 检查类型是否匹配；
3. 缓存执行计划，重复执行更快。

**对数据库来说，注入的那段字符串就是普通数据，没有任何特殊含义。**

## 多参数时的对应关系

**占位符 `?` 的数量必须和参数元组长度一致：**

```python
cur.execute("""
    INSERT INTO records(amount, category, date, note, type, created_at)
    VALUES (?, ?, ?, ?, ?, ?)
""", (38.5, "餐饮", "2026-09-27", "午餐", "支出", now))
# 6 个 ? 对应 6 个值
```

**顺序必须对齐。** 错位会导致数据插进错误的字段——更糟的是它**不报错**，你只会发现"金额列里出现了一串日期"。

## 翻车现场一：引号未转义导致语法错误

```python
note = "Tom's lunch"
cur.execute(f"INSERT INTO records(note) VALUES ('{note}')")
# SQL: INSERT INTO records(note) VALUES ('Tom's lunch')
#                                     ^ 这里提前结束，语法错
```

**症状**：`sqlite3.OperationalError: unrecognized token` 或 `near "s": syntax error`。

**原因**：`note` 里有个单引号，把 SQL 字符串提前截断了。

**解决**：用占位符 `?`，让 SQLite 自动转义。这也顺带解释了为什么"注入能得手"——攻击者就是靠故意放引号来篡改语法。

## 翻车现场二：IN 子句不能一个 ? 塞一堆值

```python
cats = ("餐饮", "交通", "购物")
cur.execute(f"SELECT * FROM records WHERE category IN {cats}")
# SQL: WHERE category IN ('餐饮','交通','购物')  ← 恰好能跑，但只对元组生效
```

**看似能跑，但换成用户输入就崩。** 正确写法是用 `?` 占位符配合字符串拼接出对应数量的问号：

```python
cats = ("餐饮", "交通", "购物")
placeholders = ",".join("?" * len(cats))          # "?,?,?"
sql = f"SELECT * FROM records WHERE category IN ({placeholders})"
cur.execute(sql, cats)
```

**注意**：这里**只有 IN 的括号部分用了 f-string**，值是用占位符传的，两全其美——既灵活又安全。

## 翻车现场三：表名、列名不能用占位符

```python
col = "amount"
cur.execute("SELECT ? FROM records", (col,))
# 查出来的结果是一列字符串 "amount"，不是 amount 的值！
```

**症状**：返回的不是数据，而是列名本身。

**原因**：`?` 占位符只能替代**值**，不能替代表名、列名、排序方向。SQLite 会把 `?` 填进去的地方当成字符串值。

**解决**：表名/列名确实需要动态的，只能用字符串拼接，但要**白名单校验**：

```python
VALID_COLS = {"amount", "category", "date"}
def get_sorted(col):
    if col not in VALID_COLS:
        raise ValueError(f"非法列名: {col}")
    cur.execute(f"SELECT * FROM records ORDER BY {col}")
```

**白名单 = 只放行已知安全的名字**，从根源上杜绝注入。

## 小结

- 字符串拼接 SQL 会导致 SQL 注入，严重时 DROP TABLE 数据全没
- 所有"值"都用 `?` 占位符 + 参数元组传，让 SQLite 转义
- `?` 数量要和参数个数对齐，错位会插错字段且不报错
- IN 子句用 `",".join("?"*len(seq))` 动态造占位符
- 表名/列名不能用占位符，只能拼接 + 白名单校验
- 即使自己用也该养成习惯，且能避免引号带来的语法错

```quiz
type: local
q: 故意演示一次"引号导致的语法错误"：写脚本用 f-string 拼接一条带单引号的备注（比如 "Tom's lunch"）做插入，观察报错。然后改成 ? 占位符版本，验证能正常插入。注意：sqlite3 本地运行，网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  import sqlite3

  conn = sqlite3.connect("ledger.db")
  cur = conn.cursor()
  cur.execute("CREATE TABLE IF NOT EXISTS demo(note TEXT)")

  bad = "Tom's lunch"
  # 错误版：f-string 拼接
  try:
      cur.execute(f"INSERT INTO demo(note) VALUES ('{bad}')")
  except Exception as e:
      print("错误版报错:", e)

  # 正确版：? 占位符
  cur.execute("INSERT INTO demo(note) VALUES (?)", (bad,))
  conn.commit()
  print("正确版结果:", cur.execute("SELECT * FROM demo").fetchall())
  conn.close()
checklist:
- 错误版确实因引号报错
- 正确版用了 ? 占位符
- 正确版能正常插入并查回
- 观察到了报错信息
```
