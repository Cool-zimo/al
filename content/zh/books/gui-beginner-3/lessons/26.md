# 异常处理与兜底：程序不能崩给用户看

> 用户磁盘写满了、数据库文件被同事误删、有人在金额栏输了个"abc"——这些事一定会发生。这一课给你的记账本装上"安全带"：全局异常钩子兜住漏网之鱼，磁盘满了有提示，乱输入有校验，而不是弹一堆红色报错让用户一脸懵。

## 为什么需要兜底

**桌面程序面对的是真实用户，不是你自己。** 你自己跑的时候不会手滑把 `ledger.db` 删了，不会在金额框里填"两百块"，不会在 C 盘只剩 1KB 的时候还往里写。但你的用户会。

**一个没做异常处理的程序，崩溃长这样：**

```
Traceback (most recent call last):
  File "app.py", line 42, in on_save
    self.db.insert(amount=float(self.amount.get()), ...)
ValueError: could not convert string to float: 'abc'
```

**窗口直接闪退，用户丢数据、吓一跳、再也不打开。** 这不是用户体验问题，是信任问题。

## 全局异常钩子：最后一道路障

**tkinter 有个特点：回调函数里抛出的异常默认会打印到控制台然后继续运行，但如果有没捕获的异常跑到事件循环外，整个程序就崩了。** 解决办法是装一个全局钩子。

**Python 的 `sys.excepthook` 能在任何未捕获异常发生时被调用：**

```
import sys
import tkinter.messagebox as mb

def global_exc_handler(exc_type, exc_value, exc_tb):
    import traceback
    text = "".join(traceback.format_exception(exc_type, exc_value, exc_tb))
    print("未捕获异常:\n", text)          # 开发者视角：完整堆栈
    mb.showerror("程序出错了",
        f"发生了一个意外错误：\n{exc_value}\n\n请重启程序，数据已自动保存。")

sys.excepthook = global_exc_handler
```

**三个要点：**

1. **先 print 完整堆栈**——给开发者的排查线索，用户看不到；
2. **再弹一个友好的 messagebox**——给用户看的，只说"发生了什么、该怎么办"，不甩堆栈；
3. **放在 `main.py` 最顶部**，比任何业务代码都早执行。

**`tkinter` 自己抛的异常走的是另一条路**，有些 GUI 框架的事件循环会吞掉异常。保险起见，业务回调里还是自己 `try/except`。

## 磁盘写满：捕获 IOError

**场景**：用户账本存 U 盘，U 盘被拔了；或者系统盘满了。SQLite 执行 `COMMIT` 时直接抛 `sqlite3.OperationalError`。

**错误写法：什么都没做**

```
def save(self):
    self.db.insert(...)
    mb.showinfo("已保存")    # 如果 insert 失败了，这行照样执行
```

**正确写法：把保存包在 try 里，失败了明确告诉用户**

```
def on_save(self):
    try:
        self.db.insert(
            category=self.category.get(),
            amount=float(self.amount.get()),
            note=self.note.get(),
            date=self.date.get(),
        )
    except OSError as e:              # 磁盘满、权限不足、U盘被拔
        mb.showerror("保存失败", f"无法写入数据文件：\n{e}\n请检查磁盘空间和文件权限。")
        return
    except ValueError as e:           # 金额格式不对
        mb.showwarning("输入有误", f"金额必须是数字：{e}")
        return
    self.on_changed()
    mb.showinfo("成功", "已保存一条记录")
```

**`OSError` 是 `PermissionError`、`FileNotFoundError` 的父类**，一网打尽。用户看到的不再是红色堆栈，而是"请检查磁盘空间"这种能执行的话。

## 用户乱输入：在入库前校验

**校验有两道关，越早越好：**

| 层级 | 时机 | 例子 |
|---|---|---|
| 界面层校验 | 用户点保存的那一刻 | 金额为空、日期格式错 |
| 数据层约束 | SQL 层面 | NOT NULL、CHECK 约束 |

**界面层校验示例：**

```
def validate(self):
    category = self.category.get().strip()
    if not category:
        mb.showwarning("校验失败", "请选择分类")
        return False
    amount_str = self.amount.get().strip()
    if not amount_str:
        mb.showwarning("校验失败", "金额不能为空")
        return False
    try:
        amount = float(amount_str)
    except ValueError:
        mb.showwarning("校验失败", f"金额「{amount_str}」不是有效数字")
        return False
    if amount <= 0:
        mb.showwarning("校验失败", "金额必须大于 0")
        return False
    if len(self.note.get()) > 200:
        mb.showwarning("校验失败", "备注最多 200 字")
        return False
    return True
```

**校验函数返回 True/False，保存按钮这样用：**

```
def on_save(self):
    if not self.validate():
        return                    # 校验不过就停在这里
    try:
        ...
    except ...
```

**数据层约束是第二道关**：表定义里 `amount REAL NOT NULL CHECK(amount > 0)`，万一哪天有人绕开界面直接调 `db.insert`，SQL 也会拦下来。界面层是给用户看的，数据层是给自己兜底的，两道都别省。

## 翻车现场一：裸 except 吞掉了真正的 bug

**症状**：程序"看起来没崩"，但什么也没存进去，也没任何提示。

**原因**：`except:` 把一切异常都吞了，包括你代码里的拼写错误。

**错误写法：**

```
try:
    self.db.insert(amount=float(self.amount.get()), ...)
except:                  # 裸 except，连 KeyboardInterrupt 都吃
    pass                 # 啥也不做，bug 被彻底藏起来了
```

**正确写法：捕获具体异常，else 兜底记日志**

```
try:
    self.db.insert(...)
except (ValueError, OSError) as e:
    mb.showerror("保存失败", str(e))
except Exception as e:              # 兜底：真正的意外
    logging.exception("保存时发生意外")   # 第 28 课讲 logging
    mb.showerror("程序出错了", "请联系开发者")
```

**规则：`except` 后面永远写具体的异常类型。** 实在要兜底，也只兜 `Exception`，并且记日志。

## 翻车现场二：数据库文件损坏，程序直接崩

**症状**：`ledger.db` 被同步盘中途覆盖，文件截断，下次打开直接报错。

```
sqlite3.DatabaseError: file is not a database
```

**思路**：打开时检测，坏了就告诉用户，并保留原文件重命名备份。

```
import os, shutil

def open_db(path):
    try:
        db = LedgerDB(path)
        db.test_connection()        # 跑一条 SELECT 1 探活
        return db
    except sqlite3.DatabaseError as e:
        logging.exception("数据库损坏")
        bad = path + ".corrupt"
        shutil.move(path, bad)     # 先保留坏文件，别覆盖
        mb.showerror("数据文件损坏",
            f"数据文件无法读取并已备份为：\n{bad}\n\n程序将重新创建一个新的空账本。")
        return LedgerDB(path)      # 重新建一个
```

**关键：先备份再新建。** 直接覆盖坏文件等于把唯一的证据毁了，用户没法拿去恢复。

## 翻车现场三：全局钩子弹不出 messagebox

**症状**：装了 `sys.excepthook` 之后崩溃时没弹窗，控制台也没输出。

**原因**：异常发生时主循环可能已经退出了，`tk.Tk()` 不存在了，`messagebox.showerror` 会再抛一个 `RuntimeError: main thread is not in main loop`。

**解决办法：钩子里先判断能不能弹窗，不行就只写日志。**

```
def global_exc_handler(exc_type, exc_value, exc_tb):
    import traceback
    text = "".join(traceback.format_exception(exc_type, exc_value, exc_tb))
    logging.error("未捕获异常:\n%s", text)
    try:
        if tk._default_root is not None:
            mb.showerror("程序出错了", str(exc_value))
    except Exception:
        pass    # 连弹窗都弹不了，至少日志已经写了
```

## 小结

- 桌面程序必须兜底，崩溃不是"小事"而是信任问题
- `sys.excepthook` 是最后一道防线，要同时写日志 + 弹友好提示
- 磁盘满、权限不足都归 `OSError`，统一捕获
- 校验分两层：界面层给用户提示，数据层 SQL 约束兜底
- `except` 只抓具体异常，裸 `except: pass` 是埋 bug
- 数据库损坏先备份坏文件再新建，别覆盖证据
