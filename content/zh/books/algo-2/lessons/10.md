# 实战：LRU 缓存的实现思路

> LRU（Least Recently Used）缓存是面试的"试金石"：要 O(1) 查找、O(1) 插到头部、O(1) 删尾部——单靠哈希表或单链表都做不到，必须哈希表 + 双向链表双持。

## 问题

设计一个 LRU 缓存，支持两个操作：

- `get(key)`：存在则返回 value 并把该 key 标记为"最近使用"；不存在返回 -1
- `put(key, value)`：写入或更新；如果 key 已存在就更新值并标记为最近使用；如果容量已满，**先淘汰最久未使用的 key**，再写入

要求 `get` 和 `put` 都是 **O(1)** 时间。

示例：容量 2

```
cache = LRUCache(2)
cache.put(1, 1)   # [1]
cache.put(2, 2)   # [2, 1]  2 是最近使用
cache.get(1)      # 返回 1, [1, 2]
cache.put(3, 3)   # 容量满，淘汰 2 -> [3, 1]
cache.get(2)      # 返回 -1 (已被淘汰)
cache.put(4, 4)   # 淘汰 1 -> [4, 3]
cache.get(1)      # -1
cache.get(3)      # 3
cache.get(4)      # 4
```

## 为什么单用任何一个都不行

| 数据结构 | 查找 | 移到头部 | 删尾部 | 结论 |
|---|---|---|---|---|
| 哈希表 | O(1) | — | — | 不知道谁最久没用 |
| 数组/列表 | — | O(n) 搬移 | O(1) | put/get 不是 O(1) |
| 单链表 | — | O(n) 找前驱 | O(n) | 处处 O(n) |

**单链表删尾要 O(n)**——你找到尾容易，但改它的前驱的 next 得从头遍历。双向链表每个节点都记着前驱，删自己 O(1)。

所以要两件武器：

- **哈希表**：`key -> 节点`，O(1) 定位
- **双向链表**：维护"最近使用"顺序，头部=最新、尾部=最久未用；增删都是 O(1)

## 完整实现

```python
class Node:
    def __init__(self, key=0, val=0):
        self.key = key
        self.val = val
        self.prev = None
        self.next = None

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.cache = {}                  # key -> Node
        # 哨兵头尾，消灭空链表和边界判断
        self.head = Node()               # 最近使用的放在 head 后面
        self.tail = Node()               # 最久未用的在 tail 前面
        self.head.next = self.tail
        self.tail.prev = self.head

    def _remove(self, node):
        """从双向链表中摘除 node"""
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_to_head(self, node):
        """把 node 插到 head 之后（标记为最近使用）"""
        node.next = self.head.next
        node.prev = self.head
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        if key not in self.cache:
            return -1
        node = self.cache[key]
        self._remove(node)        # 先摘下来
        self._add_to_head(node)   # 再挂到头部
        return node.val

    def put(self, key, value):
        if key in self.cache:
            # 已存在：更新值，并提到头部
            self._remove(self.cache[key])
        node = Node(key, value)
        self._add_to_head(node)
        self.cache[key] = node
        if len(self.cache) > self.cap:
            # 容量超了，淘汰 tail 前面的节点
            lru = self.tail.prev
            self._remove(lru)
            del self.cache[lru.key]
```

**三段逻辑要记清：**

1. **`get` 命中** = 查表 O(1) + 摘下 + 挂头，三次指针操作都是 O(1)
2. **`put` 已存在** = 先 `_remove` 旧的再挂新的（位置变了，值也更新了）
3. **容量满了** = 淘汰 `tail.prev`，即最久未用的那个

## 手跑一遍

容量 2，执行 `put(1,1)`, `put(2,2)`, `get(1)`, `put(3,3)`：

```
put(1,1): cache={1:node1}, 链表 head <-> 1 <-> tail
put(2,2): cache={1,2},    链表 head <-> 2 <-> 1 <-> tail  (2 在头，最新)
get(1):   命中，1 摘下再挂头 -> head <-> 1 <-> 2 <-> tail
put(3,3): 容量 2 已满 -> 淘汰 tail.prev 即节点 2
           -> head <-> 3 <-> 1 <-> tail
```

注意淘汰的顺序：`2` 是最久未用的（在 `tail` 前面），被删掉。`1` 刚被访问过，保留。

## 为什么双向链表要加哨兵 head/tail

没有哨兵的话，`_add_to_head` 要分"链表为空"和"不为空"两种情况，`_remove` 也要判断是不是最后一个节点。加了 head/tail 两个空节点后：

- 链表永远非空，head/tail 永远不动
- `_remove` 不用判断 node 是不是头或尾——它总有前驱和后继
- `_add_to_head` 永远插在 `head` 和 `head.next` 之间

这和链表题里 dummy 哨兵是同一个思路。

## 复杂度

| 操作 | 时间 | 空间 |
|---|---|---|
| get | O(1) | — |
| put | O(1) | — |
| 总体 | — | O(capacity) |

注意是 **均摊 O(1)**：哈希表在最坏情况下可能退化到 O(n)，但面试和工程上按 O(1) 算。

## 翻车现场：用 list 维护顺序，每次 get 都 remove

```python
# WRONG
class LRUList:
    def __init__(self, cap):
        self.cap = cap
        self.d = {}
        self.order = []           # 用列表记录访问顺序

    def get(self, key):
        if key not in self.d:
            return -1
        self.order.remove(key)    # O(n)！列表删除任意元素要搬移
        self.order.append(key)
        return self.d[key]
```

`list.remove()` 是 O(n)，一次 `get` 就把整体复杂度拖到 O(n)。容量大、访问频繁时性能崩盘。

```
# 翻车输出（行为上看似正确，但超时）
>>> l = LRUList(2)
>>> l.put(1, 1); l.put(2, 2); l.get(1); l.put(3, 3)
>>> l.get(2)
-1            # 结果对了，但 remove 这一步悄悄慢了
```

LRU 的考察点就是"双向链表把 remove 降到 O(1)"，用列表等于绕过了核心考点。

## 翻车现场：用单链表，删尾部要遍历整条链

```python
# WRONG
class LRUSingle:
    def __init__(self, cap):
        self.cap = cap
        self.d = {}
        self.head = None

    def get(self, key):
        if key not in self.d:
            return -1
        return self.d[key].val

    def put(self, key, value):
        if key in self.d:
            self.d[key].val = value
            return               # 只更新了值，节点位置没变！
        node = self.Node(value)
        self.d[key] = node
        if not self.head:
            self.head = node
        else:
            # 单链表没法把任意节点提到头部，只能往尾巴挂
            cur = self.head
            while cur.next:
                cur = cur.next
            cur.next = node
        if len(self.d) > self.cap:
            k = self.head.val
            self.head = self.head.next
            del self.d[k]
```

两个致命问题：

1. **没法"提到头部"**：单链表没有前驱指针，找到某个节点后改不了它前面的指向，只能挂尾巴。`get(1)` 后节点 1 还是老位置，LRU 语义失效。
2. **淘汰逻辑错误**：只删了 `head`，但没正确维护顺序。

```
实际执行:
put(1,1), put(2,2) -> 链表 1 -> 2
get(1)              -> 应该把 1 提到最前，但实际什么都没做
put(3,3)            -> 超容量，删 head(1)，期望删最久未用的 2
实际 get(1) 还能返回 1（本该被淘汰），LRU 语义彻底错误
```

这就是双向链表不可替代的原因：**每个节点都能 O(1) 自删除，也能 O(1) 把自己插到任意位置。**

## 小结

- LRU 的核心是"查找 O(1) + 任意位置增删 O(1)"，单靠哈希表或链表都做不到
- **哈希表存 key→节点，双向链表维护使用顺序**（头=最新，尾=最久未用）
- 两个哨兵 `head`/`tail` 让插入和删除不用判断边界
- `get` 命中 = 摘下 + 挂头；`put` 存在 = 先删旧的再挂新的；超容量 = 删 `tail.prev`
- 千万别用 `list.remove()` 或单链表糊过去——复杂度或语义会出问题
- 这是面试高频题，本质是"哈希表 + 双向链表"这对组合的标准用法

```quiz

- 哈希表负责去重，双向链表负责排序，两者功能不重叠所以必须一起用
- 哈希表查找 O(1) 但不知道使用顺序；双向链表能 O(1) 把任意节点移到头部或删除尾部。单用任一个都无法同时满足"查找 O(1)"和"维护顺序 O(1)"
- 双向链表是为了节省内存，哈希表是为了加速
- 因为 Python 的 dict 本身不保证顺序，所以需要链表补上顺序
answer: 1
```
