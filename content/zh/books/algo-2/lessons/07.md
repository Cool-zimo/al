# 环形链表：快慢指针为什么一定能相遇

> 判断一个链表里有没有环。链表不像数组，没有"走到末尾"这种明确的终止条件——有环就意味着永远走不完。

## 问题

```
1 -> 2 -> 3 -> 4
     ^         |
     |_________|      4 指回 2，形成环
```

让你判断有没有环。直觉写法是边走边记：

```python
def has_cycle_set(head):
    seen = set()
    cur = head
    while cur:
        if id(cur) in seen:
            return True
        seen.add(id(cur))
        cur = cur.next
    return False
```

能过，但用了 **O(n) 额外空间**。面试官要的是 O(1)。

## Floyd 判环（龟兔赛跑）

两个指针，一个一次走一步（慢），一个一次走两步（快）：

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```

**循环条件 `fast and fast.next`**：因为 `fast` 一次要走两步，必须保证 `fast.next` 存在，否则 `fast.next.next` 会 `AttributeError`。

## 为什么一定会相遇？

这是这节课唯一需要真正想明白的事。

假设链表无环部分长 `m`，环长 `k`。快指针进环后，慢指针迟早也进环。此时：

- 慢指针在环上每秒走 1 格
- 快指针在环上每秒走 2 格
- **两者的相对速度是 1 格/秒**

相对速度 1 意味着：快指针每走一步，就把和慢指针的"环上距离"缩短 1。距离从 `d` 变成 `d-1`、`d-2`……必然归零。归零的那一刻就是相遇。

**关键前提：相对速度是 1。** 如果快指针一次走三步（相对速度 2），就可能在环长为偶数时永远错开——所以标准写法是走两步。

手跑一遍，环长 3：

```
位置:  0  1  2  (回到 0)
slow:  S
fast:  F
step1: slow=1, fast=2
step2: slow=2, fast=1  (fast 走 2 格: 2->0->1)
step3: slow=0, fast=0  <- 相遇
```

三步相遇，环长 3。总步数不超过 `m + k`。

## 只有两个节点自环也能判

```python
class Node:
    def __init__(self, v):
        self.v = v
        self.next = None

a = Node(1); b = Node(2)
a.next = b; b.next = a        # 1 -> 2 -> 1

print(has_cycle(a))           # True
```

最极端的情形是**单个节点指向自己**：

```python
x = Node(9)
x.next = x
print(has_cycle(x))           # True
```

想想为什么：一开始 `slow is fast` 都指向 `x`，但循环体先移动再比较，第一次移动后 `slow = x.next = x`，`fast = x.next.next = x`，仍然相等 → True。**先移动再比较**这个顺序很重要。如果写成先比较再移动，`slow is fast` 一进来就成立，那无环单节点链表也会被误判成有环：

```python
# WRONG
def has_cycle_bad(head):
    slow = fast = head
    while fast and fast.next:
        if slow is fast:      # 第一轮就成立！
            return True
        slow = slow.next
        fast = fast.next.next
    return False

n = Node(1)                   # 无环，只有一个节点
print(has_cycle_bad(n))       # True  <- 错的！
```

## 找到环的入口

相遇之后，把其中一个指针**放回起点**，两者都改成每次一步，再次相遇的位置就是环的入口。

```python
def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p = p.next
                slow = slow.next
            return p          # 环的入口
    return None
```

这个结论不直观，但可以这么理解：设无环部分长 `m`，环入口到相遇点距离 `x`，环长 `k`。相遇时快指针走了 `2s`，慢指针走了 `s`，差值是 `s`，而差值必然是环长的整数倍，所以 `s = n*k`。相遇点再走 `m` 步就回到入口（`s + m = n*k + m`，从入口算正好 `m`）。所以从头走 `m` 步的指针，和从相遇点走 `m` 步的指针，会同时抵达入口。

不需要背推导，记住**"相遇后一个放回起点，同步一步走，再相遇即入口"**就够了。

## 复杂度

| 方法 | 时间 | 空间 |
|---|---|---|
| 哈希集合记 `id()` | O(n) | O(n) |
| Floyd 快慢指针 | O(n) | **O(1)** |

## 翻车现场：比较值而不是比较身份

```python
# WRONG
def has_cycle_wrong(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow.v == fast.v:      # 用 == 比较值
            return True
    return False

a = Node(7); b = Node(7); c = Node(7)
a.next = b; b.next = c            # 7 -> 7 -> 7，无环
print(has_cycle_wrong(a))         # True  <- 错！三个节点值相同
```

链表判环比较的是**节点身份**，必须用 `is`，不是 `==`。

## 翻车现场：循环条件写错

```python
# WRONG
while fast.next:          # fast 本身可能是 None
    ...
```

```python
n = Node(1)               # 无环单节点
# has_cycle(n): fast = n, fast.next = None -> 条件为 False，正常退出
```

这一步侥幸没事，但换成空链表 `head = None` 就炸：

```python
# AttributeError: 'NoneType' object has no attribute 'next'
```

所以必须写成 `while fast and fast.next`。

## 小结

- Floyd 判环：慢走 1 步，快走 2 步，相遇即有环
- **相对速度 1** 保证必然相遇；走 3 步不保证
- 先移动再比较，否则单节点无环链表会被误判
- 比较用 `is`（节点身份），不能用 `==`（值）
- 循环条件 `while fast and fast.next`
- 找入口：相遇后一个放回起点，同步一步，再相遇处即入口
- 时间 O(n)，**空间 O(1)**——这是它相对于哈希集合的全部价值
