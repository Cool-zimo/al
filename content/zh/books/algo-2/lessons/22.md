# 冲突与解决：链地址法、开放寻址，负载因子与扩容

> 冲突是哈希表的宿命——把无限的世界塞进有限的数组，不可能不撞车。但撞车了怎么处理，决定了你的哈希表是快还是慢。

## 冲突：不可避免的宿命

回顾上节课的核心公式：`index = hash(key) % table_size`。

问题来了：**table_size 是有限的（比如 10），但可能的 key 是无限的（所有字符串）。** 根据鸽巢原理，必然有不同的 key 映射到同一个 index。

```python
hash("张三") % 10 = 3
hash("王五") % 10 = 3   # 撞了！
```

这就是**冲突（collision）**。

**冲突不可怕，可怕的是处理不好。**

## 方法一：链地址法（Separate Chaining）

每个数组位置不放一个元素，而是放一个**链表**（Python 里用 list）。所有映射到同一位置的 key 都挂在这个列表上。

```
index = hash(key) % 10

table[3] → [("张三", 95), ("王五", 88), ("赵六", 72)]
              ↑ 三个 key 都映射到了 index 3

查找"王五"：hash("王五") % 10 = 3 → table[3] → 遍历列表 → 找到
```

代码实现：

```python
class ChainingHash:
    def __init__(self, size=8):
        self.size = size
        self.table = [[] for _ in range(size)]
    
    def _hash(self, key):
        return sum(ord(c) for c in key) % self.size
    
    def put(self, key, value):
        idx = self._hash(key)
        # 遍历桶，看 key 是否已存在
        for i, (k, v) in enumerate(self.table[idx]):
            if k == key:
                self.table[idx][i] = (key, value)  # 更新
                return
        self.table[idx].append((key, value))  # 新增
    
    def get(self, key):
        idx = self._hash(key)
        for k, v in self.table[idx]:
            if k == key:
                return v
        return -1

h = ChainingHash()
h.put("张三", 95)
h.put("王五", 88)
print(h.get("张三"))   # 95
```

**优点**：实现简单，删除方便，即使冲突严重也只是链表变长。
**缺点**：多了一层指针/列表开销，链表太长时退化成 O(n)。

## 方法二：开放寻址（Open Addressing）

不另外开链表，**冲突了就找下一个空位**。

```
table[3] 被占了 → 试试 table[4]
table[4] 也被占了 → 试试 table[5]
table[5] 空着 → 放这里！
```

```python
class OpenAddressingHash:
    def __init__(self, size=8):
        self.size = size
        self.table = [None] * size
    
    def _hash(self, key):
        return sum(ord(c) for c in key) % self.size
    
    def put(self, key, value):
        idx = self._hash(key)
        # 线性探测：依次往后找空位
        while self.table[idx] is not None:
            idx = (idx + 1) % self.size
        self.table[idx] = (key, value)
    
    def get(self, key):
        idx = self._hash(key)
        while self.table[idx] is not None:
            k, v = self.table[idx]
            if k == key:
                return v
            idx = (idx + 1) % self.size
        return -1

h = OpenAddressingHash()
h.put("张三", 95)
h.put("王五", 88)  # 假设也映射到 3，放到 4
print(h.get("张三"))   # 95
```

**优点**：不用额外分配链表节点，缓存友好（数据连续存放），省内存。
**缺点**：删除困难（删除后不能简单置 None，否则会打断探测链），容易产生"聚集"现象。

## 两种方法的对比

| 特性 | 链地址法 | 开放寻址 |
|---|---|---|
| 实现难度 | 简单 | 较复杂（删除难） |
| 内存开销 | 每个节点额外指针 | 无额外开销 |
| 缓存友好 | 否（节点分散） | 是（连续存放） |
| 负载因子上限 | 可以 > 1 | 必须 < 1 |
| 删除操作 | 简单（删链表节点） | 复杂（需要墓碑标记） |

**Python 的 dict 用的是开放寻址。** Java 的 HashMap 在 JDK8 之前用链地址法，冲突严重时链表转红黑树。

## 负载因子：什么时候该扩容

**负载因子（load factor）= 已存储元素数 / 数组容量**

```python
load_factor = len(hash_table) / table_size
```

- 负载因子 = 0.5 → 平均每个桶 0.5 个元素，比较宽松
- 负载因子 = 1.0 → 平均每个桶 1 个元素，开始挤了
- 负载因子 = 2.0 → 平均每个桶 2 个元素，链表开始变长

**负载因子越大 → 冲突概率越高 → 性能越差。**

```python
# 直观感受
table_size = 10
num_elements = 10
load_factor = 1.0
# 如果 hash 完美均匀，每个桶恰好 1 个元素

num_elements = 50
load_factor = 5.0
# 平均每个桶 5 个元素 → 查找要遍历 5 个 → 从 O(1) 变成 O(5) ≈ 还在可接受范围
# 但如果分布不均，某个桶可能有 10+ 个元素
```

**经验值**：
- 链地址法：负载因子 > 0.75 时扩容
- 开放寻址：负载因子 > 0.5~0.7 时扩容

## 扩容：代价巨大的"搬家"

扩容不是简单地把数组变大，而是**重新哈希所有元素**。

```python
def resize(self):
    old_table = self.table
    self.size *= 2
    self.table = [[] for _ in range(self.size)]
    for bucket in old_table:
        for key, value in bucket:
            self.put(key, value)  # 重新计算 hash % 新的 size
```

**为什么必须 rehash？** 因为 `hash(key) % old_size ≠ hash(key) % new_size`。

```python
key = "张三"
old_size = 8
new_size = 16
hash(key) % 8   # 可能是 3
hash(key) % 16  # 可能是 11，完全不同！
```

**扩容的代价是 O(n)**——一次性搬动所有元素。但分摊到每次插入操作上，平均仍是 O(1)。

**这就是为什么插入的均摊复杂度是 O(1)：偶尔一次 O(n) 的扩容，被大量 O(1) 的操作分摊掉了。**

## 翻车现场：扩容后迭代器失效

```python
# WRONG：边遍历 dict 边增删，可能导致无限循环或 RuntimeError
d = {"a": 1, "b": 2, "c": 3}
for k in d:
    if k == "b":
        d["d"] = 4   # 在 Python 3 中这会触发 RuntimeError
```

实际运行：

```python
d = {"a": 1, "b": 2, "c": 3}
for k in d:
    if k == "b":
        d["d"] = 4
# RuntimeError: dictionary changed size during iteration
```

**正确做法**：

```python
# RIGHT：先收集要改的 key，再修改
d = {"a": 1, "b": 2, "c": 3}
to_add = {}
for k in d:
    if k == "b":
        to_add["d"] = 4

d.update(to_add)
print(d)   # {'a': 1, 'b': 2, 'c': 3, 'd': 4}
```

或者用 `list(d.keys())` 创建副本再遍历：

```python
d = {"a": 1, "b": 2, "c": 3}
for k in list(d.keys()):
    if k == "b":
        d["d"] = 4   # 安全，遍历的是副本
```

## 翻车现场：删除开放寻址中的元素

```python
# WRONG：开放寻址中直接置 None 会打断探测链
h = OpenAddressingHash(size=5)
h.put("a", 1)   # 假设映射到 index 0
h.put("f", 2)   # 假设也映射到 0，探测到 index 1
# table: [(a,1), (f,2), None, None, None]

h.table[0] = None  # 删掉 "a"
# table: [None, (f,2), None, None, None]

h.get("f")  # 从 index 0 开始探测，index 0 是 None → 以为"没找到" → 返回 -1！
# 但 "f" 明明在 index 1！
```

**正确做法：用墓碑（tombstone）标记**

```python
class OpenAddressingHashV2:
    DELETED = object()  # 墓碑标记
    
    def delete(self, key):
        idx = self._hash(key)
        while self.table[idx] is not None:
            if self.table[idx] is self.DELETED:
                idx = (idx + 1) % self.size
                continue
            k, v = self.table[idx]
            if k == key:
                self.table[idx] = self.DELETED  # 标记为墓碑，不断链
                return
            idx = (idx + 1) % self.size
    
    def get(self, key):
        idx = self._hash(key)
        while self.table[idx] is not None:
            if self.table[idx] is not self.DELETED:
                k, v = self.table[idx]
                if k == key:
                    return v
            idx = (idx + 1) % self.size
        return -1
```

**墓碑只是一个"我在这里被删了"的占位符，探测链不会断。** 但墓碑多了也需要清理（重建哈希表）。

## 翻车现场：扩容后顺序全变了

```python
d = {}
for i in range(100):
    d[i] = i

# 遍历顺序取决于内部布局
keys_before = list(d.keys())

d[99999] = 99999  # 可能触发扩容

keys_after = list(d.keys())
# keys_before 和 keys_after 的顺序可能完全不同！
```

**实际影响**：Python 3.7+ 虽然保证了插入顺序，但**扩容/重建会重新排列内部存储**，遍历顺序可能变化。不要写依赖遍历顺序的业务逻辑（除非你明确只需要"插入顺序"这一保证）。

## 小结

- 冲突不可避免：有限数组装无限 key，鸽巢原理保证必有碰撞
- 链地址法：每个桶挂一个链表，实现简单，删除方便
- 开放寻址：冲突后线性探测找空位，省内存但删除困难（需要墓碑标记）
- Python dict 用开放寻址，Java HashMap 用链地址法（JDK8+ 转红黑树）
- 负载因子 = 元素数 / 容量，超过阈值（0.5~0.75）就扩容
- 扩容 = 重新哈希所有元素，O(n) 但均摊到每次插入仍是 O(1)
- 边遍历边修改 dict 会 RuntimeError，删除开放寻址中的元素不能简单置 None
