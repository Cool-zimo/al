# 反转链表：迭代版（三指针）逐帧手跑

> 反转链表是面试第一题。这一课用 prev / cur / nxt 三个指针逐帧手跑一遍，把每一步的箭头变化都摊开来看。


## 题目：把链表反过来

给 `1 → 2 → 3 → None`，要变成 `3 → 2 → 1 → None`。

```python
head = build([1, 2, 3])
# 目标：3 → 2 → 1 → None
```

直觉：从头开始，把每个节点的 `next` 指向前一个。


## 三指针：prev / cur / nxt

一次只改一个箭头，必须先把「下一个」存起来，否则一改就断了。

```python
def reverse_list(head):
    prev = None          # 反转后，原来的头变成尾，指向 None
    cur = head
    while cur:
        nxt = cur.next    # ① 先保存后继，不然一会儿找不到
        cur.next = prev   # ② 反转当前箭头
        prev = cur        # ③ prev 前进
        cur = nxt         # ④ cur 前进
    return prev           # 循环结束 cur 是 None，prev 就是新头
```


## 逐帧手跑

输入 `1 → 2 → 3 → None`，初始 `prev=None, cur=1`。

```
帧 1: nxt=2; 1.next=None; prev=1; cur=2
      链表：1→None，2→3→None
帧 2: nxt=3; 2.next=1;  prev=2; cur=3
      链表：2→1→None，3→None
帧 3: nxt=None; 3.next=2; prev=3; cur=None
      链表：3→2→1→None
循环结束，返回 prev=3
```

每一帧都只有一件事：把 `cur.next` 掰向 `prev`，然后三个指针整体往右滑一格。


## 翻车现场：不存 nxt，改完箭头就找不到下一个了

```python
# WRONG
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        cur.next = prev    # 直接改了，后继没保存
        prev = cur
        cur = cur.next     # cur.next 刚刚被改成 prev，也就是原来的 cur！死循环
    return prev
```

```text
结果：死循环。cur 的 next 被改成了 prev（也就是上一步的自己方向的节点），
cur = cur.next 等于往回走，链被打结成环，程序永不退出。
```

**教训：凡是要改 `cur.next`，前一行动作永远是 `nxt = cur.next`。** 这是链表题的铁律。


## 验证：转成列表比对

```python
head = build([1, 2, 3, 4, 5])
new_head = reverse_list(head)
print(to_list(new_head))    # [5, 4, 3, 2, 1]
```

反转后原来的尾变成头，原来的头变成尾（指向 None）。


## 小结

- - 反转链表 = 把每个节点的 next 指向前一个
- - 三指针 prev / cur / nxt，每帧先存 nxt 再改箭头
- - 不存 nxt 直接改 next 会把链表打成环、死循环
- - 循环结束 cur 为 None，返回 prev 就是新头

```quiz
type: choice
exam: true
q: 反转链表中，为什么必须在改动 cur.next 之前用 nxt 保存 cur.next？
options:
- 因为改了 cur.next 之后，原来的下一个节点就再也访问不到了，不保存会导致链表断裂或死循环
- 因为 Python 会报错
- 为了节省内存
- 为了让链表保持有序
answer: 0
explain: 反转操作要把 cur.next 指向 prev，一旦改完，原本的下一个节点就失去引用。如果不事先存到 nxt 里，后续 cur 和 prev 都无法继续推进，循环会死掉或漏节点。保存 nxt 是链表「先存后改」铁律的典型应用。报错、省内存、保有序都不是原因。
```
