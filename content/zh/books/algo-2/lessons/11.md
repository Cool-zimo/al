# 栈是什么：后进先出，以及 Python 的 list 为什么天然就是它

> 栈是全部数据结构里最简单的一个，也是最常被低估的一个。括号匹配、撤销操作、函数调用、表达式求值——都靠它。

## 生活里的栈

一摞盘子，只能从最上面拿；浏览器后退按钮，回到的是"最近访问的那个页面"；编辑器里的 Ctrl+Z，撤销的是"最后一步操作"。它们的共同点是：**最后放进去的，最先出来**。这个规则叫 **LIFO（Last In, First Out，后进先出）**。

与之相反的是队列（Queue），它是 **FIFO（先进先出）**——排队买饭，先来的先打到饭。

> 一句话区分：栈是"摞盘子"，队列是"排队"。

## 栈的三个操作

一个栈只需要三个动作就够用：

| 操作 | 含义 | Python 写法 |
|---|---|---|
| push | 把元素压到栈顶 | `s.append(x)` |
| pop | 弹出并返回栈顶元素 | `s.pop()` |
| top / peek | 只看栈顶，不弹出 | `s[-1]` |

此外还有两个辅助判断：`len(s) == 0` 判断是否为空，`len(s)` 看栈里有多少元素。

```python
s = []
s.append('A')      # 栈: ['A']
s.append('B')      # 栈: ['A', 'B']
s.append('C')      # 栈: ['A', 'B', 'C']
s.pop()            # 弹出 'C'，栈变成 ['A', 'B']
print(s[-1])       # 看一眼栈顶，是 'B'，栈没变
```

## 核心结论：Python 的 list 就是栈

你不需要自己写一个 `Stack` 类。Python 的 `list` 从尾部做 `append` 和 `pop` 都是 **O(1)**，天然就是栈。

为什么是 O(1)？因为 CPython 的 list 底层是一块**连续内存（动态数组）**，它会在末尾预留空位（over-allocate）。只要没超过预留容量，`append` 只是往已知地址写一个数、长度加一；`pop()` 只是长度减一。两者都不需要搬动其他元素。

```python
stack = []
for i in range(5):
    stack.append(i)          # push
print(stack)                 # [0, 1, 2, 3, 4]
while stack:
    print(stack.pop(), end=' ')   # 4 3 2 1 0  ← 后进先出
```

输出：`4 3 2 1 0`。注意这个顺序是反的——这是栈最本质的特征，也是很多初学者第一次调试时"为什么我的结果倒过来了"的答案。

## 时间复杂度

| 操作 | 时间复杂度 | 说明 |
|---|---|---|
| `append(x)`（push） | O(1) 均摊 | 极少情况下触发扩容，均摊后仍 O(1) |
| `pop()`（无参数） | O(1) | 只减长度，不搬数据 |
| `s[-1]`（peek） | O(1) | 下标访问 |
| `s.pop(0)` | **O(n)** | 弹头部，要搬动 n-1 个元素 |

> **关键提醒**：`append` / `pop` **不带参数**才是 O(1)。`pop(0)` 是弹头部，O(n)。这是本课最容易踩的坑。

## 翻车现场：`pop(0)` 让 O(1) 变成 O(n)

```python
# WRONG
stack = [1, 2, 3]
stack.pop(0)    # 想"弹出第一个"，结果是 1，栈变成 [2, 3]
                # 但底层把所有元素往前挪了一位
```

这个写法有两重错：一是语义错（它弹的是最早进来的，是队列行为，不是栈）；二是性能错（O(n)）。栈要弹，永远 `pop()`。

## 翻车现场：空栈上 `pop()` 直接抛异常

```python
# WRONG
s = []
s.pop()          # IndexError: pop from empty list
s[-1]            # IndexError: list index out of range
```

每次 `pop` 或 `peek` 前都要判断栈非空。写成 `while stack:` 比 `while len(stack) > 0:` 更地道。

## 用 collections.deque 做栈更快吗？

`deque` 的 `append` / `pop` 也是 O(1)，但它是**双向链表**实现，在内存上不连续。实测表明：纯栈场景（只从一端进出），`list` 比 `deque` **更快**——因为连续内存的缓存局部性更好。

`deque` 的真正优势是**两端都能 O(1) 操作**，比如实现队列 `popleft()`。所以结论很简单：

> **只当栈用 → `list`。需要左端出队 → `deque`。**

## 用类包装一下更清晰

想让代码读起来更像栈，可以包一层：

```python
class Stack:
    def __init__(self):
        self._d = []
    def push(self, x):
        self._d.append(x)
    def pop(self):
        if not self._d:
            raise IndexError("pop from empty stack")
        return self._d.pop()
    def peek(self):
        if not self._d:
            raise IndexError("peek from empty stack")
        return self._d[-1]
    def __bool__(self):
        return bool(self._d)
    def __len__(self):
        return len(self._d)

s = Stack()
s.push(1); s.push(2)
print(s.pop())    # 2
print(len(s))     # 1
```

这一层封装的价值在于：**把"空栈该怎么处理"集中在类里**，调用方不会再到处写 `if stack`。面试和工程里都更推荐这种写法。

## 栈能解决什么问题

栈擅长处理**"最近相关"**的问题——当前元素只关心离它最近的那个。典型场景：

- **括号匹配**：遇到 `)` 要找最近的未匹配 `(`
- **下一个更大元素**：每个数找它右边第一个比它大的数
- **撤销 / 回退**：Ctrl+Z 回退最后一步
- **表达式求值**：先算最内层的括号
- **递归实现**：函数调用本身就用栈

## 小结

- 栈 = 后进先出（LIFO），只有 push / pop / peek 三个核心操作
- Python 的 `list` 就是栈，`append` 是 push，无参 `pop()` 是 pop，都是 O(1)
- O(1) 来自底层连续内存 + 预留容量，`append`/`pop` 都不搬动元素
- 永远别用 `pop(0)` 当栈用——语义是队列、复杂度是 O(n)
- 空栈上 `pop()` / `[-1]` 会 `IndexError`，每次都要先判空
- 只做栈 → `list`；要两端 O(1) → `deque`
- 栈的本质优势是处理"最近相关"问题
