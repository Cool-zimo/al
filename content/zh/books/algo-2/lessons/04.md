# 虚拟头节点 dummy：为什么它能消灭「删除头节点」的特判

> dummy 节点是链表题的第一个套路，也是最重要的一条：它能让「删除头节点」这种烦人的特判彻底消失。


## 问题回顾：删除头节点总要特判

上一课我们写删除函数，开头总是两行：

```python
if head is None:
    return head
if head.val == target:
    return head.next
```

第二行就是特判——因为头节点没有前驱。只要函数可能删头，就得写它。**特判多一处，出错多一分。**


## dummy 的思路：凭空造一个假头

在真正的头前面，人为加一个**虚拟头节点 dummy**，让真正的头也有「前驱」。

```
dummy → 1 → 2 → 3 → None
  ↑
dummy.next 就是真正的头
```

```python
dummy = ListNode(0)
dummy.next = head      # 把真头挂在 dummy 后面
prev = dummy           # 前驱从 dummy 起步
cur = head
while cur:
    if cur.val == target:
        prev.next = cur.next   # 统一处理，删头也不例外
        break
    prev = cur
    cur = cur.next
return dummy.next      # 返回真正的头（可能没变，也可能被删了）
```

**关键**：现在不管删谁，都是 `prev.next = cur.next`。删头时，`prev` 就是 `dummy`，`dummy.next = head.next`，完美。


## 完整代码对比

有 dummy 的版本：

```python
def delete_all(head, target):
    dummy = ListNode(0, head)
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        else:
            prev = cur
        cur = cur.next
    return dummy.next

head = build([1, 1, 2, 3, 1])
print(to_list(delete_all(head, 1)))    # [2, 3]
```

注意这里删的是**所有**等于 target 的节点。`prev` 只有在「没删」的时候才后移——删了的话前驱不变，因为下一个节点还得由同一个前驱来判。


## 翻车现场：删多个节点时 prev 跟着 cur 一起走，漏删

```python
# WRONG
def delete_all(head, target):
    dummy = ListNode(0, head)
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        prev = cur          # 不管删没删都后移
        cur = cur.next
    return dummy.next
```

```text
head=[1,1,2], target=1
结果：[1,2] —— 第一个 1 删了，第二个 1 漏了。
```

原因：删掉第一个 `1` 之后，`prev` 不该后移（它还要负责判断新的下一个节点）。**prev 只在「没删节点」时后移。**


## dummy 的通用价值

dummy 不只是用来删头。凡是「可能改头」的题，都用它：

| 场景 | 不用 dummy | 用 dummy |
|---|---|---|
| 删除节点 | 要特判头 | 无特判 |
| 反转链表 | 要特判空链 | 直接写 |
| 合并有序链表 | 要处理某条先空 | 优雅 |

一句话：**涉及修改链表结构、且可能改头，就先写 `dummy = ListNode(0, head)`。**


## 小结

- - dummy 是一个挂在真头前面的假节点，让真头也有了前驱
- - 有了 dummy，删除统一成 `prev.next = cur.next`，删头不用特判
- - 删多个节点时，**只有没删 prev 才后移**，否则会漏删
- - 凡可能改头的结构题，先写 dummy，是链表题的通用起手式

```quiz
- 让头节点也有了前驱，从而把「删除/修改头节点」这类操作统一成和其他节点一样的写法，省掉特判
- 能减少链表占用的内存
- 能加快链表的遍历速度
- 能把单向链表变成双向链表
answer: 0
explain: dummy 本身不存有效数据，它唯一的作用是当真头的前驱，使所有节点（包括头）都处在「有前驱」的统一框架下。于是删除、反转、插入的写法可以共用一套逻辑，不必为头节点单独写一个分支。它不会减少内存、不会加速遍历，更不是双向链表。
```
