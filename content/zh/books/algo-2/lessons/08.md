# 合并两个有序链表

> 两个已经排好序的链表，合成一个。这是链表题里最常考、也最考验"指针操作基本功"的一题。

## 问题

```
l1: 1 -> 3 -> 5
l2: 2 -> 4 -> 6
结果: 1 -> 2 -> 3 -> 4 -> 5 -> 6
```

注意：不是"把值取出来排序再建新链表"——那是 O(n) 空间且没用到有序这个条件。题目要求**原地拼接节点**。

## 思路

和"合并两个有序数组"一模一样：两个指针分别指着两条链的当前节点，谁小就把谁接到结果上，然后那个指针往后挪。

```python
def merge_two_lists(l1, l2):
    dummy = ListNode(0)
    cur = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            cur.next = l1
            l1 = l1.next
        else:
            cur.next = l2
            l2 = l2.next
        cur = cur.next
    cur.next = l1 if l1 else l2      # 剩下的一段直接接上
    return dummy.next
```

**三件事值得单独说**：

### 1. dummy 节点消灭了"第一个节点是谁"的特判

没有 dummy 的话，你得先单独决定结果链表的头：

```python
# 啰嗦版
if l1.val <= l2.val:
    head = l1; l1 = l1.next
else:
    head = l2; l2 = l2.next
cur = head
...
```

有了 dummy，`head` 就是一个固定的哨兵，最后返回 `dummy.next`。**这是链表题里最高频的技巧。**

### 2. 循环结束后不用一个个接

`while l1 and l2` 退出时，至少有一个是 `None`。但另一个**剩下的整段本来就是有序的**，而且都比已合并的部分大——所以直接 `cur.next = l1 if l1 else l2` 整段挂上去。

这不是偷懒，是因为链表本身就是"串好的"，挂一次就够。

### 3. `cur = cur.next` 不能忘

忘了会怎样？`cur` 一直停在 dummy 上，每次 `cur.next = l1` 都是覆盖同一个位置，最后只剩最后一个节点：

```python
# WRONG
def merge_bad(l1, l2):
    dummy = ListNode(0)
    cur = dummy
    while l1 and l2:
        if l1.val <= l2.val:
            cur.next = l1
            l1 = l1.next
        else:
            cur.next = l2
            l2 = l2.next
        # 忘了 cur = cur.next
    return dummy.next
```

结果链表只有 1 个节点，其余全丢了。

## 逐帧手跑

```
l1: 1 -> 3 -> 5
l2: 2 -> 4 -> 6

初始: dummy -> None,  cur=dummy
1<=2: cur.next=1, l1=3, cur=1      dummy->1
3>2 : cur.next=2, l2=4, cur=2      dummy->1->2
3<=4: cur.next=3, l1=5, cur=3      dummy->1->2->3
5>4 : cur.next=4, l2=6, cur=4      dummy->1->2->3->4
5<=6: cur.next=5, l1=None, cur=5   dummy->1->2->3->4->5
退出循环: cur.next = l2 (=6)
最终: 1->2->3->4->5->6
```

## 递归写法

同一件事，用递归写出来极短：

```python
def merge_two_lists_rec(l1, l2):
    if not l1:
        return l2
    if not l2:
        return l1
    if l1.val <= l2.val:
        l1.next = merge_two_lists_rec(l1.next, l2)
        return l1
    else:
        l2.next = merge_two_lists_rec(l1, l2.next)
        return l2
```

**但递归版的空间是 O(n)**——调用栈深度等于总节点数。节点多时会 `RecursionError`。面试可以写，工程上用迭代版。

## 复杂度和取舍

| 写法 | 时间 | 空间 | 备注 |
|---|---|---|---|
| 迭代 + dummy | O(n+m) | **O(1)** | 推荐 |
| 递归 | O(n+m) | O(n+m) | 栈深，长链表会炸 |
| 取出来排序重建 | O((n+m)log(n+m)) | O(n+m) | 没用到有序条件，最差 |

## 翻车现场：用 == 比较节点而不是值

```python
# WRONG
if l1 <= l2:          # TypeError: '<=' not supported between instances of 'ListNode' and 'ListNode'
```

必须比较 `.val`。除非你给 ListNode 实现了 `__lt__`，否则 Python 不知道两个节点谁大谁小。

## 翻车现场：把 `l1` 直接赋值给 `cur` 再移动

```python
# WRONG
cur = l1          # 本意是"接上 l1"，实际是把 cur 指向了 l1 本身
l1 = l1.next
```

这样 `dummy.next` 从来没被设置过，返回的还是那个孤零零的 dummy。正确做法是 `cur.next = l1` 然后 `cur = cur.next`。

## 扩展到 K 条链表

合并 K 条有序链表，最简单的做法是两两合并：

```python
def merge_k(lists):
    if not lists:
        return None
    res = lists[0]
    for l in lists[1:]:
        res = merge_two_lists(res, l)
    return res
```

复杂度 O(kN)（k 是链表数，N 是总节点数）。更优的做法是**分治合并**（两两配对，递归）或者用**堆**，能做到 O(N log k)。这属于进阶，第 6 章会回来讲分治。

## 小结

- 双指针各指一条链，谁小接谁，`cur` 跟着往前走
- **dummy 哨兵节点**消灭"头节点是谁"的特判，最后返回 `dummy.next`
- 循环退出后把剩下一整段直接挂上，不用一个个接
- 千万别忘 `cur = cur.next`
- 比较的是 `.val`，不是节点对象
- 迭代版 O(1) 空间；递归版好看但栈深 O(n)

```quiz
type: choice
exam: true
q: 合并两个有序链表时，为什么常用一个 dummy（虚拟头）节点？
options:
- 让代码跑得更快
- 免掉"结果链表的第一个节点是谁"的特判，最后返回 dummy.next 即可
- 为了不修改原链表
- dummy 是必须的，没有它写不出来
answer: 1
explain: 没有 dummy 就得先单独判断第一次该接 l1 还是 l2、并把结果的 head 记下来，之后再进入循环，两套逻辑。dummy 把"接第一个"和"接后续"统一成同一行 cur.next = x。它不是性能技巧，是消除分支。
```
