# 队列与 deque：FIFO 的艺术

> 队列就是"排队"——先来先服务。但 Python 的 list 用来做队列，会在最意想不到的地方踩进 O(n) 的坑。`collections.deque` 才是正解。

## 问题

队列（Queue）是一种**先进先出**（FIFO, First In First Out）的数据结构。就像食堂排队打饭：先来的先打到，后来的排后面。

核心操作只有两个：

- **入队 enqueue**：从队尾加入一个元素
- **出队 dequeue**：从队首取走一个元素

```python
# 理想中的队列用法
q = []
q.append("小明")      # 入队：小明排队
q.append("小红")      # 入队：小红排在小明后面
q.append("小刚")      # 入队：小刚排在最后
first = q.pop(0)      # 出队：小明先走 → "小明"
```

看起来没问题，对吧？**但是**，`q.pop(0)` 这一步的代价，远比你想的大。

## 为什么 `list.pop(0)` 是 O(n)

Python 的 list 底层是**动态数组**，元素在内存中连续存放。当你 `pop(0)` 时，第 1 个元素被拿走，后面所有元素都要往前挪一格，补上这个空位。

```python
# 一个长度为 n 的 list，pop(0) 之后：
# 原来: [a0, a1, a2, a3, ..., a(n-1)]
# 之后: [a1, a2, a3, ..., a(n-1), ?]
# 所有 n-1 个元素都要移动一次 → O(n)

# 如果你做了 n 次 pop(0)，总代价就是 O(n²)
q = list(range(10000))
for _ in range(len(q)):
    q.pop(0)   # 每次都要搬动剩下的所有元素
# 总计移动：9999 + 9998 + ... + 1 ≈ 5千万次操作
```

**这就是为什么用 list 当队列，n 稍大就会 TLE。**

## `collections.deque`：双向队列

`deque`（double-ended queue）是 Python 标准库专门为两端操作优化的数据结构。它的 `popleft()` 和 `append()` 都是 **O(1)**。

```python
from collections import deque

q = deque()
q.append("小明")       # 队尾入队 → O(1)
q.append("小红")       # O(1)
q.append("小刚")       # O(1)
first = q.popleft()    # 队首出队 → O(1)，"小明"
print(first)           # 小明
print(q)               # deque(['小红', '小刚'])
```

deque 的底层是一个**双向链表 + 分块数组**的混合结构，头尾操作都不需要搬运元素。这就是为什么它能做到 O(1)。

## 翻车现场：用 list.pop(0) 当队列

```python
# WRONG：用 list 模拟队列
q = []
q.append(1)
q.append(2)
q.append(3)
while q:
    print(q.pop(0))   # 每次 pop(0) 都是 O(n)
```

代码能跑、结果也对，但**性能是 O(n²)**。当 n = 10⁵ 时，这个差别就是"100ms"和"10s"的差距。

**反例验证**：

```python
import time
from collections import deque

n = 100000

# list 版本
q1 = list(range(n))
t0 = time.time()
while q1:
    q1.pop(0)
t1 = time.time()

# deque 版本
q2 = deque(range(n))
t2 = time.time()
while q2:
    q2.popleft()
t3 = time.time()

print(f"list.pop(0) 耗时: {t1-t0:.3f}s")
print(f"deque.popleft() 耗时: {t3-t2:.3f}s")
# list 版本可能耗时数秒，deque 版本几乎瞬间完成
```

**结论：只要你的语义是"队列"，就用 `deque`，不要犹豫。**

## 翻车现场：搞混 append 和 appendleft

```python
from collections import deque

q = deque([1, 2, 3])
q.appendleft(0)    # 从左边加入 → deque([0, 1, 2, 3])
q.append(4)        # 从右边加入 → deque([0, 1, 2, 3, 4])
q.pop()            # 从右边弹出 → 4
q.popleft()        # 从左边弹出 → 0
```

这四种操作要分清：

| 操作 | 位置 | 时间复杂度 |
|---|---|---|
| `append(x)` | 右端入队 | O(1) |
| `appendleft(x)` | 左端入队 | O(1) |
| `pop()` | 右端出队 | O(1) |
| `popleft()` | 左端出队 | O(1) |

**队列的标准用法是 `append()` + `popleft()`**（右进左出 = FIFO）。如果你写成 `append()` + `pop()`，那它就是一个栈（LIFO），不是队列。

## deque 的其他常用操作

```python
from collections import deque

q = deque([1, 2, 3])

# 查看队首（不弹出）
print(q[0])        # 1，O(1)

# 查看队尾
print(q[-1])       # 3，O(1)

# 判断是否为空
print(len(q) == 0)  # False

# 旋转
q.rotate(1)        # 右旋1位 → deque([3, 1, 2])
q.rotate(-1)       # 左旋1位 → deque([1, 2, 3])

# 限制最大长度（超了自动丢掉另一端）
dq = deque(maxlen=3)
dq.append(1)       # deque([1])
dq.append(2)       # deque([1, 2])
dq.append(3)       # deque([1, 2, 3])
dq.append(4)       # deque([2, 3, 4])，最左的1被丢掉
```

`maxlen` 非常适合做"滑动窗口"类的需求——自动维护固定大小的窗口。

## 翻车现场：遍历时修改 deque

```python
# WRONG：遍历时一边 pop 一边 append
q = deque([1, 2, 3])
for x in q:
    q.append(x * 10)   # 无限循环！每次迭代都往队尾加新元素
```

Python 的 for 循环会一直发现"还有新元素"，导致**无限循环**。正确的做法：

```python
# RIGHT：先记录长度，只处理当前已有的元素
q = deque([1, 2, 3])
for _ in range(len(q)):
    x = q.popleft()
    q.append(x * 10)
print(q)   # deque([10, 20, 30])
```

或者干脆不用 deque 遍历，改用 while 循环控制边界。

## 队列的典型应用场景

1. **BFS 广度优先搜索**：队列天然记录"当前层"的节点
2. **生产者-消费者模型**：一方入队，一方出队
3. **消息队列 / 任务调度**：先提交的任务先执行
4. **缓冲区**：如键盘输入缓冲区

## 复杂度对比总结

| 操作 | list 队列 | deque |
|---|---|---|
| 队尾入队 | O(1) | O(1) |
| 队首出队 | **O(n)** | **O(1)** |
| 随机访问 `q[i]` | O(1) | O(1)（较慢） |
| 空间开销 | 小 | 略大 |

**一句话记住：语义是 FIFO → deque；语义是随机访问 → list。**

## 小结

- 队列是 FIFO 结构：先入队的元素先出队
- Python list 的 `pop(0)` 是 **O(n)**，因为它要搬动所有剩余元素
- `collections.deque` 的 `popleft()` 是 **O(1)**，队列首选
- 标准队列用法：`append()` 入队 + `popleft()` 出队
- 遍历 deque 时修改它会无限循环，先记录长度再操作
- `maxlen` 参数可以让 deque 自动维护固定窗口
