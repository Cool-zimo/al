# Python 的 dict 与 set：底层是哈希表

> Python 的 dict 和 set 是哈希表的"亲儿子"。为什么 3.7+ 的 dict 突然有序了？为什么 list 不能当 key？答案都在哈希表里。

## dict 就是一张哈希表

Python 的 `dict`（字典）底层就是一个**哈希表**。这就是它能 O(1) 查找、插入、删除的原因。

```python
d = {"name": "张三", "age": 18}
print(d["name"])   # "张三"，O(1)
d["score"] = 95    # 插入，O(1) 均摊
del d["age"]       # 删除，O(1) 均摊
```

上一课我们手写了简易哈希表，Python 的 dict 做的事情本质上一样，只是：
- 哈希函数更强大（SipHash，防哈希碰撞攻击）
- 用**开放寻址**解决冲突
- 自动扩容（容量始终保持 2 的幂次）
- 内存布局做了优化

## set 也是哈希表

`set` 底层同样是一张哈希表——只是**只存 key，不存 value**。

```python
s = {1, 2, 3, 2, 1}
print(s)   # {1, 2, 3}，自动去重

# set 的核心操作都是 O(1)
3 in s        # True，O(1) 查找
s.add(4)      # O(1)
s.remove(1)   # O(1)
```

**为什么 set 能去重？** 因为它就是哈希表，相同的 key 算出来是同一个位置，自然只存一份。

**为什么 set 能 O(1) 判断存在？** 因为它就是哈希表，`in` 操作就是一次 hash + 探测。

## 翻车现场：用 list 当 dict 的 key

```python
# WRONG：list 是不可哈希的
d = {}
d[[1, 2, 3]] = "hello"
```

报错：

```
TypeError: unhashable type: 'list'
```

**为什么 list 不能当 key？** 因为 list 是**可变的**——如果 list 的内容变了，它的 hash 值也应该变，但哈希表依赖"key 的 hash 永远不变"这个前提。

```python
# 想象一下如果 list 可以当 key 会怎样
k = [1, 2, 3]
d = {k: "hello"}
k.append(4)     # k 变了
d[k]            # hash 变了，找不到 → 哈希表彻底混乱
```

**能当 key 的类型必须是不可变的（immutable）**：
- ✅ `int`, `float`, `str`, `bool`
- ✅ `tuple`（前提是里面没有可变元素）
- ✅ `frozenset`
- ✅ 自定义类（默认用 id 做 hash，不推荐）
- ❌ `list`, `dict`, `set`

```python
# RIGHT：用 tuple 代替 list 当 key
d = {}
d[(1, 2, 3)] = "hello"   # tuple 不可变，可以当 key
print(d[(1, 2, 3)])      # "hello"

# 嵌套 tuple 也可以
d2 = {(1, 2): "a", (3, 4): "b"}
```

**但 tuple 里不能有 list！**

```python
# WRONG：tuple 里包含可变元素
d = {(1, [2, 3]): "hello"}
# TypeError: unhashable type: 'list'
```

## 翻车现场：以为 dict 无序而写错依赖顺序的代码

```python
# 在 Python 3.6 及之前：
d = {"c": 3, "a": 1, "b": 2}
print(list(d.keys()))   # 顺序不确定！可能是 ['a', 'c', 'b'] 或其他
```

很多老代码写了这样的逻辑：

```python
# WRONG：依赖 dict 的遍历顺序
config = {"host": "localhost", "port": 8080, "debug": True}
keys = list(config.keys())
first_key = keys[0]
# Python 3.6 及之前：first_key 可能是任意 key
# Python 3.7+：first_key 一定是 "host"
```

**Python 3.7+ 保证了什么？** Python 3.7 起，dict 的遍历顺序**等于插入顺序**（这是语言规范，不只是 CPython 实现细节）。

```python
# Python 3.7+
d = {}
d["first"] = 1
d["second"] = 2
d["third"] = 3
print(list(d.keys()))   # ['first', 'second', 'third']  guaranteed
```

**但注意：这不等于"按 key 排序"！**

```python
d = {}
d["zebra"] = 1
d["apple"] = 2
d["monkey"] = 3
print(list(d.keys()))   # ['zebra', 'apple', 'monkey']  按插入顺序，不是字母序！
```

如果你需要排序，必须显式调用 `sorted()`：

```python
d = {"zebra": 1, "apple": 2, "monkey": 3}
for k in sorted(d.keys()):
    print(k, d[k])
# apple 2
# monkey 3
# zebra 1
```

## 为什么 Python 3.7+ 的 dict 有序了

**核心改动：用了一个额外的"索引数组"记录插入顺序。**

```
Python 3.6 之前：
  hash table: [entry0, None, entry1, None, entry2, None, None, None]
  遍历时要跳过 None → 慢

Python 3.7+：
  hash table: [entry0, entry1, entry2, None, None, ...]
  indices:    [0, 2, 1, ...]  ← 记录插入顺序
  遍历 indices 即可按序输出
```

**实际效果**：
- 遍历从"跳过空洞"变成"按 indices 顺序读"
- 牺牲了少量额外内存（一个 indices 数组），换来更快的遍历和确定的顺序
- Python 3.6 在 CPython 中已实现但未写入规范，3.7 正式纳入语言规范

**insertion-order preservation 的代价**：

```python
import sys
# 有序 dict 比无序版本多了一个 indices 数组
d = {i: i for i in range(1000)}
print(sys.getsizeof(d))  # 比纯哈希表多 ~8KB（1000 个索引 × 8 字节）
```

**一句话：Python 3.7+ 的 dict 是用空间换顺序保证。**

## 翻车现场：dict 的 key 比较用的是 __eq__，不是 is

```python
# 两个不同的对象，但 __eq__ 返回 True，就是同一个 key
class Number:
    def __init__(self, value):
        self.value = value
    def __eq__(self, other):
        return self.value == other.value
    def __hash__(self):
        return hash(self.value)

a = Number(42)
b = Number(42)
print(a is b)        # False，不是同一个对象
print(a == b)        # True，值相等

d = {a: "answer"}
print(d[b])          # "answer"！因为 hash 相同且 == 为 True
```

**规则：dict 判断两个 key 是否相同 = `hash(a) == hash(b) and a == b`**

这也意味着：

```python
# WRONG：__eq__ 返回 True 但 __hash__ 不同 → 违反约定
class Bad:
    def __eq__(self, other):
        return True
    def __hash__(self):
        return id(self)   # 每个实例 hash 不同

b1 = Bad()
b2 = Bad()
d = {b1: 1}
print(d[b2])   # KeyError! 虽然 b1 == b2，但 hash 不同
```

**Python 的检查**：

```python
class Broken:
    def __eq__(self, other):
        return True
    # 没有 __hash__ → Python 会设 __hash__ = None → 不可哈希

b = Broken()
d = {b: 1}   # TypeError: unhashable type: 'Broken'
```

**如果你重写了 `__eq__` 但没重写 `__hash__`，Python 会直接让这个类的实例不可哈希。** 这是 Python 帮你踩的刹车。

## dict 和 set 常用操作一览

```python
# dict
d = {"a": 1, "b": 2}

d.get("c", 0)        # 0，不存在返回默认值，不会 KeyError
d.setdefault("c", 0) # 0，如果 key 不存在就设置默认值
d.update({"c": 3})   # 批量更新
d.pop("a")           # 1，弹出 key 并返回 value
d.keys()             # 视图对象，动态反映 dict 变化
d.values()           # 视图对象
d.items()            # 视图对象，遍历用

# set
s = {1, 2, 3}
s | {3, 4}           # 并集 {1, 2, 3, 4}
s & {2, 3, 4}        # 交集 {2, 3}
s - {1, 2}           # 差集 {3}
s ^ {3, 4}           # 对称差 {1, 2, 4}

{1, 2} <= {1, 2, 3}  # 子集判断 True
```

**视图对象（view）vs 列表**：

```python
d = {"a": 1, "b": 2}
keys = d.keys()      # dict_keys 视图，不是 list！
print(keys)          # dict_keys(['a', 'b'])
d["c"] = 3
print(keys)          # dict_keys(['a', 'b', 'c'])  动态更新了！

# 如果需要 list，显式转换
key_list = list(d.keys())
```

## 翻车现场：dict.get() 的默认值和 setdefault 的坑

```python
# WRONG：get 的默认值不会写入 dict
d = {}
value = d.get("key", [])
value.append(1)
print(d)          # {}  dict 没变！value 是一个新的空列表，但没存回 dict

# RIGHT：用 setdefault
d = {}
d.setdefault("key", []).append(1)
print(d)          # {'key': [1]}

# 或者用 defaultdict
from collections import defaultdict
d = defaultdict(list)
d["key"].append(1)
print(d)          # defaultdict(<class 'list'>, {'key': [1]})
```

**`setdefault` 的陷阱：默认值每次都创建一个新的对象**

```python
# WRONG：在循环里用可变默认值
d = {}
for i in range(3):
    d.setdefault("key", []).append(i)
print(d)   # {'key': [0, 1, 2]}  ✅ 这是对的

# 但如果你手动写：
d = {}
for i in range(3):
    if "key" not in d:
        d["key"] = []   # 只有第一次创建
    d["key"].append(i)
print(d)   # {'key': [0, 1, 2]}  ✅ 也对
```

区别在于 `setdefault` 每次都求值默认值表达式：

```python
def make_list():
    print("创建新列表")
    return []

d = {}
d.setdefault("a", make_list())  # 打印 "创建新列表"
d.setdefault("a", make_list())  # 又打印 "创建新列表"！虽然不会用到，但表达式已求值
```

**如果创建默认值很耗时，用 `defaultdict` 或先判断 key 是否存在。**

## 复杂度速查表

| 操作 | dict | list | set |
|---|---|---|---|
| 查找 | O(1) | O(n) | O(1) |
| 插入 | O(1) 均摊 | O(1) 尾部 / O(n) 中间 | O(1) 均摊 |
| 删除 | O(1) 均摊 | O(n) | O(1) 均摊 |
| 遍历 | O(n) | O(n) | O(n) |
| 取最大/最小 | O(n) | O(n) / O(1) 排序后 | O(n) |

**核心建议**：
- 需要"快速查找/去重" → `set`
- 需要"键值映射" → `dict`
- 需要"保持插入顺序 + 映射" → `dict`（3.7+ 天然有序）
- 需要"排序遍历" → 用 `sorted(dict.items())`

## 小结

- Python 的 dict 和 set 底层都是哈希表，核心操作 O(1)
- set 只存 key 不存 value，天然去重
- list、dict、set 不可哈希（可变），不能当 dict 的 key
- tuple 可哈希的前提是内部没有可变元素
- Python 3.7+ dict 保证插入顺序（用 indices 数组记录），但不是按 key 排序
- dict 判断 key 相同 = `hash(a) == hash(b) and a == b`
- 重写 `__eq__` 必须同时重写 `__hash__`，否则 Python 会让实例不可哈希
- `get()` 的默认值不会写入 dict，`setdefault()` 会；耗时默认值用 `defaultdict`
