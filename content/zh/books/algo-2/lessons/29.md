# 分治：归并排序的递归写法

> 分治（Divide and Conquer）是递归最自然的应用场景。它只有三步：分、治、合。归并排序把这三步演得淋漓尽致，也是理解 O(n log n) 怎么来的最佳教材。

## 分治三步走

分治的核心思想：

1. **分（Divide）**：把大问题拆成两个或多个小问题。
2. **治（Conquer）**：递归地解决每个小问题。
3. **合（Combine）**：把小问题的解合并成大问题的解。

**注意"治"这一步用的就是递归本身**——所以分治天然就是递归。区别在于：分治要求"拆分是均匀、独立的"，每个子问题互不干扰。

## 归并排序：一个标准的分治算法

归并排序（Merge Sort）的步骤：

- **分**：把数组从中间切成两半。
- **治**：递归地对左右两半分别排序。
- **合**：把两个**已排好序**的半段合并成一个有序数组。

```python
def mergesort(nums):
    # 终止条件：长度为 0 或 1 的数组天然有序
    if len(nums) <= 1:
        return nums
    
    mid = len(nums) // 2
    left = mergesort(nums[:mid])     # 治：左半
    right = mergesort(nums[mid:])    # 治：右半
    return merge(left, right)        # 合：合并
```

**注意这个结构有多干净**：分是 `mid = len(nums) // 2`，治是两次递归调用，合是 `merge`。三步走，一步不多一步不少。

## 合并两个有序数组：merge 的实现

合并是归并排序的"灵魂"。前提：**左右两半都已经排好序了**。

```python
def merge(left, right):
    result = []
    i = j = 0
    # 双指针：每次取两个指针里较小的那个
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    # 把剩下的直接接上去
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

**用两个指针 `i`、`j` 各指着一段的开头，每次挑小的那个追加。** 因为两边都有序，挑出来的顺序就是全局有序的。

举个具体的例子，`merge([1, 4, 7], [2, 3, 6])`：

```
i→1  4  7   ← left
j→2  3  6   ← right

第1轮：left[0]=1 vs right[0]=2 → 取1, i=1
第2轮：left[1]=4 vs right[0]=2 → 取2, j=1
第3轮：left[1]=4 vs right[1]=3 → 取3, j=2
第4轮：left[1]=4 vs right[2]=6 → 取4, i=2
第5轮：left[2]=7 vs right[2]=6 → 取6, j=3 (right 用完)
剩下的：把 left[2:]=7 接上去

结果：[1, 2, 3, 4, 6, 7]
```

**`merge` 的复杂度是 O(n)**：每个元素只被比较、追加一次，两个指针一共走 n 步。

## 完整跑一遍

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

def mergesort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = mergesort(nums[:mid])
    right = mergesort(nums[mid:])
    return merge(left, right)

print(mergesort([38, 27, 43, 3, 9, 82, 10]))
# [3, 9, 10, 27, 38, 43, 82]
```

**看递归树的分层**，以 `[38, 27, 43, 3, 9, 82, 10]` 为例：

```
第1层（合）：merge([3,27,38,43], [9,10,82])
第2层（治）：merge([27,38], [3,43])    merge([9,82], [10])
第3层（治）：merge([38],[27])  merge([43],[3])  merge([82],[9])  merge([10])
第4层（分）：... 长度<=1，直接返回
```

**每一层所有的 merge 加起来，处理的元素总数是 n。** 因为每一层合起来刚好覆盖原数组的每个元素一次。

## 翻车现场：merge 时用了 > 而不是 <=，不稳定了

```python
# WRONG：把 <= 写成 >，合并顺序出错
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] > right[j]:    # ← 应该是 <=
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

这个例子恰好用 `>` 也"能跑"，但**顺序反了**——结果会变成降序，或者更糟，和你预期的不一致。而如果你用的是 `>=`：

```python
if left[i] >= right[j]:   # ← 用了 >=
```

**结果是"不稳定排序"**：相等元素的相对顺序可能被打乱。归并排序本应是**稳定排序**（相等元素保持原顺序），用 `<=` 才能保证稳定性。

```python
pairs = [("a", 2), ("b", 1), ("c", 2)]
# 按第二个元素排序
# 稳定排序结果：[("b",1), ("a",2), ("c",2)]  ← ("a","c") 保持原顺序
# 不稳定结果：[("b",1), ("c",2), ("a",2)]    ← 顺序乱了
```

**稳定排序在按多个字段排序时很重要**：先按成绩排、再按姓名排，如果排序稳定，成绩相同的记录会保持上一步姓名排好的顺序。

## O(n log n) 是怎么来的

这是本课的核心推导。**分两步看：**

**第一步：有几层？** 每次都对半分，从 n 到 n/2 到 n/4……到 1。这是 log n 层。

```
n → n/2 → n/4 → ... → 1   一共 log n 层
```

**第二步：每层的工作量是多少？** 每层所有的 merge 加起来处理的元素总数 = n（因为每一层的子数组合起来就是原数组）。

```
第1层：1 次 merge，处理 n 个元素     → n
第2层：2 次 merge，各处理 n/2 个     → n
第3层：4 次 merge，各处理 n/4 个     → n
...
总共：log n 层 × 每层 n = n log n
```

**所以归并排序的时间复杂度是 O(n log n)。**

对比一下：

| 排序 | 最好 | 平均 | 最坏 | 空间 |
|---|---|---|---|---|
| 冒泡/插入 | O(n) | O(n²) | O(n²) | O(1) |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) |

**归并排序的可贵之处：最坏情况也是 O(n log n)。** 快排在"数组已经有序"这种倒霉输入下会退化成 O(n²)，归并排序不会——它对任何输入都是 n log n。代价是**需要 O(n) 的额外空间**来存放合并结果。

## 翻车现场：忘了合并，只做了"分"

```python
# WRONG：只递归，不 merge
def mergesort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    mergesort(nums[:mid])      # ← 排了，但结果丢了
    mergesort(nums[mid:])      # ← 排了，但结果丢了
    return nums                # ← 原样返回，啥也没发生
```

跑一下：

```python
print(mergesort([3, 1, 2]))   # [3, 1, 2] 原样返回！
```

**左右两半确实被排好序了，但"合"这一步没做，排好的结果被你扔掉了。** 递归的返回值必须被用上——要么 merge，要么返回。这是递归改写时最容易犯的"丢了结果"错误。

正确写法：`return merge(mergesort(nums[:mid]), mergesort(nums[mid:]))`。**递归的返回值不是装饰，是数据流。**

## 翻车现场：切片拷贝，空间翻倍

```python
# WRONG：每层递归都切片，产生大量临时列表
def mergesort(nums):
    if len(nums) <= 1:
        return nums
    mid = len(nums) // 2
    left = mergesort(nums[:mid])   # 切片拷贝，O(n) 额外空间
    right = mergesort(nums[mid:])
    return merge(left, right)
```

**这不是 bug，是性能问题。** `nums[:mid]` 和 `nums[mid:]` 各产生一个新列表，每层递归都要 O(n) 的空间来存拷贝。总空间是 O(n log n) 而不是理想的 O(n)。

工程级的归并排序会**预先分配一个临时数组**，用索引区间 `[l, r]` 来表示"这一段"，避免反复拷贝：

```python
def mergesort_inplace(nums):
    tmp = [0] * len(nums)
    
    def sort(l, r):
        if r - l <= 1:
            return
        mid = (l + r) // 2
        sort(l, mid)
        sort(mid, r)
        # 合并 nums[l:r] 到 tmp，再拷回 nums
        i, j, k = l, mid, l
        while i < mid and j < r:
            if nums[i] <= nums[j]:
                tmp[k] = nums[i]; i += 1
            else:
                tmp[k] = nums[j]; j += 1
            k += 1
        while i < mid:
            tmp[k] = nums[i]; i += 1; k += 1
        while j < r:
            tmp[k] = nums[j]; j += 1; k += 1
        for i in range(l, r):
            nums[i] = tmp[i]
    
    sort(0, len(nums))
    return nums
```

**这种写法只用一个 tmp 数组，空间 O(n)，且避免了递归切片的开销。** 写算法题用切片版没问题，写生产代码要考虑这个。

## 分治的适用条件

不是所有问题都能分治。要能用分治，得满足：

1. **问题能拆**：大问题能分成独立的小问题。
2. **子问题解法相同**：小问题和大问题是同一种问题（递归的递推关系）。
3. **合并可行**：小问题的解能低成本地合并成大问题的解。

**归并排序满足：拆是砍一刀（O(1)），合并是双指针（O(n)）。**

## 小结

- 分治三步走：**分**（切半）、**治**（递归解决子问题）、**合**（合并结果）
- 归并排序：`mid = len(nums)//2` 分；两次递归治；`merge` 合
- `merge` 用双指针，O(n)；归并整体 O(n log n)，最坏情况也是
- **log n 层 × 每层 O(n) = O(n log n)**，这是推导的关键
- 归并是**稳定排序**，要求 merge 里用 `<=` 而非 `<`
- 切片版归并空间 O(n log n)；工程版用索引区间 + 一个 tmp 数组，空间 O(n)
- 分治适用条件：能拆、子问题同构、合并低成本
