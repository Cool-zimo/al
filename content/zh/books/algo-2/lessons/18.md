# BFS 与队列：层序遍历的骨架

> BFS（广度优先搜索）是队列最经典的应用。它的核心思想就一句话："一层一层地向外扩展"。而"一层一层"这件事，恰好就是队列的 FIFO 语义。

## 问题

给你一棵树（或图），要求**按层**访问所有节点：先访问第 1 层的所有节点，再访问第 2 层，以此类推。这就是**层序遍历**（Level Order Traversal）。

如果用 DFS（深度优先），你会一条路走到黑再回头——它不是按层的。BFS 才是正确的工具。

## 核心思路：队列 + 分层扩展

BFS 的骨架非常固定，记住这个模板就够了：

```python
from collections import deque

def bfs(graph, start):
    visited = set([start])           # ★ 标记已访问
    q = deque([start])               # 队列初始化，放入起点

    while q:
        node = q.popleft()           # 取出队首
        print(node, end=" ")         # 处理当前节点
        for neighbor in graph[node]: # 扩展所有邻居
            if neighbor not in visited:
                visited.add(neighbor)
                q.append(neighbor)   # 未访问的邻居入队
```

**为什么用队列？** 因为你要保证"先发现的节点先扩展"。队列的 FIFO 语义天然保证：第 k 层的所有节点一定在第 k+1 层之前被处理。

## 用列表模拟图

## 分层 BFS：知道每一层有哪些节点

很多时候你需要**区分每一层**（比如求树的最小深度、层平均值）。技巧是：**每一轮循环前，先记录当前队列的长度**：

```python
from collections import deque

def bfs_by_level(graph, start):
    visited = set([start])
    q = deque([start])
    level = 0

    while q:
        size = len(q)                # ★ 当前层的节点数
        print(f"第 {level} 层:", end=" ")
        for _ in range(size):        # ★ 只处理当前层的节点
            node = q.popleft()
            print(node, end=" ")
            for neighbor in graph[node]:
                if neighbor not in visited:
                    visited.add(neighbor)
                    q.append(neighbor)
        print()                      # 换行，进入下一层
        level += 1

# 输出：
# 第 0 层: 1
# 第 1 层: 2 3
# 第 2 层: 4 5 6 7
```

**关键**：`size = len(q)` 记录了"这一层有多少个节点"。内层 for 循环只弹出 `size` 个节点，它们全部属于同一层。新加入的节点属于下一层，不会被这次循环处理。

## 翻车现场：忘了 visited 导致死循环

```python
# WRONG：没有 visited 集合
def bfs_no_visited(graph, start):
    q = deque([start])
    while q:
        node = q.popleft()
        print(node, end=" ")
        for neighbor in graph[node]:
            q.append(neighbor)   # 每次都入队，不管有没有访问过
```

以树为例：1→2→1→2→1→2... **无限循环！**

```
graph[1] = [2, 3]
graph[2] = [1, 4, 5]

q = [1]
弹出1 → 入队2,3  → q=[2,3]
弹出2 → 入队1,4,5 → q=[3,1,4,5]  ← 1 又被加回来了！
弹出3 → 入队1,6,7 → q=[1,4,5,1,6,7]  ← 1 又被加了一次！
...
永远不会结束
```

**为什么必须有 visited？** 因为图（和树）中节点之间有回边，不标记已访问就会反复入队同一个节点。BFS 和 DFS 都必须有 visited。

## 翻车现场：先标记 visited 再入队的位置写错

```python
# WRONG：在 for 循环里先 append 再 add
for neighbor in graph[node]:
    q.append(neighbor)          # 先入队
    visited.add(neighbor)       # 后标记
# 看起来没问题？但如果图有平行边或多条路径到同一节点，
# 同一个节点可能被入队多次

# RIGHT：先检查再标记再入队，一气呵成
for neighbor in graph[node]:
    if neighbor not in visited:
        visited.add(neighbor)   # 先标记，防止同一节点被多次入队
        q.append(neighbor)
```

**顺序很重要**：先检查 → 再标记 → 最后入队。如果标记晚了，同一个节点可能被多个路径同时发现并多次入队。

## 翻车现场：visited 放在 popleft 之后检查

```python
# WRONG：出队时才检查是否已访问
q = deque([start])
while q:
    node = q.popleft()
    if node in visited:       # 出队了才检查？太晚了
        continue
    visited.add(node)
    for neighbor in graph[node]:
        q.append(neighbor)
```

问题是：**同一个节点可能已经在队列里出现了多次**，每次出队才跳过，浪费了队列空间和遍历时间。正确做法是在**入队前**就标记 visited，保证每个节点最多入队一次。

## BFS vs DFS 对比

| 特性 | BFS | DFS |
|---|---|---|
| 数据结构 | 队列 | 栈（递归调用栈） |
| 遍历顺序 | 按层（近→远） | 一条路走到黑 |
| 最短路径 | ✅ 天然找到 | ❌ 不一定 |
| 空间复杂度 | O(宽度) | O(深度) |
| 适用场景 | 最短路径、层序遍历 | 连通性、拓扑排序 |

**记忆口诀**：求最短路径用 BFS，求连通/全排列用 DFS。

## 复杂度

| 指标 | 值 |
|---|---|
| 时间 | **O(V + E)**，每个节点入队出队各一次，每条边检查一次 |
| 空间 | **O(V)**，队列最坏存满一层的所有节点 |

其中 V 是节点数，E 是边数。在树中 E = V-1，所以树的 BFS 是 O(V)。

## 小结

- BFS = 队列 + visited，骨架极其固定
- 队列保证"先发现的先扩展"，天然按层遍历
- **visited 必须配合 BFS 使用**，否则图中有回边会死循环
- 分层 BFS 的技巧：先记录 `size = len(q)`，再 for 循环处理 size 次
- visited 的标记时机是**入队前**：检查→标记→入队
- BFS 适合求最短路径和层序遍历，时间 O(V+E)，空间 O(V)
