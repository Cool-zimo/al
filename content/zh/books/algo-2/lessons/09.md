# 删除倒数第 N 个节点

> 链表不像数组那样能按下标回退，要删"倒数第 N 个"，经典做法是让两个指针始终相隔 N 步——走一遍就能定位。

## 问题

给定一个链表，删除它的**倒数第 N 个节点**，返回新的头。

```
输入: head = 1 -> 2 -> 3 -> 4 -> 5, n = 2
输出: 1 -> 2 -> 3 -> 5
```

也就是说被删的是节点 `4`。

最直觉的做法是：先遍历一遍算出长度 `L`，再走 `L - n` 步找到要删节点的**前驱**。这是两次遍历。题目要求（以及面试想要的答案）是**一次遍历**。

## 思路：快慢指针保持 N 的距离

核心想法：**先让快指针领先慢指针 N 步，然后两个一起走，快指针到尾时慢指针正好停在被删节点的前一个。**

为什么是"前一个"？因为链表只能改 `prev.next`，我们得定位到被删节点的前驱。

```python
def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)      # 哨兵，处理删头的情况
    fast = slow = dummy

    # 快指针先走 n+1 步（不是 n 步！）
    for _ in range(n + 1):
        fast = fast.next

    # 两指针同步前进，直到 fast 走到 None
    while fast:
        fast = fast.next
        slow = slow.next

    # slow 现在是被删节点的前驱
    slow.next = slow.next.next
    return dummy.next
```

**关键点：快指针走 `n + 1` 步，不是 `n` 步。**

- 走 `n` 步 → 快指针停在被删节点上 → slow 差一位
- 走 `n + 1` 步 → 快指针比被删节点再多走一步 → slow 正好落在前驱

举个直观的例子，`n = 2`：

```
1 -> 2 -> 3 -> 4 -> 5
^fast（0 步，在 dummy）

fast 走 3 步（n+1=3）后：
dummy -> 1 -> 2 -> 3 -> 4 -> 5
                  ^fast（在节点 3）

此时 slow 还在 dummy。两指针一起走，fast 到 None 时：
dummy -> 1 -> 2 -> 3 -> 4 -> 5
          ^slow（在节点 2，节点 3 的前驱）

slow.next = slow.next.next  # 跳过节点 3
```

## 为什么必须加 dummy

不加 dummy 的代码是这样的：

```python
# 不加 dummy 的版本
fast = slow = head
for _ in range(n):
    fast = fast.next
while fast.next:
    fast = fast.next
    slow = slow.next
slow.next = slow.next.next
return head
```

**当 `n == len(list)` 时，要删的就是头节点。** 此时 `slow` 还是 `head`，`slow.next = slow.next.next` 改的是第二个节点，头根本没动——返回 `head` 还是原来的链表，答案错了。

dummy 让所有节点（包括原头）都有了"前驱"，删头也只是 `dummy.next = head.next`，和其他情况走同一套逻辑。

## 逐帧手跑

```
链表: dummy -> 1 -> 2 -> 3 -> 4 -> 5, n = 2

阶段一：fast 走 n+1 = 3 步
  fast=1 → fast=2 → fast=3
  slow 仍在 dummy

阶段二：两指针同步
  fast=4,  slow=1
  fast=5,  slow=2
  fast=None（退出循环）
  slow 停在节点 2，正是节点 3 的前驱

阶段三：删除
  slow.next = slow.next.next   # 2 -> 4，节点 3 被跳过
返回 dummy.next，即 1 -> 2 -> 4 -> 5
```

边界情况也要跑一遍：`[1]`, `n = 1`

```
dummy -> 1
fast 走 2 步：fast=1, fast=None（第 2 步直接出界）
while fast: 不执行，slow 还在 dummy
slow.next = slow.next.next  # dummy.next = dummy.next.next = None
返回 None ✓
```

## 复杂度

- 时间 O(L)：只遍历一次
- 空间 O(1)：只用了两个指针

## 翻车现场：快指针只走 N 步

```python
# WRONG
def remove_nth_bad(head, n):
    dummy = ListNode(0, head)
    fast = slow = dummy
    for _ in range(n):           # 应该是 n+1
        fast = fast.next
    while fast:
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return dummy.next
```

后果：slow 停在被删节点的**前前驱**，多跳了一个。`[1,2,3,4,5]`, `n=2` 时，本该删 `4`，结果删掉了 `3`。

```
实际结果: 1 -> 2 -> 4 -> 5   (期望 1 -> 2 -> 3 -> 5)
                    删错了节点
```

这是最经典的 off-by-one。记住一句话：**快指针要走 n+1 步，是为了让 slow 落在前驱上。**

## 翻车现场：没有 dummy，删头节点时崩掉

```python
# WRONG
def remove_nth_no_dummy(head, n):
    fast = slow = head
    for _ in range(n):
        fast = fast.next
    while fast.next:        # fast 为 None 时这里直接 AttributeError
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return head
```

两个层面的错误：

1. **当 `n == len(list)`**（要删头），`for` 循环里 `fast` 会变成 `None`，下一轮 `while fast.next` 抛 `AttributeError: 'NoneType' object has no attribute 'next'`。
2. 即使不崩，**删头永远删不掉**——`slow` 停在 `head`，改的是 `head.next`。

```
输入: [1, 2], n = 2
期望: [2]
实际: AttributeError
```

正确做法就是乖乖加 dummy。

## 小结

- 快慢指针，快指针先走 `n+1` 步，再同步前进——**一步定位到前驱**
- `n+1` 不是 `n`：多走那一步是为了让 slow 落在"被删节点的前一个"
- **dummy 节点**让删头节点和删中间节点走同一套逻辑，也避免 `None.next` 的崩溃
- 时间 O(L)，空间 O(1)
- 这类"找倒数第 k 个 / 找中点 / 判环"的题，本质都是快慢指针的同一套路

```quiz
type: choice
exam: true
q: 用快慢指针删除倒数第 N 个节点时，快指针为什么要先走 N+1 步（而不是 N 步）？
options:
- 因为 Python 的 range 从 0 开始计数，多走一步是习惯写法
- 多走那一步是为了让慢指针最后停在"被删节点的前驱"上，这样才能执行 prev.next = prev.next.next
- 快指针必须走完整个链表，N+1 是为了保证它不提前停下
- N+1 是为了跳过 dummy 节点本身
answer: 1
explain: 链表删除需要改前驱的 next。快指针先走 N 步时会停在"被删节点"上，慢指针差一位停在它的前前驱；走 N+1 步快指针比被删节点再多走一步，慢指针恰好落在被删节点的前驱。这是快满指针解决"倒数第 k 个"问题的标准偏移量设定。
```
