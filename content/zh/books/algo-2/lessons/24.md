# 哈希的解题套路：两数之和、计数、前缀和+哈希

> 哈希表是算法题的"万能钥匙"之一。看到"查找""去重""计数""和为 K"这些关键词，就该想到哈希表。

## 套路一：两数之和（Two Sum）

**经典问题**：给一个整数数组 `nums` 和一个目标值 `target`，找出两个数，使它们的和等于 `target`，返回这两个数的下标。

暴力做法：双重循环，O(n²)。

```python
# WRONG：O(n²) 暴力
def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
```

**用哈希表优化到 O(n)**：遍历数组时，把"我已经见过的数字"存进哈希表。对每个 `nums[i]`，算 `need = target - nums[i]`，看 `need` 在不在哈希表里。

```python
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:           # O(1) 查找
            return [seen[need], i]
        seen[num] = i              # 记录当前数字和位置
    return []

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]  因为 2+7=9
print(two_sum([3, 2, 4], 6))        # [1, 2]  因为 2+4=6
```

**为什么是 O(n)？** 只遍历一次数组，每次查找哈希表 O(1)，总 O(n)。

**核心思想：用哈希表把"另一个数在哪里"这个 O(n) 的查找变成 O(1)。**

## 套路二：计数（Counter / 频次统计）

**问题**：统计一个列表中每个元素出现的次数。

```python
from collections import Counter

nums = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
c = Counter(nums)
print(c)            # Counter({4: 4, 3: 3, 2: 2, 1: 1})
print(c[3])         # 3
print(c[999])       # 0，不存在的 key 返回 0（不会 KeyError！）
```

**`Counter` 的三个常用操作**：

```python
c = Counter("abracadabra")

# 1. most_common(k)：返回出现次数最多的 k 个元素
print(c.most_common(2))   # [('a', 5), ('b', 2)]

# 2. 加减法：Counter 之间可以做加减
c1 = Counter("hello")
c2 = Counter("world")
print(c1 + c2)   # Counter({'l': 3, 'o': 2, 'h': 1, 'e': 1, 'w': 1, 'r': 1, 'd': 1})

# 3. elements()：展开成迭代器
print(list(c.elements()))  # ['a', 'a', 'a', 'a', 'a', 'b', 'b', 'r', 'r', 'c', 'd']
```

## 翻车现场：Counter 的默认补 0 特性被误用

```python
c = Counter([1, 2, 3])
print(c[999])   # 0，不会报错

# WRONG：以为 c[key] 不存在会 KeyError，写出冗余判断
if 999 in c:
    print(c[999])
else:
    print("not found")
# 其实直接 print(c[999]) 就行，默认返回 0

# 但注意：这不会真正把 key 加进 Counter
print(len(c))   # 3，999 不在里面
print(list(c.keys()))  # [1, 2, 3]
```

**这个"补 0"特性是一把双刃剑**：

```python
# 好处：统计时不需要先判断 key 是否存在
c = Counter()
for x in data:
    c[x] += 1   # 不用 if x in c: c[x] += 1 else: c[x] = 1

# 坏处：容易掩盖逻辑错误
c = Counter([1, 2, 3])
total = sum(c.values())  # 3，正确

# 但如果你误以为 999 被记录了：
all_keys = list(c.keys()) + [999]
total = sum(c[k] for k in all_keys)  # 3 + 0 = 3，0 被悄悄加进去了
```

**如果你需要区分"值为 0"和"key 不存在"，用 `c.get(key, 0)` 配合 `in` 判断。**

## 套路三：前缀和 + 哈希（子数组和为 K 的个数）

**问题**：给一个整数数组 `nums` 和一个整数 `k`，找出**和为 k 的连续子数组的个数**。

例如 `nums = [1, 1, 1]`, `k = 2`，答案为 2（子数组 `[1,1]` 出现两次）。

暴力做法：枚举所有子数组起点和终点，O(n²)。

**用前缀和 + 哈希表优化到 O(n)**：

```python
def subarray_sum(nums, k):
    prefix_count = {0: 1}  # 关键！前缀和为 0 出现了 1 次
    prefix_sum = 0
    count = 0
    
    for num in nums:
        prefix_sum += num                    # 当前前缀和
        need = prefix_sum - k                # 需要找的前缀和
        if need in prefix_count:
            count += prefix_count[need]      # 累加有多少个这样的前缀
        prefix_count[prefix_sum] = prefix_count.get(prefix_sum, 0) + 1
    
    return count

print(subarray_sum([1, 1, 1], 2))       # 2
print(subarray_sum([1, 2, 3], 3))       # 2  → [1,2] 和 [3]
print(subarray_sum([1, -1, 1, -1, 1], 0))  # 6
```

**为什么这样对？**

```
前缀和定义：pref[i] = nums[0] + nums[1] + ... + nums[i-1]

子数组 nums[j..i-1] 的和 = pref[i] - pref[j]

如果 pref[i] - pref[j] = k，
那么 pref[j] = pref[i] - k

所以对每个位置 i，我们只需要知道"前面有多少个 j 使得 pref[j] = pref[i] - k"
```

```
nums = [1, 1, 1], k = 2

i=0: pref=1,  need=1-2=-1,  count=0,  prefix_count={0:1, 1:1}
i=1: pref=2,  need=2-2=0,   count+=1 (有1个前缀和为0), prefix_count={0:1, 1:1, 2:1}
i=2: pref=3,  need=3-2=1,   count+=1 (有1个前缀和为1), prefix_count={0:1, 1:1, 2:1, 3:1}

answer = 2
```

## 翻车现场：前缀和 + 哈希忘了初始化 {0: 1}

```python
# WRONG：忘记初始化 prefix_count = {0: 1}
def subarray_sum_wrong(nums, k):
    prefix_count = {}   # 空的！
    prefix_sum = 0
    count = 0
    for num in nums:
        prefix_sum += num
        need = prefix_sum - k
        if need in prefix_count:
            count += prefix_count[need]
        prefix_count[prefix_sum] = prefix_count.get(prefix_sum, 0) + 1
    return count

print(subarray_sum_wrong([1, 1, 1], 2))  # 2？还是 1？
```

分析一下：

```
nums = [1, 1, 1], k = 2

i=0: pref=1,  need=-1,  count=0,  prefix_count={1:1}
i=1: pref=2,  need=0,   0 不在 prefix_count 里！count=0,  prefix_count={1:1, 2:1}
i=2: pref=3,  need=1,   count+=1 (有1个前缀和为1), prefix_count={1:1, 2:1, 3:1}

answer = 1  ← WRONG! 正确答案应该是 2
```

**为什么少了 1？** 因为当 `pref[i] == k` 时（即前缀和本身就是 k），`need = pref[i] - k = 0`，我们需要"前缀和为 0 出现了 1 次"这个事实。但空的 `prefix_count` 里没有 `0: 1`！

```python
# RIGHT：必须初始化 {0: 1}
prefix_count = {0: 1}  # 代表"在数组开始前，前缀和为 0 出现了 1 次"

# 这样当 pref[i] = k 时：
# need = k - k = 0
# prefix_count[0] = 1 → count += 1 ✅
```

**这是前缀和 + 哈希的必背模板：初始化 `prefix_count = {0: 1}`。**

## 翻车现场：两数之和的边界情况

```python
# WRONG：没有考虑 target = 2 * nums[i] 的情况
def two_sum_wrong(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:
            return [seen[need], i]
        seen[num] = i
    return []

print(two_sum_wrong([3, 2, 4], 6))  # [1, 1]？同一个元素用了两次！

# 因为 3 在 seen 里，need = 6-3 = 3，找到了自己！
```

等等，让我仔细看看这个例子……

```python
nums = [3, 2, 4], target = 6

i=0: num=3, need=3, 3 not in seen, seen={3:0}
i=1: num=2, need=4, 4 not in seen, seen={3:0, 2:1}
i=2: num=4, need=2, 2 in seen! return [1, 2]  ✅ 正确！
```

**其实上面这个"翻车"不对。真正的问题在于：如果同一个元素被用两次。**

```python
nums = [3, 3], target = 6

i=0: num=3, need=3, 3 not in seen, seen={3:0}
i=1: num=3, need=3, 3 in seen! return [0, 1]  ✅ 正确！
```

```python
nums = [3], target = 6

i=0: num=3, need=3, 3 not in seen, seen={3:0}
结束，返回 [] ✅ 正确
```

**真正会翻车的情况：只有一个元素，且 target = 2 * num**

```python
nums = [5], target = 10

i=0: num=5, need=5, 5 not in seen, seen={5:0}
结束，返回 [] ✅ 正确（确实需要两个不同的元素）
```

OK 那让我看一个真的会翻车的情况：

```python
# WRONG：先放 seen 再查 need → 同一个元素被匹配两次
def two_sum_wrong(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        seen[num] = i          # 先放进去
        if need in seen:       # 再查 → 可能查到自己！
            return [seen[need], i]
    return []

print(two_sum_wrong([3, 3], 6))  # [0, 0]？查到了自己！

# i=0: need=3, seen={3:0}, 3 in seen → return [0, 0] WRONG!
```

**教训：必须先查后放。**

```python
def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:       # 先查（此时哈希表里没有当前元素）
            return [seen[need], i]
        seen[num] = i          # 后放
    return []
```

## 三个套路的总结

| 套路 | 核心思想 | 哈希表存什么 | 时间复杂度 |
|---|---|---|---|
| 两数之和 | 把"找另一个数"变成 O(1) 查询 | value → index | O(n) |
| 计数 | 频次统计，Counter 一行搞定 | value → count | O(n) |
| 前缀和+哈希 | 把"找子数组和"变成"找前缀和" | prefix_sum → count | O(n) |

**识别特征**：
- 看到"两个数之和为 X" → 哈希表存已见元素
- 看到"统计出现次数" → Counter
- 看到"子数组/子串和/积为 K" → 前缀和 + 哈希

## 小结

- 两数之和：哈希表存 `{value: index}`，边遍历边查 `target - num`
- 计数：用 `collections.Counter`，自带 `most_common()`、`elements()`、加减法
- 前缀和 + 哈希：`prefix_count[pref[i] - k]` 统计和为 k 的子数组
- 前缀和必须初始化 `prefix_count = {0: 1}`，否则 `pref[i] == k` 的情况会被漏掉
- 两数之和必须先查后放，否则同一个元素被匹配两次
- Counter 对不存在的 key 返回 0 而不是报错，这既是便利也可能掩盖 bug
