# 单调栈：下一个更大元素

> 这道题问的是"每个元素右边第一个比它大的数是谁"。暴力是 O(n²)，单调栈一次遍历 O(n)。它是栈最巧妙的用法——栈里的元素始终是单调的。

## 问题

给数组 `nums = [2, 1, 2, 4, 3]`，对每个元素，找出它**右边**第一个比它大的元素。没有就填 `-1`。

```
下标:   0   1   2   3   4
值:     2   1   2   4   3
答案:   4   2   4  -1  -1
```

暴力做法：每个元素都往右扫一遍。O(n²)。有没有更快的？有——**单调栈**。

## 核心思路：把"等答案"的元素压在栈里

换个角度想。从左到右遍历，维护一个栈，**栈里存的是"还在等右边更大元素来认领"的下标**，而且这些下标对应的值是**严格递减**的（从栈底到栈顶）。

为什么必须递减？因为一旦某个新元素比栈顶小，它就认领不了栈顶，只能自己进栈继续等——这正是栈的 LIFO 语义在起作用。

```python
def next_greater(nums):
    n = len(nums)
    ans = [-1] * n
    stack = []                      # 存下标，栈底→栈顶 值递减
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:   # ★ 当前元素能认领栈顶
            j = stack.pop()
            ans[j] = x                          # x 就是 nums[j] 的下一个更大元素
        stack.append(i)
    return ans
```

手跑 `nums = [2, 1, 2, 4, 3]`：

```
i=0,x=2  stack空, 直接压   栈:[0]          (值[2])
i=1,x=1  nums[0]=2>1, 不弹 栈:[0,1]        (值[2,1])
i=2,x=2  nums[1]=1<2 → 弹j=1, ans[1]=2    栈:[0]
          nums[0]=2<2? 不, 2==2 不弹      栈:[0,2]      (值[2,2])
i=3,x=4  nums[2]=2<4 → 弹j=2, ans[2]=4    栈:[0]
          nums[0]=2<4 → 弹j=0, ans[0]=4    栈:[]
          压栈                        栈:[3]
i=4,x=3  nums[3]=4>3, 不弹              栈:[3,4]
结束, 没人认领的下标保持 -1 → ans[3]=ans[4]=-1
ans = [4, 2, 4, -1, -1]
```

## 为什么弹出来的那个，就是答案

这是单调栈最关键的一问。看 `j = stack.pop()` 这一刻：

- `j` 是栈顶，也就是**离 `i` 最近**的、还在等答案的下标；
- `nums[i] > nums[j]` 成立（否则不会进 while）；
- 而且在 `j` 和 `i` 之间没有任何元素比 `nums[j]` 大——否则那个元素早就把 `j` 弹出去了。

所以 `nums[i]` 是 `nums[j]` 右边**第一个**比它大的数。三个条件同时成立，"下一个更大"的定义被精确命中。

## 单调栈的名字从哪来

栈里存的下标对应的值，始终是**单调递减**的。一旦新元素打破了这个单调性，我们就弹出栈顶——**弹出的动作就是"结算答案"的动作**。这是单调栈最精妙的地方：**不是先找答案再存，而是"被弹出的那一刻，答案就确定了"**。

> 记法：找下一个**更大**→ while 里用 `<`，栈里**递减**。找下一个更小则反过来。

## 翻车现场：比较方向写反

```python
# WRONG：把 < 写成 >
while stack and nums[stack[-1]] > x:   # 本想找更大，却弹了比 x 大的
    j = stack.pop()
    ans[j] = x
```

这样会把"比 x 大的"先弹掉，留下的反而是比 x 小的。结果答案是错的，而且错误非常隐蔽——代码能跑、用例可能部分通过。

正确对应关系要背下来：

| 想找 | while 条件 | 栈的单调性 |
|---|---|---|
| 下一个更大 | `nums[栈顶] < x` | 递减 |
| 下一个更小 | `nums[栈顶] > x` | 递增 |

## 翻车现场：栈里存值而不是存下标

```python
# WRONG
stack = []
for x in nums:
    while stack and stack[-1] < x:
        ans[???] = x        # 弹出来的是值，我怎么知道它是谁的答案？
    stack.append(x)
```

存值的问题是：**你不知道这个被弹出的数原本在数组的哪个位置**，就没法回填 `ans`。**单调栈几乎总是存下标**，值在 `nums[栈顶]` 里现取。

## 翻车现场：漏了 `<=` 和 `<` 的区别

```python
# 想找"严格更大"
while stack and nums[stack[-1]] < x:     # 严格小于才弹，等于时 x 不会被认领
# 若想"大于等于就算更大"，则用 <=
```

在"下一个更大元素 I"里，两个数组可能有**重复值**（比如 `nums2` 里有两个 2）。如果你用 `<=`，会错误地把值相同的元素也认领掉。用 `<` 才是"严格更大"。**先想清楚"相等算不算"再选符号**。

## 实战：每日温度

LeetCode 739。给每天的温度，求要等多少天才出现更高温度：

```python
def daily_temperatures(t):
    ans = [0] * len(t)
    stack = []
    for i, x in enumerate(t):
        while stack and t[stack[-1]] < x:
            j = stack.pop()
            ans[j] = i - j          # 答案是"天数差"，不是值
        stack.append(i)
    return ans
```

和上一题只差一行：`ans[j] = i - j` 而不是 `ans[j] = x`。**栈存下标的好处在这里体现得淋漓尽致**——既能取到值，又能算距离。

## 复杂度

| 指标 | 值 |
|---|---|
| 时间 | **O(n)**，每个元素最多进栈一次、出栈一次 |
| 空间 | O(n)，栈最坏存满整个数组 |

从 O(n²) 到 O(n)，省掉的就是那层"往右一直找"的内循环——单调栈替你记住了"谁还在等"。

## 小结

- 单调栈 = 栈里元素保持单调；**弹出 = 结算答案**
- 找下一个更大：`while nums[栈顶] < x`，栈单调递减
- 找下一个更小：`while nums[栈顶] > x`，栈单调递增
- **栈里必须存下标**，否则没法回填答案；下标还能顺便算距离
- 注意 `<` 与 `<=` 的差别，取决于"相等算不算更大"
- 每个元素进出栈各一次，总复杂度 O(n)
