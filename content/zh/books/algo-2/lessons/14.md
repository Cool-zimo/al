# 栈与递归的关系：函数调用栈、栈帧与 RecursionError

> 递归不是魔法。它背后就是栈——每次你调用一个函数，系统就在"调用栈"上压一帧；函数返回，就弹一帧。理解这一点，`RecursionError` 就再也不会让你意外。

## 递归 = 自己调用自己

```python
def factorial(n):
    if n <= 1:            # 终止条件（base case）
        return 1
    return n * factorial(n - 1)
```

写递归只需要想清楚两件事：**终止条件**和**递归关系**。但这两件事是怎么在机器里跑起来的？答案是**调用栈（call stack）**。

## 函数调用栈是什么

每次调用一个函数，Python 都会在调用栈上压入一个**栈帧（stack frame）**，里面存着：

- 函数的局部变量（参数 `n`、局部变量）
- 当前执行到哪一行（返回地址）
- 上一层函数的上下文

函数执行完 `return`，这一帧就被弹出，结果交回给调用它的那一行。

用 `factorial(3)` 手跑一遍：

```
factorial(3)  → 3 * factorial(2)   压帧 [3]
factorial(2)  → 2 * factorial(1)   压帧 [3, 2]
factorial(1)  → return 1           压帧 [3, 2, 1]
                                   ↓ 开始返回
factorial(1)=1  → factorial(2)=2*1=2
factorial(2)=2  → factorial(3)=3*2=6
最终结果 6
```

整个过程就是**压栈 → 触底 → 依次弹栈**。`return` 的顺序和调用的顺序相反——这正是栈的 LIFO。

## 用 inspect 亲眼看看栈

```python
import inspect

def f(n):
    if n == 0:
        # 打印当前调用栈深度
        print("栈深度:", len(inspect.stack()))
        return
    f(n - 1)

f(4)      # 输出: 栈深度: 5  （f(4)→f(3)→f(2)→f(1)→f(0)，共 5 帧）
```

`inspect.stack()` 返回的就是当前调用栈上的所有帧。你可以直接看到自己压了几层。

## 翻车现场：没有终止条件，无限递归

```python
# WRONG
def factorial(n):
    return n * factorial(n - 1)     # 永远在减小，永远不停止
```

运行：

```
RecursionError: maximum recursion depth exceeded
```

为什么是报错而不是卡死？因为 Python **主动限制了最大递归深度**（默认 1000），防止栈无限增长把内存吃光。这个限制可以查：

```python
import sys
print(sys.getrecursionlimit())      # 1000
```

也可以改（但不建议随便改，见下文）。

## 翻车现场：终止条件写错，差一步就炸

```python
# WRONG：把终止条件写成了 n == 1 但参数会到 0
def sum_to(n):
    if n == 1:          # 当 n=0 时进不来
        return 1
    return n + sum_to(n - 1)

sum_to(3)    # 3+2+1=6，恰好能算
sum_to(0)    # 0 + (-1) + (-2) + ... 无限递归 → RecursionError
```

`sum_to(3)` 能跑通会给你一种"代码是对的"的错觉，但 `sum_to(0)` 就炸了。**测试用例要覆盖边界值**（0、负数、空输入）。

正确写法：

```python
def sum_to(n):
    if n <= 0:           # 用 <= 0 兜底
        return 0
    return n + sum_to(n - 1)
```

## 翻车现场：改递归深度只是把"早炸"变成"慢炸"

```python
import sys
sys.setrecursionlimit(100000)     # 看起来解决问题了？

def f(n):
    return f(n - 1)

f(50000)      # RecursionError: 还是会炸，只是更晚
f(100000)     # 这次不是报错——是 Segmentation fault / 进程被杀，更糟
```

调大限制只是延后问题。**栈空间是有限的内存**，不是无限的。Python 的递归深度上限本质是内存保护。正确的解法是：

1. **改迭代**：能用循环就别递归；
2. **尾递归优化**：Python 不支持，别指望；
3. **手动用 list 当栈**：把"递归状态"压进 list，避免真的调函数。

## 把递归改写成"手动栈"

同一个阶乘，用 list 手动模拟调用栈：

```python
def factorial_iter(n):
    if n <= 1:
        return 1
    stack = list(range(1, n + 1))   # 模拟"还欠着"的子问题
    res = 1
    while stack:
        res *= stack.pop()
    return res
```

这其实就是把递归"摊平"成迭代。栈帧里的信息，你用 list 和几个变量同样能装下，而且**完全不占用调用栈深度**。

## 栈溢出（stack overflow）的真正含义

很多人在网站 Stack Overflow 上提问，但这个词本意是**调用栈被撑爆了**：递归太深、每层函数又定义了大数组，栈空间耗尽，操作系统直接杀进程。

> 递归深度 × 每帧大小 > 栈容量 → stack overflow

Python 因为主动设了递归上限，通常是抛 `RecursionError` 而不是真溢出。但 C/C++ 里，没有这个保护，一旦写错就是段错误。

## 递归和栈的对应表

| 递归概念 | 栈的概念 |
|---|---|
| 调用函数 | push 一帧 |
| `return` | pop 一帧 |
| 调用顺序 | push 顺序（正序） |
| 返回顺序 | pop 顺序（逆序） |
| 局部变量 | 栈帧里的数据 |
| 终止条件 | "不再压栈"的开关 |
| `RecursionError` | 栈深度超过系统上限 |

## 复杂度：递归的隐藏空间代价

```python
# O(n) 时间，O(n) 空间（栈深 n）
def rec(n):
    if n <= 0: return
    rec(n - 1)
```

递归版的阶乘、链表遍历，空间都是 O(n)——**因为调用栈要占 n 帧**。而对应的迭代版只用 O(1)。这是递归最常见的代价：**代码短，但栈深**。

## 小结

- 递归背后就是调用栈：调用=压帧，return=弹帧
- 栈帧存局部变量、返回地址、调用者上下文
- 终止条件是"不再压栈"的开关，没有它就无限递归
- `RecursionError` 是 Python 主动保护，默认上限 1000
- 调大递归上限不是修 bug，只是延后崩溃
- 递归版空间 O(n)（栈深），改成迭代或手动栈能降到 O(1)
- 写递归必须测边界值：0、负数、空输入
