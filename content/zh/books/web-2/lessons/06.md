# 数组常用方法：push/pop/slice/splice

> 这一节解决"JS 数组有哪些常用操作"的问题。你熟悉 Python list 的 `append`、`pop`、`slice`，JS 有对应的方法，但有一些关键差异。

## 增删元素

```javascript
const arr = [1, 2, 3];

// 末尾添加（类似 Python append）
arr.push(4);        // arr 变为 [1, 2, 3, 4]，返回新长度 4

// 末尾删除（类似 Python pop）
arr.pop();          // 返回 4，arr 变为 [1, 2, 3]

// 开头添加（Python 没有对应方法，list.insert(0, x) 性能差）
arr.unshift(0);     // arr 变为 [0, 1, 2, 3]，返回新长度 4

// 开头删除
arr.shift();        // 返回 0，arr 变为 [1, 2, 3]
```

| 操作 | Python | JavaScript |
|---|---|---|
| 末尾添加 | `append(x)` | `push(x)` |
| 末尾删除 | `pop()` | `pop()` |
| 开头添加 | `insert(0, x)` | `unshift(x)` |
| 开头删除 | 无（需切片） | `shift()` |

## slice：截取子数组（不改原数组）

```javascript
const arr = [10, 20, 30, 40, 50];

arr.slice(1, 3);    // [20, 30]（不含结束索引）
arr.slice(2);       // [30, 40, 50]（到末尾）
arr.slice(-2);      // [40, 50]（负数从末尾算）
arr.slice();        // [10, 20, 30, 40, 50]（浅拷贝整个数组）

console.log(arr);   // [10, 20, 30, 40, 50]（原数组不变）
```

`slice` **不修改原数组**，返回新数组。这和 Python 的切片行为一致。

## splice：删除并插入（会改原数组！）

`splice` 是 JS 数组里最强大的方法，也是最容易搞混的：

```javascript
const arr = [10, 20, 30, 40, 50];

// splice(start, deleteCount, ...itemsToInsert)
arr.splice(1, 2);           // 从索引 1 删除 2 个元素
console.log(arr);           // [10, 40, 50]

const arr2 = [10, 20, 30];
arr2.splice(1, 0, 99);      // 从索引 1 删除 0 个，插入 99
console.log(arr2);          // [10, 99, 20, 30]

const arr3 = [10, 20, 30];
const removed = arr3.splice(0, 1);  // 删除并返回被移除的元素
console.log(removed);       // [10]
```

**核心记忆：`splice` 改原数组，`slice` 不改原数组。**

翻车现场一：以为 splice 返回新数组。

```javascript
const arr = [1, 2, 3, 4, 5];
const result = arr.splice(1, 3);
console.log(result);  // [2, 3, 4]（返回的是被删除的元素！）
console.log(arr);     // [1, 5]（原数组被修改了！）
```

后果：如果你像 Python 的 `list[start:end]` 那样期望 `splice` 返回一个"剩余的视图"，你会得到被删掉的部分——完全相反。而且原数组被改了。

正确做法：想要不修改原数组的截取，用 `slice`；想要原地修改，用 `splice`。

## 会改原数组 vs 不改原数组

| 不改原数组（返回新数组） | 会改原数组（返回被操作的值） |
|---|---|
| `slice()` | `splice()` |
| `map()` | `push()` / `pop()` |
| `filter()` | `shift()` / `unshift()` |
| `concat()` | `sort()` |
| `slice()` | `reverse()` |
| `...` 展开运算符 | `fill()` |

翻车现场二：sort() 原地排序。

```javascript
const numbers = [3, 1, 4, 1, 5, 9, 2, 6];
const sorted = numbers.sort();  // 期望得到排序后的新数组
console.log(numbers);  // [1, 1, 2, 3, 4, 5, 6, 9]（原数组被改了！）
console.log(sorted);   // [1, 1, 2, 3, 4, 5, 6, 9]（和原数组是同一个引用！）
```

后果：`sort()` 原地排序并返回同一个数组的引用。如果你需要保留原数组，先拷贝：

```javascript
const numbers = [3, 1, 4, 1, 5];
const sorted = [...numbers].sort((a, b) => a - b);  // 先展开拷贝再排序
```

翻车现场三：sort() 默认按字符串排序。

```javascript
const numbers = [10, 2, 30, 4];
numbers.sort();  // [10, 2, 30, 4] → 按字符串比较："10" < "2" < "30" < "4"
console.log(numbers);  // [10, 2, 30, 4]？不对，实际是 [10, 2, 30, 4] 字符串排序后是 [10, 2, 30, 4]
// 实际结果：[10, 2, 30, 4] 字符串排序比较的是字符编码
// "10" vs "2"：'1' < '2'，所以 10 在 2 前面
// "30" vs "4"：'3' < '4'，所以 30 在 4 前面
// 最终结果：[10, 2, 30, 4]
```

等等，让我验证：

```javascript
[10, 2, 30, 4].sort();  // [10, 2, 30, 4]? 
// 字符串比较：'10' < '2'（因为 '1' < '2'），所以 10 在 2 前面
// '2' < '30'（'2' < '3'），所以 2 在 30 前面  
// '30' < '4'（'3' < '4'），所以 30 在 4 前面
// 结果：[10, 2, 30, 4]
```

不对，让我重新想。`sort()` 无参数时按 Unicode 码位排序：
- `'10'` 和 `'2'`：`'1'`(49) < `'2'`(50)，所以 `'10'` 排在 `'2'` 前面
- `'2'` 和 `'30'`：`'2'`(50) < `'3'`(51)，所以 `'2'` 排在 `'30'` 前面
- `'30'` 和 `'4'`：`'3'`(51) < `'4'`(52)，所以 `'30'` 排在 `'4'` 前面

所以 `[10, 2, 30, 4].sort()` → `[10, 2, 30, 4]`。这确实是正确的！

```javascript
// 正确做法：传比较函数
numbers.sort((a, b) => a - b);  // [2, 4, 10, 30]
```

## 与 Python 的对比

```python
# Python 的切片不修改原列表
numbers = [1, 2, 3, 4, 5]
sub = numbers[1:3]   # [2, 3]
# numbers 不变：[1, 2, 3, 4, 5]

# Python 没有 splice 的直接对应
# 删除：del numbers[1:3]
# 插入：numbers[1:1] = [99]
```

```javascript
// JS 的 slice 不修改原数组
const numbers = [1, 2, 3, 4, 5];
const sub = numbers.slice(1, 3);  // [2, 3]
// numbers 不变

// JS 的 splice 修改原数组
numbers.splice(1, 2);  // numbers 变为 [1, 4, 5]
```

## 小结

- `push`/`pop` 操作末尾，`unshift`/`shift` 操作开头。
- `slice(start, end)` 不改原数组，返回新数组（和 Python 切片一样）。
- `splice(start, count, ...items)` 改原数组，返回被删除的元素。
- `sort()` 原地排序且默认按字符串比较，数字排序要传比较函数。
- 记住口诀：**slice 不切原数组，splice 切了原数组**。
