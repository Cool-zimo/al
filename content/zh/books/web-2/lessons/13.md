# 改内容：textContent vs innerHTML

> 这一节解决"怎么修改元素的文字和 HTML 内容"的问题。`textContent` 和 `innerHTML` 都能改内容，但安全性和行为完全不同。

## textContent：纯文本

```javascript
const div = document.querySelector('.content');
div.textContent = "你好，世界";
```

- 把内容当作**纯文本**处理。
- 特殊字符（`<`、`>`、`&`）会被转义显示。
- **安全**：不会被执行为 HTML 或 JS。

## innerHTML：HTML 字符串

```javascript
const div = document.querySelector('.content');
div.innerHTML = "<strong>你好</strong>，<em>世界</em>";
```

- 把内容当作 **HTML 解析**。
- 标签会被渲染成实际的 DOM 元素。
- **危险**：如果内容来自用户输入，可能导致 XSS 攻击。

## 两者的行为差异

```javascript
const div = document.querySelector('.demo');

// textContent：原样显示
div.textContent = "<strong>加粗</strong>";
// 页面显示：<strong>加粗</strong>（标签作为文字显示）

// innerHTML：解析渲染
div.innerHTML = "<strong>加粗</strong>";
// 页面显示：加粗（文字加粗了）
```

翻车现场一：用 innerHTML 插入用户输入。

```javascript
const userInput = prompt("请输入你的名字：");  // 用户输入：<img src=x onerror=alert('XSS')>
document.querySelector('.greeting').innerHTML = "你好，" + userInput;
```

后果：用户的输入被当作 HTML 解析执行。恶意代码可以：
- 窃取 Cookie（`document.cookie`）
- 跳转到钓鱼网站
- 伪造页面内容

这就是 **XSS（跨站脚本攻击）**。如果用户能控制页面的某个部分，就能注入任意 JS。

**正确做法：永远用 textContent 处理用户输入。**

```javascript
const userInput = prompt("请输入你的名字：");
document.querySelector('.greeting').textContent = "你好，" + userInput;
// <img src=x onerror=...> 会被原样显示，不会执行
```

## innerHTML 的使用场景

`innerHTML` 并非完全不能用，只是要小心来源：

```javascript
// ✅ 安全：内容是开发者写死的，不是用户输入
const template = `
  <div class="card">
    <h3>${product.name}</h3>
    <p>¥${product.price}</p>
  </div>
`;
container.innerHTML = template;

// ❌ 危险：内容拼接了用户数据
container.innerHTML = `<div>${userInput}</div>`;
```

如果必须用 `innerHTML` 且包含动态数据，先转义：

```javascript
function escapeHtml(str) {
  const div = document.createElement('div');
  div.textContent = str;       // textContent 自动转义
  return div.innerHTML;         // 取回转义后的 HTML
}

container.innerHTML = `<div>${escapeHtml(userInput)}</div>`;
```

## 读取内容时的差异

```javascript
// HTML: <div class="demo"><strong>Hello</strong> World</div>
const div = document.querySelector('.demo');

div.textContent;   // "Hello World"（纯文本，无标签）
div.innerHTML;     // "<strong>Hello</strong> World"（带标签）
```

## 性能差异

```javascript
// textContent 更快（不需要 HTML 解析）
element.textContent = "Hello";  // ✅ 快

// innerHTML 需要解析 HTML 字符串
element.innerHTML = "<span>Hello</span>";  // 较慢
```

如果内容是纯文本，用 `textContent` 既安全又快。

翻车现场二：innerHTML 会破坏已有元素和事件监听。

```html
<div id="container">
  <button id="myBtn">点击</button>
</div>

<script>
  document.getElementById('myBtn').addEventListener('click', () => {
    console.log('clicked');
  });

  // 后来...
  const container = document.getElementById('container');
  container.innerHTML = '<button id="myBtn">点击</button>';
  // 旧按钮被销毁重建了！之前绑定的事件监听器全部丢失！
</script>
```

后果：`innerHTML` 赋值会**销毁容器内所有旧元素并重建**。之前绑定的事件监听器全部失效，因为那些 DOM 节点已经不存在了。

## 与 Python 的对比

Python 里没有 DOM 操作，但可以用字符串转类比对：

```python
# Python：手动构造 HTML 字符串
name = "<script>alert('xss')</script>"
html = f"<div>Hello {name}</div>"  # 不会执行，因为只是字符串

# 在 Web 框架（如 Flask/Django）中
# 模板引擎会自动转义，类似 textContent 的效果
# {{ user_input }} → 自动转义
# {{ user_input|safe }} → 不转义（类似 innerHTML）
```

JS 的 `textContent` 类似模板引擎的自动转义，`innerHTML` 类似 `|safe` 过滤器。

## 小结

- `textContent` 设置纯文本，安全、快速，特殊字符被转义。
- `innerHTML` 解析 HTML，能渲染标签，但有 XSS 风险。
- **用户输入永远用 `textContent`**，不要用 `innerHTML` 拼接。
- `innerHTML` 会销毁并重建内部元素，事件监听器会丢失。
- 读取时：`textContent` 返回纯文本，`innerHTML` 返回带标签的 HTML 字符串。
