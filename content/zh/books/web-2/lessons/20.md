# 事件冒泡与捕获：事件流的三阶段模型

> 这一节解决"点击一个按钮，为什么它的父元素也收到了事件"的问题，以及怎么利用或阻止这种传播。

## 事件流的三阶段

当你点击一个嵌套元素时，事件不是只触发一次，而是经历三个阶段：

```
document → html → body → div → button  （捕获阶段，从上到下）
button（目标阶段）
button → div → body → html → document  （冒泡阶段，从下到上）
```

```javascript
// 第三个参数控制监听哪个阶段
element.addEventListener('click', handler, true);   // 捕获阶段
element.addEventListener('click', handler, false);  // 冒泡阶段（默认）
element.addEventListener('click', handler);          // 冒泡阶段（默认）
```

大多数场景下你只需要冒泡阶段（第三个参数不传或传 `false`）。捕获阶段用得很少，主要用于极少数需要"先拦截再往下传"的场景。

## 冒泡：从里往外

```html
<div id="outer">
  <div id="inner">
    <button id="btn">点我</button>
  </div>
</div>
```

```javascript
document.querySelector('#outer').addEventListener('click', () => {
  console.log('outer 冒泡');
});
document.querySelector('#inner').addEventListener('click', () => {
  console.log('inner 冒泡');
});
document.querySelector('#btn').addEventListener('click', () => {
  console.log('btn 冒泡');
});
// 点击按钮，输出顺序：btn 冒泡 → inner 冒泡 → outer 冒泡
```

## 捕获：从外往里

```javascript
document.querySelector('#outer').addEventListener('click', () => {
  console.log('outer 捕获');
}, true);
document.querySelector('#inner').addEventListener('click', () => {
  console.log('inner 捕获');
}, true);
document.querySelector('#btn').addEventListener('click', () => {
  console.log('btn 捕获');
}, true);
// 点击按钮，输出顺序：outer 捕获 → inner 捕获 → btn 捕获
```

## stopPropagation：停止传播

```javascript
document.querySelector('#btn').addEventListener('click', (event) => {
  event.stopPropagation();  // 事件到此为止，不再冒泡
  console.log('btn 被点击，事件不会冒泡到父元素');
});
```

翻车现场一：在捕获阶段 stopPropagation 后，目标阶段和冒泡阶段都不会触发。

```javascript
document.querySelector('#outer').addEventListener('click', (event) => {
  event.stopPropagation();  // 在捕获阶段就停了！
  console.log('outer 捕获 - 事件到此为止');
}, true);

document.querySelector('#btn').addEventListener('click', () => {
  console.log('这行永远不会执行');  // 因为外层在捕获阶段就阻止了传播
});
```

后果：在捕获阶段的监听器中调用 `stopPropagation()` 会阻止后续所有阶段（包括目标阶段和冒泡阶段）的监听器执行。如果子元素还需要响应事件，就会出现"莫名其妙不生效"的 bug。

## 为什么事件委托依赖冒泡

事件委托的核心逻辑是：在父元素上监听，利用冒泡让所有子元素的事件都冒泡到父元素。如果事件不冒泡，委托就失效了。

```javascript
// 事件委托依赖冒泡
document.querySelector('#todo-list').addEventListener('click', (event) => {
  // 子元素的 click 事件冒泡到这里
  const li = event.target.closest('li');
  if (li) console.log('点击了：', li.textContent);
});
```

翻车现场二：用了不冒泡的事件，事件委托失效。

```javascript
// ❌ focus 和 blur 默认不冒泡！
// 如果试图用事件委托处理 focus：
document.querySelector('#form').addEventListener('focus', (event) => {
  console.log('某个输入框获得了焦点');  // 永远不会触发！
});

// ✅ 解决：用 focusin / focusout（它们会冒泡）
document.querySelector('#form').addEventListener('focusin', (event) => {
  console.log('某个输入框获得了焦点');  // 正常触发
});
```

后果：`focus`/`blur` 事件不冒泡，事件委托无法使用它们。需要委托时用 `focusin`/`focusout` 替代。同样，`mouseenter`/`mouseleave` 也不冒泡，要用 `mouseover`/`mouseout`。

## stopPropagation 的使用场景

**场景：点击弹窗内部不应该关闭弹窗。**

```javascript
// 点击弹窗外部关闭
document.addEventListener('click', (event) => {
  if (!event.target.closest('#modal')) {
    closeModal();
  }
});

// 点击弹窗内部时阻止冒泡
document.querySelector('#modal').addEventListener('click', (event) => {
  event.stopPropagation();  // 阻止冒泡到 document
});
```

## 与 Python 的对比

Python 的 GUI 框架中事件传播也需要手动控制：

```python
# Tkinter 中事件会沿组件树传播，可以手动 stop
def on_click(event):
    # 处理逻辑
    return "break"  # 类似 stopPropagation，阻止事件继续传播
```

JS 的事件流是浏览器自动管理的三阶段模型，你只需要在合适的阶段监听，必要时调用 `stopPropagation()`。

## 小结

- 事件流分三阶段：捕获（外→内）、目标、冒泡（内→外）。
- 默认监听冒泡阶段，第三个参数传 `true` 才监听捕获阶段。
- `stopPropagation()` 立即停止事件传播，后续阶段和其他监听器都不会执行。
- 事件委托依赖冒泡机制，不冒泡的事件（focus/blur、mouseenter/mouseleave）不能用于委托，用 focusin/focusout、mouseover/mouseout 替代。
- 大多数业务场景只需要冒泡阶段 + 事件委托。
