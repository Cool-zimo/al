# 事件委托：给父元素绑一次管所有子元素

> 这一节解决"列表有很多项，每项都要绑定点击事件，怎么避免绑几百次"的问题。答案就是事件委托——利用事件冒泡，在父元素上统一处理。

## 问题：为什么要事件委托

假设有一个 100 项的列表，每项都要能点击：

```javascript
// ❌ 不推荐：给每个 li 都绑定监听器
const items = document.querySelectorAll('#list li');
items.forEach(item => {
  item.addEventListener('click', handleClick);
});
// 100 个监听器，内存占用大
```

问题：
1. **内存占用**：100 个监听器实例。
2. **动态元素**：后续新增的 li 没有绑定监听器。
3. **代码冗余**：逻辑重复。

## 解决方案：事件委托

利用**事件冒泡**——点击子元素时，事件会一路冒泡到父元素。所以在父元素上绑定一次监听器，就能处理所有子元素的事件。

```javascript
// ✅ 推荐：给父元素绑定一次
document.querySelector('#list').addEventListener('click', function(event) {
  // event.target 是被点击的子元素
  const li = event.target;
  console.log('点击了：', li.textContent);
});
```

## 完整示例

```html
<ul id="todo-list">
  <li data-id="1">买牛奶</li>
  <li data-id="2">写代码</li>
  <li data-id="3">看书</li>
</ul>
```

```javascript
document.querySelector('#todo-list').addEventListener('click', function(event) {
  const li = event.target;
  const id = li.dataset.id;

  // 根据被点击的 li 做不同处理
  console.log(`id 为 ${id} 的任务被点击了`);

  // 标记完成
  li.classList.toggle('done');
});
```

## 动态元素也能响应

这是事件委托最大的优势：

```javascript
const list = document.querySelector('#todo-list');

// 给父元素绑定监听器（只绑一次）
list.addEventListener('click', function(event) {
  if (event.target.tagName === 'LI') {
    event.target.classList.toggle('done');
  }
});

// 后来动态添加的新项
const newLi = document.createElement('li');
newLi.textContent = '新任务';
newLi.dataset.id = '4';
list.appendChild(newLi);
// 新项自动能响应点击！不需要再绑定
```

翻车现场一：target 可能是子元素而不是 li。

```html
<ul id="todo-list">
  <li>
    <span class="task-name">买牛奶</span>
    <button class="delete-btn">删除</button>
  </li>
</ul>
```

```javascript
document.querySelector('#todo-list').addEventListener('click', function(event) {
  const li = event.target;  // 如果点击了 button，target 就是 button！
  if (li.tagName === 'LI') {
    li.classList.toggle('done');
  }
  // 点击删除按钮时，li.tagName 是 "BUTTON"，不会执行 toggle
});
```

后果：如果 li 内部有子元素（span、button），`event.target` 可能是那些子元素而不是 li。解决：用 `closest()` 从 target 往上找最近的 li。

```javascript
document.querySelector('#todo-list').addEventListener('click', function(event) {
  const li = event.target.closest('li');  // 从 target 往上找最近的 li
  if (li) {
    li.classList.toggle('done');
  }
});
```

翻车现场二：点击删除按钮时触发了 li 的 toggle。

```javascript
// 点击删除按钮时，event.target.closest('li') 仍然能找到 li
// 导致"删除"和"标记完成"同时触发

document.querySelector('#todo-list').addEventListener('click', function(event) {
  // 如果点击的是删除按钮，不应该标记完成
  if (event.target.closest('.delete-btn')) {
    // 执行删除逻辑
    return;  // 阻止后续逻辑
  }

  const li = event.target.closest('li');
  if (li) {
    li.classList.toggle('done');
  }
});
```

后果：子元素事件会冒泡到父元素的监听器。需要根据 `target` 的具体元素类型做判断和分发。

## 事件委托的模式总结

```javascript
parent.addEventListener('eventType', function(event) {
  // 1. 用 closest 找到目标元素
  const item = event.target.closest('.item-selector');
  if (!item) return;  // 点击的不是目标元素

  // 2. 根据 target 的具体类型分发
  if (event.target.closest('.delete-btn')) {
    deleteItem(item);
    return;
  }

  if (event.target.closest('.edit-btn')) {
    editItem(item);
    return;
  }

  // 3. 默认行为
  toggleItem(item);
});
```

## 与 Python 的对比

Python 的事件处理框架中也有类似概念，但通常是在框架层面封装好的：

```python
# 类比：Tkinter 中手动实现类似委托
# 在一个 Canvas 上绑定事件，然后判断点击了哪个子图形
def on_click(event):
    # 手动判断点击位置对应的元素
    x, y = event.x, event.y
    for shape in shapes:
        if shape.contains(x, y):
            shape.on_click()
```

JS 的事件冒泡机制自动帮你做了"从子元素冒泡到父元素"这件事，你只需要 `closest()` 找到对应的子元素即可。

## 小结

- 事件委托利用冒泡机制，在父元素上绑定一次监听器管理所有子元素。
- 优势：减少内存占用、自动支持动态新增元素。
- `event.target.closest(selector)` 是从 target 向上查找匹配元素的利器。
- 需要根据 target 的具体类型做判断（删除按钮 vs 列表项）。
- 事件委托是处理列表类交互的标准模式。
