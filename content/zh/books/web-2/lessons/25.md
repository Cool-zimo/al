# setTimeout / setInterval：异步直觉入门

> 这一节解决"为什么我的代码没有按写的顺序执行"的问题——理解 JS 的异步机制和事件循环。

## 先点出异步直觉

```javascript
console.log('1');
setTimeout(() => {
  console.log('2');
}, 0);  // 延迟 0 毫秒
console.log('3');
// 输出顺序：1 → 3 → 2
```

**`setTimeout(fn, 0)` 也不会立即执行！** 它只是把回调放到"待执行队列"的末尾，等当前所有同步代码执行完后才运行。

这就是 JS 异步的核心直觉：**回调不会立刻执行，即使延迟是 0。**

## setTimeout：延迟执行一次

```javascript
// 语法：setTimeout(回调函数, 延迟毫秒)
setTimeout(() => {
  console.log('3 秒后执行');
}, 3000);

// 带参数的写法
setTimeout((name) => {
  console.log(`你好，${name}`);
}, 1000, '张三');
```

### 清除定时器

```javascript
const timerId = setTimeout(() => {
  console.log('这行不会执行');
}, 5000);

// 在触发前清除
clearTimeout(timerId);
console.log('定时器已取消');
```

## setInterval：每隔一段时间执行

```javascript
let count = 0;
const intervalId = setInterval(() => {
  count++;
  console.log(`第 ${count} 次执行`);
  if (count >= 3) {
    clearInterval(intervalId);  // 执行 3 次后停止
    console.log('定时器已停止');
  }
}, 1000);
```

翻车现场一：忘记清除 setInterval，导致内存泄漏。

```javascript
// ❌ 忘记 clearInterval
setInterval(() => {
  fetch('/api/notifications')
    .then(res => res.json())
    .then(data => updateUI(data));
}, 5000);
// 这个定时器永远运行，即使用户切换了页面或组件已卸载
// 每次触发都会发网络请求，浪费资源
```

后果：定时器一直运行，不断发请求、操作 DOM，造成内存泄漏和性能问题。SPA 中组件卸载时必须清除定时器。

```javascript
// ✅ 保存 timerId，在适当时机清除
const intervalId = setInterval(pollNotifications, 5000);

// 页面卸载或组件销毁时清除
window.addEventListener('beforeunload', () => {
  clearInterval(intervalId);
});
```

## 异步直觉的深入理解

```javascript
console.log('A');

setTimeout(() => {
  console.log('B');
}, 0);

Promise.resolve().then(() => {
  console.log('C');
});

console.log('D');

// 输出：A → D → C → B
```

执行顺序：
1. `console.log('A')` — 同步，立即执行
2. `setTimeout` — 注册回调到宏任务队列
3. `Promise.then` — 注册回调到微任务队列
4. `console.log('D')` — 同步，立即执行
5. 同步代码执行完毕，先执行**微任务**（Promise.then → 输出 C）
6. 再执行**宏任务**（setTimeout → 输出 B）

翻车现场二：以为 setTimeout 是精确的定时器。

```javascript
console.log('start');
setTimeout(() => {
  console.log('100ms 后');
}, 100);
// 做一些耗时操作
for (let i = 0; i < 1000000000; i++) {}  // 模拟耗时计算
console.log('end');
// "100ms 后" 实际在 "end" 之后才输出
// 因为 setTimeout 的回调要等同步代码执行完
```

后果：`setTimeout` 的延迟时间是**最小值**，不是精确值。如果主线程被阻塞，回调会一直等待。不适合做精确计时。

## 常见应用场景

```javascript
// 1. 防抖（搜索框输入停止后延迟搜索）
let searchTimer;
input.addEventListener('input', () => {
  clearTimeout(searchTimer);
  searchTimer = setTimeout(() => {
    doSearch(input.value);
  }, 300);  // 停止输入 300ms 后才搜索
});

// 2. 倒计时
let seconds = 60;
const countdown = setInterval(() => {
  seconds--;
  countdownEl.textContent = seconds;
  if (seconds <= 0) {
    clearInterval(countdown);
    countdownEl.textContent = '时间到！';
  }
}, 1000);

// 3. 轮询（定期检查数据更新）
const pollTimer = setInterval(async () => {
  const res = await fetch('/api/status');
  const data = await res.json();
  if (data.ready) {
    clearInterval(pollTimer);
    showResult(data);
  }
}, 2000);
```


## 与 Python 的对比

Python 中也有类似概念，但语义不同：

```python
# Python：time.sleep 是阻塞的！
import time

print("开始")
time.sleep(3)  # 整个线程被阻塞 3 秒
print("3 秒后")  # 3 秒后才执行
```

```python
# Python 3.7+：asyncio 是非阻塞的
import asyncio

async def main():
    print("开始")
    await asyncio.sleep(3)  # 让出控制权，不阻塞其他协程
    print("3 秒后")

asyncio.run(main())
```

JS 的 `setTimeout`/`setInterval` 是非阻塞的——它们把回调交给事件循环，主线程继续往下执行。这与 Python 的 `time.sleep`（阻塞）有本质区别。

## 小结

- `setTimeout(fn, delay)` 延迟执行一次，`setInterval(fn, delay)` 每隔 delay 重复执行。
- **回调不会立即执行**，即使 delay 是 0——同步代码优先执行完毕。
- `clearTimeout`/`clearInterval` 用于取消定时器，必须保存返回的 timerId。
- 忘记清除 `setInterval` 会导致内存泄漏。
- `setTimeout` 的延迟不是精确的，主线程阻塞时会延迟更久。
- 异步直觉：JS 是单线程 + 事件循环，回调排队等待执行。
