# 控制台调试：console、断点与读报错信息

> 这一节解决"代码不工作了怎么办"的问题——学会用 console 打日志、用断点单步执行、读懂报错信息。

## console 全家桶

### console.log：最常用的调试工具

```javascript
const name = '张三';
const age = 25;

console.log('name:', name);          // name: 张三
console.log('age:', age, '岁');      // age: 25 岁

// 多值打印
console.log({ name, age });          // { name: "张三", age: 25 }
```

### console.table：表格形式展示数组/对象

```javascript
const users = [
  { name: '张三', age: 25, city: '北京' },
  { name: '李四', age: 30, city: '上海' },
  { name: '王五', age: 28, city: '广州' }
];

console.table(users);
// 以表格形式输出，列名为对象的 key
```

### console.dir：查看对象的属性和方法

```javascript
const button = document.querySelector('button');

console.log(button);    // 输出 DOM 元素（显示为 HTML 标签）
console.dir(button);    // 输出 DOM 对象的属性列表（可展开查看所有属性）
```

**区别**：`console.log` 对 DOM 元素显示 HTML 结构，`console.dir` 显示 JavaScript 对象的属性树。要看 DOM 元素的属性（如 `tagName`、`className`、`dataset`）用 `dir`。

### 其他有用方法

```javascript
console.warn('这是一个警告');      // 黄色警告
console.error('这是一个错误');     // 红色错误
console.group('分组标题');         // 开始分组
console.log('组内内容1');
console.log('组内内容2');
console.groupEnd();               // 结束分组
console.count('计数器');          // 计数，每次调用+1
console.time('耗时');             // 开始计时
// ... 一些操作
console.timeEnd('耗时');          // 结束计时，输出耗时
```

## 断点调试

`console.log` 是"打游击"，断点是"正规军"。

### 如何打断点

1. 打开浏览器 DevTools（F12）→ Sources 面板
2. 找到你的 JS 文件
3. 在行号左侧点击，出现蓝色箭头 → 断点已设置
4. 触发代码执行，程序会在断点处暂停

### 断点调试的核心操作

| 操作 | 快捷键 | 作用 |
|---|---|---|
| Step Over | F10 | 执行当前行，跳到下一行（不进入函数内部） |
| Step Into | F11 | 进入当前行调用的函数内部 |
| Step Out | Shift+F11 | 跳出当前函数 |
| Resume | F8 | 继续执行到下一个断点 |
| Watch | - | 在 Watch 面板添加变量名，实时查看值 |

翻车现场一：只用 console.log，变量太多看花眼。

```javascript
function calculateTotal(items) {
  console.log('items:', items);
  let total = 0;
  console.log('total init:', total);
  for (const item of items) {
    console.log('item:', item);
    total += item.price * item.qty;
    console.log('total after:', total);
  }
  console.log('final total:', total);
  return total;
}
// 10 个 item 就是 40 行日志，根本看不清
```

后果：日志轰炸，关键信息淹没在噪声中。断点可以暂停执行，逐行查看每个变量的值，效率高得多。

## 怎么读报错信息

### 报错信息结构

```
TypeError: Cannot read properties of null (reading 'value')
    at handleSubmit (app.js:15:23)
    at HTMLFormElement.<anonymous> (app.js:8:5)
```

从下往上读：
1. **最底部**是触发事件的源头（用户点击 → 事件监听 → 你的函数）
2. **中间**是调用链（谁调用了谁）
3. **最顶部**是出错位置（文件名 + 行号 + 列号）

### 常见错误类型

| 错误 | 含义 | 常见原因 |
|---|---|---|
| `TypeError: Cannot read properties of null` | 对 null 调用了方法/属性 | 元素没找到，`querySelector` 返回 null |
| `TypeError: xxx is not a function` | 调用了不存在的方法 | 拼写错误、类型不对 |
| `ReferenceError: xxx is not defined` | 使用了未声明的变量 | 变量名拼错、忘记声明 |
| `SyntaxError: Unexpected token` | 语法错误 | 少了括号/分号/引号 |
| `RangeError: Maximum call stack` | 递归没有终止条件 | 死递归 |

### 从下往上读栈

```javascript
// app.js
document.querySelector('#btn').addEventListener('click', () => {
  handleSubmit();  // line 8
});

function handleSubmit() {
  const input = document.querySelector('#username');
  console.log(input.value);  // line 15 —— 报错！#username 不存在
}
```

报错栈：
```
TypeError: Cannot read properties of null (reading 'value')
    at handleSubmit (app.js:15:23)        ← 出错行
    at HTMLButtonElement.<anonymous> (app.js:8:5)  ← 调用者
```

**调试思路**：
1. 看错误类型 → `TypeError` 说明对一个非预期类型的值做了操作
2. 看消息 → `of null (reading 'value')` 说明值是 null，你试图读 `.value`
3. 看行号 → `app.js:15` → 打开文件第 15 行
4. 在 15 行打断点 → 检查 `input` 的值 → 发现是 `null`
5. 回溯 → `#username` 这个元素不存在

## console.log 调试法 vs 断点

| 对比项 | console.log | 断点 |
|---|---|---|
| 设置成本 | 低，一行搞定 | 中，需要打开 DevTools |
| 信息量 | 只能看打印时的值 | 可以看所有变量、调用栈、作用域链 |
| 修改代码 | 需要改源码（加 log） | 不改源码 |
| 条件断点 | 需要写 if 包裹 | 右键断点设条件 |
| 循环调试 | 日志会刷屏 | 可以设条件断点，只在特定迭代停下 |
| 生产环境 | 容易忘记删除 | 不影响代码 |

翻车现场二：断点设在异步回调里不生效。

```javascript
document.querySelector('#btn').addEventListener('click', () => {
  setTimeout(() => {
    const data = fetchData();
    console.log(data);  // 想在这里打断点，但不知道什么时候执行
  }, 3000);
});
```

后果：断点在异步回调中，你不知道什么时候会触发，可能等了 3 秒才停住。解决方案：在回调第一行打断点，触发事件后 DevTools 会自动停住。

## 调试实战流程

```
代码不工作
  ↓
看控制台有没有红色报错
  ↓ 有报错 → 读错误信息，定位行号
  ↓ 没报错 → 逻辑不对
  ↓
在可疑位置打断点或加 console.log
  ↓
检查变量的值是否符合预期
  ↓
发现问题 → 修复 → 刷新验证
```


## 与 Python 的对比

Python 调试常用 `print()` 或 `pdb`：

```python
# Python 的 print 调试
def calculate(items):
    print(f"items: {items}")  # 类似 console.log
    total = 0
    for item in items:
        total += item.price
    return total

# Python 断点调试
import pdb; pdb.set_trace()  # 类似 JS 的 debugger;
```

JS 的 DevTools 断点调试体验更好——图形化界面、实时查看变量、条件断点，是前端开发的核心技能。

## 小结

- `console.log` 快速打日志，`console.table` 展示表格，`console.dir` 看 DOM 属性树。
- 断点调试比 console.log 更高效：不改源码、可看所有变量、支持条件断点。
- 读报错信息**从下往上**：最底部是事件源头，最顶部是出错行。
- `TypeError: of null` 是最常见的错误——元素没找到（querySelector 返回 null）。
- 调试流程：看报错 → 定位行号 → 打断点 → 检查变量 → 修复 → 验证。
