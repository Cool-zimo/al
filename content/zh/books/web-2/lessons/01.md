# 变量：let、const 与 var 的函数作用域

> 这一节解决"JS 里怎么声明变量，以及为什么 `var` 会坑人"的问题。你学过 Python，已经知道变量是什么——JS 的差异在于它有三种声明方式，而 `var` 有一个经典陷阱。

## 三种声明方式

Python 里只有一种赋值方式：`x = 10`。JS 有三种：

```javascript
let name = "张三";       // 可变变量，块级作用域
const age = 25;         // 不可重新赋值，块级作用域
var city = "北京";       // 可变变量，函数作用域（老写法）
```

| 关键字 | 能否重新赋值 | 作用域 | 推荐度 |
|---|---|---|---|
| `let` | 能 | 块级（{} 内） | 默认选择 |
| `const` | 不能 | 块级（{} 内） | 优先使用 |
| `var` | 能 | 函数级 | 避免使用 |

**优先用 `const`**，只有确实需要重新赋值才用 `let`。这是一个刻意培养的习惯：能减少很多"变量在哪儿被改了"的调试时间。

## const 不是"不可变"，是"不能重新绑定"

```javascript
const person = { name: "张三", age: 25 };
person.age = 26;        // ✅ 没问题！改的是对象内部属性
person = { name: "李四" }; // ❌ 报错：Assignment to constant variable
```

`const` 保证的是"这个变量名始终指向同一个内存地址"，不是"那个地址里的数据不能改"。就像 Python 里 `tuple` 不能替换元素，但 `list` 元素可以改。

## var 的函数作用域坑

这是 JS 最经典的坑之一。看这段代码：

```javascript
function example() {
  if (true) {
    var x = 10;      // var 声明提升到函数顶部
  }
  console.log(x);    // 输出 10！x 在 if 块外仍然可见
}
```

换成 `let`：

```javascript
function example() {
  if (true) {
    let x = 10;      // let 是块级作用域
  }
  console.log(x);    // ❌ ReferenceError: x is not defined
}
```

翻车现场一：for 循环里的 var。

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);  // 输出什么？
  }, 100);
}
// 输出：3、3、3（不是 0、1、2！）
```

后果：`var` 声明的 `i` 在整个函数内共享，三个 `setTimeout` 回调都引用同一个 `i`，等它们执行时 `i` 已经是 3 了。用 `let` 就正常输出 0、1、2。

翻车现场二：变量提升（hoisting）。

```javascript
console.log(name);  // 输出 undefined，不报错！
var name = "张三";
```

后果：`var name` 的声明被"提升"到函数顶部，但赋值留在原地。等价于在函数开头写了 `var name;`（值为 undefined）。而 `let` 有"暂时性死区"——声明前访问直接报错，反而更安全。

## 与 Python 的对比

| 场景 | Python | JavaScript |
|---|---|---|
| 声明变量 | `x = 10` | `let x = 10` |
| 常量 | 靠约定（全大写） | `const` 语言强制 |
| 块级作用域 | 有（Python 3.10+ 部分支持） | `let`/`const` 有，`var` 没有 |
| 变量提升 | 不存在 | `var` 有，`let`/`const` 有 TDZ |

## 小结

- 优先用 `const`，需要重新赋值才用 `let`。
- `var` 是函数作用域且有变量提升，是 bug 温床，不要使用。
- `const` 不保证数据不可变，只保证变量不能重新绑定。
- 块级作用域 `{}` 内声明的 `let`/`const` 在块外不可见。
