# 项目设计：待办清单的功能拆解与数据结构

> 这一节解决"拿到一个项目需求，怎么拆解功能、定义数据结构、画界面草图"的问题。

## 项目目标

做一个待办清单（Todo List）应用，功能包括：

1. **增** —— 输入任务文本，点击添加
2. **删** —— 点击删除按钮移除任务
3. **改** —— 点击任务切换完成状态
4. **查** —— 显示所有任务列表
5. **持久化** —— 刷新页面后数据不丢失
6. **筛选** —— 按"全部 / 未完成 / 已完成"筛选显示

## 功能拆解

把大需求拆成小任务：

```
Todo List 应用
├── 界面层
│   ├── 输入框 + 添加按钮
│   ├── 任务列表（每项含复选框、文本、删除按钮）
│   └── 筛选按钮组（全部 / 未完成 / 已完成）
├── 数据层
│   ├── 任务数组（内存中）
│   ├── localStorage 读写
│   └── 渲染函数（数据 → DOM）
└── 交互层
    ├── 添加任务
    ├── 删除任务
    ├── 切换完成状态
    └── 切换筛选条件
```

## 数据结构设计

每个任务是一个对象：

```javascript
// 单个任务
{
  id: 1,           // 唯一标识（用时间戳或自增数字）
  text: '买牛奶',   // 任务内容
  done: false      // 是否完成
}

// 任务列表（数组）
const todos = [
  { id: 1, text: '买牛奶', done: false },
  { id: 2, text: '写代码', done: true },
  { id: 3, text: '看书', done: false }
];
```

**为什么需要 id？** 因为 `text` 可能重复，你无法用文本唯一标识一个任务。id 是删除和切换状态时的唯一索引。

翻车现场一：用数组下标作为标识。

```javascript
const todos = [
  { text: '买牛奶', done: false },
  { text: '写代码', done: true }
];

// 删除下标 0 后
todos.splice(0, 1);
// 原来下标 1 的"写代码"变成下标 0
// 如果 DOM 上存的还是旧下标，就会操作错对象
```

后果：数组是动态的，删除元素后下标会变。用下标关联 DOM 和数据会导致错乱。必须用稳定的唯一 id。

## id 生成策略

```javascript
// 方案一：时间戳（简单，但极端情况可能重复）
function generateId() {
  return Date.now();
}

// 方案二：自增计数器（最稳妥）
let nextId = 1;
function generateId() {
  return nextId++;
}

// 方案三：UUID（最严谨，但太长）
function generateId() {
  return crypto.randomUUID();
}
```

## 状态管理思路

```javascript
// 单一数据源：所有界面状态都从 todos 数组推导
let todos = loadFromStorage();  // 从 localStorage 恢复
let filter = 'all';            // 当前筛选条件：'all' | 'active' | 'completed'

// 渲染函数：读取 todos + filter，重建 DOM
function render() {
  // 1. 根据 filter 过滤
  const filtered = todos.filter(todo => {
    if (filter === 'active') return !todo.done;
    if (filter === 'completed') return todo.done;
    return true;
  });

  // 2. 生成 DOM
  list.innerHTML = '';
  filtered.forEach(todo => {
    const li = document.createElement('li');
    li.className = todo.done ? 'done' : '';
    li.innerHTML = `
      <input type="checkbox" ${todo.done ? 'checked' : ''}>
      <span>${todo.text}</span>
      <button class="delete-btn">删除</button>
    `;
    list.appendChild(li);
  });

  // 3. 更新统计
  updateStats();
}

// 每次数据变化后调用 render()
function addTodo(text) {
  todos.push({ id: generateId(), text, done: false });
  saveToStorage();
  render();  // 重新渲染
}

function toggleTodo(id) {
  const todo = todos.find(t => t.id === id);
  if (todo) todo.done = !todo.done;
  saveToStorage();
  render();
}

function deleteTodo(id) {
  todos = todos.filter(t => t.id !== id);
  saveToStorage();
  render();
}
```

**核心模式：数据驱动视图**——不直接操作 DOM 来改状态，而是改数据 → 重新渲染整个列表。这比手动增删 DOM 元素简单得多。

## 与 Python 的对比

Python 的 CLI 程序处理列表：

```python
# Python：直接操作列表打印
todos = []

def add_todo(text):
    todos.append({"id": len(todos) + 1, "text": text, "done": False})

def show_todos():
    for t in todos:
        status = "✓" if t["done"] else "☐"
        print(f"{status} {t['text']}")

# 交互循环
while True:
    cmd = input("> ")
    if cmd.startswith("add "):
        add_todo(cmd[4:])
    show_todos()
```

JS 版本多了一步：把数据映射到 DOM。核心思路一致——**数据是唯一真相源，界面是数据的投影**。

## 小结

- 项目从功能拆解开始：增删改查 + 持久化 + 筛选。
- 每个任务需要唯一 id，不能用数组下标（下标会变）。
- 数据驱动视图：改数据 → 调 render() 重建 DOM，比手动操作 DOM 简单可靠。
- 界面草图帮助理清布局，数据结构定义帮助理清逻辑。
- 单一数据源（todos 数组 + filter 状态），所有渲染都从它推导。
