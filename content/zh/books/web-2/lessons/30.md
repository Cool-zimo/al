# 收官：代码组织与常见 Bug 复盘

> 这一节解决"项目写完了，怎么让代码更清晰可维护，以及那些经典 bug 为什么会出现"的问题。

## 代码组织与拆分

### 原始版本：全写在一个文件

```javascript
// app.js —— 200 行全在一起
let todos = [];
let nextId = 1;
let currentFilter = 'all';
// ... 100 行 DOM 引用和函数定义 ...
// ... 100 行事件绑定 ...
```

### 优化版本：按职责分块

```javascript
// ====== 配置 ======
const STORAGE_KEY = 'todos';

// ====== 状态 ======
let todos = loadTodos();
let nextId = getNextId(todos);
let currentFilter = 'all';

// ====== 持久化 ======
function loadTodos() { /* ... */ }
function saveTodos() { /* ... */ }
function getNextId(todos) { /* ... */ }

// ====== 渲染 ======
function render() { /* ... */ }
function updateStats() { /* ... */ }

// ====== 操作 ======
function addTodo(text) { /* ... */ }
function deleteTodo(id) { /* ... */ }
function toggleTodo(id) { /* ... */ }

// ====== 事件绑定 ======
function bindEvents() { /* ... */ }

// ====== 启动 ======
bindEvents();
render();
```

**分块原则：**
- 配置在最上面（常量、API 地址）
- 状态紧随其后（可变的全局数据）
- 工具函数（持久化、渲染）
- 业务函数（增删改查）
- 事件绑定
- 启动代码

## Bug 复盘一：改了数组忘了重新渲染

**症状**：数据变了但页面没更新，console 里打印 todos 是新数据，但页面显示旧的。

```javascript
// ❌ 忘了 render()
function toggleTodo(id) {
  const todo = todos.find(t => t.id === id);
  todo.done = !todo.done;
  saveTodos();
  // 忘了 render()！页面不更新
}
```

**原因**：DOM 不会自动响应数据变化。JS 不像 Vue/React 那样有响应式系统，你必须手动调渲染函数。

**解决**：养成"改数据 → save → render"的固定三步：

```javascript
function addTodo(text) {
  todos.push({ id: nextId++, text, done: false });
  saveTodos();  // 持久化
  render();     // 更新视图
}
```

**自检方法**：在所有修改 `todos` 的地方搜索，确保每个分支都有 `render()` 调用。

## Bug 复盘二：事件委托绑错父元素

**症状**：点击列表项没反应，监听器不触发。

```javascript
// ❌ 绑到了错误的父元素上
document.querySelector('.filter-area').addEventListener('click', (event) => {
  // 这里监听的是筛选区，不是列表区！
  // 点击列表项永远不会触发
});

// ✅ 正确：绑到列表容器上
document.querySelector('#todo-list').addEventListener('click', (event) => {
  const li = event.target.closest('li');
  if (!li) return;
  // 处理列表项点击
});
```

**原因**：事件委托必须绑在**包含所有目标子元素的共同祖先**上。绑错了父元素，子元素的事件根本不会冒泡到那里。

**自检方法**：问自己"这个父元素是否包含所有需要委托的子元素？"

翻车现场：父元素在渲染时被替换了。

```javascript
// ❌ render 时把整个容器替换了
function render() {
  const container = document.querySelector('#todo-list');
  container.innerHTML = '<ul id="todo-list"></ul>';  // 新元素，旧监听器丢失！
  // 原来绑在旧 #todo-list 上的监听器没了
}

// ✅ 只清空内容，不替换容器本身
function render() {
  const container = document.querySelector('#todo-list');
  container.innerHTML = '';  // 只清空内容
  // 容器本身没变，监听器还在
  todos.forEach(todo => {
    const li = createTodoElement(todo);
    container.appendChild(li);
  });
}
```

## Bug 复盘三：localStorage 忘了 JSON.parse

**症状**：从 localStorage 取出数据后调用数组方法报错。

```javascript
// ❌ 忘了 parse
function loadTodos() {
  const raw = localStorage.getItem('todos');
  return raw || [];  // 返回字符串或空数组！
}

const todos = loadTodos();
todos.forEach(todo => console.log(todo));  // 字符串也有 forEach？没有！报错！
// 或者更隐蔽的：raw 是 "[object Object]"，JSON.parse 直接报错
```

**后果**：取出的数据是字符串，`forEach`、`filter` 等方法可能不存在或行为异常。

```javascript
// ✅ 正确做法
function loadTodos() {
  const raw = localStorage.getItem('todos');
  if (raw === null) return [];
  try {
    return JSON.parse(raw);
  } catch (err) {
    console.error('数据解析失败：', err);
    return [];
  }
}
```

**自检方法**：在 `loadTodos` 返回后打印 `Array.isArray(todos)`，确认是数组。

## 其他常见 Bug 速查

| Bug | 症状 | 原因 | 解决 |
|---|---|---|---|
| 事件只触发一次 | 监听器执行一次后失效 | 用 `innerHTML` 重建了容器 | 用事件委托或只清空内容 |
| 中文乱码 | 页面中文显示为问号 | 没设 charset 或文件编码不对 | `<meta charset="UTF-8">` |
| 点击没反应 | 元素存在但事件不触发 | JS 在 DOM 前执行 | script 放 body 末尾或用 DOMContentLoaded |
| 变量 undefined | 函数里访问不到外部变量 | 变量作用域问题 | 检查声明位置和闭包 |
| 内存泄漏 | 页面越来越卡 | setInterval 没清除 | 组件卸载时 clearInterval |

## 小结

- 代码按职责分块：配置 → 状态 → 工具 → 业务 → 事件 → 启动。
- 经典 Bug 1：**改了数组忘了 render()** —— 数据变了 DOM 不会自动更新。
- 经典 Bug 2：**事件委托绑错父元素** —— 父元素必须是所有目标子元素的共同祖先。
- 经典 Bug 3：**localStorage 忘了 JSON.parse** —— 取出的字符串没有数组方法。
- 养成自检习惯：搜所有修改数据的地方确认都有 render/save。
- 下一步：模块化、异步请求、现代框架。
