# `==` 与 `===`：类型转换的陷阱

> 这一节解决"JS 里两个等号和三个等号有什么区别"的问题。`==` 会做隐式类型转换，产生一些反直觉的结果。`===` 严格比较，不转换类型。

## 为什么需要两个等号

Python 里只有一个 `==`，比较值是否相等。JS 里有两个：

- `==`（宽松相等）：比较前**先转换类型**
- `===`（严格相等）：**不转换类型**，类型和值都必须相同

```javascript
'5' == 5      // true —— 字符串被转成数字
'5' === 5     // false —— 类型不同，直接 false
0 == false    // true —— 布尔被转成数字
0 === false   // false —— 类型不同
```

## `==` 的隐式转换规则

`==` 的转换规则非常复杂，以下是常见情况：

| 表达式 | 结果 | 原因 |
|---|---|---|
| `5 == "5"` | `true` | 字符串转数字 |
| `0 == false` | `true` | `false` 转成 `0` |
| `"" == 0` | `true` | 空字符串转成 `0` |
| `null == undefined` | `true` | 语言特殊规定 |
| `null == 0` | `false` | `null` 不转数字 |
| `[] == 0` | `true` | 空数组转成 `""` 再转 `0` |
| `[1] == 1` | `true` | `[1]` 转成 `"1"` 再转 `1` |

翻车现场一：`null` 和 `undefined` 的混淆。

```javascript
function greet(user) {
  if (user == null) {  // 这里 null == undefined 也是 true
    return "请先登录";
  }
  return "你好，" + user.name;
}
```

后果：这里用 `==` 其实"碰巧对"了（`null == undefined` 是 true）。但如果写 `user == false` 或 `user == 0`，就会引入完全无关的真值比较。最佳实践是明确意图：`user === null || user === undefined`，或者用 `user == null`（仅此一种情况 `==` 是可接受的简写）。

翻车现场二：`""` 和 `0` 的比较。

```javascript
const input = document.getElementById('age').value;  // 输入框返回字符串
if (input == 0) {
  console.log("年龄为 0");
}
// 用户什么都没输入时，input 是 ""，"" == 0 是 true！
```

后果：用户留空输入框，代码认为年龄是 0，显示"年龄为 0"——明显不对。应该用 `===` 并明确类型转换：`if (Number(input) === 0)`。

## 为什么推荐 `===`

1. **可预测**：不会出现隐式转换的意外结果。
2. **易读**：看代码就知道在比较什么类型。
3. **避免 bug**：绝大多数 `==` 的使用场景都是 bug 来源。

**结论：永远用 `===`，永远不用 `==`。** 除非你非常清楚自己在做什么（比如 `x == null` 用来同时检查 `null` 和 `undefined`）。

## 与 Python 的对比

Python 的 `==` 行为更直觉化：它不会把 `"5"` 和 `5` 视为相等。Python 里 `"5" == 5` 直接是 `False`。JS 的 `==` 是它的"特色"，也是新手最常见的 bug 来源。

## 小结

- `===` 严格相等：类型和值都相同才返回 `true`。
- `==` 宽松相等：会先转换类型再比较，规则复杂且反直觉。
- 日常开发只用 `===`，`==` 只在极少数场景（如 `x == null`）可接受。
- 类型转换的坑：`"" == 0`、`null == undefined` 都是 `true`。
