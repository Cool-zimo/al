# 类型与转换：NaN、`typeof null` 与字符串数字相加

> 这一节解决"JS 里类型是怎么工作的"的问题。JS 是动态类型语言，变量可以存任何类型的值——但这也带来了一些反直觉的行为，比如 `"5" + 3` 等于什么？

## JS 的基本类型

JS 有七种基本类型（Primitive Types）：

| 类型 | 示例 | 说明 |
|---|---|---|
| `number` | `42`、`3.14`、`NaN` | 所有数字都是 number |
| `string` | `"hello"`、`'world'` | 字符串 |
| `boolean` | `true`、`false` | 布尔值 |
| `undefined` | `undefined` | 未赋值 |
| `null` | `null` | 空值（故意的） |
| `symbol` | `Symbol("id")` | 唯一标识符 |
| `bigint` | `9007199254740993n` | 大整数 |

加上 `object`（对象类型，包括数组、函数、日期等）。

## 字符串与数字相加：经典的 `+` 号歧义

`+` 在 JS 里有两种含义：数字相加和字符串拼接。当其中一个操作数是字符串时，`+` 做拼接：

```javascript
5 + 3        // 8（数字相加）
"5" + 3      // "53"（字符串拼接）
3 + "5"      // "35"（同上）
"hello" + 5  // "hello5"
```

翻车现场一：从输入框取到的都是字符串。

```javascript
const price = document.getElementById('price').value;  // "100"
const quantity = document.getElementById('qty').value;   // "2"
const total = price + quantity;  // "1002"！不是 102
```

后果：本该算总价 102，结果得到字符串 `"1002"`。后面如果拿这个去做更多计算，bug 会一路传递下去。正确做法：`Number(price) + Number(quantity)` 或 `+price + +quantity`。

## NaN：Not a Number

`NaN` 是一个特殊的 number 值，表示"不是一个有效的数字"：

```javascript
Number("abc")   // NaN
parseInt("12px") // 12（从头解析，到 p 停止）
parseInt("px12") // NaN（开头就不是数字）
0 / 0            // NaN
Math.sqrt(-1)    // NaN
```

**NaN 有一个奇特属性：它不等于任何值，包括它自己。**

```javascript
NaN === NaN  // false！
```

检查 NaN 的正确方式：`Number.isNaN(x)` 或 `isNaN(x)`。

```javascript
Number.isNaN(NaN);       // true
Number.isNaN("hello");   // false（"hello" 不是 NaN 类型）
isNaN("hello");          // true（"hello" 先被转成 NaN，再判断）
```

翻车现场二：用 `=== NaN` 判断。

```javascript
function calculate(a, b) {
  const result = a / b;
  if (result === NaN) {  // ❌ 永远不会为 true！
    return "计算失败";
  }
  return result;
}
```

后果：`result === NaN` 永远是 `false`，错误处理永远不触发。应该用 `Number.isNaN(result)`。

## `typeof null === 'object'`：历史遗留 bug

这是一个 JS 设计了 27 年都没修的 bug：

```javascript
typeof null      // "object"  ← bug！
typeof undefined  // "undefined"
typeof []         // "object"
typeof {}         // "object"
typeof 42         // "number"
typeof "hello"    // "string"
typeof true       // "boolean"
typeof function(){} // "function"
```

原因：`typeof` 检查的是值的**类型标签**（type tag）。`null` 的类型标签是 `0`，和对象的类型标签一样，所以返回 `"object"`。

翻车现场三：用 `typeof x === 'object'` 判断对象。

```javascript
function isObject(x) {
  return typeof x === 'object';
}
isObject(null);    // true！但 null 不是对象
isObject([]);      // true
isObject({});      // true
```

后果：`null` 被误判为对象。正确写法：

```javascript
function isObject(x) {
  return x !== null && typeof x === 'object';
}
// 或者用更现代的方式
x === Object(x);  // true 表示是对象或数组
```

## 与 Python 的对比

| 场景 | Python | JavaScript |
|---|---|---|
| `"5" + 3` | `TypeError` | `"53"`（拼接） |
| `5 / 0` | `ZeroDivisionError` | `Infinity` |
| `int("abc")` | `ValueError` | `NaN` |
| `type(None)` | `<class 'NoneType'>` | `"object"`（bug） |
| 类型检查 | `isinstance(x, int)` | `typeof x === 'number'` |

Python 是强类型，`"5" + 3` 直接报错。JS 是弱类型，`+` 会隐式转换。

## 小结

- `+` 号两边有字符串就做拼接，数字和其他类型相加也可能被转成字符串。
- 从 DOM 取到的输入都是字符串，计算前必须转成数字。
- `NaN` 不等于任何值（包括自己），用 `Number.isNaN()` 检查。
- `typeof null === 'object'` 是历史 bug，判断对象要先排除 `null`。
- JS 是弱类型语言，`==` 和 `+` 都会做隐式类型转换。
