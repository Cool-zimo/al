# 22 Bearer Token：当今 API 的主流认证方式

> Basic 认证每次都要发密码，这在真实产品里不可接受。于是有了 Token：登录一次，服务器给你一张"票据"，之后每次只带票据。这一课讲 Bearer Token 的完整机制，以及 GitHub Personal Access Token 的实战用法——**这是你在这本书里用得最多的认证方式**。

## 为什么需要 Token

回顾 Basic 认证的问题：

1. **每次请求都发密码** —— 密码在网络上出现的次数越多，泄露风险越大
2. **无法细粒度控制** —— 只能"能访问"或"不能"，不能说"只读仓库但不能删"
3. **无法撤销单个凭证** —— 密码改了，所有用到它的地方都失效
4. **没有过期机制** —— 密码不会自己失效

**Token 解决了所有这四点**：

```
1. 你用用户名密码登录一次（或者直接在网站上生成一个 token）
2. 服务器给你一个长字符串：ghp_xxxxxxxxxxxxxxxxxxxx
3. 之后每个请求只带这个 token，不再带密码
4. token 有权限范围（scope）、有过期时间、可以随时单独撤销
```

**这个类比最贴切**：

> **密码 = 你家钥匙**（丢了要换锁，影响所有人）
> **Token = 酒店房卡**（有房间范围、有有效期、丢了只作废这一张）

## Bearer 这个词

```text
Authorization: Bearer ghp_xxxxxxxxxxxx
```

**Bearer 的字面意思是"持有者"**。

语义是：**"谁持有这个 token，谁就被认为是合法用户"**。

**这意味着什么**？**token 本身就是全部凭证**——不像 Basic 还需要密码，也不像 OAuth2 的某些流程需要签名。**谁拿到谁能用**。

**所以**：

> **Token 泄露 = 账号被盗用。** 这就是为什么它必须像密码一样保护。

**顺带说**：因为"持有者即可用"，所以**token 只能通过 HTTPS 传输**，而且**绝不能出现在 URL 里**（URL 会被记录在各种日志中，第 8 课讲过）。

## GitHub Personal Access Token 实战

这本书的很多例子用 GitHub API，所以详细讲它。

### 怎么生成

1. 打开 GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. 点 "Generate new token (classic)"
3. **勾选需要的权限（scope）**
4. 生成，**立刻复制**（**关掉页面后就再也看不到了**）

### scope：最小权限原则

生成时会让你勾选权限。**原则是：只勾需要的**。

| scope | 能干什么 |
|---|---|
| `repo` | 读写仓库（**最常用的**） |
| `public_repo` | 只读写公开仓库 |
| `read:user` | 读用户信息 |
| `gist` | 管理 Gist |
| `delete_repo` | **删除仓库**（危险） |

**为什么最小权限重要**：如果你的 token 泄露了，攻击者能造成的破坏**仅限于你勾选的范围**。

**反面例子**：为了省事勾了所有权限，token 泄露 → 攻击者删光你所有仓库。

### 怎么用

```python
import requests
import os

token = os.environ.get("GITHUB_TOKEN")       # ① 从环境变量读

if not token:
    raise RuntimeError("请设置 GITHUB_TOKEN 环境变量")

headers = {
    "Authorization": f"Bearer {token}",       # ② Bearer + 空格 + token
    "Accept": "application/vnd.github+json",  # ③ GitHub 要求的 Accept
    "User-Agent": "MyApp/1.0",                # ④ GitHub 强制要求 UA
}

r = requests.get("https://api.github.com/user", headers=headers, timeout=10)
print(r.status_code)                          # 200
print(r.json()["login"])                      # 你的用户名
```

> **逐行拆解**
>
> - **① `os.environ.get()`**：第 21 课讲过，**token 绝不能写进代码**
> - **②** `Bearer {token}`。**"Bearer" 后面必须有空格**
> - **③** GitHub 的 `Accept` 有特殊值，不设会拿到旧版格式
> - **④** **GitHub 强制要求 UA**，没有就 403（第 14 课讲过）

### 用 Session 简化（推荐）

每次都写四个头太烦。**设到 Session 上一次搞定**：

```python
import requests
import os

def make_github_session(token=None):
    """创建一个配置好认证的 GitHub Session"""
    token = token or os.environ.get("GITHUB_TOKEN")
    if not token:
        raise RuntimeError("需要 GITHUB_TOKEN")

    s = requests.Session()
    s.headers.update({                                    # ① 四个头一次设好
        "Authorization": f"Bearer {token}",
        "Accept": "application/vnd.github+json",
        "User-Agent": "MyApp/1.0",
        "X-GitHub-Api-Version": "2022-11-28",             # ② API 版本
    })
    return s

s = make_github_session()

r = s.get("https://api.github.com/user", timeout=10)      # ③ 不用再写头
print(r.json()["login"])

r = s.get("https://api.github.com/user/repos", timeout=10)
print(len(r.json()))
```

> **逐行拆解**
>
> - **① `s.headers.update()`**：设到 Session 上，**之后所有请求自动带**
> - **②** GitHub 建议指定 API 版本，避免未来版本变化影响你
> - **③** 之后每个请求**只需要写 URL 和 timeout**，认证头自动带上
>
> **这是真实项目里最常用的模式**。把认证封装成一个函数，业务代码干净。

## Token 的三种常见形式

不同服务的 token 格式不同，但用法一样：

| 服务 | 格式 | 头 |
|---|---|---|
| **GitHub PAT** | `ghp_xxxx` | `Authorization: Bearer ghp_xxxx` |
| **GitHub (老)** | `ghp_xxxx` | `Authorization: token ghp_xxxx` ← **注意是 token 不是 Bearer** |
| **GitLab** | 任意字符串 | `PRIVATE-TOKEN: xxxx` ← **自定义头** |
| **多数现代 API** | JWT | `Authorization: Bearer eyJhbG...` |

**关键教训**：

> **不要假设所有 API 都用 `Bearer`。看文档。**

**GitHub 的例子最能说明问题**：老文档写 `token ghp_xxx`，新文档写 `Bearer ghp_xxx`，**两种都能用**，但你得知道有这个差异，否则看别人代码时会困惑。

### JWT 简单提一下

`eyJhbGciOi...` 这种以 `eyJ` 开头的是 **JWT（JSON Web Token）**。

**它的特别之处**：**token 本身包含信息**（用 `.` 分成三段：头部.载荷.签名）。

```python
import base64
import json

jwt = "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyX2lkIjoxMjN9.signature"
header_b64, payload_b64, sig = jwt.split(".")

# 补上 padding 再解码（base64 需要长度是 4 的倍数）
payload_b64 += "=" * (-len(payload_b64) % 4)
payload = json.loads(base64.b64decode(payload_b64))
print(payload)          # {'user_id': 123}  ← 信息就在 token 里
```

**注意**：**JWT 的载荷也只是 Base64 编码，不是加密**（和第 21 课一样）。**任何人都能读到里面的内容**。所以**绝不能在 JWT 里放敏感信息**。

**JWT 的价值在第三段签名**——服务器能验证"这个 token 确实是我签发的，没被篡改"。但**验证需要密钥，客户端做不了**。

## Token 的生命周期管理

### 过期

很多 token 有过期时间。过期后服务器返回 **401**：

```python
r = s.get(url, timeout=10)
if r.status_code == 401:
    print("token 过期或无效，需要重新获取")
```

**处理策略**：

- **短期 token**（几小时）：需要**自动刷新**（用 refresh token 换新 token）
- **长期 token**（如 GitHub 的 classic PAT）：可以设成永不过期，但**安全性差**

### 撤销

**Token 泄露了怎么办**？

1. **立刻去服务后台撤销（revoke）这个 token**
2. 生成一个新 token
3. 更新所有用到它的地方

**这就是为什么用环境变量**——改一次环境变量就行，不用改代码。

### 轮换

**安全实践**：**定期更换 token**（比如 90 天一次）。即使没泄露也换。

**为什么**：你不知道它有没有泄露。定期轮换能把"泄露后能被利用的时间窗口"限制住。

## 一个完整的认证封装

把这一课的东西组合起来：

```python
import requests
import os
import logging

class ApiClient:
    """封装了认证和错误处理的 API 客户端"""

    def __init__(self, base_url, token=None, timeout=10):
        self.base_url = base_url.rstrip("/")              # ① 去掉结尾斜杠
        self.timeout = timeout
        token = token or os.environ.get("API_TOKEN")       # ② 环境变量兜底
        if not token:
            raise RuntimeError("需要 token：传参或设置 API_TOKEN")

        self.session = requests.Session()
        self.session.headers.update({
            "Authorization": f"Bearer {token}",
            "Accept": "application/json",
            "User-Agent": "MyApp/1.0",
        })

    def get(self, path, **kwargs):
        """发 GET 请求，返回 dict 或 None"""
        url = f"{self.base_url}{path}"                     # ③ 拼 URL
        try:
            r = self.session.get(url, timeout=self.timeout, **kwargs)
        except requests.exceptions.RequestException as e:
            logging.error(f"请求失败: {url} -> {e}")
            return None

        if r.status_code == 401:                           # ④ 认证失败单独提示
            logging.error("token 无效或已过期")
            return None

        if not r.ok:
            logging.error(f"HTTP {r.status_code}: {url}")
            return None

        try:
            return r.json()
        except ValueError:
            logging.error(f"响应不是 JSON: {url}")
            return None

    def close(self):
        self.session.close()

# 用法
client = ApiClient("https://api.github.com")
user = client.get("/user")
if user:
    print(user["login"])
client.close()
```

> **逐行拆解**
>
> - **① `rstrip("/")`**：去掉 base_url 结尾的斜杠，这样拼路径时不会出现 `//`
> - **②** 优先用传入的 token，没有就用环境变量。**两种入口都支持**
> - **③** 拼 URL。**注意 path 要以 `/` 开头**
> - **④** **401 单独处理**，因为它的修复方式和其他错误完全不同（换 token 而不是改代码）
>
> **这个类的价值**：**认证、错误处理、日志都封装了，业务代码只需要 `client.get("/user")`**
>
> 第 30 课会把这个思路发展成一个完整的命令行工具。

## 翻车现场

### 翻车一：token 出现在 URL 里

```python
# ❌ 危险
r = requests.get(f"https://api.example.com/data?token={token}", timeout=10)
```

**现象**：能用。然后 token 出现在：

1. **服务器访问日志**（明文）
2. **代理/CDN 日志**
3. **浏览器历史**
4. **Referer 头**（如果页面有外链）

**教训**：**token 只放 `Authorization` 头或请求体，绝不进 URL**。第 8 课讲过。

### 翻车二：Bearer 后面漏空格

```python
# ❌ 错误
headers = {"Authorization": f"Bearer{token}"}
```

**现象**：401。你检查 token 是对的，复制粘贴三遍还是 401。

**原因**：`Bearer` 和 token 之间需要空格。

**教训**：**打印出来看**。`print(headers)` 一眼发现。

### 翻车三：token 写进代码并推到 GitHub

和第 21 课一样的问题，但**更常见**，因为 token 看起来"像随机字符串"，不像密码。

**真实后果**：GitHub 官方说，**公开的 token 平均在几分钟内就被机器人发现并利用**。

**教训**：**用环境变量**。如果已经推上去了，**立刻撤销那个 token**——撤销比删除代码更优先，因为删代码来不及了。

### 翻车四：把 token 打印到日志

```python
# ❌ 危险
print(f"用 token {token} 请求 {url}")
logging.debug(f"headers: {headers}")        # 头里有 token！
```

**现象**：日志里躺着明文 token。日志文件通常权限更松、会被收集、会被共享。

**教训**：**打印头之前把认证信息抹掉**：

```python
safe_headers = {k: ("***" if k.lower() == "authorization" else v)
                for k, v in headers.items()}
print(safe_headers)
```

## 为什么这对你写代码有用

1. **Token 比 Basic 好**：细粒度权限、可撤销、可过期
2. **Bearer 的意思是"持有者即可用"**——**token 泄露 = 账号被盗**
3. **不要假设所有 API 都用 Bearer**，看文档（GitLab 用自定义头）
4. **用 Session 封装认证**，业务代码干净
5. **401 单独处理**——它的修复方式是换 token，不是改代码
6. **token 绝不进 URL、绝不进代码、绝不进日志**

## 小结

- **Token 解决了 Basic 的四个问题**：不用每次发密码、有细粒度权限、可单独撤销、可过期
- **Bearer = 持有者**，语义是"谁拿着谁能用"，**所以 token 就是全部凭证**
- **GitHub PAT 三件套**：`Authorization: Bearer xxx` + `Accept: application/vnd.github+json` + **`User-Agent`（强制）**
- **scope 用最小权限**——泄露时把损失限制住
- **用 `s.headers.update()` 封装**，之后请求只写 URL
- **不同服务格式不同**，别假设都是 Bearer（GitLab 用 `PRIVATE-TOKEN` 头）
- **JWT 的载荷只是 Base64，不是加密**——别放敏感信息
- **token 过期 → 401**，需要刷新或换新的
- ❌ **token 别进 URL / 代码 / 日志**；**`Bearer` 后别漏空格**
