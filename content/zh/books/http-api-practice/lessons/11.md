# 11 你的第一个请求：每一行都在做什么

> 这一课我们只做一件事：发出一个真实的 HTTP 请求，然后把代码里的**每一行**拆开讲清楚它在干什么、为什么这么写、不这么写会怎样。如果你之前"照着抄过代码但不知道为什么"，这一课就是为你写的。

## 先装库

`requests` **不是 Python 自带的**。它是第三方库，必须先安装：

```bash
pip install requests
```

**这一行为什么必须单独说**：很多人第一次接触 Python 时以为 `import` 什么都能用。实际上 Python 只自带"标准库"（`os`、`json`、`time`、`uuid` 这些），`requests` 不在其中。

装完之后可以这样确认：

```bash
python -c "import requests; print(requests.__version__)"
```

输出类似 `2.31.0` 就说明装好了。

### 为什么是 requests 而不是标准库的 urllib

Python 标准库里**有**发 HTTP 请求的东西，叫 `urllib.request`。但它很难用：

```python
# 标准库写法（作为对比，你不需要背）
import urllib.request
import json

req = urllib.request.Request(
    "https://api.github.com/user",
    headers={"Authorization": "Bearer xxx"},
)
with urllib.request.urlopen(req, timeout=10) as r:
    data = json.loads(r.read().decode("utf-8"))
```

对比 `requests`：

```python
import requests

r = requests.get(
    "https://api.github.com/user",
    headers={"Authorization": "Bearer xxx"},
    timeout=10,
)
data = r.json()
```

`requests` 的口号是 **"HTTP for Humans"**（给人用的 HTTP）。这不是营销——**它把 JSON 解析、编码检测、连接复用、压缩解压全都自动做了**。

这本书全程用 `requests`，因为你要学的是 **HTTP**，不是 Python 标准库的历史包袱。

## 第一段代码：发出请求

```python
import requests                                  # ① 把库拿进来

response = requests.get(                         # ② 发一个 GET 请求
    "https://api.github.com/users/Cool-zimo",    # ③ 目标地址
    timeout=10,                                  # ④ 超时时间
)

print(response.status_code)                      # ⑤ 打印状态码
print(response.text)                             # ⑥ 打印响应正文
```

就这六行。现在**一行一行拆**。

### ① `import requests`

这行做的是：把 `requests` 这个模块**加载进内存**，并让当前文件可以用 `requests.xxx` 访问它里面的东西。

**它不做的事**：
- 不发起任何网络请求
- 不建立任何连接
- 不读任何配置文件

**它只是一次"把工具箱搬到手边"的动作。**

一个小知识：`requests` 内部依赖三个库——`urllib3`（真正干活的连接层）、`certifi`（CA 证书）、`charset_normalizer` / `chardet`（编码探测）、`idna`（国际化域名）。`pip` 会自动把它们一起装上。

### ② `requests.get(...)`

这是核心的一行。它做了什么？

表面上：发一个 GET 请求，返回一个 `Response` 对象。

**实际上，这一行背后发生了至少六件事**：

```
1. 解析 URL
   把 "https://api.github.com/users/Cool-zimo" 拆成：
   协议 https / 域名 api.github.com / 端口 443（默认）/ 路径 /users/Cool-zimo

2. DNS 查询
   问 DNS 服务器：api.github.com 的 IP 是多少？
   → 得到 140.82.112.5（举例）

3. 建立 TCP 连接
   向 140.82.112.5:443 发起三次握手
   （如果你用过 socket，这就是 socket.connect()）

4. TLS 握手（因为是 https）
   验证服务器证书是否由可信机构签发
   协商加密算法，建立加密通道
   ★ 你看到网址前面的小锁，就是这一步建立的

5. 发送 HTTP 请求
   实际发出去的文本大概是：
   GET /users/Cool-zimo HTTP/1.1
   Host: api.github.com
   User-Agent: python-requests/2.31.0
   Accept-Encoding: gzip, deflate
   Accept: */*
   Connection: keep-alive
                              ← 空行
   （GET 没有正文）

6. 接收响应并封装
   读到状态行、头部、正文
   如果 Content-Encoding 是 gzip，自动解压
   把结果打包成一个 Response 对象返回
```

**理解这六步的价值**：当你的请求出问题时，你能**定位是哪一步坏了**：

| 现象 | 大概是第几步 |
|---|---|
| `NameResolutionError` | 第 2 步，DNS 挂了 |
| `ConnectionError` | 第 3 步，连不上（服务没开/防火墙） |
| `SSLError` | 第 4 步，证书问题 |
| 一直卡住直到超时 | 第 5 步发出去了但没回来，或第 6 步很慢 |
| 401 / 403 | 全通过了，是业务层拒绝 |

### ③ URL 作为一个字符串

```python
"https://api.github.com/users/Cool-zimo"
```

**注意它必须是完整的 URL，包含 `https://`。**

这是一个极常见的新手错误：

```python
# ❌ 错误
requests.get("api.github.com/users/Cool-zimo")
# 报错：MissingSchema: Invalid URL 'api.github.com/...': No scheme supplied

# ✅ 正确
requests.get("https://api.github.com/users/Cool-zimo")
```

**为什么必须写协议？** 因为 `requests` 不知道你想用 http 还是 https。**浏览器会帮你猜**（地址栏输入 `example.com`，浏览器自动补 `https://`），但库不会——它严格按你给的来。

### ④ `timeout=10`

**这是全书最重要的一行，值得单独强调。**

```python
requests.get(url)              # ← 没有 timeout
requests.get(url, timeout=10)  # ← 有 timeout
```

**不写 timeout 会发生什么？**

> **程序会无限期等待。**

不是 10 秒，不是 60 秒，是**永远**。如果服务器不响应，你的程序就卡在这一行，一动不动，直到你手动杀掉它。

**为什么这是灾难**：

- 你在写一个脚本，它在半夜跑，卡住了 → 第二天早上发现什么都没干成
- 你在写一个 Web 服务，一个请求卡住 → 占着一个线程/协程，请求堆积 → 整个服务雪崩
- 你在写一个爬虫，1000 个 URL 里有 5 个卡住 → 全军覆没

**`timeout=10` 的含义**：**等 10 秒**。10 秒内没有完成，抛 `requests.exceptions.Timeout` 异常。

**再说一遍**：

> **每一个 requests 调用都必须带 timeout。没有例外。**

这本书后面所有的代码都会带 `timeout=10`。如果你从这本书只记住一条，就记这条。

一个细节：`timeout` 也可以给一个元组，分别表示"连接超时"和"读取超时"：

```python
requests.get(url, timeout=(3, 10))
#                         ↑   ↑
#                      连不上最多等3秒  连上之后每次读取最多等10秒
```

**什么时候需要分开**：网络很差、DNS 很慢时用得到。一般情况给一个数字就够了——它同时作用于连接和读取。

### ⑤ `response.status_code`

`requests.get()` 返回的对象，我们习惯叫它 `response`（或简写 `r`）。

`.status_code` 是它的一个属性，**类型是整数**：

```python
print(type(response.status_code))    # <class 'int'>
print(response.status_code)          # 200
```

**为什么先看状态码再看内容**：因为 404、500 的响应里没有你要的数据。先确认"这次请求成功了"，再处理内容。

### ⑥ `response.text`

响应正文，**已经解码成字符串**了。

对于 GitHub 的这个接口，你会看到一大段 JSON 文本。

**注意**：它只是**字符串**，不是字典。你不能写 `response.text["login"]`。要变成字典得用 `.json()`——下一课讲。

## 完整的第一段代码，加上注释版

```python
import requests                                  # 导入库

url = "https://api.github.com/users/Cool-zimo"   # 目标地址（养成单独存变量的习惯）

try:                                             # 开始：可能失败的包裹
    response = requests.get(url, timeout=10)     # 发请求，最多等 10 秒

    print("状态码:", response.status_code)        # 先看成没成功

    if response.status_code == 200:              # 只有成功了才处理内容
        print("响应前 200 个字符:")
        print(response.text[:200])               # 只打印前 200 个，别刷屏
    else:
        print("请求没成功:", response.status_code)

except requests.exceptions.Timeout:              # 超时
    print("超时了，服务器 10 秒没响应")

except requests.exceptions.ConnectionError:      # 连不上
    print("连不上，检查网络或地址")

except requests.exceptions.RequestException as e:  # 其他所有 requests 异常
    print(f"请求出错: {e}")
```

> **逐行拆解（这次讲结构，不讲基础）**
>
> - **`url = "..."` 单独一行**：把 URL 存成变量。好处是改地址只用改一处，而且可以在前面加日志
> - **`try:` 包住整个请求**：网络请求是**必然会失败**的操作。不写 `try` 的话，任何一次网络抖动都会让你的程序崩溃退出
> - **先 `status_code` 再 `text`**：顺序固定。拿到响应第一眼看状态码，这是肌肉记忆
> - **`response.text[:200]`**：只打印前 200 个字符。**真实 API 的响应可能有几万字符**，全打印出来会把终端刷爆，你反而找不到重点
> - **`except` 的顺序**：先捕获具体的（`Timeout`、`ConnectionError`），最后捕获通用的（`RequestException`）。**顺序反了的话，通用的会先把具体的吃掉**
> - **`RequestException` 是所有 requests 异常的父类**。放最后做兜底，保证不会有漏网的错误让程序崩掉

## 一个可以立刻验证的版本

如果你不想用 GitHub API（它需要网络），可以先用一个专门的测试网站 **httpbin.org**——它就是为测试 HTTP 请求而生的：

```python
import requests

try:
    r = requests.get("https://httpbin.org/get", timeout=10)
    print(r.status_code)
    print(r.text)
except requests.exceptions.RequestException as e:
    print(f"失败: {e}")
```

`httpbin.org/get` 会把**你发出去的请求原样返回给你**。所以你会看到类似这样的响应：

```json
{
  "args": {},
  "headers": {
    "Accept": "*/*",
    "Accept-Encoding": "gzip, deflate",
    "Host": "httpbin.org",
    "User-Agent": "python-requests/2.31.0"
  },
  "origin": "1.2.3.4",
  "url": "https://httpbin.org/get"
}
```

**这个响应非常有价值**——它告诉你：

- **`headers`**：服务器实际收到了哪些请求头。你可以验证自己设的头有没有生效
- **`origin`**：你的公网 IP
- **`url`**：服务器看到的完整 URL

**调试技巧**：不确定自己发出去的请求长什么样时，就往 `httpbin.org/get` 发一次，它会如实告诉你。

## Response 对象里都有什么

先剧透一下，下一课会详细讲：

```python
r.status_code        # 状态码（int）
r.text               # 正文（str，已解码）
r.content            # 正文（bytes，原始）
r.headers            # 响应头（字典状）
r.url                # 最终 URL（重定向后会变）
r.encoding           # 用的编码
r.elapsed            # 花了多长时间
r.ok                 # 状态码 < 400
r.request            # 对应的请求对象
r.history            # 重定向历史
r.cookies            # cookie
```

## 翻车现场

### 翻车一：忘了 timeout

```python
# ❌ 错误示范
r = requests.get("https://some-slow-site.com")
```

**现象**：程序卡住不动，没有任何输出，也不会自己结束。你等了五分钟，怀疑是不是死了。

**原因**：默认没有超时。Python 的 socket 默认也是阻塞且无超时的。

**后果有多严重**：如果这个代码跑在服务器上，每个卡住的请求都占着一个线程。来 100 个这样的请求，服务就废了。

**教训**：**写 `requests.` 的时候，手自动跟上 `timeout=`。** 让它变成肌肉记忆。

### 翻车二：把 URL 拼在字符串里不打日志

```python
# ❌ 不好
r = requests.get(f"https://api.example.com/users/{user_id}/posts/{post_id}")
```

**现象**：报 404，但你不知道到底是哪个 URL 拼错了。

**原因**：f-string 拼出来的 URL 看不见。如果 `user_id` 里有空格或中文，拼出来的地址是坏的，但你一眼看不出来。

**改进**：

```python
# ✅ 好
url = f"https://api.example.com/users/{user_id}/posts/{post_id}"
print(f"→ 请求: {url}")            # 打出来看看
r = requests.get(url, timeout=10)
```

**教训**：**拼出来的 URL 一定要先打印**。这一行日志能在你调试时省下大量时间。

### 翻车三：用 print 看一个巨大的响应

```python
r = requests.get("https://api.github.com/repos/psf/requests", timeout=10)
print(r.text)          # 几万字符，终端刷屏
```

**现象**：终端滚了几十屏，你按 Ctrl+C 都来不及，最后什么都没看清。

**改进**：

```python
print(r.text[:500])                    # 只看前 500 字符
# 或者
import json
print(json.dumps(r.json(), indent=2, ensure_ascii=False)[:1000])
```

**教训**：**永远截断后再打印**。或者用 `pprint`。

## 为什么这对你写代码有用

1. **`timeout` 不是可选项**。这是本课唯一"必须记住"的东西
2. **`import` 不发请求**，真正干活的是 `requests.get()`
3. **一次 `get()` 背后有六步**（解析/DNS/TCP/TLS/发送/接收）。知道这个，你就能从错误信息反推是哪一步坏了
4. **URL 必须带 `https://`**，库不会帮你猜
5. **先看状态码，再看正文**，顺序固定
6. **所有网络请求都要包 `try`**，因为失败是常态不是意外

## 小结

- `requests` 是第三方库，`pip install requests` 装。**它比标准库 `urllib` 好用得多**
- **一次 `requests.get()` 背后六步**：解析 URL → DNS → TCP → TLS → 发送 → 接收封装
- **URL 必须写全，带 `https://`**
- **`timeout=10` 是强制的**。没有它，程序可能永远卡住
- **`timeout=(3, 10)`** 可以分别指定连接超时和读取超时
- **响应先看 `.status_code`（int），再看 `.text`（str）**
- **网络请求必须包 `try`**，按"具体在前、通用在后"的顺序捕获
- **`httpbin.org/get` 会把你的请求原样返回**，是调试神器
- ❌ 别忘 timeout；别把拼好的 URL 不打日志就发；别无截断地 print 大响应
