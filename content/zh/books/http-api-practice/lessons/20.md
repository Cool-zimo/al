# 20 响应解析：从 JSON 里安全地把数据拿出来

> 你拿到了 `r.json()`，是个嵌套很深的字典。这一课讲怎么**安全**地从中取数据——不崩、不 KeyError、不 TypeError，以及遇到结构变化时怎么办。这是从"能跑通"到"能上线"的关键一步。

## API 返回的 JSON 长什么样

典型的用户信息：

```json
{
  "login": "Cool-zimo",
  "id": 236305070,
  "name": "Feng Zimo",
  "public_repos": 39,
  "plan": {
    "name": "free",
    "space": 976562499
  },
  "created_at": "2025-01-01T00:00:00Z"
}
```

典型的分页列表：

```json
{
  "total_count": 1234,
  "incomplete_results": false,
  "items": [
    {"name": "repo1", "owner": {"login": "a"}},
    {"name": "repo2", "owner": {"login": "b"}}
  ]
}
```

**特点**：嵌套、混合类型、字段可能缺失。**你的代码必须能应对这些**。

## 危险的直接索引

新手最常写的代码：

```python
import requests

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)
data = r.json()

print(data["name"])
print(data["plan"]["space"])
```

**这有什么问题？** 三个假设：

1. **`r.json()` 一定成功** → 如果响应是 HTML 就崩
2. **`data` 一定有 `name`** → 如果这个用户没填名字，字段可能不存在
3. **`data["plan"]` 一定存在且是字典** → 可能是 `null`

**任何一条不成立就是 `KeyError` 或 `TypeError`，程序崩溃。**

而 API 的字段**经常**会缺失——用户没填的字段、权限不足看不到的字段、API 版本变化时改名的字段。

## 安全访问模式

### 模式一：.get() 链

```python
# ❌ 危险
space = data["plan"]["space"]

# ✅ 安全
space = data.get("plan", {}).get("space", 0)
```

> **逐行拆解**
>
> - **`data.get("plan", {})`**：拿不到 `plan` 时返回空字典 `{}`，**而不是 None**
> - **`.get("space", 0)`**：在前面的结果上继续取
>
> **关键**：**中间层的默认值必须是一个可以继续 `.get()` 的对象**（字典或列表），不能是 None。否则下一层 `.get()` 会 `AttributeError`

**三层嵌套的写法**：

```python
login = data.get("owner", {}).get("login", "")
if isinstance(data.get("owner"), dict) else ""
```

这太丑了。**更好的方案在下面**。

### 模式二：写一个安全取值函数（推荐）

```python
def dig(obj, *keys, default=None):
    """沿着 keys 逐层取值，任何一层取不到就返回 default"""
    cur = obj
    for k in keys:
        if isinstance(cur, dict) and k in cur:      # ① 字典
            cur = cur[k]
        elif isinstance(cur, list) and isinstance(k, int):  # ② 列表用下标
            if -len(cur) <= k < len(cur):
                cur = cur[k]
            else:
                return default
        else:
            return default                           # ③ 走不下去
    return cur

# 用法
data = {"plan": {"name": "free", "space": 976}}
print(dig(data, "plan", "space"))           # 976
print(dig(data, "plan", "missing"))         # None
print(dig(data, "nope", "deeper"))          # None ← 不崩！
print(dig(data, "plan", "missing", default=0))   # 0
```

> **逐行拆解**
>
> - **①** 当前是字典且键存在 → 往下走
> - **②** 当前是列表且键是整数 → 检查下标合法后往下走（**支持负索引**）
> - **③** 任何一层走不下去 → 立刻返回默认值，**不抛异常**
>
> **这个函数建议存进你的工具箱**。它比 `.get()` 链清晰得多，而且支持列表。

### 模式三：try/except 包裹

```python
try:
    space = data["plan"]["space"]
except (KeyError, TypeError):
    space = 0
```

**什么时候用**：你需要**精确知道**取的是哪一层，且失败时要特殊处理。

**缺点**：嵌套深的时候 `try` 块会很大，而且**会掩盖真正的 bug**（比如你把键名写错了，它也静默走 except）。

**建议**：**优先用 `dig()`**，只在需要区分"哪一层失败"时用 try。

## 类型处理：不要相信类型

JSON 只有这几种类型：

| JSON | Python |
|---|---|
| object | `dict` |
| array | `list` |
| string | `str` |
| number | `int` 或 `float` |
| true/false | `True`/`False` |
| null | `None` |

**实际中要注意**：

### 1. 数字可能是字符串

```python
# 有些 API 会把数字当字符串返回
{"count": "42"}          # 不是 42！

count = data.get("count", 0)
if isinstance(count, str):
    count = int(count)        # ① 手动转
```

> **①** 转换前最好再 `try/except ValueError`，因为可能不是合法数字。

### 2. null 不等于空字符串

```python
{"bio": null}            → Python: None
{"bio": ""}              → Python: ""

# 判断"有没有填简介"要分开
bio = data.get("bio")
if bio:                  # None 和 "" 都是假值，一起处理
    print(bio)
else:
    print("（未填写）")
```

### 3. 单元素可能是对象也可能是数组

这是**最恶心**的一种情况：

```
有时候: {"tag": "python"}
有时候: {"tag": ["python", "http"]}
```

**同一个接口，字段类型会变**（取决于数据）。

**处理**：

```python
tag = data.get("tag")

if tag is None:
    tags = []
elif isinstance(tag, str):
    tags = [tag]              # ① 单个 → 包成列表
elif isinstance(tag, list):
    tags = tag
else:
    tags = []
```

> **①** **归一化**：不管对方给什么，都转成列表。**后面的代码就只用处理一种情况了**
>
> **这是处理外部数据的黄金法则**：**在边界处归一化，内部只处理一种形状**

## 验证数据：确认你拿到的是对的

**不要假设 API 一定返回你要的东西**。加一层验证：

```python
import requests

def get_user(username):
    """获取用户信息，返回 dict 或 None"""
    r = requests.get(
        f"https://api.github.com/users/{username}",
        headers={"User-Agent": "MyApp/1.0"},
        timeout=10,
    )

    if r.status_code != 200:              # ① 状态不对
        return None

    try:
        data = r.json()                    # ② 可能不是 JSON
    except ValueError:
        return None

    if not isinstance(data, dict):         # ③ 可能是列表
        return None

    if "login" not in data:                # ④ 关键字段缺失
        return None

    return data

user = get_user("Cool-zimo")
if user is None:
    print("获取失败")
else:
    print(user["login"], user.get("public_repos", 0))
```

> **逐行拆解**
>
> - **①** 先确认状态码。**200 才是成功**
> - **②** `.json()` 可能失败（对方返回了 HTML 错误页）
> - **③** **确认类型**。有些 API 出错时返回一个列表而不是对象
> - **④** **确认关键字段存在**。这是"我拿到的数据确实是用户对象"的最低成本验证
>
> **为什么要这么多检查**：因为**这一层失败，后面所有代码都会以奇怪的方式崩**。在这里拦住，错误定位最简单

## 处理分页数据

典型的"拉全部"场景：

```python
import requests

def fetch_all_pages(base_url, params=None, max_pages=10):
    """拉取所有分页数据（基于 page 参数）"""
    all_items = []
    params = dict(params or {})

    for page in range(1, max_pages + 1):         # ① 有上限
        params["page"] = page
        r = requests.get(base_url, params=params, timeout=10)

        if r.status_code != 200:
            print(f"第 {page} 页失败: {r.status_code}")
            break                                 # ② 失败就停

        try:
            data = r.json()
        except ValueError:
            break

        items = data.get("items", [])
        if not items:                             # ③ 空了就说明没了
            break

        all_items.extend(items)
        print(f"第 {page} 页拿到 {len(items)} 条")

    return all_items
```

> **逐行拆解**
>
> - **① `max_pages` 是必要的防护**。没有上限的话，如果 API 的分页逻辑有问题，你会一直拉下去
> - **② 失败就停止**，不要继续。继续只会拿到更多垃圾
> - **③ `if not items: break`** 是**终止条件**。最后一页通常是空的或不满
>
> **注意**：不同 API 的分页方式不同——有的用 `?page=`，有的用 `?offset=`，有的用游标（cursor），还有的用 `Link` 头。第 27 课会详细讲。**先看文档确认是哪种**

## 提取数据的常见模式

### 模式一：列表推导提取字段

```python
# 从 100 个仓库里提取名字和星数
repos = r.json()
brief = [
    {"name": dig(repo, "name", default=""),
     "stars": dig(repo, "stargazers_count", default=0)}
    for repo in repos
]
```

### 模式二：过滤

```python
# 只要星数超过 100 的
popular = [r for r in repos if dig(r, "stargazers_count", default=0) > 100]
```

### 模式三：排序

```python
# 按星数倒序
top = sorted(repos,
             key=lambda r: dig(r, "stargazers_count", default=0),
             reverse=True)
```

### 模式四：去重

```python
# 按 id 去重（保持顺序）
seen = set()
unique = []
for r in repos:
    rid = dig(r, "id")
    if rid is not None and rid not in seen:
        seen.add(rid)
        unique.append(r)
```

## 处理大响应

如果一个响应有几 MB（比如一次返回 1000 条记录）：

```python
import requests

r = requests.get(url, timeout=10)

print(len(r.content))        # 5000000  ← 5MB
data = r.json()              # 一次性解析，占用约 3-5 倍内存
```

**5MB 的 JSON 解析成 Python 对象后可能占用 20-50MB 内存**（Python 对象的开销远大于 JSON 文本）。

**如果数据量很大**：

1. **用分页，一次少拿点**（最有效）
2. **用 `params` 只请求需要的字段**（很多 API 支持 `?fields=`）
3. **流式处理**（见第 25 课的下载部分）

## 一个完整的数据提取示例

把这一课的东西用起来：

```python
import requests

def dig(obj, *keys, default=None):
    cur = obj
    for k in keys:
        if isinstance(cur, dict) and k in cur:
            cur = cur[k]
        elif isinstance(cur, list) and isinstance(k, int) and -len(cur) <= k < len(cur):
            cur = cur[k]
        else:
            return default
    return cur

def summarize_repos(username, limit=5):
    """获取用户仓库，返回精简摘要"""
    r = requests.get(
        f"https://api.github.com/users/{username}/repos",
        params={"per_page": 100, "sort": "updated"},
        headers={"User-Agent": "MyApp/1.0"},
        timeout=10,
    )

    if r.status_code != 200:                     # ① 状态
        return {"error": f"HTTP {r.status_code}"}

    try:
        repos = r.json()
    except ValueError:                            # ② 解析
        return {"error": "响应不是 JSON"}

    if not isinstance(repos, list):               # ③ 类型
        return {"error": "响应不是数组"}

    # ④ 提取 + 归一化
    items = []
    for repo in repos:
        items.append({
            "name": dig(repo, "name", default="(无名)"),
            "stars": dig(repo, "stargazers_count", default=0),
            "lang": dig(repo, "language") or "未知",     # ⑤ None 也算没填
            "url": dig(repo, "html_url", default=""),
        })

    # ⑥ 排序 + 截断
    items.sort(key=lambda x: x["stars"], reverse=True)
    return {"repos": items[:limit], "total": len(repos)}

result = summarize_repos("Cool-zimo")
if "error" in result:
    print("失败:", result["error"])
else:
    print(f"共 {result['total']} 个仓库，前几个：")
    for r in result["repos"]:
        print(f"  {r['name']}  ★{r['stars']}  {r['lang']}")
```

> **逐行拆解**
>
> - **①②③** 三层验证：状态 / 解析 / 类型。**都在边界处拦住**
> - **④ 提取时用 `dig()`**，字段缺失不会崩
> - **⑤ `or "未知"`** 处理 `None` 和空字符串两种情况
> - **⑥** 排序后截断。**注意先 sort 再切片**，反过来会先截断后排序（结果错）
>
> **这个函数可以安全运行**，即使 API 返回奇怪的东西也不会崩

## 翻车现场

### 翻车一：直接索引嵌套字段

```python
# ❌ 错误
owner = data["owner"]["login"]

# 实际数据: {"owner": null}
# KeyError / TypeError: 'NoneType' object is not subscriptable
```

**现象**：大部分用户正常，某些用户（数据不完整）崩。

**教训**：**用 `dig()` 或 `.get()` 链**。

### 翻车二：以为字段一定是某种类型

```python
# ❌ 错误
tags = data["tags"]
for t in tags:            # 如果 tags 是字符串，会逐字符遍历！
    print(t)
```

**现象**：`tags` 是 `"python"`（字符串）而不是列表时，`for` 循环会**逐个字符**打印 `p`, `y`, `t`...

**这个 bug 极其隐蔽**——不报错，输出看起来"差不多对"。

**教训**：**先归一化再遍历**（前面讲过的模式）。

### 翻车三：解析了 HTML 错误页

```python
r = requests.get(url, timeout=10)
data = r.json()
# JSONDecodeError: Expecting value: line 1 column 1
```

**现象**：API 返回了 HTML（可能是 502 网关错误页），你当 JSON 解析。

**教训**：**先看状态码和 Content-Type，再 `.json()`**。第 12 课讲过。

## 为什么这对你写代码有用

1. **API 数据不可信**：字段可能缺失、类型可能变、结构可能改。**永远不要直接索引**
2. **`dig()` 是最好用的工具**——存进工具箱
3. **在边界处归一化**（单值→列表、字符串→数字），**内部只处理一种形状**
4. **验证四件事**：状态码 → 能解析 → 类型对 → 关键字段在
5. **分页要设上限**，失败就停，空了就结束
6. **大响应吃内存**，用分页和 field 过滤来减负

## 小结

- **API 返回的 JSON 嵌套深、字段可缺、类型可变**。**不要假设**
- **直接索引 `data["a"]["b"]` 会崩**（KeyError / TypeError）
- **`.get()` 链**：`data.get("a", {}).get("b", 0)`，**中间层默认值必须是可继续 get 的对象**
- **`dig(obj, *keys, default=None)`**：逐层安全取值，**支持列表下标**，推荐
- **归一化**：单值和列表统一成列表；字符串数字转成数字。**在边界做，内部只处理一种形状**
- **验证顺序**：状态码 → `.json()` 能否解析 → 类型对不对 → 关键字段在不在
- **分页**：设上限、失败即停、空页终止。**不同 API 分页方式不同**
- **大响应**：JSON 解析后内存占用是文本的 3-5 倍，**用分页减负**
- ❌ 别直接索引嵌套字段；**别假设字段类型**（字符串被当列表遍历时**不报错**）
