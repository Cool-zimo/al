# 19 重定向：那些"自动跳转"背后的坑

> 第 12 课简单提过 `r.history` 和 `r.url`。这一课把重定向彻底讲透：为什么你请求 A 却拿到 B、为什么 POST 发出去变成了 GET、为什么认证头会消失。这三个问题每个都能让你排查半天。

## 重定向是什么

服务器不给你内容，而是告诉你"去别处拿"：

```text
HTTP/1.1 301 Moved Permanently
Location: https://new.example.com/page
```

浏览器看到 3xx + `Location` 头，就自动去新地址再发一次请求。**用户完全感知不到**——地址栏最后显示的是新地址。

**`requests` 默认也这么做**（`allow_redirects=True`）。

## 五个 3xx 状态码

第 7 课列过表，这里补上最重要的细节——**重定向后方法会怎么变**：

| 状态码 | 含义 | **重定向后的方法** |
|---|---|---|
| **301** | 永久移动 | ⚠️ **允许改成 GET**（绝大多数客户端会改） |
| **302** | 临时移动 | ⚠️ **允许改成 GET**（同上） |
| **303** | See Other | ✅ **必须改成 GET**（规范强制） |
| **307** | 临时重定向 | ✅ **必须保持原方法** |
| **308** | 永久重定向 | ✅ **必须保持原方法** |

**这张表是本节的重点**，因为它解释了一个经典谜题。

## 谜题：我的 POST 变成了 GET

### 场景

```python
import requests

r = requests.post(
    "http://old.example.com/api",      # 注意是 http
    json={"name": "cool"},
    timeout=10,
)
```

如果服务器把 `http` 重定向到 `https`（**这非常常见**），会发生什么？

```
1. 你 POST http://old.example.com/api，带 JSON 请求体
2. 服务器返回 301/302，Location: https://old.example.com/api
3. requests 自动跟随 → 但改成 GET 发出去了！
4. 请求体丢了
```

**最终服务器收到的是一个 GET 请求，没有请求体**。你的数据"消失"了。

### 为什么会这样

**这是历史遗留**。

HTTP/1.1 规范（RFC 2616）规定：301 和 302 时**允许**客户端把 POST 改成 GET。理由很实际——早期浏览器这样做，用户点完"提交订单"刷新时就不会重复提交。

但规范说的是"允许"，不是"必须"。**结果所有浏览器都改了，成了事实标准。**

### requests 的具体行为

`requests` 遵循主流做法：

- **301 / 302 / 303** → **改成 GET**，丢弃请求体
- **307 / 308** → **保持原方法和请求体**

```python
import requests

# 看看到底发生了什么
r = requests.post("https://httpbin.org/redirect-to?url=/post",
                  json={"a": 1}, timeout=10)

print(r.history[0].status_code)        # 302
print(r.request.method)                # GET  ← 变了！
print(r.json()["data"])                # ""   ← 请求体没了
```

### 怎么解决

**方案一：直接用最终地址**（最推荐）

```python
# 别用 http，直接用 https
r = requests.post("https://old.example.com/api", json={"name": "cool"}, timeout=10)
```

**大部分重定向问题都是因为你用了 http 而对方要 https。一开始就写对，问题消失。**

**方案二：手动跟随，自己控制**

```python
r = requests.post(url, json=data, allow_redirects=False, timeout=10)

if r.status_code in (301, 302, 303, 307, 308):
    new_url = r.headers["Location"]
    r = requests.post(new_url, json=data, timeout=10)   # 用 POST 重新发
```

> **注意这里用 `requests.post` 而不是 `requests.get`**——你自己决定方法，requests 不会再改。

**方案三：让服务器用 307/308**（如果你是服务端开发者）

这是规范上正确的做法。**307 明确保持方法**，不会丢数据。

## 谜题二：认证头消失了

第 8 课和第 14 课都提过，这里从重定向角度重新讲。

```python
r = requests.get(
    "https://a.com/data",
    headers={"Authorization": "Bearer xxx"},
    timeout=10,
)
# a.com 重定向到 b.com
# 结果：401
```

**原因**：**`requests` 在重定向时，如果域名变了，会主动剥离 `Authorization` 头**。

**为什么这是对的**：如果你带着给 a.com 的凭证去访问 b.com，**等于把 a 的密码交给了 b**。这是严重的安全漏洞。所以这是刻意的保护。

**同样被剥离的还有**：`Cookie`（同样理由）。

### 怎么判断是不是这个问题

```python
print(len(r.history))                              # > 0 说明有重定向
print(r.history[0].headers.get("Location"))        # 看跳到哪了
print(r.request.headers.get("Authorization"))      # None ← 确认被剥离
```

### 怎么解决

**方案一：直接用最终地址**（还是最推荐）

**方案二：手动跟随并重新带认证**

```python
headers = {"Authorization": "Bearer xxx"}

r = requests.get(url, headers=headers, allow_redirects=False, timeout=10)
while r.status_code in (301, 302, 303, 307, 308):
    new_url = r.headers["Location"]
    r = requests.get(new_url, headers=headers, allow_redirects=False, timeout=10)
```

> **注意循环有风险**：如果服务器配置错误导致无限重定向，这里会死循环。**生产代码要加次数上限**（见下）。

## 关闭自动重定向

```python
import requests

r = requests.get("http://github.com", allow_redirects=False, timeout=10)

print(r.status_code)                    # 301
print(r.headers["Location"])            # https://github.com/
print(r.text)                            # 通常是空的，或一小段提示
```

> **逐行拆解**
>
> - **`allow_redirects=False`** 让 requests 停在 3xx，不跟随
> - **此时 `r.text` 基本没内容**——3xx 响应通常没有正文，只有 Location 头
>
> **什么时候用**：
> - 你想自己控制跳转逻辑
> - 你想检查重定向目标（比如检测钓鱼）
> - 你想避免认证头被剥离

## 限制重定向次数

```python
import requests

s = requests.Session()
s.max_redirects = 5                # ① 最多跟 5 次

r = s.get(url, timeout=10)
```

> **①** 默认是 30。30 次重定向意味着 30 次完整往返，慢得离谱。
>
> **建议设成 5-10**。正常网站 1-2 次就够了。

**超限会抛 `TooManyRedirects`**（第 15 课讲过）。

## r.history 的完整用法

```python
import requests

r = requests.get("http://github.com", timeout=10)

print("最终状态:", r.status_code)          # 200
print("最终 URL:", r.url)                   # https://github.com/
print("跳转次数:", len(r.history))           # 1

# 完整链条：history + 最终响应
chain = r.history + [r]
for i, resp in enumerate(chain):
    marker = "→" if i < len(chain) - 1 else "●"
    print(f"{marker} [{i}] {resp.status_code} {resp.url}")
```

**输出**：

```
→ [0] 301 http://github.com/
● [1] 200 https://github.com/
```

> **逐行拆解**
>
> - **`r.history + [r]`** 是拿到完整链条的标准写法。**记住 `r` 不在 history 里**
> - **每个元素都是完整的 Response 对象**，有 `.status_code`、`.url`、`.headers`
>
> **注意**：中间那些响应**通常没有正文**（3xx 不需要正文），所以 `resp.text` 是空的。**别指望从 history 里读内容**

## 一个实用的重定向追踪函数

```python
import requests

def trace_redirects(url, max_hops=10):
    """手动追踪重定向链，打印每一步"""
    seen = []
    current = url

    for hop in range(max_hops):                          # ① 有上限，不会死循环
        r = requests.get(current, allow_redirects=False, timeout=10)
        seen.append((r.status_code, current))

        if r.status_code in (301, 302, 303, 307, 308):   # ② 还要跳
            loc = r.headers.get("Location")
            if not loc:
                print(f"  [{hop}] {r.status_code} 但没有 Location 头，停止")
                break
            # ③ 处理相对路径
            if loc.startswith("/"):
                from urllib.parse import urljoin
                loc = urljoin(current, loc)
            print(f"  [{hop}] {r.status_code} {current}")
            print(f"       → {loc}")
            current = loc
        else:
            print(f"  [{hop}] {r.status_code} {current}  （结束）")
            break
    else:
        print(f"  超过 {max_hops} 次，可能存在重定向循环")

    return seen

trace_redirects("http://github.com")
```

> **逐行拆解**
>
> - **① `for ... in range(max_hops)`** 天然有上限，**不会死循环**。这是生产代码的必要防护
> - **②** 只在 3xx 时继续
> - **③ `urljoin`** 处理相对路径。**`Location` 可能是 `/new-path` 这种相对地址**，要拼成完整 URL
>
> **为什么需要这个函数**：排查"我请求 A 却拿到 B"时，它能把每一步都打出来，**比看 history 更清楚**（因为它记录了每一次尝试，包括失败的）

## 翻车现场

### 翻车一：POST 数据被重定向吃掉

```python
# ❌ 问题代码
r = requests.post("http://api.example.com/create", json={"name": "x"}, timeout=10)
# http → https 重定向 → 变成 GET → 数据丢失 → 创建了一个空记录或 405
```

**现象**：**不报错**。服务器可能创建了一个空的记录，或者返回 405 Method Not Allowed。你得查很久才发现创建了错误的数据。

**原因**：301/302 时 POST 被改成 GET。

**教训**：**API 地址直接写 https**。这个习惯能消灭大部分重定向问题。

### 翻车二：无限重定向

```python
# 服务端错误配置：A → B → A → B...
r = requests.get(url, timeout=10)
# TooManyRedirects: Exceeded 30 redirects
```

**现象**：`TooManyRedirects` 异常，而且**耗时很长**（30 次往返）。

**常见原因**：
- Cookie 没设置好：服务器因为你没 cookie 跳登录页，登录页又跳回来
- URL 规则写错

**教训**：**设 `s.max_redirects = 5`**，快速失败而不是慢慢转 30 圈。

### 翻车三：以为 history 里能读到内容

```python
r = requests.get(url, timeout=10)
for resp in r.history:
    print(resp.text)        # 都是空的
```

**现象**：打印出一堆空字符串，你以为代码错了。

**原因**：**3xx 响应通常没有正文**。这是正常的，重定向只需要 Location 头。

**教训**：**重定向过程只看 `.status_code` 和 `.url`**，不要指望正文。

## 为什么这对你写代码有用

1. **API 地址直接写 `https://`**，能消灭大部分重定向问题（POST 变 GET、认证头丢失都是它引起的）
2. **301/302 会把 POST 改成 GET**，请求体丢失。**307/308 不会**
3. **跨域重定向会剥离 Authorization 和 Cookie**，这是安全设计
4. **`allow_redirects=False` 让你自己控制**，配合 `Location` 头手动跳
5. **`r.history` 不含最终响应**，完整链条是 `r.history + [r]`
6. **手动追踪要设上限**，否则可能死循环
7. **`Location` 可能是相对路径**，要用 `urljoin` 拼

## 小结

- **重定向 = 3xx + Location 头**，客户端自动去新地址。`requests` 默认跟随
- **301/302/303 允许把 POST 改成 GET**（历史遗留，请求体会丢）；**307/308 保持方法**
- **跨域重定向会剥离 Authorization 和 Cookie**——安全设计，不是 bug
- **`allow_redirects=False`** 手动控制，配合 `r.headers["Location"]`
- **`s.max_redirects = 5`** 建议设置，默认 30 太慢
- **`r.history` 只有中间过程**，最终响应是 `r`；完整链条 `r.history + [r]`
- **3xx 响应通常没有正文**，别指望从 history 读内容
- **手动追踪循环必须设上限**；**`Location` 可能是相对路径，用 `urljoin` 拼**
- ✅ **最省事的方案：API 地址直接写 https**
