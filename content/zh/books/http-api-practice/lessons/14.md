# 14 请求头定制：让服务器按你要的方式来

> 上一课讲了怎么用 `params` 传参数。这一课讲请求头——它是"你和服务器之间的约定区"。设对了，服务器给你想要的东西；设错了，你可能被当成爬虫拒绝、拿到错误的语言、或者根本连不上。

## requests 默认给你发什么头

什么都不设的时候，`requests` 会自动带上这几个：

```python
import requests

r = requests.get("https://httpbin.org/get", timeout=10)
print(r.text)          # 看服务器收到了什么
```

服务器回显的内容里，headers 部分大概是：

```json
{
  "headers": {
    "Accept": "*/*",
    "Accept-Encoding": "gzip, deflate",
    "Connection": "keep-alive",
    "Host": "httpbin.org",
    "User-Agent": "python-requests/2.31.0"
  }
}
```

**逐个看**：

| 头 | 值 | 谁加的 |
|---|---|---|
| `Host` | `httpbin.org` | 底层库自动加（HTTP/1.1 必需） |
| `Accept` | `*/*` | requests 默认："我什么都接受" |
| `Accept-Encoding` | `gzip, deflate` | requests 默认："我支持压缩" |
| `User-Agent` | `python-requests/2.31.0` | **requests 默认：主动表明自己是 Python** |
| `Connection` | `keep-alive` | urllib3 默认：复用连接 |

**关键观察**：**`User-Agent` 明明白白写着 `python-requests`**。

这意味着什么？下一节讲。

## User-Agent：最该改的一个头

### 为什么默认 UA 是个问题

很多网站会**根据 User-Agent 判断你是不是真人浏览器**：

```
User-Agent: python-requests/2.31.0     ← 一眼就是脚本
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ... ← 看起来像浏览器
```

**场景一：直接拒绝**。有些网站对非浏览器的 UA 返回 403，或者给一个"请使用现代浏览器"的页面。

**场景二：内容不同**。有些网站对爬虫 UA 返回简化版页面。

**场景三：被限流**。API 会对脚本 UA 施加更严格的额度。

### 改 UA 的正确做法

```python
import requests

headers = {
    "User-Agent": "MyApp/1.0 (contact@example.com)",    # ①
}

r = requests.get("https://httpbin.org/get", headers=headers, timeout=10)
```

> **逐行拆解**
>
> - **①** 这个值是**你自己起的**名字，不是伪装成浏览器。
>
> **两种策略**：
> - **诚实标识**（推荐）：`MyApp/1.0 (contact@example.com)`。网站管理员看到这个能联系到你。**这是爬虫社区公认的礼仪**
> - **伪装浏览器**：写 `Mozilla/5.0 ...`。能过一些反爬，但**有法律和道德风险**——你在主动欺骗对方服务器
>
> **这本书的建议**：**优先诚实标识**。如果对方明确禁止爬虫，那就不要爬。

### GitHub API 的强制要求

**GitHub API 明确要求必须设置 UA**：

```python
# ❌ 会被拒绝
r = requests.get("https://api.github.com/user", timeout=10)
# 403 Forbidden: "Please make sure your request has a User-Agent header"

# ✅ 正确
r = requests.get(
    "https://api.github.com/user",
    headers={"User-Agent": "MyApp/1.0"},
    timeout=10,
)
```

**这是真实存在的规则**，不是假设。GitHub 从 2012 年起就强制要求 UA。

## 三种设置头的方式

### 方式一：单次请求（最常用）

```python
import requests

r = requests.get(
    url,
    headers={"Authorization": "Bearer xxx"},    # ① 只对这一次生效
    timeout=10,
)
```

> **①** 这个头**只作用于这一次请求**。下一次 `requests.get()` 不带它。

### 方式二：Session 级别（推荐用于多个请求）

```python
import requests

s = requests.Session()
s.headers.update({                               # ① 设置到 Session 上
    "User-Agent": "MyApp/1.0",
    "Authorization": "Bearer xxx",
})

r1 = s.get(url1, timeout=10)                     # ② 自动带上
r2 = s.get(url2, timeout=10)                     # ③ 也自动带上
```

> **逐行拆解**
>
> - **①** `s.headers` 是一个字典，`update()` 往里加。**它对该 Session 的所有请求生效**
> - **②③** 两次请求都自动带上这两个头。**不用每次重复写**
>
> **这是最实用的方式**——特别是 `Authorization`，你通常需要每个请求都带它。

### 方式三：单次覆盖 Session 的头

```python
import requests

s = requests.Session()
s.headers.update({"User-Agent": "MyApp/1.0"})     # ① 全局默认

r = s.get(                                        # ② 这次请求
    url,
    headers={"User-Agent": "Special/2.0"},        #    覆盖掉
    timeout=10,
)
```

> **合并规则**：**单次传入的 `headers` 会和 Session 的合并，同名的以单次传入的为准**。
>
> 所以 ② 这次发出去的 UA 是 `Special/2.0`，其他头还在。

## 常见的头设置场景

### 场景一：Bearer Token（最常用）

```python
import requests

token = "ghp_xxxxxxxxxxxx"
headers = {
    "Authorization": f"Bearer {token}",     # ① 注意 Bearer 后面有空格
    "Accept": "application/vnd.github+json", # ② GitHub 专用格式
}

r = requests.get("https://api.github.com/user", headers=headers, timeout=10)
```

> **逐行拆解**
>
> - **①** 格式是 `Bearer <token>`。**"Bearer" 后面有一个空格**，漏了会 401
> - **②** GitHub API 的 `Accept` 有特殊值。不设的话会拿到默认版本格式

**注意**：不是所有 API 都用 `Bearer`。有的用 `Token xxx`，有的用 `Basic xxx`。**看文档**。

### 场景二：只接受 JSON

```python
headers = {"Accept": "application/json"}

r = requests.get(url, headers=headers, timeout=10)
data = r.json()          # 现在基本可以确定是 JSON 了
```

**为什么有用**：有些 API 根据 `Accept` 返回不同格式（JSON / XML / HTML）。明确声明后，你拿到的就一定是你说的那种。

### 场景三：指定语言

```python
headers = {"Accept-Language": "zh-CN,zh;q=0.9,en;q=0.8"}

r = requests.get(url, headers=headers, timeout=10)
```

**服务器可能因此返回中文内容**。注意这只是"请求"，服务器可以不理。

### 场景四：条件请求（省流量）

```python
import requests

# 第一次请求，记下 ETag
r1 = requests.get(url, timeout=10)
etag = r1.headers.get("ETag")

# 第二次，带上 ETag
r2 = requests.get(url, headers={"If-None-Match": etag}, timeout=10)
if r2.status_code == 304:
    print("没变，用缓存")
```

第 7 课讲过，这是 HTTP 缓存机制的核心。

## 删除一个头

有时候你需要**删掉**某个默认头，而不是覆盖它。

`requests` 没有直接的"删除"参数，但有个技巧：**把它设成 `None`**：

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    headers={"User-Agent": None},        # ① 设成 None = 不发这个头
    timeout=10,
)
```

> **①** 值为 `None` 的头**不会出现在请求里**。
>
> **什么时候需要**：极少数服务器对某些头过敏。或者你想测"不带 UA 会怎样"。

**注意**：这和 `params` 里 None 被跳过是同一个设计——**`None` 在 requests 里通常表示"不要这个"**。

## 调试：确认头真的发出去了

这是本课最实用的一节。

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    headers={"X-My-Header": "hello"},
    timeout=10,
)

# 方法一：看服务器回显
print(r.json()["headers"])         # ① 服务器如实报告收到了什么

# 方法二：看 requests 自己记录的请求对象
print(r.request.headers)            # ② 直接看发出去的
```

> **逐行拆解**
>
> - **①** `httpbin.org/get` 会把收到的请求头原样返回。**这是验证头是否生效的黄金方法**
> - **②** `r.request.headers` 是客户端视角的记录。**两者应该一致**
>
> **不一致时说明什么**：中间有代理或重定向修改了请求。特别是 **跨域重定向会剥离 Authorization**。

## 一个辅助函数：合并头的正确方式

真实项目里你经常需要"基础头 + 本次额外头 + 认证头"三层合并。这样写最清晰：

```python
import requests

def make_headers(token=None, extra=None):
    """生成请求头：基础头 + 认证头 + 额外头"""
    headers = {                                    # ① 基础头
        "User-Agent": "MyApp/1.0",
        "Accept": "application/json",
    }
    if token:                                       # ② 可选的认证
        headers["Authorization"] = f"Bearer {token}"
    if extra:                                       # ③ 可选的额外头
        headers.update(extra)
    return headers

# 用法
h = make_headers(token="xxx", extra={"X-Request-ID": "abc123"})
r = requests.get(url, headers=h, timeout=10)
```

> **逐行拆解**
>
> - **①** 所有请求都该有的头，无条件写死
> - **②** token 为 `None` 或空字符串时**不加认证头**。这样未登录和已登录可以用同一个函数
> - **③** `extra` 是可选的额外头，**它会覆盖前面的同名头**（因为 `update` 后写胜）
>
> **为什么要封装成函数**：避免在每个请求处重复写那一堆头。**而且改 UA 只用改一处**

## 翻车现场

### 翻车一：Bearer 后面漏了空格

```python
# ❌ 错误
headers = {"Authorization": "Bearerghp_xxxx"}
# 或
headers = {"Authorization": "ghp_xxxx"}       # 连 Bearer 都没有
```

**现象**：401 Unauthorized。你检查 token 是对的，复制粘贴了三遍，还是 401。

**原因**：格式必须是 `Bearer <token>`，**中间有空格**。

**教训**：**打印出来看**。`print(headers)` 一眼就能发现。

### 翻车二：认证头被重定向吃掉

```python
# ❌ 现象：401
r = requests.get("https://a.com/data", headers={"Authorization": "Bearer xxx"}, timeout=10)
# a.com 重定向到了 b.com，Authorization 没了
```

**现象**：直接访问目标地址没问题，访问会重定向的地址就 401。

**原因**：**第 8 课讲过——跨域重定向时 requests 会剥离 Authorization**。这是安全设计。

**验证**：

```python
print(r.request.headers.get("Authorization"))    # None ← 确实没了
print(r.history)                                  # 有重定向
```

**解决**：手动跟随，或者用 Session（**Session 也救不了**，这是重定向逻辑决定的）。正确做法是：

```python
r = requests.get(url, headers=headers, allow_redirects=False, timeout=10)
if r.status_code in (301, 302):
    new_url = r.headers["Location"]
    r = requests.get(new_url, headers=headers, timeout=10)    # 手动重新带
```

### 翻车三：把 headers 写成位置参数

```python
# ❌ 错误
r = requests.get(url, {"Authorization": "Bearer xxx"}, timeout=10)
```

**现象**：请求发出去了，但没有认证头，401。

**原因**：**`requests.get()` 的第二个位置参数是 `params`，不是 `headers`**。你那个字典被当成了查询参数。

**验证**：`print(r.url)` 会看到 `?Authorization=Bearer%20xxx` —— 头跑到 URL 里去了。

**教训**：**`headers=` 必须用关键字**。这是最隐蔽的一类错误，因为**它不报错**。

## 为什么这对你写代码有用

1. **`User-Agent` 是最该改的默认头**。GitHub API 强制要求它
2. **认证头用 Session 级别设置**，一次设好全站生效
3. **单次 `headers` 会覆盖 Session 的同名头**（合并而非替换）
4. **`None` 表示删除一个头**
5. **调试用 `r.request.headers` 或 httpbin**——"我设了但没生效"的第一手段
6. **`headers=` 必须写关键字**，写成位置参数会变成查询参数且**不报错**

## 小结

- **默认头**：`Host`（自动）/ `Accept: */*` / `Accept-Encoding` / **`User-Agent: python-requests/2.31.0`** / `Connection: keep-alive`
- **UA 暴露了你是脚本**。建议设成诚实标识 `MyApp/1.0 (contact@...)`
- **GitHub API 强制要求 UA**，否则 403
- **三种设头方式**：单次 `headers=` / Session 级 `s.headers.update()` / 单次覆盖 Session
- **常用场景**：`Authorization: Bearer <token>`（**注意空格**）/ `Accept: application/json` / `Accept-Language` / `If-None-Match`
- **值设 `None` = 删除这个头**
- **验证方式**：`r.request.headers` 或打给 `httpbin.org/get`
- ❌ **Bearer 后漏空格**；**`headers` 写成位置参数**（不报错，变成查询参数）；**跨域重定向吃掉认证头**

type: function

  def merge_headers(base, override):
      # 提示：先 copy base，再遍历 override：None 就删，否则设置
      return {}

  {"A": "1"}, {"B": "2"} -> {"A": "1", "B": "2"}
