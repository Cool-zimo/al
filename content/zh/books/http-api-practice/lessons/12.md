# 12 Response 对象：把响应拆成 15 个零件

> 上一课我们拿到了一个 `response`。这一课把它彻底拆开——它身上有十几个属性，每一个都对应你在第 2 章学过的某个 HTTP 概念。学完这一课，你就知道面对任何响应该先看什么、后看什么、以及每个属性在什么时候会坑你。

## 先看全景

```python
import requests

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)

# 下面这些全是 r 身上的属性
r.status_code        # ① 状态码
r.ok                 # ② 是不是成功
r.reason             # ③ 状态文字
r.text               # ④ 正文（字符串）
r.content            # ⑤ 正文（字节）
r.json()             # ⑥ 正文解析成 Python 对象（这是方法，不是属性）
r.headers            # ⑦ 响应头
r.cookies            # ⑧ cookie
r.encoding           # ⑨ 编码
r.url                # ⑩ 最终 URL
r.history            # ⑪ 重定向历史
r.elapsed            # ⑫ 耗时
r.request            # ⑬ 对应的请求对象
r.is_redirect        # ⑭ 是否还要继续重定向
r.is_permanent_redirect  # ⑮ 是不是永久重定向
```

**注意 ⑥ `r.json()` 带括号**——它是**方法**（要执行），其他都是**属性**（直接取值）。这个区别新手经常搞错。

## ①②③ 状态三件套

```python
print(r.status_code)     # 200
print(r.ok)              # True
print(r.reason)          # 'OK'
```

| 属性 | 类型 | 说明 |
|---|---|---|
| `status_code` | `int` | 状态码。**拿它做判断** |
| `ok` | `bool` | `status_code < 400`。**快速判断用这个** |
| `reason` | `str` | 状态文字。**只给人看，别用来判断** |

**为什么不能用 `reason` 判断**？看这个：

```python
# 不同服务器返回的状态文字可能不同
"OK" / "ok" / "Success" / "请求成功"
```

规范没规定 `reason` 必须是某个固定字符串（虽然常见的是 `OK`）。**而且 HTTP/2 干脆取消了这个字段**——`requests` 在 HTTP/2 下会给你一个它自己生成的默认值。

**所以**：判断永远用 `status_code` 或 `ok`。

## ④⑤⑥ 正文的三种形态

这是最容易出事的一组。

### r.content：字节，永远是原始真相

```python
print(type(r.content))       # <class 'bytes'>
print(len(r.content))        # 1234（字节数）
```

**它是服务器发来的原始字节，一个都没动过**（除了自动解压）。

**什么时候必须用 `.content`**：

- 下载图片 / 视频 / PDF / 压缩包
- 出现乱码时，从这里重新解码
- 你要计算响应大小时

### r.text：解码后的字符串

```python
print(type(r.text))          # <class 'str'>
```

**它等价于** `r.content.decode(r.encoding)`。

**风险**：`r.encoding` 可能是猜错的（第 9 课讲过）。所以 `.text` 可能是乱码。

### r.json()：解析成 Python 对象

```python
data = r.json()              # 注意有括号！
print(type(data))            # <class 'dict'> 或 <class 'list'>
print(data["login"])         # 'Cool-zimo'
```

**它是"解码 + JSON 解析"两步合一**。

**什么时候会失败**：

```python
r = requests.get("https://example.com", timeout=10)
r.json()
# json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

**原因**：你请求的是一个 HTML 页面，它的正文是 `<html>...`，不是 JSON。`.json()` 试图把 HTML 当 JSON 解析，第一个字符 `<` 就不合法。

**教训**：**调用 `.json()` 之前，先确认响应确实是 JSON**。两种方法：

```python
# 方法一：看 Content-Type
if "application/json" in r.headers.get("Content-Type", ""):
    data = r.json()

# 方法二：直接 try（更常用）
try:
    data = r.json()
except ValueError:
    print("响应不是 JSON:", r.text[:200])
```

### 三者对比表

| | 类型 | 经过解码吗 | 经过 JSON 解析吗 | 用途 |
|---|---|---|---|---|
| `.content` | `bytes` | ❌ | ❌ | 二进制文件、重新解码 |
| `.text` | `str` | ✅ | ❌ | 查看文本、正则提取 |
| `.json()` | `dict`/`list` | ✅ | ✅ | API 数据 |

## ⑦ r.headers：响应头

```python
print(type(r.headers))                       # requests.structures.CaseInsensitiveDict
print(r.headers["Content-Type"])             # 大写能取
print(r.headers["content-type"])             # 小写也能取
print(r.headers.get("X-Not-Exist"))          # None（不抛异常）
```

三个要点：

1. **它是 `CaseInsensitiveDict`**，头名不区分大小写
2. **用 `.get()` 不要用 `[]`**——服务器不保证给你某个头
3. **值是字符串**。`Content-Length` 拿到的是 `"1234"`，要 `int()` 才能算数

**最常用的几个**：

```python
r.headers.get("Content-Type")        # 类型和字符集
r.headers.get("Content-Length")      # 大小（可能没有）
r.headers.get("X-RateLimit-Remaining")  # GitHub 限流剩余
r.headers.get("Retry-After")         # 429 时要等多久
r.headers.get("ETag")                # 内容指纹
```

## ⑧ r.cookies

```python
print(dict(r.cookies))               # {'session': 'abc123'}
print(r.cookies.get("session"))      # 'abc123'
```

类型是 `RequestsCookieJar`。**想当普通字典用就 `dict()` 转一下**。

**注意**：单个请求（不用 Session）拿到的 cookie 不会自动带到下一个请求。第 10 课讲过，要用 `Session`。

## ⑨ r.encoding

```python
print(r.encoding)               # 'utf-8'（可能来自头部，也可能是猜的）
print(r.apparent_encoding)      # 通过分析内容重新猜（属性，无括号）
```

**修乱码的标准操作**：

```python
r.encoding = r.apparent_encoding     # 改编码
text = r.text                        # 重新读（会按新编码重解码）
```

**再次强调**：**必须在读 `.text` 之前改**。因为 `.text` 是每次访问现算的，不缓存。

## ⑩ r.url：重定向后的真实地址

```python
r = requests.get("http://github.com", timeout=10)
print(r.url)
# 'https://github.com/'     ← 注意变成 https 了
```

**你请求的是 http，最终到的是 https** —— 因为服务器返回了重定向，`requests` 自动跟随了。

**什么时候有用**：调试"我明明请求 A，怎么拿到的是 B 的内容"。`r.url` 会告诉你最终落点。

## ⑪ r.history：重定向链

```python
r = requests.get("http://github.com", timeout=10)

print(len(r.history))            # 1
for resp in r.history:
    print(resp.status_code, resp.url)
# 301 http://github.com/
```

**`r.history` 是一个列表**，里面是**重定向过程中的每一个响应**，按顺序排列。

**重要细节**：**`r` 本身是最后一个响应（200）**，不在 history 里。history 只包含中间那些 3xx。

**什么时候有用**：

- 你想知道"到底重定向了几次"（重定向太多会拖慢速度）
- 你想知道重定向路径，排查配置错误

**可以关掉自动重定向**：

```python
r = requests.get("http://github.com", allow_redirects=False, timeout=10)
print(r.status_code)     # 301
print(r.headers["Location"])   # 'https://github.com/'
```

## ⑫ r.elapsed：耗时

```python
print(r.elapsed)                      # 0:00:00.234567
print(r.elapsed.total_seconds())      # 0.234567（秒，浮点数）
```

类型是 `datetime.timedelta`。用 `.total_seconds()` 转成浮点数最方便。

**它测的是什么**：**从发出请求到收到响应头**的时间，**不包括下载正文的时间**。

```python
import requests
import time

start = time.time()                    # ① 请求前计时
r = requests.get(url, timeout=10)
end = time.time()                      # ② 请求后计时

print(f"elapsed（不含下载正文）: {r.elapsed.total_seconds():.3f}s")
print(f"实际总耗时（含下载）: {end - start:.3f}s")
```

> **逐行拆解**
>
> - **① ②** 用 `time.time()` 手动计时，得到的是**完整耗时**（包括接收正文）
> - **`r.elapsed`** 只到响应头为止
> - **两者差很多时说明什么**：正文很大，或者网络下载慢。**这是判断"慢在哪"的简易方法**

## ⑬ r.request：发出去的那个请求

```python
print(r.request.method)          # 'GET'
print(r.request.url)             # 你请求的 URL
print(r.request.headers)         # 你发出的请求头 ★ 调试神器
print(r.request.body)            # 你发的请求体（GET 是 None）
```

**`r.request` 是 `PreparedRequest` 对象**——它代表"真正被发出去的那个请求"（经过了所有处理和重定向修正）。

**这是调试的头号工具**：

```python
# "我明明设了 Authorization，为什么 401？"
r = requests.get(url, headers={"Authorization": "Bearer xxx"}, timeout=10)
print(r.request.headers.get("Authorization"))    # 看看到底发没发
```

**最常见的答案**：**跨域重定向时 Authorization 被剥离了**（第 8 课讲过）。打印 `r.request.headers` 一眼就能看出来。

## ⑭⑮ 重定向标志

```python
r.is_redirect                # 响应是不是 3xx 且带 Location
r.is_permanent_redirect      # 是不是 301
```

**什么时候用**：你关掉了自动重定向（`allow_redirects=False`），需要自己判断要不要跟、以及是不是要更新书签。

一般情况用不到——`requests` 默认自动跟随重定向。

## 综合：一个"体检函数"

下面这个函数把常用属性一次性打印出来。**调试任何奇怪的响应时，先跑它**：

```python
import requests

def inspect(resp, body_limit=300):
    """把一个 Response 的关键信息打印出来，用于调试"""
    print("=" * 50)
    print(f"状态       : {resp.status_code} {resp.reason}")     # ①
    print(f"成功       : {resp.ok}")                             # ②
    print(f"最终 URL   : {resp.url}")                            # ③
    print(f"耗时       : {resp.elapsed.total_seconds():.3f}s")    # ④
    print(f"编码       : {resp.encoding}")                        # ⑤
    print(f"重定向次数 : {len(resp.history)}")                     # ⑥
    print("-" * 50)
    print("响应头:")
    for k, v in resp.headers.items():                            # ⑦
        print(f"  {k}: {v}")
    print("-" * 50)
    ct = resp.headers.get("Content-Type", "")                    # ⑧
    if "json" in ct:
        print("正文(JSON):")
        print(str(resp.json())[:body_limit])
    else:
        print("正文(文本):")
        print(resp.text[:body_limit])

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)
inspect(r)
```

> **逐行拆解**
>
> - **①** 状态和文字一起打，最省事
> - **②** `ok` 快速判断
> - **③** `url` 而不是你传的那个——**重定向后它会变**
> - **④** 耗时转浮点数
> - **⑤** 编码，乱码时第一要看的
> - **⑥** 重定向次数异常多说明配置有问题
> - **⑦** 头部全打出来。**很多问题的答案就在头部里**（限流剩余、内容类型、服务器标识）
> - **⑧** 根据 Content-Type 决定怎么展示正文。**避免对 HTML 调 `.json()` 报错**

**把这个函数存进你的工具箱**，后面每一课都能用上。

## 翻车现场

### 翻车一：对 HTML 调 .json()

```python
# ❌ 错误示范
r = requests.get("https://www.baidu.com", timeout=10)
data = r.json()      # JSONDecodeError
```

**现象**：`json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`

**原因**：百度返回的是 HTML。`.json()` 只能解析 JSON。

**教训**：**先看 Content-Type，再决定用 `.text` 还是 `.json()`**。

### 翻车二：以为 r.history 包含最终响应

```python
r = requests.get("http://github.com", timeout=10)
for resp in r.history:
    print(resp.status_code)      # 只打印了 301
# 你期望看到 301 和 200，但只有 301
```

**原因**：**`r` 本身就是最终响应**，`history` 只有中间过程。

**教训**：要完整链条就 `r.history + [r]`。

### 翻车三：把 r.json 当属性用

```python
# ❌ 错误
data = r.json        # 少了括号！
print(data["login"]) # TypeError: 'method' object is not subscriptable
```

**现象**：`TypeError: 'method' object is not subscriptable`

**原因**：`r.json` 是方法对象本身，不是调用结果。**它没有报错，直到你用 `[]` 时才炸**——错误信息离出错的地方很远，很难查。

**教训**：**记住 `.json()` 有括号，`.text` / `.content` 没有**。这是这几个属性里唯一的例外。

## 为什么这对你写代码有用

1. **顺序固定**：`status_code` → `headers` → 正文。**先看状态，再看头，最后才碰正文**
2. **`.content` / `.text` / `.json()` 是同一份数据的三种形态**，用错类型就崩
3. **`.json()` 是唯一带括号的**
4. **`r.request.headers` 是调试"我设的头没生效"的第一手段**
5. **`r.url` 和 `r.history` 揭示重定向真相**——"我请求 A 却拿到 B"的答案在这里
6. **`r.elapsed` 不含下载正文**，要测总耗时得自己计时

## 小结

- `Response` 有十几个属性，每个都对应一个 HTTP 概念
- **状态三件套**：`status_code`（判断用）/ `ok`（快速判断）/ `reason`（**只给人看**）
- **正文三形态**：`.content`（bytes，原始）/ `.text`（str，已解码）/ `.json()`（**方法，有括号**）
- **`.headers` 是 CaseInsensitiveDict**，**用 `.get()`**
- **`r.encoding` 可能是猜的**，乱码时改成 `apparent_encoding`（**要在读 text 之前**）
- **`r.url` 是重定向后的最终地址**；**`r.history` 只有中间过程，不含最终响应**
- **`r.elapsed` 只到响应头**，不含下载正文
- **`r.request.headers` 是调试神器**——"我设的头没生效"先看它
- ❌ 别对非 JSON 调 `.json()`；别把 `.json` 当属性；别指望 history 含最终响应

```quiz
q: 关于 r.history，下列说法正确的是？
options:
- 它包含所有响应，包括最终那个 200
- 它只包含重定向过程中的中间响应（3xx），最终响应是 r 本身，不在 history 里
- 它是一个字符串
- 只有在手动关闭重定向时才有值
answer: 1

```

```quiz
type: choice
exam: true
q: 下面这段代码错在哪？
   data = r.json
   print(data["login"])
options:

- r.json 是方法对象本身，少了括号，应该用 r.json()
```
