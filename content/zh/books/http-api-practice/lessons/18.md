# 18 请求侧的编码：中文提交为什么变乱码

> 第 9 课讲过**响应**的乱码（服务器发来的内容解码错了）。这一课讲另一半：**请求**的编码——你发出去的中文、文件名、表单字段，为什么到服务器那边变成了别的字。这是双向的，两边都要对。

## 编码问题是对称的

第 9 课的核心是：

```
发送方: 文字 --encode--> 字节 --传输--> 字节 --decode--> 文字: 接收方
```

**解码错了会乱码**（第 9 课），**编码错了同样会乱码**（这一课）。

而且在请求侧，问题**更难查**，因为：

> **你看不到服务器收到了什么。**

响应乱码你能 `print()` 出来看；请求乱码发生在**对方的机器上**，你只能靠推测。

**这就是为什么 httpbin 这类回显服务这么重要**——它让你看到"服务器视角"的请求。

## 场景一：JSON 请求体中的中文

### requests 怎么处理

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    json={"name": "张三", "city": "北京"},
    timeout=10,
)

print(r.request.headers["Content-Type"])
# application/json
```

**`json=` 时，`requests` 内部做的事**：

1. `json.dumps(obj)` → 字符串。**默认 `ensure_ascii=True`**，所以中文变成 `\u5f20\u4e09`
2. 编码成字节（UTF-8）
3. 发出去

**所以发出的字节里，中文其实是以 `\u5f20\u4e09` 这种 ASCII 转义形式存在的**。

**这有问题吗？** 没有。因为：

- **`\u5f20\u4e09` 是合法的 JSON**，任何标准解析器都会还原成"张三"
- 全是 ASCII，**不存在编码问题**，管你服务器用什么编码都不会错

**这其实是 JSON 设计上的一个巧妙之处**：用 ASCII 转义绕开了所有字符集争议。

### 什么时候会出问题

**情况一：对方的 JSON 解析器有 bug**（很少见但存在）。

**情况二：你想让请求体可读**（抓包时看到真实中文）。

**解决**：自己 dumps 并关掉转义：

```python
import json
import requests

payload = json.dumps({"name": "张三"}, ensure_ascii=False)   # ① 关掉转义

r = requests.post(
    "https://httpbin.org/post",
    data=payload.encode("utf-8"),                             # ② 手动编码成字节
    headers={"Content-Type": "application/json; charset=utf-8"},  # ③ 声明
    timeout=10,
)
```

> **逐行拆解**
>
> - **①** `ensure_ascii=False` 让 dumps 保留真实中文字符
> - **②** **必须手动 encode**。`data=` 收到字符串时不会帮你编码，而 HTTP 要的是字节
> - **③** 明确声明 UTF-8。**JSON 规范本来就规定 UTF-8**，写上更保险

**注意 ② 的坑**：如果只写 `data=payload`（字符串而非字节），`requests` 会用 **Latin-1** 去编码它，中文直接报错或产生错误字节。

## 场景二：表单中的中文

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    data={"name": "张三"},
    timeout=10,
)

print(r.request.body)
# name=%E5%BC%A0%E4%B8%89        ← 百分号编码
```

**这是正确的。** 表单格式规定：非 ASCII 字符必须做百分号编码（第 13 课讲过）。

服务器收到 `name=%E5%BC%A0%E4%B8%89`，解码后得到"张三"。**标准流程，不会错。**

**会出问题的情况**：

```python
# ❌ 错误：自己拼表单字符串
data = f"name={name}"        # 中文没编码
r = requests.post(url, data=data, timeout=10)
```

**原因**：`%E5%BC%A0` 这种编码没人做，中文原样进了请求体。服务器可能：
- 按 Latin-1 解读 → 乱码
- 直接拒绝

**教训**：**表单用 `data={dict}`，别手拼字符串**。

## 场景三：URL 里的中文（复习）

第 13 课讲过，这里复习一个容易忘的点：

```python
# ✅ 正确
requests.get(url, params={"q": "中文"})

# ❌ 错误
requests.get(f"{url}?q=中文")
```

**`requests` 会把中文编码成 `%E4%B8%AD%E6%96%87`**。不编码的话，某些服务器/代理会出错。

## 场景四：文件名中的中文（真实的坑）

上传文件时文件名有中文，这是**最容易出问题**的场景之一。

### 老问题：RFC 2231 与各家实现不一

HTTP 规范里，文件名出现在 `Content-Disposition` 头里：

```text
Content-Disposition: form-data; name="file"; filename="头像.jpg"
```

**问题**：**HTTP 头部理论上只能是 ASCII**。中文文件名怎么放？

历史上各家做法不一，主要有两种：

```
方式 A: filename="%E5%A4%B4%E5%83%8F.jpg"     ← 百分号编码
方式 B: filename="头像.jpg"; filename*=UTF-8''%E5%A4%B4%E5%83%8F.jpg
                                              ↑ RFC 5987 的标准做法
```

**方式 B 是现在的标准**（RFC 5987，2007 年）：`filename` 放 ASCII 兜底版本，`filename*` 放完整的 UTF-8 编码版本。

### requests 怎么处理

```python
import requests

r = requests.post(
    "https://httpbin.org/post",
    files={"file": ("头像.jpg", b"image-bytes", "image/jpeg")},
    timeout=10,
)
```

**`requests` 会自动处理**——它会按 RFC 5987 生成正确的值。**你只要传对文件名就行**。

### 但接收方可能有问题

**如果对方的服务器比较老**，可能只认百分号编码或者 Latin-1。**这时候你会看到服务器上的文件名变成乱码。**

**排查方法**：

```python
print(r.request.body[:500])        # 看请求体里 filename 长什么样
```

如果看到 `filename="å¤´åƒ.jpg"` 这种（Latin-1 解读 UTF-8 字节的典型症状），说明**发送方用了错误的编码**。但这是 `requests` 内部行为，你很难改。

**解决办法**：
- 升级 requests 到最新版
- 或者**把文件名改成 ASCII**（拼音或英文），这是最务实的方案

## 调试请求编码的方法论

这是本课最实用的一节。**遇到"服务器说收到的数据不对"时，按这个顺序查**：

### 第一步：用 httpbin 回显

```python
import requests

r = requests.post("https://httpbin.org/post", json={"name": "张三"}, timeout=10)
d = r.json()

print("Content-Type:", d["headers"].get("Content-Type"))
print("服务器收到的 JSON:", d["json"])          # ① 看解析结果
print("原始 body:", d["data"][:300])            # ② 看原始字节
```

> **①** 如果这里是 `{'name': '张三'}`，说明一切正常
> **②** 如果 ① 不对，看原始字节判断是编码问题还是格式问题

### 第二步：看自己发出去的字节

```python
print(r.request.body)                # 发出去的请求体
print(type(r.request.body))          # bytes 还是 str
print(r.request.headers)             # 特别是 Content-Type 有没有 charset
```

**关键检查点**：

| 检查项 | 期望 |
|---|---|
| `Content-Type` | 和你的实际格式一致 |
| 有中文时 | 应有 `charset=utf-8` 或用了 `\u` 转义 |
| `body` 是 bytes | 编码正确 |

### 第三步：确认对方期望什么

**很多"编码问题"其实是"格式问题"**：你发了 JSON 但对方要表单，或者反过来。这在第 16 课讲过。

**先看文档确认格式，再查编码。顺序别反。**

## 一个通用的"中文安全"检查函数

```python
def check_request_encoding(prepared):
    """检查一个 PreparedRequest 的编码情况，用于调试"""
    body = prepared.body
    ct = prepared.headers.get("Content-Type", "")

    print(f"Content-Type: {ct}")

    if body is None:
        print("body: 无")
        return

    if isinstance(body, bytes):
        print(f"body 类型: bytes, 长度 {len(body)}")
        # ① 尝试用 UTF-8 解码看看
        try:
            text = body.decode("utf-8")
            print(f"UTF-8 解码成功: {text[:100]}")
        except UnicodeDecodeError:
            print("UTF-8 解码失败（可能是二进制数据，正常）")
    else:
        print(f"body 类型: str（requests 会用 Latin-1 编码，中文会出错！）")

    # ② 检查是否声明了字符集
    if "charset" in ct.lower():
        print("已声明 charset ✓")
    else:
        print("未声明 charset ⚠️ 对方可能猜错编码")

r = requests.post("https://httpbin.org/post", json={"name": "张三"}, timeout=10)
check_request_encoding(r.request)
```

> **逐行拆解**
>
> - **①** 尝试 UTF-8 解码。**能解出来说明内容是 UTF-8 文本**；解不出来可能是二进制（正常）或者用了别的编码（有问题）
> - **②** 检查有没有声明 charset。**没声明的话对方只能猜**
>
> **为什么要检查 `isinstance(body, bytes)`**：**如果 body 是 str 类型，`requests` 会用 Latin-1 编码它**——这对中文是灾难。这只在你自己手动传字符串时才会发生（`json=` 和 `files=` 都不会）

## 翻车现场

### 翻车一：手动传 str 给 data=

```python
# ❌ 错误
payload = json.dumps({"name": "张三"}, ensure_ascii=False)   # 含真实中文的 str
r = requests.post(url, data=payload, timeout=10)
# UnicodeEncodeError 或服务器收到乱码
```

**现象**：要么直接报 `UnicodeEncodeError: 'latin-1' codec can't encode characters`，要么服务器收到一堆乱码字节。

**原因**：**`data=` 收到 str 时用 Latin-1 编码**（这是 HTTP/1.1 时代的遗留默认），Latin-1 根本装不下中文。

**教训**：**用 `json=`**，或者手动 `.encode("utf-8")` 后再传，**并声明 charset**。

### 翻车二：以为 \uXXXX 是乱码

```python
r = requests.post(url, json={"name": "张三"}, timeout=10)
print(r.request.body)
# b'{"name": "\\u5f20\\u4e09"}'      ← 你以为是乱码
```

**现象**：看到 `\u5f20` 以为编码坏了，花一下午去"修"。

**原因**：**这是正确的 JSON 转义**。`json.dumps` 的 `ensure_ascii=True` 默认值。

**验证**：

```python
import json
print(json.loads('{"name": "\\u5f20\\u4e09"}')["name"])
# 张三        ← 完全正常
```

**教训**：**`\uXXXX` 不是 bug**。先 `json.loads` 验证再下结论。

### 翻车三：文件名中文在服务器上变成乱码

**现象**：上传成功，但服务器上的文件名是 `å¤´åƒ.jpg` 或 `???`。

**原因**：三方不一致——你发的编码、对方的解析方式、对方存储的编码，任何一个环节错了都会这样。

**排查**：

```python
r = requests.post(url, files={"f": ("头像.jpg", b"x")}, timeout=10)
print(r.request.body[:400])       # 看 filename 是怎么编码的
```

**务实解决**：

1. 升级 requests
2. **把文件名改成 ASCII**（`touxiang.jpg`）——这一招解决 90% 的问题
3. 如果必须保留中文，和后端约定好编码方式

## 为什么这对你写代码有用

1. **编码问题是对称的**：响应要正确解码，请求要正确编码
2. **请求侧更难查**，因为你看不到对方收到了什么——**用 httpbin 回显**
3. **JSON 的 `\uXXXX` 转义不是 bug**，它反而绕开了所有字符集问题
4. **`data=` 传 str 会用 Latin-1 编码**，中文必炸。要么用 `json=`，要么手动 encode
5. **表单的中文由 `data={dict}` 自动编码**，别手拼
6. **中文文件名是真实的高频坑**，最省事的方案是改成 ASCII

## 小结

- **请求侧和响应侧都要编码正确**。请求侧更难查，因为看不到对方收到了什么
- **JSON 里的中文默认是 `\uXXXX` 转义**（`ensure_ascii=True`）。**这是正确的，不是乱码**
- **要真实中文**：`json.dumps(..., ensure_ascii=False)` + `.encode("utf-8")` + 声明 charset
- **表单中文由 `data={dict}` 自动百分号编码**，不要手拼字符串
- **URL 中文由 `params=` 自动编码**
- **中文文件名是高频坑**：RFC 5987 规定 `filename*`，但老服务器可能不认
- **`data=` 传 str 会用 Latin-1 编码** → 中文必炸
- **调试三步**：httpbin 回显 → 检查自己发的字节 → 确认对方期望的格式
