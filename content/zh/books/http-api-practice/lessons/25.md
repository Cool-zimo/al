# 25 文件上传与下载：从几 KB 到几 GB

> 前面所有例子都是"小数据"——几十 KB 的 JSON。这一课处理真正的文件：几 MB 的图片、几百 MB 的视频。核心问题是**内存**——把 1GB 文件读进内存再发出去，你的程序会崩。

## 下载：先看小文件

```python
import requests

r = requests.get("https://example.com/photo.jpg", timeout=10)
r.raise_for_status()

with open("photo.jpg", "wb") as f:        # ① "wb" 二进制写
    f.write(r.content)                     # ② r.content 是字节

print(f"保存了 {len(r.content)} 字节")
```

> **逐行拆解**
>
> - **① `"wb"`**：`w`=写，`b`=二进制。**写字节必须带 `b`**
> - **② `r.content`**：**不是 `r.text`**（第 9 课讲过，用 `.text` 会破坏图片）
>
> **这个写法的问题**：**`r.content` 会把整个响应读进内存**。
>
> - 5MB 图片 → 内存里 5MB，没问题
> - **1GB 视频 → 内存里 1GB**，可能直接 OOM（内存溢出）

## 流式下载：stream=True

**大文件必须流式下载**——边收边写，内存里只保留一小块。

```python
import requests

url = "https://example.com/big-video.mp4"

with requests.get(url, stream=True, timeout=10) as r:      # ① stream=True
    r.raise_for_status()

    with open("video.mp4", "wb") as f:
        for chunk in r.iter_content(chunk_size=8192):       # ② 分块读取
            f.write(chunk)                                   # ③ 边收边写
```

> **逐行拆解**
>
> - **① `stream=True`**：告诉 requests **先只下载响应头，不下载正文**。正文等你主动去读
> - **② `iter_content(chunk_size=8192)`**：**生成器**，每次产出 8192 字节（8KB）。**关键是它不会一次性把全部内容读进来**
> - **③** 每收到一块就写盘。**内存里始终只有 8KB**
>
> **两个 `with` 嵌套**：外层保证连接关闭，内层保证文件关闭。**缺任何一个都会泄漏资源**

### 为什么是 8192

`chunk_size=8192` 是个常用值（8KB）。**原理**：

- 太小（比如 100）→ 循环次数太多，Python 开销大
- 太大（比如 10MB）→ 内存占用大，失去流式意义
- **8KB ~ 64KB 是甜点区**

**实际上**：这个值**不是"网络每次收这么多"**，而是"Python 每次从缓冲区取这么多"。网络层有自己的缓冲。

### stream=True 时必须注意的两件事

**一、不用 `with` 就要手动 close**

```python
r = requests.get(url, stream=True, timeout=10)
try:
    for chunk in r.iter_content(8192):
        f.write(chunk)
finally:
    r.close()          # 必须！否则连接不释放
```

**二、如果不读完就关闭，连接不会复用**

```python
r = requests.get(url, stream=True, timeout=10)
print(r.headers["Content-Length"])      # 只看头，不读正文
r.close()                                # 连接被丢弃，不能复用
```

**这正好是 HEAD 的替代方案**（第 6 课讲过 HEAD 只要头）—— 不过**用 HEAD 更合适**。

## 带进度条的下载

```python
import requests
import os

def download_with_progress(url, path, chunk_size=8192):
    """下载文件并显示进度"""
    with requests.get(url, stream=True, timeout=10) as r:
        r.raise_for_status()

        total = int(r.headers.get("Content-Length", 0))    # ① 总大小
        downloaded = 0

        with open(path, "wb") as f:
            for chunk in r.iter_content(chunk_size=chunk_size):
                if not chunk:                               # ② 过滤 keep-alive 空块
                    continue
                f.write(chunk)
                downloaded += len(chunk)

                if total:                                   # ③ 有总大小才算百分比
                    pct = downloaded * 100 // total
                    print(f"\r进度: {pct}%  ({downloaded}/{total} 字节)", end="")

        print()          # 换行

download_with_progress("https://example.com/big.zip", "big.zip")
```

> **逐行拆解**
>
> - **① `Content-Length`** 可能是 None（分块传输时没有）。**用 `int(..., 0)` 兜底为 0**
> - **② `if not chunk: continue`** —— **`iter_content` 有时会产出空的 keep-alive 块**。不过滤的话 `f.write(b"")` 无害，但会让计数逻辑混乱
> - **③ `if total:`** —— 没有总大小时跳百分比计算，只显示已下载字节数
> - **`\r` + `end=""`**：让进度条在同一行刷新。**这是终端进度条的标准技巧**

## 断点续传：Range 头

**下载到一半断了，能不能从断点继续？** 能，用 `Range` 头。

```python
import requests
import os

def resume_download(url, path):
    """支持断点续传的下载"""
    # ① 看本地已有多少
    if os.path.exists(path):
        downloaded = os.path.getsize(path)
    else:
        downloaded = 0

    headers = {}
    if downloaded:
        headers["Range"] = f"bytes={downloaded}-"      # ② 从断点开始要

    with requests.get(url, headers=headers, stream=True, timeout=10) as r:
        # ③ 服务器可能不支持断点续传
        if downloaded and r.status_code != 206:
            print("服务器不支持断点续传，重新下载")
            downloaded = 0          # 从头开始

        r.raise_for_status()

        mode = "ab" if downloaded else "wb"             # ④ 追加或新建
        with open(path, mode) as f:
            for chunk in r.iter_content(8192):
                if chunk:
                    f.write(chunk)
                    downloaded += len(chunk)

    return downloaded
```

> **逐行拆解**
>
> - **①** 检查本地文件大小，作为断点位置
> - **② `Range: bytes=5000-`** 意思是"从第 5000 个字节开始给我"
> - **③ 状态码 206 Partial Content** 表示服务器支持并返回了部分内容。**如果返回 200，说明它不支持 Range，会从头发完整文件**——这时候必须从头写（`"wb"`）
> - **④ `"ab"`** 是追加模式（append binary），`"wb"` 是新建（会清空）
>
> **这个判断很关键**：**不问 206 就盲目追加，会得到一份"前半段旧 + 后半段新"的损坏文件**

## 上传：小文件

第 17 课讲过基础，这里补全：

```python
import requests

with open("photo.jpg", "rb") as f:                    # ① "rb" 二进制读
    r = requests.post(
        "https://httpbin.org/post",
        files={"avatar": ("photo.jpg", f, "image/jpeg")},   # ② 元组写法
        timeout=30,                                    # ③ 上传超时给长一点
    )

print(r.status_code)
```

> **逐行拆解**
>
> - **① `"rb"`**：读二进制。**注意 `with` 保证文件关闭**
> - **② 元组 `(文件名, 文件对象, MIME)`**。第 17 课讲过——**推荐这个写法**，因为服务器能拿到真实文件名
> - **③ `timeout=30`**：**上传比下载慢**，超时要给更长。1MB 的文件在慢速网络下可能要几十秒

**为什么不直接 `files={"avatar": open(...)}`**？因为那样**文件句柄不会被关闭**（没有 with）。虽然 `requests` 读完会帮你关，但显式用 `with` 更好。

## 上传：大文件

**`files=` 的问题**：`requests` 会把整个文件读进内存再编码成 multipart。

**100MB 的文件 → 内存占用可能 200MB+**。

### 方案一：用 requests-toolbelt 流式上传

```bash
pip install requests-toolbelt
```

```python
from requests_toolbelt.multipart.encoder import MultipartEncoder
import requests

# ① 流式编码器，不会一次性读入内存
encoder = MultipartEncoder(
    fields={
        "description": "我的视频",
        "video": ("video.mp4", open("video.mp4", "rb"), "video/mp4"),
    }
)

r = requests.post(
    "https://httpbin.org/post",
    data=encoder,                                        # ② 直接传编码器
    headers={"Content-Type": encoder.content_type},       # ③ 必须带 boundary
    timeout=60,
)
```

> **逐行拆解**
>
> - **① `MultipartEncoder`** 是 requests-toolbelt 提供的**流式** multipart 编码器
> - **② `data=encoder`**：直接把编码器对象传给 `data=`。requests 会边读边发
> - **③ `encoder.content_type`**：**必须手动设置**，因为它包含 boundary（第 17 课讲过 boundary 必须带）
>
> **注意 ③** 就是第 17 课"用 files= 时别手动设 Content-Type"的**例外**——这里你必须设，因为 `data=` 不会自动加。

### 方案二：分块上传（很多云存储用这个）

大文件服务的常见做法：**把文件切成块，一块一块传**。

```python
import requests
import os

def upload_in_chunks(path, upload_url, chunk_size=5 * 1024 * 1024):
    """分块上传（示意代码，实际接口因服务而异）"""
    total_size = os.path.getsize(path)
    uploaded = 0

    with open(path, "rb") as f:
        index = 0
        while True:
            chunk = f.read(chunk_size)          # ① 每次读一块
            if not chunk:
                break

            # ② 告诉服务器这是第几块、总共有多大
            r = requests.post(
                upload_url,
                data=chunk,
                headers={
                    "Content-Type": "application/octet-stream",
                    "X-Chunk-Index": str(index),
                    "X-Total-Size": str(total_size),
                },
                timeout=60,
            )
            r.raise_for_status()

            uploaded += len(chunk)
            index += 1
            print(f"已上传 {uploaded}/{total_size}")

    return uploaded
```

> **逐行拆解**
>
> - **① `f.read(chunk_size)`** 每次只读一块（这里 5MB）。**内存占用固定**
> - **②** 用自定义头告诉服务器块序号。**具体头名因服务而异**（AWS S3、七牛、阿里云各不相同）
>
> **这是分块上传的原理**。实际项目里**用服务商提供的 SDK**，不要自己写——各家协议细节很多。

## 校验：确认文件没坏

下载完（或上传前）**校验哈希**是好习惯：

```python
import requests
import hashlib

def sha256_file(path, chunk_size=8192):
    """流式计算文件 SHA256（不占内存）"""
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(chunk_size), b""):   # ① 读到空为止
            h.update(chunk)
    return h.hexdigest()

print(sha256_file("big.zip"))
```

> **逐行拆解**
>
> - **① `iter(lambda: f.read(chunk_size), b"")`**：**这是 Python 里"分块读文件直到 EOF"的惯用法**。
>   - `iter(可调用对象, 哨兵值)`：反复调用直到返回哨兵值 `b""`（空字节）
>   - 比 `while True` + `if not chunk: break` 简洁
>   - **注意必须是 `b""`（空字节串）而不是 `""`（空字符串）**，因为读的是二进制
>
> **为什么流式**：1GB 文件如果 `f.read()` 一次性读进来，内存就爆了。**哈希计算可以增量进行**（`h.update()` 多次调用），所以能流式

**比对**：

```python
expected = "abc123..."          # 从下载页面拿到的官方哈希
actual = sha256_file("big.zip")

if actual == expected:
    print("文件完整 ✓")
else:
    print("文件损坏或被篡改 ✗")
```

## 完整的下载函数

把这一课组合起来：

```python
import requests
import os
import hashlib
import logging

def download(url, path, chunk_size=8192, timeout=30, expected_sha256=None):
    """
    下载文件（流式、支持断点续传、可选校验）
    返回 True 表示成功
    """
    # ① 断点续传
    resume = 0
    headers = {}
    if os.path.exists(path):
        resume = os.path.getsize(path)
        if resume:
            headers["Range"] = f"bytes={resume}-"
            logging.info(f"断点续传，已有 {resume} 字节")

    mode = "ab" if resume else "wb"

    try:
        with requests.get(url, headers=headers, stream=True, timeout=timeout) as r:
            # ② 服务器不支持续传就从头来
            if resume and r.status_code != 206:
                logging.warning("服务器不支持断点续传，重新开始")
                resume = 0
                mode = "wb"

            if not r.ok:
                logging.error(f"HTTP {r.status_code}")
                return False

            with open(path, mode) as f:
                for chunk in r.iter_content(chunk_size):
                    if chunk:
                        f.write(chunk)

    except requests.exceptions.RequestException as e:
        logging.error(f"下载失败: {e}")
        return False

    # ③ 可选校验
    if expected_sha256:
        actual = sha256_file(path)
        if actual != expected_sha256:
            logging.error(f"校验失败: 期望 {expected_sha256}, 实际 {actual}")
            return False
        logging.info("校验通过 ✓")

    return True
```

> **逐行拆解**
>
> - **①** 检查本地文件，准备续传
> - **② 206 检查**（前面讲过的关键判断）
> - **③** 校验放在最后。**只有提供了 expected_sha256 才校验**
>
> **这个函数可以放进工具箱**，覆盖了大文件下载的主要需求。

## 翻车现场

### 翻车一：用 r.text 下载

第 9 课讲过，这里重申因为**太常见**：

```python
# ❌ 图片损坏
with open("photo.jpg", "w") as f:
    f.write(r.text)
```

**教训**：**二进制文件一律 `.content` + `"wb"`**。

### 翻车二：忘了 stream=True 下载大文件

```python
# ❌ 1GB 文件直接进内存
r = requests.get(big_url, timeout=10)
with open("big.zip", "wb") as f:
    f.write(r.content)          # 内存爆炸
```

**现象**：小文件测试正常，遇到大文件直接 MemoryError 或者系统卡死。

**教训**：**超过 10MB 就用 `stream=True` + `iter_content`**。

### 翻车三：断点续传没检查 206

```python
# ❌ 错误
headers = {"Range": f"bytes={resume}-"}
r = requests.get(url, headers=headers, stream=True, timeout=10)
with open(path, "ab") as f:        # 盲目追加
    ...
```

**现象**：服务器不支持 Range，返回 200 和完整文件，你追加到旧数据后面 → **文件大小翻倍，且是损坏的**。

**教训**：**必须检查 `r.status_code == 206`**，不是 206 就从头写。

### 翻车四：上传时 timeout 太短

```python
# ❌ 错误
requests.post(url, files={"f": big_file}, timeout=10)     # 10 秒不够
```

**现象**：大文件上传到一半超时，抛出 Timeout。文件没传完，但服务器可能已经收了一部分。

**教训**：**上传/下载的 timeout 要比普通 API 调用长**（30~120 秒，视文件大小）。

## 为什么这对你写代码有用

1. **小文件 `.content` + `"wb"`，大文件 `stream=True` + `iter_content`**
2. **`chunk_size` 8KB~64KB 是甜点区**
3. **断点续传必须检查 206**，否则会拼接出损坏文件
4. **上传用 `files=` 元组写法**；超大文件用 toolbelt 流式或分块
5. **哈希校验要流式计算**（`h.update()` 增量）
6. **文件操作的 timeout 要比 API 调用长**
7. **`iter(lambda: f.read(n), b"")`** 是分块读文件的惯用法

## 小结

- **小文件**：`f.write(r.content)` + `"wb"`
- **大文件**：`stream=True` + `iter_content(chunk_size=8192)`，**内存只占一块**
- **两 `stream` 要点**：用 `with` 或手动 `close()`；不读完连接不复用
- **进度条**：`Content-Length` 算百分比，`\r` + `end=""` 同行刷新，**过滤空 chunk**
- **断点续传**：`Range: bytes=N-` + **检查 206** + `"ab"` 追加
- **上传**：`files={"k": ("name", f, "mime")}`，**用 `with` 打开文件**
- **超大文件**：toolbelt 的 `MultipartEncoder`（**必须手动设 Content-Type**）或分块上传
- **校验**：`hashlib` + 流式 `update()`，**`iter(lambda: f.read(n), b"")`**
- ❌ 别用 `.text` 下载二进制；大文件别忘 stream；**续传别忘检查 206**；文件操作 timeout 给长

```quiz
type: choice
exam: true
q: 断点续传时，为什么要检查状态码是不是 206？
options:
- 206 表示成功，和 200 一样
- 206 Partial Content 表示服务器支持 Range 并只返回了部分内容；返回 200 说明它不支持，会把完整文件从头发过来，此时若盲目追加会得到损坏文件
- 206 是错误的
- 只是惯例，没有实际作用
answer: 1
```
