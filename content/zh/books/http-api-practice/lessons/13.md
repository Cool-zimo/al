# 13 查询参数与编码：为什么空格要写成 %20

> 你在地址栏见过 `?q=python&page=2` 这种东西。这一课讲它叫什么、怎么用 `requests` 传、以及**为什么直接拼字符串会出事**——中文、空格、`&`、`=` 这些字符在 URL 里有特殊含义，处理不当会把你的参数切碎。

## 什么是查询参数

看一个完整的 URL：

```
https://api.github.com/search/repositories?q=python&sort=stars&order=desc
└────────────┬────────────────────────┘ └──────────────┬──────────────────┘
          基础地址（scheme+host+path）              查询字符串（query string）
```

**查询字符串（query string）** 是 `?` 后面的那一段，格式是：

```
?键1=值1&键2=值2&键3=值3
```

它的作用：**给这个请求附加参数**。搜索关键词、页码、排序方式、过滤条件，都放这儿。

### 为什么叫"查询"参数

这个名字来自数据库时代的习惯——`?` 后面常常就是 SQL 查询条件。今天它早已不限于"查询"，但名字留下来了。

### 它和路径的区别

```
/users/123          ← 路径：标识"哪个资源"
/users?page=2       ← 查询参数：修饰"怎么给你"
```

**一般原则**：
- **路径**标识资源本身
- **查询参数**是可选的修饰（分页、过滤、排序）

所以 `/users/123` 和 `/users?page=2` 是两种东西，不要混用。

## 用 params= 传参数

`requests` 提供了 `params` 参数，你给它一个**字典**：

```python
import requests

r = requests.get(                          # ①
    "https://api.github.com/search/repositories",
    params={                               # ② 用字典，不要拼字符串
        "q": "python",
        "sort": "stars",
        "order": "desc",
        "per_page": 10,
    },
    timeout=10,
)

print(r.url)                               # ③ 看看最终拼成了什么
```

> **逐行拆解**
>
> - **①** `requests.get()` 的第二个参数是 `params`。**它是关键字参数**——不要写成位置参数，虽然技术上允许，但可读性差
> - **②** 字典的**键是参数名，值是参数值**。**值可以是字符串、数字、布尔**，`requests` 会帮你转成字符串
> - **③** **`r.url` 会显示最终拼好的完整 URL**。这是验证"我传的参数对不对"的最快方法

运行后 `r.url` 大概是：

```
https://api.github.com/search/repositories?q=python&sort=stars&order=desc&per_page=10
```

**注意数字 `10` 变成了字符串**——HTTP 是文本协议，URL 里没有"数字"这个概念。

### 为什么不用字符串拼接

你完全可以手动拼：

```python
# 能跑，但不推荐
url = f"https://api.github.com/search/repositories?q={keyword}&sort=stars"
r = requests.get(url, timeout=10)
```

**问题在哪？** 往下看。

## URL 编码：URL 里不是什么字符都能放

### 哪些字符有问题

URL 里有几个字符是**有特殊含义的保留字符**：

| 字符 | 在 URL 里的作用 |
|---|---|
| `?` | 开始查询字符串 |
| `&` | 分隔参数 |
| `=` | 分隔键和值 |
| `#` | 片段标识符（锚点） |
| `/` | 路径分隔 |
| `+` | 历史上表示空格 |
| `%` | 编码引导符 |

**如果你的参数值里包含这些字符，就必须编码**，否则 URL 会被解析错。

### 一个具体的灾难

假设用户搜索 `python & java`：

```python
# ❌ 手动拼接
keyword = "python & java"
url = f"https://example.com/search?q={keyword}"
print(url)
# https://example.com/search?q=python & java
```

现在服务器收到这个 URL，它会怎么解析？

```
q = "python "        ← 到 & 就断了
（后面多了个莫名其妙的参数 " java"）
```

**用户搜的是"python & java"，服务器收到的却是 `q="python "` 加上一个无名参数。** 搜索结果完全不对，而且不报错。

### 正确的做法

```python
# ✅ 用 params=
r = requests.get(
    "https://example.com/search",
    params={"q": "python & java"},
    timeout=10,
)
print(r.url)
# https://example.com/search?q=python+%26+java
```

看 `&` 变成了 **`%26`**。这就是**百分号编码（percent-encoding）**，也叫 URL 编码。

## 百分号编码是什么

规则很简单：

> **把字符的 UTF-8 字节用十六进制表示，每个字节前面加 `%`。**

```
&  的 UTF-8 字节是 0x26      → %26
空格 的 UTF-8 字节是 0x20     → %20  （在查询串里常写成 +）
中  的 UTF-8 字节是 E4 B8 AD  → %E4%B8%AD
```

所以 `中文` 编码后是 `%E4%B8%AD%E6%96%87`。

**为什么这么设计**：因为 `%` 后面跟两位十六进制，就不会和任何保留字符冲突。`%` 自己则编码成 `%25`。

### 空格的特殊性：`%20` 还是 `+`

这是个历史遗留的坑：

| 场景 | 空格编码成 |
|---|---|
| 路径中 | `%20` |
| **查询字符串中** | **`+` 或 `%20` 都可以** |

`+` 来自早期 HTML 表单的 `application/x-www-form-urlencoded` 格式。**两种服务器都应该能识别**，但个别老旧服务器只认其中一种。

`requests` 默认用 **`+`**（因为它用的是 urlencode）。这符合主流做法。

## 让 requests 帮你编码

**这是本课最重要的结论**：

> **永远用 `params=` 传参数，不要手动拼字符串。**

`requests` 会自动做三件事：

1. 把字典转成 `k=v&k=v` 的形式
2. 对**键和值**都做百分号编码
3. 处理 None 值（**None 会被跳过**，不出现在 URL 里）

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={
        "q": "中文 & 空格",          # ① 中文、&、空格
        "n": None,                    # ② None 会被跳过
        "page": 2,                    # ③ 数字会转字符串
        "flag": True,                 # ④ 布尔会转成 "True"
    },
    timeout=10,
)
print(r.url)
```

输出类似：

```
https://httpbin.org/get?q=%E4%B8%AD%E6%96%87+%26+%E7%A9%BA%E6%A0%BC&page=2&flag=True
```

> **逐行拆解**
>
> - **①** `中文 & 空格` 被完整编码了。**`&` 变成 `%26`，不会切断参数**
> - **②** **`n=None` 直接不出现在 URL 里**。这非常实用——你可以无条件传一堆参数，用 None 表示"这次不用这个参数"
> - **③** `page=2` 数字自动转字符串
> - **④** 布尔 `True` 变成字符串 `"True"`（**首字母大写**）。**注意有些 API 期望 `true` 小写或 `1`**，遇到这种情况自己转成字符串传

## 同一个参数多个值

有些 API 允许同一个参数出现多次：

```
?tag=python&tag=http&tag=json
```

用 `params=` 时，给一个**列表**：

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={"tag": ["python", "http", "json"]},    # ① 列表
    timeout=10,
)
print(r.url)
# https://httpbin.org/get?tag=python&tag=http&tag=json
```

> **逐行拆解**
>
> - **①** 值是列表时，`requests` 会**重复这个键**。这正是 HTTP 规范允许的写法
> - **注意**：不是所有服务器都支持这种格式。有些期望 `tag=python,http,json`（逗号分隔）。**读 API 文档确认**

## 已经编码过的值怎么办

如果你拿到的值**已经是编码过的**（比如从别处复制来的 URL 片段），再编码一次会变成双编码：

```
原始:  python & java
编码1次: python+%26+java
编码2次: python%2B%2526%2Bjava    ← 坏了
```

**`requests` 会编码你给的值**，所以如果你给它已编码的字符串，就会被编码两次。

**解决办法**：先解码，再交给 `requests`：

```python
from urllib.parse import unquote

already = "python+%26+java"
decoded = unquote(already)              # 'python & java'

r = requests.get(url, params={"q": decoded}, timeout=10)   # 让 requests 重新编码
```

## 手动编码：urllib.parse

有时候你需要自己编码（比如给别人生成链接）。标准库提供了工具：

```python
from urllib.parse import urlencode, quote, quote_plus

# 编码一整个字典 → 查询字符串
print(urlencode({"q": "中文 & 空格", "page": 2}))
# q=%E4%B8%AD%E6%96%87+%26+%E7%A9%BA%E6%A0%BC&page=2

# 编码单个值（用于查询串，空格 → +）
print(quote_plus("python & java"))
# python+%26+java

# 编码单个值（用于路径，空格 → %20）
print(quote("python & java"))
# python%20%26%20java

# 解码
print(unquote("python+%26+java"))
# python & java
```

**三者的区别**：

| 函数 | 用途 | 空格变成 |
|---|---|---|
| `urlencode(dict)` | 整个字典 → 查询字符串 | `+` |
| `quote_plus(s)` | 单个值，用于查询串 | `+` |
| `quote(s)` | 单个值，用于**路径** | `%20` |

**什么时候用哪个**：
- 拼查询串 → `urlencode` 或 `quote_plus`
- 拼路径（比如文件名里有空格） → `quote`

## 翻车现场

### 翻车一：中文搜索结果不对

```python
# ❌ 错误示范
keyword = "中文"
url = f"https://api.example.com/search?q={keyword}"
r = requests.get(url, timeout=10)
```

**现象**：有时候能用，有时候服务器返回"参数错误"，有时候搜索结果为空。**时好时坏最难查**。

**原因**：**未编码的中文直接放进 URL**。有些服务器/代理能容忍，有些直接拒绝。而且中间经过 CDN、代理时，可能被二次处理。

**教训**：**永远用 `params=`**。

### 翻车二：搜索条件被 & 切断

```python
# ❌ 错误示范
keyword = "python & java"          # 用户输入的
url = f"https://api.example.com/search?q={keyword}&sort=stars"
```

**现象**：**不报错**，但搜索的是 `"python "`，排序参数也乱了。用户反馈"搜索不准"，你查半天查不到原因。

**原因**：`&` 被当成参数分隔符。

**教训**：**这是最危险的一类 bug——它不报错**。用户以为搜了完整词，实际只搜了一半。

### 翻车三：忘了 None 会被跳过

```python
# ⚠️ 注意
r = requests.get(url, params={"page": None, "size": 10}, timeout=10)
print(r.url)
# https://...?size=10       ← page 消失了
```

这**通常是你想要的**（不传这个参数）。但如果你想传**空字符串**而不是跳过：

```python
r = requests.get(url, params={"page": "", "size": 10}, timeout=10)
print(r.url)
# https://...?page=&size=10    ← page= 空值，会传
```

**区别**：`None` = 不传；`""` = 传一个空值。

## 为什么这对你写代码有用

1. **`params=` 不只是方便，它是正确性问题**。手动拼串会在遇到特殊字符时静默出错
2. **这类 bug 不报错**，只是结果不对。用户说"搜索不准"时，第一嫌疑就是它
3. **`None` 会被跳过**，这让你可以无条件传一堆可选参数
4. **值可以是列表**，生成重复参数
5. **记得 `r.url` 能验证**：不确定参数对不对，打印它

## 小结

- **查询字符串**是 `?` 后面 `k=v&k=v` 的那段，用来附加参数（分页、过滤、排序）
- **用 `params={...}` 传字典**，让 requests 自动编码
- **URL 保留字符**（`? & = # / + %`）在值里必须编码，否则会切断 URL
- **百分号编码**：把字节写成 `%XX`。`&` → `%26`，`中` → `%E4%B8%AD`
- **空格在查询串里可以是 `+` 或 `%20`**，在路径里必须是 `%20`
- **`requests` 自动做三件事**：转字符串、百分号编码、**跳过 None**
- **值为列表 → 重复同一个键**
- **不要给已编码的值**（会双编码），先 `unquote` 再传
- 手动编码用 `urlencode` / `quote_plus` / `quote`
- ❌ 别手动拼 URL；这类 bug **不报错**，只是结果错
