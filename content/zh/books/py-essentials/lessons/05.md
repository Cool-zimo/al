# 注释与报错阅读

> 这一课学完，你能写出别人看得懂的代码，并且第一次看到报错不再慌——因为报错就是在告诉你该改哪一行。

## 注释：写给半年后的自己看

代码是写给机器跑的，注释是写给人看的。Python 用 `#` 开头表示注释，这一行后面的内容全部被忽略：

```python
# 这是单行注释
name = "张三"      # 也可以写在代码后面，说明这一行的意图
```

多行注释用三个引号包起来（技术上是个没被赋值的字符串，常被拿来当注释用）：

```python
"""
这个函数用来计算用户的 BMI
参数：身高（米）、体重（公斤）
返回：BMI 数值
"""
```

**什么时候写注释？** 三种情况：

1. **解释"为什么"**，而不是"做了什么"。代码本身已经说了做了什么。
   ```python
   # 糟糕：把价格乘以 0.9
   price = price * 0.9

   # 好：会员打九折
   price = price * 0.9
   ```
2. **给复杂逻辑写路标**，比如一个难懂的算法步骤。
3. **临时屏蔽一行代码**（调试时用），叫"注释掉"。

> 反过来说，别写废话注释：`i = i + 1  # i 加 1` 这种等于没写。

## 报错不是洪水猛兽

新手最怕红色字。其实 Python 的报错信息（Traceback）是全世界最友好的提示之一，**它就是在告诉你：错在哪一行、什么错、为什么错**。

一个完整报错长这样：

```
TraceError: Traceback (most recent call last):
  File "demo.py", line 3, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero
```

四段信息，从上往下读：

1. **`Traceback` 开头**：表示"下面开始回溯错误"
2. **`File "demo.py", line 3`**：**出错的文件和行号**。这是最有用的一行，直接点过去改
3. **`print(10 / 0)`**：出错那行代码的样子，帮你回忆上下文
4. **`ZeroDivisionError: division by zero`**：**错误类型 + 一句话解释**

**看报错的正确姿势**：先找 `line 3` 这一行（去哪改），再看最后一行（是什么错）。

## 三大高频报错

### 1. SyntaxError：语法写错了

```python
print("你好"
```

```
  File "demo.py", line 1
    print("你好"
          ^
SyntaxError: unexpected EOF while parsing
```

**特征**：`^` 箭头指向出错位置。通常是**少括号、少引号、少冒号**。

**常见原因**：
- 引号只写了一半：`print("你好)`
- 括号只写了一半
- `if`、`for`、`def` 后面漏了冒号 `:`
- 用了中文标点

### 2. NameError：用了不存在的名字

```python
print(message)
```

```
NameError: name 'message' is not defined
```

**特征**：`not defined`。通常是**拼错、用了中文引号、还没赋值就用了**。

### 3. TypeError：类型对不上

```python
print("年龄：" + 18)
```

```
TypeError: can only concatenate str (not "int") to str
```

**特征**：`unsupported operand` 或 `must be ... not ...`。通常是**拿字符串和数字做了不该做的运算**——转一下类型就好。

## 翻车现场：缩进混用 Tab 和空格

```python
def greet():
    print("你好")    # 这行用 Tab
    print("世界")    # 这行用 4 个空格
```

```
TabError: inconsistent use of tabs and spaces in indentation
```

**为什么**：Python 用缩进判断代码块归属，Tab 和空格被当成不同长度的缩进，混用就报错。

**怎么修**：VSCode 底部状态栏能看到当前是 Tab 还是空格，点一下可以切换。最省事的办法：设置里打开 `Editor: Insert Spaces`，并设 `Tab Size = 4`。这样按 Tab 键实际插入的是 4 个空格，永远不会混。

> 顺带一提，`IndentationError: expected an indented block` 是"该缩进却没缩进"，比如 `if` 后面直接空着。Python 不允许空的代码块，临时占位的写法是 `pass`。

## 故意制造一个错误

下面这段故意写错，跑跑看：

```python
# WRONG
name = input("你叫什么？")
print("你好" name)     # 漏了逗号，会 SyntaxError
```

报错信息会精准指出：`print("你好" name)` 这一行语法不对。加上逗号就修好了：`print("你好", name)`。

## 小结

- `#` 开头是单行注释，`"""..."""` 包起来是多行注释
- 注释写"为什么"，不写"做了什么"；调试时用注释临时屏蔽代码
- 读报错三步：**哪一行 → 什么错 → 为什么**
- 三大高频错：`SyntaxError`（语法）、`NameError`（名字）、`TypeError`（类型）
- `TabError` 和 `IndentationError` 都是缩进问题，统一用 4 个空格最稳妥
- VSCode 开启 Insert Spaces + Tab Size 4，一劳永逸
