# 异常处理：try / except / finally

> 这一课学完，你能让程序在出错时"优雅地兜底"，而不是一脸红字崩溃。

## 崩溃不是优雅的退出方式

```python
age = int(input("你的年龄："))
print("你出生年份大概是", 2026 - age)
```

用户输入 `二十` 会怎样？

```
ValueError: invalid literal for int() with base 10: '二十'
```

程序直接崩了。用户体验极差——**你能预料到的错误，就该自己兜住。**

## try / except：兜底

```python
try:
    age = int(input("你的年龄："))
    print("你出生年份大概是", 2026 - age)
except ValueError:
    print("请输入数字，比如 18")
```

结构：把**可能出错**的代码放进 `try`，把**出错后怎么办**写在 `except`。

- `try` 块里没出错：正常走，`except` 被跳过
- `try` 块里出了 `ValueError`：立刻跳到 `except` 执行兜底逻辑

## 抓住具体的错

`except` 后面要写**具体的异常类型**，别一股脑全抓。常见几种：

| 异常 | 触发场景 |
|---|---|
| `ValueError` | 类型转换失败，`int("abc")` |
| `ZeroDivisionError` | 除以零 |
| `FileNotFoundError` | 文件不存在 |
| `KeyError` | 字典查不到键 |
| `IndexError` | 列表下标越界 |
| `TypeError` | 类型对不上 |

```python
try:
    num = int(input("输入一个数字："))
    result = 100 / num
    print("100 /", num, "=", result)
except ValueError:
    print("那不是数字")
except ZeroDivisionError:
    print("不能除以零")
```

两个 `except` 各管各的错，针对性更强。

## 翻车现场：except 抓太宽

```python
# WRONG：看似很安全，实际很危险
try:
    age = int(input("年龄："))
    print(2026 - age)
except Exception:
    print("出错了")
```

**问题在哪**：`Exception` 是所有异常的基类，这样写会**连你代码里的 bug 一起吞掉**。比如你手滑把 `2026` 写成了没定义的变量 `year2026`，也会进入 `except`，然后你完全不知道代码写错了。

**正确做法**：只抓你能处理的、具体的异常：

```python
try:
    age = int(input("年龄："))
    print(2026 - age)
except ValueError:
    print("请输入合法的数字")
```

> 原则：**抓具体的错，别抓 Exception。**

## else 和 finally

```python
try:
    f = open("data.txt", "r", encoding="utf-8")
    content = f.read()
except FileNotFoundError:
    print("文件不存在")
else:
    print("读取成功，内容长度：", len(content))   # 没出错才执行
finally:
    f.close()                                      # 无论成败都执行
```

- `else`：**没出错**才执行，用来放"正常流程的后续"
- `finally`：**无论出没出错**都执行，用来放"清理工作"（关文件、释放资源）

> 不过用了 `with` 语句就不用手动 `close()` 了，`finally` 在文件场景用得少了，但在**网络连接、数据库事务**里仍然是必写的。

## 什么时候该捕获，什么时候不该

**该捕获**：你能预料、且知道怎么处理的错误。

```python
try:
    config = json.load(open("config.json", encoding="utf-8"))
except FileNotFoundError:
    config = {}         # 没配置文件就用默认配置，合理
```

**不该捕获**：你没预料到的、程序层面的 bug。

```python
try:
    do_something()
except Exception as e:
    pass                # 静默吞掉，出了事完全没线索，最差实践
```

把异常 `print` 出来也不错，至少留个日志：

```python
try:
    age = int(input("年龄："))
except ValueError as e:
    print("转换失败：", e)    # e 是异常对象，打印它看具体原因
```

## 小结

- `try/except` 把可能出错的代码和兜底逻辑分开
- `except` 后面写**具体异常类型**，别写 `Exception`
- 常见错：`ValueError`、`ZeroDivisionError`、`FileNotFoundError`、`KeyError`、`IndexError`
- `else` 没出错才执行，`finally` 无论成败都执行
- 只抓能处理的错；静默吞掉 `except: pass` 是最差实践
- `except ... as e` 能拿到异常对象，打印出来便于排查
