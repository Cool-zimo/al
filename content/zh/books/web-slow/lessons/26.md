# 第 6 章 综合实战（26-30）

# 项目设计：待办清单的功能拆解

> 从这一课开始，我们做一个真实的网页项目：待办清单（Todo List）。这是前端入门最经典的练手项目，它把前面 25 课的知识串成了一条线。第一步不是写代码，而是把需求拆清楚。

## 我们要做什么

一个能用的待办清单，至少要有这些功能：

1. 显示一个任务列表（苹果、香蕉、写代码……）。
2. 能添加新任务。
3. 能删除某个任务。
4. 能标记完成 / 取消完成。
5. 数据刷新后还在（用 localStorage 记住）。

慢班先把前三个做扎实，后两个作为进阶。

## 从需求到数据：先想清楚"数据长什么样"

**做网页的正确顺序是：先设计数据，再设计界面，最后写交互。**别一上来就画界面。

我们的任务是一个对象，至少需要两个字段：

```js
let todo = {
    id: 1,
    text: "买菜"
};
```

为了支持"完成/未完成"，加一个 `done` 字段：

```js
let todo = {
    id: 1,
    text: "买菜",
    done: false
};
```

整个清单就是对象数组：

```js
let todos = [
    { id: 1, text: "买菜", done: false },
    { id: 2, text: "写代码", done: true },
    { id: 3, text: "看电影", done: false }
];
```

**这就是"单一数据源"：整个应用的状态就存在这一个数组里。**界面只是这个数组的"投影"。

## 从需求到函数：每个功能就是一个函数

| 需求 | 对应的函数 | 它做什么 |
|---|---|---|
| 显示列表 | `render()` | 把 `todos` 数组变成页面上的 `<li>` |
| 添加任务 | `addTodo(text)` | 往 `todos` 里加一项，然后重新 render |
| 删除任务 | `deleteTodo(id)` | 从 `todos` 里删掉，然后重新 render |

**注意规律：每个会改数据的操作，改完之后都要重新 render。**这是整个项目最重要的思想，后面会反复强调。

## 把函数骨架先写出来

```js
let todos = [];           // 单一数据源

function render() {
    // 把 todos 变成 <li> 显示出来（下一课实现）
}

function addTodo(text) {
    // 往 todos 里加一项
}

function deleteTodo(id) {
    // 从 todos 里删掉 id 对应的那项
}
```

先把这三个名字和参数定下来，不用急着填内容。**写代码前先把"有哪些函数、各自干什么"列成表，比闷头写高效十倍。**

## 翻车现场一：还没设计数据就先写界面

很多初学者一上来就写 HTML，写着写着发现"我怎么存这些数据"、"删的时候怎么找到那一项"全都乱了。

**正确顺序是：数据 → 函数 → 界面。**数据是地基，界面只是展示层。

## 翻车现场二：需求没拆完就动手

"做一个待办清单"太笼统。你要拆到这种程度：添加怎么触发（回车还是按钮）？删除按钮在哪？编辑要不要支持？**需求没拆细，代码一定返工。**

## 需求文档 = 验收标准

写代码前，把这三条写下来当"验收标准"，写完一项划掉一项：

- [ ] 输入文字点按钮，列表多一项
- [ ] 点删除，那一项消失
- [ ] 刷新页面，列表还在

**有验收标准的代码不会跑偏。**后面三课就是按这三条一个一个实现。

## 小结

- 做项目的顺序：设计数据 → 设计函数 → 实现界面。
- 单一数据源：整个应用状态存在一个数组里。
- 每个需求对应一个函数，改完数据要重新渲染。
- 先列验收标准再写代码，写完一项划一项。
