# 事件：addEventListener 与为什么不用 onclick

> 网页不是"跑完一遍就结束"的程序，而是"等用户来点"的程序。这一课学事件：让 JS 在用户点击、输入、移动鼠标时做出反应。

## 用 addEventListener 监听点击

```html
<button id="btn">点我</button>
<p id="msg"></p>
```

```js
let btn = document.querySelector("#btn");
let msg = document.querySelector("#msg");

btn.addEventListener("click", function () {
    msg.textContent = "你点了我！";
});
```

**`addEventListener("click", 函数)` 的意思是：当用户点击这个按钮时，执行这个函数。**传进去的函数叫"回调函数"——不是你主动调的，是浏览器在事件发生时替你调的。

## 事件对象 e 和 e.target

```js
btn.addEventListener("click", function (e) {
    console.log(e.target);       // 被点击的那个元素（就是 btn）
    console.log(e.target.id);    // "btn"
});
```

**`e` 是浏览器传给你的"事件对象"，里面装着这次点击的所有信息。**`e.target` 是最常用的，表示"真正被点到的是哪个元素"。

## 为什么不用 onclick = ...

**写法一：`onclick`（不推荐）**

```js
btn.onclick = function () { console.log("第一次"); };
btn.onclick = function () { console.log("第二次"); };
// 结果：只有"第二次"生效，第一次被覆盖了
```

**写法二：`addEventListener`（推荐）**

```js
btn.addEventListener("click", function () { console.log("第一次"); });
btn.addEventListener("click", function () { console.log("第二次"); });
// 结果：两个都生效
```

**`onclick` 是属性赋值，赋第二次会覆盖第一次；`addEventListener` 可以绑定任意多个处理函数。**真实项目里几乎都用 `addEventListener`。

## 常见事件类型

| 事件名 | 触发时机 |
|---|---|
| `click` | 点击 |
| `input` | 输入框内容变化 |
| `submit` | 表单提交 |
| `mouseover` | 鼠标移入 |
| `keydown` | 按下键盘按键 |

```html
<input id="name" placeholder="输入名字">
```

```js
let input = document.querySelector("#name");

input.addEventListener("input", function () {
    console.log("当前输入：" + input.value);
});
```

## 翻车现场一：button.click() 不触发 form 提交

```html
<form id="myForm">
  <input name="q">
</form>
```

```js
let form = document.querySelector("#myForm");

form.addEventListener("submit", function () {
    console.log("提交啦");
});

document.querySelector("button").click();   // 没用，form 的 submit 不会触发
```

后果：什么都没打印。**想用代码触发 form 提交，要用 `form.dispatchEvent(new Event("submit"))`。**

## 翻车现场二：给很多元素绑定事件时一个一个绑

```js
let items = document.querySelectorAll(".item");
for (let i = 0; i < items.length; i++) {
    items[i].addEventListener("click", function () {
        console.log("点了");   // 能跑，但元素多时性能差
    });
}
```

**更好的办法是用"事件委托"：把监听绑到父元素上，用 `e.target` 判断点到的是哪个子元素。**这一招在下一章的待办清单里会实战用到。

## 事件让网页"活"起来

事件就是网页的灵魂。没有事件，JS 只能一次性跑完；有了事件，网页就能一直等着用户操作并随时响应。本章后面的实战项目全靠它。

## 小结

- `addEventListener("click", 函数)` 绑定点击处理。
- 传进去的函数由浏览器在事件发生时调用，叫回调。
- `e.target` 是被点到的最底层元素。
- 推荐 `addEventListener` 而非 `onclick`，因为它能绑多个、不会覆盖。
- 触发 form 提交要用 `dispatchEvent(new Event("submit"))`。
