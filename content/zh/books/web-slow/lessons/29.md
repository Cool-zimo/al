# 增删：加一项、删一项，改了数组要重新渲染

> 上一课实现了 render。这一课把"添加"和"删除"两个功能做完——整个待办清单就能跑起来了。核心只有一句话：**改了数组，就要重新 render。**

## 添加：往数组里加一项

```js
function addTodo(text) {
    let todo = {
        id: Date.now(),     // 用时间戳当唯一 id
        text: text,
        done: false
    };
    todos.push(todo);       // 1. 改数组
    render();               // 2. 重新渲染
}
```

**两步走：先 push 进数组，再调 render。**顺序不能反，也不能只做一半。

## 给按钮绑事件，读输入框内容

```js
addBtn.addEventListener("click", function () {
    let text = input.value;          // 读输入框的文字

    if (text === "") return;         // 空的不加

    addTodo(text);                   // 加进数组并渲染
    input.value = "";                // 清空输入框
});
```

**在输入框里输入文字 → 点按钮 → 文字出现在列表里，这就是一个完整的"添加"流程。**

## 删除：从数组里删掉，再渲染

```js
function deleteTodo(id) {
    // 找到不是这个 id 的所有项，留下它们
    let newTodos = [];
    for (let i = 0; i < todos.length; i++) {
        if (todos[i].id !== id) {
            newTodos.push(todos[i]);
        }
    }
    todos = newTodos;   // 1. 改数组
    render();           // 2. 重新渲染
}
```

**删除的本质是"过滤"：把不要的那项丢掉，把剩下的重新组成新数组。**

用 `filter` 一行就能写：

```js
function deleteTodo(id) {
    todos = todos.filter(function (todo) {
        return todo.id !== id;
    });
    render();
}
```

## 在渲染时给删除按钮绑事件

```js
function render() {
    list.innerHTML = "";

    todos.forEach(function (todo) {
        let li = document.createElement("li");

        let span = document.createElement("span");
        span.textContent = todo.text;
        li.appendChild(span);

        let delBtn = document.createElement("button");
        delBtn.textContent = "删除";
        delBtn.addEventListener("click", function () {
            deleteTodo(todo.id);    // 点删除 → 删掉这一项
        });
        li.appendChild(delBtn);

        list.appendChild(li);
    });
}
```

**按钮是在 render 里动态创建的，所以事件也只能在 render 里绑。**点击 → deleteTodo → render，形成一个完整的闭环。

## 翻车现场一：改了数组忘了重新渲染

```js
function addTodo(text) {
    todos.push({ id: Date.now(), text: text, done: false });
    // 忘了写 render()
}
```

后果：数组里确实有新数据，但页面上一动不动。**这是本项目最高频的 bug。记住：凡改 todos，必 render。**

## 翻车现场二：删除时直接 splice 但下标算错

```js
function deleteTodo(index) {
    todos.splice(index, 1);
    render();
}
// 渲染时绑定的 index 是当时循环的下标 i
```

问题：`splice` 之后数组长度变了，但页面上的按钮记的还是旧下标，**删第二项可能删掉别的项**。用 `id` 而不是下标来定位，就避开了这个坑。

## 用 id 定位比用下标更稳

```js
// 推荐：用 id 定位
todos = todos.filter(function (t) { return t.id !== id; });

// 不推荐：用下标，删掉一项后下标就错位了
todos.splice(index, 1);
```

**id 是永久的、唯一的；下标是临时的、会变的。**在会增删的列表里，永远用 id 定位。

## 小结

- 添加：push → render；删除：filter → render。
- **凡改数组，必 render**，这是本项目第一铁律。
- 删除用 id 定位，别用下标，避免错位。
- 事件在 render 里绑，点按钮 → 改数据 → render 形成闭环。
