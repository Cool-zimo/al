# 读和改内容：textContent vs innerHTML

> 找到元素之后，最常做的事就是"读它的文字"和"改它的文字"。这一课讲两个最容易搞混的属性，以及一个严重的安全风险。

## textContent：读写纯文字

```html
<h1 id="title">旧标题</h1>
```

```js
let h1 = document.querySelector("#title");

// 读
console.log(h1.textContent);   // "旧标题"

// 改
h1.textContent = "新标题";
// 页面上立刻变成"新标题"
```

**`textContent` 只管文字，不管标签。**它是读写内容最安全的方式。

## innerHTML：读写"带标签的 HTML"

```html
<div id="box"><p>原来的段落</p></div>
```

```js
let box = document.querySelector("#box");

console.log(box.innerHTML);
// "<p>原来的段落</p>" —— 拿到的是带标签的字符串

box.innerHTML = "<p>新的<b>段落</b></p>";
// 页面上 box 里变成了一个新的 <p>，"段落"两个字还是加粗的
```

**`innerHTML` 会把字符串当成 HTML 去解析渲染。**正因为如此，它有风险。

## XSS 风险：千万别把用户输入塞进 innerHTML

```js
// 假设 userInput 来自用户在评论框里输入的内容
let userInput = "<img src=x onerror=alert('你被攻击了')>";
document.querySelector("#box").innerHTML = userInput;
```

后果：那段 `<img>` 会被当成真的 HTML 执行，`onerror` 里的 JS 就会跑起来。**如果 `userInput` 是坏人输入的，他就能在你的页面上执行任意 JS——这叫 XSS（跨站脚本攻击）。**

规则一句话：**凡是来自用户的、不可信的字符串，一律用 `textContent` 写入，不要用 `innerHTML`。**

```js
// 安全的写法
box.textContent = userInput;   // 坏人写的标签会被当成纯文字显示，不会执行
```

## 改属性：读和写像对象一样自然

```html
<img id="photo" src="a.jpg" alt="一张照片">
<a id="link" href="https://example.com">点我</a>
```

```js
let img = document.querySelector("#photo");
img.src = "b.jpg";           // 改图片地址，图片立刻切换
img.alt = "新照片";

let link = document.querySelector("#a");
link.href = "https://qq.com";   // 改链接地址
```

**标签属性在 JS 里就是对象的属性，直接 `元素.属性名 = 值` 就行。**

## 常见属性对照

| HTML 属性 | JS 里的写法 |
|---|---|
| `id` | `el.id` |
| `src` | `el.src` |
| `href` | `el.href` |
| `value`（输入框） | `el.value` |
| `disabled` | `el.disabled` |
| `class` | `el.className`（注意不是 `class`） |

`class` 是个例外，因为 `class` 在 JS 里是关键字，所以写成 `className`：

```js
let box = document.querySelector("#box");
box.className = "red big";   // 设置 class
```

## 翻车现场一：用 innerHTML 拼接用户输入

```js
let name = prompt("你叫什么？");   // 用户输入 <script>alert(1)</script>
box.innerHTML = "欢迎你，" + name;
```

后果：用户的脚本被执行。**凡是拼接用户输入，一律换成 `textContent`。**

## 翻车现场二：用 = 比较时想改值却写成了 ===

```js
let input = document.querySelector("#username");
if (input.value = "admin") {    // 手滑写成了 =，变成了赋值
    console.log("是管理员");
}
```

后果：条件永远为真，因为 `input.value = "admin"` 是赋值表达式，结果是 `"admin"`（真值）。**这是第 1 课的老坑，在 DOM 里照样要小心：判断用 `===`，赋值时才用 `=`。**

## 小结

- `textContent` 读写纯文字，安全，日常首选。
- `innerHTML` 读写带标签的 HTML，有 XSS 风险。
- 用户输入一律用 `textContent`。
- 改属性用 `元素.属性名 = 值`，`class` 写成 `className`。
