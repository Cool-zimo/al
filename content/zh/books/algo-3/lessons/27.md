# 贪心 vs DP：什么时候贪心是对的

> 贪心算法写起来比 DP 简单得多，但"贪心选择"不一定总是对的。本课用活动选择和零钱兑换两个经典问题，讲清楚贪心为什么在有的题上成立、在有的题上翻车。

## 贪心：每一步都做"当前看起来最优"的选择

**贪心算法的思路：每一步都做出局部最优选择，希望最终得到全局最优。**

**听起来很美，但关键问题是：贪心真的能保证全局最优吗？**

**答案：不一定。只有在问题满足"贪心选择性质"时，贪心才是正确的。**

> **贪心选择性质**：一个问题如果满足——**做出局部最优选择后，原问题的最优解仍然包含这个选择**，那么贪心就是正确的。

**换句话说：如果你选了一个"当前最好"的选项，后面无论如何安排，都不可能比"不选这个选项"得到更好的结果，那贪心就成立。**

## 活动选择：贪心成立

**问题：** 给你一堆活动，每个活动有开始时间和结束时间。同一时间只能进行一个活动。求最多能参加多少个活动。

**贪心策略：每次选"结束时间最早"的活动。**

```python
def activity_selection(start, end):
    # 按结束时间排序
    activities = sorted(zip(start, end), key=lambda x: x[1])
    
    count = 0
    last_end = -1
    for s, e in activities:
        if s >= last_end:          # 不冲突
            count += 1
            last_end = e
    return count

print(activity_selection([1, 3, 0, 5, 8], [2, 4, 6, 7, 9]))   # 4
```

**为什么贪心成立？**

**直觉：** 结束时间越早，留给后面活动的时间就越多。选结束时间最早的活动，不会让后面的选择空间变小。

**严格证明（交换论证）：** 假设最优解的第一个活动是 A，而结束时间最早的活动是 B（B 结束时间 ≤ A 结束时间）。那么把最优解中的 A 换成 B，得到的仍然是合法解（B 结束更早，后面能安排的活动只会更多不会更少），且活动数相同。所以最优解中"一定可以包含"结束时间最早的活动——这就是贪心选择性质。

**既然最优解包含它，我们就放心地选它，然后对剩下的子问题递归求解。**

## 零钱兑换：贪心有时成立，有时不成立

**问题：** 用最少的硬币凑出金额 amount。

### 情况一：US 硬币体系 {1, 5, 10, 25}，贪心成立

```python
def coin_change_greedy(amount):
    coins = [25, 10, 5, 1]
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(coin_change_greedy(37))   # 4（25+10+1+1）
```

**对于 US 硬币 {1, 5, 10, 25}，贪心确实给出最优解。** 因为每种大面额都是小面额的倍数。

### 情况二：硬币 {1, 3, 4}，贪心翻车！

```python
# 凑 6 块钱
# 贪心：先选 4 → 剩 2 → 选 1+1 → 共 3 枚（4+1+1）
# 最优：3+3 → 共 2 枚！

def coin_change_greedy_bad(amount):
    coins = [4, 3, 1]      # 降序
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(coin_change_gad_bad(6))   # 输出 3，但最优是 2！
```

**贪心给出了 3 枚（4+1+1），但最优解是 2 枚（3+3）。贪心翻车了！**

**为什么？** 因为 4 不是 3 的倍数。选了 4 之后，剩下的 2 只能用 1+1 凑，而如果不选 4 直接选两个 3，反而更少。

**这就是贪心不成立的情况——"选了当前最大的"反而堵死了更好的组合。**

### 正确做法：DP

```python
def coin_change_dp(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

print(coin_change_dp([1, 3, 4], 6))   # 2（3+3）
```

**DP 的思路：对于每个金额 i，尝试"最后一枚硬币是 c"，那么前面的金额就是 i-c。取所有可能中的最小值。**

## 贪心 vs DP：怎么判断该用哪个？

**核心区别：**

| | 贪心 | DP |
|---|---|---|
| 决策方式 | 只做当前最优选择，不回头 | 考虑所有子问题的解，取最优 |
| 适用条件 | 必须满足"贪心选择性质" | 只要有"最优子结构"即可 |
| 复杂度 | 通常 O(n log n) | 通常 O(n²) 或更高 |
| 正确性 | 需要证明 | 一般天然正确 |

**判断流程：**

```
1. 尝试构造贪心策略
2. 找一个反例（像 {1,3,4} 凑 6）
3. 能找到反例 → 贪心不成立 → 用 DP
4. 找不到反例 → 尝试证明（或相信直觉，比赛时先写贪心）
```

## 更多贪心成立的经典问题

**以下问题的贪心策略都经过证明是正确的：**

1. **最小生成树（Kruskal）**：每次选权值最小的边，且不形成环 → 正确
2. **单源最短路（Dijkstra）**：每次选距离最小的未访问点 → 正确（边权非负时）
3. **任务调度**：按结束时间排序贪心 → 正确（如活动选择）
4. **区间覆盖**：每次选能覆盖当前位置且延伸最远的区间 → 正确

**共同点：这些问题都有"贪心选择性质"——局部最优选择后，剩下的子问题最优解不受影响。**

## 翻车现场：把贪心能解的题当成 DP 写复杂

**活动选择用 DP 也能做，但完全没必要。**

```python
# 可以写 DP，但复杂度 O(n^2)，不如贪心 O(n log n)
def activity_selection_dp(start, end):
    n = len(start)
    activities = sorted(zip(start, end), key=lambda x: x[1])
    ends = [a[1] for a in activities]
    starts = [a[0] for a in activities]
    
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        # 找最后一个结束时间 <= starts[i-1] 的活动
        prev = 0
        for j in range(i - 1, 0, -1):
            if ends[j - 1] <= starts[i - 1]:
                prev = j
                break
        dp[i] = max(dp[i - 1], dp[prev] + 1)
    return dp[n]

# 能跑对，但 O(n^2)，而贪心只需 O(n log n)
print(activity_selection_dp([1, 3, 0, 5, 8], [2, 4, 6, 7, 9]))   # 4
```

**活动选择满足贪心选择性质，直接贪心 O(n log n) 就搞定。用 DP 不仅代码长，还慢。**

**判断标准：如果问题有明显的贪心策略且找不到反例，优先用贪心。**

## 翻车现场：贪心没证明就写，遇到 {1,3,4} 翻车

**最常见的错误——看到"求最少"就无脑贪心。**

```python
# WRONG：对所有零钱问题都用贪心
def min_coins_wrong(coins, amount):
    coins = sorted(coins, reverse=True)
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(min_coins_wrong([1, 3, 4], 6))   # 输出 3，正确答案应该是 2！
```

**反例：coins=[1,3,4], amount=6，贪心给出 4+1+1=3 枚，但最优是 3+3=2 枚。**

**修复：用 DP。**

```python
def min_coins(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

print(min_coins([1, 3, 4], 6))   # 2
```

**记住：贪心需要先验证"贪心选择性质"。拿不准时，先想反例。**

## 翻车现场：零钱兑换 II（求方案数），DP 转移顺序写反

**求"最少硬币数"和求"硬币组合数"是两个不同的问题，DP 写法也不同。**

```python
# WRONG：求组合数时把循环顺序写反
def coin_change_combo_wrong(coins, amount):
    dp = [0] * (amount + 1)
    dp[0] = 1
    for i in range(1, amount + 1):        # 先遍历金额
        for c in coins:                    # 再遍历硬币
            if c <= i:
                dp[i] += dp[i - c]         # 这样会重复计数！
    return dp[amount]

print(coin_change_combo_wrong([1, 2, 5], 5))   # 输出不对，重复计数了
```

**问题在于：先遍历金额再遍历硬币，会导致同一个组合被多次计数（如 1+2 和 2+1 算两次）。**

**修复：外层遍历硬币，内层遍历金额（保证每种硬币只用一次在顺序上，组合数不重不漏）。**

```python
def coin_change_combo(coins, amount):
    dp = [0] * (amount + 1)
    dp[0] = 1
    for c in coins:                    # 外层遍历硬币
        for i in range(c, amount + 1):  # 内层遍历金额
            dp[i] += dp[i - c]
    return dp[amount]

print(coin_change_combo([1, 2, 5], 5))   # 4
```

## 小结

- **贪心**：每一步做局部最优选择，代码简单但需要"贪心选择性质"才能正确
- **DP**：考虑所有子问题的最优解，适用范围更广但代码复杂
- **贪心选择性质**：做出局部最优选择后，全局最优解仍然包含这个选择
- **活动选择**：按结束时间排序贪心，O(n log n)，正确
- **零钱兑换**：US 硬币 {1,5,10,25} 贪心成立；{1,3,4} 贪心失败，必须用 DP
- 判断方法：先构造贪心策略，再找反例；找不到反例再考虑证明
- 常见坑：无脑贪心（{1,3,4} 翻车）、贪心能解的题用 DP 写复杂、组合数 DP 循环顺序写反
