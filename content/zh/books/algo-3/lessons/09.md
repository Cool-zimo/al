# 重建二叉树：从前序 + 中序恢复

> 给你一棵树的遍历结果，能把它还原回原来的树吗？前序+中序可以，中序+后序可以，但前序+后序不行。这一课讲清为什么，并亲手实现"前序+中序"的重建。

## 一个遍历序列还原不了一棵树

**前序序列和中序序列各自包含的信息不同。** 前序告诉你"谁是根"，中序告诉你"根把左右子树分在哪"。两者结合，就能唯一确定一棵树。

```
前序：1 2 4 5 3 6 7     ← 第一个是根 1
中序：4 2 5 1 6 3 7     ← 1 左边是左子树 [4,2,5]，右边是右子树 [6,3,7]
```

**前序的第一个元素一定是根。** 在中序里找到这个根的位置，它左边的都是左子树节点、右边的都是右子树节点——左子树大小就知道了。然后回到前序，紧跟根的那一段就是左子树的前序，再往后是右子树的前序。递归处理即可。

## 手动走一遍

**以 `pre = [3,9,20,15,7]`、`inorder = [9,3,15,20,7]` 为例：**

1. 前序首元素 3 是根。在中序里 3 的位置是下标 1，左边 `[9]`（size=1）是左子树，右边 `[15,20,7]`（size=3）是右子树。
2. 前序中 3 之后紧跟的 1 个元素 `[9]` 是左子树的前序，再往后 `[20,15,7]` 是右子树的前序。
3. 递归重建左子树（pre=[9], in=[9]）→ 节点 9 是叶子；右子树（pre=[20,15,7], in=[15,20,7]）→ 20 是根，左 `[15]` 右 `[7]`。

```
        3
       / \
      9   20
         /  \
        15   7
```

**递归的"分治边界"是 pre 为空时返回 None。**

## 实现：用哈希表加速中序查找

**如果在中序里每次都线性查找根的位置，复杂度是 O(n²)。** 先用一个哈希表把"值→下标"存起来，查找就是 O(1)，整体 O(n)。

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    pre_iter = iter(preorder)

    def go(left, right):
        """当前子树在中序 [left, right) 区间内的节点"""
        if left == right:
            return None
        val = next(pre_iter)              # 前序的下一个，就是当前根
        mid = idx_map[val]               # 在中序中的位置
        node = TreeNode(val)
        node.left = go(left, mid)        # 左子树在中序 [left, mid)
        node.right = go(mid + 1, right)  # 右子树在中序 [mid+1, right)
        return node

    return go(0, len(inorder))

def preorder(node):
    if node is None:
        return []
    return [node.val] + preorder(node.left) + preorder(node.right)

r = build_tree([3, 9, 20, 15, 7], [9, 3, 15, 20, 7])
print(preorder(r))        # [3, 9, 20, 15, 7]
print(inorder(r)) if False else None

def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.val] + inorder(node.right)
print(inorder(r))         # [9, 3, 15, 20, 7]
```

**用迭代器 `pre_iter` 代替"维护一个全局下标"，代码更干净。** `next(pre_iter)` 每次取出前序的下一个元素作为当前子树的根——它天然按顺序走，因为前序是"根→左→右"。

**区间是左闭右开 `[left, right)`**，这是写递归区间的常用约定，能避免下标算错。

## 翻车现场：中序下标用闭区间算错边界

```python
# WRONG：左闭右闭区间，却忘了调整递归参数
def build_tree_wrong(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    pre_iter = iter(preorder)
    def go(l, r):
        if l > r:           # 空
            return None
        val = next(pre_iter)
        mid = idx_map[val]
        node = TreeNode(val)
        node.left = go(l, mid)        # ← 应该是 go(l, mid-1)
        node.right = go(mid, r)       # ← 应该是 go(mid+1, r)
        return node
    return go(0, len(inorder)-1)
```

**这会重复包含 `mid` 位置的节点**（根自己又被传进左子树递归），导致节点被重复使用，最终树结构错误甚至无限递归。

**要么用左闭右开 `[l, r)`，递归写 `go(l, mid)` 和 `go(mid+1, r)`；要么用左闭右闭 `[l, r]`，写 `go(l, mid-1)` 和 `go(mid+1, r)`。两套约定别混用。**

## 中序 + 后序也能重建

**后序序列的最后一个元素是根。** 思路完全对称：从后往前取根，先建右子树、再建左子树（因为后序是"左→右→根"，从后往前是"根→右→左"）。

```python
def build_tree_in_post(inorder, postorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    post_iter = reversed(postorder)    # 从后往前取根

    def go(left, right):
        if left == right:
            return None
        val = next(post_iter)
        mid = idx_map[val]
        node = TreeNode(val)
        node.right = go(mid + 1, right)   # 注意：先右后左
        node.left = go(left, mid)
        return node

    return go(0, len(inorder))

r2 = build_tree_in_post([9, 3, 15, 20, 7], [9, 15, 7, 20, 3])
print(inorder(r2))   # [9, 3, 15, 20, 7]
print(preorder(r2))  # [3, 9, 20, 15, 7]
```

**先右后左是因为 `reversed(postorder)` 从后往前是"根→右→左"。** 如果你先建左子树，拿到的根就错位了。

## 为什么"前序 + 后序"还原不了一棵树

**前序告诉你"谁是根"，后序也告诉你"谁是根"，但没人告诉你"左子树有多长"。** 根把序列切成两半这件事，只有中序能做到。

```
前序：1 2 3 4
后序：4 3 2 1

能确定 1 是根，但 2 是左子树的第一个节点还是右子树的第一个节点？不知道。
两种可能：
    1         或         1
   /                    \
  2                      2
 /                        \
3                          3
/                            \
4                            4
```

**两者的前序、后序序列完全相同，但树结构不同。** 所以"前序+后序"无法唯一确定一棵二叉树（除非限制是满二叉树等特殊情况）。

## 重建的复杂度与适用条件

**时间 O(n)**：每个节点只建一次，中序查找用哈希表 O(1)。
**空间 O(n)**：哈希表 + 递归栈。

**前提：树中所有节点值互不相同。** 如果值有重复，中序里 `idx_map[val]` 只能存一个位置，无法区分哪个是哪个——重建失败。面试时题目通常保证"所有值唯一"。

## 翻车现场：重复值导致 idx_map 存错位置

```python
# WRONG：值不唯一时，idx_map 只保存了最后一次出现的位置
def build_tree_dup(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}   # 重复值会被覆盖
    # 假设 inorder = [1, 2, 1]，idx_map[1] 只会是 2
    ...

t = build_tree_dup([1, 1, 2], [1, 2, 1])
print(preorder(t))   # 结果错误
```

**`{v: i for i, v in enumerate(inorder)}` 遇到重复 v，后面的下标会覆盖前面的。** 导致在中序里定位根时拿到错误位置，重建出的树结构错乱。

**结论：重建算法只适用于"节点值唯一"的树。** 如果题目允许重复值，需要额外信息（比如把下标也作为参数传入），那已经超出基础范围。

## 小结

- 前序+中序能唯一重建：前序定根、中序分左右
- 用哈希表存中序下标，把 O(n²) 优化到 O(n)
- 递归区间推荐左闭右开 `[left, right)`，递归写 `go(l, mid)` 和 `go(mid+1, r)`
- 中序+后序对称：从后往前取根，先建右子树再建左子树
- **前序+后序还原不了一棵树**（不知道左子树长度），反例存在
- 重建算法要求节点值唯一；重复值会让 `idx_map` 存错位置
