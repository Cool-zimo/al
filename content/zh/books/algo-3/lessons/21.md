# DP 是什么：重叠子问题与最优子结构

> 动态规划（Dynamic Programming）是算法竞赛中最实用、最高频的思想之一。它把"大问题"拆成"小问题"，把小问题的答案记下来复用——避免重复计算，把指数级复杂度压成多项式。

## 从斐波那契说起：一棵爆炸的递归树

**斐波那契数列的定义很简单：F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)。** 最直觉的写法是递归：

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))   # 55
```

**这个写法的时间复杂度是 O(2ⁿ)。** 为什么？画出递归树就一目了然：

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) → fib(1)+fib(0)
│   │   └── fib(1)
│   └── fib(2)
│       ├── fib(1)
│       └── fib(0)
└── fib(3)  ← 又算了一次！
    ├── fib(2)  ← 又算了一次！
    └── fib(1)
```

**`fib(3)` 被算了两次，`fib(2)` 被算了三次——越往下重复越多。** 这就是**重叠子问题（Overlapping Subproblems）**：同一个子问题被反复求解。

## 记忆化：把答案存起来

**既然子问题会重复出现，那算过一次就记下来，下次直接查表。** 这就是"记忆化搜索"（Memoization）：

```python
def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n in memo:           # 查表：算过了就直接返回
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

print(fib_memo(50))   # 12586269025，秒出
```

**时间复杂度从 O(2ⁿ) 降到了 O(n)。** 每个 `fib(k)` 只算一次，共 n 个不同的子问题，每次算的代价是 O(1)。空间复杂度也是 O(n)（递归栈 + 备忘录）。

**记忆化的三步走：**

1. 定义一个"备忘录"（字典或数组）
2. 进函数先查表，命中就返回
3. 算完后把结果存进表

## 递推：从底向上填表

**记忆化是自顶向下（Top-down），那能不能反过来——从最小的子问题开始，一步步推到大问题？** 当然可以，这就是**递推（Bottom-up）**：

```python
def fib_dp(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)    # dp[i] 表示 F(i)
    dp[0] = 0
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_dp(50))   # 12586269025
```

**递推的精髓是"填表"：把 dp[0]、dp[1]、dp[2]……一路填到 dp[n]。** 每个格子只依赖前面已填好的格子，绝不回头。

**对比三种写法：**

| 写法 | 时间 | 空间 | 思路方向 |
|------|------|------|----------|
| 纯递归 | O(2ⁿ) | O(n) 栈 | 自顶向下 |
| 记忆化 | O(n) | O(n) | 自顶向下 |
| 递推 | O(n) | O(n) | 自底向上 |

## 最优子结构：大问题的最优解包含小问题的最优解

**动态规划的第二个要件是"最优子结构"。** 什么意思？以"爬楼梯"为例：

> 你每次可以爬 1 阶或 2 阶，问爬到第 n 阶有多少种方法？

**要到达第 n 阶，最后一步只有两种可能：从第 n-1 阶迈 1 步，或从第 n-2 阶迈 2 步。** 所以：

> 到达第 n 阶的方法数 = 到达第 n-1 阶的方法数 + 到达第 n-2 阶的方法数

**这就是最优子结构：大问题的解可以由小问题的最优解组合而来。**

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(climb_stairs(5))   # 8
```

**爬楼梯本质上是斐波那契的变种。** dp[i] 的含义是"到达第 i 阶的方法数"，转移方程 `dp[i] = dp[i-1] + dp[i-2]`。

## 翻车现场：记忆化忘了写 base case

**最常见的新手错误：备忘录里没放 base case，导致死循环或报错。**

```python
# WRONG：没在 memo 里预设 base case
def fib_bug(n, memo={}):
    if n in memo:
        return memo[n]
    # 忘了 memo[0]=0, memo[1]=1
    memo[n] = fib_bug(n - 1) + fib_bug(n - 2)   # 无限递归！
    return memo[n]

# RecursionError: maximum recursion depth exceeded
```

**为什么崩了？** 因为 `fib_bug(1)` 会调用 `fib_bug(0)` 和 `fib_bug(-1)`，`fib_bug(-1)` 又会调用 `fib_bug(-2)` 和 `fib_bug(-3)`……永远到不了 base case。

**修复：要么用 `if n <= 1: return n`（天然 base case），要么在 memo 里显式初始化 `memo[0]` 和 `memo[1]`。**

## 翻车现场：爬楼梯的 dp 数组大小和索引对不上

**另一个高频 bug：dp 数组开太小，或者索引从 0 还是 1 开始搞混。**

```python
# WRONG：dp 开成 n 大小，但访问了 dp[n]
def climb_wrong(n):
    dp = [0] * n        # 只有 dp[0] ~ dp[n-1]
    dp[1] = 1
    dp[2] = 2           # IndexError! n 可能只有 2，dp[2] 越界
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]         # IndexError! dp[n] 越界

# IndexError: list assignment index out of range
```

**修复：dp 数组开成 `n + 1` 大小，索引从 0 到 n，用 `dp[i]` 表示"到达第 i 阶"。** 这种"多开一格"的技巧在 DP 里非常常见，专门用来处理边界。

## 小结

- **重叠子问题**：同一个子问题被反复计算 → 用记忆化或递推避免重复
- **最优子结构**：大问题的最优解由小问题的最优解组合而成 → DP 的前提
- **记忆化 = 递归 + 备忘录**：自顶向下，先查表再计算
- **递推 = 填表**：自底向上，从 base case 一路推到大问题
- 斐波那契和爬楼梯是 DP 的"Hello World"，核心都是 `dp[i] = dp[i-1] + dp[i-2]`
- 常见坑：base case 漏写、数组大小开错、索引从 0/1 搞混
