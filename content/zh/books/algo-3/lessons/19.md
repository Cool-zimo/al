# 快速排序：分区思想

> 快排是实践中最快的通用排序算法，C++ 的 `std::sort`、Java 的基本类型排序都基于它。核心操作是"分区"：选一个 pivot，把数组分成"左边都小、右边都大"两部分。这一课讲透 Lomuto 和 Hoare 两种分区方案，以及快排为什么可能退化到 O(n²)。

## 分区：快排的核心操作

**分区的目标：选一个 pivot（基准），把数组重排为 `[<=pivot | pivot | >=pivot]` 的形式，返回 pivot 的最终位置。**

```python
def quick_sort(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition(a, low, high)   # 分区，p 是 pivot 的最终位置
        quick_sort(a, low, p - 1)     # 递归排左半
        quick_sort(a, p + 1, high)    # 递归排右半
    return a
```

**快排和归并的区别：归并是先分再合（合是主要工作），快排是先分区再递归（分区是主要工作，不需要合）。**

## Lomuto 分区：简单直观，一个指针划界

**Lomuto 分区方案：选最右元素为 pivot，用一个指针 `i` 维护"小于 pivot 区域"的边界。**

```python
def partition(a, low, high):
    pivot = a[high]        # 选最右元素为 pivot
    i = low - 1            # i 是"小于等于 pivot"区域的右边界
    for j in range(low, high):    # j 扫描 [low, high-1]
        if a[j] <= pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[high] = a[high], a[i + 1]  # pivot 放到正确位置
    return i + 1           # 返回 pivot 下标
```

**执行过程（`a = [10, 80, 30, 90, 40, 50, 70]`，pivot=70）：**

```
j=0: a[0]=10 <= 70, i=0, swap(a[0],a[0]) → [10, 80, 30, 90, 40, 50, 70]
j=1: a[1]=80 > 70, 跳过
j=2: a[2]=30 <= 70, i=1, swap(a[1],a[2]) → [10, 30, 80, 90, 40, 50, 70]
j=3: a[3]=90 > 70, 跳过
j=4: a[4]=40 <= 70, i=2, swap(a[2],a[4]) → [10, 30, 40, 90, 80, 50, 70]
j=5: a[5]=50 <= 70, i=3, swap(a[3],a[5]) → [10, 30, 40, 50, 80, 90, 70]
最后: swap(a[4], a[6]) → [10, 30, 40, 50, 70, 90, 80]
pivot 70 在位置 4，左边都 <=70，右边都 >=70 ✓
```

**Lomuto 的特点：简单、易理解，但交换次数比 Hoare 多。**

## Hoare 分区：双指针对撞，效率更高

**Hoare 分区（快排发明者 Tony Hoare 的原始方案）：左右两个指针向中间扫描，左指针找 >pivot 的，右指针找 <pivot 的，找到就交换。**

```python
def partition_hoare(a, low, high):
    pivot = a[low]          # 选最左元素为 pivot
    i = low - 1
    j = high + 1
    while True:
        i += 1
        while a[i] < pivot:
            i += 1
        j -= 1
        while a[j] > pivot:
            j -= 1
        if i >= j:
            return j        # 返回分界点
        a[i], a[j] = a[j], a[i]
```

**Hoare 分区的特点：**
- **交换次数少**：左右指针各找到违规元素才交换，平均比 Lomuto 少 3 倍交换
- **pivot 不一定在最终位置**：返回的是分界点，pivot 本身可能还在左边或右边
- **递归时要用 `[low, p]` 和 `[p+1, high]`**，不能像 Lomuto 那样排除 pivot

**Hoare 是实践中更常用的方案**，C++ `std::sort` 内部用的就是类似 Hoare 的双轴分区变体。

## 翻车现场：Lomuto 分区中 pivot 选错导致死循环

**最常见的快排 bug：分区后递归的区间包含了 pivot 本身，导致无限递归。**

```python
# WRONG：递归区间包含了 pivot 位置
def quick_sort_wrong(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition(a, low, high)
        quick_sort_wrong(a, low, p)      # 错！应该是 p-1
        quick_sort_wrong(a, p, high)     # 错！应该是 p+1
    return a

# 死循环！p 位置的元素不会被排除，递归永远不会收敛
```

**错误分析：如果 `a = [3, 1, 2]`，pivot=a[2]=2，p=1。递归调用 `quicksort(a, 0, 1)` 和 `quicksort(a, 1, 2)`。第二个调用中 pivot 还是位置 1 的元素，又会返回 p=1，无限递归！**

**修复：`quicksort(a, low, p-1)` 和 `quicksort(a, p+1, high)`——pivot 已经在正确位置，不需要再排。**

## 最坏情况 O(n²)：当分区极度不平衡

**快排的平均复杂度是 O(n log n)，但最坏情况会退化到 O(n²)。**

**什么情况下退化？当每次分区都极不平衡时——比如数组已有序，且 pivot 总是选最左/最右元素。**

```python
a = [1, 2, 3, 4, 5]   # 已有序
# pivot=5, 分区后左边 4 个，右边 0 个
# pivot=4, 分区后左边 3 个，右边 0 个
# ...
# 每次只减少 1 个元素，递归深度 n，总比较次数 n + (n-1) + ... + 1 = n(n+1)/2 = O(n²)
```

**退化链：递归树退化成链表，深度 O(n)，每层 O(n)，总 O(n²)。**

**这和插入排序在有序数据上的表现恰恰相反！** 插入排序在有序数据上 O(n)，快排在有序数据上 O(n²)。

## 随机化快排：用随机 pivot 避免最坏情况

**解决方案：不要固定选最左/最右，而是随机选一个 pivot，然后和最左/最右交换。**

```python
import random

def partition_random(a, low, high):
    # 随机选 pivot，和最右元素交换
    pivot_idx = random.randint(low, high)
    a[pivot_idx], a[high] = a[high], a[pivot_idx]
    return partition(a, low, high)    # 复用 Lomuto

def quick_sort_random(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition_random(a, low, high)
        quick_sort_random(a, low, p - 1)
        quick_sort_random(a, p + 1, high)
    return a
```

**随机化的意义：把"最坏情况"从"依赖输入"变成"依赖随机种子"。** 恶意构造的退化输入（如攻击者精心构造的数组）不再能稳定触发 O(n²)。

**实践中还有三数取中法（median-of-three）：选 low、mid、high 三个位置的中位数作为 pivot，对常见输入效果更好。**

**随机化快排的期望复杂度是 O(n log n)**，而且实践中常数因子很小，通常比归并排序快 20-40%（因为原地操作，缓存友好）。

## 小结

- 快排核心 = 分区：选 pivot，把数组分成 `<=pivot` 和 `>=pivot` 两部分
- Lomuto 分区：单指针划界，简单但交换多；Hoare 分区：双指针对撞，效率高
- **Lomuto 递归时 pivot 已就位，用 `[low, p-1]` 和 `[p+1, high]`**
- **Hoare 递归时用 `[low, p]` 和 `[p+1, high]`**
- 最坏 O(n²)：已有序 + 固定 pivot 选择 → 退化
- 随机化 pivot → 期望 O(n log n)，抗恶意输入
- 快排原地、缓存友好、常数小，是实践中最快的通用排序
