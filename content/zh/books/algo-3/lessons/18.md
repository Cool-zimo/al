# 归并排序：分治与稳定性

> 归并排序是第一个真正的 O(n log n) 排序，而且它是**稳定**的。代价是需要 O(n) 的额外空间。这一课从分治思想讲到合并操作，掰开揉碎。

## 分治：先分后合

**归并排序的核心思想就两步：Divide（分）和 Conquer（合）。**

1. **分**：把数组从中间劈成两半，递归排序左半和右半
2. **合**：把两个已排序的子数组合并成一个有序数组

```python
def merge_sort(a):
    if len(a) <= 1:          # 基线条件：0 或 1 个元素天然有序
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])    # 分：递归排左半
    right = merge_sort(a[mid:])  # 分：递归排右半
    return merge(left, right)    # 合：合并两个有序数组
```

**递归树的深度是 log n，每一层要处理的总元素数是 n。** 所以时间复杂度 O(n log n)。

**对比：冒泡/选择/插入的 O(n²) 是因为内层循环"看不全"——每次只处理局部。归并排序每一层都完整地覆盖了所有元素，且只做 O(n) 的工作。**

## 合并操作：两个指针，一个结果数组

**合并（merge）是归并排序的灵魂。它利用"两个子数组都已有序"这个条件，用两个指针线性扫描完成合并。**

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:     # 注意用 <= 保证稳定性
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])    # 左半剩余
    result.extend(right[j:])   # 右半剩余
    return result

print(merge([1, 4, 7], [2, 3, 6]))
# [1, 2, 3, 4, 6, 7]
```

**为什么用 `<=` 而不是 `<`？** 当 `left[i] == right[j]` 时，先取左半的元素，保证相等元素的相对顺序不变 → **稳定性**。

**合并操作是 O(n) 的：每个元素只被比较和移动一次。**

## 递归展开：看看归并排序到底在做什么

**以 `[38, 27, 43, 3, 9, 82, 10]` 为例，递归展开过程：**

```
[38, 27, 43, 3, 9, 82, 10]
        /              \
[38, 27, 43, 3]    [9, 82, 10]
   /      \          /      \
[38,27]  [43,3]   [9,82]   [10]
 /  \    /  \     /  \     |
[38][27][43][3] [9][82]   [10]
 \  /    \  /     \  /     |
[27,38] [3,43]   [9,82]   [10]
    \      /          \     /
 [3,27,38,43]      [9,10,82]
        \              /
     [3, 9, 10, 27, 38, 43, 82]
```

**每一层合并都消耗 O(n) 时间，树的深度为 log n，总 O(n log n)。**

**不管输入是什么顺序，归并排序永远是 O(n log n)。** 没有最好/最坏之分——这是它比快排更"可靠"的原因。

## 翻车现场：merge 里忘了处理剩余元素

**这是最常见的 bug：两个指针有一个走完后，忘了把另一个数组的剩余部分追加到结果里。**

```python
# WRONG：忘记 extend 剩余元素
def merge_wrong(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    # 忘了：result.extend(left[i:]) 和 result.extend(right[j:])
    return result

print(merge_wrong([1, 2, 3], [4, 5, 6]))
# [1, 2, 3]  ← 只拿到左半，右半丢了！
```

**输出 `[1, 2, 3]` 而不是 `[1, 2, 3, 4, 5, 6]`。** 因为左半元素全部小于右半，i 先走完，j 还停在 0，右半的 `[4, 5, 6]` 永远不会被加入。

**修复：while 循环结束后，必须 `result.extend(left[i:])` 和 `result.extend(right[j:])`。**

## 翻车现场：在 merge 里用 `<` 而不是 `<=`，破坏稳定性

**用 `<` 会导致相等元素取右半的，破坏稳定性。**

```python
# WRONG：用 < 破坏稳定性
def merge_unstable(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] < right[j]:    # 用 < 而不是 <=
            result.append(left[i])
            i += 1
        else:                     # 当相等时走这里，取右半的
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# 测试稳定性
# 假设有两个值相等的对象，左半的排在前面
# 用 < 时，相等会取右半的，左半那个被"推后"了
```

**`<` vs `<=` 的区别：当 `left[i] == right[j]` 时，`<` 会把右半的元素先放入结果，导致原来在前面的元素跑到后面 → 不稳定。**

**稳定性在实际中很重要：** 比如先按分数排序，再按姓名排序，如果第二次排序不稳定，第一次的顺序就被破坏了。

## 空间代价：O(n) 的额外数组

**归并排序需要一个 O(n) 的辅助数组来存放合并结果。** 这是它与堆排序（O(1) 额外空间）的核心区别。

```python
# 原地归并（省空间但很复杂）vs 辅助数组（简单直接）
# Python 切片写法隐式创建新列表，空间开销更大
# 优化版：只分配一次辅助数组，递归时复用

def merge_sort_inplace(a, temp=None, left=0, right=None):
    if right is None:
        right = len(a) - 1
    if temp is None:
        temp = [0] * len(a)    # 只分配一次
    if left >= right:
        return
    mid = (left + right) // 2
    merge_sort_inplace(a, temp, left, mid)
    merge_sort_inplace(a, temp, mid + 1, right)
    # merge 时利用 temp 做中转
```

**空间代价总结：**
- Python 切片版：`O(n log n)` 临时空间（每层递归都创建新列表）
- 优化版（复用 temp 数组）：`O(n)` 额外空间

**如果内存极度受限（嵌入式、大规模外部排序），归并排序的 O(n) 空间可能是不可接受的。此时堆排序是更好的选择。**

## 小结

- 归并排序：分治思想，先递归分、再合并合，O(n log n) 无论输入
- **merge 操作是灵魂**：双指针线性合并两个有序数组，O(n)
- 用 `<=` 保证稳定性，用 `<` 会破坏稳定性
- **必须处理剩余元素**：while 结束后 extend 左/右半剩余部分
- 空间代价 O(n)（优化版复用数组）或 O(n log n)（Python 切片版）
- 归并排序是稳定的、可靠的 O(n log n)，适合外部排序和链表排序
