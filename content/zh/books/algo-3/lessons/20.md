# 堆排序与非比较排序：突破 O(n log n) 下界

> 比较排序的理论下界是 Ω(n log n)——你没法比这更快。但计数排序、桶排序、基数排序不需要比较元素大小，它们利用数据的数值范围信息，可以达到 O(n)。这一课讲清堆排序和"非比较排序"的区别。

## 堆排序：原地 O(n log n)，不需要额外空间

**堆排序分两步：1) 建堆（把数组变成大顶堆）2) 反复取堆顶最大值放到末尾。**

```python
def heap_sort(a):
    n = len(a)
    # Step 1: 建堆（从最后一个非叶子节点开始下沉）
    for i in range(n // 2 - 1, -1, -1):
        heapify(a, n, i)
    # Step 2: 逐个把堆顶（最大值）放到末尾
    for i in range(n - 1, 0, -1):
        a[0], a[i] = a[i], a[0]    # 堆顶和末尾交换
        heapify(a, i, 0)            # 对 [0:i] 重新堆化
    return a

def heapify(a, n, i):
    largest = i
    left = 2 * i + 1
    right = 2 * i + 2
    if left < n and a[left] > a[largest]:
        largest = left
    if right < n and a[right] > a[largest]:
        largest = right
    if largest != i:
        a[i], a[largest] = a[largest], a[i]
        heapify(a, n, largest)      # 递归下沉
```

**建堆 O(n) + n 次取顶各 O(log n) = O(n log n)。** 空间 O(1)（原地操作）。

**为什么是 O(n) 建堆？** 看起来 `heapify` 是 O(log n)，有 n/2 个节点要 heapify……但实际是 O(n)。因为第 k 层的节点数是 n/2^(k+1)，每个节点最多下沉 k 层，总工作量 = Σ k · n/2^(k+1) = O(n)。

## 堆排序 vs 快排 vs 归并：各有取舍

| | 时间 | 空间 | 稳定 | 原地 |
|---|---|---|---|---|
| 快排 | O(n log n) 期望 / O(n²) 最坏 | O(log n) 栈 | 否 | 是 |
| 归并 | O(n log n) | O(n) | **是** | 否 |
| 堆排 | O(n log n) | O(1) | 否 | **是** |

**堆排序是唯一同时做到 O(n log n) 和最坏情况 O(1) 额外空间的排序。** 但它的缓存性能很差——堆的父子节点在数组中位置跳跃大，不如快排的局部性。

## 翻车现场：heapify 的下标公式写错

**最常见的堆 bug：左孩子和��孩子的下标算错。**

```python
# WRONG：右孩子下标写错
def heapify_wrong(a, n, i):
    largest = i
    left = 2 * i        # 错！应该是 2*i + 1
    right = 2 * i + 1   # 错！应该是 2*i + 2
    if left < n and a[left] > a[largest]:
        largest = left
    if right < n and a[right] > a[largest]:
        largest = right
    if largest != i:
        a[i], a[largest] = a[largest], a[i]
        heapify_wrong(a, n, largest)
```

**0-based 堆的下标规则：节点 i 的左孩子是 `2i+1`，右孩子是 `2i+2`，父节点是 `(i-1)//2`。**

**如果是 1-based 堆（堆顶在位置 1），则左孩子 `2i`，右孩子 `2i+1`，父节点 `i//2`。** Python 的 `heapq` 模块使用 0-based，所以必须用 `2i+1` 和 `2i+2`。

## 非比较排序：为什么能突破 O(n log n)

**比较排序的下界 Ω(n log n) 来自于决策树——n! 种排列至少需要 log₂(n!) ≈ n log n 次比较。**

**但计数排序、桶排序、基数排序不比较元素大小。它们利用"元素的取值范围有限"这个信息，直接"按值分配"到对应位置。**

```python
# 计数排序：知道元素范围是 0~k
def counting_sort(a, k):
    count = [0] * (k + 1)
    for x in a:
        count[x] += 1          # 统计每个值的出现次数
    result = []
    for val in range(k + 1):
        result.extend([val] * count[val])  # 按值从小到大输出
    return result

print(counting_sort([4, 2, 2, 8, 3, 3, 1], 8))
# [1, 2, 2, 3, 3, 4, 8]
```

**时间复杂度 O(n + k)，其中 k 是值域大小。** 如果 k = O(n)，那就是 O(n)！

**为什么不算"作弊"？** 因为计数排序的前提是"数据范围已知且不太大"。如果你只被告知"有一组数要排序"，没有范围信息，比较排序是最通用的。但现实中大量数据（年龄、成绩、像素值）都有天然的范围限制。

## 计数排序的下标陷阱

**计数排序最容易犯的错：值域 k 判断错误导致下标越界。**

```python
# WRONG：假设元素都 >= 0，但输入包含负数
def counting_sort_wrong(a):
    k = max(a)
    count = [0] * (k + 1)
    for x in a:
        count[x] += 1     # IndexError: x 是负数！
    return []

counting_sort_wrong([5, -2, 3, -1])  # 崩溃！
```

```python
# WRONG：k 取值太小，漏掉最大值
def counting_sort_wrong2(a):
    count = [0] * 10      # 假设所有元素 < 10
    for x in a:
        count[x] += 1     # IndexError: x=15 越界！
    return []

counting_sort_wrong2([3, 7, 15, 2])  # 崩溃！
```

**修复：正确处理偏移量。**

```python
def counting_sort_safe(a):
    mn, mx = min(a), max(a)
    count = [0] * (mx - mn + 1)
    for x in a:
        count[x - mn] += 1      # 用偏移量映射到合法下标
    result = []
    for i, c in enumerate(count):
        result.extend([i + mn] * c)
    return result
```

## 桶排序：计数排序的"分块"升级版

**桶排序的思路：把值域分成若干桶，每个桶内用插入排序，最后按桶顺序拼接。**

```python
def bucket_sort(a, bucket_count=10):
    if not a:
        return []
    mn, mx = min(a), max(a)
    bucket_size = (mx - mn) / bucket_count + 1e-9
    buckets = [[] for _ in range(bucket_count)]
    
    for x in a:
        idx = int((x - mn) / bucket_size)
        idx = min(idx, bucket_count - 1)   # 防止边界越界
        buckets[idx].append(x)
    
    result = []
    for bucket in buckets:
        insertion_sort(bucket)       # 桶内用插入排序
        result.extend(bucket)
    return result
```

**桶排序的时间复杂度取决于数据分布。** 如果数据均匀分布，每个桶平均 n/bucket_count 个元素，桶内排序 O((n/k)²)，总 O(n + k·(n/k)²) = O(n + n²/k)。当 k = Θ(n) 时，达到 O(n)。

**对比：计数排序是桶大小为 1 的特殊情况。桶排序适合桶大小 > 1 的场景。**

## 翻车现场：以为 sorted() 是快排

**面试高频错误：声称 Python 的 `sorted()` 使用快排。**

```python
# 错误说法："Python 的 sorted() 用的是快排"
# 实际：Python 用的是 Timsort

a = [3, 1, 4, 1, 5, 9, 2, 6]
sorted_a = sorted(a)   # Timsort: 混合插入排序 + 归并排序
# 特点：利用已有有序片段，最好 O(n)，最坏 O(n log n)，稳定
```

**Timsort 为什么比纯快排好？** 真实世界的数据往往包含大量"部分有序"的片段。Timsort 识别这些自然有序的 run，用插入排序扩展短 run，用归并合并 run。在最坏情况下仍保持 O(n log n)，且是稳定的。

**各语言排序算法速查：**
- Python `sorted()` / `list.sort()` → Timsort
- C++ `std::sort` → Introsort（快排 + 堆排 + 插入，混合）
- Java `Arrays.sort(int[])` → 双轴快排变体
- Java `Arrays.sort(Object[])` → Timsort

## 小结

- 堆排序：O(n log n) 最坏、O(1) 空间、不稳定、原地，缓存不友好
- 0-based 堆：左孩子 `2i+1`，右孩子 `2i+2`，父节点 `(i-1)//2`
- 比较排序下界 Ω(n log n)，来自决策树信息论论证
- 非比较排序利用数据范围信息突破下界：
  - 计数排序 O(n+k)，适合 k=O(n) 的小整数
  - 桶排序 O(n + n²/k)，适合均匀分布数据
- 计数排序注意偏移量（负数处理），桶排序注意边界越界
- Python `sorted()` 用的是 Timsort，不是快排
