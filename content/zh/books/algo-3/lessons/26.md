# 怎么判断一道题该用什么：从数据范围反推算法

> 拿到一道题，别急着写。先看数据范围，反推出时间复杂度上限，再倒推该用什么算法。这是竞赛和面试中最实用的"读题心法"。

## 先看 n 有多大，再决定怎么写

**拿到一道题，第一步不是想算法，而是看数据范围。** 因为数据范围直接决定了你的算法必须跑多快。

**时间复杂度的换算公式：**

> 1 秒大约能跑 10^8 次基本操作（Python 会慢一些，大约 10^6 ~ 10^7）。

**所以数据范围和算法的对应关系：**

| n 的范围 | 可用复杂度 | 常见算法 |
|---|---|---|
| n ≤ 20 | O(n·2^n)、O(n!) | 暴力枚举、回溯、状压 |
| n ≤ 10^3 | O(n^2)、O(n^2 log n) | 双重循环、Floyd、DP |
| n ≤ 10^5 | O(n log n)、O(n) | 排序、二分、单调栈、DFS |
| n ≤ 10^6 | O(n log n) 谨慎、O(n) | 线性扫描、计数排序 |
| n ≤ 10^7 | 只能 O(n) 且常数要小 | 前缀和、差分、桶计数 |

**举个例子：**

- 题目说 n ≤ 20 → 你可以放心写 O(2^n) 的状压或回溯
- 题目说 n ≤ 10^5 → O(n^2) 会跑 10^10 次操作，必超时，必须想 O(n log n) 或 O(n)
- 题目说 n ≤ 10^7 → 连 O(n log n) 都不行（log n ≈ 23，23×10^7 ≈ 2.3×10^8，Python 跑不动），只能纯 O(n)

**这就是"数据范围反推法"：先看 n，再反推算法。**

## n ≤ 20：暴力 / 回溯的舒适区

**当 n 很小（≤ 20）时，指数级算法是可行的。** 因为 2^20 ≈ 100 万，20! 虽然大但剪枝后可行。

```python
# n=20，枚举所有子集
def subset_sum(nums, target):
    n = len(nums)
    ans = 0
    for mask in range(1 << n):          # 2^n 种状态
        s = 0
        for i in range(n):
            if mask >> i & 1:
                s += nums[i]
        if s == target:
            ans += 1
    return ans

print(subset_sum([1, 2, 3], 3))   # 2（{3} 和 {1,2}）
```

**2^20 ≈ 10^6，在现代计算机上 1 秒内完全可以跑完。** 所以看到 n ≤ 20，不要怕写指数级——但要写对。

## n ≤ 10^3：O(n^2) 是主力

**n ≤ 10^3 时，O(n^2) 大约 10^6 次操作，非常安全。**

```python
# n=1000 的最近点对？不行，O(n^2)=10^6 还行
# 最长上升子序列就是典型 O(n^2)
def lis(nums):
    n = len(nums)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

print(lis([10, 9, 2, 5, 3, 7, 101, 18]))   # 4
```

**O(n^2) 在 n=1000 时是 10^6，安全；但 n=10^5 时是 10^10，必超时。**

## n ≤ 10^5：必须 O(n log n) 或 O(n)

**n=10^5 是分水岭。O(n^2) 必死，必须升级。**

```python
# 用二分把 LIS 优化到 O(n log n)
import bisect

def lis_fast(nums):
    tail = []
    for x in nums:
        i = bisect.bisect_left(tail, x)
        if i == len(tail):
            tail.append(x)
        else:
            tail[i] = x
    return len(tail)

print(lis_fast([10, 9, 2, 5, 3, 7, 101, 18]))   # 4
```

**从 O(n^2) 到 O(n log n)，n=10^5 时从 10^10 降到 1.7×10^6，差距 5000 倍。** 这就是为什么必须优化。

## n ≤ 10^7：只能 O(n)，且常数要小

**n=10^7 时，连 O(n log n) 都危险（约 2.3×10^8 次操作，Python 跑不动）。只能用纯 O(n)。**

```python
# 前缀和：O(n) 预处理 + O(1) 查询
def range_sum(nums, queries):
    n = len(nums)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + nums[i]
    
    res = []
    for l, r in queries:               # 每个查询 O(1)
        res.append(pref[r + 1] - pref[l])
    return res

print(range_sum([1, 2, 3, 4, 5], [(0, 2), (1, 4)]))   # [6, 14]
```

**前缀和把每次查询从 O(n) 降到 O(1)，整体从 O(nq) 降到 O(n+q)。** 这正是"数据范围逼出来的优化"。

## 常见算法的复杂度速查

**记住这张表，做题时心里就有底了：**

| 算法 | 复杂度 | 10^5 能用？ |
|---|---|---|
| 冒泡/插入排序 | O(n^2) | 不行 |
| 快排/归并/堆排序 | O(n log n) | 行 |
| 二分查找 | O(log n) | 行 |
| 哈希表查询 | O(1) 均摊 | 行 |
| 前缀和 | O(n) 预处理 | 行 |
| 单调栈/单调队列 | O(n) | 行 |
| DFS/BFS | O(n+m) | 行 |
| 朴素 DP（O(n^2)） | O(n^2) | 不行 |
| 状压 DP | O(n·2^n) | n≤20 行 |
| Floyd | O(n^3) | n≤300 行 |

**判断流程：**

```
1. 看 n 的范围
2. 算出允许的最大复杂度
3. 在允许范围内挑算法
4. 检查是否卡常（Python 的常数比 C++ 大）
```

## 翻车现场：n=10^5 还写 O(n^2)，必然超时

**这是最常见的翻车——没有看数据范围就写。**

```python
# WRONG：n=10^5 还用双重循环
def count_pairs(nums, target):
    n = len(nums)
    ans = 0
    for i in range(n):            # O(n^2)
        for j in range(i + 1, n):
            if nums[i] + nums[j] < target:
                ans += 1
    return ans

# n = 100000 时，循环次数 ≈ 5×10^9
# 实际运行：TLE（Time Limit Exceeded）
```

**为什么超时？** 10^5 个元素，双重循环要做约 50 亿次比较。即使每次比较只要 1ns，也要 5 秒；Python 每次循环至少几十 ns，实际要几分钟。

**修复：先排序，再用双指针或二分，降到 O(n log n)。**

```python
def count_pairs_fast(nums, target):
    nums.sort()
    ans = 0
    for i in range(len(nums)):
        # 二分找第一个 nums[j] >= target - nums[i] 的位置
        left, right = i + 1, len(nums)
        while left < right:
            mid = (left + right) // 2
            if nums[mid] < target - nums[i]:
                left = mid + 1
            else:
                right = mid
        ans += left - i - 1
    return ans

print(count_pairs_fast([1, 2, 3, 4, 5], 5))   # 4
```

## 翻车现场：n=10^7 还用排序，TLE

**n=10^7 时，O(n log n) 也跑不动。**

```python
# WRONG：n=10^7 还用 sorted()
def find_most_frequent(nums):
    nums = sorted(nums)          # O(n log n)，10^7 * 23 ≈ 2.3×10^8 次操作
    # Python 跑 10^7 个元素排序，可能要 10+ 秒
    return nums

# 实际运行：TLE
```

**修复：用计数排序（如果值域不大）或哈希计数，O(n)。**

```python
from collections import Counter

def find_most_frequent_fast(nums):
    cnt = Counter(nums)          # O(n) 一次遍历
    return cnt.most_common(1)[0][0]

print(find_most_frequent_fast([1, 2, 2, 3, 2, 1, 2]))   # 2
```

## 翻车现场：误判复杂度，以为 O(n log n) 在 n=10^5 会超时

**有些人看到 n=10^5 就慌，把本来 O(n log n) 的解法放弃，其实完全没必要。**

```python
# 有些人觉得 n=10^5 排序会超时，其实完全没问题
def sort_and_process(nums):
    nums.sort()          # O(n log n) = 10^5 * 17 ≈ 1.7×10^6 次操作
    # 1.7×10^6 次操作，在 1 秒内轻松跑完
    return nums

print(sort_and_process([3, 1, 2]))   # [1, 2, 3]
```

**n log n 在 n=10^5 时只有约 170 万次操作，完全安全。** 真正危险的是 O(n^2)（100 亿次）和 n=10^7 时的 O(n log n)（2.3 亿次，Python 危险）。

**判断要精准：不是"n 大就不能用 log"，而是要看 n log n 的绝对数值。**

## 小结

- **数据范围反推法**：先看 n，反推最大允许复杂度，再选算法
- **n ≤ 20**：可以写 O(2^n)、O(n!) 的回溯/状压
- **n ≤ 10^3**：O(n^2) 安全，是主力复杂度
- **n ≤ 10^5**：必须 O(n log n) 或 O(n)，O(n^2) 必死
- **n ≤ 10^7**：只能 O(n)，常数要小，不能用排序
- **1 秒 ≈ 10^8 次操作**（Python 约 10^6 ~ 10^7）
- 常见坑：不看数据范围就写、把 O(n^2) 当安全、误判 O(n log n) 会超时

func: max_subarray_len
starter: |
  def max_subarray_len(nums, target):
      # 返回和为 target 的最长连续子数组长度
      # 在这里改
      return 0
cases: |
  max_subarray_len([1, -1, 5, -2, 3], 3) -> 4
  max_subarray_len([1, 2, 3], 3) -> 2
  max_subarray_len([1, 2, 3], 7) -> 0
  max_subarray_len([], 0) -> 0
  max_subarray_len([5, 5, 5], 5) -> 1
hint: 用前缀和 prefix。对于每个位置 i，查找 prefix - target 最早出现在哪。用字典记录每个前缀和第一次出现的下标，遇到已经存在的 prefix 不要更新（保持最早）。
explain: 前缀和 prefix[i] 表示 nums[0..i-1] 的和。子数组 nums[j..i-1] 的和为 prefix[i] - prefix[j]。要找 prefix[i] - prefix[j] == target，即 prefix[j] == prefix[i] - target。用字典记录每个前缀和最早出现的下标，遍历时查找 prefix[i]-target 是否在字典中，更新最大长度。

q: 一道题给出 n ≤ 10^5，下面哪个复杂度是安全的？
options:
- O(n log n)，约 1.7×10^6 次操作
- O(n^2)，约 10^10 次操作
- O(n^3)，约 10^15 次操作
- O(2^n)，约 10^30000 次操作
answer: 0
explain: n=10^5 时 O(n log n) ≈ 1.7×10^6 次操作，1 秒内轻松完成。而 O(n^2) ≈ 10^10 次操作会严重超时。数据范围直接决定了可用算法的复杂度上限。
```

type: function
exam: true
q: 写一个函数 two_sum_exists(nums, target)，判断数组中是否存在两个不同的下标 i、j 使得 nums[i] + nums[j] == target。n 可达 10^5，必须用哈希表 O(n) 解法，不能用双重循环。
func: two_sum_exists
starter: |
  def two_sum_exists(nums, target):
      # 判断是否存在两数之和等于 target
      # 在这里改
      return False
cases: |
  two_sum_exists([2, 7, 11, 15], 9) -> True
  two_sum_exists([2, 7, 11, 15], 20) -> False
  two_sum_exists([3, 2, 4], 6) -> True
  two_sum_exists([3, 3], 6) -> True
  two_sum_exists([1], 2) -> False
hint: 用集合记录已经遍历过的数。对每个数 x，检查 target - x 是否已经在集合中。注意要找"两个不同下标"，所以同一个元素不能用两次（但如果有两个相同的元素如 [3,3] 是可以的）。
explain: 用一个集合 seen 记录已遍历的数。遍历 nums，对每个 x 检查 target - x 是否在 seen 中。如果在，说明找到了；否则把 x 加入 seen。这样每个元素只访问一次，O(n) 时间。注意 [3,3] 这种情况：先查 6-3=3 不在 seen 中，再把 3 加入 seen，下次遇到 3 就能查到了，返回 True。
```
