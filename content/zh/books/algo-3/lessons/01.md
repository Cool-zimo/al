# 树是什么：为什么要有树

> 数组查找要 O(n)，有序数组二分能到 O(log n) 但插入是 O(n)；链表插入 O(1) 但查找还是 O(n)。树是这中间的折中：它把"有序"这件事藏在结构里，让查找、插入、删除都能接近 O(log n)。

## 数组和链表的问题，其实是同一个问题

先回顾你已经会的东西。在《算法专攻 1》里，数组随机访问 O(1) 但中间插入要搬元素；《算法专攻 2》里链表插入 O(1) 但想找到那个位置要遍历。

看一个具体场景：维护一个有序的整数集合，频繁做"查找一个数是否存在"和"插入一个新数"。

| 操作 | 无序数组 | 有序数组（二分） | 链表 |
|---|---|---|---|
| 查找 | O(n) | O(log n) | O(n) |
| 插入 | O(1)（末尾） | O(n)（搬元素） | O(1)（已知位置） |
| 删除 | O(n) | O(n) | O(1)（已知位置） |

**有序数组的二分查找很快，但它的有序是"靠每次插入后整体搬家维持的"。** 如果你插入 10 万次，每次都要搬一半的元素，总量是 O(n²)。链表不用搬家，但查找时只能一个个数过去，10 万个元素要数 10 万步。

**要既查得快、又插得快，就必须让数据"天然就有序地散开"。** 这就是树。

## 树的定义：一组节点，由边连成无环连通结构

树（Tree）是 n 个节点的有限集合。当 n=0 时是空树；否则有一个特殊的节点叫**根（root）**，其余节点分成若干棵互不相交的子树。

几个术语，全部围绕一个家族谱系来记：

- **根 root**：最顶上的节点，没有父节点。
- **父节点 parent / 子节点 child**：一条边直接相连，靠上的叫父，靠下的叫子。
- **叶子 leaf**：没有子节点的节点。
- **深度 depth**：从根到该节点的边数（根的深度为 0）。
- **高度 height**：从该节点到最远叶子的边数（叶子高度为 0，空树高度为 -1）。
- **子树 subtree**：某个节点连同它的后代构成的树。

```python
# 用类来表示一个树的节点
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

# 手工拼出这棵树：
#       1
#      / \
#     2   3
#    / \
#   4   5
root = TreeNode(1)
root.left = TreeNode(2)
root.right = TreeNode(3)
root.left.left = TreeNode(4)
root.left.right = TreeNode(5)

print(root.val)              # 1
print(root.left.val)         # 2
print(root.left.right.val)   # 5
```

**树的"结构信息"就是它的有序性。** 在上面的例子里，2 和 3 谁大谁小并不由数值决定，而是由它们的位置决定。要表示"大小关系"，就得靠一种特殊结构的树——二叉搜索树，第 04 课讲。

## 翻车现场：把树当成图，陷入环里出不来

```python
# WRONG：自己引用自己，形成环
a = TreeNode(1)
b = TreeNode(2)
a.left = b
b.left = a      # a 的儿子是 b，b 的儿子又是 a

def count_nodes(node):
    if node is None:
        return 0
    return 1 + count_nodes(node.left) + count_nodes(node.right)

print(count_nodes(a))
```

报错（或永远不返回）：

```
RecursionError: maximum recursion depth exceeded
```

**树的定义里明确写了"无环"。** 一旦形成环，任何递归遍历都会无限循环，直到 Python 掐掉调用栈。在算法题里，输入的树**保证是无环的**，你不用担心；但如果你自己在代码里"拼树"（比如某些构建类题目），就必须小心别把边连错。

**判断依据：遇到 `RecursionError` 且你确信终止条件写对了，就该怀疑结构里有环。**

## 为什么树能让操作变快：分叉把搜索空间砍一半

数组二分快，靠的是"下标能随机跳"。树没有下标，但它有**分叉**——每个节点天然把后续节点分成"左一拨、右一拨"。

想象一棵"理想"的树，它有 7 个节点，结构是满的：

```
        A
      /   \
     B     C
    / \   / \
   D   E F   G
```

**从 A 出发，一步就能排除一半的节点。** 找 D 的路径是 A→B→D，3 步；这棵树总共 7 个节点，最多走 3 步。节点数翻倍到 15，最多也就多走 1 步。

规律是：一棵**高度为 h 的树，最多有 2^(h+1) - 1 个节点**。反过来，n 个节点的树，高度最少是 ⌊log₂n⌋。**高度就是"最多要走多少步"，也就是操作的时间复杂度。**

这正是"折中"的含义：

- 链表是一条线，n 个节点要走 n 步，O(n)。
- 平衡的树是"叉开"的，n 个节点只要走 log n 步，O(log n)。
- 极端歪掉的树（每个节点只有右儿子）就是一条链表，退化成 O(n)。

**树的性能全看它歪不歪。** 后续 BST、堆、平衡树，本质上都是在跟"歪"做斗争。

## 二叉树：每个节点最多两个子节点

**二叉树（Binary Tree）是最常用的树**，限定每个节点最多有 left、right 两个子节点。它的价值在于：结构简单（只有两个出口），却足够表达各种有序关系。

一棵二叉树有五种基本形态：空、只有一个根、只有左子树、只有右子树、左右都有。所有复杂的二叉树，都是这五种的组合。

```python
# 层序构造：用列表下标关系构造完全二叉树
# 下标 i 的左儿子是 2i+1，右儿子是 2i+2，父节点是 (i-1)//2
vals = [1, 2, 3, 4, 5, 6, 7]
nodes = [TreeNode(v) for v in vals]
for i in range(len(vals)):
    left = 2 * i + 1
    right = 2 * i + 2
    if left < len(vals):
        nodes[i].left = nodes[left]
    if right < len(vals):
        nodes[i].right = nodes[right]

root = nodes[0]
print(root.val, root.left.val, root.right.val)   # 1 2 3
```

**下标关系 `2i+1`、`2i+2` 是"完全二叉树"特有的。** 它只在"从上到下、从左到右填满"时才成立（堆就是这种结构，第 10 课细讲）。**普通的二叉树不能用下标定位儿子**——你必须老老实实靠 `node.left`、`node.right` 的指针。

## 翻车现场：None 解引用，空节点上取属性

```python
# WRONG：没有判断 node 是否为 None 就访问 .val
def tree_max(node):
    m = node.val                  # 假设 node 一定存在
    if node.left:
        m = max(m, tree_max(node.left))
    if node.right:
        m = max(m, tree_max(node.right))
    return m

print(tree_max(None))
```

报错：

```
AttributeError: 'NoneType' object has no attribute 'val'
```

**树里最容易犯的错，是忘了节点可能是空的。** 几乎每一个递归树函数，第一行都应该是 `if node is None: return ...`。空树不是"异常情况"，而是"最常见的基本情况之一"。

## 树的表示：指针版 vs 数组版

| 表示法 | 写法 | 优点 | 缺点 |
|---|---|---|---|
| 链式（指针） | `TreeNode` + `left/right` | 通用，任意形状都能表示 | 多两个指针字段，内存开销大 |
| 数组（层序） | 列表按层序存放，`None` 表示空缺 | 适合完全二叉树，下标能定位父子 | 稀疏树浪费大量空间 |

**算法题里，`[1,2,3,None,None,4,5]` 这种层序列表是标准输入格式。** 它是把树"一层层从左到右"拍平成数组，`None` 表示那个位置没有节点。第 02 课会讲怎么把它还原成 `TreeNode`，也会讲怎么反过来把 `TreeNode` 拍平成列表——这两件事在测试用例里反复用到。

```python
def build(vals):
    """把层序列表还原成 TreeNode。"""
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left = 2 * i + 1
        right = 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]

def to_list(root):
    """把 TreeNode 层序拍平成列表（末尾的 None 一并去掉）。"""
    if root is None:
        return []
    from collections import deque
    ans, q = [], deque([root])
    while q:
        n = q.popleft()
        if n is None:
            ans.append(None)
        else:
            ans.append(n.val)
            q.append(n.left)
            q.append(n.right)
    while ans and ans[-1] is None:   # 去掉末尾多余的 None
        ans.pop()
    return ans

t = build([1, 2, 3, None, None, 4, 5])
print(to_list(t))   # [1, 2, 3, None, None, 4, 5]
```

## 树的深度、高度、节点数：三个最基本的量

**所有"遍历整棵树"的问题，本质都是对这棵树做一遍 DFS 或 BFS。** 先记住三个量的定义，后面每课都会用：

- **深度**：根到该节点的边数，根的深度是 0。
- **高度**：该节点到最远叶子的边数，叶子是 0，空树是 -1。
- **节点数**：整棵树有多少个节点（包括根）。

```python
def count_nodes(root):
    if root is None:
        return 0
    return 1 + count_nodes(root.left) + count_nodes(root.right)

print(count_nodes(build([1, 2, 3, 4, 5])))   # 5
print(count_nodes(None))                       # 0
```

**这个"1 + 左子树 + 右子树"的句式，是后面所有树递归题的骨架。** 第 06 课会把它系统化：任何关于整棵树的量，几乎都能写成"左子树的结果 + 根的贡献 + 右子树的结果"。

## 小结

- 数组查找/插入的矛盾，源于"有序要靠搬家维持"；树让数据天然有序地散开，把查找和插入都压到 O(h)
- 树的核心术语：根、父/子、叶子、深度、高度、子树
- **树必须无环**，一旦成环，任何递归遍历都会 `RecursionError`
- 二叉树每个节点最多两个子节点；理想情况下高度 h ≈ log n，操作 O(log n)
- 空节点是常态，**每个递归树函数的第一行都要先判断 `None`**
- 链式表示通用，数组（层序）表示适合完全二叉树；`[1,2,3,None,None,4,5]` 是标准输入格式
- `build()` / `to_list()` 两个辅助函数是后面所有树题的基础设施
