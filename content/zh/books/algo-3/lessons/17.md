# 三大基础排序：冒泡、选择、插入

> 它们都是 O(n²)，看起来笨拙，但插入排序在数据近乎有序时比很多"高级"算法还快。这一课掰开揉碎讲透三个 O(n²) 排序的本质差异。

## 冒泡排序：不断把最大的"冒"到最后

**冒泡排序的核心思想：每一轮从头到尾比较相邻元素，把当前未排序区间的最大值"冒泡"到末尾。**

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n):            # i 轮
        for j in range(n - 1 - i):  # 已"冒"到末尾的不用再比
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
    return a

print(bubble_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**每轮结束后，末尾 i 个元素已经是有序的。** 第 1 轮把最大值放到 a[n-1]，第 2 轮把次大值放到 a[n-2]，依此类推。

**比较次数固定为 n(n-1)/2，无论输入是否有序。** 这是冒泡排序最大的浪费——即使数据已经有序，它还是会傻傻地比完所有轮。

## 选择排序：每轮挑最小的放到前面

**选择排序的核心思想：每一轮从未排序区间里找出最小值，放到已排序区间的末尾。**

```python
def selection_sort(a):
    n = len(a)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):    # 找最小值下标
            if a[j] < a[min_idx]:
                min_idx = j
        a[i], a[min_idx] = a[min_idx], a[i]  # 交换到位置 i
    return a

print(selection_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**选择排序的交换次数最多 n-1 次，远少于冒泡排序。** 冒泡可能每比较一次就交换一次（最坏 n² 次交换），选择排序每轮只交换一次。

**但选择排序永远做不到"提前结束"。** 无论数据多有序，它都要扫描完整个未排序区间才能确定最小值。

## 插入排序：像整理手牌一样把元素插到正确位置

**插入排序的核心思想：维护一个已排序的前缀，每次把下一个元素"插入"到前缀中的正确位置。**

```python
def insertion_sort(a):
    n = len(a)
    for i in range(1, n):
        key = a[i]          # 当前要插入的元素
        j = i - 1
        while j >= 0 and a[j] > key:   # 比 key 大的往后挪
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key      # 插入到正确位置
    return a

print(insertion_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**插入排序的内层循环是"挪位置"，不是"交换"。** 它先把 a[j] 往后移，腾出空位，最后一次性放入 key。这比冒泡的"每次交换两个元素"少了一次赋值。

## 翻车现场：把插入排序写成冒泡排序

**很多初学者写"插入排序"时，其实写的是冒泡排序——用交换代替挪位，本质完全不同。**

```python
# WRONG：这不是插入排序，这是冒泡排序！
def insertion_sort_fake(a):
    n = len(a)
    for i in range(1, n):
        for j in range(i, 0, -1):
            if a[j] < a[j - 1]:
                a[j], a[j - 1] = a[j - 1], a[j]  # 交换！
            else:
                break
    return a
```

**这段代码虽然结果正确，但它是冒泡排序的变种，不是插入排序。** 真正的插入排序是"先把元素取出来，把比它大的往后挪，最后一次性插入"。交换版每次要 3 次赋值，挪位版只需 1 次赋值（最终插入），在元素较大时差距明显。

**判断标准：插入排序内层循环里应该有一个 `key` 变量暂存待插入元素，且只赋值一次。**

## 插入排序为什么在近乎有序的数据上飞快

**当数据近乎有序时，插入排序的内层循环几乎不执行——每个元素只需和前一个比较一次就"break"了。**

```python
# 近乎有序的数据
a = [1, 2, 3, 4, 5, 0, 6, 7, 8, 9]
# 只有 0 需要移动，其余元素各比较 1 次就结束
```

**插入排序在最好情况下（已有序）只需 O(n) 时间——每个元素只比较一次，零次移动。** 冒泡和选择做不到这一点。

**这就是为什么 Python 的 Timsort、Java 的 Arrays.sort() 都在内部使用插入排序处理小规模或近乎有序的子数组。** 插入排序的小常数因子和 O(n) 的最好情况，让它在实际数据中表现出色。

## 翻车现场：以为 sorted() 用的是快排

**Python 的 `sorted()` 和 `list.sort()` 用的是 Timsort，不是快排，也不是堆排。**

```python
# 错误认知：认为 sorted() 是快排
a = [3, 1, 4, 1, 5, 9, 2, 6]

# Timsort 是混合排序：
# - 利用数据中已有的有序片段（run）
# - 对短 run 用二分插入排序
# - 用归并排序合并 run
# 最坏 O(n log n)，最好 O(n)，稳定

sorted(a)  # [1, 1, 2, 3, 4, 5, 6, 9]
```

**Timsort 的最坏复杂度是 O(n log n)，而快排的最坏是 O(n²)。** 如果你在面试中说"Python 用快排"，会被扣分。Timsort 由 Tim Peters 在 2002 年为 Python 设计，后来被 Java、Android、Swift 等采用。

**记忆点：Python = Timsort，C++ `std::sort` = Introsort（快排+堆排+插入的混合），Java 对对象用 Timsort，对基本类型用双轴快排。**

## 三种排序对比

| | 最好 | 平均 | 最坏 | 额外空间 | 稳定 |
|---|---|---|---|---|---|
| 冒泡 | O(n)（优化后） | O(n²) | O(n²) | O(1) | 是 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | **否** |
| 插入 | O(n) | O(n²) | O(n²) | O(1) | 是 |

**选择排序是不稳定的！** 例如 `[5, 5, 2]`，第一轮会把第一个 5 和 2 交换，变成 `[2, 5, 5]`，两个 5 的相对顺序变了。

**冒泡排序可以通过"不交换相等元素"来保证稳定。** 插入排序天然稳定。

**实际建议：n ≤ 16 时插入排序通常最快；大规模数据请用 O(n log n) 的算法（下一课开始讲）。**

## 小结

- 冒泡：相邻交换，把最大冒到末尾；优化后可提前结束（O(n) 最好）
- 选择：每轮找最小放前面，交换次数少但永远 O(n²)，且不稳定
- 插入：维护有序前缀，把新元素插入正确位置；近乎有序时 O(n) 飞快
- **插入排序是三个里面唯一在真实场景中仍被广泛使用的**（作为混合排序的兜底）
- Python 的 `sorted()` 用的是 Timsort，不是快排
- 三者都是 O(n²)，但常数因子不同：插入 < 选择 < 冒泡（一般）
