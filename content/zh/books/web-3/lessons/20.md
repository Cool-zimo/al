# 防抖与节流：本册最能落地的一节

> 这一节讲两个控制函数执行频率的工具：防抖（debounce）和节流（throttle），配合异步场景。

## 防抖（debounce）：等它安静下来再执行

**防抖**：触发后**等待一段时间**，如果这段时间内又触发了，就**重新计时**。只有"安静了足够久"才真正执行。

典型场景：**搜索框输入联想**。用户连续输入"北"、"北京"、"北京市"，你不想每个字都发请求，只想在**他停下输入后**发一次。

```javascript
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);          // 每次触发都清除旧的计时器
    timer = setTimeout(() => {    // 重新计时
      fn.apply(this, args);
    }, delay);
  };
}

// 用法
const search = debounce((keyword) => {
  console.log('发请求查：', keyword);
}, 300);

// 用户快速输入
search('北');     // 计时开始
search('北京');   // 重置计时
search('北京市'); // 重置计时
// 300ms 后只执行一次：发请求查：北京市
```

## 节流（throttle）：按固定频率执行

**节流**：无论触发多频繁，**每隔一段时间最多执行一次**。

典型场景：**滚动加载**。用户疯狂滚动，你不想每秒执行几十次回调，只想**每 200ms 最多处理一次**。

```javascript
function throttle(fn, interval) {
  let lastTime = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

window.addEventListener('scroll', throttle(() => {
  console.log('检查是否需要加载更多');
}, 200));
```

翻车现场一：把防抖函数直接当事件监听器传进去，导致 debounce 每次都返回新函数。

```javascript
// ❌ 错误：每次 addEventListener 都创建了一个全新的 debounce 包装器
input.addEventListener('input', debounce(doSearch, 300));
// 如果写在某个反复执行的函数里，每次绑定都是不同的包装器，timer 不共享

// ✅ 先把包装好的函数存起来，只绑定一次
const debouncedSearch = debounce(doSearch, 300);
input.addEventListener('input', debouncedSearch);
```

后果：如果 `debounce(doSearch, 300)` 每次都在重新执行，就会**每次都创建一个带着全新 `timer` 的新函数**，各次调用之间无法共享计时器，防抖就失效了。必须先把包装结果存到变量，绑定同一个引用。

翻车现场二：异步请求 + 防抖，先发的慢请求后到，覆盖了新结果。

```javascript
// ❌ 竞态：快速输入 "beijing" 再输入 "shanghai"
const search = debounce(async (keyword) => {
  const res = await fetch(`/api/search?q=${keyword}`);
  const data = await res.json();
  render(data);   // "beijing" 的请求可能比 "shanghai" 的更晚到，覆盖掉新结果
}, 300);

// ✅ 用"请求版本号"忽略过期响应
let requestVersion = 0;
const search = debounce(async (keyword) => {
  const version = ++requestVersion;   // 每次请求递增版本号
  const res = await fetch(`/api/search?q=${keyword}`);
  const data = await res.json();
  if (version !== requestVersion) return;  // 不是最新的，丢弃
  render(data);
}, 300);
```

后果：防抖只保证**少发请求**，不保证**先发的一定先到**。慢网络的旧请求可能覆盖新结果，表现为"搜北京市却显示北京的数据"。用版本号或 `AbortController`（第 9 课）可以解决。

## 两者对比

| 特性 | 防抖 debounce | 节流 throttle |
|---|---|---|
| 触发频率 | 安静后才执行一次 | 固定间隔最多执行一次 |
| 典型场景 | 搜索联想、表单校验 | 滚动、鼠标移动、resize |
| 用户体验 | 停止操作后才响应 | 操作期间持续有规律地响应 |

```javascript
// 防抖：停止输入 300ms 后搜索
input.addEventListener('input', debounce(search, 300));

// 节流：每 200ms 最多记录一次鼠标位置
window.addEventListener('mousemove', throttle(record, 200));
```

## 立即执行的防抖（leading）

有时需要**第一次立即执行**，后续再防抖：

```javascript
function debounceLeading(fn, delay) {
  let timer = null;
  return function (...args) {
    if (!timer) {
      fn.apply(this, args);   // 第一次立即执行
    }
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;           // 重置，允许下次立即执行
    }, delay);
  };
}
```

## 与 Python 的对比

Python 前端不常见，但服务端也有类似需求（限流、去抖），常用装饰器实现：

```python
# Python：用 time 做简易节流
import time
def throttle(interval):
    def decorator(fn):
        last = 0
        def wrapper(*args):
            nonlocal last
            now = time.time()
            if now - last >= interval:
                last = now
                return fn(*args)
        return wrapper
    return decorator
```

JS 的防抖/节流是前端面试和实战的高频刚需。

## 小结

- **防抖**：等"安静"了才执行一次，适合搜索联想、表单校验。
- **节流**：固定间隔最多执行一次，适合滚动、mousemove、resize。
- 防抖函数要先**包装一次存成变量**，避免每次绑定都重建计时器。
- 异步防抖要防**竞态**：用版本号或 AbortController 忽略过期响应。
- 选哪个看需求：要"停止后响应"用防抖，要"持续响应但降频"用节流。
