# async/await：异步代码的同步写法

> 这一节讲 `async/await` 语法糖，以及"并行执行"这一性能关键点。

## async/await 是什么

`async/await` 是**基于 Promise 的语法糖**：它让你写异步代码时，看起来和同步代码几乎一样。

```javascript
// 不用 async/await 的 Promise 链
function loadUser() {
  return fetchUser(1)
    .then(user => fetchPosts(user.id))
    .then(posts => posts.length);
}

// ✅ 用 async/await：代码是"直的"
async function loadUser() {
  const user = await fetchUser(1);    // 等 Promise 完成，拿到结果
  const posts = await fetchPosts(user.id);
  return posts.length;
}
```

`await` 后面跟一个 Promise，它会**暂停当前 async 函数的执行**，等 Promise 完成后再把结果赋值给左边的变量。注意：**暂停的只是这个函数，不是整个主线程**——别的代码照常跑。

## async 函数总是返回 Promise

无论你写不写 Promise，`async` 函数的返回值都会被自动包装成 Promise：

```javascript
async function add(a, b) {
  return a + b;   // 等价于 return Promise.resolve(a + b)
}

add(1, 2).then(result => console.log(result));  // 3
```

所以 async 函数可以互相 `await`：

```javascript
async function getName() {
  return '张三';
}
async function greet() {
  const name = await getName();  // await 一个 async 函数
  return `你好，${name}`;
}
```

翻车现场一：`await` 用在了普通函数或全局作用域里，直接语法错误。

```javascript
// ❌ 语法错误：await 只能在 async 函数内使用
function normalFn() {
  const data = await fetchData();  // SyntaxError
  return data;
}

// 顶层也不能直接用 await（旧环境）
const data = await fetchData();  // 某些旧版本直接报错
```

后果：代码**根本无法运行**，直接抛语法错误。解决方法是给函数加 `async`：

```javascript
// ✅ 加 async
async function normalFn() {
  const data = await fetchData();
  return data;
}
```

（注：现代 JS 支持顶层 `await`，但只在 ES Module 里可用，脚本标签下仍受限制。）

## 串行与并行：性能分水岭

这是 async/await 最容易踩的性能坑。看下面两段代码：

```javascript
// ❌ 串行：先等 A，再等 B，总共约 2 秒
async function serial() {
  const a = await fetchA();  // 假设耗时 1 秒
  const b = await fetchB();  // 再等 1 秒
  return [a, b];
}

// ✅ 并行：A、B 同时发起，总共约 1 秒
async function parallel() {
  const p1 = fetchA();   // 立刻发起，返回 Promise
  const p2 = fetchB();   // 立刻发起
  const a = await p1;    // 等两个都完成
  const b = await p2;
  return [a, b];
}
```

串行写法里，两个 `await` 是**先后排队**的，耗时相加；并行写法里，先把两个 Promise 都**发起**，再统一 `await`，耗时取最大值。

翻车现场二：误以为 `Promise.all` 里放 await 表达式能并行。

```javascript
// ❌ 这其实还是串行的
async function wrong() {
  const results = await Promise.all([
    await fetchA(),   // await 在这里会先等 fetchA 完成
    await fetchB()    // 再等 fetchB 完成
  ]);
  return results;
}
// Promise.all 收到的是 [a 的结果, b 的结果]，都是普通值，
// 等于失去了"同时等待"的意义，而且写法混乱。

// ✅ 正确：传入 Promise 本身
async function right() {
  const results = await Promise.all([
    fetchA(),   // 传入 Promise，不是 await 的结果
    fetchB()
  ]);
  return results;
}
```

后果：第一个写法在功能上能跑通，但**没有并行效果**，而且 `Promise.all` 的作用被浪费了。记住口诀：**`Promise.all` 里放的是 Promise，不是 await 后的结果。**

## Promise.all 的失败语义

`Promise.all` 是**"一败全败"**：只要有一个 Promise reject，整体立刻 reject，其他还在跑的 Promise 不会被取消（只是结果被忽略）。

```javascript
// 有一个失败，整体就失败
Promise.all([
  Promise.resolve(1),
  Promise.reject(new Error('挂了')),
  Promise.resolve(3)
])
  .then(values => console.log(values))
  .catch(error => console.error('整体失败：', error.message));  // 整体失败：挂了
```

如果你的需求是"**即使有失败也要收集所有结果**"，应该用 `Promise.allSettled`：

```javascript
Promise.allSettled([
  Promise.resolve(1),
  Promise.reject(new Error('失败'))
]).then(results => {
  // results: [{status:'fulfilled', value:1}, {status:'rejected', reason: Error}]
  console.log(results[1].status);  // 'rejected'
});
```

## 与 Python 的对比

Python 的 `async/await` 和 JS 几乎同构，只是 JS 的 Promise 对应 Python 的 `coroutine`，`Promise.all` 对应 `asyncio.gather`：

```python
# Python
import asyncio
async def main():
    results = await asyncio.gather(fetch_a(), fetch_b())
```

```javascript
// JS
async function main() {
  const results = await Promise.all([fetchA(), fetchB()]);
}
```

两者的语义、串行/并行的坑都一致。

## 小结

- `async/await` 是基于 Promise 的语法糖，让异步代码看起来像同步代码。
- `await` **只能在 async 函数内**使用（顶层 await 有限制）。
- async 函数的返回值**自动包装成 Promise**。
- `await` 会暂停函数但不会阻塞主线程。
- 性能关键：**需要并行时用 `Promise.all` 传入 Promise 本身，不要 `await` 后再传**。
- `Promise.all` 一败全败，`Promise.allSettled` 收集所有结果。
