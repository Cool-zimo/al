# JSON 深拷贝与循环引用、structuredClone

> 这一节讲对象的"深拷贝"问题，以及 `JSON.parse(JSON.stringify(x))` 这个经典技巧和它的致命缺陷。

## 为什么需要深拷贝

JS 里对象是**引用类型**，赋值只是复制引用，两个变量指向同一块内存：

```javascript
const a = { name: '张三', scores: [90, 85] };
const b = a;          // b 和 a 指向同一个对象
b.name = '李四';
console.log(a.name);  // '李四' —— a 也被改了！

// ✅ 浅拷贝：只复制第一层
const c = { ...a };
c.name = '王五';
console.log(a.name);  // '李四' —— 第一层独立了
console.log(c.scores === a.scores);  // true —— 但嵌套的数组还是同一个引用
c.scores.push(100);   // 会污染 a.scores！
```

浅拷贝（`{...obj}`、`Object.assign`）只解决了第一层，嵌套对象/数组**仍然共享引用**。

## JSON 深拷贝技巧

最经典的"深拷贝"手法，是利用 JSON 序列化再反序列化：

```javascript
const a = { name: '张三', scores: [90, 85] };
const b = JSON.parse(JSON.stringify(a));  // 深拷贝

b.scores.push(100);
console.log(a.scores);  // [90, 85] —— 原始对象没被污染
console.log(b.scores);  // [90, 85, 100]
```

原理：`JSON.stringify` 把对象变成字符串（无引用概念），`JSON.parse` 把字符串还原成全新的对象，引用链彻底断开。

翻车现场一：对象里有循环引用，JSON.stringify 直接抛错。

```javascript
// ❌ 循环引用
const a = { name: '张三' };
a.self = a;   // 指向自己，形成循环

JSON.stringify(a);  // TypeError: Converting circular structure to JSON

// ✅ 需要先处理循环，或使用 structuredClone
```

后果：`JSON.stringify` 遇到循环引用会**直接抛异常**，后续代码中断。这在处理树形结构（如 DOM 节点、带 parent 引用的对象）时很常见。

翻车现场二：JSON 深拷贝丢掉了函数、undefined、Date、Map、Set 等类型信息。

```javascript
const obj = {
  name: '张三',
  sayHi: () => console.log('hi'),  // 函数
  birth: new Date('1990-01-01'),  // Date 对象
  extra: undefined,                 // undefined
  map: new Map()                   // Map
};

const copy = JSON.parse(JSON.stringify(obj));
console.log(copy.sayHi);   // undefined —— 函数丢了
console.log(copy.birth);   // "1989-12-31T16:00:00.000Z" —— Date 变成字符串
console.log(copy.extra);   // undefined —— 属性被删除了
console.log(copy.map);     // undefined —— Map 整个没了
```

后果：`JSON.parse(JSON.stringify(x))` 不是真正的"完美深拷贝"，它会**丢弃**函数、`undefined`、Symbol、Map、Set、WeakMap 等，并把 `Date` 转成字符串、把 `RegExp` 转成空对象。数据一旦经过这层转换就**不可逆地丢失信息**。

## structuredClone：真正的深拷贝

现代浏览器提供了 `structuredClone`，能正确处理更多类型，包括循环引用：

```javascript
const a = { name: '张三' };
a.self = a;

const b = structuredClone(a);  // 不报错
console.log(b.self === b);     // true —— 循环结构被保留

// 支持的类型更多
const obj = {
  date: new Date(),
  map: new Map([['key', 'value']]),
  set: new Set([1, 2, 3]),
  nested: { deep: true }
};
const copy = structuredClone(obj);
console.log(copy.map.get('key'));  // 'value'
console.log(copy.date instanceof Date);  // true
```

`structuredClone` 的局限：仍然**不能克隆函数**，遇到函数会抛错；DOM 节点等部分宿主对象也不支持。

## 三者对比

| 方式 | 循环引用 | Date/Map/Set | 函数 | 兼容性 |
|---|---|---|---|---|
| `{...obj}` | 不处理嵌套 | 不复制嵌套 | 保留引用 | 全兼容 |
| `JSON.parse(JSON.stringify())` | ❌ 报错 | ❌ 丢类型 | ❌ 丢失 | 全兼容 |
| `structuredClone()` | ✅ | ✅ | ❌ 报错 | 现代浏览器 |

## 与 Python 的对比

Python 的 `copy.deepcopy` 是"真正"的深拷贝，能处理循环引用，也能拷贝函数：

```python
import copy
a = {'name': '张三'}
a['self'] = a
b = copy.deepcopy(a)  # 正常工作
```

JS 的 `structuredClone` 更接近 Python 的 `deepcopy`，但功能上仍有差距（不能拷函数）。

## 小结

- 对象赋值是引用拷贝，浅拷贝只独立第一层。
- `JSON.parse(JSON.stringify(x))` 是经典深拷贝技巧，但有三大坑：**循环引用报错、丢函数/undefined、Date/Map/Set 丢类型**。
- `structuredClone` 支持循环引用和更多内置类型，是更可靠的选择。
- `structuredClone` 仍不能克隆函数。
- 选型：简单数据用 JSON 技巧，复杂结构用 `structuredClone`。
