# Promise：三种状态与链式调用

> 这一节讲 Promise 是什么、有哪三种状态，以及 `.then`/`.catch` 如何把回调地狱拍平成链式调用。

## Promise 是什么

Promise 是**对"未来某个时刻才会到手的结果"的一个容器**。它把"异步操作"和"拿到结果后做什么"分离开来。

```javascript
// 创建一个 Promise：包裹一个异步操作
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve('数据加载成功');   // 成功时调用 resolve，把结果传出去
    } else {
      reject(new Error('网络异常'));  // 失败时调用 reject
    }
  }, 1000);
});

// 消费这个 Promise
promise.then(result => console.log(result));
promise.catch(error => console.error(error));
```

`new Promise` 接受一个**执行器函数**，它立刻被同步执行，参数 `resolve` 和 `reject` 由 JS 引擎提供。

## 三种状态

Promise 一生只经历以下三种状态之一：

| 状态 | 含义 |
|---|---|
| `pending` | 进行中，结果还没定 |
| `fulfilled`（或 `resolved`） | 已成功，有结果值 |
| `rejected` | 已失败，有失败原因 |

```javascript
const p = new Promise((resolve, reject) => {
  // 刚创建时 p 是 pending
});
console.log(p);  // Promise { <pending> }
```

翻车现场一：同一个 Promise 里既 resolve 又 reject，后面的不生效。

```javascript
// ❌ 以为可以多次改变状态
const p = new Promise((resolve, reject) => {
  resolve('第一次成功');
  reject(new Error('第二次失败'));  // 无效！
  resolve('第三次成功');            // 同样无效
});

p.then(v => console.log(v));  // 只输出：第一次成功
```

后果：Promise 的状态一旦从 `pending` 变为 `fulfilled` 或 `rejected`，就**不可逆**，后续再调用 `resolve`/`reject` 都会被忽略。这个设计保证了"结果只能定一次"，但也意味着你不能在异步流程里反复尝试去"改变主意"。

## then / catch：注册处理回调

```javascript
fetchData()                    // 假设返回一个 Promise
  .then(data => {              // 成功时执行
    console.log('成功：', data);
    return data.name;          // 返回的值会传给下一个 then
  })
  .catch(error => {            // 任何一环失败都跳到这里
    console.error('失败：', error);
  });
```

`.then(onFulfilled, onRejected)` 可以接收两个回调，但通常更推荐**只传成功回调、用单独的 `.catch` 收尾**，这样语义更清晰。

## 链式调用：把嵌套拍平

这是 Promise 解决回调地狱的关键：**`.then` 返回一个新的 Promise**，所以可以一直 `.then` 下去。

```javascript
// ✅ 链式调用：从上到下，而不是从外到内
getUser(1)
  .then(user => {
    console.log('用户：', user.name);
    return getPosts(user.id);   // 返回一个新的 Promise
  })
  .then(posts => {
    console.log('文章数：', posts.length);
    return getComments(posts[0].id);
  })
  .then(comments => {
    console.log('评论：', comments);
  })
  .catch(error => {
    console.error('链中任何一环失败都会到这里：', error);
  });
```

对比第 2 课的嵌套版，链式调用**没有向右的缩进**，流程是自上而下的一条直线。

`.then` 里 `return` 的值会决定下一个 `.then` 收到的内容：

- `return 123` → 下一个 `.then` 收到 `123`（值会被自动包装成 `Promise.resolve(123)`）
- `return anotherPromise` → 下一个 `.then` 等它完成才执行
- `throw new Error(...)` → 跳到最近的 `.catch`

翻车现场二：在 `.then` 里忘了 return，导致下一环拿到 undefined。

```javascript
// ❌ 忘记 return
getUser(1)
  .then(user => {
    getPosts(user.id);   // 没 return！返回的是 undefined
  })
  .then(posts => {
    console.log(posts.length);  // TypeError: Cannot read properties of undefined
  });

// ✅ 补上 return
getUser(1)
  .then(user => {
    return getPosts(user.id);
  })
  .then(posts => {
    console.log(posts.length);  // 正常
  });
```

后果：`.then` 没 `return` 时，它返回的是 `undefined`（等价于 `Promise.resolve(undefined)`），下一个 `.then` 收到的就是 `undefined`。这类 bug 在链式调用里非常隐蔽，因为代码不报错，只是下游拿不到数据。

## Promise 的静态方法

| 方法 | 作用 |
|---|---|
| `Promise.resolve(value)` | 返回一个立刻成功的 Promise |
| `Promise.reject(error)` | 返回一个立刻失败的 Promise |
| `Promise.all([p1, p2])` | 全部成功才算成功，一个失败就整体失败（下一节细讲） |
| `Promise.race([p1, p2])` | 谁先定状态（无论成功失败）就用谁的结果 |

```javascript
Promise.all([
  fetch('/api/user'),
  fetch('/api/posts')
]).then(([user, posts]) => {
  console.log('用户和文章都拿到了');
});
```

## 与 Python 的对比

Python 的 `asyncio` 用 `await` 直接拿到结果，不需要 `.then` 这种链式写法。JS 的 Promise 链式调用更接近**管道（pipeline）**的概念：每一步加工上一步的输出。

```python
# Python：await 直接取值
user = await get_user(1)
posts = await get_posts(user.id)
```

```javascript
// JS：.then 链式传值
getUser(1)
  .then(user => getPosts(user.id))
  .then(posts => console.log(posts));
```

## 小结

- Promise 是"未来结果"的容器，有三种状态：`pending`、`fulfilled`、`rejected`。
- 状态一旦确定就**不可逆**，再次调用 `resolve`/`reject` 无效。
- `.then` 返回新 Promise，可实现**链式调用**，把嵌套拍平成直线。
- `.then` 里**必须 return**，否则下一环收到 `undefined`。
- `Promise.all` / `Promise.race` 用于组合多个 Promise。
