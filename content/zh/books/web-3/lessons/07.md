# POST 请求与请求头：method、headers、body

> 这一节讲怎么用 fetch 发 POST 请求，以及 `JSON.stringify` 为什么是必需的。

## 发起 POST 请求

`fetch` 的第二个参数是一个**配置对象**，用来指定请求方法、请求头、请求体等：

```javascript
fetch('/api/users', {
  method: 'POST',              // 请求方法
  headers: {                   // 请求头
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({        // 请求体，必须是字符串
    name: '张三',
    age: 28
  })
})
  .then(res => res.json())
  .then(data => console.log(data));
```

## 为什么 body 要 JSON.stringify

HTTP 请求体在网络上传输的**只能是字符串（或二进制）**，不能是 JS 对象。所以发 JSON 数据时必须先用 `JSON.stringify` 把对象序列化成字符串。

```javascript
const user = { name: '张三', age: 28 };

// ❌ 错误：直接传对象
fetch('/api/users', {
  method: 'POST',
  body: user   // 对象会被转成 "[object Object]"，服务端解析失败
});

// ✅ 正确：先 stringify
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(user)
});
```

翻车现场一：忘了 `Content-Type` 头，服务端不知道怎么解析 body。

```javascript
// ❌ 没有 Content-Type
fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify({ name: '张三' })
  // 服务端收到后不知道这是 JSON，可能按普通文本处理
});

// ✅ 显式声明
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: '张三' })
});
```

后果：服务端（如 Express、Django）通常靠 `Content-Type: application/json` 这个头来决定是否把 body 解析成 JSON 对象。漏了这个头，服务端拿不到结构化数据，可能返回 400 或直接把原始字符串丢给你。

## 常用请求方法

| method | 用途 |
|---|---|
| GET | 获取资源（默认） |
| POST | 创建资源 |
| PUT | 完整更新资源 |
| PATCH | 部分更新资源 |
| DELETE | 删除资源 |

```javascript
// PUT 更新
fetch('/api/users/1', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: '李四' })
});

// DELETE
fetch('/api/users/1', { method: 'DELETE' });
```

## headers 里的认证信息

很多接口要求登录后才能调用，会把 token 放在请求头里：

```javascript
const token = localStorage.getItem('token');

fetch('/api/profile', {
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`   // 携带 token
  }
});
```

翻车现场二：把 token 直接写死在前端代码里。

```javascript
// ❌ 敏感信息硬编码在前端
const token = 'sk-1234567890abcdef';  // 任何人查看源码都能看到

// ✅ 从登录态获取，且只在 HTTPS 下传输
const token = localStorage.getItem('authToken');
// 配合后端做鉴权、过期、刷新
```

后果：前端代码对用户**完全可见**，把 API key、token 写死在代码里等于公开。敏感凭证应存在后端，前端只持有短期有效的访问令牌。

## 发送 FormData（上传文件）

如果要上传文件，用 `FormData`，**不要**手动 stringify：

```javascript
const form = new FormData();
form.append('username', '张三');
form.append('avatar', document.querySelector('#file').files[0]);

fetch('/api/upload', {
  method: 'POST',
  body: form
  // 注意：不要手动设置 Content-Type，浏览器会自动加 boundary
});
```

## 与 Python 的对比

Python 的 `requests` 库对 JSON 有专门参数，会自动 stringify 并加头：

```python
# Python requests 自动处理
import requests
requests.post('/api/users', json={'name': '张三'})  # 自动 stringify + 加头
```

```javascript
// JS 必须手动 stringify 和加头
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: '张三' })
});
```

JS fetch 的"原始"设计是它容易漏写 `JSON.stringify` 和 `Content-Type` 的原因。

## 小结

- POST 请求用 `fetch(url, { method: 'POST', headers, body })`。
- body **必须是字符串**，发 JSON 要用 `JSON.stringify`。
- `Content-Type: application/json` 头告诉服务端怎么解析 body。
- PUT / PATCH / DELETE 对应更新和删除语义。
- 认证用 `Authorization` 头，token 不要硬编码在前端。
