# 错误处理：try/catch 配 await 与 finally

> 这一节讲异步代码里的错误怎么抓、怎么别让 `.catch` 把错误"吞掉"。

## try/catch 配 await

`async/await` 的最大便利之一，就是**可以用同步的 `try/catch` 捕获异步错误**。

```javascript
async function loadUser() {
  try {
    const response = await fetch('/api/user');
    const user = await response.json();
    return user;
  } catch (error) {
    console.error('加载失败：', error.message);
    return null;  // 给一个兜底值
  }
}
```

当 `await` 后面的 Promise **reject** 时，程序会像同步代码抛异常一样跳进 `catch` 块。这让错误处理和写普通同步代码的体验一致。

翻车现场一：`.catch` 里没 return，错误被"吞掉"，调用方拿到 undefined。

```javascript
// ❌ 错误被静默吞掉
async function loadData() {
  return fetchData()
    .then(data => {
      return data.value;
    })
    .catch(error => {
      console.error(error);  // 只打印，没 return
      // 函数默认返回 undefined
    });
}

// 调用方以为拿到了值，其实拿到 undefined
const value = await loadData();
console.log(value.toFixed(2));  // TypeError: Cannot read properties of undefined
```

后果：`.catch` 里如果不 `return` 或 `throw`，它会返回一个**成功（resolved）**的 Promise，值为 `undefined`。调用方完全不知道出错了，继续往下走就崩。修复办法是**要么 return 兜底值，要么重新 throw**：

```javascript
// ✅ 方案 A：return 兜底值
.catch(error => {
  console.error(error);
  return { value: 0 };  // 给调用方一个可用的值
})

// ✅ 方案 B：重新抛出，让上层处理
.catch(error => {
  console.error('本地记录一下');
  throw error;  // 继续向上传播
})
```

## catch 吞掉错误的三种"伪装"

`.catch` 把异步流程的失败**转成了成功（带着 undefined 值）**，这类 bug 很隐蔽，因为代码不报错、也不进断点。

```javascript
// 场景：错误处理函数自己又出错了
async function process() {
  try {
    await mayFail();
  } catch (error) {
    // 假设这里访问了不存在的对象
    console.log(error.message.toUpperCase());  // 如果 message 是 undefined 就崩
  }
}
```

翻车现场二：catch 块内部抛错，但外层没接住，变成"未处理的 Promise 拒绝"。

```javascript
// ❌ catch 里又出错，没人接
async function process() {
  try {
    await mayFail();
  } catch (error) {
    reportError(error);  // 假设这个函数内部抛异常
  }
  console.log('继续');  // 如果 reportError 抛错，这行不会执行
}

// ✅ 双层保护
async function process() {
  try {
    await mayFail();
  } catch (error) {
    try {
      reportError(error);
    } catch (e) {
      console.error('连错误上报都失败了：', e);
    }
  }
}
```

后果：catch 块内部的错误会**取代**原来的错误继续向上抛。如果外层再没 try/catch，就成了未处理的 Promise 拒绝（Unhandled Promise Rejection），在控制台留下一条警告，且后续逻辑中断。

## finally：无论成败都要执行

`finally` 用于**清理工作**——无论 try 成功还是 catch 报错，它都会执行。

```javascript
let loading = true;

async function loadData() {
  try {
    return await fetchData();
  } catch (error) {
    console.error(error);
    return null;
  } finally {
    loading = false;   // 无论成功失败，都关闭 loading
    console.log('请求结束');
  }
}
```

典型场景：关闭 loading 状态、释放资源、断开连接。

```javascript
async function withLock(resource, task) {
  resource.lock();
  try {
    return await task();
  } finally {
    resource.unlock();  // 保证任务结束后一定解锁
  }
}
```

**注意：`finally` 里 `return` 会覆盖 try/catch 的返回值。**

```javascript
// ❌ finally 的 return 覆盖了 try 的返回值
async function example() {
  try {
    return '来自 try';
  } finally {
    return '来自 finally';  // 最终返回这个
  }
}
example().then(v => console.log(v));  // 来自 finally
```

后果：finally 里的 return 会**覆盖** try 或 catch 中的返回值，导致调用方拿到错误的结果。所以 finally 里**只做清理，不要 return**。

## 三种错误传播路径对比

| 写法 | 错误去向 |
|---|---|
| `try { await x() } catch(e) { ... }` | 错误被 catch 捕获，流程继续 |
| `await x().catch(e => ...)` | 等价于 try/catch，但语义偏"值处理" |
| 什么都不写 | 错误向上冒泡，最终成为未处理的 Promise 拒绝 |

```javascript
// 全局兜底（浏览器环境）
window.addEventListener('unhandledrejection', (event) => {
  console.error('未处理的 Promise 拒绝：', event.reason);
});
```

## 与 Python 的对比

Python 的 `try/except/finally` 语义和 JS 完全一致，也包括 `except` 里再抛错、finally 里 return 覆盖返回值这些坑。

```python
# Python
try:
    result = await fetch_data()
except Exception as e:
    print(e)
finally:
    loading = False
```

```javascript
// JS
try {
  const result = await fetchData();
} catch (error) {
  console.error(error);
} finally {
  loading = false;
}
```

## 小结

- `try/catch` 可以捕获 `await` 的异步错误，写法与同步一致。
- `.catch` 不 return 也不 throw 时，会把失败转成 `undefined` 成功值——**错误被吞**。
- catch 块内部也可能出错，必要时双层 try/catch 保护。
- `finally` 用于清理（关闭 loading、释放资源），**不要在里面 return**。
- 未处理的 Promise 拒绝会触发 `unhandledrejection` 事件。
