# Canvas 动画：requestAnimationFrame 与动画循环

> 这一节讲怎么让 Canvas 动起来，以及为什么 `requestAnimationFrame` 比 `setInterval` 更适合做动画。

## 动画的本质：反复擦除再重画

动画就是**每一帧都把画面擦掉重画一遍，而且每一帧画的位置稍有不同**。核心三步：更新状态 → 清屏 → 重绘。

```javascript
const canvas = document.querySelector('#board');
const ctx = canvas.getContext('2d');
let x = 0;

function draw() {
  ctx.clearRect(0, 0, canvas.width, canvas.height); // 1. 清屏
  ctx.fillStyle = 'rgb(33, 150, 243)';
  ctx.fillRect(x, 80, 30, 30);                      // 2. 按当前状态画
  x += 3;                                           // 3. 更新状态
  requestAnimationFrame(draw);                       // 4. 约 16.7ms 后画下一帧
}
draw();
```

每帧 x 加 3，方块就往右移动一点。重复 60 次/秒，人眼看到的就是平滑动画。

## requestAnimationFrame 是什么

`requestAnimationFrame(fn)` 告诉浏览器：**在下一次重绘之前，调用一次 fn**。浏览器会自动匹配刷新率（通常 60 次/秒，约 16.7ms 一帧）。

```javascript
function step() {
  // 做这一帧的事
  requestAnimationFrame(step);   // 末尾再预约下一帧
}
requestAnimationFrame(step);     // 启动
```

它**只预约一帧**，所以要持续动画，就得在回调里再调一次 `requestAnimationFrame`。

## 对比 setInterval：四个优势

| 维度 | requestAnimationFrame | setInterval |
|---|---|---|
| 时机 | 与屏幕刷新同步 | 固定时间片，可能与刷新错位 |
| 后台标签页 | 自动暂停，省电 | 照样跑，浪费 CPU |
| 丢帧 | 一次回调里能感知 | 回调排队堆积 |
| 时间精度 | 回调拿到高精度时间戳 | 依赖系统定时器 |

```javascript
// ❌ setInterval 做法：与刷新率错位，切后台还在跑
setInterval(() => {
  x += 3;
  draw();      // 可能一帧画两次，也可能两次刷新画一次
}, 16);

// ✅ rAF 做法：与刷新同步，切后台自动暂停
function loop() {
  x += 3;
  draw();
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);
```

翻车现场一：以为 requestAnimationFrame 和 setInterval 一样会"自动循环"。

```javascript
// ❌ 只画一帧就停了
requestAnimationFrame(draw);   // draw 执行完就结束

// ✅ 回调内部再预约下一帧
function draw() {
  // ...
  requestAnimationFrame(draw);
}
requestAnimationFrame(draw);
```

后果：rAF 是"单次预约"，不是定时器。忘记在回调里再次调用，动画就只会跑一帧。这是新人最常踩的坑。

## 用时间戳做匀速运动

rAF 的回调会收到一个 `timestamp` 参数（毫秒），用它做基于时间的运动比"每帧 +3"更稳——即使掉帧，物体也能走到正确位置。

```javascript
let start = null;
function step(ts) {
  if (start === null) start = ts;
  const elapsed = ts - start;     // 已过去多少毫秒
  const x = elapsed * 0.2;        // 速度 0.2 px/ms
  ctx.clearRect(0, 0, canvas.width, canvas.height);
  ctx.fillRect(x, 80, 30, 30);
  if (elapsed < 5000) requestAnimationFrame(step);  // 5 秒后停
}
requestAnimationFrame(step);
```

## 停止动画：cancelAnimationFrame

`requestAnimationFrame` 返回一个 id，传给 `cancelAnimationFrame(id)` 就能取消尚未执行的预约。

```javascript
let rafId = null;
function loop() {
  x += 3;
  draw();
  rafId = requestAnimationFrame(loop);
}
rafId = requestAnimationFrame(loop);

// 某个条件满足后停
function stop() {
  cancelAnimationFrame(rafId);
}
```

翻车现场二：停止动画忘了清屏，画面停在最后一帧。

```javascript
// ❌ 取消后画面定格，物体"卡"在中间
cancelAnimationFrame(rafId);

// ✅ 想清空就手动清屏，或重置到初始态再画一帧
cancelAnimationFrame(rafId);
ctx.clearRect(0, 0, canvas.width, canvas.height);   // 彻底清空
```

后果：`cancelAnimationFrame` 只阻止**下一次**回调，不会改动画布。画布上仍然是最后一帧的内容。要清空就得自己 `clearRect`。

## 小结

- 动画 = 清屏 → 重绘 → 更新状态 → 预约下一帧。
- `requestAnimationFrame(fn)` 单次预约、与刷新率同步、切后台自动暂停。
- 它**不是**定时器，持续动画要在回调里再次调用。
- 用回调的 `timestamp` 做基于时间的运动，掉帧也不偏位。
- 停止用 `cancelAnimationFrame(id)`，且要自己决定清不清屏。
