# 加载状态与错误处理：三态与 AbortController

> 这一节讲一个真实应用必备的"三态管理"，以及如何取消一个已经发出去的请求。

## 三态：loading / error / empty

任何"从服务器取数据显示"的界面，都至少有三种状态：

| 状态 | 含义 | 界面表现 |
|---|---|---|
| `loading` | 请求进行中 | 转圈、骨架屏 |
| `error` | 请求失败 | 错误提示、重试按钮 |
| `success` | 请求成功 | 展示数据 |

如果数据可能是空列表，还要加一个 `empty`（空状态）：

```javascript
async function loadUsers() {
  setStatus('loading');
  try {
    const res = await fetch('/api/users');
    if (!res.ok) throw new Error('加载失败');
    const data = await res.json();
    if (data.length === 0) {
      setStatus('empty');
    } else {
      setStatus('success');
      render(data);
    }
  } catch (error) {
    setStatus('error');
    showError(error.message);
  }
}
```

翻车现场一：请求失败时界面永远停在 loading，转圈转个没完。

```javascript
// ❌ 没有错误处理，失败就卡住
async function load() {
  setStatus('loading');
  const res = await fetch('/api/data');
  const data = await res.json();
  render(data);
  setStatus('success');  // 如果上面抛错，这行永远不会执行
}

// ✅ try/catch 兜底
async function load() {
  setStatus('loading');
  try {
    const res = await fetch('/api/data');
    if (!res.ok) throw new Error('HTTP ' + res.status);
    const data = await res.json();
    render(data);
    setStatus('success');
  } catch (error) {
    setStatus('error');  // 失败时也要更新状态
  }
}
```

后果：没有 catch 时，一旦请求失败（断网、404、500），函数抛错中断，`setStatus('success')` 永远不执行，界面就**永远显示 loading**。用户看到的是一个永远转不停的圈，不知道发生了什么。

## 状态与 UI 的对应

```html
<div id="app">
  <div id="loading" style="display:none;">加载中...</div>
  <div id="error" style="display:none;">出错了，<button id="retry">重试</button></div>
  <div id="empty" style="display:none;">暂无数据</div>
  <ul id="list"></ul>
</div>
```

```javascript
function setStatus(status) {
  document.querySelector('#loading').style.display = status === 'loading' ? 'block' : 'none';
  document.querySelector('#error').style.display = status === 'error' ? 'block' : 'none';
  document.querySelector('#empty').style.display = status === 'empty' ? 'block' : 'none';
}
```

## AbortController：取消请求

场景：用户在搜索框快速输入"北"、"北京"、"北京市"，触发了 3 次请求。第 1 次的响应可能比第 3 次**更晚到**，导致界面显示成旧结果。

```javascript
let controller = null;

async function search(keyword) {
  // 取消上一次还没完成的请求
  if (controller) {
    controller.abort();
  }
  controller = new AbortController();

  try {
    const res = await fetch(`/api/search?q=${keyword}`, {
      signal: controller.signal  // 把信号绑上去
    });
    const data = await res.json();
    render(data);
  } catch (error) {
    if (error.name === 'AbortError') {
      console.log('请求被取消');  // 取消不算真正的错误，静默处理
      return;
    }
    console.error('请求失败：', error);
  }
}
```

`AbortController` 的核心三步：

1. `new AbortController()` 创建一个控制器
2. 把 `controller.signal` 传给 fetch 的 `signal` 选项
3. 调用 `controller.abort()` 取消请求（fetch 会抛 `AbortError`）

翻车现场二：用 AbortController 时忘了区分 AbortError 和真实错误，导致取消也弹错误提示。

```javascript
// ❌ 取消也被当成错误处理
async function load() {
  try {
    const res = await fetch(url, { signal: controller.signal });
    render(await res.json());
  } catch (error) {
    showError('加载失败');  // 取消也会弹"加载失败"，用户体验差
  }
}

// ✅ 区分取消和失败
async function load() {
  try {
    const res = await fetch(url, { signal: controller.signal });
    render(await res.json());
  } catch (error) {
    if (error.name === 'AbortError') return;  // 取消，静默
    showError('加载失败');  // 真正的失败才提示
  }
}
```

后果：每次用户快速输入，旧的请求被取消都会弹一个"加载失败"的提示。用户会看到一堆莫名其妙的错误信息，体验极差。判断 `error.name === 'AbortError'` 是处理取消的标准做法。

## 超时控制

`AbortController` 还能配合 `setTimeout` 实现超时：

```javascript
async function fetchWithTimeout(url, ms) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);

  try {
    const res = await fetch(url, { signal: controller.signal });
    clearTimeout(timer);
    return res;
  } catch (error) {
    clearTimeout(timer);
    throw error;
  }
}

// 超过 5 秒就取消
fetchWithTimeout('/api/slow', 5000).catch(error => {
  if (error.name === 'AbortError') console.log('超时');
});
```

## 小结

- 数据加载界面至少有 **loading / error / empty** 三态，都要有对应的 UI。
- 请求失败必须更新状态，否则界面会**永远停在 loading**。
- `AbortController` 用于取消请求，三步：创建、绑 signal、abort。
- 取消会抛 `AbortError`，要单独处理、静默忽略，不要提示给用户。
- `AbortController` + `setTimeout` 可实现请求超时。
