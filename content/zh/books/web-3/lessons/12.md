# Map 与 Set：对比 Object / Array 的适用边界

> 这一节讲两个"增强版"数据结构：Map（键值对）和 Set（不重复集合），以及什么时候该用它们而不是 Object/Array。

## Map：键可以是任意类型

普通 Object 的键**只能是字符串或 Symbol**。Map 的键可以是**任意类型**：对象、函数、数字都行。

```javascript
const map = new Map();

map.set('name', '张三');
map.set(1, '数字键');
map.set({ id: 1 }, '对象作为键');
map.set(() => {}, '函数作为键');

console.log(map.get('name'));  // '张三'
console.log(map.size);         // 4
```

Object 做不到：

```javascript
const obj = {};
obj[{ id: 1 }] = '值';       // 对象的键会被 toString 成 "[object Object]"
console.log(obj);             // { '[object Object]': '值' }
```

## Map 的常用 API

```javascript
const map = new Map();

map.set('a', 1);             // 增 / 改
map.get('a');                // 查：1
map.has('a');                // 判断存在：true
map.delete('a');             // 删
map.clear();                 // 清空
map.size;                    // 大小

// 遍历
map.forEach((value, key) => console.log(key, value));
for (const [key, value] of map) console.log(key, value);
```

对比 Object，Map 在"需要频繁增删键"的场景下**性能更好**，因为 Map 是为频繁增删优化的。

翻车现场一：用 Object 做"计数/去重"时，数字 1 和字符串 '1' 被当成同一个键。

```javascript
// ❌ Object 的键都会被转成字符串
const counts = {};
counts[1] = 1;
counts['1'] = 2;
console.log(counts);  // { '1': 2 } —— 1 和 '1' 冲突了

// ✅ Map 的键保留类型
const map = new Map();
map.set(1, 1);
map.set('1', 2);
console.log(map.get(1));   // 1
console.log(map.get('1')); // 2 —— 不同类型，不冲突
```

后果：Object 会**强制把所有键 toString**，导致数字 `1` 和字符串 `'1'` 冲突，数字 `true` 和字符串 `'true'` 冲突。如果业务里键可能是混合类型，用 Map 才能保真。

## Set：值唯一的集合

Set 是**元素不重复**的集合，常用于去重：

```javascript
const set = new Set();

set.add(1);
set.add(1);        // 重复，不会添加
set.add(2);
console.log(set.size);   // 2

set.has(1);      // true
set.delete(1);   // true
```

最常用的场景——**数组去重**：

```javascript
const arr = [1, 2, 2, 3, 3, 3];
const unique = [...new Set(arr)];  // [1, 2, 3]
```

翻车现场二：以为 `new Set()` 能按对象的"内容"去重。

```javascript
// ❌ 对象去重失效
const set = new Set();
set.add({ id: 1 });
set.add({ id: 1 });   // 看起来一样，但这是两个不同的对象引用
console.log(set.size);  // 2 —— 没有去重！

// Set 判断唯一性用的是"引用相等"，和对象内容无关
console.log({id:1} === {id:1});  // false

// ✅ 需要按内容去重时，用 Map 或先提取唯一键
const seen = new Map();
items.forEach(item => seen.set(item.id, item));
const unique = [...seen.values()];
```

后果：Set 的去重依据是**引用相等（===）**，不是"长得一样"。两个内容相同但引用不同的对象会被当成不同元素，去重失败。需要按内容去重时，要先提取一个唯一的原始类型键（如 id）。

## 四者适用边界

| 需求 | 用 | 原因 |
|---|---|---|
| 键值对，键是字符串/Symbol | Object | 字面量语法简洁，JSON 友好 |
| 键值对，键是任意类型 | Map | 键类型保真，增删性能好 |
| 去重、判断存在性 | Set | 天然去重，has 是 O(1) |
| 有序集合、需要下标 | Array | 有 index、slice、map 等方法 |
| 需要 JSON 序列化 | Object / Array | Map、Set 不能直接 JSON.stringify |

```javascript
// Map / Set 不能直接序列化
JSON.stringify(new Map([['a', 1]]));  // '{}'
JSON.stringify(new Set([1, 2]));      // '{}'
```

## 与 Python 的对比

Python 的 `dict` 键可以是任意可哈希类型，`set` 也是天然去重，与 JS 的 Map/Set 高度对应：

```python
# Python
d = {1: '数字键', '1': '字符串键'}  # 不冲突，键保留类型
s = set([1, 1, 2])  # {1, 2}
```

```javascript
// JS
const map = new Map();
map.set(1, '数字键');
map.set('1', '字符串键');  // 不冲突
const set = new Set([1, 1, 2]);  // Set {1, 2}
```

Python 的 dict 在"键类型保真"上比 JS 的 Object 更强，更接近 JS 的 Map。

## 小结

- Map 的键可以是**任意类型**，Object 的键会被强制转成字符串。
- Map 适合频繁增删键值对的场景，性能优于 Object。
- Set 天然去重，但判重依据是**引用相等**，对象去重要按唯一键处理。
- Map、Set **不能直接 JSON 序列化**，需要转成 Array/Object 才行。
- 选型：字符串键 + 要序列化 → Object；任意键 → Map；去重 → Set；有序 → Array。
