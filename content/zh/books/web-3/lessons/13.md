# localStorage 进阶：容量、版本迁移与 JSON.parse 安全

> 这一节讲 localStorage 的进阶用法，重点是怎么避免"读出来一段坏数据导致整个页面崩"。

## 回顾 localStorage 基础

```javascript
localStorage.setItem('name', '张三');
localStorage.getItem('name');    // '张三'
localStorage.removeItem('name');
localStorage.clear();            // 清空所有
```

存进去的都是**字符串**。要存对象必须 `JSON.stringify`，读取要 `JSON.parse`。

## 容量限制：约 5MB，且存的是字符串

localStorage 每个源（origin）大约只有 **5MB** 空间，超出会抛 `QuotaExceededError`。而且**按字符串长度计算**，不是按对象大小。

```javascript
// 看看用了多少
function usedBytes() {
  let total = 0;
  for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i);
    total += key.length + localStorage.getItem(key).length;
  }
  return total;  // 字符数（约等于字节数，中文占 3 字节）
}
```

翻车现场一：存了大对象导致超出配额，页面静默报错。

```javascript
// ❌ 把整个大列表存进去
try {
  localStorage.setItem('huge-list', JSON.stringify(bigArray));  // 可能抛错
} catch (e) {
  console.error('存不下了');  // 必须捕获，否则中断
}

// ✅ 先算大小，超了就提示或降级
function safeSet(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
    return true;
  } catch (e) {
    if (e.name === 'QuotaExceededError') {
      console.warn('localStorage 已满，数据未保存');
      return false;
    }
    throw e;
  }
}
```

后果：超出 5MB 时 `setItem` 会**抛异常**。如果不包裹 try/catch，后续代码全部中断，可能导致页面功能瘫痪。生产代码应始终对 `setItem` 做容量保护。

## JSON.parse 必须 try/catch

localStorage 里的数据**可能损坏**：用户手动改过、旧版本格式变了、甚至被其他标签页写了坏数据。直接 `JSON.parse` 可能抛错。

```javascript
// ❌ 危险：假设存储的数据一定是合法 JSON
function getConfig() {
  const raw = localStorage.getItem('config');
  return JSON.parse(raw);  // raw 可能是 null、undefined 或坏 JSON
}

getConfig();  // 如果 raw 是 "不是json"，抛 SyntaxError

// ✅ 安全读取：带默认值 + try/catch
function getConfig() {
  const raw = localStorage.getItem('config');
  if (!raw) return { theme: 'light' };  // 默认值
  try {
    return JSON.parse(raw);
  } catch (e) {
    console.warn('config 数据损坏，使用默认值');
    localStorage.removeItem('config');   // 清掉坏数据
    return { theme: 'light' };
  }
}
```

翻车现场二：把 `null` 或 `undefined` 当对象用，导致 TypeError。

```javascript
// ❌ 没做兜底
const user = JSON.parse(localStorage.getItem('user'));
console.log(user.name);  // 如果没存过，getItem 返回 null，JSON.parse(null) 是 null

// ✅ 提供默认值
const raw = localStorage.getItem('user');
let user = { name: '游客' };
if (raw) {
  try {
    user = JSON.parse(raw);
  } catch (e) {
    console.warn('用户数据损坏');
  }
}
console.log(user.name);  // 总有值
```

后果：`localStorage.getItem` 没找到时返回 `null`，`JSON.parse(null)` 结果是 `null`。后续访问 `null.name` 就抛 TypeError。养成"**读取必有默认值**"的习惯。

## 版本迁移：数据结构变了怎么办

应用升级后，localStorage 里的旧数据格式可能和新版本不兼容。需要在读取时做迁移：

```javascript
const STORAGE_VERSION = 2;

function loadData() {
  const raw = localStorage.getItem('app-data');
  if (!raw) return getDefaultData();

  let parsed;
  try {
    parsed = JSON.parse(raw);
  } catch (e) {
    return getDefaultData();
  }

  // 版本迁移
  if (!parsed.version || parsed.version < STORAGE_VERSION) {
    parsed = migrate(parsed, parsed.version || 1);
    parsed.version = STORAGE_VERSION;
    localStorage.setItem('app-data', JSON.stringify(parsed));
  }

  return parsed;
}

function migrate(data, fromVersion) {
  if (fromVersion === 1) {
    // v1 → v2：把旧字段名改掉
    data.settings = data.prefs || {};
    delete data.prefs;
  }
  return data;
}
```

关键是在数据里**存一个版本号字段**，每次读取时比对并升级。

## 小结

- localStorage 每个源约 **5MB**，按字符串长度算，超了抛 `QuotaExceededError`。
- `setItem` 要包裹 try/catch，避免容量超限中断页面。
- `JSON.parse` **必须 try/catch**，存储的数据可能损坏或为 `null`。
- 读取要有**默认值兜底**，防止 `null.name` 式 TypeError。
- 数据结构升级靠**版本号字段 + 迁移函数**。
