# 项目设计：天气/汇率查询应用的功能拆解

> 这一节不写代码，先把要做的东西想清楚——需求、数据结构、API 选型、界面草图，四步走。

## 先定需求清单

做一个"天气 + 汇率"查询应用，先把**用户能做什么**列成清单。别急着写代码，清单写清楚后面才不会被返工。

**核心需求（MVP）**
- 输入城市名，查询该城市当前天气（温度、天气状况、湿度、风速）。
- 选择两种货币，查询它们的实时汇率。
- 加载时显示 loading 状态。
- 出错时显示错误信息并允许重试。

**进阶需求（加分项）**
- 把最近查询的城市/汇率存到本地，下次打开自动恢复。
- 搜索城市名时做防抖，停止输入后再发请求。
- 支持切换温度单位（℃/℉）。
- 响应式布局，手机上也好看。

需求清单要**分清优先级**。先把核心需求做稳，再动进阶需求。边写边加需求是延期的最大原因。

## 数据结构：决定你拿到什么

后端返回什么，你就得存什么。提前设计好数据形状，后面渲染和缓存都省事。

```javascript
// 天气数据
{
  city: '北京',
  temp: 23,
  condition: '晴',
  humidity: 45,      // 湿度 %
  windSpeed: 3.2,    // 风速 m/s
  updatedAt: 1717500000000
}

// 汇率数据
{
  base: 'CNY',
  target: 'USD',
  rate: 0.138,
  updatedAt: 1717500000000
}
```

设计要点：**只保留页面真正要显示的字段**，多余字段直接丢掉，减少内存和网络传输。`updatedAt` 用时间戳存，方便判断是否过期。

## API 选型：免费 ≠ 好用

这类练习级项目，选 API 有三个硬指标：**免登录/免 key、有 CORS、文档清晰**。

| 用途 | 候选 | 注意点 |
|---|---|---|
| 天气 | Open-Meteo（免费无 key） | 需先把城市名转成经纬度 |
| 汇率 | exchangerate-api / 央行公开接口 | 注意调用频率限制 |

翻车现场一：直接调一个没有 CORS 的接口，浏览器报错。

```javascript
// ❌ 接口不允许跨域，控制台报 CORS error
fetch('http://某个无CORS的天气站/北京')
  .then(r => r.json())   // 直接失败

// ✅ 选带 Access-Control-Allow-Origin 的接口
fetch('https://api.open-meteo.com/v1/forecast?latitude=39.9&longitude=116.4&current=temperature_2m')
  .then(r => r.json())
```

后果：浏览器同源策略会拦下跨域响应。选 API 时先确认响应头有 `Access-Control-Allow-Origin: *` 或包含你的域名，否则前端直接调不通。

## 界面草图：先用纸画

在动手前，把界面结构画成 ASCII 草图，能省掉大量返工。

```
┌──────────────────────────────────────┐
│  [北京          ]  [查询]            │  ← 搜索框 + 按钮
├──────────────────────────────────────┤
│  ⏳ 加载中… / ❌ 请求失败，点此重试    │  ← 状态区
├──────────────────────────────────────┤
│  城市：北京                           │
│  温度：23 ℃     天气：晴              │  ← 天气卡片
│  湿度：45%      风速：3.2 m/s         │
├──────────────────────────────────────┤
│  [CNY ▼]  →  [USD ▼]  [查询]         │  ← 汇率区
│  1 CNY = 0.138 USD                   │
└──────────────────────────────────────┘
```

草图要标出：**状态区**（加载/错误/空/成功）和**数据区**。真实应用至少要处理这四种状态，不是只有"成功"。

## 拆成模块：一个文件只做一件事

把功能按职责拆成几个模块，后面每章对应一个：

```text
weather-app/
├── index.html        # 骨架
├── style.css         # 布局与样式
└── main.js           # 入口：串联 API + 缓存 + 渲染
                      # 内部可拆：api.js(请求) / storage.js(缓存) / ui.js(渲染)
```

| 模块 | 职责 | 依赖 |
|---|---|---|
| `api.js` | 封装 fetch、错误处理 | 无 |
| `storage.js` | localStorage 读写 | 无 |
| `ui.js` | 渲染数据、切换状态 | api、storage |

依赖单向：ui 用 api 和 storage，反过来不行。这样每个模块都能单独测试。

## 小结

- 需求分**核心**和**进阶**两档，先做稳核心。
- 数据结构只保留要显示的字段，附带 `updatedAt` 时间戳。
- 选 API 必查 CORS，否则前端调不通。
- 界面先画草图，明确四种状态（空/加载/错误/成功）。
- 按职责拆模块，依赖单向，便于测试和复用。
