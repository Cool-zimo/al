# 实战：接真实 API 的小应用与 CORS

> 这一节把前 4 课串起来，做一个能调用公开 API 的小应用，并搞懂跨域到底是怎么回事。

## 选一个公开 API

公开 API 是练手的好素材。推荐几个无需登录即可使用的：

| API | 地址 | 说明 |
|---|---|---|
| 公共词典 | `https://api.dictionaryapi.dev/api/v2/entries/en/{word}` | 查英文单词释义 |
| 比特币价格 | `https://api.coindesk.com/v1/bpi/currentprice.json` | 实时价格 |
| 测试接口 | `https://jsonplaceholder.typicode.com/posts/1` | 测试用假数据 |

## 实战：查单词应用

```html
<input id="word" placeholder="输入英文单词，如 hello">
<button id="search">查询</button>
<div id="loading" style="display:none;">加载中...</div>
<div id="error" style="display:none;"></div>
<div id="result"></div>
```

```javascript
async function searchWord() {
  const word = document.querySelector('#word').value.trim();
  const resultEl = document.querySelector('#result');
  const loadingEl = document.querySelector('#loading');
  const errorEl = document.querySelector('#error');

  resultEl.textContent = '';
  errorEl.style.display = 'none';
  loadingEl.style.display = 'block';

  try {
    const res = await fetch(`https://api.dictionaryapi.dev/api/v2/entries/en/${word}`);
    if (!res.ok) throw new Error(`查无此词：${word}`);
    const data = await res.json();

    const meanings = data[0].meanings
      .map(m => `<li>${m.partOfSpeech}：${m.definitions[0].definition}</li>`)
      .join('');
    resultEl.innerHTML = `<h3>${data[0].word}</h3><ul>${meanings}</ul>`;
  } catch (error) {
    errorEl.textContent = error.message;
    errorEl.style.display = 'block';
  } finally {
    loadingEl.style.display = 'none';
  }
}

document.querySelector('#search').addEventListener('click', searchWord);
```

注意这个应用**直接用浏览器打开就能跑**，因为它访问的 API 在服务端配置了允许跨域。

## CORS：跨域资源共享

**跨域（CORS）问题只在浏览器里存在**。当你用 JS 从一个域名请求另一个域名时，浏览器会检查响应头里有没有允许当前源的声明。

```
你的页面：https://myapp.com
请求的接口：https://api.other.com/data
```

浏览器会先问服务器："`myapp.com` 能访问你吗？"——看响应头：

```
Access-Control-Allow-Origin: https://myapp.com
```

如果这个头允许你的源，浏览器才把响应交给 JS；否则**拦截**，控制台报 CORS 错误。

翻车现场一：在浏览器里直接请求一个没配 CORS 的接口，得到"跨域报错"。

```javascript
// ❌ 浏览器里请求未配置 CORS 的接口
fetch('https://另一个域名.com/api/data')
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.log(err));  // TypeError: Failed to fetch
// 控制台：Access to fetch at '...' from origin '...' has been blocked by CORS policy
```

后果：请求其实**发出去了**，服务器也可能处理了，但浏览器**拦截了响应**，JS 拿不到数据。这不是代码 bug，而是浏览器的安全策略。常见解决方案：

1. **后端加 CORS 头**（最正统，需要你能改后端）
2. **用代理**：让同源的后端转发请求
3. **开发环境代理**：`vite`、`webpack-dev-server` 都支持配置代理

翻车现场二：以为 CORS 报错就是请求没发出去，反复重试。

```javascript
// ❌ 无意义的重试
async function load() {
  for (let i = 0; i < 3; i++) {
    try {
      return await fetch('https://未配CORS.com/api/data');
    } catch (e) {
      console.log('重试...');  // 重试 3 次都失败，因为服务器根本没改 CORS 配置
    }
  }
}

// ✅ 正视问题：要么后端加头，要么走代理
// 开发环境可用 vite.config.js 配代理
// server: { proxy: { '/api': 'https://未配CORS.com' } }
```

后果：CORS 是**响应被拦截**，不是网络失败。重试不会改变响应头，只会让问题重复出现。解决方向是改服务端配置或加代理。

## CORS 需要的两个头

服务端要返回的响应头：

```
Access-Control-Allow-Origin: https://myapp.com   # 允许哪个源
Access-Control-Allow-Methods: GET, POST, PUT     # 允许哪些方法
```

对于带自定义头的请求（如 `Authorization`），浏览器会先发一个 **预检请求（OPTIONS）**，确认允许后才发正式请求。这是浏览器的自动行为，开发者通常不用手写。

## 与 Python 的对比

Python 用 `requests` 请求其他域名**不存在跨域问题**——CORS 是**浏览器**的安全策略，服务端之间通信不受限。

```python
# Python 服务端请求，无 CORS 概念
import requests
r = requests.get('https://另一个域名.com/api/data')
print(r.json())  # 正常
```

JS 浏览器环境受同源策略约束，这就是为什么"前后端分离"项目经常要处理 CORS。

## 小结

- 公开 API 是练手 fetch 的好素材，选无需登录的接口起步。
- 完整流程：`loading` → `fetch` → 检查 `res.ok` → `res.json()` → 渲染 → `catch` 处理错误 → `finally` 关 loading。
- CORS 是**浏览器**的安全策略，服务端间通信不存在。
- CORS 报错是**响应被拦截**，重试无用，要后端加 `Access-Control-Allow-Origin` 头或走代理。
- 带自定义头的请求会触发浏览器自动预检（OPTIONS）。
