# 收官：代码组织、性能、可访问性与后续学习

> 最后一节，把项目从"能跑"变成"能维护"：拆模块、抠性能、照顾可访问性、学会调试。

## 代码组织：从单文件到模块

小型练习一个 `main.js` 够用，但功能多了就要拆。浏览器原生支持 ES Module：

```html
<script type="module" src="./main.js"></script>
```

```javascript
// api.js
export async function getWeather(city) { /* ... */ }
export async function getRate(base, target) { /* ... */ }

// storage.js
export const cache = {
  read() { /* ... */ },
  save(data) { /* ... */ }
};

// ui.js
export function render(data) { /* ... */ }
export function showStatus(state, msg) { /* ... */ }

// main.js
import { getWeather } from './api.js';
import { cache } from './storage.js';
import { render, showStatus } from './ui.js';
```

规则：**依赖单向**。ui 用 api 和 storage，反过来不行。每个模块单独可测、可替换。

## 性能：四条最划算的优化

1. **防抖输入类请求**：搜索、联想类 300ms 防抖，立竿见影。
2. **缓存重复请求**：localStorage 或内存 Map，避免同参数重复网络往返。
3. **取消无用请求**：用 AbortController 在页面切换/组件卸载时 abort。
4. **DOM 操作批量、减少重排**：先改数据再统一渲染，别在循环里反复读写 offsetWidth。

```javascript
// ❌ 循环里反复读写布局，触发多次重排
items.forEach(it => {
  el.appendChild(renderItem(it));
  console.log(el.offsetHeight);   // 强制同步布局
});

// ✅ 批量插入，最后再读一次
const frag = document.createDocumentFragment();
items.forEach(it => frag.appendChild(renderItem(it)));
el.appendChild(frag);
console.log(el.offsetHeight);
```

翻车现场一：在动画循环里同步读布局属性。

```javascript
function loop() {
  el.style.width = x + 'px';
  const w = el.offsetWidth;   // 强制浏览器立刻重排，掉帧
  x += 3;
  requestAnimationFrame(loop);
}
```

后果：写样式后立刻读 `offsetWidth`/`getBoundingClientRect`，浏览器必须同步完成一次布局计算，这一帧的时间预算被吃掉，动画明显卡顿。批量写、最后统一读。

## 可访问性：让更多人能用

- **语义标签**：`<main>`、`<nav>`、`<button>` 替代满屏 `<div>`。
- **表单关联**：`<input id="kw">` 配 `<label for="kw">`，点击标签能聚焦输入框。
- **状态告知**：`aria-live="polite"` 让读屏软件读出动态内容。

```html
<label for="cityInput">城市</label>
<input id="cityInput" type="text" aria-describedby="cityHint" />
<span id="cityHint">请输入中文城市名</span>

<section id="status" aria-live="polite"></section>
```

- **键盘可达**：自定义控件用 `tabindex`、按钮用原生 `<button>`（自带空格/回车激活）。
- **颜色对比度**：文字与背景对比度至少 4.5:1。

翻车现场二：只用颜色区分状态。

```html
<!-- ❌ 色盲用户看不出区别 -->
<span style="color:red">失败</span>
<span style="color:green">成功</span>

<!-- ✅ 颜色 + 文字/图标双重表达 -->
<span class="status status--error">✕ 失败</span>
<span class="status status--success">✓ 成功</span>
```

后果：约 8% 男性有某种色觉障碍，仅靠颜色会丢失关键信息。状态、错误必须同时有文字或图标。

## 调试要点：console 之外还有这些

- **断点**：DevTools Sources 面板点行号下断点，比 `console.log` 高效。
- **网络**：Network 面板看请求是否发出、状态码、响应内容。
- **条件断点**：只在特定值出现时停下，比如 `city === '北京'`。
- **监控表达式**：Watch 面板盯住 `seq`、`cache` 等变量。
- **断点日志**：不暂停，只在命中时打印，替代临时 `console.log`。

调试竞态问题最有用的一招：**给每次请求编号**。在请求发起时 `console.log('[req #3] 发出 北京')`，回来时再打一次，一眼看出谁先谁后。

## 指路后续学习

学完本册，你已经能独立做一个能发请求、有缓存、有状态的 Web 应用。下一步：

| 方向 | 学什么 | 为什么 |
|---|---|---|
| 框架 | React / Vue | 数据和视图自动同步，告别手写 DOM |
| 工程化 | Vite / Webpack、ESM | 模块热更新、打包、按需加载 |
| 类型 | TypeScript | 接口数据有类型约束，重构更稳 |
| 后端 | Node.js + Express | 自己写 API，绕过 CORS 限制 |
| 全栈 | Next.js / Nuxt | SSR、路由、数据获取一体化 |

## 小结

- 用 ES Module 拆分 api / storage / ui，依赖单向。
- 性能四件套：防抖、缓存、取消、批量 DOM 操作。
- 可访问性：语义标签 + 表单关联 + aria-live + 键盘可达 + 对比度。
- 状态别只靠颜色，必须配文字/图标。
- 调试竞态：给每次请求编号，Network 面板看状态。
- 后续走框架（React/Vue）、工程化、TypeScript、Node 后端。
