# 接入真实 API：fetch + async/await + 错误处理 + 加载状态

> 这一节把前端和真实接口连起来：用 fetch 拿数据、用 async/await 写、把错误和加载状态都处理好。

## fetch 的基本形态

`fetch(url)` 返回一个 Promise，解析后是 `Response` 对象。要拿到 JSON，还得再 `.json()` 一次。

```javascript
async function getWeather(city) {
  const url = 'https://api.open-meteo.com/v1/forecast'
    + '?latitude=39.9&longitude=116.4'
    + '&current=temperature_2m,weather_code,wind_speed_10m';
  const res = await fetch(url);
  const data = await res.json();
  return data;
}
```

两个 `await`：第一个等响应头，第二个等响应体解析完。少写一个就拿到 Promise 而不是数据。

## async/await 让异步代码像同步

```javascript
async function main() {
  showStatus('loading');
  try {
    const data = await getWeather('北京');
    render(data);
    showStatus('success');
  } catch (err) {
    showStatus('error', err.message);
  }
}
```

`async` 函数里才能用 `await`。`await` 会暂停函数执行直到 Promise 完成——**但只是暂停这个函数，不会阻塞整个页面**，事件循环照常运行。

## 错误处理：fetch 不会自动抛 HTTP 错误

这是最容易被忽略的一点：`fetch` 遇到 404、500 **不会** reject，只有网络断开、跨域被拦才会 reject。

```javascript
// ❌ 以为 fetch 失败会进 catch
const res = await fetch(url);
const data = await res.json();     // 404 时也返回 HTML，.json() 抛错但类型信息丢了

// ✅ 手动检查 ok
const res = await fetch(url);
if (!res.ok) {
  throw new Error('请求失败：' + res.status);   // 主动抛错，进入 catch
}
const data = await res.json();
```

翻车现场一：只看 `catch`，却不知道 404 根本不走 catch。

```javascript
async function load() {
  try {
    const res = await fetch(url);   // 404 时 res.ok 为 false
    const data = await res.json();
    render(data);
  } catch (e) {
    showError(e.message);           // 404 时这里根本不会执行
  }
}
```

后果：`fetch` 只在**网络层**失败时 reject，HTTP 错误状态码属于"成功拿到了响应"，Promise 正常 fulfill。必须检查 `res.ok` 或 `res.status`，否则错误状态会被当成成功渲染。

## 加载状态：先置 loading 再请求

```javascript
async function search(city) {
  showStatus('loading');
  try {
    const data = await getWeather(city);
    renderWeather(data);
    showStatus('success');
  } catch (e) {
    showStatus('error', e.message);
  }
}

// 按钮点击
searchBtn.addEventListener('click', () => {
  search(cityInput.value.trim());
});
```

状态切换顺序固定：**loading → 成功/失败**。在数据返回前就显示 loading，用户才知道"正在查"。

## 把数据归一化再交给渲染

接口返回字段往往很啰嗦，渲染前先整理成自己想要的形状：

```javascript
function normalize(raw) {
  const cur = raw.current;
  return {
    temp: Math.round(cur.temperature_2m),
    humidity: cur.relative_humidity_2m,
    windSpeed: cur.wind_speed_10m,
    updatedAt: Date.now()
  };
}
```

分离**数据获取**和**数据整形**。这样即使接口字段改了，只改 `normalize`，渲染代码完全不用动。

翻车现场二：忘记处理接口里的 null 字段。

```javascript
// ❌ 接口没返回湿度，下一行直接抛 TypeError
const humidity = data.current.relative_humidity_2m;   // undefined
document.querySelector('#wHumidity').textContent = humidity + '%';

// ✅ 给默认值
const humidity = data.current.relative_humidity_2m ?? '--';
```

后果：真实接口字段可能缺失或为 null，`undefined + '%'` 得到 `'undefined%'`。用 `??` 给默认值，或者用可选链 `data.current?.relative_humidity_2m`。

## 汇率接口同理

```javascript
async function getRate(base, target) {
  const url = `https://open.er-api.com/v6/latest/${base}`;
  const res = await fetch(url);
  if (!res.ok) throw new Error('汇率请求失败');
  const data = await res.json();
  return data.rates[target];
}
```

调用时同样套一层 try/catch，显示 loading、成功、错误三种状态。

## 小结

- `fetch` 要两次 await：一次拿 `Response`，一次 `.json()` 拿数据。
- `fetch` 遇 HTTP 错误**不**自动 reject，必须检查 `res.ok`。
- 状态顺序固定：`loading → try{成功} catch{失败}`。
- 渲染前先 `normalize` 整形，隔离接口变化。
- 接口字段可能缺失，用 `??` 或可选链给默认值。
