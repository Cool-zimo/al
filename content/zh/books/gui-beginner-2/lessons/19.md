# 画图形与加载图片：Surface、blit、坐标系

> 上一节用 pygame.draw 画基本图形。这一节深入"Surface"这个概念，学会加载图片、把图片贴到画面上（blit），以及 pygame 的坐标系。

## Surface 是什么

**Surface 就是"一块像素画布"**——本质是个二维像素数组。你创建的任何窗口、加载的任何图片，都是 Surface。

```
screen = pygame.display.set_mode((800, 600))
# screen 就是一个 800x600 的 Surface
```

**Surface 上的操作**：可以在上面画（`pygame.draw`）、往上面贴别的 Surface（`blit`）、填色（`fill`）。

**关键概念：所有绘制都是"画在某个 Surface 上"**。画到 screen 上最终会显示；画到别的 Surface（比如一张图片、一个离屏缓存）上则只是修改那块像素。

## blit：把一个 Surface 贴到另一个上

**`dest.blit(source, (x, y))` 把 source 贴到 dest 的 (x, y) 位置。**

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((800, 600))

# 创建一个 100x100 的红色 Surface
red_surface = pygame.Surface((100, 100))
red_surface.fill((255, 0, 0))

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    screen.fill((0, 0, 0))
    screen.blit(red_surface, (200, 150))   # 贴在 (200, 150)
    pygame.display.flip()

pygame.quit()
```

**`blit` 的名字来自"bit block transfer"（位块传输）**，就是"把一块像素搬过去"。这是 2D 游戏最核心的操作——把精灵、背景、UI 都 blit 到 screen 上。

## 加载图片

**`pygame.image.load(路径)` 加载图片，返回一个 Surface：**

```python
player_img = pygame.image.load("player.png").convert_alpha()
screen.blit(player_img, (300, 200))
```

**两个重要方法：**

| 方法 | 作用 |
|---|---|
| `convert()` | 转成与屏幕一致的像素格式，**加快 blit 速度** |
| `convert_alpha()` | 转格式**并保留透明通道**（PNG 透明图用这个） |

**规则**：普通不透明图用 `convert()`；带透明（如 PNG 带 alpha 通道）用 `convert_alpha()`。都转换后再 blit 会更快。

## 翻车现场一：图片路径错或文件不存在

```
img = pygame.image.load("nonexistent.png")
```

**症状**：`pygame.error: Couldn't open nonexistent.png`。

**解决**：用绝对路径或确认相对路径。相对路径相对于**程序运行时的当前目录**。常见技巧：

```python
import os
base_path = os.path.dirname(__file__)          # 当前 .py 所在目录
img_path = os.path.join(base_path, "player.png")
img = pygame.image.load(img_path).convert_alpha()
```

**`os.path.dirname(__file__)` 拿到脚本所在目录**，再 join 上文件名，这样无论在哪运行都能找到图片。

## 翻车现场二：忘了 convert，blit 巨慢

```
img = pygame.image.load("big.png")   # 没 convert
```

**症状**：画面帧率明显下降，尤其贴大图或大量图片时。

**原因**：`image.load` 返回的 Surface 像素格式可能和屏幕不一致，每次 blit 都要实时转换。`.convert()` 提前转好，之后 blit 就快了。

**这是 pygame 性能优化的基本功**。加载图片后立刻 convert。

## 翻车现场三：透明图边缘是黑的

```
img = pygame.image.load("player.png").convert()   # 应该用 convert_alpha
```

**症状**：PNG 的透明部分变成了黑色块。

**原因**：`convert()` 会**丢掉 alpha 通道**。透明 PNG 必须用 `convert_alpha()`。

## 缩放图片

**`pygame.transform.scale(surface, (新宽, 新高))` 缩放：**

```python
big_img = pygame.image.load("player.png").convert_alpha()
small_img = pygame.transform.scale(big_img, (50, 50))
```

**`scale` 返回一个新的 Surface**，原图不变。缩放是**有损**的，反复缩放会模糊，建议一次性算好目标尺寸。

**`pygame.transform` 还有**：`rotate(surface, 角度)`、`flip(surface, x, y)`（镜像）、`scale2x`（放大 2 倍，较快）。

## 翻转与旋转

```python
flipped = pygame.transform.flip(img, True, False)   # 水平翻转
rotated = pygame.transform.rotate(img, 45)          # 逆时针 45 度
```

**`flip(surface, xbool, ybool)`**：两个布尔表示是否水平/垂直翻转。做"面向左右"的角色动画时常用水平翻转。

## Rect：位置和尺寸的统一表示

**pygame 里常用 `pygame.Rect(x, y, 宽, 高)` 表示"一个矩形区域"。** Rect 对象有很多实用属性：

```python
rect = pygame.Rect(100, 50, 80, 60)
rect.x        # 100
rect.y        # 50
rect.width    # 80
rect.height   # 60
rect.center   # (140, 80) 中心点
rect.centerx  # 140
rect.bottom   # 110
```

**Rect 是 pygame 碰撞检测的基础**（第 23 课），也是"图片位置+尺寸"的标准容器。

## 用 Rect 管理图片位置

**把图片和它自己的 Rect 绑在一起管理：**

```python
player_img = pygame.image.load("player.png").convert_alpha()
player_rect = player_img.get_rect()
player_rect.topleft = (300, 200)

# 移动
player_rect.x += 5

# blit 用 rect
screen.blit(player_img, player_rect)
```

**`surface.get_rect()` 返回一个和图片尺寸一样的 Rect**，初始位置在 (0,0)。然后设 `topleft`、`center` 等定位。

**用 Rect 管理位置的好处**：blit 时直接传 Rect（pygame 会取它的左上角），碰撞、边界判断都能用 Rect 的方法。

## 小结

- Surface = 像素画布；窗口、图片都是 Surface
- `dest.blit(source, (x, y))` 把 source 贴到 dest
- `image.load(path).convert()` 加速；透明图用 `convert_alpha()`
- 加载图片后务必 convert；透明图用 convert_alpha
- `transform.scale/rotate/flip` 缩放旋转
- Rect 统一管理位置和尺寸，是碰撞检测的基础
- 路径用 `os.path.dirname(__file__)` 定位更稳
