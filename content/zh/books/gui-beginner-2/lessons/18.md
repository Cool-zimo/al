# 游戏循环的三件事：处理事件、更新状态、重绘

> 上一节搭了最小窗口。这一节把游戏循环拆成"三件事"，并用它做一个能在屏幕上移动的小方块——理解这套结构，后面所有游戏都长这样。

## 游戏循环的标准结构

**每帧依次做三件事：**

```python
while running:
    # ① 处理输入（事件）
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # ② 更新状态（移动、物理、AI）
    player_x += speed

    # ③ 渲染（清空 + 画 + 翻屏）
    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, 200, 50, 50))
    pygame.display.flip()
```

**这三步的顺序很重要**：先响应用户，再算新的状态，最后把新状态画出来。

**为什么是这个顺序？** 因为你希望"这一帧的渲染反映的是这一帧最新的状态"。如果先渲染再更新，画面就会"慢一帧"，肉眼能感觉到延迟。

## 第一步：画一个方块

**`pygame.draw.rect(surface, color, rect)` 画矩形。** rect 可以用元组 `(x, y, 宽, 高)`：

```python
import pygame

pygame.init()
WIDTH, HEIGHT = 800, 600
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("移动方块")

BLACK = (0, 0, 0)
RED = (255, 0, 0)

player_x = 375
player_y = 275

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()

pygame.quit()
```

**运行：一个红色方块在黑色背景上。**

## 第二步：让它动起来

**在"更新状态"阶段改坐标：**

```python
player_x = 375
speed = 4

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player_x += speed                 # 更新状态：每帧 +4

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**运行：方块从左边匀速飞向右边，出画后继续飞（只是看不见了）。**

## 第三步：边界反弹

**用状态变量 + 判断做反弹：**

```python
player_x = 375
speed = 4

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player_x += speed
    if player_x <= 0 or player_x >= WIDTH - 50:
        speed = -speed                # 反弹

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**这里 `WIDTH - 50` 是右边界**：方块宽 50，右边缘到达窗口右边界时反弹。

## 翻车现场一：忘了 fill，画面全是残影

```
while running:
    for event in pygame.event.get():
        ...
    # screen.fill(BLACK)  忘记填充
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**症状**：方块移动过的地方留下一长串拖尾，画面糊成一片。

**原因**：`flip` 只是把后台缓冲翻上来，而你在上面又画了新方块。旧方块没被清掉，就叠在一起了。

**修复**：每帧开头用 `screen.fill(背景色)` 清空。

## 翻车现场二：边界判断用错了右边界

```
if player_x >= WIDTH:       # 方块宽 50，player_x 是左上角
    speed = -speed
```

**症状**：方块已经"飞出"画面一大截才反弹，看起来像穿墙了。

**原因**：`player_x` 是方块**左上角**坐标。方块右边缘是 `player_x + 50`，所以右边界判断要用 `player_x >= WIDTH - 50`。

**在 pygame 里坐标几乎都指"左上角"**，计算边界时务必算上物体尺寸。

## 翻车现场三：更新和渲染顺序颠倒导致"一帧延迟"

```
screen.fill(BLACK)
pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
pygame.display.flip()

player_x += speed      # 先渲染后更新
```

**症状**：操作响应感觉"慢半拍"，方块像在拖。

**原因**：这一帧画的是"上一帧的位置"，下一帧才画新位置。虽然差异微小，但在快节奏游戏里明显。

**牢记顺序：事件 → 更新 → 渲染。**

## 用 pygame.draw 画各种图形

**pygame.draw 模块提供基本绘图函数：**

| 函数 | 画什么 | 参数 |
|---|---|---|
| `rect(surface, color, rect)` | 矩形 | 面、色、(x,y,w,h) |
| `circle(surface, color, center, radius)` | 圆 | 面、色、中心、半径 |
| `line(surface, color, start, end, width)` | 线段 | 面、色、起点、终点、线宽 |
| `polygon(surface, color, pointlist)` | 多边形 | 面、色、顶点列表 |
| `ellipse(surface, color, rect)` | 椭圆 | 面、色、外接矩形 |

```python
pygame.draw.circle(screen, BLUE, (400, 300), 30)              # 中心 (400,300) 半径 30
pygame.draw.line(screen, GREEN, (0, 0), (800, 600), 3)        # 线宽 3
pygame.draw.polygon(screen, YELLOW, [(400,100),(450,200),(350,200)])  # 三角形
```

## 把状态组织成"玩家"变量组

**当状态多了，用一组变量管理更清晰：**

```python
player = {
    "x": 375,
    "y": 275,
    "size": 50,
    "speed": 4,
    "color": (255, 0, 0),
}

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player["x"] += player["speed"]
    if player["x"] <= 0 or player["x"] >= WIDTH - player["size"]:
        player["speed"] = -player["speed"]

    screen.fill(BLACK)
    pygame.draw.rect(screen, player["color"],
                     (player["x"], player["y"], player["size"], player["size"]))
    pygame.display.flip()
```

**下一步（第 21 课）会把这些状态封装成"类"，结构更规范。**

## 小结

- 游戏循环三步：处理事件 → 更新状态 → 渲染
- 顺序不能乱：事件→更新→渲染，否则会慢一帧
- `pygame.draw.rect` 画矩形，`circle` 画圆，`line` 画线
- 坐标指左上角，右边界用 `WIDTH - 物体宽度`
- 每帧必须 `fill` 清空，否则残影
- 状态多了用字典或类组织
