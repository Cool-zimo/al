# 存档与配置：把最高分存进文件

> 游戏关了再开，分数就没了，这让人没动力玩第二遍。这一节教你怎么把数据（最高分、设置、进度）**写进文件、读出来**，而且读坏文件也不会崩。

## 为什么要用文件存档

**变量的寿命 = 程序运行的寿命。** 程序一关，内存里的 `high_score` 就没了。想"下次打开还是记得上次的成绩"，就得把数据存到硬盘上。

**常见存档需求：**

| 存什么 | 例子 |
|---|---|
| 最高分 | `{"high_score": 8500}` |
| 玩家设置 | `{"volume": 0.6, "fullscreen": false}` |
| 游戏进度 | `{"level": 3, "coins": 12}` |

**存档文件一般放在哪？** 和 `main.py` 同目录、文件名 `save.json` 最省事，跨机器也能跑。

## JSON：存档格式的首选

**JSON 是文本格式，长得几乎和 Python 的字典一模一样。**

```python
import json

data = {"high_score": 8500, "volume": 0.6, "player": "小明"}
text = json.dumps(data)            # 字典 → 字符串
print(text)
```

**存盘三件套：`open` + `json.dump` + 关文件。**

```python
import json

def save(data, path="save.json"):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

**读盘：`json.load` 直接拿到字典。**

```python
def load(path="save.json"):
    with open(path, "r", encoding="utf-8") as f:
        return json.load(f)

data = load()
print(data["high_score"])
```

**`ensure_ascii=False` 很重要**——不加的话中文会变成 `\u5c0f\u660e` 这种乱码转义。`indent=2` 让文件换行缩进，方便你用记事本打开看。

## 存档在游戏里怎么接

**套路：启动时读档（没有文件就用默认值），结束时存盘（或得分刷新时存）。**

```python
import json
import os
import pygame

SAVE_FILE = "save.json"
DEFAULT = {"high_score": 0, "volume": 0.6}

def load_save():
    if not os.path.exists(SAVE_FILE):
        return dict(DEFAULT)                 # 文件不存在 → 用默认
    with open(SAVE_FILE, "r", encoding="utf-8") as f:
        return json.load(f)

def save_score(score):
    data = load_save()
    if score > data["high_score"]:
        data["high_score"] = score
        with open(SAVE_FILE, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)

# 启动
save = load_save()
print("历史最高:", save["high_score"])
```

**把"最高分更新"封装成一个函数**，调用方就不用操心"要不要写文件"了。

## 翻车现场一：文件不存在直接崩

```python
data = json.load(open("save.json"))
```

**症状**：`FileNotFoundError: [Errno 2] No such file or directory: 'save.json'`（第一次运行、删了存档都会遇到）。

**原因**：`open` 一个不存在的文件，`"r"` 模式会直接报错。

**正确写法：先 `os.path.exists` 判断，不存在就返回默认值。**

```python
import os

if os.path.exists("save.json"):
    with open("save.json", "r", encoding="utf-8") as f:
        data = json.load(f)
else:
    data = {"high_score": 0}
```

## 翻车现场二：JSON 里存了 pygame 对象

```python
data = {"player_rect": pygame.Rect(10, 10, 50, 50)}
json.dump(data, f)
```

**症状**：`TypeError: Object of type Rect is not JSON serializable`。

**原因**：JSON 只认几种基础类型——`dict`、`list`、`str`、`int/float`、`bool`、`None`。`pygame.Rect`、函数、日期对象它都不会序列化。

**解法**：**存"数据"，不存"对象"。** 把 Rect 拆成四个数：

```python
data = {
    "player": {"x": 10, "y": 10, "w": 50, "h": 50},
    "high_score": 8500,
}
json.dump(data, f)

# 读出来再拼回 Rect
d = json.load(f)
rect = pygame.Rect(d["player"]["x"], d["player"]["y"],
                   d["player"]["w"], d["player"]["h"])
```

## 翻车现场三：存档文件被改坏了

**玩家用记事本打开 `save.json`，手抖删了个引号——再开游戏：**

```python
json.load(open("save.json"))
```

**症状**：`json.decoder.JSONDecodeError: Expecting ',' delimiter: line 1 column 12 (char 11)`。

**原因**：文件内容不再是合法 JSON。`json.load` 遇到坏数据就抛异常，程序直接崩，玩家体验极差。

**解法**：**用 `try / except` 兜底，读坏了就当没存档。**

```python
def load_save():
    try:
        with open("save.json", "r", encoding="utf-8") as f:
            return json.load(f)
    except (json.JSONDecodeError, FileNotFoundError, OSError):
        return dict(DEFAULT)          # 任何读取失败 → 用默认值
```

**三样一起防**：`JSONDecodeError`（内容坏了）、`FileNotFoundError`（没文件）、`OSError`（权限/磁盘问题）。**游戏里"读不出来就用默认"永远比"崩溃"好。**

## 翻车现场四：写了半截就崩了，存档变空

**你的存盘函数写到一半程序崩溃/被关掉：**

```python
with open("save.json", "w") as f:
    json.dump(huge_data, f)      # 写了一半被强退
```

**症状**：存档文件变成 0 字节或残缺，下次读档全崩。

**原因**：`"w"` 模式先**清空文件**，再写内容。中途打断 = 空文件。

**稳妥写法：先写临时文件，成功再替换原文件。**

```python
import os

def safe_save(data, path="save.json"):
    tmp = path + ".tmp"
    with open(tmp, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    os.replace(tmp, path)        # 写完了才替换，原子操作
```

**要么存完整的临时文件，要么保留旧的存档**——永远不会出现"半截存档"。

## 翻车现场五：同一个文件并发读写

**在游戏里每帧都 `json.dump`：**

```python
while running:
    json.dump({"score": score}, open("save.json", "w"))
```

**症状**：磁盘疯狂读写，游戏卡顿，存档还可能损坏。

**原因**：文件 I/O 很慢，不该进主循环。而且**每次覆盖重写**成本很高。

**原则**：**存档是"低频事件"**——只在"游戏结束、玩家主动保存、过了一个大关卡"时存一次。

## 小结

- 存档用 JSON：`json.dump` 写、`json.load` 读，文件用 `"w"`/`"r"` 模式
- 中文存档记得 `ensure_ascii=False`，否则变 `\u` 转义
- 只存数据（数字、字符串、列表、字典），别存 Rect、Surface 这类对象
- 容错三件套：`os.path.exists` + `try/except` + 安全写盘（先写临时再替换）
- 存档是低频操作：只在关键节点存，别每帧都写
- 读不出来就用默认值——"降级"比崩溃好
