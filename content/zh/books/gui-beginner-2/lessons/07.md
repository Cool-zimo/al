# 让图形动起来：after + move，一个会弹的球

> 上一节学了 `after`，这一节用它做一个完整的动画——一个在画布里弹来弹去的球。核心就是"每帧移动一点 + 碰壁反弹"。

## 动画的本质：帧

**动画 = 在固定时间间隔里，把图形挪一点点，再画出来。** 人眼的视觉暂留会把这些连续画面连成"运动"。

```
第 1 帧: 球在 x=10
第 2 帧: 球在 x=15
第 3 帧: 球在 x=20
...
```

**"帧"就是一次完整的"移动 + 重绘"。** 在 tkinter 里，`move` 已经隐式触发了重绘，所以只要不断 `move`，画面就动起来了。

## 第一步：画一个球

**球就是一个圆（椭圆），我们先让它出现在画布上：**

```python
import tkinter as tk

root = tk.Tk()
root.title("弹球")
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

# 球：外接矩形 (30,30)-(70,70)，半径约 20
ball = canvas.create_oval(30, 30, 70, 70, fill="tomato")
```

## 第二步：给它一个速度

**定义一个全局变量 `dx` 表示"每帧在 x 方向移动多少像素"：**

```python
dx = 4   # 每帧向右 4 像素
dy = 3   # 每帧向下 3 像素
```

**用 `coords()` 读取当前位置，判断要不要反弹：**

```python
def animate():
    global dx, dy
    canvas.move(ball, dx, dy)

    # 读取当前坐标
    x1, y1, x2, y2 = canvas.coords(ball)

    # 碰右墙：x2 超过画布宽度
    if x2 >= 400 or x1 <= 0:
        dx = -dx          # 水平反向
    # 碰下墙/上墙
    if y2 >= 300 or y1 <= 0:
        dy = -dy          # 垂直反向

    root.after(20, animate)   # 约 50 帧/秒

animate()
root.mainloop()
```

**反弹的秘诀就是把速度取反**：碰到右墙时 `dx = -dx`，球就改为向左走。

## 完整代码

```python
import tkinter as tk

root = tk.Tk()
root.title("弹球")
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

ball = canvas.create_oval(30, 30, 70, 70, fill="tomato")
dx, dy = 4, 3

def animate():
    global dx, dy
    canvas.move(ball, dx, dy)
    x1, y1, x2, y2 = canvas.coords(ball)

    if x2 >= 400 or x1 <= 0:
        dx = -dx
    if y2 >= 300 or y1 <= 0:
        dy = -dy

    root.after(20, animate)

animate()
root.mainloop()
```

**运行：一个红色小球在窗口里弹来弹去，碰到边缘就反弹。**

## 为什么用 coords 判断边界

**你可能会问：为什么不直接记一个"球的位置变量"，用变量判断边界？**

因为 `move` 之后，球的实际坐标由 Canvas 内部管理。用 `coords()` 读出来永远是最准的。**让"数据源"保持单一**——坐标就是 Canvas 里的坐标，我们只在需要时去读它。

**这样写也天然支持"同时有多个球"**——每个球自己读自己的坐标，互不干扰。

## 翻车现场一：球"卡"在墙外反弹不回来

```
if x2 > 400:
    dx = -dx
```

**症状**：球速度慢时正常，速度大（比如 dx=20）时球飞出画面再也回不来。

**原因**：当 `dx` 很大，`x2` 一下子越过 400 很多（比如到了 430），下一帧 `x2 >= 400` 成立，dx 变负，球往回走。但如果判断条件写得不严谨，或者球已经在墙外很深，需要多帧才能"走回来"，看起来就像卡住了。

**修复**：把边界判断写成"大于等于/小于等于"，容忍球稍微越过边界：

```python
if x2 >= 400 or x1 <= 0:
    dx = -dx
```

## 翻车现场二：用了 while True 做动画

```
while True:
    canvas.move(ball, dx, dy)
    root.update()     # 有人建议用 update 替代 sleep
    time.sleep(0.02)
```

**症状**：能勉强动，但窗口拖动卡顿、按钮点不了、关不掉。

**原因**：`while True` 霸占了事件循环。`root.update()` 只是手动刷一次界面，不是真正的事件循环，很多事件（如窗口缩放、关闭）处理得不完整。**官方推荐始终用 `after`。**

## 翻车现场三：after 时间设得太短或太长

```
root.after(200, animate)   # 5 帧/秒，肉眼可见的跳
root.after(1, animate)     # 太快，CPU 占用拉满
```

**经验值**：`after(16, ...)` 约等于 60 帧/秒，`after(20, ...)` 约 50 帧/秒，`after(33, ...)` 约 30 帧/秒。

**tkinter 的精度有限**，间隔设到 1ms 并不会真的 1ms 一帧，反而让 Python 空转抢 CPU。一般 15~30ms 足够流畅。

## 让球越弹越慢（加摩擦力）

**真实世界里球会减速。给速度乘一个小于 1 的系数就能模拟：**

```python
def animate():
    global dx, dy
    canvas.move(ball, dx, dy)
    x1, y1, x2, y2 = canvas.coords(ball)
    if x2 >= 400 or x1 <= 0:
        dx = -dx * 0.98     # 每次反弹损失 2% 速度
    if y2 >= 300 or y1 <= 0:
        dy = -dy * 0.98
    root.after(20, animate)
```

**`0.98` 就是"恢复系数"**，越接近 1 越弹得久。小于 0 会反向加速（别这么写）。

## 多个球：把逻辑封装成函数

**想同时有多个球，把"一个球"的逻辑写成函数，各自维护自己的 ID 和速度：**

```python
balls = []   # 存 (id, dx, dy)

def make_ball(x, y, color, dx, dy):
    ball = canvas.create_oval(x, y, x+30, y+30, fill=color)
    balls.append([ball, dx, dy])

def animate():
    for ball, dx, dy in balls:
        canvas.move(ball, dx, dy)
        x1, y1, x2, y2 = canvas.coords(ball)
        if x2 >= 400 or x1 <= 0:
            dx = -dx
        if y2 >= 300 or y1 <= 0:
            dy = -dy
    root.after(20, animate)
```

**这里把每个球的 `(id, dx, dy)` 存成列表**，因为速度会变，用可变对象更方便。下一课讲"帧率独立"时会把这种状态管理做得更规范。

## 小结

- 动画 = 每帧移动一点点 + 重绘，用 `after` 驱动
- `move` + `coords` 读坐标 + 判断边界 + 速度取反 = 反弹
- 反弹核心：`dx = -dx`、`dy = -dy`
- 别用 `while True` / `time.sleep`，用 `after` 递归
- after 间隔 15~30ms 通常足够流畅
- 加摩擦力：反弹时 `dx = -dx * 0.98`
