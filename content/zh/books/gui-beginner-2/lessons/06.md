# after() 定时：为什么不能用 while True 做动画

> 想让画面动起来，第一反应往往是"加个循环"。但 GUI 程序里用 `while True` 会直接卡死界面。这一节讲 tkinter 正确的定时机制：`after()`。

## 问题：怎么让图形"自己动"

**需求**：让一个方块每 50 毫秒移动 5 像素，模拟"自动移动"。

直觉写法：

```python
import time

while True:
    canvas.move(rect, 5, 0)
    time.sleep(0.05)
```

**这个写法会彻底卡死程序。** 为什么？因为 tkinter 的事件循环（`mainloop`）被你的 `while` 霸占了，它永远走不到下一步去处理重绘、响应鼠标。

## 为什么 while True 不行

**tkinter 是单线程的事件驱动模型**：`mainloop()` 不停地"取事件 → 处理事件 → 重绘"。你写的代码（回调、脚本主体）都是"借"事件循环的时间片来跑的。

```
mainloop 的内部循环（简化）：
  while 程序还在跑:
      取一个事件（点击/按键/定时）
      调用对应的处理函数
      刷新界面
```

**一旦你在处理函数里写了 `while True`**，事件循环就被堵在这个无限循环里，出不来——无法取下一个事件、无法重绘、无法响应窗口拖动，甚至**连"关闭窗口"的点击都处理不了**（只能靠操作系统强制结束）。

## 正确方案：after()

**`widget.after(毫秒, 函数)` 的意思是："过这么多毫秒后，请调用这个函数。"** 它不是阻塞等待，而是向事件循环"挂号"一个未来的任务，然后立刻返回，让 `mainloop` 继续跑。

```python
import tkinter as tk

root = tk.Tk()
canvas = tk.Canvas(root, width=400, height=200, bg="white")
canvas.pack()

rect = canvas.create_rectangle(10, 50, 60, 100, fill="orange")

def move_step():
    canvas.move(rect, 5, 0)
    # 再挂号下一次
    root.after(50, move_step)

move_step()          # 启动第一次
root.mainloop()
```

**关键点：`move_step` 执行完之前，先挂号下一次 `after`，然后函数返回。** 这样事件循环每次处理完一次移动就空闲下来，能响应其他事件和重绘。

**这就是"递归式定时"**——函数自己安排自己下一次执行，形成持续循环，但每次之间都还给事件循环喘息的机会。

## after 的两个用法

| 用法 | 作用 |
|---|---|
| `after(ms, func)` | 延迟执行函数（func 不带参数） |
| `after(ms)` | 仅等待（返回一个"id"，可配合 `after_cancel`） |

**不带函数的 `after(ms)` 其实很少单独用**，更多是用在"延迟一段时间后做某件事"。

## 翻车现场一：after 的回调带了括号

```
root.after(1000, move_step())   # 立即执行 move_step，而不是 1 秒后
```

**症状**：`move_step()` 立刻执行，返回值（None）被当成"要调用的函数"，1 秒后报错。

**原因**：`after(ms, func)` 要的是函数对象。`move_step()` 带了括号，是"现在就调用"，把返回值传给了 after。

**修复**：去掉括号，传函数本身：

```python
root.after(1000, move_step)
```

**如果回调需要参数，用 lambda**：

```python
root.after(1000, lambda: move_step(5))
```

## 翻车现场二：递归定时忘了再挂号，只动一次

```
def move_step():
    canvas.move(rect, 5, 0)
    # 忘记再 after 了

move_step()
```

**症状**：方块只移动了一次就停住。

**原因**：只挂号了一次。`move_step` 内部必须再写一句 `root.after(50, move_step)`，才能持续循环。这是"递归式定时"的必备结构。

## 翻车现场三：想用 time.sleep 让动画慢一点

```
def move_step():
    canvas.move(rect, 5, 0)
    time.sleep(0.05)          # 错误！会卡界面
    root.after(50, move_step)
```

**症状**：动画一顿一顿，窗口卡顿，甚至无响应。

**原因**：`time.sleep` 是**阻塞式**等待，调用期间整个线程被挂起，事件循环无法工作。GUI 里**严禁**用 `time.sleep` 做动画延时。

**正确做法**：全部用 `after` 安排。"我想 50 毫秒后再做下一步" → `after(50, 下一步)`。

## 用 after 做"延迟一次性任务"

**after 不一定非得循环，也常用于"几秒后自动做某事"：**

```python
def show_tip():
    label.configure(text="操作成功！", fg="green")

def on_click():
    label.configure(text="处理中...", fg="gray")
    root.after(1500, show_tip)   # 1.5 秒后显示成功

tk.Button(root, text="提交", command=on_click).pack()
```

**这就是"伪异步"**：按钮点击后立即给反馈，然后 after 安排后续处理。界面不会卡，用户体验好得多。

## 取消定时：after_cancel

**`after` 返回一个"任务 ID"，可以用 `after_cancel(id)` 取消还没执行的任务：**

```python
job_id = root.after(3000, some_func)

def cancel():
    root.after_cancel(job_id)
```

**常见场景**：倒计时、自动保存、轮播图——需要"重新开始"时先取消旧的定时，再安排新的。

```python
self.timer = None

def start_countdown(self):
    if self.timer:
        root.after_cancel(self.timer)   # 先取消旧的
    self.timer = root.after(1000, self.tick)
```

## 小结

- tkinter 是单线程事件循环，**`while True` 和 `time.sleep` 都会卡死界面**
- `after(ms, func)` 非阻塞地挂号未来任务，让出时间给事件循环
- 持续动画用"递归式定时"：`func` 内部再 `after` 自己
- 回调**不要加括号**传函数对象；带参数用 `lambda`
- `after` 返回 id，可用 `after_cancel` 取消
- 想"慢一点"用 `after` 控制节奏，绝对不用 `time.sleep`
