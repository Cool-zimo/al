# ttk 是什么：为什么原生控件丑，ttk 主题控件

> 到目前为止我们用的都是 tkinter 的"原生控件"（tk.Button、tk.Label），它们长相朴素，Windows、macOS、Linux 上长得还不一样。ttk 是 tkinter 的主题控件库，让界面更美观、更统一。

## 先看看问题：原生控件有多丑

**回顾第一册的代码，我们一直这么写：**

```python
import tkinter as tk

root = tk.Tk()
tk.Button(root, text="确定").pack()
tk.Checkbutton(root, text="同意").pack()
tk.Radiobutton(root, text="选项A").pack()
root.mainloop()
```

**这些控件的样子由操作系统自带的"tk 渲染"决定**：Windows 上是灰扑扑的经典 3D 样式，Linux 上可能更简陋。而且在 Windows 10/11 上，tk 控件往往是"Windows 95 风格"的——圆角、阴影、高 DPI 支持都很弱。

**这就是为什么专业一点的 Python GUI 程序都推荐用 ttk。**

## ttk 是什么

**ttk（Themed Tk）是 tkinter 的一个子模块，提供了一套"主题化"的控件。** 它的控件外观由"主题引擎"绘制，能跟随操作系统的视觉风格（Windows 的 Vista/Win10 主题、macOS 的 Aqua 主题、Linux 的 clam/alt 主题）。

```python
from tkinter import ttk

root = tk.Tk()
ttk.Button(root, text="确定").pack()
ttk.Checkbutton(root, text="同意").pack()
root.mainloop()
```

**注意导入方式**：`from tkinter import ttk`，然后 `ttk.Button`、`ttk.Label` 这样用。

## 原生 vs ttk：对比

| 特性 | 原生 tk | ttk |
|---|---|---|
| 外观 | 老旧、各平台不一 | 主题化、更现代 |
| 高 DPI | 支持差 | 支持较好 |
| 样式定制 | 直接参数（bg、fg） | 用 Style 对象 |
| 跨平台一致性 | 差 | 好 |
| 控件数量 | 基础齐全 | 额外多（Treeview、Notebook 等） |

**一句话**：ttk 的控件"看起来更像是这个时代的软件"。

## ttk 提供的控件

**基础控件 ttk 都有对应，而且多了几个 tk 没有的：**

| 控件 | ttk 写法 |
|---|---|
| 按钮 | `ttk.Button` |
| 标签 | `ttk.Label` |
| 输入框 | `ttk.Entry` |
| 复选框 | `ttk.Checkbutton` |
| 单选框 | `ttk.Radiobutton` |
| 组合框 | `ttk.Combobox`（tk 没有） |
| 进度条 | `ttk.Progressbar`（tk 没有） |
| 表格 | `ttk.Treeview`（tk 没有） |
| 标签页 | `ttk.Notebook`（tk 没有） |

**后面几课会重点讲 Treeview、Notebook、Progressbar，因为它们是 ttk 独有的。**

## 混用：tk 和 ttk 可以一起用

**一个程序里完全可以同时用 tk 和 ttk 控件**：

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()

# tk 的 Canvas（ttk 没有 Canvas）
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

# ttk 的按钮
ttk.Button(root, text="确定").pack()

root.mainloop()
```

**Canvas、Frame、Menu 等"容器/画布类"控件 ttk 没有**，只能用 tk 的。所以实战里常见的模式是：**布局容器用 tk，交互控件用 ttk**。

## 翻车现场一：想给 ttk 控件改颜色用 bg/fg 无效

```
ttk.Button(root, text="确定", bg="red", fg="white").pack()
```

**症状**：`bg`、`fg` 参数被忽略，按钮还是默认主题样式。

**原因**：ttk 控件的外观由主题引擎统一管理，不接受 tk 那种 `bg`/`fg`/`font` 直接参数。要改样式必须用 `ttk.Style()` 对象（下一课讲）。

**这不是 bug，是设计**：ttk 的理念是"外观交给主题，你只管结构"。想精细定制颜色，就用 Style。

## 翻车现场二：导入写错

```
import ttk                     # ModuleNotFoundError
from ttk import Button         # 老式写法，Python 3 已移除
```

**正确写法：**

```python
from tkinter import ttk        # 唯一推荐写法
```

**`ttk` 是 `tkinter` 的子模块**，不是顶层模块。Python 3 之后 `import ttk` 的旧写法已经失效。

## 翻车现场三：ttk 控件尺寸偏小、显得拥挤

**ttk 控件默认 padding 比 tk 小，看起来"挤在一起"。** 解决方法是用 `ttk.Style` 设置 padding，或者用 `pack(padx=5, pady=5)` 加间距。

```python
ttk.Button(root, text="确定").pack(padx=10, pady=5)
```

**布局层面的间距（`padx`/`pady`）tk 和 ttk 都一样，照常使用。**

## 什么时候不该用 ttk

**有几种情况 ttk 反而不方便：**

1. **需要高度自定义外观**（比如做彩色按钮、渐变背景）——ttk 的 Style 系统学起来比直接传 `bg` 麻烦。
2. **Canvas 画图**——ttk 没有 Canvas，必须用 tk。
3. **快速做原型/教学演示**——tk 参数直观，写起来快。

**所以这本书的策略是：前面用 tk 打基础，后面用 ttk 做"正经界面"。**

## 小结

- ttk = Themed Tk，主题化控件库，外观更现代、跨平台更一致
- 导入：`from tkinter import ttk`，用 `ttk.Button` 等
- ttk 独有控件：Combobox、Progressbar、Treeview、Notebook
- Canvas、Frame、Menu 等只能用 tk 的
- ttk 不接受 `bg`/`fg` 直接参数，要用 Style（下一课）
- 实战模式：容器用 tk，交互控件用 ttk
