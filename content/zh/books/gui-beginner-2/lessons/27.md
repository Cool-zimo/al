# 状态管理：用一个变量切换开始、游戏中、结束

> 你写的第一个游戏只有"在玩"这一种状态。但真实的游戏有开始菜单、暂停、结算画面。这一节讲怎么用**一个 `state` 变量**把这些画面串起来。

## 为什么需要状态

**没有状态管理时，代码长这样：**

```python
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    # 这里既画菜单又画游戏又画结束画面
    # 用一堆 if 判断现在该画啥……
```

**问题**：所有逻辑挤在一个循环里，菜单要不要响应点击、游戏里要不要计分、结束画面要不要显示最高分——全靠 `if` 嵌套，很快变成"意大利面"。

**解法**：用一个变量记住"现在在哪个画面"，循环里根据它分流。

## 用字符串当状态

**最简单的方式：`state` 是个字符串，取值 `'menu'` / `'playing'` / `'gameover'`。**

```python
state = 'menu'          # 初始停在菜单

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

        if state == 'menu':
            if event.type == pygame.KEYDOWN and event.key == pygame.K_RETURN:
                state = 'playing'          # 按回车开始

        elif state == 'playing':
            if event.type == pygame.KEYDOWN and event.key == pygame.K_ESCAPE:
                state = 'menu'              # 按 Esc 回菜单

        elif state == 'gameover':
            if event.type == pygame.KEYDOWN and event.key == pygame.K_r:
                state = 'playing'           # 按 R 重开

    screen.fill((0, 0, 0))

    if state == 'menu':
        screen.blit(title_text, (250, 200))
    elif state == 'playing':
        # 游戏逻辑 + 绘制
        pass
    elif state == 'gameover':
        screen.blit(over_text, (250, 200))

    pygame.display.flip()
    clock.tick(60)
```

**这就是状态机的雏形**：`state` 是当前状态，事件改变它，绘制根据它分流。

## 状态切换时要做"清理"

**光改 `state` 往往不够。** 从菜单进入游戏，得重置分数、把玩家放回原位；从游戏进入结束，要记录最终成绩。

**在切换的那一刻做初始化，不要拖到后面：**

```python
if state == 'menu' and key == pygame.K_RETURN:
    score = 0                          # 重置分数
    player.rect.center = (400, 300)    # 重置玩家位置
    state = 'playing'
```

**反例**：把 `score = 0` 写在 `if state == 'playing':` 的每一帧里——那分数永远清零，游戏没法玩。

## 翻车现场一：状态多了以后 if 嵌套失控

```python
if state == 'menu':
    if event.type == pygame.KEYDOWN:
        if event.key == pygame.K_RETURN:
            if score > 100:            # 解锁才让玩
                state = 'playing'
```

**症状**：逻辑越加越多，缩进套到 8 层，改一处崩三处。

**原因**：把"状态判断"和"具体逻辑"混在一起。

**解法**：**每个状态抽成一个函数**，循环里只负责调用。

```python
def handle_menu(event):
    if event.type == pygame.KEYDOWN and event.key == pygame.K_RETURN:
        return 'playing'
    return 'menu'

def handle_playing(event):
    if event.type == pygame.KEYDOWN and event.key == pygame.K_ESCAPE:
        return 'menu'
    return 'playing'

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        state = {
            'menu': handle_menu,
            'playing': handle_playing,
        }[state](event)
```

**这是"查表法"切换**：把状态名映射到处理函数，新增状态只加一个函数和一行字典项。

## 翻车现场二：改了 state 但忘了重绘

```python
if event.key == pygame.K_RETURN:
    state = 'playing'
# 然后什么都没画
```

**症状**：按了回车，画面卡在菜单不动，好像没反应。过一会儿才刷出来。

**原因**：你改了 `state`，但**这一帧的绘制代码还在画菜单**。`flip()` 之后要等下一帧才走新的分支。

**这不是 bug，是帧驱动的正常现象。** 但如果你在切换时**有一步耗时操作**（加载图片、读文件），就会卡住。所以**重资源加载要提前做**，别在切换瞬间做。

## 翻车现场三：事件被"吞掉"或重复处理

```python
for event in pygame.event.get():
    if state == 'menu':
        if event.key == pygame.K_SPACE:
            state = 'playing'
    if state == 'playing':          # 注意：这里还是同一个 event 循环
        if event.key == pygame.K_SPACE:
            fire()                  # 刚进游戏就射了一发！
```

**症状**：按回车进游戏，角色立刻放了个技能、子弹飞出去。

**原因**：同一个事件对象在循环里被多个 `if` 分支检查，`state` 改了之后下面的分支还用**旧事件的属性**判断。

**解法**：用 `elif` 而不是一堆独立的 `if`。

```python
if state == 'menu':
    ...
elif state == 'playing':     # 只会进一个分支
    ...
```

## 翻车现场四：state 写成 typo 但没报错

```python
state = 'playeing'          # 拼错了
# 后面 if state == 'playing': 永远不成立
```

**症状**：什么报错都没有，但游戏怎么按都没反应。

**原因**：字符串比较不报错，拼错只是比较失败。这是"静默错误"。

**对策**：**状态用常量（变量）而不是字面量字符串**，拼错会在引用时报 `NameError`：

```python
MENU = 'menu'
PLAYING = 'playing'
GAMEOVER = 'gameover'

state = MENU
# 后面写 if state == PLAYIGN:  ← 立刻 NameError，马上发现
```

更进一步可以改成整数枚举，比较更快，拼错必报错。

## 小结

- 状态管理 = 一个 `state` 变量 + 事件里改它 + 绘制里分流
- 常见三状态：`menu`（开始）→ `playing`（游戏中）→ `gameover`（结束）
- 切换时要重置数据：分数归零、角色归位、计时器清零
- 状态多了就抽函数 + 查表法，别堆 if 嵌套
- 同一事件用 `elif` 分流，否则会重复触发
- 用常量代替状态字符串，把静默拼写错变成报错

options:
- 事件循环里对 state 用 if / elif 分支分流
- 事件循环里对 state 用一串独立的 if 分支，且分支内部还会根据修改后的 state 再判断

- 用常量保存状态字符串
answer: 1
explain: 同一个事件对象会被后续独立的 if 分支继续检查，state 改了以后旧事件仍可能命中 playing 分支，导致刚进游戏就触发技能/开火。用 elif 分流只进一个分支，就能避免这个问题。抽函数和用常量都是好习惯，不是问题。
