# 帧率与 delta time：为什么固定步长会时快时慢

> 上一节我们用"每帧移动 4 像素"来做动画。但这有个隐患：不同机器、不同负载下帧率不同，动画速度就不一样。这一节引入"delta time"这个概念，让动画在任何机器上都跑得一样快。

## 问题：固定步长的动画不可靠

**回忆第 7 课的弹球：每帧移动 `dx=4` 像素，每 20 毫秒一帧。**

```
速度 = 4 像素/帧 × 50 帧/秒 = 200 像素/秒
```

**这个"200 像素/秒"是算出来的理想值。** 但现实是：

- 你的电脑快，`after(20, ...)` 真能 20ms 一帧 → 速度接近 200
- 电脑卡（开着很多程序），实际 40ms 一帧 → 速度只有 100
- 换一台慢电脑，帧率更低 → 动画更慢

**同样的代码，跑在不同环境里速度不一样。** 这在游戏里是致命的：玩家 A 的球 2 秒到终点，玩家 B 的要 4 秒。

## 核心概念：delta time

**delta time（简称 dt）是"距离上一帧过去了多长时间"。** 单位是秒（或毫秒）。用它来缩放移动量，就能让"移动速度"变成"每秒多少像素"，与帧率无关。

```
这一帧移动量 = 速度 × dt
```

**dt 大（帧间隔长）→ 移动多；dt 小（帧间隔短）→ 移动少。平均速度恒定。**

## 用 time.time 测量 dt

**Python 标准库 `time.time()` 返回当前时间戳（秒）：**

```python
import time

t = time.time()
# 干点别的
time.sleep(0.1)
print(time.time() - t)   # 约 0.1
```

**用它在动画里算 dt：**

```python
import tkinter as tk
import time

root = tk.Tk()
canvas = tk.Canvas(root, width=400, height=200, bg="white")
canvas.pack()

ball = canvas.create_oval(10, 80, 40, 110, fill="tomato")
speed = 200          # 每秒 200 像素
last_time = time.time()

def animate():
    global last_time
    now = time.time()
    dt = now - last_time      # 距离上一帧的秒数
    last_time = now

    canvas.move(ball, speed * dt, 0)

    # 边界反弹
    x1, y1, x2, y2 = canvas.coords(ball)
    if x2 >= 400 or x1 <= 0:
        # 注意：这里要让球留在边界内
        pass

    root.after(16, animate)

animate()
root.mainloop()
```

**关键改动**：`canvas.move(ball, speed * dt, 0)`。当 dt 是 0.02 秒（20ms 一帧），移动 `200 * 0.02 = 4` 像素，和之前一样；若帧率掉到 40ms，dt=0.04，移动 8 像素——一次补回来，平均速度不变。

## 翻车现场一：第一帧 dt 巨大

```
last_time = time.time()   # 程序启动时记录
animate()                 # 第一帧：now - last_time 可能是几秒！
```

**症状**：第一帧球"瞬移"一大段，甚至飞出画布。

**原因**：从 `last_time = time.time()` 到第一次 `animate()` 执行，中间可能隔了很久（加载资源、创建窗口）。dt 算出来几秒，乘上速度就飞了。

**修复：在第一次 animate 里重新采样 last_time，dt 当作 0：**

```python
def animate():
    global last_time
    now = time.time()
    dt = now - last_time
    last_time = now
    if dt > 0.1:        # 帧间隔异常大（卡顿/首帧），当作 0
        dt = 0
    canvas.move(ball, speed * dt, 0)
    root.after(16, animate)
```

**这就是"clamp dt"**——给 dt 设上限，避免一次补太多。

## 翻车现场二：坐标精度丢失（整数 vs 浮点）

```
speed = 200
dt = 0.016          # 60 帧
move_x = speed * dt  # 3.2
canvas.move(ball, move_x, 0)
```

**`move` 的参数是浮点数时，tkinter 会取整（内部存的是浮点，但显示取整）。** 长期累积，微小的亚像素运动会丢失。

**对策**：自己维护球的"精确浮点位置"，用 `coords` 绝对定位，而不是累加 `move`：

```python
ball_x = 10.0      # 精确位置
ball_y = 80.0

def animate():
    global ball_x, ball_y, last_time
    now = time.time()
    dt = now - last_time
    last_time = now
    if dt > 0.1:
        dt = 0
    ball_x += speed * dt
    # 反弹
    if ball_x > 370:
        ball_x = 370
        speed = -abs(speed)
    if ball_x < 0:
        ball_x = 0
        speed = abs(speed)
    # 用 coords 绝对定位
    canvas.coords(ball, ball_x, ball_y, ball_x+30, ball_y+30)
    root.after(16, animate)
```

**这是游戏开发的标准做法**：自己存精确状态，每帧用 `coords` 把状态"画"到画布上。`move` 只适合粗粒度的快速动画。

## 翻车现场三：用了 time.sleep 测 dt

```
time.sleep(0.5)
dt = time.time() - last_time   # 确实是 0.5
```

**虽然算出来 dt 是对的，但 `sleep` 会让界面卡住**，本末倒置。GUI 里测 dt 只能用时间戳相减，**驱动节奏依然靠 `after`**。

## 目标帧率的"匀速" vs "固定步长"

**两种主流做法对比：**

| 做法 | 移动量 | 优点 | 缺点 |
|---|---|---|---|
| 固定步长 | 每帧固定 4px | 简单 | 帧率变化则速度变化 |
| delta time | 速度 × dt | 帧率无关、稳定 | 要维护精确位置、防首帧跳变 |

**tkinter 小动画用固定步长通常够用**；一旦你做游戏、需要"同样速度跨设备一致"，就必须用 dt。pygame 部分（第 20 课）的 `Clock.tick` 本质就是帮你算 dt + 限速。

## 用 dt 做"平滑插值"

**dt 还能用来做"缓动"。比如让一个球在 2 秒内匀速从 x=10 移动到 x=300：**

```python
start_x = 10
target_x = 300
duration = 2.0       # 2 秒
elapsed = 0.0

def move():
    global elapsed
    dt = 1/60        # 近似
    elapsed += dt
    if elapsed > duration:
        elapsed = duration
    progress = elapsed / duration     # 0~1
    x = start_x + (target_x - start_x) * progress
    canvas.coords(ball, x, 80, x+30, 110)
    if elapsed < duration:
        root.after(16, move)
```

**`progress` 是"完成百分比"**，`start + (target-start)*progress` 就是线性插值公式。这是做转场动画、进度条填充的基础。

## 小结

- 固定步长动画的速度依赖帧率，跨设备不一致
- **delta time = 当前时间 − 上一帧时间**，让移动量与帧间隔成正比
- 移动量 = 速度 × dt，单位"像素/秒"
- 防首帧跳变：dt 超过阈值（如 0.1）就当作 0
- 追求精度时自己维护浮点坐标，用 `coords` 绝对定位
- tkinter 小动画固定步长够用，游戏必须用 dt
