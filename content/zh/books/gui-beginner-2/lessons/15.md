# Progressbar 与进度反馈：耗时操作不能卡住界面

> 程序在后台做事（下载、计算）时，用户需要一个"进度条"知道还要等多久。这一节学 ttk.Progressbar，以及 tkinter 里"耗时操作不卡界面"的正确做法。

## Progressbar 是什么

**Progressbar 显示一个进度条，有"确定模式"（已知总量）和"不确定模式"（未知要多久，来回滚动）。**

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.title("进度条")

# 确定模式：max 100，当前 0
bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100, value=0)
bar.pack(padx=20, pady=20)

root.mainloop()
```

**参数：**

| 参数 | 含义 |
|---|---|
| `mode` | `"determinate"` 确定进度 / `"indeterminate"` 不确定（滚动条） |
| `maximum` | 最大值（进度 100% 对应的值） |
| `value` | 当前值 |
| `length` | 长度（像素） |
| `orient` | `"horizontal"` 横向 / `"vertical"` 纵向 |

## 更新进度

**用 `bar["value"] = 新值` 或 `bar.step(增量)` 更新：**

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100, value=0)
bar.pack(padx=20, pady=20)

def start():
    bar["value"] = 0
    update_progress()

def update_progress():
    bar["value"] += 10
    if bar["value"] < 100:
        root.after(200, update_progress)
    else:
        bar["value"] = 100

ttk.Button(root, text="开始", command=start).pack()
root.mainloop()
```

**用 `after` 递归模拟"逐步推进"，界面不会卡。**

## 不确定模式（indeterminate）

**不知道要多久时用它，进度条会来回滚动，表示"正在忙"：**

```python
bar = ttk.Progressbar(root, mode="indeterminate", length=300)
bar.pack()

def start():
    bar.start(10)      # 开始滚动，10 是步进速度

def stop():
    bar.stop()         # 停止

ttk.Button(root, text="开始", command=start).pack()
ttk.Button(root, text="停止", command=stop).pack()
```

**`start(interval)` 让条动起来，`stop()` 停下。**

## 翻车现场一：耗时操作直接写在回调里，界面卡死

```
def on_click():
    time.sleep(5)              # 模拟耗时 5 秒
    label.configure(text="完成")

ttk.Button(root, text="开始", command=on_click).pack()
```

**症状**：点击后窗口彻底卡住 5 秒，进度条不动、按钮无响应、甚至"无响应"提示。

**原因**：`on_click` 是在事件循环里同步执行的，它不返回，事件循环就一直等。所有"看起来在跑"的假象都是骗人的。

**tkinter 是单线程的：耗时操作必须"交出去"或"分段做"。**

## 翻车现场二：用线程后直接操作界面报错

**把耗时操作丢到线程里是正确思路，但线程里不能直接改界面：**

```python
import threading

def worker():
    time.sleep(5)
    bar["value"] = 100         # 从非 GUI 线程操作 → 可能崩溃
```

**症状**：`RuntimeError` 或随机崩溃、界面异常。

**原因**：tkinter 不是线程安全的，界面操作必须在主线程的事件循环里做。

**正确做法**：线程里做完活，用 `root.after(0, callback)` 把"更新界面"的任务挂号到主线程：

```python
def worker():
    time.sleep(5)
    root.after(0, lambda: bar.configure(value=100))
```

## 耗时操作的标准模板

**后台线程 + after 回调，是 tkinter 处理耗时任务的标准套路：**

```python
import tkinter as tk
from tkinter import ttk
import threading
import time

root = tk.Tk()
root.title("下载模拟")

bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100)
bar.pack(padx=20, pady=10)
label = ttk.Label(root, text="等待开始")
label.pack()

def do_work():
    for i in range(1, 101):
        time.sleep(0.05)                     # 模拟耗时
        root.after(0, lambda v=i: bar.configure(value=v))
    root.after(0, lambda: label.configure(text="完成！"))

def start():
    label.configure(text="进行中...")
    bar["value"] = 0
    thread = threading.Thread(target=do_work, daemon=True)
    thread.start()

ttk.Button(root, text="开始下载", command=start).pack(pady=10)
root.mainloop()
```

**`daemon=True` 让线程随主线程退出，避免程序关不掉。**

## 用 indeterminate 做"忙状态"

**有些操作没法预估进度（比如联网检查、搜索文件），用 indeterminate：**

```python
def search():
    bar.config(mode="indeterminate")
    bar.start(10)
    def done():
        bar.stop()
        bar.config(mode="determinate", value=100)
        label.configure(text="搜索完成")
    # 假设 3 秒后完成
    root.after(3000, done)
```

## 进度条配文字百分比

**让进度条旁边显示百分比数字：**

```python
progress = tk.IntVar(value=0)
label = ttk.Label(root, text="0%")

def update(v):
    bar["value"] = v
    label.configure(text=f"{v}%")
    if v < 100:
        root.after(100, lambda: update(v+5))

update(0)
```

**`IntVar` 是 tkinter 的变量类（还有 StringVar、DoubleVar、BooleanVar），用于控件和变量双向绑定，后面做 MVC 时会用到。**

## 小结

- Progressbar 两种模式：`determinate` 确定进度、`indeterminate` 滚动忙碌
- 更新用 `bar["value"]=...` 或 `step()`；indeterminate 用 `start()`/`stop()`
- **耗时操作不能在回调里同步执行**，否则界面卡死
- 正确做法：后台线程 + `root.after(0, 更新界面)`
- tkinter 非线程安全，线程里绝不直接操作界面
- `daemon=True` 的线程随主程序退出
