# 常见崩溃与调试：把"卡死"和"黑屏"治明白

> 前面几课讲的都是"怎么写对"。这一节讲"写错了怎么修"——窗口卡死、图片找不到、按键没反应、rect 和 Surface 分不清，这是 pygame 新手的四大崩溃现场。

## 崩溃一：窗口无响应（假死）

**症状**：程序一运行，窗口就"未响应"，鼠标转圈，只能强制结束。

**最可能的原因：忘了处理 `QUIT` 事件，或主循环根本没进。**

```python
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:    # ← 少了这段
            running = False
    # 没 flip、没 tick
```

**更隐蔽的假死：死循环卡在主循环之外。**

```python
while loading:
    pass                 # 死等，事件队列没人消费，窗口必卡死
```

**原因**：Windows/macOS 要求你的程序**定期回来"处理消息"**。pygame 靠 `pygame.event.get()` 消费系统消息。你要是跑了个死循环、或 `time.sleep(10)` 睡大觉，系统就认为"这窗口死了"。

**对策清单：**

1. 主循环里**必须有** `for event in pygame.event.get(): if QUIT: running=False`
2. 不要在循环里写 `while True: pass` 这种死等，改用状态 + 计时器
3. 别用 `time.sleep` 做游戏内延时，用 `pygame.time.get_ticks()` 算时间差
4. 每帧都有 `pygame.display.flip()` 或 `update()`

## 崩溃二：图片路径找不到

**症状**：`pygame.error: Couldn't open player.png`。

```python
img = pygame.image.load("player.png")
```

**原因**：路径是**相对工作目录**的，而"工作目录"不一定是你 `main.py` 所在目录。你在 VS Code 里点了别的文件夹、或用命令行从不同目录启动，路径就对不上。

**对策一：用 `__file__` 拼绝对路径（推荐）。**

```python
import os

base = os.path.dirname(os.path.abspath(__file__))   # main.py 所在目录
path = os.path.join(base, "assets", "player.png")
img = pygame.image.load(path)
```

**`__file__` 是当前这个 `.py` 文件的路径**，`abspath` 转绝对路径，`dirname` 取目录。这样**无论从哪启动都能找到**，因为锚点固定了。

**对策二：加载前先检查存在。**

```python
if not os.path.exists(path):
    print("找不到图片:", path)
    raise SystemExit
```

**对策三：找不到就用占位 Surface 顶上（游戏不崩更友好）。**

```python
def load_image(name):
    path = os.path.join(base, "assets", name)
    if os.path.exists(path):
        return pygame.image.load(path).convert_alpha()
    surf = pygame.Surface((50, 50))
    surf.fill((255, 0, 255))        # 洋红色 = "图片丢了"的明显标记
    return surf
```

## 崩溃三：键盘/鼠标事件"没反应"

**症状**：按了键什么都没发生，但你明明写了判断。

**第一嫌疑：事件类型写错。**

```python
for event in pygame.event.get():
    if event.key == pygame.K_SPACE:        # 错！少了 event.type 判断
        jump()
```

**正确写法：**

```python
for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:          # 先判断"键盘按下"事件
        if event.key == pygame.K_SPACE:
            jump()
```

**第二嫌疑：持续按键不该用事件，该用 `key.get_pressed()`。**

```python
keys = pygame.key.get_pressed()
if keys[pygame.K_LEFT]:
    player.rect.x -= 4          # 按住就持续移动
```

**事件（`KEYDOWN`）是"按下的那一瞬间"触发一次**；`get_pressed()` 是"此刻哪些键正被按着"的快照。想做平滑移动用后者。

**第三嫌疑：主循环没跑到事件处理——死循环在前。**

```python
while heavy_computation():      # 算太久，事件队列堆满
    pass
for event in pygame.event.get():   # 这一行根本没机会执行
    ...
```

## 崩溃四：Surface 和 rect 的关系搞混

**先说清楚两者是啥：**

| 概念 | 是什么 | 典型用法 |
|---|---|---|
| `Surface` | 一块"像素画布"，有尺寸和颜色 | 图片、方块、文字 |
| `Rect` | 一个"位置和尺寸"的矩形描述 | 坐标计算、碰撞、blit 位置 |

**`Surface` 管"长什么样、多大"，`Rect` 管"在哪、多大"。两者分开存，但要配合。**

```python
img = pygame.Surface((60, 60))
img.fill((0, 200, 255))
rect = img.get_rect(center=(400, 300))     # 从 Surface 抠尺寸，再定位置
screen.blit(img, rect)
```

**翻车写法一：把 Surface 当 Rect 用。**

```python
img = pygame.Surface((60, 60))
img.x += 5              # AttributeError: 'pygame.Surface' object has no attribute 'x'
```

**Surface 没有 `x`、`y`、`collidepoint`**。移动它，得移动它对应的 `rect`，再按 rect 重新 blit。

**翻车写法二：rect 移动了，但 blit 还用旧位置。**

```python
rect.x += 5
screen.blit(img, (0, 0))        # 一直贴在左上角
```

**正确：`blit` 用 `rect`，不是硬编码坐标。**

```python
rect.x += 5
screen.blit(img, rect)
```

**翻车写法三：改了 Surface 尺寸忘了同步 rect。**

```python
img = pygame.transform.scale(img, (120, 120))
# rect 还是 (60, 60)，碰撞判断会错
rect = img.get_rect(center=rect.center)      # 重新算 rect，保留中心位置
```

## 翻车现场汇总表

| 现象 | 第一怀疑 | 怎么查 |
|---|---|---|
| 窗口未响应 | 没处理 QUIT / 死循环 | 检查事件循环，加 print 定位卡在哪 |
| 黑屏但没报错 | 没 flip / 没 blit | 确认每帧 `flip()`，确认 blit 了东西 |
| 图片加载报错 | 路径不对 | 用 `__file__` 拼绝对路径 |
| 按键没反应 | 漏写 `event.type` / 逻辑死循环 | 事件里先判断 `KEYDOWN` |
| 移动卡顿 | 用了 `time.sleep` | 改用 `get_ticks` 计时 |
| 碰撞算错 | rect 和 Surface 尺寸不同步 | 缩放后重算 rect |
| 字体中文乱码 | 用了默认字体 | 指定中文字体文件 |

## 调试三板斧

**第一板斧：在可疑处 `print`。**

```python
print("state:", state, "score:", score)
```

**窗口程序里 `print` 输出在终端，不会显示在游戏画面**——这是最朴素的调试手段。定位"为什么这个分支没进"。

**第二板斧：用异常信息反查。**

```
Traceback (most recent call last):
  File "main.py", line 42, in <module>
    player.rect.x += 5
AttributeError: 'NoneType' object has no attribute 'rect'
```

**看最下面一行**——`AttributeError` + `'NoneType'` 告诉你"player 是 None"。往上找：谁把它赋值成了 None？多半是 `find` 没找到、`load` 失败返回了 None。

**第三板斧：把复杂表达式拆开。**

```python
# 看不出哪步错
if player.rect.colliderect(enemies.sprites()[0].rect):
    ...

# 拆开，每一步都能 print
enemy_list = enemies.sprites()
print("敌人数量:", len(enemy_list))
enemy = enemy_list[0]
print("enemy.rect:", enemy.rect)
print("撞了:", player.rect.colliderect(enemy.rect))
```

**一行表达式拆成三行，每一行都能插 print，bug 立刻现形。**

## 小结

- 窗口无响应 = 事件队列没人消费：必须有 QUIT 处理 + 每帧 flip/tick，别死循环别 sleep
- 图片找不到 = 路径是相对的：用 `__file__` 拼绝对路径最稳
- 事件没反应 = 漏写 `event.type`，或持续移动该用 `get_pressed()` 而非 KEYDOWN
- Surface 管"长相+尺寸"，Rect 管"位置+尺寸"，blit 用 rect，缩放后要重算 rect
- 调试三板斧：print 插桩、读异常最后一行、复杂表达式拆开逐步查
