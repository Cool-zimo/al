# 注释与文档字符串：注释应该讲 why，不是 what

> 你看到一段注释 `# 把 i 加 1`，下面是 `i += 1`。这段注释说了代码的 what，但任何会读 Python 的人都不需要被告知 `i += 1` 是干什么的。好的注释讲**为什么**，坏的注释讲**是什么**。

## 什么时候该写注释

判断标准：**这行代码的意图是否一眼能看出来？**

```python
# WRONG：讲 what 的注释，纯噪音
# 把 count 加 1
count += 1

# 用 for 循环遍历 users
for user in users:
    process(user)
```

```python
# GOOD：讲 why 的注释，有信息量
# 这里必须先校验再查库：校验能挡住大部分非法请求，
# 避免对每条脏数据都做一次昂贵的数据库查询。
validate(order)
save_order(order)

# 减去 1 是因为月份是 1 基的，但 timedelta 需要 0 基索引
target = now - timedelta(days=date(2024, month - 1, 1).day)
```

**翻车现场：注释和实现不一致**

```python
# WRONG：注释过期了
# 最多重试 3 次
for attempt in range(5):
    try:
        do_request()
        break
    except RequestError:
        continue
```

**后果**：注释说 3 次，代码跑 5 次。看注释的人以为重试 3 次够了，结果在故障演练时发现实际重试 5 次，怀疑是 bug，花了 20 分钟排查——而真相只是注释没更新。这种"撒谎的注释"比没注释更糟，因为它给出错误的信息。

**铁律：改代码时同步改注释。做不到就删掉注释。**

## docstring 规范

文档字符串（docstring）是写在函数/类/模块第一行的字符串，能被 `help()` 和 IDE 读取。

```python
def calculate_discount(user, amount):
    """根据用户的会员等级计算折扣金额。

    黄金会员 8 折，白银会员 9 折，普通用户无折扣。

    Args:
        user: 用户对象，需包含 vip_level 属性
        amount: 原价，单位为元

    Returns:
        折扣后的金额（浮点数）

    Raises:
        ValueError: 当 amount 为负数时
    """
    if amount < 0:
        raise ValueError("金额不能为负")
    if user.vip_level == "gold":
        return amount * 0.8
    elif user.vip_level == "silver":
        return amount * 0.9
    return amount
```

```python
>>> help(calculate_discount)
# 会显示上面的文档字符串
```

规范要点：

- 第一行是**一句话摘要**，说明做什么
- 空一行后写详细描述
- 用 `Args`、`Returns`、`Raises` 说明参数、返回值、异常
- 这不是唯一格式（Google、NumPy、reST 三种风格都常见），团队统一即可

**模块级 docstring** 放在文件最开头：

```python
"""订单处理模块。

负责订单的校验、持久化和通知。对外暴露 process_order。
"""
```

**翻车现场：docstring 写成了注释格式**

```python
# WRONG
def fetch_data(url):
    # 从 url 获取数据
    # 返回解析后的字典
    ...
```

这不算 docstring，是普通注释，`help()` 读不到，IDE 的悬浮提示也没有。写成字符串才叫 docstring：

```python
def fetch_data(url):
    """从 url 获取数据并返回解析后的字典。"""
    ...
```

## 类型注解基础

类型注解不改变运行行为，但能让 IDE 和静态检查器（mypy、pyright）帮你找错。

```python
def greet(name: str) -> str:
    return f"你好，{name}"

def get_user(user_id: int) -> dict | None:
    user = db.find(user_id)
    return user  # dict 或 None
```

`dict | None` 是 Python 3.10+ 的写法，等价于 `Optional[dict]`。

**容器类型要写全**：

```python
from collections.abc import Sequence

def average(values: Sequence[float]) -> float:
    return sum(values) / len(values)
```

用 `Sequence` 而不是 `list`，因为函数只用到"能取下标、有长度"这个能力，元组、`range` 都符合，没必要限定死成 list。

**翻车现场：没写注解，IDE 帮不上忙**

```python
# WRONG
def process(items, threshold):
    result = []
    for item in items:
        if item["score"] > threshold:
            result.append(item)
    return result
```

你传了个 `threshold="high"` 进去，运行到 `item["score"] > "high"` 才报错——**运行时才暴露类型错误**。有注解的话，IDE 在你写代码的瞬间就能标红。

类型注解是"给人和工具看的文档"，不强制运行时检查。想要强制检查需要 `mypy` 或 `pyright`。

## 小结

- 注释讲 why，不讲 what
- 改代码要同步改注释，做不到就删掉
- docstring 用 `"""` 写，help() 和 IDE 能读
- docstring 写 Args / Returns / Raises，团队统一风格
- 类型注解是文档也是给静态检查器的提示
