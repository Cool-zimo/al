# 命名与可读性：名字是代码的用户界面

> 你接手一段代码，看到 `def p(data):` 和 `def process_order_payload(payload):`。前者你得读完整个函数才知道它在干嘛，后者扫一眼就懂。代码读的次数远多于写的次数，名字就是给"未来的你"和同事看的说明书。

## 好名字的标准

好名字有三个标准：**说清它是什么、说清它做什么、说清它的单位**。

```python
# 含糊
d = 30

# 清晰
days_to_keep_log = 30
```

```python
# 含糊
def get(uid):
    ...

# 清晰
def fetch_user_by_id(user_id):
    ...
```

**说清单位**尤其重要。一个 `timeout` 是秒还是毫秒？一个有经验的团队会明确约定：

```python
timeout_sec = 30
retry_interval_ms = 500
file_size_mb = 256
```

看到变量名就知道单位，不用去翻文档，更不用去猜。

## 不要用 l 和 O 单字母命名

小写字母 `l`、大写字母 `O`、大写字母 `I` 在大部分字体里和数字 `1`、`0` 长得几乎一样。

```python
# WRONG：灾难级命名
l = 1
O = 0
I = 1
```

```python
# 报错示例（如果你真写出来了）
l = 10
O = 5
print(l, O, I)
# 输出：10 5 1
# 但你盯着屏幕看，以为是 10 5 1 还是 101 还是别的什么
```

**翻车现场：`l` 和 `1` 混淆导致 bug**

```python
# WRONG
def count_items(l):
    return len(l)

items = [1, 2, 3]
print(count_items(l))  # NameError: name 'l' is not defined
```

**错误输出**：`NameError: name 'l' is not defined`。你以为传的是那个列表，其实你想传 `items`，只是 `l` 看着像 `1`，又像 `items` 的首字母，三天后你自己都分不清。

Python 官方风格指南（PEP 8）明确建议：**永远不要用 `l`、`O`、`I` 作为单字符变量名**。循环变量用 `i`、`j`、`k`；列表用 `lst` 或直接用复数名词 `items`。

## 布尔变量用 is_ 前缀

布尔值的名字应该直接回答"是或不是"。

```python
# 差
enabled = True
valid = False
empty = True

# 好
is_enabled = True
is_valid = False
is_empty = True
can_retry = True     # 能力类用 can_
has_permission = True # 拥有类用 has_
```

```python
# 读起来像自然语言
if is_valid and can_retry:
    process()

# 对比
if valid and retry:
    process()
# retry 是次数还是开关？valid 是函数还是变量？
```

`is_`、`has_`、`can_` 这三个前缀能消除大量歧义。新人读代码不用猜。

## 函数名要体现副作用

纯函数（同样的输入永远同样的输出，不改外部状态）和带副作用的函数（写文件、改数据库、打印、改全局变量）要区分开。

```python
# 纯函数：从名字就能看出只是计算
def calculate_total(items):
    return sum(item.price for item in items)

# 带副作用：名字要体现"做了什么"
def save_order_to_db(order):
    db.insert(order)

def send_notification(user, msg):
    ...

def delete_user(user_id):
    ...
```

**翻车现场：函数名掩盖了副作用**

```python
# WRONG：名字像纯函数，实际改了数据库
def get_or_create_user(name):
    user = db.find(name)
    if user is None:
        user = db.create(name)  # 默默写了数据库
    return user
```

调用方看到 `get_or_create_user`，以为只是查询，可能在一个只读的上下文里调用它——结果触发了写操作。名字应该把副作用喊出来，比如 `find_user_or_insert_default`。

## 名字的长度应该和作用的域成正比

- **循环里的临时变量**：短，作用域就一行
  ```python
  for ch in text:
      count[ch] = count.get(ch, 0) + 1
  ```
- **函数参数**：中等，要在签名里表意
  ```python
  def retry_with_backoff(operation, max_attempts, delay_sec):
      ...
  ```
- **模块级常量、类属性**：要长、要自解释
  ```python
  DEFAULT_CONNECTION_TIMEOUT_SECONDS = 30
  MAX_RETRY_ATTEMPTS = 3
  ```

## 小结

- 好名字说清是什么、做什么、什么单位
- 永远别用 `l`、`O`、`I` 单字母命名
- 布尔值用 `is_`/`has_`/`can_` 前缀，读起来像自然语言
- 带副作用的函数，名字要喊出来
- 名字长度与作用域大小成正比

## 随堂练习

```quiz
type: choice
q: 下面哪个变量名最符合"说清单位"的原则？
options:
- t = 30
- timeout = 30
- timeout_sec = 30
- tm = 30
answer: 2
explain: timeout_sec 直接说清了单位是秒。t 和 tm 完全看不出含义；timeout 只说了是超时，但没说是秒、毫秒还是分钟，别人调用时可能传错量级。
```
