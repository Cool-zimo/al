# pip 之外：uv 与现代工具链

> 你 `pip install` 一个包要等半分钟，装完还要等它的十个依赖慢慢下载。团队里三个人装出来的环境还不一样。现代 Python 工具链解决的就是"慢"和"不一致"这两个痛点，uv 是其中跑得最快的那个。

## 为什么 pip 慢

pip 是 Python 官方的包安装器，稳定可靠，但它慢。慢在两个地方：

1. **依赖解析**：给你一份依赖清单，pip 要找出所有包互相兼容的版本组合。这个求解过程在 Python 里跑，复杂项目要几十秒
2. **安装过程**：下载 wheel、解压、编译（如果没预编译轮子）、拷贝到 site-packages，一个包一个包串行处理

这两个瓶颈都不是 pip 偷懒，而是设计使然。于是社区做了更快的工具。

## uv 为什么快

[uv](https://github.com/astral-sh/uv) 是 Astral 公司（也是 Ruff 的作者）用 Rust 写的 Python 包管理器和项目管理器。它的卖点是速度，官方基准测试里比 pip 快 10~100 倍。

快在哪：

- **依赖解析用 Rust 实现**，同样的求解问题几毫秒搞定，而不是几十秒
- **并行下载和安装**，不像 pip 串行
- **全局包缓存**，不同项目共用同一个缓存目录，装过的包不重复下载
- **自带虚拟环境管理**，不用先 `python -m venv` 再激活

```bash
# 安装 uv（一次）
$ curl -LsSf https://astral.sh/uv/install.sh | sh

# 建项目（同时建环境、建 pyproject.toml）
$ uv init myproject
$ cd myproject

# 加依赖（自动建 .venv、自动写 pyproject.toml）
$ uv add requests pandas

# 跑脚本（自动在 .venv 里执行）
$ uv run main.py
```

注意 `uv add requests` 会自动创建 `.venv`、安装包、并把依赖写进 `pyproject.toml`，三步合成一步。

## 常用命令对照

| 要做的事 | pip + venv | uv |
|---|---|---|
| 建环境 | `python3 -m venv .venv` | `uv venv` |
| 激活 | `source .venv/bin/activate` | `uv venv` 后同样激活，或干脆 `uv run` 跳过激活 |
| 装包 | `pip install requests` | `uv pip install requests` 或 `uv add requests` |
| 装清单 | `pip install -r requirements.txt` | `uv pip install -r requirements.txt` |
| 初始化项目 | 手动建目录和文件 | `uv init` |
| 跑脚本 | 激活后 `python main.py` | `uv run main.py` |
| 加开发依赖 | 手动维护 dev 分组 | `uv add --dev pytest` |
| 锁文件 | `pip-tools compile` | `uv lock`（自动） |

## uv 的取舍

**什么时候该用 uv**：新项目、个人项目、对安装速度敏感、想要一体化工具链。它目前生态最活跃，也是社区公认的方向。

**什么时候不用**：维护老项目，团队还在用 pip + requirements.txt，迁移没有收益；或者 CI 环境受限、没法装 Rust 编译的工具。工具是手段，稳定交付才是目的。

**翻车现场：混用 pip 和 uv 导致环境不一致**

```bash
$ uv venv
$ source .venv/bin/activate
(.venv) $ uv add requests
(.venv) $ pip install pandas
(.venv) $ uv lock
# uv 的锁定文件里只有 requests，因为它只跟踪自己装的
```

**后果**：`uv.lock` 里没有 pandas，同事按 lock 文件重建环境时缺了 pandas。同一个环境被两个工具管，一定会乱。

**规则很简单：一个项目只用一个包管理器**。要么全 pip，要么全 uv，别混。

## pip-tools：中间路线

如果你想要可复现构建，又不想换工具，可以用 `pip-tools`：

```bash
# requirements.in 写直接依赖
$ cat requirements.in
requests>=2.28
pandas>=2.0,<3.0

# compile 生成锁定文件
$ pip-compile requirements.in
# 输出 requirements.txt，含所有间接依赖和精确版本

# sync 严格按锁定文件安装
$ pip-sync requirements.txt
```

`pip-sync` 比 `pip install -r` 更严格：它**会卸载**清单里没有的包，保证环境干净。

## 小结

- pip 慢在依赖解析（Python 求解）和串行安装
- uv 用 Rust 重写这两个环节，速度提升 10~100 倍
- uv 还能管理虚拟环境、项目结构、锁文件，是一体化工具
- 一个项目只用一个包管理器，别混用
- 不想换工具可以用 pip-tools 做可复现构建

type: choice

- 立即把整个项目迁移到 uv，重写所有脚本

answer: 1
explain: 迁移工具没有免费收益。老项目稳定就别动，新项目可以尝试更现代的工具。同一项目混用两个工具会导致依赖跟踪不一致，是明确要避免的。
