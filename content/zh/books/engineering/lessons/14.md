# .gitignore 与不该提交的东西

> `.venv/`、`__pycache__/`、`.env`、`.DS_Store`、几百 MB 的训练模型文件——这些东西进版本库，仓库立刻从"几 MB 的源码"变成"几个 G 的垃圾场"。`.gitignore` 就是那道门。

## 该忽略的：__pycache__、.env、大文件

**`__pycache__/`**：Python 自动生成的字节码缓存。它和具体 Python 版本绑定（3.11 的 `.pyc` 和 3.12 的不兼容），进库毫无意义，还让每次 `git status` 都脏。

**`.env`**：密钥文件。第 5 课讲过，进了 Git 就等于泄露。

**`.DS_Store` / `Thumbs.db`**：macOS / Windows 自动生成的文件夹配置，纯噪音。

**`.vscode/` / `.idea/`**：编辑器个人配置。每个人用的插件、快捷键不同，不该共享。

**大文件**：数据集、模型权重、视频、打包产物。Git 不适合存二进制大文件，会让 clone 越来越慢。

```gitignore
# Python
__pycache__/
*.py[cod]
*$py.class
*.so

# 虚拟环境
.venv/
venv/
env/

# 环境变量 / 密钥
.env
.env.*
!.env.example

# 编辑器 / OS
.vscode/
.idea/
.DS_Store
Thumbs.db

# 构建 / 测试产物
build/
dist/
*.egg-info/
.pytest_cache/
.coverage
htmlcov/

# 日志 / 数据
*.log
data/raw/
models/*.bin
```

注意 `!.env.example` 这一行：以 `!` 开头表示"不忽略"，用来把模板文件提交进去。

## 大文件不该进 Git

**翻车现场：把 500MB 的模型文件 commit 了**

```bash
$ git add models/bert-base.bin
$ git commit -m "add model"
$ git push
# 等了十分钟
remote: fatal: pack exceeds maximum allowed size
```

**错误输出**：远程直接拒绝。就算远程不拒绝，后果也很糟：每个 clone 的人都要下载这 500MB，CI 每次跑都要拉，硬盘被占满。

**正确做法**：大文件放对象存储（S3、OSS、COS），代码里下载；或者用 **Git LFS**（Large File Storage）管理。

```bash
# Git LFS 用法
$ git lfs install
$ git lfs track "*.bin"
$ git lfs track "data/*.csv"
$ git add .gitattributes
$ git add models/bert-base.bin
$ git commit -m "add model via lfs"
```

LFS 把大文件存在单独服务器，Git 仓库里只留一个指针，clone 时按需下载。

## 万一已经提交了密钥怎么办

这是最紧急的场景，**不要只删掉再提交**，因为密钥还在 Git 历史里。

**处理步骤**：

1. **立即轮换密钥**：假设已经泄露，所有相关密钥全部作废换新
2. **从 Git 历史中彻底删除**：用 `git filter-repo`（推荐，比老旧的 `git filter-branch` 快且安全）
   ```bash
   $ pip install git-filter-repo
   $ git filter-repo --path .env --invert-paths
   # 这会重写整个仓库历史，删除所有提交中的 .env
   ```
3. **强推到远程**：`git push --force`。因为历史被重写，必须强推
4. **通知所有协作者**：让他们重新 clone，而不是 pull（他们的本地历史还是旧的）
5. **如果已经推到公开仓库**：即使删除，别人可能已经 fork 或 clone 过。**轮换密钥是唯一可靠的止损手段**

**翻车现场：删了文件再 commit，以为就安全了**

```bash
$ git rm .env
$ git commit -m "remove .env"
$ git push
```

```bash
$ git log --all -- .env
# 历史里还能看到 .env 的所有内容
$ git clone <repo>
$ git checkout <那个老提交>
# .env 还在
```

**后果**：假设泄露。这种做法只让"当前 HEAD"看不到 `.env`，历史里的每个版本都还在。

## .gitignore 不生效的常见原因

**翻车现场：明明写了规则，文件还是被追踪**

```bash
$ echo "__pycache__/" >> .gitignore
$ git status
Untracked files:
  __pycache__/main.cpython-311.pyc
```

**原因**：`.gitignore` 只对**未追踪**的文件生效。如果这个文件**已经被 `git add` 过**（在暂存区或仓库里），规则对它无效。

**解决**：先从仓库里移除（保留磁盘文件）：

```bash
$ git rm --cached -r __pycache__/
$ git commit -m "停止追踪 __pycache__"
```

`--cached` 表示只从 git 索引里删，不动磁盘上的文件。

## 小结

- `.venv/`、`__pycache__/`、`.env`、编辑器配置、OS 文件都要忽略
- `.env.example` 可以提交（模板），但 `.env` 本身不行
- 大文件用对象存储或 Git LFS，别直接塞仓库
- 密钥泄露的处理是**轮换**，不是删除
- `.gitignore` 对已追踪文件无效，要先 `git rm --cached`
