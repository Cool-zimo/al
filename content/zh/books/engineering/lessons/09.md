# 格式化与 lint：把风格争论交给工具

> 团队里张三喜欢单引号，李四喜欢双引号，王五缩进 2 格，你缩进 4 格。每次代码评审 80% 的时间花在"这里该不该加空格"。格式化工具的作用就是：这些争论一次定下来，以后再也不讨论。

## black / ruff / flake8 解决什么问题

三个工具各管一段：

| 工具 | 职责 | 类比 |
|---|---|---|
| **black** | 代码格式化（改你的代码） | 自动排版 |
| **ruff** | 静态检查 + 格式化（更快的替代品） | 排版 + 找毛病 |
| **flake8** | 静态检查（只读，不改代码） | 只找毛病 |

**black** 是"不妥协的格式化器"。它的设计哲学是：几乎不给配置项。你不喜欢的换行方式，它照样给你那么排——正因为没有配置，团队之间不需要争论。

```python
# 格式化前
def long_function(argument_one,argument_two,argument_three,argument_four,argument_five,argument_six):
    return argument_one+ argument_two

x=[1,2,3,]
```

```python
# black 格式化后
def long_function(
    argument_one,
    argument_two,
    argument_three,
    argument_four,
    argument_five,
    argument_six,
):
    return argument_one + argument_two

x = [1, 2, 3]
```

注意：`argument_one+ argument_two` 中间补了空格，参数列表过长自动换行并对齐，列表末尾的逗号被保留（这样 diff 更干净——加元素只动一行）。

**ruff** 是 Rust 写的，目标是替代 flake8 + isort + pyupgrade 等一系列工具，速度比 Python 写的同类快 10~100 倍。它既能格式化（替代 black 的部分能力），也能做 lint 检查。

**flake8** 是老牌检查器，插件生态丰富。它不改代码，只报问题：

```bash
$ flake8 main.py
main.py:12:1: E302 expected 2 blank lines, found 1
main.py:15:80: E501 line too long (92 > 79 characters)
main.py:20:5: F841 local variable 'unused' is assigned but never used
```

`E302`、`E501`、`F841` 是规则编号。每条规则对应一类风格或潜在问题。

## 为什么要在提交前跑

**翻车现场：格式化问题留到代码评审**

```bash
# 张三提了一个 PR
$ git push origin feature/login
```

评审界面上：张三改了 3 行业务逻辑，但因为没跑格式化，diff 里混进了 50 行缩进和换行的变化。李四评审时：要么逐行忽略格式噪音、看不清实际改动；要么顺手提一堆格式意见——而格式本来就不该由人来判断。

**正确做法：提交前自动跑**

用 Git 的 pre-commit 钩子，提交时自动格式化：

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/psf/black
    rev: 24.0.0
    hooks:
      - id: black
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.5.0
    hooks:
      - id: ruff
```

装好 `pre-commit` 后：

```bash
$ pre-commit install     # 安装钩子（一次）
$ git commit -m "feat: 登录"
black....................Passed
ruff.....................Failed
# 提交被拦截，因为 ruff 发现了问题
# 修复后重新 add + commit
```

提交被自动拦截，你在本地就修好了，评审者看到的是干净的 diff。

## 编辑器集成

**翻车现场：手动跑格式化，总忘**

```bash
$ vim main.py
# 改了 20 分钟
$ python main.py
# 能跑
$ git add main.py
# 完全忘了跑 black
```

人靠不住。**让编辑器保存时自动格式化**：

VS Code 里装 `Python` 扩展，设置：

```json
{
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "ms-python.black-formatter"
    }
}
```

保存即格式化，和你没关系了。

PyCharm 自带 `Reformat Code`（快捷键 Ctrl+Alt+L），可以设为保存时自动执行。

**检查器的 IDE 集成**：VS Code 装 `Ruff` 扩展后，保存时实时标红有问题的行，鼠标悬停能看到规则说明。

## 小结

- black 做格式化（改代码），flake8/ruff 做检查（只读）
- ruff 用 Rust 写，更快，能替代多个工具
- pre-commit 钩子让格式化在提交前自动跑，别留给评审
- 编辑器配置保存时自动格式化，消除"忘记跑"的可能
