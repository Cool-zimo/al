# 收官：走一遍完整上线，然后开始你自己的项目

> 三十课走到这里，你已经集齐了把"能跑的脚本"变成"能交付的项目"的全部工具。这一课把它们串成一条真实的发布流水线，给出一份**能真正打勾用的项目健康度自检清单**，并告诉你接下来往哪个方向走。

## 一个真实小工具的上线全流程

我们用一个贯穿全章的项目作例子：**CSV 数据清洗小工具**——读 CSV、清洗、输出 JSON。从空目录到线上运行，完整流程如下。

### 第 1 步：搭环境、管依赖（第 1 章）

```bash
$ uv venv && source .venv/bin/activate
$ uv pip install -r requirements.txt
```

`pyproject.toml` 定元数据、入口、`requires-python`；`.gitignore` 排除 `.env`、`__pycache__`、`.venv`。

### 第 2 步：写可读的代码（第 2 章）

函数单一职责、参数明确、类型注解到位、`black` + `ruff` 格式化与 lint 通过。配置和密钥走环境变量，绝不硬编码。

### 第 3 步：建仓库、写历史（第 3 章）

```bash
$ git init && git add . && git commit -m "feat: 初始化 CSV 清洗工具"
```

分支策略 `main` + `feature/*`，提交信息遵循 Conventional Commits，PR 经过评审再合入。

### 第 4 步：补测试、接 CI（第 4 章）

```bash
$ pytest -v --cov=data_tool
```

测试覆盖关键路径，CI 在每次 push / PR 自动跑测试 + lint。

### 第 5 步：定版本、打包、写文档（第 5 章）

`0.1.0` 起步，写 `CHANGELOG.md`、`README.md`，`pyproject.toml` 声明 `[project.scripts]` 入口。

### 第 6 步：性能测量（第 26 课）

上线前对清洗逻辑跑 `cProfile`，确认瓶颈不在热点外；没有数据支撑不做优化。

### 第 7 步：加日志与可观测（第 27 课）

结构化日志 + request_id（这里是一个批处理任务 ID），敏感字段脱敏。

### 第 8 步：安全扫描与密钥核查（第 28 课）

```bash
$ pip-audit -r requirements.txt
```

确认无高危漏洞、密钥全部走 KMS / 环境变量。

### 第 9 步：部署与运维（第 29 课）

Docker 镜像打 tag，Compose 托管进程，配 `/health` 与 `/ready`，保留上一版本镜像用于回滚。

### 第 10 步：过上线清单（第 29 章清单）

逐条打勾，全绿才发。

**翻车现场：跳步上线**

```text
# WRONG：只做了第 1、2、5 步就发
$ git push && docker build -t myapp . && docker push
$ ssh server "docker compose up -d"
# 上线 5 分钟后：依赖有漏洞告警、日志里出现密码明文、CI 根本没配
```

```text
复盘结论：
漏掉的是第 4 步（测试）、第 7 步（日志脱敏）、第 8 步（安全扫描）
# 流程存在的意义就是防止"凭印象"漏掉环节
```

**教训**：流程不是官僚，是**把依赖记忆变成外部工具**。你记不住的，清单帮你记。

## 项目健康度自检清单（可打勾版）

这是本书最重要的交付物。**把它复制到你项目的根目录，起名叫 `HEALTH.md` 或贴在 README 里**，每次发版前过一遍。全部打勾才健康。

### 环境、依赖与配置

- [ ] 项目有独立的虚拟环境（`venv` / `uv` / `conda`），依赖写进 `requirements.txt` 或 `pyproject.toml` 并锁定版本
- [ ] `requires-python` 明确声明，CI 在目标版本上验证过
- [ ] 配置（端口、超时、开关）通过环境变量或配置文件注入，不在代码里写死
- [ ] `.env`、密钥、token 已写进 `.gitignore`，未提交到版本库
- [ ] `README.md` 写清：项目是干什么的、怎么装、怎么跑、怎么测

### 代码质量

- [ ] 函数和变量命名清晰，能"读代码就知道在做什么"
- [ ] 函数单一职责，参数不超过 4~5 个，无超长函数
- [ ] 有类型注解，复杂逻辑有必要的注释（讲"为什么"而不是"做什么"）
- [ ] `black` / `ruff`（或等价工具）已配置并跑通，无 lint 告警
- [ ] 错误处理得当：不吞异常、不裸 `except:`、错误能定位

### 版本控制

- [ ] 有 `.gitignore`，排除缓存、虚拟环境、构建产物、敏感文件
- [ ] 提交信息清晰、原子化，能看懂每个提交做了什么
- [ ] 有分支策略（如 `main` + `feature/*`），关键改动经过评审
- [ ] 版本号遵循语义化版本（major.minor.patch），`CHANGELOG.md` 记录变更

### 测试与 CI

- [ ] 关键路径有单元测试，用 `pytest` 能一键跑通
- [ ] 测试覆盖常见输入、边界值和异常路径
- [ ] CI 自动跑测试 + lint + 安全扫描，不通过不能合入
- [ ] 测试能在干净环境（容器 / 新机器）里跑通

### 日志、安全与文档

- [ ] 用 `logging` 而非 `print`，有级别、有时间、有上下文
- [ ] 日志结构化（含 `request_id` / 任务 ID），敏感信息已脱敏
- [ ] `pip-audit` 通过，无已知高危依赖漏洞
- [ ] 密钥走环境变量 / KMS，数据库查询参数化（防 SQL 注入），命令调用不用 `shell=True` 拼用户输入
- [ ] `CHANGELOG.md`、`README.md`、运维说明同步更新

### 打包、部署与回滚

- [ ] 打包配置（`pyproject.toml` / `Dockerfile`）正确，能在干净环境构建
- [ ] 镜像 / 包已打版本 tag，每个版本可追溯
- [ ] 进程由 systemd / Compose / K8s 托管，有 `Restart` 策略
- [ ] 有 `/health`（存活）和 `/ready`（就绪）端点，轻量可探
- [ ] 有监控与告警（日志、错误率、延迟、资源）
- [ ] 有回滚方案并演练过，上一个版本产物已保留
- [ ] 上线前逐条过过部署清单（依赖锁定、审计、密钥、测试、CI、日志、健康检查、回滚）

**判读标准**：全部打勾 = 项目健康，可以放心发版；任一"必选项"未勾 = 暂不发布，先补。这条清单不是形式主义，它是你项目的**体检表**。

**翻车现场：清单打了勾但没真检查**

```text
# WRONG：勾是勾了，实际没看
- [x] 密钥不进版本库
# 实际上 .env 一周前被 git add 过，历史里还有
```

```text
安全审计结果：
.git/ 历史中发现 1 处 API_KEY → 立即轮换 + 清理历史
# 勾选不是走过场，要真的去验证
```

**教训**：清单的每一项是**动作**，不是表态。打勾之前要去验证——grep 一遍、跑一遍命令、看一眼输出。

## 这本书带走了什么

三十课下来，你带走的不只是工具用法，而是一套**把工程当工程做**的思维方式：

1. **环境可复现**：任何人在任何机器上都能按同一套步骤跑起来
2. **代码可读、可维护**：命名、函数设计、注解、格式化形成肌肉记忆
3. **变更可追溯**：git 历史清晰，版本号有意义，回滚有依据
4. **质量有自动验证**：测试 + CI + lint 替你守门，不靠人肉
5. **交付物完整**：打包、容器、文档、日志、监控、回滚预案齐备
6. **先测量再动手**：性能、安全、上线都以数据说话，不猜、不赌

**一句话概括**：你学会了把"能跑"变成"可靠"——这就是工程的差别。

## 接下来往哪个方向走

三十课是通用工程能力，下面几条路各有侧重。按你的兴趣挑一条深入，工程基本功在哪条路上都用得上。

### 方向 A：数据分析 / 数据工程

- 深入 `pandas`、`polars`、数据清洗与可视化
- 学 Airflow / Dagster 做数据流水线调度
- 练手项目：搭一个每日抓取 → 清洗 → 入库 → 出报表的自动化管道

### 方向 B：算法 / 机器学习工程

- 深入 `numpy`、`scikit-learn`，再学 `pytorch`
- 学模型训练、评估、服务化（FastAPI + ONNX）
- 练手项目：把一个训练好的模型做成可调用、可监控的推理服务

### 方向 C：桌面应用 / GUI

- 学 `PySide6` / `tkinter` / `Flet` 做桌面界面
- 学打包成可执行文件（`PyInstaller` / `briefcase`）
- 练手项目：做一个带 GUI 的本地工具并打包分发

### 方向 D：标准库深挖

- 系统学 `asyncio`、`concurrent.futures`、`multiprocessing`
- 学 `dataclasses`、`typing`、`functools`、`itertools` 等内建利器
- 练手项目：用标准库实现一个小型 HTTP 服务器或任务队列

### 方向 E：更深入的软件工程

- 学软件架构（分层、依赖注入、领域驱动设计）
- 学分布式系统基础、消息队列、缓存、数据库设计
- 学阅读优秀开源项目源码，理解真实项目的组织方式
- 练手项目：参与一个开源项目，从修文档、改 bug 开始

**无论走哪条路，本书的工程基本功都会跟着你**：虚拟环境、测试、CI、版本号、日志、安全、部署——这些是所有方向共享的底盘。挑一条感兴趣的深入，保持"能跑 → 可靠 → 可交付"的工程习惯，你写的代码会越来越经得起时间和别人的检验。

## 小结

- 从空目录到上线要走过 10 步：环境 → 代码 → 版本控制 → 测试CI → 版本打包 → 性能 → 日志 → 安全 → 部署 → 清单
- 流程的意义是防止凭印象漏环节，把记忆外包给清单
- 「项目健康度自检清单」覆盖环境/代码/版本/测试/日志安全/部署六类，全部打勾才算健康
- 清单的每项是动作，不是表态，打勾前要真的验证
- 三十课带走的是"可复现、可读、可追溯、有自动验证、交付物完整、先测后动"的工程思维
- 下一步可选数据分析、算法、桌面、标准库深挖或更深的软件工程，工程基本功通用
