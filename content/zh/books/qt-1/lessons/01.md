# 装环境与第一个窗口

> tkinter 是 Python 标准库，装好 Python 就能用；PySide6 得自己装，而且启动窗口有个"事件循环"必须显式跑起来。这一课把环境装好、把第一个窗口点出来，重点是那句容易漏的 `app.exec()`。

## 安装 PySide6

**一条命令搞定：**

```
pip install PySide6
```

装完在终端里验一下版本，能正常导入就说明装好了：

```python
import PySide6
print(PySide6.__version__)   # 比如 6.5.2
from PySide6 import QtCore
print(QtCore.qVersion())     # Qt 底层版本，比如 6.5.2
```

**两个版本号要分清**：`PySide6.__version__` 是 Python 绑定包的版本，`QtCore.qVersion()` 是底层 C++ Qt 库的版本，两者通常一致，但有时会差一个补丁号。

**虚拟环境是好习惯。** 给每个项目单独建一个 venv，避免不同项目的 Qt 版本互相打架：

```
python -m venv .venv
source .venv/bin/activate    # Windows 用 .venv\Scripts\activate
pip install PySide6
```

**如果 pip 装得很慢**，换成国内镜像：`pip install PySide6 -i https://pypi.tuna.tsinghua.edu.cn/simple`。安装包大约一百多 MB，包含 Qt 的运行时，耐心等一下。

## 第一个窗口：四步结构

**每个 PySide6 程序都有固定骨架，四步：建应用 → 建窗口 → 显示 → 进入循环。**

```
import sys
from PySide6.QtWidgets import QApplication, QWidget

app = QApplication(sys.argv)        # 第 1 步：应用对象，必须有

window = QWidget()                  # 第 2 步：窗口，QWidget 是最基础的控件
window.setWindowTitle("我的第一个 Qt 窗口")
window.resize(400, 300)             # 宽 400、高 300

window.show()                       # 第 3 步：显示
app.exec()                          # 第 4 步：事件循环，卡在这里等用户操作
```

**`QApplication(sys.argv)` 接收一个字符串列表**，用来接收命令行参数（比如 `-style fusion` 指定主题）。不传会报错，这是 Qt 的规定。

**`QWidget` 是所有界面控件的老祖宗**：按钮、标签、输入框，全都是 QWidget 的子类。用它做窗口，就是最干净的空壳。

**`resize(400, 300)` 设的是窗口客户区大小**，不含标题栏和边框，单位是像素。你也可以用 `setGeometry(100, 100, 400, 300)`，前两个是屏幕坐标（窗口左上角位置），后两个是宽高。

## 翻车现场一：忘了 app.exec()，窗口一闪而过

**这是 tkinter 转过来的人必踩的坑。** tkinter 的 `root.mainloop()` 你不会忘，因为它就是最后一行；但 Qt 的 `app.exec()` 要你自己写，漏了窗口就闪一下就没了。

```
import sys
from PySide6.QtWidgets import QApplication, QWidget

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("闪一下就消失的窗口")
window.show()
# app.exec()   ← 漏了！
print("程序结束")
```

**症状**：窗口在屏幕上闪一下立刻关闭，控制台打印出"程序结束"。

**原因**：`show()` 只是"安排显示"，并没有启动等待事件的循环。程序执行到最后一行直接退出，进程结束，窗口自然被销毁。

**解决**：永远把 `app.exec()` 放在主流程的最后一行。把它当成和 `mainloop()` 等价的东西记，写代码时先把它写好再往里填逻辑。

**补充**：Qt 6 里正确的写法是 `app.exec()`（没有末尾的 `u`）。旧教程里的 `app.exec_()` 是 Qt 5 / PyQt5 时代的写法，在 PySide6 里会报 `AttributeError`。

## 翻车现场二：创建了多个 QApplication

**`QApplication` 在一个进程里只能有一个。** 重复创建会直接崩溃。

```
from PySide6.QtWidgets import QApplication, QWidget
import sys

app1 = QApplication(sys.argv)
app2 = QApplication(sys.argv)    # 报错！
```

**报错信息**：`QApplication: There should be only one application object`。

**原因**：Qt 的底层是单例结构，事件队列、剪贴板、屏幕信息都挂在唯一的 QApplication 上。多建一个它就不知道该听谁的。

**解决**：写一个模块级的函数统一创建，或者在入口处用 `QApplication.instance()` 判断：

```python
app = QApplication.instance() or QApplication(sys.argv)
```

**测试代码和正式程序混跑时也常踩这个坑**：pytest 加载多个测试模块，每个模块都建了一个 app。解决方式是在 conftest.py 里用 fixture 建一次、全部复用。

## 翻车现场三：先 show 后改属性，改动不生效

**`show()` 之后还能改属性，但有些改动需要手动触发刷新。**

```
window = QWidget()
window.resize(400, 300)
window.show()
window.setWindowTitle("改个标题")   # 这行有时不生效
```

**原因**：`show()` 只是发送一个显示请求，Qt 会在事件循环里才真正绘制。你在 `show()` 之后立刻改标题，可能赶不上第一次绘制。

**解决**：**先把所有属性设完，最后再 `show()`**。养成"配置在前、显示在最后"的习惯。如果你确实需要在运行中改标题（比如下载进度），用 `setWindowTitle` 是没问题的，Qt 会自动重绘，上面那个例子只是提醒你顺序很重要。

## 窗口的几个常用设置

**除了标题和大小，还有几个高频设置值得记住：**

```
window.setWindowTitle("记账本")
window.resize(480, 320)
window.setMinimumSize(320, 240)    # 最小尺寸，用户拖不到比这更小
window.setMaximumSize(800, 600)    # 最大尺寸
window.move(200, 100)              # 移动到屏幕坐标
```

**`setFixedSize(400, 300)` 最省心**：用户不能拖拽改变窗口大小，布局不会乱。工具类小窗口（计算器、单位换算）特别适合固定尺寸。

**`window.setWindowIcon(QIcon("icon.png"))` 设图标**，图标文件建议用 32×32 或 64×64 的 PNG。这个留到第 4 课讲资源系统时再展开。

## 小结

- 安装：`pip install PySide6`，建议装进虚拟环境
- 四步骨架：QApplication → QWidget → show() → app.exec()
- `QApplication(sys.argv)` 一个进程只能有一个，漏写会报错
- **漏写 `app.exec()` 窗口一闪而过**，这是 tkinter 转 Qt 的头号翻车点
- `QWidget` 是所有控件的基类，用它做窗口就是最干净的空壳
- 先配置属性、最后再 show()，避免改动不生效
