# 实战：文件批量重命名工具

> 把第 14、15、17、27 课的知识全串起来——多线程、进度条、文件对话框、表格，做一个真正能用的工具。

## 项目目标

**做一个批量重命名工具：选择文件夹 → 预览文件列表 → 设置命名规则 → 多线程执行重命名 → 实时显示进度和日志。**

功能清单：
- 选择文件夹（QFileDialog）
- 预览文件列表（QTableWidget）
- 设置命名模式（前缀 + 序号 / 正则替换 / 日期前缀）
- 多线程执行，不冻界面
- 进度条 + 日志区

## 整体架构

**三个核心类：MainWindow（界面）、RenameWorker（重命名逻辑 + 线程）、RenameConfig（命名规则配置）。**

```
project/
├── main.py              # 入口
├── main_window.py       # 主窗口
├── rename_worker.py     # 重命名 Worker
└── config.py            # 命名规则配置
```

**为什么这样切分：MainWindow 只管界面和信号连接，RenameWorker 只管重命名逻辑，Config 只管规则解析。各司其职，测试和维护都方便。**

## RenameWorker：重命名逻辑

**Worker 的核心：接收文件列表和命名规则，逐个重命名，通过信号报告进度和日志。**

```
from PySide6.QtCore import QObject, Signal, Slot
import os
import time

class RenameWorker(QObject):
    progress = Signal(int)        # 进度 0-100
    log = Signal(str)             # 日志消息
    finished = Signal(int)        # 完成，返回成功数量
    error = Signal(str)           # 错误信息

    def __init__(self, files, pattern):
        super().__init__()
        self.files = files
        self.pattern = pattern    # 命名规则，如 "IMG_{n:03d}"
        self._cancelled = False

    @Slot()
    def run(self):
        total = len(self.files)
        success = 0
        for i, filepath in enumerate(self.files):
            if self._cancelled:
                self.log.emit("已取消")
                break
            try:
                dirname = os.path.dirname(filepath)
                ext = os.path.splitext(filepath)[1]
                new_name = self.pattern.format(n=i + 1) + ext
                new_path = os.path.join(dirname, new_name)
                os.rename(filepath, new_path)
                success += 1
                self.log.emit(f"✓ {os.path.basename(filepath)} → {new_name}")
            except Exception as e:
                self.log.emit(f"✗ {os.path.basename(filepath)}: {e}")
            self.progress.emit(int((i + 1) * 100 / total))
            time.sleep(0.05)  # 模拟耗时，实际重命名很快
        self.finished.emit(success)
```

**注意：`os.rename` 本身是很快的操作（毫秒级），这里的 sleep 只是为了让进度条有时间动画。真实场景中如果是网络文件或大量文件，重命名本身就可能耗时。**

## 文件选择 + 预览

**用 QFileDialog 选文件夹，然后把文件列表加载到 QTableWidget：**

```
def browse(self):
    folder = QFileDialog.getExistingDirectory(self, "选择文件夹")
    if folder:
        self.path_edit.setText(folder)
        self.load_preview(folder)

def load_preview(self, folder):
    files = sorted([
        f for f in os.listdir(folder)
        if os.path.isfile(os.path.join(folder, f))
    ])
    self.table.setRowCount(len(files))
    for i, f in enumerate(files):
        ext = os.path.splitext(f)[1]
        new_name = self.pattern_edit.text().format(n=i + 1) + ext
        self.table.setItem(i, 0, QTableWidgetItem(str(i + 1)))
        self.table.setItem(i, 1, QTableWidgetItem(f))
        new_item = QTableWidgetItem(new_name)
        new_item.setForeground(Qt.gray)
        self.table.setItem(i, 2, new_item)
    self._files = [os.path.join(folder, f) for f in files]
```

**预览表格的第三列显示"新名字"（灰色），让用户在执行前确认命名效果。**

## 启动线程 + 信号连接

**点击"开始"后启动 Worker 线程：**

```
def start_rename(self):
    if not hasattr(self, '_files') or not self._files:
        self.log("请先选择文件夹")
        return

    pattern = self.pattern_edit.text()
    self.thread = QThread()
    self.worker = RenameWorker(self._files, pattern)
    self.worker.moveToThread(self.thread)

    # 信号连接
    self.thread.started.connect(self.worker.run)
    self.worker.progress.connect(self.progress.setValue)
    self.worker.log.connect(self.append_log)
    self.worker.finished.connect(self.on_finished)
    self.worker.finished.connect(self.thread.quit)
    self.worker.finished.connect(self.worker.deleteLater)
    self.thread.finished.connect(self.thread.deleteLater)

    self.thread.start()
    self.start_btn.setEnabled(False)
    self.cancel_btn.setEnabled(True)
    self.append_log("开始重命名...")

def append_log(self, msg):
    self.log_area.append(msg)

def on_finished(self, count):
    self.append_log(f"完成！成功重命名 {count} 个文件")
    self.start_btn.setEnabled(True)
    self.cancel_btn.setEnabled(False)
```

**这里体现了完整的 moveToThread 模式：Worker 无 parent → moveToThread → started 信号触发 run → 进度/日志通过信号桥接回主线程 → 完成后 quit + deleteLater。**

## 翻车现场一：日志太多导致界面卡顿

**症状：几千个文件重命名时，日志区疯狂 append，界面越来越卡，甚至假死。**

```
self.worker.log.connect(self.append_log)
# 每个文件都 emit 一次 → 几千次信号 → 主线程忙于更新 QTextEdit
```

**原因：信号跨线程传递是有开销的。几千个文件 = 几千次跨线程信号 + 几千次 QTextEdit 更新。QTextEdit 的 append 操作本身也有成本。**

**✅ 正确做法：批量发送日志，或者用队列攒够一批再刷新。**

```
# 方案：每 10 条发一次汇总
self._log_buffer = []
def _flush_log(self):
    if self._log_buffer:
        self.log_area.append("\n".join(self._log_buffer))
        self._log_buffer.clear()

# Worker 改为每处理 10 个文件 emit 一次汇总
```

## 翻车现场二：重命名失败没有回滚

**症状：重命名中途失败（比如目标文件名已存在），部分文件改了名、部分没改，文件夹一片混乱。**

```
os.rename(filepath, new_path)  # 如果 new_path 已存在会抛 FileExistsError
```

**✅ 正确做法：先检查目标是否存在，或者用 try-except 跳过并记录，执行完后报告哪些失败了。更完善的方案是先做 dry-run 预览，确认无误再执行。**

```
def run(self):

        self.error.emit(f"以下文件会与已有文件冲突: {conflicts[:5]}...")
        return
```

## 翻车现场三：取消后文件状态不一致

**症状：点了取消，重命名停在了中间——文件夹里一半新名字一半旧名字。**

**这本质上不是 bug 而是设计取舍。** 批量操作中途取消必然导致部分完成。更专业的做法是：
1. 执行前先建一个"操作清单"（所有 old→new 的映射）
2. 执行时先复制清单到内存
3. 取消时只影响尚未执行的项

**对于教学项目，我们简单处理：取消按钮设置 `_cancelled` 标志，当前文件处理完就退出。**

```
def cancel(self):
    if self.worker:
        self.worker._cancelled = True
```

```quiz
type: choice
exam: true
q: 在批量重命名工具中，为什么重命名操作要放在子线程的 Worker 里，而不是在按钮的槽函数里直接执行？
options:
- 因为重命名操作会修改文件，Qt 要求所有文件操作必须在子线程
- 因为 os.rename 只能在子线程调用
- 因为文件数量多时逐个重命名耗时较长，放在主线程会阻塞事件循环导致界面冻结
- 因为子线程执行速度比主线程快
answer: 2
explain: 批量文件操作（即使是 os.rename）在文件数量多时也会累积出可观的耗时，放在主线程会阻塞事件循环。用子线程 + 信号桥接是标准做法。os.rename 本身没有线程限制。
```
