# 为什么选 PySide6

> 学 Qt 要做的第一个决定是选哪个绑定：PySide6 还是 PyQt6。两者的 API 几乎一样，差别在许可证。这一课把这件事讲透，免得你做完项目才发现没法商用。

## 两个绑定，一个 Qt

**Qt 本身是 C++ 写的**，Python 想用它，得有人在中间搭桥。这个"搭桥的人"就是绑定库。市面上最主流的两个是：

| 对比项 | PySide6 | PyQt6 |
|---|---|---|
| 维护方 | Qt 官方（The Qt Company） | Riverbank Computing（第三方） |
| 许可证 | LGPL 3.0 | GPL 3.0 / 商业许可双轨 |
| 最新 Qt 版本跟进 | 最快，官方同步发布 | 稍慢 |
| API 风格 | snake_case（`exec()`） | camelCase（`exec()` 也是 camelCase 但命名习惯不同） |
| 商业项目 | **免费使用**，动态链接即可 | 要么开源代码，要么买商业授权 |
| 文档资源 | 官方文档完善，社区逐年增大 | 历史久，老教程多 |

**它们背后用的是同一套 Qt C++ 库，所以运行效果、性能、控件长相完全一样。** 你写的按钮在两边都是同一个 Qt 按钮，区别只在"你用什么许可证、写什么风格的名字"。

## 许可证：这件事决定你能不能商用

**先说结论：做闭源商业项目，选 PySide6。** 原因在 LGPL 和 GPL 的根本差异。

**GPL（PyQt 的默认许可）是"传染性"的**：只要你用了 GPL 的代码，你的整个项目就必须以 GPL 开源——把源代码公开、允许别人修改再发布。这对公司内部工具、卖给客户的桌面软件来说是致命的：你没法把源码交给客户。

**LGPL（PySide6 的许可）宽松得多**：允许你在闭源项目里使用它，条件是"动态链接"。PySide6 本身是动态链接库（.so / .pyd），你正常 `pip install` 装的就是动态链接，天然满足条件。只要你不修改 PySide6 自己的源码，就不用担心许可证问题。

**打个比方**：GPL 像"用了我的秘方，你的菜谱也得公开"；LGPL 像"用我的锅做菜可以，但别改我的锅"。

**商业许可是什么？** Riverbank 卖的 PyQt 商业授权，本质是"花钱买豁免权"，让你不用 GPL 开源。一个开发席位几百美元，团队用起来成本不低。PySide6 没有这个问题。

## 翻车现场一：项目做完才发现要开源

**这是真实发生的惨剧，尤其在国内外包和小公司里。**

张三接了个单子，给客户做一个内部数据录入工具。他熟悉 PyQt，直接上手写，两个月做完了。客户验收时问："能不能只交付 exe，源码我们自己留着？"

**问题来了**：PyQt 是 GPL 的，客户要闭源商用，张三要么把整个项目源码公开（违反合同），要么回头买 PyQt 商业授权（额外支出），要么整个重写换成 PySide6（再花两个月）。

**解决**：**项目启动时就选 PySide6。** 如果你已经用 PyQt6 写了一半，迁移成本其实很低（见下文），但越早换越省事。

## 命名差异：PySide6 vs PyQt6

**两者的 API 90% 以上相同，剩下的差异主要在命名风格和一个导入细节。**

**1. 模块导入路径不同：**

```
# PySide6
from PySide6.QtWidgets import QApplication, QPushButton
from PySide6.QtCore import Qt, QPoint

# PyQt6
from PyQt6.QtWidgets import QApplication, QPushButton
from PyQt6.QtCore import Qt, QPoint
```

**就只是把 `PySide6` 换成 `PyQt6`，模块名和类名完全一致。** 这是最容易改的地方。

**2. 枚举的写法不同（重点）：**

```
# PySide6：枚举用属性访问，清晰
button.setCheckable(True)
window.setWindowFlags(Qt.WindowType.Dialog)

# PyQt6：早期写法需要加枚举类前缀，且值要 .value
from PyQt6.QtCore import Qt
window.setWindowFlags(Qt.WindowType.Dialog)   # 风格趋同了
```

**PySide6 的枚举可以直接用 `Qt.AlignmentFlag.AlignCenter`**，PyQt6 里有时要写 `Qt.AlignmentFlag.AlignCenter.value`。这是 PySide6 的一个便利点，少写 `.value`。

**3. `exec()` 的写法（前面提过）：**

PySide6 用 `app.exec()`，PyQt6 用 `app.exec()` 也一样（PyQt6 已经统一成没有下划线了）。**只有老版本的 PyQt5 才用 `app.exec_()`**，看到这种写法的教程就是十年前的老古董。

## 翻车现场二：照着 PyQt6 教程写，import 全报错

**症状**：你装的是 PySide6，却搜了一篇 PyQt6 的教程，照着写：

```
from PyQt6.QtWidgets import QApplication   # ModuleNotFoundError
```

**原因**：`PyQt6` 这个包根本没装，你装的是 `PySide6`。

**解决**：全局替换 `PyQt6` → `PySide6`。模块名、类名都不变，通常替换完就能跑。如果教程里出现了 `.value` 后缀或 `exec_()`，删掉它们。

**建议**：学 PySide6 时，搜教程请加上"PySide6"关键词，别搜"PyQt6 教程"。两者的教程数量差异巨大（PyQt 历史久，老教程泛滥），搜错了会走弯路。

## Qt 版本对应关系

**PySide6 对应 Qt 6。** 这不是文字游戏，是有实际影响的：

| PySide 版本 | 对应 Qt | Python 要求 |
|---|---|---|
| PySide2 | Qt 5 | Python 2.7 / 3.x |
| PySide6 | Qt 6 | Python 3.6+（新版要求 3.8+） |

**Qt 6 和 Qt 5 有破坏性更新**：部分模块被移除（如 `QtWebKit`），部分类的位置变了（如 `QRandomGenerator` 从 `QtCore` 来），枚举必须加前缀（`Qt.AlignmentFlag.AlignCenter` 而不是 `Qt.AlignCenter`）。

**如果你在网上搜到 `from PySide2 import ...` 的代码，那是 Qt 5 时代的**。装 PySide6 的话要改导入，还要处理枚举前缀的变化。

## 翻车现场三：枚举没加前缀，报 TypeError

**PySide6 强制要求枚举写全路径，这是 Qt 6 的安全特性。**

```
from PySide6.QtCore import Qt

label = QLabel("居中文本")
label.setAlignment(Qt.AlignCenter)   # 报错！
```

**报错信息**：`TypeError: setAlignment(self, alignment: Qt.AlignmentFlag): argument 1 has unexpected type 'EnumType'`。

**原因**：`Qt.AlignCenter` 在 Qt 6 里必须写成 `Qt.AlignmentFlag.AlignCenter`，`Qt.AlignLeft` 写成 `Qt.AlignmentFlag.AlignLeft`。

**解决**：**写全枚举路径**。常用几个记一下：

```
Qt.AlignmentFlag.AlignCenter
Qt.AlignmentFlag.AlignLeft
Qt.AlignmentFlag.AlignRight
Qt.AlignmentFlag.AlignTop
Qt.AlignmentFlag.AlignBottom
Qt.Orientation.Horizontal
Qt.Orientation.Vertical
Qt.CheckState.Checked
Qt.CheckState.Unchecked
```

**为了少打字，可以导入时用 `from PySide6.QtCore import Qt, Qt as QtCore`**，或者直接在文件顶部 `from PySide6.QtCore import Qt`。写代码时 IDE 的自动补全会帮你把枚举路径补全。

## 什么时候该选 PyQt6

**公平地说，PySide6 不是所有场景下的最优解：**

- **维护老项目**：公司代码库是 PyQt5/PyQt6 的，迁移成本大于收益，继续用 PyQt。
- **依赖某个只有 PyQt 绑定的第三方库**：极少数商业库只提供 PyQt 接口。
- **你就是要开源**：GPL 对你无所谓，PyQt6 和 PySide6 用哪个都行。

**但对一个从零开始学的新项目，尤其可能商用的，PySide6 是更省心的选择。** 官方维护、许可证友好、新特性跟进最快，这就是我们这本书选它的理由。

## 小结

- Qt 的 Python 绑定有两个：PySide6（官方、LGPL）和 PyQt6（第三方、GPL）
- **LGPL 允许闭源商用，GPL 要求开源**——这是选型的核心差别
- 两者 API 90% 相同，迁移只需替换 import 和处理枚举前缀
- PySide6 枚举要写全：`Qt.AlignmentFlag.AlignCenter`
- PySide6 对应 Qt 6，PySide2 对应 Qt 5，别混用
- 搜教程时搜"PySide6"，别搜"PyQt6"，否则 import 全报错
