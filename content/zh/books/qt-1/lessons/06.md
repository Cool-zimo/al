# 为什么不能用 setGeometry 摆控件

> tkinter 里你可以 `btn.place(x=20, y=30)` 手动定坐标，Qt 里也能 `widget.setGeometry(20, 30, 100, 40)`。但这招在真实项目里基本没人用——这一课讲清它的四个毛病，以及布局管理器为什么是正确选择。

## 绝对定位：手动算坐标

**`setGeometry(x, y, w, h)` 给控件定死位置和大小：**

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QLabel

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("绝对定位")
window.resize(400, 300)

title = QLabel("登录", window)
title.setGeometry(20, 20, 100, 30)

name_edit = QLabel("用户名：", window)
name_edit.setGeometry(20, 60, 80, 30)

name_input = QLabel("", window)   # 假装是输入框
name_input.setGeometry(110, 60, 200, 30)

submit = QPushButton("登录", window)
submit.setGeometry(150, 120, 100, 40)

window.show()
app.exec()
```

**四个数字的含义**：`x`（距窗口左边）、`y`（距窗口上边）、`w`（宽）、`h`（高），单位像素。

**这在小demo里看着还行，但一放大项目就崩了。**

## 毛病一：窗口一拉伸，控件留在原地

**绝对定位最大的问题是：控件不会跟着窗口变。**

**用户把窗口从 400×300 拖到 800×600，控件还是挤在左上角那一块**，右边和下边大片空白。而用布局的话，控件会自动重排、自动分配多余空间。

**想想你用过的软件**：浏览器拉伸时地址栏会变长、微信拉伸时聊天记录区会变大。这些都不是写死坐标能做到的。

## 毛病二：控件多了，坐标全靠手算

**五个控件就要算十几个数字，还容易重叠。**

```
btn1.setGeometry(20, 20, 100, 40)
btn2.setGeometry(20, 70, 100, 40)    # 20+40+10 间距=70，手动算
btn3.setGeometry(20, 120, 100, 40)   # 70+40+10=120，又算一次
btn4.setGeometry(140, 20, 100, 40)   # 横向也要算
```

**每改一个控件的大小，后面所有控件的坐标都要重算。** 二十个控件的界面，改一次布局等于重写一遍坐标。

**布局的写法（对比一下）：**

```
layout = QVBoxLayout()
layout.addWidget(btn1)
layout.addWidget(btn2)
layout.addWidget(btn3)
layout.addWidget(btn4)
```

**加控件、删控件、改顺序，改一行就完事**，坐标全自动。

## 毛病三：文字长度一变，布局就乱

**中文、英文、长文本，显示宽度差别巨大。**

```
btn = QPushButton("保存", window)
btn.setGeometry(20, 20, 60, 30)   # "保存"够放

btn2 = QPushButton("保存到云端", window)
btn2.setGeometry(20, 60, 60, 30)  # 宽度还是 60，文字被截断
```

**"保存到云端"五个字在 60 像素里放不下**，按钮上的文字被挤、被省略号代替。布局管理器会根据控件的 `sizeHint()`（推荐大小）自动给足空间。

**国际化更是灾难**：英文 "Save" 很短，德文 "Speichern" 长得多，你不可能为每种语言都算一套坐标。

## 毛病四：不同系统、不同字体，尺寸全变

**同一个程序在 Windows 和 macOS 上，控件大小不一样。**

**原因：**

- 系统默认字体不同（Windows 微软雅黑 vs macOS 苹方），同样字号下汉字宽度不同
- 按钮有原生样式（Windows 的按钮有边框和阴影，macOS 是圆角扁平），占的像素不同
- 屏幕 DPI 不同（普通屏 96 DPI vs 高分屏 192 DPI），像素密度差一倍

**你在一台机器上算好的坐标，换台机器可能就重叠了。** 布局管理器会查询当前系统的字体和样式，自动算出合适的尺寸。

## 翻车现场一：控件没显示出来，原来是被盖住了

**症状**：代码里明明创建了控件，运行后窗口里看不到。

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QPushButton

app = QApplication(sys.argv)
window = QWidget()
window.resize(300, 200)

btn1 = QPushButton("按钮一", window)
btn1.setGeometry(20, 20, 100, 40)

btn2 = QPushButton("按钮二", window)
btn2.setGeometry(30, 25, 100, 40)   # 和 btn1 几乎重叠

window.show()
app.exec()
```

**原因**：btn1 和 btn2 的坐标几乎一样，btn2 后创建，盖在了 btn1 上面。你以为"按钮一"没显示，其实它被盖住了。

**解决**：用布局管理器，或者仔细检查坐标。布局会自动分配不重叠的位置。

## 翻车现场二：窗口太小，控件跑到窗口外面去了

**症状**：控件看不见，但代码没错。

```
btn.setGeometry(350, 250, 100, 40)
window.resize(300, 200)   # 窗口比控件位置还小
```

**原因**：控件的左上角在 (350, 250)，但窗口只有 300×200，控件跑到了窗口可见区域之外。

**解决**：**控件的坐标必须在窗口客户区内。** 用布局管理器就不用操心这个，它会保证控件在窗口内。

## 什么时候可以用绝对定位

**绝对定位并非一无是处，少数场景它反而最合适：**

- **自定义绘制控件**：你自己在 `paintEvent` 里画东西（画布、图表、游戏），需要精确坐标。
- **控件极少且固定**：一个全屏背景图 + 一个居中按钮，用 `resizeEvent` 里动态算。
- **原型快速验证**：先硬摆出来看效果，再换成布局。

**判断标准：如果这个界面需要拉伸、需要适配不同语言、控件超过五个，就用布局。**

## 布局管理器的三种基本布局

**Qt 提供了几个布局类，对应 tkinter 的 pack/grid：**

| 布局类 | 作用 | 对应 tkinter |
|---|---|---|
| QVBoxLayout | 控件竖着排（上下） | pack(side=TOP) |
| QHBoxLayout | 控件横着排（左右） | pack(side=LEFT) |
| QGridLayout | 控件按行列排 | grid(row, column) |
| QFormLayout | 两列表单（标签 + 输入） | LabelFrame + grid |

**布局可以嵌套**：一个横向布局里放两个纵向布局，做出复杂界面。

**最基础的 QVBoxLayout 用法（预告第 7 课）：**

```
layout = QVBoxLayout(window)
layout.addWidget(title_label)
layout.addWidget(name_input)
layout.addWidget(submit_btn)
window.setLayout(layout)
```

**运行效果**：三个控件从上到下排列，窗口拉伸时它们一起拉伸。

## 小结

- `setGeometry(x, y, w, h)` 是绝对定位，手动算坐标
- 四个毛病：拉伸不变、坐标手算、文字变长就乱、跨系统尺寸不一致
- 窗口拉伸时绝对定位的控件留在原地，大片空白
- 控件多了改一处要重算所有坐标，维护成本极高
- 布局管理器自动分配空间、自动适配字体和系统
- 绝对定位只在自定义绘制、控件极少等少数场景使用
- 后续第 7~10 课系统讲 QVBoxLayout / QHBoxLayout / QGridLayout / QFormLayout
