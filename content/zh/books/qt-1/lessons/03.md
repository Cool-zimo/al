# 信号与槽：和 tkinter 的 command 有什么本质区别

> tkinter 里按钮点了就调一个函数（`command=callback`），这是"回调"。Qt 里是"信号与槽"：控件发出信号，你把它连到槽函数上。这不是换个名字，而是思维方式的升级——一个信号可以连多个槽，一个槽也能接多个信号。

## tkinter 的方式：一对一的回调

**先回顾你熟悉的 tkinter。** 按钮点一下，执行一个函数，就这么简单：

```python
import tkinter as tk

def say_hi():
    print("你好")

root = tk.Tk()
btn = tk.Button(root, text="点我", command=say_hi)
btn.pack()
root.mainloop()
```

**`command=say_hi` 是"一对一"的**：一个按钮绑定一个函数，点一下调一次。要传参数怎么办？要么用 `lambda`，要么用 `functools.partial`：

```python
import tkinter as tk
from functools import partial

def greet(name):
    print("你好，" + name)

root = tk.Tk()
btn = tk.Button(root, text="打招呼", command=partial(greet, "张三"))
btn.pack()
root.mainloop()
```

**痛点来了**：如果你想让一个按钮同时干两件事（点完打印日志、又更新界面、又写文件），tkinter 的 `command` 只能绑一个函数。你只能在这个函数里调用其他函数，耦合在一起。

## Qt 的方式：信号与槽，一对多

**Qt 把"发生了一件事"和"这件事该干什么"彻底解耦。** 控件在内部定义了很多"信号"（signal），信号在某个时刻被"发射"（emit），谁连着这个信号谁就被调用。

```
from PySide6.QtWidgets import QApplication, QWidget, QPushButton
import sys

def on_click():
    print("按钮被点了")

app = QApplication(sys.argv)
window = QWidget()
btn = QPushButton("点我", window)

btn.clicked.connect(on_click)   # 信号.connect(槽)

window.show()
app.exec()
```

**三个名词，一次记牢：**

| 名词 | 是什么 | 举例 |
|---|---|---|
| 信号 Signal | 控件发出的"事件通知" | `clicked`（被点击）、`textChanged`（文本改变） |
| 槽 Slot | 收到信号后执行的函数 | 你自己写的 `on_click` |
| connect | 把信号和槽连起来 | `btn.clicked.connect(on_click)` |

**`clicked` 是 QPushButton 的内置信号**，按钮被点击时自动发射。`connect` 是信号的成员方法，接收一个可调用对象（函数、方法、lambda）。

**运行它，点三下按钮，控制台输出：**

```
按钮被点了
按钮被点了
按钮被点了
```

## 信号与槽的本质差异

**这不是"换了个名字"，而是架构上的升级。** 关键在三处：

**1. 一对多：一个信号可以连多个槽。**

```
def log_click():
    print("记录日志：按钮被点击")

def update_ui():
    print("更新界面")

btn.clicked.connect(log_click)
btn.clicked.connect(update_ui)
btn.clicked.connect(lambda: print("第三个动作"))
```

**点一下按钮，三个函数依次执行。** 这在 tkinter 里做不到，你只能写一个函数去调用另外三个。

**2. 多对一：多个信号可以连同一个槽。**

```
def handle_any():
    print("无论是哪个控件触发的，都走这里")

btn1.clicked.connect(handle_any)
btn2.clicked.connect(handle_any)
line_edit.returnPressed.connect(handle_any)
```

**一个槽函数处理多个控件**，靠 `sender()` 方法区分是谁发的信号：

```
def handle_any(self):
    who = self.sender()         # 返回发出信号的那个 QObject
    print("触发者：", who.objectName())
```

**3. 解耦：发送者不需要知道谁在接收。** 按钮只管"我被点了，我发信号"，完全不关心有几个槽、槽里干什么。这种解耦让大型程序的结构清晰得多。

## 翻车现场一：信号连了，但槽函数签名不匹配

**这是最常见的报错，尤其带参数的信号。**

```
from PySide6.QtWidgets import QApplication, QCheckBox
import sys

app = QSide6.QtWidgets.QApplication(sys.argv)   # 手滑写错
```

上面是拼写错误，下面这个是真正的"签名不匹配"：

```
from PySide6.QtWidgets import QCheckBox

cb = QCheckBox("同意条款")

def on_state(s):
    print("状态：", s)

cb.stateChanged.connect(on_state)   # 报错！
```

**报错信息**：`TypeError: on_state() takes 1 positional argument but 2 were given`。

**原因**：`stateChanged` 信号发射时**带一个参数**（一个 `Qt.CheckState` 枚举值），但你的 `on_state` 虽然定义了参数 `s`，实际被传入时可能因为重载机制导致参数数量不匹配。这里更常见的情况是：信号带了参数，你却写了一个不接收参数的槽。

**正确写法**：槽函数的参数个数要和信号带的值的个数一致。

```
def on_state(state):
    if state == Qt.CheckState.Checked.value:
        print("已勾选")
    else:
        print("未勾选")

cb.stateChanged.connect(on_state)
```

**判断信号带几个参数**：查官方文档，或者看 IDE 的提示。`clicked` 不带参数，`clicked[bool]` 重载版本带一个 bool，`textChanged(str)` 带一个字符串。

## 翻车现场二：用 lambda 传参，结果全绑到了最后一个值

**这是 Python 闭包的经典坑，在 Qt 里尤其容易踩。**

```
from PySide6.QtWidgets import QPushButton

buttons = []
for i in range(3):
    btn = QPushButton(f"按钮 {i}")
    btn.clicked.connect(lambda: print(i))   # 全打印 2！
    buttons.append(btn)
```

**症状**：三个按钮点下去，全打印 `2`。

**原因**：lambda 捕获的是变量 `i` 的**引用**，不是值。循环结束时 `i` 等于 2，所以三个 lambda 执行时都读到了 2。

**解决一：用默认参数捕获当时的值：**

```
btn.clicked.connect(lambda checked, i=i: print(i))
```

**`i=i` 把当前循环的值拷贝进 lambda 的默认参数**，每个 lambda 各存一份，互不影响。

**解决二：用 functools.partial：**

```
from functools import partial
btn.clicked.connect(partial(self.on_click, i))
```

**解决三：写个工厂函数：**

```
def make_handler(index):
    return lambda: print(index)

btn.clicked.connect(make_handler(i))
```

**三种写法都行，第一种 `i=i` 最简洁**，但要记得加 `checked` 参数——因为 `clicked` 信号会传一个 bool 值进来，lambda 需要接住它，否则会报参数过多的错误。

## 内置信号一览

**每个控件都有一堆内置信号，常用的记住就够用：**

| 控件 | 常用信号 | 带什么参数 |
|---|---|---|
| QPushButton | `clicked` | 无 / bool（是否 checked） |
| QLineEdit | `textChanged` | str（新文本） |
| QLineEdit | `returnPressed` | 无 |
| QCheckBox / QRadioButton | `stateChanged` | int（CheckState） |
| QComboBox | `currentIndexChanged` | int（新索引） |
| QSlider / QSpinBox | `valueChanged` | int |
| QWidget | `windowTitleChanged` | str |

**`textChanged` 是个好例子，演示信号带参数：**

```
from PySide6.QtWidgets import QLineEdit

edit = QLineEdit()

def on_text(text):
    print("当前输入：", text)

edit.textChanged.connect(on_text)
```

**每敲一个键，`on_text` 就被调用一次**，参数 `text` 是输入框里的完整新文本。这就是"实时响应输入"的实现方式。

## 小结

- tkinter 是回调（`command=fn`），一对一；Qt 是信号与槽，一对多、多对一
- 三个名词：信号（Signal）发出事件、槽（Slot）接收处理、`connect` 连接两者
- `btn.clicked.connect(on_click)` 是最基础的形式
- 一个信号连多个槽：点一次按钮触发多个动作
- 多个信号连一个槽：多个控件共用一个处理函数
- 槽函数参数个数必须和信号带的值的个数一致，否则报 TypeError
- lambda 传参用 `lambda checked, i=i: ...` 捕获当时的值，避免全绑到最后一个
