# QThread 与 Worker 模式

> 把重活扔到子线程，让界面永远流畅。这一课讲 QThread 的正确用法，以及那个最容易踩的雷区。

## QThread 的基本思路

**QThread 是 Qt 提供的线程封装。核心模式是：创建一个 QThread 对象 + 一个 Worker 对象，用 `moveToThread` 把 Worker 挪到子线程，通过信号触发 Worker 干活。**

```
from PySide6.QtCore import QThread, QObject, Signal, Slot

class Worker(QObject):
    finished = Signal()           # 任务完成信号
    progress = Signal(int)        # 进度信号

    @Slot()
    def do_work(self):
        for i in range(100):
            # 模拟耗时
            import time
            time.sleep(0.05)
            self.progress.emit(i + 1)
        self.finished.emit()

# ---- 主线程 ----
worker = Worker()
thread = QThread()

worker.moveToThread(thread)              # 关键：把 worker 移到子线程
thread.started.connect(worker.do_work)   # 线程启动后自动开始干活
worker.finished.connect(thread.quit)     # 干完后退出线程
worker.finished.connect(worker.deleteLater)
thread.finished.connect(thread.deleteLater)

thread.start()  # 启动线程
```

**流程：`thread.start()` → 触发 `started` 信号 → 调用 `worker.do_work()` → do_work 在子线程执行 → 通过 `progress` 信号把进度发回主线程 → 完成 → `quit()` 结束线程。**

## moveToThread 的正确姿势

**三步走：① 创建 QThread ② moveToThread ③ 用信号连接启动逻辑。**

```
# ✅ 正确
worker = Worker()
thread = QThread()
worker.moveToThread(thread)
thread.started.connect(worker.do_work)
thread.start()
```

**要点：Worker 不能有父对象（parent）。** 如果 Worker 构造时传了 parent，`moveToThread` 会失败——Qt 不允许有父对象的 QObject 跨线程移动。

```
# ❌ 错误：Worker 有父对象
worker = Worker(parent=some_widget)
worker.moveToThread(thread)  # 静默失败！moveToThread 什么都不做
```

**Worker 的信号是连接主线程和子线程的桥梁。** 子线程不能直接改 UI，但它可以 emit 信号，信号连接到主线程的槽函数，Qt 会自动做线程间调度。

## 翻车现场一：在子线程里直接改 UI → 崩溃

**症状：程序跑一会儿就崩溃，报错 `Cannot send events to objects owned by a different thread` 或者直接 segmentation fault。**

```
class Worker(QObject):
    def do_work(self):
        for i in range(100):
            time.sleep(0.05)
            progress_bar.setValue(i)   # ❌ 在子线程里直接改 UI 控件！
```

**原因：所有 QWidget 的实例都"属于"主线程。** 子线程直接调用 `setValue` 是非线程安全的，Qt 会检测到并报警告，严重时直接崩溃。这是未定义行为——可能正常工作一千次，然后第 1001 次崩。

**✅ 正确做法：子线程只 emit 信号，让主线程的槽函数来更新 UI。**

```
class Worker(QObject):
    progress = Signal(int)   # 子线程 emit

    def do_work(self):
        for i in range(100):
            time.sleep(0.05)
            self.progress.emit(i)   # ✅ 发信号

# 主线程连接
worker.progress.connect(progress_bar.setValue)  # ✅ 主线程的槽更新 UI
```

**这个模式叫"信号桥接"——子线程不直接碰 UI，只发信号说"我这里有个新数据"，主线程收到后自己改。**

## 翻车现场二：子类化 QThread 但把活写在 run() 外面

**症状：以为用了 QThread 就没问题了，但界面照样卡死。**

```
class MyThread(QThread):
    def __init__(self):
        super().__init__()
        self.heavy_result = None

    def prepare(self):
        # ❌ 这个方法是在主线程调用的！
        result = requests.get("https://slow-api.com")  # 主线程阻塞
        self.heavy_result = result

    def run(self):
        # run() 才在子线程执行
        print("thread running")

thread = MyThread()
thread.prepare()   # 主线程调用 → 阻塞！
thread.start()
```

**原因：`run()` 确实在子线程执行，但 `prepare()` 是在创建线程的那个线程（主线程）里调用的。** 很多人把初始化逻辑写在其他方法里，以为"反正在线程对象里就是在线程里"——错。

**✅ 正确做法：把耗时逻辑放 `run()` 里，或者用 moveToThread 模式（推荐）。**

```
class MyThread(QThread):
    result_ready = Signal(str)

    def run(self):
        # ✅ run() 在子线程执行
        result = requests.get("https://slow-api.com").text
        self.result_ready.emit(result)

thread = MyThread()
thread.result_ready.connect(label.setText)
thread.start()
```

## 翻车现场三：忘记 quit() 和 wait()，关窗口后进程不退出

**症状：点 X 关闭窗口，窗口消失了，但 Python 进程还在后台跑，任务管理器里能看到。**

```
class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        self.thread = QThread()
        self.worker = Worker()
        self.worker.moveToThread(self.thread)
        self.thread.started.connect(self.worker.do_work)
        self.thread.start()

    # ❌ 没有重写 closeEvent
```

**原因：子线程还在运行时，Python 进程不会退出。** 窗口关了只是隐藏了 UI，后台线程还在跑。

**✅ 正确做法：重写 `closeEvent`，确保线程退出并等待。**

```
class MainWindow(QMainWindow):
    def closeEvent(self, event):
        self.thread.quit()       # 请求线程退出事件循环
        self.thread.wait(3000)   # 等待最多 3 秒
        super().closeEvent(event)
```

**`quit()` 是"温柔地请线程退出"，`wait()` 是"阻塞等待它真的退出"。** 两个都要写。

## Worker 模式完整模板

**一个生产级的 Worker 应该包含：开始信号、进度信号、完成信号、错误信号、取消支持。**

```
from PySide6.QtCore import QThread, QObject, Signal, Slot

class Worker(QObject):
    started = Signal()
    progress = Signal(int)
    finished = Signal(object)    # 携带结果
    error = Signal(str)
    cancelled = Signal()

    def __init__(self):
        super().__init__()
        self._is_cancelled = False

    @Slot()
    def do_work(self, param):
        self.started.emit()
        try:
            result = []
            for i in range(100):
                if self._is_cancelled:
                    self.cancelled.emit()
                    return
                time.sleep(0.05)
                result.append(i * param)
                self.progress.emit(i + 1)
            self.finished.emit(result)
        except Exception as e:
            self.error.emit(str(e))

    def cancel(self):
        self._is_cancelled = True


# 主线程组装
worker = Worker()
thread = QThread()
worker.moveToThread(thread)

thread.started.connect(lambda: worker.do_work(42))
worker.progress.connect(progress_bar.setValue)
worker.finished.connect(on_success)
worker.error.connect(on_error)
worker.finished.connect(thread.quit)
worker.finished.connect(worker.deleteLater)
thread.finished.connect(thread.deleteLater)

thread.start()
```

## 小结

- QThread 的正确模式是 moveToThread + 信号驱动，而非子类化 run()
- Worker 不能有 parent，否则 moveToThread 静默失败
- ⚠️ 子线程绝不能碰 UI——直接改控件会崩溃，只能用信号桥接
- 耗时逻辑必须确保在子线程执行，别写在 run() 外面的方法里
- 关闭窗口时务必 quit() + wait()，否则进程残留
- Worker 应有取消机制和错误处理，生产代码必备
