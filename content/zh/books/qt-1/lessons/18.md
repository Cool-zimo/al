# 自定义对话框 QDialog

> 内置对话框只能取一个值，真正的交互界面得自己画。这一课讲怎么写一个 QDialog，以及为什么 exec() 能拿返回值而 show() 不行。

## QDialog 是能自己排版的弹窗

**继承 QDialog，往里塞布局和控件，就是一个自定义对话框。**

```
from PySide6.QtWidgets import QDialog, QFormLayout, QLineEdit, QPushButton, QVBoxLayout

class LoginDialog(QDialog):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setWindowTitle("登录")
        self.resize(250, 150)

        self.user_edit = QLineEdit()
        self.pass_edit = QLineEdit()
        self.pass_edit.setEchoMode(QLineEdit.Password)

        form = QFormLayout()
        form.addRow("用户名：", self.user_edit)
        form.addRow("密码：", self.pass_edit)

        self.ok_btn = QPushButton("确定")
        self.cancel_btn = QPushButton("取消")
        btn_row = QHBoxLayout()
        btn_row.addStretch()
        btn_row.addWidget(self.ok_btn)
        btn_row.addWidget(self.cancel_btn)

        main = QVBoxLayout(self)
        main.addLayout(form)
        main.addLayout(btn_row)

        self.ok_btn.clicked.connect(self.accept)
        self.cancel_btn.clicked.connect(self.reject)
```

**`accept()` 和 `reject()` 是 QDialog 内置的槽函数，分别把对话框状态设为 Accepted 和 Rejected 并关闭。** 连到按钮上就行，不用自己写关闭逻辑。

## exec() 与 show() 的区别

**`exec()` 是模态运行：代码停在这一行，等对话框关掉才往下走，返回值是 Accepted/Rejected。**

```
dlg = LoginDialog(window)
result = dlg.exec()          # 卡住，等用户操作完
if result == QDialog.Accepted:
    print("用户名：", dlg.user_edit.text())
    print("密码：", dlg.pass_edit.text())
```

**`show()` 是非模态运行：对话框弹出来，代码立刻往下走，不等你操作。**

```
dlg = LoginDialog(window)
dlg.show()                   # 立刻返回，下面这行马上执行
print("这行会先打印出来")      # 用户还没来得及输密码
# dlg.user_edit.text() 此时是空的
```

**关键差异：模态靠 exec 阻塞主流程，才能"填完再取"；show 是非阻塞的，你根本不知道用户什么时候填完。**

## 翻车现场一：用 show() 取对话框数据，拿到一堆空值

**症状：弹窗显示出来了，但立刻打印出的用户名、密码都是空的，好像用户什么都没填。**

```
dlg = LoginDialog(window)
dlg.show()                          # ❌ 非阻塞
print(dlg.user_edit.text())          # 空字符串！
print(dlg.pass_edit.text())          # 空字符串！
# 程序已经走到这里，用户还没动键盘
```

**原因：`show()` 只是"发起显示"就返回了，主流程继续往下跑。** 你在第 2 行取值时弹窗刚画出来，输入框当然是空的。

**✅ 正确写法用 exec()：**

```
dlg = LoginDialog(window)
if dlg.exec() == QDialog.Accepted:    # ✅ 阻塞等用户点确定
    username = dlg.user_edit.text()    # 用户已经填完了
    password = dlg.pass_edit.text()
    do_login(username, password)
```

**反过来也有坑：数据校验要在 accept 之前做，不能 exec 之后才发现输入不合法。** 重写 `accept` 方法：

```
def accept(self):
    if not self.user_edit.text().strip():
        QMessageBox.warning(self, "提示", "用户名不能为空")
        return              # 不调用 super().accept()，对话框就不会关
    super().accept()
```

**`return` 掉这次 accept，对话框保持打开，用户能继续改。** 只有校验通过才走 `super().accept()` 真正关闭。

## 翻车现场二：exec() 返回 True/False，用 1/0 判断

**症状：PySide6 里 `exec()` 返回的是枚举 `QDialog.Accepted`（值为 1），直接 `if dlg.exec():` 居然也能用，换成 `if dlg.exec() == 1` 却报错。**

```
if dlg.exec() == 1:      # ❌ 枚举和整数不能这么比
    ...
```

**原因：PySide6 里返回的是 `QDialog.DialogCode` 枚举，值是 1 和 0，但类型是枚举不是 int。** 布尔上下文里它真值正确（Accepted 是真值），所以 `if dlg.exec():` 不会报错，但显式比较必须用枚举。

**✅ 正确写法：**

```
result = dlg.exec()
if result == QDialog.Accepted:
    ...
elif result == QDialog.Rejected:
    ...
```

**不要写 `if dlg.exec():`，虽然能跑但含义模糊，读代码的人不知道 Accepted 和 Rejected 哪个是真。** 显式写枚举最清楚。

## 非模态对话框的应用场景

**show() 不是错误，只是用途不同：需要用户在主窗口和弹窗之间来回切换时用非模态。**

```
class ToolWindow(QDialog):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setWindowTitle("工具面板")
        # 不需要 accept/reject，点了右上角 X 关闭即可

tool = ToolWindow(window)
tool.show()    # 非模态：主窗口还能操作，工具面板常驻
```

**非模态对话框要自己管生命周期。** 如果用局部变量 `dlg = ToolWindow()` 然后 `dlg.show()`，函数返回后局部变量被回收，对话框立刻消失。

**✅ 解决：挂到 self 上保活：**

```
self.tool = ToolWindow(self)
self.tool.show()
```

**模态和非模态的选择标准：要"填完再取数据"用 exec；要"开着随时交互"用 show 并保活。**

## 小结

- QDialog 继承后自己排版，accept()/reject() 内置关闭并设状态
- exec() 模态阻塞，show() 非模态不阻塞
- ⚠️ 经典坑：用 show() 取数据拿到空值；exec 返回值用枚举 QDialog.Accepted 判断
- 数据校验重写 accept，不合法时 return 掉，对话框保持打开
- 非模态对话框要挂到 self 上保活，否则函数返回即被回收
- exec 之后取值，show 之后不能立即取值
