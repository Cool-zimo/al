# 收官：Qt 项目组织与下一步

> 25 课走完了。这一课讲怎么把 Qt 项目组织好、怎么打包发布，以及《Qt 进阶 2》里有什么在等你。

## Qt 项目的组织方式

**小项目可以一个文件搞定，但稍大一点的项目必须按职责切模块。** 推荐的目录结构：

```
myapp/
├── main.py                  # 入口：只创建 QApplication 和主窗口
├── main_window.py           # 主窗口：菜单栏、工具栏、状态栏、核心布局
├── dialogs/                 # 对话框模块
│   ├── __init__.py
│   ├── settings_dialog.py   # 设置对话框
│   └── about_dialog.py      # 关于对话框
├── widgets/                 # 自定义控件
│   ├── __init__.py
│   └── custom_slider.py     # 自定义滑块
├── core/                    # 业务逻辑（不依赖 Qt 的部分）
│   ├── __init__.py
│   ├── data_model.py        # 数据模型
│   └── file_operations.py   # 文件操作
├── workers/                 # 线程 Worker
│   ├── __init__.py
│   └── rename_worker.py
├── resources/               # 资源文件
│   ├── icons/
│   ├── themes/
│   └── resources.qrc
├── styles/
│   └── main.qss
└── tests/                   # 单元测试
    └── test_data_model.py
```

**切分原则：**

| 层 | 放什么 | 能 import 谁 |
|---|---|---|
| `core/` | 纯逻辑（数据模型、算法、文件 I/O） | 不依赖 Qt |
| `workers/` | 线程任务逻辑 | 只 import core |
| `widgets/` | 自定义控件 | Qt + core |
| `dialogs/` | 各种对话框 | 以上全部 |
| `main_window.py` | 主窗口组装 | 以上全部 |
| `main.py` | 入口 | 只创建 app + 窗口 |

**为什么 `core/` 不依赖 Qt？** 因为它要能被单元测试覆盖，单元测试不需要启动 GUI。把业务逻辑和 Qt 解耦，是专业 Qt 开发的标志。

## 模块切分的判断标准

**一个文件超过 300 行就该考虑拆了。** 但这不是硬指标——更重要的是"职责是否单一"。

**信号和槽的连接放在哪里？** 推荐在 `MainWindow.__init__` 里连接主窗口和子控件的信号。子控件自己内部的事自己连，不要"越级"。

```
# ✅ 好的做法：连接就近
class SettingsDialog(QDialog):
    settings_changed = Signal(dict)
    def __init__(self):
        # 内部信号自己连
        self.ok_btn.clicked.connect(self._on_ok)

class MainWindow(QMainWindow):
    def __init__(self):
        self.settings_dialog = SettingsDialog()
        # 跨模块的信号在 MainWindow 里连
        self.settings_dialog.settings_changed.connect(self._apply_settings)
```

## PyInstaller 打包 Qt 程序

**PyInstaller 是 Python 打包的首选工具。但 Qt 程序有特殊要求——必须带上 Qt 的插件和动态链接库。**

**基础打包命令：**

```
pip install pyinstaller
pyinstaller --onefile --windowed main.py
```

**`--windowed` 很重要**——它告诉 PyInstaller 这是一个 GUI 程序，不要在运行时弹出控制台窗口。Windows 上是 `--noconsole`，macOS 上是 `--windowed`。

**Qt 特有的坑：插件目录。**

**Qt 运行需要平台插件（platform plugin），比如 Windows 上的 `qwindows.dll`、Linux 上的 `libqxcb.so`。PyInstaller 通常会自动收集，但有时会漏。**

```
# 如果运行时报 "qt.qpa.plugin: Could not find the Qt platform plugin"
# 手动指定插件目录
pyinstaller --onefile --windowed \
    --add-data "venv/Lib/site-packages/PySide6/plugins;PySide6/plugins" \
    main.py
```

**Windows 上的典型错误：**

```
qt.qpa.plugin: Could not load the Qt platform plugin "windows" in "" even though it was found.
This application failed to start because no Qt platform plugin could be initialized.
```

**这通常意味着 Qt 的 `plugins/platforms/qwindows.dll` 没有被正确打包。** 解决方案：

```
# 方法一：用 --collect-all 强制收集 PySide6 所有文件
pyinstaller --onefile --windowed --collect-all PySide6 main.py

# 方法二：手动指定 hooks
# 创建 hooks/hook-PySide6.py
from PyInstaller.utils.hooks import collect_all
datas, binaries, hiddenimports = collect_all('PySide6')
```

**macOS 上 `.app` 包内的 Qt 框架路径问题：**

```
# 如果报 "Library not loaded: @rpath/QtCore.framework/Versions/A/QtCore"
# 需要在 .spec 文件里加
import PySide6
PySide6.__file__  # 找到 PySide6 安装路径
# 在 .spec 中加
binaries=[( '/path/to/PySide6/Qt/lib/*.dylib', '.' )],
```

**Linux 上要确保目标机器有 `libxcb` 等系统库，否则报 `xcb` 相关错误。**

## 打包清单

**发布前必须检查的事项：**

```
- [ ] --windowed/--noconsole 已设置
- [ ] PySide6 插件（platforms、styles、imageformats）已打包
- [ ] .qrc 资源已编译为 .py 并正常加载
- [ ] QSS 文件路径在打包后仍然有效（用 resource_path 辅助函数）
- [ ] 程序图标已设置（.ico for Windows, .icns for macOS）
- [ ] 在干净机器上测试（没有 Python/Qt 环境的机器）
- [ ] 文件体积可接受（PySide6 打包后通常 30-50MB）
```

**路径问题：`sys._MEIPASS` 是关键。**

**PyInstaller 打包后，文件被解压到临时目录 `sys._MEIPASS`。你的资源文件路径要做兼容处理：**

```
import sys
import os

def resource_path(relative_path):
    """获取资源文件的绝对路径，兼容开发和打包两种模式"""
    if hasattr(sys, '_MEIPASS'):
        return os.path.join(sys._MEIPASS, relative_path)
    return os.path.join(os.path.abspath("."), relative_path)

# 使用
icon_path = resource_path("resources/icons/app.png")
qss_path = resource_path("styles/main.qss")
```

## 翻车现场一：打包后 QSS 加载失败

**症状：开发时样式正常，打包后界面变成默认样式（丑）。

**原因：QSS 文件路径在打包后变了。开发时用相对路径 `./styles/main.qss`，但打包后这个文件在 `sys._MEIPASS` 里。**

**✅ 正确做法：用上面的 `resource_path` 函数处理所有资源路径。**

```
# ❌ 开发能跑，打包后失败
with open("./styles/main.qss", "r") as f:
    app.setStyleSheet(f.read())

# ✅ 两种模式都能跑
path = resource_path("styles/main.qss")
with open(path, "r", encoding="utf-8") as f:
    app.setStyleSheet(f.read())
```

## 翻车现场二：打包后程序体积 200MB+

**症状：一个简单程序打包后居然 200MB+。**

**原因：PyInstaller 打包了整个 Python 环境和所有依赖。如果你用了 `numpy`、`pandas` 等大型库，体积会暴增。

**✅ 优化方案：用虚拟环境只装必要依赖 + `--exclude-module` 排除不需要的模块。

```
# 创建干净的虚拟环境
python -m venv build_env
source build_env/bin/activate  # Windows: build_env\Scripts\activate
pip install PySide6 pyinstaller

# 排除不需要的大型模块
pyinstaller --onefile --windowed --exclude-module numpy main.py
```

## 这本书带走了什么

**回顾 25 课的核心收获：**

| 章节 | 核心能力 | 关键 API |
|------|---------|----------|
| 第 1 章 | 信号与槽、事件驱动思维 | Signal, connect, lambda 传参 |
| 第 2 章 | 布局管理、响应式界面 | QVBoxLayout, QGridLayout, addStretch |
| 第 3 章 | 常用控件全掌握 | QPushButton, QLineEdit, QTableWidget... |
| 第 4 章 | 对话框与菜单 | QMessageBox, QFileDialog, QAction |
| 第 5 章 | 样式美化 | QSS, 伪状态, qrc 资源系统 |
| 第 6 章 | 多线程 + 实战 | QThread, moveToThread, QTimer |

**你学到的不仅是 API，更是一种思维方式：**

1. **事件驱动**：程序不是从上到下执行，而是"等事件发生 → 做出响应"
2. **信号与槽**：组件之间解耦通信，不需要知道对方的存在
3. **主线程不阻塞**：重活扔线程，界面永远流畅
4. **信号桥接**：子线程不直接碰 UI，只发信号
5. **样式与逻辑分离**：QSS 管外观，Python 管逻辑

## 指路《Qt 进阶 2》

**《Python Qt 进阶 2》会带你进入更深的水域：**

| 主题 | 内容 |
|------|------|
| **Model/View 架构** | QAbstractTableModel 自定义数据模型，QListView/QTableView 的底层原理 |
| **自定义控件** | 继承 QWidget 重写 paintEvent，自定义绘图、动画 |
| **QPainter 绘图** | 矢量图形、图表绘制、Canvas 类应用 |
| **数据库集成** | QtSQL 模块、QSqlTableModel、SQLite/MySQL 连接 |
| **网络编程** | QNetworkAccessManager、异步 HTTP 请求、WebSocket |
| **国际化** | tr() 翻译系统、.ts 文件、多语言切换 |
| **单元测试** | pytest-qt、模拟信号、测试自定义控件 |
| **高级打包** | 代码签名、自动更新、MSI/DMG 安装包 |

**Model/View 是 Qt 最强大也最被低估的架构。** 当你有 10 万行数据要显示时，QTableWidget 会卡死，而 QTableView + QAbstractTableModel 能流畅滚动。这是从"能做出东西"到"做出专业级应用"的分水岭。

## 小结

- Qt 项目按职责分模块：core / workers / widgets / dialogs / main_window / main
- core 层不依赖 Qt，方便单元测试
- PyInstaller 打包 Qt 程序必须带 plugins（platforms、styles、imageformats）
- `--windowed` 隐藏控制台；`--collect-all PySide6` 解决插件缺失
- 用 `resource_path` 兼容开发和打包两种路径模式
- 虚拟环境 + `--exclude-module` 控制包体积
- 本书核心：事件驱动、信号与槽、主线程不阻塞、信号桥接、样式分离
- 《Qt 进阶 2》将深入 Model/View、自定义控件、绘图、数据库、网络
