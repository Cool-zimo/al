# QTimer：定时任务的正确姿势

> 用 QTimer 做定时任务，永远不会冻住界面。这一课讲清楚 QTimer 怎么用，以及为什么 time.sleep 是 GUI 的毒药。

## time.sleep 为什么是毒药

**`time.sleep(1)` 会冻结整个 Python 解释器 1 秒——包括事件循环。** 这 1 秒内什么都处理不了：鼠标点击没反应、窗口重绘不了、动画不动。

```
from PySide6.QtWidgets import QApplication, QLabel
import time, sys

app = QApplication(sys.argv)
label = QLabel("倒计时: 5")
label.show()

for i in range(5, 0, -1):
    label.setText(f"倒计时: {i}")
    app.processEvents()     # 勉强刷新
    time.sleep(1)           # ❌ 冻住 1 秒
```

**这段代码虽然用了 processEvents，但 sleep 期间界面完全无响应。** 拖动窗口会卡住，点关闭按钮要等 sleep 结束才生效。

## QTimer 的基本用法

**QTimer 是 Qt 的定时器，它不阻塞事件循环——到时间后通过信号通知你，你的槽函数在事件循环的间隙被调用。**

```
from PySide6.QtCore import QTimer

timer = QTimer()
timer.timeout.connect(on_tick)   # 时间到就触发
timer.start(1000)                # 每 1000ms（1 秒）触发一次
```

**对比：**

| | time.sleep | QTimer |
|---|---|---|
| 阻塞事件循环 | ✅ 是 | ❌ 否 |
| 界面响应 | 冻结 | 正常 |
| 精度 | 高（毫秒级） | 受事件循环影响（一般够用） |
| 适合场景 | 命令行脚本 | GUI 定时任务 |

## QTimer 做倒计时

**用 QTimer 改写上面的倒计时：**

```
from PySide6.QtCore import QTimer

class CountdownWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.label = QLabel("倒计时: 5")
        self.count = 5

        self.timer = QTimer(self)
        self.timer.timeout.connect(self.tick)
        self.timer.start(1000)   # 每秒 tick 一次

        layout = QVBoxLayout(self)
        layout.addWidget(self.label)

    def tick(self):
        self.count -= 1
        if self.count > 0:
            self.label.setText(f"倒计时: {self.count}")
        else:
            self.label.setText("时间到！")
            self.timer.stop()    # 停止定时器
```

**关键点：timer 的 timeout 信号触发 tick，tick 执行完立即返回，事件循环继续运转——界面始终响应。**

## QTimer.singleShot：一次性延迟

**`singleShot` 是"延迟执行一次"的便捷方法——不需要创建 QTimer 实例。**

```
from PySide6.QtCore import QTimer

# 3 秒后执行一次
QTimer.singleShot(3000, lambda: label.setText("3 秒到了！"))

# 等价于：
timer = QTimer()
timer.setSingleShot(True)
timer.timeout.connect(lambda: label.setText("3 秒到了！"))
timer.start(3000)
```

**常见用途：延迟初始化、自动隐藏提示、防抖（debounce）。**

```
# 防抖：用户停止输入 500ms 后才触发搜索
self.debounce_timer = QTimer()
self.debounce_timer.setSingleShot(True)
self.debounce_timer.timeout.connect(self.do_search)

def on_text_changed(self, text):
    self.debounce_timer.start(500)  # 每次输入重置定时器
```

## 翻车现场一：timer 没有 parent，被垃圾回收后定时器消失

**症状：定时器跑着跑着就停了，或者程序莫名其妙崩溃。**

```
def setup_timer():
    timer = QTimer()          # ❌ 局部变量，函数结束后被回收
    timer.timeout.connect(tick)
    timer.start(1000)
    return

setup_timer()  # timer 立即被 GC，timeout 永远不会触发
```

**原因：Python 的垃圾回收会回收没有引用的对象。QTimer 被回收后，底层定时器也跟着没了。**

**✅ 正确做法：把 timer 存为实例属性（self.timer）或设置 parent。**

```
class MyWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.timer = QTimer(self)   # ✅ parent 保证生命周期
        self.timer.timeout.connect(self.tick)
        self.timer.start(1000)
```

## 翻车现场二：在 tick 里做重活，定时器变"不准"

**症状：设置 100ms 间隔，但实际触发间隔越来越长，甚至好几秒才触发一次。**

```
def tick():
    time.sleep(0.5)   # ❌ 在 tick 里 sleep
    # 或者做了大量计算
    for i in range(10_000_000):
        pass
```

**原因：tick 函数是在事件循环里调用的。tick 不返回，下一个 timeout 事件就得排队等着。** 如果 tick 执行了 500ms，那实际间隔就是 500ms + 设定的 100ms = 600ms。如果 tick 超过设定的间隔，定时器会"追赶"——连续触发多个 timeout。

**✅ 正确做法：tick 里只做轻量操作（更新 UI、读取状态）。重活扔线程。**

```
def tick(self):
    # ✅ 轻量：只更新界面
    self.label.setText(self.get_status_text())
```

## 翻车现场三：忘记 stop()，重复 start 导致多次触发

**症状：点击按钮启动定时器，再点一次，发现 tick 被触发了两次——而且越来越多。**

```
def on_start(self):
    self.timer = QTimer(self)
    self.timer.timeout.connect(self.tick)
    self.timer.start(1000)   # ❌ 每次点击都新建一个 timer，旧的还在跑
```

**原因：每次点击都创建新 QTimer，旧的没有被 stop。两个（甚至更多）定时器同时触发 tick。**

**✅ 正确做法：复用同一个 timer，start 前先 stop，或者检查是否在运行。**

```
def on_start(self):
    if self.timer.isActive():
        self.timer.stop()
    self.timer.start(1000)   # ✅ 先停再起

# 或者更简洁：
def on_start(self):
    self.timer.start(1000)   # start 会自动替换之前的间隔
```

## QTimer 做进度动画

**用 QTimer 做一个"假进度条"动画——在真实任务没开始时给用户视觉反馈：**

```
from PySide6.QtCore import QTimer, Qt
from PySide6.QtGui import QColor

class FakeProgress(QWidget):
    def __init__(self):
        super().__init__()
        self.progress = 0
        self.bar = QProgressBar()
        self.bar.setRange(0, 100)

        self.timer = QTimer(self)
        self.timer.timeout.connect(self.animate)

    def start_animation(self):
        self.progress = 0
        self.timer.start(50)   # 每 50ms 更新一次

    def animate(self):
        self.progress += 2
        if self.progress > 100:
            self.progress = 0   # 循环动画
        self.bar.setValue(self.progress)
```

**这是"不确定进度"的经典替代方案——当不知道任务要多长时间时，用一个来回摆动的动画告诉用户"程序没死，正在干活"。**

**更高级的做法：用 QProgressBar 的 `setRange(0, 0)` 开启"忙等待"模式，Qt 会自动显示一个来回滚动的动画块，不需要手动更新。**

```
progress_bar.setRange(0, 0)  # 不确定模式：显示一个动画滑块
```

## 小结

- time.sleep 会冻住事件循环，GUI 中绝对不能用
- QTimer 通过信号机制实现定时，不阻塞事件循环
- QTimer.singleShot 用于一次性延迟执行
- timer 必须存为实例属性或设置 parent，否则被 GC
- tick 里只能做轻量操作，重活必须扔线程
- start 前先 stop，防止重复触发
- QProgressBar.setRange(0, 0) 是不确定进度的快捷方案
