# 为什么 GUI 里不能干重活

> GUI 程序最致命的错误不是崩溃，而是"卡死"。这一课讲清楚主线程阻塞的原理，以及什么活该扔出去。

## 单线程的真相

**PySide6 程序启动后，只有一条"主线程"在干活。** 这条线程干两件事：一是执行你的业务逻辑，二是运行事件循环（event loop）。事件循环不停地处理鼠标点击、键盘输入、窗口重绘请求，让界面"活着"。

```
while True:
    事件 = 取一个事件()      # 点击、重绘、定时器超时...
    处理(事件)              # 调用你的槽函数
```

**关键事实：`app.exec()` 就是那个 while 循环。** 你的 `on_clicked()` 槽函数是在事件循环里被调用的。只要 `on_clicked()` 不返回，事件循环就卡在那里——新的点击事件进不来，重绘请求也处理不了，窗口自然就"无响应"了。

```
import sys
import time
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QVBoxLayout

app = QApplication(sys.argv)

def heavy():
    time.sleep(5)  # 模拟耗时操作：事件循环被卡住 5 秒

win = QWidget()
btn = QPushButton("点我（会卡 5 秒）")
btn.clicked.connect(heavy)
QVBoxLayout(win).addWidget(btn)
win.show()
app.exec()
```

**点了那个按钮之后，窗口完全冻住——拖不动、点不动、系统还会弹"无响应"。** 这不是 bug，是事件循环被你的 `time.sleep(5)` 堵死了。

## 什么是"重活"

**一句话：任何执行时间超过 100ms 的操作，都不该出现在主线程的槽函数里。** 用户的感知阈值大约是 100ms——超过这个时间，界面就会有明显的"卡顿感"。

| 操作类型 | 示例 | 耗时量级 | 能否放主线程 |
|---------|------|---------|------------|
| 网络请求 | requests.get(url) | 100ms ~ 30s+ | ❌ 必须扔出去 |
| 大文件读写 | open(大文件).read() | 10ms ~ 数秒 | ❌ 视文件大小 |
| 大量计算 | 图像处理、数据排序 | 100ms ~ 数分钟 | ❌ 必须扔出去 |
| 数据库查询 | cursor.execute("SELECT ...") | 10ms ~ 数秒 | ❌ 网络型 DB 必须扔 |
| 简单字符串处理 | 拼接、格式化 | < 1ms | ✅ 没问题 |
| 创建控件 | QPushButton("xxx") | < 5ms | ✅ 没问题 |

**网络请求是最常见的罪魁祸首：**

```
import requests

def on_fetch():
    resp = requests.get("https://api.example.com/data")  # 可能 3 秒
    label.setText(resp.text)
```

**这段代码在网络慢的时候，界面冻住 3 秒。** 用户以为程序崩了，疯狂点击，结果事件队列堆积，解冻后疯狂触发——雪上加霜。

## 翻车现场一：循环里没给事件循环喘息的机会

**症状：想做一个"逐行处理大文件"的进度显示，但进度条完全不更新，直到全部处理完才一次性跳到 100%。**

```
def process_file():
    for i, line in enumerate(huge_file):
        do_something(line)          # 每行耗时 10ms
        progress_bar.setValue(i)    # 设了值但界面不重绘！
    # 循环结束后事件循环才恢复，进度条一口气跳到 100%
```

**原因：你的 `process_file` 是一次性跑完的。在它 return 之前，Qt 根本没有机会执行重绘事件。** `setValue` 只是更新了内部数值，重绘要等事件循环来调度。

**✅ 正确思路：把大任务拆成小块，用 QTimer 分批执行，每块结束后让出控制权给事件循环。** 或者——用线程（下一课讲）。

## 翻车现场二：以为 `QApplication.processEvents()` 是万能解药

**症状：听人说"在循环里调一下 processEvents 就能刷新界面"，写上之后确实进度条动了，但程序变得极不稳定。**

```
from PySide6.QtCore import QCoreApplication

def process_file():
    for i, line in enumerate(huge_file):
        do_something(line)
        progress_bar.setValue(i)
        QCoreApplication.processEvents()  # "强制刷新"
```

**问题：`processEvents()` 会处理所有待处理事件——包括用户点的"取消"按钮、关闭窗口按钮。** 如果在处理事件的过程中又触发了别的槽函数，可能形成重入调用，导致难以调试的崩溃。而且这本质上是在"手动驱动事件循环"，性能和稳定性都不如正确的线程方案。

**✅ 正确做法：`processEvents()` 只适合极短期的临时刷新（比如一个 500ms 的加载动画），真正的解法是用 QThread 把重活挪到子线程。**

## 翻车现场三：在 `__init__` 里做了网络请求

**症状：程序启动后要等好几秒才弹出窗口。**

```
class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        self.data = requests.get("https://api.example.com/init").json()  # 阻塞 3 秒
        self.init_ui()  # 3 秒后才执行

app = QApplication(sys.argv)
win = MainWindow()  # 构造时就卡住了
win.show()
app.exec()
```

**原因：窗口 show 之前要做的事都在主线程里同步执行。** 用户看到的是"双击图标后等了 3 秒才出窗口"，体验极差。

**✅ 正确做法：先 show 窗口，再异步发起请求（用信号/线程/Qt 的网络模块）。**

## 阻塞的深层原理

**事件循环是"协作式"的——它依赖所有槽函数快速返回。** 这不是 PySide6 的缺陷，而是几乎所有 GUI 框架的共性设计（包括浏览器、Electron、Swing）。它的优点是简单高效——不需要锁就能保证 UI 操作安全。代价就是：你不能在里面干重活。

**类比：** 事件循环像餐厅里唯一的一个服务员。他一次只能服务一桌。如果某桌客人点单后要等 5 分钟才能决定吃什么，其他所有桌都得干等。

**线程就是"再雇一个服务员"——让新服务员去厨房等菜，原来的服务员继续服务其他客人。**

## 小结

- GUI 程序只有一条主线程，它既要跑业务逻辑又要跑事件循环
- `app.exec()` 就是事件循环；槽函数不返回，循环就卡死
- 超过 100ms 的操作都算"重活"：网络请求、大文件 I/O、大量计算
- 重活放主线程 = 界面冻住 = "无响应"
- `processEvents()` 是临时方案不是正解，真正的解法是 QThread
- 下一课讲怎么用 Worker 模式正确地把活挪到子线程

```quiz
type: local
q: 写一个程序验证"主线程阻塞"现象：窗口有一个 QLabel（显示当前时间）、一个 QPushButton（"模拟耗时"）、一个 QLineEdit。点击按钮后，在槽函数里用 for 循环做 100 万次数学运算（模拟重活），循环过程中更新 QLabel 显示进度百分比。观察进度条/标签是否在循环过程中实时更新，还是循环结束后一次性跳变。然后尝试用 time.sleep(0.01) 在每次循环中"让步"，对比效果。注意：这是窗口程序，网页里跑不了，请点"在 VS Code 里打开"运行。
starter: |
  import sys
  import time
  from PySide6.QtWidgets import (
      QApplication, QWidget, QPushButton, QLabel, QLineEdit, QVBoxLayout
  )

  app = QApplication(sys.argv)
  win = QWidget()
  win.setWindowTitle("主线程阻塞验证")
  win.resize(400, 200)

  time_label = QLabel("时间会停")
  result_edit = QLineEdit()
  result_edit.setPlaceholderText("循环结果会显示在这里")
  btn = QPushButton("开始耗时计算")

  def on_click():
      total = 0
      for i in range(10_000_000):
          total += i * i
      result_edit.setText(str(total))

  btn.clicked.connect(on_click)

  # 用 QTimer 每秒更新时间标签
  from PySide6.QtCore import QTimer
  def update_time():
      from datetime import datetime
      time_label.setText(datetime.now().strftime("%H:%M:%S"))
  timer = QTimer()
  timer.timeout.connect(update_time)
  timer.start(1000)
  update_time()

  layout = QVBoxLayout(win)
  layout.addWidget(time_label)
  layout.addWidget(result_edit)
  layout.addWidget(btn)
  win.show()
  app.exec()
checklist:
- 能观察到点击按钮后时间标签停止更新（事件循环被阻塞）
- 计算结果最终正确显示
- 理解了 time.sleep 和纯计算都会阻塞事件循环
- 程序正常显示并运行
```

## 本节测验

```quiz
type: choice
exam: true
q: 关于 GUI 主线程阻塞，以下说法正确的是？
options:
- 只要把耗时操作放在单独的 Python 函数里，就不会阻塞界面
- 耗时操作放在槽函数里会导致事件循环卡住，界面"无响应"，因为槽函数在主线程执行
- PySide6 会自动把耗时操作放到后台线程，开发者无需关心
- 用 QTimer 可以解决所有阻塞问题，因为 QTimer 会自己开线程
answer: 1
explain: 槽函数是在主线程的事件循环中同步调用的，耗时操作不返回就会堵住整个循环。QTimer 只是定时触发，本身不创建线程。PySide6 也不会自动后台化你的代码。
```
