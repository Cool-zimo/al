# 20 网页三题型：HTML / CSS / JS

> 它们判的是效果，不是代码长什么样。

## 三种题型

| 题型 | 判什么 |
|---|---|
| `html` | DOM 结构（有几个 li、链接指向哪） |
| `css` | 计算后的样式 |
| `js` | 函数返回值，或 DOM 操作结果 |

## 共同点：要写 checks

```
type: html
q: 写一个含三项的无序列表
starter: |
  <ul>
    <li>第一项</li>
  </ul>
checks: |
  document.querySelectorAll("li").length === 3
html: |
  <!DOCTYPE html>
  <html><body></body></html>
hint: 用 ul 和三个 li
```

`checks` 是一行行表达式，全部为真才算通过。`html` 是运行环境（可选）。

## 判效果，不判写法

这是最关键的设计。

CSS 题让把 h1 变红，读者写 `red`、`#f00`、`rgb(255,0,0)` 都算对 —— 因为 `getComputedStyle` 会把它们统一算成 `rgb(255, 0, 0)`。

同理 HTML 题不看缩进、不看属性顺序、不看单双引号。

**所以别写检查源码字符串的 checks。**

## 几个实测出来的坑

写 CSS 题时我踩过这些：

```
getComputedStyle(btn).fontSize === "8px"
```

`<button>` 默认字号是 **13.333px**，写 `0.5em` 算出来是 6.67px 不是 8px。改用 `rem` 才好判断。

```
getComputedStyle(img).height === "auto"
```

`height: auto` 算出来是图片固有高度的**像素值**，永远不会等于字符串 `auto`。

```
margin: 0 auto
```

水平 margin 算出来是具体像素。验居中要写「左右 margin 相等且大于 0」。

```
:hover 的 transform
```

`:hover` 伪类没法用 JS 触发，hover 态的值永远是 `none`。要改查 `transition` 属性。

这些不实测根本发现不了 —— 写出来的题会让**所有人都过不了**。

## 小结

- 三种网页题都要写 `checks`
- 判计算后的效果，不判源码
- 写之前先自己跑一遍确认能过

```quiz
type: choice
answer: 0
q: CSS 题判分时，读者写 red 和 #f00 都算对吗？
options:
- 算对，因为比的是计算后的值
- 只有 red 对
- 只有 #f00 对
- 都算错，必须写 rgb()
hint: getComputedStyle 会统一格式
explain: 判的是计算后的样式，这三种写法算出来都是 rgb(255, 0, 0)。
```

```quiz
type: choice

answer: 0
q: 为什么不该写检查源码字符串的 checks？
options:
- 缩进、属性顺序、引号写法不同都会被误判为错
- 字符串比对更慢
- 源码里有注释
- 会报错
explain: 判效果才公平。同样正确的代码换个写法就该算错，那是题目的问题不是读者的问题。
```
