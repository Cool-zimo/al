# 02 albook.json：一本书的身份证

> 这个文件写错了，整本书都发不出去。

## 最小能用的样子

```
{
  "format": "al-book",
  "id": "my-first-book",
  "title": "我的第一本书",
  "subtitle": "写给谁看、讲什么",
  "desc": "两三句话说清这本书的定位。",
  "stage": "基础",
  "level": "入门",
  "langs": ["zh"],
  "license": "CC BY-NC 4.0",
  "author": { "name": "你的名字" }
}
```

## 每个字段在干嘛

| 字段 | 作用 | 不写会怎样 |
|---|---|---|
| `format` | **必须精确等于** `al-book` | 直接不收录 |
| `id` | 书的唯一标识 | 校验报错 |
| `title` / `subtitle` / `desc` | 书城里显示的三行字 | 校验报错 |
| `stage` | 分类 | 校验报错 |
| `level` | 难度，随便写，比如「入门」「进阶」 | 校验报错 |
| `langs` | `["zh"]`、`["en"]` 或 `["zh","en"]` | 校验报错 |
| `license` | 许可证名 | 校验报错 |
| `author.name` | 作者名 | 校验报错 |

## format 必须精确

这几个都会被**静默跳过**：

```
"format": "albook"      不行
"format": "AL-BOOK"     不行
"format": "al-book "    不行（多了个空格）
```

只有 `al-book` 这一个字符串能过。这是故意的 —— 宁可漏收，也不误收。

## id 的规则

```
"id": "my-first-book"     可以
"id": "MyFirstBook"       不行，不能大写
"id": "my_first_book"     不行，不能用下划线
"id": "-mybook"           不行，不能以连字符开头
```

id 会变成书在站内的地址的一部分，所以它必须能在网址里安全出现。

## 可选但有用的字段

```
"tags": ["Python", "入门"],
"kind": "textbook",
"homepage": "https://example.com"
```

`kind` 后面有一整课专门讲，它决定你的书**要不要强制有题目**。

## 小结

- `format` 精确等于 `al-book`
- 八个必需字段一个都不能少
- `id` 只能小写字母、数字、连字符
- `author` 是对象，至少要有 `name`
