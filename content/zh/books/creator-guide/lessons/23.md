# 23 hint 与 explain

> 这两个字段决定读者卡住时是放弃还是继续。

## hint：卡住时看一眼

`hint` 默认不显示，读者点「提示」才展开。

好的 hint：

```
hint: 想想 len() 返回的是什么类型
hint: 用 n % 2 == 0
```

不好的：

```
hint: 再想想                           等于没说
hint: 答案是 return a + b              直接给了，读者不会真的想
hint: 参考课本第 37 页                  读者手边没有
```

**hint 的目标是把读者从「完全没思路」推到「有一点思路」，不是给答案。**

## explain：做完之后看

`explain` 在做完（无论对错）之后显示。

它的作用是**讲为什么**，不只是讲是什么：

```
explain: 因为列表是可变的，函数里改了会影响外面。如果不想被影响，传 list(x) 的副本。
```

比 `explain: 答案是 [1, 2, 3]` 有价值得多。

## 做错了也要有收获

读者做错时也会看到 explain。所以写的时候想着：**如果他做错了，这句话能让他明白错在哪吗？**

```
explain: 注意 randint(1, 6) 是闭区间，两端都包含；randrange(1, 6) 不含 6。
```

这种 explain 在读者做错时最有价值。

## 什么时候必须写

- 有反直觉的坑（比如 `0.1 + 0.2`、`randrange` 的边界）
- 有多种写法，你想说明为什么推荐这种
- 错误答案很常见，你想提前堵住

不用每题都写，但**有坑的题一定要写**。

## 小结

- hint 给思路不给答案
- explain 讲为什么
- 有坑的题必须写 explain
