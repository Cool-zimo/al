# 16 函数题：真的调用你写的函数

> 这是最有价值的一种题型 —— 网页会真跑一遍。

## 写法

```
type: function
q: 写一个函数 add(a, b)，返回两数之和
func: add
starter: |
  def add(a, b):
      return 0
cases: |
  1, 2 -> 3
  5, 7 -> 12
  -1, 1 -> 0
hint: 直接把两个参数加起来
explain: return a + b 就行。
```

## 三个关键字段

| 字段 | 作用 |
|---|---|
| `func` | 要调用的函数名，必须和 starter 里的定义一致 |
| `starter` | 初始代码，读者在此基础上改 |
| `cases` | 用例表，逐条比对返回值 |

`func` 写错了（比如写 `add` 但 starter 里定义的是 `sum`），校验器会报错 —— 因为它查得到 starter 里的 `def add`。

## 判分是真的

读者点运行后，网页会：

1. 执行他写的整个代码
2. 取出 `func` 指定的函数
3. 对 `cases` 里每一行，用参数调用它
4. 把返回值和期望值比对

所以这不只是"看起来对"，是**真的对**。

## starter 要能跑

新手常给一个跑不起来的 starter：

```
starter: |
  def add(a, b):
      # 在这里写代码
```

这段是语法错误（函数体不能只有注释）。读者一打开就看到报错，体验很差。

**给一个能跑但结果不对的版本**：

```
starter: |
  def add(a, b):
      return 0
```

至少能跑，读者改一个数字就对了。

## 用例要有区分度

```
cases: |
  1, 2 -> 3       好
  0, 0 -> 0       一般（return 0 也能过）
```

**一定要检查：starter 原样提交能不能过？** 如果能过，说明这题没区分度 —— 校验器会拦下这种题。

比如上面 `0, 0 -> 0` 单独用的话，`return 0` 就直接通过了。

## 小结

- `func`、`starter`、`cases` 三件套
- starter 要能跑，只是结果不对
- 用例要能挡住 starter 原样提交

## 随堂练习

```quiz
type: function
func: double
q: 写一个函数 double(n)，返回 n 的两倍
starter: |
  def double(n):
      return 0
cases: |
  1 -> 2
  5 -> 10
  -3 -> -6
hint: 返回 n * 2
explain: 把参数乘以 2 返回。
```
