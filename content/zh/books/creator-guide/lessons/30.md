# 30 发布之后

> 书发出去不是结束，是开始。

## 更新内容

在开发者平台里改，改完再发布一次 —— 会推到同一个仓库。

或者直接在 GitHub 上改。因为内容是从你的仓库直读的，**改完读者立刻看到新版**。

## 草稿和发布是两回事

```
草稿    在你的私有仓库 al-drafts 里，随时改，别人看不到
发布    推到公开仓库，进书城
```

草稿会自动保存（停止改动 3 秒后），换设备可以拉取。所以你可以大胆改，改坏了不发布就行。

## 改文件名要小心

改章测文件名（`test-01` → `quiz-01`）时，旧文件会在下次推送时一起删掉，不会攒孤儿。

但**已经发布过的公开仓库不会自动同步删除**。如果你很在意仓库整洁，去 GitHub 上手动删一下。

## 收集反馈

书城里每本书都带作者名和许可证。读者看到问题会来找你 —— 留个联系方式在 README 里是个好主意。

## 什么时候该开新书

一个大话题写到 40 课以上，考虑拆成两本书。一本 30 课左右的书，读者更容易读完。

## 最后

写教材最难的不是格式 —— 格式这一册讲完了。最难的是判断**读者在哪一步会卡住**，然后在那里放一个例子、一句提醒、一道题。

这个只能靠读反馈、看数据、反复改。

祝写得开心。

## 小结

- 改完再发布一次就行
- 草稿私有、发布公开，两回事
- 内容直读，改了立刻生效
- 反馈比格式重要
