# 22 小项目题

> 一章的收尾用它，把前面学的串起来。

## 和 local 的区别

`project` 也是开放式、靠清单自评，但它有**初始代码**，而且通常是**纯逻辑、浏览器能跑的**。

`local` 是「必须去本地跑」，`project` 是「给你一个起点，自己往上加」。

## 写法

```
type: project
q: 做一个通讯录：能增删改查，能存到文件
starter: |
  contacts = {}

  def add(name, phone):
      contacts[name] = phone
checklist: |
  - 能添加联系人
  - 能按名字查
  - 退出后数据还在
```

## 放在哪

建议放在**章测的最后一题**，或者一章的最后一课。

它不该出现在每一课里 —— 小项目要花时间，一课一个就太多了。

## starter 要"半成品"

好的 starter 给出**骨架和一部分实现**，读者照着补剩下的：

```
contacts = {}

def add(name, phone):
    contacts[name] = phone

def find(name):
    # 在这里补
    pass

def delete(name):
    # 在这里补
    pass
```

比只给一个空文件友好得多。

## 清单按功能拆

```
- 能添加联系人
- 能按名字查
- 能删除联系人
- 退出后数据还在
```

一条一个功能，读者做完一项勾一项，有成就感。

## 小结

- `project` 给初始代码 + 清单
- 放章测末尾或章末一课
- starter 给半成品骨架
- 清单按功能拆
