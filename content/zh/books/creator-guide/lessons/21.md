# 21 本地运行题：浏览器跑不了的东西

> GUI、文件、子进程 —— 这些只能让读者自己跑。

## 什么时候用它

有些东西浏览器沙箱里根本没有：

- 图形窗口（tkinter、Qt）
- 真实文件系统
- 子进程（`subprocess`）
- 需要联网或需要硬件的

这些题不能自动判分，用 `type: local`。

## 写法

```
type: local
q: 用 tkinter 做一个带按钮的窗口
starter: |
  import tkinter as tk

  root = tk.Tk()
  root.title("我的窗口")
  root.mainloop()
checklist: |
  - 窗口能打开
  - 有一个按钮
  - 点按钮有反应
hint: 点「在 VS Code 里打开」跑
```

## checklist 是重点

因为没有自动判分，**清单就是这题的全部**。读者靠它判断自己做没做完。

写清单的原则：

```
- 窗口能打开            好，可验证
- 代码写得优雅          不好，没法判断
- 点按钮会打印一句话     好，可验证
- 理解了布局原理        不好，是心态不是结果
```

每一条都应该是**读者能自己回答是或不是**的。

## 给一个能跑的 starter

和函数题一个道理：starter 要能打开（至少不报错），读者在它上面加东西。

## 页面上的样子

`local` 题会显示一个「在 VS Code 里打开」按钮，把 starter 写进本地文件并唤起编辑器。读者在本地跑完，回来自己勾清单。

## 小结

- 浏览器跑不了的用 `local`
- `checklist` 要可验证
- starter 要能跑
