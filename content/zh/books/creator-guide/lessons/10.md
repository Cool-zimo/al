# 10 一课该写多长

> 太短讲不透，太长读不完。

## 一个参考区间

**正文 60 ~ 150 行**是个舒服的区间。

不到 60 行，校验器会提示「可能是占位内容」—— 这只是警告，不是错误，但通常说明你还没写完。

超过 150 行，读者容易在中途流失。真要讲一个大话题，**拆成两课**比硬塞一课好。

## 怎么判断该不该拆

一个信号：**这一课里有几个 `##` 小标题？**

```
2 ~ 4 个   合适
5 个以上   考虑拆成两课
1 个       可能太水，或者你漏了小节
```

## 一课只解决一个问题

好的课名长这样：

```
切片：一次取出一整段
字典：按键取值而不是按位置
为什么 0.1 + 0.2 不等于 0.3
```

坏的课名：

```
列表和字典和集合          三个东西，拆开
Python 数据结构（上）     「上」说明你没想清楚边界
一些常用的函数            太散
```

## 别在开头铺陈太久

读者点进一课，前三屏决定他要不要继续。所以应该先给：这一课解决什么问题、一个能立刻看懂的例子、为什么需要它。

**不要**先用两屏讲历史背景、设计哲学、和其它语言的对比。那些东西读者不关心，直到他先会用为止。

## 小结

- 60 ~ 150 行
- 一课一个问题，名字要具体
- 开头三屏内给出例子
