# 收官：打包发布与两册 Qt 带走了什么

> 项目写完了，接下来是两件事：把它打成一个能发给别人的 exe，以及回头看看这两册书到底给你留下了什么。

## 打包：PyInstaller 打 Qt 程序要带插件

纯 Python 脚本打包很简单：`pyinstaller main.py`。但 Qt 程序要多做一步——**把 Qt 的插件目录一起带进去**。PySide6 运行时要动态加载平台插件（windows/linux/android 那套）、图片格式插件、样式插件，找不到就直接起不来。

**症状：双击 exe 闪一下就没了，命令行跑报 `qt.qpa.plugin: Could not find the Qt platform plugin "windows"`。**

打包命令：

```
pyinstaller --onefile --windowed ^
    --add-data "venv/Lib/site-packages/PySide6/plugins;PySide6/plugins" ^
    main.py
```

Linux/macOS 把分号换成冒号：

```
pyinstaller --onefile --windowed \
    --add-data "venv/lib/python3.12/site-packages/PySide6/plugins:PySide6/plugins" \
    main.py
```

`--windowed`（macOS 上叫 `--noconsole`）是给 GUI 程序用的，表示不要控制台黑窗口。`--add-data` 把插件目录拷进包里，Qt 启动时会去 `PySide6/plugins` 找它。

**更简单可靠的做法：让 PyInstaller 自己找。** 用 `--collect-all PySide6` 一键把所有 Qt 相关文件都收进去，代价是包大一点：

```
pyinstaller --onefile --windowed --collect-all PySide6 main.py
```

## spec 文件：需要反复打包就别每次敲命令

第一次打包成功后，PyInstaller 会生成 `main.spec`。以后改了代码，直接：

```
pyinstaller main.spec
```

spec 文件里插件路径是写死的，所以如果你换机器或换虚拟环境，重新跑一次带 `--add-data` 的命令重新生成 spec 更稳。

## 打包体积：为什么 Qt 的 exe 动辄 50MB 起

PySide6 本身 + Qt 核心库 + 平台插件 + 图片插件，加起来 40~60MB 是常态。这是 Qt 的固有成本。**如果你做的是要发给别人、功能不算简单的桌面应用，这个体积完全可接受。** 如果是写个小工具只想几 MB，那 tkinter 反而更合适——它随 Python 自带，不需要打包 Qt。

**别为了体积去手动删 plugins 里的 .dll。** 删掉哪个没用的你可能判断错，删错了就是平台插件找不到的报错。体积敏感的话用 UPX 压缩（`--upx-dir`），但会稍微拖慢启动速度。

## 数据库文件怎么办

SQLite 的 `ledger.db` 要跟 exe 放一起。两个思路：

**1. 放 exe 同目录，相对路径。** 程序启动时在 exe 所在目录找 `ledger.db`：

```
import os, sys

def app_dir():
    if getattr(sys, "frozen", False):
        return os.path.dirname(sys.executable)   # 打包后是 exe 目录
    return os.path.dirname(os.path.abspath(__file__))

DB_PATH = os.path.join(app_dir(), "ledger.db")
```

**2. 放用户目录，跨设备更稳。** Windows 上放 `%APPDATA%/Ledger/ledger.db`，换机器、重装都不会丢数据。

**强烈建议用方案 2。** 方案 1 的问题是：用户把 exe 放桌面、把 db 也放桌面，重装系统直接没了。财务数据丢不得。

## 这两册 Qt 带走了什么

回头看《窗口入门 4》和这一册，我们覆盖了：

**第一册（窗口入门 4）——把界面搭起来**
- QWidget、布局管理器、信号槽
- 常用控件：按钮、输入框、列表、对话框
- 事件与鼠标键盘
- 菜单栏、工具栏、状态栏

**第二册（这一册）——让界面和数据好好相处**
- Model/View 三角色：Model 出数据、View 负责显示、Delegate 负责画和编辑
- 三方法：`rowCount`、`columnCount`、`data`
- 自定义 Delegate：进度条单元格、行高列宽、表头
- 视图选择：`QItemSelectionModel`
- 代理排序过滤：`QSortFilterProxyModel`
- 绘图：`QPainter`、坐标变换、渐变、矢量路径
- 数据：`QtSql`、`QSqlTableModel`、`QSqlQuery` 参数化
- 网络：`QNetworkAccessManager` 异步 + JSON 填 Model

**一条主线贯穿始终：把"数据是什么"和"数据怎么显示"分开。** 这是 Model/View 架构教给你的思维方式，它不只在 Qt 里有用——前端框架的 MVVM、后端的 MVC、甚至你自己设计任何带界面的程序，都是同一套思想。

## 和你学过的 tkinter 三册对照

| 能力 | tkinter 三册 | Qt 两册 |
|---|---|---|
| 搭界面 | 够用，布局偏手动 | 布局管理器 + Designer 更顺 |
| 数据绑定 | 要自己刷 Listbox | Model/View 自动响应 |
| 自定义单元格 | 基本没有 | Delegate 想怎么画怎么画 |
| 排序过滤 | 自己重排列表 | ProxyModel 一行搞定 |
| 绘图 | 靠 matplotlib 图片 | QPainter 矢量自绘 |
| 数据库 | sqlite3 手写 | QtSql 直接绑视图 |
| 网络 | requests + 线程 | 异步信号，UI 不卡 |
| 打包 | PyInstaller | 多带 Qt 插件 |
| 体积 | 小 | 40MB 起 |

**不是"Qt 比 tkinter 好"，而是"Qt 适合更大的项目"。** 写个 200 行的工具，tkinter 又快又小；写一个要维护三年、要排序要筛选要图表的记账本，Qt 的结构能救你很多次返工。

## 翻车现场一：打包后报平台插件找不到

**症状**：`qt.qpa.plugin: Could not find the Qt platform plugin "windows"`。

**原因**：没把 `PySide6/plugins` 打进包。

**正确写法：**

```
pyinstaller --onefile --windowed --collect-all PySide6 main.py
```

## 翻车现场二：用了 `--onefile` 但忘了 `--windowed`，双击蹦出控制台

**症状**：程序正常，但旁边跟着一个黑窗口关不掉。

**正确写法：GUI 程序一律加 `--windowed`（Windows）或 `--noconsole`（macOS）。**

## 翻车现场三：数据库路径写死成相对路径，换机器数据全丢

**错误写法：**

```
DB_PATH = "ledger.db"                 # 相对当前工作目录，极不可靠
```

**正确写法：打包后用 exe 所在目录或用户 AppData 目录。**

## 翻车现场四：打包后程序启动慢得像死了一样

**原因**：`--onefile` 模式要先把所有内容解压到临时目录再运行，50MB 解压要两三秒。

**正确做法：发布版用 `--onedir` 更快；或者接受 onefile 的启动延迟。** 别以为程序卡死了。

## 翻车现场五：打包时把虚拟环境里的所有包都带上了

**症状**：包体积 200MB，里面塞了一堆开发用的包（pytest、ipython）。

**正确做法：用一个干净的虚拟环境专门装打包所需的依赖，别在开发环境里直接打包。**

## 翻车现场六：以为"Qt 性能比 tkinter 好所以程序更快"

**正确理解：Qt 的性能优势体现在渲染复杂界面、大数据量表格、矢量绘图上，不是执行你那段循环更快。你的 for 循环在哪都是一样的。**

## 小结

- PyInstaller 打 Qt 要带插件：`--collect-all PySide6`
- GUI 程序加 `--windowed` 去掉控制台
- 数据库路径用 exe 目录或用户目录，别用相对路径
- 两册主线是"数据与显示分离"的架构思维
- Qt 适合大项目，tkinter 适合小工具，各有所长
- 下一步：工程实践（测试/样式/多线程）、数据分析（pandas/PyQtGraph）、算法（自定义 View）
- 最好的进阶练习：用同一套架构换一个数据源再做一遍
