# 项目设计：把 tkinter 记账本用 Qt 重写一遍

> 这一册我们一路从 Model/View 走到绘图再到网络，收官项目是**把你在《窗口入门 3》写过的那个 tkinter 记账本，用 Qt 完整重写一遍**。同样的数据库，完全不同的界面层。

## 你之前做过什么

《窗口入门 3》里那个记账本大概长这样：SQLite 存收支记录，tkinter 做录入窗口和列表框，matplotlib 画饼图。它有四层：

```
数据层   data.py       建表、增删查、按分类/月份汇总
模型层   models.py     一条记录的对象封装（可选）
界面层   app.py        tkinter 窗口、Entry、Button、Listbox
图表层   charts.py     matplotlib 生成图片塞进 tkinter.Label
```

这个结构本身是好的。**一个真正能维护的项目，从来不是"所有代码塞一个文件"，而是按职责分好层，每层只干一件事。** 我们要复用的就是这种分层思想，换掉的是里面的技术栈。

## 哪些能原样复用

**数据层几乎是零修改的。** 建表语句、增删改查的 SQL、按分类汇总和按月份统计的查询函数，全部不动。为什么？因为它们只依赖 `sqlite3`，跟界面毫无关系。

```
# data.py —— 这层在 Qt 版里一字不改
import sqlite3

def connect():
    return sqlite3.connect("ledger.db")

def init_db():
    with connect() as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS transactions (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                date TEXT NOT NULL,
                category TEXT NOT NULL,
                amount REAL NOT NULL,
                note TEXT
            )
        """)

def add(date, category, amount, note=""):
    with connect() as conn:
        conn.execute(
            "INSERT INTO transactions(date, category, amount, note) VALUES (?, ?, ?, ?)",
            (date, category, amount, note))

def delete(tid):
    with connect() as conn:
        conn.execute("DELETE FROM transactions WHERE id = ?", (tid,))

def all_records():
    with connect() as conn:
        conn.row_factory = sqlite3.Row
        return conn.execute(
            "SELECT * FROM transactions ORDER BY date DESC").fetchall()
```

**模型层也不动**：`Category` 枚举、日期格式化这些纯逻辑函数继续用。

## 哪些必须重写

**界面层和图表层全部换掉**，这也是本章的重头戏：

| 原来（tkinter） | 现在（Qt） | 差别在哪 |
|---|---|---|
| `Listbox` 显示记录 | `QTableView` + `TransactionModel` | 记录变成"模型里的数据"，视图自动响应 |
| `Entry` + `Button` 录入 | `QFormLayout` + 信号槽 | 布局更整齐，数据校验更顺 |
| 点按钮刷新列表 | Model 通知 View 自动刷新 | 不用手动 `listbox.delete(0, END)` |
| matplotlib 图片塞 Label | `QPainter` 自绘图表 | 零依赖、矢量、随窗口缩放 |

## 重写之后能多出什么

这才是 Qt 版真正的附加值，也是这一章要逐个实现的四件事：

**1. 排序和过滤。** 点表头按金额/日期排序，下拉框选"餐饮"只看餐饮。tkinter 的 Listbox 想做这个要自己重排列表，Qt 用一个 `QSortFilterProxyModel` 挡在 Model 和 View 之间，几行搞定。

**2. 进度条单元格。** 给每个分类画一条横向进度条，长度代表该分类占总支出的比例。这是第 3 章 Delegate 的用武之地——自定义 `paint` 就能在单元格里画任意东西。

**3. 自绘图表。** 饼图、柱状图都用 `QPainter` 自己画，不依赖 matplotlib。好处是程序更轻、图表能跟着窗口缩放、样式跟界面完全统一。代价是要自己算角度、自己处理图例。

**4. 选中即操作。** 点一行高亮，按 Delete 键直接删。这背后是 `QItemSelectionModel`，比 tkinter 里"记住选中下标"优雅得多。

## 三层架构在 Qt 版里的样子

```
data.py              数据层：SQLite（不变）
   ↓ 返回 list[dict] 或 sqlite3.Row
models.py            TransactionModel：把记录变成 QAbstractTableModel
   ↓ 数据
QSortFilterProxyModel 排序/过滤（可选加一层）
   ↓
QTableView          视图 + 自定义 Delegate
   ↓ 信号
MainWindow           窗口：表单录入、按钮、图表控件、选中删除
   ↓
ChartView（QWidget）  自绘饼图 + 柱状图
```

**关键洞察：Model 是"数据层"和"界面层"之间的翻译官。** 数据层只懂 SQL 和行记录，View 只懂 `rowCount/columnCount/data` 三个方法。Model 把这两边接起来，所以数据层可以任意替换（换成 JSON 文件、换成网络接口），界面完全不用动。

## 为什么不用 matplotlib 了

matplotlib 没错，但它是一个**额外的依赖**，而且是很大的依赖。一个记账本本来 200 行能装完，带上 matplotlib 之后打包体积直接翻倍。更重要的是：matplotlib 画出来的是一张**位图**，缩放会模糊；而 `QPainter` 画的是矢量路径，放大多少倍都清晰。

**不是 matplotlib 不好，而是"合适的工具用在合适的规模上"。** 一个内嵌的小图表用 QPainter 更轻；如果是要做 3D 可视化、科学绘图、导出高清大图，那还是 matplotlib（或 PyQtGraph）更合适。这个取舍我们放到第 29 课细讲。

## 翻车现场一：把 SQL 查询写进槽函数，界面层混进数据逻辑

**症状**：`on_add` 按钮里直接写 `conn.execute("INSERT ...")`，后来想加一个"导入 CSV"功能，同样的 SQL 又要抄一遍。

**错误写法：**

```
def on_add(self):
    conn = sqlite3.connect("ledger.db")
    conn.execute("INSERT INTO transactions(...) VALUES (...)")
    conn.commit()
    # 刷新列表
    self.refresh_listbox()
```

**正确做法：数据操作统一收口在 data.py，界面只调用函数。** 这样换数据库、加缓存、加日志都只改一个地方。

## 翻车现场二：想着"Qt 版要从零开始"，把建表语句也重写一遍

**症状**：新程序建了个新表，旧数据全丢了；或者两套建表语句字段不一样，迁移起来很痛苦。

**正确做法：`init_db()` 放在程序启动时调用一次，`IF NOT EXISTS` 保证幂等。** 老数据库文件直接复用，新机器上第一次跑也能自动建表。

## 翻车现场三：先写界面再想数据结构，写到一半发现字段对不上

**症状**：录入表单有"类型（收入/支出）"字段，但数据库表里没这列，要么改表结构要么改表单，两头返工。

**正确做法：动手前先把表结构和 Model 的列定义写在纸上。** 先定 `transactions` 表有哪些列，再定 `TransactionModel.HEADERS` 有哪些列，最后才写界面。数据契约先定，界面跟着契约走。

## 翻车现场四：把图表控件和表格控件写进同一个类

**症状**：`MainWindow` 里既有表格逻辑又有绘图逻辑，500 行挤在一个类里，改图例位置要翻半天。

**正确做法：图表单独做一个 `ChartView(QWidget)` 子类，只暴露 `set_data(records)` 方法。** 主窗口只负责把数据喂给它，至于它怎么画、画不画得完，主窗口不管。

## 翻车现场五：以为 Qt 版一定比 tkinter 版快

**症状**：同样的增删操作，Qt 版感觉不到更快，反而代码量多了。

**正确理解：Qt 的优势不是"运行更快"，而是"结构更清晰、功能更完整、维护更省心"。** 排序、过滤、自定义单元格渲染、矢量图表——这些 tkinter 要做就得自己造轮子，Qt 是现成的。代码量多点是因为你在用一套正规的架构，而不是因为 Qt 臃肿。

## 小结

- 原项目四层结构（数据/模型/界面/图表）在 Qt 版里全部保留
- 数据层（SQLite）原样复用，界面层和图表层重写
- Model 是数据层与界面层的翻译官，解耦两边
- Qt 版额外获得：排序过滤、进度条单元格、自绘矢量图表、选中操作
- matplotlib 适合科学绘图，QPainter 适合内嵌小图表，看规模取舍
- 数据契约（表结构 + Model 列定义）先定，界面后写
- 图表封装成独立控件，别塞进主窗口
