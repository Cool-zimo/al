# 数据层与 Model：把数据库记录变成 Model

> 上一课定了分层，这一课干实事：写一个 `TransactionModel`，把 SQLite 的查询结果变成 `QAbstractTableModel` 能吐出去的数据。数据层还是那个数据层，Model 是翻译官。

## TransactionModel 的完整骨架

回顾第 1 章讲的"三方法"：`rowCount`、`columnCount`、`data`。加上 `headerData` 就有了完整的最小可用 Model。我们在这个骨架上叠功能：

```
from PySide6.QtCore import Qt, QAbstractTableModel, QModelIndex

from data import all_records, add as db_add, delete as db_delete


class TransactionModel(QAbstractTableModel):
    HEADERS = ["日期", "分类", "金额", "备注"]

    def __init__(self, parent=None):
        super().__init__(parent)
        self._records = []           # 每条是 sqlite3.Row 或 dict
        self.refresh()

    def rowCount(self, parent=QModelIndex()):
        return len(self._records)

    def columnCount(self, parent=QModelIndex()):
        return len(self.HEADERS)

    def data(self, index, role=Qt.ItemDataRole.DisplayRole):
        if not index.isValid():
            return None
        record = self._records[index.row()]
        col = index.column()
        if role == Qt.ItemDataRole.DisplayRole:
            if col == 0:
                return str(record["date"])
            if col == 1:
                return str(record["category"])
            if col == 2:
                return f"{record['amount']:.2f}"
            if col == 3:
                return str(record["note"] or "")
        return None

    def headerData(self, section, orientation, role=Qt.ItemDataRole.DisplayRole):
        if role == Qt.ItemDataRole.DisplayRole and orientation == Qt.Orientation.Horizontal:
            return self.HEADERS[section]
        return None
```

**注意列号的对应关系**：`col == 2` 是金额列，格式化逻辑集中在这里。第 1 章说过，View 要数据就来问 `data`，你不用操心它什么时候问、问几次。

## 接入数据层

`refresh()` 负责从数据库拉数据，用 `beginResetModel/endResetModel` 包住，让 View 知道"全变了"：

```
def refresh(self):
    self.beginResetModel()
    self._records = list(all_records())   # data.py 的查询
    self.endResetModel()
```

`all_records()` 返回的如果是 `sqlite3.Row`，就能用 `record["date"]` 字典式取值；如果返回的是 tuple，就得 `record[0]` 按下标取。两者都行，**但必须统一**——混着用是最难查的 bug。

**推荐用 `sqlite3.Row`**，因为字段名比下标 0/1/2/3 可读性强得多，改表结构时也不容易错位。

## 增删：用 beginInsertRows / beginRemoveRows 精细通知

`refresh` 是"大锤"，适合整体重载。录入一条新记录，用 `beginInsertRows/endInsertRows` 更优雅——View 只插入那一行，滚动位置、选中状态都保留：

```
def add_record(self, date, category, amount, note=""):
    db_add(date, category, amount, note)          # 先写库
    row = self.rowCount()
    self.beginInsertRows(QModelIndex(), row, row) # 告知要在末尾插一行
    self._records.append(None)                    # 占位，下面 refresh 会覆盖
    self.endInsertRows()
    self.refresh()                               # 重新拉一遍，保证顺序正确
```

**等等，这样 append + refresh 不是多此一举？** 确实。如果你的查询顺序不重要，可以直接 `self.refresh()` 一次搞定。但用 `beginInsertRows` 的正确姿势是：

```
def add_record(self, date, category, amount, note=""):
    db_add(date, category, amount, note)
    self.refresh()   # beginResetModel/endResetModel 已在 refresh 里
```

**对于本项目的"按日期倒序"展示，`refresh` 就够了。** 需要精细增删的场景是：列表很大（上万行）、你不想每次都全表重查。这种时候应该只插那一行新数据，并自己维护 `_records` 的顺序。

## 删除一行

删除要拿到"源 Model 里的真实行号"——因为 View 可能经过了 ProxyModel 的过滤/排序，View 显示的第 3 行不一定是源 Model 的第 3 行。这个坑我们第 28 课专门讲，这里先给源 Model 的删除：

```
def remove_row(self, row):
    if 0 <= row < len(self._records):
        tid = self._records[row]["id"]
        self.beginRemoveRows(QModelIndex(), row, row)
        del self._records[row]
        self.endRemoveRows()
        db_delete(tid)           # 后删库，避免异常时 Model 已不一致
```

**顺序很关键：先改 Model 内部数据，再删库。** 反过来如果删库抛异常，Model 已经说"我没了"，界面就和实际数据对不上。更稳的做法是把 `db_delete` 包在 try 里，失败时把数据加回去——不过对 SQLite 的本地小项目，这个复杂度通常不必要。

## 多角色：让金额列右对齐、负数标红

第 1 章讲过 `data()` 可以处理多个角色。记账本里这个特别实用：

```
def data(self, index, role=Qt.ItemDataRole.DisplayRole):
    if not index.isValid():
        return None
    record = self._records[index.row()]
    col = index.column()

    if role == Qt.ItemDataRole.DisplayRole:
        # ... 省略各列取值
        if col == 2:
            return f"{record['amount']:.2f}"

    if role == Qt.ItemDataRole.TextAlignmentRole and col == 2:
        return Qt.AlignmentFlag.AlignRight | Qt.AlignmentFlag.AlignVCenter

    if role == Qt.ItemDataRole.ForegroundRole and col == 2:
        if record["amount"] < 0:
            return QBrush(QColor(200, 0, 0))      # 支出标红

    return None
```

记得把 `from PySide6.QtGui import QBrush, QColor` 加到导入里。**一个 `data()` 方法处理五六个角色是常态**，别想着去子类化一百个角色类——直接 `if role ==` 堆条件就行。

## 给图表提供汇总数据

Model 是最适合放"衍生数据"的地方。图表要的饼图和柱状图数据，可以从 Model 里算出来：

```
def total_by_category(self):
    """返回 {分类: 总额} 的字典"""
    result = {}
    for r in self._records:
        cat = r["category"]
        result[cat] = result.get(cat, 0.0) + r["amount"]
    return result

def total_by_month(self):
    """返回 {"2026-09": 总额, ...}"""
    result = {}
    for r in self._records:
        month = str(r["date"])[:7]
        result[month] = result.get(month, 0.0) + r["amount"]
    return result
```

**为什么放 Model 里而不是 View 里？** 因为这两份汇总是"数据的另一种形态"，跟数据本身绑定。谁要谁调，View 不用自己重新遍历一遍。

## 翻车现场一：忘了 beginResetModel / endResetModel，界面停在旧数据

**症状**：`add_record` 里直接 `self._records.append(...)` 然后期望表格自动出现新行，结果什么都没变。

**错误写法：**

```
def add_record(self, date, category, amount, note=""):
    db_add(date, category, amount, note)
    self._records = list(all_records())   # View 不知道变了
```

**正确写法：**

```
def refresh(self):
    self.beginResetModel()
    self._records = list(all_records())
    self.endResetModel()
```

## 翻车现场二：插入行时 beginInsertRows 的起止索引写错

**症状**：程序崩溃报 `ASSERT: "last >= first"` 或界面插入了多行/错位。

**错误写法：**

```
self.beginInsertRows(QModelIndex(), row, row + 1)   # 只在 row 处插一行，不是两行
```

**正确写法：**

```
self.beginInsertRows(QModelIndex(), row, row)        # first == last 表示插 1 行
```

`beginInsertRows(parent, first, last)` 的 last 是闭区间。插 1 行就写 `row, row`；插 3 行写 `row, row + 2`。

## 翻车现场三：data() 里忘记 return None，其他角色全串味

**症状**：除了 DisplayRole 以外的角色都返回了字符串，表格对齐、颜色全失效，还偶发崩溃。

**错误写法：**

```
def data(self, index, role):
    if role == Qt.ItemDataRole.DisplayRole:
        return str(self._records[index.row()][index.column()])
    # 走到这里返回了字符串 ""，Qt 把它当成了某个角色的值
    return ""
```

**正确写法：**

```
def data(self, index, role):
    if role == Qt.ItemDataRole.DisplayRole:
        return ...
    # 其他角色一律 None，表示"我不管这个角色"
    return None
```

**`return None` 和 `return ""` 的差别是致命的。** None 告诉 View"这个角色我没有值，你用默认"；空字符串会被当成"我有值，值是空"，Qt 就会真的画一个空的东西上去，各种怪事随之而来。

## 翻车现场四：用 tuple 取值却在 data 里当下标混用

**症状**：`all_records()` 返回 tuple，你在 data 里既写 `record[2]` 又写 `record["amount"]`，一半能跑一半 KeyError。

**正确做法：统一。** 要么让 `all_records()` 返回 `sqlite3.Row`（推荐），要么全用下标。不要赌自己记得哪一列是金额。

## 翻车现场五：把 db_add 的异常吞掉，界面以为成功了

**症状**：录入表单点了没反应，数据库里也没有。一查发现日期格式不对 SQL 报错，但异常被某层 `except: pass` 吃掉了。

**正确写法：异常要往上传到界面层，让界面给提示。** Model 层不弹窗（Model 不该知道有界面），而是让异常抛出，由调用它的槽函数捕获并显示 `QMessageBox.warning`。

## 翻车现场六：Model 持有数据库连接不关闭

**症状**：程序跑久了报"too many open connections"，或者退出时数据库锁住。

**正确做法：用 `with connect() as conn` 上下文管理器，每次操作用完即关。** 别把 `conn` 存成 `self._conn` 长期持有——SQLite 的写锁是连接级别的，一个长连接会卡住所有写入。

## 小结

- TransactionModel 继承 QAbstractTableModel，核心是 rowCount/columnCount/data/headerData
- data() 用 if role == 分发，处理多角色（对齐、颜色、显示格式）
- 整体刷新用 beginResetModel/endResetModel，精细增删用 beginInsertRows/beginRemoveRows
- 插入行的 first/last 是闭区间，插 1 行写 `row, row`
- 其他角色不处理时 return None，绝不能是空字符串
- 汇总数据（按分类、按月）放在 Model 里最合适
- 数据库操作统一用上下文管理器，别长期持有连接
