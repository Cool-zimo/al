# 界面与交互：排序过滤、录入与选中删除

> Model 写好了，这一课把它接到视图上。重点是两个：用 `QSortFilterProxyModel` 做排序和分类过滤，用 `QItemSelectionModel` 实现"点选即删"。

## QSortFilterProxyModel 是夹在中间的一层

它的位置很固定，永远是"源 Model → Proxy → View"：

```
TransactionModel（源）
       ↓ setSourceModel
QSortFilterProxyModel（过滤 + 排序）
       ↓ setModel
QTableView
```

**ProxyModel 不是数据的第二份拷贝，它只是一个"视图的视图"。** 源 Model 数据没变，Proxy 只是决定"哪些行显示出来、按什么顺序排"。这也意味着：删数据时，你要删的是**源 Model 里的那一行**，而不是 Proxy 显示的那一行。

## 分类过滤：重写 filterAcceptsRow

`QSortFilterProxyModel` 默认能按字符串匹配某一列。我们要"下拉选分类，表格只显示该分类"，需要自定义过滤规则：

```
from PySide6.QtCore import QSortFilterProxyModel, Qt

class CategoryFilterProxy(QSortFilterProxyModel):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._category = ""                      # 空字符串 = 全部

    def set_category(self, category):
        self._category = category
        self.invalidateFilter()                  # 告诉 Qt 重新过滤

    def filterAcceptsRow(self, source_row, source_parent):
        if not self._category:
            return True                          # 全部
        model = self.sourceModel()
        idx = model.index(source_row, 1, source_parent)   # 分类是第 1 列
        return model.data(idx) == self._category
```

**`invalidateFilter()` 是关键。** 你改了 `_category` 之后必须调用它，否则 Proxy 还记着旧的过滤结果，界面不会变。`set_category` 这个方法是我们自己加的 API，外面调用它而不是去碰 Proxy 内部。

## 排序：重写 lessThan 或设置 sortRole

让金额列点表头能排序，最省事的方式是给金额列一个"可比较的值"作为 `UserRole`，然后告诉 Proxy 用这个角色排序：

```
from PySide6.QtCore import Qt

# 在 TransactionModel.data 里加一个角色
def data(self, index, role=Qt.ItemDataRole.DisplayRole):
    ...
    if role == Qt.ItemDataRole.UserRole and index.column() == 2:
        return self._records[index.row()]["amount"]   # 返回 float，可直接比大小
```

然后在主窗口里启用排序：

```
self.proxy = CategoryFilterProxy(self)
self.proxy.setSourceModel(self.model)
self.table.setModel(self.proxy)
self.table.setSortingEnabled(True)
self.proxy.setSortRole(Qt.ItemDataRole.UserRole)
```

**为什么不能直接按显示字符串排序？** 因为显示的是 `"38.50"` 这种字符串，按字符串比 `"9.00"` 会大于 `"38.50"`（首字符 '9' > '3'）。用 UserRole 返回 float，数值排序就对了。

## 选中删除：QItemSelectionModel

`QTableView` 自带一个 `selectionModel()`，它就是 `QItemSelectionModel`。你要拿到"用户选中的行"，问它就行：

```
def on_delete(self):
    sel = self.table.selectionModel()
    indexes = sel.selectedRows()          # 返回 Proxy 视角下的 QModelIndex 列表
    if not indexes:
        QMessageBox.information(self, "提示", "请先选中一行")
        return

    # 映射回源 Model 的行号！这一步不能省
    source_rows = []
    for idx in indexes:
        source_idx = self.proxy.mapToSource(idx)
        source_rows.append(source_idx.row())

    for row in sorted(source_rows, reverse=True):   # 从后往前删
        self.model.remove_row(row)

    sel.clearSelection()
```

**`mapToSource` 是这一节最容易错的地方。** Proxy 做了过滤/排序之后，Proxy 的第 0 行可能不是源 Model 的第 0 行。直接用 Proxy 的 index 去源 Model 删，删错行是小，越界崩溃是大。

## 为什么要从后往前删

假设选中了源 Model 的第 2、5 行。如果你先删第 2 行，原来的第 5 行就变成第 4 行了，再删"第 5 行"就删错了。反过来从大到小删，前面删掉的行不影响后面待删的下标：

```
rows = [2, 5]
for r in sorted(rows, reverse=True):   # [5, 2]
    self.model.remove_row(r)           # 先删 5（不影响 2），再删 2
```

**`sorted(..., reverse=True)` 这一行不是炫技，是正确性。** 记住这条规则：批量按索引删东西，永远从后往前。

## 翻车现场一：删除时用 Proxy 的 index 直接去源 Model 删

**症状**：筛选"餐饮"之后删一行，结果删掉了"交通"的记录。筛选状态下表格第 0 行对应的是源数据的第 3 行，直接用 0 去删就删错了。

**错误写法：**

```
idx = self.table.selectionModel().currentIndex()
self.model.remove_row(idx.row())          # idx 是 Proxy 的视角
```

**正确写法：**

```
idx = self.table.selectionModel().currentIndex()
source_idx = self.proxy.mapToSource(idx)
self.model.remove_row(source_idx.row())
```

## 翻车现场二：忘了 invalidateFilter，下拉框选了没反应

**症状**：选"餐饮"，表格一动不动；选回"全部"也不变。

**原因**：只改了 `_category` 成员变量，没通知 Proxy 重新过滤。

**正确写法：**

```
def set_category(self, category):
    self._category = category
    self.invalidateFilter()              # 必须有
```

## 翻车现场三：金额按字符串排序，9.00 排到了 38.50 后面

**症状**：点表头排序后，金额列显示 `"9.00"` 排在 `"38.50"` 后面（字符串字典序 9 > 3）。

**正确写法：给金额列提供 UserRole 返回 float，并 `proxy.setSortRole(UserRole)`。**

## 翻车现场四：currentIndex 和 selectedRows 混用

**症状**：多选之后只删了一行；或者没选中时 `currentIndex()` 返回无效 index，`.row()` 得到莫名其妙的值。

**正确写法：删除操作用 `selectedRows()` 拿所有选中行；单条操作才用 `currentIndex()`，且要先 `isValid()` 判断。**

## 翻车现场五：从前向后删，删串行了

**症状**：选了第 2、5 行，结果第 2、6 行被删掉。

**正确写法：从后往前删，用 `sorted(rows, reverse=True)`。**

## 翻车现场六：删除后没有 clearSelection，选中状态残留

**症状**：删完一行，刚才那行的位置还留着蓝色高亮，但实际选中已经悬空，再按 Delete 报越界。

**正确写法：删除循环结束后调用 `selectionModel().clearSelection()`。**

## 翻车现场七：setSortingEnabled(True) 之后表头点击没反应

**症状**：表头能点，但数据不排序。

**原因**：`sortRole` 没设，或者源 Model 的 `data()` 里没处理 UserRole。**两个都要有：Proxy 要知道按哪个角色比，Model 要能给出这个角色的值。**

## 小结

- ProxyModel 是源 Model 与 View 之间的中间层，不存数据副本
- 自定义过滤重写 filterAcceptsRow，改条件后调 invalidateFilter
- 数值排序用 UserRole 返回可比较的值 + setSortRole
- 删除前必须用 mapToSource 把 Proxy 坐标转回源坐标
- 批量删除从后往前，用 sorted(rows, reverse=True)
- 删除后 clearSelection 清理选中状态
- 筛选状态下 Proxy 的行号与源 Model 完全不对应，别混用
