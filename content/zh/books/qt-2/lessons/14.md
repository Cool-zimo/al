# 事件处理：mousePressEvent / keyPressEvent，event 与 eventFilter 的区别

> 自绘控件不会自动响应点击，你要自己处理鼠标和键盘事件。这一课讲事件分发机制，以及 event() 和事件过滤器 eventFilter 的区别。

## 事件机制：谁发给谁

**Qt 是事件驱动的。用户的每次鼠标点击、按键、窗口缩放，都变成一个个 QEvent 对象，由 Qt 的事件循环分发给对应的 widget。**

**widget 收到事件后，会调用对应的 handler：**

| 事件 | handler |
|---|---|
| 鼠标按下 | `mousePressEvent(event)` |
| 鼠标释放 | `mouseReleaseEvent(event)` |
| 鼠标移动 | `mouseMoveEvent(event)` |
| 鼠标双击 | `mouseDoubleClickEvent(event)` |
| 键盘按下 | `keyPressEvent(event)` |
| 键盘释放 | `keyReleaseEvent(event)` |
| 滚轮 | `wheelEvent(event)` |
| 进入/离开 | `enterEvent(event)` / `leaveEvent(event)` |
| 绘制 | `paintEvent(event)` |
| 尺寸变化 | `resizeEvent(event)` |

**要处理哪个事件，就重写哪个方法。**

## 鼠标事件基础

```
from PySide6.QtCore import Qt
from PySide6.QtWidgets import QWidget, QApplication

class ClickWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setMinimumSize(200, 200)

    def mousePressEvent(self, event):
        if event.button() == Qt.LeftButton:
            pos = event.position().toPoint()       # 点击位置（相对本 widget）
            print(f"左键点击：({pos.x()}, {pos.y()})")
        elif event.button() == Qt.RightButton:
            print("右键点击")
        super().mousePressEvent(event)              # 交给父类处理（保持默认行为）

    def mouseMoveEvent(self, event):
        pos = event.position().toPoint()
        print(f"鼠标移动到：({pos.x()}, {pos.y()})")
        super().mouseMoveEvent(event)

    def keyPressEvent(self, event):
        if event.key() == Qt.Key_Escape:
            print("按了 ESC")
        elif event.key() == Qt.Key_A:
            print("按了 A")
        super().keyPressEvent(event)
```

**`event.position().toPoint()` 拿到的是相对本 widget 左上角的坐标。** 坐标原点是 widget 自己的左上角，不是屏幕。

## 翻车现场一：忘了调 super()，父类的默认行为丢了

**症状：重写了 mousePressEvent 做自己的事，结果这个 widget 原来的点击行为（比如 QPushButton 的点击高亮、QLineEdit 的光标）全没了。**

```
class MyButton(QPushButton):
    def mousePressEvent(self, event):
        print("被点击了")
        # ❌ 没调 super()，按钮的点击高亮、click 信号都不会触发
```

**原因：父类的 mousePressEvent 里实现了点击高亮、状态切换、click 信号触发等逻辑。你不调 super，这些全丢了。**

**✅ 正确做法：做完你的事，调 super()。**

```
def mousePressEvent(self, event):
    if event.button() == Qt.LeftButton:
        print("自定义处理")
    super().mousePressEvent(event)     # ✅ 交给父类
```

**例外：你要**完全**接管这个事件、不让父类处理，才故意不调 super()。但这种场景很少。**

## 翻车现场二：mouseMoveEvent 只在按下时才触发

**症状：想做"鼠标悬停时高亮"，结果 mouseMoveEvent 只在按住左键拖动时才触发，单纯移动鼠标不触发。

```
def mouseMoveEvent(self, event):
    print("移动")      # 只在按下拖动时打印
```

**原因：默认情况下，widget 只在有鼠标按钮按下时才持续收到 mouseMove 事件。这是性能优化。**

**✅ 正确做法：调用 `setMouseTracking(True)`。**

```
class HoverWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setMouseTracking(True)        # ✅ 不按键也能收到 mouseMove

    def mouseMoveEvent(self, event):
        pos = event.position().toPoint()
        print(f"悬停：({pos.x()}, {pos.y()})")
        super().mouseMoveEvent(event)
```

## 翻车现场三：键盘事件收不到，焦点不在自己身上

**症状：重写了 keyPressEvent，运行后按键盘完全没反应。**

```
class KeyWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        # ❌ 没设焦点策略，widget 拿不到键盘焦点

    def keyPressEvent(self, event):
        print("按键：", event.key())
```

**原因：键盘事件只会发给当前拥有焦点的 widget。一个 QWidget 默认是 `NoFocus`，即不参与焦点，所以键盘事件根本不会到它手上。**

**✅ 正确做法：设置 focusPolicy。**

```
class KeyWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.setFocusPolicy(Qt.StrongFocus)   # ✅ 可获取焦点

    def keyPressEvent(self, event):
        if event.key() == Qt.Key_Left:
            print("左")
        elif event.key() == Qt.Key_Right:
            print("右")
        super().keyPressEvent(event)
```

**`Qt.StrongFocus` 表示可以通过点击和 Tab 键获取焦点。`Qt.ClickFocus` 表示只能通过点击获取。**

## event()：事件的"总入口"

**event(event) 是所有事件到达 handler 之前的"总入口"。它的默认实现根据事件类型分发给 mousePressEvent 等具体 handler。**

```
def event(self, event):
    if event.type() == QEvent.KeyPress:
        key_event = QKeyEvent(event)
        if key_event.key() == Qt.Key_F5:
            print("拦截 F5，不放给 keyPressEvent")
            return True          # True 表示"我处理了，不用再分发"
    return super().event(event)  # 其他事件照常分发
```

**返回 True 表示"事件已被处理，停止分发"；返回 False 或调 super() 表示"继续走正常分发流程"。**

**event() 适合做"拦截"和"统一处理多种事件"的场景。** 比如你不想重写五个方法，只想在某个事件到来时做点什么，就 override event()。

## 事件过滤器 eventFilter：不子类化也能监听别人的事件

**eventFilter 是最常被问到的概念。它让你在不子类化的情况下，监听另一个 widget 的事件。**

```
class Watcher(QObject):
    def eventFilter(self, watched, event):
        if event.type() == QEvent.MouseButtonPress:
            print(f"{watched.objectName()} 被点击了")
            return False        # False = 不拦截，让事件继续传递
        return False

watcher = Watcher()
button = QPushButton("按钮")
button.setObjectName("我的按钮")
button.installEventFilter(watcher)     # 给 button 装过滤器
```

**三步：① 定义一个 QObject 子类，重写 eventFilter；② 对目标 widget 调 installEventFilter；③ eventFilter 返回 True 表示拦截、False 表示放行。**

## event() 与 eventFilter() 的区别

**这是本课的核心辨析点：**

| | event() | eventFilter() |
|---|---|---|
| 监听谁 | 监听**自己**的事件 | 监听**别人**的事件 |
| 前置条件 | 需要子类化这个 widget | 不需要子类化，任意 QObject 都能当过滤器 |
| 用途 | 在自己 widget 内拦截/预处理 | 在不改别人代码的情况下加监听 |
| 返回值 | True=已处理，停止分发 | True=拦截（目标收不到），False=放行 |

**event() 是"我自己的门"，eventFilter 是"装在我身上的监控摄像头，看别人家的门"。**

## 翻车现场四：eventFilter 返回 True 但忘了处理，事件被吞了

**症状：装了 eventFilter 想做日志记录，结果按钮点击后不触发了——click 信号没发，高亮也没了。**

```
class Logger(QObject):
    def eventFilter(self, watched, event):
        if event.type() == QEvent.MouseButtonPress:
            print("点击了")
            return True         # ❌ 返回 True 且没做实际处理，事件被吞
        return False
```

**原因：返回 True 表示"事件已处理，不要再分发给目标的 handler 了"。** 你只打印了一句，却告诉 Qt"处理完了"，目标的 mousePressEvent 根本不会被调用。

**✅ 正确做法：只做观察就返回 False（放行）。**

```
def eventFilter(self, watched, event):
    if event.type() == QEvent.MouseButtonPress:
        print("点击了")
        return False            # ✅ 放行
    return False
```

**拦截（返回 True）只在你确实要"替目标处理这个事件"时才用，而且通常要自己完成该做的事。**

## 翻车现场五：过滤器对象被垃圾回收，过滤悄悄失效

**症状：程序运行一段时间后，eventFilter 不再被调用，但代码没改。

```
def setup(widget):
    watcher = Watcher()
    widget.installEventFilter(watcher)
    # ❌ watcher 是局部变量，函数返回后可能被 GC
```

**原因：installEventFilter 只是存了个指针，不增加引用计数。Python 的 GC 把 watcher 回收了，过滤就失效了。**

**✅ 正确做法：保持引用，比如挂成属性。**

```
self._watcher = Watcher()
widget.installEventFilter(self._watcher)
```

## 小结

- 事件机制：QEvent 由事件循环分发，widget 重写对应 handler 处理
- 鼠标事件用 event.position().toPoint() 拿相对坐标
- 重写 handler 一般要调 super()，否则父类默认行为丢失
- 鼠标悬停跟踪需 setMouseTracking(True)
- 键盘事件要先 setFocusPolicy 拿到焦点
- event() 是总入口，用于拦截和统一预处理，返回 True 停止分发
- eventFilter 监听别人的事件，无需子类化；返回 False 放行，True 拦截
- 过滤器对象要保持引用，防止被 GC
