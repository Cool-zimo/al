# 为什么要自定义控件：现有控件拼不出你要的样子

> QPushButton、QLabel、QProgressBar 已经很好用了。但总有一天 PM 指着设计稿说："我要这个圆角的、带渐变的、点击有水波纹的按钮。"这时候你会发现，拼控件是拼不出来的。

## 现成控件能拼到什么程度

**Qt 的控件库覆盖了 90% 的日常需求。按钮、输入框、表格、菜单、滑块、进度条、选项卡……能用拼的就用拼的，这是最省事的正解。**

```
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QHBoxLayout, QLineEdit

app = QApplication([])

win = QWidget()
search = QLineEdit()
search.setPlaceholderText("搜索...")
btn = QPushButton("搜索")

layout = QHBoxLayout(win)
layout.addWidget(search)
layout.addWidget(btn)
win.show()
app.exec()
```

**用 QSS 能改颜色、圆角、边框、渐变、状态。前面《Qt 进阶 1》讲过，这里不再展开。** QSS 能解决"样式"问题，但解决不了"行为"问题。

## QSS 的边界在哪

**QSS 能改的是"已经存在的那些部件的样子"：背景、边框、圆角、字体、padding。它不能：**

- 画一个环形进度条（进度条只能是横条）
- 让按钮点击出现水波纹动画
- 画一个仪表盘、速度表、波形图
- 做一个可拖拽的旋钮、转盘
- 做一个聊天气泡（气泡尾巴、三角形指向）
- 做一个星星评分控件

**这些的共同特征：它们的几何形状是"计算出来"的，不是"摆出来"的。** 环形进度条的角度随数值变，水波纹的中心随点击位置变——这些都是要"算"的，不是"设"的。

## 自定义控件的三种姿势

| 姿势 | 怎么搞 | 适用场景 |
|---|---|---|
| 继承现有控件扩展 | `class MyButton(QPushButton)`，加属性、加信号、重写几个方法 | 现有控件 90% 满足，只差一点行为 |
| 完全自绘（继承 QWidget） | 重写 paintEvent，用 QPainter 自己画 | 全新外观，市面上没有的控件 |
| 组合成复合控件 | 把多个子控件装进一个 QWidget + 布局 | 一个"卡片"里要放图、标题、按钮 |

**三种姿势从省事到费事递增。** 能组合就组合（第 12 课会讲这不是"自定义"而是"封装"），差一点就继承扩展，完全拼不出才自绘。

## 翻车现场一：用一堆 QLabel 拼一个仪表盘，性能炸了

**症状：为了画一个仪表盘，用了 100 个 QLabel 排成弧形，每个显示一个小刻度。窗口一多，内存和 CPU 都飙高。**

```
# ❌ 100 个 QLabel 画刻度
for angle in range(0, 181, 2):
    label = QLabel("|")
    label.setGeometry(...)     # 每个都要布局计算
    label.show()
# 100 个 widget 对象，每个都有自己的窗口句柄和事件处理
```

**原因：每个 QWidget 子类都是一个真正的窗口对象，有句柄、有事件队列、要参与布局。** 数量一多，创建和绘制都变贵。

**✅ 正确做法：一个 QWidget，重写 paintEvent，用 QPainter 循环画 100 条线。**

```
class Gauge(QWidget):
    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setRenderHint(QPainter.Antialiasing)
        cx, cy = self.width() // 2, self.height() // 2
        for angle in range(0, 181, 2):
            rad = math.radians(angle)
            x1 = cx + 80 * math.cos(rad)
            y1 = cy - 80 * math.sin(rad)
            x2 = cx + 90 * math.cos(rad)
            y2 = cy - 90 * math.sin(rad)
            painter.drawLine(int(x1), int(y1), int(x2), int(y2))
        painter.end()
```

**一个 widget，一次 paintEvent，画一百条线——代价远低于一百个 widget。** 这是"自绘"的核心价值：把 N 个对象变成 1 个对象 + 一个循环。

## 翻车现场二：为了改一个属性，复制了整个 Qt 控件源码

**症状：只想让 QPushButton 多一个"倒计时自动禁用"的功能，于是复制了 QPushButton 的源码（上千行）改，结果 bug 一堆。**

```
# ❌ 错误思路：复制 QPushButton 实现，改它
class MyButton(QPushButton):
    def __init__(self, text, parent=None):
        super().__init__(text, parent)
        # ... 复制了一堆私有方法 ...
```

**原因：Qt 控件不是让你抄的，是让你继承的。** 它的私有实现你抄不全，也抄不对。

**✅ 正确做法：继承 + 组合。**

```
from PySide6.QtCore import QTimer

class CountdownButton(QPushButton):
    def __init__(self, text, seconds=10, parent=None):
        super().__init__(text, parent)
        self._seconds = seconds
        self._remaining = seconds
        self._timer = QTimer(self)
        self._timer.timeout.connect(self._tick)

    def start_countdown(self):
        self._remaining = self._seconds
        self.setEnabled(False)
        self._timer.start(1000)

    def _tick(self):
        self._remaining -= 1
        self.setText(f"请等待 {self._remaining}s")
        if self._remaining <= 0:
            self._timer.stop()
            self.setEnabled(True)
            self.setText("可以点击了")
```

**继承 QPushButton，复用它全部已有行为（点击、样式、焦点），只加你要的 countdown 逻辑。** 这才是面向对象该有的用法。

## 翻车现场三：把自绘逻辑写在 mousePressEvent 里直接画

**症状：想在点击位置画一个红点，于是在 mousePressEvent 里 new 一个 QPainter 画。第一次点了有反应，第二次点之前的就没了，而且偶尔报错。**

```
def mousePressEvent(self, event):
    painter = QPainter(self)
    painter.setPen(Qt.red)
    painter.drawPoint(event.position().toPoint())   # ❌ 直接在事件里画
    painter.end()
```

**原因：paintEvent 之外的绘制不会持久化。Qt 随时可能重绘这个 widget（被遮挡后恢复、窗口缩放、调用 update()），你画的红点就没了。而且 paint 设备状态也可能不对。**

**✅ 正确做法：在 mousePressEvent 里记录数据，然后调用 update() 触发 paintEvent，在 paintEvent 里画。**

```
class DotWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._points = []          # 记录要画的点

    def mousePressEvent(self, event):
        self._points.append(event.position().toPoint())
        self.update()              # 标记需要重绘，Qt 会调用 paintEvent

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setPen(Qt.red)
        for p in self._points:
            painter.drawPoint(p)
        painter.end()
```

**这是 Qt 绘制的铁律：永远在 paintEvent 里画，事件处理函数里只改数据 + 调 update()。**

## 三种姿势怎么选

**判断流程：**

```
需求来了
  ├─ 能用 QSS 改样式搞定？→ 用 QSS
  ├─ 现有控件 90% 满足，只差一点行为？→ 继承扩展（第 12 课）
  ├─ 形状是"算"出来的？→ 完全自绘（第 13 课）
  └─ 多个控件要打包成一个整体？→ 组合成复合控件（第 12 课）
```

**本课是第 3 章的序章，后面三课分别是：继承扩展（12）、完全自绘（13）、事件处理（14），最后第 15 课用一个圆形进度指示器把三课串起来。**

## 小结

- 现成控件 + QSS 能解决 90% 需求，优先用
- QSS 只能改样式，改不了几何形状和行为
- 三种姿势：继承扩展、完全自绘、组合复合控件，从省事到费事
- 大量重复子控件要用自绘代替，一个 widget 画 N 条线远快于 N 个 widget
- 不要复制 Qt 控件源码，继承才是正解
- 永远在 paintEvent 里画，事件处理里只改数据 + update()
