# QSqlQuery 与手写 SQL：参数化查询、遍历结果与事务

> 当你需要联表、聚合、复杂条件时，Model 不够用了。QSqlQuery 让你直接写 SQL，但要守两条铁律：**永远参数化、永远检查 exec 返回值**。

## 一次完整的查询

```
from PySide6.QtSql import QSqlQuery, QSqlDatabase

def list_books():
    q = QSqlQuery()
    ok = q.exec("SELECT id, title, price FROM books ORDER BY price DESC")
    if not ok:
        print("查询失败:", q.lastError().text())
        return

    while q.next():
        book_id = q.value(0)        # 按列下标取值
        title = q.value("title")    # 按列名取值（更可读）
        price = q.value("price")
        print(f"[{book_id}] {title} - ¥{price}")
```

`q.next()` 把内部指针移到下一行，返回 False 表示遍历结束（没有异常，也不会抛 StopIteration）。

## 参数化查询：防止 SQL 注入

**千万不要用 f-string 拼 SQL 字符串**，尤其当内容来自用户输入时。

```
# 错误写法（危险！）
name = input("书名: ")
q.exec(f"SELECT * FROM books WHERE title = '{name}'")   # SQL 注入漏洞

# 正确写法：位置占位符
q = QSqlQuery()
q.prepare("SELECT * FROM books WHERE price BETWEEN ? AND ? AND author = ?")
q.addBindValue(20.0)            # 第 1 个 ?
q.addBindValue(100.0)          # 第 2 个 ?
q.addBindValue("鲁迅")          # 第 3 个 ?
q.exec()

# 或者用命名占位符（Qt 支持 :name 形式）
q.prepare("SELECT * FROM books WHERE author = :author")
q.bindValue(":author", "鲁迅")
q.exec()
```

参数化之后，即使用户输入 `'; DROP TABLE books; --`，也只会当成普通字符串字面量，不会被执行。

## 增删改

```
q = QSqlQuery()
q.prepare("INSERT INTO books (title, author, price) VALUES (?, ?, ?)")
q.addBindValue("Qt 编程入门")
q.addBindValue("张三")
q.addBindValue(59.9)
if not q.exec():
    print("插入失败:", q.lastError().text())

# 更新
q.prepare("UPDATE books SET price = ? WHERE id = ?")
q.addBindValue(69.9)
q.addBindValue(1)
q.exec()

# 删除
q.prepare("DELETE FROM books WHERE price < ?")
q.addBindValue(10.0)
q.exec()
```

## 事务：要么全成，要么全不成

SQLite 默认每条语句一个事务。多条语句要"一起成功或一起失败"，手动控制：

```
db = QSqlDatabase.database()     # 取默认连接
db.transaction()                 # 开始事务

q1 = QSqlQuery()
q2 = QSqlQuery()
ok1 = q1.exec("UPDATE accounts SET balance = balance - 100 WHERE id = 1")
ok2 = q2.exec("UPDATE accounts SET balance = balance + 100 WHERE id = 2")

if ok1 and ok2:
    db.commit()
    print("转账成功")
else:
    db.rollback()
    print("转账失败，已回滚")
```

## 翻车现场一：用 f-string 拼 SQL，遇到单引号就炸

**症状：书名里带个撇号，程序报 `near "s": syntax error`。**

**错误写法：**

```
title = "O'Reilly 的书"
q.exec(f"INSERT INTO books (title) VALUES ('{title}')")
# SQL: INSERT INTO books (title) VALUES ('O'Reilly 的书')  ← 语法错误
```

**正确做法：用参数化，让 Qt 负责转义。**

```
q.prepare("INSERT INTO books (title) VALUES (?)")
q.addBindValue(title)
q.exec()
```

## 翻车现场二：exec 失败没检查，程序"假成功"

**症状：SQL 写错了（比如表名拼错），程序不报错，但数据就是没插进去。**

**错误写法：**

```
q.exec("SELCT * FROM books")    # 少了个 E
# 没有检查返回值，静默失败
```

**正确做法：每次 exec 后检查返回值，并打 lastError。**

```
if not q.exec(sql):
    print("SQL 执行失败:", q.lastError().text())
```

## 翻车现场三：遍历结果时用了错误的数据类型

**症状：取出的 price 是个字符串 `"59.9"`，做加法时变成字符串拼接。**

**原因**：Qt 默认把数据返回为 `QVariant`，`q.value()` 返回的对象可能是任意类型。SQLite 不严格区分 REAL 和 TEXT，存入时是什么就返回什么。

**正确做法：显式转换。**

```
price = float(q.value("price"))     # 转成 float 再计算
count = int(q.value(0))             # 转成 int
```

## 翻车现场四：事务里混用了不同连接，commit 没生效

**症状：在一个连接里 `db.transaction()`，却用另一个连接对象执行语句，结果每条还是独立事务。

**原因**：事务是**连接级别**的。A 连接开事务，B 连接执行的语句不在 A 的事务里。

**正确做法：确保 transaction / exec / commit 都用同一个 QSqlDatabase 连接。**

## 翻车现场五：查询没 next() 就取值，拿到空

**症状：查询返回了结果，但 `q.value(0)` 拿到 None。

**错误写法：**

```
q.exec("SELECT COUNT(*) FROM books")
count = q.value(0)          # ← 没 next()，指针在"第一行之前"
```

**正确写法：**

```
q.exec("SELECT COUNT(*) FROM books")
if q.next():
    count = q.value(0)
```

## 小结

- QSqlQuery 用于手写 SQL，适合复杂查询
- 遍历用 `while q.next(): q.value(idx 或列名)`
- 永远用 prepare + addBindValue / bindValue 参数化，杜绝 SQL 注入
- 每次 exec 检查返回值并查 lastError
- 事务：db.transaction / commit / rollback，连接级别
- 取出的值显式转型（float/int）
- 取值前必须先 next()
