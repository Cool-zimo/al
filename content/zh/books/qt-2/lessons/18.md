# 坐标变换：translate、rotate、scale 与状态栈

> 想画一个绕中心旋转的指针、一个重复的花纹、一个缩放到任意尺寸的分形？靠算坐标太痛苦了。QPainter 内置的坐标变换 + 状态栈，能让"局部画布"随你摆布。

## 四个变换方法

| 方法 | 作用 | 类比 |
|---|---|---|
| translate(dx, dy) | 平移原点 | 把纸往右往下挪 |
| rotate(angle) | 绕原点旋转（角度制，正值为顺时针） | 把纸顺时针转 angle 度 |
| scale(sx, sy) | 缩放 | 把纸拉伸/压缩 |
| shear(sh, sv) | 错切 | 把纸推斜 |

**关键点：变换是叠加的，且按代码顺序从右往左作用于坐标。**

```
def paintEvent(self, event):
    p = QPainter(self)
    p.setRenderHint(QPainter.RenderHint.Antialiasing)

    p.translate(160, 120)     # 原点移到窗口中心
    p.rotate(30)              # 再绕新原点顺时针转 30°
    p.scale(1.5, 1.5)         # 再放大 1.5 倍

    p.setBrush(QBrush(Qt.GlobalColor.blue))
    p.drawRect(0, 0, 40, 40)  # 这个矩形现在"飞"到旋转+放大后的位置
```

矩形本该画在左上角，但因为坐标系已经被平移+旋转+缩放，它出现在了窗口中心、倾斜 30°、放大 1.5 倍的位置。

## 状态栈：save() 与 restore() 必须配对

每次 `save()` 把当前画笔、画刷、变换矩阵等状态压栈，`restore()` 弹栈恢复。这是唯一安全的"隔离变换"方式。

```
def paintEvent(self, event):
    p = QPainter(self)
    p.setRenderHint(QPainter.RenderHint.Antialiasing)

    # 画一个未变换的参考方块
    p.setBrush(QBrush(Qt.GlobalColor.gray))
    p.drawRect(10, 10, 30, 30)

    p.save()                        # ① 存档
    p.translate(150, 120)
    p.rotate(45)
    p.setBrush(QBrush(Qt.GlobalColor.red))
    p.drawRect(-20, -20, 40, 40)   # 绕自身中心转 45°
    p.restore()                     # ② 读档，变换和颜色回到存档时

    # 这里的坐标系已经恢复正常，可以放心继续画
    p.setBrush(QBrush(Qt.GlobalColor.gray))
    p.drawRect(60, 10, 30, 30)      # 这个方块不会受 45° 旋转影响
```

## 实战套路：在中心点画旋转图形

画一个绕自身中心旋转的物体，标准三步是：

1. `translate(cx, cy)` 把原点搬到旋转中心
2. `rotate(angle)` 绕它转
3. 用负半宽的坐标画图形（让它以原点为中心对称）

```
p.translate(cx, cy)
p.rotate(self._angle)
p.setBrush(QBrush(Qt.GlobalColor.blue))
p.drawRect(-50, -6, 100, 12)   # 指针，以原点为中心、长 100 宽 12
```

## 翻车现场一：save/restore 不配对，变换越叠越歪

**症状：每次重绘（resize、遮挡重现）后图形位置/角度都漂移到奇怪的地方，或者程序越跑越卡。**

**错误写法：**

```
def paintEvent(self, event):
    p = QPainter(self)
    p.translate(160, 120)
    p.rotate(self._angle)
    p.drawRect(-20, -20, 40, 40)
    # 忘了 p.restore()
```

**原因**：虽然这次 paintEvent 结束 QPainter 析构会清掉当前状态，但真正的坑是**你在多个地方 save 后只 restore 了一部分**，或者你在 `save()` 和 `restore()` 之间提前 return / 抛异常，导致 restore 没执行。变换矩阵一旦残留，后续所有绘制都会带上一笔莫名其妙的旋转+平移。

**正确写法：save 和 restore 成对，且放在同一个作用域里：**

```
p.save()
try:
    p.translate(160, 120)
    p.rotate(self._angle)
    p.drawRect(-20, -20, 40, 40)
finally:
    p.restore()          # 保证任何路径下都恢复
```

## 翻车现场二：resetTransform 用错，把自己画的参考系也清掉了

**症状：想只清掉旋转、保留平移，结果平移也丢了。**

**错误写法：**

```
p.translate(150, 120)
p.rotate(45)
# ... 画旋转的
p.resetTransform()       # ← 所有变换都没了，包括平移
p.drawRect(0, 0, 30, 30)   # 以为在(150,120)，实际在(0,0)
```

**原因**：`resetTransform()` 是"一键归零"，不是"撤销上一步"。

**正确做法**：用 save/restore 精确控制，或用 `p.setTransform(QTransform())` 显式重置。如果只是想撤销某段变换，save/restore 才是正解。

## 翻车现场三：绕原点旋转时，图形飞出画面

**症状：旋转后矩形不见了，因为矩形本来的坐标是 `(0,0,40,40)`，绕原点转 180° 后跑到了左上角以外。**

**错误写法：**

```
p.translate(160, 120)
p.rotate(180)
p.drawRect(0, 0, 40, 40)   # 绕原点转 180° 后这个矩形在 (-40,-40) 相对中心
```

**正确写法：把图形中心对齐到原点：**

```
p.translate(160, 120)
p.rotate(180)
p.drawRect(-20, -20, 40, 40)   # 以原点为中心，旋转后仍在中心
```

## 小结

- translate / rotate / scale / shear 改变坐标系，按代码顺序叠加
- save() 存档、restore() 恢复，是隔离变换的唯一安全方式
- 两者必须配对，最好用 try/finally 包裹
- 绕中心旋转的标准套路：translate 到中心 → rotate → 用负半宽坐标画
- resetTransform 是全部清零，不是撤销一步
- 旋转后图形"飞走"通常是没有把图形中心对齐到原点
