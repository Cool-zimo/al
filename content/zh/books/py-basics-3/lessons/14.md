# 主动抛出：raise

> 不只是"接住"错误，你也可以"制造"错误——用来拒绝不合理的情况。

## 为什么需要主动报错

写个除法函数：

```python
def divide(a, b):
    return a / b

print(divide(10, 0))      # ZeroDivisionError，还行
```

但如果是这个：

```python
def get_price(age):
    if age < 0:
        pass           # ??? 负年龄怎么办
    return 100 if age >= 18 else 50
```

**负年龄是不合理的，但 Python 不会替你报错**——它会算出个莫名其妙的结果。

**这时候你要主动说"不行"：**

```python
def get_price(age):
    if age < 0:
        raise ValueError("年龄不能是负数")
    return 100 if age >= 18 else 50

get_price(-5)      # ValueError: 年龄不能是负数
```

## raise 的基本写法

```python
raise 异常类型("说明文字")
```

```python
raise ValueError("值不对")
raise TypeError("类型不对")
raise PermissionError("没有权限")
```

**异常类型 + 一句人话说明**。

## 常见的用法：参数校验

```python
def calculate_bmi(weight, height):
    if weight <= 0:
        raise ValueError(f"体重必须大于 0，收到 {weight}")
    if height <= 0:
        raise ValueError(f"身高必须大于 0，收到 {height}")
    return weight / (height ** 2)


print(calculate_bmi(70, 1.75))      # 22.86
print(calculate_bmi(-70, 1.75))     # ValueError: 体重必须大于 0，收到 -70
```

**这种"在函数开头检查参数"的写法叫"前置条件检查"**——是专业代码的标志。

## raise 会中断函数

```python
def check(n):
    if n < 0:
        raise ValueError("不能是负数")
    print("这行不会执行")        # ← raise 之后的代码不执行
    return n * 2

check(-1)      # 报错，函数在此中断
```

**`raise` 和 `return` 一样会立刻结束函数**，区别是它带着错误出去。

## 自定义异常

内置的异常不够用时，可以自己造一个：

```python
class AgeError(Exception):
    pass


def set_age(age):
    if not 0 <= age <= 150:
        raise AgeError(f"年龄必须在 0~150 之间，收到 {age}")
    print(f"年龄设为 {age}")


try:
    set_age(200)
except AgeError as e:
    print(f"设置失败：{e}")
```

**自定义异常就是继承 `Exception` 的一个类**（类的知识在第 21 课）。

**好处**：调用者可以精确地捕获你这种错误：

```python
try:
    set_age(200)
except AgeError:
    print("年龄有问题")          # 只抓 AgeError
except ValueError:
    print("其他值错误")           # 不会被 AgeError 触发
```

## 重新抛出

有时你想"记录一下，但不管，让它继续传上去"：

```python
try:
    risky()
except ValueError as e:
    print(f"[日志] 发生错误：{e}")
    raise              # ← 不带参数，原样再抛出去
```

**单独的 `raise`（不带任何东西）表示"把刚才那个异常原样再抛一次"**。

**用途**：记日志 / 做清理，然后让上层去处理。

## 一个常见模式：转换错误信息

```python
try:
    config = json.load(open('c.json'))
except json.JSONDecodeError as e:
    raise ValueError(f"配置文件格式错误：{e}") from e
```

**`raise ... from e`** 保留原始异常的上下文——traceback 里能看到"由 XX 引起"。

## 什么时候该 raise？

| 情况 | 建议 |
|---|---|
| 参数明显不合理（负数、空字符串） | **raise** |
| 外部数据不符合预期 | **raise** |
| 只是"没找到"这类正常情况 | 返回 None 或空值，别 raise |
| 能自己修复的小问题 | 自己处理，别 raise |

**原则：`raise` 用于"这个情况不该发生"，而不是"这个情况不常见"。**

```python
# ✅ 该 raise：负数年龄是不合理的输入
if age < 0:
    raise ValueError("年龄不能为负")

# ❌ 不该 raise：搜索没结果是正常情况
def find(name):
    ...
    return None        # 没找到就返回 None
```

## 小结

- `raise 类型("说明")` 主动抛出错误
- **常用于参数校验**（前置条件检查）
- `raise` 会立刻中断函数
- 自定义异常继承 `Exception`
- **裸 `raise`** 重新抛出当前异常
- 只对该"不该发生"的情况 raise
