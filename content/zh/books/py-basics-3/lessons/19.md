# 包：把模块装进文件夹

> 模块多了，就该用文件夹整理了。这个"装模块的文件夹"叫包。

## 为什么需要包

```
myapp/
├── main.py
├── database.py
├── api.py
├── models.py
├── utils.py
├── helpers.py
├── validators.py
└── formatters.py
```

**八个模块平铺在一起**，还是乱。

**按功能分组**：

```
myapp/
├── main.py
├── db/
│   ├── database.py
│   └── models.py
├── web/
│   ├── api.py
│   └── validators.py
└── utils/
    ├── helpers.py
    └── formatters.py
```

**这就是包**——用文件夹把相关模块归到一起。

## 包就是一个文件夹（加个文件）

**Python 3.3+ 之后，任何文件夹都能当包用**（不需要 `__init__.py`）：

```
utils/
├── helpers.py
└── formatters.py
```

```python
import utils.helpers
from utils import formatters
```

**但为了兼容性，通常还是放一个 `__init__.py`**（可以是空文件）：

```
utils/
├── __init__.py      ← 空的也行
├── helpers.py
└── formatters.py
```

> 💡 **`__init__.py` 的作用**：告诉 Python "这是个包"，同时可以在里面写初始化代码。

## 导入包里的模块

```python
# 方式一：import 完整路径
import utils.helpers
utils.helpers.do_something()

# 方式二：from ... import ...
from utils import helpers
helpers.do_something()

# 方式三：直接导入函数
from utils.helpers import do_something
do_something()
```

**三种都行**，按需要选。

## `__init__.py` 能做什么

**1. 空的**——最常见，只是标记"这是个包"

```python
# utils/__init__.py
```

**2. 简化导入**——把常用东西提到包级别：

```python
# utils/__init__.py
from .helpers import format_date
from .formatters import format_money
```

之后可以直接：

```python
from utils import format_date, format_money
# 不用 from utils.helpers import format_date
```

**3. 定义 `__all__`**——控制 `from utils import *` 能导入什么：

```python
# utils/__init__.py
__all__ = ['format_date', 'format_money']
```

## 相对导入 vs 绝对导入

**在包的内部**，模块之间互相导入有两种写法：

```python
# utils/helpers.py

# 相对导入（用点表示"相对当前位置"）
from . import formatters          # 同级
from .formatters import fmt       # 同级的具体模块
from ..db import models           # 上一级

# 绝对导入（写完整路径）
from utils import formatters
from myapp.db import models
```

| | 优点 | 缺点 |
|---|---|---|
| **绝对导入** | 清楚，不会搞错 | 路径写死了，包改名要改一堆 |
| **相对导入** | 包改名不影响 | 层数多了容易看晕 |

> 💡 **建议：优先用绝对导入**（更清楚），只在写会被复用的库时才用相对导入。

## 一个常见错误

```
myapp/
├── main.py
└── utils/
    └── helpers.py
```

在 `utils/helpers.py` 里写：

```python
import main        # ❌ 可能找不到
```

**原因**：Python 查找模块的起点是"你运行程序时的目录"。

**如果你在 myapp/ 目录下运行 `python main.py`**，那 `main.py` 所在目录会被加进搜索路径，`import main` 能找到。

**但如果你在别处运行**，就找不到了。

> ⚠️ **所以包内部不要 import 顶层模块**——会造成混乱的循环依赖。让上层（`main.py`）去 import 下层，别反过来。

## 实际的例子

```
myapp/
├── main.py
├── config.py
└── utils/
    ├── __init__.py
    └── helpers.py
```

```python
# utils/helpers.py
def format_date(d):
    return d.strftime("%Y-%m-%d")
```

```python
# utils/__init__.py
from .helpers import format_date
```

```python
# main.py
from utils import format_date        # 因为 __init__.py 里提上来了
from datetime import date

print(format_date(date.today()))
```

## 包名也是命名空间

```python
import utils.helpers
import web.helpers        # 两个 helpers 不冲突
```

**包提供了第二层命名空间**，比把所有模块平铺清晰得多。

## `if __name__ == "__main__"` 在包里的注意

如果你想**运行包里的某个模块**：

```bash
python -m utils.helpers        # 用 -m 参数，把它当模块运行
```

**不要直接** `python utils/helpers.py`——那样相对导入会失败。

## 小结

- **包 = 装模块的文件夹**（通常带 `__init__.py`）
- 三种导入：`import pkg.mod` / `from pkg import mod` / `from pkg.mod import fn`
- **`__init__.py` 可以简化导入**、定义 `__all__`
- 优先用**绝对导入**
- 包内部不要 import 顶层模块（避免循环依赖）
