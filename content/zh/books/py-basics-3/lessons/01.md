# 为什么需要文件

> 你写的程序一关，数据就没了。这一课讲清楚"为什么"，以及文件的本质是什么。

## 一个让你沮丧的实验

写这样一个程序，运行它，输入你的名字：

```python
name = input("你叫什么名字？")
print("记住你了：", name)
```

然后**再运行一次**，输入另一个名字。你会发现：程序完全不记得上一次是谁。

```python
# 每次运行都是全新的开始
name = input("你叫什么名字？")
print("记住你了：", name)
print("上次是谁？我不知道。")     # 变量只在程序运行期间存在
```

**变量住在内存里，程序一结束，内存就被回收了。**

## 内存 vs 硬盘

| | 内存（RAM） | 硬盘（磁盘） |
|---|---|---|
| 速度 | 极快 | 慢得多 |
| 断电后 | **数据消失** | 数据还在 |
| 容量 | 小（几 G～几十 G） | 大（几百 G～几 T） |
| 程序里的对应物 | 变量 | 文件 |

**变量的寿命 = 程序的寿命。文件的寿命 = 你不去删它。**

所以要"让数据活过关机"，就必须把数据从内存搬到硬盘上——**这就是文件读写**。

## 文件就是一串字节

别把文件想复杂了。**一个文件本质上就是硬盘上的一串数据**，仅此而已。

```python
# 文本文件里存的就是字符
# "你好\n世界" 存进去就是这几个字加一个换行符
```

扩展名（`.txt` `.csv` `.json` `.py`）**只是给人和操作系统看的标签**，不改变"它是一串数据"这个事实。

> 💡 你可以用记事本打开 `.py` 文件，也可以用 Python 读 `.txt` 文件。**扩展名是约定，不是魔法。**

## 一个最小的例子

```python
# 写：把内存里的东西搬到硬盘
with open('note.txt', 'w', encoding='utf-8') as f:
    f.write("我今天学了文件读写")

# 读：把硬盘上的东西搬回内存
with open('note.txt', 'r', encoding='utf-8') as f:
    content = f.read()

print("文件里写的是：", content)
```

**运行两次试试**：第一次写入，第二次读出来。哪怕隔了一天再运行，内容还在。

**这就是"持久化"——数据活过了程序的生命周期。**

## 两个先看一眼的词

后面的课会反复出现，这里先混个眼熟：

- **编码（encoding）**：文字在硬盘上怎么存。`utf-8` 是现在最通用的，中文也能存。**写文件时建议总是加上 `encoding='utf-8'`**。
- **路径（path）**：文件在硬盘上的位置，比如 `note.txt`（当前目录）或 `C:/Users/me/note.txt`（完整路径）。

## 一个马上会遇到的坑

```python
# ❌ 这样在 Windows 上可能读不了中文
with open('note.txt', 'r') as f:
    ...

# ✅ 明确指定编码
with open('note.txt', 'r', encoding='utf-8') as f:
    ...
```

**为什么？** Python 在 Windows 上默认用系统编码（通常是 GBK），而文件可能是 UTF-8 存的，两边对不上就乱码或报错。

**养成习惯：凡是 open，都带上 `encoding='utf-8'`。** 第 02 课会详细讲。

## 小结

- 变量在内存里，程序结束就没了；文件在硬盘上，关机还在
- **文件就是一串数据**，扩展名只是标签
- `open()` 打开文件，读或写，用完要关闭
- **永远写 `encoding='utf-8'`**
