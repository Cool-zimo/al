# try / except：让程序不崩

> 上一个报错就整个停掉的程序，没人敢用。这一课教你接住错误。

## 基本形态

```python
try:
    可能出错的代码
except 错误类型:
    出错了怎么办
```

**执行流程**：

1. 先跑 `try` 里的代码
2. **没出错** → 跳过 `except`，继续往下
3. **出错了** → 立刻跳到 `except`，执行里面的代码，然后程序继续

```python
try:
    n = int(input("请输入数字："))
    print(f"你输入的是 {n}")
except ValueError:
    print("这不是一个数字")

print("程序继续运行")        # ← 无论上面怎样，这行都会执行
```

## 一个真实的场景

```python
# ❌ 用户输入字母就崩溃
age = int(input("年龄："))
print(f"明年你 {age + 1} 岁")

# ✅ 用 try/except 兜住
try:
    age = int(input("年龄："))
    print(f"明年你 {age + 1} 岁")
except ValueError:
    print("请输入数字")
```

**用户输入是不可控的**——这是 `try/except` 最经典的用途。

## 只抓你预期的错误

```python
try:
    value = int(user_input)
except ValueError:          # ← 明确写类型
    print("输入不是数字")
```

> ⚠️ **不要用裸 `except:`**（不写类型）。它会把**所有**错误都吞掉，包括你没想到的 bug：

```python
# ❌ 糟糕：连键盘中断、拼写错误都吞了
try:
    result = calculate()
except:
    print("出错了")
```

问题在于：如果 `calculate` 里有个拼写错误（NameError），你也会看到"出错了"，**永远找不到真正的 bug**。

**原则：只捕获你知道怎么处理的异常类型。**

## 拿到错误信息

```python
try:
    n = int("abc")
except ValueError as e:          # as e 拿到异常对象
    print(f"出错原因：{e}")
```

```
出错原因：invalid literal for int() with base 10: 'abc'
```

**`as e` 把异常存进变量**，可以打印出来看详情，或写进日志。

## 捕获多种异常

```python
try:
    value = int(user_input)
    result = 100 / value
except ValueError:
    print("不是数字")
except ZeroDivisionError:
    print("不能输入 0")
```

**写多个 `except`**，每种错误分别处理。

**也可以用元组一次抓多个**：

```python
try:
    ...
except (ValueError, TypeError):
    print("输入有问题")
```

## 不确定会出什么错？

```python
try:
    risky_operation()
except Exception as e:          # Exception 是所有常见异常的父类
    print(f"意外错误：{e}")
```

**`Exception` 比裸 `except:` 好**——它不包括 `KeyboardInterrupt`（Ctrl+C）和 `SystemExit`，你的程序还能被正常中断。

**顺序很重要**：

```python
try:
    ...
except ValueError:
    print("值错误")
except Exception as e:
    print(f"其他错误：{e}")
```

**具体的写前面，笼统的写后面**。反过来写的话，`Exception` 会先把所有错误都抓走，后面的 `ValueError` 永远执行不到。

## 实战：反复输入直到合法

```python
while True:
    try:
        age = int(input("请输入年龄："))
        if age < 0:
            print("年龄不能是负数，重新输入")
            continue
        break                    # 成功，跳出循环
    except ValueError:
        print("请输入数字")

print(f"你的年龄是 {age}")
```

**这是"输入校验"的标准写法**——不合法就重来，直到拿到合法的。

## 实战：安全地读文件

```python
try:
    with open('data.txt', 'r', encoding='utf-8') as f:
        content = f.read()
except FileNotFoundError:
    print("文件不存在，使用默认内容")
    content = ""
except PermissionError:
    print("没有权限读取")
    content = ""
except UnicodeDecodeError:
    print("编码不对，无法解码")
    content = ""

print(f"读到 {len(content)} 个字符")
```

**比第 07 课用 `os.path.exists` 判断更好**——因为除了"不存在"，还有权限、编码等问题。

## 一个对比

| 做法 | 问题 |
|---|---|
| 不处理 | 一报错就崩 |
| `os.path.exists` 预先判断 | 只能防"不存在"，防不住权限/编码问题 |
| **`try/except`** | **一次兜住所有可能** |

> 💡 **Python 圈有句行话：EAFP（Easier to Ask Forgiveness than Permission）**——"先做，出错了再道歉"，比"做之前先检查一遍"更简洁可靠。

## 小结

- `try` 放可能出错的代码，`except 类型` 接住
- **只捕获你知道怎么处理的类型**，别用裸 `except:`
- `as e` 拿到错误详情
- 多个 `except` 时，**具体的写前面**
- **用户输入、文件读写**是 try/except 的两大主战场

  # open('nope.txt') 会触发 FileNotFoundError
  # 捕获它

- assert "文件不存在" in __out
