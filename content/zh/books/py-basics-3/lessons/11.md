# 什么是异常

> 程序不会因为你写错了就"忍着"——它会停下来并告诉你发生了什么。这个"停下来+"就是异常。

## 你早就见过它们了

```python
print(10 / 0)          # ZeroDivisionError: division by zero
print(int("abc"))      # ValueError: invalid literal for int()
print("abc"[10])       # IndexError: string index out of range
print(undefined_name)  # NameError: name 'undefined_name' is not defined
```

**这些红色文字不是"程序坏了"，而是 Python 在认真告诉你：这里有个问题。**

## 异常的三个部分

以这个为例：

```python
numbers = [1, 2, 3]
print(numbers[5])
```

```
Traceback (most recent call last):
  File "demo.py", line 2, in <module>
    print(numbers[5])
IndexError: list index out of range
```

**三部分**：

1. **Traceback**：调用栈，告诉你错误发生在哪
2. **位置**：`File "demo.py", line 2` —— 哪个文件第几行
3. **类型和说明**：`IndexError: list index out of range`

> 💡 **读报错从最后一行读起**。最后一行才是"到底出了什么事"，上面那些是"怎么走到这一步的"。

## 常见的异常类型

| 异常 | 什么时候出现 | 例子 |
|---|---|---|
| `SyntaxError` | **语法写错了**（代码根本没运行） | `if x = 1:` |
| `NameError` | 用了没定义过的名字 | `print(abc)` |
| `TypeError` | 类型不对 | `"1" + 1` |
| `ValueError` | 类型对但值不对 | `int("abc")` |
| `IndexError` | 下标越界 | `lst[100]` |
| `KeyError` | 字典里没这个键 | `d['不存在']` |
| `ZeroDivisionError` | 除以零 | `10 / 0` |
| `FileNotFoundError` | 文件不存在 | `open('nope.txt')` |
| `AttributeError` | 对象没有这个属性 | `"abc".push()` |

**记住这些名字**——后面 `except` 要按名字抓。

## SyntaxError 是特殊的

```python
# ❌ 这行连运行都运行不了
if x = 1:
    print("x")
```

**`SyntaxError` 在"运行之前"就发生了**——Python 读不懂你的代码。

> ⚠️ **SyntaxError 不能被 `try/except` 捕获**，因为代码根本没跑起来。其他所有异常都可以。

## 异常会"中断"程序

```python
print("第一步")
print(10 / 0)          # 这里崩了
print("第二步")         # ← 永远不会执行
```

**一旦发生异常且没人处理，程序立刻停止**，后面的代码全部跳过。

这就是为什么要学 `try/except`——**让程序在该停的地方优雅地停下来，而不是整个崩掉**。

## 为什么要区分"错误类型"

```python
int("abc")     # ValueError  —— 类型对（是字符串），值不对（不是数字）
"1" + 1        # TypeError   —— 类型就不对（字符串不能和整数相加）
```

**这个区分很有用**，因为：

- `ValueError` → 说明你要检查数据内容
- `TypeError` → 说明你要检查数据类型

**报错类型本身就是调试线索。**

## 一个重要的心态

**报错不是你错了，是 Python 在帮你。**

对比一下：

| 语言 | 出错时的表现 |
|---|---|
| 有些语言 | 默默给你个错误结果，跑完才发现不对 |
| **Python** | **立刻停下来，精确指出第几行出了什么事** |

**崩溃比"悄悄算错"好一万倍**——后者会让 bug 潜伏几周才发现。

所以看到红色 traceback，**别慌，读最后一行**。

## 小结

- **异常 = 程序遇到问题时的"停下并报告"机制**
- **读报错从最后一行读起**
- `SyntaxError` 在运行前发生，无法捕获
- 异常会中断程序——所以要学 `try/except`
- **报错是帮你，不是骂你**

## 随堂练习

认识报错类型。

```quiz
type: code
q: 让 int("abc") 触发 ValueError，用 try/except 捕获并打印 "值不对"
starter: |
  # int("abc") 会触发 ValueError
  # 用 try: ... except ValueError: ... 捕获
  
  print("TODO：把这行改成你要打印的结果")
tests:
- assert "值不对" in __out
hint: try: int("abc") except ValueError: print("值不对")。except 后面写要捕获的异常类型。
explain: try/except 的基本形态：try 里放"可能出错的代码"，except 里写"出错了怎么办"。这样程序不会崩，而是按你安排的方式继续。
```
