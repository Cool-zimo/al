# 正则的性能：灾难性回溯

> 这一课解决"正则为啥会卡死"的问题。某些看似无害的模式，在"几乎匹配"的输入面前会让引擎指数级回溯，直接拖垮服务。学会识别嵌套量词，是写正则的成人礼。

## 一个会卡死的例子

先看一段看似正常的代码：

```python
import re

pat = re.compile(r'^(a+)+b$')
text = "aaaaaaaaaaaaaaaaaaaaaaaaac"   # 25 个 a 加一个 c

# 运行这行，会发现它卡住好几秒
print(pat.match(text))
```

输出（很久之后）：

```
None
```

字符串里**根本不存在** `b`，为什么花了这么久？因为正则引擎在"拼命试"。

`(a+)+` 的含义是"**一个或多个 a，这一组又重复一次或多次**"。当引擎发现最后是 `c` 而不是 `b` 时，它要**回退重试**：a+ 少吞一个 a、让外层的 + 多消化一个、再检查 b 成不成立……每一种可能的拆分方式都要试一遍。

## 为什么是指数级

`(a+)+` 匹配 20 个 a 的方式有 **2^19 种**（每个 a 都可以属于内层或外层）。引擎在"几乎成功"时要把每种拆分都试一遍，复杂度是 **O(2^n)**。

```python
import re
import time

pat = re.compile(r'^(a+)+b$')

for n in [10, 20, 25, 28]:
    text = "a" * n + "c"
    t0 = time.time()
    pat.match(text)
    print(f"n={n:2d} 耗时 {time.time()-t0:.3f}s")
```

典型输出（具体数值随机器变化，但**增长趋势**是关键）：

```
n=10 耗时 0.000s
n=20 耗时 0.002s
n=25 耗时 0.064s
n=28 耗时 0.520s
```

每多几个字符，耗时翻几倍。这就是"灾难性回溯"（Catastrophic Backtracking）。它不报错、不抛异常，只是**卡住**——在 Web 服务里这就是一次完美的拒绝服务。

## 嵌套量词：罪魁祸首

凡是"**量词包住量词**"的结构，都要警惕：

| 危险模式 | 问题 |
|---|---|
| `(a+)+` | 内层 `+` 外层 `+`，指数级 |
| `(a*)*` | 与上面同类 |
| `(a|a)*` | 分支 + 量词，指数级 |
| `(\w+)*` | 内层贪婪、外层再量词 |

**关键观察**：这些模式里，内外两层都在"抢着吞同一个字符"，于是引擎只能来回试探。

## 翻车现场：验证标签时的嵌套量词

张三想校验一段文本是否全是成对的尖括号标签：

```python
import re

# WRONG：嵌套量词，恶意输入会让它卡死
TAG_RE = re.compile(r'^<([^>]+)>.*</\1>$')
evil = "<a>" + "a" * 30 + "<"
TAG_RE.match(evil)      # 卡住
```

看着没事，但 `.+` 和 `.*` 的叠加，加上回溯，遇到"几乎闭合"的输入就会出问题。

**正确做法一：把贪婪改成非贪婪，消除回溯空间**：

```python
import re

TAG_RE = re.compile(r'^<([^>]+)>.*?</\1>$')   # 注意 .*? 非贪婪
print(TAG_RE.match("<div>hello</div>"))
```

**正确做法二：用"占有优先"或原子分组（Python 里是 `(?>...)` 需第三方库支持，标准库不提供）**——那就退一步，用**更精确的字符类**替代 `.`：

```python
import re

# 标签内容不允许出现 < 和 >，就明确写出来，避免 .* 回退
TAG_RE = re.compile(r'^<([^>]+)>([^<]*)</\1>$')
print(TAG_RE.match("<div>hello</div>").groups())
```

输出：

```
('div', 'hello')
```

`[^<]*` 明确说"里面不能有左尖括号"，引擎**没有别的选择可以回退**，回溯空间直接被消灭。

## 规避清单

写正则时问自己三个问题：

1. **有没有嵌套量词**？`(a+)+` `(.+)*` `(.*)*` 一律重写。
2. **能不能用更精确的字符类**？把 `.` 换成 `[^...]` 否定式，直接消灭回溯分支。
3. **输入可控吗**？如果用户能提交任意字符串给这个正则，就要做长度限制。

```python
import re

def safe_match(pat, text, limit=1000):
    """给不可信输入加个长度保险丝"""
    if len(text) > limit:
        raise ValueError(f"输入过长：{len(text)} > {limit}")
    return pat.match(text)

pat = re.compile(r'^(a+)+b$')
print(safe_match(pat, "a" * 50 + "c"))   # 直接抛错，不卡
```

输出：

```
ValueError: 输入过长：51 > 1000
```

**这个"保险丝"是防御灾难性回溯最简单有效的一招**：回溯复杂度随输入长度指数增长，那就在长度上卡死它。Web 框架、日志系统里到处是这个套路。

## 小结

- 灾难性回溯：嵌套量词让引擎指数级试探每种拆分，结果是不报错但卡死
- `(a+)+` `(a*)*` `(\w+)*` 这类"量词包量词"是头号危险分子
- 用**非贪婪** `(.*?)` 或**更精确的字符类** `[^<]*` 替代 `.`，消灭回溯分支
- 对不可信输入加**长度限制**，是防御回溯的最简有效手段
- 正则性能问题不报错、不抛异常，只表现为"突然变慢"，必须主动识别
