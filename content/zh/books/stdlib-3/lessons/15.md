# functools：缓存、偏函数与归约

> 这一课讲 `functools` 里最实用的三个工具：`lru_cache` 把重复计算砍到 O(1)、`partial` 把"参数绑定"变成新函数、`reduce` 把一串值归约为一个值。三者都是写"函数式风格"代码的核心零件。

## lru_cache：用缓存换速度

先看一个朴素版斐波那契：

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))
print(fib(20))
```

输出：

```
55
6765
```

看着没问题，但 `fib(30)` 会卡好几秒——因为 `fib(5)` 被算了成千上万次，每次都重新算一遍。

**加一行装饰器，瞬间快到飞起**：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(100))    # 不缓存的话这辈子都算不完
```

输出：

```
354224848179261915075
```

`fib(100)` 立刻出结果。`lru_cache` 的原理：**把每次调用的入参和返回值存进字典**，下次用同样的参数调用时直接返回缓存值，不再重新执行函数体。

## 翻车现场：lru_cache 对可变参数不生效

`lru_cache` 的键是"入参的元组"。如果参数是**可变对象**（列表、字典），它没法安全地当作字典键：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def sum_list(lst):
    print(f"正在计算 {lst}")
    return sum(lst)

sum_list([1, 2, 3])
sum_list([1, 2, 3])     # 列表不可哈希，不会命中缓存，重新算
```

报错：

```
TypeError: unhashable type: 'list'
```

**正确做法**：用元组等不可变类型做参数，或者把可变对象转成不可变形式。

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def sum_tuple(tup):
    print(f"正在计算 {tup}")
    return sum(tup)

sum_tuple((1, 2, 3))
sum_tuple((1, 2, 3))     # 元组可哈希，命中缓存，不再打印"正在计算"
```

输出：

```
正在计算 (1, 2, 3)
6
6
```

第二次调用**没有**打印"正在计算"——说明直接命中缓存，函数体没再执行。

## partial：把参数"冻住"变成新函数

`partial` 把一个函数的**部分参数预先绑定**，返回一个新函数：

```python
from functools import partial

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)      # 把 exp 固定为 2
cube   = partial(power, exp=3)      # 把 exp 固定为 3

print(square(5))
print(cube(5))
print(square(10))
```

输出：

```
25
125
100
```

`square` 是一个"只剩 base 没填"的新函数。它和"手动写个 lambda"效果类似，但**语义更清晰、性能更好、有 `__name__` 等元数据**。

## 翻车现场：partial 的位置参数顺序

```python
from functools import partial

def divide(a, b):
    return a / b

# 想做"除以 2"，应该把 b 固定为 2
half = partial(divide, b=2)

print(half(10))      # 10 / 2 = 5
print(half(a=20))    # 也能用关键字
```

输出：

```
5.0
10.0
```

但如果用位置参数，顺序必须对齐：

```python
from functools import partial

def divide(a, b):
    return a / b

# WRONG：位置参数会填到最前面的形参 a，结果变成 a=2
half = partial(divide, 2)
print(half(10))      # 实际是 divide(2, 10) = 0.2
```

输出：

```
0.2
```

**正确做法**：用 `partial` 绑定靠后的参数时，**一律用关键字参数**，避免位置错配。

## reduce：把一串值"折"成一个值

`reduce` 把一个**二元函数**依次作用到序列上，把 n 个值归约为 1 个值：

```python
from functools import reduce

nums = [1, 2, 3, 4, 5]

# reduce(函数, 序列) => 依次合并
result = reduce(lambda acc, x: acc + x, nums)
print("求和:", result)

# 第三个参数是初始值
product = reduce(lambda acc, x: acc * x, nums, 1)
print("求积:", product)
```

输出：

```
求和: 15
求积: 120
```

过程是这样的：先算 `1+2=3`，再用 `3+3=6`，再 `6+4=10`，再 `10+5=15`。`reduce` 就是"把二元操作一路折叠下去"。

## 翻车现场：reduce 空序列不传初始值就崩

```python
from functools import reduce

# WRONG：空序列 + 没有初始值
print(reduce(lambda a, b: a + b, []))
```

报错：

```
TypeError: reduce() of empty sequence with no initial value
```

**正确做法**：传一个初始值，`reduce` 会用它作为"第一次计算的左操作数"：

```python
from functools import reduce

print(reduce(lambda a, b: a + b, [], 0))      # 空序列求和为 0
print(reduce(lambda a, b: a * b, [], 1))      # 空序列求积为 1
```

输出：

```
0
1
```

**经验法则**：用 `reduce` 时**总是传初始值**。这是 Guido 本人的建议，也是 Python 3 把 `reduce` 从内置函数移到 `functools` 的原因之一——它不是万能工具，简单场景用 `sum()`、`max()`、`any()` 更清晰。

## 小结

- `lru_cache` 把"相同入参的重复计算"缓存起来，递归（如斐波那契）提速最明显
- `lru_cache` 要求入参**可哈希**，列表/字典作参数会 TypeError，改用元组等不可变类型
- `partial` 把部分参数绑定成新函数；绑定靠后参数时**用关键字参数**避免位置错配
- `reduce` 把二元函数依次折叠到序列上，把 n 个值归约为 1 个值
- `reduce` 遇到空序列且不传初始值会报错，**总是传初始值**更安全
- 简单聚合（求和、取最大）优先用 `sum()`/`max()`，别硬套 reduce
