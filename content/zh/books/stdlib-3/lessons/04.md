# 分组与捕获

> 这一课解决"匹配到了，但只想拿走其中一部分"的问题。`()` 捕获、`(?:)` 非捕获、`(?P<name>)` 命名分组，以及那个**最经典的正则陷阱**——`findall` 遇到分组时只返回分组内容。

## 括号的第一重身份：捕获分组

`()` 在正则里是"把一块打包"的意思。被括号括起来的部分，匹配成功后可以被单独取出来。

```python
import re

text = "订单号DD20260927001金额299.5"
m = re.search(r'DD(\d{8})(\d{3})金额(\d+\.?\d*)', text)
print("整段:", m.group(0))      # 完整匹配
print("分组1:", m.group(1))     # 第一个括号
print("分组2:", m.group(2))     # 第二个括号
print("分组3:", m.group(3))     # 第三个括号
print("所有分组:", m.groups())
```

输出：

```
整段: DD20260927001001299.5
分组1: 20260927
分组2: 001
分组3: 299.5
所有分组: ('20260927', '001', '299.5')
```

`.group(0)` 或 `.group()` 返回完整匹配；`.group(1)` 返回第 1 个左括号对应的分组，以此类推。`.groups()` 一次性把所有分组装成元组返回。

**这就是"捕获"**：括号不仅影响匹配，还会在匹配成功后把那部分内容单独存起来给你用。

## 翻车现场：findall 有分组时只返回分组

这是正则里**最出名**的陷阱，几乎没有初学者能避开。张三想从日志里提取"时间+级别"：

```python
import re

log = "10:20 ERROR 服务异常\n11:05 INFO 启动完成"
# WRONG：以为会返回整段匹配
result = re.findall(r'(\d{2}:\d{2}) (\w+)', log)
print(result)
```

输出：

```
[('10:20', 'ERROR'), ('11:05', 'INFO')]
```

他原本想要 `['10:20 ERROR', '11:05 INFO']`，结果拿到的是**分组组成的元组列表**。

**规则**：`findall` 发现正则里有**捕获分组**时，就只返回分组内容；分组只有一个就返回字符串列表，分组有多个就返回元组列表。想拿整段匹配，就得把整个模式包进一个括号，或者干脆去掉内部括号。

```python
import re

log = "10:20 ERROR 服务异常\n11:05 INFO 启动完成"

# 解法一：去掉内部括号，让 findall 返回整段
print("解法一:", re.findall(r'\d{2}:\d{2} \w+', log))

# 解法二：想要分组就用括号，接受元组
print("解法二:", re.findall(r'(\d{2}:\d{2}) (\w+)', log))
```

输出：

```
解法一: ['10:20 ERROR', '11:05 INFO']
解法二: [('10:20', 'ERROR'), ('11:05', 'INFO')]
```

## 非捕获分组 (?:)

有时候加括号只是为了"量词能作用到一片"，并不想捕获。比如想匹配"http 或 https"：

```python
import re

urls = "http://a.com 和 https://b.com"

# 用捕获分组，结果里多了一层不需要的东西
print(re.findall(r'(https?)://(\w+\.com)', urls))

# 用非捕获分组 (?:)，只捕获真正想要的域名
print(re.findall(r'https?://(?:www\.)?(\w+\.com)', urls))
```

输出：

```
[('http', 'a.com'), ('https', 'b.com')]
['a.com', 'b.com']
```

`(?:...)` 的冒号读法：**不存下来，只当分组用**。它不改变匹配行为，只改变"要不要捕获"。在 `findall` 里它就是救星——能把"必须分组但又不想让它污染结果"的场景处理干净。

## 命名分组 (?P<name>)

分组多了之后，靠数字下标 `.group(1)` `.group(2)` 很容易数错。命名分组让每个分组有自己的名字：

```python
import re

log = "2026-09-28 10:20:35 ERROR 数据库连接失败"
pat = r'(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) (?P<level>\w+) (?P<msg>.*)'
m = re.search(pat, log)

print("级别:", m.group('level'))
print("时间:", m.group('time'))
print("全部命名分组:", m.groupdict())
```

输出：

```
级别: ERROR
日期: 2026-09-28
时间: 10:20:35
消息: 数据库连接失败
```

`.groupdict()` 把所有命名分组打包成字典，这在解析结构化文本（日志、配置文件）时非常顺手。可读性也远好于数括号下标。

## 翻车现场：嵌套分组时 group(1) 数错

```python
import re

text = "订单(DD20260927-001)完成"
m = re.search(r'\((\w+(\d{8})-(\d+))\)', text)
print("group(0):", m.group(0))
print("group(1):", m.group(1))
print("group(2):", m.group(2))
print("group(3):", m.group(3))
```

输出：

```
group(0): (DD20260927-001)
group(1): DD20260927-001
group(2): 20260927
group(3): 001
```

`group(1)` 是"最外层那个左括号"对应的内容，不是"第一个看起来像内容的东西"。括号嵌套时按**左括号出现的顺序**编号。这种场景用命名分组能救命：把 `(?P<order>...)` `(?P<date>...)` `(?P<seq>...)` 一标，代码读起来就是人话。

## 小结

- `()` 是捕获分组，匹配后可用 `.group(n)` 单独取出，`.groups()` 拿全部
- **`findall` 有捕获分组时只返回分组内容**，这是最经典的正则陷阱
- `(?:...)` 是非捕获分组：只参与匹配逻辑，不污染结果
- `(?P<name>...)` 是命名分组，可用 `.group('name')` 和 `.groupdict()` 取值
- 分组多、嵌套深时优先用命名分组，可读性远高于数下标
