# 常见实战模式：邮箱、手机号、IP、日期、URL

> 这一课把前面学过的语法拼成一个个"能直接抄走用"的实战模式。同时讲清一个更重要的事：**不要追求完美正则**——够用就好，边界情况交给业务规则。

## 手机号：11 位，第二位 3-9

中国大陆手机号 11 位，第 1 位固定是 1，第 2 位是 3-9（对应各运营商号段）。

```python
import re

PHONE_RE = re.compile(r'1[3-9]\d{9}')

text = "张三13812345678，李四13800138000，王五号码不全13812"
print(PHONE_RE.findall(text))
```

输出：

```
['13812345678', '13800138000']
```

**为什么是 `[3-9]` 不是 `[0-9]`**：手机号第二位历史上只用 3-9，虽然近年新增了 12 开头等新号段，但日常数据清洗里写死 `[3-9]` 已经能覆盖绝大多数真实数据。写 `[0-9]` 会把"10000000000"这种明显不是手机号的字符串误判进来。

## 翻车现场：把正则写得"太完美"

张三想写一个"完美"的邮箱正则，花了一下午写成这样：

```python
# 超长、难维护、容易漏
EMAIL_PERFECT = re.compile(
    r'^[a-zA-Z0-9.!#$%&\'*+/=?^_`{|}~-]+'
    r'@[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?'
    r'(?:\.[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?)+$'
)
```

三天后有人注册了带中文域名的邮箱，正则又挂了。真正的生产环境里，**邮箱验证的正确做法是"先粗略拦明显错的，再发一封验证邮件"**。

```python
import re

# 够用的邮箱正则：@ 前后都有内容，@ 后面有至少一个点
EMAIL_RE = re.compile(r'[\w.+-]+@[\w-]+\.[\w.-]+')

text = "联系 support@公司.cn 或 bug-report_01@test.org.cn"
print(EMAIL_RE.findall(text))
```

输出：

```
['support@公司.cn', 'bug-report_01@test.org.cn']
```

**核心观点**：正则验证的是"**格式看起来像**"，不是"**这个东西真实存在**"。判断邮箱真假，唯一可靠的方法是发一封验证邮件。

## IP 地址：点分十进制

IPv4 地址是"四个 0-255 的数字，用点分隔"。直接写 `\d+\.\d+\.\d+\.\d+` 会把 `999.999.999.999` 也匹配进来，所以要做范围约束：

```python
import re

IP_RE = re.compile(r'(?:(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)')

text = "服务器 192.168.1.1 和 8.8.8.8，异常地址 999.0.0.1"
print(IP_RE.findall(text))
```

输出：

```
['192.168.1.1', '8.8.8.8']
```

`(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)` 这个段读法是：要么 250-255，要么 200-249，要么 100-199，要么 0-99（前面可选补零）。四种情况用 `|` 列全，正好覆盖 0-255。

**现实建议**：如果只是要"看起来像 IP"，用 `r'\d+\.\d+\.\d+\.\d+'` 就够了；要严格校验范围，才用上面这个大块头。

## 日期：YYYY-MM-DD 与 YYYY/MM/DD

```python
import re

DATE_RE = re.compile(r'(\d{4})[-/](\d{1,2})[-/](\d{1,2})')

text = "发货日2026-09-28，到货日2026/10/05"
for m in DATE_RE.finditer(text):
    y, mo, d = m.groups()
    print(f"年={y} 月={mo} 月={d}")     # 注意：这里只提取，不校验日期合法性
```

输出：

```
年=2026 月=09 月=28
年=2026 月=10 月=05
```

**这个正则不校验日期合法性**：`2026-02-30` 照样匹配得上。真正的日期合法性校验交给 `datetime.strptime`（第二册讲过）——**正则负责格式，datetime 负责语义**，这是最干净的分工。

## URL：http/https 开头

```python
import re

URL_RE = re.compile(r'https?://[\w.-]+(?:\.[\w.-]+)+(?:/[\w./?%&=~-]*)?')

text = "详见 https://www.python.org/doc 和 http://example.com/path?a=1"
print(URL_RE.findall(text))
```

输出：

```
['https://www.python.org/doc', 'http://example.com/path?a=1']
```

`(?:/[\w./?%&=~-]*)?` 这部分处理 URL 的路径和查询参数，最后的 `?` 表示"可有可无"——域名后面的路径不一定存在。

## 翻车现场：把 [-\w] 里的横杠写错位置

字符类 `[]` 里的横杠 `-` 是范围符。想让横杠本身成为"可被匹配的字符"，要么**放在开头或结尾**，要么**转义**：

```python
import re

text = "版本 v1.2-rc 和 v1.3-beta"

# WRONG：[-.] 里横杠在中间，被解释成范围，结果匹配到奇怪的东西
print(re.findall(r'[\w.-]+', text))    # 碰巧没出错，但语义不清晰

# 正确：横杠放末尾，明确表示"字面的横杠"
print(re.findall(r'[\w.-]+', text))
```

输出：

```
['v1.2-rc', 'v1.3-beta']
```

`[\w.-]` 和 `[\w\.-]` 效果一样（横杠在末尾或转义），都是"单词字符 + 点 + 横杠"。**写 `[\w-]` 这种把横杠放中间、且后面没有字符的写法，Python 会按字面处理，但很多其他正则引擎会报错**，可移植性差。

## 小结

- 手机号：`1[3-9]\d{9}`；邮箱：`[\w.+-]+@[\w-]+\.[\w.-]+`（够用即可）
- 不要追求完美正则：格式像不等于真实存在，业务验证靠发邮件/查数据库
- IP 严格模式用大段 `|` 枚举 0-255；宽松模式用 `\d+\.\d+\.\d+\.\d+`
- 日期正则只校验格式，日期合法性交给 `datetime.strptime`
- 字符类 `[]` 里的横杠放末尾或转义，保证跨引擎可移植
