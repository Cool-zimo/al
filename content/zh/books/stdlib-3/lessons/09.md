# 什么时候不该用正则

> 这一课讲"收手"。正则不是银弹：解析有结构的文本它不如专门工具，简单的切分用字符串方法反而更快、更可读。学会判断"这件事不值得写正则"，比学会更多正则语法更有价值。

## 不要用正则解析 HTML

HTML 是**嵌套结构**：标签可以层层包裹。正则是**一维的线性模式**，两者根本不在一个维度上。张三想从网页里提取所有链接：

```python
import re

html = '<a href="https://a.com">A</a><a href="https://b.com">B</a>'

# 看着能跑
print(re.findall(r'href="(.*?)"', html))
```

输出：

```
['https://a.com', 'https://b.com']
```

这次"碰巧"对了。但只要 HTML 里出现一个**换行**或**单引号**，或者属性换个顺序，正则就失灵：

```python
import re

html = """<a
  href='https://a.com'
  target='_blank'>A</a>"""

print(re.findall(r'href="(.*?)"', html))   # 单引号 + 换行，全部失手
```

输出：

```
[]
```

**正确做法**：用专门的 HTML 解析器。`html.parser`（标准库自带）或第三方 `BeautifulSoup` 会先把 HTML 建成一棵树，你按标签、按属性去取，稳如磐石。

```python
from html.parser import HTMLParser

class LinkParser(HTMLParser):
    def __init__(self):
        super().__init__()
        self.links = []
    def handle_starttag(self, tag, attrs):
        if tag == 'a':
            for name, value in attrs:
                if name == 'href':
                    self.links.append(value)

p = LinkParser()
p.feed("""<a
  href='https://a.com'
  target='_blank'>A</a>""")
print(p.links)
```

输出：

```
['https://a.com']
```

换行、单双引号、属性顺序全都不再影响结果。**有结构的文本，交给能理解结构的工具。**

## 不要用正则解析 JSON

第二册讲过 `json` 模块。用正则从 JSON 里抠值，等于自己造一个残缺的 JSON 解析器：

```python
import re

raw = '{"name": "张三", "tags": ["a", "b"]}'

# WRONG：正则抠不出 tags 这个数组
print(re.findall(r'"name": "(.*?)"', raw))
```

输出：

```
['张三']
```

但一旦值里出现转义引号 `\"`、或结构嵌套，正则立刻崩。而 `json.loads` 一行搞定：

```python
import json

data = json.loads(raw)
print(data['tags'])
```

输出：

```
['a', 'b']
```

**判断标准**：输入是**结构化数据**（有键、有层级、有数组）就用 `json`/`csv`/`configparser`；输入是**纯文本**（日志、聊天记录、自然语言）才上正则。

## 翻车现场：简单场景用正则，反而更慢更难读

正则引擎有启动和编译开销。对"切分、前缀判断、去空白"这类**模式极其简单**的任务，字符串方法不仅更快，而且人人都看得懂。

```python
import re

text = "苹果, 香蕉, 橘子, 西瓜"

# 用正则：要编译、要理解模式、要处理可能的空格
print(re.split(r',\s*', text))

# 用字符串方法：一眼看懂，不用想
print([x.strip() for x in text.split(',')])
```

输出：

```
['苹果', '香蕉', '橘子', '西瓜']
['苹果', '香蕉', '橘子', '西瓜']
```

再比如判断前缀：

```python
import re

filename = "data_2026.csv"

# 正则：写错成本、维护成本都更高
print(bool(re.match(r'data_', filename)))

# startswith：意图一目了然
print(filename.startswith("data_"))
```

输出：

```
True
True
```

**原则**：当 `split`/`startswith`/`endswith`/`strip`/`replace` 能三行内解决，**就不要引正则**。正则的价值在"模式复杂"，不在"能做字符串操作"。

## 决策清单

写正则之前，先问自己三件事：

| 问题 | 若是 | 结论 |
|---|---|---|
| 输入有嵌套/层级结构吗？ | 是 | 用专门解析器（HTML/JSON/XML） |
| 模式是不是就"切分 / 前缀 / 去空白"这种简单动作？ | 是 | 用字符串方法 |
| 模式真的复杂（多种格式并存、需要分组提取）吗？ | 是 | 上正则 |

```python
import re

def choose_tool(text, goal):
    """三个问题，决定用什么工具"""
    if goal == "parse_html":
        return "用 html.parser 或 BeautifulSoup"
    if goal == "parse_json":
        return "用 json.loads"
    if goal in ("split", "prefix", "strip", "replace"):
        return "用字符串方法"
    return "用正则"

print(choose_tool("", "parse_html"))
print(choose_tool("", "split"))
print(choose_tool("", "extract_phone"))
```

输出：

```
用 html.parser 或 BeautifulSoup
用字符串方法
用正则
```

## 翻车现场：把正则当全文搜索

张三想在一段中文里找"Python"这个词，写了：

```python
import re

text = "我学Python和python"
print(re.findall(r'python', text))      # 默认大小写敏感，漏了大写
```

输出：

```
['python']
```

如果只是"找找有没有这个词"，`in` 运算符更直接；要忽略大小写，用 `re.IGNORECASE` 或干脆 `.lower()` 后 `in`。

```python
text = "我学Python和python"
print("python" in text.lower())        # True
```

**`in` 运算符的时间复杂度是 O(n)，但常数极小，且零编译开销**。短文本、单次查找，它就是最佳答案。

## 小结

- HTML 是嵌套结构，正则是一维模式，两者维度不对等，用 `html.parser` 或 BeautifulSoup
- JSON 用 `json.loads`，正则抠值等于自己造残缺解析器
- 结构化数据（有键、有层级）用专门模块，纯文本才上正则
- 简单动作（切分、前缀、去空白）用 `split`/`startswith`/`strip`，更快更可读
- 判断"该不该用正则"的标准：结构复杂度 > 正则价值；否则字符串方法更优
- 单次查找、短文本，`in` 运算符优于正则
