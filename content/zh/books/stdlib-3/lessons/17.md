# logging 进阶：logger、handler、formatter 三件套

> 这一课讲清楚日志系统的内部架构：logger 负责发、handler 负责送到哪、formatter 负责长什么样。以及两个经典坑——不要在每模块 basicConfig、重复输出。

## 三者的分工

把 logging 想象成邮局系统：

- **Logger**：发件人。你调用 `logger.info("...")`，就是往系统里投递一封信
- **Handler**：邮递路线。信送到哪？控制台？文件？网络？
- **Formatter**：信封格式。信上写什么内容？要不要时间？要不要发件人地址？

一个 logger 可以挂多个 handler，实现"控制台看简版、文件存详细版"。

```python
import logging

# 1. 拿到 logger（按名字，方便区分模块）
logger = logging.getLogger("myapp")

# 2. 创建 handler（送到控制台）
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.WARNING)  # 控制台只看 WARNING 及以上

# 3. 创建 formatter
fmt = logging.Formatter("%(asctime)s [%(levelname)s] %(message)s")
console_handler.setFormatter(fmt)

# 4. 把 handler 挂到 logger 上
logger.addHandler(console_handler)
logger.setLevel(logging.DEBUG)  # logger 自己的级别闸门

logger.debug("调试信息")     # 被 logger 放行，但被 handler 拦截
logger.warning("警告信息")   # 两层都放行，输出
```

输出：

```
2026-09-28 10:30:00 [WARNING] 警告信息
```

**有两个关卡**：logger 的级别是总闸（DEBUG，全放行），handler 的级别是分闸（WARNING，只放警告以上）。消息要过两关才输出。

## getLogger 的命名空间

`getLogger("a.b.c")` 这种带点的名字不是装饰，它构成**层级关系**，子 logger 默认会把消息传给父 logger 处理。

```python
import logging

parent = logging.getLogger("parent")
child = logging.getLogger("parent.child")

handler = logging.StreamHandler()
handler.setFormatter(logging.Formatter("%(name)s - %(levelname)s - %(message)s"))
parent.addHandler(handler)
parent.setLevel(logging.DEBUG)

child.debug("来自子 logger 的消息")
```

输出：

```
parent.child - DEBUG - 来自子 logger 的消息
```

**父子关系是自动建立的**：名字以点分隔，子 logger 的消息默认会冒泡给父 logger 的 handler 处理。这就是模块级日志能统一管控的原理。

## 翻车现场：每个模块都 basicConfig

王五的项目有 20 个文件，每个文件开头都写了 `logging.basicConfig(...)`，结果只有第一个文件的配置生效，其余全被忽略。

```python
# a.py
import logging
logging.basicConfig(level=logging.DEBUG, format="A: %(message)s")

# b.py
import logging
logging.basicConfig(level=logging.INFO, format="B: %(message)s")

# main.py
import a  # 先导入 a
import b  # 再导入 b

import logging
logging.info("测试")
```

输出：

```
A: 测试
```

**`basicConfig` 是全局唯一的，只生效一次。** 在多个模块里反复调用，后面的全是空操作。正确做法：只在程序入口（如 `main.py`）配置一次，其他模块用 `getLogger(__name__)` 获取自己的 logger。

```python
# utils.py（子模块的正确写法）
import logging
logger = logging.getLogger(__name__)  # 用模块名做 logger 名

def do_something():
    logger.info("utils 里干活了")

# main.py（入口，配置一次）
import logging
logging.basicConfig(level=logging.INFO, format="%(name)s - %(message)s")
import utils
utils.do_something()
```

输出：

```
__main__ - utils 里干活了
```

## 翻车现场：日志重复输出

这是新手最高频的坑：同一条日志打印了两遍、三遍。

```python
import logging

logger = logging.getLogger("dup")

# 第一次 addHandler
h1 = logging.StreamHandler()
h1.setFormatter(logging.Formatter("handler1: %(message)s"))
logger.addHandler(h1)

# 第二次 addHandler（重复！）
h2 = logging.StreamHandler()
h2.setFormatter(logging.Formatter("handler2: %(message)s"))
logger.addHandler(h2)

logger.warning("一条消息")
```

输出：

```
handler1: 一条消息
handler2: 一条消息
```

**同一个 logger 被加了多个 handler，消息就会按 handler 数量重复输出。** 在交互式环境或重复导入时尤其容易踩。

更隐蔽的是 **propagate**：子 logger 的消息默认会传给父 logger（直到 root），如果父 logger 也有 handler，就会重复。

```python
import logging

root_handler = logging.StreamHandler()
root_handler.setFormatter(logging.Formatter("root: %(message)s"))
logging.getLogger().addHandler(root_handler)  # root logger 加了 handler

child = logging.getLogger("child")
child_handler = logging.StreamHandler()
child_handler.setFormatter(logging.Formatter("child: %(message)s"))
child.addHandler(child_handler)

child.warning("消息")  # 既走 child handler，又冒泡到 root handler
```

输出：

```
child: 消息
root: 消息
```

**解决办法有两个**：要么把子 logger 的 `propagate` 设为 `False`，要么只在 root logger 上配置 handler、子 logger 不重复加。

```python
child.propagate = False  # 不再冒泡给父 logger
child.warning("消息")    # 只输出一次
```

输出：

```
child: 消息
```

## 翻车现场：basicConfig 之后再 addHandler 的级别问题

```python
import logging

logging.basicConfig(level=logging.DEBUG)
logger = logging.getLogger()

# basicConfig 已经给 root 加了一个 handler
# 现在又手动加一个
h = logging.StreamHandler()
h.setLevel(logging.ERROR)
logger.addHandler(h)

logger.info("info 消息")
logger.error("error 消息")
```

输出：

```
INFO:root:info 消息
ERROR:root:error 消息
ERROR:root:error 消息
```

**`info` 只出现一次（basicConfig 的 handler 输出），`error` 出现两次**——因为两个 handler 都放行了 error。这就是重复输出的又一个来源：忘记 basicConfig 已经配过 handler。

## 小结

- Logger 发消息、Handler 决定送到哪、Formatter 决定长什么样，三者各司其职
- 消息要过两关：logger 的级别（总闸）和 handler 的级别（分闸）
- `getLogger("a.b.c")` 的点号构成父子层级，子消息默认冒泡给父
- **不要在每个模块都 basicConfig**，只在入口配置一次，子模块用 `getLogger(__name__)`
- basicConfig 全局只生效一次，重复调用无效
- 重复输出的两大元凶：同一 logger 重复 addHandler、子 logger 冒泡到父 logger 的 handler
- 解决重复：检查 handler 数量、必要时设 `propagate = False`

  import logging

  logger = logging.getLogger("shop")

  console = logging.StreamHandler()
  console.setLevel(logging.WARNING)
  console.setFormatter(logging.Formatter("控制台: %(message)s"))
  logger.addHandler(console)

  logger.setLevel(logging.DEBUG)

  logger.warning("库存不足")

  # 返回 handler 数量
  print(len(logger.handlers))

- assert "控制台: 库存不足" in __out
