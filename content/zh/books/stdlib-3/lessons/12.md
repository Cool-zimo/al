# defaultdict 与 OrderedDict

> 这一课解决"字典里套列表/套字典"这种嵌套结构的写法问题。`defaultdict` 让你不用判空就能直接往里塞；`OrderedDict` 保留插入顺序——但既然 Python 3.7+ 的普通 dict 已经有序，它现在只剩特定场景有用。

## 手写分组为什么啰嗦

李四有一批订单，想按"客户名"分组，把每个客户的订单号归到一起：

```python
orders = [
    ("张三", "DD001"), ("李四", "DD002"),
    ("张三", "DD003"), ("王五", "DD004"), ("李四", "DD005"),
]

# 手写分组：要先判断键是否存在
groups = {}
for name, oid in orders:
    if name not in groups:
        groups[name] = []
    groups[name].append(oid)

print(groups)
```

输出：

```
{'张三': ['DD001', 'DD003'], '李四': ['DD002', 'DD005'], '王五': ['DD004']}
```

那个 `if name not in groups` 的判断，每个分组逻辑都要写一遍，烦且容易漏。

## defaultdict：键不存在时自动造一个默认值

`defaultdict` 接收一个"工厂函数"——当访问不存在的键时，它会**自动调用这个函数造一个默认值**塞进去。

```python
from collections import defaultdict

orders = [
    ("张三", "DD001"), ("李四", "DD002"),
    ("张三", "DD003"), ("王五", "DD004"), ("李四", "DD005"),
]

groups = defaultdict(list)      # 工厂函数是 list，默认值是 []
for name, oid in orders:
    groups[name].append(oid)    # 不用判断键是否存在

print(dict(groups))             # 转成普通 dict 方便打印
```

输出：

```
{'张三': ['DD001', 'DD003'], '李四': ['DD002', 'DD005'], '王五': ['DD004']}
```

**这就是全部差别**：`defaultdict(list)` 的意思是"这个字典里每个值默认是个空列表"。于是你可以放心地 `.append()`，永远不用担心 `KeyError`。

## 翻车现场：用 list 当默认值的结果

张三想给每个客户存一个订单数量，误把 `list` 传给了需要"数字默认值"的场景：

```python
from collections import defaultdict

# WRONG：想统计每个客户订单数，却用了 list 做工厂
d = defaultdict(list)
d["张三"].append("DD001")
d["张三"].append("DD002")
print(d["张三"])
```

输出：

```
['DD001', 'DD002']
```

能跑，但不是想要的——他要的是**数量**。统计数量该用 `int`（默认值是 `0`）：

```python
from collections import defaultdict

count = defaultdict(int)      # 默认值是 0
items = ["苹果", "香蕉", "苹果", "橘子", "香蕉", "苹果"]
for it in items:
    count[it] += 1            # 0 += 1 完全合法

print(dict(count))
```

输出：

```
{'苹果': 3, '香蕉': 2, '橘子': 1}
```

**`int` 的默认值是 `0`，`list` 的默认值是 `[]`，`set` 的默认值是 `set()`**。选哪个工厂，取决于你要"数数"、"存列表"还是"存集合"。

## 自己写工厂函数

工厂函数不必是内置类型，任何**无参可调用对象**都行：

```python
from collections import defaultdict

# 自定义工厂：默认值是一个"带初始值的结构"
def make_record():
    return {"count": 0, "items": []}

db = defaultdict(make_record)
db["张三"]["count"] += 1
db["张三"]["items"].append("DD001")
db["李四"]["count"] += 1

print(dict(db))
```

输出：

```
{'张三': {'count': 1, 'items': ['DD001']}, '李四': {'count': 1, 'items': []}}
```

注意工厂函数**不带括号**：传的是 `make_record` 这个函数对象本身，不是 `make_record()` 的结果。传结果会让所有键共享**同一个对象**，这是下一条翻车现场。

## 翻车现场：工厂函数写成"返回同一个对象"

```python
from collections import defaultdict

# WRONG：lambda 每次返回同一个列表对象
shared = []
d = defaultdict(lambda: shared)

d["a"].append(1)
d["b"].append(2)
print("a:", d["a"])
print("b:", d["b"])
```

输出：

```
a: [1, 2]
b: [1, 2]
```

`a` 和 `b` 指向**同一个列表**，改一个全变。因为 `lambda: shared` 每次都返回同一个 `shared` 对象。

**正确做法**：让工厂每次**新建**一个对象：

```python
from collections import defaultdict

d = defaultdict(list)          # list 每次调用都新建空列表
d["a"].append(1)
d["b"].append(2)
print("a:", d["a"])
print("b:", d["b"])
```

输出：

```
a: [1]
b: [2]
```

`list`、`dict`、`set` 这些内置类型本身**每次调用都返回新对象**，所以 `defaultdict(list)` 天然安全。坑只出现在你自己写的工厂函数返回了外部变量。

## OrderedDict：曾经很重要，现在没那么重要了

Python 3.7 起，**普通 `dict` 就已经保证插入顺序**。所以 `OrderedDict` 的核心卖点——"记住元素添加顺序"——已经被普通字典吸收。

```python
# Python 3.7+ 普通 dict 就有序
d = {}
d["张三"] = 1
d["李四"] = 2
d["王五"] = 3
print(list(d.keys()))        # 顺序被保留
```

输出：

```
['张三', '李四', '王五']
```

**那 OrderedDict 还有什么用？** 三个场景：

1. **`move_to_end(key)` 和 `popitem(last=...)`**：能精确控制"谁在最前/最后"，普通 dict 没有这套 API。
2. **`==` 比较时考虑顺序**：两个 OrderedDict 顺序不同就算不相等，普通 dict 不看顺序。
3. **LRU 缓存类场景**：需要频繁调整顺序时，OrderedDict 的 `move_to_end` 是 O(1)。

```python
from collections import OrderedDict

od = OrderedDict()
od["a"] = 1
od["b"] = 2
od["c"] = 3

od.move_to_end("a")          # 把 a 移到末尾
print(list(od.items()))

od.move_to_end("c", last=False)  # 把 c 移到开头
print(list(od.items()))
```

输出：

```
[('b', 2), ('c', 3), ('a', 1)]
[('c', 3), ('b', 2), ('a', 1)]
```

## 翻车现场：以为 dict 一直都有序

这个坑是**版本相关的**。在 Python 3.6 及更早版本，普通 `dict` 不保证顺序；3.7 起才成为语言规范。写代码时要明确知道：你依赖顺序，就要么用 3.7+，要么显式用 `OrderedDict`。

```python
import sys
print("当前 Python 版本:", sys.version_info[:2])
```

输出（具体版本随环境变化）：

```
当前 Python 版本: (3, 11)
```

**现实建议**：新项目直接用普通 `dict` 享受有序性；只有需要 `move_to_end` 这类精确顺序控制、或与旧代码保持兼容时才用 `OrderedDict`。

## 小结

- `defaultdict(工厂)` 在键不存在时自动调用工厂造默认值，省掉判空样板代码
- 工厂选 `int`（默认 0）做计数、`list`（默认 []）做分组、`set`（默认 set()）做去重集合
- 自定义工厂要**每次返回新对象**，返回外部变量会导致所有键共享同一对象
- Python 3.7+ 普通 `dict` 已保证插入顺序，`OrderedDict` 的核心卖点被吸收
- `OrderedDict` 现在主要用于：精确顺序控制（`move_to_end`/`popitem`）、顺序敏感的相等比较
