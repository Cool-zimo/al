# 项目设计：日志分析 CLI 工具

> 这一课开始做一件真正"拿得出手"的事——把前面 25 课的知识串成一个完整项目：一个能跑在命令行里的日志分析工具。

## 我们要做什么

设想一个场景：张三负责维护公司的 Web 服务，每天产生几百 MB 的日志文件。他想知道"今天有多少 ERROR 级别日志""哪个小时错误最多""出现频率最高的 10 个异常是什么"。手动翻日志不现实，Excel 也装不下。我们要做的工具就是解决这个问题的。

工具的名字叫 `logalyzer`（log analyzer 的缩写）。它能：
1. 读取一个或多个日志文件
2. 用正则解析每一行，提取时间、日志级别、模块名、消息内容
3. 做多维度统计（级别分布、小时分布、Top N 错误）
4. 输出到控制台（表格形式）或导出为 JSON / CSV
5. 通过命令行参数控制所有行为

这不是玩具项目。它的架构思路（分层、解析、统计、输出、CLI 入口）和你在公司里见到的工具是同一套。

## 四层架构

好的项目不是把所有代码塞进一个 `main.py`，而是分层。我们的工具分四层：

```
┌──────────────────────────────────────────────┐
│  CLI 层  (cli.py)                            │
│  argparse 子命令，参数解析，调用各层           │
├──────────────────────────────────────────────┤
│  输出层  (output.py)                          │
│  控制台表格 / JSON 导出 / CSV 导出            │
├──────────────────────────────────────────────┤
│  统计层  (stats.py)                           │
│  Counter / defaultdict 多维度聚合             │
├──────────────────────────────────────────────┤
│  解析层  (parser.py)                          │
│  正则提取时间/级别/模块/消息，容错             │
└──────────────────────────────────────────────┘
```

每一层只做一件事，只依赖下一层。**解析层不知道数据要输出到 CSV 还是控制台，输出层不知道数据来自文件还是网络**。这种解耦让每一层都可以独立测试。

## 日志格式定义

我们先约定日志格式（这也是真实项目中"先定协议再写代码"的做法）：

```
2026-01-15 10:23:45 [ERROR] [auth] 用户登录失败: user_id=10086
2026-01-15 10:23:46 [INFO]  [order] 订单创建成功: order_id=5001
2026-01-15 10:24:01 [WARN]  [payment] 支付超时: order_id=5001, timeout=30s
```

四段信息：**时间** `YYYY-MM-DD HH:MM:SS`、**级别** `INFO/WARN/ERROR/DEBUG`、**模块** `[xxx]`、**消息** 冒号后任意内容。

```python
# logalyzer/parser.py
import re
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self):
        """从时间戳提取小时，用于时间分布统计"""
        return self.timestamp.split(" ")[1].split(":")[0]


# 正则模式：时间 级别 模块 消息
LOG_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)


def parse_line(line: str) -> LogEntry | None:
    """解析单行日志，失败返回 None（不抛异常）"""
    line = line.strip()
    if not line:
        return None
    match = LOG_PATTERN.match(line)
    if match is None:
        return None
    return LogEntry(
        timestamp=match.group(1),
        level=match.group(2),
        module=match.group(3),
        message=match.group(4),
    )


def parse_lines(lines: list[str]) -> tuple[list[LogEntry], list[str]]:
    """解析多行日志，返回 (成功解析的条目, 解析失败的行)"""
    entries = []
    failed = []
    for line in lines:
        entry = parse_line(line)
        if entry is None:
            failed.append(line)
        else:
            entries.append(entry)
    return entries, failed
```

```python
# logalyzer/stats.py
from collections import Counter, defaultdict
from .parser import LogEntry


def level_distribution(entries: list[LogEntry]) -> dict[str, int]:
    """统计各级别日志数量"""
    counter = Counter(entry.level for entry in entries)
    return dict(counter)


def hourly_distribution(entries: list[LogEntry]) -> dict[str, int]:
    """统计每小时日志数量"""
    counter = Counter(entry.hour for entry in entries)
    return dict(sorted(counter.items()))


def top_errors(entries: list[LogEntry], n: int = 10) -> list[tuple[str, int]]:
    """统计出现频率最高的错误消息 Top N（仅 ERROR 级别）"""
    counter = Counter(entry.message for entry in entries if entry.level == "ERROR")
    return counter.most_common(n)


def module_error_count(entries: list[LogEntry]) -> dict[str, int]:
    """按模块统计 ERROR 数量"""
    result = defaultdict(int)
    for entry in entries:
        if entry.level == "ERROR":
            result[entry.module] += 1
    return dict(result)
```

```python
# logalyzer/output.py
import json
import csv
import io
from .parser import LogEntry


def format_table(entries: list[LogEntry], max_rows: int = 20) -> str:
    """控制台表格输出"""
    lines = []
    lines.append(f"{'时间':<22} {'级别':<8} {'模块':<10} 消息")
    lines.append("-" * 80)
    for entry in entries[:max_rows]:
        msg = entry.message[:50]
        lines.append(f"{entry.timestamp:<22} {entry.level:<8} {entry.module:<10} {msg}")
    if len(entries) > max_rows:
        lines.append(f"... 共 {len(entries)} 条，仅显示前 {max_rows} 条")
    return "\n".join(lines)


def export_json(data: dict, indent: int = 2) -> str:
    """导出为 JSON 字符串"""
    return json.dumps(data, ensure_ascii=False, indent=indent)


def export_csv(rows: list[dict], headers: list[str]) -> str:
    """导出为 CSV 字符串"""
    buf = io.StringIO()
    writer = csv.DictWriter(buf, fieldnames=headers)
    writer.writeheader()
    writer.writerows(rows)
    return buf.getvalue()
```

```python
# logalyzer/cli.py
import argparse
import logging
from .parser import parse_lines
from .stats import (
    level_distribution, hourly_distribution,
    top_errors, module_error_count,
)
from .output import format_table, export_json, export_csv


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="logalyzer",
        description="日志分析 CLI 工具 v0.1.0",
    )
    subparsers = parser.add_subparsers(dest="command", help="子命令")

    # analyze 子命令
    p_analyze = subparsers.add_parser("analyze", help="解析并统计日志")
    p_analyze.add_argument("--top", type=int, default=10, help="Top N 错误数量")

    # export 子命令
    p_export = subparsers.add_parser("export", help="导出统计结果为 JSON/CSV")
    p_export.add_argument("format", choices=["json", "csv"], help="导出格式")

    # stats 子命令
    p_stats = subparsers.add_parser("stats", help="显示统计摘要")
    p_stats.add_argument("--verbose", "-v", action="store_true", help="详细输出")

    return parser


def main(argv: list[str] | None = None) -> int:
    parser = build_parser()
    args = parser.parse_args(argv)
    logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

    if args.command is None:
        parser.print_help()
        return 0
    # 后面几课逐步填充各子命令的实现
    logging.info(f"执行子命令: {args.command}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## 为什么这样分层

- **可测试性**：解析层输入是字符串列表、输出是 `LogEntry` 列表，不涉及文件 IO，可以直接单测
- **可替换性**：明天要把输出改成 HTML 报告？只改输出层。后天要支持 JSON 格式日志输入？只改解析层
- **职责清晰**：看一眼目录就知道项目在干什么，新人接手不会迷路

## 小结

- 真实项目要分层：解析 / 统计 / 输出 / CLI，各层职责单一
- 层与层之间用纯数据结构传递（dataclass / dict / list），不直接传递文件句柄
- 先定数据格式再写代码，避免中途返工
- 每一层可独立测试，是分层架构最大的隐性收益
- 日志格式约定为：`时间 [级别] [模块] 消息`
