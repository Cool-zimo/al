# 为什么要有正则表达式

> 这一课解决"从一段乱糟糟的文本里抠出想要的那一小块"的问题。你会明白 `split` 和 `find` 写起来有多啰嗦，而正则一句话就能表达"找一个手机号"。

## 字符串方法干到一半就废了

张三拿到一段客服聊天记录，要从中提取所有手机号。他第一反应是写个循环，逐个字符判断：

```python
text = "客户张三 13812345678 咨询发货，另一个客户 13987654321 已签收，备用 0571-88123456"

# 想找出所有手机号，用字符串方法怎么写？
phones = []
i = 0
while i < len(text):
    # 找到一个"1"开头、后面跟着10个数字的片段
    if text[i] == '1' and i + 11 <= len(text):
        seg = text[i:i+11]
        if seg[1:].isdigit():
            phones.append(seg)
    i += 1

print(phones)
```

输出：

```
['13812345678', '13987654321']
```

代码跑通了，但写的人累，读的人更累。这段代码只处理了"1开头+10位数字"这一种格式，一旦要支持带区号的固话、带分机号、中间带横杠的写法，就得往里叠 `if`，很快就成一锅浆糊。

**字符串方法的本质困境**：`find`、`split`、`startswith`、`isdigit` 这些工具都只能表达"一个非常具体的动作"，而"符合某种**模式**的文本"这种描述，它们天生表达不出来。

## 正则：把"模式"写成一句话

同样的需求，用正则写：

```python
import re

text = "客户张三 13812345678 咨询发货，另一个客户 13987654321 已签收"
phones = re.findall(r'1[3-9]\d{9}', text)
print(phones)
```

输出：

```
['13812345678', '13987654321']
```

`r'1[3-9]\d{9}'` 这一串小符号就是**模式**：一个 `1`，后面跟一个 `3` 到 `9` 之间的数字，再跟 9 个任意数字。正则引擎读这句话，自动帮你扫完整段文本、找出所有匹配。

这就是正则的价值：**它把"描述一种文本长相"这件事，变成了一行可读、可复用的表达式。**

| 需求 | 只用字符串方法 | 用正则 |
|---|---|---|
| 找出所有手机号 | 手写循环 + 一堆 `if` | `re.findall(r'1[3-9]\d{9}', text)` |
| 判断是不是合法日期 `2026-09-28` | 切三段分别 `isdigit`、判断范围 | `re.fullmatch(r'\d{4}-\d{2}-\d{2}', s)` |
| 把多个空格压成一个 | 循环里 `while '  ' in s` | `re.sub(r' +', ' ', s)` |

## 翻车现场：忘了写循环，只匹配到一次

```python
import re

text = "电话 13812345678 和 13987654321"

# WRONG：search 只返回第一个匹配
m = re.search(r'1[3-9]\d{9}', text)
print(m.group())
```

输出：

```
13812345678
```

第二个号码不见了。`search` 只找**第一个**，`findall` 才找**所有**。这两个函数名看着像，行为差了一截，初学者几乎必踩。

**正确做法**：要全部就写 `findall`，只要第一个才用 `search`。

```python
import re

text = "电话 13812345678 和 13987654321"
print(re.findall(r'1[3-9]\d{9}', text))   # 全部
```

输出：

```
['13812345678', '13987654321']
```

## 翻车现场：把正则当字符串拼，转义满天飞

```python
import re

text = "价格是 99.9 元"
# WRONG：字符串里的 \. 被当成转义序列，正则收到的是 "99.9" 里的点被吃掉了
pat = '99\.9'
print(re.findall(pat, text))
```

输出：

```
['99.9']
```

这次"碰巧"对了，但只是因为 `\.` 不是 Python 字符串的特殊转义。真正出事的是这种：

```python
import re

text = "路径 C:\\new\\test"
# WRONG：'\n' 在字符串里是换行符，正则收到的已经不是反斜杠 n 了
pat = '\new'          # 实际是换行符 + 'ew'
print(re.findall(pat, text))
```

报错或匹配不到。正则里反斜杠是主力符号（`\d` `\w` `\s` `\b`），而 Python 字符串里反斜杠也是转义符，**两层转义撞在一起就是灾难**。

**正确做法**：所有正则字符串一律加 `r` 前缀，变成原始字符串。`r'\n'` 就是"反斜杠加 n"两个字符，不会被 Python 吃掉。

```python
import re

text = "路径 C:\\new\\test"
pat = r'\new'          # 原始字符串：反斜杠和 n 都是字面的
print(re.findall(pat, text))
```

## 正则能做什么、不能做什么

正则擅长的是**"按模式找文本"**这一类事：

- 校验：这个字符串是不是符合某个格式（手机号、邮箱、身份证）
- 提取：从一段文本里抠出想要的部分
- 替换：把符合某种模式的地方统一改成别的
- 切分：按"一个或多个空格""连续的逗号"这种不规则的分隔符切开

正则**不擅长**的是有结构、有嵌套的东西。比如解析一段 HTML 标签层级、解析 JSON。那种活交给专门的解析器（后面章节会讲 `html.parser`，第二册讲过 `json`）。

一句话总结：**正则适合"一维的文本模式"，不适合"有层级的树形结构"。**

## 一个简单的端到端例子

下面模拟一个真实场景：一条订单备注里混着姓名、电话、金额，要提取出电话和金额。

```python
import re

note = "收货人张三, 电话13812345678, 实付金额 299.5 元, 备注尽快送达"

phone = re.search(r'1[3-9]\d{9}', note)
amount = re.search(r'(\d+(\.\d+)?)\s*元', note)

print("电话:", phone.group() if phone else "无")
print("金额:", amount.group(1) if amount else "无")
```

输出：

```
电话: 13812345678
金额: 299.5
```

注意金额那句正则：`\d+(\.\d+)?` 表示"一串数字，后面可选地跟一个小数点和更多数字"。`\s*元` 表示"零个或多个空白，然后是元字"。整句把"299.5 元"这种带可选空格的写法都兜住了。

## 小结

- 字符串方法只能表达"一个具体动作"，描述"一种文本模式"必须用正则
- `re.search` 只找第一个匹配，`re.findall` 找全部，名字像、行为差很远
- **正则字符串永远加 `r` 前缀**，否则反斜杠会被 Python 字符串转义吃掉
- 正则擅长"按模式找文本"：校验、提取、替换、切分
- 正则不擅长有嵌套结构的文本（HTML、JSON），那种交给专门解析器
