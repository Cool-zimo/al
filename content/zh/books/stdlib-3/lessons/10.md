# 实战：日志解析器

> 这一课把正则的前 9 课串成一件能用的东西：一个日志解析器。输入是一堆日志行，输出是"时间、级别、消息"的结构化记录，再按级别统计数量。这是正则最典型、最真实的应用场景。

## 先看看真实的日志长什么样

```python
log_lines = """2026-09-28 10:20:35 ERROR 数据库连接超时，重试中
2026-09-28 10:21:02 WARN 磁盘使用率 87%，建议清理
2026-09-28 10:22:15 INFO 用户张三登录成功
2026-09-28 10:22:18 ERROR 订单 DD20260927001 支付回调失败
2026-09-28 10:25:00 INFO 清理任务启动
2026-09-28 10:25:01 ERROR 清理任务执行异常 java.lang.NullPointerException
2026-09-28 10:30:45 WARN 内存占用 92%
2026-09-28 10:31:00 INFO 服务健康检查通过"""

print(f"共 {len(log_lines.splitlines())} 行日志")
```

输出：

```
共 8 行日志
```

每行结构固定：日期 + 空格 + 时间 + 空格 + 级别 + 空格 + 消息。这种"格式高度一致"的文本，正是正则的主场。

## 设计一条能拆字段的正则

用命名分组，让每个字段都有名字：

```python
import re

LINE_RE = re.compile(
    r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
    r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
    r'(?P<level>[A-Z]+)\s+'
    r'(?P<msg>.*)'
)

m = LINE_RE.match("2026-09-28 10:20:35 ERROR 数据库连接超时，重试中")
print(m.groupdict())
```

输出：

```
{'date': '2026-09-28', 'time': '10:20:35', 'level': 'ERROR', 'msg': '数据库连接超时，重试中'}
```

`groupdict()` 把命名分组直接变成字典，后续处理就是普通的字典操作——**正则负责把文本变成字典，后面的活交给 Python 自己**。

## 解析成结构化列表

```python
import re

LINE_RE = re.compile(
    r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
    r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
    r'(?P<level>[A-Z]+)\s+'
    r'(?P<msg>.*)'
)

records = []
for line in log_lines.splitlines():
    m = LINE_RE.match(line.strip())
    if m:
        records.append(m.groupdict())

print(f"成功解析 {len(records)} 条记录")
print("第一条:", records[0])
print("第四条:", records[3])
```

输出：

```
成功解析 8 条记录
第一条: {'date': '2026-09-28', 'time': '10:20:35', 'level': 'ERROR', 'msg': '数据库连接超时，重试中'}
第四条: {'date': '2026-09-28', 'time': '10:22:18', 'level': 'ERROR', 'msg': '订单 DD20260927001 支付回调失败'}
```

**注意那个 `if m`**：正则匹配不到就返回 `None`，真实日志里经常有空行、注释行、异常堆栈（多行），直接 `.groupdict()` 会抛 `AttributeError`。

## 翻车现场：异常堆栈把解析器打崩

真实的错误日志常常是**多行**的：第一行是格式规整的日志头，后面几行是 Java/Python 的堆栈。

```python
import re

multiline_log = """2026-09-28 10:31:00 ERROR 清理任务执行异常
java.lang.NullPointerException
    at com.example.Task.run(Task.java:42)
    at com.example.Main.main(Main.java:10)
2026-09-28 10:32:00 INFO 服务恢复"""

LINE_RE = re.compile(r'(?P<date>\d{4}-\d{2}-\d{2})\s+(?P<time>\d{2}:\d{2}:\d{2})\s+(?P<level>[A-Z]+)\s+(?P<msg>.*)')

for line in multiline_log.splitlines():
    m = LINE_RE.match(line.strip())
    if m:
        print("解析到:", m.group('level'), m.group('msg'))
    else:
        print("跳过（非标准行）:", line.strip()[:40])
```

输出：

```
解析到: ERROR 清理任务执行异常
跳过（非标准行）: java.lang.NullPointerException
跳过（非标准行）:     at com.example.Task.run(Task.java:42)
跳过（非标准行）:     at com.example.Main.main(Main.java:10)
解析到: INFO 服务恢复
```

**这就是正确的处理方式**：不是所有行都符合格式，匹配不上的就跳过（或合并到上一条记录的 msg 里）。强迫每一行都匹配，是解析器的常见死法。

## 按级别统计：Counter 登场

第 11 课会系统讲 `collections.Counter`，这里先借它用一次——统计每个级别出现了多少次：

```python
from collections import Counter

levels = [r['level'] for r in records]
count = Counter(levels)
print(count)
print(f"错误最多，共 {count['ERROR']} 次")
```

输出：

```
Counter({'ERROR': 3, 'INFO': 3, 'WARN': 2})
错误最多，共 3 次
```

**这就是正则的终局价值**：把非结构化的文本变成结构化的记录，再用 Python 的字典、列表推导、`Counter` 去分析。**正则只做"翻译"，分析交给 Python 自己。**

## 翻车现场：日期消息里含有 ERROR 字样被误判

张三的日志消息里提到了别的系统：

```python
import re

line = "2026-09-28 10:20:35 ERROR 上游返回 ERROR_CODE=500"
m = re.match(r'(\d{4}-\d{2}-\d{2})\s+(\d{2}:\d{2}:\d{2})\s+([A-Z]+)\s+(.*)', line)
print("级别:", m.group(3))
print("消息:", m.group(4))
```

输出：

```
级别: ERROR
消息: 上游返回 ERROR_CODE=500
```

消息里的 `ERROR` 没有干扰级别提取，因为模式里**级别后面紧跟空格再是消息**，正则按位置匹配，消息里出现什么字都不影响。这也是为什么"格式固定"的日志特别适合正则：**分隔符是天然的锚点**。

## 完整成品：一个可复用的日志解析器

```python
import re
from collections import Counter

class LogParser:
    LINE_RE = re.compile(
        r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
        r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
        r'(?P<level>[A-Z]+)\s+'
        r'(?P<msg>.*)'
    )

    def __init__(self):
        self.records = []

    def feed(self, text):
        for line in text.splitlines():
            line = line.strip()
            if not line:
                continue
            m = self.LINE_RE.match(line)
            if m:
                self.records.append(m.groupdict())

    def stats(self):
        return dict(Counter(r['level'] for r in self.records))

    def filter_by_level(self, level):
        return [r['msg'] for r in self.records if r['level'] == level]

# 跑一遍
p = LogParser()
p.feed(log_lines)
print("统计:", p.stats())
print("所有错误消息:")
for msg in p.filter_by_level("ERROR"):
    print(" -", msg)
```

输出：

```
统计: {'ERROR': 3, 'INFO': 3, 'WARN': 2}
所有错误消息:
 - 数据库连接超时，重试中
 - 订单 DD20260927001 支付回调失败
 - 清理任务执行异常 java.lang.NullPointerException
```

**这个类只有三个方法，却覆盖了日志解析的完整生命周期**：喂入文本、按行解析、统计与筛选。正则只藏在 `feed` 里，对外暴露的是干净的数据结构。这就是正则该有的位置——**藏在工具内部，而不是散落在业务代码里**。

## 小结

- 日志解析的正则要点：**用分隔符做锚点**，给每个字段命名分组，结果用 `groupdict()` 变字典
- 真实日志含空行、注释、多行堆栈，**必须 `if m` 判空**，不要假设每行都匹配
- 正则只负责"把文本翻译成字典"，分析（统计、筛选）交给 Python 自己的工具
- `Counter` 统计级别数量是日志分析最快的一行代码
- 正则应封装在工具类内部（如 `LogParser`），对外暴露干净接口，而不是散落在业务代码里
