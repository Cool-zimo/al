# 测试组织：一个函数一个测试、边界值、可重复

> 这一课讲测试怎么组织才靠谱：一个函数一个测试、覆盖边界值（空/单个/极大）、以及测试必须能稳定重复跑——别依赖随机和时间。

## 一个函数一个测试

好的测试是"一个测试只验证一件事"。对比两种写法：

```python
# 反面：一个测试验证三件事
def test_cart(self):
    cart = Cart()
    cart.add("apple", 2)
    self.assertEqual(cart.total, 2)        # 验证添加
    cart.remove("apple")
    self.assertEqual(cart.total, 0)        # 验证删除
    cart.apply_coupon("VIP")
    self.assertEqual(cart.discount, 0.1)   # 验证优惠券

# 正面：每个行为一个测试
def test_add_item(self):
    cart = Cart()
    cart.add("apple", 2)
    self.assertEqual(cart.total, 2)

def test_remove_item(self):
    cart = Cart()
    cart.add("apple", 2)
    cart.remove("apple")
    self.assertEqual(cart.total, 0)

def test_apply_coupon(self):
    cart = Cart()
    cart.apply_coupon("VIP")
    self.assertEqual(cart.discount, 0.1)
```

**为什么要拆开？** 因为如果 `remove` 有 bug，第一个写法只报告"test_cart 失败"，你不知道是添加、删除还是优惠券的问题。拆开后直接告诉你 `test_remove_item` 失败，定位时间从 10 分钟变成 10 秒。

## 边界值：空、单个、极大

任何处理集合的函数都要测这几类输入：

```python
import unittest

def average(nums):
    if not nums:
        raise ValueError("列表不能为空")
    return sum(nums) / len(nums)

class TestAverage(unittest.TestCase):
    def test_empty(self):
        # 边界：空列表
        with self.assertRaises(ValueError):
            average([])

    def test_single(self):
        # 边界：只有一个元素
        self.assertEqual(average([42]), 42.0)

    def test_normal(self):
        self.assertEqual(average([1, 2, 3]), 2.0)

    def test_large(self):
        # 边界：极大数值
        self.assertEqual(average([10**15, 10**15]), 10**15)

    def test_negative(self):
        self.assertEqual(average([-2, 2]), 0.0)

    def test_float(self):
        self.assertAlmostEqual(average([0.1, 0.2, 0.3]), 0.2)

if __name__ == "__main__":
    unittest.main()
```

输出：

```
......
----------------------------------------------------------------------
Ran 6 tests in 0.000s

OK
```

**`assertAlmostEqual` 用于浮点数比较**——`0.1 + 0.2` 在计算机里不等于精确的 0.3，用 `==` 会失败。

## 翻车现场：测试依赖随机，结果不稳定

```python
import unittest
import random

def pick_winner(players):
    return random.choice(players)

class TestWinner(unittest.TestCase):
    def test_pick(self):
        players = ["张三", "李四", "王五"]
        winner = pick_winner(players)
        self.assertEqual(winner, "张三")   # 有时通过，有时失败
```

**`random.choice` 的结果不确定**，这个测试有时过有时不过，叫"flakey test"（不稳定测试）。一旦混入 CI，会导致"代码没改但测试红了"的假警报，久而久之没人信测试结果了。

正确做法：**测试时固定随机种子，或者 mock 掉随机源**。

```python
class TestWinner(unittest.TestCase):
    def test_pick(self):
        players = ["张三", "李四", "王五"]
        random.seed(42)   # 固定种子，结果可预测
        winner = pick_winner(players)
        self.assertEqual(winner, "王五")   # 种子 42 下固定结果
```

**或者用 unittest.mock 替换随机源**，让测试完全可控。

## 翻车现场：测试依赖当前时间

```python
import unittest
from datetime import datetime

def is_expired(deadline_str):
    deadline = datetime.fromisoformat(deadline_str)
    return datetime.now() > deadline

class TestExpired(unittest.TestCase):
    def test_expired(self):
        self.assertTrue(is_expired("2020-01-01"))   # 2026 年跑是 True
        self.assertFalse(is_expired("2030-01-01"))  # 2030 年跑会失败
```

**第二个断言在 2030 年会失败**——测试依赖"当前时间"这个外部状态。正确做法：把时间作为参数传入，或者 mock `datetime.now`。

```python
from unittest.mock import patch

class TestExpired(unittest.TestCase):
    def test_expired(self):
        fixed_now = datetime(2026, 9, 28)
        with patch("datetime.datetime") as mock_dt:
            mock_dt.now.return_value = fixed_now
            mock_dt.fromisoformat = datetime.fromisoformat
            self.assertFalse(is_expired("2030-01-01"))
```

**时间、随机数、网络请求——所有外部依赖都要可控**，否则测试不可重复。

## 翻车现场：测试之间有共享状态

```python
import unittest

_database = []   # 模块级共享状态

def test_insert(self):
    _database.append("a")
    self.assertEqual(len(_database), 1)

def test_clear(self):
    _database.clear()
    self.assertEqual(len(_database), 0)
```

**如果先跑 test_clear 再跑 test_insert，test_insert 会因为 `_database` 已经是空的而行为不同。** 测试的执行顺序不应该影响结果。用 `setUp` 重置状态：

```python
class TestDB(unittest.TestCase):
    def setUp(self):
        self.db = []   # 每个测试拿到全新的空列表

    def test_insert(self):
        self.db.append("a")
        self.assertEqual(len(self.db), 1)

    def test_clear(self):
        self.db.append("x")
        self.db.clear()
        self.assertEqual(len(self.db), 0)
```

## 翻车现场：assertAlmostEqual 的精度陷阱

```python
import unittest

class TestFloat(unittest.TestCase):
    def test_money(self):
        result = 0.1 + 0.2
        self.assertEqual(result, 0.3)   # 失败！
```

输出：

```
FAIL: test_money
AssertionError: 0.30000000000000004 != 0.3
```

**浮点精度问题**。金融计算别用 float，用 `decimal.Decimal`；测试里用 `assertAlmostEqual(actual, expected, places=2)` 限定精度。

## 小结

- 一个测试只验证一件事，出问题时直接定位到具体行为
- 边界值必测：空列表、单个元素、极大/极小数、负数、浮点数
- 浮点数比较用 `assertAlmostEqual`，不要用 `==`
- 测试不能依赖随机和当前时间，否则不可重复
- 固定随机种子或用 mock 隔离外部依赖
- 测试间不能有共享状态，用 setUp 确保每个测试拿到干净环境
- 不可重复的测试（flakey test）比没有测试更糟——它会让人不再信任测试

## 随堂练习

```quiz
type: code
q: 写一个函数 safe_divide 和它的测试。safe_divide(a, b) 在 b==0 时返回 None，否则返回 a/b。写三个测试：test_normal（10/2==5）、test_zero（b=0 返回 None）、test_float（3/2==1.5，用 assertAlmostEqual）。用 unittest.TestCase 组织。
starter: |
  import unittest

  def safe_divide(a, b):
      if b == 0:
          return None
      return a / b

  class TestSafeDivide(unittest.TestCase):
      def test_normal(self):
          self.assertEqual(safe_divide(10, 2), 5)

      def test_zero(self):
          self.assertIsNone(safe_divide(10, 0))

      def test_float(self):
          self.assertAlmostEqual(safe_divide(3, 2), 1.5)

  if __name__ == "__main__":
      unittest.main()
tests:
- assert "test_normal" in __out or "Ran 3 tests" in __out
- assert "assertIsNone" in __out
hint: 三个 test_ 方法分别用 assertEqual、assertIsNone、assertAlmostEqual。
explain: 这题覆盖正常、边界（除零）、浮点三种场景，是边界值测试的实操。
```
