# unittest 基础：用框架写规范测试

> 这一课讲 Python 标准库自带的 `unittest` 框架：TestCase、assertEqual/assertTrue/assertRaises，以及 setUp/tearDown 和运行方式。

## 从 assert 到 TestCase

上一课用裸 `assert` 做测试，问题是：一个失败后面全不跑了，也没有汇总报告。`unittest` 把测试组织成类和方法：

```python
import unittest

def add(a, b):
    return a + b

class TestAdd(unittest.TestCase):
    def test_normal(self):
        self.assertEqual(add(1, 2), 3)

    def test_zero(self):
        self.assertEqual(add(0, 0), 0)

    def test_negative(self):
        self.assertEqual(add(-1, 1), 0)

if __name__ == "__main__":
    unittest.main()
```

输出：

```
...
----------------------------------------------------------------------
Ran 3 tests in 0.000s

OK
```

**三个点代表三个测试通过**。`TestCase` 是容器，`test_` 开头的方法自动被发现和执行。

## 常用断言方法

| 方法 | 含义 | 例子 |
|---|---|---|
| `assertEqual(a, b)` | a == b | `self.assertEqual(add(1,2), 3)` |
| `assertNotEqual(a, b)` | a != b | `self.assertNotEqual(x, 0)` |
| `assertTrue(x)` | x 为真 | `self.assertTrue(result)` |
| `assertFalse(x)` | x 为假 | `self.assertFalse(is_empty)` |
| `assertIn(a, b)` | a 在 b 中 | `self.assertIn("error", msg)` |
| `assertRaises(Exc)` | 抛出指定异常 | `with self.assertRaises(ZeroDivisionError):` |
| `assertIsNone(x)` | x is None | `self.assertIsNone(result)` |
| `assertGreater(a, b)` | a > b | `self.assertGreater(score, 60)` |

```python
import unittest

def divide(a, b):
    if b == 0:
        raise ValueError("除数不能为 0")
    return a / b

class TestDivide(unittest.TestCase):
    def test_normal(self):
        self.assertEqual(divide(6, 3), 2.0)

    def test_raises(self):
        with self.assertRaises(ValueError):
            divide(1, 0)

    def test_in_result(self):
        result = divide(7, 2)
        self.assertIn("3.5", str(result))

if __name__ == "__main__":
    unittest.main()
```

输出：

```
...
----------------------------------------------------------------------
Ran 3 tests in 0.000s

OK
```

**`assertRaises` 用 with 语句**，验证代码确实抛出了预期的异常。

## setUp 和 tearDown：测试前后的准备和清理

有些测试需要先建数据库连接、创建临时文件、启动服务，测完要关连接、删文件。`setUp` 在每个测试方法**之前**运行，`tearDown` 在每个测试方法**之后**运行：

```python
import unittest
import tempfile
import os

class TestFileOps(unittest.TestCase):
    def setUp(self):
        # 每个测试前创建一个临时文件
        self.fd, self.path = tempfile.mkstemp()
        with os.fdopen(self.fd, "w") as f:
            f.write("hello")

    def tearDown(self):
        # 每个测试后删除临时文件
        os.remove(self.path)

    def test_read(self):
        with open(self.path) as f:
            self.assertEqual(f.read(), "hello")

    def test_append(self):
        with open(self.path, "a") as f:
            f.write(" world")
        with open(self.path) as f:
            self.assertEqual(f.read(), "hello world")

if __name__ == "__main__":
    unittest.main()
```

输出：

```
..
----------------------------------------------------------------------
Ran 2 tests in 0.001s

OK
```

**setUp/tearDown 确保每个测试都有干净的初始状态**，测试之间互不干扰。

## 运行方式

除了 `unittest.main()`，还可以从命令行运行：

```bash
# 运行整个模块
python -m unittest test_file.py

# 运行指定测试类
python -m unittest test_file.TestAdd

# 运行指定测试方法
python -m unittest test_file.TestAdd.test_normal

# 详细输出
python -m unittest -v test_file.py
```

**`-v` 是 verbose**，会列出每个测试方法名和结果，调试时很有用。

## 翻车现场：测试方法名不以 test_ 开头

```python
import unittest

class TestMath(unittest.TestCase):
    def check_add(self):           # 不以 test 开头！
        self.assertEqual(1 + 1, 2)

    def test_sub(self):
        self.assertEqual(1 - 1, 0)

if __name__ == "__main__":
    unittest.main()
```

输出：

```
.
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK
```

**只跑了 1 个测试**，`check_add` 被忽略了——unittest 只自动发现 `test` 开头的方法。这是新手最常踩的坑，测试方法名必须以 `test` 开头。

## 翻车现场：setUp 里抛异常，所有测试都失败

```python
import unittest

class TestDB(unittest.TestCase):
    def setUp(self):
        raise ConnectionError("数据库连接失败")   # 连接不了

    def test_query(self):
        self.assertEqual(1, 1)

    def test_insert(self):
        self.assertEqual(2, 2)

if __name__ == "__main__":
    unittest.main()
```

输出：

```
EE
======================================================================
ERROR: test_query
----------------------------------------------------------------------
ConnectionError: 数据库连接失败
----------------------------------------------------------------------
Ran 2 tests in 0.000s

FAILED (errors=2)
```

**setUp 抛异常会导致该测试类里所有方法都被记为 ERROR**，因为前置条件没满足，后面的代码根本没执行。这不是被测代码的问题，而是测试环境的问题。排查时要先看 setUp。

## 翻车现场：忘记调用父类 setUp

```python
import unittest

class TestBase(unittest.TestCase):
    def setUp(self):
        self.data = [1, 2, 3]

class TestChild(TestBase):
    def setUp(self):
        # 忘了 super().setUp()
        self.extra = [4, 5, 6]

    def test_something(self):
        self.assertEqual(len(self.data) + len(self.extra), 6)  # AttributeError!
```

**子类覆盖了 setUp 却没调 `super().setUp()`，父类的初始化没执行**，`self.data` 不存在。修正：

```python
    def setUp(self):
        super().setUp()
        self.extra = [4, 5, 6]
```

## 小结

- `unittest.TestCase` 是测试的容器，`test_` 开头的方法自动发现执行
- 断言方法：`assertEqual`、`assertTrue`、`assertIn`、`assertRaises` 等
- `assertRaises` 用 with 语句验证预期异常
- `setUp` 每个测试前运行（准备），`tearDown` 每个测试后运行（清理）
- 运行方式：代码中 `unittest.main()` 或命令行 `python -m unittest`
- 测试方法名必须以 `test` 开头，否则被忽略
- 子类覆盖 setUp 必须调 `super().setUp()`

  import inspect

  def collect_test_names(cls):
      methods = [name for name, _ in inspect.getmembers(cls, predicate=inspect.isfunction)
