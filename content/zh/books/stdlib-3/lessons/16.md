# logging 基础：别再靠 print 调试了

> 这一课解决"为什么 print 不够用"以及 logging 五个级别和 basicConfig 的正确用法。`print` 是随手写的便签，`logging` 是带级别、带时间、能开关的正式日志系统。

## 为什么 print 不够

张三写了个下单脚本，出问题了要排查，他满屏 `print("到这里了")`、`print(x)`。上线前得一行行删掉，忘了删就把内部数据打印给了用户看。更糟的是：

- **没法分级别**：哪句是"出错必须看"，哪句是"调试随便看看"，全混在一起
- **没法关掉**：想让调试信息只在开发时显示、生产时消失，做不到
- **没有时间和位置**：打印 `Error!` 却不知道是什么时间、哪个文件第几行发生的
- **输出目的地单一**：只能打印到控制台，没法同时写文件

```python
# 张三的 print 调试
def process_order(order_id):
    print("开始处理订单", order_id)
    if order_id <= 0:
        print("订单号不对")
        return
    print("处理完成")
    return True

process_order(123)
process_order(-1)
```

输出：

```
开始处理订单 123
处理完成
开始处理订单 -1
订单号不对
```

看起来能用，但一旦脚本跑在服务器上、一天处理几万单，这种输出毫无排查价值。

## logging 的五个级别

`logging` 模块定义了五个标准级别，**严重程度从低到高**：

| 级别 | 数值 | 使用场景 |
|---|---|---|
| `DEBUG` | 10 | 调试细节，开发时看 |
| `INFO` | 20 | 正常运行的关键节点 |
| `WARNING` | 30 | 意外但不致命的问题 |
| `ERROR` | 40 | 出错，功能无法完成 |
| `CRITICAL` | 50 | 严重错误，程序可能崩溃 |

**级别是过滤器**：你设置成 `INFO`，那么 `DEBUG` 信息自动被屏蔽，不用改代码。

```python
import logging

logging.debug("这是调试信息")      # 默认看不到
logging.info("程序启动了")         # 默认看不到
logging.warning("磁盘快满了")      # 能看到
logging.error("数据库连接失败")     # 能看到
logging.critical("内存耗尽，即将崩溃")  # 能看到
```

输出：

```
WARNING:root:磁盘快满了
ERROR:root:数据库连接失败
CRITICAL:root:内存耗尽，即将崩溃
```

**默认级别是 `WARNING`**，所以 `DEBUG` 和 `INFO` 不显示。这就是"能开关"的实现——改一行配置，不用删代码。

## basicConfig：最简单的配置方式

`logging.basicConfig()` 是给小程序用的快速配置入口，一次设置好级别、格式、输出位置。

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(name)s - %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S"
)

logging.debug("调试：正在解析配置文件")
logging.info("信息：用户张三登录成功")
logging.warning("警告：密码将于 3 天后过期")
```

输出：

```
2026-09-28 10:30:00 [DEBUG] root - 调试：正在解析配置文件
2026-09-28 10:30:00 [INFO] root - 信息：用户张三登录成功
2026-09-28 10:30:00 [WARNING] root - 警告：密码将于 3 天后过期
```

**格式字符串里的占位符**是 logging 自己的：`%(asctime)s` 时间、`%(levelname)s` 级别名、`%(name)s` logger 名、`%(message)s` 消息。这套占位符在进阶课会大量用到。

## 翻车现场：basicConfig 没生效

最常见的问题：`basicConfig` 设置了 `level=DEBUG`，但 `debug()` 还是不输出。

```python
import logging

logging.error("我先被调用了")   # 第一次调用 logging，触发默认配置

logging.basicConfig(level=logging.DEBUG)  # 晚了！已经配置过了，这行无效

logging.debug("这条看不到")
```

输出：

```
ERROR:root:我先被调用了
```

**`basicConfig` 只在第一次调用 logging 时生效**，之后调用都会被忽略。根源在于 logging 是"惰性初始化"：第一次有任何 log 调用时，如果还没配置，就自动套一个默认配置。`basicConfig` 必须在**所有 log 调用之前**调用。

```python
import logging

logging.basicConfig(level=logging.DEBUG)  # 放在最前面

logging.debug("现在能看到了")
```

输出：

```
DEBUG:root:现在能看到了
```

## 翻车现场：把敏感信息打进日志

李四在日志里打印了完整的用户请求，结果日志文件被同事拷走，里面全是用户的身份证号、手机号、密码。

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(message)s")

def login(user, password):
    logging.info(f"用户 {user} 尝试登录，密码是 {password}")  # 翻车！
    return True

login("张三", "123456")
```

输出：

```
用户 张三 尝试登录，密码是 123456
```

**日志会被留存、被转发、被第三方采集**，里面绝不能出现密码、token、身份证号、银行卡号。正确做法：

```python
def login(user, password):
    logging.info(f"用户 {user} 尝试登录")
    # 密码只在调试级别，且脱敏
    logging.debug(f"密码长度={len(password)}")
```

**不要在日志里打印任何你不愿意贴在公司公告栏上的东西。**

## 小结

- `print` 没有级别、无法关闭、没有时间位置，只适合临时调试
- 五个级别 `DEBUG < INFO < WARNING < ERROR < CRITICAL`，默认级别是 `WARNING`
- 级别是过滤器：设成 `INFO` 就自动屏蔽所有 `DEBUG`
- `basicConfig` 一次配好级别、格式、时间格式，但只在第一次 log 调用前有效
- `%(asctime)s`、`%(levelname)s`、`%(message)s` 是格式字符串里的占位符
- 日志里绝不能出现密码、token、身份证号等敏感信息

- assert result == "网络延迟高"
