# argparse 进阶：子命令与互斥参数

> 这一课讲 `argparse` 的高级用法：像 `git clone`/`git push` 那样组织子命令，用互斥组确保参数不冲突，以及和手写 `sys.argv` 的对比。

## 子命令：像 git 那样组织 CLI

`git clone`、`git push`、`git commit` 是同一个程序的不同子命令，各自有各自的参数。`argparse` 用 `subparsers` 实现：

```python
import argparse

parser = argparse.ArgumentParser(prog="mygit")
sub = parser.add_subparsers(dest="command", help="可用子命令")

# 子命令：clone
p_clone = sub.add_parser("clone", help="克隆仓库")
p_clone.add_argument("url", help="仓库地址")

# 子命令：commit
p_commit = sub.add_parser("commit", help="提交")
p_commit.add_argument("-m", "--message", required=True, help="提交信息")

args = parser.parse_args(["clone", "https://github.com/xxx/yyy.git"])
print(args.command, args.url)
```

输出：

```
clone https://github.com/xxx/yyy.git
```

**`dest="command"` 记录用户选了哪个子命令**，`sub.add_parser("clone")` 创建子解析器，它有自己独立的参数。每个子命令可以有完全不同的参数列表。

```python
# 切换子命令
args2 = parser.parse_args(["commit", "-m", "修复登录 bug"])
print(args2.command, args2.message)
```

输出：

```
commit 修复登录 bug
```

## 互斥参数：不能同时出现

`--verbose` 和 `--quiet` 不应该同时传，用 `add_mutually_exclusive_group` 约束：

```python
import argparse

parser = argparse.ArgumentParser()
group = parser.add_mutually_exclusive_group()
group.add_argument("--verbose", action="store_true", help="详细输出")
group.add_argument("--quiet", action="store_true", help="静默模式")

args = parser.parse_args(["--verbose", "--quiet"])  # 两个都传
```

输出：

```
usage: xxx.py [-h] [--verbose | --quiet]
xxx.py: error: argument --quiet: not allowed with argument --verbose
```

**自动报错**，不用自己写判断逻辑。

## 和 sys.argv 手写解析的对比

| 维度 | 手写 sys.argv | argparse |
|---|---|---|
| 类型转换 | 自己 `int()`、`float()` | `type=` 自动转换 |
| 默认值 | 自己判断 len | `default=` |
| 帮助信息 | 自己 print | `--help` 自动生成 |
| 参数校验 | 自己写 if | `choices`、`required`、`互斥组` |
| 子命令 | 极难实现 | `subparsers` 原生支持 |
| 错误处理 | 自己 try/except | 自动生成 usage 和报错 |

**手写解析在参数超过 3 个就开始痛苦**，而 `argparse` 无论多少参数都保持清晰。

## 翻车现场：子命令参数忘了设 dest

```python
import argparse

parser = argparse.ArgumentParser()
sub = parser.add_subparsers(help="子命令")

sub.add_parser("start")
sub.add_parser("stop")

args = parser.parse_args(["start"])
print(args.command)  # AttributeError!
```

输出：

```
usage: xxx.py [-h] {start,stop} ...
xxx.py: error: argument {start,stop}: invalid choice: 'command' (choose from 'start', 'stop')
```

**没有 `dest="command"`，解析结果里就没有 `command` 属性**，你无法判断用户选了哪个子命令。`dest` 是子命令的"必选项"。

## 翻车现场：互斥组里的参数都设了 required=True

```python
import argparse

parser = argparse.ArgumentParser()
group = parser.add_mutually_exclusive_group(required=True)
group.add_argument("--local", action="store_true")
group.add_argument("--remote", action="store_true")

parser.parse_args([])  # 两个都没传
```

输出：

```
usage: xxx.py [-h] (--local | --remote)
xxx.py: error: one of the arguments --local --remote is required
```

**互斥组设了 `required=True` 时，必须传且只能传其中一个。** 这很适合"二选一必选"的场景，比如 `--install` 和 `--uninstall`。但如果两个都设了 `action="store_true"`，用户一个都不传就会报错。

## 翻车现场：子命令自己的参数和全局参数混用

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--verbose", action="store_true")  # 全局参数
sub = parser.add_subparsers(dest="command")
p_run = sub.add_parser("run")
p_run.add_argument("target")   # 子命令参数

# 正确顺序：全局参数在前，子命令在后
args = parser.parse_args(["--verbose", "run", "main.py"])
print(args.verbose, args.command, args.target)
```

输出：

```
True run main.py
```

**全局参数要写在子命令前面**。写成 `run --verbose main.py` 会把 `--verbose` 当作 `run` 子命令的参数（而 run 并没有注册 --verbose），直接报错。

## 小结

- `subparsers` 实现子命令，每个子命令有独立的参数列表，像 git 那样组织 CLI
- `dest="command"` 是子命令的必选项，用于判断用户选了哪个子命令
- 互斥组 `add_mutually_exclusive_group` 确保参数不冲突，`required=True` 时二选一
- `argparse` 自动生成 `--help`、自动类型转换、自动校验，远超手写 sys.argv
- 全局参数写在子命令之前，子命令参数写在子命令之后
- 互斥组里参数都 `store_true` 且组 `required=True` 时，用户必须选一个
