# 解析层：正则提取与容错

> 这一课把第 1-2 章的正则知识用在一个真实场景里——从日志文本中提取结构化信息，并且做到"脏数据不崩溃"。

## 从一行日志里提取什么

回顾我们的日志格式：

```
2026-01-15 10:23:45 [ERROR] [auth] 用户登录失败: user_id=10086
```

需要提取四段：
- **时间**：`2026-01-15 10:23:45`
- **级别**：`ERROR`
- **模块**：`auth`
- **消息**：`用户登录失败: user_id=10086`

用第 1 章学过的捕获组 `(...)` 就能搞定：

```python
import re

LOG_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '   # 组1: 时间
    r'\[(\w+)\] '                                   # 组2: 级别
    r'\[(\w+)\] '                                   # 组3: 模块
    r'(.*)$'                                        # 组4: 消息
)

line = "2026-01-15 10:23:45 [ERROR] [auth] 用户登录失败: user_id=10086"
match = LOG_PATTERN.match(line)
if match:
    print(f"时间={match.group(1)}")
    print(f"级别={match.group(2)}")
    print(f"模块={match.group(3)}")
    print(f"消息={match.group(4)}")
```

输出：

```
时间=2026-01-15 10:23:45
级别=ERROR
模块=auth
消息=用户登录失败: user_id=10086
```

## 用 dataclass 包装结果

用第 3 章学过的 `dataclass` 让结果更有结构感：

```python
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self) -> str:
        """提取小时 '10:23:45' -> '10'"""
        return self.timestamp.split(" ")[1].split(":")[0]

    @property
    def date(self) -> str:
        """提取日期 '2026-01-15 10:23:45' -> '2026-01-15'"""
        return self.timestamp.split(" ")[0]
```

`dataclass` 自动生成 `__init__`、`__repr__`，比手写类少一半代码。

## 容错：脏数据不能让工具崩溃

真实日志里什么都有：空行、格式错乱的行、多出的空格、堆栈跟踪、编码乱码。**解析层的原则是：一行解析失败，记下来，继续处理下一行。**

```python
def parse_line(line: str) -> LogEntry | None:
    """解析单行日志，失败返回 None"""
    line = line.strip()
    if not line:
        return None
    match = LOG_PATTERN.match(line)
    if match is None:
        return None
    return LogEntry(
        timestamp=match.group(1),
        level=match.group(2),
        module=match.group(3),
        message=match.group(4).strip(),
    )


def parse_lines(lines: list[str]) -> tuple[list[LogEntry], list[str]]:
    """批量解析，返回 (成功条目, 失败行)"""
    entries = []
    failed = []
    for line in lines:
        entry = parse_line(line)
        if entry is None:
            failed.append(line.strip())
        else:
            entries.append(entry)
    return entries, failed
```

关键点：
- `parse_line` **绝不抛异常**，格式不对就返回 `None`
- `parse_lines` 收集所有失败行，方便后续报告"有多少行解析失败"
- 用 `strip()` 去掉前后空白，避免空格导致的匹配失败

## 容错实战

```python
test_lines = [
    "2026-01-15 10:23:45 [ERROR] [auth] 用户登录失败",
    "2026-01-15 10:23:46 [INFO]  [order] 订单创建",      # 多空格
    "",                                                    # 空行
    "2026-01-15 10:23:47 [WARN] [payment] 支付超时",
    "Traceback (most recent call last):",                  # 堆栈行
    "2026-01-15 10:23:48 [DEBUG] [db] query executed",
]

entries, failed = parse_lines(test_lines)
print(f"成功解析 {len(entries)} 条")
print(f"解析失败 {len(failed)} 条: {failed}")

for e in entries:
    print(f"  {e.level:<6} {e.module:<8} {e.message}")
```

输出：

```
成功解析 4 条
解析失败 2 条: ['', 'Traceback (most recent call last):']
  ERROR  auth     用户登录失败
  INFO   order    订单创建
  WARN   payment  支付超时
  DEBUG  db       query executed
```

## 支持多种日志格式

真实项目里日志格式不统一。比如有的用 `INFO:` 前缀，有的用 `<timestamp>`。可以用多个正则尝试匹配：

```python
import re
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self):
        return self.timestamp.split(" ")[1].split(":")[0]


# 格式A: 2026-01-15 10:23:45 [ERROR] [auth] msg
PATTERN_A = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)

# 格式B: 2026/01/15 10:23:45 ERROR auth - msg
PATTERN_B = re.compile(
    r'^(\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}) '
    r'(\w+) '
    r'(\w+) '
    r'- '
    r'(.*)$'
)

PATTERNS = [PATTERN_A, PATTERN_B]


def parse_line(line: str) -> LogEntry | None:
    line = line.strip()
    if not line:
        return None
    for pattern in PATTERNS:
        match = pattern.match(line)
        if match:
            return LogEntry(
                timestamp=match.group(1),
                level=match.group(2),
                module=match.group(3),
                message=match.group(4).strip(),
            )
    return None
```

注意格式 B 的时间分隔符是 `/` 而不是 `-`，这不影响我们的正则（因为我们只提取原始字符串），但如果后面要做时间排序或时间差计算，就需要统一格式。

## 翻车现场：贪婪匹配吃掉后面的内容

```python
# WRONG：用 .* 匹配级别
BAD_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(.+)\] '          # 贪婪！会一直匹配到最后一个 ]
    r'\[(\w+)\] '
    r'(.*)$'
)

line = "2026-01-15 10:23:45 [ERROR] [auth] [extra] 消息内容"
match = BAD_PATTERN.match(line)
print(match.group(2))  # 'ERROR] [auth] [extra'  —— 贪婪吞掉了！
```

**错误输出**：级别被匹配成了 `ERROR] [auth] [extra`，完全错误。

**修复**：用 `\w+`（非贪婪的字符类）代替 `.+`，限定级别只能是字母数字：

```python
GOOD_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)
```

## 翻车现场：parse_line 抛异常导致整个流程中断

```python
# WRONG：解析失败直接抛异常
def parse_line_bad(line):
    parts = line.strip().split(" ")
    return LogEntry(
        timestamp=f"{parts[0]} {parts[1]}",
        level=parts[2].strip("[]"),
        module=parts[3].strip("[]"),
        message=" ".join(parts[4:]),
    )

lines = [
    "2026-01-15 10:23:45 [ERROR] [auth] msg1",
    "这条格式不对",                    # IndexError!
    "2026-01-15 10:23:46 [INFO] [order] msg2",
]
for line in lines:
    entry = parse_line_bad(line)  # 第二行崩了，第三行永远处理不到
    print(entry)
```

**错误输出**：

```
LogEntry(timestamp='2026-01-15 10:23:45', level='ERROR', module='auth', message='msg1')
IndexError: list index out of range
```

**第一条处理完就崩了，后面所有行都被跳过。** 生产环境里这可能意味着"日志分析跑到一半悄悄停了，没人知道"。

**正确做法**：返回 `None`，由调用方决定是否记录失败行。

## 翻车现场：忘记 strip 导致匹配失败

```python
# WRONG：没去空白
def parse_line_nostrip(line):
    match = LOG_PATTERN.match(line)  # "  2026-01-15..." 前面有空格，^ 锚定失败
    return match

line = "  2026-01-15 10:23:45 [ERROR] [auth] msg"
print(parse_line_nostrip(line))  # None！静默失败
```

**错误输出**：`None`——日志行前面有个空格就匹配不上了，而且不报错，非常难排查。

**修复**：`line = line.strip()` 放在第一行。

## 小结

- 解析层用正则 + 捕获组提取结构化信息，配合 `dataclass` 包装
- **容错是解析层的核心要求**：格式不对返回 `None`，绝不抛异常
- 多格式支持用多个正则依次尝试，匹配到即止
- 贪婪匹配 `.*` / `.+` 可能吞掉后续内容，优先用字符类 `\w+` / `[^]]+`
- 空白字符是隐形杀手，`strip()` 要放在最前面
- 解析层只做解析，不涉及文件 IO、不涉及统计、不涉及输出
