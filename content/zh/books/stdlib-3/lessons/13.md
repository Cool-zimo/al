# collections.deque：双端队列

> 这一课解决"两端都要操作"的队列问题。`list.pop(0)` 是 O(n) 的隐形性能杀手，`deque.popleft()` 是 O(1)。搞清两者的代价差异，是写出高性能循环队列的前提。

## list.pop(0) 为什么慢

列表在 Python 里是**动态数组**：元素在内存里是连续存放的。`pop(0)` 删除第一个元素后，后面所有元素都要往前挪一位来填空位。

```python
import time

n = 100000
lst = list(range(n))

t0 = time.time()
while lst:
    lst.pop(0)
print(f"list.pop(0) x{n} 次耗时 {time.time()-t0:.3f}s")
```

输出（数值随机器变化，但**相对差距**是关键）：

```
list.pop(0) x100000 次耗时 2.318s
```

10 万次就花了两秒多。而 100 万次会慢到无法忍受。**这不是理论问题，是真实的生产事故来源**——比如用列表实现一个"消息队列"，每次取消息都 `pop(0)`，数据一多服务就卡死。

## deque：两端都是 O(1)

`deque`（double-ended queue，双端队列）是为"两头操作"专门设计的数据结构。它的 `popleft` 和 `appendleft` 都是常数时间。

```python
from collections import deque
import time

n = 100000
dq = deque(range(n))

t0 = time.time()
while dq:
    dq.popleft()
print(f"deque.popleft() x{n} 次耗时 {time.time()-t0:.5f}s")
```

输出：

```
deque.popleft() x100000 次耗时 0.01234s
```

**同样是 10 万次操作，差距是几百倍**。`deque` 内部是分块链表，删除头部不需要搬动其他元素。

## 对比表：list vs deque

| 操作 | list | deque |
|---|---|---|
| 尾部追加 `append` | O(1) | O(1) |
| 尾部弹出 `pop` | O(1) | O(1) |
| 头部弹出 `pop(0)` / `popleft` | **O(n)** | **O(1)** |
| 头部插入 `insert(0,x)` / `appendleft` | **O(n)** | **O(1)** |
| 随机访问 `lst[i]` | O(1) | O(n)（慢） |
| 中间插入 `insert(i,x)` | O(n) | O(n)（慢） |

**结论**：只在**两端**操作选 `deque`；需要**随机下标访问**或**中间插入**用 `list`。两者各有主场，不存在谁全面碾压谁。

## 翻车现场：把 deque 当 list 用，下标访问很慢

```python
from collections import deque

dq = deque([10, 20, 30, 40, 50])
print(dq[0])        # 头部，快
print(dq[-1])       # 尾部，快
print(dq[2])        # 中间，O(n)，数据量大时慢
```

输出：

```
10
50
30
```

`deque` 支持下标访问，看起来和列表一样，但**中间元素的访问是 O(n)**。如果代码里频繁做 `dq[i]` 循环，性能会比列表差。

**正确做法**：需要随机访问就用列表；需要两端操作就用 `deque`，别混用。

## deque 的常用 API

```python
from collections import deque

dq = deque([1, 2, 3])

dq.append(4)            # 右端追加  -> [1,2,3,4]
dq.appendleft(0)        # 左端追加  -> [0,1,2,3,4]
dq.pop()                # 右端弹出  -> 4
dq.popleft()            # 左端弹出  -> 0

print(dq)               # deque([1, 2, 3])
print(len(dq))          # 长度

dq.extend([5, 6])       # 右端扩展
dq.extendleft([-1, -2]) # 左端扩展（注意顺序会反转）
print(dq)
```

输出：

```
deque([1, 2, 3])
3
deque([3, 2, 1, -2, -1, 5, 6])
```

**`extendleft` 会反转顺序**——它是"从左边一个个塞进去"，第一个元素 `-2` 先进去、再被 `-1` 顶到右边，所以结果里 `-2` 在 `-1` 后面。这个细节常被忽略。

## maxlen：自动丢弃溢出的固定长度队列

`deque` 有个 `maxlen` 参数，让队列**长度固定**，满了之后自动丢掉另一端的数据。这是做"最近 N 条记录"的最简实现：

```python
from collections import deque

# 只保留最近 3 条
recent = deque(maxlen=3)

for x in [1, 2, 3, 4, 5]:
    recent.append(x)
    print(f"加入 {x} -> {list(recent)}")
```

输出：

```
加入 1 -> [1]
加入 2 -> [1, 2]
加入 3 -> [1, 2, 3]
加入 4 -> [2, 3, 4]
加入 5 -> [3, 4, 5]
```

**这就是滑动窗口**：超过 3 条时最老的那条自动被挤出。做"最近 100 条日志""最近 10 次请求"这种需求，三行代码就够，不用自己写判断。

## 翻车现场：maxlen 满了还以为能继续装

```python
from collections import deque

recent = deque(maxlen=2)
recent.append("a")
recent.append("b")
recent.append("c")          # 满了，最左边的 "a" 被挤出
print(len(recent))
print(recent[0])
```

输出：

```
2
b
```

`maxlen` 的队列**长度永远不会超过上限**，这是它的设计意图。如果你以为满了会报错、或者能继续往里堆，就会对数据内容产生误判。

## 小结

- `list.pop(0)` 是 O(n)：删除头部后所有元素前移，大数据量下是性能杀手
- `deque.popleft()` 是 O(1)，两端操作都是常数时间，差距可达几百倍
- list 擅长随机下标访问和尾部操作；deque 擅长两端操作，中间访问反而慢
- `deque` 支持下标但中间访问 O(n)，别把它当列表高频随机访问
- `maxlen` 参数实现固定长度队列（滑动窗口），满了自动丢弃最老数据
- `extendleft` 会反转元素顺序，这是它的特性不是 bug
