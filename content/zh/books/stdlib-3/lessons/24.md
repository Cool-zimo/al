# pytest 简介：为什么很多人用 pytest

> 这一课讲 pytest 的核心优势：更简洁的断言语法和 fixture 机制。以及它与 unittest 的关系。不需要安装，只讲概念和对比。

## 更简洁的断言

unittest 需要记一堆 `assertXxx` 方法，pytest 直接用 Python 原生的 `assert` 关键字：

```python
# unittest 风格
class TestCart(unittest.TestCase):
    def test_total(self):
        cart = Cart()
        cart.add("apple", 2)
        self.assertEqual(cart.total, 2)
        self.assertTrue(cart.has_items())
        self.assertIn("apple", cart.items)

# pytest 风格
def test_total():
    cart = Cart()
    cart.add("apple", 2)
    assert cart.total == 2
    assert cart.has_items()
    assert "apple" in cart.items
```

**pytest 会智能地分析 `assert` 表达式的左右两边**，失败时告诉你具体的值。比如 `assert cart.total == 5` 失败时，pytest 会显示：

```
>       assert cart.total == 5
E       assert 2 == 5
E        +  where 2 = cart.total
```

**不用记 `assertEqual`、`assertTrue`、`assertIn` 的方法名**，一个 `assert` 走天下。

## fixture：比 setUp 更灵活

unittest 的 `setUp` 是每个方法都跑一次，写多了要么浪费要么不够用。pytest 的 fixture 是**按需注入**的：

```python
import pytest

@pytest.fixture
def cart():
    c = Cart()
    c.add("apple", 2)
    return c

def test_total(cart):          # 参数名匹配 fixture 名，自动注入
    assert cart.total == 2

def test_add_more(cart):       # 每个测试拿到全新的 cart
    cart.add("banana", 1)
    assert cart.total == 3
```

**fixture 的特点**：

| 特性 | 说明 |
|---|---|
| 按需注入 | 只有声明了同名参数的测试才用 |
| 作用域可控 | `scope="function"/"module"/"session"` |
| 支持 teardown | yield 之前的代码是 setup，之后的代码是 teardown |
| 可组合 | fixture 可以依赖其他 fixture |

```python
import pytest

@pytest.fixture
def db():
    print("\n连接数据库")
    yield "db_connection"   # yield 给测试用
    print("\n关闭数据库")     # 测试跑完执行这里

def test_query(db):
    assert db == "db_connection"
```

**`yield` 之前的代码是准备，`yield` 之后的是清理**，比 setUp/tearDown 更直观。

## 与 unittest 的关系

pytest 和 unittest 是**兼容的**：pytest 能直接发现和运行 unittest 的 TestCase 类，不需要改代码。

```bash
# 同一个 TestCase 类，两种都能跑
python -m unittest test_cart.py
pytest test_cart.py -v
```

**关系是共存不是替代**：

| 维度 | unittest | pytest |
|---|---|---|
| 归属 | Python 标准库，无需安装 | 第三方库，需 pip install |
| 断言 | `self.assertXxx` 系列 | 原生 `assert` |
| 前置准备 | setUp/tearDown | fixture（更灵活） |
| 参数化 | 需手写循环或 subTest | `@pytest.mark.parametrize` 原生支持 |
| 插件生态 | 较少 | 丰富（覆盖率、并发、报告等） |
| 学习曲线 | 较平缓，OOP 风格 | 更 Pythonic，功能更强 |

**如果你的项目已经在用 unittest，不需要迁移**——pytest 可以无缝运行。新项目如果允许引入第三方依赖，pytest 的开发体验更好。

## 翻车现场：pytest 没装就 import

```python
import pytest  # 没装的话直接 ImportError
```

输出：

```
ModuleNotFoundError: No module named 'pytest'
```

**pytest 是第三方库，不是标准库。** 标准库自带的 unittest 随时可用。本课只讲概念对比，不要求安装。

## 翻车现场：fixture 名和参数名不匹配

```python
import pytest

@pytest.fixture
def my_cart():
    return Cart()

def test_something(cart):   # 参数名 cart ≠ fixture 名 my_cart
    assert cart.total == 0  # NameError!
```

**pytest 靠参数名匹配 fixture**，名字对不上就当普通参数处理，报 `TypeError: test_something() missing required argument`。修正：参数名改成 `my_cart`。

## 翻车现场：fixture 放在了错误的文件

```python
# conftest.py（正确：放在这里或测试文件里）
@pytest.fixture
def shared():
    return "shared"

# utils.py（错误：放在了非测试模块里）
@pytest.fixture
def shared():
    return "shared"
```

**pytest 只在 `conftest.py` 和测试文件里自动发现 fixture**。放在普通业务模块里，其他测试文件引用不到。解决办法：把公共 fixture 放进 `conftest.py`（放在测试目录下）。

## 翻车现场：fixture 默认每个测试重建，以为能共享状态

```python
import pytest

counter = 0

@pytest.fixture
def count():
    global counter
    counter += 1
    return counter

def test_a(count):
    assert count == 1

def test_b(count):
    assert count == 1   # 通过！因为 fixture 每次重建
```

**默认 `scope="function"` 时 fixture 每个测试都重新执行**，`test_b` 拿到的是全新的 `count`。如果想共享，要设 `scope="module"` 或 `scope="session"`。

## 小结

- pytest 用原生 `assert` 替代 `assertXxx` 系列，更简洁且报错信息更详细
- fixture 比 setUp 更灵活：按需注入、作用域可控、支持 yield 做 teardown
- pytest 兼容 unittest，能直接运行 TestCase 类
- pytest 是第三方库不是标准库，unittest 随 Python 自带
- fixture 靠参数名匹配，名字对不上会报错
- 公共 fixture 放 `conftest.py`，fixture 默认每个测试重建
