# 基本匹配：search、match 与 findall

> 这一课解决"用哪把钥匙开哪把锁"的问题。`re.search`、`re.match`、`re.fullmatch` 看着差不多，其实是三种完全不同的查找姿势；`findall` 和 `finditer` 也各有所长。

## 三个查找函数，三种姿势

正则模块 `re` 提供了三个最常用的查找函数，区别全在**从哪里开始、要匹配到哪**：

```python
import re

text = "我的电话是13812345678，备用13987654321"

# search：扫一遍全文，返回第一个匹配
m = re.search(r'1[3-9]\d{9}', text)
print("search:", m.group())

# match：只从字符串开头匹配，开头对不上就 None
m2 = re.match(r'1[3-9]\d{9}', text)
print("match:", m2)

# fullmatch：整个字符串必须完全符合模式，多一个字都不行
m3 = re.fullmatch(r'1[3-9]\d{9}', "13812345678")
print("fullmatch 纯净号码:", m3.group())
m4 = re.fullmatch(r'1[3-9]\d{9}', "电话13812345678")
print("fullmatch 带前缀:", m4)
```

输出：

```
search: 13812345678
match: None
fullmatch 纯净号码: 13812345678
fullmatch 带前缀: None
```

| 函数 | 起点 | 终点 | 典型用途 |
|---|---|---|---|
| `search` | 全文任意位置 | 匹配到一处即可 | 从一段话里找某个模式 |
| `match` | **强制从开头** | 开头符合即返回 | 校验字符串是否以某模式起始 |
| `fullmatch` | 开头 | **必须一直到结尾** | 校验整串是否完全合规 |

**一句话记忆**：`search` 是"有没有"，`match` 是"开头是不是"，`fullmatch` 是"从头到尾是不是"。

## 翻车现场：把 match 当 search 用，永远匹配不到

这是最高频的错误。张三想校验一段文本里是否含"错误"两个字：

```python
import re

log = "系统运行正常，未检测到错误"

# WRONG：match 强制从开头匹配
m = re.match(r'错误', log)
print(m)
```

输出：

```
None
```

明明有"错误"两个字，却返回 `None`。因为 `match` 只认开头，字符串第一个字是"系"，对不上就放弃。

**正确做法**：要在全文里找，用 `search`；确实要校验"字符串是否以某模式开头"时才用 `match`。

```python
import re

log = "系统运行正常，未检测到错误"
m = re.search(r'错误', log)
print(m.group())      # 错误
```

输出：

```
错误
```

## findall 与 finditer：要列表还是要对象

`findall` 返回**匹配字符串的列表**，`finditer` 返回**匹配对象的迭代器**。大多数时候 `findall` 够用，但一旦你还需要"匹配在原文里的位置"，`finditer` 是唯一的干净解法。

```python
import re

text = "订单DD20260901, 订单DD20260915, 订单DD20261003"

# findall：只要字符串
print("findall:", re.findall(r'DD\d{8}', text))

# finditer：要对象，能拿位置
for m in re.finditer(r'DD\d{8}', text):
    print(f"匹配到 {m.group()} 位于位置 {m.start()}-{m.end()}")
```

输出：

```
findall: ['DD20260901', 'DD20260915', 'DD20261003']
匹配到 DD20260901 位于位置 2-12
匹配到 DD20260915 位于位置 15-25
匹配到 DD20261003 位于位置 28-38
```

`finditer` 是**惰性**的：它返回一个迭代器，一个一个往外吐匹配对象。文本很长、匹配很多时，内存占用比 `findall` 小得多——`findall` 会一次性把所有结果装进列表。

## 翻车现场：对匹配对象忘写 .group()

`search` 返回的是一个**匹配对象**，不是字符串。对它直接做字符串操作会报错：

```python
import re

text = "电话13812345678"

# WRONG：把匹配对象当成字符串
m = re.search(r'1[3-9]\d{9}', text)
print("客户电话是" + m)        # 直接拼接
```

报错：

```
TypeError: can only concatenate str (not "re.Match") to str
```

**正确做法**：调用 `.group()`（或它的简写 `.group(0)`）取出匹配到的字符串。

```python
import re

text = "电话13812345678"
m = re.search(r'1[3-9]\d{9}', text)
print("客户电话是" + m.group())
```

输出：

```
客户电话是13812345678
```

## 原始字符串 r"" 为什么必须

正则的灵魂是反斜杠：`\d` 代表数字、`\w` 代表字母数字下划线、`\.` 代表字面点号。但 Python 的字符串也会吃掉反斜杠：`\n` 是换行、`\t` 是制表符。

```python
import re

text = "文件 v1.2.3 已发布"

# WRONG：'\d' 在普通字符串里只是 'd' 前加个反斜杠，正则收到的其实是 "d"
pat = '\d+\.\d+\.\d+'       # Python 里 '\d' 不是特殊转义，这次碰巧能跑
print(re.findall(pat, text))

# 真正出事的情况：想匹配字面点号，写成 '\.'
pat2 = '\.'                 # Python 字符串里 '\.' 其实是字面的 '\.' 两个字符
print(re.findall(pat2, text))
```

输出：

```
['1.2.3']
['.', '.', '.']
```

这次碰巧没炸，但靠的是"Python 不认识 `\d` 和 `\.`"这种侥幸。真正灾难现场是**自己拼正则**时：

```python
import re

# 想匹配 "C:\new" 里的反斜杠 + new
folder = "C:\\new"
pat = "\\\\new"      # 普通字符串要写四个反斜杠才代表正则里的一个反斜杠！
print(re.findall(pat, folder))
```

**正确做法**：一律加 `r`。`r'\d'` 就是"反斜杠和 d"两个字符，原样交给正则引擎，两层转义不再打架。

```python
import re

folder = "C:\\new"
pat = r'\\new'        # 原始字符串：写两个反斜杠，正则就收到两个反斜杠
print(re.findall(pat, folder))
```

输出：

```
['\\new']
```

## 小结

- `search` 全文找第一个，`match` 强制从开头，`fullmatch` 要求整串完全符合
- 要在一段文本里"找是否存在"用 `search`；要"校验整串格式"用 `fullmatch`
- `findall` 返回字符串列表，`finditer` 返回带位置信息的匹配对象迭代器，大数据量用后者省内存
- 匹配对象要用 `.group()` 取出字符串，不能直接当字符串用
- **正则一律用 `r""` 原始字符串**，避免反斜杠被 Python 字符串转义
