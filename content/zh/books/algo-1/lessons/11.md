# 为什么需要预处理：区间求和从 O(n) 到 O(1)

> 前两章我们学会了用双指针降维。这一章换一个角度：**预处理**——先把答案算好存起来，查询时直接取。

## 先看一个朴素的需求

**题目**：给你一个数组，反复询问"区间 [l, r] 的元素和是多少"。

```python
nums = [1, 3, 5, 7, 9, 11]
# 问 [1, 3] 的和 → 3+5+7 = 15
# 问 [0, 4] 的和 → 1+3+5+7+9 = 25
# 问 [2, 2] 的和 → 5
```

朴素做法：每次询问都从头累加一遍。

```python
def range_sum(nums, l, r):
    total = 0
    for i in range(l, r + 1):
        total += nums[i]
    return total

nums = [1, 3, 5, 7, 9, 11]
print(range_sum(nums, 1, 3))    # 15
print(range_sum(nums, 0, 4))    # 25
```

**每次查询 O(n)。** 如果问 10 万次，总操作量是 10 万 × n —— 直接超时。

## 核心洞察：用空间换时间

如果能在**开始之前**花 O(n) 的时间把所有"前缀"信息算好存起来，那每次查询就能变成 O(1)。

这就是**前缀和**的思想。

## 前缀和数组

**定义**：`prefix[i]` 表示 `nums[0..i-1]` 的所有元素之和（前 i 个元素的和）。

```python
nums   = [1, 3, 5, 7, 9, 11]
prefix = [0, 1, 4, 9, 16, 25, 36]
# prefix[0] = 0（前 0 个元素的和）
# prefix[1] = 1
# prefix[2] = 1+3 = 4
# prefix[3] = 1+3+5 = 9
# ...
# prefix[6] = 1+3+5+7+9+11 = 36
```

**怎么算 prefix**：

```python
def build_prefix(nums):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    return prefix

nums = [1, 3, 5, 7, 9, 11]
prefix = build_prefix(nums)
print(prefix)    # [0, 1, 4, 9, 16, 25, 36]
```

**O(n) 一次，永久使用。**

## 用前缀和快速查询

**区间 [l, r] 的和 = prefix[r+1] - prefix[l]**

为什么？画图理解：

```
prefix[r+1] = nums[0] + nums[1] + ... + nums[l-1] + nums[l] + ... + nums[r]
prefix[l]   = nums[0] + nums[1] + ... + nums[l-1]
```

两者相减，前面那一长串公共部分抵消，剩下就是 `nums[l..r]` 的和。

```python
def query(prefix, l, r):
    return prefix[r + 1] - prefix[l]

prefix = [0, 1, 4, 9, 16, 25, 36]
print(query(prefix, 1, 3))    # prefix[4] - prefix[1] = 16 - 1 = 15 ✓
print(query(prefix, 0, 4))    # prefix[5] - prefix[0] = 25 - 0 = 25 ✓
print(query(prefix, 2, 2))    # prefix[3] - prefix[2] = 9 - 4 = 5 ✓
```

**O(1) 查询！** 从 O(n) 到 O(1)，这是质的飞跃。

## 为什么 prefix 要多一个前导 0

这是新手最容易困惑的地方。

**问题**：如果 `l=0`，我们要算 `prefix[0]`。如果没有前导 0，`prefix[0]` 是 `nums[0]` 而不是 0。

```python
# 没有前导 0 的版本（错误）
prefix = [1, 4, 9, 16, 25, 36]   # 直接存前缀和
# 查询 [0, 3] 需要 prefix[3] - prefix[-1] → 越界！
```

**有前导 0 的版本**：

```python
prefix = [0, 1, 4, 9, 16, 25, 36]   # prefix[0]=0
# 查询 [0, 3] = prefix[4] - prefix[0] = 16 - 0 = 16 ✓
```

**前导 0 让"从位置 0 开始"的公式和其他情况统一**，不需要特殊处理。

| 查询 | 公式 | 有前导 0 | 无前导 0 |
|---|---|---|---|
| [0, 3] | prefix[4] - prefix[0] | 16 - 0 = 16 ✓ | 需要特判 |
| [1, 3] | prefix[4] - prefix[1] | 16 - 1 = 15 ✓ | 16 - 1 = 15 ✓ |
| [2, 2] | prefix[3] - prefix[2] | 9 - 4 = 5 ✓ | 9 - 4 = 5 ✓ |

**有前导 0 时，所有查询用同一个公式，不用特判 l==0。**

## 复杂度对比

| 操作 | 朴素 | 前缀和 |
|---|---|---|
| 预处理 | — | O(n) |
| 单次查询 | O(n) | **O(1)** |
| m 次查询 | O(mn) | O(n + m) |

当 m 很大时，差距是天壤之别：

```
m=100000, n=1000:
朴素: 100000 × 1000 = 1 亿次操作
前缀和: 1000 + 100000 = 10.1 万次操作
差距约 1000 倍
```

## 前置和的适用场景

**不是所有题都适合用前缀和。** 适合的条件是：

- 需要**反复查询**区间信息（和、积、异或等）
- 查询次数 m 远大于数组长度 n
- 区间信息满足**可加减性**（和可以加减，最大值就不行）

| 场景 | 能否用前缀和 |
|---|---|
| 区间求和 | ✅ |
| 区间异或和 | ✅ |
| 区间最大值 | ❌（不满足可加减性） |
| 区间元素个数 | ✅ |
| 区间乘积（取模） | ✅ |

> 💡 **判断标准**：如果问"某个区间里的什么什么"，而且会问很多次，就想想前缀和。

## 小结

- 前缀和：预处理 O(n)，查询 O(1)
- `prefix[i]` = 前 i 个元素的和，`prefix[0] = 0`
- 区间 [l, r] 的和 = `prefix[r+1] - prefix[l]`
- 前导 0 让公式统一，不需要特判 l==0
- 适用场景：反复查询满足可加减性的区间信息
