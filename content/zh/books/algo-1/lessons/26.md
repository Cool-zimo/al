# 窗口是什么：什么时候该用滑动窗口

> 暴力枚举所有子区间要 O(n²)，滑动窗口能把它压到 O(n)。这一课讲清楚**什么场景该用窗口、什么场景不该用**，以及它和双指针的关系。

## 什么是"窗口"

窗口就是数组上一段**连续的区间**，用两个指针 `left` 和 `right` 标记边界。比如数组 `[3, 1, 4, 1, 5, 9]`，`left=1, right=3` 就代表子数组 `[1, 4, 1]`。

```python
nums = [3, 1, 4, 1, 5, 9]
left = 1
right = 3
window = nums[left:right + 1]
print(window)  # [1, 4, 1]
```

关键区别：**窗口强调的是"区间内的整体信息"**（和、最大值、出现次数等），而不是单独的两个元素。

## 什么时候该用滑动窗口

满足以下两个条件，就可以考虑滑动窗口：

1. **答案是连续区间**（子数组、子串），不是随意挑选的元素组合
2. **窗口滑动时，区间信息可以增量更新**——加一个元素、删一个元素都只要 O(1)

| 场景 | 能否用窗口 | 原因 |
|---|---|---|
| 子数组最大和 | ✅ | 加/减一个元素 O(1) |
| 最长无重复子串 | ✅ | 用集合维护出现情况 |
| 子数组和等于 k | ✅ | 配合前缀和或哈希表 |
| 数组中选两个元素最大和 | ❌ | 不是连续区间 |
| 三数之和 | ❌ | 需要三个任意位置元素 |

## 固定窗口 vs 可变窗口

**固定窗口**：窗口长度始终为 k。每次右移时，右边进一个、左边出一个。

```python
nums = [2, 1, 5, 6, 3, 4]
k = 3

# 初始窗口和
window_sum = sum(nums[:k])
max_sum = window_sum
print(f"窗口 [0:{k}] = {nums[:k]}, 和 = {window_sum}")

# 向右滑动
for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_sum = max(max_sum, window_sum)
    print(f"窗口 [{i-k+1}:{i+1}] = {nums[i-k+1:i+1]}, 和 = {window_sum}")

print(f"最大和 = {max_sum}")
# 窗口 [0:3] = [2, 1, 5], 和 = 8
# 窗口 [1:4] = [1, 5, 6], 和 = 12
# 窗口 [2:5] = [5, 6, 3], 和 = 14
# 窗口 [3:6] = [6, 3, 4], 和 = 13
# 最大和 = 14
```

`window_sum - nums[i-k] + nums[i]` 就是核心：**去掉左边界的旧值，加上右边界的新值**。这样每个位置的窗口和都是 O(1) 算出来的，总复杂度 O(n)。

## 可变窗口：右边界扩张、左边界收缩

固定窗口长度不变，可变窗口则根据条件**动态决定左边界什么时候收缩**。最经典的问题是"无重复字符的最长子串"——这个问题在第 28 课详细讲，这里先看框架：

```python
s = "abcabcbb"
char_set = set()
left = 0
max_len = 0

for right in range(len(s)):
    # 如果新字符已经在窗口里，就收缩左边界
    while s[right] in char_set:
        char_set.remove(s[left])
        left += 1
    # 加入新字符
    char_set.add(s[right])
    # 更新答案
    max_len = max(max_len, right - left + 1)

print(max_len)  # 3
```

**核心套路**：`right` 一路向右扩张，`left` 只在"窗口不合法"时才向右收缩。两个指针都只增不减，所以总共最多走 2n 步，复杂度 O(n)。

## 翻车现场一：忘记减去左边界的值

新手写固定窗口时，最容易犯的错误是**只加不减**：

```python
nums = [2, 1, 5, 6, 3]
k = 3

window_sum = sum(nums[:k])  # 8
max_sum = window_sum

for i in range(k, len(nums)):
    window_sum = window_sum + nums[i]  # 错误！只加了右边，没减左边
    max_sum = max(max_sum, window_sum)

print(max_sum)
```

输出：

```
# 错误输出：17
# 实际过程：8 → 8+6=14 → 14+3=17
# 正确过程：8 → 8-2+6=12 → 12-1+3=14
```

**为什么会错**：`window_sum` 代表的已经不是长度为 k 的窗口了，它变成了"所有经过的元素之和"。k=3 时第一个窗口是 `[2,1,5]`，但滑到 i=3 时变成了 `[2,1,5,6]`，长度已经是 4 了。

正确写法是 `window_sum = window_sum - nums[i-k] + nums[i]`，**永远保持窗口里恰好 k 个元素**。

## 翻车现场二：把窗口当成双指针的别名

很多人以为"窗口就是双指针"，其实两者有本质区别：

| | 双指针 | 滑动窗口 |
|---|---|---|
| 指针移动 | 两个指针各自独立决策 | 右指针扩张为主，左指针条件性收缩 |
| 关注点 | 两个指针指向的元素关系 | 两指针**之间**的整个区间 |
| 典型题 | 两数之和、三数之和 | 子数组最大和、最小覆盖子串 |
| 是否需要维护区间状态 | 通常不需要 | 通常需要（和、集合、计数器） |

```python
# 双指针：找两数之和
nums = [1, 2, 3, 4, 5]
target = 6
left, right = 0, len(nums) - 1
while left < right:
    s = nums[left] + nums[right]
    if s == target:
        print(f"找到: {nums[left]} + {nums[right]}")
        break
    elif s < target:
        left += 1
    else:
        right -= 1

# 滑动窗口：子数组最大和
nums = [1, 2, 3, 4, 5]
k = 3
window_sum = sum(nums[:k])
max_sum = window_sum
for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_sum = max(max_sum, window_sum)
print(f"最大和: {max_sum}")
```

双指针的 left 和 right 是**协作找答案**，滑动窗口的 left 和 right 是**共同框住一个区间**。

## 翻车现场三：可变窗口只扩不缩

写可变窗口时，忘记收缩左边界是最常见的 bug：

```python
s = "abcabcbb"
seen = set()
max_len = 0

for right in range(len(s)):
    seen.add(s[right])  # 只加不删！
    max_len = max(max_len, len(seen))

print(max_len)  # 错误输出：8（整个字符串长度）
# 正确答案是 3（"abc"）
```

**问题出在哪**：集合 `seen` 只增不减，它记录的是"整个字符串里出现过哪些字符"，而不是"当前窗口里有哪些字符"。窗口的右边界在走，但左边界永远是 0，这根本不是窗口。

## 窗口和前缀和的配合

窗口不是孤立的技巧。固定窗口最大和其实可以和前缀和结合：

```python
# 前缀和 + 窗口
nums = [2, 1, 5, 6, 3, 4]

# 先算前缀和
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)

print(prefix)  # [0, 2, 3, 8, 14, 17, 21]

# 区间 [i, j] 的和 = prefix[j+1] - prefix[i]
k = 3
max_sum = 0
for i in range(len(nums) - k + 1):
    s = prefix[i + k] - prefix[i]
    max_sum = max(max_sum, s)

print(max_sum)  # 14
```

两种方式结果一样，但**纯滑动窗口的 O(1) 更新更省空间**（不需要额外 O(n) 数组）。前缀和的优势在于可以做**多个不同长度**的窗口查询，而滑动窗口更适合逐个滑动。

## 小结

- 滑动窗口 = 用 `left` 和 `right` 框住一段连续区间，维护区间内的聚合信息
- **固定窗口**：长度不变，每次右移时"去头加尾"，O(n) 时间
- **可变窗口**：右边界扩张，左边界条件性收缩，两个指针都只增不减
- 窗口 ≠ 双指针：窗口关注的是**两指针之间的区间**，双指针关注的是**两个指针本身**
- 典型适用场景：子数组/子串的最值、满足条件的最短/最长区间
