# 大 O 记号

> 上一课我们说双重循环"是 n² 级增长"。这一课给这种说法一个标准的名字和严格的规则。

## 为什么不用"跑了多少秒"

你可能会想：直接计时不就行了？**不行**，因为同一个程序在不同环境下耗时完全不同：

| 影响因素 | 差别 |
|---|---|
| 电脑快慢 | 同一份代码，老机器可能慢 5 倍 |
| 编程语言 | C 写的双重循环可能比 Python 的单循环还快 |
| 数据内容 | 有重复时会提前返回，快得多 |
| 当时负载 | 后台在下载东西，你就变慢了 |

**所以我们需要一个与机器无关、只描述算法本身的指标。** 这就是大 O 记号。

## 大 O 在说什么

**`O(f(n))` 的意思是：当数据规模 n 变得很大时，操作次数的增长趋势不超过 f(n) 的量级。**

三个要点：

**1. 只关心"增长趋势"，不关心具体数字。**

- 跑了 3n 次 → 记作 `O(n)`
- 跑了 3n + 100 次 → 还是 `O(n)`
- 跑了 n²/2 + 5n 次 → 记作 `O(n²)`

**2. 忽略常数倍数。**

`O(2n)` 和 `O(n)` 是同一回事。因为它俩的增长趋势一样：n 翻倍，耗时都翻倍。

**3. 只看最高阶项（最大的那一项）。**

`O(n² + n)` 记作 `O(n²)`。因为 n 很大时，n² 这一项会把 n 完全盖过去：

```
n = 10     → n² + n = 110          n 占 9%
n = 100    → n² + n = 10100        n 占 1%
n = 1000   → n² + n = 1001000      n 占 0.1%
```

> 💡 **类比**：说"我年收入 30 万"时，不会说"30 万零 5 块 3 毛"。大 O 就是这种"只说量级"的记法。

## 怎么数出复杂度

### 规则一：顺序执行，取最大的

```python
def f(n):
    for i in range(n):        # n 次
        print(i)
    for i in range(n):        # n 次
        print(i)
```

总共 2n 次 → **O(n)**（忽略常数 2）

### 规则二：嵌套循环，相乘

```python
def f(n):
    for i in range(n):            # n 次
        for j in range(n):        # 每次里面又跑 n 次
            print(i, j)
```

总共 n × n = n² 次 → **O(n²)**

### 规则三：不随 n 变化的操作，是 O(1)

```python
def f(n):
    x = 5 + 3          # O(1)
    print(x)           # O(1)
    return n * 2       # O(1)
```

不管 n 是 10 还是 1000 万，这几行都只做固定的几次操作 → **O(1)**

**注意**：`O(1)` 不是说"只做 1 次操作"，而是说"**操作次数不随 n 增长**"。

### 规则四：取最大的那部分

```python
def f(n):
    for i in range(n):            # O(n)
        print(i)
    for i in range(n):            # O(n²)
        for j in range(n):
            print(i, j)
```

`O(n) + O(n²)` → **O(n²)**（n² 更大，n 被吸收）

## 一个容易错的地方：循环变量的写法

下面两个看起来很像，但复杂度完全不同：

```python
# A：内层每次都跑满 n 次 → O(n²)
for i in range(n):
    for j in range(n):
        ...

# B：内层从 i 开始，总共约 n²/2 次 → 仍然是 O(n²)
for i in range(n):
    for j in range(i, n):
        ...
```

**B 虽然少了一半操作，但它仍然是 O(n²)** —— 因为 n 翻倍时它还是变成 4 倍。大 O 忽略 1/2 这个常数。

这就是为什么上一课的"挨个比"（内层 `range(i+1, n)`）虽然已经比朴素双重循环少了一半，却依然慢得要命。

## 常见的三种，先认全

| 写法 | 复杂度 | 典型场景 |
|---|---|---|
| 直接取值、算术运算 | `O(1)` | 访问列表第 i 项、判断奇偶 |
| 单层 for 遍历 | `O(n)` | 找最大值、求和、查重（用集合） |
| 双层 for 嵌套 | `O(n²)` | 两两比较、朴素排序 |

```python
# O(1)：不随 n 变化
def get_first(items):
    return items[0]

# O(n)：遍历一次
def find_max(items):
    m = items[0]
    for x in items:
        if x > m:
            m = x
    return m

# O(n²)：两两比较
def count_pairs(items):
    count = 0
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                count += 1
    return count
```

## 练习：判断下面代码的复杂度

```python
def mystery(items):
    total = 0
    for x in items:              # O(n)
        total += x
    for a in items:              # O(n²)
        for b in items:
            total += a * b
    return total                 # O(1)
```

答案：**O(n²)**。因为 `O(n) + O(n²) + O(1)` 里最大的是 O(n²)。

## 为什么要学这个

因为**它是你选解法的依据**：

- 看到双重循环 → 想想能不能降到 O(n)
- 面试官问"能优化吗" → 就是在问"能不能把复杂度降一阶"
- 代码跑得慢 → 先看复杂度，而不是先纠结某行代码

**复杂度降一阶，比任何微观优化都管用。** 上一课 4000 倍的差距，就是 O(n²) 降到 O(n) 带来的。

## 小结

- 大 O 描述**增长趋势**，与机器无关
- **忽略常数、只看最高阶项**
- 顺序取最大、嵌套相乘、不随 n 变化是 O(1)
- 先认全 `O(1)` / `O(n)` / `O(n²)` 这三种
- 下一课会把常见复杂度**排成一队**做对比

  n = 10
  count = 0
  for i in range(n):
      for j in range(i, n):
          count += 1
  
  # 应该是 10+9+8+...+1 = 55
  
  print("TODO：把这行改成你要打印的结果")
tests:
- assert "55" in __out
