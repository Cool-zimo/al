# 什么是算法复杂度

> 同一道题，两种解法都能给出正确答案。但在 8000 条数据上，一个跑 0.2 毫秒，另一个跑 916 毫秒——**差 4000 倍**。

## 先看一个真问题

给你一份名单，判断里面**有没有重名**。

```python
names = ["张三", "李四", "王五", "张三"]
```

"张三"出现了两次，答案应该是"有"。

**解法一：挨个比。** 拿第 1 个和后面所有人比，再拿第 2 个和后面比……

```python
def has_duplicate_v1(items):
    n = len(items)
    for i in range(n):
        for j in range(i + 1, n):
            if items[i] == items[j]:
                return True      # 找到一对相同的
    return False                  # 全都比完了，没有重复

print(has_duplicate_v1(["张三", "李四", "王五", "张三"]))   # True
print(has_duplicate_v1(["张三", "李四", "王五"]))           # False
```

**解法二：边走边记。** 用一个集合记住"已经见过的人"，每遇到一个新人就查一下"见过没"。

```python
def has_duplicate_v2(items):
    seen = set()            # 空集合，用来记住见过的
    for x in items:
        if x in seen:       # 之前见过 → 有重复
            return True
        seen.add(x)         # 没见过 → 记下来
    return False

print(has_duplicate_v2(["张三", "李四", "王五", "张三"]))   # True
print(has_duplicate_v2(["张三", "李四", "王五"]))           # False
```

两个都能给出正确答案。**接下来才是真正的问题。**

## 它们差多远？实测说话

让两份名单都没有重复（这样两个函数都必须"跑满"才能回答"没有"），然后计时：

```python
import time

def time_ms(fn, items):
    best = float('inf')
    for _ in range(3):                  # 跑 3 次取最快，减少偶然误差
        t0 = time.perf_counter()
        fn(items)
        best = min(best, (time.perf_counter() - t0) * 1000)
    return best

for n in [500, 1000, 2000, 4000, 8000]:
    items = list(range(n))              # 0~n-1，完全没有重复
    print(f"n={n:>5}  双重循环 {time_ms(has_duplicate_v1, items):>8.2f} ms"
          f"   集合 {time_ms(has_duplicate_v2, items):>7.3f} ms")
```

在一台普通笔记本电脑上（Python 3.10）的实测结果：

```
n=  500  双重循环     3.41 ms   集合   0.015 ms
n= 1000  双重循环    13.74 ms   集合   0.028 ms
n= 2000  双重循环    54.95 ms   集合   0.067 ms
n= 4000  双重循环   221.78 ms   集合   0.121 ms
n= 8000  双重循环   916.58 ms   集合   0.228 ms
```

**n=8000 时，双重循环跑了将近 1 秒，集合只用了 0.0002 秒——4000 倍的差距。**

> 📌 你的机器上数字会不一样（可能快些也可能慢些），但**差距的量级一定成立**。我们关心的不是具体跑了多少毫秒，而是"它们差多远、为什么差"。

## 为什么差这么多

关键在于**比较的次数**。

**解法一（双重循环）**：n 个人，第 1 个要比 n-1 次，第 2 个要比 n-2 次……加起来大约是

```
(n-1) + (n-2) + ... + 1 = n × (n-1) / 2 ≈ n² / 2 次
```

- n = 100 → 约 5000 次
- n = 1000 → 约 50 万次
- n = 8000 → 约 3200 万次

**解法二（集合）**：每个人只做一次"查一查见过没"，加起来正好 n 次。

- n = 100 → 100 次
- n = 1000 → 1000 次
- n = 8000 → 8000 次

**注意规律**：n 变成 2 倍时——

- 解法一的比较次数变成 **4 倍**（因为是 n²）
- 解法二的比较次数变成 **2 倍**（因为是 n）

实测数据完美印证了这一点：

```
双重循环：n 从 1000 → 2000，耗时 13.74 → 54.95 ms，正好 4.00 倍
集合：    n 从 1000 → 2000，耗时 0.028 → 0.067 ms，约 2.4 倍
```

## 三个关键认知

**一、正确只是及格线。**

两个函数都"对"。但一个在 8000 条数据上要花 1 秒，另一个花 0.0002 秒。**面试、工程、竞赛里，"能跑出正确答案"从来不是终点。**

**二、数据规模是放大镜。**

小数据量时差距不明显（n=100 时两者都是毫秒级，你根本感觉不到）。**随着 n 增大，差距会爆炸式拉开**：

按实测趋势外推：

| 数据量 | 双重循环 | 集合 |
|---|---|---|
| 8 千 | 0.92 秒 | 0.0002 秒 |
| 10 万 | 约 143 秒（2 分 23 秒） | 约 0.003 秒 |
| 100 万 | 约 4 小时 | 约 0.03 秒 |

**100 万条数据时，一个要跑 4 小时，另一个不到半毫秒。** 这不是"优化"，这是"能用"和"不能用"的区别。

**三、快慢是可以分析出来的，不用靠猜。**

你不需要真的跑一遍才知道谁快——只要数清楚"操作次数随 n 怎么增长"就行。这就是**复杂度分析**，也是这一章的核心。

## 本册要用到的语法（30 秒回顾）

算法题要写函数，这里快速确认几个你必须会的东西：

```python
# 1. 定义函数：def + 名字 + 参数，用 return 把结果送出去
def add(a, b):
    return a + b

# 2. for 循环遍历
for x in [1, 2, 3]:
    print(x)

# 3. range(n) 产生 0~n-1
for i in range(3):        # i 依次是 0, 1, 2
    print(i)

# 4. 条件判断
if x > 0:
    print("正数")

# 5. 集合 set：装不重复的元素，查"在不在里面"极快
s = set()
s.add(1)
print(1 in s)      # True
print(2 in s)      # False

# 6. len() 取长度
print(len([1, 2, 3]))     # 3
```

**这些就够了。** 后面每道算法题，都是在 `def` 里用 `for` / `if` / `return` 把思路写出来。

> 💡 如果 `def` 和 `return` 你还觉得陌生，建议先补《Python 详细基础 1》的相关章节再回来，会更轻松。

## 小结

- 同一问题可以有多种解法，**都能对，但快慢天差地别**
- 差距来自**操作次数随数据规模 n 的增长方式**
- n² 级增长（双重循环）在大数据上是灾难，n 级增长（单次遍历）则轻松应对
- **复杂度分析**让我们不用跑代码就能预判快慢

**下一课讲"大 O 记号"**——用它给这种增长方式起个标准的名字。

- 2 倍
- 4 倍
- 8 倍
- 不变
answer: 1
explain: 比较次数约 n²/2，是平方级增长。n 翻倍 → n² 变成 4 倍。这正是它慢的根本原因：数据量一大，平方项会迅速失控。实测也印证了这点（n 从 1000 到 2000，耗时正好 4 倍）。

  def has_duplicate(nums):

      return None

  [1,2,3,3,4] -> True
