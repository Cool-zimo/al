# 亲手实测复杂度

> 分析出来说是 O(n²)，怎么验证？**跑一遍，看 n 翻倍时耗时翻几倍。** 这一课给你一套可复用的测量方法。

## 怎么计时

### 方法一：time.perf_counter()

```python
import time

t0 = time.perf_counter()
# ... 要测的代码 ...
elapsed = (time.perf_counter() - t0) * 1000    # 毫秒
print(f"耗时 {elapsed:.3f} ms")
```

**为什么用 `perf_counter` 而不是 `time.time()`**：`perf_counter` 是专门用来计时的高精度时钟，不受系统时间调整影响。

### 方法二：timeit 模块（更严谨）

```python
import timeit

t = timeit.timeit(lambda: sum(range(1000)), number=1000)
print(f"1000 次共 {t*1000:.1f} ms，单次 {t*1000/1000:.4f} ms")
```

**`number=N` 表示重复跑 N 次**，返回总耗时。它自动帮你做了"多次平均"，比手写计时可靠。

## 关键：跑多次，取最小值

**单次计时几乎不可信。** 同一个操作连跑 5 次，实测结果：

```
第1次 14.5 ms
第2次 11.2 ms
第3次 10.8 ms
第4次 10.8 ms
第5次 10.5 ms   ← 最小值
```

第 1 次明显偏慢（Python 内部还在"热身"），后面趋于稳定。

**为什么取最小值而不是平均值？**

因为计时只会因为"被其他事情打扰"而变慢——系统调度、后台程序、CPU 降频，都只会**增加**耗时，不会让它变快。所以**最小值最接近"这段代码真实需要的纯净时间"**。

```python
def time_ms(fn, *args, reps=3):
    best = float('inf')
    for _ in range(reps):
        t0 = time.perf_counter()
        fn(*args)
        best = min(best, (time.perf_counter() - t0) * 1000)
    return best
```

**这个 `time_ms` 是你要记住的模板**——后面所有测量都用它。

## 实测验证复杂度：n 翻倍法

**核心方法**：让 n 翻倍，看耗时变成几倍。

- 变成 **2 倍** → 是 O(n)
- 变成 **4 倍** → 是 O(n²)
- 变成 **8 倍** → 是 O(n³)
- 几乎**不变** → 是 O(1) 或 O(log n)

```python
import time

def count_pairs(items):        # O(n²)：两两比较
    c = 0
    n = len(items)
    for i in range(n):
        for j in range(i + 1, n):
            if items[i] < items[j]:
                c += 1
    return c

def count_all(items):          # O(n)：遍历一次
    c = 0
    for x in items:
        c += 1
    return c

def measure(fn, n):
    items = list(range(n))
    best = float('inf')
    for _ in range(3):
        t0 = time.perf_counter()
        fn(items)
        best = min(best, (time.perf_counter() - t0) * 1000)
    return best

prev = None
for n in [500, 1000, 2000, 4000]:
    t = measure(count_pairs, n)
    ratio = f"{t/prev:.2f}" if prev else "—"
    print(f"n={n:>5}  {t:>8.2f} ms   （相对上一次：{ratio} 倍）")
    prev = t
```

第 1 课我们跑过这个，实测结果是：

```
n=  500     3.41 ms
n= 1000    13.74 ms   （4.03 倍）
n= 2000    54.95 ms   （4.00 倍）
n= 4000   221.78 ms   （4.04 倍）
```

**每次都是 4.00 倍左右——完美印证了 O(n²)。** 如果换成 O(n) 的 `count_all`，你会看到 2 倍左右。

## 一个必须知道的干扰：内置函数是用 C 写的

```python
import time

items = list(range(100000))

def manual_sum(xs):          # 纯 Python 循环
    total = 0
    for x in xs:
        total += x
    return total

# 实测：手写循环 1.81 ms，内置 sum() 0.20 ms → 内置快 9 倍
```

**同样的 O(n) 操作，内置函数快 9 倍。** 原因是 `sum()` 内部是 C 循环，没有 Python 解释器逐行执行的开销。

**这意味着**：

- **大 O 告诉你增长趋势**（n 翻倍 → 2 倍）
- **常数因子决定基准快慢**（同样是 O(n)，C 实现比 Python 循环快近 10 倍）

所以优化有两条路：

1. **降复杂度**（O(n²) → O(n)）——收益巨大，优先做
2. **降常数**（用内置函数、用 C 库）——收益有限但在同一复杂度内也有价值

> 💡 **顺序很重要**：先降复杂度，再抠常数。第 1 课 4000 倍的差距来自降复杂度；这里的 9 倍只是抠常数。

## 测量时的四个陷阱

**1. 数据量太小，测不出来。**

n=10 时，O(n) 和 O(n²) 都是几微秒，噪声完全掩盖了差距。**至少测到几千**，趋势才会显现。

**2. 提前退出会掩盖最坏情况。**

如果数据里"恰好有重复"，查重函数会在第一次命中时就返回，跑得飞快。**要测最坏情况，就得构造不会提前退出的数据**（比如 `list(range(n))` 保证无重复）。

**3. 第一次运行包含热身开销。**

Python 有各种延迟加载机制，第一次调用往往偏慢。**跑 3 次取最小值**能避开。

**4. 后台程序会干扰。**

测的时候关掉下载、视频、杀毒扫描。**只看最小值**也是一种防御。

## 一个完整的测量模板

把这套流程固化下来，以后随时能用：

```python
import time

def measure(fn, make_data, sizes, reps=3):
    """测 fn 在不同数据规模下的耗时，返回 [(n, 毫秒, 相对倍数)]"""
    out = []
    prev = None
    for n in sizes:
        data = make_data(n)
        best = float('inf')
        for _ in range(reps):
            t0 = time.perf_counter()
            fn(data)
            best = min(best, (time.perf_counter() - t0) * 1000)
        ratio = (best / prev) if prev else None
        out.append((n, best, ratio))
        prev = best
    return out

# 用法
sizes = [500, 1000, 2000, 4000]
for n, ms, ratio in measure(count_pairs, lambda n: list(range(n)), sizes):
    r = f"{ratio:.2f}x" if ratio else "—"
    print(f"n={n:>5}  {ms:>8.2f} ms  {r}")
```

**拿到"倍数"这一列，你就知道它是什么复杂度了。**

## 从实测反推复杂度

| n 翻倍后的耗时倍数 | 对应复杂度 |
|---|---|
| ≈ 1（几乎不变） | O(1) 或 O(log n) |
| ≈ 2 | O(n) |
| ≈ 2.x（略高于 2） | O(n log n) |
| ≈ 4 | O(n²) |
| ≈ 8 | O(n³) |

**这是工程里最实用的技巧**：不用看代码，跑两个规模就知道瓶颈在哪。

## 小结

- 计时用 `time.perf_counter()` 或 `timeit`
- **跑多次取最小值**（噪声只会让结果变慢）
- **n 翻倍法**：耗时翻 2 倍是 O(n)，翻 4 倍是 O(n²)
- 内置函数是 C 实现的，同复杂度下快很多——**先降复杂度，再抠常数**
- 注意四个陷阱：数据太小、提前退出、首次热身、后台干扰
