# 常见复杂度对比

> 把常见复杂度排成一队，看看它们之间到底差多少个数量级。

## 从小到大排个队

| 复杂度 | 名字 | n=1000 时大约的操作数 |
|---|---|---|
| `O(1)` | 常数 | 1 |
| `O(log n)` | 对数 | 约 10 |
| `O(n)` | 线性 | 1 000 |
| `O(n log n)` | 线性对数 | 约 10 000 |
| `O(n²)` | 平方 | 1 000 000 |
| `O(2ⁿ)` | 指数 | 约 10³⁰⁰（宇宙都算不完） |

**从 O(n) 到 O(n²)，n=1000 时差了 1000 倍。到 O(2ⁿ) 就直接不可完成了。**

## O(1)：不随规模变化

```python
def get_middle(items):
    return items[len(items) // 2]      # 无论多长，一次就拿到
```

典型操作：按下标访问、字典/集合的查询、算术运算。

**注意**：O(1) 不代表"快"，只代表"不随 n 变慢"。一个 O(1) 的操作如果本身很重（比如读一个大文件），依然可能耗时很久。

## O(log n)：每次砍一半

**这是第二好的复杂度，也是最能体现算法威力的一种。**

直觉来源：**翻书找页码**。想在 1000 页的书里找第 700 页：

1. 随手翻到中间 → 发现是 500 页，太靠前了，**右半本**继续
2. 翻到右半本的中间 → 750 页，太靠后了，**左半部分**继续
3. ……每次都把范围砍掉一半

**每次砍一半，需要多少次才能砍到只剩 1 个？**

```
1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1
```

**只用了 9 步。** 而从头到尾一页页翻需要 1000 步。

数学上：**log₂(1000) ≈ 10**，所以叫"对数级"。

| n | 一页页找 O(n) | 每次砍一半 O(log n) |
|---|---|---|
| 1 000 | 1 000 步 | 10 步 |
| 100 万 | 100 万步 | 20 步 |
| 10 亿 | 10 亿步 | 30 步 |

**数据量翻 1000 倍，log n 只多了 10 步。** 这就是为什么二分查找是必修课——下一章会详细讲它。

```python
def binary_steps(n):
    """n 个有序元素里二分查找，最多需要几步"""
    steps = 0
    while n > 0:
        n //= 2          # 每次砍一半
        steps += 1
    return steps

print(binary_steps(1000))       # 10
print(binary_steps(1000000))    # 20
```

## O(n)：遍历一遍

最直观的一种：每个元素看一次。

```python
def find_max(items):
    m = items[0]
    for x in items:          # 每个元素恰好看一次
        if x > m:
            m = x
    return m
```

**O(n) 通常就是"能做到的最好情况"** —— 毕竟你至少得把数据看一遍，才知道答案。

## O(n log n)：高效排序的极限

"n 个元素，每个都要处理 log n 次"。所有**比较类排序**（归并、快排、堆排）的最优复杂度就是 O(n log n)。

直觉：把 n 个元素排好序，相当于"每次砍一半地分治" × "每层都要处理全部 n 个元素"。

```python
# Python 内置的排序就是 O(n log n)
items = [5, 2, 8, 1]
items.sort()
print(items)        # [1, 2, 5, 8]
```

**这是排序能达到的最好结果**，已经被数学证明（比较类排序的下界）。

## O(n²)：双重循环

两两比较、朴素排序。上一课已经见识过它的威力：

```
n = 1000  → 100 万次操作
n = 10000 → 1 亿次操作
```

**一般规则：n 超过几千，O(n²) 就该警惕了。**

## O(2ⁿ)：暴力枚举，禁区

每增加一个元素，可能性翻倍。典型场景：枚举一个集合的所有子集。

```python
# n 个元素的所有子集，一共 2ⁿ 个
# n=20 → 100 万个
# n=30 → 10 亿个
# n=60 → 比宇宙中的原子数还多
```

**n 只要到 30 左右，O(2ⁿ) 就基本不可完成了。** 遇到这种问题，正确做法通常是换思路（动态规划、贪心），而不是优化常数。

## 一张图感受差距

假设每秒能做 1 亿次操作：

| 复杂度 | n=50 | n=1000 | n=10 万 |
|---|---|---|---|
| O(log n) | 瞬间 | 瞬间 | 瞬间 |
| O(n) | 瞬间 | 瞬间 | 0.001 秒 |
| O(n log n) | 瞬间 | 瞬间 | 0.002 秒 |
| O(n²) | 瞬间 | 0.01 秒 | **10 秒** |
| O(2ⁿ) | **3.5 年** | 宇宙毁灭 | 宇宙毁灭 |

**注意 O(2ⁿ) 那一行**：n=50 就要 3.5 年。它比 O(n²) 恐怖得多——O(n²) 只是慢，O(2ⁿ) 是完全不可行。

## 怎么快速判断该优化到什么程度

| 数据规模 | 你能承受的最高复杂度 |
|---|---|
| n ≤ 100 | O(n²) 勉强可以 |
| n ≤ 1000 | O(n²) 还行，最好 O(n log n) |
| n ≤ 10 万 | 必须 O(n log n) 或更好 |
| n ≥ 100 万 | 基本只能 O(n) 或 O(log n) |

**这是一条实用的经验法则**：看到题目给的数据范围，先在心里定个"复杂度预算"，再决定用什么算法。

## 小结

- 从小到大：`O(1)` < `O(log n)` < `O(n)` < `O(n log n)` < `O(n²)` < `O(2ⁿ)`
- **O(log n) 是"每次砍一半"**，数据量翻千倍只多 10 步
- **O(n log n) 是比较排序的极限**
- **O(n²) 在 n 过几千后吃力**，**O(2ⁿ) 是禁区**
- 看到数据规模，先定"复杂度预算"

**下一课讲空间复杂度**——时间能换，内存也能换。

## 随堂练习

亲手验证对数的威力。

```quiz
type: code
q: 算一算 100 万个有序元素二分查找最多需要几步，打印出来
starter: |
  def binary_steps(n):
      steps = 0
      while n > 0:
          n //= 2
          steps += 1
      return steps
  
  # 100 万 → 打印结果（应该是 20）
  
  print("在这里改")
tests:
- assert "20" in __out
hint: print(binary_steps(1000000))。每次 n//=2 砍掉一半，砍到 0 为止，数的就是步数。2^20 ≈ 104 万，所以是 20 步。
explain: 100 万个元素挨个找要 100 万步，二分只要 20 步 —— 差 5 万倍。这就是 log n 的威力：数据量翻一倍，步数只加 1。
```
