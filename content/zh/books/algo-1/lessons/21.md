# 字符串的不可变性：为什么拼接在循环里是 O(n²)

> 前四章都是数组。这一章进入字符串——看似简单，但**字符串的不可变性**会悄悄拖慢你的代码。

## 什么是不可变性

**Python 中的字符串一旦创建就不能修改。**

```python
s = "hello"
# s[0] = "H"     # TypeError: 'str' object does not support item assignment
```

**字符串没有 `s[0] = "H"` 这个操作。** 想改，只能新建一个。

```python
s = "hello"
new_s = "H" + s[1:]    # 新建了一个字符串 "Hello"
print(s)               # "hello"（原字符串没变）
print(new_s)           # "Hello"
```

**每次"修改"字符串，都是新建一个字符串。**

## 这为什么是个性能陷阱

**问题场景**：循环里不断拼接字符串。

```python
# 错误示范：在循环里用 += 拼接
def concat_slow(n):
    s = ""
    for i in range(n):
        s += str(i)      # 每次都新建字符串！
    return s

print(concat_slow(5))   # "01234"
```

**每次 `s += str(i)` 发生了什么？**

1. 分配一块新内存（长度是 `len(s) + 1`）
2. 把 `s` 的所有字符拷贝过去
3. 把 `str(i)` 追加到最后
4. 丢弃旧的 `s`

**第 i 次操作要拷贝 i 个字符。** 总拷贝次数 = 0 + 1 + 2 + ... + (n-1) = **O(n²)**。

```python
# n=1000 时：
# 第 1 次拷贝 1 个字符
# 第 2 次拷贝 2 个字符
# ...
# 第 1000 次拷贝 1000 个字符
# 总共约 50 万次拷贝
```

## 实测对比

```python
import time

def concat_slow(n):
    s = ""
    for i in range(n):
        s += str(i)
    return s

def concat_fast(n):
    parts = []
    for i in range(n):
        parts.append(str(i))
    return "".join(parts)

for n in [1000, 2000, 4000, 8000]:
    t1 = time.perf_counter()
    concat_slow(n)
    t1 = (time.perf_counter() - t1) * 1000

    t2 = time.perf_counter()
    concat_fast(n)
    t2 = (time.perf_counter() - t2) * 1000

    print(f"n={n:>5}  += {t1:>8.3f} ms   join {t2:>7.4f} ms")
```

输出（近似）：

```
n= 1000  +=    0.8 ms   join  0.2 ms
n= 2000  +=    3.1 ms   join  0.3 ms
n= 4000  +=   12.5 ms   join  0.5 ms
n= 8000  +=   50.0 ms   join  1.0 ms
```

**`+=` 版本耗时约 4 倍增长（O(n²)），`join` 版本约 2 倍增长（O(n)）。**

## 正确做法：join

```python
parts = ["hello", "world", "python"]
result = "".join(parts)      # "helloworldpython"
print(result)
```

**`join` 的工作原理**：

1. 先遍历所有字符串，**算出总长度**
2. 一次性分配一块足够大的内存
3. 把所有字符串拷贝进去

**总拷贝次数 = 所有字符数 = O(n)**（线性）。

```python
# 正确：用列表收集，最后 join
def concat_good(n):
    parts = []
    for i in range(n):
        parts.append(str(i))
    return "".join(parts)

print(concat_good(5))   # "01234"
```

## 字符串常用操作的时间复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `s[i]` 访问 | O(1) | 按下标取字符 |
| `s[i:j]` 切片 | O(j-i) | **会拷贝** |
| `s + t` 拼接 | O(len(s)+len(t)) | **会新建** |
| `s += t` | O(len(s)+len(t)) | **每次都新建** |
| `s.split()` | O(n) | 遍历一次 |
| `sep.join(list)` | O(n) | 遍历一次 |
| `s in t`（子串） | O(nm) | 朴素匹配 |

**关键**：切片和拼接都会**新建字符串**，在循环里反复用就是 O(n²)。

## 常见错误

### 错误一：在循环里反复切片

```python
# 错误：每次循环都切片（新建字符串）
s = "abcdefghij"
while len(s) > 0:
    print(s[0])
    s = s[1:]       # 每次新建，O(n²)
```

**每次 `s[1:]` 都要拷贝剩下的所有字符。** n 次循环就是 O(n²)。

### 错误二：用 sum 拼接字符串

```python
# 错误
result = sum(strings, "")   # TypeError: sum() can't sum strings
```

**`sum` 不支持字符串。** 用 `"".join()`。

### 错误三：以为字符串像列表一样可变

```python
# 想"原地修改"字符串
s = "hello"
s.replace("h", "H")         # 返回新字符串 "Hello"
print(s)                    # "hello" ← 原字符串没变！

# 正确
s = s.replace("h", "H")
print(s)                    # "Hello"
```

**`replace`、`upper`、`strip` 等所有字符串方法都返回新字符串，不修改原字符串。**

## 什么时候可以直接用 +=

**短字符串、拼接次数少时，`+=` 没问题。**

```python
# 完全 OK：只有几次拼接
greeting = "Hello, " + name + "! Welcome to " + city + "."
```

**Python 对短字符串的 `+=` 有优化**（如果字符串没有其他引用，会原地扩容）。但**在循环里、字符串很长时**，一定要用 `join`。

> 💡 **经验法则**：循环里拼接 → 用列表 + join；普通拼接 → `+=` 或 `+` 都可以。

## 字符串转列表再改

**如果需要频繁"修改"字符，可以先转成列表，改完再拼回来：**

```python
# 把 "hello" 的第一个字符改成大写
s = "hello"
chars = list(s)       # ['h', 'e', 'l', 'l', 'o']
chars[0] = "H"        # 列表可以修改
result = "".join(chars)
print(result)         # "Hello"
```

**时间 O(n)**——列表修改是 O(1)，最后 join 是 O(n)。

## 小结

- 字符串**不可变**：`s[0] = "x"` 会报错
- 所有修改操作都**返回新字符串**
- 循环里用 `+=` 拼接是 **O(n²)**——每次都新建
- 正确做法：用**列表收集 + `join`**，O(n)
- 需要修改字符 → 转列表 → 改 → join 回来
