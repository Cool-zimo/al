# 空间复杂度

> 上一课比的是时间。这一课比内存——**用空间换时间**是最常见的优化手段，但不是免费的。

## 什么是空间复杂度

**算法运行时额外占用的内存，随数据规模 n 的增长趋势。**

注意关键词是**额外**：输入本身占的内存不算（那是必须给的）。

```python
def find_max(items):          # 输入 items 占的内存不算
    m = items[0]              # 只用了 1 个变量 m
    for x in items:
        if x > m:
            m = x
    return m                  # 额外空间 O(1)
```

不管 items 有 10 个还是 1000 万个，这个函数只多了 1 个变量 → **空间复杂度 O(1)**。

```python
def copy_double(items):
    result = []
    for x in items:
        result.append(x * 2)  # 新建了一个和输入等长的列表
    return result             # 额外空间 O(n)
```

新建的 result 和 items 一样长 → **空间复杂度 O(n)**。

## 经典案例：两数之和

**题目**：给一个数组和一个目标值，找出**和等于目标值**的两个数的下标。

```python
nums = [2, 7, 11, 15]
target = 9
# 2 + 7 = 9，答案是下标 [0, 1]
```

### 解法一：暴力枚举（O(n²) 时间，O(1) 空间）

```python
def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []       # 没找到

print(two_sum_brute([2, 7, 11, 15], 9))     # [0, 1]
```

只用了一个循环变量，没有新建数组 → **空间 O(1)**，但时间是 O(n²)。

### 解法二：哈希辅助（O(n) 时间，O(n) 空间）

**思路**：一边遍历，一边把"见过的值 → 它的下标"记进字典。遇到一个新数 x 时，查一下 `target - x` 是不是见过。

```python
def two_sum_hash(nums, target):
    seen = {}                      # 值 -> 下标
    for i, x in enumerate(nums):
        need = target - x
        if need in seen:           # 之前见过需要的那个数
            return [seen[need], i]
        seen[x] = i                # 记住当前这个
    return []

print(two_sum_hash([2, 7, 11, 15], 9))       # [0, 1]
```

多了一个字典 `seen`，最多存 n 个条目 → **空间 O(n)**，但时间降到了 O(n)。

### 实测对比

```python
import time
# 构造无解的情况，逼两个函数都跑满
for n in [500, 1000, 2000, 4000]:
    nums = list(range(n))
    target = -1                   # 保证找不到
    ...
```

实测结果：

```
n=  500  暴力     4.50 ms   哈希   0.027 ms    快 168 倍
n= 1000  暴力    18.38 ms   哈希   0.052 ms    快 353 倍
n= 2000  暴力    72.97 ms   哈希   0.107 ms    快 680 倍
n= 4000  暴力   292.80 ms   哈希   0.247 ms    快 1183 倍
```

**这就是"用空间换时间"**：多花一份 O(n) 的内存（那个字典），换来从 O(n²) 到 O(n) 的跨越。

## 什么时候不值得换

**"空间换时间"不是永远正确。** 三种情况要慎重：

**1. 内存本身就紧张。**

嵌入式设备、超大数据集。如果 n = 1 亿，一个 O(n) 的辅助字典要占好几个 GB——可能直接内存溢出。

**2. 数据量大到"存不下"时，O(1) 空间的解法反而更实用。**

同样是"判断有没有重复"，有个**排序后相邻比较**的做法：

```python
def has_duplicate_sort(items):
    items = sorted(items)         # 排序：O(n log n) 时间
    for i in range(1, len(items)):
        if items[i] == items[i - 1]:
            return True
    return False
```

（注意 `sorted()` 会返回一个新列表，所以严格说它也是 O(n) 空间；如果允许修改原数组，用 `items.sort()` 就是 O(1) 额外空间。）

对比三种方案：

| 方案 | 时间 | 额外空间 |
|---|---|---|
| 双重循环 | O(n²) | O(1) |
| 集合 | O(n) | O(n) |
| 排序后相邻比 | O(n log n) | O(1)（若原地排序） |

**排序方案是折中**：时间比集合慢一点，但省下了那 O(n) 的内存。

**3. 追求"原地"算法的场景。**

很多题目要求"**原地修改**，不允许新建数组"（下一章的双指针题就会遇到）。这时 O(1) 空间是硬指标。

## 时间换空间：反向操作

反过来也成立——**用时间换空间**：

```python

# 代价是需要更仔细地下标控制（第 2 章会详细讲）
```

这种情况少见，但在内存受限时是唯一出路。

## 常见操作的空间开销

| 写法 | 额外空间 |
|---|---|
| `for x in items` | O(1) |
| `set(items)` / `dict` | O(n) |
| `sorted(items)` | O(n)（返回新列表） |
| `items.sort()` | O(1)（原地，视实现而定） |
| `items[:]` / `items[1:]` | O(n)（切片会复制） |
| `list(range(n))` | O(n) |

> ⚠️ **切片会复制！** `items[1:3]` 看起来只是"取一部分"，实际上新建了一个列表。在循环里反复切片是很隐蔽的空间浪费。

## 怎么分析空间复杂度

和时间的规则一样，只是数的是**内存**而不是操作次数：

1. 有没有新建和 n 等长的数据结构（列表、集合、字典）→ 有就是 O(n)
2. 递归调用多少层 → 递归深度 d 就是 O(d)（后面章节会遇到）
3. 只有固定几个变量 → O(1)

## 小结

- 空间复杂度衡量**额外内存**随 n 的增长
- **用空间换时间**是最常见优化（哈希辅助是典型）
- 内存紧张、要求原地、数据量极大时，要反过来考虑省空间
- 切片、`sorted()`、建集合都会产生 O(n) 的额外空间
