# 双指针是什么：为什么暴力 O(n²) 能降到 O(n)

> 上一章我们学会用哈希表把"两数之和"从 O(n²) 降到 O(n)。这一章讲另一种降维思路：**用两个指针代替一重循环**，几乎不花额外空间。

## 先看暴力解法有多贵

**题目**：在一个**已排序**的数组里找两个数，使它们的和等于 `target`，返回它们的下标。

```python
nums = [2, 7, 11, 15, 18, 21]
target = 18
# 7 + 11 = 18，答案是 [1, 2]
```

**暴力做法**：拿每个数和后面所有数配对。

```python
def two_sum_brute(nums, target):
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []

print(two_sum_brute([2, 7, 11, 15, 18, 21], 18))   # [1, 2]
print(two_sum_brute([2, 7, 11, 15], 99))            # []
```

**这是 O(n²)**——n=1000 时要比较约 50 万次。

**关键前提：数组已经排好序。** 排序让我们可以利用"大小关系"来剪枝，这是双指针能工作的根本原因。

## 双指针的思路：一左一右，两头夹

放两个指针：

- `left` 从**最左边**出发（最小的数）
- `right` 从**最右边**出发（最大的数）

每次看 `nums[left] + nums[right]`：

| 情况和 target 的关系 | 说明 | 怎么办 |
|---|---|---|
| 和 **等于** target | 找到了 | 返回 |
| 和 **小于** target | 当前和太小 | left 右移，让和大一点 |
| 和 **大于** target | 当前和太大 | right 左移，让和小一点 |

```python
def two_sum_sorted(nums, target):
    left = 0                  # 最左边
    right = len(nums) - 1     # 最右边

    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left, right]
        elif s < target:
            left += 1         # 太小 → 左指针右移，和大一点
        else:
            right -= 1        # 太大 → 右指针左移，和小一点
    return []

print(two_sum_sorted([2, 7, 11, 15, 18, 21], 18))   # [1, 2]
print(two_sum_sorted([2, 7, 11, 15], 99))            # []
```

## 为什么它一定收敛

每次循环 `left` 或 `right` 一定会动一格，且两者相向移动。最坏情况下 `left` 一路走到 `right`，循环正好执行 **n-1 次**。

**总操作数：n-1 次 → 复杂度 O(n)。**

和暴力解对比：

| 做法 | 时间 | 额外空间 |
|---|---|---|
| 暴力双重循环 | O(n²) | O(1) |
| 哈希表（无序数组） | O(n) | O(n) |
| **双指针（有序数组）** | **O(n)** | **O(1)** |

**这就是双指针的价值：在 O(n) 时间里做到 O(1) 空间。**

## 手跑一遍，理解指针怎么动

`nums = [2, 7, 11, 15, 18, 21]`，`target = 18`：

```
初始：left=0, right=5
nums[0]+nums[5] = 2+21 = 23 > 18 → right 左移到 4

left=0, right=4
nums[0]+nums[4] = 2+18 = 20 > 18 → right 左移到 3

left=0, right=3
nums[0]+nums[3] = 2+15 = 17 < 18 → left 右移到 1

left=1, right=3
nums[1]+nums[3] = 7+15 = 22 > 18 → right 左移到 2

left=1, right=2
nums[1]+nums[2] = 7+11 = 18 == 18 → 找到！返回 [1, 2]
```

每一步都在"排除"不可能的情况，而不是傻傻地枚举所有组合。

## 三个容易踩的坑

### 坑一：left < right 写成 left <= right

如果允许 `left == right`，你会把**同一个元素用两次**。

```python
# 错误写法
while left <= right:    # left 可能追上 right，导致同一个元素用两遍
    ...
```

`target = 4`，`nums = [2]` 时，`left=0, right=0`，`nums[0]+nums[0] = 4`，会错误地返回 `[0, 0]`。

### 坑二：忘记处理"找不到"的情况

找不到时要返回空列表 `[]`，别让函数默认返回 `None`。

```python
# 错误：没写 return []
def two_sum_buggy(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        s = nums[left] + nums[right]
        if s == target:
            return [left, right]
        elif s < target:
            left += 1
        else:
            right -= 1
    # 循环结束没 return → 返回 None

print(two_sum_buggy([1, 2, 3], 99))   # None（应该返回 []）
```

### 坑三：数组没排序就套用

双指针的前提是**有序**。如果数组无序，必须先排序，或者改用哈希表解法。

```python
# 错误：无序数组直接用双指针
nums = [11, 2, 15, 7]   # 无序
print(two_sum_sorted(nums, 18))   # 可能返回 [] 或错误答案
```

> 💡 **判断用哪种解法**：数组已排序 → 双指针；数组无序但允许 O(n) 空间 → 哈希表；数组无序且必须 O(1) 空间 → 先排序再用双指针（排序 O(n log n)，比 O(n²) 好）。

## 双指针的三种常见形态

后面几课会逐一展开：

| 形态 | 指针怎么动 | 典型题目 |
|---|---|---|
| **对撞指针** | 一头一尾，相向 | 两数之和、回文判断、反转 |
| **快慢指针** | 一快一慢，同方向 | 删除重复、移除元素、找中点 |
| **滑动窗口** | 同向，维护区间 | 最长子串、最短子数组 |

**本课是对撞指针的开场。**

## 小结

- 双指针用两个下标代替一重循环，**把 O(n²) 降到 O(n)**
- 前提：数组**已排序**，能利用大小关系剪枝
- 对撞指针：left 从左、right 从右，根据和与 target 的关系决定谁动
- **空间 O(1)**，这是它比哈希表更省的地方
- 注意三个坑：`left < right`、处理找不到、确保有序

- 完全没影响，答案一样
- 可能把同一个元素用两次
- 会漏掉正确答案
- 会死循环

explain: 当 left == right 时，nums[left] 和 nums[right] 是同一个元素。target 恰好等于"这个值的两倍"时就会错误地把同一个位置用两遍。比如 target=4、nums=[2]，会返回 [0, 0]。
