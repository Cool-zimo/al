# 固定窗口：长度为 k 的最大和与滑动平均值

> 固定窗口是所有窗口技巧的入门。窗口长度 k 不变，每次右移只需"去掉最左、加上最右"。这一课把套路掰透，并揭示一个隐藏的性能陷阱。

## 固定窗口的核心操作

固定窗口的骨架只有三步：

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
k = 4

# 第一步：算出第一个窗口
window_sum = sum(nums[:k])
max_sum = window_sum

# 第二步：逐个滑动
for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_sum = max(max_sum, window_sum)

# 第三步：输出结果
print(max_sum)  # 21
```

`window_sum - nums[i-k] + nums[i]` 就是固定窗口的灵魂。**减掉滑出窗口的那个元素，加上滑进窗口的那个元素**，窗口和就更新好了。

## 为什么是 O(n) 而不是 O(nk)

很多人写窗口时是这样写的：

```python
# 错误示范：每个窗口重新求和
nums = [3, 1, 4, 1, 5, 9, 2, 6]
k = 4
max_sum = 0

for i in range(len(nums) - k + 1):
    current_sum = sum(nums[i:i + k])  # 每次 O(k)！
    max_sum = max(max_sum, current_sum)

print(max_sum)  # 21
```

**结果对，但效率差。** `sum(nums[i:i+k])` 每次都要遍历 k 个元素，外层循环 n-k+1 次，总复杂度 **O(nk)**。当 n=100000、k=50000 时，这就是 50 亿次操作。

用滑动窗口后，每个元素**只被加一次、减一次**，总复杂度 **O(n)**，无论 k 多大。

## 翻车现场一：用整数除法算平均值

求"长度 k 的最大平均子数组"是 LeetCode 643 原题。很多人写出这样的代码：

```python
nums = [1, 12, -5, -6, 50, 3]
k = 4

window_sum = sum(nums[:k])
max_avg = window_sum // k  # 错误！用了整数除法

for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_avg = max(max_avg, window_sum // k)

print(max_avg)  # 12（错误）
```

正确输出应该是 12.75（窗口 `[12, -5, -6, 50]` 的和为 51，51/4 = 12.75）。

**为什么会错**：`//` 是整数除法，直接截断了小数部分。`51 // 4 = 12`，而正确答案需要 `51 / 4 = 12.75`。

```python
# 正确写法
window_sum = sum(nums[:k])
max_avg = window_sum / k  # 用普通除法，保留小数

for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_avg = max(max_avg, window_sum / k)

print(f"{max_avg:.2f}")  # 12.75
```

**教训**：涉及平均值、比例、概率的题目，永远用 `/` 而不是 `//`。

## 翻车现场二：数组长度小于 k 时的边界处理

如果输入的数组长度比 k 还小怎么办？

```python
nums = [1, 2]
k = 5

window_sum = sum(nums[:k])  # 不会报错！返回 3
print(window_sum)
```

`nums[:5]` 在列表长度不足时**不会报错**，只会返回所有元素。这导致后续逻辑全部错误。

```python
# 正确的防御性写法
def max_sum_k(nums, k):
    if len(nums) < k:
        return None  # 或者抛异常，或者返回 0，根据需求决定
    window_sum = sum(nums[:k])
    max_sum = window_sum
    for i in range(k, len(nums)):
        window_sum = window_sum - nums[i - k] + nums[i]
        max_sum = max(max_sum, window_sum)
    return max_sum

print(max_sum_k([1, 2], 5))  # None
print(max_sum_k([1, 2, 3, 4, 5], 3))  # 12
```

**教训**：写函数时永远要考虑"输入不合法"的情况，尤其是在做除法或切片操作时。

## 输出所有窗口的平均值

有时不只是要最大值，还要**输出每个窗口的平均值**：

```python
温度 = [22, 25, 23, 28, 30, 27, 26]
k = 3

# 计算每个 3 天的平均温度
averages = []
window_sum = sum(温度[:k])
averages.append(window_sum / k)

for i in range(k, len(温度)):
    window_sum = window_sum - 温度[i - k] + 温度[i]
    averages.append(window_sum / k)

for i, avg in enumerate(averages):
    day_start = i + 1
    day_end = i + k
    print(f"第 {day_start}~{day_end} 天平均温度: {avg:.1f}°C")

# 第 1~3 天平均温度: 23.3°C
# 第 2~4 天平均温度: 25.3°C
# 第 3~5 天平均温度: 27.0°C
# 第 4~6 天平均温度: 28.3°C
# 第 5~7 天平均温度: 27.7°C
```

这就是**滑动平均值**（Moving Average），在金融、气象、信号处理里无处不在。

## 固定窗口的通用模板

把固定窗口抽象成模板，以后遇到同类题直接套：

```python
def fixed_window_template(nums, k):
    if len(nums) < k:
        return  # 处理边界
    
    # 1. 初始化：算第一个窗口的状态
    window_state = compute_state(nums[:k])
    
    # 2. 滑动
    for i in range(k, len(nums)):
        # 移除 nums[i - k]
        remove_from_state(nums[i - k])
        # 加入 nums[i]
        add_to_state(nums[i])
        # 更新答案
        update_answer(window_state)
    
    # 3. 返回结果
    return answer
```

`compute_state`、`remove_from_state`、`add_to_state`、`update_answer` 根据具体题目要求替换。

## 翻车现场三：变量命名导致逻辑混乱

看下面这段代码：

```python
nums = [5, 2, 8, 1, 9, 3]
k = 3
n = len(nums)

window_sum = sum(nums[:k])
max_sum = window_sum

for i in range(k, n):
    # 以下三行哪个对？
    window_sum = window_sum + nums[i] - nums[i - k]   # A
    window_sum = window_sum - nums[i - k] + nums[i]   # B
    window_sum = window_sum - nums[i] + nums[i - k]   # C（错误！）
    max_sum = max(max_sum, window_sum)

print(max_sum)
```

A 和 B 都对（加法交换律），C 是错的。写 C 的人**把加减方向搞反了**：应该是"减旧值、加新值"，他却写了"减新值、加旧值"。

**调试技巧**：在纸上画出窗口滑动过程，标出哪个元素离开、哪个元素进入，然后对照代码确认符号方向。

## 小结

- 固定窗口长度不变，核心是 `window_sum - nums[i-k] + nums[i]`
- 滑动窗口 O(n)，每次重新求和 O(nk)，差距巨大
- 平均值用 `/` 不用 `//`，否则小数被截断
- 数组长度 < k 时要做防御性检查
- 变量命名和加减方向要小心，建议统一写成"先减后加"

  def max_of_min_windows(nums, k):
