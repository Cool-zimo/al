# 读写文件的正确姿势

> 这一课解决"怎么安全地读和写文件"。你会搞懂 `with` 为什么必须写、`r/w/a/x` 四种模式的差别，以及 `read`/`readline`/`readlines` 和逐行迭代在大文件场景下的取舍。

## with 语句：打开文件的正确姿势

用 `open()` 打开文件后，**必须关闭**，否则会泄漏文件描述符，还可能丢数据（缓冲区没刷盘）。

```python
# 正确：with 会自动帮你关
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
# 这里 f 已经自动关闭，无论中间是否抛异常
```

`with` 语句的核心是**上下文管理器协议**：进入时调用 `__enter__`，退出时（哪怕抛异常）调用 `__exit__`，而 `__exit__` 里会执行 `f.close()`。

```python
# WRONG：忘了关，或者只靠代码走完才关
f = open("data.txt", "r", encoding="utf-8")
content = f.read()
# 如果上面抛异常，close() 永远不会执行 → 文件描述符泄漏
```

长期运行的服务里，忘记关文件会让进程很快耗尽文件描述符（`Too many open files`）。

## 四种打开模式：r / w / a / x

| 模式 | 含义 | 文件不存在时 | 文件存在时 |
|------|------|-------------|-----------|
| `r` | 只读（默认） | 抛 `FileNotFoundError` | 正常打开 |
| `w` | 写入（覆盖） | 创建新文件 | **清空原有内容** |
| `a` | 追加 | 创建新文件 | 写在末尾，保留原内容 |
| `x` | 独占创建 | 创建新文件 | **抛 `FileExistsError`** |

```python
# w 模式：写入前会先清空
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")

# a 模式：追加到末尾，原内容保留
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("第二行\n")
```

## 翻车现场：`w` 会清空已有文件

这是最惨烈的误操作之一——手滑把要读的文件用 `w` 打开，内容瞬间蒸发。

```python
# WRONG：本想读取，却写成了 "w"
f = open("重要数据.txt", "w", encoding="utf-8")
# 文件已经被清空成 0 字节！哪怕你还没 write，内容也没了
data = f.read()   # io.UnsupportedOperation: not readable
```

报错：

```
io.UnsupportedOperation: not readable
```

打开模式和你要做的操作必须一致：要读就用 `r`，要写就用 `w`。另外 `w` 模式在 `open` 那一瞬间就把文件清空了，所以**误用 `w` 是不可逆的数据丢失**。

正确做法：

```python
# 正确：只读用 r
with open("重要数据.txt", "r", encoding="utf-8") as f:
    data = f.read()
```

## 翻车现场：`x` 存在就报错，但它正是你想要的

```python
# WRONG：用 w 写配置，结果把用户已有配置覆盖了
with open("config.ini", "w", encoding="utf-8") as f:
    f.write("新配置...")

# 用户：？？？我原来的配置呢
```

如果你只想在文件不存在时才创建、存在时绝不覆盖，用 `x`：

```python
# 正确：只在文件不存在时创建
try:
    with open("config.ini", "x", encoding="utf-8") as f:
        f.write("初始配置\n")
    print("已创建")
except FileExistsError:
    print("配置文件已存在，跳过初始化")
```

`x` 是"独占创建"——POSIX 上的 `O_CREAT | O_EXCL`，是原子操作，多进程竞争时也不会互相覆盖。

## 读文件的三种方式

```python
# 1. read()：一次性读全部内容到字符串
with open("data.txt", "r", encoding="utf-8") as f:
    all_text = f.read()

# 2. readline()：一次读一行（含末尾换行符）
with open("data.txt", "r", encoding="utf-8") as f:
    first = f.readline()
    second = f.readline()

# 3. readlines()：读全部行，返回列表
with open("data.txt", "r", encoding="utf-8") as f:
    lines = f.readline()  # 忘记加 s，只读到第一行
```

`read()` 和 `readlines()` 会把整个文件加载进内存。一个 5GB 的日志文件，用 `read()` 直接撑爆内存。

## 大文件必须逐行迭代

文件对象本身就是可迭代的，逐行 yield，**内存占用恒定**：

```python
with open("huge.log", "r", encoding="utf-8") as f:
    for line in f:           # 每次只在内存里留一行
        if "ERROR" in line:
            print(line.rstrip())
```

对比一下三种读法的内存占用：

| 方法 | 内存占用 | 适用场景 |
|------|---------|---------|
| `f.read()` | O(文件大小) | 小文件、需要整体处理 |
| `f.readlines()` | O(文件大小) | 需要随机访问行号 |
| `for line in f` | O(1) 行 | 大文件、流式处理 |

## 实战：统计日志里的错误数

```python
def count_errors(log_text):
    """接收一个多行字符串（模拟文件内容），统计包含 ERROR 的行数"""
    count = 0
    for line in log_text.splitlines():   # 逐行，纯内存计算
        if "ERROR" in line:
            count += 1
    return count

text = """INFO  启动服务
ERROR 数据库连接失败
INFO  重试中
ERROR 磁盘已满
"""
print(count_errors(text))   # 2
```

真实场景里这里会换成 `for line in f`。关键是**养成逐行处理大文件的习惯**。

## 小结

- 打开文件一律用 `with`，别手写 `close()`
- `r` 只读、`w` 清空写、`a` 追加、`x` 独占创建
- **`w` 会立即清空文件**，误操作无法恢复
- `read()`/`readlines()` 一次性加载，大文件用 `for line in f`
- 文件对象本身可迭代，逐行内存占用恒定
