# 计时：perf_counter vs time.time

> 这一课解决"如何精确测量代码执行时间"。你会明白为什么不能用 `time.time()` 计时，以及 `perf_counter` 为什么是计时首选。

## 为什么不能用 time.time 计时

`time.time()` 返回当前 Unix 时间戳。看起来用它来测时间差很自然：

```python
import time

start = time.time()
# ... 做一些操作 ...
end = time.time()
print(f"耗时：{end - start:.4f} 秒")
```

**问题在于**：`time.time()` 返回的是**墙上时钟（wall clock）**时间。系统的墙上时钟会被人为调整——NTP 校时、手动改时间、夏令时切换，都可能让时钟**往前跳或往后退**。

```python
# 假设系统时间在你测速时被 NTP 向前校准了 2 秒
start = time.time()    # 1000.0
# ... 代码实际跑了 1 秒 ...
end = time.time()      # 1003.0 ← 被校准了！
print(end - start)     # 3.0 ← 错误！实际只有 1 秒
```

这种偶发性的"时间倒流"或"时间跳跃"会让你的计时结果完全不可信。

## perf_counter：专为计时设计

`time.perf_counter()` 返回一个**单调递增**的计数器，不受系统时间调整影响：

```python
import time

start = time.perf_counter()
# ... 一些操作 ...
end = time.perf_counter()
elapsed = end - start
print(f"耗时：{elapsed:.6f} 秒")
```

`perf_counter` 的特点是：

- **单调递增**：永远不会倒退，不会被系统校时影响
- **高精度**：通常达到纳秒级分辨率
- **起点任意**：差值有意义，绝对值无意义（不要拿它当前时间戳）

```python
import time

print(time.perf_counter())  # 1234567.890123 ← 数字本身没意义
print(time.perf_counter())  # 1234567.890456 ← 只关心差值
```

## 实战：测量代码性能

```python
import time

def benchmark():
    start = time.perf_counter()
    total = 0
    for i in range(1_000_000):
        total += i
    elapsed = time.perf_counter() - start
    return elapsed

t = benchmark()
print(f"循环 100 万次耗时：{t*1000:.2f} 毫秒")
```

输出（具体数值取决于机器）：

```
循环 100 万次耗时：35.42 毫秒
```

## 翻车现场：用 time.time 测 sleep

```python
import time

# WRONG：用 time.time 测 sleep 精度
start = time.time()
time.sleep(0.5)
end = time.time()
print(f"sleep 了 {end - start:.2f} 秒")
```

虽然这个例子在绝大多数情况下"看起来能用"，但它不是**保证**的。`time.time()` 的分辨率在 Windows 上可能只有 15.6 毫秒（约 1/64 秒），测 0.005 秒的操作会完全不准。而 `perf_counter` 在所有平台上都提供最高可用精度。

## time.monotonic：另一种选择

`time.monotonic()` 也是单调递增的，但它不保证高精度。如果你只是需要"测量经过了多久"（比如超时判断），用它也行：

```python
import time

start = time.monotonic()
time.sleep(1)
print(f"经过了 {time.monotonic() - start:.2f} 秒")  # 1.00
```

**结论**：测性能用 `perf_counter`，测超时用 `monotonic`，**不要用 `time.time()` 测时间差**。

## 实战例子：装饰器计时

```python
import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} 耗时 {elapsed*1000:.2f} ms")
        return result
    return wrapper

@timer
def slow_task():
    total = 0
    for i in range(10_000_000):
        total += i
    return total

slow_task()  # 输出：slow_task 耗时 XX.XX ms
```

## 三种 time 函数的对比

| 函数 | 用途 | 受影响 | 精度 |
|---|---|---|---|
| `time.time()` | 时间戳/日历时间 | 系统校时会变 | 中等 |
| `time.perf_counter()` | 性能测量 | 不受影响 | 最高 |
| `time.monotonic()` | 超时判断 | 不受影响 | 中等 |

## 小结

- `time.time()` 是墙上时钟，会被 NTP 校时、手动改时间影响 → **不能用来计时**
- `time.perf_counter()` 单调递增、高精度 → **测性能首选**
- `time.monotonic()` 单调递增 → 适合超时判断
- perf_counter 的绝对值无意义，只关心差值
- 写装饰器/工具函数时，一律用 perf_counter
