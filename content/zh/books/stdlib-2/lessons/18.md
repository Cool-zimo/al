# 临时文件与目录

> 这一课讲为什么不该自己 `open("/tmp/xxx", "w")`：并发冲突、权限泄露、忘了清理。你会学会 `tempfile` 模块的 `TemporaryFile`、`NamedTemporaryFile`、`mkdtemp`，以及那个最坑的 `delete` 陷阱。

## 为什么需要 tempfile

手动管理临时文件有三大问题：

1. **命名冲突**：`/tmp/cache.txt` 两个进程同时写就互相覆盖
2. **权限问题**：`os.open` 直接开可能暴露敏感数据给同机用户
3. **忘了清理**：进程崩溃或忘记 `unlink`，临时文件越积越多

`tempfile` 模块一次性解决这三个问题：名字唯一、权限收紧（`0o600`）、退出自动清理。

## TemporaryFile：匿名临时文件

```python
import tempfile

with tempfile.TemporaryFile(mode="w+t", encoding="utf-8") as f:
    f.write("中间计算结果\n")
    f.seek(0)                    # 写完后要 seek 回开头才能读
    print(f.read())

# 退出 with 块时自动删除，连名字都不需要
```

`TemporaryFile` 在大多数平台上是**匿名**的（没有目录项），关掉就彻底消失，连名字都查不到——最安全。

## NamedTemporaryFile：需要一个"真名字"

有些库只接受文件路径字符串，不接受文件对象（比如 `sqlite3` 要一个数据库文件路径、外部命令要一个文件名）。这时候需要 `NamedTemporaryFile`。

```python
import tempfile

with tempfile.NamedTemporaryFile(
    mode="w+t", suffix=".csv", delete=False
) as f:
    f.write("name,age\n张三,25\n")
    path = f.name                # 拿到真实路径字符串
    print(f"文件位于: {path}")

# 外部程序可以用 path 操作这个文件
# 用完记得手动 os.unlink(path)
```

`suffix`/`prefix`/`dir` 都能指定，生成的名字形如 `/tmp/tmp3k9x...csv`。

## mkdtemp：临时目录

需要临时目录放一堆文件时用 `mkdtemp`。**它不会自动清理**，你得自己负责删。

```python
import tempfile
import os
import shutil

tmpdir = tempfile.mkdtemp(prefix="myapp_")
try:
    # 在 tmpdir 里随意读写
    with open(os.path.join(tmpdir, "step1.txt"), "w") as f:
        f.write("中间结果")
    # ... 更多处理 ...
finally:
    shutil.rmtree(tmpdir)        # 自己负责清理
```

用 `try/finally` 保证清理一定执行，这是 `mkdtemp` 的标准套路。

## 翻车现场：NamedTemporaryFile 的 `delete` 陷阱

这是最经典的坑。默认 `delete=True`，也就是退出上下文管理器时文件**立即被删除**——但你可能想在 `with` 外面用这个名字。

```python
import tempfile

# WRONG：delete=True（默认），文件退出 with 就被删
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt") as f:
    f.write("数据")
    path = f.name

import os
os.path.exists(path)     # False！文件已经没了
```

更隐蔽的是在 `with` **里面**就想读：

```python
import tempfile

# WRONG：Windows 上同一文件不能同时又写又打开
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt") as f:
    f.write("hello")
    f.flush()
    # 想在另一个句柄里读这个文件
    with open(f.name, "r") as reader:   # Windows: PermissionError
        print(reader.read())
```

Windows 上文件默认不允许共享打开。跨平台正确的做法是 `delete=False` + 手动删：

```python
import tempfile
import os

with tempfile.NamedTemporaryFile(
    mode="w+t", suffix=".txt", delete=False
) as f:
    f.write("hello")
    path = f.name

try:
    with open(path, "r") as reader:
        print(reader.read())      # hello
finally:
    os.unlink(path)               # 手动清理
```

## 翻车现场：mkdtemp 不自动清理

```python
import tempfile
import os

# WRONG：用完就走，忘了删
def process_data():
    tmp = tempfile.mkdtemp()
    # 在 tmp 里写了一堆中间文件
    return do_work(tmp)

# 函数返回后 tmp 里的文件永远留在磁盘上
# 长期运行的程序会慢慢把 /tmp 塞满
```

正确做法永远是 `try/finally`：

```python
import shutil
import tempfile

def process_data():
    tmp = tempfile.mkdtemp()
    try:
        return do_work(tmp)
    finally:
        shutil.rmtree(tmp)        # 无论是否抛异常都清理
```

## 实战：安全的中间结果缓存

```python
import tempfile
import os
import hashlib

def write_temp_report(records):
    """把一批记录写成临时 CSV，返回路径（调用方负责删除）"""
    with tempfile.NamedTemporaryFile(
        mode="w+t", suffix=".csv", delete=False
    ) as f:
        f.write("id,value\n")
        for r in records:
            f.write(f"{r['id']},{r['value']}\n")
        return f.name

# 模拟使用（不真写磁盘）
records = [{"id": 1, "value": "北京"}, {"id": 2, "value": "上海"}]
path = write_temp_report(records)
print(f"临时报告: {path}")      # 返回类似 /tmp/tmp_xxx.csv
# 调用方用完 os.unlink(path)
```

生产环境里这个函数通常还会配合 `hashlib` 做内容校验，确保中间数据没被损坏。

## 小结

- `tempfile` 解决命名冲突、权限、清理三个问题
- `TemporaryFile` 匿名、最安全、退出即删
- `NamedTemporaryFile` 有真名字，给只接受路径字符串的接口用
- **`NamedTemporaryFile` 默认 `delete=True`**，跨平台复用名字必须 `delete=False` + 手动 `unlink`
- `mkdtemp` 生成临时目录，**不自动清理**，必须用 `try/finally` + `rmtree`
- 安全口诀：匿名用 `TemporaryFile`，要名字用 `NamedTemporaryFile(delete=False)`，要目录用 `mkdtemp` + `try/finally`
