# subprocess 基础

> 这一课讲怎么在 Python 里安全地调用外部命令。核心是 `subprocess.run()`：`capture_output` 拿输出、`check=True` 自动检查错误，以及那条铁律——**绝不要用 `shell=True` 拼用户输入**。

## run()：最基本的用法

```python
import subprocess

result = subprocess.run(["ls", "-la"], capture_output=True, text=True)
print(result.stdout)        # 命令的标准输出（字符串）
print(result.stderr)        # 标准错误
print(result.returncode)    # 退出码，0 表示成功
```

三个关键参数：
- `capture_output=True`：捕获 stdout/stderr（等价于 `stdout=PIPE, stderr=PIPE`）
- `text=True`（或 `encoding="utf-8"`）：输出是字符串而不是字节
- `check=True`：退出码非零时自动抛 `CalledProcessError`

## 参数用列表，别用字符串

```python
import subprocess

# 正确：命令和参数拆成列表
subprocess.run(["git", "log", "--oneline", "-n", "5"], capture_output=True, text=True)

# WRONG：字符串形式依赖 shell 解析，空格会出问题
subprocess.run("git log --oneline -n 5", capture_output=True, text=True)
# 不加 shell=True 时会被当成"执行一个名为 'git log ...' 的程序"，直接 FileNotFoundError
```

报错：

```
FileNotFoundError: [Errno 2] No such file or directory: 'git log --oneline -n 5'
```

Python 会以为整个字符串是程序名。所以**永远用列表形式传参**，除非你明确需要 shell 特性（管道、通配符展开）。

## check=True：让错误看得见

```python
import subprocess

# WRONG：忘了 check=True，命令失败也当成功处理
result = subprocess.run(["grep", "xyz", "不存在的文件"])
print("继续处理...")   # grep 找不到文件退出码是 2，但这里照样往下走
```

`grep` 找不到文件退出码是 2，程序却"若无其事"地继续了——典型的静默失败。

```python
import subprocess

# 正确：check=True，非零退出码立即抛异常
try:
    result = subprocess.run(
        ["grep", "xyz", "/etc/hosts"],
        capture_output=True, text=True, check=True,
    )
    print(result.stdout)
except subprocess.CalledProcessError as e:
    print(f"命令失败，退出码 {e.returncode}，stderr: {e.stderr}")
```

`check=True` 让子进程的错误变成 Python 异常，你能在一层统一处理，而不是满屏 `if result.returncode != 0`。

## 翻车现场：`shell=True` + 用户输入 = 命令注入

这是安全红线。当你把用户输入直接拼进 `shell=True` 的命令里，等于把 shell 的权限拱手让人。

```python
import subprocess

# WRONG：从网页/API/用户输入拿到的 filename
filename = input("要查看的文件名: ")
# 用户输入："; rm -rf /"
subprocess.run(f"cat {filename}", shell=True)
# 实际执行：cat ; rm -rf /
# 你的文件全没了
```

只要输入里出现 `;`、`&&`、`|`、反引号、换行，攻击者就能注入任意命令。这就是经典的**命令注入漏洞**。

**永远别这么做**。正确做法是：

```python
import subprocess

filename = input("要查看的文件名: ")

# 正确：用列表 + 绝不 shell=True
subprocess.run(["cat", filename])

# 即便 filename 是 "; rm -rf /"，cat 也只会报"找不到文件"，不会执行删除
```

列表形式的参数**不会经过 shell 解析**，特殊字符全部按字面量处理——安全。

## 翻车现场：`shell=True` 不是性能优化

```python
import subprocess

# WRONG：以为 shell=True 更快
for i in range(10000):
    subprocess.run(f"echo {i}", shell=True)
# 每次都 fork 一个 /bin/sh 进程，极慢且浪费
```

`shell=True` 意味着额外启动一个 shell 进程来解析命令。循环里调用一万次，就启动了一万个 shell，既慢又浪费。

```python
import subprocess

# 正确：列表形式直接 exec，无 shell 开销
for i in range(10000):
    subprocess.run(["echo", str(i)])
```

只有当你**确实需要** shell 特性（管道 `|`、重定向 `>`、通配符 `*`、环境变量展开 `$VAR`）时才用 `shell=True`，且**参数必须是硬编码的、不含任何外部输入**：

```python
# 唯一合理的 shell=True 用法：需要管道
subprocess.run("ps aux | grep python | wc -l", shell=True, capture_output=True, text=True)
```

## 实战：安全执行外部命令的封装

```python
import subprocess

def run_git(args):
    """安全执行 git 子命令，返回 (成功与否, 输出或错误信息)"""
    try:
        result = subprocess.run(
            ["git"] + args,
            capture_output=True, text=True, check=True, timeout=30,
        )
        return True, result.stdout.strip()
    except subprocess.CalledProcessError as e:
        return False, e.stderr.strip()
    except subprocess.TimeoutExpired:
        return False, "命令执行超时"

ok, output = run_git(["status", "--short"])
print(ok, output)

ok, output = run_git(["log", "-1", "--format=%H"])
print(ok, output)
```

列表拼接 + `check=True` + `timeout`，三条都齐全，才是生产级的调用方式。

## 小结

- `subprocess.run(args, capture_output=True, text=True)` 是最常用形态
- 参数永远是**列表**，不用字符串（除非 shell=True 且内容硬编码）
- `check=True`：非零退出码自动抛 `CalledProcessError`
- `timeout=` 防止命令卡死
- **`shell=True` + 用户输入 = 命令注入**，绝不允许
- `shell=True` 有额外 shell 进程开销，循环里尤其要避免
