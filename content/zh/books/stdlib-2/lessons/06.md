# 时区：naive vs aware

> 这一课解决"为什么不能混用带时区和不带时区的时间，以及怎么正确地用 zoneinfo 处理时区"。你会掌握"存 UTC，显示本地"的黄金原则。

## naive 和 aware：一眼分清

| 类型 | 含义 | `tzinfo` |
|---|---|---|
| **naive**（天真的） | 不知道自己属于哪个时区 | `None` |
| **aware**（有意识的） | 明确绑定了时区 | 非 `None` |

```python
from datetime import datetime, timezone, timedelta

naive = datetime(2026, 9, 27, 14, 30)
print(naive.tzinfo)   # None → naive

tz_utc8 = timezone(timedelta(hours=8))
aware = datetime(2026, 9, 27, 14, 30, tzinfo=tz_utc8)
print(aware.tzinfo)   # UTC+08:00 → aware
```

**naive 对象只是一个数字**——它说"14:30"，但没说这是北京时间还是纽约时间。只有你（程序员）心里知道。这就是 bug 的温床。

## 翻车现场：naive 和 aware 不能比较

```python
from datetime import datetime, timezone, timedelta

tz_utc8 = timezone(timedelta(hours=8))
aware = datetime(2026, 9, 27, 14, 30, tzinfo=tz_utc8)
naive = datetime(2026, 9, 27, 14, 30)

# WRONG：混用 naive 和 aware
print(aware > naive)
```

报错：

```
TypeError: can't compare offset-naive and offset-aware datetimes
```

Python 拒绝比较，因为它无法判断这两个时间是不是同一个时刻。14:30 北京时间比 14:30 UTC 早 8 小时——它们根本不是同一时刻。

## zoneinfo：用真实时区数据库（Python 3.9+）

`timezone(timedelta(hours=8))` 只能表示固定偏移的时区。但现实中很多时区有**夏令时**——夏天偏移 +9，冬天偏移 +8。用固定偏移会算错。

Python 3.9+ 提供 `zoneinfo`，它使用系统的时区数据库（IANA tz database），能正确处理夏令时。

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 创建带时区的 datetime
dt_bj = datetime(2026, 9, 27, 14, 30, tzinfo=ZoneInfo("Asia/Shanghai"))
dt_ny = datetime(2026, 9, 27, 14, 30, tzinfo=ZoneInfo("America/New_York"))

print(dt_bj)   # 2026-09-27 14:30:00+08:00
print(dt_ny)   # 2026-09-27 14:30:00-04:00（夏令时）

# 现在可以比较了！
print(dt_bj > dt_ny)   # True
```

## 时区转换：astimezone

同一个时刻，在不同时区显示不同时间——这就是 `astimezone` 的作用。

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 北京时间 2026-09-27 14:30
dt_bj = datetime(2026, 9, 27, 14, 30, tzinfo=ZoneInfo("Asia/Shanghai"))

# 转成纽约时间
dt_ny = dt_bj.astimezone(ZoneInfo("America/New_York"))
print(dt_ny.strftime("%Y-%m-%d %H:%M:%S %Z"))  # 2026-09-27 02:30:00 EDT

# 转成 UTC
dt_utc = dt_bj.astimezone(ZoneInfo("UTC"))
print(dt_utc.strftime("%Y-%m-%d %H:%M:%S"))   # 2026-09-27 06:30:00
```

**关键理解**：`astimezone` 不改**时刻**，只改**显示方式**。就像同一场比赛，北京观众说凌晨 3 点看，纽约观众说下午 3 点看——指的是同一时刻。

## 黄金原则：存 UTC，显示本地

这是业界共识的最佳实践：

1. **存储**：所有时间以 UTC 存入数据库
2. **计算**：全部在 UTC 下做
3. **展示**：输出时按用户所在时区转换

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 1. 拿到当前 UTC 时间（aware）
now_utc = datetime.now(ZoneInfo("UTC"))
print(now_utc)   # 2026-09-27 06:30:00+00:00

# 2. 存数据库（存 UTC timestamp 或 UTC datetime）
ts = now_utc.timestamp()

# 3. 展示给用户时转成北京时间
user_tz = ZoneInfo("Asia/Shanghai")
display = now_utc.astimezone(user_tz)
print(display.strftime("%Y-%m-%d %H:%M:%S"))  # 2026-09-27 14:30:00
```

## replace 给 naive 补时区

如果你有一个 naive datetime，知道它其实是北京时间，可以"贴"上时区：

```python
from datetime import datetime
from zoneinfo import ZoneInfo

naive = datetime(2026, 9, 27, 14, 30)
aware = naive.replace(tzinfo=ZoneInfo("Asia/Shanghai"))
print(aware)   # 2026-09-27 14:30:00+08:00
```

**注意**：这里用 `replace` 是"声明它原本就是这个时区"，不是"转换时区"。如果你要把一个 naive 时间从 A 时区转成 B 时区，要先用 `replace` 贴上 A，再 `astimezone(B)`。

## 小结

- **naive** = 无时区信息（tzinfo 为 None）；**aware** = 有时区信息
- naive 和 aware **不能比较**，会抛 TypeError
- `zoneinfo.ZoneInfo("Asia/Shanghai")` 使用真实时区数据库，支持夏令时
- `astimezone()` 转换显示时区，不改变实际时刻
- 黄金原则：**存 UTC，算 UTC，显示本地**
- `replace(tzinfo=...)` 给 naive 对象"贴"上时区标签
