# os.path vs pathlib

> 这一课解决"Python 里怎么表示文件路径"。你会明白为什么 pathlib 比字符串拼接好，以及那些让老手写 os.path 也翻车的坑。

## 老方法：os.path 拼路径的坑

在 pathlib 出现之前，大家都用 `os.path` 处理路径。最常见的问题——**手动拼路径**：

```python
import os

base = "/home/zhangsan/docs"
filename = "report.txt"

# 手动拼
path = base + "/" + filename
print(path)   # /home/zhangsan/docs/report.txt
```

看起来没问题。但如果 `base` 末尾多了一个斜杠呢？

```python
# WRONG：base 末尾已经有 / 了
base = "/home/zhangsan/docs/"
path = base + "/" + filename
print(path)   # /home/zhangsan/docs//report.txt ← 双斜杠！
```

又或者有人在 Windows 上跑这段代码——Windows 用 `\` 分隔路径，`/` 就错了。还有 `..`、`.`、`~` 这些特殊符号的处理，全都得手动来。

## pathlib：面向对象的路径

Python 3.4+ 引入了 `pathlib`，把路径变成了一个**对象**，所有操作都变成方法调用：

```python
from pathlib import Path

p = Path("/home/zhangsan/docs") / "report.txt"
print(p)   # /home/zhangsan/docs/report.txt
```

`/` 运算符就是**路径拼接**——不管末尾有没有斜杠，不管是什么操作系统，都能正确处理。

## 翻车现场：字符串拼接的跨平台噩梦

```python
# WRONG：硬编码路径分隔符
log_path = "C:\\Users\\" + username + "\\logs\\app.log"

# 在 Linux 上完全不能用
# 而且 Windows 上要用 \\，容易写错
```

用 pathlib，同样的代码在所有平台都能跑：

```python
from pathlib import Path

home = Path.home()                    # 自动获取当前用户主目录
log_path = home / "logs" / "app.log"
print(log_path)
# Linux: /home/zhangsan/logs/app.log
# Windows: C:\Users\zhangsan\logs\app.log
```

`Path.home()` 自动识别操作系统并返回正确的主目录，不需要你写死路径。

## 翻车现场：os.path 链式调用的可读性灾难

```python
import os

# 获取某个文件的父目录
path = "/home/zhangsan/docs/report.txt"
parent = os.path.dirname(path)        # /home/zhangsan/docs
grandparent = os.path.dirname(parent) # /home/zhangsan

# 想再往上两层？继续套
great = os.path.dirname(os.path.dirname(path))  # /home/zhangsan

# 获取扩展名
ext = os.path.splitext(path)[1]       # .txt
name = os.path.basename(path)          # report.txt
stem = os.path.splitext(name)[0]       # report
```

嵌套调用越来越深，读起来像绕口令。

**pathlib 版本**：

```python
from pathlib import Path

p = Path("/home/zhangsan/docs/report.txt")
print(p.parent)       # /home/zhangsan/docs
print(p.parent.parent)  # /home/zhangsan
print(p.suffix)       # .txt
print(p.name)         # report.txt
print(p.stem)         # report
```

链式属性，一目了然。

## pathlib vs os.path 功能对照

| 操作 | os.path | pathlib |
|---|---|---|
| 拼接 | `os.path.join(a, b)` | `a / b` |
| 文件名 | `os.path.basename(p)` | `p.name` |
| 扩展名 | `os.path.splitext(p)[1]` | `p.suffix` |
| 父目录 | `os.path.dirname(p)` | `p.parent` |
| 是否存在 | `os.path.exists(p)` | `p.exists()` |
| 是否文件 | `os.path.isfile(p)` | `p.is_file()` |
| 主目录 | `os.path.expanduser("~")` | `Path.home()` |
| 当前目录 | `os.getcwd()` | `Path.cwd()` |

## 纯路径操作：PurePath

如果你**只需要处理路径字符串**（比如在计算题里操作路径，不碰真实文件系统），用 `PurePath`：它只做字符串运算，不检查文件是否存在。

```python
from pathlib import PurePath

p = PurePath("/home/zhangsan/docs/report.txt")
print(p.name)      # report.txt
print(p.suffix)    # .txt
print(p.parent)    # /home/zhangsan/docs
print(p.stem)      # report
```

PurePath 的好处：**不需要文件系统**，可以在任何环境（包括浏览器里的 Pyodide）运行。这也是为什么我们的练习题都用 PurePath。

## 小结

- **手动拼路径有坑**：分隔符不统一、`..` 不处理、跨平台不兼容
- pathlib 用 `/` 运算符拼路径，自动处理分隔符和 `.`/`..`
- pathlib 的 API 是面向对象的：`p.name`、`p.suffix`、`p.parent` 比 os.path 的嵌套调用清晰
- **纯路径运算用 PurePath**，不需要真实文件系统
- Python 3.4+ 标准库自带，无需安装
