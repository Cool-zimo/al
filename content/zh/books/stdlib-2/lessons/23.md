# 压缩还是不压缩

> 这一课讲一个反直觉的事实：很多常见文件压缩了等于白压。你会知道哪些文件已经"压缩过"、哪些还有空间，以及现实里压缩率到底该期待多少。

## 已经压缩过的文件：压了也白压

以下格式**内部已经用了压缩算法**，再套一层 gzip/xz 几乎没收益，甚至略微变大（压缩头本身占空间）：

- 图片：`jpg`/`jpeg`、`png`、`gif`、`webp`、`avif`
- 视频：`mp4`/`mkv`/`avi`/`mov`/`flv`
- 音频：`mp3`/`aac`/`ogg`/`flac`
- 压缩包本身：`zip`、`7z`、`rar`、已有的 `.tar.gz`
- 已压缩文档：`docx`/`xlsx`/`pptx`（本质是 zip）

```python
import zlib

data = b"\xff\xd8\xff" * 10_000     # 模拟 jpg 式的已压缩数据
compressed = zlib.compress(data, 9)
print(f"原始: {len(data)} 字节")
print(f"压缩后: {len(compressed)} 字节")
print(f"压缩率: {len(compressed)/len(data):.2%}")
# 压缩率 99%+，基本没压
```

已压缩数据的信息熵接近最大，没有冗余可去，压缩算法无能为力。

## 还有压缩空间的：纯文本

文本文件有大量重复字符和模式，压缩效果显著：

- 源代码（`.py`、`.js`、`.c`、`.java`）
- 日志（`.log`）
- CSV / JSON / XML / YAML
- 文档源码（`.md`、`.tex`）
- 纯文本数据库导出

```python
import zlib

text = ("def hello():\n    print('你好，世界')\n" * 5_000).encode("utf-8")
compressed = zlib.compress(text, 9)
print(f"原始: {len(text)} 字节")
print(f"压缩后: {len(compressed)} 字节")
print(f"压缩率: {len(compressed)/len(text):.2%}")
# 压缩率 5% 左右，压缩效果很好
```

同样的文本、同样的算法，和 jpg 的 99% 形成鲜明对比。

## 现实预期：别指望"压一半"

真实场景的压缩率因内容而异：

| 内容类型 | 典型压缩率 |
|---------|-----------|
| 纯文本 / 源码 | 10%~30% |
| JSON / CSV 大量重复 | 5%~20% |
| 混合文件（项目目录） | 30%~60% |
| 已压缩媒体（jpg/mp4/zip） | 95%~105% |

**压缩率 = 压缩后大小 / 原始大小**。0.3 表示压到三成，0.95 表示几乎没压。

```python
import zipfile
import os

def estimate_ratio(original_size, compressed_size):
    """返回压缩率百分比字符串"""
    if original_size == 0:
        return "N/A"
    ratio = compressed_size / original_size
    saved = (1 - ratio) * 100
    return f"压缩率 {ratio:.1%}，节省 {saved:.1f}% 空间"
```

## 翻车现场：把 100 个 jpg 打包成 tar.gz 体积没变

```python
import tarfile
import io
import os

# 100 张 jpg，每张 2MB
jpg_files = {f"photo_{i}.jpg": os.urandom(2_000_000) for i in range(100)}

buf = io.BytesIO()
with tarfile.open(fileobj=buf, mode="w:gz") as tf:
    for name, content in jpg_files.items():
        info = tarfile.TarInfo(name=name)
        info.size = len(content)
        tf.addfile(info, io.BytesIO(content))

raw = sum(len(v) for v in jpg_files.values())
compressed = buf.tell()
print(f"原始: {raw/1e6:.1f} MB")
print(f"压缩后: {compressed/1e6:.1f} MB")
print(f"节省: {(1-compressed/raw)*100:.1f}%")
# 几乎 0%，白忙一场
```

你花了 CPU 时间和等待时间，换来几乎为零的节省。这种场景下**直接 tar 不压缩**（`.tar`）或干脆打包成 zip 但不压缩（`ZIP_STORED`）就够了，还能省下压缩时间。

## 实战：智能备份——决定哪些文件值得压缩

```python
# 已经压缩过的扩展名，打包时跳过压缩
ALREADY_COMPRESSED = {
    ".jpg", ".jpeg", ".png", ".gif", ".webp",
    ".mp4", ".mkv", ".avi", ".mov",
    ".mp3", ".aac", ".flac",
    ".zip", ".7z", ".rar", ".gz", ".bz2", ".xz",
    ".docx", ".xlsx", ".pptx",
}

# 强烈建议压缩的文本类
TEXT_LIKE = {
    ".py", ".js", ".ts", ".java", ".c", ".cpp", ".go", ".rs",
    ".txt", ".csv", ".json", ".xml", ".yaml", ".yml", ".md", ".log",
}

def classify_for_backup(filename):
    """判断一个文件在备份时该用压缩还是仅打包"""
    ext = "." + filename.rsplit(".", 1)[-1].lower() if "." in filename else ""
    if ext in ALREADY_COMPRESSED:
        return "store"
    if ext in TEXT_LIKE:
        return "compress"
    return "try"   # 其他格式尝试压缩

print(classify_for_backup("report.docx"))   # store
print(classify_for_backup("main.py"))       # compress
print(classify_for_backup("data.bin"))      # try
```

真实备份工具（像 `restic`、`borg`）内部就是按块做内容去重和压缩，对媒体文件基本不压缩，对文本块则重拳出击。

## 翻车现场：把压缩率算成"节省了百分之几"

压缩率有两种说法，混用会让人误判"省了多少"。

```python
original = 1000
compressed = 250

ratio_v1 = compressed / original      # 0.25  → "压到 25%"
ratio_v2 = 1 - compressed / original  # 0.75  → "节省了 75%"

# WRONG：把 0.25 说成"只节省了 25%"
print(f"节省 {ratio_v1*100}%")        # 节省 25%  ← 错，实际省了 75%
```

这两个数字的口径完全相反，汇报时张嘴就来最容易出丑。标准库的 `tarfile` 和 `zipfile` 的 `compress_size / file_size` 给出的是**前者**（`compressed / original` = 压到几成），而你口头说的"省了百分之多少"是**后者**。

```python
original = 1000
compressed = 250

to_ratio = compressed / original          # 0.25  压到 25%
saved_pct = (1 - compressed / original) * 100   # 75.0%  节省 75%

print(f"压缩率 {to_ratio:.0%}，节省 {saved_pct:.0f}%")
# 压缩率 25%，节省 75%
```

统一口径写个函数，别随手算：

```python
def compression_report(original, compressed):
    if original == 0:
        return "无法计算（原始大小为 0）"
    ratio = compressed / original
    saved = (1 - ratio) * 100
    return f"压缩率 {ratio:.1%}，节省 {saved:.1f}%"
```

记牢：**小于 1 的数是"压到几成"，减去它才是"省了多少"。**

## 小结

- jpg/png/mp4/mp3/zip/docx 等**已经压缩过**，再压基本白压
- 纯文本、源码、JSON/CSV、日志还有 70%~95% 的压缩空间
- 压缩率 = 压缩后/原始，现实里文本能压到 10%~30%，媒体 95%+ 即"没压"
- 大批量媒体文件备份用 `tar`（不压缩）即可，省 CPU 也省时间
- 智能备份按扩展名分流：媒体 store、文本 compress、其他 try
