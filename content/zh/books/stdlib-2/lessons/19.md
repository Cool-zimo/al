# os 模块与系统信息

> 这一课讲怎么在 Python 里读取环境变量、判断当前操作系统、执行系统命令。你会学会 `os.environ` 的正确用法，以及为什么 `os.system` 已经被 `subprocess` 取代。

## os.environ：读取环境变量

`os.environ` 是一个类似字典的对象，装着进程启动时继承的所有环境变量。

```python
import os

# 读取
home = os.environ["HOME"]            # 不存在会抛 KeyError
home = os.environ.get("HOME", "/tmp")  # 不存在返回默认值

# 写入（仅影响当前进程及其子进程，不改系统配置）
os.environ["MY_APP_DEBUG"] = "1"

# 检查是否存在
if "JAVA_HOME" in os.environ:
    print("Java 已配置:", os.environ["JAVA_HOME"])

# 删除
os.environ.pop("MY_APP_DEBUG", None)
```

注意：`os.environ` 的改动**只在当前 Python 进程内生效**，程序退出后恢复原状。想永久改系统环境变量得去系统设置里改。

## os.environ 不是普通字典

```python
import os

# WRONG：直接赋 None 会崩
os.environ["KEY"] = None
```

报错：

```
TypeError: str expected, not NoneType
```

`os.environ` 的值**必须是字符串**。另外，子进程继承的是修改后的环境，但父进程（你的 shell）不受影响。

```python
import os
import subprocess

os.environ["GREETING"] = "你好"
# 子进程能读到
subprocess.run(["python3", "-c", "import os; print(os.environ['GREETING'])"])
# 输出：你好
```

## 判断操作系统：os.name 与 sys.platform

```python
import os
import sys

print(os.name)        # 'posix'（Linux/macOS/Unix）或 'nt'（Windows）
print(sys.platform)   # 'linux', 'darwin', 'win32' 等，粒度更细

if os.name == "nt":
    print("Windows 路径用反斜杠")
    config = os.path.expanduser("~\\AppData\\Local")
else:
    print("类 Unix 系统")
    config = os.path.expanduser("~/.config")
```

| 判断目标 | 推荐方式 | 取值示例 |
|---------|---------|---------|
| 是否 Windows | `os.name == "nt"` | `"nt"` / `"posix"` |
| 精确系统名 | `sys.platform` | `"linux"` / `"darwin"` / `"win32"` |
| 是否在 WSL 里 | `sys.platform == "linux"` + 读 `/proc/version` | — |

## 翻车现场：环境变量没设置时 KeyError

```python
import os

# WRONG：假设环境变量一定存在
db_url = os.environ["DATABASE_URL"]
# 如果没配置，直接崩
```

报错：

```
KeyError: 'DATABASE_URL'
```

生产代码一律用 `get` 带默认值，或者用专门的配置库（`python-decouple`、`pydantic-settings`）。至少要这样：

```python
import os

db_url = os.environ.get("DATABASE_URL")
if db_url is None:
    raise RuntimeError(
        "环境变量 DATABASE_URL 未设置，请在 .env 或系统环境里配置"
    )
```

报错信息要告诉用户**该设置什么、去哪设置**，而不是抛一个看不懂的 `KeyError`。

## 翻车现场：os.system 的种种问题

```python
import os

# WRONG：用字符串拼接命令，无法捕获输出
ret = os.system("ls -la")
print(ret)   # 返回退出码，不是命令输出
```

`os.system` 的三大缺陷：
1. **拿不到输出**：直接打到终端，你无法用变量接收
2. **依赖 shell 解析**：空格、引号、特殊字符都会出错
3. **没有超时控制**：命令卡死你只能干等

正确做法是 `subprocess.run`（下一课详讲）：

```python
import subprocess

result = subprocess.run(
    ["ls", "-la"], capture_output=True, text=True
)
print(result.stdout)          # 标准输出内容
print(result.returncode)      # 退出码
```

## 实战：跨平台路径配置

```python
import os
from pathlib import Path

def get_app_dir(app_name):
    """根据操作系统返回应用数据目录"""
    if os.name == "nt":
        base = os.environ.get("APPDATA", str(Path.home()))
    else:
        base = os.environ.get("XDG_CONFIG_HOME", str(Path.home() / ".config"))
    app_dir = Path(base) / app_name
    app_dir.mkdir(parents=True, exist_ok=True)
    return app_dir

# 模拟调用（不真建目录）
print(get_app_dir("myapp"))   # 返回 Path 对象
```

Linux/macOS 遵循 XDG 规范（`~/.config`），Windows 用 `%APPDATA%`，这是跨平台应用的标配逻辑。

## 小结

- `os.environ` 是类字典对象，值必须是字符串
- 读取环境变量用 `os.environ.get(key, default)`，别直接下标
- `os.name` 粗粒度（`nt`/`posix`），`sys.platform` 细粒度（`linux`/`darwin`/`win32`）
- `os.environ` 的修改只影响当前进程和子进程，不写系统配置
- `os.system` 拿不到输出、依赖 shell、无超时——已过时，用 `subprocess`
- 跨平台配置：Windows 读 `%APPDATA%`，类 Unix 读 `$XDG_CONFIG_HOME`
