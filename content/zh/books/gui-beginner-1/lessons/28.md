# 逻辑与界面分离：别把所有代码塞进按钮回调

> 界面搭好了，现在写统计逻辑。这一课的核心思想是：界面代码和业务逻辑代码要分开。如果你把所有东西都塞进按钮的回调函数里，100 行代码之后你就会迷失自己。

## 什么叫做"混在一起"

**先看一个反面教材——把一切塞进回调函数：**

```
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.title("文本统计工具")

input_frame = ttk.LabelFrame(root, text="输入区")
input_frame.grid(row=0, column=0, padx=10, pady=5, sticky="ew")

text_input = tk.Text(input_frame, height=10, wrap="word")
text_input.grid(row=0, column=0, sticky="ew", padx=5, pady=5)

result_label = ttk.Label(root, text="结果将显示在这里")
result_label.grid(row=1, column=0)

def on_count():
    text = text_input.get("1.0", "end-1c")
    # 统计字符数
    char_count = len(text)
    # 统计行数
    lines = text.split("\n")
    line_count = len(lines) if text.strip() else 0
    # 统计词频
    from collections import Counter
    chars = [c for c in text if c.strip()]
    freq = Counter(chars)
    top5 = freq.most_common(5)
    # 格式化输出
    result = f"字符数：{char_count}\n行数：{line_count}\n"
    result += "词频 Top 5：\n"
    for char, count in top5:
        result += f"  {char}: {count} 次\n"
    result_label.configure(text=result)

btn = ttk.Button(root, text="开始统计", command=on_count)
btn.grid(row=2, column=0)

root.columnconfigure(0, weight=1)
root.mainloop()
```

**这段代码能跑，功能也全。但它是"定时炸弹"。** 为什么？

## 混在一起的四个问题

**问题一：无法复用。** `on_count` 里的统计逻辑和 Text 控件绑死了。如果明天你想加一个"命令行版本"或者"从文件读取统计"，这些统计代码你还得重写一遍。

**问题二：无法测试。** 统计逻辑藏在回调函数里，你没法单独验证"词频算法对不对"。只能运行整个 GUI 程序，手动粘贴文本，肉眼看结果。

**问题三：无法维护。** 假设产品经理说"词频要按词算而不是按字算"。你得在 `on_count` 这个大函数里翻来翻去，找到那几行，改了还怕影响其他逻辑。

**问题四：容易变巨型函数。** 一开始只有 20 行，后来加了异常处理、加了文件读取、加了设置选项……不知不觉变成 200 行。你改第 150 行的时候，已经忘了第 30 行写了什么。

## 正确做法：把逻辑抽出来

**核心原则：业务逻辑不依赖 tkinter。**

**我们先写纯逻辑函数——它们只接收字符串、返回结果，完全不知道 tkinter 的存在：**

```
# ===== 业务逻辑层（纯函数，不依赖 tkinter）=====

def count_chars(text: str) -> int:
    """统计字符数（含空格和标点）"""
    return len(text)

def count_lines(text: str) -> int:
    """统计行数"""
    if not text.strip():
        return 0
    return len(text.split("\n"))

def count_word_freq(text: str, top_n: int = 5) -> list:
    """统计词频，返回前 top_n 个（按字统计）"""
    from collections import Counter
    chars = [c for c in text if c.strip()]
    if not chars:
        return []
    return Counter(chars).most_common(top_n)

def format_result(chars: int, lines: int, freq: list) -> str:
    """把统计结果格式化成字符串"""
    lines_out = [
        f"总字符数：{chars}",
        f"总行数：{lines}",
        f"词频 Top {len(freq)}：",
    ]
    for char, count in freq:
        lines_out.append(f"  「{char}」：{count} 次")
    return "\n".join(lines_out)
```

**这 4 个函数有几个特点：**

1. **纯函数**：输入确定，输出就确定。不读全局变量，不修改外部状态。
2. **无 tkinter 依赖**：里面没有任何 `tk.` 或 `ttk.`。
3. **职责单一**：一个函数只干一件事。
4. **可独立测试**：你可以直接 `print(count_chars("hello"))` 验证它。

**这就是"逻辑与界面分离"。** 逻辑层是程序的大脑，界面层只是大脑的一个显示器。

## 界面层只做三件事

**界面层的回调函数只做：取数据 → 调逻辑 → 更新显示。**

```
# ===== 界面层 =====

def on_count():
    # 1. 取数据：从 Text 控件读取
    text = text_input.get("1.0", "end-1c")

    # 2. 调逻辑：纯函数计算
    chars = count_chars(text)
    lines = count_lines(text)
    freq = count_word_freq(text, top_n=5)
    result = format_result(chars, lines, freq)

    # 3. 更新显示
    result_text.configure(state="normal")
    result_text.delete("1.0", "end")
    result_text.insert("1.0", result)
    result_text.configure(state="disabled")
```

**`on_count` 现在只有 11 行，而且每一行都一目了然。** 业务逻辑的变化不会影响到它，界面的变化也不会影响到纯函数。

## Text 控件的取值和赋值

**Text 控件和 Entry 不一样，取值要用 `get("1.0", "end")`：**

```
# 读取 Text 全部内容
content = text_widget.get("1.0", "end")

# 去掉末尾多余的换行
content = text_widget.get("1.0", "end-1c")
```

**`"1.0"` 是什么？** Text 控件的索引格式是 `"行.列"`，行从 1 开始，列从 0 开始。`"1.0"` 就是第 1 行第 0 列，即最开头。

**`"end"` 是末尾，`"end-1c"` 是末尾往前一个字符。** 为什么减 1 个字符？因为 Text 控件在用户输入时，末尾会自动加一个换行符，如果不减掉，读取出来的文本会多一个空行。

**写入 Text 控件：**

```
text_widget.configure(state="normal")   # 先解锁
text_widget.delete("1.0", "end")        # 清空
text_widget.insert("1.0", content)      # 插入新内容
text_widget.configure(state="disabled")  # 再锁定
```

**记住这个顺序：解锁 → 清空 → 写入 → 锁定。** 只读的 Text 必须先 `configure(state="normal")` 才能改内容。

## 翻车现场一：忘记解锁 Text，写入无效

```
result_text = tk.Text(root, state="disabled")

def on_count():
    text = text_input.get("1.0", "end-1c")
    result = f"字符数：{len(text)}"
    result_text.delete("1.0", "end")      # ← 报错！
    result_text.insert("1.0", result)
```

**报错：**

```
_tkinter.TclError: text widget is disabled
```

**原因**：Text 被设为 `state="disabled"` 后，任何修改操作（delete、insert、键入）都会被拒绝。

**修复**：先解锁，写完再锁回去：

```
def on_count():
    text = text_input.get("1.0", "end-1c")
    result = f"字符数：{len(text)}"
    result_text.configure(state="normal")
    result_text.delete("1.0", "end")
    result_text.insert("1.0", result)
    result_text.configure(state="disabled")
```

## 翻车现场二：Text.get 用 "end" 不去掉换行，统计结果总是多一个空行

**症状**：粘贴一段 3 行文本，统计出来是 4 行。每次都多 1。

**原因**：用了 `text_input.get("1.0", "end")`，末尾的换行符被算进去了。`split("\n")` 会多切出一段空字符串。

**修复**：用 `"end-1c"` 去掉末尾换行：

```
text = text_input.get("1.0", "end-1c")
```

**但更好的做法是让 `count_lines` 自己处理：**

```
def count_lines(text: str) -> int:
    if not text.strip():
        return 0
    return len(text.split("\n"))
```

**`strip()` 去掉首尾空白后再判断**，这样即使有多余的换行也能正确处理。

## 翻车现场三：回调函数里写死 tkinter 变量名

**反面写法：**

```
def on_count():
    global text_input, result_text   # ← 全局变量，坏味道
    text = text_input.get("1.0", "end-1c")
    ...
```

**问题**：`global` 让函数依赖外部变量，难以测试和复用。

**更好做法：用闭包（嵌套函数）捕获变量：**

```
def create_app():
    root = tk.Tk()
    text_input = tk.Text(root)
    result_text = tk.Text(root)

    def on_count():
        text = text_input.get("1.0", "end-1c")
        chars = count_chars(text)
        lines = count_lines(text)
        freq = count_word_freq(text)
        result = format_result(chars, lines, freq)
        result_text.configure(state="normal")
        result_text.delete("1.0", "end")
        result_text.insert("1.0", result)
        result_text.configure(state="disabled")

    btn = ttk.Button(root, text="开始统计", command=on_count)
    btn.pack()

    return root

app = create_app()
app.mainloop()
```

**闭包的好处**：`text_input` 和 `result_text` 被 `on_count` 自然捕获，不需要 `global`，也不需要把它们变成全局变量。整个应用被包在 `create_app()` 里，干净利落。

**这是 tkinter 项目推荐的代码组织方式。** 你会在很多开源项目里看到类似的 `create_app()` / `build_ui()` 函数。

## 翻车现场四：在回调里做耗时操作，界面卡死

**症状**：点按钮后界面直接"未响应"，鼠标变转圈，整个窗口冻住几秒甚至几十秒。

**原因**：回调函数在主线程（GUI 线程）里执行。如果里面有个大循环或文件读取，GUI 线程被占满了，没法刷新界面、响应点击，看起来就是"卡死"。

**错误示例：**

```
def on_count():
    # 模拟耗时操作
    total = 0
    for i in range(100_000_000):   # 几秒钟的循环
        total += i
    result_text.insert("1.0", f"结果：{total}")
```

**用户视角**：点了按钮，窗口灰了，转圈，什么都点不了。

**解决方案（思路，本课不展开实现）：**

1. **多线程**：把耗时操作放到 `threading.Thread` 里，做完后通过 `root.after()` 把结果传回主线程更新界面。
2. **分批处理**：用 `root.after()` 把大任务拆成小块，每处理一块就让 GUI 刷新一次。
3. **进度条**：用 `ttk.Progressbar` 显示进度，让用户知道程序没死。

**第 30 课会讲"大文件"场景的处理思路。** 现在你只要记住一条铁律：

> **回调函数里不要做任何耗时操作。** 超过 100ms 的操作都要考虑放到后台线程。

## 完整的统计逻辑实现

**把前面所有内容组装起来，这是当前版本的完整代码：**

```
import tkinter as tk
from tkinter import ttk
from collections import Counter

# ==================== 业务逻辑层 ====================

def count_chars(text: str) -> int:
    return len(text)

def count_lines(text: str) -> int:
    if not text.strip():
        return 0
    return len(text.split("\n"))

def count_word_freq(text: str, top_n: int = 5) -> list:
    chars = [c for c in text if c.strip()]
    if not chars:
        return []
    return Counter(chars).most_common(top_n)

def format_result(chars: int, lines: int, freq: list) -> str:
    parts = [
        f"总字符数：{chars}",
        f"总行数：{lines}",
        f"词频 Top {len(freq)}：",
    ]
    for char, count in freq:
        parts.append(f"  「{char}」：{count} 次")
    return "\n".join(parts)

# ==================== 界面层 ====================

def create_app():
    root = tk.Tk()
    root.title("文本统计工具")
    root.geometry("600x500")

    # 输入区
    input_frame = ttk.LabelFrame(root, text="输入区")
    input_frame.grid(row=0, column=0, padx=10, pady=5, sticky="ew")

    text_input = tk.Text(input_frame, height=10, wrap="word")
    text_input.grid(row=0, column=0, sticky="ew", padx=5, pady=5)

    # 按钮区
    button_frame = ttk.LabelFrame(root, text="操作区")
    button_frame.grid(row=1, column=0, padx=10, pady=5, sticky="ew")

    def on_count():
        text = text_input.get("1.0", "end-1c")
        chars = count_chars(text)
        lines = count_lines(text)
        freq = count_word_freq(text, top_n=5)
        result = format_result(chars, lines, freq)

        result_text.configure(state="normal")
        result_text.delete("1.0", "end")
        result_text.insert("1.0", result)
        result_text.configure(state="disabled")

    btn_count = ttk.Button(button_frame, text="开始统计", command=on_count)
    btn_count.grid(row=0, column=0, padx=5, pady=5)

    # 结果区
    result_frame = ttk.LabelFrame(root, text="统计结果")
    result_frame.grid(row=2, column=0, padx=10, pady=5, sticky="ew")

    result_text = tk.Text(result_frame, height=8, wrap="word", state="disabled")
    result_text.grid(row=0, column=0, sticky="ew", padx=5, pady=5)

    # 可拉伸配置
    root.columnconfigure(0, weight=1)
    input_frame.columnconfigure(0, weight=1)
    result_frame.columnconfigure(0, weight=1)

    return root

if __name__ == "__main__":
    app = create_app()
    app.mainloop()
```

**结构一目了然：上半部分是纯逻辑，下半部分是界面。** 这就是专业项目的代码组织方式。

## 小结

- **逻辑与界面分离**：业务逻辑写成纯函数，不依赖 tkinter
- **纯函数的好处**：可复用、可测试、职责单一、易于维护
- **界面层只做三件事**：取数据 → 调逻辑 → 更新显示
- **Text 取值**：`get("1.0", "end-1c")` 去掉末尾换行
- **Text 写入**：先解锁 → 清空 → 写入 → 再锁定
- **闭包替代 global**：把应用包在 `create_app()` 里，回调自然捕获控件变量
- **回调里不做耗时操作**：超过 100ms 要考虑多线程，否则界面卡死
