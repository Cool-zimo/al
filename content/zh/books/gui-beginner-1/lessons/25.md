# 用 `Toplevel` 开第二个窗口（模态与非模态）

> 一个窗口往往不够用。设置面板、帮助框、确认页——这些都需要是独立的窗口。`tkinter.Toplevel` 能造出第二个（甚至第三个）窗口；再配合 `grab_set()`，你还能让它变成模态的：用户必须先处理它，才能回到主窗口。

## 三行代码开第二个窗口

**`Toplevel(root)` 创建一个独立的新窗口；之后往里放控件的方式跟 `root` 一模一样。**

```
import tkinter as tk

root = tk.Tk()
root.title("主窗口")

def open_window():
    top = tk.Toplevel(root)
    top.title("额外窗口")
    tk.Label(top, text="来自第二个窗口的问候！").pack(padx=20, pady=20)

tk.Button(root, text="打开窗口").pack(command=open_window)

root.mainloop()
```

**点一下按钮，一个全新的窗口就出现了，带它自己的标题栏和关闭按钮。** 它跟主窗口跑在同一个 `mainloop` 上，所以关掉主窗口，所有窗口一起关。你已知的任何控件——Label、Entry、Button——都能像塞进 root 一样塞进 Toplevel。

## 翻车现场一：把 `Toplevel` 当函数调用链来写

```
top = tk.Toplevel(root).title("额外")   # WRONG-ish: 能跑，但掩盖了流程
```

**构造函数后面直接 `.title(...)` 在语法上合法但容易让人看糊涂，而且一旦你想对 `top` 多做点什么就立刻失效。** 可读的写法是三条独立的行：创建、配置、填充。等窗口变复杂时你会感谢自己。

## 非模态窗口：用户可以切回去

**普通 Toplevel 是非模态的：用户可以在它和主窗口之间来回点。** 这特别适合搜索框、调色板，或者同一份数据的另一个视图。

```
import tkinter as tk

root = tk.Tk()
root.title("主窗口")

def open_palette():
    top = tk.Toplevel(root)
    top.title("颜色")
    for colour in ("red", "green", "blue"):
        tk.Button(top, text=colour,
                  command=lambda c=colour: root.configure(bg=c)).pack(fill="x")

tk.Button(root, text="挑颜色").pack(command=open_palette)

root.mainloop()
```

**因为它非模态，用户可以把它一直开着继续干活。** 那些按钮能回到 `root`，是因为 `root` 在作用域里。窍门就在这：Toplevel 不过是个普通容器，外层函数的变量在它里面照样能用。

## 让它变成模态：`grab_set`

**模态窗口会把程序其余部分冻住，直到用户关掉它——这正是确认框或必填表单想要的。**

```
import tkinter as tk

root = tk.Tk()
root.title("主窗口")

def confirm():
    top = tk.Toplevel(root)
    top.title("确认")
    tk.Label(top, text="要删除全部内容吗？").pack(padx=20, pady=10)
    tk.Button(top, text="是的，删除",
              command=lambda: (print("已删除"), top.destroy())).pack(side="left")
    tk.Button(top, text="取消", command=top.destroy).pack(side="left")
    top.grab_set()       # 模态：锁住其余部分

tk.Button(root, text="全部删除", command=confirm).pack()

root.mainloop()
```

**`top.grab_set()` 让 `top` 成为唯一能接收输入的窗口。** 在 `top` 被销毁之前，点主窗口毫无反应。这是"你确定吗？"类对话框和必填录入弹窗的标准套路。

## 翻车现场二：模态了却关不掉

```
def confirm():
    top = tk.Toplevel(root)
    tk.Label(top, text="重要！").pack()
    top.grab_set()        # WRONG-ish: 没有销毁 top 的按钮或协议
```

**如果窗口里没有任何东西调用 `top.destroy()`，grab 永远不会解除，整个程序就被永久锁死。** 每个模态窗口都要有一个调 `top.destroy()` 的按钮，或是一个 `protocol("WM_DELETE_WINDOW", ...)` 处理器——通常两者都要。

## 让它等：`wait_window`

**有时候你要的是用户在弹窗里*输入*的那个值。`wait_window` 会让调用函数暂停，直到 Toplevel 被销毁，之后你就能读结果了。**

```
import tkinter as tk

root = tk.Tk()
root.title("主窗口")

def ask_name():
    result = {"name": None}
    top = tk.Toplevel(root)
    top.title("输入名字")

    entry = tk.Entry(top)
    entry.pack(padx=10, pady=10)

    def submit():
        result["name"] = entry.get()
        top.destroy()

    tk.Button(top, text="确定", command=submit).pack()
    top.grab_set()
    top.wait_window()          # 在这里暂停，直到 top 被销毁

    if result["name"]:
        print(f"拿到了：{result['name']}")

tk.Button(root, text="问名字", command=ask_name).pack()

root.mainloop()
```

**`wait_window()` 会阻塞调用它的函数，但事件循环照转——所以弹窗仍然响应。** 当 `submit` 调用 `top.destroy()`，`wait_window()` 返回，函数继续执行，这时它就能读 `result["name"]` 了。用字典（或只有一个元素的列表）来避开"在嵌套函数里给局部变量赋值"的问题。

## 翻车现场三：忘了 `wait_window`，读得太早

```
def ask_name():
    top = tk.Toplevel(root)
    entry = tk.Entry(top)
    entry.pack()
    tk.Button(top, text="确定", command=top.destroy).pack()
    print(entry.get())     # WRONG: 立刻打印出 ""，用户还没来得及打字
```

**没有 `wait_window()`，代码会直接往下冲，在 Entry 刚创建的那一刻就去读它——那时它是空的。** 修法是在控件之后、读取之前放上 `top.wait_window()`。

## transient、geometry 及其他窗口小调整

**再加上几句，Toplevel 就会显得是"有意而为之"，而不是意外弹出来的。**

```
top = tk.Toplevel(root)
top.title("设置")
top.geometry("300x150")
top.transient(root)      # 贴在 root 上方，一起最小化
top.resizable(False, False)
```

**`transient(root)` 告诉窗口管理器把这个弹窗保持在父窗口之上，并随父窗口一起最小化。** `resizable(False, False)` 锁死尺寸，用户不会不小心把一个小小的对话框拉变形。两者合起来，就是一个精致设置窗口和一个偶然出现的方块之间的差别。

## 综合示例：自制确认对话框

**你可以用 Toplevel 加 `grab_set` 和 `wait_window`，造出一个行为跟 `messagebox.askyesno` 一样的对话框。**

```
import tkinter as tk

def ask_yes_no(root, question):
    answer = None
    top = tk.Toplevel(root)
    top.title("确认")
    top.transient(root)
    tk.Label(top, text=question, padx=20, pady=15).pack()

    def yes():
        nonlocal answer
        answer = True
        top.destroy()

    def no():
        nonlocal answer
        answer = False
        top.destroy()

    tk.Button(top, text="是", command=yes).pack(side="left", padx=10, pady=10)
    tk.Button(top, text="否", command=no).pack(side="left", padx=10, pady=10)
    top.grab_set()
    top.wait_window()
    return answer

root = tk.Tk()
root.title("示例")

def check():
    if ask_yes_no(root, "真的要退出吗？"):
        root.destroy()

tk.Button(root, text="退出", command=check).pack()

root.mainloop()
```

**`nonlocal answer` 让内层函数能改写外层函数的变量**——跟上一例里字典干的活一样，只是更干净一点。两种做法都行，挑读起来更顺手的那个。

## 小结

- `Toplevel(root)` 创建第二个窗口；往里塞控件就跟 root 一样
- 普通 Toplevel 是非模态的——用户可以来回切换
- `grab_set()` 让窗口变成模态；一定要给用户一条关闭它的路
- `wait_window()` 暂停到窗口销毁，让你随后能读结果
- `transient(root)` 和 `resizable(False, False)` 能让弹窗更精致
- 用 `nonlocal` 变量或单元素字典，把结果从嵌套回调里带出来
