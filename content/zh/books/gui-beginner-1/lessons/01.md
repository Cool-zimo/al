# 从命令行到窗口

> 你以前写的程序，输入靠打字、输出靠 print。窗口程序不一样——它自己会"摆摊"，等着用户来点。这一节讲清楚 GUI 到底解决了什么问题。

## 命令行程序的三件烦心事

你写过的最熟悉的程序大概长这样：

```python
name = input("你叫什么名字？")
print("你好，", name)
```

**它有三个绕不开的限制：**

1. **顺序死板**：先问姓名，再问年龄，不能回头改。想加一个"重填"按钮？做不到。
2. **界面靠文字**：菜单靠打印编号、让用户输 `1`/`2`/`3` 选。稍微复杂一点就变成"请输入 1 选北京、2 选上海……"，用户骂娘。
3. **只能线性跑完**：程序从上到下走完就退出。没法"打开窗口 → 用户随便点 → 点了之后才干活"。

```python
# 一个典型的"伪菜单"，你是不是也写过？
print("1. 查看余额")
print("2. 转账")
print("3. 退出")
choice = input("请选择：")
if choice == "1":
    ...
```

**这不是不能用，是用户体验太差。** 你手机里任何一个 App、电脑上任何一个软件，都不是靠 `input()` 和 `print()` 做出来的。

## GUI 是什么：三要素

**GUI = Graphical User Interface（图形用户界面）**。拆解开来，它只由三样东西组成：

| 要素 | 英文 | 干什么 | 例子 |
|---|---|---|---|
| 窗口 | Window | 程序的"房子"，承载一切 | 标题栏写着"记事本"的那个框 |
| 控件 | Widget / Control | 用户看得见、摸得着的东西 | 按钮、输入框、文字、下拉框 |
| 事件 | Event | 用户做了什么动作 | 点击、敲键盘、移动鼠标 |

**三要素的关系一句话说完：控件摆在窗口里，用户的动作变成事件，程序响应事件。**

```python
# 伪代码，先理解思路，跑不起来
创建窗口
在窗口里放一个按钮，文字是"点我"
当用户点击按钮时：
    把一段文字改成"谢谢点击"
让窗口一直显示着，等用户操作
```

**最后那句"一直显示着、等用户操作"是关键。** 命令行程序是自己主动跑完就退；窗口程序是被动的——它启动后**原地待命**，用户的每一次点击、按键才触发一段代码。

## 事件驱动：你写的不是"流程"，是"反应"

命令行程序的主线是"我做什么、然后做什么"。窗口程序的主线是"**当……发生时，我做什么**"。

```python
# 命令行：我主动
print("开始处理")
data = load_file()
result = process(data)
print(result)

# 窗口：我被动，写好一堆"当……时"
当点击"打开"按钮时 → 弹出文件选择框
当点击"统计"按钮时 → 统计当前文本
当在输入框打字时   → 实时更新字数
```

**这两种思维方式的切换，是学 GUI 第一道坎。** 你不再写一个从上到下的长流程，而是写好一堆**回调函数**（callback）——它们平时躺着不动，等事件来了才被调用。

## tkinter 是什么，能吃吗

**tkinter 是 Python 自带的标准库**，用来做窗口程序。Python 安装好，tkinter 就已经在电脑里了，不用额外 `pip install`。

它封装的是一个叫 **Tcl/Tk** 的老牌图形库（1991 年就存在了）。优点和缺点都来自这里：

- **优点**：自带、轻量、跨平台（Windows / macOS / Linux 都能跑）、学起来快
- **缺点**：样子比较"复古"，做不出花哨的界面；不适合做大型商业软件

```python
# 验证一下你有没有 tkinter（这个可以在网页里跑）
import tkinter
print(tkinter.TkVersion)   # 比如 8.6
```

**判断你该不该用 tkinter**：学 Python 半年以内、想做点小工具给自己用、要处理文件/表单/数据可视化——tkinter 刚好。要做炫酷 App、要精确控制像素、要商业产品——那应该去看网页前端或 Qt。

## 一个最小窗口：先别管细节

先看一个完整例子（**窗口程序在网页里跑不了，请点"在 VS Code 里打开"运行**）：

```
import tkinter as tk

root = tk.Tk()              # 创建主窗口
root.title("我的第一个窗口")  # 设置标题
root.geometry("400x300")    # 设置大小

root.mainloop()             # 进入事件循环，窗口才显示
```

**这四行就是窗口程序的全部骨架。** 后面 29 课，都是在往这个骨架上加东西：加控件、加事件、加布局。

| 代码 | 作用 |
|---|---|
| `tk.Tk()` | 造一个窗口对象，通常叫 `root` |
| `root.title("...")` | 标题栏文字 |
| `root.geometry("宽x高")` | 初始尺寸，注意是字母 x |
| `root.mainloop()` | 启动事件循环，**没有它窗口一闪就没** |

**关于 `mainloop()`，记住一句话：它是程序的"终点站"。** 调用它之后，程序就停在这里，专心处理用户操作，直到窗口被关闭才继续往下走（如果下面还有代码的话）。

## 翻车现场一：忘了 mainloop，窗口一闪而过

**这是新手最常见的错误，没有之一。**

```
import tkinter as tk

root = tk.Tk()
root.title("测试")
# 哎呀忘了写 mainloop()
print("程序结束")
```

**症状**：程序"唰"地运行了一下，窗口没出现（或者出现 0.01 秒就关了），终端打印出"程序结束"。

**原因**：没有 `mainloop()`，Python 把两行代码执行完就退出了。窗口刚被创建、还没来得及画出来，程序就没了。

**修复**：在最后一行补上 `root.mainloop()`。

**同理，把逻辑代码写在 `mainloop()` 后面也跑不到：**

```
root.mainloop()
print("这句永远不会执行")   # 窗口关闭后才会打印
do_something()              # 窗口关了才调用
```

**记住：mainloop 之后只写"收尾代码"。**

## 翻车现场二：把 mainloop 写在前面

```
root = tk.Tk()
root.mainloop()          # 太早了！
root.title("标题")       # 窗口都开始循环了，才想起来设标题
```

**虽然这句 title 能生效（窗口关闭前最后一刻），但逻辑上是错的。** 正确顺序是：**先把窗口和控件都准备好，最后才调用 `mainloop()`。**

## 翻车现场三：Tk() 被调用两次

```
import tkinter as tk

a = tk.Tk()   # 第一个窗口
b = tk.Tk()   # 第二个窗口——其实不该这么写
```

**一个程序通常只有一个 `Tk()` 实例。** 想开第二个窗口要用 `tk.Toplevel()`（这个第 25 课讲）。创建两个 `Tk()` 会导致事件循环混乱、程序卡死。

**如果你就是想要两个窗口，第二个请写成 `tk.Toplevel(root)`。**

## 命令行 vs 窗口：一张对照表

| 对比项 | 命令行程序 | 窗口程序 |
|---|---|---|
| 输入 | `input()` 打字 | 输入框、按钮、菜单 |
| 输出 | `print()` 打印 | 标签、文本框、弹窗 |
| 流程 | 线性，跑完即退 | 事件驱动，常驻待命 |
| 入口 | `if __name__ == "__main__"` | 创建窗口 + `mainloop()` |
| 调试 | 看终端输出 | 看界面反应、print 辅助 |

## 小结

- GUI 三要素：**窗口（装东西）、控件（用户操作）、事件（用户动作）**
- tkinter 是 Python **自带**的标准库，import 即用
- 窗口程序是**事件驱动**的：写好一堆"当……时"，等用户触发
- 程序骨架只有四步：`Tk()` 创建 → 设标题/尺寸 → 加控件 → `mainloop()` 启动
- **mainloop 是终点站**：必须放在最后；它之后只写收尾代码
- 一个程序只创建一个 `Tk()`，第二个窗口用 `Toplevel()`
