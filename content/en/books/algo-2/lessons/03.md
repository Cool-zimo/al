# Insertion and Deletion: Head Insert, Middle Insert, Deleting a Node (Why You Need a Predecessor)

> Insertion and deletion are where linked lists truly shine. This lesson breaks down head insertion, middle insertion, and deletion one by one, and explains why deletion absolutely requires the **predecessor**.

## Head Insertion: The Fastest Linked-List Operation

Head insertion means adding a node at the very front of the list, in O(1).

```python
def insert_head(head, val):
    return ListNode(val, head)   # the new node's next points at the old head

head = build([2, 3])
head = insert_head(head, 1)
print(to_list(head))    # [1, 2, 3]
```

How it works: the new node points at the old head, then the head pointer points at the new node. **Two steps, regardless of how long the list is.**

## Middle Insertion: You Must Find the Predecessor

To insert `99` between `2` and `3`, you first need to grab node `2` (the predecessor), then:

```
predecessor.next = new_node
new_node.next    = what predecessor.next used to point to
```

In code:

```python
def insert_after(prev_node, val):
    new_node = ListNode(val, prev_node.next)
    prev_node.next = new_node

head = build([1, 2, 3])
insert_after(head.next, 99)   # head.next is node 2
print(to_list(head))          # [1, 2, 99, 3]
```

**Key point**: first point the new node's `next` at `2`'s original next, then point `2.next` at the new node. **The order cannot be reversed**—if you change `prev_node.next` first, the original next node is lost.

## WRONG: Changing the Predecessor's Next First Makes the Old Successor Vanish

```python
# WRONG
def insert_after(prev_node, val):
    prev_node.next = ListNode(val)          # new node is hung
    prev_node.next.next = prev_node.next    # want to reconnect the old successor? It is already gone
```

```text
Result: [1, 2, 99] — node 3 is permanently lost, a memory leak.
```

Once you overwrite `prev_node.next`, the original reference to `3` has nothing pointing at it anymore. The correct order is to first build `ListNode(val, prev_node.next)`, which captures the old successor inside the new node's `next`, and only then reassign `prev_node.next`.

## Deleting a Node: Why You Must Have the Predecessor

Deleting a node from a linked list really means "make its predecessor skip over it."

```python
def delete_node(head, target_val):
    if head is None:
        return head
    if head.val == target_val:      # the node to delete is the head - special case
        return head.next
    prev = head
    cur = head.next
    while cur:
        if cur.val == target_val:
            prev.next = cur.next    # predecessor skips cur
            return head
        prev = cur
        cur = cur.next
    return head

head = build([1, 2, 3, 4])
head = delete_node(head, 3)
print(to_list(head))    # [1, 2, 4]
```

**Why is the predecessor mandatory?** Because in a singly linked list you can only move forward. The single line `prev.next = cur.next` makes the predecessor point straight at the successor, and `cur` simply falls out of the chain. Without a predecessor pointer, you cannot rewrite the arrow that points into the node you want gone.

## WRONG: Pointing `cur` at `cur.next` Does Not Delete Anything

The most classic misconception:

```python
# WRONG
def delete_node(head, target):
    cur = head
    while cur:
        if cur.val == target:
            cur = cur.next    # thought this deletes it
            return head
        cur = cur.next
```

```text
Result: the linked list is completely unchanged.
You only changed where the local variable cur points; not one arrow in the list moved.
```

`cur` is just a variable. Pointing `cur` at the next node changes the variable, but the `2 → 3` arrow in the list is still `2 → 3`. **Deletion must change the predecessor's `next`.**

## WRONG: Forgetting the Head Case Returns the Wrong Node

```python
# WRONG
def delete_node(head, target):
    prev = head
    cur = head.next
    while cur:
        if cur.val == target:
            prev.next = cur.next
            return head
        prev = cur
        cur = cur.next
    return head
```

```text
Trace: head = [5, 5, 5], delete 5
Result: returns [5, 5] instead of []
The function can never remove the first node because it starts prev and cur one step too far.
```

Because `prev` begins at `head` and `cur` at `head.next`, the first node is never even checked. **The head has no predecessor, so it must be handled explicitly before the loop.**

## Boundary: Deleting the Head Requires a Separate Return

Notice the special handling of the head in the correct `delete_node`:

```python
if head.val == target_val:
    return head.next
```

The head has no predecessor. This is exactly the problem the next lesson's "dummy head node" solves.

## Summary

- Head insertion is O(1): `ListNode(val, head)` does it in one step.
- Middle insertion needs the predecessor first, and you must attach the old successor before rewriting the predecessor.
- Deletion must change the predecessor's `next`; changing only the local variable `cur` does nothing.
- The head has no predecessor, so deleting it requires special handling (this motivates the dummy node).
