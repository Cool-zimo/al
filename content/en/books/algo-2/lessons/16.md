# Queues and Deques: The Art of FIFO

> A queue is "waiting in line" — first come, first served. But using a Python list as a queue will bite you with O(n) in the most unexpected place. `collections.deque` is the real answer.

## The Problem

A **queue** is a **First-In-First-Out** (FIFO) data structure. Think of a cafeteria line: the person who arrives first gets served first; everyone else waits behind them.

There are only two core operations:

- **enqueue**: add an element to the back of the line
- **dequeue**: remove an element from the front

```python
# Ideal queue usage
q = []
q.append("Alice")      # enqueue: Alice joins the line
q.append("Bob")        # enqueue: Bob stands behind Alice
q.append("Carol")      # enqueue: Carol goes to the very back
first = q.pop(0)       # dequeue: Alice leaves first -> "Alice"
```

Looks fine, right? **But** — the cost of `q.pop(0)` is far greater than you think.

## Why `list.pop(0)` Is O(n)

Python's `list` is backed by a **dynamic array** — elements are stored contiguously in memory. When you `pop(0)`, the first element is removed and every remaining element must shift forward by one position to fill the gap.

```python
# A list of length n, after pop(0):
# Before: [a0, a1, a2, a3, ..., a(n-1)]
# After:  [a1, a2, a3, ..., a(n-1), ?]
# All n-1 elements move one slot -> O(n)

# If you do n calls to pop(0), total cost is O(n²)
q = list(range(10000))
for _ in range(len(q)):
    q.pop(0)   # every call moves all remaining elements
# Total moves: 9999 + 9998 + ... + 1 = about 50 million
```

**This is exactly why a list-based queue will TLE (Time Limit Exceeded) as soon as n grows.**

## `collections.deque`: Double-Ended Queue

`deque` (double-ended queue) is a data structure in the Python standard library optimized specifically for operations at both ends. Its `popleft()` and `append()` are both **O(1)**.

```python
from collections import deque

q = deque()
q.append("Alice")     # enqueue at back -> O(1)
q.append("Bob")       # O(1)
q.append("Carol")     # O(1)
first = q.popleft()   # dequeue from front -> O(1), "Alice"
print(first)          # Alice
print(q)              # deque(['Bob', 'Carol'])
```

Under the hood, a deque is a hybrid of a **doubly-linked list and a block-based array**. Neither end requires shifting elements, which is why it achieves O(1).

## WRONG: Using `list.pop(0)` as a Queue

```python
# WRONG: simulating a queue with a list
q = []
q.append(1)
q.append(2)
q.append(3)
while q:
    print(q.pop(0))   # every pop(0) is O(n)
```

The code runs, and the output is correct — but **the performance is O(n²)**. When n = 10⁵, this is the difference between "100ms" and "10 seconds."

**Proof by measurement:**

```python
import time
from collections import deque

n = 100000

# list version
q1 = list(range(n))
t0 = time.time()
while q1:
    q1.pop(0)
t1 = time.time()

# deque version
q2 = deque(range(n))
t2 = time.time()
while q2:
    q2.popleft()
t3 = time.time()

print(f"list.pop(0) took: {t1-t0:.3f}s")
print(f"deque.popleft() took: {t3-t2:.3f}s")
# list version may take several seconds; deque finishes almost instantly
```

**Rule: whenever your intent is "queue," reach for `deque` without hesitation.**

## WRONG: Confusing `append` and `appendleft`

```python
from collections import deque

q = deque([1, 2, 3])
q.appendleft(0)    # add from the left -> deque([0, 1, 2, 3])
q.append(4)        # add from the right -> deque([0, 1, 2, 3, 4])
q.pop()            # remove from the right -> 4
q.popleft()        # remove from the left -> 0
```

Here are all four operations side by side:

| Operation | Position | Time Complexity |
|---|---|---|
| `append(x)` | right end enqueue | O(1) |
| `appendleft(x)` | left end enqueue | O(1) |
| `pop()` | right end dequeue | O(1) |
| `popleft()` | left end dequeue | O(1) |

**The standard queue idiom is `append()` + `popleft()`** (right-in, left-out = FIFO). If you write `append()` + `pop()`, you've built a **stack** (LIFO), not a queue.

## Other Useful deque Operations

```python
from collections import deque

q = deque([1, 2, 3])

# Peek at the front (without removing)
print(q[0])        # 1, O(1)

# Peek at the back
print(q[-1])       # 3, O(1)

# Check if empty
print(len(q) == 0)  # False

# Rotate
q.rotate(1)        # rotate right by 1 -> deque([3, 1, 2])
q.rotate(-1)       # rotate left by 1  -> deque([1, 2, 3])

# Cap the maximum length (auto-discards from the opposite end)
dq = deque(maxlen=3)
dq.append(1)       # deque([1])
dq.append(2)       # deque([1, 2])
dq.append(3)       # deque([1, 2, 3])
dq.append(4)       # deque([2, 3, 4]), the leftmost 1 is discarded
```

`maxlen` is perfect for "sliding window" problems — it auto-maintains a fixed-size window.

## WRONG: Modifying a deque While Iterating

```python
# WRONG: popping and appending during iteration
q = deque([1, 2, 3])
for x in q:
    q.append(x * 10)   # infinite loop! every iteration adds a new element
```

Python's for-loop keeps discovering "new elements," causing an **infinite loop**. The correct approach:

```python
# RIGHT: snapshot the length, process only what's already there
q = deque([1, 2, 3])
for _ in range(len(q)):
    x = q.popleft()
    q.append(x * 10)
print(q)   # deque([10, 20, 30])
```

Alternatively, skip iteration entirely and control the boundary with a `while` loop.

## Typical Queue Applications

1. **BFS (Breadth-First Search)**: a queue naturally tracks the "current level" of nodes
2. **Producer-consumer model**: one side enqueues, the other dequeues
3. **Message queues / task scheduling**: tasks submitted first run first
4. **Buffers**: e.g., keyboard input buffers

## Complexity Comparison

| Operation | list as queue | deque |
|---|---|---|
| enqueue at back | O(1) | O(1) |
| dequeue at front | **O(n)** | **O(1)** |
| random access `q[i]` | O(1) | O(1) (slower) |
| space overhead | small | slightly larger |

**One-liner: FIFO semantics -> deque; random access -> list.**

## Summary

- A queue is a FIFO structure: the first element enqueued is the first to leave
- Python `list.pop(0)` is **O(n)** because it shifts every remaining element
- `collections.deque.popleft()` is **O(1)** — the default choice for queues
- Standard queue idiom: `append()` to enqueue + `popleft()` to dequeue
- Modifying a deque during iteration causes an infinite loop — snapshot the length first
- The `maxlen` parameter lets a deque auto-maintain a fixed window
