# Cycle Detection: Why Floyd's Algorithm Always Meets

> A linked list gives you no "end of the road" marker when a cycle exists—it just goes on forever. Floyd's cycle-finding algorithm answers "is there a loop?" in O(1) memory instead of O(n).

## The Problem

```
1 -> 2 -> 3 -> 4
     ^         |
     |_________|      node 4 points back at node 2, forming a cycle
```

Decide whether the list contains a cycle. The instinctive approach is to walk and remember every node you have seen:

```python
def has_cycle_set(head):
    seen = set()
    cur = head
    while cur:
        if id(cur) in seen:
            return True
        seen.add(id(cur))
        cur = cur.next
    return False
```

It passes, but it costs **O(n) extra space**. The interview question wants O(1).

## Floyd's Cycle-Finding Algorithm (the Tortoise and the Hare)

Two pointers: one takes a single step (slow), the other takes two (fast).

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True
    return False
```

**The guard `fast and fast.next`**: since `fast` advances by two, `fast.next` must exist; otherwise `fast.next.next` raises `AttributeError`.

## Why They Must Meet

This is the only part that really needs a proof.

Suppose the acyclic prefix has length `m` and the cycle has length `k`. Once the fast pointer enters the cycle, the slow pointer also enters it eventually. At that moment:

- Slow moves 1 position per round.
- Fast moves 2 positions per round.
- **Their relative speed is 1 position per round.**

A relative speed of 1 means: every round, the fast pointer reduces its gap behind (or ahead of) the slow pointer by exactly 1. The gap goes `d`, `d-1`, `d-2`, … and eventually reaches zero. The round it reaches zero is the round they occupy the same node.

**The key premise: relative speed 1.** If fast moved three steps (relative speed 2), it could permanently skip past the slow pointer on an even-length cycle. Two steps is the safe choice.

Trace it by hand on a cycle of length 3:

```
positions: 0  1  2  (then back to 0)
slow:      S
fast:      F
round 1:   slow=1, fast=2
round 2:   slow=2, fast=1   (fast took two steps: 2->0->1)
round 3:   slow=0, fast=0   <- meeting point
```

Three rounds on a three-node cycle. The total number of rounds never exceeds `m + k`.

## A Two-Node Mutual Loop Works Too

```python
class Node:
    def __init__(self, v):
        self.v = v
        self.next = None

a = Node(1); b = Node(2)
a.next = b; b.next = a        # 1 -> 2 -> 1

print(has_cycle(a))           # True
```

The extreme case is a single node pointing at itself:

```python
x = Node(9)
x.next = x
print(has_cycle(x))           # True
```

Think through why this works. Initially `slow is fast` both point at `x`, but the loop moves first and compares after. After the first move, `slow = x.next = x` and `fast = x.next.next = x`, still equal → True. **Move before comparing** matters. If you compared first and moved after, an acyclic one-node list would be wrongly declared cyclic:

```python
# WRONG
def has_cycle_bad(head):
    slow = fast = head
    while fast and fast.next:
        if slow is fast:      # true on the very first round!
            return True
        slow = slow.next
        fast = fast.next.next
    return False

n = Node(1)                   # one node, no cycle
print(has_cycle_bad(n))       # True  <- wrong!
```

## Finding the Cycle's Entrance

Once the two pointers meet, put one of them back at the start. Now move both one step at a time. The node where they meet again is the entrance of the cycle.

```python
def detect_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            p = head
            while p is not slow:
                p = p.next
                slow = slow.next
            return p          # cycle entrance
    return None
```

The conclusion is not obvious, but the intuition goes like this. Let the acyclic prefix be `m`, the distance from the entrance to the meeting point be `x`, and the cycle length be `k`. When they meet, fast has taken `2s` steps and slow has taken `s`, so the difference `s` must be an integer multiple of `k`. Walking `m` more steps from the meeting point lands you back at the entrance, and walking `m` steps from the head also lands you at the entrance. So the two pointers arrive together.

You do not need to memorize the algebra. Remember the recipe: **after meeting, put one pointer back at the head, advance both one step at a time, and their second meeting is the entrance.**

## Complexity

| Method | Time | Space |
|---|---|---|
| Hash set of `id()` | O(n) | O(n) |
| Floyd two-pointer | O(n) | **O(1)** |

That O(1) space is the whole reason Floyd's algorithm exists.

## # WRONG 1 — Comparing Values Instead of Identities

```python
# WRONG
def has_cycle_wrong(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow.v == fast.v:      # using == to compare values
            return True
    return False

a = Node(7); b = Node(7); c = Node(7)
a.next = b; b.next = c            # 7 -> 7 -> 7, no cycle
print(has_cycle_wrong(a))         # True  <- wrong! identical values
```

Cycle detection asks whether two pointers hold the **same node object**, so it must use `is`. `==` compares values, and values can repeat.

## # WRONG 2 — Writing the Guard Backwards

```python
# WRONG
while fast.next:          # fast itself might be None
    ...
```

```python
n = Node(1)               # one node, no cycle
# has_cycle(n): fast=n, fast.next=None -> guard is False, exits normally
```

This particular case happens to survive, which makes it a silent trap. Pass it an empty list—`head = None`—and it detonates:

```python
# AttributeError: 'NoneType' object has no attribute 'next'
```

Always write `while fast and fast.next`.

## Where This Shows Up in Real Systems

Cycle detection is not just an interview curiosity. It is the core idea behind:

- **Hair-pin detection in linked structures** where a serializer must refuse to walk a cycle.
- **Proving termination of state-machine simulations**, where revisiting a state means "we have seen this configuration before."
- **Pollard's Rho algorithm** for integer factorization, which uses the same tortoise-and-hare walk over a pseudo-random sequence.

The shape is always the same: a finite state space plus a deterministic step function. If you ever revisit a state, you are in a loop.

## Summary

- Floyd: slow takes 1 step, fast takes 2; a meeting means a cycle.
- **Relative speed 1** guarantees a meeting; 3 steps does not.
- Move before comparing, otherwise a one-node acyclic list is misclassified.
- Compare with `is` (identity), never `==` (value).
- Guard: `while fast and fast.next`.
- Entrance: after meeting, put one pointer at the head, advance both one step, and meet again at the entrance.
- Time O(n), **space O(1)**—that is the whole point over a hash set.
