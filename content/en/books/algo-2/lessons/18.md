# BFS and Queues: The Skeleton of Level-Order Traversal

> BFS (Breadth-First Search) is the classic application of a queue. Its core idea fits in one sentence: "expand level by level." And "level by level" is exactly the FIFO semantics of a queue.

## The Problem

Given a tree (or graph), you need to visit all nodes **by level**: first every node at depth 1, then every node at depth 2, and so on. This is called **level-order traversal**.

A DFS (Depth-First Search) would go all the way down one branch and then backtrack — it doesn't visit by level. BFS is the right tool.

## Core Idea: Queue + Level-by-Level Expansion

The BFS skeleton is remarkably stable. Memorize this template and you're set:

```python
from collections import deque

def bfs(graph, start):
    visited = set([start])           # mark visited
    q = deque([start])               # initialize queue with the start node

    while q:
        node = q.popleft()           # take from the front
        print(node, end=" ")         # process the current node
        for neighbor in graph[node]: # expand all neighbors
            if neighbor not in visited:
                visited.add(neighbor)
                q.append(neighbor)   # enqueue unvisited neighbors
```

**Why a queue?** Because you need to guarantee "the node discovered first gets expanded first." The FIFO semantics of a queue naturally ensures: all nodes at level k are processed before any node at level k+1.

## Representing a Graph with an Adjacency List

To focus on BFS itself, we'll represent the graph as an **adjacency-list dictionary** — no need to "build" a graph:

```python
# Adjacency list: keys are nodes, values are lists of neighbors
graph = {
    1: [2, 3],
    2: [1, 4, 5],
    3: [1, 6, 7],
    4: [2],
    5: [2],
    6: [3],
    7: [3],
}
# This is a tree: 1 is the root, 2 and 3 are its children, and so on
```

```
     / \ / \
    4  5 6  7
```

## Level-by-Level BFS: Knowing What's on Each Level

Often you need to **distinguish the levels** (e.g., finding a tree's minimum depth or computing the average of each level). The trick: **record the current queue length before each round**:

```python
from collections import deque

def bfs_by_level(graph, start):
    visited = set([start])
    q = deque([start])
    level = 0

    while q:
        size = len(q)                # the number of nodes at this level
        print(f"Level {level}:", end=" ")
        for _ in range(size):        # process only the nodes at this level
            node = q.popleft()
            print(node, end=" ")
            for neighbor in graph[node]:
                if neighbor not in visited:
                    visited.add(neighbor)
                    q.append(neighbor)
        print()                      # newline, move to next level
        level += 1

# Output:
# Level 0: 1
# Level 1: 2 3
# Level 2: 4 5 6 7
```

**The key**: `size = len(q)` captures "how many nodes are at this level." The inner loop pops exactly `size` nodes, and they all belong to the same level. Any newly added nodes belong to the next level and won't be touched this round.

## WRONG: Forgetting visited Causes an Infinite Loop

```python
# WRONG: no visited set
def bfs_no_visited(graph, start):
    q = deque([start])
    while q:
        node = q.popleft()
        print(node, end=" ")
        for neighbor in graph[node]:
            q.append(neighbor)   # always enqueue, regardless of visits
```

With the tree above: 1→2→1→2→1→2... **infinite loop!**

```
graph[1] = [2, 3]
graph[2] = [1, 4, 5]

q = [1]
pop 1 -> enqueue 2,3  -> q=[2,3]
pop 2 -> enqueue 1,4,5 -> q=[3,1,4,5]  <- 1 comes back!
pop 3 -> enqueue 1,6,7 -> q=[1,4,5,1,6,7]  <- 1 again!
...
never ends
```

**Why is visited mandatory?** Because graphs (and trees) have back-edges. Without marking nodes as visited, the same node gets enqueued over and over. Both BFS and DFS need a visited mechanism.

## WRONG: Marking visited After Appending

```python
# WRONG: appending first, then marking
for neighbor in graph[node]:
    q.append(neighbor)          # append first
    visited.add(neighbor)       # mark second
# Looks harmless? But with parallel edges or multiple paths to the same node,
# the same node may be appended many times.

# RIGHT: check, mark, then append - all in one motion
for neighbor in graph[node]:
    if neighbor not in visited:
        visited.add(neighbor)   # mark first, so the same node can't be enqueued twice
        q.append(neighbor)
```

**Order matters**: check -> mark -> enqueue. If you mark too late, the same node can be discovered by multiple paths and enqueued repeatedly.

## WRONG: Checking visited Only After Popleft

```python
# WRONG: checking whether a node was visited only when it leaves the queue
q = deque([start])
while q:
    node = q.popleft()
    if node in visited:       # too late!
        continue
    visited.add(node)
    for neighbor in graph[node]:
        q.append(neighbor)
```

The problem: **the same node may already appear in the queue multiple times**. You skip it on dequeue, but you've wasted queue space and traversal time. The right place to mark visited is **before enqueueing**, guaranteeing each node enters the queue at most once.

## BFS vs. DFS

| Feature | BFS | DFS |
|---|---|---|
| Data structure | queue | stack (recursion stack) |
| Visit order | level by level (near -> far) | goes deep down one branch |
| shortest path | yes, naturally finds it | not guaranteed |
| space complexity | O(width) | O(depth) |
| best for | shortest paths, level order | connectivity, topological sort |

**Memory aid**: use BFS for shortest paths, DFS for connectivity and full enumeration.

## Complexity

| Metric | Value |
|---|---|
| Time | **O(V + E)** — each node enters and leaves once, each edge checked once |
| Space | **O(V)** — the queue can hold at most one full level |

Here V is the number of vertices and E the number of edges. For a tree, E = V-1, so tree BFS is O(V).

## Summary

- BFS = queue + visited; the skeleton is extremely stable
- The queue guarantees "first discovered, first expanded" -> natural level-order traversal
- **visited is mandatory for BFS**, otherwise back-edges cause infinite loops
- Level BFS trick: record `size = len(q)` first, then loop `size` times
- Mark visited **before enqueueing**: check -> mark -> enqueue
- BFS is ideal for shortest paths and level-order traversal; O(V+E) time, O(V) space
