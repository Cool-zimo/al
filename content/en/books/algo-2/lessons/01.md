# Why Linked Lists Exist: The Weakness of Arrays and the Strength of Linked Lists

> In the previous chapters we squeezed every trick out of arrays: two pointers, prefix sums, binary search, sliding windows. But arrays have one built-in weakness—**insertion and deletion cost O(n)**. This chapter introduces the cure: linked lists.

## The Pain of Arrays

**Scenario**: You have a sorted guest list `names`, and now you need to insert a new name in the middle, or remove an existing one.

```python
names = ["Alice", "Bob", "Charlie", "Diana"]
# Insert "Eve" right after "Bob"
```

How do you do it with an array? First find the position, then shift every element after it one slot to the right.

```python
names = ["Alice", "Bob", "Charlie", "Diana"]
names.append(None)            # expand by one slot
for i in range(4, 1, -1):     # copy from back to front
    names[i] = names[i - 1]
names[2] = "Eve"
print(names)
# ['Alice', 'Bob', 'Eve', 'Charlie', 'Diana']
```

**One insertion forces you to move every element that comes after it—O(n).** If the list has 100,000 names, inserting one person means 100,000 moves.

Deletion works the same way in reverse: remove one from the middle and everything after it must shift left to fill the gap. Still O(n).

## How Linked Lists Fix It

The idea behind a linked list is beautifully simple: **don't store elements contiguously; let each element remember "who comes next."**

```
Array:  [Alice][Bob][Charlie][Diana]   <- packed tight, no room to squeeze in
List:   Alice → Bob → Charlie → Diana   <- each remembers the next, just rewire an arrow
```

To insert "Eve": point Bob's arrow at Eve, then point Eve at Charlie. Two steps, **O(1)**.

```
Bob → Eve → Charlie
```

No data has to move. That is the entire reason linked lists exist.

## Contiguous Memory: The One Advantage Lists Don't Have

Linked lists solve insertion and deletion, but **they give up random access**.

```python
names = ["Alice", "Bob", "Charlie", "Diana"]
print(names[2])    # Charlie — O(1), just offset arithmetic
```

Array elements sit in **contiguous memory**, so `names[2]` is just "base address + 2 × element size"—one calculation, instant access.

A linked list? To reach the 3rd element you must start at the first and follow arrows three times: **O(n)**.

| Operation | Array | Linked List |
|---|---|---|
| Indexed access | O(1) | O(n) |
| Insert at head | O(n) | O(1) |
| Insert in middle | O(n) | O(1) (after finding the spot) |
| Delete in middle | O(n) | O(1) (after finding the spot) |
| Memory layout | Compact, fragmentation risk | Flexible, two extra pointers per node |

## WRONG: `list.insert` Is O(n)—Don't Be Fooled

Many people assume Python's `list` inserts are fast, so they write this:

```python
# WRONG
data = list(range(100000))
for _ in range(10000):
    data.insert(0, 0)   # head-insert every time
```

```text
Observed behavior: the program hangs.
Each insert(0, x) must shift 100,000 elements right,
so total work is 10000 × 100000 = 1 billion shifts.
This will always time out in a contest.
```

`list.insert` is **O(n)**, full stop. **When you need frequent insertions or deletions at both ends, a Python `list` is the wrong tool**—use `collections.deque` (a double-ended queue) or build your own linked list.

## When to Use Which

Rule of thumb:

- **Need fast indexed access** (binary search, prefix sums, dynamic programming) → array
- **Need frequent insertion/deletion, especially at the head** (queues, LRU caches) → linked list
- **Unbounded size with no interest in reserving capacity** → linked list

> 💡 Arrays and linked lists don't replace each other; they **divide the work**: arrays make "lookups fast," linked lists make "edits fast."

## Summary

- Array insert/delete must shift elements: **O(n)**. A linked list just rewires arrows: **O(1)**.
- Arrays win on **contiguous memory and O(1) random access**; linked lists have neither.
- Python's `list.insert(0, x)` is O(n); heavy head-insertion will time out.
- Linked lists are the foundation for every data structure that follows (stacks, queues, hash tables, LRU caches).
