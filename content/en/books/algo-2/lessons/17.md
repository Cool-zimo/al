# Circular Queues: Implementing a Queue with a Fixed Array

> An interviewer favorite: given a fixed-size array, how do you implement a queue? The answer is a circular queue — two pointers that "wrap around" the array.

## The Problem

`deque` is great, but in low-level settings (embedded systems, high-frequency trading, interviews) you need to implement a queue using a **fixed-size array**. That means reusing the limited space in a **circular** fashion.

The core challenge: **how do you distinguish "queue empty" from "queue full"?**

If `front` and `rear` point to the same position, does that mean empty or full?

## Core Idea: Two Pointers — front and rear

A circular queue uses a fixed-size array `data` plus two pointers:

- **front**: points to the next element to dequeue (the head of the line)
- **rear**: points to the next empty slot to enqueue (one past the tail)

```
Assume capacity is 5 (actually holds 4 elements; one slot reserved):

Initial state (empty):
data: [_, _, _, _, _]
       ↑            ↑
      front        rear

Enqueue 10, 20, 30:
data: [10, 20, 30, _, _]
        ↑           ↑
       front       rear

Dequeue one (10 leaves):
data: [_, 20, 30, _, _]
             ↑      ↑
           front   rear

Enqueue 40, 50 (rear wraps to the beginning):
data: [50, 20, 30, 40, _]
       ↑        ↑
      rear     front
```

## Why You Must Leave One Slot Empty

This is the most subtle design decision in a circular queue. If you don't reserve a slot:

```
If front == rear means empty:
  when you fill the queue, rear catches up to front -> front == rear means full
  -> empty and full are indistinguishable!
```

**The solution: always leave one slot empty.** Then:

- **Empty**: `front == rear`
- **Full**: `(rear + 1) % capacity == front`

That one reserved slot trades away one unit of storage in exchange for O(1) empty/full checks.

```python
class CircularQueue:
    def __init__(self, k):
        self.capacity = k + 1        # one extra empty slot
        self.data = [0] * self.capacity
        self.front = 0
        self.rear = 0

    def enqueue(self, x):
        if self.is_full():
            return False
        self.data[self.rear] = x
        self.rear = (self.rear + 1) % self.capacity
        return True

    def dequeue(self):
        if self.is_empty():
            return False
        self.front = (self.front + 1) % self.capacity
        return True

    def is_empty(self):
        return self.front == self.rear

    def is_full(self):
        return (self.rear + 1) % self.capacity == self.front

    def get_front(self):
        if self.is_empty():
            return -1
        return self.data[self.front]

# Test
cq = CircularQueue(3)   # actual array size is 4, holds at most 3
cq.enqueue(1)           # [1, _, _, _], front=0, rear=1
cq.enqueue(2)           # [1, 2, _, _], front=0, rear=2
cq.enqueue(3)           # [1, 2, 3, _], front=0, rear=3
print(cq.is_full())     # True <- the 4th slot is forbidden
cq.dequeue()            # [_, 2, 3, _], front=1, rear=3
cq.enqueue(4)           # [4, 2, 3, _], front=3, rear=0 <- wrapped around!
```

## Wrapping Around with Modulo

The whole trick is one line: `(rear + 1) % capacity`. When `rear` reaches the end of the array, adding 1 wraps it back to 0.

```
capacity = 5
rear = 0 -> (0+1)%5 = 1
rear = 1 -> (1+1)%5 = 2
rear = 2 -> (2+1)%5 = 3
rear = 3 -> (3+1)%5 = 4
rear = 4 -> (4+1)%5 = 0  <- wraps to the start!
```

This is cleaner and less error-prone than an `if` statement checking "did we go out of bounds? then reset."

## WRONG: Using the Same Condition for Empty and Full

```python
# WRONG: using the same condition for empty and full
def is_empty(self):
    return self.front == self.rear

def is_full(self):
    return self.front == self.rear   # identical to is_empty!
# Result: you can never tell empty from full; enqueue/dequeue logic collapses
```

**The fix**: the full condition is `(rear + 1) % capacity == front` — it has an extra `+1`.

```
Quick mnemonic:
  empty: front has caught up to rear   -> front == rear
  full:  rear's next slot is front     -> (rear+1) % cap == front
```

## WRONG: Replacing Modulo with an if Statement

```python
# WRONG: manually wrapping with if
self.rear += 1
if self.rear == self.capacity:
    self.rear = 0   # seems fine...

# But other operations (like computing the size) also need wrapping:
# size = (self.rear - self.front)  can be negative!
```

**Stick with modulo** — it's safer:

```python
# RIGHT
self.rear = (self.rear + 1) % self.capacity

# Computing the current element count also needs modulo:
def size(self):
    return (self.rear - self.front) % self.capacity
```

```
Example: front=3, rear=1, capacity=5
  rear - front = 1 - 3 = -2
  (rear - front) % 5 = 3  <- correct, the queue does have 3 elements
```

## WRONG: Forgetting capacity Must Be k + 1

```python
# WRONG: caller asks for capacity 3, you allocate exactly 3
self.data = [0] * k       # size 3
# After reserving one slot, you can only store 2 -> not what was requested

# RIGHT: allocate one extra
self.capacity = k + 1     # size 4, actually stores 3
self.data = [0] * self.capacity
```

**In the constructor, `k` is the user's requested capacity, but you must allocate `k+1` slots.** This is the classic off-by-one mistake with circular queues.

## Circular Queue vs. deque

| Feature | Circular Queue | collections.deque |
|---|---|---|
| Backing store | fixed array | block-based array / linked list |
| Capacity | fixed | dynamic growth |
| Space efficiency | high (no pointer overhead) | slightly lower |
| Implementation difficulty | medium (pointers + modulo) | none (use it directly) |
| Use case | embedded, interviews, fixed buffers | day-to-day coding |

**In an interview**: a circular queue tests your grasp of pointers and modulo.
**In real code**: just use `deque` — don't reinvent the wheel.

## Complexity

| Operation | Time | Space |
|---|---|---|
| enqueue | O(1) | O(k) |
| dequeue | O(1) | O(k) |
| is_empty / is_full | O(1) | — |
| random access | O(1) | — |

Every operation is O(1), and space stays fixed at O(k).

## Summary

- A circular queue uses a fixed array + two pointers (front/rear) to achieve FIFO
- **You must reserve one empty slot** to distinguish "empty" (`front==rear`) from "full" (`(rear+1)%cap==front`)
- Modulo `% capacity` makes the pointers wrap around
- In the constructor, `capacity = k + 1` — caller wants capacity k, you allocate k+1
- Element count: `(rear - front) % capacity`
- In practice use `deque`; hand-roll a circular queue for interviews and low-level work
