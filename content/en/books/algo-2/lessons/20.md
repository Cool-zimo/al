# Practice: Unweighted Shortest Path with BFS

> BFS's most powerful application is finding shortest paths in unweighted graphs. Why does BFS find the shortest path? Because "arriving first" means "fewest steps." This lesson breaks it down completely.

## The Problem

Given an undirected unweighted graph and a starting node, find the shortest distance from the start to every other node.

```
graph = {
    0: [1, 2],
    1: [0, 3, 4],
    2: [0, 5],
    3: [1],
    4: [1],
    5: [2],
}

Starting at 0:
  dist[0] = 0
  dist[1] = 1  (0->1)
  dist[2] = 1  (0->2)
  dist[3] = 2  (0->1->3)
  dist[4] = 2  (0->1->4)
  dist[5] = 2  (0->2->5)
```

**Why can BFS find shortest paths?** Because BFS expands **by level** — every node at level k is exactly k steps from the start. If you encounter a node for the first time at level k, its shortest distance is k — there can't be a shorter path, because BFS has already examined every node reachable in fewer than k steps.

## Core Idea: Distance + Parent

The standard BFS shortest-path template uses three data structures:

```python
from collections import deque

def bfs_shortest_path(graph, start):
    dist = {}          # shortest distance from start to each node
    parent = {}        # predecessor of each node, for path reconstruction
    visited = set([start])

    dist[start] = 0
    parent[start] = None
    q = deque([start])

    while q:
        node = q.popleft()
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                dist[neighbor] = dist[node] + 1   # distance = parent's distance + 1
                parent[neighbor] = node           # record the parent
                q.append(neighbor)

    return dist, parent
```

**The key**: `dist[neighbor] = dist[node] + 1`. The first time a node is visited, the number of steps taken is its shortest. Because BFS always processes smaller distances first, the first encounter is guaranteed to be the closest one.

## Reconstructing the Full Path from parent

With the `parent` dictionary, you can recover the path from start to any node:

```python
def reconstruct_path(parent, start, target):
    path = []
    cur = target
    while cur is not None:       # walk backward from target to start
        path.append(cur)
        cur = parent[cur]
    path.reverse()               # flip: start -> target
    return path

# Continuing the example above
dist, parent = bfs_shortest_path(graph, 0)
print(dist)    # {0: 0, 1: 1, 2: 1, 3: 2, 4: 2, 5: 2}
print(reconstruct_path(parent, 0, 3))  # [0, 1, 3]
print(reconstruct_path(parent, 0, 5))  # [0, 2, 5]
```

## Why BFS Finds the Shortest Path: A Proof

Suppose BFS first encounters node v at level k. We want to prove `dist[v] = k` is the shortest distance:

1. **Existence**: BFS found v at level k, so there really is a path of length k.
2. **Optimality**: suppose there were a shorter path of length k' < k. Then BFS would have processed v's parent at level k', and encountered v at level k'+1. That contradicts "first encountered v at level k."

**That's the correctness guarantee for BFS shortest paths.** It doesn't depend on luck — it follows from the level-by-level structure.

> Contrast with DFS: DFS can also find a path, but not necessarily the shortest. For example 0->2->5 is 2 steps, but DFS might wander 0->1->3->...->5 and take a much longer route.

## WRONG: Incomplete Distance Initialization

```python
# WRONG: only initialize the start; assume dist always has a value
dist = {start: 0}
# ...
for neighbor in graph[node]:
    if neighbor not in visited:
        dist[neighbor] = dist[node] + 1  # KeyError if node isn't in dist
```

In BFS, `node` is always in `dist` (since `dist` and `visited` update together), but a more common mistake is:

```python
# WRONG2: using dist to track visited, but never initializing all nodes
dist = [-1] * len(graph)   # -1 means "not visited"
dist[start] = 0
q = deque([start])
while q:
    node = q.popleft()
    for neighbor in graph[node]:
        if dist[neighbor] == -1:    # use -1 as the unvisited sentinel
            dist[neighbor] = dist[node] + 1
            q.append(neighbor)
```

**Both styles are valid** — the key is **consistency**: either use a `visited` set + `dist` dictionary, or use a `dist` array with a sentinel (like -1) for everything. Mixing the two invites bugs.

## WRONG: Forgetting Unreachable Nodes

```python
# WRONG: assuming every node is reachable
dist, parent = bfs_shortest_path(graph, 0)
print(dist[5])   # KeyError if 5 is unreachable!

# RIGHT: check first
if target in dist:
    print(f"distance: {dist[target]}")
else:
    print("unreachable")

# Or with a dist array + sentinel:
dist = [-1] * n
# ...
if dist[target] == -1:
    print("unreachable")
else:
    print(f"distance: {dist[target]}")
```

**You must handle unreachable nodes.** The graph may not be connected, so BFS only traverses nodes reachable from the start.

## WRONG: Treating an Undirected Graph as Directed

```python
# WRONG: only adding one-way edges
graph = {}
graph[0] = [1, 2]      # 0->1, 0->2
graph[1] = [3, 4]      # but forgot 1->0!
# BFS from 0 reaches 1, but from 1 you can't get back to 0

# RIGHT: add both directions for an undirected graph
graph = {}
graph.setdefault(0, []).append(1)
graph.setdefault(1, []).append(0)   # bidirectional!
```

**An undirected adjacency list needs both edges.** If the problem says "undirected" but you only add one direction, BFS will miss many reachable nodes.

## Full Example: Shortest Path in a Maze

Applying BFS to a 2D grid (a maze problem):

```python
from collections import deque

def maze_shortest_path(grid, start, target):
    """grid is a 2D list, 0=walkable, 1=wall. Find the fewest steps from start to target."""
    n, m = len(grid), len(grid[0])
    visited = [[False] * m for _ in range(n)]
    dist = [[-1] * m for _ in range(n)]

    sx, sy = start
    tx, ty = target

    q = deque([(sx, sy)])
    visited[sx][sy] = True
    dist[sx][sy] = 0

    # four directions
    directions = [(0, 1), (0, -1), (1, 0), (-1, 0)]

    while q:
        x, y = q.popleft()
        if (x, y) == (tx, ty):
            return dist[x][y]          # first arrival is the shortest

        for dx, dy in directions:
            nx, ny = x + dx, y + dy
            if (0 <= nx < n and 0 <= ny < m
                and not visited[nx][ny]
                and grid[nx][ny] == 0):
                visited[nx][ny] = True
                dist[nx][ny] = dist[x][y] + 1
                q.append((nx, ny))

    return -1   # unreachable

# Test
grid = [
    [0, 0, 0, 0],
    [1, 1, 0, 1],
    [0, 0, 0, 0],
    [0, 1, 1, 0],
]
print(maze_shortest_path(grid, (0, 0), (3, 3)))  # 6
```

**The only difference between 2D BFS and graph BFS** is how you compute the neighbors (from "look up in an adjacency list" to "compute four neighbor coordinates"). The core skeleton is identical.

## Complexity

| Metric | Value |
|---|---|
| Time | **O(V + E)** — each node and edge is visited once |
| Space | **O(V)** — visited, dist, and parent are each O(V); queue is O(V) |

For a grid maze: V = n×m, E ≈ 4×V, so time is **O(nm)**.

## Summary

- BFS naturally finds shortest paths in unweighted graphs because "expand by level" = "increase by steps"
- The three-piece template: visited (dedupe), dist (record distance), parent (reconstruct path)
- `dist[neighbor] = dist[node] + 1` is the core recurrence
- The distance when a node is first visited is its shortest distance (see proof above)
- Always handle unreachable cases (return -1 or use a sentinel)
- For undirected graphs, add both directions to the adjacency list
- 2D grid BFS: replace neighbors with four-direction coordinate math; the skeleton stays the same
