# The Dummy Head Node: How It Eliminates the "Delete the Head" Special Case

> The dummy node is the first linked-list technique, and the most important one: it makes the annoying special case of "deleting the head" disappear entirely.

## The Problem: Deleting the Head Always Needs a Special Case

In the previous lesson, our deletion function always started with two lines:

```python
if head is None:
    return head
if head.val == target:
    return head.next
```

That second line is the special case—the head has no predecessor. Any function that might delete the head has to include it. **One more special case means one more place to make a mistake.**

## The Dummy Idea: Invent a Fake Head Out of Thin Air

Place an artificial **dummy head node** in front of the real head so that the real head gets a "predecessor" too.

```
dummy → 1 → 2 → 3 → None
  ↑
dummy.next is the real head
```

```python
dummy = ListNode(0)
dummy.next = head      # hang the real head behind the dummy
prev = dummy           # predecessor starts at the dummy
cur = head
while cur:
    if cur.val == target:
        prev.next = cur.next   # unified handling, including the head
        break
    prev = cur
    cur = cur.next
return dummy.next      # return the real head (may be unchanged, may be deleted)
```

**The key insight**: now it does not matter who you delete—the operation is always `prev.next = cur.next`. When you delete the head, `prev` is the `dummy`, so `dummy.next = head.next`. Perfect.

## Full Code Comparison

Here is a version that uses a dummy and deletes **every** node equal to the target:

```python
def delete_all(head, target):
    dummy = ListNode(0, head)
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        else:
            prev = cur
        cur = cur.next
    return dummy.next

head = build([1, 1, 2, 3, 1])
print(to_list(delete_all(head, 1)))    # [2, 3]
```

Notice this version deletes **all** nodes equal to the target. `prev` only advances when **no deletion happened**—when a node is deleted, the predecessor stays put because the next node still has to be judged by the same predecessor.

## WRONG: Advancing `prev` Every Time When Deleting Multiple Nodes Causes Skipped Deletions

```python
# WRONG
def delete_all(head, target):
    dummy = ListNode(0, head)
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        prev = cur          # advance no matter what
        cur = cur.next
    return dummy.next
```

```text
head=[1,1,2], target=1
Result: [1,2] - the first 1 is gone but the second 1 was skipped.
```

Why: after deleting the first `1`, `prev` should **not** advance (it still has to judge the new next node). **`prev` only advances when no deletion occurred.**

## WRONG: Returning `head` Instead of `dummy.next` After Deleting the Head

```python
# WRONG
def delete_all(head, target):
    dummy = ListNode(0, head)
    prev, cur = dummy, head
    while cur:
        if cur.val == target:
            prev.next = cur.next
        else:
            prev = cur
        cur = cur.next
    return head     # the head might have been deleted!
```

```text
head=[7, 7, 7], target=7
Result: returns [7, 7, 7] - the list still looks full, but dummy.next is now None.
```

Even though the dummy correctly rewired the chain, returning `head` hands the caller a reference to a node that no longer belongs to the list. **Always return `dummy.next`, never the original `head`.**

## The General Value of Dummy

The dummy is not just for deleting the head. Use it whenever a problem "might change the head":

| Scenario | Without dummy | With dummy |
|---|---|---|
| Deleting a node | Special-case the head | No special case |
| Reversing a list | Special-case an empty list | Just write it |
| Merging sorted lists | Handle "one runs out first" | Clean and elegant |

One sentence: **any time you are modifying a list's structure and the head might change, start with `dummy = ListNode(0, head)`.**

## Summary

- A dummy is a fake node hung in front of the real head, giving the real head a predecessor.
- With a dummy, deletion becomes uniformly `prev.next = cur.next`—no special case for the head.
- When deleting multiple nodes, **`prev` only advances when nothing was deleted**, or you will skip nodes.
- Whenever a structural problem might change the head, write the dummy first—it is the universal opening move.
