# Fast & Slow Pointers: Find the Middle, Lay the Groundwork for Cycle Detection

> The two-runner trick is a linked-list specialty. Two pointers leave the same starting line at different speeds, and that single idea unlocks finding the middle, detecting a cycle, and locating the k-th node from the end.

## The Basic Shape of Two-Speed Pointers

One runner moves one step at a time; the other moves two. Here is the canonical form that detects a cycle.

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:        # they met!
            return True
    return False
```

The loop guard `fast and fast.next` is an **iron rule**: because `fast` advances two nodes per turn, you must confirm both that `fast` itself is not `None` and that `fast.next` is not `None`. Otherwise `fast.next.next` blows up.

## Finding the Middle: The Slow Runner Stops Right in the Center

When `fast` reaches the end, `slow` is exactly in the middle.

```python
def find_middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow

print(find_middle(build([1,2,3,4,5])).val)   # 3
print(find_middle(build([1,2,3,4])).val)     # 2  (left middle on even lengths)
```

**Why it works**: when `fast` takes 2 steps and `slow` takes 1, the distance `fast` travels is always exactly twice what `slow` travels. So the moment `fast` has covered the whole list, `slow` has covered exactly half of it.

## WRONG: The Even-Length Middle Is Ambiguous

```python
# WRONG (unclear semantics)
def middle(head):
    slow = fast = head
    while fast.next:        # forgot to check fast itself
        slow = slow.next
        fast = fast.next.next
    return slow
```

```text
Input [1,2]: fast starts at node 1, fast.next is node 2, so we enter the loop.
slow=2, fast=fast.next.next=None.next -> AttributeError: 'NoneType' object has no attribute 'next'
```

And even when the code does not crash, the "middle" of an even-length list is genuinely ambiguous: there is the **left middle** (node `2` in a list of length 4) and the **right middle** (node `3`). The template above yields the **left middle**.

If you need the **right middle**—common in merge sort—start `fast` at `head.next`, or change the loop condition to `while fast and fast.next`.

## Splitting the List at the Middle

Many problems ask you to cut a list into two halves at its midpoint.

```python
def split(head):
    slow = fast = head
    prev = None                      # track the node before slow
    while fast and fast.next:
        prev = slow
        slow = slow.next
        fast = fast.next.next
    prev.next = None                 # sever the link
    return head, slow                # left half, right half

left, right = split(build([1,2,3,4,5]))
print(to_list(left))     # [1, 2, 3]
print(to_list(right))    # [4, 5]
```

`prev` is what lets you actually cut the chain (`prev.next = None`). This is also the split step of merge sort.

## Summary

- Two-speed pointers: `slow` takes 1 step, `fast` takes 2, so `fast` always travels twice as far as `slow`.
- The loop guard must be `while fast and fast.next`; otherwise `fast.next.next` crashes.
- When `fast` finishes, `slow` is at the middle (the left middle on even lengths).
- To split the list you must also maintain `slow`'s predecessor so you can sever the link.
