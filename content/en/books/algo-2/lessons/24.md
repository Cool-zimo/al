# Hash Table Patterns: Two Sum, Counting, Prefix Sum + Hash

> A hash table is one of the skeleton keys of algorithm problems. When you see "lookup," "dedup," "count," or "sum equals K," you should think hash table.

## Pattern 1: Two Sum

**Classic problem**: given an integer array `nums` and a target value `target`, find two numbers that add up to `target` and return their indices.

Brute force: nested loops, O(n²).

```python
# WRONG: O(n²) brute force
def two_sum_brute(nums, target):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
```

**Optimize to O(n) with a hash table**: as you scan, store the numbers you've already seen in a hash table. For each `nums[i]`, compute `need = target - nums[i]` and check whether `need` is in the table.

```python
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:           # O(1) lookup
            return [seen[need], i]
        seen[num] = i              # record the current number and its index
    return []

print(two_sum([2, 7, 11, 15], 9))   # [0, 1]  because 2+7=9
print(two_sum([3, 2, 4], 6))        # [1, 2]  because 2+4=6
```

**Why O(n)?** One pass through the array, each hash-table lookup is O(1), total O(n).

**Core idea: use a hash table to turn the O(n) question of "where is the other number?" into O(1).**

## Pattern 2: Counting (Counter / Frequency)

**Problem**: count how many times each element appears in a list.

```python
from collections import Counter

nums = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
c = Counter(nums)
print(c)            # Counter({4: 4, 3: 3, 2: 2, 1: 1})
print(c[3])         # 3
print(c[999])       # 0, missing keys return 0 (no KeyError!)
```

**Three common Counter operations:**

```python
c = Counter("abracadabra")

# 1. most_common(k): the k most frequent elements
print(c.most_common(2))   # [('a', 5), ('b', 2)]

# 2. arithmetic: Counters can be added and subtracted
c1 = Counter("hello")
c2 = Counter("world")
print(c1 + c2)   # Counter({'l': 3, 'o': 2, 'h': 1, 'e': 1, 'w': 1, 'r': 1, 'd': 1})

# 3. elements(): expand into an iterator
print(list(c.elements()))  # ['a', 'a', 'a', 'a', 'a', 'b', 'b', 'r', 'r', 'c', 'd']
```

## WRONG: Misusing Counter's "Returns 0" Behavior

```python
c = Counter([1, 2, 3])
print(c[999])   # 0, no error

# WRONG: thinking c[key] raises KeyError on miss, writing a redundant check
if 999 in c:
    print(c[999])
else:
    print("not found")
# Just print(c[999]) - it returns 0 by default

# But note: this does NOT actually add the key to the Counter
print(len(c))   # 3, 999 is not in there
print(list(c.keys()))  # [1, 2, 3]
```

**This "returns 0" behavior cuts both ways:**

```python
# Good: you don't need to check existence before counting
c = Counter()
for x in data:
    c[x] += 1   # no need for "if x in c: c[x] += 1 else: c[x] = 1"

# Bad: it can hide logic bugs
c = Counter([1, 2, 3])
total = sum(c.values())  # 3, correct

# But if you mistakenly assume 999 was recorded:
all_keys = list(c.keys()) + [999]
total = sum(c[k] for k in all_keys)  # 3 + 0 = 3, a 0 sneaks in
```

**If you need to distinguish "value is 0" from "key doesn't exist," use `c.get(key, 0)` together with `in`.**

## Pattern 3: Prefix Sum + Hash (Subarray Sum Equals K)

**Problem**: given an integer array `nums` and an integer `k`, count the number of **contiguous subarrays whose sum equals k**.

For example `nums = [1, 1, 1]`, `k = 2`, answer is 2 (the subarray `[1,1]` appears twice).

Brute force: enumerate every start and end, O(n²).

**Optimize to O(n) with prefix sum + hash table:**

```python
def subarray_sum(nums, k):
    prefix_count = {0: 1}  # KEY! prefix sum 0 has appeared once
    prefix_sum = 0
    count = 0
    
    for num in nums:
        prefix_sum += num                    # current prefix sum
        need = prefix_sum - k                # the prefix sum we need to find
        if need in prefix_count:
            count += prefix_count[need]      # how many such prefixes exist
        prefix_count[prefix_sum] = prefix_count.get(prefix_sum, 0) + 1
    
    return count

print(subarray_sum([1, 1, 1], 2))       # 2
print(subarray_sum([1, 2, 3], 3))       # 2  -> [1,2] and [3]
print(subarray_sum([1, -1, 1, -1, 1], 0))  # 6
```

**Why this works:**

```
Prefix sum definition: pref[i] = nums[0] + nums[1] + ... + nums[i-1]

Sum of subarray nums[j..i-1] = pref[i] - pref[j]

If pref[i] - pref[j] = k,
then pref[j] = pref[i] - k

So for each position i, we only need to know how many j's before it satisfy pref[j] = pref[i] - k.
```

```
nums = [1, 1, 1], k = 2

i=0: pref=1,  need=1-2=-1,  count=0,  prefix_count={0:1, 1:1}
i=1: pref=2,  need=2-2=0,   count+=1 (one prefix sum equals 0), prefix_count={0:1, 1:1, 2:1}
i=2: pref=3,  need=3-2=1,   count+=1 (one prefix sum equals 1), prefix_count={0:1, 1:1, 2:1, 3:1}

answer = 2
```

## WRONG: Prefix Sum + Hash Forgets to Initialize {0: 1}

```python
# WRONG: forget to initialize prefix_count = {0: 1}
def subarray_sum_wrong(nums, k):
    prefix_count = {}   # empty!
    prefix_sum = 0
    count = 0
    for num in nums:
        prefix_sum += num
        need = prefix_sum - k
        if need in prefix_count:
            count += prefix_count[need]
        prefix_count[prefix_sum] = prefix_count.get(prefix_sum, 0) + 1
    return count

print(subarray_sum_wrong([1, 1, 1], 2))  # 2? or 1?
```

Let's trace it:

```
nums = [1, 1, 1], k = 2

i=0: pref=1,  need=-1,  count=0,  prefix_count={1:1}
i=1: pref=2,  need=0,   0 is NOT in prefix_count! count=0,  prefix_count={1:1, 2:1}
i=2: pref=3,  need=1,   count+=1 (one prefix sum equals 1), prefix_count={1:1, 2:1, 3:1}

answer = 1  <- WRONG! The correct answer is 2
```

**Why did we lose one?** Because when `pref[i] == k` (the prefix sum itself equals k), `need = pref[i] - k = 0`, and we need "prefix sum 0 has appeared once." But the empty `prefix_count` has no `0: 1`!

```python
# RIGHT: always initialize {0: 1}
prefix_count = {0: 1}  # represents "before the array starts, prefix sum 0 has appeared once"

# So when pref[i] = k:
# need = k - k = 0
# prefix_count[0] = 1 -> count += 1  ✓
```

**This is the must-memorize template for prefix sum + hash: initialize `prefix_count = {0: 1}`.**

## WRONG: Two Sum Edge Cases

```python
# WRONG: doesn't account for target = 2 * nums[i]
def two_sum_wrong(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:
            return [seen[need], i]
        seen[num] = i
    return []

print(two_sum_wrong([3, 2, 4], 6))  # [1, 2]? Correct!
```

Wait, let's trace this example carefully:

```python
nums = [3, 2, 4], target = 6

i=0: num=3, need=3, 3 not in seen, seen={3:0}
i=1: num=2, need=4, 4 not in seen, seen={3:0, 2:1}
i=2: num=4, need=2, 2 in seen! return [1, 2]  ✓ correct!
```

**The trace above was actually fine. The real bug appears with a different ordering:**

```python
nums = [3, 3], target = 6

i=0: num=3, need=3, 3 not in seen, seen={3:0}
i=1: num=3, need=3, 3 in seen! return [0, 1]  ✓ correct!
```

**The genuinely broken version: insert before you check**

```python
# WRONG: insert into seen first, THEN check need -> you match the current element itself
def two_sum_wrong(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        seen[num] = i          # insert first
        if need in seen:       # then check -> might find YOURSELF!
            return [seen[need], i]
    return []

print(two_sum_wrong([3, 3], 6))  # [0, 0]? Matched itself!

# i=0: need=3, seen={3:0}, 3 in seen -> return [0, 0] WRONG!
```

**Lesson: always check first, then insert.**

```python
def two_sum(nums, target):
    seen = {}
    for i, num in enumerate(nums):
        need = target - num
        if need in seen:       # check first (the current element isn't in the table yet)
            return [seen[need], i]
        seen[num] = i          # insert after
```

## Summary of the Three Patterns

| Pattern | Core Idea | What the Hash Table Stores | Time |
|---|---|---|---|
| Two Sum | Turn "find the other number" into an O(1) lookup | value -> index | O(n) |
| Counting | Frequency stats, Counter does it in one line | value -> count | O(n) |
| Prefix Sum + Hash | Turn "find subarray sum" into "find prefix sum" | prefix_sum -> count | O(n) |

**Recognition cues:**
- "Two numbers sum to X" -> hash table of seen elements
- "Count occurrences" -> Counter
- "Subarray/substring sum/product equals K" -> prefix sum + hash

## Summary

- Two Sum: hash table stores `{value: index}`, compute `target - num` while scanning
- Counting: use `collections.Counter`, which has `most_common()`, `elements()`, and arithmetic built in
- Prefix Sum + Hash: `prefix_count[pref[i] - k]` counts subarrays summing to k
- Prefix Sum MUST initialize `prefix_count = {0: 1}`, otherwise the `pref[i] == k` case is missed
- Two Sum must check before inserting, otherwise you match the same element twice
- Counter returns 0 instead of raising for missing keys — convenient, but it can also hide bugs
