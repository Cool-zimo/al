# What a Stack Is: Last In, First Out, and Why Python's List Already Is One

> The stack is the simplest data structure in this book, and the most underrated. Parenthesis matching, undo, function calls, and expression evaluation all depend on it.

## Stacks in Everyday Life

A stack of plates, where you can only take from the top. A browser's back button, which returns you to the page you visited most recently. The undo command in an editor, which reverses the **last** action. Their common rule: **the last thing added is the first thing removed**. That rule is called **LIFO (Last In, First Out)**.

The opposite is a queue, which is **FIFO (First In, First Out)**—think of a line at a coffee shop, where the first person in line is the first to be served.

> One-line distinction: a stack is a stack of plates; a queue is a line.

## The Three Stack Operations

A stack needs exactly three actions:

| Operation | Meaning | Python |
|---|---|---|
| push | push an element onto the top | `s.append(x)` |
| pop | remove and return the top element | `s.pop()` |
| top / peek | look at the top without removing it | `s[-1]` |

Two auxiliary checks: `len(s) == 0` tests whether the stack is empty, and `len(s)` tells you how many elements it holds.

```python
s = []
s.append('A')      # stack: ['A']
s.append('B')      # stack: ['A', 'B']
s.append('C')      # stack: ['A', 'B', 'C']
s.pop()            # removes 'C', stack becomes ['A', 'B']
print(s[-1])       # peek at the top, which is 'B'; the stack is unchanged
```

## The Core Conclusion: Python's List Already Is a Stack

You do not need to write a `Stack` class. Appending to and popping from the end of a Python `list` are both **O(1)**, so a list already behaves as a stack.

Why O(1)? CPython's `list` is a **dynamic array**: a contiguous block of memory with spare capacity reserved at the end. As long as that capacity is not exceeded, `append` writes one value at a known address and increments the length; `pop()` decrements the length. Neither operation moves the other elements.

```python
stack = []
for i in range(5):
    stack.append(i)          # push
print(stack)                 # [0, 1, 2, 3, 4]
while stack:
    print(stack.pop(), end=' ')   # 4 3 2 1 0  <- last in, first out
```

Output: `4 3 2 1 0`. Notice the reversal—this is the stack's defining feature, and it is the answer to "why did my output come out backwards?" the first time you debug one.

## Time Complexity

| Operation | Time | Note |
|---|---|---|
| `append(x)` (push) | O(1) amortized | Rarely triggers a resize; still O(1) amortized |
| `pop()` (no argument) | O(1) | Decrements length only, no data movement |
| `s[-1]` (peek) | O(1) | Index access |
| `s.pop(0)` | **O(n)** | Pops from the front and shifts n-1 elements |

> **The key warning**: only `append` and `pop` **without an argument** are O(1). `pop(0)` pops from the front in O(n). This is the easiest trap in the lesson.

## # WRONG 1 — `pop(0)` Turns O(1) Into O(n)

```python
# WRONG
stack = [1, 2, 3]
stack.pop(0)    # intended to "pop the first element", returns 1, stack becomes [2, 3]
                # but internally every remaining element was shifted left by one
```

This has two errors at once: the semantic error (it removed the oldest element, which is queue behavior, not stack behavior) and the performance error (O(n)). To pop from a stack, always use plain `pop()`.

## # WRONG 2 — Popping From an Empty Stack Raises Immediately

```python
# WRONG
s = []
s.pop()          # IndexError: pop from empty list
s[-1]            # IndexError: list index out of range
```

Every `pop` and every peek must first check that the stack is non-empty. Writing `while stack:` reads better than `while len(stack) > 0:`.

## Is `collections.deque` Faster?

`deque`'s `append` and `pop` are also O(1), but it is implemented as a **doubly linked list of blocks**, so its memory is not contiguous. In practice, for a pure stack (operations only at one end), `list` is **faster** than `deque` because contiguous memory has better cache locality.

The real advantage of `deque` is that **both ends support O(1)** operations, such as `popleft()` for a queue. So the rule is simple:

> **Use a `list` for a stack. Use a `deque` when you need O(1) pops from the left.**

## A Cleaner Wrapper Class

If you want code that reads more obviously as a stack, wrap the list:

```python
class Stack:
    def __init__(self):
        self._d = []
    def push(self, x):
        self._d.append(x)
    def pop(self):
        if not self._d:
            raise IndexError("pop from empty stack")
        return self._d.pop()
    def peek(self):
        if not self._d:
            raise IndexError("peek from empty stack")
        return self._d[-1]
    def __bool__(self):
        return bool(self._d)
    def __len__(self):
        return len(self._d)

s = Stack()
s.push(1); s.push(2)
print(s.pop())    # 2
print(len(s))     # 1
```

The value of this wrapper is that **empty-stack handling lives in one place** instead of being scattered through the caller. Both interviews and production code prefer this style.

## What Stacks Are Actually Good For

A stack shines on problems of **"nearest neighbor"**: the current element only cares about the element nearest to it. Typical cases:

- **Balanced parentheses**: a closing `)` needs the nearest unmatched `(`.
- **Next greater element**: each number wants the first number to its right that is larger.
- **Undo / backtracking**: Ctrl+Z reverses the most recent action.
- **Expression evaluation**: the innermost parentheses are solved first.
- **Recursion**: function calls themselves use a stack.

The next four lessons cover exactly these scenarios.

## Why Reversal Comes for Free

A stack reverses a sequence as a side effect. Push every element of a list and then pop them all, and the result is the original list backwards. This is not a separate algorithm—it is just what happens when you defer output until after the whole input has arrived. Many problems that look like "reverse something" are really asking you to exploit this property.

## Summary

- A stack is LIFO; its only core operations are push, pop, and peek.
- A Python `list` already is a stack: `append` is push, parameterless `pop()` is pop, both O(1).
- O(1) comes from contiguous memory plus reserved capacity; neither `append` nor `pop` moves elements.
- Never use `pop(0)` for stack behavior—it is queue semantics and O(n) cost.
- `pop()` and `[-1]` raise `IndexError` on an empty stack; always check first.
- Pure stack → `list`. Both ends in O(1) → `deque`.
- The stack's real strength is handling "nearest neighbor" problems.
