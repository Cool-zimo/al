# Reversing a Linked List: The Iterative Version (Three Pointers), Frame by Frame

> Reversing a linked list is the #1 interview question. This lesson hand-runs the `prev` / `cur` / `nxt` three-pointer approach frame by frame, laying out every arrow change in plain sight.

## The Problem: Flip the List

Given `1 → 2 → 3 → None`, turn it into `3 → 2 → 1 → None`.

```python
head = build([1, 2, 3])
# Goal: 3 → 2 → 1 → None
```

Intuition: starting at the front, make each node's `next` point at the node before it.

## The Three Pointers: `prev` / `cur` / `nxt`

We only rewrite one arrow per step, so we must save "the next node" first—otherwise the chain breaks the moment we reassign.

```python
def reverse_list(head):
    prev = None          # after reversal, the old head becomes the tail and points at None
    cur = head
    while cur:
        nxt = cur.next    # ① save the successor, or we lose it
        cur.next = prev   # ② reverse the current arrow
        prev = cur        # ③ advance prev
        cur = nxt         # ④ advance cur
    return prev           # when the loop ends, cur is None and prev is the new head
```

## Frame-by-Frame Walkthrough

Input `1 → 2 → 3 → None`, starting state `prev=None, cur=1`.

```
Frame 1: nxt=2; 1.next=None; prev=1; cur=2
         List: 1→None, 2→3→None
Frame 2: nxt=3; 2.next=1;  prev=2; cur=3
         List: 2→1→None, 3→None
Frame 3: nxt=None; 3.next=2; prev=3; cur=None
         List: 3→2→1→None
Loop ends, return prev=3
```

Each frame does exactly one thing: bend `cur.next` back toward `prev`, then slide all three pointers one step to the right.

## WRONG: Skip Saving `nxt` and You Lose the Next Node

```python
# WRONG
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        cur.next = prev    # reassigned immediately, successor not saved
        prev = cur
        cur = cur.next     # cur.next was just set to prev - same node! infinite loop
    return prev
```

```text
Result: infinite loop.
cur.next was changed to point at prev (the node from the previous step),
so cur = cur.next walks backward; the chain ties itself into a cycle and never exits.
```

**Lesson: whenever you are about to rewrite `cur.next`, the line before it is always `nxt = cur.next`.** This is an iron law of linked-list problems.

## WRONG: Reassigning in the Wrong Order Corrupts the Chain

```python
# WRONG
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        prev = cur         # advance prev first
        cur = cur.next     # now cur moved forward...
        prev.next = cur    # ...so prev.next is set to the node AFTER cur, not to prev's old self!
        nxt = cur
    return prev
```

```text
Trace on 1→2→3→None:
prev=1, cur=2, then prev.next = cur → 1.next = 2 (no change yet)
prev=2, cur=3, then prev.next = cur → 2.next = 3 (still the original arrow!)
The list is never reversed; depending on the exact variant this can also drop the last node.
```

The four assignments form a fixed sequence—save the successor, reverse the arrow, advance the predecessor, advance the cursor. **Change the order and the chain is either left unchanged or torn apart.** The safe skeleton is always: `nxt = cur.next` → `cur.next = prev` → `prev = cur` → `cur = nxt`.

## Verification: Convert Back to a List and Compare

```python
head = build([1, 2, 3, 4, 5])
new_head = reverse_list(head)
print(to_list(new_head))    # [5, 4, 3, 2, 1]
```

After reversal, the old tail becomes the head and the old head becomes the tail (pointing at `None`).

## Summary

- Reversing a list = making each node's `next` point at its predecessor.
- Three pointers `prev` / `cur` / `nxt`: each frame saves `nxt` before touching any arrow.
- Failing to save `nxt` before rewriting `next` ties the list into a cycle and loops forever.
- When the loop ends, `cur` is `None` and `prev` is the new head.
