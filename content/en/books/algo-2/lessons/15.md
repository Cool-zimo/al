# Applied: Expression Evaluation and a Calculator

> Given the infix expression `"3 + 5 * (2 - 4)"`, how do you compute the result? This is a comprehensive use of stacks — two stacks (an operand stack plus an operator stack), where operator precedence decides "who goes first".

## Why a Calculator Needs Stacks

We humans are used to writing **infix** (operator between operands, like `3 + 5 * 2`), but a computer needs to know "which part to compute first". This is essentially a **nearest-match** problem — `(` waits for `)` to "settle" what is inside it, and a stack is exactly the tool for that.

> infix expression -> with stacks -> evaluate correctly by precedence.

## Operator Precedence

First define a precedence table:

```python
precedence = {'+': 1, '-': 1, '*': 2, '/': 2}
```

`*` and `/` have precedence 2, `+` and `-` have 1. **Higher precedence goes first**. At the same level, go left to right (left-associative).

## The Two-Stack Idea

| Stack | What it stores |
|---|---|
| `vals` | operands (numbers) |
| `ops` | operators |

The rule in one sentence: **if the new operator's precedence is <= the precedence of the operator on top of the stack, finish the top operation first, then push the new operator.** Parentheses are the exception — `(` gets pushed, `)` keeps computing until `(`.

```python
def eval_expr(s):
    precedence = {'+': 1, '-': 1, '*': 2, '/': 2}
    vals, ops = [], []
    i = 0
    while i < len(s):
        c = s[i]
        if c == ' ':                    # skip spaces
            i += 1; continue
        if c.isdigit():                 # multi-digit numbers must be read in full
            num = 0
            while i < len(s) and s[i].isdigit():
                num = num * 10 + int(s[i]); i += 1
            vals.append(num); continue
        if c == '(':
            ops.append(c)
        elif c == ')':                  # compute all the way to '('
            while ops[-1] != '(':
                _apply(vals, ops.pop())
            ops.pop()                   # throw away '('
        else:                           # operator + - * /
            while ops and ops[-1] != '(' and precedence[ops[-1]] >= precedence[c]:
                _apply(vals, ops.pop())
            ops.append(c)
        i += 1
    while ops:                          # after scanning, finish remaining operators
        _apply(vals, ops.pop())
    return vals[0]

def _apply(vals, op):
    b = vals.pop(); a = vals.pop()      # note the order: first out is the right operand
    if op == '+': vals.append(a + b)
    elif op == '-': vals.append(a - b)
    elif op == '*': vals.append(a * b)
    elif op == '/': vals.append(int(a / b))   # truncate toward zero
```

`_apply` is where the actual computation happens: pop two numbers, pop one operator, push the result back onto the operand stack.

## Hand Trace of `3 + 5 * 2`

```
read 3       -> vals=[3]
read +       -> ops empty, push        ops=['+']
read 5       -> vals=[3,5]
read *       -> top '+' precedence 1 < 2, no pop, push  ops=['+','*']
read 2       -> vals=[3,5,2]
scan done    -> pop '*': 5*2=10 -> vals=[3,10]
              pop '+': 3+10=13 -> vals=[13]
return 13 ✓
```

Note: **`*` is not popped** because it has higher precedence and must "go first". This is the stack-form expression of "higher precedence goes first".

## Hand Trace of `3 * (5 + 2)`

```
read 3       -> vals=[3]
read *       -> ops=['*']
read (       -> ops=['*','(']
read 5       -> vals=[3,5]
read +       -> top is '(' so do not pop (wait for the matching right paren) ops=['*','(','+']
read 2       -> vals=[3,5,2]
read )       -> compute to '(': pop '+' -> 5+2=7 -> vals=[3,7], pop '('
scan done    -> pop '*': 3*7=21 -> vals=[21]
return 21 ✓
```

`(` works by **isolating precedence** — it "seals off" a whole subexpression and waits for `)` to settle it.

## Crash Scene: Multi-Digit Numbers Read Only the First Digit

```python
# WRONG
for c in s:
    if c.isdigit():
        vals.append(int(c))    # "42" would be read as two numbers, 4 and 2
```

For input `42 + 1`, you would get three operands `4 2 1`, and the result becomes `4+2+1=7`. **You must use a while loop to read the whole run of digits**: `num = num*10 + int(c)`. This is the most common mistake when writing a calculator.

## Crash Scene: `a` and `b` Are Swapped in `_apply`

```python
# WRONG
def _apply(vals, op):
    a = vals.pop(); b = vals.pop()   # first out is the right operand!
    vals.append(a - b)              # 8-3 computed as 3-8=-5
```

A stack is LIFO. The left operand `a` went in first, `b` went in later. So the pop order must be `b = pop(); a = pop()`. **Swap subtraction or division and the answer is wrong**, and because it is all numeric Python raises no error — a very sneaky bug.

## Crash Scene: Division Truncation Done Wrong

```python
vals.append(a / b)          # floating point, 3/2=1.5
vals.append(a // b)         # Python's // floors toward negative infinity: -3//2=-2, not toward zero!
```

Calculator division (e.g. LeetCode 227 Basic Calculator) usually requires **truncation toward zero**. `int(a/b)` does exactly that in Python (because `/` returns a float and `int()` simply chops off the fractional part). **Do not use `//`** — it disagrees with mathematical "truncate toward zero" for negatives.

## Crash Scene: Forgetting to Drain `ops` After Scanning

```python
# WRONG: return vals[0] immediately after the loop ends
while i < len(s):
    ...
return vals[0]          # ops may still hold operators that were never evaluated
```

For input `3 + 4`, when the loop ends `ops=['+']` is still there, `vals=[3,4]`, and returning `vals[0]` gives `3`. **After scanning finishes you must do `while ops: apply(pop())`** to evaluate every remaining operator.

## Advanced: Infix to Postfix (Reverse Polish)

If you want to convert first and compute after, the idea is different (output queue plus operator stack). The result looks like:

```
infix:   3 + 5 * 2
postfix: 3 5 2 * +        <- no parentheses; when you see an operator, pop two and compute

infix:   (3 + 5) * 2
postfix: 3 5 + 2 *
```

The nice thing about postfix is that **evaluating it needs only one stack** and no precedence checks: scan left to right, push numbers, and when you see an operator pop two, compute, and push the result back. This is the internal intermediate representation used by many compilers and calculators.

## Complexity

| Metric | Value |
|---|---|
| Time | O(n) — each character is pushed and popped at most once |
| Space | O(n) — the stack may fill up in the worst case |

## Summary

- Calculator = operand stack + operator stack, with precedence deciding evaluation order
- New operator with precedence <= top -> finish the top operation first
- `(` pushes, `)` computes to `(`; parentheses isolate precedence
- Multi-digit numbers need a while loop to read continuously, not just one digit
- `_apply` pop order: `b=pop(); a=pop()`; subtraction and division must not be swapped
- Division uses `int(a/b)` to truncate toward zero, not `//`
- After scanning finishes, all operators left in ops must be evaluated
