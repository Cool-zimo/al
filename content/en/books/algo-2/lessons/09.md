# Removing the N-th Node From the End

> Unlike an array, a linked list has no backward index. To delete the N-th node from the end in one pass, make two pointers keep a constant gap of N between them.

## The Problem

Given a linked list, delete the **N-th node from the end** and return the new head.

```
input:  head = 1 -> 2 -> 3 -> 4 -> 5, n = 2
output: 1 -> 2 -> 3 -> 5
```

So the deleted node is `4`.

The obvious approach: traverse once to compute the length `L`, then walk `L - n` steps to find the **predecessor** of the node to delete. That is two passes. The problem—and the interview answer—calls for **one pass**.

## The Idea: Keep the Two Pointers N + 1 Apart

Core idea: **let the fast pointer get N steps ahead of the slow pointer, then advance both together; when fast hits the end, slow is parked right before the node to delete.**

Why "right before"? Because a linked list can only modify `prev.next`, so we need to locate the predecessor.

```python
def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)      # sentinel; handles deleting the head
    fast = slow = dummy

    # fast takes n+1 steps (not n!)
    for _ in range(n + 1):
        fast = fast.next

    # advance together until fast is None
    while fast:
        fast = fast.next
        slow = slow.next

    # slow is now the predecessor
    slow.next = slow.next.next
    return dummy.next
```

**Key point: fast takes `n + 1` steps, not `n`.**

- `n` steps → fast stops on the node to delete → slow is one short.
- `n + 1` steps → fast is one node past the deletion target → slow lands on the predecessor.

A concrete example with `n = 2`:

```
1 -> 2 -> 3 -> 4 -> 5
^fast (0 steps, at dummy)

after fast moves 3 steps (n+1 = 3):
dummy -> 1 -> 2 -> 3 -> 4 -> 5
                  ^fast (node 3)

slow is still at dummy. Move both until fast is None:
dummy -> 1 -> 2 -> 3 -> 4 -> 5
          ^slow (node 2, the predecessor of node 3)

slow.next = slow.next.next   # skip node 3
```

## Why the Dummy Is Mandatory

Without a dummy, the code looks like this:

```python
# version without a dummy
fast = slow = head
for _ in range(n):
    fast = fast.next
while fast.next:
    fast = fast.next
    slow = slow.next
slow.next = slow.next.next
return head
```

**When `n == len(list)`, the node to delete is the head itself.** At that moment `slow` is still `head`, and `slow.next = slow.next.next` modifies the second node. The head never moves, so returning `head` gives you the original list—the answer is wrong.

The dummy gives every node, including the original head, a predecessor. Deleting the head becomes `dummy.next = head.next`, which is the same code path as every other case.

## Frame-by-Frame Walkthrough

```
list: dummy -> 1 -> 2 -> 3 -> 4 -> 5, n = 2

phase 1: fast moves n+1 = 3 steps
  fast=1 -> fast=2 -> fast=3
  slow is still at dummy

phase 2: move both
  fast=4,  slow=1
  fast=5,  slow=2
  fast=None (loop exits)
  slow stops at node 2, the predecessor of node 3

phase 3: delete
  slow.next = slow.next.next   # 2 -> 4, node 3 is skipped
return dummy.next: 1 -> 2 -> 4 -> 5
```

Now run the edge case `[1]`, `n = 1`:

```
dummy -> 1
fast takes 2 steps: fast=1, then fast=None (the second step goes out of bounds)
while fast: does not run; slow stays at dummy
slow.next = slow.next.next   # dummy.next = dummy.next.next = None
returns None  ✓
```

## Complexity

- Time O(L): one traversal.
- Space O(1): two pointers.

## # WRONG 1 — fast Advances Only N Steps

```python
# WRONG
def remove_nth_bad(head, n):
    dummy = ListNode(0, head)
    fast = slow = dummy
    for _ in range(n):           # should be n+1
        fast = fast.next
    while fast:
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return dummy.next
```

Effect: slow lands on the **predecessor's predecessor** and you skip one extra node. With `[1,2,3,4,5]` and `n=2`, the target is `4` but the code deletes `3`.

```
actual output:   1 -> 2 -> 4 -> 5   (expected 1 -> 2 -> 3 -> 5)
                                 deleted the wrong node
```

This is the classic off-by-one. Remember the rule: **fast takes n+1 steps so that slow lands on the predecessor.**

## # WRONG 2 — No Dummy, Crashes When Deleting the Head

```python
# WRONG
def remove_nth_no_dummy(head, n):
    fast = slow = head
    for _ in range(n):
        fast = fast.next
    while fast.next:        # when fast is None this raises AttributeError
        fast = fast.next
        slow = slow.next
    slow.next = slow.next.next
    return head
```

Two independent failures:

1. **When `n == len(list)`** (deleting the head), the `for` loop drives `fast` to `None`, and the next `while fast.next` raises `AttributeError: 'NoneType' object has no attribute 'next'`.
2. Even if it did not crash, **the head can never be deleted**—`slow` sits on `head`, so it mutates `head.next`.

```
input:  [1, 2], n = 2
expect: [2]
actual: AttributeError
```

Just add the dummy and the problem disappears.

## A Useful Generalization

This same gap technique answers a family of questions:

| Question | Gap | Stop condition |
|---|---|---|
| Delete N-th from end | fast leads by `n+1` | fast is `None` |
| Find N-th from end | fast leads by `n` | fast is `None` |
| Find middle | speed ratio 2:1 | fast is `None` |
| Detect cycle | speed ratio 2:1 | pointers meet |

They are all the same idea in different clothing. Once you internalize "maintain a fixed gap," the variations are mechanical.

## Summary

- Two pointers: fast leads by `n+1`, then both advance—**one pass lands on the predecessor**.
- It is `n+1`, not `n`: that extra step puts slow on the node *before* the deletion target.
- **A dummy node** makes deleting the head identical to deleting a middle node, and prevents `None.next` crashes.
- Time O(L), space O(1).
- Finding the N-th from end, the middle, and cycle detection are all variants of the same two-pointer pattern.

## Chapter Quiz

```quiz

exam: true
q: When removing the N-th node from the end with two pointers, why must the fast pointer move N+1 steps instead of N?
options:
- Because Python's range starts at 0, and the extra step is just customary
- The extra step makes the slow pointer stop on the predecessor of the node to delete, so prev.next = prev.next.next works
- Fast must traverse the whole list, and N+1 prevents it from stopping early
- N+1 is used to skip over the dummy node itself
answer: 1
explain: Linked-list deletion modifies the predecessor's next pointer. If fast moves N steps it stops on the node to delete and slow stops one place short of the predecessor; N+1 lets fast get one node past the target so slow lands exactly on the predecessor. This offset is the standard setting for any "N-th from end" two-pointer solution.
```
