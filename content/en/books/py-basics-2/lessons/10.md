# The Family Resemblance: list, tuple, and str Are Sequences

> The last four lessons covered lists, tuples, and strings separately. You have probably noticed they feel **very alike** — all can be indexed, sliced, and measured for length.
>
> This lesson brings them together: all three are kinds of **sequence**, and they share a common set of operations. Learn that common core and you have learned three things at once.

## 1. What is a "sequence"?

Python abstracts "an ordered row of elements" into a concept called a **sequence**. Lists, tuples, and strings are concrete types of sequence.

To tell whether something is a sequence, check whether it supports these operations: fetching by index, slicing, asking for its length, and testing membership.

```python
a = [10, 20, 30]          # list
b = (10, 20, 30)          # tuple
c = "102030"              # string
```

Every operation in the next section works on **all three**.

## 2. Six things they share

### 1. Fetching by index `[i]`

```python
print([10, 20, 30][0])        # 10
print((10, 20, 30)[1])        # 20
print("hello"[4])             # o
```

All start at 0, and all support negative indexes (-1 is the last).

### 2. Slicing `[start:stop]`

```python
print([10, 20, 30, 40][1:3])      # [20, 30]
print((10, 20, 30, 40)[1:3])      # (20, 30)
print("hello world"[6:])          # world
```

The half-open rule is identical for all three. Note: **the type of a slice matches the type you sliced** — a list slice is a list, a tuple slice is a tuple, and a string slice is a string.

### 3. Length `len()`

```python
print(len([10, 20, 30]))      # 3
print(len((1, 2)))            # 2
print(len("London"))          # 6
```

`len` is a **function**, not a method, so it is always written `len(x)` and never `x.len()`.

### 4. Membership `in`

```python
print(20 in [10, 20, 30])         # True
print("Lo" in "London")           # True
print(5 in (1, 2, 3))             # False
```

⚠️ **Crash: `in` on a string tests for a substring.**

```python
print("cd" in "abcdef")       # True — the substring exists
```

A string's `in` asks "does this substring occur", not "is this single character present". That differs subtly from checking for an element in a list, so do not conflate the two.

### 5. Concatenation `+`

```python
print([1, 2] + [3, 4])        # [1, 2, 3, 4]
print((1, 2) + (3, 4))        # (1, 2, 3, 4)
print("ab" + "cd")            # abcd
```

**The types must match:** a list can only concatenate with a list, never with a tuple or a string.

```python
[1, 2] + (3, 4)          # WRONG  TypeError: can only concatenate list to list
"1" + 2                  # WRONG  TypeError: can only concatenate str to str
```

To concatenate different types, convert them to the same type first:

```python
[1, 2] + list((3, 4))    # [1, 2, 3, 4]
str(1) + "2"             # "12"
```

### 6. Repetition `*`

```python
print([0] * 4)           # [0, 0, 0, 0]
print("ab" * 3)          # ababab
print((1, 2) * 2)        # (1, 2, 1, 2)
```

`*` repeats a sequence several times. **Caveat:** when a list is repeated, the elements are **the same object referenced repeatedly**, which can bite when the elements are mutable:

```python
rows = [[]] * 3
rows[0].append(1)
print(rows)              # [[1], [1], [1]] — all three sublists are the same object!
```

All three `[]` are the same list object, so changing one changes all of them. To build genuinely independent rows, use a list comprehension:

```python
rows = [[] for _ in range(3)]
rows[0].append(1)
print(rows)              # [[1], [], []]
```

⚠️ **Crash: building a 2D list with `[[]] * n`.**

This is a classic Python trap. The comprehension `[[] for _ in range(n)]` builds a fresh `[]` on every iteration, which is what you actually wanted.

## 3. How to choose among the three

Now that the common ground is clear, the **differences** are what decide "which one".

| Property | list | tuple | str |
|---|---|---|---|
| Mutable? | Yes | No | No |
| What it stores | similar or mixed items | distinct fields | characters |
| Has `append`? | Yes | No | No |
| Usable as a dict key? | No | Yes | Yes |
| Literal | `[ ]` | `( )` | `" "` |

A decision flow:

1. **Is it character text?** → use `str`
2. **Does the data need to change?** → use `list`
3. **Is it fixed fields that must not change, possibly used as a key?** → use `tuple`
4. **Not sure?** → default to `list`, the most flexible option

Three realistic scenarios:

```python
# scenario 1: a shopping basket, items added and removed constantly
cart = ["apples", "milk", "bread"]      # list

# scenario 2: one coordinate record, fixed after creation
point = (51.5074, -0.1278)             # tuple

# scenario 3: a sentence
greeting = "Welcome to the shop"        # str
```

One especially common combination — a list holding tuples — gives you both flexibility and structure:

```python
# a class score sheet: each student is a (name, score) tuple, and the whole is a mutable list
students = [("Alice", 92), ("Bob", 78), ("Carol", 100)]
students.append(("Dave", 85))
print(students[0][1])      # 92
```

The outer `list` handles "add and remove", while the inner `tuple` keeps "the shape of each record fixed". This is an extremely common and idiomatic way to organise data in Python.

## Summary

- Lists, tuples, and strings are all **sequences**, sharing `[i]`, slicing, `len`, `in`, `+`, and `*` as their six core operations.
- A slice keeps the original type; `len` is a function, not a method.
- Types must match to concatenate: `[1] + [2]` works, `[1] + (2,)` raises an error.
- `[[]] * n` is a classic trap — use `[[] for _ in range(n)]` instead.
- Choosing a type: characters belong in `str`; data that must change belongs in `list`; fixed fields or dictionary keys belong in `tuple`.
