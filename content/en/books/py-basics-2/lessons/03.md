# Adding and Removing: Making a List Grow and Shrink

> An index can only change a position that **already exists**. But real programs collect data as they run — each time the user submits a form, there is one more item.
>
> This lesson covers the **add and remove** side of lists: how to put things in, how to take them out, and a few mistakes you should memorise on the spot.

## 1. Meet the four methods

The built-in actions a list comes with are called **methods**, and you write them by putting a dot after the list:

```python
bag = []
bag.append("book")      # add one item at the end
```

| Method | What it does | Who gets changed |
|---|---|---|
| `append(x)` | Add one item at the **end** | The original list |
| `insert(i, x)` | Insert one item at a **chosen position** | The original list |
| `pop(i)` | Remove at the chosen position, **and hand the item back to you** | The original list |
| `remove(x)` | Remove the **first item equal to x** | The original list |

All four **modify the original list directly** and do not return a new list (only `pop` returns the item that was removed).

## 2. `append`: the one you will use most

```python
bag = []
bag.append("book")
bag.append("pen")
bag.append("notebook")
print(bag)
```

Output:

```
['book', 'pen', 'notebook']
```

**`append` adds exactly one element, at the end.**

⚠️ **Crash: trying to add several at once.**

```python
bag = []
bag.append("book", "pen")     # WRONG  TypeError: append() takes exactly one argument
```

`append` accepts exactly one argument. To add several at once, use `extend` (Lesson 4) or write multiple `append` calls.

⚠️ **Another crash: trying to capture the return value.**

```python
bag = ["book"]
result = bag.append("pen")
print(result)      # None
```

`append` has **no return value** (it returns `None`); it silently changes `bag`. If you want the result, print `bag` itself:

```python
bag = ["book"]
bag.append("pen")
print(bag)         # ['book', 'pen']
```

**A useful rule:** a method that "does something" returns `None`; a method that "gives you something back" (such as `pop`) returns a value.

## 3. `insert`: adding at a chosen position

`append` only reaches the end. To slip an item into the middle, use `insert`:

```python
queue = ["Alice", "Bob"]
queue.insert(0, "Carol")     # insert at the very front
print(queue)
```

Output:

```
['Carol', 'Alice', 'Bob']
```

`insert(position, value)` — note that **the position comes first, the value second**. Do not reverse them.

After the insertion, "Carol" sits at index 0 and everyone else shifts one place to the right.

⚠️ Inserting past the end does **not** raise an error; Python treats it as "add at the end":

```python
queue = ["Alice", "Bob"]
queue.insert(99, "Carol")
print(queue)      # ['Alice', 'Bob', 'Carol'] — no error, but not at slot 99
```

This is unlike index assignment, which crashes when you go out of range — `insert` is forgiving. But do not expect it to pad the gap with empty slots.

## 4. `pop`: remove it and hand it back

```python
scores = [87, 92, 78]
last = scores.pop()        # no index given = remove the last
print(last)                # 78
print(scores)              # [87, 92]
```

**`pop` is the only removal method that "gives something back"** — it returns the item that was removed.

That is the key difference from `remove`. Sometimes you need to delete **and** use the value:

```python
tasks = ["write report", "read book", "exercise"]
doing = tasks.pop(0)       # take the first item, remove it from the list
print("Now doing:", doing)
print("Still left:", tasks)
```

Output:

```
Now doing: write report
Still left: ['read book', 'exercise']
```

This "take it out and remove it" move has a standard name in programming: **dequeue**, and it is very common in task queues.

⚠️ Popping from an empty list raises an error:

```python
bag = []
bag.pop()      # WRONG  IndexError: pop from empty list
```

## 5. `remove`: by value, not by position

The first three methods work by position. `remove` is different — you tell it **what content to delete**:

```python
names = ["Alice", "Bob", "Carol"]
names.remove("Bob")
print(names)
```

Output:

```
['Alice', 'Carol']
```

You do not need to know that "Bob" was at index 1.

⚠️ **The trap everyone hits: `remove` only deletes the first match.**

```python
nums = [1, 2, 3, 2, 2]
nums.remove(2)
print(nums)      # [1, 3, 2, 2] — only the first 2 is gone
```

Two more 2s are still in there. **`remove` deletes exactly one item per call.**

⚠️ **The other trap: removing something that is not there raises an error.**

```python
names = ["Alice", "Bob"]
names.remove("Carol")      # WRONG  ValueError: list.remove(x): x not in list
```

So the safe habit is to ask first (`in` is covered in Lesson 5, but meet it here):

```python
names = ["Alice", "Bob"]
if "Carol" in names:
    names.remove("Carol")
else:
    print("No such person")
```

## 6. `del`: by position, no return value wanted

There is also the `del` statement (it is not a method, so no parentheses):

```python
scores = [87, 92, 78]
del scores[0]
print(scores)      # [92, 78]
```

`del scores[0]` and `scores.pop(0)` achieve the same result, but **`del` does not hand you the removed value**.

| What you want | Use |
|---|---|
| Just delete it, you do not need it | `del scores[i]` |
| Delete it, but also use the value | `scores.pop(i)` |
| You know the content, not the position | `scores.remove(x)` |

## 7. A genuinely common mistake: deleting while iterating

This one deserves a mention now, because so many people hit it. You will understand it fully once Lesson 5 covers iteration.

First, an example that **looks correct**:

```python
nums = [1, 2, 3, 4, 5]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)      # [1, 3, 5] — exactly what we wanted
```

Now the **same shape** of code, but a different list:

```python
nums = [2, 4, 6, 8]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)      # [4, 8] — two items mysteriously missed!
```

Why does the first one get lucky while the second one fails?

Because **after an item is removed, every later element shifts one place forward, while the loop counter keeps marching forward** — so every deletion skips exactly one element.

| Round | Counter position | Value fetched | List after removal |
|---|---|---|---|
| 1 | 0 | 2 | `[4, 6, 8]` |
| 2 | 1 | **6** (4 was skipped) | `[4, 8]` |
| 3 | 2 | gone, loop ends | `[4, 8]` |

**The correct approach:** do not modify the list you are iterating over; instead, **build a new list of what should stay**:

```python
nums = [2, 4, 6, 8, 9]
kept = []
for n in nums:
    if n % 2 != 0:
        kept.append(n)
print(kept)      # [9]
```

Walk the original list, append to a new one — every element gets examined, none is skipped.

**The rule to remember: never modify the list you are currently iterating over. To delete, build a new one.**
