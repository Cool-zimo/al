# Iteration and Common Operations: Actually Using a List

> The previous four lessons answered "how do I store, fetch, and change values". This one answers the final question: **how do I do something to the whole pile at once?**
>
> By the end of this lesson you will be able to write genuinely useful programs — "collect a batch of scores, then analyse and rank them".

## 1. Iteration: doing something to every element

Suppose you need to print every score in a class. Writing them one by one looks like this:

```python
scores = [87, 92, 78]

print(scores[0])
print(scores[1])
print(scores[2])
```

Three is tolerable; three hundred is not. **Iteration** solves this:

```python
scores = [87, 92, 78]

for s in scores:
    print(s)
```

Output:

```
87
92
78
```

The reading is direct: **for every s in scores, do the indented block once.**

`s` is a name you choose yourself. On each round it becomes the next element in the list. `score`, `x`, or `item` would all work.

```
Round 1:  s = 87  → print(87)
Round 2:  s = 92  → print(92)
Round 3:  s = 78  → print(78)
(the list is exhausted, the loop ends)
```

**The number of rounds equals the length of the list**, so you never need to write `range(len(...))` to count. This is the second time you have met a loop (the first was Lesson 23 in Python in Depth 1), but that time it counted through numbers; this time it walks through a list.

⚠️ **Crash: forgetting the colon or the indentation.**

```python
for s in scores      # WRONG  SyntaxError: expected ':'
    print(s)
```

```python
for s in scores:
print(s)             # WRONG  IndentationError: expected an indented block
```

These two errors were covered in Lesson 16 of Python in Depth 1, and they remain the most common mistakes when writing loops.

## 2. Doing something real on each round

Printing is only the beginning. The point of iteration is **to process every element**:

```python
scores = [87, 92, 78]

total = 0
for s in scores:
    total = total + s

print("Total:", total)
print("Average:", total / len(scores))
```

Output:

```
Total: 257
Average: 85.66666666666667
```

This is the complete version of the code from Lesson 1. Note that `total = 0` **must sit outside the loop** — if it lived inside, it would reset to zero on every round and you would end up with only the final number.

**The accumulation pattern** (seen in Lesson 21 of Python in Depth 1, now applied to a list):

```python
total = 0            # ① outside the loop, prepare a container
for s in scores:     # ② iterate
    total = total + s    # ③ add into it
```

## 3. `in`: asking "is it in there?"

```python
names = ["Alice", "Bob", "Carol"]

print("Alice" in names)      # True
print("Dave" in names)       # False
```

`in` tests whether an element is present, and the result is the boolean `True` or `False`.

With `not`, you can reverse the question:

```python
if "Dave" not in names:
    print("No such person")
```

**When is `in` useful?** Two typical cases:

**① Preventing duplicate entries.**

```python
names = ["Alice", "Bob"]

new_name = "Alice"
if new_name in names:
    print("Already exists")
else:
    names.append(new_name)
```

**② Checking before removing** (Lesson 3: calling `remove` on a missing value raises `ValueError`).

⚠️ **`in` on a list compares elements one by one**, and the longer the list, the slower it gets. At small sizes this is harmless, but once you are handling tens of thousands of items, a set or a dictionary (Chapter 3) is the right tool — keeping track of membership is one of the main reasons they exist.

## 4. Four statistics functions you do not need to write

Python already provides these:

```python
scores = [87, 92, 78, 95, 61]

print(len(scores))      # 5     how many
print(sum(scores))      # 413   the total
print(max(scores))      # 95    the largest
print(min(scores))      # 61    the smallest
```

| Function | Purpose | On an empty list |
|---|---|---|
| `len(x)` | number of elements | returns 0 |
| `sum(x)` | sum of elements | returns 0 |
| `max(x)` | largest element | ⚠️ **raises ValueError** |
| `min(x)` | smallest element | ⚠️ **raises ValueError** |

The last two deserve care: **asking for the maximum of an empty list crashes.** When the data might be empty, check first:

```python
scores = []
if len(scores) > 0:
    print("Highest:", max(scores))
else:
    print("No scores yet")
```

⚠️ `max` and `min` require elements that **can be compared with each other**. Mixing numbers and strings raises an error:

```python
mixed = [87, "Alice"]
print(max(mixed))      # WRONG  TypeError: '>' not supported between 'str' and 'int'
```

## 5. Sorting: `sort` versus `sorted` (the biggest trap in this lesson)

Both sort a list, but their behaviour is **completely different**:

```python
scores = [87, 92, 78]

scores.sort()          # method: sort the list in place
print(scores)          # [78, 87, 92]
```

```python
scores = [87, 92, 78]

ordered = sorted(scores)     # function: return a new list
print(ordered)               # [78, 87, 92]
print(scores)                # [87, 92, 78]  ← the original is untouched
```

| | Writing | Changes the original? | Return value |
|---|---|---|---|
| `sort()` | method, follows a dot | ✅ **yes** | `None` |
| `sorted()` | function, wraps the value | ❌ no | a **new** sorted list |

⚠️ **Crash of the year: capturing the return value of `sort()`.**

```python
scores = [87, 92, 78]
result = scores.sort()
print(result)      # None  ← nothing useful at all!
print(scores)      # [78, 87, 92]  ← the result is in the original list
```

Like `append()`, `sort()` **does the work and returns nothing**. If you want the sorted result, use `sorted()`, or sort first and then print the list.

**How to choose?**

- Want to keep the original order → `sorted(scores)`
- Do not need the original order any more → `scores.sort()`

### Reversing the sort order

Both accept `reverse=True`:

```python
scores = [87, 92, 78]

print(sorted(scores, reverse=True))     # [92, 87, 78]   largest first
```

```python
scores = [87, 92, 78]
scores.sort(reverse=True)
print(scores)      # [92, 87, 78]
```

⚠️ Note that `reverse=True` is a **sorted reversal**, whereas `[::-1]` from Lesson 4 is **a reversal of the existing order** — on an unsorted list the two give completely different results:

```python
nums = [3, 1, 2]
print(nums[::-1])                    # [2, 1, 3]  ← merely reversed
print(sorted(nums, reverse=True))    # [3, 2, 1]  ← truly sorted largest first
```

## 6. Putting it all together: a score report

Time to assemble the pieces. The requirement:

> Given a batch of scores, print the count, the total, the average, the highest and lowest, and a ranking from high to low.

```python
scores = [87, 92, 78, 95, 61, 88]

print("Count:", len(scores))
print("Total:", sum(scores))
print("Average:", round(sum(scores) / len(scores), 1))
print("Highest:", max(scores))
print("Lowest:", min(scores))

ranked = sorted(scores, reverse=True)
print("Ranking:", ranked)
```

Output:

```
Count: 6
Total: 501
Average: 83.5
Highest: 95
Lowest: 61
Ranking: [95, 92, 88, 87, 78, 61]
```

(`round(x, 1)` keeps one decimal place; it only affects how it looks, not the logic.)

**The best thing about this code is that it has nothing to do with how many scores there are.** Drop ten more numbers into `scores` and not a single line needs to change.

One more genuinely useful feature — finding the **failing** scores:

```python
scores = [87, 92, 78, 95, 61, 88]

failed = []
for s in scores:
    if s < 60:
        failed.append(s)

print("Fail count:", len(failed))
print("Failing scores:", failed)
```

This is the central pattern of this course, repeated again and again: **iterate, test, append to a new list**. Filtering data always comes down to this.

(Lesson 3 established that you should not delete from a list while iterating over it; build a new one. This example is exactly that principle used well.)

## 7. Quick reference for this lesson

| Goal | How to write it |
|---|---|
| Do something to every element | `for x in list:` |
| Count the elements | `len(list)` |
| Add them up | `sum(list)` |
| Largest / smallest | `max(list)` / `min(list)` |
| Test membership | `x in list` |
| Sort (changes the list) | `list.sort()` |
| Sort (returns a new list) | `sorted(list)` |
| Largest first | add `reverse=True` |

```quiz
type: code
q: Given `nums = [4, 7, 1, 9, 3]`, print the largest value and the smallest value, each on its own line.
starter: |
  nums = [4, 7, 1, 9, 3]

  # print the largest

  # print the smallest
tests:
- assert "9" in __out
- assert "1" in __out
hint: max gives the largest, min the smallest. Both are functions: wrap the list in parentheses.
explain: The missing line is print(min(nums)). These two names are the easiest to swap — remember that min stands for minimum (smallest) and max for maximum (largest). Both are three-letter abbreviations but with opposite meanings. Also, do not write nums.max(): these are functions, not methods.
```
