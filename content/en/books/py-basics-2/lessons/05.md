# Iteration and Everyday Operations

> The previous four lessons covered how to store, fetch and change. This one covers the last piece: **how to do work on the whole pile at once.**
>
> After this lesson you'll be able to write things like "enter a batch of scores → summarise → rank" — a genuinely useful program.

## 1. Iteration: Do Something to Every Element

Suppose you want to print everyone's score. One by one it looks like:

```python
scores = [87, 92, 78]

print(scores[0])
print(scores[1])
print(scores[2])
```

Three is bearable; three hundred isn't. **Iteration** solves it:

```python
scores = [87, 92, 78]

for s in scores:
    print(s)
```

```
87
92
78
```

It reads almost literally: **for every s in scores, do the following.**

`s` is a name you choose. Each round it becomes the next element in the list. `score`, `x`, `item` — anything works.

```
round 1:  s = 87  → print(87)
round 2:  s = 92  → print(92)
round 3:  s = 78  → print(78)
(the list is finished, loop ends)
```

**The number of rounds = the length of the list.** You don't write `range(len(...))` to count. You already met `for` in Basics 1 lesson 23 — except there it counted numbers, and here it walks a list.

⚠️ **Traps: forgetting the colon or forgetting the indent.**

```python
for s in scores      # ✗ SyntaxError: expected ':'
    print(s)
```

```python
for s in scores:
print(s)             # ✗ IndentationError: expected an indented block
```

Both were covered in Basics 1 lesson 16, and they're still the two most common errors when writing loops.

## 2. Doing Real Work While Iterating

Printing alone is boring. The value of iteration is **processing each element**:

```python
scores = [87, 92, 78]

total = 0
for s in scores:
    total = total + s

print("Total:", total)
print("Average:", total / len(scores))
```

```
Total: 257
Average: 85.66666666666667
```

That's the full version of the snippet from the start of lesson 1. Note that `total = 0` **must be outside the loop** — inside it, the total would reset every round and you'd be left with only the last number.

**The accumulation pattern** (Basics 1 lesson 21, now applied to a list):

```python
total = 0            # ① outside the loop, prepare the container
for s in scores:     # ② iterate
    total = total + s    # ③ add into it
```

## 3. in: Asking "Is It In There?"

```python
names = ["Alice", "Bob", "Charlie"]

print("Alice" in names)      # True
print("Dave" in names)       # False
```

`in` checks whether an element **is in the list**, and gives you a boolean `True` / `False`.

Flip it around with `not`:

```python
if "Dave" not in names:
    print("No such person")
```

**When do you use `in`?** Two typical cases:

**① Preventing duplicates.**

```python
names = ["Alice", "Bob"]

new_name = "Alice"
if new_name in names:
    print("Already exists")
else:
    names.append(new_name)
```

**② Confirming something exists before removing it** (lesson 3: calling `remove` on something absent raises `ValueError`).

⚠️ **`in` on a list compares one element at a time**, so it gets slower as the list grows. With small data it doesn't matter — but when you're handling tens of thousands of rows, you'll want a set or a dict from chapter 3. That's one of the main reasons they exist.

## 4. Four Statistics You Don't Have to Write Yourself

Python has already done this work for you:

```python
scores = [87, 92, 78, 95, 61]

print(len(scores))      # 5     how many
print(sum(scores))      # 413   what they add up to
print(max(scores))      # 95    the largest
print(min(scores))      # 61    the smallest
```

| Function | What it does | On an empty list |
|---|---|---|
| `len(x)` | number of elements | returns 0 |
| `sum(x)` | the total | returns 0 |
| `max(x)` | the largest | ⚠️ **errors**: ValueError |
| `min(x)` | the smallest | ⚠️ **errors**: ValueError |

Watch those last two: **asking for the maximum of an empty list crashes.** So when you're not sure there's data, check first:

```python
scores = []
if len(scores) > 0:
    print("Highest:", max(scores))
else:
    print("No scores yet")
```

⚠️ `max` / `min` require elements that **can be compared**. Mixing numbers and strings errors:

```python
mixed = [87, "Alice"]
print(max(mixed))      # ✗ TypeError: '>' not supported between 'str' and 'int'
```

## 5. Sorting: sort vs sorted (The Biggest Trap in This Lesson)

Both sort, but they behave **completely differently**:

```python
scores = [87, 92, 78]

scores.sort()          # method: changes the original in place
print(scores)          # [78, 87, 92]
```

```python
scores = [87, 92, 78]

ordered = sorted(scores)     # function: returns a new list
print(ordered)               # [78, 87, 92]
print(scores)                # [87, 92, 78]  ← the original didn't change
```

| | Form | Changes the original? | Returns |
|---|---|---|---|
| `sort()` | method, trailing dot | ✅ **yes** | `None` |
| `sorted()` | function, wrapping | ❌ no | a **new sorted list** |

⚠️ **Trap of all traps: grabbing sort()'s return value.**

```python
scores = [87, 92, 78]
result = scores.sort()
print(result)      # None  ← nothing there!
print(scores)      # [78, 87, 92]  ← the sorted result is in the original
```

Like `append()`, `sort()` **does the work and hands back nothing**. To get a sorted result, use `sorted()`, or sort and then print the original.

**How to choose?**

- You want to keep the original order → `sorted(scores)`
- You don't need the original order → `scores.sort()`

### Descending Order

Both accept `reverse=True`:

```python
scores = [87, 92, 78]

print(sorted(scores, reverse=True))     # [92, 87, 78]   largest first
```

```python
scores = [87, 92, 78]
scores.sort(reverse=True)
print(scores)      # [92, 87, 78]
```

⚠️ Note that `reverse=True` means **sort in descending order**, while `[::-1]` from lesson 4 means **flip the existing order** — on an unsorted list the two give completely different results:

```python
nums = [3, 1, 2]
print(nums[::-1])                    # [2, 1, 3]  ← just flipped
print(sorted(nums, reverse=True))    # [3, 2, 1]  ← actually sorted descending
```

## 6. Project: A Score Report

Let's stitch this lesson together. The requirement:

> Given a batch of scores, print: how many, the total, the average, the highest, the lowest, and a ranking from high to low.

```python
scores = [87, 92, 78, 95, 61, 88]

print("Count:", len(scores))
print("Total:", sum(scores))
print("Average:", round(sum(scores) / len(scores), 1))
print("Highest:", max(scores))
print("Lowest:", min(scores))

ranked = sorted(scores, reverse=True)
print("Ranking:", ranked)
```

```
Count: 6
Total: 501
Average: 83.5
Highest: 95
Lowest: 61
Ranking: [95, 92, 88, 87, 78, 61]
```

(`round(x, 1)` keeps one decimal place — purely cosmetic, it doesn't affect the logic.)

**The best thing about this code: it has nothing to do with how many scores there are.** Add ten more numbers to `scores` and not a single character needs changing.

One more practical feature — finding everyone who **failed**:

```python
scores = [87, 92, 78, 95, 61, 88]

failed = []
for s in scores:
    if s < 60:
        failed.append(s)

print("Failed count:", len(failed))
print("Failing scores:", failed)
```

This is the core pattern that keeps reappearing: **iterate → test → collect into a new list.** All data filtering rests on it.

(Lesson 3 warned: don't remove from a list while iterating over it — build a new one. This is that principle used correctly.)

## 7. Quick Reference

| What you want | How to write it |
|---|---|
| Do something to every element | `for x in list:` |
| How many elements | `len(list)` |
| Add them all up | `sum(list)` |
| Largest / smallest | `max(list)` / `min(list)` |
| Is it in there | `x in list` |
| Sort (changes the original) | `list.sort()` |
| Sort (want a new list) | `sorted(list)` |
| Descending | add `reverse=True` |

```quiz
type: code
q: Given `nums = [4, 7, 1, 9, 3]`, print the largest and the smallest value, each on its own line.
starter: |
  nums = [4, 7, 1, 9, 3]

  # print the largest
  print(max(nums))

  # print the smallest

tests:
- assert "9" in __out
- assert "1" in __out
hint: max is the largest, min is the smallest. Both are functions — wrap the list in parentheses.
explain: You fill in print(min(nums)). These two names are the easiest to mix up — mnemonic: min is "minimum", max is "maximum". And don't write nums.max(): they're functions, not methods.
```
