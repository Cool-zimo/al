# Functions Are Objects: Assign Them, Put Them in Lists, Pass Them In

> So far we have treated a function as "a bundled chunk of code". This lesson upgrades that picture: **a function is itself an object** — you can assign it to a variable, drop it in a list, and pass it as an argument to another function.
>
> Understand this and you have opened the door to **higher-order functions**.

## 1. A function is an object with a name and an identity

In Python, a function is an object just like a number, a string or a list — it lives in memory, and `def` simply binds a name to it.

```python
def greet(name):
    return f"Hello, {name}!"

print(greet)                 # <function greet at 0x...>
print(type(greet))           # <class 'function'>
print(id(greet))             # a number, proving it really has an "identity"
```

`greet` is a variable name pointing at a function object in memory. `type` and `id` both work on it — that is proof positive of "object".

⚠️ **Crash: forgetting the parentheses and getting the function itself.**

```python
def get_greeting():
    return "Hello"

print(get_greeting)          # <function get_greeting at 0x...>  <- not called!
```

`get_greeting` is the function object; `get_greeting()` is the call. Miss the parentheses and you get "the function", not "its return value".

## 2. Assigning a function to another variable

Since a function is an object, you can give it another name — and that name is callable too:

```python
def square(n):
    return n * n

calc = square            # bind the function object to calc, no parentheses
print(calc(5))           # 25
print(square(5))         # 25 -- both names point at the same function
```

`calc = square` has **no parentheses**, meaning "hand me that function, I want a name for it too" — not "call it".

⚠️ **Crash: accidentally adding parentheses at assignment, which calls it on the spot.**

```python
def square(n):
    return n * n

calc = square(5)         # calls immediately, calc becomes 25 (a number)
print(calc(6))           # WRONG  TypeError: 'int' object is not callable
```

`square(5)` calls the function and returns 25, so `calc` becomes the integer 25 — calling it again blows up. **No parentheses = the function itself; with parentheses = its return value.**

## 3. Storing functions in a list: a set of "actions"

Functions can live in lists and dictionaries, so you can **manage a whole family of behaviours in one container**:

```python
def add(a, b):
    return a + b

def sub(a, b):
    return a - b

def mul(a, b):
    return a * b

ops = [add, sub, mul]        # the list holds function objects

for op in ops:
    print(op(10, 3))
# 13
# 7
# 30
```

`ops` is a "function list"; iterating it runs each operation in turn. This is wonderfully handy for calculators and menu-driven programs.

⚠️ **Crash: calling the functions while storing them, so you store the return values.**

```python
ops = [add(10, 3), sub(10, 3), mul(10, 3)]
print(ops)        # [13, 7, 30] -- the list holds numbers, not functions
```

What got stored here is **the result of calling them** (numbers). The list is now just ordinary numbers and nothing inside it is callable any more. **To store the function itself, the parentheses must stay off.**

## 4. Passing a function as an argument

Passing a function in is the heart of a "higher-order function":

```python
def apply_twice(func, value):
    """apply func to value twice"""
    return func(func(value))

def add_five(x):
    return x + 5

print(apply_twice(add_five, 10))        # 20
```

`apply_twice` has no idea what `func` actually does; it only knows "take func and call it". Passing behaviour in this way makes code **remarkably flexible**.

⚠️ **Crash: accidentally calling the argument when passing it.**

```python
apply_twice(add_five(10), 20)   # WRONG  TypeError: 'int' object is not callable
```

`add_five(10)` returns 15 (an integer), and `apply_twice` tries to call 15 as a function. **Pass the function itself, not its return value.**

## 5. Returning a function: a factory

A function can return a function too — this is the beginning of a **closure**:

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor
    return multiply            # return the function object

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))              # 20
print(triple(10))              # 30
```

`make_multiplier(2)` returns a function that "remembers `factor=2`" — `double`. The outer function has become a **function factory**: feed it different arguments and it produces functions with different behaviour.

⚠️ **Crash: adding parentheses at the return, returning the call result instead.**

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor
    return multiply()          # WRONG  TypeError: multiply() missing 1 required positional argument: 'x'

print(make_multiplier(2))
```

`return multiply()` means "call multiply right now", but no argument was supplied. **To return the function itself, do not put parentheses after it.**

## 6. A command dispatch with a dictionary: real use

A contacts mini-tool often needs to run different operations based on user input; a "function dictionary" is the cleanest approach:

```python
def do_add(name):
    return f"Adding {name}"

def do_del(name):
    return f"Deleting {name}"

def do_find(name):
    return f"Finding {name}"

menu = {
    "1": do_add,
    "2": do_del,
    "3": do_find,
}

cmd = "2"
name = "Alice"
print(menu[cmd](name))        # Deleting Alice
```

The user picks `"2"`, you fetch `do_del` from `menu` and call it with the argument. **No pile of `if/elif`, and adding a feature is just one more line in the dictionary.**

⚠️ **Crash: storing a function call's result in the dictionary.**

```python
menu = {
    "1": do_add("Alice"),       # runs immediately! the value stored is a string
}
print(menu["1"])              # Adding Alice (already happened long ago)
```

The dictionary holds the *return value* of `do_add("Alice")` — a string. You have lost the ability to "call it later". **The dispatch pattern must store the function itself.**

## 7. Why this matters

Treating a function as an object is really about **passing behaviour around**. It lets you:

- pass "what to do" as an argument (`map`, `filter`, `sorted(key=...)` all work this way)
- gather "a set of operations" in a container (menus, plugins, routing tables)
- generate functions dynamically (factories, decorators — coming later)

Once "functions can travel" becomes second nature, your code takes a clear step up in flexibility.

## Summary

- In Python a function is a **first-class object**: it has identity, can be assigned, stored, passed in and returned
- `funcname` = the function itself; `funcname()` = a call
- **Never use parentheses** when storing, passing or returning a function
- A list of functions is ideal for "managing a family of behaviours"
- A dictionary of functions is ideal for "command dispatch", replacing long `if/elif` chains
- The classic mistake is adding parentheses by accident
