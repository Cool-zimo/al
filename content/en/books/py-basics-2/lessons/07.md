# Tuple Unpacking: Assigning to Several Names at Once

> Lesson 6 said "a tuple is defined by its commas". This lesson covers the single biggest convenience that commas bring: **taking the values inside a tuple and handing them to several variables at once.**
>
> It is one of the most elegant bits of Python syntax, and it is the reason "a function returning several values" is even possible.

## 1. Assigning to several variables in one line

The basic form you already know is one assignment at a time:

```python
x = 51.5074
y = -0.1278
```

But when two numbers already travel around as a pair, Python lets you **split them apart** and hand them to variables in one step:

```python
x, y = (51.5074, -0.1278)
print(x)       # 51.5074
print(y)       # -0.1278
```

On the left, write **several variable names**; on the right, put something that can be unpacked (a tuple, a list, anything iterable). Python pairs them up in order.

The parentheses are actually optional — because the comma itself already defines a tuple:

```python
x, y = 51.5074, -0.1278       # exactly the same as the example above
print(x, y)                   # 51.5074 -0.1278
```

⚠️ **Crash: the two sides have different lengths.**

```python
a, b, c = (1, 2)          # WRONG  ValueError: not enough values to unpack (expected 3, got 2)
```

The error is crystal clear: you expected 3 but were given 2. Having too many values is also an error:

```python
a, b = (1, 2, 3)          # WRONG  ValueError: too many values to unpack (expected 2)
```

**The number of variables on the left must match the number of elements on the right exactly.** That is the hard rule of tuple unpacking.

## 2. Swapping two variables: the classic use

In many other languages, swapping two variables means **borrowing a temporary variable**:

```python
# the C / Java style
temp = a
a = b
b = temp
```

Python needs only one line:

```python
a = 10
b = 20
a, b = b, a
print(a, b)          # 20 10
```

How does that work? Python evaluates the right-hand side first, packing `b, a` into a tuple `(20, 10)`, and **only then** unpacks it back into `a` and `b`.

The key point: **Python fully evaluates the right-hand tuple before it touches the left-hand side.** So you never get the self-defeating situation of "I changed `a`, so now `b` sees the new `a`". It happens **simultaneously**.

⚠️ **Crash: "simplifying" the swap by hand and creating a bug.**

Someone might assume Python's swap is just sugar, and write it out long-form:

```python
a = 10
b = 20
a = b          # a becomes 20
b = a          # b becomes 20 too — disaster, the original 10 is gone
print(a, b)    # 20 20
```

Just use `a, b = b, a` and let Python guarantee it for you.

## 3. Functions returning several values

This is where tuple unpacking earns its keep, and it sets the stage for functions in Book 5. First, the usage:

```python
def divide(n, d):
    quotient = n // d
    remainder = n % d
    return quotient, remainder       # returns a tuple

q, r = divide(17, 5)
print("Quotient:", q)      # Quotient: 3
print("Remainder:", r)     # Remainder: 2
```

`return a, b` in Python **is really returning the tuple `(a, b)`** — you just do not see the parentheses. The call above is equivalent to:

```python
result = divide(17, 5)
print(result)        # (3, 2) — genuinely a tuple
print(type(result))  # <class 'tuple'>
```

That is why a function can "return several values": it does not literally return several things, it **packs them into a tuple**, and the caller unpacks them.

A more realistic example:

```python
def analyze(nums):
    return min(nums), max(nums), sum(nums) / len(nums)

low, high, avg = analyze([87, 92, 78, 65, 100])
print(low, high, avg)      # 65 100 84.4
```

⚠️ **Crash: catching "several return values" in a single variable.**

```python
def divide(n, d):
    return n // d, n % d

r = divide(17, 5)
print(r[0])          # 3 — reachable, but awkward
print(r)             # (3, 2) — it is a tuple, not two separate numbers
```

Catching everything in one variable is fine in principle, but if you **thought** it was the quotient and then used it as a number, you are wrong:

```python
r = divide(17, 5)
print(r + 1)        # WRONG  TypeError: can only concatenate tuple and int
```

So the habit is: when a function returns several values, unpack them into several variables. If you genuinely only want one, remember it is a tuple and index it.

## 4. `*` gathers the leftovers

Sometimes you only want the first few values, and everything else should be "collected however many there are":

```python
first, *rest = (10, 20, 30, 40, 50)
print(first)        # 10
print(rest)         # [20, 30, 40, 50] — note: a list
```

`*rest` gathers "everything remaining" into a **list**.

The `*` can sit in the middle or at the end too:

```python
a, *middle, z = (1, 2, 3, 4, 5)
print(a)            # 1
print(middle)       # [2, 3, 4]
print(z)            # 5
```

```python
a, b, *rest = (1, 2, 3, 4)
print(a, b)         # 1 2
print(rest)         # [3, 4]
```

⚠️ **Crash: the `*` variable receives nothing and becomes an empty list.**

```python
a, *rest = (7,)          # only 1 element
print(rest)              # [] — an empty list, not an error
```

No error, but `rest` will be `[]`. Bear that in mind when you write the code — do not assume `rest` is non-empty.

⚠️ **Crash: two `*` variables in one assignment.**

```python
*a, *b = (1, 2, 3)      # WRONG  SyntaxError: multiple starred expressions
```

Python has no idea which side "the rest" belongs to, so **one assignment can contain only one `*` variable**.

## Summary

- Tuple unpacking: `a, b = (x, y)` — the number of variables on the left must equal the number of elements on the right.
- Swap with `a, b = b, a`: one line, and Python guarantees it happens simultaneously.
- A "function returning several values" is really returning a tuple, which the caller unpacks.
- A `*` variable gathers the leftovers into a list, and only one `*` is allowed per assignment.
