# Variable Arguments: `*args` and `**kwargs`

> So far every function has had a fixed number of parameters. This lesson handles "I do not know how many arguments there will be": `*args` gathers any number of **positional arguments**, `**kwargs` gathers any number of **keyword arguments**.
>
> Along the way you also get **argument unpacking** — spreading a list or dictionary out into arguments.

## 1. `*args`: gathering any number of positional arguments

When you do not know how many arguments will arrive, use `*args`:

```python
def total(*args):
    return sum(args)

print(total(1, 2))              # 3
print(total(1, 2, 3, 4, 5))     # 15
print(total())                  # 0
```

`*args` **packs every positional argument into a tuple**. That tuple is `args` — the name is just a convention; the `*` is what matters, and you may choose another name.

⚠️ **Crash: thinking `args` is a list and trying to `append`.**

```python
def show(*args):
    args.append(4)          # WRONG  AttributeError: 'tuple' object has no attribute 'append'

show(1, 2, 3)
```

What `*args` gathers is a **tuple**, and tuples are immutable — no `append`. To add or remove, convert first: `list(args)`.

## 2. `**kwargs`: gathering any number of keyword arguments

Keyword arguments can be gathered too, with two stars:

```python
def print_info(**kwargs):
    for k, v in kwargs.items():
        print(f"{k} = {v}")

print_info(name="Alice", city="London", age=20)
# name = Alice
# city = London
# age = 20
```

`**kwargs` **packs keyword arguments into a dictionary**; `kwargs` is that dictionary. The name `kwargs` is a convention, but the `**` is what counts.

⚠️ **Crash: passing positional arguments to `**kwargs`.**

```python
print_info("Alice", "London")      # WRONG  TypeError: print_info() takes 0 positional arguments but 2 were given
```

`**kwargs` **only accepts keyword arguments**; positional ones will not fit. Positional-only goes to `*args`.

## 3. Combining them: `def f(a, b, *args, **kwargs)`

All three can coexist, but **the order is fixed**:

```python
def f(a, b=2, *args, **kwargs):
    print(f"a={a}, b={b}, args={args}, kwargs={kwargs}")

f(1)                        # a=1, b=2, args=(), kwargs={}
f(1, 3, 4, 5, name="Alice") # a=1, b=3, args=(4, 5), kwargs={'name': 'Alice'}
```

**The rule is: positional → default → `*args` → `**kwargs`.**

⚠️ **Crash: putting `**kwargs` before `*args`.**

```python
def f(**kwargs, *args):     # WRONG  SyntaxError
    pass
```

Reverse the order and you get a syntax error on the spot. **If you cannot remember the whole thing, just recite: ordinary parameters first, then the `*` ones, then the `**` one last.**

## 4. When do you actually need variable arguments?

**Typical case 1: the count really is unknown.**

```python
def average(*numbers):
    if not numbers:
        return 0
    return sum(numbers) / len(numbers)

print(average(80, 90, 100))        # 90.0
print(average(70, 80, 90, 100))    # 85.0
```

The number of scores varies, so `*args` fits perfectly.

**Typical case 2: wrapping and forwarding arguments.**

```python
def log_and_call(func, *args, **kwargs):
    print(f"Calling {func.__name__}, args {args}, kwargs {kwargs}")
    return func(*args, **kwargs)

def add(a, b):
    return a + b

log_and_call(add, 3, 5)        # Calling add, args (3, 5), kwargs {}
# returns 8
```

`log_and_call` has no idea what arguments the wrapped function wants, so it gathers them all with `*args, **kwargs` and forwards them unchanged. This is the seed of **decorators and middleware**.

⚠️ **Crash: the wrapper forgets `**kwargs` and drops the keyword arguments.**

```python
def log_and_call(func, *args):          # missing **kwargs
    return func(*args)

log_and_call(add, a=3, b=5)     # WRONG  TypeError: add() got an unexpected keyword argument 'a'
```

When forwarding, `*args` and `**kwargs` **must appear as a pair**, otherwise the keyword arguments have nowhere to go.

## 5. Argument unpacking: spreading a container back out

`*` and `**` work in reverse on the **call side**, as "unpacking":

```python
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
print(add(*nums))              # 6 -- equivalent to add(1, 2, 3)

info = {"name": "Alice", "city": "London"}
def greet(name, city):
    return f"Hello {name} of {city}!"

print(greet(**info))           # Hello Alice of London! -- equivalent to greet(name="Alice", city="London")
```

`*nums` spreads the list into positional arguments; `**info` spreads the dictionary into keyword arguments.

⚠️ **Crash: the number of items after unpacking does not match.**

```python
nums = [1, 2]
add(*nums)              # WRONG  TypeError: add() missing 1 required positional argument: 'c'
```

`add` needs 3 parameters, but the list only had 2, so one is still missing after spreading. **The number of items you unpack must match the parameter count** (unless the function itself uses variable arguments).

⚠️ **Crash: using `*` to unpack a dictionary.**

```python
greet(*info)            # WRONG  TypeError: greet() missing 1 required positional argument: 'city'
```

`greet(*info)` spreads the **keys** of the dictionary (`"name"`, `"city"`), mapping them positionally to `name` and `city` — it happens to line up here, but the meaning is wrong (you get two string keys). **A dictionary should be unpacked with `**` into keyword arguments.**

## 6. Worked example: a simplified SQL builder

```python
def make_insert(table, **fields):
    cols = ", ".join(fields.keys())
    vals = ", ".join(str(v) for v in fields.values())
    return f"INSERT INTO {table} ({cols}) VALUES ({vals})"

print(make_insert("users", name="Alice", age=20, city="London"))
# INSERT INTO users (name, age, city) VALUES (Alice, 20, London)
```

Both the column count and the value count are unknown, so `**fields` collects them all and you take the keys and values separately.

⚠️ **Crash: dropping user input straight into SQL — in real code this is an injection hole (this is a teaching demo, not a recommendation).**

```python
name = "Alice'; DROP TABLE users; --"
make_insert("users", name=name)
# INSERT INTO users (name) VALUES (Alice'; DROP TABLE users; --)
```

⚠️ **This is an explicit bad example.** Never build SQL by string concatenation in real code; use parameterised queries (`cursor.execute(sql, params)`). This lesson teaches the syntax; the real job of `**kwargs` is configuration and argument forwarding, not building SQL.

## Summary

- `*args` gathers any number of **positional arguments** into a **tuple**
- `**kwargs` gathers any number of **keyword arguments** into a **dictionary**
- Order rule: positional → default → `*args` → `**kwargs`
- In reverse: `*list` unpacks into positionals, `**dict` unpacks into keywords
- The unpacked count must match the parameter count
- In real projects `*args`/`**kwargs` are mostly for forwarding — do not use them to build SQL

- 'def f(a, b=1, *args): pass'
answer: 2
explain: **kwargs must come last; putting it before *args is a SyntaxError. A is legal (a, b after *args become "keyword-only" parameters), B is the standard form, D is legal (default before *args). Remember: positional → default → *args → keyword-only → **kwargs.
