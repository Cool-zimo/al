# Strings Are Immutable

> Lesson 3 taught you that you can replace an element by position: `nums[0] = 99`. You might wonder whether, since a string is just a sequence of characters, you can write `s[0] = 'X'`.
>
> This lesson covers the **immutable** nature of strings, and the set of common methods that goes with it.

## 1. "Changing" a string really means making a new one

First, the direct attempt:

```python
s = "hello"
s[0] = "H"          # WRONG  TypeError: 'str' object does not support item assignment
```

The error is explicit: a string **does not support assignment by position**.

So why does this next example look like it "changed successfully"?

```python
s = "hello"
s = "H" + s[1:]
print(s)            # Hello
```

Because nothing here actually changed the original `"hello"`. What happened was:

1. `"H" + s[1:]` is evaluated, producing the new string `"Hello"`.
2. The variable `s` is made to point at that new string.
3. The old `"hello"` has no references left, so Python recycles it.

**A string cannot be changed once it is created.** A variable can be pointed at a different string, but the string object itself is frozen.

This property matches tuples and contrasts with lists:

| Type | Assignable by position? | Example |
|---|---|---|
| `list` | Yes | `nums[0] = 99` |
| `tuple` | No | `t[0] = 1` → error |
| `str` | No | `s[0] = 'H'` → error |

⚠️ **Crash: assuming `replace` changes the original string.**

```python
msg = "I love apples"
msg.replace("apples", "bananas")
print(msg)          # I love apples — the original is untouched!
```

`replace` **returns a new string**; it never touches the original. You must capture the result:

```python
msg = "I love apples"
msg = msg.replace("apples", "bananas")
print(msg)          # I love bananas
```

This "the method returns a new object and the original stays put" rule applies to almost every string method. Memorise it: **a string method always computes a new string; the original never changes.**

## 2. A set of methods you will reach for constantly

| Method | Purpose | Example |
|---|---|---|
| `split(separator)` | Split into a list at the separator | `"a,b,c".split(",")` → `['a','b','c']` |
| `"sep".join(list)` | Glue a list back into a string | `",".join(['a','b'])` → `"a,b"` |
| `strip()` | Remove whitespace from both ends | `"  hi  ".strip()` → `"hi"` |
| `replace(a, b)` | Replace every a with b | `"aa".replace("a","b")` → `"bb"` |
| `find(x)` | Find the position of x, or -1 if absent | `"abc".find("b")` → `1` |
| `startswith(x)` | Does it begin with x? | `"2026-09-29".startswith("2026")` → `True` |

### `split`: breaking a line apart

```python
line = "Alice,07123456789,London"
parts = line.split(",")
print(parts)        # ['Alice', '07123456789', 'London']
print(parts[0])     # Alice
```

`split` returns a **list**. With no argument, it splits on "any whitespace":

```python
s = "a  b\tc\nd"
print(s.split())    # ['a', 'b', 'c', 'd']
```

⚠️ **Crash: what if `split` cannot find the separator?**

```python
s = "helloworld"
print(s.split(","))      # ['helloworld'] — no error; the whole string comes back in a list
```

When there is nothing to split, the whole string is returned, still wrapped in a list. This is often used for "tentative parsing" — but do not expect it to tell you that nothing was split.

### `strip`: clearing whitespace

```python
name = "   Alice   "
print(name.strip())      # "Alice"
```

With no argument, `strip()` removes **all whitespace** from both ends (spaces, newlines, tabs). You can also tell it which characters to remove:

```python
s = "###Important###"
print(s.strip("#"))      # Important
```

⚠️ **Crash: `strip` does not mean "remove this exact prefix and suffix" — it means "remove any of these characters".**

```python
s = "abcFOOcab"
print(s.strip("abc"))    # FOO
```

It repeatedly peels characters from both ends that belong to the given set, stopping at the first one that does not. So the result is not necessarily "the prefix you expected removed".

### `find` and `startswith`: looking for things

```python
url = "https://example.com"
print(url.startswith("https"))     # True
print(url.find("example"))        # 8
print(url.find("github"))         # -1 — not found
```

When `find` cannot locate the substring it returns `-1`, not an error and not `None`. This differs from the list method `index`:

```python
"abc".index("z")        # WRONG  ValueError: substring not found
```

**Use `in` or `find` when you only need to know whether it is present, `find` when you need the position, and `index` only when you are certain it exists.**

## 3. `join`: gluing a list back together

`join` is the reverse of `split`:

```python
parts = ["Alice", "07123456789", "London"]
line = ",".join(parts)
print(line)             # Alice,07123456789,London
```

Notice the slightly **counter-intuitive** shape: **the separator is the one calling `join`, and the list is passed in.**

```python
",".join(parts)      # correct
parts.join(",")      # WRONG  AttributeError: 'list' object has no attribute 'join'
```

Why this design? Because "what glues things together" is the string's job; the list only supplies the elements. Say it out loud and it clicks: "comma, join these parts".

## 4. Why `join` beats `+=`

Suppose you want to glue a bunch of words into a sentence:

```python
words = ["I", "love", "writing", "Python"]
```

**The `+=` approach:**

```python
s = ""
for w in words:
    s += w
print(s)          # IlovewritingPython
```

**The `join` approach:**

```python
s = "".join(words)
print(s)          # IlovewritingPython
```

The result is the same, but `join` is clearly shorter. The bigger difference is **performance**:

Strings are immutable, so each step of `s += w` **builds a brand new string**, copying the previous content and then attaching the new piece. More words means more repeated copying — at a thousand words, the total amount copied is roughly a thousand times the final length.

`join`, on the other hand, **knows the total size up front**, allocates enough memory once, and assembles everything in a single pass.

⚠️ **Crash: using `+=` in a loop until it becomes a problem.**

This is not an error you will see — it is a **performance hazard**. Concatenating strings with `+=` inside a loop gets visibly slow at scale; using `join` (or collecting fragments into a list first and calling `join` once at the end) stays predictable.

A useful rule of thumb: when building a string in a loop, **collect into a list first, then `join` once the loop ends**.

```python
lines = []
for name in ["Alice", "Bob", "Carol"]:
    lines.append(f"Hello, {name}")
text = "\n".join(lines)
print(text)
```

## Summary

- Strings are immutable: `s[0] = 'X'` is illegal. What looks like "changing" a string is just the variable being pointed at a new one.
- Every string method **returns a new string** and never alters the original — `s = s.replace(...)` is the correct form.
- `split` breaks into a list, `join` glues back into a string, and `join` is called on the separator.
- `strip` removes a **set of characters**, not a fixed prefix; `find` returns `-1` when it fails.
- When building strings in a loop, use a list plus `join` rather than `+=`.
