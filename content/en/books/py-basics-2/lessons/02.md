# Indexes: Pulling Things Out by Position

> A list can hold a pile of things now. But storing them is useless on its own — you need to **take one out and use it**.
>
> For example: get the third student's score, change the last element, check whether the first one is empty.
>
> This lesson covers the list's **collection code: the index**.

## 1. Why You Need an Index

A list looks like this:

```python
scores = [87, 92, 78, 95, 61]
```

Now you want to print just the second score, 92. How?

**Not `scores(2)`** — a list isn't a function. You fetch elements with square brackets:

```python
scores = [87, 92, 78, 95, 61]
print(scores[1])
```

```
92
```

The key point: `scores[1]` gives you **92**, which is the *second* element.

## 2. Indexes Start at 0 (Every Beginner's First Wall)

```
scores  →  ┌────┬────┬────┬────┬────┐
           │ 87 │ 92 │ 78 │ 95 │ 61 │
           └────┴────┴────┴────┴────┘
index:       0    1    2    3    4
"the nth":  1st  2nd  3rd  4th  5th
```

**Indexes count from 0, not 1.** So "the 3rd one" has index 2.

Why is it so counter-intuitive? Because an index really means **offset**:

> `scores[0]` = zero steps past the start → the first
> `scores[1]` = one step past the start → the second

The starting point is offset 0 from itself, so the first is 0. This is the convention in nearly every language (C, Java, JavaScript all do it), and once you're used to it you'll find it's actually more consistent.

⚠️ **The most common crash: being off by one.**

```python
scores = [87, 92, 78, 95, 61]
print(scores[5])      # ✗ IndexError: list index out of range
```

The list has five elements, so valid indexes are **0 through 4**. `scores[5]` is out of range.

**How to remember**: the last element's index is always `len(list) - 1`.

```python
scores = [87, 92, 78, 95, 61]
print(scores[len(scores) - 1])     # 61, the last one
```

## 3. Negative Indexes: Counting Backwards

Writing `len(scores) - 1` every time is tedious. Python has a nicer way:

```python
scores = [87, 92, 78, 95, 61]

print(scores[-1])     # 61, the last
print(scores[-2])     # 95, second to last
print(scores[-5])     # 87, fifth from the end (i.e. the first)
```

**Negative indexes start at -1**: -1 is the last, and they get smaller as you move forward.

```
           ┌────┬────┬────┬────┬────┐
           │ 87 │ 92 │ 78 │ 95 │ 61 │
           └────┴────┴────┴────┴────┘
positive:    0    1    2    3    4
negative:   -5   -4   -3   -2   -1
```

**Why -1 and not -0?** Because `-0` *is* `0` — two indexes would collide and you couldn't tell the first from the last. So the last one is defined as -1.

⚠️ Negative indexes can go out of range too:

```python
scores = [87, 92, 78, 95, 61]
print(scores[-6])     # ✗ IndexError, only 5 elements exist
```

The smallest legal negative index is `-len(list)`.

### When to Use Negative Indexes

**Whenever you want the last (or last few) elements**, they're clearly cleaner:

```python
# wordy
print(scores[len(scores) - 1])

# clean
print(scores[-1])
```

## 4. An Index Doesn't Just Read — It Can Write

Lists are mutable (lesson 1 said so), so an index can sit on the left of `=`:

```python
scores = [87, 92, 78, 95, 61]

scores[0] = 100          # change the first to 100
print(scores)
```

```
[100, 92, 78, 95, 61]
```

Read it as: **put 100 into locker number 0 of scores.**

The same works with negative indexes:

```python
scores[-1] = 0
print(scores)
```

```
[100, 92, 78, 95, 0]
```

⚠️ But assigning to an index that **doesn't exist** is an error too — it won't silently grow the list:

```python
scores = [87, 92]
scores[5] = 100     # ✗ IndexError: list assignment index out of range
```

To add something at the end, you need `append` (lesson 3). **An index can only change a position that already exists.**

## 5. What "Out of Range" Means, and How to Avoid It

Here's the full error:

```python
scores = [87, 92, 78]
print(scores[3])
```

```
IndexError: list index out of range
```

It means "the index is beyond the end". You asked for locker 3, but this list only has 0, 1, 2.

**Two out-of-range mistakes beginners make constantly:**

**① Running one loop iteration too many.**

```python
scores = [87, 92, 78]
for i in range(4):          # range(4) gives 0,1,2,3 — one too many
    print(scores[i])        # crashes on the last round
```

Use `range(len(scores))` instead:

```python
scores = [87, 92, 78]
for i in range(len(scores)):
    print(scores[i])
```

**② Fetching from an empty list.**

```python
bag = []
print(bag[0])      # ✗ IndexError, there are no elements
```

Checking the length first is a good habit:

```python
bag = []
if len(bag) > 0:
    print(bag[0])
else:
    print("The bag is empty")
```

## 6. One Easily Confused Pair

| Written as | What it means |
|---|---|
| `scores[0]` | the first element — the **number** `87` |
| `scores[0:1]` | a slice (lesson 4) — the **list** `[87]` |

One gives a value, the other gives a list. One colon apart, completely different types.

```python
scores = [87, 92, 78]

print(scores[0])       # 87
print(scores[0:1])     # [87]
print(type(scores[0]))      # <class 'int'>
print(type(scores[0:1]))    # <class 'list'>
```

This difference becomes very important in lesson 4, on slicing.

```quiz
type: code
q: Given `scores = [87, 92, 78, 95, 61]`, print its **last** element (using a negative index), then print its **first** element.
starter: |
  scores = [87, 92, 78, 95, 61]

  # print the last one (using a negative index)

  # print the first one

tests:
- assert "61" in __out
- assert "87" in __out
hint: The last element's index is -1. The first element's index is 0 (not 1). Write the two print calls on separate lines.
explain: The answer is print(scores[-1]) and print(scores[0]). This drills two traps at once: negative indexes start at -1 (not -0), and positive indexes start at 0 (not 1). scores[-5] would also give you 87, but the question asks for "the first" — using 0 is clearer and far less error-prone.
```

## Section Quiz

```quiz
type: choice
exam: true
q: With `letters = ["a", "b", "c", "d"]`, what is `letters[-2]`?
options:
- "b"
- "c"
- "d"
- It errors — negative indexes don't exist
answer: 1
explain: Negative indexes count backwards from -1: -1 is d, -2 is c, -3 is b, -4 is a. So letters[-2] is "c". Positive index 2 is also "c" — both point at the same element, they just count in opposite directions.
```

```quiz
type: code
exam: true
q: Given `data = [10, 20, 30]`, do two things: change the second element (20) to 99, then print the whole list.

  data = [10, 20, 30]

  # change the second element to 99

  print(data)
tests:
- assert "[10, 99, 30]" in __out

explain: You fill in data[1] = 99. The second element has index 1, not 2 — that's the easiest mistake in this lesson. Writing data[2] = 99 changes the 30 instead, giving [10, 20, 99], and the test won't pass. That assertion exists specifically to confirm you counted right.
```
