# Indexes: Reaching in by Position

> A list can hold a whole pile of values, but stuffing them in is useless if you cannot **take one back out**.
>
> For example: pull out the third student's score, change the last element, or check whether the first item is empty.
>
> This lesson is about the list's **address system: the index**.

## 1. Why you need an index

Here is a list:

```python
scores = [87, 92, 78, 95, 61]
```

Now you want to print the second score, 92. How do you write it?

**You do not write `scores(2)`** — a list is not a function. To fetch an element, you use square brackets:

```python
scores = [87, 92, 78, 95, 61]
print(scores[1])
```

Output:

```
92
```

The key point: `scores[1]` gives you **92**, the "second" element.

## 2. Indexes start at zero (your first real hurdle)

```
scores  →  ┌────┬────┬────┬────┬────┐
           │ 87 │ 92 │ 78 │ 95 │ 61 │
           └────┴────┴────┴────┴────┘
index:        0    1    2    3    4
position:     1st  2nd  3rd  4th  5th
```

**Indexes start at 0, not at 1.** So the "third" element is at index 2.

Why this seemingly backwards rule? Because an index really means **an offset**:

> `scores[0]` = move 0 steps from the start → the first
> `scores[1]` = move 1 step from the start → the second

The starting position itself is 0 steps away, so the first element is 0. This is the convention in almost every language (C, Java, JavaScript are all the same), and once it clicks it actually feels more consistent.

⚠️ **The classic crash: you drift off by one.**

```python
scores = [87, 92, 78, 95, 61]
print(scores[5])      # WRONG  IndexError: list index out of range
```

The list has five elements, so the indexes run from **0 to 4**. `scores[5]` is past the end.

**Rule of thumb:** the last index is always `len(list) - 1`.

```python
scores = [87, 92, 78, 95, 61]
print(scores[len(scores) - 1])     # 61, the last element
```

## 3. Negative indexes: counting from the end

Writing `len(scores) - 1` every time gets old. Python gives you a cleaner shortcut:

```python
scores = [87, 92, 78, 95, 61]

print(scores[-1])     # 61, the last element
print(scores[-2])     # 95, the second to last
print(scores[-5])     # 87, the fifth from the end (which is the first)
```

**Negative indexes start at -1**, and -1 is the last element. The further back you go, the smaller the number.

```
           ┌────┬────┬────┬────┬────┐
           │ 87 │ 92 │ 78 │ 95 │ 61 │
           └────┴────┴────┴────┴────┘
positive:    0    1    2    3    4
negative:   -5   -4   -3   -2   -1
```

**Why does it start at -1 instead of -0?** Because `-0` is just `0`, so the two indexes would collide — Python could not tell the first from the last. So the last element is -1.

⚠️ Negative indexes can go out of range too:

```python
scores = [87, 92, 78, 95, 61]
print(scores[-6])     # WRONG  IndexError, the list only has 5 elements
```

The smallest valid negative index is `-len(list)`.

### When negative indexes earn their keep

**Any time you want the last (or the last few) elements**, a negative index is far cleaner:

```python
# wordy
print(scores[len(scores) - 1])

# clean
print(scores[-1])
```

## 4. An index does not only "fetch" — it can also "assign"

A list is mutable (Lesson 1), so an index can sit on the left side of an assignment:

```python
scores = [87, 92, 78, 95, 61]

scores[0] = 100          # change the first element to 100
print(scores)
```

Output:

```
[100, 92, 78, 95, 61]
```

Read it as: **put 100 into locker number 0 of scores.**

The same trick works with negative indexes:

```python
scores[-1] = 0
print(scores)
```

Output:

```
[100, 92, 78, 95, 0]
```

⚠️ **But assigning to a slot that does not exist still raises an error — it will not grow the list for you.**

```python
scores = [87, 92]
scores[5] = 100     # WRONG  IndexError: list assignment index out of range
```

To add at the end you need `append`, which Lesson 3 covers. **An index can only change a position that already exists.**

## 5. What "out of range" really means, and how to avoid it

Here is the full error one more time:

```python
scores = [87, 92, 78]
print(scores[3])
```

Output:

```
IndexError: list index out of range
```

It means "list index out of range". You asked for locker 3, but this list only has lockers 0, 1, and 2.

**Two out-of-range mistakes beginners make constantly:**

**① The loop runs one extra time.**

```python
scores = [87, 92, 78]
for i in range(4):          # range(4) gives 0,1,2,3 — that 3 is one too many
    print(scores[i])        # crashes on the final round
```

Use `range(len(scores))` instead:

```python
scores = [87, 92, 78]
for i in range(len(scores)):
    print(scores[i])
```

**② Fetching from an empty list.**

```python
bag = []
print(bag[0])      # WRONG  IndexError, there is nothing there
```

It is good practice to peek at the length first:

```python
bag = []
if len(bag) > 0:
    print(bag[0])
else:
    print("The bag is empty")
```

## 6. An easy confusion, worth clearing up now

| Writing | Meaning |
|---|---|
| `scores[0]` | Fetch the first element — the result is the **number** `87` |
| `scores[0:1]` | A slice (Lesson 4) — the result is the **list** `[87]` |

One gives you a value, the other gives you a list. A single colon changes the type entirely.

```python
scores = [87, 92, 78]

print(scores[0])       # 87
print(scores[0:1])     # [87]
print(type(scores[0]))      # <class 'int'>
print(type(scores[0:1]))    # <class 'list'>
```

This distinction becomes critical in Lesson 4, when slices enter the picture.

```quiz
type: code
q: Given the list `scores = [87, 92, 78, 95, 61]`, print its **last** element using a negative index, then print its **first** element.
starter: |
  scores = [87, 92, 78, 95, 61]

  # print the last element using a negative index

  # print the first element
tests:
- assert "61" in __out
- assert "87" in __out
hint: The last element's index is -1. The first element's index is 0 (not 1). Write two separate print lines.
explain: The answer is print(scores[-1]) followed by print(scores[0]). Two traps sit next to each other here: negative indexes start at -1 (not -0), and positive indexes start at 0 (not 1). Writing scores[-5] would also reach 87, but the question asks for "the first", and 0 is the more direct, less error-prone choice.
```

- "c"
- "d"
