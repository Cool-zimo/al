# Iterating Dictionaries and Other Common Operations

> So far we have handled one dictionary entry at a time. This lesson is about **batch** operations: how to walk through every key, value, and key-value pair, plus the error you are almost certain to hit.

## 1. `keys`, `values`, `items`: three views

A dictionary gives you three methods for getting at its contents:

| Method | What it yields | One loop step gives you |
|---|---|---|
| `d.keys()` | every key | one key |
| `d.values()` | every value | one value |
| `d.items()` | every key-value pair | one `(key, value)` tuple |

```python
scores = {"Alice": 92, "Bob": 78, "Carol": 100}
```

### Walking the keys: `keys()`

```python
for name in scores.keys():
    print(name)
```

```
Alice
Bob
Carol
```

In fact **`for name in scores` is enough** — `keys()` can be omitted:

```python
for name in scores:
    print(name)        # exactly the same result
```

### Walking the values: `values()`

```python
for s in scores.values():
    print(s)
```

```
92
78
100
```

### Walking key-value pairs: `items()` (the most useful)

```python
for name, score in scores.items():
    print(f"{name}: {score}")
```

```
Alice: 92
Bob: 78
Carol: 100
```

`items()` yields `(key, value)` tuples, and combined with **tuple unpacking** from the previous chapter you receive both pieces at once. This is the **recommended** way to iterate a dictionary.

⚠️ **Crash: wanting both key and value while iterating, but not using items.**

```python
for name in scores:
    print(name, scores[name])       # works, but redundant
```

It works, but you look the value up in the dictionary a second time. With `items()` the code is clearer and avoids that extra lookup.

⚠️ **Crash: treating the result of items as a list.**

```python
print(scores.items())      # dict_items([('Alice', 92), ('Bob', 78), ('Carol', 100)])
```

In Python 3, `keys()`, `values()`, and `items()` return **view objects**, not lists. They look list-like and iterate fine, but you cannot index them or call `append` on them.

To get a real list, convert explicitly:

```python
names = list(scores.keys())
print(names)               # ['Alice', 'Bob', 'Carol']
```

## 2. The classic error: do not mutate while iterating

This is the **most frequent trap** in the chapter — remember it.

First, an example that **looks fine**:

```python
d = {"a": 1, "b": 2, "c": 3}
for k in d:
    if d[k] < 2:
        del d[k]
print(d)          # {'b': 2, 'c': 3} — got lucky
```

Now the **same shape** of code, different data:

```python
d = {"a": 1, "b": 0, "c": 1}
for k in d:
    if d[k] < 1:
        del d[k]
print(d)          # RuntimeError: dictionary changed size during iteration
```

Why does one sometimes sneak by and the other raise? Because Python **does not allow you to change a dictionary's structure** (adding or removing keys) while you iterate over it. When you are lucky nothing trips the check; when you are not, it raises immediately.

⚠️ **Classic crash: deleting entries while looping over the dictionary.**

```python
scores = {"Alice": 92, "Bob": 78, "Carol": 100, "Diana": 55}
for name in scores:
    if scores[name] < 60:
        del scores[name]      # WRONG  RuntimeError
```

**The fix: iterate over a copy of the dictionary, or collect the keys to remove and delete them afterwards.**

### Fix 1: iterate over a list copy of the keys

```python
for name in list(scores.keys()):
    if scores[name] < 60:
        del scores[name]
print(scores)      # {'Alice': 92, 'Bob': 78, 'Carol': 100}
```

`list(scores.keys())` builds an **independent list** first. Iterating over that list cannot disturb the dictionary, so deleting from the dictionary is safe.

### Fix 2: collect first, delete after

```python
to_remove = []
for name, score in scores.items():
    if score < 60:
        to_remove.append(name)

for name in to_remove:
    del scores[name]
```

Write down who must go, then act once the loop is finished. This same idea applies to lists too — recall the "deleting while iterating skips elements" trap from Lesson 3; the solution is identical.

**Hold to this principle: while iterating over a container, do not add or remove its keys/elements.** If you must change it, iterate a copy, or collect first and act afterwards.

## 3. Sorting dictionaries

A dictionary does not really *care* about order (Python 3.7+ preserves insertion order, but **do not rely on it for sorting purposes**). When you want "sorted by value" or "sorted by key", use `sorted`.

### Sort by key

```python
scores = {"Alice": 92, "Bob": 78, "Carol": 100}
for name in sorted(scores):
    print(name, scores[name])
```

```
Alice 92
Bob 78
Carol 100
```

`sorted(scores)` is equivalent to `sorted(scores.keys())` and returns a **list of keys** in sorted order.

### Sort by value

Use `sorted`'s `key` argument to say "what to compare by":

```python
scores = {"Alice": 92, "Bob": 78, "Carol": 100}
for name in sorted(scores, key=lambda k: scores[k]):
    print(name, scores[name])
```

```
Bob 78
Alice 92
Carol 100
```

`key=lambda k: scores[k]` means: during sorting, compare using the value belonging to each key.

⚠️ **Crash: `sorted(scores.items())` sorts by key, not by value.**

```python
scores = {"Alice": 92, "Bob": 78}
print(sorted(scores.items()))      # [('Alice', 92), ('Bob', 78)] — sorted by key
```

For sorting by value you must supply `key`:

```python
print(sorted(scores.items(), key=lambda item: item[1]))
# [('Bob', 78), ('Alice', 92)]
```

`item` is a `(key, value)` tuple, and `item[1]` is the value.

## Summary

- `keys()`, `values()`, `items()` iterate keys, values, and key-value pairs respectively.
- For key-value pairs use `for k, v in d.items()` — the recommended form.
- **Never add or remove keys while iterating a dictionary**, or you get a `RuntimeError`; iterate a copy or collect then delete.
- `sorted(d)` sorts by key; for sorting by value write `key=lambda k: d[k]`.
- The three view methods do not return lists; wrap them in `list()` if you need a list.
