# String Formatting: Slipping Data into Strings

> In earlier lessons you have probably written code like this:
>
> ```python
> print("Total is " + str(price) + " pounds, at " + str(discount) + " percent off")
> ```
>
> A tangle of `+` signs and `str()` calls. This lesson covers **formatting** — a cleaner way to slot variables into strings.

## 1. `%` formatting: the old way, now obsolete

This was the original approach, and it looks like C's `printf`:

```python
name = "Alice"
age = 28
s = "My name is %s and I am %d years old" % (name, age)
print(s)          # My name is Alice and I am 28 years old
```

`%s` means "a string goes here", `%d` means "an integer goes here", and the `%` at the end takes a tuple of values.

It has two obvious problems:

1. **Too many symbols to memorise:** `%s`, `%d`, `%f`, `%r` — get one wrong and you get an error.
2. **The order is rigid:** values must line up with placeholders in order, and inserting a new value means recounting positions.

```python
"Total £%.2f, discount %d%%" % (128.567, 8)
# Total £128.57, discount 8%
```

`%.2f` means "a floating-point number with 2 decimal places". It works, but it feels awkward.

⚠️ **Crash: the number of placeholders and values do not match.**

```python
"My name is %s and I am %d years old" % ("Alice",)
# WRONG  TypeError: not enough arguments for format string
```

If you supply one value too few, it raises an error. This happens often, especially when a string holds many variables and you keep adjusting the wording.

**Verdict: `%` works, but do not reach for it.** You will see it in older code; for new code, use one of the two approaches below.

## 2. `str.format`: the middle ground

`format` uses `{}` as a placeholder and `.format()` to supply the values:

```python
name = "Alice"
age = 28
s = "My name is {} and I am {} years old".format(name, age)
print(s)          # My name is Alice and I am 28 years old
```

Cleaner than `%`: the placeholder is uniformly `{}`, so there is no `%s` versus `%d` to remember.

You can also number the placeholders to reorder them:

```python
"{} is {} years old, and {} is male".format("Alice", 28, "he")
# Alice is 28 years old, and he is male

"{0} {0} {1}".format("hi", "ya")
# hi hi ya — the same position can be reused
```

And you can use **named arguments**:

```python
"My name is {name} and I come from {city}".format(name="Bob", city="London")
# My name is Bob and I come from London
```

That last form is highly readable for template-style strings.

⚠️ **Crash: writing the braces but forgetting to call `format`.**

```python
s = "My name is {} and I am {} years old"
print(s)          # My name is {} and I am {} years old — the braces stay put
```

`{}` is only a placeholder, and it only gets replaced when you actually call `.format()`. Forget the call and it prints as-is.

## 3. f-strings: the recommended style today

Introduced in Python 3.6, f-strings are now the most common and the most readable option. Put an `f` in front of the string, and you can write **variable names directly inside the `{}`**:

```python
name = "Alice"
age = 28
s = f"My name is {name} and I am {age} years old"
print(s)          # My name is Alice and I am 28 years old
```

The variable name goes right inside `{}`; there is no need to list the values at the end. **Readability is the best you will get** — the variable and where it appears in the sentence sit side by side.

⚠️ **Crash: forgetting the `f` prefix.**

```python
name = "Alice"
s = "My name is {name}"      # no f
print(s)                     # My name is {name} — printed literally
```

This is by far the most frequent mistake. Build the habit: **the moment a string contains `{}`, put an `f` in front of it.**

## 4. Useful f-string tricks

### 4.1 Putting expressions inside

The `{}` can hold **not just variables but any expression**:

```python
price = 128.5
count = 3
print(f"Total £{price * count}")       # Total £385.5
print(f"Doubled: {count * 2}")         # Doubled: 6
```

```python
name = "alice"
print(f"Upper: {name.upper()}")         # Upper: ALICE
```

⚠️ **Crash: trying to put an assignment inside `{}`.**

```python
n = 10
f"{n = }"        # this is the Python 3.8+ "debug expression", and prints 'n = 10'
f"{n = 20}"      # WRONG  SyntaxError
```

A normal `{}` can only contain an expression; `n = 20` is an assignment, which is not allowed. If you need to change a variable, do it outside the f-string.

### 4.2 Alignment and width

Very useful for tabular output:

```python
names = ["Alice", "Bob", "Carol"]
scores = [92, 78, 100]
for n, s in zip(names, scores):
    print(f"{n:6} {s:4}")
```

Output:

```
Alice     92
Bob       78
Carol    100
```

`{n:6}` means "occupy 6 character-widths, right-aligned by default". For left alignment add `<`:

```python
print(f"{'Alice':<6}|")      # Alice  |
print(f"{'Alice':>6}|")      #   Alice|
```

`<` is left-aligned, `>` is right-aligned, `^` centres. The number is the **total width** (measured in characters; wide characters such as Chinese take two columns, so the columns can look slightly uneven — keep that in mind).

### 4.3 Decimal places

```python
pi = 3.1415926
print(f"Pi is roughly {pi:.2f}")      # Pi is roughly 3.14
print(f"{pi:.4f}")                    # 3.1416
```

`:.2f` means "format as a float with 2 decimal places". This is the most-used format specifier in f-strings.

You can combine width and decimal places:

```python
price = 12.5
print(f"£{price:>8.2f}")      # £   12.50
```

⚠️ **Crash: using `:.2f` on an integer.**

```python
n = 100
f"{n:.2f}"        # '100.00' — no error, but two decimal places were added
```

It does not raise an error, but the result becomes `100.00`, which may not be what you wanted. If you intend to show decimal places, make sure the value is actually a float first.

### 4.4 Thousands separators

```python
n = 1234567
print(f"{n:,}")          # 1,234,567
print(f"{n:_}")          # 1_234_567
```

A comma or an underscore both work as a thousands separator — handy for prices and large numbers.

## 5. Which style should you choose?

| Style | Writing | Recommendation |
|---|---|---|
| `%` formatting | `"%s %d" % (a, b)` | Obsolete, not recommended |
| `str.format` | `"{} {}".format(a, b)` | Fine, common in older code |
| **f-string** | `f"{a} {b}"` | **The default choice** |

For everyday code, f-strings are the right answer. Their advantage is that **the variable and its placeholder sit in the same place**, so you never jump back and forth between the string and a `.format()` argument list.

⚠️ **Crash: you want a literal `{` character inside an f-string.**

```python
f"A dictionary is written with {{ and }}"      # correct: double the braces
# Output: A dictionary is written with { and }
```

`{{` is interpreted as a literal `{`. This comes up whenever you write JSON or template-style text.

## Summary

- `%` formatting is obsolete: too many placeholder symbols and a rigid ordering.
- `str.format` uses `{}` placeholders; readable enough, common in older code.
- **f-strings are the default:** put `f` in front of the string and write variables or expressions directly inside `{}`.
- Common formats: `:<6` for left alignment, `:>8.2f` for right-aligned with 2 decimal places, `:,` for thousands separators.
- To output a literal `{`, write `{{`.
