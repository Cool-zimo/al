# Return Values: One, Several, and "Returning Early"

> The previous lesson was about getting values **in**. This one is about handing a result **back**: `return` can give back one value, several values (actually a tuple), end the function early, and how to test for `None`.
>
> The key idea of this lesson: **"returning several values" is just sugar — underneath it is tuple unpacking.**

## 1. Returning a single value

The basic case: compute a result, hand it back with `return`.

```python
def celsius_to_fahrenheit(c):
    return c * 9 / 5 + 32

f = celsius_to_fahrenheit(100)
print(f)        # 212.0
```

The caller gets whatever stands after `return` — it can be stored in a variable, put in a list, or passed straight into another function.

## 2. Returning several values: it is really a tuple

Python lets you `return` several values, separated by commas:

```python
def split_name(full_name):
    parts = full_name.split("·")
    return parts[0], parts[1]        # two values

first, last = split_name("Alice·Smith")
print(first)        # Alice
print(last)         # Smith
```

It *looks* like "two values came back", but **only one thing was returned: a tuple with two elements**.

```python
result = split_name("Alice·Smith")
print(result)        # ('Alice', 'Smith') -- just a tuple
print(type(result))  # <class 'tuple'>
```

The line `first, last = ...` is **tuple unpacking** (Lesson 6): the two elements of the tuple are assigned to two variables. The function never "returned two things"; it returned one tuple.

⚠️ **Crash: thinking you got several values, then indexing them wrong.**

```python
def get_point():
    return 3, 5

x = get_point()
print(x[0])        # 3 -- but x is actually a tuple
print(x[1])        # 5
```

This is not wrong, but it feeds the illusion of "several things came back". Remember: **`return a, b` is exactly the same as `return (a, b)`.**

## 3. Receiving: unpack, or keep the tuple

```python
def stats(numbers):
    return min(numbers), max(numbers), sum(numbers) / len(numbers)

# style 1: unpack into three variables
lo, hi, avg = stats([10, 20, 30, 40])
print(lo, hi, avg)        # 10 40 25.0

# style 2: keep the whole tuple
result = stats([10, 20, 30, 40])
print(result)             # (10, 40, 25.0)
```

⚠️ **Crash: the number of variables does not match.**

```python
lo, hi = stats([10, 20, 30])      # WRONG  ValueError: too many values to unpack (expected 2)
```

`stats` returns a 3-tuple, but you only gave it two names. **The tuple size and the variable count must agree** (unless you use `*` to collect the rest — covered later).

## 4. Early return: "get out while you can"

Once `return` runs, the function ends on the spot; nothing after it executes. That makes it great for "bailing out":

```python
def safe_divide(a, b):
    if b == 0:
        return "Cannot divide by zero"        # hit this and stop
    return a / b                             # otherwise reach here

print(safe_divide(10, 0))        # Cannot divide by zero
print(safe_divide(10, 2))        # 5.0
```

This style — **handle the bad cases first, then do the real work** — is called a **guard clause**, and it is far cleaner than nested `if/else`:

```python
# not recommended: the nested nightmare
def safe_divide(a, b):
    if b != 0:
        if a > 0:
            if b < 100:
                return a / b
    return "no"

# recommended: rule them out one by one
def safe_divide(a, b):
    if b == 0:
        return "Cannot divide by zero"
    if a <= 0:
        return "Dividend must be positive"
    if b >= 100:
        return "Divisor too large"
    return a / b
```

⚠️ **Crash: assuming code still runs after `return`.**

```python
def process(x):
    if x < 0:
        return "negative"
    print("Does this line run?")

process(-1)        # returns "negative", prints nothing
```

`return "negative"` ends the function, so the `print` never runs. This is a feature, not a bug — **but if you thought the line below would run, you have written "dead code" that never executes.**

## 5. Testing for `None`

A function with no `return` returns `None`. To check whether a function returned `None`, use `is`:

```python
def find_user(users, name):
    for u in users:
        if u["name"] == name:
            return u
    # not found, falls through, returns None

alice = find_user([{"name": "Alice"}], "Bob")
if alice is None:
    print("User not found")
else:
    print("Found")
```

⚠️ **Crash: using `==` to test for `None`.**

```python
if alice == None:        # runs, but not the recommended style
    print("not found")
```

`is` asks "are these the very same object", while `==` asks "are their values equal". `None` is a singleton, so the convention is **always `is None` / `is not None`.**

⚠️ **Crash: using `if` on the result, and treating 0, empty strings and empty lists as "not found".**

```python
def get_score(name):
    scores = {"Alice": 0, "Bob": 95}
    if name in scores:
        return scores[name]
    return None

s = get_score("Alice")
if not s:                  # WRONG  Alice's score is 0, also treated as "not found"
    print("not found")
```

Alice's score is 0, and `not 0` is `True`, so she is wrongly called "not found". **When the return value could be 0, an empty string or an empty list (all falsy), do not write `if not s`; write `if s is None`.**

## 6. A worked example: an order amount

```python
def calc_order(price, quantity, discount=0, vip=False):
    if price <= 0 or quantity <= 0:
        return None, "Price or quantity invalid"

    amount = price * quantity
    amount -= amount * discount
    if vip:
        amount *= 0.9
    return round(amount, 2), "ok"

total, msg = calc_order(100, 2, discount=0.1, vip=True)
print(total, msg)        # 162.0 ok

total, msg = calc_order(-10, 2)
print(total, msg)        # None Price or quantity invalid
```

It returns **two values: the result and a status message**. On success you get the amount plus `"ok"`; on failure you get `None` plus a reason. The caller receives both "what was computed" and "what it means".

⚠️ **Crash: catching only one value, and losing the message.**

```python
total = calc_order(100, 2, discount=0.1, vip=True)
print(total)        # (162.0, 'ok') -- that is the whole tuple, msg is lost
```

You expected `total` to be a number, but it is `(162.0, 'ok')`. **Catch as many values as you return; do not leave any behind.**

## Summary

- `return a, b` actually returns one tuple `(a, b)`; "several values" is sugar
- Two ways to receive: unpack into variables, or keep the tuple
- When unpacking, variable count must match the tuple length
- An early `return` is the heart of the guard-clause pattern
- Test for `None` with `is None`, not `==`
- When the result could be 0/empty string/empty list, do not use `if not x`; use `if x is None`
