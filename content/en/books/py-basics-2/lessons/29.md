# Recursion: A Function Calling Itself

> Recursion is "a function that calls itself". It sounds like a tongue-twister, but it is a natural fit for **nested structures that break down into smaller versions of the same problem**.
>
> This lesson covers two things: **how to write it correctly** (it must have a stopping condition), and **when to use it — and when not to.**

## 1. The simplest recursion: factorial

Factorial `n! = n × (n-1) × ... × 1` is defined in terms of a smaller version of itself:

```python
def factorial(n):
    if n <= 1:                # stopping condition
        return 1
    return n * factorial(n - 1)   # call itself

print(factorial(5))        # 120
```

The execution unfolds like this:

```
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 5 * 4 * 3 * 2 * 1
= 120
```

Each step makes the problem a little smaller, until it reaches the smallest case (`n<=1`) and stops.

⚠️ **Crash: forgetting the stopping condition.**

```python
def factorial(n):
    return n * factorial(n - 1)       # no stopping condition!

factorial(5)
# WRONG  RecursionError: maximum recursion depth exceeded
```

It never returns and never stops calling itself, until Python hits its recursion limit (default 1000) and raises `RecursionError`. **A recursive function with no stopping condition always blows up.**

⚠️ **Crash: the wrong stopping condition, missing a boundary.**

```python
def factorial(n):
    if n == 1:            # only catches n == 1, so n == 0 recurses forever
        return 1
    return n * factorial(n - 1)

factorial(0)              # RecursionError
```

`n == 1` catches only 1 and misses 0. **When writing recursion, think through the smallest case carefully** — miss one boundary and it explodes.

## 2. The two iron rules of recursion

**1. There must be a stopping (base) condition**, or it recurses forever.

**2. Each recursive call must make the problem smaller**, moving towards the stopping condition.

```python
def count_down(n):
    if n <= 0:                # stopping condition
        return
    print(n)
    count_down(n - 1)         # smaller: n - 1

count_down(3)
# 3
# 2
# 1
```

`n` decreases by 1 each time and eventually reaches 0, hitting the stopping condition. **If you wrote `count_down(n)` without subtracting 1, it would never reach 0 and would always blow up.**

## 3. Recursion vs loop: Fibonacci

The Fibonacci sequence: 1, 1, 2, 3, 5, 8... (each number is the sum of the previous two).

**The recursive version:**

```python
def fib(n):
    if n <= 2:
        return 1
    return fib(n - 1) + fib(n - 2)

print(fib(6))        # 8
```

The code is almost the mathematical definition itself — **it reads beautifully**. But it is slow: `fib(6)` recomputes `fib(5)` and `fib(4)` separately, and the duplicated work explodes.

**The loop version:**

```python
def fib(n):
    a, b = 1, 1
    for _ in range(n - 2):
        a, b = b, a + b
    return b

print(fib(6))        # 8
```

The loop computes each number exactly once — **much faster**.

⚠️ **Crash: the recursive Fibonacci on a large number is painfully slow.**

```python
fib(50)        # takes far too long, and may RecursionError
```

The recursive `fib(50)` makes roughly 2^50 calls, and a browser-based Pyodide environment will hang or error out. **When there are many repeated subproblems, recursion is the wrong tool.**

## 4. When recursion is the right choice

Recursion fits **structures that are nested by nature**:

**Case 1: a nested hierarchy (a directory tree)**

```python
def walk(dir_path, indent=0):
    print("  " * indent + dir_path)
    # suppose list_dir returns the subdirectories
    # for sub in list_dir(dir_path):
    #     walk(sub, indent + 1)

walk("/home")
```

Directories contain directories, so recursion fits perfectly.

**Case 2: divide and conquer (quicksort)**

```python
def quick_sort(nums):
    if len(nums) <= 1:            # stop: empty or a single element is already sorted
        return nums
    pivot = nums[0]
    left = [x for x in nums[1:] if x < pivot]
    right = [x for x in nums[1:] if x >= pivot]
    return quick_sort(left) + [pivot] + quick_sort(right)

print(quick_sort([3, 1, 4, 1, 5, 9, 2, 6]))
# [1, 1, 2, 3, 4, 5, 6, 9]
```

Each step splits the problem in two, sorts each half, and joins them back. **The structure is clear and the code almost *is* the algorithm description.**

⚠️ **Crash: recursing on a list but forgetting to catch the return value.**

```python
nums = [3, 1, 2]
quick_sort(nums)          # computes a new list but nobody catches it
print(nums)               # [3, 1, 2] -- the original did not change
```

`quick_sort` returns a **new list**; the original is never modified. To keep the result you must write `nums = quick_sort(nums)`.

## 5. Maximum recursion depth

Python guards against runaway recursion with a **recursion limit** (default 1000):

```python
def forever(n):
    return forever(n + 1)

forever(0)
# RecursionError: maximum recursion depth exceeded
```

This is not a bug — it is protection. **If your recursion might go deeper than 1000, do not use recursion** (say, walking a linked list of tens of thousands of nodes).

⚠️ **Crash: using recursion to walk a very deep chain.**

```python
def sum_list(nums, i=0):
    if i >= len(nums):
        return 0
    return nums[i] + sum_list(nums, i + 1)

sum_list(list(range(2000)))      # RecursionError
```

2000 levels exceed the default limit. **This kind of linear walk should use a `for` loop** — recursion is the wrong tool here.

## 6. A safer shape: the tail-recursion idea

Python **does not optimise tail recursion**, but passing the "running total" as a parameter keeps the logic clear and is easy to convert to a loop:

```python
def factorial_tail(n, acc=1):
    if n <= 1:
        return acc
    return factorial_tail(n - 1, acc * n)

print(factorial_tail(5))        # 120
```

Even though Python will not turn it into a loop (it can still hit the depth limit), this "pass the running result along" style is clear and converts cleanly:

```python
def factorial_loop(n):
    acc = 1
    for i in range(2, n + 1):
        acc *= i
    return acc
```

**Reach for a loop when you can; save recursion for structures that nest naturally** — that is Python's pragmatic rule.

## Summary

- Recursion = a function calling itself; ideal for "problems that break into smaller copies of themselves"
- Two rules: **there must be a stopping condition** + **every call must make the problem smaller**
- No stopping condition, or the wrong one → `RecursionError`
- Recursive code reads like a definition but is often slower than a loop (lots of repeated subproblems)
- Python's default recursion limit is 1000; for great depth use a loop
- Directory trees and divide-and-conquer sorts are where recursion really pays off
