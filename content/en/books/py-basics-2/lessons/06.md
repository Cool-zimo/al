# Tuples: Lists That Cannot Change

> A list can grow, shrink, and be rewritten at will. But some data is **never meant to change** — the coordinates of London, someone's name, the fact that a year has twelve months.
>
> This lesson introduces **tuples**: they are almost identical to lists, except that **they cannot be changed**. Learn them, and you will know when to "lock" your data.

## 1. Why have a "cannot change" list at all?

A list is gloriously free: `append`, `remove`, `[i] =`, all fair game. But freedom has a cost:

```python
point = [51.5074, -0.1278]      # the coordinates of London
point[0] = 0                    # changed by accident to the origin
```

Coordinates should never be changed. If you pass a list like this around as a function argument, any piece of code can quietly damage it, and finding the culprit is painful.

**The whole point of a tuple is immutability:** once created, its elements **cannot be changed by anyone.** That buys you two things:

1. **Peace of mind:** you know nothing else can tamper with it.
2. **Tuples can be used as dictionary keys** (Chapter 3 — lists cannot, but tuples can).

⚠️ **Crash: assuming a tuple is "just a read-only list".**

Some people describe tuples as "a list with the mutations taken away", and that is a useful first intuition. But a tuple is **not a subclass of list** — they are two separate types. The real question when choosing between them is "what does this value **represent**", not "do I happen to feel like changing it right now".

## 2. Creating a tuple

Swap the list's square brackets `[ ]` for parentheses `( )` and you have a tuple:

```python
rgb = (255, 128, 0)
print(rgb)              # (255, 128, 0)
print(rgb[0])           # 255
print(type(rgb))        # <class 'tuple'>
```

Tuples support indexing and slicing (because they are a "sequence"):

```python
rgb = (255, 128, 0)
print(rgb[1])           # 128
print(rgb[0:2])         # (255, 128) — slicing returns a tuple
print(len(rgb))         # 3
```

You can even leave the parentheses out — Python recognises a tuple by the **commas**:

```python
point = 51.5074, -0.1278       # valid, equivalent to (51.5074, -0.1278)
x, y = point
print(x, y)                    # 51.5074 -0.1278
```

⚠️ **The classic trap: a single-element tuple must have a trailing comma.**

This is the single most common place for a Python beginner to trip. You want "a tuple containing exactly one element":

```python
a = (5)            # what is this?
print(type(a))     # <class 'int'>  ← it is just an integer!
print(a)           # 5
```

**Parentheses mean "grouping" in mathematics, and they mean "grouping" in Python too.** `(5)` just wraps the number 5 for emphasis; the result is still 5.

```python
a = (5,)           # add the comma, and it becomes a single-element tuple
print(type(a))     # <class 'tuple'>
print(a)           # (5,)
```

Remember the iron rule: **a tuple is defined by its commas, not its parentheses.** A one-element tuple must be written `(5,)`, and that trailing comma is not optional.

```python
b = 5,             # no parentheses, just a comma — still a single-element tuple
print(type(b))     # <class 'tuple'>
```

On the flip side, an empty tuple is `()` or `tuple()`:

```python
empty = ()
print(type(empty))      # <class 'tuple'>
print(len(empty))       # 0
```

Calling `tuple()` also converts a list, string, or other "sequence" into a tuple:

```python
t1 = tuple([1, 2, 3])
print(t1)          # (1, 2, 3)

t2 = tuple("London")
print(t2)          # ('L', 'o', 'n', 'd', 'o', 'n')
```

## 3. What "cannot change" really means

The elements of a tuple cannot be added, removed, or replaced:

```python
rgb = (255, 128, 0)
rgb[0] = 100       # WRONG  TypeError: 'tuple' object does not support item assignment
```

The error message says it plainly: a tuple does not support assignment by position. Likewise, it has no `append`, `remove`, or `pop` methods.

⚠️ **A subtlety: "a tuple is immutable" does not mean "what it contains cannot change".**

This is the easiest misunderstanding. Watch:

```python
data = (1, [2, 3])
data[1].append(4)        # somehow no error!
print(data)              # (1, [2, 3, 4])
```

**What a tuple guarantees is that the references in its slots do not change — not that the objects those references point to stay frozen.** In the example above, `data[1]` always points at the same list; it is just that the list changed itself.

| Operation | Allowed on a tuple? | Explanation |
|---|---|---|
| `t[0] = 1` | No | you cannot replace an element in a slot |
| `t[1].append(x)` | Yes | the list changes itself; the tuple cannot stop it |
| `t.append(x)` | No | a tuple has no such method |

So a tuple can be a dictionary key only if **its elements are also immutable** (numbers, strings, tuples). If it contains a list, it stops working as a key — a point that comes up again in Lesson 14.

## 4. When should you use a tuple?

Here is a practical test:

| Situation | Use | Reason |
|---|---|---|
| You hold **several distinct fields** (coordinates, name + age) | tuple | the fields are fixed and their meaning is clear |
| You hold **a batch of similar items** (a shopping cart, a score sheet) | list | you need to add, remove, and sort |
| The data **must never change** (settings, constants) | tuple | immutable means safe |
| You need a **dictionary key** | tuple | a list is not hashable; a tuple is |

In one sentence: **fields go in tuples, collections go in lists.**

Real examples:

```python
# one entry in an address book — name, phone, email are three distinct fields
contact = ("Alice", "07123456789", "alice@example.com")

# a class score sheet — a batch of similar numbers
scores = [87, 92, 78, 65, 100]
```

The first one uses a tuple, because each position carries a clear meaning (position 0 is always the name). The second uses a list, because you expect to add scores, average them, and sort them.

## Summary

- Tuples are written with `( )`, and they support indexing, slicing, and `len` — they are a "sequence", just like lists.
- **A single-element tuple must be written `(5,)`** — the comma defines the tuple, not the parentheses.
- A tuple **cannot be mutated**, has no `append`, and will raise `TypeError` if you try to replace an element.
- "Immutable" means the references in the slots stay put; a list stored inside the tuple can still change itself.
- Fields belong in tuples, collections in lists; when you need a dictionary key, only a tuple will do.

- [1]
- tuple(1)
