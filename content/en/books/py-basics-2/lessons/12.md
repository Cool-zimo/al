# Dictionaries: Create, Read, Update, Delete

> The previous lesson covered creating a dictionary and reading values by key. This lesson treats the dictionary as a **mutable container** — adding an entry, changing one, removing one, looking one up — plus a few methods designed to save you trouble.

## 1. Read: fetch by key

The basic form is square brackets:

```python
scores = {"Alice": 92, "Bob": 78}
print(scores["Alice"])        # 92
```

But this form has a hard edge — **a missing key raises an error**:

```python
print(scores["Carol"])        # WRONG  KeyError: 'Carol'
```

⚠️ **Crash: reading a key without checking first.**

This is the single most common source of dictionary errors. For safer lookups you have two options.

### Option 1: check with `in` first

```python
if "Carol" in scores:
    print(scores["Carol"])
else:
    print("No score for that person")
```

In a dictionary, `in` tests whether the **key** is present, not the value.

### Option 2: use `get` with a default

```python
value = scores.get("Carol", "not found")
print(value)                # not found
```

The rule for `get(key, default)` is: **if the key exists, return its value; if it does not, return the default you supplied**.

```python
print(scores.get("Alice", 0))     # 92 — present, returns the real value
print(scores.get("Carol", 0))     # 0 — absent, returns the default
```

**With no default, `get` returns `None`:**

```python
print(scores.get("Carol"))        # None
```

⚠️ **Crash: treating `get`'s default as something that "writes into the dictionary".**

```python
v = scores.get("Carol", 0)
print(scores)        # {'Alice': 92, 'Bob': 78} — nothing changed!
```

`get` is **read-only**: it never writes a `"Carol": 0` entry. It just hands you a fallback value when it cannot find the key; the dictionary itself is untouched.

## 2. Create and update: square-bracket assignment

**Adding** an entry and **changing** an entry look exactly the same — both are square-bracket assignment:

```python
scores = {"Alice": 92}
scores["Bob"] = 78        # key absent → create
scores["Alice"] = 100     # key present → update
print(scores)              # {'Alice': 100, 'Bob': 78}
```

**The only test is whether the key exists.** Present means update; absent means create.

⚠️ **Crash: thinking "add" and "update" are two different operations.**

You do not need two rules. Remember one sentence: **square brackets: present updates, absent creates.** One syntax covers both.

## 3. `setdefault`: create the entry if it is missing

This is a genuinely useful and considerate method. The situation:

> I want the value for a key; if it is not there yet, give it a default value first, then fetch it.

The ordinary version takes an `if` plus an assignment, two lines:

```python
words = {}
word = "apple"
if word not in words:
    words[word] = 0
words[word] += 1
```

`setdefault` does it in one line:

```python
words = {}
word = "apple"
words.setdefault(word, 0)
words[word] += 1
print(words)          # {'apple': 1}
```

`setdefault(key, default)` behaves as follows: **if the key exists, do nothing and return the value already stored; if it does not, write `key: default` and return the default.**

Run the same code again:

```python
words.setdefault("apple", 0)      # apple exists, untouched, returns 100 (the stored value)
words["apple"] += 1
print(words)                       # {'apple': 101}
```

Notice that it returns the **value actually stored in the dictionary**, which is not necessarily the default you passed in.

⚠️ **Crash: passing a mutable object as the default and reusing it.**

```python
d = {}
d.setdefault("tags", []).append("python")
d.setdefault("tags", []).append("java")
print(d)          # {'tags': ['python', 'java']}
```

This example **happens to work**, because each `setdefault` finds the key already present and returns the same list. But if you grab that list under another name and mutate it, you can bypass `setdefault` entirely:

```python
lst = d.setdefault("tags", [])
lst.append("go")
print(d)          # {'tags': ['python', 'java', 'go']}
```

Reading is fine; when writing, keep the rule clear: **`setdefault` only creates the default when the key is absent**, and returns the existing value otherwise.

## 4. Merging: `update`

To merge one dictionary into another, use `update`:

```python
prices = {"apple": 0.55, "milk": 0.80}
prices.update({"milk": 0.75, "bread": 0.35})
print(prices)      # {'apple': 0.55, 'milk': 0.75, 'bread': 0.35}
```

Existing keys are overwritten, missing keys are added. Think of it as "bulk assignment".

⚠️ **Crash: expecting `update` to preserve both values, or to merge them into a list.**

```python
a = {"x": 1}
a.update({"x": 2})
print(a)           # {'x': 2} — overwritten, not merged
```

`update` is an overwriting assignment: the later key wins. It will not combine the two values into a list, and it will not raise an error.

## 5. Delete: `pop` and `del`

### `pop(key)`: remove and return

```python
scores = {"Alice": 92, "Bob": 78}
score = scores.pop("Alice")
print(score)        # 92
print(scores)       # {'Bob': 78}
```

`pop` returns the value it removed — just like a list's `pop`.

⚠️ **Crash: popping a key that does not exist raises an error.**

```python
scores.pop("Carol")      # WRONG  KeyError: 'Carol'
```

For safety, supply a default:

```python
v = scores.pop("Carol", None)
print(v)               # None — no error
```

`pop(key, default)` has the same temperament as `get`: **when the key is missing it returns the default and leaves the dictionary alone.**

### `del`: remove, discard the value

```python
del scores["Alice"]
print(scores)          # {'Bob': 78}
```

`del` only deletes; it returns nothing. A missing key raises an error all the same:

```python
del scores["Carol"]     # WRONG  KeyError: 'Carol'
```

| What you want to do | Use |
|---|---|
| Remove and get the value back | `d.pop(key)` |
| Just remove it | `del d[key]` |
| Remove safely, no error | `d.pop(key, default)` |

⚠️ **Crash: writing `d.pop()` with no argument.**

```python
d = {"a": 1}
d.pop()                 # WRONG  TypeError: pop expected at least 1 argument
```

A dictionary's `pop` **must be given a key** (unlike a list's `pop()`, which defaults to "remove the last item" — the idea of "the last key" is not reliable here).

## Summary

- Read: `d[k]` raises `KeyError` when the key is missing; `d.get(k, default)` returns the default and does not change the dictionary.
- Create and update: `d[k] = v` — present updates, absent creates.
- `setdefault(k, v)`: only writes the default when the key is absent; returns the value actually stored.
- `update`: bulk merge, same key overwrites.
- Delete: `pop` returns the removed value, `del` returns nothing; both raise `KeyError` without a default.
