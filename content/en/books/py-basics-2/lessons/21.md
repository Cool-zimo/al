# Why We Need Functions: Stop Copying and Pasting

> Up to now, every program has been one long block of code running from top to bottom. As programs grow, you quickly hit three pains: **repetition**, **hard to change**, and **hard to read**.
>
> This chapter introduces **functions** — a way to wrap a reusable chunk of code, give it a name, and call on it whenever you need it. Mastering functions is when you truly start "writing programs".

## 1. A real problem: the cost of copying and pasting

Imagine you are writing a small class-score tool and need to grade each student:

```python
score1 = 92
if score1 >= 90:
    print("excellent")
elif score1 >= 60:
    print("pass")
else:
    print("fail")

score2 = 55
if score2 >= 90:
    print("excellent")
elif score2 >= 60:
    print("pass")
else:
    print("fail")

score3 = 78
if score3 >= 90:
    print("excellent")
elif score3 >= 60:
    print("pass")
else:
    print("fail")
```

Three nearly identical blocks. Now suppose the requirement changes — you need four bands, "excellent / good / pass / fail". You would have to **edit three places**, and by the time you reach the third your hand slips and a bug appears.

That is the true cost of copying and pasting: **logic should live in exactly one place; writing it three times plants three landmines**.

## 2. Giving a block of code a name

The idea behind a function is almost embarrassingly simple: **wrap the logic, give it a name, then call the name whenever you need it**.

```python
def judge(score):
    if score >= 90:
        print("excellent")
    elif score >= 60:
        print("pass")
    else:
        print("fail")

judge(92)        # excellent
judge(55)        # fail
judge(78)        # pass
```

Three duplicated blocks have become **one**. `def` means "define", `judge` is the name of this logic, and `score` is "what you feed into it". Say `judge(92)` and Python runs that logic.

⚠️ **Crash: trying to call a function before defining it.**

```python
greet("Alice")          # WRONG  NameError: name 'greet' is not defined

def greet(name):
    print("Hello", name)
```

Python executes top to bottom. `greet("Alice")` appears **before** the definition, so the interpreter has never heard of `greet` and raises `NameError`. **Define first, then call** — the order cannot be reversed.

## 3. Functions separate "what it does" from "where it is used"

Without functions, code is "do and use at the same time". With functions it becomes "**define what to do first, then call it where needed**".

```python
# define first: what does this do
def calc_tax(price):
    return price * 0.13

# then use it: call it where needed
total = 100 + calc_tax(100)
print("You pay:", total)        # You pay: 113.0
```

The benefit: **the caller only cares that "it calculates tax"** and does not need to read the formula. This is encapsulation — hide the detail, expose only a name.

⚠️ **Crash: mixing definitions and calls until the file is unreadable.**

```python
print("start")
def f1():
    print("A")
def f2():
    print("B")
f1()
f2()
print("end")
```

This runs, but definitions and calls are all jumbled together. **The usual convention is to group all the `def` lines in the top half of the file and the calls in the bottom half**, or better yet wrap the main logic in a `main()`. This is not a syntax rule, but it will save you.

## 4. Copy-paste versus functions: a real comparison

Same requirement: "apply a discount to each item in a shopping cart".

**The copy-paste version:**

```python
p1 = 100
if p1 >= 200:
    p1 *= 0.8
else:
    p1 *= 0.9
print(p1)

p2 = 300
if p2 >= 200:
    p2 *= 0.8
else:
    p2 *= 0.9
print(p2)
```

**The function version:**

```python
def discount(price):
    if price >= 200:
        return price * 0.8
    return price * 0.9

print(discount(100))        # 90.0
print(discount(300))        # 240.0
```

Now your boss says "spend £300 gets 30% off". **The copy-paste version needs two edits (and you will miss one); the function version needs exactly one change inside `discount`**. That is the whole point of functions — **define once, use everywhere**.

⚠️ **Crash: writing the discount rule three times and only updating two of them.**

```python
p1 = 100
if p1 >= 200:
    p1 *= 0.8
else:
    p1 *= 0.9

p2 = 300
if p2 >= 200:
    p2 *= 0.8
else:
    p2 *= 0.7       # updated here

p3 = 500
if p3 >= 200:
    p3 *= 0.8       # forgot to update here!
else:
    p3 *= 0.9
```

One of the three copies will always be the one you forget. This is not "carelessness" — **people miss things, so make repetition impossible in the first place**.

## 5. Functions do not just save effort; they make code readable

A good function name says something all by itself:

```python
def is_vip(user):
    return user.get("level", 0) >= 3

if is_vip(alice):
    print("send a voucher")
```

Compare it with the no-function version:

```python
if alice.get("level", 0) >= 3:
    print("send a voucher")
```

They are almost the same length, but `is_vip(alice)` reads like English: **"is Alice a VIP?"**. Six months later, when you come back to this code, the first version is instantly clear while the second makes you figure out the condition again.

**The value of a function name**: it lets the code read like a description instead of a sequence of operations.

## Summary

- Copying the same logic three times plants three landmines — one change means many edits
- A function is defined with `def name(parameters):` and called with `name(arguments)`
- **Define before calling**, or you get `NameError`
- A function separates "what it does" from "where it is used", so logic lives in one place
- A good function name is itself a comment and makes code read like plain English
