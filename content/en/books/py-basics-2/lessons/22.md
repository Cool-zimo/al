# Defining and Calling: def, Parameters, return and Indentation

> The last lesson covered *why* you want functions. This one is about *how* to write one: **how `def` works, how arguments get passed in, what `return` gives back, and what indentation controls**.
>
> There are three traps here and every beginner falls into all of them: **bad indentation, the wrong number of arguments, and forgetting `return`.**

## 1. Defining: the four parts of `def`

A function has four parts: the `def` keyword, a name, parameters in parentheses, and an indented block after the colon.

```python
def add(a, b):
    """Return the sum of two numbers."""
    return a + b
```

- `def` tells Python: I'm about to define a function
- `add` is the name — it should say what the function does
- `(a, b)` are the parameters; you supply the two numbers when you call it
- after the colon `:` you **must** indent (usually 4 spaces); the indented lines are the function body

Calling it:

```python
result = add(3, 5)
print(result)        # 8
```

⚠️ **Crash: forgetting to indent after the colon.**

```python
def add(a, b):
print(a + b)        # ✗ IndentationError: expected an indented block
```

Python uses **indentation** to decide which lines belong to the function. Forget it and the interpreter complains immediately. `return` also has to sit inside the indented block, otherwise it isn't part of the function at all.

## 2. Parameters: what a function "eats"

Parameters are how a function receives information from the outside. Separate several with commas:

```python
def make_name(first, last):
    return first + " " + last

print(make_name("Ada", "Lovelace"))    # Ada Lovelace
print(make_name("Bill", "Gates"))      # Bill Gates
```

The values you pass in when calling are called **arguments** (the actual values: `3`, `"Ada"`), while `a` and `first` in the definition are **parameters** (the formal names).

⚠️ **Crash: the wrong number of arguments.**

```python
def add(a, b):
    return a + b

add(3)              # ✗ TypeError: add() missing 1 required positional argument: 'b'
add(1, 2, 3)        # ✗ TypeError: add() takes 2 positional arguments but 3 were given
```

Too few or too many, either way you get a `TypeError`. **The number of arguments you pass must match the number of parameters you declared** (lessons 23 and 26 cover variable-length arguments; for now take this as an absolute rule).

## 3. `return`: the function's exit

`return` is how a function hands a result back. When you call `add(3, 5)`, that `8` is what `return` delivered.

```python
def square(n):
    return n * n

x = square(4)        # x is 16
```

After a `return`, the function **stops immediately** — nothing below it runs:

```python
def divide(a, b):
    if b == 0:
        return "cannot divide by zero"
    return a / b

print(divide(10, 0))        # cannot divide by zero
print(divide(10, 2))        # 5.0
```

The moment the first `return` is hit, the function leaves. `return a / b` never runs. This is exactly what you want for "check something first, then compute" logic.

## 4. The classic trap: no `return` means `None`

This is trap number one for beginners, and it always shows up on tests.

```python
def add(a, b):
    result = a + b        # computed, but never returned

x = add(3, 5)
print(x)                  # None
print(x + 1)              # ✗ TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

`add(3, 5)` worked out `8`, but **without `return` that `8` is thrown away**, and the function returns the default: `None`. Then `None + 1` blows up.

⚠️ **Crash: printing inside the function and forgetting `return`, then assuming you captured the result.**

```python
def double(n):
    print(n * 2)          # printed, but not returned

x = double(5)             # prints 10
print(x)                  # None — you never got the 10
```

`print` only puts something on the screen; **it does not hand a value back**. If the caller needs the value, you must write `return`.

⚠️ **Crash: expecting the function to return the last expression automatically (a habit from other languages).**

```python
def add(a, b):
    a + b                 # no return, no assignment

print(add(3, 5))          # None
```

Python never "returns the last line". **No `return` means `None`** — no exceptions, ever.

## 5. Indentation decides what belongs to what

Same indent level = same block. Look at this:

```python
def classify(score):
    if score >= 60:
        result = "pass"          # belongs to the if
    else:
        result = "fail"          # belongs to the else
    return result                # belongs to the function
```

`return result` lines up with `if`, so it belongs to the function and runs whichever branch was taken.

⚠️ **Crash: `return` indented one level too deep, ending up inside the `if`.**

```python
def classify(score):
    if score >= 60:
        result = "pass"
        return result      # only returns when passing

alice = classify(55)
print(alice)               # None
```

55 doesn't enter the `if`, so `return` never runs and the function falls back to `None`. **This "one branch forgot to return" bug is notoriously hard to spot** — you test 90 and everything looks fine, you test 55 and get `None`.

## 6. A complete small example

Let's write a "total price" function: unit price, quantity, and whether the customer is a member (members get 10% off).

```python
def total_price(price, quantity, is_member):
    amount = price * quantity
    if is_member:
        amount *= 0.9
    return round(amount, 2)

print(total_price(100, 2, False))        # 200
print(total_price(100, 2, True))         # 180.0
```

One function, one job; the parameters are everything it needs from outside; `return` hands the result back. **That is what a good function looks like.**

⚠️ **Crash: changing a global variable inside the function instead of returning a result.**

```python
result = 0

def add(a, b):
    result = a + b          # this is a *local* variable; the outer one is untouched

add(3, 5)
print(result)               # 0 — nothing changed out here
```

`result = a + b` creates a **local** variable that happens to share a name with the outer one; they are not the same thing. **A function hands results back with `return`, not by mutating variables outside itself** (lesson 25 covers scope in detail).

## Summary

- A function definition has four parts: `def`, a name, parameter parentheses, and an indented block after the colon
- Argument counts must match exactly: too few or too many is a `TypeError`
- `return` is the exit — once it runs, the function stops
- **No `return` means `None`** — trap number one, guaranteed to be tested
- `print` only displays; it does not return. Python never returns the last line automatically
- Indentation decides ownership; a branch that misses `return` silently yields `None`

```quiz
type: code
q: Write a function circle_area(r) that returns the area of a circle using 3.14 * r * r (do not import math). Then use it to compute and print the areas for radius 5 and radius 2.
starter: |
  def circle_area(r):
      # return 3.14 * r * r

  print(circle_area(5))
  print(circle_area(2))
tests:
- assert "78.5" in __out
- assert "12.56" in __out
hint: Return 3.14 * r * r. Note it's return, not print.
explain: answer: def circle_area(r): return 3.14 * r * r. This is the most basic function shape — take a parameter, compute a value, return it. The point is the difference between "returning" and "printing": here you need the value back, so use return.
```
