# Holding Many Things at Once: Lists

> So far your program could only remember **one** thing at a time — one score, one name, one number.
>
> But in the real world, things come in batches: a whole class of scores, ten items in a shopping cart, seven days of temperatures.
>
> This lesson is about: **how to fit a whole pile of data into a single variable.**

## 1. First, See How Painful Life Is Without Lists

Say you need to record five students' scores and work out the average. With what you know now, you'd write:

```python
s1 = 87
s2 = 92
s3 = 78
s4 = 95
s5 = 61

total = s1 + s2 + s3 + s4 + s5
print("Average:", total / 5)
```

It runs. But the problem shows up immediately —

**What if there are 50 students?**

You'd need 50 variables and 50 additions. Worse: what if the number comes from user input and you don't know it ahead of time? **You can't even decide how many variables to write.**

That's the fundamental limit of "one variable, one value":

> **The number of variables must be decided when you write the code, but how much data there is usually isn't known until the program runs.**

## 2. A List: A Row of Numbered Lockers

Lists solve exactly this. They let **one variable hold a whole row of data**:

```python
scores = [87, 92, 78, 95, 61]
print(scores)
```

Output:

```
[87, 92, 78, 95, 61]
```

`scores` is a single variable, but it holds five numbers.

Here's the mental picture: an ordinary variable is **one box**, a list is **a row of numbered lockers**.

```
scores  →  ┌────┬────┬────┬────┬────┐
           │ 87 │ 92 │ 78 │ 95 │ 61 │
           └────┴────┴────┴────┴────┘
             0    1    2    3    4      ← the number, called an "index"
```

Every locker has a fixed number, and you use that number to store and fetch. It's called the **index**, and it's the subject of the next lesson.

## 3. How to Create a List

Square brackets `[]`, elements separated by commas:

```python
numbers = [1, 2, 3, 4, 5]
names = ["Alice", "Bob", "Charlie"]
mixed = [87, "Alice", True, 3.14]    # anything goes
empty = []                            # an empty list — no elements at all
```

Three things to note:

**① Any type is allowed, and you can mix them.** Numbers, strings, booleans, even another list.

**② An empty list is legal, and extremely useful.** Like grabbing an empty shopping cart first and filling it as you go.

**③ Order matters.** `[87, 92]` and `[92, 87]` are **two different lists** — the order itself is information (e.g. "score on the first test" vs "score on the second").

### Bonus: Splitting a String into a List

```python
chars = list("hello")
print(chars)
```

```
['h', 'e', 'l', 'l', 'o']
```

`list()` breaks a string into a list of single characters.

## 4. How Long Is It: len()

Don't count by hand — ask with `len()`:

```python
scores = [87, 92, 78, 95, 61]
print(len(scores))
```

```
5
```

`len` is short for "length". It's a built-in Python function, and it can count almost any container.

**Why does this one line matter?** Because it frees your program from **needing to know how much data there is**:

```python
scores = [87, 92, 78, 95, 61]
print("Total scores:", len(scores))
```

Whether the list later holds 5 items or 500, this line stays exactly the same.

⚠️ **The most common crash: treating `len` as an attribute.**

```python
scores.len()      # ✗ AttributeError: 'list' object has no attribute 'len'
```

`len()` is a **function** — it wraps around its argument. It is not a method, so you can't call it with a dot.

| Written as | OK? | Why |
|---|---|---|
| `len(scores)` | ✅ | len is a function; it wraps the list |
| `scores.len()` | ❌ | lists have no `.len()` method |

**How to remember it**: `len` is an "outsider" doing the counting, so it stands outside the parentheses. A method is an "insider", so it trails behind with a dot.

## 5. The Most Important Thing About Lists: They Can Change

Worth saying early, because it's what makes lists useful:

```python
scores = [87, 92, 78]
scores.append(95)          # add one at the end
print(scores)
```

```
[87, 92, 78, 95]
```

**A list can grow, shrink, and be rewritten while the program runs.** You don't need to know in advance how much data will arrive — the user submits one, you `append` one.

That's exactly how it solves the problem from the start of this lesson: **how much data there is gets decided at runtime.**

(The full story on adding and removing is lesson 3. For now just remember "it can change".)

## 6. Back to the Original Problem

Rewrite that "average score" program with a list:

```python
scores = [87, 92, 78, 95, 61]

total = 0
for s in scores:
    total = total + s

print("Average:", total / len(scores))
```

```
Average: 82.6
```

See it? **This code has nothing to do with how many scores there are.**

- Add a score: put one more number in the list, change no code
- Remove a score: same
- 50 scores: still runs

That's the real value of a list: **it takes "how many" out of your code.**

(`for s in scores` is iteration; lesson 5 covers it properly. For now just feel what it does: take each element out and do something with it.)

## 7. When Should You Use a List?

One simple rule:

| Situation | Use |
|---|---|
| One user's name | A plain variable |
| 40 students' names | **A list** |
| A fixed tax rate | A plain variable |
| Seven days of temperatures | **A list** |

The test is a single sentence: **if you can't say "how many" while writing the code, use a list.**
