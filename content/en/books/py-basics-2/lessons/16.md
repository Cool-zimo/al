# Sets: Dedupe, Membership and Disorder

> So far you have met lists, tuples and dictionaries. This lesson introduces the fourth built-in container: **sets**.
>
> A set has three defining traits: **its elements are unique, membership tests are lightning fast, and there is no order**. Learn those three and you will know exactly when to reach for it.

## 1. Creating a set

A set is written with braces, and the elements are separated by commas:

```python
nums = {1, 2, 3, 4}
print(nums)          # {1, 2, 3, 4}
print(type(nums))    # <class 'set'>
```

It looks a lot like a dictionary because both use `{ }`, but **a set has no colon and no key-value pairs**.

⚠️ **Crash: using `{}` to build an empty set.**

```python
s = {}
print(type(s))      # <class 'dict'>  -- this is an empty dict!
```

`{}` means **an empty dictionary**. To build an empty set you must use `set()`:

```python
s = set()
print(type(s))      # <class 'set'>
print(len(s))       # 0
```

Remember: **`{}` is a dict; `set()` is the empty set**. This is one of Python's most counter-intuitive corners.

### Converting from other sequences

```python
s1 = set([1, 2, 2, 3, 3, 3])
print(s1)               # {1, 2, 3}

s2 = set("hello")
print(s2)               # {'h', 'e', 'l', 'o'}  -- note only one 'l'
```

`set(sequence)` **drops the duplicates** for you. This is the single most classic use of a set — **deduplication**.

## 2. Trait one: every element is unique

Inside a set **the same element can appear only once**. Add it ten times and the set still keeps one copy:

```python
s = {1, 2, 3}
s.add(2)            # 2 is already there, nothing happens
s.add(2)
print(s)            # {1, 2, 3}
```

`add(element)` adds one element. If it already exists, Python ignores the request silently — no error.

⚠️ **Crash: assuming `add` allows duplicates the way a list's `append` does.**

```python
s = set()
s.add("Beijing")
s.add("Beijing")
print(len(s))       # 1 -- not 2
```

A set is naturally self-deduping. So if you need "a bunch of things that may repeat", use a list; if you need "one copy of each", use a set.

## 3. Trait two: membership is blazing fast

A set's killer feature is that **`in` is extremely fast** — whether the set holds one hundred or one million elements, asking "is it in there?" takes essentially the same amount of time.

```python
blocked = {"spam", "ads", "virus"}
print("spam" in blocked)       # True
print("hello" in blocked)      # False
```

Why it is fast is the main topic of Lesson 18. For now, just remember **how to use it and how it feels**: a set is ideal for "allowlist", "blocklist" and "already visited" checks.

```python
vip = {"Alice", "Bob", "Carol"}
name = "Alice"
if name in vip:
    print("Welcome, VIP user")
else:
    print("Regular user")
```

⚠️ **Crash: using a list as your "blocklist".**

```python
blocked = ["spam", "ads", "virus", ...]   # ten thousand names
"target" in blocked                       # checks one by one, very slow
```

Once the list grows, `in` slows down (Lesson 18 explains why). In that situation, swapping in a set makes the check fast instantly.

## 4. Trait three: no order at all

A set has **no positional concept** — you cannot index into it:

```python
s = {10, 20, 30}
print(s[0])          # WRONG  TypeError: 'set' object is not subscriptable
```

A set has no indexing, no slicing, and no "first element". Each element is simply either in or out.

⚠️ **Crash: assuming a set preserves insertion order.**

```python
s = {3, 1, 4, 1, 5, 9, 2, 6}
print(s)             # {1, 2, 3, 4, 5, 6, 9}  -- the order is not guaranteed!
```

The printed order is not promised to match the order you inserted. In some Python versions or implementations it may *look* sorted, but **logically you must never rely on that**.

If you need to process the elements in order, convert to a list and sort:

```python
s = {3, 1, 4, 1, 5}
print(sorted(s))     # [1, 3, 4, 5]  -- a sorted list
```

⚠️ **Crash: assigning or slicing through a set's "indexes".**

```python
s = {1, 2, 3}
s[0] = 10           # WRONG  TypeError
s[1:3]              # WRONG  TypeError
```

A set **cannot be modified by index and cannot be sliced**. When you need those operations, use a list.

## 5. When should you actually use a set?

| Your need | Use this | Why |
|---|---|---|
| A bunch of things that may repeat and have an order | list | You need `append`, indexing and slicing |
| A bunch of things, one copy of each | **set** | It dedupes automatically |
| Frequent "is it in there?" checks | **set** | `in` is extremely fast |
| Key-to-value mapping | dict | A set only knows "in or out", not "what value goes with it" |

A real scenario: counting website UV (unique visitors), where the same user visiting ten times counts as one person:

```python
visitors = set()
visitors.add("192.168.1.1")
visitors.add("192.168.1.2")
visitors.add("192.168.1.1")      # duplicate, ignored
visitors.add("192.168.1.3")
print(len(visitors))             # 3  -- three unique visitors
```

With a list, `len` would have reported 4, which would have been wrong.

⚠️ **Crash: wanting to "keep the first-seen order" with a set.**

```python
items = ["apple", "banana", "apple", "orange"]
seen = set()
result = []
for x in items:
    if x not in seen:
        seen.add(x)
        result.append(x)
print(result)          # ['apple', 'banana', 'orange']
```

To "dedupe while keeping the original order" you need a set for the bookkeeping and a list for the result. A plain set cannot preserve order on its own.

## Summary

- A set is created with `{1, 2, 3}`; **`{}` is an empty dict, `set()` is the empty set**
- Three traits: unique elements, lightning-fast membership, no order
- You cannot index or slice a set
- Typical uses: deduplication, blocklists / allowlists, unique-visitor counts
- Set elements must be hashable (just like dictionary keys), so you cannot put a list inside a set
