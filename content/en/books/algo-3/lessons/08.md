# Lowest Common Ancestor (LCA)

> The Lowest Common Ancestor is the classic "return a node" problem in tree questions: given two nodes p and q, find their deepest common ancestor. Its solution is remarkably elegant — a few lines of recursion hiding a clever divide-and-conquer idea.

## Problem definition: what is an LCA

**Lowest Common Ancestor: for two nodes p and q in a rooted tree, a common ancestor is any node that is an ancestor of both p and q; the "lowest" (deepest) among them is the LCA.**

```
        3
      /   \
     5     1
    / \   / \
   6   2 0   8
      / \
     7   4
```

The LCA of p=5 and q=1 is 3 (3 is a common ancestor of 5 and 1, and no deeper node is).
The LCA of p=5 and q=4 is 5 (5 is an ancestor of 4 and also an ancestor of itself).

**The LCA has a very practical property: if p and q are on opposite sides of a node, that node is their LCA.**

## The idea: divide and conquer + short-circuiting

**Core idea: recursively process the left and right subtrees, returning "whether this branch found p or q."**

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build(vals):
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]

def lowest_common_ancestor(root, p, q):
    if root is None or root is p or root is q:
        return root                    # found p or q, return it
    left = lowest_common_ancestor(root.left, p, q)
    right = lowest_common_ancestor(root.right, p, q)
    if left and right:
        return root                    # one found in each branch, this node is the LCA
    return left or right               # only found on one side, pass it upward
```

**Read it line by line:**

- `if root is None or root is p or root is q: return root` — an empty node returns None; if you find p or q, return that node. Note the use of `is`: we are comparing "the same object," not "equal values."
- `if left and right: return root` — one was found in the left subtree and one in the right, meaning p and q are on opposite sides, so the current node is the LCA.
- `return left or right` — found on only one side, so pass that result upward.

```python
t = build([3, 5, 1, 6, 2, 0, 8, None, None, 7, 4])
p = t.left          # 5
q = t.right         # 1
print(lowest_common_ancestor(t, p, q).val)   # 3

p2 = t.left.right.left   # 7
print(lowest_common_ancestor(t, p, p2).val)  # 5
```

## WRONG WAY: comparing by value `root.val == p.val` instead of using `is`

```python
# WRONG: comparing by value, which fails when values are duplicated
def lowest_common_ancestor_wrong(root, p, q):
    if root is None or root.val == p.val or root.val == q.val:  # ← value comparison
        return root
    left = lowest_common_ancestor_wrong(root.left, p, q)
    right = lowest_common_ancestor_wrong(root.right, p, q)
    if left and right:
        return root
    return left or right

t2 = build([3, 5, 1, 5, 2])   # two nodes with value 5 in the left subtree
p = t2.left          # the first 5
q = t2.left.left     # the second 5
print(lowest_common_ancestor_wrong(t2, p, q).val)  # might return 3, which is wrong!
```

**When the tree contains duplicate values, `root.val == p.val` mistakenly "finds p."** The definition of LCA is based on "node identity," not "node value."

**The correct approach: use `root is p` to test whether it is the same object.** In algorithm problems, p and q are usually passed in directly as node references, so using `is` is naturally correct.

## WRONG WAY: what if p or q is itself the ancestor?

**Do we need a special case for "one node is the ancestor of the other"?** No — the algorithm above handles it naturally.

```python
t = build([3, 5, 1, 6, 2, 0, 8, None, None, 7, 4])
p = t.left        # 5
q = t.left.right  # 2
print(lowest_common_ancestor(t, p, q).val)   # 5
```

**Why is this correct?** When recursion enters the subtree rooted at 5, `lowest_common_ancestor(5, 5, 2)` hits `root is p` on its very first line and returns 5. Going back up to 5's parent 3, the left subtree returned 5 and the right subtree returned None, so `left or right` returns 5. **The result is 5, which is exactly correct** — because 5 is itself an ancestor of 2 and an ancestor of itself, so the LCA is 5.

**This property makes the LCA implementation exceptionally concise: no need to讨论 "whether one is the ancestor of the other."**

## BST LCA: exploiting ordering, O(h) without recursing into both branches

**If the tree is a BST, you can radically simplify LCA using ordering: compare the current node's value with the values of p and q to decide whether to go left or right.**

```python
def lca_bst(root, p, q):
    if root is None:
        return None
    # p and q are both in the left subtree
    if root.val > p.val and root.val > q.val:
        return lca_bst(root.left, p, q)
    # p and q are both in the right subtree
    if root.val < p.val and root.val < q.val:
        return lca_bst(root.right, p, q)
    # on opposite sides (or the current node is p/q), the current node is the LCA
    return root

t = build([6, 2, 8, 0, 4, 7, 9, None, None, 3, 5])
print(lca_bst(t, t.left, t.right).val)              # 6  (LCA of 2 and 8)
print(lca_bst(t, t.left.right, t.left.right.right).val)  # 4  (LCA of 4 and 5)
```

**The key test: `if (p.val <= root.val <= q.val) or (q.val <= root.val <= p.val)` also works.** As long as p and q are on opposite sides (or one of them is the root), the root is the LCA — return it.

**The BST version is O(h) and walks only one path, while the ordinary binary tree version is O(n) and visits nearly the whole tree.** BST ordering provides a "sense of direction" that an ordinary tree lacks.

## An application of LCA: finding the distance between two nodes

**The distance between two nodes u and v = depth(u) + depth(v) - 2*depth(LCA(u,v)).** Once you can compute depth and LCA, distance falls out for free.

```python
def depth(root, target, d=0):
    if root is None:
        return -1
    if root is target:
        return d
    return depth(root.left, target, d+1) or depth(root.right, target, d+1) or -1

def distance(root, u, v):
    lca = lowest_common_ancestor(root, u, v)
    return depth(root, u) + depth(root, v) - 2 * depth(root, lca)

t = build([3, 5, 1, 6, 2, 0, 8, None, None, 7, 4])
u = t.left          # 5
v = t.right         # 1
print(distance(t, u, v))   # 2  (5->3->1)
```

**`depth` returns the number of edges from the root to the target.** Geometrically, the distance formula says: the distance from u to the LCA is `depth(u)-depth(lca)`, and from v to the LCA is `depth(v)-depth(lca)`; adding them gives the total.

## Summary

- LCA definition: the "deepest" node among all common ancestors of p and q.
- Ordinary binary tree LCA: `if left and right: return root; return left or right`, O(n).
- **Compare node identity with `is`, never value with `==`** — duplicates cause misidentification.
- The algorithm naturally covers the case where "one node is the ancestor of the other," with no special cases needed.
- The BST version exploits ordering, walks only one path, and runs in O(h): when p and q are on opposite sides, the current node is the LCA.
- Distance formula: `depth(u) + depth(v) - 2*depth(LCA)`.
