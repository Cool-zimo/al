# Quick Sort: The Partitioning Idea

> Quick sort is the fastest general-purpose sorting algorithm in practice. C++'s `std::sort` and Java's primitive sort are both based on it. The core operation is "partitioning": pick a pivot and rearrange the array into "all smaller on the left, all larger on the right". This lesson thoroughly covers the Lomuto and Hoare partitioning schemes and explains why quick sort can degenerate to O(n²).

## Partitioning: The Core Operation of Quick Sort

**The goal of partitioning: pick a pivot, rearrange the array into `[<=pivot | pivot | >=pivot]`, and return the pivot's final position.**

```python
def quick_sort(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition(a, low, high)   # Partition; p is the pivot's final position
        quick_sort(a, low, p - 1)     # Recursively sort the left half
        quick_sort(a, p + 1, high)    # Recursively sort the right half
    return a
```

**The difference between quick sort and merge sort: merge sort divides first then merges (merging is the main work); quick sort partitions first then recurses (partitioning is the main work, with no merge step).**

## Lomuto Partition: Simple and Intuitive, One Pointer to Mark the Boundary

**Lomuto partition: pick the rightmost element as the pivot and use a pointer `i` to maintain the boundary of the "less than or equal to pivot" region.**

```python
def partition(a, low, high):
    pivot = a[high]        # Pick the rightmost element as pivot
    i = low - 1            # i is the right boundary of the "<= pivot" region
    for j in range(low, high):    # j scans [low, high-1]
        if a[j] <= pivot:
            i += 1
            a[i], a[j] = a[j], a[i]
    a[i + 1], a[high] = a[high], a[i + 1]  # Put the pivot in its correct place
    return i + 1           # Return the pivot index
```

**Execution trace (`a = [10, 80, 30, 90, 40, 50, 70]`, pivot=70):**

```
j=0: a[0]=10 <= 70, i=0, swap(a[0],a[0]) → [10, 80, 30, 90, 40, 50, 70]
j=1: a[1]=80 > 70, skip
j=2: a[2]=30 <= 70, i=1, swap(a[1],a[2]) → [10, 30, 80, 90, 40, 50, 70]
j=3: a[3]=90 > 70, skip
j=4: a[4]=40 <= 70, i=2, swap(a[2],a[4]) → [10, 30, 40, 90, 80, 50, 70]
j=5: a[5]=50 <= 70, i=3, swap(a[3],a[5]) → [10, 30, 40, 50, 80, 90, 70]
Finally: swap(a[4], a[6]) → [10, 30, 40, 50, 70, 90, 80]
Pivot 70 is at index 4: everything left is <=70, everything right is >=70 ✓
```

**Lomuto's traits: simple, easy to understand, but it performs more swaps than Hoare.**

## Hoare Partition: Two Pointers Colliding, More Efficient

**Hoare partition (the original scheme by quick sort inventor Tony Hoare): two pointers scan from the left and right toward the middle; the left pointer looks for an element >pivot, the right pointer looks for an element <pivot, and they swap when both are found.**

```python
def partition_hoare(a, low, high):
    pivot = a[low]          # Pick the leftmost element as pivot
    i = low - 1
    j = high + 1
    while True:
        i += 1
        while a[i] < pivot:
            i += 1
        j -= 1
        while a[j] > pivot:
            j -= 1
        if i >= j:
            return j        # Return the partition point
        a[i], a[j] = a[j], a[i]
```

**Traits of Hoare partition:**
- **Fewer swaps**: each pointer finds a violating element before swapping, averaging about 3 times fewer swaps than Lomuto
- **The pivot is not necessarily in its final position**: it returns a boundary, and the pivot itself may remain on either side
- **Recursion uses `[low, p]` and `[p+1, high]`**, unlike Lomuto which excludes the pivot

**Hoare is the more commonly used scheme in practice**; C++ `std::sort` internally uses a dual-pivot variant of Hoare.

## # WRONG: Picking the Wrong Pivot in Lomuto Causes an Infinite Loop

**The most common quick sort bug: the recursive interval after partitioning still includes the pivot itself, causing infinite recursion.**

```python
# WRONG: Recursive interval includes the pivot position
def quick_sort_wrong(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition(a, low, high)
        quick_sort_wrong(a, low, p)      # WRONG! Should be p-1
        quick_sort_wrong(a, p, high)     # WRONG! Should be p+1
    return a

# Infinite loop! The pivot position is never excluded, so recursion never converges
```

**Error analysis: if `a = [3, 1, 2]`, pivot=a[2]=2, p=1. The recursive calls are `quicksort(a, 0, 1)` and `quicksort(a, 1, 2)`. In the second call, the pivot is still the element at position 1, which again returns p=1 → infinite recursion!**

**Fix: `quicksort(a, low, p-1)` and `quicksort(a, p+1, high)` — the pivot is already in its correct position, so it does not need to be sorted again.**

## Worst Case O(n²): When Partitioning Is Extremely Unbalanced

**Quick sort averages O(n log n), but it can degenerate to O(n²) in the worst case.**

**When does it degenerate? When each partition is extremely unbalanced — for example, an already sorted array with the pivot always chosen as the leftmost/rightmost element.**

```python
a = [1, 2, 3, 4, 5]   # Already sorted
# pivot=5, after partition: left has 4, right has 0
# pivot=4, after partition: left has 3, right has 0
# ...
# Only one element is removed each time, recursion depth n
# Total comparisons n + (n-1) + ... + 1 = n(n+1)/2 = O(n²)
```

**The chain of degradation: the recursion tree becomes a linked list, depth O(n), O(n) per level, total O(n²).**

**This is exactly the opposite of insertion sort's behavior on sorted data!** Insertion sort is O(n) on sorted data; quick sort is O(n²) on sorted data.

## Randomized Quick Sort: Using a Random Pivot to Avoid the Worst Case

**Solution: instead of always picking the leftmost/rightmost, randomly pick a pivot and swap it with the leftmost/rightmost element.**

```python
import random

def partition_random(a, low, high):
    # Randomly pick a pivot and swap it with the rightmost element
    pivot_idx = random.randint(low, high)
    a[pivot_idx], a[high] = a[high], a[pivot_idx]
    return partition(a, low, high)    # Reuse Lomuto

def quick_sort_random(a, low=0, high=None):
    if high is None:
        high = len(a) - 1
    if low < high:
        p = partition_random(a, low, high)
        quick_sort_random(a, low, p - 1)
        quick_sort_random(a, p + 1, high)
    return a
```

**The point of randomization: it turns "worst case depends on input" into "worst case depends on the random seed".** A maliciously constructed degenerate input (e.g., an array carefully crafted by an attacker) can no longer reliably trigger O(n²).

**In practice, there is also median-of-three: pick the median of low, mid, and high as the pivot, which performs better on common inputs.**

**Randomized quick sort has expected complexity O(n log n)**, with a very small constant factor in practice — typically 20–40% faster than merge sort (because it operates in-place and is cache-friendly).

## Summary

- Quick sort core = partition: pick a pivot, split the array into `<=pivot` and `>=pivot`
- Lomuto partition: one pointer marking the boundary, simple but more swaps; Hoare: two pointers colliding, more efficient
- **With Lomuto, the pivot is already in place, so recurse on `[low, p-1]` and `[p+1, high]`**
- **With Hoare, recurse on `[low, p]` and `[p+1, high]`**
- Worst case O(n²): already sorted + fixed pivot selection → degeneration
- Randomized pivot → expected O(n log n), resistant to malicious inputs
- Quick sort is in-place, cache-friendly, and has a small constant — the fastest general-purpose sort in practice
