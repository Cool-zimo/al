# Graphs: Adjacency Matrix vs Adjacency List

> Arrays are one-to-one, trees are one-to-many, and graphs are many-to-many. This lesson covers the basic elements of graphs and the two most common storage methods — adjacency matrices and adjacency lists — and when to use each.

## What Is a Graph: Vertices and Edges

**A graph G = (V, E) consists of a set of vertices V and a set of edges E.** Compared to a tree, a graph removes two restrictions: cycles are allowed, and a node can have multiple parents.

```python
# An example of an undirected graph: roads between 4 cities
# Cities are numbered 0, 1, 2, 3
graph = {
    0: [1, 2],       # city 0 connects to cities 1 and 2
    1: [0, 2, 3],    # city 1 connects to 0, 2, 3
    2: [0, 1],       # city 2 connects to 0, 1
    3: [1],          # city 3 only connects to 1
}
```

**Graphs are classified by whether edges have direction and whether they carry weight:**

| Type | Meaning | Representation |
|---|---|---|
| Undirected | Edges have no direction; A-B means B-A | If `graph[a]` contains b, then `graph[b]` contains a |
| Directed | Edges have direction; A→B is not the same as B→A | Adjacency list records only one direction |
| Weighted | Edges carry weight (distance, cost) | Adjacency list stores `(neighbor, weight)` tuples |

## Adjacency List: The Most Common Representation

**An adjacency list uses an array or dictionary where each node stores a list of all its neighbors.** This is the dominant representation in algorithm problems and real-world engineering.

```python
# Undirected, unweighted graph
adj = {
    0: [1, 2],
    1: [0, 2, 3],
    2: [0, 1],
    3: [1],
}

# Directed, weighted graph: edges carry distances
weighted = {
    0: [(1, 4), (2, 3)],
    1: [(3, 5)],
    2: [(1, 2), (3, 6)],
    3: [],
}
```

**To iterate over all neighbors of node 0: `for nb in adj[0]:`.** In an undirected graph, every edge appears twice in the adjacency list (a's list contains b, and b's list contains a); in a directed graph, each edge appears only once.

**For a weighted graph, `weighted[0]` gives a list of `(neighbor, weight)` tuples.** Dijkstra's algorithm (Lesson 15) consumes exactly this format.

## Adjacency Matrix: Trading Space for Query Speed

**An adjacency matrix is an n×n 2D array `g[i][j]` that indicates whether there is an edge from i to j (or the weight of that edge).**

```python
# 4 nodes, represented as an adjacency matrix
n = 4
g = [[0]*n for _ in range(n)]
def add_edge(u, v, w=1):
    g[u][v] = w
    g[v][u] = w          # Undirected: symmetric

add_edge(0, 1)
add_edge(0, 2)
add_edge(1, 2)
add_edge(1, 3)

for row in g:
    print(row)
```

Output:

```
[0, 1, 1, 0]
[1, 0, 1, 1]
[1, 1, 0, 0]
[0, 1, 0, 0]
```

**`g[i][j] == 0` means no edge; `g[i][j] == 1` means there is an edge.** For weighted graphs, use `g[i][j] = w`, and use `inf` or `0` for "no edge" (with the convention that 0 means no edge, weights cannot be 0).

## Adjacency Matrix vs Adjacency List

| Dimension | Adjacency Matrix | Adjacency List |
|---|---|---|
| Space | O(n²) | O(n + m) |
| Check if two nodes are adjacent | O(1) | O(deg(u)) |
| Iterate over all neighbors | O(n) | O(deg(u)) |
| Best for | Dense graphs, Floyd-Warshall, fast edge lookup | Sparse graphs, DFS/BFS, most algorithm problems |

**For sparse graphs (few edges, m ≈ n), use an adjacency list to save space; for dense graphs (many edges, m ≈ n²), both are roughly equivalent.**

**An adjacency matrix at n = 10^5 is fatal**: `n × n = 10^10` integers is about 40 GB — instant memory overflow. So for large graphs, always use an adjacency list.

## # WRONG: Using "0 means no edge" Collides with "Weight 0"

```python
# WRONG: Using 0 to mean both "no edge" and "weight is 0"
n = 3
g = [[0]*n for _ in range(n)]
g[0][1] = 0     # Trying to say "the weight of edge 0-1 is 0"
print(g[0][1] == 0)   # True, but is this "no edge" or "weight 0"?
```

**There is no way to distinguish.** This is the classic pitfall when representing weighted graphs with an adjacency matrix.

**Fix: use `float('inf')` to represent "no edge".**

```python
n = 3
INF = float('inf')
g = [[INF]*n for _ in range(n)]
for i in range(n):
    g[i][i] = 0          # Distance to self is 0
g[0][1] = 0              # Weight 0 is perfectly valid
print(g[0][1])           # 0, indeed weight 0
print(g[0][2])           # inf, indeed no edge
```

## Differences Between Directed and Undirected Graphs

**Undirected graphs store each edge twice; directed graphs store each edge only once.** This difference directly affects traversal and algorithms.

```python
# Undirected graph: add edge in both directions
def add_undirected(adj, u, v):
    adj[u].append(v)
    adj[v].append(u)

# Directed graph: add edge in one direction only
def add_directed(adj, u, v):
    adj[u].append(v)

adj = {0: [], 1: [], 2: []}
add_undirected(adj, 0, 1)
add_directed(adj, 1, 2)
print(adj)   # {0: [1], 1: [0, 2], 2: []}
```

**Topological sort (Lesson 13) and strongly connected components are defined only on directed graphs; connected components and minimum spanning trees are defined on undirected graphs.** The first thing to do when solving a problem: determine whether it is directed or undirected.

## Graph Representation Convention: Nodes Numbered from 0

**In algorithm problems, graph nodes are typically numbered 0 to n−1.** An adjacency list using a list of lists `adj = [[] for _ in range(n)]`, where the index is the node ID, is more efficient than a dictionary.

```python
n = 5
adj = [[] for _ in range(n)]
edges = [[0, 1], [0, 2], [1, 3], [1, 4]]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)

print(adj)
# [[1, 2], [0, 3, 4], [0], [1], [1]]
```

**`adj` is a "list of lists", and `adj[u]` is the neighbor list of node u.** This format matches LeetCode's `List[List[int]]` standard input.

## Basic Graph Quantities: Degree, Path, Cycle

**Degree**: the number of edges connected to a node in an undirected graph. In directed graphs, this splits into in-degree (incoming edges) and out-degree (outgoing edges).

```python
def degree(adj, u):
    return len(adj[u])

adj = [[1, 2], [0, 2, 3], [0, 1], [1]]
print(degree(adj, 1))   # 3
print(degree(adj, 3))   # 1
```

**Path**: a sequence of edges traversed in order. **Cycle**: a path where the start and end nodes are the same. **Connected**: there is a path between two nodes.

**A tree is simply an "acyclic connected graph".** A graph is a generalization of a tree (allowing cycles and multiple parents). So the code for DFS/BFS looks almost identical to tree traversal — the only addition is a "visited set" to prevent going in circles.

## # WRONG: Traversing a Graph Without visited Causes Infinite Loop

```python
# WRONG: DFS on a cyclic graph without recording visited — infinite recursion
adj = {0: [1], 1: [2], 2: [0]}   # Triangle (cycle)

def dfs(u):
    print(u)
    for v in adj[u]:
        dfs(v)

dfs(0)   # 0 1 2 0 1 2 0 1 2 ... until RecursionError
```

**A tree never cycles back to an ancestor, so tree DFS does not need visited. A graph has cycles, so visited is mandatory.**

**Correct approach:**

```python
def dfs(u, visited):
    if u in visited:
        return
    visited.add(u)
    print(u)
    for v in adj[u]:
        dfs(v, visited)

dfs(0, set())   # 0 1 2
```

**`visited` is the one essential difference between graph and tree traversal.** Remember this and you will never forget it.

## Summary

- Graph = vertices + edges; directed/undirected by direction; weighted/unweighted by weight
- Adjacency list: space O(n+m), iterate neighbors O(deg(u)), first choice for sparse graphs
- Adjacency matrix: space O(n²), edge lookup O(1); use for dense graphs and Floyd-Warshall
- **For weighted graphs in an adjacency matrix, use `inf` for "no edge" — never use 0**
- Undirected edges go both ways; directed edges go one way
- **Always record visited when traversing a graph**, otherwise cycles cause infinite recursion
