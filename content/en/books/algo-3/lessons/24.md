# 2D Dynamic Programming: Longest Common Subsequence (LCS)

> 1D DP only needs one index to describe a state; 2D DP needs two. This lesson uses Longest Common Subsequence (LCS) as a case study to clarify the meaning of the dp array, the filling order, and boundary handling in 2D DP.

## LCS Problem Description

**Given two strings text1 and text2, return the length of their longest common subsequence. A subsequence need not be contiguous, but must preserve relative order.**

Example: `text1 = "abcde"`, `text2 = "ace"` → the LCS is `"ace"`, with length 3.

## Meaning of dp[i][j]

> `dp[i][j]` = the length of the longest common subsequence of the **first i characters** of text1 and the **first j characters** of text2

**Note that "first i characters" means considering `text1[0:i]` (left-inclusive, right-exclusive), i.e., indices 0 to i-1.**

**The benefit of this definition: dp[0][j] means the LCS between an empty string and the first j characters of text2 = 0, naturally handling the empty-string boundary.**

## Transition Equation

**Consider `text1[i-1]` and `text2[j-1]` (since dp[i] corresponds to the first i characters, the last character is at index i-1):**

```
If text1[i-1] == text2[j-1]:
    dp[i][j] = dp[i-1][j-1] + 1     # Characters match, LCS length +1
Else:
    dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # No match, take max of dropping one char
```

**Why take `max(dp[i-1][j], dp[i][j-1])` when they don't match?**

- `dp[i-1][j]`: don't use the i-th character of text1 (equivalent to dropping it from text1)
- `dp[i][j-1]`: don't use the j-th character of text2 (equivalent to dropping it from text2)

**Taking the max gives you the best LCS you can get after "dropping at least one character."**

## Full Implementation and Filling Process

```python
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    
    return dp[m][n]

print(longest_common_subsequence("abcde", "ace"))   # 3
print(longest_common_subsequence("abc", "abc"))    # 3
print(longest_common_subsequence("abc", "def"))    # 0
```

**Using `text1 = "abcde"`, `text2 = "ace"` as an example, the filling process:**

```
      ""  a   c   e
""    0   0   0   0
a     0   1   1   1
b     0   1   1   1
c     0   1   2   2
d     0   1   2   2
e     0   1   2   3
```

**How to read the table:**

- Row 0 and column 0 are all 0 (LCS of any string with an empty string is 0)
- `dp[1][1]`: first 1 char of text1 "a" vs. first 1 char of text2 "a" → match → `dp[0][0] + 1 = 1`
- `dp[3][2]`: first 3 chars "abc" vs. first 2 chars "ac" → c matches → `dp[2][1] + 1 = 2`
- `dp[5][3]`: final answer = 3

## Filling Order: Why Left-to-Right, Top-to-Bottom

**Computing dp[i][j] requires three subproblems: dp[i-1][j-1] (top-left), dp[i-1][j] (above), and dp[i][j-1] (left).**

```
        j-1      j
      ┌────────┬────────┐
 i-1  │   ↖    │   ↑    │
      ├────────┼────────┤
  i   │   ←    │ dp[i][j]
      └────────┴────────┘
```

**Iterating left to right, top to bottom guarantees that top-left, above, and left are all computed beforehand.**

```python
for i in range(1, m + 1):       # Top to bottom
    for j in range(1, n + 1):  # Left to right
        # At this point dp[i-1][j-1], dp[i-1][j], dp[i][j-1] are all ready
        ...
```

**If you filled from bottom-right to top-left instead, the dependencies wouldn't be ready, and the results would be wrong.**

## WRONG: dp Array Is m×n, Missing the Extra Row/Column

**Forgetting to reserve space for the empty string causes index errors when handling the first row/column.**

```python
# WRONG: dp is m × n, missing one extra row and column
def lcs_wrong(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * n for _ in range(m)]    # Only m rows, n cols—no row 0 or col 0
    for i in range(m):
        for j in range(n):
            if text1[i] == text2[j]:
                # Needs dp[i-1][j-1], which goes out of bounds at i=0 or j=0
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m - 1][n - 1]

# IndexError: list index out of range
```

**Fix: allocate dp as `(m+1) × (n+1)`, shift all indices by one, and access characters with `text1[i-1]` and `text2[j-1]`:**

```python
def lcs_correct(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]  # One extra row and column
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:    # Use i-1 and j-1 for characters
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]
```

**The "one extra slot" trick: make the dp array one larger than the input length, use row/column 0 for base cases (usually 0), making the code cleaner and less error-prone.**

## WRONG: Comparing text1[i] Instead of text1[i-1]

**This is an index offset issue: dp[i][j] corresponds to "first i characters," and the last character's index is i-1, not i.**

```python
# WRONG: comparing text1[i] and text2[j]
def lcs_bad_index(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i] == text2[j]:    # IndexError! i might equal m
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

# IndexError: string index out of range
```

**When i = m, `text1[i]` accesses `text1[m]`, which is out of bounds.** The correct access is `text1[i-1]`.

**Remember the mantra: "dp indices are offset by 1 from string indices."** dp[i][j] processes text1[i-1] and text2[j-1].

## WRONG: On Mismatch, Only Taking dp[i-1][j], Forgetting dp[i][j-1]

**On a mismatch in LCS, you must consider both "drop text1's character" and "drop text2's character." Taking only one will miss solutions.**

```python
# WRONG: on mismatch, only took dp[i-1][j]
def lcs_incomplete(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = dp[i - 1][j]    # Only considered dropping text1's char
                # Forgot max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

print(lcs_incomplete("abcde", "ace"))   # Result is too small or wrong
```

**Why must we take the max?** Because `dp[i-1][j]` and `dp[i][j-1]` represent two different "drop strategies," and it's impossible to know which yields a longer common subsequence without taking the max.

## Summary

- **LCS dp[i][j]**: the LCS length of the first i chars of text1 and first j chars of text2
- **On match**: `dp[i][j] = dp[i-1][j-1] + 1`
- **On mismatch**: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
- **Filling order**: left to right, top to bottom, ensuring dependencies are ready
- **"One extra slot" trick**: dp is (m+1)×(n+1), row/col 0 is naturally 0, handling empty-string boundaries
- **Index mantra**: "dp indices are offset by 1 from string indices"—use text1[i-1] and text2[j-1]
- Common pitfalls: wrong array dimensions, index offset errors, taking only one direction on mismatch
