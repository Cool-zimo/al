# Path Problems: Root-to-Leaf Path Sums

> "Paths" are the second major category of tree problems. This lesson covers the two most basic kinds: root-to-leaf path sums, and "does a path with sum equal to target exist." The core idea is to pass the "current path state" downward as a parameter.

## Root-to-leaf paths: preorder traversal + passing parameters

**"Root to leaf" requires you to walk from the root all the way to some leaf.** The approach: preorder traversal, passing "the current running sum" downward as a parameter; when you reach a leaf, check whether it equals the target.

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build(vals):
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]

def has_path_sum(root, target):
    if root is None:
        return False
    target -= root.val                  # pass along "how much of the target remains"
    if root.left is None and root.right is None:
        return target == 0             # reached a leaf
    return has_path_sum(root.left, target) or \
           has_path_sum(root.right, target)

print(has_path_sum(build([5, 4, 8, 11, None, 13, 4, 7, 2]), 22))   # True
print(has_path_sum(build([5, 4, 8, 11, None, 13, 4, 7, 2]), 20))   # False
```

**Key trick: `target -= root.val`, passing "how much is still left" downward.** This way, at a leaf you only need to check `target == 0`; there is no need to maintain a global accumulator variable.

## WRONG WAY: treating an "empty node" as a "leaf"

```python
# WRONG: no leaf check, testing target == 0 at an empty node
def has_path_sum_wrong(root, target):
    if root is None:
        return target == 0          # ← wrong! an empty node is not a leaf
    target -= root.val
    return has_path_sum_wrong(root.left, target) or \
           has_path_sum_wrong(root.right, target)

t = build([1, 2])   # only one path: 1->2, with sum 3
print(has_path_sum_wrong(t, 1))   # True  ← wrong! the path sum is 3, yet it claims True
```

**Why is it wrong?** After walking `1->2` you reach leaf 2, then go left into the empty node: at that point `target = 1 - 1 - 2 = -2`. An empty node's `target == 0` is False, so it looks harmless — but if you happen to hit the target on some "nonexistent" halfway point, you get a false positive.

**The real trap is here:**

```python
t2 = build([1, 2, 3])
# the paths are 1->2 (sum 3) and 1->3 (sum 4)
print(has_path_sum_wrong(t2, 1))   # False, no problem
print(has_path_sum_wrong(t2, 3))   # True  ← wrong! 3 is the sum of "1->2", but it could also be mistaken as "1->empty" adding up
```

**The correct写法: only count it when "it is a leaf AND target == 0."** Return False at an empty node (unless the problem explicitly allows "ending at any node," as in the variant of problem 257, path sum II, discussed later).

## Returning all qualifying paths

**If you are asked to "return all paths," collect them in a list: append the current node value, then pop it on the way back.**

```python
def path_sum_paths(root, target):
    ans = []
    def go(n, cur, rem):
        if n is None:
            return
        cur.append(n.val)
        rem -= n.val
        if n.left is None and n.right is None and rem == 0:
            ans.append(cur.copy())      # must copy!
        go(n.left, cur, rem)
        go(n.right, cur, rem)
        cur.pop()                       # backtrack
    go(root, [], target)
    return ans

print(path_sum_paths(build([5, 4, 8, 11, None, 13, 4, 7, 2]), 22))
# [[5, 4, 11, 2]]
```

**`cur.copy()` is mandatory.** If you write `ans.append(cur)`, you are appending a reference to the very same list object, and the subsequent `cur.pop()` will modify its contents —最终 ans will be full of empty lists.

## WRONG WAY: appending the same list reference, ruining the result

```python
# WRONG: forgot to copy
def path_sum_paths_wrong(root, target):
    ans = []
    def go(n, cur, rem):
        if n is None:
            return
        cur.append(n.val)
        rem -= n.val
        if n.left is None and n.right is None and rem == 0:
            ans.append(cur)           # ← the same list object
        go(n.left, cur, rem)
        go(n.right, cur, rem)
        cur.pop()
    go(root, [], target)
    return ans

t = build([1, 2, 3])
print(path_sum_paths_wrong(t, 3))
# actually gets [[], []] or something similar, depending on traversal order
```

**You appended a reference, and pop modifies the same object.** This is the easiest mistake in "backtracking" problems, especially common in Python — because `list.append` does not copy.

**Fixed写法: whenever you "collect paths" with backtracking, use `cur.copy()` (or `cur[:]`) when appending.**

## Paths ending at any node

**LeetCode 437 (Path Sum III) relaxes the requirement: the path does not have to start at the root or end at a leaf; it only has to go downward.** At that point "passing a parameter" is not enough; you need two levels of recursion:

```python
def path_sum_any(root, target):
    def from_node(n, rem):
        """How many downward paths starting at n sum to target"""
        if n is None:
            return 0
        rem -= n.val
        return (1 if rem == 0 else 0) + from_node(n.left, rem) + from_node(n.right, rem)

    def dfs(n):
        """Visit every node and treat it as a starting point"""
        if n is None:
            return 0
        return from_node(n, target) + dfs(n.left) + dfs(n.right)

    return dfs(root)

print(path_sum_any(build([10, 5, -3, 3, 2, None, 11, 3, -2, None, 1]), 8))   # 3
```

**The outer `dfs` enumerates starting points; the inner `from_node` enumerates paths going downward from each start.** The time complexity is O(n²), which is slow on skewed trees; the advanced approach uses prefix sums + a hash map (covered in lesson 29).

## Maximum path sum: between any two nodes

**LeetCode 124 (Binary Tree Maximum Path Sum) asks for "the maximum sum of a path between any two nodes in the tree."** The path does not have to pass through the root, so the "return a value + update a global answer" pattern comes into play again.

```python
def max_path_sum(root):
    ans = [float('-inf')]
    def go(n):
        if n is None:
            return 0
        l = max(go(n.left), 0)     # if negative, drop it (do not take this branch)
        r = max(go(n.right), 0)
        ans[0] = max(ans[0], l + n.val + r)   # the max path through the current node
        return n.val + max(l, r)              # can only pick one side going upward
    go(root)
    return ans[0]

print(max_path_sum(build([1, 2, 3])))            # 6  (1+2+3)
print(max_path_sum(build([-10, 9, 20, None, None, 15, 7])))  # 42  (15+20+7)
```

**`max(l, 0)` is the key: if a child path's sum is negative, discard it — equivalent to "not taking that branch."** This is the standard trick for "maximum sum" problems: negative values only drag the total down.

**The return value and the global update use different logic**: when returning, you "can only pick one side to go up" (because a path cannot fork); when updating the answer, you "take both left and right" (using the current node as the turning point).

## WRONG WAY: also adding both left and right in the return value, forking the path

```python
# WRONG: also adding left and right in the return, forking the path
def max_path_sum_wrong(root):
    ans = [float('-inf')]
    def go(n):
        if n is None:
            return 0
        l = max(go(n.left), 0)
        r = max(go(n.right), 0)
        ans[0] = max(ans[0], l + n.val + r)
        return n.val + l + r          # ← wrong! returns a forked path
    go(root)
    return ans[0]
```

**A path in a tree cannot fork** (a path is a single chain). When returning upward you must "pick left or right" using `max(l, r)`; only the full path that "uses the current node as the turning point and stops there" gets to add both sides.

## Summary

- Root-to-leaf path: preorder traversal + `target -= root.val` as a parameter; at the leaf check `target == 0`.
- **A leaf is the终点; an empty node is not.** Only count it as a success when `both children are empty AND target == 0`.
- Collecting all paths: backtracking with `append + pop`; **you must use `cur.copy()` when appending**.
- Paths ending at any node (437): enumerate starting points in the outer layer, enumerate downward paths in the inner layer.
- Maximum path sum between any two nodes (124): return `n.val + max(l, r)`, update the answer with `l + n.val + r`; use `max(.., 0)` to discard negative branches.
