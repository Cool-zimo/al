# Greedy vs. DP: When Is Greedy Correct?

> Greedy algorithms are much simpler to write than DP, but "greedy choice" isn't always correct. This lesson uses Activity Selection and Coin Change—two classic problems—to clarify why greedy works for some problems and fails for others.

## Greedy: At Each Step, Make the "Locally Optimal" Choice

**The greedy approach: at each step, make the locally optimal choice, hoping it leads to the globally optimal result.**

**Sounds great, but the key question is: does greedy actually guarantee the global optimum?**

**Answer: not always. Greedy is only correct when the problem satisfies the "greedy choice property."**

> **Greedy choice property**: If a problem satisfies—**after making the locally optimal choice, the optimal solution to the original problem still includes that choice**—then greedy is correct.

**In other words: if you pick the "best option right now," and no matter how you arrange things afterward, you can never do better than "not picking this option," then greedy works.**

## Activity Selection: Greedy Works

**Problem:** You have a set of activities, each with a start time and an end time. Only one activity can run at a time. What's the maximum number of activities you can attend?

**Greedy strategy: always pick the activity with the earliest end time.**

```python
def activity_selection(start, end):
    # Sort by end time
    activities = sorted(zip(start, end), key=lambda x: x[1])
    
    count = 0
    last_end = -1
    for s, e in activities:
        if s >= last_end:          # No conflict
            count += 1
            last_end = e
    return count

print(activity_selection([1, 3, 0, 5, 8], [2, 4, 6, 7, 9]))   # 4
```

**Why does greedy work?**

**Intuition:** The earlier an activity ends, the more time remains for subsequent activities. Picking the earliest-ending activity doesn't shrink your options for what comes next.

**Formal proof (exchange argument):** Suppose the optimal solution's first activity is A, and the earliest-ending activity is B (B ends no later than A). If we swap A with B in the optimal solution, we still get a valid solution (B ends earlier, so the remaining activities have at least as much room), with the same number of activities. So the optimal solution "can include" the earliest-ending activity—that's the greedy choice property.

**Since the optimal solution includes it, we confidently pick it and recursively solve the remaining subproblem.**

## Coin Change: Greedy Works Sometimes, Fails Other Times

**Problem:** Make change for amount using the fewest coins.

### Case 1: US Coin System {1, 5, 10, 25}, Greedy Works

```python
def coin_change_greedy(amount):
    coins = [25, 10, 5, 1]
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(coin_change_greedy(37))   # 4 (25+10+1+1)
```

**For US coins {1, 5, 10, 25}, greedy does give the optimal solution.** Because each larger denomination is a multiple of the smaller ones.

### Case 2: Coins {1, 3, 4}, Greedy Fails!

```python
# Making change for 6
# Greedy: pick 4 first → 2 left → 1+1 → total 3 coins (4+1+1)
# Optimal: 3+3 → total 2 coins!

def coin_change_greedy_bad(amount):
    coins = [4, 3, 1]      # Descending order
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(coin_change_greedy_bad(6))   # Outputs 3, but optimal is 2!
```

**Greedy gives 3 coins (4+1+1), but the optimal is 2 coins (3+3). Greedy failed!**

**Why?** Because 4 is not a multiple of 3. After picking 4, the remaining 2 can only be made with 1+1, but if you skip 4 and pick two 3s, you get fewer coins.

**This is a case where greedy doesn't hold—"picking the largest available" actually blocks a better combination.**

### Correct Approach: DP

```python
def coin_change_dp(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

print(coin_change_dp([1, 3, 4], 6))   # 2 (3+3)
```

**DP thinking: for each amount i, try "the last coin is c," then the remaining amount is i-c. Take the minimum over all possibilities.**

## Greedy vs. DP: How to Decide Which to Use?

**Core differences:**

| | Greedy | DP |
|---|---|---|
| Decision style | Only local optimum, never looks back | Considers all subproblem solutions, picks the best |
| Applicability | Requires "greedy choice property" | Only needs "optimal substructure" |
| Complexity | Usually O(n log n) | Usually O(n²) or higher |
| Correctness | Requires proof | Generally correct by construction |

**Decision process:**

```
1. Try to construct a greedy strategy
2. Find a counterexample (like {1,3,4} for amount 6)
3. Found a counterexample → greedy fails → use DP
4. No counterexample → try to prove (or trust intuition; in a contest, write greedy first)
```

## More Classic Problems Where Greedy Works

**The greedy strategies for these problems are all proven correct:**

1. **Minimum Spanning Tree (Kruskal)**: always pick the smallest edge that doesn't form a cycle → correct
2. **Single-source shortest path (Dijkstra)**: always pick the unvisited node with minimum distance → correct (non-negative edge weights)
3. **Task scheduling**: sort by end time and greedily pick → correct (like Activity Selection)
4. **Interval covering**: always pick the interval that covers the current position and extends farthest → correct

**Common thread: these all have the "greedy choice property"—after making the local optimal choice, the optimal solution to the remaining subproblem is unaffected.**

## WRONG: Using DP for a Problem Greedy Can Solve

**Activity Selection can be done with DP, but it's completely unnecessary.**

```python
# You can write DP, but it's O(n^2) instead of greedy O(n log n)
def activity_selection_dp(start, end):
    n = len(start)
    activities = sorted(zip(start, end), key=lambda x: x[1])
    ends = [a[1] for a in activities]
    starts = [a[0] for a in activities]
    
    dp = [0] * (n + 1)
    for i in range(1, n + 1):
        # Find the last activity that ends before starts[i-1]
        prev = 0
        for j in range(i - 1, 0, -1):
            if ends[j - 1] <= starts[i - 1]:
                prev = j
                break
        dp[i] = max(dp[i - 1], dp[prev] + 1)
    return dp[n]

# It works, but O(n^2) while greedy only needs O(n log n)
print(activity_selection_dp([1, 3, 0, 5, 8], [2, 4, 6, 7, 9]))   # 4
```

**Activity Selection satisfies the greedy choice property, so greedy O(n log n) solves it directly. Using DP gives you longer code and slower runtime.**

**Rule of thumb: if the problem has an obvious greedy strategy and you can't find a counterexample, use greedy.**

## WRONG: Using Greedy Without Proof, Failing on {1,3,4}

**The most common error—seeing "find the minimum" and blindly applying greedy.**

```python
# WRONG: greedy for ALL coin change problems
def min_coins_wrong(coins, amount):
    coins = sorted(coins, reverse=True)
    count = 0
    for c in coins:
        count += amount // c
        amount %= c
    return count

print(min_coins_wrong([1, 3, 4], 6))   # Outputs 3, correct answer is 2!
```

**Counterexample: coins=[1,3,4], amount=6. Greedy gives 4+1+1=3 coins, but optimal is 3+3=2 coins.**

**Fix: use DP.**

```python
def min_coins(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

print(min_coins([1, 3, 4], 6))   # 2
```

**Remember: greedy requires verifying the "greedy choice property." When in doubt, think of a counterexample first.**

## WRONG: Coin Change II (Counting Combinations), Reversed Loop Order

**"Minimum coins" and "number of coin combinations" are two different problems with different DP implementations.**

```python
# WRONG: reversed loop order when counting combinations
def coin_change_combo_wrong(coins, amount):
    dp = [0] * (amount + 1)
    dp[0] = 1
    for i in range(1, amount + 1):        # Amount first
        for c in coins:                    # Then coins
            if c <= i:
                dp[i] += dp[i - c]         # This double-counts!
    return dp[amount]

print(coin_change_combo_wrong([1, 2, 5], 5))   # Wrong output, double-counting
```

**The problem: iterating amount first then coins causes the same combination to be counted multiple times (e.g., 1+2 and 2+1 count as two).**

**Fix: outer loop over coins, inner loop over amounts (ensures each coin is used in order, no duplicates or omissions).**

```python
def coin_change_combo(coins, amount):
    dp = [0] * (amount + 1)
    dp[0] = 1
    for c in coins:                    # Outer loop: coins
        for i in range(c, amount + 1):  # Inner loop: amounts
            dp[i] += dp[i - c]
    return dp[amount]

print(coin_change_combo([1, 2, 5], 5))   # 4
```

## Summary

- **Greedy**: makes locally optimal choices at each step, simple code but requires "greedy choice property" to be correct
- **DP**: considers optimal solutions to all subproblems, broader applicability but more complex code
- **Greedy choice property**: after making the locally optimal choice, the global optimum still includes that choice
- **Activity Selection**: sort by end time, greedy, O(n log n), correct
- **Coin Change**: US coins {1,5,10,25} greedy works; {1,3,4} greedy fails, must use DP
- Decision method: construct a greedy strategy first, then find a counterexample; if none, try to prove
- Common pitfalls: blind greedy (fails on {1,3,4}), using DP for a problem greedy can solve, reversed loop order for counting combinations
