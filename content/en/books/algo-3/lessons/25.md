# Knapsack Problems: 0/1 Knapsack & Unbounded Knapsack

> The knapsack problem is a classic application of dynamic programming. This lesson covers the two most fundamental variants: 0/1 Knapsack (each item can be used at most once) and Unbounded Knapsack (each item can be used infinitely). The core insight is understanding "why 0/1 knapsack requires reverse-order traversal."

## 0/1 Knapsack: Each Item at Most Once

**Problem description:** You have a knapsack with capacity W and n items. Item i has weight `weight[i]` and value `value[i]`. **Each item can be chosen at most once.** Find the maximum total value you can carry.

### dp Array Definition

**The classic 0/1 knapsack uses a 2D dp:**

> `dp[i][j]` = the maximum value achievable using the first i items with a knapsack capacity of j

### Transition Equation

**For the i-th item (1-indexed), there are two choices:**

```
Skip item i:    dp[i][j] = dp[i-1][j]
Take item i (only if j >= weight[i]):  dp[i][j] = dp[i-1][j-weight[i]] + value[i]

dp[i][j] = max(dp[i-1][j], dp[i-1][j-weight[i]] + value[i])
```

```python
def knapsack_2d(W, weights, values):
    n = len(weights)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        for j in range(W + 1):
            dp[i][j] = dp[i - 1][j]    # Skip item i
            if j >= weights[i - 1]:    # Enough capacity, try taking it
                dp[i][j] = max(dp[i][j],
                               dp[i - 1][j - weights[i - 1]] + values[i - 1])
    return dp[n][W]

print(knapsack_2d(4, [1, 2, 3], [15, 20, 30]))   # 35
```

### Space Optimization: 1D dp + Reverse-Order Traversal

**Notice that dp[i][j] only depends on dp[i-1][...] (the previous row), so we can use a 1D array with rolling optimization:**

```python
def knapsack_1d(W, weights, values):
    n = len(weights)
    dp = [0] * (W + 1)
    
    for i in range(n):
        for j in range(W, weights[i] - 1, -1):   # REVERSE! From W down to weight[i]
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])
    
    return dp[W]

print(knapsack_1d(4, [1, 2, 3], [15, 20, 30]))   # 35
```

### Why Must 0/1 Knapsack Use Reverse Order?

**This is the core of the lesson.**

**The meaning of the 1D dp[j]: `dp[j]` = the maximum value achievable with a knapsack of capacity j (in the current state).**

**When considering the i-th item, updating `dp[j]` requires the "previous round's" value of `dp[j - weights[i]]`.**

- **Forward order (j从小到大)**: when updating dp[j], `dp[j - weights[i]]` may have already been updated in this round → meaning item i was **used more than once**
- **Reverse order (j从大到小)**: when updating dp[j], `dp[j - weights[i]]` hasn't been updated yet this round → guarantees item i is used only once

```
Forward (WRONG): dp[j] depends on dp[j-w], which may have been overwritten this round
  dp = [0, 0, 0, 0, 0]
  Consider item with weight=2, value=15:
  j=2: dp[2] = max(0, dp[0]+15) = 15 → dp = [0, 0, 15, 0, 0]
  j=3: dp[3] = max(0, dp[1]+15) = 0
  j=4: dp[4] = max(0, dp[2]+15) = 30 ← dp[2] is already 15 from this round! Item used twice!

Reverse (CORRECT):
  dp = [0, 0, 0, 0, 0]
  Consider item with weight=2, value=15:
  j=4: dp[4] = max(0, dp[2]+15) = 15 → dp = [0, 0, 0, 0, 15]
  j=3: dp[3] = max(0, dp[1]+15) = 0
  j=2: dp[2] = max(0, dp[0]+15) = 15 → dp = [0, 0, 15, 0, 15]
  → Each item is used at most once
```

**In one sentence: reverse order guarantees that `dp[j - w]` is the "previous round's" value; forward order causes the "current round's" value to be reused → item selected repeatedly.**

## Unbounded Knapsack: Items Can Be Used Infinitely

**The only difference between Unbounded Knapsack and 0/1 Knapsack: each item can be selected an unlimited number of times.**

**This means—we can use forward order!**

```python
def unbounded_knapsack(W, weights, values):
    dp = [0] * (W + 1)
    
    for i in range(len(weights)):
        for j in range(weights[i], W + 1):    # FORWARD! From weight[i] to W
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])
    
    return dp[W]

print(unbounded_knapsack(4, [1, 2, 3], [15, 20, 30]))   # 60 (four of weight 1)
```

**Why does Unbounded Knapsack use forward order?** Because in forward order, `dp[j - w]` may have already been updated this round, meaning **the same item can be selected again**—which is exactly what Unbounded Knapsack requires.

**Comparison:**

| | 0/1 Knapsack | Unbounded Knapsack |
|---|---|---|
| Item usage | At most 1 | Unlimited |
| Traversal | **Reverse** (W → w) | **Forward** (w → W) |
| Essence | Use previous round's value | Allow current round's value |

## WRONG: 0/1 Knapsack Using Forward Order, Item Reused

**This is the most frequent error in 0/1 knapsack—getting the traversal direction wrong.**

```python
# WRONG: 0/1 knapsack using forward order
def knapsack_wrong(W, weights, values):
    n = len(weights)
    dp = [0] * (W + 1)
    for i in range(n):
        for j in range(weights[i], W + 1):   # Forward! WRONG!
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])
    return dp[W]

print(knapsack_wrong(4, [2], [10]))   # Expected 10, got 20!
```

**Why does it output 20?** There's only one item with weight 2 and value 10. With capacity 4:

```
Forward traversal:
  j=2: dp[2] = max(0, dp[0]+10) = 10 → dp = [0, 0, 10, 0, 0]
  j=3: dp[3] = max(0, dp[1]+10) = 0
  j=4: dp[4] = max(0, dp[2]+10) = 20 ← dp[2] is already 10! Item used twice!
```

**The same item was used twice, violating the "at most once" constraint.** Fix: change the traversal to reverse order `range(W, weights[i] - 1, -1)`.

## WRONG: dp Array Size W, But Accessing dp[j - weights[i]] Causes Index Error

**The inner loop starts from `weights[i]`, but if weights[i] is larger than W, the loop won't execute (which is correct). However, if you write `range(1, W+1)` without checking capacity, you'll get an index error.**

```python
# WRONG: inner loop starts from 1, no capacity check
def knapsack_bad(W, weights, values):
    n = len(weights)
    dp = [0] * (W + 1)
    for i in range(n):
        for j in range(1, W + 1):           # Starts from 1, no check for j >= weights[i]
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])  # Out of bounds when j < weights[i]
    return dp[W]

# IndexError: list index out of range
```

**Fix: start the inner loop from `weights[i]`: `for j in range(weights[i], W + 1)` (unbounded, forward) or `range(W, weights[i] - 1, -1)` (0/1, reverse).**

## WRONG: Initializing dp to 1 Instead of 0, Inflating All Values

**The dp array should be initialized to 0 (maximum value with 0 capacity is 0). If initialized to 1, all computed results will be too large.**

```python
# WRONG: dp initialized to 1
def knapsack_init_wrong(W, weights, values):
    n = len(weights)
    dp = [1] * (W + 1)    # WRONG! Should be [0] * (W + 1)
    for i in range(n):
        for j in range(W, weights[i] - 1, -1):
            dp[j] = max(dp[j], dp[j - weights[i]] + values[i])
    return dp[W]

print(knapsack_init_wrong(4, [1, 2, 3], [15, 20, 30]))  # Result is too large
```

**`dp[0] = 1` means "with 0 capacity, we already have value 1," which is wrong.** With 0 capacity, you can't carry anything, so the value must be 0.

**Note: for the "exact capacity" variant, the initialization differs—`dp[0] = 0`, and all other `dp[j] = -inf` (meaning unreachable).**

## Summary

- **0/1 Knapsack**: each item at most once, transition `dp[j] = max(dp[j], dp[j-w] + v)`, **reverse traversal**
- **Unbounded Knapsack**: unlimited items, same transition but **forward traversal**
- **Reverse order essence**: guarantees `dp[j-w]` is from the previous round, item not reused
- **Forward order essence**: allows `dp[j-w]` to be from the current round, item can be reused
- **Initialize dp to all 0s**: default is "don't need exact capacity," `dp[0] = 0` means empty knapsack has value 0
- Common pitfalls: reversed traversal direction, wrong loop start position, incorrect dp initialization

```quiz
answer: 0
explain: 0/1 knapsack requires each item at most once. In reverse order, the dp[j-w] used to update dp[j] hasn't been overwritten yet this round—it's the "previous round" state (without the current item), ensuring the item isn't reused. Unbounded knapsack allows unlimited selections, so forward order means dp[j-w] may have already been updated this round, effectively allowing the current item to be selected again.
```
