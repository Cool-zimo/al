# State & Transition: How to Define the DP Array

> "What does dp[i] mean?"—this is the hardest step in dynamic programming. Many students can write the code but have no idea what the dp array actually represents. This lesson walks you through defining the state and deriving the transition equation step by step.

## Step 1: State the Meaning of dp[i] in One Sentence

**Defining the dp array is the soul of DP.** You must be able to say clearly: "dp[i] means…" A vague definition will inevitably lead to an incorrect transition equation.

**Taking climbing stairs as an example, the correct definition is:**

> `dp[i]` = the **total number of ways** to reach the **i-th step**

**Note the key points:**

- **"Reach"** is crucial—not "starting from step i," but "arriving at step i"
- **"Total number of ways"** is a concrete quantity—not a vague "some value"
- With this definition, you can derive `dp[i] = dp[i-1] + dp[i-2]`

**If the definition is vague, like "dp[i] represents the situation at step i," you simply cannot write a transition equation.**

## Step 2: Derive the State Transition Equation

**The state transition equation describes "how the big problem is composed of smaller problems."** The three-step method for finding the transition:

1. **Consider the last move**: what did you do in the final step to reach position i?
2. **Enumerate cases**: what are all the possible final moves?
3. **Write the equation**: add up the number of ways for each case

**Using climbing stairs as an example:**

```
Final move to reach step i:
  Option A: take 1 step from step i-1 → dp[i-1] ways to reach step i-1
  Option B: take 2 steps from step i-2 → dp[i-2] ways to reach step i-2

∴ dp[i] = dp[i-1] + dp[i-2]
```

**Another example: Minimum Path Sum.** Given an m×n grid where each cell has a number, you can only move right or down. Find the minimum path sum from the top-left to the bottom-right corner.

```
dp[i][j] = minimum path sum to reach cell (i, j)

Final move to reach (i, j):
  Option A: come down from above (i-1, j) → dp[i-1][j]
  Option B: come from the left (i, j-1) → dp[i][j-1]

∴ dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]
```

## Step 3: Determine the Base Cases

**Base cases are the starting point of the recurrence—they must be initialized manually.** Usually, these are the simplest states that can be determined without any transition.

```python
# Minimum Path Sum: initialize the first row and first column
def min_path_sum(grid):
    m, n = len(grid), len(grid[0])
    dp = [[0] * n for _ in range(m)]
    
    dp[0][0] = grid[0][0]          # Starting point
    
    # First row: can only come from the left
    for j in range(1, n):
        dp[0][j] = dp[0][j - 1] + grid[0][j]
    
    # First column: can only come from above
    for i in range(1, m):
        dp[i][0] = dp[i - 1][0] + grid[i][0]
    
    # Fill in the rest
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j]
    
    return dp[m - 1][n - 1]

print(min_path_sum([[1, 3, 1], [1, 5, 1], [4, 2, 1]]))  # 7
```

**The role of base cases is to "provide a starting point for the recurrence."** Without correct base cases, the recurrence has no foundation.

## Step 4: Determine the Filling Order

**The filling order must guarantee that "when computing dp[i], all subproblems it depends on have already been computed."**

- 1D DP: usually left to right (small to large)
- 2D DP: usually left to right within each row, top to bottom
- Special DP: may need diagonal order, by length, etc.

**For minimum path sum: computing dp[i][j] requires dp[i-1][j] (above) and dp[i][j-1] (left).** So filling row by row, left to right, top to bottom guarantees that dependencies are already computed.

## WRONG: Vague dp Definition Leading to a Broken Transition

**This is the most typical DP failure mode: you start coding without thinking through what dp[i] actually means.**

```python
# WRONG: vague dp[i] meaning, wrong transition equation
def house_robber_wrong(nums):
    # Trying to solve "House Robber": can't rob adjacent houses
    # What does dp[i] mean? Started coding without clarity
    dp = [0] * len(nums)
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])
    for i in range(2, len(nums)):
        # Thought dp[i] meant "max profit from first i houses"
        # But forgot the case where we don't rob house i
        dp[i] = dp[i - 1] + nums[i]   # WRONG! This might rob adjacent houses
    return dp[-1]

print(house_robber_wrong([2, 7, 9, 3, 1]))  # Expected 12, gets larger or errors
```

**Correct thinking: `dp[i]` should mean "the maximum amount you can rob up to and including house i."** The transition equation:

```
dp[i] = max(dp[i-1], dp[i-2] + nums[i])
         ↑ skip house i     ↑ rob house i (so house i-1 can't be robbed)
```

**Key insight: the transition equation must cover both "do it" and "skip it" cases, then take the maximum or minimum.**

## WRONG: Only Initializing One Base Case, Causing Index Errors

**A recurrence often needs to access dp[i-2]. If you only initialize dp[0], then at i=1 you'll access dp[-1].**

```python
# WRONG: only initialized dp[0], forgot dp[1]
def rob_wrong(nums):
    n = len(nums)
    if n == 0: return 0
    dp = [0] * n
    dp[0] = nums[0]
    # Forgot dp[1] = max(nums[0], nums[1])
    for i in range(1, n):           # Starting from 1
        prev = dp[i - 2] if i >= 2 else 0  # Using ternary as a workaround
        dp[i] = max(dp[i - 1], prev + nums[i])
    return dp[-1]

# It runs, but the logic is convoluted and error-prone
# Correct approach: explicitly initialize both dp[0] and dp[1]
```

**Correct version:**

```python
def rob(nums):
    n = len(nums)
    if n == 0: return 0
    if n == 1: return nums[0]
    dp = [0] * n
    dp[0] = nums[0]
    dp[1] = max(nums[0], nums[1])
    for i in range(2, n):
        dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
    return dp[-1]

print(rob([2, 7, 9, 3, 1]))   # 12
```

**Explicit base cases are much clearer than convoluted ternary expressions, and they make debugging far easier.**

## Summary

- **DP Four-Step Method**: define the state → write the transition equation → determine base cases → determine filling order
- **The meaning of dp[i] must be statable in one precise sentence**, including keywords like "reach / choose / ending at" and a concrete quantity
- **The transition equation must cover all choices** (do/don't, which one to pick), taking a max/min or sum
- **Base cases are the starting point**; allocating an array one slot larger (size n+1) greatly simplifies boundary handling
- The filling order must ensure that dependent subproblems are already computed
- Common pitfalls: vague dp meaning, incomplete base cases, missing cases in the transition
