# Capstone: One Problem from Brute Force → Optimization → Optimal

> This lesson uses "Maximum Subarray Sum" to demonstrate the complete evolution from the most naive brute force through divide-and-conquer to the optimal solution. Learning this "step-by-step optimization" mindset will help you tackle new problems independently.

## The Problem: Maximum Subarray Sum

**Problem:** Given an integer array nums, find a contiguous subarray with the largest sum (a subarray must contain at least one element), and return that maximum sum.

**Example:**

```
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Maximum subarray is [4, -1, 2, 1], sum = 6
```

**Why this problem?** It's simple enough for anyone to understand, yet rich enough to have 4 solution approaches, from O(n³) to O(n). Walking through all of them, you'll experience how "optimization" happens step by step.

## Level 1: Brute Force Enumeration O(n³)

**The most naive approach: enumerate all possible start and end positions of subarrays, summing each one.**

```python
def max_subarray_bruteforce(nums):
    n = len(nums)
    ans = float('-inf')
    for i in range(n):
        for j in range(i, n):
            s = 0
            for k in range(i, j + 1):    # Sum each element
                s += nums[k]
            ans = max(ans, s)
    return ans

print(max_subarray_bruteforce([-2, 1, -3, 4, -1, 2, 1, -5, 4]))   # 6
```

**Complexity O(n³).** At n=10⁴, it's unusable.

**What's the problem?** The innermost loop recomputes the sum from i to j every time, doing massive redundant work.

## Level 2: Optimized Enumeration + Prefix Sums O(n²)

**Optimization idea: enumerate start i, then expand end j while accumulating, avoiding recomputation.**

```python
def max_subarray_n2(nums):
    n = len(nums)
    ans = float('-inf')
    for i in range(n):
        cur = 0
        for j in range(i, n):
            cur += nums[j]          # Accumulate, no need to restart from i
            ans = max(ans, cur)
    return ans

print(max_subarray_n2([-2, 1, -3, 4, -1, 2, 1, -5, 4]))   # 6
```

**Complexity O(n²).** Better than O(n³), but still TLE at n=10⁵.

**Further: use prefix sums to reduce sum queries to O(1).**

```python
def max_subarray_prefix(nums):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    
    ans = float('-inf')
    for i in range(n):
        for j in range(i, n):
            s = prefix[j + 1] - prefix[i]    # O(1) sum query
            ans = max(ans, s)
    return ans

print(max_subarray_prefix([-2, 1, -3, 4, -1, 2, 1, -5, 4]))   # 6
```

**Still O(n²), just with a smaller constant.** Can we do better?

## Level 3: Divide and Conquer O(n log n)

**Divide-and-conquer idea: the maximum subarray is either in the left half, the right half, or crosses the midpoint.**

```python
def max_subarray_divide(nums):
    def helper(left, right):
        if left == right:
            return nums[left]
        
        mid = (left + right) // 2
        
        # Recurse on left and right halves
        left_max = helper(left, mid)
        right_max = helper(mid + 1, right)
        
        # Case: crosses the midpoint
        # Find max suffix sum from mid going left
        left_sum = 0
        left_best = float('-inf')
        for i in range(mid, left - 1, -1):
            left_sum += nums[i]
            left_best = max(left_best, left_sum)
        
        # Find max prefix sum from mid+1 going right
        right_sum = 0
        right_best = float('-inf')
        for i in range(mid + 1, right + 1):
            right_sum += nums[i]
            right_best = max(right_best, right_sum)
        
        cross_max = left_best + right_best
        return max(left_max, right_max, cross_max)
    
    return helper(0, len(nums) - 1)

print(max_subarray_divide([-2, 1, -3, 4, -1, 2, 1, -5, 4]))   # 6
```

**Complexity O(n log n).** Recursion depth is log n, each level does O(n) work.

**Much better than O(n²), but can we do even better?**

## Level 4: Kadane's Algorithm O(n) — The Optimal Solution

**Core insight: if the maximum subarray sum ending at position j is negative, it only drags down whatever comes after it. Better to restart from j+1.**

```python
def max_subarray(nums):
    n = len(nums)
    cur = nums[0]        # Maximum subarray sum ending at current position
    ans = nums[0]
    
    for i in range(1, n):
        cur = max(nums[i], cur + nums[i])   # Either restart here, or extend the previous subarray
        ans = max(ans, cur)
    
    return ans

print(max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4]))   # 6
```

**This is Kadane's Algorithm: O(n) time, O(1) space.**

**Intuitive understanding:**

```
At position i:
  If nums[i] alone is greater than "previous sum + nums[i]"
  → The previous prefix was negative; discard it, restart from nums[i]
  Otherwise → extend the previous subarray
```

**Comparison of all four approaches:**

| Method | Time | Space | Core idea |
|---|---|---|---|
| Brute force | O(n³) | O(1) | Enumerate all subarrays |
| Prefix sums | O(n²) | O(n) | Avoid recomputing sums |
| Divide & conquer | O(n log n) | O(log n) | Left + Right + Cross-midpoint |
| Kadane | O(n) | O(1) | Discard negative prefixes |

## The General Methodology of Optimization

**From this problem's evolution, we can extract a general optimization framework:**

```
Step 1: Write the most naive brute force → confirm understanding
Step 2: Find redundant computation → eliminate with prefix sums/memoization
Step 3: Find the decision structure → divide & conquer? DP?
Step 4: Find greedy opportunities → can local optimum lead to global optimum?
Step 5: Verify correctness → find counterexamples
```

**Applied to this specific problem:**

1. Brute force enumerate all subarrays → O(n³)
2. Notice repeated summing → prefix sums → O(n²)
3. Notice "negative prefixes should be discarded" → greedy → Kadane → O(n)

**Every optimization step comes from a specific observation.**

## WRONG: Kadane Initialized to 0, All-Negative Array Fails

**The most common error—initializing both cur and ans to 0.**

```python
# WRONG: initialized to 0
def max_subarray_wrong(nums):
    cur = 0
    ans = 0
    for x in nums:
        cur = max(x, cur + x)
        ans = max(ans, cur)
    return ans

print(max_subarray_wrong([-2, -1, -3]))   # Outputs 0, correct answer is -1!
```

**Why is it wrong?** If the array is all negative, the maximum subarray sum should be a negative number (the largest negative). But ans initialized to 0 returns 0 (equivalent to selecting an empty subarray).

**Fix: initialize to nums[0], or handle the "all negative" special case.**

```python
def max_subarray_fixed(nums):
    cur = nums[0]
    ans = nums[0]
    for i in range(1, len(nums)):
        cur = max(nums[i], cur + nums[i])
        ans = max(ans, cur)
    return ans

print(max_subarray_fixed([-2, -1, -3]))   # -1
```

## WRONG: Divide & Conquer Forgot "Cross-Midpoint," Wrong Result

**In divide-and-conquer, only handling left and right but missing the cross-midpoint case.**

```python
# WRONG: divide & conquer missing the cross-midpoint case
def helper_wrong(nums, left, right):
    if left == right:
        return nums[left]
    mid = (left + right) // 2
    return max(helper_wrong(nums, left, mid),
               helper_wrong(nums, mid + 1, right))
    # Missing the cross-midpoint case!

# nums = [2, -1, 2]
# Left [2,-1] max=2, right [2] max=2
# But [2,-1,2]=3 crossing midpoint is larger, and gets missed
```

**Fix: add the cross-midpoint calculation.**

```python
def helper_fixed(nums, left, right):
    if left == right:
        return nums[left]
    mid = (left + right) // 2
    left_max = helper_fixed(nums, left, mid)
    right_max = helper_fixed(nums, mid + 1, right)
    
    # Cross-midpoint case
    left_sum = 0
    left_best = float('-inf')
    for i in range(mid, left - 1, -1):
        left_sum += nums[i]
        left_best = max(left_best, left_sum)
    
    right_sum = 0
    right_best = float('-inf')
    for i in range(mid + 1, right + 1):
        right_sum += nums[i]
        right_best = max(right_best, right_sum)
    
    return max(left_max, right_max, left_best + right_best)
```

## WRONG: Returning Only the Sum, But Also Need the Interval

**Sometimes the problem asks not just for the maximum sum, but also the corresponding subarray.**

```python
# WRONG: only returns the sum, doesn't track the interval
def max_subarray_no_range(nums):
    cur = nums[0]
    ans = nums[0]
    for i in range(1, len(nums)):
        cur = max(nums[i], cur + nums[i])
        ans = max(ans, cur)
    return ans    # Don't know which subarray it is

# If the problem also needs the subarray itself, we need extra tracking
```

**Fix: use two variables to track the optimal interval's endpoints.**

```python
def max_subarray_with_range(nums):
    cur = nums[0]
    ans = nums[0]
    start = end = 0
    temp_start = 0    # Start of the current segment
    
    for i in range(1, len(nums)):
        if nums[i] > cur + nums[i]:
            cur = nums[i]
            temp_start = i        # Restart from i
        else:
            cur += nums[i]
        
        if cur > ans:
            ans = cur
            start = temp_start
            end = i
    
    return ans, nums[start:end + 1]

print(max_subarray_with_range([-2, 1, -3, 4, -1, 2, 1, -5, 4]))
# (6, [4, -1, 2, 1])
```

## Summary

- **Maximum Subarray Sum** has four solutions: brute force O(n³), prefix sums O(n²), divide & conquer O(n log n), Kadane O(n)
- **Kadane's Algorithm**: `cur = max(nums[i], cur + nums[i])`—discard negative prefixes decisively
- **General optimization path**: brute force → eliminate redundancy → divide & conquer / DP → greedy
- Every optimization step comes from a specific observation, not out of thin air
- Common pitfalls: Kadane initialized to 0 (fails on all-negative), divide & conquer missing cross-midpoint, returning only the sum without tracking the interval
- **Learning "step-by-step optimization" matters more than memorizing any specific algorithm**
