# Heaps and Priority Queues: Array Representation of a Complete Binary Tree, and heapq

> A heap is a special kind of complete binary tree: a parent's value is always "no greater than / no smaller than" its children's values. Its killer application is the priority queue — you can grab the maximum or minimum element in O(1) at any time. This lesson covers its array representation and Python's `heapq`.

## The complete binary tree: the physical structure of a heap

**A complete binary tree is a binary tree that is "filled top to bottom, left to right."** Every level except the last is completely filled, and the nodes on the last level are as far left as possible.

```
        10
      /    \
     7      9
    / \    / \
   5   6  3   8
  /
 2
```

**The biggest advantage of a complete binary tree: it can be stored compactly in an array, with no pointers.** Using 0-based indexing, node i's left child is `2i+1`, its right child is `2i+2`, and its parent is `(i-1)//2`.

```python
heap = [10, 7, 9, 5, 6, 3, 8, 2]
# index 0:10, 1:7, 2:9, 3:5, 4:6, 5:3, 6:8, 7:2
print(heap[1], heap[2*1+1], heap[2*1+2])   # 7 5 6  (the children of node 7)
print(heap[(5-1)//2])                       # 9  (the parent of node 3)
```

**`2i+1` and `(i-1)//2` are the lifeblood of a heap.** Every heap operation — insert, delete, sink, swim — locates parents and children in the array using these two formulas, with no pointer manipulation involved.

## The heap property: a parent is no smaller / no larger than its children

**In a max-heap, every parent's value is ≥ both of its children's values. In a min-heap, every parent's value is ≤ both of its children's values.**

**The root of a heap is the global maximum (or minimum) element, accessible in O(1).** This is the core value of a heap.

```python
max_heap = [100, 80, 90, 50, 60, 70, 85]
print(max_heap[0])   # 100, the maximum, in O(1)
```

**A heap is "partially ordered," not "fully ordered."** A parent ≥ its children, but there is no size relationship between left and right siblings. So a heap cannot do binary search the way a BST can (finding a specific value takes O(n)).

**This distinction matters**: a BST is ordered so it can search for and delete any value; a heap makes no ordering guarantees, but it keeps "grab the maximum/minimum" at O(log n). They optimize different operations.

## heapq: Python's min-heap

**Python's standard library `heapq` implements a min-heap.** Every operation works on an ordinary list.

```python
import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
heapq.heappush(h, 2)
heapq.heappush(h, 4)

print(h)            # [1, 2, 4, 5, 3]  ← note: not fully sorted
print(heapq.heappop(h))   # 1
print(heapq.heappop(h))   # 2
print(heapq.heappop(h))   # 3
```

**`heapq.heappush(h, x)` adds x to the heap and maintains the heap property, O(log n).**
**`heapq.heappop(h)` pops and returns the minimum value, O(log n).**

**`h` does not look sorted, but it satisfies the heap property.** Printing `h` gives `[1, 2, 4, 5, 3]`, which is indeed not ascending. But `heappop` always returns the current minimum — "partially ordered is enough."

## heapify: turning an ordinary list into a heap

**`heapq.heapify(lst)` turns any list into a heap in place, O(n).** This is faster than pushing elements one by one (which totals O(n log n)).

```python
import heapq

a = [5, 1, 3, 2, 4]
heapq.heapify(a)
print(a)   # [1, 2, 4, 5, 3]

# pop repeatedly
while a:
    print(heapq.heappop(a), end=' ')   # 1 2 3 4 5
```

**After `heapify`, repeatedly calling `heappop` yields an ascending sequence — that is heap sort.** It runs in O(n log n), uses O(1) extra space (in place), but is not stable.

## WRONG WAY: heapq is a min-heap; to get the maximum you must negate

```python
# WRONG: using heapq directly hoping to "get the maximum first," but getting the minimum
import heapq
h = []
for x in [5, 1, 3, 2, 4]:
    heapq.heappush(h, x)
print(heapq.heappop(h))   # 1, not 5
```

**`heapq` is always a min-heap; there is no "switch to max-heap" option.**

**To get a max-heap, store the negatives:**

```python
import heapq
h = []
for x in [5, 1, 3, 2, 4]:
    heapq.heappush(h, -x)        # store negatives
print(-heapq.heappop(h))         # 5  ✓
```

**After storing negatives, the "most negative" corresponds to the "largest positive."** This is the standard trick for simulating a max-heap with a min-heap. It is used in Top-K largest elements, Dijkstra, and many other scenarios.

## Heap insertion: append at the end, then swim upward

**Insertion steps: place the new element at the end of the array, then repeatedly compare it with its parent; if it is "better" than the parent, swap, until the heap property is restored.**

```python
def heap_push(heap, x):
    heap.append(x)
    i = len(heap) - 1
    while i > 0:
        parent = (i - 1) // 2
        if heap[i] < heap[parent]:    # min-heap: swap if child < parent
            heap[i], heap[parent] = heap[parent], heap[i]
            i = parent
        else:
            break

h = []
for x in [5, 1, 3, 2, 4]:
    heap_push(h, x)
print(h)   # [1, 2, 4, 5, 3]
```

**Swimming takes at most h = O(log n) steps, so insertion is O(log n).**

## Heap popping: take the root, refill with the last element, then sink

**Pop steps: save the root (the minimum), move the last element to the root, then repeatedly swap it with the "better" of its two children, sinking it into the correct position.**

```python
def heap_pop(heap):
    if not heap:
        raise IndexError("pop from empty heap")
    ans = heap[0]
    last = heap.pop()
    if not heap:           # heap became empty after the pop
        return ans
    heap[0] = last
    i = 0
    n = len(heap)
    while True:
        left = 2 * i + 1
        right = 2 * i + 2
        smallest = i
        if left < n and heap[left] < heap[smallest]:
            smallest = left
        if right < n and heap[right] < heap[smallest]:
            smallest = right
        if smallest == i:
            break
        heap[i], heap[smallest] = heap[smallest], heap[i]
        i = smallest
    return ans

h = [1, 2, 4, 5, 3]
print(heap_pop(h))   # 1
print(h)             # [2, 3, 4, 5]
```

**Sinking also takes at most O(log n) steps.** Every core heap operation — push, pop, swim, sink — is O(log n).

## Heap application: finding the kth largest element

**Top-K: maintain a heap of size K holding "the smallest K so far" or "the largest K so far."**

```python
import heapq

def kth_largest(nums, k):
    """Return the kth largest element."""
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)      # keep the heap size at k
    return heap[0]

print(kth_largest([3, 2, 1, 5, 6, 4], 2))   # 5
```

**The heap always holds "the largest K elements"; the top is the smallest among those K, i.e., the kth largest.** Time is O(n log k), space is O(k). This is more memory-efficient than sorting at O(n log n), especially when k is small.

**If k is large (close to n), sorting is actually simpler.** Always choose the algorithm based on the data range (this thinking is covered systematically in lesson 26).

## WRONG WAY: after heapify, assuming the list is fully sorted

```python
import heapq
a = [5, 1, 3, 2, 4]
heapq.heapify(a)
print(a)                # [1, 2, 4, 5, 3]
print(a[1] < a[2])      # True, but the whole list is not ascending
```

**After `heapify`, `a` is not an ascending list.** It only guarantees "parent ≤ child." To get a fully sorted result, you must repeatedly call `heappop`.

**`heapq` does not provide "sort the list"; it only provides "grab the minimum."** If you need a complete sort, just use `sorted()` (Timsort, which is usually faster).

## Summary

- A complete binary tree is stored in an array: left child `2i+1`, right child `2i+2`, parent `(i-1)//2`.
- Max-heap: parent ≥ children; min-heap: parent ≤ children. The root is the global extremum, accessible in O(1).
- **A heap is partially ordered and cannot do binary search**; a BST is globally ordered but takes O(log n) to grab an extremum.
- `heapq` is a min-heap: `heappush`, `heappop`, and `heapify` are O(log n)/O(n) respectively.
- To get a max-heap, store `-x`.
- Insert = append at the end then swim up; pop = refill the root with the last element then sink; both are O(log n).
- Top-K uses a heap of size K, O(n log k).
