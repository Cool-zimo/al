# What Is Dynamic Programming: Overlapping Subproblems & Optimal Substructure

> Dynamic Programming (DP) is one of the most practical and high-frequency techniques in competitive programming. It breaks a "big problem" into "smaller problems," remembers the answers to those smaller problems, and reuses them—avoiding redundant computation and compressing exponential complexity into polynomial time.

## Starting with Fibonacci: An Exploding Recursion Tree

**The Fibonacci sequence is defined simply: F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2).** The most intuitive implementation is recursive:

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))   # 55
```

**This implementation has time complexity O(2ⁿ).** Why? The recursion tree makes it crystal clear:

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) → fib(1)+fib(0)
│   │   └── fib(1)
│   └── fib(2)
│       ├── fib(1)
│       └── fib(0)
└── fib(3)  ← computed again!
    ├── fib(2)  ← computed again!
    └── fib(1)
```

**`fib(3)` is computed twice, `fib(2)` is computed three times—the deeper you go, the more repetition.** This is **overlapping subproblems**: the same subproblem is solved over and over.

## Memoization: Remembering the Answers

**Since subproblems reappear, compute them once and store the result for lookup next time.** This is "memoization":

```python
def fib_memo(n, memo=None):
    if memo is None:
        memo = {}
    if n in memo:           # Lookup: already computed, return immediately
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

print(fib_memo(50))   # 12586269025, instant
```

**Time complexity drops from O(2ⁿ) to O(n).** Each `fib(k)` is computed exactly once; there are n distinct subproblems, each costing O(1). Space complexity is also O(n) (recursion stack + memo table).

**The three steps of memoization:**

1. Define a "memo" (dictionary or array)
2. At the start of the function, check the table—if found, return immediately
3. After computing, store the result in the table

## Bottom-Up: Filling the Table

**If memoization is top-down, can we flip it—start from the smallest subproblems and work our way up?** Absolutely. This is the **bottom-up** approach:

```python
def fib_dp(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)    # dp[i] represents F(i)
    dp[0] = 0
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_dp(50))   # 12586269025
```

**The essence of bottom-up is "filling the table": dp[0], dp[1], dp[2]… all the way to dp[n].** Each cell depends only on previously filled cells—never looking back.

**Comparing the three approaches:**

| Approach | Time | Space | Direction |
|----------|------|-------|-----------|
| Pure recursion | O(2ⁿ) | O(n) stack | Top-down |
| Memoization | O(n) | O(n) | Top-down |
| Bottom-up | O(n) | O(n) | Bottom-up |

## Optimal Substructure: The Optimal Solution Contains Optimal Solutions

**The second requirement for DP is "optimal substructure."** What does this mean? Let's use "climbing stairs" as an example:

> You can climb either 1 or 2 steps at a time. How many distinct ways are there to reach the nth step?

**To reach the nth step, the last move has only two possibilities: a 1-step from step n-1, or a 2-step from step n-2.** So:

> Number of ways to reach step n = number of ways to reach step n-1 + number of ways to reach step n-2

**This is optimal substructure: the solution to the big problem can be assembled from optimal solutions to smaller problems.**

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    dp[2] = 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(climb_stairs(5))   # 8
```

**Climbing stairs is essentially a Fibonacci variant.** The meaning of dp[i] is "the number of ways to reach step i," and the transition is `dp[i] = dp[i-1] + dp[i-2]`.

## WRONG: Forgetting the Base Case in Memoization

**The most common beginner mistake: the memo table doesn't contain the base case, leading to infinite recursion or an error.**

```python
# WRONG: no base case initialized in memo
def fib_bug(n, memo={}):
    if n in memo:
        return memo[n]
    # Forgot memo[0]=0, memo[1]=1
    memo[n] = fib_bug(n - 1) + fib_bug(n - 2)   # Infinite recursion!
    return memo[n]

# RecursionError: maximum recursion depth exceeded
```

**Why does it crash?** Because `fib_bug(1)` calls `fib_bug(0)` and `fib_bug(-1)`, and `fib_bug(-1)` calls `fib_bug(-2)` and `fib_bug(-3)`… it never reaches a base case.

**Fix: either use `if n <= 1: return n` (a natural base case), or explicitly initialize `memo[0]` and `memo[1]` in the memo table.**

## WRONG: Mismatched Array Size and Index in Climbing Stairs

**Another frequent bug: the dp array is too small, or confusion about whether indexing starts at 0 or 1.**

```python
# WRONG: dp has size n, but accesses dp[n]
def climb_wrong(n):
    dp = [0] * n        # Only dp[0] ~ dp[n-1]
    dp[1] = 1
    dp[2] = 2           # IndexError! n might be only 2, dp[2] is out of bounds
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]         # IndexError! dp[n] is out of bounds

# IndexError: list assignment index out of range
```

**Fix: allocate the dp array with size `n + 1`, indexing from 0 to n, using `dp[i]` to mean "the number of ways to reach step i."** This "one extra slot" technique is extremely common in DP—it's specifically used to handle boundary conditions cleanly.

## Summary

- **Overlapping subproblems**: the same subproblem is solved repeatedly → use memoization or bottom-up to avoid redundancy
- **Optimal substructure**: the optimal solution to the big problem is assembled from optimal solutions to smaller problems → the prerequisite for DP
- **Memoization = recursion + memo table**: top-down, check the table first, then compute
- **Bottom-up = filling a table**: start from base cases and work up to the big problem
- Fibonacci and climbing stairs are the "Hello World" of DP—both revolve around `dp[i] = dp[i-1] + dp[i-2]`
- Common pitfalls: missing base cases, wrong array size, confusion about 0-based vs 1-based indexing
