# Reconstructing a Binary Tree: From Preorder + Inorder

> Given a tree's traversal results, can you restore the original tree? Preorder + inorder works, inorder + postorder works, but preorder + postorder does not. This lesson explains why, and walks through implementing a "preorder + inorder" reconstruction by hand.

## One traversal sequence cannot uniquely reconstruct a tree

**A preorder sequence and an inorder sequence each carry different information.** The preorder tells you "who is the root," while the inorder tells you "where the root splits the left and right subtrees." Together they uniquely determine a tree.

```
Preorder: 1 2 4 5 3 6 7     ← the first element is the root, 1
Inorder:  4 2 5 1 6 3 7     ← everything left of 1 is the left subtree [4,2,5],
                              everything right is the right subtree [6,3,7]
```

**The first element of a preorder sequence is always the root.** Find that root's position in the inorder sequence: everything to its left belongs to the left subtree, everything to its right belongs to the right subtree — and now you know the size of the left subtree. Then回到 the preorder sequence: the segment immediately after the root is the preorder of the left subtree, and what follows is the preorder of the right subtree. Recurse to reconstruct.

## Walk through it by hand

**Take `pre = [3,9,20,15,7]` and `inorder = [9,3,15,20,7]` as an example:**

1. The first element of preorder, 3, is the root. In the inorder sequence, 3 is at index 1; to its left `[9]` (size 1) is the left subtree, to its right `[15,20,7]` (size 3) is the right subtree.
2. In preorder, the 1 element immediately after 3, namely `[9]`, is the preorder of the left subtree; after that, `[20,15,7]` is the preorder of the right subtree.
3. Recurse to reconstruct the left subtree (pre=[9], in=[9]) → node 9 is a leaf; the right subtree (pre=[20,15,7], in=[15,20,7]) → 20 is the root, left `[15]`, right `[7]`.

```
        3
       / \
      9   20
         /  \
        15   7
```

**The "divide-and-conquer boundary" of the recursion is: return None when pre is empty.**

## Implementation: a hash map to speed up the inorder lookup

**If you do a linear search for the root's position in the inorder sequence every time, the complexity is O(n²).** First build a hash map from "value → index"; then lookup is O(1) and the whole algorithm is O(n).

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build_tree(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    pre_iter = iter(preorder)

    def go(left, right):
        """The nodes of the current subtree occupy inorder[left, right)"""
        if left == right:
            return None
        val = next(pre_iter)              # the next element in preorder is the root
        mid = idx_map[val]               # its position in inorder
        node = TreeNode(val)
        node.left = go(left, mid)        # left subtree occupies inorder [left, mid)
        node.right = go(mid + 1, right)  # right subtree occupies inorder [mid+1, right)
        return node

    return go(0, len(inorder))

def preorder(node):
    if node is None:
        return []
    return [node.val] + preorder(node.left) + preorder(node.right)

r = build_tree([3, 9, 20, 15, 7], [9, 3, 15, 20, 7])
print(preorder(r))        # [3, 9, 20, 15, 7]

def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.val] + inorder(node.right)
print(inorder(r))         # [9, 3, 15, 20, 7]
```

**Using an iterator `pre_iter` instead of "maintaining a global index" makes the code cleaner.** `next(pre_iter)` pulls the next element from preorder as the root of the current subtree — it naturally walks in order because preorder is "root → left → right."

**The interval is "left-closed, right-open" `[left, right)`**, a common convention for recursive intervals that avoids index mistakes.

## WRONG WAY: using a closed interval for inorder and miscalculating the boundaries

```python
# WRONG: left-closed, right-closed interval, but forgetting to adjust the recursion arguments
def build_tree_wrong(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    pre_iter = iter(preorder)
    def go(l, r):
        if l > r:           # empty
            return None
        val = next(pre_iter)
        mid = idx_map[val]
        node = TreeNode(val)
        node.left = go(l, mid)        # ← should be go(l, mid-1)
        node.right = go(mid, r)       # ← should be go(mid+1, r)
        return node
    return go(0, len(inorder)-1)
```

**This repeatedly includes the node at position `mid`** (the root itself gets passed into the left subtree's recursion), causing nodes to be reused; eventually the tree structure is wrong or it loops infinitely.

**Either use left-closed right-open `[l, r)` with `go(l, mid)` and `go(mid+1, r)`, or use left-closed right-closed `[l, r]` with `go(l, mid-1)` and `go(mid+1, r)`. Do not mix the two conventions.**

## Inorder + postorder can also reconstruct

**The last element of a postorder sequence is the root.** The logic is perfectly symmetric: take the root from back to front, build the right subtree first, then the left (because postorder is "left → right → root," so backward it is "root → right → left").

```python
def build_tree_in_post(inorder, postorder):
    idx_map = {v: i for i, v in enumerate(inorder)}
    post_iter = reversed(postorder)    # take the root from back to front

    def go(left, right):
        if left == right:
            return None
        val = next(post_iter)
        mid = idx_map[val]
        node = TreeNode(val)
        node.right = go(mid + 1, right)   # note: right first, then left
        node.left = go(left, mid)
        return node

    return go(0, len(inorder))

r2 = build_tree_in_post([9, 3, 15, 20, 7], [9, 15, 7, 20, 3])
print(inorder(r2))   # [9, 3, 15, 20, 7]
print(preorder(r2))  # [3, 9, 20, 15, 7]
```

**Right before left, because `reversed(postorder)` reads backward as "root → right → left."** If you build the left subtree first, you will pull the wrong root.

## Why "preorder + postorder" cannot reconstruct a tree

**Preorder tells you "who is the root," and postorder also tells you "who is the root," but neither tells you "how long the left subtree is."** Only inorder can split the sequence into two parts at the root.

```
Preorder: 1 2 3 4
Postorder: 4 3 2 1

We know 1 is the root, but is 2 the first node of the left subtree or the first of the right subtree?
Two possibilities:
    1          or         1
   /                    \
  2                      2
 /                        \
3                          3
/                            \
4                            4
```

**Both trees have exactly the same preorder and postorder sequences, yet their structures differ.** So "preorder + postorder" cannot uniquely determine a binary tree (unless extra restrictions apply, such as a full binary tree).

## Complexity and preconditions of reconstruction

**Time O(n)**: each node is built once, and the inorder lookup is O(1) via the hash map.
**Space O(n)**: the hash map plus the recursion stack.

**Precondition: all node values in the tree are distinct.** If values are duplicated, `idx_map[val]` can store only one position, so you cannot tell which node is which — reconstruction fails. Interview problems usually guarantee "all values are unique."

## WRONG WAY: duplicate values cause idx_map to store the wrong position

```python
# WRONG: when values are not unique, idx_map keeps only the last occurrence
def build_tree_dup(preorder, inorder):
    idx_map = {v: i for i, v in enumerate(inorder)}   # duplicates get overwritten
    # suppose inorder = [1, 2, 1], idx_map[1] will only be 2
    ...

t = build_tree_dup([1, 1, 2], [1, 2, 1])
print(preorder(t))   # wrong result
```

**`{v: i for i, v in enumerate(inorder)}` overwrites earlier indices when v is duplicated.** So when locating the root in inorder you get the wrong position, and the reconstructed tree is structurally wrong.

**Conclusion: the reconstruction algorithm only works for trees with unique node values.** If duplicates are allowed, you need extra information (such as passing indices as parameters as well) — that goes beyond the basics.

## Summary

- Preorder + inorder can uniquely reconstruct a tree: preorder identifies the root, inorder splits left from right.
- Store inorder indices in a hash map to bring the complexity down from O(n²) to O(n).
- Recursive intervals are recommended to be left-closed right-open `[left, right)`: recurse with `go(l, mid)` and `go(mid+1, r)`.
- Inorder + postorder is symmetric: take the root from back to front, build the right subtree first, then the left.
- **Preorder + postorder cannot reconstruct a tree** (left subtree length is unknown); counterexamples exist.
- The reconstruction algorithm requires unique node values; duplicates cause `idx_map` to store the wrong position.
