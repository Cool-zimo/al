# Binary Search on Answer + Feasibility Check

> Some problems ask for "what's the optimal value," which is hard to compute directly. But if you're given a candidate value X and asked "can the answer be ≤ X," it's often easy to check. Binary search on the answer is the classic technique that turns "find the optimum" into "check feasibility."

## The Core Idea of Binary Search on Answer

**Binary search on answer applies to this type of problem:**

> You need to find the "maximum/minimum" optimal value, which is hard to compute directly. But given a candidate value X, it's easy to determine whether "the answer can be ≤ X (or ≥ X)."

**The approach:**

```
1. Determine the answer range [left, right]
2. Binary search within that range
3. At each step, take mid and write a check(mid) function
4. If check(mid) is true, the answer can be smaller/larger—narrow the range
5. If check(mid) is false, the answer must be larger/smaller—narrow the range
6. Eventually converge to the optimal solution
```

**Key: writing the check function. It must determine whether "answer ≤ mid is feasible."**

## Classic Example: Minimizing the Maximum

**Problem:** You have n books to distribute among k people. Each book has a page count pages[i]. The books assigned to each person must be contiguous. Find the minimum possible value of "the maximum number of pages assigned to any one person."

**Hard to compute directly, but easy to check:**

```python
def check(pages, k, limit):
    """Check: can we distribute all books among k people such that
    no person reads more than limit pages?"""
    people = 1
    cur = 0
    for p in pages:
        if cur + p <= limit:
            cur += p
        else:
            people += 1
            cur = p
            if people > k:
                return False
    return True
```

**Checking logic:** Greedily assign books from left to right. When the current person reaches the limit, move to the next person. If we can finish with at most k people, the limit is feasible.

**Then binary search:**

```python
def min_max_pages(pages, k):
    left = max(pages)          # Must read at least the largest single book
    right = sum(pages)         # One person reads everything
    
    while left < right:
        mid = (left + right) // 2
        if check(pages, k, mid):
            right = mid          # Feasible, try smaller
        else:
            left = mid + 1       # Not feasible, must be larger
    return left

print(min_max_pages([12, 34, 67, 90], 2))   # 113
```

**Time complexity: O(n log sum)—binary search log(sum) times, each check is O(n).**

## Monotonicity Is the Lifeblood of Binary Search on Answer

**The prerequisite for binary search on answer is that the check function is monotonic.**

> If answer ≤ X is feasible, then answer ≤ X+1 must also be feasible (for "minimization" problems).

**Intuition:** The looser the limit (larger limit), the easier it is to distribute. So from some critical point onward, check flips from False to True, and stays True after that.

```
limit:   50  60  70  80  90  100  110  120
check:   F   F   F   F   F    F    T    T
                              ↑ Critical point = answer
```

**Binary search is finding this F→T transition point.**

## Templates for Binary Search on Answer

**Minimization (find the smallest X that satisfies the condition):**

```python
left = lower_bound
right = upper_bound
while left < right:
    mid = (left + right) // 2
    if check(mid):
        right = mid          # mid is feasible, answer might be smaller
    else:
        left = mid + 1       # mid not feasible, answer must be larger
return left
```

**Maximization (find the largest X that satisfies the condition):**

```python
left = lower_bound
right = upper_bound
while left < right:
    mid = (left + right + 1) // 2    # Note the +1, prevents infinite loop
    if check(mid):
        left = mid          # mid is feasible, answer might be larger
    else:
        right = mid - 1     # mid not feasible, answer must be smaller
return left
```

**Note: for maximization, mid must use ceiling `(left+right+1)//2`, otherwise you may get an infinite loop.**

## More Classic Problems Using Binary Search on Answer

**These are all common applications of binary search on answer:**

1. **Capacity to ship packages within D days**: minimize ship capacity → check: can it be done in D days
2. **Split array largest sum**: minimize the maximum subarray sum → check: can it be split into m segments with sum ≤ limit
3. **Wood cutting**: maximize the length of equal pieces → check: how many pieces of a given length can be cut
4. **Find the k-th smallest pair distance**: minimize the k-th smallest distance → check: how many pairs have distance ≤ mid

**Common thread: asks "what's the minimum/maximum value," hard to compute directly, easy to check feasibility.**

## WRONG: Reversed Monotonicity in Check, Wrong Binary Search Direction

**This is the most frequent error in binary search on answer—the check function is correct, but the binary search direction is reversed.**

```python
# WRONG: minimization problem, but going larger when check returns true
def min_max_pages_wrong(pages, k):
    left = max(pages)
    right = sum(pages)
    while left < right:
        mid = (left + right) // 2
        if check(pages, k, mid):
            left = mid + 1       # WRONG! Should go smaller
        else:
            right = mid           # WRONG! Should go larger
    return left

# Returns wrong answer
```

**Why is it wrong?** When check(mid) is True, it means mid is feasible and the answer can be smaller—you should set `right = mid`, not `left = mid + 1`.

**Fix: when check is True, shrink the upper bound; when False, shrink the lower bound.**

```python
def min_max_pages_fixed(pages, k):
    left = max(pages)
    right = sum(pages)
    while left < right:
        mid = (left + right) // 2
        if check(pages, k, mid):
            right = mid
        else:
            left = mid + 1
    return left

print(min_max_pages_fixed([12, 34, 67, 90], 2))   # 113
```

## WRONG: Maximization Forgot to Take Ceiling of Mid, Infinite Loop

**For maximization, if mid uses floor division, you might get a case where left == right never holds.**

```python
# WRONG: maximization, mid uses floor, causing infinite loop
def maximize_wrong(check_func, left, right):
    while left < right:
        mid = (left + right) // 2     # WRONG! Should add 1
        if check_func(mid):
            left = mid                # left=mid, if right=mid+1 → infinite loop!
        else:
            right = mid - 1
    return left

# When left=3, right=4, mid=3:
# check(3) is True → left=3, right=4 → infinite loop!
```

**Fix: for maximization, take the ceiling of mid.**

```python
def maximize(check_func, left, right):
    while left < right:
        mid = (left + right + 1) // 2    # +1 prevents infinite loop
        if check_func(mid):
            left = mid
        else:
            right = mid - 1
    return left
```

**Reasoning: when the interval has only two elements [left, left+1], floor gives mid=left. If check is True, left stays the same → infinite loop. Ceiling gives mid=left+1, left updates, and the loop converges.**

## WRONG: Missing Boundary Conditions in the Check Function

**The check function's boundary conditions aren't handled correctly, causing wrong feasibility results.**

```python
# WRONG: check doesn't handle "a single book exceeds the limit"
def check_wrong(pages, k, limit):
    people = 1
    cur = 0
    for p in pages:
        if cur + p <= limit:
            cur += p
        else:
            people += 1
            cur = p          # If p > limit, cur=p still exceeds the limit!
            if people > k:
                return False
    return True

# pages=[100, 1, 1], k=2, limit=50
# First book 100 > 50, cur=100, but only counted as 1 person
# Actually impossible to distribute with 2 people (100 alone exceeds limit), but function returns True
```

**Fix: add a check for whether a single book exceeds the limit.**

```python
def check_fixed(pages, k, limit):
    if max(pages) > limit:       # Single book exceeds limit, impossible
        return False
    people = 1
    cur = 0
    for p in pages:
        if cur + p <= limit:
            cur += p
        else:
            people += 1
            cur = p
            if people > k:
                return False
    return True
```

**This also aligns with setting the binary search range: left should be max(pages) because a single book can't be split.**

## Summary

- **Binary search on answer**: turn "find the optimum" into "check feasibility," then binary search over the answer range
- **Core: the check function**—determines "is answer ≤ X feasible," must handle monotonicity and boundaries correctly
- **Minimization template**: check True → right=mid; check False → left=mid+1
- **Maximization template**: mid uses ceiling `(left+right+1)//2`; check True → left=mid
- **Monotonicity** is the prerequisite for binary search on answer: looser limits are always easier to satisfy
- Common pitfalls: reversed binary search direction, forgetting +1 in maximization (infinite loop), missing boundary checks in check
