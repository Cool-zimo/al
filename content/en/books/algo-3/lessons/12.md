# DFS and BFS: Two Traversal Frameworks and Their Differences

> There are only two ways to traverse a graph: Depth-First Search (DFS) and Breadth-First Search (BFS). DFS uses recursion (a stack) to plunge down one path; BFS uses a queue to expand level by level. This lesson drills both frameworks and explains when each is appropriate.

## DFS: Recursion + visited

**DFS (Depth-First Search) follows one path all the way to the end, then backtracks to try other paths.** It is implemented with recursion (which is essentially a call stack).

```python
def build_adj(n, edges):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    return adj

adj = build_adj(5, [[0,1],[0,2],[1,3],[1,4]])

def dfs(u, visited):
    visited.add(u)
    print(u, end=' ')
    for v in adj[u]:
        if v not in visited:
            dfs(v, visited)

dfs(0, set())   # 0 1 3 4 2  (one possible ordering)
```

**The "return" from recursion is backtracking.** When all neighbors in `adj[u]` have been visited, the function naturally returns to the previous level — that is "backtracking".

**The traversal order depends on the order of neighbors in the adjacency list, so it is not unique.** As long as every node is visited exactly once, the result is valid.

## BFS: Queue + visited

**BFS (Breadth-First Search) expands level by level: it visits all nodes at distance 1 from the start, then all nodes at distance 2, and so on.** It is implemented with a queue (level-order traversal from Lesson 03 is exactly BFS).

```python
from collections import deque

def bfs(start, adj):
    visited = {start}
    q = deque([start])
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:
            if v not in visited:
                visited.add(v)
                q.append(v)
    return order

print(bfs(0, adj))   # [0, 1, 2, 3, 4]
```

**The queue guarantees "first in, first out", so nodes on the same level appear consecutively.**

## # WRONG: Forgetting visited in DFS/BFS Causes an Infinite Loop on Cyclic Graphs

```python
# WRONG: No visited tracking
def dfs_no_visited(u):
    print(u, end=' ')
    for v in adj[u]:
        dfs_no_visited(v)

# adj = build_adj(5, [[0,1],[1,2],[2,0]])  # Triangle with a cycle
# dfs_no_visited(0)  ->  0 1 2 0 1 2 0 ... infinite recursion
```

**A tree has no cycles, so tree traversal does not need visited. A graph has cycles, so visited is required.**

**Mark `visited` "before enqueueing/recursing", not "after processing".** Otherwise, the same node can be discovered by multiple neighbors and enqueued multiple times.

```python
# Correct: mark as soon as discovered
visited = {start}
q = deque([start])
while q:
    u = q.popleft()
    for v in adj[u]:
        if v not in visited:
            visited.add(v)      # <- mark before enqueueing
            q.append(v)
```

**If you mark "after processing", a node can be enqueued multiple times by its neighbors.** The final result may still be correct, but performance degrades.

## The Essential Difference Between DFS and BFS

| Dimension | DFS | BFS |
|---|---|---|
| Data structure | Stack (recursion / explicit stack) | Queue |
| Exploration order | Goes deep down one path | Expands level by level |
| Space | O(h), where h is the maximum depth | O(w), where w is the maximum width |
| Finds shortest path? | Not necessarily on unweighted graphs | Guaranteed shortest on unweighted graphs |
| Best for | Connectivity, cycle detection, topological sort, backtracking | Shortest path, layering, diffusion problems |

**DFS space is proportional to path depth; BFS space is proportional to layer width.** On a tall, thin tree (a linked list), BFS uses very little space. On a wide, shallow tree (a star), DFS uses very little space.

## BFS for Shortest Path in Unweighted Graphs

**The first time BFS encounters the target node, the number of edges traversed is the shortest distance.** BFS explores nodes in increasing order of distance.

```python
def shortest_path(adj, start, target):
    if start == target:
        return 0
    visited = {start}
    q = deque([(start, 0)])      # (node, distance)
    while q:
        u, d = q.popleft()
        for v in adj[u]:
            if v == target:
                return d + 1
            if v not in visited:
                visited.add(v)
                q.append((v, d + 1))
    return -1     # unreachable

adj = build_adj(6, [[0,1],[0,2],[1,3],[2,3],[3,4],[4,5]])
print(shortest_path(adj, 0, 5))   # 3  (0->1->3->4->5 or 0->2->3->4->5)
print(shortest_path(adj, 0, 0))   # 0
```

**Store `(node, distance)` in the queue and return as soon as the target is reached.** Why is the first encounter the shortest? Because BFS processes all nodes at distance d before any node at distance d+1 — it never "reaches a far node first and then comes back".

## # WRONG: BFS Adds Distance to Nodes Instead of Edges

```python
# WRONG: Storing "level" but adding 1 at each step — fails with weighted edges
def shortest_path_wrong(adj, start, target):
    q = deque([start])
    dist = {start: 0}
    while q:
        u = q.popleft()
        for v in adj[u]:
            if v not in dist:
                dist[v] = dist[u] + 1     # <- assumes every edge has weight 1
                q.append(v)
    return dist.get(target, -1)
```

**This is correct for unweighted graphs, but the moment edges carry weight (e.g., road distances), BFS fails.** `+1` only works when "every edge has the same weight".

**For weighted shortest paths, use Dijkstra (Lesson 15), which uses a priority queue instead of an ordinary queue.**

## Iterative DFS: Explicit Stack

**Recursive DFS is limited by Python's recursion depth (default 1000). When there are many nodes, switch to an explicit stack.**

```python
def dfs_iter(start, adj):
    visited = set()
    stack = [start]
    order = []
    while stack:
        u = stack.pop()        # Stack: last in, first out
        if u in visited:
            continue
        visited.add(u)
        order.append(u)
        for v in adj[u]:
            if v not in visited:
                stack.append(v)
    return order

print(dfs_iter(0, adj))   # [0, 2, 1, 4, 3] (order differs slightly from recursion)
```

**`stack.pop()` removes the most recently added element, achieving "depth-first".** Note that you must check visited before processing, otherwise the same node can be pushed multiple times by its neighbors.

**The order of iterative DFS does not exactly match recursive DFS** (because recursive DFS always processes "the first neighbor in the list" first), but both correctly visit all nodes.

## Checking Connectivity

**Starting a DFS/BFS from any node, the set of reachable nodes is its connected component.** If all nodes are reachable, the graph is connected.

```python
def is_connected(adj):
    if not adj:
        return True
    visited = set()
    start = 0
    stack = [start]
    while stack:
        u = stack.pop()
        if u in visited:
            continue
        visited.add(u)
        for v in adj[u]:
            if v not in visited:
                stack.append(v)
    return len(visited) == len(adj)

print(is_connected(build_adj(4, [[0,1],[1,2],[2,3]])))   # True
print(is_connected(build_adj(4, [[0,1],[2,3]])))         # False
```

**`len(visited) == n` means every node is reachable from the start.** This is the standard way to test graph connectivity.

## Summary

- DFS uses a stack/recursion, going deep down one path; BFS uses a queue, expanding level by level
- **Graphs have cycles, so visited is mandatory**; mark it "before enqueueing/pushing"
- BFS finds the shortest path on unweighted graphs on the first encounter of the target, O(n+m)
- Recursive DFS is limited by recursion depth; for many nodes, use an explicit stack
- DFS space is O(h), BFS space is O(w); choose the traversal based on the graph shape
- To check connectivity: traverse from one node and see if all nodes were visited
