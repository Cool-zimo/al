# Practice: Depth, Node Count, and Balance of a Tree

> The first three lessons covered traversal; this lesson ties them together with three "quantities": maximum depth, total node count, and whether the tree is balanced. All three are "result from the subtrees + processing at the root," differing only in how they are combined.

## Three quantities, one skeleton

**A problem that asks for "some overall quantity of a tree" can almost always be written as: `f(root) = combine(f(left), root, f(right))`.** Their skeletons are identical:

| Problem | Termination condition | How to combine the left and right results |
|---|---|---|
| Node count | empty tree returns 0 | `1 + left + right` |
| Maximum depth | empty tree returns 0 | `1 + max(left, right)` |
| Maximum width | empty tree returns 0 | the maximum `size` across BFS layers |

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build(vals):
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]
```

## Maximum depth: bottom-up, you need the children's answers first

**Maximum depth = 1 + the larger of the left and right subtree depths.** Note that this is "bottom-up" — you must know the depths of the left and right subtrees before you can compute your own.

```python
def max_depth(root):
    if root is None:
        return 0
    left = max_depth(root.left)
    right = max_depth(root.right)
    return 1 + max(left, right)

print(max_depth(build([3, 9, 20, None, None, 15, 7])))   # 3
print(max_depth(build([1, 2, 3, 4, 5])))                 # 3
print(max_depth(None))                                    # 0
```

**The termination condition `None -> 0` sets the depth of an empty tree to 0.** This convention is consistent with the definition of "height": a leaf has height 0, and an empty tree has height -1. Note that "depth" and "height" are both 0 at a leaf, but for an empty tree depth is usually 0 while height is usually -1 — different textbooks disagree, so decide on a convention before you code.

## Node count: 1 + left + right

**Node count = 1 (the root) + nodes in the left subtree + nodes in the right subtree.** This is the simplest example of the "subtree result + root" pattern.

```python
def count_nodes(root):
    if root is None:
        return 0
    return 1 + count_nodes(root.left) + count_nodes(root.right)

print(count_nodes(build([1, 2, 3, None, None, 4, 5])))   # 5
print(count_nodes(None))                                   # 0
```

**This写法 gives the same number as the node count obtained from level-order traversal.** It shows that "traversal" and "counting" are two sides of the same coin: traversal extracts the nodes, while counting accumulates them.

## Balanced binary tree: height difference no more than 1

**A balanced binary tree is defined as: the height difference between the left and right subtrees is no more than 1, and both subtrees are themselves balanced.** Note that this must hold at **every** node, not just the root.

```python
def is_balanced(root):
    def height(n):
        if n is None:
            return 0
        return 1 + max(height(n.left), height(n.right))
    if root is None:
        return True
    left_h = height(root.left)
    right_h = height(root.right)
    return abs(left_h - right_h) <= 1 and is_balanced(root.left) and is_balanced(root.right)

t1 = build([3, 9, 20, None, None, 15, 7])
t2 = build([1, 2, 3, 4, 5, None, None])
print(is_balanced(t1))   # True
print(is_balanced(t2))   # False  (the right subtree has height 2, the left has height 0)
```

**This写法 is correct but not efficient: every node recomputes the height, making it O(n²) overall.** It is especially slow on skewed trees. Interviews usually demand O(n).

## WRONG WAY: is_balanced written as O(n²)

The写法 above, where "every node recomputes the height," suffers from the same heights being calculated over and over. Take a right-leaning chain `[1, None, 2, None, 3, None, 4]`:

```
height(1): still has to compute height(2), height(3), height(4)
height(2): still has to compute height(3), height(4)
height(3): still has to compute height(4)
```

**Four nodes to compute heights, but height(4) is computed 4 times, height(3) is computed 3 times...** The total number of calls is roughly n(n+1)/2 = O(n²). With n = 10000 that is fifty million calls — an outright timeout.

**The fix is to "bring back both height and balance information in a single traversal"** — that is the O(n)写法 in the next section.

## O(n) balance check: one traversal returns both height and a balance flag

**Core idea: let the recursive function return both "subtree height" and "whether the subtree is balanced."** Once an imbalance is found anywhere, the whole chain returns "not balanced."

```python
def is_balanced_fast(root):
    def go(n):
        if n is None:
            return 0, True          # height 0, and an empty tree is balanced
        lh, lb = go(n.left)
        if not lb:
            return -1, False        # left subtree already unbalanced, short-circuit
        rh, rb = go(n.right)
        if not rb:
            return -1, False
        if abs(lh - rh) > 1:
            return -1, False        # current node is unbalanced
        return 1 + max(lh, rh), True
    return go(root)[1]

t2 = build([1, 2, 3, 4, 5, None, None])
print(is_balanced_fast(t2))   # False
print(is_balanced_fast(build([3, 9, 20, None, None, 15, 7])))   # True
```

**Returning `-1` is a约定 "error code."** Once some node returns `-1`, every ancestor returns `-1` as well, short-circuiting the whole chain. Each node is visited exactly once: O(n).

**This pattern is called "postorder traversal + returning multiple pieces of information."** LCA, diameter, and path sum all use it — any problem where "you must know the children's status before you can decide your own" is a postorder problem.

## The diameter of a tree: postorder returns two pieces of information

**The diameter is "the distance (in edges) between the two farthest nodes in the tree."** It has two possibilities: it either passes through the root, equal to the sum of the left and right depths, or it lies entirely inside the left subtree or the right subtree. So at every node you must simultaneously update "the maximum distance passing through this node" and "my own depth."

```python
def diameter(root):
    ans = [0]                       # use a list so the closure can modify it
    def go(n):
        if n is None:
            return 0
        l = go(n.left)
        r = go(n.right)
        ans[0] = max(ans[0], l + r)   # the farthest path through the current node
        return 1 + max(l, r)          # return my own depth
    go(root)
    return ans[0]

print(diameter(build([1, 2, 3, 4, 5])))            # 3  (paths 4-2-1-3 or 4-2-1-5)
print(diameter(build([1, 2, None, 3, None, 4])))   # 3  (path 4-3-2-1)
print(diameter(None))                               # 0
```

**Here again we "return depth + update a global answer."** The key insight for the diameter is: the farthest path is **always** "left depth + right depth" at some node. So you visit every node, compute `l + r` once, and take the maximum.

## WRONG WAY: diameter only counts "the path through the root"

```python
# WRONG: only counting left depth + right depth, ignoring the path entirely inside one subtree
def diameter_wrong(root):
    if root is None:
        return 0
    left_d = max_depth(root.left)
    right_d = max_depth(root.right)
    return left_d + right_d

t = build([1, 2, None, 3, None, 4, None, 5])  # a left-leaning chain, diameter should be 3
print(diameter_wrong(t))   # 0  ← wrong! the left subtree is empty
```

**The output is 0, while the correct answer is 3.** Because the farthest path 5-4-3-2 lies entirely in the left subtree and never passes through the root at all.

**Lesson: for any "global optimum" problem, you must visit every node and consider "using it as the turning point"; you cannot look only at the root.**

## Invert a binary tree: swap left and right

**Inverting (flipping / mirroring) means "for every node, swap its left and right subtrees."** This is a great preorder/postorder exercise.

```python
def invert(root):
    if root is None:
        return None
    root.left, root.right = invert(root.right), invert(root.left)
    return root

def to_list(root):
    if root is None:
        return []
    from collections import deque
    ans, q = [], deque([root])
    while q:
        n = q.popleft()
        if n is None:
            ans.append(None)
        else:
            ans.append(n.val)
            q.append(n.left)
            q.append(n.right)
    while ans and ans[-1] is None:
        ans.pop()
    return ans

t = build([4, 2, 7, 1, 3, 6, 9])
invert(t)
print(to_list(t))   # [4, 7, 2, 9, 6, 3, 1]
```

**The swap can happen after the recursion (postorder) or before it (preorder), as long as both sides are processed.** Preorder写法: `root.left, root.right = invert(root.right), invert(root.left)` — swap first, then recurse; the effect is the same.

## Summary

- Computing a quantity of a tree = `combine(left result, root, right result)`: node count is `1+left+right`, depth is `1+max(left,right)`.
- **A balanced tree requires every node's left and right height difference to be ≤ 1**, not just the root.
- The naive balance check is O(n²); the O(n)写法 is "one traversal returning both height and a balance flag," using `-1` to short-circuit.
- **For diameter you must consider "passing through every node"**, not just the root; the pattern is return depth + update the global maximum.
- Inverting a binary tree means swapping every node's left and right subtrees; either preorder or postorder works.
