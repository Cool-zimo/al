# Binary Trees and Traversal: Preorder / Inorder / Postorder

> Traversal means visiting every node in a tree exactly once. A binary tree only has three positions — left, root, right — and changing the order in which you visit them gives you the three classic traversals: preorder, inorder, and postorder. They are not just exam questions; they are the skeleton for every tree problem that follows.

## Why traversal matters

**Visiting "each node exactly once" is the starting point of every tree algorithm.** Counting nodes, finding the maximum depth, summing path values, serializing, copying an entire tree — all of them first require walking through the tree. So "how to walk" is the foundation for the next twenty-plus lessons.

A tree has no indices, so you must "follow the pointers." There are three pointers: `.left`, `.right`, and "go back to the parent." But `TreeNode` has no `parent` pointer, so you can only **go downward** and rely on the return of the recursive call to complete the "upward" movement.

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build(vals):
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]
```

**The universal framework for traversal is one sentence: decide when the "root" gets visited, then recursively process the left and right children.** The only difference among the three is where the "root" is inserted.

## Preorder traversal: root → left → right

**In preorder, visit the root first, then the left subtree, then the right subtree.** "Pre" means "the root comes before." Its most intuitive use is "copying or serializing a tree" — because you always handle the current node first, then go down to its children.

```python
def preorder(root):
    if root is None:
        return []
    return [root.val] + preorder(root.left) + preorder(root.right)

t = build([1, 2, 3, 4, 5, 6, 7])
print(preorder(t))   # [1, 2, 4, 5, 3, 6, 7]
```

Walk through it: `1` is output first, then we recurse into the left subtree `2`; `2` is output first, then into its left subtree `4`; `4` is output, both children are empty, so we return to `2` and enter the right subtree `5`...

**Can a preorder sequence uniquely determine a tree's structure?** No. From the preorder sequence alone, you do not know where branching happens or where the leaves are. To reconstruct a tree you need at least two sequences — usually "preorder + inorder" (covered in lesson 09).

## Inorder traversal: left → root → right

**In inorder, visit the left subtree first, then the root, then the right subtree.** "In" means "the root is in the middle." Its biggest feature: **for a binary search tree, inorder traversal yields a strictly increasing sequence.**

```python
def inorder(root):
    if root is None:
        return []
    return inorder(root.left) + [root.val] + inorder(root.right)

print(inorder(t))   # [4, 2, 5, 1, 6, 3, 7]
```

**This is the most common way to verify whether a BST is valid.** The inorder sequence of a legal BST must be non-decreasing. Note, however, that simply collecting the inorder result and checking it again costs O(n) space. If you need O(h) space (where h is the tree height), you must use Morris traversal to "find inversions in an inorder traversal" — that is advanced material.

## Postorder traversal: left → right → root

**In postorder, visit the left subtree first, then the right subtree, then the root.** "Post" means "the root comes after." Its most typical use is "compute the children's information first, then use it to compute the root" — for example, finding a tree's height, or computing each subtree's state before deciding the current node's color.

```python
def postorder(root):
    if root is None:
        return []
    return postorder(root.left) + postorder(root.right) + [root.val]

print(postorder(t))   # [4, 5, 2, 6, 7, 3, 1]
```

**The position "the root at the very end" is crucial.** If a problem asks you to "finish processing the left and right subtrees before processing the root" (for example: deleting the node whose value is x, or computing subtree information rooted at each node), it is almost certainly a postorder traversal.

## Comparing the three traversals

| Traversal | Position of root | Typical use |
|---|---|---|
| Preorder | Root before the left subtree | Copy a tree, serialize, process parent before child |
| Inorder | Root between left and right | Read values from a BST (increasing), infix of expression trees |
| Postorder | Root after the right subtree | Aggregate children before computing the root, free resources, find height |

```python
t = build([1, 2, 3, 4, 5, 6, 7])
print("pre :", preorder(t))
print("in  :", inorder(t))
print("post:", postorder(t))
```

Output:

```
pre : [1, 2, 4, 5, 3, 6, 7]
in  : [4, 2, 5, 1, 6, 3, 7]
post: [4, 5, 2, 6, 7, 3, 1]
```

**The three traversals share the same "set" of nodes; only the order differs.** If you sort each of the three results, you get exactly the same list. You can use this property while debugging to check whether your traversal implementation missed any nodes.

## WRONG WAY: None plus a list — TypeError warning

```python
# WRONG: the recursive branch returns +, but the empty branch returns None
def preorder(root):
    if root is None:
        return None          # ← returns None instead of []
    return [root.val] + preorder(root.left) + preorder(root.right)

print(preorder(build([1, 2, 3])))
```

Error:

```
TypeError: can only concatenate list (not "NoneType") to list
```

**`[root.val] + preorder(left)` requires that `preorder(left)` is a list.** You made the empty branch return `None`, so `[root.val] + None` is a type error.

**Uniform convention: a traversal function always returns a list, and the empty branch returns `[]`.** Likewise, `to_list`, collecting paths, collecting leaves — every "collecting" recursion returns a list for the empty branch and lists for the non-empty branches. This one convention prevents about 90% of tree-recursion type errors.

## WRONG WAY: Forgetting the None check, touching None.val

```python
# WRONG: reading .val without first checking whether root is None
def inorder(root):
    return inorder(root.left) + [root.val] + inorder(root.right)

print(inorder(build([1, 2, 3])))
```

Error:

```
AttributeError: 'NoneType' object has no attribute 'val'
```

**The first line of a recursive function must be the boundary check.** Build this muscle memory when writing tree recursion: `def f(node): if node is None: return ...`. Any tree recursion that does not check None first will blow up one level below the leaf nodes.

## A unified template for recursive traversal

Put the three traversals side by side and only one line differs:

```python
def traverse(root, order):
    """order: 'pre' / 'in' / 'post'"""
    if root is None:
        return []
    left = traverse(root.left, order)
    right = traverse(root.right, order)
    if order == 'pre':
        return [root.val] + left + right
    if order == 'in':
        return left + [root.val] + right
    return left + right + [root.val]

print(traverse(build([1,2,3,4,5]), 'pre'))   # [1, 2, 4, 5, 3]
print(traverse(build([1,2,3,4,5]), 'in'))    # [4, 2, 5, 1, 3]
print(traverse(build([1,2,3,4,5]), 'post'))  # [4, 5, 2, 3, 1]
```

**This is what "divide and conquer" looks like on a tree: let the left and right subtrees compute their answers first, then decide how to combine them with the root.** The difference is only *when* the root gets added — before, in the middle, or after the拼接. Lesson 06 turns this idea into a "universal method for solving tree recursion problems."

## The iterative version: simulating recursion with a stack (just for awareness)

Recursion is essentially a call stack. You can maintain a stack yourself and push "what to do next" onto it.

```python
def preorder_iter(root):
    if root is None:
        return []
    ans, stack = [], [root]
    while stack:
        n = stack.pop()
        ans.append(n.val)
        if n.right:
            stack.append(n.right)   # right is visited later, so push it first
        if n.left:
            stack.append(n.left)    # left is visited first, so push it last
    return ans

print(preorder_iter(build([1, 2, 3, 4, 5])))   # [1, 2, 4, 5, 3]
```

**A stack is "last in, first out," so to get the left child out first, you must push the right child first.** This detail is the easiest part of the iterative version to get wrong. The iterative forms of inorder and postorder are more complex (they require a "visited flag" or Morris traversal). Recursive code is the mainstream in interviews, so mastering recursion is enough.

## Summary

- The core difference among the three traversals is "when the root gets visited": preorder (root first), inorder (root in the middle), postorder (root last).
- Preorder is for "parent before child" (copy, serialize); inorder yields an increasing sequence for a BST; postorder is for "children before parent" (find height, aggregate subtrees).
- **Traversal functions uniformly return lists, and the empty branch returns `[]`**; otherwise `+` raises TypeError.
- **The first line of every recursive tree function must check None**; otherwise `AttributeError` strikes one level below the leaf.
- The outputs of the three traversals are the same set of nodes in different orders; sorting them gives the same result.
- The iterative version uses a stack; remember the detail "push the right child first."
