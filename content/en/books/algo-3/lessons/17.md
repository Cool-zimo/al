# The Three Basic Sorts: Bubble, Selection, and Insertion

> They are all O(n²) and look clumsy, but insertion sort can outperform many "fancy" algorithms when the data is nearly sorted. This lesson thoroughly dissects the essential differences among the three O(n²) sorts.

## Bubble Sort: Repeatedly Bubbling the Largest to the End

**The core idea of bubble sort: each pass compares adjacent elements from start to finish, "bubbling" the maximum value of the unsorted portion to the end.**

```python
def bubble_sort(a):
    n = len(a)
    for i in range(n):            # i passes
        for j in range(n - 1 - i):  # Already-bubbled tail needs no comparison
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
    return a

print(bubble_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**After each pass, the last i elements are already sorted.** Pass 1 places the maximum at a[n-1], pass 2 places the second-largest at a[n-2], and so on.

**The comparison count is fixed at n(n-1)/2, regardless of whether the input is sorted.** This is bubble sort's biggest waste — even when the data is already sorted, it still foolishly completes every pass.

## Selection Sort: Picking the Smallest Each Pass

**The core idea of selection sort: each pass finds the minimum value in the unsorted portion and places it at the end of the sorted portion.**

```python
def selection_sort(a):
    n = len(a)
    for i in range(n):
        min_idx = i
        for j in range(i + 1, n):    # Find the index of the minimum
            if a[j] < a[min_idx]:
                min_idx = j
        a[i], a[min_idx] = a[min_idx], a[i]  # Swap into position i
    return a

print(selection_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**Selection sort swaps at most n−1 times, far fewer than bubble sort.** Bubble sort may swap on every single comparison (up to n² swaps in the worst case), while selection sort swaps only once per pass.

**But selection sort can never "finish early".** No matter how sorted the data is, it must scan the entire unsorted portion to determine the minimum.

## Insertion Sort: Inserting Each Element Into Its Correct Position

**The core idea of insertion sort: maintain a sorted prefix and "insert" the next element into its correct position within that prefix.**

```python
def insertion_sort(a):
    n = len(a)
    for i in range(1, n):
        key = a[i]          # The element to insert
        j = i - 1
        while j >= 0 and a[j] > key:   # Shift elements larger than key to the right
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key      # Insert into the correct position
    return a

print(insertion_sort([5, 2, 9, 1, 5, 6]))
# [1, 2, 5, 5, 6, 9]
```

**Insertion sort's inner loop "shifts elements", not "swaps".** It first moves a[j] one slot to the right to free up space, then inserts key in one final step. This saves one assignment compared to bubble sort's "swap two elements each time".

## # WRONG: Writing Insertion Sort as Bubble Sort

**Many beginners write what they call "insertion sort", but they are really writing bubble sort — using swaps instead of shifting, which is fundamentally different.**

```python
# WRONG: This is not insertion sort, it is bubble sort!
def insertion_sort_fake(a):
    n = len(a)
    for i in range(1, n):
        for j in range(i, 0, -1):
            if a[j] < a[j - 1]:
                a[j], a[j - 1] = a[j - 1], a[j]  # Swap!
            else:
                break
    return a
```

**This code produces correct results, but it is a variant of bubble sort, not insertion sort.** True insertion sort "takes the element out first, shifts the larger elements back, then inserts once". The swap version needs 3 assignments each time, while the shift version needs only 1 (the final insertion), a noticeable difference for large elements.

**Rule of thumb: inside the inner loop of insertion sort there should be a `key` variable holding the element to insert, and it should be assigned exactly once.**

## Why Insertion Sort Is Fast on Nearly Sorted Data

**When the data is nearly sorted, insertion sort's inner loop barely runs — each element compares with the previous one once and then "breaks".**

```python
# Nearly sorted data
a = [1, 2, 3, 4, 5, 0, 6, 7, 8, 9]
# Only 0 needs to move; every other element compares once and stops
```

**Insertion sort's best case (already sorted) takes only O(n) — each element compares once and moves zero times.** Bubble and selection cannot do this.

**This is why Python's Timsort and Java's Arrays.sort() both use insertion sort internally for small-scale or nearly sorted subarrays.** Insertion sort's small constant factor and O(n) best case make it excellent on real-world data.

## # WRONG: Believing sorted() Uses Quick Sort

**Python's `sorted()` and `list.sort()` use Timsort, not quick sort or heap sort.**

```python
# Misconception: thinking sorted() uses quick sort
a = [3, 1, 4, 1, 5, 9, 2, 6]

# Timsort is a hybrid sort:
# - Exploits already-sorted runs in the data
# - Uses binary insertion sort for short runs
# - Merges runs with merge sort
# Worst O(n log n), best O(n), stable

sorted(a)  # [1, 1, 2, 3, 4, 5, 6, 9]
```

**Timsort's worst-case complexity is O(n log n), while quick sort's worst case is O(n²).** If you say "Python uses quick sort" in an interview, you will lose points. Timsort was designed by Tim Peters for Python in 2002 and was later adopted by Java, Android, Swift, and others.

**Memory aid: Python = Timsort; C++ `std::sort` = Introsort (a hybrid of quick, heap, and insertion); Java uses Timsort for objects and dual-pivot quick sort for primitives.**

## Comparing the Three Sorts

| | Best | Average | Worst | Extra space | Stable |
|---|---|---|---|---|---|
| Bubble | O(n) (optimized) | O(n²) | O(n²) | O(1) | Yes |
| Selection | O(n²) | O(n²) | O(n²) | O(1) | **No** |
| Insertion | O(n) | O(n²) | O(n²) | O(1) | Yes |

**Selection sort is not stable!** For example, `[5, 5, 2]`: the first pass swaps the first 5 with 2, yielding `[2, 5, 5]`, changing the relative order of the two 5s.

**Bubble sort can guarantee stability by "never swapping equal elements".** Insertion sort is stable by nature.

**Practical advice: for n ≤ 16, insertion sort is usually fastest; for large-scale data, use an O(n log n) algorithm (starting with the next lesson).**

## Summary

- Bubble: adjacent swaps, bubbling the largest to the end; with optimization can finish early (O(n) best case)
- Selection: picks the minimum each pass and puts it at the front; few swaps but always O(n²), and unstable
- Insertion: maintains a sorted prefix and inserts new elements in the right place; screams at O(n) on nearly sorted data
- **Insertion sort is the only one of the three still widely used in real scenarios** (as a fallback in hybrid sorts)
- Python's `sorted()` uses Timsort, not quick sort
- All three are O(n²), but their constant factors differ: insertion < selection < bubble (generally)
