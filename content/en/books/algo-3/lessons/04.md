# Binary Search Trees (BST): Smaller on the Left, Larger on the Right — Search in O(h)

> A BST is how "order" truly enters a tree structure. It stipulates that every node in the left subtree is smaller than the root, and every node in the right subtree is larger. This simple rule lets search, insertion, and deletion all walk one path to the bottom — and as long as the tree is not too skewed, that is O(log n).

## The BST definition: smaller on the left, larger on the right

**A binary search tree is a binary tree satisfying: for any node, all values in its left subtree are smaller than it, and all values in its right subtree are larger.** More precisely it is "left subtree ≤ root < right subtree" or "left < root ≤ right," depending on the implementation (whether duplicates are allowed). Here we use "left < root, right > root, duplicates not allowed."

```
        8
      /   \
     3     10
    / \      \
   1   6      14
      / \    /
     4   7  13
```

**Inorder traversal of a BST always yields an increasing sequence.** This is the most important property of a BST, and the most intuitive way to verify whether a tree is a BST.

```python
def inorder(root, ans):
    if root is None:
        return
    inorder(root.left, ans)
    ans.append(root.val)
    inorder(root.right, ans)

def is_sorted(lst):
    return all(lst[i] < lst[i+1] for i in range(len(lst)-1))

root = build([8, 3, 10, 1, 6, None, 14, None, None, 4, 7, None, None, 13])
ans = []
inorder(root, ans)
print(ans)                 # [1, 3, 4, 6, 7, 8, 10, 13, 14]
print(is_sorted(ans))      # True
```

**Note: build uses a level-order list, and the tree structure it constructs is consistent with the diagram only if you verify it manually.** The level-order sequence in the example strictly matches the figure above.

## Search: halving the search space every time

**The idea behind BST search is "compare, then go one direction."** If the current node is what you are looking for, return it; if the target is smaller, go left; if larger, go right.

```python
def search(root, key):
    if root is None:
        return None            # not found
    if root.val == key:
        return root
    if key < root.val:
        return search(root.left, key)
    return search(root.right, key)

t = build([8, 3, 10, 1, 6, None, 14, None, None, 4, 7, None, None, 13])
print(search(t, 6).val if search(t, 6) else None)   # 6
print(search(t, 9))                                  # None
```

**One search walks at most one path from the root to a leaf, whose length equals the tree's height h.** So search is O(h). A balanced BST (like AVL or red-black) has h = O(log n), making search O(log n). If the tree skews into a linked list, h = n and search degenerates to O(n).

**This is exactly the "Achilles' heel" of a BST: performance depends entirely on balance.** Insertion order affects the shape — inserting 1,2,3,4,5 in that order produces a single right-leaning chain. The balanced trees you will study later (AVL, red-black) exist precisely to cure this; Python's standard library has no built-in balanced BST.

## Insertion: find the spot, then hang the node there

**Insertion does not move elements; it only finds "which leaf to hang from."** The logic is almost identical to search, except that when you hit an empty slot you create a new node.

```python
def insert(root, key):
    if root is None:
        return TreeNode(key)
    if key < root.val:
        root.left = insert(root.left, key)
    elif key > root.val:
        root.right = insert(root.right, key)
    # key == root.val: here we choose to ignore duplicates
    return root

def inorder_vals(root):
    ans = []
    def go(n):
        if n is None: return
        go(n.left); ans.append(n.val); go(n.right)
    go(root)
    return ans

t = None
for x in [5, 3, 7, 1, 4, 6, 8]:
    t = insert(t, x)
print(inorder_vals(t))   # [1, 3, 4, 5, 6, 7, 8]
```

**`insert` returns the new node and lets the parent catch it: `root.left = insert(root.left, key)`.** This is the standard写法 of recursive insertion — create the new node at the empty slot, return it to the parent, and the parent points its own left/right back at it.

**Why must you write `root.left = insert(...)`?** Because reassigning a parameter in Python does not affect the caller. You must "hang the new node back" through the return value; otherwise the new node is created but never referenced, which is the same as not inserting it at all.

## WRONG WAY: Forgetting to hang the return value back during insertion

```python
# WRONG: insert creates the new node, but the parent never catches it
def insert(root, key):
    if root is None:
        return TreeNode(key)
    if key < root.val:
        insert(root.left, key)      # ← the return value is discarded
    else:
        insert(root.right, key)
    return root

t = None
for x in [5, 3, 7]:
    t = insert(t, x)
print(inorder_vals(t))   # [5]  ← 3 and 7 are both lost!
```

**The output is only `[5]`.** The nodes 3 and 7 were indeed created as `TreeNode`s, but nothing referenced them — the parent's `left/right` remained `None`, and those new nodes were garbage collected.

**Fix: on the left, write `root.left = insert(root.left, key)`; on the right, write `root.right = insert(root.right, key)`.** Likewise, deletion often needs to "hang the subtree's return value back to the parent."

## WRONG WAY: Checking a BST by only comparing adjacent parent and child

```python
# WRONG: only checking "parent > left child && parent < right child"
def is_bst_wrong(root):
    if root is None:
        return True
    if root.left and not root.left.val < root.val:
        return False
    if root.right and not root.right.val > root.val:
        return False
    return is_bst_wrong(root.left) and is_bst_wrong(root.right)

# Build a tree where "every adjacent pair is legal but the whole is not a BST":
#       5
#      / \
#     3   8
#        /
#       2          <- 8's left child is 2, which is legal; but 2 < 5, violating the BST rule
bad = TreeNode(5, TreeNode(3), TreeNode(8, TreeNode(2)))
print(is_bst_wrong(bad))   # True  ← wrong!
```

**The output is `True`, but it is clearly not a BST** (because 2 is in 5's right subtree yet is smaller than 5).

**Root cause: the BST constraint is "everything in the left subtree < root," not "left child < root."** Checking only the parent-child relation misses cases where a grandchild violates the constraint.

**The correct approach: give each node a valid interval `(lo, hi)`.** The root has no restriction; going left tightens the upper bound to `root.val`; going right tightens the lower bound to `root.val`.

```python
def is_bst(root, lo=float('-inf'), hi=float('inf')):
    if root is None:
        return True
    if not (lo < root.val < hi):
        return False
    return is_bst(root.left, lo, root.val) and is_bst(root.right, root.val, hi)

print(is_bst(bad))    # False  ✓
```

**Pushing the interval downward is the universal trick for BST problems**: verification, finding the lowest common ancestor, and counting nodes in a range all use it.

## Deletion: three cases

**Deletion is the trickiest operation in a BST, and it comes in three cases:**

1. **Leaf node**: delete it directly (set the parent's pointer to None).
2. **Only one child**: let the parent bypass it and point directly at that child.
3. **Two children**: find the minimum node in the right subtree (or the maximum node in the left subtree), replace the current node with it, then delete that surrogate.

```python
def find_min(n):
    while n.left:
        n = n.left
    return n.val

def delete(root, key):
    if root is None:
        return None
    if key < root.val:
        root.left = delete(root.left, key)
    elif key > root.val:
        root.right = delete(root.right, key)
    else:   # found the node to delete
        if root.left is None:
            return root.right          # cases 1/2: left is empty
        if root.right is None:
            return root.left           # case 2: right is empty
        # case 3: neither side is empty, replace with the minimum of the right subtree
        root.val = find_min(root.right)
        root.right = delete(root.right, root.val)
    return root
```

**Why "replace with the minimum of the right subtree"?** Because the minimum of the right subtree is guaranteed to be larger than every node in the left subtree and smaller than the rest of the right subtree, so the BST property is preserved after replacement. That minimum node has at most one right child, so deleting it degenerates back to case 1 or 2.

**Deletion is not commonly required in interviews, but understanding "the replacement in case 3" is essential** — it demonstrates how the BST's ordering is exploited.

## A BST application: finding the kth smallest element

**Since a BST's inorder is increasing, the "kth smallest" is simply the kth element of the inorder sequence.** To save space, you can count inside the inorder recursion and stop once you find it.

```python
def kth_smallest(root, k):
    ans = [None]
    def go(n):
        if not n or ans[0] is not None:
            return
        go(n.left)
        k[0] -= 1
        if k[0] == 0:
            ans[0] = n.val
        go(n.right)
    k = [k]
    go(root)
    return ans[0]

t = build([5, 3, 7, 2, 4, 6, 8])
print(kth_smallest(t, 3))   # 4
```

**This写法 is "inorder + counting," stopping early once the kth element is found.** A more general approach uses a BST "augmented with subtree sizes" (common in balanced trees like AVL) to find any kth smallest in O(log n). This is LeetCode 230 and appears very frequently in interviews.

## Summary

- BST property: **everything in the left subtree < root < everything in the right subtree**; inorder traversal is always increasing.
- Search, insertion, and deletion all walk one path; complexity is O(h); when balanced, h = O(log n).
- Insertion must `root.left = insert(root.left, key)` to hang the return value back, otherwise the new node is lost.
- **You cannot判断 a BST by checking only the parent-child relation**; push an interval `(lo, hi)` downward, or verify with an increasing inorder sequence.
- Deletion has three cases: delete a leaf directly, bypass a single child, replace a node with two children using the minimum of the right subtree.
- Inorder + counting finds the kth smallest element in O(k).
