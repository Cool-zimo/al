# The Universal Recipe for Tree Recursion: Split the Problem into "Left Subtree + Root + Right Subtree"

> Tree problems look like they come in endless varieties, but their solutions all look the same: first ask "what do my left and right subtrees each give me," then ask "how do I combine their answers." This lesson turns that thinking into a template.

## In one sentence: every tree recursion is "left + right + root"

**At its core, solving a tree problem recursively means breaking it into three pieces: the result from the left subtree, the result from the right subtree, and the root node's own contribution.** In lesson 26 we covered the three elements of recursion (termination condition, recurrence relation, return value); on a tree they become:

1. **Termination condition**: what does the function return when the node is `None`? (Almost always 0, an empty list, True, etc.)
2. **Recurrence relation**: recursively process the left and right subtrees first, capturing their answers.
3. **Return value**: combine the left and right answers with the root's contribution, and return the result upward.

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def build(vals):
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left, right = 2 * i + 1, 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]
```

**This "left + right + root" template was already used for node count, depth, and diameter in the previous lesson.** The only difference is "how they are combined."

## Template 1: returning a single number

**When the problem asks for "one number for the whole tree" (node count, depth, path sum), return a number.** Combine with arithmetic.

```python
def tree_sum(root):
    """Return the sum of all node values in the tree."""
    if root is None:
        return 0
    return root.val + tree_sum(root.left) + tree_sum(root.right)

def max_depth(root):
    """Return the maximum depth of the tree."""
    if root is None:
        return 0
    return 1 + max(max_depth(root.left), max_depth(root.right))

print(tree_sum(build([1, 2, 3, 4, 5])))   # 15
print(max_depth(build([1, 2, 3, 4, 5])))   # 3
```

**These two code blocks have exactly the same structure; only the "combination line" differs.** Memorize this pattern: termination condition → recurse left and right → combine and return.

## Template 2: returning multiple values

**When a node needs to pass "multiple pieces of information" upward at once (such as "is it balanced" and "what is its height"), pack them into a tuple.** This is the idea behind `is_balanced_fast` from the previous lesson, and it is a high-frequency trick in tree problems.

```python
def balanced_and_height(root):
    if root is None:
        return True, 0             # empty tree: balanced, height 0
    lb, lh = balanced_and_height(root.left)
    if not lb:
        return False, -1           # left subtree already unbalanced, short-circuit
    rb, rh = balanced_and_height(root.right)
    if not rb or abs(lh - rh) > 1:
        return False, -1
    return True, 1 + max(lh, rh)
```

**Returning a tuple makes "getting multiple pieces of information in one traversal" possible.** Every problem that requires "both a check and a computation" (balance, BST validity, diameter, path sum) uses this trick.

## Template 3: returning a list (collecting paths / nodes)

**When the problem asks you to "collect all paths / nodes that satisfy a condition," the return value is a list.** Combine with `+`.

```python
def collect_leaves(root):
    """Collect the values of all leaf nodes."""
    if root is None:
        return []
    if root.left is None and root.right is None:
        return [root.val]                    # leaf: return a list containing itself
    return collect_leaves(root.left) + collect_leaves(root.right)

print(collect_leaves(build([1, 2, 3, 4, 5, 6, 7])))   # [4, 5, 6, 7]
```

**A leaf node returns `[root.val]`; an internal node returns the left and right lists added together.** This is the standard写法 of "collecting" recursion.

## WRONG WAY: confusing None with 0, treating an empty node as "value 0"

```python
# WRONG: treating an empty node as "the value exists but is 0," then combining with +
def tree_sum_wrong(root):
    # forgot to check None and went straight to root.val
    return root.val + tree_sum_wrong(root.left) + tree_sum_wrong(root.right)

print(tree_sum_wrong(build([1, 2, 3])))
```

Error:

```
AttributeError: 'NoneType' object has no attribute 'val'
```

**The first line of every tree recursion function must be `if root is None: return ...`.** What you return depends on the problem: 0 for sums, 0 for counts, `[]` for paths, True/False for checks. This "base value" must match your combination operation (0 goes with `+`, `[]` goes with `+`, True/False goes with `and`).

## WRONG WAY: returning a number when you should return a boolean

```python
# WRONG: the recursive function sometimes returns True/False and sometimes returns a number;
#        the layer above connects the results with `and`, causing an error
def has_path_sum(root, target):
    if root is None:
        return 0                 # ← empty node returns 0, but the layer above uses `and`
    if root.left is None and root.right is None:
        return root.val == target
    return has_path_sum(root.left, target - root.val) or \
           has_path_sum(root.right, target - root.val)

# When a path hits an empty node midway, 0 participates in the `or` check:
# 0 is "falsy" in Python and contaminates the logic
```

**The return type must be consistent.** Either always return a bool or always return a number. Use `or`/`and` to connect booleans, `+` to connect numbers, and `+` to connect lists. Mixing them causes errors on certain paths, and the error messages tend to be confusing.

## How to think: work backward from "what does the problem ask for"

**When you get a tree problem, answer three questions first:**

1. **What should I return?** A number, a boolean, a list, or a tuple?
2. **What base value should the empty node return?** 0 for sums, 0 for counts, `[]` for paths, True/False for checks.
3. **How do I compute my answer from the left and right results plus the root?**

```python
# Example: checking whether a tree is symmetric
def is_symmetric(root):
    def check(a, b):
        if a is None and b is None:
            return True
        if a is None or b is None:
            return False
        if a.val != b.val:
            return False
        return check(a.left, b.right) and check(a.right, b.left)
    if root is None:
        return True
    return check(root.left, root.right)

print(is_symmetric(build([1, 2, 2, 3, 4, 4, 3])))     # True
print(is_symmetric(build([1, 2, 2, None, 3, None, 3])))  # False
```

**A symmetry check is "left child of the left subtree vs. right child of the right subtree" — and that is exactly "the root's contribution."** Here the return type of `check` is bool, and the combination uses `and`.

## Checking for a mirror vs. checking for symmetry

**"Are two trees identical" and "is one tree symmetric" follow the same pattern; only the comparison differs.**

```python
def is_same_tree(a, b):
    if a is None and b is None:
        return True
    if a is None or b is None:
        return False
    if a.val != b.val:
        return False
    return is_same_tree(a.left, b.left) and is_same_tree(a.right, b.right)

t1 = build([1, 2, 3])
t2 = build([1, 2, 3])
t3 = build([1, 2, None, None, 3])
print(is_same_tree(t1, t2))   # True
print(is_same_tree(t1, t3))   # False
```

**`is_same_tree` is "left compared with left, right compared with right"; `is_symmetric` is "left compared with right, right compared with left."** The only difference is the order of the two recursive arguments in `check`.

## Summary

- The universal recipe for tree recursion: **termination condition (return a base value) → recurse left and right → combine and return**.
- Three return types: a single number (`+`/`max`), a boolean (`and`/`or`), and a list (`+`).
- **The return type must be consistent**; you cannot return a number at one moment and a boolean the next.
- When you need multiple pieces of information, pack them in a tuple (such as `(balanced, height)`), and use `-1` to short-circuit on imbalance.
- The three questions to answer: what to return? what does an empty node return? how do left + root + right combine?
- `is_same_tree` is "left vs. left, right vs. right"; `is_symmetric` is "left vs. right, right vs. left."
