# What Is a Tree: Why Trees Exist at All

> Arrays need O(n) to find an element; a sorted array gets lookup down to O(log n) but insertion costs O(n). A linked list inserts in O(1) yet still searches in O(n). A tree is the compromise in between: it bakes the "order" into the shape itself, so lookup, insertion, and deletion all run close to O(log n).

## The problem with arrays and linked lists is really the same problem

Let's revisit what you already know. In *Algo 1* you learned that arrays give O(1) random access but moving elements to insert in the middle is expensive. In *Algo 2* you saw that a linked list inserts in O(1) but first you have to walk the list to find the right spot.

Think about a concrete scenario: you maintain an ordered set of integers and frequently ask "is this number in the set?" and "insert this new number."

| Operation | Unsorted array | Sorted array (binary search) | Linked list |
|---|---|---|---|
| Search | O(n) | O(log n) | O(n) |
| Insert | O(1) (at the end) | O(n) (shift elements) | O(1) (if position known) |
| Delete | O(n) | O(n) | O(1) (if position known) |

**Binary search on a sorted array is fast, but its order is "maintained by moving everything around after every insertion."** If you insert 100,000 times, each one shifts half the elements — the total is O(n²). A linked list avoids shifting, but to search you must visit nodes one by one; 100,000 elements take 100,000 steps.

**To search fast *and* insert fast, the data must be "naturally spread out in order."** That is exactly what a tree does.

## The definition: a collection of nodes connected by edges, forming an acyclic connected structure

A tree is a finite set of n nodes. When n = 0 it is an empty tree; otherwise there is one special node called the **root**, and the remaining nodes split into several disjoint subtrees.

All the terminology revolves around a family tree:

- **Root**: the topmost node, with no parent.
- **Parent / child**: two nodes directly joined by an edge; the one higher up is the parent, the one lower is the child.
- **Leaf**: a node with no children.
- **Depth**: the number of edges from the root to that node (the root has depth 0).
- **Height**: the number of edges from that node down to its farthest leaf (a leaf has height 0, an empty tree has height -1).
- **Subtree**: a node together with all its descendants.

```python
# A class that represents one node of a tree
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

# Manually build this tree:
#       1
#      / \
#     2   3
#    / \
#   4   5
root = TreeNode(1)
root.left = TreeNode(2)
root.right = TreeNode(3)
root.left.left = TreeNode(4)
root.left.right = TreeNode(5)

print(root.val)              # 1
print(root.left.val)         # 2
print(root.left.right.val)   # 5
```

**A tree's "structural information" *is* its ordering.** In the example above, whether 2 is larger or smaller than 3 is not determined by their values — it is determined by their positions. To express a "size relationship" you need a specially shaped tree: a binary search tree, which we cover in lesson 04.

## WRONG WAY: Treating a tree like a graph and falling into a cycle

```python
# WRONG: a node references itself, forming a cycle
a = TreeNode(1)
b = TreeNode(2)
a.left = b
b.left = a      # a's child is b, b's child is a again

def count_nodes(node):
    if node is None:
        return 0
    return 1 + count_nodes(node.left) + count_nodes(node.right)

print(count_nodes(a))
```

Error (or it never returns):

```
RecursionError: maximum recursion depth exceeded
```

**The definition of a tree explicitly says "acyclic."** Once a cycle exists, any recursive traversal loops forever until Python kills the call stack. In algorithm problems the input tree is **guaranteed to be acyclic**, so you do not need to worry. But if you "build a tree yourself" (as in some construction problems), you must be careful not to wire the edges incorrectly.

**Rule of thumb: if you get `RecursionError` and you are sure your termination condition is correct, suspect a cycle in the structure.**

## Why a tree makes operations faster: branching cuts the search space in half

Binary search on an array is fast because "the index lets you jump around." A tree has no indices, but it has **branches** — every node naturally splits the nodes below it into "the left bunch" and "the right bunch."

Imagine an "ideal" tree with 7 nodes, perfectly filled:

```
        A
      /   \
     B     C
    / \   / \
   D   E F   G
```

**Starting from A, one step eliminates half the nodes.** The path to D is A→B→D, three steps; the tree has 7 nodes total and the longest path is 3 steps. Double the nodes to 15 and you add at most one more step.

The rule: a **tree of height h holds at most 2^(h+1) - 1 nodes**. Conversely, a tree with n nodes has height at least ⌊log₂n⌋. **Height *is* "the maximum number of steps," which is the time complexity of the operation.**

This is exactly what "compromise" means:

- A linked list is one long line: n nodes take n steps, O(n).
- A balanced tree "fans out": n nodes take only log n steps, O(log n).
- An extremely skewed tree (every node has only a right child) is just a linked list, degrading to O(n).

**A tree's performance depends entirely on how skewed it is.** BSTs, heaps, and balanced trees are all, at their core, fighting against "skewness."

## Binary trees: at most two children per node

**A binary tree is the most useful kind of tree**, restricting each node to at most two children: left and right. Its value is that the structure is simple (only two exits) yet rich enough to express all kinds of orderings.

A binary tree has five basic shapes: empty, a single root, only a left subtree, only a right subtree, and both. Every complex binary tree is a combination of these five.

```python
# Level-order construction: using index arithmetic for a complete binary tree
# The left child of index i is 2i+1, the right child is 2i+2,
# the parent is (i-1)//2
vals = [1, 2, 3, 4, 5, 6, 7]
nodes = [TreeNode(v) for v in vals]
for i in range(len(vals)):
    left = 2 * i + 1
    right = 2 * i + 2
    if left < len(vals):
        nodes[i].left = nodes[left]
    if right < len(vals):
        nodes[i].right = nodes[right]

root = nodes[0]
print(root.val, root.left.val, root.right.val)   # 1 2 3
```

**The index relations `2i+1` and `2i+2` belong specifically to "complete binary trees."** They only hold when the tree is "filled top to bottom, left to right" (a heap has exactly this shape, covered in lesson 10). **An ordinary binary tree cannot locate children by index** — you must follow the `node.left` and `node.right` pointers.

## WRONG WAY: Dereferencing None, touching an attribute on an empty node

```python
# WRONG: accessing .val without first checking whether node is None
def tree_max(node):
    m = node.val                  # assumes node always exists
    if node.left:
        m = max(m, tree_max(node.left))
    if node.right:
        m = max(m, tree_max(node.right))
    return m

print(tree_max(None))
```

Error:

```
AttributeError: 'NoneType' object has no attribute 'val'
```

**The easiest mistake with trees is forgetting that a node might be empty.** Almost every recursive tree function should start with `if node is None: return ...`. An empty tree is not an "exceptional case" — it is "one of the most common base cases."

## Tree representations: pointer version vs. array version

| Representation | How it looks | Pros | Cons |
|---|---|---|---|
| Linked (pointers) | `TreeNode` + `left/right` | Universal; any shape works | Two extra pointer fields, larger memory overhead |
| Array (level-order) | Values stored layer by layer, `None` for gaps | Great for complete binary trees; indices locate parent/child | A sparse tree wastes a lot of space |

**In algorithm problems, a level-order list like `[1,2,3,None,None,4,5]` is the standard input format.** It "flattens" the tree "layer by layer, left to right"; `None` means no node at that position. Lesson 02 shows how to turn this back into a `TreeNode`, and how to flatten a `TreeNode` back into a list — both operations show up constantly in test cases.

```python
def build(vals):
    """Turn a level-order list back into a TreeNode."""
    if not vals or vals[0] is None:
        return None
    nodes = [None if v is None else TreeNode(v) for v in vals]
    for i in range(len(nodes)):
        if nodes[i] is None:
            continue
        left = 2 * i + 1
        right = 2 * i + 2
        if left < len(nodes) and nodes[left] is not None:
            nodes[i].left = nodes[left]
        if right < len(nodes) and nodes[right] is not None:
            nodes[i].right = nodes[right]
    return nodes[0]

def to_list(root):
    """Flatten a TreeNode into a level-order list (trailing Nones removed)."""
    if root is None:
        return []
    from collections import deque
    ans, q = [], deque([root])
    while q:
        n = q.popleft()
        if n is None:
            ans.append(None)
        else:
            ans.append(n.val)
            q.append(n.left)
            q.append(n.right)
    while ans and ans[-1] is None:   # drop the extra Nones at the end
        ans.pop()
    return ans

t = build([1, 2, 3, None, None, 4, 5])
print(to_list(t))   # [1, 2, 3, None, None, 4, 5]
```

## Depth, height, and node count: the three most basic quantities

**Every problem that "traverses the whole tree" is really doing a DFS or BFS on that tree.** Memorize these three definitions; every later lesson uses them:

- **Depth**: the number of edges from the root to that node; the root's depth is 0.
- **Height**: the number of edges from that node down to its farthest leaf; a leaf is 0, an empty tree is -1.
- **Node count**: how many nodes the whole tree has (including the root).

```python
def count_nodes(root):
    if root is None:
        return 0
    return 1 + count_nodes(root.left) + count_nodes(root.right)

print(count_nodes(build([1, 2, 3, 4, 5])))   # 5
print(count_nodes(None))                       # 0
```

**This "1 + left subtree + right subtree" pattern is the skeleton of every tree recursion problem to come.** Lesson 06 turns this into a system: any quantity about a whole tree can almost always be written as "the result from the left subtree + the root's contribution + the result from the right subtree."

## Summary

- The contradiction of array search/insert comes from "order having to be maintained by moving elements"; a tree lets data spread out in order naturally, pushing both search and insert down to O(h).
- Core tree terms: root, parent/child, leaf, depth, height, subtree.
- **A tree must be acyclic**; once a cycle forms, any recursive traversal throws `RecursionError`.
- A binary tree allows at most two children per node; in the ideal case height h ≈ log n and operations are O(log n).
- Empty nodes are the norm — **the first line of every recursive tree function must check for `None`**.
- Linked representation is universal; array (level-order) representation fits complete binary trees; `[1,2,3,None,None,4,5]` is the standard input format.
- `build()` and `to_list()` are the infrastructure for every tree problem that follows.
