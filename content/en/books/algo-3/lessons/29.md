# Prefix Sums + Hash + Sliding Window: Combined Techniques

> Prefix sums, hash tables, and sliding windows are three fundamental tools. Each is simple on its own. But the truly difficult problems require combining them. This lesson uses classic problems to demonstrate how these three tools work together.

## The Role of Each Tool

**First, let's review what each tool solves:**

| Tool | Core problem it solves |
|---|---|
| Prefix sums | Range sum queries: reduces O(n) range queries to O(1) |
| Hash table | Fast lookup: O(1) to check "exists?" or "where?" |
| Sliding window | Two pointers maintain a window: O(n) to process "subarrays satisfying a condition" |

**The core idea behind combining them:**

> Prefix sums compute "interval sums," hash tables remember "where prefix sums occurred," and sliding windows maintain "interval boundary conditions."

## Classic Problem: Subarray Sum Equals K

**Problem:** Given an integer array nums and a target value k, find the number of contiguous subarrays whose sum equals k.

**Brute force O(n²): enumerate all start and end positions, compute the sum.**

```python
def subarray_sum_bruteforce(nums, k):
    n = len(nums)
    count = 0
    for i in range(n):
        s = 0
        for j in range(i, n):
            s += nums[j]
            if s == k:
                count += 1
    return count

print(subarray_sum_bruteforce([1, 1, 1], 2))   # 2
```

**O(n²), guaranteed TLE at n=10⁵.**

### Optimization: Prefix Sum + Hash Table

**Prefix sum prefix[i] = nums[0] + ... + nums[i-1].**

**The sum of subarray nums[j..i-1] = prefix[i] - prefix[j].**

**We want prefix[i] - prefix[j] == k, i.e., prefix[j] == prefix[i] - k.**

**Use a hash table to record how many times each prefix sum has appeared. While iterating, look up how many times prefix[i] - k has appeared.**

```python
def subarray_sum(nums, k):
    from collections import defaultdict
    count = 0
    prefix_count = defaultdict(int)
    prefix_count[0] = 1        # Empty prefix has sum 0, appears once
    cur = 0
    
    for x in nums:
        cur += x               # Current prefix sum
        count += prefix_count[cur - k]   # How many prefix sums == cur - k?
        prefix_count[cur] += 1            # Record current prefix sum
    
    return count

print(subarray_sum([1, 1, 1], 2))   # 2
print(subarray_sum([1, 2, 3], 3))   # 2 ([1,2] and [3])
print(subarray_sum([1, -1, 0], 0))  # 3
```

**Time complexity O(n), space O(n).**

## Sliding Window: Handling "Longest/Shortest" Subarrays

**Problem:** Given an array of positive integers and an integer S, find the length of the shortest contiguous subarray with sum ≥ S.

**Since the array is all positive, the window sum is monotonic: expanding increases the sum, shrinking decreases it. This makes sliding window applicable.**

```python
def min_subarray_len(S, nums):
    n = len(nums)
    left = 0
    cur = 0
    ans = float('inf')
    
    for right in range(n):
        cur += nums[right]
        while cur >= S:               # Satisfies condition, try to shrink
            ans = min(ans, right - left + 1)
            cur -= nums[left]
            left += 1
    
    return ans if ans != float('inf') else 0

print(min_subarray_len(7, [2, 3, 1, 2, 4, 3]))   # 2 ([4,3])
```

**Why is monotonicity important?** If the array has negative numbers, expanding the window doesn't guarantee an increase in sum, and shrinking doesn't guarantee a decrease—sliding window fails. In that case, you'd use prefix sums + binary search or prefix sums + hash.

## Combining the Three: Longest Substring Without Repeating Characters

**Problem:** Find the length of the longest substring without repeating characters.

**This combines "sliding window + hash table":**

```python
def length_of_longest_substring(s):
    n = len(s)
    left = 0
    max_len = 0
    last_pos = {}          # Hash table: char -> most recent position
    
    for right in range(n):
        c = s[right]
        if c in last_pos and last_pos[c] >= left:
            left = last_pos[c] + 1     # Shrink left boundary past the last occurrence
        last_pos[c] = right
        max_len = max(max_len, right - left + 1)
    
    return max_len

print(length_of_longest_substring("abcabcbb"))   # 3 ("abc")
print(length_of_longest_substring("bbbbb"))       # 1
print(length_of_longest_substring("pwwkew"))      # 3 ("wke")
```

**The sliding window maintains the "no repeats" interval, and the hash table records the most recent position of each character—solved in O(n).**

## Advanced Combination: Longest Subarray with Sum K (Including Negatives)

**Problem:** Array contains negative numbers; find the longest subarray with sum == k.

**Prefix sum + hash table, but this time the hash table records "the earliest occurrence of each prefix sum":**

```python
def longest_subarray_sum_k(nums, k):
    prefix_first = {}       # prefix sum -> earliest index
    prefix_first[0] = -1    # Empty prefix
    cur = 0
    max_len = 0
    
    for i, x in enumerate(nums):
        cur += x
        target = cur - k
        if target in prefix_first:
            max_len = max(max_len, i - prefix_first[target])
        if cur not in prefix_first:     # Only record the first occurrence (earliest)
            prefix_first[cur] = i
    
    return max_len

print(longest_subarray_sum_k([1, -1, 5, -2, 3], 3))   # 4
print(longest_subarray_sum_k([1, 2, 3], 3))            # 2
print(longest_subarray_sum_k([-2, -1, 2, 1], 1))       # 2
```

**Because we want "longest," the hash table only records the first occurrence of each prefix sum. This gives us the smallest j, maximizing i-j.**

## WRONG: Prefix Sum + Hash, Forgot to Initialize prefix[0]=1

**This is the most frequent error—missing the empty prefix.**

```python
# WRONG: forgot prefix_count[0] = 1
def subarray_sum_wrong(nums, k):
    from collections import defaultdict
    count = 0
    prefix_count = defaultdict(int)
    # Missing prefix_count[0] = 1
    cur = 0
    for x in nums:
        cur += x
        count += prefix_count[cur - k]
        prefix_count[cur] += 1
    return count

print(subarray_sum_wrong([1, 1, 1], 2))   # Misses subarrays starting at index 0
```

**Why is it wrong?** When `cur - k == 0` (i.e., the current prefix sum exactly equals k), we need `prefix_count[0]` to be 1 to count "the subarray starting at index 0." Without initialization, it's 0, and we miss it.

**Fix: add `prefix_count[0] = 1`.**

## WRONG: For "Longest Subarray," Hash Table Records "Last" Position Instead of "First"

**In "longest sum" problems, you should record the first occurrence of each prefix sum, not the last.**

```python
# WRONG: records the last occurrence position
def longest_wrong(nums, k):
    last_pos = {}
    cur = 0
    max_len = 0
    for i, x in enumerate(nums):
        cur += x
        target = cur - k
        if target in last_pos:
            max_len = max(max_len, i - last_pos[target])  # Uses last position, smaller gap
        last_pos[cur] = i          # Overwrites previous position
    return max_len

# [1, 2, 3], k=3
# prefix: 1, 3, 6
# When cur=6, target=3, last_pos[3]=1 (overwritten, but happened to appear only once)
# If prefix 3 appeared multiple times, it would be overwritten to a later position, giving a shorter interval
```

**Fix: only record when the key doesn't exist yet (preserve the earliest position).**

```python
def longest_fixed(nums, k):
    first_pos = {}
    first_pos[0] = -1
    cur = 0
    max_len = 0
    for i, x in enumerate(nums):
        cur += x
        target = cur - k
        if target in first_pos:
            max_len = max(max_len, i - first_pos[target])
        if cur not in first_pos:       # Only record the first time
            first_pos[cur] = i
    return max_len
```

## WRONG: Using Sliding Window on an Array with Negative Numbers

**Sliding window correctness depends on monotonicity. If the array has negative numbers, the window sum isn't monotonic.**

```python
# WRONG: using sliding window for "sum >= S" on an array with negative numbers
def min_len_wrong(S, nums):
    left = 0
    cur = 0
    ans = float('inf')
    for right in range(len(nums)):
        cur += nums[right]
        while cur >= S:
            ans = min(ans, right - left + 1)
            cur -= nums[left]
            left += 1
    return ans if ans != float('inf') else 0

print(min_len_wrong(3, [1, -1, 5, -2, 3]))   # May return wrong result
# The problem: when shrinking, cur might actually increase (if we subtract a negative)
```

**Why is it wrong?** If nums[left] is negative, subtracting it makes cur larger, so the while condition `cur >= S` becomes unreliable.

**Fix: if the array has negative numbers, use prefix sums + binary search or prefix sums + hash. Sliding window only works when all elements have the same sign (or the window size is fixed).**

## Summary

- **Prefix sums**: reduce range sum from O(n) to O(1), core formula `sum(i,j) = prefix[j+1] - prefix[i]`
- **Hash table**: records prefix sum counts/positions, reduces lookup from O(n) to O(1)
- **Sliding window**: two pointers maintain an interval, applicable when elements have the same sign (monotonic window sum)
- **Subarrays summing to K**: prefix sum + hash table, O(n), remember to initialize `prefix[0]=1`
- **Longest subarray**: hash table records "earliest" occurrence position
- **Longest substring without repeats**: sliding window + hash table recording most recent character position
- Common pitfalls: forgetting prefix[0] initialization, recording last instead of first position, using sliding window with negative numbers
