# Naming and Readability: Names Are the UI of Your Code

> You inherit a codebase and see `def p(data):` next to `def process_order_payload(payload):`. To understand the first you must read the entire body; the second you grasp at a glance. Code is read far more often than it is written — names are the manual you leave for your future self and your colleagues.

## The Standard for a Good Name

A good name meets three standards: **it says what the thing is, what it does, and what unit it is in.**

```python
# Vague
d = 30

# Clear
days_to_keep_log = 30
```

```python
# Vague
def get(uid):
    ...

# Clear
def fetch_user_by_id(user_id):
    ...
```

**Stating the unit matters especially.** Is a `timeout` in seconds or milliseconds? A disciplined team makes the choice explicit:

```python
timeout_sec = 30
retry_interval_ms = 500
file_size_mb = 256
```

See the name and you know the unit — no documentation dive, no guesswork.

## Never Use l, O, or I as Single-Letter Names

In most fonts, the lowercase letter `l`, the uppercase letter `O`, and the uppercase letter `I` look almost identical to the digits `1`, `0`, and `1`.

```python
# WRONG: disastrous naming
l = 1
O = 0
I = 1
```

```python
# If you actually wrote this out
l = 10
O = 5
print(l, O, I)
# Output: 10 5 1
# But staring at the screen you wonder whether it is 10 5 1, 101, or something else
```

**Crash Site: `l` and `1` get confused and produce a bug**

```python
# WRONG
def count_items(l):
    return len(l)

items = [1, 2, 3]
print(count_items(l))  # NameError: name 'l' is not defined
```

**What you see:** `NameError: name 'l' is not defined`. You meant to pass the list, but you typed `l` — which looks like `1`, and also like the first letter of `items`. Three days later you cannot tell the difference yourself.

PEP 8, Python's official style guide, explicitly advises: **never use `l`, `O`, or `I` as single-character variable names.** Use `i`, `j`, `k` for loop counters; call a list `lst` or, better, use the plural noun `items`.

## Boolean Names Take the is_ Prefix

A boolean name should answer "yes or no" directly.

```python
# Poor
enabled = True
valid = False
empty = True

# Good
is_enabled = True
is_valid = False
is_empty = True
can_retry = True     # capability uses can_
has_permission = True # possession uses has_
```

```python
# Reads like natural language
if is_valid and can_retry:
    process()

# Compare with
if valid and retry:
    process()
# Is retry a count or a switch? Is valid a function or a variable?
```

The three prefixes `is_`, `has_`, and `can_` eliminate a great deal of ambiguity. Newcomers stop guessing.

## Function Names Must Reveal Side Effects

Pure functions (same input always yields same output; no external state touched) must be distinguishable from functions with side effects (writing files, hitting the database, printing, mutating a global).

```python
# Pure: the name already says it only computes
def calculate_total(items):
    return sum(item.price for item in items)

# Side effect: the name says what it does
def save_order_to_db(order):
    db.insert(order)

def send_notification(user, msg):
    ...

def delete_user(user_id):
    ...
```

**Crash Site: a function name hides its side effect**

```python
# WRONG: reads like a pure function, actually writes to the database
def get_or_create_user(name):
    user = db.find(name)
    if user is None:
        user = db.create(name)  # silently writes to the database
    return user
```

A caller sees `get_or_create_user`, expects a query, and may invoke it inside a read-only context — only to trigger a write. The name should shout the side effect, e.g. `find_user_or_insert_default`.

## Name Length Grows with Scope

- **Loop temporaries:** short, the scope is one line.
  ```python
  for ch in text:
      count[ch] = count.get(ch, 0) + 1
  ```
- **Function parameters:** medium length; they must carry meaning in the signature.
  ```python
  def retry_with_backoff(operation, max_attempts, delay_sec):
      ...
  ```
- **Module-level constants, class attributes:** long and self-explanatory.
  ```python
  DEFAULT_CONNECTION_TIMEOUT_SECONDS = 30
  MAX_RETRY_ATTEMPTS = 3
  ```

## Summary

- A good name states what, what it does, and its unit.
- Never use `l`, `O`, `I` as single-character names.
- Booleans take `is_`/`has_`/`can_` so they read like natural language.
- Functions with side effects must name the effect.
- Name length grows in proportion to the size of the scope.

## In-Class Exercise

```quiz
type: choice
q: Which variable name best follows the "state the unit" rule?
options:
- t = 30
- timeout = 30
- timeout_sec = 30
- tm = 30
answer: 2
explain: timeout_sec states the unit directly: seconds. t and tm reveal nothing; timeout says it is a timeout but not whether it is seconds, milliseconds, or minutes, so a caller may pass the wrong magnitude.
```
