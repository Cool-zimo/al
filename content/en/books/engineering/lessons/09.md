# Formatting and Linting: Let Tools Settle Style Arguments

> Alice likes single quotes, Bob likes double quotes, Carol indents by two spaces, and you use four. Eighty percent of code review time goes to "should there be a space here?" Formatting tools exist to settle those arguments once and never discuss them again.

## What black / ruff / flake8 Each Handle

The three tools divide the territory:

| Tool | Job | Analogy |
|---|---|---|
| **black** | Format code (rewrites your code) | Automatic typesetting |
| **ruff** | Static checks + formatting (a faster all-rounder) | Typesetting + finding faults |
| **flake8** | Static checks (read-only, never rewrites) | Only finding faults |

**black** is "the uncompromising code formatter." Its philosophy is to offer almost no configuration. It will lay out your code in ways you dislike — and precisely because there is nothing to configure, teams have nothing to argue about.

```python
# Before formatting
def long_function(argument_one,argument_two,argument_three,argument_four,argument_five,argument_six):
    return argument_one+ argument_two

x=[1,2,3,]
```

```python
# After black
def long_function(
    argument_one,
    argument_two,
    argument_three,
    argument_four,
    argument_five,
    argument_six,
):
    return argument_one + argument_two

x = [1, 2, 3]
```

Notice: `argument_one+ argument_two` gains a space; an overlong argument list breaks and aligns; the trailing comma in the list is kept (cleaner diffs — adding an element touches only one line).

**ruff** is written in Rust and aims to replace flake8 + isort + pyupgrade and a handful of others; it runs 10–100× faster than its Python-written counterparts. It formats (partly replacing black) and lints.

**flake8** is the veteran checker with a rich plugin ecosystem. It never changes code, only reports:

```bash
$ flake8 main.py
main.py:12:1: E302 expected 2 blank lines, found 1
main.py:15:80: E501 line too long (92 > 79 characters)
main.py:20:5: F841 local variable 'unused' is assigned but never used
```

`E302`, `E501`, and `F841` are rule codes. Each maps to a category of style issue or potential problem.

## Why Run It Before Committing

**Crash Site: formatting problems leak into code review**

```bash
# Alice opens a PR
$ git push origin feature/login
```

On the review page, Alice changed three lines of business logic, but because she never ran the formatter, the diff mixes in fifty lines of indentation and line-break changes. Bob reviewing it can either ignore the formatting noise line by line (and miss the real change), or leave a pile of formatting comments — neither of which is a judgement a human should be making.

**The fix: run it automatically before commit**

Use Git's pre-commit hook to format on commit:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/psf/black
    rev: 24.0.0
    hooks:
      - id: black
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.5.0
    hooks:
      - id: ruff
```

After installing `pre-commit`:

```bash
$ pre-commit install     # install the hook (once)
$ git commit -m "feat: login"
black....................Passed
ruff.....................Failed
# The commit is blocked because ruff found issues
# Fix them, then add + commit again
```

The commit is blocked locally, you fix it, and the reviewer sees a clean diff.

## Editor Integration

**Crash Site: running the formatter by hand, always forgetting**

```bash
$ vim main.py
# edited for 20 minutes
$ python main.py
# works
$ git add main.py
# completely forgot to run black
```

Humans are unreliable. **Let the editor format on save:**

In VS Code, install the Python extension and set:

```json
{
    "[python]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "ms-python.black-formatter"
    }
}
```

Save and it formats — no longer your problem.

PyCharm ships with `Reformat Code` (Ctrl+Alt+L), which can be configured to run on save.

**Checker integration in the IDE:** install the Ruff extension in VS Code and it marks offending lines in real time as you save, with the rule explanation on hover.

## Summary

- black formats (rewrites); flake8/ruff check (read-only).
- ruff is written in Rust, faster, and can replace several tools.
- A pre-commit hook runs formatting before commit; do not leave it to review.
- Configure the editor to format on save, removing the possibility of forgetting.
