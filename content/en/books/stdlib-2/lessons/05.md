# Timestamps

> This lesson answers "why should I pass time as a timestamp when talking between systems, and what are the time-zone traps when converting to and from a timestamp?" You will see why storing local time directly can cause bugs.

## What a timestamp is

A **timestamp** is the number of **seconds** elapsed since **1970-01-01 00:00:00 UTC** (typically a float in Python, with the fractional part representing sub-second precision).

```python
import time

ts = time.time()
print(ts)   # 1787800000.123456 (a big number)
```

That number looks meaningless, but it has one huge advantage: **it is independent of time zone**. Whether you are in London or New York, the fact that "N seconds have passed since 1970-01-01" is the same everywhere. That makes timestamps the universal currency for passing time between systems.

## Converting between datetime and timestamp

```python
from datetime import datetime, timezone, timedelta

# datetime -> timestamp
dt = datetime(2026, 9, 27, 14, 30, 0)
ts = dt.timestamp()
print(ts)   # 1787807400.0

# timestamp -> datetime
dt2 = datetime.fromtimestamp(ts)
print(dt2)  # 2026-09-27 14:30:00
```

## Crash Site: the time-zone trap in timestamp conversion

```python
from datetime import datetime

# WRONG: timestamp() interprets a naive datetime as local time
dt = datetime(2026, 9, 27, 14, 30, 0)
ts = dt.timestamp()

# on a machine set to London time, this ts represents 14:30 local
# if the same code runs on a server in another zone, the value changes!
```

The root cause: `dt` is naive (no time-zone information), but `timestamp()` **assumes it is in local time**. Move the server to a different zone and the result changes.

```python
from datetime import datetime, timezone, timedelta

# correct: attach a time zone explicitly
tz_bst = timezone(timedelta(hours=1))  # BST / UTC+1
dt = datetime(2026, 9, 27, 14, 30, 0, tzinfo=tz_bst)
ts = dt.timestamp()
print(ts)  # the same result on every machine
```

## Crash Site: fromtimestamp returns local time

```python
from datetime import datetime

ts = 1787807400.0

# WRONG: fromtimestamp returns the time "from the local perspective"
dt_local = datetime.fromtimestamp(ts)
print(dt_local)
# in London:     2026-09-27 14:30:00 (or 15:30 in BST)
# in New York:   2026-09-27 09:30:00 (or 10:30 in EDT)
```

If you want "what moment in UTC does this timestamp represent," use `datetime.fromtimestamp(ts, tz=timezone.utc)`:

```python
# correct: ask for the UTC perspective explicitly
dt_utc = datetime.fromtimestamp(ts, tz=timezone.utc)
print(dt_utc)  # 2026-09-27 13:30:00+00:00
```

In Python 3.12 and later, the old `utcfromtimestamp` spelling is deprecated, so prefer the explicit `tz=timezone.utc` form.

## Worked example: recording an event time

```python
import time
from datetime import datetime, timezone, timedelta

def log_event(name):
    """Record an event and return its timestamp plus a readable time string."""
    ts = time.time()
    tz_bst = timezone(timedelta(hours=1))
    dt = datetime.fromtimestamp(ts, tz=tz_bst)
    return ts, dt.strftime("%Y-%m-%d %H:%M:%S")

ts, readable = log_event("user login")
print(f"Event time (London): {readable}")
print(f"Timestamp: {ts}")
```

## Worked example: comparing two timestamps

```python
from datetime import datetime, timezone, timedelta

tz_bst = timezone(timedelta(hours=1))

t1 = datetime(2026, 9, 27, 10, 0, 0, tzinfo=tz_bst).timestamp()
t2 = datetime(2026, 9, 27, 14, 30, 0, tzinfo=tz_bst).timestamp()

diff_seconds = t2 - t1
print(f"Difference: {diff_seconds / 3600:.1f} hours")  # 4.5 hours
```

Because a timestamp is just a number, you can add, subtract, and compare them directly — no timedelta required.

## Summary

- A timestamp is seconds since 1970-01-01 00:00:00 UTC — a zone-independent universal value
- `datetime.timestamp()` goes to a timestamp; `datetime.fromtimestamp(ts)` goes back
- **A naive datetime's timestamp() is interpreted as local time**, so it can vary by server
- Do it right by attaching `tzinfo=timezone(timedelta(hours=1))`
- `fromtimestamp(ts, tz=timezone.utc)` gives you the UTC perspective
- Timestamps are numbers, so you can compare and do arithmetic on them directly
