# The Three Siblings: date, time, datetime

> This lesson answers "which of `date`, `time`, or `datetime` should I actually use?" You will learn what each type covers, and when to combine them versus when to keep them separate.

## Three types, three levels of detail

The `datetime` module exposes three classes that are easy to confuse but have completely different jobs:

| Class | Covers | Typical use |
|---|---|---|
| `date` | year-month-day | birthdays, deadlines, payment due dates |
| `time` | hour:minute:second.microsecond | alarm time, opening hours |
| `datetime` | year-month-day hour:minute:second | log timestamps, order-creation times |

```python
from datetime import date, time, datetime

d = date(2026, 9, 27)          # date only
t = time(14, 30, 0)             # time only
dt = datetime(2026, 9, 27, 14, 30, 0)  # date + time

print(d)    # 2026-09-27
print(t)    # 14:30:00
print(dt)   # 2026-09-27 14:30:00
```

**The key difference**: `date` has no idea what time it is, and `time` has no idea which day it belongs to. `datetime` carries both, but uses more memory and brings more complexity with it.

## date: when you only need a calendar day

Good fit: anniversaries, contract terms, birthday reminders.

```python
from datetime import date

today = date.today()
print(today)              # 2026-09-27 (the day this runs)
print(today.year)         # 2026
print(today.month)        # 9
print(today.day)          # 27
print(today.weekday())    # 6 -> Sunday (0=Monday, 6=Sunday)
```

Note that `weekday()` returns 0 through 6, corresponding to Monday through Sunday. If your week starts on Sunday, use `isoweekday()` instead — it returns 1 through 7.

```python
print(today.isoweekday())  # 7 -> Sunday
```

## time: when you only need a clock reading

Good fit: scheduled reminders, shop opening hours, time slots in a timetable.

```python
from datetime import time

opening = time(9, 0)       # opens at 09:00
closing = time(22, 30)     # closes at 22:30
now = time(14, 30)

print(opening.hour)    # 9
print(closing.minute)  # 30
print(now > opening)   # True
```

`time` objects compare naturally — 09:00 is less than 14:30, which matches intuition.

## datetime: date and time combined

Good fit: log entries, order timestamps, message send times — anywhere you need "the exact moment something happened."

```python
from datetime import datetime

now = datetime.now()
print(now)           # 2026-09-27 14:30:05.123456

# combine a date + time -> datetime
from datetime import date, time
d = date(2026, 9, 27)
t = time(9, 0)
dt = datetime.combine(d, t)
print(dt)   # 2026-09-27 09:00:00

# split it back apart
print(dt.date())   # 2026-09-27
print(dt.time())   # 09:00:00
```

## Crash Site: mixing date and datetime raises an error

```python
from datetime import date, datetime

d = date(2026, 9, 27)
dt = datetime(2026, 9, 27, 10, 0)

# WRONG: date and datetime cannot be compared directly
print(dt > d)
```

Error:

```
TypeError: can't compare datetime.datetime to datetime.date
```

These two types cannot be compared as-is. The fix is to convert one of them so the types match.

```python
# correct: turn the date into "midnight that day" as a datetime
from datetime import datetime, time
dt_same_day = datetime.combine(d, time.min)  # 2026-09-27 00:00:00
print(dt > dt_same_day)   # True
```

Or, going the other way, just compare the date portion of the datetime:

```python
print(dt.date() == d)   # True
```

## Crash Site: datetime.now() and the time-zone problem

```python
from datetime import datetime

# WRONG: now() returns local time but carries no zone information
t = datetime.now()
print(t)           # 2026-09-27 14:30:05.123456
print(t.tzinfo)    # None <- no time zone!
```

An object like this is called **naive** — it holds the digits of your local clock but has no idea which zone those digits belong to. If you store this value in a database, a user in another time zone who reads it back will get the wrong answer. Lesson 06 covers time zones in full.

## Summary

- `date` = year/month/day, `time` = hour/minute/second, `datetime` = date + time
- The three types **cannot be compared directly** — use `datetime.combine()` or `.date()` to align them
- `date.today()` / `datetime.now()` give you the current date and time
- `date.weekday()` returns 0-6 (Monday=0); `isoweekday()` returns 1-7
- `datetime.now()` returns a naive object with no time-zone info (fixed in lesson 06)
