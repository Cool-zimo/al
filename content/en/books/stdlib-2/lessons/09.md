# Parsing Dates in the Wild

> This lesson answers "users type dates in every format imaginable — how do I parse them forgivingly?" You will learn to try multiple formats with try/except, and discover the limits of format-based parsing.

## The date-format chaos of real input

You can never be sure what format a user will type:

| Source | Typical formats |
|---|---|
| A UK user | `27 September 2026`, `2026-09-27`, `27/09/2026` |
| A US API | `09/27/2026`, `Sep 27, 2026`, `2026-09-27T14:30:00Z` |
| A log file | `[2026-09-27 14:30:05]`, `27/Sep/2026:14:30:05 +0000` |
| A filename | `20260927_143005` |

If you only support one format, the first unexpected input crashes your program. You need **forgiving parsing**.

## Trying multiple formats

The most practical approach: keep a list of format strings, try each in turn, and the first one that succeeds wins.

```python
from datetime import datetime

def parse_date(s):
    """Try several formats to parse a date string."""
    formats = [
        "%Y-%m-%d",
        "%Y/%m/%d",
        "%d %B %Y",
        "%m/%d/%Y",
        "%d/%m/%Y",
        "%Y-%m-%d %H:%M:%S",
    ]
    for fmt in formats:
        try:
            return datetime.strptime(s, fmt)
        except ValueError:
            continue
    raise ValueError(f"Could not parse date: {s}")

print(parse_date("2026-09-27"))       # 2026-09-27 00:00:00
print(parse_date("09/27/2026"))       # 2026-09-27 00:00:00
print(parse_date("27 September 2026"))  # 2026-09-27 00:00:00
```

## Crash Site: ambiguous formats get parsed wrong

```python
# WRONG: no handling for the ambiguity
formats = ["%m/%d/%Y", "%d/%m/%Y"]

def parse(s):
    for fmt in formats:
        try:
            return datetime.strptime(s, fmt)
        except ValueError:
            continue

print(parse("03/04/2026"))
```

This prints `2026-03-04 00:00:00` — because `%m/%d/%Y` was tried first and parsed 03 as the month. But if a British user meant "3 April," the correct answer is `2026-04-03`.

**This is the fundamental limit of format-based parsing**: when the input is ambiguous, you must either *know in advance* which convention the user follows or *ask the user to choose*. A program cannot reliably tell whether `03/04/2026` means March 4 or April 3.

## Worked example: parsing an ISO 8601 string with a zone

Many APIs return ISO 8601: `2026-09-27T14:30:00+01:00`

```python
from datetime import datetime
from zoneinfo import ZoneInfo

def parse_iso(s):
    """Parse an ISO 8601 string that may end in Z."""
    # replace Z (meaning UTC) with +00:00
    s = s.replace("Z", "+00:00")
    # Python 3.11+ handles this directly with fromisoformat
    return datetime.fromisoformat(s)

dt = parse_iso("2026-09-27T14:30:00+01:00")
print(dt)   # 2026-09-27 14:30:00+01:00

dt2 = parse_iso("2026-09-27T13:30:00Z")
print(dt2)  # 2026-09-27 13:30:00+00:00
```

Python 3.11's `fromisoformat` already understands `Z` and `+HH:MM` suffixes. On older versions you would need to handle those by hand.

## Worked example: loose parsing by extracting digits

When the format is wildly inconsistent, you can reach for a regex to pull the numbers out and reassemble them:

```python
import re
from datetime import datetime

def parse_flexible(s):
    """Very loose: extract all digits and assemble them positionally."""
    numbers = re.findall(r'\d+', s)
    if len(numbers) >= 3:
        y, m, d = int(numbers[0]), int(numbers[1]), int(numbers[2])
        if y < 100:
            y += 2000
        return datetime(y, m, d)
    raise ValueError(f"Could not extract a date from: {s}")

print(parse_flexible("Today is 27 September 2026"))  # 2026-09-27 00:00:00
print(parse_flexible("Date: 2026/09/27"))            # 2026-09-27 00:00:00
```

## The third-party option: dateutil.parser

If third-party libraries are allowed, `python-dateutil`'s `parser.parse` recognises almost any common format automatically:

```python
# pip install python-dateutil
from dateutil.parser import parse

print(parse("2026-09-27"))
print(parse("Sep 27, 2026"))
print(parse("27/09/2026"))
print(parse("20260927"))
```

**But note**: this is still ambiguous. `parse("03/04/2026")` follows US conventions and returns March 4. You can pass `dayfirst=True` to change that behaviour.

## Worked example: pulling a timestamp out of a log line

```python
import re
from datetime import datetime

log_line = "2026-09-27 14:30:05 [INFO] User Alice logged in"

def extract_time(log):
    match = re.match(r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})', log)
    if match:
        return datetime.strptime(match.group(1), "%Y-%m-%d %H:%M:%S")
    return None

print(extract_time(log_line))  # 2026-09-27 14:30:05
```

## Summary

- Multiple formats are best handled with a **try/except loop over a list of format strings**
- Ambiguous input (`03/04/2026`) cannot be resolved automatically — you need prior knowledge or user input
- Python 3.11+'s `datetime.fromisoformat()` supports ISO 8601 strings
- For very loose input, extract digits with a regex and reassemble them
- `python-dateutil`'s `parser.parse` recognises most formats (third-party)
