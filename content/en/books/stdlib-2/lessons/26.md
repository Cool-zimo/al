## The Problem This Tool Solves

Open your Downloads folder. Is it a mess? PDFs, images, installers, archives, and temporary files all sit side by side. Alice has more than 3,000 files in hers and spends five minutes finding a contract. Bob manually creates a few folders and drags files around once a week, but "Videos", "Movies", and "Clips" all hold the same kind of content—after a few moves he forgets the rules he set.

The **Smart File Organiser** will scan a directory, classify files by rule, move them into subdirectories, and print a report. Nothing is deleted, and every step is previewable and reversible.

```text
# The end result (pseudocode)
$ python organize.py ~/Downloads --preview
[Preview] Will move 1284 files
  Images/  -> 412 (jpg/png/webp)
  Docs/    -> 267 (pdf/docx/xlsx)
  Archives/-> 198 (zip/tar.gz/7z)
  Media/   -> 96  (mp4/mkv/mp3)
  Other/   -> 311

$ python organize.py ~/Downloads --apply
✓ Done. 1284 files organised.

$ python organize.py ~/Downloads --undo last
✓ Reversed the moves for 1284 files.
```

## Why Layers Matter: Four Independent Modules

The classic large-project mistake is "one function that does everything"—scanning, classifying, moving, and logging all mixed together. It cannot be tested and breaks the moment you change it. Split the tool into four layers so that each one has a single responsibility:

| Module | Responsibility | Standard library support | Input → output |
|--------|-----------------|--------------------------|----------------|
| **Scanner** | Walks the directory and collects file metadata | `pathlib`, `os` | Directory path → list of file-info dicts |
| **Classifier** | Labels each file with a category | `pathlib`, `datetime` | File info → category string |
| **Planner** | Decides the destination path and resolves conflicts | `datetime`, `fnmatch` | File plus rules → destination path |
| **Executor** | Actually moves files, writes a log, supports undo | `shutil`, `json`, `tempfile` | Plan → operation results |

```python
# The shape of data moving between layers: one dictionary, pure and serialisable.
file_info = {
    "src": "/home/alice/Downloads/contract.pdf",
    "name": "contract.pdf",
    "ext": ".pdf",
    "size": 204800,
    "mtime": "2026-09-20T10:30:00",
}
# Scanner produces it -> Classifier adds "category": "Docs"
#                  -> Planner adds "dest": "Docs/2026-09/contract.pdf"
#                  -> Executor performs the actual move.
```

**The key design:** the first three layers are pure functions. They accept data and return data without touching the real filesystem (during tests). Only the Executor performs real I/O. That is how you can test the core logic without reading or writing a single file.

## Safety by Design: Preview First, Execute Later

Organising files carries two main risks: **accidental deletion** and **no way to undo**. This is where a real tool separates itself from a quick script.

**Rule one: always preview first (dry-run).** The default behaviour should be "show me what you would do"; the user must explicitly pass `--apply` to commit.

```python
class Organizer:
    def __init__(self, root):
        self.root = Path(root)
        self.plan = []          # The operation plan.
        self.log_path = None     # Log location (used for undo).

    def scan(self):        # Layer 1
        ...
    def classify(self):    # Layer 2
        ...
    def plan_moves(self):  # Layer 3
        ...

    def preview(self):
        """Print only; do not touch files."""
        print(f"[Preview] Will process {len(self.plan)} files")
        by_cat = {}
        for item in self.plan:
            by_cat[item["category"]] = by_cat.get(item["category"], 0) + 1
        for cat, n in sorted(by_cat.items(), key=lambda x: -x[1]):
            print(f"  {cat:<12} -> {n}")
        print("\nTip: add --apply to actually execute.")

    def apply(self):       # Layer 4
        """Write the log first, then move files one by one.
        Failures must not abort the run."""
        ...
```

**Rule two: undo depends on an operation log.** Before every real execution, write the complete plan—source path, destination path, timestamp—to a JSON log. To undo, read the log and move every file back. That is the subject of Lesson 29.

## Crash Site: Moving First and Logging Later Leaves an Incomplete Trail

The most common error is splitting execution and logging into two phases, moving first and writing the log afterwards. If something fails midway, the log no longer matches reality.

```python
import shutil, json, os

# WRONG: move first, then write the log at the very end.
def apply_wrong(plan):
    for item in plan:
        shutil.move(item["src"], item["dest"])
    # If the third move raises an exception, the first two are already gone
    # and ops.log has not been created yet.
    with open("ops.log", "w") as f:
        json.dump(plan, f)
    print("Log written")

plan = [
    {"src": "a.txt", "dest": "Text/a.txt"},
    {"src": "b.txt", "dest": "Text/b.txt"},
    {"src": "c.txt", "dest": "/root/no_perm/c.txt"},  # Raises PermissionError.
]
apply_wrong(plan)
# Traceback: PermissionError
# At this point a.txt and b.txt have moved, but ops.log does not exist -> no undo.
```

The fix is to **write the log first, then execute**, updating each entry's status as it completes. Even if the run crashes halfway, the log remains complete and trustworthy. Lesson 29 provides the full implementation.

## Crash Site: Mutating a Directory While Scanning It

If you create new subdirectories inside the directory you are scanning, the scanner may "see" its own output and loop or double-classify entries.

```python
from pathlib import Path

# WRONG: creating directories while scanning can pull them into the scan.
def classify_inplace(root):
    cats = {}
    for p in Path(root).rglob("*"):
        if p.is_file():
            ext = p.suffix.lower()
            if ext in {".jpg", ".png"}:
                cats.setdefault("Images", []).append(p)
            # If this step also creates Images/, the next iteration scans it.
    return cats

# Correct: scanning and classifying are completely separate; classification only reads.
def classify_only(files):
    cats = {}
    for f in files:          # files is already a frozen list.
        ext = f["ext"]
        if ext in {".jpg", ".png"}:
            cats.setdefault("Images", []).append(f["src"])
    return cats
```

Another benefit of layered design: **data is frozen into a list first, so later operations cannot contaminate each other**.

## Recap

- The organiser has four layers: Scanner → Classifier → Planner → Executor.
- The first three layers are **pure functions** that process data; only the Executor performs real I/O, which keeps testing straightforward.
- **Preview first, execute later:** dry-run is the default; the user must confirm explicitly.
- **Log first, execute later:** the log is the only basis for undo and must never be patched in afterwards.
- Data moves between layers as dictionaries with a stable, serialisable shape.
