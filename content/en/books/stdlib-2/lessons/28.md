# The Rule Engine: Configurable Classification and Date-Based Archiving

> Hardcoding classification rules makes a toy. This lesson turns rules into data and adds date-based archiving—putting the time knowledge from Chapters 1 and 2 to work.

## Configurable Rules: Rules Are Data

Hardcoding `if ext == ".jpg": cat = "Images"` has one problem: a different user or a different situation requires code changes. Extract the rules and the organiser becomes reusable.

```python
# rules.yaml (expressed as JSON here to avoid introducing a new library).
RULES = {
    "categories": {
        "Images":   [".jpg", ".jpeg", ".png", ".gif", ".webp", ".bmp"],
        "Docs":     [".pdf", ".docx", ".xlsx", ".pptx", ".txt", ".md"],
        "Media":    [".mp4", ".mkv", ".mov", ".mp3", ".wav", ".flac"],
        "Archives": [".zip", ".tar", ".gz", ".7z", ".rar", ".bz2"],
        "Code":     [".py", ".js", ".ts", ".go", ".rs", ".java", ".c", ".cpp"],
    },
    "date_archive": True,        # Group files by year and month.
    "date_format": "%Y-%m",      # Directory name format.
    "size_thresholds": {"tiny": 10240, "huge": 104857600},
}
```

```python
from datetime import datetime
from pathlib import Path


def build_ext_map(rules):
    """Flatten categories into an extension-to-category mapping."""
    m = {}
    for cat, exts in rules["categories"].items():
        for ext in exts:
            m[ext.lower()] = cat
    return m


def date_folder(mtime_iso, fmt):
    """Derive a date directory name such as 2026-09 from an mtime string."""
    dt = datetime.fromisoformat(mtime_iso)
    return dt.strftime(fmt)


def plan_destination(file_info, rules):
    """Produce a destination path (relative to the root) for one file.
    Return (category, dest_rel)."""
    ext_map = build_ext_map(rules)
    ext = file_info["ext"]
    mtime = file_info["mtime"]

    # 1. Classify by extension.
    category = ext_map.get(ext)

    # 2. Fall back to size when the extension has no mapping.
    if category is None:
        sz = file_info["size"]
        t = rules["size_thresholds"]
        if sz < t["tiny"]:
            category = "Tiny"
        elif sz >= t["huge"]:
            category = "Huge"
        else:
            category = "Other"

    # 3. Optionally archive by date.
    if rules.get("date_archive"):
        sub = date_folder(mtime, rules["date_format"])
        dest = f"{category}/{sub}/{file_info['name']}"
    else:
        dest = f"{category}/{file_info['name']}"

    return category, dest
```

## Date-Based Archiving: Putting Time to Work

`strftime` from Chapter 1 and "organising data by time" from Chapter 2 now have a concrete use. `date_folder` turns a file's **modification time** into a directory name, so files in the same category layer themselves by time:

```text
Docs/2026-09/contract.pdf
Docs/2026-08/quotation.pdf
Images/2026-09/IMG_0001.jpg
```

The benefit is a natural chronological order: "last month's material" lives in one directory you can open directly.

```python
files = [
    {"src": "/d/a.pdf", "name": "a.pdf", "ext": ".pdf", "size": 1000, "mtime": "2026-09-20T10:00:00"},
    {"src": "/d/b.pdf", "name": "b.pdf", "ext": ".pdf", "size": 2000, "mtime": "2026-08-05T09:00:00"},
    {"src": "/d/c.jpg", "name": "c.jpg", "ext": ".jpg", "size": 3000, "mtime": "2026-09-01T08:00:00"},
]

for f in files:
    cat, dest = plan_destination(f, RULES)
    print(f"{f['name']:<10} -> {dest}")
# a.pdf      -> Docs/2026-09/a.pdf
# b.pdf      -> Docs/2026-08/b.pdf
# c.jpg      -> Images/2026-09/c.jpg
```

## Rule Conflicts: Make the Priority Explicit

When several rules could match one file (for example `.tar.gz` triggers logic for both `.tar` and `.gz`), the engine needs a deterministic priority. The rule here is straightforward: **extension mapping beats size fallback, and size fallback beats "Other".**

But a more practical conflict is a **name collision**: the destination already contains `a.pdf`, and you need to move another one there.

```python
from pathlib import Path


def unique_dest(dest, existing):
    """When dest collides, append an index: a.pdf -> a_1.pdf -> a_2.pdf."""
    if dest not in existing:
        return dest
    p = Path(dest)
    stem, suffix = p.stem, p.suffix
    parent = str(p.parent)
    i = 1
    while True:
        cand = f"{parent}/{stem}_{i}{suffix}" if parent else f"{stem}_{i}{suffix}"
        if cand not in existing:
            return cand
        i += 1


existing = {"Docs/2026-09/a.pdf"}
print(unique_dest("Docs/2026-09/a.pdf", existing))   # Docs/2026-09/a_1.pdf
print(unique_dest("Docs/2026-09/new.pdf", existing))  # Docs/2026-09/new.pdf
```

**Three strategies**, selected by configuration:

| Strategy | Behaviour | Best for |
|----------|-----------|----------|
| `suffix` (default) | Append an index such as `a_1.pdf` | Most cases, preserving every file |
| `skip` | Leave the file in place | Conservative organising, avoiding duplicates |
| `overwrite` | Replace the existing target | When the source is definitely newer; requires confirmation |

## Crash Site: Misclassifying `.tar.gz` as a Single Suffix

Looking at only the final suffix makes `.tar.gz` land in the `gz` category when it semantically belongs with archives.

```python
from pathlib import Path

# WRONG: taking only the last suffix.
def category_wrong(ext_map, filename):
    return ext_map.get(Path(filename).suffix.lower())

ext_map = {".gz": "Gzip", ".tar": "Archives"}
print(category_wrong(ext_map, "data.tar.gz"))
# "Gzip" -- but semantically this is a tar archive.
```

```python
from pathlib import Path

# Correct: try the compound suffix first, then fall back to the single suffix.
COMPOUND = {".tar.gz", ".tar.bz2", ".tar.xz"}

def category_right(ext_map, filename):
    p = Path(filename)
    if len(p.suffixes) >= 2:
        compound = "".join(p.suffixes[-2:]).lower()
        if compound in COMPOUND and compound in ext_map:
            return ext_map[compound]
    return ext_map.get(p.suffix.lower())

ext_map2 = {".tar.gz": "Archives", ".gz": "Gzip", ".tar": "Archives"}
print(category_right(ext_map2, "data.tar.gz"))   # Archives
print(category_right(ext_map2, "data.gz"))       # Gzip
```

A rule engine must **declare compound suffixes explicitly**; guessing is not a strategy. That is precisely the benefit of "rules as data": policy lives in configuration, not scattered through the code.

## Crash Site: Date Archiving Fails When mtime Does Not Parse

`mtime` comes from Lesson 27's `datetime.fromtimestamp(...).isoformat()`, which has a fixed format. But an mtime string from elsewhere may not be standard, and `fromisoformat` will raise an error.

```python
from datetime import datetime

# WRONG: assuming mtime always follows the standard format.
def date_folder_wrong(mtime):
    return datetime.fromisoformat(mtime).strftime("%Y-%m")

print(date_folder_wrong("2026/09/20"))  # ValueError: Invalid isoformat string
```

```python
from datetime import datetime

# Correct: provide an explicit fallback; on parse failure, skip date archiving.
def date_folder_safe(mtime, fmt):
    try:
        return datetime.fromisoformat(mtime).strftime(fmt)
    except (ValueError, TypeError):
        return None   # The caller falls back to category/filename.

def plan_destination_safe(file_info, rules):
    category, _ = plan_destination(file_info, rules)  # Reuse the earlier logic.
    sub = date_folder_safe(file_info["mtime"], rules["date_format"])
    if sub is None:
        return category, f"{category}/{file_info['name']}"
    return category, f"{category}/{sub}/{file_info['name']}"

print(plan_destination_safe({"name":"x.jpg","ext":".jpg","size":100,"mtime":"bad"}, RULES))
# ('Images', 'Images/x.jpg') -- graceful degradation instead of a crash.
```

## Recap

- Make rules configurable: encode classification rules as data so you can reuse the tool without code changes.
- The Planner builds destinations as `category/date-subfolder/filename`.
- Date-based archiving applies the time knowledge from Chapters 1 and 2 to a real use case.
- Name collisions need an explicit strategy: `suffix`, `skip`, or `overwrite`.
- Compound suffixes such as `.tar.gz` need a declared mapping rather than guesswork.
- Parse failures should degrade gracefully; one bad field must not abort the whole organising run.
