# The os Module and System Information

> This lesson shows how to read environment variables, detect the current operating system, and run system commands from Python. You will learn the correct use of `os.environ` and understand why `os.system` has been replaced by `subprocess`.

## os.environ: Reading Environment Variables

`os.environ` is a dictionary-like object containing every environment variable the process inherited at startup.

```python
import os

# Read.
home = os.environ["HOME"]            # Raises KeyError when missing.
home = os.environ.get("HOME", "/tmp")  # Returns a default value instead.

# Write (affects only this process and its children; it never edits system config).
os.environ["MY_APP_DEBUG"] = "1"

# Check for presence.
if "JAVA_HOME" in os.environ:
    print("Java is configured:", os.environ["JAVA_HOME"])

# Remove.
os.environ.pop("MY_APP_DEBUG", None)
```

Any change to `os.environ` **only lives inside the current Python process**. When the program exits, the original environment comes back. Permanent changes require editing the system configuration instead.

## os.environ Is Not an Ordinary Dictionary

```python
import os

# WRONG: assigning None crashes immediately.
os.environ["KEY"] = None
```

The error:

```
TypeError: str expected, not NoneType
```

Every value in `os.environ` **must be a string**. Child processes inherit the modified environment, but the parent process—your shell—is not affected.

```python
import os
import subprocess

os.environ["GREETING"] = "Hello"
# The child process sees the new variable.
subprocess.run(["python3", "-c", "import os; print(os.environ['GREETING'])"])
# Output: Hello
```

## Detecting the Operating System: os.name and sys.platform

```python
import os
import sys

print(os.name)        # 'posix' (Linux/macOS/Unix) or 'nt' (Windows)
print(sys.platform)   # 'linux', 'darwin', 'win32', and so on (more detail).

if os.name == "nt":
    print("Windows paths use backslashes")
    config = os.path.expanduser("~\\AppData\\Local")
else:
    print("A Unix-like system")
    config = os.path.expanduser("~/.config")
```

| What you need to know | Recommended check | Example values |
|-----------------------|-------------------|----------------|
| Is this Windows? | `os.name == "nt"` | `"nt"` / `"posix"` |
| Exact system name | `sys.platform` | `"linux"` / `"darwin"` / `"win32"` |
| Running inside WSL? | `sys.platform == "linux"` plus a check of `/proc/version` | — |

## Crash Site: KeyError When the Variable Is Not Set

```python
import os

# WRONG: assuming the variable is always present.
db_url = os.environ["DATABASE_URL"]
# If it is unset, the program crashes here.
```

The error:

```
KeyError: 'DATABASE_URL'
```

Production code should always provide a default with `get`, or use a dedicated configuration library (`python-decouple`, `pydantic-settings`). At minimum, do this:

```python
import os

db_url = os.environ.get("DATABASE_URL")
if db_url is None:
    raise RuntimeError(
        "Environment variable DATABASE_URL is not set; "
        "configure it in .env or your shell environment"
    )
```

The error message should tell the user **what to set and where to set it**, not just expose a confusing `KeyError`.

## Crash Site: Everything Wrong with os.system

```python
import os

# WRONG: string concatenation, no captured output.
ret = os.system("ls -la")
print(ret)   # Returns the exit code, not the command output.
```

`os.system` has three serious flaws:

1. **No captured output**: the result goes straight to the terminal; you cannot store it in a variable.
2. **Shell parsing required**: spaces, quotes, and special characters break easily.
3. **No timeout**: if the command hangs, you simply wait.

The correct replacement is `subprocess.run` (covered in the next lesson):

```python
import subprocess

result = subprocess.run(
    ["ls", "-la"], capture_output=True, text=True
)
print(result.stdout)          # Standard output content.
print(result.returncode)      # Exit code.
```

## Hands-On: A Cross-Platform Application Directory

```python
import os
from pathlib import Path

def get_app_dir(app_name):
    """Return the appropriate application data directory for this OS."""
    if os.name == "nt":
        base = os.environ.get("APPDATA", str(Path.home()))
    else:
        base = os.environ.get("XDG_CONFIG_HOME", str(Path.home() / ".config"))
    app_dir = Path(base) / app_name
    app_dir.mkdir(parents=True, exist_ok=True)
    return app_dir

# Simulated call (no real directory is created here).
print(get_app_dir("myapp"))   # Returns a Path object.
```

On Linux and macOS, follow the XDG convention (`~/.config`); on Windows, use `%APPDATA%`. This is the standard pattern for cross-platform applications.

## Recap

- `os.environ` is a mapping-like object, and its values must be strings.
- Read variables with `os.environ.get(key, default)`; never use a bare subscript.
- `os.name` is coarse-grained (`nt`/`posix`); `sys.platform` is more specific (`linux`/`darwin`/`win32`).
- Changes to `os.environ` affect only the current process and its children.
- `os.system` cannot capture output, depends on the shell, and offers no timeout—it is obsolete; use `subprocess` instead.
- For cross-platform configuration: Windows reads `%APPDATA%`; Unix-like systems read `$XDG_CONFIG_HOME`.
