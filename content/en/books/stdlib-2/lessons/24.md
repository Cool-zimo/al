# glob and fnmatch: Filename Pattern Matching

> This lesson presents a pair of modules: `fnmatch` tests whether a single filename matches a shell-style pattern, while `glob` expands that pattern into a real file list. You will learn their syntax and how each one relates to `pathlib.glob`.

## fnmatch: Matching a Single Filename

`fnmatch.fnmatch(name, pattern)` reports whether a filename matches a pattern and returns a boolean.

```python
import fnmatch

print(fnmatch.fnmatch("main.py", "*.py"))        # True
print(fnmatch.fnmatch("data.tar.gz", "*.gz"))    # True
print(fnmatch.fnmatch("notes.TXT", "*.txt"))     # True (case-insensitive on Windows)
print(fnmatch.fnmatch("README.md", "*.py"))      # False
```

## The Four Wildcards in fnmatch

| Pattern | Meaning |
|---------|---------|
| `*` | Matches any number of characters, including zero |
| `?` | Matches exactly one character |
| `[abc]` | Matches one character: a, b, or c |
| `[!abc]` | Matches one character **not** in a, b, or c |

```python
import fnmatch

files = ["photo01.jpg", "photo02.jpg", "photo10.jpg", "doc.txt"]

# ? matches exactly one character.
print([f for f in files if fnmatch.fnmatch(f, "photo??.jpg")])
# ['photo01.jpg', 'photo02.jpg'] -- photo10 has two digits and does not match.

# [abc] is a character set.
print([f for f in files if fnmatch.fnmatch(f, "photo0[12].jpg")])
# ['photo01.jpg', 'photo02.jpg']
```

Notice that `?` matches **one** character only; for two digits you need `??`. That is the difference between `?` and `*`.

## glob: Expanding a Pattern into a File List

`glob.glob(pattern)` returns the list of matching path strings.

```python
import glob

# All .py files in the current directory.
py_files = glob.glob("*.py")

# Recursive search (Python 3.5+ supports **).
all_py = glob.glob("**/*.py", recursive=True)

# Multiple directory matches.
configs = glob.glob("config/*.yaml")
```

`recursive=True` is what makes `**` work; without it, `**` is treated as the literal characters `**`.

## fnmatch Versus glob Versus pathlib.glob

| Situation | Use |
|-----------|-----|
| Testing whether one known filename matches a pattern | `fnmatch.fnmatch` |
| Needing a real path list (filesystem operations) | `glob.glob` or `pathlib.Path.glob` |
| Needing object-oriented `Path` chaining | `pathlib.Path.glob` |
| Filtering a list of strings in memory | `fnmatch.fnmatch` (fastest, lightest) |

```python
import fnmatch
from pathlib import Path

# Lightweight filtering: plain strings, no filesystem access.
names = ["a.py", "b.py", "c.md"]
py_only = [n for n in names if fnmatch.fnmatch(n, "*.py")]

# Real file operations: you want Path objects.
py_paths = list(Path(".").glob("*.py"))
```

## Crash Site: Getting `[!...]` Wrong

```python
import fnmatch

files = ["a.txt", "b.txt", "_tmp.txt", ".gitignore"]

# WRONG: trying to exclude dotfiles with [!.], expecting it to match non-dots.
result = [f for f in files if fnmatch.fnmatch(f, "[!.]*.txt")]
print(result)
# ['a.txt', 'b.txt', '_tmp.txt'] -- .gitignore has no .txt suffix anyway.
```

The subtler trap is character-set syntax: `[!abc]` means "not abc", but `[^abc]` is **not** valid `fnmatch` syntax. That belongs to regular expressions.

```python
import fnmatch

# WRONG: regex syntax is not recognised by fnmatch.
fnmatch.fnmatch("a.txt", "[^.]*.txt")
# The pattern tries to match a literal "^" character.
```

```python
import fnmatch

# Correct: fnmatch uses ! for negation.
fnmatch.fnmatch("a.txt", "[!.]*")   # True
fnmatch.fnmatch(".git", "[!.]*")    # False
```

**Remember: `fnmatch` is shell-style, not regex.** `*`, `?`, and `[]` are `fnmatch` syntax; `.`, `^`, `$`, and `\d` are all treated literally.

## Crash Site: `**` Requires recursive=True

```python
import glob

# WRONG: you wanted every .py file recursively but forgot recursive.
all_py = glob.glob("**/*.py")
print(all_py)   # When there is no directory literally named **, the result may be [].
```

The result is empty (or at least far shorter than you expected):

```
[]
```

`glob.glob` defaults to `recursive=False`, so `**` does not mean "any depth". Enable it explicitly:

```python
import glob

# Correct.
all_py = glob.glob("**/*.py", recursive=True)
```

Compare this with `pathlib`: `Path.rglob("*.py")` is equivalent to `glob("**/*.py", recursive=True)` and saves you a parameter.

## Hands-On: Exclusion Patterns for a Backup List

```python
import fnmatch

def build_exclude_filter(patterns):
    """Receive a list of fnmatch patterns and return a filter function."""
    def should_exclude(name):
        return any(fnmatch.fnmatch(name, pat) for pat in patterns)
    return should_exclude

is_excluded = build_exclude_filter([
    "*.pyc", "__pycache__", ".git", "*.tmp", "node_modules",
])

files = ["main.py", "main.pyc", "__pycache__/x.py", ".git/config", "data.csv"]
kept = [f for f in files if not is_excluded(f)]
print(kept)   # ['main.py', 'data.csv']
```

This is the core of "exclude rules" in a backup tool. Filtering in memory with `fnmatch` is far faster than traversing the filesystem.

## Recap

- `fnmatch.fnmatch(name, pattern)` tests a single filename and returns a boolean.
- Wildcards: `*` for any number, `?` for one, `[abc]` for a set, `[!abc]` for the inverse set.
- **fnmatch is shell-style, not regex**: `*` is a wildcard, while `^`, `$`, and `\d` are literals.
- `glob.glob(pattern, recursive=True)` expands to a path list; `**` needs `recursive`.
- `pathlib.Path.rglob("*.py")` equals `glob("**/*.py", recursive=True)`.
- Use `fnmatch` for strings in memory and `glob` or `pathlib` for filesystem work.
