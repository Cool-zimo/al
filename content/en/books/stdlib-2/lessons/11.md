# os.path vs pathlib

> This lesson answers "how do I represent file paths in Python?" You will see why `pathlib` beats string concatenation, and the traps that catch even experienced developers using `os.path`.

## The old way: the traps of os.path

Before `pathlib`, everyone used `os.path`. The most common mistake was **concatenating paths by hand**:

```python
import os

base = "/home/alice/docs"
filename = "report.txt"

# manual concatenation
path = base + "/" + filename
print(path)   # /home/alice/docs/report.txt
```

That looks fine — until `base` already has a trailing slash:

```python
# WRONG: base already ends with /
base = "/home/alice/docs/"
path = base + "/" + filename
print(path)   # /home/alice/docs//report.txt <- double slash!
```

And then there is the Windows case — Windows uses `\` as a separator, so a hard-coded `/` breaks. Add `..`, `.`, and `~` into the mix and you are handling all of it by hand.

## pathlib: paths as objects

Python 3.4 introduced `pathlib`, which turns a path into an **object** and turns every operation into a method call:

```python
from pathlib import Path

p = Path("/home/alice/docs") / "report.txt"
print(p)   # /home/alice/docs/report.txt
```

The `/` operator **joins paths** — whether or not there is a trailing slash, and regardless of the operating system.

## Crash Site: hard-coded separators are not portable

```python
# WRONG: hard-coding the path separator
log_path = "C:\\Users\\" + username + "\\logs\\app.log"

# this does not work on Linux at all
# and on Windows, \\ is easy to get wrong
```

With `pathlib`, the same code runs everywhere:

```python
from pathlib import Path

home = Path.home()                      # automatically finds the current user's home
log_path = home / "logs" / "app.log"
print(log_path)
# Linux:   /home/alice/logs/app.log
# Windows: C:\Users\alice\logs\app.log
```

`Path.home()` detects the operating system and returns the correct home directory without you hard-coding anything.

## Crash Site: the readability disaster of chained os.path calls

```python
import os

# get the grandparent of a file
path = "/home/alice/docs/report.txt"
parent = os.path.dirname(path)               # /home/alice/docs
grandparent = os.path.dirname(parent)        # /home/alice

# want to go up two more levels? nest even more
great = os.path.dirname(os.path.dirname(path))  # /home/alice

# get the extension
ext = os.path.splitext(path)[1]       # .txt
name = os.path.basename(path)         # report.txt
stem = os.path.splitext(name)[0]     # report
```

The nesting gets deeper and deeper, and reading it becomes a tongue-twister.

**The `pathlib` version**:

```python
from pathlib import Path

p = Path("/home/alice/docs/report.txt")
print(p.parent)         # /home/alice/docs
print(p.parent.parent)  # /home/alice
print(p.suffix)         # .txt
print(p.name)           # report.txt
print(p.stem)           # report
```

Attributes chained together, immediately readable.

## pathlib vs os.path: a feature map

| Operation | os.path | pathlib |
|---|---|---|
| Join | `os.path.join(a, b)` | `a / b` |
| Filename | `os.path.basename(p)` | `p.name` |
| Extension | `os.path.splitext(p)[1]` | `p.suffix` |
| Parent | `os.path.dirname(p)` | `p.parent` |
| Exists? | `os.path.exists(p)` | `p.exists()` |
| Is a file? | `os.path.isfile(p)` | `p.is_file()` |
| Home directory | `os.path.expanduser("~")` | `Path.home()` |
| Current directory | `os.getcwd()` | `Path.cwd()` |

## Pure paths: PurePath

If you only need to **manipulate path strings** — for example, in an exercise where you should not touch the real file system — use `PurePath`. It does string arithmetic only and never checks whether a file exists.

```python
from pathlib import PurePath

p = PurePath("/home/alice/docs/report.txt")
print(p.name)      # report.txt
print(p.suffix)    # .txt
print(p.parent)    # /home/alice/docs
print(p.stem)      # report
```

The benefit of `PurePath`: **no file system needed**. It runs in any environment, including browser-based Python. That is why the exercises in this book use `PurePath`.

## Summary

- **Hand-joined paths are fragile**: inconsistent separators, no `..` handling, no portability
- `pathlib` uses `/` to join paths and handles separators and `.`/`..` automatically
- `pathlib` is object-oriented: `p.name`, `p.suffix`, `p.parent` read far better than nested `os.path` calls
- **For pure path arithmetic, use `PurePath`** — it needs no real file system
- It ships with Python 3.4+ in the standard library, so no installation is required
