# To Compress or Not to Compress

> This lesson covers a counterintuitive fact: many common files cannot be compressed further. You will see which formats are already compressed, which still have room, and what compression ratios are realistic.

## Already Compressed: Compression Is Futile

The following formats already use compression internally, so adding another layer of gzip or xz barely helps—and may even grow the file because the compression header takes space.

- Images: `jpg`/`jpeg`, `png`, `gif`, `webp`, `avif`
- Video: `mp4`, `mkv`, `avi`, `mov`, `flv`
- Audio: `mp3`, `aac`, `ogg`, `flac`
- Archives themselves: `zip`, `7z`, `rar`, an existing `.tar.gz`
- Compressed documents: `docx`, `xlsx`, `pptx` (which are zips internally)

```python
import zlib

data = b"\xff\xd8\xff" * 10_000     # Simulated already-compressed JPEG-like data.
compressed = zlib.compress(data, 9)
print(f"Original:   {len(data)} bytes")
print(f"Compressed: {len(compressed)} bytes")
print(f"Ratio:      {len(compressed)/len(data):.2%}")
# About 99%, so almost nothing was saved.
```

Already-compressed data has entropy close to its maximum; there is no redundancy left to remove.

## Still Compressible: Plain Text

Text files contain repeated characters and patterns, so compression works well:

- Source code (`.py`, `.js`, `.c`, `.java`)
- Logs (`.log`)
- CSV / JSON / XML / YAML
- Document sources (`.md`, `.tex`)
- Plain-text database exports

```python
import zlib

text = ("def hello():\n    print('Hello, world')\n" * 5_000).encode("utf-8")
compressed = zlib.compress(text, 9)
print(f"Original:   {len(text)} bytes")
print(f"Compressed: {len(compressed)} bytes")
print(f"Ratio:      {len(compressed)/len(text):.2%}")
# Around 5%, a very effective result.
```

The same algorithm on the same volume of text produces a striking contrast with the 99% result above.

## Realistic Expectations: Do Not Expect to Halve Everything

Compression ratios vary widely with content:

| Content type | Typical ratio |
|--------------|---------------|
| Plain text and source code | 10% to 30% |
| JSON or CSV with repetition | 5% to 20% |
| Mixed project directory | 30% to 60% |
| Already-compressed media (jpg/mp4/zip) | 95% to 105% |

**Compression ratio equals compressed size divided by original size.** A value of 0.3 means the result is 30% of the original; 0.95 means almost nothing was saved.

```python
import zipfile
import os

def estimate_ratio(original_size, compressed_size):
    """Return a human-readable ratio description."""
    if original_size == 0:
        return "N/A"
    ratio = compressed_size / original_size
    saved = (1 - ratio) * 100
    return f"Ratio {ratio:.1%}, saving {saved:.1f}% of space"
```

## Crash Site: Packing 100 JPEGs into tar.gz Changes Nothing

```python
import tarfile
import io
import os

# 100 JPEGs, 2MB each.
jpg_files = {f"photo_{i}.jpg": os.urandom(2_000_000) for i in range(100)}

buf = io.BytesIO()
with tarfile.open(fileobj=buf, mode="w:gz") as tf:
    for name, content in jpg_files.items():
        info = tarfile.TarInfo(name=name)
        info.size = len(content)
        tf.addfile(info, io.BytesIO(content))

raw = sum(len(v) for v in jpg_files.values())
compressed = buf.tell()
print(f"Original: {raw/1e6:.1f} MB")
print(f"Compressed: {compressed/1e6:.1f} MB")
print(f"Saved: {(1-compressed/raw)*100:.1f}%")
# Almost 0%, all effort for nothing.
```

You spent CPU time and waiting time for nearly zero savings. In this scenario, **tar without compression** (`.tar`) or zip with `ZIP_STORED` is enough and saves the compression step.

## Hands-On: A Smart Backup That Decides What Is Worth Compressing

```python
# Extensions already compressed; package them without compression.
ALREADY_COMPRESSED = {
    ".jpg", ".jpeg", ".png", ".gif", ".webp",
    ".mp4", ".mkv", ".avi", ".mov",
    ".mp3", ".aac", ".flac",
    ".zip", ".7z", ".rar", ".gz", ".bz2", ".xz",
    ".docx", ".xlsx", ".pptx",
}

# Text-like formats worth compressing aggressively.
TEXT_LIKE = {
    ".py", ".js", ".ts", ".java", ".c", ".cpp", ".go", ".rs",
    ".txt", ".csv", ".json", ".xml", ".yaml", ".yml", ".md", ".log",
}

def classify_for_backup(filename):
    """Decide whether a file should be stored or compressed in a backup."""
    ext = "." + filename.rsplit(".", 1)[-1].lower() if "." in filename else ""
    if ext in ALREADY_COMPRESSED:
        return "store"
    if ext in TEXT_LIKE:
        return "compress"
    return "try"   # Try compressing unknown formats.

print(classify_for_backup("report.docx"))   # store
print(classify_for_backup("main.py"))       # compress
print(classify_for_backup("data.bin"))      # try
```

Real backup tools such as `restic` and `borg` deduplicate and compress in blocks: they barely touch media files but compress text blocks aggressively.

## Crash Site: Confusing Two Ways of Reporting Ratios

There are two common ways to describe compression, and mixing them makes you misreport the savings.

```python
original = 1000
compressed = 250

ratio_v1 = compressed / original      # 0.25  -> "reduced to 25%"
ratio_v2 = 1 - compressed / original  # 0.75  -> "saved 75%"

# WRONG: calling 0.25 "only 25% saved"
print(f"Saved {ratio_v1*100}%")        # Saved 25% <- wrong; the real saving is 75%.
```

Those two numbers move in opposite directions. If you state them casually, you will embarrass yourself. `tarfile` and `zipfile` expose `compress_size / file_size`, which gives you **the first form**—the fraction remaining. What people say out loud ("saved 75%") is **the second form**.

```python
original = 1000
compressed = 250

to_ratio = compressed / original          # 0.25  -> reduced to 25%
saved_pct = (1 - compressed / original) * 100   # 75.0%  -> saved 75%

print(f"Ratio {to_ratio:.0%}, saved {saved_pct:.0f}%")
# Ratio 25%, saved 75%
```

Encode the rule in a function instead of calculating it by hand:

```python
def compression_report(original, compressed):
    if original == 0:
        return "Cannot calculate (original size is 0)"
    ratio = compressed / original
    saved = (1 - ratio) * 100
    return f"Ratio {ratio:.1%}, saved {saved:.1f}%"
```

Remember: **a number below 1 is the fraction remaining; subtract it to get the savings.**

## Recap

- `jpg`, `png`, `mp4`, `mp3`, `zip`, and `docx` are already compressed and will not shrink further.
- Plain text, source code, JSON/CSV, and logs still have 70% to 95% of their size to lose.
- Ratio equals compressed over original; real text lands around 10% to 30%, while media sits at 95% or more.
- For large batches of media, use plain `tar` (no compression) and save CPU time.
- A smart backup routes media to "store", text to "compress", and the rest to "try".
