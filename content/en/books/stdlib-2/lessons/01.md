# Why Time Is Hard

> This lesson answers "why time is one of the trickiest data types in programming." You will see why hand-rolling date math is a bad idea, and how deep the pitfalls of time zones, leap seconds, and daylight saving time really go.

## Hand-rolled date math: looks easy, fails everywhere

Suppose you are writing a program that needs to compute when a 30-day trial expires. The naive thought: take the year, month, and day, add 30 to the day, and you are done.

```python
year, month, day = 2026, 1, 15
day += 30
print(f"{year}-{month}-{day}")   # 2026-1-45  ?
```

The result is January 45 — clearly not a valid date. You might think: "fine, I will just detect overflow and carry into the next month." So you write:

```python
# A table of days per month
days_in_month = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

def add_days(year, month, day, n):
    day += n
    while day > days_in_month[month - 1]:
        day -= days_in_month[month - 1]
        month += 1
        if month > 12:
            month = 1
            year += 1
    return year, month, day
```

It seems to run. But what happens when you add one day to February 29, 2024? `days_in_month[1]` is 28, so your table does not account for leap years. The year 2024 **is** a leap year, so February has 29 days — yet your program will miscalculate. At this point you are probably already losing track of the correct answer yourself. That confusion **is** the problem.

## Crash Site: leap years break your birthday math

```python
# WRONG: hand-rolled leap-year check with the wrong condition
def is_leap(year):
    return year % 4 == 0   # forgot the "100 but not 400" rule

print(is_leap(1900))   # True? WRONG! 1900 is NOT a leap year
```

The year 1900 is divisible by 4, but it is also a multiple of 100 **and not** a multiple of 400, so it is **not** a leap year. The correct test is:

```python
def is_leap(year):
    return (year % 4 == 0 and year % 100 != 0) or (year % 400 == 0)

print(is_leap(1900))  # False  ✓
print(is_leap(2000))  # True   ✓
print(is_leap(2024))  # True   ✓
```

This is just the tip of the iceberg. Working with time also means dealing with:

| Pitfall | What goes wrong |
|---|---|
| Time zones | London is UTC+0 in winter but BST in summer; offsets shift twice a year |
| Leap seconds | Earth's rotation is irregular, so a second is occasionally inserted |
| Daylight saving | In spring an hour "vanishes"; in autumn an hour "appears" |
| Calendar systems | Saudi Arabia uses the Hijri calendar; Japan has era names |
| Date formats | The US writes 09/27/2026 (month/day/year); most of Europe writes 2026-09-27 |

## Crash Site: date strings mean different things in different regions

Alice receives a file from a colleague in the United States:

```python
# WRONG: parsing an American date using a local assumption
date_str = "03/04/2026"
month, day, year = date_str.split("/")
print(f"year: {year}, month: {month}, day: {day}")
```

The output is `year: 2026, month: 03, day: 04`. Alice assumes this is March 4, 2026. But wait — in the US the format is month/day/year, so this **is** March 4. However, if Alice's application is configured for a British user who writes day/month/year, the very same string would mean April 3, 2026. One string, two completely different dates.

**The real solution**: use the standard library's date-handling modules. Hand the format-parsing job to code that already knows the rules — do not slice strings yourself.

## The standard library's three tools

Python ships with three main tools for dealing with time. We will cover each of them in depth in this volume:

| Module | What it handles | Typical use |
|---|---|---|
| `datetime` | dates, times, deltas, time zones | computing expiry dates, formatting output |
| `time` | timestamps, timing, sleeping | performance tests, delays |
| `pathlib` / `os` | file systems, paths | walking directories, reading file attributes |

This lesson builds intuition; the next few lessons dive into each one.

## An intuitive example: the distance between two dates

```python
from datetime import date

today = date(2026, 9, 27)
launch = date(2026, 12, 25)
delta = launch - today
print(f"Christmas is {delta.days} days away")
```

Output:

```
Christmas is 89 days away
```

Notice that we did not manually compute "December 25 minus September 27." The `date` object already knows how many days each month has — you just subtract. The type of `delta` is `timedelta`, which we cover properly in lesson 03.

## Summary

- The hard parts of time: leap-year rules, time zones, DST, and wildly different local formats
- **Never hand-write date arithmetic** — use the standard library's `datetime`
- Leap year test: `(year % 4 == 0 and year % 100 != 0) or (year % 400 == 0)`
- Date formats vary by region: US `MM/DD/YYYY`, ISO `YYYY-MM-DD`
- Subtracting two `datetime.date` objects gives you a `timedelta`, with month lengths handled automatically
