# Temporary Files and Directories

> This lesson explains why you should never write `open("/tmp/scratch", "w")` yourself: concurrent collisions, permission leaks, and forgotten cleanup are all waiting. You will learn `TemporaryFile`, `NamedTemporaryFile`, `mkdtemp`, and the classic `delete` trap.

## Why tempfile Exists

Managing temporary files by hand creates three problems:

1. **Name collisions**: two processes writing `/tmp/cache.txt` overwrite each other.
2. **Permission issues**: a raw `os.open` call may expose sensitive data to other users.
3. **Forgotten cleanup**: a crash or a missed `unlink` leaves stale files behind.

The `tempfile` module solves all three: names are unique, permissions are tightened to `0o600`, and eligible objects clean themselves up on exit.

## TemporaryFile: Anonymous Temporary Storage

```python
import tempfile

with tempfile.TemporaryFile(mode="w+t", encoding="utf-8") as f:
    f.write("intermediate calculation\n")
    f.seek(0)                    # After writing, rewind before reading.
    print(f.read())

# On leaving the with block, the file disappears. It does not even need a name.
```

On most platforms, `TemporaryFile` is **anonymous** (it has no directory entry). Once it is closed, it is gone—no name, no trace. That makes it the safest option.

## NamedTemporaryFile: When You Need a Real Path

Some libraries accept only a file path string, not a file object. A SQLite handle wants a database path; an external command wants a filename. `NamedTemporaryFile` exists for these cases.

```python
import tempfile

with tempfile.NamedTemporaryFile(
    mode="w+t", suffix=".csv", delete=False
) as f:
    f.write("name,age\nAlice,25\n")
    path = f.name                # Grab the real path string.
    print(f"File lives at: {path}")

# An external program can now operate on that path.
# When you are done, call os.unlink(path) yourself.
```

You can set `suffix`, `prefix`, and `dir`. The generated name looks like `/tmp/tmp3k9x....csv`.

## mkdtemp: A Temporary Directory

When you need a directory full of intermediate files, reach for `mkdtemp`. **It never cleans itself up**, so you must do it.

```python
import tempfile
import os
import shutil

tmpdir = tempfile.mkdtemp(prefix="myapp_")
try:
    # Work freely inside tmpdir.
    with open(os.path.join(tmpdir, "step1.txt"), "w") as f:
        f.write("intermediate result")
    # ...more processing...
finally:
    shutil.rmtree(tmpdir)        # Your responsibility.
```

The `try/finally` pattern guarantees cleanup under every exit path. That is the standard way to use `mkdtemp`.

## Crash Site: The `delete` Trap in NamedTemporaryFile

This is the classic pitfall. By default, `delete=True`, so the file **vanishes the moment the context ends**—even when you still need its name.

```python
import tempfile

# WRONG: delete=True (the default) removes the file on exit.
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt") as f:
    f.write("data")
    path = f.name

import os
os.path.exists(path)     # False! The file is already gone.
```

A more subtle version: you try to read the same file from inside the `with` block.

```python
import tempfile

# WRONG: on Windows a file cannot be opened twice for writing and reading.
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt") as f:
    f.write("hello")
    f.flush()
    # Now you want another handle to the same file.
    with open(f.name, "r") as reader:   # Windows: PermissionError
        print(reader.read())
```

Windows does not allow the same file to be shared this way. The portable solution is `delete=False` plus a manual unlink:

```python
import tempfile
import os

with tempfile.NamedTemporaryFile(
    mode="w+t", suffix=".txt", delete=False
) as f:
    f.write("hello")
    path = f.name

try:
    with open(path, "r") as reader:
        print(reader.read())      # hello
finally:
    os.unlink(path)               # Clean up by hand.
```

## Crash Site: mkdtemp Does Not Clean Up for You

```python
import tempfile
import os

# WRONG: you walk away and forget to delete anything.
def process_data():
    tmp = tempfile.mkdtemp()
    # A lot of intermediate files end up inside tmp.
    return do_work(tmp)

# After the function returns, the contents of tmp remain on disk forever,
# and a long-running program will slowly fill up /tmp.
```

The correct pattern is always `try/finally`:

```python
import shutil
import tempfile

def process_data():
    tmp = tempfile.mkdtemp()
    try:
        return do_work(tmp)
    finally:
        shutil.rmtree(tmp)        # Cleanup runs no matter what.
```

## Hands-On: A Safe Place for Intermediate Reports

```python
import tempfile
import os
import hashlib

def write_temp_report(records):
    """Write a batch of records to a temporary CSV and return the path.
    The caller is responsible for deleting it."""
    with tempfile.NamedTemporaryFile(
        mode="w+t", suffix=".csv", delete=False
    ) as f:
        f.write("id,value\n")
        for r in records:
            f.write(f"{r['id']},{r['value']}\n")
        return f.name

# Simulated use (no real disk writes).
records = [{"id": 1, "value": "London"}, {"id": 2, "value": "Edinburgh"}]
path = write_temp_report(records)
print(f"Temporary report: {path}")      # Something like /tmp/tmp_xxx.csv
# When the caller is done: os.unlink(path)
```

In production, add a `hashlib` checksum so you can confirm the intermediate data was not corrupted.

## Recap

- `tempfile` removes naming collisions, permission mistakes, and cleanup bugs.
- `TemporaryFile` is anonymous, safest, and disappears on close.
- `NamedTemporaryFile` has a real name for APIs that require a path string.
- **`NamedTemporaryFile` defaults to `delete=True`**, so cross-platform reuse needs `delete=False` and a manual `unlink`.
- `mkdtemp` creates a temporary directory but **never cleans up**, so use `try/finally` with `rmtree`.
- A useful rule of thumb: anonymous work uses `TemporaryFile`; an external API needs `NamedTemporaryFile(delete=False)`; a batch of files needs `mkdtemp` plus `try/finally`.
