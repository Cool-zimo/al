# Reading and Writing Files the Right Way

> This lesson answers one question: how do you read and write files safely? You will understand why `with` is mandatory, how the four modes `r / w / a / x` differ, and which trade-offs matter when choosing between `read`, `readline`, `readlines`, and line iteration.

## The `with` Statement: The Only Acceptable Way to Open Files

When you open a file with `open()`, **you must close it**. Otherwise you leak file descriptors and you may also lose data, because buffered output never reaches the disk.

```python
# Correct: `with` closes the file for you.
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
# At this point the file is already closed, even if an exception occurred.
```

A `with` block implements the **context manager protocol**. On entry it calls `__enter__`; on exit—even when an exception is raised—it calls `__exit__`, and that method calls `f.close()`.

```python
# WRONG: you forgot to close, or you merely hope the code reaches the end.
f = open("data.txt", "r", encoding="utf-8")
content = f.read()
# If the previous line raises an exception, close() is never called
# and the file descriptor leaks.
```

In a long-running service, forgetting to close files will eventually exhaust the process limit and you will see `OSError: [Errno 24] Too many open files`.

## Four Modes: `r` / `w` / `a` / `x`

| Mode | Meaning | File missing | File exists |
|------|---------|--------------|-------------|
| `r` | Read only (the default) | Raises `FileNotFoundError` | Opens normally |
| `w` | Write (overwrite) | Creates a new file | **Truncates the existing content** |
| `a` | Append | Creates a new file | Writes at the end, keeps existing content |
| `x` | Exclusive creation | Creates a new file | **Raises `FileExistsError`** |

```python
# Mode w truncates before you write anything.
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("first line\n")

# Mode a appends, so the original content stays intact.
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("second line\n")
```

## Crash Site: `w` Empties the File You Meant to Read

This is one of the most painful mistakes: you intend to read a file but type `w`, and the contents vanish instantly.

```python
# WRONG: you meant to read, but opened with "w".
f = open("important_data.txt", "w", encoding="utf-8")
# The file is already truncated to 0 bytes!
data = f.read()   # io.UnsupportedOperation: not readable
```

The actual error:

```
io.UnsupportedOperation: not readable
```

Your open mode must match your intent: `r` for reading, `w` for writing. Moreover, mode `w` truncates the moment `open()` succeeds, so **misusing `w` causes irreversible data loss**.

The correct version:

```python
# Correct: use r for reading.
with open("important_data.txt", "r", encoding="utf-8") as f:
    data = f.read()
```

## Crash Site: `x` Raises When the File Exists—And That Is Exactly What You Want

```python
# WRONG: you used w and silently overwrote the user's configuration.
with open("config.ini", "w", encoding="utf-8") as f:
    f.write("new settings...")
# User: ??? where did my original configuration go?
```

If you want to create a file only when it does not exist, and never overwrite, use `x`:

```python
# Correct: create only when the file is missing.
try:
    with open("config.ini", "x", encoding="utf-8") as f:
        f.write("initial settings\n")
    print("Created")
except FileExistsError:
    print("Configuration already exists, skipping initialization")
```

The `x` mode is exclusive creation—the POSIX equivalent of `O_CREAT | O_EXCL`. It is atomic, so two competing processes will not overwrite each other.

## Three Ways to Read

```python
# 1. read(): load the entire content into one string.
with open("data.txt", "r", encoding="utf-8") as f:
    all_text = f.read()

# 2. readline(): read one line at a time, newline included.
with open("data.txt", "r", encoding="utf-8") as f:
    first = f.readline()
    second = f.readline()

# 3. readlines(): read every line into a list.
with open("data.txt", "r", encoding="utf-8") as f:
    lines = f.readline()  # Forgot the s; this reads only the first line.
```

Both `read()` and `readlines()` load the whole file into memory. A 5 GB log file will blow up your memory footprint if you call `read()`.

## Big Files Require Line-by-Line Iteration

A file object is itself iterable and yields one line at a time, so **memory use stays constant**:

```python
with open("huge.log", "r", encoding="utf-8") as f:
    for line in f:           # Only one line lives in memory at a time.
        if "ERROR" in line:
            print(line.rstrip())
```

| Method | Memory use | Best for |
|--------|------------|----------|
| `f.read()` | O(file size) | Small files, whole-content processing |
| `f.readlines()` | O(file size) | When you need random access by line number |
| `for line in f` | O(1) per line | Large files and streaming pipelines |

## Hands-On: Count Errors in a Log

```python
def count_errors(log_text):
    """Receive a multi-line string (simulated file content)
    and count lines that contain ERROR."""
    count = 0
    for line in log_text.splitlines():   # Process line by line in memory.
        if "ERROR" in line:
            count += 1
    return count

text = """INFO  service started
ERROR database connection failed
INFO  retrying
ERROR disk is full
"""
print(count_errors(text))   # 2
```

In a real program, replace the simulated string with `for line in f`. The key habit is **processing large files line by line**.

## Recap

- Always open files with `with`; never write `close()` by hand.
- `r` reads, `w` truncates and writes, `a` appends, `x` creates exclusively.
- **`w` truncates immediately**, and the mistake cannot be undone.
- `read()` and `readlines()` load everything at once; use `for line in f` for big files.
- A file object is iterable, so line-by-line processing has constant memory cost.
