# Execution and Undo: Making the Tool Trustworthy

> Generating a plan is only paper. Moving files is where the value—and the risk—appears. This lesson explains why undo is the dividing line between a professional tool and a throwaway script.

## Executor: Log First, Execute Second

Lesson 26 established the rule: **log first, then execute**. The log is a JSON file recording every `source → destination` mapping and a timestamp. It is the only basis for undo and the source of the tool's reliability.

```python
import json
import shutil
from datetime import datetime
from pathlib import Path


class Executor:
    def __init__(self, root, log_dir):
        self.root = Path(root)
        self.log_dir = Path(log_dir)
        self.log_dir.mkdir(parents=True, exist_ok=True)

    def apply(self, plan):
        """plan: {dest_rel: src_abs}. Write the log before executing,
        then move files one by one. Return (success_count, failures, run_id)."""
        run_id = datetime.now().strftime("%Y%m%d_%H%M%S_%f")
        log_file = self.log_dir / f"ops_{run_id}.json"

        # 1) Persist the complete plan first (the core rule: log before acting).
        log = {
            "run_id": run_id,
            "timestamp": datetime.now().isoformat(),
            "root": str(self.root),
            "operations": [
                {"src": src, "dest": str(self.root / dest), "status": "pending"}
                for dest, src in plan.items()
            ],
        }
        log_file.write_text(json.dumps(log, ensure_ascii=False, indent=2), encoding="utf-8")

        # 2) Execute one operation at a time, updating status as you go.
        ok, failed = 0, []
        for op in log["operations"]:
            try:
                d = Path(op["dest"])
                d.parent.mkdir(parents=True, exist_ok=True)
                shutil.move(op["src"], op["dest"])
                op["status"] = "done"
                ok += 1
            except OSError as e:
                op["status"] = "failed"
                op["error"] = str(e)
                failed.append(op["src"])

        # 3) Rewrite the status.
        log_file.write_text(json.dumps(log, ensure_ascii=False, indent=2), encoding="utf-8")
        return ok, failed, run_id

    def undo(self, run_id=None):
        """Reverse one execution: read the log and replay the moves in reverse.
        Without a run_id, undo the most recent run."""
        log_file = self._pick_log(run_id)
        log = json.loads(log_file.read_text(encoding="utf-8"))

        undone, failed = 0, []
        for op in reversed(log["operations"]):        # Reverse order avoids parent-dir issues.
            if op["status"] != "done":
                continue
            try:
                src = Path(op["dest"])
                dest = Path(op["src"])
                if src.exists():
                    dest.parent.mkdir(parents=True, exist_ok=True)
                    shutil.move(str(src), str(dest))
                    undone += 1
            except OSError as e:
                failed.append(op["dest"])
        return undone, failed

    def _pick_log(self, run_id):
        if run_id:
            return self.log_dir / f"ops_{run_id}.json"
        # Pick the newest log.
        logs = sorted(self.log_dir.glob("ops_*.json"))
        if not logs:
            raise FileNotFoundError("No reversible operation record found")
        return logs[-1]
```

**Why log first:** even if execution crashes halfway, every entry in the log carries a `status`. After a restart you can still tell which files moved and which did not; just follow the log backwards.

**Why undo walks in reverse:** the last file moved may live inside a directory created by an earlier move. Reversing the order avoids the awkward case where the parent directory has already been moved out from under you.

## Hands-On: Preview → Execute → Undo

```python
# A simulated plan (in reality this comes from Lesson 28's plan_all).
plan = {
    "Docs/2026-09/a.pdf": "/d/a.pdf",
    "Images/2026-09/b.jpg": "/d/b.jpg",
}

ex = Executor("/d", "/d/.organize_logs")

# Preview (print only, no file changes).
print(f"[Preview] Will move {len(plan)} files")
for dest, src in plan.items():
    print(f"  {src}  ->  {dest}")

# Execute.
ok, failed, run_id = ex.apply(plan)
print(f"✓ Done: {ok} files, {len(failed)} failed, run_id={run_id}")

# Undo.
undone, errs = ex.undo(run_id)
print(f"✓ Reversed {undone} moves")
```

## Crash Site: Overwriting Without Checking Leaves No Escape

Without checking whether the destination exists, `shutil.move` may **silently overwrite** it on Unix, and the original file disappears.

```python
import shutil

# WRONG: overwriting the destination when it already exists.
def apply_wrong(plan):
    for dest, src in plan.items():
        shutil.move(src, dest)   # If dest exists, the source is overwritten and lost.

plan = {"Docs/a.pdf": "/d/a.pdf"}
# /d/Docs/a.pdf had content -> replaced by /d/a.pdf. The original is gone forever.
```

```python
import shutil
from pathlib import Path

# Correct: check destination existence before acting; apply the conflict policy.
def move_safe(src, dest, conflict="suffix"):
    d = Path(dest)
    if d.exists():
        if conflict == "skip":
            return False, "skip"
        if conflict == "suffix":
            stem, suffix = d.stem, d.suffix
            i = 1
            while d.exists():
                d = d.with_name(f"{stem}_{i}{suffix}")
                i += 1
        # overwrite proceeds straight to shutil.move; require explicit confirmation.
    d.parent.mkdir(parents=True, exist_ok=True)
    shutil.move(src, str(d))
    return True, str(d)

print(move_safe("/d/a.pdf", "/d/Docs/a.pdf"))     # (True, '/d/Docs/a.pdf')
print(move_safe("/d/b.pdf", "/d/Docs/a.pdf"))     # (True, '/d/Docs/a_1.pdf')
```

The conflict policy lives in the configuration; the executor merely applies it. This also explains **why the Planner must produce unique destination names first**—resolving conflicts before execution keeps the executor's job to pure "moving".

## Crash Site: Undo Reads the Wrong Log and Reverses the Wrong Batch

A log directory may contain many records. Picking the wrong file either reverses the wrong operation or cannot find the target.

```python
from pathlib import Path

# WRONG: hardcoding one log filename.
def undo_wrong(log_dir):
    log = json.loads((Path(log_dir) / "ops.json").read_text())
    # If ops_1.json and ops_2.json exist, this always touches ops.json, which
    # may not exist or may be out of date.

# Correct: respect run_id; default to the newest record.
def pick_log(log_dir, run_id=None):
    d = Path(log_dir)
    if run_id:
        target = d / f"ops_{run_id}.json"
        if not target.exists():
            raise FileNotFoundError(f"No operation record for run_id={run_id}")
        return target
    logs = sorted(d.glob("ops_*.json"))
    if not logs:
        raise FileNotFoundError("No reversible operation record found")
    return logs[-1]   # The most recent one.

print(pick_log("/d/.organize_logs"))
# /d/.organize_logs/ops_20260928_150000_123456.json
```

**This is what separates a professional tool from a script:** explicit `run_id`, a clear error when the log is missing, and no silent wrong action.

## Recap

- Execution order: **log first, move files one by one, update each status in place.**
- The log is the only basis for undo, and it remains useful even after a crash.
- Undo walks the operation list **in reverse** to avoid parent-directory dependencies.
- Always check whether the destination exists; resolve conflicts with a policy decided by the Planner.
- An explicit `run_id` and a clear error when the log is missing are hallmarks of a professional tool.
