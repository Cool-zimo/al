# 22 Project questions

> Use one to close a chapter and tie everything together.

## How it differs from local

`project` is also open-ended and self-checked, but it ships **starter code** and is usually **pure logic the browser can run**.

`local` means "you have to run this locally". `project` means "here is a start, build on it".

## The syntax

```
type: project
q: Build a contacts app: create, read, update, delete, and save to a file
starter: |
  contacts = {}

  def add(name, phone):
      contacts[name] = phone
checklist: |
  - Can add a contact
  - Can look one up by name
  - Data survives a restart
```

## Where to put it

The **last question of a chapter test**, or the final lesson of a chapter.

Not in every lesson — a project takes real time, and one per lesson is too many.

## Make the starter half-finished

A good starter gives the **skeleton and part of the implementation**:

```
contacts = {}

def add(name, phone):
    contacts[name] = phone

def find(name):
    # fill this in
    pass

def delete(name):
    # fill this in
    pass
```

Far friendlier than an empty file.

## Split the checklist by feature

```
- Can add a contact
- Can look up by name
- Can delete a contact
- Data survives a restart
```

One feature per line, so the reader ticks as they go and feels progress.

## Recap

- `project` gives starter code plus a checklist
- Put it at the end of a chapter test or chapter
- Make the starter half-finished
- One checklist item per feature
