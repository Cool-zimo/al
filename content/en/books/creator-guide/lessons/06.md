# 06 Markdown in five minutes

> Writing lessons needs only a small slice of Markdown.

## All you need

| Syntax | Result |
|---|---|
| `# Heading` | level-1 heading (lesson title) |
| `## Subheading` | level-2 heading |
| `**bold**` | bold |
| `> quote` | blockquote (intros, emphasis) |
| single backticks | inline code |
| `- item` | bullet list |
| `1. item` | numbered list |
| `[text](url)` | link |

That is it. Tables, footnotes, task lists — you will not need them.

## Code blocks: tagged vs untagged

**Tagged** with a language, the reader can run it:

```python
print("hello")
```

**Untagged**, it is for output or illustration:

```
hello
```

This distinction matters: a block tagged `python` really runs in the browser (Pyodide); an untagged one is just text.

So to show "what does this print", use **two blocks** — the tagged code, then an untagged one with the output.

## Do not put output in the same block

The classic beginner mistake is stuffing code and output into one `python` block. Running it then fails, because the output is not valid code.

## Recap

- Headings, bold, lists, code blocks — that is enough
- Only tagged blocks can run
- Output goes in a separate untagged block

## In-class exercise

```quiz
type: choice
answer: 0
q: How do you make a code block runnable?
options:
- Tag it with python
- Leave it untagged
- Indent it four spaces
- Wrap it in a blockquote
hint: The language tag decides
explain: Blocks tagged python, js, html or css are wired to a runner.
```

- Everything in one python block
