# 26 Reading the review report

> Click it before publishing and save yourself an embarrassing release.

## What is in it

Click "Review report" in the editor and a full validation runs:

```
3 errors
  [en] 07.md: choice answer=4 out of range (4 options)
  [en] 12.md: in cases, "1 2 -> 3" args must be comma-separated
  albook.json is missing required field: desc

5 warnings
  [en] 03.md: only 42 lines, might be placeholder content
  [en] lesson numbers not continuous, missing 08, 09

Stats: 30 lessons · 6 chapter tests · 138 questions
```

## Errors vs warnings

| | Consequence |
|---|---|
| **Error** | cannot publish until fixed |
| **Warning** | publishes, but usually means something is wrong |

A warning is not a reason to shrug. "Only 42 lines, might be placeholder content" usually means that lesson genuinely is not finished.

## Common errors and their causes

| Message | Fix |
|---|---|
| `answer out of range` | you miscounted; indices start at 0 |
| `args must be comma-separated` | change `1 2 -> 3` to `1, 2 -> 3` |
| `func not defined in starter` | `func` and the `def` name disagree |
| `toc declares X.md but it is missing` | missing file, or a typo in the name |
| `question counts differ between languages` | the two sides have different numbers |
| `quiz block not closed` | no closing fence on its own line |

## Watch the stats line

```
30 lessons · 6 chapter tests · 138 questions
```

If the question count is well below what you expect, some quiz blocks **failed to parse** — almost always a fence problem.

## Recap

- Errors must be fixed; warnings deserve a look
- A short question count means check your fences
- Run it before publishing
