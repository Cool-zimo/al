# 23 hint and explain

> These two decide whether a stuck reader gives up or keeps going.

## hint: a glance when stuck

`hint` is hidden until the reader clicks "Hint".

Good hints:

```
hint: What type does len() return?
hint: Use n % 2 == 0
```

Bad ones:

```
hint: Think harder              says nothing
hint: The answer is return a + b   gives it away, so nobody thinks
hint: See page 37               the reader does not have the book
```

**A hint moves the reader from "no idea" to "some idea". It is not the answer.**

## explain: shown after answering

`explain` appears once the reader answers, right or wrong.

Its job is to say **why**, not just what:

```
explain: Lists are mutable, so changing one inside a function affects the caller. Pass list(x) if you want a copy.
```

Far more valuable than `explain: The answer is [1, 2, 3]`.

## Getting it wrong should still teach something

`explain` shows on wrong answers too. Write it asking: **if they got it wrong, will this line tell them why?**

```
explain: randint(1, 6) is inclusive at both ends; randrange(1, 6) never returns 6.
```

That is the kind of explain that earns its keep on a wrong answer.

## When you must write one

- counter-intuitive traps (`0.1 + 0.2`, `randrange` bounds)
- several valid approaches and you want to say why this one
- a wrong answer is common and you want to head it off

Not every question needs one, but **any question with a trap does**.

## Recap

- hint gives direction, not the answer
- explain says why
- Trappy questions need an explain
