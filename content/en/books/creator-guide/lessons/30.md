# 30 After you publish

> Shipping is not the end. It is the start.

## Updating content

Edit in the developer platform, then publish again — it pushes to the same repo.

Or edit straight on GitHub. Because content is read from your repo, **readers see the new version immediately**.

## Drafts and publishing are separate things

```
draft      in your private al-drafts repo, edit freely, nobody sees it
published  pushed to a public repo, listed in the library
```

Drafts auto-save (3 seconds after you stop typing) and can be pulled on another device. So experiment freely; if it goes wrong, just do not publish.

## Be careful renaming files

Renaming a chapter test (`test-01` → `quiz-01`) deletes the old file on the next push, so no orphans pile up.

But an **already published public repo is not cleaned up automatically**. If tidy repos matter to you, delete the stale file on GitHub by hand.

## Collect feedback

Every book in the library carries the author name and license. Readers who spot a problem will look for you — put a contact line in the README.

## When to start a new book

Once one book passes about 40 lessons, consider splitting. A book of roughly 30 lessons is much easier for a reader to finish.

## Finally

The hard part of writing a textbook is not the format — this book covered that. The hard part is working out **where the reader gets stuck**, and putting an example, a warning or a question exactly there.

That only comes from reading feedback, watching the data, and revising.

Happy writing.

## Recap

- Edit and publish again, or edit on GitHub
- Drafts are private, published is public — separate
- Content is read live
- Feedback matters more than format
