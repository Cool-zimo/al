# 02 albook.json: the book identity card

> Get this file wrong and the book never ships.

## The smallest thing that works

```
{
  "format": "al-book",
  "id": "my-first-book",
  "title": "My First Book",
  "subtitle": "Who it is for and what it covers",
  "desc": "Two or three sentences on where this book sits.",
  "stage": "Basics",
  "level": "Beginner",
  "langs": ["en"],
  "license": "CC BY-NC 4.0",
  "author": { "name": "Your Name" }
}
```

## What each field does

| Field | Purpose | If missing |
|---|---|---|
| `format` | **must be exactly** `al-book` | not listed at all |
| `id` | unique identifier for the book | validation error |
| `title` / `subtitle` / `desc` | the three lines shown in the library | validation error |
| `stage` | category | validation error |
| `level` | difficulty, free text such as "Beginner" | validation error |
| `langs` | `["en"]`, `["zh"]`, or `["zh","en"]` | validation error |
| `license` | license name | validation error |
| `author.name` | author name | validation error |

## format must be exact

All of these are **silently skipped**:

```
"format": "albook"      no
"format": "AL-BOOK"     no
"format": "al-book "    no (trailing space)
```

Only the single string `al-book` passes. That is deliberate: better to under-collect than to collect garbage.

## id rules

```
"id": "my-first-book"     yes
"id": "MyFirstBook"       no capitals
"id": "my_first_book"     no underscores
"id": "-mybook"           no leading hyphen
```

The id becomes part of the book's address on the site, so it has to be safe inside a URL.

## Optional but useful

```
"tags": ["Python", "Beginner"],
"kind": "textbook",
"homepage": "https://example.com"
```

`kind` gets a whole lesson later — it decides whether your book **must have questions**.

## Recap

- `format` is exactly `al-book`
- eight required fields, none optional
- `id` allows only lowercase letters, digits and hyphens
- `author` is an object and needs at least `name`
