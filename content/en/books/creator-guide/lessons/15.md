# 15 Putting code in the question text

> Use the code: field, never a fence.

## Why the field exists

Many questions ask "what does this print" or "what is wrong here". The instinctive move is to type a fence in the question text:

```
type: choice
q: What does this print?
```
  print(1 + 1)
```
options:
- 1
- 2
answer: 1
```

**That is wrong.** The parser hits the fence in the middle of the question text and treats it as the end of the block, so `options` and `answer` are never read.

On screen you get a **choice question with no options**. The reader can only stare at it.

## Do this instead: the code field

```
type: choice
q: What does this print?
code: |
  print(1 + 1)
options:
- 1
- 2
answer: 1
```

`code:` is a multi-line block shown **read-only** below the question text. It is never executed and never confuses the parser.

## Mind the indentation

```
code: |
  def f(x):
      return x * 2
```

Two spaces is the block indent; the function body indents two more — four spaces total. Get it wrong and the code renders a mess.

## One snippet per question

`code:` holds one snippet. To compare two pieces of code, describe them in `q:` or split into two questions.

## Recap

- Always use `code:` for code in the question text
- A fence there loses every later field
- Watch the indentation inside multi-line blocks
