# 19 Code questions: running a whole snippet

> For print and control flow — graded with assert.

## How it differs from function questions

| | Function | Code |
|---|---|---|
| What it tests | one function's return value | the output or side effects of a snippet |
| Grading | compare return values | `assert` statements |

Code questions suit things a return value cannot express: what gets printed, how many times a loop ran.

## The syntax

```
type: code
q: Print 1 to 5, one per line
starter: |
  for i in range(1, 6):
      print(i)
tests: |
  assert __out.count("1") == 1
  assert "5" in __out
hint: __out holds the complete output
```

## What is __out

`__out` is the snippet's **complete standard output**, as one string.

So assertions can be:

```
assert "5" in __out                      5 appears
assert len(__out.strip().split("\n")) == 5    five lines
assert __out.count("1") == 1             1 appears once
```

## Be lenient in assertions

Readers write things in wildly different ways, so output can differ in small details:

```
assert "5" in __out            good, lenient
assert __out == "1\n2\n3"      bad, strict (a trailing newline breaks it)
```

**Use `in` and `count`, not `==`.**

## Do not forget to check "did nothing"

As with function questions: does submitting starter unchanged pass? If starter already prints the right thing, the question is pointless.

## Recap

- `tests:` holds asserts
- `__out` is the full output string
- Prefer `in` / `count` over `==`
- starter runs but produces the wrong result

## In-class exercise

```quiz
type: function
func: triple
q: Write triple(n) returning three times n
starter: |
  def triple(n):
      return 0
cases: |
  2 -> 6
  0 -> 0
  -4 -> -12
hint: n times three
explain: Return the parameter multiplied by three.
```
