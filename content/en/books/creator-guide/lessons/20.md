# 20 The three web types: HTML, CSS, JS

> They grade the effect, not what the code looks like.

## The three

| Type | What is graded |
|---|---|
| `html` | DOM structure (how many li, where a link points) |
| `css` | computed style |
| `js` | function return values, or DOM results |

## In common: you must write checks

```
type: html
q: Write an unordered list with three items
starter: |
  <ul>
    <li>first item</li>
  </ul>
checks: |
  document.querySelectorAll("li").length === 3
html: |
  <!DOCTYPE html>
  <html><body></body></html>
hint: Use ul with three li
```

`checks` is a list of expressions; all must be true. `html` is the runtime environment (optional).

## Grade the effect, not the source

This is the key design.

On a CSS question asking to make an h1 red, `red`, `#f00` and `rgb(255,0,0)` all pass — because `getComputedStyle` normalises them to `rgb(255, 0, 0)`.

Likewise HTML questions ignore indentation, attribute order and quote style.

**So never write checks that inspect the source string.**

## Traps I hit while building these

```
getComputedStyle(btn).fontSize === "8px"
```

A `<button>` defaults to **13.333px**, so `0.5em` computes to 6.67px, not 8px. Use `rem` if you want to assert a size.

```
getComputedStyle(img).height === "auto"
```

`height: auto` computes to the image's **intrinsic pixel height**, never the string `auto`.

```
margin: 0 auto
```

Horizontal margins compute to concrete pixels. To test centring, assert "left and right margins are equal and greater than zero".

```
:hover transform
```

Pseudo-classes cannot be triggered from JS, so a hover transform is always `none`. Assert the `transition` property instead.

You will not find any of these without running them — and shipping them means **nobody can pass**.

## Recap

- All three web types need `checks`
- Grade computed results, not source text
- Run it yourself before publishing
