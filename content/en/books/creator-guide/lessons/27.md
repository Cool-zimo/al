# 27 Publishing in one click

> Four steps, all automatic. You only choose visibility.

## The flow

Click "Publish to GitHub" and four steps run:

```
1. Validate        stops here if there are errors
2. Create repo     creates it if missing, reuses it otherwise
3. Push files      one commit, all or nothing
4. Set topic       al-book, which is how the bot finds you
```

## Visibility

Pick **public** or **private**:

- **public** gets collected by the bot and listed in the library
- **private** suits unfinished work, or things just for you

You can change visibility any time afterwards in the management panel — private to public and back, one click each way.

## Files go in a single commit

It uses the Git Tree API: **create blobs → create tree → create commit**, all in one go.

The upside is no half-state. If the network dies mid-push you do not end up with a repo containing a broken book.

## The repo name

Defaults to `al-book-{id}`. Change it in "Book info" if you like.

Note: **renaming does not migrate the old repo.** The old one stays where it is and the new name creates a new repo.

## After publishing

Content is read **straight from your repo**, not copied into the site. So:

- edit lessons on GitHub and readers see the new version immediately
- edit in the developer platform and republish, and it pushes to the same repo

## Recap

- Four automatic steps
- Only public repos get collected
- One commit, no half-states
- Content is read live from your repo
