# Debounce and Throttle: The Most Practical Lesson in This Book

> This lesson covers two tools for controlling how often a function runs: debounce and throttle, including the async cases.

## Debounce: run once it finally goes quiet

**Debounce:** after a trigger, **wait a while** — and if another trigger arrives in that window, **reset the timer**. The function only actually runs after things have been quiet for long enough.

The classic use case is **search-as-you-type**. A user types "L", "Lo", "Lon", "London" — you don't want a request per keystroke, just **one request after they stop typing**.

```js
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);          // every trigger clears the old timer
    timer = setTimeout(() => {    // and resets the clock
      fn.apply(this, args);
    }, delay);
  };
}

// Usage
const search = debounce((keyword) => {
  console.log('Requesting:', keyword);
}, 300);

// The user types quickly
search('L');     // timer starts
search('Lo');    // timer resets
search('Lon');   // timer resets
// After 300ms of quiet: one call → Requesting: Lon
```

## Throttle: run at most once per fixed interval

**Throttle:** no matter how often it's triggered, **run at most once in every time window**.

The classic use case is **infinite scroll**. The user scrolls frantically — you don't want dozens of callbacks per second, just **at most one every 200ms**.

```js
function throttle(fn, interval) {
  let lastTime = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

window.addEventListener('scroll', throttle(() => {
  console.log('Checking whether to load more');
}, 200));
```

### Crash Site 1: passing the debounced result straight in as a listener, so debounce builds a new function every time

```js
// ❌ Wrong: every addEventListener call builds a brand-new debounce wrapper
input.addEventListener('input', debounce(doSearch, 300));
// If this lives inside something that runs repeatedly, each bind gets a different
// wrapper and they don't share a timer at all.

// ✅ Build the wrapped function once and bind the same reference
const debouncedSearch = debounce(doSearch, 300);
input.addEventListener('input', debouncedSearch);
```

**Why it crashes:** If `debounce(doSearch, 300)` runs over and over, it **creates a new function with a fresh `timer` every time**, so the calls can never share a timer — and the debounce silently stops working. Always store the wrapped result in a variable and bind that single reference.

### Crash Site 2: async requests plus debounce — an old slow request arrives late and overwrites the new result

```js
// ❌ Race condition: quickly type "London" then "Paris"
const search = debounce(async (keyword) => {
  const res = await fetch(`/api/search?q=${keyword}`);
  const data = await res.json();
  render(data);   // The "London" request might arrive AFTER "Paris" and overwrite it
}, 300);

// ✅ Use a "request version number" to ignore stale responses
let requestVersion = 0;
const search = debounce(async (keyword) => {
  const version = ++requestVersion;   // bump the version on each request
  const res = await fetch(`/api/search?q=${keyword}`);
  const data = await res.json();
  if (version !== requestVersion) return;  // not the latest — drop it
  render(data);
}, 300);
```

**Why it crashes:** Debounce only guarantees **fewer requests**, not **first sent = first arrived**. A slow old request can clobber a newer result, showing up as "I searched for London but the page displays data for Londo". A version number or `AbortController` (covered in a later lesson) fixes it.

## The two side by side

| Feature | Debounce | Throttle |
|---|---|---|
| When it fires | Once, after things go quiet | At most once per fixed interval |
| Typical use | Search suggestions, form validation | Scrolling, mouse movement, resize |
| User experience | Responds after the action stops | Regular, steady responses during the action |

```js
// Debounce: search 300ms after typing stops
input.addEventListener('input', debounce(search, 300));

// Throttle: record the mouse position at most every 200ms
window.addEventListener('mousemove', throttle(record, 200));
```

## Leading-edge debounce

Sometimes you want **the first call to fire immediately**, with debouncing applied afterwards:

```js
function debounceLeading(fn, delay) {
  let timer = null;
  return function (...args) {
    if (!timer) {
      fn.apply(this, args);   // fire on the very first call
    }
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;           // reset so the next call fires immediately again
    }, delay);
  };
}
```

## Comparison with Python

Python isn't much of a frontend language, but servers have similar needs (rate limiting, debouncing), often done with decorators:

```python
# Python: a simple throttle using time
import time
def throttle(interval):
    def decorator(fn):
        last = 0
        def wrapper(*args):
            nonlocal last
            now = time.time()
            if now - last >= interval:
                last = now
                return fn(*args)
        return wrapper
    return decorator
```

In JavaScript, debounce and throttle are everyday, interview-favourite tools on the frontend.

## Recap

- **Debounce:** wait until it's quiet, then run once — great for search suggestions and form validation.
- **Throttle:** at most once per interval — great for scroll, mousemove and resize.
- Wrap a debounce function **once and store it in a variable**, so the timer isn't rebuilt on every bind.
- Async debounce has to handle **races**: use a version number or `AbortController` to ignore stale responses.
- Pick one based on the need: "respond after it stops" → debounce; "keep responding but less often" → throttle.
