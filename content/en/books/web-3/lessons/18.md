# Classes and Modules: `class` and ES Modules

> This lesson covers two tools for organising code: the object-oriented style of `class`, and splitting files apart with `import`/`export`.

## class: a cleaner constructor syntax

ES6 `class` is syntactic sugar over prototypes, but it reads far more naturally:

```js
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  // A prototype method
  greet() {
    return `Hi, I'm ${this.name}`;
  }

  // A getter
  get isAdult() {
    return this.age >= 18;
  }
}

const user = new User('Alice', 20);
console.log(user.greet());    // "Hi, I'm Alice"
console.log(user.isAdult);    // true
```

**Static methods** use `static` and hang off the class itself — no instance needed:

```js
class MathUtil {
  static add(a, b) {
    return a + b;
  }
}

MathUtil.add(1, 2);  // 3, no `new` required
```

### Crash Site 1: putting commas between class methods causes a syntax error

```js
// ❌ That comma is a syntax error!
class User {
  greet() {
    return 'hi';
  },                    // ← this comma is wrong!
  walk() {
    return 'walking';
  }
}

// ✅ No commas between methods (unlike object literals)
class User {
  greet() {
    return 'hi';
  }
  walk() {             // no comma
    return 'walking';
  }
}
```

**Why it crashes:** Inside a class body **you must not put commas between methods** — this is one of the places where a class differs from an object literal `{ }`. A stray comma throws a syntax error and the whole file fails to run.

## Inheritance: extends and super

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a noise`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);       // super MUST be called first, or this is unavailable
    this.breed = breed;
  }
  speak() {
    return `${this.name} says woof`;  // override the parent method
  }
}

const dog = new Dog('Rex', 'Corgi');
console.log(dog.speak());  // "Rex says woof"
```

### Crash Site 2: forgetting `super()` in a subclass constructor

```js
class Dog extends Animal {
  constructor(name) {
    this.name = name;   // ❌ ReferenceError: Must call super before accessing 'this'
  }
}

// ✅ Call super first, then use this
class Dog extends Animal {
  constructor(name) {
    super(name);        // call the parent constructor first
    this.breed = 'Corgi';
  }
}
```

**Why it crashes:** Inside a subclass constructor, **`super()` must run before you touch `this`** — that's a hard rule in ES6. Forget it and you get a `ReferenceError` immediately.

## ES Modules: import / export

Split your code across files using `export` to publish and `import` to consume:

```js
// utils.js
export function formatDate(date) {
  return date.toISOString().slice(0, 10);
}

export const VERSION = '1.0.0';

// A default export (a module can only have one default)
export default class User { /* ... */ }
```

```js
// main.js
import User, { formatDate, VERSION } from './utils.js';
//        ↑ the default export     ↑ named exports

console.log(formatDate(new Date()));
console.log(VERSION);
```

**Note: import paths are usually relative and need the `.js` suffix** (in the browser).

## Running modules in the browser: type="module"

To use ES Modules directly in the browser, **the `<script>` tag must have `type="module"`**:

```html
<!-- ❌ Plain script, the browser doesn't understand import/export -->
<script src="./main.js"></script>

<!-- ✅ Add type="module" -->
<script type="module" src="./main.js"></script>
```

`type="module"` also gives you three extras, free:

1. **Automatic strict mode** (no need to write `'use strict'` yourself).
2. **Deferred execution** (roughly like `defer` — it waits for the DOM to parse).
3. **Cross-origin restrictions**: module files must be served over HTTP, **not opened with a raw `file://` double-click**.

### Crash Site 3: opening the HTML from `file://` makes every import fail

```html
<!-- ❌ Under the file:// protocol, the module load is blocked by CORS -->
<script type="module" src="./main.js"></script>
<!-- Console: Access to script at '.../main.js' from origin 'null' has been blocked by CORS policy -->

<!-- ✅ Serve it through a local server -->
<!-- npx serve .    or    python3 -m http.server -->
```

**Why it crashes:** Opening a page with `type="module"` directly from `file://` means the browser blocks the module file via CORS and every `import` fails. For any modular project you **must** use a local HTTP server (like `npx serve` or `python3 -m http.server`).

## Comparison with Python

Python's `import` system is global and automatically searches `sys.path`; JS ES Modules are **static with explicit paths**, and in the browser they have to go over HTTP:

```python
# Python: import searches paths automatically
import utils
from utils import format_date
```

```js
// JS: paths must be explicit, and the browser needs type="module"
import { formatDate } from './utils.js';
```

## Recap

- `class` is a cleaner constructor syntax — **no commas** between methods.
- `extends` for inheritance; `super()` must run first in a subclass constructor.
- Modules use `export` to publish and `import` to consume; one default export and many named exports.
- Running modules in the browser needs `<script type="module">` **and an HTTP server** — no `file://`.
- `type="module"` implies strict mode and deferred execution.
