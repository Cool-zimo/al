# Promises: Three States and Chaining

> This lesson covers what a Promise is, its three states, and how `.then`/`.catch` flatten callback hell into a chain.

## What is a Promise?

A Promise is **a container for a result that will only be available at some future moment**. It separates "the asynchronous operation" from "what to do once you have the result."

```js
// Create a Promise: wrap an async operation
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve('Data loaded successfully');   // on success, call resolve with the result
    } else {
      reject(new Error('Network error'));    // on failure, call reject
    }
  }, 1000);
});

// Consume this Promise
promise.then(result => console.log(result));
promise.catch(error => console.error(error));
```

`new Promise` accepts an **executor function**, which is executed synchronously right away. The parameters `resolve` and `reject` are provided by the JS engine.

## The three states

A Promise can only ever be in one of three states:

| State | Meaning |
|---|---|
| `pending` | In progress; the result isn't decided yet |
| `fulfilled` (or `resolved`) | Succeeded; has a result value |
| `rejected` | Failed; has a reason for failure |

```js
const p = new Promise((resolve, reject) => {
  // when first created, p is pending
});
console.log(p);  // Promise { <pending> }
```

### Crash Site 1: calling both resolve and reject in the same Promise — the later calls have no effect

```js
// ❌ Expecting to change state multiple times
const p = new Promise((resolve, reject) => {
  resolve('First success');
  reject(new Error('Second failure'));  // ignored!
  resolve('Third success');             // also ignored
});

p.then(v => console.log(v));  // only outputs: First success
```

**Why it crashes:** Once a Promise's state changes from `pending` to `fulfilled` or `rejected`, it is **irreversible**. Subsequent calls to `resolve`/`reject` are ignored. This design guarantees that "the result is decided only once," but it also means you can't keep trying to "change your mind" mid-flight in an async flow.

## then / catch: registering handlers

```js
fetchData()                    // assume this returns a Promise
  .then(data => {              // runs on success
    console.log('Success:', data);
    return data.name;          // the returned value is passed to the next then
  })
  .catch(error => {            // any failure along the chain jumps here
    console.error('Failed:', error);
  });
```

`.then(onFulfilled, onRejected)` can accept two callbacks, but it's generally recommended to **only pass the success callback and use a separate `.catch` to finish the chain**, which makes the intent clearer.

## Chaining: flattening the pyramid

This is the key to how Promises solve callback hell: **`.then` returns a new Promise**, so you can keep chaining `.then` calls.

```js
// ✅ Chaining: top to bottom, not inside out
getUser(1)
  .then(user => {
    console.log('User:', user.name);
    return getPosts(user.id);   // returns a new Promise
  })
  .then(posts => {
    console.log('Post count:', posts.length);
    return getComments(posts[0].id);
  })
  .then(comments => {
    console.log('Comments:', comments);
  })
  .catch(error => {
    console.error('Any failure in the chain ends up here:', error);
  });
```

Compared to the nested version in Lesson 2, chaining has **no rightward indentation** — the flow is a straight line from top to bottom.

What you `return` inside `.then` determines what the next `.then` receives:

- `return 123` → the next `.then` receives `123` (the value is auto-wrapped as `Promise.resolve(123)`)
- `return anotherPromise` → the next `.then` waits for it to complete before executing
- `throw new Error(...)` → jumps to the nearest `.catch`

### Crash Site 2: forgetting to return inside `.then`, causing the next link to receive undefined

```js
// ❌ Forgot to return
getUser(1)
  .then(user => {
    getPosts(user.id);   // no return! Returns undefined
  })
  .then(posts => {
    console.log(posts.length);  // TypeError: Cannot read properties of undefined
  });

// ✅ Add the return
getUser(1)
  .then(user => {
    return getPosts(user.id);
  })
  .then(posts => {
    console.log(posts.length);  // works fine
  });
```

**Why it crashes:** When `.then` doesn't `return`, it returns `undefined` (equivalent to `Promise.resolve(undefined)`), and the next `.then` receives `undefined`. This kind of bug is very sneaky in chains — the code doesn't throw an error, it just means downstream gets no data.

## Promise static methods

| Method | Purpose |
|---|---|
| `Promise.resolve(value)` | Returns a Promise that succeeds immediately |
| `Promise.reject(error)` | Returns a Promise that fails immediately |
| `Promise.all([p1, p2])` | Succeeds only if all succeed; fails immediately if any fails (covered in detail next lesson) |
| `Promise.race([p1, p2])` | Whichever settles first (success or failure) wins |

```js
Promise.all([
  fetch('/api/user'),
  fetch('/api/posts')
]).then(([user, posts]) => {
  console.log('Got both user and posts');
});
```

## Comparison with Python

Python's `asyncio` uses `await` to get the result directly, without needing `.then`-style chaining. JS Promises are closer to the concept of a **pipeline**: each step processes the output of the previous step.

```python
# Python: await gets the value directly
user = await get_user(1)
posts = await get_posts(user.id)
```

```js
// JS: .then passes values down the chain
getUser(1)
  .then(user => getPosts(user.id))
  .then(posts => console.log(posts));
```

## Recap

- A Promise is a container for a "future result" with three states: `pending`, `fulfilled`, `rejected`.
- Once the state is determined, it is **irreversible**; calling `resolve`/`reject` again has no effect.
- `.then` returns a new Promise, enabling **chaining** that flattens nesting into a straight line.
- Always **return** inside `.then`, otherwise the next link receives `undefined`.
- `Promise.all` / `Promise.race` are used to combine multiple Promises.
