# fetch Basics: GET Requests and the Response Object

> This lesson covers the basic usage of the browser-native `fetch` API, with a focus on how to extract values from the `Response` object.

## What is fetch?

`fetch` is a **network request** API provided by modern browsers. It returns a Promise and is much cleaner than the old `XMLHttpRequest`.

```js
// The most basic GET request
fetch('/api/users')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Request failed:', error));
```

The first argument is the URL; by default, it sends a **GET** request.

## The Response object

The Promise returned by `fetch` **resolves to a `Response` object**, not the data itself. You need to call one of its methods to "read out" the response body:

| Method | Description |
|---|---|
| `res.json()` | Parse the response body as JSON; returns a Promise |
| `res.text()` | Read as a text string |
| `res.blob()` | Read as a binary blob (e.g., an image) |
| `res.formData()` | Read as FormData |

```js
fetch('/api/user/1')
  .then(res => {
    console.log(res.status);     // status code, e.g., 200
    console.log(res.ok);         // true means 200~299
    console.log(res.headers);    // response headers
    return res.json();           // ⚠️ returns a Promise, not parsed data
  })
  .then(data => console.log(data));
```

### Crash Site 1: assuming `res.json()` synchronously returns parsed data and using it as a value

```js
// ❌ Common mistake
fetch('/api/users')
  .then(res => {
    const data = res.json();   // data is a Promise, not an array!
    console.log(data.length);  // undefined
  });

// ✅ Correct: return it out, pick it up in the next link
fetch('/api/users')
  .then(res => res.json())
  .then(data => {
    console.log(data.length);  // works fine
  });
```

**Why it crashes:** `res.json()` returns a Promise, not a parsed JSON object. Directly accessing properties on it gives `undefined`, and it doesn't throw an error — making it very hard to debug. **You must `await` or `.then` once more** to get the actual data.

## async/await style

Combined with `await`, `fetch` is much more intuitive:

```js
async function getUsers() {
  const response = await fetch('/api/users');
  const data = await response.json();  // await gives you the real data
  console.log(data);
}
```

Note the **two awaits**: one waits for the response to arrive (`fetch`), and one waits for the response body to be parsed (`json()`).

## Reading text responses with text()

Not all APIs return JSON — some return plain text or HTML:

```js
const res = await fetch('/api/version');
const version = await res.text();
console.log('Current version:', version);  // a string
```

## Query parameters

For GET requests with query parameters, you append them to the URL:

```js
const params = new URLSearchParams({
  city: 'London',
  lang: 'en'
});
const url = `/api/weather?${params}`;
// → /api/weather?city=London&lang=en

const res = await fetch(url);
const data = await res.json();
```

`URLSearchParams` automatically URL-encodes values, which is safer than manually拼接 strings.

### Crash Site 2: manually拼接 URLs without encoding, causing Chinese characters or special characters to result in a 404

```js
// ❌ Manual拼接, no encoding for non-ASCII
const city = 'London';
fetch(`/api/weather?city=${city}`);  // unencoded special chars can cause errors

// ✅ Use URLSearchParams
const params = new URLSearchParams({ city });
fetch(`/api/weather?${params}`);  // automatically encoded
```

**Why it crashes:** Unencoded special characters (spaces, non-ASCII, `&`, `#`) can break the URL structure, causing either a 404 or truncated parameters. Make it a habit to use `URLSearchParams`.

## Comparison with Python

Python's `requests` library is **synchronous** and returns parsed results directly:

```python
# Python requests
import requests
r = requests.get('/api/users')
data = r.json()  # directly get a dict
```

JS `fetch` is asynchronous, and `.json()` requires yet another `await`. This "double wait" is the aspect of JS fetch most often complained about by Python developers.

## Recap

- `fetch(url)` sends a GET request by default and returns `Promise<Response>`.
- The Response object is not the data itself; call `json()`/`text()` etc. to read it.
- **`res.json()` returns a Promise**; you must `await` or `.then` to get the real data.
- For GET parameters, use `URLSearchParams` to construct the query string.
- Common flow: `await fetch()` → `await res.json()`.
