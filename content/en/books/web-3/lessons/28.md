# Connecting to Real APIs: fetch + async/await + Error Handling + Loading State

> This lesson wires the frontend to a real endpoint: fetching data with fetch, writing it with async/await, and handling errors and loading states properly.

## The basic shape of fetch

`fetch(url)` returns a Promise that resolves to a `Response` object. To get JSON, you call `.json()` on it — a second time.

```js
async function getWeather(city) {
  const url = 'https://api.open-meteo.com/v1/forecast'
    + '?latitude=48.8567&longitude=2.3522'
    + '&current=temperature_2m,weather_code,wind_speed_10m';
  const res = await fetch(url);
  const data = await res.json();
  return data;
}
```

Two `await`s: the first waits for the response headers, the second for the body to finish parsing. Miss one and you get a Promise instead of the data.

## async/await makes async code look synchronous

```js
async function main() {
  showStatus('loading');
  try {
    const data = await getWeather('Paris');
    render(data);
    showStatus('success');
  } catch (err) {
    showStatus('error', err.message);
  }
}
```

You can only use `await` inside an `async` function. `await` pauses the function until the Promise settles — **but only that function; the page itself isn't blocked,** and the event loop keeps running.

## Error handling: fetch does NOT reject on HTTP errors

This is the easiest thing to miss: `fetch` does **not** reject on 404 or 500. It only rejects on a network failure or a blocked cross-origin request.

```js
// ❌ Expecting a failed fetch to land in catch
const res = await fetch(url);
const data = await res.json();     // on 404 it returns HTML, .json() throws but loses type info

// ✅ Check ok manually
const res = await fetch(url);
if (!res.ok) {
  throw new Error('Request failed: ' + res.status);   // throw explicitly, land in catch
}
const data = await res.json();
```

**Crash Site 1:** only watching `catch`, and not realizing 404 never reaches it.

```js
async function load() {
  try {
    const res = await fetch(url);   // on 404, res.ok is false
    const data = await res.json();
    render(data);
  } catch (e) {
    showError(e.message);           // on 404, this never runs
  }
}
```

**Why it crashes:** `fetch` only rejects at the **network layer**. An HTTP error status is "a response was received successfully," so the Promise fulfills normally. You must check `res.ok` or `res.status`, or error states will be rendered as success.

## Loading state: set loading before the request

```js
async function search(city) {
  showStatus('loading');
  try {
    const data = await getWeather(city);
    renderWeather(data);
    showStatus('success');
  } catch (e) {
    showStatus('error', e.message);
  }
}

// button click
searchBtn.addEventListener('click', () => {
  search(cityInput.value.trim());
});
```

The state-switching order is fixed: **loading → success/failure**. Show loading before the data arrives so the user knows something is happening.

## Normalize before you render

API responses tend to be verbose. Tidy them into the shape you want before rendering:

```js
function normalize(raw) {
  const cur = raw.current;
  return {
    temp: Math.round(cur.temperature_2m),
    humidity: cur.relative_humidity_2m,
    windSpeed: cur.wind_speed_10m,
    updatedAt: Date.now()
  };
}
```

Keep **fetching** and **shaping** separate. That way, if the API fields change, you only touch `normalize` — the rendering code stays untouched.

**Crash Site 2:** forgetting to handle a `null` field in the response.

```js
// ❌ The API omits humidity, and the next line throws a TypeError
const humidity = data.current.relative_humidity_2m;   // undefined
document.querySelector('#wHumidity').textContent = humidity + '%';

// ✅ Provide a default
const humidity = data.current.relative_humidity_2m ?? '--';
```

**Why it crashes:** real APIs can omit fields or return null. `undefined + '%'` produces `'undefined%'`. Use `??` for a default, or optional chaining: `data.current?.relative_humidity_2m`.

## Exchange rates work the same way

```js
async function getRate(base, target) {
  const url = `https://open.er-api.com/v6/latest/${base}`;
  const res = await fetch(url);
  if (!res.ok) throw new Error('Rate request failed');
  const data = await res.json();
  return data.rates[target];
}
```

Wrap the call in the same try/catch and show the three states: loading, success, error.

## Recap

- `fetch` needs two awaits: one for the `Response`, one for `.json()` to get the data.
- `fetch` does **not** reject on HTTP errors — you must check `res.ok`.
- The state order is fixed: `loading → try{success} catch{failure}`.
- Normalize before rendering to isolate API changes.
- API fields can be missing; use `??` or optional chaining to provide defaults.
