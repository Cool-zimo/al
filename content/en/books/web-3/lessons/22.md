# Canvas Paths and Shapes: beginPath / moveTo / lineTo / arc / fill / stroke

> This lesson covers Canvas's "path" mechanism — the foundation for drawing any shape (lines, circles, polygons).

## What a path is

**A path is a collection of pen movements.** You describe the trail with `moveTo`/`lineTo`/`arc`, then render it with `fill` or `stroke`.

```js
const canvas = document.querySelector('#board');
const ctx = canvas.getContext('2d');

// Draw a line segment
ctx.beginPath();        // start a brand-new path (clear out the old one)
ctx.moveTo(50, 50);     // move the pen to the start point
ctx.lineTo(150, 100);   // draw to the end point
ctx.strokeStyle = 'rgb(33, 150, 243)';
ctx.lineWidth = 3;
ctx.stroke();           // render it as a stroke
```

The four-step口诀 (formula): **beginPath → describe the path → set the style → stroke/fill**.

## Why beginPath is required

`beginPath()` **starts a completely fresh path**. Without it, the new trail **gets added to the old one**.

```js
// ❌ Forgot beginPath, so the two lines join into one
ctx.moveTo(10, 10);
ctx.lineTo(50, 50);
ctx.stroke();           // draws the first line

ctx.moveTo(60, 60);     // no beginPath, so this start joins onto the previous path
ctx.lineTo(100, 100);
ctx.stroke();           // actually draws all three segments!

// ✅ beginPath before every new shape
ctx.beginPath();
ctx.moveTo(10, 10);
ctx.lineTo(50, 50);
ctx.stroke();

ctx.beginPath();        // the crucial bit — severs the connection to the previous stroke
ctx.moveTo(60, 60);
ctx.lineTo(100, 100);
ctx.stroke();
```

### Crash Site 1: an animation loop without beginPath, redrawing every historical trail until the screen is a mess

```js
// ❌ No beginPath in the loop — paths keep accumulating
function draw() {
  // no clear and no beginPath
  ctx.moveTo(x, 100);
  ctx.lineTo(x + 10, 100);
  ctx.stroke();   // every frame redraws the entire accumulated history — slower and thicker
  x += 2;
  requestAnimationFrame(draw);
}

// ✅ Clear the canvas + beginPath
function draw() {
  ctx.clearRect(0, 0, canvas.width, canvas.height);  // clear
  ctx.beginPath();                                    // fresh path
  ctx.moveTo(x, 100);
  ctx.lineTo(x + 10, 100);
  ctx.stroke();
  x += 2;
  requestAnimationFrame(draw);
}
```

**Why it crashes:** Without `beginPath`, all your `moveTo`/`lineTo` calls pile up on the same path, so every `stroke` redraws **the whole historical path**. After a while the animation isn't just visually wrong — performance tanks too.

## Drawing triangles and polygons

```js
// A triangle
ctx.beginPath();
ctx.moveTo(100, 50);
ctx.lineTo(150, 120);
ctx.lineTo(50, 120);
ctx.closePath();        // auto-closes back to the start point
ctx.fillStyle = 'rgb(255, 152, 0)';
ctx.fill();

// Stars, pentagons, any polygon — just add more lineTo calls
```

`closePath()` draws a straight line from the current point back to the path's starting point, closing the shape.

## Circles: arc

```js
ctx.beginPath();
ctx.arc(100, 100, 40, 0, Math.PI * 2);  // centre (100,100), radius 40, from 0 to 2π (full circle)
ctx.fillStyle = 'rgb(156, 39, 176)';
ctx.fill();
```

The angles in `arc(x, y, radius, startAngle, endAngle)` are in **radians**. `Math.PI * 2` is a full circle; `Math.PI` is a half circle.

```js
// A semicircle arc (stroke only)
ctx.beginPath();
ctx.arc(100, 100, 40, 0, Math.PI);  // top half
ctx.stroke();
```

### Crash Site 2: assuming arc uses degrees, so the shape comes out wrong

```js
// ❌ Degrees by mistake
ctx.arc(100, 100, 40, 0, 360);   // expected a full circle, got a tiny sliver instead

// ✅ Use radians
ctx.arc(100, 100, 40, 0, Math.PI * 2);   // full circle
ctx.arc(100, 100, 40, 0, Math.PI / 2);  // quarter circle
```

**Why it crashes:** The arc angles are **in radians**. `360` radians is roughly 206 full turns — way more than `2π` — so you end up with a wild, over-wound line. Remember: π radians = 180°.

## Path cheat sheet

| Method | What it does |
|---|---|
| `beginPath()` | Start a new path, cutting ties with whatever came before |
| `moveTo(x, y)` | Move the pen (without drawing) |
| `lineTo(x, y)` | Draw a straight line to the target |
| `arc(...)` | Draw an arc or circle |
| `closePath()` | Close the shape back to the start point |
| `fill()` | Fill the current path |
| `stroke()` | Stroke the current path |

## Comparison with Python

Python drawing is usually done with `matplotlib`, `PIL/Pillow` or `turtle` — the concepts line up:

```python
# Pillow (PIL): also follows a "create a drawing object → draw shapes → save" flow
from PIL import Image, ImageDraw
img = Image.new('RGB', (200, 200))
draw = ImageDraw.Draw(img)
draw.rectangle([10, 10, 100, 100], fill='red')
```

Canvas is **immediate-mode** bitmap drawing — its closest cousin is PIL's `ImageDraw`.

## Recap

- The path formula: **beginPath → describe the path → set the style → stroke/fill**.
- `beginPath()` must run before every new shape, otherwise trails accumulate and the picture goes wrong.
- `moveTo` moves the pen, `lineTo` draws a line, `closePath` closes the shape, `arc` draws a circle.
- `arc` uses **radians**; `Math.PI * 2` is a full circle.
- An animation loop needs both `clearRect` and `beginPath` to reset cleanly.
