# localStorage Advanced: Capacity, Version Migration, and JSON.parse Safety

> This lesson covers advanced localStorage usage, with a focus on how to avoid "reading corrupt data and crashing the entire page."

## A quick回顾 of localStorage basics

```js
localStorage.setItem('name', 'Alice');
localStorage.getItem('name');    // 'Alice'
localStorage.removeItem('name');
localStorage.clear();            // clear everything
```

Everything stored is a **string**. To store an object you must `JSON.stringify`; to read you must `JSON.parse`.

## Capacity limit: about 5MB, and it stores strings

Each origin gets only about **5MB** of localStorage space; exceeding it throws `QuotaExceededError`. And it's **measured by string length**, not object size.

```js
// check how much is used
function usedBytes() {
  let total = 0;
  for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i);
    total += key.length + localStorage.getItem(key).length;
  }
  return total;  // character count (roughly bytes; non-ASCII chars take more)
}
```

### Crash Site 1: storing a large object exceeds the quota and the page errors out silently

```js
// ❌ Storing an entire huge list
try {
  localStorage.setItem('huge-list', JSON.stringify(bigArray));  // might throw
} catch (e) {
  console.error('Could not save');  // must catch, or execution halts
}

// ✅ Check the size first; if it's too large, warn or degrade gracefully
function safeSet(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
    return true;
  } catch (e) {
    if (e.name === 'QuotaExceededError') {
      console.warn('localStorage is full; data not saved');
      return false;
    }
    throw e;
  }
}
```

**Why it crashes:** When you exceed 5MB, `setItem` **throws an exception**. Without a `try/catch` wrapper, all subsequent code is interrupted, which can cripple page functionality. Production code should always protect `setItem` against capacity issues.

## JSON.parse must be wrapped in try/catch

Data in localStorage **can be corrupted**: a user might have edited it manually, an old version's format might have changed, or another tab might have written bad data. Calling `JSON.parse` directly can throw.

```js
// ❌ Dangerous: assuming stored data is always valid JSON
function getConfig() {
  const raw = localStorage.getItem('config');
  return JSON.parse(raw);  // raw might be null, undefined, or invalid JSON
}

getConfig();  // if raw is "not json", throws SyntaxError

// ✅ Safe reading: with a default value + try/catch
function getConfig() {
  const raw = localStorage.getItem('config');
  if (!raw) return { theme: 'light' };  // default value
  try {
    return JSON.parse(raw);
  } catch (e) {
    console.warn('config data corrupted, using defaults');
    localStorage.removeItem('config');   // clear the bad data
    return { theme: 'light' };
  }
}
```

### Crash Site 2: using `null` or `undefined` as an object, causing a TypeError

```js
// ❌ No fallback
const user = JSON.parse(localStorage.getItem('user'));
console.log(user.name);  // if never stored, getItem returns null, JSON.parse(null) is null

// ✅ Provide a default
const raw = localStorage.getItem('user');
let user = { name: 'Guest' };
if (raw) {
  try {
    user = JSON.parse(raw);
  } catch (e) {
    console.warn('User data corrupted');
  }
}
console.log(user.name);  // always has a value
```

**Why it crashes:** When `localStorage.getItem` finds nothing, it returns `null`, and `JSON.parse(null)` evaluates to `null`. Subsequently accessing `null.name` throws a TypeError. Make it a habit to **always provide a default value when reading**.

## Version migration: what happens when the data structure changes?

After an app upgrade, old data in localStorage may be incompatible with the new version. You need to migrate when reading:

```js
const STORAGE_VERSION = 2;

function loadData() {
  const raw = localStorage.getItem('app-data');
  if (!raw) return getDefaultData();

  let parsed;
  try {
    parsed = JSON.parse(raw);
  } catch (e) {
    return getDefaultData();
  }

  // version migration
  if (!parsed.version || parsed.version < STORAGE_VERSION) {
    parsed = migrate(parsed, parsed.version || 1);
    parsed.version = STORAGE_VERSION;
    localStorage.setItem('app-data', JSON.stringify(parsed));
  }

  return parsed;
}

function migrate(data, fromVersion) {
  if (fromVersion === 1) {
    // v1 → v2: rename the old field
    data.settings = data.prefs || {};
    delete data.prefs;
  }
  return data;
}
```

The key is to **store a version field** in your data, and compare + upgrade it every time you read.

## Recap

- Each origin gets about **5MB** of localStorage, measured by string length; exceeding it throws `QuotaExceededError`.
- Wrap `setItem` in `try/catch` to avoid halting the page on capacity overflow.
- `JSON.parse` **must** be wrapped in `try/catch` — stored data can be corrupted or `null`.
- Reading should have a **default-value fallback** to prevent `null.name`-style TypeErrors.
- Upgrading data structures relies on a **version field + migration function**.
