# Destructuring, Spread, Optional Chaining and Nullish Coalescing

> This lesson covers four bits of syntax that make code shorter and safer at the same time: destructuring, spread, `?.` and `??`.

## Destructuring, levelled up

You already know the basics of destructuring. Here are three patterns that come up constantly in real code.

**Nested destructuring:**

```js
const user = {
  name: 'Alice',
  address: { city: 'London', postcode: 'EC1A 1BB' }
};

// Pull city out of a nested object
const { name, address: { city } } = user;
console.log(name);  // 'Alice'
console.log(city);  // 'London'
// Note: the variable `address` itself is NOT declared
```

**Rename + default value in one move:**

```js
const { name: userName = 'Anonymous', age = 18 } = getUser();
// userName is the renamed variable, age falls back to 18
```

**Default value for the whole parameter:**

```js
function createUser({ name = 'guest', age = 18, city = 'London' } = {}) {
  return `${name}, ${age} years old, from ${city}`;
}
createUser();                 // 'guest, 18 years old, from London'
createUser({ name: 'Bob' });  // 'Bob, 18 years old, from London'
```

The `= {}` after the parameter is the key part — **calling the function with nothing still works**.

### Crash Site 1: destructuring a parameter with no default value crashes on undefined

```js
// ❌ No default for the parameter
function draw({ width, height }) {
  console.log(width, height);
}
draw();        // TypeError: Cannot destructure property 'width' of 'undefined'
draw(undefined);  // same error

// ✅ Give the parameter a default empty object
function draw({ width, height } = {}) {
  console.log(width, height);  // undefined undefined, no error
}
draw();  // safe
```

**Why it crashes:** Destructuring `undefined` or `null` throws a `TypeError` on the spot. Whenever you destructure a function parameter, you **must** give it a `= {}` fallback, otherwise a caller who passes nothing brings the whole thing down.

## Spread, levelled up

**Arrays — merge, copy, insert:**

```js
const a = [1, 2];
const b = [3, 4];

[...a, ...b];        // [1, 2, 3, 4]  merge
[0, ...a, 3];        // [0, 1, 2, 3]  insert
[...a];              // [1, 2]  shallow copy

// ⚠️ Spread only does a shallow copy
const nested = [[1, 2]];
const copy = [...nested];
copy[0].push(3);
console.log(nested[0]);  // [1, 2, 3] — the inner array is still the SAME reference
```

**Objects — merge and override:**

```js
const base = { name: 'Alice', age: 28 };
const extra = { ...base, age: 30, city: 'London' };
// { name: 'Alice', age: 30, city: 'London' } — same keys are overridden left to right

// Object shallow copy (same as {...obj})
const copy = { ...base };
```

### Crash Site 2: thinking `...` does a deep copy, so nested objects stay shared

```js
// ❌ Thought {...obj} was a deep copy
const a = { user: { name: 'Alice' } };
const b = { ...a };
b.user.name = 'Carol';
console.log(a.user.name);  // 'Carol' — Alice's object was mutated!

// ✅ Use structuredClone (or the JSON trick) when you really need a deep copy
const c = structuredClone(a);
c.user.name = 'Dave';
console.log(a.user.name);  // 'Alice' — safe
```

**Why it crashes:** `...` only copies the **first level** of properties; nested objects are shared by reference. For a real deep copy, reach for `structuredClone` or `JSON.parse(JSON.stringify())`.

## Optional chaining `?.`

`?.` lets you read deep properties **without checking every level manually**:

```js
const user = { profile: { name: 'Alice' } };

// The old way
const city = user && user.profile && user.profile.address && user.profile.address.city;

// Optional chaining
const city = user?.profile?.address?.city;  // undefined, no error thrown
```

When it hits `null` or `undefined` it **short-circuits and returns `undefined`** instead of throwing.

```js
// Optional chaining with a method call
const result = obj?.someMethod?.();  // safe even if the method doesn't exist

// Optional chaining with a bracket lookup
const first = arr?.[0];
```

## Nullish coalescing `??`

`??` only reaches for the right-hand side when the left is **`null` or `undefined`**:

```js
const a = 0 ?? 100;           // 0     (0 is not null/undefined, so 0 stays)
const b = '' ?? 'default';    // ''    (empty string is kept)
const c = null ?? 100;        // 100
const d = undefined ?? 100;   // 100
```

**The difference between `??` and `||`** is the single most important thing in this lesson:

```js
// || treats 0, '' and false as falsy and overwrites them
const count = 0 || 10;        // 10  ❌ the legitimate 0 got clobbered
const name = '' || 'Anonymous';  // 'Anonymous' ❌ the empty string got clobbered

// ?? only kicks in for null/undefined
const count = 0 ?? 10;        // 0  ✅ keeps the 0
const name = '' ?? 'Anonymous';  // ''  ✅ keeps the empty string
```

### Crash Site 3: using `||` for a quantity default wipes out a legal zero

```js
// ❌ Using || as the fallback
function setLimit(limit) {
  const n = limit || 10;   // When the user passes 0, we get 10 — wrong!
  return n;
}
setLimit(0);  // Expected 0, got 10

// ✅ Use ?? instead
function setLimit(limit) {
  const n = limit ?? 10;   // 0 is preserved correctly
  return n;
}
setLimit(0);   // 0 ✅
setLimit();    // 10 (undefined triggers the fallback)
```

**Why it crashes:** In a form, "quantity 0", "empty notes" and "enabled: false" are all legal values. Using `||` as a fallback misreads them as "not filled in" and overwrites them. Bugs like this show up as "**the user's 0 turned into the default value**" — quietly, and very hard to spot.

## Comparison with Python

Python 3.8+ has the walrus operator `:=`, but no optional chaining. Digging into nested dicts is usually done with chained `.get` calls or a `try/except`:

```python
# Python: chained .get calls, or a third-party library like glom
city = user.get('profile', {}).get('address', {}).get('city')
```

```js
// JavaScript: optional chaining does it in one line
const city = user?.profile?.address?.city;
```

`??` is the rough equivalent of Python's `x if x is not None else y`.

## Recap

- When destructuring a function parameter, always write a `= {}` default so missing arguments don't blow up.
- `...` spread is a **shallow copy** — nested objects still share a reference.
- Optional chaining `?.` short-circuits at `null`/`undefined`, saving you a chain of null checks.
- **`??` only cares about null/undefined; `||` overwrites every falsy value (including 0, '' and false).**
- For quantity and toggle-style defaults, prefer `??` so you never silently overwrite a legal value.
