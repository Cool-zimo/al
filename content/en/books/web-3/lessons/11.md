# JSON Deep Cloning, Circular References, and structuredClone

> This lesson covers the "deep clone" problem for objects, and the classic `JSON.parse(JSON.stringify(x))` trick — along with its fatal flaws.

## Why deep cloning is necessary

In JS, objects are **reference types** — assignment only copies the reference, so both variables point to the same block of memory:

```js
const a = { name: 'Alice', scores: [90, 85] };
const b = a;          // b and a point to the same object
b.name = 'Bob';
console.log(a.name);  // 'Bob' — a was also changed!

// ✅ Shallow copy: only copies the first level
const c = { ...a };
c.name = 'Charlie';
console.log(a.name);  // 'Bob' — first level is independent
console.log(c.scores === a.scores);  // true — but nested arrays still share a reference
c.scores.push(100);   // this pollutes a.scores!
```

A shallow copy (`{...obj}`, `Object.assign`) only solves the first level; nested objects/arrays **still share references**.

## The JSON deep clone trick

The most classic "deep clone" technique uses JSON serialization followed by deserialization:

```js
const a = { name: 'Alice', scores: [90, 85] };
const b = JSON.parse(JSON.stringify(a));  // deep clone

b.scores.push(100);
console.log(a.scores);  // [90, 85] — the original object is untouched
console.log(b.scores);  // [90, 85, 100]
```

How it works: `JSON.stringify` turns the object into a string (no concept of references), and `JSON.parse` rebuilds it into a brand new object — the reference chain is completely broken.

### Crash Site 1: an object with a circular reference causes JSON.stringify to throw immediately

```js
// ❌ Circular reference
const a = { name: 'Alice' };
a.self = a;   // points to itself, creating a cycle

JSON.stringify(a);  // TypeError: Converting circular structure to JSON

// ✅ Handle the cycle first, or use structuredClone
```

**Why it crashes:** `JSON.stringify` **throws an exception immediately** when it encounters a circular reference, halting all subsequent code. This is common when working with tree structures (like DOM nodes or objects with parent references).

### Crash Site 2: JSON deep cloning loses functions, undefined, Date, Map, Set, and other type information

```js
const obj = {
  name: 'Alice',
  sayHi: () => console.log('hi'),  // function
  birth: new Date('1990-01-01'),  // Date object
  extra: undefined,                // undefined
  map: new Map()                   // Map
};

const copy = JSON.parse(JSON.stringify(obj));
console.log(copy.sayHi);   // undefined — the function is gone
console.log(copy.birth);   // "1989-12-31T16:00:00.000Z" — Date became a string
console.log(copy.extra);   // undefined — the property was removed
console.log(copy.map);     // undefined — the Map is gone entirely
```

**Why it crashes:** `JSON.parse(JSON.stringify(x))` is not a "perfect deep clone" — it **drops** functions, `undefined`, Symbols, Maps, Sets, and WeakMaps, and converts `Date` to a string and `RegExp` to an empty object. Once data passes through this transformation, information is **irreversibly lost**.

## structuredClone: a true deep clone

Modern browsers provide `structuredClone`, which correctly handles more types — including circular references:

```js
const a = { name: 'Alice' };
a.self = a;

const b = structuredClone(a);  // no error
console.log(b.self === b);     // true — the circular structure is preserved

// supports even more types
const obj = {
  date: new Date(),
  map: new Map([['key', 'value']]),
  set: new Set([1, 2, 3]),
  nested: { deep: true }
};
const copy = structuredClone(obj);
console.log(copy.map.get('key'));  // 'value'
console.log(copy.date instanceof Date);  // true
```

`structuredClone`'s limitation: it still **cannot clone functions** — it will throw on functions; some host objects like DOM nodes are also unsupported.

## The three approaches compared

| Approach | Circular refs | Date/Map/Set | Functions | Compatibility |
|---|---|---|---|---|
| `{...obj}` | Doesn't handle nesting | Doesn't copy nested | Keeps reference | Universal |
| `JSON.parse(JSON.stringify())` | ❌ throws | ❌ loses types | ❌ lost | Universal |
| `structuredClone()` | ✅ | ✅ | ❌ throws | Modern browsers |

## Comparison with Python

Python's `copy.deepcopy` is a "true" deep clone — it handles circular references and can also copy functions:

```python
import copy
a = {'name': 'Alice'}
a['self'] = a
b = copy.deepcopy(a)  # works fine
```

JS's `structuredClone` is closer to Python's `deepcopy`, but still falls short in functionality (can't copy functions).

## Recap

- Object assignment is reference copying; a shallow copy only makes the first level independent.
- `JSON.parse(JSON.stringify(x))` is a classic deep clone trick, but has three major pitfalls: **circular references throw, functions/undefined are lost, Date/Map/Set lose their types**.
- `structuredClone` supports circular references and more built-in types — a more reliable choice.
- `structuredClone` still can't clone functions.
- Choosing: use the JSON trick for simple data; use `structuredClone` for complex structures.
