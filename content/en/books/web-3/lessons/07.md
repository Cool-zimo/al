# POST Requests and Headers: method, headers, body

> This lesson covers how to send POST requests with `fetch`, and why `JSON.stringify` is required.

## Sending a POST request

The second argument to `fetch` is a **configuration object** used to specify the request method, headers, body, and more:

```js
fetch('/api/users', {
  method: 'POST',              // request method
  headers: {                   // request headers
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({        // request body must be a string
    name: 'Alice',
    age: 28
  })
})
  .then(res => res.json())
  .then(data => console.log(data));
```

## Why body needs JSON.stringify

What travels over the network in an HTTP request body can **only be a string (or binary)**, not a JS object. So when sending JSON data, you must first serialize the object into a string with `JSON.stringify`.

```js
const user = { name: 'Alice', age: 28 };

// ❌ Wrong: passing the object directly
fetch('/api/users', {
  method: 'POST',
  body: user   // the object gets converted to "[object Object]"; the server can't parse it
});

// ✅ Correct: stringify first
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(user)
});
```

### Crash Site 1: forgetting the `Content-Type` header, so the server doesn't know how to parse the body

```js
// ❌ No Content-Type
fetch('/api/users', {
  method: 'POST',
  body: JSON.stringify({ name: 'Alice' })
  // server receives this but doesn't know it's JSON; may treat it as plain text
});

// ✅ Explicitly declare it
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Alice' })
});
```

**Why it crashes:** Servers (like Express, Django) typically rely on the `Content-Type: application/json` header to decide whether to parse the body as a JSON object. Without this header, the server can't get structured data and may return 400 or hand you the raw string.

## Common request methods

| Method | Purpose |
|---|---|
| GET | Retrieve a resource (default) |
| POST | Create a resource |
| PUT | Full update of a resource |
| PATCH | Partial update of a resource |
| DELETE | Delete a resource |

```js
// PUT update
fetch('/api/users/1', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Bob' })
});

// DELETE
fetch('/api/users/1', { method: 'DELETE' });
```

## Auth information in headers

Many APIs require login before they can be called; they place the token in the request headers:

```js
const token = localStorage.getItem('token');

fetch('/api/profile', {
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`   // carry the token
  }
});
```

### Crash Site 2: hardcoding a token directly in frontend code

```js
// ❌ Sensitive info hardcoded in the frontend
const token = 'sk-1234567890abcdef';  // anyone viewing the source can see it

// ✅ Get it from the login state, and only transmit over HTTPS
const token = localStorage.getItem('authToken');
// combine with backend auth, expiration, refresh
```

**Why it crashes:** Frontend code is **completely visible** to users. Hardcoding an API key or token in your code is the same as publishing it. Sensitive credentials should live on the backend; the frontend should only hold a short-lived access token.

## Uploading files with FormData

If you need to upload a file, use `FormData` — **don't** manually stringify it:

```js
const form = new FormData();
form.append('username', 'Alice');
form.append('avatar', document.querySelector('#file').files[0]);

fetch('/api/upload', {
  method: 'POST',
  body: form
  // Note: don't manually set Content-Type; the browser adds the boundary automatically
});
```

## Comparison with Python

Python's `requests` library has a dedicated `json` parameter that automatically stringifies and adds the header:

```python
# Python requests handles it automatically
import requests
requests.post('/api/users', json={'name': 'Alice'})  # auto stringify + header
```

```js
// JS requires manual stringify and header
fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Alice' })
});
```

The "low-level" design of JS fetch is exactly why it's easy to forget `JSON.stringify` and `Content-Type`.

## Recap

- POST requests use `fetch(url, { method: 'POST', headers, body })`.
- The body **must be a string**; for JSON, use `JSON.stringify`.
- The `Content-Type: application/json` header tells the server how to parse the body.
- PUT / PATCH / DELETE correspond to update and delete semantics.
- For auth, use the `Authorization` header; never hardcode tokens in the frontend.
