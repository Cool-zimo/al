# concat: stacking tables top to bottom

> `merge` joins side-by-side, `concat` stacks one on top of another. Get this distinction clear and you will never reach for the wrong tool again.

## Starting with a real scenario

Alice runs the London office and Bob runs Manchester. At month end they each send a sales sheet. You need one combined table:

```python
import pandas as pd

london = pd.DataFrame({
    'date': ['2026-09-01', '2026-09-02'],
    'city': ['London', 'London'],
    'revenue': [1200, 1500]
})

manchester = pd.DataFrame({
    'date': ['2026-09-01', '2026-09-02'],
    'city': ['Manchester', 'Manchester'],
    'revenue': [900, 2100]
})
```

**Both tables share the same columns**, only the rows differ. This is a "stack on top" operation — use `concat`:

```python
total = pd.concat([london, manchester])
print(total)
```

```
         date        city  revenue
0  2026-09-01      London     1200
1  2026-09-02      London     1500
0  2026-09-01  Manchester      900
1  2026-09-02  Manchester     2100
```

**Four rows** — exactly 2 + 2. That is the whole job of `concat`: pile rows up and stop.

## Syntax: pass a list

```python
pd.concat([table1, table2, table3])
```

**Key point: the first argument is a list**, not two side-by-side positional arguments.

```python
# WRONG
pd.concat(london, manchester)
```

```
TypeError: concat() got multiple values for argument 'objs'
```

## axis decides the direction

```python
df1 = pd.DataFrame({'A': [1, 2], 'B': [3, 4]})
df2 = pd.DataFrame({'A': [5, 6], 'C': [7, 8]})
```

**Default is `axis=0`, vertical stacking**:

```python
print(pd.concat([df1, df2]))
```

```
   A    B    C
0  1  3.0  NaN
1  2  4.0  NaN
0  5  NaN  7.0
1  6  NaN  8.0
```

When the two tables have no column names in common, pandas fills with NaN. **With `axis=1` it becomes horizontal alignment (by index)**:

```python
print(pd.concat([df1, df2], axis=1))
```

```
   A  B  A  C
0  1  3  5  7
1  2  4  6  8
```

Duplicate column names are not a problem — pandas will not rename them for you. **That is `merge`'s territory; do not force `concat` to do it.**

## ignore_index keeps the index clean

The vertical stack above gave us an index of `0, 1, 0, 1` — awkward. Add `ignore_index=True`:

```python
print(pd.concat([london, manchester], ignore_index=True))
```

```
         date        city  revenue
0  2026-09-01      London     1200
1  2026-09-02      London     1500
2  2026-09-01  Manchester      900
3  2026-09-02  Manchester     2100
```

**The index is renumbered from 0.** This is the setting to reach for whenever you intend to fetch rows by position later.

## Keys: tag each row with its source

```python
g = pd.concat([london, manchester], keys=['London', 'Manchester'])
print(g)
```

```
                  date        city  revenue
London     0 2026-09-01      London     1200
           1 2026-09-02      London     1500
Manchester 0 2026-09-01  Manchester      900
           1 2026-09-02  Manchester     2100
```

The result now has a **two-level index (MultiIndex)** — the top level is the source tag. To pull just the London rows: `g.loc['London']`.

**This is a source-preserving stack** — far more useful than `ignore_index` when you are auditing or tracing where each record came from.

## append is gone — stop using it

The `df1.append(df2)` you still see in old tutorials was removed entirely in pandas 2.0:

```python
# WRONG
total = london.append(manchester)
```

```
AttributeError: 'DataFrame' object has no attribute 'append'
```

**The modern, uniform answer is `pd.concat([df1, df2])`.**

## Crash site: silent NaN when column counts differ

```python
# Alice's sheet has an extra "channel" column
london2 = pd.DataFrame({
    'date': ['2026-09-01'],
    'city': ['London'],
    'revenue': [1200],
    'channel': ['online']
})

print(pd.concat([london2, manchester], ignore_index=True))
```

```
         date        city  revenue  channel
0  2026-09-01      London     1200   online
1  2026-09-01  Manchester      900      NaN
2  2026-09-02  Manchester     2100      NaN
```

**No error, but Manchester's `channel` is all NaN.** This is the most dangerous kind of bug: the code runs and the conclusion silently drifts. Always run `print(df.columns)` on both tables before stacking.

## Crash site: axis=1 aligns on index, not position

```python
a = pd.DataFrame({'revenue': [100, 200]}, index=['London', 'Manchester'])
b = pd.DataFrame({'cost': [60, 120]}, index=['Manchester', 'Bristol'])

print(pd.concat([a, b], axis=1))
```

```
            revenue  cost
London         100.0   NaN
Manchester     200.0  60.0
Bristol         NaN  120.0
```

**Any index position that does not overlap becomes NaN.** That is not a bug — it is `concat`'s "align on index" rule. If you really meant to join side-by-side, use `merge`.

## Recap

- **`concat` does one thing: stacks tables.** Default direction is `axis=0`
- **The first argument must be a list**: `pd.concat([a, b])`
- **`ignore_index=True`** renumbers the index; **`keys=[...]`** tags the source
- **Mismatched columns do not raise** — missing cells become NaN, so check column names first
- **`append` is gone** — use `concat` everywhere
