# Reading CSV into a DataFrame

> `read_csv` is the most-used function in pandas and the one with the most arguments. This lesson covers the useful ones and four classic traps.

## The basics

```python
import pandas as pd

df = pd.read_csv('data.csv')
print(df.shape)
print(df.head())
```

**pandas treats the first row as the header** and everything after it as data.

## Arguments worth knowing

| Argument | What it does |
|---|---|
| `sep` / `delimiter` | the separator; a comma by default |
| `header` | which row is the header; `None` means there isn't one |
| `names` | supply your own column names |
| `index_col` | use a column as the row index |
| `usecols` | read only certain columns |
| `encoding` | the file encoding (use `gbk` for mojibake) |
| `skiprows` | skip N lines at the top |
| `nrows` | read only the first N rows |
| `na_values` | which strings count as missing |
| `thousands` | the thousands separator |

## Trap one: no header

The file looks like this (the first row is already data):

```
Alice,18
Bob,19
```

```python
df = pd.read_csv('no_header.csv')     # ❌ treats "Alice,18" as the header!
print(df.columns)     # ['Alice', '18']  ← wrong

df = pd.read_csv('no_header.csv', header=None)     # ✅
print(df.columns)     # [0, 1]

df = pd.read_csv('no_header.csv', header=None, names=['name', 'age'])   # ✅ better
```

## Trap two: encoding (mojibake)

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd5 in position 0
```

**CSVs saved by Excel on Chinese Windows default to GBK** — the number one cause of garbled text.

```python
df = pd.read_csv('data.csv', encoding='gbk')       # try this
df = pd.read_csv('data.csv', encoding='gb18030')   # or this (a superset of gbk)
```

**The permanent fix:** re-save the file as UTF-8 in VSCode and you'll never hit it again.

## Trap three: numeric columns arriving as text

This is the sneakiest trap. **The file looks numeric, but pandas reads object:**

```
price
"1,299"
89
```

```python
df = pd.read_csv('price.csv')
print(df['price'].dtype)      # object ← but they're numbers!
print(df['price'].tolist())   # ['1,299', '89']
```

**Why:** `1,299` contains a thousands comma, so pandas can't parse the column as numeric and falls back to object.

**Two fixes:**

```python
# 1. handle it while reading
df = pd.read_csv('price.csv', thousands=',')
print(df['price'].dtype)      # int64 ✓

# 2. convert after reading
df['price'] = pd.to_numeric(df['price'].str.replace(',', ''), errors='coerce')
```

**Then there's the placeholder-text variant:**

```
price
199
n/a
89
```

```python
df = pd.read_csv('price2.csv')
print(df['price'].dtype)      # object (because of "n/a")

# 1. tell pandas what counts as missing
df = pd.read_csv('price2.csv', na_values=['n/a'])
print(df['price'].dtype)      # float64 ✓, 'n/a' becomes NaN

# 2. or force the conversion; anything unparseable becomes NaN
df['price'] = pd.to_numeric(df['price'], errors='coerce')
```

**`to_numeric(..., errors='coerce')` is the universal converter** — anything that isn't a number becomes NaN, which you then treat as missing.

> 💡 **`info()` is the only reliable way to spot this**: when a column that should be numeric shows object, go straight to `head()` and see what crept in.

## Trap four: ragged rows

```
ParserError: Expected 3 fields in line 2, saw 2
```

A row has the wrong number of fields. Usual causes:

- a field contains a comma that was never quoted
- a truncated line at the end of the file
- mismatched quotes

**To diagnose**, read it as plain text first:

```python
with open('data.csv', encoding='utf-8') as f:
    for i, line in enumerate(f):
        if i >= 5: break
        print(repr(line))
```

## Reading a big file safely

Don't load a multi-million-row CSV in one go:

```python
# read just 1000 rows to inspect the structure
df = pd.read_csv('huge.csv', nrows=1000)
print(df.info())

# once it looks right, read everything
df = pd.read_csv('huge.csv')
```

**`nrows` is the life-saver for large files.**

You can also read only the columns you need, saving memory:

```python
df = pd.read_csv('huge.csv', usecols=['date', 'amount', 'city'])
```

## Using a column as the index

```python
df = pd.read_csv('data.csv', index_col='name')
print(df.index)          # Index(['Alice', 'Bob', ...])
print(df.loc['Alice'])   # fetch a row by name directly
```

**If a column works as an identifier** (order id, city name, date), `index_col` makes life much easier.

## Writing CSV out

```python
df.to_csv('out.csv', index=False)      # index=False is the important bit
df.to_csv('out.csv', index=False, encoding='utf-8-sig')   # for Excel
```

**Two points:**

1. **`index=False`** — otherwise the row index is written too, adding an unnamed column of numbers
2. **`encoding='utf-8-sig'`** — the BOM makes Excel open Chinese text correctly

## A full routine

```python
import pandas as pd

# 1. read a sample to inspect the structure
df = pd.read_csv('sales.csv', nrows=100, encoding='utf-8')
print(df.info())

# 2. having spotted a problem (amount is object), re-read with arguments
df = pd.read_csv('sales.csv',
                 encoding='utf-8',
                 thousands=',',
                 na_values=['n/a', '-'],
                 parse_dates=['date'])

# 3. check again
print(df.info())
print(df.isna().sum())
```
