# loc versus iloc

> The biggest source of confusion in pandas. Master this and half your future bugs never happen.

## The difference in one line

| | Selects by | Slice includes the end? |
|---|---|---|
| **`loc`** | **label** (the name) | **Yes** |
| **`iloc`** | **position** (which one) | **No** |

**Two differences, both matter**: what you select by, and where the slice ends.

## loc: by name

```python
import pandas as pd

df = pd.DataFrame({
    'name': ['Alice', 'Bob', 'Cara', 'Dan'],
    'age': [18, 19, 20, 17],
    'score': [89.5, 92.0, 78.0, 95.0]
})
df = df.set_index('name')      # use the name as the row index

print(df)
print()
print(df.loc['Bob'])
```

```
       age  score
name
Alice   18   89.5
Bob     19   92.0
Cara    20   78.0
Dan     17   95.0

age      19.0
score    92.0
Name: Bob, dtype: float64
```

**`loc['Bob']` fetched that row by name.**

## iloc: by position

```python
print(df.iloc[1])      # position 1 (counting from 0)
```

```
age      19.0
score    92.0
Name: Bob, dtype: float64
```

**Bob again** — because Bob sits at position 1. But the rules differ.

**When do they disagree?** Sort the frame:

```python
df2 = df.sort_values('score', ascending=False)
print(df2)
print()
print("loc['Bob']  →", df2.loc['Bob', 'score'])
print("iloc[0]     →", df2.iloc[0]['score'])
```

```
       age  score
name
Dan     17   95.0
Bob     19   92.0
Alice   18   89.5
Cara    20   78.0

loc['Bob']  → 92.0     ← still Bob
iloc[0]     → 95.0     ← now Dan!
```

**After sorting, positions changed but labels travelled with their data.** That's the essential difference:

- **`loc` follows "which row is this"** — sorting and filtering don't affect it
- **`iloc` follows "the Nth row"** — after sorting it's somebody else

## A single value

```python
print(df.loc['Bob', 'score'])     # 92.0   row label + column name
print(df.iloc[1, 1])              # 92.0   row position + column position
```

**The format is `[row, column]`** — before the comma is rows, after it is columns.

You can also take part of a row:

```python
print(df.loc['Bob', ['age', 'score']])     # several columns of one row
print(df.iloc[1, 0:2])                     # by position
```

## Slicing: inclusive versus exclusive

**This is the second trap, and the sneakier one.**

```python
s = pd.Series([10, 20, 30, 40], index=['a', 'b', 'c', 'd'])

print(s.loc['a':'c'])      # [10, 20, 30]   ← includes 'c'! 3 items
print(s.iloc[0:2])         # [10, 20]       ← excludes position 2! 2 items
```

**With the same `0:2` written:**

```python
df3 = pd.DataFrame({'name': ['Alice','Bob','Cara','Dan'], 'score': [1,2,3,4]})

print(df3.loc[0:2])        # 3 rows (includes 2)
print(df3.iloc[0:2])       # 2 rows (excludes 2)
```

| Write | Rows |
|---|---|
| `df.loc[0:2]` | **3** (0,1,2) |
| `df.iloc[0:2]` | **2** (0,1) |

> ⚠️ **`loc` includes the end** — deliberate in pandas, because with names, "from a to c" naturally includes c. But it contradicts Python intuition and **it's the easiest way to miscount rows.**

## Boolean filters: loc (or brackets)

```python
print(df.loc[df['score'] > 90])
print(df.loc[df['score'] > 90, 'age'])     # plus a column choice
```

**`df.loc[boolean Series]` is the standard form.** `iloc` won't accept a boolean Series (it only knows positions).

> 💡 `df[df['score'] > 90]` works too. But **as soon as you also want to pick columns, you need loc**: `df.loc[cond, 'col']` works, whereas the chained `df[cond]['col']` breaks in some assignment cases.

## A comparison table

| Need | Write |
|---|---|
| Row by name | `df.loc['Bob']` |
| Row by position | `df.iloc[1]` |
| One value | `df.loc['Bob', 'score']` |
| Value by position | `df.iloc[1, 1]` |
| Slice by label | `df.loc['Alice':'Cara']` (inclusive) |
| Slice by position | `df.iloc[0:2]` (exclusive) |
| Filter | `df.loc[df['score'] > 90]` |
| Filter plus columns | `df.loc[df['score'] > 90, ['name','score']]` |

## How to remember

- **`loc` = label** → names
- **`iloc` = integer location** → which one

The `i` is for integer. Remember that and you'll never mix them up.

## Which to use

- **You know "which row"** (a city, an order id) → **`loc`**
- **You know "the Nth row"** (first 3, the last one) → **`iloc`**

Most real work is the former — selecting by condition or name. So **`loc` gets used far more**.
