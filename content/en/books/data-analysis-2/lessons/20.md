# Putting it together: a sales report

> Stringing the last four chapters into one real analysis pass. Not much new syntax here — the point is **order**.

## The full flow

```
get data → inspect structure → clean → group and aggregate → pivot → state conclusions
```

Plenty of people jump straight to groupby and end up aggregating dirty data. **Get the order wrong and the conclusion is wrong.**

## Step one: inspect the structure

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    'date': ['2024-01-01', '2024-01-01', '2024-01-02', '2024-01-02',
             '2024-01-03', '2024-01-03'],
    'city': ['London', 'Paris', 'London', 'Paris', 'London', 'Berlin'],
    'category': ['peripheral', 'display', 'peripheral', 'display', 'audio', 'peripheral'],
    'revenue': ['£1,299', '£8,999', '£899', '£12,999', 'n/a', '£599'],
    'units': ['2', '1', '3', '2', '1', 'x']
})

print(df.head())
print()
print(df.dtypes)
```

**Don't calculate yet** — note that revenue is text (with £ and commas), and units contains an `x`.

## Step two: clean

```python
# 1. revenue: strip symbols and commas, convert
df['revenue'] = pd.to_numeric(
    df['revenue'].str.replace('£', '').str.replace(',', ''),
    errors='coerce'
)

# 2. units: convert, failures become 0, then int
df['units'] = pd.to_numeric(df['units'], errors='coerce').fillna(0).astype(int)

# 3. date to datetime
df['date'] = pd.to_datetime(df['date'])

print(df.dtypes)
print()
print("gaps:")
print(df.isna().sum())
```

**"n/a" became NaN** — that's the truth (that sale has no recorded amount). We'll deal with it next.

## Step three: handle the gaps

```python
print("rows before:", len(df))
df = df.dropna(subset=['revenue'])
print("rows after:", len(df))
```

**Why drop:** revenue is the core measure. Without it there's nothing to analyse, so dropping beats inventing.

## Step four: group and aggregate

```python
print("=== revenue by city ===")
city = df.groupby('city')['revenue'].agg(['sum', 'mean', 'count'])
print(city.sort_values('sum', ascending=False))

print("\n=== revenue by category ===")
cate = df.groupby('category')['revenue'].agg(['sum', 'mean', 'count'])
print(cate.sort_values('sum', ascending=False))
```

```
=== revenue by city ===
        sum     mean  count
city
Paris  21998  10999.0      2
London  2197   1098.5      2
Berlin   599    599.0      1

=== revenue by category ===
             sum     mean  count
category
display    21998  10999.0      2
peripheral  2197   1098.5      2
audio        599    599.0      1
```

**Look at the `count` column** — Paris and London have 2 orders each, Berlin only 1. **A mean from a small group isn't reliable**, and that's the column people ignore.

## Step five: analysis columns (transform)

```python
df['city_total'] = df.groupby('city')['revenue'].transform('sum')
df['city_share'] = (df['revenue'] / df['city_total'] * 100).round(1)
df['above_mean'] = df['revenue'] > df.groupby('city')['revenue'].transform('mean')

print(df[['date', 'city', 'category', 'revenue', 'city_total', 'city_share', 'above_mean']])
```

**Detail rows plus group-level measures in one pass.**

## Step six: pivot table

```python
print("=== city × category ===")
pt = df.pivot_table(index='city', columns='category', values='revenue',
                    aggfunc='sum', fill_value=0, margins=True,
                    margins_name='Total')
print(pt)
```

```
category  peripheral  display  audio  Total
city
Paris              0    21998      0  21998
London          2197        0    599   2796
Berlin           599        0      0    599
Total           2796    21998    599  25393
```

**One glance tells you**: Paris is all displays; London is spread out.

## Step seven: state the conclusion

```python
print("=== conclusions ===")
s = df.groupby('city')['revenue'].sum()
total = df['revenue'].sum()

print(f"total revenue: {total:,.0f}")
print(f"top city: {s.idxmax()} ({s.max():,.0f}, {s.max()/total*100:.1f}% of total)")
print(f"top category: {df.groupby('category')['revenue'].sum().idxmax()}")
print(f"valid orders: {len(df)}")
```

**The value of analysis is the conclusion, not the procedure.** Every step above exists for these few lines.

## A reusable template

```python
import pandas as pd
import numpy as np

def analyse(df):
    """A standard sales analysis pass"""
    # 1. structure
    print("[1] structure")
    print(df.dtypes)
    print(f"{len(df)} rows x {df.shape[1]} cols")

    # 2. clean
    print("\n[2] cleaning")
    for col in df.select_dtypes(include='object').columns:
        conv = pd.to_numeric(df[col], errors='coerce')
        if conv.notna().sum() > 0:      # something converted → should be numeric
            df[col] = conv
            print(f"  {col}: converted to numeric, {conv.isna().sum()} failed")
    print("  remaining gaps:")
    print(df.isna().sum().to_string())

    # 3. group
    print("\n[3] by city")
    g = df.groupby('city')['revenue'].agg(['sum','mean','count'])
    print(g.sort_values('sum', ascending=False))

    # 4. pivot
    print("\n[4] pivot")
    print(df.pivot_table(index='city', columns='category', values='revenue',
                         aggfunc='sum', fill_value=0, margins=True))

    # 5. conclude
    print("\n[5] conclusions")
    s = df.groupby('city')['revenue'].sum()
    print(f"  total {df['revenue'].sum():,.0f}; top city {s.idxmax()} "
          f"({s.max():,.0f}, {s.max()/s.sum()*100:.1f}%)")

    return df
```

## Why this chapter's order is what it is

| Step | Why here |
|---|---|
| Inspect structure | acting without knowing the types guarantees mistakes |
| Clean | conclusions from dirty data are wrong |
| Fill gaps | gaps affect count and mean |
| Group | aggregation only makes sense once clean |
| transform | add group-level measures when you need them |
| Pivot | last, for presentation |

**Swap the order — group before cleaning, say — and you get the wrong totals.**
