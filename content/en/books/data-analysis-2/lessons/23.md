# Merge pitfalls: duplicate keys, naming clashes, and indicator

> Merge most often goes wrong not with a syntax error, but with a result that "looks fine" while the numbers quietly double. This lesson is about catching those hidden mistakes.

## The classic: row counts that double

```python
import pandas as pd

orders = pd.DataFrame({'order_id': ['A001', 'A002'], 'customer': ['Alice', 'Bob']})
lines  = pd.DataFrame({
    'order_id': ['A001', 'A001', 'A002'],
    'item': ['keyboard', 'mouse', 'monitor'],
    'amount': [200, 50, 1500]
})
```

We want the total amount per order:

```python
# WRONG
merged = orders.merge(lines, on='order_id')
print(merged.groupby('order_id')['amount'].sum())
```

```
order_id
A001    250
A002   1500
dtype: int64
```

**It happens to look right!** But check the merge row count:

```python
print(len(merged))   # 3
```

Two rows became three. **The one-to-many join stretched the left table.** This example got lucky because the groupby aggregated on the lines side.

The real failure looks like this:

```python
# The orders table also has a "shipping" column we want to sum
orders2 = pd.DataFrame({
    'order_id': ['A001', 'A002'], 'customer': ['Alice', 'Bob'], 'shipping': [10, 15]
})
merged2 = orders2.merge(lines, on='order_id')
print(merged2.groupby('order_id')['shipping'].sum())
```

```
order_id
A001    20
A002    15
dtype: int64
```

**Alice's shipping is £10, but the result is £20** — because A001 has two line items, the shipping value was counted twice.

**The fix: aggregate first, then merge:**

```python
amount_sum = lines.groupby('order_id')['amount'].sum().reset_index()
result = orders2.merge(amount_sum, on='order_id')
print(result)
```

```
  order_id customer  shipping  amount
0    A001    Alice        10     250
1    A002      Bob        15    1500
```

## Crash site: outer join leaves a sea of NaN

```python
members = pd.DataFrame({
    'user_id': [1, 2, 3],
    'tier': ['Gold', 'Silver', 'Bronze']
})
orders  = pd.DataFrame({
    'user_id': [2, 3, 4, 5],
    'amount': [100, 200, 300, 400]
})

all_rows = members.merge(orders, on='user_id', how='outer')
print(all_rows)
```

```
   user_id    tier  amount
0      1.0    Gold     NaN
1      2.0  Silver   100.0
2      3.0  Bronze   200.0
3      4.0     NaN   300.0
4      5.0     NaN   400.0
```

**User 1 never ordered (amount is NaN), users 4 and 5 are not members (tier is NaN).** An outer join keeps everything from both sides.

**That is not automatically wrong** — for a "full picture" analysis it is exactly what you want. But if your goal is "average spend per member", **this should be a left join**:

```python
print(members.merge(orders, on='user_id', how='left'))
```

```
   user_id    tier  amount
0        1    Gold     NaN
1        2  Silver   100.0
2        3  Bronze   200.0
```

**Only members remain — non-members never enter the denominator.**

## Duplicate keys: the Cartesian product

```python
a = pd.DataFrame({'date': ['09-01', '09-01'], 'store': ['London', 'London'], 'revenue': [1200, 1500]})
b = pd.DataFrame({'date': ['09-01', '09-01'], 'store': ['London', 'London'], 'footfall': [80, 120]})
```

**Both tables have two rows for the same `date + store` combination:**

```python
print(a.merge(b, on=['date', 'store']))
```

```
    date   store  revenue  footfall
0  09-01  London     1200        80
1  09-01  London     1200       120
2  09-01  London     1500        80
3  09-01  London     1500       120
```

**2 × 2 = 4 rows — every permutation.** Merge cannot know which row pairs with which, so it pairs them all.

**Fix: add a column that actually distinguishes the rows** (an order number, a timestamp), or aggregate first to remove duplicates:

```python
b1 = b.drop_duplicates(subset=['date', 'store'])
print(len(a.merge(b1, on=['date', 'store'])))   # 2
```

## The indicator parameter: see where every row came from

```python
r = members.merge(orders, on='user_id', how='outer', indicator=True)
print(r)
```

```
   user_id    tier  amount     _merge
0        1    Gold     NaN  left_only
1        2  Silver   100.0       both
2        3  Bronze   200.0       both
3        4     NaN   300.0  right_only
4        5     NaN   400.0  right_only
```

The `_merge` column has only three possible values: `left_only`, `right_only`, and `both`.

**This is the fastest way to audit a join.** For example, "what fraction of members have placed an order?":

```python
buyers = r[r['_merge'] == 'both']
print(len(buyers) / len(members))   # 2/3
```

## Column-name clashes: automatic suffixes

```python
x = pd.DataFrame({'id': [1, 2], 'value': [10, 20]})
y = pd.DataFrame({'id': [1, 2], 'value': [100, 200]})

print(x.merge(y, on='id'))
```

```
   id  value_x  value_y
0   1       10      100
1   2       20      200
```

**Non-key columns with the same name get `_x` (left) and `_y` (right) suffixes automatically.** It is a lifesaving feature — without it you could not tell the two apart.

To set your own suffixes:

```python
print(x.merge(y, on='id', suffixes=('_last_year', '_this_year')))
```

```
   id  value_last_year  value_this_year
0   1               10              100
1   2               20              200
```

## Recap

- **One-to-many grows the left table** — always aggregate, then merge
- **Outer joins leave large patches of NaN** — be clear whether you want the full set or one side
- **Duplicate keys produce a Cartesian product** — dedupe first or add a distinguishing key
- **`indicator=True`** tags every row as `left_only` / `both` / `right_only`
- **Clashing column names get `_x` / `_y`** — customise with `suffixes`
