# Why pandas

> At the end of *Data Analysis 1* we said NumPy struggles with "text columns plus numeric columns". This lesson starts from that pain.

## How awkward NumPy gets

Say you have a student table:

```python
import numpy as np

# name (text) + age (int) + score (float)
data = np.array([['Alice', '18', '89.5'],
                 ['Bob', '19', '92.0'],
                 ['Cara', '20', '78.0']])
print(data)
print("dtype:", data.dtype)
```

```
[['Alice' '18' '89.5']
 ['Bob' '19' '92.0']
 ['Cara' '20' '78.0']]
dtype: <U5
```

**Note the dtype: `<U5` — everything is a string.** NumPy allows one type per array, so once text is in, the numbers become text too.

To average the scores you must convert:

```python
scores = data[:, 2].astype(float)      # every time
print(scores.mean())
```

**One conversion per column**, and it spirals as columns multiply.

## How pandas does it

```python
import pandas as pd

df = pd.DataFrame({
    'name': ['Alice', 'Bob', 'Cara'],
    'age': [18, 19, 20],
    'score': [89.5, 92.0, 78.0]
})
print(df)
print(df.dtypes)
```

```
    name  age  score
0  Alice   18   89.5
1    Bob   19   92.0
2   Cara   20   78.0

name     object
age       int64
score   float64
dtype: object
```

**The difference:** `name` is object (text), `age` is int64, `score` is float64 — **each column keeps its own type**.

That's what a table should look like. The average is now:

```python
print(df['score'].mean())      # 86.5
```

No conversion, because the column was numeric all along.

## What pandas actually is

In one sentence: **pandas is a table library built on top of NumPy.**

```python
print(type(df['score'].values))    # <class 'numpy.ndarray'>
```

**Every column's `.values` is a NumPy array.** Everything from *Data Analysis 1* — broadcasting, axes, boolean indexing, ufuncs — works unchanged here.

```python
print(df['score'].values * 1.1)          # broadcasting
print(df['score'].values > 85)           # a boolean array
print(np.where(df['score'].values > 85, 'A', 'B'))
```

So this isn't "start over with a new library" — it's **a convenience layer for tables, laid over NumPy**.

## Four pains pandas removes

| NumPy pain | pandas answer |
|---|---|
| One text column turns everything into strings | **A type per column** |
| Positions only, no names | **Column names plus index labels** |
| Must remember nanmean and friends | **`mean()` skips gaps by default** |
| Grouping means hand-written loops | **`groupby`, one line** |

## Three names to learn first

| Name | What it is | Think of it as |
|---|---|---|
| **Series** | one labelled column | a 1-D NumPy array plus index names |
| **DataFrame** | a table (several Series together) | one Excel sheet |
| **Index** | the row labels | the numbers down the left edge |

```python
print(type(df))              # DataFrame
print(type(df['score']))     # Series ← one column is a Series
print(type(df.index))        # Index
```

**A DataFrame is a dictionary of Series:** `df['score']` fetches the column named "score".

## A first complete example

```python
import pandas as pd

df = pd.DataFrame({
    'product': ['Keyboard', 'Mouse', 'Monitor', 'Headset'],
    'price': [199, 89, 1299, 399],
    'units': [120, 500, 30, 200]
})

# new column: revenue = price × units
df['revenue'] = df['price'] * df['units']

print(df)
print("\ntotal revenue:", df['revenue'].sum())
print("best seller:", df.loc[df['units'].idxmax(), 'product'])
```

```
    product  price  units  revenue
0  Keyboard    199    120    23880
1     Mouse     89    500    44500
2   Monitor   1299     30    38970
3   Headset    399    200    79800

total revenue: 187150
best seller: Mouse
```

**Two lines worth studying:**

- `df['price'] * df['units']` — pandas **aligns by index**, then computes element-wise
- `df.loc[df['units'].idxmax(), 'product']` — `idxmax()` returns the **index label** of the maximum, then `.loc` fetches that row's product name

Column arithmetic and label-based lookup are the two most common pandas moves; both get proper treatment later.

## When not to use pandas

pandas isn't universal. NumPy fits better when:

- **Large-scale pure numeric matrix work** (images, signals, linear algebra)
- **Inner loops needing maximum speed** (NumPy skips label bookkeeping, so it's faster)
- **Feeding libraries like sklearn** (they convert to ndarray internally anyway)

**Rule of thumb:** tables → pandas; matrices and tensors → NumPy.
