# shift and differencing: day-on-day, year-on-year, and growth rates

> How much did we sell yesterday? The same day last year? Answering "how much changed, and by what percent" is not a recomputation — it is a matter of sliding the data along and subtracting.

## shift: sliding the data

```python
import pandas as pd

idx = pd.date_range('2026-09-01', periods=6, freq='D')
revenue = pd.Series([100, 120, 90, 130, 110, 150], index=idx)
```

`shift(1)` **moves the whole series down by one row:** what was day 2 now sits on day 3, and the top slot becomes NaN.

```python
yesterday = revenue.shift(1)
print(yesterday)
```

```
2026-09-01      NaN
2026-09-02    100.0
2026-09-03    120.0
2026-09-04     90.0
2026-09-05    130.0
2026-09-06    110.0
Freq: D, dtype: float64
```

**`shift(1)` means "take the previous row's value."** So row 2 shows 100 — that is day 1's revenue.

## Day-on-day: today minus yesterday

`day_on_day = today - yesterday`. Using `revenue - revenue.shift(1)`:

```python
delta = revenue - revenue.shift(1)
print(delta)
```

```
2026-09-01      NaN
2026-09-02     20.0
2026-09-03    -30.0
2026-09-04     40.0
2026-09-05    -20.0
2026-09-06     40.0
Freq: D, dtype: float64
```

**Day one is NaN** — it has no yesterday. Day two is +20, meaning sales were £20 higher than the day before.

For "what percent did it grow," divide by yesterday:

```python
growth = revenue / revenue.shift(1) - 1
print(growth)
```

```
2026-09-01         NaN
2026-09-02    0.200000
2026-09-03   -0.250000
2026-09-04    0.444444
2026-09-05   -0.153846
2026-09-06    0.363636
Freq: D, dtype: float64
```

Day two's 0.2 = up 20%.

## The periods parameter: moving by more than one row

`shift(1)` moves one place; `shift(7)` moves seven — exactly "the same day last week."

```python
last_week = revenue.shift(7)
print(last_week)
```

```
2026-09-01    NaN
2026-09-02    NaN
2026-09-03    NaN
2026-09-04    NaN
2026-09-05    NaN
2026-09-06    NaN
Freq: D, dtype: float64
```

This sample only has 6 days, so moving 7 leaves it empty. **`periods` is the number of places to move**; the sign sets the direction — positive goes back (the past), negative goes forward (the future).

## diff(): the whole subtraction in one step

`diff()` is equivalent to `x - x.shift(1)` — one less thing to write.

```python
print(revenue.diff())
print(revenue.diff(1))      # same as above
print(revenue.diff(2))      # subtract the row two places back: today - day before yesterday
```

```
2026-09-01      NaN
2026-09-02     20.0
2026-09-03    -30.0
2026-09-04     40.0
2026-09-05    -20.0
2026-09-06     40.0
Freq: D, dtype: float64
```

`diff(2)` gives [NaN, NaN, -10, 10, 20, 60], because day 3 is computed against day 1 (90-100 = -10).

## pct_change(): growth rate in one step

`pct_change()` is equivalent to `x / x.shift(1) - 1`.

```python
print(revenue.pct_change())
```

```
2026-09-01         NaN
2026-09-02    0.200000
2026-09-03   -0.250000
2026-09-04    0.444444
2026-09-05   -0.153846
2026-09-06    0.363636
Freq: D, dtype: float64
```

**`diff()` gives absolute change, `pct_change()` gives relative change (percent)** — they are the pair you reach for together: one shows the pounds, the other the magnitude.

## Year-on-year: this year vs. the same day last year

Across years, day-on-day looks at yesterday and year-on-year looks at the same day last year. Shift by 365 places:

```python
days = 365
idx_y = pd.date_range('2025-01-01', periods=400, freq='D')
last_year = pd.Series(range(100, 500), index=idx_y)
day_one_this_year = last_year.shift(-365)     # negative moves up = the future row
```

A more robust approach is **to align by the actual date rather than counting rows:**

```python
s = pd.Series([120, 150, 90, 200],
              index=pd.to_datetime(['2026-01-01', '2026-07-01', '2027-01-01', '2027-07-01']))
same_day_last_year = s.index - pd.DateOffset(years=1)
yoy = s / s.reindex(same_day_last_year).values - 1
```

**Date-based alignment does not depend on row count** — leap years and missing dates do not break it. Counting rows is only safe when every single day is present.

## Crash site: shift leaves NaN, then it spreads

```python
# WRONG
sales = pd.Series([100, 120, 130])
next_day = sales.shift(-1)
result = next_day / sales
print(result)
```

```
0    NaN
1    1.0
2    NaN
dtype: float64
```

The last row is NaN (there is nothing to shift into). **But the subtle part is that NaN contaminates anything it touches.** If you then call `result.sum()`, you get NaN instead of the 1.0 you expected.

**Deal with it first using `dropna()` or `fillna()`:**

```python
next_day = sales.shift(-1).fillna(0)
result = next_day / sales
print(result.sum())   # 1.0
```

Or keep only rows where both sides exist: `sales.shift(-1).dropna()`.

## Crash site: periods goes the wrong way, producing "future growth"

```python
# WRONG
shifted = revenue.shift(-1)       # moves up = pulls tomorrow's value
growth = revenue / shifted - 1     # today divided by tomorrow
print(growth)
```

```
2026-09-01   -0.166667
2026-09-02    0.333333
2026-09-03   -0.307692
2026-09-04    0.181818
2026-09-05   -0.266667
2026-09-06         NaN
dtype: float64
```

**A positive shift is "look back."** Get the sign wrong and there is no error — the numbers are just completely reversed. This is the dangerous kind of bug: silent but wrong.

Mnemonic: **to see "yesterday," use a positive number (look back); to see "tomorrow," use a negative (look forward).**

## Crash site: calling diff on a string column

```python
# WRONG
df = pd.DataFrame({'city': ['London', 'Manchester', 'Bristol'], 'sales': [100, 200, 150]})
df['sales'].diff()      # fine
df['city'].diff()      # TypeError
```

```
TypeError: unsupported operand type(s) for -: 'str' and 'str'
```

**`diff()` and `pct_change()` only make sense on numeric columns.** On strings or dates they error immediately. For date differences use `dt.days`:

```python
gap_days = (df['date'] - df['date'].shift(1)).dt.days
```

## Recap

- **`shift(1)` takes the previous row, `shift(-1)` takes the next** — positive looks back
- **`diff()` = current minus previous**; `pct_change()` = current divided by previous, minus 1
- **Day-on-day looks at yesterday; year-on-year looks at the same day last year** — for cross-year data, align by date instead of row count
- **NaN contaminates** — handle it with `dropna()` or `fillna()` after shifting
- **Reversing the `periods` sign produces no error but inverts the conclusion** — always sanity-check the first and last values
