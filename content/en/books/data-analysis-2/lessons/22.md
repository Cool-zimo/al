# merge: joining tables four ways

> Real data never lives in one table. Staff details sit in table A, salaries in B, departments in C — `merge` is the tool that brings them together by key.

## Starting with a scenario

The staff table `emp` has only a name and a department number; the department table `dept` has the department name. To get "Alice → Engineering":

```python
import pandas as pd

emp = pd.DataFrame({
    'name': ['Alice', 'Bob', 'Carol'],
    'dept_id': [10, 20, 10]
})

dept = pd.DataFrame({
    'dept_id': [10, 20, 30],
    'dept_name': ['Engineering', 'Marketing', 'Finance']
})
```

```python
result = emp.merge(dept, on='dept_id')
print(result)
```

```
    name  dept_id dept_name
0  Alice       10  Engineering
1  Carol       10  Engineering
2    Bob       20    Marketing
```

**Both tables aligned on `dept_id`, and the department name came along.** That is the whole point of merge: match by key.

## The syntax

```python
left.merge(right, on='key', how='join_type')
```

Three ingredients: **a left table, a right table, and the key to join on.**

## The four join types

| how | meaning |
|---|---|
| `inner` | keep only keys present in both tables (default) |
| `left` | keep every key from the left table; fill the right with NaN |
| `right` | keep every key from the right table |
| `outer` | keep every key from both tables |

Here they are with concrete data:

```python
left = pd.DataFrame({'k': ['a', 'b', 'c'], 'v': [1, 2, 3]})
right = pd.DataFrame({'k': ['b', 'c', 'd'], 'w': [4, 5, 6]})
```

```python
print(left.merge(right, on='k', how='inner'))
```

```
   k  v  w
0  b  2  4
1  c  3  5
```

**Only `b` and `c` exist in both tables** — `a` and `d` are dropped. This is the default.

```python
print(left.merge(right, on='k', how='left'))
```

```
   k  v    w
0  a  1  NaN
1  b  2  4.0
2  c  3  5.0
```

**All of `a`, `b`, `c` from the left are kept**; `a` has no match on the right, so `w` is NaN.

```python
print(left.merge(right, on='k', how='outer'))
```

```
   k    v    w
0  a  1.0  NaN
1  b  2.0  4.0
2  c  3.0  5.0
3  d  NaN  6.0
```

**Every key appears at least once**, with NaN filling the gaps.

## When the key has different names: left_on / right_on

```python
emp2 = pd.DataFrame({'name': ['Alice', 'Bob'], 'dept_id': [10, 20]})
dept2 = pd.DataFrame({'dept_no': [10, 20], 'dept_name': ['Engineering', 'Marketing']})
```

When the key columns are named differently, you cannot use `on=` — specify each side separately:

```python
print(emp2.merge(dept2, left_on='dept_id', right_on='dept_no'))
```

```
    name  dept_id  dept_no dept_name
0  Alice       10       10  Engineering
1    Bob       20       20    Marketing
```

**Both `dept_id` and `dept_no` appear in the result.** Usually you drop one straight after:

```python
r = emp2.merge(dept2, left_on='dept_id', right_on='dept_no').drop(columns='dept_no')
```

## Crash site: one-to-many makes the row count grow

```python
orders = pd.DataFrame({'order_id': ['A001', 'A002'], 'customer': ['Alice', 'Bob']})
lines  = pd.DataFrame({'order_id': ['A001', 'A001', 'A002'], 'item': ['keyboard', 'mouse', 'monitor']})
```

One order has several line items — a classic one-to-many relationship:

```python
print(orders.merge(lines, on='order_id'))
```

```
  order_id customer       item
0    A001    Alice   keyboard
1    A001    Alice      mouse
2    A002      Bob    monitor
```

**Three rows!** The orders table had only 2 rows, yet the result has 3. Alice appears twice because her order has two line items.

**This is not a bug — it is the correct behaviour of merge.** Every matching pair becomes a row. If you forget this before aggregating, your sums will double. Always check `len()` first.

## Crash site: duplicate keys explode the row count

```python
a = pd.DataFrame({'k': ['x', 'x'], 'v': [1, 2]})
b = pd.DataFrame({'k': ['x', 'x'], 'w': [3, 4]})

print(a.merge(b, on='k'))
```

```
   k  v  w
0  x  1  3
1  x  1  4
2  x  2  3
3  x  2  4
```

**2 rows × 2 rows = 4 rows: a Cartesian product.** When the key is not unique, merge expands every combination.

**`indicator=True` lets you see how each row was produced**:

```python
r = a.merge(b, on='k', indicator=True)
print(r['_merge'].value_counts())
```

```
both          4
left_only     0
right_only    0
Name: _merge, dtype: int64
```

The new `_merge` column marks each row as `left_only`, `right_only`, or `both`. **When something looks wrong after a join, this column is the first place to look** — it tells you instantly which rows failed to match.

## Recap

- **merge matches by key**: `left.merge(right, on=key, how=type)`
- **inner keeps only shared keys; left/right keep one side; outer keeps everything**
- **Different key names → `left_on` / `right_on`**; both key columns stay in the result
- **One-to-many grows the row count** — run `len()` before aggregating
- **Duplicate keys produce a Cartesian product** — use `indicator=True` to investigate
