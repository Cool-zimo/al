# melt: turning a wide table into a long one

> Why reshape the same data at all? Because plotting and grouping both love long tables. `melt` is the tool that stands up values that are lying flat across columns.

## Wide tables vs. long tables

```python
import pandas as pd

wide = pd.DataFrame({
    'store': ['London', 'Manchester'],
    'Jan': [1200, 900],
    'Feb': [1500, 1100],
    'Mar': [1300, 1000]
})
```

A table with "one column per month" is easy on the eye, **but awkward to plot or group by.**

`melt` turns it into a long table:

```python
long = wide.melt(id_vars=['store'], var_name='month', value_name='revenue')
print(long)
```

```
       store month  revenue
0     London   Jan     1200
1  Manchester   Jan      900
2     London   Feb     1500
3  Manchester   Feb     1100
4     London   Mar     1300
5  Manchester   Mar     1000
```

**Six rows, three columns.** The month names stopped being column names and became values; the revenue stopped being several columns and became one.

## The three parameters

```python
df.melt(id_vars=[primary_keys], var_name='new_column_name', value_name='new_value_column')
```

| parameter | purpose |
|---|---|
| `id_vars` | columns to leave untouched (the key / identifier columns) |
| `var_name` | what to call the column made from the old column names |
| `value_name` | what to call the column made from the old values |

**The payoff of a long table:** you can `groupby('month')` for a quarterly trend, or hand it straight to a plotting function. A wide table cannot do either without rewriting.

## Crash site: forget id_vars and everything melts

```python
# WRONG
print(wide.melt())
```

```
  variable value
0     store  London
1     store  Manchester
2      Jan   1200
3      Jan    900
4      Feb   1500
5      Feb   1100
6      Mar   1300
7      Mar   1000
```

**`store` became just another variable name**, and "London" and "Manchester" got mixed in with the months. The data is all still there, but it is unusable.

**`id_vars` must be stated explicitly** — it is "the columns I do not want touched."

## value_vars: melt only part of the table

```python
mixed = pd.DataFrame({
    'store': ['London', 'Manchester'],
    'Jan': [1200, 900],
    'Feb': [1500, 1100],
    'manager': ['Alice', 'Bob']
})

# Melt only the month columns; leave manager alone
print(mixed.melt(id_vars=['store', 'manager'], value_vars=['Jan', 'Feb'],
                 var_name='month', value_name='revenue'))
```

```
       store manager month  revenue
0     London   Alice   Jan     1200
1  Manchester     Bob   Jan      900
2     London   Alice   Feb     1500
3  Manchester     Bob   Feb     1100
```

**`value_vars` says which columns to melt**; `id_vars` says which to leave alone. They are complementary. Leave out `value_vars` and every column except `id_vars` is melted by default.

## melt and groupby working together

The biggest win from a long table is **grouping**:

```python
print(long.groupby('month')['revenue'].mean())
```

```
month
Jan    1050
Feb    1300
Mar    1150
Name: revenue, dtype: int64
```

**A wide table would take three lines** (repeating `df['Jan'].mean()` for each month). A long table does it in one.

## The reverse operation: pivot

A long table can be stood back up into a wide one:

```python
print(long.pivot(index='store', columns='month', values='revenue'))
```

```
month        Jan   Feb   Mar
store
London      1200  1500  1300
Manchester   900  1100  1000
```

**This is exactly what lesson 25 covers.**

## Crash site: dtype can shift after melting

```python
numeric_wide = pd.DataFrame({
    'store': ['London', 'Manchester'],
    'Q1': [100, 200],
    'Q2': [150, 250]
})
r = numeric_wide.melt(id_vars=['store'], var_name='quarter', value_name='revenue')
print(r.dtypes)
```

```
store       object
quarter     object
revenue      int64
dtype: object
```

**The value column keeps its dtype (int64)** — no problem there. But be careful: if the two melted columns have different types, pandas will **coerce them to a common type**. One int column and one string column, for example, and the result is all `object`.

## Recap

- **melt turns wide into long:** month names become values
- **`id_vars` is mandatory:** state which columns must stay put
- **`value_vars`** picks which columns to melt; leave it out and everything else is melted
- **Long tables are the natural shape for grouping and plotting**
- **pivot is the reverse of melt**
