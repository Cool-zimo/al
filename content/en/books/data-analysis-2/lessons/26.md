# Time series basics: from strings to a DatetimeIndex

> Storing "2026-09-01" as a string lets you sort, but not "summarise by week." Once it becomes a real datetime, pandas' time magic actually kicks in.

## Why datetime is not optional

```python
import pandas as pd

df = pd.DataFrame({
    'date': ['2026-09-01', '2026-09-02', '2026-09-03'],
    'revenue': [1200, 1500, 900]
})

print(df.dtypes)
```

```
date      object
revenue    int64
dtype: object
```

**`date` is `object` (a string).** You cannot group by "week" or "month," and you certainly cannot tell which quarter a row belongs to.

## pd.to_datetime: the entry point

```python
df['date'] = pd.to_datetime(df['date'])
print(df.dtypes)
```

```
date      datetime64[ns]
revenue             int64
dtype: object
```

**`datetime64[ns]` is the real thing.**

pandas recognises several formats automatically:

```python
print(pd.to_datetime(['2026/9/1', '20260902', 'Sep-03-2026']))
```

```
DatetimeIndex(['2026-09-01', '2026-09-02', '2026-09-03'], dtype='datetime64[ns]', freq=None)
```

**It copes with a mix of formats.** But in real projects, uniform input is safer — relying on inference will eventually burn you.

## When conversion fails: the errors parameter

```python
# WRONG
pd.to_datetime(['2026-09-01', 'not-a-date', '2026-09-03'])
```

```
ParserError: Unknown string format
```

**One bad value kills the whole call.** Add `errors='coerce'` to turn anything unparseable into `NaT`:

```python
s = pd.to_datetime(['2026-09-01', 'not-a-date', '2026-09-03'], errors='coerce')
print(s)
```

```
DatetimeIndex(['2026-09-01', 'NaT', '2026-09-03'], dtype='datetime64[ns]', freq=None)
```

**`NaT` is the time-series version of NaN** — you can filter it out with `isna()`.

## Set it as the index: now slicing works

```python
df['date'] = pd.to_datetime(df['date'])
df = df.set_index('date')
print(df.index)
```

```
DatetimeIndex(['2026-09-01', '2026-09-02', '2026-09-03'], dtype='datetime64[ns]', name='date', freq=None)
```

**Once the index is a DatetimeIndex, slicing speaks time.**

## String slicing: why it works

```python
df.loc['2026-09-02']
```

```
revenue    1500
Name: 2026-09-02 00:00:00, dtype: int64
```

**A plain string fetches that day** — because the index is a DatetimeIndex, pandas parses it for you.

A range of days:

```python
print(df.loc['2026-09-01':'2026-09-02'])
```

```
            revenue
date
2026-09-01     1200
2026-09-02     1500
```

**Partial strings such as "year" or "year-month" also work:**

```python
# Pull the whole of September
print(df.loc['2026-09'])
```

## The dt accessor: pull fields out of a datetime column

```python
df2 = pd.DataFrame({
    'time': pd.to_datetime(['2026-09-01 10:30', '2026-12-25 18:00'])
})

print(df2['time'].dt.year)        # 2026, 2026
print(df2['time'].dt.month)       # 9, 12
print(df2['time'].dt.day)         # 1, 25
print(df2['time'].dt.hour)        # 10, 18
print(df2['time'].dt.dayofweek)   # 1 (Tuesday), 4 (Friday)
```

**The `dt` accessor exposes year, month, day, hour, weekday — everything you need to group by quarter or weekday.**

```python
df2['quarter'] = df2['time'].dt.quarter
print(df2['quarter'])   # 0    3, 1    4
```

## Crash site: time zones

```python
a = pd.Timestamp('2026-09-01 08:00')
b = pd.Timestamp('2026-09-01 08:00', tz='Europe/London')
print(a == b)
```

```
False
```

**One is timezone-aware, the other is naive — they are never equal.** For cross-border data this is a very common trap.

Standardise explicitly:

```python
print(a.tz_localize('Europe/London') == b)   # True
```

## Crash site: you thought you converted, but you did not

```python
df3 = pd.DataFrame({'date': ['2026-09-01']})
df3['date'].astype(str)   # wrong approach
```

**You meant to convert, but nothing happened.** Checking `dtypes` is the only reliable test:

```python
df3['date'] = pd.to_datetime(df3['date'])
print(df3['date'].dtype)   # datetime64[ns]
```

## Recap

- **`pd.to_datetime()`** turns a string column into real datetime
- **When parsing fails, `errors='coerce'`** gives you `NaT` instead of an exception
- **Set the column as the index** before you try string-based slicing
- **`dt.year` / `dt.month` / `dt.day` / `dt.hour`** expose the time fields
- **Time zones must match** — tz-aware and naive are never equal
