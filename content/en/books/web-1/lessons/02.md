# Your First HTML Document: Get the Skeleton Right

> This lesson answers the question: "Why does my page look odd in the browser?" The root cause is the skeleton: doctype, html, head and body - not one of them can be missing.

## The skeleton of an HTML document

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Alice's homepage</title>
  </head>
  <body>
    <h1>Hello</h1>
  </body>
</html>
```

Each of these five pieces has a job:

| Tag | Purpose |
|---|---|
| `<!DOCTYPE html>` | Declares that this is HTML5, so the browser parses it in standards mode |
| `<html lang="en">` | The root element; `lang` tells the browser that the page's main language is English |
| `<head>` | Holds information "for the browser to read", not shown on the page |
| `<title>` | The tab title, also used in search results and bookmarks |
| `<body>` | Holds the content "for the user to see"; everything visible lives here |

## DOCTYPE is not a tag

`<!DOCTYPE html>` is written at the very top, with no blank line and no space before it. It is a **directive** telling the browser "please render this according to the HTML5 standard". Without it, the browser enters "Quirks Mode", and the box model is calculated using the old rules from the 1990s - the `width` you write may not be the value you get.

By the way: in Python, a bad indent causes an error. In HTML, a few extra spaces or messy indentation will **not** cause an error - the browser is forgiving. But that does not mean you can write carelessly. Indentation is for you; readability is for the version of yourself six months from now.

## What is in the head is not shown on the page

`<head>` holds metadata: character encoding, the title, stylesheet links, viewport settings. The user cannot see any of this, but it decides whether the page can display correctly.

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Alice's CV</title>
  <link rel="stylesheet" href="style.css">
</head>
```

`<meta charset="UTF-8">` prevents garbled characters. `<meta name="viewport">` lets the page scale correctly on mobile phones; without it, a mobile browser renders the page at desktop width and then shrinks it, leaving the text too small to read.

## Tags must be closed

HTML tags come in two kinds:

- **Paired tags**: `<p>...</p>`, `<div>...</div>`, `<h1>...</h1>`. Every opening tag has a closing tag.
- **Self-closing tags**: `<img>`, `<br>`, `<hr>`, `<input>`. They have no content, so they need no closing tag.

## Crash site 1: forgetting the closing tag

```html
<div>
  <p>First paragraph
  <p>Second paragraph
</div>
```

Consequence: the browser "guesses" that you omitted a closing tag, and in most cases it can fill it in automatically so the page looks normal. **But** once the structure gets more complex, a wrong guess becomes expensive. Alice wrote a `<div class="card">` with three levels of nested divs inside it and only closed the outermost one, so the card's border stretched across the whole page. The browser treated everything afterwards as still being inside the card. Getting into the habit of closing tags as you write them saves far more time than debugging later.

## Crash site 2: crossed, overlapping nesting

```html
<p>This is<b>bold text</p></b>
```

Consequence: `<p>` contains `<b>`, but `</p>` comes before `</b>`, creating a cross. When the browser parses this it may hoist the `<b>` out of the `<p>`, so the DOM structure is completely different from what you wrote and CSS selectors fail to match. The correct version is `<p>This is<b>bold text</b></p>`.

## Comments

```html
<!-- This is a comment; the browser does not display it - it is for humans -->
```

Comments never appear on the page. A good comment explains **why** something was written that way, which is more valuable than describing **what** was written.

## Summary

- The skeleton four-piece set: `<!DOCTYPE html>` + `<html>` + `<head>` + `<body>`.
- DOCTYPE must be on the first line; it decides whether the browser uses standards mode or quirks mode.
- `<head>` holds metadata and `<body>` holds visible content; the two must not be mixed up.
- Paired tags must be closed, and they must not be nested in a crossed order.

## In-class exercise

```quiz
type: html
q: Write a complete minimal HTML skeleton: doctype, html, head and body. Inside the head put a title whose content is "My Page".
starter: |
  <!DOCTYPE html>
  <html>
  </html>
checks:
- document.querySelectorAll('head').length === 1
- document.querySelectorAll('body').length === 1
- document.querySelectorAll('title').length === 1
- document.querySelector('title').textContent.trim() === 'My Page'
hint: The html element should contain two child elements, head and body, with the title placed inside the head.
explain: The standard skeleton requires head and body to sit side by side as direct children of html, with the title inside the head.
```

```quiz
type: choice
exam: true
q: Which statement about DOCTYPE is correct?
options:
- DOCTYPE is an ordinary tag and can be omitted
- DOCTYPE tells the browser which standard to use when parsing the page, and omitting it may trigger quirks mode
- DOCTYPE is used to set the page background colour
- DOCTYPE must be written inside the body
answer: 1
explain: DOCTYPE is a document-type declaration, not a tag, and it must come at the very start of the document. Omitting it causes the browser to enter quirks mode.
```

```quiz
type: html
exam: true
q: Write a pair of nested divs: the outer div has class="box", the inner div has class="inner", and inside the inner div put a p whose text is "content".
starter: |
  <div class="box">
  </div>
checks:
- document.querySelectorAll('.box').length === 1
- document.querySelectorAll('.inner').length === 1
- document.querySelector('.box > .inner') !== null
- document.querySelector('.inner > p') !== null
- document.querySelector('.inner > p').textContent.trim() === 'content'
hint: The inner div is a direct child of the outer div, and the p is a direct child of the inner div.
explain: The nested structure requires inner to be a child of box, and p to be a child of inner, forming the correct parent-child relationship.
```
