# Semantic Tags: header, nav, main, section, article and footer

> This lesson answers the question: "My page is nothing but divs, and machines cannot tell what it is about." Semantic tags let the structure speak for itself.

## The problem with a pile of divs

```html
<div class="header">Header</div>
<div class="nav">Navigation</div>
<div class="main">
  <div class="section">
    <div class="article">Body</div>
  </div>
</div>
<div class="footer">Footer</div>
```

This stack of divs renders without any problem, but **not one of these tags tells a machine "this is navigation" or "that is the main content"**. To a machine, this is just six boxes that look different.

## Semantic tags: give the structure the right name

```html
<header>Header</header>
<nav>Navigation</nav>
<main>
  <section>
    <article>Body</article>
  </section>
</main>
<footer>Footer</footer>
```

| Tag | Purpose |
|---|---|
| `<header>` | The head of a page or a block (title, logo, navigation) |
| `<nav>` | A set of navigation links |
| `<main>` | The page's main content; **one per page** |
| `<section>` | A thematic block of content, usually with a heading |
| `<article>` | A self-contained, independently distributable piece of content (a blog post, a comment) |
| `<footer>` | The foot of a page or a block (copyright, contact) |

## main may only appear once

`<main>` represents the page's **main content**. A page should have only one `<main>`. Screen reader users have a shortcut key, "jump to main content", and it is this main that they jump to. If Alice wrote two mains, the reader would not know which one to jump to.

## header and footer are not single-use

They can be nested inside any block:

```html
<article>
  <header>
    <h3>Article title</h3>
    <p>Published in September 2026</p>
  </header>
  <p>Body text...</p>
  <footer>
    <p>Tags: front-end, HTML</p>
  </footer>
</article>
```

Here, the header belongs to this article, not to the whole page. The semantics are "acting as a header inside some container", with no limit on how many times they may appear.

## The difference between section and article

The test is: **can this content stand alone, independently of its context?**

- Content that can stand alone (a blog post, a news item, a comment) → `<article>`
- A block of thematically related content ("About us", "Skills") → `<section>`

```html
<main>
  <section>
    <h2>My projects</h2>
    <article>
      <h3>Project one</h3>
      <p>A web scraper written in Python.</p>
    </article>
    <article>
      <h3>Project two</h3>
      <p>A to-do app built with Vue.</p>
    </article>
  </section>
</main>
```

Crash site 1: a section with no heading.

```html
<section>
  <p>Some content</p>
</section>
```

Consequence: the point of a section is "a block of content with a topic", and by the spec it should have a heading (h2-h6) stating that topic. A section with no heading has no semantics - in that case, a div would actually be more accurate.

Crash site 2: article inside article, treating section as a universal container.

```html
<article>
  <article>Nested content</article>
</article>
```

Consequence: article means "one complete, independent piece of content". One complete piece of content wrapping another complete piece creates a semantic contradiction. Nesting must follow the actual hierarchy of the content.

## Why this beats a pile of divs

1. **Accessibility**: screen reader users can jump by "landmark" - straight to nav or straight to main.
2. **SEO**: search engines find it easier to understand the page structure and to decide which parts are the main body and which are navigation.
3. **Maintainability**: six months later, `<main>` tells you immediately that this is the main content area; the class name `.main` could mean anything depending on who wrote it.

## Summary

- header, nav, main, section, article and footer each have clear semantics.
- main may appear only once per page, while header and footer can be used in several places.
- Use article for content that stands alone, section for a thematic block, and div only for a container with no theme.
- Semantics improve accessibility, SEO and code readability.

## In-class exercise

```quiz
type: html
q: Write a main containing a section, which contains an article. Inside the article put an h2 with the content "My projects" and a p with the content "Introduction".
starter: |
  <main>
  </main>
checks:
- document.querySelectorAll('main').length === 1
- document.querySelector('main > section') !== null
- document.querySelector('section > article') !== null
- document.querySelector('article > h2') !== null
- document.querySelector('article > h2').textContent.trim() === 'My projects'
hint: main directly contains section, section directly contains article, and article contains h2 and p.
explain: The semantic structure requires the three-level nesting to be correct, with the content inside the right tags.
```

```quiz
q: Which statement about semantic tags is correct?
options:
- Semantic tags only make the code look nice and serve no real purpose
- Semantic tags help screen readers and search engines understand the page structure
- Semantic tags render completely differently from an ordinary div
- A page may have any number of main elements
answer: 1
explain: Semantic tags provide structural and semantic information, improving accessibility and SEO. Their default rendering is the same as a div, and a page should have only one main.
```

```quiz
type: html
exam: true
q: Write a header containing a nav, which contains a ul with two li elements: Home and About. header and nav must be in a direct parent-child relationship.
starter: |
  <header>
  </header>
checks:
- document.querySelector('header > nav') !== null
- document.querySelector('nav > ul') !== null
- document.querySelectorAll('li').length === 2
- Array.from(document.querySelectorAll('li')).map(e => e.textContent.trim()).join(',') === 'Home,About'
hint: header directly contains nav, nav directly contains ul, and ul contains two li elements.
explain: The header-nav-list hierarchy requires the parent-child relationships to be correct.
```
