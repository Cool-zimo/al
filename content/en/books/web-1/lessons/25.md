# Transitions and animations: bring the page to life

> This lesson answers two questions: "How do I make a button change colour smoothly on hover?" and "How do I build a loading animation?" CSS animations need no JavaScript, and the browser accelerates them on the GPU for great performance.

## transition: the in-between

`transition` turns a property change from an instant jump into a smooth process.

```css
.button {
  background: #4a90d9;
  padding: 10px 20px;
  color: white;
  border: none;
  border-radius: 4px;
  transition: background 0.3s ease;
}

.button:hover {
  background: #357abd;
}
```

When the mouse moves over it, the background shifts from light blue to deep blue over 0.3 seconds instead of jumping instantly.

The full `transition` syntax:

```css
transition: property duration timing-function delay;
transition: background 0.3s ease 0s;
```

Four values:

- **Property**: which property to watch. `all` means every animatable property.
- **Duration**: `0.3s`, `300ms`.
- **Timing function**: `ease` (default), `linear`, `ease-in`, `ease-out`, `ease-in-out`.
- **Delay**: how many seconds to wait before starting.

Crash site 1: the transition does nothing because the value never changed.

```css
.box {
  transition: width 0.5s;
}
```

```html
<div class="box">Content</div>
```

Consequence: no transition at all. Why: a transition watches for **a change in a property value** — `.box`'s width was never changed (no hover, no class toggle). A transition cannot conjure an animation on its own; it needs a trigger.

Crash site 2: trying to transition the `display` property.

```css
.dropdown {
  display: none;
  transition: display 0.3s;
}
.dropdown.show {
  display: block;
}
```

Consequence: the transition does not work. `display` is a discrete property and cannot be interpolated. The jump from `none` to `block` can only be instant. To animate showing and hiding, use `opacity` plus `visibility`, or `max-height`.

## transform: translate, scale, rotate

`transform` can move, scale and rotate an element without affecting the layout.

```css
.card {
  transition: transform 0.2s ease;
}
.card:hover {
  transform: translateY(-4px); /* move up 4px */
}
```

```css
.zoom:hover {
  transform: scale(1.05);  /* grow by 5% */
}
.rotate {
  transform: rotate(45deg); /* rotate 45 degrees */
}
.skew {
  transform: skewX(10deg);  /* skew horizontally */
}
```

## transform beats left/top for performance

Changing `left` and `top` triggers a layout recalculation (reflow), whereas `transform` and `opacity` only trigger compositing, which the GPU handles — no reflow, no repaint.

Crash site 3: animating movement with `left`/`top` makes the page janky.

```css
.box {
  position: relative;
  left: 0;
  transition: left 0.5s;
}
.box:hover {
  left: 100px; /* triggers reflow */
}
```

The better way:

```css
.box {
  transform: translateX(0);
  transition: transform 0.5s;
}
.box:hover {
  transform: translateX(100px); /* GPU-accelerated, no reflow */
}
```

## @keyframes: keyframe animations

`transition` can only go from one state to another. `@keyframes` handles complex animations with many keyframes.

```css
@keyframes pulse {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.1); }
  100% { transform: scale(1); }
}

.loading {
  animation: pulse 1.5s ease infinite;
}
```

```html
<div class="loading">Loading…</div>
```

`pulse` defines three keyframes: original size → 10% larger → back to original. `infinite` means it loops forever.

Crash site 4: the animation vanishes the moment it finishes.

```css
.tip {
  animation: slideIn 0.5s ease;
}
```

Consequence: once the animation ends, the element snaps back to its initial state (`transform: none`). If you want it to stay at the final frame, add `forwards`:

```css
.tip {
  animation: slideIn 0.5s ease forwards;
}
```

## Summary

- `transition` smooths a property change, but it needs a trigger.
- The property being watched must be interpolatable (`display` is not).
- `transform` handles translate/scale/rotate and is GPU-accelerated without reflow.
- For movement, prefer `transform` over `left`/`top`.
- `@keyframes` defines multi-keyframe animations; `forwards` keeps the end state.

## In-class exercise

```quiz
type: css
q: Make .btn default to a #4a90d9 background, switch to #357abd on hover, with a transition of 0.3s and ease timing.
html: |
  <button class="btn">Submit</button>
starter: |
  .btn {
    background: #4a90d9;
    color: white;
    padding: 10px 24px;
    border: none;
    border-radius: 4px;
  }
checks:
- getComputedStyle(document.querySelector('.btn')).transition.startsWith('background 0.3s')
- getComputedStyle(document.querySelector('.btn')).backgroundColor === 'rgb(74, 144, 217)'
hint: Use a transition to watch the background property, set to 0.3s ease.
explain: A transition makes the background colour change on hover smooth instead of instant.
```
