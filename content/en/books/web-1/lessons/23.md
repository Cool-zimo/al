# Relative units and fluid layout

> This lesson answers the question: "Why shouldn't I hard-code widths?" and "How do I choose between rem, em, %, and vw?" Pick the right unit and your layout flows with the screen.

## Why you should not hard-code widths

Writing `width: 1200px` means your layout only works at 1200px and above. At any other size it either overflows or leaves huge gaps.

The fluid-layout idea is: **let sizes follow the parent container or the viewport**.

```css
/* Hard-coded: inflexible */
.container-fixed {
  width: 1000px;
}

/* Fluid: follows the parent */
.container-fluid {
  width: 100%;
  max-width: 1200px;  /* cap it so huge screens do not run wild */
  margin: 0 auto;     /* centre it */
}
```

`max-width: 1200px` is a great habit: it fills 100% on a narrow screen, caps at 1200px on a wide one and centres neatly.

## Percentages: relative to the parent

```css
.child {
  width: 50%; /* half of the parent's width */
}
```

A percentage is always relative to the **parent's corresponding property**. `width: 50%` is relative to the parent's width, and `padding-top: 50%` is also relative to the parent's width (yes — even a vertical percentage padding is calculated from the width).

Crash site 1: a percentage height that does not work.

```css
.child {
  height: 50%; /* might not work */
}
```

Consequence: the child's height is zero. Why: a percentage height depends on the parent having an explicit height; if the parent's height is `auto` (driven by content), the child's `height: 50%` has nothing to reference. Fix: give the parent a fixed height or use `min-height`.

## rem and em: relative to font size

- `rem`: relative to the **root element's (`html`)** font size. The default root size is 16px, so `1rem = 16px` and `1.5rem = 24px`.
- `em`: relative to the **current element's** font size.

```css
html {
  font-size: 16px; /* root font size */
}

.box {
  font-size: 1.2rem;  /* 19.2px, relative to the root */
  padding: 1rem;      /* 16px */
  margin: 0.5em;       /* relative to its own font size = 9.6px */
}
```

Crash site 2: `em` compounds through nested elements.

```css
body { font-size: 16px; }
.level-1 { font-size: 1.2em; }   /* 19.2px */
.level-2 { font-size: 1.2em; }   /* 23.04px! */
.level-3 { font-size: 1.2em; }   /* 27.65px! */
```

Consequence: each nesting level multiplies the em against the previous one, growing bigger and bigger until it is out of control. Fix: use `rem` consistently — it only references the root size and never compounds.

## vw / vh: relative to the viewport

- `vw`: 1% of the viewport width. `100vw` = full screen width.
- `vh`: 1% of the viewport height. `100vh` = full screen height.

```css
.hero {
  width: 100vw;
  height: 100vh;        /* fill the entire screen */
  font-size: 4vw;       /* font size follows the screen width */
}
```

Crash site 3: `100vw` causes a horizontal scrollbar.

```css
body {
  margin: 0;
}
.full {
  width: 100vw; /* includes the scrollbar width! */
}
```

Consequence: `100vw` includes the browser's scrollbar width, which can produce a horizontal scrollbar. Fix: use `width: 100%` instead.

## Putting fluid layout to work

```css
img {
  max-width: 100%;
  height: auto; /* scale while keeping the aspect ratio */
}

.container {
  width: 100%;
  max-width: 1200px;
  margin: 0 auto;
  padding: 0 16px;
}

.card {
  flex: 1 1 300px; /* 300px basis, can grow or shrink */
}
```

Three techniques:

1. `max-width: 100%` plus `height: auto` on images keeps them from overflowing and from distorting.
2. A container using `max-width` plus `margin: auto` works on both narrow and wide screens.
3. A Flex item using `flex: 1 1 300px` makes a fluid card grid (combined with `flex-wrap`).

## Summary

- Hard-coded widths are inflexible; fluid layout lets sizes follow the container or viewport.
- `max-width` handles both filling on narrow screens and capping on wide ones.
- `rem` is relative to the root and never compounds; `em` compounds on nesting, so use it with care.
- `vw`/`vh` are relative to the viewport; `100vw` may include the scrollbar width.
- Give images `max-width: 100%; height: auto` for fluid scaling.

## In-class exercise

```quiz
type: css
q: Make .container 100% wide, with a maximum width of 1000px, horizontally centred (margin: 0 auto) and 20px of left and right padding.
html: |
  <div class="container">Content area</div>
starter: |
  .container {
  }
checks:
- Math.abs(parseFloat(getComputedStyle(document.querySelector('.container')).width) - document.body.clientWidth) < 3
- getComputedStyle(document.querySelector('.container')).maxWidth === '1000px'
- getComputedStyle(document.querySelector('.container')).marginLeft === getComputedStyle(document.querySelector('.container')).marginRight
- getComputedStyle(document.querySelector('.container')).paddingLeft === '20px'
- getComputedStyle(document.querySelector('.container')).paddingRight === '20px'
hint: width: 100% fills the space, max-width caps it, and equal left/right margin centres it.
explain: A fluid container combines width: 100%, a max-width cap and auto margins for centring, working well at every screen size.
```
