# Project design: planning a personal CV page

> This lesson answers the question: "Where do I start when I am given a page requirement?" A good front-end developer does not open the editor and start writing `<div>` straight away — they think through the structure, the colour scheme and the information hierarchy first.

## Structure before style

Many beginners open the editor the moment they get the brief and start writing `<div>`. Halfway through they realise the structure is a mess and start over. The right approach is to **sketch first, code second**.

Our project is a "personal CV page", containing the following:

| Section | Content | Tag to use |
|---|---|---|
| Header | Name, role, contact details | `<header>` |
| About me | A self-introduction paragraph | `<section>` |
| Skills | A skill list (languages / frameworks) | `<section>` + `<ul>` |
| Work experience | A timeline | `<section>` + `<ul>` |
| Projects | Project cards | `<section>` + `<article>` |
| Footer | Copyright / social links | `<footer>` |

## The benefits of a semantic structure

```html
<header>
  <h1>Alice Chen</h1>
  <p>Front-end Engineer</p>
</header>
<section>
  <h2>About me</h2>
  <p>Five years of web development experience…</p>
</section>
```

Using `<header>`, `<section>` and `<footer>` instead of a pile of `<div>`s:

1. **SEO-friendly**: search engines understand the page structure.
2. **Accessible**: screen readers can navigate by region.
3. **Readable**: when you come back six months later you know at a glance what each region does.

## The colour scheme

A CV page does not need to be flashy — two or three main colours are enough:

| Role | Value | Use |
|---|---|---|
| Primary | `#2c3e50` | Headings and emphasis |
| Accent | `#4a90d9` | Links, buttons, timeline markers |
| Background | `#f8f9fa` | Page background |
| Card | `#ffffff` | Card background |
| Body text | `#333333` | Body copy |

Crash site 1: you use a pile of highly saturated colours and the page looks like a rainbow.

Consequence: there is too much visual noise and the user does not know where to look. A CV is an information page — the colour scheme should be restrained, guiding the eye rather than scattering attention.

## Information hierarchy

The information on a CV has a hierarchy, built with font size and spacing:

- **Name**: the largest size (2rem–2.5rem), primary colour
- **Section headings** (About me, Skills, Experience): 1.5rem, primary colour, bold
- **Body copy**: 1rem, body colour, line-height 1.6
- **Supporting info** (dates, locations): 0.875rem, grey

```css
:root {
  --color-primary: #2c3e50;
  --color-accent: #4a90d9;
  --color-bg: #f8f9fa;
  --color-card: #ffffff;
  --color-text: #333333;
  --color-muted: #888888;
}

h1 { font-size: 2rem; color: var(--color-primary); }
h2 { font-size: 1.5rem; color: var(--color-primary); }
body { font-size: 1rem; color: var(--color-text); line-height: 1.6; }
```

Notice the `--color-*` notation — these are **CSS variables** (Custom Properties). Define them once and reuse them everywhere. Lesson 28 covers them in detail.

## Layout planning

The CV page uses the following layout strategy overall:

- **Page container**: `max-width: 900px`, centred
- **Section spacing**: `margin-bottom: 48px`, leaving breathing room between regions
- **Cards**: white background, 8px radius, subtle shadow
- **Mobile**: single-column stack; at `>= 768px` some sections become two columns

## Summary

- Plan the structure before writing code; sketching is more efficient than diving straight in.
- Semantic tags (header / section / footer) improve SEO and accessibility.
- Keep the colour scheme restrained — two or three main colours are enough, letting colour guide the eye.
- Font size and spacing build the information hierarchy so the user sees the priorities at a glance.
- CSS variables give centralised control of colours and spacing for easy later adjustment.

## In-class exercise

```quiz
type: html
q: Write the header structure for a CV page: an h1 inside the header with the content "Alice Chen", followed by a p with the content "Front-end Engineer", then a nav containing three a links: Email, GitHub and Portfolio.
starter: |
  <header>
  </header>
checks:
- document.querySelector('header h1').textContent.trim() === 'Alice Chen'
- document.querySelector('header p').textContent.trim() === 'Front-end Engineer'
- document.querySelector('header nav') !== null
- document.querySelectorAll('header nav a').length === 3
- Array.from(document.querySelectorAll('header nav a')).map(a => a.textContent.trim()).join(',') === 'Email,GitHub,Portfolio'
hint: Put h1, p and nav inside the header in that order, with three a tags inside the nav.
explain: The header groups personal information and social navigation links as the page's header region.
```

```quiz
type: choice
exam: true
q: Why should you "plan the structure before writing the styles" when building a page?
options:
- Because HTML is harder to write than CSS
- Because deciding the information hierarchy and semantic structure first avoids rework later
- Because the browser must load HTML before it can load CSS
- Because CSS variables must be defined before HTML
answer: 1
explain: Planning the structure and information hierarchy first makes the subsequent styling more organised and avoids rework caused by a messy structure. This is the workflow of a professional front-end developer.
```
