# display: the three states of block, inline and inline-block

> This lesson answers the question: "Why do some elements take up a whole line while others sit side by side and refuse to accept a width?" `display` decides how an element exists in the normal flow, and it is the starting point for every layout you will ever build.

## Three kinds of display behaviour

Every HTML element has a default `display` value. The `<div>` you have used so many times defaults to `block`; `<span>` defaults to `inline`; and `<img>` is `inline-block`. These three behaviours decide how an element claims space.

```html
<div class="box block">I am block</div>
<div class="box block">I am block too</div>
<span class="box inline">I am inline</span>
<span class="box inline">I am inline too</span>
<span class="box inline-block">I am inline-block</span>
<span class="box inline-block">I am inline-block too</span>
```

```css
.box {
  width: 200px;
  height: 60px;
  padding: 10px;
  margin: 5px;
  background: #e0f0ff;
  border: 1px solid #4a90d9;
}
.block { display: block; }
.inline { display: inline; }
.inline-block { display: inline-block; }
```

The core differences are summarised below:

| Behaviour | Takes a full line | Can set width/height | Can set top/bottom margin |
|---|---|---|---|
| block | Yes,独占一行 | Yes | Yes |
| inline | No, sits in the flow | No | Top/bottom margin does nothing |
| inline-block | No, sits in the flow | Yes | Yes |

## block: the big one that claims a whole line

A `block` element fills the width of its parent by default (100% of the parent when no width is set), with an automatic line break before and after. Common block elements are `<div>`, `<p>`, `<h1>`–`<h6>`, `<section>` and `<li>`.

```css
div {
  display: block; /* default, can be omitted */
  width: 300px;
  height: 100px;
  margin: 20px;
}
```

Because a block element owns its line, two divs stack vertically, each taking the full width.

## inline: flows with the text

An `inline` element's width and height are decided by its content. You cannot manually set `width` or `height`. Left and right margins work, but top and bottom margins do nothing. Common inline elements are `<span>`, `<a>`, `<strong>` and `<em>`.

```css
span {
  display: inline; /* default, can be omitted */
  width: 200px;    /* ignored! */
  height: 60px;    /* ignored! */
  margin-top: 20px; /* ignored! */
}
```

Crash site 1: you set a width on a span and nothing happens.

```css
span.badge {
  width: 100px;
  height: 40px;
  background: red;
  color: white;
}
```

Consequence: the span's width is still decided by the text, so the 100px and 40px you set are completely ignored. On the page the badges clump together and the text overflows. Fix: change to `display: inline-block` or `display: block`.

## inline-block: side by side AND a size

`inline-block` combines the best of both worlds: it sits beside text and other elements like `inline` does, but it accepts a width, height and top/bottom margins like `block`. Navigation menus, button groups and card grids are its typical uses.

```css
.menu-item {
  display: inline-block;
  width: 120px;
  height: 40px;
  line-height: 40px;
  text-align: center;
  margin: 0 5px;
  background: #4a90d9;
  color: white;
}
```

Now every menu item has a fixed width and height and sits side by side. Perfect.

Crash site 2: mysterious gaps appear between inline-block elements.

```html
<nav>
  <a href="#">Home</a>
  <a href="#">About</a>
  <a href="#">Contact</a>
</nav>
```

```css
nav a {
  display: inline-block;
  width: 100px;
  background: #4a90d9;
}
```

Consequence: there is roughly a 4px blank gap between each `a`. This is not a bug — the line break between inline-block elements is treated as a space. The fix is to set `font-size: 0` on the parent and restore the font size on the children, or simply use Flex (covered in lessons 19 and 20, where this problem does not exist at all).

## display is the foundation of every layout

Every advanced layout technique — float, position, flex and grid — works by changing an element's `display` behaviour. Understand these three basic forms and you can trace every layout quirk you meet back to this lesson.

## Summary

- `block` claims a whole line and accepts a width, height and every margin.
- `inline` flows with the content; width and height cannot be set, and top/bottom margin does nothing.
- `inline-block` behaves like inline on the outside and block on the inside: it sits beside siblings and keeps its own size.
- A line break between inline-block elements creates a blank gap — a classic trap.

## In-class exercise

```quiz
type: css
q: Make span.item inline-block with a width of 120px, a height of 40px and a blue background (#4a90d9).
html: |
  <span class="item">Front-end</span><span class="item">Back-end</span>
starter: |
  .item {
  }
checks:
- getComputedStyle(document.querySelector('.item')).display === 'inline-block'
- getComputedStyle(document.querySelector('.item')).width === '120px'
- getComputedStyle(document.querySelector('.item')).height === '40px'
- getComputedStyle(document.querySelector('.item')).backgroundColor === 'rgb(74, 144, 217)'
hint: Change display to inline-block, then set width and height.
explain: inline-block lets an inline element keep a settable width and height at the same time.
```
