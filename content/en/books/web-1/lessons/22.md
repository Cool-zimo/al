# The viewport and media queries

> This lesson answers two questions: "Why does my page shrink into a thumbnail on a phone?" and "How do I write different CSS for different screens?"

## The viewport: the mobile rendering switch

Adding this line inside `<head>` is the very first step of every mobile page:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

What happens if you leave it out?

Crash site 1: you forget the viewport meta tag.

Consequence: the mobile browser assumes your page was designed for a 980px-wide desktop screen, so it shrinks the whole page to fit the phone — the entire page becomes a thumbnail and the text is too small to read. The user has to zoom manually.

Once you add `width=device-width`, the browser uses the device's real width (an iPhone's 375px or 414px, for example) as the viewport width, and the page renders at its actual size.

`initial-scale=1.0` means the initial zoom is 1, preventing the browser from auto-scaling.

## The syntax of media queries

```css
@media (condition) {
  /* CSS that applies when the condition is met */
}
```

The most common condition is **width**:

```css
@media (max-width: 767px) {
  .sidebar {
    display: none; /* hide the sidebar on phones */
  }
}

@media (min-width: 768px) and (max-width: 1023px) {
  .card {
    width: 50%; /* two per row on a tablet */
  }
}

@media (min-width: 1024px) {
  .card {
    width: 33.33%; /* three per row on a desktop */
  }
}
```

## How to choose breakpoints

A breakpoint should not be dictated by a specific device (because device sizes keep changing). It should be dictated by **your own content**.

When your layout looks "cramped" or "too empty" at a certain width, that is where a breakpoint belongs.

Common reference breakpoints:

| Breakpoint | Typical scenario |
|---|---|
| 480px | Small-screen phone |
| 768px | Tablet portrait / phone landscape |
| 1024px | Tablet landscape / small laptop |
| 1200px | Desktop monitor |

Crash site 2: a breakpoint set too rigidly, covering only a specific model.

```css
@media (width: 375px) {
  /* only kicks in when the iPhone happens to be exactly 375px wide */
}
```

Consequence: a phone with any other size (390px or 360px) misses it completely. The right approach is to use **ranges** (`min-width` / `max-width`), not exact values.

## Mobile-first breakpoint writing

Use `min-width` to enhance progressively from narrow to wide:

```css
/* Default: applies on every screen (the mobile styles) */
.nav { flex-direction: column; }

/* Small screens and up */
@media (min-width: 600px) {
  .nav { flex-direction: row; }
}

/* Medium screens and up */
@media (min-width: 900px) {
  .nav { justify-content: space-between; }
}
```

Each breakpoint writes only the **delta** — the new or changed properties on top of the default. The code stays shorter and easier to maintain.

## What else media queries can check

Beyond width, media queries can also detect:

```css
/* Landscape / portrait */
@media (orientation: landscape) { ... }

/* When printing */
@media print { .no-print { display: none; } }

/* Dark mode */
@media (prefers-color-scheme: dark) { body { background: #222; } }
```

Crash site 3: repeating a lot of identical code inside a media query.

```css
.card {
  padding: 16px;
  margin: 8px;
  background: white;
  border-radius: 8px;
}
@media (min-width: 768px) {
  .card {
    padding: 16px;
    margin: 8px;
    background: white;
    border-radius: 8px;
    width: 50%;  /* the only thing you actually wanted to change */
  }
}
```

Consequence: redundant, hard-to-maintain code. Fix: write the full default styles once and **override only the properties that need to change** inside the media query.

## Summary

- The viewport meta tag is essential for mobile pages; without it the page renders as a thumbnail.
- Media queries wrap conditional CSS in `@media (condition)`.
- Breakpoints are dictated by content; use ranges (min/max-width), not exact values.
- The mobile-first strategy uses min-width to enhance progressively, with each breakpoint writing only a delta.

## In-class exercise

```quiz
type: css
q: Write a media query so that when the screen width is >= 768px, .box becomes 50% wide and its font size becomes 18px.
html: |
  <div class="box">Responsive box</div>
starter: |
  .box {
    width: 100%;
    font-size: 14px;
  }
checks:
- getComputedStyle(document.querySelector('.box')).fontSize === '18px'
- Math.abs(parseFloat(getComputedStyle(document.querySelector('.box')).width) - document.body.clientWidth * 0.5) < 3
hint: Wrap the wide-screen overrides in @media (min-width: 768px).
explain: Write the narrow-screen defaults first, then override the changing properties at the wide breakpoint.
```
