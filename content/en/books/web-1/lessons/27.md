# Building the HTML skeleton: semantic tags for the CV

> This lesson turns the design from the previous lesson into HTML. The focus is **picking the right tag** — give every region the tag that fits it best, so the structure itself becomes the document.

## The complete CV skeleton

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Alice Chen — Front-end Engineer</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header class="site-header">
    <h1>Alice Chen</h1>
    <p class="title">Front-end Engineer</p>
    <nav class="social">
      <a href="mailto:alice@example.com">Email</a>
      <a href="https://github.com">GitHub</a>
      <a href="https://juejin.cn">Portfolio</a>
    </nav>
  </header>

  <main>
    <section class="about">
      <h2>About me</h2>
      <p>Five years of web development experience, focused on front-end engineering and user experience optimisation…</p>
    </section>

    <section class="skills">
      <h2>Skills</h2>
      <ul>
        <li>JavaScript / TypeScript</li>
        <li>React / Vue</li>
        <li>Node.js</li>
      </ul>
    </section>

    <section class="experience">
      <h2>Work experience</h2>
      <article class="job">
        <h3>Senior Front-end Engineer · Acme Corp</h3>
        <time>2022.03 — Present</time>
        <p>Responsible for the front-end architecture and development of the company's core products…</p>
      </article>
    </section>

    <section class="projects">
      <h2>Projects</h2>
      <article class="project-card">
        <h3>E-commerce admin system</h3>
        <p>A management platform built on Vue 3 and Element Plus…</p>
      </article>
    </section>
  </main>

  <footer class="site-footer">
    <p>© 2026 Alice Chen · Made with ❤️</p>
  </footer>
</body>
</html>
```

## Why wrap the body in `<main>`?

`<main>` represents the page's main content. There should be exactly one per page. It helps screen-reader users skip the navigation and jump straight to the content.

## Why `<article>` for jobs and projects?

`<article>` represents content that is **independent and distributable**. A job description or a project card could, in principle, stand on its own (for example, be quoted on another page), so `article` is the right choice.

## Why `<time>` for dates?

```html
<time datetime="2022-03">2022.03 — Present</time>
```

The `datetime` attribute on `<time>` provides a machine-readable date format that search engines and browsers can parse. The user sees the friendlier "2022.03 — Present".

Crash site 1: the whole page is nothing but divs.

```html
<div class="header">
  <div class="title">Alice Chen</div>
</div>
<div class="main">
  <div class="section">
    <div class="section-title">About me</div>
    <div class="text">...</div>
  </div>
</div>
```

Consequence: it renders, but there is no semantics at all — poor SEO, poor accessibility and hard to understand the structure when maintaining it. "A div for everything" is the most common beginner habit.

## The nesting between regions

Notice that a `<section>` can contain `<article>`, and an `<article>` can have its own `<h3>` and subsections:

```
<body>
  <header>          ← the head
  <main>            ← the body
    <section>       ← region: about me
    <section>       ← region: skills
    <section>       ← region: experience
      <article>     ← an independent experience entry
    <section>       ← region: projects
      <article>     ← an independent project card
  <footer>          ← the bottom
```

The hierarchy h1 → h2 → h3 follows this structure. Heading levels must not skip (jumping straight from h1 to h3) or screen-reader users will be confused.

## Summary

- The CV skeleton is built with header / main / section / article / footer.
- The rule for picking tags is "the most semantic match", not "whatever renders".
- main is unique; article means independent, distributable content; time provides a machine-readable date.
- Heading levels h1 → h2 → h3 do not skip and reflect the nesting of the content.

## In-class exercise

```quiz
type: html
q: Write a section with class "projects" containing an h2 with the content "Projects" and two articles, each containing an h3 (project name) and a p (description). The project names are "Online shop" and "Data visualisation platform", and the descriptions are "A React-based e-commerce front end" and "A data dashboard built on ECharts".
starter: |
  <section class="projects">
  </section>
checks:
- document.querySelector('.projects h2').textContent.trim() === 'Projects'
- document.querySelectorAll('.projects article').length === 2
- document.querySelectorAll('.projects article h3').length === 2
- document.querySelectorAll('.projects article')[0].querySelector('h3').textContent.trim() === 'Online shop'
- document.querySelectorAll('.projects article')[0].querySelector('p').textContent.trim() === 'A React-based e-commerce front end'
- document.querySelectorAll('.projects article')[1].querySelector('h3').textContent.trim() === 'Data visualisation platform'
- document.querySelectorAll('.projects article')[1].querySelector('p').textContent.trim() === 'A data dashboard built on ECharts'
hint: The section contains an h2 and two articles, each containing h3 + p.
explain: section is the project region and article represents each independent project card, for a clean structure.
```

## Section quiz

```quiz
type: choice
exam: true
q: Which statement about `<article>` and `<section>` is correct?
options:
- article and section are exactly the same; either will do
- article represents independent, distributable content; section represents a thematic grouping of content
- section can only be placed inside article
- article cannot contain a heading
answer: 1
explain: article is for independent, separately distributable content (a blog post, a card); section is for a thematic grouping of related content. They can nest, and article can have its own heading inside.
```
