# Why responsive design matters

> This lesson answers the question: "How can one codebase look good on both a phone and a desktop?" Responsive is not a bonus feature — in 2026 it is a baseline requirement. Mobile traffic is already the mainstream.

## A real problem

You build a page, open it on a desktop and the three-column layout looks perfect. Then you open it on a phone and the text is too small to read, the content overflows horizontally and you have to swipe left and right to finish a single line.

That is not the user's problem. It is your code.

```html
<div class="container">
  <aside class="sidebar">Sidebar</aside>
  <main class="content">Main content</main>
  <aside class="ads">Advertisements</aside>
</div>
```

```css
.container { width: 1200px; }
.sidebar { width: 200px; float: left; }
.content { width: 800px; float: left; }
.ads { width: 200px; float: left; }
```

This CSS is fine above 1200px. But on an iPhone at 375px, the container's 1200px far exceeds the screen, the whole page overflows horizontally and the user has to scroll sideways.

## The core idea of responsive design

**One codebase, many presentations.** You do not build two sites (one mobile, one desktop); you let the same HTML and CSS adjust the layout automatically according to the screen width.

```css
/* Default: mobile first */
.container {
  display: flex;
  flex-direction: column;
}

/* When the screen gets wider: switch to three columns */
@media (min-width: 768px) {
  .container {
    flex-direction: row;
  }
}
```

On a phone the container stacks vertically; above 768px it becomes a horizontal three-column layout. One HTML, two layouts.

## Three key ingredients

Responsive design depends on three things:

1. **Fluid layout**: use percentages, flex and grid instead of fixed pixels.
2. **Flexible images**: images scale with their container and never overflow.
3. **Media queries**: switch styles at breakpoints.

Crash site 1: you hard-code a width and make no adaptation at all.

```css
.page {
  width: 1000px;
}
```

Consequence: on a phone the page overflows horizontally and the user has to swipe. This was normal before 2010; today users just close the tab.

Crash site 2: you hard-code one size for phones and forget that desktops will stretch it out of shape.

```css
.card {
  width: 90vw;  /* 90% of the viewport on a phone — about 340px */
  font-size: 14px;
}
```

Consequence: on a 27-inch monitor the card is nearly 2400px wide and one line of text stretches halfway across the screen. The reading experience is terrible.

## Mobile-first vs desktop-first

There are two schools of thought:

**Mobile-first (recommended)**: write the mobile styles first (the default), then progressively enhance with `min-width` media queries.

```css
.card {
  width: 100%;
  padding: 12px;
}
@media (min-width: 768px) {
  .card {
    width: 50%;
    padding: 24px;
  }
}
```

**Desktop-first**: write the desktop styles first, then scale back with `max-width`.

```css
.card {
  width: 33.33%;
  float: left;
}
@media (max-width: 767px) {
  .card {
    width: 100%;
    float: none;
  }
}
```

Mobile-first fits the idea of progressive enhancement and is the mainstream approach today.

## Summary

- Responsive = one codebase that looks different at different screen sizes.
- The three pillars: fluid layout, flexible images, media queries.
- Mobile-first is the recommended strategy, using `min-width` to enhance progressively.
- Hard-coding fixed widths is the greatest enemy of responsive design.
