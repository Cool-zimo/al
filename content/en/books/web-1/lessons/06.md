# Three Ways to Write CSS

> This lesson answers the question: "Where does CSS go?" All three ways work, but their maintenance costs are very different.

## Method 1: Inline styles

```html
<p style="color: red; font-size: 16px;">Some red text</p>
```

Written directly in the tag's `style` attribute. Inline styles have the highest priority and can override the other methods. But the problem is equally obvious: the style is bound tightly to the tag, so changing ten places means editing ten places.

## Method 2: the style tag (internal stylesheet)

```html
<head>
  <style>
    p {
      color: #333;
      line-height: 1.6;
    }
    .intro {
      font-size: 18px;
    }
  </style>
</head>
```

Written in a `<style>` element inside `<head>`. You can define many rules at once, which is enough for a single page. But if your site has twenty pages and you want to change the heading colour everywhere, you have to open all twenty files.

## Method 3: an external stylesheet

```html
<head>
  <link rel="stylesheet" href="style.css">
</head>
```

Create a separate `style.css` file:

```css
body {
  font-family: "PingFang SC", sans-serif;
  color: #333;
}
h1 {
  color: #2c7a7b;
}
```

This is the **recommended** method, for three reasons:

1. **Change it once and the whole site updates.** Change one file and every page is updated together.
2. **Caching.** After the browser downloads `style.css` once, it caches it, so later pages do not need to download it again and load faster.
3. **Structure and style are separated.** HTML handles structure and CSS handles presentation, each doing its own job and making the code easier to read.

Alice built a CV page and put all her styles in `style.css`. When she later wanted a new accent colour, she changed one line and the whole site updated. If she had used style tags, she would have had to hunt through every file.

## The priority order of the three methods

When all three methods act on the same element, **the more specific and the closer to the element wins**:

inline `style` > internal `<style>` ≈ external `<link>` > browser default styles

The latter two have the same priority and are decided by their order in the HTML: whichever appears later overrides whichever came first.

Crash site 1: using inline styles to "make a quick fix".

```html
<h1 style="color: red;">Title</h1>
<h1 style="color: red;">Subtitle</h1>
<h1 style="color: red;">Another one</h1>
```

Consequence: all three h1s are red. When Alice later wanted teal, she had to change three places. If she had written `.title { color: red; }` and added `class="title"` to the three h1s, one change would have been enough.

Crash site 2: the external path is wrong.

```html
<link rel="stylesheet" href="css/style.css">
```

Consequence: the file is actually at `styles/main.css`, the path is wrong, the styles do not apply at all, and the page is left "naked" in default styles. Open the browser's developer tools and look at the Network panel: the CSS file returns 404.

## Your first styles

```css
h1 {
  color: #2c7a7b;
  font-size: 32px;
}
```

This structure is called a **rule**: `h1` is the selector (which elements to pick), the braces hold the **declaration block**, and each declaration is a "property: value" pair.

## Summary

- Three methods: inline, internal and external - with external the recommended one.
- External stylesheets offer centralised maintenance, browser caching and separation of structure from style.
- Priority order: inline > internal ≈ external > browser default.
- A selector plus a declaration block makes one CSS rule.

## In-class exercise

```quiz
type: css
q: Make the text colour of every p element on the page a dark grey, rgb(51, 51, 51).
html: |
  <p>First paragraph</p>
  <p>Second paragraph</p>
starter: |
  p {
  }
checks:
- getComputedStyle(document.querySelectorAll('p')[0]).color === 'rgb(51, 51, 51)'
- getComputedStyle(document.querySelectorAll('p')[1]).color === 'rgb(51, 51, 51)'
hint: Use the color property with an rgb value.
explain: The tag selector p matches every paragraph, and color sets the text colour.
```
