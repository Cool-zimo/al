# Tables: table, tr, td and th

> This lesson answers the question: "How do I present data laid out in rows and columns?" A table should be used only for tabular data, never for page layout.

## A complete table

```html
<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>City</th>
      <th>Monthly salary</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Alice</td>
      <td>Beijing</td>
      <td>&pound;25,000</td>
    </tr>
    <tr>
      <td>Bob</td>
      <td>Shanghai</td>
      <td>&pound;22,000</td>
    </tr>
  </tbody>
</table>
```

How the tags divide the work:

| Tag | Meaning |
|---|---|
| `<table>` | The table container |
| `<tr>` | A row (table row) |
| `<th>` | A header cell (table header) |
| `<td>` | A normal cell (table data) |
| `<thead>` | The header section |
| `<tbody>` | The body section |
| `<tfoot>` | The footer section (optional) |

## Header cells use th, not td

```html
<thead>
  <tr>
    <th>Name</th>
    <th>City</th>
  </tr>
</thead>
```

`<th>` is **bold and centred by default**. More importantly, it carries semantics: it tells the browser and screen readers "this is a column heading". When a screen reader user browses by column, they hear "Name column, Beijing, Shanghai...", with the context clear.

Crash site 1: using td for a header cell.

```html
<tr>
  <td>Name</td>
  <td>City</td>
</tr>
```

Consequence: visually, you can use CSS to bold and centre a td so it looks the same. But semantically these cells are ordinary data cells, so a screen reader will not treat them as headers and accessibility is lost. Spend the extra two characters on th - the benefit is real.

## thead and tbody make the structure clearer

Even if you do not write thead and tbody, the browser will insert them automatically. But writing them **explicitly** has several benefits:

1. Styles are easier to control - you can give thead its own background colour and tbody alternating row colours.
2. When printed, long tables repeat the header automatically.
3. The code is easier to read; you can see at a glance which part is the header.

## Tables must not be used for layout

In the early days, before flex and grid existed, front-end engineers used tables (`table > tr > td`) to assemble multi-column layouts. This approach is now **deprecated**:

```html
<!-- An example of what not to do -->
<table>
  <tr>
    <td>Left sidebar</td>
    <td>Main content</td>
    <td>Right sidebar</td>
  </tr>
</table>
```

Consequence: semantically this is "a table", but it actually holds layout content. A screen reader announces it as a table, and the user hears "table, three columns" - completely misleading. And changing the layout means touching the HTML structure, which is expensive to maintain.

When should you use a table? **When the data is naturally tabular**: grade sheets, price lists, schedules, parameter comparisons. The test is simple - would it make sense to turn this content into a spreadsheet? If yes, use a table; otherwise use flex or grid.

Crash site 2: hand-rolling a "fake table" with divs while discarding table semantics.

```html
<div class="row">
  <div>Name</div>
  <div>City</div>
</div>
```

If you are only displaying tabular data, this approach is worse than using `<table>` - you have reinvented the wheel and lost the header semantics. When the data is a table, use table.

## Summary

- table > tr > (th/td): the hierarchy is clear - table, then row, then cell.
- Header cells use `<th>`: clear semantics, bold and centred by default.
- Write thead/tbody explicitly for easier styling and readability.
- Tables are only for tabular data; never use them for page layout.

## In-class exercise

```quiz
type: html
q: Write a table where the thead has one row with two th cells, "Product" and "Price", and the tbody has one row with two td cells, "Laptop" and "&pound;5,000".
starter: |
  <table>
  </table>
checks:
- document.querySelectorAll('table').length === 1
- document.querySelectorAll('th').length === 2
- document.querySelectorAll('td').length === 2
- document.querySelector('th').textContent.trim() === 'Product'
- document.querySelectorAll('td')[1].textContent.trim() === '£5,000'
hint: Put the th row inside the thead and the td row inside the tbody.
explain: The thead holds the header row of th cells, and the tbody holds the data row of td cells, making the structure complete.
```
