# Lists: ul, ol and dl

> This lesson answers the question: "How do I organise a group of parallel items?" Why does a navigation menu use a list? Because it already is "a set of parallel options".

## Three kinds of list

```html
<!-- Unordered list -->
<ul>
  <li>Apple</li>
  <li>Banana</li>
  <li>Orange</li>
</ul>

<!-- Ordered list -->
<ol>
  <li>Open the browser</li>
  <li>Type in the URL</li>
  <li>Press Enter</li>
</ol>

<!-- Description list -->
<dl>
  <dt>HTML</dt>
  <dd>The structural language of web pages</dd>
  <dt>CSS</dt>
  <dd>The styling language of web pages</dd>
</dl>
```

- `<ul>` is an unordered list: the order does not matter, and a small bullet appears in front.
- `<ol>` is an ordered list: the order matters, and a number appears in front.
- `<dl>` is a description list: a set of "term - explanation" pairs, good for glossaries and parameter documentation.

## li is the real member of a list

```html
<ul>
  <li>First item</li>
  <li>Second item</li>
</ul>
```

Only `<li>` may be placed directly inside `<ul>` or `<ol>`. Writing other tags there is not valid by the spec; the browser may still render it, but the structure is not clean.

Crash site 1: writing text directly inside a list without using li.

```html
<ul>
  Apple
  Banana
  Orange
</ul>
```

Consequence: the browser displays it, but the `<ul>` contains only text nodes with no li elements, so semantically it is not a list. A screen reader will not announce it as a list, and CSS selectors cannot target "list items".

## Why navigation uses ul

What is navigation, at its core? It is "a set of parallel jump links". That is exactly what a list expresses.

```html
<nav>
  <ul class="menu">
    <li><a href="/">Home</a></li>
    <li><a href="/about">About</a></li>
    <li><a href="/contact">Contact</a></li>
  </ul>
</nav>
```

The benefits of `<ul>` + `<li>`:

1. **Correct semantics**: a screen reader user hears "list, 3 items", and knows this is a set of options.
2. **Clear structure**: each link is wrapped in an li, so it can be styled independently and given a divider.
3. **A natural hierarchy**: a sub-menu can nest another ul, keeping the structure clear.

Crash site 2: a navigation built from a pile of divs.

```html
<nav>
  <div><a href="/">Home</a></div>
  <div><a href="/about">About</a></div>
  <div><a href="/contact">Contact</a></div>
</nav>
```

Consequence: it looks about the same, but semantically it is just a pile of divs. A screen reader cannot tell the user "there are 3 navigation items here". And because div is a block-level element that takes a full line by default, more CSS has to be written to make it horizontal.

## Nested lists

```html
<ul>
  <li>Fruit
    <ul>
      <li>Apple</li>
      <li>Banana</li>
    </ul>
  </li>
  <li>Vegetables
    <ul>
      <li>Cabbage</li>
      <li>Tomato</li>
    </ul>
  </li>
</ul>
```

The sub-list goes **inside** the parent li. Note: the inner ul is nested inside the li, not placed alongside it.

## Summary

- `<ul>` is unordered, `<ol>` is ordered, `<dl>` is descriptive - each has its place.
- List items must use `<li>`; bare text is not allowed.
- A navigation menu using ul is the semantically correct choice: clean structure and good accessibility.
- When nesting lists, place the inner ul inside the parent li.

## In-class exercise

```quiz
type: html
q: Write an ordered list containing three items: London, Paris and Berlin, each in its own li.
starter: |
  <ol>
  </ol>
checks:
- document.querySelectorAll('ol').length === 1
- document.querySelectorAll('li').length === 3
- document.querySelectorAll('li')[0].textContent.trim() === 'London'
- document.querySelectorAll('li')[1].textContent.trim() === 'Paris'
- document.querySelectorAll('li')[2].textContent.trim() === 'Berlin'
hint: Write three li elements inside the ol, in order, with the three city names as their content.
explain: The ol wraps three li elements, and the order and content of the li elements determine how the ordered list is presented.
```

options:
- A ul automatically becomes a horizontal layout
- ul + li is semantically a set of parallel options that a screen reader can recognise, with a clearer structure
- A div cannot contain an a tag
- Writing a ul is faster
answer: 1
explain: List semantics express "a set of parallel items", and a screen reader can announce the number of items - a semantic value that div does not have.
```

type: html
exam: true
q: Write an unordered list with three li items: Study, Work and Life. The "Study" li must contain a nested unordered sub-list with two items: Front-end and Back-end.
starter: |
  <ul>
  </ul>
checks:
- document.querySelectorAll('ul').length === 2
- document.querySelectorAll('li').length === 5
- document.querySelector('li > ul') !== null
- Array.from(document.querySelector('li > ul').children).map(e => e.textContent.trim()).join(',') === 'Front-end,Back-end'
hint: The first ul has three li elements, and the first li contains another ul.
explain: A nested list requires the inner ul to sit inside the parent li, forming the correct hierarchy.
```
