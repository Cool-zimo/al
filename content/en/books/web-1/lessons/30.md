# Wrapping up: the checklist and going live

> This lesson answers two questions: "How do I know the page is done?" and "How do I make it reachable by others?" A pre-launch checklist, plus the GitHub Pages deployment flow.

## The pre-launch checklist

### Semantics

- [ ] Every page has exactly one `<main>`
- [ ] Heading levels h1 → h2 → h3 do not skip
- [ ] Images have an `alt` attribute
- [ ] Link text is descriptive (not "click here")
- [ ] Lists use `<ul>` / `<ol>` / `<li>` and navigation uses `<nav>`

### Responsive

- [ ] There is a viewport meta tag
- [ ] At 320px (small-screen phone) there is no horizontal scroll
- [ ] At 1920px (large desktop) it does not stretch out of control
- [ ] Fonts are at least 14px on phones
- [ ] Images use `max-width: 100%; height: auto`

### Accessibility

- [ ] Colour contrast is sufficient (at least 4.5:1 for body text)
- [ ] Forms have associated `<label>`s
- [ ] Buttons have understandable text (no empty divs pretending to be buttons)
- [ ] All interactive elements can be reached with the Tab key
- [ ] Hover effects also appear on keyboard focus

```css
/* keep focus and hover consistent */
a:hover,
a:focus {
  color: var(--color-accent);
  text-decoration: underline;
}
```

### Performance

- [ ] Images are compressed (no 5MB originals)
- [ ] CSS lives in an external file (cacheable)
- [ ] Animations only use transform and opacity
- [ ] No console.log left in production code

## Deploying to GitHub Pages

GitHub Pages is a free static-site hosting service from GitHub. Your CV page is pure HTML/CSS/JS, so it fits perfectly.

**Steps:**

1. **Create a repository**: on GitHub, create a new repository named `your-username.github.io` (for example, `alicechen.github.io`).

2. **Upload the code**: put `index.html`, `style.css` and `app.js` in the repository root.

```bash
git init
git add .
git commit -m "First version of the CV"
git branch -M main
git remote add origin https://github.com/your-username/your-username.github.io.git
git push -u origin main
```

3. **Enable Pages**: Repository → Settings → Pages → set Source to the `main` branch → Save.

4. **Visit**: wait about a minute, then open `https://your-username.github.io` and your CV is live.

Crash site 1: a non-compliant repository name.

Consequence: if the repository name does not follow the `username.github.io` format, the Pages URL becomes `username.github.io/repository-name`. It still works, but the URL has an extra layer.

Crash site 2: the page shows a 404.

Consequence: likely causes — the HTML file is not named `index.html` (GitHub Pages looks for index.html by default), or the branch/directory has not been selected correctly. Check that index.html exists in the repository root and that the branch is set correctly in the Pages settings.

## In-class exercise

```quiz
type: html
q: Check the following HTML for accessibility: add an alt attribute to the img with the content "Alice's profile photo", give the a element meaningful link text of "Visit Alice's GitHub profile", and add a type attribute of "submit" to the button.
starter: |
  <img src="avatar.jpg">
  <a href="https://github.com/alicechen"></a>
  <button>Submit CV</button>
checks:
- document.querySelector('img').getAttribute('alt') === "Alice's profile photo"
- document.querySelector('a').textContent.trim() === "Visit Alice's GitHub profile"
- document.querySelector('button').getAttribute('type') === 'submit'
hint: Add alt to the img, descriptive text to the a and type="submit" to the button.
explain: alt lets screen-reader users know what the image shows; descriptive link text is more meaningful than "click here"; the button's type attribute makes its semantics explicit.
```

## Section quiz

```quiz
type: choice
exam: true
q: Which statement about deploying to GitHub Pages is correct?
options:
- The repository name can be anything and it does not affect the URL
- A repository named in the username.github.io format is published automatically to https://username.github.io
- GitHub Pages can only host Python projects
- Once deployed the code cannot be updated; you must create a new repository
answer: 1
explain: The special repository name username.github.io publishes directly to the root domain. An ordinary repository publishes to the subpath username.github.io/repository-name. Code can be pushed and updated continuously.
```
