# Headings and Paragraphs: The Semantics of h1-h6

> This lesson answers the question: "Which tag should I use for a heading?" The key idea is: **h1 means "this is a level-one heading", not "this is large text".**

## A heading is a level, not a font size

HTML has six levels of heading: `<h1>` through `<h6>`. They express the **hierarchical relationship of the content**, like the "chapter - section - subsection" of a book.

```html
<h1>Alice's CV</h1>
<h2>Education</h2>
<h3>Bachelor's degree</h3>
<p>Peking University, Computer Science, 2018-2022</p>
<h3>Master's degree</h3>
<p>Tsinghua University, Software Engineering, 2022-2024</p>
<h2>Work experience</h2>
```

This heading tree can be read by the browser, by search engines and by screen readers. A visually impaired user can jump between headings with a screen reader to locate the "Work experience" section quickly - **this is the real value of heading tags**.

Crash site 1: faking a heading with font size.

```html
<p style="font-size: 32px; font-weight: bold;">Work experience</p>
<p>Alice, front-end engineer...</p>
```

Consequence: the text is large and bold and looks like a heading. But to a machine it is just two ordinary paragraphs. A screen reader user hears no signal at all that "a new section begins here", and search results will not treat "Work experience" as a structural marker. And as you add more `style` attributes, the code gets dirtier.

## A page has only one h1

An h1 is the "main title of the page", and there should be exactly one on a page. It tells search engines and assistive tools "what this page is about". Use h2 for sub-headings and h3 for finer levels, stepping down one level at a time.

```html
<h1>Alice's personal website</h1>
<h2>About me</h2>
<p>...</p>
<h2>My projects</h2>
<h3>Project one</h3>
<p>...</p>
<h3>Project two</h3>
<p>...</p>
```

If Alice's CV page made "Education", "Work experience" and "Skills" all h1s, a search engine would think the page had three equally important main titles, and the page's topic would become blurred.

## Paragraphs: the p tag

```html
<p>Alice is a front-end developer working at an internet company in Beijing.</p>
<p>She likes writing clear, maintainable code.</p>
```

`<p>` represents a complete block of content. The browser automatically adds whitespace (margin) before and after a paragraph, so **you do not need to add blank lines by hand**.

Crash site 2: piling up `<br>` tags to make space.

```html
<p>First paragraph</p>
<br><br><br>
<p>Second paragraph</p>
```

Consequence: `<br>` is meant for breaking a line **inside** a paragraph (an address or a poem, for example). Using three br tags to manufacture paragraph spacing means using a content element to do a layout job. Spacing belongs to CSS's margin property. This approach also creates a maintenance headache: if you later want to adjust the spacing uniformly, you have to delete br tags one by one, whereas with CSS you only change one line.

## br and hr

`<br>` forces a line break and should only be used where a line really must break inside a paragraph:

```html
<p>
  100 Century Avenue<br>
  Pudong, Shanghai<br>
  Postcode 200120
</p>
```

`<hr>` is a dividing line marking a change of topic:

```html
<h2>Part one</h2>
<p>...</p>
<hr>
<h2>Part two</h2>
<p>...</p>
```

Modern pages rarely use hr; most dividing effects are achieved with CSS borders. It is enough to know that it exists.

## Summary

- h1-h6 express **levels**, not font size; a page has only one h1.
- The heading tree is read by machines and affects accessibility and SEO.
- Use `<p>` for paragraphs; do not pile up `<br>` for spacing - that is CSS's job.
- `<br>` is only for line breaks inside a paragraph; `<hr>` marks a change of topic.

## In-class exercise

```quiz
type: html
q: Write an h1 whose content is "My homepage", an h2 whose content is "About me", and a p whose content is "I like programming". Write the three elements in that order.
starter: |
  <h1>My homepage</h1>
checks:
- document.querySelectorAll('h1').length === 1
- document.querySelectorAll('h2').length === 1
- document.querySelectorAll('p').length === 1
- document.querySelector('h1').textContent.trim() === 'My homepage'
- document.querySelector('h2').textContent.trim() === 'About me'
hint: Write the three tags side by side, in order.
explain: h1, h2 and p are independent of one another, and their content sits inside the respective tags.
```

## Section quiz

```quiz
type: choice
exam: true
q: Why should you avoid using several h1s?
options:
- Using h1 only once is a syntax rule, and using it more than once causes an error
- Multiple h1s confuse the page hierarchy, so search engines and screen readers cannot determine the page topic
- The h1 tag has a quantity limit, and the browser stops displaying them after three
- Multiple h1s make the page load more slowly
answer: 1
explain: h1 represents the page's main title. Multiple h1s blur the page's topical hierarchy and harm SEO and accessibility. Using more than one is not an error, but it is semantically wrong.
```
