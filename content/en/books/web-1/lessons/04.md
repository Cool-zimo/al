# Text Tags: strong, em, span and div

> This lesson answers the question: "How do I add emphasis to a piece of text?" There is only one test: **do you want to express meaning, or do you want to express a look?**

## Semantic tags vs. presentational tags

The key point of this lesson is to keep two pairs apart:

| Semantic tag | Presentational tag | The difference |
|---|---|---|
| `<strong>` | `<b>` | strong = important; b = bold |
| `<em>` | `<i>` | em = emphasis; i = italic |

`<strong>` says "this content is important"; `<b>` only says "please render this text in bold". Browsers render strong as bold and em as italic by default, so **they look identical**. The difference is in how machines interpret them.

```html
<p>Please note: <strong>tomorrow's meeting in Beijing has been moved to 3 p.m.</strong></p>
<p>This is a sentence with <em>emphasis</em>.</p>
<p>The title of this book is <i>Front-end Fundamentals</i>.</p>
```

In the third sentence, using `<i>` for the book title is appropriate: a book title is conventionally italicised, and here we are emphasising **appearance** rather than vocal emphasis. "The meeting time has changed" is important information, so it gets strong.

## Why semantics matter

When a screen reader encounters `<strong>`, it may change its intonation and add weight to remind the user "this is the key point". When it encounters `<b>` it does not - because b is only styling and carries no semantic weight.

Search engines also give the words inside strong a higher weight. When Alice writes in her CV "I am proficient in `<strong>`Python`</strong>`", the keyword judgement is clearer than if she had written "I am proficient in `<b>`Python`</b>`".

**A simple test**: strip away all the CSS (imagine the page showing only plain text). Does this piece of text still need to be emphasised? If yes, use strong/em; if you only want it to look nice, use b/i, or just hand it over to CSS.

## span: marking up a piece of text

`<span>` is the "nameless tag" for inline elements. It has no semantics; it exists purely to make it easy to **select a piece of text and apply styling to it**.

```html
<p>Alice was in charge of front-end development for <span class="highlight">this project</span>.</p>
```

```css
.highlight {
  background-color: yellow;
}
```

Without span, you could not put a yellow background on just the four words "this project" - the p is a whole paragraph and cannot be precise about a few words inside it. Span lets you hang styling on any arbitrary piece of text.

## div: a block-level container

`<div>` is the "nameless tag" for block-level elements. It wraps a group of elements into one whole, making it easy to lay them out and style them as a unit.

```html
<div class="card">
  <h3>Project one</h3>
  <p>A web scraper written in Python.</p>
</div>
```

A div takes up its own line by default (block-level), while span does not cause a line break (inline). That is their core difference.

## Crash site 1: making a whole paragraph strong

```html
<strong>Alice, female, 28 years old, living in Beijing. Graduated from the Computer Science department of Peking University. Familiar with Python and JavaScript. Has taken part in several web projects, including an e-commerce back end and a data visualisation platform.</strong>
```

Consequence: the whole thing is bold, which means there is no emphasis at all. The value of strong lies in **contrast** - most of the text is normal weight and the important sentence stands out, so the reader's eye lands on the key point at a glance. All bold = nothing bold.

## Crash site 2: using div instead of span for an inline mark

```html
<p>The keyword is <div>front-end</div> development.</p>
```

Consequence: div is a block-level element, so it forces a line break between "The keyword is" and "development", breaking the sentence apart. An inline mark can only use span.

## Summary

- `<strong>` means important and `<em>` means emphasis - these are semantic; `<b>` and `<i>` are purely presentational.
- To decide whether to use a semantic tag, ask: does this text still need emphasis after the CSS is removed?
- `<span>` is an inline container, `<div>` is a block-level container; do not mix them up.

## In-class exercise

```quiz
type: html
q: Write a p whose content begins "Alice knows", with the word "Python" wrapped in a strong tag in the middle, followed by " and JavaScript". The concatenated plain text of the p must be "Alice knowsPython and JavaScript" (watch the spacing).
starter: |
  <p>Alice knows</p>
checks:
- document.querySelectorAll('p').length === 1
- document.querySelectorAll('strong').length === 1
- document.querySelector('strong').textContent.trim() === 'Python'
- document.querySelector('p').textContent.replace(/\s+/g, '').includes('AliceknowsPythonandJavaScript')
hint: The strong is nested inside the p, and the text continues inside the p after the strong.
explain: strong is a child of p, and the text before and after it remains inside the p to form a complete sentence.
```

## Section quiz

```quiz
type: choice
exam: true
q: You want to bold the phrase "stay safe" inside a sentence and have a screen reader announce that it is important. Which should you use?
options:
- `<b>stay safe</b>`
- `<i>stay safe</i>`
- `<strong>stay safe</strong>`
- `<span>stay safe</span>`
answer: 2
explain: strong expresses semantic importance, and a screen reader adds vocal weight accordingly. b only expresses a bold appearance and carries no semantic weight.
```
