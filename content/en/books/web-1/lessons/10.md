# Text Styling: Fonts, Line Height and Alignment

> This lesson answers the question: "Why does my text look bad?" Font size, line height and letter spacing are the properties that decide how readable your page is.

## Common text properties

```css
p {
  font-size: 16px;          /* font size */
  font-weight: bold;        /* weight: normal / bold / 100-900 */
  line-height: 1.8;         /* line height, unitless, relative to the font size */
  text-align: center;       /* alignment: left / center / right / justify */
  letter-spacing: 2px;      /* letter spacing */
  font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
}
```

## font-size: the size of the text

rem is the recommended unit for font size, so the whole page has a uniform baseline and scales together when the user zooms.

## font-weight: how heavy the text is

```css
.title {
  font-weight: 700;   /* the same as bold */
}
.light {
  font-weight: 300;   /* a light weight */
}
```

The values run from 100 to 900 in steps of 100. Not every font supports every weight; Chinese fonts usually have only two weights, 400 (regular) and 700 (bold). Alice wanted a weight of 500 for a heading, but the browser picked the nearest available weight, 400, so it looked identical to the body text - because the font does not provide a 500 glyph.

## line-height: the property that most affects readability

`line-height: 1.8` means the line height is 1.8 times the font size. For body text on a web page, the usual range is **1.5 to 1.8**.

Crash site 1: line height is too small.

```css
p {
  line-height: 1;
}
```

Consequence: multiple lines are crammed together with almost no space between them, and after a few lines of a long passage the reader is tired. This is the most common beginner mistake - thinking "tighter saves space" - when in fact readability is being sacrificed.

Crash site 2: writing line height in px.

```css
p {
  font-size: 16px;
  line-height: 24px;
}
```

Consequence: when the font size is later changed to 24px, the line height stays at 24px and the proportion is wrong. A unitless multiple such as `1.8` **follows the font size automatically**, which is the recommended way to write it.

## text-align: alignment

```css
h1 { text-align: center; }
p { text-align: justify; }   /* justified, often used for Chinese body text */
```

`justify` makes every line flush at both ends, with extra space added in between. In Western text it can make word spacing uneven, so it is mostly used for Chinese body text.

## letter-spacing: spacing between letters

```css
h1 {
  letter-spacing: 4px;
}
```

This works well for headings, logos and capitalised abbreviations, adding a touch of design. Body text is usually left at the default - leaving it alone is best.

## font-family: the font stack

```css
body {
  font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
}
```

The browser tries from left to right: if PingFang SC is available it is used; if not, it tries Microsoft YaHei; if neither is present, it falls back to the system's default sans-serif font. This is called a **font stack**, and it exists to support different operating systems (macOS, Windows, Linux).

Crash site 3: writing only one font name.

```css
body {
  font-family: "PingFang SC";
}
```

Consequence: a Windows user has no PingFang SC, so the browser falls back to its default font and the page looks completely different from what was intended. Always provide several alternatives.

## Summary

- Use rem for font size, a unitless multiple (1.5-1.8) for line height, and pick a font weight to suit.
- Line height directly affects readability; do not write it in px.
- text-align controls alignment; letter-spacing opens up the gaps between letters.
- font-family should be a font stack with several fallbacks for different systems.

## In-class exercise

```quiz
type: css
q: Give p a font size of 18px, a line height of 1.6 and centred text alignment.
html: |
  <p>Some text that needs formatting</p>
starter: |
  p {
  }
checks:
- getComputedStyle(document.querySelector('p')).fontSize === '18px'
- getComputedStyle(document.querySelector('p')).lineHeight === '28.8px'
- getComputedStyle(document.querySelector('p')).textAlign === 'center'
hint: The three properties are font-size, line-height and text-align.
explain: 18px x 1.6 = 28.8px is the computed line height; text-align controls alignment.
```

type: choice
exam: true
q: Which statement about line-height is correct?
options:
- Writing line height in px is the safest approach
- A unitless multiple follows the font size automatically and is more flexible
- line-height has no effect on the element's actual height
- The larger the line height, the smaller the text
answer: 1
explain: A unitless multiple is calculated relative to the current font size, so the line height follows automatically when the font size changes; px is rigid.
