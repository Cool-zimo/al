# float and clearing floats: the normal flow, bypassed

> This lesson answers two questions: "How do I wrap text around a picture?" and "Why did two divs sitting side by side collapse their parent container?" `float` carries a lot of historical baggage. Once you understand it you will see why Flex is the preferred choice today.

## What float was originally for

`float` was designed for exactly one job: **let text wrap around an image**, the way a newspaper lays out its pages.

```html
<img src="cat.jpg" class="float-left">
<p>This is a long paragraph that flows down the right side of the image. A floated element is taken out of the normal flow, but the text never covers it — it actively flows around, producing the classic text-and-image wrap effect…</p>
```

```css
.float-left {
  float: left;
  margin-right: 15px;
  margin-bottom: 10px;
}
```

`float: left` pins the element to the left edge of its parent, while the content to its right (the text, here) wraps around it. `float: right` pins it to the right.

Later someone noticed "hey, float can put elements side by side", and an entire era of Web 1.0 layouts was built on it. But that trick brought a famous side effect — **parent-height collapse**.

## Height collapse: the legendary float trap

When every child inside a parent is floated, the parent "cannot feel" the children's height, so it collapses to zero.

```html
<div class="parent">
  <div class="child">Block A</div>
  <div class="child">Block B</div>
</div>
<p class="after">I am the content that follows</p>
```

```css
.parent {
  border: 2px solid red;
  background: #ffe0e0;
}
.child {
  float: left;
  width: 150px;
  height: 100px;
  background: #4a90d9;
  margin-right: 10px;
}
```

Consequence: the parent's red border sits on a single line and its height is almost zero. The two blue children look as though they have "flown out", and the following `<p>` slides straight up underneath them.

Crash site 1: you expect `overflow: hidden` on the parent to clip the children.

```css
.parent {
  overflow: hidden;
}
```

Actual effect: the parent regains its height and wraps the floated children. This happens because any `overflow` other than `visible` triggers a BFC (block formatting context), which forces the parent to measure the height of its floated children. So `overflow: hidden` happens to be a way of clearing floats, even though its original purpose is clipping overflow.

## Three ways to clear floats

**Method 1: the `clear` property**

`clear: both` means "no floated element may sit to my left or to my right". It is typically used by placing a clearing element after the floats.

```css
.clear {
  clear: both;
}
```

```html
<div class="parent">
  <div class="child">Block A</div>
  <div class="child">Block B</div>
  <div class="clear"></div>
</div>
```

**Method 2: the clearfix pseudo-element (recommended)**

No extra empty div in the HTML — the `::after` pseudo-element does the job.

```css
.clearfix::after {
  content: '';
  display: block;
  clear: both;
}
```

```html
<div class="parent clearfix">
  <div class="child">Block A</div>
  <div class="child">Block B</div>
</div>
```

The parent automatically wraps its floated children and the HTML stays clean.

**Method 3: trigger a BFC with `overflow`**

```css
.parent {
  overflow: hidden; /* or auto */
}
```

Simple and direct, but beware: if a child has content that extends beyond the parent (a dropdown menu, for example), it will be clipped.

Crash site 2: hard-coding a `height` on the parent to "hold" it open.

```css
.parent {
  height: 100px;
}
```

Consequence: the parent appears to wrap its children, but if you later add more children or they grow taller, the fixed height is no longer enough and the content overflows. It treats the symptom instead of the cause, so it breaks as soon as the content is dynamic.

## Does modern layout still need float?

The answer: **side-by-side layouts do not, but text wrapping still does**.

For navigation, cards and grids, use Flex (lessons 19 and 20) or Grid (lesson 24) — neither has a height-collapse problem. But if you want text to flow gracefully around a picture, `float` is still the only choice.

```css
.article img {
  float: left;
  width: 200px;
  margin-right: 16px;
  margin-bottom: 8px;
}
```

## Summary

- `float` was originally for text-and-image wrapping and was later abused for layout.
- A floated element leaves the normal flow, which collapses the parent's height to zero.
- Three ways to clear floats: the `clear` property, the clearfix pseudo-element and `overflow` to trigger a BFC.
- Clearfix is the cleanest, most general solution: it touches neither the HTML nor the content.
- Use Flex or Grid instead of float for side-by-side layouts; keep float for wrapping.

## In-class exercise

```quiz
type: css
q: Write the clearfix for the .clearfix class using the ::after pseudo-element to clear floats.
html: |
  <div class="parent clearfix">
    <div class="child">A</div>
    <div class="child">B</div>
  </div>
starter: |
  .clearfix::after {
  }
  .parent {
    border: 2px solid red;
  }
  .child {
    float: left;
    width: 100px;
    height: 80px;
    background: #4a90d9;
  }
checks:
- getComputedStyle(document.querySelector('.clearfix'), '::after').display === 'block'
- getComputedStyle(document.querySelector('.clearfix'), '::after').clear === 'both'
hint: The pseudo-element needs content and display: block, plus clear: both.
explain: clearfix inserts a clearing block-level element with ::after so the parent wraps its floated children again.
```
