# Colours and Units

> This lesson answers the question: "How do I write a colour, and which unit should I use for sizes?" Picking the right unit lets your page adapt across different screens.

## Three ways to write a colour

```css
h1 {
  color: red;               /* named colour */
  color: #2c7a7b;           /* hexadecimal */
  color: rgb(44, 122, 123); /* RGB */
}
```

All three forms are valid. Named colours number only around a hundred - enough, but not precise. Hex and RGB can represent any colour and are equivalent to each other:

`#2c7a7b` = `rgb(44, 122, 123)` (red 44, green 122, blue 123).

A form with transparency:

```css
.box {
  background-color: rgba(44, 122, 123, 0.5);  /* the last value is opacity, 0-1 */
}
```

For exercise checking, always write the expected value in `rgb(...)` form. That way, whether a student writes `red`, `#f00` or `rgb(255,0,0)`, the answer is accepted - the browser computes all of them to the same value.

## px: pixels, an absolute unit

```css
p {
  font-size: 16px;
}
```

px is the most intuitive unit: 1px is roughly one physical pixel on a screen. Its problem is that **it does not change with the user's settings**: a user with poor eyesight who increases the browser's default font size will find that px-based sizes do not scale up, and will feel that "the text is too small to change".

## em: relative to the current element's font size

```css
.box {
  font-size: 16px;
  padding: 1em;   /* 16px */
}
.box p {
  font-size: 1.2em; /* 19.2px, relative to the parent's 16px */
}
```

`1em` = the current element's font size. Its feature is that **it compounds when nested**:

```html
<div style="font-size: 1.2em">
  <div style="font-size: 1.2em">
    <p>At this point the font size is 16 x 1.2 x 1.2, about 23px</p>
  </div>
</div>
```

Crash site 1: nested em causes font sizes to run away.

Consequence: Alice used `font-size: 1.2em` for every item in her navigation menu, so the sub-menu became 1.2 times larger relative to the parent menu, and by the third level the text had inflated absurdly. The fix is to use rem, or to write px directly at each level.

## rem: relative to the root element's font size

```css
html {
  font-size: 16px;
}
.box {
  font-size: 1rem;   /* 16px */
  padding: 1.5rem;   /* 24px */
}
```

`1rem` is always equal to the font size of the root element (html). It does **not** accumulate with nesting, which makes it the most recommended unit for font sizes. When the user increases the browser's default font size, rem scales with it and the whole page zooms. (In this book, the root font size is fixed at 16px, so `1.5rem` works out to `24px`.)

## %: relative to the parent's dimensions

```css
.container {
  width: 80%;
}
```

`80%` means 80% of the parent element's width. This is often used to centre content and leave margins.

## When to use which

| Unit | Best for |
|---|---|
| px | Border thickness, small fixed-size icons |
| rem | Font sizes, spacing, most layout dimensions |
| em | Padding related to the element's own font size (such as a button) |
| % | Widths relative to the parent, responsive layouts |

## Summary

- Colours can be named, hex or rgb, all equivalent; for checks write the expected value as `rgb(...)`.
- px is absolute and does not follow the user's settings; em is relative to the current element and compounds when nested.
- rem is relative to the root element, never runs away on nesting, and is the recommended font unit.
- % is relative to the parent and suits responsive layouts.

## In-class exercise

```quiz
type: css
q: Make the p font size 1.5rem (with a root font size of 16px this is 24px) and the text colour a deep teal, rgb(0, 121, 107).
html: |
  <p>Some text</p>
starter: |
  p {
  }
checks:
- getComputedStyle(document.querySelector('p')).fontSize === '24px'
- getComputedStyle(document.querySelector('p')).color === 'rgb(0, 121, 107)'
hint: 1.5rem equals 24px, and colour uses the color property.
explain: rem is relative to the root font size, so 24px is the expected value; color sets the text colour.
```
