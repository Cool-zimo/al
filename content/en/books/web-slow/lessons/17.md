# Parameters: Making Functions Reusable

> So far every function we wrote did exactly the same thing each time. This lesson introduces **parameters** — the feature that lets a function "swallow different data and produce different results." This is where functions become genuinely useful.

## Parameters vs arguments

```js
function sayHi(name) {          // name is a "parameter" (a placeholder)
    console.log("Good morning, " + name);
}

sayHi("Mr. Smith");            // "Mr. Smith" is an "argument" (the real value)
sayHi("Alice");
```

- **Parameter:** the name inside the parentheses when you *define* the function. It acts like a placeholder variable.
- **Argument:** the actual value you pass in when you *call* the function.

When the function runs, the argument's value is copied into the parameter, and the function body can then use that name.

## Multiple parameters

Separate parameters with commas in the definition, and separate arguments with commas in the call:

```js
function introduce(name, age, city) {
    console.log("I'm " + name + ", " + age + " years old, from " + city);
}

introduce("Alice", 20, "London");
// I'm Alice, 20 years old, from London

introduce("Bob", 25, "Paris");
// I'm Bob, 25 years old, from Paris
```

**Positional matching:** the first argument goes to the first parameter, the second to the second. Order matters.

## What happens when you skip an argument

```js
function greet(name) {
    console.log("Hello, " + name);
}

greet();            // no argument passed
// Hello, undefined
```

When an argument is missing, the parameter's value is `undefined`. We first met this back in lesson 2 — any variable without a value is `undefined`. So before using a parameter, it is wise to check:

```js
function greet(name) {
    if (name === undefined) {
        name = "guest";
    }
    console.log("Hello, " + name);
}

greet();            // Hello, guest
greet("Alice");     // Hello, Alice
```

A shorter way is a **default value**, written with `=` right after the parameter:

```js
function greet(name = "guest") {
    console.log("Hello, " + name);
}

greet();            // Hello, guest
greet("Alice");     // Hello, Alice
```

`name = "guest"` means: if nobody passes `name`, automatically use `"guest"`.

## Crash site 1: argument count does not match

```js
function add(a, b) {
    return a + b;
}

add(3);     // b is missing, so it is undefined; result is NaN
```

**Consequence:** `3 + undefined` gives `NaN`. **Mismatched argument counts do not throw an error, but produce bizarre results — one of the hardest bugs to track down.**

## Crash site 2: treating a parameter like a global variable

```js
function setName(name) {
    name = "can't change this";   // this only changes the local copy
}

let myName = "Alice";
setName(myName);
console.log(myName);             // still "Alice"
```

**With primitives (numbers, strings), changes inside the function do not affect the outside.** If you want to modify something outside, you must `return` the new value and reassign it (covered in the next lesson).

## Default values in practice

```js
function makeMenu(main, side = "rice") {
    console.log(main + " with " + side);
}

makeMenu("roast beef");        // roast beef with rice
makeMenu("steak", "pasta");    // steak with pasta
```

A rule of thumb: put parameters with defaults *after* those without. If you reverse the order, callers must pass `undefined` explicitly to trigger the default — awkward and confusing.

## Summary

- A parameter is a placeholder at definition time; an argument is the real value at call time.
- Multiple parameters are comma-separated and matched by position.
- A missing argument means `undefined`, often producing `NaN`.
- Use `parameter = defaultValue` to avoid the `undefined` surprise.
