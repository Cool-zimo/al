# The while Loop and Picking the Right Kind

> This lesson answers the question: "When should I use while instead of for?" Both loops repeat work, but each one fits a different situation. Understanding the difference helps you write code that feels natural.

## while: keep going as long as the condition is true

The logic of `while` is simple: **keep repeating for as long as the condition stays true.**

```js
let count = 1;

while (count <= 5) {
    console.log("Round number " + count);
    count++;
}
```

Output:

```
Round number 1
Round number 2
Round number 3
Round number 4
Round number 5
```

**The syntax:**

```js
while (condition) {
    // repeat this while the condition is true
}
```

Compare that with `for`: `while` has just one part (the condition), while `for` has three (initialisation + condition + update). `while` is more compact, but it is your job to update the counter inside the loop body.

## for vs while: which one?

| Situation | Use for | Use while |
|---|---|---|
| You know how many rounds | Yes — "count to 10" | Possible, but clumsier |
| You know the stopping point | Yes — "go through 5 items" | Yes |
| You do not know how many rounds | Awkward | Yes — "keep asking until they get it right" |
| The condition depends on an outside event | Awkward | Yes — "wait until the user clicks" |

**The rule of thumb:**

- **You know the number of rounds** — use `for`
- **You do not know the number of rounds, only when to stop** — use `while`

```js
// You know the count -> for
for (let i = 0; i < 10; i++) {
    console.log(i);
}

// You do not know the count -> while
let answer = "";
while (answer !== "Paris") {
    answer = prompt("What is the capital of France?");  // ask until correct
}
```

## The infinite loop: it never stops

If the `while` condition stays true forever, the loop never ends — that is called an **infinite loop**:

```js
let i = 1;
while (i <= 5) {
    console.log(i);
    // oops, forgot i++ !
}
```

**Consequence:** this code prints 1 forever and the browser tab freezes solid — you have to force-close it. **An infinite loop is one of the classic beginner mistakes.**

**Why does it never stop?** The condition is `i <= 5`, but i is stuck at 1 forever, so it always satisfies `<= 5`, so it never stops.

**Three rules to dodge infinite loops:**

1. Make sure the condition will eventually become false.
2. Make sure the loop body actually changes the condition variable in the "right direction."
3. After writing, ask yourself: "will this condition ever become false?"

```js
// correct: i grows, and eventually passes 5
let i = 1;
while (i <= 5) {
    console.log(i);
    i++;  // i changes, so eventually i becomes 6 and the loop ends
}
```

## A guessing game with while

```js
let secret = 42;
let guess = 0;

while (guess !== secret) {
    guess = Number(prompt("Guess a number:"));
    if (guess < secret) {
        console.log("Too low");
    } else if (guess > secret) {
        console.log("Too high");
    }
}
console.log("You got it!");
```

Here you have **no idea** how many guesses it will take, so `for` will not work (it needs a count up front). This is exactly where `while` shines.

## do...while: runs at least once

There is a variant called `do...while` — it runs once first, then checks the condition:

```js
let input = "";
do {
    input = prompt("Enter the password:");
} while (input !== "sesame");
```

The difference from plain `while`: `do...while` **always runs at least once**, because the check comes after.

## Crash site 1: forgetting to update the counter (infinite loop)

```js
let count = 0;
while (count < 3) {
    console.log("hello");
    // forgot count++ ! count stays 0 forever
}
```

**Consequence:** "hello" prints forever and the browser freezes. **Every time you write a while loop, check that the body actually changes the condition variable.**

## Crash site 2: reaching for for when you do not know the count

```js
// reading lines from a file until there are no more,
// but you have no idea how many lines there are
for (let i = 0; ???; i++) {  // you cannot write a sensible condition
    // ...
}
```

**Consequence:** you cannot come up with a sensible stop condition. This situation calls for `while`: `while (hasNextLine()) { ... }`. **When you do not know the count, do not force for.**

## Summary

- `while (condition) { ... }` keeps repeating while the condition is true.
- **Know the count -> for. Do not know the count -> while.**
- An infinite loop happens when the condition never becomes false, usually because you forgot to update a variable.
- `do...while` always runs at least once; the check comes afterwards.

## In-class exercise

```quiz
type: js
q: Write a function countdown that takes n and uses a while loop to count down from n to 1 (subtracting 1 each time), then returns the string "Liftoff".
func: countdown
starter: |
  function countdown(n) {
      // write your code here
  }
cases: |
  3 -> "Liftoff"
  1 -> "Liftoff"
hint: while (n > 0) { console.log(n); n--; } return "Liftoff";
explain: while depends on n changing; n-- eventually makes the condition false.
```
