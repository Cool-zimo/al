# Structure and Styles: Build the Shell First

> Last lesson fixed the data and the functions. This lesson puts up the page "skeleton" and its "look" — the input box, the button, and the list container. The logic stays empty for now; we get the structure working first.

## The HTML structure

```html
<div class="todo-app">
  <h1>My To-Do List</h1>

  <div class="input-area">
    <input id="todo-input" placeholder="Add a new task...">
    <button id="add-btn">Add</button>
  </div>

  <ul id="todo-list"></ul>
</div>
```

**Three key elements, each with a clear job:**

- `#todo-input`: the box where the user types a new task.
- `#add-btn`: clicking it adds the typed text into the list.
- `#todo-list`: the `<ul>` container where every task item hangs.

## The basic styles

```css
.todo-app {
  width: 400px;
  margin: 40px auto;
  font-family: sans-serif;
}

.input-area {
  display: flex;
  gap: 8px;
  margin-bottom: 16px;
}

#todo-input {
  flex: 1;
  padding: 8px;
  font-size: 16px;
}

#add-btn {
  padding: 8px 16px;
  font-size: 16px;
}

#todo-list {
  list-style: none;
  padding: 0;
}

#todo-list li {
  display: flex;
  justify-content: space-between;
  padding: 8px;
  border-bottom: 1px solid rgb(238, 238, 238);
}
```

**Structure plus styles props up the "shell"; the list part stays empty for now.** The next step is to use JS to turn the data into `<li>` elements.

## Grab the elements in JS first

```js
let input = document.querySelector("#todo-input");
let addBtn = document.querySelector("#add-btn");
let list = document.querySelector("#todo-list");

let todos = [];
```

**Look up the elements you need once, store them in variables, and do not query them again every time.** This is one of the most important code-organisation habits for the slow track.

## Crash site 1: `.input-area` uses flex but the children have no `flex: 1`

```css
.input-area { display: flex; }
/* forgot to give the input flex: 1 */
```

Consequence: the input box is crammed on the left, the button is about the same width, and the layout looks ugly. **In a flex layout, if you want a child to "fill the remaining space", you must give it `flex: 1`.**

## Crash site 2: forgetting to remove the bullet points on the `<ul>`

```css
/* forgot #todo-list { list-style: none; } */
```

Consequence: every task has a little black dot in front of it, which looks ugly. **When building a custom list, you almost always clear the default styling with `list-style: none` first.**

## Why build the structure before the logic

1. **You can see the result.** The moment the structure is up, a refresh shows something on screen — quick feedback and a real sense of progress.
2. **With the element ids fixed, JS can find its place.** `#todo-input`, `#add-btn`, and `#todo-list` are the "contract" between JS and HTML.
3. **Write the styles once and you are done.** The rendering logic only has to drop elements into the container; it does not need to worry about styles.

## Summary

- Three key elements: an input box, a button, and a list container, each with its own job.
- Build the structure and styles first, so the page "looks like a to-do list".
- Element ids are the contract between JS and HTML; fix them before writing JS.
- Look up the elements you use often once, and store them in variables.

## In-class exercise

```quiz
type: css
q: Given the HTML <div class="box"><input id="i"><button id="b">Add</button></div>, make .box a flex container, let the input fill the remaining space, and fix the button at 80px wide.
html: |
  <div class="box"><input id="i"><button id="b">Add</button></div>
starter: |
  .box {
  }
  #i {
  }
  #b {
  }
checks:
- getComputedStyle(document.querySelector('#i')).flexGrow === '1'
- getComputedStyle(document.querySelector('#b')).width === '80px'
hint: set display:flex on .box; flex:1 (that is, flex-grow:1) on the input; width:80px on the button
explain: a flex layout lets the input use flex:1 to fill the remaining space.
```
