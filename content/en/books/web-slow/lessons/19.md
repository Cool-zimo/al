# Scope: Where a Variable Lives

> Why can't you use a variable declared inside a function from the outside? And why *can* a function read a variable declared outside it? This lesson explains **scope** so you never get blindsided by a `ReferenceError` again.

## Variables inside a function are invisible outside

```js
function demo() {
    let secret = "I'm a secret inside this function";
    console.log(secret);   // works fine
}

demo();
console.log(secret);       // error: secret is not defined
```

`secret` is declared with `let` *inside* the function `demo`, so its "home" is within `demo`. **Step outside those curly braces and it no longer exists.**

This is **local scope**: a function body is a sealed room, and variables declared in it live only in that room.

## Global variables: declared on the outside

```js
let globalMsg = "I'm a global variable";

function demo() {
    console.log(globalMsg);   // the function can read a global variable
}

demo();                       // "I'm a global variable"
console.log(globalMsg);       // also readable from the outside
```

**A variable declared with `let` outside any function is a "global variable" — usable both inside and outside functions.**

The rule in one sentence: **the inside can see the outside; the outside cannot see the inside.**

```js
let outside = "outside";

function demo() {
    let inside = "inside";
    console.log(outside);    // fine, the function sees the outside
}

console.log(inside);         // error, the outside cannot see the inside
```

## Same name, closer wins

```js
let name = "global Alice";

function demo() {
    let name = "local Bob";     // same name as the global
    console.log(name);          // "local Bob"
}

demo();
console.log(name);              // "global Alice"
```

**When the same name exists both inside and outside, the function uses the one "closest to it" — its own local copy.** This is called **shadowing**: the local variable casts a shadow over the global one.

Important: the function did *not* change the global `name`; it simply **declared a brand-new local variable with the same name**. The global one is still intact, and once you step back outside you read it again.

## Crash site 1: forgetting `let`, accidentally rewriting a global

```js
let count = 0;

function add() {
    count = count + 1;   // no let, so this reuses the global count and mutates it
}

add();
console.log(count);      // 1
```

This code runs, but **the function silently altered a global variable**. In a large project you would have no idea who is changing `count`, making bugs nearly impossible to trace. A better approach is to pass `count` in as a parameter and `return` the new value out.

## Crash site 2: using a loop variable after the loop

```js
function printNumbers() {
    for (let i = 0; i < 3; i++) {
        console.log(i);
    }
    console.log(i);   // error: i is not defined
}

printNumbers();
```

**Consequence:** `let i` is declared in the `for` parentheses, so **its scope is exactly the curly braces of the loop** — once the loop ends, `i` vanishes. If you need it afterwards, declare it with `let` before the loop.

## Nested scopes

```js
let a = "global a";

function outer() {
    let b = "outer's b";
    function inner() {
        let c = "inner's c";
        console.log(a);   // global a — yes, look outwards
        console.log(b);   // outer's b — yes, look further outwards
        console.log(c);   // inner's c — already here
    }
    inner();
    console.log(c);       // error: outer cannot see inner's c
}

outer();
```

**Scope is like an onion, with layers wrapped inside layers.** When looking up a variable, JS starts from the innermost layer and works outward, stopping at the first match. Once you step out, you can never see back in.

## Summary

- A variable declared with `let` inside a function is local — unusable from the outside.
- A variable declared outside every function is global — visible inside functions.
- With the same name in both places, the closer one wins (shadowing).
- The rule: inside sees outside; outside does not see inside.

## In-class exercise

```quiz
type: js
q: Write a function double that takes a number n and returns n * 2. Keep the function free of any variables that pollute the global scope.
func: double
starter: |
  function double(n) {
      // write your code here
  }
cases: |
  3 -> 6
  10 -> 20
  -4 -> -8
hint: just return n * 2; no extra variable needed
explain: the parameter is already a local variable, and return hands the result out without touching anything global.
```
