# Return Values: The Function's Output Chute

> Every function we have written so far just `console.log`-ed its result. In real projects you usually want to "calculate something and hand it back" so the caller can use it. This lesson covers `return`.

## What `return` does

```js
function add(a, b) {
    return a + b;    // hand the result of a+b back to the caller
}

let result = add(3, 5);
console.log(result); // 8
```

`return expression` means: **take the value of that expression and hand it back to whoever called the function.** The caller can store it in a variable, print it, or feed it into another calculation.

Compare a function with `return` against one without:

```js
function add1(a, b) {
    return a + b;
}
function add2(a, b) {
    console.log(a + b);   // just prints, no return
}

let x = add1(1, 2);   // x is 3, usable
let y = add2(1, 2);   // prints 3, but y is undefined
console.log(x + 10);  // 13, fine
console.log(y + 10);  // NaN, because y is undefined
```

**`console.log` only displays something on the screen; `return` actually hands data back.** This is the single most common confusion for slow-track learners.

## No return means undefined

```js
function nothing() {
    let a = 1;
}

console.log(nothing());   // undefined
```

**Every function that runs to the end without hitting a `return` gives back `undefined`.** This is the same logic as "a variable with no value is undefined" from lesson 2.

## Code after return never runs

```js
function check(age) {
    if (age >= 18) {
        return "adult";
    }
    return "minor";
}

console.log(check(20));   // "adult"
console.log(check(15));   // "minor"
```

The moment `return` executes, the function stops dead — everything after it is skipped:

```js
function demo() {
    return 1;
    console.log("you will never see me");   // never runs
    return 2;                               // never runs
}

console.log(demo());   // 1
```

This is the **early return** technique: when a condition is met, return immediately instead of nesting layers of `if-else`.

## Crash site 1: writing `return` with nothing after it

```js
function getScore() {
    let score = 95;
    return;     // forgot to write score
    score;
}

console.log(getScore());   // undefined
```

**Consequence:** the value is `undefined`. **Always put the value you want to return right after `return`, otherwise it is the same as `return undefined`.**

## Crash site 2: returning inside an `if` but forgetting a fallback

```js
function getLevel(score) {
    if (score >= 90) return "excellent";
    if (score >= 60) return "pass";
    // oops, forgot to return anything here
}

console.log(getLevel(50));   // undefined, not "fail"
```

**Consequence:** for scores below 60 the function reaches the end with no `return`, producing `undefined`. **In any function with multiple return branches, ask yourself: does every possible path return something?**

## A function can return anything

```js
function getFirst(arr) {
    return arr[0];        // returns the first element
}

function makeUser(name, age) {
    return { name: name, age: age };   // returns an object
}

function isAdult(age) {
    return age >= 18;     // returns a boolean true / false
}
```

Functions that return booleans are especially handy inside `if`:

```js
function isAdult(age) {
    return age >= 18;
}

if (isAdult(20)) {
    console.log("come on in");
}
```

## Summary

- `return value` hands data back; `console.log` only prints.
- No `return` (or a bare `return`) gives `undefined`.
- Once `return` runs, the function ends — later lines do not execute.
- For every branch, ask: does it return?

type: js
q: Write a function isEven(n) that returns true if n is even, and false otherwise.
func: isEven
starter: |
  function isEven(n) {
      // write your code here
  }
cases: |
  2 -> true
  3 -> false
  0 -> true
