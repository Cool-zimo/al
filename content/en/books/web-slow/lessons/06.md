# Comparisons: Teaching Your Program to Make Judgements

> This lesson answers the question: "How does a program decide whether something is true?" Comparison operators are the foundation of the `if` statement, and the difference between `=` and `===` is the single biggest trap for a beginner.

## A comparison is a true/false question

Every day you make little judgements:

- Is the temperature today **above** 30 degrees?
- Is my balance **enough** to buy this?
- Are these two people **the same person**?

A program makes those judgements with **comparison operators**, and the answer is always `true` (yes) or `false` (no):

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `>` | greater than | `5 > 3` | `true` |
| `<` | less than | `5 < 3` | `false` |
| `>=` | greater than or equal | `5 >= 5` | `true` |
| `<=` | less than or equal | `3 <= 2` | `false` |
| `===` | strictly equal | `5 === 5` | `true` |
| `!==` | strictly not equal | `5 !== 3` | `true` |

```js
console.log(10 > 5);   // true
console.log(10 < 5);   // false
console.log(10 === 10); // true
console.log(10 !== 5);  // true
```

**The answer is always true or false** -- a boolean. A comparison is really just a yes/no question.

## `===` means "is equal to"; `=` means "put it in"

**This is the super-trap. Memorise it.**

```js
let x = 5;            // put 5 into x (assignment)
console.log(x === 5);  // is x equal to 5? (comparison) → true
```

| Syntax | Name | What it does | Example |
|---|---|---|---|
| `=` | Assignment | Put the right value into the left variable | `let a = 3` |
| `===` | Strict equal | Check whether both sides are equal, return true/false | `3 === 3` → true |
| `!==` | Strict not equal | Check whether both sides are different | `3 !== 4` → true |

**The everyday analogy:** `=` is like dropping something into a box. `===` is like putting two things on a balance scale to see if they match.

```js
let age = 20;       // ✅ assignment: put 20 into age
console.log(age === 20);  // ✅ comparison: is age equal to 20? true
console.log(age === 30);  // ✅ comparison: is age equal to 30? false
```

## Why three equals signs?

JavaScript also has `==` (two equals). It helpfully converts types behind your back:

```js
console.log(5 == "5");   // true  ("5" gets quietly turned into a number)
console.log(5 === "5");  // false (different types: number vs string)
```

`===` is stricter: both the value **and** the type must match. `"5"` is text and `5` is a number, so `===` says they are not equal.

**Always write `===`, never `==`.** This is standard industry practice and it saves you from a long list of hidden bugs.

## The result of a comparison is a boolean

```js
let isAdult = age >= 18;  // if age is 20, isAdult becomes true
console.log(isAdult);     // true
```

A comparison expression produces `true` or `false`, and you can drop that result straight into a variable. This is used constantly in the `if` statement in the next lesson.

## Crash site 1: using `=` when you meant `===`

```js
let score = 80;
if (score = 60) {  // WRONG! this puts 60 into score
    console.log("You passed");
}
```

**Consequence:** the condition is **always true**. `score = 60` is an assignment, and the result of an assignment is `60`, which counts as true. So no matter what `score` originally was, this prints "You passed". The fix is `score === 60`.

## Crash site 2: using `==` and getting burned by type conversion

```js
console.log("" == 0);          // true (the empty string is converted to 0)
console.log(null == undefined);  // true
console.log("0" == false);       // true
```

**Consequence:** results that fly in the face of common sense and produce logic bugs. For example `"" == 0` is true, even though you probably meant "an empty string is not zero." **Use `===` and these traps disappear.**

## Summary

- Comparison operators: `>` `<` `>=` `<=` `===` `!==`, always producing `true` or `false`.
- `=` assigns (puts it in); `===` compares (checks for equality).
- Always use `===`, never `==`, to avoid surprise type conversion.
- A comparison result can be stored in a variable as a boolean.
