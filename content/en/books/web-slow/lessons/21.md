# The Web Page Is a Tree: What the DOM Is

> Every line of JavaScript we have written so far ran in the "console." From this chapter on, JS gets to work with real elements on a web page — clicking buttons, changing text, adding list items. All of that relies on the **DOM**.

## HTML is actually a tree

When the browser receives some HTML, it parses it into a "tree of nodes." Take this HTML:

```html
<html>
  <body>
    <h1>Hello</h1>
    <div>
      <p>A paragraph</p>
    </div>
  </body>
</html>
```

In the browser's eyes it looks like this:

```
html
 └─ body
     ├─ h1
     └─ div
         └─ p
```

**This tree-shaped structure is called the DOM (Document Object Model).** Every tag on a web page is a "node" in that tree.

Why "tree"? There is a topmost node (`html`, the root) that branches downward into children — like an upside-down tree.

## `document` is the entry point for everything

To manipulate a web page, JS uses a global object called `document` — it is the root of the tree:

```js
console.log(document);          // the whole document
console.log(document.title);   // the current page title
```

**Remember this sentence: `document` is the bridge between JS and the web page. Every "find an element" or "change an element" operation starts here.**

## Creating an element and adding it to the page

```js
// 1. create a <p> element (it is "in mid-air" — not visible yet)
let p = document.createElement("p");

// 2. give it some text
p.textContent = "I was added by JavaScript";

// 3. attach it under body — now it shows up on the page
document.body.appendChild(p);
```

Three steps: **create → set content → attach to the tree.** Only after step 3 does the element actually appear in the page.

## Relationships between elements

```html
<div id="box">
  <h1>Title</h1>
  <p>Paragraph</p>
</div>
```

- `div` is the **parent** of `h1` and `p`.
- `h1` and `p` are the **children** of `div`.
- `h1` and `p` are **siblings** of each other.

JS can reach them like this:

```js
let box = document.querySelector("#box");
console.log(box.children);          // the child collection: h1, p
console.log(box.children.length);   // 2
console.log(box.firstElementChild); // the first child: h1
```

## Crash site 1: creating an element but never attaching it

```js
let p = document.createElement("p");
p.textContent = "hello";
// forgot appendChild — nothing appears on the page
```

**Consequence:** no error, but zero visible change. **A created element must be attached to the tree (via appendChild to an existing node), or it just floats in memory.**

## Crash site 2: treating text as an element

```html
<div id="box">some text</div>
```

```js
let box = document.querySelector("#box");
console.log(box.children.length);   // 0, because "some text" is a text node, not an element node
```

The text `"some text"` is a **text node**, not an element node. `children` only counts element children, so the length is 0. To read the text itself, use `textContent` (covered in the next lesson).

## Why the DOM is an "Object" model

Every element in the DOM is a JavaScript object with properties you can read and write:

```js
let h1 = document.querySelector("h1");
h1.textContent = "New title";     // change the text
h1.style.color = "red";           // change the style
h1.id = "main-title";             // change an attribute
```

**That is why it is called the "Object" in DOM — every tag is an object in JS, and you can read or write its properties.** This also explains why `document.body.appendChild` works: `body` is an object, and `appendChild` is a method sitting on it.

## Summary

- HTML is parsed by the browser into a DOM tree.
- `document` is the entry point for all operations.
- Three steps to create an element: createElement → set content → appendChild to attach it.
- Every tag is an object whose properties you can read and write.
