# Events: `addEventListener` and Why Not `onclick`

> A web page is not a program that "runs once and ends." It is a program that "waits for the user to click." This lesson is about events: how to make JavaScript react when the user clicks, types, or moves the mouse.

## Listening for a click with addEventListener

```html
<button id="btn">Click me</button>
<p id="msg"></p>
```

```js
let btn = document.querySelector("#btn");
let msg = document.querySelector("#msg");

btn.addEventListener("click", function () {
    msg.textContent = "You clicked me!";
});
```

**`addEventListener("click", function)` means: when the user clicks this button, run this function.** The function you pass in is called a "callback" — you do not call it yourself; the browser calls it when the event happens.

## The event object `e` and `e.target`

```js
btn.addEventListener("click", function (e) {
    console.log(e.target);       // the element that was clicked (btn, in this case)
    console.log(e.target.id);    // "btn"
});
```

**`e` is the "event object" the browser hands you, filled with information about this click.** The most useful part is `e.target` — "which element did the user actually hit?"

## Why not `onclick = ...`

**Approach one: `onclick` (not recommended)**

```js
btn.onclick = function () { console.log("first"); };
btn.onclick = function () { console.log("second"); };
// result: only "second" runs — the first one was overwritten
```

**Approach two: `addEventListener` (recommended)**

```js
btn.addEventListener("click", function () { console.log("first"); });
btn.addEventListener("click", function () { console.log("second"); });
// result: both run
```

**`onclick` is a property assignment, and the second assignment overwrites the first; `addEventListener` can attach any number of handlers.** Real projects almost always use `addEventListener`.

## Common event types

| Event name | When it fires |
|---|---|
| `click` | a click |
| `input` | the content of an input changes |
| `submit` | a form is submitted |
| `mouseover` | the mouse enters an element |
| `keydown` | a keyboard key is pressed |

```html
<input id="name" placeholder="Type your name">
```

```js
let input = document.querySelector("#name");

input.addEventListener("input", function () {
    console.log("typed: " + input.value);
});
```

## Crash site 1: `button.click()` does not submit a form

```html
<form id="myForm">
  <input name="q">
</form>
```

```js
let form = document.querySelector("#myForm");

form.addEventListener("submit", function () {
    console.log("submitted");
});

document.querySelector("button").click();   // does nothing — the form's submit never fires
```

Consequence: nothing is logged. **To trigger a form submission from code, use `form.dispatchEvent(new Event("submit"))`.**

## Crash site 2: binding a handler to every single element, one by one

```js
let items = document.querySelectorAll(".item");
for (let i = 0; i < items.length; i++) {
    items[i].addEventListener("click", function () {
        console.log("clicked");   // works, but is wasteful when the list is long
    });
}
```

**A better technique is "event delegation": attach one listener to the parent and use `e.target` to figure out which child was clicked.** This trick is put to real use in the to-do list project in the next chapter.

## Events bring a page to life

Events are what give a web page its soul. Without events, JavaScript runs once and stops; with events, the page keeps waiting for the user and responding the moment something happens. Every project in the rest of this chapter depends on them.

## Summary

- `addEventListener("click", function)` attaches a click handler.
- The function you pass is a callback — the browser calls it when the event occurs.
- `e.target` is the innermost element that was clicked.
- Prefer `addEventListener` over `onclick`: it accepts many handlers and never overwrites.
- To submit a form programmatically, use `dispatchEvent(new Event("submit"))`.
