# If / Else: Making Your Program Choose

> This lesson answers the question: "How do I make a program do different things in different situations?" `if / else` is the most basic branch in programming, exactly like the everyday "if this, then that; otherwise, do something else."

## "If" in everyday life

Before you leave the house you probably think:

> If it is raining, take an umbrella. Otherwise, do not bother.

A program expresses that with `if / else`:

```js
let isRaining = true;

if (isRaining) {
    console.log("Take an umbrella");
} else {
    console.log("No umbrella needed");
}
```

**The shape of the syntax:**

```js
if (condition) {
    // runs when the condition is true
} else {
    // runs when the condition is false
}
```

After the `if` comes a condition in brackets -- an expression that works out to true or false. If it is true, the first set of braces runs. Otherwise the `else` branch runs.

## One check only: `if` without `else`

Sometimes you only want to do something when a condition holds, and do nothing at all when it does not:

```js
let score = 85;

if (score >= 60) {
    console.log("You passed!");
}
// if the score is below 60, nothing happens -- the code moves on
```

## Several branches: `else if`

When a decision has three or more outcomes:

```js
let score = 85;

if (score >= 90) {
    console.log("Excellent");
} else if (score >= 60) {
    console.log("Pass");
} else {
    console.log("Fail");
}
```

The checks run **top to bottom**, and the moment one matches, the program takes that branch and stops looking:

1. Is `score >= 90`? 85 >= 90 → false, skip it
2. Is `score >= 60`? 85 >= 60 → **true**, run "Pass", and **the whole if is finished**
3. The `else` never runs

## Indentation is for humans

```js
if (score >= 60) {
    console.log("Pass");
    console.log("Congratulations");
}
```

The lines inside the braces are usually indented by two or four spaces. The indentation is **for you and other people to read** -- the browser does not care about it. It lets you see instantly that those two lines belong to the `if` branch.

```js
// runs, but is painful to read
if (score >= 60) {
console.log("Pass");
console.log("Congratulations");
}

// much easier on the eyes
if (score >= 60) {
    console.log("Pass");
    console.log("Congratulations");
}
```

## Never skip the braces

Beginners often write this:

```js
if (score >= 60)
    console.log("Pass");
    console.log("Congratulations");  // this line ALWAYS runs, no matter what
```

**Only the very first line after the `if` belongs to it.** That second `console.log` runs regardless of the score.

**Safe habit: always use braces**, even for a single line:

```js
if (score >= 60) {
    console.log("Pass");
}
```

Then you can never get confused about which lines belong to the `if`.

## Crash site 1: using `=` instead of `===` in a condition

```js
let status = "vip";

if (status = "normal") {  // WRONG! this is assignment
    console.log("Normal user");
} else {
    console.log("VIP user");
}
```

**Consequence:** `status = "normal"` drops `"normal"` into `status`, and the result of that assignment is `"normal"` -- which counts as true. So the condition is always true and it always prints "Normal user". The fix is `status === "normal"`.

## Crash site 2: writing the branches in the wrong order

```js
let score = 95;

if (score >= 60) {
    console.log("Pass");  // this matches first, so we stop here
} else if (score >= 90) {
    console.log("Excellent");  // never reached!
}
```

**Consequence:** 95 prints "Pass" instead of "Excellent". Because 95 >= 60 matches first, the program never checks the next branch. **With several branches, write the strictest condition first.**

## Summary

- `if (condition) { ... } else { ... }` is the most basic choice structure.
- When true, the `if` branch runs; when false, the `else` branch runs.
- Several branches use `else if`, checked top to bottom, stopping at the first match.
- **Always use braces**, and indent purely for readability.
