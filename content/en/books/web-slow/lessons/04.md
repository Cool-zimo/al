# Numbers vs Strings: Why "3" + "4" = "34"

> This lesson answers the question: "Why on earth does `'3' + '4'` give me `'34'`?" This is the most famous trap in JavaScript, and understanding it will save you from an entire class of bugs.

## A little experiment that shocks everyone

Open the console and type these two lines:

```js
console.log(3 + 4);     // 7
console.log("3" + "4"); // "34"
```

The first one is ordinary addition. 7. No surprises.

The second one is **string joining**, and the answer is `"34"` -- not 7. The two characters have been glued together.

**This is the classic JavaScript trap.** Plenty of developers run into it even after writing hundreds of lines of code.

## Why is `"3" + "4"` not 7?

Because the `+` sign does two different jobs:

- When **both sides are numbers** → do addition
- When **either side is a string** → do joining

```js
console.log(3 + 4);      // 7  (both numbers, so add)
console.log("3" + "4");  // "34"  (both strings, so join)
console.log("3" + 4);    // "34"  (one string, so JS turns 4 into a string too)
```

That third line is the sneaky one. `"3"` is text, so JS sees the string and helpfully converts the `4` into `"4"` as well, then joins them into `"34"`.

## Turning a string into a number: `Number()`

When you get a value that looks like a number but is actually text -- for example, something read out of an input box -- you need to convert it before you can do maths:

```js
let str = "100";
let num = Number(str);  // turns it into the number 100
console.log(num + 50);  // 150 ✅
```

`Number(...)` is simply the tool that says "make this into a number."

```js
console.log(Number("3") + Number("4"));  // 7 ✅
```

## Turning a number into a string: `String()`

Going the other way -- if you need to turn a number into text, for example to display it on a page:

```js
let age = 20;
let msg = "I am " + String(age) + " years old";
console.log(msg);  // "I am 20 years old"
```

Strictly speaking, you could skip `String()` here because `+` will auto-convert the number for you. But writing `String()` out loud makes your intention clear -- anyone reading your code can see you meant to do it.

## Where this bites you in real life

The most common place this happens is reading from an input box:

```html
<input id="price" value="50">
```

```js
let inputVal = document.querySelector("#price").value;
// inputVal is the string "50", not the number 50!
console.log(inputVal + 10);  // "5010" ❌  not 60
console.log(Number(inputVal) + 10);  // 60 ✅
```

A value read out of an input is **always** a string, even when you typed in digits. If you want to do maths, you must convert it first.

## Crash site 1: forgetting to convert before adding

```js
let price1 = "29.9";
let price2 = "15.1";
let total = price1 + price2;
console.log(total);  // "29.915.1" ❌
```

**Consequence:** instead of £45 you get the unreadable `"29.915.1"` and your customer is very confused. The fix is `Number(price1) + Number(price2)`.

## Crash site 2: assuming `Number()` can convert anything

```js
console.log(Number("hello"));  // NaN
```

**Consequence:** `Number("hello")` gives you `NaN`, which stands for Not a Number. Do any further maths with `NaN` and the result stays `NaN`. If you are not sure a value will convert cleanly, check first:

```js
let result = Number("hello");
if (isNaN(result)) {
    console.log("That conversion failed");
}
```

## Summary

- `"3" + "4"` equals `"34"` because `+` joins whenever a string is involved.
- To do real maths, convert first with `Number()`.
- A value read from an input is always a string, so convert before calculating.
- `Number("not a number")` gives `NaN`, which means the conversion failed.
