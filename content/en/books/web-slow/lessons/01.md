# What Code Actually Is

> This lesson answers the question: "How does the text I type turn into a running program?" Once you understand how the browser runs your code, you will know where to look when something goes wrong.

## A program is a list of instructions, run one at a time

You have probably ordered food on your phone. That app is a program full of rules: *if* the user taps this button, *then* show that screen. You did not have to write those rules to use the app -- someone else already did. Today, you become that someone else.

**JavaScript** (JS for short) is a programming language. Think of it as the way you talk to a browser: you write one instruction, the browser carries it out, then moves to the next.

Here is your first program:

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8">
    <title>My first program</title>
  </head>
  <body>
    <script>
      console.log("Hello, world");
    </script>
  </body>
</html>
```

Save this as `index.html` and open it in a browser. Press F12 (or Cmd+Option+I on a Mac), then click the **Console** tab. You will see one line:

```
Hello, world
```

**That is a real program.** It does exactly one thing: it asks the browser to print a sentence into the console.

## The `<script>` tag is a container for code

Inside an HTML file, the `<script>` tag works like a sign taped to the wall that says: "Everything below this is code, not page content. Run it."

```html
<script>
  console.log("This is code");
</script>
```

The browser reads the HTML from top to bottom. When it hits a `<script>` tag, it stops reading the page, runs every line of code inside, and only then keeps going.

**Where you put the script matters:**

| Location | Effect | Recommended? |
|---|---|---|
| Inside `<head>` | Runs before the page has appeared | ⚠️ can cause problems |
| At the very end of `<body>` | Page appears first, code runs last | ✅ recommended |
| Separate `.js` file | Loaded with `<script src="app.js">` | ✅ used in real projects |

**Why put it at the end of `<body>`?** Because JS often needs to touch things on the page -- a button, a paragraph, a picture. If the code runs before the browser has read those elements, it cannot find them and throws an error. Putting the script at the end guarantees that the page is fully ready first.

## Code runs top to bottom, never out of order

This is the single most important rule in programming: **code starts at the first line and runs straight down, one line at a time.**

```js
console.log("First");
console.log("Second");
console.log("Third");
```

The browser prints `First`, then `Second`, then `Third`. Never in reverse, never skipping a line.

Think about cooking instant noodles: boil water, add the noodles, wait three minutes, add the seasoning. Each step depends on the one before it. You cannot season the water before it boils. Code works the same way.

## `console.log` is your megaphone

`console.log(...)` means "print whatever is inside the brackets to the console." It is the tool you will use most often to talk to your program.

```js
console.log("The weather is nice today");
console.log(123);
console.log("My name is Alice and I am 20 years old");
```

Open the console and the output is right there. **Whenever something is not working, your first move should be to throw a few `console.log` lines in and look at what comes out.** That is the most basic -- and most effective -- way to debug.

## Crash site 1: the script runs before the button exists

```html
<!DOCTYPE html>
<html>
  <head>
    <script>
      // I want to attach a click handler to the button -- but it has not been read yet!
      document.querySelector("button").addEventListener("click", function() {
        alert("Clicked");
      });
    </script>
  </head>
  <body>
    <button>Click me</button>
  </body>
</html>
```

**Consequence:** the console shows `Cannot read properties of null`. The browser has not met the `<button>` yet, so `querySelector` finds nothing. The fix is to move the `<script>` to the end of `<body>`, or wait until the page has fully loaded.

## Crash site 2: code written without a script tag

```html
<!DOCTYPE html>
<html>
  <body>
    console.log("Hello");  <!-- Wrong! There is no script tag -->
    <button>Click me</button>
  </body>
</html>
```

**Consequence:** the browser thinks `console.log("Hello");` is just ordinary text and prints it directly onto the page. Your code never runs. The browser only recognises code that lives inside `<script>` tags.

## Summary

- JavaScript is the language you use to talk to the browser, and it **runs one line at a time, top to bottom**.
- The `<script>` tag tells the browser "this is code" -- put it at the end of `<body>`.
- `console.log()` is your basic output tool. Use it constantly to peek at what your program is doing.
- The order of execution is exactly the order you wrote things in. No shuffling, no guessing.
