# Rendering the List: Turning an Array into Elements on the Page

> Last lesson put up the shell. This lesson implements `render()`: it turns every item in the `todos` array into an `<li>` on the page. This is the core step of the whole project.

## The idea behind render

```js
function render() {
    // 1. clear the container first
    list.innerHTML = "";

    // 2. loop through todos, create one <li> for each item
    for (let i = 0; i < todos.length; i++) {
        let todo = todos[i];

        let li = document.createElement("li");
        li.textContent = todo.text;

        list.appendChild(li);
    }
}
```

**Three steps: clear the container → loop through the array → create the elements and attach them.** Every render is a "full repaint" — no matter what changed, it redraws everything from scratch.

## Calling render twice means clearing first

This is a trap you will hit in the grading environment and in real projects too. Suppose `todos = ["apples", "bananas"]`:

```js
function render() {
    // forgot to clear
    for (let i = 0; i < todos.length; i++) {
        let li = document.createElement("li");
        li.textContent = todos[i];
        list.appendChild(li);
    }
}

render();   // page: apples bananas
render();   // page: apples bananas apples bananas  ← duplicated!
```

**Without clearing, the elements keep piling up.** So the very first line of render must always be clearing the container:

```js
function render() {
    list.innerHTML = "";   // ← never skip this line
    // ...
}
```

## Rendering with a delete button

```js
function render() {
    list.innerHTML = "";

    for (let i = 0; i < todos.length; i++) {
        let todo = todos[i];

        let li = document.createElement("li");

        let span = document.createElement("span");
        span.textContent = todo.text;
        li.appendChild(span);

        let delBtn = document.createElement("button");
        delBtn.textContent = "Delete";
        li.appendChild(delBtn);

        list.appendChild(li);
    }
}
```

**One task = text plus a delete button, held inside the `<li>` as two children, a span and a button.** The structure is clear, which also makes binding events to the delete button easy later.

## What rendering really is: data → interface

```
todos = [{id:1,text:"Buy groceries"}, {id:2,text:"Write some code"}]
                ↓  render()
on the page:
  <li>Buy groceries  [Delete]</li>
  <li>Write some code [Delete]</li>
```

**The interface is always a projection of the data.** Changing the data does not automatically update the interface; you must call render again. This rule is the root of every bug in the rest of the project — and it is the cure for every one of them.

## Crash site 1: forgetting to clear, so elements pile up

```js
function render() {
    // forgot list.innerHTML = ""
    todos.forEach(function (todo) {
        let li = document.createElement("li");
        li.textContent = todo.text;
        list.appendChild(li);
    });
}
```

Consequence: every render appends after the elements that are already there, so **the list keeps growing and repeating itself.** The first line must clear.

## Crash site 2: inserting text with innerHTML while rendering

```js
li.innerHTML = "<span>" + todo.text + "</span>";   // todo.text comes from user input
```

Consequence: if the user types `<script>`, that script will run. **To render user content, use `textContent`; never拼接 with `innerHTML`.**

## Rewriting render with forEach

```js
function render() {
    list.innerHTML = "";

    todos.forEach(function (todo) {
        let li = document.createElement("li");
        li.textContent = todo.text;
        list.appendChild(li);
    });
}
```

This is exactly equivalent to the `for` loop, only shorter. **The slow track learns both forms; in real projects `forEach` and `map` are more common.**

## Summary

- render in three steps: clear → loop → create and attach.
- **Clearing the container is the first line of render**, otherwise items pile up.
- The interface is a projection of the data; after changing the data you must re-render.
- For user content use `textContent`; do not拼接 with `innerHTML`.
