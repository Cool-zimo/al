# Reading and Changing Content: `textContent` vs `innerHTML`

> Once you have found an element, the most common thing to do is "read its text" or "change its text." This lesson covers the two properties people mix up most often — and one serious security risk.

## textContent: read and write plain text

```html
<h1 id="title">Old title</h1>
```

```js
let h1 = document.querySelector("#title");

// read
console.log(h1.textContent);   // "Old title"

// write
h1.textContent = "New title";
// the page now shows "New title"
```

**`textContent` only cares about text — never about tags.** It is the safest way to read or write content, and it should be your default choice.

## innerHTML: read and write "HTML with tags"

```html
<div id="box"><p>An original paragraph</p></div>
```

```js
let box = document.querySelector("#box");

console.log(box.innerHTML);
// "<p>An original paragraph</p>" — what you get is a string with tags in it

box.innerHTML = "<p>A new <b>paragraph</b></p>";
// the box now contains a real new <p>, with "paragraph" shown in bold
```

**`innerHTML` parses the string you give it as HTML and renders it.** That power is exactly what makes it dangerous.

## The XSS risk: never put user input into innerHTML

```js
// suppose userInput came from something a user typed in a comment box
let userInput = "<img src=x onerror=alert('you got hacked')>";
document.querySelector("#box").innerHTML = userInput;
```

Consequence: that `<img>` is treated as real HTML, so the JavaScript inside `onerror` actually runs. **If `userInput` was typed by an attacker, they can run arbitrary JS on your page — that is called XSS (cross-site scripting).**

The rule in one sentence: **any untrusted string that came from a user must be written with `textContent`, never with `innerHTML`.**

```js
// the safe version
box.textContent = userInput;   // tags typed by an attacker show up as plain text and never run
```

## Changing attributes: read and write them like object properties

```html
<img id="photo" src="a.jpg" alt="A photo">
<a id="link" href="https://example.com">Click me</a>
```

```js
let img = document.querySelector("#photo");
img.src = "b.jpg";           // change the image URL — the picture swaps instantly
img.alt = "New photo";

let link = document.querySelector("#link");
link.href = "https://qq.com";   // change where the link points
```

**In JavaScript, an HTML attribute is just a property on the element object — write `element.attributeName = value` and you are done.**

## Common attributes

| HTML attribute | How to write it in JS |
|---|---|
| `id` | `el.id` |
| `src` | `el.src` |
| `href` | `el.href` |
| `value` (an input) | `el.value` |
| `disabled` | `el.disabled` |
| `class` | `el.className` (note: not `class`) |

`class` is the exception. Because `class` is a reserved word in JavaScript, it becomes `className`:

```js
let box = document.querySelector("#box");
box.className = "red big";   // set the class
```

## Crash site 1: building a string with user input, then pouring it into innerHTML

```js
let name = prompt("What is your name?");   // user types <script>alert(1)</script>
box.innerHTML = "Welcome, " + name;
```

Consequence: the user's script runs. **Anywhere you concatenate user input, switch to `textContent` instead.**

## Crash site 2: meaning to compare, but writing `=` instead of `===`

```js
let input = document.querySelector("#username");
if (input.value = "admin") {    // typo: a single =, so this is an assignment
    console.log("is admin");
}
```

Consequence: the condition is always true, because `input.value = "admin"` is an assignment expression whose result is `"admin"` — a truthy value. **This is the same old trap from lesson 1, and it still bites in the DOM: use `===` for tests, `=` only for assignments.**

## Summary

- `textContent` reads and writes plain text; it is safe and your everyday choice.
- `innerHTML` reads and writes HTML strings; it carries an XSS risk.
- Anything that came from a user belongs in `textContent`.
- Change attributes with `element.attributeName = value`; for `class`, write `className`.
