# Pop-Up Dialogs: `messagebox`

> A GUI program needs to talk to the user sometimes — to confirm a risky action, report a problem, or ask a yes/no question. `tkinter.messagebox` gives you a handful of ready-made pop-up windows so you don't have to build them from scratch.

## Why Pop-Ups Exist

**A pop-up pauses the flow and forces attention; that's exactly why you should use it sparingly.** In a command-line program you print a message and hope the user sees it. In a GUI the user might not even be looking at the terminal. A `messagebox` puts a small window in front of everything else with a message and a couple of buttons, so the user has to deal with it.

```
import tkinter as tk
from tkinter import messagebox

root = tk.Tk()
root.title("Demo")

def clicked():
    messagebox.showinfo("Hello", "You clicked the button!")

tk.Button(root, text="Click me", command=clicked).pack(padx=20, pady=20)

root.mainloop()
```

**Run this and click the button: a new little window appears with an information icon, your title, your text, and an OK button.** Click OK and it goes away. That's the whole pattern — a function call that blocks until the user responds.

## The Four Read-Only Flavours

**`showinfo`, `showwarning`, and `showerror` all work the same way; only the icon and tone change.**

| Function | Icon shown | Typical use |
|---|---|---|
| `showinfo(title, msg)` | blue "i" | "File saved successfully" |
| `showwarning(title, msg)` | yellow "!" | "You have unsaved changes" |
| `showerror(title, msg)` | red "X" | "Could not open the file" |
| `showinfo` with `parent=` | any | attach to a specific window |

```
def save():
    # pretend to save...
    messagebox.showinfo("Saved", "Your file has been saved.")

def check():
    messagebox.showwarning("Heads up", "This will overwrite the old file.")

def fail():
    messagebox.showerror("Error", "Permission denied:\n cannot write to that folder.")
```

**The second argument is the message body and `\n` produces a line break, so you can write a short paragraph.** Don't pour a stack trace in there — the user doesn't want to read one and you don't want to expose internal details. One or two sentences, then let them click OK.

## Crash Scene 1: Forgetting to Import the Module

```
import tkinter as tk

root = tk.Tk()

def clicked():
    messagebox.showinfo("Hi", "hello")   # WRONG: NameError
```

**`messagebox` is not a submodule that Python imports automatically when you import `tkinter`.** You have to bring it in yourself:

```
from tkinter import messagebox
```

That single line is easy to forget because `tk.Button`, `tk.Label`, and the rest all work with just `import tkinter as tk`. Add the import and the error disappears.

## The Question Functions Return Values

**`askyesno`, `askokcancel`, `askyesnocancel`, and `askretrycancel` don't just show a box — they give you back a value you can branch on.** This is where pop-ups stop being decorative and start controlling your program's logic.

```
from tkinter import messagebox

answer = messagebox.askyesno("Delete", "Delete this file?")
if answer:
    print("user said yes")
else:
    print("user said no")
```

**`askyesno` returns a plain Python `True` or `False`.** `askokcancel` also returns a bool. `askretrycancel` returns `True` for Retry and `False` for Cancel. `askyesnocancel` returns `True`, `False`, or `None` — `None` means the user closed the dialog with the corner X instead of picking an option, so always handle that third case.

```
result = messagebox.askyesnocancel("Save", "Save changes before quitting?")
if result is True:
    save_and_quit()
elif result is False:
    quit_without_saving()
else:            # None
    pass         # don't quit, just go back
```

## Crash Scene 2: Treating the Return Value as a String

```
result = messagebox.askyesno("Continue", "Go ahead?")
if result == "yes":          # WRONG: never matches
    do_it()
```

**The dialog returns `True`/`False`, not the label on the button.** Comparing to `"yes"` or `"ok"` means your branch never runs and you silently do nothing. Compare to `True`, `False`, or — for the three-button version — use `is None`.

## Pinning the Dialog to a Parent Window

**A dialog without a `parent` can get lost behind other windows, especially on Windows and macOS.** Pass `parent=root` (or whatever your main window variable is) and the pop-up stays attached to it.

```
messagebox.showerror(parent=root, title="Oops", message="Something broke")
```

**The parent argument must come first positionally, or you must use the keyword form.** With keyword arguments you can put `parent` anywhere, which is the style to copy. It also centres the dialog over the parent and makes it modal — the user can't ignore it by clicking the main window.

## Crash Scene 3: `mainloop` Isn't Running Yet

```
import tkinter as tk
from tkinter import messagebox

root = tk.Tk()
messagebox.showerror("Uh oh", "Something went wrong")   # WRONG in many setups
root.mainloop()
```

**If you try to show a dialog before `mainloop()` is running — for example at import time or during module-level setup — the dialog may appear but behave oddly, or the program may error out on some systems.** The safe rule: only open a dialog from inside a callback or after `mainloop` has started. If you need to report a startup failure, print to the console instead.

## Putting It Together: Confirm Before Quitting

**A classic use of `askyesno` is asking the user to confirm before doing something destructive.**

```
import tkinter as tk
from tkinter import messagebox

root = tk.Tk()
root.title("Notepad-ish")
root.geometry("300x200")

def on_close():
    if messagebox.askyesno("Quit", "Really quit without saving?"):
        root.destroy()

root.protocol("WM_DELETE_WINDOW", on_close)
root.mainloop()
```

**`root.protocol("WM_DELETE_WINDOW", ...)` lets you intercept the corner close button** and replace the default behaviour with your own function. Now clicking the X triggers your confirmation dialog instead of instantly killing the window.

## Summary

- Import the module explicitly: `from tkinter import messagebox`
- `showinfo`, `showwarning`, `showerror` announce things; they don't return anything useful
- `askyesno` / `askokcancel` return `True`/`False`; `askyesnocancel` can also return `None`
- Always compare the return value to a bool, never to the button label text
- Pass `parent=` so the dialog stays attached to your window
- Only show dialogs after `mainloop` is running, ideally from inside a callback
