# `lambda` and Passing Arguments

> `command` only takes callables with zero arguments, but callbacks almost always need data. `lambda` is the bridge — a way to manufacture a zero-argument function on the spot. This lesson also covers `functools.partial`, the gotcha that catches every tkinter learner, and when you should stop using lambda entirely.

## Why Arguments Are a Problem

**Here's the trap in its simplest form:**

```
def greet(name):
    print(f"hello, {name}!")

tk.Button(root, text="Zhang", command=greet).pack()   # missing argument
```

**`command=greet` passes nothing, and `greet` demands a `name`.** Click it and you get `missing 1 required positional argument: 'name'`.

**`command=greet("Zhang")` is wrong too** — it calls `greet` immediately and hands `None` to `command`.

**You need a wrapper: a function with no arguments whose body calls `greet("Zhang")`.**

## `lambda` in One Line

**`lambda` builds a small function on the spot:**

```
tk.Button(root, text="Zhang", command=lambda: greet("Zhang")).pack()
tk.Button(root, text="Li",   command=lambda: greet("Li")).pack()
```

**`lambda: greet("Zhang")` reads as "a function of no arguments whose body is `greet('Zhang')`".** Click the button and tkinter calls that function, which in turn calls `greet("Zhang")`.

## `lambda` Syntax Refresher

**For comparison, the two forms side by side:**

```python
# ordinary function
def add(a, b):
    return a + b

# equivalent lambda
add = lambda a, b: a + b

print(add(2, 3))   # 5
```

**`lambda parameters: expression`.** The colon must be followed by a single expression — something that produces a value. No statements, no blocks.

## Several Arguments Through `lambda`

```
def set_text(text, colour):
    label.configure(text=text, fg=colour)

tk.Button(root, text="warn",  command=lambda: set_text("warning", "red")).pack()
tk.Button(root, text="ok",    command=lambda: set_text("all good", "black")).pack()
```

**The outer lambda stays argument-free; inside, it can pass any number of arguments to the real function.**

## Freezing the Loop Variable

**`lambda` also captures "which data belongs to which button" — the pattern you'll use constantly:**

```
fruits = ["apple", "banana", "orange"]

for f in fruits:
    tk.Button(root, text=f,
              command=lambda name=f: print(f"picked {name}")).pack()
```

**`lambda name=f: ...` uses a default argument to freeze the current value of `f` inside the lambda.** That default-value trick is the key to everything in this lesson.

## `functools.partial`: `lambda`'s Alternative

**`partial` also bakes arguments into a function:**

```
from functools import partial

def greet(name):
    print(f"hello, {name}!")

tk.Button(root, text="Zhang", command=partial(greet, "Zhang")).pack()
tk.Button(root, text="Li",    command=partial(greet, "Li")).pack()
```

**`partial(greet, "Zhang")` returns a new callable that, when called, runs `greet("Zhang")`.**

**`lambda` and `partial` achieve the same result.** Use `lambda` for quick one-liners; reach for `partial` when the intent needs to read more clearly, or when you're pre-binding several arguments and it's getting hard to read.

## Crash Scene 1: The Classic Loop Trap

**The most famous tkinter bug, in three lines:**

```
buttons = []
for i in range(3):
    btn = tk.Button(root, text=f"btn{i}",
                    command=lambda: print(f"I am btn{i}"))
    btn.pack()
```

**Click any of the three buttons and you get "I am btn2" every time.**

**Why: all three lambdas share the same variable `i`.** By the time you click, the loop has finished and `i` is `2`. Every lambda reads `2`.

**Fix it by freezing the value into a default argument:**

```
for i in range(3):
    btn = tk.Button(root, text=f"btn{i}",
                    command=lambda idx=i: print(f"I am btn{idx}"))
    btn.pack()
```

**`lambda idx=i:` takes a snapshot of `i` at that iteration.** Each lambda carries its own `idx` — problem solved.

**Or use `partial`:**

```
from functools import partial
for i in range(3):
    btn = tk.Button(root, text=f"btn{i}",
                    command=partial(print, f"I am btn{i}"))
    btn.pack()
```

`partial` captures values at the time it's called, so it dodges the trap automatically.

## Crash Scene 2: `curselection()[0]` in a Lambda

```
lb = tk.Listbox(root)
lb.pack()
lb.insert("end", "A", "B", "C")

# this line is fine; the problem is what happens at click time
tk.Button(root, text="show", command=lambda: print(lb.curselection()[0])).pack()
```

**The lambda isn't the bug — the missing guard is.** `curselection()` returns an empty tuple when nothing is selected, and `[0]` raises `IndexError`. The check belongs inside the callback:

```
def show():
    sel = lb.curselection()
    if sel:
        print(lb.get(sel[0]))

tk.Button(root, text="show", command=show).pack()
```

## Crash Scene 3: Multiple Statements in a Lambda

**A lambda body must be a single expression:**

```
# WRONG: lambda bodies can't contain statements
btn = tk.Button(root, text="click",
                command=lambda: print("1"); print("2")).pack()
```

**The fix is to write a real function:**

```
def on_click():
    print("1")
    print("2")

btn = tk.Button(root, text="click", command=on_click).pack()
```

**Rule of thumb: if the body is more than two lines, stop fighting lambda and write a function.** Your future self will thank you when you're reading the code at 2 a.m.

## `lambda` Receiving the Event Object

**A callback bound with `bind` receives an event object, so the lambda must accept it:**

```
def on_click(event):
    print("clicked at:", event.x, event.y)

btn = tk.Button(root, text="click me")
btn.bind("<Button-1>", on_click)
```

**`on_click` declares `event`, and `bind` fills it in automatically.** Lesson 18 covers `bind` properly.

## The Default-Argument Recipe, Summarised

**The template for freezing a loop variable:**

```
# general form
lambda param=loop_var: expression

# concrete examples
lambda i=i:     do_something(i)
lambda name=f:  greet(name)
lambda idx=i:   select(idx)
```

**A default argument captures the value at definition time.** Each lambda gets its own private copy, so they don't step on each other.

## Worked Example: A Menu Built From a List

```
import tkinter as tk

root = tk.Tk()
root.title("Dynamic Menu")

def action(name):
    label.configure(text=f"ran: {name}")

label = tk.Label(root, text="pick an action")
label.pack(pady=10)

items = ["new", "open", "save", "save as", "quit"]
for item in items:
    tk.Button(root, text=item,
              command=lambda name=item: action(name)).pack(fill="x", padx=20)

root.mainloop()
```

**Five buttons, one callback, each carrying its own name.** Add a sixth item to the list and you get a sixth button for free — that's the payoff of generating UI from data.

## Summary

- `command` accepts only zero-argument callables; to pass data you must wrap with `lambda` or `partial`
- `lambda: func(args)` creates a "run it later" function
- **In a loop, use `lambda param=loop_var:` to freeze the current value** — without it, every lambda shares the final value
- `functools.partial(func, arg)` is a clearer alternative in many cases
- A lambda body is one expression; for more, write a function
- Event callbacks receive an `event` object, so declare the parameter
