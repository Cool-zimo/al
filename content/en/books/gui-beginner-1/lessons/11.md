# Entry: The Single-Line Input Box — `get`, `delete`, `insert`

> Entry is the workhorse of every login screen, search bar, and settings dialog. It holds exactly one line of text. This lesson covers its four core methods — `get`, `delete`, `insert`, `index` — plus `StringVar` and `trace`, the pair that turns a plain input box into a living piece of your program's data.

## Entry in One Glance

**Entry is the single-line input widget.** Type something, read it back, clear it, change it — that's the whole job.

```
import tkinter as tk

root = tk.Tk()
root.title("Input Box")

entry = tk.Entry(root, width=30)
entry.pack(padx=10, pady=10)

root.mainloop()
```

Run it and you get a thin white bar where the blinking cursor lives. Click inside, type a few characters, and they appear. So far, so obvious — but the real power is what you do with those characters in code.

**The most useful arguments:**

| Argument | What it does |
|---|---|
| `width` | Display width in characters |
| `show` | Replace every character with a symbol (password mode) |
| `state` | `"normal"` editable / `"readonly"` selectable-but-not-changeable / `"disabled"` greyed out |
| `fg` / `bg` | Text colour / background colour |
| `font` | The font used for typed text |
| `justify` | Alignment: `"left"` / `"center"` / `"right"` |
| `validate` / `validatecommand` | Validate each keystroke (advanced) |

## `show`: Turning Entry into a Password Box

**`show="*"` hides what the user types:**

```
pwd = tk.Entry(root, show="*")
pwd.pack()
```

Type `secret` and the box shows `******`. The actual string is still there untouched — `show` only changes what the screen draws.

```
pwd.get()   # returns the real string "secret", not asterisks
```

**This is exactly how every password field on the web works.** The value is never altered; only its visual representation is masked.

## `state`: Editable, Read-Only, Disabled

**Three states, three different behaviours:**

```
tk.Entry(root, state="normal")     # editable (default)
tk.Entry(root, state="readonly")   # can select and copy, cannot type
tk.Entry(root, state="disabled")   # greyed out, ignores all interaction
```

**Read-only is perfect for a result field.** The user sees the answer but can't accidentally edit it:

```
result = tk.Entry(root, state="readonly")
result.insert(0, "42")
```

**Crash Scene: `insert` on a read-only Entry blows up.**

```
entry = tk.Entry(root, state="readonly")
entry.insert(0, "hello")
# TclError: state must be normal to modify text
```

**The fix is a quick toggle: switch to normal, write, switch back.**

```
entry.configure(state="normal")
entry.delete(0, "end")
entry.insert(0, "new content")
entry.configure(state="readonly")
```

That four-line dance is the official recipe. Memorise it; you'll use it a lot.

## `get`: Reading What the User Typed

**`entry.get()` returns the current contents as a string — always a string, even if it looks like a number.**

```
def show():
    print("You typed:", entry.get())

tk.Button(root, text="Print", command=show).pack()
```

**An empty box returns `""`, not `None`.** This matters in conditions:

```
if entry.get():        # True when something was typed
    do_something()
if entry.get() == "":  # same idea, spelled out
    do_something()
```

Never write `if entry.get() is None:` — it will never match.

## `insert`: Putting Text In

**`insert(index, string)` drops text at the given position.**

```
entry.insert(0, "default value")   # at the very beginning
entry.insert("end", "appended")    # at the end
entry.insert(tk.END, "same")       # tk.END is identical to "end"
```

**`"end"` is a tkinter constant meaning "the position right after the last character".**

**The standard way to set a placeholder:**

```
entry = tk.Entry(root)
entry.insert(0, "Type here...")
entry.pack()
```

Note that this is *not* a true placeholder — the text stays there as real content and the user has to delete it manually. A real placeholder needs focus events (Lesson 19).

## `delete`: Removing Text

**`delete(start, end)` removes the slice from `start` up to, but not including, `end`.**

```
entry.delete(0, "end")    # wipe the whole box
entry.delete(0, 5)        # remove the first 5 characters
entry.delete(tk.END)      # remove the single character just before the cursor
```

**`"end"` as the second argument means "all the way to the tail".** The first form is your all-purpose "clear the field" button.

## `index`: Where Is the Cursor?

**`entry.index("insert")` returns the cursor's current position as an integer.**

```
pos = entry.index("insert")          # e.g. 3
entry.insert("insert", "INSERTED")   # inserts at the blinking cursor
```

**`"insert"` is a built-in position name, like `"end"`.** There's also `"sel.first"` / `"sel.last"` for the current selection, and `"@x,y"` for the character at a pixel coordinate.

## `StringVar`: Binding a Variable to the Box

**A `StringVar` is a string that tkinter watches. Change it, and every widget tied to it updates automatically.**

Without it, changing a box means two steps:

```
entry.delete(0, "end")
entry.insert(0, "new value")   # two calls, every single time
```

With it, one call does the job:

```
import tkinter as tk

root = tk.Tk()

var = tk.StringVar()
var.set("initial text")

entry = tk.Entry(root, textvariable=var)
entry.pack()

tk.Button(root, text="Say hi",
          command=lambda: var.set("hi there")).pack()

root.mainloop()
```

**`textvariable=var` is the bridge.** Click the button and the Entry repaints itself — no `delete`, no `insert`, no manual refresh.

## Reading and Writing a `StringVar`

**`var.set(value)` writes; `var.get()` reads. That's the whole API.**

```
var = tk.StringVar()
var.set("abc")
print(var.get())   # "abc"
```

**Once bound, `var.get()` and `entry.get()` return the same string — they're two views of one value.**

```
var = tk.StringVar(value="initial")
entry = tk.Entry(root, textvariable=var)
entry.pack()

print(entry.get())   # "initial"
print(var.get())     # "initial", identical
```

**Rule of thumb: whenever you need to read or change an Entry, reach for `StringVar` first.** The code stays cleaner and you avoid the delete/insert shuffle.

## The Four Variable Classes

**tkinter has four "watchable" variable types:**

| Class | Python type behind it | Typical widgets |
|---|---|---|
| `StringVar` | `str` | Entry, Label, OptionMenu |
| `IntVar` | `int` | Checkbutton, Radiobutton, Scale |
| `DoubleVar` | `float` | Scale |
| `BooleanVar` | `bool` | Checkbutton |

**Every one of them uses `get()` and `set()`.** They're interchangeable in spirit; the difference is what kind of value they hold.

## Crash Scene 1: Forgetting to Set the Initial Value

**Creating a `StringVar` without a value leaves the Entry blank — silently.**

```
var = tk.StringVar()        # never set
entry = tk.Entry(root, textvariable=var)
entry.pack()
print(var.get())            # ""  -> empty string
```

**Not a crash, but deeply confusing the first time it happens.** Fix it with `var = tk.StringVar(value="...")` or a `var.set(...)` right after.

## Crash Scene 2: The Variable Gets Garbage-Collected

**A `StringVar` created inside a function can vanish when the function returns.**

```
def make_entry():
    var = tk.StringVar(value="x")
    return tk.Entry(root, textvariable=var)   # var may disappear

entry = make_entry()
entry.pack()
# binding stops working; tkinter may segfault or print a warning
```

**The fix is to keep a reference somewhere reachable** — store it on the widget, in the instance, or in a module-level list:

```
entry.var = tk.StringVar(value="x")   # hangs onto the var through `entry`
```

This is one of those "it works on my machine, then crashes on yours" bugs. Anchoring the variable solves it.

## Crash Scene 3: Passing a Plain String Instead of a StringVar

```
name = "hello"
entry = tk.Entry(root, textvariable=name)   # WRONG
```

**`textvariable` demands a tkinter variable object.** A plain `str` has no `get`/`set`, so tkinter rejects it or, worse, fails silently. The correct line is `textvariable=var` where `var = tk.StringVar(value="hello")`.

## Crash Scene 4: Trying to Make Entry Multiline

**Entry physically cannot hold more than one line.**

```
entry.insert("end", "first line\nsecond line")
# the \n shows up as a literal, or the second line gets clipped
```

**When you need paragraphs, switch to `Text` (Lesson 12).** Entry is single-line by design — no amount of packing will change that.

## Live Validation with `validate`

**`validate` plus `validatecommand` checks every keystroke as it happens.**

```
import tkinter as tk

root = tk.Tk()

def only_digits(new_val):
    return new_val.isdigit() or new_val == ""

vcmd = (root.register(only_digits), "%P")

entry = tk.Entry(root, validate="key", validatecommand=vcmd)
entry.pack()

root.mainloop()
```

**Type `12a` and the `a` is rejected before it ever appears.** `validate="key"` fires on each key; `%P` is tkinter's stand-in for "what the box would contain after this keystroke".

**Treat this as a preview, not a tool to memorise.** For everyday work, catching bad input inside a Button callback with `try/except` is far easier to read and debug.

## Summary

- Entry holds **one line**; `get()` always returns a `str`
- `insert(i, s)` writes, `delete(a, b)` removes, `"end"` means the tail
- `show="*"` makes a password box; `state="readonly"` makes a result field
- **`StringVar` is a watched string**; bind it with `textvariable` and `set()` refreshes the widget
- `var.set()` changes the box, `var.get()` reads it — no manual delete/insert
- Alongside `StringVar` there's `IntVar`, `DoubleVar`, `BooleanVar`
