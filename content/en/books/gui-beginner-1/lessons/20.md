# Variable Tracing With `trace`: Update as You Type

> Buttons make things happen after a click. `trace` makes things happen the instant a variable changes — no button required. This lesson explains the three trace modes, the callback signature tkinter expects, and uses both to build a calculator that updates while you type.

## What `trace` Is

**`trace` is a notification system on tkinter's variable classes. When the variable changes, your function runs.**

```
import tkinter as tk

root = tk.Tk()

var = tk.StringVar()

def on_change(*args):
    print("value changed:", var.get())

var.trace("w", on_change)   # watch for writes

var.set("hello")   # on_change fires, prints "value changed: hello"
```

**`var.trace("w", on_change)` says: call `on_change` whenever this variable is written to.** Set the value and the print appears immediately, with no button and no event binding.

## The Three Trace Modes

| Mode | When it fires |
|---|---|
| `"r"` | The variable was read |
| `"w"` | The variable was written to |
| `"u"` | The variable was deleted (`unset`) |

**`"w"` is the one you'll reach for.** Reading and deletion traces have niche uses (debugging, resource cleanup); the live-update pattern is always write.

## The Callback Signature

**tkinter passes three arguments to a trace callback: `name`, `index`, and `mode`** — though the exact form varies between tkinter versions, so the safe play is `*args`.

```
def on_change(var_name, index, mode):
    print(f"{var_name} was {mode}, new value: {var.get()}")

var.trace("w", on_change)
```

**If you only care about the value, keep it simple:**

```
def on_change(*args):
    print("new value:", var.get())

var.trace("w", on_change)
```

**`*args` absorbs whatever tkinter hands over** and keeps your code working across versions. This is the form to memorise.

## Worked Example: A Live Calculator

**Two inputs, one result, no button — the answer appears as you type.**

```
import tkinter as tk

root = tk.Tk()
root.title("Mini Calculator")

tk.Label(root, text="number 1:").grid(row=0, column=0)
tk.Label(root, text="number 2:").grid(row=1, column=0)
tk.Label(root, text="result:").grid(row=2, column=0)

v1 = tk.StringVar()
v2 = tk.StringVar()
result = tk.StringVar()

tk.Entry(root, textvariable=v1).grid(row=0, column=1)
tk.Entry(root, textvariable=v2).grid(row=1, column=1)
tk.Label(root, textvariable=result).grid(row=2, column=1)

def calc(*args):
    try:
        a = float(v1.get() or 0)
        b = float(v2.get() or 0)
        result.set(a + b)
    except ValueError:
        result.set("invalid input")

v1.trace("w", calc)
v2.trace("w", calc)

root.mainloop()
```

**`v1.trace("w", calc)` and `v2.trace("w", calc)` — every change to either input reruns `calc`.** Type `12` in the first box and the result column shows `12` plus whatever's in the second.

**The `or 0` is deliberate.** An empty StringVar is `""`, and `float("")` raises `ValueError`. Substituting `0` turns an empty field into zero instead of an error.

## Crash Scene 1: Callback With the Wrong Number of Parameters

```
def calc():   # no parameters declared
    print(var.get())

var.trace("w", calc)
# calc() takes 0 positional arguments but 3 were given
```

**tkinter always passes its three arguments.** Use `*args` and the error disappears.

## Crash Scene 2: Tracing a Plain String

```
name = ""
name.trace("w", on_change)   # AttributeError: 'str' object has no attribute 'trace'
```

**Only tkinter variable classes have `trace`.** A plain `str`, `int`, or `list` has no such method — wrap it in `StringVar` first.

## Crash Scene 3: Binding Twice, Firing Twice

```
var.trace("w", func)   # first binding
var.trace("w", func)   # second binding
var.set("x")           # func runs twice!
```

**The same callback attached twice executes twice.** It's an easy mistake when refactoring — you move the binding but forget to remove the old one, and suddenly your function runs in duplicate.

**To remove a binding, keep the trace id:**

```
trace_id = var.trace("w", func)
var.trace_remove("w", trace_id)
```

**That symmetry — `trace` returns an id, `trace_remove` consumes it — is how you manage traces cleanly.**

## `trace` Versus `bind`

**Which one should you reach for?**

| Situation | Use |
|---|---|
| A variable's value changed | `trace` (data-driven) |
| The user clicked, pressed, or moved something | `bind` (event-driven) |
| An Entry's content changed | Either works; `trace` reads more naturally |
| A key was pressed | `bind` |
| A Scale or Spinbox moved | `bind`'s virtual events, or `trace` |

**The rule of thumb: data changes → `trace`; user actions → `bind`.** If you're reacting to a variable, trace it. If you're reacting to an event, bind it.

## Live Validation With `trace`

**Validate input the moment it appears.**

```
import tkinter as tk

root = tk.Tk()

var = tk.StringVar()
entry = tk.Entry(root, textvariable=var)
entry.pack()

label = tk.Label(root, text="")
label.pack()

def check(*args):
    val = var.get()
    if val.isdigit():
        label.configure(text="ok all digits", fg="green")
    else:
        label.configure(text="not all digits", fg="red")

var.trace("w", check)
root.mainloop()
```

**Type `123` and the label turns green; type `12a` and it flips red.** No button, no submit — feedback as you go.

## A More Complete Calculator

**Addition, subtraction, multiplication, division, with the operator selectable.**

```
import tkinter as tk

root = tk.Tk()
root.title("Calculator")

tk.Label(root, text="first number").grid(row=0, column=0)
tk.Label(root, text="operation").grid(row=1, column=0)
tk.Label(root, text="second number").grid(row=2, column=0)
tk.Label(root, text="result").grid(row=3, column=0)

v1 = tk.StringVar()
op = tk.StringVar(value="+")
v2 = tk.StringVar()
result = tk.StringVar()

tk.Entry(root, textvariable=v1).grid(row=0, column=1)
ops = tk.OptionMenu(root, op, "+", "-", "*", "/")
ops.grid(row=1, column=1, sticky="ew")
tk.Entry(root, textvariable=v2).grid(row=2, column=1)
tk.Label(root, textvariable=result).grid(row=3, column=1)

def calc(*args):
    try:
        a = float(v1.get() or 0)
        b = float(v2.get() or 0)
        o = op.get()
        if   o == "+": r = a + b
        elif o == "-": r = a - b
        elif o == "*": r = a * b
        elif o == "/" and b != 0: r = a / b
        else: r = "division by zero"
        result.set(r)
    except ValueError:
        result.set("invalid input")

v1.trace("w", calc)
v2.trace("w", calc)
op.trace("w", calc)

root.mainloop()
```

**`OptionMenu` is tkinter's dropdown, bound to a StringVar.** Change the operator, change a number — every alteration recomputes the result.

## `trace` and Over-Triggering

**`trace("w")` fires on every write, even when the value didn't change.**

```
var.set("abc")
var.set("abc")   # same value, but trace still fires
```

**If the callback does heavy work, repeated firing can stall the interface.** Options: use a flag to skip duplicate values, or validate on `<FocusOut>` instead — only when the user leaves the field.

## Summary

- `trace("w", callback)` watches for writes; the callback runs the moment the value changes
- Three modes: `"r"` read, `"w"` write, `"u"` delete
- Write callbacks with `*args` so they accept whatever tkinter passes
- Only variable classes (`StringVar` and friends) support `trace`; plain types don't
- `trace` is for data changes, `bind` is for user actions
- `trace_remove("w", trace_id)` cancels a trace
