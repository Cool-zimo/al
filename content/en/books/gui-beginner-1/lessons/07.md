# pack: Top, Bottom, Left, Right

> pack is the simplest geometry manager, and the first one beginners get comfortable with. This lesson breaks down every pack argument so you know exactly where it works well — and where it falls short.

## pack's Default Behavior

**pack defaults to `side="top"`, stacking widgets top to bottom:**

```
import tkinter as tk

root = tk.Tk()
for color in ["red", "green", "blue"]:
    tk.Label(root, text=color, bg=color, width=20, height=3).pack()
root.mainloop()
```

**The three Labels each occupy their own row from top to bottom.** This is pack at its most intuitive.

## side: Which Edge to Hug

**`side` decides which edge of the parent the widget hugs:**

```
tk.Label(root, text="Top").pack(side="top")
tk.Label(root, text="Bottom").pack(side="bottom")
tk.Label(root, text="Left").pack(side="left")
tk.Label(root, text="Right").pack(side="right")
```

**A practical "top + bottom + left + middle" layout:**

```
import tkinter as tk

root = tk.Tk()

top = tk.Label(root, text="Top title bar", bg="lightblue")
top.pack(side="top", fill="x")

bottom = tk.Label(root, text="Bottom status bar", bg="gray80")
bottom.pack(side="bottom", fill="x")

left = tk.Label(root, text="Left sidebar", bg="lightyellow", width=10)
left.pack(side="left", fill="y")

tk.Label(root, text="Main content area").pack()
root.mainloop()
```

**The order of the `side` arguments affects the final layout** — pack allocates space to each widget "in the order it is called." For complex structures, the recommended approach is Frame partitioning with pack inside each Frame.

## fill: Which Direction to Stretch

**`fill` lets a widget expand when extra space is available:**

| Value | Effect |
|---|---|
| `"none"` | Keep the natural size (default) |
| `"x"` | Fill horizontally |
| `"y"` | Fill vertically |
| `"both"` | Fill in both directions |

```
tk.Label(root, text="Horizontal fill", bg="yellow").pack(fill="x")
tk.Label(root, text="Natural size", bg="green").pack()
```

**The first Label stretches across the full window width; the second keeps its natural text width.**

**Compare the effect of different fill values:**

```
for t, fill in [("none", "none"), ("x", "x"), ("both", "both")]:
    tk.Label(root, text=f"fill={t}", bg=color, width=20).pack(fill=fill)
```

**Only `fill="x"` or `fill="both"` causes the widget to grow wider as the window grows.**

## expand: Do You Claim the Spare Space?

**`expand=True` means "if there is leftover space, give me a share."** It is often paired with `fill`:

```
tk.Label(root, text="expand=True, fill='both'", bg="red").pack(expand=True, fill="both")
tk.Label(root, text="default", bg="blue").pack()
```

**The red Label claims all the space not taken by the blue Label.**

**The difference between `expand` and `fill`:** `expand` decides "do I want space?", while `fill` decides "now that I have space, how do I use it?" Writing only `expand=True` without `fill` gives the widget space but it stays at its natural size, centered. Writing only `fill="both"` without `expand` stretches it only within its own "row."

**The most common combination is `expand=True, fill="both"`:** let one widget (such as the central editor area) occupy all the remaining space, resizing along with the window.

## padx / pady: External Margin

**`padx`/`pady` leave blank space around a widget:**

```
tk.Button(root, text="Button 1").pack(padx=20, pady=10)
tk.Button(root, text="Button 2").pack(padx=20, pady=10)
```

**The two buttons have 20 pixels of vertical space between them (the two pady values add up), and 20 pixels on each side horizontally.**

**`padx` can also be a tuple `(left, right)`, and `pady` can be `(top, bottom)`:**

```
tk.Label(root, text="Uneven margin").pack(padx=(5, 30), pady=(2, 15))
```

## ipadx / ipady: Internal Padding

**`ipadx`/`ipady` is internal padding that makes the widget itself larger:**

```
tk.Button(root, text="Small").pack()
tk.Button(root, text="Large (internal padding)").pack(ipadx=20, ipady=10)
```

**The second button is noticeably larger than the first** because 20 pixels were added on each side internally, and 10 pixels above and below.

**`padx` vs `ipadx`:** pad is "the distance between me and my neighbors," while ipad is "the inflation of my own size."

## anchor: Which Side of the Allocated Space to Hug

**`anchor` controls where the widget sits within the space it was allocated:**

```
tk.Label(root, text="Top-left", bg="red").pack(anchor="nw", fill="x")
tk.Label(root, text="Centered", bg="green").pack(anchor="center", fill="x")
tk.Label(root, text="Bottom-right", bg="blue").pack(anchor="se", fill="x")
```

**Direction abbreviations:** `n` (north, up), `s` (south, down), `w` (west, left), `e` (east, right) — these can be combined as `"nw"`, `"se"`, etc.

**A common use:** `anchor="w"` left-aligns the text — the Label fills the row but the text sits on the left.

## The Order in Which pack Arranges Widgets

**pack allocates space "in call order," a detail that is often overlooked:**

```
tk.Label(root, text="First").pack(side="top")
tk.Label(root, text="Second").pack(side="top")
```

**The result is "First" on top and "Second" below it.** Reverse the order in the code and the interface reverses.

**A trap that is easy to fall into:**

```
tk.Label(root, text="A").pack(side="left")
tk.Label(root, text="B").pack(side="top")   # this top is relative to the remaining space
```

**When `side` values are mixed, pack first allocates the left edge to the `side="left"` widget, then arranges `side="top"` within whatever space remains.** The result may not be what you intuitively expect. Mixed `side` values get confusing fast; try to keep them consistent.

## Crash Scene 1: Expecting pack to Align Like a Table

```
tk.Label(root, text="Name:").pack(side="left")
tk.Entry(root).pack(side="left")
tk.Label(root, text="Age:").pack(side="left")
tk.Entry(root).pack(side="left")
```

**The four widgets end up in a single line crammed on the left, and the two "rows" never align vertically.** This is not a form; do not write it this way.

**This requirement calls for grid** — pack has no concept of "column alignment."

## Crash Scene 2: `fill="both"` but No `expand`

```
tk.Label(root, text="Editor area", bg="lightblue").pack(fill="both")
```

**It looks as though it fills the space, but it only stretches horizontally within its own "row"; vertically, it never claimed any space.** For it to scale with the window, add `expand=True`:

```
tk.Label(root, text="Editor area", bg="lightblue").pack(expand=True, fill="both")
```

## Crash Scene 3: Trying to Position Precisely After pack

```
label = tk.Label(root, text="x").pack()
label.place(x=100, y=100)   # Error! label is None
```

**`pack()` returns `None`** (as emphasized earlier). And once a widget is packed, you cannot `place` it as well.

**If you need precise positioning, use place from the start.**

## A Practical Example: Toolbar + Body

**The structure pack handles best:**

```
import tkinter as tk

root = tk.Tk()
root.title("Editor")

toolbar = tk.Frame(root, bg="lightgray")
toolbar.pack(side="top", fill="x")

tk.Button(toolbar, text="New").pack(side="left", padx=2, pady=2)
tk.Button(toolbar, text="Open").pack(side="left", padx=2, pady=2)
tk.Button(toolbar, text="Save").pack(side="left", padx=2, pady=2)

status = tk.Label(root, text="Ready", bd=1, relief="sunken", anchor="w")
status.pack(side="bottom", fill="x")

body = tk.Label(root, text="(Editor area here)", bg="white")
body.pack(expand=True, fill="both")

root.mainloop()
```

**This structure is extremely common in real software:** a toolbar at the top, a status bar at the bottom, and a scalable body in the middle. It can all be built with pack + Frame.

## Summary

- `side`: which edge to hug; defaults to `"top"`
- `fill`: stretch along x/y/both; `expand`: do you claim extra space?
- Most useful combo: `expand=True, fill="both"` lets a widget occupy all remaining space
- `padx`/`pady` are external margins; `ipadx`/`ipady` are internal (making the widget grow)
- `anchor` controls which side of its allocated space the widget hugs
- pack excels at: toolbars, simple stacking; it struggles with: aligning into a table (use grid)
