# `bind` and Event Sequences

> `command` covers clicks on a handful of widgets. Everything else — mouse movement, key presses, double-clicks, window resizing — goes through `bind`. This lesson covers event sequences, the difference between widget-level and global bindings, and the `event` object that arrives with every callback.

## What `bind` Does

**`bind` connects an event sequence to a callback. When the event happens, tkinter calls your function and hands it an event object.**

```
import tkinter as tk

root = tk.Tk()

def on_click(event):
    print(f"clicked at ({event.x}, {event.y})")

root.bind("<Button-1>", on_click)   # bind left mouse button
root.mainloop()
```

**Click anywhere in the window and the terminal shows the coordinates.** `Button-1` is the left button; `event.x` and `event.y` are measured from the top-left corner of whatever you bound to.

## Event Sequence Syntax

**A sequence is a string: `<modifier-type-detail>`.**

```
<Button-1>     -> left mouse button pressed
<Button-3>     -> right mouse button pressed
<Double-1>     -> left button double-click
<Enter>        -> mouse enters the widget
<Leave>        -> mouse leaves the widget
<Key>          -> any key pressed
<Return>       -> the Enter key
<Shift_L>      -> left Shift key
<Configure>    -> the window was resized or moved
```

**The common event types:**

| Type | Meaning |
|---|---|
| `Button-1` / `2` / `3` | Left / middle / right button pressed |
| `ButtonRelease-1` | Left button released |
| `Motion` | Mouse moved |
| `Enter` / `Leave` | Mouse entered / left the widget |
| `Key` / `KeyPress` | A key was pressed |
| `KeyRelease` | A key was released |
| `FocusIn` / `FocusOut` | Widget gained / lost focus |
| `Configure` | Widget was resized or repositioned |
| `Destroy` | Widget is being destroyed |

## Widget-Level Versus Global

**Bind to a widget and only that widget triggers the callback.**

```
btn = tk.Button(root, text="button")
btn.bind("<Enter>", lambda e: print("mouse entered"))
```

**Bind to `root` and the whole window listens.**

```
root.bind("<Key>", lambda e: print("pressed", e.char))
```

**The difference is reach.** A widget-level binding is precise — the mouse must be over that button. A root binding catches everything the window receives. Pick the narrower scope that does the job; a global key binding can interfere with text entry if you're not careful.

## The `event` Object

**tkinter passes an event object whether you want it or not. It carries everything about what just happened.**

| Attribute | Meaning |
|---|---|
| `event.x` / `event.y` | Coordinates relative to the bound widget |
| `event.x_root` / `event.y_root` | Coordinates relative to the screen |
| `event.char` | The typed character, if printable |
| `event.keysym` | The key's symbolic name ("Return", "Escape", "a") |
| `event.keycode` | The raw keycode |
| `event.num` | Mouse button number (1/2/3) |
| `event.widget` | The widget that triggered the event |
| `event.width` / `event.height` | New size reported by `Configure` |

## Reading Key Presses

```
def on_key(event):
    print(f"char: {event.char!r}, key: {event.keysym}")

root.bind("<Key>", on_key)
```

**`event.char` is the character — `'a'`, `'1'`, a space is `' '`. `event.keysym` is the key name — `"Return"`, `"Escape"`, `"Shift_L"`.**

**Crash Scene: `event.char` is empty for function keys.**

```
event.keysym == "Return"   # Enter
event.keysym == "Escape"   # Esc
event.keysym == "Tab"      # Tab
```

**To detect a function key, use `event.keysym`, not `event.char`.** The latter is `''` for anything without a printable character.

## `<Return>`: Submitting on Enter

**The single most common keyboard binding — submit when the user presses Enter in an entry box.**

```
entry = tk.Entry(root)
entry.pack()
entry.bind("<Return>", lambda e: print("submit:", entry.get()))
```

**The lambda must accept the event parameter** even if it never names it — `bind` will pass it regardless. `lambda e:` is the conventional way to ignore it.

## Crash Scene 1: Forgetting to Accept the Event

```
def handler():   # no event parameter
    print("clicked")

btn.bind("<Button-1>", handler)
# clicking: handler() takes 0 positional arguments but 1 was given
```

**`bind` always passes one argument. The fix is to declare it.**

```
def handler(event):
    print("clicked")
```

**If you truly don't need it, swallow it with a lambda:**

```
btn.bind("<Button-1>", lambda e: do_something())
```

## Crash Scene 2: Expecting `command` to Pass an Event

```
def handler(event):
    print(event)

btn = tk.Button(root, text="click", command=handler)
# clicking: handler() missing 1 required positional argument: 'event'
```

**`command=` calls the callback with zero arguments. Only `bind` supplies an event object.**

**If one function must work both ways, give the parameter a default:**

```
def handler(event=None):
    print("clicked or keyed")

btn = tk.Button(root, text="click", command=handler)
btn.bind("<Button-1>", handler)
```

## Crash Scene 3: No Focus, No Keyboard Event

```
entry.bind("<Key>", on_key)   # only fires while entry has focus
```

**Keyboard events go only to the focused widget.** If you want the whole window to respond, bind to `root`. To put focus somewhere deliberately:

```
entry.focus_set()   # give the entry focus as soon as the window opens
```

**`focus_set()` is the little touch that makes your form feel right** — the cursor is already blinking in the first field instead of making the user click it.

## Virtual Events

**tkinter defines higher-level events using double angle brackets.**

| Event | Fires when |
|---|---|
| `<<ListboxSelect>>` | A Listbox selection changed |
| `<<ComboboxSelected>>` | A Combobox item was picked |
| `<<NotebookTabChanged>>` | A Notebook tab switched |
| `<<TreeviewSelect>>` | A Treeview selection changed |

**They bind exactly like ordinary events:**

```
lb.bind("<<ListboxSelect>>", on_select)
```

**Virtual events are the clean way to react to widget-level changes** without polling — tkinter tells you the moment they happen.

## Modifier Keys

**Event sequences support modifiers:**

```
<Control-s>     -> Ctrl+S
<Alt-F4>        -> Alt+F4
<Shift-Return>  -> Shift+Enter
```

**Watch the spelling — uppercase letter, hyphen, no spaces:**

```
root.bind("<Control-s>", lambda e: print("save"))
root.bind("<Control-Shift-s>", lambda e: print("save as"))
```

## Stopping an Event With `"break"`

**Returning `"break"` from a callback stops the event from propagating further.**

```
def on_close(event):
    print("intercepted Alt+F4")
    return "break"

root.bind("<Alt-F4>", on_close)
```

**`"break"` tells tkinter "I handled this, don't pass it on."** It's how you build "are you sure you want to quit?" prompts, as Lesson 21 will show with messagebox.

## Worked Example: A Mouse Tracker

```
import tkinter as tk

root = tk.Tk()
root.title("Mouse Tracker")

label = tk.Label(root, text="move the mouse in here")
label.pack(padx=20, pady=20)

def on_motion(event):
    label.configure(text=f"({event.x}, {event.y})")

root.bind("<Motion>", on_motion)
root.mainloop()
```

**Move the mouse over the window and the label updates live.** It's the smallest possible example of an event-driven interface.

## The `add` Argument

**By default, a second `bind` for the same event replaces the first. Use `add="+"` to stack them.**

```
def a(event): print("A")
def b(event): print("B")

btn.bind("<Button-1>", a)
btn.bind("<Button-1>", b)          # replaces a
btn.bind("<Button-1>", b, add="+") # adds b alongside a; both run
```

**`add="+"` is rare but valuable when you're layering behaviour** — say, one library wants the event and so does your own code.

## Summary

- `bind(sequence, callback)` attaches behaviour; the callback **must accept one event argument**
- Sequences look like `<modifier-type-detail>`: `<Button-1>`, `<Return>`, `<Configure>`
- Useful event fields: `x`/`y` (relative to the widget), `char`/`keysym` (the key), `widget` (what fired)
- Bind to `root` for global response; bind to a widget for a narrow scope
- `command=` callbacks get **no** event; `bind` callbacks get **one**
- `return "break"` halts event propagation
