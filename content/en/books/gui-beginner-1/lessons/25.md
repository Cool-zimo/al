# Extra Windows with `Toplevel` (and Modal vs Non-Modal)

> One window is rarely enough. A settings panel, a help box, a confirmation sheet — these all want to be separate windows. `tkinter.Toplevel` makes a second (or third) window, and with `grab_set()` you can make it modal: the user has to deal with it before going back to the main window.

## A Second Window in Three Lines

**`Toplevel(root)` creates a new independent window; after that it accepts widgets exactly like `root` does.**

```
import tkinter as tk

root = tk.Tk()
root.title("Main")

def open_window():
    top = tk.Toplevel(root)
    top.title("Extra window")
    tk.Label(top, text="Hello from a second window!").pack(padx=20, pady=20)

tk.Button(root, text="Open window", command=open_window).pack()

root.mainloop()
```

**Click the button and a brand-new window appears, complete with its own title bar and close button.** It runs on the same `mainloop`, so closing the main window closes everything. Any widget you already know — Label, Entry, Button — can be packed into a Toplevel just as it would be into root.

## Crash Scene 1: Treating `Toplevel` Like a Function Call

```
top = tk.Toplevel(root).title("Extra")   # WRONG-ish: works, but obscures the flow
```

**Chaining `.title(...)` after the constructor is legal but confusing, and it stops working the moment you want to do more with `top`.** The readable pattern is three separate lines: create, configure, populate. You'll thank yourself when the window grows.

## Non-Modal Windows: The User Can Switch Back

**A plain Toplevel is non-modal: the user can click back and forth between it and the main window.** That's perfect for a search box, a palette, or a second view of the same data.

```
import tkinter as tk

root = tk.Tk()
root.title("Main")

def open_palette():
    top = tk.Toplevel(root)
    top.title("Colours")
    for colour in ("red", "green", "blue"):
        tk.Button(top, text=colour,
                  command=lambda c=colour: root.configure(bg=c)).pack(fill="x")

tk.Button(root, text="Pick colour", command=open_palette).pack()

root.mainloop()
```

**Because the window is non-modal, the user can leave it open and keep working.** The buttons reach back into `root` because `root` is in scope. That's the whole trick: a Toplevel is just another container, so variables from the outer function work inside it.

## Making It Modal: `grab_set`

**A modal window freezes the rest of the app until the user closes it — exactly what you want for a confirmation or a required form.**

```
import tkinter as tk

root = tk.Tk()
root.title("Main")

def confirm():
    top = tk.Toplevel(root)
    top.title("Confirm")
    tk.Label(top, text="Delete everything?").pack(padx=20, pady=10)
    tk.Button(top, text="Yes, delete",
              command=lambda: (print("deleted"), top.destroy())).pack(side="left")
    tk.Button(top, text="Cancel", command=top.destroy).pack(side="left")
    top.grab_set()       # modal: block the rest of the app

tk.Button(root, text="Delete all", command=confirm).pack()

root.mainloop()
```

**`top.grab_set()` makes `top` the only window that accepts input.** Clicks on the main window do nothing until `top` is destroyed. This is the standard pattern for "are you sure?" dialogs and required-data-entry pop-ups.

## Crash Scene 2: Modal But No Way to Close It

```
def confirm():
    top = tk.Toplevel(root)
    tk.Label(top, text="Important!").pack()
    top.grab_set()        # WRONG-ish: no button or protocol to destroy top
```

**If nothing inside the window calls `top.destroy()`, the grab never lifts and the whole app is permanently locked.** Every modal window needs either a Button that calls `top.destroy()` or a `protocol("WM_DELETE_WINDOW", ...)` handler that does — usually both.

## Making It Wait: `wait_window`

**Sometimes you need the *value* the user entered in the popup. `wait_window` pauses the calling function until the Toplevel is destroyed, letting you read the result afterwards.**

```
import tkinter as tk

root = tk.Tk()
root.title("Main")

def ask_name():
    result = {"name": None}
    top = tk.Toplevel(root)
    top.title("Enter name")

    entry = tk.Entry(top)
    entry.pack(padx=10, pady=10)

    def submit():
        result["name"] = entry.get()
        top.destroy()

    tk.Button(top, text="OK", command=submit).pack()
    top.grab_set()
    top.wait_window()          # pause here until top is destroyed

    if result["name"]:
        print(f"got: {result['name']}")

tk.Button(root, text="Ask name", command=ask_name).pack()

root.mainloop()
```

**`wait_window()` blocks the function that called it, but the event loop keeps spinning — so the popup stays responsive.** When `submit` calls `top.destroy()`, `wait_window()` returns and the function resumes, now able to read `result["name"]`. Using a dict (or a `list` with one element) dodges the problem of assigning to a local inside a nested function.

## Crash Scene 3: Forgetting `wait_window` and Reading Too Early

```
def ask_name():
    top = tk.Toplevel(root)
    entry = tk.Entry(top)
    entry.pack()
    tk.Button(top, text="OK", command=top.destroy).pack()
    print(entry.get())     # WRONG: prints "" immediately, before user types
```

**Without `wait_window()`, your code charges straight on and reads the Entry the instant it's created — which is empty.** The fix is `top.wait_window()` placed after the widgets and before the read.

## Transient, Geometry, and Other Window Tweaks

**A few extra calls make a Toplevel feel intentional rather than accidental.**

```
top = tk.Toplevel(root)
top.title("Settings")
top.geometry("300x150")
top.transient(root)      # stay on top of root, minimise together
top.resizable(False, False)
```

**`transient(root)` tells the window manager to keep the popup above its parent and minimise it with the parent.** `resizable(False, False)` locks the size so the user can't accidentally reshape a small dialog. Together they're the difference between a polished settings window and a stray rectangle.

## Putting It Together: A Custom Confirm Dialog

**You can build your own dialog that looks and behaves like `messagebox.askyesno`, using a Toplevel plus `grab_set` and `wait_window`.**

```
import tkinter as tk

def ask_yes_no(root, question):
    answer = None
    top = tk.Toplevel(root)
    top.title("Confirm")
    top.transient(root)
    tk.Label(top, text=question, padx=20, pady=15).pack()

    def yes():
        nonlocal answer
        answer = True
        top.destroy()

    def no():
        nonlocal answer
        answer = False
        top.destroy()

    tk.Button(top, text="Yes", command=yes).pack(side="left", padx=10, pady=10)
    tk.Button(top, text="No", command=no).pack(side="left", padx=10, pady=10)
    top.grab_set()
    top.wait_window()
    return answer

root = tk.Tk()
root.title("Demo")

def check():
    if ask_yes_no(root, "Really quit?"):
        root.destroy()

tk.Button(root, text="Quit", command=check).pack()

root.mainloop()
```

**`nonlocal answer` lets the inner functions write to the outer function's variable** — the same job a dict did in the previous example, just a little cleaner. Either approach works; pick the one that reads better to you.

## Summary

- `Toplevel(root)` creates a second window; fill it with widgets just like root
- A plain Toplevel is non-modal — the user can switch back and forth
- `grab_set()` makes a window modal; always give the user a way to close it
- `wait_window()` pauses until the window is destroyed, letting you read results after
- `transient(root)` and `resizable(False, False)` polish a popup window
- Use a `nonlocal` variable or a one-element dict to carry a result out of nested callbacks
