# Project: A Window That Says Hello

> So far the material has been零散 (scattered) pieces of knowledge. This lesson ties them together: use Entry (input box) + Button (button) + Label (display) to build a small interactive program. The focus is on how the interface connects to the logic.

## What We Are Building

**The goal is modest: the user types a name, clicks a button, and the program says "Hello, XXX."**

```
Layout (top to bottom):
[ Please enter your name: ]
[ ____________________ ]   <- Entry input box
[ Say Hi ]                  <- Button
Hello, Alice                <- Label shows the result
```

**Each widget has a distinct role:**

| Widget | Role |
|---|---|
| Entry | Let the user type something in |
| Button | Trigger an action |
| Label | Display the result |

## Step 1: Build the Interface Skeleton

**First, place all three widgets on screen; ignore the interaction for now:**

```
import tkinter as tk

root = tk.Tk()
root.title("Greeting Program")

tk.Label(root, text="Please enter your name:").pack()

entry = tk.Entry(root)
entry.pack()

def greet():
    pass   # leave it empty for now

tk.Button(root, text="Say Hi", command=greet).pack()

result_label = tk.Label(root, text="")
result_label.pack()

root.mainloop()
```

**Run it now and the interface appears, but clicking the button does nothing.** The next step brings it to life.

## Step 2: Let the Button Read the Input Box

**Entry's `get()` method retrieves whatever the user typed:**

```
def greet():
    name = entry.get()          # read the input box
    print("Name is:", name)     # print to the terminal first, to verify
```

**`entry.get()` returns a string.** When the user types nothing, it returns the empty string `""`.

**The question: how does the `greet` function get hold of the `entry` variable?** Because `entry` is defined outside the function, you can use it directly inside — it is a global variable, and reading it requires no `global` declaration.

## Step 3: Display the Result on the Label

**Use `result_label.configure(text=...)` to change the text dynamically:**

```
def greet():
    name = entry.get()
    result_label.configure(text=f"Hello, {name}!")
```

**Complete code:**

```
import tkinter as tk

root = tk.Tk()
root.title("Greeting Program")

tk.Label(root, text="Please enter your name:").pack()

entry = tk.Entry(root)
entry.pack()

result_label = tk.Label(root, text="")

def greet():
    name = entry.get()
    result_label.configure(text=f"Hello, {name}!")

tk.Button(root, text="Say Hi", command=greet).pack()
result_label.pack()

root.mainloop()
```

**Run it: type "Alice," click the button, and the Label shows "Hello, Alice!"**

**This is the basic loop of a GUI program: user input → button click → function reads the input → the interface updates.** Every window program you write from now on is essentially an enlarged version of this pattern.

## Other Common Entry Methods

**Entry is a single-line input box with a handful of methods, all of which you should know:**

| Method | Purpose |
|---|---|
| `get()` | Read the value (returns a string) |
| `insert(index, string)` | Insert text at the given position |
| `delete(start, end)` | Delete a range of text |
| `delete(0, "end")` | Clear the entire input box |
| `icursor(index)` | Set the cursor position |
| `select_range(start, end)` | Select a range of text |

**Clearing the input box is a frequent operation:**

```
entry.delete(0, "end")   # "end" is a special position defined by tkinter
```

**`"end"` is a string constant** meaning "the end." It is far more convenient than calculating the length yourself. You can also write `from tkinter import END` and then `entry.delete(0, END)`.

## Setting a Default Value in the Input Box

**Pre-fill the input box with a hint when the program starts:**

```
entry.insert(0, "Default name")
```

**Improved greeting program: after clicking the button, also clear the input box for a smoother experience:**

```
def greet():
    name = entry.get()
    result_label.configure(text=f"Hello, {name}!")
    entry.delete(0, "end")   # clear it, ready for the next input
```

## Crash Scene 1: `entry.get()` Always Returns a String

```
def calc():
    a = entry.get()
    print(a + 10)   # TypeError: can only concatenate str (not "int") to str
```

**`entry.get()` is always a string.** For math you must convert:

```
def calc():
    a = int(entry.get())   # or float()
    print(a + 10)
```

**If the user did not enter a number, `int()` raises `ValueError`.** Exception handling is covered in Lesson 29; for now, just remember that you need to convert.

## Crash Scene 2: Adding Parentheses to the Button's `command`

```
tk.Button(root, text="Say Hi", command=greet()).pack()
```

**Symptoms:** the program runs `greet()` immediately on startup, and the button does absolutely nothing when clicked.

**Why:** `greet()` with parentheses means "call it right now" — it executes at the moment the button is created. But `command` expects a "function object" that it can call later, when the click actually happens.

**Fix:** drop the parentheses:

```
tk.Button(root, text="Say Hi", command=greet).pack()
```

**Mnemonic: `command=greet` means "hand the function to the button; we will talk about it later"; `command=greet()` means "run it right now."**

## Crash Scene 3: Passing Arguments to a Callback Incorrectly

**Want to pass an argument to `greet`? You cannot write `command=greet("Alice")`.** The correct way uses `lambda` (covered in detail in the next chapter; for now, just learn the conclusion):

```
# WRONG
tk.Button(root, text="Say Hi", command=greet("Alice")).pack()

# RIGHT
tk.Button(root, text="Say Hi", command=lambda: greet("Alice")).pack()
```

**`lambda` creates a "delayed execution" mini-function** that only calls `greet("Alice")` when the button is clicked.

## Crash Scene 4: Widget Order and `pack` Order

**`pack()` arranges widgets in the order they are called, from top to bottom:**

```
tk.Label(root, text="First line").pack()
tk.Label(root, text="Second line").pack()
tk.Label(root, text="Third line").pack()
```

**Reverse the code order and the interface reverses.** So interface layout really just means "tweaking the order of widget creation and packing." To make the Label show the result, `result_label` must be packed after `entry` and `button`.

**If you pack `result_label` first and then the button, the result area ends up wedged in the middle.** This is common with pack-only layouts; for complex interfaces, use grid (next chapter).

## Level Up: A Prompt When the Input Is Empty

**Add a check for when the user clicks the button without filling in a name:**

```
def greet():
    name = entry.get().strip()   # strip removes leading and trailing whitespace
    if name == "":
        result_label.configure(text="Name cannot be empty!", fg="red")
    else:
        result_label.configure(text=f"Hello, {name}!", fg="black")
```

**`strip()` matters:** if the user types only spaces, that is logically the same as typing nothing.

**Temporarily changing `fg` (the text color) is a handy way to give feedback**, so the user sees right away where the error is.

## Level Up Again: Pressing Enter Also Says Hello

**In addition to clicking the button, let the user press Enter inside the input box:**

```
def greet():
    name = entry.get().strip()
    if name:
        result_label.configure(text=f"Hello, {name}!", fg="black")
    else:
        result_label.configure(text="Name cannot be empty!", fg="red")

entry = tk.Entry(root)
entry.pack()
entry.bind("<Return>", lambda e: greet())   # Enter also triggers greet
```

**`bind` is covered systematically in the next chapter.** For now, just know that `<Return>` means the Enter key, and the `e` in `lambda e: greet()` is the event object that must be received.

## A Common Structure: One Function Reads, One Function Writes

**Splitting the interface into a "read function" and a "write function" is a good tkinter habit:**

```
def read_input():
    return entry.get().strip()

def write_output(msg, color="black"):
    result_label.configure(text=msg, fg=color)

def greet():
    name = read_input()
    if name:
        write_output(f"Hello, {name}!")
    else:
        write_output("Name cannot be empty!", "red")
```

**The benefit:** if the interface changes (say, to a pop-up dialog), you only edit `write_output` in one place; the business logic stays untouched.

## The Complete Finished Product

**Here is the runnable final version:**

```
import tkinter as tk

root = tk.Tk()
root.title("Greeting Program")
root.geometry("300x200")

tk.Label(root, text="Please enter your name:").pack(pady=5)

entry = tk.Entry(root)
entry.pack(pady=5)
entry.focus_set()   # auto-focus the input box on startup

result_label = tk.Label(root, text="")
result_label.pack(pady=5)

def greet():
    name = entry.get().strip()
    if name:
        result_label.configure(text=f"Hello, {name}!", fg="black")
    else:
        result_label.configure(text="Name cannot be empty!", fg="red")
    entry.delete(0, "end")

tk.Button(root, text="Say Hi", command=greet).pack(pady=5)
entry.bind("<Return>", lambda e: greet())

root.mainloop()
```

**`entry.focus_set()` puts the cursor in the input box when the program starts**, so the user can just type without clicking first — a small touch that noticeably improves the experience.

## Summary

- Three widgets working together: **Entry takes input, Button triggers action, Label displays output**
- `entry.get()` reads the input (always a string; convert with `int()`/`float()` for numbers)
- `entry.delete(0, "end")` clears it; `"end"` is a tkinter constant
- `label.configure(text=...)` updates the display dynamically
- `command=greet` (**no parentheses**); parentheses mean "run immediately"
- For callbacks with arguments, use `lambda`; check empty input with `strip()`
- `entry.focus_set()` auto-focuses and improves the experience
