# grid Weight: Why Widgets Refuse to Move When the Window Grows

> This is the single most frustrating problem in tkinter: you enlarge the window and the widgets stay stubbornly glued to their original positions. This lesson explains `rowconfigure` / `columnconfigure` and the `weight` property. Once you understand it, your interfaces will scale with the window.

## The Symptom: Enlarging the Window, the Widgets Do Not Move

**First, reproduce this classic problem:**

```
import tkinter as tk

root = tk.Tk()
root.geometry("400x300")

tk.Label(root, text="Name:").grid(row=0, column=0)
tk.Entry(root).grid(row=0, column=1)
tk.Label(root, text="Age:").grid(row=1, column=0)
tk.Entry(root).grid(row=1, column=1)

tk.Button(root, text="Submit").grid(row=2, column=0, columnspan=2)

root.mainloop()
```

**After running it, drag the window from 400x300 to 800x600 — and the widgets stay crammed in the top-left corner while the empty space on the right keeps growing.**

**This is the "widgets will not move" problem.**

## The Cause: Every Row and Column Defaults to Weight 0

**grid treats space allocation as a "dividing the cake" problem.** When the window grows, who gets the extra cake? By default, nobody — every weight is 0 — so the widgets keep their original sizes and the leftover space is dumped on the right and bottom edges.

**The fix: use `columnconfigure` and `rowconfigure` to tell grid "this column/row has weight and wants a share of the cake."**

```
import tkinter as tk

root = tk.Tk()
root.geometry("400x300")

root.columnconfigure(1, weight=1)   # column 1 gets weight
root.rowconfigure(2, weight=1)      # row 2 gets weight

tk.Label(root, text="Name:").grid(row=0, column=0)
tk.Entry(root).grid(row=0, column=1, sticky="ew")
tk.Label(root, text="Age:").grid(row=1, column=0)
tk.Entry(root).grid(row=1, column=1, sticky="ew")
tk.Button(root, text="Submit").grid(row=2, column=0, columnspan=2, sticky="ew")

root.mainloop()
```

**Now, when you enlarge the window: column 1 (where the input boxes are) grows wider, and row 2 (where the button is) grows taller.**

## What `weight` Is

**`weight` decides "how the extra space is divided."** It is an integer:

| Situation | Allocation result |
|---|---|
| Every row/column has weight 0 | Nobody wants space; leftover is dumped on the right/bottom |
| Only one column has weight=1 | That column takes all the extra space |
| One column has weight=1, another weight=2 | The second column gets twice as much space as the first |
| Two columns both have weight=1 | The two columns split the space evenly |

**Weight is a ratio, not a pixel count.** `weight=1` and `weight=100` are equivalent in a scenario with only two contenders (both mean "I want a share").

**Multiple columns splitting space proportionally:**

```
root.columnconfigure(0, weight=1)
root.columnconfigure(1, weight=2)
root.columnconfigure(2, weight=1)
# when the window widens, the three columns split space in a 1:2:1 ratio
```

## rowconfigure Works the Same Way

**Rows also have weight:**

```
root.rowconfigure(0, weight=1)   # row 0 grows taller with the window
root.rowconfigure(1, weight=2)   # row 1 grows twice as fast as row 0
```

**A common pattern:** give the row containing the "main content area" a weight of 1 so it stretches with the window, while the row containing the buttons keeps its natural height (weight=0).

```
tk.Label(root, text="Editor area", bg="lightblue").grid(row=0, column=0, sticky="nsew")
tk.Button(root, text="Button").grid(row=1, column=0)

root.rowconfigure(0, weight=1)   # editor row fills
root.rowconfigure(1, weight=0)   # button row stays put
root.columnconfigure(0, weight=1)
```

## sticky Only Makes Sense Together with weight

**Many people write only `sticky="ew"` and forget `columnconfigure(weight=1)` — and the widget still will not fill.**

**Both steps are required:**

```
root.columnconfigure(1, weight=1)           # tell grid: this column has weight
tk.Entry(root).grid(row=0, column=1, sticky="ew")  # tell the widget: fill horizontally in this cell
```

**Without the first:** the cell itself never grows, so the widget has nothing to fill even if it wants to.
**Without the second:** the cell grows, but the widget stays at its natural size, shrinking in the middle of the cell.

**Mnemonic: weight makes the cell grow, sticky makes the widget fill the cell. Neither works without the other.**

## uniform: Making Multiple Columns/Rows Equal in Size

**`uniform` forces multiple rows or columns to be exactly the same width/height:**

```
root.columnconfigure(0, weight=1, uniform="group1")
root.columnconfigure(1, weight=1, uniform="group1")
root.columnconfigure(2, weight=1, uniform="group1")
```

**All three columns are equal in width regardless of content.** Columns sharing the same `uniform` string (the name is arbitrary) are forced to divide space equally.

**Good use cases:** calculator buttons, evenly split panels.

## minsize: Setting a Minimum Size for a Row or Column

**`minsize` guarantees a minimum size for a row/column:**

```
root.columnconfigure(1, weight=1, minsize=100)  # this column is at least 100 pixels wide
root.rowconfigure(0, minsize=50)                 # this row is at least 50 pixels tall
```

**Even if the window is shrunk very small, this column will never go below 100 pixels.**

## Configuring Several at Once: The Loop Approach

**Writing out each column individually gets tedious; use a loop:**

```
for c in range(4):
    root.columnconfigure(c, weight=1)

for r in range(3):
    root.rowconfigure(r, weight=1)
```

**This pairs beautifully with a calculator keypad:**

```
import tkinter as tk

root = tk.Tk()
buttons = [str(i) for i in range(1, 10)] + ["0"]

for c in range(3):
    root.columnconfigure(c, weight=1, uniform="col")

for r in range(4):
    root.rowconfigure(r, weight=1, uniform="row")

r = c = 0
for b in buttons:
    tk.Button(root, text=b).grid(row=r, column=c, sticky="nsew", padx=2, pady=2)
    c += 1
    if c > 2:
        c = 0
        r += 1

root.mainloop()
```

**`sticky="nsew"` + weight on both rows and columns + uniform equal sizing = a calculator that scales with the window while the buttons stay perfectly square.**

## Crash Scene 1: weight Is Set but sticky Is Not

```
root.columnconfigure(1, weight=1)
tk.Entry(root).grid(row=0, column=1)   # forgot sticky
```

**When you enlarge the window, the cell grows but the input box shrinks in the middle and never moves.** Just add `sticky="ew"`.

## Crash Scene 2: sticky Is Set but weight Is Not

```
tk.Entry(root).grid(row=0, column=1, sticky="ew")
# forgot columnconfigure(1, weight=1)
```

**The cell never grows, sticky has no space to fill, and the whole thing is effectively a no-op.**

## Crash Scene 3: weight on the Wrong Row or Column

```
root.columnconfigure(0, weight=1)   # the label column gets weight
tk.Label(root, text="Name:").grid(row=0, column=0)
tk.Entry(root).grid(row=0, column=1)  # the input box column gets nothing
```

**When you enlarge the window, it is the label column that grows ("Name:" gets stretched) while the input box stays put — which is usually the opposite of what you wanted.**

**The fix:** put the weight on column 1, where the input box lives.

## Crash Scene 4: Using grid but Expecting pack's Automatic Stretch

**pack's `fill="both", expand=True` stretches automatically; grid requires an explicit weight configuration.** This is the easiest thing to forget when moving from pack to grid.

## A Quick Reference Table

| Desired effect | Code that must be written |
|---|---|
| A column grows with the window | `columnconfigure(c, weight=1)` + that column's widgets use `sticky="ew"` |
| A row grows with the window | `rowconfigure(r, weight=1)` + that row's widgets use `sticky="ns"` |
| A widget fills its entire cell | `sticky="nsew"` |
| Multiple equal-width columns | `columnconfigure` using the same `uniform` value |
| Minimum row/column size | `minsize=N` |

## Summary

- When widgets refuse to move as the window grows, it is because **every row and column defaults to weight 0**
- `columnconfigure(c, weight=1)` gives column c weight so it can claim space
- weight is a ratio: 1:2 means space is divided 1:2; weight=0 means "do not give me any space"
- **weight makes the cell grow + sticky makes the widget fill the cell; neither works alone**
- `uniform` makes multiple columns/rows equal in size; `minsize` sets a minimum dimension
- With many columns, loop: `for c in range(N): columnconfigure(c, weight=1)`
