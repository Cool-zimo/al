# Menus: Main, Dropdown, and Right-Click

> Every real desktop program has a menu bar across the top: File, Edit, Help. `tkinter.Menu` builds those, plus dropdown submenus and the right-click context menu. Once you learn the three-step recipe, all three kinds fall out for free.

## The Recipe: Make, Add, Attach

**A menu is a widget like any other, but it lives in the window's frame rather than being packed.**

```
import tkinter as tk

root = tk.Tk()
root.title("Menu demo")
root.geometry("300x200")

menubar = tk.Menu(root)        # 1. create the bar
root.config(menu=menubar)      # 2. attach it to the window

def say_hello():
    print("hello!")

menubar.add_command(label="Greet", command=say_hello)   # 3. add items
menubar.add_command(label="Quit", command=root.destroy)

root.mainloop()
```

**Step 1 creates a `Menu` attached to `root`. Step 2 tells the window to display it as the menu bar with `root.config(menu=...)`. Step 3 adds `command` items — each one is just a labelled button that fires a callback.** That's the whole skeleton; everything else is variations on it.

## Crash Scene 1: Forgetting `root.config(menu=...)`

```
menubar = tk.Menu(root)
menubar.add_command(label="Greet", command=say_hello)
# WRONG: menu bar never appears
```

**You can build the menu perfectly and still see nothing, because `root.config(menu=menubar)` is the one line that actually puts it on screen.** If your menu is "missing", this is the first line to look for.

## Dropdown Submenus

**A dropdown is a second `Menu` that you add to the first one with `add_cascade` instead of `add_command`.**

```
import tkinter as tk

root = tk.Tk()
root.title("Editor")

menubar = tk.Menu(root)
root.config(menu=menubar)

# the dropdown is a Menu in its own right
file_menu = tk.Menu(menubar, tearoff=False)

def do_open():  print("open")
def do_save():  print("save")
def do_quit():  root.destroy()

file_menu.add_command(label="Open...", command=do_open)
file_menu.add_command(label="Save", command=do_save)
file_menu.add_separator()          # a horizontal line
file_menu.add_command(label="Quit", command=do_quit)

# cascade attaches the dropdown to the bar
menubar.add_cascade(label="File", menu=file_menu)

root.mainloop()
```

**`add_cascade(label=..., menu=...)` is the bridge: it puts a labelled item on the bar that, when clicked, reveals the submenu you built.** `add_separator()` draws the thin divider line that groups related commands — put it before Quit, before destructive actions, or anywhere it helps readability.

## `tearoff=False` and Why It Matters

**A menu built with `tearoff=True` (the default) has a dotted line at the top that lets the user drag the menu into a floating window of its own.** That was useful in the 1990s; today it mostly confuses people and adds an empty first slot you have to click past.

```
file_menu = tk.Menu(menubar, tearoff=False)
```

**Setting `tearoff=False` removes that dotted line and makes the menu behave like every other modern application.** It costs nothing and makes your program look less like a museum piece.

## Crash Scene 2: Wrong Argument to `add_cascade`

```
menubar.add_cascade(label="File", file_menu)   # WRONG: TypeError
```

**`add_cascade` takes `label=` and `menu=` as keyword arguments. Passing the submenu positionally, or naming it wrong, raises an error.** The correct form is `add_cascade(label="File", menu=file_menu)`.

## A Full Menu Bar

**Three top-level menus follow the same recipe three times.**

```
menubar = tk.Menu(root)
root.config(menu=menubar)

file_menu = tk.Menu(menubar, tearoff=False)
file_menu.add_command(label="Open", command=open_file)
file_menu.add_command(label="Save", command=save_file)
file_menu.add_separator()
file_menu.add_command(label="Quit", command=root.destroy)
menubar.add_cascade(label="File", menu=file_menu)

edit_menu = tk.Menu(menubar, tearoff=False)
edit_menu.add_command(label="Cut", command=cut)
edit_menu.add_command(label="Copy", command=copy)
edit_menu.add_command(label="Paste", command=paste)
menubar.add_cascade(label="Edit", menu=edit_menu)

help_menu = tk.Menu(menubar, tearoff=False)
help_menu.add_command(label="About", command=show_about)
menubar.add_cascade(label="Help", menu=help_menu)
```

**The structure is perfectly regular: one `Menu` per dropdown, then one `add_cascade` per dropdown on the bar.** Once you can type this without thinking, menus stop being a special topic and become just another layout job.

## Right-Click Menus with `bind` and `post`

**A context menu is a menu you display at the mouse position when the user right-clicks.**

```
import tkinter as tk

root = tk.Tk()
root.title("Right-click demo")

def cut():   print("cut")
def copy():  print("copy")
def paste(): print("paste")

# a menu with no tearoff, not attached to any bar
context = tk.Menu(root, tearoff=False)
context.add_command(label="Cut", command=cut)
context.add_command(label="Copy", command=copy)
context.add_command(label="Paste", command=paste)

def show_menu(event):
    context.post(event.x_root, event.y_root)   # pop up at the cursor

# right-click is Button-3 on X11/macOS, Button-2 on some configs
root.bind("<Button-3>", show_menu)

root.mainloop()
```

**`event.x_root` and `event.y_root` are the cursor's coordinates on the screen, which is exactly what `post()` wants.** The menu appears at the mouse and stays until the user picks an item or clicks elsewhere.

## Crash Scene 3: `bind` Expects an Event Argument

```
root.bind("<Button-3>", show_menu)

def show_menu():                  # WRONG: TypeError on click
    context.post(100, 100)
```

**`bind` calls your function with an `event` object whether you want it or not.** Your handler must accept that argument, even if you ignore it. Add `event` as the first parameter and the crash goes away.

## Putting It Together

**One program can have a menu bar *and* a right-click menu — they're independent objects.**

```
import tkinter as tk
from tkinter import messagebox

root = tk.Tk()
root.title("Menu combo")

def about():
    messagebox.showinfo("About", "A menu demo", parent=root)

menubar = tk.Menu(root, tearoff=False)
root.config(menu=menubar)
app_menu = tk.Menu(menubar, tearoff=False)
app_menu.add_command(label="About", command=about)
app_menu.add_command(label="Quit", command=root.destroy)
menubar.add_cascade(label="App", menu=app_menu)

context = tk.Menu(root, tearoff=False)
context.add_command(label="Clear", command=lambda: print("cleared"))
root.bind("<Button-3>", lambda e: context.post(e.x_root, e.y_root))

tk.Label(root, text="Right-click anywhere").pack(padx=20, pady=40)

root.mainloop()
```

**Notice that the right-click menu uses a `lambda` to forward the event, while the bar's items point straight at a function.** Both styles are fine; `lambda e: ...` is just the cheapest way to hand the event through.

## Summary

- The recipe: create `Menu(root)`, call `root.config(menu=bar)`, then `add_command` / `add_cascade`
- A dropdown is a second `Menu` attached with `add_cascade(label=, menu=)`
- `tearoff=False` removes the draggable dotted line at the top
- `add_separator()` draws a divider; use it to group related items
- A context menu is a free-floating `Menu` shown with `.post(x_root, y_root)` inside a `bind` handler
- The handler bound with `bind` must accept the `event` argument
