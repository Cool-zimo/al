# Where tkinter Lives and How to Import It

> In the previous lesson you saw `import tkinter as tk`. This lesson goes deep on that single line — why there are two flavors (`tkinter` and `tkinter.ttk`), what `Tk()` actually returns, and why `mainloop()` is not optional.

## Checking Whether tkinter Is Available

**tkinter ships with the standard library, but "built in" does not always mean "installed."** This is especially common on Linux, where "Python is installed but tkinter is not."

```python
# These lines can run in the web preview; they need no window
import tkinter
print(tkinter.__name__)      # 'tkinter'
print(tkinter.TkVersion)     # 8.6
print(tkinter.Tk, type(tkinter.Tk))  # <class 'tkinter.Tk'>
```

**If the import raises `ModuleNotFoundError: No module named 'tkinter'`, it means Python was installed without tcl/tk:**

- **Windows / macOS:** reinstall the official Python build (the versions from python.org include it).
- **Ubuntu / Debian:** `sudo apt install python3-tk`
- **CentOS / Fedora:** `sudo dnf install python3-tkinter`

**Linux users, take note:** many minimal servers, Docker images, and trimmed-down WSL installs ship a "bare" Python with tkinter missing. After installing it, verify with `python3 -c "import tkinter; print('ok')"`.

## Two Ways to Import

**Approach 1: import the module with an alias (recommended)**

```
import tkinter as tk

root = tk.Tk()
btn = tk.Button(root, text="Button")
```

**Approach 2: import the classes directly**

```
from tkinter import Tk, Button, Label

root = Tk()
btn = Button(root, text="Button")
```

| Comparison | `import tkinter as tk` | `from tkinter import *` |
|---|---|---|
| Readability | High — `tk.Button` makes the source obvious | Low — where did this name come from? |
| Name clashes | None; everything has a `tk.` prefix | **Yes** — collides with the standard library and your own names |
| Official recommendation | ✅ Recommended | ❌ Not recommended |

**`import tkinter as tk` is strongly recommended.** The reason is practical: tkinter contains many names (`Label`, `Frame`, `StringVar`, `END`) that are easy to collide with your own variables. The `tk.` prefix makes the source instantly recognizable.

**Avoid `from tkinter import *` at all costs.** It dumps hundreds of names into your namespace. The moment you write `Label = ...`, every later reference to `tkinter.Label` breaks, and the resulting error is painful to track down.

## A Quick Note on ttk

**tkinter actually contains two sets of widgets:** `tkinter` and `tkinter.ttk` (Themed Tk).

```
import tkinter as tk
import tkinter.ttk as ttk

root = tk.Tk()

# Both sets can be used
old_btn = tk.Button(root, text="Old-style button")     # retro look
new_btn = ttk.Button(root, text="New-style button")    # follows the system theme
```

**For now, just know that ttk exists.** Lesson 15 covers ttk-specific widgets such as Combobox, Spinbox, and Scale that plain tkinter lacks, and explains why ttk is preferred. For the moment, sticking with the `tk.` prefix is enough.

## What `Tk()` Returns

**`tk.Tk()` returns a window object, the "root" of your entire program.**

```
root = tk.Tk()
print(type(root))   # <class 'tkinter.Tk'>
```

**What can you do with this object?** Almost every window operation lives on it:

| Operation | Method / attribute |
|---|---|
| Set the title | `root.title("Title")` |
| Set the size | `root.geometry("400x300")` |
| Change the background color | `root.configure(bg="lightblue")` |
| Shut down | `root.destroy()` / `root.quit()` |

**By convention, it is called `root`, `master`, or `win`.** Roughly 90% of tutorials in the wild call it `root`, so following that convention reduces confusion when you read other people's code.

## Every Widget Must "Know Its Parent"

**The first argument when creating any widget must be its "parent" (the widget it hangs from).**

```
import tkinter as tk

root = tk.Tk()

# The first argument is the parent
label = tk.Label(root, text="I hang from root")
button = tk.Button(root, text="I also hang from root")

root.mainloop()
```

**If you omit the parent, the widget has nowhere to be displayed:**

```
label = tk.Label(text="Forgot the parent")
label.pack()
root.mainloop()
```

**This sometimes runs (Label will auto-attach to the default root window), but the behavior is unreliable — never write it this way.** Always pass the parent explicitly; it is a good habit.

## mainloop, Revisited: What It Really Is

**`mainloop()` starts an "event loop."** Think of it as an endless `while True`:

```python
# Pseudocode to build intuition; this is not the real implementation
def mainloop():
    while the window has not been closed:
        check for events (did the user click? press a key? move the mouse?)
        if so, call the matching callback function
        redraw the interface
```

**This is why the window can "stay visible forever":** it constantly refreshes itself inside that loop. The "when the button is clicked…" callbacks you write are exactly what this loop invokes when an event occurs.

**Why is mainloop required?** Without it, Python finishes executing `tk.Tk()` and hands control back to the operating system. The window is neither drawn nor listening for mouse and keyboard input — so it "crashes out" instantly.

## Crash Scene 1: Misspelling `tkinter`

```
import Tkinter as tk     # Error!
```

**In Python 3, the module is `tkinter` (all lowercase).** `Tkinter` with an uppercase first letter is the Python 2 spelling. If you copy a ten-year-old tutorial, the very first line raises `ModuleNotFoundError`.

**Also note:** submodules such as `tkinter.messagebox` and `tkinter.filedialog` **must be imported separately**. They do not come along for free just because you imported `tkinter`.

```
import tkinter as tk
tk.messagebox.showinfo("Title", "Content")   # AttributeError! messagebox was never imported
```

The correct version:

```
import tkinter as tk
import tkinter.messagebox as mb

mb.showinfo("Title", "Content")
```

**Remember: you can only use what you import.** `import tkinter` gives you `tkinter.Tk` and `tkinter.Label` at that level; `tkinter.ttk`, `tkinter.messagebox`, and `tkinter.filedialog` each require their own import line.

## Crash Scene 2: Import Order Causing a "Chicken-and-Egg" Problem

```
from tkinter import messagebox
import tkinter as tk

root = tk.Tk()
mb.showinfo("hi", "hello")   # Sometimes raises: no display / root window not yet created
```

**Dialogs such as `messagebox` depend on an existing root window.** The correct order is: `import tkinter as tk` first, then create `root = tk.Tk()`, and only then import and use messagebox. The safest style is to put every import at the top of the file.

## Crash Scene 3: Storing a Widget in a Variable You Never Use

```
tk.Label(root, text="Hint").pack()          # no variable, no problem
label = tk.Label(root, text="Hint").pack()  # trap!
print(label)                                 # None
```

**`pack()`, `grid()`, and `place()` all return `None`.** So in the code above, `label` is actually `None`. When you later try `label.configure(text="New text")`, you get `AttributeError: 'NoneType' object has no attribute 'configure'`.

The correct version uses two lines:

```
label = tk.Label(root, text="Hint")
label.pack()
# now you can use the label variable
```

**You will meet this trap again when we cover layout, so remember it now.**

## Inspecting the Window's Own Properties

**The `Tk()` object carries a number of useful properties:**

```
import tkinter as tk

root = tk.Tk()
print(root.title())          # the current title; '' if never set
print(root.geometry())       # the current geometry, e.g. '400x300+100+100'
print(root.winfo_screenwidth(), root.winfo_screenheight())  # screen resolution
print(root.winfo_width(), root.winfo_height())              # current window size
```

**The `winfo_*` family asks for various pieces of "current state":** screen size, window position, widget dimensions. **You need these for "centering a window"** (coming up in the next lesson).

## Summary

- tkinter is a standard library; `import tkinter as tk` is the safest choice — avoid `from tkinter import *`
- tkinter comes in two flavors, `tkinter` and `tkinter.ttk`; ttk widgets look more modern
- `tk.Tk()` returns the root window object, conventionally named `root`; it is the "root" of the program
- The first argument of every widget must be its **parent** — do not skip it
- `mainloop()` is the event loop and the "final stop" of a window program: write it, and write it last
- `pack()`/`grid()`/`place()` all return `None`; never store their return values in a variable
- `messagebox`, `filedialog`, and `ttk` require **separate imports**
