# Asking for One Value: `simpledialog`

> Sometimes you don't need a whole form — you just need the user to type a name, a number, or a password. `tkinter.simpledialog` is the quickest way to pop up a single-input box and get one value back.

## The Three Functions

**`askstring`, `askinteger`, and `askfloat` each show a small dialog with a prompt and a single field; they differ only in what they hand you back.**

| Function | Returns |
|---|---|
| `askstring(title, prompt)` | `str`, or `None` if cancelled |
| `askinteger(title, prompt, ...)` | `int`, or `None` if cancelled |
| `askfloat(title, prompt, ...)` | `float`, or `None` if cancelled |

```
import tkinter as tk
from tkinter import simpledialog

root = tk.Tk()

name = simpledialog.askstring("Name", "What is your name?")
print(repr(name))

root.mainloop()
```

**Type a name, click OK, and `name` is that string. Click Cancel or the X and it's `None`.** That `None` is the key difference from a normal Entry widget — you don't need to wire up a Button and read `.get()`, the dialog does it and returns the answer directly.

## Reading Numbers Safely

**`askinteger` and `askfloat` validate for you: a non-number can't be confirmed.**

```
import tkinter as tk
from tkinter import simpledialog

root = tk.Tk()

def get_age():
    age = simpledialog.askinteger("Age", "How old are you?", minvalue=0, maxvalue=150)
    if age is None:
        print("cancelled")
    else:
        print(f"you are {age}")

tk.Button(root, text="Enter age", command=get_age).pack()

root.mainloop()
```

**`minvalue` and `maxvalue` reject values outside the range and keep the dialog open until the user fixes it.** You don't write a `try/except` for that case — the dialog handles it. Other useful keyword arguments are `initialvalue` (pre-fills the field) and `parent` (anchors the dialog to your window).

## Crash Scene 1: Comparing a Possibly-None Result to a Number

```
count = simpledialog.askinteger("Count", "How many?")
if count > 0:           # WRONG: TypeError when user cancels (None > 0)
    print("positive")
```

**When the user cancels, `count` is `None`, and `None > 0` raises `TypeError`.** The fix is the same guard you use everywhere else: check for `None` first, then do the comparison.

```
count = simpledialog.askinteger("Count", "How many?")
if count is None:
    return
if count > 0:
    print("positive")
```

## Crash Scene 2: Forgetting `parent=` on Some Systems

```
simpledialog.askstring("Name", "Your name?")   # looks fine... sometimes
```

**Without `parent`, the dialog can appear behind your main window on macOS and some Linux setups**, leaving the user wondering why the app froze. Pass `parent=root` and it stays on top and centred.

```
simpledialog.askstring("Name", "Your name?", parent=root)
```

## Using the Result to Update a Widget

**The usual pattern is: pop the dialog from a button callback, then immediately push the answer into a Label or Entry.**

```
import tkinter as tk
from tkinter import simpledialog

root = tk.Tk()

label = tk.Label(root, text="(no name yet)")
label.pack()

def rename():
    name = simpledialog.askstring("Name", "New label text:", parent=root)
    if name:
        label.configure(text=name)

tk.Button(root, text="Rename", command=rename).pack()

root.mainloop()
```

**Notice the truthy check `if name:` — it handles both `None` (cancel) and an empty string (user clicked OK with nothing typed).** If you'd rather treat "empty string" as a real answer, compare explicitly with `is None` instead.

## Asking for a Password

**`simpledialog` can mask the input, but for real password prompts `tkinter` has a separate helper in newer versions — and a manual Entry with `show="*"` is the portable fallback.**

```
import tkinter as tk

root = tk.Tk()

entry = tk.Entry(root, show="*")
entry.pack()

def reveal():
    print(entry.get())

tk.Button(root, text="Submit", command=reveal).pack()

root.mainloop()
```

**`show="*"` replaces every typed character with an asterisk on screen while the real string stays in the widget.** This is the pattern to remember: `simpledialog` is for convenience, but an Entry with `show=` is what you reach for when you need a password field in your main layout.

## Crash Scene 3: Dialogs Must Be Triggered by a Callback

```
import tkinter as tk
from tkinter import simpledialog

root = tk.Tk()
name = simpledialog.askstring("Name", "Name?")   # WRONG: fires at startup
root.mainloop()
```

**If you call `askstring` at module level, it pops up before the main window appears and blocks startup.** Always put the call inside a function that a Button or menu command triggers. The same rule applies to `messagebox` and `filedialog`.

## Putting It Together: A Mini Settings Panel

**A few dialogs can replace a whole settings window when the values are simple.**

```
import tkinter as tk
from tkinter import simpledialog, messagebox

root = tk.Tk()
root.title("Settings")

config = {"title": "My App", "width": 400}

def set_title():
    new = simpledialog.askstring("Title", "Window title:", initialvalue=config["title"], parent=root)
    if new:
        config["title"] = new
        root.title(new)

def set_width():
    w = simpledialog.askinteger("Width", "Window width:", initialvalue=config["width"],
                                minvalue=100, maxvalue=2000, parent=root)
    if w:
        config["width"] = w
        messagebox.showinfo("Updated", f"Width set to {w}")

tk.Button(root, text="Change title", command=set_title).pack(fill="x")
tk.Button(root, text="Change width", command=set_width).pack(fill="x")

root.mainloop()
```

**`initialvalue` pre-fills the field with the current setting, so the user can tweak rather than retype.** And the result is written into a plain dict — your data stays separate from the widgets, which is the theme of Lesson 28.

## Summary

- `askstring`, `askinteger`, `askfloat` return the typed value, or `None` on cancel
- Always check `is None` (or use a truthy check) before doing anything with the result
- `minvalue`/`maxvalue` validate numbers for you; `initialvalue` pre-fills the field
- Pass `parent=root` so the dialog stays on top
- Never call a dialog at module level — only from inside a callback
- For passwords in your main layout, use `Entry(show="*")`
