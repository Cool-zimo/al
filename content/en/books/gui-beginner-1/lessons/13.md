# Checkbutton and Radiobutton

> Pick one of several options, or any number of them — that's the job of Radiobutton and Checkbutton. This lesson explains why tkinter forces you to use variable classes (`BooleanVar`, `IntVar`, `StringVar`) and how the same variable is what makes "pick one" actually mean "pick exactly one".

## Checkbutton: Picking Any Number

**A Checkbutton is a tick box. Tick as many as you like.**

```
import tkinter as tk

root = tk.Tk()
root.title("Multiple Choice")

tk.Checkbutton(root, text="apple").pack(anchor="w")
tk.Checkbutton(root, text="banana").pack(anchor="w")
tk.Checkbutton(root, text="orange").pack(anchor="w")

root.mainloop()
```

**Three boxes appear, all clickable — but your program has no idea which ones are ticked.** There's no variable binding yet, so the ticks live only on screen.

## Binding a Checkbutton to a `BooleanVar`

**Pass a variable class through `variable=` and the box becomes readable from code.**

```
import tkinter as tk

root = tk.Tk()

var_apple  = tk.BooleanVar()
var_banana = tk.BooleanVar()
var_orange = tk.BooleanVar()

tk.Checkbutton(root, text="apple",  variable=var_apple).pack(anchor="w")
tk.Checkbutton(root, text="banana", variable=var_banana).pack(anchor="w")
tk.Checkbutton(root, text="orange", variable=var_orange).pack(anchor="w")

def show():
    fruits = []
    if var_apple.get():  fruits.append("apple")
    if var_banana.get(): fruits.append("banana")
    if var_orange.get(): fruits.append("orange")
    print("selected:", fruits)

tk.Button(root, text="Confirm", command=show).pack()

root.mainloop()
```

**`var.get()` returns `True` or `False`.** Tick the boxes, hit Confirm, and the terminal lists exactly what you picked.

**The mechanical rule: one variable per box, one `if` per variable.** More boxes means more of both — there's no built-in "give me the list of ticked boxes", which is why Checkbutton groups are usually small.

## `onvalue` / `offvalue`: Customising the Values

**By default a Checkbutton reports `True` when ticked and `False` when not. You can change both.**

```
var = tk.BooleanVar()
tk.Checkbutton(root, text="enable", variable=var,
               onvalue="yes", offvalue="no").pack()

# var.get() now returns "yes" or "no"
```

**A common variant pairs `IntVar` with `onvalue=1, offvalue=0`** when the rest of your code expects numbers rather than booleans.

## Radiobutton: Pick Exactly One

**A Radiobutton is the round option button. In a group, one selection cancels the others.**

```
import tkinter as tk

root = tk.Tk()

var = tk.StringVar(value="Beijing")

tk.Radiobutton(root, text="Beijing", variable=var, value="Beijing").pack(anchor="w")
tk.Radiobutton(root, text="Shanghai", variable=var, value="Shanghai").pack(anchor="w")
tk.Radiobutton(root, text="Guangzhou", variable=var, value="Guangzhou").pack(anchor="w")

def show():
    print("selected:", var.get())

tk.Button(root, text="Confirm", command=show).pack()

root.mainloop()
```

**The two lines that matter: `variable` is the same object, `value` is different on every button.** Pick Shanghai and `var` becomes `"Shanghai"`; pick Guangzhou and it becomes `"Guangzhou"`. The old value is overwritten — that's the whole mechanism of mutual exclusion.

## One Variable = One Group

**Radiobuttons that share a `variable` form a group. Different variables mean different groups.**

```
var = tk.StringVar(value="male")
tk.Radiobutton(root, text="male",   variable=var, value="male").pack()
tk.Radiobutton(root, text="female", variable=var, value="female").pack()

# a second, independent question needs a second variable
var2 = tk.StringVar(value="youth")
tk.Radiobutton(root, text="youth",  variable=var2, value="youth").pack()
tk.Radiobutton(root, text="middle", variable=var2, value="middle").pack()
```

**`var` and `var2` are two separate groups and never interfere with each other.** If you have three questions on a form, you need three variables — no shortcuts.

## Why tkinter Insists on Variable Classes

**Crash Scene: binding a plain Python variable.**

```
checked = False
tk.Checkbutton(root, text="agree", variable=checked).pack()   # useless or errors
```

**`variable=` must receive a tkinter variable object.** A plain `bool`, `int`, or `str` has no `get`/`set` machinery, so tkinter can't observe changes through it.

**Why does tkinter bother with these classes at all?** A normal Python variable changes silently — tkinter never hears about it. A variable class is *observable*: change it and the widget redraws; edit the widget and the variable updates. That two-way link is tkinter's entire "data binding" story, and it's the reason every other GUI framework also has something similar.

## Reacting Immediately with `command`

**Both Checkbutton and Radiobutton accept a `command` that fires the moment the state changes.**

```
def on_change():
    print("now:", var.get())

tk.Radiobutton(root, text="A", variable=var, value="A", command=on_change).pack()
tk.Radiobutton(root, text="B", variable=var, value="B", command=on_change).pack()
```

**No Confirm button needed — the terminal prints the new value on every switch.** This is how you build "live preview" controls.

**Two reminders:** `command` is passed without parentheses, exactly like a Button. And if you need to pass arguments, wrap it in `lambda:` (Lesson 17).

## `IntVar` with Radiobuttons

**When your options are numbers, `IntVar` keeps the types clean.**

```
var = tk.IntVar(value=1)

tk.Radiobutton(root, text="small",  variable=var, value=1).pack()
tk.Radiobutton(root, text="medium", variable=var, value=2).pack()
tk.Radiobutton(root, text="large",  variable=var, value=3).pack()

# var.get() returns 1, 2, or 3
```

**This is the right tool for size, level, priority, rating — any discrete numeric choice.** No string parsing, no `int()` conversion.

## `indicatoron`: Making Radiobuttons Look Like Buttons

**`indicatoron=False` hides the round dot and draws a sunken button instead.**

```
var = tk.StringVar(value="A")

tk.Radiobutton(root, text="A", variable=var, value="A",
               indicatoron=False, width=5).pack(side="left")
tk.Radiobutton(root, text="B", variable=var, value="B",
               indicatoron=False, width=5).pack(side="left")
tk.Radiobutton(root, text="C", variable=var, value="C",
               indicatoron=False, width=5).pack(side="left")
```

**The selected one presses in like a toolbar button.** It's a clean look for "view mode", "alignment", or any choice that deserves a button bar rather than a list.

## Crash Scene 1: Radiobuttons With No `value`

```
var = tk.StringVar()
tk.Radiobutton(root, text="A", variable=var).pack()   # value missing
tk.Radiobutton(root, text="B", variable=var).pack()
```

**With no `value`, both buttons use an empty string, so clicking either does nothing useful.** Fix it by giving every button a distinct `value=`.

## Crash Scene 2: Two Variables, Two Groups, No Exclusivity

```
var1 = tk.StringVar()
var2 = tk.StringVar()
tk.Radiobutton(root, text="A", variable=var1, value="A").pack()
tk.Radiobutton(root, text="B", variable=var2, value="B").pack()
```

**Both can be selected at once — the "single choice" behaviour is gone.** Different variables mean different groups. Collapse them into one `var`.

## Crash Scene 3: Reading a Checkbutton Before Setting It

```
var = tk.BooleanVar()
cb = tk.Checkbutton(root, text="agree", variable=var)
cb.pack()

print(var.get())   # False — the default
```

**An unbound-or-just-created `BooleanVar` starts at `False`.** If you want the box pre-ticked, set it explicitly: `var.set(True)` right after creating it.

## Crash Scene 4: `select()` / `deselect()` and the Variable

**You can tick and untick from code, and it syncs with the variable.**

```
cb.select()      # tick it   (same as var.set(True))
cb.deselect()    # untick it (same as var.set(False))
```

**Either path works — pick the one that reads better in context.** Setting the variable is usually cleaner because it keeps all state changes in one place.

## Worked Example: A Settings Panel

**Checkbutton for "notify me by email/SMS", Radiobutton for theme.**

```
import tkinter as tk

root = tk.Tk()
root.title("Settings")

tk.Label(root, text="Notifications (pick any):").pack(anchor="w")
notify_email = tk.BooleanVar()
notify_sms   = tk.BooleanVar()
tk.Checkbutton(root, text="email", variable=notify_email).pack(anchor="w")
tk.Checkbutton(root, text="sms",   variable=notify_sms).pack(anchor="w")

tk.Label(root, text="Theme:").pack(anchor="w")
theme = tk.StringVar(value="light")
tk.Radiobutton(root, text="light", variable=theme, value="light").pack(anchor="w")
tk.Radiobutton(root, text="dark",  variable=theme, value="dark").pack(anchor="w")

def save():
    methods = []
    if notify_email.get(): methods.append("email")
    if notify_sms.get():   methods.append("sms")
    print("notify:", methods, "theme:", theme.get())

tk.Button(root, text="Save", command=save).pack()

root.mainloop()
```

**The pattern is identical every time: declare variables, bind widgets, read variables in the handler.**

## Summary

- **Checkbutton** = any number; bind `BooleanVar`; `get()` gives True/False
- **Radiobutton** = exactly one; **share one `variable`, give each a distinct `value`**
- The four variable classes: `BooleanVar`, `IntVar`, `StringVar`, `DoubleVar`
- `command=` fires when the state changes (no parentheses)
- `onvalue` / `offvalue` customise the values reported
- `indicatoron=False` turns Radiobutton into a button bar
- `select()` / `deselect()` tick and untick from code
