# From the Command Line to a Window

> Every program you have written so far takes input from the keyboard and prints output to the terminal. A window program is different — it sets up a little "shop" and waits for the user to walk in and click things. This lesson explains exactly what problem a GUI solves.

## The Three Pain Points of Command-Line Programs

Here is the program you know best:

```python
name = input("What is your name? ")
print("Hello,", name)
```

**It has three unavoidable limits:**

1. **The order is rigid.** Ask for the name first, then the age; you can't go back and change the name. Want a "refill" button? Impossible.
2. **The interface is made of text.** Menus are printed as a numbered list and the user types `1`/`2`/`3`. A slightly more complex program becomes "type 1 for Beijing, 2 for Shanghai…" and the user gets annoyed.
3. **It can only run once, straight through.** The program starts at the top, reaches the bottom, and exits. There is no room for "open a window → the user clicks whenever → only then do some work."

```python
# A typical "fake menu" — have you written one of these?
print("1. Check balance")
print("2. Transfer money")
print("3. Quit")
choice = input("Choose: ")
if choice == "1":
    ...
```

**It is not that this approach does not work; it is that the experience is poor.** No app on your phone and no program on your computer was built using only `input()` and `print()`.

## What a GUI Is: The Three Elements

**GUI stands for Graphical User Interface.** When you break it down, it consists of only three things:

| Element | English | What it does | Example |
|---|---|---|---|
| Window | Window | The "house" that holds everything | The frame titled "Notepad" |
| Widget / Control | Widget | Something the user can see and touch | Button, entry box, text, dropdown |
| Event | Event | An action the user performs | Click, key press, mouse movement |

**The relationship between the three can be stated in one sentence: widgets sit inside a window, the user's actions become events, and the program responds to those events.**

```
# Pseudocode — understand the idea first, it will not run
Create a window
Put a button inside the window with the text "Click me"
When the user clicks the button:
    Change a line of text to "Thanks for clicking"
Keep the window visible, waiting for the user
```

**That last sentence — "keep it visible, waiting for the user" — is the key.** A command-line program actively runs to completion and exits. A window program is passive: once it starts, it **stands by**. Each click or key press triggers a piece of code.

## Event-Driven Programming: You Are Not Writing a "Flow," You Are Writing "Reactions"

A command-line program is built around "I do this, then I do that." A window program is built around "**when this happens, I do that**."

```python
# Command line: I am active
print("Starting")
data = load_file()
result = process(data)
print(result)

# Window: I am passive; write a pile of "when…" rules
When the "Open" button is clicked → show a file chooser
When the "Analyze" button is clicked → analyze the current text
When the user types in the input box → update the character count live
```

**Making this mental switch is the first real hurdle in learning GUIs.** You stop writing one long, top-to-bottom procedure. Instead, you write a set of **callback functions** — they sit quietly until an event arrives and calls them.

## What Is tkinter, and Can You Eat It?

**tkinter is a standard library that ships with Python** for building window programs. Once Python is installed, tkinter is already on your computer; there is no need for an extra `pip install`.

It wraps a long-established graphics library called **Tcl/Tk** (first released in 1991). Its strengths and weaknesses both come from this heritage:

- **Strengths:** it ships with Python, it is lightweight, it is cross-platform (Windows / macOS / Linux), and it is quick to learn.
- **Weaknesses:** it looks somewhat "retro" and cannot produce flashy interfaces; it is not a good fit for large commercial software.

```python
# Check whether you have tkinter (this one can run in the web preview)
import tkinter
print(tkinter.TkVersion)   # e.g. 8.6
```

**To decide whether tkinter is right for you:** if you have been using Python for less than six months, want to build small tools for your own use, and need to process files / forms / data visualization — tkinter is a good match. If you want a polished app, pixel-perfect control, or a commercial product — look at web front-ends or Qt instead.

## A Minimal Window: Do Not Worry About the Details Yet

First, look at a complete example (**a window cannot open inside a web page — click "Open in VS Code" to run it**):

```
import tkinter as tk

root = tk.Tk()              # create the main window
root.title("My First Window")  # set the title
root.geometry("400x300")    # set the size

root.mainloop()             # start the event loop; only then does the window appear
```

**Those four lines are the complete skeleton of a window program.** The remaining lessons all add things to this skeleton: widgets, events, and layout.

| Code | Purpose |
|---|---|
| `tk.Tk()` | Creates a window object, conventionally named `root` |
| `root.title("...")` | Sets the title bar text |
| `root.geometry("widthxheight")` | Sets the initial size; note the letter **x** |
| `root.mainloop()` | Starts the event loop; **without it the window flashes and vanishes** |

**About `mainloop()`: remember one phrase — it is the program's "final stop."** After you call it, the program parks itself there, handling the user's actions. It only moves past that line once the window has been closed (if there is any code below it).

## Crash Scene 1: Forgetting `mainloop()`, the Window Flashes By

**This is the single most common beginner mistake.**

```
import tkinter as tk

root = tk.Tk()
root.title("Test")
# Oops, forgot to write mainloop()
print("Program ended")
```

**Symptoms:** the program runs "whoosh" for a split second, the window never appears (or appears for 0.01 seconds and vanishes), and the terminal prints "Program ended."

**Why:** without `mainloop()`, Python runs those two lines and exits immediately. The window was just created and never got a chance to be drawn before the program died.

**Fix:** add `root.mainloop()` as the last line.

**By the same logic, code placed after `mainloop()` will never run on time:**

```
root.mainloop()
print("This will never execute")   # it only prints after the window is closed
do_something()                     # called only after the window is closed
```

**Rule: write only "cleanup code" after mainloop.**

## Crash Scene 2: Writing `mainloop` Too Early

```
root = tk.Tk()
root.mainloop()          # Too early!
root.title("Title")      # The window is already looping; only now do you set the title
```

**Even though the title will take effect (at the very last moment before the window closes), the logic is wrong.** The correct order is: **prepare the window and all its widgets first, and only then call `mainloop()`.**

## Crash Scene 3: Calling `Tk()` Twice

```
import tkinter as tk

a = tk.Tk()   # first window
b = tk.Tk()   # second window — this is not how you should do it
```

**A program normally has exactly one `Tk()` instance.** If you want a second window, use `tk.Toplevel()` (covered in Lesson 25). Creating two `Tk()` instances causes the event loops to tangle and the program to freeze.

**If you genuinely need two windows, write the second one as `tk.Toplevel(root)`.**

## Command Line vs. Window: A Comparison Table

| Item | Command-line program | Window program |
|---|---|---|
| Input | Typing via `input()` | Entry boxes, buttons, menus |
| Output | Printing via `print()` | Labels, text boxes, pop-ups |
| Flow | Linear, exits when done | Event-driven, always on standby |
| Entry point | `if __name__ == "__main__"` | Create a window + `mainloop()` |
| Debugging | Reading terminal output | Watching the interface react, plus `print()` |

## Summary

- The three elements of a GUI: **window (holds things), widget (user interaction), event (user action)**
- tkinter is a **built-in** standard library: `import` and use it immediately
- A window program is **event-driven**: write a pile of "when…" rules and wait for the user to trigger them
- The program skeleton has only four steps: `Tk()` creation → set title/size → add widgets → start `mainloop()`
- **`mainloop()` is the final stop**: it must come last, and only cleanup code belongs after it
- Create only one `Tk()` per program; use `Toplevel()` for a second window
