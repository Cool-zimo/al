# Laying Out the Interface with `Frame` and `grid`

> Lesson 26 gave you a sketch of the text-statistics tool. This lesson turns that sketch into real widgets, organised into `Frame` panels and placed with `grid`. The rule is simple: divide first, place second, and never mix `pack` and `grid` inside the same container.

## Frames Are Invisible Boxes for Grouping Widgets

**A `Frame` is a plain rectangular container you put widgets into so they move and resize as a group.** It draws nothing by default, which is exactly what you want when all you need is structure.

```
import tkinter as tk

root = tk.Tk()
root.title("Text Stats")

top_frame = tk.Frame(root)
top_frame.pack(fill="x")

body_frame = tk.Frame(root)
body_frame.pack(fill="both", expand=True)

tk.Button(top_frame, text="Open file...").pack(side="left")
tk.Label(top_frame, text="No file yet").pack(side="left", padx=10)

root.mainloop()
```

**Two frames, one for the button row and one for the main display, sit inside `root`.** Anything you later add to `top_frame` stays in the top strip; anything in `body_frame` owns the rest of the window. That separation is what stops a growing program from turning into spaghetti.

## Crash Scene 1: Mixing `pack` and `grid` in the Same Container

```
top_frame = tk.Frame(root)
tk.Button(top_frame, text="Open").pack(side="left")
tk.Label(top_frame, text="Path").grid(row=0, column=1)   # WRONG: _tkinter.TclError
```

**Tkinter cannot decide between two layout managers for one container, so it raises `_tkinter.TclError: cannot use geometry manager grid inside . which already has slaves managed by pack`.** Pick one manager per container and stick with it. In this book the choice is easy: use `pack` for the big vertical regions, use `grid` inside each region for column-and-row layouts.

## Using `grid` for the Stats Panel

**`grid` puts widgets into rows and columns, like a spreadsheet. `sticky` decides how a widget expands inside its cell.**

```
body = tk.Frame(root)
body.pack(fill="both", expand=True)

tk.Label(body, text="Characters:").grid(row=0, column=0, sticky="w", padx=5, pady=2)
chars_label = tk.Label(body, text="0")
chars_label.grid(row=0, column=1, sticky="w", padx=5)

tk.Label(body, text="Words:").grid(row=1, column=0, sticky="w", padx=5, pady=2)
words_label = tk.Label(body, text="0")
words_label.grid(row=1, column=1, sticky="w", padx=5)
```

**`sticky="w"` (west) glues the widget to the left edge of its cell instead of letting it float centred.** Labels lined up at `"w"` read cleanly in a column. `padx` and `pady` give you breathing room — without them every widget touches its neighbours.

## Crash Scene 2: `grid` Sizes Cells by What's Inside

```
chars_label = tk.Label(body, text="0")
chars_label.grid(row=0, column=1)
# later:
chars_label.configure(text="999999")
# the layout jumps as the number grows
```

**Cells resize to fit their contents, so updating a label can shift the whole layout.** Either give the column a fixed width with `body.columnconfigure(1, minsize=120)` or pad the initial label text with spaces. Picking column widths up front keeps the numbers from dancing around as they change.

## `rowconfigure` and `columnconfigure` for Resizing

**`weight` tells `grid` which rows or columns should grow when the window is resized.**

```
body.columnconfigure(0, weight=0)   # labels: fixed width
body.columnconfigure(1, weight=1)   # values: take extra space
body.rowconfigure(2, weight=1)      # results row expands
```

**A column with `weight=1` soaks up spare space; one with `weight=0` stays put.** If you've ever stretched a window and nothing inside moved, it's because no row or column had a non-zero weight. Give the results area weight and it will grow with the window.

## Building the Full Sketch

**Here's the complete layout from Lesson 26, now as working code.**

```
import tkinter as tk

root = tk.Tk()
root.title("Text Stats")
root.geometry("420x320")

# top strip
top = tk.Frame(root)
top.pack(fill="x")
tk.Button(top, text="Open file...").pack(side="left", padx=5, pady=5)
path_label = tk.Label(top, text="(no file)", fg="gray")
path_label.pack(side="left", padx=5)

# stats grid
stats = tk.Frame(root)
stats.pack(fill="x", padx=5, pady=5)

labels = ["Characters", "No spaces", "Words", "Lines"]
value_labels = {}
for i, name in enumerate(labels):
    tk.Label(stats, text=name + ":").grid(row=i, column=0, sticky="w", padx=4, pady=2)
    vl = tk.Label(stats, text="0")
    vl.grid(row=i, column=1, sticky="w", padx=4)
    value_labels[name] = vl

# results area
results = tk.Listbox(root)
results.pack(fill="both", expand=True, padx=5, pady=5)

root.mainloop()
```

**Three frames, three jobs. The `value_labels` dict is the trick that lets you update "Characters" by name later — keep references to the widgets you'll change.** A loop builds the four stat rows in eight lines instead of sixteen, and adding a fifth stat is one list entry.

## Crash Scene 3: Throwing Away the Reference

```
tk.Label(stats, text="0").grid(row=0, column=1)
# WRONG: you can't update this label later, the variable is gone
```

**`tk.Label(...).grid(...)` returns `None`, because `grid` is the last thing called.** Store the widget in a variable *first*, then grid it on a separate line. This is the single most common `grid` mistake and it only shows up later, when you try to update something you can no longer name.

## Sticky Values as Compass Directions

**`sticky` takes compass letters; combine them to fill a cell.**

| `sticky` | Effect |
|---|---|
| `"w"` | left-aligned |
| `"e"` | right-aligned |
| `"we"` | fills the cell horizontally |
| `"ns"` | fills vertically |
| `"nsew"` | fills the whole cell |

**`sticky="nsew"` plus a `weight` of 1 is how a `Text` or `Listbox` grows with the window.** Without `nsew` the widget stays its default size and leaves empty space around it, even though you gave the row and column permission to grow.

## Putting It Together: The Skeleton App

**The skeleton has no logic yet — and that's deliberate. It runs, it resizes, and it gives you a place to hang code in Lesson 29.**

```
import tkinter as tk

class TextStatsApp:
    def __init__(self, root):
        root.title("Text Stats")
        root.geometry("420x320")

        self._build_top(root)
        self._build_stats(root)
        self._build_results(root)

    def _build_top(self, root):
        top = tk.Frame(root)
        top.pack(fill="x")
        tk.Button(top, text="Open file...",
                  command=self.open_file).pack(side="left", padx=5, pady=5)
        self.path_label = tk.Label(top, text="(no file)", fg="gray")
        self.path_label.pack(side="left", padx=5)

    def _build_stats(self, root):
        stats = tk.Frame(root)
        stats.pack(fill="x", padx=5, pady=5)
        self.values = {}
        for i, name in enumerate(["Characters", "No spaces", "Words", "Lines"]):
            tk.Label(stats, text=name + ":").grid(row=i, column=0, sticky="w", padx=4)
            vl = tk.Label(stats, text="0")
            vl.grid(row=i, column=1, sticky="w", padx=4)
            self.values[name] = vl

    def _build_results(self, root):
        self.results = tk.Listbox(root)
        self.results.pack(fill="both", expand=True, padx=5, pady=5)

    def open_file(self):
        # filled in lesson 29
        pass

root = tk.Tk()
TextStatsApp(root)
root.mainloop()
```

**Three private methods, one per region. `self.values` and `self.results` are the handles the callbacks will grab in Lesson 29.** The `open_file` method exists now as an empty stub so the button has somewhere to point; that's not cheating, it's how you grow a program one layer at a time.

## Summary

- Use `Frame` to group widgets into regions; it draws nothing by default
- Pick one geometry manager per container — `pack` for regions, `grid` for rows/columns
- `sticky="w"` left-aligns; `"nsew"` lets a widget fill its cell
- Store widget references in variables before calling `grid`, or you can't update them later
- `rowconfigure`/`columnconfigure` with `weight` controls what grows on resize
- Build the layout first with stub callbacks, then add logic in later lessons
