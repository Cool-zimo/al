# Window Properties

> A bare gray window is ugly. This lesson is about dressing it up: title, size, whether it can be resized, minimum dimensions, icons, and the most useful trick of all — centering the window on the screen.

## Title: `title()`

**`title()` controls the title bar text.** If you do not set it, a default name appears (often "tk" on Windows).

```
import tkinter as tk

root = tk.Tk()
root.title("Accounting Book 1.0")
root.mainloop()
```

**The title bar is the first thing the user sees — make it clear what your program does.** Do not leave the default "tk."

## Size and Position: `geometry()`

**`geometry()` sets the width, height, and position in a single string:**

```
root.geometry("400x300")        # width 400, height 300; the system picks the position
root.geometry("400x300+100+50") # width 400, height 300; top-left at screen (100, 50)
```

**The format is `widthxheight+X+Y`. Note the letter `x`, not the multiplication sign `*`.** This is the most common typo:

```
root.geometry("400*300")   # Error: bad geometry specifier
root.geometry("400×300")   # Error: full-width multiplication sign
root.geometry("400x300")   # correct
```

**Reading the current value:**

```
print(root.geometry())   # e.g. '400x300+100+50'
```

**Splitting geometry apart is straightforward:**

```
geo = root.geometry()        # '400x300+100+50'
w, h = geo.split('+')[0].split('x')   # w='400', h='300'
print(w, h)                 # 400 300
```

**Here is a small but useful detail:** in the string `'400x300+100+50'`, the part before `+` is the size and the two numbers after `+` are the position. `split('+')` therefore yields `['400x300', '100', '50']`.

## Resizable: `resizable()`

**`resizable(w, h)` controls whether the user can drag to resize the window.** Two booleans, for width and height respectively.

```
root.resizable(True, True)   # default: both width and height can change
root.resizable(False, False) # both locked; the window is fixed
root.resizable(True, False)  # width can change, height cannot
```

**When should you lock the size?** For small utility programs (such as a unit converter) whose layout is fixed — enlarging them only adds empty space, which looks worse. Lock it.

```
import tkinter as tk

root = tk.Tk()
root.title("Fixed Window")
root.geometry("300x200")
root.resizable(False, False)   # the user cannot drag the border
root.mainloop()
```

**When you lock the size, the system usually also grays out the "maximize" button.**

## Minimum Size: `minsize()` and Maximum Size: `maxsize()`

**`minsize(w, h)` and `maxsize(w, h)` set a resizing range for the window.**

```
root.minsize(300, 200)   # cannot go any smaller
root.maxsize(800, 600)   # cannot go any larger
```

**The difference between these methods and `resizable`:** `resizable(False, False)` locks the window down completely (it cannot be dragged at all), whereas `minsize`/`maxsize` define a range within which the user remains free to drag.

**A practical habit:** set `minsize` to stop the user from shrinking the window until the widgets are crushed together.

```
root.minsize(400, 300)   # smaller than this looks bad, so forbid it
```

**Beware:** `maxsize` on its own can backfire — if the user's screen is physically smaller than `maxsize`, the window may not fit on it. In practice, use only `minsize`.

## Icons: `iconphoto()` and `iconbitmap()`

**The icon is the small image at the top-left of the title bar.** There are two approaches:

```
# Approach 1: iconphoto, cross-platform, uses PNG
root.iconphoto(False, tk.PhotoImage(file="icon.png"))

# Approach 2: iconbitmap, Windows-specific, uses .ico
root.iconbitmap("icon.ico")
```

| Method | Platform | Image format |
|---|---|---|
| `iconphoto()` | Cross-platform | PNG / GIF / PPM |
| `iconbitmap()` | Mainly Windows | ICO |

**The first argument to `iconphoto` is `True` or `False`:** `True` means "also apply this icon to every Toplevel window created in the future," while `False` means "only the current root window." In most cases `False` is fine.

**Crash scene:** a wrong image path raises an error, or — even more annoying — fails silently and shows no icon at all.

```
root.iconphoto(False, tk.PhotoImage(file="no-such-file.png"))
# Error: _tkinter.TclError: couldn't open "no-such-file.png"
```

**Use absolute paths or verify the working directory:** the icon file must sit in the same folder as the script, or use an absolute path such as `C:/.../icon.png`. Wrapping the path with `os.path` avoids mistakes:

```
import os
icon_path = os.path.join(os.path.dirname(__file__), "icon.png")
if os.path.exists(icon_path):
    root.iconphoto(False, tk.PhotoImage(file=icon_path))
```

**macOS and most Linux desktop environments no longer show the traditional icon, but adding it does no harm and it still works on Windows.**

## Centering the Window: An Extremely Useful Trick

**When a program starts, the window often appears in the top-left corner of the screen, which looks bad.** Calculate the centered coordinates yourself:

```
import tkinter as tk

root = tk.Tk()
root.title("Centered Window")
root.geometry("400x300")

# Screen dimensions
screen_w = root.winfo_screenwidth()
screen_h = root.winfo_screenheight()

# Window dimensions
win_w, win_h = 400, 300

# Centered coordinates
x = (screen_w - win_w) // 2
y = (screen_h - win_h) // 2

root.geometry(f"400x300+{x}+{y}")
root.mainloop()
```

**The whole formula boils down to one line: `x = (screen_width - window_width) // 2`.** Subtract first, then integer-divide, and you get the coordinate the top-left corner should sit at.

**Crash scene: centering first, then changing the size, wastes the calculation.** If you later call `root.geometry("600x400")` and alter the size, the centered coordinates you worked out become invalid. The correct approach is to keep every `geometry`-related setting together in one block.

## A Quick Reference of Common Properties

| Property / method | Purpose |
|---|---|
| `root.title("...")` | Title bar text |
| `root.geometry("WxH+X+Y")` | Size and position |
| `root.resizable(w, h)` | Whether the window can be dragged to resize |
| `root.minsize(w, h)` | Minimum size |
| `root.maxsize(w, h)` | Maximum size |
| `root.iconphoto(False, img)` | Set the icon |
| `root.configure(bg="color")` | Background color |
| `root.attributes("-topmost", True)` | Keep the window on top |
| `root.attributes("-alpha", 0.8)` | Transparency (0~1) |
| `root.state("zoomed")` | Start maximized (Windows) |
| `root.overrideredirect(True)` | Remove the title bar (borderless window) |
| `root.destroy()` | Destroy the window and exit the program |
| `root.quit()` | Exit the main loop (the window remains) |

**The difference between `destroy()` and `quit()` is worth remembering:** `destroy()` tears the window down and ends the program; `quit()` merely steps out of the main loop while the window stays in memory. To close the program, use `root.destroy()` (or let the default system behavior handle it).

## Background Color and Full Screen

**`configure` is the most general "change a property" method:**

```
root.configure(bg="#f0f0f0")        # light gray background
root.configure(cursor="watch")      # change the mouse cursor style ("arrow"/"watch"/"cross")
```

**`attributes` can change many "window-level" properties; it has a lot of parameters. Here are two useful ones:**

```
root.attributes("-topmost", True)   # the window always stays in front
root.attributes("-alpha", 0.8)      # semi-transparent
```

**A transparent window is great for floating widget tools.** Remember that `alpha` ranges from 0.0 (fully transparent) to 1.0 (fully opaque).

## Crash Scene 1: `geometry` Uses the Multiplication Sign

```
root.geometry("400*300")   # TclError: bad geometry specifier
```

**Only the letter `x` is allowed.** The geometry string is an old Tcl/Tk format that has been preserved ever since.

## Crash Scene 2: Reversing the `resizable` Arguments

```
root.resizable(False, True)   # you intended "width locked, height free"
# In reality: width=False, height=True
```

**The order is `(width, height)`. Do not overthink it.** To lock both, write `resizable(False, False)`.

## Crash Scene 3: Setting the Icon but Forgetting the `PhotoImage` Reference

```
root.iconphoto(False, tk.PhotoImage(file="icon.png"))
# in some situations the icon does not appear
```

**Although `iconphoto` keeps its own reference internally, in a complex program the image object can be garbage-collected and the icon disappears.** The safe move is to store the image in a variable: `icon = tk.PhotoImage(file="icon.png"); root.iconphoto(False, icon)`.

## Crash Scene 4: Mixing Up Units

**In tkinter, every dimension is in pixels — no centimeters, no inches.** `geometry("400x300")` means 400 pixels wide by 300 pixels tall. On a high-DPI screen the same number of pixels will look small.

## Summary

- `title()` sets the title; `geometry("WxH+X+Y")` sets the size and position, using the letter `x`
- `resizable()` locks the size; `minsize()` sets a lower bound — in practice, use only `minsize`
- Icons use `iconphoto()` (cross-platform PNG) or `iconbitmap()` (Windows ICO)
- **Centering formula:** `x = (screen_width - window_width) // 2`
- `configure()` changes the background color and similar properties; `attributes()` changes topmost, transparency, and other window properties
- `destroy()` destroys the window; `quit()` only exits the loop
