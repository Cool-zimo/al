# place: Absolute and Relative Positioning

> place is tkinter's most "primitive" layout method — it assigns coordinates directly. This lesson covers how to use it, why it is usually not recommended, and the rare situations where nothing else will do.

## Basic Usage of place

**`place` assigns an explicit x, y coordinate (in pixels) and width/height to a widget:**

```
import tkinter as tk

root = tk.Tk()
root.geometry("400x300")

tk.Label(root, text="Top-left", bg="red").place(x=0, y=0, width=80, height=30)
tk.Label(root, text="Middle", bg="green").place(x=150, y=120, width=100, height=40)

root.mainloop()
```

**The two Labels are pinned precisely at the specified coordinates.**

**place's core arguments:**

| Argument | Purpose |
|---|---|
| `x` / `y` | Absolute coordinates (pixels), the **top-left** corner of the widget |
| `relx` / `rely` | Relative coordinates (0.0~1.0), relative to the parent's size |
| `width` / `height` | Absolute size (pixels) |
| `relwidth` / `relheight` | Relative size (0.0~1.0) |
| `anchor` | Anchor point: `"nw"` means the widget's top-left aligns with (x, y) |

## Absolute Positioning vs. Relative Positioning

**Absolute positioning uses `x`/`y`/`width`/`height`, all in pixels:**

```
label.place(x=10, y=20, width=100, height=30)
```

**Relative positioning uses `relx`/`rely`/`relwidth`/`relheight`, all values from 0 to 1:**

```
label.place(relx=0.5, rely=0.5, relwidth=0.5, relheight=0.5, anchor="center")
```

**This Label sits in the exact center of the parent, at half the parent's width and half its height.**

**The advantage of relative positioning: the widget's position scales proportionally as the window is resized.** It is the only way place can be "responsive."

## anchor: The Anchor Point

**`anchor` decides which point of the widget aligns with (x, y):**

| Value | Meaning |
|---|---|
| `"nw"` | Widget's top-left (default) |
| `"n"` | Midpoint of the widget's top edge |
| `"ne"` | Widget's top-right |
| `"w"` | Midpoint of the widget's left edge |
| `"center"` | Center of the widget |
| `"e"` | Midpoint of the widget's right edge |
| `"sw"` | Widget's bottom-left |
| `"s"` | Midpoint of the widget's bottom edge |
| `"se"` | Widget's bottom-right |

**Use anchor to "pin" a widget in the bottom-right corner:**

```
tk.Label(root, text="Bottom-right").place(relx=1.0, rely=1.0, anchor="se")
```

**`relx=1.0, rely=1.0` is the parent's bottom-right corner; `anchor="se"` means the widget's bottom-right corner aligns with that point — so the widget sits flush in the corner.**

## Keeping a Widget Centered

**Combine relx/rely with anchor:**

```
tk.Label(root, text="Center").place(relx=0.5, rely=0.5, anchor="center")
```

**No matter how large the window gets, it stays in the middle.** Enlarging the window moves it so it remains centered.

## A Practical Use Case: Watermarks / Overlays

**place is great for "stacking" — laying text over an image:**

```
import tkinter as tk

root = tk.Tk()

# Background image (simulated with a solid block)
canvas = tk.Label(root, text="", bg="gray", width=400, height=300)
canvas.place(x=0, y=0, relwidth=1, relheight=1)

# A line of watermark text floating on top
tk.Label(root, text="© 2026 My Software", bg="white").place(relx=1.0, rely=1.0, anchor="se", x=-10, y=-10)

root.mainloop()
```

**`x=-10, y=-10` is "fine-tuning":** after using relative positioning for the general direction, apply a small pixel offset.

**This "widget on top of widget" effect is hard to achieve with pack/grid; place handles it naturally.**

## Another Practical Use Case: A Custom Dashboard

**Want a circular button, diagonally arranged text, or an irregular layout? place is the right tool:**

```
import tkinter as tk

root = tk.Tk()
root.geometry("300x300")

tk.Button(root, text="A", width=6).place(x=20, y=20)
tk.Button(root, text="B", width=6).place(x=120, y=80)
tk.Button(root, text="C", width=6).place(x=60, y=160)
tk.Label(root, text="Irregular layout", bg="yellow").place(x=180, y=180, width=100, height=40)

root.mainloop()
```

**Every coordinate is yours to decide; place things however you like.**

## Why place Is Not Recommended

**place has three fatal weaknesses:**

1. **It does not scale with the window (unless you use rel*):** with absolute coordinates, enlarging the window throws the widgets out of alignment and creates gaps.
2. **Changing one means changing a whole chain:** add a widget and you must recalculate the coordinates of everything that follows.
3. **Alignment requires hand calculation:** pack/grid align automatically; place makes you compute pixels, which is tedious and error-prone.

**A comparison:**

| Requirement | pack | grid | place |
|---|---|---|---|
| Scaling with the window | Easy | Easy | Must use rel* |
| Adding a widget | Change one spot | Change one spot | May require recalculating every coordinate |
| Alignment | Automatic | Automatic | Hand-calculated |
| Pixel-level control | None | None | Yes |

**Conclusion: use grid when you can, use pack when you can, and use place only when you need "stacking or precise positioning."**

## Crash Scene 1: place Widgets Do Not Scale with the Window

```
label.place(x=10, y=10, width=100, height=30)
```

**Drag the window from 400x300 to 800x600 and the label stays pinned at (10,10).** To make it follow the window, you must use `relx`/`rely`/`relwidth`/`relheight`.

## Crash Scene 2: `relx=1.0` but No anchor, the Widget Vanishes Off-Screen

```
tk.Label(root, text="Right side").place(relx=1.0)
```

**`relx=1.0` is the parent's right edge, and the default anchor is `"nw"` (top-left),** so the widget's top-left sits on the right edge — the entire widget is now outside the window and invisible.

**Fix:** add `anchor="ne"` or `"e"` so the widget's right edge aligns with the parent's right edge.

## Crash Scene 3: Mixing `width`/`height` and `relwidth`/`relheight`

**`width` is in pixels, `relwidth` is a ratio; when both are given, `width` wins (and giving both creates a conflict anyway):**

```
label.place(relwidth=0.5, width=200)   # effectively width=200 is used
```

**Do not write both; pick one approach.**

## Crash Scene 4: Using place for a Form — Exhausting and Wrong

```
tk.Label(root, text="Name:").place(x=10, y=10)
tk.Entry(root).place(x=80, y=10, width=150)
tk.Label(root, text="Age:").place(x=10, y=40)
tk.Entry(root).place(x=80, y=40, width=150)
```

**It looks acceptable, but the moment you resize the window it falls apart — and adding a field means editing four coordinates.** This form takes three lines with grid.

## place's Advanced Argument: `bordermode`

**`bordermode` controls whether coordinates are relative to the parent's "outside" or "inside":**

```
label.place(x=0, y=0, bordermode="outside")   # includes the parent's border
label.place(x=0, y=0, bordermode="inside")    # excludes the border (default)
```

**In the vast majority of cases you do not need to worry about it; the default is fine.**

## When place Is Truly Unavoidable

**Three scenarios:**

1. **Overlays / watermarks / floating layers** (a widget must sit on top of another widget)
2. **Canvas-style applications** (drawing, custom controls, game interfaces)
3. **Precise pixel positions are required** (dashboards, custom meters)

**For everything else, prefer grid.**

## Summary

- place uses `x`/`y`/`width`/`height` for absolute positioning and `relx`/`rely`/`relwidth`/`relheight` for relative positioning
- `anchor` decides which point of the widget aligns with the coordinates; the default is `"nw"`
- To scale with the window you must use the `rel*` family of arguments
- place is not recommended for ordinary layouts: it does not follow resizes, changing one forces you to change many, and alignment requires hand calculation
- place is best for: overlays, watermarks, canvas-style layouts, and pixel-level customization
