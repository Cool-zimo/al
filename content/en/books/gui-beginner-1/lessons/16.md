# The `command` Callback: What Happens When You Click

> A button that does nothing is just a label with an attitude. This lesson is about the function behind the button: why `command=greet()` is a disaster, what `command=` actually accepts, and how a callback reaches back into the widgets on screen.

## What a Callback Is

**A callback is a function you hand over to be called later, when something happens.** A button's `command` is the simplest possible example.

```
import tkinter as tk

root = tk.Tk()

def say_hi():
    print("hello!")

tk.Button(root, text="Click me", command=say_hi).pack()

root.mainloop()
```

**The sequence: you write the function, the button holds onto it, the user clicks, tkinter calls it.** You're not calling `say_hi` yourself anywhere — that's the whole point of a callback.

## The Rule: No Parentheses

**`command=say_hi` is correct; `command=say_hi()` is the mistake everyone makes once.**

```
# correct
tk.Button(root, text="Click me", command=say_hi).pack()

# WRONG
tk.Button(root, text="Click me", command=say_hi()).pack()
```

**With parentheses, `say_hi()` runs immediately** — right there, while the window is still being built. Its return value (`None`) is what gets handed to `command`. So the function fires once at startup, and clicking the button does absolutely nothing.

## Crash Scene 1: Parentheses Cause Immediate Execution

```
def greet():
    print("hello")

tk.Button(root, text="Click me", command=greet()).pack()
# "hello" prints the instant the program starts
# clicking the button does nothing
```

**The fix is just to delete the parentheses.** It's a small character with a dramatic effect, which is why it shows up in nearly every tkinter tutorial.

## Crash Scene 2: Passing a String Instead of a Function

```
tk.Button(root, text="Click me", command="greet").pack()
# clicking: error about an unexpected keyword 'greet'
```

**`command` wants a function object, not the function's name as text.** A string has no code to run, and tkinter has no way to know what `"greet"` was supposed to mean.

## What `command` Can Accept

| Form | Meaning |
|---|---|
| `command=function_name` | The usual case |
| `command=lambda: ...` | When you need arguments (Lesson 17) |
| `command=callable_object` | Any object with a `__call__` method |

**Every form has one thing in common: `command` receives a callable that takes zero arguments.** That constraint is what drives the rest of this chapter.

## Callbacks Reaching Into the Interface

**A callback usually needs to read or change widgets, so those widgets have to be in scope.**

```
import tkinter as tk

root = tk.Tk()

entry = tk.Entry(root)
entry.pack()

label = tk.Label(root, text="")

def show():
    name = entry.get()
    label.configure(text=f"hello, {name}!")

label.pack()
tk.Button(root, text="Greet", command=show).pack()

root.mainloop()
```

**`entry` and `label` are module-level variables, so `show` can see them.** Two details worth fixing in your head: reading a global needs no declaration, but *rebinding* one (writing `entry = ...`) would need `global entry`. Here you're just calling methods on it, so you're fine.

## Passing Arguments: A First Look at `lambda`

**When a callback needs data, wrap it in a `lambda`:**

```
def greet(name):
    print(f"hello, {name}!")

tk.Button(root, text="Greet Zhang", command=lambda: greet("Zhang")).pack()
tk.Button(root, text="Greet Li",   command=lambda: greet("Li")).pack()
```

**`lambda: greet("Zhang")` builds a brand-new function with zero parameters.** Click it, and that new function calls `greet("Zhang")`. Lesson 17 goes deep on this; for now, just notice the shape.

## Organising With a Class

**Once the interface grows, a class keeps the widgets and the callbacks in one place.**

```
import tkinter as tk

class App:
    def __init__(self, root):
        self.root = root
        root.title("Counter")

        self.count = 0
        self.label = tk.Label(root, text="0")
        self.label.pack()

        tk.Button(root, text="Add one", command=self.add).pack()

    def add(self):
        self.count += 1
        self.label.configure(text=str(self.count))

root = tk.Tk()
App(root)
root.mainloop()
```

**`command=self.add` passes the bound method; tkinter calls it with no arguments and Python supplies `self` automatically.** Every widget and counter lives on `self`, so there are no module-level globals to keep track of.

## Crash Scene 3: A Method With the Wrong Number of Arguments

```
class App:
    def __init__(self, root):
        tk.Button(root, text="click", command=self.click).pack()

    def click(self, name):   # one argument too many
        print(name)

# clicking: click() missing 1 required positional argument: 'name'
```

**`command=` calls the callback with zero arguments.** If your method needs data, reach for `lambda` or `functools.partial`:

```
from functools import partial
tk.Button(root, text="click", command=partial(self.click, "Zhang")).pack()
```

## Three Buttons, One Callback

**One function plus a parameter handles a whole row of buttons:**

```
def choose(option):
    label.configure(text=f"you picked: {option}")

tk.Button(root, text="A", command=lambda: choose("A")).pack()
tk.Button(root, text="B", command=lambda: choose("B")).pack()
tk.Button(root, text="C", command=lambda: choose("C")).pack()
```

**The value each button carries is frozen into its own `lambda`.** It's the same trick you'll use dozens of times, and Lesson 17 explains exactly why it works.

## A Callback That Updates Several Widgets

**The real pattern: read several inputs, validate, then update the result.**

```
def submit():
    name    = name_entry.get().strip()
    age_str = age_entry.get().strip()
    if not name:
        result.configure(text="name cannot be empty", fg="red")
        return
    try:
        age = int(age_str)
    except ValueError:
        result.configure(text="age must be a number", fg="red")
        return
    result.configure(text=f"submitted: {name}, {age}", fg="black")
```

**Read, check, react. That three-step rhythm is the skeleton of almost every form you'll ever write.**

## Where `command` Falls Short

**`command` handles clicks and little else, and only on a few widgets: Button, Checkbutton, Radiobutton, Scale, Spinbox.**

**For mouse movement, key presses, double-clicks, or window resizing you need `bind`** — Lesson 18. Think of `command` as the friendly front door and `bind` as the whole rest of the house.

## Summary

- A callback is "a function called when an event happens"; `command` is the simplest callback
- **`command=function_name` with no parentheses; parentheses mean run now and click does nothing**
- `command` only accepts callables with zero arguments; use `lambda` or `functools.partial` for arguments
- Reading global widgets needs no `global`; rebinding them does
- Complex interfaces belong in a **class**, with widgets and methods on `self`
- `command` covers clicks; everything else needs `bind`
