# Separating Logic From the Interface

> The counting code belongs in plain functions; the widgets belong on screen. Lesson 28 is about keeping that boundary clean, so you can change the interface without breaking the maths, and test the maths without opening a window.

## The Boundary: Data In, Data Out

**A logic function takes plain Python values and returns plain Python values. It never touches `tk`, never reads an Entry, never updates a Label.**

```
import re
from collections import Counter

def count_stats(text):
    chars = len(text)
    chars_no_spaces = len(text.replace(" ", ""))
    words = text.split()
    word_count = len(words)
    lines = text.count("\n") + 1 if text else 0
    return {
        "chars": chars,
        "no_spaces": chars_no_spaces,
        "words": word_count,
        "lines": lines,
    }

def top_words(text, n=10):
    words = re.findall(r"[A-Za-z']+", text.lower())
    return Counter(words).most_common(n)
```

**`count_stats` returns a `dict`, `top_words` returns a `list` of tuples. Both are printable, comparable, and completely unaware that a GUI exists.** That's the boundary: anything past it can be tested with `print()` in a shell.

## The Adapter: The Only Place Widgets and Logic Meet

**A method on your `App` class is allowed to cross the boundary, because its job is translation: read from widgets, call logic, push results back.**

```
def analyse(self, text):
    stats = count_stats(text)
    self.values["Characters"].configure(text=str(stats["chars"]))
    self.values["Words"].configure(text=str(stats["words"]))
    self.values["Lines"].configure(text=str(stats["lines"]))
    self.values["No spaces"].configure(text=str(stats["no_spaces"]))

    self.results.delete(0, tk.END)
    for word, count in top_words(text):
        self.results.insert(tk.END, f"{word}: {count}")
```

**`analyse` is the bridge. Everything above it is GUI, everything below it is data.** Notice that it calls `count_stats` and immediately feeds the result into `configure` calls — that handoff is the only place the two worlds touch.

## Crash Scene 1: Putting the Maths Inside the Button Callback

```
def open_file(self):
    path = filedialog.askopenfilename()
    with open(path, encoding="utf-8") as f:
        text = f.read()
    chars = len(text)                                  # WRONG: logic lives here now
    self.values["Characters"].configure(text=str(chars))
    # ... repeat for every stat ...
```

**Inline logic seems faster to write, but now the counting is welded to the button and can't be reused or tested.** The moment you want the same numbers from a different source — a pasted string, a URL, a unit test — you have to copy the code. Keep it in a function and call that function.

## Crash Scene 2: A Logic Function That Imports `tkinter`

```
import tkinter as tk          # WRONG in a logic module

def count_stats(text):
    tk.Label(...)             # why is a maths function making widgets?
    return len(text)
```

**If your counting module imports `tkinter`, the boundary has collapsed.** Logic functions should run in a bare Python shell. The only `tk` import belongs in the file that builds the interface.

## Two Files, Two Jobs

**A clean project splits into `stats.py` (logic) and `app.py` (interface).**

```
# stats.py
import re
from collections import Counter

def count_stats(text):
    ...

def top_words(text, n=10):
    ...
```

```
# app.py
import tkinter as tk
from stats import count_stats, top_words

class TextStatsApp:
    ...
```

**`app.py` imports the functions; `stats.py` knows nothing about the app.** Delete the window, keep the maths. Replace the CLI with a GUI, keep the same import. That independence is the point — you can hand `stats.py` to someone who doesn't use tkinter at all.

## Crash Scene 3: A Function That Reads the File Itself

```
def count_stats(path):        # WRONG-ish: mixes file IO with logic
    with open(path, encoding="utf-8") as f:
        text = f.read()
    return len(text)
```

**A function that opens a file can't be tested on a string literal, and it drags in file errors where they don't belong.** Take `text` (a string) as the argument; let the caller — a method that already crossed the boundary — do the reading and the error handling.

## Testing the Logic Without a Window

**Because the functions take strings, you can prove them right before the interface exists.**

```
if __name__ == "__main__":
    sample = "Hello world\nHello again."
    stats = count_stats(sample)
    print(stats)
    print(top_words(sample, 5))
```

**Run that with `python stats.py` and you'll see `{'chars': 24, 'no_spaces': 21, 'words': 4, 'lines': 2}`.** The `__main__` guard means the demo only runs when you execute the file directly — importing it from `app.py` doesn't trigger the print. This is the standard Python pattern for keeping a quick test alongside the code.

## Crash Scene 4: Mutable Defaults

```
def top_words(text, n=10, seen={}):   # WRONG: the dict is shared forever
    ...
```

**A default argument is evaluated once when the function is defined, so `seen` is the same dict on every call and leaks data between runs.** Never use a mutable default; use `None` and create the object inside the function. This bug is silent until your second call mysteriously remembers the first.

## What Crosses the Boundary (And What Doesn't)

**A short checklist prevents almost every mess.**

| Stays in logic | Stays in the interface |
|---|---|
| counting, parsing, sorting | opening files, showing dialogs |
| `str`, `dict`, `list`, numbers | `Label`, `Entry`, `Listbox` |
| pure functions | `App` class and its methods |
| no `tk` import | imports `tk` and the logic module |

**If you're tempted to put a `Label` inside `stats.py`, stop. That's the line.** Likewise, don't put a regex inside a button callback — move it down into the logic file.

## Putting It Together: The Whole Class So Far

**Here's the full class with logic cleanly separated. It doesn't read files yet — that's Lesson 29 — but it already analyses text correctly.**

```
import tkinter as tk
import stats

class TextStatsApp:
    def __init__(self, root):
        root.title("Text Stats")
        root.geometry("420x320")

        self._build_top(root)
        self._build_stats(root)
        self._build_results(root)

    def _build_top(self, root):
        top = tk.Frame(root)
        top.pack(fill="x")
        tk.Button(top, text="Analyse text",
                  command=self._on_analyse).pack(side="left", padx=5, pady=5)
        self.path_label = tk.Label(top, text="(paste or load text)", fg="gray")
        self.path_label.pack(side="left", padx=5)

    def _build_stats(self, root):
        frame = tk.Frame(root)
        frame.pack(fill="x", padx=5, pady=5)
        self.values = {}
        for i, name in enumerate(["Characters", "No spaces", "Words", "Lines"]):
            tk.Label(frame, text=name + ":").grid(row=i, column=0, sticky="w", padx=4)
            vl = tk.Label(frame, text="0")
            vl.grid(row=i, column=1, sticky="w", padx=4)
            self.values[name] = vl

    def _build_results(self, root):
        self.results = tk.Listbox(root)
        self.results.pack(fill="both", expand=True, padx=5, pady=5)

    def _on_analyse(self):
        text = self.text_widget.get("1.0", tk.END)
        self._display(text)

    def _display(self, text):
        stats_dict = stats.count_stats(text)
        for key, label_name in [("chars", "Characters"),
                                ("no_spaces", "No spaces"),
                                ("words", "Words"),
                                ("lines", "Lines")]:
            self.values[label_name].configure(text=str(stats_dict[key]))

        self.results.delete(0, tk.END)
        for word, count in stats.top_words(text):
            self.results.insert(tk.END, f"{word}: {count}")

root = tk.Tk()
TextStatsApp(root)
root.mainloop()
```

**`_display` is the only method that touches both sides, and it does so in two obvious steps: call logic, then update widgets.** Read it top to bottom and you can see exactly where data becomes pixels.

## Summary

- Logic functions take data and return data; no `tk` import, no widgets
- One method per class is the bridge: read widgets, call logic, push results back
- Split the project into `stats.py` and `app.py` so each file has one job
- Never let a logic function open a file — take the text as a string
- Avoid mutable default arguments; they leak state across calls
- The `__main__` guard gives you a free test harness inside any module
