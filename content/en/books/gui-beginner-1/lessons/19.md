# Keyboard and Mouse: Focus, Shortcuts, and Drag

> This lesson fills in the parts of input handling that `bind` only hints at: who receives keyboard events, how to wire up shortcuts, and how to make something draggable. Along the way it covers the three-mouse-event recipe that nearly every drawing and game program in tkinter ends up using.

## Focus: Who Hears the Keyboard

**Keyboard events are delivered only to the widget that currently has focus — the one with the blinking cursor.**

```
import tkinter as tk

root = tk.Tk()

e1 = tk.Entry(root)
e1.pack()
e2 = tk.Entry(root)
e2.pack()

root.mainloop()
```

**At startup one of the entries holds focus (usually the first).** Click the other and focus moves there. Only the focused widget receives keystrokes — that's why typing into a form fills one field at a time.

## `focus_set` and `focus_get`

**`focus_set()` moves focus to a widget; `focus_get()` asks root which widget has it.**

```
e1.focus_set()   # put the cursor in e1 as soon as the window appears
```

```
w = root.focus_get()
print(w)   # the widget that currently has focus
```

**`focus_set()` is the single most useful trick in this lesson.** Use it on the main input field during `__init__` so the user can start typing immediately instead of having to click first.

## Keyboard Shortcuts

**Bind the modifier plus the key, then call the function from the callback.**

```
import tkinter as tk

root = tk.Tk()

def save(event=None):
    print("saving file")

def open_file(event=None):
    print("opening file")

root.bind("<Control-s>", lambda e: save())
root.bind("<Control-o>", lambda e: open_file())

tk.Label(root, text="Press Ctrl+S to save, Ctrl+O to open").pack()
root.mainloop()
```

**`<Control-s>` means Ctrl+S.**

**The `event=None` default deserves a closer look.** The same `save` works as a `bind` callback (tkinter passes an event) and as a plain function call from a menu — the parameter becomes optional. Write your file-handling functions this way and they slot into either mechanism.

## Chords and Combinations

```
root.bind("<Control-Shift-s>", lambda e: print("save as"))  # Ctrl+Shift+S
root.bind("<Alt-F4>",         lambda e: print("trying to quit"))  # Alt+F4
```

**The conventions users expect:**

| Shortcut | Usual meaning |
|---|---|
| Ctrl+N | New |
| Ctrl+O | Open |
| Ctrl+S | Save |
| Ctrl+Shift+S | Save As |
| Ctrl+Z | Undo |
| Ctrl+C / Ctrl+V | Copy / Paste |
| Delete | Delete |
| F5 | Refresh |
| Esc | Cancel / close |

## Intercepting a System Shortcut

**Return `"break"` to swallow an event and stop it reaching the system.**

```
def on_alt_f4(event):
    print("caught Alt+F4, doing nothing")
    return "break"

root.bind("<Alt-F4>", on_alt_f4)
```

**This is the building block of "are you sure you want to quit?"** — Lesson 21 adds messagebox and you'll have a complete confirm-exit dialog.

## The Full Mouse Event Table

| Event | When it fires |
|---|---|
| `<Button-1>` | Left button pressed |
| `<ButtonRelease-1>` | Left button released |
| `<Double-1>` | Left button double-click |
| `<Triple-1>` | Left button triple-click |
| `<Motion>` | Mouse moved (any button) |
| `<B1-Motion>` | Left button held while moving |
| `<B2-Motion>` / `<B3-Motion>` | Middle / right held while moving |
| `<Enter>` | Mouse entered the widget |
| `<Leave>` | Mouse left the widget |

## Drag: Press, Move, Release

**A drag is three events working together.**

```
import tkinter as tk

root = tk.Tk()
root.title("Drag the Box")

canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

rect = canvas.create_rectangle(50, 50, 100, 100, fill="blue")

def on_press(event):
    # record where the drag started
    canvas._drag_data = {"x": event.x, "y": event.y}

def on_drag(event):
    # how far have we moved? shift the rectangle by that amount
    dx = event.x - canvas._drag_data["x"]
    dy = event.y - canvas._drag_data["y"]
    canvas.move(rect, dx, dy)
    canvas._drag_data = {"x": event.x, "y": event.y}

def on_release(event):
    # drag finished, forget the start point
    canvas._drag_data = None

canvas.bind("<ButtonPress-1>", on_press)
canvas.bind("<B1-Motion>", on_drag)
canvas.bind("<ButtonRelease-1>", on_release)

root.mainloop()
```

**The three-part pattern:**

1. **Press** — remember the starting point
2. **Drag** — compute the delta, move by it, update the remembered point
3. **Release** — tidy up

**That's the universal shape of dragging in tkinter.** It's used for moving shapes, resizing windows, sliders, anything that follows the cursor.

## Crash Scene 1: Moving by Absolute Coordinates

**The classic mistake is treating `event.x` as a target rather than a delta.**

```
def on_drag(event):
    # WRONG: event.x is absolute; the rectangle flies off into the distance
    canvas.move(rect, event.x, event.y)
```

**`canvas.move(item, dx, dy)` moves by a relative amount.** You must subtract the previous position to get that delta. Pass absolute coordinates and the rectangle accelerates away from the cursor with every mouse move.

## Crash Scene 2: Binding the Canvas Event to `root`

```
canvas = tk.Canvas(root, ...)
root.bind("<Button-1>", on_press)   # WRONG: bound to root
```

**If you want canvas-only mouse handling, bind to the canvas.** Binding to `root` makes the drag start anywhere in the window, including outside the canvas. Sometimes that's what you want; usually it isn't.

## Hover Effects

**`<Enter>` and `<Leave>` make a button light up when the mouse is over it.**

```
def on_enter(event):
    btn.configure(bg="lightblue")

def on_leave(event):
    btn.configure(bg="SystemButtonFace")

btn = tk.Button(root, text="button")
btn.bind("<Enter>", on_enter)
btn.bind("<Leave>", on_leave)
```

**That's the familiar "highlight on hover" behaviour from the web, done with two events.**

**Note: ttk widgets generally ignore `bg=` — use `Style` to change their colours.**

## Event Callbacks Inside a Class

**A class keeps the label, the bindings, and the logic in one place.**

```
import tkinter as tk

class App:
    def __init__(self, root):
        self.label = tk.Label(root, text="move the mouse")
        self.label.pack(padx=30, pady=30)
        root.bind("<Motion>", self.on_motion)

    def on_motion(self, event):
        self.label.configure(text=f"({event.x}, {event.y})")

root = tk.Tk()
App(root)
root.mainloop()
```

**The method already has `self`; tkinter adds `event` as the second argument, which matches `self, event` perfectly.**

## One Callback, Several Events

```
def on_any(event):
    print(f"event: {event.type}, at ({event.x}, {event.y})")

root.bind("<Button-1>", on_any)
root.bind("<Button-3>", on_any)
root.bind("<Motion>", on_any)
```

**`event.type` identifies the event type numerically.** To tell events apart in a readable way, check `event.widget` or — better — write separate callbacks.

## `bind_all` and `bind_class`

**`bind_all` listens everywhere, regardless of which widget is focused.**

```
root.bind_all("<Control-q>", lambda e: root.destroy())
```

**`bind_class` attaches to every instance of a widget class.**

```
root.bind_class("Button", "<Enter>",
                lambda e: print("mouse entered a button"))
```

**Both are advanced and rarely needed.** Ordinary `bind` covers the day-to-day cases.

## Summary

- **Focus** decides who receives keyboard events; `focus_set()` sets it deliberately
- Shortcuts use `bind`: `<Control-s>`, `<Control-Shift-s>`, `<Alt-F4>`
- `return "break"` stops propagation and can intercept system shortcuts
- **Drag = press (record) + motion (delta) + release (clean up)**
- `canvas.move(item, dx, dy)` takes a **relative** delta, never absolute coordinates
- `<Enter>` / `<Leave>` build hover effects
