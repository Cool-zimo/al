# enum: Killing Magic Strings with Enumerations

> Is your code full of `"pending"`, `"paid"`, `"shipped"`? This lesson gathers them into a named, typed enum class — never misspell one again.

## Why You Need Enums

First, the pain without enums:

```python
STATUS_PENDING = "pending"
STATUS_PAID = "paid"
STATUS_SHIPPED = "shipped"

def handle(status):
    if status == "pading":      # misspelled, and it won't error
        print("processing")
```

`"pading"` is misspelled, but Python stays silent and you only find out after deployment. Enums eliminate this at the type level:

```python
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"

print(Status.PENDING)
print(Status.PENDING.value)
```

Output:

```
Status.PENDING
pending
```

`Status.PENDING` is the enum member; `.value` is the underlying string.

## IntEnum and auto(): Automatic Numbering

When the values are integers, use `IntEnum`; to auto-assign values, use `auto()`:

```python
from enum import IntEnum, auto

class Level(IntEnum):
    LOW = auto()       # 1
    MID = auto()       # 2
    HIGH = auto()      # 3

print(Level.LOW)
print(Level.LOW.value)
print(Level.LOW == 1)      # True: IntEnum can be compared with int
```

Output:

```
Level.LOW
1
True
```

**`auto()` starts at 1 and increments.** A plain `Enum` member can't be compared directly with an integer; `IntEnum` can (because it's a subclass of int).

## Iteration and Lookup

Enums can be iterated over, and you can look up a member by its value:

```python
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"

# iterate
for s in Status:
    print(s.name, s.value)

print("---")
# look up by value
print(Status("pending"))
print(Status["PENDING"])
```

Output:

```
PENDING pending
PAID paid
SHIPPED shipped
---
Status.PENDING
Status.PENDING
```

`Status("pending")` looks up by value; `Status["PENDING"]` fetches by name.

## Crash Site 1: Enum Members Aren't Comparable — Unless It's IntEnum

A plain `Enum` member **cannot** be compared directly with its `.value`:

```python
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"

# WRONG: comparing an enum member with a string is always False
print(Status.PAID == "paid")
```

Output:

```
False
```

`Status.PAID == "paid"` is False! **You need `.value`:**

```python
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"

print(Status.PAID.value == "paid")     # True
print(Status.PAID is Status.PAID)      # True
```

## Crash Site 2: JSON Serialisation of Enums Raises an Error

Calling `json.dumps(Status.PAID)` directly raises a `TypeError`, because JSON doesn't understand enums:

```python
import json
from enum import Enum

class Status(Enum):
    PAID = "paid"

# WRONG
# json.dumps(Status.PAID)      # TypeError
```

**Solution: use `.value` to get the string, or write a custom encoder:**

```python
import json
from enum import Enum

class Status(Enum):
    PAID = "paid"
    SHIPPED = "shipped"

# approach 1: take .value directly
print(json.dumps(Status.PAID.value))

# approach 2: custom encoder
class EnumEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, Enum):
            return obj.value
        return super().default(obj)

print(json.dumps(Status.SHIPPED, cls=EnumEncoder))
```

Output:

```
"paid"
"shipped"
```

## How to Choose Between .value and .name

| Scenario | Use | Example |
| --- | --- | --- |
| Storing in a database, writing JSON, external interfaces | `.value` | `"paid"` |
| Logging, debugging, human-readable | `.name` | `"PAID"` |
| Looking up a member | `Enum(value)` | `Status("paid")` |
| Fetching by name | `Enum[name]` | `Status["PAID"]` |

`.value` is the business value; `.name` is the name in code. Don't mix them up.

## Summary

- Enums replace magic strings — `Status.PENDING` is safer than `"pending"`
- Compare `Enum` members with their value using `.value`; `IntEnum` can compare directly with int
- `auto()` assigns values automatically; `Status(value)` looks up a member
- JSON serialisation requires `.value` or a custom `JSONEncoder`
- Use `.value` for persistence, `.name` for logging and debugging
