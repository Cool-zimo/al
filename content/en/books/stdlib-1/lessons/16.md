# configparser: How to Read INI Configuration Files

> This lesson solves "how to read configuration when your program starts." You no longer need to write a custom `key=value` parser — the standard library ships one called `configparser`. By the end, you'll understand: **everything it returns is a string**, which is where newcomers trip up most often.

## What an INI File Looks Like

INI is a configuration format that dates back to the Windows era. Its structure is so simple you can grasp it at a glance: sections are wrapped in square brackets `[ ]`, and inside each section you have `key = value` pairs (options).

```ini
[database]
host = localhost
port = 3306
debug = true

[user]
name = Alice
city = London
```

The naming has three parts: `[database]` is the section name, `host` is the option name, and `localhost` is the value. Comments use `#` or `;`.

## Minimum Viable Example: Reading an INI String

`configparser` only reads from a "file" — it cannot directly consume a string. So we wrap the string in a file-like object using `io.StringIO` — a pattern you've already seen in the CSV lessons.

```python
import configparser
import io

text = """[database]
host = localhost
port = 3306

[user]
name = Alice
city = London"""

cp = configparser.ConfigParser()
cp.read_file(io.StringIO(text))

print(cp.sections())              # which sections exist
print(cp['database']['host'])     # get a value
print(type(cp['database']['port']))  # the type of the value
```

Output:

```
['database', 'user']
localhost
<class 'str'>
```

Notice the last line: `port` is clearly the number `3306`, yet it comes out as the string `'3306'`. **`configparser` does no type inference — every value is returned as a string.** This is the biggest difference between it and JSON (which auto-detects numbers and booleans).

## getint / getfloat / getboolean: Requesting a Type Manually

Since everything is a string, you must convert yourself. The module provides three convenience methods:

```python
import configparser
import io

text = """[database]
host = localhost
port = 3306
ratio = 0.75
debug = true"""

cp = configparser.ConfigParser()
cp.read_file(io.StringIO(text))

port = cp.getint("database", "port")
ratio = cp.getfloat("database", "ratio")
debug = cp.getboolean("database", "debug")

print(port, type(port).__name__)    # 3306 int
print(ratio, type(ratio).__name__)  # 0.75 float
print(debug, type(debug).__name__)  # True bool
```

`getboolean` also recognises several forms common in English configs: `true/false`, `yes/no`, `on/off`, `1/0`.

## Crash Site 1: Treating a String as a Number

```python
# WRONG
port = cp["database"]["port"]
print(port + 1)          # trying to offset the port number
```

Error:

```
TypeError: can only concatenate str (not "int") to str
```

Because `port` is `"3306"`, adding a number to a string blows up immediately.

**The fix**: use `getint`, or cast with `int()` yourself.

```python
port = cp.getint("database", "port")
print(port + 1)          # 3307
```

By the way, what happens with `getint("database", "host")`? It raises `ValueError: invalid literal for int() with base 10: 'localhost'` — so **a key existing does not mean it can be converted to a number**. In production code, wrap it in a `try` block.

## Crash Site 2: Case Sensitivity — Option Names Get Lowercased

This is the most counter-intuitive aspect of `configparser`: **option names (keys) are normalised to lower case internally, but section names are preserved as-is.**

```python
import configparser
import io

text = """[database]
Host = localhost
PORT = 3306"""

cp = configparser.ConfigParser()
cp.read_file(io.StringIO(text))

print(cp["database"]["host"])   # localhost — key was lowercased
print(cp["database"]["Host"])   # also works — case-insensitive
try:
    print(cp["DATABASE"]["host"])
except KeyError as e:
    print("KeyError:", e)       # section names ARE case-sensitive!
```

Output:

```
localhost
localhost
KeyError: 'DATABASE'
```

**Section names are sensitive, option names are not, and option names are normalised to lower case.** If you can't remember this rule, debugging "I clearly wrote `Host`, why can't I read it?" can waste half an hour.

## Writing Back: Modifying and Saving Configuration

`configparser` is fully read-write. After making changes, use `io.StringIO` as the "file" to capture output, so you can inspect the modified string without touching real disk.

```python
import configparser
import io

cp = configparser.ConfigParser()
cp["database"] = {"host": "localhost", "port": "3306"}
cp["user"] = {}
cp["user"]["name"] = "Alice"

buf = io.StringIO()
cp.write(buf)
print(buf.getvalue())
```

Output:

```
[database]
host = localhost
port = 3306

[user]
name = Alice

```

When writing, it automatically adds spacing and sections — the output is impeccably formatted.

## Checking Whether a Key Exists: `in` and `get` with Defaults

```python
import configparser
import io

cp = configparser.ConfigParser()
cp.read_file(io.StringIO("[db]\nhost=localhost\n"))

# using `in`
if "timeout" in cp["db"]:
    print("has timeout")
else:
    print("no timeout")       # lands here

# using get with a default (second positional argument)
t = cp.get("db", "timeout", fallback="30")
print(t)                        # 30
```

`fallback` is cleaner than checking `in` first and then fetching — prefer it.

## When NOT to Use INI

INI only suits "flat key-value pairs." If your config looks like this, switch to YAML or JSON:

- You need multiple levels of nesting (INI sections go only one level deep)
- A value is a list, e.g. `servers = a, b, c` (you'd have to `split` it yourself)
- You have hundreds of config items and can't sensibly divide them into sections

INI's strength comes precisely from its simplicity: **it's hard for humans to get wrong, it's diff-friendly, and you can read it in three lines of code.** For things like log levels, database connections, and feature flags — scenarios where "a few lines get the job done" — it remains the top choice.

## Summary

- INI structure is `section → option → value`, using `[section]` to delimit sections
- Values read by `configparser` **are all strings** — you must use `getint/getfloat/getboolean` or cast with `int()` yourself
- **Option names are converted to lower case (case-insensitive); section names are case-sensitive** — this is the easiest place to crash
- Use `io.StringIO` instead of real files for read/write — much easier to test
- When fetching a key that might not exist, use `get(..., fallback=...)` to supply a default
