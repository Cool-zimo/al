# CSV Encoding and Dialect Pitfalls

> This lesson tackles "why it is all garbled when you open it" and "why are the delimiters wrong." The differences between UTF-8 and GBK, how to change the delimiter, and the four quoting strategies — they are all here.

## Pitfall #1: Excel Shows Garbled Characters When Opening Chinese CSV

Alice wrote a CSV:

```python
import csv

with open("users.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["Name", "City"])
    writer.writerow(["Alice", "London"])
```

Double-click to open it in Excel — everything is garbled.

**Reason**: Excel on Windows decodes CSV using **GBK (CP936)** by default, but the file is stored in UTF-8. The encoding mismatch causes garbled text.

### Solution A: Save as GBK

```python
with open("users_gbk.csv", "w", encoding="gbk", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["Name", "City"])
    writer.writerow(["Alice", "London"])
```

Excel opens it normally. **Cost**: GBK does not support emoji or some rare characters; attempting to store them will cause an error.

### Solution B: UTF-8 with BOM

```python
with open("users_bom.csv", "w", encoding="utf-8-sig", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["Name", "City"])
    writer.writerow(["Alice", "London"])
```

`utf-8-sig` writes a BOM (`\ufeff`) at the beginning of the file. **When Excel sees the BOM, it knows it is UTF-8** and decodes it correctly. This is currently the most recommended compromise.

### Corresponding Reading

```python
# Reading a GBK file
with open("users_gbk.csv", encoding="gbk", newline="") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)

# Reading UTF-8 with BOM
with open("users_bom.csv", encoding="utf-8-sig", newline="") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
```

Using the wrong encoding to read a file will raise a `UnicodeDecodeError`.

## Pitfall #2: The Delimiter Is Not a Comma

CSV does not necessarily use commas as delimiters. Many tools on Linux use **tabs (TSV)**, and some regions in Europe use **semicolons** (because the comma is the decimal separator).

```python
import csv
import io

# TSV (tab-separated)
text = "name\tage\tcity\nAlice\t28\tLondon\n"
reader = csv.reader(io.StringIO(text), delimiter="\t")
for row in reader:
    print(row)
```

Output:

```
['name', 'age', 'city']
['Alice', '28', 'London']
```

Simply specify `delimiter="\t"`. The same applies to semicolons: `delimiter=";"`.

## `quoting`: When to Add Quotes

There are four quoting strategies in CSV, controlled by the `quoting` parameter:

| Strategy | Meaning | Example output |
|---|---|---|
| `QUOTE_MINIMAL` (default) | Only add quotes if the field contains a comma/newline/quote | `Alice,28,London` |
| `QUOTE_ALL` | Quote all fields | `"Alice","28","London"` |
| `QUOTE_NONNUMERIC` | Quote non-numeric fields | `"Alice","28","London"` |
| `QUOTE_NONE` | Do not quote any (you must ensure no commas) | `Alice,28,London` |

### `QUOTE_MINIMAL` (default)

```python
import csv
import io

buf = io.StringIO()
writer = csv.writer(buf, quoting=csv.QUOTE_MINIMAL)
writer.writerow(["name", "London", "28"])        # only London needs quotes
print(repr(buf.getvalue()))
```

Output:

```
'name,"London",28\r\n'
```

### `QUOTE_ALL`

```python
buf = io.StringIO()
writer = csv.writer(buf, quoting=csv.QUOTE_ALL)
writer.writerow(["name", "London", "28"])
print(repr(buf.getvalue()))
```

Output:

```
'"name","London","28"\r\n'
```

Every field is wrapped in double quotes, which is required when interfacing with certain systems (like legacy database imports).

### `QUOTE_NONNUMERIC`: Automatically Converts Strings to Numbers

```python
buf = io.StringIO()
writer = csv.writer(buf, quoting=csv.QUOTE_NONNUMERIC)
writer.writerow(["Alice", 28, 3.14])
print(repr(buf.getvalue()))
```

Output:

```
'"Alice",28,3.14\r\n'
```

`"Alice"` is a string so it gets quoted; `28` and `3.14` are numbers so they do not. **Conversely**: when reading with `QUOTE_NONNUMERIC`, csv will automatically convert **unquoted fields to float**.

```python
import csv
import io

text = '"Alice",28,3.14\n'
reader = csv.reader(io.StringIO(text), quoting=csv.QUOTE_NONNUMERIC)
for row in reader:
    print(row, [type(x).__name__ for x in row])
```

Output:

```
['Alice', 28.0, 3.14] ['str', 'float', 'float']
```

Note that `28` becomes `28.0` (float). This is the `csv` module's **only automatic type conversion**.

## Crash Site: `escapechar` and Quotes Within Quotes

What if a field itself contains double quotes?

```python
import csv
import io

buf = io.StringIO()
writer = csv.writer(buf, quoting=csv.QUOTE_MINIMAL)
writer.writerow(["note", 'He said "hello"'])
print(repr(buf.getvalue()))
```

Output:

```
'note,"He said ""hello"""\r\n'
```

CSV uses **two double quotes to represent one double quote** for escaping. It can be correctly restored when read back.

## Dialects: Configuring Multiple Format Options at Once

If passing `delimiter`, `quoting`, and `escapechar` every time is too cumbersome, you can register a dialect:

```python
import csv

csv.register_dialect("pipe", delimiter="|", quoting=csv.QUOTE_NONE)

buf = io.StringIO()
writer = csv.writer(buf, dialect="pipe")
writer.writerow(["Alice", "London", 28])
print(repr(buf.getvalue()))        # 'Alice|London|28\r\n'
```

The built-in dialect `csv.excel` is the default behavior, and `csv.unix_dialect` uses `\n` for newlines without `\r`.

## Summary

- Excel garbled text: save as **GBK** (best compatibility) or **UTF-8-SIG** (with BOM, the recommended compromise)
- Use `encoding="gbk"` for reading GBK, `encoding="utf-8-sig"` for reading UTF-8-SIG
- When the delimiter is not a comma: `delimiter="\t"` or `delimiter=";"`
- `QUOTE_MINIMAL` (default): only add quotes if special characters are present
- `QUOTE_ALL`: quote everything, suitable for legacy system interfaces
- `QUOTE_NONNUMERIC`: do not quote numbers when writing; convert unquoted fields to float when reading
- `csv.register_dialect` packages a set of format parameters for reuse
