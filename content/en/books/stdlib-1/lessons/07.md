# Custom Object Serialization: `default` and `object_hook`

> This lesson answers: "How do I store my class objects in JSON?" Building on the pitfalls from Lesson 03, you will learn to use `default=` to convert arbitrary objects into JSON and `object_hook` to restore them.

## The Problem: Instances of Custom Classes Cannot Be Serialized Directly

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
json.dumps(p)
```

Error:

```
TypeError: Object of type Point is not JSON serializable
```

The `json` module only understands six basic types. It has no idea how your `Point` should become JSON. You need to **tell it the rules**.

## The `default` Parameter: Giving the Serializer a "Conversion Function"

The `default` parameter of `json.dumps` accepts a function: when it encounters an unrecognized type, it calls this function and uses the value you return for serialization.

The most common pattern is to return the object's `__dict__`:

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)

text = json.dumps(p, default=lambda o: o.__dict__)
print(text)            # {"x": 3, "y": 4}
```

`o.__dict__` is the dictionary composed of all the object's **instance attributes**. For `Point(3,4)`, `__dict__` is `{"x": 3, "y": 4}`, which happens to be valid JSON.

```python
class Order:
    def __init__(self, order_id, total):
        self.order_id = order_id
        self.total = total

orders = [Order("DD001", 199.0), Order("DD002", 59.0)]
text = json.dumps(orders, default=lambda o: o.__dict__, ensure_ascii=False)
print(text)
# [{"order_id": "DD001", "total": 199.0}, {"order_id": "DD002", "total": 59.0}]
```

## Crash Site: The `default` Function Does Not Cover All Types

If your `default` function only wants to handle `Point` and gets confused by other types:

```python
import json

class Point:
    pass

def my_default(o):
    if isinstance(o, Point):
        return {"x": o.x, "y": o.y}
    # WRONG: other types are not handled and will error out

json.dumps([Point(1,2), set([1,2])], default=my_default)
```

Error:

```
TypeError: Object of type set is not JSON serializable
```

**A more robust `default` pattern**: fall back to a string for unrecognized types so it can at least be serialized:

```python
def safe_default(o):
    if isinstance(o, Point):
        return {"x": o.x, "y": o.y}
    # Fallback: convert to string to guarantee no crash
    return str(o)
```

## Custom Conversion Logic: Not All Objects Should Use `__dict__`

`__dict__` exposes **all attributes**, including ones you do not want to store (such as caches or connection objects). A more refined approach is to construct the dictionary yourself:

```python
import json

class User:
    def __init__(self, uid, name, password, email):
        self.uid = uid
        self.name = name
        self.password = password      # sensitive field, must not be serialized
        self.email = email

u = User(10086, "Alice", "123456", "alice@example.com")

def user_to_dict(o):
    if isinstance(o, User):
        return {
            "uid": o.uid,
            "name": o.name,
            "email": o.email
            # intentionally omitting password
        }
    raise TypeError(f"Unsupported type: {type(o)}")

text = json.dumps(u, default=user_to_dict, ensure_ascii=False)
print(text)
# {"uid": 10086, "name": "Alice", "email": "alice@example.com"}
```

**This example is crucial**: serialization is the data出口, and it is also the perfect time to do "sanitization." Passwords, tokens, and private keys must never enter JSON.

## Crash Site: Accessing `self` in a Lambda Causes `NameError`

Some people try to be more elegant by adding a method to the class:

```python
class Point:
    def to_dict(self):
        return {"x": self.x, "y": self.y}

p = Point(3, 4)
json.dumps(p, default=lambda o: o.to_dict())   # this line itself is fine
```

**Note that `o.to_dict()` inside the lambda presupposes that `o` actually has this method.** A safer approach is to check with `hasattr`:

```python
text = json.dumps(p, default=lambda o: o.to_dict() if hasattr(o, "to_dict") else str(o))
```

## `object_hook`: Turning Dictionaries Back into Objects During Deserialization

What goes out is a dictionary; what comes back is still a dictionary. If you want it to come back as a `Point`, you need `object_hook`:

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

def dict_to_point(d):
    """If this dict looks like a Point, convert it to a Point object"""
    if "x" in d and "y" in d and len(d) == 2:
        return Point(d["x"], d["y"])
    return d          # return other dicts as-is

# First serialize a Point
text = json.dumps(Point(3, 4), default=lambda o: o.__dict__)
print("Outgoing:", text)          # {"x": 3, "y": 4}

# Then deserialize, using object_hook to restore it
back = json.loads(text, object_hook=dict_to_point)
print("Returned type:", type(back))  # <class '__main__.Point'>
print(back.x, back.y)            # 3 4
```

The mechanism of `object_hook`: every time the parser constructs a dictionary, it passes it through your function first. Whatever you return is what the final `loads` result becomes.

## Crash Site: `object_hook` Fails to Return the Original Dict, Breaking the Structure

```python
def bad_hook(d):
    return Point(d["x"], d["y"])      # blindly converts everything to Point

# If the JSON contains other dicts (such as nested user info):
text = '{"point": {"x": 3, "y": 4}, "meta": {"version": 1}}'
json.loads(text, object_hook=bad_hook)
```

Error:

```
KeyError: 'x'
```

This is because the dict `"meta": {"version": 1}` was also thrown into `bad_hook`, which has no `x` key.

**The correct approach**: use **type-tag recognition** in the hook. Agree on adding a type field during serialization:

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = self.y = None

def point_to_json(o):
    if isinstance(o, Point):
        return {"__type__": "Point", "x": o.x, "y": o.y}
    raise TypeError(f"Unsupported type: {type(o)}")

def json_to_point(d):
    if d.get("__type__") == "Point":
        p = Point(0, 0)
        p.x, p.y = d["x"], d["y"]
        return p
    return d

text = json.dumps(Point(3, 4), default=point_to_json)
back = json.loads(text, object_hook=json_to_point)
print(type(back).__name__, back.x, back.y)    # Point 3 4
```

**The `__type__` field is the agreed-upon "type tag."** It is added during serialization and checked against during deserialization. This is the classic solution for preserving type information in JSON.

## Hands-On: An Object Archive Utility That Can Both Save and Load

```python
import json
import os

# Registry: type name -> (class, encoder, decoder)
_REGISTRY = {}

def register_type(name, cls, to_dict, from_dict):
    _REGISTRY[name] = (cls, to_dict, from_dict)

def _encoder(o):
    for name, (cls, to_dict, _) in _REGISTRY.items():
        if isinstance(o, cls):
            d = to_dict(o)
            d["__type__"] = name
            return d
    raise TypeError(f"Unregistered type: {type(o)}")

def _decoder(d):
    t = d.get("__type__")
    if t in _REGISTRY:
        d2 = {k: v for k, v in d.items() if k != "__type__"}
        return _REGISTRY[t][2](d2)
    return d

def save_objects(obj, path):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(obj, f, default=_encoder, ensure_ascii=False, indent=2)

def load_objects(path):
    with open(path, encoding="utf-8") as f:
        return json.load(f, object_hook=_decoder)

# —— Register the Point type ——
class Point:
    def __init__(self, x, y): self.x, self.y = x, y

register_type(
    "Point",
    Point,
    to_dict=lambda p: {"x": p.x, "y": p.y},
    from_dict=lambda d: Point(d["x"], d["y"])
)

# Usage
data = {
    "title": "Geometry Archive",
    "origin": Point(0, 0),
    "points": [Point(1, 2), Point(3, 4)]
}
save_objects(data, "shapes.json")

loaded = load_objects("shapes.json")
print("Title:", loaded["title"])
print("Origin:", type(loaded["origin"]).__name__, loaded["origin"].x, loaded["origin"].y)
print("First point:", loaded["points"][0].x, loaded["points"][0].y)
```

Output:

```
Title: Geometry Archive
Origin: Point 0 0
First point: 1 2
```

Open `shapes.json`, and you will see an archive file with `__type__` tags that is still human-readable. **This is what many "save systems" and "config systems" do under the hood.**

## Summary

- Custom classes will raise `TypeError` if you `dumps` them directly
- `default=` accepts a function that converts unrecognized objects into something serializable
- The most common pattern is `default=lambda o: o.__dict__`, but be aware it exposes all attributes
- **Serialization is a great time for sanitization**: do not include sensitive fields in the dict
- `object_hook=` lets `loads` restore dicts to objects
- Inside the hook, use **type tags** (like `__type__`) or you will accidentally convert other dicts too
- Using a "registry + encoder + decoder" can create a general-purpose object archive utility
