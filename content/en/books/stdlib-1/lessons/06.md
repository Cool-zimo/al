# Accessing Nested Structures: Safe Retrieval from Multi-Level Dicts and Lists

> This lesson answers: "After reading JSON, how do you safely retrieve values from deep within?" You will learn chained `get` access to prevent a `KeyError` from crashing your entire script.

## JSON Data Structures Are Fundamentally Nested Dicts and Lists

Real API responses are never flat. For example, querying a user's order details:

```python
import json

raw = '''
{
    "code": 0,
    "msg": "ok",
    "data": {
        "user": {
            "id": 10086,
            "name": "Alice",
            "address": {
                "city": "London",
                "district": "Camden"
            }
        },
        "orders": [
            {"id": "DD001", "total": 199.0, "status": "paid"},
            {"id": "DD002", "total": 59.0, "status": "pending"}
        ]
    }
}
'''

resp = json.loads(raw)
```

Here: `resp` is a dictionary; retrieving `"data"` yields a dictionary; retrieving `"user"` yields a dictionary; retrieving `"address"` yields a dictionary. Retrieving `"orders"` yields a list, which in turn contains dictionaries.

**The basic action of retrieval is simply repeated `[]`**:

```python
city = resp["data"]["user"]["address"]["city"]
print(city)                # London

first_order_id = resp["data"]["orders"][0]["id"]
print(first_order_id)      # DD001
```

## Crash Site: One Missing Level and the Whole Thing Crashes with `KeyError`

The most common problem with production APIs is that a certain field **might not exist**. For example, the user did not fill in their address:

```python
import json

raw = '''
{
    "code": 0,
    "data": {
        "user": {
            "name": "Alice"
        }
    }
}
'''

resp = json.loads(raw)
district = resp["data"]["user"]["address"]["district"]
print(district)
```

Error:

```
KeyError: 'address'
```

As soon as one level is missing a key, the entire retrieval chain breaks, and all subsequent logic fails to execute. Using `[]` to force retrieval on "potentially incomplete external data" is extremely fragile.

## Safe Retrieval with `get`

The dictionary `get` method allows you to specify "what to return if the value cannot be retrieved":

```python
d = {"name": "Alice"}
print(d.get("age"))            # None (for a non-existent key, None is returned by default)
print(d.get("age", 18))        # 18 (specify a default value)
```

**For nested retrieval, replace every level with `get`**:

```python
resp = json.loads(raw)

city = resp.get("data", {}).get("user", {}).get("address", {}).get("city", "unknown")
print(city)                    # unknown (because this data has no address field)
```

Why is the chained form `resp.get("data", {}).get(...)` safe? Because:

- If `"data"` does not exist, `resp.get("data", {})` returns `{}`
- Calling `.get("user", {})` on the empty dict `{}` still returns `{}`
- This continues returning `{}` until `.get("city", "unknown")` returns `"unknown"`

**The key is that the default value for each level's `get` must be an empty container of the same type** — `{}` for dictionaries, `[]` for lists — so that you can continue to call `.get` down the chain without hitting `None.get(...)`.

## Crash Site: A `None` Default Causes the Chain to Collapse

```python
# WRONG: the default value is None, so .get on the next level crashes
city = resp.get("data", None).get("user", None).get("city", "unknown")
```

Error:

```
AttributeError: 'NoneType' object has no attribute 'get'
```

**Remember**: the default value at each level in a chain must be "an empty container of the same type" — `{}` for dictionaries, `[]` for lists — so that you can continue to go deeper.

## Safe List Access: Check Length First

List index errors raise `IndexError`:

```python
orders = resp["data"]["orders"]

# WRONG
first = orders[0]          # if orders is an empty list, this raises IndexError

# Correct: check length first
if orders:
    print(orders[0]["id"])
else:
    print("no orders")
```

Or use `next` with a default value (a handy Python trick):

```python
first = next(iter(orders), None)
print(first)                # first element or None
```

## Hands-On: Extracting Information from a Real API

The following code simulates processing an order API response, safely extracting each field:

```python
import json

def extract_order_info(raw):
    """Extract an order summary from an API response, filling in missing fields with defaults"""
    resp = json.loads(raw)

    # Safe retrieval chain
    user_name = resp.get("data", {}).get("user", {}).get("name", "Anonymous")
    city = resp.get("data", {}).get("user", {}).get("address", {}).get("city", "unknown")

    orders = resp.get("data", {}).get("orders", [])
    paid_count = sum(1 for o in orders if o.get("status") == "paid")
    total_amount = sum(o.get("total", 0) for o in orders)

    return {
        "user": user_name,
        "city": city,
        "order_count": len(orders),
        "paid_count": paid_count,
        "total_amount": round(total_amount, 2)
    }

raw = '''
{
    "code": 0,
    "data": {
        "user": {"name": "Alice", "address": {"city": "London"}},
        "orders": [
            {"id": "DD001", "total": 199.0, "status": "paid"},
            {"id": "DD002", "total": 59.0, "status": "pending"},
            {"id": "DD003", "total": 320.0, "status": "paid"}
        ]
    }
}
'''

info = extract_order_info(raw)
print(f"User: {info['user']}, City: {info['city']}")
print(f"Orders: {info['order_count']}, Paid: {info['paid_count']}, Total: £{info['total_amount']}")
```

Output:

```
User: Alice, City: London
Orders: 3, Paid: 2, Total: £578.0
```

If you delete the entire `address` section from `raw` and run it again, the result will be `City: unknown`, but **the program will not crash**.

## Crash Site: Wrapping the Entire Retrieval in `try/except` Masks the Real Problem

Some people take the easy way out:

```python
# Not recommended
try:
    city = resp["data"]["user"]["address"]["city"]
except (KeyError, TypeError):
    city = "unknown"
```

This approach works, but it has two problems:

1. `TypeError` will mask a real bug like "this level is not a dict" (e.g., the API returned a string)
2. Large `try` blocks make it harder to pinpoint the problem

**Chained `get` retrieval is cleaner and more precise**, making it the preferred approach for handling uncertain data structures.

## A More Concise Pattern: A Custom Retrieval Function

If you frequently need to retrieve values from deep structures, you can wrap a utility function:

```python
def dig(obj, *keys, default=None):
    """Traverse the path given by keys, returning default if anything cannot be retrieved"""
    cur = obj
    for k in keys:
        if isinstance(cur, dict):
            cur = cur.get(k)
        elif isinstance(cur, list) and isinstance(k, int):
            try:
                cur = cur[k]
            except IndexError:
                return default
        else:
            return default
        if cur is None:
            return default
    return cur

resp = json.loads(raw)
print(dig(resp, "data", "user", "address", "city", default="unknown"))  # London
print(dig(resp, "data", "orders", 0, "id", default="none"))            # DD001
```

`dig(obj, "a", "b", "c")` is equivalent to `obj["a"]["b"]["c"]`, but it is safe throughout. This pattern is extremely common in config reading and API parsing.

## Summary

- JSON is a nested combination of `dict` + `list`; retrieval relies on repeated `[]`
- Using `[]` to force retrieval on external data will crash everything with a `KeyError`
- **Chained safe retrieval**: `resp.get("a", {}).get("b", {}).get("c", default)`
- The default value at each level must be **an empty container of the same type** (`{}`/`[]`); otherwise, `.get` on the next level will crash
- For lists, check the length first or use `next(iter(x), None)` to avoid `IndexError`
- For frequent deep retrieval, wrap a `dig` utility function
- Wrapping the entire retrieval in `try/except` works, but it is neither as precise nor as clear as `get`
