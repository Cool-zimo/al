# The `csv` Module and Why You Cannot Just `split(',')`

> This lesson tells you: CSV looks simple, but commas inside quotes and newlines inside fields will make your hand-written parser collapse completely. Python's standard `csv` module was built for exactly these pitfalls.

## What Exactly Is CSV?

CSV = Comma-Separated Values. Each line is a record, fields are separated by commas, and the first line is usually a header.

```csv
name,age,city
Alice,28,London
Bob,35,New York
```

It looks so simple that many people write code like this:

```python
# WRONG
line = "Alice,28,London"
fields = line.split(",")
print(fields)        # ['Alice', '28', 'London']
```

It runs. But **only on the first line**.

## Crash Site #1: A Comma Inside a Field

```python
# WRONG
line = 'Alice,"London,Camden",28'
fields = line.split(",")
print(fields)
```

Output:

```
['Alice', '"London', 'Camden"', '28']
```

It falls apart. The actual address is "London,Camden" and should count as one field, but `split` cuts at every comma without a second thought.

**The correct approach**: use `csv.reader`, which recognizes fields wrapped in double quotes.

```python
import csv
import io

line = 'Alice,"London,Camden",28\n'
reader = csv.reader(io.StringIO(line))
for row in reader:
    print(row)
```

Output:

```
['Alice', 'London,Camden', '28']
```

`csv.reader` knows: **a comma inside quotes is not a delimiter**. This is the most fundamental difference between it and `split`.

## Crash Site #2: A Newline Inside a Field

The CSV specification allows newlines inside fields, as long as that field is wrapped in double quotes:

```csv
name,remark
Alice,"First time
visiting London",2026-01-01
```

```python
# WRONG
text = '''name,remark
Alice,"First time
visiting London",2026-01-01'''

lines = text.split("\n")
print(len(lines))        # 3 —— but there are only 2 rows of data!
```

Using `split("\n")` slices one record into two halves. `csv.reader` handles this correctly:

```python
import csv
import io

reader = csv.reader(io.StringIO(text))
for row in reader:
    print(row)
```

Output:

```
['name', 'remark']
['Alice', 'First time\nvisiting London', '2026-01-01']
```

The newline is preserved inside the field and is not treated as a record separator.

## Why You Absolutely Must Use the `csv` Module

| Situation | `split(",")` | `csv.reader` |
|---|---|---|
| Normal fields with no commas | Works | Works |
| Comma inside quotes | Crashes | Correct |
| Newline inside a field | Crashes | Correct |
| Quote inside a quote (escaped) | Crashes | Correct (treats `""` as one) |
| Different delimiter (tabs, etc.) | Change split | Change `delimiter` |

CSV "looks like a plain-text protocol," but the rules in the RFC 4180 specification regarding quotes and newlines run to over a dozen. The `csv` module implements all of them for you.

## Minimal Usable Example: Reading a CSV Text

```python
import csv
import io

text = """name,age,city
Alice,28,London
Bob,35,New York
Carol,42,Glasgow"""

reader = csv.reader(io.StringIO(text))
for row in reader:
    print(row)
```

Output:

```
['name', 'age', 'city']
['Alice', '28', 'London']
['Bob', '35', 'New York']
['Carol', '42', 'Glasgow']
```

`io.StringIO` feeds a string to the `reader` as if it were a "file," which is especially convenient in Pyodide/grading environments since it does not rely on a real file system.

## Do Not Build the Output by Hand Either

```python
# WRONG
rows = [["Alice", "London,Camden", 28], ["Bob", "New York", 35]]
for r in rows:
    line = ",".join(str(x) for x in r)
    print(line)
```

Output:

```
Alice,London,Camden,28       # the field got split
Bob,New York,35
```

**The correct approach**: use `csv.writer`.

```python
import csv
import io

buf = io.StringIO()
writer = csv.writer(buf)
writer.writerow(["name", "address", "age"])
writer.writerow(["Alice", "London,Camden", 28])
writer.writerow(["Bob", "New York", 35])

print(buf.getvalue())
```

Output:

```
name,address,age
"Alice","London,Camden",28
"Bob","New York",35
```

`csv.writer` automatically adds double quotes around fields containing commas (or newlines).

## Crash Site #3: Forgetting `newline=''` Causes Extra Blank Lines

(This pitfall is covered in detail in Lesson 12, but consider this a preview.)

```python
# WRONG: on Windows, writing CSV in default mode
import csv

with open("out.csv", "w", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["a", "b"])
    writer.writerow(["c", "d"])
```

On Windows, an extra blank line will appear between each row. The reason is that the `csv` module manages newlines itself, but when you open the file, Python adds another layer of newline translation — the two layers stack and produce blank lines. **The fix: add `newline=''`.**

## Summary

- CSV **is not simply "split by commas"** — commas inside quotes and newlines inside fields will cause `split` to崩溃
- `csv.reader` complies with RFC 4180, correctly handling quotes, newlines, and escaping
- Use `io.StringIO` to feed strings to reader/writer as if they were files, which is convenient for testing
- Use `csv.writer` for writing; it automatically quotes fields with special characters
- Do not forget `newline=''` — covered in detail in the next lesson
