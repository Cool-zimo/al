# Why Data Formats Matter

> This lesson answers a simple question: how do two programs hand data to each other intact? You will understand that `print` output is for human eyes, while `json.dumps` output is for programs.

## Talking Between Programs Cannot Rely on `print`

Imagine you wrote a script that pulls today's orders from a database, and you want to hand them to a colleague's program for accounting. The most obvious idea: just print them out, right?

```python
orders = [{"id": 1, "total": 99.5}, {"id": 2, "total": 128.0}]

print(orders)
```

Output:

```
[{'id': 1, 'total': 99.5}, {'id': 2, 'total': 128.0}]
```

This string is only useful to **someone who understands Python**. Hand it to a Java program, a web front end, or an Excel plugin, and they will stare at the single quotes around `'id'` in utter confusion — that is not their language.

Worse still, this output is meant for **debugging**, not for "structured data". If you wanted to extract the total of the second order, you would have to write a mess of string-splitting logic.

The purpose of a **data format** is to establish a common "world language" for this kind of conversation: both sides agree that all strings use double quotes, all arrays use square brackets, and all keys are strings. Anyone can generate it, anyone can parse it, and nobody cares which language the other side was written in.

## JSON Is That "World Language"

JSON (JavaScript Object Notation) originated as JavaScript's object syntax, but because it is simple enough, it has become the de facto standard for internet data exchange. When you shop online, scroll through short videos, or check the weather, your phone app and the server are exchanging JSON.

Its syntax has only a few rules:

| JSON form | Meaning | Python equivalent |
|---|---|---|
| `123` | number | `int` / `float` |
| `"hello"` | string (must be double-quoted) | `str` |
| `true` / `false` | boolean | `True` / `False` |
| `null` | null value | `None` |
| `[1, 2, 3]` | array (ordered list) | `list` |
| `{"name": "Alice"}` | object (key-value table) | `dict` |

Pay attention to **two hard rules you must remember**:

1. **Strings must use double quotes** `"` — single quotes `'` are wrong.
2. **Keys must also use double quotes** — writing `{"name": 1}` works, but `{name: 1}` does not.

## Crash Site: Handing Off Data via `print`, Broken by a Single Comma

Alice wrote a script to process order notes and used `print` to hand them to Bob:

```python
# WRONG
note = "Customer requests: urgent, deliver on weekend"
print(note)
```

Bob split the string on commas, but the comma inside the note threw off his parsing. The reliable approach is to let the program serialize the data itself — never hand-write it.

```python
import json

order = {
    "id": "DD20260927001",
    "buyer": "Alice",
    "total": 99.5,
    "items": [
        {"name": "Mechanical Keyboard", "price": 459, "qty": 1},
        {"name": "Mouse Pad", "price": 39, "qty": 2}
    ],
    "note": "urgent, deliver on weekend",
    "paid": True
}

text = json.dumps(order)
print(text)
```

Output (shown here with line breaks for clarity):

```
{"id": "DD20260927001", "buyer": "Alice", "total": 99.5,
 "items": [{"name": "Mechanical Keyboard", "price": 459, "qty": 1},
           {"name": "Mouse Pad", "price": 39, "qty": 2}],
 "note": "urgent, deliver on weekend", "paid": true}
```

Notice the `paid` field: Python's `True` became JSON's `true`, with a lowercase first letter. `None` becomes `null`. This is the "translation" process in action.

## Crash Site: Single Quotes and Trailing Commas — JSON Rejects Them All

```python
import json

# WRONG: a Python repr-style string, not valid JSON
data = "{'name': 'Alice'}"
json.loads(data)
```

Error:

```
JSONDecodeError: Expecting property name enclosed in double quotes
```

The JSON specification has **no concept of single quotes**, nor trailing commas (the extra comma after `[1, 2,]`). These are legal in Python but will always raise an error in JSON.

**The correct approach**: always generate with `json.dumps` and parse with `json.loads`, letting the library handle quote conversion for you. Never拼 strings by hand.

## A Simple End-to-End Example

The code below simulates a real scenario: a server returns a JSON text blob, and your program needs to extract the order total from it.

```python
import json

# Pretend this string came from a network call or a file (it is a string standing in for external input)
raw = '''
{
    "order_id": "DD20260927001",
    "buyer": "Alice",
    "items": [
        {"name": "Mechanical Keyboard", "price": 459, "qty": 1},
        {"name": "Mouse Pad", "price": 39, "qty": 2}
    ],
    "paid": true
}
'''

order = json.loads(raw)          # string -> Python object
total = sum(it["price"] * it["qty"] for it in order["items"])
print(f"Buyer: {order['buyer']}, Total due: £{total}")
```

Output:

```
Buyer: Alice, Total due: £537
```

The key step here: `json.loads` "restores" the outer string back into Python dictionaries and lists, after which you can process them with familiar `[]` and loops. **This is the entire value of a "data format": turning external text into internal objects.**

## The Standard Library Means "Batteries Included"

`json` is part of Python's standard library. The so-called standard library is the collection of libraries that ship with Python — no `pip install` required. Its peers include `csv` (for tabular data), `os` (for OS interaction), and `datetime` (for dates and times), all of which are covered in this book.

```python
import json        # standard library, just import and go
import csv
import os
```

**Why the standard library deserves its own chapter**: it covers roughly 80% of the "grunt work" in everyday scripting. Writing your own string parsers, handling file encodings by hand, or拼接 delimiters are all error-prone and unnecessary forms of重复劳动.

## Summary

- Exchanging data between programs requires an **agreed-upon data format** — you cannot just `print` random strings
- JSON is the most universal data exchange format today: double-quoted strings, arrays with `[]`, objects with `{}`
- Strings must use double quotes, keys must use double quotes; `true`/`false`/`null` are JSON's vocabulary
- `json.dumps(obj)` turns a Python object into a JSON string; `json.loads(text)` restores a string to an object
- JSON has **no single quotes and no trailing commas** — these Python idioms will raise errors
- `json` is part of the standard library: no installation needed, just `import`
