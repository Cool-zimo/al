# Reading and Writing Files: `dump`, `load`, and Three Key Parameters

> This lesson covers how to actually store JSON on disk and read it back. You will learn the three parameters that make files "both usable and readable": `ensure_ascii`, `indent`, and `sort_keys`.

## `dump`: Writing an Object Directly to a File

In the previous lesson, `dumps` returned a string. If your end goal is to save to a file, `dump` does it in one step:

```python
import json

config = {
    "app_name": "Order Management System",
    "version": "1.2.0",
    "debug": False,
    "max_workers": 8
}

with open("config.json", "w") as f:
    json.dump(config, f)
```

`dump(obj, f)` accepts two arguments: the object to serialize and an **already opened file object**. It handles the `write` call internally, so you do not need to call it again.

Reading works the same way with `load(f)`:

```python
with open("config.json") as f:
    cfg = json.load(f)

print(cfg["app_name"])      # Order Management System
print(cfg["max_workers"])   # 8
```

**The only difference between `dump`/`load` and `dumps`/`loads` is whether you manage the file yourself.** Use `dump` to save to disk, and `dumps` to work in memory.

## `ensure_ascii=False`: Making Chinese Characters Display Properly

This is the question beginners ask most often. First, observe the default behavior:

```python
import json

data = {"city": "London", "slogan": "I love coding"}

print(json.dumps(data))
# {"city": "\u6d6e\u6566", "slogan": "\u6211\u7231\u7f16\u7a0b"}
```

The Chinese characters have all turned into `\uXXXX` **escape sequences**.

This is not a bug — it is the default strategy of `json.dumps`: to be "absolutely safe in any encoding environment," it converts all non-ASCII characters to `\uXXXX`. The data is not lost and parsing works fine; it is just **unreadable to humans**.

The solution: add `ensure_ascii=False`:

```python
print(json.dumps(data, ensure_ascii=False))
# {"city": "London", "slogan": "I love coding"}
```

It works the same way when writing to a file:

```python
with open("city.json", "w") as f:
    json.dump(data, f, ensure_ascii=False)
```

Now, when you open `city.json`, the Chinese characters are crystal clear.

**Conclusion**: whenever your data contains Chinese (or any non-ASCII text), you should almost always write `ensure_ascii=False`. The only exception is when you explicitly need to support legacy systems that only understand ASCII.

## `indent`: Adding Structure to the File

By default, JSON output is **crammed onto a single line**. This is fine for machines but a nightmare for humans to maintain.

```python
import json

users = {
    "users": [
        {"name": "Alice", "age": 20, "city": "London"},
        {"name": "Bob", "age": 25, "city": "New York"}
    ],
    "count": 2
}

print(json.dumps(users))
# {"users": [{"name": "Alice", "age": 20, "city": "London"}, {"name": "Bob", "age": 25, "city": "New York"}], "count": 2}
```

Add `indent=2`:

```python
print(json.dumps(users, indent=2, ensure_ascii=False))
```

Output:

```json
{
  "users": [
    {
      "name": "Alice",
      "age": 20,
      "city": "London"
    },
    {
      "name": "Bob",
      "age": 25,
      "city": "New York"
    }
  ],
  "count": 2
}
```

`indent=2` means "indent 2 spaces per level." **For config files and log files, adding indent is strongly recommended**, because you may need to edit them by hand, diff them, or troubleshoot issues.

## `sort_keys`: Sorting Keys Alphabetically

```python
import json

profile = {"name": "Alice", "age": 20, "city": "London"}

print(json.dumps(profile, sort_keys=True))
# {"age": 20, "city": "London", "name": "Alice"}
```

The keys are now in alphabetical order. When is this useful?

- **When you need to do version comparisons (diffs)**: after sorting, two files will produce an empty diff as long as their content is identical, without being thrown off by order
- **For debugging**: a fixed order lets you find a specific field at a glance
- **For writing test snapshots**: the serialized result is stable and predictable

If you do not need it (when pursuing performance or when field order itself carries meaning), do not turn it on, as sorting incurs overhead.

## Crash Site: Forgetting `encoding` Makes Chinese Garbled on Windows

```python
import json

data = {"msg": "Hello, world"}

# WRONG: on Windows, the default encoding might be gbk
with open("hello.json", "w") as f:
    json.dump(data, f, ensure_ascii=False)
```

On a Chinese-language Windows system, `open()` defaults to GBK encoding. You thought you were writing UTF-8, but you actually wrote GBK. When another program (or a Linux server) tries to read it, the text becomes garbled.

**The correct approach**: explicitly specify `encoding="utf-8"`:

```python
with open("hello.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False)

# Specify the same when reading
with open("hello.json", encoding="utf-8") as f:
    obj = json.load(f)
```

## How to Combine the Three Parameters

In real projects, the most common pattern looks exactly like this:

```python
import json

def save_json(obj, path):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(obj, f, ensure_ascii=False, indent=2)

def load_json(path):
    with open(path, encoding="utf-8") as f:
        return json.load(f)
```

Four guarantees: `ensure_ascii=False` keeps Chinese readable, `indent=2` keeps the format clean, `encoding="utf-8"` prevents cross-platform garbling, and the `with` statement automatically closes the file.

## Hands-On: Saving and Reading a Grade Report

```python
import json

report = {
    "class": "Year 3 Class 1",
    "exam": "September 2026 Monthly Exam",
    "students": [
        {"name": "Alice", "chinese": 118, "math": 135, "english": 122},
        {"name": "Bob", "chinese": 105, "math": 142, "english": 130},
        {"name": "Carol", "chinese": 128, "math": 98, "english": 115}
    ]
}

# Save
with open("report.json", "w", encoding="utf-8") as f:
    json.dump(report, f, ensure_ascii=False, indent=2, sort_keys=False)

# Read and summarize
with open("report.json", encoding="utf-8") as f:
    data = json.load(f)

print(f"Class: {data['class']}  Exam: {data['exam']}")
print("-" * 30)
for s in data["students"]:
    avg = round((s["chinese"] + s["math"] + s["english"]) / 3, 1)
    print(f"{s['name']}  Total: {s['chinese']+s['math']+s['english']}  Avg: {avg}")
```

Output:

```
Class: Year 3 Class 1  Exam: September 2026 Monthly Exam
------------------------------
Alice  Total: 375  Avg: 125.0
Bob  Total: 377  Avg: 125.7
Carol  Total: 341  Avg: 113.7
```

Open `report.json`, and you will see a neatly formatted, clearly Chinese-readable JSON file that you can edit by hand at any time. This is the value of `indent` and `ensure_ascii`.

## Summary

- `dump(obj, f)` writes to a file, `load(f)` reads from a file; `dumps`/`loads` only handle strings
- **Always add `ensure_ascii=False` for Chinese**, otherwise it turns into `\uXXXX` escapes
- **Always add `indent=2` for config files** so humans can read and diff them
- **Add `sort_keys=True` when comparisons/snapshots matter** to keep the output stable
- When reading and writing files, **always specify `encoding="utf-8"` explicitly** to avoid the Windows-GBK trap
- It is recommended to wrap everything in `save_json` / `load_json` utility functions
