# pickle: Serialising Arbitrary Python Objects to Bytes

> This lesson solves "how to store things that JSON can't." Custom class instances, structures with circular references, sets, complex numbers — `pickle` handles all of them. The cost is that what it produces can only be read by Python.

## What JSON Can't Do, pickle Can

Recall lessons 03 and 09: JSON only understands six types. The object below causes `json.dumps` to raise a `TypeError` immediately.

```python
import json

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
json.dumps(p)        # TypeError: Object of type Point is not JSON serializable
```

With `pickle`, however:

```python
import pickle

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)
data = pickle.dumps(p)         # bytes
print(type(data).__name__, len(data), "bytes")

p2 = pickle.loads(data)
print(type(p2).__name__, p2.x, p2.y)
```

Output:

```
bytes 57 bytes
Point 3 4
```

The object comes back intact. This is called **serialisation** (turning an in-memory object into a transmittable byte string) and **deserialisation** (restoring it).

## dumps / loads: Operating on Bytes

`pickle`'s naming mirrors `json` exactly — the correspondence is easy to remember:

| Purpose | pickle | json |
|---|---|---|
| object → string/bytes | `dumps(obj)` | `dumps(obj)` |
| bytes/string → object | `loads(data)` | `loads(data)` |
| object → file | `dump(obj, f)` | `dump(obj, f)` |
| file → object | `load(f)` | `load(f)` |

The only difference: `pickle.dumps` returns **bytes**, not a string. So you use `io.BytesIO` rather than `io.StringIO` as your "in-memory file".

```python
import pickle
import io

buf = io.BytesIO()
pickle.dump([1, 2, {"a": 3}], buf)
print("wrote", buf.tell(), "bytes")

buf.seek(0)
obj = pickle.load(buf)
print(obj)
```

Output:

```
wrote 43 bytes
[1, 2, {'a': 3}]
```

## Three Things pickle Can Do That JSON Cannot

**One: store instances of custom classes.** Demonstrated above.

**Two: store circular references.** When an object references itself (or two objects reference each other), JSON recurses infinitely until the stack overflows, whereas pickle handles it correctly using an "object memo" mechanism:

```python
import pickle

a = {"name": "Alice"}
a["self"] = a            # circular reference: dict references itself

data = pickle.dumps(a)
a2 = pickle.loads(data)

print(a2["name"])        # Alice
print(a2["self"] is a2)  # True — the restored structure is still the same object
```

`a2["self"] is a2` being `True` proves the circular structure was faithfully reconstructed. This is pickle's killer feature relative to JSON.

**Three: store types that JSON simply doesn't have.**

```python
import pickle

stuff = {
    "set": {1, 2, 3},
    "complex": 3 + 4j,
    "frozenset": frozenset([9, 9, 8]),
    "bytes": b"\x00\x01\x02",
}
data = pickle.dumps(stuff)
back = pickle.loads(data)
print(type(back["set"]).__name__, back["set"])
print(back["complex"], back["frozenset"], back["bytes"])
```

Output:

```
set {1, 2, 3}
(3+4j) frozenset({8, 9}) b'\x00\x01\x02'
```

Sets, complex numbers, frozensets, bytes — JSON recognises none of these, but pickle preserves every original type.

## Crash Site 1: dumps Returns Bytes, Not a String

```python
import pickle

data = pickle.dumps([1, 2, 3])
# WRONG
print("serialised result: " + data)
```

Error:

```
TypeError: can only concatenate str (not "bytes") to str
```

`data` is `bytes`. To inspect its contents you must decode it first, or simply print its `repr`:

```python
data = pickle.dumps([1, 2, 3])
print(repr(data))                    # b'\x80\x04\x95\x0b...'
print(data.decode("latin-1"))        # decodes, but the content is gibberish — not recommended
```

**Remember: use JSON for anything you want to treat as text; use pickle for anything you want to treat as bytes.**

## Crash Site 2: Cross-Version, Cross-Python — Can't Be Read

pickle has protocol version numbers. A byte string generated by a newer Python version may not be readable by an older one. You can use `protocol=` to explicitly specify an older version for compatibility:

```python
import pickle

obj = [1, 2, 3]
print("default protocol:", pickle.DEFAULT_PROTOCOL)
print("highest protocol:", pickle.HIGHEST_PROTOCOL)

b5 = pickle.dumps(obj, protocol=pickle.HIGHEST_PROTOCOL)
b0 = pickle.dumps(obj, protocol=0)   # earliest text protocol, largest size
print("protocol 5:", len(b5), "bytes")
print("protocol 0:", len(b0), "bytes")
```

Output:

```
default protocol: 4
highest protocol: 5
protocol 5: 22 bytes
protocol 0: 18 bytes
```

The protocol version also affects size. More importantly, **Python 2 pickle and Python 3 pickle have extremely poor interoperability** — if you need long-term archival, pickle is a poor choice. The next lesson explains why, and how to choose.

## Crash Site 3: When the Class Definition Changes, Old Data Won't Restore

pickle stores "reconstruction instructions" that include the class name (e.g. `__main__.Point`). If the class name or constructor arguments change, deserialisation fails:

```python
import pickle

class Old:
    def __init__(self, x):
        self.x = x

obj = Old(1)
data = pickle.dumps(obj)
del Old                        # class definition removed

# WRONG: class not found during deserialisation
try:
    pickle.loads(data)
except AttributeError as e:
    print("AttributeError:", e)
```

Output:

```
AttributeError: Can't get attribute 'Old' on <module '__main__'>
```

**So don't use pickle for long-term cross-version archival, and don't expect a different program to be able to read it.** It's a tool for "temporary persistence on disk within the same language and same code version" — not an interchange format.

## Summary

- `pickle.dumps` returns `bytes`; restore with `pickle.loads`. For file operations, use `dump/load` + `io.BytesIO`
- pickle can store custom class instances, circular references, sets, and complex numbers — none of which JSON supports
- The cost: the output is bytes, it's tightly coupled to the Python version and class definitions, and it's completely non-portable across languages
- Good fit: caching, passing objects temporarily between processes, session state. Bad fit: long-term archival, external interfaces, cross-language exchange
- The next lesson covers the most important rule: **never unpickle data from an untrusted source**
