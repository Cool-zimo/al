# `dumps` and `loads`: Four Functions, Two Pairs

> This lesson thoroughly covers the four most commonly used functions in the `json` module. You only need to remember two pairs: use `dumps`/`loads` for **strings**, and `dump`/`load` for **files**.

## The `json` Module Has Only Four Tools

Open a Python interactive session and take a look at what it provides:

```python
import json

print([x for x in dir(json) if not x.startswith("_")])
```

The four most common ones are:

| Function | Purpose | Input | Output |
|---|---|---|---|
| `json.dumps(obj)` | serialize (encode) | Python object | **string** `str` |
| `json.loads(s)` | deserialize (decode) | JSON string | **Python object** |
| `json.dump(obj, f)` | serialize to a file | Python object + file object | none (writes directly) |
| `json.load(f)` | deserialize from a file | file object | Python object |

Mnemonic: **the ones with `s` are the string versions, the ones without are the file versions**.

- `dumps` = dump + string — the result is a string
- `loads` = load + string — reads from a string
- `dump` / `load` operate directly on file objects

## `dumps`: Turning an Object into a String

```python
import json

config = {
    "host": "api.example.com",
    "port": 443,
    "timeout": 30,
    "debug": False,
    "retry": None
}

text = json.dumps(config)
print(text)
print(type(text))      # <class 'str'>
```

Output:

```
{"host": "api.example.com", "port": 443, "timeout": 30, "debug": false, "retry": null}
<class 'str'>
```

Notice a few "translations": `False` → `false`, `None` → `null`. The return value is of type `str`, which can be stored in a database, sent over a network, or written to a log.

**This is the "output to the outside world" format**: your program uses dictionaries internally for convenience, but to hand data to the outside world, you must first `dumps` it into a string.

## `loads`: Turning a String Back into an Object

```python
import json

raw = '{"host": "api.example.com", "port": 443, "debug": false}'

obj = json.loads(raw)
print(obj)
print(type(obj))       # <class 'dict'>
print(obj["host"])     # api.example.com
```

`loads` is the inverse of `dumps`. The input must be a **valid JSON string**, and the return value is a dictionary or list.

## Crash Site: Using `dump` on the Result of `dumps` Serializes a String Twice

This is the easiest thing for a beginner to confuse: `dumps` already gave you a string, so what happens if you then pass it to `dump`?

```python
import json

config = {"host": "localhost", "port": 8080}

# WRONG: dumps already gave us a string; using dump to write it to a file
text = json.dumps(config)
with open("/tmp/wrong.json", "w") as f:
    json.dump(text, f)      # the string gets serialized *again*
```

Open `/tmp/wrong.json`, and you will see:

```
"{\"host\": \"localhost\", \"port\": 8080}"
```

The entire content has been **wrapped in double quotes with backslash escapes** — because the string itself was treated as a JSON string value and serialized a second time. The correct approach is one of two options:

```python
# Correct approach 1: let dump write the object directly
with open("/tmp/right1.json", "w") as f:
    json.dump(config, f)

# Correct approach 2: get the string with dumps, then write it yourself
with open("/tmp/right2.json", "w") as f:
    f.write(json.dumps(config))
```

## Crash Site: Passing a File Object to `loads` Instead of a String

```python
import json

# WRONG
with open("/tmp/right1.json") as f:
    obj = json.loads(f)     # passed a file object
```

Error:

```
TypeError: the JSON object must be str, bytes or bytearray, not TextIOWrapper
```

`loads` only wants a string. To read a file directly, use `load` (no `s`):

```python
with open("/tmp/right1.json") as f:
    obj = json.load(f)      # correct: load accepts a file object
print(obj)                  # {'host': 'localhost', 'port': 8080}
```

**One sentence to remember it**: whether or not you manage the file yourself depends on whether there is an **`s` in the function name**. `dump`/`load` handle reading and writing for you; `dumps`/`loads` only deal with strings — you manage the file.

## When to Use Which Function

| Scenario | Use this |
|---|---|
| Store config in a database or send it over a network | `dumps` → get a string |
| Parse text received from a network response or message queue | `loads` → get an object |
| Write config directly to a `config.json` file | `dump` |
| Read a `data.json` file directly | `load` |
| Quickly serialize in memory and deserialize again | `dumps` + `loads` combo |

## Hands-On: Simulating a "Send Request — Receive Response" Cycle

The code below simulates the complete process of "packaging data to send out, then unpacking the reply" in real development:

```python
import json

# —— Client: package the request ——
request = {
    "action": "query_order",
    "order_id": "DD20260927001",
    "fields": ["buyer", "total", "items"]
}
body = json.dumps(request)          # turn into a string, ready to send over the network
print("Sending:", body)

# —— Pretend this is the network传输; body is just that string ——

# —— Server: unpack the request, build a response ——
received = json.loads(body)         # server gets the string, restores it to an object
resp = {
    "code": 0,
    "msg": "ok",
    "data": {
        "buyer": "Alice",
        "total": 537,
        "items": [{"name": "Mechanical Keyboard", "price": 459, "qty": 1}]
    }
}
resp_body = json.dumps(resp)

# —— Client: unpack the response ——
result = json.loads(resp_body)
print(f"Response code: {result['code']}, buyer: {result['data']['buyer']}, total: £{result['data']['total']}")
```

Output:

```
Sending: {"action": "query_order", "order_id": "DD20260927001", "fields": ["buyer", "total", "items"]}
Response code: 0, buyer: Alice, total: £537
```

As you can see, the entire communication process uses `dumps` and `loads` exactly twice each. This is what 90% of API calls do under the hood.

## Summary

- The four core functions of the `json` module: `dumps`/`loads` (strings), `dump`/`load` (files)
- Mnemonic: **with `s` = string version, without `s` = file version**
- `dumps` outputs `str`, `loads` outputs `dict`/`list`
- The most common confusions: calling `dump` after `dumps` (double serialization, escaping appears), and mistakenly passing a file object to `loads`
- Use `dumps` to send data out, `loads` to receive data from outside; use `dump`/`load` for direct file I/O
- Network requests/responses are just a combination of `dumps` + `loads`
