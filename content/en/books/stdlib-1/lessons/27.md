# Lesson 27 · The Data Pipeline: Reading Multiple Formats

> The load layer's goal — no matter what format arrives, out comes `list[dict]`.

## Dispatching by File Extension

The core logic of the load layer: check the file suffix first, then decide which parser to use. This is the **dispatch** pattern:

```python
def load(filepath):
    if filepath.endswith(".json"):
        return load_json(filepath)
    elif filepath.endswith(".csv"):
        return load_csv(filepath)
    elif filepath.endswith(".ini"):
        return load_ini(filepath)
    else:
        raise ValueError(f"unsupported format: {filepath}")
```

**A single `if-elif` handles the dispatch.** Why not a fancier design pattern? Because three branches are plenty — over-abstracting just makes it harder to read. When you eventually face ten formats, that's the time to consider a strategy pattern.

## Three Parsers

### Reading JSON

```python
import json

def load_json(filepath):
    with open(filepath, encoding="utf-8") as f:
        data = json.load(f)
    # unify to list[dict]
    if isinstance(data, dict):
        data = [data]
    return data
```

JSON may be a single object or an array — `isinstance` covers both cases.

### Reading CSV

```python
import csv

def load_csv(filepath):
    with open(filepath, encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        return list(reader)
```

`csv.DictReader` gives you a list of dicts directly, with the header row as the keys. Note `newline=""` — it's a hard requirement of the `csv` module; omit it and Windows will give you blank lines.

### Reading INI

```python
import configparser

def load_ini(filepath):
    cp = configparser.ConfigParser()
    cp.read(filepath, encoding="utf-8")
    records = []
    for section in cp.sections():
        d = dict(cp[section])
        # INI has no top-level id, so use the section name as the id
        d["id"] = section
        records.append(d)
    return records
```

INI sections map naturally to individual records; `cp[section]` behaves like a dict and can be passed straight to `dict()`.

## The Complete Load Layer

Wrap the three parsers in one module:

```python
import json
import csv
import configparser

def load_json(filepath):
    with open(filepath, encoding="utf-8") as f:
        data = json.load(f)
    return data if isinstance(data, list) else [data]

def load_csv(filepath):
    with open(filepath, encoding="utf-8", newline="") as f:
        return list(csv.DictReader(f))

def load_ini(filepath):
    cp = configparser.ConfigParser()
    cp.read(filepath, encoding="utf-8")
    records = []
    for section in cp.sections():
        d = dict(cp[section])
        d["id"] = section
        records.append(d)
    return records

def load(filepath):
    if filepath.endswith(".json"):
        return load_json(filepath)
    elif filepath.endswith(".csv"):
        return load_csv(filepath)
    elif filepath.endswith(".ini"):
        return load_ini(filepath)
    else:
        raise ValueError(f"unsupported format: {filepath}")
```

**The caller only needs to know about `load()`** — it doesn't care which format is underneath. That's the value of layering.

## Normalisation: Unifying Different Keys

The load layer emits "native dicts in each format's own dialect," with non-uniform field names. CSV's header might be `order_no`, while INI uses `id`. The transform layer handles this:

```python
def normalize(raw_list):
    """Convert a list of native dicts into a list of standard Record dicts"""
    result = []
    for raw in raw_list:
        # handle different key names
        id_val = raw.get("id") or raw.get("order_no") or raw.get("no")
        amount = raw.get("amount") or raw.get("amount_gbp")
        status = raw.get("status") or raw.get("state")
        qty = raw.get("qty") or raw.get("quantity")
        result.append({
            "id": id_val,
            "amount": str(amount),
            "status": status,
            "qty": int(qty) if qty else 0,
        })
    return result
```

`raw.get("id") or raw.get("order_no")` — try the standard name first, then the aliases. **This is the "translation" logic**, mapping a wild variety of input field names to a uniform standard set.

## Why Return list[dict] Instead of Converting to Record Directly

You might ask: why not return `list[Record]` straight away? Because **the load layer shouldn't know that the domain model exists.**

The load layer only handles "turn the file into a dict"; the transform layer handles "turn the dict into a Record." So if the `Record` structure changes later (say, a new field is added), the load layer doesn't move at all.

This is the **single-responsibility principle** at work inside a pipeline.

## Summary

- The load layer uses `if-elif` to dispatch to three parsers by file extension
- JSON uses `json.load`, CSV uses `csv.DictReader`, INI uses `configparser`
- Always open CSV files with `newline=""`
- The normalisation layer maps different field names (English / aliases) to a uniform key
- The load layer only outputs `list[dict]` and never touches the domain model
- Callers only call `load()`, shielded from format differences

## Crash Site 1: INI Values Are Always Strings

```python
import configparser

cp = configparser.ConfigParser()
# cp.read(...) omitted
# WRONG: assuming INI preserves types
# amount = cp["T001"]["amount"]  # this is str, not int or float
```

**The INI format inherently only stores strings.** Every value must be manually type-converted — that's an intrinsic limitation of INI, and exactly why the transform layer does type conversion.

## Crash Site 2: JSON's Top Level Is an Object, Not an Array

```python
import json

# WRONG: assuming it's always a list
# data = json.load(f)
# for item in data: ...   # crashes if the top level is {}

# correct: check the type
data = {"id": "T001", "amount": "19.90"}
if isinstance(data, dict):
    data = [data]
for item in data:
    print(item)
```

**Never assume the top-level JSON structure.** An API might return a single object or an array — use `isinstance` as a fallback.
