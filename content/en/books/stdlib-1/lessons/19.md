# base64: Slipping Binary Data into Text-Only Contexts

> This lesson solves "how to embed images, signatures, or archives into JSON / email / URLs." Binary bytes can't be placed raw into text protocols — base64 is that translation layer, turning 3 bytes into 4 printable characters.

## The Problem: Binary Can't Be Placed Raw into Text Protocols

Imagine you're building an API and need to embed a user's avatar into a JSON payload:

```python
import json

avatar = b"\x89PNG\r\n\x1a\n\x00..."   # the bytes of a PNG
payload = {"user": "Alice", "avatar": avatar}

# WRONG
json.dumps(payload)
```

Error:

```
TypeError: Object of type bytes is not JSON serializable
```

JSON only understands strings (and Unicode strings at that) — it doesn't know what to do with `bytes`. Nor can you simply "treat the bytes as a string" and concatenate them in — high bytes like `\x89` get rewritten, truncated, or rejected as invalid UTF-8 by many transport layers.

**The solution: encode the bytes into ASCII characters first, then put them in.** That's exactly what base64 does.

## Minimum Viable Example: b64encode / b64decode

```python
import base64

data = b"\x89PNG\r\n\x1a\n"          # arbitrary binary
encoded = base64.b64encode(data)     # returns bytes
text = encoded.decode("ascii")       # now a string that can go into JSON

print("encoded:", text)
print("length: ", len(text), "chars")

# restore
back = base64.b64decode(text)
print("restored:", back, "equal:", back == data)
```

Output:

```
encoded: iVBORw0KGgo=
length:  12 chars
restored: b'\x89PNG\r\n\x1a\n' equal: True
```

Three things to note:

1. `b64encode` takes `bytes` and returns `bytes` — so you must additionally `.decode("ascii")` to get a string
2. The output contains only `A-Z a-z 0-9 + /` and the padding character `=`, all **ASCII printable characters**, so it won't cause problems in JSON, email, XML, or similar contexts
3. The size expands by roughly **4/3** (3 bytes become 4 characters), and with padding it can reach 1.37×. Using it to transmit large files means pointlessly sending 33% extra traffic — don't do that

## Embedding an Image in JSON: The Full Flow

This is base64's home ground — small binary payloads attached to an interface.

```python
import json
import base64

def wrap_file(name, raw_bytes):
    return {
        "name": name,
        "size": len(raw_bytes),
        "data_b64": base64.b64encode(raw_bytes).decode("ascii"),
    }

png_header = b"\x89PNG\r\n\x1a\n" + b"\x00" * 10
msg = wrap_file("logo.png", png_header)
print(json.dumps(msg, ensure_ascii=False, indent=2))
```

Output:

```
{
  "name": "logo.png",
  "size": 14,
  "data_b64": "iVBORw0KGgoAAAAAAgAAAAA="
}
```

Reverse parsing:

```python
import json
import base64

doc = json.loads('{"name":"logo.png","size":14,"data_b64":"iVBORw0KGgoAAAAAAgAAAAA="}')
raw = base64.b64decode(doc["data_b64"])
print(raw == png_header)        # True
```

This is the standard implementation pattern for "thumbnail attached to an upload/download endpoint."

## urlsafe_b64encode: Making the Result Safe for URLs

Standard base64 uses `+` and `/`, both of which have special meanings in URLs (`+` gets interpreted as a space, `/` is a path separator). Concatenating standard base64 directly into a link will break things.

```python
import base64

raw = b"hello+/world"

std = base64.b64encode(raw).decode()
url = base64.urlsafe_b64encode(raw).decode()

print("standard: ", std)     # aGVsbG8rL3dvcmxk
print("url-safe:", url)      # aGVsbG8rL3dvcmxk
```

This example happens to produce the same output because it didn't trigger the difference. The difference lies in `+ /`: the URL-safe variant replaces `+` with `-` and `/` with `_`, so the result contains **no special characters at all** and can be concatenated directly into a query parameter.

```python
import base64

raw = b"\xff\xfe\xfd\xfc"          # high bytes — likely to trigger / and +
std = base64.b64encode(raw).decode()
url = base64.urlsafe_b64encode(raw).decode()
print("standard: ", std)
print("url-safe:", url)

# no problem at all embedding in a URL
link = "https://example.com/token=" + url
print(link)
```

Output:

```
standard:  //7//A==
url-safe: __7__A==
https://example.com/token=__7__A==
```

**Whenever a value is going into a URL, filename, or HTTP header, use `urlsafe_b64encode`** — make it muscle memory.

## Crash Site 1: Encoding a String Instead of Bytes

```python
import base64

# WRONG
base64.b64encode("Alice")       # trying to encode a string
```

Error:

```
TypeError: a bytes-like object is required, not 'str'
```

`b64encode` only accepts `bytes`. To encode text, first convert it to bytes using some encoding:

```python
text = "Alice"
encoded = base64.b64encode(text.encode("utf-8")).decode("ascii")
print(encoded)                          # QWxpY2U=

decoded = base64.b64decode(encoded).decode("utf-8")
print(decoded)                          # Alice
```

**Encoding and decoding must come in pairs: `b64encode` processes bytes and outputs bytes; to use it as a string, decode as ASCII; when restoring, first `b64decode`, then decode back to text using the original encoding.**

## Crash Site 2: base64 Is Not Encryption

This is the most common misconception. base64 is **encoding**, not encryption — anyone who gets the string can decode it back to the original in a split second.

```python
import base64

secret = "password123"
encoded = base64.b64encode(secret.encode()).decode()
print("looks messy:", encoded)            # cGFzc3dvcmQxMjM=

# but anyone can decode it
print(base64.b64decode(encoded).decode())  # password123
```

**base64 exists for "safe transport", not "confidentiality."** For confidentiality, use `secrets` / `hashlib` / `cryptography` — don't try to fake it with base64. Lesson 20 covers digests and "why you must never store passwords in plain text."

## Crash Site 3: The `=` Sign Gets Eaten by URL Processing

Standard base64 uses `=` for padding. Some older HTTP libraries or logging systems treat a trailing `=` as an "end of parameter" marker and drop it. If the decoding side receives a string missing its padding, `b64decode` raises an error:

```python
import base64

try:
    base64.b64decode("iVBOR")      # missing the final two =
except Exception as e:
    print(type(e).__name__, e)
```

Output:

```
binascii.Error Incorrect padding
```

Two countermeasures: always use `urlsafe_b64encode` for URL scenarios (it doesn't itself solve the padding problem, but its character set is safe); when faced with a string missing padding, add `=` first:

```python
import base64

def safe_b64decode(text):
    pad = 4 - len(text) % 4
    if pad != 4:
        text = text + "=" * pad
    return base64.b64decode(text)

print(safe_b64decode("iVBOR"))          # b'\x89PNG'
print(safe_b64decode("iVBORw0K"))       # b'\x89PNG\xd0\xd0'
```

## Summary

- base64 turns 3 binary bytes into 4 ASCII characters, letting you **slip bytes into text-only contexts** (JSON, email, XML, URLs)
- `b64encode` takes `bytes` and returns `bytes`; to use it as a string, call `.decode("ascii")`
- **Whenever a value is going into a URL, use `urlsafe_b64encode`** (it swaps `+`/`/` for `-`/`_`)
- The cost is roughly 1.33× size inflation — **only suitable for small data** (thumbnails, tokens, signatures, small attachments)
- base64 is encoding, not encryption — **never use it as a confidentiality mechanism**
- Remember to handle `=` padding before decoding
