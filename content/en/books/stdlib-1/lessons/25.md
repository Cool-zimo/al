# In Practice: An Order Data Validator

> This is the capstone project of chapter 5. We'll stitch `decimal`, `enum`, `dataclasses`, and `json` together into a complete order-validation system that can read, validate, and report.

## Project Goals

We need to process a batch of order data (from JSON) with these requirements:

1. Amounts use `Decimal` for exact computation — no float allowed
2. Order status uses enums — no magic strings
3. Dataclasses carry the order structure
4. Validate each order: non-negative amount, legal status, quantity greater than 0
5. Output a validation report: how many passed, how many failed, and why

## Step 1: Define the Enum and Dataclass

```python
from enum import Enum
from dataclasses import dataclass, field, asdict
from decimal import Decimal, ROUND_HALF_UP
import json

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"
    CANCELLED = "cancelled"

@dataclass
class Order:
    id: str
    amount: Decimal
    status: OrderStatus
    qty: int

    @classmethod
    def from_dict(cls, d):
        return cls(
            id=d["id"],
            amount=Decimal(str(d["amount"])),
            status=OrderStatus(d["status"]),
            qty=int(d["qty"]),
        )
```

**Note `amount=Decimal(str(d["amount"]))`** — external data is always constructed from a string, leaving no float error behind.

## Step 2: The Validation Logic

```python
from dataclasses import dataclass
from decimal import Decimal, ROUND_HALF_UP
from enum import Enum
import json

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"
    CANCELLED = "cancelled"

@dataclass
class Order:
    id: str
    amount: Decimal
    status: OrderStatus
    qty: int

    @classmethod
    def from_dict(cls, d):
        return cls(
            id=d["id"],
            amount=Decimal(str(d["amount"])),
            status=OrderStatus(d["status"]),
            qty=int(d["qty"]),
        )

def validate(order):
    """Returns (passed, reason)"""
    if order.amount < 0:
        return False, "amount cannot be negative"
    if order.qty <= 0:
        return False, "quantity must be greater than 0"
    # a paid order's amount must be >= 0.01
    if order.status == OrderStatus.PAID and order.amount < Decimal("0.01"):
        return False, "paid order amount cannot be zero"
    return True, "ok"
```

The validation function returns a tuple `(bool, str)`, which makes it easy to aggregate into a report.

## Step 3: Process a Batch of Orders and Produce a Report

```python
from decimal import Decimal, ROUND_HALF_UP
from enum import Enum
from dataclasses import dataclass, field, asdict
import json

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"
    CANCELLED = "cancelled"

@dataclass
class Order:
    id: str
    amount: Decimal
    status: OrderStatus
    qty: int

    @classmethod
    def from_dict(cls, d):
        return cls(
            id=d["id"],
            amount=Decimal(str(d["amount"])),
            status=OrderStatus(d["status"]),
            qty=int(d["qty"]),
        )

def validate(order):
    if order.amount < 0:
        return False, "amount cannot be negative"
    if order.qty <= 0:
        return False, "quantity must be greater than 0"
    if order.status == OrderStatus.PAID and order.amount < Decimal("0.01"):
        return False, "paid order amount cannot be zero"
    return True, "ok"

def process(raw_list):
    """Takes a raw list of dicts; returns (passed_list, failed_list)"""
    passed = []
    failed = []
    for d in raw_list:
        try:
            order = Order.from_dict(d)
        except (ValueError, KeyError) as e:
            failed.append({"id": d.get("id", "?"), "reason": f"invalid data format: {e}"})
            continue
        ok, reason = validate(order)
        if ok:
            passed.append(order)
        else:
            failed.append({"id": order.id, "reason": reason})
    return passed, failed

# test data
data = [
    {"id": "A001", "amount": "19.90", "status": "paid", "qty": 2},
    {"id": "A002", "amount": "-5.00", "status": "pending", "qty": 1},
    {"id": "A003", "amount": "0", "status": "paid", "qty": 3},
    {"id": "A004", "amount": "9.99", "status": "shipped", "qty": 0},
]
passed, failed = process(data)
print(f"{len(passed)} passed, {len(failed)} failed")
for f in failed:
    print("  failed:", f)
```

Output:

```
1 passed, 3 failed
  failed: {'id': 'A002', 'reason': 'amount cannot be negative'}
  failed: {'id': 'A003', 'reason': 'paid order amount cannot be zero'}
  failed: {'id': 'A004', 'reason': 'quantity must be greater than 0'}
```

## Crash Site 1: A Misspelled Status Causes a Crash

If an illegal status value sneaks into the JSON, `OrderStatus(d["status"])` raises a `ValueError`:

```python
from enum import Enum

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"

# WRONG: illegal value
# OrderStatus("unknow")      # ValueError
```

**The `process` function above already catches this with try/except** — it catches `ValueError` and `KeyError`, routing malformed records into the failed list so the whole batch doesn't go down.

## Crash Site 2: Constructing an Amount from float Loses Precision

```python
from decimal import Decimal

# WRONG
print(Decimal(19.90))     # carries float error
# correct
print(Decimal("19.90"))
```

Output:

```
19.9000000000000003552713678800500929355621337890625
19.90
```

`Order.from_dict` uses `Decimal(str(d["amount"]))`, so even if a number is passed in, it constructs correctly.

## Reporting Output: Converting to JSON

Serialise the report as JSON — note that both `Decimal` and `Enum` need converting:

```python
from decimal import Decimal, ROUND_HALF_UP
from enum import Enum
from dataclasses import dataclass, field, asdict
import json

class OrderStatus(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"
    CANCELLED = "cancelled"

@dataclass
class Order:
    id: str
    amount: Decimal
    status: OrderStatus
    qty: int

    @classmethod
    def from_dict(cls, d):
        return cls(
            id=d["id"],
            amount=Decimal(str(d["amount"])),
            status=OrderStatus(d["status"]),
            qty=int(d["qty"]),
        )

def order_to_dict(order):
    d = asdict(order)
    d["amount"] = str(order.amount)       # Decimal -> str
    d["status"] = order.status.value      # Enum -> value
    return d

passed = [Order("A001", Decimal("19.90"), OrderStatus.PAID, 2)]
report = {
    "passed": [order_to_dict(o) for o in passed],
}
print(json.dumps(report, ensure_ascii=False, indent=2))
```

Output:

```
{
  "passed": [
    {
      "id": "A001",
      "amount": "19.90",
      "status": "paid",
      "qty": 2
    }
  ]
}
```

**`asdict` only goes one level deep** — `Decimal` and `Enum` still need manual handling. This is the most common pitfall in a combined practical.

## The Complete Flow Diagram

The validator's workflow:

```
raw JSON list
   ↓ from_dict (Decimal string construction, Enum value lookup)
Order dataclass instance
   ↓ validate
(True, "ok") / (False, reason)
   ↓ split
passed list / failed list
   ↓ order_to_dict (Decimal→str, Enum→value)
JSON report
```

## Summary

- Always construct amounts with `Decimal(str(...))` for full precision
- Use `Enum`; look up with `Status(value)` and catch illegal values with try/except
- Dataclasses carry the structure; `asdict` does the first layer of serialisation
- `Decimal` and `Enum` need manual conversion to `str` and `.value` before going into JSON
- Validation returns `(bool, str)` to make report aggregation easy
- A combined practical is just the tools from the previous lessons working together, each in its own role
