# `JSONDecodeError`: Common Bad JSON and Locating Errors

> This lesson is dedicated to the question: "What do I do when parsing fails?" You will learn to read the line and column numbers in error messages and recognize the most common JSON mistakes.

## What Does the Error Look Like?

When `json.loads` encounters invalid content, it raises `json.JSONDecodeError`. Unlike ordinary exceptions, it carries **precise location information**:

```python
import json

raw = '{"name": "Alice", "age": }'
try:
    json.loads(raw)
except json.JSONDecodeError as e:
    print("Error message:", e)
    print("Line number:", e.lineno)
    print("Column number:", e.colno)
    print("Character position:", e.pos)
```

Output:

```
Error message: Expecting value: line 1 column 22 (char 21)
Line number: 1
Column number: 22
Character position: 21
```

`lineno`/`colno` are the **line and column numbers** (starting from 1), and `pos` is the **character position from the start** (starting from 0).

**The value of this information**: when your JSON has thousands of lines, the error message tells you "line 342, column 15," so you can jump straight to the problem instead of scanning with your eyes.

## Common Mistake #1: Trailing Commas

```python
import json

raw = '''
{
    "name": "Alice",
    "age": 20,    <<< there is an extra comma here
}
'''

json.loads(raw)
```

Error:

```
JSONDecodeError: Expecting property name enclosed in double quotes: line 4 column 5 (char ...)
```

**The comma after `age: 20` is illegal.** Python dictionaries allow trailing commas; JSON does not. This is the most common mistake for people transitioning from Python to JSON.

**Fix**: remove the comma after the last element, or preprocess the code (see below).

## Common Mistake #2: Single Quotes

```python
import json

raw = "{'name': 'Alice'}"
json.loads(raw)
```

Error:

```
JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```

JSON specifies that **both strings and keys must use double quotes**. Single quotes are Python style, not JSON style.

```python
# WRONG: using repr to generate a "JSON-like" string
data = str({"name": "Alice"})          # "{'name': 'Alice'}"
json.loads(data)                      # error
```

**Fix**: always generate with `json.dumps`, never `str()`.

## Common Mistake #3: Using Python's `True`/`None` as JSON

```python
import json

raw = '{"paid": True, "note": None}'
json.loads(raw)
```

Error:

```
JSONDecodeError: Expecting value: line 1 column 10 (char 9)
```

`True`/`None` must be written as `true`/`null`. Similarly, `False` → `false`.

## Common Mistake #4: Writing Comments in JSON

```python
import json

raw = '''
{
    // username
    "name": "Alice"
}
'''

json.loads(raw)
```

Error:

```
JSONDecodeError: Expecting property name enclosed in double quotes: line 3 column 5 (char ...)
```

**The JSON standard does not support comments.** Many config files (like VS Code's `settings.json` or npm's `package.json`) actually use the JSON5 or JSONC superset, but the standard `json` module does not recognize them.

**If you absolutely must have comments**, the common approach is to strip them out before parsing (write your own preprocessing, or use a third-party library like `json5`).

## Crash Site: Catching the Exception but Ignoring the Error Info, Just Saying "Format Error"

```python
# Not recommended
try:
    data = json.loads(raw)
except json.JSONDecodeError:
    print("JSON format error")
```

This kind of message is useless to the user — they have no idea which line to change.

**The correct approach**: report the line and column numbers along with the error:

```python
def parse_with_report(raw):
    try:
        return json.loads(raw)
    except json.JSONDecodeError as e:
        print(f"Line {e.lineno}, column {e.colno} error: {e.msg}")
        return None

parse_with_report('{"name": "Alice", "age": }')
# Line 1, column 22 error: Expecting value
```

## Quick Validation with `json.tool` on the Command Line

Python comes with a command-line tool that can validate and beautify JSON:

```bash
python3 -m json.tool data.json
```

If `data.json` has a syntax error, it will report the specific location and cause; if it is valid, it outputs the beautified content.

```bash
# You can also read from standard input
echo '{"name": "Alice", "age": }' | python3 -m json.tool
```

Output:

```
Expecting value: line 1 column 22 (char 21)
```

This is the fastest way to troubleshoot "why a JSON file will not read," without writing any code.

## Hands-On: Writing a Parser That Automatically Fixes Common Errors

The following function demonstrates "tolerant parsing": when it encounters common errors, it attempts to auto-correct them rather than giving up immediately.

```python
import json
import re

def forgiving_loads(raw):
    """Attempt to parse JSON; on common errors, try auto-correcting before retrying"""
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        pass

    fixed = raw

    # Fix 1: remove // line comments and /* */ block comments
    fixed = re.sub(r"//.*", "", fixed)
    fixed = re.sub(r"/\*.*?\*/", "", fixed, flags=re.DOTALL)

    # Fix 2: remove trailing commas (commas before } or ])
    fixed = re.sub(r",(\s*[}\]])", r"\1", fixed)

    # Fix 3: converting single quotes to double quotes is not done here (too risky)
    # because of the high risk of unintended side effects, leaving it to the user

    try:
        return json.loads(fixed)
    except json.JSONDecodeError as e:
        raise ValueError(f"Cannot fix; line {e.lineno}, column {e.colno} still has error: {e.msg}") from e

# Test
raw_with_comments = '''
{
    // user info
    "name": "Alice",
    "age": 20,   // trailing comma
}
'''

data = forgiving_loads(raw_with_comments)
print(data)            # {'name': 'Alice', 'age': 20}
```

**Note**: auto-fixing is risky (e.g., content inside strings may be affected), so real projects generally only perform **explicit, conservative** fixes and log the corrections — never silently swallowing errors.

## Summary

- `JSONDecodeError` carries line numbers, column numbers, and character positions — the key to locating bad JSON
- The four most common errors: **trailing commas, single quotes, `True`/`None` not lowercased, and comments**
- `repr`/`str(dict)` in Python do not produce valid JSON; always use `json.dumps`
- When reporting errors, **include the line and column numbers for the user**, not just a vague "format error"
- `python3 -m json.tool <file>` is a powerful command-line tool for quick JSON validation
- Tolerant parsing is possible, but it should be conservative and logged — never silently swallowed
