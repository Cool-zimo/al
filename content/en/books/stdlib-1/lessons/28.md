# Lesson 28 · The Data Pipeline: Cleaning and Validation

> The core principle of validation — **collect every error, not just the first one.**

## Validating Record by Record

Once the transform layer emits a list of standard dicts, the check layer inspects them one by one. A single record may have multiple problems, and we want to find all of them:

```python
from decimal import Decimal, InvalidOperation
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"

def validate(record):
    """Returns a list of errors; an empty list means passed"""
    errors = []

    # check id
    if not record.get("id"):
        errors.append("missing id")

    # check amount
    try:
        amount = Decimal(record["amount"])
    except (InvalidOperation, KeyError, TypeError):
        errors.append(f"invalid amount: {record.get('amount')}")
        amount = None

    if amount is not None and amount < 0:
        errors.append(f"amount cannot be negative: {amount}")

    # check qty
    qty = record.get("qty", 0)
    if qty <= 0:
        errors.append(f"quantity must be greater than 0: {qty}")

    # check status
    status_str = record.get("status")
    try:
        Status(status_str)
    except ValueError:
        errors.append(f"invalid status: {status_str}")

    return errors
```

**`validate` returns a list of errors rather than raising an exception** — every problem with a record gets collected, instead of bailing at the first one.

## Batch Processing: One Bucket for Passes, One for Failures

```python
from decimal import Decimal, InvalidOperation
from enum import Enum

class Status(Enum):
    PENDING = "pending"
    PAID = "paid"
    SHIPPED = "shipped"

def validate(record):
    errors = []
    if not record.get("id"):
        errors.append("missing id")
    try:
        amount = Decimal(str(record.get("amount", "")))
    except InvalidOperation:
        errors.append(f"invalid amount: {record.get('amount')}")
        amount = None
    if amount is not None and amount < 0:
        errors.append(f"amount cannot be negative: {amount}")
    qty = int(record.get("qty", 0))
    if qty <= 0:
        errors.append(f"quantity must be greater than 0: {qty}")
    status_str = record.get("status")
    try:
        Status(status_str)
    except ValueError:
        errors.append(f"invalid status: {status_str}")
    return errors

def check_all(records):
    passed = []
    failed = []
    for rec in records:
        errors = validate(rec)
        if errors:
            failed.append({"record": rec, "errors": errors})
        else:
            passed.append(rec)
    return passed, failed

# test
data = [
    {"id": "T001", "amount": "19.90", "status": "paid", "qty": 2},
    {"id": "",    "amount": "-5.00", "status": "pending", "qty": 0},
    {"id": "T003", "amount": "abc",  "status": "UNKNOWN", "qty": 1},
    {"id": "T004", "amount": "9.99", "status": "shipped", "qty": 3},
]

passed, failed = check_all(data)
print(f"{len(passed)} passed, {len(failed)} failed")
for f in failed:
    print(f"  {f['record']['id'] or '(no id)'}: {f['errors']}")
```

Output:

```
2 passed, 2 failed
  (no id): ['missing id', 'amount cannot be negative: -5.00', 'quantity must be greater than 0: 0']
  T003: ['invalid amount: abc', 'invalid status: UNKNOWN']
```

**Notice that T003 reports two errors at once** — that's the value of "collect every error." If you only reported the first, users would have to run the program repeatedly to find every issue.

## Generating the Report

Once validation is done, produce a clear report for the user:

```python
def make_report(passed, failed):
    lines = []
    lines.append(f"=== Data Validation Report ===")
    lines.append(f"total: {len(passed) + len(failed)} records")
    lines.append(f"passed: {len(passed)} records")
    lines.append(f"failed: {len(failed)} records")
    lines.append("")
    if failed:
        lines.append("--- failure details ---")
        for f in failed:
            rid = f["record"].get("id") or "(no id)"
            lines.append(f"[{rid}]")
            for err in f["errors"]:
                lines.append(f"  ✗ {err}")
    return "\n".join(lines)

print(make_report(passed, failed))
```

Output:

```
=== Data Validation Report ===
total: 4 records
passed: 2 records
failed: 2 records

--- failure details ---
[(no id)]
  ✗ missing id
  ✗ amount cannot be negative: -5.00
  ✗ quantity must be greater than 0: 0
[T003]
  ✗ invalid amount: abc
  ✗ invalid status: UNKNOWN
```

## Strict Mode vs Lenient Mode

Sometimes you want "better to process less than ingest dirty data"; other times you want "process as much as possible, set the dirty records aside." Both are valid strategies:

```python
def check_all(records, strict=False):
    passed = []
    failed = []
    for rec in records:
        errors = validate(rec)
        if errors:
            failed.append({"record": rec, "errors": errors})
            if strict:
                # strict mode: stop on the first error
                break
        else:
            passed.append(rec)
    return passed, failed
```

**Lenient by default, strict on demand** — a common design for CLI tools. Users can choose the strategy via a flag.

## Summary

- The validation function returns a list of errors, collecting every problem with a record
- Wrap `Decimal` construction in try/except to catch invalid values
- Look up status with `Enum(value)`; illegal values raise `ValueError` — catch it
- Batch processing: passes go into `passed`, failures into `failed` with their error lists
- Reports should clearly show every issue for every record
- Optional strict mode stops at the first error

## Crash Site 1: Constructing Decimal from an Empty String

```python
from decimal import Decimal, InvalidOperation

# WRONG
# Decimal("")        # InvalidOperation: Invalid literal for Decimal

# correct: check for empty first
s = ""
if s.strip():
    d = Decimal(s)
else:
    print("amount is empty")
```

**An empty string cannot be used to construct a Decimal.** Either check in advance during validation, or catch `InvalidOperation` with try/except.

## Crash Site 2: INI Numbers Are Always Strings

```python
import configparser

cp = configparser.ConfigParser()
# cp.read(...) omitted
# WRONG
# qty = cp["T001"]["qty"]   # str '2' — comparing directly with int raises TypeError
# if qty > 0: ...            # TypeError

# correct: convert the type explicitly
qty = int(cp["T001"]["qty"])
print(qty > 0)
```

**INI has no type system — every value is a str.** You must convert explicitly after reading, or type comparisons will raise `TypeError`.
