# Hands-On: A Configuration Read/Write Module

> This lesson ties together everything from Chapter 2: reading config, modifying config, writing it back to a file, with defaults and fault tolerance. When you are done, you will have a `config.py` that you can use directly in your own projects.

## A Real-World Scenario

Alice is writing a command-line tool and needs to save user preferences: default city, page size, and whether dark mode is enabled. She plans to use a JSON file for storage.

```python
import json

DEFAULT_CONFIG = {
    "city": "London",
    "page_size": 20,
    "dark_mode": False,
}

def load_config(path):
    with open(path, encoding="utf-8") as f:
        return json.load(f)

def save_config(path, config):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(config, f, ensure_ascii=False, indent=2)
```

This looks fine. But the real environment is far harsher than this.

## Crash Site #1: Crashing When the File Does Not Exist

```python
# WRONG
import json

with open("config.json", encoding="utf-8") as f:
    config = json.load(f)
# FileNotFoundError: [Errno 2] No such file or directory: 'config.json'
```

The first time a user runs the program, the config file has not been created yet. Simply calling `open` to read it will inevitably cause an error. **The correct approach: catch the exception and return a default value.**

```python
import json

DEFAULT_CONFIG = {
    "city": "London",
    "page_size": 20,
    "dark_mode": False,
}

def load_config(path):
    try:
        with open(path, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return dict(DEFAULT_CONFIG)   # return a copy of the default config
```

Why use `dict(DEFAULT_CONFIG)` instead of `DEFAULT_CONFIG`? Because if you return the original dict directly, the user's modifications will affect the global default.

## Crash Site #2: The Config File Contains Bad JSON

```python
# WRONG
# config.json contains: {"city": "London", "page_size": 20, dark_mode: False}
# The last key has no quotes, making it invalid JSON

import json
json.load(open("config.json", encoding="utf-8"))
# json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes
```

The user manually edited the config file and made a mistake. **The correct approach: catch `JSONDecodeError`, give a prompt, and fall back to the defaults.**

```python
import json
from json import JSONDecodeError

def load_config(path):
    try:
        with open(path, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return dict(DEFAULT_CONFIG)
    except JSONDecodeError:
        print("Config file format error, using default configuration")
        return dict(DEFAULT_CONFIG)
```

## Filling in Missing Fields: `get` Defaults as a Fallback

The user has an old config with only `"city"` but no `"page_size"` or `"dark_mode"`. If you read it out and use it directly, accessing a non-existent key will raise a `KeyError`.

```python
config = load_config("config.json")
config.setdefault("page_size", DEFAULT_CONFIG["page_size"])
config.setdefault("dark_mode", DEFAULT_CONFIG["dark_mode"])
```

Or, more concisely, **use the defaults as a base and let the user's config override them**:

```python
def load_config(path):
    cfg = dict(DEFAULT_CONFIG)          # start with the full set of defaults
    try:
        with open(path, encoding="utf-8") as f:
            user_cfg = json.load(f)
        cfg.update(user_cfg)            # user config overrides the defaults
    except (FileNotFoundError, JSONDecodeError):
        pass
    return cfg
```

`dict.update` only overwrites existing keys, keeping the missing ones as defaults — so no matter how many fields are missing from the user's config, it will not crash.

## The Complete Module: `config.py`

Combining all the considerations above, a usable config module looks like this:

```python
import json
from json import JSONDecodeError

DEFAULT_CONFIG = {
    "city": "London",
    "page_size": 20,
    "dark_mode": False,
}


def load_config(path):
    """Read the config. Return the default config if the file does not exist or the format is invalid."""
    cfg = dict(DEFAULT_CONFIG)
    try:
        with open(path, encoding="utf-8") as f:
            user_cfg = json.load(f)
        if isinstance(user_cfg, dict):
            cfg.update(user_cfg)
        else:
            print("Config root is not an object, using default configuration")
    except FileNotFoundError:
        pass
    except JSONDecodeError:
        print("Config file format error, using default configuration")
    return cfg


def save_config(path, config):
    """Write the config back to the file with 2-space indentation and no escaping for Chinese characters."""
    with open(path, "w", encoding="utf-8") as f:
        json.dump(config, f, ensure_ascii=False, indent=2)


def get(config, key, default=None):
    """Safe retrieval: return default if the key does not exist."""
    return config.get(key, default)


def set_and_save(path, config, key, value):
    """Change one field and write it back immediately."""
    config[key] = value
    save_config(path, config)
```

**Note the extra `isinstance(user_cfg, dict)` check in `load_config`**: if the root of the config file is a string or array, `update` will error out, so this provides a fallback.

## Usage Demonstration

```python
import os

path = "app_config.json"

# First run: file does not exist, returns the default config
cfg = load_config(path)
print(cfg)                      # {'city': 'London', 'page_size': 20, 'dark_mode': False}

# Modify the config and save
cfg["city"] = "New York"
cfg["page_size"] = 50
save_config(path, cfg)

# Read again
cfg2 = load_config(path)
print(cfg2["city"], cfg2["page_size"])   # New York 50

# Clean up the demo file
os.remove(path)
```

Output:

```
{'city': 'London', 'page_size': 20, 'dark_mode': False}
New York 50
```

The entire flow is **read → modify in memory → write back**, with persistence happening transparently to the user.

## Summary

- The core of config read/write is the pair of functions `load_config` + `save_config`
- Use `dict(DEFAULT_CONFIG)` as a base, then `update` to override — automatically filling in missing fields
- Catch `FileNotFoundError` and `JSONDecodeError` for fault tolerance without crashing
- When writing back, use `ensure_ascii=False, indent=2` so Chinese is readable and the format is clean
- The benefit of modularization: all callers use `load_config`, without having to write `try/except` everywhere
