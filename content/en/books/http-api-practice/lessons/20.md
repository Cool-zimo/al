# 20 Parsing Responses: Getting Data Out Safely

> You have `r.json()` — a deeply nested dict. This lesson is about extracting data from it **safely**: no crashes, no KeyError, no TypeError, and a plan for when the structure changes. This is the step from "it runs" to "it can ship".

## What API JSON Looks Like

Typical user info:

```json
{
  "login": "Cool-zimo",
  "id": 236305070,
  "name": "Feng Zimo",
  "public_repos": 39,
  "plan": {
    "name": "free",
    "space": 976562499
  },
  "created_at": "2025-01-01T00:00:00Z"
}
```

Typical paginated list:

```json
{
  "total_count": 1234,
  "incomplete_results": false,
  "items": [
    {"name": "repo1", "owner": {"login": "a"}},
    {"name": "repo2", "owner": {"login": "b"}}
  ]
}
```

**Characteristics**: nested, mixed types, possibly missing fields. **Your code must cope with all of that.**

## Dangerous Direct Indexing

What beginners write most often:

```python
import requests

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)
data = r.json()

print(data["name"])
print(data["plan"]["space"])
```

**What's wrong?** Three assumptions:

1. **`r.json()` always succeeds** → crashes if the response is HTML
2. **`data` always has `name`** → the field may be absent if the user didn't fill it in
3. **`data["plan"]` exists and is a dict** → it may be `null`

**Any one failing means `KeyError` or `TypeError` and a crash.**

And API fields are **frequently** missing — fields the user left blank, fields you lack permission to see, fields renamed between API versions.

## Safe Access Patterns

### Pattern one: .get() chains

```python
# ❌ Risky
space = data["plan"]["space"]

# ✅ Safe
space = data.get("plan", {}).get("space", 0)
```

> **Line-by-line**
>
> - **`data.get("plan", {})`**: returns an empty dict `{}` when `plan` is missing, **not None**
> - **`.get("space", 0)`**: continues on that result
>
> **Key point**: **the intermediate default must be something you can keep calling `.get()` on** (a dict or list), never None. Otherwise the next `.get()` raises `AttributeError`

Three levels deep gets ugly:

```python
owner = data.get("owner")
login = owner.get("login", "") if isinstance(owner, dict) else ""
```

**Better options follow.**

### Pattern two: a safe getter function (recommended)

```python
def dig(obj, *keys, default=None):
    """Walk keys level by level; return default if any level fails"""
    cur = obj
    for k in keys:
        if isinstance(cur, dict) and k in cur:      # ① dict
            cur = cur[k]
        elif isinstance(cur, list) and isinstance(k, int):  # ② list by index
            if -len(cur) <= k < len(cur):
                cur = cur[k]
            else:
                return default
        else:
            return default                           # ③ can't go further
    return cur

# Usage
data = {"plan": {"name": "free", "space": 976}}
print(dig(data, "plan", "space"))           # 976
print(dig(data, "plan", "missing"))         # None
print(dig(data, "nope", "deeper"))          # None ← no crash!
print(dig(data, "plan", "missing", default=0))   # 0
```

> **Line-by-line**
>
> - **①** current is a dict and the key exists → descend
> - **②** current is a list and the key is an int → check bounds, then descend (**negative indices supported**)
> - **③** any level fails → return the default immediately, **no exception**
>
> **Keep this function in your toolbox.** Far clearer than `.get()` chains, and it handles lists.

### Pattern three: wrap in try/except

```python
try:
    space = data["plan"]["space"]
except (KeyError, TypeError):
    space = 0
```

**When to use**: you need to know **exactly** which level you're reading and want special handling on failure.

**Drawback**: with deep nesting the `try` block grows, and **it hides real bugs** (a typo'd key name also lands silently in except).

**Advice**: **prefer `dig()`**; use try only when you need to distinguish "which level failed".

## Type Handling: Don't Trust Types

JSON has only these types:

| JSON | Python |
|---|---|
| object | `dict` |
| array | `list` |
| string | `str` |
| number | `int` or `float` |
| true/false | `True`/`False` |
| null | `None` |

**In practice**:

### 1. Numbers may arrive as strings

```python
# Some APIs return numbers as strings
{"count": "42"}          # not 42!

count = data.get("count", 0)
if isinstance(count, str):
    count = int(count)        # ① convert manually
```

> **①** Better to wrap in `try/except ValueError`, since it may not be a valid number.

### 2. null isn't an empty string

```python
{"bio": null}            → Python: None
{"bio": ""}              → Python: ""

# "has the user filled in a bio?" needs both cases
bio = data.get("bio")
if bio:                  # both None and "" are falsy
    print(bio)
else:
    print("(not provided)")
```

### 3. A single element may be an object or an array

**The nastiest case**:

```
sometimes: {"tag": "python"}
sometimes: {"tag": ["python", "http"]}
```

**Same endpoint, field type changes** (depending on the data).

**Handling**:

```python
tag = data.get("tag")

if tag is None:
    tags = []
elif isinstance(tag, str):
    tags = [tag]              # ① wrap the single value
elif isinstance(tag, list):
    tags = tag
else:
    tags = []
```

> **①** **Normalise**: whatever they give you, turn it into a list. **Downstream code then handles only one shape**
>
> **The golden rule for external data**: **normalise at the boundary; handle one shape internally**

## Validating Data: Confirm You Got the Right Thing

**Don't assume the API returned what you wanted.** Add a validation layer:

```python
import requests

def get_user(username):
    """Fetch a user; return a dict or None"""
    r = requests.get(
        f"https://api.github.com/users/{username}",
        headers={"User-Agent": "MyApp/1.0"},
        timeout=10,
    )

    if r.status_code != 200:              # ① status
        return None

    try:
        data = r.json()                    # ② may not be JSON
    except ValueError:
        return None

    if not isinstance(data, dict):         # ③ may be a list
        return None

    if "login" not in data:                # ④ key field missing
        return None

    return data

user = get_user("Cool-zimo")
if user is None:
    print("failed")
else:
    print(user["login"], user.get("public_repos", 0))
```

> **Line-by-line**
>
> - **①** Check status first. **Only 200 means success**
> - **②** `.json()` may fail (they returned an HTML error page)
> - **③** **Check the type.** Some APIs return a list on error instead of an object
> - **④** **Check the key field exists.** The cheapest way to confirm "this really is a user object"
>
> **Why so many checks**: because **if it fails here, everything downstream crashes in strange ways.** Catching it here makes the error trivial to locate

## Handling Paginated Data

The classic "fetch everything" scenario:

```python
import requests

def fetch_all_pages(base_url, params=None, max_pages=10):
    """Fetch all pages (based on a page parameter)"""
    all_items = []
    params = dict(params or {})

    for page in range(1, max_pages + 1):         # ① bounded
        params["page"] = page
        r = requests.get(base_url, params=params, timeout=10)

        if r.status_code != 200:
            print(f"page {page} failed: {r.status_code}")
            break                                 # ② stop on failure

        try:
            data = r.json()
        except ValueError:
            break

        items = data.get("items", [])
        if not items:                             # ③ empty means done
            break

        all_items.extend(items)
        print(f"page {page}: {len(items)} items")

    return all_items
```

> **Line-by-line**
>
> - **① `max_pages` is essential protection.** Without a cap, broken pagination means fetching forever
> - **② Stop on failure.** Continuing only gathers more garbage
> - **③ `if not items: break`** is the **termination condition.** The last page is usually empty or partial
>
> **Note**: pagination styles differ — some use `?page=`, some `?offset=`, some cursors, some a `Link` header. Lesson 27 covers it. **Check the docs first**

## Common Extraction Patterns

### Pattern one: list comprehension

```python
# Pull name and stars out of 100 repos
repos = r.json()
brief = [
    {"name": dig(repo, "name", default=""),
     "stars": dig(repo, "stargazers_count", default=0)}
    for repo in repos
]
```

### Pattern two: filtering

```python
# Only repos with over 100 stars
popular = [r for r in repos if dig(r, "stargazers_count", default=0) > 100]
```

### Pattern three: sorting

```python
# By stars, descending
top = sorted(repos,
             key=lambda r: dig(r, "stargazers_count", default=0),
             reverse=True)
```

### Pattern four: deduplication

```python
# Dedupe by id, preserving order
seen = set()
unique = []
for r in repos:
    rid = dig(r, "id")
    if rid is not None and rid not in seen:
        seen.add(rid)
        unique.append(r)
```

## Handling Large Responses

If a response is several MB (say 1000 records at once):

```python
import requests

r = requests.get(url, timeout=10)

print(len(r.content))        # 5000000  ← 5MB
data = r.json()              # parse in one go
```

**5MB of JSON may occupy 20-50MB once parsed into Python objects** (Python object overhead far exceeds JSON text size).

**For big data**:

1. **Paginate — fetch less at a time** (most effective)
2. **Request only needed fields** (many APIs support `?fields=`)
3. **Stream** (see the download section in Lesson 25)

## A Complete Extraction Example

Putting this lesson together:

```python
import requests

def dig(obj, *keys, default=None):
    cur = obj
    for k in keys:
        if isinstance(cur, dict) and k in cur:
            cur = cur[k]
        elif isinstance(cur, list) and isinstance(k, int) and -len(cur) <= k < len(cur):
            cur = cur[k]
        else:
            return default
    return cur

def summarize_repos(username, limit=5):
    """Fetch a user's repos and return a compact summary"""
    r = requests.get(
        f"https://api.github.com/users/{username}/repos",
        params={"per_page": 100, "sort": "updated"},
        headers={"User-Agent": "MyApp/1.0"},
        timeout=10,
    )

    if r.status_code != 200:                     # ① status
        return {"error": f"HTTP {r.status_code}"}

    try:
        repos = r.json()
    except ValueError:                            # ② parse
        return {"error": "response isn't JSON"}

    if not isinstance(repos, list):               # ③ type
        return {"error": "response isn't a list"}

    # ④ extract + normalise
    items = []
    for repo in repos:
        items.append({
            "name": dig(repo, "name", default="(unnamed)"),
            "stars": dig(repo, "stargazers_count", default=0),
            "lang": dig(repo, "language") or "unknown",   # ⑤ None counts as empty
            "url": dig(repo, "html_url", default=""),
        })

    # ⑥ sort + truncate
    items.sort(key=lambda x: x["stars"], reverse=True)
    return {"repos": items[:limit], "total": len(repos)}

result = summarize_repos("Cool-zimo")
if "error" in result:
    print("failed:", result["error"])
else:
    print(f"{result['total']} repos total; top ones:")
    for r in result["repos"]:
        print(f"  {r['name']}  ★{r['stars']}  {r['lang']}")
```

> **Line-by-line**
>
> - **①②③** Three validation layers: status / parse / type. **All caught at the boundary**
> - **④ Use `dig()` when extracting**; missing fields won't crash
> - **⑤ `or "unknown"`** handles both None and empty string
> - **⑥ Sort, then slice.** **Reversed, you'd truncate first and sort after** (wrong result)
>
> **This function runs safely** even if the API returns something odd

## Crash Site

### Crash 1: indexing nested fields directly

```python
# ❌ Wrong
owner = data["owner"]["login"]

# Actual data: {"owner": null}
# KeyError / TypeError: 'NoneType' object is not subscriptable
```

**Symptom**: fine for most users; crashes for some (incomplete data).

**Lesson**: **use `dig()` or `.get()` chains.**

### Crash 2: assuming a field's type

```python
# ❌ Wrong
tags = data["tags"]
for t in tags:            # if tags is a string, this iterates characters!
    print(t)
```

**Symptom**: when `tags` is `"python"` (a string) rather than a list, the loop prints `p`, `y`, `t`… one character at a time.

**Extremely subtle** — no error, and the output "looks about right".

**Lesson**: **normalise before iterating** (the pattern above).

### Crash 3: parsing an HTML error page

```python
r = requests.get(url, timeout=10)
data = r.json()
# JSONDecodeError: Expecting value: line 1 column 1
```

**Symptom**: the API returned HTML (maybe a 502 gateway error page) and you parsed it as JSON.

**Lesson**: **check status and Content-Type before `.json()`.** Lesson 12 covered it.

## Why This Matters for Your Code

1. **API data isn't trustworthy**: fields go missing, types change, structures evolve. **Never index directly**
2. **`dig()` is the most useful tool here** — put it in your toolbox
3. **Normalise at the boundary** (single value → list, string → number); **handle one shape internally**
4. **Validate four things**: status → parses → right type → key fields present
5. **Cap pagination**, stop on failure, end on an empty page
6. **Large responses eat memory** — reduce with pagination and field filters

## Summary

- **API JSON is deeply nested, fields may be missing, types may vary.** **Never assume**
- **Direct indexing `data["a"]["b"]` crashes** (KeyError / TypeError)
- **`.get()` chains**: `data.get("a", {}).get("b", 0)` — **intermediate defaults must be objects you can keep calling get on**
- **`dig(obj, *keys, default=None)`**: safe level-by-level access, **supports list indices**, recommended
- **Normalise**: single values and lists both become lists; numeric strings become numbers. **Do it at the boundary, handle one shape inside**
- **Validation order**: status → parses as JSON → correct type → key fields present
- **Pagination**: cap it, stop on failure, end on empty. **Different APIs paginate differently**
- **Large responses**: parsed JSON uses 3-5× the text size in memory — **paginate to lighten the load**
- ❌ Don't index nested fields directly; **don't assume a field's type** (iterating a string as a list **doesn't raise**)
