# 11 Your First Request: What Every Line Does

> This lesson does exactly one thing: send a real HTTP request, then take the code apart **line by line** — what it does, why it's written that way, and what breaks if you skip it. If you've ever "copied code without knowing why," this lesson is for you.

## Install the Library First

`requests` **doesn't ship with Python**. It's third-party and must be installed:

```bash
pip install requests
```

**Why spell that out**: many people new to Python assume `import` works for anything. In reality Python ships only the **standard library** (`os`, `json`, `time`, `uuid`, …), and `requests` isn't in it.

Confirm it worked:

```bash
python -c "import requests; print(requests.__version__)"
```

Something like `2.31.0` means you're good.

### Why requests and not the stdlib's urllib

Python's standard library **does** include something for HTTP: `urllib.request`. It's just painful:

```python
# Stdlib version (for comparison — don't memorise this)
import urllib.request
import json

req = urllib.request.Request(
    "https://api.github.com/user",
    headers={"Authorization": "Bearer xxx"},
)
with urllib.request.urlopen(req, timeout=10) as r:
    data = json.loads(r.read().decode("utf-8"))
```

Versus `requests`:

```python
import requests

r = requests.get(
    "https://api.github.com/user",
    headers={"Authorization": "Bearer xxx"},
    timeout=10,
)
data = r.json()
```

`requests`'s tagline is **"HTTP for Humans"**. Not marketing — **it handles JSON parsing, encoding detection, connection reuse, and decompression automatically**.

This book uses `requests` throughout, because what you're here to learn is **HTTP**, not the stdlib's historical baggage.

## First Code: Send the Request

```python
import requests                                  # ① bring the library in

response = requests.get(                         # ② send a GET request
    "https://api.github.com/users/Cool-zimo",    # ③ the target address
    timeout=10,                                  # ④ timeout
)

print(response.status_code)                      # ⑤ print the status code
print(response.text)                             # ⑥ print the body
```

Six lines. Now **one at a time**.

### ① `import requests`

This loads the `requests` module **into memory** so the current file can use `requests.xxx`.

**What it does not do**:
- send any network request
- open any connection
- read any config file

**It is purely "moving the toolbox within reach."**

Small fact: `requests` depends on several libraries internally — `urllib3` (the connection layer that does the real work), `certifi` (CA certificates), `charset_normalizer`/`chardet` (encoding detection), `idna` (internationalised domains). `pip` installs them all together.

### ② `requests.get(...)`

The core line. What does it do?

On the surface: send a GET request, return a `Response` object.

**In reality, at least six things happen behind that one line**:

```
1. Parse the URL
   Split "https://api.github.com/users/Cool-zimo" into:
   scheme https / host api.github.com / port 443 (default) / path /users/Cool-zimo

2. DNS lookup
   Ask a DNS server: what IP is api.github.com?
   → 140.82.112.5 (for example)

3. Open a TCP connection
   Three-way handshake to 140.82.112.5:443
   (If you've used sockets, this is socket.connect())

4. TLS handshake (because it's https)
   Verify the server certificate was issued by a trusted CA
   Negotiate a cipher, establish the encrypted channel
   ★ The little padlock in your browser's address bar comes from this step

5. Send the HTTP request
   What actually goes out is roughly:
   GET /users/Cool-zimo HTTP/1.1
   Host: api.github.com
   User-Agent: python-requests/2.31.0
   Accept-Encoding: gzip, deflate
   Accept: */*
   Connection: keep-alive
                              ← blank line
   (GET has no body)

6. Receive the response and wrap it
   Read status line, headers, body
   If Content-Encoding is gzip, decompress
   Package everything into a Response object and return
```

**Why knowing these six helps**: when a request fails, you can **locate which step broke**:

| Symptom | Usually which step |
|---|---|
| `NameResolutionError` | step 2, DNS is down |
| `ConnectionError` | step 3, can't reach it (service down / firewall) |
| `SSLError` | step 4, certificate problem |
| Hangs until timeout | step 5 went out but nothing came back, or step 6 is slow |
| 401 / 403 | everything worked; the application layer refused |

### ③ The URL as a string

```python
"https://api.github.com/users/Cool-zimo"
```

**It must be a complete URL including `https://`.**

An extremely common beginner error:

```python
# ❌ Wrong
requests.get("api.github.com/users/Cool-zimo")
# MissingSchema: Invalid URL 'api.github.com/...': No scheme supplied

# ✅ Right
requests.get("https://api.github.com/users/Cool-zimo")
```

**Why is the scheme mandatory?** Because `requests` doesn't know whether you meant http or https. **Browsers guess for you** (type `example.com` and they prepend `https://`), but a library won't — it does exactly what you said.

### ④ `timeout=10`

**The most important line in this book; it deserves its own emphasis.**

```python
requests.get(url)              # ← no timeout
requests.get(url, timeout=10)  # ← has one
```

**What happens without a timeout?**

> **The program waits forever.**

Not 10 seconds. Not 60. **Forever.** If the server never responds, your program sits on that line, motionless, until you kill it.

**Why that's a disaster**:

- A script running overnight hangs → next morning, nothing got done
- A web service: one request hangs → occupies a thread/coroutine → requests pile up → the whole service collapses
- A scraper over 1000 URLs with 5 bad ones → total failure

**What `timeout=10` means**: **wait 10 seconds.** If it isn't done in 10 seconds, raise `requests.exceptions.Timeout`.

**Once more**:

> **Every requests call must have a timeout. No exceptions.**

All code in this book carries `timeout=10`. If you remember one thing from this book, make it this.

One detail: `timeout` can also be a tuple for "connect timeout" and "read timeout" separately:

```python
requests.get(url, timeout=(3, 10))
#                         ↑   ↑
#              max 3s to connect   max 10s per read afterwards
```

**When to split them**: on bad networks with slow DNS. Usually one number is enough — it applies to both connect and read.

### ⑤ `response.status_code`

The object returned by `requests.get()` is conventionally named `response` (or `r`).

`.status_code` is an attribute, **an integer**:

```python
print(type(response.status_code))    # <class 'int'>
print(response.status_code)          # 200
```

**Why check status before content**: because a 404 or 500 body doesn't contain what you want. Confirm "this request succeeded" before processing content.

### ⑥ `response.text`

The response body, **already decoded to a string**.

For this GitHub endpoint you'll see a large chunk of JSON text.

**Note**: it's only a **string**, not a dict. `response.text["login"]` won't work. To get a dict, use `.json()` — next lesson.

## The Complete Version, Annotated

```python
import requests                                  # import the library

url = "https://api.github.com/users/Cool-zimo"   # target (get used to storing it separately)

try:                                             # begin: wrap the part that can fail
    response = requests.get(url, timeout=10)     # send; wait at most 10s

    print("status:", response.status_code)        # check success first

    if response.status_code == 200:              # only process content if it worked
        print("first 200 chars of body:")
        print(response.text[:200])               # print 200 chars only — don't flood
    else:
        print("request failed:", response.status_code)

except requests.exceptions.Timeout:              # timed out
    print("timed out; server didn't respond in 10s")

except requests.exceptions.ConnectionError:      # couldn't connect
    print("can't connect; check network or address")

except requests.exceptions.RequestException as e:  # every other requests error
    print(f"request error: {e}")
```

> **Line-by-line (structure this time, not basics)**
>
> - **`url = "..."` on its own line**: store the URL in a variable. Change the address in one place, and you can log it beforehand
> - **`try:` around the whole request**: network requests **will** fail. Without `try`, any network hiccup crashes your program
> - **status_code before text**: fixed order. Reading the status first should be muscle memory
> - **`response.text[:200]`**: print only 200 characters. **Real API responses can be tens of thousands of characters**; printing it all floods the terminal and you lose the signal
> - **except order**: specific first (`Timeout`, `ConnectionError`), general last (`RequestException`). **Reversed, the general one swallows the specific ones**
> - **`RequestException` is the parent of all requests exceptions.** Put it last as a catch-all so nothing escapes and crashes the program

## A Version You Can Verify Right Now

If you'd rather not use the GitHub API (it needs network access), use **httpbin.org** — a site built specifically for testing HTTP:

```python
import requests

try:
    r = requests.get("https://httpbin.org/get", timeout=10)
    print(r.status_code)
    print(r.text)
except requests.exceptions.RequestException as e:
    print(f"failed: {e}")
```

`httpbin.org/get` **echoes your request back to you**. You'll see something like:

```json
{
  "args": {},
  "headers": {
    "Accept": "*/*",
    "Accept-Encoding": "gzip, deflate",
    "Host": "httpbin.org",
    "User-Agent": "python-requests/2.31.0"
  },
  "origin": "1.2.3.4",
  "url": "https://httpbin.org/get"
}
```

**This response is genuinely useful** — it tells you:

- **`headers`**: which request headers the server actually received. Verify your headers took effect
- **`origin`**: your public IP
- **`url`**: the full URL the server saw

**Debugging tip**: unsure what you're actually sending? Fire one request at `httpbin.org/get` and it tells you truthfully.

## Crash Site

### Crash 1: forgetting the timeout

```python
# ❌ Wrong
r = requests.get("https://some-slow-site.com")
```

**Symptom**: the program sits there, no output, never exits. You wait five minutes wondering if it died.

**Cause**: no timeout by default. Python's sockets are blocking with no default timeout.

**How bad it gets**: on a server, every hung request occupies a thread. A hundred such requests and the service is finished.

**Lesson**: **when you type `requests.`, your hand should automatically add `timeout=`.** Make it muscle memory.

### Crash 2: building a URL without logging it

```python
# ❌ Poor
r = requests.get(f"https://api.example.com/users/{user_id}/posts/{post_id}")
```

**Symptom**: a 404, and you can't tell which part of the URL was wrong.

**Cause**: you never see the URL the f-string produced. If `user_id` has a space or non-ASCII characters, the result is malformed — and you can't see it.

**Better**:

```python
# ✅ Good
url = f"https://api.example.com/users/{user_id}/posts/{post_id}"
print(f"→ requesting: {url}")        # look at it first
r = requests.get(url, timeout=10)
```

**Lesson**: **print any URL you build.** That one log line saves enormous debugging time.

### Crash 3: printing a huge response

```python
r = requests.get("https://api.github.com/repos/psf/requests", timeout=10)
print(r.text)          # tens of thousands of characters
```

**Symptom**: the terminal scrolls for dozens of screens; Ctrl+C barely helps; you saw nothing useful.

**Better**:

```python
print(r.text[:500])                    # first 500 chars
# or
import json
print(json.dumps(r.json(), indent=2, ensure_ascii=False)[:1000])
```

**Lesson**: **always truncate before printing.** Or use `pprint`.

## Why This Matters for Your Code

1. **`timeout` is not optional.** The single must-remember item in this lesson
2. **`import` sends nothing**; `requests.get()` does the work
3. **Six steps behind one `get()`** (parse/DNS/TCP/TLS/send/receive). With that, you can work backwards from an error to the broken step
4. **URLs must include `https://`**; the library won't guess
5. **Status first, body second** — fixed order
6. **Wrap every network request in `try`**, because failure is normal, not exceptional

## Summary

- `requests` is third-party: `pip install requests`. **Far nicer than stdlib `urllib`**
- **Six steps behind one `requests.get()`**: parse URL → DNS → TCP → TLS → send → receive & wrap
- **URLs must be complete, with `https://`**
- **`timeout=10` is mandatory.** Without it, the program may hang forever
- **`timeout=(3, 10)`** sets connect and read timeouts separately
- **Check `.status_code` (int) first, then `.text` (str)**
- **Wrap network requests in `try`**, catching specific exceptions before general ones
- **`httpbin.org/get` echoes your request back** — a debugging superpower
- ❌ Don't omit timeout; don't send a built URL without logging it; don't print huge responses untruncated
