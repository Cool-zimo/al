# 21 Basic Auth: Base64 Is Not Encryption

> The simplest of the three authentication schemes, and **the most misunderstood**. Many people think "it's Base64-encoded, so it's encrypted" — no. Base64 is **plaintext written differently**. This lesson covers how it works, why HTTPS is mandatory, and how to use it in requests.

## Authentication and Authorisation Are Different

Clear these up first, since they're constantly mixed up:

| | English | Question answered |
|---|---|---|
| **Authentication** | Authentication | **Who are you?** |
| **Authorisation** | Authorization | **What can you do?** |

- Swiping a badge → **authentication** (proves you're an employee)
- The system deciding which rooms you may enter → **authorisation** (your permissions)

**HTTP's `Authorization` header is named "authorisation" but usually carries authentication credentials.** A historical naming quirk; just remember it.

**This lesson is about authentication** (proving who you are).

## How Basic Auth Works

### The flow

```
1. Client requests a protected resource
   GET /private HTTP/1.1

2. Server returns 401 and says how to authenticate
   HTTP/1.1 401 Unauthorized
   WWW-Authenticate: Basic realm="Admin Area"
                             ↑ tells the client to use Basic

3. Client joins "username:password", Base64-encodes it, resends with the header
   GET /private HTTP/1.1
   Authorization: Basic Y29vbDpzZWNyZXQ=

4. Server decodes, verifies, returns content if valid
```

### What that Base64 string is

```python
import base64

cred = "cool:secret"                              # ① username:password
encoded = base64.b64encode(cred.encode("utf-8"))  # ② Base64 encode
print(encoded)
# b'Y29vbDpzZWNyZXQ='
```

> **Line-by-line**
>
> - **①** Format is `username:password`, **one colon between**
> - **②** Base64 encodes **bytes** (hence the encode first)

**In reverse**:

```python
print(base64.b64decode("Y29vbDpzZWNyZXQ=").decode("utf-8"))
# cool:secret        ← restored instantly
```

**That's the point**:

> **Base64 is not encryption, it's encoding. Anyone who has it can restore it instantly — no key needed.**

**Then why use it?** Not for secrecy, but so **a password containing colons, newlines, or non-ASCII can safely go into an HTTP header** (headers must be ASCII).

### An important consequence

> **Basic auth over plain HTTP is broadcasting your password in the clear.**

Anyone capturing the traffic runs `base64 -d` once and has it.

**So**: **Basic auth must be used over HTTPS.** Not a suggestion — a requirement.

## Using It in requests

### Way one: the auth= parameter (recommended)

```python
import requests
from requests.auth import HTTPBasicAuth

r = requests.get(
    "https://httpbin.org/basic-auth/cool/secret",
    auth=HTTPBasicAuth("cool", "secret"),        # ① explicit form
    timeout=10,
)
print(r.status_code)        # 200
```

> **①** `HTTPBasicAuth(username, password)` — requests does the Base64 encoding and header assembly.

### Way two: tuple shorthand

```python
import requests

r = requests.get(
    "https://httpbin.org/basic-auth/cool/secret",
    auth=("cool", "secret"),        # ① a tuple, same effect
    timeout=10,
)
```

> **①** **Pass a `(username, password)` tuple and requests recognises it as Basic auth.** The most concise form.

### Verify the header it sends

```python
import requests
import base64

r = requests.get(
    "https://httpbin.org/basic-auth/cool/secret",
    auth=("cool", "secret"),
    timeout=10,
)

print(r.request.headers.get("Authorization"))
# Basic Y29vbDpzZWNyZXQ=

# Verify yourself
print(base64.b64decode("Y29vbDpzZWNyZXQ=").decode())
# cool:secret
```

**That's the proof that "Base64 isn't encryption"** — you recovered the password straight from the header.

### Way three: set the header manually (not recommended, but know it)

```python
import requests
import base64

cred = base64.b64encode(b"cool:secret").decode("ascii")
r = requests.get(
    url,
    headers={"Authorization": f"Basic {cred}"},      # note the space after "Basic"
    timeout=10,
)
```

**Why not recommended**: more lines, and you handle encoding yourself. **Just use `auth=`.**

But **it's worth knowing**, because:
- you can recognise `Authorization: Basic xxx` when debugging
- some libraries have no `auth=` parameter

### Way four: at Session level

```python
import requests

s = requests.Session()
s.auth = ("cool", "secret")        # ① set on the Session

r1 = s.get(url1, timeout=10)       # attached automatically
r2 = s.get(url2, timeout=10)       # also attached
```

> **①** `s.auth` applies to every request from that Session. **Good when a whole API uses one set of credentials**

## The WWW-Authenticate Header

A 401 response **must** carry it (Lesson 07):

```python
import requests

r = requests.get("https://httpbin.org/basic-auth/cool/secret", timeout=10)
# no credentials

print(r.status_code)                              # 401
print(r.headers.get("WWW-Authenticate"))
# Basic realm="Fake Realm"
```

**What `realm` is**: a "protected area" name. Browsers show it in the login box:

```
This site requires you to log in:
"Admin Area"  ← this is the realm
Username: ____
Password: ____
```

**Its only purpose is display.** **Meaningless to programs** — don't parse it.

## Special Characters in Passwords

```python
# Password is p@ss:word (contains a colon)
auth = ("cool", "p@ss:word")
```

**Any problem?** No. The format splits on **the first** colon:

```
cool:p@ss:word
    ↑ the first colon separates; everything after is part of the password
```

The server splits on the first colon, so colons in the password are fine.

**What about non-ASCII passwords** (Chinese characters, say)?

requests UTF-8-encodes then Base64s, so it can work. **But the server may mishandle it** — many older servers assume Latin-1.

**Advice**: **keep passwords ASCII.** Same principle as filenames in Lesson 18.

## When to Use Basic Auth

**Pros**:
- dead simple, a few lines
- supported by virtually every HTTP client and server

**Cons**:
- **the password is sent on every request** (no "log in once, get a ticket")
- credentials sit in client memory/config
- no fine-grained permissions (just "can access" or "cannot")
- no expiry mechanism

**Good for**:
- internal tools, test environments
- simple APIs (e.g. a router's admin interface)
- **simple services over HTTPS**

**Bad for**:
- user-facing products (use OAuth)
- fine-grained permissions (use tokens)

## Crash Site

### Crash 1: Basic over HTTP

```python
# ❌ Dangerous
r = requests.get("http://api.example.com/private", auth=("cool", "secret"))
```

**Symptom**: works, tests pass. Until someone on the same WiFi captures packets.

**Cause**: Base64 is encoding, not encryption; plaintext transfer broadcasts the password.

**Lesson**: **Basic auth requires HTTPS.** Check that your URL starts with `https://`.

### Crash 2: committing credentials to Git

```python
# ❌ Disaster
USERNAME = "admin"
PASSWORD = "SuperSecret123"
r = requests.get(url, auth=(USERNAME, PASSWORD), timeout=10)
```

**Symptom**: the code runs. Then you push to GitHub. **The credentials live in git history forever** — deleting later doesn't remove them from history.

**Worse**: GitHub scans automatically, and **public tokens get found and abused by bots within minutes**.

**The right way**:

```python
import os

username = os.environ.get("API_USER")      # ① read from the environment
password = os.environ.get("API_PASS")

if not username or not password:            # ② check
    raise RuntimeError("set API_USER and API_PASS environment variables")

r = requests.get(url, auth=(username, password), timeout=10)
```

> **① `os.environ.get()`** reads environment variables. **No credentials appear in the code**
> **②** Fail immediately when missing, rather than sending a request with `None`

**Setting them**:

```bash
export API_USER=admin
export API_PASS=SuperSecret123
python my_script.py
```

**Further**: use a `.env` file (with `python-dotenv`), but **add `.env` to `.gitignore`**.

### Crash 3: writing Bearer as Basic

```python
# ❌ Wrong
r = requests.get(url, auth=("token", "ghp_xxxx"), timeout=10)
# produces a Basic header, but they wanted Bearer
```

**Symptom**: 401. You verify the token is correct.

**Cause**: Lesson 14 — **`Bearer xxx` and `Basic xxx` are entirely different schemes**:

```
Basic:  Authorization: Basic base64(username:password)
Bearer: Authorization: Bearer ghp_xxxx
```

**Lesson**: **check the docs for which one.** Confusing them is a common 401 cause.

## Why This Matters for Your Code

1. **Base64 is encoding, not encryption** — the single most important point here. Anyone can reverse it
2. **Basic auth requires HTTPS**, or you're broadcasting plaintext
3. **Use the `auth=(user, pass)` tuple** — simplest
4. **`s.auth` set once applies to the whole Session**
5. **Never put credentials in code** — use environment variables
6. **Tell Basic and Bearer apart** — mixing them gives 401

## Summary

- **Authentication = who you are; authorisation = what you may do.** The `Authorization` header usually carries authentication credentials
- **Basic flow**: request → 401 + `WWW-Authenticate` → resend with `Authorization: Basic base64(user:pass)`
- **Base64 is encoding, not encryption** — reversible with no key. **It only makes the password safe for an HTTP header**
- **Basic requires HTTPS**, or it's plaintext broadcast
- **`auth=("user", "pass")` is the concise form**; `HTTPBasicAuth` is the explicit equivalent
- **`s.auth = (...)`** once, applies to the whole Session
- **`WWW-Authenticate`'s `realm` is for humans only**; don't parse it
- **Colons in passwords are fine** (split on the first); **non-ASCII passwords may break**
- ❌ **Don't use Basic over http**; **don't put credentials in code** (use `os.environ`); **don't confuse Basic with Bearer**
