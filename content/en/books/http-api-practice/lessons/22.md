# 22 Bearer Tokens: How Most APIs Authenticate Today

> Basic auth sends the password on every request, which is unacceptable in real products. Hence tokens: log in once, get a "ticket", then send only the ticket. This lesson covers the full Bearer token mechanism plus practical GitHub Personal Access Token usage — **the auth scheme you'll use most in this book**.

## Why Tokens Exist

Recall Basic auth's problems:

1. **The password goes out on every request** — the more often it crosses the network, the higher the leak risk
2. **No fine-grained control** — just "can access" or "cannot", not "may read repos but not delete them"
3. **A single credential can't be revoked** — change the password and everything using it breaks
4. **No expiry** — passwords don't expire on their own

**Tokens solve all four**:

```
1. You log in once with username/password (or generate a token on the site)
2. The server gives you a long string: ghp_xxxxxxxxxxxxxxxxxxxx
3. Every later request carries only that token, never the password
4. The token has scopes, an expiry, and can be revoked individually
```

**The apt analogy**:

> **Password = your house key** (losing it means changing locks, affecting everyone)
> **Token = a hotel key card** (room scope, expiry date, and cancelling it voids only that card)

## The Word "Bearer"

```text
Authorization: Bearer ghp_xxxxxxxxxxxx
```

**Bearer literally means "the holder".**

The semantics: **"whoever holds this token is treated as the legitimate user."**

**What does that imply**? **The token alone is the complete credential** — unlike Basic, which needs a password, or some OAuth2 flows that need signing. **Whoever has it can use it.**

**Therefore**:

> **A leaked token = a compromised account.** That's why it must be protected like a password.

**Also**: because "holder is enough", **tokens must travel over HTTPS only**, and must **never appear in a URL** (URLs get recorded in all kinds of logs — Lesson 08).

## GitHub Personal Access Tokens in Practice

Much of this book uses the GitHub API, so let's cover it properly.

### How to generate one

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
2. Click "Generate new token (classic)"
3. **Tick only the scopes you need**
4. Generate and **copy it immediately** (**once you leave the page it's never shown again**)

### Scopes: least privilege

You tick permissions at creation time. **The rule: only what you need.**

| Scope | What it allows |
|---|---|
| `repo` | read/write repositories (**most commonly needed**) |
| `public_repo` | read/write public repositories only |
| `read:user` | read user info |
| `gist` | manage Gists |
| `delete_repo` | **delete repositories** (dangerous) |

**Why least privilege matters**: if your token leaks, the damage an attacker can do is **limited to the scopes you ticked**.

**Counter-example**: ticking everything for convenience, then a leak → attacker deletes every repo you own.

### How to use it

```python
import requests
import os

token = os.environ.get("GITHUB_TOKEN")       # ① read from the environment

if not token:
    raise RuntimeError("set the GITHUB_TOKEN environment variable")

headers = {
    "Authorization": f"Bearer {token}",       # ② Bearer + space + token
    "Accept": "application/vnd.github+json",  # ③ GitHub's Accept value
    "User-Agent": "MyApp/1.0",                # ④ GitHub requires a UA
}

r = requests.get("https://api.github.com/user", headers=headers, timeout=10)
print(r.status_code)                          # 200
print(r.json()["login"])                      # your username
```

> **Line-by-line**
>
> - **① `os.environ.get()`**: Lesson 21 — **never put a token in code**
> - **②** `Bearer {token}`. **There must be a space after "Bearer"**
> - **③** GitHub's `Accept` has a special value; omit it and you get the legacy format
> - **④** **GitHub requires a UA** — without it, 403 (Lesson 14)

### Simplify with a Session (recommended)

Writing four headers every time is tedious. **Set them once on a Session**:

```python
import requests
import os

def make_github_session(token=None):
    """Create a GitHub Session with auth configured"""
    token = token or os.environ.get("GITHUB_TOKEN")
    if not token:
        raise RuntimeError("GITHUB_TOKEN required")

    s = requests.Session()
    s.headers.update({                                    # ① all four at once
        "Authorization": f"Bearer {token}",
        "Accept": "application/vnd.github+json",
        "User-Agent": "MyApp/1.0",
        "X-GitHub-Api-Version": "2022-11-28",             # ② API version
    })
    return s

s = make_github_session()

r = s.get("https://api.github.com/user", timeout=10)      # ③ no headers needed
print(r.json()["login"])

r = s.get("https://api.github.com/user/repos", timeout=10)
print(len(r.json()))
```

> **Line-by-line**
>
> - **① `s.headers.update()`**: set on the Session, **attached to every later request**
> - **②** GitHub recommends pinning the API version so future changes don't break you
> - **③** Afterwards each request needs **only the URL and timeout** — auth is automatic
>
> **This is the most common pattern in real projects.** Wrap auth in a function; keep business code clean.

## Three Common Token Formats

Different services, different formats — same usage pattern:

| Service | Format | Header |
|---|---|---|
| **GitHub PAT** | `ghp_xxxx` | `Authorization: Bearer ghp_xxxx` |
| **GitHub (legacy)** | `ghp_xxxx` | `Authorization: token ghp_xxxx` ← **note "token", not "Bearer"** |
| **GitLab** | any string | `PRIVATE-TOKEN: xxxx` ← **a custom header** |
| **Most modern APIs** | JWT | `Authorization: Bearer eyJhbG...` |

**Key lesson**:

> **Don't assume Bearer everywhere. Read the docs.**

**GitHub illustrates it best**: old docs say `token ghp_xxx`, new docs say `Bearer ghp_xxx`, **both work** — but knowing the difference saves confusion when reading others' code.

### A quick note on JWT

Anything starting with `eyJ` is usually a **JWT (JSON Web Token)**.

**What's special**: **the token itself carries information** (three dot-separated parts: header.payload.signature).

```python
import base64
import json

jwt = "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyX2lkIjoxMjN9.signature"
header_b64, payload_b64, sig = jwt.split(".")

# Add padding before decoding (base64 needs a multiple-of-4 length)
payload_b64 += "=" * (-len(payload_b64) % 4)
payload = json.loads(base64.b64decode(payload_b64))
print(payload)          # {'user_id': 123}  ← info is in the token
```

**Note**: **a JWT's payload is only Base64-encoded, not encrypted** (same as Lesson 21). **Anyone can read it.** So **never put sensitive data in a JWT**.

**A JWT's value lies in the third part, the signature** — the server can verify "I issued this and it hasn't been tampered with". But **verification needs the key, which the client doesn't have**.

## Token Lifecycle Management

### Expiry

Many tokens expire. Afterwards the server returns **401**:

```python
r = s.get(url, timeout=10)
if r.status_code == 401:
    print("token expired or invalid — get a new one")
```

**Strategy**:

- **Short-lived tokens** (hours): need **automatic refresh** (exchange a refresh token for a new one)
- **Long-lived tokens** (like GitHub classic PATs): can be set to never expire, but **that's less secure**

### Revocation

**What if a token leaks?**

1. **Revoke it in the service's admin UI immediately**
2. Generate a new one
3. Update everywhere it's used

**This is why environment variables matter** — change one variable, no code change.

### Rotation

**Security practice**: **rotate tokens periodically** (say every 90 days), even without a known leak.

**Why**: you can't know whether it leaked. Rotation bounds the window in which a leaked token is usable.

## A Complete Auth Wrapper

Putting this lesson together:

```python
import requests
import os
import logging

class ApiClient:
    """An API client wrapping auth and error handling"""

    def __init__(self, base_url, token=None, timeout=10):
        self.base_url = base_url.rstrip("/")              # ① strip trailing slash
        self.timeout = timeout
        token = token or os.environ.get("API_TOKEN")       # ② env fallback
        if not token:
            raise RuntimeError("token required: pass it or set API_TOKEN")

        self.session = requests.Session()
        self.session.headers.update({
            "Authorization": f"Bearer {token}",
            "Accept": "application/json",
            "User-Agent": "MyApp/1.0",
        })

    def get(self, path, **kwargs):
        """GET a path; return a dict or None"""
        url = f"{self.base_url}{path}"                     # ③ build the URL
        try:
            r = self.session.get(url, timeout=self.timeout, **kwargs)
        except requests.exceptions.RequestException as e:
            logging.error(f"request failed: {url} -> {e}")
            return None

        if r.status_code == 401:                           # ④ auth failure handled separately
            logging.error("token invalid or expired")
            return None

        if not r.ok:
            logging.error(f"HTTP {r.status_code}: {url}")
            return None

        try:
            return r.json()
        except ValueError:
            logging.error(f"not JSON: {url}")
            return None

    def close(self):
        self.session.close()

# Usage
client = ApiClient("https://api.github.com")
user = client.get("/user")
if user:
    print(user["login"])
client.close()
```

> **Line-by-line**
>
> - **① `rstrip("/")`**: strip the trailing slash so joining paths never yields `//`
> - **②** Prefer a passed-in token, fall back to the environment. **Both entry points supported**
> - **③** Join the URL. **Note `path` should start with `/`**
> - **④** **Handle 401 separately**, because its fix is completely different (replace the token, not the code)
>
> **The value of this class**: **auth, error handling, and logging are wrapped — business code just calls `client.get("/user")`**
>
> Lesson 30 grows this idea into a full command-line tool.

## Crash Site

### Crash 1: token in the URL

```python
# ❌ Dangerous
r = requests.get(f"https://api.example.com/data?token={token}", timeout=10)
```

**Symptom**: works. Then the token shows up in:

1. **Server access logs** (plaintext)
2. **Proxy/CDN logs**
3. **Browser history**
4. **The Referer header** (if the page has external links)

**Lesson**: **tokens go in the `Authorization` header or the body, never the URL.** Lesson 08.

### Crash 2: missing space after Bearer

```python
# ❌ Wrong
headers = {"Authorization": f"Bearer{token}"}
```

**Symptom**: 401. You check the token, paste it three times, still 401.

**Cause**: a space is needed between `Bearer` and the token.

**Lesson**: **print it.** `print(headers)` reveals it instantly.

### Crash 3: committing the token to GitHub

Same problem as Lesson 21, but **more common**, because a token looks "like a random string" rather than a password.

**Real consequence**: GitHub says **public tokens are found and abused by bots within minutes on average**.

**Lesson**: **use environment variables.** If you already pushed it, **revoke that token immediately** — revoking beats deleting code, because deletion is too late.

### Crash 4: printing the token to logs

```python
# ❌ Dangerous
print(f"requesting {url} with token {token}")
logging.debug(f"headers: {headers}")        # the token is in there!
```

**Symptom**: plaintext tokens sitting in logs. Log files usually have looser permissions, get collected, get shared.

**Lesson**: **mask credentials before printing headers**:

```python
safe_headers = {k: ("***" if k.lower() == "authorization" else v)
                for k, v in headers.items()}
print(safe_headers)
```

## Why This Matters for Your Code

1. **Tokens beat Basic**: fine-grained scopes, revocable, expirable
2. **Bearer means "the holder"** — **a leaked token is a compromised account**
3. **Don't assume Bearer everywhere**; read the docs (GitLab uses a custom header)
4. **Wrap auth in a Session** — keeps business code clean
5. **Handle 401 separately** — its fix is a new token, not new code
6. **Tokens never go in URLs, code, or logs**

## Summary

- **Tokens solve Basic's four problems**: no password every time, fine-grained scopes, individually revocable, expirable
- **Bearer = "holder"** — whoever holds it can use it, **so the token is the entire credential**
- **GitHub PAT trio**: `Authorization: Bearer xxx` + `Accept: application/vnd.github+json` + **`User-Agent` (mandatory)**
- **Use least-privilege scopes** — limit the damage if it leaks
- **Wrap with `s.headers.update()`**, then requests need only a URL
- **Formats differ per service** — don't assume Bearer (GitLab uses a `PRIVATE-TOKEN` header)
- **A JWT's payload is Base64, not encrypted** — never put sensitive data in it
- **Expired token → 401** — refresh or replace it
- ❌ **Never put tokens in URLs / code / logs**; **don't forget the space after Bearer**
