# 13 Query Parameters & Encoding: Why a Space Becomes %20

> You've seen `?q=python&page=2` in an address bar. This lesson covers what it's called, how to send it with `requests`, and **why building strings by hand goes wrong** — characters like non-ASCII text, spaces, `&`, and `=` have special meaning in URLs, and mishandling them shreds your parameters.

## What Is a Query Parameter

A complete URL:

```
https://api.github.com/search/repositories?q=python&sort=stars&order=desc
└────────────┬────────────────────────┘ └──────────────┬──────────────────┘
        base address (scheme+host+path)          query string
```

The **query string** is everything after `?`, formatted:

```
?key1=value1&key2=value2&key3=value3
```

Its job: **attach parameters to the request.** Search terms, page numbers, sort order, filters — all of it goes here.

### Why "query"

The name comes from database-era habits — what followed `?` was often a SQL query condition. Today it's far broader than querying, but the name stuck.

### Query vs path

```
/users/123          ← path: identifies "which resource"
/users?page=2       ← query: modifies "how to give it to you"
```

**General rule**:
- **Path** identifies the resource itself
- **Query** is optional decoration (paging, filtering, sorting)

So `/users/123` and `/users?page=2` are different things; don't mix them up.

## Passing Parameters With params=

`requests` takes a `params` argument — give it a **dict**:

```python
import requests

r = requests.get(                          # ①
    "https://api.github.com/search/repositories",
    params={                               # ② a dict, not a built string
        "q": "python",
        "sort": "stars",
        "order": "desc",
        "per_page": 10,
    },
    timeout=10,
)

print(r.url)                               # ③ see what it assembled
```

> **Line-by-line**
>
> - **①** `requests.get()`'s second parameter is `params`. **Pass it by keyword** — positional works but reads poorly
> - **②** **Keys are parameter names, values are parameter values.** Values may be strings, numbers, or booleans; `requests` stringifies them
> - **③** **`r.url` shows the final assembled URL.** The fastest way to verify your parameters

After running, `r.url` is roughly:

```
https://api.github.com/search/repositories?q=python&sort=stars&order=desc&per_page=10
```

**Note the number `10` became a string** — HTTP is a text protocol; URLs have no concept of "number."

### Why Not Build Strings

You absolutely can:

```python
# Works, but not recommended
url = f"https://api.github.com/search/repositories?q={keyword}&sort=stars"
r = requests.get(url, timeout=10)
```

**What's wrong with it?** Keep reading.

## URL Encoding: Not Every Character Is Allowed

### Which characters are problematic

Several characters are **reserved** in URLs:

| Character | Role in a URL |
|---|---|
| `?` | starts the query string |
| `&` | separates parameters |
| `=` | separates key from value |
| `#` | fragment identifier (anchor) |
| `/` | path separator |
| `+` | historically means space |
| `%` | introduces an encoding |

**If your parameter value contains these, it must be encoded**, or the URL parses incorrectly.

### A concrete disaster

Suppose a user searches `python & java`:

```python
# ❌ Manual concatenation
keyword = "python & java"
url = f"https://example.com/search?q={keyword}"
print(url)
# https://example.com/search?q=python & java
```

How does the server parse that?

```
q = "python "        ← stops at &
(plus a stray nameless parameter " java")
```

**The user searched "python & java"; the server received `q="python "` plus a junk parameter.** Results are completely wrong, and nothing raises an error.

### The right way

```python
# ✅ Use params=
r = requests.get(
    "https://example.com/search",
    params={"q": "python & java"},
    timeout=10,
)
print(r.url)
# https://example.com/search?q=python+%26+java
```

See how `&` became **`%26`**. That's **percent-encoding**, also called URL encoding.

## What Percent-Encoding Is

The rule is simple:

> **Write each UTF-8 byte in hexadecimal, prefixed with `%`.**

```
&    UTF-8 byte is 0x26       → %26
space UTF-8 byte is 0x20      → %20  (often + in query strings)
中    UTF-8 bytes are E4 B8 AD → %E4%B8%AD
```

So `中文` encodes to `%E4%B8%AD%E6%96%87`.

**Why this design**: `%` followed by two hex digits can't collide with any reserved character. `%` itself becomes `%25`.

### The space special case: %20 or +

A historical wrinkle:

| Context | Space becomes |
|---|---|
| In a path | `%20` |
| **In a query string** | **`+` or `%20`, both valid** |

`+` comes from the early HTML form format `application/x-www-form-urlencoded`. **Servers should accept both**, but some older ones accept only one.

`requests` uses **`+`** by default (via urlencode). That matches mainstream practice.

## Let requests Encode For You

**The most important takeaway of this lesson**:

> **Always pass parameters via `params=`; never concatenate strings by hand.**

`requests` automatically does three things:

1. Turns the dict into `k=v&k=v` form
2. Percent-encodes **both keys and values**
3. Handles None (**None is skipped** and omitted from the URL)

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={
        "q": "中文 & 空格",          # ① non-ASCII, &, space
        "n": None,                    # ② None is skipped
        "page": 2,                    # ③ numbers become strings
        "flag": True,                 # ④ booleans become "True"
    },
    timeout=10,
)
print(r.url)
```

Output is something like:

```
https://httpbin.org/get?q=%E4%B8%AD%E6%96%87+%26+%E7%A9%BA%E6%A0%BC&page=2&flag=True
```

> **Line-by-line**
>
> - **①** `中文 & 空格` is fully encoded. **`&` became `%26` and won't cut the parameter**
> - **②** **`n=None` simply doesn't appear.** Very handy — pass a pile of optional parameters unconditionally, using None for "not this time"
> - **③** `page=2` is stringified automatically
> - **④** Boolean `True` becomes `"True"` (**capital T**). **Note some APIs want lowercase `true` or `1`** — in that case pass the string yourself

## Multiple Values for One Parameter

Some APIs accept a repeated parameter:

```
?tag=python&tag=http&tag=json
```

With `params=`, pass a **list**:

```python
import requests

r = requests.get(
    "https://httpbin.org/get",
    params={"tag": ["python", "http", "json"]},    # ① a list
    timeout=10,
)
print(r.url)
# https://httpbin.org/get?tag=python&tag=http&tag=json
```

> **Line-by-line**
>
> - **①** With a list value, `requests` **repeats the key**. Exactly what the HTTP spec allows
> - **Note**: not every server supports this form. Some expect `tag=python,http,json` (comma-separated). **Check the API docs**

## What About Already-Encoded Values

If a value is **already encoded** (say, copied from another URL), encoding again double-encodes it:

```
original:   python & java
encoded 1×: python+%26+java
encoded 2×: python%2B%2526%2Bjava    ← broken
```

**`requests` encodes what you give it**, so handing it an encoded string encodes twice.

**Fix**: decode first, then let `requests` handle it:

```python
from urllib.parse import unquote

already = "python+%26+java"
decoded = unquote(already)              # 'python & java'

r = requests.get(url, params={"q": decoded}, timeout=10)   # let requests re-encode
```

## Manual Encoding: urllib.parse

Sometimes you need to encode yourself (e.g. generating a link for someone). The stdlib has tools:

```python
from urllib.parse import urlencode, quote, quote_plus

# Encode a whole dict → query string
print(urlencode({"q": "中文 & 空格", "page": 2}))
# q=%E4%B8%AD%E6%96%87+%26+%E7%A9%BA%E6%A0%BC&page=2

# Encode a single value (for a query string; space → +)
print(quote_plus("python & java"))
# python+%26+java

# Encode a single value (for a path; space → %20)
print(quote("python & java"))
# python%20%26%20java

# Decode
print(unquote("python+%26+java"))
# python & java
```

**The difference**:

| Function | Use | Space becomes |
|---|---|---|
| `urlencode(dict)` | whole dict → query string | `+` |
| `quote_plus(s)` | single value, query string | `+` |
| `quote(s)` | single value, for a **path** | `%20` |

**Which to use**:
- building a query string → `urlencode` or `quote_plus`
- building a path (a filename with spaces) → `quote`

## Crash Site

### Crash 1: non-ASCII search returns wrong results

```python
# ❌ Wrong
keyword = "中文"
url = f"https://api.example.com/search?q={keyword}"
r = requests.get(url, timeout=10)
```

**Symptom**: works sometimes; other times the server says "invalid parameter" or returns nothing. **Intermittent failures are the hardest to diagnose.**

**Cause**: **unencoded non-ASCII text placed directly in a URL.** Some servers/proxies tolerate it; some reject it outright. And CDNs or proxies in between may reprocess it.

**Lesson**: **always use `params=`.**

### Crash 2: search term cut off at &

```python
# ❌ Wrong
keyword = "python & java"          # user input
url = f"https://api.example.com/search?q={keyword}&sort=stars"
```

**Symptom**: **no error**, but the search runs for `"python "` and the sort parameter is mangled too. Users report "search is inaccurate" and you spend ages finding nothing.

**Cause**: `&` was treated as a parameter separator.

**Lesson**: **this is the most dangerous kind of bug — it doesn't raise.** The user thinks the full phrase was searched; only half was.

### Crash 3: forgetting that None is skipped

```python
# ⚠️ Note
r = requests.get(url, params={"page": None, "size": 10}, timeout=10)
print(r.url)
# https://...?size=10       ← page vanished
```

That's **usually what you want** (don't send this parameter). But if you want an **empty value** instead of skipping:

```python
r = requests.get(url, params={"page": "", "size": 10}, timeout=10)
print(r.url)
# https://...?page=&size=10    ← page= empty, still sent
```

**Difference**: `None` = omit; `""` = send an empty value.

## Why This Matters for Your Code

1. **`params=` isn't just convenience — it's a correctness issue.** Manual concatenation fails silently on special characters
2. **These bugs don't raise**, they just give wrong results. When a user says "search is off," this is suspect number one
3. **None is skipped**, so you can pass a pile of optional parameters unconditionally
4. **Values can be lists**, producing repeated keys
5. **Remember `r.url` for verification** — unsure? print it

## Summary

- The **query string** is the `k=v&k=v` part after `?`, used for parameters (paging, filtering, sorting)
- **Pass a dict with `params={...}`** and let requests encode
- **URL reserved characters** (`? & = # / + %`) must be encoded inside values, or they break the URL
- **Percent-encoding**: bytes written as `%XX`. `&` → `%26`, `中` → `%E4%B8%AD`
- **A space is `+` or `%20` in a query string, but must be `%20` in a path**
- **`requests` does three things**: stringify, percent-encode, **skip None**
- **A list value repeats the key**
- **Don't hand it pre-encoded values** (double-encoding); `unquote` first
- Manual encoding: `urlencode` / `quote_plus` / `quote`
- ❌ Don't build URLs by hand; these bugs **don't raise**, they're just wrong
