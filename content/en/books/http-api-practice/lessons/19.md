# 19 Redirects: The Traps Behind "Automatic" Following

> Lesson 12 touched on `r.history` and `r.url`. This lesson covers redirects completely: why asking for A gets you B, why your POST became a GET, and why your auth header vanished. Each of those can burn half a day.

## What a Redirect Is

Instead of content, the server says "get it elsewhere":

```text
HTTP/1.1 301 Moved Permanently
Location: https://new.example.com/page
```

Seeing a 3xx plus `Location`, the browser automatically requests the new address. **The user notices nothing** — the address bar ends up showing the new URL.

**`requests` does the same by default** (`allow_redirects=True`).

## The Five 3xx Codes

Lesson 07 listed them; here's the crucial detail — **what happens to the method after redirecting**:

| Code | Meaning | **Method after redirect** |
|---|---|---|
| **301** | Moved Permanently | ⚠️ **may become GET** (nearly all clients change it) |
| **302** | Found (temporary) | ⚠️ **may become GET** (same) |
| **303** | See Other | ✅ **must become GET** (spec mandates) |
| **307** | Temporary Redirect | ✅ **must keep the original method** |
| **308** | Permanent Redirect | ✅ **must keep the original method** |

**This table is the point of the section**, because it explains a classic mystery.

## Mystery One: My POST Became a GET

### The scenario

```python
import requests

r = requests.post(
    "http://old.example.com/api",      # note: http
    json={"name": "cool"},
    timeout=10,
)
```

If the server redirects `http` to `https` (**very common**), what happens?

```
1. You POST http://old.example.com/api with a JSON body
2. Server returns 301/302, Location: https://old.example.com/api
3. requests follows automatically — but sends GET!
4. The body is lost
```

**The server receives a GET with no body.** Your data "disappeared."

### Why

**Historical baggage.**

HTTP/1.1 (RFC 2616) says that for 301 and 302 the client **may** change POST to GET. The reasoning was practical — early browsers did it so that refreshing after "submit order" wouldn't re-submit.

But the spec says "may", not "must". **Every browser changed it anyway, so it became the de facto standard.**

### requests' actual behaviour

`requests` follows the mainstream:

- **301 / 302 / 303** → **change to GET**, drop the body
- **307 / 308** → **keep method and body**

```python
import requests

# See what actually happens
r = requests.post("https://httpbin.org/redirect-to?url=/post",
                  json={"a": 1}, timeout=10)

print(r.history[0].status_code)        # 302
print(r.request.method)                # GET  ← changed!
print(r.json()["data"])                # ""   ← body gone
```

### How to fix it

**Option one: use the final URL directly** (most recommended)

```python
# Not http — use https directly
r = requests.post("https://old.example.com/api", json={"name": "cool"}, timeout=10)
```

**Most redirect problems come from using http when they want https. Write it right from the start and the problem disappears.**

**Option two: follow manually and stay in control**

```python
r = requests.post(url, json=data, allow_redirects=False, timeout=10)

if r.status_code in (301, 302, 303, 307, 308):
    new_url = r.headers["Location"]
    r = requests.post(new_url, json=data, timeout=10)   # send as POST again
```

> **Note `requests.post`, not `requests.get`** — you choose the method; requests won't change it.

**Option three: make the server use 307/308** (if you control the server)

That's the spec-correct behaviour. **307 explicitly preserves the method**, so no data is lost.

## Mystery Two: The Auth Header Disappeared

Lessons 08 and 14 mentioned it; here it is from the redirect angle.

```python
r = requests.get(
    "https://a.com/data",
    headers={"Authorization": "Bearer xxx"},
    timeout=10,
)
# a.com redirects to b.com
# Result: 401
```

**Cause**: **when redirecting across domains, requests deliberately strips `Authorization`.**

**Why that's right**: carrying credentials meant for a.com over to b.com **hands a's password to b**. A serious security hole. So this is deliberate protection.

**Stripped alongside it**: `Cookie` (same reasoning).

### How to confirm

```python
print(len(r.history))                              # > 0 means there was a redirect
print(r.history[0].headers.get("Location"))        # where it went
print(r.request.headers.get("Authorization"))      # None ← confirmed stripped
```

### How to fix

**Option one: use the final URL** (still most recommended)

**Option two: follow manually, re-attaching auth**

```python
headers = {"Authorization": "Bearer xxx"}

r = requests.get(url, headers=headers, allow_redirects=False, timeout=10)
while r.status_code in (301, 302, 303, 307, 308):
    new_url = r.headers["Location"]
    r = requests.get(new_url, headers=headers, allow_redirects=False, timeout=10)
```

> **Risk**: a misconfigured server can loop forever. **Production code needs a cap** (see below).

## Turning Off Auto-Follow

```python
import requests

r = requests.get("http://github.com", allow_redirects=False, timeout=10)

print(r.status_code)                    # 301
print(r.headers["Location"])            # https://github.com/
print(r.text)                            # usually empty, or a short note
```

> **Line-by-line**
>
> - **`allow_redirects=False`** stops requests at the 3xx
> - **`r.text` is basically empty** — 3xx responses usually carry only a Location header
>
> **When to use it**:
> - you want to control the jump yourself
> - you want to inspect the target (e.g. phishing detection)
> - you want to avoid your auth header being stripped

## Capping Redirect Count

```python
import requests

s = requests.Session()
s.max_redirects = 5                # ① follow at most 5

r = s.get(url, timeout=10)
```

> **①** The default is 30. Thirty redirects means thirty full round trips — absurdly slow.
>
> **Set it to 5-10.** Normal sites need 1-2.

Exceeding it raises `TooManyRedirects` (Lesson 15).

## Using r.history Fully

```python
import requests

r = requests.get("http://github.com", timeout=10)

print("final status:", r.status_code)          # 200
print("final URL:", r.url)                      # https://github.com/
print("hops:", len(r.history))                  # 1

# Full chain: history + final response
chain = r.history + [r]
for i, resp in enumerate(chain):
    marker = "→" if i < len(chain) - 1 else "●"
    print(f"{marker} [{i}] {resp.status_code} {resp.url}")
```

**Output**:

```
→ [0] 301 http://github.com/
● [1] 200 https://github.com/
```

> **Line-by-line**
>
> - **`r.history + [r]`** is the standard way to get the full chain. **Remember `r` isn't in history**
> - **Each element is a full Response object** with `.status_code`, `.url`, `.headers`
>
> **Note**: intermediate responses **usually have no body** (3xx doesn't need one), so `resp.text` is empty. **Don't expect content from history**

## A Practical Redirect Tracer

```python
import requests

def trace_redirects(url, max_hops=10):
    """Manually trace a redirect chain, printing each step"""
    seen = []
    current = url

    for hop in range(max_hops):                          # ① bounded, no infinite loop
        r = requests.get(current, allow_redirects=False, timeout=10)
        seen.append((r.status_code, current))

        if r.status_code in (301, 302, 303, 307, 308):   # ② keep going
            loc = r.headers.get("Location")
            if not loc:
                print(f"  [{hop}] {r.status_code} but no Location header — stopping")
                break
            # ③ handle relative paths
            if loc.startswith("/"):
                from urllib.parse import urljoin
                loc = urljoin(current, loc)
            print(f"  [{hop}] {r.status_code} {current}")
            print(f"       → {loc}")
            current = loc
        else:
            print(f"  [{hop}] {r.status_code} {current}  (done)")
            break
    else:
        print(f"  over {max_hops} hops — possible redirect loop")

    return seen

trace_redirects("http://github.com")
```

> **Line-by-line**
>
> - **① `for ... in range(max_hops)`** is naturally bounded — **no infinite loop.** Essential protection in production code
> - **②** continue only on 3xx
> - **③ `urljoin`** handles relative paths. **`Location` may be a root-relative `/new-path`** needing a full URL
>
> **Why you'd want this**: when debugging "I asked for A but got B" it prints every step — **clearer than history**, because it records every attempt including failures

## Crash Site

### Crash 1: POST data eaten by a redirect

```python
# ❌ Problematic
r = requests.post("http://api.example.com/create", json={"name": "x"}, timeout=10)
# http → https redirect → becomes GET → data lost → empty record created, or 405
```

**Symptom**: **no error.** The server may create an empty record, or return 405 Method Not Allowed. You spend ages before noticing the wrong data was created.

**Cause**: on 301/302, POST becomes GET.

**Lesson**: **write API URLs as https directly.** That habit kills most redirect problems.

### Crash 2: infinite redirect

```python
# Server misconfigured: A → B → A → B…
r = requests.get(url, timeout=10)
# TooManyRedirects: Exceeded 30 redirects
```

**Symptom**: `TooManyRedirects`, and **it takes ages** (30 round trips).

**Common causes**:
- cookies not set: the server bounces you to login, login bounces back
- broken URL rules

**Lesson**: **set `s.max_redirects = 5`** — fail fast instead of spinning 30 times.

### Crash 3: expecting content in history

```python
r = requests.get(url, timeout=10)
for resp in r.history:
    print(resp.text)        # all empty
```

**Symptom**: a pile of empty strings; you think the code is broken.

**Cause**: **3xx responses usually have no body.** Normal — a redirect only needs a Location header.

**Lesson**: **look only at `.status_code` and `.url` in the redirect chain**, never the body.

## Why This Matters for Your Code

1. **Write API URLs as `https://`** — kills most redirect problems (POST→GET and lost auth both stem from it)
2. **301/302 turn POST into GET**, losing the body. **307/308 don't**
3. **Cross-domain redirects strip Authorization and Cookie** — security by design
4. **`allow_redirects=False` gives you control**, jump manually using `Location`
5. **`r.history` excludes the final response**; the full chain is `r.history + [r]`
6. **Cap manual tracing loops**, or they can spin forever
7. **`Location` may be relative** — resolve with `urljoin`

## Summary

- **Redirect = 3xx + Location header**; the client goes to the new address. requests follows by default
- **301/302/303 may downgrade POST to GET** (legacy; body lost); **307/308 preserve the method**
- **Cross-domain redirects strip Authorization and Cookie** — by design, not a bug
- **`allow_redirects=False`** for manual control with `r.headers["Location"]`
- **Set `s.max_redirects = 5`**; the default 30 is too slow
- **`r.history` holds only intermediates**; the final response is `r`. Full chain: `r.history + [r]`
- **3xx responses usually have no body** — don't expect content from history
- **Cap manual trace loops**; **`Location` may be relative — use `urljoin`**
- ✅ **Easiest fix of all: write API URLs as https**
