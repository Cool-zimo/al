# 12 The Response Object: 15 Parts Taken Apart

> Last lesson we got a `response`. This lesson takes it completely apart — it has a dozen-plus attributes, each mapping to an HTTP concept from Chapter 2. Afterwards you'll know what to look at first, what next, and where each attribute can bite you.

## The Whole Picture First

```python
import requests

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)

# everything below is an attribute on r
r.status_code        # ① status code
r.ok                 # ② did it succeed
r.reason             # ③ status text
r.text               # ④ body (string)
r.content            # ⑤ body (bytes)
r.json()             # ⑥ body parsed into a Python object (a method, not an attribute)
r.headers            # ⑦ response headers
r.cookies            # ⑧ cookies
r.encoding           # ⑨ encoding
r.url                # ⑩ final URL
r.history            # ⑪ redirect history
r.elapsed            # ⑫ elapsed time
r.request            # ⑬ the corresponding request object
r.is_redirect        # ⑭ whether to keep redirecting
r.is_permanent_redirect  # ⑮ whether it's a permanent redirect
```

**Note ⑥ `r.json()` has parentheses** — it's a **method** (you call it). Everything else is an **attribute** (you read it). Beginners mix this up constantly.

## ①②③ The Status Trio

```python
print(r.status_code)     # 200
print(r.ok)              # True
print(r.reason)          # 'OK'
```

| Attribute | Type | Purpose |
|---|---|---|
| `status_code` | `int` | status code. **Branch on this** |
| `ok` | `bool` | `status_code < 400`. **Quick check** |
| `reason` | `str` | status text. **For humans only — never branch on it** |

**Why not branch on `reason`?** Look:

```python
# Different servers send different text
"OK" / "ok" / "Success" / "请求成功"
```

The spec never fixes `reason` to a particular string (though `OK` is common). **And HTTP/2 removed the field entirely** — under HTTP/2, `requests` gives you a default it generated itself.

**So**: branch on `status_code` or `ok`, always.

## ④⑤⑥ Three Forms of the Body

The group most likely to cause trouble.

### r.content: bytes, always the raw truth

```python
print(type(r.content))       # <class 'bytes'>
print(len(r.content))        # 1234 (bytes)
```

**The raw bytes from the server, untouched** (except automatic decompression).

**When you must use `.content`**:

- downloading images / video / PDF / archives
- re-decoding when you hit mojibake
- computing response size

### r.text: the decoded string

```python
print(type(r.text))          # <class 'str'>
```

**Equivalent to** `r.content.decode(r.encoding)`.

**Risk**: `r.encoding` may be a bad guess (Lesson 09), so `.text` may be mojibake.

### r.json(): parsed into a Python object

```python
data = r.json()              # note the parentheses!
print(type(data))            # <class 'dict'> or <class 'list'>
print(data["login"])         # 'Cool-zimo'
```

**Decode + JSON parse in one step.**

**When it fails**:

```python
r = requests.get("https://example.com", timeout=10)
r.json()
# json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

**Cause**: you requested an HTML page whose body is `<html>...`, not JSON. `.json()` tried to parse HTML as JSON, and the first character `<` is invalid.

**Lesson**: **confirm the response really is JSON before calling `.json()`.** Two ways:

```python
# Way one: check Content-Type
if "application/json" in r.headers.get("Content-Type", ""):
    data = r.json()

# Way two: just try (more common)
try:
    data = r.json()
except ValueError:
    print("not JSON:", r.text[:200])
```

### Comparison

| | Type | Decoded? | JSON-parsed? | Use for |
|---|---|---|---|---|
| `.content` | `bytes` | ❌ | ❌ | binary files, re-decoding |
| `.text` | `str` | ✅ | ❌ | reading text, regex extraction |
| `.json()` | `dict`/`list` | ✅ | ✅ | API data |

## ⑦ r.headers: response headers

```python
print(type(r.headers))                       # requests.structures.CaseInsensitiveDict
print(r.headers["Content-Type"])             # uppercase works
print(r.headers["content-type"])             # lowercase works
print(r.headers.get("X-Not-Exist"))          # None (no exception)
```

Three points:

1. **It's a `CaseInsensitiveDict`** — header names aren't case-sensitive
2. **Use `.get()`, not `[]`** — servers don't guarantee any given header
3. **Values are strings.** `Content-Length` arrives as `"1234"`; `int()` it before arithmetic

**Most useful ones**:

```python
r.headers.get("Content-Type")        # type and charset
r.headers.get("Content-Length")      # size (may be absent)
r.headers.get("X-RateLimit-Remaining")  # GitHub rate limit left
r.headers.get("Retry-After")         # with 429, how long to wait
r.headers.get("ETag")                # content fingerprint
```

## ⑧ r.cookies

```python
print(dict(r.cookies))               # {'session': 'abc123'}
print(r.cookies.get("session"))      # 'abc123'
```

Type is `RequestsCookieJar`. **Convert with `dict()` to use it as a plain dict.**

**Note**: cookies from a single request (without a Session) aren't carried to the next request. Lesson 10 covered it — use `Session`.

## ⑨ r.encoding

```python
print(r.encoding)               # 'utf-8' (from headers, or guessed)
print(r.apparent_encoding)      # re-guessed by analysing content (attribute, no parens)
```

**The standard mojibake fix**:

```python
r.encoding = r.apparent_encoding     # change encoding
text = r.text                        # read again (re-decoded with the new one)
```

**Emphasis again**: **change it before reading `.text`.** `.text` is computed fresh on each access and isn't cached.

## ⑩ r.url: the real address after redirects

```python
r = requests.get("http://github.com", timeout=10)
print(r.url)
# 'https://github.com/'     ← note it became https
```

**You asked for http and landed on https** — the server redirected and `requests` followed.

**When it's useful**: debugging "I requested A but got B's content." `r.url` tells you where you ended up.

## ⑪ r.history: the redirect chain

```python
r = requests.get("http://github.com", timeout=10)

print(len(r.history))            # 1
for resp in r.history:
    print(resp.status_code, resp.url)
# 301 http://github.com/
```

**`r.history` is a list** of **every response in the redirect chain**, in order.

**Important detail**: **`r` itself is the final response (200)** and is *not* in history. History contains only the intermediate 3xx responses.

**When it's useful**:

- knowing "how many redirects happened" (many redirects slow things down badly)
- seeing the redirect path to find config mistakes

**You can turn off auto-follow**:

```python
r = requests.get("http://github.com", allow_redirects=False, timeout=10)
print(r.status_code)     # 301
print(r.headers["Location"])   # 'https://github.com/'
```

## ⑫ r.elapsed: how long it took

```python
print(r.elapsed)                      # 0:00:00.234567
print(r.elapsed.total_seconds())      # 0.234567 (seconds, float)
```

Type is `datetime.timedelta`. `.total_seconds()` is the convenient conversion.

**What it measures**: **time from sending the request to receiving the response headers** — **not including downloading the body**.

```python
import requests
import time

start = time.time()                    # ① time before
r = requests.get(url, timeout=10)
end = time.time()                      # ② time after

print(f"elapsed (no body download): {r.elapsed.total_seconds():.3f}s")
print(f"actual total (with body) : {end - start:.3f}s")
```

> **Line-by-line**
>
> - **① ②** Manual timing with `time.time()` gives the **full duration** (including receiving the body)
> - **`r.elapsed`** stops at the headers
> - **A big gap means**: the body is large, or download is slow. **A simple way to tell "where the time went"**

## ⑬ r.request: the request that went out

```python
print(r.request.method)          # 'GET'
print(r.request.url)             # the URL you requested
print(r.request.headers)         # the headers you sent ★ debugging gold
print(r.request.body)            # the body you sent (None for GET)
```

**`r.request` is a `PreparedRequest`** — it represents "the request that was actually sent" (after all processing and redirect fixes).

**The number one debugging tool**:

```python
# "I clearly set Authorization — why 401?"
r = requests.get(url, headers={"Authorization": "Bearer xxx"}, timeout=10)
print(r.request.headers.get("Authorization"))    # see whether it was sent
```

**The usual answer**: **Authorization was stripped on a cross-domain redirect** (Lesson 08). Printing `r.request.headers` shows it instantly.

## ⑭⑮ Redirect flags

```python
r.is_redirect                # is it a 3xx with a Location
r.is_permanent_redirect      # is it a 301
```

**When used**: you disabled auto-follow (`allow_redirects=False`) and must decide whether to follow, or whether to update a saved bookmark.

Rarely needed — `requests` follows redirects by default.

## Putting It Together: A "Check-Up" Function

This prints the useful attributes at once. **Run it first when facing any odd response**:

```python
import requests

def inspect(resp, body_limit=300):
    """Print the key information from a Response, for debugging"""
    print("=" * 50)
    print(f"status      : {resp.status_code} {resp.reason}")     # ①
    print(f"ok          : {resp.ok}")                             # ②
    print(f"final URL   : {resp.url}")                            # ③
    print(f"elapsed     : {resp.elapsed.total_seconds():.3f}s")    # ④
    print(f"encoding    : {resp.encoding}")                        # ⑤
    print(f"redirects   : {len(resp.history)}")                     # ⑥
    print("-" * 50)
    print("headers:")
    for k, v in resp.headers.items():                            # ⑦
        print(f"  {k}: {v}")
    print("-" * 50)
    ct = resp.headers.get("Content-Type", "")                    # ⑧
    if "json" in ct:
        print("body(JSON):")
        print(str(resp.json())[:body_limit])
    else:
        print("body(text):")
        print(resp.text[:body_limit])

r = requests.get("https://api.github.com/users/Cool-zimo", timeout=10)
inspect(r)
```

> **Line-by-line**
>
> - **①** Status and text together — cheapest useful output
> - **②** `ok` for a quick judgement
> - **③** `url`, not what you passed — **it changes after redirects**
> - **④** Elapsed as a float
> - **⑤** Encoding — first thing to check with mojibake
> - **⑥** An unusual redirect count signals a config problem
> - **⑦** Print all headers. **Many answers live in the headers** (rate limit left, content type, server identity)
> - **⑧** Decide how to show the body from Content-Type. **Avoids calling `.json()` on HTML**

**Keep this function in your toolbox** — it's useful from here on.

## Crash Site

### Crash 1: calling .json() on HTML

```python
# ❌ Wrong
r = requests.get("https://www.example.com", timeout=10)
data = r.json()      # JSONDecodeError
```

**Symptom**: `json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`

**Cause**: the site returns HTML. `.json()` only parses JSON.

**Lesson**: **check Content-Type first, then choose `.text` or `.json()`.**

### Crash 2: expecting r.history to include the final response

```python
r = requests.get("http://github.com", timeout=10)
for resp in r.history:
    print(resp.status_code)      # only 301 printed
# you expected 301 and 200, but got only 301
```

**Cause**: **`r` is itself the final response**; history holds only the intermediate steps.

**Lesson**: for the full chain use `r.history + [r]`.

### Crash 3: treating r.json as an attribute

```python
# ❌ Wrong
data = r.json        # missing parentheses!
print(data["login"]) # TypeError: 'method' object is not subscriptable
```

**Symptom**: `TypeError: 'method' object is not subscriptable`

**Cause**: `r.json` is the method object itself, not the call result. **It doesn't error until you use `[]`** — the error appears far from the mistake, making it hard to find.

**Lesson**: **remember `.json()` has parentheses; `.text` / `.content` don't.** The single exception among these attributes.

## Why This Matters for Your Code

1. **Fixed order**: `status_code` → `headers` → body. **Status first, headers next, body last**
2. **`.content` / `.text` / `.json()` are three forms of the same data**; wrong type means a crash
3. **`.json()` is the only one with parentheses**
4. **`r.request.headers` is the first thing to check for "my header didn't take effect"**
5. **`r.url` and `r.history` reveal redirect truth** — the answer to "I asked for A but got B"
6. **`r.elapsed` excludes body download**; time it yourself for the total

## Summary

- A `Response` has a dozen-plus attributes, each mapping to an HTTP concept
- **Status trio**: `status_code` (branch on it) / `ok` (quick check) / `reason` (**humans only**)
- **Body, three forms**: `.content` (bytes, raw) / `.text` (str, decoded) / `.json()` (**method, has parens**)
- **`.headers` is a CaseInsensitiveDict** — **use `.get()`**
- **`r.encoding` may be a guess**; for mojibake switch to `apparent_encoding` (**before reading text**)
- **`r.url` is the final address after redirects**; **`r.history` holds only intermediates, not the final response**
- **`r.elapsed` stops at the headers**, excluding body download
- **`r.request.headers` is a debugging superpower** — check it first for "my header didn't take"
- ❌ Don't call `.json()` on non-JSON; don't treat `.json` as an attribute; don't expect history to include the final response
