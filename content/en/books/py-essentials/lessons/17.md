# Advanced Parameters: Defaults, Keywords, and `*args`

> By the end of this lesson you will be able to write functions with many optional settings, and you will know the fixed order of positional and keyword arguments.

## Default Parameters: Parameters with a Built-in Value

Many functions have a parameter that **uses the same fixed value most of the time**, and only changes in a few cases. Default parameters are designed for exactly that:

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}"

print(greet("Alice"))                # Hello, Alice      uses the default
print(greet("Bob", "Hi"))            # Hi, Bob           caller supplies it
print(greet("Carol", greeting="Good morning"))  # Good morning, Carol
```

`greeting="Hello"` is a default parameter. **If the caller does not pass it, the default is used.**

This keeps function calls light: you only add an extra argument when you actually need to.

## Crash Scene: A Default Parameter That Is a Mutable Object

This is a classic trap:

```python
# WRONG
def add_item(item, lst=[]):
    lst.append(item)
    return lst

print(add_item(1))      # [1]
print(add_item(2))      # [1, 2]   ??? shouldn't this be [2]?
```

The second call somehow still contains the data from the first call!

**Why:** the default value is evaluated **once, when the function is defined**, and the same list object is reused afterwards. It is not a fresh empty list every time you call the function.

**The standard fix:** default to `None`, and create the list inside the function body:

```python
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

print(add_item(1))      # [1]
print(add_item(2))      # [2]    correct
```

> Remember this rule: **never use a mutable object (list, dict, set) as a default parameter**; use `None` instead.

## Keyword Arguments: Naming Values at the Call Site

```python
def create_user(name, age, city):
    return f"{name}, age {age}, lives in {city}"

# positional arguments: order decides who is who
create_user("Alice", 18, "Beijing")

# keyword arguments: names decide who is who
create_user(name="Alice", city="Beijing", age=18)
```

Keyword arguments have two advantages: **order no longer matters**, and the code is more readable — you can see at a glance which value belongs to which parameter.

**You can mix them, but positional arguments must come first:**

```python
create_user("Alice", age=18, city="Beijing")     # OK  positional first, keywords after
# create_user(name="Alice", 18, "Beijing")       # ERROR  positional args cannot follow keywords
```

## `*args`: Collecting Any Number of Positional Arguments

Sometimes you do not know how many arguments will arrive. `*args` gathers the leftover positional arguments into a **tuple**:

```python
def average(*args):
    return sum(args) / len(args)

print(average(80, 90, 75))          # 81.666...
print(average(100, 60, 88, 92, 77)) # 83.4
```

In `*args`, the `*` is syntax and `args` is just a convention (you could write `*numbers` and it would work too). Inside the function it is a tuple.

```python
def show_scores(title, *scores):
    print(title, "'s scores:")
    for s in scores:
        print(s)

show_scores("Alice", 90, 85, 92)
# Alice 's scores:
# 90
# 85
# 92
```

`title` consumes the first argument; everything else goes into `*scores`.

## The Iron Rule of Parameter Order

When several kinds of parameters appear in one function, **the order is fixed**:

```
positional → default → *args
```

```python
def f(a, b=2, *args):
    print(a, b, args)

f(1)             # a=1, b=2, args=()
f(1, 3)          # a=1, b=3, args=()
f(1, 3, 4, 5)    # a=1, b=3, args=(4, 5)
```

**Getting the order wrong raises SyntaxError on the spot**, so just memorise this sequence.

## Unpacking at the Call Site: Using `*` to Spread a List

`*` does not only gather parameters — it can also **spread** a list when you call a function:

```python
def add(a, b, c):
    return a + b + c

nums = [1, 2, 3]
print(add(*nums))      # same as add(1, 2, 3)  → 6
```

`*nums` splits the list into three separate arguments. `**` can spread a dictionary (as keyword arguments), but at this stage remembering `*` is enough.

## Summary

- Default parameters: `def f(x, y=10):`, the caller may omit them
- **Never use a mutable object as a default**; use `None` + create it inside the body
- Keyword arguments `f(name="Alice")`: order does not matter, more readable
- Positional arguments must come before keyword arguments
- `*args` collects leftover positional arguments into a tuple; `*` at the call site spreads a list
- Parameter order: positional → default → `*args`; wrong order means SyntaxError
