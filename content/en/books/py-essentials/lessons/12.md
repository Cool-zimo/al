# Common list operations

> By the end of this lesson you will be able to sort, concatenate, and count with lists — and you will avoid the trap of "modifying a list while iterating over it", the easiest mistake for a beginner to make.

## A few everyday operations

The previous lesson covered add/remove/change/fetch; this lesson fills in the most commonly used tools.

| Operation | Syntax | Notes |
|---|---|---|
| Sort (in place) | `list.sort()` | modifies the original list, returns None |
| Sort (new list) | `sorted(list)` | returns a new list, original untouched |
| Reverse (in place) | `list.reverse()` | modifies the original |
| Count | `list.count(value)` | how many times a value appears |
| Find position | `list.index(value)` | index of the first occurrence |
| Concatenate | `list1 + list2` | returns a new list |
| Repeat | `list * n` | repeat n times |
| Clear | `list.clear()` | equivalent to `list[:] = []` |

```python
nums = [3, 1, 4, 1, 5, 9, 2]
nums.sort()
print(nums)                 # [1, 1, 2, 3, 4, 5, 9]

print(sorted([3, 1, 2]))    # [1, 2, 3], original unchanged
print([1, 2] + [3, 4])     # [1, 2, 3, 4]
print([0] * 5)              # [0, 0, 0, 0, 0]
print([1, 2, 2, 3].count(2))  # 2
```

> `sort()` vs `sorted()`: use `sort()` when you **want to modify the original**; use `sorted()` when you **want to keep the original and get a sorted copy**.

## Crash Scene: expecting sort to return the list

```python
nums = [3, 1, 2]
result = nums.sort()
print(result)
```

```
None
```

**Why:** `list.sort()` is an **in-place sort** — it modifies `nums` directly, and the function itself returns `None`. Many people expect it to return a freshly sorted list.

**Two fixes:**

```python
# Method 1: use sort(), accepting that it modifies the original
nums = [3, 1, 2]
nums.sort()
print(nums)                 # [1, 2, 3]

# Method 2: use sorted(), for when you want a new list
nums = [3, 1, 2]
result = sorted(nums)
print(nums)                 # [3, 1, 2], untouched
print(result)               # [1, 2, 3]
```

## Converting between strings and lists

`split()` cuts a string into a list on a delimiter; `join()` glues a list back into a string — **these two are the left and right hands of text processing.**

```python
text = "apple,banana,cherry"
fruits = text.split(",")    # ['apple', 'banana', 'cherry']
print(fruits)

# glue it back
joined = "-".join(fruits)   # 'apple-banana-cherry'
print(joined)
```

You need to get used to the `join` syntax: **it is a method on the string** — the caller is "what to join with", and the argument is the list being joined.

```python
words = ["I", "love", "Python"]
sentence = "".join(words)
print(sentence)             # IlovePython

lines = ["first line", "second line", "third line"]
text = "\n".join(lines)
print(text)
```

```python
squares = [x**2 for x in range(1, 6)]
print(squares)              # [1, 4, 9, 16, 25]
```

Read it as "take each x in range(1,6), square it, and put the results into a new list". For now, just recognise it; lesson 23 will go deep.

## Copying a list: this is a trap

```python
a = [1, 2, 3]
b = a               # this makes "two names pointing at the same list"
b.append(4)
print(a)            # [1, 2, 3, 4]   a changed too!
```

**Why:** a variable is a label. `b = a` just sticks another label on the same list — it does not copy the contents.

**How to actually copy:**

```python
a = [1, 2, 3]
b = a.copy()        # method 1: copy()
b = a[:]            # method 2: slicing (common, concise)
b = list(a)         # method 3: reconstruct with list()
b.append(4)
print(a)            # [1, 2, 3], a is unchanged
print(b)            # [1, 2, 3, 4]
```

> This is an important difference between Python and many other languages. It is the payoff of the "variables are labels, not boxes" idea we planted back in lesson 2.

## Crash Scene: modifying a list while iterating over it

This is the trap beginners fall into most often:

```python
# WRONG: intended to remove all even numbers while iterating
nums = [1, 2, 3, 4, 5, 6]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)
```

You might expect `[1, 3, 5]`. The actual result is `[1, 3, 4, 5]` — **4 was skipped**.

**Why:** as you iterate, the list gets shorter, the index moves forward, elements shift left, and the next element is skipped.

**Three fixes:**

```python
nums = [1, 2, 3, 4, 5, 6]

# Method 1: iterate over a copy, modify the original
for n in nums.copy():
    if n % 2 == 0:
        nums.remove(n)

# Method 2: a list comprehension (recommended)
nums = [n for n in nums if n % 2 != 0]

# Method 3: iterate backwards (removing from the end does not affect earlier indices)
for i in range(len(nums) - 1, -1, -1):
    if nums[i] % 2 == 0:
        nums.pop(i)
```

**Remember the rule: never add to or remove from a list while iterating over it. To modify it, iterate over a copy or use a comprehension.**

## Summary

- `sort()` modifies the original and returns None; `sorted()` returns a new list and leaves the original alone
- `split()` cuts a string into a list; `"delimiter".join(list)` glues it back
- `count()` counts, `index()` finds position, `+` concatenates, `*` repeats
- `b = a` just adds another label — it does not copy; for a real copy use `copy()` or a slice `[:]`
- **Never add to or remove from a list while iterating over it**: iterate over a copy, use a comprehension, or delete from the end backwards
- The list comprehension `[expr for x in iterable]` is a signature Python idiom
