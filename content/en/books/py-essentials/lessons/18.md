# Scope: Local and Global Variables

> By the end of this lesson you will know where a variable can be used, where it cannot, and exactly when writing `global` is justified.

## Variables Defined Inside a Function Are Invisible Outside

```python
def calc():
    result = 10 + 20

calc()
print(result)
```

```
NameError: name 'result' is not defined
```

**Why:** `result` is defined inside `calc`, so it is a **local variable** — it exists only inside the function. Once the function finishes, `result` is gone.

**Scope** is the range in which a variable is visible. Python looks up variables using the **LEGB** rule:

1. **L**ocal: inside the current function
2. **E**nclosing: the outer function (only relevant with nested functions)
3. **G**lobal: at the level of the whole file (module)
4. **B**uilt-in: built into Python (`print`, `len`, `range`, and so on)

If Python cannot find a name, it keeps looking outward; once it reaches Built-in without success it raises `NameError`.

## Functions Can Read Variables From Outside

```python
tax_rate = 0.1       # global variable

def calc_price(price):
    return price * (1 + tax_rate)   # tax_rate is visible here

print(calc_price(100))     # 110.0
```

Reading a global variable is allowed. The trouble starts with **writing**.

## Crash Scene: Trying to Modify a Global Creates a Local Instead

```python
count = 0

def increment():
    count = count + 1     # WRONG

increment()
```

```
UnboundLocalError: local variable 'count' referenced before assignment
```

**Why:** the moment Python sees the assignment `count = ...`, it marks `count` as a local variable of this function. So on the right-hand side, `count + 1` is read before the local `count` has been assigned, and you get the error.

**This is not a bug, it is the rule:** **assigning to a variable inside a function makes it local, shadowing any outside variable with the same name.**

**Two ways to fix it:**

```python
# Option 1 (recommended): pass the value in and take the result back
count = 0
def increment(n):
    return n + 1

count = increment(count)

# Option 2: when you really must modify the global, declare it
count = 0
def increment():
    global count        # declare: I mean the count from outside
    count = count + 1

increment()
print(count)            # 1
```

## When You Should Actually Use `global`

**Principle: if you can use parameters and return values, do not use `global`.**

`global` lets a function secretly mutate outside state, and overuse makes code hard to follow — you no longer know who changed a value. This is called a *side effect*.

So when is it acceptable? **When you genuinely need shared state:**

- a score, a switch, or a configuration value in a game
- a counter that tracks "how many times this function was called"
- a single global configuration switch in a script

```python
call_count = 0

def greet(name):
    global call_count
    call_count += 1
    print(f"Greeting #{call_count}: Hello, {name}")

greet("Alice")
greet("Bob")
# Greeting #1: Hello, Alice
# Greeting #2: Hello, Bob
```

Tracking "how many times a function has been called" is a perfectly reasonable use of `global`.

## Same Name, No Conflict

```python
def func():
    x = 10        # local
    print(x)

x = 100           # global
func()            # 10
print(x)          # 100
```

Inside the function you use the local `x`; the global `x` outside is untouched. The two `x` variables are different things and do not interfere with each other.

## Summary

- Scope = the range where a variable is visible; lookup order is LEGB
- A function can **read** a global variable, but **assigning** to it makes it local
- `UnboundLocalError` = trying to read a local before assigning it; it is the direct consequence of "assignment makes it local"
- To modify a global, declare it with `global`, but **prefer parameters + return values**
- `global` is only appropriate for shared state: counters, switches, global config
- A local and a global with the same name are different variables and do not affect each other
