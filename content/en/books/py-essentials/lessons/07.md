# and / or / not and the rules of truthiness

> By the end of this lesson you will be able to combine several conditions, and you will understand what Python considers true and what it considers false.

## One condition is not enough

The `if age >= 18` from the previous lesson can only test one thing. In reality you usually combine conditions:

- "**and** at least 18 **and** has an ID" to register
- "is a VIP **or** spent over 200" for free shipping
- "is **not** a member" to show ads

Python connects conditions with three logical operators:

| Operator | Meaning | Rule |
|---|---|---|
| `and` | and | both sides must be true for the result to be true |
| `or` | or | if **either** side is true, the result is true |
| `not` | negation | turns true into false and false into true |

```python
age = 20
has_id = True

if age >= 18 and has_id:
    print("You can register")
else:
    print("Conditions not met")
```

`and` requires both to be true before it will print "You can register".

## Short-circuit: a clever lazy mechanism

When Python evaluates `and` and `or`, it **short-circuits** — as soon as the answer is certain, it stops:

```python
# and: if the left side is false, the right side is never evaluated
if False and (1 / 0 > 0):
    print("will not run")
# no error — the right side was never evaluated

# or: if the left side is true, the right side is never evaluated
if True or (1 / 0 > 0):
    print("will not run")
```

`1 / 0` ought to raise `ZeroDivisionError`, but because of short-circuiting it is never executed. This mechanism is often used to write "safe access" code:

```python
if name and len(name) > 3:    # if name is empty, len(name) is never evaluated
    print("name is long enough")
```

## Operator precedence

One rule to remember: **`not` is highest, `and` next, `or` lowest**. Comparison operators (`>`, `==`) outrank the logical operators.

```python
if not age > 18 and has_id:       # not first, then and
    ...

if age > 18 or score >= 60 and is_vip:   # and first
    ...
```

When in doubt, add parentheses — they are more reliable than memory:

```python
if (age > 18 or score >= 60) and is_vip:
    ...
```

## Crash Scene: the chained-comparison trap

In maths, `18 <= age <= 60` reads naturally; Python supports this kind of **chained comparison**:

```python
if 18 <= age <= 60:
    print("within the eligible range")
```

**But the following is wrong:**

```python
# WRONG: looks like it tests whether age is between 18 and 60
if age >= 18 and <= 60:      # syntax error
    print("within the eligible range")
```

`and` requires a complete condition on each side; on the right, `<= 60` is missing its left operand, so Python cannot parse it.

```python
# Correct version
if age >= 18 and age <= 60:
    print("within the eligible range")
```

> Another common trap: to test "not equal to several values" people write `if x != 1 or 2 or 3`. That is wrong — `or` does not work that way. The correct form is `if x != 1 and x != 2 and x != 3`, or — once you have learned it — `if x not in (1, 2, 3)`.

## The truthiness rules: what counts as false

The condition after `if` does not have to be `True`/`False`; **any value can be treated as true or false**:

```python
if "Alice":
    print("ran")      # will run
```

That is because **a non-empty string counts as true**. The complete rule:

| Counts as **false** (the few) | Counts as **true** (everything else) |
|---|---|
| `False` | the non-empty string `"a"` |
| `None` | non-zero numbers `1`, `-1` |
| `0`, `0.0` | non-empty containers `[1]`, `{"a": 1}` |
| `""` the empty string | |
| `[]` empty list, `{}` empty dict, `()` empty tuple, `set()` empty set | |

**Mnemonic: empty things and zeros are false; everything else is true.**

This rule is very useful:

```python
name = input("Name: ")      # user just presses Enter, getting ""
if name:
    print("Hello,", name)
else:
    print("You did not enter a name")
```

`if name:` means "if name is not empty". To check whether a list has elements: `if my_list:` is equivalent to `if len(my_list) > 0:`.

## Using not

`not` flips true and false:

```python
is_logged_in = False

if not is_logged_in:
    print("please log in first")

# combined with in
if "admin" not in users:
    print("no administrator found")
```

`not in` is the standard way to write "not inside".

## Summary

- `and` (true only if both are true), `or` (true if either is true), `not` (negation) combine conditions
- Short-circuit: `and` stops at the first false, `or` stops at the first true, avoiding unnecessary errors
- Precedence: `not` > `and` > `or`; when unsure, add parentheses
- Chained comparison `18 <= age <= 60` is legal; `and <= 60` is not
- **Empty and zero count as false**: `""`, `0`, `[]`, `{}`, `None`, `False`
- `if name:` means "is not empty" — cleaner than `len(name) > 0`
