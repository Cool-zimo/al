# Wrapping Up: Where to Go Next

> This lesson is not an ending — it is a signpost. You have finished the basics; now there are four paths you can take. Pick one and start digging deeper.

## What You Have Already Got

25 lessons, about 150 minutes each, spread across roughly 25 days. You can now:

- write variables, work with data types, do arithmetic, and process strings
- control the flow with `if`, `for`, and `while`
- store data in lists, dictionaries, tuples, and sets
- package code into reusable functions
- read and write files, import modules, and handle errors — so your programs can run, persist, and recover

That already makes you **a beginner who can write useful tool scripts**. But Python's real strength is its ecosystem — the four paths below each turn your basics into real productivity.

## Path 1: Data Analysis

**Keywords:** `pandas`, `numpy`, `matplotlib`, Jupyter

If your goal is to "let data do the talking" — analysing sales, producing reports, drawing charts — this is the most direct route.

```python
import pandas as pd

df = pd.read_csv("sales.csv")          # read a table in one line
print(df.head())                       # peek at the first rows
print(df.groupby("region")["sales"].sum()) # total sales by region

df["sales"].plot(kind="bar")            # one-liner chart
```

What to learn: **pandas DataFrames** (Python's answer to Excel), **numpy for numerical computing**, **matplotlib / seaborn for plotting**. A good next book is *Python for Data Analysis* — read it while practising on your own data.

Best for: operations, marketing, finance, research, and anyone whose day is built around spreadsheets.

## Path 2: Algorithms and Coding Practice

**Keywords:** LeetCode, data structures, complexity

If you want to join a top tech company, do backend work, or understand computers more deeply, this path is unavoidable.

```python
# classic: two-sum
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
```

What to learn: **time and space complexity**, linked lists, stacks, queues, trees, graphs, dynamic programming, binary search, sliding windows. Start LeetCode on "Easy" and do one problem a day — it beats reading ten books.

Best for: people aiming at backend, architecture, infrastructure, or algorithm engineering roles.

## Path 3: Desktop Apps and Automation

**Keywords:** `tkinter`, `PyQt`, `selenium`, `pyautogui`

If you want a program you can double-click to launch, or you want your computer to click the mouse and fill in forms for you, this is your route.

```python
import tkinter as tk

root = tk.Tk()
root.title("my first window")
label = tk.Label(root, text="Hello, world")
label.pack()
root.mainloop()
```

What to learn: `tkinter` (ships with Python, fastest to learn) or `PyQt` (more professional); on the automation side, look at `selenium` (browsers), `pyautogui` (keyboard and mouse), and `openpyxl` (Excel).

Best for: people building tools for themselves and their teammates, testers, operations engineers, and admin staff.

## Path 4: Engineering and the Web

**Keywords:** `flask`, `django`, `pytest`, Git, Linux, Docker

If you want to build websites, write backend services, and deploy code to production, take this route.

```python
from flask import Flask
app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello, world"

app.run()
```

What to learn: start with `flask` (lightweight, rewarding as soon as it runs), then `django` (full-stack); alongside them pick up **Git** (version control), **common Linux commands**, **pytest** (testing), and **Docker** (deployment).

Best for: people who want to ship products and services and join internet companies.

## General Advice for Any Path

No matter which route you choose, these four habits are worth building right now:

1. **Get into the habit of using Git.** Use Git from day one of writing code, even if it is just local commits. It is a thousand times better than crying over lost code.
2. **Read other people's code.** Find open-source projects in an area you care about on GitHub and start by reading — it is faster than grinding through documentation.
3. **Build something you actually want to use.** The contact book was your first; next try a budgeting app, a to-do list, or a script that fills forms for you — projects you genuinely use teach fastest.
4. **Accept the periods of "not getting it".** Every path has a stretch where every word is familiar but the whole thing is incomprehensible. That is the normal bridge from beginner to intermediate; push through it and it clicks.

## What Else You Should Know Beyond These 25 Lessons

| Topic | One-line explanation | When to learn it |
|---|---|---|
| Classes and OOP | bundle data and behaviour into "objects" | when you build larger projects |
| Decorators | add behaviour to a function without changing it | when reading framework source |
| Generators `yield` | produce data lazily and save memory | when processing large datasets |
| Async `async/await` | handle many I/O-bound tasks at once | when writing network services |
| Type hints | annotate variables with types so your editor catches bugs | when writing production code |
| Virtual environments `venv` | isolate dependencies per project | when installing your second third-party package |

You do not need to learn any of these right now. The most efficient approach is to come back and look them up the moment you actually need one.
