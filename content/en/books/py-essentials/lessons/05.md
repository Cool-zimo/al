# Comments and Reading Error Messages

> By the end of this lesson you will be able to write code that other people can read, and you will stop panicking the first time you see a stack trace — because it is literally telling you which line to fix.

## Comments: written for the you of six months from now

Code is for the machine to run; comments are for humans to read. In Python, anything after `#` on a line is a comment and is completely ignored:

```python
# This is a single-line comment
name = "Alice"      # you can also put a comment after code to explain that line
```

For a longer comment, wrap it in triple quotes (technically this is an unassigned string, but it is commonly used as a comment):

```python
"""
This function calculates a user's BMI.
Parameters: height in metres, weight in kilograms
Returns: the BMI value
"""
```

**When should you write comments?** Three cases:

1. **Explain "why", not "what".** The code itself already says what it does.
   ```python
   # Bad: multiplies the price by 0.9
   price = price * 0.9

   # Good: members get a 10% discount
   price = price * 0.9
   ```
2. **Signpost complex logic**, such as a tricky algorithmic step.
3. **Temporarily disable a line of code** while debugging — known as "commenting out".

> Conversely, skip pointless comments: `i = i + 1  # adds 1 to i` says nothing at all.

## Error messages are not the enemy

Beginners are most afraid of the red text. In reality Python's error messages (tracebacks) are among the friendliest in the world — **they tell you exactly where the error is, what the error is, and why**.

A complete error looks like this:

```
Traceback (most recent call last):
  File "demo.py", line 3, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero
```

Four pieces of information, read from top to bottom:

1. **Starts with `Traceback`**: "now I will walk back through the error"
2. **`File "demo.py", line 3`**: **the file and line number where it broke**. This is the most useful line — click it and fix it
3. **`print(10 / 0)`**: what the offending line looks like, to remind you of the context
4. **`ZeroDivisionError: division by zero`**: **the error type plus a one-line explanation**

**The right way to read an error:** first find the `line 3` line (where to go), then read the last line (what went wrong).

## Three high-frequency errors

### 1. SyntaxError: you wrote it wrong

```python
print("Hello"
```

```
  File "demo.py", line 1
    print("Hello"
          ^
SyntaxError: unexpected EOF while parsing
```

**Signature:** the `^` arrow points at the problem. Usually it is a **missing parenthesis, missing quote, or missing colon**.

**Common causes:**
- A quote written only on one side: `print("Hello)`
- A parenthesis written only on one side
- A missing colon `:` after `if`, `for`, or `def`
- Chinese punctuation used by mistake

### 2. NameError: you used a name that does not exist

```python
print(message)
```

```
NameError: name 'message' is not defined
```

**Signature:** `not defined`. Usually it is a **typo, a Chinese quote, or using a variable before assigning to it**.

### 3. TypeError: the types do not match

```python
print("Age: " + 18)
```

```
TypeError: can only concatenate str (not "int") to str
```

**Signature:** `unsupported operand` or `must be ... not ...`. Usually you **tried to do an operation between a string and a number** — just convert one of the types.

## Crash Scene: mixing tabs and spaces for indentation

```python
def greet():
    print("Hello")    # this line uses a tab
    print("World")    # this line uses 4 spaces
```

```
TabError: inconsistent use of tabs and spaces in indentation
```

**Why:** Python uses indentation to decide which lines belong to which block. Tabs and spaces are treated as different widths of indentation, so mixing them is an error.

**How to fix:** VSCode's status bar at the bottom shows whether the current file uses tabs or spaces — click it to toggle. The easiest permanent fix: turn on `Editor: Insert Spaces` in settings and set `Tab Size = 4`. Then pressing Tab actually inserts 4 spaces, and you will never mix them again.

> While we are here: `IndentationError: expected an indented block` means "you should have indented but did not", for example leaving the body after an `if` empty. Python does not allow empty blocks; the placeholder is `pass`.

## Deliberately make an error

The code below is intentionally wrong — run it and see:

```python
# WRONG
name = input("What is your name? ")
print("Hello" name)     # missing the comma — this will raise SyntaxError
```

The error message will point precisely at the line `print("Hello" name)` and tell you the syntax is wrong. Add the comma and it works: `print("Hello", name)`.

## Summary

- `#` starts a single-line comment; `"""..."""` wraps a multi-line comment
- Comments explain "why", not "what"; use them to silence lines while debugging
- Reading an error in three steps: **which line → what error → why**
- Three common errors: `SyntaxError` (syntax), `NameError` (name), `TypeError` (type)
- `TabError` and `IndentationError` are both indentation problems; 4 spaces is the safe default
- In VSCode, enable Insert Spaces with Tab Size 4 and you are done for good
