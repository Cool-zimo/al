# Reading and Writing Files

> By the end of this lesson you will be able to save data to a file and read it back, so your programs finally have a memory.

## Without Files, Everything Is Gone After a Restart

Up to the previous lesson, all program data lived in memory — close the program and everything resets to zero. Files are the bridge between your program and persistent storage.

Python uses the built-in function `open()` to work with files. The core operation has three steps: **open -> read or write -> close**.

```python
f = open("notes.txt", "w", encoding="utf-8")
f.write("learned file I/O today\n")
f.write("second line of content\n")
f.close()
```

The three key arguments to `open`:

- **filename**: `"notes.txt"`
- **mode**: `"w"` to write, `"r"` to read, `"a"` to append
- **encoding**: always write `encoding="utf-8"` explicitly, especially when working with non-ASCII text

## The Three Modes

| Mode | Meaning | File does not exist | File already exists |
|---|---|---|---|
| `r` | read-only (default) | error | opens |
| `w` | write | created | **truncated, then written** |
| `a` | append | created | writing continues at the end |
| `r+` | read + write | error | opens |

> WARNING: **mode `"w"` wipes the original file.** Use the wrong mode and your data is gone, so before writing always decide whether you intend to overwrite or append.

## The `with` Statement: The Recommended Style

Writing `open` + `close` by hand has a hidden risk: if something goes wrong during reading or writing, the later `close()` might never run, and the file stays open.

**`with` closes the file for you automatically:**

```python
with open("notes.txt", "w", encoding="utf-8") as f:
    f.write("first line\n")
    f.write("second line\n")
# once Python leaves this indented block, the file is closed automatically, errors or not
```

`with` is the standard Python idiom for any resource that needs cleanup. **Use it for files, networks, databases — everything.** Learn this template and you will never need to call `close()` again.

## Three Ways to Read a File

```python
# read everything at once
with open("notes.txt", "r", encoding="utf-8") as f:
    content = f.read()
print(content)

# read into a list of lines (each line keeps its newline)
with open("notes.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()
print(lines)      # ['first line\n', 'second line\n']

# iterate line by line (most common, memory-friendly)
with open("notes.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())   # strip removes the trailing newline on each line
```

**Iterating line by line** is the most memory-efficient approach for large files — only one line lives in memory at a time instead of the whole file.

## Appending to a Log File

```python
with open("app.log", "a", encoding="utf-8") as f:
    f.write("2026-09-27 10:00 user logged in\n")
    f.write("2026-09-27 10:05 user placed an order\n")
```

Using mode `"a"` adds to the end every time without overwriting history. This is the standard pattern for log files.

## Crash Scene: Garbled Output Without `encoding`

```python
# WRONG (especially common on Windows)
with open("notes.txt", "r") as f:
    print(f.read())
```

The output is a string of mojibake, or you get `UnicodeDecodeError` outright.

**Why:** Windows defaults to GBK, while your file was saved as UTF-8. With no `encoding` specified, Python decodes using the system default, which does not match, so you get garbage or an error.

**The fix:** explicitly set `encoding="utf-8"` on both the read side and the write side. This is an iron rule of cross-platform development.

## Crash Scene: Reading a File That Does Not Exist

```python
with open("missing.txt", "r") as f:
    print(f.read())
```

```
FileNotFoundError: [Errno 2] No such file or directory
```

**How to guard against it:** use `try/except` (proper exception handling is covered in lesson 21, but here is the minimal version):

```python
try:
    with open("missing.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("file not found, skipping")
```

## A Complete Example: A Contact List on Disk

```python
# write the contact list
with open("contacts.txt", "w", encoding="utf-8") as f:
    f.write("Alice,13800138000\n")
    f.write("Bob,13900139000\n")

# read and parse it back
with open("contacts.txt", "r", encoding="utf-8") as f:
    for line in f:
        name, phone = line.strip().split(",")
        print(f"{name}'s phone is {phone}")
```

`split(",")` cuts each line at the comma, and `name, phone = ...` unpacks the two pieces into two variables. This write-CSV / read-CSV pattern is the most basic form of data persistence in real systems.

## Summary

- open -> read or write -> close; `open(filename, mode, encoding="utf-8")`
- Three modes: `r` for reading, `w` for writing (truncates), `a` for appending
- **`"w"` wipes the original file**, so think before you use it
- **Use the `with` statement to close files automatically**; this is the standard style
- Three ways to read: `read()` for everything, `readlines()` for a list, iterate line by line (most memory-efficient)
- Always set `encoding="utf-8"` on both sides to avoid mojibake across platforms
- A missing file raises `FileNotFoundError`, which you can handle with try/except
