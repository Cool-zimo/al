# Groups and Capturing

> This lesson answers: "I matched it, but I only want to take out part of it." `()` for capturing, `(?:)` for non-capturing, `(?P<name>)` for named groups—and the **single most classic regex trap**: `findall` returns only the groups when groups are present.

## Parentheses, Identity #1: Capturing Groups

`()` in regex means "bundle this piece together." The part wrapped in parentheses is stored separately once the match succeeds, so you can pull it out later.

```python
import re

text = "Order DD20260927001 amount £299.5"
m = re.search(r'DD(\d{8})(\d{3}) amount (\d+\.?\d*)', text)
print("whole:", m.group(0))      # full match
print("group 1:", m.group(1))     # first left paren
print("group 2:", m.group(2))     # second left paren
print("group 3:", m.group(3))     # third left paren
print("all groups:", m.groups())
```

Output:

```
whole: DD20260927001001 amount £299.5
group 1: 20260927
group 2: 001
group 3: 299.5
all groups: ('20260927', '001', '299.5')
```

`.group(0)` or `.group()` returns the full match. `.group(1)` returns the group at the first left parenthesis, and so on. `.groups()` packs every group into a tuple at once.

**This is "capturing"**: parentheses affect not only the match, but also store that portion for you to use afterward.

## Crash Site: findall Returns Only Groups When Groups Are Present

This is **the most famous** regex trap—almost no beginner avoids it. Alice wants to extract "time + level" from a log:

```python
import re

log = "10:20 ERROR service crashed\n11:05 INFO startup complete"
# WRONG: expected the whole match back
result = re.findall(r'(\d{2}:\d{2}) (\w+)', log)
print(result)
```

Output:

```
[('10:20', 'ERROR'), ('11:05', 'INFO')]
```

She expected `['10:20 ERROR', '11:05 INFO']`, but got **a list of tuples of groups** instead.

**The rule**: when `findall` detects **capturing groups** in the pattern, it returns only the group contents. One group → list of strings; multiple groups → list of tuples. To get the whole match, wrap the whole pattern in one more pair of parentheses, or simply remove the inner parentheses.

```python
import re

log = "10:20 ERROR service crashed\n11:05 INFO startup complete"

# Solution 1: remove inner parens so findall returns the whole match
print("solution 1:", re.findall(r'\d{2}:\d{2} \w+', log))

# Solution 2: keep the groups and accept the tuples
print("solution 2:", re.findall(r'(\d{2}:\d{2}) (\w+)', log))
```

Output:

```
solution 1: ['10:20 ERROR', '11:05 INFO']
solution 2: [('10:20', 'ERROR'), ('11:05', 'INFO')]
```

## Non-Capturing Groups (?:)

Sometimes you add parentheses only so a quantifier can apply to a chunk—you don't actually want to capture it. For example, matching "http or https":

```python
import re

urls = "http://a.com and https://b.com"

# Capturing groups: an extra layer we don't need
print(re.findall(r'(https?)://(\w+\.com)', urls))

# Non-capturing (?:): capture only the domain we actually want
print(re.findall(r'https?://(?:www\.)?(\w+\.com)', urls))
```

Output:

```
[('http', 'a.com'), ('https', 'b.com')]
['a.com', 'b.com']
```

Read `?:` as: **don't store it, just group it.** It doesn't change the matching behavior, only "whether to capture." Inside `findall` it's a lifesaver—it cleans up cases where you "must group but don't want it in the result."

## Named Groups (?P<name>)

Once you have many groups, counting `.group(1)`, `.group(2)` becomes error-prone. Named groups give each group its own name:

```python
import re

log = "2026-09-28 10:20:35 ERROR database connection failed"
pat = r'(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) (?P<level>\w+) (?P<msg>.*)'
m = re.search(pat, log)

print("level:", m.group('level'))
print("time:", m.group('time'))
print("all named groups:", m.groupdict())
```

Output:

```
level: ERROR
date: 2026-09-28
time: 10:20:35
msg: database connection failed
```

`.groupdict()` packs all named groups into a dictionary. This is wonderfully handy when parsing structured text like logs and config files—and far more readable than counting parentheses.

## Crash Site: Miscounting group(1) in Nested Groups

```python
import re

text = "Order (DD20260927-001) complete"
m = re.search(r'\((\w+(\d{8})-(\d+))\)', text)
print("group(0):", m.group(0))
print("group(1):", m.group(1))
print("group(2):", m.group(2))
print("group(3):", m.group(3))
```

Output:

```
group(0): (DD20260927-001)
group(1): DD20260927-001
group(2): 20260927
group(3): 001
```

`group(1)` is the content of the **outermost left parenthesis**, not "the first thing that looks like content." With nesting, groups are numbered by the **order of the left parentheses**. Named groups save you here: label `(?P<order>...)`, `(?P<date>...)`, `(?P<seq>...)` and the code reads like plain English.

## Summary

- `()` creates a capturing group; after a match use `.group(n)` to retrieve it, or `.groups()` for all of them
- **When `findall` sees capturing groups, it returns only the group contents**—the single most classic regex trap
- `(?:...)` is a non-capturing group: it participates in matching logic but doesn't pollute the result
- `(?P<name>...)` is a named group, accessed via `.group('name')` and `.groupdict()`
- With many or deeply nested groups, prefer named groups—their readability beats counting indices by a mile
