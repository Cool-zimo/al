# Character Classes and Quantifiers

> This lesson answers: "How do I describe a whole category of characters, or a length, in one sentence?" `.`, `\d`, `\w`, `\s` are shorthands; `[]`, `*`, `+`, `?`, `{m,n}` are quantifiers—and their combination is where regex gets its real expressive power. **Greedy vs. non-greedy** is the most valuable trap in this lesson.

## Predefined Character Classes: Shorthands

Regex has a set of built-in shorthands for "a category of characters." Memorize these and you'll rarely need to write `[]`:

| Symbol | Meaning | Equivalent |
|---|---|---|
| `.` | Any character (**does not include newline by default**) | — |
| `\d` | Digit | `[0-9]` |
| `\D` | Non-digit | `[^0-9]` |
| `\w` | Letter, digit, or underscore | `[a-zA-Z0-9_]` |
| `\W` | Anything not a letter, digit, or underscore | `[^a-zA-Z0-9_]` |
| `\s` | Whitespace (space, tab, newline) | `[ \t\n\r\f\v]` |
| `\S` | Non-whitespace | `[^ \t\n\r\f\v]` |

```python
import re

text = "Alice id:alice_  balance £1280.5\nnote: none"
print("digits:", re.findall(r'\d+\.?\d*', text))
print("word chars:", re.findall(r'\w+', text))
print("whitespace:", re.findall(r'\s+', text))
```

Output:

```
digits: ['1280.5']
word chars: ['Alice', 'id', 'alice_', '1280', '5']
whitespace: [' ', ' ', ' ', '\n']
```

**Note**: by default `\w` includes Unicode letters (the exact set depends on flags like `re.ASCII`). If you only want ASCII letters and digits, write `[a-zA-Z0-9]` explicitly or use the `re.ASCII` flag (covered in a later lesson).

## Custom Character Classes: []

Inside `[]` you write a set; it matches **any one** of those characters. `-` means a range, and `^` at the beginning means "negate."

```python
import re

text = "IDs: A1 B7 C3 X9 test"

print("letter+digit:", re.findall(r'[A-Z][0-9]', text))   # uppercase letter then digit
print("exclude digit 1:", re.findall(r'[^1]+', text))     # runs of "not 1"
```

Output:

```
letter+digit: ['A1', 'B7', 'C3', 'X9']
exclude digit 1: ['IDs: A', ' B7 C3 X9 test']
```

`[^...]` is counterintuitive: it matches "any **one** character that is **not** these." A common use is "everything up to a delimiter."

## Quantifiers: Saying How Many

Quantifiers decide how many times the preceding element may appear:

| Quantifier | Meaning | Equivalent |
|---|---|---|
| `*` | 0 or more (optional) | `{0,}` |
| `+` | 1 or more (at least one) | `{1,}` |
| `?` | 0 or 1 (optional) | `{0,1}` |
| `{n}` | Exactly n | — |
| `{m,n}` | Between m and n | — |
| `{m,}` | At least m | — |

```python
import re

text = "Colours: red, blueish, deepdeepdeep"

print(re.findall(r'blue?ish', text))      # 'e' is optional
print(re.findall(r'de{2,3}', text))       # 'e' repeated 2-3 times
```

Output:

```
['bluish']
['dee', 'dee', 'dee']
```

**Watch what the quantifier attaches to**: `blue?ish` means "optional e + ish," so "bluish" matches. `{m,n}` only modifies the single element immediately before it.

## Crash Site: Greedy Matching Swallows the Whole Segment

This is the classic, easiest regex trap to hit. Alice wants to extract the content of the first tag from an HTML fragment:

```python
import re

html = "<div>title</div><div>body</div>"

# WRONG: greedy match; .* eats all the way to the LAST </div>
result = re.findall(r'<div>(.*)</div>', html)
print(result)
```

Output:

```
['title</div><div>body']
```

The `*` in `.*` is **greedy**: it matches as much as possible. So `.` consumes "title`</div><div>`body" in one gulp, leaving only the final `</div>` to close. That's clearly not what we wanted.

**The fix**: add `?` after the quantifier to make it **non-greedy** (also called lazy), so it stops at the **first** place the condition is satisfied.

```python
import re

html = "<div>title</div><div>body</div>"
result = re.findall(r'<div>(.*?)</div>', html)    # note the extra ? after *
print(result)
```

Output:

```
['title', 'body']
```

| Form | Name | Behavior |
|---|---|---|
| `.*` | Greedy | Matches as much as possible, eating to the last valid endpoint |
| `.*?` | Non-greedy | Matches as little as possible, stopping at the first valid endpoint |

The same applies to `+?`, `??`, `{m,n}?`—adding `?` makes any quantifier non-greedy.

## Crash Site: `.` Doesn't Match Newlines

```python
import re

text = """first line
second line
third line"""

# WRONG: . does not match newlines by default
print(re.findall(r'first(.*)third', text))
```

Output:

```
[]
```

`.` does **not** match the newline character `\n` by default, so content spanning from "first" to "third" across lines simply can't match.

**The fix**: add the `re.DOTALL` flag (or the inline form `(?s)`) so `.` includes newlines. Flags are covered in detail in Lesson 6; for now, just remember this switch exists.

```python
import re

text = """first line
second line
third line"""

print(re.findall(r'first(.*)third', text, re.DOTALL))
```

Output:

```
[' line\nsecond line\n']
```

## Summary

- `\d`, `\w`, `\s` are shorthands for "a category of characters"; the uppercase version negates
- `[]` defines a custom character set; `[^...]` means "not these characters"
- Quantifiers `*`, `+`, `?`, `{m,n}` say "how many"; they only modify the element immediately before them
- **Quantifiers are greedy by default**: `(.*)` keeps eating to the last match point—nearly always wrong across tags
- Add `?` for non-greedy `(.*?)`; it stops at the first valid point and is the usual choice when extracting content
- `.` doesn't match newlines by default; use `re.DOTALL` when you need to cross lines
