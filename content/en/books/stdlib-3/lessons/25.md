# Hands-On: Writing a Complete Test Suite for a Small Module

> This lesson brings everything together: building a real small module (a shopping cart), writing a full set of unit tests, running them, and then deliberately introducing bugs to see whether the tests catch them.

## The Module Under Test: A Shopping Cart

This is a simplified but complete shopping cart module, covering item management, total calculation, and coupon logic:

```python
# cart.py
class Cart:
    def __init__(self):
        self.items = {}       # {sku: {"name": ..., "price": ..., "qty": ...}}
        self.coupon = None    # the coupon in use

    def add(self, sku, name, price, qty=1):
        if price < 0:
            raise ValueError("price cannot be negative")
        if qty <= 0:
            raise ValueError("quantity must be greater than 0")
        if sku in self.items:
            self.items[sku]["qty"] += qty
        else:
            self.items[sku] = {"name": name, "price": price, "qty": qty}

    def remove(self, sku):
        if sku not in self.items:
            raise KeyError(f"item {sku} is not in the cart")
        del self.items[sku]

    def total(self):
        return round(sum(
            item["price"] * item["qty"]
            for item in self.items.values()
        ), 2)

    def apply_coupon(self, coupon_type, value):
        """coupon_type: 'percent' for percentage discount, 'fixed' for fixed deduction"""
        if coupon_type not in ("percent", "fixed"):
            raise ValueError("unsupported coupon type")
        self.coupon = {"type": coupon_type, "value": value}

    def final_price(self):
        t = self.total()
        if self.coupon is None:
            return t
        if self.coupon["type"] == "percent":
            return round(t * (1 - self.coupon["value"] / 100), 2)
        elif self.coupon["type"] == "fixed":
            return round(max(0, t - self.coupon["value"]), 2)
        return t

    def is_empty(self):
        return len(self.items) == 0
```

## The Test Cases

```python
# test_cart.py
import unittest
from cart import Cart

class TestCart(unittest.TestCase):
    def setUp(self):
        self.cart = Cart()

    def test_empty_cart(self):
        self.assertTrue(self.cart.is_empty())
        self.assertEqual(self.cart.total(), 0)

    def test_add_item(self):
        self.cart.add("a001", "apple", 5.0, 2)
        self.assertFalse(self.cart.is_empty())
        self.assertEqual(self.cart.total(), 10.0)

    def test_add_duplicate_item(self):
        self.cart.add("a001", "apple", 5.0, 2)
        self.cart.add("a001", "apple", 5.0, 3)
        self.assertEqual(self.cart.total(), 25.0)   # 5 * 5

    def test_add_negative_price(self):
        with self.assertRaises(ValueError):
            self.cart.add("a001", "apple", -5.0)

    def test_add_zero_qty(self):
        with self.assertRaises(ValueError):
            self.cart.add("a001", "apple", 5.0, 0)

    def test_remove_item(self):
        self.cart.add("a001", "apple", 5.0, 2)
        self.cart.remove("a001")
        self.assertTrue(self.cart.is_empty())

    def test_remove_nonexistent(self):
        with self.assertRaises(KeyError):
            self.cart.remove("ghost")

    def test_percent_coupon(self):
        self.cart.add("a001", "apple", 100.0, 2)
        self.cart.apply_coupon("percent", 20)   # 20% off
        self.assertEqual(self.cart.final_price(), 160.0)

    def test_fixed_coupon(self):
        self.cart.add("a001", "apple", 100.0)
        self.cart.apply_coupon("fixed", 30)
        self.assertEqual(self.cart.final_price(), 70.0)

    def test_fixed_coupon_exceeds_total(self):
        self.cart.add("a001", "apple", 10.0)
        self.cart.apply_coupon("fixed", 30)   # deduction exceeds total
        self.assertEqual(self.cart.final_price(), 0)   # never below 0

    def test_invalid_coupon_type(self):
        with self.assertRaises(ValueError):
            self.cart.apply_coupon("shipping", 10)

    def test_multiple_items(self):
        self.cart.add("a001", "apple", 5.0, 2)
        self.cart.add("b002", "banana", 3.0, 5)
        self.assertEqual(self.cart.total(), 25.0)   # 10 + 15

    def test_float_precision(self):
        self.cart.add("a001", "coffee", 3.33, 3)
        self.assertAlmostEqual(self.cart.total(), 9.99, places=2)

if __name__ == "__main__":
    unittest.main()
```

**13 tests covering**: empty cart, adding, adding duplicates, parameter validation, removing, nonexistent items, percentage coupons, fixed coupons, deductions exceeding the total, invalid coupons, multiple items, and float precision.

## Deliberately Introducing a Bug to See If Tests Catch It

Now let's break the percentage calculation in `final_price`:

```python
    def final_price(self):
        t = self.total()
        if self.coupon is None:
            return t
        if self.coupon["type"] == "percent":
            return round(t * self.coupon["value"] / 100, 2)  # BUG: forgot the 1-
        ...
```

**It used to be `t * (1 - value/100)`; now it's `t * value/100`** — turning "20% off" into "multiply by 20%."

Run the tests again:

```
test_percent_coupon (__main__.TestCart) ... FAIL
...
AssertionError: 40.0 != 160.0
```

**`test_percent_coupon` failed immediately** — a 20% discount computed 40 instead of 160, which didn't match the expectation. The tests caught the bug.

Another bug: forgetting `max(0, ...)` when the coupon deduction exceeds the total:

```python
    def final_price(self):
        ...
        elif self.coupon["type"] == "fixed":
            return t - self.coupon["value"]   # BUG: could be negative
```

Run the tests:

```
test_fixed_coupon_exceeds_total (__main__.TestCart) ... FAIL
...
AssertionError: -20 != 0
```

**`test_fixed_coupon_exceeds_total` caught it** — the price came out as -20 instead of conforming to the "never below 0" expectation.

## Crash Site: Only Testing the Happy Path Lets Bugs Reach Production

```python
# tests covering only the happy path
class TestCartWeak(unittest.TestCase):
    def test_add(self):
        cart = Cart()
        cart.add("a001", "apple", 5.0, 2)
        self.assertEqual(cart.total(), 10.0)

    def test_total(self):
        cart = Cart()
        cart.add("a001", "apple", 100.0, 2)
        cart.apply_coupon("percent", 20)
        self.assertEqual(cart.final_price(), 160.0)
```

**Only 2 tests, and both are positive cases.** If someone changed the percentage logic in `final_price`, the first test wouldn't notice (it never applies a coupon), leaving only the second to catch it. But if the bug were in `add`'s parameter validation (say, allowing a negative price), neither test would spot it — because neither tests the error path.

**Positive and negative cases are both indispensable.**

## Crash Site: Test and Code Drift in the Same Direction

```python
# cart.py (has a bug)
def total(self):
    return round(sum(item["price"] for item in self.items.values()), 2)  # forgot * qty

# test_cart.py (the expectation drifted to match)
def test_add_item(self):
    self.cart.add("a001", "apple", 5.0, 2)
    self.assertEqual(self.cart.total(), 5.0)   # expects 5 instead of 10
```

**The test passes, but the bug remains** — because the test expectation was copied from the faulty implementation's output. This is the classic "test and code drifting together" trap. Avoid it by hand-calculating test data, writing more boundary cases, and having someone review the tests.

## Summary

- A complete module needs tests for: happy paths, boundary values, error paths, and parameter validation.
- Test cases should cover each method's core logic and its error handling.
- Deliberately introducing bugs to verify the tests catch them is a valid way to assess test quality.
- Tests covering only the happy path are "placebo tests" — bugs slip through anyway.
- Test expectations must be hand-calculated, never copied from the code's output, or they drift together.
- 13 tests running in 0.001 seconds is tens of thousands of times faster than manual testing.
