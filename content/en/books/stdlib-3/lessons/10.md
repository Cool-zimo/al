# Real-World Project: A Log Parser

> This lesson turns the first 9 regex lessons into something usable: a log parser. The input is a pile of log lines; the output is structured records of "time, level, message," plus a count by level. This is regex's most typical and most realistic application.

## First, Look at What Real Logs Actually Look Like

```python
log_lines = """2026-09-28 10:20:35 ERROR database connection timed out, retrying
2026-09-28 10:21:02 WARN disk usage 87%, consider cleanup
2026-09-28 10:22:15 INFO user Alice logged in
2026-09-28 10:22:18 ERROR order DD20260927001 payment callback failed
2026-09-28 10:25:00 INFO cleanup task started
2026-09-28 10:25:01 ERROR cleanup task raised java.lang.NullPointerException
2026-09-28 10:30:45 WARN memory usage 92%
2026-09-28 10:31:00 INFO service health check passed"""

print(f"{len(log_lines.splitlines())} log lines in total")
```

Output:

```
8 log lines in total
```

Every line has a fixed structure: date + space + time + space + level + space + message. Text this "highly consistent in format" is exactly where regex shines.

## Design a Regex That Splits the Fields

Use named groups so every field has a name:

```python
import re

LINE_RE = re.compile(
    r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
    r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
    r'(?P<level>[A-Z]+)\s+'
    r'(?P<msg>.*)'
)

m = LINE_RE.match("2026-09-28 10:20:35 ERROR database connection timed out, retrying")
print(m.groupdict())
```

Output:

```
{'date': '2026-09-28', 'time': '10:20:35', 'level': 'ERROR', 'msg': 'database connection timed out, retrying'}
```

`groupdict()` turns named groups directly into a dictionary. Everything after that is ordinary dictionary work—**regex's job is to turn text into a dict; Python takes over from there.**

## Parse Into a Structured List

```python
import re

LINE_RE = re.compile(
    r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
    r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
    r'(?P<level>[A-Z]+)\s+'
    r'(?P<msg>.*)'
)

records = []
for line in log_lines.splitlines():
    m = LINE_RE.match(line.strip())
    if m:
        records.append(m.groupdict())

print(f"successfully parsed {len(records)} records")
print("first:", records[0])
print("fourth:", records[3])
```

Output:

```
successfully parsed 8 records
first: {'date': '2026-09-28', 'time': '10:20:35', 'level': 'ERROR', 'msg': 'database connection timed out, retrying'}
fourth: {'date': '2026-09-28', 'time': '10:22:18', 'level': 'ERROR', 'msg': 'order DD20260927001 payment callback failed'}
```

**Notice the `if m`**: a regex that doesn't match returns `None`. Real logs frequently contain blank lines, comment lines, and exception stack traces (multi-line), so calling `.groupdict()` directly would raise `AttributeError`.

## Crash Site: Exception Stack Traces Take Down the Parser

Real error logs are often **multi-line**: the first line is a well-formatted log header, followed by several lines of a Java/Python stack trace.

```python
import re

multiline_log = """2026-09-28 10:31:00 ERROR cleanup task raised exception
java.lang.NullPointerException
    at com.example.Task.run(Task.java:42)
    at com.example.Main.main(Main.java:10)
2026-09-28 10:32:00 INFO service recovered"""

LINE_RE = re.compile(r'(?P<date>\d{4}-\d{2}-\d{2})\s+(?P<time>\d{2}:\d{2}:\d{2})\s+(?P<level>[A-Z]+)\s+(?P<msg>.*)')

for line in multiline_log.splitlines():
    m = LINE_RE.match(line.strip())
    if m:
        print("parsed:", m.group('level'), m.group('msg'))
    else:
        print("skipped (non-standard line):", line.strip()[:40])
```

Output:

```
parsed: ERROR cleanup task raised exception
skipped (non-standard line): java.lang.NullPointerException
skipped (non-standard line):     at com.example.Task.run(Task.java:42)
skipped (non-standard line):     at com.example.Main.main(Main.java:10)
parsed: INFO service recovered
```

**This is the correct handling**: not every line conforms to the format, so skip the ones that don't match (or merge them into the previous record's msg). Insisting that every line must match is a common way parsers die.

## Counting by Level: Enter Counter

Lesson 11 covers `collections.Counter` systematically, but let's borrow it here once—to count how many times each level appears:

```python
from collections import Counter

levels = [r['level'] for r in records]
count = Counter(levels)
print(count)
print(f"ERROR occurs most, {count['ERROR']} times")
```

Output:

```
Counter({'ERROR': 3, 'INFO': 3, 'WARN': 2})
ERROR occurs most, 3 times
```

**This is regex's ultimate value**: turn unstructured text into structured records, then analyze them with Python's dicts, list comprehensions, and `Counter`. **Regex only "translates"; analysis belongs to Python itself.**

## Crash Site: A Message Containing "ERROR" Is Misclassified

Alice's log message mentions another system:

```python
import re

line = "2026-09-28 10:20:35 ERROR upstream returned ERROR_CODE=500"
m = re.match(r'(\d{4}-\d{2}-\d{2})\s+(\d{2}:\d{2}:\d{2})\s+([A-Z]+)\s+(.*)', line)
print("level:", m.group(3))
print("message:", m.group(4))
```

Output:

```
level: ERROR
message: upstream returned ERROR_CODE=500
```

The `ERROR` inside the message doesn't interfere with the level extraction, because the pattern says **the level is followed by a space and then the message**—regex matches by position, so whatever appears in the message is irrelevant. This is why "fixed-format" logs are such a great fit for regex: **delimiters are natural anchors.**

## The Complete Product: A Reusable Log Parser

```python
import re
from collections import Counter

class LogParser:
    LINE_RE = re.compile(
        r'(?P<date>\d{4}-\d{2}-\d{2})\s+'
        r'(?P<time>\d{2}:\d{2}:\d{2})\s+'
        r'(?P<level>[A-Z]+)\s+'
        r'(?P<msg>.*)'
    )

    def __init__(self):
        self.records = []

    def feed(self, text):
        for line in text.splitlines():
            line = line.strip()
            if not line:
                continue
            m = self.LINE_RE.match(line)
            if m:
                self.records.append(m.groupdict())

    def stats(self):
        return dict(Counter(r['level'] for r in self.records))

    def filter_by_level(self, level):
        return [r['msg'] for r in self.records if r['level'] == level]

# Run it
p = LogParser()
p.feed(log_lines)
print("stats:", p.stats())
print("all ERROR messages:")
for msg in p.filter_by_level("ERROR"):
    print(" -", msg)
```

Output:

```
stats: {'ERROR': 3, 'INFO': 3, 'WARN': 2}
all ERROR messages:
 - database connection timed out, retrying
 - order DD20260927001 payment callback failed
 - cleanup task raised java.lang.NullPointerException
```

**This class has only three methods, yet it covers the full lifecycle of log parsing**: ingest text, parse line by line, then summarize and filter. The regex is hidden inside `feed`; the outside world sees clean data structures. This is where regex belongs—**inside a tool, not scattered through business code.**

## Summary

- Log-parsing regex essentials: **use delimiters as anchors**, give each field a named group, turn results into a dict with `groupdict()`
- Real logs contain blank lines, comments, and multi-line stack traces—**always guard with `if m`**; don't assume every line matches
- Regex's only job is "translate text into dicts"; analysis (counting, filtering) belongs to Python's own tools
- `Counter` is the single fastest line of code for counting log levels
- Encapsulate regex inside a utility class like `LogParser`; expose clean interfaces, don't scatter it through business code
