# collections.Counter: Counting Made Effortless

> This lesson answers: "How do I count things?" A hand-written dictionary counter takes 4 lines and is easy to get wrong; `Counter` does it in one, and can even tell you "who's winning."

## Why Hand-Written Counting Is Annoying

Bob is counting how many times each character appears in a string:

```python
text = "abracadabra"

# Hand-written dict counting
counts = {}
for ch in text:
    if ch in counts:
        counts[ch] += 1
    else:
        counts[ch] = 1

print(counts)
```

Output:

```
{'a': 5, 'b': 2, 'r': 2, 'c': 1, 'd': 1}
```

Four lines, and you have to handle the "first time seeing this key" branch explicitly. Forgetting the `else`, or writing `=` instead of `+=`, are frequent bugs.

**`Counter` turns this into one line**:

```python
from collections import Counter

text = "abracadabra"
c = Counter(text)
print(c)
```

Output:

```
Counter({'a': 5, 'b': 2, 'r': 2, 'c': 1, 'd': 1})
```

`Counter` is a subclass of `dict`—it **is** a dictionary, just with a few methods designed specifically for counting. Every dict operation still works.

## most_common: Just Ask "Who's Winning"

This is `Counter`'s most useful method. No sorting, no lambda—one line gives you the top N:

```python
from collections import Counter

votes = ["apple", "banana", "apple", "orange", "banana", "apple", "orange", "apple"]
c = Counter(votes)

print("first place:", c.most_common(1))
print("top three:", c.most_common(3))
print("all (by frequency, descending):", c.most_common())
```

Output:

```
first place: [('apple', 4)]
top three: [('apple', 4), ('banana', 2), ('orange', 2)]
all (by frequency, descending): [('apple', 4), ('banana', 2), ('orange', 2)]
```

`most_common(n)` returns a list of `(element, count)` tuples, already sorted from highest to lowest count. **This is a convenience hand-written dicts simply can't match.**

## Crash Site: Accessing a Missing Key Returns 0, Not an Error

A normal dict raises `KeyError` for a missing key, but `Counter`—to fit the "counting" semantics—**returns 0**:

```python
from collections import Counter

c = Counter(["apple", "banana"])
print("apple:", c["apple"])
print("watermelon:", c["watermelon"])      # a plain dict would KeyError here
```

Output:

```
apple: 1
watermelon: 0
```

This is `Counter`'s deliberate fault tolerance for "counting." But it's also a trap: you can't rely on `KeyError` to catch bugs like "typo'd a key."

**Conclusion**: when you genuinely need to know "is this key even present?", use `c.get(key)` or `key in c`. Don't infer presence from `c[key] == 0`.

## Addition and Subtraction: Set-Like Counting Operations

`Counter` supports addition, subtraction, and set operations—handy for comparing two batches of data:

```python
from collections import Counter

# Last week's and this week's order-category counts
last_week = Counter(apples=30, bananas=20, oranges=15)
this_week = Counter(apples=35, bananas=18, mangoes=10)

print("combined:", last_week + this_week)
print("growth (this - last):", this_week - last_week)
```

Output:

```
combined: Counter({'apples': 65, 'bananas': 38, 'oranges': 15, 'mangoes': 10})
growth (this - last): Counter({'mangoes': 10, 'apples': 5})
```

Subtraction keeps only items with a **positive** result (bananas: 18-20 is negative, so it's dropped). This makes it ideal for a "growth board": what remains is the categories that grew.

## Crash Site: Counter Counted Something You Didn't Intend

`Counter` accepts **any iterable**. Pass it a string and it counts characters; pass it a list and it counts elements.

```python
from collections import Counter

# WRONG: expected word counts, got character counts
c = Counter("applesbananasapples")
print(c)
```

Output:

```
Counter({'a': 4, 'p': 4, 's': 4, 'l': 2, 'e': 2, 'b': 1, 'n': 1})
```

To count words or lines, you must first **split the text into a list**:

```python
from collections import Counter

words = "apples bananas apples oranges".split()
c = Counter(words)
print(c)
```

Output:

```
Counter({'apples': 2, 'bananas': 1, 'oranges': 1})
```

**The essence of this trap**: `Counter` doesn't understand "semantics"—it only cares about "what each iteration yields." A string iterates by character, a list by element, a dict by key. **Knowing what your input iterates into is the first step to using it correctly.**

## Real-World: Counting Order Amount Buckets

```python
from collections import Counter

orders = [29, 99, 129, 199, 299, 99, 129, 499, 99, 129, 29]

# Use a bucket label for counting
def bucket(amount):
    if amount < 100:
        return "under 100"
    elif amount < 300:
        return "100-300"
    else:
        return "300+"

buckets = Counter(bucket(o) for o in orders)
print(buckets.most_common())
```

Output:

```
[('100-300', 5), ('under 100', 3), ('300+', 1)]
```

**This pattern is extremely common in data analysis**: first define a "classification function," then feed a generator expression to `Counter`. One line turns a pile of numbers into a readable distribution.

## Summary

- `Counter` is a subclass of `dict`, optimized for counting—it eliminates the "check if the key exists" boilerplate
- `most_common(n)` directly returns the top N by frequency; no manual sorting needed
- Accessing a missing key returns `0`, not an error—convenient but it hides typos; use `in` to test presence
- Supports `+` and `-`; `a - b` keeps only positive entries, great for growth/diff analysis
- `Counter` counts by "iteration unit": strings by character, lists by element. Confirm what you're iterating before passing
- First classify with a function, then `Counter(generator expression)`—the standard recipe for distributions
