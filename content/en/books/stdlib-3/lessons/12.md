# defaultdict and OrderedDict

> This lesson answers: "How do I handle nested dict-of-list or dict-of-dict structures cleanly?" `defaultdict` lets you append without checking for the key first. `OrderedDict` preserves insertion order—but since Python 3.7+, plain `dict` is already ordered, so it now has only niche uses.

## Why Hand-Written Grouping Is Verbose

Bob has a list of orders and wants to group them by customer name, collecting each customer's order IDs:

```python
orders = [
    ("Alice", "DD001"), ("Bob", "DD002"),
    ("Alice", "DD003"), ("Carol", "DD004"), ("Bob", "DD005"),
]

# Hand-written grouping: must check whether the key exists first
groups = {}
for name, oid in orders:
    if name not in groups:
        groups[name] = []
    groups[name].append(oid)

print(groups)
```

Output:

```
{'Alice': ['DD001', 'DD003'], 'Bob': ['DD002', 'DD005'], 'Carol': ['DD004']}
```

That `if name not in groups` check has to be written for every grouping—tedious and easy to forget.

## defaultdict: Auto-Create a Default Value for Missing Keys

`defaultdict` takes a "factory function." When you access a missing key, it **automatically calls that function to create a default value** and stores it.

```python
from collections import defaultdict

orders = [
    ("Alice", "DD001"), ("Bob", "DD002"),
    ("Alice", "DD003"), ("Carol", "DD004"), ("Bob", "DD005"),
]

groups = defaultdict(list)      # factory is list, default value is []
for name, oid in orders:
    groups[name].append(oid)    # no need to check whether the key exists

print(dict(groups))             # convert to plain dict for clean printing
```

Output:

```
{'Alice': ['DD001', 'DD003'], 'Bob': ['DD002', 'DD005'], 'Carol': ['DD004']}
```

**That's the whole difference**: `defaultdict(list)` means "every value in this dict defaults to an empty list." So you can confidently `.append()` without ever worrying about `KeyError`.

## Crash Site: Using list When You Meant a Number

Bob wanted to store an order count per customer, but accidentally used `list` for a scenario that needs a "numeric default":

```python
from collections import defaultdict

# WRONG: trying to count orders per customer, but using list as the factory
d = defaultdict(list)
d["Alice"].append("DD001")
d["Alice"].append("DD002")
print(d["Alice"])
```

Output:

```
['DD001', 'DD002']
```

It runs, but it's not what he wanted—he wanted a **count**. For counting you use `int` (default value `0`):

```python
from collections import defaultdict

count = defaultdict(int)      # default value is 0
items = ["apple", "banana", "apple", "orange", "banana", "apple"]
for it in items:
    count[it] += 1            # 0 += 1 is perfectly legal

print(dict(count))
```

Output:

```
{'apple': 3, 'banana': 2, 'orange': 1}
```

**`int`'s default is `0`, `list`'s default is `[]`, `set`'s default is `set()`.** Which factory you pick depends on whether you're "counting," "collecting into a list," or "collecting into a set."

## Writing Your Own Factory Function

The factory doesn't have to be a built-in type—any **callable that takes no arguments** works:

```python
from collections import defaultdict

# Custom factory: the default value is a "record with initial values"
def make_record():
    return {"count": 0, "items": []}

db = defaultdict(make_record)
db["Alice"]["count"] += 1
db["Alice"]["items"].append("DD001")
db["Bob"]["count"] += 1

print(dict(db))
```

Output:

```
{'Alice': {'count': 1, 'items': ['DD001']}, 'Bob': {'count': 1, 'items': []}}
```

Note the factory is passed **without parentheses**: you pass the function object `make_record` itself, not the result of `make_record()`. Passing the result would make every key share **the same object**—see the next crash site.

## Crash Site: A Factory That Returns the Same Object Every Time

```python
from collections import defaultdict

# WRONG: the lambda returns the SAME list object every time
shared = []
d = defaultdict(lambda: shared)

d["a"].append(1)
d["b"].append(2)
print("a:", d["a"])
print("b:", d["b"])
```

Output:

```
a: [1, 2]
b: [1, 2]
```

`a` and `b` point to the **same list**—change one and you change both. Because `lambda: shared` returns that same `shared` object on every call.

**The fix**: make the factory create a **new object** on each call:

```python
from collections import defaultdict

d = defaultdict(list)          # list creates a new empty list on every call
d["a"].append(1)
d["b"].append(2)
print("a:", d["a"])
print("b:", d["b"])
```

Output:

```
a: [1]
b: [2]
```

`list`, `dict`, `set`—these built-ins **return a new object on every call**, so `defaultdict(list)` is naturally safe. The trap only appears when your custom factory returns an external variable.

## OrderedDict: Once Essential, Now Less So

Since Python 3.7, plain `dict` **guarantees insertion order**. So `OrderedDict`'s core selling point—"remember the order elements were added"—has been absorbed by the plain dict.

```python
# Python 3.7+: plain dict is ordered
d = {}
d["Alice"] = 1
d["Bob"] = 2
d["Carol"] = 3
print(list(d.keys()))        # order is preserved
```

Output:

```
['Alice', 'Bob', 'Carol']
```

**So what is OrderedDict still good for?** Three scenarios:

1. **`move_to_end(key)` and `popitem(last=...)`**: precise control over "who's first/last"—plain dict has no such API.
2. **`==` considers order**: two OrderedDicts with different order are not equal; plain dict ignores order.
3. **LRU-cache-style scenarios**: when you need to frequently reorder, `move_to_end` is O(1).

```python
from collections import OrderedDict

od = OrderedDict()
od["a"] = 1
od["b"] = 2
od["c"] = 3

od.move_to_end("a")          # move a to the end
print(list(od.items()))

od.move_to_end("c", last=False)  # move c to the front
print(list(od.items()))
```

Output:

```
[('b', 2), ('c', 3), ('a', 1)]
[('c', 3), ('b', 2), ('a', 1)]
```

## Crash Site: Assuming dict Was Always Ordered

This trap is **version-dependent**. In Python 3.6 and earlier, plain `dict` did **not** guarantee order; 3.7 made it part of the language spec. Be explicit: if you depend on order, either use 3.7+ or reach for `OrderedDict` deliberately.

```python
import sys
print("current Python version:", sys.version_info[:2])
```

Output (varies by environment):

```
current Python version: (3, 11)
```

**Practical advice**: new projects can use plain `dict` and enjoy ordered semantics; only reach for `OrderedDict` when you need precise order control like `move_to_end`, or to stay compatible with older code.

## Summary

- `defaultdict(factory)` auto-creates a default value for missing keys, eliminating the check-first boilerplate
- Pick `int` (default 0) for counting, `list` (default `[]`) for grouping, `set` (default `set()`) for dedup sets
- A custom factory must **return a new object on each call**; returning an external variable makes every key share that object
- Python 3.7+ plain `dict` already guarantees insertion order; `OrderedDict`'s core selling point has been absorbed
- `OrderedDict` now mainly covers precise order control (`move_to_end`/`popitem`) and order-sensitive equality comparisons
