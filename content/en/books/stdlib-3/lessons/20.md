# argparse In Depth: Subcommands and Mutually Exclusive Groups

> This lesson covers advanced `argparse` usage: organising subcommands the way `git clone` and `git push` do, using mutually exclusive groups to prevent conflicting arguments, and comparing the result with hand-rolled `sys.argv` parsing.

## Subcommands: Organising a CLI Like `git`

`git clone`, `git push`, and `git commit` are different subcommands of the same program, each with its own arguments. `argparse` implements this with `subparsers`:

```python
import argparse

parser = argparse.ArgumentParser(prog="mygit")
sub = parser.add_subparsers(dest="command", help="available subcommands")

# Subcommand: clone
p_clone = sub.add_parser("clone", help="clone a repository")
p_clone.add_argument("url", help="repository URL")

# Subcommand: commit
p_commit = sub.add_parser("commit", help="create a commit")
p_commit.add_argument("-m", "--message", required=True, help="commit message")

args = parser.parse_args(["clone", "https://github.com/xxx/yyy.git"])
print(args.command, args.url)
```

Output:

```
clone https://github.com/xxx/yyy.git
```

**`dest="command"` records which subcommand the user picked**, while `sub.add_parser("clone")` creates a sub-parser with its own independent arguments. Each subcommand can have a completely different argument list.

```python
# switch subcommands
args2 = parser.parse_args(["commit", "-m", "fix login bug"])
print(args2.command, args2.message)
```

Output:

```
commit fix login bug
```

## Mutually Exclusive Arguments: They Can't Both Appear

`--verbose` and `--quiet` should never be passed together. Enforce that with `add_mutually_exclusive_group`:

```python
import argparse

parser = argparse.ArgumentParser()
group = parser.add_mutually_exclusive_group()
group.add_argument("--verbose", action="store_true", help="verbose output")
group.add_argument("--quiet", action="store_true", help="quiet mode")

args = parser.parse_args(["--verbose", "--quiet"])  # both passed
```

Output:

```
usage: xxx.py [-h] [--verbose | --quiet]
xxx.py: error: argument --quiet: not allowed with argument --verbose
```

**The error is generated automatically** — no custom `if` logic required.

## `argparse` vs. Hand-Rolled `sys.argv`

| Dimension | Hand-rolled `sys.argv` | `argparse` |
|---|---|---|
| Type conversion | manual `int()`, `float()` | `type=` converts automatically |
| Default values | manual length checks | `default=` |
| Help text | manual `print` | `--help` generated automatically |
| Validation | hand-written `if` | `choices`, `required`, exclusive groups |
| Subcommands | extremely hard | `subparsers` built in |
| Error handling | manual `try/except` | usage and errors generated automatically |

**Hand-rolled parsing becomes painful once you have more than three arguments**, while `argparse` stays clear no matter how many you add.

## Crash Site: Forgetting `dest` on a Subcommand

```python
import argparse

parser = argparse.ArgumentParser()
sub = parser.add_subparsers(help="subcommands")

sub.add_parser("start")
sub.add_parser("stop")

args = parser.parse_args(["start"])
print(args.command)  # AttributeError!
```

Output:

```
usage: xxx.py [-h] {start,stop} ...
xxx.py: error: argument {start,stop}: invalid choice: 'command' (choose from 'start', 'stop')
```

**Without `dest="command"`, the parsed result has no `command` attribute**, so you can't tell which subcommand the user selected. `dest` is mandatory for subcommands.

## Crash Site: Marking Every Flag in a Mutually Exclusive Group as `required=True`

```python
import argparse

parser = argparse.ArgumentParser()
group = parser.add_mutually_exclusive_group(required=True)
group.add_argument("--local", action="store_true")
group.add_argument("--remote", action="store_true")

parser.parse_args([])  # neither passed
```

Output:

```
usage: xxx.py [-h] (--local | --remote)
xxx.py: error: one of the arguments --local --remote is required
```

**When an exclusive group has `required=True`, exactly one of its members must be passed.** That's ideal for "pick one, mandatory" scenarios such as `--install` versus `--uninstall`. But if both flags use `action="store_true"`, the user must now choose one or the parse will fail.

## Crash Site: Mixing Global and Subcommand Arguments

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--verbose", action="store_true")  # global argument
sub = parser.add_subparsers(dest="command")
p_run = sub.add_parser("run")
p_run.add_argument("target")   # subcommand argument

# correct order: global argument first, then the subcommand
args = parser.parse_args(["--verbose", "run", "main.py"])
print(args.verbose, args.command, args.target)
```

Output:

```
True run main.py
```

**Global arguments must come before the subcommand.** Writing `run --verbose main.py` would treat `--verbose` as an argument of the `run` subcommand (which never registered one) and error out immediately.

## Summary

- `subparsers` implements subcommands; each gets its own argument list, organising a CLI the way `git` does.
- `dest="command"` is required for subcommands so you can identify which one the user selected.
- A mutually exclusive group, via `add_mutually_exclusive_group`, prevents conflicting arguments; `required=True` enforces "pick exactly one".
- `argparse` auto-generates `--help`, converts types, and validates input — far beyond what `sys.argv` offers.
- Global arguments go before the subcommand; subcommand arguments go after it.
- When every flag in an exclusive group is `store_true` and the group is `required=True`, the user must pick one.
