# argparse Basics: Parsing Command-Line Arguments Properly

> This lesson covers the basic usage of `argparse`: positional arguments, optional arguments, `type`, `default`, `help`, and validating input with `choices`. The days of hand-rolling `sys.argv` parsing are over.

## Why Not Hand-Roll `sys.argv`?

Hand-written argument parsing looks like this:

```python
import sys

# Goal: support `python script.py --name Alice --age 25`
args = sys.argv[1:]   # ['--name', 'Alice', '--age', '25']

name = None
age = None
for i, a in enumerate(args):
    if a == "--name":
        name = args[i + 1]
    elif a == "--age":
        age = int(args[i + 1])   # easy to forget the type conversion

print(f"{name}, {age}")
```

**The problems pile up**: you convert types yourself, handle defaults yourself, write help text yourself, validate legality yourself, and respond to `--help` yourself. That's exactly the problem `argparse` solves.

## The Simplest Example

```python
import argparse

parser = argparse.ArgumentParser(description="A tool for processing user information")
parser.add_argument("name", help="user name")
parser.add_argument("--age", type=int, default=18, help="age, defaults to 18")

args = parser.parse_args(["Alice", "--age", "25"])
print(f"name={args.name}, age={args.age}")
```

Output:

```
name=Alice, age=25
```

**Three ingredients**: `ArgumentParser` is the container, `add_argument` registers a parameter, and `parse_args` does the parsing. The result is a `Namespace` object accessed with dot notation.

## Positional vs. Optional

| Type | Syntax | Required? | Example |
|---|---|---|---|
| Positional | no `--` | yes | `name` |
| Optional | with `--` | no (has a default) | `--age` |

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("src", help="source file path")          # positional, required
parser.add_argument("dst", help="destination file path")     # positional, required
parser.add_argument("-v", "--verbose", action="store_true", help="enable verbose output")

args = parser.parse_args(["/tmp/a.txt", "/tmp/b.txt", "-v"])
print(args.src, args.dst, args.verbose)
```

Output:

```
/tmp/a.txt /tmp/b.txt True
```

**`action="store_true"`** makes the flag a switch: present means `True`, absent means `False`. No value follows it.

## The `type`, `default`, `help` Trio

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--count", type=int, default=1, help="repeat count (default 1)")
parser.add_argument("--name", type=str, default="anonymous", help="name")

args = parser.parse_args(["--count", "3", "--name", "Alice"])
print(args.count * args.name)
```

Output:

```
AliceAliceAlice
```

**`type=int` converts automatically**; `type=str` is actually optional (the default is already a string). `default` is used when the user omits the argument.

## `choices`: Input Validation

`choices` restricts an argument to a fixed set of values and reports an error automatically if it doesn't match.

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--city", choices=["Beijing", "Shanghai", "Guangzhou", "Shenzhen"], help="city")

args = parser.parse_args(["--city", "Hangzhou"])  # not in choices
```

Output:

```
usage: xxx.py [-h] [--city {Beijing,Shanghai,Guangzhou,Shenzhen}]
xxx.py: error: argument --city: invalid choice: 'Hangzhou' (choose from 'Beijing', 'Shanghai', 'Guangzhou', 'Shenzhen')
```

**The error message is generated for you** — no need to write `if city not in [...]`.

## Crash Site: Type Conversion Failure Exits the Program

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--port", type=int, help="port number")

args = parser.parse_args(["--port", "abc"])  # "abc" can't be int
```

Output:

```
usage: xxx.py [-h] [--port PORT]
xxx.py: error: argument --port: invalid int value: 'abc'
```

**When type conversion fails, argparse calls `sys.exit()`**, terminating the program. That means an illegal input can kill an entire program if you use `parse_args` inside a library or an interactive shell. To parse safely, pass a list to `parser.parse_args(args)` instead of relying on `sys.argv`, or catch `SystemExit` with `try/except`.

## Crash Site: An Optional Argument Clashes with a Positional One

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("name", help="user name")
parser.add_argument("--name", help="user name")  # same name as the positional!

parser.parse_args([])
```

Output:

```
usage: xxx.py [-h] [-n NAME] name
xxx.py: error: argument name: conflicting option string: --name
```

**`name` and `--name` are treated as two forms of the same argument**, causing a conflict error. Fix: use a singular noun for the positional argument and a prefixed form for the optional one so they never collide.

## Crash Site: Forgetting a Required Positional Argument

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("file", help="file to process")
parser.add_argument("--encoding", default="utf-8")

args = parser.parse_args(["--encoding", "gbk"])  # forgot to pass file
```

Output:

```
usage: xxx.py [-h] [--encoding ENCODING] file
xxx.py: error: the following arguments are required: file
```

**Positional arguments are required**, and omitting one is an error. That's the biggest difference from optional arguments — don't make "always needed" things optional.

## Summary

- `argparse` in three steps: create an `ArgumentParser`, register parameters with `add_argument`, parse with `parse_args`.
- Positional arguments have no `--` and are required; optional arguments use `--` and may have defaults.
- `type` converts automatically, `default` sets the fallback, `help` documents the argument.
- `action="store_true"` creates a flag: `True` when present, `False` when absent.
- `choices` restricts the allowed values and reports errors automatically.
- A failed type conversion calls `sys.exit()`; be careful in interactive environments.
- A positional argument can't share its name with an optional one, or they'll collide.
