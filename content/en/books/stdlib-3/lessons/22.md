# unittest Basics: Writing Tests with a Framework

> This lesson covers Python's standard-library testing framework, `unittest`: TestCase, assertEqual/assertTrue/assertRaises, plus setUp/tearDown and how to run tests.

## From `assert` to `TestCase`

The previous lesson used bare `assert` statements. The problem: when one fails, the rest stop running and there's no summary report. `unittest` organises tests into classes and methods:

```python
import unittest

def add(a, b):
    return a + b

class TestAdd(unittest.TestCase):
    def test_normal(self):
        self.assertEqual(add(1, 2), 3)

    def test_zero(self):
        self.assertEqual(add(0, 0), 0)

    def test_negative(self):
        self.assertEqual(add(-1, 1), 0)

if __name__ == "__main__":
    unittest.main()
```

Output:

```
...
----------------------------------------------------------------------
Ran 3 tests in 0.000s

OK
```

**The three dots represent three passing tests.** `TestCase` is the container; methods whose names start with `test_` are auto-discovered and executed.

## Common Assertion Methods

| Method | Meaning | Example |
|---|---|---|
| `assertEqual(a, b)` | a == b | `self.assertEqual(add(1,2), 3)` |
| `assertNotEqual(a, b)` | a != b | `self.assertNotEqual(x, 0)` |
| `assertTrue(x)` | x is true | `self.assertTrue(result)` |
| `assertFalse(x)` | x is false | `self.assertFalse(is_empty)` |
| `assertIn(a, b)` | a is in b | `self.assertIn("error", msg)` |
| `assertRaises(Exc)` | raises the given exception | `with self.assertRaises(ZeroDivisionError):` |
| `assertIsNone(x)` | x is None | `self.assertIsNone(result)` |
| `assertGreater(a, b)` | a > b | `self.assertGreater(score, 60)` |

```python
import unittest

def divide(a, b):
    if b == 0:
        raise ValueError("divisor cannot be 0")
    return a / b

class TestDivide(unittest.TestCase):
    def test_normal(self):
        self.assertEqual(divide(6, 3), 2.0)

    def test_raises(self):
        with self.assertRaises(ValueError):
            divide(1, 0)

    def test_in_result(self):
        result = divide(7, 2)
        self.assertIn("3.5", str(result))

if __name__ == "__main__":
    unittest.main()
```

Output:

```
...
----------------------------------------------------------------------
Ran 3 tests in 0.000s

OK
```

**`assertRaises` uses a `with` statement** to verify that the code actually raised the expected exception.

## `setUp` and `tearDown`: Preparation and Cleanup Around Each Test

Some tests need to open a database connection, create a temporary file, or start a service, then close the connection or delete the file afterwards. `setUp` runs **before** each test method; `tearDown` runs **after** each one:

```python
import unittest
import tempfile
import os

class TestFileOps(unittest.TestCase):
    def setUp(self):
        # create a temp file before each test
        self.fd, self.path = tempfile.mkstemp()
        with os.fdopen(self.fd, "w") as f:
            f.write("hello")

    def tearDown(self):
        # delete the temp file after each test
        os.remove(self.path)

    def test_read(self):
        with open(self.path) as f:
            self.assertEqual(f.read(), "hello")

    def test_append(self):
        with open(self.path, "a") as f:
            f.write(" world")
        with open(self.path) as f:
            self.assertEqual(f.read(), "hello world")

if __name__ == "__main__":
    unittest.main()
```

Output:

```
..
----------------------------------------------------------------------
Ran 2 tests in 0.001s

OK
```

**`setUp`/`tearDown` ensure every test starts from a clean initial state**, with no interference between them.

## How to Run Tests

Besides `unittest.main()`, you can run tests from the command line:

```bash
# run an entire module
python -m unittest test_file.py

# run a specific test class
python -m unittest test_file.TestAdd

# run a specific test method
python -m unittest test_file.TestAdd.test_normal

# verbose output
python -m unittest -v test_file.py
```

**`-v` is for verbose** output — it lists every test method and its result, which is invaluable while debugging.

## Crash Site: A Test Method That Doesn't Start with `test_`

```python
import unittest

class TestMath(unittest.TestCase):
    def check_add(self):           # doesn't start with test!
        self.assertEqual(1 + 1, 2)

    def test_sub(self):
        self.assertEqual(1 - 1, 0)

if __name__ == "__main__":
    unittest.main()
```

Output:

```
.
----------------------------------------------------------------------
Ran 1 test in 0.000s

OK
```

**Only one test ran**; `check_add` was ignored — unittest only auto-discovers methods beginning with `test`. This is the most common mistake beginners make: a test method's name must start with `test`.

## Crash Site: `setUp` Raises an Exception, Failing Every Test

```python
import unittest

class TestDB(unittest.TestCase):
    def setUp(self):
        raise ConnectionError("could not connect to database")   # cannot connect

    def test_query(self):
        self.assertEqual(1, 1)

    def test_insert(self):
        self.assertEqual(2, 2)

if __name__ == "__main__":
    unittest.main()
```

Output:

```
EE
======================================================================
ERROR: test_query
----------------------------------------------------------------------
ConnectionError: could not connect to database
----------------------------------------------------------------------
Ran 2 tests in 0.000s

FAILED (errors=2)
```

**An exception in `setUp` marks every method in that class as ERROR** because the preconditions weren't met and the actual test code never ran. This isn't a failure in the code under test — it's a problem with the test environment. Always check `setUp` first when debugging.

## Crash Site: Forgetting to Call the Parent's `setUp`

```python
import unittest

class TestBase(unittest.TestCase):
    def setUp(self):
        self.data = [1, 2, 3]

class TestChild(TestBase):
    def setUp(self):
        # forgot super().setUp()
        self.extra = [4, 5, 6]

    def test_something(self):
        self.assertEqual(len(self.data) + len(self.extra), 6)  # AttributeError!
```

**The child overrode `setUp` without calling `super().setUp()`, so the parent's initialisation never ran** and `self.data` doesn't exist. The fix:

```python
    def setUp(self):
        super().setUp()
        self.extra = [4, 5, 6]
```

## Summary

- `unittest.TestCase` is the test container; methods starting with `test_` are auto-discovered and executed.
- Assertion methods: `assertEqual`, `assertTrue`, `assertIn`, `assertRaises`, and more.
- `assertRaises` uses a `with` statement to verify the expected exception.
- `setUp` runs before each test (preparation); `tearDown` runs after each test (cleanup).
- Running tests: `unittest.main()` in code, or `python -m unittest` from the command line.
- Test method names must begin with `test`, or they'll be skipped.
- A child class that overrides `setUp` must call `super().setUp()`.
