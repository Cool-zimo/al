# The Parsing Layer: Regex Extraction with Fault Tolerance

> This lesson applies the regex knowledge from Chapters 1 and 2 to a real scenario — extracting structured information from log text while ensuring that dirty data never brings the tool down.

## What to Extract From a Log Line

Recapping our log format:

```
2026-01-15 10:23:45 [ERROR] [auth] user login failed: user_id=10086
```

We need to pull out four segments:

- **Timestamp**: `2026-01-15 10:23:45`
- **Level**: `ERROR`
- **Module**: `auth`
- **Message**: `user login failed: user_id=10086`

The capture groups `(...)` from Chapter 1 handle this easily:

```python
import re

LOG_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '   # group 1: time
    r'\[(\w+)\] '                                   # group 2: level
    r'\[(\w+)\] '                                   # group 3: module
    r'(.*)$'                                        # group 4: message
)

line = "2026-01-15 10:23:45 [ERROR] [auth] user login failed: user_id=10086"
match = LOG_PATTERN.match(line)
if match:
    print(f"time={match.group(1)}")
    print(f"level={match.group(2)}")
    print(f"module={match.group(3)}")
    print(f"message={match.group(4)}")
```

Output:

```
time=2026-01-15 10:23:45
level=ERROR
module=auth
message=user login failed: user_id=10086
```

## Wrapping Results in a Dataclass

Use the `dataclass` from Chapter 3 to give the result some structure:

```python
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self) -> str:
        """Extract the hour: '10:23:45' -> '10'"""
        return self.timestamp.split(" ")[1].split(":")[0]

    @property
    def date(self) -> str:
        """Extract the date: '2026-01-15 10:23:45' -> '2026-01-15'"""
        return self.timestamp.split(" ")[0]
```

`dataclass` auto-generates `__init__` and `__repr__`, halving the amount of code you'd write by hand.

## Fault Tolerance: Dirty Data Must Not Crash the Tool

Real logs contain anything: blank lines, malformed lines, extra spaces, stack traces, and encoding garbage. **The parsing layer's rule is: when one line fails to parse, record it and move on to the next.**

```python
def parse_line(line: str) -> LogEntry | None:
    """Parse a single log line; return None on failure"""
    line = line.strip()
    if not line:
        return None
    match = LOG_PATTERN.match(line)
    if match is None:
        return None
    return LogEntry(
        timestamp=match.group(1),
        level=match.group(2),
        module=match.group(3),
        message=match.group(4).strip(),
    )


def parse_lines(lines: list[str]) -> tuple[list[LogEntry], list[str]]:
    """Batch parse; return (successful entries, failed lines)"""
    entries = []
    failed = []
    for line in lines:
        entry = parse_line(line)
        if entry is None:
            failed.append(line.strip())
        else:
            entries.append(entry)
    return entries, failed
```

Key points:

- `parse_line` **never raises**; on a bad format it returns `None`.
- `parse_lines` collects every failed line so you can later report "how many lines failed to parse."
- `strip()` removes leading and trailing whitespace, preventing spaces from causing a match failure.

## Fault Tolerance in Practice

```python
test_lines = [
    "2026-01-15 10:23:45 [ERROR] [auth] user login failed",
    "2026-01-15 10:23:46 [INFO]  [order] order created",      # extra spaces
    "",                                                    # blank line
    "2026-01-15 10:23:47 [WARN] [payment] payment timed out",
    "Traceback (most recent call last):",                  # stack trace line
    "2026-01-15 10:23:48 [DEBUG] [db] query executed",
]

entries, failed = parse_lines(test_lines)
print(f"Successfully parsed {len(entries)} lines")
print(f"Failed to parse {len(failed)} lines: {failed}")

for e in entries:
    print(f"  {e.level:<6} {e.module:<8} {e.message}")
```

Output:

```
Successfully parsed 4 lines
Failed to parse 2 lines: ['', 'Traceback (most recent call last):']
  ERROR   auth     user login failed
  INFO    order    order created
  WARN    payment  payment timed out
  DEBUG   db       query executed
```

## Supporting Multiple Log Formats

In real projects log formats aren't uniform. Some use an `INFO:` prefix, others use `<timestamp>`. Try multiple regex patterns in turn:

```python
import re
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self):
        return self.timestamp.split(" ")[1].split(":")[0]


# Format A: 2026-01-15 10:23:45 [ERROR] [auth] msg
PATTERN_A = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)

# Format B: 2026/01/15 10:23:45 ERROR auth - msg
PATTERN_B = re.compile(
    r'^(\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}) '
    r'(\w+) '
    r'(\w+) '
    r'- '
    r'(.*)$'
)

PATTERNS = [PATTERN_A, PATTERN_B]


def parse_line(line: str) -> LogEntry | None:
    line = line.strip()
    if not line:
        return None
    for pattern in PATTERNS:
        match = pattern.match(line)
        if match:
            return LogEntry(
                timestamp=match.group(1),
                level=match.group(2),
                module=match.group(3),
                message=match.group(4).strip(),
            )
    return None
```

Note that Format B uses `/` instead of `-` as the date separator. That doesn't affect our regex (we're just extracting the raw string), but if you later need to sort by time or compute time differences, the formats will need normalising.

## Crash Site: Greedy Matching Swallows What Follows

```python
# WRONG: using .* to match the level
BAD_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(.+)\] '          # greedy! will match all the way to the last ]
    r'\[(\w+)\] '
    r'(.*)$'
)

line = "2026-01-15 10:23:45 [ERROR] [auth] [extra] message content"
match = BAD_PATTERN.match(line)
print(match.group(2))  # 'ERROR] [auth] [extra'  -- greedily swallowed!
```

**Error output**: the level came out as `ERROR] [auth] [extra`, which is completely wrong.

**The fix**: use `\w+` (a non-greedy character class) instead of `.+`, restricting the level to alphanumeric characters:

```python
GOOD_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)
```

## Crash Site: `parse_line` Raises and Aborts the Whole Process

```python
# WRONG: raising an exception on parse failure
def parse_line_bad(line):
    parts = line.strip().split(" ")
    return LogEntry(
        timestamp=f"{parts[0]} {parts[1]}",
        level=parts[2].strip("[]"),
        module=parts[3].strip("[]"),
        message=" ".join(parts[4:]),
    )

lines = [
    "2026-01-15 10:23:45 [ERROR] [auth] msg1",
    "this line is malformed",                    # IndexError!
    "2026-01-15 10:23:46 [INFO] [order] msg2",
]
for line in lines:
    entry = parse_line_bad(line)  # crashes on the second line, so the third is never reached
    print(entry)
```

**Error output**:

```
LogEntry(timestamp='2026-01-15 10:23:45', level='ERROR', module='auth', message='msg1')
IndexError: list index out of range
```

**Processing stops after the first line, and every line after it is skipped.** In production that could mean "the log analysis quietly stopped halfway, and nobody noticed."

**The correct approach**: return `None` and let the caller decide whether to record the failed line.

## Crash Site: Forgetting to `strip` Causes a Match Failure

```python
# WRONG: no whitespace handling
def parse_line_nostrip(line):
    match = LOG_PATTERN.match(line)  # "  2026-01-15..." has a leading space, so ^ fails to anchor
    return match

line = "  2026-01-15 10:23:45 [ERROR] [auth] msg"
print(parse_line_nostrip(line))  # None! silent failure
```

**Error output**: `None` — a single leading space prevented the match, with no error raised, making it extremely hard to diagnose.

**The fix**: put `line = line.strip()` on the very first line.

## Summary

- The parsing layer uses regex + capture groups to extract structured information, wrapped in a `dataclass`.
- **Fault tolerance is a core requirement of the parsing layer**: return `None` on a bad format, never raise.
- For multiple formats, try several regex patterns in sequence and stop at the first match.
- Greedy matching with `.*` / `.+` can swallow what follows; prefer character classes like `\w+` / `[^]]+`.
- Whitespace is an invisible killer; `strip()` belongs at the very top.
- The parsing layer only parses — no file I/O, no statistics, no output.
