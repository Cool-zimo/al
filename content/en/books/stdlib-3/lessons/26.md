# Project Design: A Log Analysis CLI Tool

> This lesson starts building something genuinely "showcase-worthy" — combining the first 25 lessons into a complete project: a log analysis tool that runs on the command line.

## What We're Building

Picture the scenario: Alice maintains her company's web service, which generates hundreds of megabytes of log files every day. She wants to know "how many ERROR-level entries were logged today," "which hour had the most errors," and "what are the 10 most frequent exceptions." Flipping through logs by hand isn't realistic, and Excel can't load them. That's exactly the problem this tool solves.

The tool is called `logalyzer` (short for log analyzer). It will:

1. Read one or more log files
2. Parse each line with a regex, extracting the timestamp, log level, module name, and message content
3. Run multi-dimensional statistics (level distribution, hourly distribution, top N errors)
4. Output to the console (as a table) or export as JSON / CSV
5. Control all behaviour through command-line arguments

This isn't a toy project. The architectural thinking behind it — layering, parsing, statistics, output, and a CLI entry point — is the same as the tools you'll encounter in real companies.

## The Four-Layer Architecture

A good project doesn't cram everything into one `main.py`; it uses layers. Our tool has four:

```
┌──────────────────────────────────────────────┐
│  CLI layer  (cli.py)                          │
│  argparse subcommands, argument parsing,      │
│  orchestrating the other layers               │
├──────────────────────────────────────────────┤
│  Output layer  (output.py)                    │
│  console tables / JSON export / CSV export    │
├──────────────────────────────────────────────┤
│  Statistics layer  (stats.py)                 │
│  multi-dimensional aggregation with Counter /  │
│  defaultdict                                  │
├──────────────────────────────────────────────┤
│  Parsing layer  (parser.py)                   │
│  regex extraction of time/level/module/       │
│  message, with fault tolerance                │
└──────────────────────────────────────────────┘
```

Each layer does exactly one thing and depends only on the layer below. **The parsing layer doesn't know whether data goes to CSV or the console; the output layer doesn't care whether data came from a file or the network.** This decoupling lets each layer be tested independently.

## Defining the Log Format

We settle on a log format first (the real-world practice of "define the protocol before writing code"):

```
2026-01-15 10:23:45 [ERROR] [auth] user login failed: user_id=10086
2026-01-15 10:23:46 [INFO]  [order] order created: order_id=5001
2026-01-15 10:24:01 [WARN]  [payment] payment timed out: order_id=5001, timeout=30s
```

Four segments: **timestamp** `YYYY-MM-DD HH:MM:SS`, **level** `INFO/WARN/ERROR/DEBUG`, **module** `[xxx]`, and **message** (everything after the colon).

```python
# logalyzer/parser.py
import re
from dataclasses import dataclass


@dataclass
class LogEntry:
    timestamp: str
    level: str
    module: str
    message: str

    @property
    def hour(self):
        """Extract the hour from the timestamp for hourly distribution stats"""
        return self.timestamp.split(" ")[1].split(":")[0]


# regex pattern: time  level  module  message
LOG_PATTERN = re.compile(
    r'^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}) '
    r'\[(\w+)\] '
    r'\[(\w+)\] '
    r'(.*)$'
)


def parse_line(line: str) -> LogEntry | None:
    """Parse a single log line; return None (never raise) on failure"""
    line = line.strip()
    if not line:
        return None
    match = LOG_PATTERN.match(line)
    if match is None:
        return None
    return LogEntry(
        timestamp=match.group(1),
        level=match.group(2),
        module=match.group(3),
        message=match.group(4),
    )


def parse_lines(lines: list[str]) -> tuple[list[LogEntry], list[str]]:
    """Parse multiple lines; return (successful entries, failed lines)"""
    entries = []
    failed = []
    for line in lines:
        entry = parse_line(line)
        if entry is None:
            failed.append(line)
        else:
            entries.append(entry)
    return entries, failed
```

```python
# logalyzer/stats.py
from collections import Counter, defaultdict
from .parser import LogEntry


def level_distribution(entries: list[LogEntry]) -> dict[str, int]:
    """Count entries per log level"""
    counter = Counter(entry.level for entry in entries)
    return dict(counter)


def hourly_distribution(entries: list[LogEntry]) -> dict[str, int]:
    """Count entries per hour"""
    counter = Counter(entry.hour for entry in entries)
    return dict(sorted(counter.items()))


def top_errors(entries: list[LogEntry], n: int = 10) -> list[tuple[str, int]]:
    """Top N most frequent error messages (ERROR level only)"""
    counter = Counter(entry.message for entry in entries if entry.level == "ERROR")
    return counter.most_common(n)


def module_error_count(entries: list[LogEntry]) -> dict[str, int]:
    """Count ERROR entries per module"""
    result = defaultdict(int)
    for entry in entries:
        if entry.level == "ERROR":
            result[entry.module] += 1
    return dict(result)
```

```python
# logalyzer/output.py
import json
import csv
import io
from .parser import LogEntry


def format_table(entries: list[LogEntry], max_rows: int = 20) -> str:
    """Console table output"""
    lines = []
    lines.append(f"{'time':<22} {'level':<8} {'module':<10} message")
    lines.append("-" * 80)
    for entry in entries[:max_rows]:
        msg = entry.message[:50]
        lines.append(f"{entry.timestamp:<22} {entry.level:<8} {entry.module:<10} {msg}")
    if len(entries) > max_rows:
        lines.append(f"... {len(entries)} entries total, showing first {max_rows}")
    return "\n".join(lines)


def export_json(data: dict, indent: int = 2) -> str:
    """Export as a JSON string"""
    return json.dumps(data, ensure_ascii=False, indent=indent)


def export_csv(rows: list[dict], headers: list[str]) -> str:
    """Export as a CSV string"""
    buf = io.StringIO()
    writer = csv.DictWriter(buf, fieldnames=headers)
    writer.writeheader()
    writer.writerows(rows)
    return buf.getvalue()
```

```python
# logalyzer/cli.py
import argparse
import logging
from .parser import parse_lines
from .stats import (
    level_distribution, hourly_distribution,
    top_errors, module_error_count,
)
from .output import format_table, export_json, export_csv


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        prog="logalyzer",
        description="Log analysis CLI tool v0.1.0",
    )
    subparsers = parser.add_subparsers(dest="command", help="subcommands")

    # analyze subcommand
    p_analyze = subparsers.add_parser("analyze", help="parse and analyse logs")
    p_analyze.add_argument("--top", type=int, default=10, help="number of top errors")

    # export subcommand
    p_export = subparsers.add_parser("export", help="export statistics as JSON/CSV")
    p_export.add_argument("format", choices=["json", "csv"], help="export format")

    # stats subcommand
    p_stats = subparsers.add_parser("stats", help="show a statistics summary")
    p_stats.add_argument("--verbose", "-v", action="store_true", help="verbose output")

    return parser


def main(argv: list[str] | None = None) -> int:
    parser = build_parser()
    args = parser.parse_args(argv)
    logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")

    if args.command is None:
        parser.print_help()
        return 0
    # the implementations of each subcommand are filled in over the next lessons
    logging.info(f"Running subcommand: {args.command}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

## Why This Layering Works

- **Testability**: the parsing layer takes a list of strings and returns a list of `LogEntry` objects, touches no file I/O, and can be unit-tested directly.
- **Replaceability**: need to switch the output to an HTML report tomorrow? Only the output layer changes. Supporting JSON-format logs as input next month? Only the parsing layer changes.
- **Clear responsibilities**: a glance at the directory tells you what the project does; new team members won't get lost.

## Crash Site: All Logic Crammed Into One Function

```python

def process_log(file_path, output_format, top_n):
    with open(file_path) as f:
        for line in f:
            # regex parsing
            m = re.match(r'^(\d{4-...', line)
            if m:
                level = m.group(2)
                # statistics
                if level == "ERROR":
                    error_count += 1
                # output
                if output_format == "json":
                    json.dump(...)
                elif output_format == "csv":
                    csv.writer(...)
    # ... 300 lines later
```

**Error output (hypothetical)**: the function grows past 300 lines; changing one output format means reading the whole thing, and adding a new statistic means splicing code into the middle. Unit testing is impossible because the function reads files and prints directly.

## Crash Site: Writing Code Before Designing the Architecture

```python
# WRONG: making it up as you go
def main():
    # try a regex first
    pattern = r'\[(\w+)\]'
    # oh, we also need to parse the time
    # oh, we also need statistics
    # oh, we also need a CLI
    # oh, we also need CSV export
    # and it all ends up in main()
```

**Consequence**: halfway through, you realise the parsed data structure can't support the statistics you want, so you change the data format, which drags in the output layer, and you end up rewriting the whole thing. Spend 10 minutes drawing the architecture first and you'll save 10 hours of rework.

## Summary

- Real projects use layers: parsing / statistics / output / CLI, each with a single responsibility.
- Layers communicate through plain data structures (dataclasses / dicts / lists), never by passing file handles.
- Define the data format before writing code to avoid mid-project rework.
- Each layer being independently testable is the hidden payoff of layered architecture.
- The agreed log format is: `time [level] [module] message`.
