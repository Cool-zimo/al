# Basic Matching: search, match, and findall

> This lesson answers: "Which key opens which lock?" `re.search`, `re.match`, and `re.fullmatch` look nearly identical, but they are three completely different search postures. `findall` and `finditer` each have their own strengths too.

## Three Search Functions, Three Postures

The `re` module provides three of the most commonly used search functions. The only difference is **where they start and where they finish**:

```python
import re

text = "My phone is 13812345678, backup 13987654321"

# search: scan the whole string, return the first match
m = re.search(r'1[3-9]\d{9}', text)
print("search:", m.group())

# match: only matches at the START of the string; returns None otherwise
m2 = re.match(r'1[3-9]\d{9}', text)
print("match:", m2)

# fullmatch: the ENTIRE string must conform to the pattern, nothing more
m3 = re.fullmatch(r'1[3-9]\d{9}', "13812345678")
print("fullmatch clean:", m3.group())
m4 = re.fullmatch(r'1[3-9]\d{9}', "phone 13812345678")
print("fullmatch prefixed:", m4)
```

Output:

```
search: 13812345678
match: None
fullmatch clean: 13812345678
fullmatch prefixed: None
```

| Function | Start point | End point | Typical use |
|---|---|---|---|
| `search` | Anywhere in the string | First match found | Find a pattern inside a passage |
| `match` | **Forced to start at index 0** | Returns once the start matches | Check if a string starts with a pattern |
| `fullmatch` | Start | **Must reach the very end** | Validate that the whole string complies |

**Memory rule**: `search` asks "is it anywhere?"; `match` asks "does it start with?"; `fullmatch` asks "is the whole thing?"

## Crash Site: Using match as search, never matching

This is the most common error. Alice wants to check whether a log contains the word "error":

```python
import re

log = "System running normally, no error detected"

# WRONG: match forces a match at the very beginning
m = re.match(r'error', log)
print(m)
```

Output:

```
None
```

The word "error" is clearly there, yet it returns `None`. Because `match` only looks at the start—the first character is "S", it doesn't match, so it gives up.

**The fix**: use `search` to find something anywhere; only use `match` when you genuinely need to validate "does the string start with this pattern?"

```python
import re

log = "System running normally, no error detected"
m = re.search(r'error', log)
print(m.group())      # error
```

Output:

```
error
```

## findall vs finditer: List or Iterator

`findall` returns **a list of matched strings**; `finditer` returns **an iterator of match objects**. Most of the time `findall` is enough, but the moment you also need "where in the original string did this match land," `finditer` is the only clean solution.

```python
import re

text = "Order DD20260901, Order DD20260915, Order DD20261003"

# findall: just the strings
print("findall:", re.findall(r'DD\d{8}', text))

# finditer: objects with position info
for m in re.finditer(r'DD\d{8}', text):
    print(f"Found {m.group()} at position {m.start()}-{m.end()}")
```

Output:

```
findall: ['DD20260901', 'DD20260915', 'DD20261003']
Found DD20260901 at position 6-16
Found DD20260915 at position 23-33
Found DD20261003 at position 36-46
```

`finditer` is **lazy**: it returns an iterator, emitting match objects one at a time. On very long texts with many matches, it uses far less memory than `findall`, which materializes every result into a list at once.

## Crash Site: Forgetting .group() on a Match Object

`search` returns a **match object**, not a string. Using it directly in a string operation raises an error:

```python
import re

text = "Phone 13812345678"

# WRONG: treating a match object as a string
m = re.search(r'1[3-9]\d{9}', text)
print("Customer phone: " + m)        # concatenating directly
```

Error:

```
TypeError: can only concatenate str (not "re.Match") to str
```

**The fix**: call `.group()` (or its shorthand `.group(0)`) to extract the matched string.

```python
import re

text = "Phone 13812345678"
m = re.search(r'1[3-9]\d{9}', text)
print("Customer phone: " + m.group())
```

Output:

```
Customer phone: 13812345678
```

## Why Raw Strings r"" Are Mandatory

The soul of regex is the backslash: `\d` means digit, `\w` means alphanumeric-or-underscore, `\.` means a literal dot. But Python strings also consume backslashes: `\n` is a newline, `\t` is a tab.

```python
import re

text = "File v1.2.3 released"

# WRONG: in a normal string '\d' is just 'd' preceded by a backslash; regex receives "d"
pat = '\d+\.\d+\.\d+'       # '\d' isn't a special escape in Python, so this happens to run
print(re.findall(pat, text))

# The real disaster: you want to match a literal dot, so you write '\.'
pat2 = '\.'                 # in a Python string '\.' is actually the two chars '\.'
print(re.findall(pat2, text))
```

Output:

```
['1.2.3']
['.', '.', '.']
```

This time it didn't blow up, but only by luck—relying on the fact that "Python doesn't recognize `\d` and `\.`." The real crash site is **building regex dynamically**:

```python
import re

# Want to match "C:\new" — backslash + new
folder = "C:\\new"
pat = "\\\\new"      # in a normal string you must write FOUR backslashes to mean one!
print(re.findall(pat, folder))
```

**The fix**: always use `r`. `r'\d'` is exactly the two characters "backslash" and "d," handed to the regex engine as-is. No more fighting two layers of escaping.

```python
import re

folder = "C:\\new"
pat = r'\\new'        # raw string: two backslashes in source = two backslashes to the engine
print(re.findall(pat, folder))
```

Output:

```
['\\new']
```

## Summary

- `search` scans the whole string for the first match; `match` forces the start; `fullmatch` requires the whole string to conform
- Use `search` to "find whether it exists" in a passage; use `fullmatch` to "validate the whole format"
- `findall` returns a list of strings; `finditer` returns an iterator of match objects with position info—use the latter for big data to save memory
- Match objects need `.group()` to become a string; you can't use them as strings directly
- **Always use `r""` raw strings for regex**, or Python string escaping will swallow your backslashes
