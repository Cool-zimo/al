# Why Regular Expressions Exist

> This lesson answers the question: "How do I pull out the small piece I want from a messy blob of text?" You'll see why `split` and `find` become unbearable, and how one regex can express "find a phone number" in a single line.

## String Methods Break Down Halfway

Alice receives a customer-support chat transcript and needs to extract every phone number from it. Her first instinct is a loop with manual character checks:

```python
text = "Alice called 13812345678 about shipping; Bob called 13987654321 and it was delivered. Backup: 0571-88123456"

# How would you find all phone numbers with string methods alone?
phones = []
i = 0
while i < len(text):
    # Find a segment that starts with '1' followed by 10 digits
    if text[i] == '1' and i + 11 <= len(text):
        seg = text[i:i+11]
        if seg[1:].isdigit():
            phones.append(seg)
    i += 1

print(phones)
```

Output:

```
['13812345678', '13987654321']
```

The code works, but writing it is exhausting and reading it is worse. This only handles "starts with 1 + 10 digits." The moment you need to support landlines with area codes, extensions, or dashes between digits, you pile on `if` branches until it becomes an unmaintainable mess.

**The core limitation of string methods**: `find`, `split`, `startswith`, `isdigit` each express **one very specific action**. They simply cannot describe "text that matches a *pattern*."

## Regex: Turning "Pattern" Into a One-Liner

The same requirement, written with regex:

```python
import re

text = "Alice called 13812345678 about shipping; Bob called 13987654321 and it was delivered"
phones = re.findall(r'1[3-9]\d{9}', text)
print(phones)
```

Output:

```
['13812345678', '13987654321']
```

That short string of symbols—`r'1[3-9]\d{9}'`—**is** the pattern: a `1`, followed by one digit from `3` to `9`, followed by 9 arbitrary digits. The regex engine reads that sentence, scans the entire text automatically, and returns every match.

This is the value of regex: **it turns "describing what text looks like" into a single readable, reusable expression.**

| Requirement | String methods only | Regex |
|---|---|---|
| Find all phone numbers | Manual loop + piles of `if` | `re.findall(r'1[3-9]\d{9}', text)` |
| Validate date `2026-09-28` | Slice into 3 parts, `isdigit` each, check ranges | `re.fullmatch(r'\d{4}-\d{2}-\d{2}', s)` |
| Collapse multiple spaces into one | Loop with `while '  ' in s` | `re.sub(r' +', ' ', s)` |

## Crash Site: Forgetting the Loop, Getting Only One Match

```python
import re

text = "Phone 13812345678 and 13987654321"

# WRONG: search only returns the FIRST match
m = re.search(r'1[3-9]\d{9}', text)
print(m.group())
```

Output:

```
13812345678
```

The second number is gone. `search` finds only the **first** match; `findall` finds **all** of them. These two function names look similar but behave very differently—almost every beginner trips over this.

**The fix**: use `findall` when you want everything, and `search` only when you want the first hit.

```python
import re

text = "Phone 13812345678 and 13987654321"
print(re.findall(r'1[3-9]\d{9}', text))   # all matches
```

Output:

```
['13812345678', '13987654321']
```

## Crash Site: Treating Regex as a String, Escapes Everywhere

```python
import re

text = "The price is £99.9"
# WRONG: inside a normal string, \. is interpreted first; regex receives "99.9"
pat = '99\.9'
print(re.findall(pat, text))
```

Output:

```
['99.9']
```

This time it "happens" to work, only because `\.` isn't a special escape in Python strings. The real disaster looks like this:

```python
import re

text = "Path C:\\new\\test"
# WRONG: '\n' in a Python string is a newline; regex never sees backslash-n
pat = '\new'          # actually a newline + 'ew'
print(re.findall(pat, text))
```

Error or no match. Backslash is the workhorse character in regex (`\d`, `\w`, `\s`, `\b`), and it's *also* the escape character in Python strings. **Two layers of escaping collide into a disaster.**

**The fix**: always prefix regex strings with `r` to make them raw strings. `r'\n'` is literally the two characters "backslash" and "n"—Python won't eat it.

```python
import re

text = "Path C:\\new\\test"
pat = r'\new'          # raw string: backslash and n are literal
print(re.findall(pat, text))
```

## What Regex Can Do—and What It Can't

Regex excels at **"finding text by pattern"**:

- **Validation**: does this string conform to a format (phone, email, ID number)?
- **Extraction**: pull out the part you want from a blob of text
- **Replacement**: uniformly rewrite all occurrences of a pattern
- **Splitting**: cut on irregular delimiters like "one or more spaces" or "consecutive commas"

Regex is **not good at** things with structure and nesting—parsing HTML tag hierarchies, parsing JSON. For those, use a dedicated parser (`html.parser` is covered later; `json` was covered in Volume 2).

**One-line summary**: regex is for **one-dimensional text patterns**, not **hierarchical tree structures**.

## A Simple End-to-End Example

Here's a realistic scenario: an order note mixes a name, phone number, and amount, and you need to extract the phone and amount.

```python
import re

note = "Recipient Alice, phone 13812345678, paid £299.5, note: rush delivery"

phone = re.search(r'1[3-9]\d{9}', note)
amount = re.search(r'(\d+(\.\d+)?)\s*pounds', note)

print("Phone:", phone.group() if phone else "none")
print("Amount:", amount.group(1) if amount else "none")
```

Output:

```
Phone: 13812345678
Amount: 299.5
```

Notice the amount pattern: `\d+(\.\d+)?` means "a run of digits, optionally followed by a decimal point and more digits." `\s*pounds` means "zero or more whitespace, then the word pounds." Together it covers variations like "299.5pounds" with optional spacing.

## Summary

- String methods express "one specific action"; only regex can describe "a text pattern"
- `re.search` finds the first match, `re.findall` finds all—similar names, very different behavior
- **Always use the `r` prefix for regex strings**, or Python's string escaping will swallow your backslashes
- Regex is great for finding text by pattern: validate, extract, replace, split
- Regex is bad at nested structures (HTML, JSON); use a dedicated parser for those
