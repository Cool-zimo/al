# Regex Performance: Catastrophic Backtracking

> This lesson answers: "Why does my regex hang?" Some seemingly harmless patterns, when faced with "almost matching" input, cause the engine to backtrack exponentially—and bring down a service. Learning to recognize nested quantifiers is regex's rite of passage.

## An Example That Will Hang

First, a seemingly normal piece of code:

```python
import re

pat = re.compile(r'^(a+)+b$')
text = "aaaaaaaaaaaaaaaaaaaaaaaaac"   # 25 a's then a c

# Run this and you'll find it hangs for several seconds
print(pat.match(text))
```

Output (after a very long wait):

```
None
```

There's **no `b` at all** in the string. Why did it take so long? Because the regex engine is "trying its hardest."

`(a+)+` means "**one or more a's, and that group repeated one or more times**." When the engine finds a `c` instead of a `b` at the end, it has to **backtrack**: make `a+` swallow one fewer a, let the outer `+` absorb that a instead, then check whether `b` now works—and try every possible split.

## Why It's Exponential

`(a+)+` can split 20 a's in **2^19 ways** (each a can belong to the inner or outer layer). When the engine is "almost successful," it tries every split—complexity **O(2^n)**.

```python
import re
import time

pat = re.compile(r'^(a+)+b$')

for n in [10, 20, 25, 28]:
    text = "a" * n + "c"
    t0 = time.time()
    pat.match(text)
    print(f"n={n:2d} took {time.time()-t0:.3f}s")
```

Typical output (actual numbers vary by machine, but **the growth trend** is what matters):

```
n=10 took 0.000s
n=20 took 0.002s
n=25 took 0.064s
n=28 took 0.520s
```

Each few extra characters multiplies the time. This is **catastrophic backtracking**. It doesn't raise an error or throw an exception—it just **hangs**. In a web service, that's a perfect denial-of-service.

## Nested Quantifiers: The Culprit

Any structure where "**a quantifier wraps a quantifier**" deserves suspicion:

| Dangerous pattern | Problem |
|---|---|
| `(a+)+` | inner `+` + outer `+`, exponential |
| `(a*)*` | same family as above |
| `(a|a)*` | alternation + quantifier, exponential |
| `(\w+)*` | greedy inner, quantifier outside |

**Key observation**: in all of these, the inner and outer layers are **fighting over the same characters**, so the engine can only probe back and forth.

## Crash Site: Nested Quantifiers While Validating Tags

Alice wanted to check whether a string was made of matching angle-bracket tags:

```python
import re

# WRONG: nested quantifier; malicious input will hang it
TAG_RE = re.compile(r'^<([^>]+)>.*</\1>$')
evil = "<a>" + "a" * 30 + "<"
TAG_RE.match(evil)      # hangs
```

It looks fine, but the combination of `.+` and `.*` plus backtracking causes problems when input is "almost closed."

**Fix 1: make it non-greedy, removing the backtracking space**:

```python
import re

TAG_RE = re.compile(r'^<([^>]+)>.*?</\1>$')   # note .*? non-greedy
print(TAG_RE.match("<div>hello</div>"))
```

**Fix 2: use a more precise character class instead of `.`**—the standard-library-friendly approach:

```python
import re

# The tag content can't contain < or >, so say so explicitly and remove any need to backtrack
TAG_RE = re.compile(r'^<([^>]+)>([^<]*)</\1>$')
print(TAG_RE.match("<div>hello</div>").groups())
```

Output:

```
('div', 'hello')
```

`[^<]*` explicitly says "no left-angle bracket allowed inside," so the engine has **no other choices to backtrack into**—the backtracking space is eliminated entirely.

## Avoidance Checklist

Ask yourself three questions when writing regex:

1. **Are there nested quantifiers?** `(a+)+`, `(.+)*`, `(.*)*`—rewrite every one.
2. **Can I use a more precise character class?** Replacing `.` with a negated class like `[^...]` kills backtracking branches.
3. **Is the input controlled?** If a user can submit arbitrary strings to this regex, impose a length limit.

```python
import re

def safe_match(pat, text, limit=1000):
    """Add a length fuse for untrusted input"""
    if len(text) > limit:
        raise ValueError(f"input too long: {len(text)} > {limit}")
    return pat.match(text)

pat = re.compile(r'^(a+)+b$')
print(safe_match(pat, "a" * 50 + "c"))   # raises immediately, no hang
```

Output:

```
ValueError: input too long: 51 > 1000
```

**This "fuse" is the simplest and most effective defense against catastrophic backtracking**: since backtracking complexity grows exponentially with input length, just cap the length. Web frameworks and logging systems use this trick everywhere.

## Summary

- Catastrophic backtracking: nested quantifiers make the engine probe every split exponentially; the symptom is a hang, not an error
- `(a+)+`, `(a*)*`, `(\w+)*`—"quantifier wrapping quantifier" patterns are the prime suspects
- Use **non-greedy** `(.*?)` or **a more precise character class** `[^<]*` instead of `.` to eliminate backtracking branches
- For untrusted input, add a **length limit**—the simplest effective defense
- Regex performance issues don't error out; they just "suddenly slow down," so you must recognize them proactively
