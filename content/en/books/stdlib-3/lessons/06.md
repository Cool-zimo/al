# Compiling Regex: re.compile and Flags

> This lesson answers: "How do I handle performance and readability when I use the same pattern many times?" `re.compile` precompiles a pattern into an object. `IGNORECASE`, `MULTILINE`, and `DOTALL` each solve one specific pain point.

## re.compile: Precompile the Pattern

In earlier lessons we used `re.findall(r'\d+', text)`—the "functional" style. Internally, it **compiles** the pattern string on every call. If you use the same pattern repeatedly across a loop or over many strings, that repeated compilation is wasted work.

```python
import re

texts = ["Order DD20260927", "Customer C001", "Order DD20260928", "note: none"]

# Recommended: compile once, reuse many times
pat = re.compile(r'DD(\d{8})')
results = [pat.findall(t) for t in texts]
print(results)
```

Output:

```
[['20260927'], [], ['20260928'], []]
```

`re.compile` returns a `re.Pattern` object. It has methods that mirror the `re` module one-for-one: `.search()`, `.findall()`, `.sub()`, `.split()`, `.finditer()`. Usage is identical, except you **leave out the pattern argument**.

## When You Should Compile

You don't need to compile everywhere. The rule is simple:

| Scenario | Compile? |
|---|---|
| Pattern used once or twice | No—`re.findall(...)` is cleaner |
| Pattern used repeatedly in a loop/function | **Yes**—compile once, reuse |
| Pattern used in multiple places and deserves a name | **Yes**—the name is documentation |
| Writing a utility function called from many places | Compile once and store it as a module-level constant |

```python
import re

# Module-level compilation: the name IS the documentation
PHONE_RE = re.compile(r'1[3-9]\d{9}')
ORDER_RE = re.compile(r'DD(\d{8})')

def extract_info(text):
    phone = PHONE_RE.search(text)
    order = ORDER_RE.search(text)
    return {
        "phone": phone.group() if phone else None,
        "order": order.group(1) if order else None,
    }

print(extract_info("phone 13812345678 order DD20260927"))
```

Output:

```
{'phone': '13812345678', 'order': '20260927'}
```

**A second benefit of compiling is readability**: `PHONE_RE` is a comment in its own right, far easier to understand than `r'1[3-9]\d{9}'` scattered through the code.

## The Three Most Useful Flags

Flags can be passed in when you compile. They are attributes of the `re` module; combine multiple flags with `|`.

### re.IGNORECASE (shorthand re.I): Case-Insensitive

```python
import re

pat = re.compile(r'python', re.IGNORECASE)
print(pat.findall("Python python PYTHON pYtHoN"))
```

Output:

```
['Python', 'python', 'PYTHON', 'pYtHoN']
```

### re.MULTILINE (shorthand re.M): Make ^ and $ Match Every Line

Without `MULTILINE`, `^` matches only the very beginning of the string and `$` only the very end.

```python
import re

text = """ERROR: disk full
INFO: running normally
ERROR: out of memory"""

# Without MULTILINE: ^ERROR only matches at the very start
print("without:", re.findall(r'^ERROR.*', text))

# With MULTILINE: ^ matches the start of each line
print("with M:", re.findall(r'^ERROR.*', text, re.MULTILINE))
```

Output:

```
without: []
with M: ['ERROR: disk full', 'ERROR: out of memory']
```

### re.DOTALL (shorthand re.S): Make . Match Newlines

We saw this in Lesson 3. `re.DOTALL` makes `.` match **any character including newlines**—essential for cross-line text.

```python
import re

text = """first line
second line
third line"""

print("without S:", re.findall(r'first(.*)third', text))
print("with S:", re.findall(r'first(.*)third', text, re.DOTALL))
```

Output:

```
without S: []
with S: [' line\nsecond line\n']
```

## Crash Site: Passing Flags in the Wrong Position

When you compile, the flags are the second argument. When you call `re.findall`, flags are the **last** positional argument. Get the order wrong and you get an error:

```python
import re

text = "Python"
# WRONG: swapping text and flags turns text into the count argument
pat = re.compile(r'python', re.IGNORECASE)
print(re.findall(r'python', re.IGNORECASE, text))
```

Error:

```
TypeError: findall() takes at most 3 arguments (4 given)
```

`findall(pattern, string, flags)`—the order is **pattern, string, flags**. Flags must come last.

**The fix**:

```python
import re

text = "Python"
pat = re.compile(r'python', re.IGNORECASE)
print(pat.findall(text))                       # use the object method after compiling
print(re.findall(r'python', text, re.IGNORECASE))  # or pass flags last in findall
```

Output:

```
['Python']
['Python']
```

## Crash Site: Inline Flags in the Wrong Position

Flags can also be written directly into the pattern using `(?i)`, `(?m)`, `(?s)`. But **they only affect what follows them**, and parentheses affect their scope:

```python
import re

text = "PYTHON"
# WRONG-ish: inline flag at the very start affects the whole expression (works here)
print(re.findall(r'(?i)python', text))
# To make only part case-insensitive, wrap it in a group
print(re.findall(r'fixed(?i:python)', "fixedPYTHON"))
```

Output:

```
['PYTHON']
['fixedPYTHON']
```

The value of inline syntax is **local effect**: `(?i:...)` makes only the part inside case-insensitive, while the outer "fixed" stays case-sensitive. Get the scope wrong and you either over-match or match nothing.

## Summary

- `re.compile(pattern)` compiles a pattern into a `Pattern` object; reuse `.findall()` etc. to avoid repeated compilation
- No need to compile for one or two uses; **always compile** for loops, utility functions, or when you want to give the pattern a name
- `IGNORECASE` (`I`): ignore case
- `MULTILINE` (`M`): makes `^` and `$` match the start/end of every line
- `DOTALL` (`S`): makes `.` match newlines
- Combine flags with `|`; in `findall`, flags must be the last argument
- Inline flags `(?i)`, `(?m)`, `(?s)` take effect locally, scoped to what follows or to the enclosing group
