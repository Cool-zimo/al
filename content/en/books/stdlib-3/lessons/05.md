# Replacement and Splitting: sub and split

> This lesson covers two things: "change what you matched into something else" and "cut by a pattern." `re.sub` can use a string, a function, or group references. `re.split` can cut on irregular delimiters like "one or more spaces."

## re.sub: Replace Matches With Something Else

`re.sub(pattern, repl, string)` takes three arguments: the pattern, the replacement, and the original string. It returns a **new** string—the original is not modified.

```python
import re

text = "My phone is 13812345678, backup 13987654321"

# Mask the middle 4 digits of every phone number
masked = re.sub(r'(1[3-9]\d{3})\d{4}(\d{4})', r'\1****\2', text)
print(masked)
```

Output:

```
My phone is 1381****5678, backup 1398****4321
```

This example uses **group references**: `(1[3-9]\d{3})` is group 1, `(\d{4})` is group 2, and `\1` / `\2` in the replacement string mean "the content matched by groups 1 and 2." The result is "first four + four stars + last four"—both anonymized and still readable.

## Crash Site: \1 in the Replacement String Gets Eaten by Python

This is the most important trap in this lesson. Alice follows a tutorial to write an anonymizer:

```python
import re

text = "Phone 13812345678"
# WRONG: no r prefix; '\1' becomes a control character in Python
result = re.sub(r'1(\d{3})\d{4}(\d{4})', '\1***\2', text)
print(result)
```

Error:

```
re.error: invalid group reference 1
```

In a normal Python string, `'\1'` is an **octal escape** (an invisible character)—it never reaches the regex engine. The same goes for `\2`. Regex group references like `\1` must be the two literal characters in a **raw string**.

**The fix**: add the `r` prefix to the replacement string too.

```python
import re

text = "Phone 13812345678"
result = re.sub(r'1(\d{3})\d{4}(\d{4})', r'\1***\2', text)
print(result)
```

Output:

```
Phone 138***5678
```

**Memory rule**: any regex-related string containing a backslash gets the `r` prefix—the pattern string needs it, and so does the `sub` replacement string.

## Using a Function for Replacement: The Only Way Out for Complex Logic

If the replacement is a fixed piece of text, a string is enough. But when you need to **compute** the replacement dynamically based on the match, you pass a function as `repl`.

```python
import re

text = "price £100, qty 3, price £250"

def double_price(match):
    # match is the match object; group(1) is the captured number
    val = int(match.group(1))
    return str(val * 2)

result = re.sub(r'price (\d+)', double_price, text)
print(result)
```

Output:

```
price £200, qty 3, price £500
```

The function receives the **match object** and must return a string—that return value becomes the replacement. This mechanism makes `sub` dramatically more powerful: formatting, lookups, and conditional logic all become possible.

```python
import re

# Replace English number words with digits
en = {"one": "1", "two": "2", "three": "3", "ten": "10"}
text = "chapter one, chapter two, chapter ten"

result = re.sub(r'chapter (\S)', lambda m: "chapter " + en.get(m.group(1), m.group(1)), text)
print(result)
```

Output:

```
chapter 1, chapter 2, chapter 10
```

## re.split: Splitting by Pattern

`str.split` can only cut on one fixed delimiter. `re.split` can cut on **irregular** delimiters like "one or more spaces" or "consecutive commas or semicolons."

```python
import re

text = "apples,,bananas;;oranges,,,melons"

# Split on one or more commas/semicolons
print(re.split(r'[,;]+', text))
```

Output:

```
['apples', 'bananas', 'oranges', 'melons']
```

Watch out for empty strings at the ends: depending on how `re.split` handles it, leading/trailing delimiters can produce empty strings:

```python
import re

text = ",,apples,,bananas,,"
print(re.split(r'[,;]+', text))        # leading delimiter produces an empty string
```

Output:

```
['', 'apples', 'bananas', '']
```

**Solution**: filter empties with `filter(None, ...)` or a list comprehension `[x for x in ... if x]`.

## Crash Site: Capturing Groups in split Decide "Whether to Keep the Delimiter"

When `re.split` contains a **capturing group**, the captured delimiter appears in the result—a frequently overlooked feature.

```python
import re

text = "apples,bananas;oranges"

# WRONG: with a group, the delimiter ends up in the result
print(re.split(r'([,;])', text))
```

Output:

```
['apples', ',', 'bananas', ';', 'oranges']
```

The delimiter is inserted back into the result list as "captured content." Sometimes this is intentional (e.g., you want to keep the delimiter to reconstruct the text), but most of the time it's a surprise.

**The fix**: when you don't want the delimiter, use a **non-capturing group** `(?:)` or skip the parentheses entirely.

```python
import re

text = "apples,bananas;oranges"
print(re.split(r'[,;]', text))            # no delimiter
print(re.split(r'(?:[,;])', text))        # non-capturing, also no delimiter
```

Output:

```
['apples', 'bananas', 'oranges']
['apples', 'bananas', 'oranges']
```

## Summary

- `re.sub(pattern, repl, string)` returns a new string; it never modifies the original
- Use `\1`, `\2` to reference groups in the replacement, and **always add the `r` prefix**—otherwise `\1` is treated as an octal escape
- `sub`'s `repl` can be a function: it receives the match object and returns the replacement string, the only proper way to handle dynamic replacement
- `re.split` cuts by "pattern," ideal for irregular or repeated delimiters
- If the `split` pattern has a **capturing group**, delimiters appear in the result; use `(?:)` to avoid that
