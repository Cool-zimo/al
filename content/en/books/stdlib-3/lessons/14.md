# itertools Essentials: chain, product, combinations, permutations, groupby

> This lesson covers the five most-used `itertools` tools in one pass. They're all **lazy iterators**—memory-efficient and composable. The focus is `groupby`: **it must be pre-sorted first**, which is its nastiest trap.

## What Is itertools?

The `itertools` module provides a set of "iterator construction tools." Their return values are all **iterators**—they emit one element at a time and don't build the full list upfront. That's **lazy evaluation**.

```python
import itertools

# What's returned is an iterator object, not a list
print(itertools.chain([1, 2], [3, 4]))
print(list(itertools.chain([1, 2], [3, 4])))
```

Output:

```
<itertools.chain object at 0x...>
[1, 2, 3, 4]
```

**Why lazy?** When processing large data, materializing the whole result with `list()` up front could OOM you. An iterator lets you "compute one, take one," consuming it incrementally in a `for` loop.

## chain: Join Multiple Iterables End to End

`chain` joins several sequences into "what looks like one" sequence, with **no intermediate list** produced.

```python
import itertools

a = [1, 2, 3]
b = [4, 5, 6]
c = [7, 8, 9]

print(list(itertools.chain(a, b, c)))

# The more common use: flatten one level of a 2D list
matrix = [[1, 2], [3, 4], [5, 6]]
flat = list(itertools.chain.from_iterable(matrix))
print(flat)
```

Output:

```
[1, 2, 3, 4, 5, 6, 7, 8, 9]
[1, 2, 3, 4, 5, 6]
```

`chain.from_iterable` takes "an iterable of iterables" and flattens it one level—a high-frequency operation on 2D data.

## product: Cartesian Product

`product` generates the **Cartesian product** of several sequences (every possible combination):

```python
import itertools

colors = ["red", "blue"]
sizes = ["S", "M", "L"]

for combo in itertools.product(colors, sizes):
    print(combo)
```

Output:

```
('red', 'S')
('red', 'M')
('red', 'L')
('blue', 'S')
('blue', 'M')
('blue', 'L')
```

**This is the go-to for "full-combination testing"**: SKU generation, test matrices, brute-force search—all its home turf.

```python
import itertools

# Password dictionary (illustrative)
chars = "ab"
length = 3
for pwd in itertools.product(chars, repeat=length):
    print("".join(pwd))
```

Output:

```
aba
abb
baa
bab
bba
bbb
```

`repeat=n` means "multiply the same sequence by itself n times"—the shortest way to generate equal-length combinations.

## combinations and permutations: Combinations and Permutations

- `combinations`: **order doesn't matter**; pick k from n; `(A,B)` and `(B,A)` are the same
- `permutations`: **order matters**; `(A,B)` and `(B,A)` count as two

```python
import itertools

items = ["A", "B", "C"]

print("combinations 2:", list(itertools.combinations(items, 2)))
print("permutations 2:", list(itertools.permutations(items, 2)))
```

Output:

```
combinations 2: [('A', 'B'), ('A', 'C'), ('B', 'C')]
permutations 2: [('A', 'B'), ('A', 'C'), ('B', 'A'), ('B', 'C'), ('C', 'A'), ('C', 'B')]
```

3 combinations, 6 permutations—permutations are exactly k! times combinations (here 2! = 2, 3×2=6).

## Crash Site: groupby Without Sorting Shatters the Groups

`groupby` groups **adjacent, equal** elements. It does **not** sort the sequence first.

```python
import itertools

data = ["apple", "apple", "banana", "apple", "banana", "banana"]

# WRONG: not sorted first, equal elements aren't adjacent, groups get split
groups = itertools.groupby(data)
for key, grp in groups:
    print(key, "->", list(grp))
```

Output:

```
apple -> ['apple', 'apple']
banana -> ['banana']
apple -> ['apple']
banana -> ['banana', 'banana']
```

"apple" got split into two groups, and "banana" too. **This is nearly every groupby user's first trap.**

**The fix**: sort first with `sorted` so equal elements sit next to each other, then `groupby`.

```python
import itertools

data = ["apple", "apple", "banana", "apple", "banana", "banana"]

for key, grp in itertools.groupby(sorted(data)):
    print(key, "->", list(grp))
```

Output:

```
apple -> ['apple', 'apple', 'apple']
banana -> ['banana', 'banana', 'banana']
```

**Remember the rule: always `sorted` before `groupby`.**

## Crash Site: Custom Key Grouping, Where the Key and Sort Must Agree

`groupby` can take a `key` function to group by "some attribute." A common need is grouping by "first letter":

```python
import itertools

words = ["banana", "apple", "avocado", "cherry", "blueberry"]

# Group by first letter
for key, grp in itertools.groupby(sorted(words), key=lambda w: w[0]):
    print(key, "->", list(grp))
```

Output:

```
a -> ['apple', 'avocado']
b -> ['banana', 'blueberry']
c -> ['cherry']
```

**Key point**: `sorted` and `groupby` must receive the **same** `key` function. If sorting uses the default rule but grouping uses `key`, their definitions of "adjacent" disagree and the result is wrong.

```python
import itertools

words = ["banana", "apple", "avocado", "cherry"]

# WRONG: sorted didn't get a key, so it sorts by whole word by default,
# but grouping uses the first letter - the two rules disagree
result = itertools.groupby(sorted(words), key=lambda w: w[0])
print([(k, list(g)) for k, g in result])
```

Output (order looks off; "avocado" lands after the a group):

```
[('a', ['apple', 'avocado']), ('b', ['banana']), ('c', ['cherry'])]
```

This time the result happens to look passable, because the first letter coincides with the default sort order. **Swap in numbers, non-ASCII text, or compound objects and it breaks immediately.** The correct approach is to pass `key` to both:

```python
import itertools

words = ["banana", "apple", "avocado", "cherry", "blueberry"]

key = lambda w: w[0]
for k, grp in itertools.groupby(sorted(words, key=key), key=key):
    print(k, "->", list(grp))
```

## Summary

- `itertools` tools return **iterators** (lazy): memory-efficient and composable
- `chain` / `chain.from_iterable`: join end-to-end, flatten one level
- `product`: Cartesian product; `repeat=n` self-multiplies one sequence n times
- `combinations` ignores order, `permutations` respects it; permutations are k! times combinations
- **`groupby` only merges adjacent equal-key elements; you usually need `sorted` first**, or groups get split
- When grouping by a custom `key`, `sorted` and `groupby` must receive the **same key function**
