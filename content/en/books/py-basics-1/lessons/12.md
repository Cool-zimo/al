# input Always Gives You a String

> Lesson 11 left a cliffhanger: why does `18 + 18` become `1818`?
>
> This lesson nails it down. It's the single **most common and most baffling** beginner trap — because the code looks perfectly fine and the result is absurd. Understand it and you'll save yourself hours of debugging later.

## First, the weird phenomenon

```python
a = input("Enter a number: ")
b = input("Enter another number: ")
print(a + b)
```

Type `18` and `18`. You expect `36`; you get:

```
1818
```

And this:

```python
age = input("How old are you?")
print(age + 1)
```

Type `18`, expect `19`, get a wall of red:

```
TypeError: can only concatenate str (not "int") to str
```

**Two symptoms, one root cause.**

## Root cause: input gives you *text*

Lesson 11 said it: `input()` returns a string.

So when the user types `18`, you don't get **the number eighteen** — you get **a piece of text made of the characters "1" and "8"**. Type-wise it's no different from the user typing "abc".

See it yourself with `type()` (the tool from lesson 10):

```python
a = input("Enter a number: ")
print(type(a))
```

Type `18`:

```
<class 'str'>
```

`str` means string. **Even if the user types pure digits, Python treats it as text.**

Why designed this way? Because Python can't read your intent:

| User types | You might mean |
|---|---|
| `18` | the number eighteen (computing an age) |
| `18` | the text "18" (a house number — "18" and "18.0" differ) |
| `007` | text (the leading zero matters; as a number it becomes 7) |
| `+86 138...` | a phone number (text, not a quantity) |

Python chooses **not to guess**. Remember lesson 1: *the computer is blazing fast and won't guess a single thing*. It always returns a string and leaves the conversion decision to you.

## So what is + actually doing?

Key insight: **`+` means different things for different types.**

```python
print(18 + 18)      # number + number  → arithmetic  → 36
print("18" + "18")  # text  + text     → concatenate → "1818"
```

Same symbol, two behaviours. Python isn't messing with you — it decides based on **the types of the operands**.

A few more, to feel it:

```python
print("Hello" + "World")   # HelloWorld (concatenate)
print("cat" * 3)           # catcatcat (strings can be multiplied — repeat!)
print(3 * 5)               # 15 (arithmetic)
```

**Strings can be multiplied?** Yes — `"cat" * 3` repeats it three times. Which proves the point: the meaning of `+` and `*` depends on what they operate on.

Back to the `age + 1` error:

```
TypeError: can only concatenate str (not "int") to str
```

Translation: *I can only join a string to a string; I can't join a string to an integer.*

Python is telling you: **you mixed types.** It refuses to guess — do you want to treat 1 as text and get `"181"`, or convert age and get `19`? It doesn't know, so it errors and makes you say.

## Fix: convert, then compute

To do arithmetic, convert with `int()` or `float()` (lesson 10).

```python
a = input("Enter a number: ")
b = input("Enter another number: ")
print(int(a) + int(b))
```

Type `18` and `18`:

```
36
```

Correct.

Three ways to write it — see the difference:

```python
# Style 1: convert into a new variable (clearest; recommended while learning)
a = input("Number: ")
num = int(a)
print(num + 10)

# Style 2: convert and use on one line (compact)
a = input("Number: ")
print(int(a) + 10)

# Style 3: convert the moment you receive it (most common)
num = int(input("Number: "))
print(num + 10)
```

Style 3 is the tightest: user types → immediately converted → stored in `num`. From then on **`num` is cleanly a number**, no type confusion.

**Industry habit:** whenever input is used for arithmetic, **convert at the moment you receive it**. Don't keep a string version floating around.

Use `float()` for decimals:

```python
price = float(input("Price? "))
print(price * 0.8)   # 20% off
```

## Common crashes

### Crash 1: converted one input, forgot the other

```python
a = int(input("Number: "))
b = input("Number: ")      # ← forgot to convert
print(a + b)               # still errors
```

`int` and `str` still can't be added. Convert both, or neither.

### Crash 2: the user typed a non-number

```python
age = int(input("How old are you?"))
```

User types "eighteen" or "abc":

```
ValueError: invalid literal for int() with base 10: 'abc'
```

`int()` only converts text that **looks like an integer**. That's a new problem — **the program crashes**.

How to handle it? Honestly, **that's beyond this stage**. The full fix is exception handling (`try...except`), covered in *Python Basics 3*.

For now just know: **`int(input(...))` crashes on illegal input**, and that's a known, normal limitation. Lesson 14 shows `strip()` to clean up small things like stray spaces.

### Crash 3: converting when you shouldn't

```python
phone = int(input("Phone number: "))
```

User types `13800138000` — it converts fine, but it's **wrong**. A phone number is an identifier, not a quantity; leading zeros get lost (`0138...` becomes `138...`).

**Test: will this value take part in arithmetic?** If not, don't convert.

## Three things to remember

1. `input()` **always returns a string**, even when the user types digits
2. To do math, **convert first** with `int()` / `float()`
3. `+` depends on type: numbers add, strings concatenate
