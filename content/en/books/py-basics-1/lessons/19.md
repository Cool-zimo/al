# Combining Conditions: `and` / `or` / `not`

> So far, every `if` has had exactly **one** condition.
>
> But real decisions are compound: "**both** over 18 **and** a member," "**either** raining **or** snowing."
>
> This lesson gives you three tools for gluing conditions together: `and`, `or`, `not`.

## 1. `and`: Both Must Be True

```python
age = 20
is_member = True

if age >= 18 and is_member:
    print("Members only")
```

`and` means **both**. The whole condition is True only when **both sides are True**.

The truth table:

| Left | Right | Result |
|---|---|---|
| True | True | **True** |
| True | False | False |
| False | True | False |
| False | False | False |

One sentence to remember it: **with `and`, a single False makes the whole thing False.**

### ⚠️ Both Sides of `and` Must Be Complete Conditions

A very frequent beginner error:

```python
if age > 18 and < 60:        # ✗ error
    print("Adult, not retired")
```

Why is it wrong? Because `< 60` has **no subject** — Python doesn't know what is supposed to be less than 60.

Spell it out:

```python
if age > 18 and age < 60:    # ✓
    print("Adult, not retired")
```

**Mantra: `and` / `or` join two complete tests; each side must stand on its own.**

## 2. `or`: At Least One Is True

```python
weather = "rain"

if weather == "rain" or weather == "snow":
    print("Take an umbrella")
```

`or` means **either**. The whole condition is True when **at least one side is True**.

| Left | Right | Result |
|---|---|---|
| True | True | True |
| True | False | **True** |
| False | True | **True** |
| False | False | False |

One sentence: **with `or`, a single True makes the whole thing True.**

### `or` Has the Same Trap — But Worse

```python
if weather == "rain" or "snow":        # ✗ logic error, and no crash!
    print("Take an umbrella")
```

This one is sneakier than the `and` case — **it doesn't raise an error, it just always takes the umbrella.**

Why? `"snow"` is a non-empty string, and Python treats that as True. So the condition becomes:

> weather is rain **or** True

Which is always True, whatever the weather.

**This is the most dangerous kind of bug: no error, just silently wrong results.**

Correct version:

```python
if weather == "rain" or weather == "snow":    # ✓
    print("Take an umbrella")
```

## 3. `not`: Flip It

```python
is_weekend = False

if not is_weekend:
    print("Go to work")
```

`not` means **invert**: True becomes False, False becomes True.

| Before | After `not` |
|---|---|
| True | False |
| False | True |

`not` takes a single operand and goes in front of it.

A common use:

```python
if not name == "":
    print("Hello, " + name)
```

Though this has a more idiomatic form. An empty string counts as False in Python, so you can write:

```python
if name:
    print("Hello, " + name)
```

## 4. Python's Signature Move: Chained Comparisons

To test whether a score is between 60 and 80, most languages make you write:

```python
if score >= 60 and score < 80:
    print("Average")
```

Python lets you write it the way you would in math:

```python
if 60 <= score < 80:
    print("Average")
```

**This is wrong in most other languages, but perfectly legal in Python** — and it reads exactly like a mathematical interval.

The two are fully equivalent; use whichever reads better. The chained form is recommended because it announces "this is a range" at a glance.

## 5. Precedence

When you mix them, the order is:

```
not  >  and  >  or
```

`not` is evaluated first, then `and`, then `or`.

```
if age < 12 or age > 65 and is_member:
```

is understood as:

```
if age < 12 or (age > 65 and is_member):
```

**But the strong recommendation is: don't rely on precedence — add parentheses.**

```python
if (age < 12) or (age > 65 and is_member):
    print("Discount ticket")
```

Parentheses are free, and they spare the reader (including you, three weeks from now) from having to recall the precedence rules.

## 6. Nested `if`, or `and`?

To express "18 or over AND a member," you have two options.

**Version A: `and`**

```python
if age >= 18 and is_member:
    print("May enter")
```

**Version B: `if` inside `if`**

```python
if age >= 18:
    if is_member:
        print("May enter")
```

Both are correct and give the same result. Which to pick?

**Rule of thumb:**

- Simple "all of these must hold" → use `and`, one line
- When the outer condition failing **needs its own action** → nest

For example:

```python
if age >= 18:
    if is_member:
        print("Member lane")
    else:
        print("Regular lane")
else:
    print("Under 18, no entry")
```

Nesting is clearer here, because each level has its own `else`. Using `and` would force you to list every combination.

**One line: the deeper the nesting, the harder the code reads. Flatten it with `and` whenever you can.**

## 7. A Complete Example

Is a year a leap year? (Divisible by 4 and not by 100, or divisible by 400.)

```python
year = 2024

if (year % 4 == 0 and year % 100 != 0) or (year % 400 == 0):
    print(year, "is a leap year")
else:
    print(year, "is not a leap year")
```

Note the parentheses — they make each side of the `or` a single unit, so you can't get it wrong even if you forget the precedence rules.
