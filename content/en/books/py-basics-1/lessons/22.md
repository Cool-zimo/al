# Run Forever: `while True` and `break`

> Last lesson's `while` had a prerequisite: **you need to know in advance when the condition becomes false.**
>
> But a whole class of problems can't say how many times: a menu program — you don't know how many choices the user makes before quitting; a login box — you don't know how many times they'll mistype.
>
> What these share: **keep running until the user says "enough."**
>
> This lesson covers two keywords built for exactly that: `while True` and `break`.

## 1. What Problem It Solves

Think of an ATM. You insert your card, check balance, withdraw, check again, withdraw again… The machine doesn't spit your card out after one action.

What it does is:

> **Show the menu forever, until you press "Return card."**

Could you write that with last lesson's tools? Hardly. You can't know in advance how many operations the user wants, so you can't fill in the question mark in `while count <= ?`.

So a new pattern appears: **write the condition as "always true," then jump out yourself wherever you want to stop.**

## 2. What `while True` Looks Like

```python
while True:
    print("Program is running")
```

`True` is a fixed boolean value that is **always true**. So this loop's condition never becomes false — by last lesson's standard, that's an infinite loop.

And indeed it won't stop on its own. **But it gives you a brand new capability: an emergency exit from inside the loop body.**

## 3. `break`: Jumping Out of the Loop

Here's a genuinely useful example — keep asking for the password until it's right:

```python
password = "123456"      # the correct password
tries = 0

while True:
    guess = "123456"     # in a real program this would be input()
    tries = tries + 1

    if guess == password:
        print("Correct. Welcome back")
        break           # ← jump out

    print("Attempt", tries, "failed")

print("Program ended")
```

Run it:

```
Correct. Welcome back
Program ended
```

**`break` means exactly one thing: stop.**

The moment execution reaches `break`, it **leaves the whole loop** and continues at the first line after it.

### Why is `break` almost always inside an `if`?

Look at the structure above: `break` is wrapped in an `if`.

That's no accident — **`break` on its own is meaningless.** If it breaks every time, the loop runs one round, so why write a loop at all?

So the standard shape is always:

```python
while True:
    do something
    if some condition:
        break        # only stop when the condition is met
```

**"Keep doing it until some condition is met."** That sentence is the entire meaning of `while True` + `break`.

Compare when to use which:

| Form | Use when | Example |
|---|---|---|
| `while condition:` | You can judge up front whether to run | Count from 1 to 100 |
| `while True:` + `break` | You must **do it once** before you can judge | Guessing games, menus, login |

**Rule of thumb: if you need to act before you can judge, use `while True`.**

Guessing a number is the classic case — you have to let them guess once before you know whether they got it.

## 4. `continue`: Skip This Round

`continue` looks like `break` but does something completely different:

| | Meaning | Where it goes next |
|---|---|---|
| `break` | The whole loop ends | Jumps **outside** the loop |
| `continue` | **Skip the rest of this round** | Goes back to the **top**, next round |

Example: print 1 to 5, but skip 3.

```python
count = 0

while count < 5:
    count = count + 1

    if count == 3:
        continue          # ← skip the print below

    print(count)
```

Run it:

```
1
2
4
5
```

3 is gone. When it hit `continue`, it **went straight back to the top of the loop**, so the `print` below never ran.

> ⚠️ Notice `count = count + 1` sits **before** the `continue`.
> Put it after, and when `count` is 3 it gets skipped, so it never increments — **infinite loop**.
> Same trap as last lesson ("don't put the increment inside the `if`"), just wearing a different hat.

## 5. Building a Menu That Actually Stays Usable

Now combine `if` / `elif` from chapter 4 with `while True` / `break` from this one — **the most "real program" code in this book so far**:

```python
running = True

while running:
    print("")
    print("===== Calculator =====")
    print("1. Add")
    print("2. Subtract")
    print("3. Quit")

    choice = "1"        # in a real program this would be input()

    if choice == "1":
        print("10 + 5 =", 10 + 5)
    elif choice == "2":
        print("10 - 5 =", 10 - 5)
    elif choice == "3":
        print("Bye")
        running = False    # ← makes the loop condition false
    else:
        print("No such option")
```

You'll see the menu, pick 1, get a result, and then **the menu appears again** — that's exactly the difference between a "tool" and a "script."

Note this uses a different way to stop: **changing a flag variable** (`running = False`) instead of `break`.

Both stop the loop. The difference:

- `break` — leaves immediately; code below doesn't run
- `running = False` — the condition becomes false, but **this round still finishes**; it stops next round

Beginners should use `break` first; it's more direct. Flag variables get more flexible as your programs grow.

## 6. Three Traps with `while True`

### 1. Forgetting `break` → a genuine infinite loop

```python
while True:
    print("Can't stop")
```

This really never ends. When you write `while True`, **write the `break` first thing.**

### 2. `break` only exits one level

Later you'll nest loops. `break` only leaves **the innermost one**; the outer keeps going. Classic source of beginner confusion — just file it away for now.

### 3. Don't write code after `break`

```python
while True:
    break
    print("This never runs")    # dead code
```

No error, but it never executes. Delete it on sight.
