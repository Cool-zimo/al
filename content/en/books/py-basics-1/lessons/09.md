# Booleans and comparisons

> One data type has only two values, yet it is the foundation of every decision a program makes.

## Only two values

A **boolean (bool)** is either `True` or `False`.

```python
is_student = True
has_paid = False
print(is_student)
print(has_paid)
```

Note the **capital first letter**. `true`, `TRUE` and `True1` are all wrong — `true` would be treated as a variable name (and then raise NameError).

> 💡 Named after George Boole, the mathematician who built an algebra with only true and false. Programmers use his work every single day.

## Where booleans come from: comparisons

You rarely type `True` by hand. Usually you **compare** something:

```python
age = 18
print(age > 16)      # True
print(age < 16)      # False
```

Six comparison operators:

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `==` | equal | `5 == 5` | `True` |
| `!=` | not equal | `5 != 3` | `True` |
| `>` | greater than | `5 > 3` | `True` |
| `<` | less than | `5 < 3` | `False` |
| `>=` | greater or equal | `5 >= 5` | `True` |
| `<=` | less or equal | `5 <= 4` | `False` |

**`==` and `=` are completely different.** This is the single most frequent beginner mistake:

```python
age = 18        # one equals: assignment (put 18 into age)
age == 18       # two equals: comparison (is age equal to 18?)
```

Write `=` where a comparison belongs and Python raises `SyntaxError`. Write `==` where an assignment belongs and nothing errors — it silently does nothing, which is much harder to spot.

> 💡 Mnemonic: `=` means "put in", `==` means "is it". One is an action, one is a question.

## Comparisons work on strings too

```python
print("apple" == "apple")    # True
print("apple" == "Apple")    # False  ← case sensitive!
print("apple" < "banana")    # True   ← dictionary order
```

Strings compare in **lexicographic order**: compare the first character, then the second if the first matches, and so on.

```python
print("abc" < "abd")     # True, third character c < d
print("Zoo" < "apple")   # True, uppercase codes come before lowercase
```

Chinese compares too, by Unicode code point, though you rarely need it.

## Logical operators: and / or / not

Three words combine conditions.

### and — both must hold

```python
age = 20
print(age >= 18 and age <= 65)     # True, 20 is between 18 and 65
```

**Truth table**:

| A | B | A and B |
|---|---|---|
| True | True | **True** |
| True | False | False |
| False | True | False |
| False | False | False |

Mnemonic: **and means "both"** — one False makes it False.

### or — either one is enough

```python
day = "Saturday"
print(day == "Saturday" or day == "Sunday")    # True, it's the weekend
```

| A | B | A or B |
|---|---|---|
| True | True | **True** |
| True | False | **True** |
| False | True | **True** |
| False | False | False |

Mnemonic: **or means "either"** — one True makes it True.

### not — flip it

```python
is_raining = False
print(not is_raining)     # True
```

| A | not A |
|---|---|
| True | False |
| False | True |

### Combining them

```python
age = 20
has_ticket = True

# adult and has a ticket
print(age >= 18 and has_ticket)          # True

# underage or no ticket
print(age < 18 or not has_ticket)        # False
```

**Precedence**: `not` > `and` > `or`. If unsure, add brackets:

```python
print((a or b) and c)     # brackets make the intent obvious
```

## Short-circuit evaluation: a small optimisation

Python is clever — **if the answer is already settled, it stops looking**:

```python
# and: left is False, the right is never evaluated
print(False and 1 / 0)     # False, no error!

# or: left is True, the right is never evaluated
print(True or 1 / 0)       # True, no error!
```

`1 / 0` would normally raise ZeroDivisionError, but short-circuiting means it never runs.

This isn't just an optimisation — it's a practical trick for **safe checks**:

```python
name = ""
print(name and name[0])    # empty string → returns "" directly, no IndexError
```

## "Truthiness" in Python

An important feature: **not just True/False — many values can act as booleans.**

The rule is simple: **empty things and zero are falsey; everything else is truthy.**

**Values treated as False:**

```python
False          # the boolean false
0, 0.0         # numeric zero
""             # empty string
[]             # empty list (later)
{}             # empty dict
None           # no value
```

**Everything else is True**, including:

```python
True
1, -1, 0.1     # any non-zero number
"False"        # ⚠️ note! a non-empty string, so True
"0"            # ⚠️ same — the string "0" is True
```

Those last two are common traps: **the string `"False"` is truthy**, because it's text with content in it.

**How is this used?** To check whether something has content:

```python
name = ""
if name:             # empty string → False
    print("has a name")
else:
    print("no name given")
```

> 💡 The next chapter uses this constantly with `if`. For now just remember: **empty and zero are false; the rest are true.**

## None: nothing at all

`None` is Python's special constant for "no value".

```python
result = None
print(result)          # None
print(result == None)  # True, but not the recommended way
```

**Test for None with `is`:**

```python
print(result is None)       # True   ✅ recommended
print(result is not None)   # False
```

Why not `==`? Because `is` asks "is this the same object" while `==` asks "are the values equal". For a singleton like None, `is` is more precise and faster.

**The most common None you'll meet**: a function with no return value gives None.

```python
def greet():
    print("hello")

result = greet()      # prints "hello", but the function has no return
print(result)         # None
```

This confuses beginners constantly: "I saw output, so why is the variable None?" Because `print` shows something on screen while `return` hands a value back to the caller.

## Booleans are actually numbers

A small Python secret:

```python
print(True + True)     # 2
print(True * 10)       # 10
print(False + 5)       # 5
```

`bool` is a subclass of `int`; `True` is really 1 and `False` is really 0.

**But don't write code like that.** It's an implementation detail and reads badly. Know it, then use True/False properly.
