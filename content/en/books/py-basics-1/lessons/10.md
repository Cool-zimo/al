# Type conversion & type()

> Why does `"18" + 1` error? Why is `1 + 1` equal to 2 but `"1" + "1"` equal to `"11"`?
> This lesson clears up everything that "looks the same but isn't".

## Three odd results first

```python
print(1 + 1)        # 2
print("1" + "1")    # 11
print(1 + "1")      # TypeError
```

Same `+`, three completely different outcomes. What differs? **The types of the things involved.**

- number + number → arithmetic
- string + string → concatenation
- number + string → error, because Python doesn't know which you meant

That's what types are for: **the type decides which operations are allowed.**

## type(): ask what it really is

When unsure, just ask:

```python
print(type(18))        # <class 'int'>
print(type(18.5))      # <class 'float'>
print(type("hello"))   # <class 'str'>
print(type(True))      # <class 'bool'>
print(type(None))      # <class 'NoneType'>
```

The names in the output — `int`, `float`, `str`, `bool` — are the types.

**The most common use of `type()` is hunting a weird bug.** If a calculation gives the wrong answer, `print(type(x))` first. Very often the problem is "you thought it was a number, but it's a string".

### isinstance(): is it this type?

```python
print(isinstance(18, int))       # True
print(isinstance("18", int))     # False
print(isinstance(18.5, (int, float)))   # True ← one of several types
```

`isinstance()` is preferred over `type(x) == int` because it handles inheritance (recall `True` is both a bool and an int).

## The four basic types, reviewed

| Type | Name | Example | Notes |
|---|---|---|---|
| `int` | integer | `18`, `-3` | no decimal point |
| `float` | floating point | `18.5`, `3.0` | has a decimal point |
| `str` | string | `"hello"` | text in quotes |
| `bool` | boolean | `True`, `False` | only two values |

Plus `NoneType` (whose only value is `None`) — that's every type you need right now.

## Conversion: three functions

To turn one type into another:

```python
int(x)     # to integer
float(x)   # to float
str(x)     # to string
```

### str(): anything can become text

```python
print(str(18) + " years")   # 18 years
print(str(3.14))            # "3.14"
print(str(True))            # "True"
print(str(None))            # "None"
```

`str()` is the safest conversion — it **almost never fails**. It's your emergency tool when joining strings.

It's also what f-strings do for you:

```python
age = 18
print(f"I am {age}")           # calls str(age) automatically
print("I am " + str(age))      # same, written out
```

### int(): to integer

```python
print(int("18"))       # 18
print(int(3.9))        # 3    ← truncated, not rounded!
print(int(3.1))        # 3
print(int(True))       # 1
```

**Two things to watch:**

**1. Float to int truncates, it does not round:**

```python
print(int(3.9))        # 3, not 4
print(int(-3.9))       # -3, not -4
```

For rounding use `round()`:

```python
print(round(3.9))      # 4
```

**2. A string must be a plain integer:**

```python
print(int("18"))       # ✅ 18
print(int("18.5"))     # ❌ ValueError!
print(int("eighteen")) # ❌ ValueError!
print(int(""))         # ❌ ValueError!
```

`int("18.5")` fails because it isn't integer format. Go via float first:

```python
print(int(float("18.5")))     # 18 ✅
```

### float(): to floating point

```python
print(float("3.14"))   # 3.14
print(float("3"))      # 3.0
print(float(3))        # 3.0
print(float(True))     # 1.0
```

More forgiving than `int()` — `float("3")` is fine.

## input() always returns a string

**The single most practical thing in this lesson.**

```python
age = input("Enter your age: ")
print(type(age))       # <class 'str'>  — always str!
```

Whether the user types `18`, `3.14` or `hello`, `input()` returns **a string, always**.

So this is wrong:

```python
age = input("Enter your age: ")
if age > 18:           # comparing a string with a number → TypeError
    print("adult")
```

You get `TypeError: '>' not supported between instances of 'str' and 'int'`.

**The correct version** — convert first:

```python
age = int(input("Enter your age: "))
if age > 18:
    print("adult")
```

> 💡 Iron rule: **data arriving from outside (user input, files, the network) is almost always a string. Convert before doing arithmetic.**

## When conversion fails

It raises `ValueError`:

```python
int("abc")
```

```
ValueError: invalid literal for int() with base 10: 'abc'
```

Translation: "'abc' isn't valid decimal number format."

**Real code must guard against this** — users type anything. Once you learn `try/except` in a later chapter, you can handle it gracefully:

```python
# now (crashes)
age = int(input("Age: "))

# later (safe)
try:
    age = int(input("Age: "))
except ValueError:
    print("Please enter a number!")
```

## Implicit conversion: Python does it for you

Sometimes no manual conversion is needed:

```python
print(1 + 2.0)      # 3.0  ← int promoted to float
print(3 * 1.5)      # 4.5
```

The rule is to go **towards more precision**: int → float. Converting that way loses nothing (just adds `.0`); the reverse would drop the fraction.

But **str is never converted automatically**:

```python
print("18" + 1)     # TypeError — no silent conversion
```

That's a deliberate design choice: **better to raise than to guess.** Turning `"18"` into `18` or `1` into `"1"` give totally different answers (19 vs "181"); guessing wrong is worse than erroring.

## Boolean conversion: bool()

```python
print(bool(1))         # True
print(bool(0))         # False
print(bool(""))        # False
print(bool("False"))   # True  ← non-empty string!
print(bool(None))      # False
```

As last lesson said: **empty and zero are False, everything else True.** `bool()` just runs that rule explicitly.

You rarely write `bool()` by hand, because `if x:` does it for you.

## A complete example: temperature

Stringing it all together:

```python
# user enters Celsius, convert to Fahrenheit
celsius = float(input("Enter Celsius: "))
fahrenheit = celsius * 9 / 5 + 32
print(f"{celsius}°C = {fahrenheit}°F")
```

Three lines using: `input()`, `float()` conversion, arithmetic, operator precedence and f-string formatting.

## Common mistakes

| Mistake | Cause | Fix |
|---|---|---|
| `"18" + 1` TypeError | strings don't add to numbers | `int("18") + 1` |
| `int("18.5")` ValueError | string isn't integer format | `int(float("18.5"))` |
| Comparing `input()` result fails | input returns a string | `int(input(...))` |
| `int(3.9)` gives 3 | truncation, not rounding | `round(3.9)` |
| `"0"` is truthy | non-empty strings are true | convert with `int()` first |
