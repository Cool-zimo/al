# Users Never Type What You Expect

> You finished your program and tested it with "Beijing" — works fine.
>
> Then you hand it to someone else. One person types `Beijing ` (a trailing space), another types `YES`, another `yes`, and one just hits Enter.
>
> **The program crashes or judges wrongly on every one.**
>
> That's not the user's fault — the program is too fragile. This lesson is about **cleaning input before you use it**.

## First, see how fragile it is

A program that checks whether you're from Beijing:

```python
city = input("Which city are you from? ")

if city == "Beijing":
    print("Oh, the capital!")
else:
    print("Welcome.")
```

You test with `Beijing` → "Oh, the capital!" Perfect.

Then real users arrive:

| User types | Actual value | Result |
|---|---|---|
| `Beijing` | `"Beijing"` | ✅ works |
| `Beijing ` | `"Beijing "` | ❌ falls to else |
| ` Beijing` | `" Beijing"` | ❌ falls to else |
| `beijing` | `"beijing"` | ❌ falls to else |
| `` (just Enter) | `""` | ❌ falls to else |

**Exactly one spelling works; everything else fails.**

The reason is simple: `==` is an **exact comparison**. `"Beijing "` and `"Beijing"` are two different strings — one extra space and they're not equal.

And human input naturally carries impurities: **stray spaces, inconsistent case, mixed punctuation**.

Conclusion: **never compare raw user input directly.** Clean it first.

## Weapon 1: strip() — trim the ends

```python
text = "  Beijing  "
print(text.strip())      # Beijing
```

`strip()` removes whitespace (spaces, tabs, newlines) from **both ends**. It does **not** touch the middle:

```python
print("  Beijing  ".strip())    # "Beijing"
print("Bei jing".strip())       # "Bei jing" (inner space kept)
print("\tBeijing\n".strip())    # "Beijing" (tab and newline removed too)
```

**Stripping every input should be muscle memory:**

```python
city = input("Which city? ").strip()
```

Note the shape: `input()` returns a string, so **you can chain `.strip()` right onto it** — one clean step.

Two variants:

```python
text = "  Beijing  "
print(text.lstrip())   # "Beijing  "  left side only
print(text.rstrip())   # "  Beijing"  right side only
```

`strip` is used most; the other two are occasional lifesavers.

### strip with an argument

You can also say *which* characters to remove:

```python
print("***urgent***".strip("*"))    # "urgent"
print("$100".strip("$"))            # "100"
```

Uncommon, but good to know it exists.

## Weapon 2: lower() / upper() — unify case

The biggest headache with English input is case:

```python
answer = input("Continue? (yes/no)")
if answer == "yes":
    print("Continuing")
```

User types `YES`, `Yes`, `yES` — all fail.

Fix: normalise to lower case before comparing.

```python
answer = input("Continue? (yes/no)").strip().lower()

if answer == "yes":
    print("Continuing")
```

Now `YES`, `Yes`, and ` yes ` are all recognised.

`lower()` lowercases, `upper()` uppercases:

```python
print("Hello World".lower())    # "hello world"
print("Hello World".upper())    # "HELLO WORLD"
```

**Only affects letters.** Chinese has no case, so `"北京".lower()` returns `"北京"` unchanged (no error).

### Chaining

Look closely at that line:

```python
input("...").strip().lower()
```

**Methods chained one after another** — this is **method chaining**, executed left to right:

1. `input(...)` → `" YES "`
2. `.strip()` → `"YES"`
3. `.lower()` → `"yes"`

This style is everywhere in Python; once you're used to it, it reads better than three separate lines.

## Weapon 3: in — substring check

Everything so far was "**must equal exactly**". Often what you need is "**contains** is enough".

```python
city = input("Which city? ").strip()

if "Beijing" in city:
    print("Oh, the capital!")
```

Now all of these work:

```
Beijing          ✅
Beijing city     ✅
Chaoyang, Beijing ✅
I work in Beijing ✅
```

`in` tests for a **substring**: `"Beijing" in "Chaoyang, Beijing"` is true because the latter **contains** the former.

Comparing the two:

| Test | Meaning | Good for |
|---|---|---|
| `city == "Beijing"` | must be exactly equal | fixed choices (yes/no) |
| `"Beijing" in city` | contains is enough | free text that may carry extra words |

**Rule of thumb: free text → `in`; fixed options → `==` (with lower()).**

### Negating it

The opposite is `not in`:

```python
if "Beijing" not in city:
    print("Not from Beijing")
```

## Weapon 4: genuinely empty input

The user types nothing and hits Enter:

```python
name = input("Your name? ").strip()
```

`name` is now the **empty string** `""`.

Legal, but usually meaningless. How to check:

```python
if name == "":
    print("You didn't enter a name")
else:
    print(f"Hello, {name}")
```

A more Pythonic way (empty strings are "falsy"):

```python
if not name:
    print("You didn't enter a name")
```

`not name` is true when `name` is `""`. This is idiomatic, but while learning, **`name == ""` is clearer** and less likely to confuse you.

## Putting it together: a robust exchange

```python
city = input("Which city? ").strip()

if not city:
    print("You didn't enter a city.")
elif "Beijing" in city:
    print("Oh, the capital!")
elif "Shanghai" in city:
    print("The magic city!")
else:
    print(f"Welcome, friend from {city}.")
```

(Multi-branch `if / elif / else` gets full treatment in *Python Basics 2*. Just feel the shape for now.)

This short program already handles stray spaces, empty input, and varied city spellings. **This is a program you can hand to someone else.**

## A thin line: don't over-clean

Cleaning is good, but not always:

```python
# bad over-cleaning
password = input("Password: ").strip()
```

Spaces at the ends of a password **may be intentional**! `strip()` changes the password, so what the user set and what gets verified won't match.

**Test: is this input an identifier/choice, or content?**

| Input type | Strip? | Example |
|---|---|---|
| City, name, menu choice | ✅ yes | extra spaces are accidental |
| Password, article text, code | ❌ no | spaces are part of the content |

## Three things to remember

1. **Never judge raw user input** — `strip()` first
2. For English choices, **`.lower()` before comparing**
3. Free text → **`in`**; only fixed options use `==`
