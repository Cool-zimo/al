# Errors Don't Mean You're Wrong

> Beginners fear red error text; veterans love it. This lesson resets your relationship with errors — they're a free, 24/7, extremely patient tutor.

## Get the mindset right first

The usual beginner reaction on seeing an error: "I broke it."

The truth is:

> **Python refused to run code it didn't understand, and carefully told you what it didn't get, and on which line.**

It isn't criticising you. It's **protecting you from a worse outcome** — writing a wrong result into a database, or letting the program quietly drift somewhere you can't see.

A harsh fact: **the earlier an error appears, the better; the more detail it gives, the better.** The truly terrifying program is the one that "doesn't error, but gives the wrong answer".

## How to read an error: start from the last line

The most practical habit you can build here. It'll save you countless hours.

```python
print("Hello"
```

Running that gives you a block of red:

```
File "<exec>", line 1
    print("Hello"
                 ^
SyntaxError: '(' was never closed
```

Lots of information, but **you only need the last line**:

```
SyntaxError: '(' was never closed
```

Translation: "Syntax error: a bracket was never closed."

Then look just above for `line 1` — that tells you where.

**Standard error-reading procedure:**
1. Jump to the last line → know **what** went wrong
2. Look up for `line N` → know **where**
3. Go to that line → fix it

## Four errors you'll meet 100 times

### 1. SyntaxError — the phrasing is invalid

Three most common causes:

**Unmatched brackets:**

```python
print("Hello"
```

Error: `SyntaxError: '(' was never closed`

**Unmatched quotes:**

```python
print("Hello)
```

Error: `SyntaxError: unterminated string literal`

**⚠️ Full-width punctuation:** This trap catches nearly every Chinese-speaking beginner.

```python
print（"Hello"）   # these are full-width Chinese brackets （ ）
print("Hello"）；  # and a Chinese semicolon ；
```

Same `SyntaxError`, but you could stare at it for ten minutes without seeing it — because `（` and `(` look almost identical.

**How to tell**: full-width punctuation is wider, taking two character cells. When typing code, **keep your IME in English mode** (check whether the status bar shows "英" or "EN").

### 2. NameError — the name doesn't exist

```python
print(massage)
```

Error: `NameError: name 'massage' is not defined`

Meaning: you asked me to print `massage`, but I've never seen it.

Two usual causes:

- **Forgot the quotes**: you wanted the text "massage" but wrote `print(massage)`, so Python treats it as a variable
- **Inconsistent spelling**: you wrote `message = "hi"` earlier, then typed `massage`

### 3. IndentationError — wrong indentation

```python
print("line one")
    print("line two")
```

Error: `IndentationError: unexpected indent`

Python uses **leading spaces** to express nesting (heavily used later with `if` and loops). Indent where it doesn't belong and it gets confused.

For now, one rule: **in a flat block, start every line at the far left — no stray spaces.**

### 4. TypeError — wrong type

```python
print("distance: " + 100)
```

Error: `TypeError: can only concatenate str (not "int") to str`

Translation: "I can only join a string to a string, not a string to a number."

You'll meet this constantly once we cover data types. Get familiar with the shape now.

## The four-step routine

Make it a habit and you'll move faster than 90% of beginners:

**Step 1: read the last line.** Know the error type.

**Step 2: find the line number.** Locate it.

**Step 3: if you don't understand it, copy the last line into a search box.**
Paste `SyntaxError: '(' was never closed` straight in; you'll find the answer essentially 100% of the time. Programmers do this daily. Not shameful.

**Step 4: still stuck? Delete code down to one line, then add it back.**
The ultimate move. Comment out half, see if the error persists — if it's gone, the bug was in the commented half. Bisect repeatedly and you'll land on it in minutes.

## One piece of mental armour

> Professional programmers also produce dozens of errors a day.
> Their advantage isn't "not making mistakes" — it's "not panicking at an error, and locating it in 30 seconds."

Every error you hit now is experience points banked for your future self.
