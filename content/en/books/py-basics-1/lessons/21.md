# `while`: Making the Program Repeat

> Every program from the first four chapters has the same limitation: **it runs once, then stops.**
>
> Want it to calculate again? You have to click "Run" again yourself.
>
> But in the real world, most of what programs do is inherently **repetitive**: keep asking for a password until it's right, process a hundred files one by one, check for new messages every second.
>
> This lesson gives your program its second kind of control — **repetition**.

## 1. What Problem Does `while` Solve?

Think of unlocking your phone.

Type the wrong password and the phone doesn't say "wrong, goodbye" and lock itself forever. **It lets you try again** — and again, until you get it right.

In plain language:

> **While** the password is still wrong, **keep** asking.

Notice how similar this is to `if` from the last chapter — both have a condition. There's only one difference:

| | Meaning |
|---|---|
| `if` | If the condition is true → do it **once**, then move on |
| `while` | If the condition is true → do it once, **come back and check again**, and if still true, do it again |

**`if` means "if." `while` means "as long as… keep doing."**

That's the whole problem it solves: **letting the same block of code run over and over while the condition holds.**

## 2. What `while` Looks Like

```python
count = 1

while count <= 3:
    print("Hello, time", count)
    count = count + 1

print("Done")
```

Run it and you'll see:

```
Hello, time 1
Hello, time 2
Hello, time 3
Done
```

One `print` statement, written **once**, executed **three times**. That's the power of a loop.

## 3. How `while` Actually Runs (Get This Clear)

Most beginners don't struggle with the syntax — they struggle because they never **ran it in their head**. Let's break the code above down step by step:

| Round | Value of `count` | Is `count <= 3` true? | What happens |
|---|---|---|---|
| Before | 1 | — | — |
| Round 1 | 1 | ✅ Yes | Prints "time 1", count becomes 2 |
| Round 2 | 2 | ✅ Yes | Prints "time 2", count becomes 3 |
| Round 3 | 3 | ✅ Yes | Prints "time 3", count becomes 4 |
| Round 4 | 4 | ❌ No | **Loop exits**, nothing happens |

Then the program continues downward and runs the final `print("Done")`.

**Key takeaway: the condition is checked at the *start* of every round.**

So the moment `count` becomes 4, the loop body is *not* executed a fourth time — it was stopped at the door.

## 4. Three Details You Must Remember

### 1. Same as `if`: colon + indentation

```python
while count <= 3:        # ← the colon is required
    print(...)           # ← indented = the "loop body"
    count = count + 1    # ← this line is inside the loop too
print("Done")            # ← not indented; runs once, after the loop
```

To tell "which lines are in the loop," **look only at indentation.** Exactly the same rule as `if`.

### 2. The loop body must contain something that eventually breaks the condition

Look at this line:

```python
count = count + 1
```

It looks unremarkable, but **it is the brake of the entire loop.**

Delete it and try:

```python
count = 1

while count <= 3:
    print("Hello, time", count)
```

`count` stays 1 forever, `count <= 3` is always true, and the program **prints forever and never stops.**

This is the famous **infinite loop**.

> If you hit an infinite loop in the browser, the page will freeze.
> Just refresh the page. While you're learning, writing an infinite loop isn't a "mistake" — it's **something everyone goes through once**.

**The test: does the loop body contain something that eventually makes the condition false?** If not, it will never stop.

### 3. `count = count + 1` is not a math equation

This line makes beginners question reality, because as math it's obviously false.

But `=` in Python is **assignment**: "take the result of the right side and put it into the variable on the left." It does not mean "these two are equal."

It runs in two steps:

1. Evaluate the right side: `count + 1`, i.e. `1 + 1 = 2`
2. Put 2 back into `count`

So what it really means is: **increase count by 1.**

If that feels awkward, Python has a shorthand:

```python
count += 1      # exactly the same as count = count + 1
```

Both are correct. This book mostly uses `count = count + 1` because it **shows more plainly** that "the right side is evaluated first, then stored."

## 5. Two Patterns You'll Use Constantly

Loops vary endlessly, but as a beginner you only need two fixed patterns to start.

### Pattern 1: Counting (a fixed number of times)

```python
count = 1

while count <= 5:
    print("Processing file", count)
    count = count + 1
```

Three parts: **starting value, condition, increment.** Miss any one and it won't turn.

### Pattern 2: Running total (accumulating)

```python
total = 0
count = 1

while count <= 100:
    total = total + count
    count = count + 1

print("Sum of 1 to 100:", total)
```

Result:

```
Sum of 1 to 100: 5050
```

Two variables, each with its own job:

- `total` — the **accumulator**; add a bit each round and you have the answer
- `count` — the **counter**; only tracks "which round is this"

Apply the "evaluate the right side first" rule to `total = total + count`: first compute `0 + 1`, store it; next round compute `1 + 2`, store it… **each round it adds to its own old value. That's "accumulating."**

## 6. Loops and `if` Nest Together

Branching and repeating aren't either/or — they almost always appear together.

```python
total = 0
count = 1

while count <= 10:
    if count % 2 == 0:
        total = total + count
    count = count + 1

print("Sum of even numbers 1-10:", total)
```

Result:

```
Sum of even numbers 1-10: 30
```

Watch where `count = count + 1` sits: **it is not indented inside the `if`.**

What if it were? Then it would only increment when `count` is even. On the first round `count` is 1 (odd), so it never increments, and stays 1 forever — **infinite loop**.

> **This is one of the most common beginner traps**: putting the increment inside the `if`.
> How to check: is `count = count + 1` at the *same indent level* as `while`?

## 7. When to Use `while` vs `if`

Here's the simplest test. Ask yourself:

> **How many times does this need to happen?**

- "It depends — maybe zero times, maybe many" → `while`
- "Just once, depending on whether to do it" → `if`

Next lesson covers `while True`, the "run forever until I say stop" pattern. The lesson after that covers `for`, which is for "**I know exactly how many times.**"
