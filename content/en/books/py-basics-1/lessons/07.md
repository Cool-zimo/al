# Numbers: integers and floats

> Python has two common kinds of number. The difference between them is subtle, but getting it wrong causes real bugs.

## The two kinds

```python
age = 18          # integer, int
price = 9.9       # decimal, float
```

- **int**: no decimal point. `18`, `0`, `-5`, `1000000`
- **float**: has a decimal point. `9.9`, `3.0`, `-0.5`

**Why "floating" point?** Because the decimal point can float — `1.0`, `0.1` and `100.5` all use the same storage format with a movable point. The name comes from how the computer stores decimals internally; just remember **float = decimal**.

> 💡 Counter-intuitive: `3` is an int, `3.0` is a float. Same value, but Python sees **two different types**.

## Basic arithmetic

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `+` | add | `7 + 3` | `10` |
| `-` | subtract | `7 - 3` | `4` |
| `*` | multiply | `7 * 3` | `21` |
| `/` | divide | `7 / 2` | `3.5` |
| `//` | floor divide | `7 // 2` | `3` |
| `%` | modulo (remainder) | `7 % 2` | `1` |
| `**` | power | `2 ** 10` | `1024` |

The first four need no explanation. The last three matter.

### `/` always returns a float

One of the biggest differences between Python 3 and Python 2, and a classic beginner trap:

```python
print(10 / 2)     # 5.0  ← note! 5.0, not 5
print(10 / 4)     # 2.5
print(4 / 2)      # 2.0
```

**Even when it divides evenly, `/` gives a float.** Odd at first, but a single rule is easy to remember: use `/` for decimals, `//` for integers.

### `//` floor division: keep the quotient, drop the remainder

```python
print(7 // 2)     # 3
print(8 // 2)     # 4
print(-7 // 2)    # -4  ← negatives round down
```

Don't memorise the negative case; look it up if you need it. In practice `//` is mostly used on positive integers.

**The classic use:** how many full boxes?

```python
eggs = 47
boxes = eggs // 12      # 12 per box, how many boxes?
print(boxes)            # 3
```

### `%` modulo: keep the remainder

```python
print(7 % 2)      # 1
print(8 % 2)      # 0
print(47 % 12)    # 11
```

Continuing the example: after filling 3 boxes (36 eggs), **how many are left over**?

```python
left = 47 % 12
print(left)       # 11
```

`%` has one very high-frequency use — **testing odd vs even**:

```python
n = 7
print(n % 2)      # 1 → odd
n = 8
print(n % 2)      # 0 → even
```

And **testing divisibility**: `n % 3 == 0` means "n is divisible by 3".

### `**` power

```python
print(2 ** 10)    # 1024
print(3 ** 2)     # 9
print(9 ** 0.5)   # 3.0  ← square root is the 0.5 power
```

**Python has no `^` operator.** `2 ^ 3` is bitwise XOR, giving `1`, not 8. A classic trap for anyone arriving from another language.

## Operator precedence

Same as maths: multiply and divide before add and subtract.

```python
print(2 + 3 * 4)      # 14, not 20
print((2 + 3) * 4)    # 20, brackets first
```

Full order (highest to lowest):

1. `()` brackets
2. `**` power
3. `*`, `/`, `//`, `%`
4. `+`, `-`

**If you can't remember, use brackets.** That isn't laziness — brackets let the reader (including you in three weeks) see the intent at a glance.

> ⚠️ Trap: `-2 ** 2` is `-4`, not `4`, because `**` binds tighter than the minus — it means `-(2 ** 2)`. Write `(-2) ** 2` for 4.

## Mixing ints and floats

One simple rule: **if a float is involved, the result is a float.**

```python
print(1 + 2)        # 3    (int)
print(1 + 2.0)      # 3.0  (float)
print(3 * 1.5)      # 4.5  (float)
print(6 / 2)        # 3.0  (float)
```

Python promotes the int to float before computing, because it refuses to silently drop the fractional part.

## Floating point precision (read this)

**Everyone learning Python must know this one:**

```python
print(0.1 + 0.2)
```

You expect `0.3`. You get:

```
0.30000000000000004
```

**Why?** Computers store decimals in binary, and `0.1` is a **repeating** value in binary (just as 1/3 is 0.333... in decimal). The exact value can't be stored, so an approximation is stored, and the error carries into the calculation.

This is not a Python bug. **Every language does this**, because they all use the same IEEE 754 standard.

**How to live with it:**

First, **never compare floats with `==`**:

```python
print(0.1 + 0.2 == 0.3)      # False !
```

Second, compare "is the difference small enough":

```python
a = 0.1 + 0.2
b = 0.3
print(abs(a - b) < 0.00001)  # True
```

Third, **for money, count cents as integers, not pounds as floats**:

```python
# Not this
price = 19.99
total = price * 3

# This
price_cents = 1999
total_cents = price_cents * 3
print(total_cents / 100)     # 59.97
```

> 💡 Floats suit **scientific computing** (a tiny error is fine). They do not suit **exact counting** (money, stock, votes). Use integers there.

## Big numbers and readability

Python integers have **no size limit** — as big as you like:

```python
print(2 ** 100)   # a 31-digit monster, no problem at all
```

Many languages overflow here. Python doesn't.

Underscores group digits for readability; Python ignores them:

```python
population = 1_400_000_000     # same as 1400000000
print(population + 1)
```

The underscores are for your eyes only, so you can count digits at a glance.

## A few handy built-ins

```python
print(abs(-5))        # 5     absolute value
print(round(3.7))     # 4     round
print(round(3.14159, 2))   # 3.14  2 decimal places
print(max(3, 7, 2))   # 7     largest
print(min(3, 7, 2))   # 2     smallest
```

> ⚠️ `round()` has a quirk called banker's rounding: `round(2.5)` gives `2`, not `3`, while `round(1.5)` gives `2`. Values exactly in the middle go to the nearest **even** number. Harmless day to day, but watch it in financial code.
