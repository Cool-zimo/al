# Making the Computer Understand You

> Before writing code you need somewhere to run it. This lesson sorts that out properly, and walks you through installing the editor.
>
> It's a long one, but worth reading slowly — get the environment wrong and every later lesson stumbles.

## One thing first: Python is "interpreted"

Languages split roughly in two. Understanding the difference explains why "the environment" matters so much.

**Compiled (e.g. C)**: you write the whole book, hire a translator to render it into English in one go, then hand the English version to the reader. Slow to translate, fast to read.

**Interpreted (e.g. Python)**: you say a sentence, the translator renders it, the listener hears it.

Python is the latter. It has a program called the **interpreter**, which reads your code and executes it line by line.

Two direct consequences:

1. **Upside**: write one line, run it immediately — experimentation is nearly free. Perfect for learning.
2. **Cost**: you must have a correct interpreter installed, otherwise your code is just ordinary text.

So "setting up an environment" boils down to one sentence:

> **Get a Python interpreter, and make sure it can read your code.**

## Two paths — start with the first

### Path A: run it in the browser (what you're using right now)

**This site you're reading runs Python by itself.**

That's not uploading your code to some server — it uses **Pyodide**, which compiles real CPython (the official Python interpreter) into a format the browser can execute, running entirely on your own machine.

Benefits:

- **Zero install**: open the page and write code — works on a phone too
- **Zero risk**: you cannot break your computer no matter what you do
- **Genuinely real**: this is actual Python 3, not a cut-down version; `import math` and friends work

Limits:

- Libraries that need the network don't work (e.g. `requests` for scraping)
- It can't touch real files on your disk (the browser forbids it — which is a good thing)
- The first run downloads a ~10MB runtime (cached afterwards)

**Recommendation**: for all of "Python Basics 1" you can stay in the browser. Move to Path B when you reach file I/O and installing third-party packages (Basics 3 onwards).

**That doesn't mean you install nothing right now.** The editor is a separate matter — even if you only study in the browser, you'll eventually write real code on your own machine. Let's get VS Code set up once, properly.

### Path B: install real Python on your machine

Once you start building real tools, you'll want local Python.

**Windows:**

1. Go to [python.org/downloads](https://www.python.org/downloads/)
2. Hit the big yellow button for Python 3.12 or newer
3. **⚠️ In the installer, tick `Add python.exe to PATH` at the bottom**
   — skip this and you'll hit the classic "command not found" wall later
4. Click `Install Now` and wait

**macOS:**

1. Same installer from python.org, double-click to install
2. Or with Homebrew: `brew install python3`

**Linux:**

Probably already there. Run `python3 --version` in a terminal; if not, `sudo apt install python3` (Ubuntu/Debian).

### How to tell it worked

Open a terminal and type:

```
python --version
```

or:

```
python3 --version
```

See `Python 3.12.x` and you're done. See "not recognized as an internal or external command" and the PATH step was missed — uninstall, reinstall, and tick it this time.

## Installing VS Code, step by step

You need a decent editor to write code. We'll use **VS Code (Visual Studio Code)** — free, cross-platform, and close to the industry default now.

### Step 1: Download

Go to: **https://code.visualstudio.com/download**

The page detects your OS and the big button in the middle is the right build. To pick manually, scroll down:

| Your system | Choose |
|---|---|
| Windows | `Windows` → usually **User Installer 64-bit** |
| macOS | Check your chip: **macOS (Apple Silicon)** for M-series, **macOS (Intel)** for Intel |
| Linux | `.deb` (Ubuntu/Debian family) or `.rpm` (Fedora/openSUSE family) |

> **User Installer vs System Installer?**
> User Installer installs under your own user folder, needs no admin rights, and is clean to uninstall or upgrade — **pick this one**. System Installer needs admin rights and goes into `C:\Program Files`; it suits machines shared by several people.

### Step 2: Install (this is where boxes get missed)

**Windows:**

Double-click the installer and click Next through — but **stop at the "Select Additional Tasks" page** and tick all of these:

- ✅ **Add to PATH (requires shell restart)** — without it, typing `code` in a terminal won't open VS Code later
- ✅ Add "Open with Code" action to the Windows Explorer **file** context menu — right-click any file to edit it, very handy
- ✅ Add "Open with Code" action to the Windows Explorer **directory** context menu
- ✅ Register Code as an editor for supported file types

Then install. It opens itself when done.

**macOS:**

The download is a `.zip`. Double-click to extract, giving you `Visual Studio Code.app`. **Drag it into the `Applications` folder** — don't skip this, or it won't show up in Launchpad.

**Linux:**

On Ubuntu/Debian, double-click the `.deb` and use Software Centre, or from the command line:

```
sudo apt install ./code_xxx.deb
```

### Step 3: Switch to Chinese (optional)

It opens in English. To switch:

1. Press `Ctrl + Shift + X` (`Cmd + Shift + X` on Mac) to open the **Extensions** panel
2. Type `Chinese` in the search box
3. Find **Chinese (Simplified) Language Pack for Visual Studio Code** (author: Microsoft) and click `Install`
4. A prompt appears bottom-right — click `Yes` / `Restart`. The UI is Chinese after the restart.

> Installing extensions needs a network connection; the first one can be slow. Be patient.

### Step 4: Install the Python extension

This is what makes VS Code actually "speak Python".

1. In the same Extensions panel (the square icon)
2. Search `Python`
3. Pick the one **authored by Microsoft** (extension id `ms-python.python`, tens of millions of installs) and click `Install`

You get: syntax highlighting, autocompletion, hover documentation, `F5` debugging, and automatic discovery of the Python interpreters on your machine.

> You'll also see `Python Extension Pack`, `Pylance` and others. Installing Microsoft's `Python` **brings Pylance along automatically** (that's what powers completion and error squiggles), so don't install a second one by hand.

### Step 5: Write your first file

1. `File → New File` (or `Ctrl + N`)
2. Pick `Python` from the options that appear
3. Type this line:

```python
print("Hello, VS Code")
```

4. `Ctrl + S` to save. **The filename must end in `.py`** — for example `hello.py`
   Save it anywhere, but a dedicated folder is cleaner: `D:\pycode` or `~/pycode`

**Why must the extension be `.py`?** Because VS Code decides "what language is this" from the extension. Save it as `hello.txt` and you get no highlighting and it won't run as Python.

### Step 6: Make it run

Three ways, from quickest to most proper:

**Method 1: the triangle in the top right (quickest)**

With the Python extension installed, a ▶ button appears in the top right of the editor. Click it; output appears in the **Terminal** panel below.

**Method 2: right-click in the file**

Right-click in the code area → `Run Python File in Terminal`.

**Method 3: type the command yourself (worth learning)**

Press `` Ctrl + ` `` (the backtick, left of the number 1) to open VS Code's built-in terminal, then type:

```
python hello.py
```

Hit Enter. Seeing "Hello, VS Code" means it worked.

> **If it says command not found**, try `python3` instead:
> ```
> python3 hello.py
> ```
>
> And if `python3` errors on Windows, go back to `python`. The two names are just different platform conventions for the same thing.

### Step 7: Confirm VS Code found the right interpreter

If code runs but you get no highlighting, no completion, or odd errors, VS Code probably hasn't located your Python install.

Press `Ctrl + Shift + P` to open the Command Palette and type `Python: Select Interpreter`. It lists every Python it found. Pick one showing a version number, with `Python3xx` in the path.

Once selected, the bottom-left of the window shows the active interpreter — you want `Python 3.12.x`.

## A few lifesaving shortcut keys

Don't memorise them all now; come back when you need them:

| Shortcut | What it does |
|---|---|
| `` Ctrl + ` `` | Toggle the terminal panel |
| `Ctrl + S` | Save (hit it after every line until it's muscle memory) |
| `Ctrl + /` | Comment / uncomment the selected lines |
| `Ctrl + Shift + X` | Open the Extensions panel |
| `Ctrl + Shift + P` | Command Palette (forgot where a feature lives? search here) |
| `Alt + ↑ / ↓` | Move the current line up/down |
| `Shift + Alt + ↓` | Duplicate the current line below |
| `Ctrl + D` | Select the next occurrence of the word (brilliant for renaming) |

## Four problems beginners hit constantly

**1. Chinese output in the terminal is garbled**

Common on older Windows. Run this in the terminal first:

```
chcp 65001
```

and switch to a font with Chinese support (like `Consolas` or `Microsoft YaHei`). For a permanent fix, search VS Code settings for `files.autoGuessEncoding` and enable it.

**2. The file saves but Run does nothing**

Check the bottom-right for a prompt about selecting an interpreter. Follow Step 7 and pick one manually.

**3. `python is not recognized as an internal or external command`**

Python was installed without `Add to PATH`. Uninstall, reinstall, tick it this time.

**4. Extension installed but nothing changed**

Extensions often need a VS Code restart. Also confirm the file extension is `.py`.

## Three ways to run code — know the difference

With local Python you'll meet three modes:

| Mode | How | Good for |
|---|---|---|
| Interactive | type `python`, hit Enter, get a `>>>` prompt | seeing one line's effect instantly |
| Script file | write `hello.py`, run `python hello.py` | real programs |
| In the browser | right here | learning, demos, quick checks |

That `>>>` symbol means "I'm ready, talk to me". Whenever you see it in documentation, it means type this at an interactive prompt.

## Exercise · Confirm your environment is alive

Whichever path you took, let's verify the interpreter works.

The code below prints the Python version currently running. Just run it.

```quiz
type: code
q: Run this code and see which Python version you're on
starter: |
  import sys
  print(sys.version)
tests:
- assert "3." in __out
hint: The code is ready — just hit "Run & check". For more detail, add a line print(sys.version_info).
explain: import sys means "bring in the system toolbox"; sys.version holds the version string. Seeing output starting with 3. means you're on Python 3 — everything in this course assumes Python 3.
```

See a `3.` in the output? Then you're good.

> Side note: Python 2 stopped being maintained in 2020. Any Python code you see today is Python 3 by default.
