# Your First Program

> Finally, code. This lesson covers exactly one thing — `print`. But I'll break it down far enough that you know what every bracket and every quote is for.

## The smallest program

```python
print("Hello, world")
```

Hit "▶ Run" and the screen shows:

```
Hello, world
```

That's it. But don't rush on — this line has **4 parts** and none of them is optional:

```
print( "Hello, world" )
  ↑     ↑              ↑
  │     │              └─ closing bracket: the message ends here
  │     └──────────────── content: what you want to say
  └────────────────────── action: print
```

Broken down:

1. **`print`** — the name of an action. Python ships with hundreds of these ready-made; `print` means "show this on the screen".
2. **`(` and `)`** — brackets mean "hand this to the action". Like `give(Ming, a book)`: the brackets tell you the book goes to Ming.
3. **`"Hello, world"`** — the content itself. Text wrapped in quotes has a specific name in programming: a **string**.

## Why must the content be quoted?

This is the question beginners ask most, and the first real hurdle in understanding how programming thinks.

Think about it: without quotes,

```python
print(Hello)
```

how does Python read that? It assumes "Hello" is a **name** (a person's name, a variable) and goes looking for "the thing called Hello". It won't find it, so it errors.

With quotes you're telling Python:

> "This is not a command and not a name. This is **plain text** — just show it as-is."

**The job of quotes is to mark the boundary: inside is data, outside is code.**

### Single or double quotes?

Both work, identically:

```python
print("Hello")   # double quotes
print('Hello')   # single quotes
```

When must you pick one over the other? When the content itself contains quotes:

```python
print("He said: "hi"")     # ❌ breaks — Python can't tell which pair is the boundary
print("He said: 'hi'")      # ✅ double outside, single inside
print('He said: "hi"')      # ✅ the other way round works too
```

Simple rule: **whatever you use outside, don't use it inside.**

## Printing several things at once

Separate them with commas:

```python
print("apple", "banana", "orange")
```

Output:

```
apple banana orange
```

Notice the space in between — `print` adds it automatically. And you can change what it adds:

```python
print("apple", "banana", "orange", sep=", ")
```

Output:

```
apple, banana, orange
```

`sep` is short for separator: "join these items with a comma-space, not a blank space."

One more useful argument, `end`, controls "what to append when done". By default each `print` ends with a newline, which is why two prints land on two lines:

```python
print("line one")
print("line two")
```

If you don't want the newline:

```python
print("loading", end="")
print("...")
```

Output: `loading...` (all on one line)

That trick is gold for progress bars and loading animations.

## Newlines and tabs inside text

Write `\n` for a newline and `\t` for a tab:

```python
print("line one\nline two\nline three")
```

Output:

```
line one
line two
line three
```

The backslash `\` is an **escape character** — it means "treat the next character as a special instruction, not literal text."

The ones you'll actually use:

| Written | Effect |
|---|---|
| `\n` | newline |
| `\t` | one tab |
| `\\` | a literal backslash (yes, `\` escapes itself) |
| `\"` | a literal double quote |

## Programs run top to bottom, one line at a time

This "obvious" rule deserves its own section, because every complex behaviour later is built on it:

```python
print("do this first")
print("then this")
print("this last")
```

The output order **exactly** matches the order you wrote. No exceptions.

Much of "programming" is simply **arranging the order of lines**.

