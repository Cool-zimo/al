# Project: The Number Guessing Game

> Last lesson of chapter 5. No new syntax — we **stitch the previous four lessons into a game someone can actually play.**
>
> When you're done, you'll see that a program "that keeps running" is really just three things: **a loop, a condition, and an exit.**

## 1. What We're Building

State the requirements first — this step matters more than the code:

> The computer thinks of a number from 1 to 100. You guess.
> After each guess it tells you **too big** or **too small**, until you get it.

That's it. Simple as it sounds, it already has every element of a "program":

| Requirement | What it needs |
|---|---|
| The computer holds a number | Variables |
| You guess | Reading input |
| Tell you big or small | `if` / `elif` / `else` |
| Until you get it | **A loop** ← chapter 5's star |
| Stop when correct | `break` |

**Without a loop, this game lasts exactly one guess.**

## 2. First, a Version That Runs Once

Don't jump to the final version. See the minimal one first, so you understand what each later version adds.

```python
answer = 42
guess = 30          # in a real program this would be int(input())

if guess == answer:
    print("You got it!")
elif guess < answer:
    print("Too small")
else:
    print("Too big")
```

Run it:

```
Too small
```

It can judge — but **only once.** That's the level of chapters 1–4: the program runs once and ends.

## 3. Add the Loop: Make It Keep Going

Now perform chapter 5's surgery. Wrap "guess once" in a loop:

```python
answer = 42
guess = 30

while True:
    if guess == answer:
        print("You got it!")
        break              # ← correct; end it
    elif guess < answer:
        print("Too small")
    else:
        print("Too big")
```

⚠️ Don't run this version yet — it has a **serious problem**.

`guess` is 30 from start to finish, and `while True` is always true, so:

```
Too small
Too small
Too small
... (forever)
```

**Infinite loop.** You wrapped the code in a loop, but never made "guess again" actually happen.

This reviews lesson 21: the loop body must contain something that eventually falsifies the condition. Here the only trigger for `break` is `guess == answer`, and `guess` never changes — so it never happens.

## 4. Put the Input Inside the Loop

The crucial step: **the line that reads the guess must be inside the loop.**

```python
answer = 42

while True:
    guess = int(input())      # ← ask again every round

    if guess == answer:
        print("You got it!")
        break
    elif guess < answer:
        print("Too small")
    else:
        print("Too big")
```

Notice `guess = int(input())` is now **indented under the while** — meaning "read a fresh input every round."

That's why it keeps working:

| Round | You enter | Judgment | Output |
|---|---|---|---|
| 1 | 30 | 30 < 42 | Too small |
| 2 | 60 | 60 > 42 | Too big |
| 3 | 42 | equal | You got it! → break |

**"Reading input" must be inside the loop; otherwise, no matter how long it spins, it reads the same value.** This is the most common mistake in interactive programs.

### Why `int(input())`?

Lesson 12: `input()` gives you a **string**.

Comparing a string with a number errors immediately:

```python
"30" < 42     # TypeError: '<' not supported between instances of 'str' and 'int'
```

So convert with `int()` first. You do this on every read.

## 5. Add an Attempt Limit (To Make It Complete)

Real games limit attempts — say, 5 chances.

Idea: track "how many guesses so far" with a variable; stop when it's exceeded.

```python
answer = 42
max_tries = 5
tries = 0

while True:
    guess = int(input("Guess a number: "))
    tries = tries + 1

    if guess == answer:
        print("You got it! Used", tries, "tries")
        break
    elif guess < answer:
        print("Too small")
    else:
        print("Too big")

    if tries >= max_tries:
        print("Out of tries. The answer was", answer)
        break
```

Notice where the last `if` sits — **outside the `elif` chain**, not indented into it.

Why? Because the attempt check must run whether the guess was too big or too small. Indent it into one `elif` branch and the other branch skips the check.

**To tell "which code belongs to what," always look at indentation.** One iron rule shared by chapters 4 and 5.

## 6. The Complete Version

Merging the above, with a little input hardening:

```python
answer = 42
max_tries = 5
tries = 0

print("I'm thinking of a number from 1 to 100. You have 5 tries")

while True:
    guess = int(input("Your guess: "))
    tries = tries + 1

    if guess == answer:
        print("You got it! Used", tries, "tries")
        break
    elif guess < answer:
        print("Too small,", max_tries - tries, "tries left")
    else:
        print("Too big,", max_tries - tries, "tries left")

    if tries >= max_tries:
        print("Out of tries. The answer was", answer)
        break
```

That's **the most complete program in this book so far.**

## 8. One Note: Real Programs vs Graded Exercises

The complete version above uses `while True` — **that's how real programs should be written**, because you can't know how many guesses it takes.

But in this lesson's exercise we use a **fixed-count** version (`for` + `range`). The reason: the grader feeds all input at once, then it's empty; a `while True` that never stops would hang it.

**Neither form is better — the scenario differs.** When you write your own programs, use `while True` freely.
