# Variables: giving data a name

> In chapter 1 every program was disposable — it printed something and ended, leaving nothing behind.
> From this lesson on, your program has **memory**.

## Start with a problem

Say you need to print someone's name five times:

```python
print("Alex")
print("Alex")
print("Alex")
print("Alex")
print("Alex")
```

It works. Then your boss says: "Change the name to Sam."

You edit five places. What if there were 50 occurrences scattered across 500 lines?

**Variables exist precisely to solve this.** Put the data in a box, label the box, and refer to the label from then on. Change the name once and every place using that label follows automatically.

```python
name = "Alex"
print(name)
print(name)
print(name)
print(name)
print(name)
```

Now editing line one changes all five prints.

## `=` does not mean "equals"

This is the single biggest source of beginner confusion, so it gets its own section.

**In maths**, `=` states that two sides are equal. `x = 5` means "x is 5".

**In Python**, `=` is an **action** called assignment. `x = 5` means "**put 5 into the box labelled x**".

So this is nonsense in maths but perfectly normal in Python:

```python
x = 5
x = 10
print(x)
```

Why is that fine? Because line two isn't "declaring that x equals 10" — it's "**replace the contents of the box with 10**". The old value 5 is discarded.

And this, impossible in maths, is written every day in Python:

```python
x = x + 1
```

As an equation it has no solution. In Python it means:
1. Evaluate the right side `x + 1` first (if x is 5, the result is 6)
2. Put that result into the box called x

So x becomes 6. **The rule is always: evaluate the right, then store into the left.**

> 💡 The mantra: **right side reads, left side writes.** Read first, write second.

## Where variables live: a useful picture

Picture memory as a row of numbered lockers.

```python
age = 18
```

Python does three things:
1. Finds an empty locker and puts `18` inside
2. Sticks the label `age` on it
3. Records the mapping "age → that locker"

Later, `print(age)` makes Python follow the label to the locker and take out what's inside.

**Key point:** the label and the locker can be separated.

```python
a = 10
b = a      # not "copy a into b" — "make b point at the same locker as a"
```

You don't need to dig into that yet (we'll return to it with lists), but know this: **a variable is more like a label than a box**. That's an important difference between Python and some other languages.

## The rules for naming

Python has hard rules. Break them and it errors immediately:

| Rule | ✅ OK | ❌ Not OK |
|---|---|---|
| Letters, digits and underscores only | `name_1` | `name-1` (hyphen banned) |
| Cannot start with a digit | `score2` | `2score` |
| Case sensitive | `age` and `Age` are different variables | — |
| No keywords | `my_name` | `print`, `if`, `for`, `class` |
| Unicode is allowed (but unusual) | `名字 = "Alex"` | — |

**Keywords** are the 35 words Python reserves for itself. Don't memorise them — if a name suddenly changes colour in your editor, it's a keyword; pick another.

## The taste of a good name

Rules decide whether it runs. Taste decides whether it reads well.

**Use meaningful words:**

```python
# Bad
a = 18
b = "Alex"
x1 = 75.5

# Good
age = 18
name = "Alex"
weight_kg = 75.5
```

**Join words with underscores (the Python convention):**

```python
user_name = "Alex"     # ✅ snake_case, the Python mainstream
userName = "Alex"       # ⚠️ camelCase, works but isn't Pythonic
```

**Include the unit or type to remove ambiguity:**

```python
timeout = 30           # 30 seconds? milliseconds? minutes?
timeout_seconds = 30   # ✅ obvious
```

**Constants in ALL CAPS:**

```python
PI = 3.14159
MAX_RETRY = 3
```

Not enforced by the language (Python has no true constants) — it's a convention. Seeing caps tells everyone "don't change this".

## Assigning several at once

Python has a neat shortcut:

```python
x, y, z = 1, 2, 3
print(x)
print(y)
print(z)
```

Three names on the left, three values on the right, matched up in order.

**Swapping two variables** is where this really shines:

```python
a = 10
b = 20

# Other languages need a third temporary variable
# temp = a
# a = b
# b = temp

# Python: one line
a, b = b, a
print(a)
print(b)
```

The right side evaluates to `(20, 10)` first, then they're stored into `a` and `b`. That's "read the right, write the left" in action.

One value to several names works too:

```python
x = y = z = 0
print(x, y, z)
```

> ⚠️ Careful: fine for numbers, but there's a trap with lists (we'll get there). For now, "several names = the same number" is safe.

## There is no "declaration"

Many languages (C, Java) make you state the type before you can use a variable:

```c
int age = 18;         // must declare int first
age = "hello";        // error! type mismatch
```

Python doesn't. The box `age` can hold a number now and a string later:

```python
age = 18
print(age)
age = "eighteen"      # switching to a string - Python doesn't mind
print(age)
```

This is called **dynamic typing** — the variable has no type; the *value* does.

The upside is flexibility and speed. The cost: a wrong type isn't caught when you write it, only when execution reaches that line. That trade-off runs through all of Python.

## A variable must be assigned before use

This is the second most common beginner error:

```python
print(message)
```

```
NameError: name 'message' is not defined
```

Translated: "you told me to fetch a box called message, but I've never seen that label."

**Why the restriction?** If Python allowed it, what value should `message` get? 0? An empty string? Neither is right. Better to tell you plainly that it doesn't exist.

**The fix:** assign before using.

```python
message = "hello"
print(message)
```

> Three things to check for any NameError:
> 1. Typo? (`massage` vs `message`)
> 2. Chinese or full-width quotes?
> 3. Used before assigning?
