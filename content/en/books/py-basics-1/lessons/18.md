# More Than Two Options: `elif`

> `if` / `else` handles "one of two." But real life is usually **one of many.**
>
> Grades are A/B/C/D, weather is sunny/rainy/cloudy, membership is basic/silver/gold — none of those fit into two slots.
>
> `elif` exists for that. It's also the **easiest thing in this chapter to get wrong**, because its trap is deeply hidden.

## 1. What Problem Does `elif` Solve?

You want to sort scores into four bands:

- 90 and above → Excellent
- 75 and above → Good
- 60 and above → Pass
- Below 60 → Fail

With only `if` / `else` you can't write this — they have just two paths.

`elif` lets you **chain as many conditions as you like**:

```python
score = 85

if score >= 90:
    print("Excellent")
elif score >= 75:
    print("Good")
elif score >= 60:
    print("Pass")
else:
    print("Fail")
```

`elif` is short for **else if**. It means: "otherwise, if…"

Read the code out loud and it's almost plain English:

> If 90 or above, excellent; **otherwise if** 75 or above, good; **otherwise if** 60 or above, pass; **otherwise**, fail.

## 2. The Syntax

```
if condition1:
    do this when condition1 holds
elif condition2:
    do this when condition1 failed AND condition2 holds
elif condition3:
    do this when everything above failed AND condition3 holds
else:
    do this when everything above failed
```

Rules:

1. There must be exactly one `if`, and it comes first
2. You can have **any number** of `elif` (including zero)
3. At most one `else`, at the end, and it's **optional**
4. They all sit at the **same indent level**
5. Every one of them needs a **colon**

### `else` Is Optional

```python
score = 85

if score >= 90:
    print("Excellent")
elif score >= 75:
    print("Good")
```

If score is 50, neither condition holds → **nothing prints.**

That isn't necessarily a bug. Sometimes you genuinely want to act only in certain cases and stay silent otherwise.

But **more often, forgetting the `else` means you've dropped an edge case.** Rule of thumb:

> Use an `else` whenever you can. It says "I thought about the leftovers."

## 3. The Crucial Property: Top to Bottom, First Match Wins

This is the heart of this lesson and the source of 90% of `elif` bugs.

**Python starts at the first condition and tries them in order. As soon as one is true, it runs that block and the whole `if` structure ends — none of the remaining conditions are ever checked.**

```python
score = 95

if score >= 60:
    print("Pass")
elif score >= 90:
    print("Excellent")
```

What does it print?

```
Pass
```

**95 points is clearly "Excellent," yet it printed "Pass."**

Because Python checks top to bottom:

1. First condition `score >= 60` — 95 >= 60, **true**
2. Immediately runs `print("Pass")`
3. **Done.** The `elif score >= 90` never gets looked at

No error. The logic looks fine. The result is just wrong. **This is the hardest kind of bug to find.**

### The Correct Way: Strictest First

Put the **narrowest condition at the top**:

```python
score = 95

if score >= 90:
    print("Excellent")
elif score >= 60:
    print("Pass")
else:
    print("Fail")
```

Now with 95: check >= 90 first, it holds → print "Excellent" → done. Correct.

**Mantra: order your `elif` branches from strictest to loosest.**

Put another way: **highest number first.**

## 4. A Side-by-Side Experiment

Run both of these and feel the power of ordering.

**Wrong order (broad first):**

```python
score = 95
if score >= 60:
    print("Pass")
elif score >= 90:
    print("Excellent")
```

Output: `Pass` ← wrong

**Right order (strict first):**

```python
score = 95
if score >= 90:
    print("Excellent")
elif score >= 60:
    print("Pass")
```

Output: `Excellent` ← right

Same number, same two conditions. **Only the order changed, and so did the result.**

## 5. `elif` vs. Several Separate `if`s

These look similar but behave completely differently.

**Version A: `elif` (one of many)**

```python
score = 95
if score >= 90:
    print("Excellent")
elif score >= 60:
    print("Pass")
```

Output: `Excellent` (one line only)

**Version B: separate `if`s (several can hold)**

```python
score = 95
if score >= 90:
    print("Excellent")
if score >= 60:
    print("Pass")
```

Output:

```
Excellent
Pass
```

**Both print**, because these are two independent checks that don't affect each other.

Which should you use?

| Situation | Use | Example |
|---|---|---|
| The cases are mutually exclusive; only one should match | `elif` | grade bands, age groups |
| Several cases can be true at once | separate `if`s | over 18 AND a member; raining AND traffic |

## 6. Full Example: Age Groups

```python
age = 25

if age < 12:
    print("Child")
elif age < 18:
    print("Teen")
elif age < 60:
    print("Adult")
else:
    print("Senior")
```

Notice how the conditions are written: `elif age < 18` — you **don't** need `age >= 12 and age < 18`.

Because reaching this line means `age < 12` already failed — so `age >= 12` is guaranteed true.

**That's the hidden bonus of `elif`: every branch automatically excludes all the branches above it.**

Provided the order is right. Put `age < 60` first and a 25-year-old matches it, killing everything below.
