# Project: Grade Classifier

> The last lesson of Chapter 4. No new syntax — we're **wiring the last four lessons into one program that actually works.**
>
> This is your first program with real "judgment": it gives different answers for different inputs instead of the same answer every time.

## 1. What We're Building

The result (the `←` marks what you type):

```
Enter your score: 85 ←
==============================
  Score: 85
  Grade: Good
==============================
```

Type 95 → "Excellent"
Type 45 → "Fail, 15 points short"
Type 150 → "Invalid score"

## 2. Don't Write the Final Version First

The most common beginner mistake is trying to write the finished program in one go, then drowning in bugs.

We'll go in four steps, and every step runs.

## 3. Step 1: Just the Grade Logic

Don't touch input yet. Hard-code the score and focus on getting the logic right:

```python
score = 85

if score >= 90:
    level = "Excellent"
elif score >= 75:
    level = "Good"
elif score >= 60:
    level = "Pass"
else:
    level = "Fail"

print("Grade: " + level)
```

There's something new here — we **store the result** in a variable `level`, then print once at the end.

That's better than writing `print` in every branch, because:

1. Changing the output format means changing one line
2. The decision logic and the display logic are separated, which is clearer

**Remember this pattern: `if` decides "what it is," `print` handles "how it looks."**

Get this running before moving on.

## 4. Step 2: Add Real Input

Now take the score from the user (`input` from Chapter 3):

```python
score_text = input("Enter your score: ")
score = int(score_text)

if score >= 90:
    level = "Excellent"
elif score >= 75:
    level = "Good"
elif score >= 60:
    level = "Pass"
else:
    level = "Fail"

print("Grade: " + level)
```

Two key lines:

- `input()` returns a **string**, so it goes into `score_text`
- `int()` turns it into an **integer**, so it can be compared against 90 and 75

What if you forget `int()`? Chapter 3 covered it — comparing a string with an integer raises `TypeError` immediately.

## 5. Step 3: Handle Invalid Input

Users can't be trusted. Lesson 14 said it: **users don't type what you expect.**

The problem now: if someone enters 150 or -20, the program cheerfully reports "Excellent" or "Fail" — which is nonsense, because a score of 150 doesn't exist.

Add a guard in front:

```python
score_text = input("Enter your score: ")
score = int(score_text)

if score > 100 or score < 0:
    level = "Invalid score (should be 0 - 100)"
elif score >= 90:
    level = "Excellent"
elif score >= 75:
    level = "Good"
elif score >= 60:
    level = "Pass"
else:
    level = "Fail"

print("Grade: " + level)
```

Notice this `if` goes **first**. Why?

Because `elif` stops at the first match. If the range check came later, 150 would match `score >= 90` and become "Excellent," and the validity check would never run.

**That's exactly Lesson 18's rule in action: narrowest, most special condition first.**

`score > 100 or score < 0` is the most special case (an abnormal one), so it goes first.

You can also make the intent obvious with a chained comparison:

```python
if not (0 <= score <= 100):
    level = "Invalid score"
```

## 6. Step 4: Make "Fail" Actually Useful

Just saying "Fail" isn't helpful. Tell the user **how many points they were short** — that's what makes a program worth using:

```python
score_text = input("Enter your score: ")
score = int(score_text)

if score > 100 or score < 0:
    level = "Invalid score (should be 0 - 100)"
elif score >= 90:
    level = "Excellent"
elif score >= 75:
    level = "Good"
elif score >= 60:
    level = "Pass"
else:
    level = f"Fail, {60 - score} points short"

print("Grade: " + level)
```

That last branch uses the **f-string** from Chapter 3, embedding the calculation right in the string.

45 → `Fail, 15 points short`.

## 7. The Final Version

Add the formatting from Chapter 3 and make it look complete:

```python
score_text = input("Enter your score: ")
score = int(score_text)

if score > 100 or score < 0:
    level = "Invalid score (should be 0 - 100)"
elif score >= 90:
    level = "Excellent"
elif score >= 75:
    level = "Good"
elif score >= 60:
    level = "Pass"
else:
    level = f"Fail, {60 - score} points short"

print("==============================")
print(f"  Score: {score}")
print(f"  Grade: {level}")
print("==============================")
```

Try these inputs and watch the output:

| Input | Grade |
|---|---|
| 100 | Excellent |
| 90 | Excellent |
| 89 | Good |
| 75 | Good |
| 60 | Pass |
| 59 | Fail, 1 point short |
| 150 | Invalid score |

**Boundary values are especially worth trying**: 90, 75, and 60 are exactly the dividing lines between bands.

Input that sits right on a boundary is where bugs love to hide. Whenever you write a program, test the boundaries on purpose.

## 8. Chapter Review

This chapter gave your program judgment:

| Lesson | You learned | Solves |
|---|---|---|
| 16 | `if` | Do it only when the condition holds |
| 17 | `else` | Say something when it doesn't |
| 18 | `elif` | Pick one of several |
| 19 | `and` / `or` / `not` | Combine conditions |
| 20 | Putting it together | One working program |

Three things that trip people up most, worth repeating:

1. **Colon and indentation** — `if` / `elif` / `else` all need a colon, and their bodies all need indenting
2. **`elif` order** — strictest to loosest, first match wins
3. **Complete tests on both sides of `and` / `or`** — `age > 18 and < 60` is wrong

## 9. What's Next

This program has one glaring weakness: **it runs once and stops.**

To grade another score, you have to click Run again.

A real tool should **keep running and let you repeat the action until you say quit.**

That's the next chapter — loops, `while` and `for`.

With loops, your program becomes a tool instead of a script.
