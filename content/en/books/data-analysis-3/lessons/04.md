# Fonts and Garbled Text

> Chinese characters turning into boxes, minus signs turning into squares — every English user runs into this sooner or later when mixing scripts. This lesson explains the root cause and four solutions.

## The phenomenon

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 2, 3])
ax.set_title('London Store Sales')
ax.set_xlabel('Month')
ax.savefig('chinese_broken.png')
```

Output (`chinese_broken.png`): the title and axis labels occupy their places, but **the text is a row of boxes □□□**.

Why? Matplotlib's default font is **DejaVu Sans**, a **Latin-only** font. It contains no glyphs for "北", "京", "门", so when it cannot find them it draws a tofu square.

## Solution 1: `rcParams`, set globally (the most common)

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['DejaVu Sans']
plt.rcParams['axes.unicode_minus'] = False      # render minus signs normally

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [1, 2, 3])
ax.set_title('London Store Sales')
ax.set_xlabel('Month')
ax.savefig('chinese_ok.png')
print('saved')
```

Two lines solve two problems:

- `font.sans-serif`: tells matplotlib which font to render text with.
- `axes.unicode_minus`: fixes **minus signs turning into squares** (see below).

**Put these settings at the very top of every script, before any plotting.**

## Failure scenario 1: a misspelled font name

```python
# WRONG
plt.rcParams['font.sans-serif'] = ['SomeFakeFont']   # cannot be found on some systems
fig, ax = plt.subplots()
ax.set_title('Hello')                                # still boxes
```

Output: still boxes, and **no error is raised** — when matplotlib cannot find a font it silently falls back to the default. This is why people say "I set the font but it did nothing": there was no warning at all.

**How to investigate:**

```python
from matplotlib import font_manager
# list the CJK / Chinese font names available on the system
names = sorted({f.name for f in font_manager.fontManager.ttflist
                if 'CJK' in f.name or 'Hei' in f.name or 'Song' in f.name or 'Micro' in f.name})
print(names)
```

Find the **exact name** and put it into `rcParams`. Common usable values:

| Platform | Usable font names |
|---|---|
| Windows | `Microsoft YaHei`, `SimHei` |
| macOS | `PingFang SC`, `Heiti SC`, `STHeiti` |
| Linux | `WenQuanYi Micro Hei`, `Noto Sans CJK SC` |

**Failure scenario 2: passing a string instead of a list.**

```python
# WRONG
plt.rcParams['font.sans-serif'] = 'WenQuanYi Micro Hei'   # wrong: must be a list
```

Output: the font still does not work, because matplotlib expects a **list**; a string is treated as a sequence of characters.

## Solution 2: `fontproperties` on a single Text object

When you do not want a global change and only one title needs a particular font:

```python
from matplotlib.font_manager import FontProperties

fp = FontProperties(family='WenQuanYi Micro Hei', size=14)
ax.set_title('London Store Sales', fontproperties=fp)
```

`fontproperties` is passed explicitly and overrides `rcParams`. **This suits "mixed" layouts**, such as a Chinese title with English tick labels.

## Solution 3: a `with` block for temporary switching (recommended for functions)

```python
from matplotlib import rc_context

with rc_context({'font.sans-serif': ['WenQuanYi Micro Hei'],
                 'axes.unicode_minus': False}):
    fig, ax = plt.subplots()
    ax.set_title('London')
    fig.savefig('tmp.png')
# after leaving the with block, the font settings are restored automatically
```

**This is best practice for utility functions** — it does not pollute global state and the caller need not know.

## Why the minus sign also turns into a square

The setting `axes.unicode_minus = False` looks arbitrary. The reason:

- By default matplotlib renders axis ticks with the **Unicode minus `−` (U+2212)**.
- Most CJK fonts **do not contain this character**, so it becomes a square.
- Setting it to `False` makes matplotlib use the **plain ASCII minus `-` (U+002D)**, which every font has.

```python
fig, ax = plt.subplots()
ax.plot([-1, 0, 1], [-1, 0, 1])
ax.set_title('Temperature change')
ax.set_xlabel('ΔT (°C)')
# without axes.unicode_minus = False, the tick minus signs become squares
fig.savefig('minus.png')
```

## Switching to another font style

```python
plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']   # sans, for formal reports
plt.rcParams['font.sans-serif'] = ['Noto Serif CJK SC']     # serif, paper style
plt.rcParams['font.family'] = 'serif'                        # global serif
```

Font choice affects the look:

- **Sans-serif**: screen reading, slides, web — clear and striking.
- **Serif**: print, long documents, academic papers — more refined.
- **Monospace**: code and aligned numbers.

## Recap

- The root cause of boxes is: **the default DejaVu Sans has no CJK glyphs.**
- The most common fix: `rcParams['font.sans-serif']` + `rcParams['axes.unicode_minus'] = False`.
- Font names must be **exact**; a typo fails silently (use `font_manager` to check).
- `rcParams` wants a **list**; a string does nothing.
- For one element use `fontproperties=FontProperties(...)`; for temporary changes inside a function use `rc_context`.
- Minus-sign squares come from the Unicode minus; set `axes.unicode_minus = False`.
