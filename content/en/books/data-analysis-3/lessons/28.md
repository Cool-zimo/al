# Grouped Insights: Finding the Conclusions That Actually Matter

> Once the data is read and cleaned, the real work begins: how to group it, how to aggregate it, how to rank it, and how to turn a pile of numbers into something you can say to your manager, like "London's average spend is 18% higher than New York's".

## Grouping step 1: decide what you are cutting by

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import pandas as pd
import numpy as np

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

# Simulate monthly store sales data
df = pd.DataFrame({
    'store': ['London']*4 + ['New York']*4 + ['Manchester']*4 + ['Bristol']*4,
    'month': ['Jan','Feb','Mar','Apr']*4,
    'channel': ['offline','online','offline','online','offline','online','offline','online',
                'offline','online','offline','online','offline','online','offline','online'],
    'revenue': [3200,4100,3300,4300,2800,3900,2900,4000,
               2100,2600,2200,2700,2400,3100,2500,3200],
    'orders': [120,180,125,190,100,160,105,165,
               80,120,85,125,90,140,95,145],
    'footfall': [300,450,310,470,260,400,270,420,
                200,300,210,320,230,350,240,360],
})

print(df.head())
print('total', len(df), 'rows')
```

Before grouping you must answer one question: **who am I comparing with whom?** Stores by scale, channels by efficiency, or months by trend? That grouping field is your "who". Pick the wrong one and the means you calculate, however precise, are useless.

**Wreck of the day 1: forgetting to deduplicate and grouping detail rows directly.**

```python
# WRONG: each line in the detail table is one SKU, so grouping by store and summing double-counts orders
detail = pd.DataFrame({
    'order_id': ['A001','A001','A002','A002'],
    'store': ['London','London','New York','New York'],
    'item': ['coffee','cake','coffee','cake'],
    'amount': [30, 20, 30, 20],
})
print(detail.groupby('store')['amount'].sum())
# London 50, New York 50 - they look identical, but each is one 50 GBP order
```

Mixing up detail granularity and aggregation granularity is the most common beginner mistake. Each order has two rows (two items), so grouping by store gives "the total of all SKU amounts", not "total revenue per store". The correct move is to deduplicate and aggregate by order first: `detail.groupby('order_id').agg(order_total=('amount','sum'))`, then aggregate by store.

## Group + aggregate: compute several metrics at once

```python
# Single grouping, multiple metrics
g = df.groupby('store').agg(
    revenue_total=('revenue','sum'),
    orders_total=('orders','sum'),
    footfall_total=('footfall','sum'),
    avg_ticket=('revenue','mean'),
    month_count=('month','count'),
)
g['avg_spend'] = (g['revenue_total']/g['orders_total']).round(1)
g['conversion_pct'] = (g['orders_total']/g['footfall_total']*100).round(1)
print(g.sort_values('revenue_total', ascending=False))
```

Inside `agg` you can put several aggregation functions at once, using the syntax `new_name=(column, function)`. `'sum'`, `'mean'` and `'count'` are string shorthands, and `'nunique'` counts too. One grouping pass computes "scale + efficiency + conversion" together instead of writing groupby repeatedly.

**Wreck of the day 2: mixing columns in agg produces an incomprehensible error.**

```python
# WRONG: two functions on the same column but no distinct key names
try:
    df.groupby('store').agg(['sum','mean'])
except Exception as e:
    print('error:', repr(e)[:80])
# TypeError: ... duplicate column names, agg does not know what to call the result
```

Writing `["sum","mean"]` like this makes pandas use the aggregation function names as column names, and multiple functions across multiple columns collide immediately. The fix is to **name things explicitly with a dict or tuple**: `agg(revenue_total=('revenue','sum'), revenue_mean=('revenue','mean'))`, so every result gets its own column name.

## Multi-dimensional crosstab: spot differences in a grid

```python
# Store x channel cross revenue
cross = df.pivot_table(
    index='store', columns='channel', values='revenue', aggfunc='sum', fill_value=0)
print(cross)

# Add a layer: each cell shows average spend
cross2 = df.pivot_table(
    index='store', columns='channel',
    values=['revenue','orders'], aggfunc='sum', fill_value=0)
print(cross2)
```

`pivot_table` is "grouping in two dimensions". One dimension (store) goes on the rows, another (channel) on the columns, and the aggregated value sits in the middle. The point of a crosstab is that **it puts the "difference" right in front of you**: which cells are big and which are small is immediately visible. It is the fastest tool for finding conclusions, bar none.

Do not skip `fill_value=0` - the default missing value is `NaN`, and any later division produces `NaN`, taking out the whole column.

## Sort for Top / Bottom: conclusions come from comparison

```python
# Rank by revenue and find the Top 3 and Bottom 3
s = df.groupby('store')['revenue'].sum().sort_values(ascending=False)
print('Top3:', list(s.head(3).index))
print('Bottom3:', list(s.tail(3).index))

# How big is the gap? Ratio and difference
top, bot = s.iloc[0], s.iloc[-1]
print(f'the strongest ({s.index[0]}) is {top/bot:.2f}x the weakest ({s.index[-1]})')
```

Sorting is not about "neatly arranging the numbers"; it is about **creating a comparison**. A mean on its own says nothing; "the highest is 1.6 times the lowest" is a story. Top and Bottom should appear together: leading with only the best looks like boasting, leading with only the worst looks defeatist, and putting both side by side is objective analysis.

## Turning "differences" into a "story"

```python
# Express the relative gap as a percentage
base = g['revenue_total']
best = base.max()
g['vs_best_pct'] = ((base/best - 1)*100).round(1)
print(g[['revenue_total','avg_spend','conversion_pct','vs_best_pct']])
```

The raw data says "London 14900, New York 13600"; the story version says "**London leads New York by 9.6% and its average spend is 12% higher**". The difference is that raw data is for machines, while the story is for decision-makers. The three-part translation: **name the lead (who is strongest/weakest), measure the gap (ratio or percentage), give the reason (explain it with other metrics)**.

```python
# Generate one conclusion automatically
row = g.sort_values('revenue_total', ascending=False).iloc[0]
print(f"Finding: {row.name} has the highest revenue ({row['revenue_total']}), "
      f"avg spend {row['avg_spend']}, conversion {row['conversion_pct']}%, "
      f"making it the top performer.")
```

## Summary

- Before grouping, decide "what to cut by"; the grouping field sets the boundary of the conclusion
- Keep detail granularity and aggregation granularity separate; deduplicate before aggregating
- In `agg`, use `new_name=(column, function)` to name results explicitly and compute many metrics at once
- `pivot_table` does two-dimensional grouping and exposes differences naturally
- Top and Bottom belong together, and the gap should be expressed as a ratio or percentage
- Story = lead + gap + reason; no part can be missing
