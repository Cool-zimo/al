# Titles, axis labels, legends, and grids: make the plot self-explaning

> If you hand a plot to someone with no background in your data, will they understand it? This lesson covers the four elements that make a figure self-explaining: title, axis labels, legend, and grid.

## What a self-explaining plot looks like

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

months = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun']
london = [120, 135, 128, 160, 175, 190]
new_york = [110, 118, 130, 140, 155, 168]

fig, ax = plt.subplots(figsize=(9, 5))

ax.plot(months, london, marker='o', label='London')
ax.plot(months, new_york, marker='s', linestyle='--', label='New York')

ax.set_title('London vs New York: H1 2025 store sales', fontsize=14)
ax.set_xlabel('Month')
ax.set_ylabel('Sales (£10k)')
ax.legend()
ax.grid(True, linestyle='--', alpha=0.4)

fig.tight_layout()
fig.savefig('self_explained.png')
print('saved')
```

Anyone looking at this figure can answer four questions: **what is being compared (title), what the horizontal axis is (xlabel), what the vertical axis is (ylabel), which line is which (legend), and where the grid lines are (grid)**.

## The title: write it as a full sentence

**Crash site 1: the title is too short.**

```python
ax.set_title('Sales')            # which store? which period? which metric?
```

Output: the reader is **left guessing**. A good title contains three ingredients: "subject + metric + time".

**A good title:**

```python
ax.set_title('London vs New York: H1 2025 store sales', fontsize=14)
#            subject      comparison     time      metric
```

| Ingredient | Example | What goes wrong without it |
|---|---|---|
| Subject | London store / two-store comparison | the reader has no idea whose data it is |
| Metric | sales / average spend per customer | the vertical axis is meaningless |
| Time | H1 2025 | the freshness of the data is unknown |

`fig.suptitle` sets the title of the **entire figure**; `ax.set_title` sets the title of one panel. In a grid, use `suptitle` for the overall heading and `set_title` for each panel's individual heading.

## Axis labels: always include the unit

```python
ax.set_xlabel('Month')
ax.set_ylabel('Sales (£10k)')        # <- the unit is a lifesaving detail
```

**Crash site 2: forgetting the unit.**

```python
ax.set_ylabel('Sales')               # pounds? tens of thousands? millions?
ax.set_xlabel('Time')                # days? months? quarters?
```

Output: the reader **cannot judge the scale**. Is that 100 or 100 million? This kind of ambiguity is one of the most common reasons reports get sent back.

**A more precise style:**

```python
ax.set_ylabel('Sales / £10k')         # slash notation, instantly readable
ax.set_xlabel('Month (2025)')
```

## The legend: where to put it

```python
ax.plot(months, london, label='London')
ax.plot(months, new_york, label='New York')
ax.legend(loc='upper left')           # position
```

Valid values for `loc`: `'best'` (matplotlib picks the emptiest spot automatically), `'upper left'`, `'upper right'`, `'lower left'`, `'lower right'`, `'center'`.

**Crash site 3: the legend covers the data.**

```python
ax.legend(loc='upper left')           # London's data also happens to sit in the top-left, so it is covered
```

Output: the legend **sits on top of a key data point**. The fix is either `loc='best'` to let matplotlib find an empty corner, or manually picking a non-conflicting spot. If the panel has no free space at all:

```python
ax.legend(loc='upper center', bbox_to_anchor=(0.5, 1.12),
          ncol=2, frameon=False)
```

`bbox_to_anchor` places the legend **above the panel** (y=1.12 is outside the plotting area), `ncol=2` lays the entries out in two columns, and `frameon=False` drops the border. This is the standard "legend on top" recipe used in reports.

## The grid: a reading aid, not the main event

```python
ax.grid(True, linestyle='--', alpha=0.4)   # dashed + low opacity
```

The grid's job is to **help the eye align values**, but it must stay subtle. Three parameters matter:

| Parameter | Recommended value | Reason |
|---|---|---|
| `linestyle` | `'--'` dashed | weaker than a solid line, so it never competes with the data |
| `alpha` | `0.3~0.5` | keeps it pale |
| `color` | `'gray'` | neutral |

**Crash site 4: the grid is too heavy.**

```python
ax.grid(True, color='black', linewidth=1.5)    # black, thick grid overwhelms the data
```

Output: the grid lines are **more prominent than the data**, so the reader cannot tell what matters. A grid should always be weaker than the data it supports.

**One direction is often enough:**

```python
ax.grid(axis='y', linestyle=':', alpha=0.5)    # horizontal reference lines only
ax.grid(axis='x', linestyle=':', alpha=0.5)    # vertical only
```

For a line chart you usually only need `axis='y'`, and the same applies to bar charts: it lets the eye travel along the value direction.

## Putting every element together

```python
fig, ax = plt.subplots(figsize=(9, 5))

ax.plot(months, london, marker='o', linewidth=2, label='London')
ax.plot(months, new_york, marker='s', linestyle='--', linewidth=2, label='New York')

# Title: subject + comparison + time + metric
ax.set_title('London vs New York: H1 2025 store sales', fontsize=14)

# Axis labels with units
ax.set_xlabel('Month')
ax.set_ylabel('Sales / £10k')

# Legend
ax.legend(loc='upper left')

# Grid: pale, dashed, horizontal only
ax.grid(axis='y', linestyle='--', alpha=0.4)

fig.tight_layout()
fig.savefig('final.png')
```

## Recap

- A good title = **subject + metric + time**
- Axis labels **must carry a unit**; "Sales / £10k" is the clearest form
- Legend: `loc='best'` finds an empty corner automatically, or `bbox_to_anchor` puts it on top
- The grid must be **weaker than the data**: dashed + alpha 0.3~0.5 + one direction only
- `suptitle` is the figure-level title; `set_title` belongs to a single panel
- If your legend does not show up, the odds are you forgot either `label=` or `legend()`
