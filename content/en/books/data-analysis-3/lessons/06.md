# Bar Charts `bar` / `barh`: Comparing Categories

> The bar chart is the default choice for "which is bigger": which store sells more, which month performs best. This lesson covers the difference between `bar` and `barh`, and what to do when categories pile up.

## When to use a bar chart

**You are answering "which category is largest".** Each bar represents a category and its height is the value; the eye compares lengths instantly.

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

stores = ['London', 'New York', 'Tokyo', 'Paris', 'Sydney']
sales = [1280, 1520, 980, 1100, 860]

fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(stores, sales, color='#377eb8')
ax.set_title('Five Stores, H1 2025 Sales')
ax.set_ylabel('Revenue (£10k)')
fig.savefig('bar_basic.png')
print('saved')
```

`ax.bar(x, height)`: x is the category position (or label), height is the bar's height. That is all there is to it.

## Horizontal bar charts with `barh`

**Use horizontal bars when category names are long or there are more than seven or eight categories.**

```python
fig, ax = plt.subplots(figsize=(8, 5))
ax.barh(stores, sales, color='#e41a1c')
ax.set_xlabel('Revenue (£10k)')
ax.set_title('Five Stores, H1 2025 Sales')
fig.savefig('barh_basic.png')
```

`barh(y, width)`: y is the category, width is the length. **Note that the parameter changes from `height` to `width`** because the bars now run horizontally.

| Vertical `bar` | Horizontal `barh` |
|---|---|
| Short category names | Long names ("North Region", "South Region") |
| Categories ≤ 7 | Categories ≥ 8, where vertical bars get spiky |
| Emphasis on "tall vs short" | Emphasis on "ranking by length" |
| x-axis is the category | y-axis is the category |

## Failure scenario 1: too many categories turn into spikes

```python
cities = ['London', 'New York', 'Tokyo', 'Paris', 'Sydney', 'Berlin',
          'Dubai', 'Singapore', 'Toronto', 'Madrid', 'Rome', 'Bangkok',
          'Seoul', 'Cairo']
vals = [1280, 1520, 980, 1100, 860, 720, 690, 650, 630, 590, 560, 510, 480, 460]

fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(cities, vals)            # 14 categories crammed into 8 inches
fig.savefig('crowded.png')
```

Output: the 14 x-tick labels **overlap into an unreadable mess** — you cannot tell which city is which. The main cause is that `figsize` was not widened to match the number of categories.

**Fix: switch to `barh`, or make the figure wider.**

```python
fig, ax = plt.subplots(figsize=(8, 6))
ax.barh(cities, vals)
ax.set_xlabel('Revenue (£10k)')
fig.savefig('barh_many.png')
```

Once horizontal, every city gets its own row and nothing clashes.

## Quick parameter reference

```python
ax.bar(stores, sales,
       width=0.6,           # bar width, 0-1, larger means fatter
       color='#377eb8',     # fill colour
       edgecolor='black',   # border colour
       linewidth=1,         # border thickness
       alpha=0.8)           # transparency, 0 = fully transparent
```

| Parameter | Role |
|---|---|
| `width` | Bar width, default 0.8 |
| `color` | Fill colour |
| `edgecolor` | Bar border colour |
| `linewidth` | Border thickness |
| `alpha` | Transparency 0–1 |

## Failure scenario 2: colours that are too loud

```python
ax.bar(stores, sales, color='red')     # pure red, painful to look at
```

Output: the chart "screams" and hurts the eyes after a while. **Use soft, non-glaring colours** with hex values that lower saturation: `#e41a1c` (soft red), `#377eb8` (soft blue), `#4daf4a` (soft green). These are the classic Set1/Tableau palette, friendly to colour-blind readers.

## Grouped bars: comparing two or more series

```python
import numpy as np

stores = ['London', 'New York', 'Tokyo', 'Paris']
q1 = [620, 710, 480, 550]
q2 = [660, 810, 500, 550]

x = np.arange(len(stores))      # [0, 1, 2, 3]
w = 0.35                        # width of each bar

fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(x - w/2, q1, w, label='Q1')
ax.bar(x + w/2, q2, w, label='Q2')
ax.set_xticks(x)                # ticks at integer positions
ax.set_xticklabels(stores)      # labels in English
ax.legend()
ax.set_title('Quarterly Sales by Store')
fig.savefig('bar_grouped.png')
```

**The key trick: `x - w/2` and `x + w/2` offset the two groups**, otherwise they sit on top of each other. `np.arange(len(stores))` produces `[0,1,2,3]` as the category coordinates.

## Failure scenario 3: the offset is wrong

```python
# WRONG
ax.bar(x, q1, w, label='Q1')
ax.bar(x + 1, q2, w, label='Q2')   # offset by a whole unit; a big gap in between
```

Output: a **huge gap between the two groups**, and the second group has drifted onto another category. The correct offset is `w/2` (half a bar width), so they sit flush.

## Stacked bars

```python
fig, ax = plt.subplots(figsize=(8, 5))
ax.bar(stores, q1, label='Q1')
ax.bar(stores, q2, bottom=q1, label='Q2')   # bottom sets the baseline to stack on
ax.legend()
ax.set_title('Stacked: total sales = Q1 + Q2')
fig.savefig('bar_stacked.png')
```

`bottom=q1` makes the Q2 bars **start drawing from the top of Q1**, producing a stack. This is ideal for showing "total + composition".

**Stacked vs grouped — how to choose:**

| | Grouped | Stacked |
|---|---|---|
| Best for | Comparing the sizes of the parts | Seeing the total and the share of each part |
| Drawback | Many bars look cramped | The middle parts are hard to compare precisely |
| Typical question | "Did London or New York sell more in Q1?" | "What share of London's total came from Q1?" |

## Adding value labels on the bars

```python
fig, ax = plt.subplots(figsize=(8, 5))
bars = ax.bar(stores, sales, color='#377eb8')
for bar in bars:
    h = bar.get_height()
    ax.text(bar.get_x() + bar.get_width()/2, h,     # above the bar's centre
            str(h), ha='center', va='bottom')
ax.set_title('Values labelled above each bar')
fig.savefig('bar_label.png')
```

`bars` is a `BarContainer`; iterating over it yields each bar, `bar.get_height()` returns the height and `bar.get_x()` the left edge. **Iterate-and-label** is the most common finishing touch on a bar chart.

## Recap

- Bar charts answer "which category is largest"; the eye compares lengths fastest.
- `bar` is vertical, `barh` is horizontal; **use horizontal for long names or many categories**.
- Grouped: offset by `x ± w/2`; stacked: set `bottom=`.
- Avoid pure red and pure green; use soft hex colours.
- Value labels: `bar.get_height()` + `ax.text`.
- Default bar width is 0.8; too wide and they crowd.
