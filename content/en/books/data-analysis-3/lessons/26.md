# Receiving Dirty Data: Read, Overview, Set a Cleaning Strategy

> Real data never arrives clean. This lesson is about the first 15 minutes after you receive a file: get it in, understand it, set a cleaning strategy. Get the order wrong and every later step is wasted effort.

## Step 1: get it in - do not analyse yet

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import pandas as pd
import numpy as np

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

# Simulate a dirty export from a store system
raw = pd.DataFrame({
    'store': ['London', 'London', 'New York', None, 'Manchester', 'Bristol', 'London'],
    'date': ['2025-01-01', '2025-01-02', '2025/1/3', '2025-01-04',
            '20250105', '2025-01-06', '2025-01-07'],
    'revenue': ['1000', '1,200', '980', '1500', 'nan', '800', '3200 GBP'],
    'footfall': [120, 130, 'no record', 150, 90, 100, 125],
    'channel': ['offline', 'online', 'online', 'offline', 'online', None, 'offline'],
})

raw.to_csv('store_raw.csv', index=False, encoding='utf-8-sig')

df = pd.read_csv('store_raw.csv')
print(df.shape)        # (7, 5)
print(df.dtypes)
print(df.head())
```

Useful `pd.read_csv` arguments:

| Argument | Purpose |
|---|---|
| `encoding` | Chinese files are often `gbk` or `utf-8-sig`; switch if garbled |
| `dtype` | force column types so numbers are not read as object |
| `parse_dates` | which columns to parse as dates |
| `na_values` | extra strings to treat as missing, e.g. `['no record','--']` |

**Wreck of the day 1: an encoding error means the file will not load.**

```python
# WRONG: files exported from a Chinese system are often GBK, which fails immediately
pd.read_csv('beijing_store.csv')
# UnicodeDecodeError: 'utf-8' codec can't decode byte 0xbc ...
```

The error message already tells you the answer - `codec can't decode byte` means the file is not UTF-8. **Fix the encoding before anything else.** The usual order is `utf-8` -> `utf-8-sig` -> `gbk`. `utf-8-sig` exists specifically for Windows files that carry a hidden three-byte BOM at the start.

## Step 2: overview - build a data map

```python
print('=== shape ===')
print(df.shape)                    # (7, 5)
print('\n=== types ===')
print(df.dtypes)
print('\n=== missing ===')
print(df.isna().sum())
print('\n=== duplicates ===')
print('duplicate rows:', df.duplicated().sum())
print('\n=== unique values preview ===')
for c in df.columns:
    print(c, ':', df[c].unique()[:8])
```

The goal here is to **build a data map**: how many rows, which columns are numeric, where the gaps are, whether anything is duplicated, and what the valid values of each field look like. Four lines of code, almost free, but they prevent most later mistakes.

**Wreck of the day 2: unspotted duplicates double the aggregation.**

```python
print('before dedup:', len(df))
df = df.drop_duplicates()
print('after dedup:', len(df))
```

Duplicate rows distort sums and means. **Deduplicate before computing any aggregation.** But note: `drop_duplicates()` only removes completely identical rows. If several columns match while others differ, that is valid data and must not be removed - in that case set `subset=['order_id']` explicitly.

## Step 3: set the cleaning strategy

Looking at the overview, write a cleaning checklist:

```python
plan = pd.DataFrame([
    ['store',   'missing',            'fill as "unknown" or drop', 'pending'],
    ['date',    'inconsistent format', 'unify to datetime',       'required'],
    ['revenue', 'commas, units, missing', 'strip symbols, convert to number', 'required'],
    ['footfall','string "no record" mixed in', 'convert to number, mark missing', 'required'],
    ['channel', 'missing',            'fill as "unknown"',        'pending'],
], columns=['field', 'problem', 'action', 'priority'])
print(plan)
```

**Wreck of the day 3: changing things before deciding what to change, so it gets messier.**

Editing as you look, discovering that an earlier assumption was wrong, going back to fix it - you end up unsure which step changed what. **Write the list, set the priorities, then act.** The checklist is not for the report; it is an anchor you can check against later.

## The six most common problems in dirty data

| Type | Example | How to handle it |
|---|---|---|
| Wrong type | `'1000'` is a string | `pd.to_numeric` |
| Missing | `None`, `nan`, empty string | `fillna` or drop |
| Duplicate | completely identical rows | `drop_duplicates` |
| Inconsistent format | `'2025-01-01'` vs `'2025/1/3'` | parse consistently |
| Unit mixed in | `'3200 GBP'`, `'1,200'` | strip symbols then convert |
| Outlier | revenue = -5 | investigate then handle |

```python
# A quick profile function that shows every problem at once
def profile(df):
    out = pd.DataFrame({
        'type': df.dtypes.astype(str),
        'missing_count': df.isna().sum().values,
        'missing_pct': (df.isna().mean() * 100).round(1).astype(str) + '%',
        'unique_count': df.nunique().values,
        'duplicate_rows': df.duplicated().sum(),
    })
    return out

print(profile(df))
```

Note that `isna().sum().sum()` uses **two** `sum()` calls: the first sums each column into a Series, and the second adds those Series together. A single `sum()` returns a Series with one number per column, not the total.

## Summary

- Three steps to read a file: read it in -> switch encoding to fix garble -> inspect shape/dtypes/missing/duplicates
- Encoding order: `utf-8` -> `utf-8-sig` -> `gbk`
- Deduplicate before aggregating, but only remove fully identical rows
- Set the checklist, priorities and order before cleaning, so the process is reproducible
- Six common problem types: type, missing, duplicate, format, units, outliers
- A profile function gives you a one-shot health check and a data map
