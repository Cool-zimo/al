# Writing the Report: Conclusions, Evidence, Limits and "What Data to Collect Next"

> This is the final lesson of the book. By now you can read data, clean it, group it and draw charts - only one step remains: turn the work into a report that other people will actually read and dare to use. A good report = clear conclusions + verifiable evidence + honest limits + a pointer to what comes next.

## What a usable report looks like

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import pandas as pd
import numpy as np

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

df = pd.DataFrame({
    'store': ['London']*4 + ['New York']*4 + ['Manchester']*4 + ['Bristol']*4,
    'month': ['Jan','Feb','Mar','Apr']*4,
    'channel': ['offline','online']*8,
    'revenue': [3200,4100,3300,4300,2800,3900,2900,4000,
               2100,2600,2200,2700,2400,3100,2500,3200],
    'orders': [120,180,125,190,100,160,105,165,
               80,120,85,125,90,140,95,145],
    'footfall': [300,450,310,470,260,400,270,420,
             200,300,210,320,230,350,240,360],
})

# Compute the conclusions
g = df.groupby('store').agg(revenue_total=('revenue','sum'),
                          orders_total=('orders','sum'),
                          footfall_total=('footfall','sum')).sort_values('revenue_total')
g['avg_spend'] = (g['revenue_total']/g['orders_total']).round(1)
g['conversion_pct'] = (g['orders_total']/g['footfall_total']*100).round(1)

print(g)
print('\n=== report highlights ===')
print(f'1. Rank by scale: {list(g.index)}')
print(f'2. London leads Manchester by {(g["revenue_total"].max()/g["revenue_total"].min()-1)*100:.1f}%')
print(f'3. Avg spend gap < {(g["avg_spend"].max()-g["avg_spend"].min())/g["avg_spend"].min()*100:.1f}%')
```

A decent report has four paragraphs, and none can be missing:

| Paragraph | Role | Common mistake |
|---|---|---|
| Conclusion | state the finding up front | talk for ages without the point |
| Evidence | numbers + charts back it up | conclusion only, no numbers |
| Limits | state the data boundary | overclaim the conclusion |
| Next step | say what data is missing | stop at the conclusion |

## Conclusion: state "so what" in one line

```python
# Generate the conclusion from the data so the numbers stay consistent
best = g.iloc[-1]
worst = g.iloc[0]
print(f"Conclusion: {best.name} leads with {best['revenue_total']} GBP, "
      f"{(best['revenue_total']/worst['revenue_total']-1)*100:.1f}% above {worst.name}; "
      f"but avg spend across all four stores sits between "
      f"{g['avg_spend'].min()} and {g['avg_spend'].max()} GBP, "
      f"a gap under {(g['avg_spend'].max()-g['avg_spend'].min())/g['avg_spend'].min()*100:.1f}%, "
      f"so the advantage comes from footfall rather than customer value.")
```

**A conclusion has numbers, a comparison and a judgement.** A pure description ("London has the highest revenue") is not a conclusion, because it does not say by how much or why it matters. A comparison ("leads by 34%") is. Generating the conclusion programmatically also prevents a low-level but fatal error: changing the data but forgetting to update the numbers in the report.

**Wreck of the day 1: the conclusion reads like an abstract, full of "this report analyses...".**

```python
# WRONG: the conclusion became a process description
report_wrong = """
This report conducts an in-depth analysis of the sales data from four stores,
using groupby aggregation and matplotlib visualisation,
and statistical work was carried out on revenue, orders and footfall,
leading to relevant conclusions with some reference value.
"""
print(report_wrong)
# You finish reading with no idea what the conclusion is - it was not written
```

This "process-style conclusion" is extremely common in real reports: it looks busy but carries zero information. **The first sentence of the conclusion paragraph must be a judgement**, such as "London's lead comes from footfall rather than average spend". Methods, tools and process belong in an appendix and have no place in the conclusion.

## Evidence: show the table and the chart together

```python
# Supporting charts: the visual evidence for the conclusion
fig, axes = plt.subplots(1, 2, figsize=(13, 5))

axes[0].bar(g.index, g['revenue_total'], color='#4C72B0')
axes[0].set_title(f'{best.name} leads {worst.name} by '
                  f'{(best["revenue_total"]/worst["revenue_total"]-1)*100:.1f}%')
for i, v in enumerate(g['revenue_total']):
    axes[0].text(i, v+200, str(v), ha='center', fontsize=9)

axes[1].bar(g.index, g['avg_spend'], color='#DD8452')
axes[1].set_title(f'Avg spend differs by only {g["avg_spend"].max()-g["avg_spend"].min()} GBP, no efficiency gap')
for i, v in enumerate(g['avg_spend']):
    axes[1].text(i, v+0.3, str(v), ha='center', fontsize=9)

plt.tight_layout()
plt.savefig('final_report.png', dpi=120)
plt.close()
print('charts saved')
```

The standard form for evidence is **one table + one chart**. The table gives exact numbers (which others can check), and the chart gives the immediate impression (which others grasp at a glance). They complement each other: a chart alone invites "how did you get 34%?", while a table alone gets "I cannot see the trend".

## Limits: being honest about the boundary makes you more credible

```python
# Detect and list the data limits automatically
issues = []
if df['month'].nunique() < 6:
    issues.append(f'Data covers only {df["month"].nunique()} months, so seasonal conclusions are unreliable')
if df['store'].nunique() < 5:
    issues.append(f'Only {df["store"].nunique()} stores in the sample; extrapolating to other cities needs care')
if 'cost' not in df.columns:
    issues.append('Cost data is missing, so profit cannot be judged - revenue is not profit')
if 'member' not in df.columns:
    issues.append('Member / repeat-purchase data is missing, so retention cannot be assessed')

print('Data limits:')
for i, x in enumerate(issues, 1):
    print(f'  {i}. {x}')
```

Limits are not weakness; they **set the scope of the conclusion**. Declaring a "low-season pattern" from only four months is overreach; stating "fewer than six months of data, seasonality unverified" makes the earlier conclusion more believable. A practical way to write limits is column by column: which fields are absent, how long the period is, how fine the granularity is, where the gaps are - each one is a limit.

**Wreck of the day 2: writing correlation into the conclusion as causation.**

```python
# WRONG: seeing a high online share and declaring online the cause of growth
corr = df.groupby('channel')['revenue'].sum()
if corr.get('online', 0) > corr.get('offline', 0):
    print('Conclusion: the online channel is the main cause of sales growth')  # wrong!
# The data only records "what"; it does not record "why"
```

Correlation only says two variables move together; it does not say which causes which. It may simply be that the London store already has high footfall and happens to have a high online share. **"Cause" needs separate data to verify**: run an A/B test, look at a同期对照, add control variables. Writing "online share is higher" is evidence; writing "online drove the growth" is speculation - and speculation must be labelled as such, not passed off as a conclusion.

## Next step: what data to collect

```python
# Work backwards from the current limits to the next data requirement
plan = pd.DataFrame([
    ['cost / gross margin', 'profitability analysis', 'cost sheet, purchase price'],
    ['member ID / repeat purchases', 'customer retention', 'membership system export'],
    ['promotion records', 'attributing campaign impact', 'marketing calendar'],
    ['competitor pricing', 'pricing sanity', 'market research'],
    ['weather / holidays', 'controlling external factors', 'public data sources'],
], columns=['data to collect', 'question it answers', 'where to get it'])

print(plan.to_string(index=False))
```

**A data gap is the next topic.** The current data can only answer "how big, what structure"; it cannot answer "is it profitable, do customers stay, do campaigns work" - and every unanswerable question is a piece of data waiting to be collected. Listing "what to collect next" is the watershed between a one-off analysis and an ongoing one, and it is the part of the report that shows the most professionalism.

```

```

The book completes this circle: lessons 1-5 covered Python fundamentals and data structures, lessons 6-14 the core operations of NumPy and Pandas, lessons 15-20 cleaning and processing real data, lessons 21-25 deeper grouping and pivoting, lessons 26-27 the full flow from dirty data to clean data, and lessons 28-29 turning data into insights and charts. This lesson turns it into a report. **Data work is not a ray but a loop**: write the report -> discover the data gap -> go and collect -> analyse again, each round one step closer to the truth.

## Summary

- A good report has four paragraphs: conclusion, evidence, limits, next step
- The conclusion has numbers, a comparison and a judgement; its first sentence is a judgement
- Evidence = table (checkable) + chart (readable), and you need both
- Limits define the scope of the conclusion; stating them clearly makes you more credible
- Correlation is not causation; speculation must be labelled and must not be passed off as a conclusion
- A data gap is the next topic; closing the loop is what makes analysis professional
