# Figure and Axes: the Canvas and the Coordinate System

> Writing `plt.plot(x, y)` is enough to get a picture, but as soon as you need multiple subplots, titles or different sizes, you must understand figure and axes. This lesson explains the two APIs in one pass.

## Two concepts

- **Figure (the canvas)**: the whole sheet of paper — one file, one picture. It can hold a single coordinate system or be sliced into a 2×2 grid.
- **Axes (the coordinate system)**: one plotting region on the canvas, containing the x-axis, y-axis, ticks and data. `plot` ultimately draws on an Axes.

Watch out for the naming trap: `Axes` is **one** coordinate system (not the plural "axes"), whereas `Axis` is the x-axis or the y-axis.

## Approach 1: the `plt` interface (the "state machine")

`plt.plot` finds the "current figure, current axes" and draws on it, with no explicit declaration.

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt

months = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun']
sales = [120, 135, 128, 160, 175, 190]

plt.plot(months, sales)
plt.title('London Store H1 Sales')
plt.xlabel('Month')
plt.ylabel('Revenue (£10k)')
plt.savefig('sales.png')
print('saved')
```

This style is **fast to write and short to read**, fine for a quick look at your data.

## Approach 2: object-oriented (holding the object explicitly)

```python
fig, ax = plt.subplots()          # fig is the canvas, ax is the axes

ax.plot(months, sales)
ax.set_title('London Store H1 Sales')
ax.set_xlabel('Month')
ax.set_ylabel('Revenue (£10k)')
fig.savefig('sales2.png')
```

With no arguments, `plt.subplots()` returns a `(fig, ax)` tuple. The key difference: **you are holding the `ax` object**, and every later operation is called on it.

## Why the object-oriented style is recommended

**Failure scenario 1: state leaks when you draw several figures.**

```python
# WRONG: in state-machine mode, the second figure "inherits" the first one's settings
plt.plot([1, 2, 3], [1, 2, 3])
plt.title('First')              # you think this is the first figure's title
plt.savefig('fig1.png')         # but it actually saves "first + second" stacked together

plt.plot([1, 2, 3], [3, 2, 1])
plt.title('Second')
plt.savefig('fig2.png')         # this one also carries the first figure's line!
```

Output: both figures **contain both datasets**; `fig2.png` shows the title "Second" but has four lines. The reason is that the `plt` interface keeps using the **same current figure** unless you explicitly call `plt.figure()` to start a new one.

**Correct version:**

```python
fig1, ax1 = plt.subplots()
ax1.plot([1, 2, 3], [1, 2, 3])
ax1.set_title('First')
fig1.savefig('fig1.png')

fig2, ax2 = plt.subplots()
ax2.plot([1, 2, 3], [3, 2, 1])
ax2.set_title('Second')
fig2.savefig('fig2.png')
```

Each `fig` is an independent canvas; nothing leaks between them.

## `plt.xxx` versus `ax.xxx`

Most `plt.xxx` functions have a matching `ax.set_xxx` / `ax.xxx`:

| Need | `plt` interface | Object-oriented |
|---|---|---|
| Draw a line | `plt.plot(x, y)` | `ax.plot(x, y)` |
| Title | `plt.title(t)` | `ax.set_title(t)` |
| x-axis label | `plt.xlabel(t)` | `ax.set_xlabel(t)` |
| y-axis label | `plt.ylabel(t)` | `ax.set_ylabel(t)` |
| Legend | `plt.legend()` | `ax.legend()` |
| Grid | `plt.grid(True)` | `ax.grid(True)` |
| x-range | `plt.xlim(a, b)` | `ax.set_xlim(a, b)` |
| Save | `plt.savefig(f)` | `fig.savefig(f)` |

The rule: `plt` is a verb (`plt.title`), while `ax` uses `set_xxx` methods. **Remember this one line and you can read both APIs.**

## One canvas, several coordinate systems

```python
fig, axes = plt.subplots(1, 2, figsize=(10, 4))   # 1 row, 2 columns
ax1, ax2 = axes                                   # unpack

ax1.plot(months, sales, color='#e41a1c')
ax1.set_title('London')

ax2.bar(months, [90, 100, 95, 110, 130, 140], color='#377eb8')
ax2.set_title('New York')

fig.suptitle('H1 Sales Comparison')
fig.tight_layout()
fig.savefig('two_axes.png')
```

`plt.subplots(1, 2)` returns `(fig, array([ax1, ax2]))`. With multiple subplots, `axes` is a NumPy array, so you can index it as `axes[0]`, `axes[1]` or unpack it as above. **When unpacking, the count must match the number of columns**; writing `ax1, ax2, ax3 = axes` when there are only 2 columns raises an error.

## Failure scenario 2: mixing up `set` and `get`

```python
# WRONG
ax.title('A title')        # AttributeError: 'Axes' object has no attribute 'title'
ax.set_xlabel = 'Month'    # WRONG: treating a method as an attribute; nothing changes on the plot
```

Output: the first line raises `AttributeError`; the second **fails silently — the most dangerous kind.**

**Correct version:**

```python
ax.set_title('A title')      # it is a method, parentheses required
ax.set_xlabel('Month')       # same here
ax.set_ylabel('Revenue (£10k)')
```

## Recap

- **Figure = the canvas (a sheet of paper)**, **Axes = the plotting region** (with x/y ticks).
- `plt.subplots()` returns `(fig, ax)`; with subplots, `axes` is an array.
- The `plt` interface is a state machine and **easily cross-contaminates figures**; the OO style is recommended.
- `plt.xxx` ↔ `ax.set_xxx` are the two matching APIs.
- For subplots use `plt.subplots(nrows, ncols)` and unpack to match.
