# Heatmaps and correlation matrices: heatmap, annot, and masking the upper triangle

> Once variables pile up, drawing scatter plots one pair at a time is too slow. A correlation matrix tells you "who relates to whom" in one square, making it the fastest global scan in exploratory analysis.

## Correlation matrix: scan every relationship at a glance

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import seaborn as sns
import pandas as pd
import numpy as np

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

tips = sns.load_dataset('tips')

corr = tips.corr(numeric_only=True)
print(corr)
```

`df.corr()` computes the **Pearson correlation coefficient** by default, ranging from -1 to 1. The closer to +/-1, the stronger the linear relationship; the closer to 0, the weaker. The result is a symmetric square matrix: row i, column j holds the correlation between variable i and variable j.

**Crash site 1: treating the correlation coefficient as causal strength.**

```python
corr.loc['total_bill', 'tip']   # around 0.68, looks strong
```

0.68 only describes the **degree of linear同步** between "bill goes up" and "tip goes up"; it does not mean "the bill causes the tip". A correlation matrix is a **list of leads**, not a causal conclusion. Its real value is deciding **which pair to dig into next**.

## heatmap: turn the matrix into colour blocks

Reading the raw numeric matrix is exhausting once you pass a dozen variables. A heatmap maps values to colour intensity.

```python
fig, ax = plt.subplots(figsize=(7, 6))
sns.heatmap(corr, annot=True, fmt='.2f', cmap='coolwarm',
            vmin=-1, vmax=1, square=True, ax=ax)
ax.set_title('tips data correlation matrix')
fig.savefig('heatmap1.png')
```

Key parameters:

| Parameter | Role |
|---|---|
| `annot=True` | Print the value inside each cell; turn this on, otherwise the exact correlation is unreadable |
| `fmt='.2f'` | Value format, two decimal places |
| `cmap='coolwarm'` | Diverging palette: red = positive, blue = negative, white = zero |
| `vmin=-1, vmax=1` | Fix both ends so 0 lands in the centre |
| `square=True` | Each cell is a square, keeping the matrix aligned |
| `center=0` | Forces the colormap centre colour onto 0 |

**Crash site 2: using a sequential colormap (such as `viridis`) for a correlation matrix.**

A sequential palette (yellow to purple) has no "middle value = unrelated" semantics, so it visually suggests "everything is positively correlated". **A correlation matrix needs a diverging palette** (coolwarm, RdBu_r, seismic), with `vmin=-1, vmax=1` fixed so 0 sits in the middle.

## mask: drop the duplicated upper triangle

A correlation matrix is **symmetric**, so the lower-left and upper-right are identical, and the diagonal is always 1. Half the information in the picture is redundant. Use a mask to hide the upper triangle:

```python
mask = np.triu(np.ones_like(corr, dtype=bool))   # upper triangle is True

fig, ax = plt.subplots(figsize=(7, 6))
sns.heatmap(corr, annot=True, fmt='.2f', cmap='coolwarm',
            vmin=-1, vmax=1, square=True, mask=mask, ax=ax)
ax.set_title('Correlation matrix with upper triangle masked')
fig.savefig('heatmap2.png')
```

`np.triu` takes the upper triangle, and `np.ones_like(..., dtype=bool)` builds a boolean matrix of the same shape. Where the mask is `True`, heatmap **skips drawing**, leaving a blank. The information content is instantly halved and readability doubles.

## p-values: do not只看 the coefficient size

A large correlation is not necessarily "significant"; with a small sample you can accidentally produce a high correlation. **To assess significance, compute the p-value.**

```python
from scipy import stats

def corr_pvalues(df):
    cols = df.select_dtypes('number').columns
    n = len(cols)
    pmat = pd.DataFrame(np.zeros((n, n)), index=cols, columns=cols)
    for i in cols:
        for j in cols:
            if i != j:
                r, p = stats.pearsonr(df[i].dropna(), df[j].dropna())
                pmat.loc[i, j] = p
    return pmat

pmat = corr_pvalues(tips)
print(pmat.round(3))
```

`stats.pearsonr` returns both the correlation coefficient and the p-value. A p-value below 0.05 means the correlation is **unlikely to be random noise**. **The coefficient says how strong the relationship is; the p-value says whether that strength is可信.** Report both.

**Crash site 3: chasing |r| > 0.7 while ignoring the sample size.**

The correlation between `size` and `total_bill` may be only 0.6, but with n=244 and a tiny p-value the conclusion is solid. A subgroup with only 8 records can yield 0.95, which looks impressive but is not reliable. **Reports must state n and the p-value**; publishing only the coefficient is unprofessional.

## Grouped correlation: recompute after controlling for a variable

```python
# bill vs tip, lunch only
lunch = tips[tips['time'] == 'Lunch']
print(lunch[['total_bill', 'tip']].corr().loc['total_bill', 'tip'])

# dinner only
dinner = tips[tips['time'] == 'Dinner']
print(dinner[['total_bill', 'tip']].corr().loc['total_bill', 'tip'])
```

The same pair can have **different values under different groupings**, and that difference is itself a finding: it points to a **moderating variable**. A correlation matrix is not a one-off deliverable; you must recompute it after controlling for different conditions.

## Recap

- `df.corr()` gives the Pearson correlation matrix: symmetric with 1s on the diagonal
- A heatmap must use `annot=True`, a diverging colormap, and fixed vmin/vmax
- `mask=np.triu(...)` removes the duplicated upper triangle and doubles readability
- The coefficient says "how strong"; the p-value says "how可信"; report both
- Correlation is not causation; it is a **list of leads**
- Recompute correlations after controlling for variables; you may uncover a moderating effect
