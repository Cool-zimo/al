# Visual Presentation: Turning Conclusions Into a Set of Charts

> The previous lesson produced the conclusions; this one draws them. The core principle is just one line: **one idea per chart** - each chart answers exactly one question, and the charts must follow a logical order.

## Layout: a set of charts, not a pile of charts

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import pandas as pd
import numpy as np

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

df = pd.DataFrame({
    'store': ['London']*4 + ['New York']*4 + ['Manchester']*4 + ['Bristol']*4,
    'month': ['Jan','Feb','Mar','Apr']*4,
    'channel': ['offline','online']*8,
    'revenue': [3200,4100,3300,4300,2800,3900,2900,4000,
               2100,2600,2200,2700,2400,3100,2500,3200],
    'orders': [120,180,125,190,100,160,105,165,
               80,120,85,125,90,140,95,145],
})

# Compute the conclusion data
g = df.groupby('store').agg(revenue_total=('revenue','sum'),
                          orders_total=('orders','sum')).sort_values('revenue_total')
g['avg_spend'] = (g['revenue_total']/g['orders_total']).round(1)

# Chart 1: revenue total per store (conclusion: who is biggest)
fig, axes = plt.subplots(1, 2, figsize=(13, 5))

axes[0].bar(g.index, g['revenue_total'], color='#4C72B0')
axes[0].set_title('London leads on revenue, Manchester trails clearly')
axes[0].set_ylabel('Revenue (GBP)')
for i, v in enumerate(g['revenue_total']):
    axes[0].text(i, v+200, str(v), ha='center', fontsize=9)

# Chart 2: average spend per store (conclusion: who is most efficient)
axes[1].bar(g.index, g['avg_spend'], color='#DD8452')
axes[1].set_title('Average spend is similar across stores, no efficiency gap')
axes[1].set_ylabel('Average spend (GBP)')
for i, v in enumerate(g['avg_spend']):
    axes[1].text(i, v+0.5, str(v), ha='center', fontsize=9)

plt.tight_layout()
plt.savefig('store_overview.png', dpi=120)
print('saved store_overview.png')
```

`subplots(1, 2)` builds a grid of one row and two columns, returning `fig` (the whole canvas) and `axes` (the array of subplots). **Each subplot answers exactly one question**: the left answers "who is biggest", the right answers "who is most efficient". Placed side by side, the relationship between scale and efficiency appears at once - London leads on scale but not on spend, so its advantage comes from footfall rather than customer value.

**Wreck of the day 1: too much in one chart dilutes the conclusion.**

```python
# WRONG: four metrics in one chart, messy colours, impossible to read
fig, ax = plt.subplots()
ax.bar(g.index, g['revenue_total'], color='blue', label='revenue')
ax.bar(g.index, g['orders_total'], color='red', label='orders')  # different scales, bars break
ax.bar(g.index, g['avg_spend'], color='green', label='avg spend')
ax.legend()
plt.savefig('mess.png')
# orders are in the hundreds while avg spend is in the tens, so the bars differ by an order of magnitude and the chart is essentially useless
```

Metrics on different scales must never share one chart. Split into several subplots or use a second Y axis (but dual axes are hard to read, so split whenever you can). The rule is simple: **if it takes three paragraphs of explanation for someone to understand one chart, it should be split.**

## One idea per chart: the title is the name of the conclusion

```python
# Chart 3: channel structure (conclusion: online is already dominant)
chan = df.groupby('channel')['revenue'].sum()
fig, ax = plt.subplots(figsize=(6, 5))
colors = ['#55A868', '#C44E52']
ax.pie(chan.values, labels=chan.index, autopct='%1.1f%%',
       colors=colors, startangle=90)
ax.set_title('Online contributes 56.9%, now the main channel')
plt.tight_layout()
plt.savefig('channel_pie.png', dpi=120)
print('channel split:\n', chan)
```

The title is not "Revenue share by channel"; it is "**Online contributes 56.9%, now the main channel**". Put the conclusion in the title and the reader gets the information in one second, with no calculation and no guessing what you meant. That is the difference between a report chart and an analysis chart.

## Logical order: general before specific, scale before efficiency

```python
# Four charts in logical order: overview -> structure -> trend -> cross
fig, axes = plt.subplots(2, 2, figsize=(13, 10))

# 1 overview: scale per store
axes[0, 0].bar(g.index, g['revenue_total'], color='#4C72B0')
axes[0, 0].set_title('1. London leads Manchester by 34%')

# 2 structure: channel share
chan_pct = (chan/chan.sum()*100).round(1)
axes[0, 1].pie(chan_pct.values, labels=chan_pct.index, autopct='%1.1f%%')
axes[0, 1].set_title('2. Online contributes nearly 60% of revenue')

# 3 trend: monthly movement
monthly = df.groupby('month')['revenue'].sum()
axes[1, 0].plot(monthly.index, monthly.values, marker='o', color='#8172B3')
axes[1, 0].set_title('3. Revenue rises steadily month by month')

# 4 cross: store x channel
pivot = df.pivot_table(index='store', columns='channel', values='revenue', aggfunc='sum')
pivot.plot(kind='bar', ax=axes[1, 1], color=['#55A868','#C44E52'])
axes[1, 1].set_title('4. Online beats offline in every store')

plt.tight_layout()
plt.savefig('report_grid.png', dpi=120)
print('saved report_grid.png')
```

The logic chain of the four charts is: **see how big the whole pie is (1) -> then see how it is cut (2) -> then see how it moves over time (3) -> finally see whether any cross dimension shows a pattern (4)**. That is the sequence "general before specific, scale before efficiency, static before dynamic". Break that order and the reader gets lost; follow it and the story line is readable even without the text.

**Wreck of the day 2: the charts are drawn but not saved, or the size explodes.**

```python
# WRONG: no tight_layout and no savefig, labels get crushed
fig, ax = plt.subplots(figsize=(4, 3))
ax.bar(['London','New York','Manchester','Bristol'],[14900,13600,9600,11200])
ax.set_title('Store revenue comparison'*3)  # title far too long
# plt.tight_layout()  # forgotten
# plt.savefig('bad.png')  # forgotten
plt.close()
```

Long labels, long titles and many subplots will all cause labels to overlap and run off the edge without `tight_layout()`. And **always call `plt.close()` after `plt.savefig()`**, or the memory is eaten up by repeated drawing in a loop. The standard four-piece routine for a report chart: set `figsize` -> draw -> `tight_layout()` -> `savefig()` + `close()`.

## Summary

- Use `subplots` for multi-panel layouts; one canvas carries a set of charts
- One idea per chart; put the conclusion in the title instead of making the reader guess
- Never put metrics on different scales in one chart; split or use a dual axis
- Presentation order: general before specific, scale before efficiency, static before dynamic
- Chinese labels require `tight_layout()` or they will overlap
- Always `savefig` + `close` after drawing, especially in a loop
