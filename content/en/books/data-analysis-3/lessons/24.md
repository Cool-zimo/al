# Chart Readability: Information Density, Whitespace, Typography Hierarchy, One Idea Per Chart

> A chart that runs is not the same as a chart that can be read. Readability is the engineering of "letting someone grasp the conclusion within 3 seconds", and it has four controls: information density, whitespace, type hierarchy and number of conclusions.

## One conclusion per chart

One chart carries one idea. This is the first rule of readability, and the one most often broken.

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import seaborn as sns
import pandas as pd

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

sales = pd.DataFrame({
    'store': ['London', 'New York', 'Manchester', 'Bristol'],
    'revenue': [320, 310, 300, 295],
    'avg_spend': [185, 172, 158, 168],
    'per_sqm': [4.0, 4.4, 3.2, 3.4],
})

# One conclusion: only "revenue comparison"
fig, ax = plt.subplots(figsize=(7, 5))
ax.bar(sales['store'], sales['revenue'], color='#4C72B0')
ax.set_title('London has the highest revenue')
ax.set_ylabel('Revenue (10k GBP)')
for b in ax.patches:
    ax.text(b.get_x()+b.get_width()/2, b.get_height()+5,
            f'{int(b.get_height())}', ha='center')
fig.tight_layout()
fig.savefig('one_point.png')
```

The title states the conclusion directly: "London has the highest revenue", rather than the vague "Sales data". **The reader should not have to infer it - you have stated it for them.**

**Wreck of the day 1: three conclusions crammed into one chart.**

```python
fig, ax = plt.subplots(figsize=(7, 5))
x = range(len(sales))
ax.bar([i-0.2 for i in x], sales['revenue'], width=0.2, label='revenue')
ax.bar(x, sales['avg_spend'], width=0.2, label='avg spend')
ax.bar([i+0.2 for i in x], sales['per_sqm'], width=0.2, label='per sqm')
ax.set_title('Overall sales comparison')      # three metrics, different units, no focus
ax.legend()
fig.savefig('three_in_one.png')
```

The three metrics use completely different units (10k GBP, GBP, GBP/sqm), so plotting them on one axis hides the point. **When the units differ, split them up.** Three small faceted charts are far better than one confusing chart.

## Information density: remove every mark that does not carry meaning

The data-ink ratio is the ink used to express data divided by the total ink. The higher it is, the clearer the chart.

```python
# Improved version: drop top and right spines, lighten the grid
fig, ax = plt.subplots(figsize=(7, 5))
ax.bar(sales['store'], sales['revenue'], color='#4C72B0')
ax.set_title('London has the highest revenue', fontsize=13, pad=14)
ax.set_ylabel('Revenue (10k GBP)')
ax.spines['top'].set_visible(False)
ax.spines['right'].set_visible(False)
ax.grid(axis='y', alpha=0.3)
ax.set_axisbelow(True)            # push gridlines behind the bars
fig.tight_layout()
fig.savefig('clean.png')
```

Every line you remove **reduces cognitive load**. Use `alpha=0.3` to soften the gridlines and `set_axisbelow(True)` to push them behind the bars, so they stay as reference without stealing the show.

## Whitespace: not empty space, but rhythm

```python
fig, ax = plt.subplots(figsize=(7, 5))
ax.bar(sales['store'], sales['revenue'])
ax.set_title('London has the highest revenue', fontsize=13, pad=18)   # pad adds space under the title
ax.set_xlabel('Store', labelpad=10)                                   # space below the axis label
ax.set_ylabel('Revenue (10k GBP)', labelpad=10)
ax.margins(y=0.15)                                                    # top margin, bars do not touch the edge
fig.tight_layout()
fig.savefig('whitespace.png')
```

`pad` controls the distance between text and axis, and `margins(y=0.15)` leaves room above the bars. The numbers on top of the bars and the title should never touch the edges. **Whitespace is not waste; it lets the important parts be seen.**

## Typography hierarchy: three levels, each with its own job

The text on a chart has three layers, and the font sizes should make the hierarchy obvious:

| Level | Content | Suggested size |
|---|---|---|
| 1 | Chart title (the conclusion) | 13-15, bold |
| 2 | Axis labels (the units) | 11 |
| 3 | Tick labels and legend | 10 |

```python
fig, ax = plt.subplots(figsize=(7, 5))
ax.bar(sales['store'], sales['revenue'])
ax.set_title('London has the highest revenue', fontsize=14, fontweight='bold', pad=18)
ax.set_xlabel('Store', fontsize=11)
ax.set_ylabel('Revenue (10k GBP)', fontsize=11)
ax.tick_params(labelsize=10)
fig.tight_layout()
fig.savefig('hierarchy.png')
```

**Wreck of the day 2: one size for everything.**

If the title, axis labels and ticks all use size 10, the reader has no idea where to look first. **Font size is the reading order**; a confused hierarchy means there is no focus.

## Readability checklist

When the chart is done, run through this list:

- [ ] Is the title a one-line conclusion, rather than "Data analysis"?
- [ ] Does the axis label include the unit (10k GBP? visitors? %?)?
- [ ] Is there a legend, and is it actually needed (single-series charts rarely need one)?
- [ ] Are the top and right spines removed?
- [ ] Is the grid lightened and not covering the data?
- [ ] Are the values on top of the bars or points labelled?
- [ ] Have you squeezed in a second unit or a second conclusion?
- [ ] Can someone say what this chart is about within 3 seconds?

**Wreck of the day 3: the legend as pointless decoration.**

```python
ax.bar(sales['store'], sales['revenue'], label='revenue')
ax.legend()   # only one series, so the legend just repeats "revenue"
```

A legend for a single series is **completely redundant**: it takes space and adds noise. A legend only belongs with hue groupings or multiple series. The test: does the legend add new encoding information? If not, delete it.

## Summary

- One conclusion per chart: put the conclusion in the title, and facet when units differ
- Information density: remove marks that do not carry meaning, lighten the grid and push it behind the data
- Whitespace: `pad` controls text spacing, `margins` stops things touching the edges
- Three type levels: title 14 bold / axis labels 11 / ticks 10
- Keep the legend only when it adds new encoding information; remove it for single-series charts
- Walk the eight-item checklist after drawing, and use the 3-second test to decide whether it passes
