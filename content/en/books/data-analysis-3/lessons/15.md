# Plotting directly from pandas: the df.plot() family

> A DataFrame has its own `.plot()` method, so a usable figure is only a few lines away. This lesson covers where it is enough, where it falls short, and how to mix it with matplotlib.

## df.plot() is a shortcut built on matplotlib

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import pandas as pd

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

df = pd.DataFrame({
    'month': ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun'],
    'London': [120, 135, 128, 160, 175, 190],
    'New York': [110, 118, 130, 140, 155, 168],
    'Manchester': [90, 100, 95, 110, 130, 140]
})
df = df.set_index('month')

fig, ax = plt.subplots(figsize=(9, 5))
df.plot(ax=ax, marker='o')                    # <- pass the ax in
ax.set_title('Sales across three stores')
ax.set_ylabel('Sales (£10k)')
fig.savefig('df_plot.png')
print('saved')
```

`df.plot(ax=ax)` returns a matplotlib Axes object, so **every `ax.set_title` and friends still works**. That handoff is exactly what makes mixing possible.

## The kind parameter

| kind | Plot | Equivalent |
|---|---|---|
| `'line'` (default) | Line | `df.plot.line()` |
| `'bar'` | Vertical bars | `df.plot.bar()` |
| `'barh'` | Horizontal bars | `df.plot.barh()` |
| `'hist'` | Histogram | `df.plot.hist()` |
| `'box'` | Boxplot | `df.plot.box()` |
| `'scatter'` | Scatter | `df.plot.scatter()` |
| `'area'` | Area | `df.plot.area()` |
| `'pie'` | Pie | `df.plot.pie()` |

**Example: a bar chart**

```python
df.plot(kind='bar', figsize=(9, 5), color=['#e41a1c', '#377eb8', '#4daf4a'])
```

`df.plot` **automatically uses the column names as the legend**, which is its biggest convenience.

## Crash site 1: forgetting ax=, so the plot ends up somewhere else

```python
fig, ax = plt.subplots(figsize=(9, 5))
df.plot()                     # forgot ax=ax! creates a brand new figure
ax.set_title('Title')         # the title lands on a different, empty figure
```

Output: you get **two figures**, one holding the data without a title, and one holding the title with no data. Because `df.plot()` creates its own figure when no `ax` is given.

**Fix: always write `ax=ax`.**

## Crash site 2: the x-axis is numbers instead of categories

```python
df2 = pd.DataFrame({
    'London': [120, 135, 128],
    'New York': [110, 118, 130]
})                          # no explicit index
df2.plot()
```

Output: the x-axis reads `0, 1, 2` instead of the store names you wanted. **To use a column as the x-axis, set it as the index first.**

## Horizontal bars and stacking

```python
# Horizontal bars
df.plot(kind='barh', figsize=(9, 5))

# Stacked bars
df.plot(kind='bar', stacked=True, figsize=(9, 5))

# Area chart
df.plot(kind='area', alpha=0.5, figsize=(9, 5))
```

`stacked=True` stacks multiple columns, which is the right choice when you want to show a total plus its composition.

## Scatter: the column name goes straight into c

```python
df3 = pd.DataFrame({
    'floor_area': [50, 80, 120, 150, 200],
    'sales': [300, 500, 700, 900, 1200],
    'rent': [10, 15, 25, 30, 45]
})

fig, ax = plt.subplots(figsize=(8, 5))
df3.plot.scatter(x='floor_area', y='sales', c='rent', cmap='viridis',
                s=80, ax=ax)
fig.colorbar(ax.collections[0], ax=ax, label='Rent (£10k)')
fig.savefig('df_scatter.png')
```

With a scatter plot, `c` can take a **column name directly** (`c='rent'`), which is far more convenient than extracting a NumPy array yourself.

## Where df.plot is not enough

`df.plot` is built for **quick exploration**, but it cannot do the following:

| Scenario | Why it falls short |
|---|---|
| A second y-axis (twinx) | No twinx parameter |
| Merging legends across panels | A legend spanning several axes must be assembled by hand |
| Irregular panel layouts | GridSpec requires working directly with the figure |
| Precise annotation placement | annotate needs coordinate calculations |
| One colourbar shared across several panels | df.plot does not return a colourbar |

**Rule of thumb: use df.plot while exploring, switch to matplotlib for the final version.**

## The best mixing pattern

```python
fig, axes = plt.subplots(2, 1, figsize=(9, 8))

# Top: line chart
df.plot(ax=axes[0], marker='o')
axes[0].set_title('Sales trend')

# Bottom: bar chart
df.plot(kind='bar', ax=axes[1], color=['#e41a1c', '#377eb8', '#4daf4a'])
axes[1].set_title('Month-by-month comparison')

fig.tight_layout()
fig.savefig('mixed.png')
```

**The standard workflow**: build the `ax` with `plt.subplots` first, draw the data with `df.plot(ax=ax)`, then use the Axes methods for titles, legends, and annotations. **You keep pandas' convenience without giving up matplotlib's full control.**

## Crash site 3: the Axes type does not change, but reassignment loses the layout

```python
ax = df.plot()               # ax is a matplotlib.axes.Axes
fig, axes = plt.subplots(2, 1)
axes[0] = df.plot()          # overwrites axes[0] and loses the shared-axis setup
```

Output: the panel layout breaks and the shared-axis configuration stops working. **Pass `ax` explicitly instead:**

```python
df.plot(ax=axes[0])          # draws into the specified axes, creates nothing new
```

## Recap

- `df.plot(ax=ax)` is the bridge between pandas and matplotlib
- `kind` selects the plot type: `line` / `bar` / `barh` / `box` / `scatter` / `area` / `pie`
- Column names become the legend automatically; to fix the x-axis, `set_index` first
- **Always pass `ax=`**, otherwise a new figure is created
- For scatter, `c='column name'` maps a column directly to colour
- Explore with df.plot, produce the final figure with matplotlib plus an explicit ax
