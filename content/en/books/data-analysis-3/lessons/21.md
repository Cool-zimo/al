# From Question to Chart: Pick the Chart After You Know the Question

> Most bad charts are not caused by bad code. They are caused by **drawing before you know what you are trying to answer**. This lesson gives you a decision table for "question → chart" and a full workflow from picking a topic to exporting the picture.

## Ask three questions first

Before you open an editor, answer these:

1. **What am I trying to answer?** ("Do the stores differ much in revenue?" versus "How does revenue change over time?")
2. **What types are the variables?** (category vs number vs time)
3. **What should the reader see?** (comparison / trend / distribution / relationship)

If these three are not settled, do not open the editor.

## Decision table: the question decides the chart

| The question you want answered | Variable types | Reach for |
|---|---|---|
| Which category is highest or lowest | category vs number | bar / box |
| How does it change over time | time vs number | line |
| What does the distribution look like | one number | hist / kde / box |
| How do two variables move together | number vs number | scatter |
| Which pairs are related | several numbers | heatmap (correlation matrix) |
| What share is each part | category vs proportion | stacked bar (pie only with caution) |

**Wreck of the day 1: using a boxplot to answer "which is higher".**

```python
# Goal: which city has the highest revenue
sns.boxplot(data=sales, x='city', y='revenue')   # WRONG: far too much information
```

All you wanted was "which is higher", but a boxplot hands over quartiles and outliers as well. Too much information means no focus. **Use a bar for a single comparison, use a box only when the shape of the distribution matters.** Lock the question first, then decide how much detail the chart should carry.

## Four basic needs

### Comparison: differences between categories

```python
import matplotlib
matplotlib.use('Agg')
import matplotlib.pyplot as plt
import seaborn as sns
import pandas as pd

plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei']
plt.rcParams['axes.unicode_minus'] = False

sales = pd.DataFrame({
    'city': ['London', 'New York', 'Manchester', 'Bristol'],
    'Q1': [320, 280, 210, 245],
    'Q2': [335, 310, 230, 268],
})

fig, ax = plt.subplots(figsize=(8, 5))
sns.barplot(data=sales, x='city', y='Q1', ax=ax)
ax.set_title('Revenue by city in Q1')
fig.savefig('compare.png')
```

The core rule for comparison is **aligned baselines**: bars start at 0, and line charts share the same y axis. Anything that breaks that alignment distorts the comparison.

### Trend: how things change over time

```python
months = pd.DataFrame({
    'month': ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun'],
    'revenue': [120, 135, 128, 160, 175, 190],
})
fig, ax = plt.subplots(figsize=(8, 5))
sns.lineplot(data=months, x='month', y='revenue', marker='o', ax=ax)
ax.set_title('Revenue trend in the first half of the year')
fig.savefig('trend.png')
```

A trend **must use a line or an area, not bars**. In a comparison the category order is arbitrary, but in a time series the order carries meaning. Bars throw that continuity away.

### Distribution: the shape of the data

```python
fig, ax = plt.subplots(figsize=(8, 5))
sns.histplot(data=sales, x='Q1', kde=True, ax=ax)
ax.set_title('Distribution of Q1 revenue')
fig.savefig('dist.png')
```

Use hist, kde, box or violin for distributions. A bar chart implies discrete categories, while a distribution is continuous.

### Relationship: how two variables move together

```python
tips = sns.load_dataset('tips')
fig, ax = plt.subplots(figsize=(8, 5))
sns.scatterplot(data=tips, x='total_bill', y='tip', ax=ax)
ax.set_title('Total bill vs tip')
fig.savefig('rel.png')
```

## Full workflow: from question to exported chart

```text
1. Write the question: "What do I want to know?"
2. Circle the variables: what is x (the input) and what is y (the output)?
3. Set the types: is x category / time / number, and what is y?
4. Check the table and pick candidate charts
5. Sketch it first, even roughly on paper
6. Write the code and draw it
7. Self check: title, axis labels, units, legend, source all present?
8. Ask: "Can a reader get it within 3 seconds?"
```

**Wreck of the day 2: skipping step 1 and drawing something beautiful that answers the wrong question.**

This is the most common and the most expensive mistake. You have sales data, so you draw a line chart of monthly revenue because it is easy. But your manager asked which stores are underperforming. **No matter how pretty, the wrong answer is worth nothing.** After the code runs, look back at step 1. Does this chart answer it?

## A complete example: revenue per square metre

Question: **"Which city has the highest revenue per square metre?"**

```python
# 1. Question: which city has the highest revenue per square metre
# 2. Variables: city (category, x), revenue per sqm (number, y)
# 3. Types: category vs number -> comparison
# 4. Decision table: use a bar
store = pd.DataFrame({
    'city': ['London', 'New York', 'Manchester', 'Bristol'],
    'revenue_w': [320, 280, 210, 245],
    'area_sqm': [80, 70, 65, 72],
})
store['per_sqm'] = store['revenue_w'] * 10000 / store['area_sqm']

fig, ax = plt.subplots(figsize=(8, 5))
sns.barplot(data=store, x='city', y='per_sqm', ax=ax)
ax.set_title('Revenue per square metre by city (GBP/sqm)')
ax.set_ylabel('Revenue per square metre (GBP/sqm)')
fig.savefig('pingxiao.png')
print(store[['city', 'per_sqm']].round(0))
```

Comparing raw revenue puts London first, but the per-square-metre ranking can be completely different. **A derived metric often answers the business question better than the raw one.**

## Summary

- Before drawing, answer three questions: what to answer, what the variables are, what the reader should see
- Decision table: comparison → bar/box, trend → line, distribution → hist/kde, relationship → scatter, many variables → heatmap
- Align baselines for comparisons, keep continuity for trends, and never use bars for distributions
- The eight steps: question → variables → types → table → sketch → code → self check → 3 second test
- Skip the question and even a perfect chart scores zero
- Derived metrics (revenue per sqm, per capita, conversion rate) often answer business questions better than raw figures
