# Dark Mode and Theme Switching

> A "switch theme" button is really just dynamically replacing a QSS string. This lesson covers how to organize two themes and the easiest traps to fall into when switching.

## A Theme Is Two QSS Strings

**The simplest approach: write light and dark QSS as strings, then re-apply them with `setStyleSheet` on switch.**

```
light_qss = """
    QWidget {
        background-color: #ffffff;
        color: #2c3e50;
    }
    QPushButton {
        background-color: #3498db;
        color: white;
        border: none;
        border-radius: 6px;
        padding: 8px 16px;
    }
    QLineEdit {
        background-color: white;
        border: 1px solid #bdc3c7;
        border-radius: 4px;
        padding: 6px;
    }
"""

dark_qss = """
    QWidget {
        background-color: #2c3e50;
        color: #ecf0f1;
    }
    QPushButton {
        background-color: #1abc9c;
        color: #2c3e50;
        border: none;
        border-radius: 6px;
        padding: 8px 16px;
    }
    QLineEdit {
        background-color: #34495e;
        color: #ecf0f1;
        border: 1px solid #7f8c8d;
        border-radius: 4px;
        padding: 6px;
    }
"""
```

**The toggle function:**

```
def apply_theme(theme):
    if theme == "dark":
        app.setStyleSheet(dark_qss)
    else:
        app.setStyleSheet(light_qss)
```

**The key point: "set it all again" — QSS is a wholesale replacement, not an incremental addition.** Setting a new one overwrites the old.

## A Complete Dynamic-Switching Example

**A button triggers the switch, and `QSettings` remembers the user's choice:**

```
from PySide6.QtCore import QSettings

settings = QSettings("MyCompany", "MyApp")

def toggle_theme():
    current = settings.value("theme", "light")
    new_theme = "dark" if current == "light" else "light"
    apply_theme(new_theme)
    settings.setValue("theme", new_theme)
    settings.sync()

btn = QPushButton("Switch theme")
btn.clicked.connect(toggle_theme)

# apply the saved theme on startup
apply_theme(settings.value("theme", "light"))
```

**`QSettings` stores preferences in the system configuration and restores them on next launch.** On Windows it lives in the registry, on macOS in a plist, and on Linux in an ini file — your code does not care.

**Update the button text to match:**

```
def apply_theme(theme):
    if theme == "dark":
        app.setStyleSheet(dark_qss)
        btn.setText("Switch to light mode")
    else:
        app.setStyleSheet(light_qss)
        btn.setText("Switch to dark mode")
```

## Crash Site #1: Setting the Style on the Main Window Only — Children Stay Old

**Symptom: you click switch, the main window background changes, but `QLineEdit` and `QPushButton` do not react at all.**

```
def apply_theme(theme):
    window.setStyleSheet(dark_qss)    # only set on window
```

**Why: a QSS scope depends on what you set it on.** Setting it on `window` propagates part of the styling, but many controls (especially `QPushButton`) have their own background-drawing logic and do not always inherit from the parent.

**✅ Correct: set the style on `app` for a global effect.**

```
def apply_theme(theme):
    app.setStyleSheet(dark_qss)    # global
```

**Only reach for setting it per-window when you genuinely want different windows to use different themes.** For a single-theme app, setting it on `app` is by far the easiest.

## Crash Site #2: Hard-Coded Colors in QSS — After Switching, QLabel Text Is Invisible

**Symptom: the light theme looks fine, but after switching to dark the QLabel text disappears — it is actually white text on a white background.**

```
light_qss = """
    QWidget { background-color: #ffffff; }
    QLabel { color: #333333; }
"""
dark_qss = """
    QWidget { background-color: #2c3e50; }
    QLabel { color: #ffffff; }
"""
# but somewhere a specific QLabel got a hard-coded style:
label.setStyleSheet("background-color: white; color: white;")
# after switching to dark, that label is white-on-white — nothing is visible
```

**Why: a local `setStyleSheet` always outranks the global one.** A global switch cannot override it because it is "closer" to the control.

**✅ Correct: never hard-code background and foreground colors on a single control; let it inherit the global theme.**

```
label.setStyleSheet("")    # clear the local style and let the global QSS take over
```

**If a control really must have a special style, use a QSS class or ID selector and define it in both themes:**

```
light_qss = """
    QLabel#status { color: #27ae60; }
"""
dark_qss = """
    QLabel#status { color: #2ecc71; }
"""
```

**Rule: only colors managed globally can follow a theme switch; locally hard-coded colors break away from it.**

## Loading QSS from Files

**Putting QSS into `.qss` files and reading them with Python is much cleaner than hard-coded strings.**

```
def load_qss(path):
    with open(path, "r", encoding="utf-8") as f:
        return f.read()

light_qss = load_qss("themes/light.qss")
dark_qss = load_qss("themes/dark.qss")
```

**Directory layout:**

```
project/
├── main.py
├── themes/
│   ├── light.qss
│   └── dark.qss
└── icons/
```

**Have a fallback for a failed read:**

```
def load_qss(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        print(f"Theme file {path} not found; using default style")
        return ""
```

**You can even bundle theme files with `qrc`:**

```
<RCC>
    <qresource prefix="/themes">
        <file>themes/light.qss</file>
        <file>themes/dark.qss</file>
    </qresource>
</RCC>
```

**Reading QSS from resources:**

```
from PySide6.QtCore import QFile, QTextStream

def load_qss_from_rc(path):
    file = QFile(path)
    if file.open(QFile.ReadOnly | QFile.Text):
        stream = QTextStream(file)
        return stream.readAll()
    return ""
```

## Following the System Theme

**Listen for system dark/light changes to follow automatically:**

```
from PySide6.QtGui import QPalette

# detect the current system theme
def is_dark_mode():
    palette = app.palette()
    bg = palette.color(QPalette.Window)
    return bg.lightness() < 128    # window background darker than 128 = dark

# follow the system on launch
apply_theme("dark" if is_dark_mode() else "light")
```

**A finer-grained approach requires listening for system signals — on Windows that means handling the `WM_SETTINGCHANGE` message — which is usually only worth it in a polished app.** A manual toggle button plus a remembered preference is enough for most applications.

## Summary

- Theme switching is fundamentally dynamic QSS replacement — two strings (or two files)
- Use `app.setStyleSheet` for a global effect; do not set it on `window` only
- `QSettings` remembers the user's preference and restores it on next launch
- ⚠️ Classic traps: locally hard-coded colors break away from the theme (white text on white); setting the style on `window` only leaves child controls unchanged
- Theme files in `.qss` are cleaner and can be bundled with `qrc`
- Color scheme: light uses `#ffffff` background + dark text; dark uses `#2c3e50` background + `#ecf0f1` text
- `is_dark_mode` uses `QPalette` to detect the system theme
