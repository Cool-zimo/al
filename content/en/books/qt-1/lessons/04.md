# Ways to Write connect

> Lesson 3 covered the concept of signals and slots. This lesson lays out the common ways to write `connect`: connecting built-in signals, connecting custom signals, passing arguments with lambda, and declaring signals with decorators. Once you master custom signals, you've truly grasped Qt's decoupling power.

## Method 1: Connecting a Built-in Signal (Most Common)

**This is the写法 you've already seen — a quick review:**

```
from PySide6.QtWidgets import QPushButton

def on_click():
    print("Clicked")

btn = QPushButton("Click me")
btn.clicked.connect(on_click)
```

**Important: `connect` takes a function object `on_click` — do not add parentheses `on_click()`.** Adding parentheses calls it immediately, connects `None`, and nothing happens on click.

**A complete runnable example:**

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QVBoxLayout

def on_click():
    print("Button clicked")

app = QApplication(sys.argv)
window = QWidget()
btn = QPushButton("Click me")
btn.clicked.connect(on_click)

layout = QVBoxLayout(window)
layout.addWidget(btn)
window.show()
app.exec()
```

## Crash Site 1: Adding parentheses after connect

**Symptom:** clicking the button does nothing, and the console doesn't error. Worse, something prints at startup.

```
def on_click():
    print("Clicked")

btn.clicked.connect(on_click())   # WRONG: parentheses added
```

**Why:** `on_click()` is called immediately on the `connect` line, returning `None`. `btn.clicked.connect(None)` is equivalent to connecting nothing. And `on_click`'s `print("Clicked")` fires once at startup, so you see a mysterious print before anything happens.

**Fix:** **`connect` receives a function object — drop the parentheses.** To pass arguments, use lambda or partial (below).

## Method 2: Passing Arguments with lambda

**When a slot needs extra arguments, lambda is the most convenient写法.**

```
from PySide6.QtWidgets import QPushButton

def greet(name):
    print(f"Hello, {name}")

btn = QPushButton("Say hi")
btn.clicked.connect(lambda: greet("Alice"))
```

**Lambda acts as an "adapter":** the `clicked` signal carries no argument, but `greet` needs a `name`. The lambda swallows the signal's argument (if any) and calls `greet("Alice")`.

**Lambda receiving a signal argument:**

```
btn.clicked.connect(lambda checked: print("Pressed:", checked))
```

**`checked` is the bool passed by the `clicked(bool)` overload**, indicating whether the button is pressed. Note: QPushButton only has this bool value after `setCheckable(True)`; a normal button's `clicked` carries nothing.

**A more practical example: creating multiple buttons in a loop:**

```
from PySide6.QtWidgets import QPushButton, QWidget, QVBoxLayout

window = QWidget()
layout = QVBoxLayout(window)

names = ["New", "Open", "Save"]

def do_action(name):
    print(f"Action: {name}")

for n in names:
    btn = QPushButton(n)
    btn.clicked.connect(lambda checked, name=n: do_action(name))
    layout.addWidget(btn)
```

**`name=n` captures the current loop value with a default argument** — each lambda gets its own copy. This is the closure trick from Lesson 3, used daily in Qt.

## Method 3: Using functools.partial

**Lambda's alternative — better for many arguments or complex logic.**

```
from functools import partial
from PySide6.QtWidgets import QPushButton

def do_action(name, times):
    for _ in range(times):
        print(name)

btn = QPushButton("Spam click")
btn.clicked.connect(partial(do_action, "Save", 3))
```

**`partial` binds `do_action` to its first two arguments**, returning a new function. When clicked, this new function runs, equivalent to `do_action("Save", 3)`.

**When to use partial vs lambda?** Few arguments and short logic → lambda. Many arguments or reusable binding logic → partial. Partial reads more clearly because the arguments are explicit at definition.

## Method 4: Custom Signals

**This is one of Qt's most powerful features: you can define your own signals.**

**Custom signals must be declared inside a `QObject` subclass using `Signal`:**

```
from PySide6.QtCore import QObject, Signal

class TaskWorker(QObject):
    finished = Signal()                    # signal with no arguments
    progress = Signal(int)                 # signal carrying one int
    result_ready = Signal(str, int)        # signal carrying two arguments

    def run(self):
        for i in range(1, 6):
            self.progress.emit(i)          # emit the signal
        self.result_ready.emit("Done", 100)
        self.finished.emit()
```

**Three essentials:**

1. **Declare:** `finished = Signal()`, in the class body, not `__init__`.
2. **Emit:** `self.progress.emit(i)`, via the `.emit()` method.
3. **Connect:** `worker.progress.connect(on_progress)` — same as a built-in signal.

**Running example:**

```
def on_progress(value):
    print(f"Progress: {value}/5")

worker = TaskWorker()
worker.progress.connect(on_progress)

worker.run()
```

**Output:**

```
Progress: 1/5
Progress: 2/5
Progress: 3/5
Progress: 4/5
Progress: 5/5
```

## Crash Site 2: Declaring Signal inside __init__

**Symptom:** runtime error saying the attribute isn't a signal.

```
from PySide6.QtCore import QObject, Signal

class BadWorker(QObject):
    def __init__(self):
        super().__init__()
        self.finished = Signal()   # WRONG!
```

**Error message:** `AttributeError: 'PySide6.QtCore.Signal' object has no attribute 'connect'` or `TypeError: Signal must be used as a class attribute`.

**Why:** `Signal` is a descriptor — it must be declared in the **class body** so Qt's meta-object system can process it at class creation. Putting it in `__init__` makes it a plain instance attribute, stripping it of signal behavior.

**Fix:** **move the Signal declaration to the top of the class body, alongside instance methods.**

```
class GoodWorker(QObject):
    finished = Signal()           # CORRECT: declared in class body

    def __init__(self):
        super().__init__()
```

## Crash Site 3: Signal emits arguments the slot doesn't accept

**Symptom:** clicking the button or emitting the signal crashes the program.

```
class Worker(QObject):
    data_ready = Signal(str, int)

worker = Worker()
worker.data_ready.connect(lambda s: print(s))   # WRONG: only one argument
worker.data_ready.emit("Score", 95)
```

**Error message:** `TypeError: <lambda>() takes 1 positional argument but 2 were given`.

**Why:** `data_ready` emits two values `("Score", 95)`, but the lambda defines only one parameter `s` — the second value has nowhere to go.

**Fix:** the slot's parameter count must match the number of values the signal emits. Either change to `lambda s, n: print(s, n)` or reduce the signal's arguments.

## Declaring Signals with a Decorator (Advanced)

**Besides `Signal()` class attributes, you can use `@Signal` (supported in Qt 6.6+):**

```
from PySide6.QtCore import QObject, Signal

class Worker(QObject):
    @Signal
    def finished(self): ...                 # no arguments

    @Signal
    def progress(self, value: int): ...     # with argument, via type hint
```

**This写法 is more Pythonic**, with argument types declared via annotations. But older Qt versions don't support it. For compatibility, this book uniformly uses the `Signal()` class attribute写法.

## Summary

- `connect` takes a function object — no parentheses
- Lambda for arguments: `btn.clicked.connect(lambda: func(arg))`
- In a loop, use `lambda checked, i=i: ...` to capture the current value
- functools.partial is lambda's alternative — clearer for many arguments
- Custom signals: `Signal()` declared in class body → `emit()` to fire → `connect` to wire up
- Signal must be declared in the class body, never inside `__init__`
- A slot's parameter count must match the number of values the signal emits
