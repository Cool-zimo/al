# QGridLayout: Row and Column Grid Layout

> Calculator interfaces, login forms, settings pages — "grid-like" interfaces are best built with QGridLayout. It arranges widgets by row and column, and lets a widget span multiple rows or columns. This lesson covers the parameter order and the most common crash site: wrong parameters causing widgets to pile up.

## Basic Usage: Row, Column, Widget

**`addWidget(widget, row, column)` places a widget at row `row`, column `column`.**

**Rows and columns are zero-indexed.**

```
import sys
from PySide6.QtWidgets import (
    QApplication, QWidget, QPushButton, QGridLayout
)

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Calculator")

layout = QGridLayout(window)

layout.addWidget(QPushButton("1"), 0, 0)
layout.addWidget(QPushButton("2"), 0, 1)
layout.addWidget(QPushButton("3"), 0, 2)
layout.addWidget(QPushButton("4"), 1, 0)
layout.addWidget(QPushButton("5"), 1, 1)
layout.addWidget(QPushButton("6"), 1, 2)

window.resize(300, 200)
window.show()
app.exec()
```

**Effect: a 2-row, 3-column number pad.**

**Table view:**

| Row\Col | 0 | 1 | 2 |
|---|---|---|---|
| 0 | 1 | 2 | 3 |
| 1 | 4 | 5 | 6 |

**Empty cells are preserved as blank.** If you place widgets sparsely (e.g. only (0,0) and (1,2)), the middle cells stay empty but don't collapse.

## Row Span and Column Span

**`addWidget(widget, row, column, rowSpan, columnSpan)` — the last two parameters control how many rows/columns to span.**

```
layout = QGridLayout(window)

layout.addWidget(QPushButton("0"), 0, 0)          # row 0, column 0
layout.addWidget(QPushButton("Span 2 cols"), 0, 1, 1, 2)  # row 0, columns 1~2
layout.addWidget(QPushButton("1"), 1, 0)
layout.addWidget(QPushButton("2"), 1, 1)
layout.addWidget(QPushButton("3"), 1, 2)
```

**`rowSpan=1, columnSpan=2` means the button spans two columns.** The "0" key on a calculator often occupies two grid cells — that's how it's done.

**A cleaner calculator example ("0" spans two, "=" spans two rows):**

```
layout = QGridLayout(window)

# Normal buttons: text, row, column
normal = [
    ("7", 0, 0), ("8", 0, 1), ("9", 0, 2),
    ("4", 1, 0), ("5", 1, 1), ("6", 1, 2),
    ("1", 2, 0), ("2", 2, 1), ("3", 2, 2),
]
for text, r, c in normal:
    layout.addWidget(QPushButton(text), r, c)

# Special buttons: spanning cells
layout.addWidget(QPushButton("0"), 3, 0, 1, 2)    # 0 spans two columns
layout.addWidget(QPushButton("="), 3, 2, 1, 2)    # = spans the right two columns
```

## Crash Site 1: Wrong parameter order, widgets pile up in the top-left

**This is the #1 crash site in this lesson.**

**Symptom: you placed six buttons, but only one or two are visible — the rest are stacked on top of each other.**

```
layout.addWidget(0, 0, QPushButton("1"))   # WRONG: parameters reversed!
```

**Error message:** `TypeError: addWidget(self, QWidget, ...): argument 1 has unexpected type 'int'` — Qt expects the first argument to be a QWidget, but you passed the int `0`.

**But the more insidious error has no message — it just displays wrong:**

```
layout.addWidget(QPushButton("1"), 0, 0)
layout.addWidget(QPushButton("2"), 0, 1)
layout.addWidget(QPushButton("3"), 1, 0)
layout.addWidget(QPushButton("4"), 1, 1)
layout.addWidget(QPushButton("5"), 1, 1)   # wrong row! overlaps with 4
layout.addWidget(QPushButton("6"), 1, 1)   # wrong again! all three stack
```

**Symptom: buttons 4, 5, 6 are stacked in the same cell — only the last one is visible.** No error, because the syntax is perfectly legal.

**Why:** the row/column numbers were wrong or duplicated. Zero-indexing makes off-by-one mistakes easy.

**Fix: draw the grid first, label the rows and columns, then write the code.** Or generate with a 2D list:

```
grid = [
    ["7", "8", "9"],
    ["4", "5", "6"],
    ["1", "2", "3"],
]
for r, row in enumerate(grid):
    for c, text in enumerate(row):
        layout.addWidget(QPushButton(text), r, c)
```

**`enumerate` auto-generates row and column numbers — you'll never miscount.**

## Crash Site 2: Wrong span参数, grid breaks

**Symptom: a button spans a column it shouldn't, layout is scrambled.**

```
layout.addWidget(QPushButton("0"), 3, 0, 1, 3)   # meant 2 columns, wrote 3
```

**Why: `columnSpan=3` means starting at column 0, occupy columns 0, 1, 2 — that's fine; but if another widget is then placed at row 3, column 1, it gets pushed out.**

**The more common mistake is a span that causes overlap:**

```
layout.addWidget(QPushButton("Wide"), 0, 0, 1, 2)   # occupies row 0, cols 0, 1
layout.addWidget(QPushButton("Crash"), 0, 1)         # also row 0, col 1!
```

**After the collision, both widgets overlap — the later one covers the earlier one.**

**Fix: for a widget that spans cells, don't place anything else in the cells it covers.**

## setRowStretch and setColumnStretch

**`setColumnStretch(column, stretch)` sets a column's stretch factor.**

```
layout = QGridLayout(window)
layout.addWidget(QLabel("Name"), 0, 0)
layout.addWidget(QLineEdit(), 0, 1)
layout.addWidget(QLabel("Phone"), 1, 0)
layout.addWidget(QLineEdit(), 1, 1)

layout.setColumnStretch(1, 1)    # column 1 (input boxes) stretches
```

**Effect: column 0 (labels) stays at minimum width; column 1 (inputs) absorbs all extra space.**

**Similarly, `setRowStretch(row, stretch)` sets a row's stretch.**

**`setHorizontalSpacing` and `setVerticalSpacing` set horizontal and vertical spacing separately:**

```
layout.setHorizontalSpacing(10)
layout.setVerticalSpacing(4)
```

## Crash Site 3: addWidget without setting column stretch, input stays too narrow

**Symptom: the window stretches wide, but the input box stays narrow with a big gap on the right.**

```
layout = QGridLayout(window)
layout.addWidget(QLabel("Search"), 0, 0)
layout.addWidget(QLineEdit(), 0, 1)
# forgot setColumnStretch(1, 1)
```

**Why:** both columns have stretch=0, so neither stretches. All the extra window space goes unused on the right.

**Fix: `setColumnStretch(1, 1)` lets the input column absorb the extra space.**

## Complete Example: Login Form

**A standard two-column form:**

```
import sys
from PySide6.QtWidgets import (
    QApplication, QWidget, QLabel, QLineEdit,
    QPushButton, QGridLayout, QVBoxLayout
)
from PySide6.QtCore import Qt

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Login")
window.resize(320, 200)

grid = QGridLayout()
grid.addWidget(QLabel("Username"), 0, 0)
grid.addWidget(QLineEdit(), 0, 1)
grid.addWidget(QLabel("Password"), 1, 0)
grid.addWidget(QLineEdit(), 1, 1)
grid.addWidget(QLabel("Captcha"), 2, 0)
grid.addWidget(QLineEdit(), 2, 1)

grid.setColumnStretch(1, 1)          # input column stretches
grid.setVerticalSpacing(8)

main = QVBoxLayout(window)
main.addLayout(grid)
main.addWidget(QPushButton("Login"), alignment=Qt.AlignmentFlag.AlignRight)

window.show()
app.exec()
```

**Explanation: the grid layout handles the two-column alignment; the outer vertical layout places the button bar below.** In the grid, the label column is narrow, the input column wide — stretching makes the input column grow.

## Summary

- `addWidget(widget, row, column)` places widgets by row/column, zero-indexed
- Memorize the parameter order: widget first, row and column after
- `addWidget(widget, r, c, rowSpan, colSpan)` for spanning
- **Wrong parameters don't error but cause overlaps — this lesson's crash site**
- Use `enumerate` on a 2D list to never miscount rows/columns
- setColumnStretch / setRowStretch let a row or column absorb extra space
- Form interfaces commonly use "grid layout + outer vertical layout" together
