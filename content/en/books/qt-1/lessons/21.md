# Getting Started with QSS

> Qt Style Sheets (QSS) are Qt's styling language. The syntax is so close to CSS it's almost identical. This lesson shows how to beautify an interface with QSS — and exactly where it differs from CSS.

## Where QSS and CSS Look the Same

**QSS syntax is a copy of CSS: selector + property + value.**

```
QPushButton {
    background-color: #3498db;
    color: white;
    border: none;
    border-radius: 6px;
    padding: 8px 16px;
    font-size: 14px;
}
```

**Applying it works the same way, via `setStyleSheet`:**

```
btn = QPushButton("Click me")
btn.setStyleSheet("""
    QPushButton {
        background-color: #3498db;
        color: white;
        border-radius: 6px;
        padding: 8px 16px;
    }
""")
```

**What QSS and CSS share: colors, borders, rounded corners, fonts, padding/margin, gradients, sub-controls, and pseudo-states.** If you know CSS, about 80% of the syntax transfers directly.

## Selector Syntax

**The most common form is the type selector — the class name used as a tag name.**

```
QPushButton { color: white; }      # every QPushButton
QLineEdit { border: 1px solid gray; }
QWidget { background: #f0f0f0; }
```

**A class selector uses `.ClassName` — it matches the class itself but not its subclasses.**

```
.QPushButton { color: red; }       # only QPushButton, not its subclasses
```

**An ID selector uses `#objectName` — an exact match on one control.**

```
#title_label {
    font-size: 24px;
    font-weight: bold;
    color: #2c3e50;
}
```

**That requires setting the object name first:**

```
label.setObjectName("title_label")
```

**Descendant selector: separate with spaces to match a nesting relationship.**

```
QGroupBox QPushButton {
    background-color: green;
}
```

**Only the `QPushButton` inside a `QGroupBox` is affected; buttons outside are untouched.** This is great for styling buttons inside a specific group.

## Crash Site #1: Misspelling the Control Name — Styles Silently Do Nothing

**Symptom: you wrote a long QSS block, but after running the interface looks completely unchanged.**

```
btn.setStyleSheet("""
    PushButton {            # WRONG - wrong control name
        background-color: red;
    }
""")
```

**Why: QSS control names must match the PySide6 class name exactly, including case: `QPushButton`, `QLineEdit`, `QMainWindow`.** `PushButton`, `qpushbutton`, and `Button` are all invalid selectors — and none of them trigger an error, so they fail silently.

**✅ Correct:**

```
btn.setStyleSheet("""
    QPushButton {
        background-color: red;
    }
""")
```

**Another frequent error is missing a semicolon or using `=`: QSS is CSS syntax, so properties are separated by `:` and must end with `;`.** Writing `background-color = red` or dropping the `;` makes the whole rule fail.

## Where QSS and CSS Differ

**Difference one: QSS has "sub-controls", which CSS lacks. Complex Qt widgets are made of several sub-parts, accessed with `::`.**

```
QComboBox::drop-down {
    border: none;
    width: 20px;
}

QScrollBar::handle {
    background: #888;
    border-radius: 4px;
}

QCheckBox::indicator {
    width: 16px;
    height: 16px;
}
```

**Difference two: QSS has "pseudo-states", written with `:` — the same as CSS's `:hover`.**

```
QPushButton:hover {
    background-color: #2980b9;
}

QPushButton:pressed {
    background-color: #1f6391;
}

QLineEdit:focus {
    border: 2px solid #3498db;
}
```

**Difference three: QSS does not support some modern CSS features.** There is no flex layout, no grid layout, no CSS variables, no complex `:nth-child` selectors, and no `transform` animations. Qt's layouts are managed by the Layout system; QSS is only responsible for "how it looks".

**Difference four: the box model differs slightly.** QSS's box model is `margin → border → padding → content`, which matches CSS, but `width/height` in QSS acts on the whole control's outer frame — it does not easily control size the way CSS does, because the Qt layout will recompute it.

## Global vs. Local Styles

**Applying one style to the whole application:**

```
app = QApplication(sys.argv)
app.setStyleSheet("""
    QWidget {
        font-family: "Microsoft YaHei";
        font-size: 13px;
    }
    QPushButton {
        background-color: #3498db;
        color: white;
        border-radius: 4px;
        padding: 6px 12px;
    }
    QPushButton:hover {
        background-color: #2980b9;
    }
""")
```

**Scope rule: a style set on a parent propagates to its children, but a child's own style takes higher priority.**

```
window.setStyleSheet("QWidget { background: white; }")
btn.setStyleSheet("QPushButton { background: red; }")    # this button keeps its own
```

**`QWidget { background: ... }` changes the background of every child underneath it.** To affect only the window background, use the `#objectName` selector for precision.

## Summary

- QSS syntax is nearly identical to CSS: `selector { property: value; }`
- Selectors: type `QPushButton`, class `.ClassName`, ID `#objectName`, descendant (space)
- ⚠️ Classic traps: wrong control name casing (e.g. `PushButton`) makes styles fail silently; properties must use `:` and `;`
- QSS-only sub-controls such as `::drop-down`; pseudo-states `:hover/:pressed/:focus`
- QSS does not support flex/grid/CSS variables/transform
- Use `app.setStyleSheet` for global styles, `widget.setStyleSheet` for local ones; child styles win

## Lesson Quiz

```quiz
type: choice
exam: true
q: Regarding the differences between QSS and CSS, which statement is correct?
options:
- QSS fully supports flex layout and grid layout
- QSS accesses sub-controls with ::, e.g. QComboBox::drop-down
- QSS pseudo-states use the :: prefix, e.g. QPushButton::hover
- In QSS, properties are assigned with =, e.g. background-color = red
answer: 1
explain: QSS accesses sub-controls with ::, such as QComboBox::drop-down and QCheckBox::indicator. Pseudo-states use the : prefix (:hover). QSS has no flex/grid, and properties use : ending in ; — never =.
```
