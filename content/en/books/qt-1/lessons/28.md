# QTimer: The Right Way to Schedule Work

> `QTimer` lets you schedule tasks without ever freezing the interface. This lesson explains how `QTimer` works — and why `time.sleep` is poison in a GUI.

## Why time.sleep Is Poison

**`time.sleep(1)` freezes the entire Python interpreter for one second — including the event loop.** During that second nothing can happen: mouse clicks get no response, the window cannot repaint, and animations stop.

```
from PySide6.QtWidgets import QApplication, QLabel
import time, sys

app = QApplication(sys.argv)
label = QLabel("Countdown: 5")
label.show()

for i in range(5, 0, -1):
    label.setText(f"Countdown: {i}")
    app.processEvents()     #勉强刷新
    time.sleep(1)           # freezes for 1 second
```

**Even with `processEvents`, the interface is completely unresponsive during the sleep.** You cannot drag the window, and a close click only takes effect after the sleep ends.

## Basic QTimer Usage

**`QTimer` is Qt's timer. It does not block the event loop — when the time is up it notifies you via a signal, and your slot runs in the gaps of the event loop.**

```
from PySide6.QtCore import QTimer

timer = QTimer()
timer.timeout.connect(on_tick)   # fires when the time is up
timer.start(1000)                # fires every 1000ms (1 second)
```

**Comparison:**

| | time.sleep | QTimer |
|---|---|---|
| Blocks the event loop | yes | no |
| Interface responsiveness | frozen | normal |
| Precision | high (milliseconds) | depends on the event loop (usually enough) |
| Best use case | command-line scripts | GUI scheduled tasks |

## A Countdown With QTimer

**Rewriting the countdown above with `QTimer`:**

```
from PySide6.QtCore import QTimer

class CountdownWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.label = QLabel("Countdown: 5")
        self.count = 5

        self.timer = QTimer(self)
        self.timer.timeout.connect(self.tick)
        self.timer.start(1000)   # tick once per second

        layout = QVBoxLayout(self)
        layout.addWidget(self.label)

    def tick(self):
        self.count -= 1
        if self.count > 0:
            self.label.setText(f"Countdown: {self.count}")
        else:
            self.label.setText("Time's up!")
            self.timer.stop()    # stop the timer
```

**Key point: the `timeout` signal fires `tick`; `tick` returns immediately, so the event loop keeps running — the interface stays responsive.**

## QTimer.singleShot: Fire Once

**`singleShot` is a convenience for "delay once" — no `QTimer` instance needed.**

```
from PySide6.QtCore import QTimer

# run once after 3 seconds
QTimer.singleShot(3000, lambda: label.setText("3 seconds up!"))

# equivalent to:
timer = QTimer()
timer.setSingleShot(True)
timer.timeout.connect(lambda: label.setText("3 seconds up!"))
timer.start(3000)
```

**Common uses: delayed initialization, auto-hiding notices, debounce.**

```
# debounce: only search 500ms after the user stops typing
self.debounce_timer = QTimer()
self.debounce_timer.setSingleShot(True)
self.debounce_timer.timeout.connect(self.do_search)

def on_text_changed(self, text):
    self.debounce_timer.start(500)  # reset the timer on every keystroke
```

## Crash Site #1: No Parent — The Timer Is Garbage-Collected

**Symptom: the timer runs for a while then stops, or the program crashes for no clear reason.**

```
def setup_timer():
    timer = QTimer()          # local variable; collected when the function ends
    timer.timeout.connect(tick)
    timer.start(1000)
    return

setup_timer()  # timer is GC'd immediately, so timeout never fires
```

**Why: Python's garbage collector reclaims objects with no references.** Once `QTimer` is collected, its underlying timer goes with it.

**✅ Correct: store the timer as an instance attribute (`self.timer`) or give it a parent.**

```
class MyWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.timer = QTimer(self)   # parent guarantees the lifetime
        self.timer.timeout.connect(self.tick)
        self.timer.start(1000)
```

## Crash Site #2: Doing Heavy Work in tick — The Timer Drifts

**Symptom: you set a 100ms interval, but it actually fires further and further apart — sometimes several seconds late.**

```
def tick():
    time.sleep(0.5)   # sleeping inside tick
    # or doing a lot of computation
    for i in range(10_000_000):
        pass
```

**Why: `tick` is called from the event loop. Until `tick` returns, the next `timeout` event has to wait in line.** If `tick` takes 500ms, the real interval becomes 500ms + your 100ms = 600ms. If `tick` exceeds the interval, the timer "catches up" by firing multiple timeouts in a row.

**✅ Correct: keep `tick` light (update the UI, read state). Move heavy work to a thread.**

```
def tick(self):
    # light: only update the interface
    self.label.setText(self.get_status_text())
```

## Crash Site #3: Forgetting stop() — Repeated start() Fires Multiple Times

**Symptom: you click the button to start the timer, then click again, and `tick` fires twice — and keeps multiplying.**

```
def on_start(self):
    self.timer = QTimer(self)
    self.timer.timeout.connect(self.tick)
    self.timer.start(1000)   # every click creates a new timer while the old one keeps running
```

**Why: every click creates a new `QTimer`, and the old one is never stopped.** Two (or more) timers fire `tick` simultaneously.

**✅ Correct: reuse the same timer; stop it before starting, or check whether it is running.**

```
def on_start(self):
    if self.timer.isActive():
        self.timer.stop()
    self.timer.start(1000)   # stop, then start

# or more simply:
def on_start(self):
    self.timer.start(1000)   # start() automatically replaces the previous interval
```

## QTimer for Progress Animation

**Use `QTimer` for a "fake progress" animation — visual feedback while the real task has not started yet:**

```
from PySide6.QtCore import QTimer, Qt
from PySide6.QtGui import QColor

class FakeProgress(QWidget):
    def __init__(self):
        super().__init__()
        self.progress = 0
        self.bar = QProgressBar()
        self.bar.setRange(0, 100)

        self.timer = QTimer(self)
        self.timer.timeout.connect(self.animate)

    def start_animation(self):
        self.progress = 0
        self.timer.start(50)   # update every 50ms

    def animate(self):
        self.progress += 2
        if self.progress > 100:
            self.progress = 0   # loop the animation
        self.bar.setValue(self.progress)
```

**This is the classic substitute for "indeterminate progress" — when you do not know how long the task will take, an oscillating animation tells the user "the program is not dead, it is working".**

**A more advanced option: `QProgressBar`'s `setRange(0, 0)` enables "busy" mode, and Qt automatically displays a scrolling animation block — no manual updates needed.**

```
progress_bar.setRange(0, 0)  # indeterminate mode: shows a sliding animation
```

## Summary

- `time.sleep` freezes the event loop; never use it in a GUI
- `QTimer` schedules work via signals and does not block the event loop
- `QTimer.singleShot` fires once after a delay
- A timer must be stored as an instance attribute or given a parent, or it gets GC'd
- Keep `tick` light; heavy work belongs in a thread
- Stop before starting to avoid duplicate triggers
- `QProgressBar.setRange(0, 0)` is a quick indeterminate-progress solution
- Next lesson ties `QThread` + `QTimer` + signals together in a real project
