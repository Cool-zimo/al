# The Resource System: qrc

> Bundling images into your program means you don't ship a folder full of loose files. This lesson covers the `qrc` resource file and the `pyrcc6` compilation flow.

## Why Use a Resource System

**The pain of passing a file path directly: when you distribute the program, the image files must sit next to the exe, and a moved path breaks everything.**

```
btn.setIcon(QIcon("icons/open.png"))    # depends on an external file; may be missing on another machine
```

**With the `qrc` resource system, images are compiled into a Python file and become part of the code:**

```
btn.setIcon(QIcon(":/icons/open.png"))    # pulled from resources; no external file dependency
```

**The `:` prefix means "this is a resource path"; what follows is the path defined inside the `qrc`.** It is loaded from memory at runtime, so there is no "file not found" problem.

## How to Write a qrc File

**A `qrc` file is XML listing the resources to bundle:**

```
<RCC>
    <qresource prefix="/icons">
        <file>open.png</file>
        <file>save.png</file>
        <file>cut.png</file>
    </qresource>
    <qresource prefix="/images">
        <file>logo.png</file>
        <file>background.jpg</file>
    </qresource>
</RCC>
```

**Save it as `resources.qrc`. `<qresource prefix>` is the path prefix; in code you reference resources as `:/icons/open.png`.**

**You can omit the prefix and use the filename directly:**

```
<RCC>
    <qresource>
        <file>icons/open.png</file>
    </qresource>
</RCC>
```

**In that case you reference it as `:/icons/open.png`.** The point of a prefix is to group resources and avoid name collisions.

## The pyrcc6 Compilation Flow

**Step one: write `resources.qrc` and put all your images in the project directory.**

```
project/
├── main.py
├── resources.qrc
└── icons/
    ├── open.png
    ├── save.png
    └── cut.png
```

**Step two: compile the `qrc` into a Python file with `pyrcc6`.**

```
pyrcc6 resources.qrc -o resources_rc.py
```

**`-o` specifies the output filename; the `_rc.py` suffix is a convention.** The generated file is a large dictionary that holds each file as byte data.

**Step three: import that module in `main.py` and use it normally.**

```
import sys
import resources_rc                # you must import this first, or :/ paths will not resolve
from PySide6.QtWidgets import QApplication, QPushButton
from PySide6.QtGui import QIcon

app = QApplication(sys.argv)
btn = QPushButton()
btn.setIcon(QIcon(":/icons/open.png"))
btn.show()
app.exec()
```

**The `import resources_rc` line looks unused, but running it registers the resources with Qt's resource system.** Delete it and `QIcon(":/icons/open.png")` will get no image.

## Crash Site #1: You Changed the qrc but Did Not Re-run pyrcc6 — Resources Are Stale

**Symptom: you added `paste.png` to the `qrc`, your code says `QIcon(":/icons/paste.png")`, but at runtime the icon is blank — nothing shows up.**

**Why: the `qrc` is only a source file; the program actually reads the compiled output `resources_rc.py`.** After changing the `qrc` you must run `pyrcc6 resources.qrc -o resources_rc.py` again, or the new resource simply does not exist in the old `_rc.py`.

**✅ Correct flow: change an image / add an image → update the `qrc` → re-run `pyrcc6` → then run the program.**

**A troubleshooting checklist:**

```
1. Is the file listed in the qrc?          # check the <file> tags
2. Is the filename casing correct?          # Linux is case-sensitive
3. Did you re-run pyrcc6?                   # the most common miss
4. Does resources_rc.py contain the resource? # open it and search for the filename
5. Does main.py import resources_rc?        # forgetting the import means no registration
```

**A convenient shortcut is to put the compilation in your build script:**

```
# build.bat / build.sh
pyrcc6 resources.qrc -o resources_rc.py
python main.py
```

## Crash Site #2: import Comes Too Late — Resources Are Not Registered When the Icon Loads

**Symptom: your code logically imports `resources_rc`, but the icon still will not show.**

```
from PySide6.QtWidgets import QApplication, QPushButton
from PySide6.QtGui import QIcon

btn = QPushButton()
btn.setIcon(QIcon(":/icons/open.png"))    # resources_rc has not been imported yet
import resources_rc                        # too late
```

**Why: resource registration happens the moment `import resources_rc` runs.** If you create a `QIcon` before that, the resource system has no such resource yet and the icon fails to load.

**✅ Correct: `resources_rc` must be imported before any code that uses resources.**

```
import resources_rc                        # first
from PySide6.QtWidgets import QApplication, QPushButton
from PySide6.QtGui import QIcon

btn = QPushButton()
btn.setIcon(QIcon(":/icons/open.png"))    # resources are now registered
```

**By convention, put it at the very top, separate from your third-party imports, so it is easy to spot.**

## Using Resources in QSS

**QSS can reference resource paths too:**

```
QPushButton#open_btn {
    image: url(:/icons/open.png);
    /* or use border-image / background-image */
}

QPushButton#open_btn:hover {
    image: url(:/icons/open_hover.png);
}
```

**`image` keeps the image at its original aspect ratio; `border-image` stretches to fill the control; `background-image` tiles.**

**Using a resource as a background image in QSS:**

```
QWidget#header {
    background-image: url(:/images/header_bg.png);
    background-repeat: no-repeat;
    background-position: center;
}
```

**The `url()` inside QSS also accepts `:/` resource paths and mixes fine with ordinary file paths.**

## Summary

- `qrc` bundles images into the program so it has no external-file dependency at runtime
- Reference resources with `:/prefix/filename`; the colon is the resource prefix
- Compilation flow: write the `qrc` → `pyrcc6 resources.qrc -o resources_rc.py` → import and use
- ⚠️ Classic traps: changing the `qrc` without re-running `pyrcc6` leaves resources stale; importing `resources_rc` too late or forgetting it leaves resources unregistered
- `resources_rc` must be imported before any code that uses resources
- In QSS, `url(:/path)` references resources; `image` / `border-image` / `background-image` behave differently
