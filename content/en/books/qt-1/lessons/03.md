# Signals and Slots: How They Differ from tkinter's command

> In tkinter, clicking a button calls a function (`command=callback`). That's a "callback". In Qt it's "signals and slots": a widget emits a signal, and you connect it to a slot function. This isn't just a rename — it's a mindset upgrade. One signal can connect to multiple slots; one slot can receive from multiple signals.

## tkinter's Way: One-to-One Callbacks

**First, let's revisit what you know.** Click a button, execute a function — that's it:

```python
import tkinter as tk

def say_hi():
    print("Hello")

root = tk.Tk()
btn = tk.Button(root, text="Click me", command=say_hi)
btn.pack()
root.mainloop()
```

**`command=say_hi` is "one-to-one":** one button binds one function. Click once, call once. Need to pass a parameter? Use `lambda` or `functools.partial`:

```python
import tkinter as tk
from functools import partial

def greet(name):
    print("Hello, " + name)

root = tk.Tk()
btn = tk.Button(root, text="Greet", command=partial(greet, "Alice"))
btn.pack()
root.mainloop()
```

**Here's the pain point:** if you want one button to do three things (log, update the UI, write to a file), tkinter's `command` binds only one function. You must call the other functions from within that one — tightly coupled.

## Qt's Way: Signals and Slots, One-to-Many

**Qt completely decouples "something happened" from "what to do about it".** Widgets define many "signals" internally. A signal is "emitted" at a certain moment; whoever is connected receives the call.

```
from PySide6.QtWidgets import QApplication, QWidget, QPushButton
import sys

def on_click():
    print("Button was clicked")

app = QApplication(sys.argv)
window = QWidget()
btn = QPushButton("Click me", window)

btn.clicked.connect(on_click)   # signal.connect(slot)

window.show()
app.exec()
```

**Three terms, memorize them now:**

| Term | What it is | Example |
|---|---|---|
| Signal | An "event notification" a widget emits | `clicked` (clicked), `textChanged` (text changed) |
| Slot | The function executed when the signal arrives | Your own `on_click` |
| connect | What links a signal to a slot | `btn.clicked.connect(on_click)` |

**`clicked` is QPushButton's built-in signal** — emitted automatically when the button is clicked. `connect` is a method on the signal that accepts a callable (function, method, lambda).

**Run it, click three times, console output:**

```
Button was clicked
Button was clicked
Button was clicked
```

## The Real Difference

**This isn't "just a rename" — it's an architectural upgrade.** Three key points:

**1. One-to-many: one signal can connect to multiple slots.**

```
def log_click():
    print("Log: button clicked")

def update_ui():
    print("Updating UI")

btn.clicked.connect(log_click)
btn.clicked.connect(update_ui)
btn.clicked.connect(lambda: print("Third action"))
```

**One click, three functions execute in order.** Impossible in tkinter — you'd write one function that calls the other three.

**2. Many-to-one: multiple signals can connect to one slot.**

```
def handle_any():
    print("Whatever widget triggered it, it all goes here")

btn1.clicked.connect(handle_any)
btn2.clicked.connect(handle_any)
line_edit.returnPressed.connect(handle_any)
```

**One slot handles multiple widgets.** Distinguish the sender via the `sender()` method:

```
def handle_any(self):
    who = self.sender()         # returns the QObject that emitted the signal
    print("Triggered by:", who.objectName())
```

**3. Decoupling: the sender doesn't need to know who's listening.** A button just says "I was clicked, here's my signal" — it doesn't care how many slots exist or what they do. This decoupling makes large programs dramatically cleaner.

## Crash Site 1: Signal connected, but slot signature doesn't match

**This is the most common error, especially with signals that carry arguments.**

```
from PySide6.QtWidgets import QCheckBox

cb = QCheckBox("Agree to terms")

def on_state(s):
    print("State:", s)

cb.stateChanged.connect(on_state)   # Error!
```

**Error message:** `TypeError: on_state() takes 1 positional argument but 2 were given`.

**Why:** the `stateChanged` signal emits **one argument** (a `Qt.CheckState` enum value), but your `on_state` defines parameter `s`, and the overload resolution may pass a different number of arguments. The more common case: the signal carries an argument, but you wrote a slot that accepts none.

**Correct写法:** the slot's parameter count must match the number of values the signal emits.

```
def on_state(state):
    if state == Qt.CheckState.Checked.value:
        print("Checked")
    else:
        print("Unchecked")

cb.stateChanged.connect(on_state)
```

**To determine how many arguments a signal carries:** check the official docs or your IDE's hints. `clicked` carries none; `clicked[bool]` (the overload) carries a bool; `textChanged(str)` carries a string.

## Crash Site 2: Using lambda to pass arguments, everything binds to the last value

**A classic Python closure trap, especially easy to hit in Qt.**

```
from PySide6.QtWidgets import QPushButton

buttons = []
for i in range(3):
    btn = QPushButton(f"Button {i}")
    btn.clicked.connect(lambda: print(i))   # All print 2!
    buttons.append(btn)
```

**Symptom:** click any of the three buttons, all print `2`.

**Why:** the lambda captures a **reference** to variable `i`, not its value. By the time the loop ends, `i` equals 2, so all three lambdas read 2 when executed.

**Fix 1: capture the current value with a default argument:**

```
btn.clicked.connect(lambda checked, i=i: print(i))
```

**`i=i` copies the current loop value into the lambda's default argument** — each lambda gets its own copy, independent of the others.

**Fix 2: use functools.partial:**

```
from functools import partial
btn.clicked.connect(partial(self.on_click, i))
```

**Fix 3: write a factory function:**

```
def make_handler(index):
    return lambda: print(index)

btn.clicked.connect(make_handler(i))
```

**All three work. The first (`i=i`) is shortest**, but remember to add the `checked` parameter — the `clicked` signal passes a bool, and the lambda must accept it, or you'll get a "too many arguments" error.

## Built-in Signals Cheat Sheet

**Every widget has a pile of built-in signals. Memorize the common ones:**

| Widget | Common signal | Argument |
|---|---|---|
| QPushButton | `clicked` | None / bool (whether checked) |
| QLineEdit | `textChanged` | str (new text) |
| QLineEdit | `returnPressed` | None |
| QCheckBox / QRadioButton | `stateChanged` | int (CheckState) |
| QComboBox | `currentIndexChanged` | int (new index) |
| QSlider / QSpinBox | `valueChanged` | int |
| QWidget | `windowTitleChanged` | str |

**`textChanged` is a great example of a signal carrying an argument:**

```
from PySide6.QtWidgets import QLineEdit

edit = QLineEdit()

def on_text(text):
    print("Current input:", text)

edit.textChanged.connect(on_text)
```

**Each keystroke calls `on_text` once**, with `text` being the complete new content of the input box. This is how "real-time input response" is implemented.

## Summary

- tkinter uses callbacks (`command=fn`), one-to-one; Qt uses signals and slots, one-to-many, many-to-one
- Three terms: Signal emits events, Slot receives and handles, `connect` links them
- `btn.clicked.connect(on_click)` is the most basic form
- One signal → many slots: one click triggers multiple actions
- Many signals → one slot: multiple widgets share a handler
- A slot's parameter count must match the number of values the signal emits, or TypeError
- For lambda argument passing, use `lambda checked, i=i: ...` to capture the current value and avoid binding to the last one
