# Why You Shouldn't Use setGeometry for Layout

> In tkinter you can `btn.place(x=20, y=30)` to set manual coordinates, and in Qt you can `widget.setGeometry(20, 30, 100, 40)`. But this approach is almost never used in real projects. This lesson explains its four flaws and why layout managers are the right choice.

## Absolute Positioning: Manually Calculating Coordinates

**`setGeometry(x, y, w, h)` fixes a widget's position and size:**

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QLabel

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Absolute Positioning")
window.resize(400, 300)

title = QLabel("Login", window)
title.setGeometry(20, 20, 100, 30)

name_label = QLabel("Username:", window)
name_label.setGeometry(20, 60, 80, 30)

name_input = QLabel("", window)   # placeholder for an input
name_input.setGeometry(110, 60, 200, 30)

submit = QPushButton("Login", window)
submit.setGeometry(150, 120, 100, 40)

window.show()
app.exec()
```

**What the four numbers mean:** `x` (distance from window left edge), `y` (distance from top edge), `w` (width), `h` (height), all in pixels.

**It looks acceptable in a small demo, but it falls apart as the project grows.**

## Flaw 1: Stretch the window, widgets stay put

**The biggest problem with absolute positioning: widgets don't follow the window.**

**When the user drags the window from 400×300 to 800×600, the widgets stay crammed in the top-left corner**, leaving a huge empty area on the right and bottom. With a layout, widgets automatically rearrange and distribute the extra space.

**Think about the software you use:** when you stretch a browser, the address bar grows; when you stretch WeChat, the chat area expands. None of that is achievable with hard-coded coordinates.

## Flaw 2: More widgets means manually calculating every coordinate

**Five widgets means calculating a dozen numbers, and overlaps are easy.**

```
btn1.setGeometry(20, 20, 100, 40)
btn2.setGeometry(20, 70, 100, 40)    # 20+40+10 gap = 70, manual math
btn3.setGeometry(20, 120, 100, 40)   # 70+40+10 = 120, recalculate again
btn4.setGeometry(140, 20, 100, 40)   # horizontal also needs math
```

**Every time you change one widget's size, every coordinate after it must be recalculated.** A twenty-widget interface means rewriting all coordinates for one layout change.

**The layout写法 (for comparison):**

```
layout = QVBoxLayout()
layout.addWidget(btn1)
layout.addWidget(btn2)
layout.addWidget(btn3)
layout.addWidget(btn4)
```

**Add, remove, or reorder widgets — change one line and you're done.** Coordinates are automatic.

## Flaw 3: Text length changes, layout breaks

**Chinese, English, long text — display widths vary enormously.**

```
btn = QPushButton("Save", window)
btn.setGeometry(20, 20, 60, 30)   # "Save" fits

btn2 = QPushButton("Save to Cloud", window)
btn2.setGeometry(20, 60, 60, 30)  # width still 60, text gets truncated
```

**"Save to Cloud" doesn't fit in 60 pixels** — the button text is squeezed or replaced with an ellipsis. Layout managers use each widget's `sizeHint()` (its preferred size) to allocate enough room.

**Internationalization is a disaster:** English "Save" is short; German "Speichern" is much longer. You can't calculate a separate coordinate set for every language.

## Flaw 4: Different OS, different fonts, sizes all shift

**The same program shows different widget sizes on Windows vs macOS.**

**Reasons:**

- Different default fonts (Microsoft YaHei on Windows vs PingFang on macOS) — Chinese character widths differ at the same point size
- Buttons have native styling (Windows buttons have borders and shadows; macOS uses rounded flat styles) — different pixel footprints
- Different screen DPI (96 DPI on regular screens vs 192 DPI on high-DPI) — pixel density doubles

**Coordinates calculated on one machine may overlap on another.** Layout managers query the current system's fonts and styles to compute appropriate sizes automatically.

## Crash Site 1: Widget doesn't show up — it's covered

**Symptom:** you clearly created the widget in code, but it's invisible at runtime.

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QPushButton

app = QApplication(sys.argv)
window = QWidget()
window.resize(300, 200)

btn1 = QPushButton("Button One", window)
btn1.setGeometry(20, 20, 100, 40)

btn2 = QPushButton("Button Two", window)
btn2.setGeometry(30, 25, 100, 40)   # almost the same as btn1

window.show()
app.exec()
```

**Why:** btn1 and btn2 have nearly identical coordinates, and btn2 is created after btn1, so it covers btn1. You thought "Button One" wasn't showing — it's actually hidden underneath.

**Fix:** use a layout manager, or carefully check your coordinates. Layouts automatically assign non-overlapping positions.

## Crash Site 2: Window too small, widget ends up outside

**Symptom:** the widget is invisible but the code is correct.

```
btn.setGeometry(350, 250, 100, 40)
window.resize(300, 200)   # window is smaller than the widget's position
```

**Why:** the widget's top-left corner is at (350, 250), but the window is only 300×200 — the widget sits outside the visible area.

**Fix:** **a widget's coordinates must be inside the window's client area.** Layout managers handle this for you, guaranteeing widgets stay within the window.

## When Is Absolute Positioning Acceptable?

**Absolute positioning isn't useless — it's actually the best choice in a few scenarios:**

- **Custom-drawn widgets:** you draw things yourself in `paintEvent` (canvas, charts, games) and need precise coordinates.
- **Very few widgets in fixed positions:** a full-screen background image + one centered button, calculated dynamically in `resizeEvent`.
- **Quick prototyping:** rough it in to see the effect, then convert to a layout.

**Rule of thumb: if the interface needs to stretch, support multiple languages, or has more than five widgets — use a layout.**

## Four Basic Layout Classes

**Qt provides several layout classes, corresponding to tkinter's pack/grid:**

| Layout class | Purpose | tkinter equivalent |
|---|---|---|
| QVBoxLayout | Stack widgets vertically (top to bottom) | pack(side=TOP) |
| QHBoxLayout | Stack widgets horizontally (left to right) | pack(side=LEFT) |
| QGridLayout | Arrange widgets by row and column | grid(row, column) |
| QFormLayout | Two-column form (label + input) | LabelFrame + grid |

**Layouts can be nested:** put two vertical layouts inside a horizontal one for complex interfaces.

**The most basic QVBoxLayout usage (preview of Lesson 7):**

```
layout = QVBoxLayout(window)
layout.addWidget(title_label)
layout.addWidget(name_input)
layout.addWidget(submit_btn)
window.setLayout(layout)
```

**Runtime effect:** three widgets stacked top to bottom, all stretching when the window is resized.

## Summary

- `setGeometry(x, y, w, h)` is absolute positioning — manual coordinate math
- Four flaws: no stretch on resize, manual coordinate calculation, breaks with text changes, inconsistent across systems
- On window resize, absolutely-positioned widgets stay in place, leaving大片 empty space
- More widgets means recalculating every coordinate on any change —维护 cost is极 high
- Layout managers auto-allocate space and adapt to fonts and systems
- Absolute positioning only suits custom drawing, very few widgets, and similar niche cases
- Lessons 7–10 cover QVBoxLayout / QHBoxLayout / QGridLayout / QFormLayout systematically
