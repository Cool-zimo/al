# Project: Batch File Renamer

> Lessons 14, 15, 17, and 27 come together in one project — multi-threading, progress bars, file dialogs, and tables — to build a tool that actually does something useful.

## Project Goal

**Build a batch renamer: pick a folder → preview the file list → set a naming rule → run the rename on a background thread → show live progress and a log.**

Feature list:
- Pick a folder (`QFileDialog`)
- Preview the file list (`QTableWidget`)
- Set a naming pattern (prefix + index / regex replace / date prefix)
- Run multi-threaded so the interface never freezes
- Progress bar + log area

## Overall Architecture

**Three core classes: `MainWindow` (UI), `RenameWorker` (rename logic + thread), `RenameConfig` (naming-rule configuration).**

```
project/
├── main.py              # entry point
├── main_window.py       # main window
├── rename_worker.py     # rename Worker
└── config.py            # naming-rule configuration
```

**Why this split: `MainWindow` handles only the UI and signal wiring, `RenameWorker` handles only the rename logic, and `Config` handles only rule parsing.** Each has a single responsibility, which keeps things testable and maintainable.

## RenameWorker: The Rename Logic

**The core of the Worker: take a file list and a naming rule, rename one by one, and report progress and log messages via signals.**

```
from PySide6.QtCore import QObject, Signal, Slot
import os
import time

class RenameWorker(QObject):
    progress = Signal(int)        # progress 0-100
    log = Signal(str)             # log message
    finished = Signal(int)        # done, returns the number of successes
    error = Signal(str)           # error message

    def __init__(self, files, pattern):
        super().__init__()
        self.files = files
        self.pattern = pattern    # naming rule, e.g. "IMG_{n:03d}"
        self._cancelled = False

    @Slot()
    def run(self):
        total = len(self.files)
        success = 0
        for i, filepath in enumerate(self.files):
            if self._cancelled:
                self.log.emit("Cancelled")
                break
            try:
                dirname = os.path.dirname(filepath)
                ext = os.path.splitext(filepath)[1]
                new_name = self.pattern.format(n=i + 1) + ext
                new_path = os.path.join(dirname, new_name)
                os.rename(filepath, new_path)
                success += 1
                self.log.emit(f"✓ {os.path.basename(filepath)} → {new_name}")
            except Exception as e:
                self.log.emit(f"✗ {os.path.basename(filepath)}: {e}")
            self.progress.emit(int((i + 1) * 100 / total))
            time.sleep(0.05)  # simulate work; a real rename is very fast
        self.finished.emit(success)
```

**Note: `os.rename` itself is fast (milliseconds); the sleep here only makes the progress bar animate. In a real scenario, network files or very large numbers of files can make the rename itself slow.**

## Picking a Folder + Preview

**Use `QFileDialog` to pick a folder, then load the file list into the `QTableWidget`:**

```
def browse(self):
    folder = QFileDialog.getExistingDirectory(self, "Select a folder")
    if folder:
        self.path_edit.setText(folder)
        self.load_preview(folder)

def load_preview(self, folder):
    files = sorted([
        f for f in os.listdir(folder)
        if os.path.isfile(os.path.join(folder, f))
    ])
    self.table.setRowCount(len(files))
    for i, f in enumerate(files):
        ext = os.path.splitext(f)[1]
        new_name = self.pattern_edit.text().format(n=i + 1) + ext
        self.table.setItem(i, 0, QTableWidgetItem(str(i + 1)))
        self.table.setItem(i, 1, QTableWidgetItem(f))
        new_item = QTableWidgetItem(new_name)
        new_item.setForeground(Qt.gray)
        self.table.setItem(i, 2, new_item)
    self._files = [os.path.join(folder, f) for f in files]
```

**Column three of the preview table shows the "new name" (in gray) so the user can confirm the naming before executing.**

## Starting the Thread + Wiring Signals

**Launch the Worker thread when the user clicks "Start":**

```
def start_rename(self):
    if not hasattr(self, '_files') or not self._files:
        self.log("Please select a folder first")
        return

    pattern = self.pattern_edit.text()
    self.thread = QThread()
    self.worker = RenameWorker(self._files, pattern)
    self.worker.moveToThread(self.thread)

    # signal connections
    self.thread.started.connect(self.worker.run)
    self.worker.progress.connect(self.progress.setValue)
    self.worker.log.connect(self.append_log)
    self.worker.finished.connect(self.on_finished)
    self.worker.finished.connect(self.thread.quit)
    self.worker.finished.connect(self.worker.deleteLater)
    self.thread.finished.connect(self.thread.deleteLater)

    self.thread.start()
    self.start_btn.setEnabled(False)
    self.cancel_btn.setEnabled(True)
    self.append_log("Starting rename...")

def append_log(self, msg):
    self.log_area.append(msg)

def on_finished(self, count):
    self.append_log(f"Done! Successfully renamed {count} files")
    self.start_btn.setEnabled(True)
    self.cancel_btn.setEnabled(False)
```

**This demonstrates the full `moveToThread` pattern: Worker with no parent → `moveToThread` → `started` triggers `run` → progress/log bridge back to the main thread via signals → on completion `quit` + `deleteLater`.**

## Crash Site #1: Too Many Log Messages Freeze the UI

**Symptom: when renaming thousands of files, the log area updates wildly and the interface gets sluggish — sometimes appearing to hang.**

```
self.worker.log.connect(self.append_log)
# one emit per file -> thousands of signals -> the main thread is busy updating QTextEdit
```

**Why: cross-thread signals carry overhead. Thousands of files means thousands of cross-thread signals plus thousands of `QTextEdit` updates, and `QTextEdit.append` itself has a cost.**

**✅ Correct: batch the log messages, or buffer them and flush in batches.**

```
# approach: flush every 10 entries as a summary
self._log_buffer = []
def _flush_log(self):
    if self._log_buffer:
        self.log_area.append("\n".join(self._log_buffer))
        self._log_buffer.clear()

# have the Worker emit a summary every 10 files instead
```

## Crash Site #2: A Failed Rename Leaves No Rollback

**Symptom: the rename fails partway (e.g. the target filename already exists); some files were renamed and some were not, leaving the folder a mess.**

```
os.rename(filepath, new_path)  # raises FileExistsError if new_path already exists
```

**✅ Correct: check for target conflicts first, or use try-except to skip and record them, then report which ones failed after the run. A more complete approach is a dry-run preview first, then execute once everything checks out.**

## Crash Site #3: After Cancelling, the Files Are in an Inconsistent State

**Symptom: you click cancel and the rename stops halfway — half the folder has new names, half has old names.**

**This is not a bug so much as a design trade-off.** Cancelling a batch operation midway necessarily leaves partial work. A more professional approach:
1. Before running, build an "operation list" (every old→new mapping)
2. Copy that list into memory when executing
3. On cancel, only pending items are affected

**For a teaching project, the simple treatment is enough: the cancel button sets the `_cancelled` flag, and the current file is finished before exiting.**

```
def cancel(self):
    if self.worker:
        self.worker._cancelled = True
```

- Because the rename operation modifies files, and Qt requires all file operations to be on a background thread

answer: 2
