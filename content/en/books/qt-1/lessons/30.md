# Wrapping Up: Project Organization and What's Next

> Twenty-five lessons are done. This final lesson covers how to organize a Qt project, how to package it for distribution, and what awaits in *Python Qt 进阶 2*.

## How to Organize a Qt Project

**A small project can live in a single file, but anything bigger needs to be split by responsibility.** The recommended directory layout:

```
myapp/
├── main.py                  # entry point: only creates QApplication and the main window
├── main_window.py           # main window: menu bar, toolbars, status bar, core layout
├── dialogs/                 # dialog modules
│   ├── __init__.py
│   ├── settings_dialog.py   # settings dialog
│   └── about_dialog.py      # about dialog
├── widgets/                 # custom widgets
│   ├── __init__.py
│   └── custom_slider.py     # custom slider
├── core/                    # business logic (Qt-independent)
│   ├── __init__.py
│   ├── data_model.py        # data model
│   └── file_operations.py   # file operations
├── workers/                 # thread Workers
│   ├── __init__.py
│   └── rename_worker.py
├── resources/               # resource files
│   ├── icons/
│   ├── themes/
│   └── resources.qrc
├── styles/
│   └── main.qss
└── tests/                   # unit tests
    └── test_data_model.py
```

**Rules for the split:**

| Layer | What belongs there | May import |
|---|---|---|
| `core/` | pure logic (data models, algorithms, file I/O) | nothing Qt-dependent |
| `workers/` | thread-task logic | only `core` |
| `widgets/` | custom controls | Qt + `core` |
| `dialogs/` | all dialogs | everything above |
| `main_window.py` | main-window assembly | everything above |
| `main.py` | entry point | only creates app + window |

**Why must `core/` be Qt-independent?** Because it needs to be covered by unit tests, and unit tests should not need to launch a GUI. Decoupling business logic from Qt is the mark of professional Qt development.

## How to Decide When to Split

**Once a file passes 300 lines, consider splitting it.** But that is not a hard rule — what matters more is "does it have a single responsibility?".

**Where do signal-and-slot connections go?** The recommendation is to connect main-window signals in `MainWindow.__init__`, and let a child control connect its own internal signals — do not "skip levels".

```
# good: connect things close to where they belong
class SettingsDialog(QDialog):
    settings_changed = Signal(dict)
    def __init__(self):
        # connect internal signals yourself
        self.ok_btn.clicked.connect(self._on_ok)

class MainWindow(QMainWindow):
    def __init__(self):
        self.settings_dialog = SettingsDialog()
        # cross-module signals connect here in MainWindow
        self.settings_dialog.settings_changed.connect(self._apply_settings)
```

## Packaging a Qt App With PyInstaller

**PyInstaller is the go-to packaging tool for Python. But Qt apps have special requirements — you must bundle Qt's plugins and shared libraries.**

**The basic packaging command:**

```
pip install pyinstaller
pyinstaller --onefile --windowed main.py
```

**`--windowed` matters a lot** — it tells PyInstaller this is a GUI program, so do not pop up a console window at runtime. On Windows it is `--noconsole`; on macOS it is `--windowed`.

**The Qt-specific gotcha: the plugin directory.**

**Qt needs platform plugins (the platform plugin), such as `qwindows.dll` on Windows or `libqxcb.so` on Linux. PyInstaller usually collects them, but sometimes it misses one.**

```
# if you get "qt.qpa.plugin: Could not find the Qt platform plugin"
# manually specify the plugin directory
pyinstaller --onefile --windowed \
    --add-data "venv/Lib/site-packages/PySide6/plugins;PySide6/plugins" \
    main.py
```

**The typical Windows error:**

```
qt.qpa.plugin: Could not load the Qt platform plugin "windows" in "" even though it was found.
This application failed to start because no Qt platform plugin could be initialized.
```

**That usually means `plugins/platforms/qwindows.dll` was not packaged correctly.** Solutions:

```
# option 1: use --collect-all to force-collect every PySide6 file
pyinstaller --onefile --windowed --collect-all PySide6 main.py

# option 2: specify hooks manually
# create hooks/hook-PySide6.py
from PyInstaller.utils.hooks import collect_all
datas, binaries, hiddenimports = collect_all('PySide6')
```

**On macOS, the Qt framework path inside the `.app` bundle can be a problem:**

```
# if you get "Library not loaded: @rpath/QtCore.framework/Versions/A/QtCore"
# you need to add this to the .spec file
import PySide6
PySide6.__file__  # find the PySide6 install path
# in the .spec add
binaries=[( '/path/to/PySide6/Qt/lib/*.dylib', '.' )],
```

**On Linux, make sure the target machine has system libraries like `libxcb`, or you will get `xcb`-related errors.**

## Packaging Checklist

**Things that must be checked before release:**

```
- [ ] --windowed / --noconsole is set
- [ ] PySide6 plugins (platforms, styles, imageformats) are bundled
- [ ] the .qrc resource has been compiled to .py and loads correctly
- [ ] QSS file paths still work after packaging (use a resource_path helper)
- [ ] the app icon is set (.ico for Windows, .icns for macOS)
- [ ] tested on a clean machine (one with no Python/Qt environment)
- [ ] file size is acceptable (a PySide6 package is typically 30-50MB)
```

**The path problem: `sys._MEIPASS` is the key.**

**After PyInstaller packages the app, files are unpacked to a temp directory at `sys._MEIPASS`. Your resource-file paths need to handle that:**

```
import sys
import os

def resource_path(relative_path):
    """Get the absolute path to a resource, compatible with both dev and packaged modes"""
    if hasattr(sys, '_MEIPASS'):
        return os.path.join(sys._MEIPASS, relative_path)
    return os.path.join(os.path.abspath("."), relative_path)

# usage
icon_path = resource_path("resources/icons/app.png")
qss_path = resource_path("styles/main.qss")
```

## Crash Site #1: QSS Loads in Dev but Fails After Packaging

**Symptom: the styling is correct during development, but after packaging the interface reverts to the default (ugly) style.**

**Why: the QSS file path changes after packaging. In dev you use the relative path `./styles/main.qss`, but after packaging that file lives inside `sys._MEIPASS`.**

**✅ Correct: wrap every resource path with the `resource_path` function above.**

```
# fails in dev, breaks after packaging
with open("./styles/main.qss", "r") as f:
    app.setStyleSheet(f.read())

# works in both modes
path = resource_path("styles/main.qss")
with open(path, "r", encoding="utf-8") as f:
    app.setStyleSheet(f.read())
```

## Crash Site #2: The Packaged App Is 200MB+

**Symptom: a simple program ends up over 200MB after packaging.**

**Why: PyInstaller bundles the entire Python environment and all dependencies. If you pulled in large libraries like `numpy` or `pandas`, the size explodes.**

**✅ Optimization: use a clean virtual environment with only the dependencies you need + `--exclude-module` to drop unused modules.**

```
# create a clean virtual environment
python -m venv build_env
source build_env/bin/activate  # Windows: build_env\Scripts\activate
pip install PySide6 pyinstaller

# exclude unneeded large modules
pyinstaller --onefile --windowed --exclude-module numpy main.py
```

**What you learned is not just an API — it is a way of thinking:**

1. **Event-driven**: a program does not run top to bottom; it "waits for an event → responds"
2. **Signals and slots**: components communicate without coupling; they do not need to know the other exists
3. **The main thread never blocks**: heavy work goes on a thread so the interface stays smooth
4. **Signal bridging**: a background thread never touches the UI directly; it only emits signals
5. **Style separated from logic**: QSS handles appearance, Python handles logic

That is the dividing line between "can build something" and "can build professional-grade applications".

## Summary

- A Qt project is split by responsibility: core / workers / widgets / dialogs / main_window / main
- The `core` layer stays independent of Qt so it can be unit-tested
- Packaging a Qt app with PyInstaller must include the plugins (platforms, styles, imageformats)
- `--windowed` hides the console; `--collect-all PySide6` fixes missing plugins
- Use `resource_path` to be compatible with both dev and packaged path modes
- A clean virtual environment + `--exclude-module` keeps the package size down
- Core mindset: event-driven, signals and slots, main thread never blocks, signal bridging, separation of style and logic
- *Qt 进阶 2* goes deeper into Model/View, custom controls, drawing, databases, and networking
