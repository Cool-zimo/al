# Layout Stretching: sizePolicy, setStretch, and minimumSize

> Layouts distribute extra space among widgets, but "who gets it and how much" is governed by the stretch mechanism. This lesson covers three things that control stretching: sizePolicy (the widget's own stated "growth intent"), setStretch (the layout assigning proportions), and minimumSize / maximumSize (size boundaries).

## sizePolicy: A Widget's Reported "Growth Intent"

**Every QWidget has a QSizePolicy describing how it wants to stretch with the layout.**

```
from PySide6.QtWidgets import QSizePolicy

widget.sizePolicy()                        # read
widget.setSizePolicy(
    QSizePolicy.Policy.Expanding,          # horizontal
    QSizePolicy.Policy.Fixed               # vertical
)
```

**Horizontal Expanding, vertical Fixed: "take up as much horizontal space as possible, keep vertical at the preferred size".**

**Common policies:**

| Policy | Meaning |
|---|---|
| Fixed | Uses only sizeHint(), never changes |
| Minimum | Not less than sizeHint(), can grow |
| Maximum | Not more than sizeHint(), can shrink |
| Preferred | sizeHint() is ideal; can be larger or smaller |
| Expanding | Take as much space as possible (wants to stretch) |
| Ignored | Completely ignores sizeHint(), fills available space |

**Memory口诀: Expanding is the greediest, Fixed is the most stubborn.**

## Example: The Editor Area Should Fill the Remaining Space

**Typical scenario: a few input boxes on top, a large text area below.**

```
import sys
from PySide6.QtWidgets import (
    QApplication, QWidget, QLineEdit, QTextEdit, QVBoxLayout
)
from PySide6.QtWidgets import QSizePolicy

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Stretch Example")

title_edit = QLineEdit()
title_edit.setSizePolicy(
    QSizePolicy.Policy.Preferred,      # horizontal: keep preferred width
    QSizePolicy.Policy.Fixed           # vertical: fixed height
)

body_edit = QTextEdit()
body_edit.setSizePolicy(
    QSizePolicy.Policy.Expanding,     # horizontal: fill as much as possible
    QSizePolicy.Policy.Expanding      # vertical: fill as much as possible
)

layout = QVBoxLayout(window)
layout.addWidget(title_edit)
layout.addWidget(body_edit)

window.resize(400, 350)
window.show()
app.exec()
```

**Effect: the title input stays one line tall; the text editor below occupies all remaining space.**

## Crash Site 1: Widget refuses to stretch

**Symptom: the window stretches large, but the widget stays crammed in the top-left, as if no layout were set.**

**Most common cause: the widget's sizePolicy is Fixed.**

```
body_edit.setSizePolicy(
    QSizePolicy.Policy.Fixed,     # WRONG! fixed size, won't stretch
    QSizePolicy.Policy.Fixed
)
```

**Fix: change horizontal or vertical (or both) to Expanding or MinimumExpanding.**

**Another cause: the layout itself has no stretch set.** See `setStretch` below.

## setStretch: The Layout Assigns Proportions

**`layout.setStretch(index, stretch)` sets the space allocation ratio for the widget at `index`.**

```
layout = QVBoxLayout(window)
layout.addWidget(top_widget)      # index 0
layout.addWidget(mid_widget)      # index 1
layout.addWidget(bot_widget)      # index 2

layout.setStretch(0, 1)
layout.setStretch(1, 2)
layout.setStretch(2, 1)
```

**Effect: the middle widget gets twice the space of the top and bottom widgets.** Ratio 1:2:1.

**`addWidget(widget, stretch)`'s second parameter is the stretch — writing it in one line is more convenient:**

```
layout.addWidget(top_widget, 1)
layout.addWidget(mid_widget, 2)
layout.addWidget(bot_widget, 1)
```

**stretch=0 means "don't participate in stretching"** — keep sizeHint(). This is also why "the widget doesn't change when you make the window bigger" — its stretch is 0 and its sizePolicy isn't Expanding.

## Crash Site 2: setStretch set, but sizePolicy is Fixed

**Symptom: no amount of setStretch takes effect.**

```
widget.setSizePolicy(QSizePolicy.Policy.Fixed, QSizePolicy.Policy.Fixed)
layout.addWidget(widget, 10)     # setting 10x stretch does nothing
```

**Why: stretch is the layout's allocation intent, but sizePolicy is the widget's "whether it accepts it". The widget says Fixed, so even when the layout offers space, it declines.**

**Fix: the two must cooperate. The layout assigns with setStretch; the widget accepts with sizePolicy set to Expanding.**

## minimumSize and maximumSize

**`setMinimumSize(w, h)` and `setMaximumSize(w, h)` set size boundaries on a widget.**

```
window.setMinimumSize(300, 200)   # window minimum 300×200
window.setMaximumSize(800, 600)   # window maximum 800×600
```

**The window is constrained between 300×200 and 800×600 — the user can't drag outside that range.**

**`setFixedSize(w, h)` sets minimum and maximum to the same value, making the window non-resizable:**

```
window.setFixedSize(400, 300)
```

**Same goes for individual widgets:**

```
btn.setMinimumWidth(120)          # button minimum width 120
btn.setMaximumWidth(200)
```

**`sizeHint()` returns the widget's "preferred size"** — the layout allocates space based on it by default:

```
print(btn.sizeHint())            # PySide6: QSize(...)
```

**sizeHint is determined by the widget's content:** a button's sizeHint depends on its text length plus padding.

## minimumSizeHint vs sizeHint

**The two concepts are easily confused:**

- **sizeHint():** preferred size — the layout's initial allocation basis.
- **minimumSizeHint():** the minimum reasonable size — the smallest the widget can be and still be usable.

**In most cases you only need to worry about sizeHint and setMinimumSize.**

## Crash Site 3: setFixedSize applied, then the user wants resizing

**Symptom: after setting a fixed size, the window can't be resized, and users complain.**

```
window.setFixedSize(400, 300)
# later the requirements change and you want the user to resize
```

**Fix: switch to setMinimumSize + setMaximumSize, or remove the fixed size entirely:**

```
window.setMinimumSize(300, 200)
# don't set maximumSize, letting the window scale up freely
```

**Only use setFixedSize for windows that genuinely need a fixed size (calculators, small utilities).**

## Complete Example: Three-Column Layout

**Left navigation, middle content, right properties panel, ratio 1:3:1:**

```
import sys
from PySide6.QtWidgets import (
    QApplication, QWidget, QLabel, QHBoxLayout
)
from PySide6.QtWidgets import QSizePolicy
from PySide6.QtCore import Qt

app = QApplication(sys.argv)
window = QWidget()
window.setWindowTitle("Three Columns")
window.resize(800, 500)

nav = QLabel("Nav")
nav.setAlignment(Qt.AlignmentFlag.AlignCenter)
nav.setStyleSheet("background: #e0e0e0;")

content = QLabel("Content Area")
content.setAlignment(Qt.AlignmentFlag.AlignCenter)

props = QLabel("Props")
props.setAlignment(Qt.AlignmentFlag.AlignCenter)
props.setStyleSheet("background: #f0f0f0;")

layout = QHBoxLayout(window)
layout.addWidget(nav, 1)
layout.addWidget(content, 3)
layout.addWidget(props, 1)

window.show()
app.exec()
```

**`addWidget(nav, 1)`, `addWidget(content, 3)`, `addWidget(props, 1)`** directly expresses the 1:3:1 ratio. This is the stretch-parameter写法.

**As the window stretches, the three columns widen together at 1:3:1.**

## Summary

- sizePolicy is a widget's self-reported "growth intent": Expanding is greediest, Fixed is most stubborn
- setStretch(index, n) or addWidget(widget, n) lets the layout assign space proportionally
- stretch and sizePolicy must cooperate: layout assigns, widget accepts
- setMinimumSize / setMaximumSize set size boundaries
- setFixedSize makes the window non-resizable — only for small utilities
- sizeHint() is preferred size; minimumSizeHint() is the minimum reasonable size
- 1:3:1 three-column layout written in one line with addWidget's stretch parameter
