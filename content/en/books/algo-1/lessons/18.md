# Boundary Binary Search: Finding the First and Last Match

> Standard binary search only answers "is it there?". This lesson solves the more common problem: **where is the first or last element that satisfies a condition in an ordered array?**

## The Problem

**Task**: in an ordered array, find the position of the **first** and **last** occurrence of a value.

```python
nums = [1, 2, 2, 2, 2, 3, 4, 5]
# 2 first appears at index 1
# 2 last appears at index 4
```

Why look for boundaries?

- Count how many times a value occurs = `last_pos - first_pos + 1`
- Find the first position where the value is `>= target` (lower_bound)
- Find the first position where the value is `> target` (upper_bound)

## Left Boundary: lower_bound

**Goal**: find the **first position `>= target`**.

```python
def lower_bound(nums, target):
    left, right = 0, len(nums)          # note: right starts at len(nums)
    while left < right:                  # note: < not <=
        mid = (left + right) // 2        # round down
        if nums[mid] < target:
            left = mid + 1               # mid is too small, go right
        else:
            right = mid                  # mid itself might be the answer, stay
    return left
```

**Why `right = mid` instead of `right = mid - 1`?** Because when `nums[mid] >= target`, `mid` itself might be the first position that satisfies the condition, so we cannot drop it.

**Why `while left < right`?** Because when the loop stops, `left == right`, and that position is the answer.

```python
nums = [1, 2, 2, 2, 2, 3, 4, 5]
print(lower_bound(nums, 2))   # 1
print(lower_bound(nums, 3))   # 5
print(lower_bound(nums, 6))   # 8 (out of range: every element is < 6)
```

## Right Boundary: upper_bound

**Goal**: find the **first position `> target`** (that is, the position right after the last `== target`).

```python
def upper_bound(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] <= target:
            left = mid + 1               # mid is too small or equal, go right
        else:
            right = mid                  # mid is too big, mid might be the answer
    return left
```

```python
nums = [1, 2, 2, 2, 2, 3, 4, 5]
print(upper_bound(nums, 2))   # 5 (index 5 holds 3, the first value > 2)
print(upper_bound(nums, 3))   # 6
print(upper_bound(nums, 1))   # 1
```

## Counting Occurrences with lower / upper

```python
def count_occurrences(nums, target):
    return upper_bound(nums, target) - lower_bound(nums, target)

nums = [1, 2, 2, 2, 2, 3, 4, 5]
print(count_occurrences(nums, 2))   # 5 - 1 = 4 ✓
print(count_occurrences(nums, 3))   # 6 - 5 = 1 ✓
print(count_occurrences(nums, 6))   # 8 - 8 = 0 ✓ (not present)
```

**Time O(log n)** -- far faster than the linear scan at O(n).

## A Trace of lower_bound by Hand

`nums = [1, 2, 2, 2, 2, 3, 4, 5]`, looking for `target = 2`:

```
start: left=0, right=8, interval [0, 8)
mid=4, nums[4]=2 >= 2 -> right=4

left=0, right=4, interval [0, 4)
mid=2, nums[2]=2 >= 2 -> right=2

left=0, right=2, interval [0, 2)
mid=1, nums[1]=2 >= 2 -> right=1

left=0, right=1, interval [0, 1)
mid=0, nums[0]=1 < 2 -> left=1

left=1, right=1 -> loop ends, return 1 ✓
```

## Comparing the Two Styles

| Feature | lower_bound | upper_bound |
|---|---|---|
| Finds | First `>= target` | First `> target` |
| When `< target` | `left = mid + 1` | `left = mid + 1` |
| When `== target` | `right = mid` | `left = mid + 1` |
| When `> target` | `right = mid` | `right = mid` |
| Return value | First satisfying position | First non-satisfying position |

**The difference is in exactly one place**: when `nums[mid] == target`, lower_bound goes left (there may be a smaller one), and upper_bound goes right (looking for something strictly larger than target).

## # WRONG -- The Mixed-Up Crash Scene

The classic disaster: copy the loop body of one template but expect the return value of the other.

```python
# WRONG -- lower_bound's body, but hoping for the last occurrence
def buggy(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid           # this branch belongs to lower_bound
    # hoping this returns the last occurrence
    return left                   # nope: this is the FIRST occurrence

# nums = [1, 2, 2, 2, 2, 3], target = 2
# returns 1 (first 2), not 4 (last 2)
```

**Why it crashes the answer**: lower_bound and upper_bound have different branch logic and cannot be mixed. The `else: right = mid` branch is what makes lower_bound stop at the first `>=` position; it will never walk past a matching element to find the last one.

The correct right-boundary search keeps going after a match:

```python
# FIXED -- find the last occurrence
def binary_search_last(nums, target):
    left, right = 0, len(nums) - 1
    ans = -1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            ans = mid             # record, then keep going right
            left = mid + 1
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return ans
```

**The rule**: to find the last match, do not return when you find one -- record it and keep searching in the direction that may hold a later copy.

## Common Mistakes

### Mistake 1: mixing the two templates

```python
# Wrong: lower_bound's loop body + expecting upper_bound's result
def buggy(nums, target):
    left, right = 0, len(nums)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    # then expecting the last occurrence
    return left   # returns the first occurrence, not the last!
```

**The two templates have different branch logic and cannot be mixed.**

### Mistake 2: wrong initial value for right

```python
# Wrong: right starts at len(nums)-1
left, right = 0, len(nums) - 1
while left < right:
    ...
# now right can never reach len(nums)
# when target is larger than every element, we should return len(nums), but cannot
```

**In boundary binary search, `right` is initialized to `len(nums)` (the open end of the interval).**

### Mistake 3: rounding up causes an infinite loop

```python
while left < right:
    mid = (left + right + 1) // 2   # rounds up
    if nums[mid] < target:
        left = mid                  # infinite loop! mid never changes
    else:
        right = mid
```

**The left-boundary template rounds down with `(left+right)//2`; only the right-boundary template rounds up.**

## Why Python Has the bisect Module

Python's standard library ships a `bisect` module that does exactly this:

```python
import bisect

nums = [1, 2, 2, 2, 2, 3, 4, 5]
print(bisect.bisect_left(nums, 2))   # 1 (lower_bound)
print(bisect.bisect_right(nums, 2))  # 5 (upper_bound)

# insert an element
bisect.insort(nums, 2)
print(nums)   # [1, 2, 2, 2, 2, 2, 3, 4, 5]
```

**In an interview, write binary search by hand (to show you understand it); in real engineering code, use `bisect`.**

## Summary

- **lower_bound**: find the first `>= target`; when `nums[mid] >= target`, `right = mid`
- **upper_bound**: find the first `> target`; when `nums[mid] <= target`, `left = mid + 1`
- The two templates differ by a single `=`
- Occurrences = `upper_bound - lower_bound`
- Python has the `bisect` module; write it by hand in interviews
