# Big-O notation

> Last lesson we said the nested loop "grows like n²". This lesson gives that claim a standard name and strict rules.

## Why not just say "how many seconds"

You might think timing is enough. **It isn't**, because the same program takes wildly different times depending on context:

| Factor | Effect |
|---|---|
| Machine speed | the same code can be 5× slower on older hardware |
| Language | a nested loop in C may beat a single loop in Python |
| The data itself | a duplicate early on means an early return, so it finishes fast |
| Current load | a background download makes everything slower |

**So we need a measure that's independent of the machine and describes the algorithm itself.** That's big-O.

## What big-O actually says

**`O(f(n))` means: as the input size n grows large, the number of operations doesn't grow faster than f(n).**

Three points:

**1. Only the growth trend matters, not the exact number.**

- 3n operations → `O(n)`
- 3n + 100 operations → still `O(n)`
- n²/2 + 5n operations → `O(n²)`

**2. Constant factors are dropped.**

`O(2n)` and `O(n)` are the same thing, because the trend is identical: double n, double the time.

**3. Only the highest-order term survives.**

`O(n² + n)` becomes `O(n²)`, because for large n the n² term swamps the n term entirely:

```
n = 10     → n² + n = 110          n is 9%
n = 100    → n² + n = 10100        n is 1%
n = 1000   → n² + n = 1001000      n is 0.1%
```

> 💡 **Analogy:** saying "I earn 300k a year" doesn't mean "300,000 and five pounds thirty". Big-O is that kind of order-of-magnitude shorthand.

## How to count complexity

### Rule one: sequential code — take the largest

```python
def f(n):
    for i in range(n):        # n times
        print(i)
    for i in range(n):        # n times
        print(i)
```

2n in total → **O(n)** (drop the constant 2)

### Rule two: nested loops — multiply

```python
def f(n):
    for i in range(n):            # n times
        for j in range(n):        # n times each
            print(i, j)
```

n × n = n² → **O(n²)**

### Rule three: work that doesn't depend on n is O(1)

```python
def f(n):
    x = 5 + 3          # O(1)
    print(x)           # O(1)
    return n * 2       # O(1)
```

Whether n is 10 or 10 million, these lines do a fixed amount of work → **O(1)**

**Note:** `O(1)` doesn't mean "one operation" — it means "**the operation count doesn't grow with n**".

### Rule four: take the biggest part

```python
def f(n):
    for i in range(n):            # O(n)
        print(i)
    for i in range(n):            # O(n²)
        for j in range(n):
            print(i, j)
```

`O(n) + O(n²)` → **O(n²)** (n² dominates; the n is absorbed)

## A place people get it wrong: the inner loop's range

These two look similar but behave identically in big-O terms:

```python
# A: the inner loop runs the full n each time → O(n²)
for i in range(n):
    for j in range(n):
        ...

# B: the inner loop starts at i, totalling about n²/2 → still O(n²)
for i in range(n):
    for j in range(i, n):
        ...
```

**B does half the work, yet it's still O(n²)** — because doubling n still quadruples it. Big-O drops the 1/2.

That's why last lesson's "compare everything" version (inner loop `range(i+1, n)`), despite already halving the work, was still painfully slow.

## The three you must know first

| Code shape | Complexity | Typical use |
|---|---|---|
| direct access, arithmetic | `O(1)` | indexing a list, checking parity |
| a single for loop | `O(n)` | finding the max, summing, duplicate check with a set |
| nested for loops | `O(n²)` | pairwise comparison, naive sorting |

```python
# O(1): independent of n
def get_first(items):
    return items[0]

# O(n): one pass
def find_max(items):
    m = items[0]
    for x in items:
        if x > m:
            m = x
    return m

# O(n²): pairwise
def count_pairs(items):
    count = 0
    for i in range(len(items)):
        for j in range(i + 1, len(items)):
            if items[i] == items[j]:
                count += 1
    return count
```

## Practice: what's the complexity here?

```python
def mystery(items):
    total = 0
    for x in items:              # O(n)
        total += x
    for a in items:              # O(n²)
        for b in items:
            total += a * b
    return total                 # O(1)
```

Answer: **O(n²)**. Out of `O(n) + O(n²) + O(1)`, the largest is O(n²).

## Why this matters

Because **it's how you choose a solution**:

- See a nested loop → ask whether it can drop to O(n)
- An interviewer asking "can you optimise this?" is asking "can you drop a complexity class?"
- Code running slow → check complexity first, not individual lines

**Dropping one complexity class beats every micro-optimisation.** The 4000× gap in lesson one came from O(n²) → O(n).

## Summary

- Big-O describes the **growth trend**, independent of hardware
- **Drop constants, keep only the highest-order term**
- Sequential → take the max; nested → multiply; independent of n → O(1)
- Learn `O(1)` / `O(n)` / `O(n²)` first
- Next lesson lines the common complexities **up side by side**
