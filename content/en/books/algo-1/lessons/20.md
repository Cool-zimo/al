# In Practice: Searching in Rotated / Nearly Sorted Arrays

> Standard binary search requires a fully sorted array. This lesson covers a classic variation: **rotated sorted arrays** -- mostly sorted, but with one "break point."

## The Problem: Search in a Rotated Sorted Array

**Task**: an integer array `nums` was originally ascending, then rotated at some position (the first few elements were moved to the end).

```python
# Originally [1, 2, 3, 4, 5, 6, 7]
# Rotated by 3 positions: [4, 5, 6, 7, 1, 2, 3]
# Or rotated by 2 positions: [6, 7, 1, 2, 3, 4, 5]

nums = [4, 5, 6, 7, 1, 2, 3]
# Find target=2, return index 5
```

**It is not sorted overall, but it is "locally sorted."** That is exactly what we can exploit.

## The Key Observation

**Property of a rotated array**: if you cut it at the middle, **at least one of `[left, mid]` and `[mid, right]` is fully sorted.**

```
nums = [4, 5, 6, 7, 1, 2, 3]
left=0, right=6, mid=3
nums[mid] = 7

left half  [4, 5, 6, 7] -> sorted!
right half [7, 1, 2, 3] -> not sorted
```

**Use whichever half is sorted to make the decision.**

## The Algorithm

1. Take `mid = (left + right) // 2`
2. **Decide which half is sorted**
3. **In the sorted half, check whether target is in range**
   - If it is in range -> search that half
   - If not -> search the other half

```python
def search_rotated(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid

        # Is the left half sorted?
        if nums[left] <= nums[mid]:
            # left half is sorted
            if nums[left] <= target < nums[mid]:
                right = mid - 1      # target is in the left half
            else:
                left = mid + 1       # target is in the right half
        else:
            # right half is sorted
            if nums[mid] < target <= nums[right]:
                left = mid + 1       # target is in the right half
            else:
                right = mid - 1      # target is in the left half

    return -1

print(search_rotated([4, 5, 6, 7, 1, 2, 3], 2))   # 5
print(search_rotated([4, 5, 6, 7, 1, 2, 3], 8))   # -1
```

## A Trace by Hand

`nums = [4, 5, 6, 7, 1, 2, 3]`, looking for `target = 2`:

```
left=0, right=6, mid=3, nums[3]=7
7 != 2
left half [4,5,6,7] is sorted (nums[0]<=nums[3])
target=2, 2 is not in [4, 7] -> go right
left=4

left=4, right=6, mid=5, nums[5]=2
2 == 2 -> return 5 ✓
```

Looking for `target = 6`:

```
left=0, right=6, mid=3, nums[3]=7
7 != 6
left half is sorted, 6 is in [4, 7) -> go left
right=2

left=0, right=2, mid=1, nums[1]=5
5 != 6
left half [4,5] is sorted, 6 is not in [4, 5) -> go right
left=2

left=2, right=2, mid=2, nums[2]=6
6 == 6 -> return 2 ✓
```

## Why At Least One Half Must Be Sorted

**Intuition**: a rotated array is an ordered array with "one cut" then reassembled. After one cut, one segment must remain a complete ascending sequence.

```
original:  [1, 2, 3, 4, 5, 6, 7]
cut after 4: [5, 6, 7 | 1, 2, 3, 4]
              right intact   left intact
```

No matter where you cut, **one segment is always a contiguous ascending sequence**. The algorithm uses that sorted segment every time to shrink the search range.

## Complexity

**Time O(log n)** -- the same as standard binary search; half the candidates are eliminated each step.

**Space O(1)** -- only a few variables.

**The key point: it is not fully sorted, and we can still use binary search!** That is the power of "locally sorted."

## Variation: Find the Minimum in a Rotated Array

**Task**: find the minimum element in a rotated sorted array.

```python
nums = [4, 5, 6, 7, 1, 2, 3]
# The minimum is 1, at index 4
```

**Idea**: the minimum is the "break point" -- the element that is smaller than its left neighbor.

```python
def find_min(nums):
    left, right = 0, len(nums) - 1
    while left < right:
        mid = (left + right) // 2
        if nums[mid] > nums[right]:
            # mid is in the larger left half, minimum is to the right
            left = mid + 1
        else:
            # mid is in the smaller right half, minimum is at mid or to its left
            right = mid
    return nums[left]

print(find_min([4, 5, 6, 7, 1, 2, 3]))   # 1
print(find_min([3, 1, 2]))                # 1
print(find_min([1, 2, 3, 4, 5]))          # 1 (not rotated)
```

**Trace by hand** on `[4, 5, 6, 7, 1, 2, 3]`:

```
left=0, right=6, mid=3, nums[3]=7, nums[right]=3
7 > 3 -> mid is in the left half, minimum is to the right -> left=4

left=4, right=6, mid=5, nums[5]=2, nums[right]=3
2 <= 3 -> mid is in the right half, minimum is at mid or left -> right=5

left=4, right=5, mid=4, nums[4]=1, nums[right]=2
1 <= 2 -> right=4

left=4, right=4 -> done, return nums[4]=1 ✓
```

## # WRONG -- The "Half-Sorted" Crash Scene

The classic blunder: treating a rotated array as if it were fully sorted.

```python
# WRONG -- rotated arrays are NOT fully sorted
def search_buggy(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

# nums=[4,5,6,7,1,2,3], target=2
# mid=3, nums[3]=7 > 2 -> right=2
# but 2 is in the right half, which we just eliminated!
```

**Why it crashes the answer**: ordinary binary search needs `nums[left] <= nums[right]` -- the whole interval sorted -- so that "target is smaller than mid" really means "target is to the left." In a rotated array that invariant is broken, so the two halves are no longer interchangeable. `7 > 2` only proves the target is not at index 3; it says nothing about which side still contains it.

You must first figure out which half is sorted:

```python
# FIXED
if nums[left] <= nums[mid]:        # left half is sorted
    if nums[left] <= target < nums[mid]:
        right = mid - 1           # target is in the left half
    else:
        left = mid + 1            # target must be in the right half
else:                             # right half is sorted
    if nums[mid] < target <= nums[right]:
        left = mid + 1            # target is in the right half
    else:
        right = mid - 1           # target must be in the left half
```

**The rule**: before using the `target < nums[mid]` shortcut, prove the half you are about to trust is sorted. If you cannot prove it, test the other half instead.

## Common Mistakes

### Mistake 1: using standard binary search directly

```python
# Wrong: a rotated array is not fully sorted
def search_buggy(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

# nums=[4,5,6,7,1,2,3], target=2
# mid=3, nums[3]=7 > 2 -> right=2
# but 2 is in the right half, wrongly eliminated!
```

**A rotated array cannot use standard binary search directly; you must first decide which half is sorted.**

### Mistake 2: missing the `=` in `nums[left] <= nums[mid]`

```python
# Wrong: missing the =
if nums[left] < nums[mid]:     # should be <=
    ...
```

**When `nums[left] == nums[mid]` (for example, a single element or all elements equal), the left half should be treated as sorted.** Missing the `=` skips cases.

### Mistake 3: wrong comparison operators in the range check

```python
# Wrong: should be <= target < nums[mid]
if nums[left] < target < nums[mid]:    # missing the equals
    ...
```

**target may equal `nums[left]`, so the equals must be included.**

## The Essence of This Problem

**The core trick of rotated-array binary search**: it is not "the whole array must be sorted to binary-search"; it is "**if any part is sorted, we can use binary search to shrink the range**."

This idea generalizes to many variations:

- The peak in a mountain array (L33 search)
- Searching in a sorted matrix
- Searching in a partially sorted array

## Summary

- Rotated array: not sorted overall, but **at least one half is sorted**
- Algorithm: decide which half is sorted -> check whether target is in range in that half -> shrink
- Find minimum: compare `nums[mid]` with `nums[right]` to decide which half
- Time O(log n), space O(1)
- Essence: **local sortedness is enough for binary search**
