# One-Dimensional Prefix Sums: Construction, Query, and the Leading Zero

> Last lesson we learned that prefix sums can accelerate range queries. This lesson fills in every detail: **how to construct, how to query, and how to handle boundaries.**

## The Full Construction Process

**Given an array `nums`, build the prefix sum array `prefix`:**

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]
```

**Construction formula**: `prefix[i+1] = prefix[i] + nums[i]`, with initial value `prefix[0] = 0`

```python
def build_prefix(nums):
    n = len(nums)
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]
    return prefix

prefix = build_prefix([3, 1, 4, 1, 5, 9, 2, 6])
print(prefix)
# [0, 3, 4, 8, 9, 14, 23, 25, 31]
```

**Verify by hand**:

```
prefix[0] = 0
prefix[1] = 0 + 3 = 3
prefix[2] = 3 + 1 = 4
prefix[3] = 4 + 4 = 8
prefix[4] = 8 + 1 = 9
prefix[5] = 9 + 5 = 14
prefix[6] = 14 + 9 = 23
prefix[7] = 23 + 2 = 25
prefix[8] = 25 + 6 = 31
```

**Pattern**: `prefix[i]` is exactly the sum of `nums[0..i-1]`.

## Deriving the Query Formula

**Goal**: Find the sum of `nums[l..r]` (closed interval, inclusive of both l and r).

```
prefix[r+1] = nums[0] + nums[1] + ... + nums[l-1] + nums[l] + ... + nums[r]
prefix[l]   = nums[0] + nums[1] + ... + nums[l-1]
```

Subtracting the two:

```
prefix[r+1] - prefix[l] = nums[l] + nums[l+1] + ... + nums[r]
```

**This is exactly the sum of interval [l, r].**

```python
def query_sum(prefix, l, r):
    return prefix[r + 1] - prefix[l]

prefix = [0, 3, 4, 8, 9, 14, 23, 25, 31]
print(query_sum(prefix, 2, 5))   # 4+1+5+9 = 19 -> prefix[6]-prefix[2] = 23-4 = 19 ✓
print(query_sum(prefix, 0, 0))   # 3 -> prefix[1]-prefix[0] = 3-0 = 3 ✓
print(query_sum(prefix, 7, 7))   # 6 -> prefix[8]-prefix[7] = 31-25 = 6 ✓
```

## Complete Boundary Case Analysis

### Case 1: l == 0

```python
query_sum(prefix, 0, 3) = prefix[4] - prefix[0] = 9 - 0 = 9
# nums[0..3] = 3+1+4+1 = 9 ✓
```

`prefix[0] = 0` guarantees correctness.

### Case 2: l == r (single-element interval)

```python
query_sum(prefix, 5, 5) = prefix[6] - prefix[5] = 23 - 14 = 9
# nums[5] = 9 ✓
```

### Case 3: l == 0 and r == n-1 (the whole array)

```python
query_sum(prefix, 0, n-1) = prefix[n] - prefix[0] = prefix[n] - 0
# This is the sum of all elements ✓
```

**This is exactly why prefix must have length n+1** — there must be room for `prefix[n]`.

## Common Mistakes

### Mistake 1: Allocating prefix with length n instead of n+1

```python
# WRONG: not enough space
def build_prefix_buggy(nums):
    n = len(nums)
    prefix = [0] * n          # should be n+1!
    for i in range(n):
        prefix[i + 1] = prefix[i] + nums[i]   # when i=n-1, prefix[n] is out of range!
    return prefix
```

**IndexError: list assignment index out of range** — when `i=n-1`, `prefix[i+1]` accesses `prefix[n]`, but the array only has `n` elements (indices 0..n-1).

### Mistake 2: Writing the query as prefix[r] - prefix[l-1]

This is an alternative style (common in competitive programming), but it easily accesses `prefix[-1]` when `l=0`.

```python
# Alternative style: prefix indices start at 1
prefix = [0] + [0]*n
for i in range(n):
    prefix[i+1] = prefix[i] + nums[i]
# Query [l, r] = prefix[r] - prefix[l-1]
# When l=0, this accesses prefix[-1], which is the LAST element! WRONG!
```

**If you insist on writing `prefix[r] - prefix[l-1]`, you must handle l==0 as a special case:**

```python
def query_sum_v2(prefix, l, r):
    left_val = prefix[l - 1] if l > 0 else 0
    return prefix[r] - left_val
```

**Recommended style: `prefix[r+1] - prefix[l]` — naturally handles l==0 with no special case.**

### Mistake 3: Forgetting to initialize prefix[0] = 0

```python
prefix = [0] * (n + 1)   # all zeros, OK
# Or equivalently:
prefix = [0] + [0]*n     # also all zeros, OK
# Or even:
prefix = []              # empty list
prefix.append(0)         # OK, prefix[0]=0
for i in range(n):
    prefix.append(prefix[-1] + nums[i])   # this works too!
```

All three styles are valid, as long as `prefix[0]=0` is guaranteed.

## Advanced Applications

### 1. Prefix Sum + Hash Map: Count Subarrays with Sum K

**Problem**: Count how many subarrays have a sum equal to k.

Idea: use a hash map to record "how many times each prefix sum has appeared." If `prefix[j] - prefix[i] = k`, then `nums[i..j-1]` sums to k.

```python
def subarray_sum(nums, k):
    from collections import defaultdict
    cnt = defaultdict(int)
    cnt[0] = 1          # empty prefix has sum 0
    prefix = 0
    ans = 0
    for x in nums:
        prefix += x
        ans += cnt[prefix - k]   # how many earlier prefix sums equal prefix-k
        cnt[prefix] += 1
    return ans

print(subarray_sum([1, 1, 1], 2))   # 2: subarrays [1,1] at indices 0-1 and [1,1] at indices 1-2
```

### 2. Prefix Sum for Divisibility Testing

If `prefix[j] % k == prefix[i] % k`, then the sum of `nums[i..j-1]` is divisible by k.

## Complexity Confirmation

| Operation | Complexity | Notes |
|---|---|---|
| Build prefix sum | O(n) | One pass |
| Single query | O(1) | Two array accesses + one subtraction |
| Space | O(n) | One extra array |

**When the number of queries m is much larger than n, prefix sums are the only reasonable choice.**

## A Crash Site: Querying with Wrong Index Style

Mixing the two styles is a classic trap. Suppose you build with the recommended style but query with the alternative:

```python
# WRONG - mixing index conventions
nums = [3, 1, 4, 1, 5]
prefix = [0, 3, 4, 8, 9, 14]   # length 6, prefix[0]=0 (recommended style)

# Tries to use the "prefix[r] - prefix[l-1]" formula on a 0-indexed prefix array
print(prefix[3] - prefix[1 - 1])   # 8 - 0 = 8
# Expected: sum of nums[1..3] = 1+4+1 = 6
# Got: 8 -- WRONG! That is the sum of nums[0..2] = 3+1+4
```

The output is 8 instead of 6. Why? Because `prefix[r] - prefix[l-1]` assumes the array is 1-indexed, but our `prefix` is 0-indexed (with a leading zero). In the recommended convention, the query must be `prefix[r+1] - prefix[l]`. Pick one convention and **stick with it**.

## Summary

- `prefix[i]` = sum of `nums[0..i-1]`, `prefix[0] = 0`
- Construction: `prefix[i+1] = prefix[i] + nums[i]`, length n+1
- Query [l, r]: `prefix[r+1] - prefix[l]`, O(1)
- **The `prefix[r+1]-prefix[l]` style is recommended** — it naturally handles l==0
- Advanced: prefix sum + hash map solves "subarray sum equals k"
