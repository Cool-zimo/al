# Longest Palindromic Substring: From Brute Force to Center Expansion

> In the previous lesson we saw that center expansion is the right tool for one job: **finding the longest palindromic substring**. This lesson derives the algorithm step by step.

## The Problem

**Given a string `s`, find the longest substring that is a palindrome.**

```python
s = "babad"
# "bab" is a palindrome (so is "aba"); either is a valid answer

s = "cbbd"
# "bb" is the longest palindromic substring

s = "racecar"
# the whole string is a palindrome, so "racecar" is the answer
```

**A substring is any contiguous segment of the original string** — you cannot rearrange the characters.

## Attempt 1: Brute Force

**Idea**: try every possible substring, check whether it is a palindrome, and keep the longest one.

```python
def longest_palindrome_brute(s):
    n = len(s)
    best = ""
    for i in range(n):                # start index
        for j in range(i, n):         # end index
            sub = s[i:j+1]
            if sub == sub[::-1]:      # palindrome check
                if len(sub) > len(best):
                    best = sub
    return best
```

**How slow is this?**

- Number of substrings: **O(n²)**
- Checking each one with `== sub[::-1]`: **O(n)** per check
- Total: **O(n³)** time

**That is too slow for any reasonably long string.** We can do better.

## Attempt 2: Improve the Check to O(1)

**Observation**: if you already know that `s[i+1:j]` is a palindrome, then `s[i:j+1]` is a palindrome **if and only if** `s[i] == s[j]`.

```python
def longest_palindrome_dp(s):
    n = len(s)
    if n == 0:
        return ""
    
    # dp[i][j] = True if s[i:j+1] is a palindrome
    dp = [[False] * n for _ in range(n)]
    start, max_len = 0, 1
    
    # length 1 palindromes
    for i in range(n):
        dp[i][i] = True
    
    # length 2 palindromes
    for i in range(n - 1):
        if s[i] == s[i + 1]:
            dp[i][i + 1] = True
            start, max_len = i, 2
    
    # length 3 and up
    for length in range(3, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            if s[i] == s[j] and dp[i + 1][j - 1]:
                dp[i][j] = True
                if length > max_len:
                    start, max_len = i, length
    
    return s[start:start + max_len]
```

**Complexity**: **O(n²)** time and **O(n²)** space. Better than O(n³), but can we drop the space?

## Attempt 3: Center Expansion — O(n²) Time, O(1) Space

**Key insight**: every palindrome has a **center**. From that center you can expand outward as long as the characters match.

- Odd-length palindromes (`"racecar"`) have a center character
- Even-length palindromes (`"abba"`) have a center **between** two characters

```python
def longest_palindrome(s):
    if not s:
        return ""
    
    def expand(left, right):
        # expand while both ends match
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        # when the loop stops, s[left:right+1] is no longer a palindrome
        # the actual palindrome is s[left+1:right]
        return right - left - 1
    
    start, max_len = 0, 1
    for i in range(len(s)):
        # odd length: center at i
        len_odd = expand(i, i)
        # even length: center between i and i+1
        len_even = expand(i, i + 1)
        
        curr = max(len_odd, len_even)
        if curr > max_len:
            max_len = curr
            # for a palindrome of length L centered at i, it starts at i - (L-1)/2
            start = i - (curr - 1) // 2
    
    return s[start:start + max_len]
```

**Walking through** `s = "babad"`, `i = 1` (the `'a'`):

```
odd expansion from center i=1:
  left=1, right=1  -> 'a'==='a', expand: left=0, right=2
  s[0]='b', s[2]='b' -> match, expand: left=-1, right=3
  left < 0, stop
  length = 3 - (-1) - 1 = 3  -> palindrome "bab"

even expansion from between i=1 and i=2:
  left=1, right=2 -> s[1]='a', s[2]='b' -> no match
  length = 0
```

**So at `i=1` the best we found is `"bab"` of length 3.**

## Complexity Analysis

**For each of the n centers, we expand at most n/2 steps.**

- Time: **O(n²)** (n centers × up to n expansions each)
- Space: **O(1)** (only a handful of variables)

| Approach | Time | Space |
|---|---|---|
| Brute force (every substring + reverse check) | O(n³) | O(1) |
| Dynamic programming | O(n²) | O(n²) |
| Center expansion | O(n²) | O(1) |

**Center expansion is the sweet spot: the best time among the linear-space options, with the simplest code.**

## Common Mistakes

### Mistake 1: Only handling odd-length palindromes

```python
# WRONG: only expands from a single character
for i in range(n):
    length = expand(i, i)    # misses "abba", "bb", "noon", etc.
```

**You must also expand from between characters** to catch even-length palindromes.

### Mistake 2: Off-by-one when computing the start index

```python
# WRONG
start = i - max_len // 2    # fails for odd lengths

# RIGHT
start = i - (max_len - 1) // 2
```

**For length 3 centered at `i`, `(3-1)//2 = 1`, so `start = i - 1`. For length 4, `(4-1)//2 = 1`, so `start = i - 1` as well — which is correct for an even-length palindrome.**

### Mistake 3: Returning the wrong slice

```python
# WRONG
return s[left:right]    # these are the indices where expansion STOPPED

# RIGHT
return s[start:start + max_len]
```

**`left` and `right` are the indices where the expansion failed. The actual palindrome ends at `right-1`.**

## # WRONG — When the Expansion Stops

**The single most common bug is misreading what `left` and `right` mean after `expand` returns:**

```python
# WRONG
def longest_palindrome_buggy(s):
    def expand(left, right):
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        return left, right    # returns the indices where it STOPPED

    best = ""
    for i in range(len(s)):
        l1, r1 = expand(i, i)
        l2, r2 = expand(i, i + 1)
        # trying to slice with the stopped indices
        cand = s[l1:r1 + 1]      # r1 was already past the end!
        if len(cand) > len(best):
            best = cand
    return best

print(longest_palindrome_buggy("babad"))
# actual output: "babad"  <- way too long, not even a palindrome!
```

**What went wrong?** When `expand` stops, `left` has been decremented one step **past** the palindrome's left edge and `right` has been incremented one step **past** its right edge. Slicing `s[l1:r1+1]` therefore includes characters that are not part of the palindrome at all — and for `"babad"` it happily returns the whole 5-character string, which is not a palindrome.

The correct version returns the **length** from `expand`, then derives the start index with integer arithmetic:

```python
# RIGHT
def longest_palindrome(s):
    if not s:
        return ""
    def expand(left, right):
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        return right - left - 1     # length of the palindrome
    start, max_len = 0, 1
    for i in range(len(s)):
        odd = expand(i, i)
        even = expand(i, i + 1)
        curr = max(odd, even)
        if curr > max_len:
            max_len = curr
            start = i - (curr - 1) // 2
    return s[start:start + max_len]

print(longest_palindrome("babad"))   # "bab"
print(longest_palindrome("cbbd"))    # "bb"
```

**Spot the difference**: return the length, not the indices, and compute `start` once per center using `(curr - 1) // 2`. That single expression works for both odd and even lengths.

## Putting It All Together

**The full algorithm in one place:**

```python
def longest_palindrome(s):
    if not s:
        return ""
    
    def expand(left, right):
        while left >= 0 and right < len(s) and s[left] == s[right]:
            left -= 1
            right += 1
        return right - left - 1
    
    start, max_len = 0, 1
    for i in range(len(s)):
        len_odd = expand(i, i)
        len_even = expand(i, i + 1)
        curr = max(len_odd, len_even)
        if curr > max_len:
            max_len = curr
            start = i - (curr - 1) // 2
    
    return s[start:start + max_len]

# examples
print(longest_palindrome("babad"))         # "bab" (or "aba")
print(longest_palindrome("cbbd"))          # "bb"
print(longest_palindrome("racecar"))       # "racecar"
print(longest_palindrome("a"))             # "a"
print(longest_palindrome("ac"))            # "a" (or "c")
```

## Summary

- Brute force is O(n³) — try every substring and reverse-check it
- DP brings it to O(n²) time but still O(n²) space
- Center expansion: O(n²) time, **O(1)** space — the best practical choice
- Expand from each character (odd) **and** from between characters (even)
- Return the length from `expand`; compute the start as `i - (length-1)//2`
