# What Is a Window: When to Use Sliding Window

> Brute force enumerates all subarrays in O(n²); a sliding window crushes it to O(n). This lesson clarifies **when to reach for a window, when not to**, and how it relates to two pointers.

## What Is a "Window"

A window is a **contiguous segment** of an array, marked by two pointers `left` and `right`. For example, in `[3, 1, 4, 1, 5, 9]`, `left=1, right=3` represents the subarray `[1, 4, 1]`.

```python
nums = [3, 1, 4, 1, 5, 9]
left = 1
right = 3
window = nums[left:right + 1]
print(window)  # [1, 4, 1]
```

The key distinction: **a window emphasizes aggregate information across the interval** (sum, maximum, frequency counts), not just two individual elements.

## When to Use a Sliding Window

Two conditions must hold:

1. **The answer is a contiguous interval** (subarray or substring), not an arbitrary selection of elements
2. **The interval information can be updated incrementally** — adding/removing one element costs O(1)

| Scenario | Window? | Why |
|---|---|---|
| Max sum subarray | ✅ | Add/remove one element: O(1) |
| Longest substring without repeats | ✅ | Set tracks membership |
| Subarray sum equals k | ✅ | Pair with prefix sums or hash map |
| Pick two elements for max sum | ❌ | Not contiguous |
| Three sum | ❌ | Needs three arbitrary positions |

## Fixed vs. Variable Windows

**Fixed window**: length stays k. On each slide, remove the leftmost, add the rightmost.

```python
nums = [2, 1, 5, 6, 3, 4]
k = 3

# Initial window sum
window_sum = sum(nums[:k])
max_sum = window_sum
print(f"Window [0:{k}] = {nums[:k]}, sum = {window_sum}")

# Slide right
for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_sum = max(max_sum, window_sum)
    print(f"Window [{i-k+1}:{i+1}] = {nums[i-k+1:i+1]}, sum = {window_sum}")

print(f"Max sum = {max_sum}")
# Window [0:3] = [2, 1, 5], sum = 8
# Window [1:4] = [1, 5, 6], sum = 12
# Window [2:5] = [5, 6, 3], sum = 14
# Window [3:6] = [6, 3, 4], sum = 13
# Max sum = 14
```

`window_sum - nums[i-k] + nums[i]` is the core: **drop the old value, add the new one**. Each window sum is O(1), total O(n).

## Variable Window: Expand Right, Shrink Left

A fixed window never changes length. A variable window **dynamically decides when to shrink** based on a condition. The classic example is "longest substring without repeating characters" — covered in Lesson 28. Here's the skeleton:

```python
s = "abcabcbb"
char_set = set()
left = 0
max_len = 0

for right in range(len(s)):
    # If the new char is already in the window, shrink left
    while s[right] in char_set:
        char_set.remove(s[left])
        left += 1
    # Add the new char
    char_set.add(s[right])
    # Update answer
    max_len = max(max_len, right - left + 1)

print(max_len)  # 3
```

**Core pattern**: `right` expands relentlessly; `left` only moves when "the window is invalid." Both pointers are non-decreasing, so they traverse at most 2n steps total → O(n).

## Crash Scene 1: Forgetting to Subtract the Left Element

The most common beginner mistake with fixed windows is **only adding, never subtracting**:

```python
nums = [2, 1, 5, 6, 3]
k = 3

window_sum = sum(nums[:k])  # 8
max_sum = window_sum

for i in range(k, len(nums)):
    window_sum = window_sum + nums[i]  # WRONG! Only adds right, never subtracts left
    max_sum = max(max_sum, window_sum)

print(max_sum)
```

Output:

```
# Wrong output: 17
# Actual trace: 8 → 8+6=14 → 14+3=17
# Correct trace: 8 → 8-2+6=12 → 12-1+3=14
```

**Why it fails**: `window_sum` no longer represents a window of size k. At i=3 it has mutated into `[2, 1, 5, 6]` — already length 4.

The fix is `window_sum = window_sum - nums[i-k] + nums[i]`, **keeping exactly k elements** in the window at all times.

## Crash Scene 2: Treating a Window as Just "Two Pointers"

Many confuse "window" with "two pointers," but they differ fundamentally:

| | Two Pointers | Sliding Window |
|---|---|---|
| Pointer movement | Each moves independently based on logic | Right expands; left shrinks conditionally |
| Focus | Relationship between two elements | Entire interval **between** pointers |
| Typical problem | Two sum, three sum | Max subarray sum, min covering substring |
| Need interval state? | Usually no | Almost always (sum, set, counter) |

```python
# Two pointers: find two numbers that sum to target
nums = [1, 2, 3, 4, 5]
target = 6
left, right = 0, len(nums) - 1
while left < right:
    s = nums[left] + nums[right]
    if s == target:
        print(f"Found: {nums[left]} + {nums[right]}")
        break
    elif s < target:
        left += 1
    else:
        right -= 1

# Sliding window: max sum of subarray of size k
nums = [1, 2, 3, 4, 5]
k = 3
window_sum = sum(nums[:k])
max_sum = window_sum
for i in range(k, len(nums)):
    window_sum = window_sum - nums[i - k] + nums[i]
    max_sum = max(max_sum, window_sum)
print(f"Max sum: {max_sum}")
```

Two pointers' left/right **collaborate to find an answer**. A sliding window's left/right **frame an interval**.

## Crash Scene 3: Variable Window Only Expands

The classic bug when writing a variable window: forgetting to shrink the left boundary.

```python
s = "abcabcbb"
seen = set()
max_len = 0

for right in range(len(s)):
    seen.add(s[right])  # Only add, never remove!
    max_len = max(max_len, len(seen))

print(max_len)  # Wrong output: 8 (entire string length)
# Correct answer: 3 ("abc")
```

**What went wrong**: `seen` is monotonic — it records "which characters appear anywhere in the string," not "which characters are in the current window." The right boundary moves, but left stays at 0. That's not a window.

## Pairing Windows with Prefix Sums

Windows aren't an isolated trick. A fixed window max sum can also be done with prefix sums:

```python
# Prefix sum + window
nums = [2, 1, 5, 6, 3, 4]

# Build prefix sum array
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)

print(prefix)  # [0, 2, 3, 8, 14, 17, 21]

# Sum of interval [i, j] = prefix[j+1] - prefix[i]
k = 3
max_sum = 0
for i in range(len(nums) - k + 1):
    s = prefix[i + k] - prefix[i]
    max_sum = max(max_sum, s)

print(max_sum)  # 14
```

Both approaches yield the same result, but **a pure sliding window is more space-efficient** (no extra O(n) array). Prefix sums shine when you need **many different window lengths**, while sliding windows excel at stepping one position at a time.

## Summary

- A sliding window = `left` and `right` framing a contiguous interval, maintaining aggregate info
- **Fixed window**: length invariant; on each slide, "drop left, add right" → O(n)
- **Variable window**: right expands, left shrinks conditionally; both non-decreasing → O(n)
- Window ≠ two pointers: a window focuses on **the interval between pointers**
- Typical use: subarray/substring min/max, shortest/longest interval satisfying a condition
