# 2D Prefix Sums: Submatrix Sums and the Inclusion-Exclusion Principle

> 1D prefix sums handle interval sums. This lesson scales it up to two dimensions: **submatrix sums** — using inclusion-exclusion to answer in one shot.

## Problem Definition

**You are given a matrix `matrix`, and you must repeatedly answer "what is the sum of the submatrix from top-left (r1, c1) to bottom-right (r2, c2)?"**

```python
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]
# Query the submatrix from (0,0) to (1,1):
# 1 + 2 + 4 + 5 = 12
```

The naive approach: nested loops, O(mn) per query. With a 2D prefix sum, each query is O(1).

## The 2D Prefix Sum Array

**Definition**: `prefix[i][j]` stores the sum of the rectangle with **top-left at (0,0) and bottom-right at (i-1, j-1)**.

In other words: `prefix[i][j]` = the sum of all elements in rows 0..i-1 and columns 0..j-1.

**Just like 1D, we add an extra ring of leading zeros.**

## Construction: The Recurrence Formula

**Core formula** (inclusion-exclusion):

```
prefix[i][j] = prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1] + matrix[i-1][j-1]
```

**Why subtract `prefix[i-1][j-1]`?** Because `prefix[i-1][j]` and `prefix[i][j-1]` both include the top-left region, so it gets counted twice. We must subtract it once.

```python
def build_prefix_2d(matrix):
    m = len(matrix)
    n = len(matrix[0]) if m > 0 else 0
    prefix = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            prefix[i][j] = (prefix[i - 1][j]
                          + prefix[i][j - 1]
                          - prefix[i - 1][j - 1]
                          + matrix[i - 1][j - 1])
    return prefix

matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]
prefix = build_prefix_2d(matrix)
for row in prefix:
    print(row)
# [0, 0, 0, 0]
# [0, 1, 3, 6]
# [0, 5, 12, 21]
# [0, 12, 27, 45]
```

**Let's verify a few by hand**:

```
prefix[1][1] = prefix[0][1] + prefix[1][0] - prefix[0][0] + matrix[0][0]
            = 0 + 0 - 0 + 1 = 1 ✓

prefix[1][2] = prefix[0][2] + prefix[1][1] - prefix[0][1] + matrix[0][1]
            = 0 + 1 - 0 + 2 = 3 ✓

prefix[2][1] = prefix[1][1] + prefix[2][0] - prefix[1][0] + matrix[1][0]
            = 1 + 0 - 0 + 4 = 5 ✓

prefix[2][2] = prefix[1][2] + prefix[2][1] - prefix[1][1] + matrix[1][1]
            = 3 + 5 - 1 + 5 = 12 ✓
# (0,0) to (1,1): 1+2+4+5 = 12 ✓

prefix[2][3] = prefix[1][3] + prefix[2][2] - prefix[1][2] + matrix[1][2]
            = 6 + 12 - 3 + 6 = 21 ✓

prefix[3][3] = prefix[2][3] + prefix[3][2] - prefix[2][2] + matrix[2][2]
            = 21 + 27 - 12 + 9 = 45 ✓
# total sum = 1+2+3+4+5+6+7+8+9 = 45 ✓
```

So the correct result is:

```
[0, 0,  0,  0]
[0, 1,  3,  6]
[0, 5, 12, 21]
[0, 12, 27, 45]
```

## Query: Submatrix Sum

**To query the submatrix from (r1, c1) to (r2, c2)**:

```
ans = prefix[r2+1][c2+1]
    - prefix[r1][c2+1]
    - prefix[r2+1][c1]
    + prefix[r1][c1]
```

**Inclusion-exclusion**: subtract the top overflow + subtract the left overflow + add back the corner that was subtracted twice.

```python
def query_2d(prefix, r1, c1, r2, c2):
    return (prefix[r2 + 1][c2 + 1]
          - prefix[r1][c2 + 1]
          - prefix[r2 + 1][c1]
          + prefix[r1][c1])

prefix = build_prefix_2d(matrix)
print(query_2d(prefix, 0, 0, 1, 1))   # 1+2+4+5 = 12 ✓
print(query_2d(prefix, 1, 1, 2, 2))   # 5+6+8+9 = 28 ✓
print(query_2d(prefix, 0, 0, 2, 2))   # everything = 45 ✓
```

## Visualizing Inclusion-Exclusion

Query (1, 1) to (2, 2), i.e. elements [5, 6, 8, 9]:

```
The full prefix[3][3] = 45 (all elements)
We need to subtract:
  - prefix[1][3] = 6  (row 0: 1, 2, 3)
  - prefix[3][1] = 12 (column 0: 1, 4, 7)
But element (0,0) = 1 was subtracted twice, so add it back:
  + prefix[1][1] = 1

45 - 6 - 12 + 1 = 28 ✓
```

## Complexity

| Operation | Complexity |
|---|---|
| Construction | O(mn) |
| Query | O(1) |
| Space | O(mn) |

**For an m-by-n matrix, any submatrix query is O(1).**

## Common Mistakes

### Mistake 1: Getting the index offset wrong

`prefix[i][j]` corresponds to `matrix[i-1][j-1]`, **not** `matrix[i][j]`.

```python
# WRONG: no index offset
prefix[i][j] = prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1] + matrix[i][j]
# matrix[i][j] will go out of bounds (when i=m or j=n)
```

**Remember**: prefix has one extra row and one extra column, so always subtract 1 when accessing matrix.

### Mistake 2: Getting the sign wrong in the query formula

```python
# WRONG: the last term should be + not -
return prefix[r2+1][c2+1] - prefix[r1][c2+1] - prefix[r2+1][c1] - prefix[r1][c1]
# should be + prefix[r1][c1]
```

**Draw a picture and it is hard to get wrong**: the top-left corner was subtracted twice, so add it back once.

### Mistake 3: Handling an empty matrix

```python
def build_prefix_2d(matrix):
    m = len(matrix)
    n = len(matrix[0]) if m > 0 else 0   # empty matrix -> n=0
    prefix = [[0] * (n + 1) for _ in range(m + 1)]
    ...
```

**You must check `m > 0`**, otherwise `matrix[0]` raises an IndexError.

## What 2D Prefix Sums Can Do

| Problem | Prefix Sum? |
|---|---|
| Submatrix sum | ✅ |
| Submatrix maximum | ❌ |
| Counting elements in a submatrix | ✅ |
| Submatrix XOR sum | ✅ |

**Any operation that satisfies "additivity" works with prefix sums.**

## A Crash Site: Off-by-One in 2D Indexing

The most treacherous bug in 2D prefix sums is confusing `prefix` indices with `matrix` indices:

```python
# WRONG - using matrix indices directly in the prefix array
def query_2d_buggy(prefix, r1, c1, r2, c2):
    # This treats prefix as if it were 0-indexed like matrix
    return prefix[r2][c2] - prefix[r1-1][c2] - prefix[r2][c1-1] + prefix[r1-1][c1-1]

prefix = build_prefix_2d([[1, 2, 3], [4, 5, 6], [7, 8, 9]])
print(query_2d_buggy(prefix, 0, 0, 1, 1))
# prefix[1][1] - prefix[-1][1] - prefix[1][-1] + prefix[-1][-1]
# = 1 - 0 - 0 + 9 = 10  ✗  (expected 12!)
```

Python's negative indices wrap around, so `prefix[-1][-1]` gives 45 — the bottom-right corner of the prefix array. The result 10 is nonsense. The correct query always uses `r2+1`, `c2+1`, and never produces a negative index.

## Summary

- 2D prefix sum: `prefix[i][j]` is the sum from (0,0) to (i-1, j-1)
- Construction uses inclusion-exclusion: `pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + mat[i-1][j-1]`
- Query also uses inclusion-exclusion: four add/subtract steps
- **Keep an extra ring of zeros**, and subtract 1 when accessing matrix
- Construction O(mn), query O(1)
