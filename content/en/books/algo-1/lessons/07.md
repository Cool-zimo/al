# Collision Pointers: Reversing Arrays and Testing Palindromes

> Once two pointers can search, they can also **swap**. That is all reversing really is.

## The simplest use: reverse in place

```python
arr = [1, 2, 3, 4, 5]
left, right = 0, len(arr) - 1
while left < right:
    arr[left], arr[right] = arr[right], arr[left]
    left += 1
    right -= 1
print(arr)      # [5, 4, 3, 2, 1]
```

**No new list is created.** The same five slots get their contents swapped. Memory cost: O(1).

Contrast with the one-liner everyone reaches for first:

```python
arr = [1, 2, 3, 4, 5]
print(arr[::-1])     # [5, 4, 3, 2, 1]
print(arr)           # [1, 2, 3, 4, 5]  <- original untouched
```

`[::-1]` **builds a new list**. If the problem says "in place" or "O(1) extra space", the slice is not acceptable — even though it looks cleaner.

## Simultaneous assignment is not optional

The swap line looks like it could be written the long way:

```python
# WRONG
arr[left] = arr[right]
arr[right] = arr[left]      # arr[left] has already been overwritten!
```

```python
arr = [1, 2, 3]
left, right = 0, 2
arr[left] = arr[right]      # arr -> [3, 2, 3]
arr[right] = arr[left]      # arr -> [3, 2, 3]   <- nothing swapped, 1 is gone
```

The original `arr[left]` is destroyed on the first line. Python's tuple assignment evaluates the **right-hand side first**, so `arr[left], arr[right] = arr[right], arr[left]` is safe:

```python
arr = [1, 2, 3]
arr[0], arr[2] = arr[2], arr[0]
print(arr)      # [3, 2, 1]
```

## How many swaps?

For 5 elements: `left` goes 0, 1, 2 and `right` goes 4, 3, 2. The loop stops at `left < right`, so the middle element (index 2) is never touched:

```
[1, 2, 3, 4, 5]
 ^           ^     swap -> [5, 2, 3, 4, 1]
    ^     ^        swap -> [5, 4, 3, 2, 1]
       ^           left == right, stop
```

**Two swaps for five elements** — `n // 2`. The middle one is already where it belongs.

For an even count there is no middle:

```python
arr = [1, 2, 3, 4]
left, right = 0, 3
n = 0
while left < right:
    arr[left], arr[right] = arr[right], arr[left]
    left += 1; right -= 1; n += 1
print(arr, n)      # [4, 3, 2, 1] 2
```

## The `<=` question, again

For **reversing**, `left <= right` is harmless:

```python
arr = [1, 2, 3]
left, right = 0, 2
while left <= right:
    arr[left], arr[right] = arr[right], arr[left]
    left += 1; right -= 1
print(arr)      # [3, 2, 1]  <- still correct
```

When `left == right` you swap an element with itself — a no-op. So reversing tolerates `<=`.

For **palindrome checking** it is a different story. Consider `[1,2,3,2,1]` with `left <= right`: at `left == right == 2` you compare `nums[2] != nums[2]`, which is `False`, so nothing breaks *here*. But the same habit applied to `[1,2,2,3]` style inputs where the centre matters, or to "find a pair" problems, produces real bugs.

**Just use `left < right` everywhere.** There is no case where `<=` is required, and one fewer thing to think about.

## Palindromes

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1
    while left < right:
        if s[left] != s[right]:
            return False
        left += 1
        right -= 1
    return True

print(is_palindrome("level"))     # True
print(is_palindrome("hello"))     # False
print(is_palindrome("a"))         # True
print(is_palindrome(""))          # True
```

Same skeleton, but instead of swapping you **compare and bail early**. The early `return False` is what makes this fast on average — most non-palindromes die in the first comparison.

### Strings are immutable

You cannot do this:

```python
s = "hello"
s[0], s[4] = s[4], s[0]
```

```
TypeError: 'str' object does not support item assignment
```

To reverse a string manually, go through a list:

```python
def reverse_str(s):
    arr = list(s)
    left, right = 0, len(arr) - 1
    while left < right:
        arr[left], arr[right] = arr[right], arr[left]
        left += 1
        right -= 1
    return "".join(arr)

print(reverse_str("hello"))     # olleh
```

Note the empty string: `len("") == 0`, so `right` starts at `-1` and `left < right` is `0 < -1` → `False`. The loop never runs and `"".join([])` returns `""`. **No special case needed** — but only because you used `left < right`.

## A crash site: reversing a slice you forgot to assign

```python
arr = [1, 2, 3]
arr[::-1]          # result thrown away
print(arr)         # [1, 2, 3]
arr = arr[::-1]
print(arr)         # [3, 2, 1]
```

Slices **return** a new object; they never modify in place. This is the single most common "why didn't my code work" in array problems.

## A crash site: mutating while you iterate

```python
# WRONG
arr = [1, 2, 3, 4, 5]
for i, v in enumerate(arr):
    arr[i], arr[len(arr)-1-i] = arr[len(arr)-1-i], arr[i]
print(arr)      # [5, 4, 3, 4, 5]  <- wrong!
```

Once you pass the midpoint you start undoing your own work. This is exactly why the `left < right` guard exists: it **stops at the middle**.

## Where collision pointers apply

| Problem | What the two pointers do |
|---|---|
| Reverse an array | swap, both move inward |
| Palindrome check | compare, bail on mismatch |
| Two-sum on sorted array | compare sum to target, move one |
| Container with most water | compute area, move the shorter side |
| Partition / Dutch flag | swap to push values to the correct side |

The unifying idea: **two positions, one decision per step, both ends moving toward each other.**

## Summary

- Reversing in place: swap `arr[left]` and `arr[right]`, then move both inward
- Use Python's tuple swap — sequential assignment loses data
- `n // 2` swaps; the middle element never moves
- Palindromes compare instead of swapping, and return `False` early
- Strings are immutable → `list(s)` → swap → `"".join(...)`
- Always `left < right`
