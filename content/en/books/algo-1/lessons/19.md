# Binary Search on the Answer: Turning "Find the Optimum" into "Test a Candidate"

> The first two lessons searched over **positions**. This lesson levels up: **binary search on the answer** -- if the answer itself is monotonic, we can binary-search it too.

## The Core Idea

**Many optimization problems have this property:**

- If "the answer is x" works
- Then "the answer is x+1" (a larger answer) must also work

**That is monotonicity! We can binary-search for the threshold.**

Typical scenarios:
- Cutting wood: cut into k pieces, what is the longest each piece can be?
- Sharing chocolate: k people split it, what is the most each can get?
- Minimize the maximum: split an array into m segments, what is the smallest possible maximum segment sum?

## The Wood-Cutting Problem

**Task**: you have n logs with lengths `lengths`. Cut them into k pieces of **equal** length and find the largest possible length for each piece.

```python
lengths = [232, 124, 456, 234]
k = 7
# Can we cut 7 pieces? What is the longest each can be?
# 232 -> 2 pieces of 116
# 124 -> 1 piece of 116 (8 left over)
# 456 -> 3 pieces of 116 (108 left over)
# 234 -> 2 pieces of 116 (2 left over)
# total 2+1+3+2 = 8 pieces >= 7, works!
# Try 117: 232->1(115 left), 124->1(7 left), 456->3(105 left), 234->1(117 left) = 6 < 7, fails
# The answer is 116
```

**Brute force**: try every length from 1 to max(lengths), O(max * n). Far too slow.

**Binary search on the answer**: the answer lives in `[1, max(lengths)]`. For each candidate `mid`, check whether we can cut at least k pieces.

```python
def can_cut(lengths, k, L):
    """With piece length L, can we cut at least k pieces?"""
    count = 0
    for length in lengths:
        count += length // L
    return count >= k

def max_cut_length(lengths, k):
    left, right = 1, max(lengths)
    ans = 0
    while left <= right:
        mid = (left + right) // 2
        if can_cut(lengths, k, mid):
            ans = mid              # works, record it
            left = mid + 1         # try a larger length
        else:
            right = mid - 1        # does not work, try smaller
    return ans

print(max_cut_length([232, 124, 456, 234], 7))   # 116
```

## Why the Answer Is Monotonic

**Key observation:**

- If we can cut 7 pieces at length 100
- Then we can certainly cut **more** pieces at length 50 (at least 7)

**The shorter the piece, the more pieces you get.** That is monotonicity.

```
piece length:  1   50  100  116  117  200
piece count:  10+  8+   7    8    6    4

Find the largest piece length that still yields >= 7 pieces
The answer is 116
```

## The General Template for Binary Search on the Answer

```python
def binary_search_answer(check_func, left, right):
    """
    check_func(x) returns True if the answer x is feasible.
    Find the largest feasible value.
    """
    ans = left    # the smallest possible answer
    while left <= right:
        mid = (left + right) // 2
        if check_func(mid):
            ans = mid           # record it
            left = mid + 1      # look for a larger one
        else:
            right = mid - 1     # look for a smaller one
    return ans
```

**Three ingredients:**

1. **Search range**: the smallest and largest possible answers
2. **Feasibility function**: `check(x)` decides whether answer x is feasible
3. **Monotonicity**: if x works then x-1 also works (or the other way around)

## # WRONG -- The Reversed Predicate Crash Scene

The number-one way binary search on the answer returns nonsense: getting the feasibility test backwards.

```python
# WRONG -- the predicate is reversed
def can_cut_buggy(lengths, k, L):
    count = sum(length // L for length in lengths)
    return count <= k   # wrong! should be >= k

# lengths = [232, 124, 456, 234], k = 7
# can_cut_buggy(..., 116) -> 8 <= 7 -> False
# The search will reject 116 and walk left, returning some tiny length
# even though 116 is the longest valid piece length
```

**Why it crashes the answer**: the question asks for "at least k pieces." A test of `<= k` describes the opposite problem (can we cut *no more than* k pieces?), so the search moves in the wrong direction and converges on the smallest length instead of the largest.

The fix is the comparison direction:

```python
# FIXED
def can_cut(lengths, k, L):
    return sum(length // L for length in lengths) >= k
```

**The rule**: before you write the search loop, state the predicate out loud in English. "We want the largest L such that `can_cut(L)` is True." If your `check` function does not say exactly that, the search will optimize the wrong thing.

## Common Mistakes

### Mistake 1: the check function is logically reversed

```python
def can_cut_buggy(lengths, k, L):
    count = sum(length // L for length in lengths)
    return count <= k   # wrong! should be >= k
```

**We need "at least k pieces," not "at most k pieces."**

### Mistake 2: the initial value of ans

```python
ans = 0    # if nothing is feasible, returning 0 may be meaningless
# Use the minimum value as the initial answer
ans = left
```

**Or handle the "cannot cut anything at all" case explicitly.**

### Mistake 3: wrong search range

```python
left, right = 0, max(lengths)   # left=0 means count = sum(l//0), ZeroDivisionError!
```

**A piece cannot have length 0, so start left at 1.**

## When to Use Binary Search on the Answer

**Test**: can you rewrite the problem as "test feasibility"?

| Original problem | Feasibility version | Monotonic direction |
|---|---|---|
| Longest piece | With piece length L can we get k pieces? | Shorter piece -> more pieces |
| Smallest maximum | With max segment sum M can we split into m segments? | Larger M -> easier to split |
| Fastest completion | At speed V can we finish within time T? | Faster speed -> easier |

**If there is monotonicity, you can binary-search the answer.**

## Summary

- Binary search on the answer: we binary-search **the answer itself**, not an array index
- Three ingredients: search range, feasibility function, monotonicity
- Wood cutting: shorter pieces mean more pieces, find the largest feasible piece length
- `can_cut` is O(n), the binary search is O(log max_len), total O(n log max_len)
- Prerequisite: the answer is monotonic and you can write a feasibility function
