# The Sliding Window, First Steps: Smallest Subarray with a Given Sum

> Slow/fast pointers are "one fast, one slow." This lesson upgrades that idea into a **sliding window**: the two pointers enclose an "interval," which you **expand** and **shrink** based on a condition.

## Start with the cost of brute force

**Problem**: given an array of positive integers and a target value, find the **shortest contiguous subarray whose sum is >= target**, and return its length.

```python
nums = [2, 3, 1, 2, 4, 3]
target = 7
# [4, 3] sums to 7, length 2; [2,3,1,2] sums to 8, length 4
# shortest is [4, 3], return 2
```

**Brute force**: enumerate every start, then enumerate every end.

```python
def min_subarray_brute(nums, target):
    n = len(nums)
    ans = float('inf')
    for i in range(n):              # start
        s = 0
        for j in range(i, n):       # end
            s += nums[j]
            if s >= target:
                ans = min(ans, j - i + 1)
                break               # found the shortest for this start
    return ans if ans != float('inf') else 0

print(min_subarray_brute([2, 3, 1, 2, 4, 3], 7))   # 2
```

**Time O(n²)**. At n = 100,000 this times out.

## The sliding-window idea

The problem with brute force is: **every time the start moves one step right, you sum from scratch**. But the new interval and the old one overlap heavily, so you can reuse that work.

**Sliding window approach**:

- `left`: left boundary of the window
- `right`: right boundary (keeps expanding)
- `window_sum`: sum of the elements currently inside the window

**Two operations**:

1. **Expand**: move `right` right, add `nums[right]` into the window sum
2. **Shrink**: once the window sum >= target, record the length, then move `left` right, subtracting `nums[left]` from the window sum

```python
def min_subarray_len(nums, target):
    n = len(nums)
    left = 0
    window_sum = 0
    ans = float('inf')

    for right in range(n):
        window_sum += nums[right]        # expand: bring in the right edge

        while window_sum >= target:      # condition met, try to shrink
            ans = min(ans, right - left + 1)
            window_sum -= nums[left]     # shrink: drop the left edge
            left += 1

    return ans if ans != float('inf') else 0

print(min_subarray_len([2, 3, 1, 2, 4, 3], 7))   # 2
```

## Why this is O(n)

**Key point**: both `left` and `right` only ever move forward — neither ever steps backward.

- `right` goes from 0 to n-1: at most n steps
- `left` goes from 0 to n-1: at most n steps

**The two pointers take at most 2n steps combined -> O(n).**

Compared with brute force's O(n²), this is a qualitative leap.

## Trace it by hand

`nums = [2, 3, 1, 2, 4, 3]`, `target = 7`:

```
right=0: sum=2, <7, no shrink
right=1: sum=5, <7
right=2: sum=6, <7
right=3: sum=8, >=7 -> ans=min(inf,4)=4, sum-=2, left=1, sum=6
right=4: sum=10, >=7 -> ans=min(4,4)=4, sum-=3, left=2, sum=7
                  sum=7, >=7 -> ans=min(4,3)=3, sum-=1, left=3, sum=6
right=5: sum=9, >=7 -> ans=min(3,3)=3, sum-=2, left=4, sum=7
                 sum=7, >=7 -> ans=min(3,2)=2, sum-=4, left=5, sum=3
done, return 2
```

**How the window changes**:

```
[2, 3, 1, 2]      sum=8  length 4
   [3, 1, 2, 4]   sum=10 length 4 -> [3,1,2,4] shrinks -> [1,2,4] length 3
      [1, 2, 4]   sum=7  length 3 -> shrinks -> [2,4] length 2
         [2, 4, 3] sum=9  length 3 -> shrinks -> [4,3] length 2
            [4, 3] sum=7  length 2 <- shortest
```

Every shrink asks the same question: "if I drop the element on the left, does the condition still hold?" — if yes, the window can be even shorter.

## Three key details

### Detail 1: why `while` and not `if`

When `window_sum >= target`, you may need to shrink **more than once**.

```python
# if you write if, you only shrink once
if window_sum >= target:       # WRONG! there might be room to shrink further
    ...

# you need while, to keep shrinking until the condition breaks
while window_sum >= target:    # correct
    ...
```

**`if` misses the "shrink multiple times" case**, which makes your answer too large.

### Detail 2: initialize with `float('inf')`

Because you want the **minimum**, the starting value must be something **larger than any possible answer**.

```python
ans = float('inf')     # inf is larger than everything, so min will overwrite it
ans = min(ans, length) # the very first update is guaranteed to succeed
```

**Check at the end**: if `ans` was never updated (no valid subarray exists), return 0.

### Detail 3: maintain the sum in a variable; do not recompute it each time

```python
# WRONG: recomputing the sum every time degrades you back to O(n^2)
for right in range(n):
    for left in range(right):      # summing from scratch
        ...
```

**Maintaining the `window_sum` variable** is what makes the whole thing O(n).

## A crash site: `if` instead of `while` gives the wrong answer

```python
# WRONG
def min_subarray_if(nums, target):
    n = len(nums)
    left = 0
    window_sum = 0
    ans = float('inf')
    for right in range(n):
        window_sum += nums[right]
        if window_sum >= target:          # only shrinks once!
            ans = min(ans, right - left + 1)
            window_sum -= nums[left]
            left += 1
    return ans if ans != float('inf') else 0

print(min_subarray_if([2, 3, 1, 2, 4, 3], 7))   # 4  <- WRONG, should be 2
```

With `if`, at `right=3` the window `[2,3,1,2]` has sum 8, you shrink once to `[3,1,2]` (sum 6) and move on. You never discover that `[4,3]` at the end is shorter. The bug is silent: the code runs and prints a number, just the wrong one.

## How this differs from slow/fast pointers

| Feature | Slow/fast pointer | Sliding window |
|---|---|---|
| Direction | same direction | same direction |
| Main action | overwrite / relocate | expand + shrink |
| Meaning of slow/left | answer position | window left edge |
| Typical use | dedup, removal | interval satisfying a condition |

**The sliding window is an upgrade of slow/fast pointers** — `left`/`slow` is no longer just a scribe; it actively reshapes the window size.

## Summary

- Sliding window: **`right` expands, `left` shrinks**, maintaining information about what is inside
- Expand to add, shrink once the condition is met — every step searches for "the shortest valid window"
- Both `left` and `right` move only forward -> **O(n)**
- Use `while` to shrink (not `if`), initialize the minimum with `float('inf')`
- Maintain the window sum in a variable; never recompute it from scratch
