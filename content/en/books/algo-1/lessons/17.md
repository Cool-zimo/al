# Standard Binary Search: Closed-Interval Style, Computing Mid, and Infinite Loops

> In the previous lesson we understood the prerequisites for binary search. This lesson gives a **reliable closed-interval template** and explains why each step is written the way it is.

## The Closed-Interval Template (Highly Recommended)

**Core idea**: the search interval is `[left, right]` (closed), including both endpoints.

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1    # closed interval [left, right]

    while left <= right:               # keep going while the interval is non-empty
        mid = left + (right - left) // 2

        if nums[mid] == target:
            return mid                 # found it
        elif nums[mid] < target:
            left = mid + 1             # drop mid, go right
        else:
            right = mid - 1            # drop mid, go left

    return -1                          # interval is empty, not found
```

**Why `while left <= right`?** Because the interval is closed, when `left == right` there is still one unchecked element inside. The interval is truly empty only when `left > right`.

**Why `left = mid + 1`?** Because `nums[mid]` has already been compared with the target; it is not the answer and can be removed from the search interval.

## Four Ways to Compute Mid

| Expression | Meaning | When to use |
|---|---|---|
| `(left + right) // 2` | Round down | General purpose |
| `left + (right - left) // 2` | Round down | Avoids overflow (other languages) |
| `(left + right + 1) // 2` | Round up | Finding a right boundary |
| `left + (right - left + 1) // 2` | Round up | Avoids overflow + right boundary |

**All four work in Python** (integers never overflow), but **rounding down is the default choice you will use most often**.

## Two Classic Infinite-Loop Scenarios

### Scenario 1: `left = mid`

```python
while left < right:            # note: <
    mid = (left + right) // 2
    if nums[mid] < target:
        left = mid             # wrong! should be mid + 1
    else:
        right = mid

# When left=0, right=1: mid=0
# nums[0] < target -> left = mid = 0
# interval is still [0, 1], infinite loop!
```

**Why it happens**: after `left = mid` the interval does not shrink (`[0, 1]` -> `[0, 1]`).

**The fix**: `left = mid + 1`. But if `right` is also `mid`, the problem may be on the other side.

### Scenario 2: `left = mid` and `right = mid` at the same time

```python
while left < right:
    mid = (left + right) // 2   # rounds down
    if condition:
        left = mid              # no +1
    else:
        right = mid             # no -1

# left=2, right=3: mid=2
# condition is true -> left=mid=2
# interval is still [2, 3], infinite loop!
```

**This is the classic binary-search infinite loop.** Cause: when `mid` rounds down, `mid == left` (whenever the interval has length 2), and `left = mid` stops the interval from shrinking.

**Two ways to fix it:**

```python
# Fix 1: round mid up
while left < right:
    mid = (left + right + 1) // 2   # round up
    if condition:
        left = mid                  # now mid cannot equal left
    else:
        right = mid - 1             # paired with left=mid, right must -1

# Fix 2: unconditionally move past mid
while left <= right:
    mid = (left + right) // 2       # round down
    if nums[mid] == target:
        return mid
    elif nums[mid] < target:
        left = mid + 1              # +1
    else:
        right = mid - 1             # -1
```

## # WRONG -- The Off-By-One Crash Scene

The single most common way a binary search "looks fine" but returns garbage:

```python
# WRONG -- returns mid even when the target was never found
def binary_search_buggy(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return mid    # wrong! mid may be out of range, and it is not the answer

# nums = [1, 3, 5], target = 2
# loop ends with left=1, right=0, mid was 0 or 1
# returning mid returns 0 or 1 -- both are real indexes, just wrong values
```

**Why this is a silent disaster**: `-1` is an obvious "not found" signal. Returning `mid` can return a valid-looking index that happens to hold the wrong value, so the caller has no idea the search failed. Worse, after the loop `mid` may even be outside `[0, len(nums)-1]`.

The correct ending is a sentinel:

```python
# FIXED
    return -1    # not found, signal failure explicitly
```

**The rule**: when the loop terminates, the answer is gone. Return a sentinel (here `-1`), never a leftover variable.

## Why the Template Recommends `left <= right`

| Style | Search interval | Stop condition | How to compute mid | Prone to infinite loops? |
|---|---|---|---|---|
| `left <= right` | Closed [l, r] | `left > right` | Round down | No |
| `left < right` | Half-open [l, r) | `left == right` | Round up (right boundary) | Easy |

**Closed interval + round down + `<=` is the style least likely to go wrong.**

## A Complete Trace by Hand

`nums = [1, 3, 5, 7, 9, 11]`, looking for `target = 7`:

```
start: left=0, right=5, interval [0, 5]
mid = (0+5)//2 = 2, nums[2]=5 < 7 -> left = 3

left=3, right=5, interval [3, 5]
mid = (3+5)//2 = 4, nums[4]=9 > 7 -> right = 3

left=3, right=3, interval [3, 3]
mid = (3+3)//2 = 3, nums[3]=7 == 7 -> return 3 ✓
```

Looking for `target = 4` (not present):

```
start: left=0, right=5
mid=2, nums[2]=5 > 4 -> right=1

left=0, right=1
mid=0, nums[0]=1 < 4 -> left=1

left=1, right=1
mid=1, nums[1]=3 < 4 -> left=2

left=2, right=1 -> loop ends, return -1 ✓
```

## Common Mistakes

### Mistake 1: loop condition written as `while left < right`

```python
# Closed interval but using <
while left < right:         # there is still one element in [left, right]
    mid = (left + right) // 2
    ...
# When left=0, right=0 the loop never runs, but nums[0] was never checked!
```

**If the search interval is the closed `[left, right]`, the loop condition must be `<=`.** Alternatively, switch to the half-open `[left, right)` and use `<`.

### Mistake 2: forgetting the `+/-1` on left/right

```python
# just move, no +1/-1
if nums[mid] < target:
    left = mid      # wrong! should be mid + 1
```

**This causes an infinite loop** (scenario 1).

### Mistake 3: forgetting to check the bounds on return

```python
def binary_search_buggy(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return mid    # wrong! mid may be out of range
```

**When not found, return -1 (or another sentinel), not mid.**

## A Mnemonic for the Standard Template

> **Closed interval, `<=`
> Mid rounds down,
> Too big: right-1, too small: left+1,
> Return mid when found, -1 when not.**

**Memorize this template and you can handle 80% of binary-search problems.**

## Summary

- Most recommended: **closed interval `[left, right]` + `while left <= right`**
- `mid = (left + right) // 2` (round down)
- When shrinking, `left = mid + 1` or `right = mid - 1` (drop the already-checked mid)
- Root cause of infinite loops: the interval stops shrinking -> check the `+/-1`
- Return mid when found, -1 when not found
