# Putting It All Together: Two Pointers, Prefix Sums, and Sliding Windows

> Earlier lessons covered two pointers, prefix sums, and sliding windows in isolation. This lesson brings them into one toolbox: one **multi-technique** problem, plus a decision framework for choosing the right tool.

## The Three Tools and When to Reach for Them

| Technique | Solves | Key signature |
|---|---|---|
| Two pointers | Two-sum, three-sum, collision-style answers | Pointers move independently; you care about a **pair** |
| Prefix sums | Range sums, subarray-sum queries | Preprocess O(n), query O(1) |
| Sliding window | Subarray/substring extremes; shortest/longest valid interval | Maintain interval state; pointers never decrease |

**Real problems don't tell you "use a sliding window."** You have to decide.

## Problem 1: Minimum Size Subarray Sum (LeetCode 209)

**Statement**: given an array of **positive** integers `nums` and a positive integer `target`, find the length of the **shortest** contiguous subarray whose sum is **>= target**. Return 0 if none exists.

```python
nums = [2, 3, 1, 2, 4, 3]
target = 7
# Shortest subarray is [4, 3], length 2, sum 7
```

### Why a Sliding Window?

- The answer is a **contiguous interval** → satisfies the window premise
- We want the **shortest** one → variable window (shrink left when valid)
- The array is **all positive** → the window sum is monotonic, so shrinking has a deterministic effect

**If the array had negative numbers, a sliding window would fail** (after shrinking, the sum could actually get larger).

### Solution

```python
def min_subarray_len(nums, target):
    left = 0
    window_sum = 0
    min_len = float('inf')

    for right in range(len(nums)):
        # Right pointer expands: add nums[right]
        window_sum += nums[right]

        # Left pointer shrinks: while sum >= target, shrink as hard as possible
        while window_sum >= target:
            min_len = min(min_len, right - left + 1)
            window_sum -= nums[left]
            left += 1

    return min_len if min_len != float('inf') else 0

print(min_subarray_len([2, 3, 1, 2, 4, 3], 7))   # 2
print(min_subarray_len([1, 4, 4], 4))              # 1
print(min_subarray_len([1, 1, 1, 1, 1], 11))       # 0
```

### Hand Trace

## Variant: Longest Subarray with Sum <= target

If the array is **all positive**, the longest valid subarray is just the whole array. With **negative** numbers it's different:

```python
nums = [1, -1, 5, -2, 3]
target = 3
# Longest valid subarray is [1, -1, 5, -2, 3], length 5, sum 6 >= 3
```

This one **cannot** use a sliding window (negatives present). You'd need prefix sums + a monotonic queue or a TreeMap — an advanced topic.

## Problem 2: Longest Repeating Character Replacement

**Statement**: given a string `s` and an integer `k`, you may replace **at most** `k` characters so that the resulting substring is made of **all the same character**. Find the longest possible length.

```python
s = "ABAB", k = 2
# Replace to "AAAA", length 4

s = "AABABBA", k = 1
# Replace to "AAAABBA" or "AABBBBA", longest 4
```

### The Idea

Inside a window, replace every character that isn't the majority. If the window length is `len` and the most frequent character appears `max_freq` times, you must replace `len - max_freq` characters. The window is valid as long as `len - max_freq <= k`.

```python
from collections import Counter

def character_replacement(s, k):
    count = Counter()
    left = 0
    max_len = 0
    max_freq = 0

    for right in range(len(s)):
        count[s[right]] += 1
        max_freq = max(max_freq, count[s[right]])

        # Characters to replace = window length - highest frequency count
        while (right - left + 1) - max_freq > k:
            count[s[left]] -= 1
            left += 1
            # Recompute max_freq (can be optimized, but correctness is fine)
            max_freq = max(count.values()) if count else 0

        max_len = max(max_len, right - left + 1)

    return max_len

print(character_replacement("ABAB", 2))     # 4
print(character_replacement("AABABBA", 1))  # 4
```

**The clever part**: `max_freq` is **monotonic** in the sense that we only ever shrink when `len - max_freq > k`. So we don't need to maintain its exact minimum after every shrink — recomputing after the shrink is enough.

## Crash Scene 1: Forgetting to Update `max_freq`

```python
from collections import Counter

def buggy_replacement(s, k):
    count = Counter()
    left = 0
    max_len = 0
    max_freq = 0

    for right in range(len(s)):
        count[s[right]] += 1
        max_freq = max(max_freq, count[s[right]])

        while (right - left + 1) - max_freq > k:
            count[s[left]] -= 1
            left += 1
            # WRONG! max_freq is never recomputed
            # After shrinking, max_freq may have dropped, but we keep the stale value
        max_len = max(max_len, right - left + 1)

    return max_len

print(buggy_replacement("AABABBA", 1))  # May return a wrong (too-large) answer
```

Output:

```
# Could return 5 or more instead of the correct 4
```

**Why it fails**: After shrinking the left edge, the character we just evicted might have *been* the most frequent one, so `max_freq` drops. But we keep using the stale value, which makes `len - max_freq` look smaller than it really is. The window should keep shrinking — and doesn't.

**Fix**: after the shrink, recompute `max_freq = max(count.values())`.

## Crash Scene 2: Mixing Up "Shortest" vs. "Longest" Shrink Logic

```python
nums = [2, 3, 1, 2, 4, 3]
target = 7

# SHORTEST subarray with sum >= target: shrink while valid
def shortest(nums, target):
    left = 0
    window_sum = 0
    min_len = float('inf')
    for right in range(len(nums)):
        window_sum += nums[right]
        while window_sum >= target:   # >=  -> shrink
            min_len = min(min_len, right - left + 1)
            window_sum -= nums[left]
            left += 1
    return min_len

# LONGEST subarray with sum <= target: shrink while INVALID
def longest(nums, target):
    left = 0
    window_sum = 0
    max_len = 0
    for right in range(len(nums)):
        window_sum += nums[right]
        while window_sum > target:    # >  -> shrink (note: > NOT >=)
            window_sum -= nums[left]
            left += 1
        max_len = max(max_len, right - left + 1)
    return max_len

print(shortest([2, 3, 1, 2, 4, 3], 7))  # 2
print(longest([2, 3, 1, 2, 4, 3], 7))   # 4  ([3, 1, 2, 4] or [1, 2, 4, 3])
```

**The key difference**:

- **Shortest** → shrink **while the condition holds** (`>=`), pushing toward the boundary where it just barely fails
- **Longest** → shrink **while the condition is violated** (`>`), pushing toward the boundary where it just barely holds

The direction of that inequality symbol decides whether you're hunting for shortest or longest.

## Decision Flowchart

When you face an array/string interval problem, work through this in order:

```
1. Is the answer a contiguous interval?
   ├─ No  -> probably two pointers / combinatorics (two-sum, three-sum)
   └─ Yes -> continue
2. Is the interval a fixed length?
   ├─ Yes -> fixed window (O(n))
   └─ No  -> continue
3. Need the shortest/longest interval satisfying a condition?
   ├─ Yes -> variable window (needs monotonicity)
   │  ├─ All positive     -> sliding window
   │  └─ Has negatives    -> prefix sums + another structure
   └─ Just need range-sum queries -> prefix sums, O(1) per query
```

## Complexity Comparison

| Approach | Time | Space | When it works |
|---|---|---|---|
| Brute force (every subarray) | O(n³) | O(1) | Never preferred |
| Prefix sums + hash map | O(n) | O(n) | Works even with negatives |
| Sliding window | O(n) | O(1)~O(k) | Usually needs monotonicity |

## Summary

- Two pointers, prefix sums, and sliding windows solve different shapes of problems; real tasks may need them in combination
- Shortest subarray with sum >= target: expand right, shrink left, contract on `>=`
- Longest subarray with sum <= target: expand right, shrink left, contract on `>`
- Character replacement: validity condition is `len - max_freq <= k`
- Always update your maintained variables (`max_freq`, etc.) after shrinking
- With negative numbers, a sliding window typically breaks — switch to prefix sums

  def num_subarrays_with_sum(nums, k):
      # Prefix sum + hash map
      # prefix_count stores how many times each prefix sum has appeared
      # At each position, look for how many earlier prefix sums equal prefix - k
      prefix_count = {0: 1}
      prefix_sum = 0
      count = 0
