# String Immutability: Why Concatenation in a Loop Is O(n²)

> The first four chapters were all about arrays. This chapter moves on to strings — they look simple, but **string immutability** can quietly drag your code down.

## What "Immutable" Means

**In Python, a string cannot be modified once it has been created.**

```python
s = "hello"
# s[0] = "H"     # TypeError: 'str' object does not support item assignment
```

**There is no such operation as `s[0] = "H"`.** If you want to change something, you have to build a brand-new string.

```python
s = "hello"
new_s = "H" + s[1:]    # builds a brand-new string "Hello"
print(s)               # "hello"  (the original string did not change)
print(new_s)           # "Hello"
```

**Every "modification" of a string actually creates a new string.**

## Why This Is a Performance Trap

**The problem scenario**: concatenating strings over and over inside a loop.

```python
# BAD: using += inside a loop
def concat_slow(n):
    s = ""
    for i in range(n):
        s += str(i)      # a new string is built every single time!
    return s

print(concat_slow(5))   # "01234"
```

**What happens on each `s += str(i)`?**

1. Allocate a new block of memory (of length `len(s) + 1`)
2. Copy every character of `s` into it
3. Append `str(i)` at the end
4. Throw away the old `s`

**The i-th operation copies i characters.** Total copies = 0 + 1 + 2 + ... + (n-1) = **O(n²)**.

```python
# when n = 1000:
# 1st iteration copies 1 character
# 2nd iteration copies 2 characters
# ...
# 1000th iteration copies 1000 characters
# total: about 500,000 copies
```

## A Live Benchmark

```python
import time

def concat_slow(n):
    s = ""
    for i in range(n):
        s += str(i)
    return s

def concat_fast(n):
    parts = []
    for i in range(n):
        parts.append(str(i))
    return "".join(parts)

for n in [1000, 2000, 4000, 8000]:
    t1 = time.perf_counter()
    concat_slow(n)
    t1 = (time.perf_counter() - t1) * 1000

    t2 = time.perf_counter()
    concat_fast(n)
    t2 = (time.perf_counter() - t2) * 1000

    print(f"n={n:>5}  += {t1:>8.3f} ms   join {t2:>7.4f} ms")
```

Approximate output:

```
n= 1000  +=    0.8 ms   join  0.2 ms
n= 2000  +=    3.1 ms   join  0.3 ms
n= 4000  +=   12.5 ms   join  0.5 ms
n= 8000  +=   50.0 ms   join  1.0 ms
```

**The `+=` version grows roughly 4x each step (O(n²)); the `join` version grows roughly 2x (O(n)).**

## The Right Way: join

```python
parts = ["hello", "world", "python"]
result = "".join(parts)      # "helloworldpython"
print(result)
```

**How `join` works:**

1. Walk through all the strings first and **compute the total length**
2. Allocate one big enough block of memory in a single shot
3. Copy every string into it

**Total copies = number of all characters = O(n)** (linear).

```python
# correct: collect in a list, then join at the end
def concat_good(n):
    parts = []
    for i in range(n):
        parts.append(str(i))
    return "".join(parts)

print(concat_good(5))   # "01234"
```

## Time Complexity of Common String Operations

| Operation | Complexity | Note |
|---|---|---|
| `s[i]` access | O(1) | character by index |
| `s[i:j]` slice | O(j-i) | **copies** |
| `s + t` concatenate | O(len(s)+len(t)) | **creates new** |
| `s += t` | O(len(s)+len(t)) | **creates new every time** |
| `s.split()` | O(n) | one pass |
| `sep.join(list)` | O(n) | one pass |
| `s in t` (substring) | O(nm) | naive match |

**The key point**: slicing and concatenation both **create new strings**. Repeating them inside a loop is O(n²).

## Common Mistakes

### Mistake 1: Repeated slicing inside a loop

```python
# BAD: slicing on every iteration (creates a new string)
s = "abcdefghij"
while len(s) > 0:
    print(s[0])
    s = s[1:]       # new string every time, O(n²)
```

**Every `s[1:]` has to copy all the remaining characters.** Over n iterations that is O(n²).

### Mistake 2: Using sum to concatenate strings

```python
# BAD
result = sum(strings, "")   # TypeError: sum() can't sum strings
```

**`sum` does not support strings.** Use `"".join()`.

### Mistake 3: Thinking strings are mutable like lists

```python
# trying to "modify in place"
s = "hello"
s.replace("h", "H")         # returns a new string "Hello"
print(s)                    # "hello"  <- the original did not change!

# correct
s = s.replace("h", "H")
print(s)                    # "Hello"
```

**Every string method — `replace`, `upper`, `strip` — returns a new string and leaves the original untouched.**

## When You Can Just Use +=

**For short strings and a small number of concatenations, `+=` is perfectly fine.**

```python
# totally OK: only a few concatenations
greeting = "Hello, " + name + "! Welcome to " + city + "."
```

**Python does optimize `+=` on short strings** (if the string has no other references, it may resize in place). But **inside a loop, or when the string is long**, always use `join`.

> 💡 **Rule of thumb**: concatenation inside a loop → use a list + join; ordinary concatenation → `+=` or `+` is fine.

## Convert to a List, Modify, Then Join Back

**If you need to "modify" characters frequently, convert to a list first, change it, then join back:**

```python
# capitalize the first character of "hello"
s = "hello"
chars = list(s)       # ['h', 'e', 'l', 'l', 'o']
chars[0] = "H"        # lists can be modified
result = "".join(chars)
print(result)         # "Hello"
```

**Time O(n)** — list modification is O(1), and the final join is O(n).

## Summary

- Strings are **immutable**: `s[0] = "x"` raises an error
- Every modification operation **returns a new string**
- Using `+=` in a loop is **O(n²)** — a new string every time
- The correct approach: **collect in a list + `join`**, O(n)
- Need to modify characters → convert to a list → modify → join back
