# Manipulating Shapes: move, coords, itemconfig and tag

> A shape does not have to sit there once it has been drawn. This lesson covers four core operations — move it, change its coordinates, alter its properties, delete it — and how to manage a group of shapes using "tags".

## The Shape ID Is the Key to Every Operation

**As we saw earlier, every shape you draw returns an integer ID.** Every operation uses that ID:

```python
import tkinter as tk

root = tk.Tk()
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

rect = canvas.create_rectangle(10, 10, 60, 50, fill="orange")
oval = canvas.create_oval(80, 10, 140, 70, fill="skyblue")
print(rect, oval)   # prints 1 2
```

**`rect` and `oval` are the IDs**, and you use them to operate on those two shapes.

## move: Relative Movement

**`canvas.move(id, dx, dy)` moves the shape by `dx` pixels (horizontally) and `dy` pixels (vertically) relative to its current position:**

```python
canvas.move(rect, 30, 0)   # move 30 pixels right
canvas.move(oval, 0, 20)   # move 20 pixels down
```

**This is the basis of animation** — move a little, refresh, move a little more, and the shape appears to move (covered in detail in Lesson 7).

`dx` and `dy` may be negative: a negative `dx` goes left and a negative `dy` goes up.

## coords: Absolute Positioning

**`canvas.coords(id, x1, y1, x2, y2)` moves the shape to a brand-new position in one step.** The difference from `move` is that `move` means "take a few more steps", while `coords` means "teleport it over there".

```python
canvas.coords(rect, 100, 100, 160, 140)  # rect is now at (100,100)-(160,140)
```

**Keep the two uses clear:**

| Method | Semantics | Typical use |
|---|---|---|
| `move(id, dx, dy)` | Relative movement | Animation, dragging |
| `coords(id, x1, y1, x2, y2)` | Absolute positioning | Precise placement, resetting a position |

**If you call `coords(id)` without supplying new coordinates, it returns the current coordinate list** `[x1, y1, x2, y2]`. This is a very handy trick for reading the shape's present position.

```python
x1, y1, x2, y2 = canvas.coords(rect)   # unpack the four coordinates
```

## itemconfig: Changing Properties Dynamically

**`canvas.itemconfig(id, **options)` lets you change a shape's colour, border and other properties after it has been drawn.** Think of it as "putting on make-up after the drawing is finished".

```python
rect = canvas.create_rectangle(10, 10, 60, 50, fill="gray")

# Turn red when the mouse hovers over it
canvas.itemconfig(rect, fill="red", outline="black", width=3)
```

The properties you can change are the same ones used at creation time: `fill`, `outline`, `width`, `dash`, `state`, and so on.

**`state` is particularly useful:** setting it to `"hidden"` makes the shape disappear, `"disabled"` greys it out and blocks interaction, and `"normal"` restores it.

```python
canvas.itemconfig(rect, state="hidden")    # hide it
canvas.itemconfig(rect, state="normal")    # show it again
```

## delete: Removing Shapes

**`canvas.delete(id)` deletes the specified shape; `canvas.delete("all")` deletes every shape.**

```python
canvas.delete(rect)        # delete this one
canvas.delete("all")       # clear the canvas
```

**"Clearing the canvas" is extremely common in drawing pads and games.** But be careful: `delete("all")` wipes out background grids and fixed UI elements too, so in a real project you should give "things that must not be deleted" a tag (see below).

## Crash Site One: Misspelling the itemconfig Option

```
canvas.itemconfig(rect, colour="red")   # error
```

**Symptom:** `_tkinter.TclError: unknown option "-colour"`.

**Cause:** tkinter uses the American spelling `color`, not the British `colour`. Likewise `fill` (not `colour`) and `outline`. This has nothing to do with Python keywords — these are the parameter names used by the underlying Tcl/Tk layer.

## Crash Site Two: Operating on an ID After It Has Been Deleted

```
canvas.delete(rect)
canvas.itemconfig(rect, fill="red")   # does this error?
```

**In fact tkinter does not raise an error here** — calling `itemconfig` or `move` on an ID that has been deleted is a silent no-op. That is good news in that it does not crash, but it is also a trap: you think the change worked while the display stays unchanged, and that is hard to debug.

**Countermeasure:** maintain your own set of "still alive" IDs and remove entries from it when you delete them. In a complex drawing pad this habit saves a great deal of debugging time.

## Tags: Labelling Shapes

**A tag is a string you attach to one or more shapes so you can operate on them as a group.** It is similar to a class in HTML.

```python
# Assign a tag at creation time
c1 = canvas.create_rectangle(10, 10, 50, 50, fill="red", tags="enemy")
c2 = canvas.create_rectangle(70, 10, 110, 50, fill="blue", tags="enemy")
c3 = canvas.create_oval(130, 10, 170, 50, fill="green", tags="player")

# Operate on all shapes carrying the "enemy" tag at once
canvas.itemconfig("enemy", fill="gray")

# Move every enemy
canvas.move("enemy", 0, 30)
```

**One shape can carry several tags**, separated by spaces: `tags="enemy boss"`. To check whether a shape has a particular tag, `canvas.gettags(id)` returns its list of tags.

## Using Tags to Solve the "Accidental Background Deletion" Problem

**Give anything that must not be deleted a special tag, then skip it when clearing the canvas:**

```python
# The background grid uses the tag "grid"; clear by deleting "all" then redrawing
canvas.create_line(0, 0, 400, 0, tags="grid")   # suppose a grid has been drawn
# Clear without removing the grid:
for item in canvas.find_all():
    if "grid" not in canvas.gettags(item):
        canvas.delete(item)
```

**An even simpler approach is `canvas.delete("obj")`**, which removes only the shapes carrying the `"obj"` tag and leaves everything else alone. In a real drawing-pad project the strokes a user has drawn are usually tagged `"stroke"`, so clearing becomes `canvas.delete("stroke")` — clean and tidy.

## Summary

- The shape ID is the key to every operation: `move`, `coords`, `itemconfig` and `delete`
- `move(id, dx, dy)` is relative; `coords` is absolute and, when called with no arguments, reads the current coordinates
- `itemconfig` changes `fill`, `outline`, `width` and `state` dynamically
- `delete(id)` removes one shape; `delete("all")` clears the canvas
- Option names use American spelling: `fill`, `outline` — never `colour`
- **Tags are a powerful tool for group management:** pass `tags="xxx"` at creation time and use the tag instead of the ID later
