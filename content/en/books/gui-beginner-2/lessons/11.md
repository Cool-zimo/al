# What Is ttk: Why Native Widgets Look Dated and ttk Gives You Themed Widgets

> Up to now we have used tkinter's "native widgets" (tk.Button, tk.Label), which look plain and differ between Windows, macOS and Linux. ttk is tkinter's themed widget library, producing interfaces that are smarter and more consistent.

## The Problem First: How Plain Native Widgets Look

**Looking back at the code from Book 1, we have always written it this way:**

```python
import tkinter as tk

root = tk.Tk()
tk.Button(root, text="OK").pack()
tk.Checkbutton(root, text="Agree").pack()
tk.Radiobutton(root, text="Option A").pack()
root.mainloop()
```

**The appearance of these widgets is decided by the operating system's own "tk rendering":** on Windows it is a plain old 3D style, while on Linux it can be even simpler. On Windows 10/11, tk widgets often look like the "Windows 95 era" — rounded corners, shadows and high-DPI support are all weak.

**That is why any reasonably polished Python GUI program recommends using ttk.**

## What ttk Is

**ttk (Themed Tk) is a sub-module of tkinter that provides a set of "themed" widgets.** Their appearance is drawn by a "theme engine" that can follow the operating system's visual style (Windows' Vista/Win10 theme, macOS's Aqua theme, Linux's clam/alt themes).

```python
from tkinter import ttk

root = tk.Tk()
ttk.Button(root, text="OK").pack()
ttk.Checkbutton(root, text="Agree").pack()
root.mainloop()
```

**Note the import style:** `from tkinter import ttk`, then use `ttk.Button`, `ttk.Label`, and so on.

## Native Versus ttk: A Comparison

| Feature | Native tk | ttk |
|---|---|---|
| Appearance | Dated, inconsistent across platforms | Themed, more modern |
| High DPI | Poor support | Better support |
| Style customisation | Direct arguments (bg, fg) | Uses a Style object |
| Cross-platform consistency | Weak | Strong |
| Number of widgets | Basic set is complete | Extra ones too (Treeview, Notebook, etc.) |

**In one sentence:** ttk widgets "look more like software from this decade".

## Widgets Provided by ttk

**ttk covers all the basics and adds a few that tk does not have:**

| Widget | ttk form |
|---|---|
| Button | `ttk.Button` |
| Label | `ttk.Label` |
| Entry | `ttk.Entry` |
| Checkbutton | `ttk.Checkbutton` |
| Radiobutton | `ttk.Radiobutton` |
| Combobox | `ttk.Combobox` (not in tk) |
| Progress bar | `ttk.Progressbar` (not in tk) |
| Table | `ttk.Treeview` (not in tk) |
| Tabbed page | `ttk.Notebook` (not in tk) |

**The next few lessons focus on Treeview, Notebook and Progressbar because they are unique to ttk.**

## Mixing Them: tk and ttk Can Coexist

**A program can use tk and ttk widgets side by side:**

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()

# tk's Canvas (ttk has no Canvas)
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

# ttk's button
ttk.Button(root, text="OK").pack()

root.mainloop()
```

**There is no Canvas, Frame, Menu or other "container/canvas-style" widget in ttk**, so you must use the tk versions. The common pattern in real projects is therefore: **use tk for layout containers and ttk for interactive widgets.**

## Crash Site One: Setting bg/fg on a ttk Widget Does Nothing

```
ttk.Button(root, text="OK", bg="red", fg="white").pack()
```

**Symptom:** the `bg` and `fg` arguments are ignored and the button keeps its default themed appearance.

**Cause:** a ttk widget's appearance is managed centrally by the theme engine, so it does not accept tk-style direct arguments such as `bg`, `fg` or `font`. To change its style you must use a `ttk.Style()` object (next lesson).

**This is not a bug; it is by design:** ttk's philosophy is "let the theme handle the look while you focus on the structure". For fine colour control, use Style.

## Crash Site Two: Importing It Wrong

```
import ttk                     # ModuleNotFoundError
from ttk import Button         # old style, removed in Python 3
```

**Correct form:**

```python
from tkinter import ttk        # the only recommended form
```

**`ttk` is a sub-module of `tkinter`, not a top-level module.** The old `import ttk` syntax no longer works after Python 3.

## Crash Site Three: ttk Widgets Look Small and Crowded

**ttk widgets have less default padding than tk widgets, so they look cramped.** The solution is to set padding with `ttk.Style` or add spacing using `pack(padx=5, pady=5)`.

```python
ttk.Button(root, text="OK").pack(padx=10, pady=5)
```

**Layout-level spacing (`padx`/`pady`) works the same way in tk and ttk, so use it as usual.**

## When Not to Use ttk

**There are a few cases where ttk is actually less convenient:**

1. **Highly customised appearance is needed** (for example a coloured button or a gradient background) — ttk's Style system is more effort to learn than simply passing `bg`.
2. **Canvas drawing** — ttk has no Canvas, so tk is mandatory.
3. **Quick prototypes or teaching demos** — tk's arguments are intuitive and quick to write.

**So the strategy of this book is: use tk for the foundations, then use ttk for "proper interfaces".**

## Summary

- ttk = Themed Tk, a themed widget library with a more modern look and better cross-platform consistency
- Import with `from tkinter import ttk` and use `ttk.Button` etc.
- Widgets unique to ttk: Combobox, Progressbar, Treeview, Notebook
- Canvas, Frame and Menu exist only in tk
- ttk does not accept direct `bg`/`fg` arguments; use Style (next lesson)
- The real-world pattern: containers in tk, interactive widgets in ttk
