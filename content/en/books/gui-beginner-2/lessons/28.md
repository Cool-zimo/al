# Saving and Config: Storing the High Score in a File

> When you close and reopen the game, your score is gone — that doesn't motivate a second playthrough. This lesson teaches you how to write data (high score, settings, progress) **to a file and read it back**, and how to do it without crashing on a corrupted file.

## Why Use Files for Saving

**A variable's lifetime = the program's runtime.** The moment the program closes, `high_score` in memory disappears. To "remember the previous score next time you open it", you must store the data on disk.

**Common save data needs:**

| What to store | Example |
|---|---|
| High score | `{"high_score": 8500}` |
| Player settings | `{"volume": 0.6, "fullscreen": false}` |
| Game progress | `{"level": 3, "coins": 12}` |

**Where should the save file go?** In the same directory as `main.py`, named `save.json` — simplest, works across machines.

## JSON: The Go-To Format for Save Data

**JSON is a text format that looks almost identical to a Python dictionary.**

```python
import json

data = {"high_score": 8500, "volume": 0.6, "player": "小明"}
text = json.dumps(data)            # dict → string
print(text)
```

**Saving trilogy: `open` + `json.dump` + close the file.**

```python
import json

def save(data, path="save.json"):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

**Loading: `json.load` gives you a dictionary directly.**

```python
def load(path="save.json"):
    with open(path, "r", encoding="utf-8") as f:
        return json.load(f)

data = load()
print(data["high_score"])
```

**`ensure_ascii=False` is important** — without it, Chinese becomes garbled escape sequences like `\u5c0f\u660e`. `indent=2` adds line breaks and indentation, so you can open it in Notepad and read it.

## How Saving Fits Into Your Game

**Pattern: read the save on startup (use defaults if no file exists), write the save on exit (or whenever the score updates).**

```python
import json
import os
import pygame

SAVE_FILE = "save.json"
DEFAULT = {"high_score": 0, "volume": 0.6}

def load_save():
    if not os.path.exists(SAVE_FILE):
        return dict(DEFAULT)                 # No file → use defaults
    with open(SAVE_FILE, "r", encoding="utf-8") as f:
        return json.load(f)

def save_score(score):
    data = load_save()
    if score > data["high_score"]:
        data["high_score"] = score
        with open(SAVE_FILE, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2)

# On startup
save = load_save()
print("All-time high:", save["high_score"])
```

**Encapsulating "high score update" as a function** means the caller doesn't need to worry about "should I write to disk?"

## Crash Scene 1: File Doesn't Exist, Program Crashes Immediately

```python
data = json.load(open("save.json"))
```

**Symptom**: `FileNotFoundError: [Errno 2] No such file or directory: 'save.json'` (happens on first run or after deleting the save).

**Why**: `open` on a file that doesn't exist in `"r"` mode errors out immediately.

**Correct approach: check with `os.path.exists` first; if it doesn't exist, return a default value.**

```python
import os

if os.path.exists("save.json"):
    with open("save.json", "r", encoding="utf-8") as f:
        data = json.load(f)
else:
    data = {"high_score": 0}
```

## Crash Scene 2: Storing a pygame Object in JSON

```python
data = {"player_rect": pygame.Rect(10, 10, 50, 50)}
json.dump(data, f)
```

**Symptom**: `TypeError: Object of type Rect is not JSON serializable`.

**Why**: JSON only recognizes a few basic types — `dict`, `list`, `str`, `int/float`, `bool`, `None`. `pygame.Rect`, functions, and date objects are not serializable.

**Solution**: **store "data", not "objects".** Break the Rect into four numbers:

```python
data = {
    "player": {"x": 10, "y": 10, "w": 50, "h": 50},
    "high_score": 8500,
}
json.dump(data, f)

# When reading back, reconstruct the Rect
d = json.load(f)
rect = pygame.Rect(d["player"]["x"], d["player"]["y"],
                   d["player"]["w"], d["player"]["h"])
```

## Crash Scene 3: Save File Gets Corrupted

**The player opens `save.json` in Notepad, accidentally deletes a quote — then opens the game again:**

```python
json.load(open("save.json"))
```

**Symptom**: `json.decoder.JSONDecodeError: Expecting ',' delimiter: line 1 column 12 (char 11)`.

**Why**: The file content is no longer valid JSON. `json.load` throws an exception on bad data and the program crashes — terrible player experience.

**Solution**: **use `try / except` as a fallback — if reading fails, treat it as no save.**

```python
def load_save():
    try:
        with open("save.json", "r", encoding="utf-8") as f:
            return json.load(f)
    except (json.JSONDecodeError, FileNotFoundError, OSError):
        return dict(DEFAULT)          # Any read failure → use defaults
```

**Defend against all three**: `JSONDecodeError` (content corrupted), `FileNotFoundError` (no file), `OSError` (permissions/disk issues). **In a game, "can't read so use defaults" is always better than "crash".**

## Crash Scene 4: Half-Written When It Crashes, Save Becomes Empty

**Your save function crashes / gets force-closed halfway through writing:**

```python
with open("save.json", "w") as f:
    json.dump(huge_data, f)      # Force-quit halfway through
```

**Symptom**: The save file becomes 0 bytes or truncated; next time it crashes on load.

**Why**: `"w"` mode **clears the file first**, then writes content. Interrupting midway = empty file.

**Safe approach: write to a temp file first, then replace the original when done.**

```python
import os

def safe_save(data, path="save.json"):
    tmp = path + ".tmp"
    with open(tmp, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
    os.replace(tmp, path)        # Only replace once writing is complete (atomic)
```

**Either you get a complete temp file, or the old save is preserved** — you never end up with a half-written save.

## Crash Scene 5: Reading and Writing the Same File Every Frame

**Calling `json.dump` every frame in the game:**

```python
while running:
    json.dump({"score": score}, open("save.json", "w"))
```

**Symptom**: Disk thrashes wildly, game stutters, save file may corrupt.

**Why**: File I/O is slow and shouldn't be in the main loop. Plus, **rewriting the whole file each time** is expensive.

**Principle**: **saving is a "low-frequency event"** — only save on "game over, player manually saves, or completing a major level."

## Summary

- Save with JSON: `json.dump` to write, `json.load` to read; use `"w"`/`"r"` modes
- For Chinese saves, remember `ensure_ascii=False`, otherwise it becomes `\u` escapes
- Only store data (numbers, strings, lists, dicts) — don't store Rect, Surface, or similar objects
- Fault-tolerance trilogy: `os.path.exists` + `try/except` + safe writing (write temp then replace)
- Saving is low-frequency: only save at key moments, not every frame
- When reading fails, use defaults — "degrade gracefully" beats crashing
