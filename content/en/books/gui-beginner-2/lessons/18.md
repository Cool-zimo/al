# The Game Loop's Three Jobs: Handle Events, Update State, Redraw

> Last lesson we built the minimum window. This lesson breaks the game loop into "three jobs" and uses it to make a small box that moves across the screen — understand this structure and every game you build will follow the same pattern.

## The Standard Structure of a Game Loop

**Every frame does three things in order:**

```python
while running:
    # 1 Handle input (events)
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # 2 Update state (movement, physics, AI)
    player_x += speed

    # 3 Render (clear + draw + flip)
    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, 200, 50, 50))
    pygame.display.flip()
```

**The order of these three steps matters**: respond to the user first, then calculate the new state, then draw the new state on screen.

**Why this order?** Because you want "this frame's render to reflect this frame's latest state." If you render before updating, the picture will be "one frame behind" — perceptible as lag.

## Step One: Draw a Box

**`pygame.draw.rect(surface, color, rect)` draws a rectangle.** The rect can be a tuple `(x, y, width, height)`:

```python
import pygame

pygame.init()
WIDTH, HEIGHT = 800, 600
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("Moving Box")

BLACK = (0, 0, 0)
RED = (255, 0, 0)

player_x = 375
player_y = 275

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()

pygame.quit()
```

**Result: a red box on a black background.**

## Step Two: Make It Move

**Change coordinates during the "update state" phase:**

```python
player_x = 375
speed = 4

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player_x += speed                 # Update state: +4 each frame

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**Result: the box flies from left to right at constant speed, disappearing off-screen (you just can't see it anymore).**

## Step Three: Bounce Off the Edges

**Use state variables + conditions to bounce:**

```python
player_x = 375
speed = 4

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player_x += speed
    if player_x <= 0 or player_x >= WIDTH - 50:
        speed = -speed                # Bounce

    screen.fill(BLACK)
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**Here `WIDTH - 50` is the right boundary**: the box is 50 pixels wide, so when its right edge hits the window's right edge, it bounces.

## Crash Scene 1: Forgetting fill, Screen Full of Smears

```
while running:
    for event in pygame.event.get():
        ...
    # screen.fill(BLACK)  forgot to fill
    pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
    pygame.display.flip()
```

**Symptom**: The box leaves a long trail behind it as it moves; the screen turns into a smeared mess.

**Why**: `flip` just brings the back buffer to the front, and you've drawn a new box on top of it. The old box was never cleared, so they pile up.

**Fix**: Call `screen.fill(background_color)` at the start of every frame.

## Crash Scene 2: Using the Wrong Right Boundary

```
if player_x >= WIDTH:       # Box is 50px wide, player_x is the top-left corner
    speed = -speed
```

**Symptom**: The box has already flown "off-screen" quite a bit before bouncing — it looks like it passed through the wall.

**Why**: `player_x` is the box's **top-left** coordinate. The right edge is `player_x + 50`, so the right boundary check should use `player_x >= WIDTH - 50`.

**In pygame, coordinates almost always refer to the "top-left corner"** — always account for object size when calculating boundaries.

## Crash Scene 3: Reversing the Update and Render Order Causes "One-Frame Delay"

```
screen.fill(BLACK)
pygame.draw.rect(screen, RED, (player_x, player_y, 50, 50))
pygame.display.flip()

player_x += speed      # Render before update
```

**Symptom**: Input feels "half a beat behind"; the box seems to drag.

**Why**: This frame draws the "previous frame's position"; only the next frame draws the new position. The difference is tiny, but in fast-paced games it's noticeable.

**Remember the order: events → update → render.**

## Drawing Various Shapes with pygame.draw

**The pygame.draw module provides basic drawing functions:**

| Function | Draws | Parameters |
|---|---|---|
| `rect(surface, color, rect)` | Rectangle | surface, color, (x,y,w,h) |
| `circle(surface, color, center, radius)` | Circle | surface, color, center, radius |
| `line(surface, color, start, end, width)` | Line | surface, color, start, end, width |
| `polygon(surface, color, pointlist)` | Polygon | surface, color, list of vertices |
| `ellipse(surface, color, rect)` | Ellipse | surface, color, bounding rect |

```python
pygame.draw.circle(screen, BLUE, (400, 300), 30)              # Center (400,300), radius 30
pygame.draw.line(screen, GREEN, (0, 0), (800, 600), 3)        # Width 3
pygame.draw.polygon(screen, YELLOW, [(400,100),(450,200),(350,200)])  # Triangle
```

## Organizing State as a "Player" Variable Group

**When state grows, managing it as a group of variables is cleaner:**

```python
player = {
    "x": 375,
    "y": 275,
    "size": 50,
    "speed": 4,
    "color": (255, 0, 0),
}

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    player["x"] += player["speed"]
    if player["x"] <= 0 or player["x"] >= WIDTH - player["size"]:
        player["speed"] = -player["speed"]

    screen.fill(BLACK)
    pygame.draw.rect(screen, player["color"],
                     (player["x"], player["y"], player["size"], player["size"]))
    pygame.display.flip()
```

**Next lesson (Lesson 21) we'll encapsulate this state into a "class" for a more structured approach.**

## Summary

- Game loop three steps: handle events → update state → render
- Order matters: events→update→render, otherwise you get a one-frame delay
- `pygame.draw.rect` draws rectangles, `circle` draws circles, `line` draws lines
- Coordinates refer to the top-left corner; use `WIDTH - object_width` for the right boundary
- Every frame must `fill` to clear, otherwise you get smearing
- When state grows complex, use a dict or class to organize it
