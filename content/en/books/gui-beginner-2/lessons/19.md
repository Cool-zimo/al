# Drawing Shapes and Loading Images: Surface, blit, and the Coordinate System

> Last lesson used pygame.draw for basic shapes. This lesson dives into the "Surface" concept, teaching you how to load images, paste them onto the screen (blit), and understand pygame's coordinate system.

## What Is a Surface?

**A Surface is simply "a pixel canvas"** — essentially a 2D array of pixels. Every window you create, every image you load, is a Surface.

```
screen = pygame.display.set_mode((800, 600))
# screen is an 800x600 Surface
```

**Operations on a Surface**: you can draw on it (`pygame.draw`), paste another Surface onto it (`blit`), or fill it with a color (`fill`).

**Key concept: all drawing happens "onto some Surface".** Drawing onto the screen is what ultimately gets displayed; drawing onto another Surface (like an image or an off-screen buffer) just modifies those pixels.

## blit: Pasting One Surface Onto Another

**`dest.blit(source, (x, y))` pastes source onto dest at position (x, y).**

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((800, 600))

# Create a 100x100 red Surface
red_surface = pygame.Surface((100, 100))
red_surface.fill((255, 0, 0))

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    screen.fill((0, 0, 0))
    screen.blit(red_surface, (200, 150))   # Paste at (200, 150)
    pygame.display.flip()

pygame.quit()
```

**`blit` stands for "bit block transfer"** — it means "move a block of pixels from here to there." This is the most fundamental operation in 2D games — pasting sprites, backgrounds, and UI onto the screen.

## Loading Images

**`pygame.image.load(path)` loads an image and returns a Surface:**

```python
player_img = pygame.image.load("player.png").convert_alpha()
screen.blit(player_img, (300, 200))
```

**Two important methods:**

| Method | Purpose |
|---|---|
| `convert()` | Converts to the screen's pixel format, **speeding up blit** |
| `convert_alpha()` | Converts format **while preserving the alpha (transparency) channel** |

**Rule of thumb**: use `convert()` for opaque images; use `convert_alpha()` for images with transparency (like PNGs with alpha). Converting before blitting makes things faster.

## Crash Scene 1: Wrong Image Path or File Doesn't Exist

```
img = pygame.image.load("nonexistent.png")
```

**Symptom**: `pygame.error: Couldn't open nonexistent.png`.

**Solution**: Use an absolute path or verify the relative path. Relative paths are relative to **the current working directory when the program runs**. A common technique:

```python
import os
base_path = os.path.dirname(__file__)          # Directory containing this .py file
img_path = os.path.join(base_path, "player.png")
img = pygame.image.load(img_path).convert_alpha()
```

**`os.path.dirname(__file__)` gets the script's directory**, then join it with the filename so the image is found regardless of where you run the program.

## Crash Scene 2: Forgetting convert, blit Is Incredibly Slow

```
img = pygame.image.load("big.png")   # No convert
```

**Symptom**: Frame rate visibly drops, especially with large images or many images.

**Why**: The Surface returned by `image.load` may have a pixel format different from the screen, so every blit requires a real-time conversion. `.convert()` does it once upfront, making subsequent blits fast.

**This is basic pygame performance optimization.** Convert images immediately after loading.

## Crash Scene 3: Transparent Image Has Black Edges

```
img = pygame.image.load("player.png").convert()   # Should use convert_alpha
```

**Symptom**: The transparent parts of the PNG turn into black blocks.

**Why**: `convert()` **drops the alpha channel**. Transparent PNGs must use `convert_alpha()`.

## Scaling Images

**`pygame.transform.scale(surface, (new_width, new_height))` scales:**

```python
big_img = pygame.image.load("player.png").convert_alpha()
small_img = pygame.transform.scale(big_img, (50, 50))
```

**`scale` returns a new Surface**; the original is unchanged. Scaling is **lossy** — repeated scaling gets blurry. Compute the target size once.

**`pygame.transform` also has**: `rotate(surface, angle)`, `flip(surface, x, y)` (mirror), and `scale2x` (doubles size, faster).

## Flipping and Rotating

```python
flipped = pygame.transform.flip(img, True, False)   # Horizontal flip
rotated = pygame.transform.rotate(img, 45)          # Rotate 45 degrees counter-clockwise
```

**`flip(surface, xbool, ybool)`**: the two booleans control horizontal/vertical flipping. Useful for character animations where a sprite "faces left or right."

## Rect: A Unified Representation of Position and Size

**pygame commonly uses `pygame.Rect(x, y, width, height)` to represent "a rectangular area."** Rect objects have many useful attributes:

```python
rect = pygame.Rect(100, 50, 80, 60)
rect.x        # 100
rect.y        # 50
rect.width    # 80
rect.height   # 60
rect.center   # (140, 80) center point
rect.centerx  # 140
rect.bottom   # 110
```

**Rect is the foundation of pygame collision detection** (Lesson 23) and a standard container for "image position + size."

## Managing Image Position with Rect

**Bind an image to its own Rect for management:**

```python
player_img = pygame.image.load("player.png").convert_alpha()
player_rect = player_img.get_rect()
player_rect.topleft = (300, 200)

# Move it
player_rect.x += 5

# blit using rect
screen.blit(player_img, player_rect)
```

**`surface.get_rect()` returns a Rect matching the image's size**, initially at (0,0). Then set `topleft`, `center`, etc. for positioning.

**Benefits of managing position with Rect**: pass Rect directly to blit (pygame uses its top-left), and Rect methods work for collision and boundary checks.

## Summary

- Surface = pixel canvas; windows and images are both Surfaces
- `dest.blit(source, (x, y))` pastes source onto dest
- `image.load(path).convert()` for speed; `convert_alpha()` for transparent images
- Always convert after loading; use convert_alpha for transparent images
- `transform.scale/rotate/flip` for scaling and rotating
- Rect manages position and size; it's the basis for collision detection
- Use `os.path.dirname(__file__)` for reliable path resolution
