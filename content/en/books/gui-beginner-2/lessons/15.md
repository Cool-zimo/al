# Progressbar and Progress Feedback: Keeping the Interface Responsive During Long Work

> When a program does background work (downloading, calculating), the user needs a "progress bar" to know how long is left. This lesson covers ttk.Progressbar and the correct way to keep a tkinter interface responsive during long-running work.

## What a Progressbar Is

**A Progressbar displays a progress indicator in either "determinate mode" (known total) or "indeterminate mode" (unknown duration, a scrolling bar).**

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
root.title("Progress Bar")

# Determinate mode: max 100, current value 0
bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100, value=0)
bar.pack(padx=20, pady=20)

root.mainloop()
```

**Parameters:**

| Parameter | Meaning |
|---|---|
| `mode` | `"determinate"` for known progress / `"indeterminate"` for unknown (scrolling bar) |
| `maximum` | Maximum value (the value at 100%) |
| `value` | Current value |
| `length` | Length in pixels |
| `orient` | `"horizontal"` or `"vertical"` |

## Updating Progress

**Update with `bar["value"] = new_value` or `bar.step(increment)`:**

```python
import tkinter as tk
from tkinter import ttk

root = tk.Tk()
bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100, value=0)
bar.pack(padx=20, pady=20)

def start():
    bar["value"] = 0
    update_progress()

def update_progress():
    bar["value"] += 10
    if bar["value"] < 100:
        root.after(200, update_progress)
    else:
        bar["value"] = 100

ttk.Button(root, text="Start", command=start).pack()
root.mainloop()
```

**Use recursive `after` to simulate "stepping forward" without freezing the interface.**

## Indeterminate Mode

**Use this when you do not know how long something will take; the bar scrolls back and forth to indicate "busy":**

```python
bar = ttk.Progressbar(root, mode="indeterminate", length=300)
bar.pack()

def start():
    bar.start(10)      # start scrolling; 10 is the step speed

def stop():
    bar.stop()         # stop

ttk.Button(root, text="Start", command=start).pack()
ttk.Button(root, text="Stop", command=stop).pack()
```

**`start(interval)` makes the bar move; `stop()` halts it.**

## Crash Site One: Long Work Is Done Directly in the Callback, Freezing the Interface

```
def on_click():
    time.sleep(5)              # simulate 5 seconds of work
    label.configure(text="Done")

ttk.Button(root, text="Start", command=on_click).pack()
```

**Symptom:** after clicking, the window freezes for a full 5 seconds; the progress bar does not move, the button is unresponsive, and you may even see a "not responding" message.

**Cause:** `on_click` runs synchronously inside the event loop. Until it returns, the event loop waits. Every apparent "it is running" is an illusion.

**tkinter is single-threaded: long work must either be "handed off" or "split into pieces".**

## Crash Site Two: Using a Thread and Then Touching the Interface Directly

**Offloading the work to a thread is the right idea, but the thread must not modify the interface directly:**

```python
import threading

def worker():
    time.sleep(5)
    bar["value"] = 100         # from a non-GUI thread -> possible crash
```

**Symptom:** `RuntimeError` or random crashes and odd interface behaviour.

**Cause:** tkinter is not thread-safe, so interface operations must happen on the main thread's event loop.

**Correct approach:** when the thread has finished, use `root.after(0, callback)` to register the "update the interface" task on the main thread:

```python
def worker():
    time.sleep(5)
    root.after(0, lambda: bar.configure(value=100))
```

## The Standard Template for Long Work

**A background thread plus an after callback is the standard tkinter pattern for long-running tasks:**

```python
import tkinter as tk
from tkinter import ttk
import threading
import time

root = tk.Tk()
root.title("Download Simulator")

bar = ttk.Progressbar(root, length=300, mode="determinate", maximum=100)
bar.pack(padx=20, pady=10)
label = ttk.Label(root, text="Waiting to start")
label.pack()

def do_work():
    for i in range(1, 101):
        time.sleep(0.05)                     # simulate work
        root.after(0, lambda v=i: bar.configure(value=v))
    root.after(0, lambda: label.configure(text="Complete!"))

def start():
    label.configure(text="In progress...")
    bar["value"] = 0
    thread = threading.Thread(target=do_work, daemon=True)
    thread.start()

ttk.Button(root, text="Start Download", command=start).pack(pady=10)
root.mainloop()
```

**`daemon=True` lets the thread exit with the main thread, so the program can actually close.**

## Using indeterminate for a "Busy" State

**Some operations cannot estimate progress (a network check, searching files). Use indeterminate:**

```python
def search():
    bar.config(mode="indeterminate")
    bar.start(10)
    def done():
        bar.stop()
        bar.config(mode="determinate", value=100)
        label.configure(text="Search complete")
    # Suppose it finishes after 3 seconds
    root.after(3000, done)
```

## Pairing the Bar with a Percentage Label

**Show a percentage number next to the progress bar:**

```python
progress = tk.IntVar(value=0)
label = ttk.Label(root, text="0%")

def update(v):
    bar["value"] = v
    label.configure(text=f"{v}%")
    if v < 100:
        root.after(100, lambda: update(v+5))

update(0)
```

**`IntVar` is tkinter's variable class** (along with StringVar, DoubleVar and BooleanVar) and provides two-way binding between a control and a variable — useful later when building MVC-style code.

## Summary

- The Progressbar has two modes: `determinate` for known progress and `indeterminate` for a busy scrolling bar
- Update with `bar["value"]=...` or `step()`; indeterminate uses `start()`/`stop()`
- **Long work must not run synchronously inside a callback**, or the interface freezes
- The correct pattern: a background thread plus `root.after(0, update_the_interface)`
- tkinter is not thread-safe, so never manipulate the interface directly from another thread
- A thread created with `daemon=True` exits when the main program exits
