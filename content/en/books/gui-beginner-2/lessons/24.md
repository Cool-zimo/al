# Handling Keyboard Input: Continuous Keys and key.get_pressed

> tkinter keys are "press once, fire once" — useless for "hold direction key to keep moving". pygame provides two approaches: event-style (KEYDOWN/KEYUP) and state-style (key.get_pressed). This lesson covers how to use state-style input for smooth continuous movement.

## Two Ways to Handle Keys

**Method 1: Event-style — `KEYDOWN` / `KEYUP` events.** Fires once per press, great for "jump", "fire", "confirm" type discrete actions.

```python
for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:
        if event.key == pygame.K_SPACE:
            player.jump()
```

**Method 2: State-style — `pygame.key.get_pressed()`.** Returns a sequence of "which keys are currently pressed", great for "continuous movement".

```python
keys = pygame.key.get_pressed()
if keys[pygame.K_LEFT]:
    player.rect.x -= 5
if keys[pygame.K_RIGHT]:
    player.rect.x += 5
```

**The difference**: events are "edge-triggered" (the instant of pressing), `get_pressed` is "level-triggered" (true as long as it's held).

## State-Style Movement: Smooth and Continuous

**Complete example: moving the player with arrow keys:**

```python
import pygame

pygame.init()
screen = pygame.display.set_mode((800, 600))
clock = pygame.time.Clock()

player = pygame.Rect(375, 275, 50, 50)
speed = 5

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # State-style input
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player.x -= speed
    if keys[pygame.K_RIGHT]:
        player.x += speed
    if keys[pygame.K_UP]:
        player.y -= speed
    if keys[pygame.K_DOWN]:
        player.y += speed

    # Clamp to screen
    player.clamp_ip(screen.get_rect())

    screen.fill((0, 0, 0))
    pygame.draw.rect(screen, (0, 200, 255), player)
    pygame.display.flip()
    clock.tick(60)

pygame.quit()
```

**`clamp_ip` is a built-in Rect method**: it clamps a Rect inside another Rect, automatically handling boundaries — very convenient.

## Crash Scene 1: Event-Style Keys for Movement = Jerky Motion

```
for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:
        if event.key == pygame.K_RIGHT:
            player.rect.x += 5
```

**Symptom**: Holding the right arrow key makes the player jump in steps, not move continuously.

**Why**: `KEYDOWN` has a system-level repeat delay (about 0.5 seconds before repeat kicks in) — great for typing, terrible for game movement.

**Fix**: Use `pygame.key.get_pressed()` state-style input, checking every frame.

## Crash Scene 2: Using get_pressed But Only Reading It Inside the Event Loop

```
for event in pygame.event.get():
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player.rect.x -= 5
```

**Symptom**: The player moves erratically, extremely unstable.

**Why**: `get_pressed()` must be called **at the start of every frame (outside the event loop)**, not inside it. The event loop only runs when there are events; when there are none, it doesn't execute, causing inconsistent read timing.

**Correct placement:**

```python
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    keys = pygame.key.get_pressed()     # ← After event loop, every frame
    if keys[pygame.K_LEFT]:
        player.rect.x -= speed
    ...
```

## Crash Scene 3: Pressing Two Directions Cancels Out

```
if keys[pygame.K_LEFT]:
    player.x -= speed
if keys[pygame.K_RIGHT]:
    player.x += speed     # Both left and right pressed → net movement 0
```

**This is actually "reasonable" behavior** (pressing both = don't move), not a bug. But if you want "priority" (right wins), use an `elif` chain:

```python
if keys[pygame.K_LEFT]:
    player.x -= speed
elif keys[pygame.K_RIGHT]:
    player.x += speed
```

**Generally diagonal movement (all four directions) is allowed**, so separate `if` statements are more common.

## Crash Scene 4: Using a Non-Existent Key Code

```
if keys[pygame.K_W]:      # It's actually K_w (lowercase)
    ...
```

**Key code constants are** `K_a`, `K_b`, ... `K_z` (lowercase letters), `K_0`~`K_9`, `K_SPACE`, `K_RETURN`, `K_ESCAPE`, `K_UP`, `K_DOWN`, `K_LEFT`, `K_RIGHT`.

**Note that letters are lowercase `K_a`, not `K_A`** (though some uppercase versions work, the standard is `K_a`).

## Frame-Rate-Independent Movement with dt

**Just like Lessons 8 and 20, to make speed consistent across machines, use dt:**

```python
speed = 300          # pixels per second

while running:
    dt = clock.tick(60) / 1000          # Convert to seconds
    for event in pygame.event.get():
        ...
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        player.x -= speed * dt
    if keys[pygame.K_RIGHT]:
        player.x += speed * dt
    ...
```

**`tick(60)` returns milliseconds; divide by 1000 to get seconds.** Displacement = speed (px/s) × time (s).

## Encapsulating Movement Inside a Sprite Class

**Put input handling into the sprite's `update`:**

```python
class Player(pygame.sprite.Sprite):
    def __init__(self):
        super().__init__()
        self.image = pygame.Surface((50, 50))
        self.image.fill((0, 200, 255))
        self.rect = self.image.get_rect(center=(400, 300))
        self.speed = 300        # px/s

    def update(self, keys, dt, bounds):
        if keys[pygame.K_LEFT]:
            self.rect.x -= self.speed * dt
        if keys[pygame.K_RIGHT]:
            self.rect.x += self.speed * dt
        if keys[pygame.K_UP]:
            self.rect.y -= self.speed * dt
        if keys[pygame.K_DOWN]:
            self.rect.y += self.speed * dt
        self.rect.clamp_ip(pygame.Rect(0, 0, *bounds))
```

**When calling, pass keys and dt in**: `player_group.update(keys, dt, (800, 600))`.

## Summary

- Event-style KEYDOWN: discrete actions (jump, fire)
- State-style `key.get_pressed()`: continuous movement (moves while held)
- `get_pressed()` must be called every frame, outside the event loop
- Key codes: `K_LEFT`, `K_a`, `K_SPACE`, etc.
- Frame-rate-independent movement: displacement = speed × dt, dt = tick/1000
- `rect.clamp_ip(rect)` handles boundary clamping in one line
