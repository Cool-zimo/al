# Common Crashes and Debugging: Fixing "Frozen" and "Black Screen"

> The previous lessons covered "how to write it right". This lesson covers "how to fix it when you write it wrong" — windows freezing, images not found, keys unresponsive, and confusing Rect and Surface. These are the four biggest crash scenarios for pygame beginners.

## Crash 1: Window Becomes Unresponsive (Frozen)

**Symptom**: The moment the program runs, the window goes "Not Responding", the cursor spins, and you have to force-quit.

**Most likely cause: forgot to handle the `QUIT` event, or the main loop never even started.**

```python
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:    # ← Missing this
            running = False
    # No flip, no tick
```

**A more insidious freeze: an infinite loop outside the main loop.**

```python
while loading:
    pass                 # Dead wait — nobody consumes the event queue, window will freeze
```

**Why**: Windows/macOS expects your program to **periodically "process messages"**. pygame relies on `pygame.event.get()` to consume system messages. If you run an infinite loop or `time.sleep(10)`, the OS thinks "this window is dead".

**Countermeasure checklist:**

1. The main loop **must have** `for event in pygame.event.get(): if QUIT: running=False`
2. Don't write dead-wait loops like `while True: pass` — use state + a timer instead
3. Don't use `time.sleep` for in-game delays — use `pygame.time.get_ticks()` to calculate time differences
4. Every frame needs `pygame.display.flip()` or `update()`

## Crash 2: Image Path Not Found

**Symptom**: `pygame.error: Couldn't open player.png`.

```python
img = pygame.image.load("player.png")
```

**Why**: The path is **relative to the working directory**, which isn't necessarily the directory containing `main.py`. If you clicked a different folder in VS Code or launched from a different directory in the terminal, the path won't match.

**Countermeasure 1: build an absolute path with `__file__` (recommended).**

```python
import os

base = os.path.dirname(os.path.abspath(__file__))   # Directory containing main.py
path = os.path.join(base, "assets", "player.png")
img = pygame.image.load(path)
```

**`__file__` is the path to the current `.py` file**, `abspath` makes it absolute, `dirname` extracts the directory. So **no matter where you launch from, it's found**, because the anchor is fixed.

**Countermeasure 2: check if it exists before loading.**

```python
if not os.path.exists(path):
    print("Image not found:", path)
    raise SystemExit
```

**Countermeasure 3: use a placeholder Surface when not found (friendlier than crashing).**

```python
def load_image(name):
    path = os.path.join(base, "assets", name)
    if os.path.exists(path):
        return pygame.image.load(path).convert_alpha()
    surf = pygame.Surface((50, 50))
    surf.fill((255, 0, 255))        # Magenta = obvious "image missing" marker
    return surf
```

## Crash 3: Keyboard/Mouse Events "Don't Respond"

**Symptom**: You press a key and nothing happens, even though you wrote the check.

**First suspect: wrong event type.**

```python
for event in pygame.event.get():
    if event.key == pygame.K_SPACE:        # WRONG! Missing event.type check
        jump()
```

**Correct:**

```python
for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:          # First check "key pressed" event
        if event.key == pygame.K_SPACE:
            jump()
```

**Second suspect: continuous input shouldn't use events — use `key.get_pressed()`.**

```python
keys = pygame.key.get_pressed()
if keys[pygame.K_LEFT]:
    player.rect.x -= 4          # Smooth movement while held
```

**Events (`KEYDOWN`) fire "once at the instant of pressing"**; `get_pressed()` is a "snapshot of which keys are currently held". For smooth movement, use the latter.

**Third suspect: the main loop never reached event handling — an infinite loop came first.**

```python
while heavy_computation():      # Takes too long, event queue fills up
    pass
for event in pygame.event.get():   # This line never gets a chance to run
    ...
```

## Crash 4: Confusing Surface and Rect

**First, let's be clear what each is:**

| Concept | What it is | Typical use |
|---|---|---|
| `Surface` | A "pixel canvas" with size and color | Images, blocks, text |
| `Rect` | A rectangular description of "position and size" | Coordinate math, collision, blit position |

**`Surface` handles "what it looks like, how big"; `Rect` handles "where it is, how big". They're stored separately but must work together.**

```python
img = pygame.Surface((60, 60))
img.fill((0, 200, 255))
rect = img.get_rect(center=(400, 300))     # Grab size from Surface, then set position
screen.blit(img, rect)
```

**Fail 1: using a Surface as if it were a Rect.**

```python
img = pygame.Surface((60, 60))
img.x += 5              # AttributeError: 'pygame.Surface' object has no attribute 'x'
```

**Surface has no `x`, `y`, or `collidepoint`.** To move it, move its corresponding `rect`, then blit again using the rect.

**Fail 2: rect moved, but blit still uses the old position.**

```python
rect.x += 5
screen.blit(img, (0, 0))        # Still pasted at top-left
```

**Correct: `blit` uses `rect`, not hardcoded coordinates.**

```python
rect.x += 5
screen.blit(img, rect)
```

**Fail 3: changed Surface size but forgot to sync rect.**

```python
img = pygame.transform.scale(img, (120, 120))
# rect is still (60, 60), collision detection will be wrong
rect = img.get_rect(center=rect.center)      # Recalculate rect, preserve center
```

## Crash Summary Table

| Symptom | First suspicion | How to check |
|---|---|---|
| Window not responding | Didn't handle QUIT / infinite loop | Check event loop, add print to find where it's stuck |
| Black screen but no error | Didn't flip / didn't blit | Confirm flip() every frame, confirm something was blitted |
| Image load error | Wrong path | Build absolute path with `__file__` |
| Key unresponsive | Missing `event.type` / logic infinite loop | Check for KEYDOWN first in events |
| Jerky movement | Used `time.sleep` | Use `get_ticks` for timing |
| Wrong collision | Rect and Surface size out of sync | Recalculate rect after scaling |
| Chinese font garbled | Used default font | Specify a Chinese-capable font file |

## The Three Debugging Tools

**Tool 1: `print` at suspicious spots.**

```python
print("state:", state, "score:", score)
```

**In a windowed program, `print` outputs to the terminal, not the game screen** — it's the most basic debugging technique. Use it to find out "why this branch never runs".

**Tool 2: read the exception traceback.**

```
Traceback (most recent call last):
  File "main.py", line 42, in <module>
    player.rect.x += 5
AttributeError: 'NoneType' object has no attribute 'rect'
```

**Look at the bottom line** — `AttributeError` + `'NoneType'` tells you "player is None". Trace back: who set it to None? Probably a `find` that found nothing, or a `load` that failed and returned None.

**Tool 3: break complex expressions apart.**

```python
# Can't tell which step is wrong
if player.rect.colliderect(enemies.sprites()[0].rect):
    ...

# Break it apart, each step can be printed
enemy_list = enemies.sprites()
print("Enemy count:", len(enemy_list))
enemy = enemy_list[0]
print("enemy.rect:", enemy.rect)
print("Collided:", player.rect.colliderect(enemy.rect))
```

**One expression split into three lines, each line can have a print inserted — the bug reveals itself immediately.**

## Summary

- Window not responding = event queue not being consumed: must handle QUIT + flip/tick every frame, no infinite loops, no sleep
- Image not found = path is relative: build an absolute path with `__file__` for reliability
- Event unresponsive = missing `event.type`, or continuous movement should use `get_pressed()` not KEYDOWN
- Surface handles "appearance + size", Rect handles "position + size", blit uses rect, recalculate rect after scaling
- Three debugging tools: print statements, read the last line of the exception, break complex expressions apart step by step
