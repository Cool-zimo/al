# What Is a Canvas: A Blank Area You Can Draw On

> So far, every widget we have used was a ready-made component — a button is a button, a label is a label. But what if you want to draw a circle, sketch a line, or build a draggable slider? That is where the Canvas comes in. It is the most flexible widget tkinter offers.

## The Canvas Is tkinter's "Drawing Board"

**A Canvas is, at its core, a rectangular blank area on which you can draw arbitrary shapes, place text, and drop in images.** It is the only tkinter widget that says "draw whatever you like."

The labels and buttons we used earlier are like预制 components — their appearance and behaviour are fixed in advance. A Canvas, on the other hand, is a blank sheet of paper. With it you can build progress bars, flowcharts, a simple drawing pad, or even a small game.

**Why do we need it?** Sooner or later you will hit a requirement that standard widgets simply cannot express: a rounded button, a set of annotated points on a picture, a drag-and-drop connector tool. These all rely on the Canvas.

## Creating a Canvas and Showing It

**Like every other widget, you create it first and lay it out afterwards:**

```python
import tkinter as tk

root = tk.Tk()
root.title("My Canvas")

# Create a 400x300 canvas with a white background
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

root.mainloop()
```

When you run this you will see a large white rectangle. At the moment it is empty — **a canvas does not draw anything by itself; it only provides a place to draw.**

Parameter reference:

| Parameter | Meaning |
|---|---|
| `width` / `height` | Canvas width and height in pixels |
| `bg` | Background colour, light grey by default |
| `highlightthickness` | Thickness of the focus border; set it to `0` to hide the dashed frame |

## The Coordinate System: The Origin Is in the Top-Left Corner

**This is the single most important rule for the Canvas: the origin `(0, 0)` sits in the top-left corner. The x-axis grows to the right and the y-axis grows downwards.**

This is different from the coordinate system you may know from mathematics, where the y-axis grows upwards. On a screen, and on a canvas, **the further down you go, the larger the y value becomes.**

```python
# Draw a rectangle whose top-left corner is at (50, 30)
# and whose bottom-right corner is at (200, 120)
canvas.create_rectangle(50, 30, 200, 120, fill="skyblue")
```

The four numbers mean `x1, y1, x2, y2` — **top-left coordinates followed by bottom-right coordinates.**

```python
import tkinter as tk

root = tk.Tk()
canvas = tk.Ck()  # Intentional typo — see the crash section below
```

## Crash Site One: Writing `Ck` or `ck` Instead of `Canvas`

```
AttributeError: module 'tkinter' has no attribute 'Ck'
```

**It is very common to type `tk.Ck()` or `tk.ck()` by accident.** tkinter widget names use `Canvas` — capital C, everything else lowercase. Here is the rule of thumb: **widget names are written in UpperCamelCase**, with the first letter and every subsequent word capitalised (Canvas, Button, Label, Frame, Scale).

The correct form is:

```python
canvas = tk.Canvas(root, width=400, height=300)
```

## Crash Site Two: Reversing the Coordinates and Making the Shape "Disappear"

```
canvas.create_rectangle(300, 250, 50, 30, fill="red")
```

**Symptom:** the canvas comes up completely blank and nothing has been drawn.

**Cause:** although tkinter silently corrects the order to top-left and bottom-right, if your second point lies outside the canvas (for example your canvas is only 300 pixels wide but you start drawing at x=500), the shape ends up outside the visible area.

**Countermeasure:** make it a habit to write `(x1, y1, x2, y2)` with **the smaller coordinates first and the larger ones second**, and never let your coordinates exceed the width and height of the canvas.

## Canvas Size Versus Window Size

**The `width` and `height` of a canvas are fixed pixel values and do not automatically follow a window resize.** If you want the canvas to fill the available space, combine it with `pack(fill="both", expand=True)`. That affects the widget's footprint only; **the internal coordinate system of the canvas stays exactly as it was when you created it.**

```python
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack(fill="both", expand=True)
```

Here `fill="both"` makes the canvas widget occupy its parent container, while `expand=True` lets it stretch when the window grows. But **shapes that have already been drawn are not automatically redrawn or scaled** — this is an important limitation of the Canvas, and you have to handle resizing yourself when building a scalable drawing pad.

## Every Shape Gets an "ID"

**Each time you draw a shape on the canvas, tkinter returns an integer ID.** That ID is the "identity card" you will use to manipulate the shape later:

```python
rect_id = canvas.create_rectangle(10, 10, 100, 80, fill="orange")
print(rect_id)  # prints 1 (the first shape usually gets ID 1)
oval_id = canvas.create_oval(120, 10, 200, 80, fill="green")
print(oval_id)  # prints 2
```

**IDs start at 1 and increase by 1 for each shape you draw.** You can store the ID in a variable and use it later to move, recolour, or delete the shape (we will cover that in the next lesson).

## Summary

- The Canvas is the **only tkinter widget that lets you draw freely**
- Its coordinate origin is the **top-left corner, with the y-axis growing downwards**
- Rectangles and shapes use `(x1, y1, x2, y2)` for the top-left and bottom-right corners
- The canvas size is fixed; scaling has to be handled by you
- Every shape returns a unique ID, which acts as its identity card for later operations
- Widget names use UpperCamelCase: write `tk.Canvas`, not `tk.Ck`
