# Movement and Boundaries: Velocity Vectors and Boundary Detection

> Last lesson covered Sprites. This lesson makes "movement" more规范: managing motion with velocity vectors (vx, vy), encapsulating boundary detection into methods, and keeping sprite movement logic clean and reusable.

## Velocity Vectors: vx and vy

**Splitting "speed" into horizontal and vertical components is more flexible than a single speed value:**

```python
class Ball(pygame.sprite.Sprite):
    def __init__(self):
        super().__init__()
        self.image = pygame.Surface((30, 30))
        self.image.fill((255, 255, 255))
        self.rect = self.image.get_rect(center=(400, 300))
        self.vx = 4
        self.vy = 3

    def update(self):
        self.rect.x += self.vx
        self.rect.y += self.vy
```

**`vx > 0` means right, `vx < 0` means left; `vy > 0` means down, `vy < 0` means up.** With two independent components, you can achieve diagonal movement in any direction.

## Boundary Detection: Bounce vs. Wrap vs. Disappear

**There are three common ways to handle hitting a boundary:**

| Style | How | Typical Use |
|---|---|---|
| Bounce | `vx = -vx` or `vy = -vy` | Pinball, pong |
| Wrap | Exits right → appears on left | Space games, scrolling |
| Disappear | `self.kill()` | Bullets leaving screen |

## Bounce: Encapsulated as a Method

**Write boundary detection as a method on the sprite itself for cohesive logic:**

```python
class Ball(pygame.sprite.Sprite):
    def __init__(self, x, y):
        super().__init__()
        self.image = pygame.Surface((30, 30))
        self.image.fill((255, 255, 255))
        self.rect = self.image.get_rect(center=(x, y))
        self.vx = 4
        self.vy = 3

    def update(self, bounds):
        """bounds is (width, height) representing screen size"""
        self.rect.x += self.vx
        self.rect.y += self.vy

        w, h = bounds
        # Horizontal boundaries
        if self.rect.left <= 0:
            self.rect.left = 0
            self.vx = abs(self.vx)
        elif self.rect.right >= w:
            self.rect.right = w
            self.vx = -abs(self.vx)
        # Vertical boundaries
        if self.rect.top <= 0:
            self.rect.top = 0
            self.vy = abs(self.vy)
        elif self.rect.bottom >= h:
            self.rect.bottom = h
            self.vy = -abs(self.vy)
```

**The `bounds` parameter makes this method reusable without hardcoding 800/600.**

## Crash Scene 1: After Bouncing, Ball Gets Stuck in the Wall

```
if self.rect.right >= w:
    self.vx = -self.vx      # Only flips sign, doesn't push the ball out
```

**Symptom**: At high speeds the ball gets stuck in the right wall, flipping back and forth frantically.

**Why**: The ball has already "entered" the wall (rect.right > w); just flipping velocity means next frame it's still inside, still trending right (or just reversed back into the wall) — repeated bouncing.

**Fix**: Push the ball out **while** flipping the velocity:

```python
if self.rect.right >= w:
    self.rect.right = w       # First, push position back to the boundary
    self.vx = -abs(self.vx)   # Then ensure direction is outward (left)
```

**`self.rect.right = w` forces a legal position; `-abs(self.vx)` ensures a definite outward direction.** Together, it never gets stuck.

## Crash Scene 2: Using rect.x for Right Boundary Check

```
if self.rect.x >= w:         # rect.x is the top-left corner
    self.vx = -self.vx
```

**When the ball is 30px wide, `rect.x` reaching w means the ball has "completely exited the screen".** Correctly use `self.rect.right` (= x + width).

**Remember Rect's boundary attributes**: `left`, `right`, `top`, `bottom`, `centerx`, `centery`.

## Wrap: Appearing on the Other Side After Leaving

**"Wrapping" is a common technique in space shooters and snake games:**

```python
def update_wrap(self, w, h):
    self.rect.x += self.vx
    self.rect.y += self.vy
    if self.rect.left > w:
        self.rect.right = 0        # Appear on the left
    elif self.rect.right < 0:
        self.rect.left = w
    if self.rect.top > h:
        self.rect.bottom = 0
    elif self.rect.bottom < 0:
        self.rect.top = h
```

**`rect.right = 0` makes the right edge sit at x=0, so the ball perfectly enters from the left.**

## Disappear: Killing Sprites That Leave the Screen

**Bullets and particles that leave the screen should be cleaned up**, otherwise the Group keeps accumulating objects and gets slower.

```python
def update_bullet(self, h):
    self.rect.y += self.vy
    if self.rect.top > h or self.rect.bottom < 0:
        self.kill()         # Remove from all Groups
```

**`self.kill()` removes the sprite from all Groups it belongs to.** After that, `group.update()`/`draw()` won't process it, and memory is freed.

## Changing Speed: Acceleration and Deceleration

**Give a sprite an "acceleration" attribute for gradually getting faster/slower:**

```python
class Car(pygame.sprite.Sprite):
    def __init__(self):
        super().__init__()
        self.image = pygame.Surface((60, 30))
        self.image.fill((0, 200, 255))
        self.rect = self.image.get_rect(center=(100, 300))
        self.vx = 0
        self.ax = 0.2           # Acceleration

    def update(self):
        self.vx += self.ax      # Continuously accelerate
        self.rect.x += self.vx
        if self.rect.left > 800:
            self.rect.right = 0
            self.vx = 0         # Reset speed
```

**Watch out for floating-point precision**: Rect's x/y only store integers, so long-term accumulation of small decimals loses precision. For precise movement, store `self.x = 100.0`, calculate each frame, then sync with `self.rect.x = int(self.x)`.

## Summary

- Split speed into `vx`/`vy` components for movement in any direction
- Three boundary styles: bounce, wrap, disappear (kill)
- Bouncing requires "push to boundary + ensure outward direction" to avoid wall sticking
- Use `rect.left/right/top/bottom` for boundary checks
- `self.kill()` removes a sprite, cleaning up off-screen objects
- Use acceleration for speed changes; watch floating-point precision
