# Keyboard Control: Binding Key Events to Move a Square with the Arrow Keys

> Games need keyboard control. This lesson covers tkinter's keyboard-event bindings and builds a square that moves using the arrow keys.

## The Three Binding Targets for Keyboard Events

**A keyboard event can be bound to "a specific widget" or to "the whole window (root)".** The difference is that a binding on a widget only fires when that widget has focus (is selected), whereas a binding on root works globally.

```python
import tkinter as tk

root = tk.Tk()
root.title("Keyboard Movement")

def on_key(event):
    print("Pressed:", event.keysym)

# Bound on root: works globally
root.bind("<Key>", on_key)
root.mainloop()
```

**Key attributes of the event object:**

| Attribute | Meaning |
|---|---|
| `event.keysym` | Symbolic name of the key, such as `"Left"`, `"a"`, `"Return"`, `"space"` |
| `event.keycode` | Numeric code of the key (may differ by platform) |
| `event.char` | The printable character, such as `"a"` or `"!"`; arrow keys have none |

## Common Key Names

**Arrow keys and special keys use symbolic names:**

| Event string | Corresponding key |
|---|---|
| `<Left>` / `<Right>` / `<Up>` / `<Down>` | Arrow keys |
| `<Return>` | Enter |
| `<space>` | Space |
| `<Escape>` | Esc |
| `<Key>` | Any key |
| `<KeyPress-a>` | The letter a (case-sensitive) |
| `<Control-c>` | Ctrl+C |

**You can also write `<KeyPress>` (press) and `<KeyRelease>` (release).**

## Step 1: Draw a Square

```python
import tkinter as tk

root = tk.Tk()
root.title("Arrow-Key Movement")
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

rect = canvas.create_rectangle(180, 130, 220, 170, fill="dodgerblue")
```

## Step 2: Bind the Arrow Keys

**Bind one function to each arrow key and move with `move`:**

```python
step = 10

def move_left(event):
    canvas.move(rect, -step, 0)

def move_right(event):
    canvas.move(rect, step, 0)

def move_up(event):
    canvas.move(rect, 0, -step)

def move_down(event):
    canvas.move(rect, 0, step)

root.bind("<Left>", move_left)
root.bind("<Right>", move_right)
root.bind("<Up>", move_up)
root.bind("<Down>", move_down)

root.mainloop()
```

**Run it: press the arrow keys and the square moves by the step size.**

## Crash Site One: Bound on the Canvas, but the Canvas Has No Focus

```
canvas.bind("<Left>", move_left)   # nothing happens when you press the arrow keys
```

**Symptom:** the binding is there, but pressing the arrow keys does not move the square.

**Cause:** focus is on another widget or window. A Canvas binding only fires when the Canvas itself has focus.

**Fix:** bind on `root`, or give the Canvas focus:

```python
root.bind("<Left>", move_left)   # bind on root for global effect
# or
canvas.focus_set()               # give the canvas focus
```

**In a game you almost always bind on `root`** to avoid focus problems.

## Crash Site Two: A Function With an Extra Parameter That Has Nothing to Pass

```
root.bind("<Left>", move_left)

def move_left(event, step=10):   # extra default parameter is fine
    ...
```

```
def move_left(event, direction):  # error
    ...
root.bind("<Left>", move_left)
```

**Symptom:** `TypeError: move_left() missing 1 required positional argument: 'direction'`.

**Cause:** `bind` only passes one `event` argument when it calls your function. Your function cannot receive extra arguments from `bind`.

**Solution:** use a `lambda` or default values:

```python
def move_rect(event, dx, dy):
    canvas.move(rect, dx, dy)

root.bind("<Left>", lambda e: move_rect(e, -10, 0))
root.bind("<Right>", lambda e: move_rect(e, 10, 0))
```

**This pattern also appears in pygame (continuous keypress handling in Lesson 24).**

## Crash Site Three: The Square Moves Off the Canvas

**If you keep pressing an arrow key, the square leaves the canvas and disappears. Use `coords` to read its position and clamp it:**

```python
def move_left(event):
    x1, y1, x2, y2 = canvas.coords(rect)
    if x1 > 0:                    # only move left while still inside
        canvas.move(rect, -step, 0)
```

**A stricter version:**

```python
def move_left(event):
    x1, y1, x2, y2 = canvas.coords(rect)
    new_x = max(0, x1 - step)     # never below 0
    canvas.coords(rect, new_x, y1, new_x + (x2-x1), y2)
```

**Absolute positioning with `coords` plus `max/min` clamping is the universal technique for keeping a game object inside its bounds.**

## Handling It All With a Dictionary

**Four directions and four functions is verbose; a dictionary can map key names to offsets:**

```python
step = 10
key_map = {
    "Left":  (-step, 0),
    "Right": (step, 0),
    "Up":    (0, -step),
    "Down":  (0, step),
}

def on_key(event):
    dx, dy = key_map.get(event.keysym, (0, 0))
    canvas.move(rect, dx, dy)

root.bind("<Key>", on_key)
```

**`event.keysym` is exactly the string `"Left"` and so on, which matches the dictionary keys.** This "lookup table" approach is very clean when handling many inputs.

## Using dt to Make Movement Frame-Rate Independent

**Combined with the delta time from the previous lesson, instead of "jump 10 pixels per keypress" you can make the square move "200 pixels per second":**

```python
import time

speed = 200.0
rect_x, rect_y = 180.0, 130.0
last_time = time.time()

def on_key(event):
    global rect_x, rect_y, last_time
    now = time.time()
    dt = now - last_time
    last_time = now
    if dt > 0.1:
        dt = 0
    dx, dy = key_map.get(event.keysym, (0, 0))
    rect_x += dx * speed * dt / 10    # here dx is a direction of +/-1
    rect_y += dy * speed * dt / 10
    canvas.coords(rect, rect_x, rect_y, rect_x+40, rect_y+40)
```

**But note:** keyboard events fire discretely (once per press), not every frame like an animation. dt is of limited use here; the more common case is pygame's "continuous keypress" handling (Lesson 24).

## Summary

- Keyboard event: `root.bind("<Key>", handler)`; the event object has `keysym`, `keycode` and `char`
- Arrow keys are `<Left>` / `<Right>` / `<Up>` / `<Down>`; Enter is `<Return>` and space is `<space>`
- Binding on `root` works globally; binding on a widget requires that widget to have focus
- The handler takes one `event` parameter; for more arguments use `lambda`
- Boundary clamping: read the position with `coords` and apply `max/min`
- Multiple keys are tidier when handled with a dictionary lookup
