# Making Shapes Move: after Plus move, and a Bouncing Ball

> In the previous lesson we learned `after`; in this one we use it to build a complete animation — a ball that bounces around inside the canvas. The whole recipe is "nudge it a little each frame and bounce on contact".

## What Animation Really Is: Frames

**Animation = move the shape a little at fixed time intervals and redraw it.** The persistence of vision in the human eye joins those consecutive frames into "motion".

```
Frame 1: ball is at x=10
Frame 2: ball is at x=15
Frame 3: ball is at x=20
...
```

**A "frame" is one complete cycle of "move plus redraw".** In tkinter, `move` already triggers a redraw implicitly, so as long as you keep moving, the picture animates.

## Step 1: Draw a Ball

**A ball is just a circle (an oval). Let us put one on the canvas:**

```python
import tkinter as tk

root = tk.Tk()
root.title("Bouncing Ball")
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

# Ball: bounding box (30,30)-(70,70), radius about 20
ball = canvas.create_oval(30, 30, 70, 70, fill="tomato")
```

## Step 2: Give It a Velocity

**Define a global variable `dx` for "how many pixels the ball moves in the x direction per frame":**

```python
dx = 4   # 4 pixels right per frame
dy = 3   # 3 pixels down per frame
```

**Use `coords()` to read the current position and decide whether to bounce:**

```python
def animate():
    global dx, dy
    canvas.move(ball, dx, dy)

    # Read the current coordinates
    x1, y1, x2, y2 = canvas.coords(ball)

    # Hit the right wall: x2 has reached the canvas width
    if x2 >= 400 or x1 <= 0:
        dx = -dx          # reverse horizontally
    # Hit the bottom or top wall
    if y2 >= 300 or y1 <= 0:
        dy = -dy          # reverse vertically

    root.after(20, animate)   # about 50 frames per second

animate()
root.mainloop()
```

**The secret of a bounce is to negate the velocity:** when the ball hits the right wall, `dx = -dx` sends it back to the left.

## Complete Code

```python
import tkinter as tk

root = tk.Tk()
root.title("Bouncing Ball")
canvas = tk.Canvas(root, width=400, height=300, bg="white")
canvas.pack()

ball = canvas.create_oval(30, 30, 70, 70, fill="tomato")
dx, dy = 4, 3

def animate():
    global dx, dy
    canvas.move(ball, dx, dy)
    x1, y1, x2, y2 = canvas.coords(ball)

    if x2 >= 400 or x1 <= 0:
        dx = -dx
    if y2 >= 300 or y1 <= 0:
        dy = -dy

    root.after(20, animate)

animate()
root.mainloop()
```

**Run it: a red ball bounces around the window, reversing direction whenever it hits an edge.**

## Why We Use coords to Check the Boundary

**You might wonder: why not track a "ball position variable" and test the boundary against that?**

Because after `move`, the ball's actual coordinates are managed inside the Canvas. Reading them with `coords()` is always accurate. **Keep the data source single:** the coordinates live in the Canvas, and we only read them when we need them.

**This approach also supports "many balls at once" naturally** — each ball reads its own coordinates, with no interference.

## Crash Site One: The Ball Gets "Stuck" Outside the Wall

```
if x2 > 400:
    dx = -dx
```

**Symptom:** the ball behaves normally at low speed, but at a high speed (say `dx=20`) it flies off screen and never comes back.

**Cause:** when `dx` is large, `x2` jumps well past 400 (to 430, for example). On the next frame `x2 >= 400` is true and `dx` reverses, so the ball heads back. But if the condition is written too narrowly, or the ball has gone too far past the wall, it may take several frames to come back, making it look stuck.

**Fix:** write the boundary check with "greater-or-equal / less-or-equal" so it tolerates a ball that has overshot slightly:

```python
if x2 >= 400 or x1 <= 0:
    dx = -dx
```

## Crash Site Two: Using while True for the Animation

```
while True:
    canvas.move(ball, dx, dy)
    root.update()     # some suggest update instead of sleep
    time.sleep(0.02)
```

**Symptom:** it moves, but the window lags when dragged, buttons stop responding, and it cannot be closed.

**Cause:** `while True` hijacks the event loop. `root.update()` only forces one redraw; it is not a real event loop, and many events (window resizing, closing) are handled incompletely. **The official recommendation is always to use `after`.**

## Crash Site Three: after Set Too Short or Too Long

```
root.after(200, animate)   # 5 frames per second, visibly jumpy
root.after(1, animate)     # too fast, maxes out the CPU
```

**Rule of thumb:** `after(16, ...)` is roughly 60 frames per second, `after(20, ...)` about 50 fps, and `after(33, ...)` about 30 fps.

**tkinter's precision is limited** — setting the interval to 1 ms does not actually produce 1 ms frames; it just makes Python spin and consume CPU. Anything from 15 to 30 ms is usually smooth enough.

## Making the Ball Slow Down (Adding Friction)

**In the real world a ball slows down. Multiplying the velocity by a factor below 1 simulates that:**

```python
def animate():
    global dx, dy
    canvas.move(ball, dx, dy)
    x1, y1, x2, y2 = canvas.coords(ball)
    if x2 >= 400 or x1 <= 0:
        dx = -dx * 0.98     # lose 2% of speed on each bounce
    if y2 >= 300 or y1 <= 0:
        dy = -dy * 0.98
    root.after(20, animate)
```

**`0.98` is the "restitution coefficient"**; the closer it is to 1, the longer the ball keeps bouncing. A negative value would accelerate it in reverse (do not do that).

## Multiple Balls: Wrap the Logic in Functions

**To have several balls at once, write the logic for "one ball" as a function and let each one manage its own ID and velocity:**

```python
balls = []   # stores (id, dx, dy)

def make_ball(x, y, color, dx, dy):
    ball = canvas.create_oval(x, y, x+30, y+30, fill=color)
    balls.append([ball, dx, dy])

def animate():
    for ball, dx, dy in balls:
        canvas.move(ball, dx, dy)
        x1, y1, x2, y2 = canvas.coords(ball)
        if x2 >= 400 or x1 <= 0:
            dx = -dx
        if y2 >= 300 or y1 <= 0:
            dy = -dy
    root.after(20, animate)
```

**Here each ball stores `(id, dx, dy)` as a list**, because the velocity changes and a mutable object is convenient. Lesson 9 will manage this state more cleanly when we introduce "frame-rate independence".

## Summary

- Animation = move a little each frame and redraw, driven by `after`
- `move` plus `coords` to read the position, plus a boundary check, plus reversing the velocity, equals a bounce
- The core bounce is `dx = -dx` and `dy = -dy`
- Do not use `while True` or `time.sleep`; use recursive `after`
- An `after` interval of 15-30 ms is usually smooth enough
- Friction: on a bounce, multiply by `dx = -dx * 0.98`
