# The Entry Form: Label + Entry + Combobox + Button

> The table is working. This lesson builds the bottom entry area: four input controls for date, amount, category and note, plus an "Add entry" button. The form is where the user interacts with the software most often, so getting it right decides the whole experience.

## Form Layout With grid

**The bottom entry area is a "one row, many columns" alignment problem, and `grid` fits it perfectly:**

```python
form = tk.Frame(root, padx=8, pady=8)

tk.Label(form, text="Date").grid(row=0, column=0, sticky="w")
tk.Label(form, text="Amount").grid(row=0, column=2, sticky="w")
tk.Label(form, text="Category").grid(row=0, column=4, sticky="w")
tk.Label(form, text="Note").grid(row=0, column=6, sticky="w")

date_var = tk.StringVar(value="2026-09-27")
amt_var = tk.StringVar()
cat_var = tk.StringVar()
note_var = tk.StringVar()

tk.Entry(form, textvariable=date_var, width=12).grid(row=1, column=0, padx=4)
tk.Entry(form, textvariable=amt_var, width=10).grid(row=1, column=2, padx=4)

cat_cb = ttk.Combobox(form, textvariable=cat_var, width=9,
                      values=("Food","Transport","Shopping","Housing","Salary","Other"),
                      state="readonly")
cat_cb.grid(row=1, column=4, padx=4)
cat_cb.set("Food")                      # Default selection

tk.Entry(form, textvariable=note_var, width=24).grid(row=1, column=6, padx=4)

tk.Button(form, text="+ Add entry", command=on_add).grid(row=1, column=8, padx=8)

form.pack(side="bottom", fill="x")
```

**grid's two rows have distinct jobs:** row 0 holds the labels, row 1 holds the controls, keeping everything aligned vertically. `sticky="w"` makes the label stick to the left edge of its cell.

## Why Use StringVar

**`textvariable` binds a control's value to a variable, so "reading it means just reading it":**

```python
amt_var.get()      # Read the Entry's current content as a string
amt_var.set("0")   # Clear it or prefill it
```

**It is also possible to skip StringVar and just call `entry.get()`.** The advantage of StringVar is: when several controls or several places need to share one value, changing it once takes effect everywhere; and clearing the form with `amt_var.set("")` is one line instead of `entry.delete(0, "end")`.

**This project uses StringVar** because after an entry is saved every box must be cleared, and managing them through variables is tidier.

## Combobox With state="readonly"

**Category uses a dropdown, but the user should choose rather than type freely:**

```python
cat_cb = ttk.Combobox(form, textvariable=cat_var, state="readonly", ...)
```

**Why readonly?** Because allowing free text would let the user create "Food", "lunch" and "food" as three different categories, which breaks the statistics entirely (stressed back in the sketch lesson).

**The trade-off:** in readonly mode it is not possible to show a placeholder like "please choose a category". The solution is to set `cat_cb.set("Food")` as the default, or handle the focus event yourself to show placeholder text.

## The Button Callback: Read First, Then Act

**The `+ Add entry` callback has three jobs:**

```python
def on_add():
    date = date_var.get().strip()
    amt = amt_var.get().strip()
    cat = cat_var.get().strip()
    note = note_var.get().strip()

    # 1. Hand off to the logic layer for validation
    ok, msg = logic.validate(date, amt, cat)
    if not ok:
        mb.showerror("Invalid input", msg)
        return

    # 2. Hand off to the data layer to store
    rtype = "expense"                     # Simplified: expense by default; a radio can be added later
    db.add_record(conn, float(amt), cat, date, note, rtype)

    # 3. Refresh the table and clear the form
    ui.refresh_table(tree, conn)
    date_var.set("")                      # Keep the date? Product decision
    amt_var.set("")
    note_var.set("")
    # Leave cat_var at the last choice to reduce重复 work
```

**Keep callbacks short** — read, call the logic layer, call the data layer, refresh. Business logic lives in logic.py, not in the callback.

## Prefilling Today's Date

**Defaulting the date box to today saves the user a step:**

```python
from datetime import date
date_var = tk.StringVar(value=date.today().isoformat())   # "2026-09-27"
```

**`date.today().isoformat()` conveniently returns `YYYY-MM-DD`**, matching the format stored in the database — no manual typing required.

## Crash Site 1: Mixing grid and pack in the Same Parent

```python
tk.Label(form, text="Date").grid(row=0, column=0)
tk.Entry(form, textvariable=date_var).pack()    # Mixed!
```

**Symptom:** widgets either fail to appear or the layout breaks; you may even see `cannot use geometry manager grid inside ... which already has slaves managed by pack`.

**Cause:** two geometry managers in the same parent (form), so tkinter does not know which to obey.

**Fix:** pick exactly one per parent. The outer Frame uses pack for blocking; the inner form uses grid for alignment. Draw the line clearly.

## Crash Site 2: Combobox Allows Free Text, Polluting the Categories

```python
cat_cb = ttk.Combobox(form, textvariable=cat_var, values=(...))  # state missing
cat_cb.set("")   # The user can type anything
```

**Symptom:** the database fills up with near-duplicate categories — "Food", "lunch", "food" all count separately, and the pie chart shatters into tiny slices.

**Cause:** the default `state="normal"` allows editing.

**Fix:** `state="readonly"` forces a choice from the list. When users genuinely need to add a category, build a separate "manage categories" feature rather than letting them type it into the entry box.

## Crash Site 3: Forgetting to Refresh, So the User Thinks Nothing Was Saved

```python
def on_add():
    db.add_record(conn, float(amt), cat, date, note, "expense")
    # refresh_table forgotten
    mb.showinfo("Saved", "Save successful")   # The user sees the popup but the table is unchanged
```

**Symptom:** the popup says "saved", but the table shows no new record. The user clicks "Add entry" repeatedly and ends up with duplicates.

**Cause:** the table was not refreshed, so it and the data are out of sync.

**Fix:** refresh the table after every write. A later lesson uses the observer pattern to automate this; for now, call `refresh_table` by hand.

## Summary

- The entry area uses grid: labels on row 0, controls on row 1, neatly aligned
- StringVar manages input values centrally; clear with .set("") in one line
- Combobox uses state="readonly" to stop free text polluting the categories
- The button callback stays short: read values, validate, store, refresh
- Prefill the date with today's date to reduce work for the user
- One parent container gets one geometry manager; never mix grid and pack
