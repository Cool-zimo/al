# Deleting and Editing: Select a Row, Confirm, Act, Refresh

> Entry is done. This lesson adds the two remaining operations: delete and edit. They share one requirement: "select a row first". So the focus is the Treeview selection mechanism, and why the iid must be the database id.

## Selecting a Row: `selection`

**A Treeview's `selection()` returns a tuple of the currently selected row iids (possibly many):**

```python
sel = tree.selection()
if not sel:
    mb.showwarning("Notice", "Please select a record first")
    return
rid = int(sel[0])          # the iid is the database id we set
```

**Three preconditions, none optional:**

1. **Insert with `iid=str(r["id"])`** (stressed in lesson 12).
2. **Single-select only:** create the Treeview with `selectmode="browse"` (the default, one at a time).
3. **Warn when nothing is selected**, otherwise `int(sel[0])` raises `IndexError`.

**The three `selectmode` values:**

| Value | Behaviour |
|---|---|
| `"browse"` | Single select (default), the usual choice. |
| `"extended"` | Multi-select (Ctrl/Shift to grab several rows). |
| `"none"` | Selecting is disabled. |

## Delete: Confirm, Then DELETE and Refresh

**The full flow:**

```python
def on_delete():
    sel = app["tree"].selection()
    if not sel:
        mb.showwarning("Notice", "Please select a record first")
        return
    rid = int(sel[0])

    ok = mb.askyesno("Confirm delete",
                     "Delete this record?\nThis cannot be undone.")
    if not ok:
        return

    conn = db.get_conn()
    n = db.delete_record(conn, rid)
    if n == 0:
        mb.showerror("Delete failed", f"No record with id {rid} was found, it may already be deleted")
        return

    app["status_var"].set("Deleted one record")
    root.after(3000, lambda: app["status_var"].set("Ready"))
    refresh_table(app["tree"], app["empty_label"], conn)
```

**`askyesno` is the confirmation dialog**, returning True or False. Irreversible operations like delete, wipe, and reset must all use one.

**`delete_record` returns the `rowcount`**, and 0 means nothing was deleted — perhaps another process got there first, or the id is off. Refreshing the table afterwards is the safest move.

## Edit: Double-Click or Hit a Button to Open an Edit Window

**Editing is a touch harder: you must copy the selected row back into the form, change it, then UPDATE.**

**Two interaction designs:**

1. **Click "Edit", copy the values into the bottom entry area, and temporarily turn "+ Add entry" into "Save changes"** — small change, no popup, ideal for a simple ledger.
2. **Double-click a row to open a Toplevel edit window** — more "professional", but you then handle modality and focus.

**This project uses the first (lighter) option.** The trick is one flag that distinguishes "add" from "edit":

```python
app["editing_id"] = None          # None means we are in add mode

def on_edit():
    sel = app["tree"].selection()
    if not sel:
        mb.showwarning("Notice", "Please select a record first")
        return
    rid = int(sel[0])
    conn = db.get_conn()
    r = db.get_by_id(conn, rid)   # SELECT ... WHERE id=?
    if r is None:
        mb.showerror("Error", "Record not found")
        return
    # copy back into the form
    app["date_var"].set(r["date"])
    app["amt_var"].set(str(r["amount"]))
    app["cat_var"].set(r["category"])
    app["note_var"].set(r["note"] or "")
    app["type_var"].set(r["type"])
    app["editing_id"] = rid
    app["submit_btn"].config(text="Save changes")

def on_submit():                  # was on_add, renamed and reused
    # ... read values, validate ...
    conn = db.get_conn()
    if app["editing_id"] is not None:
        rid = app["editing_id"]
        db.update_record(conn, rid, float(amt), cat, date, note, rtype)
        app["status_var"].set(f"Updated, record #{rid}")
        app["editing_id"] = None
        app["submit_btn"].config(text="+ Add entry")
    else:
        db.add_record(conn, float(amt), cat, date, note, rtype)
        app["status_var"].set("Saved")
    refresh_table(...)
    _clear_form()
```

**One flag, `editing_id`, distinguishes the two modes**, and the button label changes with it so the user always knows whether they are adding or editing.

## Double-Click a Row to Edit

**An even handier trick: double-clicking a row drops you straight into edit mode:**

```python
app["tree"].bind("<Double-1>", lambda e: on_edit())
```

**`<Double-1>` is the "double-click left button" event.** Once bound, any double-click on a row starts editing — no select-then-click-button dance.

## Crash Site 1: No iid Was Set, So `selection` Returns Garbage

```python
tree.insert("", "end", values=(...))    # no iid passed
sel = tree.selection()
rid = int(sel[0])                        # ValueError: invalid literal for int()
```

**Symptom:** `ValueError: invalid literal for int() with base 10: 'I001'`.

**Cause:** without an iid, the Treeview auto-generates an internal id like `"I001"`, which cannot be converted to int.

**Fix:** pass `iid=str(r["id"])` when inserting.

## Crash Site 2: Deleting With Nothing Selected Hits `IndexError`

```python
def on_delete():
    sel = tree.selection()
    rid = int(sel[0])        # IndexError: tuple index out of range
```

**Symptom:** `IndexError`, because `sel` is the empty tuple `()`.

**Cause:** the empty case was never checked.

**Fix:** `if not sel: mb.showwarning(...); return`.

## Crash Site 3: Forgetting to Restore the Button Label After Editing

**Symptom:** after editing one record, the button still reads "Save changes". The next time the user wants to add, clicking it turns into "edit that same one" — `editing_id` is still set.

**Cause:** the state was never reset when the operation ended.

**Fix:** reset `editing_id = None`, restore the button label, and clear the form whenever a submit finishes or the user clicks "cancel edit". A dedicated Cancel button is a good place to do all three.

## Summary

- Before deleting or editing, use `tree.selection()` to get the selected row's iid, and always check for empty.
- The iid must be the database id, otherwise you cannot locate the record.
- Delete is irreversible, so always confirm with `askyesno`.
- Use `editing_id` as a flag to separate add mode from edit mode, and change the button label with it.
- Double-click to edit: `tree.bind("<Double-1>", ...)`.
- Reset state at the end (editing_id, button label, form).
