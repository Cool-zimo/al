# Summarising by Category with SQL GROUP BY

> Statistics start here. Requirement F3 is "see where the money went", and the first step is to aggregate the data into "how much was spent in each category". We have two routes: SQL's GROUP BY and pandas. This lesson covers the SQL route — it lives in the standard library, with zero dependencies.

## The Need: Category Totals

**Users want to know how much they spent this month and where it went.** The result should look like this:

```
Food       1280.50
Transport    340.00
Shopping     856.00
Housing     1500.00
```

**With this table in hand you can draw a pie chart or a bar chart.** Aggregation is the bedrock of statistics.

## GROUP BY: One SQL Statement Does It

**Sum by category:**

```python
cur.execute("""
    SELECT category, SUM(amount) AS total
    FROM records
    WHERE type = 'expense'
    GROUP BY category
    ORDER BY total DESC
""")
rows = cur.fetchall()
for cat, total in rows:
    print(f"{cat:6s} {total:>10.2f}")
```

**Result:**

```
Housing     1500.00
Food       1280.50
Shopping    856.00
Transport   340.00
```

**Four keywords, four jobs:**

| Clause | Job |
|---|---|
| `WHERE type='expense'` | Look at expenses only (exclude income). |
| `GROUP BY category` | Group rows, pooling amounts in the same category. |
| `SUM(amount)` | Sum each group. |
| `ORDER BY total DESC` | Largest first, so you see the big costs. |

## Why Not pandas

**You may have heard of pandas, the data-analysis powerhouse, where `df.groupby('category')['amount'].sum()` gives you the answer in one line.** We are not using it here, and the reasons matter:

1. **pandas is not in the standard library** — `pip install pandas` would inflate the package size by dozens of MB.
2. **Our data set is tiny** (a personal ledger has hundreds of rows), and SQL returns in milliseconds; pandas performance is overkill.
3. **SQL GROUP BY is a skill that transfers to every database**, so this is the moment to really learn it.

**Always ask whether a third-party library earns its keep.** Charts (matplotlib) we must import because tkinter cannot draw a pie chart; aggregation works perfectly in SQL, so a second dependency is unjustified.

## Monthly Totals: DATE Can Be Grouped Too

**Spending per month:**

```python
cur.execute("""
    SELECT substr(date, 1, 7) AS month, SUM(amount) AS total
    FROM records
    WHERE type = 'expense'
    GROUP BY month
    ORDER BY month
""")
# result:
# 2026-07   3200.00
# 2026-08   2560.00
# 2026-09   3976.50
```

**`substr(date, 1, 7)` takes the first 7 characters of `YYYY-MM-DD`**, which is exactly the month key. This is another win for lesson 2's decision to store dates as `YYYY-MM-DD` — the big unit comes first, so a substring naturally gives you "by month".

**Store a date as `27/09/2026` and you must pull it apart and reorder it before grouping by month — far messier.**

## Income and Expenses in One Table

**One table showing income and expenses side by side:**

```python
cur.execute("""
    SELECT category,
           SUM(CASE WHEN type='income' THEN amount ELSE 0 END) AS income,
           SUM(CASE WHEN type='expense' THEN amount ELSE 0 END) AS expense
    FROM records
    GROUP BY category
""")
# result:
# category   income   expense
# Salary     8000.00     0.00
# Food          0.00  1280.50
# Transport     0.00   340.00
```

**`CASE WHEN` is SQL's conditional expression** — it makes SUM add up only the rows that match. This trick is indispensable for cross-tab statistics.

## Wrap Aggregation in Functions

**The logic layer owns the aggregation:**

```python
# logic.py
def summarize_by_category(conn, rtype="expense"):
    cur = conn.cursor()
    cur.execute("""
        SELECT category, SUM(amount) AS total
        FROM records
        WHERE type = ?
        GROUP BY category
        ORDER BY total DESC
    """, (rtype,))
    return cur.fetchall()           # [(category, total), ...]

def summarize_by_month(conn, rtype="expense"):
    cur = conn.cursor()
    cur.execute("""
        SELECT substr(date,1,7) AS month, SUM(amount) AS total
        FROM records
        WHERE type = ?
        GROUP BY month
        ORDER BY month
    """, (rtype,))
    return cur.fetchall()
```

**The interface layer takes that list and draws from it.** Aggregation lives in the logic layer, so the chart layer and the list layer can both reuse it.

## Crash Site 1: GROUP BY Selected a Non-Aggregated Column

```sql
SELECT category, date, SUM(amount)
FROM records
GROUP BY category;
```

**Symptom:** SQLite does not complain (this is a SQLite "feature"; other databases such as MySQL and PostgreSQL would error out), but the `date` column shows "some arbitrary value from the group", unpredictable.

**Cause:** after GROUP BY, each row represents a group, and non-aggregated column values are undefined. SQLite's default permissive mode allows the syntax, but the result is meaningless.

**Fix:** only grouping columns and aggregate functions belong in the SELECT list. For the first row in a group, use a subquery or a window function.

## Crash Site 2: SUM Returns None on an Empty Table

```python
cur.execute("SELECT SUM(amount) FROM records WHERE type='expense'")
total = cur.fetchone()[0]
print(total + 100)      # TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'
```

**Symptom:** when the table is empty, `total` is None, and any arithmetic blows up.

**Cause:** an aggregate with no matches returns None, not 0.

**Fix:** `total = cur.fetchone()[0] or 0`. Always guard an aggregate result.

## Crash Site 3: Storing the Date as "27/09/2026" Breaks Monthly Grouping

```sql
SELECT substr(date, 1, 7) ... GROUP BY substr(date,1,7)
-- groups by "27/09/2", completely wrong
```

**Symptom:** the monthly grouping is nonsense, with one month's data scattered across several groups.

**Cause:** the date format is day/month/year, so the first 7 characters are `"27/09/2"`, not a month at all.

**Fix:** go back to the lesson 2 convention and use `YYYY-MM-DD` consistently. This is a textbook case of a data-model decision shaping every feature that comes after it.

## Summary

- Aggregate with GROUP BY plus SUM: standard library, zero dependencies, fast enough.
- Four clauses: WHERE filters, GROUP BY groups, SUM aggregates, ORDER BY sorts.
- Monthly totals use `substr(date,1,7)`, which only works because dates are `YYYY-MM-DD`.
- CASE WHEN gives conditional aggregation, for income and expense together.
- After GROUP BY, SELECT only grouping columns and aggregate functions.
- SUM with no matches returns None, so remember `or 0`.

  def total_summary(conn):
