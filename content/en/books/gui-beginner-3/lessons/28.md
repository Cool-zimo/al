# Packaging: Turning the Ledger Into a Double-Clickable Executable

> The code is finished and your mum wants to use your ledger. You cannot exactly ask her to install Python, then tkinter, then matplotlib, then `git clone` your repo. This lesson packages the whole project into a single executable, and explains why it is not as simple as it sounds.

## The Goal: From Source to a Distributable Product

**Packaging closes the "last mile" of delivery:**

| Goal | Detail |
|---|---|
| Single file | The user gets one `.exe` (or a macOS app, or a Linux binary) and double-clicks. |
| No Python required | The target machine runs it without an interpreter. |
| Dependencies included | sqlite3, matplotlib, tkinter — everything bundled in. |
| Resources included | Icons, default data files, Chinese fonts. |
| Clean uninstall | Nothing left behind; ideally delete one file or one folder. |

**PyInstaller is the most painless choice here:** pure Python, cross-platform, and tkinter works out of the box. `cx_Freeze` is another option but more fiddly to configure; Nuitka compiles Python to C first, smaller and faster to start, but slow to compile and painful to debug. For a beginner, PyInstaller is the no-brainer.

**Install it:**

```
pip install pyinstaller
pyinstaller --version
```

**Always install and package inside your project's virtual environment.** Installing globally and using a different set of dependencies in the project is the classic trap.

## The Basic Command: One Line to Build

**The simplest usage, run from the project root:**

```
pyinstaller main.py
```

**This command:**

1. Analyses `main.py`'s imports and recursively gathers every dependency.
2. Writes intermediate files into `build/`.
3. Outputs a folder of files into `dist/main/` — that is your program, double-click `main.exe` (Windows) or `main` (macOS/Linux) to run it.

**`--onefile` packs everything into one file:**

```
pyinstaller --onefile main.py
```

The result, `dist/main.exe`, is a single file — the easiest thing to distribute.

**`--name` sets the output filename:**

```
pyinstaller --onefile --name Ledger main.py
```

## `--onefile` Versus `--onedir`: The Classic Trade-off

**These two flags decide what the output looks like, and therefore what the user experiences:**

| Dimension | `--onefile` (single file) | `--onedir` (folder, default) |
|---|---|---|
| Output shape | One exe | A folder with exe plus DLLs and PYDs |
| Distribution | One file to send, beautifully simple | Must be zipped or wrapped in an installer |
| Startup speed | Slow: unpacks to a temp directory each time | Fast: loads directly |
| Size | One large file (the unpacked contents are the same) | Spread across many files, no net difference |
| Debug difficulty | High: error paths point into temp dirs | Low: the files are right there |
| Best use | Delivering to ordinary users | Internal tools, debugging during development |

**The key mechanism:** `--onefile` unpacks the whole runtime into the system temp directory (`%TEMP%/_MEIxxxxxx`) on every launch, then runs. That unpacking step is why it feels like "I double-clicked and nothing happened". When the program exits, the temp directory is cleaned up. **If the program spawns child processes repeatedly, this unpack happens over and over — very slow.**

**`--onedir` skips unpacking: the exe loads `python3x.dll` and the `.pyd` files sitting right next to it, launching instantly.**

**Practical advice: use `--onedir` while developing to confirm the build works; switch to `--onefile` for the real release.** For a ledger opened occasionally, an extra second or two is a fair price for "send one file". But for a tool that lives in the tray and launches often, `--onedir` is the better fit.

## An Icon: Giving the Executable a Face

**Windows uses `.ico`, macOS uses `.icns`, Linux uses `.png`:**

```
pyinstaller --onefile --icon=ledger.ico main.py
```

**For a macOS app icon:**

```
pyinstaller --onefile --windowed --icon=ledger.icns main.py
```

**Common trap:** the icon file must genuinely be an `.ico`. Renaming a `.png` does not work. An ico should contain several sizes — 16×16, 32×32, 48×48, 256×256 — so Explorer and the taskbar can pick the right one.

## Hiding the Console: Do Not Show the User a Black Window

**A tkinter program is a GUI app, but by default packaging produces a black console window alongside it.**

**`--windowed` (or `--noconsole` on Windows and macOS):**

```
pyinstaller --onefile --windowed main.py
```

**What this flag does:** it tells the OS "this is a GUI-subsystem program, do not allocate a console". The result is that double-clicking the exe shows only your tkinter window, no black box.

**When not to use `--windowed`:** during development and debugging. **With `--windowed`, everything you `print()` disappears**, and if the program crashes you get no error message at all. So during debugging, leave `--windowed` off so the console exposes the traceback; only switch once everything is solid.

**`--console` is the default** — written out only as a reminder to yourself.

## Common Parameters at a Glance

| Parameter | Purpose |
|---|---|
| `--onefile` | Single-file mode |
| `--onedir` | Folder mode (default) |
| `--windowed` | No console window |
| `--name NAME` | Set the output name |
| `--icon=FILE.ico` | Set the icon |
| `--add-data "SRC;DST"` | Bundle a resource file (Windows uses `;`, macOS/Linux use `:`) |
| `--exclude-module NAME` | Exclude a module from the bundle |
| `--clean` | Clear caches before building |
| `--hidden-import NAME` | Force-include a module PyInstaller missed |

**`--add-data` is the most useful and most forgotten parameter for tkinter apps:** a line like `open("data/default.db")` works fine in source but the relative path is gone after packaging. Lesson 30 covers locating resources with `sys._MEIPASS`.

## Crash Site 1: It Runs on Your Machine, but Double-Clicking Does Nothing on the User's

**Symptom:** `dist/main.exe` runs perfectly on your PC. You send it to a colleague, they double-click, nothing happens, and Task Manager flashes a process for a split second.

**Cause:** the target machine is missing the Visual C++ runtime, or there is an implicit dependency that only exists on your machine (a DLL, for example). Another common cause: `main.py` raised an error that `--windowed` swallowed, with no feedback at all.

**How to diagnose:**

```
# 1. rebuild without --windowed so the console shows the error
pyinstaller --onefile main.py

# 2. on the target machine, open cmd and run the exe by hand
dist\main.exe
```

**If you see `Failed to execute script main` followed by a traceback, it is your code. If you see nothing and it exits immediately, it is almost certainly the VC++ runtime.**

**The cruelest case:** your code crashed during `import`, but the traceback points at `_MEIxxxxx` — a temp path that means nothing to you.

## Crash Site 2: The Icon Does Not Apply Even Though `--icon` Is Set

**Symptom:**

```
pyinstaller --onefile --icon=ledger.png main.py
```

The build succeeds, but the exe still shows the default feather icon.

**Cause:** `ledger.png` was never a real `.ico` file, it was just a png with a renamed extension. Windows reads the bitmap resource embedded in the ICO format; renaming png fools nobody.

**The error message is often unhelpful too — PyInstaller may silently ignore an invalid icon file.**

**The fix:**

```
# convert png to a genuine ico with Pillow
python -c "from PIL import Image; Image.open('ledger.png').save('ledger.ico')"

pyinstaller --onefile --icon=ledger.ico main.py
```

**Make sure the png is square before converting (256×256 or 512×512 recommended)**, or it will distort at 16×16.

**On macOS, `icns` needs a dedicated tool such as `iconutil`; renaming the extension will not work there either.**

## Crash Site 3: `--onefile` Takes Three Seconds to Start, So the User Clicks Three Times

**Symptom:** double-click the exe, wait 3 seconds for the window, the user clicks three times, and three windows appear.

**Cause:** the unpacking cost of `--onefile`. With matplotlib bundled, the unpacked payload can be over 100MB; on an SSD that is still a second or two, and on a mechanical drive it can exceed five.

**Fixes in order of priority:**

1. **Switch to `--onedir`** — instant startup, at the cost of zipping the folder for distribution.
2. **Add a splash screen** — `--splash splash.png` shows an image while unpacking so the user knows something is happening. PyInstaller 5.3+ supports this:

```
pyinstaller --onefile --splash splash.png main.py
```

3. **Shrink the bundle** (the focus of lesson 29): less to unpack means a faster start.

## Crash Site 4: With `--windowed`, a Crash Is Completely Silent

**Symptom:** after packaging with `--windowed`, the window flashes and vanishes, with no error at all.

**Cause:** a GUI-subsystem program has no console, so `print` and uncaught exceptions have nowhere to go.

**The fix — log to a file with `logging`:**

```
import logging
import sys
from pathlib import Path

log_path = Path(sys.executable).parent / "ledger_error.log"
logging.basicConfig(
    filename=str(log_path),
    level=logging.ERROR,
    format="%(asctime)s %(levelname)s %(message)s",
)

def main():
    # your program
    ...

if __name__ == "__main__":
    try:
        main()
    except Exception:
        logging.exception("Uncaught exception")
        raise
```

**A release build must have global exception handling**, otherwise the user can only tell you "it will not open" and you have nothing to diagnose.

## Summary

- PyInstaller is the right packaging tool for tkinter projects.
- `--onefile` is convenient to ship but slow to start (it unpacks); `--onedir` is the reverse.
- `--windowed` hides the black console, but leave it off while debugging or you will see no errors.
- `--icon` needs a genuine ico/icns, not a renamed png.
- A clean machine is not the same as your dev machine — always test on a clean one.
- A release build should write a log file so a crash is never silent.

type: local

  import tkinter as tk
  import tkinter.ttk as ttk

  label = ttk.Label(root, text="Double-click me, I came from an exe")

      label.config(text=datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S"))

- --windowed is tried and the console-output difference is observed
