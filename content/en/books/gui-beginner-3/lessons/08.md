# CRUD: INSERT / SELECT / UPDATE / DELETE

> The table exists. This lesson covers all four core operations at once — Create, Read, Update and Delete, or CRUD. They are the whole foundation of the data layer; every later interface action is really a call to one of these four.

## C is for Create: INSERT

**Inserting a record.** Let id and created_at be filled in by the database:

```python
import sqlite3
from datetime import datetime

conn = sqlite3.connect("ledger.db")
cur = conn.cursor()

cur.execute("""
    INSERT INTO records(amount, category, date, note, type, created_at)
    VALUES (?, ?, ?, ?, ?, ?)
""", (38.5, "Food", "2026-09-27", "Lunch", "expense", datetime.now().isoformat(timespec="seconds")))

conn.commit()
print("New record id:", cur.lastrowid)   # The id just inserted
conn.close()
```

**Two key points:**

1. **`?` placeholders plus a parameter tuple:** never concatenate strings (the next lesson explains why); placeholders let SQLite handle escaping and types for you.
2. **`cur.lastrowid`:** immediately after insert you have the auto-generated id of that record, which you need to locate the row for later edits and deletes.

## R is for Read: SELECT

**The most common query. For requirement F2 we want "all records, newest first":**

```python
cur.execute("""
    SELECT id, amount, category, date, note, type
    FROM records
    ORDER BY date DESC, id DESC
""")
rows = cur.fetchall()
for r in rows:
    print(r)
```

**Three methods for fetching results:**

| Method | Returns |
|---|---|
| `fetchone()` | One row (a tuple) or None |
| `fetchmany(n)` | At most n rows |
| `fetchall()` | All rows, as a list |

**`ORDER BY date DESC, id DESC`:** sort by date descending, then by id descending within the same day, so the newest entry is always at the top.

**Combined with `row_factory = sqlite3.Row`**, rows can be fetched by column name: `r["amount"]`, `r["category"]`.

## Queries With Conditions

**By category, by month, by income:**

```python
# Food category
cur.execute("SELECT * FROM records WHERE category = ?", ("Food",))

# September 2026 (LIKE prefix match)
cur.execute("SELECT * FROM records WHERE date LIKE ?", ("2026-09%",))

# Income: total it up
cur.execute("SELECT SUM(amount) FROM records WHERE type = ?", ("income",))
total_income = cur.fetchone()[0] or 0   # Watch out: no rows means SUM returns None
```

**`SUM` returns `None` when nothing matches, not 0.** This is a classic trap — always fall back with `or 0`.

## U is for Update

**Editing an existing record, located by primary key id:**

```python
cur.execute("""
    UPDATE records
    SET amount = ?, category = ?, date = ?, note = ?
    WHERE id = ?
""", (42.0, "Food", "2026-09-27", "Lunch changed", 1))   # The final 1 is the id

conn.commit()
```

**`WHERE id = ?` is mandatory.** Forget it and every row in the table gets amount set to 42.0 — and SQLite gives no "are you sure?" prompt; it just happens.

## D is for Delete

**Deleting is also done by id:**

```python
cur.execute("DELETE FROM records WHERE id = ?", (1,))
conn.commit()
print("Deleted", cur.rowcount, "rows")   # rowcount tells you how many rows were hit
```

**`cur.rowcount` is how many rows the delete (or update) affected.** If you delete id=999 but no such record exists, `rowcount` is 0, and you can use that to report "record not found".

## Wrapping CRUD in Functions

**The data layer's job is to wrap these four operations in easy-to-call functions; the interface layer deals only with those functions:**

```python
def add_record(conn, amount, category, date, note="", rtype="expense"):
    cur = conn.cursor()
    cur.execute("""
        INSERT INTO records(amount, category, date, note, type, created_at)
        VALUES (?,?,?,?,?,?)
    """, (amount, category, date, note, rtype, datetime.now().isoformat(timespec="seconds")))
    conn.commit()
    return cur.lastrowid

def get_all(conn):
    cur = conn.cursor()
    cur.execute("SELECT id,amount,category,date,note,type FROM records ORDER BY date DESC, id DESC")
    return cur.fetchall()

def update_record(conn, rid, amount, category, date, note):
    cur = conn.cursor()
    cur.execute("""
        UPDATE records SET amount=?, category=?, date=?, note=?
        WHERE id=?
    """, (amount, category, date, note, rid))
    conn.commit()

def delete_record(conn, rid):
    cur = conn.cursor()
    cur.execute("DELETE FROM records WHERE id=?", (rid,))
    conn.commit()
    return cur.rowcount
```

**These four functions are everything the interface layer needs.** It never has to know what the SQL looks like.

## Crash Site 1: UPDATE / DELETE With No WHERE

```python
cur.execute("UPDATE records SET amount = 0")
# Or:
cur.execute("DELETE FROM records")
conn.commit()
```

**Symptom:** every row in the table becomes 0 or is wiped out instantly. No error, no confirmation.

**Cause:** without `WHERE`, the scope becomes the whole table.

**Fix:** make it a habit to write the WHERE clause before filling in the SET. Or, during development, wrap dangerous operations in a logging function that warns when the whole table is affected.

## Crash Site 2: SUM Returns None, Then Division

```python
cur.execute("SELECT SUM(amount) FROM records WHERE type='expense'")
total = cur.fetchone()[0]
ratio = 100 / total    # TypeError: unsupported operand type(s) for /: 'int' and 'NoneType'
```

**Symptom:** an empty table makes `total` None and the very next line crashes.

**Cause:** aggregate functions return None when no rows match, not 0.

**Fix:** `total = cur.fetchone()[0] or 0`. Likewise `COUNT` never returns None (it returns 0), but `SUM`/`AVG`/`MAX`/`MIN` all do.

## Crash Site 3: fetchall Followed by fetchone

```python
cur.execute("SELECT * FROM records")
all_rows = cur.fetchall()
first = cur.fetchone()   # None! The cursor has already reached the end
```

**Symptom:** `fetchone()` returns None and you assume the query found nothing.

**Cause:** `fetchall()` exhausts the cursor, so there is nothing left to fetch.

**Fix:** use `fetchone()` for the first row or `fetchall()` for all of them — but do not mix them on the same cursor. To traverse more than once, store the result in a variable.

## Summary

- C — INSERT ... VALUES(?,?,...); use `cur.lastrowid` to get the new id
- R — SELECT ... ORDER BY date DESC, id DESC; fetch with fetchone/many/all
- U — UPDATE ... WHERE id=?; always include the WHERE
- D — DELETE ... WHERE id=?; use rowcount to see how many rows were hit
- SUM returns None for no match; remember `or 0`
- Wrap the four operations in functions; the interface calls functions, not SQL
