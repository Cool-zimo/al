# The Main Window and a Three-Layer Layout

> The data layer is done. From this lesson on, the interface is built. This lesson does exactly one thing: create the main window, slice it into top, middle and bottom with `pack`, and ignore what widgets go inside. Get the skeleton right and adding pieces later is easy.

## Starting With main.py

**How simple should the entry file be? As simple as possible:**

```python
import tkinter as tk
import db
import ui

def main():
    root = tk.Tk()
    root.title("Ledger")
    root.geometry("800x600")

    db.init_global_conn("ledger.db")
    db.ensure_schema()               # Create the table (if it does not exist)

    app = ui.build(root)             # Build the interface onto root

    def on_close():
        db.close_conn()
        root.destroy()
    root.protocol("WM_DELETE_WINDOW", on_close)

    root.mainloop()

if __name__ == "__main__":
    main()
```

**The job of `main.py`:** create the root window, initialise the data layer, hand the interface to `ui.build`, handle cleanup on close. **It creates no Label and writes no SQL.**

## Slicing Into Three With Three pack Calls

**`pack` is the best fit for "blocks on top and bottom + something stretchy in the middle":**

```python
import tkinter as tk
import tkinter.ttk as ttk

def build(root):
    # Top toolbar
    toolbar = tk.Frame(root, height=40, bg="#e8e8e8")
    toolbar.pack(side="top", fill="x")

    # Bottom entry area
    form = tk.Frame(root, height=80, bg="#f5f5f5")
    form.pack(side="bottom", fill="x")

    # Middle body (placeholder Frame for now; Treeview arrives in lesson 12)
    body = tk.Frame(root, bg="white")
    body.pack(side="top", fill="both", expand=True)

    # A little placeholder label in each layer
    tk.Label(toolbar, text="Toolbar: Chart | Export | Settings", bg="#e8e8e8").pack(side="left", padx=8)
    tk.Label(form, text="Entry: date amount category note [Add entry]", bg="#f5f5f5").pack(side="left", padx=8)
    tk.Label(body, text="Record list area (Treeview arrives in lesson 12)", fg="#999").pack(pady=40)

    return {"toolbar": toolbar, "form": form, "body": body}
```

**Why `pack` rather than `grid` or `place`?**

- **`pack` is for blocks:** the boundaries between top, middle and bottom are clear; three lines of pack and it is done.
- **`grid` is for alignment:** use it inside the entry area where controls must line up.
- **`place` is barely used at all:** absolute coordinates mean controls do not move when the window is resized.

**Rule of thumb: `pack` for outer blocks, `grid` for inner alignment.**

## What expand=True Means

**The middle body's `fill="both", expand=True` is the key idea of this lesson:**

- `fill="both"`: the widget expands in both directions to fill the space it was given.
- `expand=True`: when the window grows, the spare space is **allocated** to this widget.

**Without `expand=True`,** dragging the window from 600 to 1000 pixels tall leaves the table at its original height with a huge empty gap underneath.

**Order matters:** pack assigns space in code order. The `side="top"` toolbar claims 40px first, then the bottom form claims 80px, **and whatever is left goes entirely to body** (because body has expand=True).

## Window Size and Minimum Size

**`geometry("800x600")` sets the initial size, but the user can drag it around at will.** Use `minsize` to stop them shrinking it so far that the controls burst:

```python
root.geometry("800x600")
root.minsize(640, 480)
```

**For high-resolution screens:** do not hard-code pixels; let the layout adapt through `expand`. When a user on a large screen enlarges the window, the table grows with it — basic good manners for a desktop application.

## Crash Site 1: None of the Three Frames Expand, Leaving a Gap

```python
toolbar.pack(side="top", fill="x")
form.pack(side="bottom", fill="x")
body.pack(side="top", fill="both")   # Missing expand=True
```

**Symptom:** body is only as tall as "just enough to hold its contents", and most of the middle of the window is empty.

**Cause:** `expand=True` was omitted, so no one claimed the spare space and it was discarded.

**Fix:** add `expand=True` to body.

## Crash Site 2: Wrong pack Order Produces a Broken Layout

```python
body.pack(side="top", fill="both", expand=True)
toolbar.pack(side="top", fill="x")    # Packed after, so it ends up below body
```

**Symptom:** the toolbar appears below the middle body instead of at the top.

**Cause:** pack's side decides "which edge to stick to", and the first thing packed claims its spot first. Body claimed top first, and by the time toolbar packed, top was already eaten up by body's expand, so toolbar was pushed down.

**Fix:** write pack in the natural top-to-bottom order — toolbar first, body in the middle, form last (`side="bottom"` sticks to the bottom edge regardless of order).

## Crash Site 3: A Frame With No Height Is Invisible

```python
toolbar = tk.Frame(root)         # No height set, and no child widgets
toolbar.pack(side="top", fill="x")
```

**Symptom:** the toolbar has zero height and cannot be seen.

**Cause:** an empty Frame defaults to "just big enough to hold its contents"; with no contents it has no height. pack's `fill` only expands a Frame once it has something inside.

**Fix:** either set `height=40` (with `pack_propagate(False)` to stop child widgets from pushing it bigger), or put at least one widget inside.

## Summary

- main.py only handles startup: build the window, initialise the data layer, register cleanup
- Three layers with pack: toolbar (side=top) / body (side=top, expand) / form (side=bottom)
- Outer blocks use pack, inner alignment uses grid
- body needs fill="both", expand=True, or the window has a gap when enlarged
- pack order should follow the visual top-to-bottom flow; side=bottom can go last
- An empty Frame needs a height or pack_propagate(False)

```quiz
type: local
q: Build the three-layer skeleton: a top toolbar (height 40, with three buttons "Chart", "Export", "Settings"), a middle body (white background, with a hint label), and a bottom form (height 80). Window 800x600, minimum 640x480. Clicking any button pops up a messagebox saying "not implemented yet". Note: a window program cannot run in a web page — click "Open in VS Code" to run it.
starter: |
  import tkinter as tk
  import tkinter.messagebox as mb

  def build(root):
      toolbar = tk.Frame(root, height=40)
      toolbar.pack(side="top", fill="x")
      # body: fill both, expand True
      # form: side bottom
      # three buttons + callback
      for name in ("Chart", "Export", "Settings"):
          tk.Button(toolbar, text=name,
                    command=lambda n=name: mb.showinfo("Hint", f"{n} not implemented yet")).pack(side="left", padx=4, pady=6)
      return {}

  if __name__ == "__main__":
      root = tk.Tk()
      root.geometry("800x600")
      root.minsize(640, 480)
      build(root)
      root.mainloop()
checklist:
- All three Frames are laid out correctly with pack
- body has fill="both", expand=True
- The three top buttons are all present
- Clicking a button shows a popup
- minsize is set
```
