# Adding a Record: From Form to Database and Back to the Table

> This lesson closes the first complete loop: the user fills in a form, clicks "Add", the data lands in the database, and a new row appears in the table. This is the single most important connection in the whole application.

## The Full Chain

**One add operation travels through four layers:**

1. Interface layer: read values from the Entry and Combobox widgets.
2. Logic layer: validate them.
3. Data layer: INSERT.
4. Interface layer again: refresh the table and clear the form.

**The callback only wires this chain together, it does not contain business logic:**

```python
def on_add():
    date = app["date_var"].get().strip()
    amt = app["amt_var"].get().strip()
    cat = app["cat_var"].get().strip()
    note = app["note_var"].get().strip()
    rtype = app["type_var"].get()          # "expense" or "income"

    ok, msg = logic.validate(date, amt, cat)
    if not ok:
        mb.showerror("Input error", msg)
        return

    conn = db.get_conn()
    rid = db.add_record(conn, float(amt), cat, date, note, rtype)
    app["status_var"].set(f"Saved, new record #{rid}")
    root.after(3000, lambda: app["status_var"].set("Ready"))

    refresh_table(app["tree"], app["empty_label"], conn)
    _clear_form()
```

**`db.add_record` returns the new record's id** (using `cur.lastrowid` from lesson 8). The status bar shows `#{rid}` so the user can confirm "it went in, and it is record number N".

## Clearing the Form

**After a successful entry, empty the inputs so the user can enter the next one:**

```python
def _clear_form():
    app["date_var"].set(date.today().isoformat())   # reset date to today
    app["amt_var"].set("")
    app["note_var"].set("")
    # keep the last chosen category, less repetition
```

**Reset the date to today and keep the last category** — these are product decisions, and both reduce repeated typing. A ledger is entered frequently; every keystroke you spare is a better experience.

## The Full Entry Area

**Store the form widgets from lesson 13 in the `app` dict so callbacks can reach them:**

```python
def build(root):
    app = {}

    # ---- bottom entry area (grid) ----
    form = tk.Frame(root, padx=8, pady=8)
    form.pack(side="bottom", fill="x")

    app["date_var"] = tk.StringVar(value=date.today().isoformat())
    app["amt_var"] = tk.StringVar()
    app["cat_var"] = tk.StringVar(value="Food")
    app["note_var"] = tk.StringVar()
    app["type_var"] = tk.StringVar(value="expense")

    tk.Label(form, text="Type").grid(row=0, column=0, sticky="w")
    tk.Radiobutton(form, text="Expense", variable=app["type_var"], value="expense").grid(row=1, column=0)
    tk.Radiobutton(form, text="Income", variable=app["type_var"], value="income").grid(row=1, column=1)

    tk.Label(form, text="Date").grid(row=0, column=2, sticky="w")
    tk.Entry(form, textvariable=app["date_var"], width=12).grid(row=1, column=2, padx=4)

    tk.Label(form, text="Amount").grid(row=0, column=3, sticky="w")
    tk.Entry(form, textvariable=app["amt_var"], width=10).grid(row=1, column=3, padx=4)

    tk.Label(form, text="Category").grid(row=0, column=4, sticky="w")
    ttk.Combobox(form, textvariable=app["cat_var"], width=9,
                 values=("Food","Transport","Shopping","Housing","Salary","Other"),
                 state="readonly").grid(row=1, column=4, padx=4)

    tk.Label(form, text="Note").grid(row=0, column=5, sticky="w")
    tk.Entry(form, textvariable=app["note_var"], width=24).grid(row=1, column=5, padx=4)

    tk.Button(form, text="+ Add entry", command=on_add).grid(row=1, column=6, padx=8)

    # ---- middle list area ----
    list_container = tk.Frame(root)
    list_container.pack(side="top", fill="both", expand=True)

    cols = ("date","amount","category","note","type")
    app["tree"] = ttk.Treeview(list_container, columns=cols, show="headings")
    for c in cols:
        app["tree"].heading(c, text=c)
        app["tree"].column(c, width=120 if c=="note" else 90,
                           anchor="center" if c!="note" else "w")
    app["tree"].pack(fill="both", expand=True)

    app["empty_label"] = tk.Label(list_container,
        text="No records yet\n\nRecord your first income or expense", justify="center", fg="#999", font=("",12))

    # ---- status bar ----
    app["status_var"] = tk.StringVar(value="Ready")
    tk.Label(root, textvariable=app["status_var"], anchor="w", relief="sunken")\
        .pack(side="bottom", fill="x")

    return app
```

**Every widget reference lives in the `app` dict**, and callbacks reach it through a closure or an argument. This is the standard tkinter trick for avoiding global variables.

## Why a Variable Dictionary Beats Globals

**Beginners tend to litter the file with global variables:**

```python
global tree, date_var, amt_var, cat_var, note_var   # globals everywhere
```

**The problem:** as soon as you have a second window (say, a statistics window), globals stop being enough, names collide, and state turns to mush.

**Wrap state in a dict or an object instead:** `app["tree"]`, `app["date_var"]`. The logic stays clear, and you can hand `app` to other modules.

## Crash Site 1: The Table Does Not Update After Entry, So the User Saves Twice

**Symptom:** the dialog says "Saved", but the new row never appears, so the user clicks again and again, creating duplicates.

**Cause:** the INSERT succeeded, but `refresh_table` was never called.

**Fix:** every write operation must end in a refresh. We do it manually for now; lesson 19 automates it with the observer pattern.

## Crash Site 2: The Amount Was Never Converted to Float

```python
db.add_record(conn, amt, cat, date, note, rtype)   # amt is the string "38.5"
```

**Symptom:** no error, but the `amount` column stores a string (or, if your CREATE TABLE got the type wrong and used TEXT, summing it later breaks).

**Cause:** `Entry`'s `get()` returns a string, which was passed along untouched. Even if the column is REAL, SQLite coerces implicitly; attach a unit like `"38.5 GBP"` and it goes wrong.

**Fix:** after validation, pass `float(amt)`. Validation has already proved it converts, so the cast is safe.

## Crash Site 3: Clearing the Form Wiped the Date Too

```python
def _clear_form():
    app["date_var"].set("")
    app["amt_var"].set("")
    ...
```

**Symptom:** after one entry, the date box is empty, and the next record needs its date typed by hand.

**Cause:** the clear logic was one-size-fits-all.

**Fix:** reset the date to `date.today().isoformat()` and keep the last chosen category. It is a small polish that cuts down repeated input.

## Summary

- Adding = read from the interface, validate, INSERT, refresh the table, clear the form.
- `add_record` returns the new id; show `#id` in the status bar as feedback.
- Keep widget references in a dict to avoid a screen full of globals.
- Reset the date to today and keep the last category, to reduce repetition.
- Refresh the table after every write, or the user cannot see the change.
- The amount must be converted to float before being passed in.
