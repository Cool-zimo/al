# The Treeview Table: Column Definitions and Filling Data

> This lesson replaces the placeholder Frame in the middle with a real table — ttk.Treeview. It is the widget in tkinter that feels closest to a "professional application", and the ledger's record list depends on it entirely.

## What a Treeview Is

**A Treeview is a widget that "does both trees and tables".** This project uses only its "table mode": several columns, several rows, with scrolling, sorting and row selection.

```python
import tkinter as tk
import tkinter.ttk as ttk

root = tk.Tk()
root.geometry("800x400")

cols = ("date", "amount", "category", "note", "type")
tree = ttk.Treeview(root, columns=cols, show="headings")

# Column headings
tree.heading("date", text="Date")
tree.heading("amount", text="Amount")
tree.heading("category", text="Category")
tree.heading("note", text="Note")
tree.heading("type", text="Type")

# Column widths and alignment
tree.column("date", width=120, anchor="center")
tree.column("amount", width=100, anchor="e")     # Amount right-aligned
tree.column("category", width=100, anchor="center")
tree.column("note", width=280, anchor="w")
tree.column("type", width=80, anchor="center")

tree.pack(fill="both", expand=True)
root.mainloop()
```

**`show="headings"` means: show only the column headings, not the tree "tree column" on the far left.** This must be set for a plain table, otherwise an empty tree column appears.

## insert and iid

**`tree.insert(parent, index, iid, values)` inserts one row:**

```python
tree.insert("", "end",
            iid="1",                              # Use the database id as the iid
            values=("2026-09-27", "38.5", "Food", "Lunch", "expense"))
```

**The four parameters:**

| Parameter | Meaning |
|---|---|
| parent | For table mode use `""` (top level) |
| index | `"end"` appends to the bottom |
| iid | A unique id for this row; use the database id |
| values | The values for each column, in cols order |

**`iid` is the heart of this lesson** — set it to the database primary key. Later, to delete or edit, you need it to find out "which record did the user select?".

## Formatting Amount and Date

**The database stores `38.5` and `"2026-09-27"`. The interface should display them nicely:**

```python
def fmt_amount(v):
    return f"{v:,.2f}"          # 38.5 -> "38.50"; thousands: 1234.5 -> "1,234.50"

def fmt_date(s):
    # 2026-09-27 -> 2026/09/27, or however you like
    return s.replace("-", "/")
```

**Format before inserting, rather than pushing raw database values straight into the table:**

```python
for r in db.get_all(conn):
    # r is a Row: id, amount, category, date, note, type
    tree.insert("", "end", iid=str(r["id"]),
                values=(fmt_date(r["date"]),
                        fmt_amount(r["amount"]),
                        r["category"],
                        r["note"] or "",
                        r["type"]))
```

**Two decimal places and thousands separators on the amount is the detail that says "this is a serious app".** When users see `1,234.50` rather than `1234.5`, the software feels reliable.

## Adding a Scrollbar

**Once there are enough records, scrolling is essential.** The scrollbar needs a wrapping Frame, and `grid` is used to glue the Treeview and Scrollbar together:

```python
wrap = tk.Frame(root)
wrap.pack(fill="both", expand=True)

tree = ttk.Treeview(wrap, columns=cols, show="headings")
vsb = ttk.Scrollbar(wrap, orient="vertical", command=tree.yview)
tree.configure(yscrollcommand=vsb.set)

wrap.grid_rowconfigure(0, weight=1)
wrap.grid_columnconfigure(0, weight=1)
tree.grid(row=0, column=0, sticky="nsew")
vsb.grid(row=0, column=1, sticky="ns")
```

**`tree.configure(yscrollcommand=vsb.set)` plus `Scrollbar(command=tree.yview)`** bind the two together so the scrollbar and table move as one. Write only one of them and the scrollbar is decorative.

## Refreshing the Table: Clear Then Refill

**When data changes, the simplest reliable approach is a full refresh:**

```python
def refresh_table(tree, conn):
    # Clear first
    for iid in tree.get_children():
        tree.delete(iid)
    # Then refill
    for r in db.get_all(conn):
        tree.insert("", "end", iid=str(r["id"]),
                    values=(fmt_date(r["date"]), fmt_amount(r["amount"]),
                            r["category"], r["note"] or "", r["type"]))
```

**`tree.get_children()` returns a list of every row's iid.** A full refresh is fast enough up to a few thousand records; incremental updates are covered in a later lesson.

## Crash Site 1: No iid Set, So the Selected Row Cannot Be Found

```python
tree.insert("", "end", values=(...))    # No iid passed
# Later, trying to get the database id of the selected row
sel = tree.selection()[0]
print(tree.item(sel)["values"])         # Only values come back; no id
```

**Symptom:** you have the selected row's values but id is not among them (you chose not to show id as a column), so you cannot tell which record to edit.

**Cause:** no iid was set, so Treeview generated a random-looking iid like `"I001"` that does not match the database id.

**Fix:** on insert use `iid=str(r["id"])`. Afterwards `int(tree.selection()[0])` is directly the database id.

## Crash Site 2: Forgetting show="headings" Leaves an Empty Tree Column

**Symptom:** an empty column appears on the far left of the table, crowding the real columns and looking awkward.

**Cause:** Treeview defaults to `show="tree headings"`, showing both the tree column and the headings. In a plain table the tree column is surplus.

**Fix:** `ttk.Treeview(..., show="headings")`.

## Crash Site 3: Forgetting to Define Columns Before Inserting

```python
tree = ttk.Treeview(root)        # No columns passed
tree.insert("", "end", values=("2026-09-27", "38.5", "Food"))
# Only the first column appears; the rest are ignored
```

**Symptom:** three columns of data were inserted but only the first is visible; no error is raised.

**Cause:** `columns=("date","amount","category")` was not declared when the Treeview was created, so it does not know how many columns to expect.

**Fix:** pass the full columns tuple when creating it, and give every column a heading and column configuration.

## Summary

- A Treeview in table mode needs show="headings" to hide the tree column
- Insert with insert; the iid must be the database primary key for easy lookup
- Format the amount: two decimal places and thousands separators add polish
- The scrollbar must be bound both ways: yscrollcommand plus Scrollbar command
- Refresh = get_children to clear, then loop and insert to refill
- Columns must be declared when the Treeview is created, with a heading for each
