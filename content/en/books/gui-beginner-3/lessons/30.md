# Release and Wrap-Up: Shipping the Ledger and Moving On to Qt

> The code is done, the build works, and the bundle is down to 30MB. Now comes the act of delivery itself — an exe with no README, no version number, and no licence is indistinguishable from a folder of random files in the user's eyes. This lesson covers the release checklist, looks back at what you have actually completed, and points out where to go next.

## The Release Checklist: What a Shippable Project Looks Like

**Here is what the ledger should have before release:**

| Item | Purpose |
|---|---|
| README.md | Project description, how to install, how to run, screenshots |
| LICENSE | A licence file (MIT / Apache 2.0 / GPL, etc.) |
| Version number | An explicit `v1.0.0` in the README and About page |
| Release artifact | The dist directory zipped, with the version in the filename |
| Dependency list | `requirements.txt` or `pyproject.toml` |
| Screenshots | At least 2-3 main-interface screenshots |
| Known issues | Known but unfixed defects on record |
| Changelog | CHANGELOG.md recording version changes |
| Build instructions | How to package from source (`pyinstaller --onefile ...`) |
| Icons and assets | Keep the ico/png originals in the repository |

**The minimum README skeleton:**

```markdown
# Ledger

A desktop expense tracker built with Python and tkinter.

## Features

- Record income and expenses, with category, date, and notes
- Monthly and per-category statistics, with pie and bar charts
- Stored locally in SQLite, no internet required

## Download and run

Download `Ledger-1.0.0.zip` from Releases, unzip, and double-click `Ledger.exe`.

## Run from source

```
pip install -r requirements.txt
python main.py
```

## Build

```
pyinstaller --onefile --windowed --icon=ledger.ico --name Ledger main.py
```

## Licence

MIT
```

**Version numbers use Semantic Versioning (SemVer):** `major.minor.patch`. An incompatible database change → bump the major; a new feature → bump the minor; a bug fix → bump the patch. That `v1.0.0` from chapter 1 is exactly this.

**Do not skip the licence.** Even for a personal project, dropping a `LICENSE` file into the repo (MIT is the most permissive) is good practice. Code with no licence is "all rights reserved" by default, and others will hesitate to use it.

## Looking Back: Six Chapters, Covering the Full Arc

**Chapter 1 — Think first, then build:** requirements list, data model (tables, fields, primary keys), three-layer architecture (data / logic / interface), a prototype sketch, and why SQLite. **Conclusion: thinking before acting is the single most important lesson in this book.**

**Chapter 2 — The data layer:** `sqlite3` connections and cursors, `CREATE TABLE`, the four CRUD statements, **parameterised queries against SQL injection**, `commit`/`rollback`, and `with` context managers. You wrote `db.py`, a clean data layer any interface can call.

**Chapter 3 — The interface skeleton:** a three-zone layout (filters on top, table in the middle, form at the bottom), Treeview column definitions and insertion, a Combobox form, input validation, and an empty-state message. You built an interface that "looked right but did nothing".

**Chapter 4 — Wiring it up:** `refresh_list` to load data, add/delete/edit through the logic layer, the observer pattern to decouple interface from data, and choosing between full refresh and incremental updates. Your interface came alive.

**Chapter 5 — Charts:** SQL `GROUP BY` aggregation, embedding matplotlib with `FigureCanvasTkAgg` (never `plt.show()`), pie and bar charts, Chinese fonts, and `fig.clear()` against memory leaks. Your ledger gained insight.

**Chapter 6 — Packaging and delivery:** global exception handling and configuration, PyInstaller `--onefile`/`--onedir`/`--windowed`/`--icon`, trimming the bundle to around 30MB, and the release checklist. **Conclusion: a complete desktop project, from zero to one.**

**Compare that prototype sketch from chapter 1 with what you have now — it is a program you can double-click and run.**

## What Comes Next: Why Learn Qt After tkinter

**tkinter taught you the core concepts of GUI programming: the event loop, layout, widgets, data binding, and MVC layering.** Those are universal; switching frameworks does not mean learning them again. But tkinter's limits are clear:

| Dimension | tkinter | Qt (PySide6 / PyQt6) |
|---|---|---|
| Looks | Native system widgets, hard to customise | QSS stylesheets allow modern interfaces |
| Widget richness | Basics cover most needs, but complex widgets are missing | Tables, trees, graphics views, OpenGL, multimedia, networking — all included |
| Layout system | pack/grid/place, simple but rigid | Nested layouts, animation, responsive design |
| High-DPI support | Weak, blurry on 4K | Native support with automatic scaling |
| Custom drawing | Canvas works but is awkward | QPainter for professional 2D drawing |
| Commercial use | Free | PySide6 is LGPL, commercial-friendly; PyQt6 is GPL or commercial |
| Learning curve | Gentle | Steep: signals and slots, the meta-object system |
| Bundle size | Small (~10MB) | Large (starting at 30-60MB) |
| Ecosystem and jobs | Niche | Widely used in industrial, automotive, and medical software |

**The crucial difference is the signal/slot mechanism.** tkinter uses `command=` callbacks, which turn into spaghetti once you have many functions. Qt signals can carry arbitrary arguments, connect to multiple slots, and fire safely across threads — naturally suited to large projects. The observer pattern you wrote in chapter 4 is built in.

**How to choose:**

- **A "tool that works"** → tkinter is already enough; you have it.
- **"Something attractive, commercial, and resume-worthy"** → learn Qt.
- **Cross-platform mobile or web** → look elsewhere (Kivy, Electron, Flutter).

**A suggested Qt learning path:**

1. **Start with PySide6** (LGPL, commercial-friendly; PyQt6 needs a commercial licence or GPL open-sourcing).
2. Begin by **rewriting the ledger in Qt** — reuse the chapter 2 data layer, swap only the interface. That is the most efficient practice.
3. Focus on: QMainWindow and QWidgets, QVBoxLayout/QHBoxLayout/QGridLayout, QTableView plus QAbstractTableModel (a whole level above tkinter's Treeview), signals and slots, and QSS styling.
4. Advanced topics: QThreadPool for threading, QNetworkAccessManager for network requests, and QML for flashy interfaces.

**You already have every prerequisite for learning Qt:** you know how to layer code, how to decouple data from interface, and how to package. All that remains is a new API.

## Crash Site 1: Shipping an exe Without Its Data File Causes a Crash on the User's Machine

**Symptom:** your program reads `with open("data/default_categories.json")` for the default categories. It works on your machine; on the user's it crashes:

```
FileNotFoundError: [Errno 2] No such file or directory: 'data/default_categories.json'
```

**Cause:** at runtime, source-code paths are relative to `main.py`. **After packaging, the program runs from a temp unpack directory `_MEIxxxxxx`, and `data/default_categories.json` was never bundled in the first place.**

**The fix: locate resources with `sys._MEIPASS`:**

```
import sys
from pathlib import Path

def resource_path(rel):
    base = getattr(sys, "_MEIPASS", Path(__file__).parent)
    return Path(base) / rel

# use it
categories = json.load(open(resource_path("data/default_categories.json"), encoding="utf-8"))
```

**And bundle it explicitly:**

```
pyinstaller --onefile --add-data "data;data" main.py    # Windows uses ;
# pyinstaller --onefile --add-data "data:data" main.py  # macOS/Linux use :
```

**Wrong:**

```
json.load(open("data/default_categories.json"))  # guaranteed to fail after packaging
```

## Crash Site 2: The README Says "Double-Click the exe", But Never Mentions That the First Run Creates a Database

**Symptom:** the user opens the program for the first time, sees a "initialising database" message, assumes it is frozen, closes it, reopens it, and now the database already exists and errors out.

**Cause:** the `init_db()` you wrote in chapter 2 creates tables on first run. That behaviour should be transparent to the user, but without guidance it causes alarm.

**The fix: give clear feedback on first launch.**

```
def ensure_database():
    if not DB_PATH.exists():
        init_db()
        show_info("Welcome to Ledger", "A ledger database has been created for you. Start recording!")
    # normal launch: say nothing
```

**State in the README: "The first run creates ledger.db in your Documents folder. This is normal."**

## Crash Site 3: The Version Number Lives Only in the README, Not the About Page

**Symptom:** a user reports a bug and you ask "which version?". They have no idea — the About page shows no version.

**Cause:** the version was maintained only in the README, and the code hard-coded `"1.0"`. The user cannot see your code.

**The fix: a Single Source of Truth.** Create `_version.py`:

```
VERSION = "1.0.0"
```

**README, About page, and PyInstaller all reference it:**

```
# about.py
from _version import VERSION
ttk.Label(root, text=f"Ledger v{VERSION}").pack()
```

**The build command can be parameterised too: `--name "Ledger-{VERSION}"`.**

## Crash Site 4: The `.db` File Got Packaged Into the Installer

**Symptom:** the user installs it and finds a pre-built ledger database already inside, complete with someone else's test data.

**Cause:** you ran the program before packaging, so `ledger.db` was created in the source directory and PyInstaller bundled it (because `--add-data` covered the whole folder).

**The fix: clean development artefacts before packaging and add the database to `.gitignore`:**

```
# .gitignore
*.db
__pycache__/
build/
dist/
*.spec
config.ini
```

**And mention in the README that the program creates the database on first run.**

## Summary

- The release essentials: README, LICENSE, version number, and the packaged artifact.
- Semantic versioning v1.0.0: major, minor, and patch each have a meaning.
- Six chapters delivered a complete desktop project: requirements, data, interface, wiring, charts, packaging.
- After tkinter comes Qt: signals and slots, QSS, rich widgets, high DPI, and commercial value.
- Resource files use `sys._MEIPASS` and are bundled with `--add-data`.
- Version numbers need one source of truth, and database files belong in `.gitignore`.
