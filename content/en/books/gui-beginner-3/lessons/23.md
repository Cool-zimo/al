# Pie Charts and Bar Charts: Category Share and Monthly Trends

> Last lesson embedded a chart in the window. This lesson draws the two most useful statistical graphics: a pie chart to show category share, and a bar chart to show a monthly trend. The data all comes from lesson 21's aggregation functions.

## Pie Chart: Category Share

**A pie chart is ideal for "what share of the whole does each part represent" — for example, where the money went.**

```python
def draw_pie(fig, ax, conn):
    ax.clear()
    rows = logic.summarize_by_category(conn, "expense")
    if not rows:
        ax.text(0.5, 0.5, "No data yet", ha="center", va="center", fontsize=14, color="gray")
        ax.axis("off")
        return

    cats = [r[0] for r in rows]
    totals = [r[1] for r in rows]
    colors = ["#4C8BF5", "#F5654C", "#4CCF8B", "#F5C14C", "#9B6BF5", "#F56CB5"]

    wedges, texts, autotexts = ax.pie(
        totals,
        labels=cats,
        autopct="%1.1f%%",        # compute and show the percentage
        startangle=90,
        colors=colors[:len(cats)],
    )
    ax.set_title("Spending by category")
```

**`autopct="%1.1f%%"` is the pie chart's most useful parameter**: it makes every slice show its percentage to one decimal place, so the user instantly sees "Food is 32%".

**`startangle=90` makes the first slice start at the top**, which reads more naturally than the default at three o'clock.

## The Pie Chart Trap: Too Many Categories Become a Mess

**With 20 categories, the pie is cut into 20 tiny slivers, the labels overlap, and nothing is legible.**

**Two solutions:**

1. **Show only the top N** (say, 6) and merge the rest into "Other".
2. Or use a bar chart instead (bar charts cope better with many categories).

```python
def draw_pie(fig, ax, conn):
    ax.clear()
    rows = logic.summarize_by_category(conn, "expense")
    if not rows:
        ax.text(0.5, 0.5, "No data yet", ha="center", va="center", fontsize=14, color="gray")
        ax.axis("off")
        return

    top_n = 6
    if len(rows) > top_n:
        top = rows[:top_n]
        other = sum(r[1] for r in rows[top_n:])
        cats = [r[0] for r in top] + ["Other"]
        totals = [r[1] for r in top] + [other]
    else:
        cats = [r[0] for r in rows]
        totals = [r[1] for r in rows]

    ax.pie(totals, labels=cats, autopct="%1.1f%%", startangle=90,
           colors=["#4C8BF5","#F5654C","#4CCF8B","#F5C14C","#9B6BF5","#F56CB5","#AAAAAA"])
    ax.set_title("Spending by category")
```

**The "Other" slice guarantees the pie stays under 7 slices** — clear and complete at the same time.

## Bar Chart: Monthly Trend

**A bar chart is ideal for "how something changes over time" — spending per month, for example.**

```python
def draw_bar(fig, ax, conn):
    ax.clear()
    rows = logic.summarize_by_month(conn, "expense")
    if not rows:
        ax.text(0.5, 0.5, "No data yet", ha="center", va="center", fontsize=14, color="gray")
        ax.axis("off")
        return

    months = [r[0] for r in rows]        # ["2026-07","2026-08","2026-09"]
    totals = [r[1] for r in rows]

    bars = ax.bar(months, totals, color="#4C8BF5", width=0.6)
    ax.set_title("Monthly spending trend")
    ax.set_ylabel("Amount (£)")

    # label on top of each bar
    for bar, v in zip(bars, totals):
        ax.text(bar.get_x() + bar.get_width()/2, v + max(totals)*0.01,
                f"{v:,.0f}", ha="center", fontsize=9)

    # stop the x-axis labels from crowding
    ax.tick_params(axis="x", rotation=30)
```

**A label above each bar** is a small touch, but the user no longer has to squint at the y-axis scale — a real usability win.

## Two Subplots on One Figure

**Want the pie and bar charts side by side? One Figure can hold several subplots:**

```python
fig = Figure(figsize=(10, 4), dpi=100)
ax1 = fig.add_subplot(121)      # 1 row, 2 columns, position 1
ax2 = fig.add_subplot(122)      # 1 row, 2 columns, position 2

draw_pie(fig, ax1, conn)
draw_bar(fig, ax2, conn)
```

**The three digits in `add_subplot(121)` are row count, column count, and position number.** This technique lets you display several charts on one page.

## Keeping the Chart in Sync With the Data

**Combine with lesson 19's observer pattern: when data changes, redraw automatically.**

```python
def _on_data_changed(action, rid):
    if current_page() == "chart":
        draw_pie(fig, ax1, db.get_conn())
        draw_bar(fig, ax2, db.get_conn())
        canvas.draw()

observer.subscribe(_on_data_changed)
```

**First check "are we on the chart page?"** — there is no point spending CPU redrawing something the user cannot see. A finer approach is to set a "dirty flag" when not on the chart page, then redraw once when the user comes back.

## Crash Site 1: The Pie Chart Shows 0.3% Instead of 30%

**Symptom:** the `autopct` number is oddly small, something like `0.3%`.

**Cause:** `autopct` divides the value by the sum. If your data is stored in pence (integer pence), the share really is in thousandths. Or the data itself is tiny.

**Fix:** confirm the unit. `autopct` must receive a value in pounds. If the unit is right, check whether the SUM in the aggregation went wrong.

## Crash Site 2: Bar Chart X-Axis Labels Overlap

**Symptom:** month labels like `"2026-07"` sit on top of each other, unreadable.

**Cause:** the labels are too long and too dense for the default horizontal layout.

**Fix:** `ax.tick_params(axis="x", rotation=30)` rotates them 30 degrees, or trim labels to the last 4 characters (`"07"`) to shorten them.

## Crash Site 3: Drawing Repeatedly on the Same Axes Makes the Chart Pile Up

**Symptom:** after switching data a few times, the old bars are still there and the new ones are drawn on top — a mess.

**Cause:** `ax.bar(...)` *adds* to the drawing, it does not clear what is already there.

**Fix:** call `ax.clear()` before every draw. This is the starting point for the memory and redraw discussion in lesson 25.

## Summary

- Pie charts show shares (`ax.pie` plus `autopct` for automatic percentages), bar charts show trends (`ax.bar`).
- Too many pie slices means merging into "Other" to stay under 7.
- Bar charts benefit from top labels and rotated x-axis ticks.
- `add_subplot(121/122)` puts several charts on one page.
- Combined with the observer pattern, data changes redraw the chart automatically.
- Clear `ax` before every draw, or the graphics stack up.
