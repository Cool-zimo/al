# Chinese Fonts: Fixing the Square Boxes in Chart Text

> You label a chart with a Chinese title and what you get is `□□□` — a row of boxes. This is not a bug, it is a font that has no Chinese glyph. This lesson fixes it once and for all, and explains how matplotlib font configuration actually works.

## The Problem: Chinese Turns Into Boxes

**Symptom:**

```python
ax.set_title("Spending by category")     # displays fine
ax.set_xlabel("月份")                    # displays "□□"
```

**Cause:** matplotlib's default font (usually DejaVu Sans) contains no Chinese glyphs. When rendering cannot find a matching glyph, it substitutes a box.

**This happens on Windows, Linux, and Mac — the default font just varies by platform.**

## Three Ways to Fix It

**From most to least recommended:**

### Method 1: `rcParams` Global Setting (Recommended)

**Set it once at the program entry point (`main.py`) and it applies everywhere:**

```python
import matplotlib
matplotlib.use("TkAgg")
from matplotlib import rcParams

rcParams["font.sans-serif"] = ["Microsoft YaHei"]   # Windows: Microsoft YaHei
rcParams["axes.unicode_minus"] = False              # render minus signs properly
```

**Common Chinese font names:**

| Platform | Font name |
|---|---|
| Windows | `Microsoft YaHei`, `SimHei`, `KaiTi` |
| Mac | `PingFang SC`, `STHeiti`, `Arial Unicode MS` |
| Linux | `WenQuanYi Micro Hei`, `Noto Sans CJK SC` |

**Do not omit `axes.unicode_minus = False`:** without it, minus signs on axes turn into boxes.

### Method 2: `FontProperties` for a One-Off Setting

**Set the font for one text element only:**

```python
from matplotlib.font_manager import FontProperties
fp = FontProperties(family="Microsoft YaHei", size=14)

ax.set_title("Spending by category", fontproperties=fp)
ax.set_xlabel("月份", fontproperties=FontProperties(family="SimHei"))
```

**Useful for mixed layouts** (heading in bold, labels in italics, and so on).

### Method 3: Point at a Font File

**Font names differ from machine to machine, so the safest route is to ship a font file:**

```python
from matplotlib.font_manager import FontProperties
fp = FontProperties(fname="assets/msyh.ttc", size=14)
ax.set_title("Spending by category", fontproperties=fp)
```

**Drawback:** a `.ttc`/`.ttf` file runs from a few MB to over ten, and must be carried along when packaging, increasing the bundle size.

## A Cross-Platform Approach

**Your ledger is meant to be shared, and font names vary by system. The safest pattern:**

```python
import platform
from matplotlib import rcParams

def setup_font():
    sysname = platform.system()
    if sysname == "Windows":
        rcParams["font.sans-serif"] = ["Microsoft YaHei"]
    elif sysname == "Darwin":          # macOS
        rcParams["font.sans-serif"] = ["PingFang SC", "STHeiti"]
    else:                              # Linux
        rcParams["font.sans-serif"] = ["WenQuanYi Micro Hei", "Noto Sans CJK SC"]
    rcParams["axes.unicode_minus"] = False

# call as early as possible in main.py
setup_font()
```

**`platform.system()` returns `"Windows"`, `"Linux"`, or `"Darwin"`** (Darwin is macOS).

**This guarantees that the exe you package runs on someone else's Windows, and your own Linux dev box, with Chinese text intact.**

## Verifying the Font Is Actually in Use

**To see which font is active:**

```python
from matplotlib import rcParams
print(rcParams["font.sans-serif"])
# ['Microsoft YaHei']

# check whether a particular glyph can be rendered
from matplotlib.font_manager import FontProperties
fp = FontProperties(family=rcParams["font.sans-serif"][0])
print(fp.get_name())
```

**If you still see boxes, first confirm the font name is spelled correctly and that the system actually has it installed.**

## Crash Site 1: Chinese Works, but Minus Signs Become Boxes

**Symptom:** the Chinese is fine, but when the chart shows a negative value, `-100` renders as `□100`.

**Cause:** `rcParams["axes.unicode_minus"] = False` is missing.

**Fix:** add it. These two lines always travel as a pair when you set a Chinese font.

## Crash Site 2: A Misspelled Font Name Fails Silently

**Symptom:** you wrote `"Microsoft YaHei"` but added a trailing space, so it became `"Microsoft YaHei "`. Chinese is still boxed, with no error.

**Cause:** matplotlib cannot find the font and **silently falls back** to the default, with no warning at all.

**Fix:** use `print(rcParams["font.sans-serif"])` to confirm the value, or point `fname` at an actual font file you know exists.

## Crash Site 3: Fonts Break After Packaging

**Symptom:** Chinese works on the dev machine, but after PyInstaller packaging it is boxes again on the user's machine.

**Cause:** either matplotlib's font cache (`fontlist`) was not bundled correctly, or the target machine does not have the font you specified.

**Fix:**

1. Use the cross-platform `setup_font()` detector above, picking a font at runtime by system.
2. Or use `fname` to point at a bundled `.ttf` file and add it via `--add-data` when packaging.

**Lesson 28 revisits `--add-data` in detail.**

## Summary

- Boxes appear because the default font has no Chinese glyphs.
- The recommended fix is `rcParams` setting `font.sans-serif` plus `axes.unicode_minus=False`.
- Common fonts: Microsoft YaHei on Windows, PingFang on Mac, WenQuanYi on Linux.
- For cross-platform work, use `platform.system()` to pick a font at runtime.
- A misspelled font name fails silently — verify with print.
- After packaging, make sure the font can be found: either detect at runtime or bundle it with `--add-data`.
