# Wiring Up the Data Layer: Loading Records into a Treeview

> The last three lessons gave you the interface skeleton. This lesson makes the first real connection: when the program starts, it reads the database automatically and fills the table. There is no entry feature yet, but you will see real data appear on screen.

## The Startup Sequence

**A standard desktop application starts in this order:**

1. Create the root window.
2. Initialise the data layer (create the table).
3. Build the interface.
4. **Refresh the table for the first time** (load whatever is already in the database).
5. Enter the main loop.

**Step 4 is the key one.** Miss it and you get this: the database contains data, but the screen is blank.

```python
import tkinter as tk
import db, logic, ui

def main():
    root = tk.Tk()
    root.title("Ledger")
    root.geometry("800x600")
    root.minsize(640, 480)

    db.init_global_conn("ledger.db")
    db.ensure_schema()

    app = ui.build(root)                 # app is a dict holding widget refs like tree
    ui.refresh_table(app["tree"], app["empty_label"], db.get_conn())

    def on_close():
        db.close_conn()
        root.destroy()
    root.protocol("WM_DELETE_WINDOW", on_close)

    root.mainloop()

if __name__ == "__main__":
    main()
```

**`ui.build` returns a dictionary of widget references** because `main` needs the tree in order to refresh it, and other functions (the entry callbacks) need it too. Stashing widget references is cleaner than using global variables.

## Filling It with Real Data

**First, seed a few test records (a throwaway script, delete it afterwards):**

```python
# seed.py (throwaway script)
import sqlite3
from datetime import datetime

conn = sqlite3.connect("ledger.db")
cur = conn.cursor()
cur.execute("""CREATE TABLE IF NOT EXISTS records(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    amount REAL NOT NULL, category TEXT NOT NULL,
    date TEXT NOT NULL, note TEXT, type TEXT NOT NULL DEFAULT 'expense',
    created_at TEXT NOT NULL)""")

samples = [
    (38.5, "Food", "2026-09-27", "Lunch", "expense"),
    (120.0, "Transport", "2026-09-26", "Taxi", "expense"),
    (8000.0, "Salary", "2026-09-25", "Payday", "income"),
    (256.0, "Shopping", "2026-09-24", "Books", "expense"),
    (65.0, "Food", "2026-09-22", "Dinner", "expense"),
]
cur.executemany("INSERT INTO records(amount,category,date,note,type,created_at) VALUES(?,?,?,?,?,?)",
                [(a, c, d, n, t, datetime.now().isoformat()) for (a, c, d, n, t) in samples])
conn.commit()
print("inserted", cur.rowcount, "rows")
conn.close()
```

**`executemany` is the bulk-insert workhorse.** Its second argument is a list of tuples, handled in one shot. During development it is the easiest way to fabricate test data, far better than inserting rows one by one.

## The Complete `refresh_table`

**Take the refresh logic from lesson 12 and add formatting plus an empty state:**

```python
def refresh_table(tree, empty_label, conn):
    rows = db.get_all(conn)                       # list of sqlite3.Row
    if not rows:
        tree.pack_forget()
        empty_label.pack(fill="both", expand=True, pady=80)
        return

    empty_label.pack_forget()
    tree.pack(fill="both", expand=True)

    for iid in tree.get_children():
        tree.delete(iid)

    for r in rows:
        tree.insert("", "end", iid=str(r["id"]), values=(
            r["date"].replace("-", "/"),
            f"{r['amount']:,.2f}",
            r["category"],
            r["note"] or "",
            r["type"],
        ))
```

**Here `r` is an `sqlite3.Row` object**, so you can read `r["amount"]` by column name. That is the payoff for setting `row_factory` back in lesson 6.

## Making the Columns Sortable

**Clicking a column heading to sort is a desktop-app staple.** The trick: bind a click callback to each heading, track the sort direction, requery, and refill.

```python
_sort_state = {"col": "date", "desc": True}

def _on_heading_click(tree, col):
    if _sort_state["col"] == col:
        _sort_state["desc"] = not _sort_state["desc"]   # click again to reverse
    else:
        _sort_state["col"] = col
        _sort_state["desc"] = True
    conn = db.get_conn()
    rows = db.get_all_sorted(conn, col, _sort_state["desc"])
    _refill(tree, rows)

def _refill(tree, rows):
    for iid in tree.get_children():
        tree.delete(iid)
    for r in rows:
        tree.insert("", "end", iid=str(r["id"]), values=(...))
```

**`db.get_all_sorted(conn, col, desc)` is a new function that whitelists the column name before splicing it into SQL:**

```python
VALID = {"date", "amount", "category", "type"}

def get_all_sorted(conn, col, desc):
    if col not in VALID:
        col = "date"
    order = "DESC" if desc else "ASC"
    cur = conn.cursor()
    cur.execute(f"SELECT ... FROM records ORDER BY {col} {order}, id DESC")
    return cur.fetchall()
```

**Column names go through f-strings, so they must be whitelisted.** That is the rule from lesson 9. Column names cannot be placeholders, so the only option is whitelist-plus-splice.

## Crash Site 1: The Table Is Blank After Startup but the Database Has Data

**Symptom:** you seeded the data, `print(len(db.get_all(conn)))` reports 5 rows, yet the screen is empty.

**Cause:** `ui.build` only created the Treeview, it never called `refresh_table`. The interface was drawn, but nothing was poured into it.

**Fix:** call `refresh_table` immediately after `build`. Make it a habit: any function that could change what is displayed should end with a refresh.

## Crash Site 2: `executemany` Gets the Parameter Structure Wrong

```python
samples = [(38.5, "Food", ...), (120, "Transport", ...)]
cur.executemany("INSERT INTO records(amount,category) VALUES(?,?)", samples)
# WRONG: Incorrect number of bindings supplied. Current statement uses 2, and there are 5 supplied.
```

**Symptom:** `sqlite3.ProgrammingError: Incorrect number of bindings supplied`.

**Cause:** the SQL has 2 placeholders, but each tuple has 5 elements (every tuple in `samples` is `(a, c, d, n, t)`). `executemany` demands that every tuple's length match the `?` count exactly.

**Fix:** either trim the tuples to the matching length, or build a generator that fills in the missing fields with defaults.

## Crash Site 3: No Whitelist on the Sort Column, Leaving an Injection Hole

```python
col = tree.heading(col)["text"]         # user clicked "Amount"
cur.execute(f"SELECT * FROM records ORDER BY {col}")   # spliced directly
```

**Symptom:** it works, but `col` comes from the interface and could in principle be tampered with (think dynamic columns).

**Fix:** always map the interface column name to a field name inside the whitelist. A `VALID` lookup that falls back to `"date"` is all you need.

## Summary

- Startup order: make the window, initialise the data layer, build the interface, refresh for the first time, enter the main loop.
- `ui.build` returns a dict of widget references, avoiding global variables.
- Use `executemany` to fabricate test data during development.
- `refresh_table` checks for empty first (empty state), then formats and fills.
- Sorting is click-a-heading plus whitelisting plus direction toggling.
- If the interface is blank after startup, your first thought should be: did I forget to call `refresh_table`?
