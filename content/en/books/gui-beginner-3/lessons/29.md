# Slimming Down: Cutting a 60MB Executable to 30MB

> A tkinter program that just says "Hello World" comes out around 10MB after PyInstaller. Add matplotlib for two charts and it jumps past 60MB. This lesson explains where the size actually goes, and how to use `--exclude-module` and careful investigation to bring it back down.

## Why a tkinter Hello World Is Already 10MB

**First, some real-world orders of magnitude so you know what to expect:**

| Program | Bundle size (`--onefile`, Windows 10, Python 3.11) |
|---|---|
| `print("hi")` console only | ~6 MB |
| tkinter showing one Label | ~10 MB |
| Plus one matplotlib chart | ~60 MB |
| After `--exclude-module` trimming | ~30 MB |

**Where does the 10MB go?** PyInstaller does not package "your code" — it packages the whole Python runtime plus everything reachable from your import graph:

- `python311.dll`: about 4 MB, the interpreter itself, unavoidable.
- `tkinter` itself: about 2 MB (Tcl/Tk runtime: `tcl86t.dll`, `tk86t.dll`).
- **Large chunks pulled in indirectly by the standard library:** `encodings` (character tables, several MB), `ssl`, `sqlite3`, `_ssl`, `hashlib` and their dependencies — tkinter drags them in transitively and PyInstaller dares not omit them.
- Once `numpy` and `matplotlib` arrive: `numpy` alone is over 30 MB, and matplotlib's font library, backends, and sample data add another ten or more.

**The key realisation: the bulk is not your code, it is the dependencies.** Your few hundred lines of business logic compress to under 100KB — negligible.

## Seeing What Got Pulled In: `--exclude-module` and Controlled Experiments

**`--exclude-module` is the most direct scalpel:**

```
pyinstaller --onefile --exclude-module matplotlib main.py
```

**It tells PyInstaller: "do not collect this module or its submodules."** This only works if your code genuinely never uses it — otherwise you get `ModuleNotFoundError` at runtime.

**The right investigation, changing one variable at a time:**

```
# baseline: full build
pyinstaller --onefile --clean main.py
# record the size of dist/main.exe

# exclude the big pieces one at a time, rebuild and record each time
pyinstaller --onefile --clean --exclude-module matplotlib main.py
pyinstaller --onefile --clean --exclude-module numpy main.py
pyinstaller --onefile --clean --exclude-module PIL main.py
```

**Record each size and you get a table like this:**

| Excluded | Size change | Conclusion |
|---|---|---|
| None (full) | 62 MB | baseline |
| matplotlib | 30 MB | matplotlib costs 32 MB |
| then numpy | 22 MB | numpy costs 8 MB |
| then PIL | 18 MB | PIL costs 4 MB |

**The point of this exercise: it tells you which costs are necessary and which are luxury imports you picked up casually.**

## Why matplotlib Is So Fat: Its Font Library

**The number-one reason matplotlib bloats is fonts.** It ships the full DejaVu family, assorted math-symbol fonts, and Chinese fonts — `matplotlib/mpl-data/fonts/ttf/` alone exceeds 10MB.

**If you only use one or two of those fonts, the rest is waste.**

**A deeper trim is to delete the surplus files inside the font directory directly in the spec file.** That is an advanced move; beginners get the best return by using `--exclude-module` to reach roughly 30MB.

**Measured result: the ledger started at 62MB, and excluding matplotlib brought it to around 30MB — a genuine halving.** If your statistics page is optional and your audience can live with "the basics work without it", you could even make matplotlib an optional dependency.

## Hunting Redundancy: Reading the Packaging Analysis

**PyInstaller writes `build/main/warn-main.txt` and `build/main/xref-main.html`, both diagnostic tools:**

- `warn-main.txt`: every "not found" or "not collected" module warning.
- `xref-main.html`: the complete module reference graph — see which module pulled in any other.

**How to use them:**

```
pyinstaller --onefile --clean main.py
# open build/main/xref-main.html, search for a large module name, and trace up the chain
```

**You may discover that a module is imported by your code but only used on a branch the user almost never reaches.** At that point you either refactor to a lazy import or accept the cost.

**A lazy import example (import only when needed):**

```
def draw_chart(self):
    import matplotlib
    matplotlib.use("Agg")
    from matplotlib.backends.backend_tkagg import FigureCanvasTkAgg
    # ... draw
```

**The benefit: if `draw_chart` is never called, PyInstaller's static analysis never sees the import, so the module is not collected.** But be aware: under `--onefile`, a lazy import can still be collected (PyInstaller scans bytecode), so true "on demand" needs `--exclude-module` combined with runtime dynamic loading.

## Crash Site 1: Excluding a Module Then Hitting ModuleNotFoundError

**Symptom:** `--exclude-module matplotlib` builds successfully, but double-clicking the exe crashes:

```
Traceback (most recent call last):
  File "main.py", line 5, in <module>
    import matplotlib.pyplot as plt
ModuleNotFoundError: No module named 'matplotlib'
```

**Cause:** your code really does import it, so excluding it cannot work — exclusion only tells PyInstaller not to collect, and at runtime the module is simply missing.

**Two options:**

1. **Do not exclude it, accept the size.** The safest route.
2. **Use a conditional import with graceful degradation:**

```
try:
    import matplotlib
    HAS_MPL = True
except ImportError:
    HAS_MPL = False

# in the interface:
if not HAS_MPL:
    chart_tab_label.config(text="Statistics (chart library not installed)")
```

**Wrong (do not do this):**

```
pyinstaller --onefile --exclude-module matplotlib main.py
# but main.py starts with import matplotlib.pyplot as plt
```

**This contradiction is invisible to PyInstaller — it only hits you at runtime.**

## Crash Site 2: Reading the Wrong File and Thinking the Optimisation Did Nothing

**Symptom:** you eagerly added `--exclude-module matplotlib`, built it, looked in `dist/`, and the file was still 62MB, so you assumed nothing happened.

**Cause:** you were looking at a `--onefile` product. **A single-file exe is a compressed self-extracting archive inside**, with high compression, yet its reported file size is still the unpacked volume. The meaningful comparison is the **unpacked directory size**, or use `--onedir` and check the whole `dist/main/` folder.

**A misleading check:**

```
# only checking this one file can mislead you
ls -lh dist/main.exe
# -rwxr-xr-x  1 user  staff  62M  dist/main.exe   <- still huge
```

**The reliable approach: compare folder totals with `--onedir`, or compare `dist/main.exe` under the same exclusion parameters.** Better still, script it:

```
#!/usr/bin/env python3
# measure.py
import os, subprocess

excludes = ["", "matplotlib", "matplotlib,numpy", "matplotlib,numpy,PIL"]
for ex in excludes:
    name = "ledger_" + (ex.replace(",", "_") or "full")
    cmd = f"pyinstaller --onefile --clean --name {name}"
    if ex:
        for m in ex.split(","):
            cmd += f" --exclude-module {m}"
    cmd += " main.py"
    subprocess.run(cmd, shell=True)
    # measure the unpacked volume
    dist_path = f"dist/{name}"
    total = sum(
        os.path.getsize(os.path.join(dirpath, f))
        for dirpath, _, files in os.walk(dist_path)
        for f in files
    )
    print(f"{name:30s} {total/1024/1024:6.1f} MB")
```

**Output along the lines of:**

```
ledger_full                    62.3 MB
ledger_matplotlib              30.1 MB
ledger_matplotlib_numpy        22.4 MB
ledger_matplotlib_numpy_PIL    18.2 MB
```

**That is the scientific way to compare.**

## Crash Site 3: `--upx-dir` Either Fails to Compress or Produces a Broken exe

**Symptom:** you heard UPX could shrink things further, added `--upx-dir`, the size did drop, but double-clicking the exe now says "not a valid Win32 application".

**Cause:** UPX can corrupt the digital signature or relocation information of certain Python DLLs when it compresses them, and antivirus tools may also flag the result.

**PyInstaller has defaulted to not using UPX since 4.x for exactly this stability reason.** **Beginners should not gamble on a 10-20% size saving at the cost of compatibility.**

## Crash Site 4: Believing "More Exclusions Are Always Better"

**Symptom:** you excluded a dozen modules, the bundle dropped to 8MB, and you were delighted. Users report a blank entry page and a statistics page that will not open.

**Cause:** exclusion is global — there is no "exclude only the part this one function uses" fine-grained option. **What you excluded may be used by tkinter or by one of your own code paths in an error branch or plugin mechanism.**

**The right mindset: only exclude modules you are certain the entire program never uses.** When in doubt, keep them. 30MB is perfectly acceptable for a desktop app; 8MB is not worth a random crash.

## Summary

- A tkinter Hello World is about 10MB; matplotlib pushes it past 60MB. The bulk is dependencies, not your code.
- Use `--exclude-module` for controlled experiments to find the real size offenders.
- matplotlib is fat because of its fonts; the ledger can drop to around 30MB by excluding it.
- `build/main/warn-main.txt` and `xref-main.html` trace where redundancy came from.
- Confirm your code never uses a module before excluding it, or you get ModuleNotFoundError.
- Skip UPX and do not over-exclude; stability beats size.
