# Keeping Charts in Sync: Auto-Refresh When the Data Changes

> You edit a record, switch to the statistics tab, and the pie chart still shows the old data — because it was only drawn once. This lesson links aggregation, drawing, and refresh into one chain, so the chart recomputes and redraws after every add, edit, and delete. It is the last step that turns the statistics page from "viewable" to "usable".

## The Current State: The Chart Is Static

**Right now, drawing the statistics page looks roughly like this:**

```
root = tk.Tk()
...
stats = StatsFrame(notebook, db)
stats.pack(fill="both", expand=True)
stats.refresh()        # drawn once at startup
root.mainloop()
```

**The problem:** `refresh()` is only called once at startup. You add a new Food entry of £128, it appears in the Treeview instantly, but the pie chart does not react — it has no idea the data changed.

**This is not a matplotlib problem, it is a question of timing.** A chart only draws when you tell it to; nobody is telling it to redraw.

## The Idea: Lift "Draw" Into a Method

**Step one, move the drawing code out of `__init__` and into `refresh()`:**

```
class StatsFrame(ttk.Frame):
    def __init__(self, master, db):
        super().__init__(master)
        self.db = db
        self.fig = Figure(figsize=(6, 4), dpi=100)
        self.canvas = FigureCanvasTkAgg(self.fig, master=self)
        self.canvas.get_tk_widget().pack(fill="both", expand=True)
        self.refresh()

    def refresh(self):
        self.fig.clear()
        ax = self.fig.add_subplot(111)
        rows = self.db.sum_by_category("expense")
        labels = [r[0] for r in rows]
        values = [r[1] for r in rows]
        ax.pie(values, labels=labels)
        self.fig.tight_layout()
        self.canvas.draw()
```

**The key point: `self.fig.clear()` wipes the old chart before adding a new subplot.** Without it, old and new charts pile up into a mess.

## Triggering Refresh After Every Write

**Now the question is: who calls `refresh()`?**

**The answer is anywhere the data changes.** A ledger has three operations that alter data: add, edit, and delete. Each must notify the statistics page to redraw.

**The simplest approach: let `App` hold a reference to the statistics page, and call it when something changes:**

```
class App:
    def __init__(self, root):
        ...
        self.stats = StatsFrame(notebook, self.db)
        self.entries = EntryFrame(notebook, self.db, on_changed=self.on_data_changed)
        ...

    def on_data_changed(self):
        self.stats.refresh()
```

**The button callback in `EntryFrame` calls `self.on_changed()` after insert, update, or delete:**

```
def on_save(self):
    self.db.insert(category=self.category.get(), amount=self.amount.get(), ...)
    self.on_changed()      # tell the layer above: I changed something
```

**This decouples the data layer from the view layer:** the entry page does not know the statistics page exists, it only announces "I made a change"; who refreshes and how is none of its business.

## Crash Site 1: Forgetting `fig.clear()`, the Chart Gets Messier Each Time

**Symptom:** with every data change, more pie slices accumulate until the whole thing is duplicated sectors and labels.

**Cause:** `refresh()` calls `self.fig.add_subplot(111)` directly, stacking another Axes onto the same Figure. A Figure never auto-clears.

**Wrong:**

```
def refresh(self):
    ax = self.fig.add_subplot(111)    # adds a new Axes every time, the old one remains
    ax.pie(...)
    self.canvas.draw()
```

**Right:**

```
def refresh(self):
    self.fig.clear()                  # wipe first
    ax = self.fig.add_subplot(111)
    ax.pie(...)
    self.fig.tight_layout()           # re-lay-out after clearing
    self.canvas.draw()
```

**`canvas.draw()` and `fig.clear()` are a pair:** clear the old, draw the new, then tell the canvas to render.

## Crash Site 2: Data Changed but Nobody Was Told, So the Chart Stays Stale

**Symptom:** the save button on the entry page clearly ran, the database has the new record, but the pie chart never updates. You have to close and reopen the window to see it.

**Cause:** the save callback called `self.db.insert(...)` but never called `self.on_changed()`. The statistics page simply never found out.

**Wrong:**

```
def on_save(self):
    self.db.insert(...)
    self.tree.insert(...)    # only the list refreshes, the stats page is forgotten
```

**Right:**

```
def on_save(self):
    self.db.insert(...)
    self.tree.insert(...)
    self.on_changed()        # do not skip this line
```

**How to debug this kind of bug:** put `print("refresh called")` at the top of `refresh()` and watch whether it appears after a save. No output means the notification chain is broken; output means the drawing logic itself is at fault.

## Crash Site 3: `refresh` Reads the Database and Freezes the Interface

**Symptom:** with tens of thousands of records, every save hangs the window for a couple of seconds and nothing responds in the meantime.

**Cause:** `db.sum_by_category()` is a synchronous SQL query running on the GUI thread, which is busy the whole time.

**For now, remember the rule: long-running work belongs on a background thread.** Lesson 26 covers exception handling; here is the skeleton:

```
import threading

def on_data_changed(self):
    threading.Thread(target=self._reload_stats, daemon=True).start()

def _reload_stats(self):
    rows = self.db.sum_by_category("expense")   # query in the worker thread
    self.after(0, self._redraw, rows)           # hop back to the main thread to draw

def _redraw(self, rows):
    self.fig.clear()
    ...
    self.canvas.draw()
```

**One hard rule: tkinter widgets may only be touched from the main thread.** A worker thread must use `widget.after(0, callback)` to schedule the actual drawing back on the main thread, or it will crash outright.

## Summary

- A chart is drawn only once by default, so it does not refresh when data changes.
- Wrap the drawing logic in `refresh()` and call it after every data change.
- `refresh()` must clear `fig` before redrawing, otherwise graphics accumulate.
- Use an `on_changed` callback to decouple things: the entry page announces, the statistics page refreshes itself.
- When debugging a refresh bug, print first to see whether `refresh` was even called.
- For large data sets, run the query on a worker thread and do the drawing on the main thread.

  import tkinter as tk
  import tkinter.ttk as ttk
  import matplotlib
  matplotlib.use("TkAgg")
  from matplotlib.figure import Figure
  from matplotlib.backends.backend_tkagg import FigureCanvasTkAgg

  class StatsFrame(ttk.Frame):
      def __init__(self, master, get_rows):
          super().__init__(master)
          self.get_rows = get_rows
          self.fig = Figure(figsize=(5, 4), dpi=100)
          self.canvas = FigureCanvasTkAgg(self.fig, master=self)
          self.canvas.get_tk_widget().pack(fill="both", expand=True)
          self.refresh()

      def refresh(self):
          self.fig.clear()
          ax = self.fig.add_subplot(111)
          rows = self.get_rows()
          if not rows:
              ax.text(0.5, 0.5, "No data yet", ha="center", va="center", fontsize=16)
          else:
              ax.pie([r[1] for r in rows], labels=[r[0] for r in rows])
          self.fig.tight_layout()
          self.canvas.draw()

  root = tk.Tk()
  store = []
  sf = StatsFrame(root, get_rows=lambda: list(store))
  tk.Button(root, text="Add Food 200",
      command=lambda: (store.append(("Food",200)), sf.refresh())).pack()
  tk.Button(root, text="Add Transport 50",
      command=lambda: (store.append(("Transport",50)), sf.refresh())).pack()
  root.mainloop()
checklist:
- Buttons add data and trigger a refresh
- With no data, the pie area shows the "No data yet" text
- With data, the pie chart renders correctly
- Every refresh clears before redrawing
