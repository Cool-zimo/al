# `map`, `filter`, `reduce`: the functional trio

> This lesson answers: how do you process arrays functionally in JS? You have seen Python's list comprehensions and `map`/`filter`; JS has equivalent methods, and they are pleasantly expressive.

## `map`: transform every element

```js
const numbers = [1, 2, 3, 4];

// double each element
const doubled = numbers.map(n => n * 2);
console.log(doubled);  // [2, 4, 6, 8]

// extract a property from each object
const users = [
  { name: "Alice", age: 25 },
  { name: "Bob", age: 30 }
];
const names = users.map(u => u.name);
console.log(names);    // ["Alice", "Bob"]
```

Compared with Python:

```python
numbers = [1, 2, 3, 4]
doubled = [n * 2 for n in numbers]  # list comprehension
names = [u["name"] for u in users]
```

## `filter`: keep selected elements

```js
const numbers = [1, 2, 3, 4, 5, 6];

const evens = numbers.filter(n => n % 2 === 0);
console.log(evens);  // [2, 4, 6]

const users = [
  { name: "Alice", age: 17 },
  { name: "Bob", age: 25 },
  { name: "Carol", age: 16 }
];
const adults = users.filter(u => u.age >= 18);
console.log(adults);  // [{ name: "Bob", age: 25 }]
```

Compared with Python:

```python
evens = [n for n in numbers if n % 2 == 0]  # conditional comprehension
adults = [u for u in users if u["age"] >= 18]
```

## `reduce`: fold into a single value

```js
const numbers = [1, 2, 3, 4];

// sum
const sum = numbers.reduce((acc, n) => acc + n, 0);
console.log(sum);  // 10

// find the maximum
const max = numbers.reduce((acc, n) => Math.max(acc, n));
console.log(max);  // 4

// count word frequencies
const words = ["apple", "banana", "apple", "cherry", "banana", "apple"];
const freq = words.reduce((acc, word) => {
  acc[word] = (acc[word] || 0) + 1;
  return acc;
}, {});
console.log(freq);  // { apple: 3, banana: 2, cherry: 1 }
```

Compared with Python:

```python
from functools import reduce
sum_result = reduce(lambda acc, n: acc + n, numbers, 0)

# in Python 3.8+ the more common tool is collections.Counter
from collections import Counter
freq = dict(Counter(words))
```

## Method chaining: the trio in concert

```js
const users = [
  { name: "Alice", age: 17, city: "London" },
  { name: "Bob", age: 25, city: "Paris" },
  { name: "Carol", age: 30, city: "London" },
  { name: "Dan", age: 16, city: "Paris" }
];

// find every adult in London, return their uppercased names
const result = users
  .filter(u => u.city === "London")
  .filter(u => u.age >= 18)
  .map(u => u.name.toUpperCase());

console.log(result);  // ["CAROL"]
```

### Crash Site 1: forgetting `return` in `map`

```js
const numbers = [1, 2, 3];
const doubled = numbers.map(n => {
  n * 2;  // no return!
});
console.log(doubled);  // [undefined, undefined, undefined]
```

**Why it crashes:** when you write an arrow function body with braces `{}`, you **must** write `return` explicitly. Either drop the braces (implicit return) or include the return statement.

```js
// correct form 1: drop the braces (implicit return)
numbers.map(n => n * 2);

// correct form 2: keep the braces and return
numbers.map(n => {
  return n * 2;
});
```

### Crash Site 2: calling `reduce` on an empty array with no initial value

```js
const numbers = [];

// no initial value
const sum = numbers.reduce((acc, n) => acc + n);
// TypeError: Reduce of empty array with no initial value

// with an initial value, no problem
const sum = numbers.reduce((acc, n) => acc + n, 0);  // 0
```

**Why it crashes:** calling `reduce` on an empty array without an initial value throws. Build the habit: **always supply an initial value to `reduce`.**

## Performance considerations

Method chaining creates several intermediate arrays:

```js
// three passes, two intermediate arrays
const result = arr.filter(...).map(...);

// for very large data, one pass is more efficient
const result = [];
for (const item of arr) {
  if (condition(item)) {
    result.push(transform(item));
  }
}
```

In day-to-day development, the readability of chaining far outweighs the performance difference. Only when you are processing **tens of thousands of items** should you consider merging the passes.

## Comparison with Python

| Operation | Python | JavaScript |
|---|---|---|
| transform | `[f(x) for x in arr]` / `map(f, arr)` | `arr.map(f)` |
| filter | `[x for x in arr if cond]` / `filter(cond, arr)` | `arr.filter(cond)` |
| reduce | `reduce(f, arr, init)` | `arr.reduce(f, init)` |
| chaining | nested comprehensions | method chaining |
| implicit return | `lambda` returns automatically | an arrow function returns automatically when `{}` is omitted |

## Recap

- `map(fn)` applies a function to each element and returns a new array.
- `filter(fn)` keeps the elements for which `fn` returns true, and returns a new array.
- `reduce(fn, init)` folds left to right into a single value — **always pass an initial value**.
- Forgetting `return` when an arrow function uses `{}` is a common bug.
- Chaining reads beautifully, and the performance cost is negligible for small data.

  function getAdultNames(users) {
      // filter for adults, then map to extract and uppercase the name
      return [];

  [] -> []
