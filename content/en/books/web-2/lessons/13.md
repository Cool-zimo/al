# Changing content: `textContent` vs `innerHTML`

> This lesson answers: how do you change an element's text or HTML content? `textContent` and `innerHTML` can both write content, but their safety and behaviour are completely different.

## `textContent`: plain text

```js
const div = document.querySelector('.content');
div.textContent = "Hello, world";
```

- Treats the content as **plain text**.
- Special characters (`<`, `>`, `&`) are escaped and displayed literally.
- **Safe:** nothing is executed as HTML or JS.

## `innerHTML`: an HTML string

```js
const div = document.querySelector('.content');
div.innerHTML = "<strong>Hello</strong>, <em>world</em>";
```

- Parses the content as **HTML**.
- Tags are rendered as real DOM elements.
- **Dangerous:** if the content came from a user, it can open the door to XSS.

## How the two behave

```js
const div = document.querySelector('.demo');

// textContent: displayed literally
div.textContent = "<strong>bold</strong>";
// the page shows: <strong>bold</strong> (the tags appear as text)

// innerHTML: parsed and rendered
div.innerHTML = "<strong>bold</strong>";
// the page shows: bold (the text is bold)
```

### Crash Site 1: inserting user input with `innerHTML`

```js
const userInput = prompt("Enter your name:");  // user types: <img src=x onerror=alert('XSS')>
document.querySelector('.greeting').innerHTML = "Hello, " + userInput;
```

**Why it crashes:** the user's input is parsed and executed as HTML. Malicious code can:

- steal cookies (`document.cookie`)
- redirect to a phishing site
- fake page content

This is **XSS (cross-site scripting)**. If an attacker can control any part of your page, they can inject arbitrary JS.

**The fix: always use `textContent` for user input.**

```js
const userInput = prompt("Enter your name:");
document.querySelector('.greeting').textContent = "Hello, " + userInput;
// <img src=x onerror=...> appears as literal text and never executes
```

## When to use `innerHTML`

`innerHTML` is not forbidden — you just have to know where the content came from:

```js
// safe: the content is written by the developer, not the user
const template = `
  <div class="card">
    <h3>${product.name}</h3>
    <p>£${product.price}</p>
  </div>
`;
container.innerHTML = template;

// dangerous: user data is concatenated in
container.innerHTML = `<div>${userInput}</div>`;
```

If you must use `innerHTML` with dynamic data, escape it first:

```js
function escapeHtml(str) {
  const div = document.createElement('div');
  div.textContent = str;       // textContent escapes automatically
  return div.innerHTML;         // read back the escaped HTML
}

container.innerHTML = `<div>${escapeHtml(userInput)}</div>`;
```

## The difference when reading

```js
// HTML: <div class="demo"><strong>Hello</strong> World</div>
const div = document.querySelector('.demo');

div.textContent;   // "Hello World" (plain text, no tags)
div.innerHTML;     // "<strong>Hello</strong> World" (tags included)
```

## Performance

```js
// textContent is faster (no HTML parsing required)
element.textContent = "Hello";  // fast

// innerHTML must parse the HTML string
element.innerHTML = "<span>Hello</span>";  // slower
```

When the content is plain text, `textContent` is both safer and faster.

### Crash Site 2: `innerHTML` destroys existing elements and listeners

```html
<div id="container">
  <button id="myBtn">Click</button>
</div>

<script>
  document.getElementById('myBtn').addEventListener('click', () => {
    console.log('clicked');
  });

  // later...
  const container = document.getElementById('container');
  container.innerHTML = '<button id="myBtn">Click</button>';
  // the old button was destroyed and recreated! all previously attached listeners are gone!
</script>
```

**Why it crashes:** assigning to `innerHTML` **destroys every old element inside the container and rebuilds it**. Any event listeners that were attached are gone, because those DOM nodes no longer exist.

## Comparison with Python

Python has no DOM, but string templates offer a useful analogy:

```python
# Python: building an HTML string by hand
name = "<script>alert('xss')</script>"
html = f"<div>Hello {name}</div>"  # does not execute — it is just a string

# in a web framework (Flask/Django), templates auto-escape by default,
# similar to textContent
# {{ user_input }} escapes automatically
# {{ user_input|safe }} does not escape (like innerHTML)
```

JS's `textContent` is like a template engine's auto-escaping; `innerHTML` is like the `|safe` filter.

## Recap

- `textContent` sets plain text: safe, fast, special characters are escaped.
- `innerHTML` parses HTML: it renders tags, but carries an XSS risk.
- **Always use `textContent` for user input**; never concatenate it into `innerHTML`.
- `innerHTML` destroys and rebuilds the inside of an element, so event listeners are lost.
- When reading: `textContent` returns plain text; `innerHTML` returns the HTML string with tags.
