# Functions: declarations, expressions and arrow functions

> This lesson answers: what are the several ways to write a function in JS, and how are arrow functions related to Python's `lambda`? You already know Python's `def` and `lambda`; JS's function system is more flexible.

## Three ways to define a function

### 1. Function declaration

```js
function greet(name) {
  return "Hello, " + name;
}
```

Characteristic: it is **hoisted**, so you can call it before it appears to be declared.

### 2. Function expression

```js
const greet = function(name) {
  return "Hello, " + name;
};
```

Characteristic: it is assigned to a variable, and is **not hoisted** (the variable is hoisted, but its function body is not).

### 3. Arrow function

```js
const greet = (name) => {
  return "Hello, " + name;
};
// shorter: a single expression lets you drop {} and return
const greet = name => "Hello, " + name;
```

Characteristic: more compact syntax, and it does **not** bind its own `this`.

## Arrow functions vs Python `lambda`

```python
# Python
square = lambda x: x * x
add = lambda a, b: a + b
```

```js
// JavaScript
const square = x => x * x;
const add = (a, b) => a + b;
```

Very close! But JS arrow functions are more capable than Python's `lambda`: they can span multiple lines (with `{}`), and they can take no arguments at all (with `()`).

```js
const greet = () => "Hello";
const sum = (a, b) => {
  const result = a + b;
  return result;
};
```

## Default parameters and rest parameters

```js
// default value (like Python's default argument)
function greet(name = "Guest") {
  return "Hello, " + name;
}

// rest parameters (like Python's *args)
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4);  // 10
```

### Crash Site 1: the default-value trap

```js
function add(a, b = 1) {
  return a + b;
}
add(5, undefined);  // 6 (undefined triggers the default)
add(5, null);       // 5 (null is a real value, no default!)
```

**Why it crashes:** `null` counts as "a value was passed", so the default `1` is not used. In form handling, an empty input field gives `""`, which is also not `undefined`, so the default is skipped there too.

## The `this` difference in arrow functions

`this` is one of the most complex topics in JS. Here we only flag the difference; later lessons go deeper.

```js
const person = {
  name: "Alice",
  // regular function: this points at the caller (person)
  greet: function() {
    console.log("Hi, I'm " + this.name);
  },
  // arrow function: this inherits from the surrounding scope
  greetArrow: () => {
    console.log("Hi, I'm " + this.name);  // this is not person!
  }
};
person.greet();       // "Hi, I'm Alice"
person.greetArrow();  // "Hi, I'm undefined"
```

**Remember: an arrow function has no `this` of its own; it inherits the `this` of the scope where it was defined.**

### Crash Site 2: using an arrow function as an object method

```js
const counter = {
  count: 0,
  increment: () => {
    this.count++;  // this is not counter!
  }
};
counter.increment();  // counter.count is still 0
```

**Why it crashes:** `this.count++` modifies `count` in the surrounding scope (which may not even exist), leaving `counter.count` untouched. Object methods should use the regular function syntax.

## Functions are first-class citizens

Just as in Python, JS functions are "first-class": they can be assigned to variables, passed as arguments and returned as values:

```js
// passed as an argument (a callback)
[1, 2, 3].map(x => x * 2);

// returned (a closure)
function makeAdder(n) {
  return x => x + n;
}
const add5 = makeAdder(5);
add5(3);  // 8
```

This is identical to Python, so you already understand the core idea of functional programming.

## Comparison with Python

| Feature | Python | JavaScript |
|---|---|---|
| define a function | `def f(x):` | `function f(x) {}` |
| anonymous function | `lambda x: x*2` | `(x) => x * 2` |
| default argument | `def f(x=1):` | `function f(x=1) {}` |
| `*args` | `def f(*args):` | `function f(...args) {}` |
| assign a function | `g = f` | `const g = f` |
| `this` / `self` | `self` is passed by hand | `this` binds automatically (except in arrow functions) |

## Recap

- Function declarations are hoisted; function expressions and arrow functions are not.
- Arrow functions are concise, similar to Python `lambda` but more powerful.
- Arrow functions have no `this` of their own — they inherit it; don't use them for object methods.
- Functions are first-class: assignable, passable, returnable.
- For default parameters, `undefined` triggers the default; `null` and `""` do not.
