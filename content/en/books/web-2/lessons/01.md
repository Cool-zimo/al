# Variables: `let`, `const` and the `var` Trap

> This lesson settles one question: how do you declare a variable in JS, and why does `var` keep biting people? You already know what a variable is from Python — the JS difference is that there are three ways to declare one, and one of them is a classic footgun.

## Three ways to declare a variable

In Python there is exactly one assignment syntax: `x = 10`. JavaScript gives you three:

```js
let name = "Alice";       // reassignable, block-scoped
const age = 25;         // not reassignable, block-scoped
var city = "London";       // reassignable, function-scoped (legacy)
```

| Keyword | Reassignable? | Scope | Recommendation |
|---|---|---|---|
| `let` | yes | block (`{}`) | default choice |
| `const` | no | block (`{}`) | prefer it |
| `var` | yes | function | avoid |

**Reach for `const` first**; only use `let` when you genuinely need to reassign. This is a habit worth cultivating — it saves a lot of "where on earth did this variable change?" debugging time.

## `const` means "not rebound", not "immutable"

```js
const person = { name: "Alice", age: 25 };
person.age = 26;        // fine — we mutate a property
person = { name: "Bob" }; // throws: Assignment to constant variable
```

What `const` guarantees is "this name always points at the same memory address", not "the data at that address cannot change". It is the same distinction as Python's: a tuple cannot be replaced, but its list element can be.

## The `var` function-scope trap

This is one of the most famous JS gotchas. Watch what happens here:

```js
function example() {
  if (true) {
    var x = 10;      // declaration is hoisted to the top of the function
  }
  console.log(x);    // 10! x is visible outside the if block
}
```

Swap in `let` and the picture changes completely:

```js
function example() {
  if (true) {
    let x = 10;      // block-scoped
  }
  console.log(x);    // ReferenceError: x is not defined
}
```

### Crash Site 1: `var` inside a `for` loop

```js
for (var i = 0; i < 3; i++) {
  setTimeout(function() {
    console.log(i);  // what does this print?
  }, 100);
}
// prints: 3, 3, 3 (not 0, 1, 2!)
```

**Why it crashes:** the `i` declared with `var` is shared across the whole function, so all three `setTimeout` callbacks reference the *same* `i`. By the time they run, the loop has finished and `i` is `3`. With `let` you get `0, 1, 2` as expected.

### Crash Site 2: hoisting

```js
console.log(name);  // undefined — no error!
var name = "Alice";
```

**Why it crashes:** the declaration `var name` is "hoisted" to the top of the function, but the assignment stays where it was written. It behaves as if the function began with `var name;` (whose value is `undefined`). `let` has a "temporal dead zone" instead — accessing it before declaration throws immediately, which is actually safer.

## Comparison with Python

| Situation | Python | JavaScript |
|---|---|---|
| declare a variable | `x = 10` | `let x = 10` |
| a constant | by convention (ALL_CAPS) | enforced by `const` |
| block scope | yes (partially, Python 3.10+) | yes for `let`/`const`, no for `var` |
| hoisting | does not exist | `var` hoists; `let`/`const` have a TDZ |

## Recap

- Prefer `const`; only use `let` when you must reassign.
- `var` is function-scoped and hoisted — a breeding ground for bugs, don't use it.
- `const` does not make data immutable, it only forbids rebinding the variable.
- A `let`/`const` declared inside a block is invisible outside that block.

## In-class exercise

```quiz
type: js
q: Write a function declareConst(value) that declares a const variable result equal to value times two, then returns result. Show the correct use of const.
func: declareConst
starter: |
  function declareConst(value) {
      // declare result with const and return it
      return 0;
  }
cases: |
  5 -> 10
  0 -> 0
  -3 -> -6
  100 -> 200
hint: const result = value * 2; then return result;
explain: const is ideal for a computed value that will not be reassigned; value * 2 expresses exactly the intent of "double".
```
