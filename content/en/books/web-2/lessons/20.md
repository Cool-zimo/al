# Bubbling and capturing: the three-phase event flow

> This lesson answers: when you click a button, why does its parent also receive the event — and how do you take advantage of that, or stop it?

## The three phases of an event

Clicking a nested element does not fire the event just once. It travels through three phases:

```
document → html → body → div → button   (capture phase, top down)
button                                    (target phase)
button → div → body → html → document   (bubble phase, bottom up)
```

```js
// the third argument controls which phase you listen on
element.addEventListener('click', handler, true);   // capture phase
element.addEventListener('click', handler, false);  // bubble phase (default)
element.addEventListener('click', handler);          // bubble phase (default)
```

In most situations you only need the bubble phase (omit the third argument, or pass `false`). Capture is rarely used — mostly for the few cases where you need to "intercept before it reaches the target".

## Bubbling: inside out

```html
<div id="outer">
  <div id="inner">
    <button id="btn">Click me</button>
  </div>
</div>
```

```js
document.querySelector('#outer').addEventListener('click', () => {
  console.log('outer bubble');
});
document.querySelector('#inner').addEventListener('click', () => {
  console.log('inner bubble');
});
document.querySelector('#btn').addEventListener('click', () => {
  console.log('btn bubble');
});
// click the button: btn bubble → inner bubble → outer bubble
```

## Capturing: outside in

```js
document.querySelector('#outer').addEventListener('click', () => {
  console.log('outer capture');
}, true);
document.querySelector('#inner').addEventListener('click', () => {
  console.log('inner capture');
}, true);
document.querySelector('#btn').addEventListener('click', () => {
  console.log('btn capture');
}, true);
// click the button: outer capture → inner capture → btn capture
```

## `stopPropagation`: cutting the chain

```js
document.querySelector('#btn').addEventListener('click', (event) => {
  event.stopPropagation();  // the event stops here - no more bubbling
  console.log('btn clicked; the parent will not hear about it');
});
```

### Crash Site 1: stopping during capture prevents later phases

```js
document.querySelector('#outer').addEventListener('click', (event) => {
  event.stopPropagation();  // stopped during capture!
  console.log('outer capture - the event ends here');
}, true);

document.querySelector('#btn').addEventListener('click', () => {
  console.log('this never runs');  // propagation was blocked upstream
});
```

**Why it crashes:** calling `stopPropagation()` inside a capture-phase listener blocks every later phase, including the target phase and the bubble phase. If the button still needs to respond, you get a bug that looks like "my handler just vanished".

## Why delegation depends on bubbling

Delegation only works because child events travel up to the parent:

```js
// delegation needs the bubble
document.querySelector('#todo-list').addEventListener('click', (event) => {
  // child click events arrive here
  const li = event.target.closest('li');
  if (li) console.log('clicked:', li.textContent);
});
```

### Crash Site 2: a non-bubbling event silently breaks delegation

```js
// focus and blur do not bubble!
document.querySelector('#form').addEventListener('focus', (event) => {
  console.log('an input got focus');  // never fires!
});

// fix: use focusin / focusout, which do bubble
document.querySelector('#form').addEventListener('focusin', (event) => {
  console.log('an input got focus');  // works
});
```

**Why it crashes:** `focus`/`blur` do not bubble, so delegation cannot use them. For delegation, switch to `focusin`/`focusout`. Likewise `mouseenter`/`mouseleave` do not bubble — use `mouseover`/`mouseout` instead.

## A practical use of `stopPropagation`

**Scenario: clicking inside a modal should not close it.**

```js
// clicking outside the modal closes it
document.addEventListener('click', (event) => {
  if (!event.target.closest('#modal')) {
    closeModal();
  }
});

// clicking inside the modal stops the bubble
document.querySelector('#modal').addEventListener('click', (event) => {
  event.stopPropagation();  // never reaches the document handler
});
```

## Comparison with Python

In Python GUI frameworks you also control propagation by hand:

```python
# Tkinter: events travel up the widget tree; you can stop them
def on_click(event):
    # do the work
    return "break"  # like stopPropagation, blocks further travel
```

JavaScript's event flow is a three-phase model managed automatically by the browser. You just pick the phase you care about and call `stopPropagation()` when you need to.

## Recap

- An event has three phases: capture (outside in), target, bubble (inside out).
- Listeners run in the bubble phase by default; pass `true` as the third argument for capture.
- `stopPropagation()` halts all further propagation immediately.
- Delegation relies on bubbling; non-bubbling events (`focus`/`blur`, `mouseenter`/`mouseleave`) cannot be delegated — use `focusin`/`focusout` and `mouseover`/`mouseout`.
- Most real applications only need the bubble phase plus delegation.
