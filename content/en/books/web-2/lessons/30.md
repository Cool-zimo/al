# Wrapping up: organising the code and revisiting the classic bugs

> This lesson answers: now that the project works, how do you keep it readable, and why do the same three bugs keep appearing?

## Organising and splitting the code

### The original: everything in one file

```js
// app.js — 200 lines, all together
let todos = [];
let nextId = 1;
let currentFilter = 'all';
// ...100 lines of DOM references and function definitions...
// ...100 lines of event wiring...
```

It works. It is also why nobody wants to touch it three weeks later.

### A better shape: group by responsibility

```js
// ====== Config ======
const STORAGE_KEY = 'todos';

// ====== State ======
let todos = loadTodos();
let nextId = getNextId(todos);
let currentFilter = 'all';

// ====== Persistence ======
function loadTodos() { /* ... */ }
function saveTodos() { /* ... */ }
function getNextId(todos) { /* ... */ }

// ====== Rendering ======
function render() { /* ... */ }
function updateStats() { /* ... */ }

// ====== Operations ======
function addTodo(text) { /* ... */ }
function deleteTodo(id) { /* ... */ }
function toggleTodo(id) { /* ... */ }

// ====== Event wiring ======
function bindEvents() { /* ... */ }

// ====== Startup ======
bindEvents();
render();
```

**The ordering principle:** config first, state next, then utilities, then business logic, then wiring, then the code that starts everything. A reader scanning from top to bottom meets concepts in the order they need them.

## Bug 1 revisited: the array changed but nothing re-rendered

**Symptom:** the data is new — you can see it in a `console.log` — but the page still shows the old list.

```js
// Wrong: render() was forgotten.
function toggleTodo(id) {
  const todo = todos.find(t => t.id === id);
  todo.done = !todo.done;
  saveTodos();
  // render() is missing: the page never updates.
}
```

**Why it happens:** the DOM does not watch your variables. JavaScript has no reactive system by default, so no assignment, however important, will redraw the screen for you.

**The fix:** a habit of three steps on every mutation.

```js
function addTodo(text) {
  todos.push({ id: nextId++, text, done: false });
  saveTodos();  // persist
  render();     // update the view
}
```

**How to self-check:** search the file for every assignment to `todos` and every `filter` and `map` that replaces it. Every branch should end in `render()`.

## Bug 2 revisited: event delegation attached to the wrong parent

**Symptom:** clicks on list items do nothing. The listener never fires.

```js
// Wrong: the listener is on the filter area, not the list.
document.querySelector('.filter-area').addEventListener('click', (event) => {
  // this listens to filter clicks, not list clicks.
});

// Right: attach to the container that holds the rows.
document.querySelector('#todo-list').addEventListener('click', (event) => {
  const li = event.target.closest('li');
  if (!li) return;
  // handle the row click
});
```

**Why it happens:** delegation only works when the element you attach to is an ancestor of every target. Attach to the wrong container and the events you care about never bubble up to it.

**How to self-check:** ask "does this element contain every child I want to delegate for?" If the answer is no, you are attaching to the wrong node.

### Crash Site 1: the parent got replaced during render

```js
// Wrong: render replaces the whole container.
function render() {
  const container = document.querySelector('#todo-list');
  container.innerHTML = '<ul id="todo-list"></ul>';  // a new element: old listeners gone
}

// Right: clear the contents, keep the container.
function render() {
  const container = document.querySelector('#todo-list');
  container.innerHTML = '';  // contents only
  todos.forEach(todo => {
    const li = createTodoElement(todo);
    container.appendChild(li);
  });
}
```

`innerHTML = ''` empties a node and leaves the node in place. Replacing the node itself destroys the listener you attached to it.

## Bug 3 revisited: forgetting JSON.parse on localStorage

**Symptom:** a call to `.forEach` or `.filter` blows up immediately after loading.

```js
// Wrong: no parsing.
function loadTodos() {
  const raw = localStorage.getItem('todos');
  return raw || [];  // a string, or an array. Pick one.
}

const todos = loadTodos();
todos.forEach(todo => console.log(todo));  // strings do not work this way
```

**Why it happens:** `localStorage` returns a string. Assigning it to a variable called `todos` does not make it an array, and the methods you expect are simply not there.

```js
// Right: parse defensively.
function loadTodos() {
  const raw = localStorage.getItem(STORAGE_KEY);
  if (raw === null) return [];
  try {
    return JSON.parse(raw);
  } catch (err) {
    console.error('Could not parse stored data:', err);
    return [];
  }
}
```

**How to self-check:** right after `loadTodos()`, log `Array.isArray(todos)`. If it is false, the rest of the program has no chance.

## A quick bug reference

| Bug | Symptom | Cause | Fix |
|---|---|---|---|
| Listener fires once | It works, then stops | `innerHTML` rebuilt the container | Delegate, or clear contents only |
| Garbled characters | Non-ASCII text looks wrong | No charset or wrong encoding | `<meta charset="UTF-8">` |
| Click does nothing | Element exists, event does not | Script ran before the DOM | Move script or use DOMContentLoaded |
| Variable is undefined | Function cannot see outer state | Scope or closure issue | Check where it is declared |
| Memory grows | Page gets slower over time | `setInterval` never cleared | `clearInterval` on teardown |

## Recap

- Group code by responsibility: config, state, utilities, business logic, wiring, startup.
- Classic bug 1: **the array changed but `render()` was forgotten.** The DOM never updates itself.
- Classic bug 2: **delegation attached to the wrong parent.** The parent must contain every target.
- Classic bug 3: **`localStorage` value was not `JSON.parse`d.** A string has no array methods.
- Make self-checks a habit: trace every data mutation, confirm each one renders and saves.
- Next up: modules, async requests, and modern frameworks.
