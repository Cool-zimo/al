# `localStorage` and `sessionStorage`: keeping data after a reload

> This lesson answers: how do you store data in the browser so it survives a refresh? The crucial detail is that **storage values are always strings**.

## `localStorage` versus `sessionStorage`

| Feature | `localStorage` | `sessionStorage` |
|---|---|---|
| Lifetime | Until removed or storage is cleared | Cleared when the tab closes |
| Scope | Shared by all tabs of the same origin | Only the current tab |
| Size | Around 5 MB | Around 5 MB |

```js
localStorage.setItem('key', 'value');      // store
const value = localStorage.getItem('key'); // read
localStorage.removeItem('key');            // delete one key
localStorage.clear();                      // delete everything
```

Both APIs work the same way. The only real difference is how long the data stays around.

## Storage stores strings only

`localStorage` converts everything you give it into a string. A number comes back as text.

```js
localStorage.setItem('age', 25);
console.log(localStorage.getItem('age')); // "25"
console.log(typeof localStorage.getItem('age')); // "string"

const age = Number(localStorage.getItem('age'));
```

`sessionStorage` has the same limitation, so the same serialisation rules apply.

## Objects need `JSON.stringify` and `JSON.parse`

### Crash Site 1: storing an object directly

```js
const settings = { theme: 'dark', fontSize: 16 };

localStorage.setItem('settings', settings);
console.log(localStorage.getItem('settings'));
// "[object Object]"

JSON.parse(localStorage.getItem('settings'));
// SyntaxError: Unexpected token o in JSON at position 1
```

**Why it crashes:** an object passed to `setItem` is implicitly converted with `String()`, producing `"[object Object]"`. The original data is gone, and the resulting text is not valid JSON. The fix is to stringify first and parse when you read:

```js
const user = { name: 'Alice', age: 28, city: 'London' };

localStorage.setItem('user', JSON.stringify(user));
// '{"name":"Alice","age":28,"city":"London"}'

const saved = JSON.parse(localStorage.getItem('user'));
console.log(saved.name); // "Alice"
```

Remember the rhythm: **`JSON.stringify` before storing, `JSON.parse` after reading.**

## A safe storage helper

A helper avoids two recurring problems: forgetting to serialise and reading a key that does not exist.

```js
function saveData(key, data) {
  localStorage.setItem(key, JSON.stringify(data));
}

function loadData(key, defaultValue = null) {
  const raw = localStorage.getItem(key);
  if (raw === null) return defaultValue;

  try {
    return JSON.parse(raw);
  } catch (err) {
    console.error('Could not parse stored data:', err);
    return defaultValue;
  }
}

saveData('todos', [{ id: 1, text: 'Buy milk', done: false }]);

const todos = loadData('todos', []);
console.log(todos); // [{ id: 1, text: 'Buy milk', done: false }]
```

### Crash Site 2: assuming a missing key is an empty array

```js
const todos = JSON.parse(localStorage.getItem('todos'));
todos.forEach(todo => console.log(todo));
// TypeError: Cannot read properties of null
```

**Why it crashes:** a missing key returns `null`, not `"null"`. `JSON.parse(null)` returns `null`, so calling `.forEach()` on it fails. Return a sensible default instead.

## Storage limits and failure handling

Most browsers allow around 5 MB. Writing more than that, or writing in private browsing on some browsers, can throw.

```js
try {
  const huge = 'x'.repeat(10 * 1024 * 1024);
  localStorage.setItem('huge', huge);
} catch (err) {
  if (err.name === 'QuotaExceededError') {
    console.error('Storage is full.');
  }
}
```

### Crash Site 3: private browsing can reject writes

```js
localStorage.setItem('key', 'value'); // may throw in private mode
```

**Why it crashes:** some private modes give storage zero effective quota. Detect availability once, then fall back to an in-memory object.

```js
function isStorageAvailable() {
  try {
    const testKey = '__test__';
    localStorage.setItem(testKey, testKey);
    localStorage.removeItem(testKey);
    return true;
  } catch (err) {
    return false;
  }
}

if (isStorageAvailable()) {
  localStorage.setItem('key', 'value');
} else {
  console.warn('localStorage is unavailable; using memory store.');
  window.__memoryStore = {};
}
```

## Practical uses

```js
// Persist a user preference
saveData('theme', { mode: 'dark', fontSize: 16 });

// Save a draft as the user types
const form = document.querySelector('#article-form');
form.addEventListener('input', () => {
  saveData('draft', { title: form.title.value, content: form.content.value });
});

// Restore the draft on load
const draft = loadData('draft', null);
if (draft) {
  form.title.value = draft.title;
  form.content.value = draft.content;
}

// Remember a shopping cart
saveData('cart', [{ id: 1, name: 'Notebook', price: 12, qty: 3 }]);
```

`sessionStorage` is the right home for temporary state such as the current page in a list or a short-lived form token:

```js
sessionStorage.setItem('currentPage', '2');
sessionStorage.setItem('searchQuery', 'JavaScript');
```

## Comparison with Python

Python persistence usually means files or a database:

```python
import json

with open('data.json', 'w') as f:
    json.dump(data, f)

with open('data.json', 'r') as f:
    data = json.load(f)
```

`localStorage` is a key-value store bound to the current origin. It is convenient, but its string-only rule makes serialisation part of almost every read and write.

## Recap

- `localStorage` survives a reload; `sessionStorage` is cleared with the tab. Their APIs are identical.
- Both store strings only. Objects must be `JSON.stringify`ed and parsed with `JSON.parse`.
- Storing an object without serialising it produces `"[object Object]"`, which cannot be parsed back.
- A missing key returns `null`; provide a default and guard against parse errors.
- Storage is limited to around 5 MB and can throw in private browsing.
- Save small, structured values such as preferences, drafts and carts.
