# Structure and style: the HTML skeleton and CSS layout

> This lesson answers: how do you turn last lesson's sketch into actual HTML and CSS?

## The HTML skeleton

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My tasks</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <div class="container">
    <h1>✦ My tasks</h1>

    <!-- Input area -->
    <div class="input-area">
      <input type="text" id="todo-input" placeholder="Add a new task...">
      <button id="add-btn">Add</button>
    </div>

    <!-- Task list -->
    <ul id="todo-list"></ul>

    <!-- Filter area -->
    <div class="filter-area">
      <button class="filter-btn active" data-filter="all">All</button>
      <button class="filter-btn" data-filter="active">Active</button>
      <button class="filter-btn" data-filter="completed">Done</button>
    </div>

    <!-- Stats -->
    <p id="stats">0 tasks total</p>
  </div>

  <script src="app.js"></script>
</body>
</html>
```

**Three points are worth your attention:**

- The list `<ul id="todo-list">` starts empty. JavaScript fills it.
- The filter buttons carry a `data-filter` attribute. That is how the script knows which mode each button represents without parsing its text.
- The `script` sits at the end of the body so the DOM exists before any JavaScript runs.

An `id` is for the one thing you will look up once, like `#todo-input`. A `data-` attribute is for information you want to read back later, like which filter a button stands for. The distinction keeps your JavaScript from having to guess what a button means based on the words printed on it.

## Reading the layout

### A flex input area

```css
.input-area {
  display: flex;
  gap: 10px;  /* spacing between children */
}

#todo-input {
  flex: 1;     /* the input takes the remaining space */
}
```

`flex: 1` means "grow to fill whatever the button did not take." The button keeps its content width, the input takes the rest, and `gap` supplies the space between them.

### A flex list row

```css
#todo-list li {
  display: flex;
  align-items: center;  /* vertical centring */
  gap: 10px;            /* spacing between elements */
}

.delete-btn {
  margin-left: auto;    /* pushed to the far right */
}
```

`margin-left: auto` is the classic flex trick for shoving an element to one end. It is doing the same job here as "right-aligned" would in a word processor, but it survives content of any width because it is just leftover space being claimed.

## What the page looks like at load

When the file first opens:

- the title sits at the top;
- the input and the add button sit in the middle;
- the list region is empty;
- the filter buttons and the stats line sit at the bottom.

Everything interactive is driven by JavaScript. The HTML is a skeleton, not a finished page.

### Crash Site 1: a stylesheet that silently does nothing

```html
<link rel="stylesheet" href="style.css">
```

```js
// app.js
const list = document.querySelector('#todo-list');
list.innerHTML = '...';  // fine
```

If the filename on disk is `styles.css` while the link asks for `style.css`, the browser fetches nothing, logs a single 404 in the network panel, and renders your page with zero styles. Students then spend twenty minutes convinced their selectors are wrong. **Open the network tab before you start rewriting CSS.** The error is almost always a mismatched filename, a wrong folder, or a server that has not been restarted.

## Comparison with Python

In Python, HTML is usually generated on the server by a template engine:

```python
# Flask / Jinja2 template
from flask import Flask, render_template

app = Flask(__name__)

@app.route('/')
def index():
    return render_template('index.html', todos=todos)
```

```html
<!-- Jinja2 template: server-side rendering -->
<ul>
  {% for todo in todos %}
    <li>{{ todo.text }}</li>
  {% endfor %}
</ul>
```

The JavaScript approach is **client-side rendering**: the HTML arrives empty and the browser builds the DOM after fetching the data. Both are valid; they differ in who does the work and when.

## Recap

- The HTML skeleton provides structure only: input area, an empty list container, filter area, stats area.
- Use flexbox for layout: `display: flex` with `gap` and `margin-left: auto`.
- The list starts empty and JavaScript renders it. That is the core pattern of front-end rendering.
- `data-filter` lets JavaScript read the filter mode without parsing button text.
- Place the script at the end of the body so the DOM is ready before it runs.
