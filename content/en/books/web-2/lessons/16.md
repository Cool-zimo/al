# Your first event: `addEventListener`

> This lesson answers: how do you make a page respond to what the user does? A Python script runs top to bottom and then exits. The browser is different: **after your code finishes, the browser keeps waiting** — for clicks, keystrokes, scrolling. That is event-driven programming.

## The event-driven model

```python
# Python script: runs to completion, then exits
print("start")
name = input("enter your name: ")  # blocks, waiting for the user
print(f"hello, {name}")
# program ends
```

```js
// JavaScript: after the synchronous code runs, the browser keeps "waiting"
console.log("script done");

document.querySelector('button').addEventListener('click', function () {
  console.log("the user clicked the button!");  // nobody knows when
});

console.log("now waiting for the user...");
// synchronous code ends here
// but the browser does not exit - it is waiting for a click
```

**That is the event-driven model**: you register a rule that says "when this happens, run that", and the browser waits in the background.

## `addEventListener`: registering an event

```js
const button = document.querySelector('#myBtn');

button.addEventListener('click', function (event) {
  console.log('the button was clicked!');
});
```

Three pieces:

1. **The event type** (`'click'`) — when does it fire?
2. **The callback function** — what should happen?
3. **The target element** — who is listening?

## Why not `onclick=`?

The HTML-attribute way:

```html
<button onclick="handleClick()">Click me</button>
```

The JavaScript-property way:

```js
button.onclick = function () {
  console.log('clicked');
};
```

**The problem: `onclick` can only hold one handler.**

```js
const button = document.querySelector('#myBtn');

// the first handler is overwritten!
button.onclick = function () { console.log('first'); };
button.onclick = function () { console.log('second'); };
// only "second" runs on click
```

With `addEventListener` you can attach as many as you like:

```js
button.addEventListener('click', function () { console.log('first'); });
button.addEventListener('click', function () { console.log('second'); });
// both run on click
```

### Crash Site 1: the script runs before the element exists

```html
<head>
  <script>
    // the button does not exist yet!
    document.querySelector('#myBtn').addEventListener('click', handler);
    // TypeError: Cannot read properties of null
  </script>
</head>
<body>
  <button id="myBtn">Click me</button>
</body>
```

**Why it crashes:** when the script runs, the browser has not parsed the button yet, so `querySelector` returns `null`. Fix: put the `<script>` just before `</body>`, or wrap the code in a `DOMContentLoaded` listener.

### Crash Site 2: assigning to `onclick` wipes out an existing handler

```js
// a third-party library already attached a handler
button.onclick = function () { trackClick(); };

// your code
button.onclick = function () { showModal(); };
// trackClick never runs again - it was overwritten!
```

**Why it crashes:** `onclick` is a property assignment; the later value replaces the earlier one. This is especially dangerous in team projects or when a library has already set up behaviour you did not know about. Always use `addEventListener`.

## Common event types

| Event | When it fires | Typical elements |
|---|---|---|
| `click` | element is clicked | button, a, div |
| `input` | the value changes | input, textarea |
| `change` | value is committed | select, checkbox |
| `submit` | a form is submitted | form |
| `keydown` / `keyup` | a key is pressed / released | document, input |
| `mouseover` / `mouseout` | pointer enters / leaves | any element |
| `load` | a resource finishes loading | window, img |
| `scroll` | the page or an element scrolls | window, scrollable elements |
| `focus` / `blur` | element gains / loses focus | input |

## The event object

The first argument passed to your callback is the **event object**, which carries details about what just happened:

```js
button.addEventListener('click', function (event) {
  console.log(event.type);     // "click"
  console.log(event.target);   // the element that was clicked
  console.log(event.clientX);  // mouse X coordinate
});
```

## Comparison with Python

Python has no built-in event loop (unless you use a GUI framework such as Tkinter):

```python
# Tkinter's event-driven model is similar
import tkinter as tk

root = tk.Tk()
button = tk.Button(root, text="Click")
button.bind("<Button-1>", lambda e: print("clicked"))  # like addEventListener
root.mainloop()  # enter the event loop
```

`button.bind("<Button-1>", callback)` is the Python cousin of `addEventListener('click', callback)`. The concepts are the same; the difference is that the browser gives you the event loop for free — no `mainloop()` required.

## Recap

- The browser is event-driven: after your code finishes, it keeps waiting for user actions.
- `addEventListener(type, callback)` registers an event handler.
- `onclick` can hold only one handler and is easily overwritten; `addEventListener` stacks handlers safely.
- Your script must run after the DOM exists (place it before `</body>` or use `DOMContentLoaded`).
- The event object is the first argument of your callback and holds the event details.
