# Types and conversion: `NaN`, `typeof null` and string-plus-number

> This lesson answers: how do types actually work in JS? JS is dynamically typed, so a variable can hold a value of any type — but that freedom brings some surprising behaviour. What does `"5" + 3` equal, for example?

## JavaScript's primitive types

JS has seven primitive types:

| Type | Example | Notes |
|---|---|---|
| `number` | `42`, `3.14`, `NaN` | every number is a number |
| `string` | `"hello"`, `'world'` | text |
| `boolean` | `true`, `false` | true/false |
| `undefined` | `undefined` | not assigned |
| `null` | `null` | intentionally empty |
| `symbol` | `Symbol("id")` | a unique identifier |
| `bigint` | `9007199254740993n` | arbitrarily large integers |

On top of those comes `object` — which includes arrays, functions, dates and more.

## Strings and numbers: the ambiguous `+`

In JS, `+` does double duty as addition and string concatenation. When one operand is a string, `+` concatenates:

```js
5 + 3        // 8 (addition)
"5" + 3      // "53" (concatenation)
3 + "5"      // "35" (same thing)
"hello" + 5  // "hello5"
```

### Crash Site 1: input values are always strings

```js
const price = document.getElementById('price').value;  // "100"
const quantity = document.getElementById('qty').value;   // "2"
const total = price + quantity;  // "1002" — not 102
```

**Why it crashes:** you expected a total of 102 but got the string `"1002"`. Every further calculation that uses this value will keep spreading the bug. The fix: `Number(price) + Number(quantity)`, or `+price + +quantity` if you enjoy unreadable code.

## `NaN`: Not a Number

`NaN` is a special numeric value meaning "this is not a valid number":

```js
Number("abc")      // NaN
parseInt("12px")   // 12 (parses from the start, stops at p)
parseInt("px12")   // NaN (does not start with a digit)
0 / 0              // NaN
Math.sqrt(-1)      // NaN
```

**`NaN` has a strange property: it is not equal to anything, including itself.**

```js
NaN === NaN  // false!
```

To test for `NaN`, use `Number.isNaN(x)` or `isNaN(x)`.

```js
Number.isNaN(NaN);       // true
Number.isNaN("hello");   // false ("hello" is not of type NaN)
isNaN("hello");          // true ("hello" is converted to NaN, then tested)
```

### Crash Site 2: testing with `=== NaN`

```js
function calculate(a, b) {
  const result = a / b;
  if (result === NaN) {  // never true
    return "Calculation failed";
  }
  return result;
}
```

**Why it crashes:** `result === NaN` is *always* `false`, so the error handling never fires. You should write `Number.isNaN(result)` instead.

## `typeof null === 'object'`: a 27-year-old bug

This is a bug JavaScript has carried for 27 years without fixing:

```js
typeof null      // "object"  ← bug!
typeof undefined  // "undefined"
typeof []         // "object"
typeof {}         // "object"
typeof 42         // "number"
typeof "hello"    // "string"
typeof true       // "boolean"
typeof function(){} // "function"
```

The reason: `typeof` inspects the value's **type tag**. `null`'s type tag is `0`, the same as an object's, so the result is `"object"`.

### Crash Site 3: using `typeof x === 'object'` to detect an object

```js
function isObject(x) {
  return typeof x === 'object';
}
isObject(null);    // true — but null is not an object
isObject([]);      // true
isObject({});      // true
```

**Why it crashes:** `null` is wrongly classified as an object. The correct test:

```js
function isObject(x) {
  return x !== null && typeof x === 'object';
}
// or, more modern:
x === Object(x);  // true for objects and arrays
```

## Comparison with Python

| Situation | Python | JavaScript |
|---|---|---|
| `"5" + 3` | `TypeError` | `"53"` (concatenation) |
| `5 / 0` | `ZeroDivisionError` | `Infinity` |
| `int("abc")` | `ValueError` | `NaN` |
| `type(None)` | `<class 'NoneType'>` | `"object"` (the bug) |
| type check | `isinstance(x, int)` | `typeof x === 'number'` |

Python is strongly typed: `"5" + 3` raises an error outright. JavaScript is weakly typed, and `+` will convert implicitly.

## Recap

- If either side of `+` is a string, you get concatenation; adding a number to other types may also coerce them to strings.
- Values read from the DOM are strings — convert them before calculating.
- `NaN` equals nothing, not even itself; check with `Number.isNaN()`.
- `typeof null === 'object'` is a historical bug; exclude `null` before detecting objects.
- JS is weakly typed: both `==` and `+` perform implicit conversion.
