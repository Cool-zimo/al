# Iteration: `for`, `for...of`, `forEach` and the `return` trap

> This lesson answers: how do you iterate over an array in JS? JS offers several styles, and the differences are subtle but important — especially the fact that `return` inside `forEach` does not break out of the loop.

## Four ways to iterate

### 1. The classic `for` loop

```js
const arr = [10, 20, 30];
for (let i = 0; i < arr.length; i++) {
  console.log(arr[i]);
}
```

Like Python's `for i in range(len(arr))`. You get an index and full control over flow.

### 2. `for...of` (recommended)

```js
for (const item of arr) {
  console.log(item);
}
```

Almost identical to Python's `for item in arr`. Clean, and you get the element value directly.

### 3. `forEach`

```js
arr.forEach(function(item) {
  console.log(item);
});
// or with an arrow function
arr.forEach(item => console.log(item));
```

### 4. `for...in` (not recommended for arrays)

```js
for (const i in arr) {
  console.log(i);  // "0", "1", "2" (string indices!)
}
```

## `return` inside `forEach` does NOT break the loop

This is a classic JS trap, and Python migrants hit it constantly:

```python
# Python: return the first even number you find
numbers = [1, 3, 4, 5, 6]
for n in numbers:
    if n % 2 == 0:
        print(n)
        break  # exit the loop
# prints: 4
```

```js
// JS: trying to "finish early" with forEach
[1, 3, 4, 5, 6].forEach(function(n) {
  if (n % 2 === 0) {
    console.log(n);
    return;  // this only skips the current iteration!
  }
});
// prints: 4, 6 (both of them!)
```

### Crash Site 1: expecting `return` to break `forEach`

```js
function findFirstEven(arr) {
  arr.forEach(function(n) {
    if (n % 2 === 0) {
      return n;  // this only skips the current callback; it does not return from the outer function
    }
  });
  return -1;  // this line always runs
}
findFirstEven([1, 3, 4, 5]);  // returns -1, not 4!
```

**Why it crashes:** `return` inside `forEach` is equivalent to Python's `continue` — it skips the current iteration and moves to the next. It **cannot** break out of the whole loop, and it **cannot** return a value from the enclosing function.

**Solutions:**

```js
// option 1: for...of with break (closest to Python)
function findFirstEven(arr) {
  for (const n of arr) {
    if (n % 2 === 0) {
      return n;  // returns from the function
    }
  }
  return -1;
}

// option 2: find() (more functional)
function findFirstEven(arr) {
  return arr.find(n => n % 2 === 0) ?? -1;
}
```

## Choosing an iteration style

| Situation | Prefer | Reason |
|---|---|---|
| you need the index | `for` or `forEach` | `for...of` needs `entries()` |
| you need break/continue | `for` or `for...of` | `forEach` cannot break out |
| you need a return value | `for`/`for...of` or `map`/`find` | `forEach`'s return is useless |
| pure iteration, no flow control | `forEach` | clear intent |
| you want to transform every element | `map` | returns a new array |
| you want to filter | `filter` | returns a new array |

## The `for...in` trap

```js
const arr = [10, 20, 30];
arr.customProp = "oops";  // someone added a custom property

for (const key in arr) {
  console.log(key);  // "0", "1", "2", "customProp"!
}
```

**Why it crashes:** `for...in` iterates over **all enumerable properties** (including custom ones), yielding string keys. It walks the prototype chain too, and it will happily enumerate non-numeric properties added by hand.

**Always use `for...of` to iterate arrays, and `for...in` to iterate objects.**

## Comparison with Python

```python
# Python
numbers = [10, 20, 30]

for n in numbers:        # JS for...of
    print(n)

for i in range(len(numbers)):  # JS for
    print(numbers[i])

for i, n in enumerate(numbers):  # JS for...of + entries()
    print(i, n)
```

```js
// JavaScript
const numbers = [10, 20, 30];

for (const n of numbers) { }       // Python's for...in
for (let i = 0; i < numbers.length; i++) { }  // Python's range(len())
for (const [i, n] of numbers.entries()) { }    // Python's enumerate
numbers.forEach(n => { });         // no direct Python equivalent
```

## Recap

- `for...of` is the everyday iteration tool; it behaves like Python's `for...in`.
- `return` inside `forEach` only skips the current iteration (like `continue`); it cannot break, and cannot return from the outer function.
- When you need to break or return, use `for`/`for...of` or an array method such as `find`, `some` or `every`.
- `for...in` iterates all enumerable properties (including custom ones); do not use it for arrays.
- `for...in` for objects, `for...of` for arrays — that is the rule.

starter: |
  function findIndex(arr, target) {
      // use for...of + entries() to get the index
      let result = -1;
      return result;
  }

  [1, 2, 3, 4], 3 -> 2
  [1, 2, 3], 5 -> -1
  [10, 20, 30], 10 -> 0
  ["a", "b", "c"], "b" -> 1
hint: Use for (const [i, item] of arr.entries()) to get both the index and the value.
