# CRUD in the browser: render functions and event handling

> This lesson answers: how do you turn the data structure from lesson 26 into a working, interactive to-do app?

## The full code skeleton

```js
// ====== Data ======
let todos = [];
let nextId = 1;

// ====== DOM references ======
const todoInput = document.querySelector('#todo-input');
const addBtn = document.querySelector('#add-btn');
const todoList = document.querySelector('#todo-list');
const statsEl = document.querySelector('#stats');

// ====== Render ======
function render() {
  todoList.innerHTML = '';

  todos.forEach(todo => {
    const li = document.createElement('li');
    if (todo.done) li.classList.add('done');

    const checkbox = document.createElement('input');
    checkbox.type = 'checkbox';
    checkbox.checked = todo.done;
    checkbox.addEventListener('click', () => toggleTodo(todo.id));

    const span = document.createElement('span');
    span.textContent = todo.text;

    const deleteBtn = document.createElement('button');
    deleteBtn.textContent = 'Delete';
    deleteBtn.className = 'delete-btn';
    deleteBtn.addEventListener('click', () => deleteTodo(todo.id));

    li.appendChild(checkbox);
    li.appendChild(span);
    li.appendChild(deleteBtn);
    todoList.appendChild(li);
  });

  updateStats();
}

// ====== Create ======
function addTodo() {
  const text = todoInput.value.trim();
  if (text === '') {
    alert('Task cannot be empty');
    return;
  }

  todos.push({ id: nextId++, text, done: false });
  todoInput.value = '';
  render();
}

// ====== Delete ======
function deleteTodo(id) {
  todos = todos.filter(todo => todo.id !== id);
  render();
}

// ====== Update ======
function toggleTodo(id) {
  const todo = todos.find(todo => todo.id === id);
  if (todo) {
    todo.done = !todo.done;
    render();
  }
}

// ====== Stats ======
function updateStats() {
  const total = todos.length;
  const done = todos.filter(t => t.done).length;
  statsEl.textContent = `${total} total, ${done} done`;
}

// ====== Event wiring ======
addBtn.addEventListener('click', addTodo);

todoInput.addEventListener('keydown', (event) => {
  if (event.key === 'Enter') {
    addTodo();
  }
});
```

Notice what every mutating function has in common: it changes `todos`, then calls `render()`. The order never varies. That regularity is not an accident; it is the whole architecture.

## Event delegation

The version above attaches a listener to every checkbox and every button. For three items that is fine. For three hundred it is wasteful, and for items that have not been created yet it is impossible. Event delegation moves the listener up to the list container:

```js
// One listener on the list container
todoList.addEventListener('click', (event) => {
  const li = event.target.closest('li');
  if (!li) return;

  const id = Number(li.dataset.id);

  if (event.target.classList.contains('delete-btn')) {
    deleteTodo(id);
    return;
  }

  if (event.target.type === 'checkbox') {
    toggleTodo(id);
    return;
  }
});
```

**One listener covers every row, including rows that do not exist yet.** The click bubbles up from the element you actually clicked, and you identify the row with `closest('li')`.

### Crash Site 1: rendering without storing the id on the DOM

```js
// Wrong: nothing about the id reaches the DOM.
function render() {
  todoList.innerHTML = '';
  todos.forEach(todo => {
    const li = document.createElement('li');
    li.textContent = todo.text;  // the id is nowhere to be found
    todoList.appendChild(li);
  });
}

// Later, delegation has nothing to read.
todoList.addEventListener('click', (event) => {
  const li = event.target.closest('li');
  const id = li.dataset.id;  // undefined: render never set data-id
});
```

Without the id in the DOM, delegation cannot locate the object. Every delete hits the wrong task.

```js
// Right: store the id on the element.
function render() {
  todoList.innerHTML = '';
  todos.forEach(todo => {
    const li = document.createElement('li');
    li.dataset.id = todo.id;  // essential: the id travels with the row
    li.className = todo.done ? 'done' : '';
    li.innerHTML = `
      <input type="checkbox" ${todo.done ? 'checked' : ''}>
      <span>${todo.text}</span>
      <button class="delete-btn">Delete</button>
    `;
    todoList.appendChild(li);
  });
  updateStats();
}
```

## Template strings versus createElement

```js
// Approach 1: innerHTML plus a template string (concise, but mind XSS)
li.innerHTML = `
  <input type="checkbox" ${todo.done ? 'checked' : ''}>
  <span>${todo.text}</span>
  <button class="delete-btn">Delete</button>
`;

// Approach 2: createElement (verbose, but safe by default)
const checkbox = document.createElement('input');
checkbox.type = 'checkbox';
// ...many appendChild calls
```

**Security note:** when `todo.text` comes from a user, `innerHTML` opens an XSS hole. Escape it or use `textContent`.

```js
// Safe template rendering: escape user input first.
function escapeHtml(str) {
  return str.replace(/[&<>"']/g, char => ({
    '&': '&amp;',
    '<': '&lt;',
    '>': '&gt;',
    '"': '&quot;',
    "'": '&#39;'
  }[char]));
}

li.innerHTML = `
  <span>${escapeHtml(todo.text)}</span>
`;
```

### Crash Site 2: an innerHTML injection

```js
// A user types malicious content into the input.
todos.push({ id: 1, text: '<img src=x onerror="alert(1)">', done: false });

// Rendered with innerHTML, the script runs.
li.innerHTML = `<span>${todo.text}</span>`;
// alert(1) fires: XSS succeeds.
```

Treat any string that came from an input as hostile until proven otherwise. `textContent` is safe because it never parses its argument as markup; `innerHTML` does. The choice is not about style, it is about whether you are willing to execute what the user typed.

## Edge cases in the add function

```js
function addTodo() {
  const text = todoInput.value.trim();

  // Edge 1: empty string
  if (text === '') {
    alert('Please enter a task');
    todoInput.focus();
    return;
  }

  // Edge 2: text too long
  if (text.length > 100) {
    alert('Keep it under 100 characters');
    return;
  }

  // Edge 3: duplicate task
  if (todos.some(t => t.text === text)) {
    alert('That task already exists');
    return;
  }

  todos.push({ id: nextId++, text, done: false });
  todoInput.value = '';
  todoInput.focus();  // keep focus for rapid entry
  render();
}
```

Validate at the boundary, once, where the data enters the system. If you scatter checks throughout the code, someone will find the one path that skips them.

## Comparison with Python

```python
# Python: create, read, update, delete
todos = []

# Create
todos.append({"id": 1, "text": "Buy milk", "done": False})

# Delete
todos = [t for t in todos if t["id"] != 1]

# Update
for t in todos:
    if t["id"] == 1:
        t["done"] = True

# Read
for t in todos:
    print(t["text"])
```

The JavaScript array operations (`push`, `filter`, `find`) map almost one for one onto Python. The only extra step is calling `render()` afterwards to make the change visible.

## Recap

- The render function is the core: clear the DOM, walk the data, create elements, assemble, update stats.
- Event delegation attaches one listener to the parent and uses `data-id` to connect the DOM back to the data.
- Rendering must write the id onto the DOM, or delegation has nothing to read.
- `innerHTML` carries an XSS risk; escape input or prefer `textContent`.
- Validate input at the boundary: empty, too long, duplicate.
- After every change to the data, call `render()`.
