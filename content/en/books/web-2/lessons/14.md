# Changing attributes and styles: `getAttribute`/`setAttribute`, `classList`, `style`

> This lesson answers: how do you change an element's attributes and CSS styles? You have changed attributes on Python objects before; DOM element attributes and styles work similarly, but with a few dedicated APIs.

## Two ways to handle attributes

### Method 1: direct access (preferred)

```js
const link = document.querySelector('a');

// read
link.href;          // "https://example.com"
link.id;            // "myLink"
link.className;     // "external"

// write
link.href = "https://google.com";
link.target = "_blank";
```

### Method 2: `getAttribute` / `setAttribute`

```js
const link = document.querySelector('a');

// read
link.getAttribute('href');     // "https://example.com"
link.getAttribute('data-id');  // "123"

// write
link.setAttribute('href', 'https://google.com');
link.setAttribute('data-user', 'Alice');
```

### Crash Site 1: the difference between the two methods

```js
const input = document.querySelector('input');

// direct access
input.value = "hello";       // changes the value property on the DOM object
input.getAttribute('value'); // "world" (the HTML attribute is untouched!)

// setAttribute changes the HTML attribute
input.setAttribute('value', 'hello');
input.value;                 // "hello" (now in sync)
```

**Why it crashes:** for **state attributes** like `value`, `checked` and `disabled`, the DOM property and the HTML attribute can fall out of sync. Assigning `input.value = "x"` changes the DOM state, but `getAttribute('value')` reads the HTML attribute (the initial value).

**Rule of thumb:** use **direct access** for everyday work (`input.value`, `img.src`); reach for `getAttribute`/`setAttribute` only for custom or `data-*` attributes.

## `classList`: manipulating CSS classes

```js
const btn = document.querySelector('.btn');

btn.classList.add('active');        // add a class
btn.classList.remove('disabled');   // remove a class
btn.classList.toggle('dark-mode');  // toggle (remove if present, add if absent)
btn.classList.toggle('dark-mode', true);  // force-add
btn.classList.contains('active');   // check whether a class is present
btn.classList.replace('old', 'new'); // replace a class
```

```js
// several operations at once
btn.classList.add('active', 'primary');
btn.classList.remove('old', 'deprecated');
```

Compared with Python (if you modelled it as a set):

```python
classes = ["btn", "primary"]
classes.append("active")       # like classList.add
classes.remove("primary")      # like classList.remove
```

## `className`: wholesale replacement

```js
const div = document.querySelector('.box');
div.className = "new-class";    // replaces every class (dangerous — wipes the rest)
div.className += " extra";     // appends a class (easy to get wrong; trailing-space issues)
```

**Prefer `classList` over `className`** — `className` replaces the whole lot.

### Crash Site 2: forgetting the space when appending with `className +=`

```js
const div = document.querySelector('.box');
div.className += "active";   // if className was "box", the result is "boxactive" — no space!
```

**Why it crashes:** the class names are glued together, so the CSS selector `.boxactive` matches nothing. `classList.add()` never has this problem.

## `style`: inline styles

```js
const div = document.querySelector('.box');

// set a single style
div.style.color = "red";
div.style.fontSize = "20px";       // CSS properties use camelCase
div.style.backgroundColor = "#fff"; // background-color becomes backgroundColor

// set several at once
div.style.cssText = "color: red; font-size: 20px; padding: 10px;";

// read
div.style.color;  // "red" (inline styles only!)

// read a computed style from any source
getComputedStyle(div).fontSize;  // "20px"
```

**Important:** `element.style.xxx` can only read and write **inline styles** (the ones in `style="..."`). To read a style defined in a CSS file or a `<style>` block, use `getComputedStyle()`.

## `data-*` attributes

HTML5 introduced `data-*` custom attributes, accessible in JS through `dataset`:

```html
<div id="user" data-id="123" data-user-name="Alice" data-role="admin"></div>
```

```js
const user = document.querySelector('#user');

// read
user.dataset.id;         // "123"
user.dataset.userName;   // "Alice" (data-user-name becomes userName: dashes to camelCase)
user.dataset.role;       // "admin"

// write
user.dataset.id = "456";
user.dataset.newProp = "value";  // automatically creates data-new-prop
```

### Crash Site 3: `dataset` naming conversion

```js
// HTML: <div data-user-id="123"></div>
element.dataset.user-id;   // undefined! there should be no dash
element.dataset.userId;    // "123"
```

**Why it crashes:** `data-user-id` maps to `dataset.userId` in JS — dashes become camelCase, and the `data-` prefix is dropped. The `data-` prefix belongs in the HTML; leave it out in JS.

## Comparison with Python

Python has no DOM, but you can model the operations on a dictionary:

```python
# analogy: attribute access is like reading and writing a dictionary
element = {"tag": "a", "attrs": {"href": "https://example.com"}}
element["attrs"]["href"] = "https://google.com"  # like setAttribute

# classList is like set operations
classes = {"btn", "primary"}
classes.add("active")      # like classList.add
classes.remove("primary")  # like classList.remove
```

## Recap

- Two ways to handle attributes: direct access (`img.src`) and `getAttribute`/`setAttribute`.
- State attributes (`value`, `checked`) can fall out of sync between the DOM property and the HTML attribute.
- `classList` is the best tool for CSS classes: `add` / `remove` / `toggle` / `contains`.
- `style.xxx` uses camelCase (`fontSize`, not `font-size`) and only reads inline styles.
- `data-*` attributes are accessed through `dataset`; dashes become camelCase.
- Prefer `classList` to `className` to avoid overwriting and spacing bugs.
