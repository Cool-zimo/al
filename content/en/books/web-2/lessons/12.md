# Finding elements: `getElementById` / `querySelector` / `querySelectorAll`

> This lesson answers: how do you find the element you want inside the DOM tree? This is the first step of every DOM operation — find it first, then manipulate it.

## Three ways to query

### 1. `getElementById`: find by ID

```js
const button = document.getElementById('submit-btn');
```

- Returns a **single element** or `null`.
- The fastest option (the browser keeps an ID index).
- Limited to IDs; you cannot use other selectors.

### 2. `querySelector`: the first match for a CSS selector

```js
document.querySelector('.intro');       // first element with class="intro"
document.querySelector('#header');     // first element with id="header"
document.querySelector('p:first-child'); // first p that is a first child
document.querySelector('ul li');        // first li inside a ul
```

- Returns the **first matching element** or `null`.
- Uses CSS selector syntax — very flexible.

### 3. `querySelectorAll`: every match for a CSS selector

```js
document.querySelectorAll('.item');     // all elements with class="item"
document.querySelectorAll('li');        // all li elements
document.querySelectorAll('div > p');   // all p that are direct children of div
```

- Returns a **NodeList** (like an array, but not an array).
- When nothing matches, it returns an **empty NodeList** (not `null`!).

## NodeList vs Array

```js
const items = document.querySelectorAll('.item');

items.length;      // count
items[0];          // first element

// NodeList has forEach but not map or filter
items.forEach(item => console.log(item));

// when you need map or filter, convert to an array
const arr = Array.from(items);
const arr2 = [...items];  // the spread operator works too
```

### Crash Site 1: expecting `querySelectorAll` to return `null`

```js
const items = document.querySelectorAll('.nonexistent');
if (items === null) {  // never true!
  console.log("not found");
}
console.log(items);  // NodeList [] (empty, but not null)
```

**Why it crashes:** when `querySelectorAll` finds nothing, it returns an **empty NodeList**, not `null`. Test with `items.length === 0`.

By contrast, `querySelector` returns `null` when it finds nothing:

```js
const item = document.querySelector('.nonexistent');
if (item === null) {  // correct
  console.log("not found");
}
```

**Remember: `querySelector` returns `null`; `querySelectorAll` returns an empty NodeList.**

### Crash Site 2: ID case sensitivity

```js
// HTML: <button id="SubmitBtn">Click</button>
document.getElementById('submit-btn');  // null! IDs are case-sensitive
```

**Why it crashes:** HTML IDs are case-sensitive, so `SubmitBtn` is not the same as `submit-btn`. This matches CSS selector behaviour.

## Scope: `document` vs a child element

```js
// search the whole document
document.querySelector('.item');

// search inside a particular element (narrower scope, faster)
const container = document.getElementById('container');
container.querySelector('.item');      // look only inside container
container.querySelectorAll('.item');   // look only inside container
```

```js
// get direct children
element.children;        // all element children (HTMLCollection)
element.childNodes;     // all child nodes (including text and comment nodes)

// get the parent
element.parentNode;     // the parent node
element.parentElement;  // the parent element (skips non-element nodes)

// get siblings
element.nextElementSibling;
element.previousElementSibling;
```

### Crash Site 3: `children` is a live collection

```js
const container = document.getElementById('list');
const items = container.children;  // HTMLCollection (live!)

console.log(items.length);  // 3

// add a new element
const newItem = document.createElement('li');
container.appendChild(newItem);

console.log(items.length);  // 4! HTMLCollection is live
```

**Why it crashes:** `children` (HTMLCollection) and, in most browsers, `querySelectorAll` (NodeList) are **live** — they update automatically when the DOM changes. That can surprise you inside a loop:

```js
// dangerous: children is live, so the loop skips elements
for (let i = 0; i < container.children.length; i++) {
  container.removeChild(container.children[i]);
  // i=0 removed element 0; the old element 1 is now element 0
  // i=1 removes the current element 1 (the old element 2); element 1 was skipped!
}
```

The fixes: iterate backwards, or copy into a static array first.

```js
// fix 1: iterate backwards
for (let i = container.children.length - 1; i >= 0; i--) {
  container.removeChild(container.children[i]);
}

// fix 2: copy to an array
const items = [...container.children];
items.forEach(item => container.removeChild(item));
```

## Comparison with Python

Python has no DOM querying, but the idea maps neatly:

```python
# if you imagine the DOM as a nested dictionary
dom = {
    "tag": "div",
    "children": [
        {"tag": "h1", "text": "Hello"},
        {"tag": "p", "text": "World"}
    ]
}
# a manual querySelector-like search
def find_by_tag(dom, tag):
    if dom["tag"] == tag:
        return dom
    for child in dom.get("children", []):
        result = find_by_tag(child, tag)
        if result:
            return result
```

JS's `querySelector` does exactly that for you, and it uses CSS selector syntax — far cleaner than hand-rolled recursion.

## Recap

- `getElementById` is fastest, but IDs only.
- `querySelector` returns the first match; `querySelectorAll` returns every match.
- When there is no match, `querySelector` returns `null` and `querySelectorAll` returns an **empty NodeList**.
- NodeList has `forEach` but not `map`/`filter`; convert it to an array first.
- Live collections (HTMLCollection) auto-update when the DOM changes — watch out in loops.
