# The event object: `event.target` vs `event.currentTarget`

> This lesson answers: what is that `event` parameter inside your handler, and what is the difference between `target` and `currentTarget`? These two properties are easy to mix up and are the source of many confusing bugs.

## The event object

Every time an event fires, the browser passes an **event object** to your callback:

```js
element.addEventListener('click', function (event) {
  // event is the event object
});
```

Useful properties:

| Property | Meaning |
|---|---|
| `event.type` | the event type (`'click'`, `'input'`, ...) |
| `event.target` | **the element that actually triggered the event** (the start of the bubble chain) |
| `event.currentTarget` | **the element the listener is attached to** (the element `this` refers to) |
| `event.clientX` / `clientY` | mouse coordinates relative to the viewport |
| `event.key` | the key that was pressed (for `keydown`) |
| `event.preventDefault()` | cancel the browser's default action |
| `event.stopPropagation()` | stop the event from bubbling further |

## `target` vs `currentTarget`

```html
<div id="parent" style="padding: 20px; background: lightblue;">
  <button id="child">Click me</button>
</div>
```

```js
const parent = document.querySelector('#parent');
const child = document.querySelector('#child');

parent.addEventListener('click', function (event) {
  console.log('target:', event.target.id);          // "child" - the element actually clicked
  console.log('currentTarget:', event.currentTarget.id); // "parent" - the element with the listener
});
```

When you click the button:

- `event.target` is the button — the element the user clicked.
- `event.currentTarget` is the div — the element where you attached the listener.

**Mnemonic: `target` is "what got clicked", `currentTarget` is "who is listening".**

### Crash Site 1: reading a child's attribute off `currentTarget`

```js
const list = document.querySelector('#todo-list');

list.addEventListener('click', function (event) {
  // we want the data-id of the <li> that was clicked
  console.log(event.currentTarget.dataset.id);  // undefined! currentTarget is the <ul>
  console.log(event.target.dataset.id);         // "123" - target is the <li>
});
```

**Why it crashes:** `currentTarget` is the element the listener was attached to (the `<ul>`), not the element that was clicked (the `<li>`). To read an attribute of the clicked item, use `target`.

## When are `target` and `currentTarget` the same?

They are the same when the event fires directly on the element that holds the listener:

```js
button.addEventListener('click', function (event) {
  // when the button itself is clicked:
  event.target === event.currentTarget;  // true
  // the button is both the trigger and the listener
});
```

They differ when the event **bubbles up** to an ancestor:

```js
// click the button - the event bubbles up to the div
div.addEventListener('click', function (event) {
  event.target;         // the button - where the bubble started
  event.currentTarget;  // the div - the current handler's element
});
```

## A preview of event delegation

Delegation is covered fully in the next lesson; here is a simple example so the distinction becomes concrete:

```html
<ul id="menu">
  <li data-page="home">Home</li>
  <li data-page="about">About</li>
  <li data-page="contact">Contact</li>
</ul>
```

```js
document.querySelector('#menu').addEventListener('click', function (event) {
  // event.target is the <li> that was clicked
  const page = event.target.dataset.page;
  if (page) {
    navigateTo(page);
  }
});
```

Here you must use `event.target`, because the listener is on the `<ul>` but the user clicks an `<li>`.

### Crash Site 2: `target` can be an inner child element

```html
<button id="myBtn">
  <span class="icon">🖱️</span>
  <span class="text">Click me</span>
</button>
```

```js
document.querySelector('#myBtn').addEventListener('click', function (event) {
  console.log(event.target.id);  // might be "" - if the span was clicked, target is the span!
});
```

**Why it crashes:** when a button contains child elements, `event.target` may be the inner `<span>` rather than the `<button>`. Two reliable fixes: use `event.currentTarget` (which is always the button), or use `closest()` to walk up from the target.

```js
// fix 1: use currentTarget
button.addEventListener('click', function (event) {
  console.log(event.currentTarget.id);  // "myBtn" always
});

// fix 2: use closest to walk up from the target
container.addEventListener('click', function (event) {
  const button = event.target.closest('.btn');
  if (button) {
    // handle the click
  }
});
```

## Other useful event methods

```js
// preventDefault: cancel the browser's default action
form.addEventListener('submit', function (event) {
  event.preventDefault();  // stop the page from reloading
  // handle the submission yourself
});

// stopPropagation: cut the bubble short
child.addEventListener('click', function (event) {
  event.stopPropagation();  // clicking child will not trigger parent's listener
});
```

## Comparison with Python

Python's event handling (for example in Tkinter) has similar ideas but a different API:

```python
# Tkinter: callbacks receive an event, but the structure differs
import tkinter as tk

def on_click(event):
    print(event.x, event.y)  # there is an event object, but it is not the same shape

button.bind("<Button-1>", on_click)
```

JavaScript's `event` object is highly standardised: every event type shares the same core API (`preventDefault`, `stopPropagation`), so the skills transfer from clicks to inputs to submits.

## Recap

- `event.target` is the element that actually triggered the event (the start of the bubble).
- `event.currentTarget` is the element the listener is attached to (the current handler).
- When a child is clicked, a parent's listener sees `target` = the child and `currentTarget` = the parent.
- On a button with inner children, `target` may be a span; use `currentTarget` or `closest()` instead.
- `preventDefault()` cancels the default action; `stopPropagation()` stops the bubble.
