# Common events: `click` / `input` / `submit` / `keydown` and `preventDefault`

> This lesson answers: which events show up most often in real work, how do you use them, and what does `preventDefault` actually do?

## Four events you will use constantly

### 1. `click` — a click

```js
button.addEventListener('click', function () {
  console.log('the button was clicked');
});
```

Use it on buttons, links, cards, list items.

### 2. `input` — the value changed

```js
const input = document.querySelector('#search');

input.addEventListener('input', function (event) {
  console.log('current value:', event.target.value);
});
```

It fires on every keystroke, including delete, paste, and composing CJK text.

Compare this with `change`, which only fires **when focus leaves the field and the value has changed**.

### 3. `submit` — a form is submitted

```js
const form = document.querySelector('#login-form');

form.addEventListener('submit', function (event) {
  event.preventDefault();  // stop the default submission (page reload)
  // handle the form data yourself
  const username = form.elements.username.value;
  const password = form.elements.password.value;
  login(username, password);
});
```

### 4. `keydown` — a key was pressed

```js
document.addEventListener('keydown', function (event) {
  console.log('key pressed:', event.key);
  console.log('code:', event.code);

  if (event.key === 'Enter') {
    console.log('Enter was pressed');
  }

  if (event.ctrlKey && event.key === 's') {
    event.preventDefault();  // stop the browser from showing the save dialog
    console.log('Ctrl+S intercepted');
  }
});
```

## `preventDefault`: cancelling the default action

Every event has a **default browser action**:

| Event | Default action | After `preventDefault` |
|---|---|---|
| `submit` | reload the page, send a GET request | page stays put, JS handles it |
| `click` (on an `<a>`) | follow the `href` | no navigation |
| `keydown` (in an input) | insert the character | nothing is inserted |
| `contextmenu` | show the right-click menu | menu is hidden |
| `wheel` / `touchmove` | scroll the page | no scrolling |

### Crash Site 1: forgetting `preventDefault` on a form

```js
const form = document.querySelector('#my-form');

form.addEventListener('submit', function (event) {
  // event.preventDefault() is missing!
  const data = new FormData(form);
  fetch('/api/submit', { method: 'POST', body: data });
  // the page reloads immediately, the fetch is aborted, the user sees a blank page
});
```

**Why it crashes:** the browser runs its default action — reloading (or navigating) — which kills your JavaScript logic and any in-flight request. The fix is to write `event.preventDefault()` as the very first line of the submit handler.

```js
form.addEventListener('submit', function (event) {
  event.preventDefault();  // step 1: stop the reload

  // step 2: handle it yourself
  const input = form.querySelector('input');
  console.log('user entered:', input.value);
});
```

### Crash Site 2: blocking keys but not paste

```js
const input = document.querySelector('#numeric');

input.addEventListener('keydown', function (event) {
  if (!/[0-9]/.test(event.key)) {
    event.preventDefault();  // blocks non-digit keystrokes
  }
});

// but the user can paste "abc"!
// keydown never sees a paste operation
```

**Why it crashes:** `keydown` only sees the keyboard; pasting (Ctrl+V) fires the `paste` event instead. To fully control the value, either listen for `paste` as well or — most reliably — sanitise inside the `input` event.

```js
// the more robust approach: sanitise on input
input.addEventListener('input', function () {
  this.value = this.value.replace(/[^0-9]/g, '');
});
```

## A live-search example

```html
<input type="text" id="search" placeholder="Search...">
<ul id="results"></ul>
```

```js
const search = document.querySelector('#search');
const results = document.querySelector('#results');

const allItems = ['Apple', 'Banana', 'Orange', 'Watermelon', 'Grape'];

search.addEventListener('input', function () {
  const keyword = this.value.toLowerCase();

  // filter
  const matched = allItems.filter(item =>
    item.toLowerCase().includes(keyword)
  );

  // render
  results.innerHTML = '';
  matched.forEach(item => {
    const li = document.createElement('li');
    li.textContent = item;
    results.appendChild(li);
  });
});
```

## Keyboard-event properties

```js
document.addEventListener('keydown', function (event) {
  event.key;        // "a", "Enter", "ArrowUp", "Escape"
  event.code;       // "KeyA", "Enter", "ArrowUp", "Escape"
  event.ctrlKey;    // is Ctrl held?
  event.shiftKey;   // is Shift held?
  event.altKey;     // is Alt held?
  event.metaKey;    // is Cmd held? (Mac)
});
```

### Crash Site 3: using `keyCode` (deprecated)

```js
document.addEventListener('keydown', function (event) {
  if (event.keyCode === 13) {  // keyCode is deprecated!
    // ...
  }
});
```

**Why it crashes:** `keyCode` was deprecated long ago and browsers differ in their values. Use `event.key`:

```js
document.addEventListener('keydown', function (event) {
  if (event.key === 'Enter') {  // clear and semantic
    // ...
  }
});
```

## Comparison with Python

A Python terminal program has no "event" concept — it runs in order:

```python
# Python: blocking input
while True:
    cmd = input("> ")  # waits for the user, returns after Enter
    if cmd == "quit":
        break
    print(f"running: {cmd}")
```

JavaScript's event model is non-blocking: you register a listener and the code moves on; you have no idea when the callback will run.

```js
input.addEventListener('input', function (e) {
  console.log(e.target.value);  // runs at some unknown time in the future
});
console.log('this line runs first');  // runs immediately
```

## Recap

- `click` for taps and clicks, `input` for live changes, `submit` for forms, `keydown` for keys.
- `preventDefault()` cancels the browser's default action; in form handling it is **required**.
- `input` is better than `keydown` for filtering values because it also catches paste.
- Use `event.key` to identify keys; the old `keyCode` is deprecated.
- `ctrlKey` / `shiftKey` let you detect modifier combinations.
