# `==` vs `===`: the type-coercion trap

> This lesson answers one question: what is the difference between two equals signs and three in JS? `==` performs implicit type conversion and produces some deeply counter-intuitive results. `===` is strict — no conversion, types must match.

## Why are there two equality operators?

Python has a single `==` that compares values for equality. JavaScript has two:

- `==` (loose equality): **converts types first**
- `===` (strict equality): **no conversion**, both type and value must match

```js
'5' == 5      // true — the string becomes a number
'5' === 5     // false — types differ, end of story
0 == false    // true — the boolean becomes 0
0 === false   // false — types differ
```

## How `==` converts

The conversion rules for `==` are sprawling. Here are the cases that matter most:

| Expression | Result | Reason |
|---|---|---|
| `5 == "5"` | `true` | string → number |
| `0 == false` | `true` | `false` → `0` |
| `"" == 0` | `true` | empty string → `0` |
| `null == undefined` | `true` | special language rule |
| `null == 0` | `false` | `null` does not become a number |
| `[] == 0` | `true` | `[]` → `""` → `0` |
| `[1] == 1` | `true` | `[1]` → `"1"` → `1` |

### Crash Site 1: confusing `null` with `undefined`

```js
function greet(user) {
  if (user == null) {  // here null == undefined is also true
    return "Please log in";
  }
  return "Hello, " + user.name;
}
```

**Why it (accidentally) works:** `user == null` is true for both `null` and `undefined`, so this particular comparison happens to be right. But writing `user == false` or `user == 0` drags in completely unrelated truthiness comparisons. The safer habit is to state your intent explicitly — `user === null || user === undefined` — or, if you really mean "nullish", use `user == null` (the one place where `==` is widely accepted as a shorthand).

### Crash Site 2: `""` versus `0`

```js
const input = document.getElementById('age').value;  // inputs always return strings
if (input == 0) {
  console.log("Age is zero");
}
// when the user leaves the field empty, input is "" and "" == 0 is true!
```

**Why it crashes:** the user submits a blank field, your code decides the age is zero, and you print "Age is zero" — clearly wrong. Use `===` and convert explicitly: `if (Number(input) === 0)`.

## Why `===` wins

1. **Predictable:** no surprise results from hidden conversions.
2. **Readable:** the code states exactly what types it is comparing.
3. **Bug-resistant:** the vast majority of `==` uses are bug sources.

**Rule of thumb: always use `===`, never `==`.** Only reach for `==` when you genuinely know what you are doing — for example `x == null` to check for both `null` and `undefined` at once.

## Comparison with Python

Python's `==` behaves the way intuition suggests: it will never call `"5"` and `5` equal. In Python, `"5" == 5` is simply `False`. JavaScript's `==` is a "feature" that is also the single most common source of beginner bugs.

## Recap

- `===` is strict: true only when both type and value match.
- `==` is loose: it converts types first, and the rules are complex and surprising.
- In daily work, use `===`; `==` is acceptable only in a handful of cases such as `x == null`.
- Coercion traps to remember: `"" == 0` and `null == undefined` are both `true`.
