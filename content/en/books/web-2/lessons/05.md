# Arrays and objects: Python's `list` and `dict` compared

> This lesson answers: how do JS arrays and objects work, and how do they differ from Python's lists and dicts? You already know Python's lists and dictionaries; the JS versions are similar, but with some important distinctions.

## JS arrays vs Python lists

```js
// Python: numbers = [1, 2, 3]
const numbers = [1, 2, 3];

numbers.length;      // 3 (a property, not a method)
numbers[0];          // 1 (index access)
numbers[5] = 10;     // out-of-range assignment works! the array grows
numbers.length;      // 6 (with 3 empty slots in between)
```

The key difference: **JS arrays allow out-of-range assignment** and do not throw. The missing positions are `undefined`, but `length` is updated.

```python
# Python: out-of-range assignment raises IndexError
numbers[5] = 10  # IndexError: list assignment index out of range
```

## Destructuring assignment

This is a very common piece of JS syntax sugar; Python 3.10+ has something similar:

```js
// array destructuring
const numbers = [1, 2, 3];
const [first, second, third] = numbers;
console.log(first);   // 1

// skip elements
const [a, , c] = [1, 2, 3];
console.log(c);       // 3

// default values
const [x, y = 10] = [5];
console.log(y);       // 10

// rest elements
const [head, ...tail] = [1, 2, 3, 4];
console.log(tail);    // [2, 3, 4]
```

## JS objects vs Python dicts

```js
// Python: person = {"name": "Alice", "age": 25}
const person = {
  name: "Alice",
  age: 25
};

// dot access
person.name;       // "Alice"

// bracket access (for dynamic keys)
person["name"];    // "Alice"
const key = "age";
person[key];       // 25
```

**The core difference: JS objects can be accessed with dot notation, like named fields.**

## Missing properties return `undefined`, not `KeyError`

This is one of the biggest JS/Python differences:

```js
const person = { name: "Alice" };

// JS: a missing property returns undefined
person.age;        // undefined (no error!)

// Python: a missing key throws
# person["age"]   # KeyError: 'age'
```

### Crash Site 1: forgetting to check whether a property exists

```js
function getCity(user) {
  return user.address.city;  // user.address might be undefined!
}

getCity({ name: "Alice" });  // TypeError: Cannot read properties of undefined
```

**Why it crashes:** in a chained access, if any link in the chain is `undefined` the whole expression throws. Solutions:

```js
// approach 1: check each level
function getCity(user) {
  if (user && user.address && user.address.city) {
    return user.address.city;
  }
  return "unknown";
}

// approach 2: optional chaining (modern)
function getCity(user) {
  return user?.address?.city ?? "unknown";
}
```

## Object destructuring

```js
const person = { name: "Alice", age: 25, city: "London" };

// basic destructuring
const { name, age } = person;
console.log(name);  // "Alice"

// rename
const { name: userName } = person;
console.log(userName);  // "Alice"

// default value
const { country = "UK" } = person;
console.log(country);   // "UK"
```

## Object CRUD

```js
const person = {};

// create
person.name = "Alice";
person["age"] = 25;

// delete
delete person.age;

// update
person.name = "Bob";

// read
"name" in person;      // true (the in operator)
person.hasOwnProperty("name");  // true

// iterate
Object.keys(person);    // ["name"]
Object.values(person);  // ["Alice"]
Object.entries(person); // [["name", "Alice"]]
```

### Crash Site 2: iterating an array with `for...in`

```js
const arr = [10, 20, 30];
for (const i in arr) {
  console.log(i);  // "0", "1", "2" (strings!)
}
```

**Why it crashes:** `for...in` iterates over **enumerable property names** (including those on the prototype chain) and yields string `"0"`, `"1"`, `"2"`, not numeric indices. To iterate an array, use `for...of` or `forEach`.

## Comparison with Python

| Operation | Python | JavaScript |
|---|---|---|
| create | `[1,2,3]` / `{"a":1}` | `[1,2,3]` / `{"a":1}` |
| read | `d["a"]` | `obj.a` or `obj["a"]` |
| missing | `KeyError` | `undefined` |
| destructure | `a, b = [1, 2]` | `const [a, b] = [1, 2]` |
| iterate keys | `for k in d:` | `for (const k in obj)` or `Object.keys()` |
| delete | `del d["a"]` | `delete obj.a` |

## Recap

- JS arrays allow out-of-range assignment and `length` grows to match.
- Destructuring makes multi-value returns and parameter extraction concise.
- JS objects use dot access, which is more convenient than Python dict's brackets.
- A missing object property returns `undefined` rather than throwing — code defensively.
- Optional chaining `?.` and the nullish coalescing operator `??` are the modern tools for nested objects.
- `for...in` iterates property names (including the prototype chain) — not the right way to traverse an array.
