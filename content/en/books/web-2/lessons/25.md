# `setTimeout` and `setInterval`: the asynchronous intuition

> This lesson answers: why does code not run in the order you wrote it? JavaScript schedules callback functions; it does not run them on the spot.

## The asynchronous intuition

```js
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0); // wait 0 milliseconds

console.log('3');
// output order: 1, 3, 2
```

**Even `setTimeout(fn, 0)` does not run immediately.** It moves the callback to the back of the task queue. The current synchronous code finishes first, then the callback runs.

That is the core idea: **a callback is not executed now, even when the delay is zero.**

## `setTimeout`: run once after a delay

```js
setTimeout(() => {
  console.log('Three seconds have passed.');
}, 3000);

setTimeout((name) => {
  console.log(`Hello, ${name}!`);
}, 1000, 'Alice');
```

The first argument is the callback, the second is the delay in milliseconds, and any further arguments are passed to the callback.

### Cancelling a timeout

```js
const timerId = setTimeout(() => {
  console.log('This will not run.');
}, 5000);

clearTimeout(timerId);
console.log('The timeout was cancelled.');
```

`timerId` is the handle you need if you want to cancel. Without it, you cannot stop the callback.

## `setInterval`: repeat until cancelled

```js
let count = 0;
const intervalId = setInterval(() => {
  count++;
  console.log(`Run number ${count}`);

  if (count >= 3) {
    clearInterval(intervalId);
    console.log('Stopped.');
  }
}, 1000);
```

### Crash Site 1: forgetting to clear the interval

```js
setInterval(() => {
  fetch('/api/notifications')
    .then(res => res.json())
    .then(data => updateUI(data));
}, 5000);
```

**Why it crashes:** the interval keeps running after the page or component no longer needs it. It continues to fetch data, update the DOM and consume memory. Always keep the id and clear the timer at the right moment:

```js
const intervalId = setInterval(pollNotifications, 5000);

window.addEventListener('beforeunload', () => {
  clearInterval(intervalId);
});
```

## Why the callback waits

```js
console.log('A');

setTimeout(() => {
  console.log('B');
}, 0);

Promise.resolve().then(() => {
  console.log('C');
});

console.log('D');

// output: A, D, C, B
```

The sequence is:

1. `console.log('A')` runs synchronously.
2. `setTimeout` registers a callback in the macrotask queue.
3. `Promise.resolve().then` registers a callback in the microtask queue.
4. `console.log('D')` runs synchronously.
5. The current task ends, so microtasks run next and print `C`.
6. The next macrotask runs and prints `B`.

### Crash Site 2: treating the delay as exact

```js
console.log('start');

setTimeout(() => {
  console.log('100ms later');
}, 100);

for (let i = 0; i < 1_000_000_000; i++) {} // blocks the main thread

console.log('end');
// "100ms later" appears after "end"
```

**Why it crashes:** the delay is a minimum wait, not a precise alarm. If the main thread is busy, the callback waits until it is free. `setTimeout` is not suitable for exact timing or animation frames.

## Useful patterns

```js
// Debounce a search input
let searchTimer;
input.addEventListener('input', () => {
  clearTimeout(searchTimer);
  searchTimer = setTimeout(() => {
    doSearch(input.value);
  }, 300);
});

// Countdown
let seconds = 60;
const countdown = setInterval(() => {
  seconds--;
  countdownEl.textContent = seconds;
  if (seconds <= 0) {
    clearInterval(countdown);
    countdownEl.textContent = "Time's up!";
  }
}, 1000);

// Poll until ready
const pollTimer = setInterval(async () => {
  const res = await fetch('/api/status');
  const data = await res.json();
  if (data.ready) {
    clearInterval(pollTimer);
    showResult(data);
  }
}, 2000);
```

## Comparison with Python

Python's `time.sleep` blocks the whole thread:

```python
import time

print("Start")
time.sleep(3)
print("Three seconds later")
```

`asyncio.sleep`, by contrast, yields control instead of blocking other coroutines:

```python
import asyncio

async def main():
    print("Start")
    await asyncio.sleep(3)
    print("Three seconds later")

asyncio.run(main())
```

`setTimeout` and `setInterval` are non-blocking. They hand the callback to the event loop and let the main thread keep running, which is a major difference from `time.sleep`.

## Recap

- `setTimeout(fn, delay)` runs once; `setInterval(fn, delay)` repeats.
- The callback does not run instantly, even with a delay of `0`; synchronous code finishes first.
- Keep the timer id to cancel with `clearTimeout` or `clearInterval`.
- An uncleared `setInterval` is a common memory leak.
- The delay is a minimum wait, not an exact time; blocking code delays the callback.
- JavaScript's model is single-threaded with an event loop, so callbacks queue up and wait.
