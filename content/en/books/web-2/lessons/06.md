# Common array methods: `push`/`pop`/`slice`/`splice`

> This lesson answers: what are the common operations on a JS array? You know Python list's `append`, `pop` and slicing; JS has corresponding methods, but with a few key differences.

## Adding and removing elements

```js
const arr = [1, 2, 3];

// add at the end (like Python append)
arr.push(4);        // arr is now [1, 2, 3, 4], returns the new length 4

// remove from the end (like Python pop)
arr.pop();          // returns 4, arr is [1, 2, 3]

// add at the start (Python has no direct equivalent; list.insert(0, x) is slow)
arr.unshift(0);     // arr is [0, 1, 2, 3], returns the new length 4

// remove from the start
arr.shift();        // returns 0, arr is [1, 2, 3]
```

| Operation | Python | JavaScript |
|---|---|---|
| add at end | `append(x)` | `push(x)` |
| remove from end | `pop()` | `pop()` |
| add at start | `insert(0, x)` | `unshift(x)` |
| remove from start | none (use slicing) | `shift()` |

## `slice`: extract a sub-array without touching the original

```js
const arr = [10, 20, 30, 40, 50];

arr.slice(1, 3);    // [20, 30] (the end index is excluded)
arr.slice(2);       // [30, 40, 50] (through to the end)
arr.slice(-2);      // [40, 50] (negative numbers count from the end)
arr.slice();        // [10, 20, 30, 40, 50] (a shallow copy of the whole array)

console.log(arr);   // [10, 20, 30, 40, 50] (unchanged)
```

`slice` **does not modify the original array**; it returns a new one. This matches Python's slicing behaviour.

## `splice`: delete and insert (it mutates!)

`splice` is the most powerful array method in JS — and the easiest to confuse with `slice`:

```js
const arr = [10, 20, 30, 40, 50];

// splice(start, deleteCount, ...itemsToInsert)
arr.splice(1, 2);           // delete 2 elements starting at index 1
console.log(arr);           // [10, 40, 50]

const arr2 = [10, 20, 30];
arr2.splice(1, 0, 99);      // at index 1, delete 0, insert 99
console.log(arr2);          // [10, 99, 20, 30]

const arr3 = [10, 20, 30];
const removed = arr3.splice(0, 1);  // delete and return the removed elements
console.log(removed);       // [10]
```

**The core memory aid: `splice` mutates, `slice` does not.**

### Crash Site 1: expecting `splice` to return a new array

```js
const arr = [1, 2, 3, 4, 5];
const result = arr.splice(1, 3);
console.log(result);  // [2, 3, 4] (the removed elements!)
console.log(arr);     // [1, 5] (the original array was changed!)
```

**Why it crashes:** if you expect `splice` to behave like Python's `list[start:end]` and hand you back "the remaining view", you get the deleted portion instead — exactly the opposite. And the original array is modified. Use `slice` for a non-mutating extract; use `splice` when you want an in-place change.

## Mutating vs non-mutating methods

| Does not mutate (returns a new array) | Mutates (returns the operated value) |
|---|---|
| `slice()` | `splice()` |
| `map()` | `push()` / `pop()` |
| `filter()` | `shift()` / `unshift()` |
| `concat()` | `sort()` |
| `slice()` | `reverse()` |
| the spread operator `...` | `fill()` |

### Crash Site 2: `sort()` sorts in place

```js
const numbers = [3, 1, 4, 1, 5, 9, 2, 6];
const sorted = numbers.sort();  // hoping for a freshly sorted array
console.log(numbers);  // [1, 1, 2, 3, 4, 5, 6, 9] (mutated!)
console.log(sorted);   // [1, 1, 2, 3, 4, 5, 6, 9] (the same reference!)
```

**Why it crashes:** `sort()` sorts in place and returns a reference to the same array. If you need to keep the original, copy first:

```js
const numbers = [3, 1, 4, 1, 5];
const sorted = [...numbers].sort((a, b) => a - b);  // spread, then sort
```

### Crash Site 3: `sort()` compares strings by default

```js
const numbers = [10, 2, 30, 4];
numbers.sort();
// default string comparison: "10" < "2" < "30" < "4"
```

`sort()` with no arguments sorts by Unicode code points:

- `'10'` vs `'2'`: `'1'`(49) < `'2'`(50), so `'10'` comes before `'2'`
- `'2'` vs `'30'`: `'2'`(50) < `'3'`(51), so `'2'` comes before `'30'`
- `'30'` vs `'4'`: `'3'`(51) < `'4'`(52), so `'30'` comes before `'4'`

So `[10, 2, 30, 4].sort()` becomes `[10, 2, 30, 4]`.

```js
// the fix: pass a comparator
numbers.sort((a, b) => a - b);  // [2, 4, 10, 30]
```

## Comparison with Python

```python
# Python slicing does not modify the original list
numbers = [1, 2, 3, 4, 5]
sub = numbers[1:3]   # [2, 3]
# numbers is still [1, 2, 3, 4, 5]

# Python has no direct splice equivalent
# delete: del numbers[1:3]
# insert: numbers[1:1] = [99]
```

```js
// JS slice does not mutate
const numbers = [1, 2, 3, 4, 5];
const sub = numbers.slice(1, 3);  // [2, 3]
// numbers is unchanged

// JS splice mutates
numbers.splice(1, 2);  // numbers becomes [1, 4, 5]
```

## Recap

- `push`/`pop` work on the end, `unshift`/`shift` work on the start.
- `slice(start, end)` does not mutate and returns a new array (like Python slicing).
- `splice(start, count, ...items)` mutates and returns the deleted elements.
- `sort()` sorts in place and compares strings by default; pass a comparator for numbers.
- Remember the rhyme: **slice leaves the original alone, splice changes it.**
