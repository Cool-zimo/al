# Reading form values: inputs, selects, checkboxes and radios

> This lesson answers: how do you get the value the user actually entered or chose? Different controls store their state in different places, and using the wrong property gives you the wrong answer.

## `input.value`: the basic text value

A plain text input keeps the typed text in its `value` property.

```js
const usernameInput = document.querySelector('#username');
console.log(usernameInput.value);
```

**`value` is always a string**, even when the input is `type="number"`.

```js
const ageInput = document.querySelector('#age');
console.log(typeof ageInput.value); // "string"

const age = Number(ageInput.value);
```

So the rule is simple: read `.value`, then convert it when you need a real number.

## `<select>`: read the chosen option, not the whole list

A dropdown has one selected option. Read `select.value` to get its `value` attribute.

```html
<select id="city">
  <option value="lon">London</option>
  <option value="par">Paris</option>
  <option value="ber">Berlin</option>
</select>
```

```js
const citySelect = document.querySelector('#city');
console.log(citySelect.value); // "par" when Paris is selected

const label = citySelect.selectedOptions[0].textContent; // "Paris"
```

### Crash Site 1: `textContent` on a select returns every option

```js
const citySelect = document.querySelector('#city');
console.log(citySelect.textContent);
// "London\n  Paris\n  Berlin"
```

**Why it crashes:** `textContent` returns the combined text of all child nodes, not the current selection. It looks like the right value when there is only one option, then silently misleads you later. Use `select.value` for the stored value and `selectedOptions[0]` when you genuinely need the visible label.

## Checkboxes: use `checked`, not `value`

A checkbox is either on or off, so its state is a boolean stored in `.checked`.

```html
<input type="checkbox" id="agree">
<label for="agree">I agree to the terms</label>
```

```js
const agree = document.querySelector('#agree');

if (agree.checked) {
  console.log('The user agreed.');
}

agree.checked = true;  // tick it
agree.checked = false; // untick it
```

### Crash Site 2: `value` does not change when a checkbox is ticked

```js
const agree = document.querySelector('#agree');
console.log(agree.value); // "on" whether or not it is ticked
```

**Why it crashes:** `value` is the form value submitted with the data; its default is `"on"`. It does not reflect the tick state at all. Treat `.value` as the label submitted when the box is checked, and `.checked` as the yes-or-no answer.

## Radio buttons: find the one that is `:checked`

A radio group shares a `name`. Only one should be selected, so use the `:checked` pseudo-class to locate it.

```html
<input type="radio" name="plan" value="basic" id="basic">
<label for="basic">Basic</label>
<input type="radio" name="plan" value="pro" id="pro">
<label for="pro">Pro</label>
```

```js
const selected = document.querySelector('input[name="plan"]:checked');

if (selected) {
  console.log(selected.value); // "basic" or "pro"
} else {
  console.log('Nothing is selected yet.');
}
```

## A submit handler must prevent the default reload

This is the classic form mistake: the handler runs, but then the browser submits the form and reloads the page.

```html
<form id="signup">
  <input type="text" name="username" placeholder="Username">
  <button type="submit">Create account</button>
</form>
```

```js
document.querySelector('#signup').addEventListener('submit', (event) => {
  event.preventDefault(); // keep the page from reloading

  const form = event.target;
  const username = form.elements.username.value;
  console.log('Submitted:', username);
});
```

### Crash Site 3: forgetting `preventDefault`

```js
document.querySelector('#signup').addEventListener('submit', (event) => {
  const data = { username: event.target.elements.username.value };
  fetch('/api/signup', {
    method: 'POST',
    body: JSON.stringify(data)
  });
  // the page reloads immediately after this line
});
```

**Why it crashes:** without `event.preventDefault()`, the browser performs the form's default action. The page reloads, the fetch may be cancelled, and the user loses any in-page state. Write `preventDefault()` first, then read the values.

## `form.elements` and `FormData` for groups of fields

`form.elements` gives you named access to controls. `FormData` is useful when you want every field at once.

```js
document.querySelector('#signup').addEventListener('submit', (event) => {
  event.preventDefault();

  const form = event.target;
  console.log(form.elements.username.value);

  const formData = new FormData(form);
  console.log(formData.get('username'));

  const data = Object.fromEntries(formData.entries());
  console.log(data); // { username: "alice" }
});
```

A checkbox that is not checked is normally omitted from `FormData`, while a checked one submits its `value`. That is why `.checked` is the reliable boolean test.

## Cheat sheet

| Control | What you want | How to read it |
|---|---|---|
| `<input type="text">` | typed text | `input.value` |
| `<input type="number">` | a number | `Number(input.value)` |
| `<select>` | chosen value | `select.value` |
| `<select>` | chosen label | `select.selectedOptions[0].textContent` |
| `<input type="checkbox">` | yes or no | `checkbox.checked` |
| `<input type="radio">` | chosen value | `document.querySelector('input[name="x"]:checked').value` |
| `<textarea>` | typed text | `textarea.value` |

## Comparison with Python

Python web frameworks usually parse submitted form data for you:

```python
# Django/Flask: request.form already behaves like a dictionary
username = request.form.get('username')
```

In JavaScript you read values directly from the controls, and each control type has its own rule. That is where most beginners go wrong: they assume one property works everywhere.

## Recap

- `input.value` is a string; convert it with `Number()` when you need a number.
- Use `select.value` for the chosen option's value, never `select.textContent`.
- A checkbox's state is `checkbox.checked` (boolean); its `.value` does not change.
- A radio group needs `:checked` to find the selected button.
- Call `event.preventDefault()` inside a submit handler before reading values.
- `FormData` collects named fields, but `checked` remains the best test for a single boolean.

  function getFormData() {
      // return { username, agreed }
  }

  <form id="reg">

    <button type="submit">Sign up</button>
  </form>

- (JSON.stringify(getFormData()) === JSON.stringify({username:"Bob", agreed:true}))
