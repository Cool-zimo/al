# Objects: create, read, update, delete, iterate, and the missing-property trap

> This lesson answers: how do you create, read, update and delete on a JS object, and how do you iterate over one? You already know that JS objects resemble Python dicts, but they have some distinctive usage patterns worth learning.

## Create, read, update, delete

```js
const person = {
  name: "Alice",
  age: 25
};

// create (two ways)
person.city = "London";       // dot notation
person["country"] = "UK";  // bracket notation

// update
person.age = 26;

// read
console.log(person.name);    // "Alice"
console.log(person["age"]);  // 26

// delete
delete person.city;          // true (whether the deletion succeeded)
console.log(person.city);    // undefined
```

Compared with Python:

```python
person = {"name": "Alice", "age": 25}
person["city"] = "London"   # brackets only
del person["city"]
```

## Three ways to iterate an object

### 1. `for...in`

```js
const person = { name: "Alice", age: 25, city: "London" };

for (const key in person) {
  console.log(key, person[key]);
}
// name Alice
// age 25
// city London
```

Note: `for...in` will also visit **enumerable properties on the prototype chain**.

### 2. `Object.keys()` / `Object.values()` / `Object.entries()`

```js
const person = { name: "Alice", age: 25 };

Object.keys(person);    // ["name", "age"]
Object.values(person);  // ["Alice", 25]
Object.entries(person); // [["name", "Alice"], ["age", 25]]

// iterate with for...of
for (const [key, value] of Object.entries(person)) {
  console.log(`${key}: ${value}`);
}
```

### 3. `Object.getOwnPropertyNames()`

```js
const person = { name: "Alice", age: 25 };
Object.getOwnPropertyNames(person);  // ["name", "age"]
```

## A missing property returns `undefined`

This is the most fundamental JS/Python difference:

```js
const person = { name: "Alice" };

person.age;        // undefined (no error!)
person["city"];    // undefined (no error!)
```

In Python, `person["age"]` raises `KeyError`. In JS it returns `undefined`, and **execution continues** — which can be a convenience (no try/except needed) or a curse (the bug is masked).

### Crash Site 1: `undefined` somewhere in a chain

```js
function getDiscount(user) {
  return user.membership.level * 0.1;  // user.membership might be undefined!
}

getDiscount({ name: "Alice" });
// TypeError: Cannot read properties of undefined (reading 'level')
```

**Why it crashes:** the code throws, but the message is not especially clear (reading 'level' does not tell you whether `user` or `membership` was undefined). The fixes:

```js
// approach 1: defensive checks at every level
function getDiscount(user) {
  if (!user || !user.membership) return 0;
  return user.membership.level * 0.1;
}

// approach 2: optional chaining (modern, preferred)
function getDiscount(user) {
  return user?.membership?.level * 0.1 || 0;
}
```

### Crash Site 2: `undefined` leaking into a calculation

```js
const product = { price: 100 };  // forgot to add the quantity property
const total = product.price * product.quantity;  // 100 * undefined = NaN
console.log(total);  // NaN (silent failure!)
```

**Why it crashes:** `undefined` combined with a number yields `NaN`, and every subsequent calculation becomes `NaN` — **without any error**. This is a very sneaky bug. The fix: use a default value with `|| 1` or `?? 1`.

## Testing whether a property exists

```js
const person = { name: "Alice", age: undefined };

"name" in person;            // true (only cares whether the key exists)
person.hasOwnProperty("name"); // true (preferred; skips the prototype chain)

// wrong way
person.name !== undefined;    // false! but the name property genuinely exists
```

### Crash Site 3: using `!== undefined` to test for a property

```js
const config = { timeout: undefined };
if (config.timeout !== undefined) {
  setTimeout(fetchData, config.timeout);
}
// the timeout property exists but its value is undefined, so the test fails
```

**Why it crashes:** when a property's value happens to be `undefined`, a `!== undefined` check falsely concludes that the property is absent. Use `"timeout" in config` or `config.hasOwnProperty("timeout")` instead.

## Other useful object methods

```js
// merge objects
const defaults = { theme: "light", lang: "en" };
const userPrefs = { theme: "dark" };
const merged = { ...defaults, ...userPrefs };
// { theme: "dark", lang: "en" }

// shallow copy
const copy = { ...original };

// freeze (make non-modifiable)
const frozen = Object.freeze({ name: "Alice" });
frozen.name = "Bob";  // fails silently (or throws in strict mode)

// test for a plain object
typeof obj === 'object' && obj !== null && !Array.isArray(obj);
```

## Comparison with Python

| Operation | Python | JavaScript |
|---|---|---|
| test whether a key exists | `"key" in d` / `d.get("key")` | `"key" in obj` / `obj.hasOwnProperty("key")` |
| get all keys | `d.keys()` | `Object.keys(obj)` |
| get all values | `d.values()` | `Object.values(obj)` |
| merge dicts | `{**d1, **d2}` | `{...o1, ...o2}` |
| delete a key | `del d["key"]` | `delete obj.key` |
| default when absent | `d.get("key", default)` | `obj.key ?? default` |

## Recap

- Object CRUD: `obj.key = val`, `delete obj.key`, `obj.key`.
- Iterate with `for...in` or `Object.keys()` / `Object.entries()` combined with `for...of`.
- A missing property returns `undefined` rather than throwing — both a convenience and a hazard.
- Test for property presence with `in` or `hasOwnProperty`, not `!== undefined`.
- Optional chaining `?.` is the modern tool of choice for nested objects.
- Object spread `{...obj}` gives you a shallow copy and a merge.

## In-class exercise

```quiz
type: js
q: Write a function countProperties(obj) that counts the number of an object's own enumerable properties (skipping the prototype chain) and returns that number. Do not simply return Object.keys(obj).length — iterate manually with for...in and hasOwnProperty.
func: countProperties
starter: |
  function countProperties(obj) {
      // iterate with for...in, filter the prototype chain with hasOwnProperty
      let count = 0;
      return count;
  }
cases: |
  {"a": 1, "b": 2, "c": 3} -> 3
  {} -> 0
  {"name": "Alice"} -> 1
  {"x": 1, "y": 2, "z": 3} -> 3
hint: Iterate obj with for...in, test obj.hasOwnProperty(key) for each key, and increment count when true.
explain: for...in walks properties on the prototype chain too, so you must filter with hasOwnProperty to count only the object's own properties. A property whose value happens to be undefined still counts as present.
```

q: To test whether an object has a property (even when its value is undefined), which is the most accurate approach?
options:
- obj.key !== undefined
- "key" in obj
- typeof obj.key !== 'undefined'
- obj.key == null
answer: 1
explain: "key" in obj only tests for the property's presence and ignores its value. By contrast, !== undefined misclassifies a property that exists with value undefined. hasOwnProperty also works but excludes the prototype chain.
