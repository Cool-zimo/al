# Event delegation: one listener to rule them all

> This lesson answers: when a list has hundreds of items and every item needs a click handler, how do you avoid attaching hundreds of listeners? The answer is event delegation — listen on the parent once and let the event bubble do the routing.

## The problem: why delegate?

Imagine a list with 100 items, each of which should respond to a click:

```js
// not recommended: one listener per item
const items = document.querySelectorAll('#list li');
items.forEach(item => {
  item.addEventListener('click', handleClick);
});
// 100 listener instances - memory adds up
```

Three problems:

1. **Memory** — 100 live listener objects.
2. **Dynamic elements** — any `<li>` added later has no listener attached.
3. **Repetition** — the same logic written over and over.

## The solution: event delegation

It relies on **event bubbling** — when you click a child, the event travels up through its ancestors. So a single listener on the parent can handle clicks for every child:

```js
// recommended: one listener on the parent
document.querySelector('#list').addEventListener('click', function (event) {
  // event.target is the child that was clicked
  const li = event.target;
  console.log('clicked:', li.textContent);
});
```

## A complete example

```html
<ul id="todo-list">
  <li data-id="1">Buy milk</li>
  <li data-id="2">Write code</li>
  <li data-id="3">Read a book</li>
</ul>
```

```js
document.querySelector('#todo-list').addEventListener('click', function (event) {
  const li = event.target;
  const id = li.dataset.id;

  console.log(`task ${id} was clicked`);

  // toggle the done state
  li.classList.toggle('done');
});
```

## Dynamic elements respond automatically

This is delegation's biggest win:

```js
const list = document.querySelector('#todo-list');

// attach the listener once, on the parent
list.addEventListener('click', function (event) {
  if (event.target.tagName === 'LI') {
    event.target.classList.toggle('done');
  }
});

// a new item added much later
const newLi = document.createElement('li');
newLi.textContent = 'New task';
newLi.dataset.id = '4';
list.appendChild(newLi);
// it responds to clicks immediately - no extra listener needed
```

### Crash Site 1: `target` may be a child of the `<li>`

```html
<ul id="todo-list">
  <li>
    <span class="task-name">Buy milk</span>
    <button class="delete-btn">Delete</button>
  </li>
</ul>
```

```js
document.querySelector('#todo-list').addEventListener('click', function (event) {
  const li = event.target;  // if the button was clicked, target is the button!
  if (li.tagName === 'LI') {
    li.classList.toggle('done');
  }
  // when delete is clicked, li.tagName is "BUTTON", so toggle never runs
});
```

**Why it crashes:** if an `<li>` contains child elements (`<span>`, `<button>`), `event.target` may be one of those children rather than the `<li>`. Fix: use `closest()` to walk up from the target until you find the matching ancestor.

```js
document.querySelector('#todo-list').addEventListener('click', function (event) {
  const li = event.target.closest('li');  // walk up to the nearest li
  if (li) {
    li.classList.toggle('done');
  }
});
```

### Crash Site 2: a delete click also toggles the `<li>`

```js
// clicking delete still finds an <li> via closest,
// so "delete" and "toggle done" both run at once

document.querySelector('#todo-list').addEventListener('click', function (event) {
  // if the delete button was clicked, do not toggle
  if (event.target.closest('.delete-btn')) {
    deleteItem(event.target.closest('li'));
    return;  // skip the rest
  }

  const li = event.target.closest('li');
  if (li) {
    li.classList.toggle('done');
  }
});
```

**Why it crashes:** events on inner controls still bubble up to the parent's listener, so you must inspect `target` to decide which action the click really represents.

## The delegation pattern, summarised

```js
parent.addEventListener('eventType', function (event) {
  // 1. find the target item by walking up
  const item = event.target.closest('.item-selector');
  if (!item) return;  // the click was not on a target item

  // 2. dispatch based on what was clicked
  if (event.target.closest('.delete-btn')) {
    deleteItem(item);
    return;
  }

  if (event.target.closest('.edit-btn')) {
    editItem(item);
    return;
  }

  // 3. default behaviour
  toggleItem(item);
});
```

## Comparison with Python

Python frameworks have a similar idea, but usually hidden behind the framework:

```python
# analogy: implement delegation by hand on a Tkinter canvas
def on_click(event):
    x, y = event.x, event.y
    for shape in shapes:
        if shape.contains(x, y):
            shape.on_click()
```

JavaScript's bubble mechanism does the "walk up from child to parent" work for you; you only need `closest()` to identify the actual item.

## Recap

- Delegation uses the bubble phase: one listener on a parent manages every child.
- Benefits: less memory, and dynamically added children respond for free.
- `event.target.closest(selector)` is the tool for locating the real target.
- Inspect `target` to decide between actions (delete button vs list item).
- Delegation is the standard pattern for list-style interactions.
