# Adding persistence and filters: reading localStorage and rendering by condition

> This lesson answers: how do you make the data survive a refresh, and how do you show only some of it?

## Persistence: reading and writing localStorage

```js
const STORAGE_KEY = 'todos';

// Read from localStorage
function loadTodos() {
  const raw = localStorage.getItem(STORAGE_KEY);
  if (raw === null) return [];  // first visit, return an empty array
  try {
    return JSON.parse(raw);
  } catch (err) {
    console.error('Failed to parse todos:', err);
    return [];  // corrupted data, start fresh
  }
}

// Save to localStorage
function saveTodos() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(todos));
}

// Initialise
let todos = loadTodos();
let nextId = todos.length > 0
  ? Math.max(...todos.map(t => t.id)) + 1  // greatest existing id, plus one
  : 1;
```

**`nextId` must be restored from the data.** After a refresh it cannot simply start at one again.

### Crash Site 1: nextId restarts at one after a refresh

```js
// Wrong: nextId is reset to 1 on every load.
let nextId = 1;

// Existing todos: [{ id: 1, text: 'Buy milk' }, { id: 2, text: 'Write code' }]
todos.push({ id: nextId++, text: 'Read a book' });  // id is 1 again: collision!
```

Two records now share an id. Toggling one toggles both. The fix is to ask the existing data what the next safe number is:

```js
// Right: recover nextId from the stored data.
let nextId = todos.length > 0
  ? Math.max(...todos.map(t => t.id)) + 1
  : 1;
```

## Adding persistence to create, update, delete

```js
function addTodo() {
  const text = todoInput.value.trim();
  if (text === '') return;

  todos.push({ id: nextId++, text, done: false });
  todoInput.value = '';
  saveTodos();  // persist
  render();
}

function deleteTodo(id) {
  todos = todos.filter(todo => todo.id !== id);
  saveTodos();  // persist
  render();
}

function toggleTodo(id) {
  const todo = todos.find(todo => todo.id === id);
  if (todo) {
    todo.done = !todo.done;
    saveTodos();  // persist
    render();
  }
}
```

**The pattern is fixed: after every data change, `saveTodos()` then `render()`.** If you ever write one without the other, you get either a page that lies or a refresh that erases your work.

## Filtering

```js
let currentFilter = 'all';  // 'all' | 'active' | 'completed'

// Filter button events
document.querySelectorAll('.filter-btn').forEach(btn => {
  btn.addEventListener('click', () => {
    document.querySelectorAll('.filter-btn').forEach(b => b.classList.remove('active'));
    btn.classList.add('active');

    currentFilter = btn.dataset.filter;
    render();  // re-render with the new filter
  });
});

// Updated render: filter first, then render.
function render() {
  todoList.innerHTML = '';

  const filtered = todos.filter(todo => {
    if (currentFilter === 'active') return !todo.done;
    if (currentFilter === 'completed') return todo.done;
    return true;  // 'all'
  });

  filtered.forEach(todo => {
    const li = document.createElement('li');
    li.dataset.id = todo.id;
    li.className = todo.done ? 'done' : '';
    li.innerHTML = `
      <input type="checkbox" ${todo.done ? 'checked' : ''}>
      <span>${escapeHtml(todo.text)}</span>
      <button class="delete-btn">Delete</button>
    `;
    todoList.appendChild(li);
  });

  updateStats();
}
```

### Crash Site 2: deleting from a filtered view using an index

```js
// Wrong: building the DOM from filtered indexes.
function render() {
  todoList.innerHTML = filtered.map((todo, index) => `
    <li data-index="${index}">
      <span>${todo.text}</span>
      <button onclick="deleteTodo(${index})">Delete</button>
    </li>
  `).join('');
}

// Under the "completed" filter, index 0 may be todos[2].
// deleteTodo(0) removes the wrong record.
```

The `filtered` array is a subset. Its indexes do not match the original array, so using them to mutate the original data is a guaranteed off-by-one error. **Always use the id.**

## The complete flow

```
Page loads
   ↓
loadTodos() → read from localStorage
   ↓
render() → draw the list
   ↓
User acts
  ├── Add      → addTodo() → todos.push → saveTodos → render
  ├── Delete   → deleteTodo() → todos.filter → saveTodos → render
  ├── Toggle   → toggleTodo() → flip done → saveTodos → render
  └── Filter   → set currentFilter → render
```

Every path ends in `render()`. That is how you keep the screen honest.

## Comparison with Python

Python persistence is usually a file:

```python
import json

def load_todos():
    try:
        with open('todos.json', 'r') as f:
            return json.load(f)
    except FileNotFoundError:
        return []

def save_todos(todos):
    with open('todos.json', 'w') as f:
        json.dump(todos, f)
```

`localStorage` spares you the file handling and the encoding errors, but it stores strings only, so objects must pass through `JSON.stringify` and `JSON.parse`. It is also capped at roughly 5MB per origin, which makes it unsuitable for large datasets.

## Recap

- Three pieces handle persistence: `loadTodos()`, `saveTodos()`, and a `saveTodos()` call after every change.
- Restoring `nextId` to one plus the greatest existing id prevents collisions after a refresh.
- Filtering is a rendering concern: filter, then render. The original array stays intact.
- Always identify records by id, never by index. Filtered indexes and original indexes diverge.
- The steady rhythm is: change data, save, render.

```quiz
q: Write a function filterAndRender(todos, mode) where todos is an array of `{id, text, done}` objects and mode is `'all'`, `'active'`, or `'completed'`. Return the filtered array. No DOM work, just data.

starter: |
  function filterAndRender(todos, mode) {
      // return the filtered array based on mode
  }
checks:
- JSON.stringify(filterAndRender([{"id":1,"text":"a","done":false},{"id":2,"text":"b","done":true},{"id":3,"text":"c","done":false}], "active")) === JSON.stringify([{"id":1,"text":"a","done":false},{"id":3,"text":"c","done":false}])
- JSON.stringify(filterAndRender([{"id":1,"text":"a","done":false},{"id":2,"text":"b","done":true}], "completed")) === JSON.stringify([{"id":2,"text":"b","done":true}])
- JSON.stringify(filterAndRender([{"id":1,"text":"a","done":false},{"id":2,"text":"b","done":true}], "all")) === JSON.stringify([{"id":1,"text":"a","done":false},{"id":2,"text":"b","done":true}])
hint: mode === 'active' → todos.filter(t => !t.done); mode === 'completed' → todos.filter(t => t.done); otherwise return the lot.
explain: Filtering is a pure function: data plus a condition in, filtered array out. Keeping it free of DOM work separates the data layer from the view layer.
```
