The core technique for review problems is **break it down before you write**: split the requirement into "read → process → output", and use one tool from the earlier lessons for each step.

## Three Things People Get Wrong

### 1. Reversing the order of "reading multiple values" and "converting strings to numbers"

```python
# WRONG: convert first, then split
nums = int(input().split())        # TypeError: int() argument must be a string
```

`split()` returns a **list** (`['3', '5', '7']`), while `int()` only accepts **a single string**. The order must be **split first, then int**:

```python
nums = list(map(int, input().split()))   # [3, 5, 7]
a, b, c = map(int, input().split())     # 3, 5, 7
```

### 2. Concatenating with `+` when the integer was never converted to a string

```python
# WRONG
print("result: " + total)          # TypeError: can only concatenate str to str
```

When `total` is an integer, either use `str(total)` or go straight to an f-string:

```python
print(f"result: {total}")          # auto-converts
print("result: " + str(total))     # manual conversion
```

The most common review problem is "print several numbers on one line, space-separated":

```python
nums = [3, 5, 7]
print(*nums)              # 3 5 7    print separates arguments with spaces automatically
print(" ".join(map(str, nums)))   # 3 5 7    build the string manually
```

The `*` in `print(*nums)` is **unpacking** — it spreads the list into individual arguments for `print`.

### 3. Missing edge cases: empty input, a single element, out of bounds

```python
s = input()               # user presses Enter immediately -> s = ""
print(s[0])               # IndexError: string index out of range
```

Whenever you take the first or last character, or use a slice, ask yourself "what if the string is empty?":

```python
s = input()
if s:                    # an empty string is falsy
    print(s[0])
else:
    print("empty input")
```

Likewise, check the divisor before dividing, and check the range before indexing. **Handle the boundary first, then write the main logic** — that is the most effective habit for writing bug-free code.

## Crash Site: A chain of errors in one review problem

Consider a typical "report card" task: read a student's name and three scores, then print the total, average and grade.

```python
# WRONG: three mistakes stacked on top of each other
name = input()
a, b, c = input().split()          # mistake 1: forgot to convert to int, a/b/c are strings
total = a + b + c                  # mistake 2: string concatenation, not addition
avg = total / 3
print(name + "'s average is " + avg)    # mistake 3: string + float -> TypeError
```

**Fix them one at a time:**

```python
name = input()
a, b, c = map(int, input().split())   # fix 1: split first, then convert
total = a + b + c                      # fix 2: now it is integer addition
avg = round(total / 3, 1)
print(f"{name}'s average is {avg}, total {total}")   # fix 3: f-string converts types
```

Key observation: **these three errors are independent**, yet any one of them crashes the program. So when debugging, **start from the first error and work downwards** — do not try to fix everything at once. Usually the errors surface in this order: first `a+b+c` produces something like `"9095100"`, then `total/3` raises TypeError because strings cannot be divided. Only after the first two are fixed does the third error appear.

## Summary

- Review problems break into "read → process → output"; use the right tool for each
- Multiple inputs: `map(int, input().split())`; multiple outputs: `print(*nums)` or `" ".join(...)`
- For integers inside strings, f-strings are the easiest — no manual `str()` needed
- Edge cases (empty strings, division by zero, out of bounds) come first, then the main logic
- Fix a chain of errors from the first one; do not skip around

## Section Quiz

```quiz
type: choice
exam: true
q: What error does the following code raise?
code: |
  a, b = input().split()
  print(a * b)
  # user input: 3 4
options:
- SyntaxError
- NameError
- TypeError
- It prints 12
answer: 2
explain: input().split() returns ['3','4'], so a='3', b='4'. Strings can only be multiplied by an integer, so '3' * '4' raises TypeError: can't multiply sequence by non-int. If you first write a,b=map(int, input().split()) to convert, the result is 12. This is exactly the "looks right, is actually wrong" bug.
```
