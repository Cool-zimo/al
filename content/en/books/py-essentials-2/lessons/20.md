# File I/O Review

> This lesson does not re-teach concepts. It does three things: **recap the key points in thirty seconds, correct the three most common mistakes, and test whether you really understand it.**
> If anything in the recap looks unfamiliar, go back and read Lesson 20 of the *Learning* book first, then come back and do the exercises.

## 30-Second Recap

```python
# Read
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()     # entire file as one string
    lines = f.readlines()  # list of strings, each with its \n

# Write (w ERASES!)
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("hello\n")     # does NOT auto-add a newline!
    f.write("world\n")
```

| Mode | File exists | File does not exist |
|---|---|---|
| `r` read-only | Opens normally | `FileNotFoundError` |
| `w` write | **Truncates, then writes** | Created |
| `a` append | Writes at the end | Created |

`with` is not just "elegant syntax" — it is essential. It automatically calls `f.close()` when the block ends, even if an exception is raised in between.

## Three Things People Get Wrong

### 1. Mode `w` erases the original file with no warning

```python
# WRONG: intended to "add a line to report.txt," but instead...
f = open("report.txt", "w", encoding="utf-8")
f.write("new content\n")
f.close()
```

If `report.txt` originally held 1,000 lines of data, after this code runs, **all 1,000 lines are gone** and only "new content" remains. The semantics of `w` is "open for writing": as soon as the file exists, it is truncated to zero bytes.

To append at the end, use `a`:

```python
f = open("report.txt", "a", encoding="utf-8")
f.write("one more line\n")   # written at the end; original content preserved
f.close()
```

To "error out if it exists, create only if it does not," use `x` (Python 3): `open("report.txt", "x")` raises `FileExistsError` if the file is already there. The difference between `w` / `a` / `x` is the most dangerous and most-tested part of file operations.

### 2. Forgetting `with`, so the file handle never gets closed

```python
# WRONG
f = open("report.txt", "w", encoding="utf-8")
f.write("hello")
# forgot f.close()
```

Three consequences:
1. The written content **might never actually reach disk**. `write` first goes to a buffer and is only flushed on close; if the process exits abnormally, data is lost.
2. File handles are a limited resource; opening many without closing them will exhaust the pool.
3. While a file is held open (especially on Windows), other programs cannot open it.

`with` calls `close()` automatically **whether an exception is raised or not** when the block ends:

```python
with open("report.txt", "w", encoding="utf-8") as f:
    f.write("hello")      # the instant the indentation ends, f.close() runs
```

By the way: `write` returns the number of characters written, not a boolean indicating success. Do not use it as a condition.

### 3. `write` does not auto-add a newline

```python
# WRONG
with open("names.txt", "w", encoding="utf-8") as f:
    f.write("Alice")
    f.write("Bob")
    f.write("Carol")
```

Reading it back gives:

```
AliceBobCarol
```

Three names crammed onto one line. `print(..., file=f)` auto-adds a newline; `f.write()` does not:

```python
with open("names.txt", "w", encoding="utf-8") as f:
    f.write("Alice\n")
    f.write("Bob\n")
    f.write("Carol\n")
```

Also, `readlines()` returns every line with its trailing `\n` still attached; you usually want to `strip()` before processing: `[line.strip() for line in f.readlines()]`.

## Crash Site: `read` / `readline` / `readlines` share a single file pointer

```python
# WRONG
with open("report.txt", "r", encoding="utf-8") as f:
    first = f.readline()
    rest = f.readlines()
    print(first, rest)
```

When `report.txt` has only one line, the output is:

```
['']
```

`readline()` already consumed the first (and only) line, so the file pointer is at the end and `readlines()` can only return an empty list. These three are not "three separate copies" — they **share one pointer, and reading consumes from it**:

```python
with open("report.txt", "r", encoding="utf-8") as f:
    content = f.read()   # read everything; pointer at the end

print(f.read())          # ""   reads nothing
```

`read()` reads all into a string / `readline()` reads one line / `readlines()` reads all into a list. For line-by-line processing, the cleanest approach is to iterate over the file object directly:

```python
with open("report.txt", "r", encoding="utf-8") as f:
    for line in f:       # reads one line into memory at a time; friendly to large files
        print(line.strip())
```

## Summary

- `r` read-only / `w` write (truncates!) / `a` append; use `x` for "create only if it does not exist"
- Always use `with` — it calls `close()` automatically, even if an exception is raised
- `f.write()` does not auto-add a newline; write `\n` yourself, or use `print(..., file=f)`
- `read` reads all into a string / `readline` reads one line / `readlines` reads all into a list; all three share a file pointer
- For large files, iterate with `for line in f:`
- Always include `encoding="utf-8"` when dealing with non-ASCII text, or Windows's default GBK will raise `UnicodeDecodeError`

q: Which approach guarantees the file is closed even if the program exits abnormally, and is the recommended style?

- "f = open(...); f.write(x); f.close()"
- "using with open(...) as f: block"
- "do not close it; Python handles all files at program exit"
- "f = open(...); try: ... finally: pass"
answer: 1
explain: with calls f.close() automatically when the block exits, whether normally or via an exception. The first option: if write raises, close never runs.
