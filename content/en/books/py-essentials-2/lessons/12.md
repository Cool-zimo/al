# List Operations — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> This lesson corresponds to Lesson 12 of *Essential Python*. If any sentence in the recap looks unfamiliar, go back to Lesson 12 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
a = [3, 1, 2]
a.append(4)     # [3, 1, 2, 4]      add one at the end
a.insert(1, 9)  # [3, 9, 1, 2, 4]   insert at position 1
a.pop()         # returns 4, a becomes [3, 9, 1, 2]
a.remove(9)     # [3, 1, 2]         remove the first element equal to 9
a.sort()        # [1, 2, 3]         sort in place, returns None
sorted(a)       # returns a new list, a is unchanged
a.reverse()     # [3, 2, 1]         reverse in place
a.index(2)      # 1   position of the first occurrence
a.count(2)      # 1   number of occurrences
len(a)          # 3
```

| Mutates in place | Returns a new list | Difference |
|---|---|---|
| `sort()` / `reverse()` | `sorted()` / `reversed()` | the former changes itself and returns `None`; the latter leaves the original alone |

## Three Things People Get Wrong

### 1. `sort()` returns `None`, not the sorted list

```python
# WRONG
a = [3, 1, 2]
b = a.sort()
print(b)        # None
```

`list.sort()` is an **in-place sort**: it sorts `a` directly and then returns `None`. So `b` ends up as `None`, while `a` itself is sorted.

When you want "do not touch the original list, give me a sorted copy", use the built-in `sorted()`:

```python
a = [3, 1, 2]
b = sorted(a)   # b is [1, 2, 3], a is still [3, 1, 2]
```

One extra note: `sorted()` works on any iterable (tuples, strings, sets), while `list.sort()` only exists on lists.

### 2. `pop()` with no argument removes the end; with an argument, a position

```python
a = [10, 20, 30, 40]
a.pop()         # returns 40, a becomes [10, 20, 30]
a.pop(0)        # returns 10, a becomes [20, 30]
```

`pop` is the only method that both **removes and returns**. `remove` only removes and returns nothing. Also, `pop(0)` removes the first element at a cost of O(n) (every element after it must shift left), so if you frequently add or remove at the head, use `collections.deque`.

### 3. `index()` and `remove()` raise errors when they fail

```python
# WRONG
a = [1, 2, 3]
print(a.index(9))
```

```
ValueError: 9 is not in list
```

`a.index(x)` raises `ValueError` when not found, and `a.remove(x)` raises `ValueError` when not found. **Check with `in` first**, or write proper exception handling.

## Crash Site: Removing elements while iterating over a list

This is the bug beginners hit most often and have the hardest time finding.

```python
# WRONG: trying to delete all odd numbers
nums = [1, 2, 3, 4, 5]
for x in nums:
    if x % 2 != 0:
        nums.remove(x)
print(nums)     # [2, 4, 5]   5 is still there!
```

```
# no error, but the result is wrong
# execution trace:
# i=0, x=1, remove 1 -> list becomes [2, 3, 4, 5], next index is 1
# i=1, x=3 (because index 1 is now 3), remove 3 -> list becomes [2, 4, 5], next index is 2
# i=2, x=5 (index 2 is now 5)... wait, index 2 is actually 4?
# index 2 is 4, so it is skipped; the loop ends. 5 was missed.
```

**Modifying a list while iterating over it causes elements to be skipped.** After removing one element, every later element shifts left, but the loop's index advances normally, so "the next one" jumps over an element that should have been checked.

There are several correct approaches:

```python
# approach 1: iterate backwards (shifting only affects parts already checked)
nums = [1, 2, 3, 4, 5]
for i in range(len(nums) - 1, -1, -1):
    if nums[i] % 2 != 0:
        nums.pop(i)
print(nums)     # [2, 4]

# approach 2: list comprehension, the recommended option
nums = [1, 2, 3, 4, 5]
nums = [x for x in nums if x % 2 == 0]
print(nums)     # [2, 4]
```

**Rule of thumb: whenever there is filtering, use a list comprehension** — it is clean and has no index-shift problem.

## Summary

- `sort()` mutates in place and returns `None`; `sorted()` returns a new list and leaves the original alone
- `pop()` removes and returns; `pop(0)` costs O(n)
- `index()` / `remove()` raise `ValueError` when not found; test with `in` first
- **Never remove elements while iterating over a list**; use a comprehension instead
- For filtering data, prefer comprehensions over manual index manipulation

```quiz
  nums = [int(x) for x in input().split()]

  result = None
  print(result)

- assert __out.strip() == "[-1, 1, 2, -2, 3]"
- assert __out.strip() == "[0, -5, 5]"
hints: sorted(nums, key=lambda x: abs(x)) sorts by absolute value; for equal keys you need the key to return a tuple: (abs(x), x).
explain: Multi-key sorting relies on the key returning a tuple. sorted(nums, key=lambda x: (abs(x), x)) means: sort by absolute value first, then by the original value. This is one of the most useful tricks with sort/sorted — just remember the "key returns a tuple" pattern.
```

```quiz
  a = [0, 1, 0, 2, 0]
```

```quiz
type: function
exam: true
q: Write merge_sorted(a, b): both lists are already sorted in ascending order. Return a merged list that is also sorted. Requires O(n+m) time; do not simply concatenate and sort. For example [1, 3, 5] and [2, 4, 6] returns [1, 2, 3, 4, 5, 6].
func: merge_sorted
starter: |
  def merge_sorted(a, b):
      # two pointers: i walks a, j walks b; take the smaller one each time
      result = []
      return result
cases: |
  [1, 3, 5], [2, 4, 6] -> [1, 2, 3, 4, 5, 6]
  [1, 2, 3], [] -> [1, 2, 3]
  [], [1, 2] -> [1, 2]
  [1, 1, 2], [1, 2, 3] -> [1, 1, 1, 2, 2, 3]
hints: Use two indices i and j; each time compare a[i] and b[j], append the smaller to result and advance. Once either pointer is exhausted, extend with the remaining elements of the other list.
explain: This is the core step of merge sort and a classic list operation. Two pointers each walk one pass, doing only constant-time comparisons and appends, for a total of n+m steps. Concatenating then sorting costs O((n+m)log(n+m)), which does not meet the requirement.
```
