# Tuples & Dictionaries — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> This lesson corresponds to Lesson 13 of *Essential Python*. If any sentence in the recap looks unfamiliar, go back to Lesson 13 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
t = (1, 2, 3)       # tuple, uses parentheses, immutable
print(t[0])         # 1         can read
t[0] = 10           # TypeError cannot assign

d = {"London": 2184, "New York": 2487, "Paris": 1881}   # dict
d["London"]           # 2184      read
d["Tokyo"] = 1766     # add/modify
del d["Paris"]       # delete
"New York" in d      # True      test whether a key exists
```

| | tuple | dict |
|---|---|---|
| mutable? | immutable | mutable |
| access | by index `t[0]` | by key `d[k]` |
| common use | pack multiple values, serve as dict keys | key-value mapping |

## Three Things People Get Wrong

### 1. A single-element tuple needs a trailing comma

```python
a = (42)
print(type(a))      # <class 'int'>    this is not a tuple

b = (42,)
print(type(b))      # <class 'tuple'>   this is a tuple

c = 42,             # parentheses optional; the comma is what matters
print(type(c))      # <class 'tuple'>
```

Parentheses are just for grouping; the comma is the actual tuple marker. This trap is especially sneaky with function return values — `return 1, 2` returns the tuple `(1, 2)`.

### 2. "Immutable" tuple does not mean "nothing inside can change"

```python
t = (1, [2, 3])
t[1].append(4)      # allowed
print(t)            # (1, [2, 3, 4])
```

```
# the error appears at this step instead:
t[1] = [2, 3, 4]    # TypeError: 'tuple' object does not support item assignment
```

A tuple's immutability means **the references it holds cannot be replaced**. But if the object being referenced is mutable (a list, a dict), its contents can still change. So the precise wording is: **a tuple guarantees "structure stays fixed", not "data never changes".**

### 3. Dictionary keys must be hashable — lists cannot be keys

```python
# WRONG
d = {[1, 2]: "value"}
```

```
TypeError: unhashable type: 'list'
```

Lists are mutable, and mutable objects are not hashable, so **they cannot be dictionary keys**. Common valid keys: `int`, `float`, `str`, `bool`, tuples (as long as every element inside is also immutable).

```python
d = {(1, 2): "London"}    # fine, tuples are hashable
print(d[(1, 2)])       # London
```

When should you use a tuple? — **when the data should never change**. Returning multiple values from a function, a coordinate point `(x, y)`, or a composite dictionary key are all classic tuple use cases.

## Crash Site: Reading a key that does not exist

```python
# WRONG
scores = {"Alice": 95, "Bob": 88}
print(scores["Carol"])
```

```
KeyError: 'Carol'
```

Reading `d[k]` with a non-existent key makes Python raise `KeyError` and halts the program on the spot.

There are three safe ways to read:

```python
# approach 1: test with in first
if "Carol" in scores:
    print(scores["Carol"])

# approach 2: get with a default, the most common
print(scores.get("Carol", 0))    # 0    key missing -> return 0, no error

# approach 3: setdefault, set it in the dict if missing, then return it
scores.setdefault("Carol", 0)    # also writes "Carol": 0 into the dict
```

**Build the habit: when you are unsure whether a key exists, use `get()`.** It combines "read + default handling" into one step, and is the safest common pattern for dictionaries.

## Summary

- A single-element tuple must be written `(42,)`; the comma is the tuple marker
- A tuple's structure is immutable, but mutable objects it contains can still change
- Dictionary keys must be hashable: **lists cannot be keys, but tuples can**
- Use `get(k, default)` for uncertain keys to avoid `KeyError`
- Use tuples for data that should not change; use dicts for lookup by key
