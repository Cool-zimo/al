# Variables & Types — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 2 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
name = "Alice"     # str (string)
age = 18           # int (integer)
height = 1.75      # float (floating-point)
is_student = True  # bool (boolean)
```

| Type | Examples | Check with `type()` |
|---|---|---|
| `int` | `18`, `-3`, `0` | `<class 'int'>` |
| `float` | `1.75`, `3.0`, `-0.5` | `<class 'float'>` |
| `str` | `"abc"`, `"18"` | `<class 'str'>` |
| `bool` | `True`, `False` | `<class 'bool'>` |

A variable is just **a label attached to a value**. Once the label is attached, you can find the value by using the label.

```python
a = 10
b = a          # b gets the value 10 that a currently points to
a = 20         # changing a does not affect b
print(a, b)    # 20 10
```

Remember this rule: **`=` puts the value on the right into the label on the left; it does not mean "the two sides are equal forever."**

## Three Things People Get Wrong

### 1. Treating `=` as a mathematical equals sign

```python
# WRONG: trying to say "x equals x + 1"
x = 5
x = x + 1      # mathematically nonsense, but perfectly legal in programming
print(x)       # 6
```

The execution order of `x = x + 1` is: **first evaluate the right-hand side `x + 1` (at that moment x is 5, giving 6), then put 6 into x**. So it is not an "equation" — it is an overwrite.

To test equality, use `==` (two equals signs):

```python
x = 5
print(x == 5)   # True   —— this is a "test"
print(x = 5)    # SyntaxError —— this is "assignment", which cannot go inside print
```

### 2. Forgetting that `input()` always returns a string

This is the single most common wall beginners hit. No contest.

```python
# WRONG
age = input("Enter your age: ")   # user types 18
if age > 18:                      # TypeError: '>' not supported between 'str' and 'int'
    print("adult")
```

`input()` **always returns a string**, even when you type a number. `"18" > 18` tries to compare a string with a number, and Python refuses outright.

The correct version:

```python
age = int(input("Enter your age: "))   # convert to an integer
if age > 18:
    print("adult")
```

Similarly, use `float()` when you want decimals. To turn a number into a string, use `str()`:

```python
print("I am " + str(18) + " years old")   # I am 18 years old
print("I am " + 18)                       # TypeError: can only concatenate str
```

### 3. `+` means two different things for numbers and strings

```python
print(1 + 2)        # 3      addition
print("1" + "2")    # 12     concatenation
print(1 + "2")      # TypeError: unsupported operand type(s)
```

When you see `TypeError: unsupported operand type(s)`, your first thought should be: **the two sides have different types**. Check with `type()`:

```python
x = "2"
print(type(x))      # <class 'str'>   —— sure enough, it is a string
```

## Crash Site: Strings Are Immutable

```python
# WRONG
s = "hello"
s[0] = "H"
```

```
TypeError: 'str' object does not support item assignment
```

Once a string is created, **you cannot change a character at a given position**. To change it, you must build a new one:

```python
s = "hello"
s = "H" + s[1:]     # build a new one with slicing
print(s)            # Hello
```

Note that `s = ...` here does **not** "modify the original string" — it makes the label `s` point at a brand new string. The original `"hello"` still sits in memory waiting to be cleaned up.

Lists are different. Lists **can** be changed:

```python
lst = ["h", "e", "l", "l", "o"]
lst[0] = "H"        # allowed
print(lst)          # ['H', 'e', 'l', 'l', 'o']
```

This distinction (strings immutable vs. lists mutable) comes up again and again later.

## Summary

- `=` is assignment (overwrite); `==` is a test (equality)
- `input()` always returns a string; use `int()` / `float()` for numbers
- `+` adds numbers but concatenates strings; mixing them raises `TypeError`
- Strings are immutable; to change a character, build a new string
- When `TypeError` appears, check the `type()` of both sides

  # input() gives a string, so remember to convert

  5

hints: Convert with int(input()) before you can add. Then just print(n + 100).

## Section Quiz

```quiz
type: choice
exam: true
q: After running the following code, what are a and b?
code: |
  a = 10
  b = a
  a = 20
options:
- a is 20, b is 20
- a is 20, b is 10
- a is 10, b is 20
- It raises an error
answer: 1
explain: When b = a runs, a is 10, so b gets the value 10 — it is not "tied to a". After that, changing a to 20 has nothing to do with b. Assignment between variables means "copy the value", not "build a connection".
```

```quiz
type: function
exam: true
q: Write describe(name, age, city): combine the name, age and city into one sentence and return it, formatted as "name is age years old, living in city". Note that age may be an integer, so convert it to a string before concatenating.
func: describe
starter: |
  def describe(name, age, city):
      # use str() to turn age into a string, then concatenate
      return ""
cases: |
  ("Alice", 18, "London") -> "Alice is 18 years old, living in London"
  ("Bob", 7, "New York") -> "Bob is 7 years old, living in New York"
  ("Carol", 60, "Paris") -> "Carol is 60 years old, living in Paris"
hints: An f-string is the easiest route: f"{name} is {age} years old, living in {city}". f-strings auto-convert integers to strings, no manual str() needed.
explain: An f-string calls str() automatically while formatting, so it is safer and shorter than manual str(age). That is why f-strings are recommended over + concatenation — with the latter you have to make sure every piece is already a string.
```
