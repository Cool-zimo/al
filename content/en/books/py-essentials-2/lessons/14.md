# Dictionaries Advanced — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> This lesson corresponds to Lesson 14 of *Essential Python*. If any sentence in the recap looks unfamiliar, go back to Lesson 14 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
d = {"London": 2184, "New York": 2487}

# read with a default
d.get("Paris", 0)      # 0   key missing, return 0

# three ways to iterate
for k in d:               # iterate keys (most common)
    pass
for v in d.values():       # iterate values
    pass
for k, v in d.items():    # iterate key-value pairs
    pass

# dict comprehension
squares = {x: x*x for x in range(5)}   # {0:0, 1:1, 2:4, 3:9, 4:16}
```

| Method | Returns |
|---|---|
| `d.keys()` | a view of all keys |
| `d.values()` | a view of all values |
| `d.items()` | a view of all key-value pairs |

**"Dictionaries are unordered" has been outdated since Python 3.7** — from 3.7 onwards, dictionaries **preserve insertion order**, so you can iterate in order with confidence.

## Three Things People Get Wrong

### 1. `get()`'s default only applies when the key is absent

```python
d = {"London": 2184, "New York": 0}
print(d.get("New York", 999))    # 0    the value is 0, not "absent"
print(d.get("Paris", 999))      # 999  the key really is missing
```

`get(key, default)` tests **whether the key exists**, regardless of the value stored there. So do not expect `get` to distinguish between "key absent" and "value is 0 / empty string / None". If you really need to tell the difference, use `in`:

```python
if "New York" in d:
    # the key exists, even if its value is 0, None, or anything else
    pass
```

### 2. Iterating with `items()` does not let you delete keys freely either

```python
# WRONG
d = {"London": 2184, "New York": 2487, "Paris": 1881}
for k in d:
    if d[k] < 2000:
        del d[k]     # RuntimeError: dictionary changed size during iteration
```

Changing size while iterating raises `RuntimeError` immediately. To filter a dictionary, use a dict comprehension:

```python
d = {"London": 2184, "New York": 2487, "Paris": 1881}
d = {k: v for k, v in d.items() if v >= 2000}
print(d)    # {'London': 2184, 'New York': 2487}
```

**Same logic as lists: filter with a comprehension.**

### 3. Nested dict reads need null checks at every layer

```python
db = {
    "Alice": {"math": 90, "english": 95},
    "Bob": {"math": 88}
}

# WRONG: trying to read Bob's english score
print(db["Bob"]["english"])     # KeyError: 'english'
```

```python
# correct: get at each layer
print(db.get("Bob", {}).get("english", 0))   # 0
```

Chained `get` is the safe idiom for reading nested dicts: the outer `get("Bob", {})` ensures that even when "Bob" is absent, an empty dict is returned, so the next `.get("english", 0)` cannot crash.

## Crash Site: Forgetting the "default" step when counting

Beginners often write counting code like this:

```python
# WRONG: reading directly, KeyError on a missing key
words = ["apple", "banana", "apple", "orange", "banana", "apple"]
count = {}
for w in words:
    count[w] = count[w] + 1      # KeyError: 'apple'
```

```
KeyError: 'apple'
```

The very first time "apple" appears it is not yet in the dict, so `count[w]` blows up.

There are three fixes, and you should know them all:

```python
words = ["apple", "banana", "apple", "orange", "banana", "apple"]

# approach 1: test with in
count = {}
for w in words:
    if w in count:
        count[w] += 1
    else:
        count[w] = 1

# approach 2: get with a default
count = {}
for w in words:
    count[w] = count.get(w, 0) + 1

# approach 3: collections.Counter, the professional choice
from collections import Counter
count = Counter(words)
print(count)        # Counter({'apple': 3, 'banana': 2, 'orange': 1})
print(count["pear"])  # 0   Counter returns 0 for missing keys, no error
```

**In real projects, reach for `Counter` directly** — it is built precisely for counting. Its `most_common(n)` also gives you the top n items immediately.

## Summary

- `get(k, default)` only checks whether the key exists; it does not care if the value is 0
- Do not delete keys while iterating a dict; filter with a dict comprehension
- For nested dicts, use chained `get(a, {}).get(b, 0)` for safe reads
- For counting, prefer `collections.Counter`
- Dict comprehension: `{k: v for k, v in ... if ...}`

## Section Quiz

```quiz
type: choice
exam: true
q: Which snippet correctly counts how many times each element appears in a list?
code: |
  items = ["a", "b", "a", "c", "b", "a"]
options:
- "count = {}\nfor x in items:\n    count[x] = count[x] + 1"
- "count = {}\nfor x in items:\n    count[x] = count.get(x, 0) + 1"
- "count = {}\nfor x in items:\n    count.setdefault(x, 0)\n    count[x] += 1"
- "count = {}\nfor x in items:\n    count[x] = 1"
answer: 1
explain: Only B is fully correct. A raises KeyError the first time x is missing; B uses get with default 0, which is correct; C looks wrong but setdefault actually does set the value, so it works — though B is cleaner; D overwrites repeated values back to 1. B is the standard answer here.
```
