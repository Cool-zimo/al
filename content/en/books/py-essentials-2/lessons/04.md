# Reading Error Messages — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 5 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
# intentionally write code that raises an error
def greet(name):
    print("Hello " + nam)   # missed the letter e

greet("Alice")
```

When run, Python prints a long block of red text — that is the **Traceback**. Read it **from bottom to top**:

```
Traceback (most recent call last):
  File "<stdin>", line 5, in <module>
    greet("Alice")
  File "<stdin>", line 2, in greet
    print("Hello " + nam)
NameError: name 'nam' is not defined
```

| Where to look | What you get |
|---|---|
| **The very last line** | error type + a one-line reason (`NameError: name 'nam' is not defined`) |
| **The arrow in the middle** | the exact line that broke |
| **Above that** | who called here (the call stack) |

**That last line is the whole answer**: the error type tells you "what kind of mistake", and the quoted text tells you "where it went wrong".

## Three Things People Get Wrong

### 1. Panicking at red text — the last line is all that matters

Beginners often just stare at a full screen of red. In reality you only need to read two places:

```python
# Example 1: SyntaxError
 if x = 3:
     print(x)
```

```
  File "<stdin>", line 1
    if x = 3:
       ^^^^
SyntaxError: cannot assign to expression here
```

`SyntaxError` is a **syntax error** — the code never even passes the "compile" stage, and not a single line has run. The arrow `^^^^` points straight at `x = 3` and says "assignment does not belong here". Common causes: `=` written instead of `==`, a missing colon, a missing quote.

### 2. `NameError` and `TypeError` both involve "names", but mean completely different things

```python
# NameError: this name simply does not exist
print(nam)                  # NameError: name 'nam' is not defined

# TypeError: the name exists, but it is being used wrong
print("3" + 3)              # TypeError: can only concatenate str to str
```

`NameError` says "I cannot find this variable" — nine times out of ten you **misspelled it** or **never defined it**. `TypeError` says "the variable is there, but this usage is wrong" — usually a **type mismatch**, such as adding a string and a number, or calling a function with the wrong number of arguments.

```python
len(123)                    # TypeError: object of type 'int' has no len()
```

### 3. `IndexError` and `ValueError` — one is out of bounds, the other is bad content

```python
s = "abc"
s[5]            # IndexError: string index out of range —— the index is out of range

int("abc")      # ValueError: invalid literal for int() with base 10: 'abc'
```

`IndexError` means "you accessed a position that does not exist". `ValueError` means "this value itself cannot be used the way you asked" — `int()` can convert `"123"`, but not `"abc"`, even though `"abc"` is a perfectly valid string.

A quick reference for all four:

| Error | Meaning | Typical scenario |
|---|---|---|
| `SyntaxError` | bad syntax, code never ran | missing colon, missing quote, `=` used as `==` |
| `NameError` | using an undefined or misspelled name | wrote `nam` instead of `name` |
| `TypeError` | wrong type usage | `"3" + 3`, wrong number of arguments |
| `IndexError` | index out of bounds | `s[100]`, `lst[-5]` when there are only 3 |
| `ValueError` | value content is invalid | `int("abc")`, `float("twelve")` |

## Crash Site: The line number in a Traceback is not the line you think

```python
# WRONG: staring at the first error line, assuming the problem is in the definition
def get_first(s):
    return s[10]          # you thought the bug was here

name = "Alice"
print(get_first(name))
```

```
Traceback (most recent call last):
  File "demo.py", line 6, in <module>
    print(get_first(name))
  File "demo.py", line 2, in get_first
    return s[10]
IndexError: string index out of range
```

Many people see "line 6" and go back to edit the `print` line. In fact **the arrow and the error type are the real guides**: the arrow points at `return s[10]`, and the error is `IndexError`. The problem is not that `print` called it wrong — `"Alice"` is only 5 characters long, so `s[10]` is out of bounds.

The correct order is: **first read the bottom line (error type and reason) → then the line the arrow points at → only then look at the call stack above**. When the error is inside a function, the call stack tells you "who passed in a weird value", and that is when you need to look upward.

By the way, **`SyntaxError` is the only one with no Traceback**: it is caught during the syntax-check phase, before execution has even started, so there is no call stack to speak of.

## Summary

- Read errors **bottom to top**; the last line = error type + reason
- The arrow `^^^^` points at the line that actually broke
- `SyntaxError` is special: no Traceback, the arrow points straight at the syntax error
- `NameError` = "no such variable"; `TypeError` = "wrong type"; `IndexError` = "out of bounds"; `ValueError` = "invalid value"
- Match the five error types to their jobs and you can fix bugs in seconds

## In-Class Practice

```quiz
type: code
q: Read a string and an integer index, then print the character at that index. If the index is out of bounds, print "out of range". The system will feed in "python" and "8".
starter: |
  s = input()
  i = int(input())
  # use len(s) to decide whether the index is valid
  print("TODO: replace this line with your output")
stdin: |
  python
  8
tests:
- assert "out of range" in __out
hints: Valid indices run from 0 to len(s)-1. Use if i < len(s); otherwise print "out of range".
explain: This practises defensive "bounds checking". At its core, IndexError means the index falls outside [0, len(s)-1], so testing first prevents it. Using len() instead of hard-coding 5 keeps the code correct for both longer and shorter strings.
```

## Section Quiz

```quiz
type: choice
exam: true
q: What error does the following code raise?
code: |
  x = "123"
  y = x + 4
  print(y)
options:
- SyntaxError
- NameError
- TypeError
- ValueError
answer: 2
explain: x is the string "123", and 4 is an integer. Python will not add a string and an integer, raising TypeError: can only concatenate str to str. Note that this is not ValueError: ValueError means "the content of a value cannot be converted" (e.g. int("abc")); here the issue is "these two types cannot be combined this way".
```

```quiz
type: function
exam: true
q: Write safe_divide(a, b): return the result of a / b (rounded to two decimal places using round). If b is 0, return the string "division by zero". Note: 0 cannot be a divisor and will trigger ZeroDivisionError.
func: safe_divide
starter: |
  def safe_divide(a, b):
      # check whether b is 0 first; otherwise divide and round(..., 2)
      return 0
cases: |
  (10, 3) -> 3.33
  (7, 2) -> 3.5
  (5, 0) -> "division by zero"
hints: Use if b == 0 as the early check; otherwise return round(a / b, 2). Remember that the second argument to round is the number of decimal places.
explain: This is basic "defensive programming": reject the illegal case first, then handle the normal logic. ZeroDivisionError is a runtime exception, not caught during syntax checking, so you must anticipate it with if. Without the check, b=0 raises an exception instead of returning the prompt string.
```
