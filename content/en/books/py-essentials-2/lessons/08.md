# while — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 8 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
i = 1
while i <= 5:          # repeat as long as the condition is true
    print(i)
    i = i + 1          # do not forget the update, or you get an infinite loop
```

A `while` loop has three parts, and **missing any one of them causes trouble**:

1. **Initial value**: where the loop variable starts (above, `i = 1`)
2. **Loop condition**: when to keep going (above, `i <= 5`)
3. **Update statement**: how to advance on each pass (above, `i = i + 1`)

The common pattern `while True:` with `break` — the condition lives inside the body and triggers an exit:

```python
while True:
    s = input("enter a number (q to quit): ")
    if s == "q":
        break              # leave the whole loop
    print("you entered", s)
```

## Three Things People Get Wrong

### 1. Infinite loop: forgetting the update statement

```python
# WRONG: the classic infinite loop
i = 1
while i <= 5:
    print(i)
    # i = i + 1 was forgotten
```

The program will **keep printing 1** until you interrupt it manually. Because `i` stays 1 forever, the condition `i <= 5` is always true.

Fix: **advance the loop variable** inside the body.

```python
i = 1
while i <= 5:
    print(i)
    i = i + 1         # add 1 each pass; after 5 passes the condition fails and we exit
```

Build the habit: **write the update first, then fill in the loop body**. Make sure it cannot loop forever before you add logic.

### 2. Updating in the wrong direction — the condition stays true forever

```python
# WRONG: the condition says "less than", but the update says "minus"
i = 1
while i < 10:
    print(i)
    i = i - 1          # gets smaller and smaller: 1, 0, -1, -2... always < 10
```

Or **updating the wrong variable**:

```python
# WRONG
i = 1
while i <= 5:
    print(i)
    n = i + 1          # changing n, while i sits completely still
```

To decide whether a loop terminates, ask one question: **is the loop variable moving in the direction that makes the condition false?** If not, you have an infinite loop.

### 3. Putting `=` inside the condition

```python
# WRONG
while x = 5:           # SyntaxError: invalid syntax
    print(x)
```

The condition can only use `==` for comparison; it cannot use `=` for assignment. Python blocks this with `SyntaxError` on the spot.

```python
x = 5
while x == 5:          # syntactically valid, but an infinite loop if x never changes
    print(x)
    x = 0              # you must give the condition a chance to become false
```

One more: do not write `while True:` and then **forget the `break`** — that is also an infinite loop.

## Crash Site: Three infinite loops stacked together

```python
# WRONG: three fatal problems
count = 0
while count < 3:
    print("count =", count)
    answer = input("continue? ")
    if answer == "n":
        break
    # count += 1 was forgotten  <- death 1: no progress made
```

If the user never enters `n`, the loop spins forever. Fix:

```python
count = 0
while count < 3:
    print("count =", count)
    answer = input("continue? ")
    if answer == "n":
        break
    count += 1          # fix: advance in every case
```

Now the second kind of death — **the condition variable and the input variable are two separate systems**:

```python
# WRONG: expecting user input to control the loop, but reading into the wrong variable
data = ""
while data != "quit":      # the condition watches data
    s = input("enter: ")    # but the input goes into s, so data stays ""
    print(s)
```

`data` is never updated, so the condition is always true. Fix: store the input in the variable the condition actually checks.

```python
data = ""
while data != "quit":
    data = input("enter (quit to exit): ")   # store into data
    if data != "quit":
        print(data)
```

The third kind of death is a `break` placed inside a **branch that is never entered**:

```python
# WRONG
while True:
    n = int(input())
    if n > 0:             # user enters 0 or a negative number -> this branch is skipped, break never reached
        print(n)
        break
```

All three deaths share the same root cause: **no path leads to termination**. When writing `while`, make sure both the "normal path" and the "error path" can reach an exit.

## Summary

- `while` has three parts: initial value, loop condition, update statement — omit one and things break
- Three causes of infinite loops: forgotten update, update in the wrong direction, updating the wrong variable
- Use `==` in the condition, never `=` (that raises `SyntaxError`)
- `while True:` must be paired with `break`, and `break` must sit on every reachable path
- Anti-infinite-loop habit: write the update first, then fill the body

## In-Class Practice

```quiz
type: code
q: Using a while loop, count from 1 to 5, printing one number per line. No input required.
starter: |
  # three parts: initial value i = 1, condition i <= 5, update i += 1
  print("TODO: replace this line with your output")
tests:
- assert __out.strip() == "1\n2\n3\n4\n5"
hints: Start i at 1, print i inside while i <= 5, then i += 1. Do not write while i < 5 — that stops at 4.
explain: This is the standard while pattern. Counter-example 1: omitting i += 1 gives an infinite loop, printing 1 forever. Counter-example 2: the condition while i < 5 only prints 1-4, missing 5. Counter-example 3: updating with i -= 1 makes i shrink forever, so the condition stays true and loops infinitely.
```

## Section Quiz

```quiz
type: choice
exam: true
q: What happens with the following code?
code: |
  i = 10
  while i > 0:
      print(i)
      i = i + 2
options:
- prints the even numbers 10 down to 2 and stops
- keeps printing 10, 12, 14... and never stops
- prints nothing
- raises SyntaxError
answer: 1
explain: i starts at 10 and grows by 2 each pass, so it only gets larger; the condition i > 0 is always true — infinite loop. This is the textbook "update in the wrong direction": if you meant a countdown, it should be i -= 1; if you meant even numbers, the condition needs an upper bound.
```
