# Comprehensions and Built-ins Review

> This lesson does not re-teach concepts. It does three things: **recap the key points in thirty seconds, correct the three most common mistakes, and test whether you really understand it.**
> If anything in the recap looks unfamiliar, go back and read Lesson 23 of the *Learning* book first, then come back and do the exercises.

## 30-Second Recap

```python
# List comprehension
squares = [x**2 for x in range(10)]            # [0, 1, 4, ..., 81]
evens = [x for x in range(20) if x % 2 == 0]   # with a condition

# Dict / set comprehension
d = {x: x**2 for x in range(5)}                # {0:0, 1:1, 2:4, 3:9, 4:16}
s = {len(w) for w in ["a", "bb", "ccc"]}       # {1, 2, 3}  auto-deduplicates

# Built-in functions
sorted([3, 1, 2], reverse=True)                # [3, 2, 1]
sorted(people, key=lambda p: p["age"])         # sort by age
zip([1, 2], ["a", "b"])                        # pair items up
any([False, True, False])                      # True
all([1, 2, 3])                                 # True -- every element is truthy
sum([1, 2, 3])                                 # 6
```

A comprehension is "**a for loop written as a single expression.**" The `key` argument accepts a function and tells sort / max "what to compare by."

## Three Things People Get Wrong

### 1. Nesting a comprehension three layers deep becomes unreadable

```python
# WRONG
matrix = [[[x * y * z for x in range(3)] for y in range(3)] for z in range(3)]
```

This runs, but nobody can read it. **A comprehension inside a comprehension** causes readability to collapse — execution order is "outside in," but reading order is the opposite of intuition.

**Once a comprehension goes beyond two levels, rewrite it as a plain for loop:**

```python
result = []
for z in range(3):
    layer = []
    for y in range(3):
        row = [x * y * z for x in range(3)]   # only the innermost stays a comprehension
        layer.append(row)
    result.append(layer)
```

The rule is simple: **if you can understand what it does in one second, keep the comprehension; if you cannot, break it up.** This is exactly the kind of trade-off the Zen of Python means by "Readability counts."

### 2. `sorted()` does not change the original list; `list.sort()` does

```python
nums = [3, 1, 2]
sorted(nums)          # returns a new list [1, 2, 3]
print(nums)           # [3, 1, 2]   -- original untouched!

nums.sort()           # in-place sort, returns None
print(nums)           # [1, 2, 3]
```

| Form | New list? | Return value | Applies to |
|---|---|---|---|
| `sorted(x)` | Yes | A new list | Any iterable (tuples, strings too) |
| `x.sort()` | No, in-place | `None` | Only lists have this method |

This distinction bites in chained calls:

```python
# WRONG
result = nums.sort(reverse=True) * 2   # TypeError: NoneType does not support multiplication
```

`sort()` returns `None`, and `None * 2` errors out immediately. For chaining you need `sorted()`.

By the way, `max`/`min` also accept a `key`:

```python
words = ["python", "is", "awesome"]
print(max(words, key=len))     # "awesome"  -- the longest
```

### 3. `all()` and `any()` on empty sequences are counterintuitive

```python
print(all([]))    # True   -- "all elements satisfy" is vacuously true
print(any([]))    # False  -- "some element satisfies" has no witness
```

This is called "vacuous truth." `all` is logically equivalent to "there is no counterexample"; an empty set has no counterexamples, so it is true. `any` means "there exists a truthy element"; an empty set has none, so it is false.

The most common real-world crash:

```python
scores = []                       # no one has submitted yet
if all(s >= 60 for s in scores):  # True! empty list means everyone passed
    print("Class passed")          # wrong conclusion
```

```python
# RIGHT: check for non-empty first
if scores and all(s >= 60 for s in scores):
    print("Class passed")
```

`and` short-circuits on the falsy empty list, and the order must be "scores first, then all(...)."

## Crash Site: `zip` stops at the shortest iterable

```python
names = ["Alice", "Bob", "Carol"]
cities = ["London", "New York"]

for n, c in zip(names, cities):
    print(f"{n} lives in {c}")
```

```
Alice lives in London
Bob lives in New York
```

`Carol` simply vanishes. `zip` stops the instant **any one** of its iterables is exhausted; the leftover elements are silently discarded. To keep everything you need `itertools.zip_longest`:

```python
from itertools import zip_longest
for n, c in zip_longest(names, cities, fillvalue="unknown"):
    print(f"{n} lives in {c}")
```

```
Alice lives in London
Bob lives in New York
Carol lives in unknown
```

An even sneakier trap is the `dict`/`zip` construction:

```python
keys = ["name", "age", "city"]
values = ["Alice", 18]                    # one short
user = dict(zip(keys, values))
print(user)                             # {'name': 'Alice', 'age': 18} -- city is missing
```

Pass one value too few and the dict loses a key — **without raising an error**. This is especially dangerous with external data, because missing data rarely announces itself with an exception.

## Summary

- Comprehensions are great, but **beyond two levels, break them into a for loop**
- `sorted()` returns a new list and leaves the original alone; `list.sort()` modifies in place and returns `None`
- `all([])` is `True`, `any([])` is `False`; when data might be empty, check for empty first
- `zip` stops at the shortest; extra elements are silently dropped — for "keep all" use `zip_longest`
- `max`/`min`/`sorted` all accept a `key` argument; do not pre-convert manually

## Section Quiz

```quiz
type: choice
exam: true
q: What does running this code print?
code: |
  data = [(1, 20), (2, 5), (3, 100), (4, 50)]
  result = sorted(data, key=lambda t: t[1])
  print(result[0])
options:
- "(1, 20)"
- "(2, 5)"
- "(3, 100)"
- "(4, 50)"
answer: 1
explain: key=lambda t: t[1] sorts by the second element of each tuple: 20, 5, 100, 50. After sorting the order is (2,5), (1,20), (4,50), (3,100), so result[0] is (2, 5). This is the standard "sort by value" idiom.
```
