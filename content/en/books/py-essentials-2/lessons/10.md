# break / continue / Nesting — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 10 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
for i in range(5):
    if i == 2:
        continue        # skip this pass, move to the next iteration
    if i == 4:
        break           # leave the whole loop
    print(i)
# output: 0 1 3  <- 2 is skipped, 4 triggers break
```

The three control-flow tools:

- `continue`: **skip this pass** and go straight to the next iteration
- `break`: **leave the entire loop**, ending it immediately
- `pass`: **do nothing** — a placeholder (for an empty branch)

Nested loops: a loop inside a loop. The inner loop runs to completion once before the outer loop advances by one.

```python
for i in range(2):          # outer runs 2 times
    for j in range(3):      # inner runs 3 times each pass
        print(i, j)
# 0 0 / 0 1 / 0 2 / 1 0 / 1 1 / 1 2
```

`for ... else`: when the loop **finishes normally** (not interrupted by `break`), the `else` block runs.

```python
for n in range(2, 10):
    if n == 5:
        break
else:
    print("only runs if break was NOT hit")
# here break was hit, so else does not run
```

## Three Things People Get Wrong

### 1. `break` only jumps one level — it cannot escape the outer loop

```python
# WRONG: expecting to stop completely once 5 is found
for i in range(3):
    for j in range(3):
        if j == 1:
            break          # only breaks out of the inner for j
        print(i, j)
# 0 0 / 1 0 / 2 0  <- the outer loop keeps going
```

An inner `break` only escapes **the layer it belongs to**; the outer loop continues as usual. Two common ways to break out of multiple levels:

```python
# approach 1: a flag variable
found = False
for i in range(3):
    for j in range(3):
        if j == 1:
            found = True
            break
    if found:
        break              # break the outer loop too

# approach 2: extract into a function and use return
def find():
    for i in range(3):
        for j in range(3):
            if j == 1:
                return i, j
    return None

print(find())              # (0, 1)
```

Extracting into a function + `return` is usually clearer — prefer it.

### 2. `continue` in the wrong place silently skips a pass

```python
# WRONG: trying to skip evens and print only odds
for i in range(5):
    if i % 2 == 0:
        print("skipping even")
        continue
    print(i)          # only odds are printed here
# prints: skipping even / 1 / skipping even / 3 / skipping even
```

This example is fine, but beware: **everything after `continue` is skipped**, including the cleanup logic you expected to run.

```python
# WRONG
for i in range(5):
    if i == 2:
        continue
    print("processing", i)
    total += i        # when i == 2 this line never runs, so total is short by 2
```

`continue` skips **all** code that follows it, including whatever you thought would still execute. When writing `continue`, ask yourself: **is there anything that must run after it?** If yes, move that code before the `continue`, or rewrite with `if-else`.

### 3. `for ... else`'s `else` does not mean "the loop was empty"

Many people assume `else` runs "when the loop never executed". The opposite is true:

```python
# else runs when the loop "finished normally with no break"
for n in []:            # empty list, the body never runs once
    print("loop body")
else:
    print("else block")     # still runs! because it was not interrupted by break
```

The trigger for `else` is **the loop ended without hitting `break`**, even if it never iterated at all.

```python
# classic use: searching a sequence; found -> break
for x in [3, 1, 4, 1, 5]:
    if x == 9:
        print("found it")
        break
else:
    print("9 not found")     # runs, because break never happened
```

`else` means "ran without break" — the perfect phrasing for "I searched everywhere and did not find it".

## Crash Site: A common mistake with nested counters

Task: print the first three rows of the multiplication table.

```python
# WRONG: only one variable, shared by both inner and outer loops
i = 1
while i <= 3:
    j = 1
    while j <= 3:
        print(f"{i}x{j}={i*j}", end="  ")
        i = i + 1       # WRONG: this changes the outer i!
    print()
    j = j + 1
```

The inner `i = i + 1` also changes the outer `i`, so the outer loop stops after one pass. The inner and outer loops must use **two independent variables**:

```python
i = 1
while i <= 3:
    j = 1
    while j <= 3:
        print(f"{i}x{j}={i*j}", end="  ")
        j = j + 1       # only changes the inner j
    print()
    i = i + 1           # the outer loop advances on its own
# 1x1=1  1x2=2  1x3=3
# 2x1=2  2x2=4  2x3=6
# 3x1=3  3x2=6  3x3=9
```

One more trap, this time with `for-else`:

```python
# WRONG: expecting else to mean "never entered the loop"
found_prime = False
for n in range(2, 10):
    for d in range(2, n):
        if n % d == 0:
            found_prime = False
            break           # this break only exits the inner for d
    else:
        found_prime = True  # belongs to for d!
        print(n, "is prime")
```

`else` pairs with the **nearest enclosing `for`/`while`**. Here `else` belongs to `for d`, not `for n`. This misalignment is the most common source of bugs in nested loops. When indenting, **`else` must sit in the same column as the `for` it is meant to pair with**.

## Summary

- `continue` skips the rest of the current pass and moves to the next; `break` ends the whole loop
- `break` only jumps one level; to escape multiple levels, use `return` from a function or a flag variable
- `for ... else`'s `else` runs when **the loop ends without break**, including an empty loop
- Nested loops need independent variables for the inner and outer levels — do not share them
- `else` pairs with the nearest `for`/`while`; indentation must align
- `pass` is a no-op, used to occupy a syntactically required empty spot
