# Output & Input — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 3 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
print("Alice", "Bob", "Carol")          # Alice Bob Carol
print("Alice", "Bob", sep="|")          # Alice|Bob|Carol
print("Hi", end="")                     # no trailing newline
print(1, 2, 3, sep=", ", end="!\n")     # 1, 2, 3!

name = input("What is your name: ")      # always returns a string
age = int(input("How old are you: "))   # convert to an integer
```

| Usage | Purpose |
|---|---|
| `print(a, b, c)` | joins items with spaces, ends with a newline |
| `print(..., sep="|")` | custom separator |
| `print(..., end="")` | nothing added at the end |
| `input("prompt")` | shows a prompt, waits for Enter, returns a string |

**Reading multiple inputs** is the key skill. When several numbers sit on one line, split them with `split()`:

```python
a, b = input().split()              # input "3 5" -> a="3", b="5"
x, y = map(int, input().split())   # input "3 5" -> x=3, y=5
```

When called with no arguments, `split()` cuts on **any whitespace** (spaces, tabs, newlines), and multiple spaces count as a single separator.

## Three Things People Get Wrong

### 1. `sep` and `end` are keyword arguments — their order matters

```python
# WRONG
print(sep="|", "Alice", "Bob")   # SyntaxError: positional argument follows keyword argument
```

Keyword arguments (`sep=`, `end=`) must come **after positional arguments**. The correct version:

```python
print("Alice", "Bob", sep="|")
```

`sep` controls what goes **between** the items; `end` controls what is added **after** printing. People often mix them up:

```python
print("1", "2", "3", sep="-")   # 1-2-3   <- dashes in the middle
print("1", "2", "3", end="-")   # 1 2 3-  <- dash at the end
```

### 2. `input()` always returns a string — split first, then convert

```python
# WRONG
a, b = input().split(int)        # want two numbers: TypeError
```

`split()` does not accept a type like `int` as its argument; it only accepts "what character to cut on". The right approach is **split first, then convert**:

```python
# input: 3 5
data = input().split()           # ['3', '5']
a, b = int(data[0]), int(data[1])
```

A more concise form uses `map`:

```python
a, b = map(int, input().split())   # input "3 5" -> a=3, b=5
```

Note: `map` returns an iterator, and here we rely on **unpacking** to assign its values to `a` and `b` in one shot. If the number of inputs does not match the number of variables, you get an error:

```python
a, b = input().split()             # only one number entered -> ValueError: not enough values
```

### 3. The result of `print` cannot be used as a value

```python
# WRONG
total = print("The result is", 18 + 24)   # screen shows "The result is 42"
print(total)                              # None
```

`print()` **always returns `None`**. Its job is "show something on screen", not "return a string". To get a string, use formatting:

```python
result = f"the result is {18 + 24}"
print(result)              # the result is 42
print(result * 2)          # the result is 42the result is 42
```

At runtime, an f-string replaces each `{...}` with the value of the expression inside:

```python
name, score = "Alice", 95
print(f"{name}'s score is {score}")   # Alice's score is 95
```

## Crash Site: Forgetting to convert leads to concatenation instead of addition

```python
# WRONG
a, b = input().split()     # input "3 5"
print(a + b)               # 35
```

When the user types `3 5`, `split()` gives `["3", "5"]`. Adding two strings concatenates them, producing `"35"`. No error is raised — the program runs "successfully" — which makes this bug especially sneaky.

```python
# RIGHT
a, b = map(int, input().split())   # convert to integers first
print(a + b)                       # 8
```

The same trap appears when you compare values right after `input`: `"5" > "18"` is `True` (strings compare lexicographically; the first character `'5' > '1'`), while `5 > 18` is `False`. **Whenever you do arithmetic or numeric comparison, convert with `int()` / `float()` first.**

## Summary

- `sep` handles the middle, `end` handles the tail — both are keyword arguments, placed after positional ones
- `input()` is always a string; for multiple inputs, use `split()` then `int()`
- `print()` returns `None`; for a string, use an f-string
- Adding strings concatenates, adding numbers computes — mixing them often produces no error but gives the wrong result

- Line 1
- Line 2
- Line 3
- Line 4
answer: 2
explain: Line 3 puts the keyword argument sep="|" before the positional argument "a", so Python raises SyntaxError: positional argument follows keyword argument.
