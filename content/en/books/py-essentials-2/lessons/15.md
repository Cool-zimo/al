# Sets — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> This lesson corresponds to Lesson 15 of *Essential Python*. If any sentence in the recap looks unfamiliar, go back to Lesson 15 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
s = {1, 2, 3, 2, 1}
print(s)         # {1, 2, 3}   automatic deduplication

s.add(4)         # {1, 2, 3, 4}
s.remove(2)      # {1, 3, 4}   raises KeyError if absent
s.discard(9)     # does nothing if absent, no error

a = {1, 2, 3}
b = {3, 4, 5}
print(a & b)     # {3}         intersection
print(a | b)     # {1, 2, 3, 4, 5}   union
print(a - b)     # {1, 2}      difference: in a but not b
print(a ^ b)     # {1, 2, 4, 5}   symmetric difference: in exactly one of them
```

| Operation | Operator | Method |
|---|---|---|
| intersection | `a & b` | `a.intersection(b)` |
| union | `a | b` | `a.union(b)` |
| difference | `a - b` | `a.difference(b)` |

Set elements must be hashable, so **lists cannot go into a set**. `in` tests are O(1).

## Three Things People Get Wrong

### 1. An empty set cannot be written `{}`

```python
a = {}
print(type(a))      # <class 'dict'>   this is an empty dict

b = set()
print(type(b))      # <class 'set'>    this is an empty set
```

In Python, `{}` is already taken by dictionaries. `set()` is what denotes an empty set. When there are elements, `{1, 2, 3}` is fine, because a dictionary would need colons.

### 2. Sets are unordered — do not expect an order

```python
print({3, 1, 2})    # {1, 2, 3}   order varies; different versions/runs may differ
```

For O(1) lookup, sets use a hash table internally and **do not record insertion order**. So:

- For "deduplicate while preserving order": use a list + a set helper (see the in-class exercise)
- For "deduplicate but order does not matter": just use `set()`
- Python 3.7+ dicts preserve order, **but sets never do**

### 3. `remove()` raises on absence, `discard()` does not

```python
s = {1, 2, 3}
s.remove(9)     # KeyError: 9
s.discard(9)    # does nothing, no error
```

**When you are unsure whether the element is present, use `discard`**; only use `remove` when you are certain it is there.

## Crash Site: Using a list where a set is needed

```python
# WRONG: trying to find which cities appear in both lists
a = ["London", "New York", "Paris"]
b = ["Paris", "Tokyo", "London"]
print(a & b)      # TypeError: unsupported operand type(s) for &: 'list' and 'list'
```

`&`, `|`, `-` are set operators — lists do not understand them. Many people have already imagined the intersection as `&`, but their hands are still writing lists, and they run into `TypeError`.

Correct version: convert to sets before operating.

```python
a = ["London", "New York", "Paris"]
b = ["Paris", "Tokyo", "London"]
common = set(a) & set(b)
print(common)             # {'Paris', 'London'}   unordered
print(sorted(common))     # ['London', 'Paris']   for order, sort afterwards
```

**To turn a set back into a list, use `sorted()` — never just `list()`**, since the latter gives a random order.

The "list `in` is slow" problem gets dramatically worse at scale:

```python
# slow
cities = ["London", "New York", "Paris", "Tokyo", "Oslo"] * 2000   # ten thousand cities
for _ in range(10000):
    if "Lima" in cities:      # every check scans from the start, O(n)
        pass
```

```
# no error, but slow
# a list of ten thousand elements averages five thousand comparisons per check
```

A list's `in` is a linear scan, O(n). **To test "is it there?", a set is O(1)** — a hash lands on the answer directly.

```python
cities = ["London", "New York", "Paris", "Tokyo", "Oslo"] * 2000
city_set = set(cities)        # convert to a set, one pass at O(n)
for _ in range(10000):
    if "Lima" in city_set:    # O(1)
        pass
```

Converting to a set costs one scan, and every query after that is constant time. The larger the dataset, the more extreme the gap: **ten thousand list lookups versus ten thousand set lookups can differ by a factor of one hundred or more**.

Remember this rule: **for deduplication, removing duplicates, and membership tests, your first thought should be a set.**

## Summary

- An empty set is `set()`; `{}` is a dict
- Sets are unordered; to deduplicate while preserving order, use a list with a set helper
- Elements must be hashable: lists cannot go into a set
- When presence is uncertain, use `discard()`; use `remove()` only when you are sure
- **Test membership with sets (O(1)), not lists (O(n))**

## In-Class Practice

```quiz
type: code
q: Read one line of several space-separated integers, and output the deduplicated list in its original order. For example input "3 1 2 1 3 2 4" outputs "[3, 1, 2, 4]". Note: converting straight to a set scrambles the order; you must use a list plus a set helper.
starter: |
  nums = [int(x) for x in input().split()]
  seen = set()
  result = []
  # iterate over nums; add unseen elements to result and register them
  print(result)
tests:
- assert __out.strip() == "[3, 1, 2, 4]"
- assert __out.strip() == "[1, 2, 3]"
hints: for n in nums: if n not in seen: seen.add(n); result.append(n). The set handles O(1) deduplication, the list preserves order.
explain: This is the most typical use of a set: use one set to track "what has already appeared", and a list to track "the final order". Together they give O(1) deduplication while preserving first-seen order. set() alone cannot preserve order.
```

## Section Quiz

```quiz
type: choice
exam: true
q: Which of the following correctly creates a set containing only the number 1?
code: |
options:
- "s = {1}"
- "s = set(1)"
- "s = {}"
- "s = (1)"
answer: 0
explain: A {1} is a set literal, correct. B set(1) raises an error because 1 is not iterable — set expects an iterable argument. C {} is an empty dict. D (1) is just the integer 1 in parentheses, neither a set nor a tuple. So only A is correct.
```

```quiz
type: function
exam: true
q: Write common_elements(a, b): return a list of elements that "appear in both" lists, deduplicated and in the order of their "first appearance in a". For example [1, 2, 3, 2, 4] and [3, 4, 5, 1] returns [1, 3, 4] (note 2 is not in b and is dropped; 1 appears earliest in a).
func: common_elements
starter: |
  def common_elements(a, b):
      # convert b to a set for O(1) lookup, then walk a to collect results
      return []
cases: |
  [1, 2, 3, 2, 4], [3, 4, 5, 1] -> [1, 3, 4]
  [1, 1, 1], [1, 2] -> [1]
  [1, 2, 3], [4, 5, 6] -> []
  [], [1, 2] -> []
hints: b_set = set(b), then iterate over a: if x is in b_set and has not yet been collected (track with a seen set), append it to result.
explain: The key is converting b to a set for O(1) lookup, plus a seen set to avoid duplicates in the result. Walking a guarantees the result order follows a. Time complexity is O(n+m), far better than two nested loops at O(n*m).
```
