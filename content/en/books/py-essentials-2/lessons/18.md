# Scope Review

> This lesson does not re-teach concepts. It does three things: **recap the key points in thirty seconds, correct the three most common mistakes, and test whether you really understand it.**
> If anything in the recap looks unfamiliar, go back and read Lesson 18 of the *Learning* book first, then come back and do the exercises.

## 30-Second Recap

```python
x = 10              # global variable

def show():
    x = 20          # local variable, not the same as the global x
    print(x)

show()              # 20
print(x)            # 10
```

| Concept | Where visible | Keyword |
|---|---|---|
| Local variable | Only inside the function | Assignment inside a function |
| Global variable | The whole file | Assignment outside any function |
| Modifying a global inside a function | Requires `global` | `global x` |
| Nested scope | Inner function | `nonlocal` |

Scope is **the layer at which a name is "visible."** A name assigned inside a function is local by default.

## Three Things People Get Wrong

### 1. Forgetting `global` when modifying a global variable inside a function

```python
# WRONG
count = 0

def inc():
    count = count + 1      # trying to modify the global count

inc()
```

```
UnboundLocalError: local variable 'count' referenced before assignment
```

Python sees the line `count = ...` inside the function and treats `count` as a local variable. So the `count` on the right side of the `=` is still the "not yet assigned" local one — and it blows up.

To modify the global, you must declare it with `global` first:

```python
count = 0

def inc():
    global count           # I mean the count from outside
    count = count + 1

inc()
print(count)              # 1
```

**One-liner: before assigning to a global variable, write `global` first.**

### 2. Reading a global does not need `global`, but writing does

```python
x = 100

def read_x():
    print(x)              # reading is fine, no global needed

def change_x():
    global x              # writing requires a declaration
    x = 200

read_x()                  # 100
change_x()
print(x)                  # 200
```

"Reading" needs no declaration; "**writing**" (assignment) needs `global`. This is the most confusing point for beginners.

### 3. Modifying a mutable parameter inside a function changes the outside too

This is not the same as "scope," but their effects often show up together.

```python
def add_score(scores, s):
    scores.append(s)

all_scores = [90, 85]
add_score(all_scores, 100)
print(all_scores)          # [90, 85, 100]
```

No `global` here — the passed-in list is simply a mutable object, and `.append()` modifies the list itself, so the outside changes too. Lesson 16 covered this: **scope governs "names"; mutable objects govern "contents."** Do not mix them up.

## Crash Site: A Closure Shares the Same Variable

```python
# WRONG
def make_functions():
    fs = []
    for i in range(3):
        def f():
            return i
        fs.append(f)
    return fs

for g in make_functions():
    print(g())             # guess what this prints?
```

Most people expect `0 1 2`, but it actually prints `2 2 2`: all three functions **share the same `i`**, and by the time they are called the loop has ended and `i` is stuck at `2`.

The fix is to use a default argument — its value is "frozen" at definition time:

```python
def make_functions():
    fs = []
    for i in range(3):
        def f(i=i):        # "engrave" the current value of i into the function
            return i
        fs.append(f)
    return fs

for g in make_functions():
    print(g())             # 0 1 2
```

A closure captures **the variable itself**, not the value it happens to hold at that moment. To "freeze" a value, use a default argument.

## Summary

- **Writing** to a global inside a function needs `global`; **reading** does not
- The `global` declaration must come before the assignment
- Scope governs "names"; mutable objects govern "contents" — do not confuse them
- A closure captures the variable itself; to freeze a value, use a default argument

## In-Class Exercise

```quiz
type: function
q: Write counter(): use global to implement a counter. The first call returns 1, the second returns 2, the third returns 3... Each call increments by one
func: counter
starter: |
  count = 0

  def counter():
      # declare count as global, increment it, and return
      return 0
cases: |
  () -> 1
  () -> 2
  () -> 3
hint: Inside the function, write global count, then count = count + 1, then return count.
explain: Every call to counter modifies the global count, so it must be declared global. Increment first, then return, so successive calls yield 1, 2, 3.
```

```quiz

q: What does this code print?

  x = 10

  def f():
      x = 20
      print("Inside:", x)

  f()
  print("Outside:", x)
options:
- Inside: 20 / Outside: 20
- Inside: 20 / Outside: 10
- Inside: 10 / Outside: 10
- error
answer: 1
explain: The x = 20 inside the function creates a local variable, not the same as the global x. A local assignment does not affect the global, so the outside still prints 10. To modify the global, you would need global x.
```
