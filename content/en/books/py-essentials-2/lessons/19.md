# String Methods Review

> This lesson does not re-teach concepts. It does three things: **recap the key points in thirty seconds, correct the three most common mistakes, and test whether you really understand it.**
> If anything in the recap looks unfamiliar, go back and read Lesson 19 of the *Learning* book first, then come back and do the exercises.

## 30-Second Recap

```python
s = "  hello, WORLD  "
s.strip()            # "hello, WORLD"           removes whitespace from both ends
s.replace("WORLD", "world")  # "  hello, world  "
s.find("WORLD")      # 3     returns -1 if not found
s.startswith("  he") # True
s.upper()            # "  HELLO, WORLD  "
s.lower()            # "  hello, world  "

s.split(",")         # ['  hello', ' WORLD  ']   split by comma
"|".join(["a", "b", "c"])  # 'a|b|c'             join back with |

name = "Alice"
f"Hello, {name}, your score is {89.4567:.2f}"   # Hello, Alice, your score is 89.46
f"{name:<10}"                          # left-aligned in a 10-character field
```

| Operation | Method | Common pitfall |
|---|---|---|
| Split | `split(",")` | With no argument, splits on **any whitespace** and collapses consecutive whitespace |
| Join | `"sep".join(iterable)` | Takes exactly one iterable argument, not multiple |
| Search | `find` / `index` | `find` returns -1 if not found; `index` raises `ValueError` |
| Format | `f"{x:.2f}"` / `f"{x:<10}"` | `:.2f` only works on floats |

**Strings are immutable**: every method returns a **new string**; the original is untouched.

## Three Things People Get Wrong

### 1. `split()` with no argument vs. with an argument behave completely differently

This is the most frequently misread behavior of `split`.

```python
s = "a  b\tc   d"
print(s.split())        # ['a', 'b', 'c', 'd']
print(s.split(" "))     # ['a', '', 'b\tc', '', '', 'd']
```

When called with no argument, `split()` splits on **any whitespace character** (space, newline, tab) and **automatically collapses consecutive whitespace**. But `split(" ")` only splits on **single spaces**, leaving empty strings `''` between multiple spaces.

When parsing structured text (logs, score sheets), you almost always want the first version:

```python
line = "Alice   95   London"
name, score, city = line.split()
print(name, score, city)   # Alice 95 London
```

`split` also takes a second argument, `maxsplit`, limiting how many cuts it makes:

```python
"a:b:c:d".split(":", 1)   # ['a', 'b:c:d']   only one cut, the rest stays together
```

### 2. `join` takes "one iterable," not multiple arguments

This is a calling mistake, not a logic mistake.

```python
# WRONG
"|".join("a", "b", "c")   # TypeError
```

`join` accepts only one positional argument, and that argument must be iterable (a list, tuple, or even a string). Correct usage:

```python
"|".join(["a", "b", "c"])   # 'a|b|c'
"".join(["a", "b", "c"])    # 'abc'         empty-string join == concatenate
", ".join(["apple", "banana", "orange"])  # 'apple, banana, orange'
```

Two details:
1. `join` is **a method of the separator string**, not of the list. Mnemonic: "let the `|` string string everyone together," so it is `"|".join(...)`.
2. `join` requires **every element to be a string**. A number sneaked into the list will error out:

```python
",".join([1, 2, 3])       # TypeError: sequence item 0: expected str
",".join(str(x) for x in [1, 2, 3])  # '1,2,3'   convert first with a generator expression
```

### 3. String methods do not change the original; you must capture the return value

```python
s = "  hello  "
s.strip()         # returns a new string, but nobody catches it
print(s)          # "  hello  "   still unchanged!
```

Correct:

```python
s = "  hello  "
s = s.strip()     # capture the return value
print(s)          # "hello"
```

`strip` / `replace` / `upper` / `lower` / `split` all work this way. Only methods like `list.sort()` mutate in place — strings have no concept of "in-place modification."

By the way, `strip()` can also take an argument to remove specified characters, but it **strips characters from the set one at a time from both ends**, not a substring:

```python
"www.example.com".strip("w")      # '.example.com'
"www.example.com".strip("cmowz.") # 'example'    dangerous: keeps stripping until it cannot
```

## Crash Site: Treating `find`'s `-1` as "found"

```python
# WRONG
s = "hello world"
pos = s.find("python")
if pos:                # -1 is "truthy"! -1 is not 0, so this actually enters the if
    print("Found at position", pos)
```

```
Found at position -1
```

`-1` is truthy in Python (`if -1` is `True`), so putting the result of `find` straight into an `if` condition will execute the branch even when "nothing was found." Correct:

```python
pos = s.find("python")
if pos != -1:          # explicit check
    print("Found at position", pos)
else:
    print("Not found")

# Better yet: just use in to test for presence
if "python" in s:
    print("Found")
```

`-1` is not `False`. Remember: **check `find`'s result with `!= -1`, or use `in` for presence and only use `find` to get the position.**

## Summary

- `split()` with no arguments splits on any whitespace and collapses consecutive whitespace; `split(",")` splits only on commas
- `join` takes exactly one iterable argument: `"|".join(list)`, and every element must be a string
- Strings are immutable; every method returns a new string — remember to capture the return value
- `find` returns `-1` when nothing is found; use `in` to test for presence and write `!= -1` when you actually need the position
- f-strings: `{x:.2f}` keeps two decimal places; `{x:<10}` left-aligns in a 10-character field

```quiz
type: code
q: Read a line of integers separated by **commas** (e.g. "3,7,2,9") and print their sum. System input: 3,7,2,9
starter: |
  line = input().strip()
  # 1. split  2. convert to int  3. sum
  print("change here")
stdin: |
  3,7,2,9
tests:
- assert "21" in __out
hint: line.split(",") gives a list of strings; convert each with int().
explain: After splitting you get ["3","7","2","9"], but each element is still a string — you must convert with int(x) before adding. If you sum them directly you will get a TypeError, or in some implementations the strings will concatenate. The correct approach is sum(int(x) for x in line.split(",")).
```
