# Arithmetic & Strings — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 4 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
print(17 // 3)     # 5    floor division, remainder discarded
print(17 % 3)      # 2    remainder
print(2 ** 10)     # 1024 exponentiation

s = "python"
print(s[0])        # p    positive index: starts at 0
print(s[-1])       # n    negative index: -1 is the last
print(s[1:4])      # yth   slice [start:stop), stop not included
print(s[::-1])     # nohtyp reversed

print("a" + "b")   # ab   string concatenation
print("ab" * 3)    # ababab repetition
```

| Operator | Meaning | Example | Result |
|---|---|---|---|
| `//` | floor division | `17 // 3` | `5` |
| `%` | remainder | `17 % 3` | `2` |
| `**` | exponentiation | `2 ** 10` | `1024` |
| `[i]` | index | `"abc"[1]` | `"b"` |
| `[a:b]` | slice | `"abcde"[1:4]` | `"bcd"` |
| `*` | repeat | `"ab" * 3` | `"ababab"` |

**Precedence**: exponentiation `**` is highest, then multiplication/division `*`, `/`, `//`, `%`, and finally addition/subtraction `+`, `-`. **When in doubt, add parentheses** — it is safe and readable.

## Three Things People Get Wrong

### 1. The precedence trap: `-3 ** 2` is not `9`

```python
print(-3 ** 2)      # -9
print((-3) ** 2)    # 9
```

`-3 ** 2` is parsed as `-(3 ** 2)` because `**` binds more tightly than unary minus. This trap is extremely common when writing formulas.

Another classic trap involves `%` with negatives:

```python
print(-17 % 3)      # 1    not -2!
print(-17 // 3)     # -6   floor towards negative infinity, not -5
```

Python's floor division **rounds towards negative infinity**, and the remainder guarantees that `a == a // b * b + a % b` always holds. So `-17 // 3` is `-6` (because `-6 * 3 = -18 ≤ -17`), which makes `-17 % 3` equal to `1`. C and Java give different results, so be careful when switching languages.

### 2. Slices are "left-inclusive, right-exclusive" — and out-of-range does not error

```python
s = "python"
print(s[1:4])       # yth   —— index 4 ('o') is not included
```

Remember the rule: **start counts, stop does not**. So `s[0:2]` contains `s[0]` and `s[1]`, but not `s[2]`.

Slicing has a "forgiving" trait: out-of-range indices **do not raise an error**; they are silently clipped to the valid range:

```python
s = "python"
print(s[2:100])     # thon    —— the out-of-range part is ignored
print(s[-100:2])    # py      —— going too far back also works
print(s[100:])      # empty string
```

But **indexing** out of range raises an error immediately:

```python
s[100]              # IndexError: string index out of range
```

That is the difference between "strict indexing" and "forgiving slicing". When writing loops or processing user input, slicing is often more convenient than indexing.

### 3. `+` and `*` mean concatenation/repetition on strings, not arithmetic

```python
print("3" + "5")    # 35    concatenation
print("3" * 5)      # 33333  repeated 5 times
print("3" * "5")    # TypeError: can't multiply sequence by non-int
```

Strings can only be multiplied by an integer (repetition), not by another string. For arithmetic, convert the type first:

```python
print(int("3") + int("5"))   # 8
```

Negative indices count "from right to left": `-1` is the last character, `-len(s)` is the first:

```python
s = "python"
print(s[-1])        # n
print(s[-2])        # o
print(s[-6])        # p
print(s[-7])        # IndexError: string index out of range
```

Note that negative indices also have a boundary — going beyond it raises an error.

## Crash Site: "Modifying" a string slice by assignment

```python
# WRONG
s = "python"
s[1:3] = "YZ"       # TypeError: 'str' object does not support item assignment
```

Strings are immutable, so neither a single character position **nor** a slice can be assigned to. To replace a segment, build a new string out of slices:

```python
s = "python"
s = s[:1] + "YZ" + s[3:]    # join the front and back slices
print(s)                     # pYthon
```

The same logic applies to "deletion":

```python
s = "python"
s = s[:2] + s[4:]           # drop indices 2 and 3 ('th')
print(s)                     # pyon
```

**Omitting the start or stop of a slice** is a very useful pattern:

```python
s = "python"
print(s[:3])    # pyt   from the very beginning
print(s[3:])    # hon   up to the very end
print(s[:])     # python  a copy (not very useful for strings; for lists it is a shallow copy)
```

## Summary

- `**` binds tighter than minus; think twice before writing `-3**2`
- Slices are left-inclusive, right-exclusive; out of range is fine, indexing out of range always errors
- Negative indices start at `-1` and count backwards from the end
- `+` concatenates strings, `*` only repeats them with an integer
- Strings are immutable; changes must build a new string from slices

type: code
q: Read a string s and print it reversed. The system will feed in "hello".

  s = input()
  # use slice [::-1] to reverse the string
  print("TODO: replace this line with your output")

  hello

- assert __out.strip() == "olleh"
hints: A slice with step -1 walks the characters backwards. The syntax is s[::-1].

## Section Quiz

```quiz
type: choice
exam: true
q: Which expression evaluates to 1?
code: |
  A: 17 % 4
  B: -17 % 4
  C: 17 // 4
  D: -17 // 4
options:
- Only A
- A and B
- Only C
- Only D
answer: 0
explain: 17 % 4 = 1 (17 = 4×4 + 1). In Python, -17 % 4 is 3: floor division rounds towards negative infinity, so -17 // 4 = -5, and -17 = -5×4 + 3. 17 // 4 = 4, -17 // 4 = -5. Of the four, only A gives 1.
```
