# if / elif / else — Reinforced

> This lesson does not introduce new concepts. It does three things: **recaps the key points in thirty seconds, corrects the three mistakes people make most often, and tests whether you actually understand it through exercises.**
> If any sentence in the recap looks unfamiliar, go back to Lesson 6 of *Essential Python* and come back to the exercises afterwards.

## 30-Second Recap

```python
score = 85

if score >= 90:
    level = "excellent"
elif score >= 60:        # elif = else if, only checked if the above missed
    level = "pass"
else:                    # none of the above
    level = "fail"

print(level)             # pass
```

Comparison operators: `==` (equals), `!=` (not equals), `>`, `<`, `>=`, `<=`.

Just two core rules govern conditionals:

1. **Conditions are tested top to bottom; once one matches, it runs and the rest are skipped.** `elif` matches in order — it does **not** run "every condition that happens to be true".
2. **Indentation defines membership.** Everything at the same indent belongs to the same branch; get the indent wrong and the logic is wrong.

```python
if score >= 60:
    print("you graduate")      # indented 4 spaces, belongs to the if block
print("this always runs")      # flush left, unrelated to the if
```

## Three Things People Get Wrong

### 1. Reversing the order — a broad condition comes first

This is the classic `elif` trap. No competition.

```python
# WRONG: the broadest condition is written first
score = 85

if score >= 60:                  # 85 satisfies this
    print("pass")               # matches, runs
elif score >= 90:               # this is never reached
    print("excellent")
```

Once `score >= 60` matches, the `elif` below is **dead on arrival**. An 85 is "excellent"? Not here — the program already took the first branch.

The correct order is **narrow to broad**, putting the smallest range first:

```python
score = 85

if score >= 90:                  # ask the strictest first
    print("excellent")
elif score >= 60:                # then the looser one
    print("pass")
else:
    print("fail")
```

Think of the order as a funnel: **narrow first, then wide**. Build the habit of arranging `elif` from the strictest condition downward.

### 2. Using `=` instead of `==` for comparison

```python
# WRONG
if x = 18:          # SyntaxError: invalid syntax
    print("equals 18")
```

`=` is assignment; `==` is comparison. Python is friendly here and blocks you with `SyntaxError` directly. But in a `while` condition this same mistake is far sneakier — Lesson 8 covers that.

```python
x = 18
if x == 18:         # True
    print("equals 18")
```

Notice that `if x = 18:` and `if x == 18:` differ by a single character, yet they are completely different things.

### 3. Inconsistent indentation — mixing spaces and tabs

```python
# WRONG: one line uses 4 spaces, another uses a tab
if score >= 60:
    print("pass")
	print("you graduate")      # IndentationError: unindent does not match
```

Python rejects inconsistent indentation on sight — the program never even runs. Worse are the cases where **it looks aligned but is not**: full-width spaces, or a mix of tabs and spaces, are nearly impossible to spot by eye.

The fix: use **4 spaces** consistently throughout. Configure your editor to turn tabs into 4 spaces automatically and you never have to think about it again.

```python
if score >= 60:
    print("pass")        # 4 spaces
    if score >= 90:
        print("excellent")    # indent 4 more, 8 total
```

## Crash Site: A branch that is never reached

```python
# WRONG: grading scores, but 95 ends up as "pass"
score = 95

if score >= 60:
    level = "pass"
elif score >= 80:
    level = "good"
elif score >= 90:
    level = "excellent"
else:
    level = "fail"

print(level)        # pass  <- 95 only gets "pass"
```

The problem is obvious in hindsight: the broadest condition `>= 60` is first, so 95 is intercepted by "pass" right away, and the `>= 80` and `>= 90` lines become **dead code** — logically unreachable.

Fix: **rearrange from strict to loose**.

```python
score = 95

if score >= 90:
    level = "excellent"
elif score >= 80:
    level = "good"
elif score >= 60:
    level = "pass"
else:
    level = "fail"

print(level)        # excellent
```

The scary part about this kind of bug is that **it does not raise an error**: the program runs perfectly, just with the wrong result. To catch it, you have to test boundary values yourself (60, 79, 80, 89, 90) rather than wait for a user to complain.

## Summary

- `elif` matches in order; one match skips the rest — not "every true condition runs"
- Write `elif` from **strict to loose**, strictest condition first
- `=` is assignment, `==` is comparison; mixing them raises `SyntaxError`
- Use 4 spaces for indentation consistently; never mix tabs
- Conditional bugs often produce no error — verify boundaries (60, 90) yourself

## In-Class Practice

```quiz
type: code
q: Read an integer score from 0 to 100, and print the grade by the rules: 90 and above -> "excellent"; 80 to 89 -> "good"; 60 to 79 -> "pass"; below 60 -> "fail". The system will feed in 78.
starter: |
  # use if-elif-else, strict to loose
  score = int(input())
  print("TODO: replace this line with your output")
stdin: |
  78
tests:
- assert "pass" in __out
hints: Order it if score >= 90, elif score >= 80, elif score >= 60, else. Test the boundaries 80 and 90 yourself.
explain: This is purely a test of condition order. A counter-example puts if score >= 60 first, so even 90 becomes "pass" because the first branch steals the value. Also watch the boundaries: exactly 80 should be "good" (takes elif >=80), exactly 60 should be "pass" (takes elif >=60).
```

## Section Quiz

```quiz
type: choice
exam: true
q: The input is 5. What does the following code print?
code: |
  n = int(input())
  if n > 3:
      print("A")
  elif n > 6:
      print("B")
  else:
      print("C")
  # user input: 5
options:
- A
- B
- C
- Nothing
answer: 0
explain: 5 > 3 is true, so the first branch is hit immediately and prints A. The second branch (n > 6) is never even evaluated — that is the cost of putting the loose condition first. Swap the two branches and 5 falls through to else, printing C.
```
