# Functions Review

> This lesson does not re-teach concepts. It does three things: **recap the key points in thirty seconds, correct the three most common mistakes, and test whether you really understand it.**
> If anything in the recap looks unfamiliar, go back and read Lesson 16 of the *Learning* book first, then come back and do the exercises.

## 30-Second Recap

```python
def function_name(param1, param2):
    do something
    return result     # hand the result back
```

```python
def add(a, b):
    return a + b

s = add(3, 5)
print(s)            # 8
```

| Concept | One-liner | Example |
|---|---|---|
| `def` | Define a function | `def hi():` |
| Parameters | Values the function needs before running | `def add(a, b)` |
| `return` | Hand the result back | `return a + b` |
| No `return` | Implicitly returns `None` | `def f(): pass` |
| Multiple return values | Actually returns a **tuple** | `return a, b` |

A function is **a reusable block of code**. Parameters feed in data; `return` hands back the result.

## Three Things People Get Wrong

### 1. Forgetting `return`, ending up with `None`

This is the easiest mistake to make, and it does not even show up as an error — because nothing errors out.

```python
# WRONG
def add(a, b):
    a + b            # it computed the sum, but never returned it

result = add(3, 5)
print(result)        # None
```

`a + b` really was computed, but the result was thrown away. **To get the result, you must `return` it:**

```python
def add(a, b):
    return a + b

print(add(3, 5))     # 8
```

Remember this sentence: **Whatever you compute inside a function, if you do not `return` it, it will not come back out.**

### 2. Thinking "returning multiple values" truly returns multiple values

```python
def point():
    x = 3
    y = 4
    return x, y       # looks like two values

p = point()
print(p)             # (3, 4)
print(type(p))       # <class 'tuple'>
```

`return x, y` actually **packs `x` and `y` into a tuple and returns that tuple**. `p` is just the tuple `(3, 4)`. Python simply lets you use an "unpacking" syntax to catch both at once:

```python
a, b = point()       # unpacking: a gets 3, b gets 4
print(a, b)          # 3 4
```

So "returning multiple values" is just syntactic sugar; at its core it still returns **one tuple**.

### 3. Thinking parameters are "pass-by-value," so the outside will not change

Python passes **object references**: the function receives the very same object. If that object is **mutable**, changing it inside also changes it outside.

```python
def add_item(lst, item):
    lst.append(item)         # modifies the original list itself

scores = [90, 85]
add_item(scores, 100)
print(scores)               # [90, 85, 100] -- changed outside too
```

Meanwhile, **immutable objects** like numbers and strings always produce a new object when you "change" them, so the outside stays untouched:

```python
def raise_price(price):
    price = price + 10       # only makes the local variable price point to a new number

p = 100
raise_price(p)
print(p)                    # 100 -- unchanged
```

**Mutable objects get changed (lists, dicts); immutable ones do not (numbers, strings, tuples).**

## Crash Site: A Function Name Gets Shadowed by a Variable

```python
# WRONG
def add(a, b):
    return a + b

add = add(3, 5)      # now add points to the number 8
print(add(1, 2))     # TypeError: 'int' object is not callable
```

The `add` defined on the first line is a function. The third line overwrites it with the number `8`. From then on, `add` is no longer a function, so "calling add" blows up.

This kind of error is easy to write by accident. The rule is simple: **never reuse a function name as a variable name.** If you genuinely need to store the return value, use a different name:

```python
def add(a, b):
    return a + b

result = add(3, 5)   # different name
print(result)         # 8
```

## Summary

- A function with no `return` implicitly returns `None`
- "Returning multiple values" is really returning **one tuple**, which can be unpacked with `a, b = f()`
- Parameters pass object references: mutable objects change; immutable ones do not
- Never reassign a function name to something else

## In-Class Exercise

```quiz
type: function
q: Write calc(a, b): return the result of a plus b and the result of a times b (use "returning multiple values" so the caller catches them with two variables)
func: calc
starter: |
  def calc(a, b):
      # use return to send back two values at once
      return 0, 0
cases: |
  (3, 5) -> (8, 15)
  (10, 2) -> (12, 20)
  (-1, 4) -> (3, -4)
hint: return a + b, a * b. Separating values with a comma returns a tuple; outside, use x, y = calc(a, b) to unpack.
explain: "Returning multiple values" is really just returning a tuple. return a + b, a * b is equivalent to return (a + b, a * b), and the caller unpacks it to get both results.
```

## Section Quiz

```quiz
type: choice
exam: true
q: What does this code print?
code: |
  def f():
      x = 10

  print(f())
options:
- 10
- None
- error
- 0
answer: 1
explain: The function only assigns to x, it never returns anything, so f() implicitly returns None. This is the classic "forgot to write return" crash -- it returns None, not 10.
```

```quiz
type: function
exam: true
q: Write double_list(lst): double every number in the passed-in list and **return the same list**. Requirement: modify the list in place (taking advantage of the fact that lists are mutable); do not build a new list
func: double_list
starter: |
  def double_list(lst):
      # modify the passed-in list directly
      return []
cases: |
  ([1, 2, 3],) -> [2, 4, 6]
  ([10],) -> [20]
  ([0, -1, 5],) -> [0, -2, 10]
hint: Loop over the indices with a for loop and do lst[i] = lst[i] * 2. Lists are mutable, so this change is also visible outside.
explain: A list is a mutable object. Inside the function, lst[i] = ... modifies the original list directly, so the outside variable sees the change too. This is exactly the consequence of "passing object references" -- mutable objects modified inside the function are reflected outside.
```
