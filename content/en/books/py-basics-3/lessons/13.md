# else and finally

> A full `try` has four parts. The last two aren't used every day, but used well they make code much cleaner.

## The full shape

```python
try:
    code that might fail
except ErrorType:
    if it failed
else:
    only if it didn't fail
finally:
    either way
```

**Four parts; only `try` is mandatory.**

## else: only when nothing went wrong

```python
try:
    n = int("42")
except ValueError:
    print("conversion failed")
else:
    print(f"converted: {n}")        # runs only on success
```

**Why a separate `else`?** Couldn't you just put it in the `try`?

```python
# ❌ the problem with mixing them
try:
    n = int(user_input)
    print(f"converted: {n}")        # ← if THIS fails, the except below catches it
except ValueError:
    print("conversion failed")
```

**The difference:** any error in the `try` block gets caught by its `except`. If you only want the conversion protected, put the rest in `else`:

```python
# ✅ only int() is protected
try:
    n = int(user_input)
except ValueError:
    print("conversion failed")
else:
    # errors here are NOT swallowed — you'll see them
    print(f"converted: {n}")
    save_to_db(n)                  # a bug in here surfaces properly
```

> 💡 **`else` narrows the protected range**, so you don't mask other bugs.

## finally: runs no matter what

```python
try:
    f = open('data.txt', 'r', encoding='utf-8')
    content = f.read()
except FileNotFoundError:
    print("no such file")
finally:
    print("this always runs")
```

**`finally` runs whether or not there was an error, and whether or not there's a `return`.**

### The classic use: cleanup

```python
f = None
try:
    f = open('data.txt', 'r', encoding='utf-8')
    content = f.read()
    print(content)
except FileNotFoundError:
    print("no such file")
finally:
    if f:
        f.close()          # closed either way
        print("file closed")
```

**That's exactly what `with` does under the hood** — `with` is syntactic sugar for `try/finally`.

> 💡 Since `with` exists, you rarely need a hand-written `finally` for files. But for **network and database connections** without a `with`, `finally` is still the standard.

### finally even beats return

```python
def demo():
    try:
        return "from try"
    finally:
        print("finally ran")      # runs before returning

print(demo())
```

```
finally ran
from try
```

**Even with a `return` inside `try`, `finally` runs first.**

## The three optional parts

| Part | Runs when |
|---|---|
| `except` | **something failed** |
| `else` | **nothing failed** |
| `finally` | **always** |

```
code in try
    ├─ failed → except → finally
    └─ fine   → else   → finally
```

## Practice: a robust reader

```python
import json


def load_config(path):
    """Read a config file; never crashes."""
    try:
        with open(path, 'r', encoding='utf-8') as f:
            config = json.load(f)
    except FileNotFoundError:
        print(f"[warn] {path} missing — using defaults")
        return {}
    except json.JSONDecodeError:
        print(f"[error] {path} isn't valid JSON")
        return {}
    except PermissionError:
        print(f"[error] no permission to read {path}")
        return {}
    else:
        print(f"[ok] loaded {len(config)} settings")
        return config


config = load_config('config.json')
print(config)
```

**Whatever happens, this returns a dict** — callers don't have to worry.

## When to use else?

**Only when you want to narrow what `try` protects.**

Most of the time, putting everything in `try` is fine:

```python
# common and perfectly fine
try:
    n = int(input("number: "))
    print(f"double is {n * 2}")
except ValueError:
    print("not a number")
```

**`else` is for "I only want this one line protected".**

## Summary

- **`except`**: when something failed
- **`else`**: when **nothing** failed (narrow the protected range)
- **`finally`**: **always** (cleanup)
- `with` is `try/finally` in disguise
- `finally` runs even before a `return`
