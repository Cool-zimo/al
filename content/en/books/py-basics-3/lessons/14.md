# Raising errors on purpose

> Not just catching — you can create errors too, to refuse inputs that make no sense.

## Why raise at all

```python
def divide(a, b):
    return a / b

print(divide(10, 0))      # ZeroDivisionError — fine
```

But consider:

```python
def get_price(age):
    if age < 0:
        pass           # ??? what now
    return 100 if age >= 18 else 50
```

**A negative age makes no sense, but Python won't complain** — it silently computes nonsense.

**You need to say "no":**

```python
def get_price(age):
    if age < 0:
        raise ValueError("age can't be negative")
    return 100 if age >= 18 else 50

get_price(-5)      # ValueError: age can't be negative
```

## The basic form

```python
raise ErrorType("a message in plain language")
```

```python
raise ValueError("bad value")
raise TypeError("wrong type")
raise PermissionError("not allowed")
```

**An exception type plus a human-readable message.**

## The common use: validating arguments

```python
def calculate_bmi(weight, height):
    if weight <= 0:
        raise ValueError(f"weight must be positive, got {weight}")
    if height <= 0:
        raise ValueError(f"height must be positive, got {height}")
    return weight / (height ** 2)


print(calculate_bmi(70, 1.75))      # 22.86
print(calculate_bmi(-70, 1.75))     # ValueError: weight must be positive, got -70
```

**Checking arguments at the top of a function is called a precondition check** — a hallmark of professional code.

## raise ends the function

```python
def check(n):
    if n < 0:
        raise ValueError("can't be negative")
    print("this never runs")        # ← nothing after raise executes
    return n * 2

check(-1)      # raises; the function stops here
```

**Like `return`, `raise` exits the function immediately** — but carrying an error.

## Custom exceptions

When the built-ins don't fit, make your own:

```python
class AgeError(Exception):
    pass


def set_age(age):
    if not 0 <= age <= 150:
        raise AgeError(f"age must be 0-150, got {age}")
    print(f"age set to {age}")


try:
    set_age(200)
except AgeError as e:
    print(f"failed: {e}")
```

**A custom exception is just a class inheriting from `Exception`** (classes arrive in lesson 21).

**The benefit:** callers can catch precisely your kind of error:

```python
try:
    set_age(200)
except AgeError:
    print("age problem")          # catches only AgeError
except ValueError:
    print("other value error")    # not triggered by AgeError
```

## Re-raising

Sometimes you want to note the error but let it travel onward:

```python
try:
    risky()
except ValueError as e:
    print(f"[log] error: {e}")
    raise              # ← bare raise re-raises the same exception
```

**A lone `raise` with nothing after it means "throw the current exception again, unchanged".**

**Use:** log it or clean up, then let the caller deal with it.

## Translating an error

```python
try:
    config = json.load(open('c.json'))
except json.JSONDecodeError as e:
    raise ValueError(f"config file is malformed: {e}") from e
```

**`raise ... from e`** preserves the original context — the traceback shows "caused by".

## When should you raise?

| Situation | Suggestion |
|---|---|
| An argument is clearly invalid (negative, empty) | **raise** |
| External data doesn't match expectations | **raise** |
| Just "nothing found" — a normal outcome | return None or empty; don't raise |
| A small problem you can fix yourself | handle it; don't raise |

**Principle: `raise` means "this shouldn't have happened", not "this is unusual".**

```python
# ✅ raise: a negative age is invalid input
if age < 0:
    raise ValueError("age can't be negative")

# ❌ don't raise: "no search results" is a normal outcome
def find(name):
    ...
    return None        # not found is fine
```

## Summary

- `raise Type("message")` throws an error on purpose
- **Commonly used for argument validation** (precondition checks)
- `raise` exits the function immediately
- Custom exceptions inherit from `Exception`
- **A bare `raise`** re-raises the current exception
- Raise only for things that shouldn't happen
