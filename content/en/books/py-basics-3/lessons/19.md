# Packages: folders of modules

> Once you have many modules, organise them into folders. A folder of modules is a package.

## Why packages

```
myapp/
├── main.py
├── database.py
├── api.py
├── models.py
├── utils.py
├── helpers.py
├── validators.py
└── formatters.py
```

**Eight modules lying flat is still a mess.**

**Group by purpose:**

```
myapp/
├── main.py
├── db/
│   ├── database.py
│   └── models.py
├── web/
│   ├── api.py
│   └── validators.py
└── utils/
    ├── helpers.py
    └── formatters.py
```

**That's a package** — a folder grouping related modules.

## A package is a folder (plus a file)

**Since Python 3.3, any folder can act as a package** (no `__init__.py` needed):

```
utils/
├── helpers.py
└── formatters.py
```

```python
import utils.helpers
from utils import formatters
```

**But for compatibility, an `__init__.py` is still conventional** (it can be empty):

```
utils/
├── __init__.py      ← empty is fine
├── helpers.py
└── formatters.py
```

> 💡 **`__init__.py`'s job**: tell Python "this is a package", and optionally run setup code.

## Importing from a package

```python
# full path
import utils.helpers
utils.helpers.do_something()

# from ... import ...
from utils import helpers
helpers.do_something()

# straight to the function
from utils.helpers import do_something
do_something()
```

**All three work** — pick by need.

## What __init__.py can do

**1. Be empty** — most common; just marks the package

```python
# utils/__init__.py
```

**2. Simplify imports** — lift common names to package level:

```python
# utils/__init__.py
from .helpers import format_date
from .formatters import format_money
```

Now callers can write:

```python
from utils import format_date, format_money
# instead of from utils.helpers import format_date
```

**3. Define `__all__`** — control what `from utils import *` brings in:

```python
# utils/__init__.py
__all__ = ['format_date', 'format_money']
```

## Relative versus absolute imports

**Inside a package**, modules can import each other two ways:

```python
# utils/helpers.py

# relative (dots mean "relative to here")
from . import formatters          # same level
from .formatters import fmt       # a specific module, same level
from ..db import models           # one level up

# absolute (spell out the path)
from utils import formatters
from myapp.db import models
```

| | Pros | Cons |
|---|---|---|
| **absolute** | clear, unambiguous | paths hard-coded; renaming the package means editing many files |
| **relative** | renaming the package is harmless | deep nesting gets confusing |

> 💡 **Prefer absolute imports** (clearer); use relative only when writing a reusable library.

## A common mistake

```
myapp/
├── main.py
└── utils/
    └── helpers.py
```

Inside `utils/helpers.py`:

```python
import main        # ❌ may not be found
```

**Why**: Python starts its search from the directory you ran from.

**Run `python main.py` from inside `myapp/`** and that directory is on the path, so `import main` works.

**Run it from anywhere else** and it doesn't.

> ⚠️ **So don't import top-level modules from inside a package** — it creates tangled circular dependencies. Let the top layer import the lower layers, never the reverse.

## A worked example

```
myapp/
├── main.py
├── config.py
└── utils/
    ├── __init__.py
    └── helpers.py
```

```python
# utils/helpers.py
def format_date(d):
    return d.strftime("%Y-%m-%d")
```

```python
# utils/__init__.py
from .helpers import format_date
```

```python
# main.py
from utils import format_date        # lifted by __init__.py
from datetime import date

print(format_date(date.today()))
```

## Package names are namespaces too

```python
import utils.helpers
import web.helpers        # two "helpers", no clash
```

**Packages give you a second level of namespacing** — much clearer than every module lying flat.

## Running a module inside a package

To **run** a module inside a package:

```bash
python -m utils.helpers        # -m runs it as a module
```

**Don't** run `python utils/helpers.py` directly — relative imports break.

## Summary

- **A package is a folder of modules** (usually with `__init__.py`)
- Three import forms: `import pkg.mod` / `from pkg import mod` / `from pkg.mod import fn`
- **`__init__.py` can simplify imports** and define `__all__`
- Prefer **absolute imports**
- Don't import top-level modules from inside a package (circular imports)
