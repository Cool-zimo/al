# Four ways to import

> The same module can be imported several ways. Pick well and your code halves in length.

## Set up a module

Say there's a `tools.py`:

```python
# tools.py
def add(a, b):
    return a + b

def greet(name):
    return f"hello, {name}"

VERSION = "1.0"
```

## Way one: import module

```python
import tools

print(tools.add(1, 2))          # 3
print(tools.greet("Alice"))     # hello, Alice
print(tools.VERSION)            # 1.0
```

**You always prefix with `tools.`**

**Advantage**: **the source is obvious** — no confusion about where things came from.

> 💡 **This is the recommended form.** Reading `tools.add()` tells you instantly which module it's from.

## Way two: import module as alias

```python
import tools as t

print(t.add(1, 2))
```

**Give long module names a short nickname.**

**The classic examples:**

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
```

**These three aliases are industry convention** — everyone writes them, so `np.` is instantly recognised as numpy.

> ⚠️ Don't invent aliases. `import pandas as p` confuses everyone, including you in three months.

## Way three: from module import name

```python
from tools import add, greet

print(add(1, 2))          # no prefix
print(greet("Alice"))
```

**Import just what you need; no prefix when using it.**

**When to use it**: you call that function dozens of times and the prefix gets tiring.

```python
from math import sqrt, pi
print(sqrt(16))         # shorter than math.sqrt(16)
print(pi)
```

## Way four: from module import *

```python
from tools import *        # everything not starting with an underscore

print(add(1, 2))
print(greet("Alice"))
```

> ⚠️ **Strongly discouraged.**

**Why**: you can't tell what got imported, and it easily overwrites names you already have:

```python
from math import *
from numpy import *

print(sqrt(16))        # math's or numpy's? Depends on import order.
```

**Worse:**

```python
def add(a, b):          # your own function
    return a + b

from tools import *     # overwrites your add!
print(add(1, 2))        # actually calls tools.add
```

**Rule: never use `import *`.**

## Comparison

| Form | Call style | Rating |
|---|---|---|
| `import tools` | `tools.add()` | ⭐⭐⭐ **recommended** |
| `import tools as t` | `t.add()` | ⭐⭐⭐ for long names |
| `from tools import add` | `add()` | ⭐⭐ for one hot function |
| `from tools import *` | `add()` | ❌ **don't** |

## Importing several names

```python
from math import sqrt, pi, floor, ceil
```

**Comma-separated**, as many as you like.

## An easy detail to miss

```python
from tools import VERSION

VERSION = "2.0"          # ← this only changes your local name
```

**`from ... import` copies a reference over** — it doesn't create a live link. Changing `VERSION` locally doesn't touch `tools.py`.

Compare:

```python
import tools
tools.VERSION = "2.0"    # ← this really does change the module's value
```

**So to modify a variable inside a module, use `import module`.**

## Import errors

```python
import nonexistent        # ModuleNotFoundError: No module named 'nonexistent'
from tools import nope    # ImportError: cannot import name 'nope'
```

**Two distinct errors:**
- `ModuleNotFoundError` — **the module doesn't exist** (typo, or not installed)
- `ImportError` — the module exists but **doesn't have the name you asked for**

## Circular imports

```python
# a.py
import b

# b.py
import a        # ← importing each other: trouble
```

**Avoid this design.** If you truly need it, move the shared part into a third module.

## Summary

| Form | Use when |
|---|---|
| `import m` | **the default**; source is clear |
| `import m as x` | long names; `np` / `pd` are conventions |
| `from m import f` | one function used constantly |
| `from m import *` | **never** |

  import math as m
  
  # m.pi is 3.14159...
  # round(m.pi, 2) is 3.14

- assert "3.14" in __out
hint: print(round(m.pi, 2)). "import math as m" gives the module a short alias, then you access things via m.
