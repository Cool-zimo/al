# Why files exist

> Your program forgets everything the moment it closes. This lesson explains why — and what a file actually is.

## A discouraging experiment

Write this, run it, type your name:

```python
name = input("What's your name? ")
print("Got it:", name)
```

Now **run it again** with a different name. The program has no idea who you were last time.

```python
# every run starts from scratch
name = input("What's your name? ")
print("Got it:", name)
print("Who was here last time? No idea.")     # variables only live while running
```

**Variables live in memory. When the program ends, that memory is reclaimed.**

## Memory versus disk

| | Memory (RAM) | Disk |
|---|---|---|
| Speed | extremely fast | far slower |
| After power off | **gone** | still there |
| Size | small (GBs) | large (hundreds of GBs) |
| In your program | variables | files |

**A variable's lifetime is the program's lifetime. A file's lifetime is "until you delete it".**

So to make data survive a restart, you must move it from memory to disk — **that's file I/O**.

## A file is just a sequence of bytes

Don't overthink it. **A file is essentially a run of data on disk**, nothing more.

```python
# a text file stores characters
# "hello\nworld" is stored as those letters plus a newline
```

Extensions (`.txt` `.csv` `.json` `.py`) are **labels for humans and the OS** — they don't change the fact that it's data.

> 💡 You can open a `.py` file in Notepad, and you can read a `.txt` file with Python. **Extensions are convention, not magic.**

## The smallest possible example

```python
# write: move something from memory to disk
with open('note.txt', 'w', encoding='utf-8') as f:
    f.write("Today I learned file I/O")

# read: move it back from disk to memory
with open('note.txt', 'r', encoding='utf-8') as f:
    content = f.read()

print("The file says:", content)
```

**Run it twice.** The first run writes; the second reads. Run it a day later and the text is still there.

**That's persistence — data outliving the program that made it.**

## Two terms to meet now

They'll come up constantly, so get familiar:

- **encoding**: how characters are stored on disk. `utf-8` is the modern default and handles every language. **Always pass `encoding='utf-8'` when you open a file.**
- **path**: where the file lives on disk, e.g. `note.txt` (current directory) or `C:/Users/me/note.txt` (full path).

## A trap you'll meet immediately

```python
# ❌ may fail on Windows files containing non-ASCII text
with open('note.txt', 'r') as f:
    ...

# ✅ state the encoding
with open('note.txt', 'r', encoding='utf-8') as f:
    ...
```

**Why?** On Windows Python defaults to the system encoding (often cp1252 or GBK), while the file is probably UTF-8. Mismatch means mojibake or an error.

**Make it a habit: every `open` gets `encoding='utf-8'`.** Lesson 02 covers this properly.

## Summary

- Variables live in memory and vanish when the program ends; files live on disk and survive
- **A file is just data**; the extension is only a label
- `open()` opens a file; read or write; then close it
- **Always pass `encoding='utf-8'`**
