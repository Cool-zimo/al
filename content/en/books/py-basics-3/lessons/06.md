# with: never write close() again

> Forgetting `close()` is the most common file mistake. `with` makes it impossible.

## The problem: close() gets forgotten

```python
f = open('note.txt', 'w', encoding='utf-8')
f.write("important data")
# ... if anything raises here, the line below never runs
f.close()
```

**Any error in between means `close()` never executes** — data may be lost and the file stays locked.

Worse, **plainly forgetting** it is extremely common:

```python
def save(data):
    f = open('data.txt', 'w', encoding='utf-8')
    f.write(data)
    # forgot close()
    return "saved"    # in truth it may still be sitting in a buffer
```

## How with looks

```python
with open('note.txt', 'w', encoding='utf-8') as f:
    f.write("important data")

# by here the file is already closed
print("file closed")
```

**The shape:**

```python
with open(...) as name:
    do things with name
# dedent → closed automatically
```

**When Python leaves the `with` block, the file is guaranteed closed** — even if the block raised.

## Why is that guaranteed?

Behind `with` sits something called a context manager. Simply:

1. Entering the block runs the setup (open the file)
2. **Whether the block ends normally or raises**, the teardown runs (close the file)

```python
with open('a.txt', 'w', encoding='utf-8') as f:
    f.write("data")
    raise ValueError("boom!")     # deliberately raising

# even so, the file is closed
```

**That's the value of `with`: handing "must always happen" to the language instead of your memory.**

## Prove it

```python
f = open('t.txt', 'w', encoding='utf-8')
with f:
    f.write("content")
    print("inside, closed?", f.closed)      # False

print("outside, closed?", f.closed)         # True
```

**`f.closed`** is an attribute on the file object: True means closed.

## Two files at once

```python
with open('src.txt', 'r', encoding='utf-8') as src, \
     open('dst.txt', 'w', encoding='utf-8') as dst:
    dst.write(src.read())
```

**One `with` line opens both** — that's all copying a file takes.

Or, on Python 3.9+:

```python
with (
    open('src.txt', 'r', encoding='utf-8') as src,
    open('dst.txt', 'w', encoding='utf-8') as dst,
):
    dst.write(src.read())
```

## Practice: copying files

```python
# copy text
with open('a.txt', 'r', encoding='utf-8') as src, \
     open('b.txt', 'w', encoding='utf-8') as dst:
    dst.write(src.read())

# copy an image (binary)
with open('photo.jpg', 'rb') as src, \
     open('copy.jpg', 'wb') as dst:
    dst.write(src.read())
```

**Copying line by line** avoids loading a big file into memory:

```python
with open('big.txt', 'r', encoding='utf-8') as src, \
     open('copy.txt', 'w', encoding='utf-8') as dst:
    for line in src:
        dst.write(line)
```

## with isn't only for files

**Anything that needs guaranteed cleanup fits `with`:**

```python
# a database connection
with connect() as conn:
    conn.execute(...)
# disconnected automatically

# a thread lock
with lock:
    update shared data
# released automatically
```

For now: **opening a file means using `with`.**

## Comparison

| Style | Can you forget? | On error |
|---|---|---|
| `f = open(); ...; f.close()` | **easily** | never closes |
| `with open() as f:` | **impossible** | closes anyway |

**Conclusion: always use `with`.** Hand-written `open()` + `close()` is only for rare cases where you must hold the file open a long time.

## Summary

- **`with open(...) as f:`** — closes when you leave the block
- **Guaranteed even on error** (which hand-written close can't promise)
- One line can open several files
- **Copy big files line by line**
- Opening a file should make you think "with", not "close"
