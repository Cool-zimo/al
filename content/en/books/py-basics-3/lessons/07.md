# Paths: relative and absolute

> "File not found" is the most common beginner error. Nine times out of ten it's a path misunderstanding.

## Two kinds

```python
# relative: start from the current directory
open('note.txt')

# absolute: from the drive / root, spelled out
open('C:/Users/me/note.txt')        # Windows
open('/home/me/note.txt')           # macOS / Linux
```

**Relative** is "in the next room"; **absolute** is "12 Baker Street, London".

## Relative to what, exactly?

**To the current working directory** — the directory you were in when you ran the program.

```python
import os
print(os.getcwd())      # current working directory
```

**This is where it bites:**

```
project/
├── main.py
└── data.txt
```

Run `python main.py` from inside `project/` and `open('data.txt')` works.

But run `python project/main.py` from somewhere else and **the current directory changed** — `open('data.txt')` fails!

> ⚠️ **Relative paths depend on where you run, not where the code file lives.** That's the root of every "the file is right there but Python can't find it".

## The separator trap

Windows uses backslashes, macOS/Linux forward slashes.

```python
# ❌ in a Python string \n is a newline and \t a tab
open('C:\new\table.txt')      # interpreted as something bizarre
```

**Three fixes:**

```python
# ① forward slashes (recommended — Windows accepts them)
open('C:/new/table.txt')

# ② escape the backslashes
open('C:\\new\\table.txt')

# ③ raw string (prefix r)
open(r'C:\new\table.txt')
```

> 💡 **Always use forward slashes `/`** — Python handles them on Windows and you avoid escaping entirely.

## Joining paths: os.path.join

**Don't concatenate strings:**

```python
# ❌ easy to end up with a doubled or missing slash
path = folder + '/' + filename

# ✅ let os.path.join do it
import os
path = os.path.join(folder, filename)
```

**`os.path.join` uses whichever separator the current OS wants:**

```python
import os
print(os.path.join('data', 'log', 'app.txt'))
# Windows: data\log\app.txt
# macOS/Linux: data/log/app.txt
```

**Essential for cross-platform code.**

## pathlib: the modern way

Python 3.4+ offers `pathlib`, where paths are objects joined with `/`:

```python
from pathlib import Path

p = Path('data') / 'log' / 'app.txt'
print(p)

# reading and writing too
p.write_text("content", encoding='utf-8')
print(p.read_text(encoding='utf-8'))
```

| Need | os.path | pathlib |
|---|---|---|
| join | `os.path.join('a','b')` | `Path('a') / 'b'` |
| exists | `os.path.exists(p)` | `p.exists()` |
| read text | `open(p).read()` | `p.read_text()` |
| write text | `open(p,'w').write(s)` | `p.write_text(s)` |

**Both work; `pathlib` is newer and reads better.** This lesson shows both — pick whichever you prefer.

## Common checks

```python
import os

p = 'data.txt'

print(os.path.exists(p))      # does it exist (file or folder)
print(os.path.isfile(p))      # is it a file
print(os.path.isdir(p))       # is it a folder
print(os.path.getsize(p))     # size in bytes
```

**`exists` versus `isfile`:**

- `exists('data')` → True if anything named data is there (file *or* folder)
- `isfile('data')` → True only if it's a **file**

**Use `isfile` before reading** — "it exists but it's a folder" still fails to open.

## Getting information

```python
import os

print(os.path.basename('data/log/app.txt'))    # 'app.txt'   the file name
print(os.path.dirname('data/log/app.txt'))     # 'data/log'  the directory part
print(os.path.splitext('app.txt'))             # ('app', '.txt')  split extension
```

**`splitext` is handy for filtering or renaming:**

```python
name, ext = os.path.splitext('photo.jpg')
print(ext)        # '.jpg'

if ext.lower() in ('.jpg', '.png', '.gif'):
    print("it's an image")
```

## Practice: reading safely

```python
import os

def read_file(path):
    """Read a file, returning None if it can't be read."""
    if not os.path.isfile(path):
        print(f"no such file: {path}")
        return None
    with open(path, 'r', encoding='utf-8') as f:
        return f.read()


content = read_file('data.txt')
if content:
    print(content)
```

**Check first, then open** — a very common pattern.

## Summary

| Concept | Meaning |
|---|---|
| relative path | relative to the **current working directory** (where you ran) |
| absolute path | spelled out from the drive / root |
| separator | **always use `/`**, never `\` |
| joining | `os.path.join()` or pathlib's `/` |
| checks | `exists` / `isfile` / `isdir` |
