# open() and the three modes

> Opening a file is one step, but "how you open it" decides what you can do — and what you might destroy.

## The basic shape of open()

```python
f = open('note.txt', 'r', encoding='utf-8')
content = f.read()
f.close()          # ← don't forget this
print(content)
```

**Three arguments:**

| Argument | Meaning |
|---|---|
| first | the file path |
| second | the mode (how to open it) |
| `encoding` | text encoding (strongly recommended always) |

**`open()` returns a file object** that you read from or write to. You must `close()` it when done.

## The three modes you'll use constantly

| Mode | Means | If file missing | Wipes existing content? |
|---|---|---|---|
| `'r'` | **read** | **raises** FileNotFoundError | no |
| `'w'` | **write** | creates it | **yes!** wiped on open |
| `'a'` | **append** | creates it | no, added at the end |

> ⚠️ **`'w'` is the dangerous one.** The moment you open, everything already there is erased — **even if you never write anything.**

```python
# ❌ after this line, note.txt is already empty!
f = open('note.txt', 'w', encoding='utf-8')
# forget to f.write(...) and the data is gone
```

**Remember**: `'a'` to keep what's there, `'w'` only when you truly want to overwrite.

## Feel the difference

```python
# set up a file
with open('demo.txt', 'w', encoding='utf-8') as f:
    f.write("first line\n")

# 'a' appends: new content goes at the end
with open('demo.txt', 'a', encoding='utf-8') as f:
    f.write("second line\n")

# 'r' reads: see what's there now
with open('demo.txt', 'r', encoding='utf-8') as f:
    print(f.read())
```

```
first line
second line
```

**Swap `'a'` for `'w'`** and only "second line" remains — the first was wiped on open.

## Reading a file that isn't there raises

```python
f = open('no_such_file.txt', 'r', encoding='utf-8')
# FileNotFoundError: [Errno 2] No such file or directory: 'no_such_file.txt'
```

**That's good** — it tells you plainly "this file doesn't exist" rather than silently giving you emptiness.

Lesson 12 shows how to handle it gracefully with `try/except`.

## Two more modes worth knowing

| Mode | Means |
|---|---|
| `'r+'` | read and write (file must exist) |
| `'x'` | create and write; **raises if the file already exists** (prevents accidental overwrite) |

`'x'` is useful when you must not clobber something:

```python
# raises if log.txt already exists, so you can't wipe it by accident
with open('log.txt', 'x', encoding='utf-8') as f:
    f.write("fresh log")
```

## Text mode versus binary mode

Everything above is **text mode** (the default): you read and write strings.

Add `b` for **binary mode**, which reads and writes bytes:

```python
# binary read (required for images, audio, video)
with open('photo.jpg', 'rb') as f:
    data = f.read()

# binary write
with open('copy.jpg', 'wb') as f:
    f.write(data)
```

> 💡 **To copy an image, audio or video file, you must use `'rb'` / `'wb'`.** Text mode corrupts them.

**Don't pass `encoding` in binary mode** — bytes have no encoding.

## What happens if you forget close()

```python
f = open('note.txt', 'w', encoding='utf-8')
f.write("important data")
# never closed
```

Consequences:
1. **The data may never reach disk** (Python buffers writes and flushes in batches)
2. The file stays locked and other programs can't open it
3. Long-running programs run out of file handles

**So always `close()`** — or use the `with` statement from lesson 06, which does it for you.

## Summary

- **`'r'` read**: raises if the file is missing
- **`'w'` write**: **wipes existing content** — dangerous
- **`'a'` append**: adds at the end — safe
- Use `'rb'` / `'wb'` for images and other binary files
- **Always `close()`**, or buffered data may be lost
