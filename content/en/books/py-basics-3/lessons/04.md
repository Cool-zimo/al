# Writing and newlines

> Reading brings data in; writing sends it out. This lesson covers writing, and the mistake everyone makes.

## The simplest write

```python
with open('note.txt', 'w', encoding='utf-8') as f:
    f.write("Today I learned file writing")
```

**`write()` takes a string and puts it in the file.**

**Note: `write()` does not add a newline.**

```python
with open('a.txt', 'w', encoding='utf-8') as f:
    f.write("line one")
    f.write("line two")
    f.write("line three")
```

What you get:

```
line oneline twoline three
```

**Three writes collapsed into one line** — because you never wrote `\n`.

## You must add newlines yourself

```python
with open('a.txt', 'w', encoding='utf-8') as f:
    f.write("line one\n")
    f.write("line two\n")
    f.write("line three\n")
```

Now it really is three lines.

> 💡 **`write()` is not `print()`**: `print()` adds a newline by default; `write()` writes exactly the string you gave, not one character more.

## write() returns something

```python
with open('a.txt', 'w', encoding='utf-8') as f:
    n = f.write("hi")
    print(n)      # 2
```

**It returns the number of characters written.**

(In binary mode it returns the number of bytes.)

## Many lines at once: writelines()

```python
lines = ["line one\n", "line two\n", "line three\n"]

with open('a.txt', 'w', encoding='utf-8') as f:
    f.writelines(lines)
```

**`writelines()` takes a list of strings** and writes them one after another.

> ⚠️ **The name misleads: it doesn't add newlines either!** Every string in the list must carry its own `\n`.

```python
# ❌ these collapse onto one line
f.writelines(["one", "two", "three"])

# ✅ correct
f.writelines(["one\n", "two\n", "three\n"])

# ✅ or add them on the fly
f.writelines(line + "\n" for line in ["one", "two", "three"])
```

## Strings only

```python
# ❌ TypeError: write() argument must be str, not int
f.write(42)

# ✅ convert first
f.write(str(42))
f.write(f"count: {42}")      # an f-string is nicer
```

**Converting types is routine when writing files**, and f-strings are the smoothest way:

```python
name, score = "Alice", 95
with open('report.txt', 'w', encoding='utf-8') as f:
    f.write(f"{name} scored {score}\n")
```

## Appending: mode 'a'

Covered before, worth reviewing:

```python
# every run adds a line; the history survives
with open('log.txt', 'a', encoding='utf-8') as f:
    f.write("the program ran once\n")
```

**That's the basic idea behind logging.**

## When does it actually reach the disk?

**Python buffers writes.** After `write()`, data may still sit in a memory buffer.

Three things force it out:

1. **Closing the file** (`close()` or leaving a `with` block)
2. **The buffer filling up**
3. **Calling `flush()`**

```python
f = open('a.txt', 'w', encoding='utf-8')
f.write("important data")
f.flush()      # push to disk now (file still open)
# ... keep writing
f.close()
```

> ⚠️ **If the program crashes before `close()`, unflushed data can be lost.**  
> That's why **`with` is strongly recommended** (lesson 06) — it guarantees the close.

## Practice: saving what the user typed

```python
name = input("Name: ")
score = input("Score: ")

with open('students.txt', 'a', encoding='utf-8') as f:
    f.write(f"{name},{score}\n")

print("saved")
```

**This little program has memory** — each run adds a record and previous ones survive.

(Comma-separated values like this are called CSV; lesson 09 covers it.)

## Summary

| Need | Write |
|---|---|
| Write a string | `f.write("text")` |
| **Newline** | **you must add `\n` yourself** |
| Many lines | `f.writelines(list)` (each still needs `\n`) |
| Numbers | `str(42)` or an f-string |
| Append | mode `'a'` |
| Force to disk | `f.flush()` |
