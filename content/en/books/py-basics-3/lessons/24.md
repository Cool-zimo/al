# Methods and attribute control

> A few techniques that make classes much nicer: `__str__`, default arguments, `property`.

## __str__: make print readable

```python
class Dog:
    def __init__(self, name):
        self.name = name

d = Dog("Rex")
print(d)        # <__main__.Dog object at 0x000001...>
```

**The default output is useless.** Add `__str__`:

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def __str__(self):
        return f"dog: {self.name}"

d = Dog("Rex")
print(d)        # dog: Rex
```

**`__str__` decides "what string this object becomes"** — used by `print()`, `str()` and f-strings.

> 💡 **Make `__str__` a habit** — debugging shows something meaningful instead of a memory address.

## __repr__: for developers

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def __str__(self):
        return f"dog: {self.name}"

    def __repr__(self):
        return f"Dog(name='{self.name}', age={self.age})"

d = Dog("Rex", 3)
print(str(d))        # dog: Rex                       ← for users
print(repr(d))       # Dog(name='Rex', age=3)         ← for developers
```

**The difference:**
- `__str__`: **for users**, friendly
- `__repr__`: **for developers**, ideally showing how to rebuild the object

Objects inside a list print via `__repr__`:

```python
dogs = [Dog("Rex", 3), Dog("Snow", 5)]
print(dogs)
# [Dog(name='Rex', age=3), Dog(name='Snow', age=5)]
```

> 💡 If you only write one, write `__repr__` — `__str__` falls back to it.

## Default arguments

```python
class Dog:
    def __init__(self, name, age=0, color="black"):
        self.name = name
        self.age = age
        self.color = color

d1 = Dog("Rex")                        # age=0, color="black"
d2 = Dog("Snow", 5)                    # color="black"
d3 = Dog("Goldie", 2, "golden")
```

**Like methods, parameters can have defaults** — much more flexible.

> ⚠️ **Never use a mutable default:**

```python
# ❌ same trap as the class attribute
def __init__(self, name, tricks=[]):
    self.tricks = tricks      # every instance shares one list!

# ✅ use None as a sentinel
def __init__(self, name, tricks=None):
    self.tricks = tricks if tricks is not None else []
```

## Returning self: chained calls

```python
class Counter:
    def __init__(self):
        self.value = 0

    def add(self, n):
        self.value += n
        return self          # ← return yourself

    def show(self):
        print(self.value)
        return self

c = Counter()
c.add(1).add(2).add(3).show()      # 6
```

**`return self` lets calls chain** — the style jQuery and pandas use.

## property: a method that looks like an attribute

**The problem**: you want validation on assignment.

```python
class Student:
    def __init__(self, name):
        self.name = name
        self.score = 0

s = Student("Alice")
s.score = 999        # ❌ scores shouldn't exceed 100, but nothing stops it
```

**Option one: methods** (clumsy to use)

```python
class Student:
    def set_score(self, value):
        if not 0 <= value <= 100:
            raise ValueError("score must be 0-100")
        self._score = value

    def get_score(self):
        return self._score

s.set_score(95)
print(s.get_score())
```

**Option two: `@property`** (better)

```python
class Student:
    def __init__(self, name):
        self.name = name
        self._score = 0

    @property
    def score(self):
        return self._score

    @score.setter
    def score(self, value):
        if not 0 <= value <= 100:
            raise ValueError("score must be 0-100")
        self._score = value


s = Student("Alice")
s.score = 95          # ← looks like plain attribute assignment
print(s.score)        # 95
s.score = 999         # ValueError: score must be 0-100
```

**It reads like an attribute but runs your checks** — the best of both.

**The three decorators:**

```python
class C:
    @property
    def x(self):          # read
        return self._x

    @x.setter
    def x(self, value):   # write
        self._x = value

    @x.deleter
    def x(self):          # delete
        del self._x
```

## Read-only properties

**Write only the getter** and it's read-only:

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2


c = Circle(5)
print(c.area)        # 78.54
c.area = 100         # ❌ AttributeError: can't set attribute
```

**Area is derived and shouldn't be assigned** — a read-only property fits perfectly.

## A complete class

```python
class BankAccount:
    """A bank account"""

    bank_name = "Python Bank"        # class attribute

    def __init__(self, owner, balance=0):
        self.owner = owner
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")
        self._balance += amount

    def withdraw(self, amount):
        if amount > self._balance:
            raise ValueError("insufficient funds")
        self._balance -= amount

    def __str__(self):
        return f"{self.owner}'s account: {self._balance}"

    def __repr__(self):
        return f"BankAccount(owner='{self.owner}', balance={self._balance})"


acc = BankAccount("Alice", 100)
acc.deposit(50)
print(acc)              # Alice's account: 150
print(acc.balance)      # 150 (read-only)
```

**Uses**: class attribute, instance attributes, `property`, validation, `__str__`, `__repr__`.

## Summary

| Technique | Purpose |
|---|---|
| `__str__` | what `print(obj)` shows (for users) |
| `__repr__` | a developer-facing representation |
| default args | `def __init__(self, name, age=0)` |
| `return self` | enables chaining |
| `@property` | looks like an attribute, runs your logic |
| read-only | getter only, no setter |
