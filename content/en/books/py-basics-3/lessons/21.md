# Why classes exist

> Functions package operations, but what about the data? A class packages **data and operations together**.

## Start with something that gets messy

Representing a student with a dict:

```python
student = {
    'name': 'Alice',
    'age': 18,
    'scores': [80, 90, 85]
}
```

Plus some functions:

```python
def get_average(student):
    return sum(student['scores']) / len(student['scores'])

def add_score(student, score):
    student['scores'].append(score)

def is_adult(student):
    return student['age'] >= 18
```

**In use:**

```python
s = {'name': 'Alice', 'age': 18, 'scores': []}
add_score(s, 90)
print(get_average(s))
```

## What's wrong with that

**1. Data and operations are separate**

`s` and `add_score(s, ...)` are linked only by convention — you must remember which keys the dict should have.

**2. Key typos are easy**

```python
student['score'] = 90        # ❌ should be 'scores'
# no error, just silently wrong data
```

**3. Every function repeats the `student` parameter**

`add_score(student, ...)`, `get_average(student)`, `is_adult(student)`…

**4. There's no notion of type**

```python
def add_score(student, score):
    ...
```

What shape is `student`? You can only guess or read the docs.

## How a class fixes it

**Bundle data and operations into one thing:**

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age
        self.scores = []

    def add_score(self, score):
        self.scores.append(score)

    def average(self):
        return sum(self.scores) / len(self.scores)

    def is_adult(self):
        return self.age >= 18
```

**In use:**

```python
s = Student('Alice', 18)
s.add_score(90)
s.add_score(85)
print(s.average())        # 87.5
print(s.is_adult())       # True
```

| | dict + functions | class |
|---|---|---|
| call | `add_score(s, 90)` | `s.add_score(90)` |
| where's the data | scattered in a dict | **inside the object** |
| typo'd key | silent corruption | **AttributeError** |
| shape | documented by convention | **written in the class** |

## Three core ideas

| Idea | What it is | Analogy |
|---|---|---|
| **class** | a template / blueprint | the architect's drawing |
| **object** | a concrete thing built from it | one house built from the drawing |
| **instance** | another word for object | same thing |

```python
class Student:          # ← the class (drawing)
    ...

s1 = Student('Alice', 18)   # ← an object
s2 = Student('Bob', 19)     # ← another object
```

**One class can make endless objects.** Each has its own data but shares the same methods.

## What's inside a class

- **attribute**: **data** the object holds (a variable)
- **method**: something the object **can do** (a function)

**Inside a class, functions are called methods** — same thing, different name.

## When should you use a class?

| Situation | Suggestion |
|---|---|
| One or two values plus simple work | plain functions are fine |
| **A set of data plus related operations** | **use a class** |
| You need several things of the same shape | **use a class** |
| You want to express "this is a X" | **use a class** |

**The signal**: if your functions **all take the same data structure**, it's time for a class.

```python
# signal: every function takes student
def a(student): ...
def b(student): ...
def c(student): ...

# → a class
student.a()
student.b()
student.c()
```

## A homely example

**Without a class:**

```python
car = {'brand': 'Toyota', 'speed': 0, 'fuel': 100}

def accelerate(car):
    car['speed'] += 10
    car['fuel'] -= 5
```

**With one:**

```python
class Car:
    def __init__(self, brand):
        self.brand = brand
        self.speed = 0
        self.fuel = 100

    def accelerate(self):
        self.speed += 10
        self.fuel -= 5


my_car = Car('Toyota')
my_car.accelerate()
print(my_car.speed)      # 10
```

**"The car accelerates" reads far better than "perform the accelerate operation on the car."**

## Summary

- **Class = blueprint; object = a thing built from it**
- A class bundles **data (attributes) with operations (methods)**
- Benefits: clear structure, typos raise, no passing the same argument everywhere
- **Signal**: many functions taking the same data structure → use a class
