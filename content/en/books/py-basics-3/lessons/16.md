# Why modules exist

> What happens when one file holds 2000 lines? Nothing good. Modules are simply "code split across files".

## The problem with one big file

Say you wrote a small tool that kept growing:

```python
# app.py — now 800 lines
def read_config(): ...
def connect_db(): ...
def add_task(): ...
def show_tasks(): ...
def delete_task(): ...
def format_date(): ...
def validate_email(): ...
# ...30 more functions

while True:
    ...
```

**The problems:**
1. **Finding things is hard** — changing `validate_email` means scrolling forever
2. **Name clashes** — two features both want to call something `parse()`
3. **No reuse** — using `format_date` in another project means copy-paste
4. **Hard to collaborate** — two people editing one file guarantees conflicts

## A module is just a .py file

**In Python, one `.py` file is one module.**

```
project/
├── app.py           ← the main program (also a module)
├── config.py        ← configuration
├── database.py      ← database work
└── utils.py         ← general helpers
```

**Each file owns one area**, and they import each other as needed.

## Bringing a module in with import

```python
# app.py
import utils

utils.format_date(...)      # call a function from utils
```

**That's it** — `import module_name`, then `module_name.function()`.

## Three levels

| Level | What it is | Example |
|---|---|---|
| **module** | one `.py` file | `utils.py` |
| **package** | a **folder** of modules | `utils/` |
| **library** | a collection of packages | requests, pandas |

**For now: module = one .py file.**

## Three sources of modules

```python
import math                 # ① standard library (ships with Python)
import pandas as pd         # ② third party (installed with pip)
import my_utils             # ③ one you wrote
```

**This chapter covers all three.**

## Start with the standard library

Python ships with a huge number of modules — **install nothing**:

```python
import math
print(math.pi)              # 3.141592653589793
print(math.sqrt(16))        # 4.0

import random
print(random.randint(1, 10))    # a random int from 1 to 10

import datetime
print(datetime.date.today())    # today's date
```

> 💡 **A big advantage of Python is how complete its standard library is.** Check there first before reaching for a third-party package.

## An important idea: namespaces

```python
import math

pi = 3        # your own variable
print(pi)         # 3
print(math.pi)    # 3.14159...
```

**`math.pi` and your `pi` are unrelated** — they don't interfere.

**That's part of a module's value** — it gives code a surname (`math.`) so names don't collide.

## Another benefit: caching

```python
import math
import math        # the second import doesn't re-run anything
import math        # nor do the rest
```

**Python executes a module's code exactly once**, then reuses it.

(So a `print` inside a module prints only once, however many times you import it.)

## Summary

- **A module is one `.py` file**
- Splitting big programs: **easier to find things, no clashes, reusable, collaboration-friendly**
- `import name` → use `name.function()`
- Three sources: standard library, third party, your own
- **Modules provide namespaces** so names don't collide
