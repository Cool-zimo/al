# What an exception is

> Your program doesn't grit its teeth when you make a mistake — it stops and tells you. That stopping-and-telling is an exception.

## You've met them already

```python
print(10 / 0)          # ZeroDivisionError: division by zero
print(int("abc"))      # ValueError: invalid literal for int()
print("abc"[10])       # IndexError: string index out of range
print(undefined_name)  # NameError: name 'undefined_name' is not defined
```

**That red text isn't "your program is broken" — it's Python telling you precisely what went wrong.**

## Three parts of an exception

```python
numbers = [1, 2, 3]
print(numbers[5])
```

```
Traceback (most recent call last):
  File "demo.py", line 2, in <module>
    print(numbers[5])
IndexError: list index out of range
```

**Three parts:**

1. **Traceback**: the call stack — how you got here
2. **Location**: `File "demo.py", line 2` — which file, which line
3. **Type and message**: `IndexError: list index out of range`

> 💡 **Read a traceback from the bottom.** The last line says what actually went wrong; everything above is how you got there.

## Common exception types

| Exception | When | Example |
|---|---|---|
| `SyntaxError` | **invalid syntax** (code never ran) | `if x = 1:` |
| `NameError` | name never defined | `print(abc)` |
| `TypeError` | wrong type | `"1" + 1` |
| `ValueError` | right type, bad value | `int("abc")` |
| `IndexError` | index out of range | `lst[100]` |
| `KeyError` | key not in the dict | `d['missing']` |
| `ZeroDivisionError` | division by zero | `10 / 0` |
| `FileNotFoundError` | no such file | `open('nope.txt')` |
| `AttributeError` | object has no such attribute | `"abc".push()` |

**Learn these names** — `except` catches them by name.

## SyntaxError is special

```python
# ❌ this never even runs
if x = 1:
    print("x")
```

**`SyntaxError` happens before running** — Python can't parse your code.

> ⚠️ **`SyntaxError` cannot be caught by `try/except`**, because the code never executes. Every other exception can.

## Exceptions interrupt

```python
print("step one")
print(10 / 0)          # crashes here
print("step two")      # ← never runs
```

**Once an exception happens and nobody handles it, the program stops right there** — everything below is skipped.

That's why `try/except` exists: **let the program stop gracefully at the right point instead of falling over entirely.**

## Why the type matters

```python
int("abc")     # ValueError  — right type (a string), bad value
"1" + 1        # TypeError   — wrong type entirely
```

**This distinction is useful:**

- `ValueError` → inspect your data's content
- `TypeError` → inspect your data's type

**The exception type is itself a debugging clue.**

## An attitude worth adopting

**An error isn't Python telling you you're wrong — it's Python helping you.**

| Language | What happens on error |
|---|---|
| some languages | silently produce a wrong answer you discover weeks later |
| **Python** | **stops immediately and points at the exact line** |

**Crashing is vastly better than quietly computing the wrong thing.** So when you see red, **don't panic — read the last line.**

## Summary

- **An exception is how a program stops and reports a problem**
- **Read tracebacks from the bottom**
- `SyntaxError` happens before running and can't be caught
- Exceptions interrupt the program — hence `try/except`
- **Errors help you; they don't scold you**
