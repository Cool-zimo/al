# Selection Models: QItemSelectionModel for Tracking and Reacting to Selection

> The user clicked a row — how do you know? A view's selection state is actually owned by a dedicated class: `QItemSelectionModel`. It answers three questions: "which index is current?", "which rows are selected?", and "who should be told when the selection changes?"

## The Selection Model Is a Built-In Member of Every View

**Every view has a `selectionModel()`. You do not need to instantiate one — just grab it.**

```python
selection_model = view.selectionModel()
current = selection_model.currentIndex()     # The index where the cursor is sitting
```

**This index lives in proxy-coordinate space if your view sits behind a proxy.** To get the source row, use `proxy.mapToSource`.

## Three Selection Modes

**Set them with `view.setSelectionMode()`:**

| Mode | Meaning |
|---|---|
| `QAbstractItemView.NoSelection` | Nothing can be selected |
| `SingleSelection` | Exactly one item |
| `ExtendedSelection` | Multiple with Ctrl / Shift (the default) |
| `MultiSelection` | Each click toggles selection, no Ctrl needed |
| `ContiguousSelection` | A continuous range |

```python
view.setSelectionMode(QAbstractItemView.ExtendedSelection)   # Allow Ctrl/Shift multi-select
view.setSelectionBehavior(QAbstractItemView.SelectRows)     # Click one cell, select the whole row
```

**`SelectionMode` governs "can I select more than one?", while `SelectionBehavior` governs "what actually gets selected when I click a cell?".** They are independent axes and are commonly paired together.

## Selection-Change Signals

**This is the most useful part of a selection model — you get a signal the moment the selection changes.**

```python
selection_model = view.selectionModel()

selection_model.currentChanged.connect(on_current_changed)
selection_model.selectionChanged.connect(on_selection_changed)

def on_current_changed(current, previous):
    # current is the new current index; previous is the one before it
    print("Current row:", current.row(), "col:", current.column())

def on_selection_changed(selected, deselected):
    # selected and deselected are QItemSelection objects (ranges of indexes)
    for index in selected.indexes():
        print("Newly selected:", index.row(), index.column())
    for index in deselected.indexes():
        print("Deselected:", index.row(), index.column())
```

**`currentChanged` means "the cursor moved somewhere"; `selectionChanged` means "these cells entered or left the selection set".** They are not the same: you can move the cursor with the arrow keys without changing the selection, in which case only `currentChanged` fires.

## Crash Site 1: Confusing currentChanged with selectionChanged, Logic Goes Sideways

**Symptom: you want "load the detail panel when a row is selected", but you connect `currentChanged`, so every arrow-key preview also triggers a (possibly expensive) detail load.**

```python
# ❌ Using currentChanged to load details
selection_model.currentChanged.connect(load_detail_from_server)  # Fires on every keypress
```

**✅ Fix: use `selectionChanged`, which fires only when something is truly selected; or debounce inside `currentChanged`.**

```python
# The requirement is "a row is selected"
selection_model.selectionChanged.connect(on_selection_changed)

def on_selection_changed(selected, deselected):
    indexes = selected.indexes()
    if not indexes:
        return
    current = indexes[0]
    load_detail(current.row())
```

**You can also test `hasSelection()` to confirm there really is a selection:**

```python
if selection_model.hasSelection():
    selected_rows = selection_model.selectedRows()   # Returns the selected rows (col 0 indexes)
```

## Selecting and Deselecting Programmatically

**You can also select a row from your own code:**

```python
# Select row 2 (entire row)
row_index = model.index(2, 0)
selection_model.select(row_index, QItemSelectionModel.Select | QItemSelectionModel.Rows)

# Clear the selection
selection_model.clearSelection()

# Set the current item without highlighting it
selection_model.setCurrentIndex(row_index, QItemSelectionModel.NoUpdate)
```

**The second argument to `select` is a combination of command flags. The common ones:**

| Flag | Meaning |
|---|---|
| `Select` | Add to the selection |
| `Deselect` | Remove from the selection |
| `Toggle` | Toggle |
| `Clear` | Clear first, then operate |
| `Rows` | Whole rows |
| `Columns` | Whole columns |
| `Current` | Also make it the current item |

**Combining them is common: `QItemSelectionModel.ClearAndSelect | QItemSelectionModel.Rows` means "clear first, then select this whole row".**

## Crash Site 2: Using a Proxy Index Directly, Row Numbers Do Not Match

**Symptom: the view sits behind a proxy, and you use `currentIndex().row()` to read from the source model — you get the wrong row.**

```python
proxy_idx = view.currentIndex()         # Proxy coordinates
row = proxy_idx.row()                  # Say, 0 — the 0th row after filtering
data = source_model._rows[row]         # ❌ The row number is wrong
```

**✅ Fix: `mapToSource`.**

```python
proxy_idx = view.currentIndex()
source_idx = proxy.mapToSource(proxy_idx)
real_row = source_idx.row()
data = source_model._rows[real_row]
```

**Any time a view sits behind a proxy, an index obtained from the view must be converted with `mapToSource` before being fed to the source model.** This is a universal rule of the proxy world.

## Crash Site 3: Modifying the Selection Inside selectionChanged, Infinite Recursion

**Symptom: you want to auto-select related rows whenever the selection changes, and the program freezes or warns about "recursive selection".**

```python
def on_selection_changed(selected, deselected):
    for idx in selected.indexes():
        # ❌ Modifying the selection inside the callback fires a new selectionChanged
        selection_model.select(idx, QItemSelectionModel.Select)
```

**Root cause: `select()` fires `selectionChanged` again, which calls your handler again, which calls `select()` again...**

**✅ Fix: use `blockSignals` to suppress signals temporarily, or only modify when genuinely needed.**

```python
def on_selection_changed(selected, deselected):
    selection_model.blockSignals(True)
    try:
        # Your bulk-selection work goes here
        pass
    finally:
        selection_model.blockSignals(False)
```

**`blockSignals` is Qt's general-purpose "temporarily silence signals" tool; pair it with `try`/`finally` everywhere you use it.**

## Summary

- `selectionModel()` is a view's built-in selection manager — there is no need to instantiate your own
- Three common modes: `NoSelection` / `SingleSelection` / `ExtendedSelection`
- `SelectionBehavior` governs selection granularity (cell / row / column) and is independent of the mode
- `currentChanged` fires as the cursor moves; `selectionChanged` fires as the selection set changes
- Programmatic selection uses `select()` with combinable flags such as `ClearAndSelect | Rows`
- Any index from a proxy-bearing view must be converted with `mapToSource` first
- Modifying a selection inside `selectionChanged` requires `blockSignals` to prevent recursion

Connect the selectionModel's selectionChanged signal, and when a row is selected, show that row's data in the right-hand label. The view must sit behind a proxy (with filtering), and you must use mapToSource to read the real data. This is a windowed program that cannot run in a web page — click "Open in VS Code" to run it.

  import sys
  from PySide6.QtCore import QAbstractTableModel, Qt, QModelIndex, QSortFilterProxyModel
  from PySide6.QtWidgets import (
      QApplication, QWidget, QTableView, QLabel, QHBoxLayout, QVBoxLayout
  )

  class StudentModel(QAbstractTableModel):
      def __init__(self):
          super().__init__()
          self._rows = [
              ["Alice", 20, "R&D"],
              ["Bob", 25, "Marketing"],
              ["Carol", 22, "Finance"],
          ]
      def rowCount(self, p=QModelIndex()):
          return len(self._rows)
      def columnCount(self, p=QModelIndex()):
          return 3
      def data(self, index, role=Qt.DisplayRole):
          if not index.isValid():
              return None
          return str(self._rows[index.row()][index.column()])
      def headerData(self, section, orientation, role=Qt.DisplayRole):
          if role == Qt.DisplayRole and orientation == Qt.Horizontal:
              return ["Name", "Age", "Department"][section]
          return None

  app = QApplication(sys.argv)
  win = QWidget()
  win.setWindowTitle("Select to Show Detail")

  source = StudentModel()
  proxy = QSortFilterProxyModel()
  proxy.setSourceModel(source)
  proxy.setFilterKeyColumn(-1)

  view = QTableView()
  view.setModel(proxy)
  view.setSelectionMode(Qt.ExtendedSelection)
  view.setSelectionBehavior(Qt.SelectRows)

  detail = QLabel("Select a row to see details")
  detail.setWordWrap(True)

  def on_selection_changed(selected, deselected):
      # Complete here: use mapToSource to get the real data and build text for the label
      pass

  view.selectionModel().selectionChanged.connect(on_selection_changed)

  layout = QHBoxLayout(win)
  layout.addWidget(view, 2)
  layout.addWidget(detail, 1)
  win.resize(600, 300)
  win.show()
  app.exec()
checklist:
- The selectionChanged signal is connected
- mapToSource converts the proxy index to a source index
- The right-hand label correctly shows all data for the selected row
- Selection is by entire row (SelectRows)
- The program displays and runs normally
