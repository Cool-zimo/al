# Custom Delegates: paint and createEditor, plus setEditorData and setModelData

> Lesson 08 covered `paint`, so a cell can now look different. This lesson makes it editable: double-click to pop up a calendar, a dropdown, or a star selector. The key is how the four methods cooperate — miss one and the edit simply does not work.

## The Four Steps of the Edit Flow

**From the moment a cell is double-clicked until the final value is written back to the model, the full sequence is:**

```
① The user double-clicks the cell
        ↓
② createEditor(parent, option, index)  ← You return an editor widget
        ↓
③ setEditorData(editor, index)        ← You pour the current model value into the editor
        ↓
④ The user operates the editor (picks a date, taps a star...)
        ↓
⑤ setModelData(editor, model, index)  ← You write the editor's value back into the model
        ↓
⑥ The editor closes and the view repaints with the new value
```

**Each of the four methods owns one step. The most common bug is implementing only `createEditor` and `setEditorData`, then wondering why "after I press Enter, the value snaps back to what it was".**

## createEditor: Return an Editor

**Inside this method you construct a widget — `QSpinBox`, `QComboBox`, `QDateEdit`, etc. — configure it, and return it.**

```python
from PySide6.QtWidgets import QSpinBox, QStyledItemDelegate, QComboBox

class SpinDelegate(QStyledItemDelegate):
    def createEditor(self, parent, option, index):
        editor = QSpinBox(parent)
        editor.setRange(0, 100)
        editor.setSuffix("%")
        return editor
```

**The `parent` argument is mandatory.** This is a Qt memory-management requirement: the editor is parented to the view's viewport and is destroyed automatically when it closes.

**`createEditor` is only responsible for "building"; it must not "fill in the value".** That job belongs to `setEditorData`.

## setEditorData: Pour the Model's Value into the Editor

```python
def setEditorData(self, editor, index):
    value = index.data(Qt.EditRole)       # Read the current value from the model
    if value is None:
        value = 0
    editor.setValue(int(value))           # Pour it into the spinbox
```

**Here you read `EditRole`.** Because the model's `data()` may return a formatted string for `DisplayRole` (such as `"92%"`), while `EditRole` returns the raw `int`. Using `DisplayRole` to fill the editor leads to conversion errors.

## setModelData: Write the Editor's Value Back to the Model

**This is the step most often forgotten.**

```python
def setModelData(self, editor, model, index):
    value = editor.value()                       # Read the current value from the editor
    model.setData(index, value, Qt.EditRole)     # Write it back into the model
```

**Note that this is `model.setData`, not a direct mutation of the model's internal list.** Going through the model's interface triggers the `dataChanged` signal and passes through any validation logic the model implements.

## Crash Site 1: createEditor Implemented, setModelData Missing, Edit Does Nothing

**Symptom: you double-click the cell, the spinbox appears and you can change the number, you press Enter, the spinbox disappears, and the cell still shows the old value.**

```python
class BadDelegate(QStyledItemDelegate):
    def createEditor(self, parent, option, index):
        editor = QSpinBox(parent)
        editor.setRange(0, 100)
        return editor

    def setEditorData(self, editor, index):
        editor.setValue(int(index.data(Qt.EditRole)))

    # ❌ setModelData was never written
```

**Root cause: Qt's edit flow is — open the editor, call `setModelData` on commit, close the editor. Without `setModelData`, the model's data is never updated, so when the view repaints it still shows the old value.**

**✅ Fix: add `setModelData`.**

```python
def setModelData(self, editor, model, index):
    model.setData(index, editor.value(), Qt.EditRole)
```

**This is the number-one delegate trap, and it shares its root cause with forgetting to emit `dataChanged`: data changed but did not travel through the correct channel, so the UI never finds out.**

## Crash Site 2: setEditorData Uses DisplayRole and Crashes on Conversion

**Symptom: on double-click to edit, `ValueError: invalid literal for int() with base 10: '92%'`.**

```python
def setEditorData(self, editor, index):
    value = index.data(Qt.DisplayRole)   # ❌ You get "92%"
    editor.setValue(int(value))          # Conversion fails
```

**Root cause: `DisplayRole` is the formatted display text — complete with units and thousands separators.**

**✅ Fix: use `EditRole` to get the raw value.**

```python
def setEditorData(self, editor, index):
    value = index.data(Qt.EditRole)      # ✅ Raw int: 92
    if value is None:
        value = 0
    editor.setValue(int(value))
```

**This only works if the model's `data()` correctly implements `EditRole`. The two must be paired; break either half and editing breaks.**

## Crash Site 3: Editor Has No parent, Memory Leak or Crash

**Symptom: after the editor opens, the UI freezes, or Python reports `RuntimeError: wrapped C/C++ object has been deleted`.**

```python
def createEditor(self, parent, option, index):
    editor = QSpinBox()                  # ❌ No parent passed
    return editor
```

**Root cause: Qt's parent-ownership mechanism depends on `parent`.** A widget with no parent has nobody managing its lifetime, so it may be destroyed prematurely.

**✅ Fix: always pass `parent`.**

```python
def createEditor(self, parent, option, index):
    editor = QSpinBox(parent)            # ✅
    return editor
```

## Dropdown Delegate in Practice

**You want the status column to offer "Pending / In Progress / Done" via a dropdown:**

```python
class StatusDelegate(QStyledItemDelegate):
    _OPTIONS = ["Pending", "In Progress", "Done"]

    def createEditor(self, parent, option, index):
        editor = QComboBox(parent)
        editor.addItems(self._OPTIONS)
        return editor

    def setEditorData(self, editor, index):
        current = index.data(Qt.EditRole) or index.data(Qt.DisplayRole)
        if current in self._OPTIONS:
            editor.setCurrentText(current)

    def setModelData(self, editor, model, index):
        model.setData(index, editor.currentText(), Qt.EditRole)

    def paint(self, painter, option, index):
        # Optional: render as a coloured label even when not being edited
        super().paint(painter, option, index)
```

**Here `createEditor` and `paint` can be designed independently.** Normally you see text; double-clicking opens the dropdown. If you want it to render as a coloured tag all the time, do that drawing yourself inside `paint`.

## Date Delegate: Popping Up a Calendar

**For a date column, use `QDateEdit` with a calendar popup:**

```python
from PySide6.QtWidgets import QDateEdit
from PySide6.QtCore import QDate

class DateDelegate(QStyledItemDelegate):
    def createEditor(self, parent, option, index):
        editor = QDateEdit(parent)
        editor.setCalendarPopup(True)           # Pop up a calendar
        editor.setDisplayFormat("yyyy-MM-dd")
        return editor

    def setEditorData(self, editor, index):
        value = index.data(Qt.EditRole)        # Expected to be QDate or date
        if isinstance(value, QDate):
            editor.setDate(value)
        else:
            editor.setDate(QDate.currentDate())

    def setModelData(self, editor, model, index):
        model.setData(index, editor.date(), Qt.EditRole)
```

**Be consistent about whether the model stores `QDate` or `datetime.date`.** Mixing them makes the type checks inside `setEditorData` messy. It is cleanest to store `QDate` throughout, or to convert at the boundary.

## updateEditorGeometry: When the Editor Is Misaligned

**The default implementation positions the editor using `option.rect`. If your custom editor has special sizing, override this:**

```python
def updateEditorGeometry(self, editor, option, index):
    editor.setGeometry(option.rect)
```

**The default is usually sufficient, but if you see "the editor is clipped, half-hidden inside the cell", this is the method where you adjust the rectangle.**

## Summary

- The four-step edit flow: `createEditor` builds → `setEditorData` fills → the user edits → `setModelData` writes back
- Forgetting `setModelData` is the classic bug, showing up as "the value snaps back after editing"
- `setEditorData` reads `EditRole` to get the raw value and avoid formatted-string conversion failures
- `createEditor` must pass `parent`, or lifetime management falls apart
- A dropdown delegate uses `QComboBox`; a date delegate uses `QDateEdit(setCalendarPopup)`
- Type consistency matters: whatever type the model stores is exactly the type the delegate must read
