# QSortFilterProxyModel: Sorting and Filtering Without Touching Your Data

> You built a solid model. Now the product manager comes back: it needs sorting, and a search box. You do not change a single line of the model — you drop a `QSortFilterProxyModel` in between, and the original data stays completely untouched.

## What a Proxy Model Is: A Middle Layer Between Model and View

**A proxy model is itself a model. The view has no idea it is talking to a proxy; it treats it like any ordinary model, and the proxy in turn asks the real source model for data.**

```
source_model ──► proxy_model ──► view
   (real data)     (sort/filter)    (display)
```

**The clever part: the source model stays read-only, complete, and in its original order. The proxy performs any transformation it likes, and the source is none the wiser.**

```python
from PySide6.QtCore import QSortFilterProxyModel, Qt
from PySide6.QtWidgets import QApplication, QTableView

# Imagine a model you already wrote
source_model = ScoreModel(students)

proxy = QSortFilterProxyModel()
proxy.setSourceModel(source_model)      # Plug into the source

view = QTableView()
view.setModel(proxy)                   # The view only talks to the proxy
```

**The key line is `view.setModel(proxy)`, not `view.setModel(source_model)`.** This is the single most common mistake — set the source, then wonder why sorting does nothing.

## Sorting: setSortRole Plus sort

**By default, sorting is done on the `DisplayRole` — which is text. To sort numerically, you must tell the proxy which role to use.**

```python
# The source model provides a UserRole for the numeric column
proxy.setSortRole(Qt.UserRole)         # Tell the proxy to sort on UserRole
view.setSortingEnabled(True)           # Let the user click headers to sort
```

**Header-click sorting is literally one line: `setSortingEnabled(True)`.** Qt wires up the click-to-sort logic for you automatically.

**Programmatic sorting:**

```python
proxy.sort(1, Qt.DescendingOrder)      # Sort column 1 descending
proxy.sort(-1)                        # -1 means: restore the original order
```

## Crash Site 1: Sorting as Text — "100" Comes Before "9"

**Symptom: You click the score column header to sort, and the result is 9, 100, 85, 88 instead of 9, 85, 88, 100.**

```python
# The source model's data() only handles DisplayRole
def data(self, index, role=Qt.DisplayRole):
    if role == Qt.DisplayRole:
        return str(self._rows[index.row()][index.column()])  # "92"
    return None
    # ❌ No UserRole, so the proxy cannot get at the number
```

**Root cause: the proxy sorts on `DisplayRole` by default, and `DisplayRole` is the string `"92"`. In string comparison `"100" < "9"` because the character `'1'` comes before `'9'`.**

**✅ Fix: provide the numeric value as `UserRole` in `data()`, and tell the proxy to use it.**

```python
def data(self, index, role=Qt.DisplayRole):
    value = self._rows[index.row()][index.column()]
    if role == Qt.DisplayRole:
        return str(value)
    if role == Qt.UserRole:                      # ✅ Used for numeric sorting
        return value if isinstance(value, int) else None
    return None

# When wiring it up
proxy.setSortRole(Qt.UserRole)
```

**Handling `DisplayRole` alone is never enough — sorting and filtering frequently need a "logical value" rather than a "display value".**

## Filtering: setFilterFixedString and Regular Expressions

**Filtering means letting the proxy keep only the rows that match, so the view sees only the filtered result.**

```python
proxy.setFilterFixedString("Zhang")          # Keep rows containing "Zhang"
proxy.setFilterRegularExpression(r"^Zhang")  # Regex: starts with "Zhang"
proxy.setFilterCaseSensitivity(Qt.CaseInsensitive)  # Ignore case
```

**filterKeyColumn: which column to filter on.**

```python
proxy.setFilterKeyColumn(0)                 # Only column 0 (name)
proxy.setFilterKeyColumn(-1)                # -1 means: all columns
```

**Clearing a filter:**

```python
proxy.setFilterFixedString("")              # Pass an empty string to show everything
```

## Crash Site 2: filterKeyColumn Defaults to Column 0, So Other Columns Never Match

**Symptom: you type "92" in the search box hoping to find the row with score 92, and nothing appears.**

```python
proxy.setFilterFixedString("92")
# filterKeyColumn defaults to 0, so only the name column is searched
```

**Root cause: `setFilterKeyColumn` defaults to `0` — only the first column is searched.** To search across all columns you must explicitly set it to `-1`.

**✅ Fix:**

```python
proxy.setFilterKeyColumn(-1)                # All columns participate
proxy.setFilterFixedString("92")            # Now the score column matches too
```

**Or filter on a specific column — often the more common case, such as a dedicated "search by name" box.**

```python
name_filter = QSortFilterProxyModel()
name_filter.setSourceModel(source_model)
name_filter.setFilterKeyColumn(0)          # Only the name column
```

## Crash Site 3: The View's Index Is a Proxy Index, Not a Source Index

**Symptom: you want the raw data of the selected row, so you take the proxy's index and look it up directly in the source model — and the row number is wrong.**

```python
idx = view.currentIndex()                  # This is the proxy's index
row = idx.row()                            # Say, 0 — the 0th row after filtering
source_model._rows[row]                    # ❌ Might be "Li Si", not "Zhang San"
```

**Root cause: after filtering, the proxy's row order no longer matches the source's row order.** The proxy's index lives in proxy-coordinate space and cannot be fed straight to the source model.

**✅ Fix: convert with `mapToSource`.**

```python
proxy_idx = view.currentIndex()
source_idx = proxy.mapToSource(proxy_idx)  # Convert to source coordinates
real_row = source_idx.row()                # This is the true row in the source
data = source_model._rows[real_row]
```

**Its siblings are `mapFromSource` (source → proxy) and `mapSelectionToSource` (bulk conversion of a selection).** Any time you move between proxy and source, these two methods are the only correct bridge.

## Chaining Proxies: Sort and Filter in Two Layers

**Because a proxy is itself a model, a proxy can sit on top of another proxy.**

```python
source_model = ScoreModel(students)

filter_proxy = QSortFilterProxyModel()
filter_proxy.setSourceModel(source_model)
filter_proxy.setFilterKeyColumn(0)

sort_proxy = QSortFilterProxyModel()
sort_proxy.setSourceModel(filter_proxy)     # Sort the already-filtered result
sort_proxy.setSortRole(Qt.UserRole)

view.setModel(sort_proxy)
```

**Order matters: filter first, then sort, giving you "a subset that is then sorted by score".** Reversing the order produces the same result but with different performance — filtering is cheap, so put it on the inside to reduce the work the outer layer has to do.

## Summary

- A proxy model sits between the source model and the view, acting as a transparent model to both sides
- `view.setModel` must receive the proxy, never the source
- Sort with `setSortRole(UserRole)` plus `setSortingEnabled(True)`, or call `proxy.sort()` directly
- Numeric columns must expose `UserRole` in `data()`, otherwise sorting falls back to text
- Filter with `setFilterFixedString` / `setFilterRegularExpression`
- `filterKeyColumn` defaults to `0`; use `-1` to search all columns
- A proxy index must be converted with `mapToSource` before it can be used against the source
- Proxies can be chained for layered sorting and filtering

  import sys
  from PySide6.QtCore import QAbstractTableModel, Qt, QSortFilterProxyModel, QModelIndex
  from PySide6.QtWidgets import (
      QApplication, QWidget, QTableView, QLineEdit, QVBoxLayout
  )

  class TodoModel(QAbstractTableModel):
      def __init__(self, rows=None):
          super().__init__()
          self._rows = rows or [
              ["Buy groceries", "Pending"],
              ["Write code", "In Progress"],
              ["Hit the gym", "Pending"],
              ["Read a book", "Done"],
          ]

      def rowCount(self, parent=Qt.QModelIndex()):
          return len(self._rows)

      def columnCount(self, parent=Qt.QModelIndex()):
          return 2

      def data(self, index, role=Qt.DisplayRole):
          if not index.isValid():
              return None
          if role == Qt.DisplayRole:
              return str(self._rows[index.row()][index.column()])
          return None

      def headerData(self, section, orientation, role=Qt.DisplayRole):
          if role == Qt.DisplayRole and orientation == Qt.Horizontal:
              return ["Task", "Status"][section]
          return None

  app = QApplication(sys.argv)
  win = QWidget()
  win.setWindowTitle("Todo List with Sort and Filter")

  source = TodoModel()
  proxy = QSortFilterProxyModel()
  proxy.setSourceModel(source)
  proxy.setFilterKeyColumn(-1)                       # All columns participate

  search = QLineEdit()
  search.setPlaceholderText("Type a keyword to filter...")

  def on_text(text):
      proxy.setFilterFixedString(text)

  search.textChanged.connect(on_text)

  view = QTableView()
  view.setModel(proxy)
  # Complete here: make header clicks trigger sorting
  # view.setSortingEnabled(True)

  layout = QVBoxLayout(win)
  layout.addWidget(search)
  layout.addWidget(view)
  win.resize(400, 300)
  win.show()
  app.exec()
