# JSON and Network Data: Parsing API Responses and Feeding Them into a Model

> The end goal of a network request is usually a JSON payload. This section connects the full chain — "network request -> JSON parsing -> into a Model -> bound to a View" — to build a genuine "online data table."

## What the Full Chain Looks Like

```
API returns JSON
   |  QJsonDocument::fromJson
QJsonDocument -> QJsonArray / QJsonObject
   |  iterate and parse
Python list[dict]
   |  hand off to a custom Model
QAbstractTableModel / QSqlTableModel
   |  bind
QTableView
```

## From QByteArray to Python Data

`reply.readAll()` returns a `QByteArray`. In PySide6 there are two ways to handle it:

```
from PySide6.QtCore import QJsonDocument, QJsonParseError

data = reply.readAll()
doc = QJsonDocument.fromJson(bytes(data))    # Needs bytes, not QByteArray
if doc.isNull():
    print("JSON parse failed")
    return
if doc.isArray():
    items = doc.array()      # QJsonArray
elif doc.isObject():
    items = doc.object()     # QJsonObject
```

A simpler approach: convert the `QByteArray` to bytes and hand it to Python's standard `json` library:

```
import json
data = reply.readAll()
items = json.loads(bytes(data).decode("utf-8"))
```

## Complete Example: An Online User List

```
import sys, json
from PySide6.QtWidgets import (QApplication, QWidget, QVBoxLayout, QPushButton,
                              QTableView, QLabel, QHeaderView)
from PySide6.QtCore import Qt, QUrl
from PySide6.QtNetwork import QNetworkAccessManager, QNetworkRequest
from PySide6.QtCore import QAbstractTableModel

class UserModel(QAbstractTableModel):
    HEADERS = ["ID", "Name", "Email", "City"]

    def __init__(self, data=None):
        super().__init__()
        self._data = data or []

    def rowCount(self, parent=None):
        return len(self._data)

    def columnCount(self, parent=None):
        return len(self.HEADERS)

    def data(self, index, role=Qt.ItemDataRole.DisplayRole):
        if not index.isValid():
            return None
        if role == Qt.ItemDataRole.DisplayRole:
            return str(self._data[index.row()][index.column()])
        return None

    def headerData(self, section, orientation, role=Qt.ItemDataRole.DisplayRole):
        if role == Qt.ItemDataRole.DisplayRole and orientation == Qt.Orientation.Horizontal:
            return self.HEADERS[section]
        return None

    def set_users(self, users):
        self.beginResetModel()
        self._data = users
        self.endResetModel()


class Demo(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("Online Users")
        self.resize(700, 500)

        self.status = QLabel("Click the button to load data")
        self.btn = QPushButton("Load")
        self.table = QTableView()

        self.model = UserModel()
        self.table.setModel(self.model)
        self.table.horizontalHeader().setSectionResizeMode(
            QHeaderView.ResizeMode.Stretch)

        self.manager = QNetworkAccessManager(self)
        self.btn.clicked.connect(self.fetch)

        layout = QVBoxLayout(self)
        layout.addWidget(self.status)
        layout.addWidget(self.btn)
        layout.addWidget(self.table)

    def fetch(self):
        self.status.setText("Requesting...")
        self.btn.setEnabled(False)
        url = QUrl("https://jsonplaceholder.typicode.com/users")
        req = QNetworkRequest(url)
        reply = self.manager.get(req)
        reply.finished.connect(lambda: self.on_done(reply))

    def on_done(self, reply):
        self.btn.setEnabled(True)
        if reply.error() != reply.NetworkError.NoError:
            self.status.setText(f"Error: {reply.errorString()}")
            reply.deleteLater()
            return
        try:
            data = json.loads(bytes(reply.readAll()).decode("utf-8"))
        except (UnicodeDecodeError, json.JSONDecodeError) as e:
            self.status.setText(f"Parse failed: {e}")
            reply.deleteLater()
            return

        users = [
            [u["id"], u["name"], u["email"], u["address"]["city"]]
            for u in data
        ]
        self.model.set_users(users)
        self.status.setText(f"Loaded, {len(users)} records")
        reply.deleteLater()


if __name__ == "__main__":
    app = QApplication(sys.argv)
    w = Demo()
    w.show()
    app.exec()
```

## Why beginResetModel / endResetModel

When you replace the entire dataset at once, the safest approach is to wrap it in a reset pair, telling the View: "the internal structure has completely changed, redraw yourself." For incremental appends, `beginInsertRows / endInsertRows` is the more precise tool.

## Crash Site 1: Skipping json.loads, Using the String as a Subscript

**Symptoms: `data[0]` raises `TypeError: string indices must be integers`, or you get the first character of the JSON string.

**Why:** `bytes(reply.readAll()).decode()` gives you a **string**, not a dict or list. You must call `json.loads` one more time.

**The fix:**

```
text = bytes(reply.readAll()).decode("utf-8")
data = json.loads(text)        # Now data is a list/dict
```

## Crash Site 2: Wrong Nested JSON Field, KeyError Crash

**Symptoms: The API returns `{..., "address": {"city": "New York"}}`, but `u["city"]` raises KeyError.

**WRONG — Do not do this:**

```
city = u["city"]               # That top-level field doesn't exist
```

**The fix: Use `.get` or navigate level by level, with a fallback:**

```
city = u.get("address", {}).get("city", "Unknown")
```

## Crash Site 3: Not Refreshing the Model When Network Data Never Arrives

**Symptoms:** `self.model.set_users([])` was forgotten on the failure path, so the UI stays stuck on "Requesting..."

**The fix:** Every code path (success / failure / parse failure) should update the status text. On failure, leave the model data untouched but give the user feedback.

## Crash Site 4: time.sleep in the UI Thread Waiting for the Network

**Symptoms: After clicking the button the window freezes for a few seconds.**

**WRONG — Do not do this:**

```
def on_click(self):
    import time
    time.sleep(3)              # Blocks the main thread, freezing the UI
    self.load_data()
```

**The fix: Always use asynchronous signals; never poll with sleep.**

## Crash Site 5: Model Data Changed Without beginResetModel, View Displays Garbage

**Symptoms: The data changed but the View still shows the old row count, or blank rows and out-of-bounds crashes appear.

**The fix:**

```
def set_users(self, users):
    self.beginResetModel()
    self._data = users
    self.endResetModel()
```

## Summary

- The network JSON pipeline: readAll -> decode -> json.loads -> parse -> feed the Model
- Either `QJsonDocument.fromJson` or the standard `json` library can parse
- A custom Model uses `beginResetModel/endResetModel` for full refreshes
- JSON fields should use `.get` with defaults to avoid KeyError
- Every code path must update the status text; failures need feedback too
- Never sleep or wait synchronously on the UI thread
- Always `deleteLater` the reply
