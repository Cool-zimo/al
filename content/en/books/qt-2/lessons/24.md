# QNetworkAccessManager Basics: Asynchronous HTTP Requests and Responses

> A desktop app that fetches data from the network could use `requests`, but that's synchronous — call it and the UI freezes. Qt's approach is asynchronous: `QNetworkAccessManager` sends the request, and a signal delivers the response when it arrives.

## A Minimal GET Request

```
import sys
from PySide6.QtWidgets import QApplication, QWidget, QVBoxLayout, QPushButton, QLabel
from PySide6.QtNetwork import QNetworkAccessManager, QNetworkRequest
from PySide6.QtCore import QUrl

class Demo(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("Network Request")
        self.resize(400, 200)

        self.label = QLabel("Click the button to send a request")
        btn = QPushButton("Fetch Data")
        btn.clicked.connect(self.fetch)

        self.manager = QNetworkAccessManager(self)   # 1. The manager (long-lived)

        layout = QVBoxLayout(self)
        layout.addWidget(self.label)
        layout.addWidget(btn)

    def fetch(self):
        url = QUrl("https://httpbin.org/get")
        request = QNetworkRequest(url)
        reply = self.manager.get(request)            # 2. Send GET
        reply.finished.connect(lambda: self.on_done(reply))  # 3. Connect the signal

    def on_done(self, reply):
        if reply.error() != reply.NetworkError.NoError:
            self.label.setText(f"Error: {reply.errorString()}")
            reply.deleteLater()
            return
        data = reply.readAll()                       # 4. Read the response
        text = bytes(data).decode("utf-8")
        self.label.setText(text[:200])
        reply.deleteLater()                          # 5. Must release

if __name__ == "__main__":
    app = QApplication(sys.argv)
    w = Demo()
    w.show()
    app.exec()
```

## Key API

| Class / method | Purpose |
|---|---|
| QNetworkAccessManager | Network manager; usually one instance per app |
| QNetworkRequest(url) | Request object; can carry headers, timeout, etc. |
| manager.get(request) | Send a GET, returning a QNetworkReply |
| manager.post(request, data) | Send a POST |
| reply.finished | Signal emitted on completion (success or failure) |
| reply.readyRead | Emitted when data is available (for streaming) |
| reply.errorOccurred | Error signal |
| reply.readAll() | Read the full response body (QByteArray) |
| reply.deleteLater() | Asynchronously safe release of the reply |

## POST Requests

```
from PySide6.QtCore import QByteArray, QJsonDocument

def post_json(self):
    url = QUrl("https://httpbin.org/post")
    request = QNetworkRequest(url)
    request.setHeader(QNetworkRequest.KnownHeaders.ContentTypeHeader,
                      "application/json")

    payload = QJsonDocument({"name": "test", "value": 42}).toJson()
    reply = self.manager.post(request, payload)
    reply.finished.connect(lambda: self.on_done(reply))
```

## Why Asynchrony Matters

The GUI main thread handles mouse, keyboard, and painting. **Once the main thread blocks, the UI freezes** — the window stops responding to drags, button clicks, and animations.

```
# WRONG: synchronous wait freezes the UI for several seconds
import urllib.request
data = urllib.request.urlopen("https://httpbin.org/get", timeout=5).read()
```

Qt's event loop works through signal callbacks. The request runs on a background thread; when it finishes, it switches back to the main thread and fires `finished`. The UI never freezes.

## Crash Site 1: Synchronous Network Call Freezes the UI

**Symptoms: Click a button and the window "whites out" for a few seconds; the cursor spins; nothing responds.

**WRONG — Do not do this:**

```
import requests
def on_click(self):
    resp = requests.get("https://httpbin.org/get", timeout=5)   # Main thread blocked for 5s
    self.label.setText(resp.text[:200])
```

**The fix: Use `QNetworkAccessManager`'s asynchronous signal mechanism (see the full example above).**

## Crash Site 2: Forgetting reply.deleteLater(), Memory Leak

**Symptoms:** The program's memory grows steadily over time, especially with frequent requests.

**Why:** `QNetworkReply` is a `QObject` allocated on the heap. Qt won't auto-delete it — you must call `deleteLater()`.

**The fix: Always call `deleteLater()` in the finished callback, whether success or failure:**

```
def on_done(self, reply):
    try:
        ...
    finally:
        reply.deleteLater()
```

## Crash Site 3: Chinese Text Decodes as Garbled Characters

**Symptoms: Chinese text appears as `\xe4\xb8\xad\xe6\x96\x87` or `����`.

**Why:** `reply.readAll()` returns a `QByteArray`. Without decoding it's just bytes; or the server sent no charset and decoding with the wrong encoding produces garbage.

**The fix: Decode as utf-8 and handle errors:**

```
data = reply.readAll()
try:
    text = bytes(data).decode("utf-8")
except UnicodeDecodeError:
    text = bytes(data).decode("gbk", errors="replace")
```

## Crash Site 4: Manager Is a Local Variable, Garbage-Collected

**Symptoms: The program runs for a while, or after a function returns, requests go out but `finished` never fires.

**Why:** The manager was a local variable and was collected by Python after the function ended, taking the Qt network session with it.

**The fix: Make the manager an instance member (`self.manager`) so its lifetime covers the entire request lifecycle.**

## Crash Site 5: SSL Error "TLS initialization failed"

**Symptoms: On some Windows environments, HTTPS requests fail with an SSL initialization error.

**Why:** Qt's network module depends on the system's TLS backend; some environments are missing it or have a version mismatch.

**Workaround:** Use a recent Qt version (5.12.4+ / 6.x usually bundles Schannel or OpenSSL); or test against an HTTP endpoint (e.g., the http version of httpbin.org) to verify the code logic.

## Summary

- Network requests use `QNetworkAccessManager`; typically one instance per application
- Requests are asynchronous, with results handled via the `finished` signal
- Read the response with `reply.readAll()`, which returns `QByteArray` and must be decoded
- Always call `reply.deleteLater()` to release the resource
- The manager must be a member variable to outlive the request
- Never use `requests` / `urllib` for synchronous waits on the main thread
- Unified utf-8 decoding with error handling avoids garbled text
