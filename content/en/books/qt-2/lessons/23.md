# QtSql Meets Model/View: QSqlQueryModel vs QSqlTableModel

> Both "bind a SQL result to a QTableView" — yet `QSqlQueryModel` and `QSqlTableModel` take two different paths: one is read-only for arbitrary SELECTs, the other is editable for a single table. This section unpacks that choice.

## How the Two Compare

| | QSqlQueryModel | QSqlTableModel |
|---|---|---|
| Purpose | Executes any SELECT, read-only display | Operates on a single table, editable |
| Setting data | setQuery(sql) | setTable(name) + select() |
| Editable | No (by default) | Yes |
| Complex SQL | Supports JOIN, GROUP BY, subqueries | Not supported |
| Commit strategy | None | EditStrategy (OnFieldChange/OnRowChange/OnManualSubmit) |
| Adding/deleting rows | Not supported | insertRow / removeRow |
| Typical use | Reports, statistics, joined queries | Single-table CRUD UI |

## QSqlQueryModel: Read-Only Arbitrary Queries

```
from PySide6.QtWidgets import QApplication, QTableView
from PySide6.QtSql import QSqlDatabase, QSqlQueryModel

def main():
    app = QApplication([])
    db = QSqlDatabase.addDatabase("QSQLITE")
    db.setDatabaseName("books.db")
    db.open()

    model = QSqlQueryModel()
    model.setQuery(
        "SELECT author, COUNT(*) AS cnt, AVG(price) AS avg_price "
        "FROM books GROUP BY author ORDER BY avg_price DESC"
    )
    model.setHeaderData(0, Qt.Orientation.Horizontal, "Author")
    model.setHeaderData(1, Qt.Orientation.Horizontal, "Count")
    model.setHeaderData(2, Qt.Orientation.Horizontal, "Avg Price")

    view = QTableView()
    view.setModel(model)
    view.show()
    app.exec()
```

Note that `setHeaderData` on a QueryModel is for **display** — the columns of a QueryModel correspond to the column order of the SELECT, and you can't arbitrarily reorder them.

## QSqlTableModel: An Editable Single Table

```
model = QSqlTableModel()
model.setTable("books")
model.setEditStrategy(QSqlTableModel.EditStrategy.OnRowChange)
model.select()
view.setModel(model)
# Double-click a cell to edit; it auto-commits when focus leaves the row
```

For batch edits with a manual commit:

```
model.setEditStrategy(QSqlTableModel.EditStrategy.OnManualSubmit)
# ... user edits many cells ...
model.submitAll()          # Commit all at once
# To discard changes: model.revertAll()
```

## Making QSqlQueryModel Editable (Advanced)

Subclass `QSqlQueryModel`, override `flags` and `setData`, and write the UPDATE SQL by hand inside `setData`:

```
class EditableQueryModel(QSqlQueryModel):
    def flags(self, index):
        fl = super().flags(index)
        if index.column() in (1, 2):     # Allow editing columns 2 and 3
            fl |= Qt.ItemFlag.ItemIsEditable
        return fl

    def setData(self, index, value, role=Qt.ItemDataRole.EditRole):
        if role != Qt.ItemDataRole.EditRole:
            return False
        row = index.row()
        # Need the primary key id; assume column 0 is id
        id_idx = self.index(row, 0)
        record_id = self.data(id_idx)
        col_name = self.record().fieldName(index.column())
        q = QSqlQuery()
        q.prepare(f"UPDATE books SET {col_name} = ? WHERE id = ?")
        q.addBindValue(value)
        q.addBindValue(record_id)
        if q.exec():
            self.refresh()
            return True
        return False

    def refresh(self):
        self.setQuery(self.query().lastQuery())   # Re-execute the original query
```

## Crash Site 1: Trying to Edit via QSqlQueryModel, Changes Vanished

**Symptoms: You can double-click a cell and enter edit mode, but after pressing Enter the value snaps back.

**Why:** `QSqlQueryModel`'s default `flags()` does not include `ItemIsEditable`, and its `setData` returns `False`. It is **read-only by design** — because an arbitrary SELECT result can't always be mapped back to a specific row in a specific table.

**The fix:** If the source is a single table, switch to `QSqlTableModel`. If the query is complex, build a custom editable QueryModel (as shown above).

## Crash Site 2: QSqlTableModel Uses a JOIN, setTable Errors Out

**Symptoms: You want "orders + customer names", write a JOIN query, bind it to a TableModel, and it can't edit — `select` may even fail.

**WRONG — Do not do this:**

```
model.setTable("orders JOIN customers ON orders.cid = customers.id")
```

**Why:** `setTable` expects a **table name**, not arbitrary SQL. It needs the table name to generate UPDATE/INSERT/DELETE statements; a JOIN result can't be reversed back into "which table to modify."

**The fix:** Use a TableModel for single-table operations; use a QueryModel (read-only) or `QSqlRelationalTableModel` for joined display.

## Crash Site 3: OnManualSubmit — Edits Disappear on Refresh

**Symptoms: You edit cells for ages, switch pages or close the window, and come back to find every change gone.

**Why:** Under `OnManualSubmit`, changes live only in memory; without `submitAll` they never reach the database.

**The fix:** Call `model.submitAll()` at the right moment (a Save button, or the window-close event). To discard: `revertAll()`.

## Crash Site 4: setHeaderData Set but Headers Don't Show

**Symptoms: Headers still show the raw column names like `id/title/author`.

**Why:** With a QueryModel, `setHeaderData` requires the correct section and horizontal orientation, and **must be called after `setQuery`** — `setQuery` rebuilds the headers.

**The fix:**

```
model.setQuery("SELECT id, title, price FROM books")
model.setHeaderData(0, Qt.Orientation.Horizontal, "ID")
model.setHeaderData(1, Qt.Orientation.Horizontal, "Title")
model.setHeaderData(2, Qt.Orientation.Horizontal, "Price")
```

## Summary

- `QSqlQueryModel`: arbitrary SELECTs, read-only, great for reports/statistics
- `QSqlTableModel`: single table, editable, works out of the box
- Complex SQL + editable = a custom QueryModel subclass
- JOIN results cannot be bound to a TableModel
- `EditStrategy` controls commit timing; `OnManualSubmit` needs manual `submitAll`
- A QueryModel's `setHeaderData` must come after `setQuery`
- To discard changes, use `revertAll()`

## In-Class Exercise

```quiz
type: local
q: Build a "product price manager" UI with QSqlTableModel: table `products`, columns id/name/price/stock. Requirements: (1) any product with price > 100 gets its entire row painted light yellow (return Qt.ItemDataRole.BackgroundRole from the Model's data method); (2) use OnRowChange as the edit strategy; (3) add a "Show out-of-stock only (stock=0)" checkbox that re-selects with a WHERE clause when toggled. Note: A window cannot open inside a web page — click "Open in VS Code" to run it.
starter: |
  import sys
  from PySide6.QtWidgets import (QApplication, QTableView, QWidget, QVBoxLayout,
                                QCheckBox)
  from PySide6.QtSql import QSqlDatabase, QSqlTableModel, QSqlQuery
  from PySide6.QtCore import Qt
  from PySide6.QtGui import QBrush, QColor

  DB_PATH = "products.db"

  def init_db():
      db = QSqlDatabase.addDatabase("QSQLITE")
      db.setDatabaseName(DB_PATH)
      db.open()
      q = QSqlQuery()
      q.exec("CREATE TABLE IF NOT EXISTS products ("
             "id INTEGER PRIMARY KEY AUTOINCREMENT,"
             "name TEXT, price REAL, stock INTEGER DEFAULT 0)")
      q.exec("DELETE FROM products")
      for n, p, s in [("Keyboard", 199.0, 10), ("Mouse", 59.0, 0),
                      ("Monitor", 1299.0, 3), ("Headphones", 89.0, 0)]:
          q.prepare("INSERT INTO products (name, price, stock) VALUES (?,?,?)")
          q.addBindValue(n); q.addBindValue(p); q.addBindValue(s)
          q.exec()

  class ProductModel(QSqlTableModel):
      def data(self, index, role=Qt.ItemDataRole.DisplayRole):
          # Handle BackgroundRole here: price > 100 returns a light-yellow brush
          if role == Qt.ItemDataRole.BackgroundRole:
              price = float(self.index(index.row(), 2).data() or 0)
              if price > 100:
                  return QBrush(QColor(255, 255, 200))
          return super().data(index, role)

  def main():
      app = QApplication([])
      init_db()
      window = QWidget()
      window.setWindowTitle("Product Manager")
      window.resize(600, 400)

      model = ProductModel()
      model.setTable("products")
      model.setEditStrategy(QSqlTableModel.EditStrategy.OnRowChange)
      model.select()
      model.setHeaderData(0, Qt.Orientation.Horizontal, "ID")
      model.setHeaderData(1, Qt.Orientation.Horizontal, "Name")
      model.setHeaderData(2, Qt.Orientation.Horizontal, "Price")
      model.setHeaderData(3, Qt.Orientation.Horizontal, "Stock")

      view = QTableView()
      view.setModel(model)
      cb = QCheckBox("Out of stock only")
      # Connect cb's stateChanged: when checked, model.setFilter("stock=0"); then model.select()

      layout = QVBoxLayout(window)
      layout.addWidget(cb)
      layout.addWidget(view)
      window.show()
      app.exec()

  if __name__ == "__main__":
      main()
checklist:
- ProductModel overrides data to handle BackgroundRole
- Rows with price > 100 show a light-yellow background
- The edit strategy is OnRowChange
- When the checkbox is checked, setFilter("stock=0") is called and select() runs
- When unchecked, all rows are shown again (setFilter("") + select)
- Price/stock are editable and auto-commit
- The program displays correctly
```
