# Custom Widgets in Practice: A Circular Progress Indicator

> Every tool from the previous three lessons comes together: a hand-painted widget subclassing `QWidget`, mouse events, custom signals, and `QTimer` for animation. The result is a circular progress indicator you can click, animate, and signal from.

## The Goal: A Circular Indicator You Can Click, Animate, and Signal

**Feature list:**

```
Features:
├── Display progress from 0 to 100 (a painted ring)
├── Drag with the mouse to change the progress (handle mouse events)
├── Click "Play" to start an automatic animation (QTimer)
├── Emit a custom signal when progress reaches 100 (Signal)
└── Emit a progress_changed(value) signal whenever the value changes
```

**This widget ties together Lessons 11–14: custom painting (13), events (14), subclass-and-extend plus signals (12), and composite packaging (11).**

## Step 1: Skeleton and Painting

**First, draw the ring.**

```python
from PySide6.QtCore import Qt, Signal, QTimer
from PySide6.QtGui import QPainter, QColor
from PySide6.QtWidgets import QWidget

class CircleProgress(QWidget):
    progress_changed = Signal(int)
    reached_100 = Signal()

    def __init__(self, parent=None):
        super().__init__(parent)
        self._value = 0                    # 0 .. 100
        self.setMinimumSize(150, 150)
        self.setMouseTracking(True)

    def set_value(self, value):
        value = max(0, min(100, int(value)))
        if value == self._value:
            return
        self._value = value
        self.progress_changed.emit(self._value)
        if self._value == 100:
            self.reached_100.emit()
        self.update()

    def value(self):
        return self._value

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setRenderHint(QPainter.Antialiasing)

        rect = self.rect().adjusted(10, 10, -10, -10)
        pen_width = 12
        inner = rect.adjusted(pen_width // 2, pen_width // 2,
                             -pen_width // 2, -pen_width // 2)

        # Track ring
        pen = painter.pen()
        pen.setWidth(pen_width)
        pen.setColor(QColor("#e8e8e8"))
        painter.setPen(pen)
        painter.drawEllipse(inner)

        # Progress arc
        color = self._color_for(self._value)
        pen.setColor(color)
        painter.setPen(pen)
        span = int(-self._value * 3.6 * 16)
        painter.drawArc(inner, 90 * 16, span)

        # Centered text
        painter.setPen(QColor("#333333"))
        font = painter.font()
        font.setPointSize(22)
        font.setBold(True)
        painter.setFont(font)
        painter.drawText(self.rect(), Qt.AlignCenter, f"{self._value}%")

        painter.end()

    def _color_for(self, value):
        if value >= 100:
            return QColor("#4caf50")
        if value >= 60:
            return QColor("#2196f3")
        return QColor("#ff9800")
```

**Notice the debounce check inside `set_value`: `if value == self._value: return`.** It prevents the same value from emitting its signal repeatedly. A small detail, but a professional one.

## Step 2: Drag to Change the Progress

**Convert the mouse position into an angle, then into a 0..100 progress value.**

```python
class CircleProgress(QWidget):
    # ... code above ...

    def mousePressEvent(self, event):
        if event.button() == Qt.LeftButton:
            self._update_from_pos(event.position().toPoint())
            self._dragging = True
        super().mousePressEvent(event)

    def mouseMoveEvent(self, event):
        if getattr(self, '_dragging', False):
            self._update_from_pos(event.position().toPoint())
        super().mouseMoveEvent(event)

    def mouseReleaseEvent(self, event):
        self._dragging = False
        super().mouseReleaseEvent(event)

    def _update_from_pos(self, pos):
        cx = self.width() // 2
        cy = self.height() // 2
        dx = pos.x() - cx
        dy = pos.y() - cy
        import math
        angle = math.degrees(math.atan2(-dy, dx))   # -dy because y grows downward
        # atan2 ranges from -180..180, with 3 o'clock at 0
        if angle < 0:
            angle += 360
        # Align 12 o'clock to 0, then clockwise
        clockwise = (angle + 90) % 360
        self.set_value(clockwise / 360 * 100)
```

**Angle calculation is the heart of this section.** `atan2` returns an angle measured counter-clockwise from the positive x-axis (the 3 o'clock direction), but our progress ring starts at 12 o'clock and grows clockwise. So we flip the y-axis with `-dy`, then apply `(angle + 90) % 360` to align 12 o'clock with 0.

**A subtle point: `atan2(-dy, dx)` gives the angle in a mathematical coordinate system where y grows upward.** Because the screen's y grows downward, `-dy` puts it back into standard orientation. This is the easiest place in the whole transform to go wrong.

## Step 3: Animation — QTimer Auto-Increment

**Add `start_animation` and `stop_animation`, advancing the value a little every 50 ms.**

```python
def start_animation(self, step=2, interval=50):
    if getattr(self, '_anim_timer', None) is None:
        self._anim_timer = QTimer(self)
        self._anim_timer.timeout.connect(self._animate_step)
    self._anim_step = step
    self._anim_timer.start(interval)

def stop_animation(self):
    if hasattr(self, '_anim_timer'):
        self._anim_timer.stop()

def _animate_step(self):
    if self._value >= 100:
        self.stop_animation()
        return
    self.set_value(self._value + self._anim_step)
```

**At its core, animation is just "a timer + changing data + update".** This matches everything we have said so far: change the data, call `update` to trigger a repaint, and let `paintEvent` do the drawing.

## Crash Site 1: QTimer Created Inside paintEvent, Repaints Run Wild

**Symptom: CPU usage spikes to 100% and `paintEvent` is being called frantically.**

```python
def paintEvent(self, event):
    painter = QPainter(self)
    # ...
    painter.end()
    self._timer = QTimer(self)          # ❌ Creating a timer inside paintEvent
    self._timer.timeout.connect(self._step)
    self._timer.start(16)
```

**Root cause: `paintEvent` is called repeatedly — on every `update`, on every repaint. Creating and starting a timer in there means spawning countless timers, each firing `update` and triggering yet more `paintEvent` calls. An infinite loop.**

**✅ Fix: create the timer once in `__init__` or a dedicated method; never inside `paintEvent`.**

```python
def __init__(self, parent=None):
    super().__init__(parent)
    self._value = 0
    self._timer = QTimer(self)                # ✅ Created once in the constructor
    self._timer.timeout.connect(self._step)
    self.setMinimumSize(150, 150)

def start_animation(self):
    self._timer.start(50)
```

## Crash Site 2: Animation Stops at 100 but the State Is Wrong

**Symptom: the animation stops at 100, but the ring colour is still blue instead of green, or `reached_100` fires only once and never again on the second run.**

```python
def _animate_step(self):
    self.set_value(self._value + self._anim_step)
    if self._value >= 100:          # ❌ Checking _value, but set_value already emitted
        self.stop_animation()
```

**Root cause: `set_value` already contains `if self._value == 100: emit reached_100`. Checking again here duplicates the logic and makes it easy to miss an emission or emit twice.**

**✅ Fix: let `set_value` be the single owner of state changes; the animation only "advances" and "stops at the top".**

```python
def _animate_step(self):
    if self._value >= 100:
        self.stop_animation()
        return
    self.set_value(self._value + self._anim_step)
```

**Keep all state transitions inside `set_value` (emitting signals, detecting 100); the animation is only responsible for advancing. That is the single-responsibility principle.**

## Crash Site 3: Progress Jitters Near the Bottom Because the Angle Wraps

**Symptom: dragging near the bottom of the ring makes the progress flicker between 99 and 0.**

```python
def _update_from_pos(self, pos):
    # ... angle calculation ...
    clockwise = (angle + 90) % 360
    self.set_value(clockwise / 360 * 100)   # Jumps at the 359° / 0° boundary
```

**Root cause: a tiny movement near 359° becomes 0°, so visually the progress "flips" across the top of the ring.**

**✅ Fix: add a dead zone, or record the starting angle on press and work in relative movement rather than absolute position.**

```python
def _update_from_pos(self, pos):
    cx = self.width() // 2
    cy = self.height() // 2
    dx = pos.x() - cx
    dy = pos.y() - cy
    import math
    angle = math.degrees(math.atan2(-dy, dx))
    if angle < 0:
        angle += 360
    clockwise = (angle + 90) % 360

    # Dead zone: near the top (0°), ignore jumps that are too large
    if 350 < clockwise < 360 or 0 <= clockwise < 10:
        if abs(clockwise - self._value / 100 * 360) > 20:
            return           # The jump is too large, so skip this update

    self.set_value(clockwise / 360 * 100)
```

**This is a "good enough" simplification. A production-grade control would compute relative movement from the press point to avoid absolute-angle wraparound entirely.**

## Full Assembly: Putting It in a Window

```python
from PySide6.QtWidgets import QApplication, QWidget, QPushButton, QVBoxLayout, QHBoxLayout

app = QApplication(sys.argv)
win = QWidget()
win.setWindowTitle("Circular Progress Indicator")

circle = CircleProgress()
circle.reached_100.connect(lambda: print("Reached 100%!"))

start_btn = QPushButton("Start")
stop_btn = QPushButton("Stop")
reset_btn = QPushButton("Reset")

start_btn.clicked.connect(lambda: circle.start_animation(2, 50))
stop_btn.clicked.connect(circle.stop_animation)
reset_btn.clicked.connect(lambda: circle.set_value(0))

h = QHBoxLayout()
h.addWidget(start_btn)
h.addWidget(stop_btn)
h.addWidget(reset_btn)

layout = QVBoxLayout(win)
layout.addWidget(circle)
layout.addLayout(h)
win.resize(300, 400)
win.show()
app.exec()
```

## Summary

- A painted ring = track (`drawEllipse`) + progress arc (`drawArc`) + centered text
- `set_value` should debounce (no signal on identical values) and own all state transitions
- Dragging to set progress requires coordinate → angle → progress conversion, including a y-axis flip
- Animation = `QTimer` + changing data + `update`; never create a timer inside `paintEvent`
- Keep state changes in `set_value`; the animation only advances — single responsibility
- The top of the ring is the angle-wraparound zone; dragging there may need a dead zone
- Custom signals are defined as `Signal()` class attributes and emitted with a value
