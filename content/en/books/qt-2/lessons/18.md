# Coordinate Transforms: translate, rotate, scale, and the State Stack

> Want to draw a needle that rotates around its center, a repeating pattern, or a fractal that scales to any size? Computing coordinates by hand is painful. `QPainter`'s built-in coordinate transforms plus a state stack let you manipulate a "local canvas" however you like.

## The Four Transform Methods

| Method | Effect | Analogy |
|---|---|---|
| translate(dx, dy) | Move the origin | Slide the paper right and down |
| rotate(angle) | Rotate around the origin (degrees, positive = clockwise) | Rotate the paper clockwise by `angle` |
| scale(sx, sy) | Scale | Stretch or compress the paper |
| shear(sh, sv) | Shear | Push the paper sideways into a slant |

**Key point: transforms accumulate, and they apply to coordinates in code order from right to left.**

```
def paintEvent(self, event):
    p = QPainter(self)
    p.setRenderHint(QPainter.RenderHint.Antialiasing)

    p.translate(160, 120)     # Move origin to window center
    p.rotate(30)              # Rotate 30° clockwise around the new origin
    p.scale(1.5, 1.5)         # Then scale up by 1.5x

    p.setBrush(QBrush(Qt.GlobalColor.blue))
    p.drawRect(0, 0, 40, 40)  # This rectangle now sits "out there" — rotated + scaled
```

The rectangle was supposed to be at the top-left. But because the coordinate system has been translated, rotated, and scaled, it appears at the window center, tilted 30°, and enlarged 1.5 times.

## The State Stack: save() and restore() Must Be Paired

Each call to `save()` pushes the current state (pen, brush, transform matrix, etc.) onto a stack; `restore()` pops it back. This is the only safe way to "isolate" a transform.

```
def paintEvent(self, event):
    p = QPainter(self)
    p.setRenderHint(QPainter.RenderHint.Antialiasing)

    # Draw an untransformed reference square
    p.setBrush(QBrush(Qt.GlobalColor.gray))
    p.drawRect(10, 10, 30, 30)

    p.save()                        # 1. Save
    p.translate(150, 120)
    p.rotate(45)
    p.setBrush(QBrush(Qt.GlobalColor.red))
    p.drawRect(-20, -20, 40, 40)   # Rotated 45° around its own center
    p.restore()                     # 2. Restore — transform and color revert to the save point

    # The coordinate system is normal again — safe to keep drawing
    p.setBrush(QBrush(Qt.GlobalColor.gray))
    p.drawRect(60, 10, 30, 30)      # Unaffected by the 45° rotation
```

## The Standard Recipe: Drawing a Rotating Shape Around Its Center

To draw an object rotating around its own center, the standard three steps are:

1. `translate(cx, cy)` — move the origin to the rotation center
2. `rotate(angle)` — rotate around it
3. Draw the shape using negative half-width coordinates (so it is symmetric around the origin)

```
p.translate(cx, cy)
p.rotate(self._angle)
p.setBrush(QBrush(Qt.GlobalColor.blue))
p.drawRect(-50, -6, 100, 12)   # A needle, centered on the origin, 100 long and 12 wide
```

## Crash Site 1: save/restore Mismatch, Transforms Keep Piling Up

**Symptoms: After every repaint (resize, uncover), the shape drifts to a weird position or angle; or the program gradually slows down.**

**WRONG — Do not do this:**

```
def paintEvent(self, event):
    p = QPainter(self)
    p.translate(160, 120)
    p.rotate(self._angle)
    p.drawRect(-20, -20, 40, 40)
    # Forgot p.restore()
```

**Why it fails:** Although the `QPainter` destructor clears the current state when `paintEvent` ends, the real trap is **calling `save()` in several places but only restoring some of them**, or returning early / raising an exception between `save()` and `restore()`, so `restore` never runs. Once a transform matrix leaks, every subsequent draw carries a mysterious extra rotation or translation.

**The fix: Pair `save` and `restore`, and keep them in the same scope:**

```
p.save()
try:
    p.translate(160, 120)
    p.rotate(self._angle)
    p.drawRect(-20, -20, 40, 40)
finally:
    p.restore()          # Runs on every code path
```

## Crash Site 2: Misusing resetTransform, Losing the Translation Too

**Symptoms: You only wanted to clear the rotation, but the translation disappeared as well.**

**WRONG — Do not do this:**

```
p.translate(150, 120)
p.rotate(45)
# ... draw rotated things ...
p.resetTransform()       # ALL transforms gone, including the translation
p.drawRect(0, 0, 30, 30)   # You expected (150,120); it's actually at (0,0)
```

**Why it fails:** `resetTransform()` is a "reset to zero" button, not "undo the last step."

**The fix:** Use `save/restore` for precise control, or `p.setTransform(QTransform())` for an explicit reset. If you only want to undo a block of transforms, `save/restore` is the right answer.

## Crash Site 3: Rotating Around the Origin Makes the Shape Fly Off-Screen

**Symptoms: After rotation the rectangle is gone, because its original coordinates were `(0,0,40,40)` — once rotated 180° around the origin it ends up outside the top-left corner.**

**WRONG — Do not do this:**

```
p.translate(160, 120)
p.rotate(180)
p.drawRect(0, 0, 40, 40)   # Rotated 180° around the origin, this rect sits at (-40,-40) relative to center
```

**The fix: Align the shape's center with the origin:**

```
p.translate(160, 120)
p.rotate(180)
p.drawRect(-20, -20, 40, 40)   # Centered on the origin, so it stays centered after rotation
```

## Summary

- `translate` / `rotate` / `scale` / `shear` change the coordinate system and accumulate
- `save()` saves state, `restore()` restores it — the only safe way to isolate transforms
- The two must be paired, preferably wrapped in `try/finally`
- The standard center-rotation recipe: translate to center -> rotate -> draw with negative half-widths
- `resetTransform` clears everything, not just one step
- A "flying away" shape after rotation usually means its center wasn't aligned with the origin

  class Pinwheel(QWidget):
      def __init__(self):

          t.start(30)

          self._angle += 3
          self.update()

      app = QApplication(sys.argv)
      w = Pinwheel()
      w.show()
      app.exec()

- Every blade is wrapped in save/restore
- The rotation animation is smooth and continuous
- The program displays correctly
