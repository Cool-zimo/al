# Database Support in Qt: The QtSql Module and QSqlTableModel

> Qt ships with its own database module, `QtSql` — no need to install SQLAlchemy to talk to SQLite, MySQL, or PostgreSQL. Even better, it integrates with the Model/View architecture out of the box: bind a table directly to a `QTableView` and it's editable immediately.

## The Module and Its Drivers

In PySide6, start with `from PySide6.QtSql import ...`. The commonly used classes:

| Class | Responsibility |
|---|---|
| QSqlDatabase | Database connection (the connect object for add/delete/query/modify) |
| QSqlQuery | Hand-written SQL: execute and iterate results |
| QSqlTableModel | A single-table Model; editable; can bind directly to a View |
| QSqlQueryModel | Read-only Model supporting arbitrary SELECTs |
| QSqlRelationalTableModel | A TableModel that supports foreign-key relations |

Check which drivers are available:

```
from PySide6.QtSql import QSqlDatabase
print(QSqlDatabase.drivers())
# Typical output: ['QSQLITE', 'QODBC', 'QPSQL', 'QMYSQL']
```

SQLite is built-in, needs zero configuration, and stores everything in a single file — ideal for practice and small desktop apps.

## The Complete Flow for Connecting to SQLite

```
import sys
from PySide6.QtWidgets import (QApplication, QTableView, QWidget,
                               QVBoxLayout, QPushButton, QHBoxLayout)
from PySide6.QtSql import QSqlDatabase, QSqlTableModel
from PySide6.QtCore import Qt

DB_PATH = "demo.db"

def init_db():
    db = QSqlDatabase.addDatabase("QSQLITE")
    db.setDatabaseName(DB_PATH)
    if not db.open():
        print("Failed to open database:", db.lastError().text())
        return False

    # Create table on first run
    q = QSqlQuery()
    q.exec("CREATE TABLE IF NOT EXISTS books ("
           "id INTEGER PRIMARY KEY AUTOINCREMENT,"
           "title TEXT NOT NULL,"
           "author TEXT,"
           "price REAL DEFAULT 0)")
    return True

def main():
    app = QApplication(sys.argv)
    if not init_db():
        sys.exit(1)

    window = QWidget()
    window.setWindowTitle("Book Manager")
    window.resize(600, 400)

    # Model: bound to the "books" table
    model = QSqlTableModel()
    model.setTable("books")
    model.setEditStrategy(QSqlTableModel.EditStrategy.OnRowChange)
    model.select()                       # YOU MUST call select(), or there is no data
    model.setHeaderData(0, Qt.Orientation.Horizontal, "ID")
    model.setHeaderData(1, Qt.Orientation.Horizontal, "Title")
    model.setHeaderData(2, Qt.Orientation.Horizontal, "Author")
    model.setHeaderData(3, Qt.Orientation.Horizontal, "Price")

    view = QTableView()
    view.setModel(model)
    view.setSelectionMode(QTableView.SelectionMode.SingleSelection)
    view.setSelectionBehavior(QTableView.SelectionBehavior.SelectRows)
    view.horizontalHeader().setStretchLastSection(True)

    btn_add = QPushButton("Add")
    btn_del = QPushButton("Delete Selected")

    def on_add():
        model.insertRow(model.rowCount())
    def on_del():
        idx = view.currentIndex()
        if idx.isValid():
            model.removeRow(idx.row())
            model.select()               # Refresh after deletion
    btn_add.clicked.connect(on_add)
    btn_del.clicked.connect(on_del)

    toolbar = QHBoxLayout()
    toolbar.addWidget(btn_add)
    toolbar.addWidget(btn_del)
    layout = QVBoxLayout(window)
    layout.addLayout(toolbar)
    layout.addWidget(view)
    window.show()
    app.exec()

if __name__ == "__main__":
    main()
```

## Three Key Details

**1. `QSqlDatabase` is a connection pool — use `addDatabase` to obtain one.**

The default connection (when you don't pass a second argument) is unique within the process. If you need multiple connections, pass distinct names: `QSqlDatabase.addDatabase("QSQLITE", "conn2")`.

**2. Call `db.close()` when you're done, but you usually don't need to close it manually before the process exits.**

`QSqlDatabase.removeDatabase(name)` explicitly removes a connection. Be especially careful with multiple connections: you can't remove a connection that other objects still reference.

**3. `EditStrategy` decides when changes are actually written to the database.**

| Strategy | When it commits |
|---|---|
| OnFieldChange | Each cell commits as soon as it loses focus (one transaction per edit) |
| OnRowChange | Commits when you move to another row |
| OnManualSubmit | Only commits on `submitAll()` — supports batch edits |

## Crash Site 1: Forgot db.open(), Every Query Returns Empty

**Symptoms: The program doesn't error out, but the table is empty, queries return nothing, and `model.rowCount()` is always 0.**

**WRONG — Do not do this:**

```
db = QSqlDatabase.addDatabase("QSQLITE")
db.setDatabaseName("demo.db")
# Forgot db.open()
model = QSqlTableModel()
model.setTable("books")
model.select()          # Silently returns False; rowCount is 0
```

**Why it fails:** `addDatabase` + `setDatabaseName` only *configure* the connection — they don't actually open it. Without `open()`, the file is never opened, and every subsequent operation targets an invalid connection.

**The fix:**

```
db = QSqlDatabase.addDatabase("QSQLITE")
db.setDatabaseName("demo.db")
if not db.open():
    print("Open failed:", db.lastError().text())
    sys.exit(1)
```

## Crash Site 2: Forgot select() on QSqlTableModel, Blank Table

**Symptoms: The table exists and has data, but `QTableView` refuses to show any rows.**

**WRONG — Do not do this:**

```
model = QSqlTableModel()
model.setTable("books")
# Forgot model.select()
view.setModel(model)
```

**Why it fails:** `setTable` only tells the Model *which* table to operate on — it does not load data. `select()` is the actual "go fetch data from the database" call.

**The fix:**

```
model.setTable("books")
model.select()          # Fetch the data
view.setModel(model)
```

## Crash Site 3: Database File in a Web/Temp Directory, Path Drifts

**Symptoms: Runs perfectly on your machine, but on another machine or in a different working directory it reports "no such table".**

**WRONG — Do not do this:**

```
db.setDatabaseName("demo.db")   # Relative path depends on the current working directory
```

**The fix:** Use an absolute path, or a Qt resource/application-data directory:

```
import os
db_path = os.path.join(os.path.dirname(os.path.abspath(__file__)), "demo.db")
db.setDatabaseName(db_path)
```

## Crash Site 4: Concurrent Access to One Connection Raises "database is locked"

**Symptoms:** Multiple threads reading and writing the same SQLite connection occasionally raise `database is locked`.

**Why:** SQLite uses file-level locking; a single connection allows only one write at a time. Qt's Model/View also uses it on the main thread.

**The fix:** Keep all database work on the main thread, create an independent connection per thread (with distinct connection names), or switch to a database engine that supports concurrency.

## Summary

- QtSql supports SQLite/MySQL/PostgreSQL, etc.; `QSqlDatabase.drivers()` shows what's available
- The standard sequence: addDatabase -> setDatabaseName -> open -> create table -> use a Model
- You must `open()`; you must `select()`
- `QSqlTableModel` binds directly to `QTableView` and is editable out of the box
- `EditStrategy` controls commit timing; `OnManualSubmit` suits batch edits
- Use absolute paths for database files to avoid working-directory drift
- SQLite serializes writes on a single connection; use separate connections for multiple threads
