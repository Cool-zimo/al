# Hand-Drawn Charts: Pie and Bar Charts with QPainter

> Chapter 4's drawing skills finally have real work to do. This lesson uses `QPainter` to draw a category-share pie chart and a monthly-trend bar chart — turning "I can draw" into "I can draw something meaningful".

## Why This Lesson Deserves Its Own Space

Chapter 4 was a practice round — we drew a speedometer. That was a warm-up. The charts in a ledger *are* a product feature, and the difference is important: a warm-up only has to look good, while a product feature has to **follow the data**. Swap the data and the chart must change; resize the window and the chart must rescale. Those two requirements decide the whole structure.

## ChartView: A QWidget That Accepts Data

A chart control only needs to do one thing: take data in and draw itself. It stays out of everything else.

```python
from PySide6.QtWidgets import QWidget
from PySide6.QtCore import Qt
from PySide6.QtGui import QPainter, QColor, QFont, QPen, QBrush

class ChartView(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._by_category = {}          # {category: total}
        self._by_month = {}             # {month: total}
        self.setMinimumHeight(260)

    def set_data(self, by_category, by_month):
        self._by_category = by_category
        self._by_month = by_month
        self.update()                  # triggers a paintEvent
```

**You must call `update()` after `set_data`.** This is the easiest line to forget. The data changes but nothing repaints, so the UI shows stale output and looks broken. `update()` is Qt's way of saying "please redraw me when you get a chance" — it triggers `paintEvent` asynchronously.

## paintEvent: All the Drawing Lives Here

```python
def paintEvent(self, event):
    painter = QPainter(self)
    painter.setRenderHint(QPainter.RenderHint.Antialiasing)

    rect = self.rect()
    left = rect.width() // 2            # pie on the left, bars on the right
    self._draw_pie(painter, rect.adjusted(0, 0, -left, 0))
    self._draw_bars(painter, rect.adjusted(left, 0, 0, 0))
```

**Each `QPainter` lives only inside one `paintEvent`.** You do not close it manually — it is destroyed when it goes out of scope. Chapter 4's warning about never storing a `QPainter` as a member variable matters even more here: Qt can call `paintEvent` at any time, and a long-lived painter will point at a device that has already gone away.

## The Pie Chart: How Angles Are Calculated

The key to a pie chart is mapping **data value → angle span**. Qt's angle unit is **one-sixteenth of a degree**, so `360° = 5760`. Compute the degrees, then multiply by 16:

```python
def _draw_pie(self, painter, rect):
    total = sum(self._by_category.values())
    if not self._by_category or total == 0:
        painter.drawText(rect, Qt.AlignmentFlag.AlignCenter, "No data yet")
        return

    colors = [QColor(66,133,244), QColor(52,168,83), QColor(251,188,4),
              QColor(234,67,53), QColor(154,76,175), QColor(0,172,193)]

    cx = rect.center().x()
    cy = rect.center().y()
    radius = min(rect.width() - 120, rect.height()) // 2 - 10
    x = cx - radius
    y = cy - radius
    size = radius * 2
    box = (x, y, size, size)

    start_angle = 0
    legend_y = rect.top() + 10
    for i, (cat, val) in enumerate(self._by_category.items()):
        span = int(360 * 16 * abs(val) / total)
        color = colors[i % len(colors)]
        painter.setBrush(QBrush(color))
        painter.setPen(Qt.PenStyle.NoPen)
        painter.drawPie(x, y, size, size, start_angle, span)
        start_angle += span

        # Legend
        painter.setBrush(QBrush(color))
        painter.drawRect(rect.right() - 110, legend_y, 12, 12)
        painter.setPen(QPen())
        painter.drawText(rect.right() - 92, legend_y + 10,
                         f"{cat} £{abs(val):.0f}")
        legend_y += 22
```

**Always use `abs(val)` for the pie chart.** Expenses are negative, so passing the raw value would give a negative span. Qt will draw it, but the wedge goes in reverse and looks odd. For display purposes you only care about the share, so take the absolute value.

## The Bar Chart: Coordinate Transformation Is the Real Work

The hard part of a bar chart is not drawing a rectangle — it is **mapping the data value into a pixel height**. That takes three steps: find the maximum to set the scale, compute each bar's width, and compute the y coordinate of the bar's top:

```python
def _draw_bars(self, painter, rect):
    if not self._by_month:
        painter.drawText(rect, Qt.AlignmentFlag.AlignCenter, "No data yet")
        return

    months = sorted(self._by_month.keys())
    values = [abs(self._by_month[m]) for m in months]
    max_val = max(values) or 1

    margin = 30
    top = rect.top() + margin
    bottom = rect.bottom() - margin
    plot_height = bottom - top
    left = rect.left() + margin
    right = rect.right() - margin
    slot = (right - left) / len(months)
    bar_w = min(40, slot * 0.6)

    # Baseline
    painter.setPen(QPen(Qt.GlobalColor.gray))
    painter.drawLine(left, bottom, right, bottom)

    for i, (m, v) in enumerate(zip(months, values)):
        h = int(plot_height * v / max_val)
        bx = int(left + slot * i + (slot - bar_w) / 2)
        by = bottom - h
        painter.setBrush(QBrush(QColor(66,133,244)))
        painter.setPen(Qt.PenStyle.NoPen)
        painter.drawRect(bx, by, int(bar_w), h)

        # X-axis label
        painter.setPen(QPen())
        painter.drawText(bx, bottom + 16, m[-2:])       # show 09 / 10

        # Value above the bar
        painter.drawText(bx, by - 4, f"{v:.0f}")
```

**The scale factor is `v / max_val`, not `v / sum`.** A pie chart divides by the total; a bar chart divides by the maximum so the tallest bar reaches the top of the plotting area and the visual comparison is clear.

## Resizing with the Window

Because every coordinate is **computed on the fly from `rect()`**, a resize triggers `paintEvent` automatically and the chart rescales with the window. That is one of the biggest advantages of hand-drawing over a matplotlib image.

**This only works if you do not cache the pixel map.** The moment you `render` the chart into a `QPixmap` and store it, resizing stops working. The whole point of hand-drawing is "compute it fresh every time".

## How to Choose Between the Two Approaches

| | QPainter hand-drawn | matplotlib embedded |
|---|---|---|
| Dependency | None — ships with PySide6 | Needs matplotlib installed separately |
| Resizing | Vector, always crisp | Bitmap goes fuzzy (dpi can be tuned) |
| Development speed | You compute every coordinate | `plt.pie()` does it in one line |
| Styling | You draw the legend and labels yourself | Legend and annotations built in |
| Bundle size | Almost no increase | Adds tens of MB |
| Best for | Embedded small charts, simple visualisation | Scientific plots, 3D, exporting high-res figures |

**The rule of thumb: hand-drawn `QPainter` for functional small charts, matplotlib for presentation and research.** Category share and monthly trend in a ledger are clearly the former — modest information, rescaling with the window, and no desire to carry matplotlib's weight.

## Wiring the Chart into the Main Window

The model computes the aggregates, the window feeds them in, and nothing is stored in between:

```python
def refresh(self):
    self.model.refresh()
    self.chart.set_data(
        self.model.total_by_category(),
        self.model.total_by_month(),
    )
```

**One `refresh` updates both the table and the chart.** That is the dividend of Model/View layering: the data is fetched once and each view takes what it needs.

## Crash Site 1: Forgetting update() After set_data

**Symptom:** The code clearly ran, `_by_category` holds new data, but the chart does not move.

**The fix:**

```python
def set_data(self, by_category, by_month):
    self._by_category = by_category
    self._by_month = by_month
    self.update()                  # required
```

## Crash Site 2: Pie Angle Not Multiplied by 16, Draws a Sliver

**Symptom:** You pass `360` to `drawPie(x, y, w, h, start, span)` expecting a full circle and get a wedge of 22.5° instead.

**Cause:** Qt's angle unit is 1/16 of a degree.

**The fix:**

```python
span = int(360 * 16 * abs(val) / total)
```

## Crash Site 3: Negative Expenses Make the Pie Wedge Draw Backwards

**Symptom:** The pie wedge unfolds counter-clockwise, or a negative span raises an error outright.

**The fix: use `abs(val)` when computing the angle span.**

## Crash Site 4: Bar Chart Drawn Outside the Plotting Area

**Symptom:** The bottom of a bar extends past the window, or the top coordinate ends up negative.

**Cause:** `bottom - h` with `h` larger than `plot_height` puts `by` above `top`.

**The fix: keep the scale factor such that `h <= plot_height`.**

```python
h = int(plot_height * v / max_val)     # max_val is the largest value in the set
assert h <= plot_height                # handy during development
```

## Crash Site 5: Storing QPainter as self.painter

**Symptom:** Crashes intermittently after the first paint, or later draws land on the wrong device entirely.

**The fix: create the QPainter inside `paintEvent` and let it die when the function returns. Never store it as a member variable.**

## Crash Site 6: Pie and Bars Overlap Because They Share One Rect

**Symptom:** The two charts are drawn on top of each other and are unreadable.

**The fix: use `rect.adjusted()` to split the area in half, and draw each into its own half.**

```python
left_w = rect.width() // 2
self._draw_pie(painter, rect.adjusted(0, 0, -left_w, 0))
self._draw_bars(painter, rect.adjusted(left_w, 0, 0, 0))
```

## Crash Site 7: Font Size Stays Fixed, Labels Crowd at Small Widths

**Symptom:** The bars get thinner as the window shrinks, but the font is still 9pt, so the labels overlap.

**The fix: scale the font size against `rect` as well, or simply skip labels (show every other one).** This is the price of hand-drawing — matplotlib auto-avoids collisions, and you write that logic yourself.

## Summary

- `ChartView(QWidget)` exposes only `set_data` to receive data
- `set_data` must call `update()` to trigger a repaint
- `QPainter` is created only inside `paintEvent`; never store it as a member
- Pie-chart angles use 1/16-degree units, so multiply by 16
- Pie charts use `abs(val)` for the span to avoid negative-reverse wedges
- Bar charts use `v / max_val` so the tallest bar reaches the top
- Computing coordinates on the fly makes the chart follow the window as it resizes
- Hand-drawn `QPainter` for embedded charts; matplotlib for scientific and research plots
