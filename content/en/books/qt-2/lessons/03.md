# Getting Started with QStandardItemModel: The Go-To Ready-Made Model

> Don't want to write a custom model but need Model/View flexibility? QStandardItemModel is Qt's "half-sugar" solution: a built-in data container you can use right away — get the pipeline running first, customize later.

## What Is QStandardItemModel?

**It is Qt's predefined generic model: internally it stores data in a tree of QStandardItem objects. It works out of the box — no subclassing required.** Think of it as the version where "data container" is extracted from QTableWidget and handed to you separately, while the view stays the same.

QTableWidget does everything in one shot. QStandardItemModel gives you the "data container" to use on its own, and the view remains just a view. You create the model, stuff items into it, then call `setModel`.

```python
from PySide6.QtWidgets import QApplication, QTableView
from PySide6.QtGui import QStandardItemModel, QStandardItem

app = QApplication([])

model = QStandardItemModel(3, 2)          # 3 rows, 2 columns
model.setHorizontalHeaderLabels(["Name", "Score"])

model.setItem(0, 0, QStandardItem("Alice"))
model.setItem(0, 1, QStandardItem("92"))
model.setItem(1, 0, QStandardItem("Bob"))
model.setItem(1, 1, QStandardItem("85"))

view = QTableView()
view.setModel(model)
view.show()
app.exec()
```

**See? It is almost identical to QTableWidget — only `table.setItem` becomes `model.setItem`.** The difference: now the model manages data and the view is just a canvas. That difference starts paying dividends immediately.

## Adding: Insert Row and Append Row

**QStandardItemModel provides `appendRow`, `insertRow`, and batch item-setting for a row.**

```python
# Append a row: pass a group of items directly
model.appendRow([QStandardItem("Charlie"), QStandardItem("77")])

# Insert a row at a specific position
model.insertRow(1, [QStandardItem("Dave"), QStandardItem("88")])

# Create an empty row first, then fill cell by cell
model.appendRow([])
model.setItem(model.rowCount() - 1, 0, QStandardItem("Eve"))
```

**Here is a subtle point: appendRow emits dataChanged / rowsInserted signals, and the view refreshes automatically.** You do not need to manually call `view.update()` — this is the model's "notification" mechanism at work (covered in depth in lesson 05).

**QStandardItem also comes with per-cell styling built in.** This is where it is more convenient than a pure-data model.

```python
item = QStandardItem("99")
item.setForeground(QColor("green"))       # Green text
item.setBackground(QColor("yellow"))      # Yellow background
item.setTextAlignment(Qt.AlignCenter)     # Center alignment
item.setEditable(False)                   # Not editable
item.setToolTip("Perfect score")
model.setItem(0, 1, item)
```

## Reading: Three Ways to Get Values

**There are several paths to retrieving a cell's value — pick by scenario.**

```python
# Method 1: item() directly
item = model.item(0, 1)
if item is not None:
    value = item.text()

# Method 2: get item via index (more "model-idiomatic")
index = model.index(0, 1)
item = model.itemFromIndex(index)
text = item.text()

# Method 3: use model.data() to ask for DisplayRole directly
value = model.data(model.index(0, 1), Qt.DisplayRole)
```

**Method 1 is most intuitive; method 3 is most "orthodox."** Method 1 gives you the QStandardItem object itself, letting you modify its color and alignment. Method 3 only returns a value without touching item properties.

## Crash Site 1: Using the Wrong Role to Read Numbers — Comparisons Break

**Symptom: You stored "92", got back a string, and the sort produced "9" > "100".**

```python
item = model.item(0, 1)
score = item.text()          # This is a str: "92"
scores = [item.text() for item in model.findItems("", Qt.MatchContains)]

# ❌ Sort as strings
scores.sort()                # ['100', '85', '9']
```

**Root cause: QStandardItem stores everything as text by default; `text()` always returns a string.**

**✅ Fix: Use `setData` to store a numeric role; specify UserRole when reading.**

```python
item = QStandardItem()
item.setData(92, Qt.UserRole)         # Store int
item.setText("92")                    # Display stays as text

# Read back
val = item.data(Qt.UserRole)          # 92, int
```

**QStandardItem's `setData(value, role)` can attach any role.** Use DisplayRole for display (text) and UserRole for logical values (int). The key technique this lesson: "each role handles its own concern."

## Modifying: Changes Must Be Notified

**When you modify a QStandardItem's text or data, it automatically emits the dataChanged signal.** This is where it is "smart" — because the item is its own creation, it knows you are changing it.

```python
item = model.item(0, 1)
item.setText("99")           # ✅ Automatically notifies the view to refresh

item.setData(99, Qt.UserRole) # ✅ Also notifies
```

**This automatic notification is implemented inside QStandardItem, not magic from the model.** Whether you use `setItem` to replace an entire item or `setText` to change text, it triggers. But if you bypass the item and directly mutate its internal data (e.g., grabbing a custom object and forcing a property change), no notification fires.

## Deleting: removeRow and clear

```python
model.removeRow(2)           # Delete row 2
model.removeRows(1, 3)       # Delete 3 rows starting at row 1
model.clear()                # Clear all data (keeps column headers! Headers get cleared too)
```

**`clear()` also clears the header labels.** This is a common trap, covered in Crash Site 2 below.

## Crash Site 2: After clear(), the Header Is Gone — Blank Screen

**Symptom: You click "Reset," which calls `model.clear()`, then re-populate the data. The column names (Name/Score) are missing.**

```python
model.clear()
# ❌ At this point horizontalHeaderLabels are also gone
model.appendRow([QStandardItem("Alice"), QStandardItem("92")])
# Data displays, but the first row has no "Name"/"Score" labels
```

**Root cause: `clear()` empties the entire model contents, including headers.** The documentation states this clearly, but nobody reads the docs.

**✅ Fix: Re-set headers after clearing, or only delete data rows without touching headers.**

```python
# Method 1: re-set headers after clear
model.clear()
model.setHorizontalHeaderLabels(["Name", "Score"])

# Method 2: only delete data rows, preserve headers
model.removeRows(0, model.rowCount())
```

**Method 2 is safer.** Your header definition lives in one place — don't write it twice (clear once, set once); that is duplicate maintenance waiting to drift apart.

## Crash Site 3: findItems Only Searches DisplayRole — Numeric Lookup Fails

**Symptom: You want to find the row with a score of 92, but `findItems` returns an empty list.**

```python
item = QStandardItem()
item.setData(92, Qt.UserRole)      # Stored in a numeric role
item.setText("92")

found = model.findItems("92")      # ✅ Found, because DisplayRole is "92"
found2 = model.findItems(92)       # ❌ Not found; findItems matches DisplayRole as string
```

**Root cause: `findItems` matches by DisplayRole text. Passing a number gets converted to string for comparison — easy to trip over.**

**✅ Fix: Either ensure DisplayRole is the string you want to search, or iterate manually.**

```python
# Manual iteration with exact UserRole matching
def find_by_score(model, score):
    for r in range(model.rowCount()):
        item = model.item(r, 1)
        if item.data(Qt.UserRole) == score:
            yield r

list(find_by_score(model, 92))     # [0]
```

## Summary

- QStandardItemModel is a ready-to-use generic model — no subclassing required
- Usage is close to QTableWidget; only `table.setItem` becomes `model.setItem`
- Add with appendRow/insertRow, delete with removeRow, read with item/data approaches
- QStandardItem has built-in styling: colors, alignment, editability, tooltips
- Store numbers in UserRole; otherwise text() returns strings and comparisons break
- `clear()` clears headers too; to clear only data, use removeRows(0, rowCount())
- findItems matches DisplayRole text; for numeric lookup, iterate manually
