# Getting Started with QPainter

> Want to draw a line, a circle, or a piece of text on a window? In PySide6 every custom paint operation comes back to one class — `QPainter` — and it has exactly one valid home: `paintEvent`.

## Why Drawing Must Live Inside paintEvent

Qt's painting model has one hard rule: **only a `QPainter` created inside `paintEvent` is "active."** When the window first appears, when it's uncovered after being hidden behind another window, or when you call `update()` to request a redraw, Qt dispatches a paint event. You grab the canvas, paint what you need, and leave. Any use of `QPainter` outside that scope is invalid.

```
import sys
from PySide6.QtWidgets import QApplication, QWidget
from PySide6.QtCore import Qt
from PySide6.QtGui import QPainter, QPen

class Canvas(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("First Strokes")
        self.resize(300, 200)

    def paintEvent(self, event):
        painter = QPainter(self)              # 1. Canvas = the current window
        painter.setRenderHint(QPainter.RenderHint.Antialiasing)
        pen = QPen(Qt.GlobalColor.blue)       # 2. Pen: color, width, line style
        pen.setWidth(3)
        painter.setPen(pen)
        painter.drawLine(20, 30, 280, 170)    # 3. Draw a line
        painter.end()                         # 4. Explicitly end (auto-ended on scope exit too)

if __name__ == "__main__":
    app = QApplication(sys.argv)
    w = Canvas()
    w.show()
    app.exec()
```

The three objects each have a distinct job:

| Object | Responsibility | Common settings |
|---|---|---|
| QPainter | The toolbox that actually applies paint | setPen / setBrush / drawXxx |
| QPen | The outline (border, lines) | Color, width, line style (solid/dash), cap style |
| QBrush | The fill (inside closed shapes) | Solid color, texture, gradient |

## When Does a Repaint Happen?

You don't refresh the window yourself — Qt dispatches `paintEvent` automatically in these situations:

1. The window appears for the first time
2. The window was hidden behind another and becomes visible again
3. The window is resized, moved, or dragged to another screen
4. You call `self.update()` (recommended — multiple calls are merged into one redraw)
5. You call `self.repaint()` (synchronous, blocks until done, use sparingly)

**Never call `update()` or `repaint()` inside `paintEvent`** — that creates an infinite recursive paint loop.

## Storing "What to Draw" in Member Variables

`paintEvent` is被动ly triggered. Its `event` parameter only tells you "it's time to paint" — it carries no information about *what* you want on screen. So the things you want to draw must live as member variables; `paintEvent` reads them. When you want to change the picture, you change the data and call `update()`:

```
class Canvas(QWidget):
    def __init__(self):
        super().__init__()
        self._points = []          # Store points
        self._color = Qt.GlobalColor.red

    def mousePressEvent(self, event):
        self._points.append(event.position().toPoint())
        self.update()              # Data changed — request a repaint

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setPen(QPen(self._color, 6))
        for p in self._points:
            painter.drawPoint(p)
```

## Crash Site 1: Using QPainter Outside paintEvent

**Symptoms: The program crashes on launch, and the console prints:**

```
QPainter::begin: Painter already active
QPainter::setPen: Painter not active
```

**WRONG — Do not do this:**

```
class Canvas(QWidget):
    def __init__(self):
        super().__init__()
        painter = QPainter(self)          # The window isn't shown yet; the canvas is not ready
        painter.drawLine(0, 0, 100, 100) # This line raises "Painter not active"
```

**Why it fails:** `QPainter`'s constructor needs a paint device that is "ready to be painted on." Before the first show, and outside `paintEvent`, that condition is not met. Even if it didn't crash, anything you draw in `__init__` would be erased the moment Qt calls `paintEvent` again.

**The fix:** Keep every drawing call inside `paintEvent`. Other methods only mutate data and call `update()`.

```
def mousePressEvent(self, event):
    self._points.append(event.position().toPoint())
    self.update()          # Let Qt call paintEvent at the right time

def paintEvent(self, event):
    painter = QPainter(self)
    ...
```

## Crash Site 2: Forgetting update(), Nothing Happens

**Symptoms: You click ten times; the window stays blank; no error in the console.**

**WRONG — Do not do this:**

```
def mousePressEvent(self, event):
    self._points.append(event.position().toPoint())
    # Forgot self.update() — paintEvent never runs
```

**Why it fails:** Qt has no idea your data changed. `paintEvent` only fires when Qt decides a repaint is needed. Appending to a list does not trigger it.

**The fix:** Call `self.update()` immediately after changing the data. `update()` is asynchronous and coalescing — calling it 100 times in one millisecond still results in a single `paintEvent`, so don't hesitate to call it freely.

## Summary

- All drawing code must live inside `paintEvent(self, event)`
- `QPainter` handles *how* to draw, `QPen` handles line style, `QBrush` handles fills
- What you draw is stored in member variables; `paintEvent` reads them
- After changing data, call `self.update()` to request a repaint
- Never call `update()` / `repaint()` inside `paintEvent`
- `repaint()` blocks the UI — stick with `update()` for daily use
