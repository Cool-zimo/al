# QSqlQuery and Hand-Written SQL: Parameterized Queries, Iterating Results, and Transactions

> When you need joins, aggregation, or complex conditions, a Model isn't enough. `QSqlQuery` lets you write SQL directly — but you must follow two iron rules: **always parameterize, and always check the exec return value.**

## A Complete Query

```
from PySide6.QtSql import QSqlQuery, QSqlDatabase

def list_books():
    q = QSqlQuery()
    ok = q.exec("SELECT id, title, price FROM books ORDER BY price DESC")
    if not ok:
        print("Query failed:", q.lastError().text())
        return

    while q.next():
        book_id = q.value(0)        # By column index
        title = q.value("title")    # By column name (more readable)
        price = q.value("price")
        print(f"[{book_id}] {title} - ¥{price}")
```

`q.next()` advances the internal pointer to the next row; it returns `False` when iteration ends (no exception, no `StopIteration`).

## Parameterized Queries: Preventing SQL Injection

**Never build SQL strings with f-strings**, especially when the content comes from user input.

```
# WRONG (dangerous!)
name = input("Book title: ")
q.exec(f"SELECT * FROM books WHERE title = '{name}'")   # SQL injection hole

# RIGHT: positional placeholders
q = QSqlQuery()
q.prepare("SELECT * FROM books WHERE price BETWEEN ? AND ? AND author = ?")
q.addBindValue(20.0)            # 1st ?
q.addBindValue(100.0)          # 2nd ?
q.addBindValue("鲁迅")          # 3rd ?
q.exec()

# Or named placeholders (Qt supports :name syntax)
q.prepare("SELECT * FROM books WHERE author = :author")
q.bindValue(":author", "鲁迅")
q.exec()
```

Once parameterized, even if a user enters `'; DROP TABLE books; --`, it's treated as an ordinary string literal and never executed as SQL.

## Insert, Update, Delete

```
q = QSqlQuery()
q.prepare("INSERT INTO books (title, author, price) VALUES (?, ?, ?)")
q.addBindValue("Intro to Qt")
q.addBindValue("Zhang San")
q.addBindValue(59.9)
if not q.exec():
    print("Insert failed:", q.lastError().text())

# Update
q.prepare("UPDATE books SET price = ? WHERE id = ?")
q.addBindValue(69.9)
q.addBindValue(1)
q.exec()

# Delete
q.prepare("DELETE FROM books WHERE price < ?")
q.addBindValue(10.0)
q.exec()
```

## Transactions: All or Nothing

SQLite wraps each statement in its own transaction by default. For multiple statements that must "succeed together or fail together," take control manually:

```
db = QSqlDatabase.database()     # Get the default connection
db.transaction()                 # Begin transaction

q1 = QSqlQuery()
q2 = QSqlQuery()
ok1 = q1.exec("UPDATE accounts SET balance = balance - 100 WHERE id = 1")
ok2 = q2.exec("UPDATE accounts SET balance = balance + 100 WHERE id = 2")

if ok1 and ok2:
    db.commit()
    print("Transfer succeeded")
else:
    db.rollback()
    print("Transfer failed; rolled back")
```

## Crash Site 1: Building SQL with f-strings, Breaks on an Apostrophe

**Symptoms: A title containing a single quote causes `near "s": syntax error`.**

**WRONG — Do not do this:**

```
title = "O'Reilly Books"
q.exec(f"INSERT INTO books (title) VALUES ('{title}')")
# SQL: INSERT INTO books (title) VALUES ('O'Reilly Books')  <- syntax error
```

**The fix: Use parameters and let Qt handle escaping.**

```
q.prepare("INSERT INTO books (title) VALUES (?)")
q.addBindValue(title)
q.exec()
```

## Crash Site 2: Not Checking exec, "Silent Success"

**Symptoms: You misspelled something in the SQL (e.g., the table name), the program doesn't error out, but the data never gets inserted.**

**WRONG — Do not do this:**

```
q.exec("SELCT * FROM books")    # Missing an E
# No return-value check, so it fails silently
```

**The fix: Check the return value of every exec and print `lastError`.**

```
if not q.exec(sql):
    print("SQL execution failed:", q.lastError().text())
```

## Crash Site 3: Wrong Data Type When Iterating

**Symptoms: The price you retrieved is the string `"59.9"`, so adding it performs string concatenation instead.**

**Why:** Qt returns data as `QVariant` by default; `q.value()` can hand back any type. SQLite doesn't strictly distinguish REAL from TEXT — values come back as they were stored.

**The fix: Cast explicitly.**

```
price = float(q.value("price"))     # Cast to float before calculating
count = int(q.value(0))             # Cast to int
```

## Crash Site 4: Mixed Connections Inside a Transaction, Commit Never Applies

**Symptoms: You call `db.transaction()` on one connection but execute statements on another, so each still runs in its own transaction.

**Why:** Transactions are **per-connection**. Connection A begins a transaction; statements executed on connection B are not part of it.

**The fix: Make sure `transaction` / `exec` / `commit` all use the same `QSqlDatabase` connection.**

## Crash Site 5: Calling value() Before next(), Getting Nothing

**Symptoms: The query returns results, but `q.value(0)` gives `None`.

**WRONG — Do not do this:**

```
q.exec("SELECT COUNT(*) FROM books")
count = q.value(0)          # No next() yet — pointer is "before the first row"
```

**The fix:**

```
q.exec("SELECT COUNT(*) FROM books")
if q.next():
    count = q.value(0)
```

## Summary

- `QSqlQuery` is for hand-written SQL, suited to complex queries
- Iterate with `while q.next(): q.value(idx or column_name)`
- Always use `prepare` + `addBindValue` / `bindValue` for parameters, eliminating SQL injection
- Check the exec return value and inspect `lastError` after every call
- Transactions: `db.transaction` / `commit` / `rollback`, scoped to a connection
- Cast retrieved values explicitly (`float` / `int`)
- You must call `next()` before retrieving values
