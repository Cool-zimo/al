# Full Custom Painting: Subclassing QWidget and Painting Only Inside paintEvent

> Subclassing got you 90% there, but the shape you need does not exist as a widget — ring progress, waveform, dashboard. Now you go all the way: subclass `QWidget` and paint it yourself with `QPainter`. The one rule that cannot be broken is that the painting happens inside `paintEvent`.

## The Smallest Custom Widget

**A `QWidget` with an overridden `paintEvent` is the starting point for everything hand-painted.**

```python
from PySide6.QtCore import Qt
from PySide6.QtGui import QPainter, QColor
from PySide6.QtWidgets import QWidget, QApplication

class DotCanvas(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._points = []
        self.setMinimumSize(300, 300)

    def mousePressEvent(self, event):
        self._points.append(event.position().toPoint())
        self.update()              # Ask Qt to repaint

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setRenderHint(QPainter.Antialiasing)
        painter.setPen(Qt.NoPen)
        painter.setBrush(QColor("#f44336"))
        for p in self._points:
            painter.drawEllipse(p, 8, 8)
        painter.end()

app = QApplication(sys.argv)
win = QWidget()
canvas = DotCanvas()
# ...
```

**The cycle is always the same: event handler mutates data, calls `update()`, and `paintEvent` renders from that data.**

## Crash Site 1: Constructing QPainter Outside paintEvent, Errors and Artefacts

**Symptom: `QPainter::begin: Painter already active` or `QPainter::end: Painter not active` appears in the console; the widget flickers or draws garbage.**

```python
class BadWidget(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._painter = QPainter(self)      # ❌ Constructed outside paintEvent
        # The widget has no valid paint device yet
```

**Root cause: a `QPainter` needs a live paint device (the widget's backing store) that is only valid during a paint operation. Creating it elsewhere either has no device or races with the paint system.**

**✅ Fix: construct and use `QPainter` strictly inside `paintEvent`.**

```python
def paintEvent(self, event):
    painter = QPainter(self)          # ✅ Valid here
    # ... draw ...
    painter.end()
```

## Crash Site 2: Painting Inside an Event Handler, Drawing Disappears on Repaint

**Symptom: you paint a red dot in `mousePressEvent`. It shows up once, then vanishes the next time the widget repaints; sometimes you also see errors.**

```python
def mousePressEvent(self, event):
    painter = QPainter(self)
    painter.setPen(Qt.red)
    painter.drawPoint(event.position().toPoint())   # ❌ Painting straight inside the event handler
    painter.end()
```

**Root cause: drawing outside `paintEvent` is not retained. Qt may repaint at any moment — when uncovered, on resize, or after `update()` — and your dot is gone. The paint-device state may also be invalid.**

**✅ Fix: store data in the handler, call `update()`, and paint in `paintEvent`.**

```python
def mousePressEvent(self, event):
    self._points.append(event.position().toPoint())
    self.update()              # Mark dirty; Qt calls paintEvent

def paintEvent(self, event):
    painter = QPainter(self)
    painter.setPen(Qt.red)
    for p in self._points:
        painter.drawPoint(p)
    painter.end()
```

**This is the iron rule: paint only in `paintEvent`; in event handlers, mutate data and call `update()`.**

## Coordinate Systems and What You Can Draw

**Coordinates inside a widget are local: the origin is the widget's own top-left, not the screen's. `event.position().toPoint()` already gives you this local coordinate.**

**Common drawing primitives:**

```python
def paintEvent(self, event):
    painter = QPainter(self)
    painter.setRenderHint(QPainter.Antialiasing)

    # Lines and rectangles
    painter.setPen(QColor("#333333"))
    painter.drawLine(0, 0, self.width(), self.height())
    painter.setBrush(QColor("#90caf9"))
    painter.drawRect(10, 10, 100, 60)

    # Ellipse and arc
    painter.setBrush(QColor("#ef5350"))
    painter.drawEllipse(120, 10, 60, 60)

    # Centered text
    painter.setPen(QColor("#212121"))
    font = painter.font()
    font.setPointSize(20)
    painter.setFont(font)
    painter.drawText(self.rect(), Qt.AlignCenter, "Hello")

    painter.end()
```

**Remember to end the painter. Python's scoping usually cleans up, but an explicit `painter.end()` is good discipline — and essential if you return early from `paintEvent`.**

## Crash Site 3: Forgetting painter.end(), Resource Leak

**Symptom: after many repaints, the application slows down or logs warn about an active painter.**

```python
def paintEvent(self, event):
    painter = QPainter(self)
    painter.setBrush(QColor("#4caf50"))
    painter.drawRect(self.rect())
    # ❌ No painter.end()
    if something:
        return             # Early return while the painter is still active
```

**✅ Fix: always end the painter, and use `try`/`finally` if you may return early.**

```python
def paintEvent(self, event):
    painter = QPainter(self)
    try:
        painter.setBrush(QColor("#4caf50"))
        painter.drawRect(self.rect())
        if not self._visible:
            return             # Safe: finally still runs
    finally:
        painter.end()          # ✅ Always paired
```

## When to Call update()

**`update()` schedules a repaint; it does not paint immediately. Qt coalesces multiple `update()` calls into one paint event — so calling it 100 times in a loop results in (at most) one repaint.**

```python
def mouseMoveEvent(self, event):
    self._points.append(event.position().toPoint())
    self.update()              # Safe to call frequently; Qt batches it
```

**`repaint()` forces an immediate synchronous paint. Use it only when you truly need it — it can cause re-entrancy and is rarely the right answer in a paint handler.**

## A Hand-Painted Gauge

**Drawing 100 tick marks as one widget instead of 100 labels:**

```python
import math
from PySide6.QtCore import Qt
from PySide6.QtGui import QPainter, QColor

class Gauge(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._value = 0
        self.setMinimumSize(200, 200)

    def set_value(self, value):
        self._value = max(0, min(100, int(value)))
        self.update()

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setRenderHint(QPainter.Antialiasing)
        cx, cy = self.width() // 2, self.height() // 2
        radius = min(cx, cy) - 20

        # Tick marks
        painter.setPen(QColor("#90a4ae"))
        for angle in range(0, 181, 9):
            rad = math.radians(angle)
            x1 = cx + radius * math.cos(rad)
            y1 = cy - radius * math.sin(rad)
            x2 = cx + (radius - 8) * math.cos(rad)
            y2 = cy - (radius - 8) * math.sin(rad)
            painter.drawLine(int(x1), int(y1), int(x2), int(y2))

        # Value arc
        painter.setPen(QColor("#f44336"))
        span = int(-self._value * 3.6 * 16)
        rect = self.rect().adjusted(20, 20, -20, -20)
        painter.drawArc(rect, 90 * 16, span)

        painter.end()
```

**One widget, one paint event, one loop — far cheaper than 100 widget objects each with its own handle and event handling.**

## Summary

- Subclass `QWidget` and override `paintEvent` for anything that needs a brand-new shape
- A `QPainter` must be constructed and used only inside `paintEvent`
- Never paint in an event handler; store data, call `update()`, paint in `paintEvent`
- Coordinates are local to the widget; `event.position().toPoint()` is already in that space
- End the painter, preferably with `try`/`finally`
- `update()` is asynchronous and coalesced; `repaint()` is immediate and rarely needed
- Loops of repeated marks belong in one paint pass, not in dozens of child widgets
