# Custom Sorting and Filtering: lessThan and filterAcceptsRow

> Default string sorting is not enough. You want "Pending < In Progress < Done", or sorting by date, or showing only rows "where the amount is over 1000 and the status is not Done". For these you must write your own logic — subclass the proxy and override `lessThan` and `filterAcceptsRow`.

## lessThan: You Decide How Two Rows Compare

**`lessThan(left, right)` returns `True` when `left` should appear before `right`. The default implementation compares text via `DisplayRole`.**

```python
from PySide6.QtCore import QSortFilterProxyModel, Qt

class StatusSortProxy(QSortFilterProxyModel):
    def lessThan(self, left, right):
        # left/right are QModelIndex values in the source model's coordinate space
        left_val = self.sourceModel().data(left, Qt.DisplayRole)
        right_val = self.sourceModel().data(right, Qt.DisplayRole)
        return left_val < right_val       # Default behavior: text comparison
```

**The crucial point: `left` and `right` are already indexes in the source model's coordinate space.** The proxy has already done the `mapToSource` for you, so you can feed them straight to `sourceModel().data()`.

**Why source coordinates?** Sorting is an internal state of the proxy. The proxy knows "which row of the source I am comparing", and hands you the most primitive information; you decide how to compare it.

## Crash Site 1: Calling mapToSource on Indexes That Are Already Source Coordinates

**Symptom: the sort result is complete nonsense.**

```python
class BadProxy(QSortFilterProxyModel):
    def lessThan(self, left, right):
        # ❌ left/right are already source coordinates; mapping again is wrong
        src_left = self.mapToSource(left)
        return self.sourceModel().data(src_left).text() < ...
```

**Root cause: Qt already passes `left` and `right` as indexes of the source model.** Calling `mapToSource` again applies a conversion that does not exist, scrambling the row numbers.

**✅ Fix: use `left` and `right` directly against the source model.**

```python
def lessThan(self, left, right):
    model = self.sourceModel()
    l = model.data(left, Qt.DisplayRole)      # ✅ Use directly
    r = model.data(right, Qt.DisplayRole)
    return l < r
```

## Custom Sorting in Practice: Status Priority

**Requirement: "Pending" first, then "In Progress", then "Done".**

```python
class StatusSortProxy(QSortFilterProxyModel):
    _ORDER = {"Pending": 0, "In Progress": 1, "Done": 2}

    def lessThan(self, left, right):
        model = self.sourceModel()
        l_status = model.data(model.index(left.row(), 1), Qt.DisplayRole)
        r_status = model.data(model.index(right.row(), 1), Qt.DisplayRole)
        l_rank = self._ORDER.get(l_status, 99)
        r_rank = self._ORDER.get(r_status, 99)
        return l_rank < r_rank
```

**A dictionary maps each status to a number, and you compare the numbers.** This is the cleanest, most reusable pattern for custom sorting.

## Crash Site 2: Comparing Dates via DisplayRole, String Order Is Wrong

**Symptom: "2024-1-15" sorts after "2024-12-3" (which is correct as text), but "2024-2-1" sorts before "2024-10-5" — because the string `"2"` does not come before `"1"`.**

```python
# data() returns strings like "2024-2-1"
def lessThan(self, left, right):
    l = self.sourceModel().data(left, Qt.DisplayRole)   # "2024-2-1"
    r = self.sourceModel().data(right, Qt.DisplayRole)  # "2024-10-5"
    return l < r      # ❌ String compare: "2024-2-1" < "2024-10-5" is True
```

**Root cause: the ISO-style date string `"YYYY-M-D"` is not zero-padded in month or day, so lexicographic order does not equal chronological order.**

**✅ Fix: expose `datetime` objects via `UserRole` in `data()`, and compare with `UserRole`.**

```python
# In the source model's data()
if role == Qt.UserRole and column == 2:      # The date column
    return self._rows[row][column]           # This is a datetime.date

def lessThan(self, left, right):
    model = self.sourceModel()
    l = model.data(left, Qt.UserRole)        # ✅ A date object
    r = model.data(right, Qt.UserRole)
    if l is None or r is None:
        return False
    return l < r
```

**Giving the model a "logical value" role such as `UserRole` is the one right answer that makes sorting, filtering, and editing all flow smoothly.**

## filterAcceptsRow: You Decide Which Rows Survive

**Return `True` to keep the row, `False` to hide it.**

```python
class NumberFilterProxy(QSortFilterProxyModel):
    def filterAcceptsRow(self, source_row, source_parent):
        model = self.sourceModel()
        idx = model.index(source_row, 1, source_parent)   # Amount column
        value = model.data(idx, Qt.UserRole)             # Logical value
        if value is None:
            return True
        return value >= 1000                             # Keep only values >= 1000
```

**The `source_row` parameter is the row number in the source model; `source_parent` is for tree structures (and is always an invalid `QModelIndex` for tables).**

## Crash Site 3: Wrong Column Number in filterAcceptsRow, Silently Wrong Result

**Symptom: you intended to filter by amount, but the filter is applied to the name column instead.**

```python
def filterAcceptsRow(self, source_row, source_parent):
    idx = self.sourceModel().index(source_row, 0, source_parent)  # ❌ Column 0 is name
    value = self.sourceModel().data(idx, Qt.UserRole)
    return value >= 1000     # The name column's UserRole is None, so this returns False -> nothing shows
```

**✅ Fix: make sure you are indexing the column you actually want to filter on.**

```python
idx = self.sourceModel().index(source_row, 1, source_parent)   # ✅ Column 1 is amount
```

**This "wrong column number" bug is especially sneaky because it never raises an error — the result is just quietly wrong.** The cure is to define column indexes as named constants.

```python
class AmountFilterProxy(QSortFilterProxyModel):
    AMOUNT_COLUMN = 1

    def filterAcceptsRow(self, source_row, source_parent):
        idx = self.sourceModel().index(source_row, self.AMOUNT_COLUMN, source_parent)
        value = self.sourceModel().data(idx, Qt.UserRole)
        return value is not None and value >= self._min_amount
```

## Crash Site 4: A Hard-Coded Threshold You Can Never Change

**Symptom: you want a UI control (say a `QSpinBox`) to adjust the threshold dynamically — "show rows where amount is at least N" — but `filterAcceptsRow` is read-only and has no way to receive outside parameters.**

```python
class BadFilter(QSortFilterProxyModel):
    def filterAcceptsRow(self, source_row, source_parent):
        idx = self.sourceModel().index(source_row, 1, source_parent)
        value = self.sourceModel().data(idx, Qt.UserRole)
        return value >= 1000       # ❌ The threshold is hard-coded
```

**✅ Fix: store the threshold as an instance attribute, expose a setter, and call `invalidateFilter()` after changing it.**

```python
class AmountFilterProxy(QSortFilterProxyModel):
    AMOUNT_COLUMN = 1

    def __init__(self, parent=None):
        super().__init__(parent)
        self._min_amount = 0

    def set_min_amount(self, value):
        self._min_amount = value
        self.invalidateFilter()        # ✅ Key: make the proxy re-run filterAcceptsRow

    def filterAcceptsRow(self, source_row, source_parent):
        idx = self.sourceModel().index(source_row, self.AMOUNT_COLUMN, source_parent)
        value = self.sourceModel().data(idx, Qt.UserRole)
        return value is not None and value >= self._min_amount
```

**`invalidateFilter()` tells the proxy "your filter condition changed, recompute everything".** Skip it and the display will not update even though the attribute changed — yet another "the UI does not refresh" trap.

## Putting It Together: Dynamic Filter Plus Custom Sort

**One proxy can override both `lessThan` and `filterAcceptsRow` at the same time — that is "custom filtering plus custom sorting".**

```python
class SmartProxy(QSortFilterProxyModel):
    def __init__(self, parent=None):
        super().__init__(parent)
        self._min_amount = 0
        self._keyword = ""

    def set_min_amount(self, v):
        self._min_amount = v
        self.invalidateFilter()

    def set_keyword(self, kw):
        self._keyword = kw
        self.invalidateFilter()

    def filterAcceptsRow(self, source_row, source_parent):
        model = self.sourceModel()
        # Condition 1: amount meets the threshold
        amt_idx = model.index(source_row, 1, source_parent)
        amt = model.data(amt_idx, Qt.UserRole)
        if amt is None or amt < self._min_amount:
            return False
        # Condition 2: name contains the keyword
        name_idx = model.index(source_row, 0, source_parent)
        name = model.data(name_idx, Qt.DisplayRole) or ""
        if self._keyword and self._keyword not in name:
            return False
        return True

    def lessThan(self, left, right):
        # Sort by status priority
        model = self.sourceModel()
        order = {"Pending": 0, "In Progress": 1, "Done": 2}
        l = model.data(model.index(left.row(), 2), Qt.DisplayRole)
        r = model.data(model.index(right.row(), 2), Qt.DisplayRole)
        return order.get(l, 99) < order.get(r, 99)
```

## Summary

- `lessThan(left, right)` returns `True` when `left` should come before `right`
- The indexes received by `lessThan` are already in source coordinates; do not call `mapToSource` again
- The cleanest custom-sort trick is to map values to numbers via a dictionary
- Types like dates must be exposed as `UserRole` logical values, or string comparison will betray you
- `filterAcceptsRow` returns `True` to show a row, `False` to hide it
- Filter thresholds need the three-piece combo: attribute + setter + `invalidateFilter()`
- One proxy can override both `lessThan` and `filterAcceptsRow`
