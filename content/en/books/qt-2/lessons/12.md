# Subclassing Existing Widgets: Extending QPushButton with a Countdown and a Custom Signal

> Full custom painting is heavy, and QSS is not enough. This lesson covers "subclassing an existing widget": inherit all of the parent's behaviour and add only the small piece you need — a countdown, a custom signal, an extra property. This is the highest-leverage form of customisation.

## The Basic Subclass Pattern

**Subclass an existing widget, call `super().__init__()`, then append your own logic.**

```python
from PySide6.QtWidgets import QPushButton

class IconButton(QPushButton):
    def __init__(self, icon_text, label, parent=None):
        super().__init__(parent)
        self._icon_text = icon_text
        self._label = label
        self.setText(f"{icon_text}  {label}")
        self.setFixedHeight(40)
```

**It may look like "just a configured button", but it is already your own class — one that can carry signals, methods, and state.**

## Defining a Custom Signal

**Define it with `Signal()` at the class body, written as `Signal` rather than `pyqtSignal` (the PySide6 spelling).**

```python
from PySide6.QtCore import Signal

class SubmitButton(QPushButton):
    submitting = Signal()          # No arguments
    submitted = Signal(bool)       # Carries a bool
    progress = Signal(int)         # Carries an int

    def __init__(self, parent=None):
        super().__init__("Submit", parent)
        self.clicked.connect(self._on_click)

    def _on_click(self):
        self.submitting.emit()
        # ... simulate submission ...
        self.submitted.emit(True)
```

**A signal's argument types are "declared when defined and supplied when emitted".** `self.submitted.emit(True)` passes a `bool`, so the declaration must read `Signal(bool)`. A type mismatch raises an error at runtime.

## Crash Site 1: Signal Written as an Instance Attribute, Never Properly Defined

**Symptom: at runtime, `AttributeError: 'Signal' object has no attribute 'connect'`, or you simply cannot connect to it.**

```python
class BadButton(QPushButton):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.submitting = Signal()    # ❌ Written inside __init__, so it becomes an instance attribute
```

**Root cause: `Signal()` must be a class attribute, defined in the class body. Written inside `__init__`, it becomes an ordinary instance attribute — not a Qt signal.**

**✅ Fix: define it in the class body.**

```python
class GoodButton(QPushButton):
    submitting = Signal()            # ✅ Class attribute

    def __init__(self, parent=None):
        super().__init__(parent)
```

**This trap was especially common in the PyQt5 / PySide2 era; PySide6 fails loudly instead, which actually makes it easier to spot.**

## A Complete Countdown Button

**Turn the idea from the previous lesson into a reusable, polished widget:**

```python
from PySide6.QtCore import QTimer, Signal

class CountdownButton(QPushButton):
    countdown_finished = Signal()     # Countdown finished
    countdown_tick = Signal(int)     # One tick per second, carrying the remaining seconds

    def __init__(self, normal_text="Get code", seconds=10, parent=None):
        super().__init__(normal_text, parent)
        self._normal_text = normal_text
        self._seconds = seconds
        self._remaining = seconds
        self._timer = QTimer(self)
        self._timer.setInterval(1000)
        self._timer.timeout.connect(self._tick)

    def start_countdown(self):
        if self._timer.isActive():
            return                    # Already counting down — guard against re-entry
        self._remaining = self._seconds
        self.setEnabled(False)
        self._timer.start()
        self._update_text()

    def reset(self):
        self._timer.stop()
        self.setEnabled(True)
        self.setText(self._normal_text)

    def _tick(self):
        self._remaining -= 1
        self.countdown_tick.emit(self._remaining)
        if self._remaining <= 0:
            self._timer.stop()
            self.setEnabled(True)
            self.setText(self._normal_text)
            self.countdown_finished.emit()
        else:
            self._update_text()

    def _update_text(self):
        self.setText(f"Please wait {self._remaining}s")
```

**Notice the re-entry guard in `start_countdown`.** It is a small detail easily overlooked, but an important one — a user hammering the button would otherwise start multiple timers and make the countdown run at double speed.

## Crash Site 2: QTimer Interval in the Wrong Unit, Counting 1000x Too Fast (or Not at All)

**Symptom: you expected one tick per second, but it ticks 1000 times per second (or does nothing at all).**

```python
self._timer = QTimer(self)
self._timer.setInterval(1)     # ❌ The unit is milliseconds; 1 ms per tick = 1000 ticks per second
```

**Root cause: `QTimer`'s interval is measured in milliseconds.**

**✅ Fix:**

```python
self._timer.setInterval(1000)          # ✅ 1000 ms = 1 second
# Or use the static form
self._timer.start(1000)
```

**"Milliseconds or seconds?" is the second most common unit trap in Qt** (the first is that angles are measured in radians in some APIs).

## Composite Widgets: Packing Several Widgets as One

**Composition is not custom painting, but it is also a form of custom widget — wrap a `QPushButton` + `QLineEdit` + `QLabel` inside a `QWidget`, and expose only a clean interface to the outside.**

```python
from PySide6.QtWidgets import QWidget, QHBoxLayout, QLineEdit, QPushButton

class SearchBox(QWidget):
    search_clicked = Signal(str)     # Expose only this one signal

    def __init__(self, parent=None):
        super().__init__(parent)
        self._input = QLineEdit()
        self._input.setPlaceholderText("Search...")
        self._btn = QPushButton("Search")

        self._btn.clicked.connect(self._on_search)

        layout = QHBoxLayout(self)
        layout.setContentsMargins(0, 0, 0, 0)
        layout.addWidget(self._input)
        layout.addWidget(self._btn)

    def _on_search(self):
        text = self._input.text().strip()
        if text:
            self.search_clicked.emit(text)

    def text(self):
        return self._input.text()

    def set_text(self, text):
        self._input.setText(text)
```

**Externally you expose only `search_clicked` plus `text()` / `set_text()`; the two inner widgets are hidden from the outside world.** That is the value of encapsulation — callers need never know whether the input is a `QLineEdit` or something else.

## Crash Site 3: Forgetting ContentsMargins on a Composite Widget, Layout Gets Pushed Out

**Symptom: after placing `SearchBox` inside an outer layout, the outer spacing looks wrong — there is an unexpected gap on the left.**

```python
class SearchBox(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        layout = QHBoxLayout(self)
        # ❌ The default contentsMargins is (9, 9, 9, 9), adding extra space when embedded
        layout.addWidget(self._input)
        layout.addWidget(self._btn)
```

**Root cause: the default layout margin for a `QWidget` is 9 px.** That is fine for a standalone window, but looks like "an extra ring" when used as an embedded component.

**✅ Fix: set it to 0, or whatever you actually want.**

```python
layout = QHBoxLayout(self)
layout.setContentsMargins(0, 0, 0, 0)     # ✅
```

## Summary

- Subclassing is the highest-leverage form of customisation because it inherits all parent behaviour
- `Signal` must be a class attribute defined in the class body, never inside `__init__`
- A signal's type is declared at definition and supplied at emit; the two must match
- `QTimer` intervals are in milliseconds: 1 second = 1000
- A countdown button needs a re-entry guard to prevent hammering the button from spawning multiple timers
- A composite widget uses a `QWidget` plus a layout, exposing only the essential interface
- A composite widget's layout normally sets its `contentsMargins` to 0
