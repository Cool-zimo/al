# Project 3: an image is an array

> A colour photo is, at bottom, a 3-D array. This lesson makes multi-dimensional arrays concrete.

## The three-layer structure

A 1080×1920 colour photo in NumPy is:

```python
img.shape    # (1080, 1920, 3)
```

| Dimension | Means | Size |
|---|---|---|
| 0 | **rows / height** (y) | 1080 |
| 1 | **columns / width** (x) | 1920 |
| 2 | **channels** (RGB) | 3 |

The order is **height × width × channels**, not width × height.

```python
import numpy as np

np.random.seed(0)
img = np.random.randint(0, 256, size=(4, 6, 3), dtype=np.uint8)
print("shape:", img.shape)
print("first pixel:", img[0, 0])       # [R G B]
```

**Every pixel is three numbers**: red, green and blue intensity, each 0–255.

## Reading one pixel

```python
print(img[0, 0])        # row 0, column 0
print(img[2, 3])        # row 2, column 3
```

**`img[y, x]`** — row first (how far down), then column (how far across). That's the reverse of the mathematical (x, y), **and the thing people get wrong most often**.

## Cropping: cutting a region out

```python
crop = img[1:3, 2:5]      # rows 1–2, columns 2–4
print(crop.shape)         # (2, 3, 3)
```

**The first two dimensions locate; the third stays put** — so you slice only the first two and every channel comes along.

Omitting a dimension takes all of it:

```python
top_half = img[:2]        # first two rows, same as img[:2, :, :]
```

## Channel operations

```python
print("red channel:\n", img[:, :, 0])
print("green channel:\n", img[:, :, 1])
print("blue channel:\n", img[:, :, 2])
```

**`img[:, :, n]` extracts channel n as a full greyscale image.**

### Red only: zero out green and blue

```python
red_only = img.copy()
red_only[:, :, 1:] = 0        # green and blue set to 0
print(red_only[0, 0])         # [R, 0, 0]
```

**Note the `.copy()`** — slices are views, so without it you'd overwrite the original.

### Channel gain: colour grading

```python
# warmer picture: red ×1.2, blue ×0.8
warm = (img.astype(float) * np.array([1.2, 1.0, 0.8])).clip(0, 255).astype(np.uint8)
print(warm[0, 0])
```

**Broadcasting feels natural here**: `(4, 6, 3)` times `(3,)` applies the gain vector to every pixel.

**Two type-handling steps that matter:**

1. **`astype(float)` must come before the multiply.** In `uint8`, arithmetic **overflows and wraps**: 250 × 1.2 = 300 → wraps to 44
2. **Then `clip(0, 255)` and cast back to `uint8`**, or values outside 0–255 are meaningless

> ⚠️ **uint8 overflow is the number one image-processing bug.** Convert to float before any arithmetic.

## Converting to greyscale

Two common approaches:

```python
# one: average the three channels (simple, but inaccurate)
gray1 = img.mean(axis=2)

# two: weighted average (matches human perception)
weights = np.array([0.299, 0.587, 0.114])
gray2 = (img.astype(float) * weights).sum(axis=2)

print("averaged:", np.round(gray1[0], 1))
print("weighted:", np.round(gray2[0], 1))
```

**The second matches the eye** — humans are most sensitive to green (hence 0.587) and least to blue.

## Flipping and rotating

```python
print("flipped vertically:", img[::-1].shape)
print("flipped horizontally:", img[:, ::-1].shape)
print("rotated 90°:", np.rot90(img).shape)       # note the shape changes
```

**`[::-1]` slicing is the fastest flip there is** — it only changes the read stride, it moves no data.

> ⚠️ `np.rot90` changes the shape: `(4, 6, 3)` becomes `(6, 4, 3)`. Don't assume the shape survives.

## In practice: adding a border

```python
import numpy as np

np.random.seed(0)
img = np.random.randint(100, 200, size=(4, 6, 3), dtype=np.uint8)

# a white canvas with the image pasted in the middle
h, w = img.shape[:2]
canvas = np.full((h + 2, w + 2, 3), 255, dtype=np.uint8)   # all white
canvas[1:-1, 1:-1] = img                                    # paste

print("canvas shape:", canvas.shape)
print("border (row 0):", canvas[0])
print("image at:", canvas[1, 1])
```

**`np.full(shape, value, dtype)` makes a flat-colour canvas**, then slice-assignment pastes the image — that's the whole principle behind bordering.

## Why this lesson matters

After it, you should see that:

- **A 3-D array isn't abstract** — it's "a set of positions, each carrying several attributes"
- An image is one; video is four (frames × height × width × channels); a batch of images is five
- Everything you do to an image is slicing + broadcasting + aggregation
