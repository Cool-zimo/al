# Reading broadcast errors

> Reading a `shape mismatch` is the dividing line between "can use NumPy" and "uses NumPy smoothly".

## What the error looks like

```python
import numpy as np

m = np.array([[1, 2, 3],
              [4, 5, 6]])      # (2, 3)
v = np.array([10, 20])         # (2,)

print(m + v)
```

The error:

```
ValueError: operands could not be broadcast together with shapes (2,3) (2,)
```

**That message carries a lot of information** — it lists both operand shapes outright: `(2,3)` and `(2,)`.

## Three steps to dissect it

**Step one: write both shapes down, right-aligned.**

```
(2, 3)
(   2)
  ↑  ↑
```

**Step two: prepend 1s to the shorter one.**

```
(2, 3)
(1, 2)
```

**Step three: compare right to left.**

```
rightmost: 3  vs  2   → not equal, neither is 1  → ✗ fails
```

Found it: **the last axis doesn't match**.

**The fix:** you wanted `v` to act across rows, so make it `(2, 1)`:

```python
print(m + v.reshape(-1, 1))
```

```
[[11 12 13]
 [24 25 26]]
```

## Common errors and their fixes

| What you wanted | Wrong code | Shapes in the error | Right code |
|---|---|---|---|
| Add a value per row | `m + v` (v is (2,)) | (2,3) vs (2,) | `v.reshape(-1,1)` |
| Add a value per column | `m + v` (v is (2,)) | (2,3) vs (2,) | use a length-3 v |
| Add two matrices | different shapes | (2,3) vs (3,2) | check whether you need `.T` |
| Use a 1-D array as a column | `(4,) - (4,1)` | broadcasts fine, but gives (4,4) | confirm (4,4) is what you want |

That last row matters: some broadcasts **succeed** and still give the wrong answer.

## Silent mistakes are worse than errors

```python
a = np.array([1, 2, 3])        # (3,)
b = np.array([[10], [20]])     # (2, 1)

print(a + b)                   # no error! result is (2, 3)
print((a + b).shape)
```

```
[[11 12 13]
 [21 22 23]]
```

NumPy assumes "you probably want all the combinations" and hands you a 2×3. If you meant to add three numbers, this is wrong — **and nothing warns you**.

> 💡 Defensive habit: **check `.shape` right after any broadcast.** One second spent saves an hour.

## The three-step debugging ritual

When shapes misbehave, do these in order:

**1. Print the shape of every variable involved.**

```python
print("m:", m.shape, "v:", v.shape)
```

**2. Walk the broadcast rules by hand** (prepend 1s → right-align → compare).

**3. When unsure, reshape explicitly — don't guess.**

```python
v_col = v.reshape(-1, 1)     # explicitly a column
v_row = v.reshape(1, -1)     # explicitly a row
```

## A useful assertion habit

In data code, state your shape assumptions as assertions so problems surface immediately:

```python
def normalize_rows(m):
    assert m.ndim == 2, f"need a 2-D array, got {m.ndim}-D"
    row_mean = m.mean(axis=1).reshape(-1, 1)
    return m - row_mean
```

Now passing a 1-D array gives you a plain-English message instead of a bizarre broadcast result.

## A note on axis

`axis=0` and `axis=1` have appeared throughout this chapter. A working understanding for now:

- `axis=0`: compute **across rows**, giving one result per **column** (the row axis collapses)
- `axis=1`: compute **across columns**, giving one result per **row** (the column axis collapses)

```python
m = np.array([[1, 2, 3],
              [4, 5, 6]])

print(m.sum(axis=0))    # [5 7 9]    sum of each column
print(m.sum(axis=1))    # [ 6 15]    sum of each row
```

Chapter 3 covers `axis` fully. For now: **`axis` names the dimension that gets collapsed**.
