# From NumPy to pandas

> The end of *Data Analysis 1* and the start of *Data Analysis 2*. This lesson states plainly **what NumPy can and cannot do**.

## What NumPy is good at

**Bulk numeric work on uniform data.** When your data is "one big grid of same-typed numbers", nothing beats it:

```python
import numpy as np

# statistics over a million values: instant
big = np.random.rand(1_000_000)
print(big.mean(), big.std(), big.min(), big.max())
```

| Strength | Why |
|---|---|
| **Fast** | C underneath; vectorisation beats Python loops by tens of times |
| **Memory-light** | a million float64 values occupy just 8 MB |
| **Mathematically capable** | broadcasting, linear algebra, Fourier transforms, random numbers |
| **Universal** | the shared foundation of pandas, scikit-learn and SciPy |

## What NumPy is not good at

### 1. Tables whose columns have different types

```python
# a real student table: name (text) + age (int) + score (float)
data = np.array([['Alice', '18', '89.5'],
                 ['Bob', '19', '92.0']], dtype=str)
print(data)
print(data.dtype)      # <U... — all strings!
```

**NumPy needs one type throughout**, so the numbers become text. To average the scores you must convert by hand:

```python
scores = data[:, 2].astype(float)     # and again for every other column
print(scores.mean())
```

**One more conversion per column**, and it spirals quickly.

> 💡 pandas `DataFrame` supports a type per column natively — which is what tabular data actually wants.

### 2. Labelled indexing

```python
scores = np.array([89, 92, 78])
# whose score is which? only "the one at position 0"
print(scores[0])
```

**NumPy has positions, not names.** You maintain your own "index → name" mapping, which drifts out of sync easily.

pandas lets you write `df.loc['Alice', 'maths']`.

### 3. Elegant handling of missing values

In chapter 3 we met `nanmean`, `nanstd`… **you must remember the nan variant of every function**, and it's easy to forget:

```python
arr = np.array([1.0, np.nan, 3.0])
print(arr.mean())        # nan  ← forgot nanmean
print(np.nanmean(arr))   # 2.0  ← right
```

pandas treats missing as a first-class citizen; `df.mean()` skips nan by default.

### 4. Grouping, joining, pivoting

```python
# mean score per class — manageable by hand in NumPy
classes = np.array(['A', 'A', 'B', 'B'])
scores = np.array([80, 90, 70, 85])

for c in np.unique(classes):
    print(c, scores[classes == c].mean())
```

Simple grouping is survivable, **but "group by two columns, take the mean of three metrics, then sort" makes NumPy code balloon**.

In pandas it's one line: `df.groupby('class')['score'].mean()`.

## Side by side

| Need | NumPy | pandas |
|---|---|---|
| Large-scale numeric computation | ✅ fastest | ⚠️ slightly slower (NumPy underneath) |
| Columns of differing types | ❌ awkward | ✅ built for it |
| Selecting rows/columns by name | ❌ positions only | ✅ `loc` / column names |
| Missing values | ⚠️ remember the nan variants | ✅ skipped by default |
| Group and aggregate | ⚠️ hand-rolled loops | ✅ `groupby` |
| Joining tables | ❌ painful | ✅ `merge` |
| Time series indexing | ❌ | ✅ dedicated support |
| Matrices / linear algebra | ✅ `linalg` | ⚠️ not its strength |

## They aren't alternatives

**The key insight: pandas is built on top of NumPy.**

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({'score': [80, 90, 70]})
print(type(df['score'].values))      # <class 'numpy.ndarray'>
```

**A pandas Series' `.values` is a NumPy array.** Everything from this book — broadcasting, axes, boolean indexing, ufuncs — **works unchanged inside pandas**.

So this course isn't "about to be replaced"; it's **laying the foundation**. Learn pandas afterwards and you'll already think in its underlying terms.

## When to stay with NumPy

Even after pandas, NumPy remains first choice for:

1. **Pure numeric work at scale** (matrix maths, signal processing, image processing)
2. **Feeding machine-learning algorithms** (sklearn takes NumPy arrays)
3. **Inner loops where performance is critical**
4. **Scientific computing** (differential equations, Fourier transforms, simulation)
