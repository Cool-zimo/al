# Common file-reading errors

> When reading a file fails, the message usually names the cause. This lesson teaches you to read them.

## Error one: file not found

```
FileNotFoundError: data.csv not found.
```

**Cause:** the path is wrong. Python resolves paths against the **current working directory**, not against where your script lives.

**Diagnose:**

```python
import os
print(os.getcwd())          # where am I
print(os.listdir('.'))      # what's here
```

**The classic trap:** your editor opened the project root, but the run happened somewhere else.

Three fixes:

```python
# 1. absolute path
data = np.loadtxt('/home/me/project/data.csv', delimiter=',')

# 2. change directory first
os.chdir('/home/me/project')

# 3. locate relative to this script (most robust)
import pathlib
base = pathlib.Path(__file__).parent
data = np.loadtxt(base / 'data.csv', delimiter=',')
```

## Error two: inconsistent column count

```
ValueError: the number of columns changed from 3 to 2 at row 2
```

**Cause:** one line has a different number of fields.

```
1,2,3
4,5      ← only two here
```

**Usual suspects:**

- The last line is truncated
- A **field itself contains the delimiter** (an address like `London, Inner London` splits into two columns when comma-separated)
- A trailing blank line

**Diagnose:** print the offending line

```python
lines = open('data.csv', encoding='utf-8').read().split('\n')
for i, line in enumerate(lines, 1):
    n = len(line.split(','))
    if n != 3:
        print(f"line {i} has {n} fields: {line!r}")
```

**Handle it:**

```python
# option one: skip trailing lines
data = np.genfromtxt('data.csv', delimiter=',', skip_footer=1)

# option two: read only the first three columns
data = np.genfromtxt('data.csv', delimiter=',', usecols=(0, 1, 2))

# option three: filter out wrong-length lines first
lines = [l for l in open('data.csv', encoding='utf-8') if len(l.split(',')) == 3]
```

## Error three: can't convert to float

```
ValueError: could not convert string to float: 'lang'
```

**Cause:** the file contains **text** (usually a header), but you asked NumPy to read numbers.

```
lang,maths,english      ← this line is text
80,90,70
```

**Fix:** skip the header.

```python
data = np.loadtxt('scores.csv', delimiter=',', skiprows=1)
```

Or `skip_header=1` with genfromtxt.

**A variant:** an empty field.

```
ValueError: could not convert string to float: ''
```

A comma with nothing after it — switch to `genfromtxt` (previous lesson).

## Error four: encoding

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc4 in position 0
```

**Cause:** the file isn't UTF-8. **Excel on a Chinese Windows saves CSV as GBK by default** — the most common source.

**Fix:** name the encoding.

```python
data = np.loadtxt('data.csv', delimiter=',', dtype=str, encoding='gbk')
```

**How do you know which?** Try them:

```python
for enc in ['utf-8', 'gbk', 'gb18030', 'latin1']:
    try:
        lines = open('data.csv', encoding=enc).readlines()
        print(f"{enc} works: {lines[0][:30]}")
        break
    except UnicodeDecodeError:
        print(f"{enc} failed")
```

**gb18030 is a superset of gbk** — try it if gbk fails.

**Fix it at the source:** re-save the file as UTF-8 in VSCode or Notepad and never see this again.

## Error five: wrong delimiter

The file uses semicolons (common in European CSVs) but you split on commas:

```
1;2;3
```

```python
np.loadtxt('d.csv', delimiter=',')    # reads one column of junk
```

**No error — just wrong data.** More dangerous than an error.

**Diagnose:** look at the raw content first.

```python
print(open('d.csv', encoding='utf-8').read()[:200])
```

**Build the habit:** before reading any unfamiliar file, `print` its first few lines. That one step prevents most of the pain.

```python
with open('data.csv', encoding='utf-8') as f:
    for i, line in enumerate(f):
        if i >= 5: break
        print(repr(line))
```

`repr()` reveals newlines and hidden characters.

## Error six: a single row of data

```python
data = np.loadtxt('one_row.csv', delimiter=',')
print(data.shape)     # (3,)   ← one row came back as 1-D
```

**A silent trap:** a one-line file reads as 1-D. Code that assumes 2-D (`data[:, 0]`) then breaks.

**Fix:** force at least two dimensions.

```python
data = np.atleast_2d(np.loadtxt('one_row.csv', delimiter=','))
print(data.shape)     # (1, 3)
```

`np.atleast_2d` is a safety wrapper worth using in general-purpose code.

## A general checklist

Do these four in order and 90% of file problems resolve:

1. **Does the file exist** → `os.path.exists(path)`
2. **What does the raw content look like** → `print(open(f, encoding='utf-8').read()[:200])`
3. **Is the encoding right** → try utf-8 / gbk
4. **Delimiter and header** → confirm delimiter and skiprows
