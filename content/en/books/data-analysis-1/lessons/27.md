# Project 2: time series and moving averages

> Share prices, temperature, daily active users — anything arranged in time needs a moving average sooner or later.

## What a moving average is

Raw daily figures are noisy and hide the trend:

```python
import numpy as np

np.random.seed(0)
daily = np.random.randint(80, 120, size=30)     # 30 days of sales
print("raw:", daily)
```

**A moving average** takes each day together with the preceding few days and averages them, smoothing out the jagged edges.

```python
# 3-day moving average
window = 3
kernel = np.ones(window) / window               # [1/3, 1/3, 1/3]
ma = np.convolve(daily, kernel, mode='valid')
print("3-day:", np.round(ma, 1))
```

**`np.convolve` is convolution**: slide the "averaging kernel" `[1/3, 1/3, 1/3]` along the series and you have a moving average.

## The mode argument: how long is the result

`np.convolve(a, kernel, mode=...)` has three modes with different lengths:

```python
x = np.array([1., 2., 3., 4., 5., 6.])
k = np.ones(3) / 3

print("full :", len(np.convolve(x, k, mode='full')))    # 8 = 6 + 3 - 1
print("same :", len(np.convolve(x, k, mode='same')))    # 6 = same as input
print("valid:", len(np.convolve(x, k, mode='valid')))   # 4 = 6 - 3 + 1
```

| mode | Length | Meaning |
|---|---|---|
| `full` | `n + k - 1` | the complete convolution, including half-overlapping ends |
| `same` | `n` | same length as the input, zero-padded at the ends |
| `valid` | `n - k + 1` | **only where the window fully overlaps** — the usual choice |

**Always use `mode='valid'` for moving averages**: the half-windows at the ends are distorted (they average only one or two values), and valid simply drops them.

The cost is that the result is `k-1` shorter than the input — which is correct, since the first `k-1` days genuinely lack enough preceding days.

## A faster formulation: cumsum

Convolution reads nicely but is slow on big data. Here's an equivalent that isn't:

```python
def moving_average(x, window):
    cum = np.cumsum(np.insert(x, 0, 0))       # prefix sums, with a leading 0
    return (cum[window:] - cum[:-window]) / window

print(np.round(moving_average(daily, 3), 1))
```

**The idea:** after `cumsum`, the sum of window i is `cum[i+window] - cum[i]` — one subtraction, **no repeated addition**.

Check that they agree:

```python
print(np.allclose(moving_average(daily, 3),
                  np.convolve(daily, np.ones(3)/3, mode='valid')))
# True
```

> 💡 **Small data: convolve (readable). Large data: cumsum (fast).** At a million points the cumsum version can be tens of times faster.

## Running totals: cumsum and cumprod

```python
sales = np.array([100, 150, 120, 200])

print("cumulative units:", np.cumsum(sales))       # [100 250 370 570]
print("compound growth:", np.cumprod([1.1, 1.05, 1.2]))
```

**`cumsum` answers "how much up to this day"** — essential for cumulative curves.

## The general sliding window

For "the max / min / std of any k consecutive days", you could loop, but there's something tidier:

```python
from numpy.lib.stride_tricks import sliding_window_view

w = sliding_window_view(daily, window_shape=3)
print(w.shape)          # (28, 3)  28 windows of 3 days
print("max per window:", w.max(axis=1))
print("min per window:", w.min(axis=1))
print("std per window:", np.round(w.std(axis=1), 1))
```

**`sliding_window_view` returns a view**, copying nothing, so it's memory-cheap. Then aggregate each window with `axis=1`.

> ⚠️ It lives in `numpy.lib.stride_tricks` and needs importing; older NumPy versions may not have it.

## In practice: reading the trend

```python
import numpy as np

np.random.seed(0)
daily = np.random.randint(80, 120, size=30).astype(float)

def ma(x, k):
    cum = np.cumsum(np.insert(x, 0, 0))
    return (cum[k:] - cum[:-k]) / k

short = ma(daily, 3)      # fast line: 3-day
long_ = ma(daily, 10)     # slow line: 10-day

# align lengths (28 versus 21 — trim to the shorter)
n = min(len(short), len(long_))
short, long_ = short[-n:], long_[-n:]

print("fast (3d):", np.round(short, 1))
print("slow (10d):", np.round(long_, 1))
print("\ndays with fast above slow:", np.sum(short > long_))
```

**"Fast crossing above slow" is the classic technical-analysis signal** (a golden cross). It's here to demonstrate the mechanics, not as investment advice — trading on it loses money.

## Traps

**1. Forgetting the window can overrun.**

```python
np.convolve(daily, np.ones(50)/50, mode='valid')   # only 30 days, window of 50
# returns an empty array!
```

When the window is longer than the data, valid returns nothing. **Assert it:**

```python
assert window <= len(daily), "window longer than the series"
```

**2. Letting nan into the series.**

A moving average propagates nan — one gap poisons the next k averages. Fill first:

```python
daily_clean = daily.copy()
inds = np.where(np.isnan(daily_clean))
if len(inds[0]):
    daily_clean[inds] = np.nanmean(daily_clean)
```
