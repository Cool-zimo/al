# npy and npz

> Saving computed data and loading it back. NumPy has its own binary format — far faster and safer than CSV.

## Why not just use CSV

Storing numbers as CSV has two hard problems:

1. **Slow** — every save and load converts numbers to text and back, which is dramatic at scale
2. **Lossy** — a float like `0.1 + 0.2` written as text and read back may not be the same number

**NumPy's `.npy` format stores raw binary** — saved as-is, loaded as-is. Fast and exact.

> 💡 When is CSV right? When a **human or another tool** needs to read it (Excel, a colleague). For data staying inside Python, always use npy.

## save and load: a single array

```python
import numpy as np

arr = np.array([[1, 2, 3],
                [4, 5, 6]])

np.save('data.npy', arr)          # save
loaded = np.load('data.npy')      # load
print(loaded)
```

```
[[1 2 3]
 [4 5 6]]
```

**Note: `np.save` appends `.npy` automatically.** Writing `np.save('data', arr)` still produces `data.npy`.

When loading, **the suffix is not optional**:

```python
np.load('data')      # FileNotFoundError (it looks for a file literally named data)
np.load('data.npy')  # ✅
```

### What actually gets stored

Beyond the values, an npy file carries **shape, dtype and byte order**. So what comes back is identical, with no type hints needed:

```python
a = np.array([1.5, 2.5], dtype=np.float32)
np.save('x.npy', a)
b = np.load('x.npy')
print(b.dtype)      # float32  ← the type was remembered
```

CSV can't do that.

## savez: several arrays at once

```python
x = np.array([1, 2, 3])
y = np.array([[10], [20]])

np.savez('bundle.npz', x=x, y=y)
```

Loading gives something **dict-like**:

```python
data = np.load('bundle.npz')
print(data.files)        # ['x', 'y']   what's inside
print(data['x'])         # [1 2 3]
print(data['y'])
```

**The keyword arguments become the names.** Skip them and you get `arr_0`, `arr_1`:

```python
np.savez('auto.npz', x, y)
d = np.load('auto.npz')
print(d.files)      # ['arr_0', 'arr_1']
```

**Always name things** — a week later you won't remember which `arr_0` was which.

### npz is a zip archive

An npz is literally a zip containing several `.npy` files. So:

- You can open it with any unzip tool
- It's slightly smaller than separate files (compression)

For stronger compression use `savez_compressed`:

```python
np.savez_compressed('packed.npz', big=arr)    # noticeably smaller for large data
```

The trade-off is slower saving.

## Close it when you're done

An npz object from `np.load` **holds an open file handle**, so close it:

```python
data = np.load('bundle.npz')
x = data['x'].copy()      # take what you need
data.close()              # then close
```

Neater with `with`:

```python
with np.load('bundle.npz') as data:
    x = data['x']
    y = data['y']
# closes automatically here
print(x, y)
```

(Loading a plain `.npy` needs no closing — it returns an array directly.)

## A habit worth having: cache intermediate results

Analysis often has a step that takes ten minutes:

```python
import numpy as np
import os

if os.path.exists('cache.npy'):
    result = np.load('cache.npy')       # reuse
    print("loaded from cache")
else:
    result = expensive_computation()    # only compute if needed
    np.save('cache.npy', result)
    print("computed and cached")
```

**This pattern saves enormous amounts of waiting.**

## Quick reference

| Need | Write |
|---|---|
| save one array | `np.save('a.npy', arr)` |
| load one array | `np.load('a.npy')` |
| save several (named) | `np.savez('b.npz', x=x, y=y)` |
| save several (compressed) | `np.savez_compressed(...)` |
| load several | `d = np.load('b.npz'); d['x']` |
| see what's inside | `d.files` |
