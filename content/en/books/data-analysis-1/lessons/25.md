# End to end: from file to report

> This lesson chains the previous four into a pipeline. It's what you actually do every day.

## The scenario

A sales CSV: 4 cities × 12 months, with gaps and bad entries. Produce an analysis report.

## Step one: make some dirty data

```python
import numpy as np

np.random.seed(42)
sales = np.random.randint(100, 1000, size=(12, 4)).astype(float)

# make it realistic: two gaps, one keying error
sales[2, 1] = np.nan
sales[7, 3] = np.nan
sales[5, 2] = -1

np.savetxt('sales.csv', sales, delimiter=',', fmt='%.0f',
           header='London,Paris,Berlin,Rome', comments='')
print("wrote sales.csv")
```

## Step two: read it, but don't compute yet

```python
raw = np.genfromtxt('sales.csv', delimiter=',', skip_header=1)
print("shape:", raw.shape)
print("missing cells:", np.sum(np.isnan(raw)))
```

**Look at the shape and the gaps first.** That single habit prevents every "wrong answer, no idea why" moment.

## Step three: clean

```python
# 1. turn the sentinel -1 into nan so it's handled uniformly
clean = raw.copy()
clean[clean == -1] = np.nan

# 2. count again
print("missing after cleaning:", np.sum(np.isnan(clean)))

# 3. fill with each column's (each city's) mean
col_mean = np.nanmean(clean, axis=0)
inds = np.where(np.isnan(clean))
if len(inds[0]):
    clean[inds] = np.take(col_mean, inds[1])

print("any gaps left?", np.any(np.isnan(clean)))
```

**Three moves:** sentinel → nan, count, fill with column means.

> 💡 Why the **column** mean instead of the table mean? Cities differ enormously in scale; a global mean would drag Paris towards London's level. Per-column filling is the honest choice.

## Step four: statistics

```python
cities = ['London', 'Paris', 'Berlin', 'Rome']

print("\nannual totals:")
totals = clean.sum(axis=0)
for name, t in zip(cities, totals):
    print(f"  {name}: {t:,.0f}")

print("\nmonthly averages:")
print("  ", np.round(clean.mean(axis=0), 1))

print("\nmost volatile city (std):")
stds = clean.std(axis=0)
print(f"  {cities[np.argmax(stds)]}: {stds.max():.1f}")
```

## Step five: find the highlights

```python
# best month overall
monthly = clean.sum(axis=1)
best_month = np.argmax(monthly)
print(f"\nbest month: #{best_month + 1}, total {monthly[best_month]:,.0f}")

# best month per city
best_months = np.argmax(clean, axis=0)
print("best month per city:")
for name, m in zip(cities, best_months):
    print(f"  {name}: #{m + 1}")
```

Mind the axis here:
- `clean.sum(axis=1)` → total per month (across cities) → 12 values
- `np.argmax(clean, axis=0)` → best month per city (across months) → 4 values

## Step six: period-over-period growth

```python
growth = np.diff(monthly) / monthly[:-1] * 100
print("\nmonth-on-month (%):")
print(np.round(growth, 1))

print(f"fastest growth: month #{np.argmax(growth) + 2} (+{growth.max():.1f}%)")
```

**`np.diff` gives neighbouring differences**, one shorter than the input. So divide by `monthly[:-1]` (drop the last month).

> ⚠️ `np.argmax(growth) + 2`: because diff loses one element and growth describes "month n → month n+1", you add 2 to name the month. Index offsets like this are the easiest thing to get wrong — verify once.

## Step seven: the report

```python
line = "=" * 40
print(line)
print("           SALES ANALYSIS REPORT")
print(line)
print(f"data: {clean.shape[0]} months × {clean.shape[1]} cities")
print(f"annual total: {clean.sum():,.0f}")
print(f"monthly average: {monthly.mean():,.0f}")
print()
print("city ranking:")
for rank, i in enumerate(np.argsort(totals)[::-1], 1):
    print(f"  {rank}. {cities[i]}  {totals[i]:,.0f}")
print()
print(f"best month: #{best_month + 1}")
print(f"steadiest city: {cities[np.argmin(stds)]} (std {stds.min():.1f})")
print(line)

# save the cleaned data for next time
np.save('sales_clean.npy', clean)
```

**That last line matters:** cleaning is slow and must be reproducible, so persist the result.

## The whole thing

```python
import numpy as np

np.random.seed(42)
raw = np.genfromtxt('sales.csv', delimiter=',', skip_header=1)
cities = ['London', 'Paris', 'Berlin', 'Rome']

# clean
clean = raw.copy()
clean[clean == -1] = np.nan
col_mean = np.nanmean(clean, axis=0)
inds = np.where(np.isnan(clean))
if len(inds[0]):
    clean[inds] = np.take(col_mean, inds[1])

# analyse
totals = clean.sum(axis=0)
monthly = clean.sum(axis=1)
stds = clean.std(axis=0)

line = "=" * 40
print(line)
print(f"  total {clean.sum():,.0f}   monthly avg {monthly.mean():,.0f}")
print("  city ranking:")
for rank, i in enumerate(np.argsort(totals)[::-1], 1):
    print(f"    {rank}. {cities[i]}  {totals[i]:,.0f}")
print(f"  best month: #{np.argmax(monthly) + 1}")
print(line)
np.save('sales_clean.npy', clean)
```

## What you used

| Step | Tools |
|---|---|
| make / read | `savetxt`, `genfromtxt` |
| inspect | `shape`, `np.isnan` + `sum` |
| clean | boolean-index assignment, `nanmean`, `where` + `take` |
| analyse | `sum(axis=)`, `mean`, `std`, `argmax` |
| change over time | `diff` |
| rank | `argsort(...)[::-1]` |
| report | f-strings, `round` |
| persist | `np.save` |

**Every chapter of this book is in here.** Swap in new data and this code barely changes.

q: Why fill with the COLUMN mean rather than the whole-table mean?
options:
- Column means are faster to compute
- Columns can differ hugely in scale; a global mean contaminates them
- The whole-table mean raises an error
- There's no real difference
answer: 1
explain: If city A sells 800 a month and city B sells 200, a global mean of 500 pushes A down and lifts B up — both columns' statistics are then wrong. Per-column filling preserves each column's own level: that's filling, not tampering.
