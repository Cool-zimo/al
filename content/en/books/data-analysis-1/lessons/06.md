# Thinking in vectors

> This lesson is the soul of NumPy: **learn to solve problems without loops**.

## Two versions, one result

Apply a 20% discount to a batch of prices:

```python
import numpy as np

prices = np.array([100, 250, 80, 300, 45])

# version one: loop (list thinking)
result = []
for p in prices:
    result.append(p * 0.8)

# version two: vectorised (array thinking)
result2 = prices * 0.8
```

**The second isn't just "shorter" — it's a different way of thinking.**

- Loop thinking: I have a pile of numbers; I take them one at a time
- Vector thinking: I have an array; I do one operation to the whole thing

Once the second becomes natural, you'll find code that used to take a dozen lines often fits in one — and runs faster.

## Measure the gap

```python
import numpy as np
import time

n = 2_000_000
arr = np.random.random(n)

t0 = time.time()
doubled = np.array([x * 2 for x in arr])   # element by element
t1 = time.time()
doubled2 = arr * 2                          # vectorised
t2 = time.time()

print(f"loop: {(t1 - t0) * 1000:.0f} ms")
print(f"vectorised: {(t2 - t1) * 1000:.0f} ms")
```

Two million values: the loop takes hundreds of milliseconds, the vectorised version usually a few.

## Conditionals can be vectorised too: np.where

The single most useful function here.

**Task:** any score below 60 becomes 0, the rest stay.

Loop version:

```python
scores = np.array([45, 78, 92, 55, 61])
result = []
for s in scores:
    if s < 60:
        result.append(0)
    else:
        result.append(s)
```

Vectorised:

```python
result = np.where(scores < 60, 0, scores)
print(result)      # [ 0 78 92  0 61]
```

**`np.where(condition, value_if_true, value_if_false)`** — three arguments, one line.

It's an element-wise ternary: for each element, is the condition true? Then take the second argument, otherwise the third.

**Given only the condition**, `np.where` returns the **indices** that match:

```python
print(np.where(scores < 60))     # (array([0, 3]),)  ← positions 0 and 3
print(scores[np.where(scores < 60)])   # [45 55]
```

(Chapter 3 shows a neater boolean-indexing form.)

## A real rewrite

**Task:** distance from a set of coordinates to the origin.

```python
import numpy as np

points = np.array([[1, 2], [3, 4], [5, 12], [8, 6]])
```

**Loop:**

```python
dists = []
for x, y in points:
    dists.append((x ** 2 + y ** 2) ** 0.5)
```

**Vectorised:**

```python
xs = points[:, 0]        # column 0 of every row → [1 3 5 8]
ys = points[:, 1]        # column 1 of every row → [2 4 12 6]
dists = (xs ** 2 + ys ** 2) ** 0.5
print(dists)             # [ 2.236  5.  13.  10.]
```

Or shorter still:

```python
dists = np.sqrt((points ** 2).sum(axis=1))
```

**Notice what happened:** we never "visited each point". We pulled out "all the x" and "all the y" and computed on them as wholes. That's the central move of vectorisation — **turn per-element handling into per-column work**.

## When loops remain necessary

Don't over-correct. Loops (or partial loops) are still right when:

**1. There's a dependency.** The current value depends on the previous step, e.g. "accumulate until a threshold":

```python
# this kind of rolling dependency doesn't vectorise cleanly
total = 0
for x in data:
    total += x
    if total > 1000:
        break
```

(`np.cumsum()` does prefix sums, but short-circuiting like "break early" is awkward to vectorise.)

**2. Each element needs different logic.** Vectorisation requires "the same operation on everything".

**3. The data is tiny.** Below a few thousand elements you may not notice the difference, so don't contort the code.

> 💡 The rule: **check whether it vectorises first, reach for a loop second** — not the other way round.

## Three common vectorised patterns

| Goal | Vectorised form |
|---|---|
| Either/or by condition | `np.where(cond, a, b)` |
| Element-wise function | `np.sqrt(arr)`, `np.exp(arr)` |
| Count by condition | `np.sum(arr > 5)` |
| Replace a subset in place | `arr[arr < 0] = 0` |
| Many means at once | `arr.mean(axis=1)` |
